## 四、插件治理界面

### 4.1 列表与分组

- 顶部按角色分四个标签页：应用（`app`）、基础卡片（`basecard`）、箱子布局（`boxlayout`）、服务（`service`）；不存在的"模块插件"角色不得出现（R1、[ADR-005](../01-架构设计/ADR/ADR-005-插件不分类只分角色.md)）。
- 每页支持：按名称搜索、按状态筛选（`installed` / `active` / `pending` / `failed` / `stopping`）、按安装时间排序。
- 记录行：图标、名称、版本、状态徽章、高频动作（应用含"启动"；`installed` 含"启用"；`active` 含"停用"）、"详情"。
- 列表数据一律来自插件注册表查询能力，禁止扫描插件目录或读取 `manifest.yaml` 文件（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §3.3）。
- 状态变化按 `plugin:installed` / `plugin:uninstalled` / `plugin:enabled` / `plugin:disabled` / `plugin:unloaded` / `plugin:failed` 事件刷新（[05-事件契约规范](../05-接口与契约/05-事件契约规范.md) §4.1）；刷新必须幂等。

### 4.2 安装

```
[1] 用户点击"安装插件"或把 .cpk 拖入窗口
        ▼
[2] 文件选择：dialog:open（过滤 .cpk）；拖拽文件经平台路径归一后进入同一入口
        ▼
[3] 调用插件管理能力的安装操作（manifestPath / 包路径）
        ▼
[4] 安装校验：包结构、签名与来源、权限声明、schema（失败 → 结构化错误，不留半成品）
        ▼
[5] 安装完成：状态 installed，不自动启用；发布 plugin:installed
        ▼
[6] 类型校验：按返回记录的 role 与当前页比对；不一致则提示并引导到正确角色页
        ▼
[7] 提示"插件已安装，启用后生效"，提供"立即启用"入口
```

- 面板不得自行解包 `.cpk`、不得复制插件文件、不得直接写入插件目录（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §4.2）。
- 安装失败必须区分：包/签名错误（`CPK_*`）、权限声明错误（`PERMISSION_*`）、配置 schema 错误（`CONFIG_SCHEMA_INVALID`）、`engines.chips` 不满足（`CPK_ENGINE_UNSUPPORTED`）。
- 安装入口支持整窗拖入：文件进入窗口时显示轻量覆盖提示，松手后走同一安装入口；页面不常驻大面积拖入区域。

### 4.3 启用与停用

**启用**：

1. 已安装未启用（`installed`）的插件提供"启用"；首次启用由平台弹出授权确认界面，逐项展示权限名称、说明、风险级别与解析后的限定值（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §6.2）。
2. 用户拒绝任一权限不阻断启用，该权限保持未授权；界面不得暗示"必须全部接受"。
3. 依赖不满足时插件进入 `pending`，列表显示"等待依赖：<插件名>"并给出去向该依赖详情的入口；版本范围不可满足时进入 `failed` 并展示冲突说明。
4. 启用成功后刷新列表与详情；失败展示 `KERNEL_APPLY_FAILED`、`KERNEL_DEPENDENCY_MISSING`、`PLUGIN_PERMISSION_DENIED` 等结构化错误与重试入口。

**停用**：

1. 存在 `active` 依赖者时默认拒绝（`KERNEL_DEPENDENCY_CONFLICT`）；确认对话框必须列出受影响插件清单，用户明确选择"级联停用"后按逆拓扑序执行（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §4.4）。
2. 应用插件停用前先处理未保存状态：由平台按应用退出流程收敛，面板只呈现"正在停止/等待保存"状态。
3. 停用不删除插件文件、配置与授权；再次启用不重新安装。
4. 停用必定完成：`stop` 失败只记录诊断，状态仍回到 `installed`；界面以注册表状态为准，不以前端推断为准。

### 4.4 权限审查

- 插件详情页固定包含"权限"区块，展示该插件的权限申请与授权状态：

| 列 | 内容 |
|---|---|
| 权限名称 | 简体中文说明（文案以 [08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §6.7 为准） |
| 权限 ID | 基础形式与限定值原文，作为次要信息展示 |
| 限定值 | 变量展开后的实际范围（目录、域名、URL、窗口、资源作用域） |
| 风险级别 | 低 / 中 / 高 / 极高 |
| 状态 | 已授予 / 已拒绝 / 未记录（未决即拒绝） |
| 来源与时间 | 启用确认、首次调用记住、设置面板、更新 |

- 区块提供"前往权限页查看全部"入口；授予与撤销动作在权限页执行（第五节），插件详情不复制一套写入逻辑。
- 插件更新引入新权限时，更新确认由平台弹出（仅展示新增项）；面板显示"待确认的新权限"标记，用户拒绝后展示当前运行版本与取消原因（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §6.4）。
- 权限审查只读展示，禁止在插件详情页直接写入授权存储。

### 4.5 更新与卸载

- 插件更新由分发链路与蓝绿替换承担，不需重启平台（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §6.2）。面板提供"更新"动作与更新状态呈现；更新成功后刷新注册表记录与详情。
- 卸载规则：
  - 仅 `installed` 或 `failed` 可卸载；`active` / `stopping` 必须先停用，否则返回 `KERNEL_INVALID_TRANSITION`。
  - 存在任何已安装依赖者时拒绝卸载（`KERNEL_DEPENDENCY_CONFLICT`），返回依赖者清单并要求先处理。
  - `source: builtin` 的内置插件不可卸载，只能停用；界面以"系统组件"标识并说明原因，不得静默失败。
- 卸载确认对话框必须说明：卸载会删除插件文件、插件配置与授权记录；用户文档不受影响；同 ID 再次安装视为全新安装，不恢复旧配置（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §3.1、[05-事件契约规范](../05-接口与契约/05-事件契约规范.md) §4.1）。
- 卸载完成后按 `plugin:uninstalled` 事件刷新；若用户当前正查看被卸载对象，返回列表并提示。

### 4.6 数据清理

数据清理在插件详情页承担，分三类，动作、风险与确认强度不同：

| 类型 | 内容 | 可用状态 | 语义与确认 |
|---|---|---|---|
| 缓存与派生数据 | 插件产生的可重建缓存（缩略图、索引等） | 任意已安装状态 | 安全动作；确认对话框说明"可重建、不影响数据" |
| 插件私有数据 | 插件私有数据目录中的用户可见数据（草稿、历史、本地索引等） | 停用或 `failed` | 高风险不可撤销；确认对话框展示占用大小并要求二次确认；用户文档与卡片内容不在此范围 |
| 配置覆盖 | 插件在当前用户层与工作区层的配置覆盖 | 停用或 `failed` | 移除覆盖后回落到插件默认值；仅清理显式覆盖，不删除文件本身 |

- 面板不得直接删除目录；清理动作必须经平台治理能力执行，并返回实际释放量。
- 清理完成后刷新该插件的数据占用摘要；清理失败保留原状并展示错误码。
- 插件卸载时的授权记录与配置文件删除由平台执行，面板不重复清理（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §6.5）。

### 4.7 应用快捷方式

仅应用插件（`app`）拥有系统入口，治理动作在应用插件详情页：

| 动作 | 语义 |
|---|---|
| 创建 / 重建 | 为应用创建（或按 `replace` 覆盖更新）桌面快捷方式（Windows）或启动台入口（macOS） |
| 移除 | 删除系统入口并清理平台登记记录 |
| 显示位置 | 在系统文件管理器中定位入口文件 |

- 状态展示：已创建 / 未创建、目标位置（桌面 / 启动台）、入口名称；`exists` 以平台返回值为准，前端不得自行判断文件是否存在。
- 全部动作经平台快捷方式治理接口执行；面板不得创建 `.lnk`、`.app` 或写入任何平台文件（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §1.2）。
- 创建图标优先使用平台返回的入口图标资源；缺失时回退到运行时统一图标组件，不显示 emoji 与路径文本。
- 卸载插件时平台尝试回收其入口；面板不补删。
