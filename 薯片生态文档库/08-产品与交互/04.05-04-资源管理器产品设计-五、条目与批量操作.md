## 五、条目与批量操作

### 5.1 打开

1. 双击 / 回车 / 右键"打开" / 工具栏"打开"对文档与普通文件表达**资源打开意图**，经 `resource:open` 能力（`origin: 'in-app'`，意图缺省 `view`）提交；平台按处理器声明（`primary` 优先、`tier: fallback` 兜底、无候选按来源确定性降级）完成路由与呈现（[资源打开与默认处理器契约](../05-接口与契约/14-资源打开与默认处理器契约.md) §二、§四）。
2. 资源管理器只发起意图：不创建查看 / 编辑会话，不自行 `document:open` 打开内容，不拼接渲染帧，不实现"用自己的窗口打开文档"；`resource:open` 的输入只接受受管 `chips-resource://` 引用。
3. 多选中时打开动作禁用并提示"请选择单个条目打开"，避免批量创建窗口。
4. 文件夹的"打开"表示进入该位置，不产生资源打开意图。
5. 打开失败（目标不存在、无处理器、权限被拒、处理器启动失败）按契约的失败语义在当前界面给出错误态与恢复动作（`RESOURCE_HANDLER_MISSING` / `BRIDGE_PERMISSION_DENIED` / `RESOURCE_PERMISSION_DENIED` / `APP_LAUNCH_FAILED` / `APP_OPEN_FILE_FAILED` 等，[资源打开与默认处理器契约](../05-接口与契约/14-资源打开与默认处理器契约.md) §4.7），不改变既有窗口内容。

### 5.2 单条目操作

| 操作 | 实现（能力） | 规则 |
|---|---|---|
| 重命名 | `file:move`（同目录改名） | 目标已存在返回 `FILE_ALREADY_EXISTS`；目录态卡片改名不改变 `card_id`（[工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §3.3） |
| 移动 | `file:move` | 目标必须是目录且在同一工作区；保留路径拒绝（`WORKSPACE_RESERVED_PATH`）；打开中的文档被移动后由平台按外部修改提示（[工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §5.5） |
| 复制 | `file:copy` | 目录递归复制；目标存在时先确认再以 `overwrite: true` 执行；不复制到保留路径 |
| 删除 | `file:delete` | 平台无回收站：确认对话框必须写明"删除后无法恢复"；非空目录需二次确认并携带 `recursive: true`；保留路径拒绝 |
| 新建文件夹 | `file:mkdir` | 仅创建目录；不提供新建卡片 / 箱子（创建与编辑属编辑引擎职责，[编辑引擎设计](../01-架构设计/01-子系统设计/12-编辑引擎设计.md) §8.4） |

- 覆盖与删除的确认对话框使用应用内组件（平台不提供确认能力）；确认文案明确对象数量与范围。
- 操作成功后以本地模型增量更新并等待平台事件收敛；同一变化不重复刷新（去重）。

### 5.3 多选与批量操作

- 选择模型：单击选择、`Mod` 点击切换单项、`Shift` 点击选择连续范围、`Mod+A` 选择当前视图全部结果、`Esc` 清除选择；选择在虚拟化列表中按路径集合保持，切换视图与排序不丢失。
- 批量操作：批量标签（§3.5）、批量移动、批量复制、批量删除。
- 批量执行规则：
  1. 操作前对删除与覆盖给出汇总确认（项数、目标位置、不可恢复提示）。
  2. 逐项执行、串行提交；进行中显示进度与"取消"（取消在项之间生效）。
  3. 单项失败不回滚已成功项；删除与移动不产生中间态（平台原子性，[资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) §4.9）。
  4. 结束后给出结果清单：成功数、失败数、失败项与原因（错误码 + 中文说明），提供"仅重试失败项"。
- 批量移动 / 复制的目标通过目录选择器（进入目标位置后确认）确定，不使用真实路径文本输入。

### 5.4 与已打开文档的关系

- 资源管理器不感知其他应用的编辑会话，不代为保存 / 关闭；重命名、移动、删除对已打开文档的影响完全按 [工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §5.5 处理。
- 批量标签写入遇到他处正在编辑的文档时返回写冲突，按单项失败处理并提示"该文档正在另一个窗口中编辑"。
- 若元数据读取发现文档版本门禁不通过（`DOCUMENT_VERSION_*`），该项标记为"无法读取元数据"，不影响浏览与其他操作。
