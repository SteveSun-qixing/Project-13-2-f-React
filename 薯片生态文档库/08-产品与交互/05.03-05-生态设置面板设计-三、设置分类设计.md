## 三、设置分类设计

### 3.1 外观

| 设置项 | 配置键 | 取值与默认 | 行为 |
|---|---|---|---|
| 界面密度 | `platform.appearance.density` | `comfortable`（默认） / `compact` | 切换 `@chips/ui` 的密度语义并即时重绘全部窗口；不改变系统缩放 |
| 动效偏好 | `platform.appearance.motion` | `system`（默认） / `reduced` | `system` 时遵循操作系统"减少动态效果"；`reduced` 时由平台统一关闭非必要过渡 |
| 默认窗口宽度 | `platform.window.defaultWidth` | 整数，最小 640，默认 1200 | 仅影响后续新创建的应用窗口，不改变已打开窗口 |

- 面板不提供主题、配色、强调色或字体家族选择：视觉由 `@chips/ui`、Design Tokens 与 antd 主题定制统一承担（R4、R5）。
- 密度与动效偏好是平台级键，对所有窗口生效；插件不得自行读取系统缩放或覆盖该偏好。

### 3.2 行为

| 设置项 | 配置键 | 取值与默认 | 行为 |
|---|---|---|---|
| 系统通知 | `platform.behavior.notifications` | `true`（默认） / `false` | `false` 时平台在通知能力出口统一丢弃系统通知；不改变应用内部的界面内提醒 |
| 自动检查更新 | `platform.behavior.autoCheckUpdate` | `true`（默认） / `false` | `false` 时停止平台定时更新检查；用户仍可在"关于更新"页发起手动检查 |
| 日志级别 | `platform.log.level` | `error` / `warn` / `info`（默认） / `debug` | 调整平台日志输出级别；该键已注册于平台 schema，界面标记为"高级"并附用途说明 |

- 行为分类不提供网络代理与下载并发设置：平台不设全局代理，网络访问按插件的 `network:http` 权限逐项目标治理（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §3.2）。
- 关闭窗口、后台运行等生命周期语义由插件 `runtime.background` 声明与平台生命周期规则决定（[07-应用插件接口](../05-接口与契约/07-应用插件接口.md) §5.2），不作为用户偏好项。

### 3.3 工作区

| 区域 | 内容 | 数据来源 |
|---|---|---|
| 当前工作区 | 工作区根路径、标记版本、绑定状态（正常/未绑定）、实例锁状态 | `config:get(platform, workspace.path)`、工作区状态接口 |
| 切换工作区 | 打开目录选择并触发平台切换流程；存在未保存变更时由平台流程接管确认 | 平台工作区切换流程 |
| 位置动作 | 在系统文件管理器中打开工作区根目录 | `shell:openExternal` |
| 保留区说明 | `.chips/` 为平台保留目录：配置、日志、缓存、备份、实例状态；说明其可重建性与缓存入口 | [13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §3.1 |
| 环境隔离说明 | 开发工作区与用户工作区为两个独立目录，插件记录、日志与配置互不混用 | [13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §七 |

- 工作区绑定向导（首次绑定、目标目录被占用、不可写、版本不支持等）由平台壳承载（[13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §2.2）；本页只提供状态查看、切换与故障入口。
- 工作区切换是唯一会整体重载工作区层配置的动作；切换完成后页面必须重新读取全部配置生效值与缓存占用，不得沿用旧值。

### 3.7 文件打开方式

- 页面按扩展名分组展示全部已注册的处理器槽位；同一类型存在多个处理器时展示候选清单、当前默认项与来源（用户偏好/专用处理器/兜底处理器）。
- 每个类型提供：设为默认、清除偏好（回落到平台优先级）、恢复全部默认。
- 用户偏好写入用户层配置，键与 schema 归口配置系统；处理器槽位来自平台资源打开治理，声明语义见 [07-应用插件接口](../05-接口与契约/07-应用插件接口.md) §5.4。
- 插件安装、启用、停用与卸载后，槽位列表必须刷新；用户偏好指向的处理器不可用时，界面提示并保留偏好记录，由平台在路由时按回退规则处理。
- 页面必须说明：文件关联只决定路由，不产生文件内容授权；应用读取内容仍受 `filesystem:read` 与资源权限判定（[07-应用插件接口](../05-接口与契约/07-应用插件接口.md) §5.4）。

### 3.8 存储缓存

| 区域 | 位置 | 动作与语义 |
|---|---|---|
| 可重建缓存 | 工作区 `.chips/cache/`（默认上限 512 MiB，LRU 淘汰） | 展示占用；"清理缓存"安全且不影响任何文档与配置（[13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §3.1） |
| 工作区日志 | 工作区 `.chips/logs/` | 展示位置与占用；"清理日志"删除已轮转日志，不影响运行 |
| 迁移备份 | 工作区 `.chips/backup/`、用户级 `backup/` | 展示位置与占用；"清理旧备份"在确认后删除迁移与修复前备份 |
| 更新暂存 | 平台用户数据目录 `updates/staging/` | 由平台更新器管理；展示占用，未完成暂存由平台启动时清理（[06-更新与分发规范](../06-开发与运维/06-更新与分发规范.md) §2.4） |
| 插件数据 | 各插件私有数据目录与配置 | 占用汇总；清理动作在插件治理详情页执行（4.6 节） |

- 全部清理动作只作用于平台可重建物与平台暂存物，绝不删除用户文档、用户目录与凭证材料；凭证材料不在工作区内（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §7）。
- 磁盘空间不足的提示与引导遵循更新规范的"提示用户清理、不自动删除用户文件"口径（[06-更新与分发规范](../06-开发与运维/06-更新与分发规范.md) §2.4）。

### 3.9 关于更新

| 区域 | 内容 | 数据来源 |
|---|---|---|
| 版本信息 | 平台版本、操作系统与版本、架构、语言环境 | `system:info`（[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) §7.14） |
| 更新通道 | 当前通道（`stable` / `beta`）及其实例说明 | 平台策略键 `platform.update.channel`；展示与切换由平台更新器的系统设置面承载 |
| 更新状态 | 检查时间、可用版本、已下载待安装状态、失败原因、被暂缓的版本 | 平台更新器状态；错误码 `UPDATE_*` 见 [06-更新与分发规范](../06-开发与运维/06-更新与分发规范.md) §3.4 |
| 许可与致谢 | 平台许可、第三方开源资产链接、文档库入口 | 静态资源与 `shell:openExternal` |
| 诊断信息 | 目录变量解析值（配置目录、用户数据目录、工作区路径） | `system:info.paths` |

- 更新执行（下载、校验、原子替换、重启安装）与手动检查由平台更新器承担，不向插件暴露接口（[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) §6.4）；本页呈现状态并提供平台更新入口。
- 更新通道是平台策略键：只在平台层文件有效，不可经插件配置写入（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §2.3、§4.2）；面板必须将该键显示为受平台策略管理，不提供伪造的本地开关。
- 平台不提供版本回退安装；失败恢复的语义与文案以更新规范 §2.4、§四为准，界面不得使用"降级/回滚安装"表述。
