## 一、定位与边界

### 1.1 定位

编辑引擎（`chips.official.editor`，`app` 角色）是编辑链路的官方消费者，也是 `.card` / `.box` 的官方生产工具。本文回答三个问题：

1. 用户进入编辑引擎后**看到什么**：布局模式、程序坞、卡箱库、文件面板、窗口、面板与占位；
2. 用户**如何操作**：拖拽、选中、排序、插入、右键、键盘、缩放与切换；
3. 系统**如何反馈**：空态、加载态、错误态、降级占位、确认与通知。

本文是编辑引擎应用层交互设计的唯一权威；同一插件内的实现细节（组件结构、状态管理、样式实现）落在应用仓库技术文档，但不得违背本文与 12 的约束。

### 1.3 术语与命名消歧

| 术语 | 定义 |
|---|---|
| 布局模式 | 编辑引擎主窗口内工作区的界面编排方式，内置六种（§二）；是应用内部 UI 状态，不构成插件扩展点 |
| 桌面层 / 窗口层 | 无限画布内的两层：桌面层承载卡片 / 箱子窗口并随桌面缩放平移；窗口层承载工具窗口与程序坞，固定于屏幕位置 |
| 文档窗口 | 承载一张卡片或一个箱子的窗口（卡片窗口 / 箱子窗口），是编辑会话的界面载体 |
| 工具窗口 | 承载工具面板的窗口：文件面板、卡箱库、历史面板等 |
| 程序坞 | 工具窗口的固定停靠区与恢复入口（含最小化工具窗口的图标） |
| 卡箱库 | 基础卡片类型与箱子布局类型的展示与拖拽创建面板 |
| 窗口显示状态 | 文档窗口的呈现状态：展开 / 收起 / 封面 / 最小化（§五） |
| 锁定 | 文档窗口在编辑模式与查看模式之间的切换开关 |

命名消歧（强制）：

- 本文「布局模式」一律指编辑引擎的工作区界面编排；箱子布局类型（`boxlayout` 插件的 `capabilities.layouts[]`）是箱子内容的呈现方式，两者不同层级、不同权威，术语并存但不得混用（§2.11）。
- 编辑引擎布局模式「网格 / 看板 / 时间轴 / 无限画布」与箱子布局类型、资源管理器视图存在同名或近名概念，引用时必须带限定语（如「编辑引擎布局模式：网格」）。
- 编辑引擎的「桌面层 / 窗口层」是应用窗口内部的两层编排，不是平台 `ui.surface: desktop` 表面，也不是操作系统桌面。

### 1.4 基本约束

1. 界面只使用 `@chips/ui` 组件与 Design Tokens、antd 主题定制；文案简体中文直写，不使用 i18n key（R4、R5）。
2. 所有系统能力经 `window.chips`；应用插件不持有 `IManagedPluginRuntime`，编辑器挂载一律经 `IEditSession`（[12](../01-架构设计/01-子系统设计/12-编辑引擎设计.md) §8.2）。
3. 应用内的动作统一登记为命令，由命令面板、菜单、上下文菜单、工具栏与快捷键消费同一条记录；不在组件内维护第二套动作模型（[命令系统契约](../05-接口与契约/13-命令系统契约.md) §5.1）。
4. 高频 UI 状态（选择、滚动、拖拽位置、窗口位置与尺寸、布局模式、程序坞显隐）只存在于应用内存或编辑会话，不写入文档、不写入配置（[12](../01-架构设计/01-子系统设计/12-编辑引擎设计.md) §1.4、§10）。
5. 文档内容的一切写入经编辑链路的唯一时序；新建、导入、导出、另存经文档服务与资源管理的受控链路（R8、裁决 B-7）。
6. 编辑引擎不实现解析、渲染、读写、资源访问的任何旁路；查看态内容一律经受控封面渲染接口或渲染会话（[12](../01-架构设计/01-子系统设计/12-编辑引擎设计.md) §8.1）。
