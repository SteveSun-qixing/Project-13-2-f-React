## 二、标签模型（交互口径）

### 2.1 两种标签形态

1. **简单标签**：单段字符串，用于快速分类（"工作"、"学习"、"已完成"）。
2. **结构化标签**：首段为键、后续为值序列，用于层级化信息（`地点:日本:东京`、`时间:2026:一月`、`项目:网站改版:设计`）。

规则：

- 一个文档的标签集合内允许两种形态混用，顺序保持用户编辑顺序；
- 结构化标签的键是分类，值是分类下的具体取值；同一键下可以有不同的值序列长度；
- 标签系统不提供标签实体、标签文件夹与独立的标签层级树；层级完全由结构化标签的段序列表达；
- 标签不参与文档命名、文件系统路径与文档 ID；重命名文档、移动文档都不改变标签。

### 2.2 显示形态

- 简单标签：原样显示，如 `工作`；
- 结构化标签：各段以 `:` 连接，如 `地点:日本:东京`；
- 段内包含 `:`、空白或运算符词时按 §3.3 转义后显示，确保显示形态复制到搜索框后可直接解析；
- 界面上的标签 chips 直接呈现该文本，转义只是必要字符的书写方式，不对用户做二次解释；编辑 chip 时回到未转义的段编辑状态。

展示链路约束：查看态与编辑态的标签展示来自渲染视图的 `tags`（[核心接口规范](../05-接口与契约/03-核心接口规范.md) §6.6 的 `TagView`、[渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §2.5），插件与产品不得自行读取 `metadata.yaml` 字节。

### 2.3 匹配形态与等价判定

用于查询匹配、编辑器去重提示与索引聚合计数的匹配形态按以下顺序归一：

1. Unicode NFC 规范化；
2. 裁剪段首尾空白（含半角与全角空白）；
3. 段内连续空白折叠为单个半角空格；
4. ASCII 字母大小写折叠（仅比较用，不改变存储）；
5. 段序列必须一致（段数、顺序、内容）。

规则：

- 两个标签项匹配形态一致即视为**同一标签**；`Work` 与 `work`、`地点:日本` 与 `地点 : 日本` 判定为同一标签；
- 存储保留用户输入原样（写入链路按[卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §4.3 去重，同一文档内保留首次出现的形态）；
- 编辑器添加标签时先按匹配形态查重，命中已有标签时复用已有形态，不新增近似重复项；
- 索引按匹配形态归并计数；查询匹配同样按匹配形态比较。

### 2.4 输入约束

| 约束 | 取值 | 执行者 |
|---|---|---|
| 单段长度 | ≤ 64 字符 | 标签编辑器与各创建入口 |
| 结构深度 | ≤ 8 段（1 键 + 至多 7 值） | 同上 |
| 单文档标签项数 | ≤ 128 | 同上 |
| 空段 / 纯空白段 | 禁止创建 | 同上 |
| 约束外的既有数据 | 可读取、可索引、可查询，不自动修改 | 读取与索引 |

约束只作用于交互层，不改写文件格式的 schema；由第三方工具写入的超限数据不影响平台读取与索引，仅在标签编辑器中提示"标签超出编辑上限"。

### 2.5 标签外观

- 标签没有独立实体，因此**不存储颜色、图标与描述等标签元数据**；外观由确定性规则生成：对匹配形态做稳定散列，从 `@chips/ui` 暴露的 Design Tokens 标签色板取值；
- 同一标签在所有产品、所有窗口中外观一致；深色模式、字号与圆角随 antd 主题 token 变化，不写死任何颜色与尺寸；
- 结构化标签为整体 chip：键使用强调字重，值以 `:` 分隔；超长标签在 chip 内截断，悬停显示完整显示形态。
