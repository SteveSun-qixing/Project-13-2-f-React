# 拖动与拖放交互规范

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片生态拖动与拖放交互的权威规范：拖放载荷数据模型与 MIME 映射、来源与落点矩阵、外部文件拖入工作区建卡（批量与冲突命名）、嵌套与优先级、插入指示与合法落点、触屏/滚轮/键盘等价、无障碍要求，以及与编辑链路节点交互协议的衔接；不定义插件接口签名、文档读写语义、工作区目录规则与能力契约本身。

## 一、定位与边界

### 1.1 定位

拖放（drag and drop）是薯片生态中跨面板、跨文档与跨应用运输内容的第一类输入方式：把卡片、箱子、文件、文本、URL 与多选项从拖动源搬运到落点，并以明确的落点语义完成移动、复制、导入、打开或创建。

拖放不新增写路径，也不新增数据通道：一次拖放只改变交互意图，落点结果必须由既有正式链路执行（`IEditSession`、`document:export`、`file:*`、`openFile`、插件编辑器变更回流）。本文件是以下内容的唯一权威：

1. 拖放载荷的数据模型、项类型与 MIME 映射；
2. 拖动源与落点清单、落点矩阵与结果到正式链路的映射；
3. 外部文件拖入工作区的导入与建卡行为（批量、冲突命名、失败呈现）；
4. 嵌套语义的现状、落点判定顺序与优先级；
5. 插入指示、拖动预览与合法落点的视觉与状态规则；
6. 触屏、滚轮与键盘等价路径及焦点管理；
7. 拖放的无障碍要求；
8. 拖放交互与编辑链路节点交互协议的对照与衔接。

### 1.3 术语

| 术语 | 定义 |
|---|---|
| 拖放（drag and drop） | 用户按住拖动源、以指针位移携带内容并在落点释放的完整交互；"拖拽"为口语同义词，正式文档统一使用"拖放/拖动"。 |
| 拖动源 | 发起拖动的界面元素或面板：工作区文件树、卡片节点区、箱子条目列表、卡箱库面板、文本选择区、操作系统或其他应用。 |
| 落点 | 接收拖放并在释放时给出明确结果的区域；按本规范 §3.2 分为 D1-D7。 |
| 索引落点 | 以"插入索引"表达结果的落点（节点间隙、条目间隙）；语义是插入/重排，不是覆盖。 |
| 容器落点 | 以"接收整体"表达结果的落点（插件编辑器容器、卡片/箱子窗口、工作区）。 |
| 插入指示 | 拖动过程中在目标间隙绘制的高亮线，指示释放后的插入索引。 |
| 载荷（payload） | 一次拖动携带的结构化数据：`ChipsDragPayload`（§二）。 |
| 受管引用 | 经资源管理归一的可寻址引用（`chips-resource://` 等形式），是载荷与文档内容之间唯一的引用形态。 |
| 外部拖入 | 指针从应用窗口外进入应用或工作区的拖放；载荷来源 `origin: 'external'`。 |
| 拖出 | 指针携带载荷离开应用窗口并在外部应用释放；只产生外部表示，不产生应用内写入。 |

### 1.4 基本约束

1. **单一载荷模型**：所有拖放共用同一载荷结构与同一落点判定流程；不得为某个面板、某个类型或某个插件另立第二套拖放通道。
2. **查看态无拖放**：渲染帧内不接收、不发起平台拖放；查看态只读（[渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §6.3、[编辑引擎设计](../01-架构设计/01-子系统设计/12-编辑引擎设计.md) §5.5）。
3. **拖放不写文件**：拖动过程的中间状态（悬停、指示位置、预览）只存在交互内存中，不写入文档、不写入配置、不进入历史栈（[编辑引擎设计](../01-架构设计/01-子系统设计/12-编辑引擎设计.md) §1.4、§十）。
4. **绘制归属固定**：节点外壳、条目外壳、插入指示与拖动预览由编辑链路/应用绘制；插件编辑器容器内的落点反馈由插件绘制并只使用 `@chips/ui` 与 Design Tokens（[编辑引擎设计](../01-架构设计/01-子系统设计/12-编辑引擎设计.md) §5.1）。
5. **载荷不含敏感信息**：载荷项不携带文件字节、真实路径、句柄、函数与类实例；对外表示不携带受管引用、工作区相对路径与文档内部标识。
6. **单项原子**：一次释放的每一项结果独立结算；单项失败不回滚已成功的项，也不留下"结构已引用、内容缺失"的中间状态（[编辑引擎设计](../01-架构设计/01-子系统设计/12-编辑引擎设计.md) §6.2）。
7. **全中文**：拖动提示、落点提示、播报与错误文案一律简体中文直写，禁止多语言运行时（[架构原则](../00-愿景与原则/01-架构原则.md) R5）。
