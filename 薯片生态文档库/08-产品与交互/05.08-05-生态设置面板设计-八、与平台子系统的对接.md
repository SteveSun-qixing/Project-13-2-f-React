### 8.2 配置系统对接

- 命名空间：设置面板只访问 `platform` 命名空间与自身命名空间 `plugins.chips.official.settings`；其他插件的命名空间一律不可见、不可写（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §2.3）。
- 写入层：偏好写入只允许 `user` 与 `workspace` 层；策略键（`x-chips-policy`）只读并标记"由平台策略管理"；写入被拒时按 `CONFIG_POLICY_LOCKED`、`CONFIG_KEY_UNKNOWN`、`CONFIG_VALUE_INVALID`、`CONFIG_NAMESPACE_DENIED`、`CONFIG_WRITE_FAILED` 分别提示。
- 变更订阅：订阅 `config:changed`，以载荷中 `effectiveValue` 为准刷新界面；工作区切换后 `origin: platform` 的事件逐一更新生效值（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §6.2）。
- 不承载高频状态：滑块拖动等高频输入在本地渲染，松手或停止输入后才提交；连续按键录制不写配置（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §9.4）。
- 外部修改：配置文件被外部修改时以配置系统的外部修改保护与 `origin: external` 事件为准，界面刷新生效值，不提示用户手工编辑文件。

### 8.3 权限系统对接

- manifest 最小权限集合（示例，限定值按实际路径收窄）：

```yaml
permissions:
  - config:read:platform
  - config:write:platform
  - system:read
  - dialogs:use
  - clipboard:access
  - shell:external:https
  - filesystem:read:${userDocuments}/chips
  - filesystem:write:${userDocuments}/chips
```

- 插件治理、授权审查、存储治理与快捷键绑定四类治理能力所需的权限 ID 随能力在 [04-能力契约规范](../05-接口与契约/04-能力契约规范.md) §6.2（R19 表）登记后按最小范围声明；面板不申请未使用的能力权限。
- 面板自身的治理动作同样受权限判定：权限不足返回 `BRIDGE_PERMISSION_DENIED`，界面按权限系统 §9.3 文案引导，不展示原始异常字符串。
- 任何治理动作不得放宽判定：面板不代替用户授予其他插件的权限，只呈现并执行用户的显式选择。
- 审计：撤销、恢复、快捷键配置导入、数据清理与卸载动作必须写入审计；面板不读取、不修改审计存储。

### 8.4 事件与刷新

| 事件 | 用途 |
|---|---|
| `plugin:installed` / `plugin:uninstalled` / `plugin:enabled` / `plugin:disabled` / `plugin:unloaded` / `plugin:failed` | 刷新插件列表、详情与文件打开方式槽位 |
| `config:changed` | 刷新偏好项生效值与生效层 |
| `permission:granted` / `permission:denied` | 刷新权限页条目（可见性：目标插件与平台） |
| `security:audit` | 追加审计记录视图（可见性：平台与官方审计界面） |
| `app:launched` | 应用插件启动后刷新其运行状态 |

- 全部订阅按组件挂载建立、卸载释放；刷新处理必须幂等，重复事件不产生重复插入。

### 8.5 命令与外观对接

- 每个 Scene 注册稳定命令并通过命令系统调用；命令标题、图标与快捷键元数据只注册一次，侧栏、顶部切换器与命令面板消费同一份数据（[13-命令系统契约](../05-接口与契约/13-命令系统契约.md)）。
- 界面实现遵循 [React 组件开发规范](../02-开发规范/03-React组件开发规范.md) 与 [ADR-008](../01-架构设计/ADR/ADR-008-React加fork-antd前端技术栈.md)：组件只能从 `@chips/ui` 导入，样式取 Design Tokens，不引入第二套组件库。

### 8.6 设置面板消费平台配置（策略键只读、自身命名空间免权限）

| 项 | 规则 | 权威 |
|---|---|---|
| 命名空间 | 面板只访问 `platform` 命名空间与自身命名空间 `plugins.chips.official.settings`；其他插件命名空间不可见、不可写 | [10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §2.3 |
| 自身命名空间 | 读写自身命名空间免权限：引导标记、界面偏好等面板私有状态经 `config:get` / `config:set` / `config:reset` 存取，不申请额外权限 | 10 §2.3、§11.3；[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) §7.11 |
| 平台命名空间读取 | 需 `config:read:platform`；外观、行为、工作区、文件打开方式、快捷键覆盖、更新通道等平台键按生效值展示 | 10 §2.3；04 §7.11 |
| 平台命名空间写入 | 需 `config:write:platform`；只写 `user` 与 `workspace` 层，不写 `platform` 层 | 10 §2.3；04 §7.11 |
| 策略键 | schema 标记 `x-chips-policy: true` 的键只读：界面标注「由平台策略管理」并禁用编辑，写入返回 `CONFIG_POLICY_LOCKED` 且不重试 | 10 §2.2、§4.4；§9.3 |
| 未注册键 | `CONFIG_KEY_UNKNOWN` / `CONFIG_VALUE_INVALID`：保留原值并提示原因；属于面板缺陷时记录诊断 | §9.3 |
| 生效值 | 界面一律以 `config:changed` 的 `effectiveValue` 与 `isDefault` 渲染；默认值不落盘，恢复默认即移除显式覆盖 | 10 §5、§6.2 |
| 高频输入 | 滑块等高频输入本地渲染，松手或停止输入后提交；连续按键录制不写配置 | 10 §9.4 |
| 外部修改 | 配置文件被外部修改时只刷新生效值，不提示用户手工编辑文件、不覆盖外部修改 | 10 §6.2、§9 |
| 工作区切换 | 工作区层覆盖随切换重算，按 `origin: platform` 的 `config:changed` 逐项更新生效值 | 10 §6.2 |

- 面板是平台配置的产品清单与交互权威（§10.1），不是配置 schema 的定义者：平台设置键的 schema 注册、默认值与迁移由 [10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) 统一承担，键未注册即不展示编辑项。
- 写入失败一律按上表错误码分支处理，禁止匹配错误文本；策略键在被平台策略管理期间不得通过任何旁路（面板自身命名空间、文件编辑）改写生效值。
