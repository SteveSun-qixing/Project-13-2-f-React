## 五、权限页（授权审查）设计

### 5.1 页面结构

- 顶部筛选：按插件、按权限域、按状态（已授予 / 已拒绝 / 未记录）、按风险级别。
- 主体以插件为分组，逐条列出授权记录；无授权记录的插件显示"未申请任何权限"。
- 每条记录展示 4.4 节的字段，并提供"撤销"（已授予）或"恢复"（已拒绝）动作。

### 5.2 撤销与恢复

- 撤销：写入 `denied` 并递增授权版本号；该插件会话权限快照立即失效，后续调用被拒绝，进行中的调用不中断（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §6.5）。确认对话框必须说明"立即生效、正在进行的操作不中断"。
- 恢复：用户手动授予后重建会话快照，插件无需重启。
- 撤销与恢复是平台内置设置面的专属动作，一般插件不提供写接口；面板必须以平台治理能力执行并写入审计。
- 卸载插件时其授权记录与快照由平台删除，审计记录保留（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §6.5）。

### 5.3 审计记录

- 页面提供"审计记录"视图，按时间倒序展示授权、撤销、拒绝与敏感放行记录（`security:audit`，可见性为平台与官方审计界面，[05-事件契约规范](../05-接口与契约/05-事件契约规范.md) §4.6）。
- 支持按插件、动作、时间范围过滤；记录字段（时间、插件、权限、限定值、动作、来源、拒绝原因、追踪 ID）以权限系统 §8.2 为准，面板不自定义字段。
- 运行时拒绝提示中的"前往授权"入口定位到对应插件与权限条目；拒绝文案遵循权限系统 §9.3 的用户提示口径。

### 5.4 授权撤销与官方审计界面

#### 5.4.1 授权撤销与恢复闭环

- 触发入口：权限页条目「撤销 / 恢复」（§5.1）；运行时拒绝提示「前往授权」定位到对应插件与权限条目（§5.3）。插件详情页的「前往权限页查看全部」只做跳转，撤销 / 恢复统一在权限页执行，不复制写入逻辑（§4.4）。
- 确认：确认对话框展示插件名、权限中文说明与解析后的限定值，并明确「立即生效：后续调用将被拒绝；正在进行的操作不会中断」（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §6.5）。
- 执行与回执：撤销 / 恢复经平台内置设置面治理动作执行（§5.2）；界面在平台确认后更新条目状态，禁止本地先行改状态；成功状态只以平台返回值与 `permission:granted` / `security:audit` 事件为准（§8.4）。
- 失败：权限不足、治理动作失败或授权存储写入失败时保持原状态，提示原因与重试；不提供「恢复全部」「撤销全部」等批量入口。
- 边界：面板不直接读写授权存储 `<userData>/security/permissions.yaml`（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §6.6）；撤销与恢复能力的登记归 [04-能力契约规范](../05-接口与契约/04-能力契约规范.md) 能力表统一收口，面板只按登记能力调用。

#### 5.4.2 官方审计界面

- 定位：本面板是生态的官方审计界面（`security:audit` 可见性为「仅平台与官方审计界面」，[05-事件契约规范](../05-接口与契约/05-事件契约规范.md) §4.6）；审计视图与权限页同属插件治理域，入口固定为「插件 → 权限 → 审计记录」。
- 列表：按时间倒序的虚拟化列表；每行展示时间、插件（名称 + ID）、权限（中文名 + ID）、动作（授予 / 撤销 / 拒绝 / 放行）与结果摘要；选择记录打开详情抽屉。
- 筛选：插件、动作、权限域、时间范围、来源（启用 / 首次调用 / 设置 / 更新 / 卸载）；条件可组合、可清除，筛选变化即重新拉取，不改变时间倒序。
- 详情：字段以 [08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §8.2 为唯一权威（含 `qualifier`、`capabilityId`、`target`、`resourceUri`、`reason`、`traceId`、`requestId`）；面板不自定义、不重命名字段，技术 ID 只作次要参考。
- 数据来源与刷新：
  - 初始加载与筛选经平台审计读取接口（仅对平台内置设置界面开放，[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §8.4）；增量经 `security:audit` 订阅追加（§8.4），订阅按组件挂载建立、卸载释放，重复事件不重复插入。
  - 事件只做增量：刷新必须幂等；事件缺失时按手动刷新重新拉取，不依赖事件必达。
  - 留存：常规至少 180 天、高 / 极高风险至少 365 天，由平台到期清理；界面只展示留存说明，不提供修改入口（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §8.4）。
- 边界：审计数据 append-only；面板不提供编辑、删除与清空入口，不读取审计文件本身，不把审计数据复制到其它存储。
- 状态：空态「暂无授权与拒绝记录」（§9.2）；加载中骨架屏、刷新中保留旧内容（§9.1）；读取失败显示错误标题、错误码与重试动作，并保留上次数据（§9.3）。
