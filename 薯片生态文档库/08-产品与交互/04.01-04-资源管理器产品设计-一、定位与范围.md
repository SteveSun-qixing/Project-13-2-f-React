# 资源管理器产品设计

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：官方应用插件 `chips.official.resource-manager`（资源管理器）的用户可见形态与交互设计：标签导航与筛选、视图（列表 / 网格 / 时间线）、条目与批量操作、收藏与最近、与工作区扫描和事件的对接、搜索与索引边界、拖放、空态与错误态、快捷键、性能要求与自检清单；平台资源访问机制、文档读写链路、工作区扫描模型与能力契约一律引用权威文档，本文不定义协议

## 一、定位与范围

### 1.1 产品定位

资源管理器是工作区内容的**浏览与管理产品**：让用户看到工作区里有什么、按标签与属性找到它、以批量方式组织它，并把"打开"交给平台路由到合适的应用。

| 项 | 内容 |
|---|---|
| 插件角色 | `app`（[ADR-005](../01-架构设计/ADR/ADR-005-插件不分类只分角色.md)、[插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §4） |
| 插件 ID | `chips.official.resource-manager`（[代码组织规范](../02-开发规范/01-代码组织规范.md) §3.2） |
| 表面 | `ui.surface: window`，平台创建主窗口；运行中额外窗口经 `window:create`（[应用插件接口](../05-接口与契约/07-应用插件接口.md) §5.2） |
| 数据根 | 当前绑定的运行时工作区（[工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §2.1） |
| 启动器 | 注册启动器入口（[插件清单规范](../03-插件开发/02-插件清单规范.md) §8.3）；不声明 `fileAssociations`，不成为任何格式的处理器 |

**术语区分（强制）**：本文"资源管理器"一律指上述应用插件；平台侧的 Rust 子系统统一称**资源管理（ResourceManager）**，其挂载、句柄、缓存、作用域与受控写入机制以 [资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 为唯一权威。资源管理器不实现、不复制、不绕过资源管理子系统。

职责边界：

1. **浏览**：呈现工作区目录结构、条目属性、文档标签与封面预览。
2. **查找**：名称搜索、标签筛选、类型 / 时间 / 收藏筛选。
3. **组织**：重命名、移动、复制、删除、新建文件夹、批量标签、收藏与最近。
4. **不承担**：不创建卡片 / 箱子，不编辑文档内容，不解析 `.card` / `.box`，不查看 / 编辑文档（打开经平台路由），不实现文件预览之外的渲染。

### 1.3 总则

1. **经桥**：所有系统能力经 `window.chips` / `ctx.bridge` 调用；禁止 `node:*`、`electron`、真实文件系统路径与平台内部结构（[架构原则](../00-愿景与原则/01-架构原则.md) R2、R17）。
2. **经链路**：解析、渲染、打开、导出、写入只走统一链路；不自行解析 `.card` / `.box`、不构造文档字节、不实现第二写口（[架构原则](../00-愿景与原则/01-架构原则.md) R8、[文档服务设计](../01-架构设计/01-子系统设计/11-文档服务设计.md) §2.1）。
3. **单一共享层**：组件与 Hooks 只从 `@chips/ui` 导入，颜色、间距、字号、圆角、阴影一律取 Design Tokens；不引入第二组件库、不携带独立样式文件（[React 组件开发规范](../02-开发规范/03-React组件开发规范.md) §11）。
4. **中文直写**：界面文案一律简体中文；不引入 i18n key 与第二语言，不恢复已废弃的主题 / 多语言系统（[ADR-006](../01-架构设计/ADR/ADR-006-主题系统与多语言系统.md)、R5）。
5. **状态分层**：高频交互状态（选择、展开、滚动、焦点、拖拽位置）只留内存；跨会话的浏览状态落插件私有数据目录；用户偏好走插件自身配置命名空间；不得经 `config:set` 往返高频状态（[配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §9.4、[权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §4.4）。
6. **可见降级**：任何失败都有简体中文、可诊断、可操作的界面表现；禁止静默失败、原始堆栈与敏感信息外泄（[故障排查手册](../06-开发与运维/04-故障排查手册.md)）。
7. **单一事实源**：工作区以文件系统原样为唯一事实源；资源管理器不建立与文件系统并行的第二份目录索引，全部派生缓存都可删除、可重建（[工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §1.5 第 1 条）。

### 1.4 应用清单与权限声明

```yaml
id: chips.official.resource-manager
version: 1.0.0
type: app
name: 资源管理器
description: 浏览、筛选与批量管理工作区中的卡片、箱子与文件
author: 薯片官方
license: MIT
runtime:
  targets: [host]
  background: false
permissions:
  - "filesystem:read:${workspace}"
  - "filesystem:write:${workspace}"
  - "filesystem:delete:${workspace}"
  - resources:read
  - resources:write
  - config:read:platform
  - window:control
  - menu:manage
  - shortcut:manage
  - notifications:send
ui:
  surface: window
  launcher:
    icon: assets/icons/resource-manager.svg
    name: 资源管理器
    description: 浏览与管理你的卡片和文件
```

规则：

1. `filesystem:*` 一律以 `${workspace}` 限定；未绑定工作区时相关调用按 [工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §6.1 拒绝，界面进入未绑定空态（§10.1）。
2. `resources:read` 用于文档会话与元数据读取，`resources:write` 用于批量标签的元数据写回；写入只经文档服务受控提交（[文档服务设计](../01-架构设计/01-子系统设计/11-文档服务设计.md) §9.1）。
3. `config:read:platform` 只用于读取 `platform.workspace.path` 判断工作区绑定；不读取其他平台配置。
4. 插件私有数据目录（`${userData}/plugins/chips.official.resource-manager/`）属免权限范围，收藏与最近落该目录；标签索引的存储位置以 [标签系统设计](./06-标签系统设计.md) §6.6 为准（[权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §4.4）。
5. 不声明 `fileAssociations`：`.card` / `.box` 的打开路由由编辑引擎与查看器注册，资源管理器只发起打开意图（§5.1）。
