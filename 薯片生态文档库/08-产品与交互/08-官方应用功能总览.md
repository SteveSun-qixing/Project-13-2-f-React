## 一、定位与边界

### 1.1 定位

本文是官方应用插件的功能总览与职责矩阵，回答四个问题：

1. 官方有哪些应用，每个应用负责什么；
2. 每个应用消费哪些平台能力与插件（基础卡片、箱子布局、服务）；
3. 每个应用读写或消费什么数据格式；
4. 每个应用明确不做什么（已知取舍）。

本文只描述"应用做什么、依赖什么、消费什么"，不描述"怎么实现"。应用的功能细节以对应产品设计文档为准；接口、能力、文件格式与渲染机制以权威契约文档为准，本文不复制、不另立口径。

### 1.2 通用约束

1. 十四个应用全部为 `app` 角色插件，一个插件只有一个角色；官方与第三方使用同一套接口与生命周期，官方不享有特权路径（[ADR-005](../01-架构设计/ADR/ADR-005-插件不分类只分角色.md)）。
2. 应用之间禁止相互 `import`；需要组合时只经服务注入、能力调用与事件订阅三条合法路径（[插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md)）。
3. 一切打开动作经资源打开路由，应用不得硬编码目标插件 ID、不得自行实例化其他插件（[资源打开与默认处理器契约](../05-接口与契约/14-资源打开与默认处理器契约.md) §1.1）。
4. 文档类内容（`.card` / `.box`）的解析、渲染、写入与导出只有一条链路、一个写口；应用不建第二解析器、第二渲染管线或旁路写口（[渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md)、[文档服务设计](../01-架构设计/01-子系统设计/11-文档服务设计.md)）。
5. UI 只从 `@chips/ui` 与 antd 定制主题取用组件与 Design Tokens，界面文案简体中文直写；不引入第二套组件库、不引入多语言运行时（[ADR-008](../01-架构设计/ADR/ADR-008-React加fork-antd前端技术栈.md)、[ADR-006](../01-架构设计/ADR/ADR-006-主题系统与多语言系统.md)）。

## 二、编辑引擎

| 项 | 内容 |
|---|---|
| 插件与角色 | `chips.official.editor`，`app`，`ui.surface: window`；文件关联 `.card` / `.box`；支持深链接启动（[编辑引擎设计](../01-架构设计/01-子系统设计/12-编辑引擎设计.md) §8.4） |
| 定位 | 编辑链路的官方消费者，也是 `.card` / `.box` 的官方生产工具；工作区场景加上卡片窗口与箱子窗口 |
| 核心功能 | 工作区与文件树；卡片 / 箱子的查看与编辑；节点编辑器与布局编辑面板装载；卡片设置与封面编辑；`document:export` 导出；拖拽、选中、排序与右键命令；自动保存与撤销 / 重做；多文档多窗口 |
| 依赖的插件与能力 | 编辑会话 `IEditSession` 与插件门面 `IPluginRuntime`（12）；`document:*` 文档链路（[文档服务设计](../01-架构设计/01-子系统设计/11-文档服务设计.md)）；工作区（[工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md)）；`window:*` / `menu:set` / `shortcut:register` 等能力（[能力契约规范](../05-接口与契约/04-能力契约规范.md)）；基础卡片与箱子布局插件经受管门面装载，不直接 `import`；命令经 [命令系统契约](../05-接口与契约/13-命令系统契约.md) |
| 数据格式 | `.card` / `.box`（目录态与 ZIP Store 两态）；`content/*.yaml` 基础卡片内容；导出产物为 `archive` 或 `directory` 形态 |
| 已知取舍 | 不实现解析、渲染、读写、资源访问的任何旁路；同一文档同一时刻只有一个可写编辑会话，第二个窗口为只读查看；无编辑路径的扩展名不创建半开窗口；配置只存应用偏好，禁止写入文档状态、选择与历史栈 |

| 项 | 内容 |
|---|---|

| 已知取舍 | 扫描 PDF 的 OCR 不移植，给出明确错误态（见 §十六）；口令解密只在内存进行、口令不落日志与审计；解密后保存的产物为**未加密**文档，保存前必须向用户明确提示，平台不提供文档加密（回写）能力；AI 与 Markdown 能力移除；旧 `file.session.*` / `office.document.*` 链路不进入新架构；办公引擎以内容处理服务提供方形态重建，编排归文件处理契约 |

## 十七、约束与自检清单

### 17.1 约束

1. **单一事实源**：每类内容只有一个专用应用承担；万能文件查看器只做兜底；同一功能不在第二个应用重复实现。
2. **路由唯一**：一切打开经资源打开路由；`tier` 只表达专用 / 兜底优先级，不得被解释为权限或能力等级；应用不得硬编码目标插件 ID。
3. **链路唯一**：卡片与箱子的解析、渲染、写入、导出只有一条链路、一个写口；应用不建并行管线、不旁路访问字节。
4. **应用解耦**：应用之间禁止相互 `import`；组合只经服务注入、能力调用与事件订阅。
5. **官方同构**：官方应用与第三方使用相同角色接口、清单与生命周期，不享有特权路径。
6. **职责分层**：本文只做功能总览；机制、协议、交互与实现分别以对应权威文档为准，本文不复制、不另立口径。
7. **落点指向**：§十六 条目只保留设计落点指向，不在本文展开为契约；缺口关闭以落点文档完成为准。

### 17.2 自检清单

- [ ] 十四个官方应用各有一节，定位、核心功能、依赖的插件与能力、数据格式、已知取舍五要素齐全
- [ ] 每节均链接到对应权威文档，未复制其定义与字段表
- [ ] 插件标识、处理器层级、能力 ID 的表述与新库权威文档一致
- [ ] 四个条目只保留设计落点指向，未展开为第二份契约
- [ ] 所有链接指向真实存在的文件（链接检查 0 坏链）
- [ ] 无临时实现、无简化描述、无 TODO 与占位表述
- [ ] 术语与《施工规范·12-术语与裁决速查》及文档库裁决一致
