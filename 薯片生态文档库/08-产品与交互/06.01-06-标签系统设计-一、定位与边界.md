## 一、定位与边界

### 1.1 定位

标签系统是基于文档自带标签的横向组织与检索方式，与工作区文件树正交：**文件树表达"文档在哪里"，标签表达"文档是什么"**。一个文档可以同时拥有任意数量的标签，标签可以跨越目录层级组织内容，并可通过表达式组合筛选。

标签系统不引入独立实体与第二份事实源：

- 标签的事实源是文档 `metadata.yaml` 的 `tags` 字段（[卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §4、[箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) §4）；
- 平台与产品只提供编辑、索引（映射库）与筛选，不提供"标签对象"的创建、存储与生命周期；
- 索引、动态文件夹、最近使用等均为派生数据或用户视图数据，删除后可由文档重建或由用户重建。

### 1.2 术语

| 术语 | 定义 |
|---|---|
| 标签项（TagEntry） | 一个文档上的一条标签：**简单标签**（字符串）或**结构化标签**（字符串数组，首项为键、其余为值）。字段形态与校验以[卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §4、[箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) §4 为准 |
| 简单标签 | 单段字符串标签（如"工作"、"重要"） |
| 结构化标签 | 首段为**键**、后续段为**值序列**的标签（如 `["地点","日本","东京"]`）；键相同的标签视为同一类 |
| 显示形态 | 标签在界面上的文本形态：简单标签为原文；结构化标签以 `:` 连接各段（如 `地点:日本:东京`），特殊字符按 §3.3 转义；显示形态即为查询路径形态，可直接复制为查询条件 |
| 匹配形态 | 用于比较、等价判定与查询匹配的规范形态：Unicode NFC、裁剪段首尾空白、折叠段内连续空白、ASCII 大小写折叠（§2.3） |
| 筛选表达式 | 由标签路径、`AND` / `OR` / `NOT` 与括号组成的查询串（§3） |
| 动态文件夹 | 保存的筛选表达式与视图 / 排序配置，实时展示匹配文档的虚拟视图（§4） |
| 标签索引（映射库） | 由标签索引服务维护的派生索引：标签 → 文档；可从文档元数据重建，不是事实源（§6） |
| 标签导航 | 资源管理器中按标签浏览、聚合与筛选的界面区域（§7.1） |
| 标签编辑器 | 为单个文档添加、修改、删除标签的界面组件（§5） |
| 批量标签操作 | 对多个文档统一添加、删除、重命名、合并标签的跨文档操作（§5.5） |
