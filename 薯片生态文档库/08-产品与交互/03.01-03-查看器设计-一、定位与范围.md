# 查看器设计

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片生态查看类应用（卡片查看器、图片查看器、书籍阅读器、音视频播放器、万能文件查看器）的用户可见形态与交互设计：窗口模型、工具栏与侧栏、查看模式、分享与导出、多窗口与标签页、缓存与恢复、格式支持矩阵、兜底与默认处理器界面表现、键盘与触屏、空态与错误态、性能要求与自检清单；渲染、文档、资源、能力与错误码等机制一律引用权威文档，本文不定义协议

## 一、定位与范围

### 1.1 查看器家族

薯片生态以一组查看类应用覆盖"打开即看"的全部场景：专用查看器各司其职，万能文件查看器兜底，卡片查看器承载 `.card` / `.box` 的正式消费入口。

| 角色 | 查看对象 | 核心能力 | 边界说明 |
|---|---|---|---|
| 卡片查看器 | `.card` / `.box` | 经统一渲染链路显示卡片视图与箱子布局；承载条目激活与资源打开 | `.card` / `.box` 的正式查看入口；不解析文档、不拼帧（[渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §2.1） |
| 图片查看器 | 图片资源 | 单图查看、缩放、平移、适应窗口、实际大小、保存副本；有序图包队列浏览 | 不提供编辑、裁剪、旋转、相册管理 |
| 书籍阅读器 | EPUB / EPUB3 / PDF / TXT / Markdown / FB2 / RTF | 目录、章节、锚点、搜索、书签、进度、阅读偏好、分页与滚动双模式 | 识别而无法解码的重型格式给出明确错误，不内置临时解析器 |
| 视频播放器 / 音乐播放器 | 视频与音频资源 | 播放控制、进度、音量、队列、倍速、全屏、字幕与音轨 | 卡片内嵌播放与独立播放器控制语义一致 |
| 万能文件查看器 | 专用查看器之外的格式 | 广谱预览：Office、压缩包、邮件、绘图、CAD、3D、GIS、设计资产等 | 以兜底层级声明处理能力；专用查看器优先 |

- 一个内容类别只由一个专用查看器承担；查看器之间不互相调用，不直接 `import` 彼此实现（[插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §8）。
- 查看器家族的应用形态与 UI 边界以本文件为准；具体功能列表由各应用仓库文档补充，但不得与本文件及机制权威文档冲突。

### 1.3 总则

1. **只读消费**：查看器不解析 `.card` / `.box`、不拼接渲染帧、不写文档、不直接访问文件系统或系统 API；系统能力一律经 `window.chips` / `ctx.bridge`（[架构原则](../00-愿景与原则/01-架构原则.md) §2、R2、R17）。
2. **单一共享层**：组件、Hooks 与 Design Tokens 只从 `@chips/ui` 导入；颜色、间距、字号、圆角、阴影一律取主题 token；文案简体中文直写（[React 组件开发规范](../02-开发规范/03-React组件开发规范.md) §11；[ADR-008](../01-架构设计/ADR/ADR-008-React加fork-antd前端技术栈.md)）。
3. **意图进、结果出**：打开、导出、分享等动作一律表达为平台能力调用或资源打开意图，由平台路由与判定（[能力契约规范](../05-接口与契约/04-能力契约规范.md)、[资源打开与默认处理器契约](../05-接口与契约/14-资源打开与默认处理器契约.md)）。
4. **状态分离**：查看位置等高频状态留在内存；跨会话的查看状态落插件私有数据目录；用户偏好走插件自身配置命名空间；高频进度不得经 `config:set` 往返（[配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §9.4；[权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §4.4）。
5. **降级可见**：任何失败都必须有简体中文、可诊断、可操作的界面表现，禁止静默空白与原始堆栈外泄（[渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §11；[故障排查手册](../06-开发与运维/04-故障排查手册.md)）。
