# 拖动与拖放交互规范

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片生态拖动与拖放交互的权威规范：拖放载荷数据模型与 MIME 映射、来源与落点矩阵、外部文件拖入工作区建卡（批量与冲突命名）、嵌套与优先级、插入指示与合法落点、触屏/滚轮/键盘等价、无障碍要求，以及与编辑链路节点交互协议的衔接；不定义插件接口签名、文档读写语义、工作区目录规则与能力契约本身。

## 二、拖放载荷数据模型

### 2.1 内部载荷

```typescript
/** 载荷版本：实现必须拒绝未知版本，不做兼容降级（ADR-010）。 */
type DragPayloadVersion = 1;

type DragOrigin = 'workspace' | 'card' | 'box' | 'library' | 'external';

interface ChipsDragPayload {
  payloadVersion: DragPayloadVersion;
  origin: DragOrigin;               // 一次拖动只有一个来源类别
  items: ChipsDragItem[];           // 单项拖动为长度 1 的数组；批量与多选复用同一结构
}
```

规则：

1. `payloadVersion` 不认识时整个载荷无效：显示简体中文提示"拖放数据版本不受支持"，不产生任何操作。
2. `items` 为空或全部项非法时载荷无效；部分项非法时只处理合法项，并按 §3.5 提示被忽略项数量。
3. 载荷必须可结构化克隆：不含函数、类实例、`Symbol`、循环引用（与 `DocumentView` 同规则）。
4. 载荷是交互期数据：不得持久化、不得写入日志正文、不得跨会话保存。

### 2.2 载荷项类型

```typescript
type ChipsDragItem =
  | CardDragItem
  | BoxDragItem
  | FileDragItem
  | TextDragItem
  | UrlDragItem
  | NodeSelectionDragItem
  | EntrySelectionDragItem
  | TemplateDragItem;

/** 卡片文档：.card 归档态文件或目录态包根。 */
interface CardDragItem {
  kind: 'card';
  source: string;                   // 受管引用（资源协议规范）
  title: string;                    // 仅用于拖动预览；落点决策不得依赖
}

/** 箱子文档：.box 单文件。 */
interface BoxDragItem {
  kind: 'box';
  source: string;
  title: string;
}

/** 普通文件：工作区用户文件或外部文件（已由平台归一为受管引用）。 */
interface FileDragItem {
  kind: 'file';
  source: string;
  name: string;                     // 原文件名（含扩展名），用于建卡匹配与展示
}

/** 纯文本：编辑器选中的文本或用户拖入的文本。 */
interface TextDragItem {
  kind: 'text';
  text: string;
}

/** URL：http(s) / webdav 引用（R13 引用集合成员）。 */
interface UrlDragItem {
  kind: 'url';
  url: string;
}

/** 一个卡片内的节点选择；多选为同一项内的多个 nodeIds。 */
interface NodeSelectionDragItem {
  kind: 'nodes';
  documentId: string;               // = card_id，跨会话稳定
  nodeIds: string[];                // 按 structure 声明顺序；不得乱序或去重后重排
}

/** 一个箱子内的条目选择；多选为同一项内的多个 entryIds。 */
interface EntrySelectionDragItem {
  kind: 'entries';
  documentId: string;               // = box_id
  entryIds: string[];               // 按 entries 数组顺序
}

/** 卡箱库的类型模板；显示名由插件注册表提供，不来自载荷。 */
interface TemplateDragItem {
  kind: 'template';
  role: 'basecard' | 'boxlayout';
  typeId: string;                   // cardType / layoutType 标识
}
```

规则：

1. **受管引用唯一**：`card` / `box` / `file` 的 `source` 必须是受管引用；工作区相对路径、裸绝对路径、`file://` 原始路径不得进入载荷（[资源协议规范](../05-接口与契约/06-资源协议规范.md) §2.2、R13）。
2. **多选同构**：工作区多选产生多个 `items` 项；卡片内节点多选产生一个 `nodes` 项携带多个 `nodeIds`；两种多选都复用同一载荷结构，不引入第二套批量字段。
3. **顺序即语义**：`items` 的顺序是落点按序处理的顺序；`nodes` / `entries` 的 ID 顺序是结构声明顺序，重排结果必须保持组内相对顺序（[编辑引擎设计](../01-架构设计/01-子系统设计/12-编辑引擎设计.md) §5.3）。
4. **展示信息最小化**：`title` / `name` 只服务拖动预览；落点判定只使用 `kind`、`source`、`documentId`、`role`、`typeId`。展示名优先从插件注册表与文档会话派生（防伪造）。
5. **URL 合法性**：`url` 项只接受 `http(s)://` 与 `webdav://`；其余字符串按 `text` 项处理（[资源协议规范](../05-接口与契约/06-资源协议规范.md) §2.2）。
6. **插件私有内容不进平台载荷**：节点内容、插件配置等插件私有数据不得塞入平台载荷项；需要私有拖放语义的插件使用 §2.3 的私有 MIME。
7. **类型注册校验**：`template.typeId` 必须是插件注册表中已登记且已启用的类型；未登记类型无效并按 §3.5 提示"类型不可用"。

### 2.3 MIME 映射与跨边界表示

| 媒体类型 | 数据 | 允许边界 |
|---|---|---|
| `application/x-chips-drag-data` | `ChipsDragPayload` 的 UTF-8 JSON | 平台内部：应用窗口之间、面板与画布之间；禁止跨应用传播；禁止写入剪贴板 |
| `application/x-chips-plugin-<pluginId>` | 插件私有 JSON（schema 由插件自管） | 插件编辑器容器内部；平台外壳不解释；禁止跨应用 |
| `text/uri-list` | RFC 2483，每行一个 URL | 跨应用拖出与外部拖入的 URL 表示 |
| `text/plain` | 纯文本 | 跨应用兜底与文本项载体 |
| 原生 `Files` | 操作系统文件列表 | 外部拖入的唯一入口；由壳/平台归一转受管引用后交给应用 |

规则：

1. **读取优先级**：`application/x-chips-drag-data` → 插件私有 MIME → `text/uri-list` → `text/plain` → 原生 `Files`；命中更高优先级后不再向下降级解释。
2. **写入边界**：内部拖动只写 `application/x-chips-drag-data`；拖出到外部只写 `text/uri-list` / `text/plain` / 原生文件表示。任何内部载荷都不得以 `text/plain` 形式对外暴露（旧实现把文档路径写入 `text/plain` 的做法作废）。
3. **外部入口归一**：原生 `Files` 与 `text/uri-list` 由壳/平台在进入应用前归一为受管引用；应用与插件不得直接读取 DataTransfer 中的真实路径或字节（R17）。
4. **剪贴板分离**：拖放载荷不落剪贴板；文本与 URL 的复制粘贴走 `clipboard:*` 能力（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §7.6），不属本规范。
5. **插件私有载荷命名空间**：`<pluginId>` 为插件清单 ID 的正向书写（如 `application/x-chips-plugin-chips.basecard.richtext`）；插件不得占用 `application/x-chips*` 下的其他命名。

### 2.4 载荷生命周期与校验

```
pointerdown（拖动句柄 / 长按）
  → 构建 ChipsDragPayload（受管引用、类型注册校验）
  → 写入 DataTransfer（内部 MIME + 按需外部表示）
  → 拖动中：只更新交互内存（悬停落点、插入索引、预览位置）
  → 释放：解析载荷 → 命中落点 → 按 §3 执行一次或多次独立结果
  → 清理：移除预览、指示与监听；不残留任何持久状态
```

校验顺序固定：`payloadVersion` → `items` 结构 → 类型注册 → 落点接受性。任一步失败都不产生操作；校验失败原因不展示堆栈、不展示路径与字节。
