# ADR-005: 插件不分类只分角色

## 现状注记

> 本节记录本 ADR 之后由正式文档落实或修订的口径，不修改上文原文。

1. 四种角色的方法面以四份角色接口文档为准：[07-应用插件接口](../../05-接口与契约/07-应用插件接口.md)、[08-基础卡片插件接口](../../05-接口与契约/08-基础卡片插件接口.md)、[09-箱子布局插件接口](../../05-接口与契约/09-箱子布局插件接口.md)、[10-服务插件接口](../../05-接口与契约/10-服务插件接口.md)。
2. 类型更名：`ICard` → `BaseCardView`（节点视图，含 `card: BaseCardContext`）、布局视图为 `BoxRenderView`；`IEditor` 拆分为 `IBaseCardEditor`（08）与 `ILayoutEditor`（09），SDK 不导出笼统 `IEditor`。
3. 基础卡片角色接口新增 `createInitialContent()` 与 `collectResourcePaths(basecard)`；manifest `capabilities.cardTypes[].aliases` 提供别名读取归一。
4. 双入口职责：`dist/index.js` 承载主进程纯函数（`validateConfig` 等），`render.js` 承载渲染方法；编辑链路与应用插件不得 import 插件代码，必须经平台插件门面 `IManagedPluginRuntime` 装载。
5. `healthCheck` 单位统一为字符串（`30s` / `5s`）；`runtime.background` 为可选字段、仅 `service` 可为 `true`。
6. 安装只登记权限申请，首次启用逐项授权，拒绝不阻断启用（该权限保持未授权），见[08-权限系统设计](../01-子系统设计/08-权限系统设计.md)。
7. 服务插件执行载体：受管模块加载器 + 工具进程（[03-插件架构设计](../01-子系统设计/03-插件架构设计.md) §5、[10-服务插件接口](../../05-接口与契约/10-服务插件接口.md) §2.5）。
