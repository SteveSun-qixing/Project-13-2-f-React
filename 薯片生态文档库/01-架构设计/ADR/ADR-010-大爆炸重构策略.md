# ADR-010: 大爆炸重构策略

## 元数据

- **状态**: 已接受
- **日期**: 2026-09-19
- **影响范围**: 整个薯片生态重构

---

## 决策

采用大爆炸重构策略，完全推倒重来，不做兼容。

---

## 实施方式

### 新旧代码完全独立

```
旧版薯片生态
├── 旧版-生态设计原稿/
├── 旧版-生态共用技术文档/
└── 旧版-项目日志与笔记/
    
    ↓ 完全独立

新版薯片生态
├── 薯片生态文档库/
├── packages/
│   ├── core-rust/
│   ├── host-electron/
│   ├── bridge/
│   ├── antd-fork/
│   └── ui/
└── plugins/
```

### 核心原则

1. 新系统完全独立开发
2. 不考虑旧系统兼容性
3. 不做渐进式迁移
4. 旧系统保留但冻结

---

## 实施阶段

### Phase 0：文档与预研

交付物：
- 所有 ADR 文档
- 所有子系统设计文档
- 所有开发规范
- Monorepo 骨架
- 技术预研 POC

原则：
- 文档事无巨细
- 所有接口、链路、契约规定好
- 可直接用于开发

### Phase 1：核心平台

交付物：
- Rust Cordis 运行时
- Bridge 能力系统
- Electron 壳
- 基础测试框架

原则：
- 完全新代码
- 不看旧代码
- 严格按新架构开发

### Phase 2：子系统

交付物：
- 插件系统
- 渲染引擎
- 资源管理
- 文档解析

### Phase 3：官方插件与生态

交付物：
- 应用插件重写（编辑引擎、查看器、资源管理器等）
- CLI 与示例插件
- 开发者文档

注意：
- 不是"迁移"旧插件
- 而是"重写"
- 可参考旧插件业务逻辑

### Phase 4：迁移与发布

交付物：
- 旧版 .card → 新版 .card 工具
- 旧版 .box → 新版 .box 工具
- 数据完整性验证
- 性能与安全加固、桌面三端验证
- v1.0 发布

注意：
- 不是"兼容"旧版本
- 而是提供"迁移工具"

### Phase 5：移动端（架构预留）

交付物：
- Android / iOS 实现与验证

注意：
- 架构预留，暂不排期；启动需所有者决策（见[开发流程与阶段计划](../../07-工程管理/02-开发流程与阶段计划.md) 第八章）
- 平台优先级：macOS / Windows → Linux → Android → iOS

---

## 旧代码处理

### 冻结旧代码

```
操作：
- 重命名为"旧版-"
- 不再修改
- 不再更新文档
- 只做参考

允许：
- 查看旧代码业务逻辑
- 复用业务算法
- 参考 UI 设计

禁止：
- 复制粘贴旧代码
- 保留旧架构设计
- 为兼容旧代码妥协
```

---

## 无兼容性设计

### 第一版发布前

- 不考虑兼容性重构
- 不留回退机制
- 不保留过时口径
- 不保留兼容写法

### 架构优先

- 追求最佳架构设计
- 追求最佳软件工程
- 追求最干净代码
- 10 年演进空间
