# ADR-009: 文件格式设计原则

## 元数据

- **状态**: 已接受
- **日期**: 2026-09-19
- **影响范围**: `.card` 和 `.box` 文件格式

---

## 决策

`.card` 与 `.box` 统一采用 **YAML + 目录结构 + ZIP Store（零压缩归档）**：YAML 承载全部配置，资源以引用方式组织，发布态为单文件 ZIP 归档，开发态为内容同构的目录。

格式的目录结构、字段模型、引用形式、打包与校验规则不在本 ADR 展开，以以下文档为唯一权威：

- [01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md)
- [02-箱子文件格式](../../04-文件格式规范/02-箱子文件格式.md)

---

## 关键设计原则

### 1. YAML 作为配置主格式

元数据、结构、内容与布局配置全部使用 YAML：人类可读、可增删注释、可被任意标准 YAML 解析器解析。

### 2. ZIP Store 归档

- 发布态为单文件 ZIP 归档，所有条目使用 Store 模式（零压缩）：无需解压运算，可随机访问，可直接内存映射读取资源。
- 归档根即包根，不得出现顶层包裹目录。

```bash
# 在包目录内打包；-0 为 Store 模式
(cd my-card && zip -r -0 -X ../my-card.card .)
```

- 开发态目录与归档内容同构，打包与解包不改变内容。

### 3. 资源引用而非内嵌

- 资源以引用形式组织：包内相对路径，或规范允许的 URI。
- 禁止把资源字节以 Base64 等内联形式写入 YAML 或 HTML。
- 禁止把运行时地址（`blob:`、`data:`）与系统绝对路径写回正式文件。

### 4. 版本与迁移

- 卡片与箱子的格式版本字段为 `chip_standards_version`，遵循语义化版本：主版本变更不兼容，次版本为向后兼容新增，修订号为向后兼容修正。
- 平台不提供隐式降级与运行时兼容层；旧版本文件必须经迁移工具升级后使用；不追求大版本向后兼容。
- 版本字段与迁移流程以[04-版本与迁移规范](../../04-文件格式规范/04-版本与迁移规范.md)为准。

### 5. 第三方可读写

- 格式只依赖公开标准（ZIP、YAML、UTF-8），不设自定义头部、自定义校验块、加密与专有二进制索引区。
- 第三方可用标准 ZIP 库与 YAML 解析器直接读取和写入全部正式字段。

### 6. 性能验收

- 解析 10MB `.card` < 100ms
- 加载 metadata < 10ms
- 资源懒加载，解析阶段不读取资源字节
- 解析内存占用 < 文件大小 2 倍

---

## 约束

- 目录、字段、打包命令与示例一律以[01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md)与[02-箱子文件格式](../../04-文件格式规范/02-箱子文件格式.md)为准；本 ADR 不重复定义、不自行扩展。
- 全部写入实现（编辑器、导出、迁移工具、第三方工具）与全部读取实现都必须遵守上述两份规范。
- 文件内不得出现运行时 URL 与系统绝对路径；引用形式必须落在规范允许的集合内。

---

## 后果

- 格式开放、可被第三方工具直接读写，不锁定实现与工具链。
- 解析无需解压，满足性能验收；资源懒加载使大文件不阻塞打开。
- 不设运行时兼容层，旧格式文件必须经迁移工具升级，迁移工具成为版本演进的必备交付物。
