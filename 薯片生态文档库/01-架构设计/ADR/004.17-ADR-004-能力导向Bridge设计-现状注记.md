# ADR-004: 能力导向 Bridge 设计

## 现状注记

> 本节记录本 ADR 之后由正式文档落实或修订的口径，不修改上文原文。

1. 能力模型的权威定义与全表以[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md)为准：schema 方言统一 JSON Schema 2020-12；`execute(input, ctx)` 携带 `ctx.signal` / `ctx.deadline`，二进制经 `x-chips-binary` 与 `bin` 表承载。
2. 内置能力总表在该轮为 47 项（[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md) §6.2，当前计数与完整登记以该节为准）；该轮新增 `window:list` / `window:resize` / `window:move` / `window:setTitle`、`menu:set`、`tray:set`、`shortcut:register` / `shortcut:unregister`、`system:info`、`power:query` / `power:prevent-sleep`、`transfer:download` / `transfer:cancel`、`document:export`、`config:snapshot` / `config:reset`、`file:move` / `file:copy` / `file:mkdir`；后续登记 `command:*`、`cli:task-*`、`resource:open` / `resource:list-handlers`、`document:create`；`image:*` 不登记为平台能力（内容处理由服务插件以 Cordis 服务提供）。
3. 资源句柄不再提供 `toURL()`：URL 形态由 `resourceBase` 与 `chips-resource://` 规范 URI 提供（[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md)）；`resource()` 接受裸 `http(s)://` 并按 §2.6 归一。
4. 事件不再有 `bridge.publish`：发布经 `event:publish` 能力或 `ctx.emit`，订阅经 `window.chips.subscribe` / `ctx.on`（[05-事件契约规范](../../05-接口与契约/05-事件契约规范.md)）。
5. 原文中的规划示例 ID（`websocket:connect`、`db:*`、`cards:export:pdf` 等）不属于登记能力，正式插件不得声明；未登记 ID 一律不得调用。
6. 权限判定、错误归一、超时/取消与并发策略以[02-Bridge三层设计](../01-子系统设计/02-Bridge三层设计.md)与[01-Bridge-API规范](../../05-接口与契约/01-Bridge-API规范.md)为准。
