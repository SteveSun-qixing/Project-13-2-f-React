# ADR-002: Electron 作为桌面端壳

## 现状注记

> 本节记录本 ADR 之后由正式文档落实或修订的口径，不修改上文原文。

1. 资源协议注册以 Electron 现行 `protocol.handle` 为准（原文的 `protocol.registerFileProtocol` 已废弃），实现契约见[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md) §5.3 与[04-资源管理设计](../01-子系统设计/04-资源管理设计.md) §7.4。
2. 构建与打包命令统一使用 pnpm（唯一包管理器），`npm run ...` 形式不再适用，以[02-构建与打包](../../06-开发与运维/02-构建与打包.md)与[01-代码组织规范](../../02-开发规范/01-代码组织规范.md)为准。
3. 平台优先级统一为 macOS / Windows → Linux（桌面三端完成）→ Android → iOS（R6、[ADR-007](ADR-007-桌面端与移动端分离策略.md)、[开发流程与阶段计划](../../07-工程管理/02-开发流程与阶段计划.md)）。
4. 安全基线（`nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`、CSP 与自定义协议）保持有效；细节以[01-Bridge-API规范](../../05-接口与契约/01-Bridge-API规范.md)、[05-渲染引擎设计](../01-子系统设计/05-渲染引擎设计.md)、[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md)为准。
5. 平台自动更新属平台自身机制，不提供插件接口；更新源、签名链与回滚见[更新与分发规范](../../06-开发与运维/06-更新与分发规范.md)。
6. 主进程插件的加载形态为受管模块加载器（ModuleLoader）；需要进程级隔离的服务由工具进程承担（[03-插件架构设计](../01-子系统设计/03-插件架构设计.md) §5）。
