## 四、Fork 与可逆副作用

### 4.1 数据结构

Fork 是副作用追踪与撤销的单元；每个 Context 持有一个作用域 Fork，每次插件加载创建一个插件 Fork，每次注入创建一个注入 Fork。

```rust
/// Fork 的唯一标识。
pub type ForkId = u64;

/// Fork 状态。
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ForkState {
    /// 可登记副作用。
    Active,
    /// 正在撤销，拒绝新登记。
    Disposing,
    /// 已撤销。
    Disposed,
}

/// 可撤销副作用的通用载体。
pub enum Effect {
    /// 自定义清理闭包。
    Custom(Box<dyn FnOnce() + Send + Sync>),
    /// 服务注册；撤销时按代际匹配。
    Service {
        name: ServiceName,
        generation: u64,
    },
    /// 事件监听器。
    Listener {
        name: EventName,
        token: ListenerToken,
    },
    /// 后台任务；由 `ctx.task` 登记，撤销时触发取消并等待退出（超时策略见 6.7）。
    Task {
        abort: TaskAbortHandle,
    },
}

/// Fork 节点；以 ID 挂载在 ForkRegistry 中。
pub struct Fork {
    /// Fork ID。
    pub id: ForkId,
    /// 所属 Context。
    pub context: ContextId,
    /// 父 Fork；根 Fork 为 `None`。
    pub parent: Option<ForkId>,
    /// 子 Fork，按创建顺序排列。
    pub children: Vec<ForkId>,
    /// 登记的副作用，按登记顺序排列。
    effects: Vec<Effect>,
    /// 状态。
    state: ForkState,
}
```

### 4.2 副作用追踪

`ctx.effect` 用于登记任意自定义清理逻辑；内核内建能力（服务、监听器、任务）必须走各自登记入口，不允许绕过追踪。

| 副作用 | 登记入口 | 撤销动作 |
|---|---|---|
| 服务注册 | `ctx.provide` | 当代际匹配时摘除服务表条目，并触发依赖方级联重建 |
| 事件监听 | 内核事件总线登记 | 标记监听器失效并从监听表移除 |
| 子 Fork | 内核创建子 Context / 注入 Fork | 递归销毁 |
| 后台任务 | `ctx.task`（登记一条 `Effect::Task`） | 触发取消信号，等待退出；超过强撤上限（6.7）强制中止 |
| 定时器 | `ctx.effect` 包装 | 调用清理闭包 |
| 自定义资源 | `ctx.effect` | 调用清理闭包 |

`ctx.task(work, { name?, signal? })` 是与 `Effect::Task` 一一对应的正式任务 API：任务登记到当前 Fork，随 Fork 撤销而取消；任务句柄可等待（`join()`）与取消（`cancel()`）；活跃任务数计入插件软配额（6.9）。

### 4.3 dispose 顺序

`dispose` 顺序固定为"子 Fork 后序 + 自身副作用 LIFO"：

```
dispose(fork)
  1. 状态置 Disposing，拒绝新副作用登记
  2. 按创建逆序逐个销毁子 Fork（每个子 Fork 递归执行本流程，后序）
  3. 按登记逆序（LIFO）撤销自身副作用
  4. 状态置 Disposed
```

LIFO 保证撤销顺序与资源依赖方向相反：后登记的资源可能依赖先登记的资源，必须先撤销。

```rust
impl Fork {
    /// 撤销本 Fork 的全部副作用。
    ///
    /// 顺序：先递归销毁子 Fork（后序），再按登记逆序（LIFO）撤销自身副作用。
    /// 单个副作用撤销失败不中断流程，返回首个错误。
    pub fn dispose(&mut self, kernel: &Kernel) -> Result<(), KernelError> {
        if self.state == ForkState::Disposed {
            return Ok(());
        }
        self.state = ForkState::Disposing;

        let mut first_error: Option<KernelError> = None;
        while let Some(child) = self.children.pop() {
            if let Err(error) = kernel.forks().dispose(child) {
                first_error.get_or_insert(error);
            }
        }
        while let Some(effect) = self.effects.pop() {
            if let Err(error) = kernel.revert(effect) {
                first_error.get_or_insert(error);
            }
        }

        self.state = ForkState::Disposed;
        first_error.map_or(Ok(()), Err)
    }
}
```

### 4.4 dispose 语义

- 幂等：对已 `Disposed` 的 Fork 重复调用直接返回成功。
- 容错：单个副作用撤销失败不中断其余撤销；返回首个错误，全部失败信息记入审计。
- 不重入：`Disposing` 状态下拒绝登记新副作用。
- 代际安全：被替换服务的旧代际撤销是空操作，绝不误删新代际条目。
- 可观测：撤销失败以 `KERNEL_DISPOSE_FAILED` 上报，日志与审计要求见 [04-故障排查手册.md](../../06-开发与运维/04-故障排查手册.md)。
