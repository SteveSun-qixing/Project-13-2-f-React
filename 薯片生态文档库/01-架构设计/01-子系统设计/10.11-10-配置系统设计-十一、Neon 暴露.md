## 十一、Neon 暴露

### 11.1 原生接口

核心经 Neon 暴露给宿主层的配置接口：

```typescript
type ConfigLayer = 'platform' | 'user' | 'workspace' | 'plugin';

interface NativeConfigCaller {
  caller: string;               // 调用方标识：插件 ID 或 'platform'，由宿主层从 Bridge 上下文注入
}

interface NativeConfigGetInput extends NativeConfigCaller {
  namespace: string;            // 'platform' 或 'plugins.<pluginId>'
  key: string;
}

interface NativeConfigSetInput extends NativeConfigCaller {
  namespace: string;
  key: string;
  value: unknown;
  scope: 'user' | 'workspace';
}

interface NativeConfigResetInput extends NativeConfigCaller {
  namespace: string;
  keys: string[];
  scope: 'user' | 'workspace';
}

interface NativeConfigSnapshotInput extends NativeConfigCaller {
  namespace: string;
  prefix: string;
}

interface NativeConfigChange {
  key: string;
  layer: ConfigLayer;
  value: unknown;
  effectiveValue: unknown;
  isDefault: boolean;
  origin: string;
}

interface NativeConfigView {
  key: string;
  value: unknown;
  layer: ConfigLayer;
  isDefault: boolean;
}

interface NativeSubscription {
  dispose(): void;
}

interface INativeConfig {
  get(input: NativeConfigGetInput): Promise<NativeConfigView>;
  set(input: NativeConfigSetInput): Promise<void>;
  reset(input: NativeConfigResetInput): Promise<void>;
  snapshot(input: NativeConfigSnapshotInput): Promise<Record<string, unknown>>;
  watch(prefix: string, handler: (change: NativeConfigChange) => void): NativeSubscription;
}
```

### 11.2 绑定实现

- 异步函数使用 `cx.promise()` 与 `cx.channel()`：在共享 Tokio 运行时中执行，完成后 `settle_with` 回 JS 线程；线程模型见 [ADR-003](../ADR/ADR-003-Rust核心加Node-Native-Module架构.md)。
- 订阅接口把 JS 处理函数包装为 `ChangeHandler`，经 `neon::event::Channel` 回到 JS 线程执行；`watch` 返回的对象持有 Rust 订阅句柄，`dispose()` 时释放。
- 错误统一转换为 JS Error；示例中以错误码字符串抛出，宿主层据此映射为统一错误结构的 `code`，并附简体中文 `message`。

宿主层初始化原生模块时创建一个 `ConfigSystem` 绑定对象（内部持有核心的 `ConfigStore`），所有导出函数共用该实例：

```rust
use neon::prelude::*;
use std::sync::Arc;

fn config_set(mut cx: FunctionContext) -> JsResult<JsPromise> {
    let system = cx.argument::<JsBox<ConfigSystem>>(0)?;
    let input = cx.argument::<JsObject>(1)?;

    let namespace_handle: Handle<JsString> = input.get(&mut cx, "namespace")?;
    let key_handle: Handle<JsString> = input.get(&mut cx, "key")?;
    let scope_handle: Handle<JsString> = input.get(&mut cx, "scope")?;
    let caller_handle: Handle<JsString> = input.get(&mut cx, "caller")?;
    let value_handle: Handle<JsValue> = input.get(&mut cx, "value")?;

    let namespace = namespace_handle.value(&mut cx);
    let key = format!("{}.{}", namespace, key_handle.value(&mut cx));
    let caller = caller_handle.value(&mut cx);
    let value = js_to_json(&mut cx, value_handle)?;

    let scope = match scope_handle.value(&mut cx).as_str() {
        "user" => WritableScope::User,
        "workspace" => WritableScope::Workspace,
        _ => return cx.throw_error("CONFIG_SCOPE_INVALID"),
    };

    let channel = cx.channel();
    let (deferred, promise) = cx.promise();
    let store = Arc::clone(&system.store);
    let runtime = system.runtime.clone();

    runtime.spawn(async move {
        let result = store
            .set(&key, value, scope, ChangeOrigin::Plugin(caller))
            .await;
        deferred.settle_with(&channel, move |mut cx| match result {
            Ok(change) => config_change_to_js(&mut cx, change),
            Err(error) => cx.throw_error(error.code()),
        });
    });

    Ok(promise)
}

// js_to_json / config_change_to_js：绑定层的值转换助手，基于 neon-serde 实现（见 11.1 类型）。
// ConfigSystem 的构造与其余导出函数（get/reset/snapshot/watch）遵循同一异步模式。

#[neon::main]
fn main(mut cx: ModuleContext) -> NeonResult<()> {
    cx.export_function("ConfigSystem", ConfigSystem::js_new)?;
    cx.export_function("configSystemGet", ConfigSystem::js_get)?;
    cx.export_function("configSystemSet", config_set)?;
    cx.export_function("configSystemReset", ConfigSystem::js_reset)?;
    cx.export_function("configSystemSnapshot", ConfigSystem::js_snapshot)?;
    cx.export_function("configSystemWatch", ConfigSystem::js_watch)?;
    Ok(())
}
```

### 11.3 Bridge 能力

宿主层把原生接口封装为配置能力；插件只能经 Bridge 调用：

| 能力 ID | 权限 | 说明 |
|---|---|---|
| `config:get` | `config:read:<namespace>`；自身命名空间免权限 | 读取单条生效值 |
| `config:snapshot` | `config:read:<namespace>`；自身命名空间免权限 | 读取命名空间下完整生效视图 |
| `config:set` | `config:write:<namespace>`；自身命名空间免权限 | 在用户层或工作区层写入 |
| `config:reset` | `config:write:<namespace>`；自身命名空间免权限 | 移除用户层或工作区层覆盖 |

四项能力均已在 [04-能力契约规范](../../05-接口与契约/04-能力契约规范.md) 登记；`config:snapshot` 与 `config:reset` 为配置系统正式能力，完整输入/输出契约以该规范为准。

能力契约类型：

```typescript
type ConfigLayer = 'platform' | 'user' | 'workspace' | 'plugin';

interface ConfigGetInput {
  namespace: string;              // 'platform' 或 'plugins.<pluginId>'
  key: string;
}

interface ConfigGetResult {
  key: string;                    // 完整配置键
  value: unknown;
  layer: ConfigLayer;
  isDefault: boolean;
}

interface ConfigSetInput {
  namespace: string;
  key: string;
  value: unknown;
  scope: 'user' | 'workspace';
}

interface ConfigResetInput {
  namespace: string;
  keys: string[];
  scope: 'user' | 'workspace';
}

interface ConfigSnapshotInput {
  namespace: string;
  prefix: string;
}
```

调用规则：

- `namespace` 只允许 `platform` 或 `plugins.<自身ID>`；其他值返回 `CONFIG_NAMESPACE_DENIED`。
- 自身命名空间读写免权限；访问 `platform` 命名空间必须持带命名空间限定值的 `config:read` / `config:write`。
- 插件写入 `platform` 命名空间受策略键与 `x-chips-writable` 约束；插件层与平台层默认值不可经能力写入；`scope` 只接受 `user` 与 `workspace`。

### 11.4 插件使用示例

```typescript
import { chips, type ISubscription } from '@chips/sdk';

type ConfigLayer = 'platform' | 'user' | 'workspace' | 'plugin';

const EDITOR_NAMESPACE = 'plugins.chips.official.editor';
const FONT_SIZE_KEY = `${EDITOR_NAMESPACE}.fontSize`;

interface ConfigGetResult {
  key: string;
  value: unknown;
  layer: ConfigLayer;
  isDefault: boolean;
}

interface ConfigChangedPayload {
  key: string;
  layer: ConfigLayer;
  value: unknown;
  effectiveValue: unknown;
  isDefault: boolean;
  origin: string;
}

const isConfigChangedPayload = (payload: unknown): payload is ConfigChangedPayload => {
  if (typeof payload !== 'object' || payload === null) {
    return false;
  }
  const candidate = payload as { key?: unknown; effectiveValue?: unknown };
  return typeof candidate.key === 'string' && 'effectiveValue' in candidate;
};

const readFontSize = async (): Promise<number | null> => {
  const result = await chips.request<ConfigGetResult>('config:get', {
    namespace: EDITOR_NAMESPACE,
    key: 'fontSize',
  });
  return typeof result.value === 'number' ? result.value : null;
};

const writeFontSize = async (fontSize: number): Promise<void> => {
  await chips.request('config:set', {
    namespace: EDITOR_NAMESPACE,
    key: 'fontSize',
    value: fontSize,
    scope: 'user',
  });
};

interface EditorPreferences {
  fontSize: number;
}

const editorPreferences: EditorPreferences = { fontSize: 14 };

const applyFontSize = (fontSize: number): void => {
  editorPreferences.fontSize = fontSize;
  // 插件界面在渲染时读取 editorPreferences.fontSize。
};

const startConfigSync = (): ISubscription => {
  const subscription = chips.subscribe('config:changed', (payload) => {
    if (!isConfigChangedPayload(payload)) {
      return;
    }
    if (payload.key !== FONT_SIZE_KEY) {
      return;
    }
    if (typeof payload.effectiveValue === 'number') {
      applyFontSize(payload.effectiveValue);
    }
  });
  return subscription;
};

// 插件持有 subscription；插件卸载时由 Bridge 统一撤销，也可显式 subscription.dispose()。
```
