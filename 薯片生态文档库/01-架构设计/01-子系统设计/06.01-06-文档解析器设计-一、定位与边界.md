> 版本：v1.0.0
> 日期：2026-09-19

> 适用范围：`.card` 与 `.box` 的解析、校验、诊断、惰性加载与增量重解析的实现设计

## 一、定位与边界

### 1.1 定位

文档解析器是薯片平台读取 `.card` / `.box` 的唯一入口，负责把两种文件格式转换为内存模型和结构化诊断，供渲染、资源访问、编辑、导出、同步与校验复用。格式字段的规范定义见[《卡片文件格式》](../../04-文件格式规范/01-卡片文件格式.md)与[《箱子文件格式》](../../04-文件格式规范/02-箱子文件格式.md)；本文只描述解析器实现设计。

卡片与箱子共用同一条解析流水线：读取、索引、YAML 解析、schema 校验、模型构建全部复用，仅在格式适配层（schema 集与模型类型）分支，禁止为两者各写一套并行管线。

### 1.2 边界

| 事项 | 归属 |
|---|---|
| 格式字段定义、目录结构、版本字段（`chip_standards_version`）语义 | 04-文件格式规范/01、02、04 |
| 解析、校验、诊断、惰性加载、增量重解析 | 本文 |
| 资源字节读取、缓存、权限、`chips-resource://` | [《资源管理设计》](04-资源管理设计.md)、[《资源协议规范》](../../05-接口与契约/06-资源协议规范.md) |
| 卡片/箱子渲染、插件装载、沙箱 | [《渲染引擎设计》](05-渲染引擎设计.md) |
| Rust 公开接口的正式参考与 Neon 绑定约定 | [《核心接口规范》](../../05-接口与契约/03-核心接口规范.md) |
| `.cpk` 插件包与 manifest | [《插件架构设计》](03-插件架构设计.md)、04-文件格式规范/03-插件包格式 |

解析器是只读子系统：不写入文档、不执行文档内容、不迁移旧 schema。所有写回（含资源导入、清单重算与归档重建）统一由[《文档服务设计》](11-文档服务设计.md)按格式规范执行；迁移由独立迁移工具执行（[《版本与迁移规范》](../../04-文件格式规范/04-版本与迁移规范.md) §6）。

### 1.3 核心术语

| 术语 | 定义 |
|---|---|
| 包（package） | 一个 `.card` 或 `.box` 的完整内容，目录态与压缩态同构 |
| 包根（package root） | 目录态为指定目录；压缩态为 ZIP 归档根 |
| 包内路径（`PackagePath`） | 相对包根的规范化路径，`/` 分隔，UTF-8 + NFC，禁 `..`、绝对路径、反斜杠与控制字符 |
| 数据源（source） | 包字节的提供者，实现 `DocumentSource`，分目录态与压缩态两种 |
| 解析单元（unit） | 可独立解析与缓存的最小成员：一个 YAML 文件或一段索引 |
| 层级（level） | 惰性加载的粒度：L0 metadata、L1 structure、L2 内容单元（卡片 `content/*.yaml`；箱子 `structure.yaml` 条目与 `content.yaml` 布局配置）、L3 resources |
| 诊断（diagnostic） | 非致命问题记录，含严重级、码、位置（文件、字段指针、行列）、提示 |
| 修订（revision） | 数据源指纹与索引摘要的组合，用于缓存失效与增量重解析 |
