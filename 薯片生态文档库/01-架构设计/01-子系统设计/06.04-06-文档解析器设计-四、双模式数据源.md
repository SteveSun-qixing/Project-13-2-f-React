## 四、双模式数据源

### 4.1 统一抽象

```rust
pub trait DocumentSource: Send + Sync {
    fn kind(&self) -> SourceKind;
    fn fingerprint(&self) -> SourceFingerprint;
    fn member(&self, path: &PackagePath) -> Option<MemberMeta>;
    fn list(&self, prefix: &PackagePath) -> Result<Vec<PackagePath>>;
    fn read(&self, path: &PackagePath) -> Result<Vec<u8>>;
    fn open_stream(&self, path: &PackagePath) -> Result<ByteStream>;
}

pub enum ByteStream {
    Mapped { source: Arc<Mapping>, offset: u64, length: u64 },
    Decoded(Box<dyn std::io::Read + Send>),
}
```

- `read` 用于 YAML 等小文本成员，返回 `Vec<u8>`。
- `open_stream` 用于资源成员：Store 成员返回映射切片（零拷贝），Deflate 成员返回解码流。
- `member` 与 `list` 基于阶段 2 的索引，O(log n) 查找。
- 两种实现必须产生相同的索引内容与相同的读取结果；模式差异只体现在 `ByteStream` 变体。

### 4.2 目录态（`DirectorySource`）

- 面向开发态与编辑态：成员即文件系统文件。
- 路径安全：所有访问以 `PackagePath` 校验后拼接，并验证真实路径仍位于包根内；内部符号链接不跟随。
- `open_stream` 使用普通文件读取流；`crc32` 为空，`method` 为 Store 语义。

### 4.3 压缩态（`ArchiveSource`）

- 打开时对归档做只读内存映射（`mmap`），中央目录解析后持有映射，成员读取不经过 `read()` 系统调用。
- Store 成员：`ByteStream::Mapped` 直接切片，资源读取接近磁盘顺序访问速度，无需解压与复制。
- Deflate 成员：`ByteStream::Decoded` 流式解码；小文本成员可在限额内一次性读入。
- CRC32 校验：`verify_hashes` 开启或 `validate` 时校验 Store 成员 CRC32；普通解析只信任中央目录并校验尺寸。
- ZIP64、UTF-8 文件名标志位（EFLAG bit 11）由读取层处理；非 UTF-8 文件名按拒绝处理（`DOCUMENT_ARCHIVE_INVALID`）。
- 映射生命周期由 `DocumentHandle` 持有；`documentClose` 或缓存淘汰时释放。Windows 上映射会占用文件句柄，编辑保存走「临时文件 + 原子替换」，与解析读取互不阻塞。
- `mmap` 相关 `unsafe` 仅允许出现在 `source/archive.rs`，`unsafe fn` 使用 `# Safety` 章节、`unsafe` 块使用 `// SAFETY:` 注释，说明映射有效性与生命周期不变量。

### 4.4 模式一致性保证

同一内容在目录态与压缩态必须得到完全一致的模型与诊断结果（除成员时间戳、`kind` 字段外）。`tests/fixtures/documents/` 中的每个夹具同时提供目录与归档两种形态，一致性测试逐一比对规范化模型摘要，作为发布门禁。
