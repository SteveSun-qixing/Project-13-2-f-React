## 三、目录布局与文件边界

### 3.1 目录布局

```
<workspace>/                              # 工作区根（用户数据根）
├── .chips/                               # 平台保留目录（隐藏；不进入扫描）
│   ├── workspace.json                    # 标记文件（格式与版本）
│   ├── config.workspace.json             # 工作区层配置（权威：10-配置系统设计 §3.1）
│   ├── plugins/                          # 工作区层插件配置
│   │   └── chips.official.editor.json
│   ├── backup/                           # 迁移与修复前备份（权威：10-配置系统设计 §3.1）
│   ├── logs/                             # 工作区级日志与诊断导出
│   ├── state/                            # 平台维护的工作区级运行状态（可重建）
│   │   ├── instance.lock                 # 实例锁（§2.4）
│   │   ├── cleanup.json                  # 未完成临时物与恢复登记
│   │   └── host-state.json               # CLI 运行标记（chips start / stop 维护）
│   └── cache/                            # 可重建派生缓存（缩略图、树索引、封面缓存）
│
├── 旅行日记.card/                         # 目录态卡片（编辑工作形态）
│   ├── .card/
│   ├── content/
│   └── ...
├── 参考资料.card                          # 归档态卡片（交付形态，ZIP Store）
├── 2026-东京.box                          # 箱子（唯一正式形态：单文件）
├── 笔记.md                                # 其他用户文件（普通文件，平台不解释）
└── 项目/                                  # 用户自建子目录（允许）
    └── 照片.card/                         # 文档可位于工作区任意层级
```

规则：

1. 用户文件区允许任意层级子目录；平台不规定用户的组织方式，也不自动移动用户文件。
2. `.chips/` 内的条目不是用户数据，删除后平台按需重建；其中 `backup/` 与 `logs/` 的内容由对应子系统管理。
3. **凭证材料不进入工作区**：凭证存储位于用户级 `<user-config-dir>/credentials/`（[10-配置系统设计](./10-配置系统设计.md) §7.2、[07-同步引擎设计](./07-同步引擎设计.md) §8.3）；工作区层配置只保存 `credential://` 引用，不保存材料。保留目录因此不设 `credentials/` 子目录。
4. 工作区不保存插件安装产物：`.cpk` 安装目录位于平台用户数据目录（[03-插件架构设计](./03-插件架构设计.md) §3.4、§4.2）；工作区只保存可选的工作区层插件配置。
5. `.chips/cache/` 容量受平台管理（默认上限 512 MiB，LRU 淘汰）；删除该目录不影响任何文档与配置。
6. `.chips/state/` 只存平台可重建的运行状态；三份运行标记的写入与清理规则：

| 条目 | 写入 | 清理 | 语义 |
|---|---|---|---|
| `instance.lock` | 工作区打开时建立（§2.4） | 正常关闭释放；心跳超过 60s 的失效锁可被接管 | 实例状态的权威来源 |
| `cleanup.json` | 崩溃残留与未完成临时物登记（§2.3） | 启动恢复或 `chips doctor --fix`；清理登记物后同步移除记录 | 恢复登记的权威来源 |
| `host-state.json` | `chips start` 覆盖刷新为 `{ running, pid, startedAt }` | `chips stop` 删除；文件缺失即视为未运行 | 面向脚本的运行标记，不是实例状态权威（[CLI 完整参考](../../06-开发与运维/07-CLI完整参考.md) §3.2） |

   - `.chips/state/` 整目录可随时删除：平台在下次打开工作区时按需重建；删除只丢失运行标记与恢复登记，不影响用户文档、工作区配置与插件配置（[开发数据与成品验证空间](../../06-开发与运维/09-开发数据与成品验证空间.md) §2.1、§3.2）。
   - 脚本判定实例是否在运行必须读 `instance.lock` 与诊断输出，不得只信 `host-state.json`；`host-state.json` 只是 `chips status` 的读取对象与幂等开关。

### 3.2 不进入扫描的条目

| 类别 | 规则 |
|---|---|
| 保留目录 | `.chips/` 整棵子树不扫描、不进文件树、不可搜索 |
| 平台保留前缀 | 根或任意层级以 `.chips` 开头的条目（如保存临时物 `.chips-save-<随机>`、导出暂存 `.chips-export-<随机>`、解包工作目录 `.chips-unpack-<随机>`）不扫描、不进文件树 |
| 系统生成物 | `__MACOSX/`、`.DS_Store`、`Thumbs.db`、`desktop.ini` 及其他以 `.` 开头的隐藏条目不扫描、不进文件树（[04-资源管理设计](./04-资源管理设计.md) §4.10） |
| 临时物 | 任何平台临时文件与目录（同保留前缀）不扫描；崩溃残留由启动恢复清理（§2.3） |
| 符号链接 | 不跟随、不扫描其目标；树中显示为不可展开条目并标注"链接不跟随"（[04-资源管理设计](./04-资源管理设计.md) §9.2） |
| 不可读条目 | 读取失败（权限、占用）的条目在树中标记错误态，不中断同目录其他条目 |

### 3.3 命名与冲突规则

1. 用户文件命名遵循[《卡片文件格式》](../../04-文件格式规范/01-卡片文件格式.md) §9.1 的通用命名规则：UTF-8、避免 `< > : " / \ | ? *`、扩展名小写、建议不超过 255 字符。
2. 目录态卡片的目录名固定以 `.card` 结尾（`<名称>.card/`）；归档态文件为 `<名称>.card`；箱子为 `<名称>.box`。名称部分是用户可读名，可随时重命名。
3. 保留前缀禁止：用户与插件不得创建 `.chips` 开头的条目；创建/重命名/移动到保留前缀一律返回 `WORKSPACE_RESERVED_PATH`。
4. 同名冲突：
   - 导入、导出、另存、新建产生冲突时，平台自动追加编号后缀：`旅行日记.card` → `旅行日记-2.card` → `旅行日记-3.card`；文档内部标识（`card_id` / `box_id`）保持源文档值不变。
   - 重命名已有文档只改变文件名，不改变 `card_id` / `box_id`；引用该文档的箱子条目 URL 由用户显式更新（平台不自动改写引用）。
5. 文档 ID 冲突：导入的文档与工作区中已有文档解析出相同稳定标识（`DOCUMENT_ID_CONFLICT`）时，导入流程中止并提示用户（重复副本，[11-文档服务设计](./11-文档服务设计.md) §3.1）。
6. 大小写：归档条目与文档 ID 精确匹配；目录态名称遵循卷语义，重命名只改大小写视为重命名（[04-资源管理设计](./04-资源管理设计.md) §9.3）。
