## 四、插件装载与调用

### 4.1 受管门面 `IManagedPluginRuntime`

```typescript
interface IManagedPluginRuntime {
  /** 按卡片类型装载基础卡片插件；返回平台包装的受管门面。 */
  loadBaseCard(cardType: string): Promise<IBaseCardPlugin>;
  /** 按布局类型装载箱子布局插件；返回平台包装的受管门面。 */
  loadLayout(layoutType: string): Promise<IBoxLayoutPlugin>;
}
```

规则：

1. `IManagedPluginRuntime` 由平台提供（渲染侧插件运行时），是编辑链路、渲染会话与任何渲染侧代码装载插件的**唯一入口**；应用插件不得持有它，插件不得调用它。
2. 入参是类型标识（`cardType` / `layoutType`），不是插件 ID、路径或入口 URL：装载对象由平台注册表按 manifest `capabilities.cardTypes[].id` / `capabilities.layouts[].id` 解析（[03-插件架构设计](./03-插件架构设计.md) §2.3）。
3. 返回的门面方法面与角色接口一致（`renderView` / `renderEditor` / `validateConfig` / `export`），但它是平台包装对象：平台在其上附加插件状态校验、错误归一与调用登记；**插件模块本身（ESM 模块图）不交给调用方**。
4. 装载失败不缓存失败结果：插件状态变化（启用、更新完成）后可重新装载；重复失败按 §九降级。
5. `export` 不因门面装载而执行：只有导出链路显式调用时才执行（[08-基础卡片插件接口](../../05-接口与契约/08-基础卡片插件接口.md) §2.4.4）。

### 4.2 缓存与失效

| 项 | 规则 |
|---|---|
| 缓存键 | 插件 ID + 版本（模块图与受管门面同键缓存） |
| 复用范围 | 单渲染进程内跨会话复用；模块级状态只在单个渲染帧/单个编辑容器生命周期内有效，插件不得假设全局唯一实例 |
| 失效事件 | `plugin:loaded` / `plugin:unloaded` 到达后失效对应插件全部缓存；随后按需重新装载 |
| 更新语义 | 蓝绿更新完成前，已挂载编辑器保持旧版本直到释放；更新完成后新装载使用新版本（[03-插件架构设计](./03-插件架构设计.md) §6.3） |
| 卸载语义 | 插件停用/卸载时，使用该插件的编辑器与预览节点占位降级；编辑器 `dispose()` 由编辑链路执行，插件不得依赖自身卸载时机 |

缓存失效必须在下一次装载前完成；不允许跨版本混用同一门面对象。

### 4.3 共享依赖外部化与 CSP

1. 插件渲染入口（`render.js`）构建时把 `react`、`react-dom`、`@chips/ui` 外部化，由平台在渲染进程提供唯一实例；插件不得打包第二份 React 或组件库（R4、[02-构建与打包](../../06-开发与运维/02-构建与打包.md) §5.5）。
2. 编辑态就近渲染与查看态帧共享同一套平台依赖提供物：同一版本、同一令牌来源（Design Tokens 经顶层的 `@chips/ui` ConfigProvider 注入）。
3. 应用窗口 CSP 的脚本来源必须包含 `'self'` 与 `chips-resource:`，插件模块经 `chips-resource://<plugin-scope>/render.js` 装载；完整 CSP 以[《渲染引擎设计》](./05-渲染引擎设计.md) §4.3 为准。
4. 插件渲染入口必须为 UTF-8 文本 ESM；禁止内联脚本、`eval` / `new Function`（构建门禁见[《构建与打包》](../../06-开发与运维/02-构建与打包.md) §9.3）。

### 4.4 权限判定

- 就近渲染不改变权限模型：插件在编辑容器内仍然只能经 `window.chips` 访问系统能力，Bridge 每次调用照常执行权限判定与审计（R17）。
- 编辑链路不得为插件代持权限：不把文档会话、资源句柄、文件路径透传给插件；插件需要资源时使用 08/09 规定的协议路径与句柄路径。
- 编辑器插件通常需要 `resources:read`；需要导入资源或导出产物时，由编辑链路经平台能力执行（资源导入经文档服务受控提交，导出经 `document:export`，见 §六.3、§八.3），插件不直接调用写能力。
- 授权被撤销时，运行中的编辑会话在下一次调用即被拒绝（[《权限系统设计》](./08-权限系统设计.md) §4.3）；编辑链路显示中文提示并保持文档未被修改。

### 4.5 隔离边界声明

就近渲染是"与应用同 realm 的受信调用"，不是沙箱：

| 边界 | 事实 | 平台要求 |
|---|---|---|
| 进程/realm | 插件编辑器代码与应用插件 UI 运行在同一渲染进程、同一 JS realm | 应用插件必须把插件代码视为不可信代码：不向其暴露应用内部对象与可变全局状态 |
| DOM | 编辑器可访问同 realm 的 `document` 对象 | 平台不承诺编辑器无法访问应用 DOM；应用不得把敏感数据放入编辑器可触达的 DOM/全局变量 |
| 系统访问 | 仍只能经 `window.chips`；无 Node.js / Electron API | 违反者视为插件缺陷，按插件故障处理并记录审计 |
| 权限 | 与其它插件一致，按 manifest 申请与授权判定 | 不因就近渲染放宽任何权限 |
| 错误 | 编辑器抛错由编辑链路错误边界捕获 | 单个编辑器故障不得破坏应用与其它编辑器 |
| 信任等级 | 就近渲染要求高于查看帧（查看帧是不可信内容的默认形态） | 官方编辑引擎只对已安装且经用户授权的插件执行就近渲染；安装与授权界面必须如实展示插件能力与权限 |

第三方插件的最低信任约束：

1. 插件包必须通过安装校验与签名策略（[03-插件包格式](../../04-文件格式规范/03-插件包格式.md) §5、§6）；`development` 来源仅限开发工作区，不得分发。
2. 插件声明的权限是可申请上限，实际可用范围是"申请集合 ∩ 授权集合"；未授权能力一律拒绝（R3）。
3. 编辑器代码不得读取同 realm 其它插件的容器、订阅或资源句柄；插件之间的通信只经服务 / 能力 / 事件（[03-插件架构设计](./03-插件架构设计.md) §8）。
4. 平台不因编辑器运行在应用窗口而授予其更高信任；编辑器崩溃、循环或滥用按插件配额与故障策略处理（[01-薯片内核设计](./01-薯片内核设计.md)）。
