## 一、定位与边界

### 1.1 定位

薯片社区平台是薯片生态的**多用户内容社区**：用户注册登录后把 `.card` / `.box` 作品发布到社区，访客用浏览器浏览，日常用户用官方社区客户端浏览、上传与完整下载。定位由三句话组成：

1. **以个人主页为中心**：公开浏览单位是用户的公开作品（卡片与箱子混排），不做信息流门户、不做房间公开浏览主结构、不做工作台式聚合后台。
2. **服务端只做控制面**：服务端负责账号、鉴权、会话、预签名、元数据、状态与任务调度；`.card` / `.box` 与资源字节一律由客户端直传对象存储，服务端不接收、不代理、不中转文件字节。
3. **网页浏览、客户端发布**：浏览器只负责浏览与提示；上传、完整下载与在线查看由客户端统一卡片传输链路执行（[《卡片传输协议》](../../05-接口与契约/16-卡片传输协议.md)、[《社区客户端设计》](./16-社区客户端设计.md)）。

社区平台是**服务端产品**，不是平台运行时的一部分：它不加载 Cordis 内核、不注册平台能力、不接收平台事件、不依赖 `window.chips` 与 Bridge；它与平台共享文件格式、能力语义与设计理念，但部署、进程与运行时完全独立（[ADR-010](../ADR/ADR-010-大爆炸重构策略.md)）。

### 1.2 产品范围

| 类别 | 内容 |
|---|---|
| 必做 | 欢迎页、社区简介页、登录 / 注册、个人主页（头图 + 作品网格）、客户端发布说明页、卡片与箱子内容直达页、管理后台；账号与令牌体系、内容模型、`card-transfer` 传输控制面、服务端渲染缓存与 Worker、发现与检索接口、内容管理写操作、平台治理与安全基线 |
| 明确不做 | 传统信息流首页；欢迎页上的发现、搜索、统计、最新内容橱窗；房间列表页与房间详情页（房间能力保留在接口与数据模型中，网页不暴露房间组织界面）；工作台聚合页；浏览器内上传与打包；浏览器内完整下载；服务端内容改写与格式迁移；服务端同步 |

规则：

1. 网页端不上传、不打包、不完整下载；旧版网页上传中心与房间页、发现页、工作台从活动路由移除（[《社区平台 API 契约》](../../05-接口与契约/11-社区平台API契约.md) §1.3）。
2. 房间不作为公开浏览主结构；个人主页直接消费用户级卡片 / 箱子列表，不依赖空间聚合接口。
3. 管理员后台独立于公开站点：公开站点不设显性后台入口，管理员登录后自动分流到 `/admin/`。

### 1.3 术语

| 术语 | 定义 |

| 受控代理 | 私有卡片查看 / 封面缓存的 API 代理路径，支持 `Range` 与权限判定 |

## 二、总体架构

### 2.1 运行形态

```
访客浏览器 ─┐                       官方社区客户端（Host 插件）
            │ 同源 HTTPS            │ 平台网络能力 http:request
            ▼                       ▼
      ┌────────────────────────────────────────────┐
      │ Nginx（证书、跳转、缓存头、反向代理）        │
      │  /        → web（前台 SPA）                 │
      │  /admin/  → admin（后台 SPA）               │
      │  /api/    → server:3000（Fastify）          │
      │  /admin/api/ → server:3000（管理端路由）     │
      └──────┬──────────────────────────┬───────────┘
             │                          │
   ┌─────────▼─────────┐      ┌─────────▼──────────┐
   │ worker（同镜像）   │      │ PostgreSQL         │
   │ 渲染缓存消费       │      │ Redis（队列/吊销） │
   └─────────┬─────────┘      └────────────────────┘
             │
     ┌───────▼────────────────────────────┐
     │ 对象存储 / CDN（公开桶 + 私有桶）    │
     │ 客户端字节直传与直读，不经 API 进程  │
     └────────────────────────────────────┘
```

| 能力 | 归属 |
|---|---|
| 卡片与箱子制作、编辑 | 平台客户端（工作区与编辑链路） |
| 上传 / 完整下载 / 本地查看的协议执行 | 客户端统一卡片传输链路 |
| 账号、令牌、元数据、状态、预签名、下载计划 | 社区服务端 API |
| 文件字节（源文件、资源、渲染产物） | 对象存储 |
| 服务端渲染（查看缓存与封面缓存） | 社区 Worker + 服务端渲染集成 |
| 页面展示与浏览 | 社区 Web 前台 |
| 平台治理 | 社区管理后台 |

### 2.2 模块划分

**服务端**（`packages/server/src/`）：

| 模块 | 职责 |
|---|---|
| `app.ts` | 组装 Fastify：Helmet、CORS、JWT、Cookie、Multipart、Swagger（可关）、错误处理、认证插件与全部路由 |
| `config/` | 环境变量 schema 校验与加载（`deploy/.env`）；校验失败拒绝启动 |
| `db/` | Drizzle 客户端、schema 与迁移；启动与 Worker 启动时自动执行迁移 |
| `errors/` | `AppError` 工厂与错误码常量；统一归一为契约错误信封 |
| `plugins/` | `error-handler`（统一错误响应）、`authenticate`（令牌解析与角色判定） |
| `routes/` | `health`、`auth`、`users`、`rooms`、`space`、`upload`、`card-transfer`、`cards`、`boxes`、`discover`、`admin` |
| `schemas/` | 请求体与查询参数校验 schema |
| `services/` | 业务服务：认证、用户、房间、卡片、箱子、上传会话、渲染缓存、无头宿主渲染集成 |
| `storage/` | S3 客户端、逻辑桶定义、公开读策略与启动初始化 |
| `worker.ts` | 渲染 Worker 入口：迁移 → Redis → 桶初始化 → 无头宿主渲染集成 → 重新入队 → 清理 → 消费循环 |

**Web 前台**（`packages/web/src/`）：`pages/`（欢迎、简介、登录、注册、个人主页、发布说明、卡片详情、箱子详情、后台中转、404）、`components/`（页头、页脚、个人头图、作品网格与磁贴）、`api/`（API 客户端与错误归一）、`contexts/`（会话上下文）、`lib/`（路由与工具）。

**管理后台**（`packages/admin/src/`）：独立 SPA：管理员登录、平台总览、用户治理、内容治理。

**部署**（`deploy/`）：`Dockerfile.server`、`Dockerfile.web`、`Dockerfile.admin`、`docker-compose.yml`、`nginx/`、`certs/`；本地开发脚本 `scripts/start-local-dev.sh`。部署细则以[《服务端部署与运维》](../../06-开发与运维/08-服务端部署与运维.md)为唯一权威。

### 2.3 与平台和客户端的关系

| 关系 | 规则 |
|---|---|
| 与平台运行时 | 社区服务端不在平台进程内，不加载 Cordis、不注册能力、不接收平台事件；平台侧无对应插件 |
| 与官方社区客户端 | 客户端是 `app` 插件，经平台网络能力访问社区 API；服务端不感知客户端内部结构，只消费契约字段 |
| 与传输链路 | 发布与下载由客户端统一卡片传输链路执行；服务端只做事务、校验与调度 |
| 与工作区 | 服务端不访问用户工作区；发布输入是客户端从工作区准备好的归档态交付物（[《工作区设计》](./13-工作区设计.md) §4.4） |
| 与同步引擎 | 发布不是同步：社区平台不是同步提供者，不参与工作区同步清单与冲突解决（[《同步引擎设计》](./07-同步引擎设计.md)） |
| 与文档解析器 / 渲染引擎 | 服务端渲染集成使用平台渲染链路生成缓存，不引入第二解析器与第二渲染管线；服务端不解析用户内容做任何改写 |
| 与主题 / 多语言 | 不承载主题与语言标识（[ADR-006](../ADR/ADR-006-主题系统与多语言系统.md)）；渲染缓存记录与 Web 前端均不得出现主题 / 语言维度 |

### 2.4 数据实体与不变量

| 实体 | 语义 | 关键不变量 |
|---|---|---|
| `users` | 账号、公开资料、角色与启用状态 | `username` 与 `username_lower` 全站唯一；`role ∈ {user, admin}`；`isActive` 由管理员控制 |
| `rooms` | 用户的内容组织单元（保留能力，网页不暴露） | `slug` 在用户范围内唯一；房间公开不代表内容公开 |
| `cards` | 卡片作品：服务器 ID + `cardFileId`（10 位 Base62）+ 元数据摘要 + 源对象 + 资源清单 + 状态与可见性 | 源对象永久保留；`status` 只取 `pending` / `ready` / `error`（契约 §4.5）；公开列表只含 `public + ready` |
| `boxes` | 箱子作品：服务器 ID + `boxFileId` + 元数据与结构 + 源对象 + 封面 + 可见性 | 箱子不进入渲染队列、不接受渲染产物 |
| `upload_sessions` | 上传事务：内容类型、可见性、幂等键、状态、源对象、有效期 | 同一幂等键重复创建返回同一会话；会话期间可见性不可变更 |
| `upload_session_resources` | 会话内已预签名对象的角色、相对路径、桶、对象键、大小与状态 | 对象键由服务端构造；`relativePath` 只允许包内相对路径 |
| `card_render_caches` | 渲染缓存记录：`cardId` + `sourceCardSha256` + `rendererVersion` + `renderProfile` + 缓存桶与前缀 + 入口 + TTL | 缓存可由源文件重建；过期只删缓存，不删源文件 |
| `card_render_jobs` | 渲染任务：状态、优先级、尝试次数、锁定者、`runAfter`、创建来源 | 同一版本（`cardId + sha256 + rendererVersion + profile`）不重复排产；失败超限置 `failed` |

以上实体与字段的线级定义（DTO、枚举、迁移）以[《社区平台 API 契约》](../../05-接口与契约/11-社区平台API契约.md) §4 与仓库初始迁移为准；本文件只定义语义与不变量。服务端不存在 `download_sessions` 表：下载会话无状态，`downloadId` 与作品实体对应，断点由客户端以对象为单位管理。

## 三、账号与认证

### 3.1 账号模型

1. 账号字段：`username`（全小写字母、数字与连字符，3–32 字符，全站唯一）、`email`（唯一）、`passwordHash`、`displayName`、`bio`、`avatarUrl`、`role`、`isActive`、创建与更新时间。口令只以哈希保存，只传输、不落日志。
2. 注册即建立会话；登录接受邮箱或用户名作为标识；连续失败触发账号锁定（阈值与时长由服务端配置）。
3. 个人资料编辑只允许 `displayName` / `bio` / `avatar` 三个入口；头像上传经 `multipart/form-data` 进入 API 进程，是除房间封面外唯一允许字节进入 API 的入口。
4. 修改密码成功后，除当前会话外的全部 refresh 会话被吊销。
5. 管理员禁用账号（`isActive = false`）后，该账号所有受保护访问按不可用处理；账号内容不随禁用被删除，由治理流程决定。

### 3.2 令牌模型

| 令牌 | 载体 | 保存位置 | 生命周期 |
|---|---|---|---|
| `accessToken` | 请求头 `Authorization: Bearer` | 浏览器与客户端内存；不落盘、不入日志 | 短时效，由服务端配置 |
| `refreshToken` | 浏览器：`HttpOnly` Cookie（`chips_refresh_token`，`Path=/api/v1/auth`，HTTPS 下 `Secure`，`SameSite=Strict`）；非浏览器：请求 / 响应体 | 浏览器由 Cookie 自动携带；桌面客户端保存到 Host 凭据（平台凭据能力） | 长时效，服务端可吊销并可轮换 |

- 令牌不得出现在 URL、查询串、对象键、恢复清单、预签名头与日志中。
- 服务端可轮换 refresh token；轮换时客户端必须原子替换旧值。

### 3.3 会话生命周期

1. **建立**：注册或登录成功返回用户资料与两个令牌；浏览器同时写入 Cookie。
2. **刷新**：刷新接口不区分"令牌不存在 / 已失效 / 用户不可用"，一律返回 `204` 表示"当前没有可恢复登录态"，避免泄露会话状态；客户端收到 `204` 必须清空本地令牌进入未登录态。
3. **401 自动刷新**：客户端对受保护接口的 `COMMUNITY_AUTH_TOKEN_EXPIRED` / `COMMUNITY_AUTH_TOKEN_INVALID` 只重试一次；并发 401 必须合并为单次刷新（single-flight），其余请求等待结果后重放。
4. **登出**：吊销当前 refresh 会话并清除 Cookie，幂等；登出尽力而为，客户端必须自行清理本地凭据。
5. **服务器地址变更**：客户端必须先清会话再切换基址，禁止令牌跨服务器复用。

### 3.4 权限与角色

- 内容读取：公开内容匿名可读；私有内容只有所有者与管理员可读；无权访问一律按 `404` 处理，不暴露存在性。
- 内容写入：卡片 / 箱子的可见性变更与删除只允许所有者；管理端删除允许管理员。
- 管理端：`/admin/api/v1/*` 全部接口要求有效 access token 且 `role = "admin"`；非管理员返回 `403`。
- 房间管理：创建、修改、删除、封面与内容列出均按所有者判定；房间内内容各自按 `visibility` 判定。

## 四、内容模型与发布形态

### 4.1 用户与房间

1. 公开面以用户为中心：`GET /users/:username`、`GET /users/:username/cards`、`GET /users/:username/boxes` 是个人主页的数据来源。
2. 房间是内容组织单元：`roomId` 为空表示挂在用户根目录；房间计数只统计当前请求者可见数量。
3. 网页不暴露房间浏览；`space`、房间列表与房间内容接口保留在契约中，供客户端与后续能力使用。

### 4.2 卡片

1. 一张卡片由服务器实体（UUID v4）与文件级 ID（`cardFileId`，来自 `.card/metadata.yaml` 的 `card_id`，10 位 Base62）共同标识；`sourceCardSha256` 与源对象位置构成源文件身份。
2. 卡片状态机：

```
上传会话创建（占位记录）
        │ complete（校验通过，源文件就绪）
        ▼
     pending ──────────────┐
        │ 渲染缓存 ready     │ 校验 / 渲染失败
        ▼                    ▼
     ready ◀── 重新发布 ──  error
```

状态取值与语义以[《社区平台 API 契约》](../../05-接口与契约/11-社区平台API契约.md) §4.5 为唯一权威，本文件只描述转换：服务端渲染模式下 `complete` 成功即 `ready`（查看产物由 Worker 异步生成，`viewState` 独立推进）；渲染产物模式下提交产物后转 `ready`、未提交产物保持 `pending`，补传产物并再次提交后转 `ready`；校验或发布失败转 `error`，重新发布可回到 `ready`。卡片状态固定三值，不存在 `processing` 等流水线中间状态。

3. 查看状态（`viewState`）独立于卡片状态，取值与语义以契约 §4.5 为准；卡片打开必须以 `open-view` 的 `viewState` 与 `viewUrl` 为准，`status = ready` 不表示查看产物已生成。
4. 发布形态只有两种，同一会话二选一：

| 形态 | 触发 | 服务端行为 |
|---|---|---|
| 服务端渲染模式 | `includeRenderArtifacts: false`（缺省） | 源文件就绪后排产查看与封面缓存，客户端轮询 `render-status` |
| 渲染产物模式 | `includeRenderArtifacts: true` | 服务端不调度渲染，校验并发布客户端上传的查看 / 封面产物；`rendererVersion` 只记录，不参与协商 |

5. 源文件永久保留：缓存删除、重建或过期清理都不得删除 `chips-card-files` 中的 `.card` 源文件；缓存可由源文件重建。
6. 服务端不改写用户内容：版本门禁不通过时确定性拒绝（`COMMUNITY_CARD_VERSION_UNSUPPORTED`），迁移由客户端迁移工具完成。

### 4.3 箱子

1. 箱子由服务器实体（UUID v4）与文件级 ID（`boxFileId`，来自 `.box/metadata.yaml` 的 `box_id`）共同标识；源 `.box` 保存到私有桶 `chips-box-files`。
2. 箱子不使用服务端渲染队列，也不接受渲染产物；查看态由服务端生成**只读箱子文档**（名称、描述、条目列表），不是布局渲染。
3. 条目模型：卡片条目命中社区公开就绪卡片时给出社区卡片链接与查看入口；内嵌条目显示包内路径；`contentType = 'chips/box'` 时浏览态显示被引用箱子的封面，不展开其布局。
4. 箱子在个人主页与卡片统一混排为"作品"；封面缺失时使用默认封面。

### 4.4 作品聚合

1. 公开列表只返回 `status = ready` 且 `visibility = public` 的内容；本人列表额外包含私有与未就绪内容。
2. 个人主页把卡片与箱子转换为统一作品模型（`id` / `type` / `title` / `coverUrl` / `href` / `createdAt`），按创建时间倒序混排，不按类型分段。
3. 卡片 `coverUrl` 表示独立封面入口而非任意资源图；卡片封面与内容 HTML 是两份独立产物，并保有可追溯的互相关联关系（[《社区平台 API 契约》](../../05-接口与契约/11-社区平台API契约.md) §4.5）。

### 4.5 可见性

| 可见性 | 公开面行为 | 桶与缓存 |
|---|---|---|
| `public` | 出现在列表与详情；查看与封面入口公开可读 | 资源、源网络卡片、查看 / 封面缓存入公开桶 |
| `private` | 全部公开读接口按不存在处理（`404` 语义） | 查看 / 封面缓存入私有桶，只经受控代理读取；资源与源对象按会话可见性选择桶 |

规则：`public → private` 变更时必须移除公开桶中的查看 / 封面缓存并让缓存记录失效，公开直链立即失效；`private → public` 不自动恢复旧缓存，按源文件重新可用。

## 五、上传、下载、浏览与检索

### 5.1 上传（服务端职责）

1. 上传走 `card-transfer` 控制面：创建上传会话 → 对象预签名 → 客户端分片直传对象存储 → 完成提交（`complete`）→ 发布。客户端算法、断点与校验顺序见[《卡片传输协议》](../../05-接口与契约/16-卡片传输协议.md)；线级字段见[《社区平台 API 契约》](../../05-接口与契约/11-社区平台API契约.md) §5。
2. 会话创建时服务端构造 `resourcePrefix`、`networkCard` / `boxFile` 目标与 `expiresAt`；客户端只消费响应字段，不得自行拼接对象键。
3. 完成阶段服务端必须：校验会话状态与对象归属；读取网络资源卡片对象并校验 ZIP 可读与必需文件；提取 `card_id` / `chip_standards_version` / `name` / `tags` / `cover_ratio`；校验资源路径、存在性与大小；保存资源清单、摘要与恢复清单；按发布形态分派渲染或直接发布；写作品列表可用状态。
4. 对象角色：卡片为 `resource` / `network-card` / `render-file` / `cover-file`；箱子为 `box-file`。角色与桶的完整定义以[《社区平台 API 契约》](../../05-接口与契约/11-社区平台API契约.md) §5.2 与[《卡片传输协议》](../../05-接口与契约/16-卡片传输协议.md) §6 为准。
5. 幂等：上传会话创建必须携带幂等键；同键同体返回首次结果，同键不同体返回 `COMMUNITY_IDEMPOTENCY_CONFLICT`。
6. 大小与类型限制：会话创建与预签名阶段即按角色上限校验，超限返回 `COMMUNITY_FILE_TOO_LARGE` / `COMMUNITY_FILE_TYPE_INVALID`；Nginx 上传体积上限与配置上限保持匹配（[《服务端部署与运维》](../../06-开发与运维/08-服务端部署与运维.md) §3.6）。

### 5.2 下载（服务端职责）

1. 完整下载走 `card-transfer` 下载会话：创建下载会话 → 读取下载计划 → 客户端按计划逐对象下载、校验摘要、还原资源并重新打包为完整离线卡片。
2. 下载计划包含网络资源卡片对象（箱子为 `boxFile`）、资源对象清单、`restoreManifest` 与 `schemaVersion`；恢复清单结构与恢复验收标准见[01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md) §2.3、§2.4。
3. 服务端不保存断点：断点续传以对象为单位重试；计划 URL 与下载 URL 均为短时地址，不得缓存或长期保存。
4. 私有内容的下载会话只有所有者与管理员的创建请求成功，其他请求者按 `404` 处理。

### 5.3 浏览与检索

| 分类 | 服务端行为 |
|---|---|
| 用户与空间 | 公开资料、当前用户资料、资料编辑、密码修改、头像上传；空间聚合接口保留 |
| 房间 | 创建、修改、删除、封面、列表与内容列表；房间不作为公开浏览主结构 |
| 卡片 | 摘要 / 详情 / 打开视图（`open-view`）/ 状态 / 渲染状态 / 查看入口 / 封面入口 / 缓存代理 / 可见性变更 / 删除 |
| 箱子 | 摘要 / 详情 / 只读文档 / 封面 / 可见性变更 / 删除 |
| 发现与检索 | 公开就绪卡片与箱子按时间倒序分页；检索按名称、标签与用户名匹配 |

规则：

1. 列表统一使用 `page` / `pageSize` 分页；非法参数返回 `COMMUNITY_VALIDATION_ERROR`；超过总页数返回空数组与正确分页对象。
2. "认证：可选"的接口在携带非法令牌时返回 `401`，不静默降级为匿名。
3. 检索结果只含公开可见内容，不返回私有或未就绪内容的存在性。
4. 公开浏览类 `GET` 返回 `ETag` 并支持 `If-None-Match`；认证、传输控制面、查看 / 封面入口与渲染状态接口返回 `Cache-Control: no-store`。

### 5.4 内容管理写操作

1. 可见性变更（`PATCH`）：只允许所有者；`public → private` 必须同时清理公开缓存并失效公开直链。
2. 删除（`DELETE`）：卡片删除实体、源对象、资源对象与渲染产物 / 缓存；箱子删除实体与源对象；房间删除后房间内内容回到根目录。删除首次返回 `204`，重复删除返回 `404`（副作用只发生一次）。
3. 管理端删除由管理员执行，走同一业务服务，副作用与所有者删除一致。

## 六、渲染缓存与 Worker

### 6.1 服务端渲染

1. 社区平台承担服务端渲染：Worker 从私有桶读取 `.card` 源文件，经平台渲染链路生成查看缓存与封面缓存，写回对象存储；渲染集成使用平台无头壳的离屏帧宿主（[17-跨端Shell与平台抽象设计](./17-跨端Shell与平台抽象设计.md) §七），不引入第二渲染管线。
2. 渲染 profile 固定为两类：`community-web`（完整查看缓存）与 `community-cover`（封面缓存）；两者各自独立排产、独立记录。
3. 服务端渲染不引入第二解析器与第二渲染管线：解析、渲染与资源处理使用平台同一条链路与同一套插件接口（[《文档解析器设计》](./06-文档解析器设计.md)、[《渲染引擎设计》](./05-渲染引擎设计.md)）。
4. 渲染缓存不含主题与语言标识（[ADR-006](../ADR/ADR-006-主题系统与多语言系统.md)）；`rendererVersion` 标识输出契约版本，输出变化必须递增该值使旧缓存整体失效。

### 6.2 缓存模型

| 项 | 规则 |
|---|---|
| 缓存键 | `cardId + sourceCardSha256 + rendererVersion + renderProfile` 共同标识一份缓存 |
| 缓存版本（`cacheVersion`） | 由服务端在生成时确定；客户端只能使用 `viewUrl` 或响应头返回的地址，不得自行构造缓存路径 |
| 桶选择 | 公开卡片入公开缓存桶；私有卡片入私有缓存桶，只经受控代理读取 |
| TTL | 最后一次访问后续期 30 天；过期由 Worker 每小时清理；清理只删缓存，不删源文件 |
| 重建 | 源文件永久保留，缓存可由源文件重建；渲染器版本变化整体失效并按需重建 |
| 受控代理 | 私有缓存代理必须支持 `Range` 与 `206 Partial Content`；公开缓存入口同样保留分段读取能力，否则不得发布 |

### 6.3 Worker 流水线

1. 启动顺序：执行数据库迁移 → 连接 Redis → 初始化对象存储桶 → 初始化渲染集成 → 重新入队超过 30 分钟仍处于处理中的任务 → 执行一次过期清理 → 按并发配置启动消费循环 → 每小时清理一次过期缓存。
2. 任务来源（`createdBy`）：上传、查看未命中、封面未命中、人工、系统重建；同一版本不重复排产。
3. 取任务：从 Redis 队列阻塞取出任务 ID，在 PostgreSQL 任务表中锁定任务，下载私有桶源文件，按 profile 生成缓存并上传对象存储。
4. 重试：单个任务最大尝试次数由配置控制（默认 2）；超过次数任务置 `failed`、缓存记录置 `error`；滞留任务自动重新入队。
5. 并发：Worker 消费并发、缓存上传并发、队列阻塞超时、缓存 TTL 与渲染器版本均由环境变量配置，阈值口径以[《服务端部署与运维》](../../06-开发与运维/08-服务端部署与运维.md) §6.2 为唯一权威。
6. Worker 不监听公网端口，不接收 HTTP 请求；存活以日志与队列状态判断。

### 6.4 渲染状态与查看入口

| 入口 | 行为 |
|---|---|
| `GET /cards/:cardId/render-status` | 返回 `viewState` 与 `attemptCount`；客户端轮询直到 `ready` 或 `error`，轮询间隔不低于 1 秒并退避 |
| `GET /cards/:cardId/view` | `ready` 时 `302` 到查看缓存入口（公开内容为公开桶 / CDN 地址，私有内容为受控代理路径）；处理中返回 `202` + `Retry-After`；失败返回 `409` |
| `GET /cards/:cardId/cover` | `ready` 时 `302` 到封面缓存入口；处理中返回带 `Retry-After` 的临时占位页；失败回退默认封面 |
| `GET /cards/:cardId/open-view` | 打开热路径的轻量视图：只含 `viewState`、`viewUrl`、封面入口与基础元数据，不含标签、大小与摘要等重字段 |

### 6.5 内容直达的呈现边界（无浏览器插件宿主）

1. 社区前台**不承载浏览器侧插件宿主**：浏览器侧应用插件宿主（`plugin-sessions` 插件会话 API、资源打开计划、`entry` / `bootstrap` 引导与 Web Runtime）不在薯片生态架构范围；插件运行目标只有 `host`（[17-跨端Shell与平台抽象设计](./17-跨端Shell与平台抽象设计.md) §2.2、§5.5）。
2. 内容直达页展示**服务端渲染产物**：社区渲染 Worker 经无头宿主生成查看缓存与封面缓存，前台经 §6.4 的 `view` / `cover` 入口呈现并轮询状态；前台不创建插件会话、不装配 `window.chips`、不转发 Host 调用。
3. 服务端曾有的 `/api/v1/host/*` 宿主链路随之废止：不迁移、不保留兼容路径；如未来重新评估浏览器宿主，必须走 RFC → 评审 → ADR（[03-变更与决策管理](../../07-工程管理/03-变更与决策管理.md)）。
4. 内容直达路由不渲染站点页脚与公共壳层，只保留最小化加载背景；若卡片仍在处理中显示等待态，不得把 `rendering` 误显示为不存在。

## 七、社区 Web 前台

### 7.1 定位

Web 前台面向临时访客：欢迎页与社区简介讲清社区定位，个人主页承载公开作品，登录 / 注册建立会话，发布说明页引导用户到客户端发布，内容直达页承载卡片与箱子查看。浏览器不提供上传、打包与完整下载入口。

### 7.2 路由与页面

| 路由 | 页面 | 访问规则 |
|---|---|---|
| `/` | 未登录为欢迎页；已登录普通用户跳个人主页；管理员跳 `/admin` | 公开 |
| `/about` | 社区简介 | 公开 |
| `/login`、`/register` | 登录 / 注册 | 已登录时重定向 |
| `/@:username` | 个人主页：头图 + 作品网格 | 公开；私有内容仅本人可见 |
| `/workspace` | 客户端发布说明页 | 需登录 |
| `/cards/:cardId` | 卡片内容直达 | 公开 |
| `/boxes/:boxId` | 箱子内容直达 | 公开 |
| `/admin` | 后台中转页，跳转独立后台 | 公开；鉴权在后台完成 |
| `*` | 404 | 公开 |

路由壳分两类：`default`（社区页面，含页头；个人主页不渲染站点页脚）、`document`（卡片 / 箱子内容页，页面级文档流滚动）。内容直达页不显示社区页脚。

### 7.3 个人主页

1. 头图区展示头像、昵称、用户名与简介；本人访问时显示资料设置入口。
2. 作品网格展示该用户全部公开作品，卡片与箱子混排、创建时间倒序；卡片封面以独立封面入口承载，箱子封面缺失时回退统一占位。
3. 本人专属入口：作品区显示"+"进入发布说明页；支持管理态批量删除（卡片与箱子统一按"作品"口径，`Promise.allSettled` 编排，失败项保留并提示）。
4. 状态要求：头图区与作品网格各有骨架加载态；用户不存在时页面级 404；空作品时保留头图与本人入口。

### 7.4 技术栈与视觉

1. 前台与后台统一 React + TypeScript + antd + `@chips/ui`（`ConfigProvider` 统一主题）；界面文案简体中文直写；不使用自建主题、图标与多语言运行时（[ADR-006](../ADR/ADR-006-主题系统与多语言系统.md)、[ADR-008](../ADR/ADR-008-React加fork-antd前端技术栈.md)）。
2. 组件取材、样式与视觉验收遵循[03-React组件开发规范](../../02-开发规范/03-React组件开发规范.md)、[08-@chips/ui共享层使用指南](../../02-开发规范/08-@chips-ui共享层使用指南.md)、[09-统一视觉规范](../../02-开发规范/09-统一视觉规范.md)；不硬编码颜色、间距与字号。
3. 响应式桌面优先，平板保持头图完整性，移动端不出现挤压失控；键盘可访问、焦点态可见；拖拽区域（若有）必须提供点击回退路径。
4. 内容安全：生产 CSP、HSTS 与安全响应头由 Nginx 输出；`style-src` 允许 `'unsafe-inline'` 的唯一原因是组件库运行时注入样式；不放行第三方统计、字体 CDN 与 `script-src 'unsafe-inline'`（[《服务端部署与运维》](../../06-开发与运维/08-服务端部署与运维.md) §3.3）。

## 八、管理后台

### 8.1 定位与入口

1. 管理后台是独立 SPA，部署在 `/admin/`，与前台、API 严格同源；公开站点不设置显性后台按钮。
2. 管理员账号登录后自动分流：前台根路由与登录成功均跳转 `/admin`；普通用户不受影响。
3. 后台与前台共用同一令牌模型与刷新链路，管理端接口统一前缀 `/admin/api/v1`；端点级契约（方法、路径、鉴权、幂等与错误码）见[《社区平台 API 契约》](../../05-接口与契约/11-社区平台API契约.md) §十一。

### 8.2 功能面

| 功能 | 行为 |
|---|---|
| 登录 | 管理员账号登录；非管理员拒绝进入后台 |
| 平台总览 | 用户数、卡片数、箱子数、存储总量与当日增量 |
| 用户治理 | 按用户名 / 昵称检索；查看角色、存储占用、创建时间与启用状态；启用 / 禁用账号 |
| 内容治理 | 按卡片 / 箱子类型检索；查看归属、可见性、大小、状态与时间；删除违规或损坏内容 |
| 退出 | 清理本地会话并返回登录页 |

### 8.3 鉴权与安全

1. 所有管理端接口要求有效 access token 且 `role = "admin"`；未认证返回 `401`，权限不足返回 `403 COMMUNITY_AUTH_INSUFFICIENT_PERMISSION`。
2. 管理端与前台共用错误模型与业务码；后台接口额外校验角色。
3. 管理员操作必须写服务端访问日志（含操作者、对象与结果，不含令牌与请求体敏感内容）；登录失败与账号锁定同样记录。
4. 首次启动管理员由环境变量初始化；初始化完成后必须从环境移除或轮换口令（[《服务端部署与运维》](../../06-开发与运维/08-服务端部署与运维.md) §6.2、§6.4）。

## 九、内容治理

### 9.1 治理对象与动作

| 对象 | 治理动作 | 副作用 |
|---|---|---|
| 账号 | 禁用 / 启用（`isActive`） | 禁用后该账号受保护访问不可用；内容保留待处置 |
| 卡片 | 可见性变更、删除 | 删除清理实体、源对象、资源对象与渲染产物 / 缓存 |
| 箱子 | 可见性变更、删除 | 删除清理实体与源对象 |
| 房间 | 修改、删除 | 删除后房间内内容回到根目录，不级联删除内容 |
| 渲染失败 | 重新排产或保留错误 | 错误可定位（`errorMessage` / 任务记录）；不静默丢弃 |

### 9.2 治理原则

1. **服务端不改写用户内容**：治理只做隐藏（私有化）、删除与账号状态变更；格式问题由客户端迁移工具处理。
2. **副作用一次性**：删除首次 `204`、重复 `404`；中止与登出幂等；任何治理动作不得产生半成品状态。
3. **公开性可撤回**：`public → private` 必须同时失效公开直链与公开缓存；撤回后公开面立即不可见。
4. **人工治理**：社区不引入自动化内容审核算法；滥用控制由限流、账号锁定与上传大小限制承担，处置由管理员人工执行。
5. **可追溯**：关键治理动作（登录失败、账号锁定、禁用、删除、传输会话创建与完成）必须写访问日志与审计记录；审计不含文件字节与恢复清单正文。

### 9.3 滥用与稳定性控制

1. 限流按账号与来源 IP 两个维度计数；认证类接口与传输控制面使用比浏览接口更严格的档位；触发限流返回 `429` 与 `Retry-After` 及限流响应头。
2. 上传限制按角色（卡片 / 箱子 / 资源 / 渲染产物）分别配置上限；超限确定性拒绝。
3. 账号锁定、会话吊销与令牌轮换构成凭证滥用防线；疑似泄露按[《服务端部署与运维》](../../06-开发与运维/08-服务端部署与运维.md) §6.4 轮换处置。

## 十、隐私与合规

### 10.1 数据清单与用途

| 数据 | 用途 | 公开面 |
|---|---|---|
| 账号：用户名、邮箱、口令哈希、角色、启用状态 | 认证、治理、计费与容量统计 | 不公开 |
| 公开资料：昵称、简介、头像 | 个人主页展示 | 公开 |
| 内容元数据：标题、标签、封面比例、大小、摘要、时间 | 浏览、检索、治理 | 公开内容公开；私有内容仅所有者与管理员可见 |
| 内容字节：源文件、资源、渲染产物 | 存储与展示 | 公开内容入公开桶；私有内容入私有桶并通过受控代理 |
| 会话与传输记录：上传 / 下载会话、渲染任务、访问日志 | 运行、排查、审计 | 不公开 |
| 来源 IP | 限流、安全审计 | 不公开、不回显给非本人 |

### 10.2 公开面边界

1. 公开 DTO 只含公开资料字段；不返回邮箱、角色、来源 IP、内部对象键与真实路径。
2. 私有资源与不存在资源统一按 `404` 处理，不暴露存在性。
3. 错误 `message` 为简体中文面向用户；`details` 为结构化诊断且不含令牌、预签名地址、真实文件系统路径与堆栈。
4. 管理端操作日志只记录对象标识与结果，不回显用户敏感信息。

### 10.3 凭证与日志红线

1. 令牌、预签名地址、下载地址都是短时凭证：不得写入日志、不得进入卡片 / 箱子文件与恢复清单、不得出现在错误 `message` 中。
2. 日志不得记录口令、`accessToken`、`refreshToken`、Cookie；对象键、查询串按需脱敏。
3. 生产密钥与口令只保存在部署主机 `.env`、密码管理器与发布密钥库；凭据不得写入 Git、镜像、文档与聊天记录（[《服务端部署与运维》](../../06-开发与运维/08-服务端部署与运维.md) §6.3）。

### 10.4 数据保留与删除

| 数据 | 生命周期 |
|---|---|
| 源文件（`.card` / `.box`） | 永久保留，直到用户删除作品或管理员治理删除 |
| 渲染缓存 | 最后一次访问后 30 天，过期由 Worker 清理；可由源文件重建 |
| 上传会话 | 默认 60 分钟过期；过期会话预签名失效 |
| 下载会话 | 短时；不落库，不保存断点 |
| 备份 | 按[《服务端部署与运维》](../../06-开发与运维/08-服务端部署与运维.md) §7 的周期与保留策略执行，备份含数据库与对象存储 |

### 10.5 第三方与跨端合规

1. 生产只依赖对象存储 / CDN、证书签发与主机服务；不引入第三方统计、广告、字体 CDN 与外部脚本。
2. 资源域名与主站域名分离，对象存储公开域名保留 `Range` 与正确 `Content-Type`；生产证书与密钥只存在于部署主机。
3. 桌面客户端侧：`accessToken` 仅内存，`refreshToken` 存平台凭证存储；不保存账号密码；不把令牌写入工作区、配置、事件与日志（[《社区客户端设计》](./16-社区客户端设计.md) §5.4）。

## 十一、错误语义

1. 权威登记表是[《社区平台 API 契约》](../../05-接口与契约/11-社区平台API契约.md) §7：HTTP 状态、`COMMUNITY_*` 业务码、`retryable` 与 `ChipsError` 映射只在该处定义，本文件不复制。
2. 分层归一：网络未达服务端沿用平台网络错误码（`HTTP_REQUEST_FAILED` / `RESOURCE_NETWORK_FAILED`）；服务端 4xx / 5xx 业务失败保留同名 `COMMUNITY_*` 码并附加 `httpStatus`；响应不符合契约时客户端归一为 `COMMUNITY_RESPONSE_INVALID`。
3. 业务码不改名、不二次命名；客户端只按 `code` 分支，不匹配 `message` 文本；`retryable: false` 不得自动重试。
4. 新增错误码必须先登记进契约 §7.3 再使用；服务端未归一异常统一转换为 `COMMUNITY_INTERNAL_ERROR` 并记录 `traceId`，不得回显内部堆栈与组件名。
5. 社区前台与客户端展示简体中文用户提示；`traceId` 只进诊断信息，不向用户展示。

## 十二、约束清单

### 12.1 架构约束

1. 服务端产品独立于平台运行时：不加载 Cordis、不注册平台能力、不接收平台事件；插件访问系统能力只能走平台正式链路（R1、R2、[《插件架构设计》](./03-插件架构设计.md)）。
2. 只做控制面：API 进程不接收、不代理、不中转 `.card` / `.box` 与资源字节；头像与房间封面是仅有的字节入口。
3. 浏览器不提供上传与完整下载入口；发布与下载只在客户端统一卡片传输链路执行。
4. 服务端不改写用户内容；版本门禁确定性拒绝；迁移由客户端迁移工具完成。
5. 不存在第二解析器、第二渲染管线、第二套传输协议；两端（社区 / 个人服务器）差异只允许"裁剪"与协议能力开关（[《个人服务器设计》](./15-个人服务器设计.md) §7）。
6. 单一事实源：契约字段、错误码、桶名、环境变量与部署要求各自只有一处权威定义；本文只引用不复制。
7. 无兼容包袱：`/api/v1` 内只允许向后兼容变更；不做运行时兼容层与双轨（[ADR-010](../ADR/ADR-010-大爆炸重构策略.md)）。
8. 不承载主题与多语言：渲染缓存、产物记录与 Web 前端都不得出现主题 / 语言标识或运行时（[ADR-006](../ADR/ADR-006-主题系统与多语言系统.md)）。

### 12.2 安全约束

1. 生产只提供 HTTPS；令牌 Cookie `Secure` + `SameSite=Strict`；主站入口与 `BASE_URL` 精确一致。
2. CORS 不放行 `Access-Control-Allow-Origin: *`；生产只允许同源、平台客户端来源与显式白名单（[《服务端部署与运维》](../../06-开发与运维/08-服务端部署与运维.md) §3.4）。
3. 路径与对象键安全：服务端构造对象键；客户端只提交包内相对路径；拒绝 `..`、前导 `/`、反斜杠、控制字符与超长输入；通配路径重新解析原始 URL。
4. 私有对象只允许所有者经受控代理读取；受控代理与缓存代理必须支持 `Range` 且不得信任路由折叠结果。
5. 令牌、预签名、密钥、口令不落日志、不入库、不入文档；管理端与传输控制面额外校验角色与所有权。

### 12.3 质量约束

1. 测试范围与门禁遵循[05-测试规范](../../02-开发规范/05-测试规范.md)与[05-CICD与质量门禁](../../06-开发与运维/05-CICD与质量门禁.md)；传输完成校验、可见性切换、渲染状态机与鉴权是必测路径。
2. 性能与容量只引用[01-架构原则](../../00-愿景与原则/01-架构原则.md) §4.2 与部署文档口径，不自造指标；单主机规格与 Worker 并发是当前唯一容量调节手段。
3. 运行脚本与验证方式使用服务端仓库 `package.json` 中的正式脚本（构建 / lint / test / 本地联调），不引入旁路流程。

## 十三、自检清单

- [ ] 网页端没有上传、打包与完整下载入口；发布链路的输入来自客户端传输链路。
- [ ] 服务端 API 进程不接收文件字节；对象角色、桶可见性与预签名/CID 规则与契约 §5 一致。
- [ ] 卡片状态机只取 `pending` / `ready` / `error`，`viewState` 只取 `pending` / `rendering` / `ready` / `error`，与契约 §4.5 一致。
- [ ] 公开列表只含 `public + ready`；私有资源按 `404` 处理；`public → private` 清理公开缓存与直链。
- [ ] 上传完成校验覆盖会话状态、对象归属、ZIP 可读、必需文件、版本门禁、资源路径与大小、摘要与恢复清单。
- [ ] 渲染缓存键含 `sourceCardSha256` 与 `rendererVersion`；TTL 30 天且只删缓存不删源文件；Worker 启动顺序与重试策略与 §6.3 一致。
- [ ] 查看 / 封面入口、受控代理与公开缓存均保留 `Range` / `206`；处理中返回 `202` + `Retry-After`，不误报不存在。
- [ ] Web 前台路由、路由壳与状态（加载 / 空 / 错误 / 404）与 §7 一致；个人主页作品混排与本人入口正确显隐。
- [ ] 前台与后台只从 `@chips/ui` 与 antd 取材，文案简体中文直写，未引入主题 / 多语言运行时或第二组件库。
- [ ] 管理后台全部接口要求 `role = "admin"`；公开站点无显性后台入口；管理员登录自动分流。
- [ ] 全部业务码来自契约 §7.3 登记表；新增错误码先登记后使用；日志不含令牌、口令与预签名。
- [ ] 隐私边界与数据保留策略与 §10 一致；第三方 CDN / 统计未引入；备份与轮换流程引用部署文档。
- [ ] 本文与契约、传输协议、客户端设计、个人服务器设计、部署运维之间没有重复定义，链接全部为真实路径。
