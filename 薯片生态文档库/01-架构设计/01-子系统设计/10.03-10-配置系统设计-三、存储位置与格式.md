## 三、存储位置与格式

### 3.1 目录布局

```
<platform-config-dir>/                 # 平台安装级配置目录
└── config.platform.json

<user-config-dir>/                     # 用户级配置目录
├── config.user.json
├── credentials/                       # 凭证存储（归凭证能力，见第七节）
├── backup/                            # 迁移与修复前备份
└── plugins/
    ├── chips.official.editor.json
    └── chips.official.settings.json

<workspace>/                           # 用户工作区目录
└── .chips/                            # 平台保留目录
    ├── config.workspace.json
    ├── backup/
    └── plugins/
        └── chips.official.editor.json
```

- `.chips/` 是平台在工作区内的保留目录，工作区首次打开时由平台创建（工作区实体与目录布局见 [13-工作区设计](13-工作区设计.md)）。
- 只有存在显式覆盖的插件才会生成对应的插件配置文件；插件卸载时其用户级与工作区级插件文件一并删除。

### 3.2 平台路径映射

| 平台 | 平台级目录 | 用户级目录 |
|---|---|---|
| macOS | `/Library/Application Support/Chips/` | `~/Library/Application Support/Chips/` |
| Windows | `%PROGRAMDATA%\Chips\` | `%APPDATA%\Chips\` |
| Linux（后续阶段） | `/etc/chips/` | `~/.config/chips/` |

### 3.3 文件结构

平台键文件（平台层/用户层/工作区层）结构一致：

```json
{
  "schemaVersion": 1,
  "values": {
    "platform.log.level": "info",
    "platform.window.defaultWidth": 1400
  }
}
```

插件文件额外携带 `pluginId`，`values` 中为相对键：

```json
{
  "pluginId": "chips.official.editor",
  "schemaVersion": 2,
  "values": {
    "fontSize": 14,
    "autoSave": true
  }
}
```

字段说明：

| 字段 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `schemaVersion` | integer | 是 | 配置 schema 版本，正整数，从 1 开始 |
| `values` | object | 是 | 显式覆盖项；缺省键不写入，读取时由默认值补足 |
| `pluginId` | string | 插件文件必需 | 插件 ID，反向域名 |

### 3.4 格式选择

配置文件统一使用 JSON：

- 配置由平台写入、程序读取，JSON 无隐式类型歧义；YAML 将 `no`、`1.0` 等值隐式转换会破坏字符串型配置。
- 序列化输出确定（UTF-8、两空格缩进、键按字典序排序），便于原子替换、差异比较与测试。
- 人类可读，符合开放原则；需要注释与多行文本的人类创作文件（manifest、`.card`、`.box`）继续使用 YAML，见 [ADR-009](../ADR/ADR-009-文件格式设计原则.md)。
