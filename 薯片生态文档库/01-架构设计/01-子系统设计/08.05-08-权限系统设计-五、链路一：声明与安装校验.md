## 五、链路一：声明与安装校验

### 5.1 manifest 声明

插件在 `manifest.yaml` 的 `permissions` 中声明申请集合；字段为字符串数组，可省略（等价空集合）。

```yaml
id: chips.official.editor
version: 1.0.0
type: app
name: 编辑引擎
description: 创建和编辑卡片
author: 薯片官方
license: MIT
runtime:
  targets: [host]
  background: false
permissions:
  - "filesystem:read:${userDocuments}/chips"
  - "filesystem:write:${userDocuments}/chips"
  - notifications:send
  - clipboard:access
  - dialogs:use
  - window:control
ui:
  surface: window
  launcher: {}
```

规则：

- 一个权限 ID 一次声明；相同限定值的重复条目去重，不同限定值需要多条声明。
- 声明必须表达最小范围：能用子目录限定就不写整个目录变量，能用具体域名就不用 `*`。
- 依赖插件（`dependencies`）声明的权限不构成本插件的授权，也不得代为申请。

### 5.2 能力声明

能力（内置能力与第三方注册能力）通过 `permissions` 声明执行所需的基础权限 ID：

```typescript
import type { ICapability, JSONSchema } from '@chips/sdk';

interface IFileWriteInput {
  path: string;
  data: string;
  encoding?: 'utf-8' | 'base64';
}

const inputSchema: JSONSchema = {
  type: 'object',
  properties: {
    path: { type: 'string', minLength: 1 },
    data: { type: 'string' },
    encoding: { type: 'string', enum: ['utf-8', 'base64'], default: 'utf-8' },
  },
  required: ['path', 'data'],
  additionalProperties: false,
};

const fileWriteCapability: ICapability<IFileWriteInput, void> = {
  id: 'file:write',
  permissions: ['filesystem:write'],
  schema: inputSchema,
  execute: async (input) => {
    await writeFileAtomic(input.path, input.data, input.encoding ?? 'utf-8');
  },
};
```

规则：

- 能力只声明**基础权限 ID**（`<domain>:<scope>`），不携带限定值；限定值只存在于授权记录，判定时与实际调用目标比对。
- 纯计算能力（图像编解码、压缩、格式转换等）声明空权限数组。
- 第三方服务插件注册的能力只能引用平台已注册的基础权限 ID，不得自造权限。

### 5.3 安装校验流程

```
① manifest schema 校验
② 权限条目解析：语法、domain/scope 注册表、qualifier 文法
③ 角色适用性校验
④ 去重；更新场景下与已授权集合比对
⑤ 记录权限申请集合（默认未授权），进入 installed
⑥ 任一校验失败则安装终止，.cpk 不落盘、不注册；授权交互在首次启用时执行（见 6.2）
```

| 校验项 | 失败错误码 |
|--------|------------|
| 权限 ID 格式或限定值文法非法 | `PERMISSION_INVALID` |
| domain/scope 未注册 | `PERMISSION_UNKNOWN` |
| 权限不适用于该插件角色（如 `basecard` 申请 `window:control`） | `PERMISSION_ROLE_NOT_ALLOWED` |
| 用户拒绝授权 | 不产生错误码；被拒权限保持未记录，插件仍可启用 |

角色适用性规则：

- `window:control`、`menu:manage`、`tray:manage`、`shortcut:manage`、`power:manage`、`dialogs:use`、`shell:external` 仅 `app` 可申请。
- `system:read`、`power:read`、`transfer:manage` 与其余内置权限四种角色均可申请。
- `basecard`、`boxlayout` 的界面在平台容器内渲染，不申请窗口与系统集成类权限。

### 5.4 能力注册校验

服务插件注册能力时，平台校验：

1. `capability.permissions` 中每一项均为已注册的基础权限 ID；否则拒绝注册并返回 `PERMISSION_NOT_DECLARED`。
2. 服务插件自身 manifest 已声明这些权限；未声明则拒绝注册。
3. 服务插件执行能力内部访问时，使用服务插件自己的会话快照判定，不借用调用方权限。
