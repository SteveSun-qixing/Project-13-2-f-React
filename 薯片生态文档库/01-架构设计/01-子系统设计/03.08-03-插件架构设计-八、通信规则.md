## 八、通信规则

### 8.1 三条合法通道

| 通道 | 形态 | 方向 | 适用 | 生命周期绑定 |
|---|---|---|---|---|
| 服务 | `ctx.provide` / `ctx.inject` | 插件 ↔ 插件、插件 ↔ 平台 | 同步、类型化、进程内请求-响应 | 随 Fork；提供者卸载即撤销 |
| 能力 | Bridge `request` | 插件 → 平台、插件 → 插件（经注册的能力） | 需要权限判定、Schema 校验、审计的动作 | 订阅与句柄随 Fork；能力注册随提供者 |
| 事件 | `ctx.on` / `emit`、Bridge `subscribe` | 任意方向，广播与通知 | 状态变化通知、解耦协作 | 订阅随 Fork 自动退订 |

### 8.2 插件 → 平台

- 唯一入口是 Bridge 的三个方法（`request` / `subscribe` / `resource`，形状与语义见 [02-Bridge三层设计](02-Bridge三层设计.md) 与 [01-Bridge-API规范](../../05-接口与契约/01-Bridge-API规范.md)）。
- 每次 `request` 由 Bridge 依次执行：能力存在性检查 → 权限判定（插件申请集合 ∩ 能力权限，R3）→ JSON Schema 校验 → 路由执行 → 错误归一。
- 资源访问统一使用 `chips-resource://`，不得使用裸绝对路径（R13）。
- 平台不接受插件直接调用 Node.js / Electron API；沙箱与安全配置遵循 R17。

### 8.3 平台 → 插件

平台只能通过事件与已注册的插件接口触达插件：

- 事件：平台发布 `file:changed`、`plugin:loaded`、`plugin:disabled` 等标准事件，插件订阅后自行响应；标准事件清单见 [05-事件契约规范](../../05-接口与契约/05-事件契约规范.md)。事件名文法为 `^[a-z][a-z0-9-]*:[a-z][a-z0-9-]*$`（无点号、无通配符），插件自有域取插件 ID 末段（[09-事件系统设计](09-事件系统设计.md) §2.2）。
- 已注册接口：渲染引擎按注册表调用 `renderView` / `renderLayout` / `renderEditor`；生命周期动作调用角色入口（§4.3、§4.4）。

平台不得直接调用插件内部函数或访问插件内部状态；平台与插件之间禁止跨层直连（架构红线 §2.3）。

### 8.4 插件 ↔ 插件

禁止 `import`（源文件依赖）与直接对象引用。合法方式仅三种：

1. **服务**：提供者在激活期间 `ctx.provide('image', service)`；消费者 `ctx.inject(['image'], (ctx) => { void ctx.image.process(data); })`；调用经内核路由，消费者不感知提供者身份。
2. **能力**：提供者在激活期间注册已登记的能力 ID（如 [04-能力契约规范](../../05-接口与契约/04-能力契约规范.md) §8.2 的 `hello:greet`）；消费者经 Bridge `request` 调用，享受权限判定与审计。
3. **事件**：发布者 `ctx.emit('image:processed', payload)`，订阅者 `ctx.on('image:processed', handler)`；只用于通知，不承担请求-响应语义。

选择规则：

| 需求 | 通道 |
|---|---|
| 确定返回值、强类型契约、进程内同步调用 | 服务 |
| 需要权限、Schema 校验、跨上下文或审计 | 能力 |
| 只通知、不要求响应 | 事件 |

### 8.5 禁令

| 禁止 | 原因 |
|---|---|
| 跨插件 `import` 或直接实例化对方类 | 破坏可替换性与隔离 |
| 通过全局变量、全局单例交换数据 | 生命周期不可控，卸载残留 |
| 调用未声明的服务或未申请权限的能力 | 绕过内核路由与权限系统 |
| 直接访问 Node.js / Electron / 系统 API | 违反能力导向与安全基线 |
| 平台直接调用插件内部函数 | 违反分层红线 |
| 用事件模拟请求-响应并等待超时 | 语义错误，应使用服务或能力 |

### 8.6 示例

```typescript
// 主进程侧：服务插件提供 'image' 服务
class ImageService {
  async process(data: Uint8Array): Promise<Uint8Array> {
    // 示例处理：返回输入副本，调用方与内部不共享缓冲区
    return data.slice();
  }
}

class ImageServicePlugin {
  constructor(ctx: Context) {
    ctx.provide('image', new ImageService());
  }
}

// 主进程侧：消费者通过注入使用服务，不感知提供者身份
class ImageCardPlugin {
  constructor(ctx: Context) {
    ctx.inject(['image'], (ctx) => {
      ctx.on('image:requested', (payload: { data: Uint8Array }) => {
        void ctx.image.process(payload.data);
      });
    });
  }
}
```

```typescript
// 渲染进程侧：应用插件经 @chips/sdk 调用能力、订阅事件
import { chips } from '@chips/sdk';
import type { ISubscription } from '@chips/sdk';

export async function notifyExported(cardId: string): Promise<void> {
  await chips.request('notification:send', {
    title: '导出完成',
    body: `卡片 ${cardId} 已导出`,
  });
}

export function watchDocumentChanges(onChange: () => void): ISubscription {
  return chips.subscribe('document:changed', onChange);
}
```
