## 十一、错误模型

渲染错误统一为 `ChipsError`（`code` / `message` / `details?` / `retryable?`，见基准 5.3），错误码使用 `RENDER_` 前缀：

| 错误码 | 触发 | 可重试 | 用户可见表现 |
|---|---|---|---|
| `RENDER_DOCUMENT_INVALID` | 解析校验失败 | 否 | 卡片内显示损坏说明与文件路径提示 |
| `RENDER_PLUGIN_MISSING` | 找不到匹配角色的插件 | 否 | 占位卡片，提示安装对应插件 |
| `RENDER_PLUGIN_FAILED` | 插件渲染抛错 | 是 | 占位卡片 + 重试 |
| `RENDER_FRAME_TIMEOUT` | 握手或首帧超时 | 是 | 占位卡片 + 重试 |
| `RENDER_RESOURCE_DENIED` | 资源越权或权限被拒 | 否 | 资源位置显示权限说明 |
| `RENDER_SCHEMA_UNSUPPORTED` | 已装插件的版本策略、能力声明或 schema 与内容要求不匹配 | 否 | 占位卡片，提示升级插件 |
| `RENDER_SESSION_DISPOSED` | 会话已释放仍被调用 | 否 | 调用方错误，记录诊断 |
| `RENDER_UPDATE_FAILED` | `update(view, revision)` 更新失败（视图非法、帧更新异常） | 是 | 保留旧帧并提示重试，不产生半更新 |
| `RENDER_PROTOCOL_VIOLATION` | 帧消息违规 | 否 | 断开帧通道，占位降级 |

规则：错误信息面向用户的部分使用简体中文；诊断信息（`details`）结构化且不含敏感路径与字节内容；重试必须重走完整链路。
