## 四、渲染产物上传模型

### 4.1 原则

1. **渲染在客户端**：客户端把卡片渲染为自包含 HTML 目录（查看产物）并组装封面产物；服务器不执行渲染、不排队列、不重建、不清理过期产物。
2. **一次发布一个版本**：每次发布产生新的缓存版本（`cacheVersion`，个人服务器为会话 ID），产物对象键前缀为 `{cardId}/{cacheVersion}`；新版本发布后旧产物不再被引用（由后续发布或删除动作清理）。
3. **产物生命周期与作品一致**：服务器没有 TTL；产物要么随作品存在，要么随可见性切换/删除被清理（§4.8）。
4. **服务器不解释产物**：产物是存储与分发的字节集合；服务器只记录入口、文件数与大小，不理解 HTML 内容与样式（§9.2）。
5. **协议唯一**：控制面与数据面的会话语义（状态机、预签名与分片、对象角色与桶角色、恢复清单 schema、摘要校验、传输错误码）以[《卡片传输协议》](../../05-接口与契约/16-卡片传输协议.md)为唯一权威；本节只写个人服务器的模型、取值与发布行为。

### 4.2 上传会话

上传会话由 `card-transfer` 控制面创建（请求/响应字段与状态机见[《卡片传输协议》](../../05-接口与契约/16-卡片传输协议.md) §三）；个人服务器侧的取值与约束：

| 项 | 个人服务器取值 |
|---|---|
| `capabilities.renderArtifacts` | `true`：接受客户端渲染产物（这是个人服务器的正式发布模式） |
| `capabilities.rooms` | `false`：单用户形态没有房间归属；非空 `roomId` 一律拒绝 |
| `capabilities.multipart` | 部署能力：支持分片上传的部署声明 `true`；不支持时单对象以单次预签名 `PUT` 上传，超过部署上限在预签名阶段拒绝并给出上限 |
| `idempotencyKey` | 命中已存在会话直接复用；唯一约束覆盖整个服务器（无用户维度） |
| 会话有效期 | 部署参数 `UPLOAD_SESSION_TTL_MINUTES`（默认 60）；预签名有效期不超过会话剩余有效期 |
| `abort` | 会话置为 `cancelled`，不产生作品；已直传对象按 §4.8 处理 |

规则：客户端只能使用服务器在会话创建响应中声明为 `true` 的能力；请求与声明不符时服务器拒绝（`CARD_TRANSFER_RENDER_UNSUPPORTED` 等，映射见《卡片传输协议》§八）。

### 4.3 对象角色与桶路由

对象角色（`network-card` / `resource` / `render-file` / `cover-file` / `box-file`）与对象键模板以[《卡片传输协议》](../../05-接口与契约/16-卡片传输协议.md) §6.1 为准；个人服务器的路由规则：

| 角色 | 个人服务器路由 |
|---|---|
| `network-card` / `resource` | 由会话可见性决定访问策略（§6.2）；对象写入卡片资源桶 |
| `render-file` | 卡片可见性为公开 → 公开查看产物桶；私密 → 私有查看产物桶 |
| `cover-file`（卡片） | 卡片可见性为公开 → 公开封面产物桶；私密 → 私有封面产物桶 |
| `cover-file`（箱子） | 通用封面桶（公开读）；箱子封面不是卡片产物 |
| `box-file` | 箱子源文件桶（私有）；下载经短有效期预签名 |

规则：

1. 对象键由服务器生成并与会话绑定；客户端不得构造、拼接或跨会话复用对象键（《卡片传输协议》§6.3）。
2. 相对路径必须归一化（无 `..`、无反斜杠、无控制字符），服务器在预签名与提交两个阶段校验。
3. 桶角色与默认桶名以《卡片传输协议》§6.2 为唯一登记；个人服务器不启用头像桶（多用户形态），其余桶角色按产品需要启用；不得新增与既有角色职责重叠的第二套桶。

### 4.4 完成校验与发布

`complete` 是发布事务的收口动作。协议层校验（会话归属与状态、对象归属与大小、摘要与恢复清单校验）以[《卡片传输协议》](../../05-接口与契约/16-卡片传输协议.md) §3.6、§五为准；个人服务器在通过协议校验后按固定顺序发布：

```
[1] 校验对象归属与大小（network-card / resource / box-file 必须属于本会话）
[2] 校验摘要与恢复清单（摘要一致性、资源覆盖完整）
[3] 若提交 renderArtifacts：
        ├─ 本会话必须存在 render-file 预签名对象
        ├─ view.entryRelativePath（与 cover.entryRelativePath）必须是已预签名并上传的对象
        └─ 构造产物记录（入口 URL：公开直链 / 私密受控代理）
[4] 写入作品元数据：标题、file_id、封面比例、源对象、元数据与结构、资源清单
        ├─ 已提交产物 → status = ready，记录产物入口与接收时间
        └─ 未提交产物 → status = pending
[5] 会话置为已完成；返回作品 ID、版本与状态
```

规则：

1. `complete` 响应中的 `status` 为 `ready` 或 `pending`；`pending` 不是失败。
2. 产物入口必须在会话内预签名过，服务器不隐式信任客户端提交的任意 URL。
3. 服务器把产物入口写成公开直链或受控代理路由；私密产物的入口不泄露桶与对象键结构。
4. 提交 `renderArtifacts` 时按协议携带 `rendererVersion`（标识产物生成器），**不包含**主题标识与语言标识：主题系统与多语言系统已废止，渲染结果自包含，文案简体中文直写（[ADR-006](../ADR/ADR-006-主题系统与多语言系统.md)）。
5. 重新发布同一卡片会产生新作品版本（新缓存版本），旧产物在新版本发布后不再被卡片引用；产物清理见 §4.8。

### 4.5 产物记录模型

产物记录（`render_artifacts`）由两组对称的 profile 组成，本文只定义语义模型，线级字段以[《个人服务器 API 契约》](../../05-接口与契约/12-个人服务器API契约.md)为准：

| profile | 字段语义 |
|---|---|
| `view` | 缓存版本、逻辑桶、键前缀、入口对象键、入口 URL、文件数、总字节数 |
| `cover` | 同 `view`；封面缺失时整个 profile 不存在 |

规则：

1. `keyPrefix = {cardId}/{cacheVersion}`；入口对象键在其下，入口 URL 为公开直链或受控代理路由（§4.6）。
2. `rendererVersion` 记录在产物记录顶层，取值由客户端渲染器定义（如 `chips-client-renderer-1`），服务器不解释其内部含义。
3. 产物记录是服务器唯一认可的"可展示"依据：没有记录时作品不可打开（`pending` / `error`）。
4. 产物由客户端保证自包含：HTML 只引用本版本产物内的相对资源与已发布的卡片资源；服务器不做外链改写与内容安全扫描。

### 4.6 查看与私有代理

| 入口 | 行为 |
|---|---|
| `GET /api/v1/cards/{cardId}/view` | 有查看产物：302 重定向到入口 URL；无：`CARD_RENDER_NOT_READY`（状态冲突语义） |
| `GET /api/v1/cards/{cardId}/cover` | 有封面产物：302 重定向；无：返回 200 默认占位 HTML（不报错） |
| `GET /api/v1/cards/{cardId}/render-cache/{cacheVersion}/{path}` | 私有查看产物受控代理；校验 `cacheVersion` 与产物记录一致后流式读取 |
| `GET /api/v1/cards/{cardId}/cover-cache/{cacheVersion}/{path}` | 私有封面产物受控代理；规则同上 |
| `GET /api/v1/boxes/{boxId}/view` | 服务器生成的极简只读 HTML：标题、描述、条目链接列表（内嵌条目展示标签，服务器内卡片链接到卡片页） |
| `GET /api/v1/boxes/{boxId}/cover` | 有封面：302 到封面对象；无：返回封面占位 HTML |
| `GET /api/v1/boxes/{boxId}/download` | 返回箱子源文件预签名下载地址（短有效期，附件下载） |

规则：

1. 私有代理支持 `Range` 请求（视频等大文件流式播放），并做资产路径归一化，拒绝路径穿越（《卡片传输协议》§6.5）。
2. `cacheVersion` 不匹配时按 `NOT_FOUND` 处理，不泄露其他版本产物。
3. 重定向与下载地址都是短时有效的预签名或公开直链；除私有代理外服务器不做字节中转。
4. 读接口对已登录/未登录没有区别：公开作品对所有访客一致；端点与参数以[《个人服务器 API 契约》](../../05-接口与契约/12-个人服务器API契约.md)为准。

### 4.7 客户端发布链路

发布由 **Host 侧统一传输引擎**执行（协议与算法见[《卡片传输协议》](../../05-接口与契约/16-卡片传输协议.md)）；应用侧只负责选择源与发起任务。个人服务器场景的完整链路：

1. 从工作区取得归档态 `.card` / `.box` 交付物（[《工作区设计》](./13-工作区设计.md) §4.4）。
2. 传输引擎生成网络资源卡片：资源预签名直传，资源引用改写为对象存储/CDN URL，同时生成可逆恢复清单。
3. `includeRenderArtifacts` 控制两种发布模式：
   - `false`：只上传源文件与资源；服务器保持 `pending`（社区平台模式）；
   - `true`：调用 Host 内内容转换服务把卡片渲染为 HTML 目录，组装查看与封面产物，以 `render-file` / `cover-file` 角色预签名直传，并在 `complete` 提交产物摘要（个人服务器推荐模式）。
4. 箱子上传：散落卡片逐个走卡片上传链路，然后直传 `.box` 源文件与封面，并把 `includeRenderArtifacts` 透传给散落卡片。
5. 下载恢复：按下载计划取回网络资源卡片与资源，按恢复清单恢复原始相对路径并重新打包完整离线卡片。

约束：

1. 内容转换服务不可用时发布失败（`CARD_TRANSFER_RENDER_UNAVAILABLE`），不静默降级为服务端渲染——服务器没有渲染能力（《卡片传输协议》§八）。
2. 客户端不得把管理令牌写入工作区文档、文档内容或日志；令牌只存在于插件配置/凭证存储（[《配置系统设计》](./10-配置系统设计.md) §7.2）。
3. 发布是显式用户动作：上传不得在用户不知情时触发（[《同步引擎设计》](./07-同步引擎设计.md) §2.3 同类原则）。

### 4.8 清理与生命周期

| 动作 | 清理范围 |
|---|---|
| 可见性切换 | 删除该作品产物对象（`view` / `cover` 的 `keyPrefix` 全量），清空产物记录与入口，状态回到 `pending`；已发布到公开桶的资源对象不自动回收（§9.2） |
| 删除卡片 | 删除已发布资源与网络资源卡片对象、删除产物对象、删除数据库记录 |
| 删除箱子 | 删除源 `.box` 对象（封面对象在通用封面桶，由部署清理策略处理），删除数据库记录 |
| 会话过期 | 会话置为 `expired`；未完成上传的对象不产生作品，残留对象由部署侧存储生命周期规则处理（《卡片传输协议》§6.6） |
| 服务器 TTL | 不存在：产物无过期清理，服务器不重建、不回收未被引用的历史版本产物 |

规则：作品与产物是不可分割的发布结果；任何人不得只手删数据库记录或只删对象（会导致入口悬空）。恢复与一致性要求见 §8。
