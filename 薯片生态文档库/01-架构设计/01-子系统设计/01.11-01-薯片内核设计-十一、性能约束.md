## 十一、性能约束

### 11.1 指标与测量边界

| 指标 | 目标 | 测量边界 |
|---|---|---|
| 插件加载 | < 100 ms | 内核收到 `LoadRequest` 至 `plugin:loaded` 发布完成；不含包解压与校验（插件管理层负责）、不含插件业务初始化 |
| 服务调用 | < 1 μs | 已绑定服务句柄上的一次方法调用，或内核内一次服务查找；不含被调用方法的业务耗时 |
| 事件发布 | < 1 μs | `emit` 入口至全部监听器调用或入队完毕（含快照与调度）；Rust 监听器同步调用、JS 监听器仅入队，不含监听器与 JS 执行耗时 |
| 依赖解析 | O(N + E) | 与插件数 N、依赖边数 E 线性相关 |
| Context 销毁 | O(E) | 与副作用登记数量 E 线性相关 |

测量口径与 [09-事件系统设计.md](09-事件系统设计.md) 第六节一致；其余结构复杂度为架构性质，不作为门禁数值。

### 11.2 实现保障

- 服务查找：快照命中路径只做读锁与 `Arc::clone`；查找以 Context 祖先链为界，不遍历全表。
- 事件发布：无监听器时 `HashMap` 未命中直接返回，零分配；有监听器时只复制一次监听器桶。
- 加载：依赖解析增量计算；服务注册写时复制；apply 要求快速返回，耗时初始化由插件异步承担。
- 撤销：Fork 副作用以 `Vec` 顺序登记与逆序弹出，无中间分配。
- 内存：空 Context 与空 Fork 为常数级开销；监听表与依赖索引按需分配。
- 质量门禁：Clippy 无 warning，`unsafe` 附 `# Safety`，测试覆盖率 > 80%（引用《架构原则》与《超大型工程管理体系》）。

### 11.3 基准测试

关键路径必须提供 criterion 基准，纳入 CI 回归对比：

```rust
use criterion::{black_box, criterion_group, criterion_main, Criterion};

fn bench_service_get(c: &mut Criterion) {
    let kernel = Kernel::new();
    let ctx = kernel.root_context();
    let name = String::from("file");

    c.bench_function("service_get", |b| {
        b.iter(|| {
            let service = ctx
                .get(black_box(&name))
                .expect("file 服务已在根 Context 注册");
            black_box(service);
        });
    });
}

criterion_group!(benches, bench_service_get);
criterion_main!(benches);
```

基准覆盖：服务查找与绑定调用、事件发布（零监听器 / 单监听器 / 多监听器）、Fork 创建与撤销、依赖解析、1000 插件规模加载。
