## 七、服务注册表与依赖解析

### 7.1 注册表结构

```rust
/// 服务表：以 (Context, 服务名) 为键；写时复制后原子替换。
pub struct ServiceTable {
    entries: HashMap<(ContextId, ServiceName), ServiceEntry>,
}

/// 服务条目。
pub struct ServiceEntry {
    /// 服务名。
    pub name: ServiceName,
    /// 服务值。
    pub value: ServiceValue,
    /// 提供方插件 ID。
    pub provider: PluginId,
    /// 提供方 Fork。
    pub fork: ForkId,
    /// 代际；每次替换递增。
    pub generation: u64,
}

/// 服务注册表。
pub struct ServiceRegistry {
    /// 只读快照；写路径复制后替换指针。
    snapshot: RwLock<Arc<ServiceTable>>,
    /// (提供方 Fork, 代际, 服务名) → 受影响注入集合（反向依赖索引）。
    dependents: RwLock<HashMap<(ForkId, u64, ServiceName), BTreeSet<InjectionId>>>,
}
```

- 读路径：持有读锁获取 `Arc<ServiceTable>` 快照并立即释放锁，随后查询快照。
- 写路径：复制当前表、修改副本、原子替换指针；服务表规模有限，写操作稀少。
- 反向依赖索引以 `(ProviderFork/Generation, ServiceName)` 为键：记录该代际被哪些注入消费；服务替换、停用与卸载时精确反查受影响注入，只有受该代际影响的注入才重建（5.4）；旧代际条目随旧条目失效一并清理。

### 7.2 依赖图与拓扑序

```rust
/// 依赖声明。
pub struct DependencySpec {
    /// 被依赖的插件 ID。
    pub id: PluginId,
    /// 版本范围（语义化版本，规则见 04-版本与迁移规范）。
    pub range: VersionRange,
}

/// 依赖图节点。
pub struct PluginNode {
    /// 插件 ID。
    pub id: PluginId,
    /// 插件版本。
    pub version: Version,
    /// 依赖声明集合。
    pub dependencies: Vec<DependencySpec>,
}
```

- 拓扑序定义：若 A 依赖 B，则 B 排在 A 之前；加载按序执行，卸载按逆序执行。
- 静态依赖图在加载请求阶段构建；服务级消费关系在运行时补充进反向索引。
- 图变更（加载/卸载）后重新计算受影响子图的顺序，不做全图重算。

### 7.3 环检测

采用三色标记的迭代式深度优先遍历，不使用递归，避免大规模插件的栈溢出；发现 `Visiting` 节点重复访问即判定成环，并返回环路径。

```rust
#[derive(Clone, Copy, PartialEq, Eq)]
enum VisitState {
    Unvisited,
    Visiting,
    Done,
}

/// 计算依赖拓扑序：被依赖者在前，依赖方在后。
///
/// 图构建与版本检查不在此函数内；只处理顺序与环检测。
pub fn resolve_order(graph: &DependencyGraph) -> Result<Vec<PluginId>, KernelError> {
    let mut states: HashMap<&str, VisitState> = graph
        .ids()
        .map(|id| (id.as_str(), VisitState::Unvisited))
        .collect();
    let mut order: Vec<PluginId> = Vec::with_capacity(states.len());

    for root in graph.ids() {
        if states[root.as_str()] == VisitState::Done {
            continue;
        }
        let mut stack: Vec<(&str, usize)> = vec![(root.as_str(), 0)];
        states.insert(root.as_str(), VisitState::Visiting);

        while let Some((current, edge)) = stack.pop() {
            let dependencies = graph.dependencies_of(current);
            match dependencies.get(edge) {
                Some(next) => {
                    stack.push((current, edge + 1));
                    match states[next.as_str()] {
                        VisitState::Visiting => {
                            let start = stack
                                .iter()
                                .position(|(id, _)| *id == next.as_str())
                                .map_or(0, |index| index);
                            let mut path: Vec<PluginId> = stack[start..]
                                .iter()
                                .map(|(id, _)| (*id).to_owned())
                                .collect();
                            path.push(next.clone());
                            return Err(KernelError::DependencyCycle { path });
                        }
                        VisitState::Done => {}
                        VisitState::Unvisited => {
                            states.insert(next.as_str(), VisitState::Visiting);
                            stack.push((next.as_str(), 0));
                        }
                    }
                }
                None => {
                    states.insert(current, VisitState::Done);
                    order.push(current.to_owned());
                }
            }
        }
    }

    Ok(order)
}
```

### 7.4 缺失与版本检查

在环检测前后各做一次线性检查，保证报错优先级稳定：

| 检查 | 条件 | 内核处理 | 错误码 |
|---|---|---|---|
| 缺失依赖 | 依赖的插件 ID 不在图中 | 停留在 `Pending`，等待依赖安装 | `KERNEL_DEPENDENCY_MISSING` |
| 自依赖 | 依赖 ID 等于自身 | 拒绝加载 → `Failed` | `KERNEL_DEPENDENCY_CYCLE`（环路径为单节点） |
| 版本暂不满足 | 已安装提供方版本不在声明范围内，但存在可满足范围的候选版本 | 停留在 `Pending`，等待依赖更新 | `KERNEL_DEPENDENCY_VERSION` |
| 版本不可满足（互斥） | 已安装候选版本集合与声明范围无交集 | 拒绝启用 → `Failed`，`details` 附双方范围与候选版本列表 | `KERNEL_DEPENDENCY_VERSION` |
| 重复声明 | 同一插件重复声明同一依赖 | 拒绝加载 → `Failed` | `KERNEL_DEPENDENCY_DUPLICATE` |

- 版本互斥是显式冲突，不静默 `Pending`：插件不会无限等待一个永远无法满足的范围；用户处理依赖版本后可通过 `enable` 重试。
- 依赖插件完全缺失时优先报 `KERNEL_DEPENDENCY_MISSING`（等待安装），只有提供方已安装但范围无交集时才判定互斥。
- 版本范围语义与比较规则引用 [04-版本与迁移规范.md](../../04-文件格式规范/04-版本与迁移规范.md)，内核不重复实现版本工具链。

### 7.5 依赖失效传播

| 触发 | 传播动作 | 结果 |
|---|---|---|
| 提供方 `disable`（存在 `Active` 依赖者） | 未显式级联则拒绝；显式级联按逆拓扑序停用依赖者 | 拒绝：`KERNEL_DEPENDENCY_CONFLICT`；级联：全部进入 `Installed` |
| 提供方 `unload`（存在依赖者） | 始终拒绝，须先卸载依赖者 | `KERNEL_DEPENDENCY_CONFLICT` |
| 提供方 `Failed` | 依赖方不自动停用；服务条目摘除，注入回到 `Waiting`，调用返回 `KERNEL_SERVICE_NOT_FOUND` | 依赖方保持 `Active`，等待提供方恢复 |
| 提供方恢复 `Active` | 服务重新注册，注入回调按拓扑序重建 | 依赖方恢复正常 |
| 服务代际替换 | 按 `(ProviderFork/Generation, ServiceName)` 反查并撤销受影响注入 Fork，按拓扑序重建 | 消费方保持 `Active`，回调重建 |
| 提供方任务 panic | 提供方进入 `Failed`（不回滚其他插件） | 依赖方保持 `Active`，服务不可用期间按上表处理 |
| 重建深度超过 16 | 中止本轮级联重建 | 受影响注入保持 `Waiting`，上报 `KERNEL_REBUILD_OVERFLOW` |
