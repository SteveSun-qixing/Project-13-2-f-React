## 七、箱子渲染

### 7.1 箱子布局插件装载

1. 由 `BoxRenderView.active_layout_type` 查询声明了该 `layouts.id` 的 `boxlayout` 插件（角色过滤规则见 ADR-005）。
2. 校验 `BoxRenderView.chip_standards_version` 与平台支持范围，规则同第 6.1 节。
3. 创建顶层布局帧并注入：`role: 'box-layout'`、`view`（含 `entries` 与 `layout_config`）、`pluginEntries`（以 `active_layout_type` 为键）、`resourceBase`（箱子作用域）、`tokens`、`limits`。
4. 箱子布局插件在 `renderLayout(box, container)` 中决定槽位、排序呈现与滚动容器结构；渲染引擎不预设任何布局算法。

### 7.2 entries 的消费

- 布局帧拿到的是 `EntryView` 列表，不含条目文件字节；条目目标的解析结果由 RenderHost 依需下发。
- 布局帧按可见范围发送 `frame:entry-request`，RenderHost 返回 `EntryTicket`：

```typescript
interface BoxCoverView {
  kind: 'box';
  box_id: string;
  name: string;
  chip_standards_version: string;
  cover: CoverView;                            // .box/cover.html
}

interface EntryTicket {
  entry_id: string;
  slotIndex: number;
  view: CardRenderView | BoxCoverView;         // 条目目标视图，按 kind 判别
  resourceBase: string;                        // 条目目标文档自身作用域
  pluginEntries: Readonly<Record<string, string>>; // 条目目标视图的插件入口；箱子目标为空对象
  estimatedHeight: number;                     // 箱子布局插件用于槽位估算
}
```

- 条目可引用卡片或箱子：`view.kind` 为 `'card'` 时为卡片文档视图；为 `'box'` 时为被引用箱子的封面视图，一律按正式封面呈现，不展开其布局、不递归展开（第 7.5 节）。条目封面统一经平台**受控封面渲染接口**取得（返回 `{ title, coverUrl, ratio? }`，命名与[01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md) §7.3、[02-箱子文件格式](../../04-文件格式规范/02-箱子文件格式.md) §9.3 一致），渲染层不自行推断封面资源。
- 箱子目标的 `pluginEntries` 为空对象：条目帧不装载布局插件；`resourceBase` 为箱子包作用域，`view.cover.entry` 即该作用域下 `.box/cover.html` 的受控封面 URL。
- RenderHost 只下发可见范围 ± overscan（默认 2）内的 ticket；滚动过程中由布局帧再次请求增量。
- 箱子布局插件不得自行读取条目文件、不得解析 YAML、不得跳过 RenderHost 直接创建非受管 iframe；条目帧必须由布局帧按协议创建。
- 条目解析失败（文件缺失、格式损坏）时，RenderHost 仍返回 ticket 并携带错误状态，布局帧渲染条目级降级占位，不影响整箱。

### 7.3 条目帧的创建与生命周期

```
布局帧                                   条目帧
   │ 创建 iframe(sandbox=allow-scripts)      │
   │ 首条 postMessage（令牌 + MessagePort）   │
   │────────────────────────────────────────▶│
   │ host:init（按 ticket 组装的视图与资源）   │
   │────────────────────────────────────────▶│
   │                         frame:ready      │
   │◀────────────────────────────────────────│
   │                         frame:height     │
   │◀────────────────────────────────────────│
   │ 布局重排 → 汇总总高度 → 上报 RenderHost   │
```

条目帧仍为受管帧，协议完整（握手、`host:init`、高度上报）；帧运行时按 `view.kind` 渲染：`card` 沿用卡片文档视图（基础卡片插件装载与执行，`nodes[]` 与 `view.content_nodes` 逐项对应、逐节点独立容器）；`box` 以受控封面 URL `view.cover.entry`（目标箱子作用域）在帧内装载封面文档（`sandbox="allow-scripts"`），封面呈现后经 `frame:height` 上报高度；不加载布局插件、不创建子帧。

- 条目帧只与直接父帧（布局帧）通信；高度由父帧聚合，不逐条上报顶层。
- 布局帧上报 `frame:entry-request` 时声明 `requestId` 与 `firstVisible` / `lastVisible`；RenderHost 在 `host:entries` 中原样回带 `requestId`，与箱子布局插件共同保证槽位数与 ticket 数一致。
- 帧销毁由布局帧触发（滚出 overscan、条目删除、箱子关闭）；销毁流程：`host:dispose` → `frame:dispose-ack` → 端口关闭 → iframe 移除 → 帧池归还（第 10.4 节）。
- 高度缓存按 `entry_id + url 摘要` 保留，重新进入视口时直接使用上次高度，减少抖动。

### 7.4 布局编辑面板

- 编辑态下，布局配置编辑由箱子布局插件 `renderEditor` 提供，经编辑链路的 `IEditSession` 与 `IPluginRuntime` 门面（`loadLayout(layoutType)`）就近挂载（第 8 节、[12-编辑引擎设计](./12-编辑引擎设计.md)），不创建额外渲染帧。
- 布局编辑产生的新 `layout_config` 由编辑链路组装为新的 `BoxRenderView`，在 `document:write` 成功后经会话 `update(view, revision)` 回流（编辑面板就近挂载，不经过帧消息）。
- 布局帧自身在编辑态与查看态使用同一 `renderLayout` 实现；编辑面板只改配置，不改渲染管线。

### 7.5 嵌套与深度

- 渲染帧树最大深度为 2：箱子布局帧（深度 1）+ 条目帧（深度 2）。
- 条目可引用卡片或箱子（格式约束见[02-箱子文件格式](../../04-文件格式规范/02-箱子文件格式.md)）；箱子条目一律按其正式封面（`.box/cover.html`）呈现，不展开其布局、不递归展开（一次进入即可）；条目帧对箱子目标仅渲染封面，不装载布局插件、不创建子帧。条目引用目标的合法性由解析链路诊断（`ENTRY_SOURCE_INVALID` / `ENTRY_TARGET_MISSING` / `ENTRY_FAILED`），渲染层不因条目引用箱子而降级。
- 卡片帧 `maxNestedFrames = 0`，不得创建任何子帧；布局帧 `maxNestedFrames` 为当前可见槽位数上限。
