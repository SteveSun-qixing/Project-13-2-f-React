## 二、总体架构

### 2.1 运行形态

```
薯片客户端（Host 传输引擎 + 内容转换服务）
  │  网络资源卡片、资源对象、渲染产物（预签名直传对象存储）
  ▼
个人服务器 API（Fastify 单进程）
  ├── PostgreSQL：作品元数据、上传会话、恢复清单（权威元数据）
  └── S3 / MinIO：源文件、资源、渲染产物（权威字节）
        ▼
Web 前端（Vite SPA，只读）→ 浏览器加载查看产物
```

| 能力 | 归属 |
|---|---|
| 卡片与箱子制作、渲染 | 客户端 Host |
| 渲染产物生成与上传 | 客户端传输引擎 + 服务器上传会话控制面 |
| 元数据、状态、签名、下载计划 | 个人服务器 API |
| 文件字节 | 对象存储 |
| 页面展示 | 个人服务器 Web 前端 |
| 箱子查看文档 | 服务器生成极简只读 HTML（条目链接列表）；**不是**箱子的布局渲染 |

服务器不解析 `.card`：卡片元数据由客户端在 `complete` 提交；服务器也不解包 `.box`，箱子查看文档使用客户端提交的 `structure` 条目模型（§4.4）。服务器不存在第二解析器与第二渲染管线（[《文档解析器设计》](./06-文档解析器设计.md)、[《渲染引擎设计》](./05-渲染引擎设计.md)）。

### 2.2 模块划分

**服务端**（`packages/server/src/`）：

| 模块 | 职责 |
|---|---|
| `app.ts` | 组装 Fastify：Helmet、CORS、Swagger（可关）、错误处理、令牌插件与四组路由 |
| `config/` | 环境变量 schema 校验与加载（`deploy/.env`）；校验失败拒绝启动 |
| `db/` | Drizzle 客户端、schema 与迁移；启动时自动执行迁移 |
| `errors/` | `AppError` 工厂与错误码常量（§十） |
| `plugins/` | `error-handler`（统一错误响应）、`api-token`（常量时间令牌校验） |
| `routes/` | `health`、`cards`、`boxes`、`card-transfer` 四组路由 |
| `schemas/` | 请求体与查询参数 zod schema |
| `services/` | 业务服务：卡片、箱子、上传会话 |
| `storage/` | S3 客户端、逻辑桶定义、公开读策略与启动初始化 |

**Web 前端**（`packages/web/src/`）：`pages/`（主页、关于、客户端发布、卡片详情、箱子详情）、`components/`（页头、页脚、作品网格与作品磁贴）、`api/`（只读 API 客户端）。

**部署**（`deploy/`）：`Dockerfile.server`、`Dockerfile.web`、`docker-compose.yml`、`docker-compose.prod.yml`、`nginx/`、`certs/`；本地开发脚本为 `scripts/start-local-dev.sh`（§八）。

### 2.3 与平台和客户端的关系

| 关系 | 规则 |
|---|---|
| 与平台运行时 | 个人服务器不在平台进程内，不加载 Cordis、不注册能力、不接收事件；平台侧无对应插件 |
| 与工作区 | 服务器不访问用户工作区；发布输入是客户端准备好的归档态交付物（[《工作区设计》](./13-工作区设计.md) §4.4） |
| 与传输引擎 | 发布与下载由 Host 侧统一传输引擎执行（[《卡片传输协议》](../../05-接口与契约/16-卡片传输协议.md)）；服务器只做事务与校验 |
| 与社区平台 | 共用文件格式、传输协议与内容模型；差异集中在用户体系、渲染与部署（§七） |
| 与同步引擎 | 发布不是同步：个人服务器不是同步提供者，不参与工作区同步清单与冲突解决（[《同步引擎设计》](./07-同步引擎设计.md)） |
| 与主题/多语言 | 产物由客户端渲染为自包含 HTML；服务器不承载主题与语言标识（[ADR-006](../ADR/ADR-006-主题系统与多语言系统.md)） |
