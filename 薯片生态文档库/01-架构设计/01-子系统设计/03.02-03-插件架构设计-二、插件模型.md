## 二、插件模型

### 2.1 插件的组成

插件是薯片平台最小的可分发、可独立更新的功能单元，由三部分组成：

| 组成 | 说明 |
|---|---|
| `manifest.yaml` | 唯一权威清单：标识、版本、角色、依赖、权限、角色能力 |
| 入口模块 | 实现该角色接口的 JavaScript 代码 |
| 静态资源 | 图标、模板等随包资源 |

三者以 `.cpk`（ZIP Store）分发；开发态允许以目录形式加载。插件是独立代码仓库，独立版本管理与独立发布（ADR-005、ADR-010）。

### 2.2 四种角色

```
薯片平台
├── basecard   基础卡片插件 ── 定义卡片类型
├── boxlayout  箱子布局插件 ── 定义箱子布局
├── app        应用插件 ───── 独立窗口应用
└── service    服务插件 ───── 无界面后台能力
```

| 角色 | `type` | 入口接口 | 核心职责 | 界面形态 |
|---|---|---|---|---|
| 基础卡片插件 | `basecard` | `IBaseCardPlugin` | 定义卡片类型，提供查看渲染、编辑渲染、配置校验、导出 | 嵌于宿主视图（iframe） |
| 箱子布局插件 | `boxlayout` | `IBoxLayoutPlugin` | 定义箱子布局，提供布局渲染、布局编辑、配置校验 | 嵌于宿主视图（iframe） |
| 应用插件 | `app` | `IAppPlugin` | 独立窗口应用：启动器、文件关联、命令、文件打开 | 独立窗口（`ui.surface`） |
| 服务插件 | `service` | `IServicePlugin` | 后台常驻服务，可注册服务与能力，提供健康检查 | 无 UI |

- `manifest.type` 决定入口接口与生命周期入口；一个插件只有一个 `type`。
- 角色不是功能分类：任意领域的功能都可以分别以四种角色承载（ADR-005）。
- 内核不感知角色：四类角色共用同一套加载、依赖与生命周期机制；角色差异由插件管理层与接口层承担（[01-薯片内核设计](01-薯片内核设计.md) §六）。

### 2.3 角色职责

#### 2.3.1 基础卡片插件 `basecard`

职责：

1. 定义卡片类型（`capabilities.cardTypes`）：类型 ID、名称、图标、支持的文件扩展名。
2. 查看渲染 `renderView(view: BaseCardView, container: HTMLElement)`。
3. 编辑渲染 `renderEditor(view: BaseCardView, container: HTMLElement): IBaseCardEditor`。
4. 配置校验 `validateConfig(config): boolean`。
5. 可选导出 `export(basecard, format): Promise<Blob>`。

生命周期行为：

- 启用：把 `cardTypes` 注册到插件注册表；不创建窗口、不渲染内容。
- 运行：渲染引擎与编辑链路按需选择插件并调用 `renderView` / `renderEditor`；返回的视图释放句柄与 `IBaseCardEditor` 实例由调用方在视图关闭时释放（编辑链路见 [12-编辑引擎设计](12-编辑引擎设计.md)）。
- 停用：注销 `cardTypes`；该类型的已打开视图被销毁并显示内容不可用提示（数据已持久化在文件中，不丢失）；新的渲染请求被拒绝。

```yaml
id: chips.basecard.richtext
type: basecard
capabilities:
  cardTypes:
    - id: base.richtext
      name: 文本卡片
      icon: assets/icons/richtext.svg
```

完整接口定义见 [08-基础卡片插件接口](../../05-接口与契约/08-基础卡片插件接口.md)。

#### 2.3.2 箱子布局插件 `boxlayout`

职责：

1. 定义布局（`capabilities.layouts`）：布局 ID、名称、图标、描述。
2. 布局渲染 `renderLayout(view: BoxRenderView, container: HTMLElement)`。
3. 布局编辑 `renderEditor(view: BoxRenderView, container: HTMLElement): ILayoutEditor`。
4. 配置校验 `validateConfig(config): boolean`。

生命周期行为：

- 启用：把 `layouts` 注册到插件注册表。
- 运行：渲染引擎按箱子的 `active_layout_type`（来自 `.box/metadata.yaml`，对应配置取自 `.box/content.yaml` 的 `layout_configs`）选择布局插件并调用 `renderLayout`；布局切换只改变呈现方式，不修改箱子数据（ADR-005）。
- 停用：注销 `layouts`；使用该布局的已打开箱子视图被销毁并显示内容不可用提示。

```yaml
id: chips.layout.grid
type: boxlayout
capabilities:
  layouts:
    - id: chips.layout.grid
      name: 网格布局
      icon: assets/icons/grid.svg
```

完整接口定义见 [09-箱子布局插件接口](../../05-接口与契约/09-箱子布局插件接口.md)。

#### 2.3.3 应用插件 `app`

职责：

1. 提供独立窗口应用，窗口形态由 `ui.surface` 决定（`window | desktop | tray`）。
2. 注册启动器入口 `ui.launcher`（图标、名称、描述）。
3. 声明文件关联 `fileAssociations`（扩展名 → 动作）。
4. 实现 `launch(ctx: IAppContext)`；可选实现 `handleCommand(command, args)` 与 `openFile(uri)`。

生命周期行为：

- 启用：注册启动器与文件关联；不创建窗口。
- 运行：用户从启动器启动、经文件关联打开或命令触发时，平台调用 `launch` / `openFile` / `handleCommand`；应用窗口及其副作用归入该插件 Fork。
- 停用：先允许应用处理未保存状态，再关闭其全部窗口，最后 `dispose()`。

```yaml
id: chips.official.editor
type: app
ui:
  surface: window
  launcher:
    icon: app-icon.svg
    name: 编辑引擎
fileAssociations:
  - extensions: [.card]
    action: open
```

完整接口定义见 [07-应用插件接口](../../05-接口与契约/07-应用插件接口.md)。

#### 2.3.4 服务插件 `service`

职责：

1. 后台常驻运行，无 UI。
2. 执行载体：主进程内由 ModuleLoader 受管加载；需要进程级隔离的服务逻辑由工具进程承载（§5.2）。
3. 实现 `start(ctx: IServiceContext)`、`stop()`，可选实现 `health(): Promise<boolean>`。
4. 激活期间可注册服务供其它插件注入消费，或注册能力供 Bridge 调用。
5. 可声明 `runtime.background: true` 与 `healthCheck`（检查间隔与超时），平台据此进行健康检查。

生命周期行为：

- 启用：调用 `start(ctx)`；服务与能力注册进入暂存代际，插件进入 `active` 时一次原子发布生效（[01-薯片内核设计](01-薯片内核设计.md) 5.2）。
- 运行：平台按 `healthCheck` 周期调用 `health()`；连续不健康触发熔断与停用（§9.1）。
- 停用：调用 `stop()`；已注册的服务、能力、订阅随 Fork `dispose()` 一并撤销。

```yaml
id: chips.service.sync
type: service
runtime:
  targets: [host]
  background: true
healthCheck:
  interval: 30s
  timeout: 5s
```

完整接口定义见 [10-服务插件接口](../../05-接口与契约/10-服务插件接口.md)。

### 2.4 单角色约束

- `manifest.type` 是单一值；一个插件包内的入口只能实现一种角色接口。
- 禁止在运行期按分支在多个角色间切换行为，禁止一个包注册多种角色。
- 需要多角色能力时按下文 §7.4 拆分，用 `dependencies` 组合。
