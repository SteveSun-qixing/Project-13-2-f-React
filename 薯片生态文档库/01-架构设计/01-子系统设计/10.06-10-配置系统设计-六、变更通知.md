## 六、变更通知

### 6.1 事件载荷

配置变更以 `config:changed` 事件发布，事件模型、投递与退订机制见 [事件系统设计](./09-事件系统设计.md)，事件契约登记见 [事件契约规范](../../05-接口与契约/05-事件契约规范.md)。

```typescript
type ConfigLayer = 'platform' | 'user' | 'workspace' | 'plugin';

type ConfigOrigin =
  | 'platform'
  | 'migration'
  | 'external'
  | `plugin:${string}`;

interface ConfigChangedPayload {
  key: string;                // 完整配置键
  layer: ConfigLayer;         // 本次变化影响的层
  value: unknown;             // 该层当前值；null 表示该层覆盖被移除
  effectiveValue: unknown;    // 变化后的生效值
  isDefault: boolean;         // 生效值是否来自 schema 声明默认值
  origin: ConfigOrigin;       // 变更来源；插件写入为 plugin:<pluginId>
}
```

`layer` 取值语义：`platform` / `user` / `workspace` 分别对应三个文件层；`plugin` 表示插件 schema 声明的默认值层。写入与删除事件的 `layer` 为被写入的层；迁移、外部采纳与工作区切换事件的 `layer` 为变化后生效值所在层。

### 6.2 触发时机

- 写入或删除提交成功后：每个发生实际存储变化的键各发一次事件。
- 同层写入与现值相同的值不落盘、不发事件（见 2.3）。
- 写入值不同于现值、但被更高层遮蔽导致生效值未变化时，事件仍按发生变化的层发送，订阅者以 `effectiveValue` 判断是否需要响应。
- 重置导致覆盖被移除时：`layer` 为被移除覆盖的层，`value` 为 `null`，`effectiveValue` 为回落后的值，`isDefault` 标记是否回落到默认值。
- 迁移完成后：按键发送，`origin` 为 `migration`。
- 外部文件修改被采纳后：`origin` 为 `external`。
- 工作区切换后：生效值发生变化的键逐一发送，`origin` 为 `platform`，`layer` 为变化后生效值所在层。

### 6.3 可见性与作用域

- `platform` 命名空间的事件对持有 `config:read:platform` 的插件可见。
- `plugins.<pluginId>` 命名空间的事件只对该插件与平台可见。
- 插件卸载时，其订阅由 Bridge 按 Fork 语义统一撤销（见 [事件系统设计](./09-事件系统设计.md)），配置系统无需感知。

### 6.4 投递顺序

- 同一键的事件按提交顺序投递；跨键不保证全序。
- 事件异步投递，`config:set` 返回表示已持久化完成，事件可能晚于返回值到达；订阅者以事件载荷中的 `effectiveValue` 为准。
- 事件载荷不携带凭证材料或未脱敏信息。
