## 十三、文档创建链路

### 13.1 定位与唯一写口

- 文档创建链路把「新建卡片 / 新建箱子」表达为一次受控写操作：入口在应用侧，写入在平台侧，产物是工作区中的新文档（卡片为目录态 `<名称>.card/`，箱子为归档态单文件 `<名称>.box`）。
- 创建的唯一执行能力是 `document:create`（能力契约登记见 [04-能力契约规范](../../05-接口与契约/04-能力契约规范.md) §7.3，服务端实现设计见 [11-文档服务设计](./11-文档服务设计.md)）：初始模型装配、文档标识生成、命名落地、校验与原子写入全部在受控写口内完成。
- 编辑链路与应用插件的职责只到「归一创建请求」与「创建成功后打开会话」：不拼装 `.card` / `.box` 内容、不生成 `card_id` / `box_id`、不自行命名落盘、不直写文件系统（R8、§十）。
- 本链路与[《工作区设计》](./13-工作区设计.md) §四的 `document:export` 两态转换职责不同：创建产生新文档；导出 / 另存转换既有文档的形态，不改变源文档。
- 创建是「新建」，不是「导入」：外部文件拖入工作区建卡（类型匹配、批量、冲突命名与资源纳入）以[《拖动与拖放交互规范》](../../08-产品与交互/02-拖动与拖放交互规范.md) §6 为准，不进入本链路。

### 13.2 入口归一

所有入口收敛到同一次 `document:create` 请求；应用侧只做上下文归一，不产生第二种创建路径：

| 入口 | 上下文 | 归一点 |
|---|---|---|
| 文件面板工具栏「新建卡片 / 新建箱子」、命令 `editor:new-card` / `editor:new-box` | 面板当前目录；不带类型 | 落点 = 当前目录；类型 / 布局取默认（§13.3） |
| 画布空白 / 主区空白右键菜单「新建卡片 / 新建箱子」（二级类型 / 布局列表） | 无目录上下文；指定类型 / 布局 | 落点 = 工作区根；类型 / 布局 = 所选值 |
| 卡箱库拖拽到画布空白 / 主区空白 | 指定类型 / 布局；窗口落点为释放点 | 落点 = 工作区根；窗口位置随释放点（[08/01](../../08-产品与交互/01-编辑引擎产品与交互设计.md) §4.3） |
| 工作区空态「新建卡片 / 新建箱子」 | 无目录上下文 | 落点 = 工作区根；类型 / 布局取默认 |

规则：

1. 入口只消费命令视图（`editor:new-card` / `editor:new-box`），菜单、快捷键、空态与命令面板共用同一命令记录（[13-命令系统契约](../../05-接口与契约/13-命令系统契约.md) §5）。
2. 创建请求的语义字段：`kind`（`card` / `box`，必需）、`parent`（目标父目录受管引用，必需）、`name`（文档名，可选，缺省按 §13.4 命名）、`initialContent`（可选装配提示：`cardType` / `layoutType`）；字段与 JSON Schema 以 [04-能力契约规范](../../05-接口与契约/04-能力契约规范.md) §7.3 的 `document:create` 契约为唯一权威，本节不重复定义。
3. 入口在提交前必须完成本地前置校验（类型 / 布局插件已安装并启用、落点可写）；前置校验失败即取消，不发起能力调用、不产生半成品。
4. 拖拽创建与「向既有卡片插入节点」的落点语义区分以 [08/02](../../08-产品与交互/02-拖动与拖放交互规范.md) §3、§4 为准。

### 13.3 初始内容装配

初始模型由 `document:create` 在受控写口内一次装配完成，不存在「先建空文档再回流插入」的中间态：

| 产物成员 | 卡片 | 箱子 | 装配方 |
|---|---|---|---|
| 文档标识 | `card_id` | `box_id` | 文档服务（[05-ID生成规范](../../04-文件格式规范/05-ID生成规范.md) §四） |
| 名称 | `name` | `name` | 请求 `name`；缺省规则见 §13.4 |
| 标准版本 | `chip_standards_version` | `chip_standards_version` | 平台当前支持的正式版本（[04-版本与迁移规范](../../04-文件格式规范/04-版本与迁移规范.md)） |
| 初始结构 | 一个初始节点（`structure` + `content/*.yaml` 成员） | 空条目集合（`structure`） | 受控写口；节点标识按 05-ID生成规范 §四的唯一生成责任生成 |
| 初始节点内容 | 插件 `createInitialContent()` 初值 | — | 基础卡片插件（[08-基础卡片插件接口](../../05-接口与契约/08-基础卡片插件接口.md) §2.4.4） |
| 生效布局 | — | `active_layout_type` + `layout_configs` 初始项 | 受控写口；布局配置初值按插件的空配置默认（[09-箱子布局插件接口](../../05-接口与契约/09-箱子布局插件接口.md) §五、§七） |
| 封面与元数据 | `cover_ratio` 缺省 `3:4`、`cover.html` 为初始封面 | `cover.html` 为初始封面 | 受控写口（[01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md) §七） |

规则：

1. 卡片初始节点类型取请求 `initialContent.cardType`；未指定时取编辑引擎应用配置 `plugins.chips.official.editor.defaultCardType`（默认 `base.richtext`，§8.5）；该类型插件未安装 / 未启用时创建失败并提示安装，不静默替换类型。
2. 箱子初始布局取请求 `initialContent.layoutType`；未指定时取 `chips.layout.grid`；该布局插件未安装 / 未启用时创建取消并提示先安装布局插件（[08/01](../../08-产品与交互/01-编辑引擎产品与交互设计.md) §6.3）。
3. 初始节点内容必须通过该类型插件的 `configSchema` 与 `validateConfig`；不通过即创建失败，不落半成品（[08-基础卡片插件接口](../../05-接口与契约/08-基础卡片插件接口.md) §七）。
4. 内容初值只有插件纯函数一个来源：应用、编辑链路与文档服务都不得内置任何卡片类型的默认内容；插件不得生成或指定文档标识与节点标识。
5. 初始结构与内容成员在同一次受控写入中一致落盘，不允许出现「结构已引用、内容缺失」的中间状态。

### 13.4 落点与命名

- 落点：`parent` 为工作区内目录受管引用（各入口按 §13.2 归一，工作区根由调用方显式传入），必须可写；写入权限按目标作用域 `resources:write` 判定（[08-权限系统设计](./08-权限系统设计.md) §4.3）。
- 形态：卡片创建为目录态 `<名称>.card/`（编辑工作形态）；箱子创建为归档态单文件 `<名称>.box`。新建不产生归档态卡片，也不产生解包保留目录。
- 命名：`name` 缺省为「未命名卡片」/「未命名箱子」；同名冲突由平台自动追加 `-2`、`-3` 后缀（`未命名卡片.card` → `未命名卡片-2.card`）；名称规则与保留前缀拒绝同[《工作区设计》](./13-工作区设计.md) §3.3，落点在保留区返回 `WORKSPACE_RESERVED_PATH`，不询问、不覆盖既有文件。
- 命名与标识分离：`card_id` / `box_id` 创建时生成，与文件名无关；重命名只改文件名，不改变文档标识与内部引用。

### 13.5 创建后打开

- `document:create` 成功后返回新文档的 `{ documentId, source }`；应用必须用返回的 `source` 经 `IEditEngine.open`（§3.1）建立编辑会话，不得靠扫描目录再取路径。
- 打开即进入编辑态：卡片窗口为预览 + EditorHost；箱子窗口为预览 + 布局编辑面板（§8.2）。
- 窗口落点：卡箱库拖拽创建时窗口落在释放点（无限画布世界坐标）或主区激活位置（[08/01](../../08-产品与交互/01-编辑引擎产品与交互设计.md) §4.3）；其余入口按当前布局模式的默认窗口位置（[08/01](../../08-产品与交互/01-编辑引擎产品与交互设计.md) §五）。
- 性能：创建到可编辑的预算与打开卡片一致（< 100ms，§8.7）；首帧由会话预览渲染承担，不额外创建查看帧。
- 打开失败时新文档已落盘：按 §九的打开失败处理，不自动删除已创建文档；用户可经 `file:delete` 删除，或保留后稍后打开。

### 13.6 失败与降级

| 场景 | 语义 |
|---|---|
| 类型 / 布局插件缺失或未启用 | 入口前置校验或创建请求被拒；取消创建并提示安装 / 启用，不发起写入 |
| 初始内容 `configSchema` / `validateConfig` 失败 | 创建失败，返回创建错误（错误族由 `document:create` 契约登记）；不落半成品 |
| 落点非法（保留前缀、保留区、不可写） | 按工作区 / 权限错误返回（`WORKSPACE_RESERVED_PATH`、`BRIDGE_PERMISSION_DENIED` 等）；目录不变 |
| 同名冲突 | 平台自动追加编号后缀；不报错、不覆盖 |
| 受控写入失败 | 返回创建错误（可重试）；不留下半成品目录或文件 |
| 创建成功但打开失败 | 文档保留；按 §九打开失败呈现，提示重试或稍后打开 |
| 应用侧渲染失败 | 平台错误边界接管；已创建的文档不受影响 |

### 13.7 工作区扫描与事件

- 创建是平台写入，与外部修改走同一事件路径：写入完成后资源管理发布 `file:changed`（`kind: 'created'`），工作区按受影响目录增量刷新文件树，不重建整棵树（[13-工作区设计](./13-工作区设计.md) §5.3）。
- 文件树识别：卡片目录条目按 `card-directory` 识别（校验 `.card/` 配置目录存在）；箱子按 `box` 识别；扫描不解析文档内容（[13-工作区设计](./13-工作区设计.md) §5.2）。
- 会话建立后文档服务发布 `document:opened`，保存后发布 `document:changed`；创建链路不新增专用事件，也不自行广播「新建成功」。
- 事件是通知不是状态：入口树刷新失败时按工作区重试节奏重新枚举，不依赖事件必达（[13-工作区设计](./13-工作区设计.md) §5.3）。
- 创建产物在工作区可见后即可被任意入口打开，无需刷新或重启。
