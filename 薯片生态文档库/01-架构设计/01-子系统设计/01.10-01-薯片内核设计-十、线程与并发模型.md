## 十、线程与并发模型

### 10.1 线程拓扑

```
┌──────────────────────────────────────────┐
│ Node.js 主线程（Electron 主进程）          │
│  · 插件代码 · window.chips                │
└──────────────────────────────────────────┘
        │ Neon 调用 / Channel 回调投递
        ▼
┌──────────────────────────────────────────┐
│ 内核命令循环（唯一写者）                   │
│  · tokio Runtime                          │
│  · 状态变更串行执行 · 生命周期 · 依赖解析  │
└──────────────────────────────────────────┘
        │ 发布只读快照
        ▼
┌──────────────────────────────────────────┐
│ 并发读路径（任意线程）                     │
│  · 服务查找 · 事件派发快照                 │
└──────────────────────────────────────────┘
```

### 10.2 单写多读

- 写操作：所有状态变更经命令队列投递到内核命令循环，串行执行，天然避免竞态与乱序。
- 读操作：服务表与监听表以 `Arc` 快照发布；读路径只做一次读锁 + `Arc::clone`，随后无锁访问。
- 加载顺序确定性：apply 在命令循环内按依赖拓扑序逐个执行。
- 插件代码在 `await` 期间不阻塞命令循环，其余命令继续按队列执行。

### 10.3 锁与调用边界

1. 调用插件代码前必须释放内核锁；传入插件的是快照或句柄。
2. 禁止在持锁状态下 `await`、执行阻塞调用或调用插件代码。
3. 服务值必须 `Send + Sync`；服务内部同步自行负责。
4. 阻塞型插件调用（文件 IO、图像处理）必须经 `spawn_blocking` 执行，禁止占用命令循环线程。
5. 跨语言调用经 Neon Channel 投递到 Node.js 线程执行，内核线程不直接调用 JavaScript。

### 10.4 异步与取消

- 生命周期方法（`apply`、`stop`）为异步；内核等待其完成后推进状态机，超时上限见 6.7。
- 插件任务经 `ctx.task(work, { name?, signal? })` 登记到当前 Fork，返回可等待句柄（`join()` / `cancel()`）；Fork 撤销时触发取消，等待退出超过 `FORK_FORCE_DISPOSE_TIMEOUT` 后中止等待。
- 取消是协作式的：长任务必须周期性检查取消信号，在取消时释放已占用资源；任务名与在途任务数进入审计与配额计量（6.9）。
- 加载事务中的所有异步等待均可被上层取消；取消按失败处理并回滚（含暂存代际）。
