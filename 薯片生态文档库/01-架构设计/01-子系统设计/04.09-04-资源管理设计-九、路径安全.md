## 九、路径安全

### 9.1 虚拟路径规则

| 规则 | 说明 |
|---|---|
| 分隔符 | 统一 `/`；拒绝 `\` |
| 相对性 | 必须相对作用域根；拒绝绝对路径、盘符、UNC |
| 段 | 拒绝空段、`.`、`..` |
| 编码 | 百分号解码仅一次；解码后重新完整校验 |
| 控制字符 | 拒绝 `\0` 与其他控制字符 |
| Unicode | NFC 规范化后比较 |
| 长度 | 超过平台上限返回 `RESOURCE_PATH_INVALID` |

### 9.2 目录穿越防护实现

`ChipsError` 为单形结构体（`new / with_details / with_retryable`，[03-核心接口规范](../../05-接口与契约/03-核心接口规范.md) §3.3）；错误码取资源域码表常量（[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md) §7.2），`details` 携带 `path` 与 `reason`（reason 词表见 §7.3）。`RESOURCE_PATH_INVALID` 不可重试，使用默认值即可。

```rust
use chips_core::ChipsError;
use chips_resource::error::RESOURCE_PATH_INVALID;

// 统一构造资源域「路径非法」错误：域码表码 + 结构化 details。
fn path_invalid(path: String, reason: &str) -> ChipsError {
    ChipsError::new(RESOURCE_PATH_INVALID, "资源路径非法")
        .with_details(serde_json::json!({ "path": path, "reason": reason }))
}

pub fn resolve_within_root(root: &Path, virtual_path: &str) -> Result<PathBuf, ChipsError> {
    // percent_decode_once / has_windows_prefix 为本模块内部辅助函数
    let decoded = percent_decode_once(virtual_path)
        .map_err(|_| path_invalid(virtual_path.to_owned(), "encoding"))?;

    if decoded.contains('\0') {
        return Err(path_invalid(decoded, "control"));
    }
    if decoded.contains('\\') {
        return Err(path_invalid(decoded, "separator"));
    }

    let candidate = Path::new(&decoded);
    if candidate.is_absolute() || has_windows_prefix(candidate) {
        return Err(path_invalid(decoded, "absolute"));
    }

    if candidate.components().any(|component| {
        matches!(
            component,
            Component::CurDir | Component::ParentDir | Component::Prefix(_)
        )
    }) {
        return Err(path_invalid(decoded, "segment"));
    }

    let resolved = root.join(candidate);
    if !resolved.starts_with(root) {
        return Err(path_invalid(decoded, "symlink"));
    }

    Ok(resolved)
}
```

- 边界比较必须使用组件语义（`starts_with`），禁止字符串前缀比较。
- 目录态来源：`canonicalize` 后再次验证仍在作用域根内；符号链接指向根外一律拒绝。
- 归档条目：按条目名直接查找，不与文件系统拼接；非常规条目类型拒绝。

### 9.3 平台差异

| 平台项 | 处理 |
|---|---|
| Windows 盘符（`C:...`） | 一律拒绝 |
| Windows UNC（`\\server\share`） | 一律拒绝 |
| Windows ADS（`file.txt:stream`） | 拒绝含 `:` 的文件名 |
| Windows 设备名（`CON`、`NUL`、`COM1`…） | 一律拒绝 |
| 尾随点与空格 | 规范化后拒绝 |
| 大小写 | 目录态遵循卷语义；归档条目精确匹配 |
| macOS 大小写不敏感卷 | 解析后仍执行组件级根校验，不依赖大小写 |

### 9.4 测试要求

PathGuard 必须有独立单元测试，覆盖：`..` 明文与编码形式、双重编码、绝对路径、UNC、ADS、`\0`、Unicode 规范化差异、符号链接逃逸、超长路径。测试规范见[05-测试规范](../../02-开发规范/05-测试规范.md)。
