## 四、资源句柄

### 4.1 接口形状

```typescript
type ResourceState = 'open' | 'invalidated' | 'released';

interface IResourceMetadata {
  uri: string;
  size: number;
  mimeType: string;
  version: string;
  scope: 'document' | 'plugin' | 'platform' | 'external';
}

interface IResourceHandle {
  readonly uri: string;
  readonly state: ResourceState;
  metadata(): Promise<IResourceMetadata>;
  read(): Promise<Uint8Array>;
  readRange(offset: number, length: number): Promise<Uint8Array>;
  stream(): ReadableStream<Uint8Array>;
  release(): void;
  onInvalidate(handler: (reason: ResourceInvalidateReason) => void): ISubscription;
}

type ResourceInvalidateReason = 'source-changed' | 'session-closed' | 'scope-revoked';
```

对外契约以[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md)为准；本节定义管理器侧语义，供 Bridge 与 SDK 实现。句柄只读；写入见 4.8。

### 4.2 状态机

```
resource(uri)
      │
      ▼
    open ──release()──▶ released（终态，句柄 ID 不复用）
      │  ▲
      │  └── 重新获取必须再次调用 resource(uri)
      │
  来源变化 / 会话关闭 / 权限撤销
      │
      ▼
 invalidated ──release()──▶ released
```

- `open`：已通过解析与权限预检，可执行 `metadata` / `read` / `readRange` / `stream`。
- `invalidated`：来源已变化或权限失效；读操作返回 `RESOURCE_HANDLE_INVALIDATED`；`release()` 仍可调用。
- `released`：不再持有任何底层资源；除 `uri`、`state`、`release()` 外的方法返回 `RESOURCE_HANDLE_RELEASED`。
- `release()` 幂等，重复调用为 no-op；句柄不可序列化、不可持久化、不可跨会话传递。

### 4.3 获取

1. 渲染层 `resource(uri)` 同步解析 URI 并做本地权限快照快速检查；非法或越权立即抛 `ChipsError`，不返回句柄。
2. 返回懒打开的代理句柄；首次 `metadata` / `read` / `readRange` / `stream` 触发主进程 `resourceOpen`。
3. 主进程再次执行解析、作用域与会话校验、权限判定（纵深防御），分配 `HandleId` 并写入 HandleTable。
4. `resourceOpen` 返回元数据；后端打开失败时，首个异步操作以对应错误码拒绝。

### 4.4 使用

- 小资源（≤ 8 MiB）：`read()` 返回完整字节；命中内存缓存直接返回。
- 大资源（> 8 MiB）：`read()` 返回 `RESOURCE_TOO_LARGE`，必须使用 `stream()` 或 `readRange()`。
- 同一句柄的并发调用由句柄级互斥串行化；流打开期间 `readRange()` 返回 `RESOURCE_BUSY`，两者互斥。
- 读取不改变句柄状态；`metadata()` 可重复调用，命中元数据缓存。

### 4.5 释放与失效

释放：`release()` → 归还租约、关闭流与底层读取器、从 HandleTable 移除、写审计。

| 失效触发 | 影响范围 | 处理 |
|---|---|---|
| `file:changed`（受监视文件） | 对应作用域全部缓存与句柄 | 缓存失效；句柄转 `invalidated` 并通知订阅者 |
| `document:changed`（内容或元数据变更） | 文档作用域 | 只刷新作用域版本戳（不重建作用域）；缓存失效；句柄转 `invalidated` |
| `document:closed`（文档关闭） | 文档作用域 | 失效并释放 |
| 插件更新或卸载 | 插件作用域 | 失效并释放 |
| 权限撤销 | 相关作用域 | 失效并释放 |
| 外部缓存过期 | 外部资源条目 | 惰性失效，下次读取重新拉取 |

`onInvalidate` 在句柄已失效后注册时，立即（下一微任务）回调一次 `reason` 并返回已失效订阅。失效同时发布 `resource:invalidated`（`{ uri }`），事件契约见[09-事件系统设计](./09-事件系统设计.md)。

`document:changed` 只刷新作用域版本戳：作用域注册、作用域 ID、所有者与策略保持不变，仅递增版本戳并失效对应缓存条目与句柄；外部修改时查看会话按[11-文档服务设计](./11-文档服务设计.md) §7.2 冻结并提示重载，资源层不得让"模型旧 + 资源新"混用（例如不得让旧句柄继续读取新字节而不失效）。

### 4.6 句柄表、所有权与租约

```rust
pub struct HandleEntry {
    pub uri: CanonicalUri,
    pub session: SessionId,
    pub provider: ProviderId,
    pub state: HandleState,
    pub created_at: Instant,
    pub last_used_at: Instant,
    pub bytes_read: u64,
}
```

- 每个句柄归属于一个资源会话，句柄持有该资源的租约；会话关闭级联释放全部句柄与租约。
- 渲染层只持有租约，不缓存字节；字节读取一律由管理器按需完成（[05-渲染引擎设计](./05-渲染引擎设计.md) 5.3）。
- 句柄 ID 单调递增且低于 2^53，释放后永不复用；表内附加代次校验，防止旧 ID 误命中。

### 4.7 使用示例

```typescript
import { useEffect, useState } from 'react';

interface IPhotoProps {
  uri: string;
}

function Photo({ uri }: IPhotoProps) {
  const [failed, setFailed] = useState(false);

  useEffect(() => {
    const handle = window.chips.resource(uri);
    const subscription = handle.onInvalidate((reason) => {
      if (reason === 'scope-revoked') {
        setFailed(true);
      }
    });

    return () => {
      subscription.dispose();
      handle.release();
    };
  }, [uri]);

  if (failed) {
    return null;
  }

  // 字节由 chips-resource:// 协议处理器按 Range 提供；句柄负责失效感知与生命周期。
  return <img src={uri} alt="卡片资源" />;
}
```

### 4.8 写入提交（resources:write）

句柄不提供写入方法；写入统一由资源管理器提交。调用方与作用域受《本轮架构收口裁决》§三.7 约束：

| 场景 | 提交目标 | 权限 | 原子性 |
|---|---|---|---|
| document 挂载写入（目录态与归档态） | 文档作用域内对应路径 / 归档整体重建 | 仅文档服务可发起；内部经 `commit_write` / `commit_write_stream` | 临时文件 + 原子替换 / 整体重建（纳入 WriteCoordinator 同一路径锁） |
| 插件写入自身作用域 | 插件包的可写区 | `resources:write`（每次调用判定，受 PathGuard 与审计） | 临时文件 + 原子替换 |
| 写入用户授权路径（临时作用域） | 用户经 `dialog:save` 选择的路径 | 按临时作用域授权规则（`resources:write` + 单次写入后自动注销） | 临时文件 + 原子替换 |

规则：

- 提交前执行与读取相同的 PathGuard 校验与作用域匹配；越权返回 `RESOURCE_PERMISSION_DENIED`，非法路径返回 `RESOURCE_PATH_INVALID`。
- 写路径唯一：document 挂载（目录态与归档态）内的所有写入都必须经文档服务受控提交（[11-文档服务设计](./11-文档服务设计.md) §2.1、§8.1）；`resource:write` 只对插件作用域与临时作用域开放，不得写 document 作用域；不存在"自身/临时作用域免写权限"的例外——插件作用域写入需 `resources:write`，临时作用域按临时授权规则，写入仍受 PathGuard 与审计。
- 归档来源不就地改写：对 Archive 来源的 `commit_write` 返回 `RESOURCE_READ_ONLY`；归档由文档保存流程整体重建，并纳入 WriteCoordinator 的同一路径锁，与文档内其它写入互斥（临时文件 + 原子替换，见[11-文档服务设计](./11-文档服务设计.md) §5.4）。
- 大资源流式写：`commit_write` 支持流式提交 `commit_write_stream`（分块写入 + 背压 + 失败回滚），资源导入、替换与归档导出共用同一条流程（[11-文档服务设计](./11-文档服务设计.md) §8.5）；一次性 `commit_write` 仅适用于 ≤ 8 MiB 的字节提交。
- 提交成功递增版本戳、失效对应缓存条目，并发布 `resource:invalidated`。
- 全部提交经 WriteCoordinator：同一路径同一时间只允许一个写者；失败或中断留下的临时文件由管理器清理，不得残留。
- 渲染进程与插件不接触真实路径；写入字节经 Bridge 提交，协议细节见[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md)。

### 4.9 文件系统操作（move / copy / rename / delete / mkdir）

资源管理器提供文件系统操作能力，供持有 `filesystem:*` 权限的插件调用（经 Bridge 能力 `file:move` / `file:copy` / `file:delete` / `file:mkdir` 暴露；`file:move` / `file:copy` / `file:mkdir` 为已登记能力，契约表见[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md)）：

| 操作 | 所需权限 | 作用域约束 | 原子性 |
|---|---|---|---|
| `delete` | `filesystem:delete` | 只能在插件自身作用域或临时作用域内 | Provider 级原子；失败不留残留 |
| `rename` | `filesystem:write` | 源与目标必须在同一作用域 | Provider 级原子（系统调用） |
| `copy` | `filesystem:read` + `filesystem:write` | 源需读权限，目标需写权限 | 临时文件 + 原子替换；大文件流式拷贝 |
| `move` | `filesystem:write` | 跨作用域时需源与目标都有权限 | 同卷时调用 `rename`；跨卷时 `copy` + `delete` |
| `mkdir` | `filesystem:write` | 只能在插件作用域或临时作用域内 | 系统调用，幂等（已存在返回成功） |

规则：

- 所有操作前执行路径校验（PathGuard）与权限判定；作用域外路径一律拒绝，不允许跨作用域移动/复制（除非调用方同时持有源与目标作用域的权限）；跨作用域且缺权限返回 `RESOURCE_CROSS_SCOPE`。
- `delete` 非递归模式下，非空目录返回 `RESOURCE_NOT_EMPTY`；递归模式需额外检查目标是否全部在允许范围内。
- `rename` / `move` 目标已存在时返回 `RESOURCE_ALREADY_EXISTS`，不覆盖（调用方需先显式 `delete`）。
- `copy` 目标已存在时覆盖；大文件采用流式拷贝，不整体加载到内存。
- 全部操作经 WriteCoordinator 互斥，同一路径同一时间只允许一个写者。
- 操作成功后失效相关缓存条目，并发布 `resource:invalidated`（源与目标）。

### 4.10 目录列举（list_directory）

资源管理器支持目录列举，供持有 `filesystem:read` 权限的插件调用（经 Bridge 能力 `file:list` 暴露）：

规则：

- 只能列举插件自身作用域、工作区作用域（用户工作区内）、文档作用域（会话内）、临时作用域（用户授权）。
- 归档作用域支持列举（返回 ZIP 条目列表，`is_directory` 根据条目名尾随 `/` 判定）。
- 平台作用域、外部作用域不支持列举，返回 `RESOURCE_NOT_SUPPORTED`。
- 返回结果包含：文件名、是否目录、大小、修改时间；不递归（调用方需自行递归）。
- 系统生成物（`.DS_Store`、`Thumbs.db`、`.git`）、隐藏文件（以 `.` 开头）默认过滤，不返回。
- 列举结果不缓存（目录变化频繁），每次调用都重新扫描。
