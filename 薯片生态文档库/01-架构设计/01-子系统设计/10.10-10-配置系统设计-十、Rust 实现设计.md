## 十、Rust 实现设计

### 10.1 模块划分

配置系统实现为核心 crate `chips-config`：

| 模块 | 职责 |
|---|---|
| `key` | 配置键解析、命名空间归属与合法性校验 |
| `scope` | 层定义、文件键集与生效值解析 |
| `schema` | `SchemaRegistry`：平台与插件 schema 注册、缓存与校验 |
| `store` | `ConfigStore`：内存快照、读写 API、订阅分发 |
| `file` | 配置文件读写、原子替换、备份与外部修改监视 |
| `migration` | 平台迁移链与插件 JSON Patch 迁移执行 |
| `error` | `ConfigError` 定义与统一错误映射 |

### 10.2 核心类型

```rust
use serde_json::Value;
use std::collections::BTreeMap;
use std::sync::Arc;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ConfigLayer {
    Platform,
    User,
    Workspace,
    Plugin,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum WritableScope {
    User,
    Workspace,
}

#[derive(Debug, Clone)]
pub enum ChangeOrigin {
    Platform,
    Plugin(String),
    Migration,
    External,
}

#[derive(Debug, Clone)]
pub struct ConfigChange {
    pub key: String,
    pub layer: ConfigLayer,
    pub value: Option<Value>,
    pub effective_value: Option<Value>,
    pub is_default: bool,
    pub origin: ChangeOrigin,
}

pub type ChangeHandler = Arc<dyn Fn(ConfigChange) + Send + Sync>;

pub struct ConfigView {
    pub key: String,
    pub value: Option<Value>,
    pub layer: ConfigLayer,
    pub is_default: bool,
}
```

### 10.3 核心接口

```rust
pub struct ConfigStore {
    // 内部：ArcSwap<ConfigSnapshot>、SchemaRegistry、每文件写队列与监视器
}

impl ConfigStore {
    /// 读取单条生效值；未定义且无默认值时 value 为 None。
    pub async fn get(&self, key: &str) -> Result<ConfigView, ConfigError>;

    /// 在指定层写入值，返回该键的变更记录。
    pub async fn set(
        &self,
        key: &str,
        value: Value,
        scope: WritableScope,
        origin: ChangeOrigin,
    ) -> Result<ConfigChange, ConfigError>;

    /// 移除指定层上的覆盖；缺失的覆盖视为空操作。
    pub async fn reset(
        &self,
        keys: &[String],
        scope: WritableScope,
        origin: ChangeOrigin,
    ) -> Result<Vec<ConfigChange>, ConfigError>;

    /// 返回键前缀下合并默认值后的完整生效视图。
    pub async fn snapshot(&self, prefix: &str) -> Result<BTreeMap<String, Value>, ConfigError>;

    /// 订阅键前缀匹配的变更；返回句柄，dispose 后不再收到事件。
    pub fn watch(&self, prefix: &str, handler: ChangeHandler) -> ConfigSubscription;
}
```

- **暴露路径唯一**：`ConfigStore` 在核心启动时构造且全局唯一；面向主进程平台代码经 Cordis 服务（服务名 `config`）消费，面向 Neon 绑定层经核心接口（11.1 的 `INativeConfig`）调用；两条路径指向同一实例，不存在第二个存储实例或第二套读写路径。插件不得直接使用这两条路径，只能经 Bridge 能力（11.3）。
- 命名空间鉴权在 `ConfigStore` 入口执行：调用方标识（插件 ID 或 `platform`）由 Bridge 注入；平台可访问全部命名空间，插件只可访问 `platform` 与 `plugins.<自身ID>`。
- `ConfigSubscription` 在析构时注销回调；Neon 绑定层的 `dispose()` 触发析构。
- 订阅回调在内部提交线程完成快照切换后调用；宿主层负责把回调转译为 Bridge 事件。
