## 三、生命周期状态机与注册表

> 内核视角的加载阶段划分与 Fork 实现见 [01-薯片内核设计](01-薯片内核设计.md)；本节定义面向插件与插件管理的能力语义与状态规则。

### 3.1 状态定义

| 状态 | 含义 | 副作用边界 |
|---|---|---|
| `discovered` | 已发现、未安装 | 无 |
| `installed` | 已安装、未启用 | 无；可随时启用 |
| `pending` | 启用请求已受理，等待依赖满足 | 不执行任何插件代码 |
| `starting` | 启用执行中 | 已产生部分副作用，失败即回收 |
| `active` | 已启用运行中 | 全部副作用生效，可被调用 |
| `stopping` | 停用清理中 | 逐步回收副作用，停止接收新调用 |
| `failed` | 启用失败或运行崩溃 | 副作用已回收，仅保留诊断信息 |

### 3.2 状态机

主链路：

```
  ①  discovered ──install──► installed ──enable（依赖满足）──► starting ──激活成功──► active
  ②  active ──disable──► stopping ──清理完成──► installed
  ③  pending ──依赖就绪──► starting
  ④  failed ──retry──► starting
```

分支：

```
  A  installed ──enable（依赖未满足）──► pending；pending ──disable──► installed
  B  starting / active ──激活失败 / 运行崩溃──► failed（副作用已回收）
  C  active ──update──► active（新版本，蓝绿替换见 §6.2）
  D  installed / failed ──uninstall──► 记录移除；active / stopping ──uninstall──► 拒绝
```

状态迁移表：

| # | 起始状态 | 事件 | 目标状态 | 关键动作 |
|---|---|---|---|---|
| T1 | `discovered` | install | `installed` | 解包、校验、原子落盘、写注册表 |
| T2 | `installed` | enable（依赖满足） | `starting` | 生成会话快照、创建 Fork、执行角色激活入口 |
| T3 | `installed` | enable（依赖未满足） | `pending` | 记录缺失依赖，不执行任何插件代码 |
| T4 | `pending` | 依赖全部就绪 | `starting` | 自动继续 T2 后续步骤 |
| T5 | `pending` | disable | `installed` | 取消等待 |
| T6 | `starting` | 激活成功 | `active` | 暂存代际原子发布；发布 `plugin:loaded` 生命周期事件（结构化 payload） |
| T7 | `starting` | 激活失败 | `failed` | 回收已产生的副作用，记录错误 |
| T8 | `active` | disable | `stopping` | 摘除路由、调用角色停止入口 |
| T9 | `stopping` | 清理完成 | `installed` | `dispose()` 完成，写入启用偏好 |
| T10 | `active` | 运行崩溃 | `failed` | 隔离故障，回收副作用 |
| T11 | `failed` | retry | `starting` | 重置并重新激活 |
| T12 | `installed` / `failed` | uninstall | 记录移除 | 删除目录、配置与授权 |
| T13 | `active` / `stopping` | uninstall | 拒绝 | 必须先停用 |
| T14 | `active` | update | `active`（新版本） | 蓝绿替换，见 §6.2 |

规则：

- 只有 `active` 状态的插件可以接收渲染请求、能力调用与服务调用。
- `failed` 保留清单、路径与最后错误用于诊断；不保留任何运行时副作用。
- `pending` 与 `starting` 可以随时被 `disable` 取消；取消后回到 `installed`。
- 运行崩溃先隔离并回收副作用；未达重启上限时按受控重启回到 `starting`（10 分钟窗口内最多 3 次、指数退避），超过上限才停留在 `failed` 等待显式启用（§9.3）。

本文状态名与内核 `PluginManager` 状态一一对应：`pending` / `starting` / `active` / `stopping` / `installed` / `failed` 与内核同名状态同义；`discovered` 与卸载完成在内核侧无对应（内核登记为 `Removed`）；`Resolving` 是内核内部子阶段，不对外暴露。完整映射与迁移规则见 [01-薯片内核设计](01-薯片内核设计.md) §6.2。

### 3.3 注册表记录

注册表由内核维护，是插件状态的唯一投影；插件管理界面经插件管理能力读取与操作（能力契约见 [04-能力契约规范](../../05-接口与契约/04-能力契约规范.md)）。

```typescript
import type { ChipsError } from '@chips/sdk';

export type PluginRole = 'basecard' | 'boxlayout' | 'app' | 'service';

export type PluginState =
  | 'discovered'
  | 'installed'
  | 'pending'
  | 'starting'
  | 'active'
  | 'stopping'
  | 'failed';

export type PluginSource = 'builtin' | 'user' | 'development';

export interface IPluginDependency {
  id: string;
  version: string;
}

export interface IPluginRecord {
  id: string;
  version: string;
  role: PluginRole;
  state: PluginState;
  source: PluginSource;
  path: string;
  hash: string;
  dependencies: IPluginDependency[];
  permissions: string[];
  grantedPermissions: string[];
  installedAt: string;
  activatedAt?: string;
  lastError?: ChipsError;
}
```

| 字段 | 说明 |
|---|---|
| `id` | 反向域名插件 ID，全局唯一 |
| `version` | 语义化版本 |
| `role` | 四种角色之一 |
| `state` | 当前生命周期状态 |
| `source` | 来源：内置 / 用户 / 开发 |
| `path` | 插件目录绝对路径（仅内核使用，不暴露给其它插件） |
| `hash` | 安装包内容摘要，用于完整性校验与更新比对 |
| `dependencies` | 直接依赖列表（§7.1） |
| `permissions` | 清单申请集合 |
| `grantedPermissions` | 授权集合的会话快照（§11，归口 [08-权限系统设计](08-权限系统设计.md)） |
| `installedAt` / `activatedAt` | 安装与最近一次激活时间 |
| `lastError` | 最近一次失败的结构化错误（`failed` 状态时有值） |

### 3.4 持久化

- 持久化内容：安装集合（`installed` 及以上）、启用偏好、授权集合、插件配置（配置归口 [10-配置系统设计](10-配置系统设计.md)）。
- 运行态（`pending`、`starting`、`active`、`stopping`、`failed`）不持久化，由平台启动时重建。
- 上次运行中断残留的 `starting` / `stopping` 痕迹在启动时清理并回滚为 `installed`。
