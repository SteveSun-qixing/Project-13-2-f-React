# 同步引擎设计

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片平台同步引擎（可选、按需加载的平台服务插件形态，供用户主动安装的同步插件使用）的设计权威：同步模型、变更检测、增量同步、冲突解决、会话状态、离线队列、隐私边界与文档服务/资源管理/事件系统接口约定。

## 一、定位与边界

### 1.1 定位

同步引擎是薯片平台提供的**可选同步机制**，以**可选、按需加载的平台服务插件形态**（`service` 角色）交付：把本地优先的数据模型与用户主动安装的同步插件连接起来，提供变更检测、增量传输、冲突判定、会话状态、失败重试与离线队列等通用能力。远端存储、账户体系与传输通道由同步插件（`service` 角色）实现；平台只定义并执行机制，不自带任何远端服务。

引擎的本地能力由 Rust 核心 `chips-sync` 提供摘要 / 分块 / 变更索引 / 离线队列原语（登记于[03-核心接口规范](../../05-接口与契约/03-核心接口规范.md) §2.4），由 `sync` Cordis 服务包装后经 `ctx.sync` 对外暴露。引擎整体可选：**未启用时不加载引擎与其原语，零副作用**——不落盘 sidecar、不监听文件、不注册路由（§1.3、§2.1）。

本文件回答：

- 本地优先数据如何被检测为"变更"，摘要、版本戳、时间戳各承担什么职责。
- 增量同步的同步单元、分块、清单、水位与提交流程。
- 并发修改如何判定、如何由用户显式解决、败者版本如何保留。
- 会话状态机、单飞、取消、暂停与恢复规则。
- 失败如何重试、离线变更如何排队、插件卸载后队列如何存续。
- 授权、清单、凭证、日志与删除传播的隐私边界。
- 同步引擎与文档服务、资源管理、事件系统的接口约定。

### 1.2 分层位置

```
┌──────────────────────────────────────────────────────────┐
│ 应用插件（授权确认、同步面板、冲突解决 UI）                  │
│ 调用 enable / updateScope / resolveConflict；消费状态与事件  │
└──────────────────────────────────────────────────────────┘
                        ↕ Bridge / 事件
┌──────────────────────────────────────────────────────────┐
│ 同步插件（service 角色，实现 ISyncProvider）                │
│ 鉴权 · 远端清单 · 块读写 · 提交                             │
└──────────────────────────────────────────────────────────┘
                        ↕ Cordis 服务 ctx.sync（唯一交互面）
┌──────────────────────────────────────────────────────────┐
│ 同步引擎（可选、按需加载的平台服务插件，service 角色）        │
│ 变更索引 · 版本向量 · 分块 · 会话状态机 · 离线队列 · 审计     │
│ 内含 Rust 核心原语 chips-sync（摘要 / 分块 / 索引 / 队列）    │
│ 未启用时不加载；不直接读写文件                               │
└──────────────────────────────────────────────────────────┘
                        ↕
┌──────────────────────────────────────────────────────────┐
│ 文档服务（短时会话 · 受控写链路） · 资源管理（读 / 缓存失效）  │
│ 文档解析器（身份与摘要） · 事件系统（file:changed / 状态广播） │
└──────────────────────────────────────────────────────────┘
```

### 1.3 边界

- 不定义远端协议之外的存储产品与账户体系；只定义提供者契约。
- 不跟随文档内部引用：引擎不解析 `.card` / `.box` 内部结构，文档整体作为同步单元，仅经文档解析器读取 `metadata.yaml` 的 `card_id` / `box_id` 与 `modified_at`。
- 不直接读写文件：本地读取经资源管理器；对 document 挂载的任何写入经[文档服务](./11-文档服务设计.md)受控写链路（§9.3）；引擎不调用文件系统 API，也不得旁路直写。
- 不参与本地编辑路径：同步禁用、失败、阻塞均不影响编辑、查看与管理。
- 未启用零副作用：引擎与其原语不加载、不落盘 sidecar、不监听文件、不注册路由（§2.1、§2.3）。
- 不实现 UI：引擎只提供状态与接口，授权、进度与冲突选择由应用插件呈现。

### 1.4 术语

| 术语 | 含义 |
|---|---|
| 同步范围（scope） | 用户显式选择的一组本地**归档态文档**所在目录，`scopeId` 稳定；目录态文档不参与（§2.4） |
| 同步单元 | 一个完整的 `.card` 或 `.box` 归档态文件，内部资源随文件整体同步 |
| 提供者（provider） | 同步插件注册的远端接入实现，实现 `ISyncProvider` |
| 副本（replica） | 一次安装实例，拥有稳定 `replicaId` |
| 版本向量 | `replicaId → 写入计数` 的映射，用于判定因果关系 |
| 基线（baseline） | 本地记录中最近一次与远端一致的状态（`lastSynced*`） |
| 水位（cursor） | 提供者返回的不透明远端增量游标 |
| 短时会话 | 同步引擎经[文档服务](./11-文档服务设计.md) `document:open` 打开、以单个文档落地为单位持有并即时释放的文档会话（§3.1、§9.3） |
| 冲突副本 | 冲突解决时保留败者版本的本地文档，经受控写链路创建并标记为 `excluded` |
