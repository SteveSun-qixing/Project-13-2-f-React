## 五、认证与会话

### 5.1 凭据模型

| 凭据 | 存放位置 | 访问方式 | 说明 |
|---|---|---|---|
| `accessToken` | 渲染进程内存 | 会话模块持有 | 每次请求写入 `Authorization: Bearer`；不落盘、不入配置、不进日志与事件 |
| `refreshToken` | 平台凭证存储 | `credential:set` / `credential:get` / `credential:delete` | 名称 `refresh-token`（自身命名空间）；需 `credential:manage` |

- 登录 / 注册响应中的两个 token 由会话模块接收；仅 `refreshToken` 落凭证存储。
- 不保存账号密码；修改密码在登录态下经社区 API 完成。
- 凭证名遵循凭证能力文法（`^[a-z][a-z0-9-]*$`）；旧实现的引用名 `community.refreshToken` 不再使用，不提供兼容映射（[ADR-010](../ADR/ADR-010-大爆炸重构策略.md)）。

### 5.2 会话链路

1. **登录 / 注册**：调用认证接口 → `refreshToken` 写入凭证存储 → `accessToken` 存入内存 → 拉取用户资料 → 进入登录态。
2. **启动恢复**：读取凭证 `refresh-token`；不存在即未登录；存在则调用刷新接口，成功后取 `accessToken` 并拉取用户资料；失败按未登录处理（不弹错误、不自动重试）。
3. **401 刷新**：单飞（single-flight）——并发 401 共用同一次刷新；刷新成功用新 token 重放原请求；刷新失败清内存 token 并抛出 `COMMUNITY_CLIENT_SESSION_EXPIRED`。
4. **登出**：尽力调用登出接口（失败不阻断）→ 删除凭证 → 清空内存状态 → 跳转欢迎页。
5. **服务器地址变更**：先清会话（内存状态 + 凭证）再切换基址，避免 token 跨服务器复用。

### 5.3 服务器地址与会话绑定

- 配置键：自身命名空间 `server.baseUrl`，默认 `https://www.chipscard.space`（默认值来自包内 `assets/schemas/config.schema.json`，不落盘）。
- 设置页校验：仅接受 `http` / `https` 绝对 URL，去除尾斜杠；域名必须命中客户端已声明的 `network:http` 域集合，否则保存拒绝并返回 `COMMUNITY_CLIENT_SERVER_UNSUPPORTED`，同时说明支持范围。
- 地址保存在用户层配置（`scope: user`）；切换工作区不改变服务器地址。
- 配置变更经 `config:changed` 通知 UI，API 客户端立即切换基址；进行中的请求按旧基址完成或取消。

### 5.4 安全约束

- 凭证材料不进入配置、事件、日志与错误 `details`（[08-权限系统设计](./08-权限系统设计.md) §8.5、[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md) §7.12）。
- 不使用页面本地存储保存任何会话材料；应用窗口不提供也不应依赖 `localStorage` / `indexedDB`。
- 登出与凭证删除必须同时清空内存 token 与用户状态，避免残留可重放会话。
