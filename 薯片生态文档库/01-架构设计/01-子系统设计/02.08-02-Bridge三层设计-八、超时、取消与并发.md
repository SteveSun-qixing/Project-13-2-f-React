## 八、超时、取消与并发

### 8.1 超时

- 超时阈值取注册项 `timeoutMs`（默认 30000 毫秒），从 Bridge 层收到请求起算，至 Host 返回结果或异常为止。
- 调用上下文 `ctx.deadline` 为发起时刻加 `timeoutMs`；Bridge 适配层如实传递给 Host 实现，Host 应在截止前完成或主动中止。
- 超时触发时：Bridge 层取消 Host 侧执行，返回 `BRIDGE_TIMEOUT`（`retryable: true`），并按 `requestId` 丢弃迟到结果。
- 超时不保证无副作用：非幂等能力可能已部分执行；插件不得仅凭超时假定"未执行"。

### 8.2 取消

`IChipsBridge` 方法面不提供客户端取消入口，取消来源仅有以下三种：

1. **会话销毁**：窗口关闭、插件停用、应用退出；Bridge 层取消该会话全部在途调用。
2. **超时**：按 8.1 节取消。
3. **能力注销或 Bridge 关闭**：平台退出、服务插件停用。

规则：

- 取消经 `ctx.signal`（`AbortSignal`）传播到 Host 实现，`ctx.deadline` 同步给出截止时间；Host 必须响应取消并释放已占用资源。
- 调用方仍在线时会收到 `BRIDGE_CANCELLED`；会话已销毁时结果直接丢弃。
- 不得为取消扩展 `IChipsBridge` 方法面；如确需客户端取消，先走 RFC 修订本文第三节。

### 8.3 并发

| 策略 | 行为 |
|---|---|
| `parallel`（默认） | 同一能力可并发执行，无队列 |
| `serial` | 同一能力 ID 全局 FIFO 队列；等待数超过 `maxQueue`（默认 32）返回 `BRIDGE_QUEUE_OVERFLOW`（`retryable: true`） |

- 同一会话对同一能力的在途调用上限取该能力注册项的 `sessionInFlightLimit`（默认 64，见 4.1）；超限返回 `BRIDGE_SESSION_BUSY`（`retryable: true`）。
- 并发调度不保证跨能力公平性；插件应自行控制批量调用的节奏与顺序。
- Bridge 不自动重试，也不做幂等去重；幂等语义由能力实现自行定义与保证。
- `requestId` 仅用于关联与丢弃迟到结果，不用于去重执行。
