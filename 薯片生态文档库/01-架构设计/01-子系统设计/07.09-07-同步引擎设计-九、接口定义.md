## 九、接口定义

### 9.1 同步引擎服务（`ctx.sync`）

同步引擎以 Cordis 服务 `sync` 提供（可选、按需加载的平台服务插件包装 Rust 核心原语，§1.1）；同步插件通过 `ctx.inject(['sync'])` 注册提供者；应用插件调用 `enable` / `updateScope` / `resolveConflict` 等管理接口，并消费状态与事件。

```typescript
interface ISyncEngine {
  readonly replicaId: string;

  registerProvider(provider: ISyncProvider): ISubscription;
  listProviders(): readonly ISyncProviderInfo[];

  addScope(input: ISyncScopeInput): Promise<ISyncScope>;
  updateScope(scopeId: string, patch: Partial<ISyncScopeInput>): Promise<ISyncScope>;
  removeScope(scopeId: string): Promise<void>;

  enable(scopeId: string, providerId: string, options?: ISyncEnableOptions): Promise<void>;
  disable(scopeId: string): Promise<void>;

  sync(scopeId: string): Promise<ISyncSessionResult>;
  cancel(scopeId: string): Promise<void>;
  pause(scopeId: string): Promise<void>;
  resume(scopeId: string): Promise<void>;

  status(scopeId?: string): readonly ISyncStatus[];
  conflicts(scopeId?: string): Promise<readonly ISyncConflict[]>;
  resolveConflict(conflictId: string, resolution: ISyncConflictResolution): Promise<void>;
  queue(scopeId?: string): Promise<readonly ISyncQueueEntry[]>;
}
```

| 方法 | 说明 |
|---|---|
| `registerProvider` | 注册提供者，返回可退订句柄；插件卸载时自动注销 |
| `addScope` / `updateScope` / `removeScope` | 管理同步范围；`removeScope` 只停同步并清理索引，不删除文件 |
| `enable` | 建立授权并启用，触发首次基线扫描；应用插件调用前必须完成用户授权确认（§2.2） |
| `disable` | 停用并撤销授权；队列冻结保留 |
| `sync` | 启动一次会话；单飞，重复调用复用当前会话结果 |
| `cancel` / `pause` / `resume` | 取消 / 暂停 / 恢复会话 |
| `status` | 权威状态查询；事件丢失时以此为准 |
| `conflicts` / `resolveConflict` | 查询与显式解决冲突 |
| `queue` | 查看待同步队列 |

### 9.2 提供者接口（同步插件实现）

```typescript
interface ISyncProviderInfo {
  id: string;                        // 反向域名，如 chips.sync.selfhosted
  displayName: string;
  capabilities: ISyncProviderCapabilities;
}

interface ISyncProvider {
  readonly id: string;
  readonly displayName: string;
  readonly capabilities: ISyncProviderCapabilities;

  connect(config: ISyncProviderConfig): Promise<void>;
  disconnect(): Promise<void>;
  openSession(options: ISyncSessionOptions): Promise<IRemoteSession>;
}

interface ISyncProviderConfig {
  endpoint: string;
  options: Readonly<Record<string, string>>;   // 非机密选项；凭证由插件自行从配置系统读取
}

interface ISyncSessionOptions {
  scopeId: string;
  replicaId: string;
  cursor: string | null;
  mode: 'auto' | 'push-only' | 'pull-only';
}

interface IRemoteSession {
  fetchChanges(cursor: string | null): Promise<IRemoteChangeSet>;
  fetchDocument(documentId: string): Promise<Uint8Array>;
  fetchChunk(documentId: string, digest: Digest): Promise<Uint8Array>;
  hasChunks(digests: readonly Digest[]): Promise<readonly Digest[]>;
  pushChunk(digest: Digest, data: Uint8Array): Promise<void>;
  pushDocument(document: IRemoteDocument): Promise<void>;
  commit(commit: IRemoteCommit): Promise<IRemoteCommitResult>;
  abort(): Promise<void>;
}

interface IRemoteChangeSet {
  cursor: string;
  entries: readonly IRemoteDocument[];
}

interface IRemoteDocument {
  documentId: string;
  digest: Digest;
  size: number;
  modifiedAt: string;
  vector: IVersionVector;
  chunkDigests?: readonly Digest[];
}

interface IRemoteCommit {
  cursor: string;
  entries: readonly IRemoteDocument[];
  deletes: readonly string[];
}

interface IRemoteCommitResult {
  cursor: string;
  accepted: readonly string[];
}
```

同步插件的 manifest 示例：

```yaml
id: chips.sync.selfhosted
version: 1.0.0
type: service
name: 自建同步
description: 将同步范围连接到用户自建的远端

  targets: [host]
  background: true
permissions:
  - network:http:*.example.com
```

### 9.3 与文档服务、资源管理的接口约定

**读路径**：引擎读取范围文档字节经资源管理器（读句柄 / 流），文档身份与 `modified_at` 经文档解析器读取（L0）；禁止直接使用 Node.js / Electron 文件 API：

```typescript
interface ISyncReadPort {
  open(uri: string): Promise<IResourceHandle>;
  stat(uri: string): Promise<IResourceStat>;
}

interface IResourceStat {
  uri: string;
  size: number;
  modifiedAt: string;
}
```

| 约定 | 说明 |
|---|---|
| 读 | 经资源句柄 `read()` / `stream()` 获取字节，句柄用毕释放 |
| 元数据 | 文档身份（`card_id` / `box_id`）与 `modified_at` 经文档解析器读取，摘要经 `chips-sync` 原语计算 |
| 缓存 | 文档服务保存后刷新作用域版本戳并由资源管理失效缓存；引擎不自行失效、不旁路读取 |
| 权限 | 引擎以平台身份执行并遵守范围边界；提供者与第三方插件不经引擎接口不得访问文件系统与文档会话 |
| 格式 | 文档 URI 统一为 `chips-resource://<scope>/<path>`，与[资源协议规范](../../05-接口与契约/06-资源协议规范.md)一致 |

**写路径**：引擎对 document 挂载的任何写入都必须经文档服务受控写链路，不得旁路直写（[11-文档服务设计](./11-文档服务设计.md) §8.4、§8.5）：

| 约定 | 说明 |
|---|---|
| 应用远端变更 | 已存在文档：`document:open` 打开短时会话 → 校验 → `document:write` / `document:save` 原子落地 → 释放会话；新文档：按受控导入链路落地并校验（[13-工作区设计](./13-工作区设计.md) §4.3）；不使用 `resource:write` 或资源管理器提交接口写 document 作用域 |
| 会话归属 | 文档会话由同步引擎持有且短时——以单个文档的落地任务为界打开与释放，不跨任务持有、不长期订阅文档级事件；落地后由文档服务发布事件，其他活动会话按[11-文档服务设计](./11-文档服务设计.md) 第七节冻结提示 |
| 冲突副本 | 经受控写链路创建为独立文档（`document:export` 另存语义，`form: archive`），落点在同一范围目录并标记 `excluded` |
| 目录态纳管 | 目录态不参与同步；用户需要同步时先经 `document:export` 打包为归档态（[13-工作区设计](./13-工作区设计.md) §4.2、§4.4） |
| 归档来源 | 归档不就地改写；保存由文档服务按整体重建执行（归档重建纳入 WriteCoordinator 同一路径锁） |

### 9.4 与事件系统的接口约定

订阅（输入）：

| 事件 | 引擎使用字段 | 用途 |
|---|---|---|
| `document:changed` | `uri`、`documentId`、`kind`、`digest`、`size` | 平台内写入 → 追加变更记录 |
| `file:changed` | `uri`、`kind`、`previousUri?` | 外部落盘 → 补算摘要并比对 |
| `config:changed` | `key` | 提供者凭据变更 → 暂停并重连 |

- `file:changed` 的订阅由引擎自身在启用期间经 `file:watch` 受控接口建立（或使用平台文件监视服务），覆盖范围目录；停用、卸载时订阅随引擎 Fork 自动退订（§3.1）。

发布（输出）：

| 事件 | payload | 说明 |
|---|---|---|
| `sync:state-changed` | `{ scopeId, providerId, state }` | 状态迁移 |
| `sync:progress` | `{ scopeId, sessionId, phase, completedEntries, totalEntries, transferredBytes }` | 进度，节流 ≥ 200 ms |
| `sync:conflict-detected` | `{ conflictId, scopeId, documentId, detectedAt }` | 发现冲突 |
| `sync:conflict-resolved` | `{ conflictId, scopeId, documentId, strategy }` | 冲突已解决 |
| `sync:queue-changed` | `{ scopeId, pendingChanges }` | 队列长度变化 |
| `sync:blocked` | `{ scopeId, code, message }` | 进入阻塞，需要用户处理 |

- 投递语义为至多一次：事件只作通知；任何消费者必须能用 `status()` / `conflicts()` / `queue()` 重建一致状态。
- 事件 payload 的正式契约以[事件契约规范](../../05-接口与契约/05-事件契约规范.md)为准，本节字段是同步引擎的最小需求。
- 插件卸载时其事件订阅随 Cordis 作用域自动退订。

### 9.5 错误码

| 错误码 | 含义 | 可重试 |
|---|---|---|
| `SYNC_SCOPE_NOT_FOUND` | 范围不存在 | 否 |
| `SYNC_PROVIDER_NOT_FOUND` | 提供者未注册 | 否 |
| `SYNC_PROVIDER_UNAVAILABLE` | 网络或远端不可达 | 是 |
| `SYNC_AUTH_REQUIRED` | 需要用户重新登录或授权 | 否 |
| `SYNC_GRANT_REQUIRED` | 缺少显式授权 | 否 |
| `SYNC_CONFLICT` | 检测到并发修改 | 否 |
| `SYNC_DIGEST_MISMATCH` | 摘要校验失败 | 是（限一次） |
| `SYNC_REMOTE_REJECTED` | 远端拒绝（配额、策略） | 否 |
| `SYNC_VERSION_UNSUPPORTED` | 提供者能力不满足 | 否 |
| `SYNC_INVALID_DOCUMENT` | 缺少 `card_id` / `box_id` 等稳定身份字段，或身份字段非法 | 否 |

错误对象统一使用 `ChipsError` 结构（`code` / `message` / `details` / `retryable`），`retryable` 与本节"可重试"列一致。
