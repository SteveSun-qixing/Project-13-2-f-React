## 六、编辑链路协作

### 6.1 变更回流顺序

```
插件编辑器                  编辑链路                        文档服务               渲染会话
   │ change / getChange()     │                              │                     │
   │─────────────────────────▶│ 校验：configSchema            │                     │
   │                          │      + validateConfig         │                     │
   │                          │ document:write ─────────────▶│ 模型替换/成员操作，   │
   │                          │◀─────────────────────────────│ revision+1，          │
   │                          │        { revision }           │ 输出 { revision }     │
   │                          │ update(view, revision) ───────────────────────────▶│
   │                          │ markCommitted(revision)       │                     │
   │◀─────────────────────────│                              │                     │
   │                          │ 防抖 → document:save ───────▶│ 两阶段提交           │
   │                          │◀────────────── {source,digest}│ 发布 changed/saved  │
```

- 顺序固定且唯一：`getChange()` → 编辑链路校验（`configSchema` + `validateConfig`）→ `document:write`（输出 `{ revision }`）→ 渲染会话 `update(view, revision)` → `markCommitted(revision)`（[05-渲染引擎设计](./05-渲染引擎设计.md) §8.3、[08-基础卡片插件接口](../../05-接口与契约/08-基础卡片插件接口.md)、[09-箱子布局插件接口](../../05-接口与契约/09-箱子布局插件接口.md)、[12-编辑引擎设计](./12-编辑引擎设计.md)）。
- `revision` 只能取自 `document:write` 的返回值：视图与会话模型共享同一 revision 序列；`document:write` 成功即代表该修订已进入会话模型，编辑链路不得跳号、不得跳过 `write` 直接 `update` 视图。
- 写入失败（结构非法、写冲突、外部修改）时编辑链路不得推进视图；向用户展示简体中文错误并保留编辑器脏状态。
- 渲染 `update` 失败（`RENDER_UPDATE_FAILED`）不回退已提交的写入：编辑链路保留脏状态并提示重试，视图重新按当前 `revision` 对齐。

### 6.2 校验职责

| 校验 | 执行方 | 时机 |
|---|---|---|
| `configSchema`（manifest 声明） | 编辑链路 | 每次回流前、保存前（[08-基础卡片插件接口](../../05-接口与契约/08-基础卡片插件接口.md) §7.4、[09-箱子布局插件接口](../../05-接口与契约/09-箱子布局插件接口.md) §3.5） |
| `validateConfig`（插件纯函数） | 编辑链路（在插件上下文中调用） | 同上 |
| 结构校验（kind/part/引用/标识） | 文档服务 | `document:write` 与 `document:save` |
| 格式校验（schema、完整性） | 解析器 | `document:save` 写盘后的 `validate` |

- 服务不得调用插件代码：插件方法只在调用方（帧运行时 / 编辑链路）上下文中执行。
- 任一校验失败即拒绝回流并给出简体中文提示；不得以"先写入再修正"的方式绕过。

### 6.3 自动保存编排

- 自动保存由编辑链路编排：订阅编辑器句柄（`IBaseCardEditor` / `ILayoutEditor`）的 `dirty` / `change`，按自身策略防抖后调用 `document:save`；默认防抖 500ms（可配置），失焦、窗口关闭与应用退出前 flush 未保存变更（[12-编辑引擎设计](./12-编辑引擎设计.md)）。服务不主动保存、不规定防抖时长。
- 保存失败：编辑链路保留脏状态、展示 `DOCUMENT_SOURCE_CHANGED` / `DOCUMENT_SAVE_FAILED` 的中文说明与重试入口；不得静默丢弃变更。
- 保存成功的回调（`document:saved`）用于更新窗口标题与状态栏；编辑链路不依赖事件必达（事件至多一次，见[05-事件契约规范](../../05-接口与契约/05-事件契约规范.md) §七）。
- 应用退出、窗口关闭前：编辑链路先完成或放弃回流；未保存变更的确认交互由编辑链路实现（[07-应用插件接口](../../05-接口与契约/07-应用插件接口.md)）。

### 6.4 禁止事项

- 禁止编辑容器或插件直接写文件、直接调用 Rust 写入接口、绕过 `document:*` 自行持久化。
- 禁止为写链路实现第二套解析、序列化或归档打包。
- 禁止跳过校验写入、禁止在 `write` 中夹带未校验的插件语义。
- 禁止服务替编辑链路做交互（弹窗、提示、自动重试轮询）。
