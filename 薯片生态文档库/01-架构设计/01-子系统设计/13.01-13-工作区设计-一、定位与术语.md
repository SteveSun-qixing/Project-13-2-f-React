## 一、定位与术语

### 1.1 定位

运行时的**工作区（workspace）**是薯片平台在用户设备上的默认用户数据根：用户的卡片、箱子与其他文档按文件系统原样存放其中，平台在该目录内维护唯一的保留目录 `.chips/`。

工作区回答四个问题：

1. 用户的文档放在哪里、以什么形态存放（目录态 / 归档态），如何相互转换。
2. 平台自身需要的工作区级状态放在哪里，哪些目录与文件不进入扫描与文件树。
3. 打开、扫描、切换与关闭工作区时，各子系统（文档服务、资源管理、配置系统、同步引擎、编辑引擎）如何重载与收敛。
4. 用户工作区与开发工作区如何隔离，开发态与用户态各自能看到什么。

工作区是**默认数据根**，不是封闭沙箱：用户仍可经文件对话框授权打开工作区之外的文件；平台不要求所有文档都位于工作区内。

### 1.2 与"生态工作区"的术语区分

| 术语 | 指代 | 权威 |
|---|---|---|
| 运行时工作区（工作区） | 用户数据根目录（如 `~/Documents/Chips`），本文的默认语义 | 本文件 |
| 生态工作区（仓库工作区） | 开发 monorepo 根目录，`pnpm-workspace.yaml` / `Cargo.toml` 所在处 | [01-代码组织规范](../../02-开发规范/01-代码组织规范.md) |
| 配置工作区层 | 配置系统的 `workspace` 层，物理载体为 `<workspace>/.chips/config.workspace.json` | [10-配置系统设计](./10-配置系统设计.md) §2.2 |

正文中"工作区"一律指运行时工作区；提及开发 monorepo 时统一写"生态工作区"。

### 1.4 术语

| 术语 | 定义 |
|---|---|
| 工作区（workspace） | 运行时用户数据根目录；由平台创建并维护标记文件与保留目录。 |
| 工作区根（workspace root） | 工作区的绝对目录路径；工作区绑定记录的值。 |
| 标记文件（marker） | `<workspace>/.chips/workspace.json`；声明该目录为薯片工作区及格式版本。 |
| 保留目录 | `<workspace>/.chips/`；平台专用的隐藏目录，不进入扫描、不作为用户数据。 |
| 保留前缀 | 以 `.chips` 开头的路径名（含 `.chips/` 与 `.chips-*` 兄弟临时物）；用户文件与插件禁止使用。 |
| 用户文件区 | 工作区根下除保留区之外的全部内容：卡片目录态、归档态文档、箱子与其他用户文件。 |
| 目录态（directory form） | 卡片以 `*.card/` 目录存在，是编辑工作形态，长期驻留工作区。 |
| 归档态（archive form） | 文档以单个 ZIP Store 文件存在（`*.card` / `*.box`），是交付形态。 |
| 扫描（scan） | 平台按固定排除规则枚举用户文件区，生成文件树模型的过程。 |
| 文件树（file tree） | 应用插件呈现的工作区目录视图；模型定义见 §5.2。 |
| 开发工作区 | 开发态专用数据根，与用户工作区在数据、插件记录与日志上完全隔离。 |
| 工作区目录变量 | 权限限定值中代表工作区根的变量 `${workspace}`。 |

### 1.5 基本约束

1. 工作区以文件系统原样为唯一事实源：平台不建立与文件系统并行的第二份目录索引；文件树与缓存均可重建（[《架构原则》](../../00-愿景与原则/01-架构原则.md) 本地优先）。
2. 工作区内的文档一律经正式链路访问：解析、渲染、编辑、资源访问、同步全部使用 `chips-resource://` 与 `document:*`；禁止旁路。
3. 保留目录只由平台组件读写；用户与插件不得创建、修改、删除保留目录与保留前缀条目（§6.3）。
4. 同一工作区同一时刻只被一个平台实例绑定；平台单实例由壳层保证（[10-配置系统设计](./10-配置系统设计.md) §9.1）。
5. 卡片存在两种正式形态（目录态与归档态），箱子只有单文件形态；形态转换必须经 `document:export`，禁止手工搬移或第三方脚本改写内容（§四）。
