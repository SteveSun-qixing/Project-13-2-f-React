## 一、定位与边界

### 1.1 定位

薯片社区是薯片生态的内容社区；**官方社区客户端**（插件 ID `chips.official.community-client`，`app` 角色，`ui.surface: window`）是社区在平台内的官方日常入口，承担四件事：

- **浏览**：欢迎页、社区简介、登录与注册、个人主页、卡片详情、箱子详情、工作区、设置与管理员入口；
- **上传**：把本机 `.card` / `.box` 文件经统一卡片传输链路发布到社区；
- **完整下载**：把社区卡片的完整离线形态下载到用户选择的本地位置；
- **本地查看**：取回社区卡片的网络资源形态，交由本地卡片查看器解析渲染，不依赖服务器渲染缓存。

客户端是**纯应用插件**：不解析 `.card` / `.box`、不渲染卡片内容、不读写文档字节、不实现上传下载协议；它只做界面与编排，一切内容能力来自平台既有链路。

网页版社区（`Chips-CommunityPlatformServer` 的 Web 前端）面向临时访客，客户端面向日常用户；两者共享同一套社区服务器 API 与内容组织语义，客户端在网页版基础上增加上传、完整下载与本地查看，页面结构与导航层级保持与网页版一致；视觉统一由 `@chips/ui` 与 Design Tokens 承担，客户端不复制网页版的私有样式与主题变量（R4、R5）。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 社区服务器 | 承载社区 API 与对象存储/CDN 的服务器；客户端按自身配置的基址访问 |
| 社区会话 | 客户端与社区服务器之间的登录状态：`accessToken`（仅内存）+ `refreshToken`（平台凭证存储） |
| 网络资源卡片 | 资源引用改写为对象存储/CDN URL 的卡片形态；上传产物，也是本地查看的输入（权威定义见[01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md)与[16-卡片传输协议](../../05-接口与契约/16-卡片传输协议.md)） |
| 完整离线卡片 | 资源字节回填、URL 还原为原始相对路径的卡片形态（同上） |
| 本地查看 | 取回网络资源卡片到本地临时位置后，交由本地卡片查看器打开（传输协议任务种类 `open-remote`，见[16-卡片传输协议](../../05-接口与契约/16-卡片传输协议.md)） |
| 完整下载 | 下载并恢复为完整离线卡片，保存到用户选择的位置 |
| 传输链路 | 承载卡片上传、完整下载、网络资源卡片取回与 URL 改写/恢复的统一链路；其提供方形态、面向插件的绑定（能力 ID、SDK 导出名）与任务语义以[16-卡片传输协议](../../05-接口与契约/16-卡片传输协议.md) §1.1 与平台能力登记为准 |
| 默认处理器 | 平台按资源类型选择处理应用的路由机制，见[14-资源打开与默认处理器契约](../../05-接口与契约/14-资源打开与默认处理器契约.md) |

### 1.4 基本约束

1. 单角色 `app`；主窗口由平台按 `ui.surface: window` 创建，客户端不创建额外系统窗口（R1、[07-应用插件接口](../../05-接口与契约/07-应用插件接口.md) §5.2）。
2. UI 只从 `@chips/ui` 导入组件、Hooks 与 Design Tokens；不导入 antd 等第二套组件库（R4、[ADR-008](../ADR/ADR-008-React加fork-antd前端技术栈.md)）。
3. 一切系统能力经 `chips.request` / `chips.resource` / `chips.subscribe`；禁止直接 `fetch`、禁止访问 Node.js / Electron API、禁止真实文件路径（R2、R17）。
4. 卡片字节的上传、下载与 URL 改写/恢复全部由统一传输链路执行；客户端不解析、不改写、不重打包卡片文件（R8、[01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md) §2.3）。
5. 卡片查看一律交给本地卡片查看器；客户端不内嵌渲染管线、不依赖服务器渲染缓存（R8、[05-渲染引擎设计](./05-渲染引擎设计.md)）。
6. 界面文案全部简体中文直写；不引入多语言运行时（R5）。
7. 权限按最小范围声明，域名限定值逐项列出；不申请宽泛通配权限（[08-权限系统设计](./08-权限系统设计.md) §5.1、§10.2）。
