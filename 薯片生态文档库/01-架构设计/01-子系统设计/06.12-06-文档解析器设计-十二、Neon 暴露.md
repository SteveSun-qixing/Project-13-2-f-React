## 十二、Neon 暴露

### 12.1 导出函数

| 导出函数 | 参数 | 返回 |
|---|---|---|
| `openDocument` | `path: string`, `options?: ParseOptions` | `Promise<DocumentHandle>`（自动识别） |
| `openCard` | `path: string`, `options?: ParseOptions` | `Promise<DocumentHandle>`（严格 card） |
| `openBox` | `path: string`, `options?: ParseOptions` | `Promise<DocumentHandle>`（严格 box） |
| `documentMetadata` | `handle` | `Promise<MetadataResult>` |
| `documentStructure` | `handle` | `Promise<StructureResult>` |
| `documentContent` | `handle`, `nodeId: string` | `Promise<ContentResult>` |
| `documentEntries` | `handle`, `range?: { offset: number; limit: number }` | `Promise<EntriesResult>` |
| `documentReadResource` | `handle`, `path: string`, `range?: { offset: number; length: number }` | `Promise<Buffer>` |
| `documentValidate` | `handle` | `Promise<ValidationReport>` |
| `documentClose` | `handle` | `Promise<void>` |
| `createCancelToken` | — | `CancelToken` |
| `cancelTokenCancel` | `token` | `void` |

`MetadataResult` / `StructureResult` / `ContentResult` / `EntriesResult` 统一携带 `{ kind, value, diagnostics }`，以 `kind` 为判别字段、`value` 与格式对应；`ValidationReport` 形状见 6.5。所有访问器函数与 Rust 方法一一对应，命名采用 camelCase。全量解析（`CardParser::parse` / `BoxParser::parse`）供 Rust 侧导出与批处理链路使用，Neon 不重复导出 eager 变体；JS 侧经句柄访问器与 `documentValidate` 获得同等能力。

### 12.2 调用约定

导出实现位于 `chips-native`，仅做类型转换与错误映射，业务逻辑全部留在 `chips-parser`。

```rust
fn js_open_card(mut cx: FunctionContext) -> JsResult<JsPromise> {
    let path = cx.argument::<JsString>(0)?.value(&mut cx);
    let options_object = cx.argument::<JsObject>(1).ok();
    let options = parse_options_from_js(&mut cx, options_object)?;
    let channel = cx.channel();
    let (deferred, promise) = cx.promise();

    std::thread::spawn(move || {
        let result = CardParser::new(options).open(Path::new(&path));
        deferred.settle_with(&channel, move |mut cx| match result {
            Ok(handle) => Ok(cx.boxed(handle).upcast()),
            Err(error) => throw_document_error(&mut cx, error),
        });
    });

    Ok(promise)
}

fn throw_document_error<'a>(
    cx: &mut FunctionContext<'a>,
    error: DocumentError,
) -> JsResult<'a, JsValue> {
    let message = cx.string(error.user_message());
    let mut js_error = cx.error(message)?;
    let code = cx.string(error.code());
    js_error.set(cx, "code", code)?;
    cx.throw(js_error.upcast())
}
```

约定：

- 所有可能触发 IO 或解析的导出均为异步：CPU 阻塞工作使用 Neon 专用后台线程（`std::thread`，Rust 编码规范允许的例外），完成后经 `cx.channel()` 回到 Node 主线程 settle，不阻塞事件循环。
- 错误归一：JS `Error` 携带 `code` / `message` / `details` / `retryable`，与 `ChipsError` 结构一致；`message` 为简体中文。
- 取消：`createCancelToken` 返回 `JsBox<CancelToken>`；解析线程在阶段边界与文件循环处检查取消标志，命中返回 `DOCUMENT_PARSE_CANCELLED`；已完成单元的缓存保留。
- 句柄：以 `JsBox<DocumentHandle>` 传递，不暴露内部结构；`documentClose` 提前释放映射，未关闭时由 GC 终结器释放。
- 值映射：`u64` 尺寸映射为 JS `number`（受限额约束，安全范围内）；时间映射为 RFC 3339 字符串；`DocumentValue` 映射为普通 JS 对象/数组/标量；资源字节映射为 `Buffer`。
- 平台边界：以上导出位于 Node 主进程内部；插件不直接加载原生模块，只能经 Bridge 能力访问（能力清单见[《能力契约规范》](../../05-接口与契约/04-能力契约规范.md)）。资源授权与缓存由[《资源管理设计》](04-资源管理设计.md)负责。

### 12.3 TypeScript 调用示例

```typescript
import {
  openCard,
  documentMetadata,
  documentContent,
  documentClose,
} from '../../native';

import type { CardContent, CardMetadata } from '@chips/sdk';

interface Diagnostic {
  severity: 'error' | 'warning' | 'info';
  code: string;
  message: string;
  file?: string;
  pointer?: string;
  line?: number;
  column?: number;
  hint?: string;
}

function formatDiagnostic(diagnostic: Diagnostic): string {
  const location = [
    diagnostic.file ?? '<document>',
    diagnostic.line !== undefined && diagnostic.column !== undefined
      ? `${diagnostic.line}:${diagnostic.column}`
      : undefined,
    diagnostic.pointer,
  ]
    .filter((part): part is string => part !== undefined)
    .join(' ');

  return `[${diagnostic.code}] ${location}: ${diagnostic.message}`;
}

async function loadCardMain(cardPath: string): Promise<CardContent | null> {
  const handle = await openCard(cardPath);

  try {
    const metadata = await documentMetadata(handle);

    for (const diagnostic of metadata.diagnostics) {
      if (diagnostic.severity !== 'info') {
        console.warn(formatDiagnostic(diagnostic));
      }
    }

    const metadataFailed = metadata.diagnostics.some(
      (diagnostic) => diagnostic.severity === 'error',
    );
    if (metadataFailed || metadata.kind !== 'card') {
      return null;
    }

    const cardMetadata: CardMetadata = metadata.value;
    const content = await documentContent(handle, 'a1B2c3D4e5');
    return content.value;
  } finally {
    await documentClose(handle);
  }
}
```

示例位于 Electron 主进程 `packages/host/src/main/`，原生绑定产物位于 `packages/host/native/`（见[《代码组织规范》](../../02-开发规范/01-代码组织规范.md)）；`CardMetadata` 等类型由 `@chips/sdk` 提供（字段定义见[《卡片文件格式》](../../04-文件格式规范/01-卡片文件格式.md)）。
