## 九、拒绝错误码与提示

### 9.1 错误码总表

| 错误码 | 触发阶段 / 层 | 说明 | retryable |
|--------|----------------|------|-----------|
| `BRIDGE_PERMISSION_DENIED` | 运行时 · 能力调用 | 会话快照未覆盖能力所需权限，含未授予、已撤销、超出限定值、用户拒绝；契约见 [02-Bridge三层设计](./02-Bridge三层设计.md) | false |
| `RESOURCE_PERMISSION_DENIED` | 运行时 · 资源访问 | 资源作用域或路径安全判定失败；契约见 [04-资源管理设计](./04-资源管理设计.md) | false |
| `PLUGIN_PERMISSION_DENIED` | 插件生命周期 | 启用、能力注册阶段的权限拒绝；契约见 [03-插件架构设计](./03-插件架构设计.md) | false |
| `RENDER_RESOURCE_DENIED` | 运行时 · 渲染帧资源代理 | 帧内资源请求越权；契约见 [05-渲染引擎设计](./05-渲染引擎设计.md) | false |
| `PERMISSION_NOT_DECLARED` | 能力注册 | 能力所需权限未在提供方 manifest 声明 | false |
| `PERMISSION_UNKNOWN` | 安装校验 | 权限 ID 的 domain/scope 未注册 | false |
| `PERMISSION_INVALID` | 安装校验 | 权限 ID 格式或限定值文法非法 | false |
| `PERMISSION_ROLE_NOT_ALLOWED` | 安装校验 | 插件角色不允许申请该权限 | false |

规则：

- 运行时拒绝的具体错误码由判定执行方返回（Bridge、资源管理器、插件运行时、渲染代理），四者共用 [9.2](#92-错误结构与示例) 的 `details` 结构与 `reason` 枚举。
- 各层错误码是拒绝判断的唯一依据；本文不定义无前缀的运行时错误码。

### 9.2 错误结构与示例

```typescript
interface IPermissionDeniedDetails {
  capabilityId?: string;
  permission: string;
  required: string[];
  missing: string[];
  granted: string[];
  reason: PermissionDenyReason;
  target?: string;
}
```

```typescript
import { ChipsError } from '@chips/sdk';

async function saveDraft(path: string, content: string): Promise<boolean> {
  try {
    await window.chips.request<void>('file:write', { path, data: content });
    return true;
  } catch (error) {
    if (error instanceof ChipsError && error.code === 'BRIDGE_PERMISSION_DENIED') {
      return false;
    }
    throw error;
  }
}
```

### 9.3 用户提示文案

| 场景 | 提示（简体中文） |
|------|------------------|
| 运行时拒绝后由插件提示 | 操作被拒绝：缺少"修改文件"权限。可在「设置 → 插件 → 编辑引擎 → 权限」中授权后重试。 |
| 用户拒绝后插件提示 | 你拒绝了本次授权请求，操作未执行。 |
| 超出限定值 | 目标位置不在已授权范围内，请重新选择位置或调整插件权限。 |
| 安装校验失败（开发者可见） | 插件声明了未注册的权限 `filesystem:exec`，安装已终止。 |
| 更新新增权限被拒绝 | 新版本需要额外权限，更新已取消，当前版本继续使用。 |

规则：面向用户的 `message` 一律简体中文，不暴露堆栈与内部路径；`details` 供开发者与日志使用。
