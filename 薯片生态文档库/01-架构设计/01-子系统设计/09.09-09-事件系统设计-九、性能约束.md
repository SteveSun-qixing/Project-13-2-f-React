## 九、性能约束

### 9.1 指标

| 指标 | 预算 | 说明 |
|---|---|---|
| 内核空发布（无监听器） | < 100 ns | 名称查表未命中直接返回，不分配 |
| 内核发布（有监听器） | P99 < 1μs | `emit` 入口至全部监听器调用或入队完毕（Rust 同步、JS 入队）；不含监听器与 JS 执行耗时 |
| 订阅 / 退订 | O(1) | 哈希桶插入 / 移除 + 效果链，随 Fork 批量撤销 |
| 桥接转发入队 | P95 < 1ms | 含结构化克隆与 IPC 排队；不含渲染侧执行 |
| 桥接 payload | ≤ 256 KiB | 超限拒绝 |
| 下行缓冲 | ≤ 1024 条 / 1 MiB（每窗口每事件） | 超限按 6.5 溢出策略处理 |
| 溢出可观测 | `dropped` 计数 | 丢弃与合并按窗口、事件累计，异步写 Trace |
| 派发深度 | 64 | 超限返回 `KERNEL_EVENT_DEPTH_EXCEEDED` |
| 事件历史 | 不缓存 | 内存占用与活跃订阅数线性 |

监听器内部耗时不计入发布预算，但 Rust 监听器在发布线程内同步执行，不得长时间阻塞发布调用栈；JS 监听器入队后异步执行，同样不得假设可以无限占用 Node.js 线程。耗时处理必须经 `ctx.task` 转交后台任务。

### 9.2 实现要求

- 发布路径无锁：监听器表采用写时复制快照，发布时只读。
- 无订阅事件零分配、零序列化、零跨进程开销。
- 精确匹配：禁止通配符、正则、谓词；发布开销与监听器数量线性。
- 桥接惰性：无跨进程订阅时不进入序列化与 IPC。
- 日志与追踪在发布路径之外异步记录，不得同步写日志。
- 基准测试使用 criterion，纳入 CI 质量门禁（见《[CICD与质量门禁](../../06-开发与运维/05-CICD与质量门禁.md)》与《[架构原则](../../00-愿景与原则/01-架构原则.md)》第 4.2 节）。

### 9.3 禁止事项

- 禁止在发布路径做内容过滤、序列化、磁盘 IO、网络 IO。
- 禁止为单个订阅者建立独立队列或独立线程；监听器在同一调度模型中执行，唯一的例外是主 → 渲染的有界下行缓冲（6.5）。
- 禁止缓存或重放事件；事件不是日志，事件溯源由需要它的子系统自行实现。
- 禁止在事件 payload 中传递资源字节或大对象。

### 9.4 日志与追踪字段

事件发布与投递日志使用统一字段（异步记录，不进入发布路径）：

| 字段 | 说明 |
|---|---|
| `eventId` | 事件 ID，`<domain>:<action>` |
| `source` | 发布者身份：平台组件 ID 或插件 ID，由内核按调用上下文记录 |
| `traceId` | 追踪 ID，与 Bridge 追踪、权限审计一致（见《[08-权限系统设计](./08-权限系统设计.md)》） |
| `publishedAt` | 发布时刻，ISO 8601 UTC |
| `listenerCount` | 本次投递的监听器数量 |
| `dropped` | 本次投递因下行缓冲溢出被丢弃或合并的事件数（无溢出的投递为 0） |
| `error` | 首个监听器错误（成功时省略） |

审计输出使用 `security:audit` 标准事件；调试追踪使用 Bridge 追踪（见《[调试指南](../../06-开发与运维/03-调试指南.md)》）。
