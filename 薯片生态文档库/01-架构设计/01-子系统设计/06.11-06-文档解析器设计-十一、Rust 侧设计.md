## 十一、Rust 侧设计

### 11.1 公开类型

```rust
pub enum DocumentKind { Card, Box }

pub struct ParseOptions {
    pub strict: bool,
    pub repair: bool,
    pub verify_hashes: bool,
    pub parallelism: usize,
    pub limits: ParseLimits,
}

impl Default for ParseOptions {
    fn default() -> Self {
        Self {
            strict: false,
            repair: true,
            verify_hashes: false,
            parallelism: 4,
            limits: ParseLimits::default(),
        }
    }
}
```

`ParseOptions` 经 `CardParser::new` / `BoxParser::new` 或 `open_document` 传入，句柄创建后不可变；`ParseLimits` 字段与默认值见 9.1。

### 11.2 解析入口

```rust
pub struct CardParser { options: ParseOptions }

impl CardParser {
    pub fn new(options: ParseOptions) -> Self {
        Self { options }
    }

    /// 打开并解析到 L0，返回惰性句柄。
    pub fn open(&self, path: &Path) -> Result<DocumentHandle> {
        DocumentHandle::open(path, DocumentKind::Card, &self.options)
    }

    /// 全量解析（导出、校验、批处理）。
    pub fn parse(&self, path: &Path) -> Result<ParsedCard> {
        let handle = self.open(path)?;
        let metadata = handle.metadata();
        let structure = handle.structure()?;
        let content = handle.parse_all_content()?;
        Ok(ParsedCard {
            metadata,
            structure,
            content,
            revision: handle.revision(),
            statistics: handle.statistics(),
            diagnostics: handle.diagnostics(),
        })
    }
}

/// 与 CardParser 对称；`open_document` 自动识别格式。
pub struct BoxParser { options: ParseOptions }

impl BoxParser {
    pub fn new(options: ParseOptions) -> Self {
        Self { options }
    }

    pub fn open(&self, path: &Path) -> Result<DocumentHandle> {
        DocumentHandle::open(path, DocumentKind::Box, &self.options)
    }
}

pub fn open_document(path: &Path, options: &ParseOptions) -> Result<DocumentHandle>;

/// 全量解析结果：模型全部冻结，诊断已排序去重。
pub struct ParsedCard {
    pub metadata: Arc<CardMetadata>,
    pub structure: Arc<StructureModel>,
    pub content: ContentIndex,
    pub revision: DocumentRevision,
    pub statistics: DocumentStatistics,
    pub diagnostics: Vec<Diagnostic>,
}
```

`BoxParser::parse` 与 `CardParser::parse` 对称；[ADR-003](../ADR/ADR-003-Rust核心加Node-Native-Module架构.md)中的 `parse_card` / `parse_box` 自由函数草图由这两个入口实现。`DocumentHandle::open` 内部顺序：`open_source` → 索引 → 格式校验 → metadata（阶段 1-3）。公开 API 必须带文档注释并通过文档测试（见[《Rust 编码规范》](../../02-开发规范/04-Rust编码规范.md)）。

### 11.3 模型

```rust
pub struct CardMetadata {
    pub chip_standards_version: String,
    pub card_id: String,
    pub name: String,
    pub created_at: String,
    pub modified_at: String,
    pub cover_ratio: Option<String>,
    pub tags: Vec<Tag>,
    pub file_info: Option<FileInfo>,
    // 其余可选字段与完整校验规则见《04-文件格式规范/01-卡片文件格式》
}

pub struct BoxMetadata {
    pub chip_standards_version: String,
    pub box_id: String,
    pub name: String,
    pub created_at: String,
    pub modified_at: String,
    pub active_layout_type: String,
    // 其余可选字段与完整校验规则见《04-文件格式规范/02-箱子文件格式》
}

pub enum DocumentMetadata {
    Card(CardMetadata),
    Box(BoxMetadata),
}

/// 标签：简单标签为字符串；结构化标签为字符串数组（首项为键，其余为值）。
pub enum Tag {
    Simple(String),
    Structured(Vec<String>),
}

/// `metadata.file_info`：由写入链路生成。
pub struct FileInfo {
    pub total_size: u64,
    pub file_count: u64,
    pub checksum: Option<String>,      // SHA256
    pub generated_at: Option<String>,  // RFC 3339 UTC
}

pub struct ContentNode {
    pub node_id: NodeId,
    pub file: PackagePath,
    pub card_type: String,
    pub value: DocumentValue,          // 插件专有字段的不透明值，原样保留
    pub diagnostics: Vec<Diagnostic>,
}

/// 箱子条目（`.box/structure.yaml` 的 `entries` 元素）。
pub struct Entry {
    pub entry_id: String,
    pub url: String,
    pub enabled: bool,
    pub snapshot: Option<DocumentValue>,      // 摘要快照，字段语义见《箱子文件格式》
    pub layout_hints: Option<DocumentValue>,  // 布局索引
}

/// 顺序保持、无标签、JSON 兼容的不透明值。
pub enum DocumentValue {
    Null,
    Bool(bool),
    Integer(i64),
    Float(f64),
    String(String),
    Sequence(Vec<DocumentValue>),
    Mapping(Vec<(String, DocumentValue)>),
}
```

`DocumentValue` 是解析器对插件专有字段的唯一表示：顺序稳定、无标签、重复键按 YAML 错误处理（`YAML_SYNTAX_ERROR`），可直接映射为 TS 对象与 `serde_json::Value`，不泄露底层 YAML 库类型。

### 11.5 依赖

| 依赖 | 用途 |
|---|---|
| serde / serde_yaml | YAML 反序列化（基线见 [ADR-003](../ADR/ADR-003-Rust核心加Node-Native-Module架构.md)） |
| serde_json | JSON Pointer、schema 校验中间表示、诊断序列化 |
| thiserror | 错误定义（与 ADR-003 一致） |
| zip | ZIP 读取（中央目录、Store/Deflate、ZIP64） |
| memmap2 | 归档只读映射 |
| rayon | L2 单元并行解析 |

`zip`、`memmap2`、`rayon` 为解析器新增依赖，必须完成许可证、维护状态、包体、安全与跨端兼容性核对并纳入 `[workspace.dependencies]` 后方可使用；解析器只允许纯 Rust 依赖，确保五端行为一致。

### 11.6 安全

- 路径：`PackagePath` 在构造时完成全部校验；目录态每次访问验证真实路径位于包根内；符号链接不跟随。
- 归档：zip-slip 拒绝、重复路径拒绝、加密拒绝、非法压缩方法拒绝、压缩比与尺寸限额。
- YAML：字节、深度、别名限额；禁用自定义标签与二进制标签；不解析执行任何内容。
- `cover.html` 只作为路径记录，不读取、不解析、不执行；渲染由沙箱承担。
- 无网络、无子进程、无文件写入。
- `unsafe` 仅限 `source/archive.rs` 的 mmap 封装：`unsafe fn` 使用 `# Safety` 章节，`unsafe` 块使用 `// SAFETY:` 注释，并通过 Clippy。
