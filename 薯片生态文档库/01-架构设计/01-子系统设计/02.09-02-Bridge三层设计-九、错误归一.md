## 九、错误归一

### 9.1 归一边界

- 所有跨 Bridge 的错误统一为 `ChipsError` 错误模型；全生态只有 `ChipsError` 一个错误类，且源码级类定义唯一归属 `@chips/bridge` 协议层（工单024 裁定，权威归属与统一形状见《RFC-ChipsError统一裁定》），`@chips/sdk` 主入口、`@chips/cli` 与宿主经该唯一定义消费：

```typescript
interface ChipsError {
  code: string;
  message: string;
  details?: unknown;
  retryable?: boolean;
}
```

- `@chips/sdk` 导出错误类 `ChipsError`（与 `@chips/bridge` 协议层同源，SDK 主入口薄再导出，插件侧 import 路径不变）；唯一构造入口为 `new ChipsError({ code, message, details?, retryable? })`；`request` 失败时以该错误类型 reject。
- 判定口径：跨上下文边界的唯一权威判定是结构守卫 `isChipsError`（不读取原型链，同时接受类实例与同构普通对象）；`instanceof ChipsError` 仅在同一打包副本的 Realm 内有效，禁止用于跨边界判定。
- Rust 侧 `ChipsError`（`thiserror`）归一为同一结构；TS 侧同构映射；preload 只还原结构，不修改 `code` 与 `retryable`。
- Host 业务错误码原样透传（如 `DOCUMENT_NOT_FOUND`、`FILE_NOT_FOUND`）；Bridge 只负责通道级错误。
- 未识别异常归一为 `BRIDGE_INTERNAL`，`message` 使用通用文案，`details` 不携带堆栈与内部路径；诊断信息写宿主日志。
- 跨 Bridge 传输的错误必须是普通对象（实例经 `toPlain()` 归一，`code`/`message`/`retryable` 恒输出、`details` 仅在有值时输出）；`message` 一律简体中文、面向用户。

### 9.2 Bridge 错误码表

| code | 触发 | retryable |
|---|---|---|
| `BRIDGE_CAPABILITY_NOT_FOUND` | 能力 ID 未注册 | `false` |
| `BRIDGE_CAPABILITY_CONFLICT` | 注册冲突（ID 已占用、保留 ID、结构校验失败） | `false` |
| `BRIDGE_INVALID_SCHEMA` | 注册期 schema 编译失败 | `false` |
| `BRIDGE_PERMISSION_DENIED` | 会话快照未覆盖能力所需权限（含未授予、已撤销、超出限定值、用户拒绝） | `false` |
| `BRIDGE_INVALID_INPUT` | 输入未通过 JSON Schema 校验 | `false` |
| `BRIDGE_TIMEOUT` | 超过 `timeoutMs` | `true` |
| `BRIDGE_CANCELLED` | 会话销毁、能力注销或 Bridge 关闭导致取消 | `false` |
| `BRIDGE_SESSION_UNKNOWN` | 来源会话无法解析或已关闭 | `false` |
| `BRIDGE_SESSION_BUSY` | 会话对同一能力的在途调用超过 `sessionInFlightLimit` | `true` |
| `BRIDGE_QUEUE_OVERFLOW` | 串行队列溢出 | `true` |
| `BRIDGE_INTERNAL` | 未归一异常 | `false` |

权限系统、插件生命周期与资源层的专属错误码（`PERMISSION_NOT_DECLARED`、`PLUGIN_PERMISSION_DENIED`、`RESOURCE_*` 等）分别以[08-权限系统设计](./08-权限系统设计.md)、[03-插件架构设计](./03-插件架构设计.md)、[04-资源管理设计](./04-资源管理设计.md)为准。

### 9.3 错误处理示例

```typescript
import { isChipsError } from '@chips/sdk';

async function openCardWithFeedback(path: string): Promise<void> {
  try {
    await window.chips.request<void>('file:read', { path });
  } catch (error) {
    if (!isChipsError(error)) {
      throw error;
    }
    if (error.code === 'BRIDGE_TIMEOUT' && error.retryable) {
      // 仅对幂等且已被平台标记可重试的调用重试
      await window.chips.request<void>('file:read', { path });
      return;
    }
    throw error;
  }
}
```

### 9.4 重试归属

Bridge 不自动重试。`retryable` 只是提示：插件必须结合能力的幂等性自行决定是否重试；`retryable: false` 的错误不得自动重试。插件处理错误必须按 `code` 分支，禁止匹配 `message` 文本。
