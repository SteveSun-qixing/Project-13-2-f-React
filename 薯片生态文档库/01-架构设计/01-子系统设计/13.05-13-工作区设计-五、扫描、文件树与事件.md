## 五、扫描、文件树与事件

### 5.1 扫描语义

1. 扫描根为工作区根；平台按需扫描，不做全量常驻索引：首屏只枚举根目录条目，子目录在展开时枚举（懒加载）。
2. 排除规则固定为 §3.2；扫描不跟随符号链接、不读取文档内容、不解析 YAML（工作区树只呈现文件系统信息）。
3. 排序：目录在文件之前，同级按名称的 Unicode 码点升序；排序只影响呈现，不写回文件系统。
4. 单目录条目超过 5,000 项时分页加载（每页 1,000 项），不影响其余目录；分页是呈现策略，不是文件数量限制。
5. 扫描结果缓存于 `.chips/cache/`（树索引）；缓存键包含目录路径与目录修改时间，失效后重新枚举。
6. 扫描与监听在文件系统事件压力下必须合并：同一目录 300ms 内的多次变化只触发一次重扫。

### 5.2 文件树模型

```typescript
type WorkspaceEntryKind =
  | 'directory'          // 普通目录
  | 'card-directory'     // 目录态卡片（名称以 .card 结尾且含 .card/ 配置目录）
  | 'card-archive'       // 归档态卡片（*.card 文件）
  | 'box'                // 箱子（*.box 文件）
  | 'file';              // 其他用户文件

interface WorkspaceEntry {
  name: string;                    // 条目名（含扩展名）
  path: string;                    // 相对工作区根的路径，'/' 分隔
  kind: WorkspaceEntryKind;
  size: number;                    // 文件字节数；目录为 0
  modifiedAt: string;              // RFC 3339 UTC
  state: 'ok' | 'unreadable' | 'link';   // 读取状态
}
```

规则：

1. 树只呈现文件系统信息；文档标题、封面与标签在文档打开后由会话/事件提供，不在扫描期解析（R18）。
2. `card-directory` 的识别必须校验 `.card/` 配置目录存在；缺失时降级为 `directory` 并允许用户展开查看（不打开为文档）。
3. `state: 'unreadable'` 的条目在树中标记错误态并提供重试；不阻塞其他条目。
4. 文件树选中不等于编辑授权：读取目录经 `file:list`（`filesystem:read`，限定值 `${workspace}`）；打开文档经 `document:open` 并按 `resources:read` 判定。
5. 应用插件可在树中展示应用级派生状态（最近打开、收藏）；这类状态属于应用插件自身数据，不写入工作区文件。

### 5.3 变更事件

| 事件 | 发布方 | 工作区侧动作 |
|---|---|---|
| `file:changed`（`created` / `modified` / `deleted` / `renamed`） | 资源管理（文件监听） | 刷新受影响目录的树索引；文档服务标记 `externally_modified`（[11-文档服务设计](./11-文档服务设计.md) §7.1） |
| `document:changed` | 文档服务 | 刷新该文档的缓存与摘要；同步引擎按需消费 |
| `document:closed` | 文档服务 | 释放资源作用域缓存；树状态不变 |
| `resource:invalidated` | 资源管理 | 句柄失效通知；封面等派生缓存失效 |
| `config:changed` | 配置系统 | 工作区层配置变化（含工作区切换后的重算） |

规则：

1. `file:changed` 的 `uri` 为受管 URI；工作区侧不因事件重建整棵树，只按受影响目录增量刷新。
2. 事件是通知不是状态：树在一次刷新失败后按重试节奏重新枚举，不依赖事件必达（[11-文档服务设计](./11-文档服务设计.md) §7.3）。
3. 平台自身写入产生的事件（保存、导出）与外部修改事件走同一路径；实现可合并但不允许屏蔽。

### 5.4 外部修改检测与提示

- 检测基线与拒绝覆盖规则完全遵循[《文档服务设计》](./11-文档服务设计.md) §7.1、§7.2：打开与保存成功后记录指纹；`file:changed` 标记 `externally_modified`；保存前强制复查指纹；不一致返回 `DOCUMENT_SOURCE_CHANGED`。
- 界面语义（应用插件实现，文案简体中文）：

| 场景 | 提示与动作 |
|---|---|
| 文档在编辑期间被外部工具修改 | 会话冻结写入，提示"文档已被外部修改，已暂停写入。请重新打开以继续编辑"；提供"重新打开"（关闭会话后重新 `document:open`）与"另存为"（`document:export` 落到新路径） |
| 文档在查看期间被外部修改 | 手动或自动刷新（重新打开）；不做静默覆盖 |
| 只读会话（非写者）读到变化 | 由编辑链路决定是否重载（[11-文档服务设计](./11-文档服务设计.md) §7.4） |

- 平台不做自动合并、不做"强制保存"入口、不做隐式重载：用户显式选择重新打开或另存（ADR-010 无兼容与静默兜底）。

### 5.5 重命名 / 移动 / 删除与会话行为

| 操作 | 对已打开会话的影响 | 处理 |
|---|---|---|
| 重命名 | `source` 失效，表现为外部修改（`renamed` 事件携带 `previousUri`） | 禁止写入（`DOCUMENT_SOURCE_CHANGED`）；提示"文件已被重命名，请重新打开"；用户可选择用新路径重新打开 |
| 移动到工作区内其他位置 | 同上（路径变化） | 同上；移动经 `file:move` 且源/目标都需权限 |
| 移动到其他工作区 / 工作区外 | 同上，且当前工作区不再可见该文档 | 同上；跨工作区引用不自动授权（§6.4） |
| 删除 | `source` 不存在；`read` 仍返回会话模型，`save` 失败 | 禁止写入；提示"文件已被删除，你的修改尚未丢失"，提供"另存为"（`document:export` 到新位置）；确认后释放会话 |
| 覆盖写入（同路径替换为新内容） | 指纹不一致 | 同"外部修改" |
| 目录态成员被外部增删 | 指纹集合变化 | 同"外部修改"；保存被拒绝 |

规则：以上操作都不由平台自动执行；平台只检测与提示，动作由用户经文件能力显式发起（`file:move` / `file:copy` / `file:delete` / `file:mkdir`，能力与权限映射见[《能力契约规范》](../../05-接口与契约/04-能力契约规范.md)、[《权限系统设计》](./08-权限系统设计.md) §4.3）。
