## 二、总体架构

### 2.1 分层

```
渲染进程（插件 UI / 渲染帧）
  <base href="resourceBase"> / window.chips.resource(uri) → IResourceHandle
        │  bridge:resource（IPC）
        ▼
主进程 · Bridge 层
  权限判定 · 会话绑定 · 句柄代理 · 审计
        │  Neon
        ▼
Rust 核心 · ResourceManager
  Resolver（URI → 地址）· ScopeRegistry · Provider 注册表
  PathGuard · CacheStore · SingleFlight · HandleTable · StreamPool · WriteCoordinator
        │
        ▼
文件系统抽象层
  DirectoryProvider · ArchiveProvider · PlatformProvider · HttpProvider
```

### 2.2 组件职责

| 组件 | 职责 |
|---|---|
| Resolver | 解析 URI 为 `ResourceAddress`，选择 Provider |
| ScopeRegistry | 注册/注销作用域，绑定所有者、来源与策略 |
| Provider 注册表 | 按来源提供 `stat` / `read_range` / `open_stream` |
| PathGuard | 虚拟路径解码、规范化与目录穿越防护 |
| CacheStore | 元数据缓存、内存 LRU、外部磁盘缓存 |
| SingleFlight | 相同资源并发读取合并 |
| HandleTable | 句柄登记、状态、所有权与泄漏审计 |
| StreamPool | 流式读取游标、chunk 拉取、背压与关闭 |
| WriteCoordinator | 写入提交、作用域写锁、临时文件与原子替换、写后失效 |

### 2.3 资源来源与作用域分类

| 作用域 | 示例 | 底层来源 | 生命周期 |
|---|---|---|---|
| Workspace | `chips-resource://workspace-3f/笔记/报告.card` | 用户工作区目录（[13-工作区设计](./13-工作区设计.md)） | 工作区打开期 |
| Document | `chips-resource://card-7f3a/images/photo.jpg` | 目录态或 ZIP Store 的 `.card` / `.box` | 文档会话 |
| Plugin | `chips-resource://plugin-001/icon.png` | `.cpk` 安装目录或包内资源 | 插件加载期 |
| Platform | `chips-resource://platform/frame.html` | 平台安装目录与内嵌资源 | 平台生命周期 |
| External | 语法见[资源协议规范](../../05-接口与契约/06-资源协议规范.md) | `http(s)://` / `webdav://` 代理 | 缓存条目 |
| Temporary | `chips-resource://temp-7a3f/report.pdf` | 用户经 `dialog:*` 授权的路径 | 单次读写或会话结束 |
| Memory | `chips-resource://memory/...`（仅运行时） | 运行时内存字节，禁止持久化 | 会话内 |

作用域 ID 由平台在注册时分配，插件无法命名、猜测或伪造作用域。

### 2.4 统一文件系统

资源管理器是平台的**统一文件系统**：一切来源皆挂载（mount），一切访问皆句柄。

- 挂载单元：每个来源（工作区、文档、插件、平台、外部、临时、内存）注册为一个挂载点与作用域；挂载携带所有者、来源、策略与能力声明。挂载注册见 5.2 节，注销随所有者生命周期（10.1 节）。
- 句柄唯一入口：所有读取（含 `<img>` 等协议路径访问）都经 `chips-resource://` 解析为 `ResourceAddress` 后由 Provider 提供；插件侧一律经句柄或协议路径，不接触真实路径。
- Provider 能力声明：`supports_write` / `supports_streaming` / 目录列举能力由 Provider 声明，管理器在调用前做能力预检，不支持的操作返回确定性的 `RESOURCE_READ_ONLY` / `RESOURCE_NOT_SUPPORTED`，不透传到 Provider 内部再失败（3.3 节）。
- 两张能力面：`file:*`（路径式，`file:read` / `file:write` / `file:move` / `file:copy` / `file:mkdir` / `file:delete` / `file:list`，以路径与 `filesystem:*` 权限表达）与 `resource:*`（地址式，`window.chips.resource(uri)` 与 `chips-resource://`，以 URI 与 `resources:*` 权限表达）是**同一引擎的两张能力面**：共用同一 Resolver、ScopeRegistry、PathGuard、CacheStore、HandleTable、StreamPool 与 WriteCoordinator，不存在第二套实现或第二套缓存。选择哪张面只影响权限词表与调用形态，不影响底层语义。
- 确定性降级：能力不支持或权限不足时返回结构化错误并保留原状态，禁止静默改写来源、禁止隐式降级为其它 Provider。
