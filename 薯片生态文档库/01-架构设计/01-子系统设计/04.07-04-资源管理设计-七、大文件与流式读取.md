## 七、大文件与流式读取

### 7.1 阈值与选择

| 资源大小 | 可用操作 |
|---|---|
| ≤ 8 MiB | `read()`、`readRange()`、`stream()`；写入可用一次性 `commit_write` |
| > 8 MiB | `stream()`、`readRange()`；`read()` 返回 `RESOURCE_TOO_LARGE`；写入必须使用 `commit_write_stream` |

- 8 MiB 上限**只适用于一次性 `read()` / `write()`**：它是单次 IPC 载荷与内存缓存的设计上限，不是资源大小限制（单资源大小上限见第十二节 `platform.resources.maxResourceBytes`）。
- 阈值为平台配置项（第十二节），变更不影响接口。

### 7.2 流式协议

Neon 不直接暴露 Rust 流；管理器提供 chunk 拉取接口，由主进程封装为 Node 流，再经 Bridge 送达渲染进程：

```
渲染进程 ReadableStream
  ↕ bridge:resource（chunk）
主进程 Readable（背压驱动）
  ↕ resourceReadChunk(handleId, maxBytes)
ResourceManager 流游标
  ↕
Provider::open_stream
```

- `resourceReadChunk` 返回 `Buffer`；到达结尾返回 `null`。
- 每次拉取上限 256 KiB；调用方不拉取时 Rust 侧不推进读取（天然背压）。
- 流结束或取消：渲染进程 `cancel()`、窗口关闭、句柄释放任一发生，主进程通知管理器终止游标并归还租约。
- ZIP Store 条目直接从映射区切片；范围读与流式共享同一游标实现，保证语义一致。

### 7.3 传输与内存

- Rust → Node：每个 chunk 拷贝一次进 `JsBuffer`，避免悬垂引用。
- Node → 渲染进程：`Uint8Array` 以 transfer 方式移交，避免二次拷贝。
- 单条 IPC 消息不超过 256 KiB；渲染进程流高水位 1 MiB。
- 流式读取不缓存整体资源；内存占用与并发流数量成正比，不随文件大小增长。
- 流式写（`commit_write_stream`）与流式读共用同一游标与背压机制：调用方按 chunk 提交，管理器写入临时文件，完成后 fsync、校验并原子替换；失败删除临时物，不产生半写文件。

### 7.4 协议处理器接入

主进程注册 `chips-resource` 自定义协议处理器（Electron `protocol.handle`），把浏览器请求转交 ResourceManager：

- 解析 `Range: bytes=start-end`，命中 Provider 范围读，返回 206 与 `Content-Range`；非法范围返回 416。
- `Content-Type` 由第 3.4 节判定；文本类型附带正确字符集。
- 越权返回 403、目录穿越拒绝、脚本/字体/媒体响应头与缓存头要求以[05-渲染引擎设计](./05-渲染引擎设计.md) 4.4 为准；管理器不依赖 Chromium 缓存，统一由 CacheStore 承担。
- 主窗口 `script-src chips-resource:` 的受控放宽（[05-渲染引擎设计](./05-渲染引擎设计.md) 4.3）以本处理器的作用域与权限判定为安全边界：无授权作用域的模块请求一律 403，不因来源是主窗口而放行。
- `<img>` / `<video>` / `<audio>` / `<link>` / 模块脚本一律使用 `chips-resource://` URL，帧内不直接访问外部网络。
