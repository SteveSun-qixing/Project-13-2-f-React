## 五、资源代理注入

### 5.1 资源作用域与基址

每个打开的文档在资源管理器中注册一个作用域，渲染层拿到的是不透明字符串 `resourceBase`，例如：

```
chips-resource://card-7f3a/          # 卡片包作用域
chips-resource://box-2c91/           # 箱子包作用域
```

帧初始化时注入 `<base href="{resourceBase}">`，使文档内相对路径（相对包根）自动解析到包内资源：

```
images/photo.jpg   →  chips-resource://card-7f3a/images/photo.jpg
```

卡片资源直接位于包根（允许子目录），包内相对路径不带 `resources/` 前缀；箱子自有资源位于 `assets/`。

URI 语法、作用域分配与权限规则以[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md)为准，渲染层只负责注入与映射。

### 5.2 引用映射

渲染层在资源准备阶段构建映射表，把视图中的资源引用归一：

| 引用形式 | 处理 |
|---|---|
| 包内相对路径 | 拼接到 `resourceBase`，注入帧后由 `<base>` 生效 |
| `chips-resource://` | 原样透传，由协议处理器判定权限 |
| `file://` | 包外本机文件的引用形态；由文档解析器在进入渲染前归一为受管作用域 URI（[06-文档解析器设计](./06-文档解析器设计.md) §3.5，与[04-资源管理设计](./04-资源管理设计.md) §5.1 一致），帧内不直接使用 `file://`；正式保存链路必须把资源复制进包并改写为包内相对路径（R13） |
| `http(s)://` | 由资源代理下载/缓存后映射为受管 URI（第 5.4 节） |
| `webdav://` | 正式引用集合成员（[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md) §2.2）；由文档解析器在进入渲染前归一为 external 受管 URI（[06-文档解析器设计](./06-文档解析器设计.md) §3.5），访问由平台 WebDAV 代理承载；凭证不写入引用，由平台凭证存储按授权策略注入（[02-箱子文件格式](../../04-文件格式规范/02-箱子文件格式.md) §十一） |
| 内联数据 `data:` | 仅允许作为运行时内存形态（帧内临时数据）；禁止持久化写入内容配置、封面与资源字段（R12/R13） |

映射表随视图版本一起冻结；`update(view, revision)` 时重建映射表并仅刷新受影响的帧。

### 5.3 资源句柄生命周期

- 渲染层不持有资源字节；只持有资源句柄租约，字节读取由资源管理器按需完成。
- 句柄租约绑定会话：会话 `dispose()` 时统一释放；帧销毁时释放该帧专属的临时句柄。
- 帧内请求资源失败时返回结构化错误，帧运行时渲染占位（图片裂图、媒体错误态），不得静默空白。
- 大量资源并发请求由资源管理器排队与去重（[04-资源管理设计](./04-资源管理设计.md)），渲染层不自行实现并发控制。

### 5.4 外部资源（http/https）

- 外部资源引用由资源代理统一拉取、校验类型、缓存后以受管 URI 注入；帧内 `connect-src 'none'` 保证没有旁路。
- 代理请求受权限系统约束（域名级权限 ID 规则见[08-权限系统设计](./08-权限系统设计.md)）；被拒绝时帧收到 `RENDER_RESOURCE_DENIED` 并显示中文说明。
- 缓存与失效策略归资源管理器；渲染层在会话级记录映射便于诊断，不缓存字节。

### 5.5 安全约束

- 所有资源访问统一经 `chips-resource://`，受限、可审计（R17）。
- 注入 `<base>` 的 `href` 必须是受管作用域 URI，禁止注入 `file://`、裸绝对路径或任意远端地址。
- 帧不允许通过 `base-uri` 覆盖平台注入值（CSP `base-uri chips-resource:` 已收紧）。
