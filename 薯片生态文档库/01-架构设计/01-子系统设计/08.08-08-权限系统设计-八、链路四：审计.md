## 八、链路四：审计

### 8.1 记录策略

| 事件                                           | 记录策略                |
| ---------------------------------------------- | ----------------------- |
| 授予（启用确认、首次调用记住、设置面板、更新） | 全量                    |
| 撤销（设置面板、卸载）                         | 全量                    |
| 运行时判定（放行与拒绝）                       | 全量                    |
| 安装、更新、卸载引起的权限集合变化             | 随每次授予/撤销逐条记录 |

注：本节「运行时判定」限指经过授予判定的 allow 与 deny；免权限直通路径（[7.2](./08.07-08-权限系统设计-七、链路三：运行时判定.md) self-scope 直通、Platform 公开只读恒放行、Document 会话内免重复校验）未经过授予判定，不产审计条目；仅 grant/revoke 动作与授予判定的 allow/deny 进入上表全量口径（工单046 裁定二，2026-09-21）。

说明：审计写入以异步追加执行，写入失败不阻塞调用，但必须记录内部告警；判定耗时不计入能力执行的性能预算。

### 8.2 审计记录字段

```typescript
type PermissionAuditAction = 'grant' | 'revoke' | 'deny' | 'allow';
type PermissionAuditSource = 'enable' | 'first-call' | 'settings' | 'update' | 'uninstall';
type PermissionDenyReason = 'not_granted' | 'revoked' | 'out_of_scope' | 'user_rejected' | 'policy';

interface IPermissionAuditEntry {
  id: string;
  timestamp: string;
  action: PermissionAuditAction;
  source?: PermissionAuditSource;
  actor: 'user' | 'system';
  pluginId: string;
  pluginVersion: string;
  sessionId?: string;
  permission: string;
  qualifier?: string;
  capabilityId?: string;
  target?: string;
  resourceUri?: string;
  reason?: PermissionDenyReason;
  traceId: string;
  requestId?: string;
}
```

| 字段                         | 说明                                                   |
| ---------------------------- | ------------------------------------------------------ |
| `id`                         | 审计记录唯一标识（ULID）                               |
| `timestamp`                  | ISO 8601 UTC 时间                                      |
| `action`                     | `grant` 授予、`revoke` 撤销、`deny` 拒绝、`allow` 放行 |
| `source`                     | 授权变化来源；运行时记录缺省                           |
| `actor`                      | 操作者：`user` 用户操作、`system` 平台判定             |
| `pluginId` / `pluginVersion` | 触发插件及版本                                         |
| `sessionId`                  | 运行时判定所在会话                                     |
| `permission`                 | 判定的基础权限 ID                                      |
| `qualifier`                  | 解析后的限定值（变量已展开）                           |
| `capabilityId`               | 能力调用涉及的审计目标                                 |
| `target`                     | 本次调用目标（路径、域名、窗口 ID 等）                 |
| `resourceUri`                | 资源访问的目标 URI                                     |
| `reason`                     | 拒绝原因：未授予、已撤销、超出范围、用户拒绝、策略禁止 |
| `traceId`                    | 全链路追踪 ID，与日志标准一致                          |
| `requestId`                  | 单次请求 ID                                            |

注：运行时判定条目（`action` 为 `allow` / `deny`）的 `permission` 字段取值粒度补注——`deny` 为首个缺失项（与判定短路的缺失项口径同值）；`allow` 为本次判定 `required` 声明序首项（与短路判定同一序），其余所需权限经判定素材 `required` 全集可回溯，不扩条目形状、不在本表新增字段。一次判定产一条条目。该口径为 RFC-权限审计跨层采集sink裁定 §5.4 条 1、条 2 之在册裁定，本注即该裁定要求在《08.08》§8.2 落文的补注（任务 #173 落文，2026-09-23）。

### 8.3 输出与日志一致

- 审计记录落盘为 JSON Lines：`<userData>/logs/audit/audit-YYYY-MM-DD.jsonl`。
- 授予与运行时拒绝同时以标准事件对外广播（事件清单与 payload 见 [09-事件系统设计](./09-事件系统设计.md) 8.6 与 [05-事件契约规范](../../05-接口与契约/05-事件契约规范.md)）：
  - `permission:granted`：权限被用户或策略授予。
  - `permission:denied`：能力调用被权限判定拒绝。
- 撤销不新增专用事件；设置界面直接读取授权存储呈现变化。
- 字段命名与统一日志标准一致（`pluginId`、`traceId`、`requestId` 等），日志系统字段定义见 [09-事件系统设计](./09-事件系统设计.md)。

### 8.4 留存与轮转

- 按日切分；当日文件超过 10 MB 时切换到同日序号文件，保证写入延迟稳定。
- 留存期：常规审计至少 180 天；涉及高、极高风险权限的记录至少 365 天。
- 到期由平台清理；插件与一般应用无删除接口。
- 审计文件为追加写入（append-only），插件无读写权限；读取接口仅对平台内置设置界面开放。

### 8.5 脱敏规则

- 不记录凭证值、文件内容、网络请求体。
- 网络目标只记录 scheme、host 与 port，不记录 path 中的敏感查询参数。
- 不记录操作系统用户名与用户主目录之外的隐私信息；路径本身属于用户数据，仅记录到审计文件，不进入遥测。

### 8.6 crate 侧采集接口

本节为《RFC-权限审计跨层采集sink裁定》v1.0.1 §十.2 项①的文档面承接（任务 #178 落文，2026-09-23）。接口契约已随段四核心 crate 波（任务 #174，提交 `4fc78e476`）落地于 `chips-core` 的 `audit` 模块；**形状与签名登记面的权威**见 [03-核心接口规范](../../05-接口与契约/03-核心接口规范.md) §3.5，**素材字段与 §8.2 条目的逐字段映射权威**为 RFC §5.3 对齐表——本节只作契约指称与审计面分工锚定，不重定义字段表、不造第二权威。

**采集契约指称**：crate 侧权限判定出站信号的唯一接口为 `chips_core::DecisionObserver`（`Send + Sync + 'static` 单方法 trait，`on_permission_decision`）。线程与纪律语义按 RFC §六全部六条：判定收敛后在判定线程同步调用一次；observer 实现只允许「拷素材 → 入有界队列 → 立即返回」级别的工作（禁同步 IO、禁等待 JS 完成、禁获取可与判定面反向成环的锁、禁回灌判定面）；crate 发射侧一律经 `emit_permission_decision` 的 `catch_unwind` 包裹调用——observer panic 即该条素材丢失，判定结果与错误返回不受任何影响；一切发射点处于 crate 核心锁外。观察面独立于内核事件总线（RFC §七），crate 侧禁直接产生 §8.3 任何标准事件。

**素材面 / 条目面两分**（RFC §5.2）：crate 侧只出 `PermissionDecision` 判定素材（14 字段，其中 11 名可锚 §8.2 词表），不出 §8.2 全 16 字段条目——`id`（ULID）、`timestamp`、`source`、`actor`、`pluginVersion` 与留存档位（§8.4）、脱敏（§8.5）均由宿主组装面与写入侧补挂；附加素材 `required` / `missing` 供宿主组装与三事件 payload 校验，不落 §8.2 条目形状。运行时判定条目 `permission` 取值粒度已随 RFC §5.4 落为 §8.2 表注。

**挂点矩阵指称**（RFC §九 9.1，每判定实现处一挂点、禁双记录）：

| 判定实现点                                  | 审计挂点            | 状态与口径                                                                                   |
| ------------------------------------------- | ------------------- | -------------------------------------------------------------------------------------------- |
| 宿主 TS `createHostCapabilityRouter` 权限臂 | 宿主 `audit` 注入位 | 内核接线前唯一生效判定面；宿主挂波承接（工单046 段三）                                       |
| `chips-bridge` `admit` 权限段               | `DecisionObserver`  | 已落地：allow/deny 素材均锁外发射；bridge 域无直通臂，一切判定皆发（RFC §九 9.3-3）          |
| `chips-resource` `resolve` 判定收敛         | `DecisionObserver`  | 已落地：经授予判定的 allow/deny 发射（含 `policy` 类拒绝臂全发）；直通臂与非权限拒绝臂零素材 |
| `@chips/bridge` `createBridgeRouter` 审计钩 | 不挂任何新钩        | 生产调用方为零，随工单046 裁定三「二选一收口」处置                                           |

直通豁免口径与 §8.1 注同源（工单046 裁定二 / RFC §九 9.3-3）：Platform 公开只读恒放行、Plugin 自身作用域读、Document 会话绑定免重复校验三直通臂未经授予判定，**不发素材、不入审计**。登记性实测：任务 #174 criterion bench 测得 `resolve` 直通臂相对改前基线中位耗时增量约 +3.5%（未注入 observer 的改后形状），observer 实作增量（拷素材入队）另计；RFC §六条 6 明示不预造具体 µs / 百分比回归阈值，本数字为实测定量登记、非门禁阈值。

**注入位与当前落地边界**：observer 构造期注入、终身不可换——`Bridge::new(observer)` 与 `ResourceManager::new(limits, observer)`（RFC §八；两者的默认无观察 `Default` 形态已随实施波收口移除），无 setter、无热替换，审计观察面不存在无观察窗口。当前 `chips-native` 装配点注入 `NoopDecisionObserver`（构造签名翻正的编译随行）；真 observer 实现（素材序列化经非阻塞 Neon 通道投递 + 宿主 TS 消费函数接 §8.2 条目组装 → 段二写入器与 §8.3 三事件发射）归接线波（RFC §八条 2）。接线波落地前 crate 素材无消费者，现生效的运行时判定审计面仍为上表宿主 TS 臂；「判定面换轨、审计面不换轨」由单一条目组装器 + 单一写入器实例结构保证（RFC §九 9.2-2）。

**版本口径**（RFC §十）：本节接口为 crate 间 Rust 签名，比照《03-核心接口规范》§9.2 判例「crate 之间的 Rust 函数签名不属于 ABI」，`CORE_ABI_VERSION` 不变；不触 Neon 导出面，《03-核心接口规范》§8.6 导出总表零扰动。
