## 二、权限模型

### 2.1 核心概念

| 概念 | 定义 |
|------|------|
| 权限（Permission） | 对受保护对象（用户文件、网络目标、窗口、剪贴板、凭证等）的一次访问许可，是平台唯一的安全执行点 |
| 权限 ID | 权限的唯一标识，格式 `<domain>:<scope>[:<qualifier>]`（R3） |
| 权限申请 | 插件 manifest 的 `permissions` 列表，表达"该插件希望获得哪些权限" |
| 能力所需权限 | `ICapability.permissions`，表达"执行该能力必须持有哪些权限" |
| 授予（Grant） | 用户在授权交互中确认后写入授权存储的记录；授权是执行前提，不随插件代码或依赖传递 |
| 会话权限快照 | 插件启用时从授权存储物化的不可变授权集合，绑定 `sessionId` 与授权版本号 |
| 判定（Check） | 每次能力调用与资源访问时，用会话快照对能力所需权限及本次调用目标做匹配 |
| 审计（Audit） | 对授予、撤销与每次判定的不可变记录 |

权限与能力的关系（R3）：

- 能力 ID 描述"做什么"：`<domain>:<action>[:<target>]`，如 `file:read`、`window:create`。
- 权限 ID 描述"被允许访问什么"：`<domain>:<scope>[:<qualifier>]`，如 `filesystem:read`、`network:http:*.example.com`。
- **禁止同一标识既当能力又当权限**：`file:read` 永远是能力，`filesystem:read` 永远是权限。
- 调用判定按两者交集执行：插件实际持有（授予）∩ 能力所需（声明）全部满足才放行。
- 能力 → 权限的映射见 [4.3](#43-能力--权限映射r19)。

### 2.2 完整链路

```
       插件包（.cpk）                         平台（内核 / Bridge / 安全模块）
┌────────────────────────┐        ┌──────────────────────────────────────────────┐
│ manifest.yaml          │        │ ① 声明：安装与加载校验                        │
│   permissions:         │───────▶│   解析 → 语法校验 → 权限注册表校验 → 角色校验  │
│     - filesystem:read  │        │   能力声明校验（服务插件注册能力时）            │
│     - network:http:... │        └──────────────────────────────────────────────┘
└────────────────────────┘                              │
                                                        ▼
                                        ┌──────────────────────────────────────┐
                                        │ ② 授予：用户授权交互                  │
                                        │   启用确认 / 目标首次调用确认 / 设置面板 │
                                        │   → 授权存储 permissions.yaml          │
                                        └──────────────────────────────────────┘
                                                        │ 插件启用时物化
                                                        ▼
                                        ┌──────────────────────────────────────┐
                                        │ ③ 判定：Bridge 调用与资源访问前        │
                                        │   会话权限快照 ∩ 能力所需权限          │
                                        │   ＋ 调用目标与限定值匹配              │
                                        └──────────────────────────────────────┘
                                                        │ 授予 / 放行 / 拒绝      │
                                                        ▼
                                        ┌──────────────────────────────────────┐
                                        │ ④ 审计：审计日志 + permission:* 事件   │
                                        └──────────────────────────────────────┘
```

链路规则：

1. **声明与授予分离**：manifest 只表达申请，不产生任何运行时授权；没有用户授予，声明过的权限同样不可用。
2. **授予与执行分离**：授权只决定"资格"，限定值必须结合每次调用的实际目标（路径、域名、URI、窗口）判定。
3. **执行全部经过 Bridge**：插件访问系统能力只能经 `window.chips`（R17）；判定点唯一，不存在绕过入口。
4. **审计不可绕过**：授予变化与判定结果一律留痕，插件无法关闭、修改或删除审计。
