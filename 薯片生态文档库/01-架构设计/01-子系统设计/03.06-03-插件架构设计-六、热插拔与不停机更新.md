## 六、热插拔与不停机更新

### 6.1 热插拔语义

安装、启用、停用、卸载、更新全部在平台运行中完成，不重启平台、不影响其它插件。

| 操作 | 生效方式 |
|---|---|
| 安装 | 立即出现在插件列表（`installed`），不产生运行副作用 |
| 启用 | 进入 `active` 即生效：`basecard` / `boxlayout` 注册即时可被渲染引擎选用；`app` 出现在启动器与文件关联；`service` 在 `start()` 完成、暂存代际原子发布后生效 |
| 停用 | 立即摘除：新调用被拒绝；依赖者按逆拓扑序级联停用；已打开的视图按角色规则销毁或关闭 |
| 更新 | 蓝绿替换（§6.2）：平台不重启，切换窗口内插件保持可用，调用方不中断 |
| 卸载 | 立即移除入口、文件与注册记录；不影响其它插件 |

### 6.2 蓝绿更新流程

```
[1] 解析并校验新版本 .cpk（不触碰运行目录）
        │
        ▼
[2] 权限变化确认：新增权限项须用户接受，拒绝则取消更新、旧版本继续运行（《08-权限系统设计》）
        │
        ▼
[3] 版本范围检查：新版本必须满足全部已安装依赖者的 dependencies 范围，否则拒绝
        │
        ▼
[4] 写入暂存目录（staging）；旧版本继续运行
        │
        ▼
[5] 以新版本创建新 Fork 并激活：新 Fork 执行 Starting，旧 Fork 继续 Active，服务代际暂不切换
        │
        ├── 失败 → dispose 新 Fork、清理暂存目录；旧版本继续运行，插件保持 active
        ▼
[6] 服务代际原子切换：新 Fork 注册服务，注册表与路由指向新版本（原子切换点）
        │
        ▼
[7] 旧 Fork 进入 draining：拒绝新调用、等待进行中的调用结束，超时强制 dispose
        │
        ▼
[8] 更新注册表版本号，删除旧版本目录
```

### 6.3 角色差异与不中断保证

| 角色 | 更新行为 |
|---|---|
| `service` | 新 Fork 进入 `active` 时暂存代际一次原子发布，完成代际切换；服务名与能力 ID 保持不变；消费方经级联重建获得新代际（[01-薯片内核设计](01-薯片内核设计.md) §5.2、§5.4） |
| `basecard` / `boxlayout` | 新版本注册覆盖旧注册；后续渲染使用新版本；旧版本实例随旧 Fork draining 结束而销毁 |
| `app` | 更新只影响新启动的实例；已打开窗口保持旧版本直到全部关闭；窗口全关前旧 Fork 标记冻结、拒绝新调用，不强制撤销，避免丢失未保存状态 |

- 切换窗口内最多两个 Fork（旧、新）并存；代际切换后旧 Fork 不再处理新调用。
- 更新对调用方原子可见：一次调用要么由旧版本处理，要么由新版本处理，不存在两者同时处理同一请求。
- 内核视角的插件状态保持 `active`，不产生 `stopping → starting` 的插件级迁移（[01-薯片内核设计](01-薯片内核设计.md) §6.5）。
- **draining 上限仅适用于非 `app` 角色**：超时后强制 `dispose()` 旧 Fork 并记录诊断；`app` 角色在旧窗口全部关闭前只冻结、不强制撤销，窗口全关后再撤销旧 Fork（[01-薯片内核设计](01-薯片内核设计.md) §6.5）。

### 6.4 约束

- 插件目录在运行期只读；更新通过暂存目录原子替换，禁止原地修改运行中的文件。
- 新版本必须满足所有已安装依赖者的版本范围，否则更新被拒绝并列出不满足的依赖者；级联更新须调用方显式确认。
- 更新触发依赖者级联重建，重建顺序为拓扑序（[01-薯片内核设计](01-薯片内核设计.md) §5.4）。
- 权限集合变化必须重新确认，任何绕过授权变化的更新一律拒绝加载（[08-权限系统设计](08-权限系统设计.md)）。
- 禁止携带原生可执行载荷（R11），因此更新不需要重启进程。
- 更新中断（崩溃 / 断电）后，平台启动时清理暂存目录并回滚到旧版本。
- 开发态热重载复用同一套替换流程；调试方法见 [07-调试与发布](../../03-插件开发/07-调试与发布.md)。
