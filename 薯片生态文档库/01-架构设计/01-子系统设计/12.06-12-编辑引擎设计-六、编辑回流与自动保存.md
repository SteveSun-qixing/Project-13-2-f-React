## 六、编辑回流与自动保存

### 6.1 唯一时序

```
插件编辑器                 编辑链路                          文档服务            渲染会话
   │ change / getChange()    │                                │                  │
   │────────────────────────▶│ [1] 校验：configSchema          │                  │
   │                         │     + validateConfig            │                  │
   │                         │ [2] document:write ────────────▶│ 模型替换         │
   │                         │◀────────────────────────────────│ { revision }     │
   │                         │ [3] 组装新 DocumentView（revision）                 │
   │                         │ [4] update(view, revision) ────────────────────────▶│
   │                         │ [5] markCommitted(revision)      │                  │
   │◀────────────────────────│                                │                  │
   │                         │ [6] 自动保存防抖 → document:save │ 两阶段提交        │
   │                         │◀───────────────── { source,digest }│ 发布事件        │
```

顺序固定且不可交换：**校验 → `document:write` → 会话 `update` → `markCommitted`**（[11-文档服务设计](./11-文档服务设计.md) §6.1）。编辑链路不得跳过 `write` 直接 `update`，也不得在 `update` 失败时调用 `markCommitted`。

### 6.2 节点级变更与 `document:write` 扩展语义

| 编辑操作 | 写到哪个 part | `document:write` 载荷 | 历史栈 |
|---|---|---|---|
| 节点内容/配置变更 | `content` | `{ nodeId, value: 完整内容模型切片 }` | 一条记录 |
| 插入节点 | `structure` + `content` | `structure` 整体替换；`content` 以不存在的 `nodeId` + 初值创建成员 | 一条记录 |
| 删除节点 | `structure` + `content` | `structure` 整体替换；`content` 目标成员 `value: null` | 一条记录 |
| 重排节点 | `structure` | `structure` 整体替换 | 一条记录 |
| 卡片元数据（名称/标签/封面比例） | `metadata` | `metadata` 合并后的完整切片 | 一条记录 |
| 箱子条目增删改序 | `structure` + `entries` | `structure` / `entries` 模型切片 | 一条记录 |
| 布局配置 | `content`（箱子） | `layout_configs` 对应项替换（含 `schema_version`） | 一条记录 |
| 封面 HTML | —（资源写入） | 不经 `document:write`；`resources:write` 受控提交 | 不进入历史栈 |
| 封面资源导入/替换/删除 | —（资源登记） | 登记变更集，随下一次 `document:save` 落地 | 不进入历史栈 |

规则：

1. 插入节点的内容初值来源：优先调用插件 `createInitialContent()`；插件未提供或返回 `undefined` 时使用 `{}`（[08-基础卡片插件接口](../../05-接口与契约/08-基础卡片插件接口.md)）。
2. 节点 ID（`node_id`）由编辑链路生成，格式为 10 位 Base62，全局在卡片内唯一；插件不得自行生成或复用 ID。
3. `structure` 替换与内容成员变更必须在**同一次保存**中一致：不允许出现 `structure` 已引用而内容缺失的中间落盘状态（[11-文档服务设计](./11-文档服务设计.md) §4.4、§8.1）。
4. 卡片与箱子共用同一写链路：上述分支只发生在模型切片层，编辑链路的校验、写、update、历史与自动保存机制完全一致（R8）。
5. `writeCover(html)` 经资源管理受控提交写入 `.card/cover.html` / `.box/cover.html`（目录态立即落盘、归档态登记随保存重建），规则见[《文档服务设计》](./11-文档服务设计.md) §8.1；封面操作不提供资源级撤销（§7.1）。

### 6.3 自动保存

1. 触发来源有两条且都必须处理：编辑器 `change` 事件（驱动）+ 编辑链路定时/防抖（节流）；订阅后立即 `getChange()` 拉取一次，避免竞态。
2. 防抖默认 **500ms**，取值范围 100–5000ms；配置位于官方编辑引擎应用自身命名空间（见 §8.5），经配置系统读取，工作区层可覆盖（[10-配置系统设计](./10-配置系统设计.md) §2.3）。
3. 强制 flush 时机：窗口失焦/最小化、窗口关闭、切换文档/工作区、应用退出、用户显式保存（`save()`）。flush 表示"完成当前全部待提交回流后立即 `document:save`"。
4. 保存失败（`DOCUMENT_SAVE_FAILED`、`DOCUMENT_SOURCE_CHANGED`、`DOCUMENT_WRITE_CONFLICT`）时：保留编辑器脏状态与历史栈；展示简体中文错误与重试入口；自动保存退避重试（间隔 2s，最多 3 次），超限后停止自动重试并等待用户操作。
5. `dirty == false` 时 `save()` 是幂等 no-op（[11-文档服务设计](./11-文档服务设计.md) §4.5）。
6. 保存成功更新窗口标题与状态栏（"已保存"/"有未保存变更"），以 `document:saved` 为参考；编辑链路不依赖事件必达。
7. 应用退出前：编辑链路先 `flush()` 全部会话；未保存变更的确认交互由应用插件实现（[07-应用插件接口](../../05-接口与契约/07-应用插件接口.md)）。

### 6.4 预览更新预算

| 指标 | 要求 |
|---|---|
| 回流到预览可见更新 | ≤ 100ms（从 `document:write` 成功起算） |
| 合并窗口 | 同一动画帧（rAF）内到达的多次回流合并为一次 `update` |
| 序列化 | 会话级队列串行处理，不得并发 `update`（[05-渲染引擎设计](./05-渲染引擎设计.md) §10.3） |
| 失败语义 | `update` 失败返回 `RENDER_UPDATE_FAILED`，保留旧帧/旧容器内容，revision 不回退；编辑器保持可编辑并允许重试 |

规则：

- 高频输入（连续按键、拖拽调节）由编辑器自行合并变更（08 §4.3 第 4 条），编辑链路再做一次 rAF 合并，禁止逐键触发完整回流。
- 超过 100ms 预算的连续编辑按"最新状态优先"合并：中间 revision 不要求逐帧呈现，但每次 `document:write` 都必须成功推进 revision。
- 预览更新只更新受影响的节点容器与整体视图；未变化的节点不重建编辑器。

### 6.5 校验职责

| 校验 | 执行方 | 时机 | 失败 |
|---|---|---|---|
| `configSchema`（manifest 声明） | 编辑链路 | 每次回流前、保存前 | 拒绝回流，中文提示，保留编辑器脏状态 |
| `validateConfig`（插件纯函数） | 编辑链路（在插件上下文中调用） | 同上 | 同上 |
| 结构校验（kind/part/引用/标识） | 文档服务 | `document:write` / `document:save` | `DOCUMENT_STRUCTURE_INVALID` / `DOCUMENT_METADATA_INVALID` |
| 格式校验（schema、完整性） | 解析器 | `document:save` 写盘后 `validate` | `DOCUMENT_SAVE_FAILED`（回滚） |

- 校验顺序固定：先 `configSchema` 后 `validateConfig`；任一失败即 `EDIT_VALIDATION_FAILED`，不得"先写入再修正"。
- 编辑链路不得调用插件方法做结构校验；插件方法只在调用方上下文中执行（[11-文档服务设计](./11-文档服务设计.md) §6.2）。
