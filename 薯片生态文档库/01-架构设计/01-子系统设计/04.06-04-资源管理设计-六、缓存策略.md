## 六、缓存策略

### 6.1 缓存层级

| 层 | 内容 | 容量 | 生命周期 |
|---|---|---|---|
| L0 元数据缓存 | URI → size / mime / version | 4096 条 | 随作用域失效 |
| L1 内存字节缓存 | ≤ 8 MiB 的资源字节 | 64 MiB（字节加权 LRU） | 进程内，随作用域失效 |
| L2 外部磁盘缓存 | `http(s)` 响应体 | 512 MiB | 跨进程重启，遵循 HTTP 语义 |
| OS Page Cache | 目录与归档映射读取 | 系统管理 | 系统管理 |

### 6.2 LRU 与容量

- L1 以 `(scope, path, version)` 为键、按字节加权 LRU；单条超过 8 MiB 不入 L1。
- 淘汰时若条目被活跃流或进行中的读取钉住（pinned），标记 `evict_pending`，引用归零后淘汰。
- L2 仅服务 External 作用域，位于用户缓存目录，条目包含响应头副本与校验信息。
- 缓存统计（命中率、字节数、淘汰数、钉住数）由主进程日志输出用于诊断，不作为发布指标。

### 6.3 失效

| 来源 | 版本戳 | 失效方式 |
|---|---|---|
| DirectoryProvider | `mtime + size` | 读取前校验版本戳；`file:changed` 主动失效 |
| ArchiveProvider | 归档 `mtime + size` + 条目 CRC | 归档变化整体失效；`document:changed` 只刷新版本戳（不重建作用域），归档重建由文档保存流程触发并受同一路径锁保护 |
| PlatformProvider | 平台版本 | 平台升级时失效 |
| HttpProvider | `ETag` / `Last-Modified`，缺失时 TTL | 条件请求校验；TTL 过期惰性失效 |
| TemporaryProvider | 目标 `mtime + size` | 写入提交后刷新；作用域注销即失效 |

失效顺序：句柄转 `invalidated` → 通知 `onInvalidate` 订阅者 → 清理缓存条目 → 关闭底层读取器。进行中的读取允许完成当前 chunk，随后终止。

- 文档保存与外部修改的联动：`document:changed`（保存完成或外部修改收敛）只刷新对应作用域版本戳，随后按上表失效缓存与句柄；外部修改场景下查看会话按[11-文档服务设计](./11-文档服务设计.md) §7.2 冻结并提示重载，禁止旧模型消费新字节。

### 6.4 并发与一致性

- SingleFlight：以缓存键合并并发读取；首个调用执行后端读取，其余等待共享结果；完成后移除在途记录。
- 缓存只写入完整读取成功的结果；范围读不写入 L1；流式读取不写入字节缓存，只更新元数据。
- 有界队列：范围读与流式后端读取进入有界任务队列，队列超限返回 `RESOURCE_POOL_EXHAUSTED`，不无限堆积。
- 锁规则：绝不在持有锁时 `await`；取出 `Arc` 句柄后立即释放锁；每个缓存条目自带内部同步。
- 作用域失效与在途读取竞态：失效标记先于数据清理，在途结果提交时再次校验版本戳，过期结果丢弃。

### 6.5 缓存键

```rust
#[derive(Clone, PartialEq, Eq, Hash)]
pub struct ResourceKey {
    pub scope: ScopeId,
    pub path: VirtualPath,
    pub version: VersionStamp,
}
```

External 资源的键额外包含 origin；query 参与键，fragment 不参与。
