## 五、写入与原子性

### 5.1 会话模型的序列化

- 序列化目标与其权威规则：YAML 输出遵循[06-文档解析器设计](./06-文档解析器设计.md) §10.2（UTF-8 无 BOM、LF、2 空格缩进、键顺序稳定、歧义标量加引号、多行文本字面量块、RFC 3339 UTC），字段顺序与形状遵循[01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md) / [02-箱子文件格式](../../04-文件格式规范/02-箱子文件格式.md)。
- 只序列化被修订的成员与清单成员；未修订成员按原字节复制（归档态）或保持不动（目录态），不经过解析再序列化，避免无意义改写。
- 资源引用原样保持 R13 允许的形式；序列化前执行最终防写回校验：拒绝 `blob:`、`data:`、裸绝对路径、`file://`、`..` 穿越出现在内容配置、封面与资源清单中（R12/R13）。
- 相同模型在同一状态下序列化必须字节一致：键顺序、数值格式、引号策略、换行与时间格式全部确定化。

### 5.2 变更集与两阶段提交

```
阶段一（准备）                              阶段二（提交）
┌───────────────────────────────┐         ┌────────────────────────────────┐
│ 写日志 preparing（fsync）       │         │ 日志转 committing（提交点，fsync）│
│ 计算变更集（路径升序）           │  ────▶  │ 按日志顺序原子替换目标             │
│ 逐个写临时物 + fsync            │         │ 删除备份与临时物，删除日志         │
│ 校验：parse/validate、摘要      │         │                                │
│ 日志转 ready（fsync）           │         │                                │
└───────────────────────────────┘         └────────────────────────────────┘
```

- 变更集按包内路径 UTF-8 字节序升序处理；同一保存内的所有替换顺序确定。
- 提交日志先于临时物创建：日志生命周期为 `preparing`（开始）→ `ready`（阶段一校验通过）→ `committing`（提交点）→ 删除（提交完成）；任一步骤的日志写入都带 fsync。
- 提交点是 `ready → committing` 的状态迁移：此前崩溃＝未提交，目标文档未被触碰；此后崩溃＝已提交，按日志前滚补完剩余替换。
- 临时物位于包根的同级保留目录（与包根同卷，保证 rename 原子）；归档态的临时文件位于归档同级目录。临时物命名使用平台保留前缀 `.chips-save-<随机>`，绝不写入包内、不计入清单、不被解析器索引。
- 包根本身为挂载点导致跨卷时，保存确定性失败（`DOCUMENT_SAVE_FAILED`），不降级为包内临时物。

### 5.3 目录态工作副本

- 目录态文档的包根本身就是工作副本（[02-箱子文件格式](../../04-文件格式规范/02-箱子文件格式.md) §2.1）：保存只对变更集执行"临时物 + 原子替换"，不整目录重写。
- 文件替换：Unix 使用 `rename(2)`；Windows 使用 `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`（与[10-配置系统设计](./10-配置系统设计.md) §9.3 一致）。
- 目录态删除资源：阶段一把目标重命名进同级保留目录（备份），提交完成后删除备份；回滚时从备份恢复（§5.6）。
- 目录态拒绝符号链接逃逸：写入前对每个目标执行真实路径校验，结果必须位于包根内（[04-资源管理设计](./04-资源管理设计.md) §9.2）；符号链接不跟随、不替换。
- 目录态保存不改变源形态：不自动打包为归档；打包/另存统一经 `document:export`（§4.7）。

### 5.4 发布态 ZIP Store 重建

归档态文档（`.card` / `.box` 文件）保存时重建归档，规则以[01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md) §1.4、§11 与[02-箱子文件格式](../../04-文件格式规范/02-箱子文件格式.md) §2.3、§13 为准：

| 规则 | 内容 |
|---|---|
| 归档根 | 归档根即包根，直接包含 `.card/` / `.box/`、`content/`、资源与 `assets/`；不得出现顶层包裹目录 |
| 条目顺序 | 按包内路径的 UTF-8 字节序升序（与解析器有序索引一致，[06-文档解析器设计](./06-文档解析器设计.md) §3.3）；不写目录条目；不写系统生成物与编辑器临时文件 |
| 压缩方式 | 全部条目 Store（零压缩，`CompressionMethod::Stored`）；写入器重算 CRC32 与尺寸；发布不产生 ZIP64（读取侧支持 ZIP64，见[06-文档解析器设计](./06-文档解析器设计.md) §3.3；`.cpk` 禁 ZIP64） |
| 路径 | `/` 分隔、UTF-8 + NFC、无重复；与解析器索引口径一致（[06-文档解析器设计](./06-文档解析器设计.md) §3.3） |
| 成员时间戳 | 统一取保存时刻 UTC（保证同一次保存输出确定）；原始条目顺序与时间戳的还原属统一卡片传输模块（[01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md) §2.3），不在本服务 |
| 未变更成员 | 经映射切片顺序写出，不经过解压/解码；内存占用为常数，不整包载入内存 |
| 变更成员 | 由序列化结果与资源变更登记生成后写入 |
| 校验 | 写出完成后以解析器重新打开校验（`validate`），`Invalid` 视为保存失败并回滚（[06-文档解析器设计](./06-文档解析器设计.md) §6.5） |
| 落地 | 写入归档同级临时文件后原子替换；失败不触碰原文件；归档重建纳入 WriteCoordinator 的同一路径锁，与文档内其它写入（含资源导入）互斥，不存在双写者 |

归档重建、资源导入与 YAML 序列化都属于 document 挂载内的写入，统一经文档服务的受控提交路径执行（§2.1）；归档来源不接受就地改写，资源协议对它的 `commit_write` 返回 `RESOURCE_READ_ONLY`（[04-资源管理设计](./04-资源管理设计.md) §4.8）。

### 5.5 摘要与清单重算

摘要口径（唯一权威，供 `document:open` / `document:save` / `document:changed` / `file_info` 使用）：

| 摘要 | 定义 |
|---|---|
| 成员摘要 | 单个成员字节的 SHA-256 |
| 包内容摘要 | 按包内路径升序拼接 `path + "\0" + size + "\0" + 成员摘要 + "\n"` 后再取 SHA-256，输出 `sha256:<hex>` |
| 文件摘要 | 归档态最终归档文件字节的 SHA-256，输出 `sha256:<hex>` |
| 快速指纹摘要 | 打开时对源指纹（尺寸、修改时间、归档 CRC 等，见[06-文档解析器设计](./06-文档解析器设计.md) §5.4）的规范序列化摘要；不读取资源字节 |

| 输出位置 | 归档态 | 目录态 |
|---|---|---|
| `document:save` 的 `digest` | 文件摘要 | 包内容摘要 |
| `document:changed` 的 `digest` | 文件摘要（与同步引擎 §3.2 一致） | 包内容摘要（目录态不参与同步，见[07-同步引擎设计](./07-同步引擎设计.md) §2.4） |
| `metadata.file_info.checksum` | 包内容摘要 | 包内容摘要 |
| `document:open` 的 `digest` | 快速指纹摘要 | 快速指纹摘要 |

保存时同步重算（[01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md) §4.1、§5.3）：

- `metadata.file_info`：`total_size`（归档态为最终归档字节数，目录态为全部文件字节之和）、`file_count`（文件成员数，不含目录条目）、`checksum`（包内容摘要）、`generated_at`（保存时刻 RFC 3339 UTC）；`file_info` 的计算在写盘前完成，`checksum` 覆盖除自身以外的成员字节。
- `structure.yaml` 的 `manifest`（卡片）：`card_count` 等于 `structure` 数组长度；`resource_count` 等于 `resources` 长度；`resources[].size` 与 `checksum` 按真实字节重算或复用未变更资源的既有值（成员摘要一致）。
- 箱子依赖的摘要字段（`snapshot.last_known_modified_at`、`snapshot.cover` 等）由编辑链路提供，服务不猜测、不生成缺失值。

### 5.6 失败回滚与崩溃恢复

| 崩溃/失败点 | 磁盘状态 | 恢复动作 |
|---|---|---|
| 阶段一写入中（日志 `preparing`） | 临时物不完整，目标未变 | 删除临时物与日志；本次保存视为未提交 |
| 阶段一完成、日志未转 `committing` | 临时物完整，目标未变 | 删除临时物与日志（放弃本次保存） |
| 日志 `committing`、阶段二部分替换（目录态多目标） | 部分目标已替换 | 按日志前滚剩余替换（临时物完整） |
| 日志 `committing`、阶段二部分替换（归档态单目标） | 归档仍为旧字节或已被新字节整体替换，不存在部分状态 | 仅需清理临时物与日志；归档态只前滚，不适用备份回滚 |
| 阶段二替换失败（非崩溃，目录态） | 部分目标已替换 | 优先前滚；无法前滚时按日志用备份回滚，返回 `DOCUMENT_SAVE_FAILED` |
| 阶段二替换失败（非崩溃，归档态） | 归档未被触碰或已完整替换（单次 rename） | 保留旧归档、删除临时物，返回 `DOCUMENT_SAVE_FAILED`；归档态无备份回滚 |
| 提交完成、清理前 | 目标为新内容 | 删除备份、临时物与日志 |
| 会话关闭且未保存 | 目录态：无待提交物；归档态：无 | 丢弃模型与资源登记（§8.1） |

- 两态恢复语义差异：目录态的变更集是多个文件，可能需要备份回滚；归档态是"临时文件 + 一次原子 rename"的单目标提交，**归档态不适用备份回滚，只前滚或放弃**——提交点之前归档未被触碰，提交点之后只剩余清理工作，永不存在部分写入的归档。
- 恢复触发：平台启动与文档打开时扫描平台数据目录中的未完成提交日志；`preparing` / `ready` 回滚（删除临时物与日志），`committing` 前滚。提交日志先于临时物创建，因此不存在无日志的残留临时物；归档态临时文件与目录态同级保留目录同步清理。恢复动作写审计（不含文件内容）。
- 恢复优先级：前滚优先（临时物已通过阶段一校验，内容完整）；回滚仅在目录态临时物缺失或校验失败时执行。
- 恢复完成后重新取源指纹；若与任何活动会话基线不一致，该会话按外部修改处理（§7.2）。
- Windows 文件映射占用：替换前释放本服务的解析句柄与映射、失效资源作用域缓存；替换失败按 [06-文档解析器设计](./06-文档解析器设计.md) §4.3 的互不阻塞规则重试一次。

### 5.7 保存性能预算

| 项 | 预算 | 口径 |
|---|---|---|
| 目录态保存 | ≤ 200 ms | 变更集 ≤ 10 MiB（序列化 + 受控提交 + 原子替换） |
| 归档态保存 | ≤ max(500 ms, 归档大小 ÷ 20 MiB/s) | 重建 + 写后校验合计；10 MB 归档约 ≤ 500 ms |
| 峰值磁盘 | ≤ 2 × 归档大小 | 新归档临时文件 + 原归档（目录态为备份目录 + 变更集临时物） |
| 全量 `validate` 成本 | 按 [06-文档解析器设计](./06-文档解析器设计.md) §9.2：10 MB 卡片 ≤ 100 ms、10 000 条目箱子 ≤ 200 ms | 写后校验以归档态重新打开并全量解析，属于保存总预算，不允许"后台校验稍后完成"；校验超预算按保存失败处理并回滚 |
| 序列化 | 单成员 ≤ 5 ms | YAML 序列化按 [06-文档解析器设计](./06-文档解析器设计.md) §10.2 确定性规则 |

预算测量基线：本地 SSD、单核基准频率 ≥ 2.5 GHz、变更集 ≤ 10 MiB；超出预算的变更必须在同一变更中优化或以数据证明调整，不允许"后续优化"。

### 5.8 目录态与归档态差异清单

| 维度 | 目录态（工作副本） | 归档态（`.card` / `.box`） |
|---|---|---|
| 形态 | 包根目录；卡片在工作区中长期驻留，箱子目录只是编辑期内部工作副本（不作为正式文件形态，[02-箱子文件格式](../../04-文件格式规范/02-箱子文件格式.md) §2.1） | 单个 ZIP 归档，归档根即包根 |
| 写入方式 | 变更集逐文件临时物 + 原子替换（§5.3） | 整体重建 + 单次原子 rename（§5.4） |
| 资源导入 | 经受控提交立即落盘（§8.1） | 登记进会话，保存时统一落地（§8.1） |
| 崩溃恢复 | 备份回滚可用；前滚优先（§5.6） | 无备份回滚，只前滚或放弃（§5.6） |
| `digest` 口径 | 包内容摘要（§5.5） | 归档文件摘要（§5.5） |
| 同步 | 不参与同步（[07-同步引擎设计](./07-同步引擎设计.md) §2.4） | 保存后按 `document:changed` 纳入同步 |
| 被箱子引用 | 不可被 `url` 直接引用（`url` 只接受 `.card` / `.box` 归档；[02-箱子文件格式](../../04-文件格式规范/02-箱子文件格式.md) §3.2） | 可被 `url` 引用或作为内嵌卡片随箱子分发 |
| 与其他态转换 | 经 `document:export` 与归档互转（§4.7；卡片支持两向，箱子只有归档形态） | 同上 |

- 两态内容同构：同一文档在目录态与归档态必须产生一致的模型与诊断（[06-文档解析器设计](./06-文档解析器设计.md) §4.4 一致性夹具）。
- 两态转换（导入归档 → 目录态、目录态 → 归档导出、另存与工作区布局）的正式流程见[13-工作区设计](./13-工作区设计.md)；转换统一走 `document:export`（§4.7），不存在第二种转换实现。
- 目录态文档需要被箱子引用或参与同步时，必须先导出为归档态；工作区可同时驻留两态副本，二者以 `documentId` 识别为同一文档的两种形态。
