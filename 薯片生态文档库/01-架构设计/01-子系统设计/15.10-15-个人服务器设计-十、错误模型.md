## 十、错误模型

### 10.1 登记权威

1. 响应信封、HTTP 状态分类、个人服务器业务错误码登记表与 `ChipsError` 归一映射以[《个人服务器 API 契约》](../../05-接口与契约/12-个人服务器API契约.md) §七为唯一权威，本文不重复定义。
2. 传输控制面错误码（`CARD_TRANSFER_*` 与协议错误码）与客户端映射以[《卡片传输协议》](../../05-接口与契约/16-卡片传输协议.md) §八为唯一权威。
3. 客户端只按 `code` 分支，`message` 仅用于展示；`details` 只携带结构化诊断，不含凭证、预签名地址、真实路径与字节内容。

### 10.2 个人服务器的错误语义

| 语义 | 规则 |
|---|---|
| 单令牌鉴权 | 令牌缺失、格式错误与不匹配统一为 `API_TOKEN_INVALID`（401），不区分原因、不泄露校验细节、不锁定来源（§5.2）。 |
| 私密即不存在 | 私密作品在公开接口返回 `CARD_NOT_FOUND` / `BOX_NOT_FOUND`（404），与真正不存在不可区分；受控代理的缓存版本不匹配返回 `NOT_FOUND`（§3.3、§4.6）。 |
| 未就绪是状态冲突 | 没有查看产物不是"资源不存在"：返回 `CARD_RENDER_NOT_READY`（409），客户端展示"尚未渲染"而不是错误页；重新发布后恢复（§3.2）。 |
| 校验失败不可重试 | 请求体、对象归属、摘要、渲染入口与恢复清单校验失败一律为不可重试错误；客户端修正输入或重新发起发布，不原样重试。 |
| 过期要重建会话 | 上传会话过期后不得复用旧会话与旧预签名地址，必须重新创建会话并重新上传（《卡片传输协议》§8.5）。 |
| 服务类错误可有限重试 | 内部错误与依赖不可用属于可重试类；客户端按传输协议的退避策略有限重试，持续失败上报诊断。 |
| 服务器不经 `ChipsError` | 服务器是独立 HTTP 服务：响应使用登记的控制面/业务码；客户端传输引擎负责归一为 `ChipsError` 并保留 `code` / `httpStatus`（《卡片传输协议》§8.1）。 |

### 10.3 处理规则

1. 保留未启用的错误码不得出现在响应中；新增业务码必须先登记进[《个人服务器 API 契约》](../../05-接口与契约/12-个人服务器API契约.md)，涉及传输控制面的码必须先登记进[《卡片传输协议》](../../05-接口与契约/16-卡片传输协议.md)。
2. 错误响应不得包含对象键以外的内部标识、堆栈与存储地址。
3. 服务器日志只记录 `code` / `httpStatus` / 路由与耗时，不记录令牌、预签名地址与请求体字节（§9.5）。
