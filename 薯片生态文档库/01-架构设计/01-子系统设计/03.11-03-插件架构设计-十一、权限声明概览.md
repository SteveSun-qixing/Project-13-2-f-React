## 十一、权限声明概览

### 11.1 链路

```
manifest.permissions（插件申请集合）
        │ 安装校验：只登记申请集合（默认未授权），不产生授权
        ▼
首次启用：逐项授权交互（拒绝不阻断启用，被拒项保持未授权）
        ▼
授权记录（granted / denied / 未记录，由平台独占写入）
        │
        ▼
启用时生成会话快照（grantedPermissions）
        │
        ▼
运行时判定：申请集合 ∩ 能力声明的权限 ∩ 会话快照（含限定值）
        │
        ├── 通过 → 执行
        └── 拒绝 → ChipsError（BRIDGE_PERMISSION_DENIED）
```

### 11.2 规则

- 权限 ID 形如 `<domain>:<scope>[:<qualifier>]`（R3），如 `filesystem:read`、`network:http:*.example.com`。
- 能力声明自己需要的权限；插件清单声明申请集合；两者交集才可能被授权（R3）。
- **安装只登记申请、首次启用逐项授权**：拒绝任一项不影响启用，仅使该权限保持未授权；相关调用在运行时返回 `BRIDGE_PERMISSION_DENIED`（[08-权限系统设计](08-权限系统设计.md) 6.2）。
- 最小权限：未声明、未授权、超出限定值的调用一律拒绝；授权由用户在设置界面撤销与恢复，撤销后会话快照立即失效，后续调用拒绝，进行中的调用不中断。
- 停用不撤销授权；卸载删除授权记录与运行时快照（§4.5）。
- 拒绝必须返回结构化错误，不得静默失败；每次拒绝写入审计记录。

### 11.3 归口

权限模型、授权交互、路径与域名级限定、审计日志格式以 [08-权限系统设计](08-权限系统设计.md) 为准；能力与权限的映射示例见 [02-Bridge三层设计](02-Bridge三层设计.md) 与 [04-能力契约规范](../../05-接口与契约/04-能力契约规范.md)。
