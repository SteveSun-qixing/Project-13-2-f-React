## 十一、约束与不变量

1. **形状冻结**：`IChipsBridge` 仅有 `request` / `subscribe` / `resource` 三个方法，不含 `context()`；插件上下文由 Cordis 注入的 `ctx` 提供。方法面变更必须走 RFC。
2. **无旁路**：插件访问系统能力只能经 Bridge；禁止直接引用系统模块、直接使用 `ipcRenderer`、自建 IPC 通道。
3. **身份不可自报**：授权只依据 Bridge 层解析的来源会话，请求负载中的身份字段不参与授权。
4. **权限命名独立**：能力 ID 与权限 ID 不得相同；能力只能声明权限词表内的权限 ID。
5. **判定不可跳过**：能力存在 → 权限判定 → schema 校验三步对插件调用与平台内部调用一律适用。
6. **错误只认 code**：调用方必须按 `ChipsError.code` 处理错误，禁止匹配 `message` 文本。
7. **不自动重试**：Bridge 不重试、不去重执行；`retryable` 仅为提示。
8. **资源统一协议**：渲染进程访问资源一律经 `chips-resource://`；禁止 `file://` 直载包内资源；资源字节不经 IPC 通道传输。
9. **事件单向、发布走能力**：事件只由 Host 推向插件；插件发布事件必须经能力 `event:publish`，不存在独立发布通道。
10. **热路径常数开销**：权限判定与 schema 校验必须使用会话快照与注册期预编译结果，不得在调用路径重复编译或线性扫描。
11. **安全基线**：Electron 安全配置不得放宽；preload 只暴露 `IChipsBridge` 定义的方法面。
12. **文档同步**：本文与[01-Bridge-API规范](../../05-接口与契约/01-Bridge-API规范.md)、[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md)、[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md)必须同 PR 更新，接口改动不得只改一处。
