## 三、会话模型

### 3.1 文档记录与文档会话

`document:open` 的执行顺序：

1. 归一 `source` 为受管作用域 URI（`chips-resource://`；裸 `file://` / `http(s)://` 按[资源协议规范](../../05-接口与契约/06-资源协议规范.md)转受管形式）。
2. 解析到 L0（`CardParser::open` / `BoxParser::open`，自动识别与版本门禁见[06-文档解析器设计](./06-文档解析器设计.md) §3、§7）；`kind` 与探测结果矛盾时按解析器规则确定性处理。
3. 建立或复用文档记录（键为受管 URI），注册资源作用域（[04-资源管理设计](./04-资源管理设计.md) §5.2），构建内存模型初值。
4. 分配 `documentId` 并返回 `{ documentId, source, kind, title, digest }`；`digest` 为打开时的**快速指纹摘要**（不读取资源字节）。
5. 发布 `document:opened`（§7.3）。

同一会话内同一 `source` 复用同一 `documentId`；`documentId` 取值取自解析得到的文档稳定标识（`metadata.card_id` / `metadata.box_id`），因此跨会话稳定，与 `document:changed` 事件的 `documentId` 同口径。同一会话内不同 `source` 解析出相同稳定标识（违反[卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md) §4.3 的复制重新生成规则）时，后到的打开请求返回 `DOCUMENT_ID_CONFLICT`，确定性拒绝，不做静默合并。

### 3.2 会话状态

```rust
pub enum SessionRole {
    Writer,   // 持有写租约
    Reader,   // 尚未写入；获得写租约后转 Writer
}

pub struct Savepoint {
    pub revision: u64,
    pub source_fingerprint: SourceFingerprint,  // 解析器指纹，见 06 文档解析器设计 5.4
    pub content_digest: String,                 // sha256:<hex>，包内容摘要
}

pub enum ResourceAction {
    Import,    // 新资源入库
    Replace,   // 覆盖既有资源
    Delete,    // 移除资源
}

pub struct ResourceChange {
    pub path: PackagePath,
    pub action: ResourceAction,
    pub source: Option<String>,  // Import / Replace 的来源受管 URI；Delete 为 None
}

pub struct DocumentSession {
    pub id: DocumentId,
    pub source: String,                        // 受管作用域 URI
    pub kind: DocumentKind,                    // Card | Box
    pub role: SessionRole,
    pub revision: u64,                         // 内存模型修订号，与会话视图共享序列
    pub dirty: bool,
    pub savepoint: Option<Savepoint>,          // 打开后尚未保存时为 None
    pub source_fingerprint: SourceFingerprint, // 打开 / 上次保存时的基线
    pub externally_modified: bool,             // file:changed 提示的外部修改
    pub resources: Vec<ResourceChange>,        // 待提交的资源变更登记
    pub handle: Arc<DocumentHandle>,           // 解析器只读句柄（复用，不新建）
    pub model: SessionModel,                   // 可变内存模型
}

pub struct SessionModel {
    pub metadata: DocumentMetadata,
    pub structure: StructureModel,
    pub content: BTreeMap<NodeId, ContentNode>, // 卡片内容节点；箱子为空
    pub entries: Vec<Entry>,                    // 箱子条目；卡片为空
    pub layout_configs: Option<DocumentValue>,  // 箱子 .box/content.yaml 的布局配置
}
```

- 会话由拥有者（调用方渲染会话 / 插件 Fork）持有；服务不提供显式关闭入口（[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md) §7.3），随拥有者释放（§4.6）。
- 模型中的插件专有字段保持解析器的 `DocumentValue` 不透明表示（[06-文档解析器设计](./06-文档解析器设计.md) §11.3），服务不解释语义。

### 3.3 `documentId`、`source` 与 `kind`

本节是 `documentId` 的唯一权威口径：

| 字段 | 语义 | 稳定性 |
|---|---|---|
| `documentId` | 文档会话标识，取值＝稳定文档标识（`card_id` / `box_id`） | 同一文档跨会话、跨重命名稳定；是事件、缓存与跨模块引用的唯一来源 |
| `source` | 受管作用域 URI，会话的读写目标；`document:save` 原样返回 | 会话内不变；重命名通过文件系统事件表现为外部修改 |
| `kind` | `card` / `box`，打开时确定，决定格式适配层 | 会话内不变 |

- `documentId` 不是新生成的会话 ID，而是解析得到的稳定文档标识（`metadata.card_id` / `metadata.box_id`）直接投影；同一文档的多个会话共享同一 `documentId`，`document:changed`、同步链路与外部引用不得另立标识。
- `kind` 分支只发生在格式适配层：模型切片映射（§4.3）、schema 集与序列化成员（§5.1）；会话、修订、原子提交、事件与错误码对卡片与箱子完全一致。

### 3.4 修订、脏状态与保存点

- `revision` 从 1 开始，每次 `document:write` 成功推进 1；同一文档的渲染会话视图与编辑链路共享该序列（[05-渲染引擎设计](./05-渲染引擎设计.md) §8.3）。服务不接收 revision 参数（能力契约固定），双方以"每次成功写入恰前进一次"为不变量：`document:write` 的输出固定为 `{ revision }`，编辑链路的 `update(view, revision)` 与 `markCommitted(revision)` 只能使用该值；回退或跳号的会话视图由渲染会话按[05-渲染引擎设计](./05-渲染引擎设计.md) §2.4 拒绝。
- `dirty` 在 `document:write` 成功后为真，在 `document:save` 成功后为假；`dirty == false` 时 `document:save` 是幂等 no-op。
- `savepoint` 记录成功保存后的基线；`source_fingerprint` 是外部修改检测的依据（§7.1）。

### 3.5 句柄与租约生命周期（复用解析器句柄）

- 读：会话持有解析器 `DocumentHandle` 的 `Arc`，L0-L3 惰性层级、`revision`、`content_digest` 与诊断全部复用（[06-文档解析器设计](./06-文档解析器设计.md) §5）。
- 写：不新建解析句柄；`document:save` 完成后按新源指纹重建只读句柄（重新打开到 L0），旧句柄随最后一个引用释放。
- 资源字节：文档服务不持有资源句柄；资源读取由资源管理器按会话租约执行；保存的资源写入经受控提交接口，租约规则见[04-资源管理设计](./04-资源管理设计.md) §4.6、§10.1。
- 释放顺序：拒绝新请求 → 排空在途保存 → 释放解析句柄与映射 → 文档记录移除（§4.6）。释放幂等。

### 3.6 单文档单写者

- 文档记录维护唯一写租约：会话首次成功 `document:write` 时获得，`document:save` 成功或会话释放时归还。
- 未持租约的会话发起 `document:write` / `document:save`（dirty 非空时）返回 `DOCUMENT_WRITE_CONFLICT`，写者保存或释放后重试。
- 写者保存后，其他会话的源指纹基线失效，其写入与保存返回 `DOCUMENT_SOURCE_CHANGED`，必须重新打开；服务不提供自动合并或静默覆盖。
- 查看会话（不写入）不受影响：只读路径无租约要求。
