## 五、权限判定

### 5.1 权限模型（R3）

- 能力 ID：`<domain>:<action>[:<target>]`，例如 `file:read`、`dialog:save`、`window:create`。
- 权限 ID：`<domain>:<scope>[:<qualifier>]`，例如 `filesystem:read`、`network:http:*.example.com`、`filesystem:read:${userDocuments}`。
- `capability.permissions`：能力执行所需权限集合（注册时固化）。
- `manifest.permissions`：插件申请权限集合（安装时提交）。
- `grantedPermissions`：会话创建时由权限系统下发的已授予快照（[08-权限系统设计](./08-权限系统设计.md)），满足"申请集合 ∩ 用户授予"。

放行条件：`capability.permissions` 中的每一项都能在会话快照中匹配；即"申请集合 ∩ 能力声明 ∩ 会话快照"全部覆盖能力所需权限（[03-插件架构设计](./03-插件架构设计.md)）。能力不能扩大自身声明的权限需求，插件不能通过调用参数扩大权限。

### 5.2 判定流程

1. 解析来源会话（7.4 节）；会话不存在或已关闭 → `BRIDGE_SESSION_UNKNOWN`。
2. 读取能力的 `permissions` 集合；为空则直接通过本步。
3. 逐项在会话快照中匹配；带 `qualifier` 的权限按限定值规则匹配（路径前缀、域名通配、标识相等；算法以[08-权限系统设计](./08-权限系统设计.md)为准）。
4. 存在未匹配项 → 拒绝，返回 `BRIDGE_PERMISSION_DENIED`，`details` 结构见 5.4 节。
5. 全部匹配 → 放行，进入 schema 校验。
6. 判定结果（放行/拒绝）写入审计；审计格式与存储位置见[08-权限系统设计](./08-权限系统设计.md)。

```typescript
function matchesPermission(required: string, granted: ReadonlySet<string>): boolean {
  if (granted.has(required)) {
    return true;
  }
  const separator = required.lastIndexOf(':');
  if (separator < 0) {
    return false;
  }
  const prefix = `${required.slice(0, separator)}:*`;
  return granted.has(prefix);
}
```

上例仅说明"精确匹配 + 通配匹配"的基础形态；`qualifier` 的路径/域名匹配由权限系统实现，不在 Bridge 层自造规则。

### 5.3 判定时机与不可绕过

- 每次调用都在 Bridge 层判定；会话快照在授权变更时更新，判定为常数开销的集合匹配。
- preload 与渲染层可以基于会话快照做**快速失败预检**（如 `resource()` 同步抛错、`subscribe` 提前失败），但预检不是安全边界，权威判定始终在主进程 Bridge 层。
- Host 内部的资源级校验（目录穿越、符号链接、域名二次核对）是纵深防御，不替代 Bridge 判定。
- 平台内部会话使用平台内部权限集合，同样经过第 2 步至第 5 步，不得短路。
- 资源访问权限的判定入口在第十节，不走 `request` 链路。

### 5.4 拒绝、审计与错误

拒绝错误的 `details` 与权限系统共用同一结构（[08-权限系统设计](./08-权限系统设计.md)）：

```typescript
import { ChipsError } from '@chips/sdk';

type PermissionDenyReason = 'not_granted' | 'revoked' | 'out_of_scope' | 'user_rejected' | 'policy';

interface IPermissionDeniedDetails {
  capabilityId?: string;
  permission: string;
  required: string[];
  missing: string[];
  granted: string[];
  reason: PermissionDenyReason;
  target?: string;
}

const denied = new ChipsError({
  code: 'BRIDGE_PERMISSION_DENIED',
  message: '插件缺少所需权限：filesystem:read',
  details: {
    capabilityId: 'file:read',
    permission: 'filesystem:read',
    required: ['filesystem:read'],
    missing: ['filesystem:read'],
    granted: [],
    reason: 'not_granted',
  } satisfies IPermissionDeniedDetails,
  retryable: false,
});
```

- 拒绝信息只包含本次调用所需与缺失的权限，不暴露其他插件、其他会话的权限信息。
- 拒绝不可重试（`retryable: false`）；插件应引导用户到权限设置，不得静默降级后继续调用。
- 审计写入失败不阻塞调用，但必须记录内部告警。

### 5.5 能力 ID → 权限 ID 映射示例表

映射规则：

- 能力 ID 描述"做什么"，权限 ID 描述"可访问什么资源"；两个命名空间相互独立，**禁止同一标识既当能力又当权限**。
- 能力只能声明权限词表中的权限 ID；插件不得自造权限 ID。
- 平台内置能力的映射在[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md)固化；插件注册的能力只能组合既有权限。
- `qualifier` 用于把权限限定到路径、域名或标识；同一能力在不同限定下的授予结果互不影响。

| 能力 ID | 能力所需权限（`capability.permissions`） | 说明 |
|---|---|---|
| `file:read`、`file:list`、`file:watch` | `filesystem:read` | 读取文件内容、列举目录、监视文件变化 |
| `file:write` | `filesystem:write` | 写入、覆盖、追加 |
| `file:delete` | `filesystem:delete` | 删除文件 |
| `file:move` | `filesystem:write` | 移动/重命名文件或目录 |
| `file:copy` | `filesystem:read` + `filesystem:write` | 复制文件或目录 |
| `file:mkdir` | `filesystem:write` | 创建目录 |
| `resource:read` | `resources:read` | 读取资源句柄 |
| `resource:write` | `resources:write` | 经受控提交接口写入资源 |
| `document:open`、`document:read` | `resources:read` | 打开与读取文档 |
| `document:write`、`document:save` | `resources:write` | 写入与保存文档 |
| `document:export` | 源文档 `resources:read` + 目标路径 `filesystem:write` | 导入/导出/另存；不修改源文档 |
| `window:create`、`window:list`、`window:focus`、`window:close`、`window:resize`、`window:move`、`window:setTitle`、`window:setState` | `window:control` | 创建与控制窗口 |
| `menu:set` | `menu:manage` | 设置应用菜单与托盘菜单 |
| `tray:set` | `tray:manage` | 设置托盘图标与提示 |
| `shortcut:register`、`shortcut:unregister` | `shortcut:manage` | 注册与注销快捷键 |
| `system:info` | `system:read` | 读取平台与设备只读信息 |
| `power:query` | `power:read` | 查询电源状态 |
| `power:prevent-sleep` | `power:manage` | 阻止系统休眠 |
| `transfer:download`、`transfer:cancel` | `transfer:manage` + 目标路径 `filesystem:write` + URL 逐跳 `network:http` | 异步下载到目标路径 |
| `notification:send` | `notifications:send` | 发送系统通知 |
| `clipboard:read`、`clipboard:write` | `clipboard:access` | 读取与写入剪贴板 |
| `dialog:open`、`dialog:save` | `dialogs:use` | 系统文件对话框 |
| `shell:openExternal` | `shell:external` | 使用系统默认程序打开 URL 或文件 |
| `http:request` | `network:http[:<domain>]` | 按调用 URL 的 scheme 与 host 匹配限定值 |
| `config:get`、`config:snapshot` | `config:read:<namespace>` | 读取配置命名空间；自身命名空间免判定 |
| `config:set`、`config:reset` | `config:write:<namespace>` | 写入配置命名空间；自身命名空间免判定 |
| `credential:get`、`credential:set`、`credential:delete` | `credential:manage` | 仅自身命名空间 |
| `event:publish` | `events:publish` | 发布标准事件 |

限定值示例：`filesystem:read:${userDocuments}` 仅允许该文档目录前缀，`network:http:*.example.com` 仅允许匹配该通配的请求；路径限定必须使用目录变量，不得写裸绝对路径。平台会话已授权的资源句柄在会话内读取免重复校验；写入仍需 `resources:write`。完整权限词表与能力清单分别以[08-权限系统设计](./08-权限系统设计.md)、[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md)为准；资源句柄不通过能力 ID 申请权限，按第十节判定。
