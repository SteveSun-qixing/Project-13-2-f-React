## 二、总体架构

### 2.1 分层位置

```
渲染进程（应用插件 / 编辑链路 / RenderHost）
    │  window.chips.request('document:*')
    ▼
主进程 · Bridge 层（权限判定 · schema 校验 · 会话绑定 · 事件转发）
    │  Neon
    ▼
Rust 核心
  文档服务（会话编排 · 内存模型 · 变更集 · 原子提交 · 摘要）
    ├── chips-parser    DocumentHandle（只读、惰性、线程安全）
    └── chips-resource  ResourceManager（写入提交 · 作用域 · PathGuard · 缓存失效）
    ▼
文件系统：目录态工作副本 / ZIP Store 归档
```

- 文档服务是 `document:*` 能力的服务端实现，运行在主进程平台服务域；渲染进程与插件只能经 Bridge 访问（[02-Bridge三层设计](./02-Bridge三层设计.md)）。
- 读路径完全复用解析器句柄与资源管理器：不新建第二套读取、缓存或路径解析。
- 写路径唯一：目录态与归档态的全部写入都经文档服务的受控提交落地（内部经资源管理器 `commit_write` / `commit_write_stream`，纳入 WriteCoordinator 同一路径锁），不绕过 PathGuard 与作用域校验；`resource:write` 只对插件作用域与临时作用域开放，归档重建不产生第二个写者。

### 2.2 模块职责

| 模块 | 职责 |
|---|---|
| `session` | 文档记录表、会话建立与释放、写租约、`documentId` 分配与复用 |
| `model` | 内存模型构建（从解析结果）、模型切片读写、修订号推进、序列化输入准备 |
| `change` | 变更集登记（YAML 输出、资源导入/替换/删除）、依赖推导、冲突检测 |
| `commit` | 两阶段提交、临时物与备份、提交日志、崩溃恢复前滚/回滚（归档态无备份，只前滚或放弃） |
| `digest` | 成员摘要、包内容摘要、文件摘要；`file_info` 与资源清单重算 |
| `events` | `document:opened` / `document:changed` / `document:saved` / `document:closed` 发布 |
| `error` | `DOCUMENT_*` 错误归一与诊断透出 |

### 2.3 设计约束

- 会话模型不可跨会话共享可变状态；只读句柄（`Arc<DocumentHandle>`）可共享。
- 输出确定性：同一内存模型在同一状态下序列化产生相同字节；变更集按包内路径排序处理。
- 无全局写锁：写串行化粒度是文档记录；不同文档的保存互不阻塞。
- 不读取网络：保存只处理本地字节；网络资源卡片的 URL 原样保留（[01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md) §2.2）。
- 不在持有锁时执行 IO 或 `await`；临时物与日志的路径在提交前完成全部安全校验。
