## 三、Cordis 事件与 Bridge 事件

### 3.1 关系

事件总线只有一条：内核总线是唯一的事件源与投递中枢。Cordis 事件与 Bridge 事件不是两套系统，而是同一条逻辑总线的两个可见面：

- **Cordis 事件**：内核进程内的事件面，插件与平台组件通过 `ctx.on` / `ctx.emit` 使用，与 Context / Fork 生命周期绑定，支持 `internal:*` 内部事件。
- **Bridge 事件**：内核总线向渲染进程的**跨进程投影**，渲染进程通过 `window.chips.subscribe` 订阅；只承载公开事件的单向副本。

```
                    内核总线（唯一事件源）
                   ╱                      ╲
   Cordis 事件（进程内）              Bridge 事件（跨进程投影）
   ctx.on / ctx.emit                  window.chips.subscribe
   Fork 追踪、广播（Rust 同步         惰性转发、结构化克隆
   / JS 监听器入队）
```

### 3.2 边界

| 维度 | Cordis 事件 | Bridge 事件 |
|---|---|---|
| 所在位置 | 内核进程（主进程）内 | 主进程 ↔ 渲染进程 |
| 使用方式 | `ctx.on` / `ctx.once` / `ctx.emit` | `window.chips.subscribe(eventId, handler)`；发布经 `event:publish` 能力 |
| 事件范围 | 标准事件、插件自有域事件、`internal:*` | 仅[05-事件契约规范](../../05-接口与契约/05-事件契约规范.md)登记的公开事件 |
| 分发方式 | 广播：Rust 订阅者同步调用，JS 监听器经 Channel 异步入队 | 异步 IPC，按通道先进先出 |
| 生命周期 | 绑定 Context / Fork，卸载自动退订 | 绑定订阅句柄与渲染进程会话，窗口销毁自动清理 |
| 投递保证 | 至多一次（见第六节） | 至多一次（见第六节） |

### 3.3 转发规则

1. **白名单转发**：只有事件契约中登记的事件才允许跨进程；插件自有域事件默认不跨进程（需要跨进程时先登记为标准事件）。
2. **内部事件不转发**：`internal:*` 永不离开内核进程，插件不得订阅或依赖 `internal:*`。
3. **平台域不可伪冒**：保留域事件只能由平台发布；插件发布保留域事件会被拒绝（`EVENT_PUBLISH_DENIED`）。发布者身份由内核按调用上下文记录，渲染进程发布由 Bridge 在 `event:publish` 调用点绑定插件 ID，不取自调用参数。
4. **单向投影**：Bridge 事件不可再发布、不可改写、不可拦截；渲染进程之间的通信必须经内核往返，以保证契约统一与权限校验。

### 3.4 Bridge 订阅与发布

渲染进程订阅使用 R2 规定的形状：

```typescript
interface IChipsBridge {
  request<TOutput>(capabilityId: string, input?: unknown): Promise<TOutput>;
  subscribe(eventId: string, handler: (payload: unknown) => void): ISubscription;
  resource(uri: string): IResourceHandle;
}

interface ISubscription {
  dispose(): void;
}
```

- `subscribe` 同步返回订阅句柄；`handler` 只接收 payload，类型由事件契约定义，使用方必须做类型收窄。
- `dispose()` 幂等；同一事件可以建立多个互相独立的订阅。
- 订阅受事件契约声明的权限门控（见 5.3）；未授权的订阅不建立。
- 渲染进程发布事件必须经能力 `event:publish`（输入 schema 见《[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md)》），由内核校验权限后发布到总线，并按 3.3 绑定来源。

Bridge 事件相关错误码：

| 错误码 | 触发条件 | 返回方式 |
|---|---|---|
| `EVENT_ID_INVALID` | 事件 ID 不符合 `<domain>:<action>` | `subscribe` / 发布能力同步抛出 |
| `EVENT_NOT_REGISTERED` | 事件未在事件契约中登记 | `event:control` 错误回执；该订阅不触发 |
| `EVENT_SUBSCRIBE_DENIED` | 订阅者缺少事件契约声明的订阅权限 | `event:control` 错误回执；该订阅不建立 |
| `EVENT_PUBLISH_DENIED` | 发布被权限判定拒绝，或发布了平台保留域 | 发布能力拒绝 |
| `EVENT_PAYLOAD_UNSUPPORTED` | payload 不可结构化克隆 | 发布能力拒绝 |
| `EVENT_PAYLOAD_TOO_LARGE` | 序列化后超过 256 KiB | 发布能力拒绝 |

**示例：渲染进程订阅并正确退订**

```typescript
import type { ISubscription } from '@chips/sdk';

interface IFileChangedPayload {
  uri: string;
  kind: 'created' | 'modified' | 'deleted' | 'renamed';
  previousUri?: string;
}

export class FileBadgeView {
  private readonly subscriptions: ISubscription[] = [];

  /**
   * 挂载视图并订阅文件变更事件。
   */
  mount(container: HTMLElement, onChanged: (payload: IFileChangedPayload) => void): void {
    container.textContent = '监听文件变更中';
    this.subscriptions.push(
      window.chips.subscribe('file:changed', (payload: unknown) => {
        if (isFileChangedPayload(payload)) {
          onChanged(payload);
        }
      }),
    );
  }

  /**
   * 卸载视图并释放全部订阅。
   */
  unmount(container: HTMLElement): void {
    container.textContent = '';
    for (const subscription of this.subscriptions) {
      subscription.dispose();
    }
    this.subscriptions.length = 0;
  }
}

function isFileChangedPayload(payload: unknown): payload is IFileChangedPayload {
  if (typeof payload !== 'object' || payload === null) {
    return false;
  }
  const candidate = payload as Record<string, unknown>;
  const kind = candidate.kind;
  return (
    typeof candidate.uri === 'string' &&
    (kind === 'created' || kind === 'modified' || kind === 'deleted' || kind === 'renamed')
  );
}
```
