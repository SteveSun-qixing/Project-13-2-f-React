## 二、总体架构

### 2.1 结构总览

```
                    Node.js 主进程（薯片平台层）
        Bridge 能力 · 资源管理 · 渲染入口 · 文档服务（写入/导出）
                              │
                            Neon
                              │
┌─────────────────────────────▼─────────────────────────────┐
│                    Rust 文档解析子系统                      │
│                                                           │
│   CardParser      BoxParser      open_document（自动识别）  │
│        └──────────────┬──────────────┘                    │
│                 DocumentHandle（惰性、可共享、线程安全）    │
│        ┌──────────────┼──────────────┐                    │
│   流水线编排      校验体系        单元缓存                   │
│  （六阶段）    YAML·Schema·引用·完整性   增量重解析          │
│        └──────────────┼──────────────┘                    │
│                       │                                   │
│              DocumentSource（trait）                       │
│         DirectorySource        ArchiveSource              │
└───────────────────────┬───────────────────────────────────┘
                        │ std::fs · mmap
               目录态 / `.card` / `.box`
```

### 2.2 模块职责

| 模块 | 职责 |
|---|---|
| `parser` | 六阶段流水线编排；`CardParser` / `BoxParser` / `open_document` 入口 |
| `source` | 双模式数据源；`PackagePath` 校验；归档索引；零拷贝字节流 |
| `yaml` | YAML 引擎封装；结构化标量语义；按需 Span 索引 |
| `schema` | 内嵌 JSON Schema 注册表；按文件格式与成员类型选取；校验与诊断生成 |
| `model` | 类型模型；`DocumentValue`；模型构建与冻结；修订与统计 |
| `error` | `DocumentError`（致命）与 `Diagnostic`（非致命）两级错误模型 |
| `neon` | Neon 导出函数、参数编解码、错误归一、取消令牌 |

### 2.3 设计约束

- 解析结果不可变：模型一旦构建即冻结为 `Arc`，所有读取者共享同一份数据。
- 输出确定性：同一输入在任何平台、任何并发度下产生完全相同的模型与诊断序列（诊断按位置与码排序去重）。
- 无全局状态：解析器不持有可变的进程级单例；缓存由外部注入。
- 不读取网络：解析阶段只访问本地数据源；`http(s)://` 条目仅做语法分类，不发起请求。
- 纯 Rust 实现：跨平台行为一致，无平台特定格式分支。
