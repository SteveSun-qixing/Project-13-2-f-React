## 五、惰性加载与增量重解析

### 5.1 加载层级

| 层级 | 内容 | 触发时机 | 预算 |
|---|---|---|---|
| L0 | 元数据（`.card/metadata.yaml` / `.box/metadata.yaml`） | `open` 阶段自动完成 | 打开 ≤ 10 ms |
| L1 | 结构与引用（卡片 `.card/structure.yaml` 结构节点；箱子 `.box/structure.yaml` 条目索引） | 首次访问 `structure()` | ≤ 10 ms |
| L2 | 内容与配置（卡片 `content/*.yaml`；箱子条目分页与 `.box/content.yaml` 布局配置） | 渲染或编辑请求到具体单元时 | 按单元 |
| L3 | 资源字节（卡片根目录资源；箱子 `assets/`） | 资源管理器请求具体资源时 | 按访问范围 |

层级不可逆：访问高层级自动完成其依赖层级；已解析层级缓存于句柄，重复访问为常数时间。渲染层按需触发，未渲染的节点不付出解析成本。

### 5.2 句柄与状态

```rust
pub struct DocumentHandle {
    source: Arc<dyn DocumentSource>,
    kind: DocumentKind,
    metadata: Arc<DocumentMetadata>,          // L0：打开时完成
    structure: OnceLock<Arc<StructureModel>>, // L1
    content: RwLock<HashMap<NodeId, Arc<ContentNode>>>,
    entries: RwLock<Option<Arc<[Entry]>>>,
    diagnostics: RwLock<Vec<Diagnostic>>,
    options: ParseOptions,
}

impl DocumentHandle {
    pub fn metadata(&self) -> Arc<DocumentMetadata>;
    pub fn structure(&self) -> Result<Arc<StructureModel>>;
    pub fn content(&self, node: &NodeId) -> Result<Arc<ContentNode>>;
    pub fn entries(&self, range: Option<Range<usize>>) -> Result<Arc<[Entry]>>;
    pub fn layout_config(&self) -> Result<Arc<DocumentValue>>;
    pub fn read_resource(&self, path: &PackagePath, range: Option<Range<u64>>) -> Result<ByteStream>;
    pub fn diagnostics(&self) -> Vec<Diagnostic>;
    pub fn revision(&self) -> DocumentRevision;
    pub fn content_digest(&self) -> Result<[u8; 32]>;
    pub fn validate(&self) -> Result<ValidationReport>;
    pub fn statistics(&self) -> DocumentStatistics;
}
```

- 句柄为 `Send + Sync`，内部可变状态由 `OnceLock` / `RwLock` 保护；同一句柄可被多个消费者共享。
- `NodeId` 与条目顺序由格式规范定义；解析器不发明标识。
- 所有错误返回 `DocumentError`，所有非致命问题追加到句柄诊断集合。
- `layout_config()` 仅供箱子句柄调用（L2 布局配置单元）：返回 `.box/content.yaml` 根值（《箱子文件格式》§6 的 `layout_configs` 布局配置），是文档视图构建器（《核心接口规范》§6.6）构建箱子视图的依赖入口。文件缺失或校验失败按 §8.4 部分成功语义返回空映射占位并携带错误级诊断（生效布局不可用，视图侧按空配置渲染）；卡片句柄调用按格式误用归一返回 `DOCUMENT_FORMAT_UNKNOWN`。
- `statistics()` 返回只读统计快照（§3.7）：结构未加载时资源/条目计数为 0，已解析 YAML 字节数随惰性层级推进。

### 5.3 并行与缓存

- 单元解析并行执行：使用受 `parallelism`（默认 4）限制的线程池，单单元内部串行。
- 诊断为共享结果，写入顺序无关；最终排序去重保证确定性。
- 单元缓存：`ParseCache` 以 `(规范化路径, 成员指纹)` 为键保存解析单元 `Arc`，LRU 淘汰并带内存配额；句柄级缓存与单元级缓存分离，后者跨修订复用。
- 缓存不持有过期数据源映射；数据源指纹变化即整体失效该路径的句柄条目，但可按单元指纹保留未变化单元。

### 5.4 增量重解析

修订比较以成员指纹为单位：

```
修订 A 指纹：[.card/metadata.yaml(s,m,crc), .card/structure.yaml(s,m,crc), content/a1B2c3D4e5.yaml(s,m,crc), content/f6G7h8I9j0.yaml(s,m,crc)]
修订 B 指纹：仅 content/a1B2c3D4e5.yaml 变化
结果：复用 metadata 与 structure 单元；仅重新解析 content/a1B2c3D4e5.yaml；句柄重建成本 ≈ 单文件解析
```

- 目录态成员指纹 = 尺寸 + 修改时间（内容哈希按需）；压缩态成员指纹 = 尺寸 + CRC32 + 修改时间。
- 索引摘要变化（成员增删或路径变化）时，结构引用校验必须重跑；内容单元按指纹复用。
- 外部变更通知（文件监听事件）触发重新取指纹，而不是直接失效全部缓存；解析器不自行轮询。
