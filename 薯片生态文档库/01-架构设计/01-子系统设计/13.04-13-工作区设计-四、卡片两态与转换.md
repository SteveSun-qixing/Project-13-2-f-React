## 四、卡片两态与转换

### 4.1 两种形态的分工

| 维度 | 目录态（`*.card/`） | 归档态（`*.card`） |
|---|---|---|
| 定位 | 工作形态：长期驻留工作区，持续编辑 | 交付形态：分享、同步、归档、备份 |
| 文件系统表现 | 目录，成员原样可见可编辑 | ZIP Store 单文件（[01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md) §1.4） |
| 打开成本 | 低（目录枚举 + 惰性读取） | 中（中央目录 + 按需成员读取） |
| 保存方式 | 只写变更集（临时物 + 原子替换） | 重建归档后整体原子替换（[11-文档服务设计](./11-文档服务设计.md) §5.3、§5.4） |
| 资源导入 | 立即落盘（受控提交） | 登记变更集，保存时统一落地 |
| 同步 | 不参与同步（[07-同步引擎设计](./07-同步引擎设计.md) §2.4） | 同步单元，参与同步 |
| 外部工具 | 可见可改，改动表现为外部修改 | 标准 ZIP，可被第三方读取 |

箱子的正式形态只有单文件 `.box`（[02-箱子文件格式](../../04-文件格式规范/02-箱子文件格式.md) §2.1），不存在"箱子目录态"：编辑过程中的解包目录是临时工作目录（§4.5）。

### 4.2 `document:export` 能力

```typescript
type DocumentExportForm = 'archive' | 'directory';

interface IDocumentExportInput {
  documentId: string;
  form: DocumentExportForm;
  target: string;                 // 受管引用：工作区作用域路径或临时作用域路径
  overwrite?: boolean;            // 默认 false
}

interface IDocumentExportOutput {
  target: string;
  form: DocumentExportForm;
  digest: string;                 // archive：文件摘要；directory：包内容摘要（口径见 11 §5.5）
}
```

规则：

1. 能力 ID `document:export` 覆盖导入、导出与另存：`directory → archive` 为导出；`archive → directory` 为导入；`directory → directory` / `archive → archive` 为另存。
2. 权限映射：源文档 `resources:read`；目标落点 `filesystem:write`（目标位于工作区内时以 `${workspace}` 限定值匹配；目标为 `dialog:save` 临时作用域时免权限）。该映射随能力登记进[《能力契约规范》](../../05-接口与契约/04-能力契约规范.md)。
3. `target` 必须是受管引用，不得是裸绝对路径（R13）；`target` 落在保留区或保留前缀内返回 `WORKSPACE_RESERVED_PATH`。
4. 目标已存在且 `overwrite` 为 `false` 时返回 `RESOURCE_ALREADY_EXISTS`；`overwrite: true` 时先完整写入临时物、校验通过后原子替换，替换失败保留原目标。
5. 导出前必须通过源文档 `validate`：`Invalid` 拒绝导出；`ValidWithWarnings` 允许但返回诊断。
6. 导出按目标形态重算并写回 `metadata.file_info` 与资源清单（口径见[《文档服务设计》](./11-文档服务设计.md) §5.5）；导出结果的 `digest` 与 `output.target` 一并返回。
7. `document:export` 不改动源文档：导出不修改源形态、不改变源会话的 savepoint；`directory → archive` 导出后源目录态继续可编辑。
8. 导出使用平台保留前缀暂存（`.chips-export-<随机>`，与目标同卷），保证原子重命名；崩溃残留由启动恢复清理。
9. `form` 受文档类型约束：卡片支持 `archive` 与 `directory`；箱子只有单文件形态，仅支持 `archive`，对箱子请求 `directory` 返回 `DOCUMENT_PART_UNSUPPORTED`（kind / form 组合不受支持，沿用[《文档服务设计》](./11-文档服务设计.md) §10.2 语义）。

### 4.3 导入归档到工作区（正式流程）

导入是"把交付形态落地为工作形态"的正式动作，全部经平台链路：

```
[1] 用户提供来源：dialog:open 选择 *.card，或拖入工作区，或从插件市场/下载链路落地
        │
        ▼
[2] document:open（来源归档）── 版本门禁与解析校验（04-版本与迁移规范 §5）
        │ 不满足 → DOCUMENT_VERSION_OUTDATED / DOCUMENT_VERSION_UNSUPPORTED，
        │           提示运行迁移工具（Phase 4 交付），不自动改写
        ▼
[3] 名称落点：<workspace>/<元数据名称或文件名>.card/
        │ 冲突 → 追加 -2 / -3 后缀（§3.3）
        ▼
[4] document:export { form: 'directory', target: 落点 }
        │ 目录态构建在 .chips-export-<随机> 内 → validate → 原子重命名到落点
        ▼
[5] 关闭来源归档会话（document:* 会话随拥有者释放）
        ▼
[6] document:open（落点目录态）── 作为新的编辑工作副本；导入结果（路径、摘要、警告）展示给用户
        ▼
[7] 可选：用户确认删除来源文件（file:delete，filesystem:delete）
```

规则：

1. 导入必须是**复制语义**，默认不改动来源文件；删除来源必须经用户显式确认。
2. 导入结果必须是可编辑的目录态工作副本；禁止在导入后继续把归档态当作工作副本编辑。
3. 版本门禁在步骤 [2] 判定：与平台支持的文档格式主版本不一致即失败；次版本高于平台记 `DOCUMENT_VERSION_MISMATCH` 警告并透出诊断（[04-版本与迁移规范](../../04-文件格式规范/04-版本与迁移规范.md) §5.1）。
4. 资源清单校验：归档内的 `manifest.resources` 与实际成员不一致、资源缺失或摘要不匹配时，导入失败并返回解析诊断（[06-文档解析器设计](./06-文档解析器设计.md) §6.4）。
5. 导入过程逐文件独立：单个文件失败不影响其它导入任务（批量导入时）。
6. 导入完成后，落点目录态文档的 `file_info` 与资源清单已按目录态口径重算（§4.2 第 6 条），无需再次保存。
7. 同步引擎回落的远端新文档同样按本节受控导入流程落地；同步引擎不直接写工作区文件（[07-同步引擎设计](./07-同步引擎设计.md) §4.4）。

### 4.4 导出归档（交付形态）

1. 目录态 → 归档态的导出即"打包交付"：使用 `document:export { form: 'archive' }`，目标常为工作区内的 `*.card` 或经 `dialog:save` 选择的位置。
2. 归档必须满足 ZIP Store、归档根即包根、路径字节序升序、无系统生成物与编辑器临时文件（[11-文档服务设计](./11-文档服务设计.md) §5.4）；不得使用第三方打包工具改写成员顺序或压缩方式。
3. 导出归档不参与同步的状态变化：同步引擎以归档态文件为同步单元，导出完成后按 `document:changed` / `file:changed` 检测（[07-同步引擎设计](./07-同步引擎设计.md) §3.1）。
4. 卡片与箱子导出共用同一条链路与同一能力；差异只在目标扩展名与格式适配层（R8）。

### 4.5 箱子单文件与临时解包工作目录

1. 工作区中的箱子始终是单个 `.box` 文件；平台不创建"箱子目录"，不把解包目录暴露给用户或文件树。
2. 编辑期需要目录形态时，文档服务在归档同级保留目录创建临时解包工作目录：`<归档同级>/.chips-unpack-<随机>/`（与归档同卷）；该目录不进入扫描、不被解析器作为文档打开、不参与同步。
3. 保存时按[《文档服务设计》](./11-文档服务设计.md) §5.4 重建归档并原子替换；重建成功后删除解包目录；失败保留解包目录并保留脏状态，由用户重试。
4. 崩溃残留：解包目录登记在 `.chips/state/cleanup.json`（工作区内）或平台用户数据目录（工作区外），启动时按登记清理。
5. 归档态就地写入一律返回 `RESOURCE_READ_ONLY`（[04-资源管理设计](./04-资源管理设计.md) §3.3），一切写入经文档服务保存流程。

### 4.6 转换的原子性、版本门禁、摘要与资源清单

| 项 | 规则 |
|---|---|
| 原子性 | 所有导出/导入/另存先写同级平台保留临时物，`validate` 通过后原子重命名；失败不触碰目标与原文档 |
| 版本门禁 | 转换不迁移版本：来源 `chip_standards_version` 不满足平台支持范围时确定性失败，提示迁移工具（Phase 4） |
| 摘要 | 结果摘要按目标形态口径：归档态为文件摘要，目录态为包内容摘要；与 `file_info.checksum` 同口径（11 §5.5） |
| 资源清单 | 按实际成员重算 `manifest.resources` 与 `asset_refs`；缺失资源、包外路径、`data:` / `blob:` 引用拒绝转换 |
| 覆盖策略 | 默认不覆盖；显式 `overwrite: true` 时仅原子替换目标，源文档不变 |
| 幂等性 | 相同源与相同目标形态重复导出产生字节一致的产物（成员顺序、时间戳口径见 11 §5.4） |
