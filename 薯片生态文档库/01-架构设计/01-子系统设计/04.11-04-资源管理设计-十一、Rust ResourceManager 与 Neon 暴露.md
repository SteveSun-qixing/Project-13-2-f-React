## 十一、Rust ResourceManager 与 Neon 暴露

### 11.1 核心结构

```rust
pub struct ResourceManager {
    scopes: Arc<ScopeRegistry>,
    providers: Arc<ProviderRegistry>,
    cache: Arc<CacheStore>,
    handles: Arc<HandleTable>,
    inflight: Arc<SingleFlight>,
    limits: ResourceLimits,
}

pub struct OpenRequest {
    pub uri: String,
    pub session: SessionId,
}

pub struct OpenHandle {
    pub id: HandleId,
    pub metadata: ResourceMetadata,
}

pub struct WriteRequest {
    pub scope: ScopeId,
    pub path: VirtualPath,
    pub bytes: Vec<u8>,
    pub session: SessionId,
}

pub struct WriteStreamRequest {
    pub scope: ScopeId,
    pub path: VirtualPath,
    pub session: SessionId,
    pub expected_size: Option<u64>,   // 流式写无法预知时可省略；完成后按实际尺寸登记
}

pub struct FsOpRequest {
    pub session: SessionId,
    pub source: ResourceAddress,
    pub target: Option<ResourceAddress>,   // rename/copy/move 需要；delete/mkdir 为 None
    pub recursive: bool,                    // 仅 delete 使用
}

impl ResourceManager {
    pub fn new(limits: ResourceLimits) -> Self;

    pub fn register_provider(&self, provider: Arc<dyn ResourceProvider>) -> Result<(), ChipsError>;

    pub fn register_scope(&self, registration: ScopeRegistration) -> Result<ScopeId, ChipsError>;
    // 注销常驻作用域：核心签名不动如实写（不设会话参数，未在册回 `RESOURCE_NOT_FOUND`，
    // 非幂等，OQ-4 实读）。绑定层 `resourceUnregisterScope(scope, sessionId)` 先行
    // 会话归属闸、未绑定即拒——见 §11.3「挂载/注销会话闸」注记。
    pub fn unregister_scope(&self, scope: &ScopeId) -> Result<(), ChipsError>;
    pub fn register_temp_scope(&self, path: PathBuf, writable: bool) -> Result<ScopeId, ChipsError>;

    pub async fn open(&self, request: OpenRequest) -> Result<OpenHandle, ChipsError>;
    // N-1 句柄归属闸：四方法携带 `session`，与句柄在册归属比对，跨会话以
    // 在册拒绝形 `RESOURCE_PERMISSION_DENIED` 收口（见 §11.1 注记）。
    pub async fn stat(
        &self,
        handle: HandleId,
        session: SessionId,
    ) -> Result<ResourceMetadata, ChipsError>;
    pub async fn read_range(
        &self,
        handle: HandleId,
        session: SessionId,
        range: ByteRange,
    ) -> Result<Vec<u8>, ChipsError>;
    pub async fn read_chunk(
        &self,
        handle: HandleId,
        session: SessionId,
        max_bytes: usize,
    ) -> Result<Option<Vec<u8>>, ChipsError>;
    pub fn release(&self, handle: HandleId, session: SessionId) -> Result<(), ChipsError>;

    pub async fn commit_write(&self, request: WriteRequest) -> Result<ResourceMetadata, ChipsError>;
    pub async fn commit_write_stream(
        &self,
        request: WriteStreamRequest,
    ) -> Result<ResourceMetadata, ChipsError>;

    // 文件系统操作（4.9、4.10）
    pub async fn list_directory(&self, address: &ResourceAddress) -> Result<Vec<DirectoryEntry>, ChipsError>;
    pub async fn delete(&self, request: FsOpRequest) -> Result<(), ChipsError>;
    pub async fn rename(&self, request: FsOpRequest) -> Result<(), ChipsError>;
    pub async fn copy(&self, request: FsOpRequest) -> Result<ResourceMetadata, ChipsError>;
    pub async fn create_directory(&self, address: &ResourceAddress) -> Result<(), ChipsError>;

    pub fn invalidate_scope(&self, scope: &ScopeId, reason: InvalidateReason);
}
```

> **N-1 句柄归属闸（安全巡检残项复核 §一.1 交回上收）**：`stat` / `read_range` /
> `read_chunk` / `release` 四方法携带 `session: SessionId`，服务端以句柄在册归属
> （`HandleTable` 条目的 `entry.session`，`open` 时登记）比对调用方会话，跨会话
> 以在册拒绝形 `RESOURCE_PERMISSION_DENIED`（`details.permission = "session"`、
> `reason = "out_of_scope"`、`target` = 句柄规范 URI）收口。归属闸次序为「状态闸
> 先行、归属闸后行」——未知/墓碑句柄仍按原口径挂 `RESOURCE_HANDLE_RELEASED` /
> `RESOURCE_HANDLE_INVALIDATED`，`release` 对未知 ID 保持幂等；`read_chunk` 归属
> 比对先于流槽位占用，越权拒绝零副作用（不抢流、不还租约）。此为 `chips-resource`
> 内部 Rust API，**不是** §11.3 Neon 导出面（后者签名只增不改，见 §11.3 注记）。

### 11.2 资源会话

```rust
pub struct ResourceSession {
    pub id: SessionId,
    pub kind: SessionKind,   // Document | Plugin | Window
    pub owner: PluginId,
    pub scopes: Vec<ScopeId>,
}

impl ResourceManager {
    pub fn open_session(&self, kind: SessionKind, owner: PluginId) -> Result<SessionId, ChipsError>;
    pub fn derive_session(
        &self,
        parent: SessionId,
        scopes: &[ScopeId],
    ) -> Result<SessionId, ChipsError>;
    pub fn close_session(&self, session: SessionId) -> Result<(), ChipsError>;
}
```

派生子会话用于渲染帧内的基础卡片与布局插件：只继承父会话允许的作用域子集，父会话关闭时级联关闭；不允许扩权。

> **导出面签名不动与归属会话来源（N-1）**：`resourceStat` / `resourceRead` /
> `resourceReadChunk` / `resourceRelease` 四导出的 JS 参数表**保持只携带
> `handleId`、不携带会话源**（导出面只增不改、`coreAbiVersion` 不随动，三方锁账
> 该波 49 项零漂移）。§11.1 归属闸所需的 `session` 由绑定层进程级「句柄↔会话归属账」
> 供给：`resourceOpen`（入参已带 `sessionId`）成功时记账 `handleId → sessionId`，
> 四句柄导出回取归属会话再交 `chips-resource` 复核；`resourceRelease` 成功与
> `resourceCloseSession`（级联释放）对应清账。未在册句柄回哨兵会话（恒不匹任何
> 真实会话，因真实 ID 受 2^53 约束），且状态闸先行，故对外行为与收口前逐字一致
> （`RESOURCE_HANDLE_RELEASED`），注册表失同步时 fail-closed。此即「绑定层保证只有
> 在册句柄放行」的最小形态。

> **挂载/注销会话闸（N-1 注记族追加，工单036 波 A1 落位，任务 #209）**：
> `resourceMountDirectory` / `resourceMountArchive` 两挂载导出的 `sessionId` 为
> **必填活体闸**——会话不存在即 `RESOURCE_PERMISSION_DENIED`
> （`details.reason = "out_of_scope"`、`target` = scope 规范 URI，不回显真实路径），
> 在册会话由核心 `mount_directory` / `mount_archive` 以 `(session, registration)`
> 一体完成「注册 + 挂根/挂档 + 绑会话」，任一步失败全量回滚、无半挂载残留
> （波 A1 锁测在册）。`resourceUnregisterScope` 的会话闸由**绑定层补齐**：核心
> `unregister_scope(&ScopeId)` 不设会话参数（§11.1 签名不动如实写），绑定层以
> `sessionId` 查在册会话、`scope` 不在其绑定集合即前置拒绝（同 `out_of_scope` 形），
> 通过后再交核心执行；注销成功级联脱绑后二次注销命中同闸（绑定形
> `RESOURCE_PERMISSION_DENIED`），直调核心则 `RESOURCE_NOT_FOUND`（核心形）——
> 幂等性依核心实读、两形双闸锁测在册（OQ-4 裁定不做静默吞错）。三导出 `kind`
> 面在绑定层钉死 `ScopeKind::Document`（JS 面无 `kind` 参数；越名前缀由核心
> 命名闸拒绝，见下「挂载 scope 派生规则」）；目录域 `writable` 直译核心
> `policy.read_only`，归档域只读强制（写路径拒 `RESOURCE_READ_ONLY`）。三导出
> 与既有资源域导出同为「主进程内部使用」口径，**插件永不可达**。`owner` 为
> 透传入参、绑定层不改写不硬编码；生产取值取固定平台服务身份哨兵
> `DOCUMENT_SCOPE_OWNER`（`chips.official.document-service`，RFC-原生承载面扩表
> 裁定 OQ-7 随波 A1 定案、名与值在册 `packages/native/README.md` 与本表说明列，
> 比照核心 `TEMP_SCOPE_OWNER` 先例、非伪造用户身份；常量定义已随波 A2b-α（任务 #217）
> 落位在宿主文档服务侧，装载注入臂随波 A2b-β 接线）。

#### 挂载 scope 派生规则（RFC §5.2 落文；算法本体已随工单036 波 A2b-α 在宿主侧落位）

派生算法本体与 `DOCUMENT_SCOPE_OWNER` 常量定义落位宿主
（`packages/host/src/capabilities/document/scope-derivation.ts`，任务 #217；生产装载注入臂
随波 A2b-β 接线，未接线期装载段仍走诚实回退、`document:*` 不注册）；native 绑定面对
scope 一律透传不生成：

- 形如 `scope = (card- | box-) + hex(lower(sha256(规范化绝对路径)))` 的前 **40** 个
  hex 字符（160 bit 截断，OQ-1 裁定），总长 ≤ 45 字符 < 64 的 `ScopeId` 预算；
  字符集合合 §2.3 `[a-z][a-z0-9-]*`（hex 恒小写）。
- 「规范化绝对路径」三细则**已定案**（2026-09-23 裁决I-⑤，本节原记「归 host 侧算法
  波次裁定」随波翻正）：**软链解析＝做**（以 `realpathSync` 取磁盘实形后再哈希，与核心
  `attach_root` 以 canonical 路径入挂载表同一权威，杜绝同一物理根派生两个 scope）、
  **大小写折叠＝不做**（realpath 已归一到目录项实际拼写，哈希输入取 canonical 路径
  UTF-8 原字节，不额外 lower）、**尾分隔符＝去除**（唯一例外为文件系统根 `/`，使
  `/a/b` 与 `/a/b/` 派生同一 scope）。
- 注册面语法校验与 URI 解析面同源：作用域注册（`ScopeRegistration::validate`）强制
  §2.3 语法（1–64 字符、`[a-z][a-z0-9-]*`、全小写 ASCII），判据取单一事实源谓词
  `is_valid_scope_syntax`（URI 解析面与注册面共用，禁止判据双写），违例在**注册阶段**
  即拒 `RESOURCE_INVALID_URI`（`reason = malformed_scope`），不进入挂载与授权链路
  （2026-09-23 裁决I-③ 落地波 #216 在册；派生形恒为小写 hex，天然合规，两口径一致）。
- 同路径重复派生 → 同一 scope → 核心注册闸回 `RESOURCE_ALREADY_EXISTS`，
  该码即重复挂载的**幂等信号**（波 A1 锁测在册：二挂拒绝且无半挂载态）。
- 前缀-类别在册对应：`card-` / `box-` → Document（本三导出唯一可达形）；
  `workspace-` / `plugin-` / `temp-` 前缀与 Document 越名绑定由核心命名闸拒
  `RESOURCE_INVALID_URI`（`malformed_scope`，波 A1 锁测在册）；越名前缀拒绝与上一条
  语法拒绝同为注册阶段拒绝形，绑定层不造第二套语义。

#### JS 投影形状冻结表（`DirectoryEntry` / `WriteStreamHandle`）

W3 Rust 腾面波任务 #204 臂③落册：上表返回列的 `DirectoryEntry` 与 `WriteStreamHandle`
两投影逐字段冻结于此。表只冻结已落位现形、不改任何导出名与签名（导出面只增不改，
该波三方锁账 49 项零漂移、`coreAbiVersion` 不随动）；`types/chips-native.d.ts` 的
`IDirectoryEntry` / `IWriteStreamHandle` 与绑定层实现为本表同文权威载体，三处逐字段
核对零漂移（#204 收口核对）。

**表一：`DirectoryEntry` → JS 投影 `IDirectoryEntry`（`resourceListDirectory` 返回元素）**

承载实现：`js_resource_list_directory` → `serialize_json(&entries, "/entries")`
（serde `rename_all = "camelCase"` → `json_to_js`）。

| --------------------- | -------------------------------- | --------- | ---------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `name`                | `name`（`String`）               | `string`  | 否（恒在） | 条目名（单层名，非路径）                                              | 输出方向无 `Option`、字段恒在；字符串经 Rust `String` 恒为合法 UTF-8，无第二拒绝臂                                  |

**表二：`WriteStreamHandle` → JS 投影 `IWriteStreamHandle`（`resourceCommitWriteStream` 返回物，闭包对象）**

承载实现：`settle_write_stream`（JS 线程同步装配；方法以捕获共享状态的
`JsFunction::new` 挂属性——neon 1.1.1 无 class API 实证，对象与方法闭包同生共死）。
Rust 侧 `WriteStreamHandle` 结构体本体仅 `{ id, uri }` 最小承载（登记表键 + 目标规范
URI，《03.07》§7.1 未定形其字段面的在册注记），写流生命周期的权威承载为绑定层
`SharedStream`（管理器 + 句柄 + 一次性收口位）。

| JS 字段  | Rust 来源                                                 | JS 类型                                | 可缺省     | 语义                                                                                         | 错配拒绝口径                                                                                                                       |
| -------- | --------------------------------------------------------- | -------------------------------------- | ---------- | -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `id`     | `WriteStreamHandle.id`（`u64`，登记表键，单调分配不复用） | `number`                               | 否（恒在） | 写流句柄 ID（低于 2^53）                                                                     | 装配即判 `safe_u64_number("/writeStream/id")`：`≥ 2^53` 同步抛出 `NATIVE_VALUE_OUT_OF_RANGE`，不产生部分构造对象                   |
| `uri`    | `WriteStreamHandle.uri`（`String`）                       | `string`                               | 否（恒在） | 目标资源规范 URI（错误回执与审计定位）                                                       | —（Rust 字符串恒合法）                                                                                                             |
| `append` | `js_stream_append`                                        | `(bytes: Uint8Array) => Promise<void>` | 否（恒在） | 分块送入（背压承载：不送入即不推进；阻塞落盘在绑定层运行时线程执行）                         | 实参非 `Buffer`/`Uint8Array` → `NATIVE_TYPE_UNSUPPORTED`（`/bytes`）；已收口/陈旧句柄 → `RESOURCE_NOT_FOUND`（uri 定位，零副作用） |
| `commit` | `js_stream_commit`                                        | `() => Promise<IResourceMetadata>`     | 否（恒在） | 原子提交并返回新版本元数据（形状即《03.07》§7.3 在册）；`expected_size` 缺省，按实际尺寸登记 | 重复调用（`AtomicBool` claim 收口失利）→ `RESOURCE_NOT_FOUND`                                                                      |
| `abort`  | `js_stream_abort`                                         | `() => Promise<void>`                  | 否（恒在） | 主动中止并清理临时文件（零残留；归还路径写锁）                                               | 重复调用同 `commit` 口径                                                                                                           |

公共语义：`commit` / `abort` 互斥一次性收口、先到先得；对象整体被 GC 回收且仍未收口

### 11.4 Neon 异步示例

```rust
use neon::prelude::*;

fn resource_read_chunk(mut cx: FunctionContext) -> JsResult<JsPromise> {
    let handle_id = cx.argument::<JsNumber>(0)?.value(&mut cx) as u64;
    let max_bytes = cx.argument::<JsNumber>(1)?.value(&mut cx) as usize;
    // N-1：导出签名不带会话源，归属会话经进程级句柄↔会话归属账回取，
    // 未在册回哨兵会话（状态闸先行，行为不变，失同步 fail-closed）。
    let session = owner_of_handle(handle_id);
    let manager = current_resource_manager(&mut cx)?;
    let runtime = tokio::runtime::Handle::current();
    let channel = cx.channel();
    let (deferred, promise) = cx.promise();

    std::thread::spawn(move || {
        let result = runtime.block_on(manager.read_chunk(handle_id, session, max_bytes));

        deferred.settle_with(&channel, move |mut cx| match result {
            Ok(Some(chunk)) => {
                let mut buffer = cx.buffer(chunk.len())?;
                cx.borrow_mut(&mut buffer, |raw| {
                    raw.as_mut_slice().copy_from_slice(&chunk);
                });
                Ok(buffer.upcast())
            }
            Ok(None) => Ok(cx.null().upcast()),
            Err(error) => cx.throw_error(error.to_string()),
        });
    });

    Ok(promise)
}
```

- 所有导出异步操作都经 `cx.channel()` 回到主线程 settle，禁止在非 JS 线程直接访问 JS 值。
- Rust 侧失败路径返回 `ChipsError`（`thiserror`），经 Bridge 归一为 `code` / `message` / `details` / `retryable` 结构（R2、[02-Bridge三层设计](./02-Bridge三层设计.md)）。
- 生产代码禁止 `unwrap()` 与 `panic!`。

### 11.5 线程与并发

- `ResourceManager: Send + Sync`，以 `Arc` 注入 Node 运行时；一次初始化，生命周期与主进程一致。
- 主进程 JS 线程只做协议编解码；文件 I/O、网络、解压在线程池执行，不阻塞事件循环。
- 流游标状态由管理器内部同步；同一句柄的读写互斥由句柄级锁保证。
