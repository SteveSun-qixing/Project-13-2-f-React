# 文档服务设计

> 日期：2026-09-19

> 适用范围：`.card` 与 `.box` 的统一读写服务设计：文档会话模型、生命周期、内存模型修订、保存原子性、ZIP Store 重建、编辑链路协作、外部修改检测、事件发布职责与错误码

## 四、生命周期

### 4.1 状态机

```
open(source)
  │  解析（L0）· 作用域注册 · 模型构建
  ▼
opening ──成功──▶ active ◀───────────────────────────────┐
  │                 │  write：revision + 1，dirty = true   │
  │                 ▼                                     │
  │               active（dirty，写租约）                    │
  │                 │  save：两阶段提交                      │
  │                 ▼                                     │
  │               saving ──成功──▶ active（savepoint 前移）──┘
  │                 └─失败（回滚，dirty 保持）──▶ active
  │
  └──失败──▶ 无会话（错误返回调用方）

active（任意状态） ──拥有者会话 / Fork 释放──▶ closed（终态，幂等）
```

### 4.2 各阶段职责与失败语义

| 阶段 | 输入 | 职责 | 成功结果 | 失败语义 |
|---|---|---|---|---|
| open | `source`、可选 `kind` | 归一 source、解析 L0、作用域注册、模型构建 | 会话 `active`，返回 `documentId` 等 | 解析错误沿用 `DOCUMENT_*`；作用域注册失败按 `RESOURCE_*`；不产生半开状态 |
| read | `documentId`、`part`、`nodeId` / `range` | 从模型返回切片；未修订部分按需触发解析器惰性层级 | `{ part, value, diagnostics }` | 会话不存在：`DOCUMENT_NOT_OPEN`；kind/part/nodeId 组合非法：`DOCUMENT_PART_UNSUPPORTED` |
| write | `documentId`、`part`、`nodeId`、`value` | 结构校验、模型替换/成员创建/成员删除、`revision + 1`、`dirty = true`、登记变更 | `{ revision }`（本次写入后的会话修订号） | 同上；写冲突 `DOCUMENT_WRITE_CONFLICT`；外部修改 `DOCUMENT_SOURCE_CHANGED`；不落盘、不发布事件 |
| save | `documentId` | 指纹复查、变更集计算、序列化、两阶段提交、savepoint 前移、句柄重建、事件发布 | `{ source, digest }` | 冲突/外部修改同上；落盘失败 `DOCUMENT_SAVE_FAILED`（回滚，dirty 保持） |
| close | 拥有者释放 | 排空在途保存、丢弃未保存模型、释放句柄、移除记录、发布事件 | 终态 `closed` | 幂等；不因未保存状态报错（提示责任在编辑链路） |

### 4.3 `read` 的切片规则

| kind | part | 返回 |
|---|---|---|
| card | `metadata` | `.card/metadata.yaml` 模型 |
| card | `structure` | `.card/structure.yaml` 结构模型 |
| card | `content`（`nodeId` 必填） | `content/{id}.yaml` 内容模型 |
| box | `metadata` | `.box/metadata.yaml` 模型 |
| box | `structure` | `.box/structure.yaml` 完整结构（含 entries） |
| box | `entries`（可带 `range`） | 条目切片，顺序即 `entries` 数组顺序 |
| box | `content` | `.box/content.yaml` 布局配置模型 |
| card | `entries` | 不支持：`DOCUMENT_PART_UNSUPPORTED` |

- 已 `write` 的 part 从模型返回（含未保存修订）；未修订的 part 首次读取时按解析器惰性层级构建并缓存于会话模型。
- `diagnostics` 为对应层级的解析诊断快照；`write` 不产生解析诊断；保存后以重建句柄的诊断为准。

### 4.4 `write` 的提交单位与结构校验

- 提交单位是完整模型切片（`replace` 语义）：`metadata`、`structure`、`content`、`entries` 各自整体替换；补丁由编辑链路在回流前应用（[08-基础卡片插件接口](../../05-接口与契约/08-基础卡片插件接口.md) §4.3、[09-箱子布局插件接口](../../05-接口与契约/09-箱子布局插件接口.md) §7.2）。
- 成员扩展语义（`part: 'content'`，卡片）：
  - `nodeId` 在当前模型中不存在时视为**创建成员**：值来自基础卡片插件的 `createInitialContent()` 或编辑链路的显式构造（[12-编辑引擎设计](./12-编辑引擎设计.md)）；服务只做结构与格式校验，不调用插件代码。
  - `value: null` 视为**删除成员**：从会话模型移除该内容成员；对应成员文件在 `document:save` 时按变更集删除（目录态移入备份后删除，归档态在重建时省略，§8.1）。
  - 创建与删除必须与 `structure` 的整体替换在**同一保存中保持一致**：结构新增的节点必须有内容成员，结构移除的节点不得残留内容成员；`document:save` 不接受"结构已改、内容未跟上"或反之的模型状态，校验不通过返回 `DOCUMENT_STRUCTURE_INVALID`。
- 结构校验（服务职责，不涉及插件语义）：`kind`/`part`/`nodeId` 匹配；`metadata` 必填字段与版本字段存在；`structure` 引用的内容节点存在于模型；`entries` 的 `entry_id` 唯一、`url` 形态合法（[06-文档解析器设计](./06-文档解析器设计.md) §6.1 语义层规则）。结构非法返回 `DOCUMENT_STRUCTURE_INVALID` 或 `DOCUMENT_METADATA_INVALID`。
- 配置语义校验（`configSchema` + `validateConfig`）由编辑链路在 `write` 之前完成（§6.2）；服务不调用插件代码。
- 写入顺序与资源登记：内容配置引用的新资源必须已经或同时登记（§8.1）；未登记资源在保存时按缺失引用处理。

### 4.5 `save` 的执行顺序

1. `dirty == false`：no-op，返回当前 `{ source, digest }`（归档态为文件摘要，目录态为包内容摘要）。
2. 回收写租约校验、重取源指纹并与基线比对（§7.2）；不一致即 `DOCUMENT_SOURCE_CHANGED`。
3. 计算变更集：序列化被修订的 YAML 成员、应用资源登记（§8.1）、推导依赖成员（§5.2）。
4. 两阶段提交（§5.2、§5.3、§5.4）。
5. 更新 savepoint、`dirty = false`、释放写租约；按新指纹重建只读句柄；刷新资源作用域版本戳。
6. 发布 `document:changed` 与 `document:saved`（§7.3）；返回 `{ source, digest }`。

### 4.6 `close` 与资源释放

- 文档服务没有显式关闭能力；`close` 由拥有者会话 / Fork 的释放触发（[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md) §7.3）。
- 释放顺序：标记会话 `closing`（拒绝新请求）→ 等待在途 `save` 完成 → 丢弃未保存模型（§8.1 的资源登记随之丢弃）→ 释放解析句柄与映射 → 移除文档记录与会话 → 发布 `document:closed`。
- 未保存变更的提示与处理属于编辑链路（关闭窗口、切换文档前完成或放弃回流）；服务不做交互。
- 资源作用域的级联失效与释放由资源管理器消费 `document:closed` 执行（[04-资源管理设计](./04-资源管理设计.md) §4.5）；两者共同构成"文档关闭"的完整语义。

### 4.7 `document:export`

`document:export` 把已打开的文档以 `archive`（`.card` / `.box` 归档）或 `directory`（目录态工作副本）形态写到目标路径，覆盖生态的导入、导出与另存场景；它是两态转换的唯一正式入口，不存在旁路。

| 项 | 设计 |
|---|---|
| 输入 | `{ documentId, target, form: 'archive' \| 'directory', overwrite?: boolean }`；`target` 必须是受管作用域内路径（工作区或 `dialog:save` 临时作用域） |
| 输出 | `{ target, form, digest }`（归档形态为文件摘要，目录形态为包内容摘要，§5.5）；不改变当前会话的 `source`、savepoint 与 `documentId` |
| 权限 | 源文档 `resources:read`；目标落点 `filesystem:write`（工作区内以 `${workspace}` 限定值匹配，临时作用域按临时授权规则；导出不修改源文档）；判定由 Bridge 与权限系统执行（§9.1、[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md) §6.2、[13-工作区设计](./13-工作区设计.md) §4.2） |
| 归档形态 | 按 §5.4 重建：归档根即包根、路径升序、全部条目 Store（不产生 ZIP64）、成员时间戳取导出时刻 |
| 目录形态 | 按 §5.3 写出目录工作副本；`target` 不存在时先创建；已存在且 `overwrite` 为 false 时返回 `RESOURCE_ALREADY_EXISTS`，`overwrite: true` 时先完整写临时物、校验通过后原子替换 |
| 形态约束 | 卡片支持 `archive` 与 `directory`；箱子只有单文件正式形态，仅支持 `archive`，对箱子请求 `directory` 返回 `DOCUMENT_PART_UNSUPPORTED`（[13-工作区设计](./13-工作区设计.md) §4.2、§4.5） |
| 原子性 | 目标先写同级临时物（平台保留前缀 `.chips-export-<随机>`）+ 校验，通过后原子替换/重命名；失败清理临时物并返回导出失败，不产生半成品；崩溃残留由启动恢复清理 |
| 校验 | 导出产物以解析器重新打开并 `validate`，`Invalid` 视为导出失败（与 §5.4 一致）；`ValidWithWarnings` 允许但返回诊断 |
| 会话关系 | 导出是只读会话模型 + 写目标路径；不推进当前会话 revision、不改变 dirty/savepoint；"另存"后继续编辑原文档，切换编辑目标需显式重新 `document:open` |
| 流程归属 | 导入归档 → 工作区目录态、目录态 → 归档导出的正式流程、目标路径选择与工作区布局见[13-工作区设计](./13-工作区设计.md)；迁移场景见[04-版本与迁移规范](../../04-文件格式规范/04-版本与迁移规范.md) §6 |

- `document:export` 不迁移文档版本、不修复诊断缺陷；版本不兼容的文档按 §1.1 的门禁拒绝，要求先迁移。
- 导出写目标路径同样纳入 WriteCoordinator：同一路径同一时间只允许一个写者（[04-资源管理设计](./04-资源管理设计.md) §4.8）。

### 4.8 `document:create`

`document:create` 新建一张卡片或一个箱子；它是文档创建的唯一受控写口，不建立会话（会话由随后的 `document:open` 建立）。输入输出、字段与 JSON Schema 以[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md) §7.3 为权威，应用侧入口归一与交互以[12-编辑引擎设计](./12-编辑引擎设计.md) §十三为准。

| 项 | 设计 |
|---|---|
| 输入 | `{ kind, parent, name?, initialContent? }`；`parent` 为目标父目录受管引用；`name` 缺省「未命名卡片」/「未命名箱子」；`initialContent` 只给装配提示（`cardType` / `layoutType`） |
| 输出 | `{ documentId, source }`；`documentId` 为新建文档的稳定标识，`source` 为落点受管引用 |
| 标识 | 文档标识（`card_id` / `box_id`）由受控写口生成；首个 `node_id` 随初始结构在受控写口一次装配；生成责任、查重与冲突检测以[05-ID生成规范](../../04-文件格式规范/05-ID生成规范.md) §四、§六为准，调用方不得指定或拼装任何标识 |
| 初始装配 | `metadata`（名称、标识、`chip_standards_version`、封面比例）、`structure`（首个节点或空条目集合）、`content`（节点内容初值取自插件 `createInitialContent()`，服务不内置内容）、箱子布局配置（缺省 `chips.layout.grid`）与初始封面 |
| 落盘 | 卡片写目录态工作副本 `<名称>.card/`；箱子写归档态单文件 `<名称>.box`；命名冲突自动追加 `-2` / `-3`（[13-工作区设计](./13-工作区设计.md) §3.3） |
| 权限 | 目标作用域 `resources:write`（[08-权限系统设计](./08-权限系统设计.md) §4.3） |
| 原子性 | 先写同级平台保留临时物，`validate` 通过后原子落地；失败清理临时物，不产生半成品、不覆盖既有文件 |
| 事件 | 不新增专用事件；写入完成后按 §7.3 发布 `document:changed` / `file:changed`，打开会话后发布 `document:opened` |

- 服务不调用插件代码：初始节点内容初值由受控写口在插件上下文中调用 `createInitialContent()` 取得（[08-基础卡片插件接口](../../05-接口与契约/08-基础卡片插件接口.md) §2.4.4）；`configSchema` 与 `validateConfig` 校验由创建链路在提交前完成（[12-编辑引擎设计](./12-编辑引擎设计.md) §13.3）。
- 创建不改变任何既有会话；同一路径并发创建由 WriteCoordinator 串行化（[04-资源管理设计](./04-资源管理设计.md) §4.8），落点重名由命名规则消解（[13-工作区设计](./13-工作区设计.md) §3.3）。
