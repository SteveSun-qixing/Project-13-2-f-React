## 九、约束清单

| 编号 | 约束 |
|---|---|
| WS-1 | 工作区是运行时用户数据根；与"生态工作区"术语严格区分（§1.2）。 |
| WS-2 | 同一工作区同一时刻只被一个平台实例绑定；实例锁与心跳规则见 §2.4。 |
| WS-3 | 绑定、初始化、切换、关闭必须原子且可恢复；失败不留下半初始化目录。 |
| WS-4 | 保留目录 `.chips/` 与保留前缀 `.chips-*` 不进入扫描、文件树与用户可见范围（§3.2）。 |
| WS-5 | 凭证材料不进入工作区；工作区配置只保存 `credential://` 引用（§3.1）。 |
| WS-6 | 卡片目录态是编辑工作形态，归档态是交付形态；形态转换只经 `document:export`，禁止手工改写。 |
| WS-7 | 箱子的正式形态只有单文件 `.box`；解包目录只在同级保留前缀目录中存在并随保存清理。 |
| WS-8 | 导入必须经版本门禁、`validate` 与资源清单校验；不自动迁移、不改写源文件。 |
| WS-9 | 导出/另存必须原子、默认不覆盖、按目标形态重算 `file_info` 与资源清单。 |
| WS-10 | 扫描排除保留区、系统生成物、临时物与符号链接；树不解析文档内容。 |
| WS-11 | 外部修改只检测、提示、冻结写入；禁止自动合并、强制保存与隐式重载。 |
| WS-12 | 保留路径写入一律 `WORKSPACE_RESERVED_PATH`；跨工作区访问不自动授权（§6.4）。 |
| WS-13 | 开发工作区与用户工作区在数据、插件记录、日志上完全隔离；`development` 插件不得在用户工作区启用。 |
| WS-14 | 工作区切换/关闭前必须 flush 并释放全部文档会话；切换期间 `WORKSPACE_BUSY`。 |
| WS-15 | 目录态不参与同步；同步只作用于归档态文档（07 §2.4）。 |
| WS-16 | `.chips/state/` 只存可重建运行状态（`instance.lock` / `cleanup.json` / `host-state.json`）；`host-state.json` 只是 CLI 运行标记，实例状态以 `instance.lock` 为权威（§3.1、[CLI 完整参考](../../06-开发与运维/07-CLI完整参考.md) §3.2）。 |
