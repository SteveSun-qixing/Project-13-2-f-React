## 一、定位与范围

### 1.1 定位

资源管理器（ResourceManager）是薯片平台统一资源访问与生命周期的权威实现，位于 Rust 核心，经 Neon 暴露给主进程，由 Bridge 路由至渲染进程。文档资源（`.card` / `.box`）、插件资源（`.cpk`）、平台资源、外部 `http(s)://` 资源全部走同一套解析、权限、缓存、句柄与清理机制，不区分卡片与箱子，也不区分查看与编辑（R8）。

### 1.3 术语约定

| 术语 | 含义 |
|---|---|
| 资源（resource） | 可寻址的可消费内容单元：读取经资源句柄，写入经受控提交接口。 |
| 挂载（mount） | 一个来源（工作区、文档、插件、平台、外部、临时、内存）在统一文件系统中的注册单元，对应一个作用域。 |
| 作用域（scope） | 资源命名空间与授权单元：`card-*` / `box-*` / `plugin-*` / `platform` / `external` / `workspace-*` / `temp-*` / `memory`。 |
| 资源会话（resource session） | 资源句柄与租约的所有权单元，与渲染会话一一对应。 |
| 句柄（handle） | 插件侧资源访问对象，持有租约，状态为 `open` / `invalidated` / `released`。 |
| 租约（lease） | 句柄在会话内对底层来源的引用，会话关闭时统一归还。 |
| 版本戳（version stamp） | 来源当前版本的标识（`mtime + size`、归档条目 CRC、HTTP `ETag`）。 |
| Provider | 文件系统抽象层的来源实现：目录、ZIP Store、平台内嵌、HTTP、内存。 |
| 能力面（capability face） | 同一引擎对外暴露的一组操作契约：`file:*`（路径式）与 `resource:*`（地址式）。 |

### 1.4 关键约束

- 资源统一经 `chips-resource://` 访问，受限、可审计（R17）。
- 一切来源皆挂载、一切访问皆句柄：插件只能经 Bridge 获取资源，不得接触真实文件系统路径（R17）。
- 资源句柄只读；资源写入只经资源管理器的受控提交接口，受 `resources:write` 约束，不通过句柄暴露。
- 写路径裁决：document 挂载（目录态与归档态）内的写入只经文档服务受控提交；`resource:write` 只允许插件作用域与临时作用域（[11-文档服务设计](./11-文档服务设计.md) §2.1、§8.1）。
- 资源引用路径只允许：包内相对路径、`file://`、`http(s)://`、`webdav://`、`chips-resource://`（R13、[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md) §2.2）；`data:` 仅运行时内存形态。
