> 日期：2026-09-19
> 状态：正式版
> 适用范围：官方社区客户端应用插件（`chips.official.community-client`，`app` 角色）的权威设计：定位与边界、总体架构、窗口与路由、浏览、认证与会话、卡片上传、完整下载与本地查看、权限声明、错误与降级、约束与自检清单；不定义卡片传输协议、资源打开与默认处理器机制、社区平台服务端接口与数据模型的内部细节。

## 七、完整下载与本地查看

### 7.1 完整下载

1. 卡片详情页点击“下载完整卡片”（需登录）。
2. `dialog:save` 选择保存位置，`defaultPath` 为 `<卡片标题>.card`（过滤器同卡片扩展名）。
3. 调用传输链路的**下载**操作，输入为卡片 ID、目标受管引用与社区会话。
4. 传输链路下载网络资源卡片与全部资源对象、把 URL 还原为原始相对路径、按 ZIP Store 重建完整离线卡片并写入目标位置。
5. 成功提示“已保存到你选择的位置”；失败展示中文原因并允许重试。
- 目标文件已存在与覆盖语义由保存对话框和传输链路承担；客户端不直接写文件。
- 完整下载不修改社区服务器上的内容，也不改变本地其它文件。
- 完整下载当前只适用于卡片；箱子完整下载不在传输协议登记范围内，客户端不提供入口（能力变化以[16-卡片传输协议](../../05-接口与契约/16-卡片传输协议.md)为准）。

### 7.2 本地查看

1. 卡片详情页点击“在本地查看器中打开”（需登录）。
2. 客户端读取卡片轻量信息（标题、封面、状态）用于界面反馈；接口形态以社区平台 API 契约为准。
3. 调用传输链路的**远程打开**操作（任务种类 `open-remote`），由传输引擎把网络资源卡片物化到本地临时位置并交付平台打开路由；资源仍按 CDN URL 在线加载。
4. 平台按[14-资源打开与默认处理器契约](../../05-接口与契约/14-资源打开与默认处理器契约.md)选择本地卡片查看器应用并投递打开意图；客户端不参与路由与投递。
5. 查看器解析卡片并渲染；客户端不参与解析、渲染与资源注入。
6. 界面展示打开进度与结果；查看器缺失或打开失败时，按该契约的失败语义提示并给出安装 / 启用指引。

- 本地查看只取回网络资源卡片本身，不等同完整下载；资源在线加载意味着离线可用性由完整下载提供。
- 客户端不硬编码查看器插件 ID、不直接调用其他应用插件（R1、[ADR-005](../ADR/ADR-005-插件不分类只分角色.md)）。
- 不启用服务器渲染缓存（`viewUrl` / 托管 HTML）作为查看主链路。
- 箱子的本地查看不在本设计范围：[16-卡片传输协议](../../05-接口与契约/16-卡片传输协议.md)未登记箱子远程打开操作，客户端不自造协议、不提供入口；是否扩展由传输协议文档决定。

### 7.3 完整下载与本地查看对比

| 维度 | 本地查看 | 完整下载 |
|---|---|---|
| 结果 | 临时位置物化网络资源卡片，交给本地查看器 | 用户选择位置的完整离线卡片 |
| 资源形态 | 按 CDN URL 在线加载 | 资源字节回填、URL 还原为原始相对路径 |
| 网络依赖 | 查看时需要网络 | 下载完成后离线可用 |
| 落盘 | 临时位置，由平台管理 | 用户选定位置，长期保存 |
| 对话框 | 不需要 | `dialog:save` |
| 使用场景 | 快速查看社区卡片 | 收藏、迁移、离线保存 |
