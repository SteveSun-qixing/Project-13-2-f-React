## 八、官方编辑引擎应用参考架构

### 8.1 定位

`chips.official.editor` 是 `app` 角色插件（`ui.surface: window`），是编辑链路的官方消费者与首个实现：

- 它不实现解析、渲染、读写、资源访问的任何旁路，只消费平台链路与 `IEditSession`。
- 它负责工作区场景、文档窗口、编辑面板、设置/封面/导出等界面与交互（本轮为平台机制的第一个完整消费者）。
- 它与查看器、资源管理器等官方应用插件按 ADR-005 拆分，不互相 `import`，需要复用能力时经服务与能力通信。

### 8.2 窗口与场景

| 场景 | 载体 | 职责 |
|---|---|---|
| 工作区场景 | 主窗口（`ui.surface: window` 的主窗口） | 文件树 / 资源管理器、最近文档、插件与设置入口；工作区切换入口 |
| 卡片窗口 | 应用内窗口层（不创建独立窗口；窗口状态机见《08-产品与交互/01-编辑引擎产品与交互设计》§5） | 单张卡片的查看/编辑：预览、节点编辑、卡片设置、封面、导出 |
| 箱子窗口 | 应用内窗口层（同上） | 箱子的预览、条目管理、布局编辑面板、封面与导出 |
| 编辑面板 | 卡片/箱子窗口内的 EditorHost 区域 | 节点编辑器（卡片）与布局编辑器（箱子）的宿主 |
| 卡片设置 | 卡片窗口内的设置面板 | 名称、标签、封面比例等元数据编辑（`updateMetadata`） |
| 封面编辑 | 卡片/箱子窗口内的封面面板 | 封面入口选择与封面 HTML 写入（`writeCover`） |
| 导出 | 卡片/箱子窗口内的导出面板 | `document:export`（archive / directory）与插件 `export` 格式导出 |

规则：

1. 文档窗口打开时创建对应编辑会话；关闭窗口前执行 `flush()`，未保存变更按 §6.3 确认。
2. 同一文档允许在多个窗口查看，但同一时刻只有一个可写编辑会话；第二个窗口打开时按文档服务写租约表现为只读查看（[11-文档服务设计](./11-文档服务设计.md) §7.4）。
3. 窗口职责只通过平台能力实现：窗口创建/聚焦/关闭/状态经 `window:*` 能力，窗口标题经 `window:setTitle`，菜单与快捷键经 `menu:set` / `shortcut:register`（[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md)）。
4. 界面层不直接调用插件：编辑器挂载一律经 `IEditSession`；应用插件不持 `IPluginRuntime`。

### 8.3 多文档与多窗口

- 一个应用实例内允许同时存在多个编辑会话（每个文档一个）；会话之间不共享编辑器、容器与状态，只共享模块缓存与配置。
- 每个文档窗口维护自己的 `IEditSession`：切换窗口只是窗口焦点变化，不重建会话；切换文档需要重新 `open`。
- 应用退出：先 `flush()` 全部会话，再释放；未保存变更按窗口逐个确认。
- 拖拽打开（拖入 `.card` / `.box`）与文件关联打开走同一条 `openFile` 路径（[07-应用插件接口](../../05-接口与契约/07-应用插件接口.md) §3.4）。

### 8.4 启动与文件关联

```yaml
id: chips.official.editor
type: app
ui:
  surface: window
  launcher: {}
fileAssociations:
  - extensions: [.card, .box]
    action: open
deepLinks:                        # manifest 深链接声明（登记见 04-能力契约规范）
  - scheme: chips
    action: open
```

- 启动意图：启动器 / 文件关联 / 命令（`AppLaunchSource`）以及深链接（`deep-link`）；深链接投递事件为 `app:opened-with-url`。
- `launch` 处理初始文件（`ctx.args.files`）与初始命令；运行中到达的文件与命令投递给 `openFile` / `handleCommand`。
- 打开文件后按扩展名进入卡片窗口或箱子窗口，不存在该扩展名的编辑路径时提示"暂不支持编辑该文件类型"，不创建半开窗口。

### 8.5 配置

| 配置键 | 层 | 含义 | 默认 |
|---|---|---|---|
| `plugins.chips.official.editor.autoSave` | 用户 / 工作区 | 是否启用自动保存 | `true` |
| `plugins.chips.official.editor.autoSaveDelayMs` | 用户 / 工作区 | 自动保存防抖毫秒 | `500` |
| `plugins.chips.official.editor.historyLimit` | 用户 / 工作区 | 历史栈上限 | `100` |
| `plugins.chips.official.editor.editorFontSize` | 用户 / 工作区 | 编辑器正文字号 | `14` |
| `plugins.chips.official.editor.defaultCardType` | 用户 / 工作区 | 不带类型的「新建卡片」使用的初始节点类型 | `base.richtext` |

- 配置 schema 随插件包发布（`assets/schemas/config.schema.json`），默认值不落盘；读取与变更通知按[《配置系统设计》](./10-配置系统设计.md) §4、§五。
- `defaultCardType` 指向的基础卡片插件不可用（未安装 / 未启用）时「新建卡片」按 §13.6 失败提示，不静默替换为其它类型。
- 禁止把文档状态、选择、滚动、历史栈写入配置（§10）。

### 8.6 与工作区的交互

- 工作区是编辑引擎的默认文档根与导出落点：文件树数据来自工作区（[13-工作区设计](./13-工作区设计.md) §五）；打开、导入、导出、另存的落点规则以 13 为准。
- 工作区切换：编辑引擎先 `flush()` 并关闭旧工作区全部编辑会话，再重建文件树与场景；切换期间禁止打开新文档。
- 编辑引擎不直接读写工作区文件：文件树读取经 `file:list`（`filesystem:read`），文件操作经 `file:move` / `file:copy` / `file:delete` / `file:mkdir`（能力契约）与文档服务链路。

### 8.7 性能要求

| 指标 | 预算 | 说明 |
|---|---|---|
| 打开卡片进入可编辑 | < 100ms（R18） | `open` 到 `ready`；骨架在请求接受后下一帧内可见 |
| 打开箱子进入可编辑 | < 200ms（R18） | 同上；首屏条目按需加载 |
| 回流到预览 | ≤ 100ms | §6.4 |
| 编辑器首次挂载 | ≤ 150ms | 单个节点编辑器；模块已在缓存时 ≤ 50ms |
| 文件树首屏 | ≤ 100ms | 只加载工作区根与一级条目 |
| 空闲内存 | < 500MB（平台级） | 与渲染引擎共享同一预算；不额外驻留文档字节 |

懒加载与虚拟化：

1. 插件模块按需装载：只有文档实际使用的 `cardType` / `layoutType` 才装载对应门面。
2. 文件树按[《工作区设计》](./13-工作区设计.md) §5.1 的分页与懒加载规则枚举，渲染层对长列表必须虚拟化；节点列表超过 100 个节点时卡片窗口对节点容器启用虚拟化（仅为可见范围渲染 `renderView`），编辑器只在可见或聚焦节点挂载。
3. 索引进度与缩略图等派生内容不得阻塞打开路径；在后台任务中生成并以事件通知 UI。
