## 七、链路三：运行时判定

### 7.1 判定点与输入

判定发生在 Bridge 层的两个入口：

1. `window.chips.request(capabilityId, input)`：能力解析后、Schema 校验前执行权限判定；失败立即返回，不进入执行。
2. `window.chips.resource(uri)`：打开资源句柄时执行资源读取判定。

事件订阅的权限门控由事件契约声明（见 [05-事件契约规范](../../05-接口与契约/05-事件契约规范.md)），机制见 [09-事件系统设计](./09-事件系统设计.md)。

判定数据结构：

```typescript
interface IPermissionGrant {
  base: string;
  qualifier?: string;
  state: 'granted' | 'denied';
  source: 'enable' | 'first-call' | 'settings' | 'update';
}

interface ISessionScope {
  sessionId: string;
  pluginId: string;
  scopeVersion: number;
  grants: ReadonlyArray<IPermissionGrant>;
}
```

### 7.2 判定算法

```typescript
interface IPermissionDecision {
  allowed: boolean;
  permission: string;
  reason?: 'not_granted' | 'revoked' | 'out_of_scope';
}

const checkPermission = (
  scope: ISessionScope,
  capabilityPermissions: ReadonlyArray<string>,
  input: unknown
): IPermissionDecision => {
  for (const required of capabilityPermissions) {
    const target = extractTarget(required, input);
    if (target !== undefined && isSelfScope(scope, required, target)) {
      continue;
    }
    const covered = scope.grants.some(
      (grant) => grant.state === 'granted' && isCovered(grant, required, target)
    );
    if (!covered) {
      return { allowed: false, permission: required, reason: describeReason(scope, required) };
    }
  }
  return { allowed: true, permission: '' };
};

const isCovered = (
  grant: IPermissionGrant,
  required: string,
  target: string | undefined
): boolean => {
  if (grant.base !== required) {
    return false;
  }
  if (target === undefined) {
    return true;
  }
  return matchesQualifier(grant.base, grant.qualifier, target);
};

const describeReason = (scope: ISessionScope, required: string): 'not_granted' | 'revoked' => {
  const known = scope.grants.some((grant) => grant.base === required);
  return known ? 'revoked' : 'not_granted';
};
```

规则：

- 循环按能力声明顺序短路，第一个未满足的权限即返回；错误详情包含全部 `required` 与 `granted`。
- `isSelfScope` 判定免权限范围（见 [4.4](#44-免权限范围)）：自身数据目录、自身配置命名空间、自身资源作用域直接通过，无需授予记录。
- `extractTarget` 的字段映射见 [4.3](#43-能力--权限映射r19)；无目标权限不进入免权限范围与限定值匹配，直接按授予判定。
- `matchesQualifier` 按域分派到路径匹配（7.3）、域名匹配（7.4）或资源匹配（7.5）。
- 判定结果放行与拒绝均全量记录审计（见 8.1）；风险级别决定留存档位（180/365 天，见 8.4），不决定是否记录（工单046 裁定一，2026-09-21）。

### 7.3 路径限定匹配规则

适用域：`filesystem`（`read`、`write`、`delete`）。

限定值文法：`<目录变量>[/<子路径>]`，目录变量平台内置：

| 变量               | 展开位置                       |
| ------------------ | ------------------------------ |
| `${userHome}`      | 用户主目录（最大范围，高风险） |
| `${userDocuments}` | 文档目录                       |
| `${userDownloads}` | 下载目录                       |
| `${userDesktop}`   | 桌面目录                       |
| `${userPictures}`  | 图片目录                       |
| `${userMusic}`     | 音乐目录                       |
| `${userVideos}`    | 视频目录                       |
| `${userData}`      | 平台数据目录                   |
| `${temp}`          | 系统临时目录                   |

匹配步骤：

1. 展开变量：把限定值与调用参数 `path` 都解析为绝对路径。
2. 归一化：折叠 `.` 与 `..`，统一路径分隔符；Windows 盘符统一大写。
3. 解析符号链接：对已存在的部分取真实路径，不存在时解析最近存在的祖先再拼接剩余段。
4. 前缀比较：限定值表示"该目录及其全部子目录"，目录边界必须精确匹配（`/a/b` 不匹配 `/a/bc`）。
5. 大小写：按平台文件系统语义比较（macOS/Windows 不敏感，Linux 敏感）。

安全规则：

- 符号链接解析后的真实路径必须仍位于授权目录内；`..` 折叠后越界的路径一律拒绝。
- 权限申请与授权界面不写死绝对路径：存储保留变量形式，展示与判定时展开。
- 一个目录需要多条限定值时声明多条权限条目；禁止用根目录或 `${userHome}` 表达"都要"，除非评审通过。

### 7.4 域名限定匹配规则

适用域：`network:http` 与 `shell:external` 的 URL 模式。

限定值文法：`<scheme>://<host-pattern>[:<port>]` 或裸 `host-pattern`；`host-pattern` 为 `host`、`*.host` 或 `*`。

匹配步骤：

1. 域名小写化；IDN 统一转换为 punycode。
2. 通配符语义：`*` 只匹配一个标签，`*.example.com` 匹配 `api.example.com`，不匹配 `example.com`；裸域必须单独声明。
3. 端口：缺省匹配默认端口（http 80、https 443）；显式端口精确匹配，不同端口不继承。
4. IP 地址（含 `127.0.0.1`、私网地址）必须显式列出；不支持 CIDR 范围。
5. 含 userinfo（`https://user:pass@host`）的 URL 直接拒绝。

安全规则：

- **重定向独立判定**：每一次实际请求（包括重定向目标）都以最终 host 重新判定；目标不在授权内的重定向失败。
- 子资源请求（脚本、图片、WebSocket 升级）按同一规则逐次判定，不继承页面授权。
- `*` 通配域名与 `${userHome}` 路径同属高风险项，仅限评审通过或用户明确确认。

### 7.5 资源级限定规则

适用对象：`window.chips.resource(uri)` 的显式资源访问。作用域注册、解析、句柄与路径安全由资源管理器承担（见 [04-资源管理设计](./04-资源管理设计.md) 第五节），本节定义各作用域的权限与限定值匹配方式。

资源 URI 为 `chips-resource://<scope>/<path>`（见 [06-资源协议规范](../../05-接口与契约/06-资源协议规范.md)）。

| 作用域             | 访问者                   | 所需权限                                                             | 限定值匹配目标                     | 附加约束                   |
| ------------------ | ------------------------ | -------------------------------------------------------------------- | ---------------------------------- | -------------------------- |
| Document           | 该文档会话及其派生子会话 | 会话内已授权句柄读取免重复校验；写入经受控提交并需 `resources:write` | 文档包（`.card` / `.box`）真实路径 | 句柄只读；会话关闭即拒绝   |
| Document（会话外） | 其他插件                 | `resources:read:<scope>` / `resources:write:<scope>`                 | 目标作用域前缀                     | 默认拒绝，经用户授权后放行 |
| Plugin（自身）     | 插件自身                 | 无（见 [4.4](#44-免权限范围)）                                       | —                                  | 仅自身作用域，只读         |
| Plugin（他人）     | 其他插件                 | `resources:read:<scope>` / `resources:write:<scope>`                 | 目标作用域前缀                     | 默认拒绝，经用户授权后放行 |
| Platform           | 任意插件                 | 无（见 [4.4](#44-免权限范围)）                                       | —                                  | 公开只读；不可列举目录     |
| External           | 任意插件                 | `resources:read:<scope>` 与 `network:http:<domain>`                  | 输入 URL 的 host（按 7.4 匹配）    | 默认不携带凭证             |

规则：

- 渲染链路注入的资源基址由渲染框架管理，不作为插件权限判定；插件主动调用 `resource(uri)` 时才按上表判定。
- Document 作用域只读：文档内容写入经文档保存链路执行，不通过资源句柄。
- External 作用域的重定向与子请求按 [7.4](#74-域名限定匹配规则) 逐次判定。
- 资源层自身错误码（如 `RESOURCE_PATH_INVALID`、`RESOURCE_PERMISSION_DENIED`）以 [04-资源管理设计](./04-资源管理设计.md) 第 5.5 节为准；权限语义与本文一致。

### 7.6 会话权限快照

- 物化时机：插件启用完成、插件运行时上下文建立时。
- 快照内容：`sessionId`、`pluginId`、`scopeVersion`、不可变授权列表；插件只能读取自身授权摘要，不能写入。
- 失效：授权授予/撤销/更新递增 `scopeVersion`，旧快照失效并按新授权重建；插件停用、卸载、崩溃重启时快照销毁。
- 一致性：同一次调用的权限判定只使用一个快照版本，判定过程中不切换。

### 7.7 边界

- 能力注册表结构、能力发现、Schema 校验、IPC 通道与消息格式、错误归一均见 [02-Bridge三层设计](./02-Bridge三层设计.md)。
- 判定所需的调用方身份（`pluginId`、`sessionId`）由 Bridge 从进程与会话绑定中注入，不取自调用参数，插件不可伪造。
- 错误结构遵循《架构原则》统一错误模型（`code` / `message` / `details` / `retryable`）。
