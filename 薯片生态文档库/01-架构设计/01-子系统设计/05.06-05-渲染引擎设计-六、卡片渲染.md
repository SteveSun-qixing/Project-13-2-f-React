## 六、卡片渲染

### 6.1 插件解析与装载

1. 按 `CardRenderView.content_nodes` 声明顺序逐节点渲染：由内容配置的 `card_type` 在插件注册表中查询声明了该 `cardTypes.id` 的 `basecard` 插件（角色过滤规则见 ADR-005）；查询同时按插件 manifest 的 `capabilities.cardTypes[].aliases` 做别名归一（别名 → 正式 ID 由插件声明、平台读取时归一，见[08-基础卡片插件接口](../../05-接口与契约/08-基础卡片插件接口.md)）。
2. 校验 `CardRenderView.chip_standards_version` 与平台支持范围：不满足时按文档格式版本门禁处理（`DOCUMENT_VERSION_OUTDATED` / `DOCUMENT_VERSION_UNSUPPORTED`；次版本高于平台时记 `DOCUMENT_VERSION_MISMATCH` 警告），版本规则见[04-版本与迁移规范](../../04-文件格式规范/04-版本与迁移规范.md)。
3. 节点插件缺失返回 `RENDER_PLUGIN_MISSING`；已装插件的版本策略、能力声明或 schema 与内容要求不匹配返回 `RENDER_SCHEMA_UNSUPPORTED`。两者都渲染节点级降级占位，说明原因并提供操作入口（如"前往插件市场"），不阻塞同卡其他内容节点与同窗口其他会话。
4. 插件装载成功后才执行该节点的渲染；装载失败不调用任何插件方法。
5. 帧运行时为**每个节点创建独立容器**，并在容器内调用 `renderView(basecard, container)`；节点级降级只替换该节点容器的内容，禁止多节点共用同一容器（第 6.2 节、RR-16）。

### 6.2 帧初始化

```
RenderHost                                   卡片帧
   │ 创建 iframe(sandbox=allow-scripts)          │
   │ URL 携带一次性握手令牌                        │
   │────────────────────────────────────────────▶│
   │  首条 postMessage（含令牌 + MessagePort）     │
   │────────────────────────────────────────────▶│
   │ host:init { role, view, nodes[],             │
   │             resourceBase, pluginEntries,     │
   │             tokens, limits }                 │
   │────────────────────────────────────────────▶│
   │                    按 nodes[] 创建独立容器    │
   │                    loadPlugin(pluginEntries) │
   │                    renderView(basecard, ctr) │
   │                              frame:ready      │
   │◀────────────────────────────────────────────│
   │                              frame:height     │
   │◀────────────────────────────────────────────│
```

帧运行时职责：

```typescript
interface FrameRuntime {
  handle(message: HostOutboundMessage): void;
  reportReady(): void;
}

interface FrameRuntimeOptions {
  container: HTMLElement;
  loadPlugin(entry: string): Promise<IBaseCardPlugin | IBoxLayoutPlugin>;
  scheduleMeasure(task: () => void): void;
}

// 帧运行时对内容节点的装载与执行（view 已按 role 收窄为 CardRenderView）
async function startCardFrame(
  view: CardRenderView,
  nodes: FrameNodeInit[],
  pluginEntries: Readonly<Record<string, string>>,
  root: HTMLElement,
): Promise<void> {
  for (const node of nodes) {
    const entry = pluginEntries[node.card_type];
    // 每个节点一个独立容器；节点级降级只影响本容器
    const container = createNodeContainer(root, node.containerId);
    if (entry === undefined) {
      // 节点级降级：RENDER_PLUGIN_MISSING，不阻塞同卡其他内容节点
      renderNodePlaceholder(container);
      continue;
    }
    const basecard = buildBaseCardView(view, node); // 补 revision 与卡片级上下文
    const plugin = await loadPlugin(entry);
    const dispose = plugin.renderView(basecard, container);
    if (typeof dispose === 'function') {
      lifecycle.track(dispose);
    }
  }
  reportReady();
}
```

插件实现 `renderView` / `renderLayout` 时必须返回可释放句柄（`void | Dispose`），帧销毁时按返回顺序反向调用，释放定时器、事件监听、观察器与媒体资源。接口签名以[08-基础卡片插件接口](../../05-接口与契约/08-基础卡片插件接口.md)与[09-箱子布局插件接口](../../05-接口与契约/09-箱子布局插件接口.md)为准。

`nodes[]` 与 `view.content_nodes` 逐项对应（`node_id` 一致）且顺序一致；帧运行时不得为视图之外的节点创建容器，不得把多个节点渲染进同一容器，也不得在容器之间搬移插件输出。节点容器是节点级降级与错误边界的定位单元。

### 6.3 编排与测量

- 帧宽度由父帧的容器宽度决定；卡片自身不得固定窗口宽度，也不得请求改变外层尺寸。
- 高度由帧测量上报（第 9.4 节），父帧 clamp 后应用；超过 `limits.maxHeight` 时在帧内滚动。
- 查看态不存在卡片外壳：渲染帧只按节点容器顺序排布节点内容，节点容器间距由帧运行时按 `@chips/ui` Design Tokens 统一提供；选中态、工具栏、拖拽把手、卡片描边与背景等外壳均不属于查看态内容。
- 编辑态外壳（选择、拖拽排序、插入指示等）由编辑链路绘制，渲染引擎、帧运行时与就近渲染容器都不提供外壳（[12-编辑引擎设计](./12-编辑引擎设计.md)）。
- 图片/字体的异步加载会触发多次高度变化，测量按稳定算法合并（第 9.4 节），避免容器抖动。

### 6.4 失败隔离与降级

- 单帧失败不影响兄弟帧与整个会话；错误边界粒度为帧。
- 降级占位必须使用 `@chips/ui` 组件与简体中文文案，展示错误码与重试入口。
- 重试重新走完整链路（解析缓存可命中），不得跳阶段。
- 帧失联（进程崩溃、渲染器 OOM）时标记会话 `error`，已渲染帧保留展示，提供"重新打开"操作。
