## 六、权限与安全

### 6.1 工作区目录变量 `${workspace}`

- `${workspace}` 是平台内置目录变量，展开为当前绑定工作区的规范化绝对根路径；变量本身不随工作区切换而改变语义，展开值随绑定变化。
- 用途：插件 manifest 的 `filesystem:*` 限定值（如 `filesystem:read:${workspace}`）、能力调用的路径匹配、授权界面展示（展开为实际路径，[08-权限系统设计](./08-权限系统设计.md) §六、§7.3）。
- 该变量与其它内置目录变量（`${userHome}`、`${userDocuments}`、`${userDownloads}`、`${userDesktop}`、`${userPictures}`、`${userMusic}`、`${userVideos}`、`${userData}`、`${temp}`）并列，登记进[《权限系统设计》](./08-权限系统设计.md) §7.3 的目录变量表。
- 未绑定工作区时，含 `${workspace}` 的调用一律拒绝（`BRIDGE_PERMISSION_DENIED` / `WORKSPACE_NOT_FOUND`）。

### 6.2 临时作用域与用户授权路径

- 工作区之外的路径访问只经两条合法路径：
  1. 用户经 `dialog:open` / `dialog:save` 显式选择路径 → 临时作用域（`temp-*`），生命周期与权限见[《资源管理设计》](./04-资源管理设计.md) §5.4。
  2. 用户已授权的工作区路径（`filesystem:*` + `${workspace}` 限定值）。
- `dialog:open` 临时作用域只读；`dialog:save` 临时作用域允许读+写，且单次写入后自动注销；两者都受 PathGuard 与作用域根约束。
- 插件不得缓存对话框返回的 URI 或句柄以规避授权；临时作用域注销后旧 URI 立即失效。

### 6.3 保留区保护

1. 保留目录与保留前缀条目只由平台组件访问（文档服务、配置系统、资源管理、启动恢复）；任何插件经 `file:*` / `resources:write` / `file:move` / `file:copy` / `file:mkdir` 触碰保留路径一律返回 `WORKSPACE_RESERVED_PATH`，并记录审计。
2. 文件树、资源枚举与搜索结果一律过滤保留区（§3.2）；插件不得通过列举发现保留区条目。
3. `document:export` / `document:save` 的临时物必须落在同级保留前缀目录；写入前逐目标执行真实路径校验（`starts_with` 组件语义），禁止符号链接逃逸（[04-资源管理设计](./04-资源管理设计.md) §9）。
4. 用户手工删除或修改 `.chips/` 内容时，平台不得崩溃：标记缺失按"未初始化"处理，状态与缓存缺失按需重建；标记格式非法返回 `WORKSPACE_VERSION_UNSUPPORTED` 并保留原目录。

### 6.4 跨工作区隔离

- 同一时刻只有一个活动工作区；切换时旧工作区的全部文档会话、资源作用域与文件监听必须释放（§2.3）。
- 路径访问按"当前工作区 + 显式授权"判定：插件不能因为曾访问过旧工作区而继续访问其路径；旧作用域注销后所有句柄 `invalidated`（`scope-revoked`）。
- 文档内容中的引用不自动获得跨工作区访问权：包内相对路径只在包作用域内解析；`file://` 指向工作区外时按普通路径权限判定（R13）；箱子条目的 `file://` 引用跨工作区时，打开该条目需要该路径的读权限，否则条目级降级占位。
- 两个工作区中同名 ID 文档互不影响：`documentId` 只在同一会话/平台运行期内唯一；跨工作区不建立关联，不自动同步（§7.4）。
