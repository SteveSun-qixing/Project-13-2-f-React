## 三、Context 结构与生命周期

### 3.1 数据结构

Context 节点之间用 ID 相互引用，避免 `Arc` 循环引用；树的实体存放在 `ContextRegistry` 中。

```rust
/// Context 的唯一标识；由内核单调递增分配。
pub type ContextId = u64;

/// Context 生命周期状态。
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ContextState {
    /// 已创建，尚不接受服务注册。
    Created,
    /// 运行中，可注册服务、订阅事件。
    Active,
    /// 正在销毁，拒绝新注册。
    Disposing,
    /// 已销毁；一切操作返回 `KERNEL_CONTEXT_DISPOSED`。
    Disposed,
}

/// Context 树节点。
#[derive(Debug)]
pub struct ContextNode {
    /// 节点 ID。
    pub id: ContextId,
    /// 父节点；根 Context 为 `None`。
    pub parent: Option<ContextId>,
    /// 子节点，按创建顺序排列。
    pub children: Vec<ContextId>,
    /// 该 Context 的作用域 Fork，见第四章。
    pub fork: ForkId,
    /// 生命周期状态。
    pub state: ContextState,
}

/// 协作式取消令牌；由内核创建并传入任务，任务周期性检查。
#[derive(Clone)]
pub struct TaskSignal(Arc<AtomicBool>);

impl TaskSignal {
    /// 触发取消；由内核在撤销 Fork 或强撤任务时调用。
    pub fn cancel(&self) {
        self.0.store(true, Ordering::Release);
    }

    /// 任务周期性检查；返回 `true` 表示应尽快退出并释放已占用资源。
    pub fn is_cancelled(&self) -> bool {
        self.0.load(Ordering::Acquire)
    }
}

/// 后台任务句柄；由 `Context::task` 返回（内部持有取消信号与等待句柄）。
///
/// - `join()`：等待任务退出；任务失败时返回错误。
/// - `cancel()`：触发协作式取消；任务未在强撤上限内响应时按 6.7 强制中止。
#[derive(Clone)]
pub struct TaskHandle {
    /// 任务名；未命名时为 `None`。
    pub name: Option<String>,
}

/// 任务登记选项；与 TypeScript 视图 `ctx.task(fn, { name?, signal? })` 一一对应。
#[derive(Default)]
pub struct TaskOptions {
    /// 任务名；用于诊断、审计与配额计量展示。
    pub name: Option<String>,
    /// 外部取消信号；任务同时受所属 Fork 的取消约束。
    pub signal: Option<TaskSignal>,
}

/// 暴露给插件与平台代码的 Context 句柄。
#[derive(Clone)]
pub struct Context {
    id: ContextId,
    kernel: Arc<Kernel>,
}

impl Context {
    /// 在当前 Context 注册服务，语义见 5.2。
    pub fn provide<T>(&self, name: ServiceName, value: T) -> Result<(), KernelError>
    where
        T: Any + Send + Sync + 'static,
    {
        self.kernel.provide(self.id, name, value)
    }

    /// 声明依赖并注入回调，语义见 5.3。
    pub fn inject<F>(
        &self,
        dependencies: &[ServiceName],
        callback: F,
    ) -> Result<InjectionId, KernelError>
    where
        F: Fn(&Context) + Send + Sync + 'static,
    {
        self.kernel.inject(self.id, dependencies, callback)
    }

    /// 按作用域链获取服务快照，语义见 5.5。
    pub fn get(&self, name: &str) -> Result<ServiceValue, KernelError> {
        self.kernel.get_service(self.id, name)
    }

    /// 登记后台任务；任务绑定当前 Fork，参与配额与取消，语义见 4.2、6.9、10.4。
    pub fn task<F>(
        &self,
        work: F,
        options: TaskOptions,
    ) -> Result<TaskHandle, KernelError>
    where
        F: Future<Output = ()> + Send + 'static,
    {
        self.kernel.tasks().spawn(self.id, work, options)
    }
}
```

### 3.2 Context 树与作用域

- 根 Context 由内核启动时创建；平台服务（含 Bridge 服务）注册在根 Context，插件无需为其声明依赖。
- 每个插件加载时创建一个插件 Context，父节点为加载请求指定的父 Context（默认为根）。
- 插件可为内部子功能创建子 Context（如一次渲染会话、一个后台任务组），实现比插件更细粒度的作用域隔离。
- 服务可见性：注册在 Context 上的服务对自身与全部后代可见；同名服务以最近祖先为准，子遮蔽父。
- 事件订阅与副作用绑定创建时的作用域 Fork；Context 销毁时一并撤销。

### 3.3 Context 生命周期

| 阶段 | 进入条件 | 期间可执行 | 离开条件 |
|---|---|---|---|
| `Created` | `create_context()` | 无 | 插件 apply 开始 → `Active` |
| `Active` | 插件 apply 成功 | `provide`、`inject`、`on`、`get` | `dispose()` → `Disposing` |
| `Disposing` | `dispose()` | 仅撤销动作 | 清理完成 → `Disposed` |
| `Disposed` | 清理完成 | 无 | 终态 |

生命周期规则：

1. 销毁父 Context 前先销毁全部子 Context（后序）。
2. 销毁顺序：先子 Context，再本 Context 的 Fork（Fork 内部顺序见 4.3）。
3. Context 进入 `Disposing` 后拒绝新的 `provide`、`inject`、`on`。
4. 销毁操作幂等；重复销毁直接返回成功。

### 3.4 插件视角示例

TypeScript 插件通过 `@chips/sdk` 提供的 `Context` 类型访问内核能力；类型与接口权威见 [03-核心接口规范.md](../../05-接口与契约/03-核心接口规范.md)。

```typescript
import type { Context } from '@chips/sdk';

interface IDocumentChanged {
  uri: string;
}

interface IEditorQueued {
  uri: string;
}

/**
 * 插件入口：由内核在 Starting 阶段调用。
 * 插件 ID 为 `chips.official.editor`，自有事件域取插件 ID 末段 `editor`。
 */
export function apply(ctx: Context): void {
  ctx.inject(['document'], (ctx) => {
    ctx.on('document:changed', (payload: IDocumentChanged) => {
      const queued: IEditorQueued = { uri: payload.uri };
      ctx.emit('editor:queued', queued);
    });
  });

  // 后台任务登记到当前插件 Fork；随 Fork 撤销自动取消。
  ctx.task(
    async () => {
      // 后台索引刷新；长任务必须周期性检查取消信号。
    },
    { name: 'editor-index' },
  );
}
```
