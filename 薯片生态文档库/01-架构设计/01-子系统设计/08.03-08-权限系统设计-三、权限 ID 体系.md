## 三、权限 ID 体系

### 3.1 语法

```
permission-id = domain ":" scope [ ":" qualifier ]
domain        = 1*( lowercase / digit / "-" )        ; 内置域，平台维护
scope         = 1*( lowercase / digit / "-" )        ; 域内作用域，平台维护
qualifier     = 按域定义的限定值文法（见 4.1）        ; 资源级限制
```

规则：

- 全部小写，不含空白；冒号为唯一分隔符，限定值中允许出现 `:`（如网络端口），解析时按**前两个冒号**切分。
- 段数只能是 2 段（基础形式）或 3 段（限定形式）；4 段及以上非法。
- 基础形式 `filesystem:read` 用于能力声明与判定比对；限定形式 `filesystem:read:${userDocuments}/chips` 用于 manifest 申请与授权记录。
- 权限 ID 不复用事件 ID、资源 URI、能力 ID 的命名空间；禁止 `*` 作为 domain 或 scope。

### 3.2 内置域

内置域由平台统一维护，第三方插件不得新增域、scope 或 qualifier 文法：

| domain | scope | qualifier 文法 | 限定值规则 |
|--------|-------|----------------|------------|
| `filesystem` | `read`、`write`、`delete` | 路径模式：目录变量 + 子路径，如 `${userDocuments}/chips` | 必需 |
| `network` | `http` | 域名模式：`host`、`*.host` 或 `*` | 必需 |
| `window` | `control` | 窗口 ID 模式，如 `editor-*` | 可选 |
| `menu` | `manage` | — | 禁止 |
| `tray` | `manage` | — | 禁止 |
| `shortcut` | `manage` | — | 禁止 |
| `system` | `read` | — | 禁止 |
| `power` | `read`、`manage` | — | 禁止 |
| `transfer` | `manage` | — | 禁止 |
| `notifications` | `send` | — | 禁止 |
| `clipboard` | `access` | — | 禁止 |
| `dialogs` | `use` | — | 禁止 |
| `shell` | `external` | URL 模式：`scheme` 或 `scheme://host-pattern` | 必需 |
| `resources` | `read`、`write` | 作用域模式：`<scope>` 或 `<scope>/<path>` | 可选 |
| `config` | `read`、`write` | 命名空间：平台注册的公共命名空间 | 必需 |
| `credential` | `manage` | — | 禁止（仅自身命名空间） |
| `events` | `publish` | — | 禁止 |

限定值规则：**必需** = manifest 中该项权限必须携带限定值，缺失按 `PERMISSION_INVALID` 处理；**可选** = 可携带可不携带；**禁止** = 不得携带，携带按 `PERMISSION_INVALID` 处理。插件私有数据目录、自身配置命名空间、自身资源作用域属于免权限范围（见 [4.4](#44-免权限范围)），不需要也不应通过限定值申请。

### 3.3 命名禁令

- 禁止使用未注册的 domain/scope：安装校验返回 `PERMISSION_UNKNOWN`。
- 禁止把能力 ID 写成权限 ID（反之亦然）：R3 红线，评审与静态检查均拦截。
- 禁止使用重复条目：相同权限 ID（含限定值）在 manifest 中重复时去重保留一条。
- 禁止在 qualifier 中写死绝对路径：路径限定必须使用目录变量（见 7.3），保证跨用户与跨平台可移植。
