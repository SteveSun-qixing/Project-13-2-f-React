## 一、定位与职责

配置系统是薯片平台的子系统，把平台、用户、工作区、插件四类配置数据统一为可校验、可覆盖、可迁移、可通知的键值模型。

### 1.1 职责

| 职责 | 说明 |
|---|---|
| 分层存储 | 管理平台层、用户层、工作区层、插件层四类配置载体 |
| 覆盖解析 | 按键计算唯一生效值，处理层间覆盖与策略锁定 |
| Schema 校验 | 注册平台与插件配置 schema，在写入、加载、迁移时校验 |
| 默认值 | 汇总平台与插件声明的默认值，默认值不落盘 |
| 插件配置视图 | 插件启用时输出 `PluginConfig` 只读快照，作为内核 `apply(ctx, config)` 的配置来源（2.5） |
| 变更通知 | 落盘成功后发布 `config:changed` 事件 |
| 版本迁移 | 按 `schemaVersion` 执行平台内置迁移链与插件声明迁移 |
| 原子持久化 | 串行写入与原子替换，杜绝半写状态 |

### 1.2 职责边界

- 设置面板等界面属于插件；本文只定义配置系统行为，不定义任何 UI。
- `.card` / `.box` / `.cpk` 的文件格式规范由 [卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md) 等文件格式文档定义；本文只定义配置系统自身的文件结构。
- 凭证材料不进入配置系统，边界见第七节；凭证能力契约见 [能力契约规范](../../05-接口与契约/04-能力契约规范.md)。
- 插件只能经 Bridge 能力读写配置，禁止直接读写配置文件（架构红线）。
- 配置数据默认留在本地，不默认上传；跨设备能力由用户主动安装的同步插件承担。
