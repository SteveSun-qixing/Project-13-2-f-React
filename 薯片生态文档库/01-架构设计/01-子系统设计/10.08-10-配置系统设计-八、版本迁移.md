## 八、版本迁移

### 8.1 版本字段

- 每份配置文件顶层携带 `schemaVersion`（正整数，从 1 开始）。
- 平台键文件（平台层/用户层/工作区层）的版本跟随平台配置 schema 版本，由核心发布时递增。
- 插件键文件的版本跟随插件 `assets/schemas/config.schema.json` 的 `x-chips-schema-version`。

### 8.2 加载时迁移流程

```
读取配置文件
    │
    ▼
解析 JSON 并读取 schemaVersion
    ├─ 等于当前版本 ──→ 按 schema 校验后加载
    ├─ 低于当前版本 ──→ 备份 → 执行迁移 → 结果校验 → 原子写回 → 逐键发 config:changed
    └─ 高于当前版本 ──→ 拒绝加载该文件（CONFIG_VERSION_UNSUPPORTED），保留原文件，使用低层值
```

### 8.3 平台配置迁移

平台键文件的迁移链内置在 Rust 核心中，按版本逐级执行：

```rust
pub struct MigrationStep {
    pub from: u32,
    pub to: u32,
    pub migrate: fn(BTreeMap<String, serde_json::Value>) -> Result<BTreeMap<String, serde_json::Value>, ConfigError>,
}

pub struct MigrationEngine {
    steps: Vec<MigrationStep>,
}

impl MigrationEngine {
    pub fn migrate(
        &self,
        from: u32,
        to: u32,
        values: BTreeMap<String, serde_json::Value>,
    ) -> Result<BTreeMap<String, serde_json::Value>, ConfigError> {
        let mut current = values;
        for version in from..to {
            let step = self
                .steps
                .iter()
                .find(|step| step.from == version)
                .ok_or(ConfigError::MigrationMissing(version.to_string()))?;
            current = (step.migrate)(current)?;
        }
        Ok(current)
    }
}
```

- 迁移函数为纯函数，只处理键值结构，不访问文件系统与网络。
- 迁移链必须连续覆盖全部历史版本；缺失步骤视为核心缺陷，加载返回 `CONFIG_MIGRATION_MISSING`。
- 版本规则的总体定义见 [版本与迁移规范](../../04-文件格式规范/04-版本与迁移规范.md)。

### 8.4 插件配置迁移

插件以声明式迁移文件 `config.migrations.json` 描述历史版本到当前版本的变更，操作使用 RFC 6902 JSON Patch：

```json
{
  "migrations": [
    {
      "from": 1,
      "to": 2,
      "patch": [
        { "op": "move", "from": "/values/font", "path": "/values/fontSize" },
        { "op": "add", "path": "/values/autoSave", "value": true }
      ]
    }
  ]
}
```

- 迁移按 `from`/`to` 连续执行，事后用当前 schema 整体校验。
- 插件启用时触发迁移；迁移在插件启动前完成，期间该插件配置读取阻塞。
- 缺失迁移声明且版本落后时返回 `CONFIG_MIGRATION_MISSING`，保留原文件，插件以 schema 默认值运行，不阻塞插件启动。
- 迁移失败时保留原文件与备份，返回 `CONFIG_MIGRATION_FAILED`，插件以默认值运行并输出诊断记录。
- 插件包内文件布局与打包要求见 [插件包格式](../../04-文件格式规范/03-插件包格式.md)。

### 8.5 迁移约束

- 迁移只执行一次，以 `schemaVersion` 为准；迁移函数必须幂等，重复执行不得产生额外副作用。
- 备份保留最近一次，写入同目录 `backup/`；备份只用于人工恢复，平台不回读。
- 不保留废弃键、不双读旧键名；重命名与删除一律在迁移中收口（大爆炸重构，无兼容包袱）。
