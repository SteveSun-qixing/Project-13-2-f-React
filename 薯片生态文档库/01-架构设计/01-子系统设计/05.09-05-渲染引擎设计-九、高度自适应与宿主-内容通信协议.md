## 九、高度自适应与宿主-内容通信协议

> 本节"宿主"指 iframe 的直接父页面（父帧），与术语表中的平台角色 Host（能力提供方）无关；正文统一使用"父帧/子帧"表述。

### 9.1 通道建立

1. RenderHost（或父帧）创建 iframe，URL 携带一次性握手令牌（fragment，仅子帧脚本可读）。
2. 子帧加载平台帧运行时并读取令牌；父帧创建 MessageChannel 并持有一端，随后把另一端随首条消息经 `contentWindow.postMessage`（目标 `'*'`，沙箱帧为不透明源）转移给子帧。
3. 子帧校验首条消息中的令牌一致后建立通道；此后所有通信只经 MessagePort。
4. 不依赖 `event.origin` 白名单：沙箱帧为不透明源（opaque origin），`origin` 恒为 `"null"`，无法作为信任依据；信任边界为一次性令牌 + 端口所有权。
5. 握手超时（默认 5s）视为帧启动失败：`RENDER_FRAME_TIMEOUT`，帧降级为占位。

### 9.3 消息清单与约束

| 消息 | 方向 | 触发时机 | 约束 |
|---|---|---|---|
| `frame:ready` | 子 → 父 | 插件装载完成、首帧已提交 | 只能发送一次；重发视为协议违规 |
| `frame:height` | 子 → 父 | 内容高度变化（合并后） | 每 rAF 最多一条；`epoch` 单调递增 |
| `host:height-ack` | 父 → 子 | 父帧接受高度 | 回带 `epoch`，子帧清理已确认批次 |
| `frame:entry-request` | 子 → 父 | 布局帧可见范围变化 | 仅布局帧允许；`maxNestedFrames = 0` 的帧发送视为违规；必须携带 `requestId` 用于关联本次请求 |
| `host:entries` | 父 → 子 | 批量下发条目 ticket | 顺序与 `entry_ids` 对应；`requestId` 必须回带对应 `frame:entry-request` 的值；只允许发往布局帧 |
| `frame:action` | 子 → 父 | 用户触发资源打开/跳转/复制/通知 | 全部经 Bridge 能力转发并做权限判定；`open-resource` 的 `request` 为 `IResourceOpenRequest`（[14-资源打开与默认处理器契约](../../05-接口与契约/14-资源打开与默认处理器契约.md) §2.2），RenderHost 校验 URI 属于当前渲染会话可见引用后按 `origin: 'frame'` 调用资源打开路由 |
| `host:action-error` | 父 → 子 | 动作被拒绝或失败 | `requestId` 必须与请求对应 |
| `frame:error` | 子 → 父 | 插件抛错、资源失败 | `ChipsError` 结构；可重试错误带 `retryable` |
| `host:update` | 父 → 子 | 编辑链路在 `document:write` 成功后更新会话视图 | `revision` 严格递增且来自 `document:write`；帧内自行 diff 渲染并逐节点重建 `BaseCardView` |
| `host:dispose` / `frame:dispose-ack` | 父 ⇄ 子 | 帧销毁 | 父帧等待 ack 或 1s 超时后强制移除 |

规则：

- 未列入清单的消息类型一律忽略并记录诊断；协议升级走 `FRAME_PROTOCOL` 版本号协商，不允许特性探测式分支。
- 单个 `frame:action` 默认超时 5s，超时回 `host:action-error`。
- 帧不得越级发送消息（条目帧不得直接请求 RenderHost）；越级视为协议违规并断开通道。
- 编辑不经帧：帧协议不承载任何编辑提交；编辑回流只经编辑链路按第 8.3 节的唯一时序执行。

### 9.4 高度自适应算法

1. 帧运行时对根滚动元素建立 `ResizeObserver`，在每帧 rAF 结束时读取一次测量值。
2. 合并与去抖：同一 rAF 内多次变化只产生一条 `frame:height`；变化小于 1px 忽略；`epoch` 递增。
3. 父帧收到高度后执行 clamp（`limits.minHeight` ~ `limits.maxHeight`），应用到 iframe 高度并回 `host:height-ack`。
4. 子帧在收到 ack 前继续累积变化，pending 值与最近发送值不一致时在下一次 rAF 重发。
5. 超过 `maxHeight` 时不再增长，帧内改为纵向滚动；父帧在高度达到上限后停止更新，避免"增长-滚动"震荡。
6. 图片、字体异步加载引起的连续变化按 100ms 稳定窗口收敛：若 100ms 内不再变化，则最终高度以最后一次测量为准。
7. 布局帧收到条目帧高度后重算自身槽位与总高度，再按同一算法上报；整棵树的高度更新在同一 rAF 批量完成。
8. 高度缓存按帧类型与 `source + revision 摘要` 记录，用于虚拟化估算与首屏占位，避免二次抖动。

### 9.5 超时与错误

| 场景 | 超时 | 结果 |
|---|---|---|
| 帧握手（`frame:ready`） | 5s | `RENDER_FRAME_TIMEOUT`，占位降级，可重试 |
| 帧动作（`frame:action`） | 5s | `host:action-error`，帧内提示 |
| 帧销毁 ack | 1s | 强制移除帧，释放端口与句柄 |
| 条目 ticket 下发 | 10s | 条目级降级占位 |

### 9.6 通道安全校验

- 所有入站消息必须经端口来源校验：只处理已建立通道上、封套 `sessionId` / `frameId` 与本地登记一致的消息。
- 拒绝超出 `limits` 的高度值、非递增 `epoch` / `revision`、未知消息类型，并记录诊断。
- 帧内错误消息不得携带文件字节或敏感路径；诊断详情按错误模型规范裁剪。
