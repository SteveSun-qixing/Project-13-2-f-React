## 四、能力注册表与发现

### 4.1 注册项结构

```typescript
interface ICapabilityRegistration {
  capability: ICapability;
  owner: string;
  timeoutMs: number;
  concurrency: 'parallel' | 'serial';
  maxQueue: number;
  sessionInFlightLimit: number;
}

interface ICapabilityRegistry {
  register(registration: ICapabilityRegistration): void;
  unregister(capabilityId: string): void;
  get(capabilityId: string): ICapabilityRegistration | undefined;
}
```

| 字段 | 默认值 | 说明 |
|---|---|---|
| `capability` | — | 能力定义（3.2 节） |
| `owner` | — | 提供方标识：平台服务域 ID 或服务插件 ID（反向域名） |
| `timeoutMs` | `30000` | 调用超时（毫秒），见 8.1 节 |
| `concurrency` | `'parallel'` | `'serial'` 时同一能力 ID 全局串行，见 8.3 节 |
| `maxQueue` | `32` | `'serial'` 时的等待队列上限 |
| `sessionInFlightLimit` | `64` | 同一会话对该能力的在途调用上限；超限返回 `BRIDGE_SESSION_BUSY`，见 8.3 节 |

注册表是平台内部结构，不通过 `window.chips` 暴露；其权威实例位于 Bridge 核心，主进程 TS 适配层只读查询。

### 4.2 注册与注销

| 操作 | 触发者 | 时机 | 处理 |
|---|---|---|---|
| 注册 | 平台服务域 | 平台启动阶段登记内置能力 | 校验失败立即失败启动流程 |
| 注册 | 服务插件 | 插件 `start` 成功后登记其能力 | 校验失败时该插件启用失败（[03-插件架构设计](./03-插件架构设计.md)） |
| 注销 | 平台 / 服务插件 | 服务插件 `stop` 前、平台退出时 | 停止接受新调用；在途调用按超时/取消收口 |
| 查询 | Bridge 核心 | 每次 `request` | 未命中返回 `BRIDGE_CAPABILITY_NOT_FOUND` |

注册时必须校验：ID 格式合法；schema 可离线编译；`permissions` 均在权限词表内且已在提供方 manifest 声明（未声明时按权限系统返回 `PERMISSION_NOT_DECLARED`）；`owner` 已处于激活状态；ID 未被占用；**ID 已登记且绑定 owner**——同一 ID 不允许改绑 owner，改绑必须等原 owner 停止完成并注销该 ID 后按新注册处理。

### 4.3 唯一性与冲突

- 能力 ID 全局唯一；重复注册返回 `BRIDGE_CAPABILITY_CONFLICT`，并拒绝后注册方启用。
- 平台内置能力的 ID 为保留标识，插件不得注册同 ID，也不得通过 `dependencies` 声明后覆盖。
- 能力 ID 与任何权限 ID 不得相同（注册时强制校验）。
- 能力注销后，其 ID 在 owner 停止完成后才可被重新注册；进行中的调用按 requestId 收口。

### 4.4 发现机制

- **编译期发现**：插件通过 `@chips/sdk` 的类型与[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md)的内置能力清单确定可用能力；调用点在编译期完成 `capabilityId` 与输入/输出类型检查。
- **静态预期**：插件在 manifest 中声明 `permissions` 与 `dependencies`；安装与启用阶段静态校验能力与权限是否存在、是否匹配。
- **运行时判定**：Bridge 不提供能力枚举 API（`IChipsBridge` 方法面固定）。能力缺失通过调用结果的 `BRIDGE_CAPABILITY_NOT_FOUND` 判定，该错误不可重试。
- **服务插件能力**：服务插件注册的能力同样进入注册表，其他插件按 ID 调用，调用链路与内置能力完全一致。
