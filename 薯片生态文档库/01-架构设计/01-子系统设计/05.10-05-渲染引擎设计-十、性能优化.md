## 十、性能优化

### 10.1 门禁基线（R18）

| 指标 | 目标 | 渲染层分解（预算） |
|---|---|---|
| 打开卡片 | < 100ms | 请求接受 → 解析 ≤ 30ms；帧创建 → `frame:ready` ≤ 40ms；ready → 首帧提交 ≤ 30ms |
| 打开箱子 | < 200ms | 请求接受 → 解析 ≤ 60ms；顶层帧创建 → `frame:ready` ≤ 80ms；首屏条目帧 ≤ 60ms |
| 持续渲染 | > 60fps（Phase 2 > 30fps） | 单帧内更新任务 ≤ 16ms；高度批量提交每 rAF 一次 |
| 空闲内存 | < 500MB（平台级） | 帧池 ≤ 32；解析缓存 ≤ 64 项；封面缓存 ≤ 64 项 |

"打开耗时"定义为：`RenderEngine.open()` 被调用到会话触发 `ready` 事件（首帧提交完成）。骨架展示不计入阻塞，但骨架必须在请求接受后下一帧内可见。

### 10.2 虚拟化

- 箱子条目由箱子布局插件上报可见范围，RenderHost 只为可见范围 ± overscan（默认 2）下发 ticket 与创建帧。
- 高度未知时先用 `estimateEntryHeight` 或高度缓存；测量完成后回填并触发布局帧重排。
- 滚动锚定：销毁视口上方帧时按累计高度差补偿滚动位置，保证视口内容不跳动。
- 帧创建限流：单批并发初始化 ≤ 4，其余排队；空闲期（`requestIdleCallback`，超时回退 `setTimeout 0`）执行。
- 帧销毁归还帧池复用，避免反复创建 iframe 造成的内存与启动抖动。

### 10.3 增量渲染

- `update(view, revision)` 只更新受影响帧；判定条件：`kind`、`pluginEntries`、`resourceBase` 不变且帧未处于错误态时复用帧，否则重建；更新失败返回 `RENDER_UPDATE_FAILED` 并保留旧帧。
- 帧内更新由插件自行 diff DOM；平台只保证视图 revision 单调与消息有序。
- 同一 rAF 内的多次编辑回流由编辑链路合并为一次 `update(view, revision)`；回流到预览更新预算 ≤ 100ms（第 8.3 节、[12-编辑引擎设计](./12-编辑引擎设计.md)）。
- 高度变化、条目增删、布局重排在同一 rAF 批量提交；避免逐条消息触发同步布局。
- 会话级队列串行处理 update，防止并发更新导致 revision 乱序。
- 大文档（条目 > 200）强制开启虚拟化；未开启虚拟化的箱子布局插件必须在 manifest 中声明并说明理由（清单规范见[02-插件清单规范](../../03-插件开发/02-插件清单规范.md)）。

### 10.4 缓存

| 缓存 | 内容 | 键 | 失效 |
|---|---|---|---|
| 解析缓存 | 解析句柄与会话解析结果（`DocumentView` 的构建输入；构建器本身无缓存，见 §2.6） | source URI + 文件摘要 | `document:changed` / `file:changed` 事件 |
| 帧文档缓存 | 平台帧 HTML/运行时产物 | 平台版本 | 应用升级 |
| 帧池 | 已销毁的可复用帧 | 帧角色 | 超过池上限按 LRU 淘汰 |
| 高度缓存 | 条目/文档高度 | `source + revision 摘要` | 文档变更或尺寸阈值变化 |
| 封面缓存 | 封面帧渲染结果 | source + 文件摘要 | `document:changed` |
| 插件模块缓存 | 插件渲染入口模块图 | 插件 ID + 版本 | `plugin:loaded` / `plugin:unloaded` |

缓存容量、LRU 淘汰与并发去重由资源管理器与 RenderHost 分别负责；帧池上限在全平台统一为 32。

### 10.5 调度

- 帧创建、模块加载、高度提交全部经渲染层调度器排队，禁止在事件回调中同步执行重活。
- 每个 rAF 周期只做一次高度聚合与一次位姿提交。
- 输入响应优先：滚动/拖拽期间暂停非可见帧的创建与更新，滚动停止后恢复。
