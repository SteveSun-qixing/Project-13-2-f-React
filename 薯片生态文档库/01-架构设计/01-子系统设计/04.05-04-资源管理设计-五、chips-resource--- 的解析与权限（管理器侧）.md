## 五、chips-resource:// 的解析与权限（管理器侧）

### 5.1 解析流水线

```
URI 字符串
  → 语法解析（scheme、scope、path）          失败：RESOURCE_INVALID_URI / RESOURCE_UNSUPPORTED_SCHEME
  → 作用域查找（ScopeRegistry）              失败：RESOURCE_NOT_FOUND
  → 路径校验（PathGuard）                    失败：RESOURCE_PATH_INVALID
  → 会话与权限判定                            失败：RESOURCE_PERMISSION_DENIED
  → Provider 选择与地址构建
  → ResourceAddress
```

URI 语法规格（scheme 写法、作用域命名、百分号编码、external 形式）以[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md)为准；包内相对路径与 `file://` 由文档解析器在进入渲染前归一为受管作用域 URI，`http(s)://` 与 `webdav://` 归一为 external 作用域（R13、[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md) §2.2、§2.6）。

### 5.2 作用域注册

```rust
pub struct ScopeRegistration {
    pub scope: ScopeId,
    pub kind: ScopeKind,          // Document | Plugin | Platform | External | Workspace | Temporary | Memory
    pub owner: PluginId,
    pub origin: Origin,
    pub policy: ScopePolicy,
}

pub struct ScopePolicy {
    pub read_only: bool,
    pub max_resource_bytes: u64,
    pub allowed_hosts: Vec<HostPattern>,   // 仅 External 使用
}
```

| 注册时机 | 作用域类型 | 说明 |
|---|---|---|
| 打开工作区 | Workspace | 用户工作区根目录；文件树与扫描范围见[13-工作区设计](./13-工作区设计.md) |
| 打开 `.card` / `.box` | Document | ID 由平台分配，绑定渲染会话与所属应用插件 |
| 插件加载 | Plugin | 指向 `.cpk` 安装目录；默认仅插件自身可读写，跨插件访问需 `resources:read` / `resources:write` 授权 |
| 平台启动 | Platform | 平台安装目录与内嵌资源；只读、不可列举 |
| 首次解析到外部引用 | External | 按 origin 注册，走 HttpProvider |
| `dialog:*` 用户授权 | Temporary | 见 5.4 节 |
| 运行时内存形态 | Memory | 仅会话内，禁止持久化 |

注册结果返回给渲染层的规范基址（`resourceBase`）以[05-渲染引擎设计](./05-渲染引擎设计.md) 5.1 为准；作用域在渲染会话 dispose 时注销并清空对应缓存。

### 5.3 权限判定

判定输入：调用者插件 ID、资源会话、作用域、所需权限。Bridge 按 manifest 申请集合与能力声明集合的交集判定（R3）；管理器对会话绑定做二次校验。免权限范围与授权交互见[08-权限系统设计](./08-权限系统设计.md) 4.4、7.5。

| 作用域 | 调用者 | 读取 | 写入 | 附加约束 |
|---|---|---|---|---|
| Document（会话绑定） | 该渲染会话及其派生子会话 | 免权限 | — | 只读；写入只经文档服务受控提交，`resource:write` 不适用；会话结束立即失效 |
| Document（会话外） | 其他插件 | `resources:read:<scope>` | 仅文档服务 | 按 scope 前缀匹配 |
| Workspace | 持有工作区会话的插件 | `resources:read:<scope>` | `resources:write:<scope>` | 写入受 PathGuard 与审计；工作区边界见[13-工作区设计](./13-工作区设计.md) |
| Plugin（自身） | 插件自身 | 免权限 | `resources:write` | 仅自身作用域；写入仍受 PathGuard 与审计 |
| Plugin（他人） | 其他插件 | `resources:read:<scope>` | `resources:write:<scope>` | 默认拒绝，经用户授权后放行 |
| Platform | 任意插件 | `resources:read:platform` | 禁止 | 只读、不可列举 |
| External | 任意插件 | `resources:read:<scope>` | 禁止 | 另需 `network:http:<host>`；默认无凭证 |
| Temporary（对话框授权） | 持有 `dialogs:use` 的插件 | 授权后放行 | 按临时授权规则（`resources:write`） | 用户经 `dialog:open` / `dialog:save` 明确选择的路径；作用域生命周期：单次读写后自动注销，或会话结束时注销；写入仍受 PathGuard 与审计 |
| Memory（仅运行时） | 会话内调用方 | 会话内免权限 | 会话内允许 | 禁止持久化，不进入磁盘缓存 |

能力 → 权限映射（资源域示例，完整表见[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md)、[08-权限系统设计](./08-权限系统设计.md) 4.3）：

| 能力 ID | 所需权限 |
|---|---|
| `file:read` | `filesystem:read` |
| `file:write` | `filesystem:write` |
| `file:list` | `filesystem:read` |
| `file:move` | `filesystem:write`（源与目标都需校验） |
| `file:copy` | `filesystem:read`（源）+ `filesystem:write`（目标） |
| `file:delete` | `filesystem:delete` |
| `file:mkdir` | `filesystem:write` |
| `dialog:open` | `dialogs:use` |
| `dialog:save` | `dialogs:use` |
| `http:request` | `network:http:<host>` |

`file:move` / `file:copy` / `file:mkdir` 为本轮正式登记的能力，契约条目以[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md)为准。

`chips.resource()` 不经过能力 ID 申请，其权限由目标作用域类型与 `resources:read` / `resources:write` 决定（上表）；两张能力面共用同一引擎，权限判定口径一致。

### 5.4 临时作用域（用户授权路径）

当插件调用 `dialog:open` / `dialog:save` 时，用户选择的路径会创建临时作用域，规则：

1. **作用域注册**：用户点击"打开"或"保存"后，平台为选中路径创建 `Temporary` 作用域，分配唯一 `ScopeId`（如 `temp-7a3f`）。
2. **权限范围**：
   - `dialog:open` 返回的路径作用域：只允许读取（`filesystem:read`）。
   - `dialog:save` 返回的路径作用域：允许读取与写入（`filesystem:read` + `filesystem:write`）。
   - 如果用户选择了目录，作用域覆盖整个目录树；如果选择了文件，作用域仅覆盖该文件。
3. **生命周期**：
   - `dialog:save` 临时作用域：单次写入后自动注销（防止插件在用户不知情时反复写入）。
   - `dialog:open` 临时作用域：会话结束时注销，或插件显式调用 `revokeTempScope(scopeId)` 提前注销。
4. **资源协议映射**：
   - 平台将用户选择的路径映射为 `chips-resource://temp-7a3f/...` URI。
   - 插件经 `dialog:*` 获得的是规范化的 `chips-resource://` URI，不接触真实文件系统路径。
   - 该 URI 在 `IResourceHandle` 中可正常读取（`read` / `stream`）；写入经受控提交路径（`file:write` 或文档服务），句柄本身只读（4.1、4.8）。
5. **路径安全**：
   - 临时作用域同样受 PathGuard 约束；用户选择 `/home/user/docs/report.pdf`，插件不能访问 `/home/user/docs/../secrets.txt`。
   - 作用域根为用户选择的路径（文件或目录）；所有访问必须在根内。

示例：

```typescript
// 插件调用保存对话框
const result = await window.chips.request<IDialogSaveOutput>('dialog:save', {
  title: '导出卡片',
  defaultPath: 'my-card.png',
  filters: [{ name: 'PNG 图片', extensions: ['png'] }],
});

if (!result.canceled && result.path) {
  // result.path 是规范化的 chips-resource:// URI
  const handle = window.chips.resource(result.path);
  await window.chips.request('file:write', {
    uri: result.path,
    data: pngBytes,
    encoding: 'base64',
  });
  // 写入完成后，临时作用域自动注销
}
```

### 5.5 错误码

| 错误码 | 含义 | 可重试 |
|---|---|---|
| `RESOURCE_INVALID_URI` | URI 语法非法 | 否 |
| `RESOURCE_UNSUPPORTED_SCHEME` | 不支持的 scheme | 否 |
| `RESOURCE_NOT_FOUND` | 作用域或资源不存在 | 否 |
| `RESOURCE_PATH_INVALID` | 路径非法（含穿越尝试） | 否 |
| `RESOURCE_PERMISSION_DENIED` | 无权限 | 否 |
| `RESOURCE_TOO_LARGE` | 超过 `read()` 上限 | 否 |
| `RESOURCE_BUSY` | 句柄正被流占用 | 是 |
| `RESOURCE_HANDLE_RELEASED` | 句柄已释放 | 否 |
| `RESOURCE_HANDLE_INVALIDATED` | 句柄已失效 | 是（重新获取） |
| `RESOURCE_POOL_EXHAUSTED` | 句柄或队列超限 | 是 |
| `RESOURCE_READ_ONLY` | 目标来源不允许就地写入 | 否 |
| `RESOURCE_WRITE_FAILED` | 写入提交失败（磁盘、锁冲突） | 是 |
| `RESOURCE_NETWORK_FAILED` | 外部请求失败 | 是 |
| `RESOURCE_ALREADY_EXISTS` | 目标已存在（`rename` / `move` 不覆盖） | 否 |
| `RESOURCE_NOT_EMPTY` | 目录非空（`delete` 非递归模式） | 否 |
| `RESOURCE_NOT_SUPPORTED` | 操作不被当前 Provider 支持（如平台作用域不支持列举） | 否 |
| `RESOURCE_CROSS_SCOPE` | 操作涉及跨作用域，但调用方无目标作用域权限 | 否 |

`RESOURCE_ALREADY_EXISTS` / `RESOURCE_NOT_EMPTY` / `RESOURCE_NOT_SUPPORTED` / `RESOURCE_CROSS_SCOPE` 已登记进[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md)（完整错误码表），本节与协议保持同一口径。

完整错误码、`details` 结构与作用域级错误以[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md)为准；跨 Bridge 归一格式遵循[02-Bridge三层设计](./02-Bridge三层设计.md)。
