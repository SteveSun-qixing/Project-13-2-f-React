## 一、定位与范围

渲染引擎负责把 `.card` / `.box` 文档变成窗口内可见、可测量的界面。它不解析文件、不读写存储、不定义格式字段、不定义插件接口签名；它消费解析结果，编排插件视图，管理渲染帧，交付最终 DOM。

本文件回答：

- 统一渲染链路由哪些阶段组成，各阶段的输入输出与权威归属。
- Electron 渲染进程如何组织 React 壳、渲染会话与渲染帧。
- 渲染帧的沙箱属性、CSP 与通信约束。
- 资源如何以 `chips-resource://` 注入渲染帧。
- 基础卡片与箱子布局如何被装载、编排、测量与降级。
- 编辑态就近渲染允许什么、必须复用什么、禁止什么。
- 高度自适应与父帧-子帧通信协议的完整定义。
- 虚拟化、增量渲染与缓存的策略与门禁。

### 1.1 术语约定

| 术语 | 含义 |
|---|---|
| 渲染会话（session） | 一次打开文档所对应的渲染上下文：解析结果引用、帧树、资源句柄、错误状态。 |
| 渲染帧（frame） | 承载第三方渲染内容的 `sandbox` iframe。 |
| 布局帧 / 条目帧 | 布局帧指承担箱子布局渲染的渲染帧；条目帧指布局帧内嵌的条目目标帧，按票证 `view.kind` 渲染卡片视图或箱子封面。 |
| 父帧 / 子帧 | iframe 树中相邻两级：创建方为父帧，被创建方为子帧。 |
| 帧运行时（frame runtime） | 平台注入每个渲染帧的引导与协议实现，不含插件业务代码；为每个内容节点创建独立容器并逐节点调用 `renderView`。 |
| RenderHost | 渲染进程内管理渲染会话与顶层帧的服务模块。 |
| 文档视图构建器 | 解析阶段把解析句柄与会话模型投影为可结构化克隆的 `DocumentView` 的构建器，运行在主进程（Rust 核心），见第 2.6 节。 |
| 编辑链路 | 权威设计见[12-编辑引擎设计](./12-编辑引擎设计.md)；本文只规定其与渲染引擎的边界。 |
| 编辑会话（`IEditSession`） | 编辑链路持有的会话对象，绑定渲染会话与插件装载门面，权威设计见[12-编辑引擎设计](./12-编辑引擎设计.md)。 |
| 插件装载门面（`IManagedPluginRuntime`） | 平台提供的渲染侧插件运行时：`loadBaseCard(cardType)` / `loadLayout(layoutType)` 返回受管插件门面；应用与编辑链路不得自行加载插件模块。 |
| 就近渲染 | 编辑链路经 `IEditSession` 与插件装载门面，把插件视图/编辑器直接挂载到自身 UI 容器内（不经 iframe）。 |
| 首帧提交 | 渲染帧完成首次 DOM 提交并上报 `frame:ready` 的时刻。 |
