## 八、标准事件总表

规则：

- 本表是事件契约的基线；完整 payload schema、字段约束与订阅示例以《[05-事件契约规范](../../05-接口与契约/05-事件契约规范.md)》为准。
- 全部标准事件采用广播（`emit`），不定义决策型事件。
- 频率：仅 `sync:progress` 为高频事件，发布方必须限流（最小间隔在事件契约中定义）。
- 新增事件先登记再实现；事件 ID 一经登记不得随意修改。
- 插件自有域事件不进入本表，也不跨进程。

### 8.1 插件生命周期

| 事件 ID | payload 要点 | 触发时机 |
|---|---|---|
| `plugin:installed` | `{ pluginId, version }` | 插件包安装到本地插件目录后 |
| `plugin:uninstalled` | `{ pluginId }` | 插件包从本地移除后 |
| `plugin:loaded` | `{ pluginId, version, role }` | 插件加载完成并进入运行态；`role` 为 `basecard` / `boxlayout` / `app` / `service` |
| `plugin:enabled` | `{ pluginId }` | 插件由停用转为启用并完成启动 |
| `plugin:disabled` | `{ pluginId }` | 插件停用完成、监听器已摘除 |
| `plugin:unloaded` | `{ pluginId }` | 插件从运行时卸载完成、副作用全部清理 |
| `plugin:failed` | `{ pluginId, error }` | 插件加载失败或运行中崩溃；`error` 为 `ChipsError` |

### 8.2 文档

| 事件 ID | payload 要点 | 触发时机 |
|---|---|---|
| `document:opened` | `{ uri, kind, title }` | 文档解析完成并开始渲染；`kind` 为 `card` / `box` |
| `document:closed` | `{ uri, kind }` | 文档关闭、相关资源句柄释放完成 |
| `document:changed` | `{ uri, documentId, kind, digest, size }` | 文档内容写入或外部变更收敛后；字段为同步引擎等消费者的最小需求 |
| `document:saved` | `{ uri, kind }` | 文档写入持久化完成 |

### 8.3 文件

| 事件 ID | payload 要点 | 触发时机 |
|---|---|---|
| `file:changed` | `{ uri, kind, previousUri? }` | 被监视的文件或目录发生变化；`kind` 为 `created` / `modified` / `deleted` / `renamed` |

### 8.4 资源

| 事件 ID | payload 要点 | 触发时机 |
|---|---|---|
| `resource:invalidated` | `{ uri, reason }`；`reason` 为 `source-changed` / `session-closed` / `scope-revoked` | 资源来源变化、会话关闭或作用域撤销导致句柄失效时；经 `event:resource:invalidated` 投递到对应渲染会话 |
| `resource:opened` | `{ pluginId, context }`；`context` 为 `IResourceOpenContext` | 命中处理器的实例已进入 `active`、平台准备投递 `openFile` 之前；定向投递给该插件实例 |

完整 payload schema 见《[05-事件契约规范](../../05-接口与契约/05-事件契约规范.md)》与《[04-资源管理设计](./04-资源管理设计.md)》。

### 8.5 配置

| 事件 ID | payload 要点 | 触发时机 |
|---|---|---|
| `config:changed` | `{ key, layer, value, effectiveValue, origin }` | 配置落盘成功后逐键发布；`layer` 为 `platform` / `user` / `workspace` / `plugin`，`origin` 区分调用写入与外部修改 |

### 8.6 安全与审计

| 事件 ID | payload 要点 | 触发时机 |
|---|---|---|
| `security:audit` | 审计记录字段（`action`、`actor`、`pluginId`、`permission`、`traceId` 等，完整字段见《[08-权限系统设计](./08-权限系统设计.md)》） | 授权、撤销、拒绝、敏感放行等审计动作产生时；仅平台与官方审计界面订阅 |
| `permission:granted` | `{ pluginId, pluginVersion, permission, qualifier?, source, actor, timestamp }` | 权限被用户或策略授予后（启用确认、首次调用记住、设置面板、更新）；可见性为目标插件与平台 |
| `permission:denied` | `{ pluginId, pluginVersion, permission, qualifier?, capabilityId?, target?, resourceUri?, reason, sessionId?, traceId, timestamp }` | 能力调用或资源访问被权限判定拒绝时；可见性为目标插件与平台 |

`permission:*` 的字段约束与订阅示例以《[05-事件契约规范](../../05-接口与契约/05-事件契约规范.md)》为准，权限语义见《[08-权限系统设计](./08-权限系统设计.md)》第六节。

### 8.7 窗口与应用

| 事件 ID | payload 要点 | 触发时机 |
|---|---|---|
| `window:created` | `{ windowId, appId }` | 应用窗口创建完成 |
| `window:closed` | `{ windowId }` | 窗口关闭、窗口级资源释放 |
| `window:focused` | `{ windowId }` | 窗口获得焦点 |
| `app:launched` | `{ appId }` | 应用启动完成并进入可用状态 |
| `app:exited` | `{ appId, exitCode? }` | 应用退出 |

### 8.8 同步

| 事件 ID | payload 要点 | 触发时机 |
|---|---|---|
| `sync:state-changed` | `{ scopeId, providerId, state }` | 同步状态迁移 |
| `sync:progress` | `{ scopeId, sessionId, phase, completedEntries, totalEntries, transferredBytes }` | 同步进度；节流不低于 200ms |
| `sync:conflict-detected` | `{ conflictId, scopeId, documentId, detectedAt }` | 检测到冲突 |
| `sync:conflict-resolved` | `{ conflictId, scopeId, documentId, strategy }` | 冲突已解决 |
| `sync:queue-changed` | `{ scopeId, pendingChanges }` | 离线队列长度变化 |
| `sync:blocked` | `{ scopeId, code, message }` | 同步进入阻塞，需要用户处理 |

同步事件是通知而非状态：消费者必须能用 `status()` / `conflicts()` / `queue()` 查询接口重建一致状态（见《[07-同步引擎设计](./07-同步引擎设计.md)》）。

### 8.9 命令

命令域事件由平台命令注册表发布，插件不可发布；payload 契约以《[13-命令系统契约](../../05-接口与契约/13-命令系统契约.md)》§3.6、§4.2 为准。

| 事件 ID | payload 要点 | 触发时机 |
|---|---|---|
| `command:registered` | `{ commandId, ownerPluginId, target, scopeKind }` | 命令首次登记成功 |
| `command:unregistered` | `{ commandId, ownerPluginId, target, reason }` | 主动注销或生命周期清理完成 |
| `command:changed` | `{ commandId, ownerPluginId, target }` | 同一 owner 对已登记命令幂等更新 |
| `command:invoked` | `{ invocationId, commandId, handlerId, source, payload?, context }` | `ui` 目标命令派发；可见性为命令 owner 插件与平台，至多一次 |

### 8.10 内核内部事件

内核自身使用 `internal:*` 域（如 `internal:service`、`internal:listener`、`internal:dispose`、`internal:update`），用于内核组件之间的协作与框架观察点：

- 不属于公开契约，插件不得订阅或依赖；
- 永不跨进程转发；
- 具体清单与语义由《[01-薯片内核设计](./01-薯片内核设计.md)》定义。
