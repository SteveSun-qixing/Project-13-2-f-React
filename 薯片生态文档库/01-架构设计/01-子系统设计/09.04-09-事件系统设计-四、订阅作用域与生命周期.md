## 四、订阅作用域与生命周期

### 4.1 作用域模型

- **运行时实例隔离**：一个内核运行时实例拥有独立总线；不同实例之间不共享事件，互不可见。
- **实例内广播**：同一实例内的公开事件对所有活跃 Context 可见；插件通过订阅显式接收所需事件。
- **Fork 即作用域边界**：通过 `ctx.on` / `ctx.once` 注册的监听器记录在发起注册的 Context 所属 Fork 中；子上下文退订不影响父上下文，父上下文退订会一并清理其子上下文未独立注册的监听器。
- **来源可见性**：发布者身份记录在事件日志与审计输出中，但事件不构成直接依赖；插件需要调用能力或服务时使用 `request` / `inject`，不使用事件。

### 4.2 Fork 追踪与自动退订

事件订阅与定时器、服务注册、资源句柄一样，都是 Fork 追踪的可逆副作用：

```
ctx.plugin(EditorPlugin)
  └── Fork
       ├── effect: ctx.on('document:changed', listenerA)
       ├── effect: ctx.once('plugin:loaded', listenerB)
       └── effect: ctx.provide('editor', service)
```

规则：

1. **自动退订**：插件卸载时，其 Fork 内全部监听器自动从总线摘除，无需插件手工调用 `dispose()`。
2. **逆序撤销**：Fork 内副作用按注册顺序的逆序撤销（后注册先撤销）；同一插件的监听器先于其服务与资源句柄撤销。
3. **幂等**：`dispose()` 可以重复调用；已撤销的监听器不再接收事件。
4. **once 语义**：`ctx.once` 的监听器在首次投递后立即退订；始终未触发时随 Fork 一起撤销。
5. **快照与存活标记**：一次投递使用发布开始时的监听器快照；投递期间新增的监听器从下一次发布生效，投递期间被退订的监听器通过存活标记跳过。
6. **发布者自身也受约束**：插件可以订阅自有域事件；插件卸载过程中不再接收任何事件。

### 4.3 插件卸载时序

插件停用与卸载的事件时序（状态机与触发点见《[03-插件架构设计](./03-插件架构设计.md)》）：

```
停用请求 → 停止对外服务 → 摘除全部事件监听器 → 释放资源句柄
        → 撤销服务注册 → 发布 plugin:disabled / plugin:unloaded → Fork 销毁完成
```

- 监听器先于资源释放摘除，避免清理阶段仍接收事件造成悬挂引用。
- `plugin:unloaded` 在副作用全部清理完成后发布，用于通知平台与其它插件刷新视图。
- 卸载中的插件不再接收事件，包括它自己发布的事件。

### 4.4 渲染侧订阅生命周期

- 渲染进程的订阅由 preload 侧订阅表管理，句柄绑定窗口（`webContents`）会话；窗口销毁时，该窗口全部订阅自动清理并向主进程注销转发计数。
- 插件视图（基础卡片、箱子布局、应用界面）卸载时，渲染框架必须销毁其全部订阅；React 组件卸载时通过共享层提供的订阅 Hook 自动退订，禁止在组件外长期持有订阅而不释放。
- 订阅生命周期与宿主插件的启用状态一致：插件停用后其视图被销毁，订阅随之释放；插件重新启用时重新建立订阅。
