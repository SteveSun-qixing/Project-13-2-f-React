# 文档解析器设计

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：`.card` 与 `.box` 的解析、校验、诊断、惰性加载与增量重解析的实现设计

## 三、解析流水线

### 3.1 六阶段总览

```
open(path)
  │
  ├─ 阶段 1  打开与识别 ── 入口路径检查 · 目录态/归档判定 · 格式判定（card/box）
  │
  ├─ 阶段 2  建立索引 ──── 目录扫描 / ZIP 中央目录扫描 · 路径归一 · 限额检查
  │
  ├─ 阶段 3  metadata ──── YAML 解析 · schema 校验 · 版本检查 · 模型构建
  │                          └── 完成即产出可用 DocumentHandle（L0）
  │
  ├─ 阶段 4  结构与引用 ── .card/structure.yaml / .box/structure.yaml · schema 校验 · 引用/路径校验（L1，惰性）
  │
  ├─ 阶段 5  内容与配置 ── 卡片 content/*.yaml · 箱子条目分页与 .box/content.yaml 布局配置
  │                          └── 按需触发、按单元并行（L2）
  │
  └─ 阶段 6  模型构建 ──── 类型模型冻结 · 修订戳 · 统计 · 诊断排序去重
                             └── 资源字节（L3）永不在此读取
```

流水线可由两个入口驱动：`DocumentHandle::open` 执行阶段 1-3 后返回；后续阶段在访问对应层级时按需执行。`CardParser::parse` / `BoxParser::parse` 则一次性驱动全部阶段，用于导出、校验与批处理。

### 3.2 阶段 1：打开与识别

1. 检查入口路径存在且可读；不存在返回 `DOCUMENT_NOT_FOUND`，权限或 IO 失败返回 `DOCUMENT_IO`。
2. 目录判定：`is_dir()` 为真进入目录态；否则按文件处理。
3. 归档签名判定：读取前 4 字节，仅接受 `PK\x03\x04`（普通归档）与 `PK\x05\x06`（空归档）；其他文件头返回 `DOCUMENT_FORMAT_UNKNOWN`。
4. 格式判定：
   - 扩展名 `.card` / `.box`（大小写不敏感）作为首选依据；
   - 扩展名缺失或未知时探测索引：存在 `.box/` 配置目录判定为箱子，存在 `.card/` 配置目录判定为卡片；
   - 扩展名与探测结果矛盾时，`open_document` 以探测结果为准并记录 `DOCUMENT_EXTENSION_MISMATCH`（警告）；`CardParser` / `BoxParser` 的严格入口按声明格式校验失败返回 `DOCUMENT_FORMAT_UNKNOWN`。
5. 阶段 2 的索引失败会终止打开（`DOCUMENT_ARCHIVE_INVALID` / `DOCUMENT_PATH_UNSAFE`）。

### 3.3 阶段 2：建立索引

统一产出一张「包内路径 → 成员元数据」的有序索引表（按路径排序，供二分查找），目录态与压缩态字段对齐：

```rust
pub struct MemberMeta {
    pub path: PackagePath,
    pub size: u64,
    pub modified: Option<SystemTime>,
    pub crc32: Option<u32>,     // 压缩态提供
    pub method: MemberMethod,   // Store | Deflate（目录态恒为 Store 语义）
}
```

索引规则：

- 目录态：有界递归扫描（深度 ≤ 16）；忽略操作系统生成物（`__MACOSX/`、`.DS_Store`、`Thumbs.db`、`desktop.ini`）并记录 `DOCUMENT_GENERATED_FILE_IGNORED`（信息）；遇到符号链接不跟随、不纳入索引，记录 `DOCUMENT_SYMLINK_IGNORED`（错误级诊断）。
- 压缩态：定位 EOCD（含 ZIP64）→ 解析中央目录 → 构建索引；不解压任何成员。成员方法只允许 Store 与 Deflate，加密条目、其他压缩方法、损坏的中央目录返回 `DOCUMENT_ARCHIVE_INVALID`。
- ZIP 压缩与 ZIP64 规则（与[《版本与迁移规范》](../../04-文件格式规范/04-版本与迁移规范.md) §2.3 差异表一致）：发布侧一律 Store，读取侧接受 Store 与 Deflate；`.card` / `.box` 支持读取 ZIP64 归档（发布不产生 ZIP64）；`.cpk` 禁止 ZIP64（[《插件包格式》](../../04-文件格式规范/03-插件包格式.md) §2.1）。读取端不得因 Deflate 或 ZIP64 而拒绝本可正常打开的文档。
- 引用形式（唯一集合）：包内相对路径、`file://`、`http(s)://`、`webdav://`、`chips-resource://`（[《资源协议规范》](../../05-接口与契约/06-资源协议规范.md) §2.2）；`data:` 仅运行时内存形态，禁止持久化；引用形式不参与索引，校验与归一规则见 3.5 节。
- 路径归一：统一 `/` 分隔、NFC 归一；归一后重复路径返回 `DOCUMENT_ARCHIVE_INVALID`（歧义拒绝）；越界路径返回 `DOCUMENT_PATH_UNSAFE`。
- 限额检查：成员数、解压总字节、压缩比、单成员解压尺寸超过[第 9.1 节](#91-限额)的可配置安全防护默认值时返回 `DOCUMENT_LIMIT_EXCEEDED`。
- 归档根即包根：`.card/` 与 `.box/` 配置目录必须位于归档根，归档内不得出现顶层包裹目录。第三方打包必须进入目录后归档（`cd my-card && zip -r -0 ../my-card.card .`），不得把目录本身作为顶层条目写入。

### 3.4 阶段 3：metadata 解析

1. 从索引定位元数据文件（卡片 `.card/metadata.yaml`、箱子 `.box/metadata.yaml`）；缺失返回 `DOCUMENT_METADATA_MISSING`。
2. 读取字节并校验：大小不超过 `max_yaml_bytes`；UTF-8 校验；BOM 在 `repair` 开启时剥离并记录 `DOCUMENT_UNICODE_NORMALIZED`（信息），否则记录错误级诊断。
3. YAML 解析：要求根节点为映射；语法错误返回 `DOCUMENT_METADATA_INVALID`，诊断携带 `file:line:column` 与字段指针。
4. schema 校验：按[《卡片文件格式》](../../04-文件格式规范/01-卡片文件格式.md)/[《箱子文件格式》](../../04-文件格式规范/02-箱子文件格式.md)定义的 schema 执行必填、类型、枚举、格式与未知字段策略（未知字段在严格模式为错误，普通模式为警告并保留原文值）。
5. 版本检查：按第 7 节校验 `chip_standards_version` 的语义化版本语法并执行兼容判定。
6. 模型构建：产出 `CardMetadata` 或 `BoxMetadata`，`repair` 开启时补齐规范定义的默认值并记录 `DOCUMENT_DEFAULT_APPLIED`（信息）。
7. 阶段结束时释放 YAML 原文缓冲，只保留模型与诊断。

阶段 1-3 完成后返回 `DocumentHandle`，其 `metadata()` 立即可用，满足 metadata 优先与 10 ms 预算。

### 3.5 阶段 4：结构与引用解析

- 读取并解析结构文件（卡片 `.card/structure.yaml`、箱子 `.box/structure.yaml`）：根节点映射；按格式 schema 校验。
- 卡片：遍历 `structure` 数组（按渲染顺序声明内容节点）与 `manifest` 资源清单；校验节点 `id`（10 位 Base62）唯一、对应 `content/{id}.yaml` 存在于索引、`manifest.resources[].path` 为包内相对路径。结构引用缺失或非法时，该节点标记为失败并记录错误级诊断，不影响其余节点。
- 箱子：解析 `.box/structure.yaml` 的 `entries` 数组，建立条目索引并校验 `entry_id` 唯一、`url` 与 `enabled` 合法、包内引用目标存在于索引；条目明细（`snapshot`、`layout_hints`）由阶段 5 按需物化。`structure.yaml` 非法时箱子的条目层级不可用，但 metadata 仍可返回。
- 引用分类与校验（与资源协议一致）：
  - 包内相对路径：语法合法且存在于索引；卡片结构引用缺失记录 `STRUCTURE_CONTENT_MISSING`（错误），箱子条目缺失记录 `ENTRY_TARGET_MISSING`（警告），均保留位置；
  - `file://`、`http(s)://`、`webdav://`、`chips-resource://`：仅做 URI 语法校验与分类，不访问外部资源；`data:` 不视为合法持久化引用，按非法引用记录诊断；
  - 其他 scheme 或裸绝对路径：`ENTRY_SOURCE_INVALID`（错误）。
- 引用归一责任：包内相对路径与 `file://` 由解析器在进入渲染前归一为受管作用域 URI；`http(s)://`、`webdav://` 归一为 external 作用域（[《资源协议规范》](../../05-接口与契约/06-资源协议规范.md) §2.6，与[《资源管理设计》](04-资源管理设计.md) §5.1 一致）。归一发生在解析输出与文档视图构建之间，归一结果不写回文档、不回填模型，帧内不出现裸 `file://`。
- 结构层级结果缓存于句柄，重复访问不重复解析。

### 3.6 阶段 5：内容、条目与布局配置解析

- 卡片内容（`content/*.yaml`）：
  - 校验通用信封（根映射、`card_type` 为字符串），插件专有字段作为不透明值（`DocumentValue`）原样保留，不解释语义；字段完整规则见[《卡片文件格式》](../../04-文件格式规范/01-卡片文件格式.md)。
  - 并行解析各内容文件，并发度受 `parallelism` 限制；单文件失败只使该节点失败，卡片整体仍可打开，失败节点返回占位模型与诊断。
  - 未在 `structure` 中引用的内容文件在严格模式记录 `DOCUMENT_UNREFERENCED_FILE`（警告），普通模式忽略。
- 箱子条目（`.box/structure.yaml` 的 `entries`）：
  - 条目顺序即 `entries` 数组顺序；`entry_id`、`url`、`enabled` 与 `snapshot`、`layout_hints` 的语义见[《箱子文件格式》](../../04-文件格式规范/02-箱子文件格式.md)。
  - 单条目非法时该条目进入失败状态并保留位置，不静默丢弃；箱子整体仍可打开。
  - 条目数量超过 `max_entry_count` 返回 `DOCUMENT_LIMIT_EXCEEDED`。
  - 支持分页读取（`documentEntries(handle, { offset, limit })`），大型箱子按需加载，不强制全量解析。
- 布局配置（`.box/content.yaml`）：校验 `active_layout_type` 与 `layout_configs`，按需解析被选中的布局配置；未知布局类型不阻断解析，由渲染层的插件解析链路处理。

### 3.7 阶段 6：模型构建与修订

- 冻结类型模型（`Arc`），生成统计（成员数、YAML 字节数、资源数、条目数、解压总字节）。
- 计算 `DocumentRevision`：数据源指纹 + `chip_standards_version` + 索引摘要。资源正文不参与，保证构建为常数时间。
- 合并全量诊断：按 `(file, line, column, pointer, code)` 排序、去重，保证确定性。
- 全量内容摘要仅在显式调用 `content_digest()` 时计算（同步、导出、发布链路使用）。
