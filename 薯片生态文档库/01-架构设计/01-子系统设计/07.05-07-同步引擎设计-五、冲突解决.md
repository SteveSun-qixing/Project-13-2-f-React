## 五、冲突解决

### 5.1 冲突判定

三方比较（本地、远端、本地基线）：

| 本地 | 远端 | 判定 |
|---|---|---|
| 未变 | 已变 | 远端快进（直接应用） |
| 已变 | 未变 | 本地推送 |
| 未变 | 未变 | 无事发生 |
| 已变 | 已变，向量可比 | 支配方胜出：本地支配则推送，远端支配则应用 |
| 已变 | 已变，向量不可比或相等但摘要不同 | **冲突** |

### 5.2 自动处理的边界

仅"一方与基线一致、另一方为新版本"与"向量严格支配"可自动处理；其余一律进入冲突流程，**禁止自动覆盖**。

### 5.3 显式选择

```typescript
type ISyncConflictResolution =
  | { strategy: 'keep-local' }
  | { strategy: 'keep-remote' }
  | { strategy: 'keep-both'; localCopyName: string };
```

| 策略 | 行为 |
|---|---|
| `keep-local` | 远端版本经受控写链路落盘为冲突副本，本地版本推送到远端 |
| `keep-remote` | 本地版本经受控写链路落盘为冲突副本，远端版本应用到本地 |
| `keep-both` | 本地版本经受控写链路以用户指定名称另存为副本，远端版本应用到本地 |

- 冲突副本命名：`原名称（冲突副本 YYYY-MM-DD HHmmss）.<扩展名>`；重名追加序号。
- 冲突副本经受控写链路创建为独立文档（`document:export` 另存语义），写入索引并标记 `excluded`，不自动参与同步，避免同一 `documentId` 重复。
- 败者版本必须先经受控写链路落盘为副本；引擎不提供静默丢弃，也不直接写文件。

### 5.4 冲突生命周期与数据结构

`detected` → `pending`（范围状态为 `conflicted`，该文档挂起，其余文档继续）→ `resolved`（用户显式选择）→ 下一会话执行推送或应用。

```typescript
interface ISyncConflict {
  id: string;
  scopeId: string;
  documentId: string;
  local: { digest: Digest; vector: IVersionVector; modifiedAt: string };
  remote: { digest: Digest; vector: IVersionVector; modifiedAt: string };
  detectedAt: string;
  resolution?: ISyncConflictResolution;
}
```
