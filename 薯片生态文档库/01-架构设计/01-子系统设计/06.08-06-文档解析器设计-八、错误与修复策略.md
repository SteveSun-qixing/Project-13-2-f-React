## 八、错误与修复策略

### 8.1 两级错误模型

- 致命错误：操作无法继续，返回 `DocumentError`，映射为 `ChipsError` 结构（`code` / `message` / `details` / `retryable`），`message` 为简体中文用户可读文案；`details` 必须携带已收集的结构化诊断（含文件、字段指针与行列），供上层直接展示与定位。
- 非致命问题：以 `Diagnostic` 记录，保留部分成功结果。

```rust
#[derive(Debug, Clone, serde::Serialize)]
pub struct Diagnostic {
    pub severity: Severity,            // Error | Warning | Info
    pub code: &'static str,
    pub message: String,
    pub file: Option<PackagePath>,
    pub pointer: Option<String>,       // RFC 6901
    pub line: Option<u32>,
    pub column: Option<u32>,
    pub hint: Option<String>,
}
```

每个 `Diagnostic` 必须包含：可判定的码、面向用户的消息、尽可能精确的位置；`hint` 只在存在确定修复方式时给出。

### 8.2 致命错误码

| 错误码 | 含义 | 可重试 |
|---|---|---|
| `DOCUMENT_NOT_FOUND` | 入口路径不存在 | 否 |
| `DOCUMENT_IO` | 读取失败（权限、IO、映射失败） | 是 |
| `DOCUMENT_FORMAT_UNKNOWN` | 非目录、非 ZIP，或与声明格式不符 | 否 |
| `DOCUMENT_METADATA_MISSING` | 缺少 `.card/metadata.yaml` / `.box/metadata.yaml` | 否 |
| `DOCUMENT_METADATA_INVALID` | metadata 语法或 schema 失败 | 否 |
| `DOCUMENT_STRUCTURE_INVALID` | structure 语法或 schema 失败（全量解析时致命） | 否 |
| `DOCUMENT_VERSION_OUTDATED` | `chip_standards_version` 主版本过旧，需迁移 | 否 |
| `DOCUMENT_VERSION_UNSUPPORTED` | `chip_standards_version` 主版本过新，需升级平台 | 否 |
| `DOCUMENT_ARCHIVE_INVALID` | 归档损坏、重复路径、加密或非法压缩方法 | 否 |
| `DOCUMENT_PATH_UNSAFE` | 包内路径越界、非法字符，或归档路径存在安全风险 | 否 |
| `DOCUMENT_LIMIT_EXCEEDED` | 超出成员数、字节数、压缩比、别名或深度限额 | 否 |
| `DOCUMENT_PARSE_CANCELLED` | 调用方取消 | 是 |

### 8.3 诊断码

| 诊断码 | 严重级 | 含义 |
|---|---|---|
| `YAML_SYNTAX_ERROR` | 错误 | YAML 语法错误，含行列 |
| `SCHEMA_REQUIRED_MISSING` | 错误 | 必填字段缺失 |
| `SCHEMA_TYPE_MISMATCH` | 错误 | 字段类型不符 |
| `YAML_UNSUPPORTED_TAG` | 错误 | 使用禁用标签（如 `!!binary`） |
| `SCHEMA_UNKNOWN_FIELD` | 警告（严格：错误） | 未知字段 |
| `SCHEMA_DEFAULT_APPLIED` | 信息 | 已补齐默认值 |
| `STRUCTURE_CONTENT_MISSING` | 错误 | 结构引用的内容文件缺失 |
| `STRUCTURE_NODE_FAILED` | 错误 | 单个内容节点解析失败 |
| `ENTRY_SOURCE_INVALID` | 错误 | 条目引用语法非法或 scheme 不允许 |
| `ENTRY_TARGET_MISSING` | 警告 | 包内引用目标不存在 |
| `ENTRY_FAILED` | 错误 | 单条目解析失败，位置保留 |
| `DOCUMENT_RESOURCE_FILE_MISSING` | 警告 | 资源清单条目对应文件缺失 |
| `DOCUMENT_RESOURCE_INTEGRITY_MISMATCH` | 警告（严格：错误） | 尺寸或哈希不匹配 |
| `DOCUMENT_UNREFERENCED_FILE` | 警告（严格） | 存在未被引用的内容或资源 |
| `DOCUMENT_GENERATED_FILE_IGNORED` | 信息 | 忽略系统生成物 |
| `DOCUMENT_SYMLINK_IGNORED` | 错误 | 目录态符号链接未纳入索引 |
| `DOCUMENT_UNICODE_NORMALIZED` | 信息 | 已执行 Unicode/换行归一或 BOM 剥离 |
| `DOCUMENT_EXTENSION_MISMATCH` | 警告 | 扩展名与实际结构不符 |
| `DOCUMENT_VERSION_MISMATCH` | 警告 | `chip_standards_version` 次版本高于平台支持版本 |

### 8.4 部分成功矩阵

| 缺陷 | 处理 | 结果 |
|---|---|---|
| metadata 缺失或非法 | 致命 | 打开失败 |
| structure 非法（结构层级） | 结构层级错误 | metadata 可用；渲染结构不可用 |
| 单个内容文件语法错误 | 节点失败 | 卡片可打开；失败节点返回占位与诊断 |
| 单个条目非法 | 条目失败并保留位置 | 箱子可打开；条目在布局中呈现失败态 |
| 布局配置非法 | 该布局不可用 | 其他布局正常 |
| 资源文件缺失/不匹配 | 诊断 | 打开成功；访问该资源时报错 |
| 引用文件缺失 | 诊断 | 打开成功；对应节点/条目失败态 |
| 严格模式全部警告升级 | 报告 Invalid | 发布被拒绝，原文档不被修改 |

原则：任何部分成功都必须保留失败对象的位置与标识，禁止静默丢弃；调用方可据诊断决定降级展示或修复。

### 8.5 修复与归一化

- 自动归一化（`repair: true`，默认）：BOM 剥离、Unicode NFC、路径分隔符统一、规范默认值补齐、空白与换行不影响语义的标准化。全部归一化必须记录诊断。
- 不自动修复：无法确定意图的问题（必填缺失、类型错误、引用缺失、版本问题）只报告并给出 `hint`。
- 解析器永不写回文档；修复写回统一经[《文档服务设计》](11-文档服务设计.md)的受控写链路，按[《卡片文件格式》](../../04-文件格式规范/01-卡片文件格式.md)/[《箱子文件格式》](../../04-文件格式规范/02-箱子文件格式.md)的写入规则执行，修复后必须重新 `validate`。
