## 六、校验体系

### 6.1 三层校验

| 层 | 输入 | 内容 | 失败级别 |
|---|---|---|---|
| YAML 层 | 原始文本 | UTF-8、YAML 1.2 核心 schema、节点类型、深度与别名限额 | 致命（该文件不可用）或节点失败 |
| Schema 层 | YAML 值树 | 必填、类型、枚举、格式、未知字段策略、默认值 | 致命（metadata/structure）或节点失败（content/entries） |
| 语义层 | 类型模型 | 引用存在性、路径与 URI 合法性、标识唯一、树环、完整性 | 节点失败或诊断 |

严格模式（`strict: true`，`validate` 强制开启）将警告升级为错误，并启用完整性哈希校验、Span 索引、未引用文件检查；普通模式保持部分成功语义，保证用户可打开受损文档。

### 6.2 YAML 解析与字段定位

- 语义基线为 YAML 1.2 核心 schema：只接受标准标量、序列与映射；禁用自定义 `!` 标签与 `!!binary`；锚点与别名允许，但受别名计数与字节限额约束；`yes`/`no`/`on`/`off` 等歧义标量按字符串处理。
- 时间统一为 RFC 3339 UTC 字符串；数值保持整数/浮点区分；映射键必须为字符串。
- 错误定位到文件与字段：`file:line:column` + RFC 6901 字段指针。metadata 与 structure 默认建立 Span 索引；内容文件默认跳过以降低开销，仅在严格模式或该文件出现错误时二次扫描建立。
- 定位输出示例：

```
error[SCHEMA_TYPE_MISMATCH] .card/metadata.yaml:2:25 /chip_standards_version
  期望字符串，实际为数字
  hint: 版本号需使用引号包裹，如 chip_standards_version: "1.0.0"
```

### 6.3 Schema 注册表

- 方言统一：全部文档级 schema 一律以 JSON Schema 2020-12 表达（`$schema` 固定为 `https://json-schema.org/draft/2020-12/schema`），编译期嵌入二进制，位于 `schema/` 目录，按文件格式与成员类型选取（如 `card/metadata.json`、`box/metadata.json`）；不存在 draft-07 等历史方言的读取或兼容分支，格式文档中的历史示例已全部改口径。`chip_standards_version` 不参与 schema 选取，兼容性由第 7 节的语义化版本判定处理。
- 校验器输出逐项诊断：JSON Pointer、期望、实际、提示；同一字段只报告最高严重级问题。
- 插件专有配置不进入文档级 schema；由基础卡片/布局插件在渲染层校验（见[《渲染引擎设计》](05-渲染引擎设计.md)）。解析器只保证信封结构与不透明值可用。

### 6.4 引用与完整性校验

- 引用路径必须是包内相对路径或允许的 URI scheme，规则与[《资源协议规范》](../../05-接口与契约/06-资源协议规范.md)一致；越界路径为错误。
- 卡片结构引用内容文件缺失：`STRUCTURE_CONTENT_MISSING`（错误），节点失败。
- 箱子条目目标缺失（包内）：`ENTRY_TARGET_MISSING`（警告），条目保留并标记失败状态。
- 卡片 `manifest.resources` 清单完整性：尺寸不匹配立即记录 `DOCUMENT_RESOURCE_INTEGRITY_MISMATCH`（警告）；`checksum`（SHA256）校验仅在 `verify_hashes` 或 `validate` 时执行，不匹配升级为错误。
- 清单外资源文件（卡片根目录资源、箱子 `assets/`）在严格模式记录 `DOCUMENT_UNREFERENCED_FILE`（警告）。

### 6.5 校验报告

`validate` 产出 `ValidationReport`，供发布门禁与命令行工具使用：

```rust
pub struct ValidationReport {
    pub kind: DocumentKind,
    pub chip_standards_version: String,
    pub status: ValidationStatus,      // Valid | ValidWithWarnings | Invalid
    pub statistics: DocumentStatistics,
    pub diagnostics: Vec<Diagnostic>,
}
```

- 同一 `validate` 在相同输入上必须产生字节级一致的报告（诊断排序确定）。
- 发布链路的门禁：`status == Invalid` 拒绝发布；`ValidWithWarnings` 允许发布但必须展示警告。
