## 三、权威接口

### 3.1 `IChipsBridge`（对外唯一形状）

```typescript
interface IChipsBridge {
  request<TOutput>(capabilityId: string, input?: unknown): Promise<TOutput>;
  subscribe(eventId: string, handler: (payload: unknown) => void): ISubscription;
  resource(uri: string): IResourceHandle;
}

interface ISubscription {
  dispose(): void;
}
```

| 方法 | 参数 | 返回 | 失败 | 说明 |
|---|---|---|---|---|
| `request` | `capabilityId`：能力 ID；`input`：能力输入（可选） | `Promise<TOutput>`：能力输出 | reject `ChipsError` | 唯一能力调用入口；输入先经 schema 校验，输出不做运行时校验 |
| `subscribe` | `eventId`：事件 ID；`handler`：投递回调 | `ISubscription` | 回执失败记录审计；订阅不建立 | handler 以 `unknown` 载荷调用；同一 `(eventId, handler)` 多次订阅各自独立 |
| `resource` | `uri`：`chips-resource://` URI | `IResourceHandle` | 预检失败同步抛出 `ChipsError` | 同步创建代理句柄；句柄形状见 3.3 节 |

约束：

- `IChipsBridge` **不含 `context()`**；插件上下文由 Cordis 注入的 `ctx` 提供（[ADR-004](../ADR/ADR-004-能力导向Bridge设计.md)）。
- `window.chips` 暴露的方法面与 `IChipsBridge` 完全一致；不得额外暴露 `ipcRenderer`、`process`、`require` 等原始对象。
- `subscribe` 必须返回可退订句柄，句柄 `dispose()` 必须幂等。
- 插件发布事件不是 Bridge 方法：渲染侧发布经能力 `event:publish`（[09-事件系统设计](./09-事件系统设计.md)）。
- 方法面冻结：新增/删除方法必须走 RFC 与评审，不得在实现中私自扩展。

### 3.2 `ICapability`（Host 侧注册形状）

```typescript
type JSONSchema = Readonly<Record<string, unknown>>;

interface ICapabilityContext {
  /** 取消信号；会话销毁、超时、能力注销或 Bridge 关闭时触发。 */
  readonly signal: AbortSignal;
  /** 调用截止时间（Unix epoch 毫秒）；无截止时为 undefined。 */
  readonly deadline?: number;
  /** 触发调用的会话标识；仅用于诊断与审计。 */
  readonly sessionId: string;
  /** 调用方标识：插件 ID 或 'platform'；仅用于诊断与审计，不参与授权。 */
  readonly callerId: string;
}

interface ICapability<TInput = unknown, TOutput = unknown> {
  id: string;
  execute(input: TInput, ctx: ICapabilityContext): Promise<TOutput>;
  schema: JSONSchema;
  permissions: string[];
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | `string` | 是 | 能力 ID，`<domain>:<action>[:<target>]`，全局唯一（第五节） |
| `execute` | `(input: TInput, ctx: ICapabilityContext) => Promise<TOutput>` | 是 | 能力实现；收到的 `input` 已通过 schema 校验，`ctx` 由 Bridge 适配层组装并如实传递 |
| `schema` | `JSONSchema` | 是 | **输入**的 JSON Schema；允许关键字集合见[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md) |
| `permissions` | `string[]` | 是 | 执行该能力所需的权限 ID 并集；空数组表示无额外权限要求（仍受会话有效性约束） |

约束：

- `TInput` / `TOutput` 仅存在于编译期；跨 Bridge 传输的值必须是结构化克隆兼容的 JSON 值（第七节）。
- `execute` 必须响应 `ctx.signal` 的取消与 `ctx.deadline` 的截止；不得忽略取消后继续占用资源（见 8.2）。
- `execute` 不得假设调用方已做业务级校验；Host 内部仍需做资源级二次约束（如路径穿越防护，见[04-资源管理设计](./04-资源管理设计.md)）。
- 能力 ID 与权限 ID 不得相同（R3）；能力只能声明权限词表内的权限 ID。
- 能力 ID 不携带版本号：内置能力的契约随平台版本演进，第三方能力的契约版本与其提供方插件版本一致，消费方以 manifest `dependencies` 版本范围约束；Bridge 不做能力级版本协商，同一 ID 同时只有一个生效注册（[04-能力契约规范](../../05-接口与契约/04-能力契约规范.md)第九节）。

### 3.3 `IResourceHandle` 与 `ISubscription`

```typescript
type ResourceScope = 'document' | 'plugin' | 'platform' | 'external';
type ResourceState = 'open' | 'invalidated' | 'released';
type ResourceInvalidateReason = 'source-changed' | 'session-closed' | 'scope-revoked';

interface IResourceMetadata {
  uri: string;
  size: number;
  mimeType: string;
  version: string;
  scope: ResourceScope;
}

interface IResourceHandle {
  readonly uri: string;
  readonly state: ResourceState;
  metadata(): Promise<IResourceMetadata>;
  read(): Promise<Uint8Array>;
  readRange(offset: number, length: number): Promise<Uint8Array>;
  stream(): ReadableStream<Uint8Array>;
  release(): void;
  onInvalidate(handler: (reason: ResourceInvalidateReason) => void): ISubscription;
}
```

| 成员 | 说明 |
|---|---|
| `uri` | 创建句柄时的原始 URI |
| `state` | 句柄状态：`open` / `invalidated` / `released` |
| `metadata()` | 读取元数据；首次调用触发主进程 `open` |
| `read()` | 读取完整字节；超过 8 MiB 返回 `RESOURCE_TOO_LARGE`，改用 `readRange()` 或 `stream()` |
| `readRange()` | 按偏移读取；与 `stream()` 互斥，流打开期间返回 `RESOURCE_BUSY` |
| `stream()` | 流式读取大资源 |
| `release()` | 释放句柄；幂等；`released` 后除 `uri`、`state`、`release()` 外的方法返回 `RESOURCE_HANDLE_RELEASED` |
| `onInvalidate()` | 订阅失效通知；失效原因见 `ResourceInvalidateReason` |

管理者侧语义、状态机与缓存策略见[04-资源管理设计](./04-资源管理设计.md)第 4 节；协议与完整错误码见[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md)。

### 3.4 `window.chips` 与 `@chips/sdk` 分工

- preload 通过 `contextBridge.exposeInMainWorld('chips', …)` 暴露 `IChipsBridge` 三个方法；这是插件访问平台的唯一运行时入口。
- `@chips/sdk` 提供 `IChipsBridge`、`ICapability`、`ChipsError`、`IResourceHandle` 等类型与 `Window.chips` 全局声明，不承载 Bridge 运行时实现。
- 插件代码从 `@chips/sdk` 导入类型与错误类，运行时使用 `window.chips`；禁止任何包直接引用 preload 内部模块。

### 3.5 类型化调用示例

```typescript
import type { IChipsBridge } from '@chips/sdk';
import { isChipsError } from '@chips/sdk';

declare global {
  interface Window {
    chips: IChipsBridge;
  }
}

interface IFileListOutput {
  entries: string[];
}

async function listCardResources(directory: string): Promise<string[]> {
  const output = await window.chips.request<IFileListOutput>('file:list', { directory });
  return output.entries;
}

async function listCardResourcesSafely(directory: string): Promise<string[]> {
  try {
    return await listCardResources(directory);
  } catch (error) {
    if (isChipsError(error) && error.code === 'BRIDGE_PERMISSION_DENIED') {
      throw new Error(`缺少目录读取权限：${directory}`);
    }
    throw error;
  }
}
```

### 3.6 调用信封与二进制载体

Bridge 调用信封固定为 `{ json, bin }` 两段，由 Bridge 层在能力调用链路上拆分与合并：

| 段 | 类型 | 内容 |
|---|---|---|
| `json` | JSON 值 | 调用输入；schema 中标记 `x-chips-binary` 的字段，其值替换为 `bin` 表键 |
| `bin` | 二进制表 | 键 → 字节；键为二进制字段的稳定路径（默认取字段的 JSON Pointer，如 `/data`） |

规则：

1. **拆分与合并**：Bridge 层按能力 schema 拆分输入；Rust 侧以 `CapabilityInput { json, bin: BTreeMap<String, Vec<u8>> }` 承载。Host 侧 TS 适配层在执行 `execute(input, ctx)` 前把 `bin` 按键合并回输入（`Uint8Array`），能力作者不感知信封形态。
2. **schema 校验对象**：校验针对 `json` 段执行（`x-chips-binary` 字段只校验键存在）；字节长度按 schema 声明的上限校验 `bin` 表条目，缺键、多余键或长度超限返回 `BRIDGE_INVALID_INPUT`。
3. **键唯一**：`bin` 表键由 Bridge 层生成，同一输入内键唯一；调用方不得自行指定或复用键。
4. **Neon 边界一次拷贝**：二进制从 JS 进入 Rust 只发生一次拷贝（`Uint8Array` → `Vec<u8>`），不经过 base64 编解码，也不产生第二份副本。
5. **传输优先级**：资源字节仍优先经 `chips-resource://` 与资源句柄传递；信封 `bin` 段只承载能力输入自身必需的二进制（见 7.3）。
