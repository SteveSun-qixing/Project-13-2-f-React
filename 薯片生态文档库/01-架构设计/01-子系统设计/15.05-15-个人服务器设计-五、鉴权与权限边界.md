## 五、鉴权与权限边界

### 5.1 读写边界

| 面向 | 接口 | 凭证 |
|---|---|---|
| 公开读 | 作品列表、详情、状态、查看/封面入口与私有代理、箱子查看/封面/下载、健康检查 | 无 |
| 管理读 | 全部作品列表（含私密与未渲染） | 管理令牌 |
| 写 | 卡片/箱子可见性修改、删除 | 管理令牌 |
| 传输控制面 | 上传会话创建、预签名、`complete`、`abort`、下载会话与下载计划 | 管理令牌 |

规则：读操作永不要求令牌；写操作无一例外要求令牌；不存在"部分写接口公开"的例外。

### 5.2 管理令牌

1. 凭证形式：`Authorization: Bearer <API_TOKEN>`；令牌由部署环境变量 `API_TOKEN` 提供，长度至少 16 字符。
2. 校验使用常量时间比较（`crypto.timingSafeEqual`，先比较长度）防止时序侧信道；校验失败统一返回 `API_TOKEN_INVALID`（401），不区分"缺失/格式错误/错误令牌"。
3. 令牌即服务器身份：没有账号、JWT、Redis 吊销列表与会话 cookie；令牌泄露等价于服务器完整写权限（可上传、可删除、可改可见性）。
4. 轮换方式：更新部署环境变量并重启服务，同步更新客户端配置；不存在旧令牌宽限期与双令牌并行（无兼容性设计）。
5. 令牌不得进入数据库、日志、错误详情与前端产物；`ENABLE_SWAGGER` 的生产取值建议为关闭（§5.5、§9.5）。

### 5.3 传输控制面与下载

1. 全部 `card-transfer` 控制面接口（上传与下载）要求令牌；下载会话与下载计划没有匿名路径。
2. 私密作品在公开面按不存在处理，因此访客无法通过公开接口枚举私密内容；管理接口与令牌是唯一入口。
3. 对象直传使用预签名 PUT；预签名地址即短期能力，服务器不代理上传字节；预签名地址的保密要求以《卡片传输协议》§6.4、§9.2 为准。

### 5.4 CORS 与浏览器来源

| 环境 | 允许来源 |
|---|---|
| 开发（`NODE_ENV=development`） | 任意 `localhost` 来源（联调便利） |
| 生产 | `BASE_URL` 同源；薯片 Host 渲染来源（`chips-render:` 前缀）；`file://` 页面来源（`null`）；`CORS_EXTRA_ORIGINS` 显式白名单 |

规则：

1. 浏览器凭据请求（`credentials: true`）只在上述来源内放行；不允许"全站放行 + 凭据"。
2. 响应头由 Helmet 与 Nginx 双层控制；跨源资源引用策略为 `cross-origin`（卡片封面与产物被 Host 窗口跨源引用）。
3. CSP 由 Nginx 层控制（服务器关闭 Helmet 的 CSP），域名与证书部署以[《服务端部署与运维》](../../06-开发与运维/08-服务端部署与运维.md) §三为准。

### 5.5 与平台权限体系的关系

1. 个人服务器不注册平台能力与权限：其读写控制是服务器自身的 HTTP 鉴权，不受 Bridge 权限判定与审计管辖（[《权限系统设计》](./08-权限系统设计.md)）。
2. 客户端访问网络受平台权限约束（网络能力 + 域名限定值）；服务器令牌是第二重边界：即使客户端获得网络权限，写操作仍必须持有令牌。
3. 服务器日志记录请求（方法、路径、状态、耗时、来源 IP/UA）；不记录请求体字节与令牌；诊断信息不上传（§9.5）。
