## 四、Schema 与校验

### 4.1 Schema 来源

| 键空间 | Schema 位置 | 注册时机 |
|---|---|---|
| `platform.*` | 核心内置 `config.schema.json`，编译期嵌入 | 核心启动 |
| `plugins.<pluginId>.*` | 插件包内 `assets/schemas/config.schema.json` | 插件安装校验通过后注册；卸载时注销 |

- Schema 方言为 JSON Schema Draft 2020-12。
- 插件 schema 顶层必须为 `type: object` 且声明 `additionalProperties: false`；键名为相对键，字符集与 2.1 一致。
- 插件使用配置能力必须携带 schema；缺失时安装校验拒绝。

### 4.2 Schema 扩展关键字

| 关键字 | 类型 | 语义 |
|---|---|---|
| `x-chips-schema-version` | integer | 插件 schema 顶层声明当前配置 schema 版本，驱动迁移 |
| `x-chips-policy` | boolean | 策略键，仅平台层可提供，默认 `false` |
| `x-chips-writable` | boolean | 是否允许经 `config:write` 写入，默认 `true` |
| `x-chips-scopes` | string[] | 允许写入的层，默认 `["user", "workspace"]` |
| `format` | string | 值为 `chips-credential` 时，要求值必须是 `credential://<pluginId>/<name>` 引用，见第七节 |

平台 schema 示例（节选）：

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "薯片平台配置",
  "type": "object",
  "properties": {
    "platform.update.channel": {
      "type": "string",
      "enum": ["stable", "beta"],
      "default": "stable",
      "x-chips-policy": true,
      "title": "更新通道"
    },
    "platform.window.defaultWidth": {
      "type": "integer",
      "minimum": 640,
      "default": 1200,
      "title": "默认窗口宽度"
    },
    "platform.log.level": {
      "type": "string",
      "enum": ["error", "warn", "info", "debug"],
      "default": "info",
      "title": "日志级别"
    }
  }
}
```

插件 schema 示例（节选）：

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "编辑引擎配置",
  "x-chips-schema-version": 2,
  "type": "object",
  "additionalProperties": false,
  "properties": {
    "fontSize": {
      "type": "integer",
      "minimum": 10,
      "maximum": 32,
      "default": 14,
      "title": "正文字号"
    },
    "autoSave": {
      "type": "boolean",
      "default": true,
      "title": "自动保存"
    },
    "apiKeyRef": {
      "type": "string",
      "format": "chips-credential",
      "title": "接口凭证引用"
    }
  }
}
```

### 4.3 校验时机与失败语义

| 时机 | 校验对象 | 失败处理 |
|---|---|---|
| 插件安装 | 插件 `assets/schemas/config.schema.json` 合法性与默认值 | 拒绝安装，返回 `CONFIG_SCHEMA_INVALID` |
| 平台启动 / 工作区切换 | 各级配置文件结构、`schemaVersion`、逐键类型 | 非法键降级到低层值并写入诊断日志；文件不可解析时进入外部修改保护（见 9.5） |
| `config:set` | 单键值、层可写性、策略锁定、命名空间 | 拒绝写入并返回对应错误码 |
| 迁移完成后 | 迁移结果整体 | 放弃结果、保留原文件，返回 `CONFIG_MIGRATION_FAILED` |

校验规则：

- 类型严格匹配，不做隐式转换；`integer` 与 `number`、字符串与数字互不兼容。
- 写入未注册键返回 `CONFIG_KEY_UNKNOWN`；加载时未注册键保留在文件中但不参与解析，并记录诊断。
- 值必须通过 `enum`、`minimum`、`maximum`、`pattern`、`format` 等全部约束；`format` 按平台注册的格式（如 `chips-credential`）强制校验，而非仅作注解。

### 4.4 错误码

| 错误码 | 含义 |
|---|---|
| `CONFIG_KEY_INVALID` | 键格式非法 |
| `CONFIG_KEY_UNKNOWN` | 键未在 schema 注册 |
| `CONFIG_VALUE_INVALID` | 值不符合 schema |
| `CONFIG_SCOPE_INVALID` | 层标识非法或该层不可写 |
| `CONFIG_POLICY_LOCKED` | 策略键不可被非平台层覆盖 |
| `CONFIG_NAMESPACE_DENIED` | 插件访问他人键空间 |
| `CONFIG_WRITE_FAILED` | 落盘失败 |
| `CONFIG_EXTERNAL_MODIFIED` | 文件被外部修改，写入受保护 |
| `CONFIG_VERSION_UNSUPPORTED` | 文件 `schemaVersion` 高于当前核心 |
| `CONFIG_MIGRATION_MISSING` | 迁移声明或迁移步骤缺失 |
| `CONFIG_MIGRATION_FAILED` | 迁移执行或结果校验失败 |
| `CONFIG_SCHEMA_INVALID` | 插件 schema 非法 |

错误结构遵循统一错误模型（`code` / `message` / `details` / `retryable`），`message` 为简体中文；权限不足由 Bridge 统一返回 `BRIDGE_PERMISSION_DENIED`。
