## 一、定位与边界

### 1.1 定位

文档服务是薯片平台对 `.card` / `.box` 的**统一读写服务**：卡片与箱子共用同一条写链路、同一套会话模型与同一组能力接口，仅在格式适配层（schema 集、模型类型与配置成员）分支——这是统一链路原则（R8）在写侧的对称实现，与只读侧的[《文档解析器设计》](./06-文档解析器设计.md)一一对应。

- 解析器（06）只读：不写入文档、不迁移、不修改；文档服务负责打开、读取、内存修订、持久化、导出与关闭的全部写入语义。
- 能力入口为 `document:open` / `document:read` / `document:write` / `document:save` / `document:export`；契约（输入输出、权限映射、错误归一）以[《能力契约规范》](../../05-接口与契约/04-能力契约规范.md) §7.3 为准。
- 写路径唯一：document 挂载（目录态与归档态）内的所有写入都必须经文档服务的受控提交落地；面向插件的资源写入只允许插件作用域与临时作用域（[《资源管理设计》](./04-资源管理设计.md) §4.8）。
- 文档服务不渲染（[《渲染引擎设计》](./05-渲染引擎设计.md)）、不管理资源字节与缓存（[《资源管理设计》](./04-资源管理设计.md)）、不定义文件格式字段（[01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md)、[02-箱子文件格式](../../04-文件格式规范/02-箱子文件格式.md)）。
- 不做运行时兼容与隐式迁移：旧版本文档由迁移工具升级后使用（[04-版本与迁移规范](../../04-文件格式规范/04-版本与迁移规范.md)）。

### 1.3 术语

| 术语 | 定义 |
|---|---|
| 文档服务（document service） | 本文描述的 `.card` / `.box` 统一读写服务，`document:*` 能力的服务端实现 |
| 文档记录（document record） | 服务按 `source` 维护的一份文档的共享状态：指纹基线、写者绑定、只读会话集合 |
| 文档会话（document session） | 一次 `document:open` 建立的读写上下文，由 `documentId` 标识；持有内存模型、解析句柄与保存点 |
| 内存模型（session model） | 会话中的可变模型，初值来自解析结果，`document:write` 只修订它、不落盘 |
| 写者会话（writer session） | 文档记录中唯一持有写租约的会话；写租约在首次成功 `document:write` 时获得 |
| 工作副本（working copy） | 目录态文档的包根目录本身；归档态文档的所有编辑都先内存修订、保存时重建归档 |
| 保存点（savepoint） | 最近一次成功保存（或打开）时的基线：修订号、源指纹与包内容摘要 |
| 变更集（change set） | 一次 `document:save` 需要写盘的文件与资源变更（新增、替换、删除） |
| 临时物（temporary artifact） | 保存过程中写入的临时文件/目录与备份，命名使用平台保留前缀，绝不作为包成员 |
| 包内容摘要（content digest） | 按包内路径升序对成员清单计算的确定性摘要，口径见 §5.5 |
| 文件摘要（file digest） | 归档态最终归档字节的 SHA-256，`document:save` 与 `document:changed` 的 `digest` 口径 |
