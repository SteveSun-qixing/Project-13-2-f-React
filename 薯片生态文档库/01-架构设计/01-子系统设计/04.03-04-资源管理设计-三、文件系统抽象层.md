## 三、文件系统抽象层

### 3.1 地址模型

```rust
pub struct ResourceAddress {
    pub scope: ScopeId,
    pub path: VirtualPath,
    pub origin: Origin,
}

pub enum Origin {
    Directory(PathBuf),       // 目录根
    Archive(PathBuf),         // ZIP Store 文件
    Platform(&'static str),   // 平台内嵌资源标识
    Http(Url),                // 规范化后的外部地址
}
```

`VirtualPath` 是以 `/` 分隔、无前导斜杠、NFC 规范化的相对路径，是平台内部唯一路径表示；所有 Provider 只接受 `VirtualPath`，不接受原始字符串。

### 3.2 ResourceProvider 契约

```rust
#[async_trait]
pub trait ResourceProvider: Send + Sync {
    fn id(&self) -> &'static str;
    fn supports_streaming(&self) -> bool;
    fn supports_write(&self) -> bool;

    // 读取操作
    async fn stat(&self, address: &ResourceAddress) -> Result<ResourceMetadata, ChipsError>;
    async fn read_range(
        &self,
        address: &ResourceAddress,
        range: ByteRange,
    ) -> Result<Vec<u8>, ChipsError>;
    async fn open_stream(&self, address: &ResourceAddress) -> Result<ResourceStream, ChipsError>;

    // 目录操作
    async fn list_directory(&self, address: &ResourceAddress) -> Result<Vec<DirectoryEntry>, ChipsError>;
    
    // 写入与修改操作
    async fn write(&self, address: &ResourceAddress, data: &[u8]) -> Result<ResourceMetadata, ChipsError>;
    async fn delete(&self, address: &ResourceAddress) -> Result<(), ChipsError>;
    async fn rename(&self, from: &ResourceAddress, to: &ResourceAddress) -> Result<(), ChipsError>;
    async fn copy(&self, from: &ResourceAddress, to: &ResourceAddress) -> Result<(), ChipsError>;
    async fn create_directory(&self, address: &ResourceAddress) -> Result<(), ChipsError>;
    
    // 元数据修改
    async fn set_metadata(&self, address: &ResourceAddress, metadata: FileMetadata) -> Result<(), ChipsError>;
}

pub struct ByteRange {
    pub offset: u64,
    pub length: Option<u64>,   // None 表示读到结尾
}

pub struct ResourceMetadata {
    pub size: u64,
    pub mime_type: String,
    pub version: VersionStamp,
}

pub struct DirectoryEntry {
    pub name: String,
    pub is_directory: bool,
    pub size: u64,
    pub modified: SystemTime,
}

pub struct FileMetadata {
    pub modified: Option<SystemTime>,
    pub created: Option<SystemTime>,
    pub permissions: Option<u32>,
}
```

`open_stream` 返回的 `ResourceStream` 权威形状如下（上表签名中的返回类型 `ResourceStream` 指其 trait 对象 `Box<dyn ResourceStream>`；本节为全库唯一定义面，其余文档引用一律指向本节、不重复定义）：

```rust
#[async_trait]
pub trait ResourceStream: Send {
    /// 拉取下一块，至多 `max_bytes`；`None` 表示结尾。
    async fn next_chunk(&mut self, max_bytes: usize) -> Result<Option<Vec<u8>>, ChipsError>;
}
```

细则：

- `None` 为唯一流结束信号；返回 `Some(bytes)` 时必为非空块，单块字节数 ∈ (0, min(`max_bytes`, 256 KiB)]。256 KiB 为平台在册块上限（§七「大文件与流式读取」），管理器侧将 `max_bytes` 钳制到配置的 `chunkBytes`。
- 流游标自 offset 0 起严格累计，块与块之间连续、无空洞、不重叠；形状不携带显式 `offset` 字段，调用方当前偏移等于此前所有已返回块长度之和。
- 句柄被流占用期间，对同一句柄调用其余读方法返回 `RESOURCE_BUSY`（§5.5 错误码表）。
- 调用方不拉取则 Rust 侧不推进读取——拉取式即天然背压（§七）。

### 3.3 内置 Provider

| Provider | 来源 | 关键实现 | 写入 | 目录列举 |
|---|---|---|---|---|
| DirectoryProvider | 目录态 `.card` / `.box`、工作区目录、插件目录、用户授权的任意文件系统路径（经 `dialog:*` 临时作用域） | 复用解析器目录语义（不跟随符号链接、忽略系统生成物）；文件 `seek` 范围读；支持 `write`/`delete`/`rename`/`copy`/`create_directory`/`list_directory` | 支持（document 挂载写入只对文档服务开放，见 4.8） | 支持 |
| ArchiveProvider | ZIP Store（`.card` / `.box` / `.cpk`） | 复用文档解析器归档层（中央目录 + mmap）；Store 成员映射切片，Deflate 成员解码流 | 不支持（`commit_write` 返回 `RESOURCE_READ_ONLY`，由文档保存流程整体重建并纳入 WriteCoordinator 路径锁） | 支持（列举归档条目） |
| PlatformProvider | 平台安装目录与编译期内嵌资源 | 只读；不可列举目录 | 不支持 | 不支持 |
| HttpProvider | `http(s)://` 与 `webdav://` 外部资源 | 代理请求、Range 续传、磁盘缓存、审计 | 不支持 | 不支持 |
| MemoryProvider | 运行时内存字节（`data:` 等仅运行时形态） | 只读或会话内可写，禁止持久化；不进入磁盘缓存 | 会话内支持 | 不支持 |

`supports_write` / `supports_streaming` 由各 Provider 声明，管理器据此在 `write` / `delete` / `rename` / `copy` / `create_directory` 调用前做能力预检，不支持的操作直接返回 `RESOURCE_READ_ONLY` 或 `RESOURCE_NOT_SUPPORTED`，不透传到 Provider 内部再失败。

归档条目必须是普通文件，拒绝符号链接、硬链接、设备等非常规类型；条目名在查找前执行与目录相同的 PathGuard 校验。

列举条目级跳过口径（工单044 裁定⑤/⑨，补充上表「目录列举」列的返回面约束、不改各 Provider 能力声明语义）：DirectoryProvider 目录态 `list_directory` 扫描时，符号链接条目（含指向根内）与文件名非合法 UTF-8 的条目一律条目级跳过不返回——列举面不跟随、不做 lossy 转写，规避根外存在性侧信道并保证返回条目可二次寻址往返一致；寻址面遇符号链接仍按[06-资源协议规范](../../05-接口与契约/06-资源协议规范.md) §2.4「符号链接」行拒绝，两层不混用。

文档作用域与 `.cpk` 作用域的目录/归档读取复用[06-文档解析器设计](./06-文档解析器设计.md)的 `DocumentSource`（`DirectorySource` / `ArchiveSource`）及其包内索引：Store 成员直接返回映射切片，Deflate 成员返回解码流；资源管理器不重复实现 ZIP 解析，也不另行扫描目录，从而保证资源字节与解析模型同源、同版本戳。

### 3.4 MIME 判定

1. 按扩展名映射（内置静态表）。
2. 外部资源响应头 `Content-Type` 优先于扩展名；按模块/样式/字体消费时必须与允许类型集匹配，否则拒绝（防止内容类型混淆）。
3. 无法判定时回退 `application/octet-stream`。
