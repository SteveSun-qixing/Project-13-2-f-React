## 二、统一渲染链路

### 2.1 唯一链路原则（R8）

卡片与箱子的**解析、资源访问、渲染、打开、导出共用同一条链路与同一套接口**；仅解析阶段按文件格式（`.card` / `.box`）分支。禁止为卡片与箱子各写一套并行管线，禁止应用插件绕过渲染引擎自行解析、拼装或展示文档内容。

链路的分支点是唯一的：`DocumentKind = 'card' | 'box'`。分支之后立即归一为 `DocumentView`（第 2.5 节），后续所有阶段不再感知文件格式差异。

### 2.2 六阶段总览

```
             ┌────────────────────────────────────────────────────────────┐
             │                        渲染进程                             │
             │                                                            │
   open() ────▶ 请求阶段 ──▶ [Bridge 能力调用]                              │
             │              │                                             │
             │              ▼                                             │
             │      主进程   解析（Rust 核心）──▶ DocumentView               │
             │              │                                             │
             │              ▼                                             │
             │          资源准备 ──▶ ResourceScope（resourceBase）         │
             │              │                                             │
             │              ▼                                             │
             │          插件渲染 ──▶ 顶层帧 + 嵌套帧（sandbox iframe）      │
             │              │                                             │
             │              ▼                                             │
             │          组装 ──▶ 帧树 + 位姿 + 错误边界                     │
             │              │                                             │
             │              ▼                                             │
             │          交付 ──▶ 挂载到目标容器，返回渲染会话                │
             └────────────────────────────────────────────────────────────┘
```

| 阶段 | 输入 | 职责 | 输出 | 执行位置 | 权威归属 |
|---|---|---|---|---|---|
| 请求 | `RenderRequest` | 校验参数、创建会话、登记取消信号 | `IRenderSession`（`opening`） | 渲染进程 | 本文件 |
| 解析 | `source` URI | 读取、解压/目录遍历、YAML 解析、schema 校验、构建模型；文档视图构建器（第 2.6 节）把解析句柄与会话模型投影为可结构化克隆的 `DocumentView` | `DocumentView` | 主进程（Rust） | [06-文档解析器设计](./06-文档解析器设计.md)、本文件 §2.6 |
| 资源准备 | `DocumentView` + 包路径 | 注册资源作用域、解析引用映射、获取资源句柄 | `ResourceScope`（渲染侧为 `resourceBase`）+ 映射表 | 主进程 | [04-资源管理设计](./04-资源管理设计.md) |
| 插件渲染 | 视图 + 插件选择结果 | 装载插件、创建帧、注入初始化、执行 `renderView` / `renderLayout` | 帧树 | 渲染进程 | 本文件 |
| 组装 | 帧树 + 测量结果 | 设置位姿、批量提交高度、装配错误边界 | 已定型的帧树 | 渲染进程 | 本文件 |
| 交付 | 已定型帧树 | 挂载目标容器、触发 `ready`、返回会话句柄 | 可见界面 + `IRenderSession` | 渲染进程 | 本文件 |

   │                 │◀───────────────────────│                        │
   │                 │ 创建顶层帧（sandbox）    │                        │

   │                 │                        │        frame:ready     │
   │                 │◀───────────────────────────────────────────────│

解析与资源准备阶段必须并行发起、按依赖合并：资源作用域注册不等待全部资源就绪，只建立映射；真正的字节读取在帧请求资源时按需发生（第 5 节）。

### 2.4 渲染会话模型

```typescript
type DocumentKind = 'card' | 'box';
type RenderMode = 'view' | 'edit';
type RenderSessionState = 'opening' | 'ready' | 'error' | 'disposed';

interface RenderRequest {
  kind: DocumentKind;
  source: string;                 // 引用形式见 04-文件格式规范
  mode: RenderMode;
  options?: RenderOptions;
}

interface RenderOptions {
  maxHeight?: number;             // px；缺省取目标容器可用高度
  estimateEntryHeight?: number;   // px；虚拟化估算高度
  signal?: AbortSignal;
}

interface IRenderEngine {
  open(request: RenderRequest): Promise<IRenderSession>;
}

interface RenderEventMap {
  ready: { sessionId: string };
  error: ChipsError;
  'height-changed': { height: number };
  disposed: { sessionId: string };
}

interface IRenderSession {
  readonly id: string;
  readonly kind: DocumentKind;
  readonly mode: RenderMode;
  readonly state: RenderSessionState;
  mount(container: HTMLElement): Promise<void>;
  unmount(): void;
  update(view: DocumentView, revision: number): Promise<void>;
  subscribe<TEvent extends keyof RenderEventMap>(
    event: TEvent,
    handler: (payload: RenderEventMap[TEvent]) => void,
  ): ISubscription;
  dispose(): Promise<void>;
}
```

会话规则：

1. `open()` 在接受请求后立即返回会话；`state = 'opening'`，界面显示骨架。解析失败、插件缺失、帧握手超时都通过 `error` 事件与降级内容表达，不阻塞调用方。
2. 同一会话绑定一个目标容器；`mount()` 可重复调用（先 `unmount()` 再挂载），`dispose()` 后一切操作返回 `RENDER_SESSION_DISPOSED`。
3. 一个窗口允许存在多个会话；会话之间不共享帧、不共享可变状态。解析缓存与资源缓存可共享（第 10.4 节）。
4. `dispose()` 按固定顺序反向清理：帧销毁 → 端口关闭 → 资源句柄释放 → 解析缓存引用释放 → 挂载点清理。dispose 必须幂等。
5. `update(view, revision)` 只在会话处于 `ready` 时生效；`revision` 必须严格递增，回退或重复的 revision 被忽略并记录诊断；更新失败返回 `RENDER_UPDATE_FAILED`，保留旧帧，不产生半更新状态。
6. 编辑态的视图回流时序固定为：`getChange()` → 编辑链路校验 → `document:write`（返回 `{ revision }`）→ `update(view, revision)` → `markCommitted(revision)`（第 8.3 节、[11-文档服务设计](./11-文档服务设计.md) §6.1、[12-编辑引擎设计](./12-编辑引擎设计.md)）；渲染引擎不接收裸提交，也不存在经帧消息的内容回流路径。

### 2.5 渲染视图模型（DocumentView）

`DocumentView` 是解析结果的**只读渲染视图**，字段对应 04-文件格式规范中的持久化字段；本节只列出渲染链路直接消费的字段，完整字段语义与校验规则以 [01-卡片文件格式](../../04-文件格式规范/01-卡片文件格式.md) 与 [02-箱子文件格式](../../04-文件格式规范/02-箱子文件格式.md) 为准。

```typescript
type DocumentView = CardRenderView | BoxRenderView;

interface CardRenderView {
  kind: 'card';
  revision: number;                        // 渲染会话修订号，单调递增
  card_id: string;                         // .card/metadata.yaml → card_id
  name: string;                            // metadata.yaml → name
  chip_standards_version: string;          // metadata.yaml → chip_standards_version
  cover_ratio: string;                     // metadata.yaml → cover_ratio，缺省 '3:4'
  tags: TagView[];                         // metadata.yaml → tags
  cover: CoverView;                        // .card/cover.html
  content_nodes: CardNodeView[];           // 按 structure.yaml 声明顺序
}

interface CardNodeView {
  node_id: string;                         // structure.yaml 节点 id，对应 content/{id}.yaml
  card_type: string;                       // 内容配置 → card_type，决定基础卡片插件
  content: Record<string, unknown>;        // 内容配置的类型专有字段，不透明值原样保留
}

interface BaseCardView {
  kind: 'basecard';                        // 一个基础卡片节点实例的渲染视图
  node_id: string;
  card_type: string;
  content: Record<string, unknown>;
  revision: number;                        // 与会话修订号同序列
  card: BaseCardContext;                   // 卡片级上下文
}

interface BaseCardContext {
  card_id: string;
  name: string;
  chip_standards_version: string;
  cover_ratio: string;
  tags: TagView[];
}

interface CoverView {
  entry: string;                           // 正式封面入口：卡片固定 '.card/cover.html'，箱子固定 '.box/cover.html'
  ratio: string;                           // metadata.yaml → cover_ratio，缺省 '3:4'
}

interface BoxRenderView {
  kind: 'box';
  revision: number;                        // 渲染会话修订号，单调递增
  box_id: string;                          // .box/metadata.yaml → box_id
  name: string;                            // metadata.yaml → name
  chip_standards_version: string;          // metadata.yaml → chip_standards_version
  active_layout_type: string;              // metadata.yaml 与 content.yaml 一致的生效布局
  layout_config: Record<string, unknown>;  // content.yaml → layout_configs[active_layout_type].props
  cover: CoverView;                        // .box/cover.html
  entries: EntryView[];                    // structure.yaml → entries，按声明顺序
}

interface EntryView {
  entry_id: string;                        // structure.yaml → entry_id
  url: string;                             // structure.yaml → url；唯一正式定位字段（R13）
  enabled: boolean;                        // structure.yaml → enabled
  snapshot?: Record<string, unknown>;      // 摘要快照：document_id / title / summary / tags / cover / last_known_modified_at / content_type
  layout_hints?: Record<string, unknown>;  // 布局索引：sort_key / aspect_ratio / group / priority
}

type TagView = string | string[];          // 简单标签或结构化标签，与 metadata.yaml 口径一致
```

约束：

- 类型命名以本节为准：渲染会话视图统一为 `DocumentView = CardRenderView | BoxRenderView`；`CardView` / `BoxView` 名称作废（避免与 `@chips/ui` 组件名冲突）；节点视图统一为 `BaseCardView`，箱子布局视图统一为 `BoxRenderView`。
- `BaseCardView` 由帧运行时按节点构建：帧运行时从帧初始化载荷的 `nodes[]` 逐节点取出 `node_id` / `card_type` / `containerId`，用 `CardRenderView` 的卡片级上下文字段组装 `card`，再以当前会话 `revision` 组装完整节点视图后调用 `renderView(basecard, container)`（第 6.2 节）；编辑链路的就近渲染使用同一构建口径（第 8 节）。
- 视图是只读的：渲染层与插件都不得修改；仅编辑态由编辑链路在 `document:write` 成功后产出**新版本**视图交给 `update(view, revision)`。
- 视图必须可结构化克隆：不得包含函数、类实例、`Symbol`、循环引用。
- 视图不携带文件字节；资源一律通过 `resourceBase` 与映射表按需读取。
- 视图中的资源引用保持文件原样（包内相对路径或 R13 允许的 URI）；运行时映射在资源准备阶段生成，不得回填视图。

### 2.6 文档视图构建器

`DocumentView` 由渲染引擎解析阶段的**文档视图构建器**（`buildDocumentView(handle, session)`，正式类型与导出登记见[03-核心接口规范](../../05-接口与契约/03-核心接口规范.md) §6.6、§8.6）产出，运行在主进程（Rust 核心）：

- 输入：解析句柄（[06-文档解析器设计](./06-文档解析器设计.md) §5.2 `DocumentHandle`）+ 会话（`SessionId`，取[11-文档服务设计](./11-文档服务设计.md) §3.2 的会话模型 `SessionModel`；查看态为解析结果的模型初值）。
- 输出：可结构化克隆的 `DocumentView`，供帧初始化、`host:update`、条目 ticket 与编辑链路就近渲染共同使用。
- 构建规则：只做字段投影与不透明值保留（`DocumentValue` → 普通对象/数组/标量），不解释插件专有语义、不读取资源字节、不拼接资源 URI；引用归一（包内相对路径、`file://` → 受管作用域 URI）由[06-文档解析器设计](./06-文档解析器设计.md)负责，在进入渲染前完成。
- 构建器无自有缓存：查看态初值来自解析结果；编辑态每次回流由编辑链路在 `document:write` 成功后触发重新构建，`revision` 由文档服务推进（[11-文档服务设计](./11-文档服务设计.md) §3.4）。
- 确定性：同一解析句柄与同一会话模型在同一 `revision` 下产生相同视图。
- 类型登记：`DocumentView` / `CardRenderView` / `BoxRenderView` / `BaseCardView` / `BoxCoverView` 的正式类型定义登记在[03-核心接口规范](../../05-接口与契约/03-核心接口规范.md)与[02-SDK-API规范](../../05-接口与契约/02-SDK-API规范.md)；本节只列出渲染链路直接消费的字段。
