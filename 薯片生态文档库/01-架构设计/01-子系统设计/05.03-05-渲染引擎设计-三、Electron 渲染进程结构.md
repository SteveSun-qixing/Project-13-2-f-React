## 三、Electron 渲染进程结构

### 3.1 进程与责任

```
┌──────────────────────────────────────────────────────────────────┐
│ 主进程                                                            │
│  Cordis 运行时（Rust/Neon） · Bridge 能力实现 · 插件加载器          │
│  文档解析器 · 资源管理器 · 权限判定 · 窗口管理                      │
└───────────────────────────────┬──────────────────────────────────┘
                                │ contextBridge + IPC
┌───────────────────────────────▼──────────────────────────────────┐
│ 渲染进程                                                          │
│  React 壳（应用插件 UI）                                           │
│  RenderHost（会话、帧树、协议、测量、缓存、调度）                    │
│  ┌──────────────┐  ┌──────────────┐  ┌────────────────────────┐  │
│  │ 顶层卡片帧    │  │ 顶层布局帧    │  │ 就近渲染容器（无帧）    │  │
│  │ frame runtime│  │ frame runtime│  │ 插件编辑器/视图         │  │
│  └──────┬───────┘  └──────┬───────┘  └────────────────────────┘  │
│         │                 │ entries                               │
│         │          ┌──────▼───────┐                               │
│         │          │ 条目帧 xN   │                               │
│         │          └──────────────┘                               │
└──────────────────────────────────────────────────────────────────┘
```

- 渲染、测量、帧管理全部在渲染进程（Chromium）内完成；解析与资源 IO 全部在主进程完成，二者只经 Bridge 通信。
- `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`，生产环境禁止关闭 `webSecurity`（R17）。渲染进程代码不得直接使用 Node.js API。
- 渲染帧内禁止任何形式的 `window.chips` 直连；帧内访问平台一律经第 9 节协议转发给 RenderHost，由 RenderHost 使用 `window.chips` 完成能力调用与权限判定。

### 3.2 React 壳分层

| 层 | 职责 | 禁止 |
|---|---|---|
| Shell | 窗口布局、路由、生命周期、应用级错误边界 | 直接操作帧 DOM |
| Surface | 每次渲染会话的挂载点，`useRenderSession` 生命周期管理 | 解析文件、拼装内容 |
| RenderHost | 会话注册表、帧树、协议、测量、缓存、调度 | 承载业务 UI |
| Frame | 第三方渲染内容，运行帧运行时与插件渲染代码 | 访问平台、跨帧访问父文档 |
| EditorHost | 编辑链路的就近渲染容器：经 `IEditSession` 与 `IPluginRuntime` 门面装载并挂载插件编辑器 | 自行加载插件模块、二次解析、绕过插件接口 |

组件树：

```
<AppRoot>                       // 应用插件入口；@chips/ui ConfigProvider、Design Tokens
  <AppShell>                    // 窗口布局、命令、菜单
    <RenderSurface>             // 一个会话一个 Surface
      <div ref={mountPoint}>    // iframe 由 RenderHost 插入
    </RenderSurface>
    <EditorHost>                // 编辑态就近渲染（可选；由编辑链路的 IEditSession 持有）
      <PluginEditorMount />     // 经 IPluginRuntime 门面装载的插件编辑器输出
    </EditorHost>
  </AppShell>
</AppRoot>
```

`useRenderSession` 是壳与 RenderHost 之间的唯一桥接 Hook：负责创建会话、挂载/卸载、订阅事件、在组件卸载时 `dispose()`。React 代码只从 `@chips/ui` 导入组件与 Hooks（R4）。

```tsx
import { useEffect, useRef } from 'react';
import { Empty, Spin } from '@chips/ui';
import { useRenderSession } from './render/useRenderSession';

interface CardWindowBodyProps {
  source: string;
}

export function CardWindowBody({ source }: CardWindowBodyProps) {
  const surfaceRef = useRef<HTMLDivElement>(null);
  const { session, state, error } = useRenderSession({ kind: 'card', source, mode: 'view' });

  useEffect(() => {
    const surface = surfaceRef.current;
    if (!surface || !session) {
      return;
    }
    void session.mount(surface);
    return () => {
      session.unmount();
    };
  }, [session]);

  if (state === 'error' && error) {
    return <Empty description={error.message} />;
  }

  return (
    <div ref={surfaceRef}>
      {state === 'opening' ? <Spin /> : null}
    </div>
  );
}
```

### 3.3 渲染层模块结构

| 模块 | 职责 |
|---|---|
| `session/` | `IRenderEngine` 与 `IRenderSession` 实现、会话注册表、dispose 顺序 |
| `pipeline/` | 六阶段编排、阶段错误归一、取消传播 |
| `frames/` | 帧创建、帧池、位姿、嵌套帧登记、握手与超时 |
| `protocol/` | 帧消息类型、封套编解码、版本协商、端口管理 |
| `resources/` | `resourceBase` 注入、引用映射、句柄租约 |
| `measure/` | 高度测量、批量提交、高度缓存 |
| `schedule/` | 帧创建队列、rAF/空闲期调度、增量更新队列 |
| `errors/` | 渲染错误码、降级占位渲染 |

目录与包名遵循《02-开发规范/01-代码组织规范》；React 组件写法遵循《02-开发规范/03-React组件开发规范》。

### 3.4 窗口与多会话

- 窗口由应用插件创建与管理（`IAppPlugin`），渲染引擎不创建窗口、不管理窗口生命周期。
- 应用插件把 `IRenderSession` 挂载到窗口内任意容器；同一窗口内多个会话互不干扰。
- 窗口销毁时先 `dispose()` 全部会话；未显式 dispose 的会话由窗口 `unload` 兜底回收。
- 会话与窗口的绑定关系由应用插件维护；RenderHost 只保证会话级隔离。

### 3.5 插件代码装载与帧运行时

1. 平台帧运行时（HTML、JS、样式）由平台构建产物提供，经 `chips-resource://platform/...` 加载，随平台版本缓存。
2. 插件渲染入口由 SDK 构建产出为单一 ESM 入口（`render.js`），随 `.cpk` 包分发，经 `chips-resource://<plugin-scope>/render.js` 加载；入口约定遵循《03-插件开发/01-快速开始》构建章节。
3. 平台级共享依赖（React、`@chips/ui`）由帧运行时统一提供并被插件构建外部化，避免每个插件重复打包；插件不得在帧内自行加载第二套组件库（R4）。
4. 插件模块按插件版本缓存；`plugin:loaded` / `plugin:unloaded` 事件触发失效（事件契约见[05-事件契约规范](../../05-接口与契约/05-事件契约规范.md)）。
5. 插件装载失败、入口缺失、版本不满足时，帧进入降级占位，错误码与提示见第 11 节。
