## 四、质量标准（Quality Standards）

### 4.1 代码质量标准

**Rust 代码**：

- ✅ 通过 `cargo clippy`（无 warning）
- ✅ 通过 `cargo fmt`
- ✅ 覆盖率：总体 > 80%，Rust 核心（`chips-*` crates）> 90%
- ✅ 所有 `unsafe` 代码必须有注释说明理由
- ✅ 所有公开 API 必须有文档注释

**TypeScript 代码**：

- ✅ 通过 ESLint（无 error）
- ✅ 通过 Prettier
- ✅ 覆盖率：总体 > 80%，共享层（`@chips/ui`、`@chips/bridge`）> 90%
- ✅ 所有导出函数/类必须有 TSDoc 注释
- ✅ 严格模式（`strict: true`）

### 4.2 性能标准

**桌面端性能基线**：

- 冷启动时间：< 1 秒
- 渲染帧率：≥ 60 fps（工单045 修口，2026-09-21——60Hz 参考机均值上限恰为 60.00，算子翻正 ≥，数值与协议零改）
- 内存占用：< 500 MB（空闲状态）
- 打开卡片：< 100 ms
- 打开箱子：< 200 ms

以上五项是全库性能基线数值的唯一来源；Phase 2 放宽值见附录 R18，其他文档只允许引用，不得改写数值或另立口径。

**如果不达标**：

- 必须分析原因
- 必须优化或调整架构
- 不得以"后续优化"为由推迟

### 4.3 文档标准

**架构文档**：

- ADR 记录决策、关键设计与约束
- 所有子系统必须有设计文档
- 所有接口必须有契约规范

**代码文档**：

- 公开 API 文档覆盖率 > 95%
- 复杂逻辑必须有注释
- 关键算法必须有说明

**开发者文档**：

- 快速开始教程
- API 参考手册
- 最佳实践指南
- 常见问题解答
