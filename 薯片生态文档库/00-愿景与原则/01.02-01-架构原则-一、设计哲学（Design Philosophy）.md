## 一、设计哲学（Design Philosophy）

### 1.1 一切皆插件（Everything is a Plugin）

**原则**：薯片平台的核心功能也应该以插件形式实现。

**源自**：Cordis 框架的核心理念

**含义**：
- 编辑器是插件
- 查看器是插件
- 资源管理器是插件
- 甚至文档解析、资源管理也可以是插件

**好处**：
- 可替换性：不喜欢官方编辑器？安装第三方编辑器
- 可扩展性：任何功能都可以通过插件添加
- 可维护性：模块边界清晰，职责单一

**反例**（禁止）：
```typescript
// ❌ 硬编码核心功能
class ChipsPlatform {
  private editor = new BuiltInEditor();  // 禁止
  private viewer = new BuiltInViewer();  // 禁止
}

// ✅ 正确做法：通过插件系统加载
class ChipsPlatform {
  private pluginManager: PluginManager;
  
  async loadEditor() {
    // 从插件市场或本地加载编辑器插件
    const editor = await pluginManager.load('chips.official.editor');
  }
}
```

### 1.2 平台不做业务（Platform Does Not Do Business Logic）

**原则**：薯片平台只提供能力，不实现具体业务逻辑。

**含义**：
- 平台提供"文件读取"能力，但不知道如何"编辑 Markdown"
- 平台提供"渲染引擎"，但不知道如何"渲染文本卡片"
- 平台提供"资源管理"，但不知道"图片处理算法"

**边界**：
- **平台层**：Cordis 运行时、Bridge、资源管理、渲染引擎框架
- **插件层**：编辑器、查看器、卡片类型、布局类型

**好处**：
- 平台保持简洁、稳定
- 业务逻辑可以快速迭代（插件更新不影响平台）
- 第三方可以完全替换官方业务逻辑

---

### 1.3 能力导向，而非功能导向（Capability-Oriented, Not Feature-Oriented）

**原则**：平台提供原子化的能力（Capability），插件组合能力实现功能。

**对比**：

```typescript
// ❌ 功能导向（禁止）
interface ChipsBridge {
  openTextEditor(filePath: string): void;
  saveTextFile(content: string): void;
  exportToPDF(content: string): void;
}

// ✅ 能力导向（正确）：请求即执行，输入随请求携带，直接返回执行结果
interface IChipsBridge {
  request<TOutput>(capabilityId: string, input?: unknown): Promise<TOutput>;
  subscribe(eventId: string, handler: (payload: unknown) => void): ISubscription;
  resource(uri: string): IResourceHandle;
}

// 插件自己组合能力（示例：读取、处理、写回）
const input = await chips.request<CapabilityOutput<'file:read'>>('file:read', { path });
const edited = input.content.replaceAll('旧标题', '新标题');
await chips.request<void>('file:write', { path, data: edited });
```

> 示例中的 `file:read` / `file:write` 均为已登记能力；第三方自定义能力必须先按《能力契约规范》登记（R19），示例不构成对未登记能力的授权。

**好处**：
- 能力可复用：同一个 `file:read` 可以被编辑器、查看器、资源管理器使用
- 可扩展：新增能力不需要修改 Bridge 核心
- 权限清晰：每个能力有明确的权限定义

---

### 1.4 开放胜于封闭（Open Over Closed）

**原则**：文件格式、协议、接口都应该开放、可读、可扩展。

**具体要求**：
- ✅ 文件格式使用 YAML/JSON（人类可读）
- ✅ 所有接口都有公开文档
- ✅ 协议设计考虑第三方兼容性
- ❌ 禁止私有二进制格式
- ❌ 禁止未文档化的接口
- ❌ 禁止只有官方才能使用的 API

**好处**：
- 用户不被锁定：数据随时可导出、迁移
- 第三方工具可以读取薯片文件
- 生态繁荣：开发者可以自由创新

---

### 1.5 本地优先（Local-First）

**原则**：所有核心功能必须在本地完整可用，云端只是可选增强。

**具体要求**：
- ✅ 离线可用：断网情况下核心功能不受影响
- ✅ 数据本地：用户数据存储在用户设备上
- ✅ 隐私保护：平台不上传用户数据（除非用户明确同意）
- ❌ 禁止依赖云端的核心功能
- ❌ 禁止强制在线验证

**例外**：
- 云同步插件（用户主动安装）
- 协作编辑插件（用户主动使用）
- 社区功能（明确需要联网）
