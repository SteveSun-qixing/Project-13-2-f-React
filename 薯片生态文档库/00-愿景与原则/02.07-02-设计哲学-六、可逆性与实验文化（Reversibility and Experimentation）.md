## 六、可逆性与实验文化（Reversibility and Experimentation）

### 6.1 可逆的副作用

**哲学**（源自 Cordis）：系统的任何变更都应该是可逆的。

**传统系统的问题**：
```typescript
// 安装插件
plugin.install();
// 无法完全卸载，留下副作用
```

**Cordis 的解决方案**：
```typescript
// 插件的所有副作用都被记录
const fork = ctx.plugin(myPlugin);

// 可以完全撤销
fork.dispose();  // 所有副作用都被清理
```

**在薯片中的体现**：
- 插件可以完全卸载：不留下任何副作用
- 配置可以重置：恢复到初始状态

**为什么可逆？**
- 实验自由：用户可以自由尝试插件
- 无负担：不喜欢就卸载，不留痕迹
- 可维护性：系统状态清晰

---

### 6.2 鼓励实验

**哲学**：系统应该鼓励用户实验，而不是害怕犯错。

**设计原则**：
1. **低风险尝试**
   - 安装插件不会破坏系统
   - 可以随时卸载
   - 沙箱隔离，不影响其他插件

2. **快速反馈**
   - 插件安装后立即可用
   - 不需要重启
   - 热插拔

3. **清晰的回退路径**
   - 卸载插件很简单
   - 配置可以重置
   - 数据不会丢失

**文化**：
- 鼓励用户尝试新插件
- 鼓励开发者发布实验性插件
- 失败不可怕，可以回退
