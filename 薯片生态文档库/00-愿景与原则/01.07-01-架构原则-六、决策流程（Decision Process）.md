## 六、决策流程（Decision Process）

### 6.1 架构决策流程

重大架构变更必须走 **RFC → 评审 → ADR 记录** 流程：

1. **提出 RFC**：
   - 背景和动机
   - 详细方案
   - 影响范围

2. **技术评审**：
   - 架构一致性检查
   - 性能影响评估
   - 风险评估（评审环节的过程判断，结论写入 RFC 与评审记录，不进入 ADR 正文，见 [07-工程管理/03-变更与决策管理](../07-工程管理/03-变更与决策管理.md)）

3. **ADR 记录**：
   - 编写 ADR 文档
   - 记录决策、关键设计与约束

4. **实施**：
   - 更新相关文档
   - 通过质量门禁
   - Code Review

### 6.2 例外情况处理

如果某个需求与架构原则冲突：

**流程**：
1. 重新审视需求：是否真的需要？
2. 调整需求：能否换一种方式实现？
3. 提出架构调整方案：如果需求合理，调整架构
4. 更新架构原则文档

**禁止**：
- 直接违反原则
- 留下"临时绕过"
- 不记录决策过程
