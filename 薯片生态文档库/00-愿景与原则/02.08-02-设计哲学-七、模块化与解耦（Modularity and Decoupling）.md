## 七、模块化与解耦（Modularity and Decoupling）

### 7.1 极致的模块化

**哲学**：系统应该由高度独立的模块组成，模块之间通过明确的接口通信。

**Unix 哲学**：
> "Write programs that do one thing and do it well.  
> Write programs to work together."

**在薯片中的体现**：
```
薯片平台 = Cordis 运行时 + Bridge 层 + 文档解析 + 资源管理 + ...

每个部分都是独立的模块：
- Cordis 运行时不知道 Bridge 的存在
- Bridge 不知道文档解析的细节
- 文档解析不知道资源管理的实现

通过接口通信：
- Cordis 提供插件加载接口
- Bridge 提供能力注册接口
- 文档解析提供解析接口
```

**好处**：
- 可测试：每个模块独立测试
- 可替换：不喜欢某个模块？换一个
- 可并行开发：不同团队开发不同模块
- 可渐进式重构：一次重构一个模块

### 7.2 解耦的艺术

**哲学**：好的架构是高内聚、低耦合的。

**耦合的层次**（从高到低）：
1. **内容耦合**（最差）：A 直接修改 B 的内部状态
2. **公共耦合**：A 和 B 依赖同一个全局变量
3. **控制耦合**：A 传递控制信息给 B
4. **数据耦合**：A 传递数据给 B
5. **消息耦合**（最好）：A 和 B 通过消息通信

**薯片追求：消息耦合**

```typescript
// ❌ 内容耦合（禁止）
class PluginA {
  doSomething() {
    // 直接修改另一个插件的状态
    PluginB.internalState = newValue;
  }
}

// ❌ 公共耦合（避免）
let globalConfig = {};
class PluginA {
  doSomething() {
    globalConfig.value = 1;
  }
}

// ✅ 消息耦合（推荐）
class PluginA {
  constructor(ctx: Context) {
    // 通过事件通信
    ctx.emit('config:changed', { value: 1 });
  }
}

class PluginB {
  constructor(ctx: Context) {
    ctx.on('config:changed', (data) => {
      // 响应事件
    });
  }
}
```
