## 一、核心哲学：原子化与可组合性

### 1.1 原子化思维（Atomic Thinking）

**哲学**：将复杂系统拆解为最小的、不可再分的原子单元，然后通过组合构建复杂功能。

**来源**：
- 化学中的原子论
- Unix 哲学："Do one thing and do it well"
- 函数式编程的组合思想

**在薯片生态中的体现**：

**卡片是知识的原子**：
- 不再是"一篇文章"或"一个文档"
- 而是最小的、独立的知识单元
- 像原子一样，可以独立存在，也可以组合成分子（箱子）

**能力是功能的原子**：
```typescript
// 不是：openAndEditTextFile(path)
// 而是：
const input = await chips.request<CapabilityOutput<'file:read'>>('file:read', { path });
const edited = input.content.replaceAll('旧标题', '新标题');
await chips.request<void>('file:write', { path, data: edited });
```

**插件是功能的原子**：
- 每个插件只做一件事
- 通过 Cordis 的服务注册机制组合
- 像乐高积木一样可以自由拼接

**为什么原子化？**
1. **灵活性**：原子可以自由组合，适应各种场景
2. **可替换性**：不喜欢某个原子？换一个
3. **可理解性**：原子简单，容易理解和维护
4. **可测试性**：原子独立，容易测试

---

### 1.2 可组合性（Composability）

**哲学**：系统的价值不在于单个组件有多强大，而在于组件之间能多好地组合。

**数学类比**：
- 好的设计像函数：`f ∘ g ∘ h`
- 坏的设计像巨石：一个大函数做所有事

**在薯片生态中的体现**：

**卡片的组合**：
```
文本卡片 + 图片卡片 + 视频卡片
    ↓
通过网格布局组合
    ↓
形成一个多媒体笔记箱子
```

**插件的组合**：
```
图像解码插件 + 图像滤镜插件 + 图像保存插件
    ↓
通过 Cordis 服务依赖
    ↓
形成完整的图像处理流程
```

**能力的组合**（示例：以已登记能力组合出插件自己的功能）：
```typescript
// 组合多个能力实现复杂功能
async function replaceText(path: string, search: string, replacement: string): Promise<void> {
  const input = await chips.request<CapabilityOutput<'file:read'>>('file:read', { path });
  const output = input.content.split(search).join(replacement);
  await chips.request<void>('file:write', { path, data: output });
}
```

**为什么可组合性？**
1. **创新涌现**：组合产生新价值
2. **用户自由**：用户决定如何组合
3. **生态繁荣**：开发者创造新组合
4. **长期演化**：系统可以持续生长
