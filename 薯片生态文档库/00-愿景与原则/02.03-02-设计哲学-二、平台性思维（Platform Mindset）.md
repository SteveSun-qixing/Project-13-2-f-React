## 二、平台性思维（Platform Mindset）

### 2.1 平台 vs 产品

**产品思维**：
- 我们提供什么功能？
- 用户能用我们的产品做什么？
- 如何让产品功能更完善？

**平台思维**：
- 我们提供什么能力？
- 开发者能在我们的平台上构建什么？
- 如何让平台更可扩展？

**薯片生态选择：平台思维**

我们不是在做一个"笔记应用"，而是在做一个"知识工作的操作系统"。

**类比**：
- **iOS** 是平台，**微信** 是产品
- **Windows** 是平台，**Word** 是产品
- **薯片平台** 是平台，**编辑器插件** 是产品

**平台的特征**：
1. **提供基础设施**：文件系统、渲染引擎、插件运行时
2. **定义规范**：文件格式、插件协议、API 规范
3. **建立生态**：插件市场、开发者工具、社区
4. **保持克制**：不与生态竞争、不做具体业务

---

### 2.2 平台的克制（Platform Restraint）

**哲学**：平台不应该与生态竞争，要保持克制。

**反例**（其他平台的问题）：
- **微信**：自己做支付、做电商、做视频号，挤压第三方空间
- **Android**：Google 自己的应用享有特权，第三方应用受限
- **App Store**：苹果自己的应用不受审核，第三方严格审核

**薯片的克制**：
1. **官方插件不享有特权**
   - 官方编辑器和第三方编辑器使用相同的 API
   - 没有"内部 API"
   - 第三方可以完全替代官方插件

2. **核心能力公开透明**
   - 所有 Bridge API 都有公开文档
   - 官方插件用什么 API，第三方也能用

3. **不与生态竞争**
   - 如果第三方做了优秀的编辑器，官方可以推荐
   - 不会因为"官方也想做"就打压第三方

**为什么克制？**
- 信任：开发者信任平台，才会投入
- 创新：第三方有创新空间，生态才繁荣
- 长期价值：生态的价值远超平台本身
