## 附录：规则编号表（R1-R20）

> 本附录从《文档库编写基准》v1.0.0 逐条搬运 R1-R20，编号稳定、不复用；全库文档引用"R 编号"时一律指向本表。
> 与现行架构口径冲突之处已按本轮架构收口裁决更新：R6（平台优先级）、R18（覆盖率口径）、R19（删除 `image:*` 并纳入本轮新增能力，含 `command:*`、`cli:task-*`、`resource:open` / `resource:list-handlers`、`document:create`，共 60 项）；其余条目保持原编号与原语义。

### R1 · 插件角色只有 4 种

`basecard`（基础卡片）、`boxlayout`（箱子布局）、`app`（应用）、`service`（服务）。

- 白皮书中"能力插件、布局插件、模块插件"的 5 类口径**作废**：
  - "能力插件" → 即服务插件（`service`）；
  - "布局插件" → 统一称"箱子布局插件"（`boxlayout`）；
  - "模块插件" → **不存在**（原子化由 Cordis 服务与能力体系承担）。
- 一个插件只有一个角色；需要多角色能力时拆成多个插件，用 `dependencies` 组合（ADR-005）。

### R2 · Bridge 对外契约（唯一权威形状）

```typescript
interface IChipsBridge {
  request<TOutput>(capabilityId: string, input?: unknown): Promise<TOutput>;
  subscribe(eventId: string, handler: (payload: unknown) => void): ISubscription;
  resource(uri: string): IResourceHandle;
}
interface ISubscription { dispose(): void }
```

- **不包含 `context()`**：插件上下文由 Cordis 注入的 `ctx` 提供（ADR-004 中的 `context()` 作废，ADR-007/ADR-002 口径生效）。
- `window.chips` 暴露与 `IChipsBridge` 相同的 3 个方法；`subscribe` 必须返回可退订句柄。

### R3 · 能力 ID 与权限 ID 的命名与关系

- 能力 ID：`<domain>:<action>[:<target>]`，如 `file:read`、`window:create`、`document:write`。
- 权限 ID：`<domain>:<scope>[:<qualifier>]`，如 `filesystem:read`、`network:http:*.example.com`。
- 能力声明自己需要的权限（`capability.permissions: string[]`）；manifest 的 `permissions` 是插件申请集合；Bridge 在调用时按两者交集判定。
- 禁止同一标识既当能力又当权限；文档必须给出"能力 → 权限"的映射示例表。

### R4 · 前端导入唯一面是 `@chips/ui`

- 插件与共享层业务代码**只能**从 `@chips/ui` 导入组件、Hooks 与 Design Tokens。
- `@chips/antd`（fork antd）仅允许 `packages/ui` 内部使用；禁止任何其他包直接 `import from '@chips/antd'`。
- 禁止 `antd`、`@mui/*`、`@chakra-ui/*` 等第二套组件库。
- ESLint `no-restricted-imports` 必须同时拦截 `antd`、`antd/*`、`@chips/antd`（`packages/ui` 例外）、`@mui/*`、`@chakra-ui/*`。
- ADR-006/ADR-008 中 `import { ConfigProvider } from '@chips/antd'` 的示例作废，改为从 `@chips/ui` 导入。

### R5 · 主题系统与多语言系统已废弃

- 不存在主题包、语言包、Theme Runtime、i18n 运行时；文档中不得出现"主题系统/多语言系统"作为平台组成部分或交付物。
- 视觉统一由 `@chips/ui` + Design Tokens + antd 主题定制承担；文案简体中文直写。
- 白皮书与路线图中的"主题系统/多语言系统"表述作废。

### R6 · 平台优先级

- 实现优先级：**macOS / Windows → Linux（桌面三端完成）→ Android → iOS**。
- 五端共享：`.card`/`.box` 文件格式、Rust 核心、Bridge 接口。
- 移动端为 Phase 5（架构预留，见 R7）；不得把未实现平台写成已交付。

### R7 · 阶段路线（唯一权威，替代所有其他版本）

| 阶段 | 目标 | 交付物 |
|---|---|---|
| Phase 0 | 文档与预研 | 全部文档库、Monorepo 骨架、Cordis/Neon/Bridge POC |
| Phase 1 | 核心平台 | Rust Cordis 运行时、Bridge、Electron 壳、React 壳、最小原型 |
| Phase 2 | 子系统 | 插件系统、渲染引擎、资源管理、文档解析、权限/事件/配置系统、覆盖率 > 80% |
| Phase 3 | 官方插件与生态 | 应用插件重写（编辑引擎、查看器、资源管理器）、CLI、示例插件、开发者文档 |
| Phase 4 | 迁移与发布 | 用户数据迁移工具、性能与安全加固、桌面三端（macOS、Windows、Linux）验证、v1.0 发布 |
| Phase 5 | 移动端 | Android / iOS（架构预留，暂不排期） |

- 不写日历年份与具体日期；只写阶段、交付物与 Definition of Done。

### R8 · 卡片与箱子统一链路

- 解析、资源访问、渲染、打开、导出共用同一条链路与同一套接口；接口内部按文件格式（`.card`/`.box`）分支。
- 编辑态允许界面就近渲染，但必须复用同一套插件接口与同一份解析结果。
- 禁止为卡片和箱子各写一套并行管线。

### R9 · 零冗余的边界

- 文档不写：设计原因的长篇论证、商业价值、优劣对比、备选方案、风险分析、人事与时间规划。
- ADR 只记录：状态、决策、关键设计、约束、后果（简短）。不写备选方案章节。
- 《架构原则》第 6 节中 RFC"至少 2 个替代方案"的要求废止；改为"重大变更走 RFC + 评审 + ADR 记录"。

### R10 · 文档库只放正式技术内容

- 进度报告、工作总结、工作汇报等为过程材料，移到 `项目日志与笔记/`。
- 库内不新增进度类、汇报类文档；README 只做索引与导航。

### R11 · 插件包格式

- `.cpk` = ZIP Store：根目录 `manifest.yaml` + 构建产物目录 + 静态资源。
- manifest 为唯一权威清单；包内不得携带原生可执行载荷（Rust 能力属于平台）。
- 服务插件的 Node/JS 依赖必须随包携带或声明为平台提供的能力。

### R12 · 文件格式以原始设计为唯一权威（卡片与箱子）

- 权威来源：`旧版-生态设计原稿/05-卡片文件格式.md`、`06-箱子文件格式.md`；`旧版-生态共用技术文档/文件格式规范/01-卡片文件格式规范.md`（v1.1.0）、`02-箱子文件格式规范.md`。
- `.card`（提要）：`.card/`（`metadata.yaml`、`structure.yaml`、`cover.html`、`cardcover/`） + `content/{10 位 Base62 编号}.yaml` + 卡片根目录资源（卡片根相对路径，允许子目录）+ 可选嵌套 `.card`；两种正式形态：完整离线卡片、网络资源卡片；版本字段为 `chip_standards_version`。
- `.box`（提要）：以原规范为准（`.box/` 四个必需文件 + `boxcover/`），不得自行发明目录（如 `cards/`、`boxes/`、`layout_configs/`）或字段。
- ADR-009 只保留原则性内容；任何与原规范冲突之处，以原规范为准并同步修正 ADR-009。
- 发布态统一 ZIP Store；不得把 `blob:`、`data:`、系统绝对路径或 `file://` 写回内容配置。

### R13 · 资源引用路径基准

- 资源引用只允许：包内相对路径（相对包根）、`file://`、`http(s)://`、`webdav://`、`chips-resource://`（运行时受控 URI；箱子条目 URL 基线以原始规范为准）。
- 禁止把裸绝对路径（如 `/path/to/card.card`）、`blob:`、`data:` 写入文件格式示例；已有示例必须修正。

### R14 · SDK 命名

- 包名统一 `@chips/sdk`；仓库名可用 `chips-sdk`；文档不得再出现"薯片 SDK（待创建）"表述。

### R15 · 文档库结构与编号

- 库根固定 9 分区：`00-愿景与原则`、`01-架构设计`、`02-开发规范`、`03-插件开发`、`04-文件格式规范`、`05-接口与契约`、`06-开发与运维`、`07-工程管理`、`08-产品与交互`。
- 子系统设计位于 `01-架构设计/01-子系统设计/`（README 中的路径统一修正）。

### R16 · 工程管理口径

- 重大变更：RFC → 评审 → ADR → 实施 → 质量门禁 → 文档同步。
- 文档与代码必须同 PR 更新；文档与实现不一致视为缺陷。
- 技术债务记录在 `项目日志与笔记/技术债务清单.md`。
- 所有质量门禁数值引用《架构原则》与《超大型工程管理体系》，不得自创指标。

### R17 · 安全与沙箱基线（所有文档引用一致）

- Electron：`nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`、生产禁用 `webSecurity` 关闭；不得出现 `enableRemoteModule`（已移除的旧 API）。
- 插件只能经 Bridge 访问系统；权限最小化、调用可审计。
- 资源统一经 `chips-resource://` 访问，受限、可审计。

### R18 · 性能与质量基线（引用一致）

- 冷启动 < 1s（Phase 2 可放宽到 < 2s）；渲染 > 60fps（Phase 2 > 30fps）；空闲内存 < 500MB；打开卡片 < 100ms；打开箱子 < 200ms。
- 测试覆盖率：总体 > 80%，Rust 核心（`chips-*` crates）与共享层（`@chips/ui`、`@chips/bridge`）> 90%；Clippy 无 warning；`unsafe` 必须有 `# Safety` 注释。

### R19 · 内置能力与权限总表（canonical）

能力（Capability）表达"做什么"，权限（Permission）表达"被允许访问什么范畴"；能力声明所需权限，调用按 manifest 申请与权限授予的交集判定。**任何能力 ID 与权限 ID 不得完全相同（R3）。**

| 能力 ID | 所需权限 ID |
|---|---|
| `file:read` / `file:list` / `file:watch` | `filesystem:read` |
| `file:write` / `file:mkdir` | `filesystem:write` |
| `file:delete` | `filesystem:delete` |
| `file:move` | `filesystem:write` |
| `file:copy` | `filesystem:read` + `filesystem:write` |
| `resource:read` | `resources:read` |
| `resource:write` | `resources:write` |
| `resource:open` | `resources:read` |
| `resource:list-handlers` | 无（只读槽位编目，调用仍写审计） |
| `document:create` | `resources:write` |
| `document:open` / `document:read` | `resources:read` |
| `document:write` / `document:save` | `resources:write` |
| `document:export` | 源文档 `resources:read` + 目标路径 `filesystem:write`（目标路径按限定值匹配；导出不修改源文档） |
| `window:create` / `window:list` / `window:focus` / `window:close` / `window:resize` / `window:move` / `window:setTitle` / `window:setState` | `window:control` |
| `menu:set` | `menu:manage` |
| `tray:set` | `tray:manage` |
| `shortcut:register` / `shortcut:unregister` | `shortcut:manage` |
| `system:info` | `system:read` |
| `power:query` | `power:read` |
| `power:prevent-sleep` | `power:manage` |
| `transfer:download` / `transfer:cancel` | `transfer:manage` |
| `notification:send` | `notifications:send` |
| `clipboard:read` / `clipboard:write` | `clipboard:access` |
| `dialog:open` / `dialog:save` | `dialogs:use` |
| `shell:openExternal` | `shell:external` |
| `http:request` | `network:http[:<domain>]` |
| `config:get` / `config:snapshot` | `config:read:<namespace>` |
| `config:set` / `config:reset` | `config:write:<namespace>` |
| `credential:get` / `credential:set` / `credential:delete` | `credential:manage` |
| `event:publish` | `events:publish` |
| `command:register` / `command:unregister` | `command:write` |
| `command:list` / `command:get` | `command:read` |
| `command:invoke` | `command:execute` |
| `cli:task-active` / `cli:task-get` / `cli:task-progress` / `cli:task-complete` / `cli:task-fail` | 无（空权限数组；owner 归属校验） |

规则：

- 本表为 **60 项 Bridge 内置能力**的完整登记；内容处理服务能力不进入本表，按《能力契约规范》第八节登记。
- 句柄访问（`resource:*`）与路径访问（`file:*`）分属两套权限；平台会话已授权的句柄在会话内读取免重复校验，写入仍需 `resources:write`。
- 路径限定必须使用目录变量（如 `${userDocuments}`），不得写裸绝对路径。
- 新增能力必须登记进本表（由《能力契约规范》维护），不得自创未登记能力；逐项 schema、示例与第三方登记规则以《能力契约规范》第 6、7、8 节为准。
- 插件自身日志无需权限（日志按插件命名空间自动归属）；接口文档不得要求 `log:write`。

### R20 · 标识符规范（canonical）

- 基础卡片类型 ID：以 `04-文件格式规范/01` 各类型章节的正式类型标识为准（含历史别名的读取归一规则；新写入一律使用正式标识）。用于：`content/*.yaml` 的 `card_type`、`.card/structure.yaml` 条目 `type`、基础卡片插件 manifest `capabilities.cardTypes[].id`。
- 布局类型 ID：`chips.layout.<name>`（如 `chips.layout.grid`）。用于：箱子 `metadata.yaml` 的 `active_layout_type`、`content.yaml` 的 `layout_configs` 键、布局插件 manifest `capabilities.layouts[].id`。
- 插件 ID：反向域名（`chips.official.*` / `chips.basecard.*` / `chips.layout.*` / `chips.service.*` / 第三方自有域）。
- 错误码分层：文档格式版本问题用 `DOCUMENT_VERSION_*`（由 04/06 维护）；渲染期插件缺失用 `RENDER_PLUGIN_MISSING`、插件/能力/schema 不匹配用 `RENDER_SCHEMA_UNSUPPORTED`。
