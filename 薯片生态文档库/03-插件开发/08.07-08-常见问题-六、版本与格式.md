## 六、版本与格式

### 6.1 生态里有哪几类版本？

三类版本，互不推导（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §2.1）：

- 平台版本：仓库根 workspace 版本，全部平台包、Rust crate、Bridge 契约与 `.cpk` 共用，统一升版、禁止漂移；
- 插件版本：`manifest.yaml` 的 `version`，独立演进、独立发布、独立热更新；
- 文档格式版本：`.card` / `.box` 的 `metadata.yaml` 中 `chip_standards_version`。

平台与插件版本起点为 `0.1.0`，Phase 4 发布 `1.0.0`。

### 6.2 版本号怎么写？

`MAJOR.MINOR.PATCH[-alpha.N|-beta.N|-rc.N][+构建元数据]`；三段为非负整数，禁止前导零与 `v` 前缀；构建元数据不参与优先级比较与范围匹配；预发布版本用于发布前验证，不进入稳定渠道（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §3.1）。

### 6.3 dependencies 的版本范围怎么写？

支持 `=`、`>`、`>=`、`<`、`<=`、`^`、`~`、`||`（逻辑或）与空格（逻辑与）；`*` 匹配任意非预发布版本；预发布版本默认不匹配任何范围。范围非法在安装校验阶段返回 `CPK_MANIFEST_INVALID`、依赖解析阶段返回 `KERNEL_DEPENDENCY_VERSION`；同一插件 ID 只保留一个已安装版本（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §4）。

### 6.4 文档里的 chip_standards_version 是做什么的？

它是卡片与箱子唯一的版本字段与兼容门禁（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §5.1）：

- 主版本低于平台支持：`DOCUMENT_VERSION_OUTDATED`，打开失败并提示运行迁移工具；
- 主版本高于平台支持：`DOCUMENT_VERSION_UNSUPPORTED`，打开失败并提示升级平台；
- 次版本高于平台支持：`DOCUMENT_VERSION_MISMATCH`（警告），正常打开并透出诊断；
- 缺失或非法：`DOCUMENT_METADATA_INVALID`，打开失败。

### 6.5 旧版卡片 / 箱子打不开怎么办？

使用迁移工具显式迁移：`chips migrate <源目录> --out <输出目录> --report <报告文件>`，也可用 `--dry-run` 只扫描不输出。迁移只读源文件、输出固定为当前格式、逐文件独立、输出必检、幂等且报告确定；平台不会自动改写用户文件（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §6）。

### 6.6 为什么不能为旧格式或旧插件保留兼容分支？

生态采用大爆炸重构：旧版冻结、新库从零建立，不提供兼容层、废弃别名或迁移转发；版本不匹配必须产生确定性错误，禁止静默降级与"尽力解析"（R7、[ADR-010](../01-架构设计/ADR/ADR-010-大爆炸重构策略.md)）。兼容问题由迁移工具解决，兼容层不属于架构。

### 6.7 能力 ID、事件 ID 可以带版本号吗？

不可以。能力 ID 与事件 ID 都不含版本：同一能力 ID 同时只有一个生效注册，无版本协商与多版本共存；每个事件 ID 只有一个 payload 形态，事件 ID 不复用。破坏性变更走 RFC，以新能力 ID、新事件 ID 或平台主版本发布（[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) §9.2、[05-事件契约规范](../05-接口与契约/05-事件契约规范.md) §2.4）。

### 6.8 更新插件时有哪些版本约束？

新版本必须满足全部已安装依赖者的 `dependencies` 版本范围，否则拒绝更新并列出不满足的依赖者；权限集合变化必须重新确认，任何绕过授权变化的更新一律拒绝加载；新版本激活失败回滚旧版本、插件保持 `active`（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §6.4）。

### 6.9 插件是否需要自己判断文档格式版本？

不需要。文档格式版本门禁由平台解析器统一执行（`DOCUMENT_VERSION_*` / `DOCUMENT_METADATA_INVALID`）；渲染期只按 `RENDER_PLUGIN_MISSING`（找不到声明该类型的插件）与 `RENDER_SCHEMA_UNSUPPORTED`（插件 / 能力 / schema 不匹配）降级。插件不得自行解析文件或实现版本分支（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §2.3.1、[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §5.2）。
