## 七、四角色专有字段

### 7.1 差异总表

| 字段 | `basecard` | `boxlayout` | `app` | `service` |
|---|---|---|---|---|
| `runtime.targets` | 必需 | 必需 | 必需 | 必需（必须含 `host`） |
| `deepLinks` | 禁止 | 禁止 | 可选 | 禁止 |
| `runtime.background: true` | 禁止 | 禁止 | 禁止 | 允许 |
| `capabilities.cardTypes` | 必需（≥1） | 禁止 | 禁止 | 禁止 |
| `capabilities.layouts` | 禁止 | 必需（≥1） | 禁止 | 禁止 |
| `ui` | 禁止 | 禁止 | 必需（`ui.surface`） | 禁止 |
| `fileAssociations` | 禁止 | 禁止 | 可选 | 可选 |
| `healthCheck` | 禁止 | 禁止 | 禁止 | 可选 |
| `cli.commands` | 禁止 | 禁止 | 可选 | 可选 |

- “禁止”字段出现即 `CPK_MANIFEST_INVALID`；“必需”字段缺失同样失败（[10-服务插件接口](../05-接口与契约/10-服务插件接口.md) 7.4、[09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) 2.1）。
- `capabilities` 是角色限定对象：`cardTypes` 与 `layouts` 互斥，不得同时出现。

### 7.2 `basecard`：`capabilities.cardTypes`

```yaml
capabilities:
  cardTypes:
    - id: base.video
      name: 视频卡片
      description: 视频播放、封面与外挂字幕
      icon: assets/icons/video.svg
      extensions: [.mp4]
      configSchema: assets/schemas/video-config.schema.json
      exportFormats:
        - id: html
          name: HTML 片段
          extension: .html
          mimeType: text/html
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `id` | 是 | 卡片类型 ID；取值以 [01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) 各类型 Schema 的 `card_type` 为准（如 `VideoCard`、`ImageCard`、`base.richtext`、`base.score`、`base.file`；04/01 未登记的类型见其 §6.10，由插件定义并随插件发布；历史别名如 `RichTextCard`、`ScoreCard`、`FileCard` 仅读取归一，不得作为新写入值）；文法 `^[A-Za-z][A-Za-z0-9]*(\.[a-z][a-z0-9-]*)*$`（允许点分形式）；全局唯一，发布后不得更名 |
| `name` | 是 | 简体中文显示名 |
| `description` | 否 | 一句话说明 |
| `icon` | 否 | 图标，包内相对路径且位于 `assets/` 内 |
| `extensions` | 否 | 支持的文件扩展名数组（含点、小写，如 `.md`），用于导入与文件关联建议 |
| `configSchema` | 条件 | 卡片内容使用 `config` 时必填；包内相对路径，JSON Schema 2020-12，顶层为 `object` |
| `aliases` | 否 | 历史别名数组；平台读取 `.card` 的 `type` / `card_type` 时归一为正式 `id`，归一结果不回写文件（[08-基础卡片插件接口](../05-接口与契约/08-基础卡片插件接口.md) §6.2） |
| `exportFormats` | 否 | 实现 `export` 时必须声明；未实现时必须省略 |

`exportFormats` 条目：

| 字段 | 必填 | 规则 |
|---|---|---|
| `id` | 是 | 格式 ID，对应 `export(card, format)` 的 `format` 参数 |
| `name` | 是 | 简体中文显示名 |
| `extension` | 是 | 文件扩展名（含点） |
| `mimeType` | 是 | 产物 MIME 类型，必须与 `export` 返回的 `Blob.type` 一致 |

规则：

- 至少一项；同一插件内不得重复；跨插件重复时后注册方启用失败，不覆盖既有注册（[08-基础卡片插件接口](../05-接口与契约/08-基础卡片插件接口.md) 6.4）。
- `id` 与 `.card/structure.yaml` 条目的 `type`、`content/*.yaml` 的 `card_type` 同值（R20、[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md)）。
- 注册与注销由平台在启用 / 停用流程中按清单执行，插件不得运行时动态增删卡片类型。
- 停用后该类型的已打开视图销毁并提示内容不可用，文档数据保留不丢失。

### 7.3 `boxlayout`：`capabilities.layouts`

```yaml
capabilities:
  layouts:
    - id: chips.layout.grid
      name: 网格布局
      icon: assets/icons/grid.svg
      description: 自适应网格排列条目
      configSchema: assets/schemas/grid-config.schema.json
      schemaVersions: ">=1.0.0 <2.0.0"
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `id` | 是 | 布局类型 ID，`chips.layout.<name>`；文法 `^chips\.layout\.[a-z0-9]([a-z0-9-]*[a-z0-9])?$`；全局唯一，发布后不得更名 |
| `name` | 是 | 简体中文显示名 |
| `icon` | 否 | 图标，包内相对路径且位于 `assets/` 内 |
| `description` | 否 | 一句话说明 |
| `configSchema` | 是 | 布局配置 schema：包内相对路径且位于 `assets/` 内；JSON Schema 2020-12，顶层为 `object`，描述 `layout_configs.<id>.props` 的结构；禁止远程 `$ref`，允许文档内 `#/...` 引用 |
| `schemaVersions` | 是 | 语义化版本范围（语法同 `dependencies[].version`，见[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) 第四节）；声明插件支持渲染与编辑的配置 `schema_version` 取值集合，不得为空；缺失或语法非法时 `CPK_MANIFEST_INVALID` |

规则：

- 至少一项；`id` 与 `.box/metadata.yaml` 的 `active_layout_type`、`.box/content.yaml` 的 `layout_configs` 键同值（R20、[02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md)）。
- `configSchema` 与 `schemaVersions` 是配置 schema 门禁的两半：编辑链路回流与保存前按 `configSchema` 做结构校验、再调用 `validateConfig` 语义校验；平台打开箱子时按 `schemaVersions` 校验 `content.yaml` 的 `schema_version`（[09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) 2.2、7.2）。
- 版本演进口径：兼容性变更提升 MINOR 并放宽 `schemaVersions` 上限；破坏性变更提升 MAJOR，不兼容旧配置时收窄范围下限并让旧配置确定性降级，需兼容时放宽范围并在插件内分支处理；平台不做运行时配置迁移（[05-箱子布局插件开发指南](05-箱子布局插件开发指南.md) 6.6）。
- 布局插件不得读取条目文件、不得解析 YAML、不得创建非受管 iframe；条目内容经帧运行时下发（[09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) 2、6）。
- 箱子引用未安装的布局类型时按 `RENDER_PLUGIN_MISSING` 降级占位，插件不承担兼容责任。

### 7.4 `app`：`ui` 与 `fileAssociations`

```yaml
ui:
  surface: window
  launcher:
    icon: assets/icons/viewer.svg
    name: 卡片查看器
    description: 打开并查看卡片
fileAssociations:
  - extensions: [.card]
    action: open
```

`ui.surface`（`app` 必填）：

| 值 | 含义 |
|---|---|
| `window` | 标准窗口应用：平台在启动时创建主窗口；`runtime.background` 为 `false` 时关闭主窗口触发实例退出 |
| `desktop` | 桌面层应用：平台创建无边框桌面表面；关闭不触发实例退出 |
| `tray` | 托盘应用：平台注册托盘图标与菜单，不创建窗口 |

`ui.launcher`（可选）：

| 字段 | 必填 | 缺省 |
|---|---|---|
| `name` | 否 | manifest `name` |
| `description` | 否 | manifest `description` |
| `icon` | 否 | 插件包默认图标；显式声明时为包内相对路径且位于 `assets/` 内 |

- 省略整个 `ui.launcher`：不注册启动器入口，应用只能经文件关联或命令启动；声明 `ui.launcher`（含空对象 `{}`）：注册启动器入口且字段按上表补齐（[07-应用插件接口](../05-接口与契约/07-应用插件接口.md) 5.3）。
- 表面窗口由平台创建，属免权限范围；运行中额外创建窗口一律经 `window:create` 能力。

`deepLinks`（`app` 可选）：

| 字段 | 必填 | 规则 |
|---|---|---|
| `scheme` | 是 | 深链接 scheme；由平台分配，不得占用系统保留 scheme |
| `host` | 是 | 深链接 host；插件内唯一 |
| `pathPattern` | 否 | 路径模式；省略表示匹配该 host 下全部路径 |

- 声明即注册深链接路由；插件未运行时以 `launch` 的 `source: deep-link` 投递 `url`，已运行时发布 `app:opened-with-url`（[07-应用插件接口](../05-接口与契约/07-应用插件接口.md) §5.5、[05-事件契约规范](../05-接口与契约/05-事件契约规范.md) §4.7）。
- 深链接只做路由，不代表内容访问授权。

`fileAssociations`（`app` / `service` 可选；完整形状与校验以 [14-资源打开与默认处理器契约](../05-接口与契约/14-资源打开与默认处理器契约.md) §3 为权威）：

| 字段 | 必填 | 规则 |
|---|---|---|
| `extensions` | 是 | 扩展名数组，含点、小写、无重复；与 `mimeTypes` 至少一项非空，只覆盖 MIME 的条目写空数组 `[]` |
| `action` | 是 | 当前唯一取值 `open`：以打开方式接收文件 |
| `mimeTypes` | 否 | MIME 声明：小写精确 MIME 或主类型通配（`type/*`）；`*/*` 不允许 |
| `tier` | 否 | 处理器层级 `primary` / `fallback`；缺省 `primary`；`fallback` 只在同等级无专用候选时接管 |

- 声明即注册文件关联路由；同一槽位存在多个声明方时按匹配等级（精确 MIME ＞ 主类型通配 ＞ 扩展名）与层级解析，用户偏好可改选默认（[14-资源打开与默认处理器契约](../05-接口与契约/14-资源打开与默认处理器契约.md) §4）。
- 文件关联只决定路由，不产生持久授权；接收方读取打开投递的资源须声明 `resources:read` 基础权限，跨作用域访问由投递授权覆盖（[14-资源打开与默认处理器契约](../05-接口与契约/14-资源打开与默认处理器契约.md) §4.4）；系统关联与拖放来源不要求 `filesystem:*`。

### 7.5 `service`：`runtime.background` 与 `healthCheck`

```yaml
runtime:
  targets: [host]
  background: true
healthCheck:
  interval: 30s
  timeout: 5s
```

| 字段 | 必填 | 默认值 | 规则 |
|---|---|---|---|
| `interval` | 否 | `30s` | 检查周期；最小 `1s` |
| `timeout` | 否 | `5s` | 单次检查超时；必须小于 `interval` |

- 时长格式为 `<正整数><单位>`，单位支持 `ms`、`s`、`m`；不支持小数与复合写法；非法时 `CPK_MANIFEST_INVALID`。
- 仅 `service` 可声明 `healthCheck`；声明该字段必须实现 `health()`，否则启用校验失败，插件不得进入 `active`（[10-服务插件接口](../05-接口与契约/10-服务插件接口.md) 5.1）。
- 实现 `health()` 但未声明 `healthCheck` 时，平台不调用 `health()`。
- 连续 3 次不健康（含超时与抛出）时平台停用插件并置 `failed`，需用户显式重试。

### 7.6 `app` / `service`：`cli.commands`

```yaml
cli:
  commands:
    - commandPath: [office, open]
      commandId: office:open          # app 目标必填：运行时命令 ID（13-命令系统契约 登记）
      title: 打开办公文档
      description: 用薯片办公打开指定文档
      examples:
        - chips office open ~/文档/报告.docx
      permissions:
        - resources:read
      target:
        type: app
        pluginId: chips.official.office
        surface:
          open: true
          focus: true
          reuse: preferred
      arguments:
        - name: path
          position: 0
          type: path
          required: true
          mapsTo: path
          path:
            kind: file
            role: input
            exists: true
      output:
        mode: json
        artifacts: [output.files]
      job:
        wait: true
        cancelOnInterrupt: true
      conflict:
        priority: 0
        namespace: office
```

`cli` 对象只能包含 `commands` 数组；`commands` 至少一项。命令入口字段：

| 字段 | 必需 | 语义索引 |
|---|---|---|
| `commandPath` | 是 | 命令路径（段文法、固定命令根、插件内唯一）见 [CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §2.3、§5.1 |
| `commandId` | `app` 目标必填 | 运行时命令 ID `<domain>:<action>`，指向 [13-命令系统契约](../05-接口与契约/13-命令系统契约.md) 登记的命令记录；`service` 目标禁止声明 |
| `title` / `description` / `examples` | `title` 是 | 简体中文展示文案；帮助与 TUI 消费，R5 |
| `permissions` | 否 | 命令执行所需的已登记权限 ID；执行前预检，缺失返回 `CLI_PERMISSION_DENIED` |
| `target` | 是 | `type` 必须等于插件角色；`app` 目标含 `surface`，`service` 目标含 `capability` |
| `arguments` / `options` | 否 | 参数模型：11 种类型、`position` / `short` / `mapsTo` / `path` / `batch` / `validation` / `ui`，完整定义见 [CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §5.2 |
| `output` / `job` / `conflict` | 否 | 输出模式与产物、任务等待与取消、冲突优先级；见 [CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §5.4、§5.5、§5.7 |

规则：

1. **入口声明与清单的关系**：本文只登记 `cli.commands` 字段的存在、角色适用与校验入口；命令路径文法、参数模型、目标调度、输出、冲突与任务生命周期等专有语义全部以 [CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §五为唯一权威，本文不重复定义。
2. **固定命令根**：`commandPath` 第一段不得命中 CLI 固定命令根（`help`、`start`、`stop`、`status`、`config`、`logs`、`plugin`、`update`、`doctor`、`open`、`completion`、`dev`，另含历史保留名 `host`），大小写不敏感；命中即清单校验失败（[CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §2.3）。
3. **入口标识派生**：CLI 入口标识 `entryId` 由 `<pluginId>.cli.<commandPath 点分>` 派生（如 `chips.official.office.cli.office.open`），用于命令索引、帮助与补全展示；不写入 manifest，也不进入运行时命令注册表（[CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §5.1）。
4. **`commandId` 与运行时命令的关系**：`commandId` 是运行时命令注册表中的记录引用，登记与存在性在运行时校验；`app` 目标经“启动并投递”执行（[13-命令系统契约](../05-接口与契约/13-命令系统契约.md) §4.4），`service` 目标经能力路由调用。
5. **校验时机**：`cli.commands` 随清单校验阶段在打包与安装时校验；违规拒绝安装（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §五），执行期错误按 CLI 域错误码返回（[CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §2.5、§2.6）。
6. **角色一致**：`app` 目标的 `target.type` 必须为 `app` 且声明 `commandId`；`service` 目标的 `target.type` 必须为 `service`、声明已登记的 `capability`，且不得声明 `commandId` / `surface` / `job`。
7. **权限不隐式提权**：`cli.commands[].permissions` 只能声明已登记权限 ID，不扩大插件自身 `permissions` 的授权范围；未授权调用按 `CLI_PERMISSION_DENIED` 拒绝（[CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §5.1、[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) §六）。
