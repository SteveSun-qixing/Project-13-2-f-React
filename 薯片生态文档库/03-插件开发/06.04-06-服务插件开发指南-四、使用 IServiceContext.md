## 四、使用 `IServiceContext`

`start` 收到的 `ctx` 就是全部可用面；不存在的成员即不可用，插件不得访问全局对象或平台内部结构扩展访问面。完整接口定义见 E10 第三节。

| 成员 | 类型 | 用途 |
|---|---|---|
| `ctx.pluginId` | `readonly string` | 当前插件 ID（反向域名）；用于日志、事件载荷与自检 |
| `ctx.bridge` | `IServiceBridge`（仅 `request` / `resource`） | 出站能力与资源访问，按被调能力声明的权限判定 |
| `ctx.config` | `IServiceConfig` | 自身命名空间 `plugins.<pluginId>` 的配置读取、监听与写入 |
| `ctx.logger` | `IServiceLogger` | 平台日志流；免权限（R19），按插件命名空间自动归属 |
| `ctx.provide` / `ctx.inject` | 方法 | 注册与消费 Cordis 服务 |
| `ctx.on` / `ctx.once` / `ctx.emit` | 方法 | 内核事件订阅与发布 |
| `ctx.registerCapability` | 方法 | 注册 Bridge 能力，只能在 `start` 内调用 |
| `ctx.effect` | 方法 | 登记自定义清理函数 |

### 4.1 服务提供与注入（`provide` / `inject`）

```typescript
interface ITranslationCache {
  touch(sourceId: string): void;
}

interface ITranslationRequested {
  sourceId: string;
}

// 提供方：注册 Cordis 服务（服务名 ^[a-z][a-z0-9]*(-[a-z0-9]+)*$）
ctx.provide<ITranslationCache>('translation-cache', {
  touch(sourceId: string): void {
    // 业务实现
    void sourceId;
  },
});

// 消费方：声明依赖后通过注入回调使用，不感知提供者身份
ctx.inject(['translation-cache'], (ctx) => {
  ctx.on<ITranslationRequested>('translation:requested', (payload) => {
    ctx.translationCache.touch(payload.sourceId);
  });
});
```

规则（E10 3.3）：

- 服务名在作用域内唯一，同名以最近祖先为准；`provide` 返回后服务即可被解析。
- `inject` 回调是同步函数；回调内不得缓存跨代际的服务引用，长期任务必须挂到注入 Fork。
- 消费其它插件提供的服务时，必须在 manifest `dependencies` 中声明对该提供方插件的依赖。
- 服务值必须可跨线程共享；服务内部并发与缓存自行负责。

### 4.2 事件（`on` / `once` / `emit`）

```typescript
interface IConversionCompleted {
  uri: string;
}

const subscription = ctx.on<IConversionCompleted>('converter:completed', (payload) => {
  // 监听器不得执行阻塞调用；耗时处理转为可取消的后台任务
  void payload.uri;
});

ctx.emit<IConversionCompleted>('converter:completed', { uri: 'example' });
subscription.dispose();
```

规则（E10 3.4）：

- 主进程事件面即内核总线；标准事件与插件自有域事件都经 `ctx.on` / `ctx.emit` 使用（[09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md) 3）。
- `internal:*` 为内核内部事件，插件不得订阅、发布或依赖。
- 事件只用于通知，不承担请求-响应语义；需要返回值时使用服务或能力。
- 订阅随当前 Fork 自动撤销；标准事件的订阅权限由[05-事件契约规范](../05-接口与契约/05-事件契约规范.md)声明，未授权的订阅不建立。

### 4.3 出站能力与资源（`ctx.bridge`）

```typescript
const handle = ctx.bridge.resource(uri);
try {
  const bytes = await handle.read();
  void bytes;
} finally {
  handle.release();
}
```

规则（E10 3.7）：

- `IServiceBridge` 只包含 `request` 与 `resource`；`bridge.subscribe` 是渲染进程投影，不在服务上下文暴露。
- 每次 `request` 与插件调用同链路：能力存在性检查 → 权限判定 → JSON Schema 校验 → 路由执行 → 错误归一（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 2.2）。
- 能力调用使用本插件自己的会话权限快照；不得借用调用方权限，也不得代调用方申请权限。
- 资源访问统一使用 `chips-resource://`；URI 只能来自平台交付的基址、文档/视图引用或调用参数与事件载荷，不得自行拼接；句柄使用完毕必须 `release()`，不得依赖垃圾回收。
- 大资源必须经句柄或流式接口读取（`read()` 超过 8 MiB 返回 `RESOURCE_TOO_LARGE`），不得经能力参数传输大对象（[06-资源协议规范](../05-接口与契约/06-资源协议规范.md) 6.6）。

### 4.4 副作用登记（`effect`）

```typescript
const changes = ctx.config.watch('quality', (change) => {
  void change.effectiveValue;
});
const timer = setInterval(() => {
  // 周期性轻量任务
}, 60_000);

ctx.effect(() => {
  changes.dispose();
  clearInterval(timer);
});
```

规则（E10 3.8）：

- 定时器、连接器、观察者等平台未内建追踪的资源必须经 `effect` 包装。
- 撤销顺序为「子 Fork 后序 + 自身副作用 LIFO」；单个清理失败不中断其余撤销。
- `cleanup` 必须幂等、不得抛出；未被 Fork 追踪的副作用视为插件缺陷，平台可检测并审计。
