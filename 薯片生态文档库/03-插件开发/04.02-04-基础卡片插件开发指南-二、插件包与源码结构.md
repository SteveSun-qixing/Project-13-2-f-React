## 二、插件包与源码结构

### 2.1 源码目录

示例插件位于 Monorepo 的 `examples/plugins/richtext-basecard/`，源码与静态资源分离：

```text
richtext-basecard/
├── manifest.yaml                    # 唯一权威清单
├── package.json                     # 构建脚本；version 必须与 manifest 一致
├── tsconfig.json
├── src/
│   ├── config.ts                    # 配置模型：读取、校验、默认值
│   ├── main.ts                      # dist/index.js 源码：主进程纯函数
│   ├── render.tsx                   # render.js 源码：查看/编辑 UI 与插件装配
│   └── index.ts                     # 拆分导出（非构建入口）
└── assets/
    ├── icons/
    │   └── richtext.svg             # 卡片类型图标
    └── schemas/
        └── richtext-config.schema.json   # 卡片配置 schema
```

目录与文件命名遵循[01-代码组织规范](../02-开发规范/01-代码组织规范.md)与[02-TypeScript编码规范](../02-开发规范/02-TypeScript编码规范.md) §2.1；两个入口的源码拆分（`main.ts` → `dist/index.js`、`render.tsx` → `render.js`）与本文 §2.3、§9.1 及[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §7.3 的源码示例一致。

### 2.2 构建产物与 `.cpk` 布局

构建后的安装暂存目录即 `.cpk` 的包根，不得出现源码、锁文件、sourcemap 或包裹目录：

```text
richtext-basecard-1.0.0.cpk (ZIP Store)
├── manifest.yaml
├── dist/
│   └── index.js                     # 插件模块入口（Cordis 运行时加载）
├── render.js                        # 渲染入口（渲染帧装载）
└── assets/
    ├── icons/
    │   └── richtext.svg
    └── schemas/
        └── richtext-config.schema.json
```

`manifest.yaml` 内的一切文件引用都必须是包内相对路径，且目标位于 `assets/` 内（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §2.6）；因此 `configSchema` 与图标都放在 `assets/` 下。

### 2.3 两个入口

| 入口 | 路径 | 说明 |
|---|---|---|
| 主进程入口 | `dist/index.js` | 全部角色必需；承载主进程纯函数（`validateConfig` / `createInitialContent` / `collectResourcePaths`）与角色模块入口，经受管模块加载器加载 |
| 渲染入口 | `render.js` | `basecard` 必需；承载渲染方法（`renderView` / `renderEditor` / `export`），在渲染帧内装载 |

规则：

1. 两个入口都必须是 UTF-8 文本 ESM；`src/index.ts` 只做拆分导出（`main.ts` → `dist/index.js`、`render.tsx` → `render.js`），不在两个入口手写重复实现。
2. `render.js` 必须外部化平台共享依赖（React、`@chips/ui`），不得内联第二套组件库；帧运行时统一提供这些依赖（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §3.5）。
3. 主进程入口只经受管模块加载器加载：只允许插件作用域 `chips-resource://` 与平台白名单模块，禁止 `node:*`、`electron` 与裸路径（[02-插件清单规范](./02-插件清单规范.md) §4.3）。
4. 包内不得出现 `.html` 文档、代码文件、原生载荷与嵌套归档；`.cpk` 总大小、成员数与单文件大小受[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §4 限额约束。

### 2.4 构建与本地验证

- 用[01-快速开始](./01-快速开始.md)中的 `basecard` 脚手架生成骨架，再按本文实现接口；
- `build` 脚本产出 `dist/index.js`、`render.js` 与资源目录，具体构建配置见[02-构建与打包](../06-开发与运维/02-构建与打包.md)；
- 开发态允许以目录形式加载（布局与包根一致）；发布单位始终是单个 `.cpk`；
- 打包与校验使用 `@chips/cli`，校验流程与错误码见[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §5、§8：

```bash
pnpm exec chips plugin pack --dir examples/plugins/richtext-basecard --out dist/
pnpm exec chips plugin validate dist/richtext-basecard-1.0.0.cpk
```
