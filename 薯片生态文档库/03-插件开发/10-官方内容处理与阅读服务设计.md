> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版

## 一、定位与边界

### 1.1 定位

- 本文承接[《官方应用功能总览》](../08-产品与交互/08-官方应用功能总览.md) §十六 登记的四类条目，给出其生态级设计结论与落点：电子书渲染引擎、媒体播放消费契约、Office 文档处理服务、OCR。
- 四类条目的共同缺口不是缺少某一个能力 ID，而是缺少**归属与形态决策**：由谁承载、以什么插件角色交付、经过哪条正式链路、失败时给什么错误语义。本文逐项回答定位、能力与权限、接口要点、错误码、实现形态、依赖与阶段六个问题。
- 本文只做设计决策与边界收口；字段级 schema、格式选项、支持矩阵、接口签名与错误码表的完整定义由既有权威文档或提供方契约承载，本文只引用、不转述。

### 1.2 覆盖与不覆盖

| 内容 | 归属 |

| 资源打开路由、处理器层级与标准业务载荷类型 | [资源打开与默认处理器契约](../05-接口与契约/14-资源打开与默认处理器契约.md) |
| 文件处理会话、编排阶段、受控提交与 `FILE_PROCESS_*` 错误码 | [文件处理契约](../05-接口与契约/15-文件处理契约.md) |

### 1.3 形态术语

| 形态 | 含义 | 判定 |
|---|---|---|
| 官方服务插件 | `service` 角色插件，经 `ctx.provide` 暴露 Cordis 服务与内容处理能力（[服务插件接口](../05-接口与契约/10-服务插件接口.md)） | 需要跨插件复用、可表达为纯处理原子操作时使用 |
| 应用插件 | `app` 角色插件，消费平台链路与能力，承载界面与交互（[应用插件接口](../05-接口与契约/07-应用插件接口.md)） | 需要渲染帧、交互状态或用户界面时使用 |
| 应用内引擎 | 应用插件内部模块层，随应用包发布，不注册服务、不注册能力 | 只服务单一应用、与渲染帧和交互强耦合时使用 |
| 平台引擎 | 随平台编译与分发的原生引擎资产，由壳创建与管理进程、内核调度（R11：Rust 能力属于平台） | 需要原生计算且插件不得携带原生载荷时使用 |

- 四种形态不叠加：同一能力只在一种形态承载；需要组合时按"服务提供方 + 应用消费者"组合，不建第二实现。

### 1.4 基本约束

1. 插件访问平台只经 `window.chips` / `ctx.bridge`，插件之间不直接 `import`（[插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §8）。
2. 内容处理能力不注册为 Bridge 能力、不进 R19 权限映射，由 `service` 角色插件以 Cordis 服务提供；消费方经 `ctx.inject` 消费（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.1、§8.5）。
3. 渲染进程（应用 UI）不直接注入内容处理服务；UI 一律经应用主逻辑或文件处理契约消费（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.5）。
4. 一切打开动作经资源打开路由；应用不硬编码目标插件 ID、不自行实例化其他插件（[资源打开与默认处理器契约](../05-接口与契约/14-资源打开与默认处理器契约.md) §1.1）。
5. `.card` / `.box` 的解析、渲染、写入只有一条链路、一个写口；本文四项设计均不得建立第二解析器或第二渲染管线（R8）。
6. 状态分层持久化：高频状态留内存、跨会话状态落插件私有数据目录、用户偏好走插件自身配置命名空间；禁止高频 `config:set` 往返（[配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §9.4、[权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §4.4）。

## 二、电子书渲染引擎

### 2.1 定位

- 电子书渲染引擎是**书籍阅读器应用（`chips.official.book-reader`）的应用内引擎**：承担 EPUB / EPUB3、PDF、TXT、Markdown、FB2、RTF 的解析、排版与阅读运行时，并驱动目录、搜索、书签与进度四类阅读状态。
- **归属决策**：应用内引擎，不登记为内容处理服务能力、不注册 Bridge 能力。依据：
  1. 分页 / 滚动 / 目录 / 搜索 / 书签 / 进度是渲染帧内的交互运行时（依赖 DOM 度量、章节视图、连续输入意图与动效），与内容处理能力"纯处理、无用户可见副作用、输入输出为结构化克隆值"的约束不相容（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.3）；
  2. 消费者只有书籍阅读器（图包模式为图片查看器），不存在跨插件复用；按"每个能力 ID 绑定唯一服务名与唯一提供方"的登记原则，不需要为此设立服务（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.2）；
  3. 引擎渲染的是电子书章节等普通文件内容，不解析 `.card` / `.box`，不构成第二渲染管线（R8）。
- 输入源：书籍阅读器只消费资源打开路由投递的受管引用与 `chips.book-card` 载荷（[资源打开与默认处理器契约](../05-接口与契约/14-资源打开与默认处理器契约.md) §5.4、§5.5）；不读取卡片包内部路径、不解析卡片文件。
- 电子书卡片：类型 `base.book` 由官方基础卡片插件 `chips.basecard.book` 登记；载荷 `chips.book-card` 含 `mode: 'ebook' | 'image-sequence'`、`resources.book` / `resources.images` 与 `display`。类型与载荷已定义，本文不重复。

### 2.2 能力与权限

- 角色与登记：`chips.official.book-reader`，`app` 角色；处理器层级 `primary`，声明 EPUB / EPUB3、PDF、TXT、Markdown、FB2、RTF 的扩展名与 MIME（登记与状态以[官方插件与应用目录](./09-官方插件与应用目录.md) §7.2 为准）。
- Bridge 能力与权限（按最小权限声明，最终以插件清单为准）：

| 能力 | 权限 | 用途 |
|---|---|---|
| `resource:read` 与 `chips.resource(uri)` 句柄 | `resources:read` | 读取投递资源与打开载荷引用；大文件用 `readRange()` / `stream()` |
| `file:read` | `filesystem:read:<限定路径>` | 经 `dialog:open` 授权的本地文件导入 |
| `dialog:open` | `dialogs:use` | 应用内手动打开文件 |
| `http:request` | `network:http[:<域名>]` | 远程阅读资源（按需声明） |
| `shell:openExternal` | `shell:external` | 章节内外部链接 |
| `window:create` / `window:setState` 等 | `window:control` | 多窗口与窗口状态恢复（按需） |
| `config:get` / `config:snapshot` / `config:set` / `config:reset` | 自身命名空间免权限 | 阅读偏好读写 |

- 免权限范围：插件私有数据目录、自身配置命名空间（[权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §4.4）。
- 内容处理服务：无依赖。阅读引擎不调用格式算法服务，也不实现图像算法；封面、缩略图等派生资源的图像归一由调用侧按内容处理服务登记使用。

### 2.3 接口要点

入口归一：

- 所有入口（文件关联、资源打开投递、应用内打开、远程链接）归一为同一阅读目标后进入统一加载链；`mode: 'ebook'` 以顶层 `resourceOpen.uri` 为唯一读取入口，`resources.book` 与 `display` 只用于恢复上下文（[资源打开与默认处理器契约](../05-接口与契约/14-资源打开与默认处理器契约.md) §5.4）；`mode: 'image-sequence'` 由图片查看器按 `resources.images[]` 顺序建立队列。

解析层（应用内模块）：

| 格式 | 解析形态 |
|---|---|
| EPUB / EPUB3 | ZIP（store / deflate）解包；`META-INF/container.xml`、OPF（metadata / manifest / spine）、NAV / NCX 目录解析；`Publication` / `Link` 内部模型；章节 HTML 变换（资源内联、内部链接改写） |
| PDF | 应用渲染帧内的 PDF 文档视图承载；页级导航、缩放与文内搜索由 PDF 视图承担，阅读器维护页级书签与进度 |
| TXT / Markdown / FB2 / RTF | 转内部虚拟章节，复用同一阅读运行时 |
| MOBI / AZW / AZW3 / DJVU / DOC / DOCX | 识别但不解码：给出明确错误态，不内置临时解析器、不静默失败 |

阅读运行时（应用内模块）：

- 分页模式：以 spread 索引绝对定位（偏移 = 索引 × 单次前进量），跨章连续翻页无累计漂移；
- 滚动模式：主轴滚动度量、章节边界检测与锚点定位；
- 布局：窗口断点、单双页 spread、版心宽度、栏间距随偏好实时计算；
- 位置追踪：章节索引 + spread 索引 / 滚动比例，输出章节内进度与全书进度；
- 搜索：跨章节增量搜索、结果摘录与视口内高亮；
- 书签：位置快照 + 正文摘录，跨阅读模式打开时按滚动比例回退定位；
- 动效：翻页动效、章节过渡与边界回弹；`prefers-reduced-motion`、竖排或 RTL 场景确定性降级为平滑滚动。

持久化分层：

| 状态 | 位置 | 说明 |
|---|---|---|
| 阅读偏好（字号、行高、字距、字体、版心、阅读模式、背景与亮度等） | 插件自身配置命名空间 | 低频、用户显式操作，经 `config:*` 写入 |
| 阅读位置、书签、最近阅读记录 | 插件私有数据目录 | 按书源隔离；高频进度只做节流落盘，不经 `config:set` 往返；文件带版本字段，以临时文件 + 原子替换写入 |

- 权限判定、句柄生命周期与错误归一由平台链路承担；引擎不直连文件系统、不自建 Bridge 通道。

### 2.4 错误码

- 引擎为应用内模块，业务失败使用书籍阅读器自身的插件域前缀（[应用插件接口](../05-接口与契约/07-应用插件接口.md) §八）；平台错误按原码透传。

| 错误码 | 场景 | retryable |
|---|---|---|
| `BOOK_READER_FORMAT_UNSUPPORTED` | 格式被识别但无正式解码器（MOBI / AZW / AZW3 / DJVU / DOC / DOCX） | false |
| `BOOK_READER_PARSE_FAILED` | EPUB 容器、OPF / NAV 目录或章节变换失败 | false |
| `BOOK_READER_RESOURCE_MISSING` | 章节资源缺失且无法按降级规则呈现 | false |
| `BOOK_READER_ENCRYPTED_UNSUPPORTED` | 加密 / DRM 出版物：明确提示不支持，不尝试绕过 | false |
| `BOOK_READER_POSITION_INVALID` | 持久化阅读位置越界或格式版本不兼容：回退章节起始位置并提示 | false |

- 平台链路错误保持原码：资源句柄与作用域错误 `RESOURCE_*`、路径能力错误 `FILE_*`、网络错误 `HTTP_*`、平台归一错误 `APP_OPEN_FILE_FAILED`（[资源协议规范](../05-接口与契约/06-资源协议规范.md) §七、[能力契约规范](../05-接口与契约/04-能力契约规范.md) §11.4、[应用插件接口](../05-接口与契约/07-应用插件接口.md) §八）。

### 2.5 实现形态

- `chips.official.book-reader`（`app`）单插件承载；解析层、阅读运行时与交互层均为应用内模块，随应用包发布。
- ReadiumCSS 样式资产与分页 / 布局度量思路的来源与许可义务以[第三方参考资产清单](../02-开发规范/11-第三方参考资产清单.md) RA-09 / RA-10 为权威；引擎对外只暴露应用自身的界面与平台契约，不暴露上游内部事件与 Electron 语义。
- 图包模式由 `chips.official.photo-viewer`（`app`）消费 `mode: 'image-sequence'` 载荷，与书籍阅读器共用资源打开链路，不互相调用。

### 2.6 依赖与阶段

- 依赖：资源打开与默认处理器契约（载荷与路由）、资源协议规范（句柄与流式）、配置系统设计（偏好分层）、权限系统设计（免权限范围）、官方插件与应用目录（ID 与状态）、第三方参考资产清单（许可）。
- 阶段：随官方应用插件重写在 Phase 3 交付；Phase 3 前不对外声明为公共能力（[开发流程与阶段计划](../07-工程管理/02-开发流程与阶段计划.md) §六）。

## 三、媒体播放消费契约

### 3.1 定位

- 本章定义音频 / 视频播放器（`chips.official.music-player`、`chips.official.video-player`）**如何消费基础卡片载荷**，以及播放偏好与播放状态如何持久化；不定义载荷形状（权威为[资源打开与默认处理器契约](../05-接口与契约/14-资源打开与默认处理器契约.md) §5.4），不定义卡片字段（权威为[卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §6.2、§6.8），不定义播放交互界面（权威为[查看器设计](../08-产品与交互/03-查看器设计.md)）。
- 音频基础卡片正式类型为 `base.music`，载荷 `kind: 'chips.music-card'`；视频基础卡片为 `base.video`，载荷 `kind: 'chips.video-card'`。播放器是载荷的只读消费者：不改写卡片、不改写资源、不解析 `.card` / `.box`。

### 3.2 能力与权限

- 角色与登记：两个播放器均为 `app` 角色，处理器层级 `primary`（`audio/*` 与 `video/*`），登记以[官方插件与应用目录](./09-官方插件与应用目录.md) §7.2 为准。
- Bridge 能力与权限（按最小权限声明，最终以插件清单为准）：

| 能力 | 权限 | 用途 |
|---|---|---|
| `resource:read` 与句柄 | `resources:read` | 读取主媒体、封面、歌词与字幕引用；大文件流式 |
| `file:read` | `filesystem:read[:<路径>]` | 本地打开读取 |
| `file:write` | `filesystem:write[:<路径>]` | 保存音频 / 视频副本（受控提交：临时文件 + 原子替换） |
| `file:copy` | `filesystem:read` + `filesystem:write` | 从真实路径复制副本（按需） |
| `dialog:open` / `dialog:save` | `dialogs:use` | 应用内打开与另存 |
| `config:get` / `config:snapshot` / `config:set` / `config:reset` | 自身命名空间免权限 | 播放偏好读写 |

- 内容处理服务消费（经 `ctx.inject`，无 Bridge 权限映射，[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.4）：
  - 媒体元数据读取（时长、编码、容器与标签）用 `content-media.read-metadata`；
  - 封面等图像归一 / 转码（如 TIFF 封面归一为 PNG）用 `content-image.normalize` / `content-image.transcode`；
  - 注入发生在应用主逻辑；渲染进程不直接注入（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.5）。
- 免权限范围：插件私有数据目录、自身配置命名空间。

### 3.3 接口要点

载荷消费：

| 载荷 | 消费字段 | 播放器行为 |
|---|---|---|
| `chips.music-card` | `resources.audio` | 播放源；与顶层 `resourceOpen.uri` 同值，以顶层 URI 为唯一读取入口 |
| `chips.music-card` | `resources.cover` / `resources.lyrics` / `display.title` / `display.artist` | 封面与滚动歌词呈现、标题与艺术家展示；字段缺失时按资源元数据或文件名回退，不拒绝打开 |
| `chips.music-card` | 无 `playback` 段 | 入口行为取应用偏好默认值（音量、循环、静音），不臆造卡片字段 |
| `chips.video-card` | `resources.video` | 播放源；同顶层 URI 规则 |
| `chips.video-card` | `resources.subtitles[]`（`id` / `label` / `language` / `kind` / `default`） | 建立字幕轨列表；`default: true` 为初始默认轨；轨道呈现锚定渲染帧的字幕层 |
| `chips.video-card` | `display.title` / `display.creator` / `display.publishTime` | 标题与发布信息展示 |
| `chips.video-card` | `playback.autoplay` / `loop` / `muted` / `playbackRate` / `startTime` | 打开时的初始播放状态；倍速取值域以卡片 schema 为准；用户操作随时覆盖初始值 |

- 音轨：卡片不定义音轨字段；音轨选择是宿主媒体能力的运行时消费，不写回卡片。
- 元数据补全：嵌入元数据（标题、歌手、专辑、封面、歌词）解析经 `content-media.read-metadata`；解析结果只用于展示与内存回退，查看态不写回卡片；卡片字段的正式补全只发生在编辑链路的基础卡片编辑态。
- 打开投递：运行中实例经标准事件 `resource:opened` 接收上下文，随后 `openFile(uri)` 投递；多文件按逐次路由（[资源打开与默认处理器契约](../05-接口与契约/14-资源打开与默认处理器契约.md) §2.1、§5.5）。
- 播放器能力协商：无解码能力的格式给出明确错误态；播放核心基于宿主媒体能力（`<audio>` / `<video>`），不引入第三方播放运行时，不做转码与剪辑（[官方应用功能总览](../08-产品与交互/08-官方应用功能总览.md) §八、§九）。

偏好与状态持久化分层：

| 状态 | 位置 | 说明 |
|---|---|---|
| 用户偏好（音量、静音、默认倍速、循环模式、字幕语言 / 开关、界面偏好） | 插件自身配置命名空间 | 低频、用户显式操作，经 `config:*` 写入 |
| 播放位置、播放队列、最近播放 | 插件私有数据目录 | 按来源隔离；播放位置节流落盘，不经 `config:set` 往返；文件带版本字段，以临时文件 + 原子替换写入 |

- 卡片 `playback` 字段是**本次打开的入口参数**，不是用户偏好：播放器先应用载荷参数，再按用户操作与偏好调整；退出时不把当前状态回写载荷。
- 保存副本：经 `dialog:save` + `file:write`（或 `file:copy`）受控提交，默认保留原始字节、不转码（[查看器设计](../08-产品与交互/03-查看器设计.md) §五）。

### 3.4 错误码

- 播放器为应用插件，业务失败使用各自插件域前缀；内容处理服务错误按提供方码透传（服务注入路径不经 Bridge 归一）。

| 错误码 | 归属 | 场景 | retryable |
|---|---|---|---|
| `MUSIC_PLAYER_SOURCE_UNAVAILABLE` | 音乐播放器 | 主音频引用失效或不可读 | false |
| `MUSIC_PLAYER_DECODE_UNSUPPORTED` | 音乐播放器 | 宿主媒体栈无对应解码能力 | false |
| `MUSIC_PLAYER_LYRICS_PARSE_FAILED` | 音乐播放器 | 歌词文件解析失败（降级为纯听，不阻断播放） | false |
| `VIDEO_PLAYER_SOURCE_UNAVAILABLE` | 视频播放器 | 主视频引用失效或不可读 | false |
| `VIDEO_PLAYER_DECODE_UNSUPPORTED` | 视频播放器 | 宿主媒体栈无对应解码能力 | false |
| `VIDEO_PLAYER_SUBTITLE_UNSUPPORTED` | 视频播放器 | 字幕轨格式不受支持（降级为无字幕，不阻断播放） | false |

- 平台与服务错误原码：`RESOURCE_*` / `FILE_*` / `HTTP_*` / `MEDIA_*` / `IMAGE_*`（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.6、§11.4）。

### 3.5 实现形态

- 两个 `app` 插件各自承载播放与界面；共享的消费规则（载荷到行为的映射、偏好分层）由本章统一，不要求跨插件代码复用。
- 元数据与图像处理由内容处理服务提供方（`chips.service.content-media`、`chips.service.content-image`）承载，播放器不实现格式算法、不复制解析库。

### 3.6 依赖与阶段

- 依赖：资源打开与默认处理器契约（载荷形状与投递）、卡片文件格式（字段）、能力契约规范 §八（元数据与图像服务）、配置系统设计（偏好分层）、权限系统设计（免权限范围）、查看器设计（交互）。
- 阶段：随播放器应用在 Phase 3 交付；依赖的内容处理服务提供方与文件处理链路按 Phase 2 / Phase 3 推进（[开发流程与阶段计划](../07-工程管理/02-开发流程与阶段计划.md) §五、§六）。

## 四、Office 文档处理服务

### 4.1 定位

- Office 文档处理服务面向 `.docx` / `.xlsx` / `.xlsm` / `.xls` / `.csv` / `.pptx` / `.pdf` 的查看与编辑，由两部分组成：
  1. **官方服务插件** `chips.service.content-office`：内容处理能力提供方，登记 `content-office.convert`、`content-office.render-page`、`content-office.decrypt`、`content-office.font-metrics` 四项原子操作（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.4）；
  2. **官方应用插件** `chips.official.office`：办公四件套应用，声明格式文件关联与 `view` / `edit` 打开意图，承载界面与编辑会话（[官方插件与应用目录](./09-官方插件与应用目录.md) §7.2）。
- 普通文件不是文档：Office 文档不使用 `document:*` 链路，产物经受控提交；转换与预览编排归[文件处理契约](../05-接口与契约/15-文件处理契约.md)。
- 旧链路 `file.session.*`、`office.document.*`、`office.engine.*`、`office.crypto.decrypt` 一律作废，不提供兼容入口（[文件处理契约](../05-接口与契约/15-文件处理契约.md) §1.1、[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.4）。

### 4.2 能力与权限

- 提供方（`chips.service.content-office`）：
  - 不注册 Bridge 能力；能力经 Cordis 服务提供；权限映射为无（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.4）；
  - 实现内部如访问受保护对象，必须使用自身会话的 Bridge 能力与权限并在 manifest 声明，不得借用消费方权限（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.4、[权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §5.4）；
  - 重计算在工具进程内执行（[插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §5.2）。
- 应用（`chips.official.office`）Bridge 能力与权限（按最小权限声明，最终以插件清单为准）：

| 能力 | 权限 | 用途 |
|---|---|---|
| `resource:read` 与句柄 | `resources:read` | 读取打开目标；大文件用 `readRange()` / `stream()` |
| `resource:write` | `resources:write` | 写回工作区 / 临时作用域产物（受控提交路径） |
| `file:read` / `file:write` | `filesystem:read` / `filesystem:write[:<限定路径>]` | 经 `dialog:open` / `dialog:save` 授权的路径读写 |
| `file:copy` / `file:move` | `filesystem:read` + `filesystem:write` / `filesystem:write` | 另存与整理（按需） |
| `dialog:open` / `dialog:save` | `dialogs:use` | 打开、另存与导出目标选择 |
| `config:get` / `config:snapshot` / `config:set` / `config:reset` | 自身命名空间免权限 | 最近文件、视图偏好 |
| `window:create` / `window:setState` 等 | `window:control` | 多文档窗口与窗口状态（按需） |

- 免权限范围：插件私有数据目录、自身配置命名空间。

### 4.3 接口要点（打开与编辑会话）

打开：

- 一切打开经资源打开路由投递（文件关联、拖放、应用内打开、系统关联）；应用声明 `primary` 处理器，不硬编码其他插件 ID（[资源打开与默认处理器契约](../05-接口与契约/14-资源打开与默认处理器契约.md) §3、§4）。
- 目标读取：以顶层 `resourceOpen.uri` 为唯一读取入口；≤ 8 MiB 可一次性读取，大文件必须流式（[文件处理契约](../05-接口与契约/15-文件处理契约.md) §五）。
- 预览与转换：经 `file-processing` 会话（`preview` / `convert` / `saveAs`）编排，原子算法来自 `content-office.*`；应用不自行解包 OOXML、不实现第二套格式算法（[文件处理契约](../05-接口与契约/15-文件处理契约.md) §三、§四）。
- 加密容器的打开流程见 §4.4。

编辑会话（应用内）：

- 会话状态机：`opened`（只读装载完成）→ `editing`（可撤销 / 重做的内存模型）→ `saving`（受控提交中）→ `clean`（与来源一致）→ `closed`；来源版本戳变化时进入 `conflict`，拒绝静默覆盖并要求用户重新打开或另存。
- 写者唯一：同一来源同一时刻只允许一个编辑会话；编辑中间态不落盘、不写配置。
- 保存语义：
  - 保存（覆盖来源）需显式用户手势；产物经受控提交（临时文件 + 原子替换），默认不覆盖既有目标；覆盖失败保留原文件、不产生半写产物（[文件处理契约](../05-接口与契约/15-文件处理契约.md) §4.3）；
  - 另存为经 `dialog:save` 选择目标；PDF 导出与打印由应用内 PDF 导出能力与浏览器打印链路承担（[官方应用功能总览](../08-产品与交互/08-官方应用功能总览.md) §七）；
  - 不使用 `document:*`；不新增写口、不绕过受控提交。
- 字体度量：排版度量经 `content-office.font-metrics`；浏览器侧字体度量近似只作为应用内排版启发式，不另立服务契约。
- 未保存编辑状态的崩溃恢复副本落插件私有数据目录，带格式版本字段与校验信息，不写回来源文件；来源始终是唯一事实源。

### 4.4 加密容器

- 探测：打开阶段识别加密容器（如加密 OOXML、受口令保护的归档），不尝试猜测口令、不静默失败。
- 解密：用户经应用内口令 UI 提供口令后，经 `content-office.decrypt` 解密（输入文档字节与口令，输出解密后的文档字节）；口令只在单次调用内使用，不写入配置、日志、审计与错误 `details`（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.6）。
- 编辑与保存：解密后进入正常编辑会话；保存产物是解密后的普通文档：
  - 默认另存为新文件，不覆盖加密原件；
  - 覆盖原件需显式确认；本设计不提供重新加密能力（`content-office` 不登记加密操作），提示用户产物为未加密副本。
- 失败：口令错误或加密方案不受支持返回 `OFFICE_DECRYPT_FAILED` / `OFFICE_INPUT_UNSUPPORTED`，停留在打开态，不产生半开会话。

### 4.5 xlsx 引擎形态与 IPC

- **形态**：xlsx 引擎（calamine 解析 + ironcalc 重算）编译为平台原生二进制，作为**平台引擎**随平台编译与分发，位于平台引擎目录（`resources/engines/xlsx-sidecar/<platform>-<arch>/`），不进任何 `.cpk`（R11；[第三方参考资产清单](../02-开发规范/11-第三方参考资产清单.md) RA-04）。
- **进程与调度**：引擎进程由壳创建与管理、内核按需调度（与工具进程同级的受控进程形态；[插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §5.2、[跨端 Shell 与平台抽象设计](../01-架构设计/01-子系统设计/17-跨端Shell与平台抽象设计.md) §2.3）；按需启动、空闲回收、崩溃自动重建。插件与服务提供方不得创建、持有、发现或直连该进程。
- **访问路径**：`chips.service.content-office`（在工具进程执行）经内核提供的平台引擎端口访问引擎；端口对插件只暴露类型化命令与 `AbortSignal` 语义，由内核完成请求关联、超时、取消与崩溃恢复。外部只经 `content-office.*` Cordis 服务消费，不感知端口与进程存在。
- **IPC 协议（平台内部）**：
  - stdio JSON Lines；请求 `{ version, requestId, command, ...参数 }`，响应 `{ version, requestId, ok, result?, error? }`；`version` 固定为 `1`，`requestId` 由端口生成并用于关联；错误体为 `{ code, message }`；
  - 命令集（按提供方能力需要）：`open`（载入工作簿建立引擎会话）、`readRange`（工作表区间读取）、`readFormulaCells`（公式单元格读取）、`recalcCells`（编辑后重算）、`saveArchive`（归档条目替换 / 删除 / 新增与重组）、`convertWorkbook`（工作簿转换）、`cancel`、`close`；
  - 控制面只传结构化参数与平台临时引用；工作簿字节与归档条目经平台临时作用域的受控文件交换，产物经受控提交发布，不在 IPC 内联大段二进制（[文件处理契约](../05-接口与契约/15-文件处理契约.md) §4.3、§五）；
  - 超时基线：打开类命令 120s、常规命令 30s、取消命令 5s；超时由端口返回 `OFFICE_ENGINE_TIMEOUT` 并发起取消；
  - 容错：进程崩溃或重启时在途请求以 `OFFICE_ENGINE_UNAVAILABLE` 失败；引擎会话丢失返回 `OFFICE_ENGINE_SESSION_LOST`，由应用重新 `open`，不提供跨重启的引擎会话恢复。
- **平台目标**：桌面端 macOS（arm64 / x64）随平台首批分发；Windows / Linux 在对应平台构建后随平台版本分发；移动端（Phase 5）引擎载体由壳实现决定（[第三方参考资产清单](../02-开发规范/11-第三方参考资产清单.md) RA-04、[跨端 Shell 与平台抽象设计](../01-架构设计/01-子系统设计/17-跨端Shell与平台抽象设计.md) §六）。

### 4.6 错误码

| 错误码 | 归属 | 场景 | retryable |
|---|---|---|---|
| `OFFICE_INPUT_UNSUPPORTED` | 提供方 | 输入格式或加密方案不受支持 | false |
| `OFFICE_DECRYPT_FAILED` | 提供方 | 口令错误或解密失败（`details` 不含口令） | false |
| `OFFICE_CONVERT_FAILED` | 提供方 | 格式转换失败 | true |
| `OFFICE_RENDER_FAILED` | 提供方 | 页面渲染失败 | true |
| `OFFICE_ENGINE_UNAVAILABLE` | 提供方 | 平台引擎不可用或崩溃重建中 | true |
| `OFFICE_ENGINE_SESSION_LOST` | 提供方 | 引擎会话丢失，需重新打开 | false |
| `OFFICE_ENGINE_TIMEOUT` | 平台引擎端口 | 引擎命令超时 | true |

- 提供方域族与代表码以[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.6 为权威；`OFFICE_ENGINE_*` 为平台引擎形态新增码，随提供方契约发布；`FONT_*` 族由 `content-office.font-metrics` 使用。
- 经文件处理编排消费时按[文件处理契约](../05-接口与契约/15-文件处理契约.md) §6.3 归一为 `FILE_PROCESS_TRANSFORM_FAILED` / `FILE_PROCESS_PREVIEW_FAILED`，原始码进 `details.cause`。
- 应用侧平台错误保持原码：`RESOURCE_*`、`FILE_*`、`FILE_PROCESS_*`、`DIALOG_FAILED`、`APP_OPEN_FILE_FAILED`。

### 4.7 实现形态

- 提供方：官方服务插件 `chips.service.content-office`（`service` 角色，无 UI，重计算在工具进程），随平台与官方插件分发；同一服务名唯一，替换实现须经平台评审（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.7）。
- 消费者：官方应用插件 `chips.official.office`（`app` 角色）；应用与提供方经 manifest `dependencies` 静态依赖与 `ctx.inject` 组合，不互相 `import`。
- 平台引擎：xlsx 引擎为平台资产（[第三方参考资产清单](../02-开发规范/11-第三方参考资产清单.md) RA-04 处置：源码移植、由平台编译分发），与插件包解耦；引擎协议是平台内部实现，不构成公共契约。

### 4.8 依赖与阶段

- 依赖：能力契约规范 §八（服务与能力登记）、文件处理契约（会话与编排）、资源打开与默认处理器契约（路由与意图）、资源协议规范（句柄与受控提交）、插件架构设计（工具进程）、跨端 Shell 与平台抽象设计（平台引擎载体）、第三方参考资产清单 RA-04（许可与平台目标）。
- 阶段：内容处理服务机制与工具进程属 Phase 2；`content-office` 提供方、xlsx 引擎与 `chips.official.office` 应用属 Phase 3；Windows / Linux 引擎构建随 Phase 4 三端验证（[开发流程与阶段计划](../07-工程管理/02-开发流程与阶段计划.md) §五、§六、§七）。

## 五、OCR 服务（明确不提供）

### 5.1 定位

- **OCR 不提供**：扫描件与图片的文字识别不登记内容处理能力、不设服务插件、不进入能力契约 §八 登记表（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.4）。
- 依据：宿主级 OCR 依赖操作系统能力，跨端不可用、不可随平台分发；引入第三方 OCR 运行时涉及体积、许可证与端侧隐私评估，未通过技术选型；本轮正式裁决为不提供（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.4）。
- 该结论是正式设计决策，不是占位：任何插件不得内置 OCR 替代实现、不得调用系统 OCR 绕过（R11、R17）。

### 5.2 能力与权限

- 无能力登记、无权限映射、无服务名。消费方不得声明或调用任何 OCR 相关 ID（未登记 ID 一律无效）。

### 5.3 接口要点

- 消费方（Office 应用、万能文件查看器、卡片编辑态等）对扫描件文字识别的请求按**不支持**语义收口：
  - 打开扫描 PDF 时正常呈现页面，不承诺文字层；用户触发文字识别时给出明确错误态，不静默失败、不降级为图片转写；
  - 经文件处理编排的识别请求返回 `FILE_PROCESS_SOURCE_UNSUPPORTED` / `FILE_PROCESS_TARGET_UNSUPPORTED`（[文件处理契约](../05-接口与契约/15-文件处理契约.md) §6.2）；
  - 直接调用场景不存在（无能注册）。
- 文档链路不受影响：`.card` / `.box` 的文字内容与 OCR 无关（R8）。

### 5.4 错误码

- 不新增 `OCR_*` 错误码（避免暗示能力存在）；统一复用：
  - 编排路径：`FILE_PROCESS_SOURCE_UNSUPPORTED`（来源需要 OCR 才能完成请求的操作）、`FILE_PROCESS_TARGET_UNSUPPORTED`（目标需要 OCR 产物）；
  - 应用直接呈现：平台错误态 + 应用域提示，不映射为已登记业务码。

### 5.5 实现形态

- 无实现形态。如未来确需提供，必须完整走：技术选型评估（[架构原则](../00-愿景与原则/01-架构原则.md) §三）→ RFC 与评审（[能力契约规范](../05-接口与契约/04-能力契约规范.md) §8.7）→ 登记内容处理能力（`content-ocr` 服务名与能力 ID）→ 按服务插件形态实现并在[官方插件与应用目录](./09-官方插件与应用目录.md) 登记。既有裁决在新能力登记前持续有效。

### 5.6 依赖与阶段

- 无依赖；不进入任何 Phase 的交付范围，Phase 5 移动端同样不引入（[跨端 Shell 与平台抽象设计](../01-架构设计/01-子系统设计/17-跨端Shell与平台抽象设计.md) §六）。

## 六、约束与不变量

1. **单一事实源**：能力 ID、服务名与描述符只在[能力契约规范](../05-接口与契约/04-能力契约规范.md) §八登记；插件 ID 只在[官方插件与应用目录](./09-官方插件与应用目录.md) 登记；本文只做设计决策，出现重复定义时以登记处为准。
2. **不建第二链路**：四项设计均不新增 Bridge 能力、不新增解析器、不新增渲染管线、不新增文档写口。
3. **不解文档**：本文涉及的应用不解析 `.card` / `.box`；载荷消费以资源打开路由交付的受管引用为唯一读取入口。
4. **最小权限**：应用只声明实际使用的能力与权限；`service` 不申请 app 类权限；免权限范围不扩展。
5. **状态分层**：高频状态（阅读位置、播放进度、编辑中间态）不入配置；跨会话状态落插件私有数据目录；偏好落自身配置命名空间；全部写入采用临时文件 + 原子替换并带版本字段。
6. **不物化原生载荷**：xlsx 引擎是平台资产，插件包不含原生可执行载荷；引擎进程只由壳创建、内核调度，插件不得创建子进程（R11、R17）。
7. **不提供即不替代**：OCR 的"不提供"是正式裁决；不得以系统工具、在线接口或私有算法兜底。
8. **无兼容包袱**：`file.session.*`、`office.document.*`、`office.engine.*`、`file.convert.*`、`converter.*`、`image.color.pick`、`chips.module.*` 等旧链路标识一律不进入新架构（[ADR-010](../01-架构设计/ADR/ADR-010-大爆炸重构策略.md)）。

## 七、自检清单

- [ ] 四项设计是否各自只落在一种形态（应用内引擎 / 应用插件 / 服务插件 + 平台引擎 / 明确不提供）？
- [ ] 是否没有新增未登记的 Bridge 能力、权限 ID、服务名与插件 ID？
- [ ] 电子书引擎是否只消费 `resourceOpen` / `chips.book-card` 载荷，未解析卡片包？
- [ ] 阅读 / 播放 / 编辑状态是否按"内存 / 私有数据目录 / 配置"三层落位，未出现高频 `config:set`？
- [ ] 媒体消费是否以载荷与卡片 schema 为唯一字段来源，未在播放器中复制格式算法？
- [ ] Office 打开与保存是否经受控提交，未使用 `document:*`、未直接写路径、未产生半写产物？
- [ ] 加密容器流程是否保证口令不落配置、日志、审计与错误 `details`？
- [ ] xlsx 引擎是否保持平台资产与平台进程形态，未进入 `.cpk`、未被插件直连？
- [ ] OCR 是否维持"明确不提供"，消费方按不支持语义收口且无临时替代？
- [ ] 所有链接指向真实文件（链接检查 0 坏链）？
