## 十三、约束与自检清单

### 13.1 强制规则

- 一个应用插件只有一个角色 `app`；需要多角色能力时拆分并用 `dependencies` 组合。
- 入口模块默认导出实现 `IAppPlugin` 的对象；模块顶层不产生副作用，启动逻辑全部在 `launch` 中。
- 主逻辑只经 `IAppContext` 访问平台；UI 只经 `chips` 访问平台；窗口只使用平台表面与 `window:*` 能力。
- 配置只经 `ctx.config` 与 `config:*` 能力读写，禁止直接读写配置文件。
- 标准事件的订阅必须可撤销；UI 组件卸载时必须 `dispose()` 订阅句柄。
- 文件、配置、剪贴板等访问所需权限已在 manifest 中按最小范围声明。
- `beforeExit` 只做保存与刷新，不假设可以取消退出。

### 13.2 禁止事项

- 禁止在模块顶层创建窗口、读取配置或执行业务逻辑。
- 禁止跨实例复用 `IAppContext` / `IAppWindow`；实例退出后必须丢弃引用。
- 禁止把包内相对路径、裸绝对路径或远程 URL 传给 `openFile`。
- 禁止直接访问 Node.js / Electron / 系统 API，禁止直接创建系统窗口。
- 禁止用事件模拟请求-响应；禁止发明未登记的 `APP_*` 错误码。
- 禁止从 `antd`、`@chips/antd`、`@mui/*`、`@chakra-ui/*` 导入组件或样式。

### 13.3 自检清单

- [ ] `manifest.type` 为 `app`，`ui.surface` 取值合法，`ui.launcher` 字段完整，图标位于 `assets/` 内。
- [ ] `launch` 处理了 `ctx.args` 的全部三种来源与不变量。
- [ ] `handleCommand` / `openFile` 的未知输入返回结构化错误，未做静默忽略。
- [ ] `beforeExit` 已释放实例级资源与订阅。
- [ ] 主逻辑与 UI 的事件、配置访问分别使用 `IAppContext` 访问面与 `chips`，订阅均可撤销。
- [ ] UI 只从 `@chips/ui` 导入组件与令牌，样式无硬编码，文案为简体中文直写。
- [ ] 构建产物为 `dist/index.js` 与 `render.js`，`render.js` 未内联 React 与 `@chips/ui`。
