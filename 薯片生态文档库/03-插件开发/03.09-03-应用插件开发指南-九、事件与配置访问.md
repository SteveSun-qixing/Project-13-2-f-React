> 适用范围：面向任务的 `app` 角色插件开发教程：从 manifest、主逻辑、命令与文件关联到 React + `@chips/ui` 界面接入，并给出一个可运行的最小应用插件完整示例。

## 九、事件与配置访问

### 9.1 两条代码路径

应用插件的主逻辑运行在平台主进程，UI 运行在应用窗口渲染进程，两者不共享内存，各自访问平台：

| 事项 | 主逻辑（主进程） | UI（渲染进程） |
|---|---|---|
| 入口接口 | `IAppPlugin` + `IAppContext` | React 组件 + `chips` |
| 能力调用 | `ctx.bridge.request<T>(id, input)` | `chips.request<T>(id, input)` |
| 事件订阅 | `ctx.on` / `ctx.once` | `chips.subscribe`（返回 `ISubscription`，必须 `dispose()`） |
| 事件发布 | `ctx.emit`（自有域，不跨进程） | `chips.request('event:publish', ...)`（受白名单与权限约束） |
| 配置读写 | `ctx.config.*`（相对键） | `chips.request('config:get' \| 'config:set', { namespace, key, ... })` |
| 服务注入 | `ctx.inject(dependencies, callback)` | 不适用 |

协作规则：UI 自行读取配置并订阅 `config:changed` 刷新，不依赖主逻辑转发；插件自有域事件不跨进程，主逻辑与 UI 之间的协作使用配置、标准事件或文档链路；两条路径最终进入同一条 Bridge 链路，权限判定、Schema 校验与审计一致。

### 9.2 主逻辑：事件与配置

订阅内核事件，句柄随实例退出自动撤销；需要提前撤销时保存返回的句柄调用 `subscription.dispose()`：

```typescript
interface IWindowClosedPayload {
  readonly windowId: number;
}

ctx.on<IWindowClosedPayload>('window:closed', (payload) => {
  void refresh(payload.windowId);
});
```

配置访问使用相对键，`set` 只写入 `user` 或 `workspace` 层：

```typescript
const view = await ctx.config.get('title');
const snapshot = await ctx.config.snapshot();
await ctx.config.set('title', '随手记', 'user');
await ctx.config.reset(['title'], 'user');
void view;
void snapshot;
```

主逻辑调用能力：

```typescript
const input: CapabilityInput<'file:read'> = {
  path: '${userDocuments}/随手记.txt',
  encoding: 'utf-8',
};
const output: CapabilityOutput<'file:read'> = await ctx.bridge.request<
  CapabilityOutput<'file:read'>
>('file:read', input);
void output;
```

上述调用需在 manifest 申请 `filesystem:read:${userDocuments}` 并获授权，否则返回 `BRIDGE_PERMISSION_DENIED`。访问 `platform` 命名空间配置不走 `ctx.config`，改经 `ctx.bridge.request('config:get' | 'config:set', { namespace: 'platform', ... })` 并持带命名空间限定值的 `config:read` / `config:write`。

### 9.3 UI：事件与配置

UI 没有 `ctx`，事件与配置一律经 `chips`：

```typescript
chips.subscribe('config:changed', (payload) => {
  if (isShowCountChange(payload) && typeof payload.effectiveValue === 'boolean') {
    setShowCount(payload.effectiveValue);
  }
});
```

```typescript
const input: CapabilityInput<'config:get'> = {
  namespace: 'plugins.chips.example.quick-notes',
  key: 'show-count',
};
const view: CapabilityOutput<'config:get'> = await chips.request<
  CapabilityOutput<'config:get'>
>('config:get', input);
setShowCount(view.value !== false);
```

规则：

- 组件卸载或窗口关闭时必须 `dispose()` 订阅句柄；会话销毁时 Bridge 兜底清理，但不得依赖兜底。
- UI 订阅 `config:changed` 时收到的 `key` 是完整键（`plugins.<appId>.<相对键>`），响应以 `effectiveValue` 为准。
- 高频事件必须限流处理；事件只做通知，不承担请求-响应语义。

### 9.4 常见规则

- 主逻辑的全部平台访问只经 `IAppContext` 访问面；不得访问全局对象、平台内部状态或 Node.js / Electron API。
- 主逻辑的订阅、注入与清理随实例退出自动撤销；平台未内建追踪的清理（如定时器）用 `ctx.effect(cleanup)` 登记。
- 插件不得依赖进程存活期的手工回收；`ctx.emit` 的自有域事件默认不跨进程。
