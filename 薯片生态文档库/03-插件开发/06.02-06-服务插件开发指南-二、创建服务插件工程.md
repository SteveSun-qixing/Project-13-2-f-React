## 二、创建服务插件工程

### 2.1 目录结构

```text
chips.service.translate/
├── manifest.yaml          # 包根唯一权威清单
├── assets/
│   └── schemas/
│       └── config.schema.json  # 自身配置的默认值与校验（使用 ctx.config 时提供）
├── src/
│   └── index.ts           # 入口模块；构建后成为包内入口
└── package.json           # 工程与构建脚本（脚手架生成，version 与 manifest 一致）
```

| 组成 | 作用 | 权威 |
|---|---|---|
| `manifest.yaml` | 标识、版本、角色、依赖、权限、后台与健康检查声明 | [02-插件清单规范](./02-插件清单规范.md) |
| 入口模块 | 实现 `IServicePlugin` 的 JavaScript 代码 | E10 第二节 |
| `assets/schemas/config.schema.json` | 配置默认值、结构与范围约束 | [10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) |
| 静态资源 | 无 UI 角色仅保留必要资源；`service` 包内不得出现 UI 资源与 `render.js` | [03-插件包格式](../04-文件格式规范/03-插件包格式.md) |

- 开发态目录结构必须与 `.cpk` 解包后的包根一致；打包与发布见[03-插件包格式](../04-文件格式规范/03-插件包格式.md)与[07-调试与发布](./07-调试与发布.md)。

### 2.2 manifest 角色字段

服务插件的最小清单骨架：

```yaml
id: chips.service.translate
version: 1.0.0
type: service
name: 翻译服务
description: 经平台网络能力调用远端翻译接口的已登记能力 translate:run
author: 薯片官方
license: MIT
runtime:
  targets: [host]
  background: true
healthCheck:
  interval: 30s
  timeout: 5s
permissions:
  - network:http:api.example.com
```

规则：

1. `type` 必须为 `service`；一个插件只有一个角色（R1）。
2. `runtime.targets` 必须包含 `host`；平台不提供 `web` 目标（E10 7.2）。
3. `runtime.background` 为可选字段（缺省 `false`）；`true` 仅 `service` 可声明，其它角色声明按清单校验失败处理。
4. `healthCheck` 仅 `service` 可声明；声明后必须实现 `health()`，否则启用校验失败、插件不得进入 `active`（E10 5.1）。
5. `permissions` 是插件自身的申请集合：只声明出站能力调用所需权限（如 `filesystem:read`）；日志免权限（R19），不在 `permissions` 中声明。
6. 服务插件不得声明 `ui`、`capabilities.cardTypes`、`capabilities.layouts`；字段级规则见[02-插件清单规范](./02-插件清单规范.md) 7.5、9.2。

### 2.3 assets/schemas/config.schema.json

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "翻译服务配置",
  "x-chips-schema-version": 1,
  "type": "object",
  "additionalProperties": false,
  "properties": {
    "target-language": {
      "type": "string",
      "pattern": "^[a-z]{2}(-[A-Za-z]{2})?$",
      "default": "zh-CN",
      "title": "默认目标语言"
    }
  }
}
```

- 顶层必须为 `object` 且显式 `additionalProperties: false`；默认值只作注解，不落盘，由平台在读取时合并（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md)）。
- 配置的读取、监听与写入层级见本文第八节；无配置的服务插件可以不提供本文件。
