## 八、资源访问

所有资源访问统一经 `chips-resource://`，受限、可审计；完整 URI 语法、作用域、权限与错误码以[06-资源协议规范](../05-接口与契约/06-资源协议规范.md)为准。插件只使用以下两条正式路径。

### 8.1 两条正式路径

| 路径 | 使用位置 | 适用场景 |
|---|---|---|
| 协议路径 | 渲染帧内的 DOM 引用（`src` / `href` / `url()`） | 纯呈现：图片、媒体、字体、样式 |
| 句柄路径 | 就近渲染容器与宿主侧代码（`window.chips.resource(uri)`） | 需要元数据、字节读取或失效感知 |

协议路径：帧初始化时注入 `<base href="{resourceBase}">`，`card.content` 中的包内相对引用（相对包根）可直接用于 DOM；也可使用 `chips-resource://` 绝对 URI。帧内 `connect-src 'none'`，不提供字节读取接口，也不发起网络请求。

### 8.2 引用形式与卡片形态

R13 允许的引用形式为包内相对路径（相对包根）、`file://`、`http(s)://`、`webdav://` 与 `chips-resource://`；进入运行时后全部归一为受管作用域 URI，经 `chips-resource://` 与资源管理器访问（[06-资源协议规范](../05-接口与契约/06-资源协议规范.md) §3.3）。完整离线卡片使用包内相对路径 + ZIP 内资源；网络资源卡片使用对象存储 / CDN URL + 外部资源。所有基础卡片插件必须正式支持 URL 资源，不得把 URL 当作临时补丁。

```yaml
# 完整离线卡片：包内相对路径
video_file: "travel/demo-video.mp4"

# 网络资源卡片：对象存储 / CDN URL
url: "https://file.example/chips-card-resources/cards/a1B2c3D4e5/video.mp4"
```

禁止把运行时 `blob:`、`data:`、系统绝对路径或 `file://` 写回内容配置；资源缺失时按占位呈现并允许重新绑定，不得让卡片无法打开。

### 8.3 句柄规则

1. 句柄只读、不可序列化、不可持久化、不可跨窗口或跨会话传递；`release()` 幂等。
2. 小资源（≤ 8 MiB）用 `read()`；大资源用 `readRange()` 或 `stream()`，越限返回 `RESOURCE_TOO_LARGE`。
3. 作用域 ID 由平台分配，插件不得构造、猜测或伪造；引用只允许来自卡片数据或调用方提供的解析结果。
4. 句柄与资源会话绑定：会话关闭、插件停用、权限撤销时失效；插件必须在 `dispose()` 中 `release()` 全部句柄并退订 `onInvalidate`。
5. 跨作用域访问默认拒绝，需 `resources:read:<scope>` 授权；写入一律要求 `resources:write`，经受控提交接口执行。

### 8.4 禁止清单

| 禁止 | 说明 |
|---|---|
| 帧内访问 `window.chips` | 帧内一律经帧协议；`window.chips` 仅就近渲染容器可用 |
| `fetch` / XHR 直连 | 帧内被 CSP 阻断；宿主侧必须经资源协议 |
| 裸绝对路径与运行时 `file://` 直载 | 违反 R13、R17；`file://` 仅目录态引用，运行前由平台归一 |
| 访问自身作用域外的资源 | 默认拒绝，需显式授权 |
