## 三、项目结构

应用插件的源码目录（构建后打包为单个 `.cpk`）：

```
chips.example.quick-notes/
├── manifest.yaml            # 唯一权威清单，打包后位于包根
├── config.schema.json       # 插件配置 schema 与默认值
├── package.json             # 工作区包清单（private）
├── assets/
│   └── icons/
│       └── app.svg          # 启动器图标（manifest 引用）
└── src/
    ├── index.ts             # 主逻辑（构建为 dist/index.js）
    └── ui/
        └── AppView.tsx      # 应用窗口界面（构建为 render.js）
```

应用插件有两个入口模块，职责与运行位置不同：

| 入口 | 源码 | 构建产物 | 运行位置 | 职责 |
|---|---|---|---|---|
| 主逻辑入口 | `src/index.ts` | `dist/index.js` | 平台主进程（Cordis 承载） | 默认导出实现 `IAppPlugin` 的对象：`launch` / `handleCommand` / `openFile` |
| 渲染入口 | `src/ui/AppView.tsx` | `render.js` | 应用窗口渲染进程 | 默认导出应用窗口 UI 组件；只提供 ESM 模块，宿主文档由平台提供，但 UI 根环境（`ChipsProvider` 主题根、按需的 `CommandProvider`）由该默认导出组件自行挂载一次，平台窗口壳不提供（[08-@chips/ui 共享层使用指南](../02-开发规范/08-@chips-ui共享层使用指南.md) §3.1，工单 002 收口口径） |

规则：

- 两个入口都必须是 UTF-8 文本 ESM 模块；入口形状与角色接口一一对应（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §2.4）。
- 模块顶层只允许声明，不得产生副作用：订阅、定时器、文件访问、窗口操作全部放入 `launch`。
- `render.js` 必须外部化平台共享依赖（React、`@chips/ui`），不得内联第二套组件库（R4）。
- 包内不得出现 `.html`、源码、测试与映射文件；包根白名单与校验清单见 [03-插件包格式](../04-文件格式规范/03-插件包格式.md) §2。
