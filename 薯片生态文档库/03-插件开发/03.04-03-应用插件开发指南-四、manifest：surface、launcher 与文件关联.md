## 四、manifest：surface、launcher 与文件关联

### 4.1 应用插件清单片段

```yaml
id: chips.example.quick-notes
version: 1.0.0
type: app
name: 随手记
description: 随手记录并管理简短事项
author: 薯片示例
license: MIT
runtime:
  targets: [host]        # 仅 host；平台不提供 web 目标
  background: false      # 可选，缺省 false；仅 service 可为 true
permissions:
  - clipboard:access     # 只申请实际使用的权限
fileAssociations:
  - extensions: [.txt, .md]
    action: open
ui:
  surface: window        # window | desktop | tray
  launcher:
    icon: assets/icons/app.svg
    name: 随手记
    description: 随手记录并管理简短事项
```

清单全字段与校验规则见 [02-插件清单规范](02-插件清单规范.md)；插件 ID 使用反向域名，版本使用语义化版本。

### 4.2 ui.surface

`app` 必须声明 `ui` 与 `ui.surface`；`ui.surface` 决定应用主窗口的形态，也决定 `ctx.window` 的取值：

| 值 | 语义 | `ctx.window` | 关闭主窗口的行为 |
|---|---|---|---|
| `window` | 标准窗口应用 | `IAppWindow` | `runtime.background` 为 `false` 时触发实例退出；为 `true` 时保持运行 |
| `desktop` | 桌面层应用 | `IAppWindow` | 不触发实例退出；实例由 `exit()` 或平台动作结束 |
| `tray` | 托盘应用 | `null` | 不适用；应用按需经 `window:create` 能力创建窗口 |

规则：

- 表面窗口由平台在启动时按 manifest 创建，插件不得创建原始系统窗口；额外窗口一律经 `window:create` 能力（需 `window:control` 权限，仅 `app` 可申请）。
- 窗口按 R17 安全基线创建：`nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`。
- `tray` 表面的主逻辑应能容忍 `ctx.window` 为 `null`，`desktop` 表面的 `setTitle` 调用被忽略。

### 4.3 ui.launcher

`ui.launcher` 声明启动器入口，字段均有缺省：

| 字段 | 类型 | 必需 | 缺省 |
|---|---|---|---|
| `name` | `string` | 否 | manifest `name` |
| `description` | `string` | 否 | manifest `description` |
| `icon` | `string` | 否 | 插件包默认图标 |

规则：

- 省略 `ui.launcher`：不注册启动器入口，应用只能经文件关联或命令启动，`ctx.launcher` 为 `null`。
- 声明 `ui.launcher`（含空对象）：注册启动器入口，缺省字段自动补齐，`ctx.launcher` 为补齐后的信息。
- `icon` 是包内相对路径，必须位于 `assets/` 内；运行时由平台解析为插件作用域资源（`chips-resource://<plugin-scope>/...`），插件不得自行拼接作用域 URI。

### 4.4 fileAssociations

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `extensions` | `string[]` | 是 | 扩展名列表，含点号、小写，如 `[.txt, .md]` |
| `action` | `'open'` | 是 | 当前唯一动作：以打开方式接收文件 |

规则：

- 声明即注册文件关联路由；同一扩展名存在多个声明方时，由平台按插件启用状态与用户选择路由。
- 文件关联只决定路由，不代表授权；应用读取文件内容仍需对应权限（第八节）。
- 未运行时打开文件以 `source: file-association` 启动实例；已运行时投递给 `openFile`。
- `fileAssociations` 对 `app` 与 `service` 可用。

### 4.5 权限

- manifest 的 `permissions` 是插件申请集合；能力声明自己需要的权限，Bridge 在调用时按两者交集判定（R3）。
- 最小权限：未使用的能力不申请。上例只使用 `clipboard:write`，因此只申请 `clipboard:access`。
- 需要读写用户文件时申请 `filesystem:read` / `filesystem:write`，路径限定值必须使用目录变量（如 `filesystem:read:${userDocuments}`），不得写裸绝对路径。
- 窗口、文件、配置访问所需权限的完整对照见 [04-能力契约规范](../05-接口与契约/04-能力契约规范.md) 与 [08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md)。
