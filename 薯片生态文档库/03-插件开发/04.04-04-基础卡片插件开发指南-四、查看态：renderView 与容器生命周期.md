## 四、查看态：renderView 与容器生命周期

### 4.1 调用与容器

```
平台创建渲染帧
  → renderView(basecard, container) 首次调用：同步提交首帧 DOM
  → 帧运行时上报 frame:ready / frame:height
  → 视图更新（revision 前进或 host:update）
  → renderView(basecard, container) 再次调用：覆盖式更新
  → 帧销毁：逆序执行各次调用返回的 Dispose
```

| 维度 | 查看态容器 |
|---|---|
| 提供方 | 渲染帧运行时为该节点创建的独立容器（容器与 `node_id` 一一对应） |
| 位置 | `sandbox="allow-scripts"` 的 iframe 内 |
| 宽度 | 由父帧容器决定，插件不得固定或改变 |
| 高度 | 帧运行时测量并上报，插件不得请求改变外层尺寸 |
| 样式 | 仅 `@chips/ui` 组件与 Design Tokens；禁止全局样式与第二套组件库 |
| 卸载 | 帧销毁时容器整体销毁 |

容器由平台所有、插件是租户：只在容器内创建 DOM，不得访问 `document.body`、`parent`、`top` 或其它帧。

### 4.2 更新与释放规则

1. 必须同步完成首次 DOM 提交；就绪信号由帧运行时上报，插件不触发。
2. 同一节点容器在帧存活期间可能被多次传入；每次调用都必须让容器呈现传入 `basecard` 的完整内容，不得叠加多份内容；禁止多节点共用容器。
3. 更新调用前，插件必须自行清理上一次调用创建的、生命周期短于帧的效果（React 根、事件监听、定时器、Observer、媒体播放）。
4. 返回的 `Dispose` 只负责本次调用建立的效果，必须幂等；帧运行时按调用顺序收集、逆序执行。
5. 视图只读：不得修改 `BaseCardView` 或 `content` 的值；读取 `content` 时必须做运行时收窄，字段缺失或类型异常时回退可读内容。
6. 不得读写存储、发起网络请求、访问 `window.chips`；这些都违反帧沙箱边界。

React 实现用「容器 → 当前挂载」映射在每次调用前释放上一轮挂载，保证覆盖式更新，并让返回的 `Dispose` 幂等；完整实现见 §9.6。

### 4.3 帧内禁止清单

| 禁止 | 原因 |
|---|---|
| 访问 `window.chips` | 帧内一律经帧协议转发（`frame:action`），由 RenderHost 判定权限 |
| 访问 `parent` / `top` / `document.body` | 破坏沙箱边界 |
| 读写 `localStorage` / `indexedDB` | 帧内不提供存储能力 |
| `fetch` / XHR 直连 | 帧内 `connect-src 'none'`，外部资源统一经资源代理 |
| 固定容器宽度或改变外层尺寸 | 高度与位姿由渲染引擎统一管理 |
| 在 `renderView` 内做重计算或字节解析 | 需要预处理的内容在编辑侧或服务侧完成 |
