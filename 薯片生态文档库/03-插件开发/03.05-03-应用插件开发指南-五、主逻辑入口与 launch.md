## 五、主逻辑入口与 launch

### 5.1 入口约定

`src/index.ts` 默认导出一个实现 `IAppPlugin` 的对象；`IAppPlugin` 只有三个方法。最小骨架如下，完整实现见第十一节：

| 方法 | 必需 | 调用时机 |
|---|---|---|
| `launch(ctx)` | 是 | 应用实例创建时，每个实例恰好一次 |
| `handleCommand(command, args)` | 否 | 实例 `active` 且收到运行中命令 |
| `openFile(uri)` | 否 | 实例 `active` 且收到运行中文件打开请求 |

```typescript
import type { IAppContext, IAppPlugin } from '@chips/sdk';

class QuickNotesApp implements IAppPlugin {
  public async launch(ctx: IAppContext): Promise<void> {
    if (ctx.window !== null) {
      await ctx.window.setTitle('随手记');
    }
  }
}

export default new QuickNotesApp();
```

平台在启动实例时调用 `launch(ctx)`；`handleCommand` / `openFile` 不接收上下文，需要通过 `launch` 保存的 `IAppContext` 引用访问实例面。

### 5.2 launch 语义

- `launch` 在平台创建表面（主窗口或托盘入口）之后调用；resolve 表示启动完成，实例进入 `active`，平台发布 `app:launched`。
- `launch` 抛出或拒绝即启动失败：平台关闭窗口、回收实例副作用，返回 `APP_LAUNCH_FAILED`，不发布 `app:launched`。
- `launch` 中不得执行长时间阻塞操作；耗时初始化交后台任务，就绪后经事件或配置通知 UI。
- `launch` 必须处理 `ctx.args`（启动意图的完整载体）；运行中到达的意图不再回放给 `launch`。
- 窗口内容由 UI（渲染进程）负责，`launch` 不直接操作 DOM。

### 5.3 IAppLaunchArgs 与启动来源

`ctx.args` 描述本次启动：`source` 为 `launcher` / `file-association` / `command` / `deep-link`，并携带对应数据。

| `source` | `files` | 其他字段 | 启动时应用要做的 |
|---|---|---|---|
| `launcher` | 空数组 | 不出现 | 初始化界面与状态 |
| `file-association` | 1 个及以上 | 不出现 | 在 `launch` 中处理全部初始文件；平台不会额外调用 `openFile` |
| `command` | 空数组 | `command` 必有，`commandArgs` 可选 | 在 `launch` 中处理初始命令；平台不会额外调用 `handleCommand` |
| `deep-link` | 空数组 | `url` 必有 | 在 `launch` 中处理深链接 URL |

`launch` 对三种来源的处理示例：

```typescript
public async launch(ctx: IAppContext): Promise<void> {
  this.context = ctx;

  this.titleSubscription = ctx.config.watch(CONFIG_KEY, (change) => {
    if (typeof change.effectiveValue === 'string') {
      void this.applyTitle(change.effectiveValue);
    }
  });

  await this.applyConfiguredTitle();

  if (ctx.args.source === 'file-association') {
    for (const uri of ctx.args.files) {
      await this.openFile(uri);
    }
  }

  if (ctx.args.source === 'command' && ctx.args.command !== undefined) {
    await this.handleCommand(ctx.args.command, ctx.args.commandArgs);
  }

  ctx.lifecycle.beforeExit(() => {
    this.titleSubscription?.dispose();
    this.titleSubscription = null;
    this.context = null;
  });
}
```

### 5.4 实例状态

平台为每个应用实例维护状态，插件不感知也不持久化：

| 状态 | 含义 | 命令 / 文件投递 |
|---|---|---|
| `launching` | `launch` 执行中 | 排队，`active` 后投递 |
| `active` | 可用 | 正常投递 |
| `exiting` | 退出流程执行中 | 拒绝，返回 `APP_STATE_INVALID` |

同一插件代际在同一时刻至多一个应用实例；重复启动不创建第二个实例：启动器请求聚焦已有窗口，文件与命令投递给运行中实例。
