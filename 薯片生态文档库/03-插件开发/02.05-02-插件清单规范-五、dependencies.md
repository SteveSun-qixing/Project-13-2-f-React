## 五、dependencies

### 5.1 结构与规则

```yaml
dependencies:
  - id: chips.service.markdown
    version: "^1.0.0"
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `id` | 是 | 被依赖插件的 `id`；不得指向插件自身 |
| `version` | 是 | 语义化版本范围（第 5.2 节） |

- 可选字段；省略等价无依赖。
- 只声明**直接依赖**，不声明传递依赖；传递关系由解析器推导（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 7.1）。
- 同一插件重复声明同一 `id` 直接拒绝（`KERNEL_DEPENDENCY_DUPLICATE`）。
- 依赖目标可以是任意角色；消费其它插件提供的服务时，必须在清单声明提供方插件，并用 `ctx.inject` 表达服务注入。
- 依赖缺失或版本不满足不阻止安装，只在启用时阻塞：插件转入 `pending`，依赖就绪后自动继续激活。
- 每项只允许 `id` 与 `version` 两个键；出现其它键时 `CPK_MANIFEST_INVALID`。

### 5.2 版本范围

`version` 是语义化版本范围；语法、运算符与匹配规则以[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) 第四节为唯一权威。常用写法：

| 写法 | 匹配范围 |
|---|---|
| `^1.2.3` | `>=1.2.3 <2.0.0`；`^0.2.3` 为 `>=0.2.3 <0.3.0`，`^0.0.3` 为 `>=0.0.3 <0.0.4` |
| `~1.2.3` | `>=1.2.3 <1.3.0` |
| `1.2.3`、`=1.2.3` | 精确匹配 `1.2.3` |
| `>=1.0.0 <2.0.0` | 同时满足两个比较项（逻辑与） |
| `^1.0.0 \|\| ^2.0.0` | 满足任一范围（逻辑或） |
| `*` | 任意非预发布版本 |

规则：

1. 预发布版本默认不匹配任何范围，除非范围自身显式包含相同 `MAJOR.MINOR.PATCH` 的预发布标识。
2. 禁止未定义写法（如 `latest`、`~>`、`workspace:*`、区间连字符）；语法非法在安装校验阶段判定为 `CPK_MANIFEST_INVALID`，在依赖解析阶段判定为 `KERNEL_DEPENDENCY_VERSION`。
3. YAML 中含 `>`、`<`、`|`、`*` 的范围必须加引号，例如 `">=1.0.0 <2.0.0"`、`"^1.0.0 || ^2.0.0"`。
4. 平台同一插件 ID 只保留一个已安装版本，范围判定针对该版本执行。

### 5.3 解析与失败语义

| 场景 | 结果 |
|---|---|
| 依赖成环 | 拒绝启用，返回 `KERNEL_DEPENDENCY_CYCLE` 并列出环路径 |
| 依赖不存在或未安装 | 插件保持 `pending`，记录 `KERNEL_DEPENDENCY_MISSING` |
| 已安装版本不在范围内 | 插件保持 `pending`，记录 `KERNEL_DEPENDENCY_VERSION` |
| 停用存在 `active` 依赖者的插件 | 默认拒绝（`KERNEL_DEPENDENCY_CONFLICT`）；显式级联时按逆拓扑序先停用依赖者 |
| 卸载存在依赖者的插件 | 始终拒绝（`KERNEL_DEPENDENCY_CONFLICT`） |
| 更新 | 新版本必须满足全部已安装依赖者的范围，否则拒绝并列出不满足者 |

- 单次批量启用按依赖拓扑序执行，被依赖者在前（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 第七节）。
