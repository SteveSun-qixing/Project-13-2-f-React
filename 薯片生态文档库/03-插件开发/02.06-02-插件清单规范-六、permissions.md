## 六、permissions

### 6.1 申请集合

- 字段为字符串数组，可省略（等价空集合）；元素为权限 ID（`<domain>:<scope>[:<qualifier>]`）。
- 语义：manifest 的 `permissions` 是**插件申请集合**，不是授权；安装阶段只记录申请集合，首次启用时由用户逐项确认。
- 运行时判定为三者交集：插件申请集合 ∩ 能力声明的权限 ∩ 会话快照（含限定值匹配）（R3、[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 11.1）。
- 依赖插件声明的权限不构成本插件的授权，也不得代为申请（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 5.1）。

### 6.2 权限词表与限定值

能力 → 权限的完整映射（R19）以[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) 6.2 为唯一权威；下表是 manifest 申请侧视图：

| 权限 ID | 限定值 | 适用角色 | 覆盖的能力 |
|---|---|---|---|
| `filesystem:read` | 路径模式（必需） | 全部 | `file:read` / `file:list` / `file:watch`；`file:copy` 源路径 |
| `filesystem:write` | 路径模式（必需） | 全部 | `file:write` / `file:move` / `file:mkdir`；`file:copy` 目标路径；`document:export` 目标路径 |
| `filesystem:delete` | 路径模式（必需） | 全部 | `file:delete` |
| `resources:read` | 作用域模式（可选） | 全部 | `resource:read`、`document:open` / `document:read`、`document:export` 源文档 |
| `resources:write` | 作用域模式（可选） | 全部 | `resource:write`、`document:write` / `document:save` |
| `window:control` | 窗口 ID 模式（可选） | `app` | `window:create` / `window:list` / `window:focus` / `window:close` / `window:resize` / `window:move` / `window:setTitle` / `window:setState` |
| `menu:manage` | 禁止 | `app` | `menu:set` |
| `tray:manage` | 禁止 | `app` | `tray:set` |
| `shortcut:manage` | 禁止 | `app` | `shortcut:register` / `shortcut:unregister` |
| `system:read` | 禁止 | 全部 | `system:info` |
| `power:read` | 禁止 | 全部 | `power:query` |
| `power:manage` | 禁止 | `app` | `power:prevent-sleep` |
| `transfer:manage` | 禁止 | 全部 | `transfer:download` / `transfer:cancel` |
| `notifications:send` | 禁止 | 全部 | `notification:send` |
| `clipboard:access` | 禁止 | 全部 | `clipboard:read` / `clipboard:write` |
| `dialogs:use` | 禁止 | `app` | `dialog:open` / `dialog:save` |
| `shell:external` | URL 模式（必需） | `app` | `shell:openExternal` |
| `network:http` | 域名模式（必需） | 全部 | `http:request` |
| `config:read` | 命名空间（必需） | 全部 | `config:get` / `config:snapshot` |
| `config:write` | 命名空间（必需） | 全部 | `config:set` / `config:reset` |
| `credential:manage` | 禁止 | 全部 | `credential:get` / `credential:set` / `credential:delete` |
| `events:publish` | 禁止 | 全部 | `event:publish` |

限定值规则（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 3.2）：

| 规则 | 含义 |
|---|---|
| 必需 | manifest 中该项权限必须携带限定值，缺失按 `PERMISSION_INVALID` 处理 |
| 可选 | 可携带可不携带 |
| 禁止 | 不得携带，携带按 `PERMISSION_INVALID` 处理 |

- 能力只声明**基础权限 ID**（`<domain>:<scope>`）；限定形式只出现在 manifest 申请与授权记录中（R3）。
- 限定值文法按域定义：路径（`filesystem`）、域名（`network`）、URL（`shell`）、窗口 ID（`window`）、作用域（`resources`）、命名空间（`config`）。
- 路径限定必须使用目录变量（如 `${userDocuments}/chips`），不得写裸绝对路径。
- 权限 ID 4 段及以上非法；`*` 不得作为 domain 或 scope；限定值中允许出现 `:`（如网络端口），解析按前两个冒号切分。

### 6.3 申请规则

1. 同一权限 ID 可声明多条，但限定值必须不同；相同权限 ID 与相同限定值的重复条目去重保留一条。
2. 声明必须表达最小范围：能用子目录限定就不写整个目录变量，能用具体域名就不用 `*`。
3. 角色适用性：`window:control`、`menu:manage`、`tray:manage`、`shortcut:manage`、`power:manage`、`dialogs:use`、`shell:external` 仅 `app` 可申请；`system:read`、`power:read`、`transfer:manage` 与其余内置权限四种角色均可申请；`basecard` / `boxlayout` 的界面在平台容器内渲染，不申请窗口与系统集成类权限。
4. 禁止把能力 ID 写成权限 ID（反之亦然）；违反在安装校验返回 `PERMISSION_UNKNOWN`（R3）。
5. 未注册的 domain/scope 返回 `PERMISSION_UNKNOWN`；限定值文法非法返回 `PERMISSION_INVALID`；角色不符返回 `PERMISSION_ROLE_NOT_ALLOWED`。
6. 免权限范围无需也不应通过限定值申请：插件私有数据目录、自身配置命名空间、自身资源作用域只读访问、`ui.surface` 声明的自身窗口（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 4.4）。
7. 更新时权限集合新增或限定值收窄，必须重新确认授权；任何绕过授权变化的更新一律拒绝加载。

### 6.4 授权与运行时判定

```
manifest.permissions（申请集合）
        │
        │ 安装：语法 / 词表 / 限定值 / 角色适用性校验（失败终止安装）
        ▼
未记录（默认拒绝）── 首次启用：逐项授权确认 ──▶ granted / denied
        │
        ▼
启用：生成会话快照 grantedPermissions
        │
        ▼
调用：申请集合 ∩ 能力所需权限 ∩ 会话快照（实际目标匹配限定值）
        ├── 通过 → 执行
        └── 拒绝 → ChipsError（BRIDGE_PERMISSION_DENIED）
```

- 用户取消授权界面则本次启用取消，不写入任何授权；被拒权限保持未记录，插件仍可启用。
- 停用不撤销授权；卸载删除授权记录与运行时快照；撤销与恢复在平台设置界面执行。
- 拒绝必须返回结构化错误，不得静默失败；每次拒绝写入审计记录（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 第六节）。
