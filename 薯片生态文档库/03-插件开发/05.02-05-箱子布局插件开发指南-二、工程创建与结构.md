## 二、工程创建与结构

### 2.1 创建工程

用 `@chips/cli` 创建布局插件工程，角色选择 `boxlayout`：

```bash
pnpm exec chips plugin create \
  --role boxlayout \
  --id chips.layout.grid \
  --name "网格布局" \
  --dir examples/plugins/grid-layout
```

生成器的文件计划来自 `@chips/sdk/scaffold` 的 `createScaffoldPlan`（[02-SDK-API规范](../05-接口与契约/02-SDK-API规范.md) 第八节），落盘、依赖安装与打包由 CLI 执行；生成结果保证通过 manifest 校验与插件包格式校验。命令的完整参数与预期输出见 [01-快速开始](01-快速开始.md)。

### 2.2 源码结构与构建产物

```text
grid-layout/
├── manifest.yaml            # 唯一权威清单（必需）
├── package.json             # 工作区包 @chips/plugin-grid-layout；version 与 manifest.yaml 一致
├── tsconfig.json
├── src/
│   ├── config.ts            # 共享类型、默认值与归一辅助
│   ├── main.ts              # 主进程纯函数源码 → dist/index.js
│   ├── render.tsx           # 角色渲染入口源码 → render.js
│   └── index.ts             # 拆分导出
├── assets/
│   ├── icons/
│   │   └── grid.svg         # 布局图标（包内相对路径）
│   └── schemas/
│       └── grid-config.schema.json   # 布局配置 schema（props 结构）
└── tests/
    └── render.test.ts
```

| 产物 | 装载方 | 约定 |
|---|---|---|
| `dist/index.js` | 主进程 | 主进程入口：`validateConfig` 等纯函数经受管模块加载器加载；构建以 `src/main.ts` 生成 |
| `render.js` | 布局帧 | 渲染入口：`renderLayout` / `renderEditor` 由 `chips-resource://<plugin-scope>/render.js` 装载（[09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) 3.1） |

- 两个入口都是必需产物，且必须是 UTF-8 文本 ESM；`dist/index.js` 承载 `validateConfig` 等主进程纯函数，只允许经受管模块加载器加载（[02-插件清单规范](02-插件清单规范.md) §4.3）。
- `render.js` 必须外部化 React 与 `@chips/ui`，由帧运行时统一提供，不得随包重复打包（R4）。
- 包内不得出现 `.html` 文档与自己的第二套组件库；界面由插件在帧内代码创建。
- React 是官方前端技术栈（R4），渲染入口源文件为 `render.tsx`；本指南第七章的契约示例使用原生 DOM，以 `render.tsx` 形式给出，逻辑可直接迁移为 React 组件。

### 2.3 `manifest.yaml`

```yaml
id: chips.layout.grid
version: 1.0.0
type: boxlayout
name: 网格布局
description: 以网格方式排列箱子条目
author: 薯片官方
license: MIT
runtime:
  targets: [host]
permissions:
  - resources:read
capabilities:
  layouts:
    - id: chips.layout.grid
      name: 网格布局
      icon: assets/icons/grid.svg
      description: 自适应网格排列条目
      configSchema: assets/schemas/grid-config.schema.json
      schemaVersions: ">=1.0.0 <2.0.0"
```

| 字段 | 说明 |
|---|---|
| `id` | 插件 ID，反向域名；官方布局插件使用 `chips.layout.*`，第三方使用自有注册域（[02-插件清单规范](02-插件清单规范.md) 3.1） |
| `type` | 固定 `boxlayout`（R1） |
| `runtime.targets` | `[host]`；布局渲染只运行在平台宿主 |
| `permissions` | 权限申请集合；查看态打开条目经 `document:open`，所需权限为 `resources:read`（R19、[04-能力契约规范](../05-接口与契约/04-能力契约规范.md)） |
| `capabilities.layouts[].id` | 布局类型标识，形如 `chips.layout.<name>`；必须与箱子 `metadata.yaml` 的 `active_layout_type`、`content.yaml` 的 `layout_configs` 键一致（R20） |
| `capabilities.layouts[].name` | 简体中文显示名；界面按「发行商：名字」展示（[02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) 10.3） |
| `capabilities.layouts[].icon` | 布局图标，包内相对路径且目标位于 `assets/`（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) 2.6） |
| `capabilities.layouts[].description` | 一句话简体中文说明 |
| `capabilities.layouts[].configSchema` | 布局配置 schema，包内相对路径且位于 `assets/`；JSON Schema 2020-12，顶层 `object`，描述 `layout_configs.<id>.props` 结构（[02-插件清单规范](02-插件清单规范.md) 7.3） |
| `capabilities.layouts[].schemaVersions` | 插件支持渲染与编辑的配置 `schema_version` 版本范围，不得为空；打开箱子时的兼容门禁依据（第 3.6 节、第 6.6 节） |

布局插件不得声明 `cardTypes`、`ui`、`fileAssociations` 等其它角色的专有字段；`runtime.background` 只属于服务插件。

### 2.4 构建与本地质量门禁

```bash
pnpm --filter @chips/plugin-grid-layout run lint
pnpm --filter @chips/plugin-grid-layout run typecheck
pnpm --filter @chips/plugin-grid-layout run test
pnpm --filter @chips/plugin-grid-layout run build

pnpm exec chips plugin pack --dir examples/plugins/grid-layout --out dist/
pnpm exec chips plugin validate dist/grid-layout-1.0.0.cpk
```

`pack` 在构建暂存目录内按 ZIP Store 写出 `.cpk`；`validate` 执行与安装同源的归档、结构、清单与签名校验（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) 第七节）。构建与打包全流程见 [02-构建与打包](../06-开发与运维/02-构建与打包.md)。
