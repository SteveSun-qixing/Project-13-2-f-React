## 五、签名与来源规则

### 5.1 来源渠道

| 来源 | 含义 | 发现优先级 |
|---|---|---|
| `development` | 开发目录（开发工作区或启动参数指定的插件目录） | 最高 |
| `user` | 用户安装的 `.cpk`（安装落盘位置） | 中 |
| `builtin` | 随平台分发的内置插件 | 最低 |

- 同一 ID 在多个来源出现时，高优先级来源生效，其余遮蔽；同一来源内同 ID 多版本取版本最高者。
- 内置插件不可卸载，只能停用（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §4.5）。
- 目录态只属于 `development`；发布单位始终是单个 `.cpk`。

### 5.2 签名文件

签名文件固定为包根 `signature.json`（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §6）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `format` | string | 是 | 固定为 `chips-signature-v1` |
| `keyId` | string | 是 | 签名密钥标识，由发布方信任根注册表解析 |
| `algorithm` | string | 是 | 固定为 `ed25519` |
| `contentHash` | string | 是 | 包内容摘要，`sha256:<小写十六进制>` |
| `signature` | string | 是 | 对 `contentHash` UTF-8 字节的 Ed25519 签名（Base64） |

`contentHash` 的构造规则（`signature.json` 自身不参与计算）：

1. 列出除 `signature.json` 外的全部文件成员，按路径字节序升序排序；
2. 对每个文件计算 SHA-256（小写十六进制）；
3. 依次拼接 `文件路径 + "\n" + 文件摘要 + "\n"` 的 UTF-8 字节流；
4. 对拼接结果计算 SHA-256，记为 `sha256:<hex>`。

### 5.3 来源 × 签名校验规则

| 来源 | 签名要求 | 缺失时 | 无效时 |
|---|---|---|---|
| `builtin` | 必须签名 | `CPK_SIGNATURE_REQUIRED`，拒绝安装 | `CPK_SIGNATURE_INVALID`，拒绝安装 |
| `user` | 可选；当前阶段无强制签名 | 安装界面明确展示"未签名发布者"，用户确认后继续 | `CPK_SIGNATURE_INVALID`，拒绝安装 |
| `development` | 不适用 | 不检查 | 不检查 |

规则：

- 未签名不得静默安装；必须产生可见提示与用户确认记录。
- 签名有效不得作为跳过归档、结构、清单与载荷校验的理由。
- 信任根未注册的 `keyId` 视为签名无效。
- 密钥生成、签名工具、信任根注册表与分发属于发布链路（Phase 3/4）；本文不定义签名命令，见 [02-构建与打包](../06-开发与运维/02-构建与打包.md)。
