## 三、接口实现（以 09 号文档为准）

### 3.1 角色接口

渲染入口默认导出实现 `IBoxLayoutPlugin` 的对象；需要条目帧与帧动作时，同一对象同时实现 `IBoxLayoutRuntimeAware`：

```typescript
type Dispose = () => void;

interface IBoxLayoutPlugin {
  /** 查看态：把箱子渲染进容器；产生副作用时必须返回释放句柄 */
  renderLayout(box: BoxRenderView, container: HTMLElement): void | Dispose;

  /** 编辑态：把布局配置编辑器挂载到容器，返回编辑器句柄 */
  renderEditor(box: BoxRenderView, container: HTMLElement): ILayoutEditor;

  /** 校验布局配置是否可用于渲染；纯函数、同步、不得抛出 */
  validateConfig(config: unknown): boolean;
}

interface IBoxLayoutRuntimeAware {
  attachRuntime(runtime: IBoxLayoutFrameRuntime): void;
}

interface IBoxLayoutFrameRuntime {
  requestEntries(request: EntryRequest): Promise<EntryTicket[]>;
  mountEntry(ticket: EntryTicket, container: HTMLElement): Promise<Dispose>;
  openDocument(source: string): Promise<void>;
  openExternal(url: string): Promise<void>;
  copyText(text: string): Promise<void>;
  notify(notification: FrameNotification): Promise<void>;
}
```

`EntryRequest`、`EntryTicket`、`FrameNotification` 与各动作的错误语义见 [09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) 第六节；`EntryTicket` 的字段结构由 [05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 7.2 定义。

```typescript
const plugin: IBoxLayoutPlugin & IBoxLayoutRuntimeAware = {
  attachRuntime,
  renderLayout,
  renderEditor,
};

export default plugin;
```

### 3.2 三方法分工

| 维度 | `renderLayout` | `renderEditor` | `validateConfig` |
|---|---|---|---|
| 调用方 | 帧运行时 | 编辑链路 | 编辑链路、编辑器自身 |
| 运行环境 | 布局帧（`sandbox="allow-scripts"` iframe） | 应用窗口渲染进程，就近渲染，无 iframe | 调用方所在上下文 |
| 输入 `box` | 只读渲染视图 | 同一份解析结果，不二次解析（R8） | — |
| 返回值 | `void \| Dispose` | 必须返回 `ILayoutEditor` | `boolean` |
| 平台访问 | 只经 `IBoxLayoutFrameRuntime`；禁止 `window.chips`、`parent`、存储与网络 | 允许经 `window.chips` 使用能力与资源句柄 | 无副作用 |
| 副作用范围 | 容器内 DOM、观察器、定时器 | 编辑面板 DOM、订阅 | 无 |
| 失败语义 | 抛出 → `RENDER_PLUGIN_FAILED` 降级可重试 | 抛出 → 编辑面板降级 | 抛出视为 `false` |

两种形态共享同一套配置结构与同一份布局算法：编辑只产出配置变更，查看只消费配置（[02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) 10.2）。

### 3.3 `renderLayout` 要点

1. 同一容器在帧存活期间会被多次调用（视图更新）：每次调用必须让容器呈现传入 `box` 的完整内容，不得叠加多份内容。
2. 重绘前自行清理上一次调用创建的短期效果（事件监听、定时器、Observer、已挂载条目帧）；返回的 `Dispose` 只负责本次调用建立的效果，幂等且不得抛出。
3. 槽位、排序呈现、滚动容器结构与布局算法全部由插件决定；容器宽度由父帧决定，插件不得请求改变外层尺寸，高度按帧协议上报。
4. 帧内一律不读文件、不解析 YAML、不创建非受管 iframe；条目内容只经 `requestEntries` / `mountEntry` 获得（第五节）。
5. 插件必须容忍字段缺失与类型异常：坏数据下仍要呈现可读内容，条目级失败不得升级为整箱失败。

### 3.4 `renderEditor` 要点

1. 宿主提供铺满可视区的容器（`width/height: 100%`、`min-height: 0`），滚动由编辑器内部管理。
2. 输入是与查看态同一份 `BoxRenderView`；不得读取文件、不得二次解析。
3. 必须返回 `ILayoutEditor`；布局没有可配置项时也返回可用句柄，面板显示空态说明。
4. 编辑器只产出配置变更：不写文件、不保存、不修改会话视图，变更经 `ILayoutEditor` 交给编辑链路回流（第 6.4 节）。
5. 不得实现第二套查看渲染；需要预览时使用会话的 `renderLayout` 输出。
6. `dispose()` 中释放全部订阅、定时器、Observer 与 DOM 引用，并停止触碰容器。

### 3.5 `validateConfig` 要点

1. 输入是布局配置对象（`BoxRenderView.layout_config` 的形状），不是整个 `layout_configs` 映射；未提供时传入 `undefined` / `null` / `{}`。
2. 纯函数、同步、无副作用、不得抛出；`true` 表示结构合法，`false` 表示结构非法。
3. 只校验结构合法性（类型、范围、枚举），不要求字段完备：缺省字段由插件内部默认值与归一逻辑补齐，因此 `{}` 与缺省字段返回 `true`；非对象、类型错误与越界值返回 `false`。
4. 平台不解释插件配置字段；默认值、归一并插件自持，查看态渲染不因配置非法阻断（第 6.2 节）。
5. 可被编辑器高频调用，检查必须与配置规模线性且轻量。

### 3.6 装载、版本与生命周期

1. 打开箱子时，渲染引擎由 `BoxRenderView.active_layout_type`（即 `metadata.yaml` 的 `active_layout_type`）在插件注册表中查询声明了该 `layouts.id` 的 `boxlayout` 插件（经平台插件门面 `IPluginRuntime` 装载）。
2. 对生效布局配置执行 schema 兼容门禁：配置项不存在时按空配置处理（`layout_config` 为空对象），插件以内部默认值渲染；配置项存在时 `schema_version` 必须存在、为合法语义化版本且落在插件 `capabilities.layouts[].schemaVersions` 范围内，任一不满足时平台按 `RENDER_SCHEMA_UNSUPPORTED` 降级占位且不调用插件。插件缺失返回 `RENDER_PLUGIN_MISSING`，渲染降级占位并提示安装（[09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) 2.2）。
3. 插件模块按「插件 ID + 版本」缓存；模块级状态只在单个渲染帧内有效，不得跨帧、跨窗口共享可变状态。
4. 启用只把 `layouts` 注册进注册表，不执行渲染代码；停用注销注册并销毁使用该布局的已打开视图，箱子的持久化数据不丢失（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 2.3.2）。
5. `RENDER_PLUGIN_FAILED`、`RENDER_FRAME_TIMEOUT` 等渲染错误的产生方与重试规则见 [09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) 第九节；插件的责任是修复缺陷并保证坏数据下的降级呈现。
