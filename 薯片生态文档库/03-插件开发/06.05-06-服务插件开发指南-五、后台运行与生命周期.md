## 五、后台运行与生命周期

### 5.1 `runtime.background`

| 值 | 规则 |
|---|---|
| `true` | 后台常驻：平台启动恢复阶段按启用偏好自动启用；运行不依赖任何界面会话 |
| `false` / 缺省 | 无后台常驻保障：启动恢复阶段不主动启用，由用户操作或依赖链显式启用 |

- 仅 `service` 角色可声明 `true`；推荐常驻服务显式声明（E10 4.6、7.2）。
- `background` 与 `healthCheck` 相互独立：只要声明 `healthCheck`，运行期间一律按周期检查。

### 5.2 状态链路

```text
installed ──enable──▶ starting ──start() 成功──▶ active
                          │                        │
                          │ start() 失败            ├── healthCheck 周期 health()
                          ▼                        │        └── 连续不健康 ──┐
                       failed ◀────────────────────┴── 运行崩溃 / 超配额 ────┤
                          │ retry（显式）                                    │
                          ▼                                                 │
                       starting                                             ▼
active ──disable──▶ stopping ──stop() + Fork.dispose()──▶ installed      failed
```

| 阶段 | 平台动作 | 插件职责 | 失败结果 |
|---|---|---|---|
| `starting` | 生成会话权限快照、创建 Fork、调用 `start(ctx)` | 完成异步初始化、注册服务与能力 | Fork 回滚，插件 `failed`，`KERNEL_APPLY_FAILED` |
| `active` | 路由服务与能力调用、周期健康检查 | 响应调用、维持健康、遵守配额 | 不健康熔断；连续失败停用 |
| `stopping` | 摘除路由、调用 `stop()`、`Fork.dispose()` | 停止接收、落盘状态、释放自有资源 | `stop` 失败记录 `KERNEL_DISPOSE_FAILED`，停用照常完成 |
| `installed` | 写入启用偏好 | 无运行副作用 | — |
| `failed` | 保留清单与最后错误 | 无运行副作用 | 需显式重试 |

### 5.3 停用与更新

- 停用顺序固定为：摘除路由 → 调用 `stop()` → `Fork.dispose()` 逆序撤销剩余副作用 → 状态置 `installed`；停用不删除插件文件、配置与授权。
- 服务插件更新走蓝绿替换：新 Fork 执行 `start()`，成功注册服务后原子切换服务代际，旧 Fork 进入 `draining` 并调用 `stop()`（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 6.2、6.3）。
- 切换窗口内新旧两个实例短暂并存：`start` / `stop` 必须各自只管理本代际资源，禁止使用进程级单例或全局可变状态承载业务状态。
- 服务名与能力 ID 在更新前后保持不变；新版本 `start` 失败时平台回滚到旧代际，插件保持 `active`。

### 5.4 启动恢复与退出

- 平台启动时清理上次中断残留，对启用偏好集合按依赖拓扑序逐个启用；单个插件失败被隔离，不阻塞其它插件。
- 平台退出时对所有 `active` 服务调用 `stop()` 后统一撤销。
- 重试必须走平台的重试入口（插件管理界面或插件管理能力），不得由插件自行调用 `start`；恢复后不得依赖旧内存状态，需要延续的状态落配置或插件私有数据目录。

### 5.5 并发与长任务

- `start`、`stop`、`health` 与能力 `execute` 都运行在主进程调度模型中，禁止执行阻塞调用、同步文件 IO 与长循环。
- 周期或长时运行的处理必须使用取消令牌：在 `start` 中创建 `AbortController`，把 `abort()` 登记进 `effect` 清理与 `stop()`。

```typescript
const controller = new AbortController();
const timer = setInterval(() => {
  // 推进后台任务；任务体接收 controller.signal 并在取消时退出
  void controller.signal;
}, 5_000);

ctx.effect(() => {
  clearInterval(timer);
  controller.abort();
});
```

- 并发策略由能力注册项决定（`parallel` / `serial`），插件不得假设同一能力的 `execute` 串行执行。
- 平台施加软配额（消息频率、后台任务并发、内存占用），超配额按「限频 → 暂停后台任务 → 停用」逐级降级；插件应主动限制自身的周期任务频率与缓存规模。
