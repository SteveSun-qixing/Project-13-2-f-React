## 八、调试、打包与发布

### 8.1 开发态联调

开发态允许以目录形式加载：目录根布局与 `.cpk` 解包后的包根完全一致，跳过大宗归档与签名校验，仍执行清单、入口、角色布局与路径安全校验（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) 2.7）。联调时至少验证一次完整链路：打开箱子 → 布局帧装载 → 条目帧挂载 → 条目激活 → 编辑面板回流 → 保存。调试工具与常见场景见 [07-调试与发布](07-调试与发布.md) 与 [03-调试指南](../06-开发与运维/03-调试指南.md)。

### 8.2 打包与安装校验

```bash
pnpm exec chips plugin pack --dir examples/plugins/grid-layout --out dist/
pnpm exec chips plugin validate dist/grid-layout-1.0.0.cpk
```

`boxlayout` 的包内要求：`manifest.yaml` + `dist/index.js` + `render.js` 必需；`assets/icons/` 放布局图标；不得出现卡片类型图标与模板资源、原生载荷、`node_modules/` 或第二套组件库（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) 第三节）。

### 8.3 发布前检查

- `manifest.capabilities.layouts[].id` 与插件实现、箱子文件中的布局类型标识一致；
- 配置只写入 `props` 与 `asset_refs`，无绝对路径、临时 URL、凭证与会话 ID；
- `manifest.capabilities.layouts[]` 已声明 `configSchema` 与 `schemaVersions`；编辑器 `replace` 写入的 `schemaVersion` 落在声明范围内；
- `render.js` 已外部化 React 与 `@chips/ui`；
- `lint` / `typecheck` / `test` / `build` / `pack` / `validate` 全部通过；
- 在开发工作区完成一次箱子查看会话与编辑面板联调（[02-构建与打包](../06-开发与运维/02-构建与打包.md)）。
