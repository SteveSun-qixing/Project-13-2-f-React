## 一、定位与边界

### 1.1 定位

`manifest.yaml` 是 `.cpk` 包根的唯一权威清单（R11）：插件标识、版本、角色、运行目标、依赖、权限申请与角色能力全部由它声明；包内其它配置文件不得与其冲突。

本文是 manifest 字段与校验规则的唯一权威，覆盖：

- 基础字段（`id` / `version` / `type` / `name` / `description` / `author` / `license`）；
- `runtime`（`targets` / `background`）；
- `engines`（`engines.chips` 平台版本范围门禁）；
- `dependencies`（对象数组与版本范围）；
- `deepLinks`（应用深链接声明）；
- `permissions`（申请集合的写法与规则）；
- 四角色专有字段（`capabilities.cardTypes` / `capabilities.layouts` / `ui` / `fileAssociations` / `deepLinks` / `healthCheck` / `cli.commands`）；
- 四种角色的完整清单示例、校验规则与常见错误。

使用者：插件开发者（编写）、`@chips/cli`（打包前校验）、平台安装校验与插件注册表（读取与登记）。

### 1.3 基本约束

- **单一权威**：每个 `.cpk` 只有一份 `manifest.yaml`，位于包根；包内不得出现第二份清单或与其冲突的标识、版本、角色声明。
- **单一角色**：`type` 只有一个取值；需要多角色能力时拆分为多个插件并用 `dependencies` 组合（R1、[ADR-005](../01-架构设计/ADR/ADR-005-插件不分类只分角色.md)）。
- **封闭结构**：manifest 为封闭 schema，出现本文未登记的字段即安装校验失败；不保留兼容字段与旧口径（[ADR-010](../01-架构设计/ADR/ADR-010-大爆炸重构策略.md)）。
- **确定性校验**：全部规则在安装校验与启用校验阶段离线判定，不依赖运行期状态。
- **失败即终止**：校验失败时 `.cpk` 不落盘、不写注册表，不产生半成品（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 4.2）。
- **界面文案**：面向用户的 `name` / `description` / 启动器文案一律简体中文直写（R5）。
