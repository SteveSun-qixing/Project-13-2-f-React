## 一、定位与前置

### 1.1 本文做什么

本文是从零写成一个可安装、可渲染、可编辑、可校验、可导出的基础卡片插件的完整教程。接口签名以[08-基础卡片插件接口](../05-接口与契约/08-基础卡片插件接口.md)（下称接口文档）为唯一权威，卡片字段以[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md)（下称格式文档）为唯一权威；本文只讲"怎么开发"，不重定义任何契约。

读完并完成本文示例后，你将得到：

- 一个 `basecard` 角色的 `.cpk` 插件包，声明了卡片类型 `base.richtext`；
- `renderView` / `renderEditor` 的 React 实现与完整的容器生命周期处理；
- 与 `configSchema` 同语义的 `validateConfig` 与 HTML 导出；
- 与该卡片类型对应的 `.card` 内容示例。

### 1.2 角色边界

一个插件只有一个角色；需要多种角色能力时拆成多个插件，用 `dependencies` 组合（[ADR-005](../01-架构设计/ADR/ADR-005-插件不分类只分角色.md)）。`basecard` 插件只负责定义卡片类型：查看渲染、编辑渲染、配置校验与可选导出；它不创建窗口、不解析 `.card`、不写文件、不注册渲染帧。

### 1.4 标识符速记

| 对象 | 规范 | 示例 |
|---|---|---|
| 插件 ID | 反向域名，基础卡片官方前缀 `chips.basecard.*` | `chips.basecard.richtext` |
| 卡片类型 ID | 以[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md)各类型 Schema 的 `card_type` 为准（如 `base.richtext`、`base.score`、`base.file`）；用于内容配置 `card_type`、`structure.yaml` 条目 `type` 与 manifest 的 `capabilities.cardTypes[].id` | `base.richtext`、`base.score`、`base.file` |
| 内容节点 ID | 10 位 Base62 编号，与 `content/{id}.yaml` 一一对应 | `a1B2c3D4e5` |
| 资源 URI | `chips-resource://<scope>/<path>` | `chips-resource://card-7f3a/images/photo.jpg` |

卡片类型历史别名（如 `RichTextCard`、`FileCard`）只允许读取归一，不作为新写入值（R20、格式文档 §5.3）。
