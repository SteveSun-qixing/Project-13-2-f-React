## 二、清单文件与字段总表

### 2.1 文件位置与加载

| 项 | 规则 |
|---|---|
| 路径 | `.cpk` 包根 `manifest.yaml`；归档内不得再有顶层包裹目录（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) 2.1） |
| 开发态 | 开发目录根使用同名文件；目录结构必须与 `.cpk` 解包后的包根一致（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) 2.7） |
| 编码与语法 | UTF-8 文本，YAML 1.2；根节点为映射 |
| 大小 | 不超过 256 KiB，超限 `CPK_LIMIT_EXCEEDED` |
| 发现阶段 | 只解析登记所需字段，不执行任何插件代码（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 4.1） |
| 打包一致性 | CLI 校验 `manifest.version` 与插件源码 `package.json` 的 `version` 一致，不一致拒绝打包（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) 7.1） |
| 引用路径 | 清单内全部文件引用为包内相对 POSIX 路径，且目标位于 `assets/` 内（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) 2.6） |

### 2.2 完整骨架

```yaml
# 基础字段（必填）
id: chips.official.editor
version: 1.0.0
type: app
name: 编辑引擎

# 基础字段（选填；发布包应填写）
description: 创建和编辑卡片
author: 薯片官方
license: MIT

# 运行时（必填）
runtime:
  targets: [host]                 # 仅 host；非空且去重
  background: false               # 可选，缺省 false；仅 service 可为 true

# 平台版本范围（选填；发布包应声明）
engines:
  chips: ">=1.0.0 <2.0.0"         # 语义化版本范围，语法见 04-版本与迁移规范 §四

# 依赖（选填）
dependencies:
  - id: chips.basecard.richtext
    version: ">=1.0.0"

# 权限申请集合（选填；省略等价空集合）
permissions:
  - "filesystem:read:${userDocuments}/chips"
  - notifications:send

# 角色专有字段：按 type 只允许对应角色的一组
capabilities:                     # basecard / boxlayout
  cardTypes: []                   # basecard 必填，至少一项
  layouts: []                     # boxlayout 必填，至少一项，每项含 configSchema 与 schemaVersions
ui:                               # app 必填
  surface: window                 # window | desktop | tray
  launcher: {}                    # 可选；空对象表示注册启动器入口
fileAssociations: []              # app / service
deepLinks:                        # app（可选）
  - scheme: chips-viewer
    host: open
healthCheck:                      # service
  interval: 30s
  timeout: 5s
cli:                              # app / service（可选）
  commands:
    - commandPath: [office, open] # 入口声明；专有语义见 CLI 完整参考 §5.1
      title: 打开办公文档
      target:
        type: app
        pluginId: chips.official.office
```

### 2.3 字段总表

| 字段 | 必填 | 类型 | 适用角色 | 说明 |
|---|---|---|---|---|
| `id` | 是 | string | 全部 | 反向域名插件 ID，全局唯一（第 3.1 节） |
| `version` | 是 | string | 全部 | 语义化版本（第 3.2 节） |
| `type` | 是 | string | 全部 | `basecard` / `boxlayout` / `app` / `service`（第 3.3 节） |
| `name` | 是 | string | 全部 | 简体中文显示名（第 3.4 节） |
| `description` | 否 | string | 全部 | 一句话说明（第 3.4 节） |
| `author` | 否 | string | 全部 | 作者或组织（第 3.5 节） |
| `license` | 否 | string | 全部 | 许可证标识，脚手架默认 `MIT`（第 3.5 节） |
| `runtime` | 是 | object | 全部 | 运行目标与后台标记（第四节） |
| `engines` | 否 | object | 全部 | 平台版本范围兼容门禁（第 3.6 节） |
| `dependencies` | 否 | object[] | 全部 | 直接依赖列表（第五节） |
| `permissions` | 否 | string[] | 全部 | 权限申请集合（第六节） |
| `capabilities` | 条件 | object | `basecard` / `boxlayout` | 角色能力声明（第 7.2、7.3 节） |
| `ui` | 条件 | object | `app` | 界面形态与启动器（第 7.4 节） |
| `fileAssociations` | 否 | object[] | `app` / `service` | 文件关联声明（第 7.4 节） |
| `deepLinks` | 否 | object[] | `app` | 深链接声明（第 7.4 节） |
| `healthCheck` | 否 | object | `service` | 健康检查周期（第 7.5 节） |
| `cli` | 否 | object | `app` / `service` | CLI 命令入口声明（第 7.6 节；专有语义见 [CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §五） |

条件必填与角色限定：

- `basecard` 必须声明 `capabilities.cardTypes` 且至少一项；
- `boxlayout` 必须声明 `capabilities.layouts` 且至少一项；
- `app` 必须声明 `ui` 与 `ui.surface`；
- 其它角色出现上述专有字段时安装校验失败（第七节差异总表）；
- `cli` 仅 `app` / `service` 可声明，其它角色声明即失败（第 7.6 节）。

### 2.4 入口与构建产物

| 产物 | 适用角色 | 职责 |
|---|---|---|
| `dist/index.js`（主进程入口） | 全部 | 角色入口实现与主进程纯函数（如 `validateConfig`、`createInitialContent`、`collectResourcePaths`）；经受管模块加载器加载 |
| `render.js`（渲染入口） | `basecard` / `boxlayout` / `app` | 渲染方法（如 `renderView` / `renderEditor` / `export`）与应用 UI；经 `chips-resource://<plugin-scope>/render.js` 在渲染帧或应用窗口装载 |
| `assets/schemas/config.schema.json` | 全部（可选） | 插件自身配置 schema；与卡片 / 布局的 `configSchema` 是两个不同文件 |

- 双入口约定与构建外部化白名单（`react`、`react-dom`、`@chips/ui`）见 [03-插件包格式](../04-文件格式规范/03-插件包格式.md) §2.6 与各角色接口文档（[08-基础卡片插件接口](../05-接口与契约/08-基础卡片插件接口.md) §2.5）。
- `service` 包内不得携带 `render.js` 与 UI 资源；主进程入口是全部角色的必需产物。
