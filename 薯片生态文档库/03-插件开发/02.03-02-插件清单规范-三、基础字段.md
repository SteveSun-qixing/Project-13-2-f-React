## 三、基础字段

### 3.1 `id`

| 项 | 规则 |
|---|---|
| 格式 | 反向域名，至少两段，段间以 `.` 分隔 |
| 文法 | `^[a-z0-9]([a-z0-9-]*[a-z0-9])?(\.[a-z0-9]([a-z0-9-]*[a-z0-9])?)+$` |
| 字符集 | 小写字母、数字、`-`、`.`；禁止大写、下划线、空白与中文 |
| 段规则 | 每段以字母或数字开头与结尾，不得出现连续点 |
| 唯一性 | 全局唯一；同一来源同 ID 多版本取最高版本，其余记录冲突并上报（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 4.1） |
| 稳定性 | 发布后不得变更；卸载后同 ID 再安装视为全新安装，不恢复旧配置 |

官方命名空间（R20）：

| 命名空间 | 用途 |
|---|---|
| `chips.official.*` | 官方应用插件 |
| `chips.basecard.*` | 官方基础卡片插件 |
| `chips.layout.*` | 官方箱子布局插件 |
| `chips.service.*` | 官方服务插件 |
| 第三方自有域 | 第三方插件；发布前必须注册自有域 |

### 3.2 `version`

- 语义化版本 `MAJOR.MINOR.PATCH`，可选预发布与构建元数据；文法 `^\d+\.\d+\.\d+(-[0-9A-Za-z.-]+)?(\+[0-9A-Za-z.-]+)?$`。
- 版本含义（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) 3.3）：
  - `MAJOR`：接口行为、配置 schema、数据契约或依赖契约的不兼容变更；
  - `MINOR`：向后兼容的新增；
  - `PATCH`：向后兼容的修复。
- `0.x` 阶段按预发布语义执行：破坏性变更升 `MINOR`，仍须走变更流程并同步迁移步骤；已发布版本的语义不可修改。
- 必须与插件源码 `package.json` 的 `version` 一致；安装为降级版本时确定性拒绝，不覆盖已安装版本（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) 5.1）。

### 3.3 `type`

| 取值 | 角色 | 入口接口 | 界面形态 | 专有字段 |
|---|---|---|---|---|
| `basecard` | 基础卡片插件 | `IBaseCardPlugin` | 嵌于宿主视图（iframe） | `capabilities.cardTypes` |
| `boxlayout` | 箱子布局插件 | `IBoxLayoutPlugin` | 嵌于宿主视图（iframe） | `capabilities.layouts` |
| `app` | 应用插件 | `IAppPlugin` | 独立窗口（`ui.surface`） | `ui`、`fileAssociations` |
| `service` | 服务插件 | `IServicePlugin` | 无 UI | `runtime.background`、`healthCheck`、`fileAssociations` |

- `type` 决定入口接口、生命周期入口与包内布局校验分支（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 2.2）；取值非法或缺失时 `CPK_MANIFEST_INVALID`。
- 内核不感知角色：四类角色共用同一套加载、依赖与生命周期机制；角色差异由插件管理层与接口层承担。

### 3.4 `name` / `description`

| 字段 | 必填 | 规则 |
|---|---|---|
| `name` | 是 | 非空简体中文显示名；用于插件列表、启动器与权限授权界面 |
| `description` | 否 | 一句话说明；`ui.launcher.description` 缺省时取其值（[07-应用插件接口](../05-接口与契约/07-应用插件接口.md) 5.3） |

- 文案直接面向用户，禁止英文占位、内部代号与版本号堆叠；发布包应同时填写两项。

### 3.5 `author` / `license`

| 字段 | 必填 | 规则 |
|---|---|---|
| `author` | 否 | 作者或组织名；发布包应填写 |
| `license` | 否 | 许可证标识（SPDX，如 `MIT`、`Apache-2.0`）；脚手架生成时默认 `MIT` |

- 两项缺失不阻断安装；发布前必须补齐并保持与实际分发许可一致。

### 3.6 `engines`

```yaml
engines:
  chips: ">=1.0.0 <2.0.0"     # 语义化版本范围，语法见 04-版本与迁移规范 §四
```

| 项 | 规则 |
|---|---|
| 必填性 | 选填；发布包应显式声明以表达兼容区间 |
| 结构 | 对象，仅允许 `chips` 一个键；出现其它键时 `CPK_MANIFEST_INVALID`（封闭 schema） |
| `chips` | 非空、语法合法的语义化版本范围（写法与匹配规则同 `dependencies[].version`，以[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) 第四节为唯一权威） |
| 语义 | 声明插件可运行的**平台版本**范围（平台版本定义见[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) 第二节）；省略时不做平台版本限定，安装、启用与更新不触发该门禁 |

- 门禁时机（安装校验、启用、平台更新后重启自检、插件更新）与不满足时的处理以[06-更新与分发规范](../06-开发与运维/06-更新与分发规范.md) §3.3 为准；安装与启用拒绝返回 `CPK_ENGINE_UNSUPPORTED`（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) 第八节）。
- `engines.chips` 是独立于 `dependencies` 的**平台侧**门禁：依赖门禁约束插件之间的版本关系，本字段约束插件与平台的版本关系，两者都通过才允许启用与更新。
- 禁止未定义写法（`latest`、`~>`、`workspace:*`、区间连字符等），语法非法在安装校验阶段判定为 `CPK_MANIFEST_INVALID`。
