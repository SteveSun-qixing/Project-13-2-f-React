## 八、配置与日志

### 8.1 配置

`ctx.config` 是平台对 `config:*` 能力的类型化封装，作用域固定为当前插件自身的命名空间 `plugins.<pluginId>`；默认值来自插件包内 `assets/schemas/config.schema.json`，默认值不落盘，只有显式覆盖写入 `user` 或 `workspace` 层（E10 3.5）。

| 成员 | 用法 |
|---|---|
| `get(key)` | 读取相对键的生效值；键未注册返回 `CONFIG_KEY_UNKNOWN` |
| `snapshot(prefix?)` | 返回前缀下合并默认值后的完整生效视图 |
| `set(key, value, scope)` | 在 `user` 或 `workspace` 层写入覆盖；值必须通过 `assets/schemas/config.schema.json` 校验 |
| `reset(keys, scope)` | 移除指定层上的覆盖；缺失覆盖为 no-op |
| `watch(prefix, handler)` | 订阅前缀匹配的变更，返回可退订句柄 |

```typescript
const view = await ctx.config.get('algorithm');
if (typeof view.value === 'string') {
  this.defaultAlgorithm = view.value;
}

const changes = ctx.config.watch('algorithm', (change) => {
  if (typeof change.effectiveValue === 'string') {
    this.defaultAlgorithm = change.effectiveValue;
    ctx.logger.info('默认目标语言已更新', { targetLanguage: this.targetLanguage });
  }
});

ctx.effect(() => {
  changes.dispose();
});
```

规则：

- `key` 为插件命名空间下的相对键（如 `quality`），不得包含命名空间前缀；插件不得直接读写配置文件。
- 读写 `platform` 命名空间不使用 `ctx.config`：读取经 `ctx.bridge.request('config:get', { namespace: 'platform', key })`，写入经 `ctx.bridge.request('config:set', { namespace: 'platform', key, value, scope })`，并持带命名空间限定值的 `config:read` / `config:write`。
- 常见错误码：`CONFIG_SCHEMA_INVALID`、`CONFIG_KEY_INVALID`、`CONFIG_KEY_UNKNOWN`、`CONFIG_VALUE_INVALID`、`CONFIG_SCOPE_INVALID`、`CONFIG_POLICY_LOCKED`、`CONFIG_NAMESPACE_DENIED`、`CONFIG_WRITE_FAILED`（完整语义见[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) 4.4）。
- `watch` 返回的句柄随订阅登记；插件卸载或停用时其订阅随 Fork 撤销。

### 8.2 日志

```typescript
ctx.logger.info('翻译服务已启动', { targetLanguage: this.targetLanguage });
ctx.logger.error('远端请求失败', error, { url });
```

规则（E10 3.6）：

- 平台自动附加 `pluginId`、`pluginVersion`、`timestamp`、`level`、`traceId`；日志按插件隔离并按限速策略写入。
- 日志免权限（R19）：按插件命名空间自动归属，写入失败不抛出、不中断服务。
- `message` 面向开发者，使用简体中文；结构化细节放 `fields`，只允许字符串、数字、布尔与 `null` 标量。
- 禁止记录凭证值、文件内容、用户数据与资源字节；禁止在发布路径同步写日志（同步写阻塞调度模型）。
- 错误对象经 `error` 参数传入，平台提取类型与消息写入诊断，不将堆栈写入用户可见输出。
