## 七、版本管理规则

### 7.1 三类版本

| 版本 | 权威位置 | 变更驱动 |
|---|---|---|
| 平台版本 | 仓库根 workspace 版本（`package.json` 与 `Cargo.toml` 一致） | 平台发布 |
| 插件版本 | `.cpk` 包根 `manifest.yaml` 的 `version`；源码 `package.json` 必须一致 | 插件发布 |
| 文档格式版本 | `.card` / `.box` 内 `metadata.yaml` 的 `chip_standards_version` | 文档格式变更（随平台版本发布） |

三类版本互不推导；插件按自身需求独立升级。完整定义见 [04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §二。

### 7.2 版本格式

```text
MAJOR.MINOR.PATCH[-预发布标识][+构建元数据]
```

- 三段数字为非负整数，禁止前导零；禁止 `v` 前缀；
- 预发布标识使用 `-alpha.N`、`-beta.N`、`-rc.N`，`N` 从 1 递增；预发布版本不进入稳定渠道；
- 构建元数据不参与优先级比较与范围匹配；
- 预发布版本默认不匹配任何依赖范围，除非范围显式包含相同 `MAJOR.MINOR.PATCH` 的预发布标识。

### 7.3 升级含义（插件）

| 级别 | 含义 |
|---|---|
| `MAJOR` | 接口行为、配置 schema、数据契约或依赖契约的不兼容变更 |
| `MINOR` | 向后兼容的新增功能 |
| `PATCH` | 向后兼容的缺陷修复 |

0.x 阶段按预发布语义执行：破坏性变更升 `MINOR`，并同步提供迁移步骤；升级后不得修改已发布版本的语义。

### 7.4 依赖版本范围

`manifest.dependencies[].version` 使用语义化版本范围，常用写法：

| 写法 | 匹配范围 |
|---|---|
| `*` | 任意非预发布版本 |
| `1.2.3` / `=1.2.3` | 精确匹配 |
| `^1.2.3` | `>=1.2.3 <2.0.0` |
| `^0.2.3` | `>=0.2.3 <0.3.0` |
| `~1.2.3` | `>=1.2.3 <1.3.0` |
| `>=1.0.0 <2.0.0` | 逻辑与 |
| `^1.0.0 \|\| ^2.0.0` | 逻辑或 |

规则：

- 只声明直接依赖；传递关系由解析器推导。
- 版本范围非法在安装校验阶段返回 `CPK_MANIFEST_INVALID`，在依赖解析阶段返回 `KERNEL_DEPENDENCY_VERSION`。
- 依赖不满足时插件保持 `pending`，不执行任何插件代码；依赖就绪后自动继续激活。

完整语法与匹配规则见 [04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §四。

### 7.5 禁止事项

- 禁止在同一版本号下发布两种语义，禁止降低已发布版本号。
- 禁止为兼容旧版本保留双读字段、别名映射或运行时分支（大爆炸重构，[ADR-010](../01-架构设计/ADR/ADR-010-大爆炸重构策略.md)）。
- 禁止绕过版本范围强推更新；更新必须满足全部已安装依赖者的范围。
- 禁止把插件配置 schema 的迁移逻辑放进文档解析器或渲染器；迁移与兼容边界见 [04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §六、§八。
