## 四、渲染与资源

### 4.1 为什么卡片资源路径不能写绝对路径？

- 正式文件只允许三类引用：包内相对路径（相对卡片根 / 箱子根）、正式绝对 URL（`file://`、`http(s)://`、`webdav://`）、受管 `chips-resource://`；裸绝对路径（`/Users/...`、`C:\...`）与 `blob:`、`data:` 一律禁止（R13，[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §8.2、[02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) §3.4）。
- 绝对路径不可移植、不可审计，跨用户、跨端与迁移后必然失效；运行时由渲染层把相对路径归一为 `chips-resource://<scope>/...` 后访问。
- 相对路径一律相对包根解析（卡片不相对 `content/` 目录），禁止 `..` 路径逃逸。

### 4.2 为什么渲染帧内不能使用 window.chips？

查看态卡片 / 布局运行在 `sandbox="allow-scripts"` 的 iframe 帧内，帧内不提供 `window.chips`、存储与网络直连。帧内需要打开文档、复制、通知、请求条目时，经帧运行时句柄或 `frame:action` 转发给 RenderHost，由 RenderHost 经 Bridge 执行权限判定与审计（[08-基础卡片插件接口](../05-接口与契约/08-基础卡片插件接口.md) §5.4、[09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) §6.1）。`window.chips` 只在就近渲染容器与应用窗口渲染进程可用。

### 4.3 资源加载失败 / 空白怎么排查？

- 按 `ChipsError.code` 定位：URI 非法 `RESOURCE_INVALID_URI`；scheme 不支持 `RESOURCE_UNSUPPORTED_SCHEME`；路径非法（穿越、绝对路径、编码）`RESOURCE_PATH_INVALID`；无权限 `RESOURCE_PERMISSION_DENIED`；不存在 `RESOURCE_NOT_FOUND`（[06-资源协议规范](../05-接口与契约/06-资源协议规范.md) §7.2）。
- 核对引用形态合法、目标作用域已注册、会话已获授权；外部资源另查 `RESOURCE_NETWORK_FAILED`，其 `details.reason` 区分 DNS / 连接 / TLS / 超时 / 重定向 / 拦截。
- 渲染层必须显示占位或错误态，不得静默空白（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §5.3）。

### 4.4 read() 返回 RESOURCE_TOO_LARGE 怎么办？

`read()` 与单条内存缓存上限为 8 MiB，超过时改用 `readRange(offset, length)` 或 `stream()`；单资源上限 2 GiB，超限同样返回 `RESOURCE_TOO_LARGE`（[06-资源协议规范](../05-接口与契约/06-资源协议规范.md) §6.6、§9.3）。同一句柄同时只服务一个流，流打开期间调用 `readRange()` 返回 `RESOURCE_BUSY`。

### 4.5 资源句柄失效了怎么办？

- `onInvalidate` 给出 `source-changed` / `session-closed` / `scope-revoked` 三种原因；失效后读操作返回 `RESOURCE_HANDLE_INVALIDATED`，不得复用旧句柄，应重新调用 `resource(uri)` 获取新句柄（[06-资源协议规范](../05-接口与契约/06-资源协议规范.md) §6.3-§6.5）。
- `release()` 必须显式调用且幂等；会话关闭时平台强制释放全部句柄，插件不得把强制回收当作正常清理路径。

### 4.6 为什么 renderView / renderLayout 会被多次调用？

视图更新时同一容器会以新模型再次调用：每次调用必须让容器呈现传入模型的完整内容（覆盖式更新或自行 diff），并在创建新效果前清理上一轮生命周期短于帧的效果（事件监听、定时器、Observer、媒体播放）；返回的 `Dispose` 只负责本次调用建立的效果且必须幂等（[08-基础卡片插件接口](../05-接口与契约/08-基础卡片插件接口.md) §2.4.1、[09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) §3.3）。

### 4.7 编辑器的改动如何保存？

编辑器不写文件、不直接操作会话：回流唯一时序为 `getChange()` → 编辑链路校验（`configSchema` + `validateConfig`）→ `document:write`（返回 `{ revision }`）→ 渲染会话 `update(view, revision)` → `markCommitted(revision)`（[08-基础卡片插件接口](../05-接口与契约/08-基础卡片插件接口.md) §4.3）；持久化由文档链路经 `document:save`（`resources:write`）完成。`dispose()` 会丢弃未提交变更，需要保留时由编辑链路在释放前先行回流。

### 4.8 布局插件可以自己读取条目文件吗？

不能。条目完整内容由平台管理的条目帧渲染：布局插件对可见条目调用帧运行时的 `requestEntries` 取得票证，再 `mountEntry` 挂载进槽位容器（[09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) §6.2）。禁止读取条目文件、解析 YAML、`import` 条目代码、创建非受管 iframe，或把条目 `url` 直接赋给 `iframe.src`；条目级失败由平台显示占位，插件不得使整箱失败。

### 4.9 箱子条目很多时如何保证性能？

条目数超过 200 时布局插件必须虚拟化：只为可见范围 ± overscan（默认 2）请求与挂载条目帧，滚出范围立即释放句柄；高度未知时用票证的 `estimatedHeight` 或平台高度缓存占位（[09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) §6.3）。资源下载、缓存与去重由平台承担，插件不得自建缓存。

### 4.10 打开与读写文档用哪些能力？

- 打开：`document:open`，`source` 为受管引用；`documentId` 取自文档稳定标识（`card_id` / `box_id`），跨会话、跨重命名稳定。
- 读取：`document:read`，`part` 取 `metadata` / `structure` / `content` / `entries`，`content` 需带 `nodeId`。
- 写入：`document:write` 只改内存模型，`document:save` 才落盘；卡片与箱子共用同一套接口，仅模型切片与文件格式不同（R8，[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) §7.3）。

### 4.11 卡片封面为什么没有显示？

封面由封面帧独立渲染，`renderView` 不处理封面（[08-基础卡片插件接口](../05-接口与契约/08-基础卡片插件接口.md) §3 规则 7）。封面引用必须使用 `.card/`（箱子为 `.box/`）内部的相对路径；写入 `blob:`、`data:` 或系统绝对路径会导致封面无法解析且校验不通过（[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §7.5、[02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) §7.2）。

### 4.12 外部网络资源如何访问？

- 卡片 / 箱子中的 `http(s)://` 引用归一为 External URI；显式访问需同时具备 `resources:read:external` 与 `network:http:<host>`（[06-资源协议规范](../05-接口与契约/06-资源协议规范.md) §4.3、§8.4）。
- External 只读、默认不携带 Cookie / Authorization；每次解析与每次重定向都执行 SSRF 校验，重定向最多 5 跳。
- 需要自定义请求方法 / 请求头时使用 `http:request` 能力，而不是资源通道（[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) §7.10）。

### 4.13 资源写入怎么做？

句柄只读，不提供写入方法。写入边界：document 挂载（目录态与归档态）内的写入经文档服务受控提交（`document:write` / `document:save`，`resources:write`）；`document:export` 只读源文档（`resources:read`）并写目标路径（`filesystem:write`）；`resource:write` 仅用于插件作用域与临时作用域，自身作用域写入同样需要 `resources:write`（[06-资源协议规范](../05-接口与契约/06-资源协议规范.md) §4.3）。对归档来源就地写入返回 `RESOURCE_READ_ONLY`，由文档保存流程重建归档。
