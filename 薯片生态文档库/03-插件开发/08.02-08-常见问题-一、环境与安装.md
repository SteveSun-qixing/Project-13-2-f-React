## 一、环境与安装

### 1.1 开发插件需要哪些工具链与版本？

- 桌面壳要求 Electron >= 27.x、Chromium >= 118、Node.js >= 18 LTS（[ADR-002](../01-架构设计/ADR/ADR-002-Electron作为桌面端壳.md)）。
- Node 生态唯一包管理器为 pnpm，根清单声明 `packageManager: pnpm@9`，禁止 npm / yarn 混用（[01-代码组织规范](../02-开发规范/01-代码组织规范.md) §2.3、§8.2）。
- 前端技术栈为 React 18+、`@chips/ui`、TypeScript（[ADR-008](../01-架构设计/ADR/ADR-008-React加fork-antd前端技术栈.md)）；测试栈为 vitest + jsdom。
- 只有开发平台本体才需要 Rust：`rust-version = "1.75"`、`edition = "2021"`（[04-Rust编码规范](../02-开发规范/04-Rust编码规范.md) §1.1）。

### 1.2 如何从零创建一个插件？

- 工程生成由 `@chips/cli` 执行，模板与文件计划来自 `@chips/sdk/scaffold`；生成器是纯函数，只产出文件计划与结构化 manifest，不写盘、不联网、不安装依赖（[02-SDK-API规范](../05-接口与契约/02-SDK-API规范.md) §8.1、§8.3）。
- 脚手架覆盖四种角色，生成结果可直接通过 manifest 校验与 `.cpk` 校验。
- 完整分步流程（创建 → 运行调试 → 打包发布）见 [01-快速开始](./01-快速开始.md)。

### 1.3 开发插件需要安装 Rust 工具链吗？

不需要。Rust 核心（Cordis 运行时、Bridge、文档解析、资源管理）属于平台并随平台分发；插件使用 `@chips/sdk` 与 `window.chips` 即可完成开发。插件包不得携带任何原生可执行载荷（R11）；需要系统能力时经 Bridge 申请。

### 1.4 插件仓库应该如何组织？

- 每个插件是独立代码仓库，独立版本管理与独立发布；官方插件源码位于 `plugins/<目录名>`，包名 `@chips/plugin-<目录名>`（[01-代码组织规范](../02-开发规范/01-代码组织规范.md) §3.2）。
- 插件根目录含 `manifest.yaml`、`src/` 与静态资源；构建产物为 `dist/index.js`、`render.js` 与 `.cpk`。
- 插件依赖只允许 `@chips/ui` 与 `@chips/sdk`；禁止依赖其它插件或平台内部包（依赖矩阵见 [01-代码组织规范](../02-开发规范/01-代码组织规范.md) §4.2）。

### 1.5 可以使用 npm 或 yarn 吗？

不能。Node 生态唯一包管理器为 pnpm；工作区内部依赖只允许 `workspace:*`，禁止 `file:` / `link:` 路径依赖与写死版本号（[01-代码组织规范](../02-开发规范/01-代码组织规范.md) §2.3、§3.4）。

### 1.6 开发态如何加载插件、如何热重载？

- 开发目录来源为 `development`，发现优先级高于 `user` 与 `builtin`；同一 ID 时高优先级来源生效，其余来源被遮蔽但不删除文件（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §4.1）。
- 目录态布局与 `.cpk` 解包后的包根完全一致；开发态跳过归档与签名校验，仍执行 manifest、入口、原生载荷、路径安全与角色布局校验（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §2.7）。
- 开发态热重载复用蓝绿替换流程，不重启平台；调试工具与场景见 [07-调试与发布](./07-调试与发布.md)。

### 1.7 插件安装后放在哪里？来源优先级如何？

- 插件来源按优先级从高到低：`development`（开发目录）→ `user`（用户插件目录，安装落盘位置）→ `builtin`（随平台分发）。
- 同一来源内同 ID 多个版本时取版本最高者，其余记录为冲突并报告；内置插件不可卸载，只能停用（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §4.1、§4.5）。

### 1.8 单元测试用什么工具，Mock 从哪里来？

- 测试栈为 vitest + jsdom；Mock Bridge 从 `@chips/sdk/testing` 导入，禁止在插件测试中引用 `@chips/bridge`、`@chips/host` 内部实现（[02-SDK-API规范](../05-接口与契约/02-SDK-API规范.md) §7.1）。
- `installMockBridge()` 把 Mock 安装到 `globalThis.window.chips`；能力桩、事件触发、资源夹具、调用记录与断言辅助见 §7.2。
- Mock 只模拟调用结果，不执行权限判定与 schema 校验；覆盖率与用例要求见 [05-测试规范](../02-开发规范/05-测试规范.md)。
