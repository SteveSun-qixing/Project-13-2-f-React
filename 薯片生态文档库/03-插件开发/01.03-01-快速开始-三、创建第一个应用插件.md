## 三、创建第一个应用插件

### 3.1 一条命令创建

```bash
pnpm exec chips plugin create \
  --role app \
  --id chips.example.hello-world \
  --name "你好世界" \
  --dir examples/plugins/hello-world
```

- `chips` 是开发者 CLI `@chips/cli` 的命令，负责创建插件、打包 `.cpk`、校验 manifest 与文件格式（[01-代码组织规范](../02-开发规范/01-代码组织规范.md) §3.3）；`pnpm exec` 保证使用工作区内的同一版本，与后文的打包、校验命令口径一致（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §7.2）。
- 模板与文件计划来自 `@chips/sdk/scaffold`：生成器是纯函数，只产出路径与内容，不写盘、不联网、不安装依赖，落盘由 `@chips/cli` 完成（[02-SDK-API规范](../05-接口与契约/02-SDK-API规范.md) §8.1、§8.3）。
- 生成结果必然通过 manifest 校验与插件包格式校验（[02-SDK-API规范](../05-接口与契约/02-SDK-API规范.md) §8.1）；四角色模板文件清单见同文档 §8.2。

参数说明：

| 参数 | 本课取值 | 说明 |
|---|---|---|
| `--role` | `app` | 插件角色四选一；本文创建应用插件 |
| `--id` | `chips.example.hello-world` | 反向域名插件 ID，全局唯一、发布后不得变更；官方命名空间用 `chips.official.*` / `chips.basecard.*` / `chips.layout.*` / `chips.service.*`，第三方使用自有域（R20、[02-插件清单规范](./02-插件清单规范.md) §3.1） |
| `--name` | `你好世界` | 非空简体中文显示名，用于插件列表、启动器与授权界面 |
| `--dir` | `examples/plugins/hello-world` | 目标目录；官方插件放 `plugins/`，教学示例放 `examples/plugins/`（[01-代码组织规范](../02-开发规范/01-代码组织规范.md) §2.1、§3.2） |

预期输出：

```text
已创建 app 角色插件：chips.example.hello-world
目标目录：examples/plugins/hello-world
生成文件：manifest.yaml、package.json、tsconfig.json、src/index.ts、src/ui/AppView.tsx、assets/icons/app.svg
下一步：pnpm install 建立工作区链接，然后执行 pnpm dev 启动开发环境
```

新包加入工作区后重新安装依赖：

```bash
pnpm install
```

### 3.2 目录结构

```text
examples/plugins/hello-world/
├── manifest.yaml            # 唯一权威清单（必需）
├── package.json             # 工作区包 @chips/plugin-hello-world
├── tsconfig.json            # 继承仓库 tsconfig.base.json
├── src/
│   ├── index.ts             # app 主逻辑入口（构建为 dist/index.js）
│   └── ui/
│       └── AppView.tsx      # 应用窗口 UI 根组件（构建为 render.js）
├── assets/
│   └── icons/
│       └── app.svg          # 启动器图标
└── dist/                    # 构建与打包产物（自动生成，不入库）
```

| 路径 | 约定 |
|---|---|
| `manifest.yaml` | 包内唯一权威清单；标识、版本、角色、依赖、权限、角色能力都在此声明，字段见 [02-插件清单规范](./02-插件清单规范.md) |
| `package.json` | 工作区包名 `@chips/plugin-<目录名>`，提供 `build` / `test` / `lint` / `clean` / `package` 标准脚本（[01-代码组织规范](../02-开发规范/01-代码组织规范.md) §3.4、§8.1） |
| `tsconfig.json` | 继承仓库共享配置，不在包内重复定义编译选项（[01-代码组织规范](../02-开发规范/01-代码组织规范.md) §2.3） |
| `src/index.ts` | `IAppPlugin` 实现；模块顶层只允许声明，不产生副作用 |
| `src/ui/AppView.tsx` | 应用窗口 UI；经 `@chips/ui` 使用组件，经 `chips`（`window.chips`）访问平台 |
| `assets/` | 静态资源；manifest 只允许以包内相对路径引用，且目标必须位于 `assets/` 内（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §2.5、§2.6） |

### 3.3 清单 `manifest.yaml`

```yaml
id: chips.example.hello-world
version: 0.1.0
type: app
name: 你好世界
description: 第一个应用插件：打开一个窗口并显示问候
author: 薯片示例
license: MIT
runtime:
  targets: [host]
  background: false
ui:
  surface: window
  launcher:
    icon: assets/icons/app.svg
    name: 你好世界
    description: 第一个应用插件
```

说明：

- `type: app` 决定角色与入口接口（R1）；`ui.surface: window` 是标准窗口应用，`ui.launcher` 注册启动器入口（[02-插件清单规范](./02-插件清单规范.md) §7.4）。
- 本插件不访问文件、网络等系统能力，`permissions` 为空——最小权限是默认做法（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md)）。
- `version` 必须与 `package.json` 的 `version` 一致，否则打包与安装拒绝（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §7.1）。
- 启动器图标使用包内相对路径，运行时由平台解析为插件作用域资源，插件不得自行拼接 `chips-resource://` URI（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §2.6）。

### 3.4 主逻辑 `src/index.ts`

```typescript
import type { IAppContext, IAppPlugin } from '@chips/sdk';

class HelloWorldApp implements IAppPlugin {
  public async launch(ctx: IAppContext): Promise<void> {
    if (ctx.window === null) {
      return;
    }
    await ctx.window.setTitle('你好世界');
  }
}

export default new HelloWorldApp();
```

- 入口模块默认导出 `IAppPlugin` 实现；模块顶层只声明，全部副作用放入 `launch`（[07-应用插件接口](../05-接口与契约/07-应用插件接口.md) §3.1）。
- 主窗口句柄由平台按 manifest 创建，属免权限范围；运行中额外创建窗口必须经 `window:create` 能力（[07-应用插件接口](../05-接口与契约/07-应用插件接口.md) §4.4）。
- 示例未声明文件关联与命令，启动来源只有启动器；`ctx.args` 的三种来源与不变量见 [07-应用插件接口](../05-接口与契约/07-应用插件接口.md) §4.3。

### 3.5 界面 `src/ui/AppView.tsx`

```tsx
import React from 'react';
import { Button, ChipsProvider } from '@chips/ui';

const APP_ID = 'chips.example.hello-world';

const AppContent: React.FC = () => {
  const [count, setCount] = React.useState(0);

  return (
    <div>
      <p>你好，世界！这是你的第一个薯片应用插件。</p>
      <Button onClick={() => setCount((value) => value + 1)}>
        点击次数：{count}
      </Button>
    </div>
  );
};

export const AppView: React.FC = () => {
  return (
    <ChipsProvider appId={APP_ID} surface="window">
      <AppContent />
    </ChipsProvider>
  );
};

export default AppView;
```

- 窗口 UI 经构建产出为 `render.js`，由平台窗口壳装载；React 与 `@chips/ui` 由宿主统一提供并被构建外部化，插件包内不得重复打包（R4、[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §2.4）。
- **UI 根环境职责（唯一口径，工单 002 收口）**：主题根 `ChipsProvider` 由应用窗口 UI 入口（`render.js` 默认导出组件）自行挂载一次并包裹整个界面树，`surface` 取值与 manifest `ui.surface` 一致；平台窗口壳**不**提供主题根，同一窗口内不得重复挂载或在子树上另建主题根（[08-@chips/ui 共享层使用指南](../02-开发规范/08-@chips-ui共享层使用指南.md) §3.1）。`CommandProvider` 仅在注册 ui 目标命令时叠加挂载，本示例未注册故不挂载。
- 组件写法遵循 [03-React组件开发规范](../02-开发规范/03-React组件开发规范.md)；需要访问平台能力时经 `chips`（`window.chips`）调用，不得直连 Node.js / Electron API（R17）。
