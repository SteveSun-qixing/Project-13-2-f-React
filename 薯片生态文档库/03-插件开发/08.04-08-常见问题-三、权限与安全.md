## 三、权限与安全

### 3.1 为什么必须经 Bridge 访问系统能力？

- Bridge 是插件访问薯片平台的唯一运行时入口（`window.chips` 只有 `request` / `subscribe` / `resource` 三个方法）；权限判定、Schema 校验与审计全部在这一层完成（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md)）。
- 渲染进程由 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true` 隔离；直接访问 Node.js / Electron / 系统 API、绕过 Bridge 自建 IPC 或读写全局对象的插件不予加载（R17、[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §11）。
- `@chips/sdk` 只做类型化转发，不承载任何运行时实现。

### 3.2 为什么 manifest 声明了权限，调用仍返回 BRIDGE_PERMISSION_DENIED？

- 声明不等于授予：安装只记录申请集合（默认未授权），授权在首次启用确认或目标首次调用确认后写入；运行时按"能力所需权限 ∩ 会话快照 + 限定值匹配"判定（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §2.2、§7.2）。
- 常见原因：用户拒绝了该项、调用目标超出限定值、授权被撤销后旧快照立即失效。
- 读取 `error.details`（`permission`、`required`、`missing`、`granted`、`reason`、`target`）定位，禁止匹配 `message`。

### 3.3 能力 ID 与权限 ID 有什么区别？

- 能力 ID 描述"做什么"：`<domain>:<action>[:<target>]`，如 `file:read`；权限 ID 描述"被允许访问什么范畴"：`<domain>:<scope>[:<qualifier>]`，如 `filesystem:read`（[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) §3.1）。
- 两者命名空间互相隔离，禁止同一标识既当能力又当权限（R3）；能力在 `permissions` 中只声明基础权限 ID，限定值只存在于 manifest 申请与授权记录。
- 能力 → 权限映射总表见 [04-能力契约规范](../05-接口与契约/04-能力契约规范.md) §6.2，不得自创未登记标识。

### 3.4 为什么路径限定必须使用目录变量，不能写死绝对路径？

- 权限申请与授权存储保留变量形式（如 `filesystem:read:${userDocuments}/chips`），展示与判定时才展开为实际路径；写死绝对路径会破坏跨用户、跨平台可移植性（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §3.3、§7.3）。
- 可用目录变量：`${userHome}`、`${userDocuments}`、`${userDownloads}`、`${userDesktop}`、`${userPictures}`、`${userMusic}`、`${userVideos}`、`${userData}`、`${temp}`。
- 判定会折叠 `..`、解析符号链接并做目录边界前缀比较（`/a/b` 不匹配 `/a/bc`），越界一律拒绝。

### 3.5 用户拒绝授权后还能重试吗？

- 用户拒绝后本次调用返回 `BRIDGE_PERMISSION_DENIED`（`details.reason = user_rejected`），同一会话内不再弹窗；勾选"不再询问"会写入 `denied`，后续调用直接拒绝（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §6.3）。
- 插件应提示用户到「设置 → 插件 → 权限」手动授予；恢复后会话快照重建，插件无需重启。
- 不得静默失败，也不得用错误文案推断授权状态。

### 3.6 为什么基础卡片插件不能申请 window:control？

角色适用性限制：`window:control`、`dialogs:use`、`shell:external` 仅 `app` 角色可申请；`basecard` / `boxlayout` 的界面在平台渲染容器内呈现，不申请窗口类权限。违规会在安装校验阶段返回 `PERMISSION_ROLE_NOT_ALLOWED`（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §5.3）。

### 3.7 插件之间可以借用权限吗？

不能。权限不继承、不转让、不代理；`dependencies` 不产生授权；服务插件执行能力内部访问时使用自身会话快照，不借用调用方权限，也不得代调用方申请权限（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §5.4、§11）。

### 3.8 凭证应该如何保存？

- 使用 `credential:get` / `credential:set` / `credential:delete` 能力（需 `credential:manage`），只能访问自身命名空间；`platform` 凭证对插件不可见（[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) §7.12）。
- 禁止把凭证值写入配置、事件、日志、审计或错误 `details`；配置中只保存 `credential://<pluginId>/<name>` 引用（format `chips-credential`）。

### 3.9 哪些访问属于免权限范围？

插件私有数据目录 `${userData}/plugins/<pluginId>/`、自身配置命名空间、自身资源作用域只读、`chips-resource://platform/...` 公开只读、以及 manifest `ui.surface` 声明的窗口本身，均不需要额外授权（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §4.4）。注意：任何资源写入（含自身作用域）仍需 `resources:write`，免权限范围不覆盖写入。

### 3.10 写日志需要权限吗？

不需要。插件日志免权限（R19），按插件命名空间自动归属，写入失败不抛出、不中断业务（[10-服务插件接口](../05-接口与契约/10-服务插件接口.md) §3.6）。日志禁止记录凭证值、文件内容、用户数据与资源字节；结构化细节放 `fields`，只允许标量。

### 3.11 窗口与帧的安全基线是什么？

`nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`，生产环境禁止关闭 `webSecurity`（R17）。插件不得替换 `window.chips`、不得引用 preload 内部模块或 `ipcRenderer`、不得创建子进程或加载原生载荷；帧内禁止 `parent` / `top` / 存储 / 网络直连。
