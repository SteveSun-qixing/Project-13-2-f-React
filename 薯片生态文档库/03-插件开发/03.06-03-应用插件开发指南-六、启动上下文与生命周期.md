## 六、启动上下文与生命周期

### 6.1 IAppContext 组成

`IAppContext` 是内核 `Context` 在应用实例维度的受控视图，由实例字段与平台访问面两部分组成；未列出的成员即不可用。

| 成员 | 用途 |
|---|---|
| `appId` / `surface` / `launcher` / `args` / `window` | 实例字段：标识、生效表面、启动器信息、启动参数、主窗口句柄 |
| `lifecycle.beforeExit(handler)` | 注册退出前钩子；返回句柄可提前撤销，实例退出时自动撤销 |
| `bridge.request(capabilityId, input)` / `bridge.resource(uri)` | 主进程出站能力与资源访问 |
| `config.get/snapshot/set/reset/watch` | 自身命名空间配置访问，`key` 为相对键 |
| `on` / `once` / `emit` | 内核事件订阅、一次性订阅与自有域事件发布（`emit` 不跨进程） |
| `inject(dependencies, callback)` | 声明服务依赖并注入回调；消费其他插件的服务须在 manifest `dependencies` 声明提供方 |
| `effect(cleanup)` | 登记平台未内建追踪的清理（定时器、连接器等）；必须幂等且不抛出 |
| `logger.debug/info/warn/error` | 平台日志流，按插件隔离 |
| `exit(code?)` | 请求结束本应用实例；幂等 |

规则：

- 平台在每次启动时构造新对象；实例退出后该对象失效，其上登记的订阅、注入回调与清理自动撤销；再次启动得到新对象。
- 实例字段只读，不得跨实例缓存复用 `IAppContext` 与 `IAppWindow`。
- 访问面之外的内核结构（全局对象、平台内部状态、Node.js / Electron API）一律不可访问。

### 6.2 主窗口句柄 IAppWindow

| 成员 | 说明 |
|---|---|
| `id` | 窗口 ID，与 `window:created` / `window:closed` 事件的 `windowId` 同值 |
| `setTitle(title)` | 设置窗口标题；`desktop` 表面忽略该调用 |
| `setSize(width, height)` | 设置窗口内容尺寸（像素） |
| `focus()` | 聚焦并置前窗口 |
| `close()` | 关闭窗口；`window` 表面且 `background` 为 `false` 时触发实例退出 |

规则：

- 主窗口句柄属免权限范围；运行中创建额外窗口、操作非自身窗口一律经 `window:*` 能力。
- 窗口已关闭后调用返回 `APP_WINDOW_CLOSED`。
- `tray` 表面没有主窗口，应用应把 `ctx.window` 视为 `null` 处理。

```typescript
private async applyTitle(title: string): Promise<void> {
  const appWindow = this.context?.window ?? null;
  if (appWindow === null) {
    return;
  }
  await appWindow.setTitle(title);
}
```

### 6.3 beforeExit 与退出

`beforeExit(handler)` 在退出流程开始时调用，每个实例每轮退出恰好一次，用于保存未保存状态、刷新配置、释放业务资源：

- 不可取消退出：钩子只能做收尾，不能阻止实例结束；钩子抛出或超时被平台捕获并记录，退出继续。
- 实例退出时自动撤销全部 `beforeExit` 订阅；返回值仅用于提前撤销。
- 其他生命周期信号经标准事件获取：`app:launched`、`app:exited`、`window:closed`。

`exit(code?)` 请求平台结束本应用实例：幂等，`code` 随 `app:exited` 的 `exitCode` 透出。退出原因：

| reason | 触发 |
|---|---|
| `user` | 用户关闭主窗口（`window` 表面且 `background: false`）或应用调用 `exit()` |
| `platform` | 平台停用、卸载或更新该插件 |
| `shutdown` | 平台整体退出 |
| `failure` | 实例异常崩溃，由平台回收 |

退出后插件仍为 `active`，再次启动会创建新实例并重新调用 `launch`。

### 6.4 实例生命周期

```
启动器 / 文件关联 / 命令
        │
        ▼
平台解析意图（构造 ctx.args）
        │
        ├─ 无实例 ──► 创建表面 ──► launch(ctx) ──► active ──► 发布 app:launched
        │                             │ 拒绝
        │                             └──► APP_LAUNCH_FAILED，回收副作用
        │
        └─ 已有实例 ──► launching：排队；active：投递 handleCommand / openFile，或聚焦窗口
                                            │
                                            ▼
                              退出：beforeExit ──► 关闭窗口 ──► 回收副作用 ──► 发布 app:exited
```
