> 适用范围：面向任务的 `service` 角色插件开发教程：工程与清单、`IServicePlugin` / `IServiceContext` 使用、后台运行与生命周期、健康检查、Bridge 能力注册、配置与日志，以及一个可运行的最小服务插件完整示例。

## 十一、自检清单

- [ ] `manifest.type` 为 `service`，`runtime.targets` 包含 `host`，未声明 UI 与其它角色字段。
- [ ] `permissions` 只包含实际使用的权限：出站能力所需权限（如 `filesystem:read`）已声明，范围最小化；不含日志权限。
- [ ] `runtime.background`、`healthCheck` 取值合法；`timeout` 小于 `interval`；声明 `healthCheck` 时已实现 `health()`。
- [ ] `start`、`stop` 已实现；`start` 内完成全部注册与副作用登记；`stop` 幂等、不抛出。
- [ ] 所有副作用（服务、能力、订阅、定时器、资源句柄）均纳入 Fork 或 `effect` 追踪；无跨激活内存状态与进程级单例。
- [ ] 注册能力的 ID 已在平台登记且提供方绑定一致；schema 符合 E4 第五节；能力声明的权限已在 manifest 声明。
- [ ] 能力 `execute(input, ctx)` 响应 `ctx.signal` 并在 `ctx.deadline` 前收口；取消时释放已占用资源。
- [ ] 能力 `execute` 异步、无阻塞、不假设调用方身份；输出为结构化克隆兼容值；错误使用结构化 `ChipsError`。
- [ ] 出站访问只经 `ctx.bridge` / `ctx.config` / `ctx.on` / `ctx.emit`；无 `node:*`、`electron`、Node.js 或系统 API 直连。
- [ ] 配置键为自身命名空间相对键；默认值写在 `assets/schemas/config.schema.json`；插件不直接读写配置文件。
- [ ] 日志不包含凭证、文件内容、用户数据与资源字节；错误按 `ChipsError.code` 处理，无静默吞错与 `any` 类型。
