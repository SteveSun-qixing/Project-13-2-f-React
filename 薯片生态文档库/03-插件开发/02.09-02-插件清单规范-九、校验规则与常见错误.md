## 九、校验规则与常见错误

### 9.1 校验时机与流程

```
编写 manifest.yaml
      │
      ├─ 打包前：pnpm exec chips plugin validate <目录或 .cpk>
      │        （与安装校验同源；见 04-文件格式规范/03-插件包格式 7.2）
      ▼
[1] 归档校验 ── [2] 结构校验 ── [3] 清单校验 ── [4] 签名校验 ── [5] 摘要与落盘
                                    │
                                    │ schema 校验 + 字段级校验 + 路径引用 + 与包内容一致
                                    ▼
                           失败 → CPK_MANIFEST_INVALID / CPK_MANIFEST_MISSING
                                    │
                                    ▼
启用校验：权限角色适用性、依赖解析（pending/failed）、healthCheck 与 health() 配套
```

- 清单校验属于安装校验第 [3] 阶段，完整流程见[03-插件包格式](../04-文件格式规范/03-插件包格式.md) 第五节；本文规则是该阶段的判定依据。
- 校验失败必须携带结构化 `details`：阶段（`manifest`）、成员路径、字段指针（如 `capabilities.cardTypes[0].icon`）；面向用户的消息为简体中文（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) 第八节）。
- 启用阶段的失败按插件状态机处理：依赖未满足转 `pending`，激活失败转 `failed`（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 4.3）。

### 9.2 字段级校验规则

| 字段 | 校验 |
|---|---|
| `id` | 必填；反向域名文法；不得与已登记插件冲突（同 ID 走更新流程） |
| `version` | 必填；语义化版本；与源码 `package.json` 一致 |
| `type` | 必填；四取值之一；决定专有字段与包内布局校验分支 |
| `name` | 必填；非空字符串 |
| `description` / `author` / `license` | 选填；填写时须为非空字符串 |
| `runtime` | 必填对象；`targets` 非空、去重、仅 `host`；`background` 为布尔且可选，非 `service` 不得为 `true` |
| `engines` | 选填对象；仅允许 `chips` 一个键；`chips` 为合法且非空的版本范围；声明时当前平台版本必须落在范围内（第 3.6 节） |
| `dependencies` | 选填数组；每项恰含 `id` 与 `version`；`id` 合法且非自身；版本范围语法合法 |
| `permissions` | 选填字符串数组；域与 scope 已注册；限定值文法与必需性合法；角色适用 |
| `capabilities` | 仅 `basecard` / `boxlayout`；`cardTypes` 与 `layouts` 互斥；对应键至少一项 |
| `capabilities.cardTypes[]` | `id` 符合文法且与 04/01 各类型 Schema 的 `card_type` 一致（未登记类型按 04/01 §6.10），全局唯一；`name` 非空；`icon` / `configSchema` 位于 `assets/` 且存在；`configSchema` 合法 JSON Schema；`aliases` 每项为合法类型 ID 且不与任何类型的正式 `id` 或其他别名冲突；`exportFormats` 条目字段完整、`mimeType` 合法 |
| `capabilities.layouts[]` | `id` 匹配 `chips.layout.*` 且全局唯一；`name` 非空；`icon` 位于 `assets/` 且存在；`configSchema` 位于 `assets/`、存在且为合法 JSON Schema；`schemaVersions` 为合法且非空的版本范围 |
| `ui` | 仅 `app`；`surface` 必填且取值合法 |
| `ui.launcher` | 选填；`icon` 位于 `assets/` 且存在；`name` / `description` 非空字符串 |
| `fileAssociations` | 仅 `app` / `service`；`extensions` 含点、小写、无重复且与 `mimeTypes` 至少一项非空；`mimeTypes` 为小写精确 MIME 或主类型通配（`*/*` 不允许）；`tier` 取 `primary` / `fallback`；`action` 为 `open` |
| `deepLinks` | 仅 `app`；每项含 `scheme` 与 `host`，`pathPattern` 可选；`scheme` / `host` 非空且插件内唯一；`scheme` 不得占用系统保留 scheme |
| `healthCheck` | 仅 `service`；`interval` / `timeout` 时长格式合法；`interval ≥ 1s`；`timeout < interval` |
| `cli` | 仅 `app` / `service`；对象只含 `commands`；`commands` 为非空数组 |
| `cli.commands[]` | `commandPath` 段文法合法、至少一段、第一段不命中固定命令根、插件内大小写归一后唯一；`title` 非空简体中文；`target.type` 等于插件角色；`app` 必填 `commandId` 且符合 `<domain>:<action>` 文法，`service` 禁止 `commandId` / `surface` / `job`；`permissions` 均为已登记权限 ID；参数模型（类型、`position`、`short`、`mapsTo`、`path`、`batch`、`validation`、`ui`）合法（[CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §5.1、§5.2） |
| 未登记字段 | 一律拒绝（封闭 schema） |

### 9.3 交叉一致性规则

1. `type` 与专有字段组必须对应：`basecard` ↔ `capabilities.cardTypes`；`boxlayout` ↔ `capabilities.layouts`；`app` ↔ `ui` / `deepLinks`；`service` ↔ `background` / `healthCheck`（第 7.1 节）。
2. `capabilities.cardTypes[].id` 必须与卡片文件写入的 `card_type` / 结构条目 `type` 一致，取值以 04/01 各类型 Schema 的 `card_type` 为准（历史别名仅读取归一）；`capabilities.layouts[].id` 必须与箱子 `active_layout_type` 一致（`chips.layout.*`）。
3. 清单中全部路径引用必须是包内相对路径且位于 `assets/` 内；平台在运行时把它们解析为 `chips-resource://<pluginId>/...` 形式的插件作用域 URI，插件不得自行拼接作用域 URI。
4. `manifest.version` 与源码 `package.json` 的 `version` 必须一致；`.cpk` 不得出现与清单冲突的标识、版本或角色声明。
5. 声明 `healthCheck` 必须实现 `health()`；声明 `exportFormats` 必须实现 `export`；`service` 声明 `fileAssociations` 必须实现 `handleFile`（[10-服务插件接口](../05-接口与契约/10-服务插件接口.md) §7.5）。
6. `permissions` 中的每一项必须是权限 ID；能力 ID 与权限 ID 不得相同（R3）。
7. `service` 包内不得出现 `render.js` 与 UI 资源；`basecard` / `boxlayout` / `app` 包内必须存在 `render.js`（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) 3.1）。
8. `capabilities.layouts[].configSchema` 必须描述 `layout_configs.<id>.props` 的实际结构；`capabilities.layouts[].schemaVersions` 必须覆盖插件实现支持渲染与编辑的 `schema_version`（[09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) 2.2、7.2）。
9. `cli.commands[].target.type` 必须与插件 `type` 一致（`app` → `app`、`service` → `service`）；`app` 目标的 `commandId` 指向 [13-命令系统契约](../05-接口与契约/13-命令系统契约.md) 登记的命令记录，存在性在运行时校验，不在打包期校验（[CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §5.3）。

### 9.4 常见错误

| 现象 | 根因 | 结果与错误码 | 修正 |
|---|---|---|---|
| 安装被拒：找不到清单 | 包根缺少 `manifest.yaml` 或存在多份 | `CPK_MANIFEST_MISSING` | 包根保留唯一 `manifest.yaml` |
| YAML 解析失败 | 缩进、引号或含特殊字符的值未引用 | `CPK_MANIFEST_INVALID` | 修正 YAML 语法；`>` / `*` / `$` 开头的值加引号 |
| `id` 非法 | 大写、下划线、单段或含空格 | `CPK_MANIFEST_INVALID` | 改为反向域名小写形式 |
| `type` 非法 | 拼写错误或试图声明多种角色 | `CPK_MANIFEST_INVALID` | 取四角色之一；多角色拆包（R1） |
| `basecard` 无 `cardTypes` | 专有字段缺失 | `CPK_MANIFEST_INVALID` | 声明至少一项卡片类型 |
| 卡片类型 ID 与 04/01 定义不符 | 使用未登记标识或历史别名 | `CPK_MANIFEST_INVALID` | 改用 04/01 的正式 `card_type`（如 `VideoCard`、`base.richtext`；R20） |
| 布局 ID 不是 `chips.layout.*` | 使用裸 ID 或旧命名空间 | `CPK_MANIFEST_INVALID` | 改为 `chips.layout.<name>`（R20） |
| 图标 / schema 路径无效 | 绝对路径、`file://`、不在 `assets/` 或目标缺失 | `CPK_MANIFEST_INVALID`（`details.pointer` 指向字段） | 改为包内相对路径且移入 `assets/` |
| 角色声明了禁用的专有字段 | 如 `service` 声明 `ui`、`app` 声明 `cardTypes` | `CPK_MANIFEST_INVALID` | 删除非本角色字段 |
| `background: true` 出现在非 `service` | 角色越界 | `CPK_MANIFEST_INVALID` | 删除或改由 `service` 声明 |
| 依赖条目重复 | 同一 `id` 声明两次 | `KERNEL_DEPENDENCY_DUPLICATE`（启用解析） | 合并为一条并合并版本范围 |
| 版本范围语法错误 | 使用 `latest`、`~>`、区间写法 | `CPK_MANIFEST_INVALID`；解析期 `KERNEL_DEPENDENCY_VERSION` | 改用[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) 第四节的写法 |
| `engines.chips` 不含当前平台版本 | 平台版本超出插件声明范围 | 安装 / 启用 / 更新拒绝，`CPK_ENGINE_UNSUPPORTED` | 升级平台版本或改用兼容的插件版本（第 3.6 节） |
| 依赖未安装 / 版本不满足 | 提供方缺失或版本偏低 | `KERNEL_DEPENDENCY_MISSING` / `KERNEL_DEPENDENCY_VERSION`，插件 `pending` | 安装或更新提供方插件 |
| 权限 ID 未注册 | 自造权限或把能力 ID 写入 | `PERMISSION_UNKNOWN` | 改用[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) 6.2 的权限 ID |
| 权限限定值非法或缺失 | 路径型权限未写限定值、禁止限定值的权限携带限定值 | `PERMISSION_INVALID` | 按第 6.2 节限定值规则修正 |
| 权限不适用于该角色 | 如 `basecard` 申请 `window:control` | `PERMISSION_ROLE_NOT_ALLOWED` | 删除或改由 `app` 申请 |
| `healthCheck` 时长格式或关系错误 | 写 `30`（无单位）、`1.5s` 或 `timeout >= interval` | `CPK_MANIFEST_INVALID` | 使用 `<正整数><单位>`，且 `timeout < interval` |
| 声明 `healthCheck` 未实现 `health()` | 接口与清单不配套 | 启用校验失败，插件不得进入 `active` | 实现 `health()` 或移除 `healthCheck` |
| 清单超过 256 KiB | 大段内联 schema 或注释 | `CPK_LIMIT_EXCEEDED` | 移出内联内容，改用 `assets/` 内文件引用 |
| `runtime.targets` 含 `web` | 平台不提供 `web` 目标 | `CPK_MANIFEST_INVALID` | 改为 `[host]` |
| `deepLinks` 的 scheme / host 非法或越角色 | scheme 未分配、host 重复或角色非 `app` | `CPK_MANIFEST_INVALID` | 使用平台分配的 scheme，修正角色与唯一性 |
| `cli.commands` 越角色 | `basecard` / `boxlayout` 声明 `cli` | `CPK_MANIFEST_INVALID` | 删除；CLI 扩展只属 `app` / `service`（第 7.6 节） |
| 命令路径命中固定命令根 | 第一段使用 `plugin`、`config`、`dev` 等保留名 | `CPK_MANIFEST_INVALID` | 更换命令路径首段（[CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §2.3） |
| `service` 目标声明 `commandId` / `surface` / `job` | 目标类型与字段不匹配 | `CPK_MANIFEST_INVALID` | 删除；`service` 目标只声明 `capability` |
| 出现未登记字段 | 拼写错误或沿用旧版字段 | `CPK_MANIFEST_INVALID` | 删除或改用本文登记字段 |
