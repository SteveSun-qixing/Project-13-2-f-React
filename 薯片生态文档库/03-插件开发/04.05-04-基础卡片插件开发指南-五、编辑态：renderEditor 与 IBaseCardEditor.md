## 五、编辑态：renderEditor 与 IBaseCardEditor

### 5.1 调用与容器

`renderEditor` 由编辑链路在**就近渲染容器**中调用，不经 iframe、不创建新帧（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §8）：编辑器运行在应用窗口渲染进程，允许经 `window.chips` 使用能力与资源句柄，权限判定与其它插件一致。

1. 每次调用创建一个独立编辑器实例，并以传入 `basecard` 的内容与配置完成挂载；同一容器不得并存两个 `IBaseCardEditor`。
2. 挂载时把容器内容替换为编辑器 UI；编辑结果不得写文件、不得直接操作渲染会话。
3. 抛出的异常由编辑链路按错误边界隔离，不得破坏宿主应用其余界面。
4. 编辑器尺寸由编辑面板布局决定，插件不得改变宿主布局。

### 5.2 IBaseCardEditor 与变更回流

`IBaseCardEditor` 是编辑器与编辑链路之间的唯一通道，成员集合以[08-基础卡片插件接口](../05-接口与契约/08-基础卡片插件接口.md) §4.1 为准：

```
插件编辑器                    编辑链路（IEditSession）        文档服务          渲染会话
   │ getChange()                │                             │                 │
   │───────────────────────────▶│ 校验 configSchema           │                 │
   │                            │ + validateConfig            │                 │
   │                            │ document:write ────────────▶│                 │
   │                            │◀──────────── { revision } ──│                 │
   │                            │ 组装新 DocumentView                            │
   │                            │ session.update(view, revision) ───────────────▶│
   │ markCommitted(revision)    │                             │                 │
   │◀───────────────────────────│                             │                 │
   │（基线前进、清除已提交变更）   │                                                │
```

实现要点：

1. `change` 与 `dirty` 事件同时可用；编辑链路既可订阅事件驱回流，也可用 `getChange()` 拉取；回流唯一时序为 `getChange` → 校验 → `document:write`（`{ revision }`）→ `update` → `markCommitted`。
2. 变更载荷用 `{ kind: 'replace', content }` 提交完整节点内容，或用 `{ kind: 'patch', operations }` 提交增量；`path` 为相对 `content` 根的 RFC 6901 指针。本示例编辑器只发布 `replace`，因此基线推进只需处理 `replace` 分支。
3. 同一任务或同一动画帧内的多次编辑应合并为一次变更发布，避免逐键回流。
4. 回流成功后编辑链路调用 `markCommitted(revision)`：以该 revision 更新基线并清除已提交变更；若期间产生新变更，`isDirty()` 保持为真。
5. 外部视图变化时编辑链路调用 `update(basecard, revision)`；`revision` 不大于编辑器已知值时忽略该调用，且调用前编辑器必须无待提交变更。
6. `dispose()` 释放全部订阅、DOM 与资源，不发布任何事件、不持久化数据；释放后 `getChange()` 返回 `null`、`isDirty()` 返回 `false`，其余行为为空操作。

### 5.3 React 编辑器实现方式

- 用 `createRoot` 挂载表单组件，`flushSync` 保证挂载完成后再返回 `IBaseCardEditor`；
- `update(basecard, revision)` 时以 `key={revision}` 重挂载表单，`initialValues` 取新视图，等价于替换编辑基线；
- 表单每次值变化调用句柄内部的草稿处理方法，由句柄统一维护 `pending`、脏状态与事件发布；
- `dispose()` 调用 `root.unmount()` 卸载 React 树，并清空全部订阅集合。
