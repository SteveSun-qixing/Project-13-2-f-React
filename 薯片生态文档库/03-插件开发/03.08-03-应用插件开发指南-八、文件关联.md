## 八、文件关联

### 8.1 声明与路由

manifest 声明（第四节）注册文件关联路由，平台按实例状态投递：

| 触发 | 无实例 | `launching` | `active` | `exiting` / 已退出 |
|---|---|---|---|---|
| 文件打开 | 创建实例，`launch`（`source: file-association`，含 `files`） | 排队；`launch` 成功后逐个 `openFile` | 逐个 `openFile` | 丢弃并记录诊断 |

规则：

- 启动意图只投递一次：初始文件随 `launch` 的 `ctx.args.files` 送达；运行中到达的才走 `openFile`。
- 多文件按传入顺序串行调用，前一次 settle 后才调用下一次；单个文件失败不阻断后续文件投递。
- 未实现 `openFile` 的插件收到文件请求时，平台返回 `APP_OPEN_FILE_UNSUPPORTED`。

### 8.2 openFile 实现

```typescript
public async openFile(uri: string): Promise<void> {
  if (!isSupportedUri(uri)) {
    throw new QuickNotesError(
      'APP_URI_INVALID',
      `只接受受管 file://（目录态、投递前已归一）或 chips-resource:// URI：${uri}`,
      { uri },
    );
  }
  await this.applyTitle(`${DEFAULT_TITLE} - ${fileNameOf(uri)}`);
}
```

### 8.3 URI 与内容读取约束

- `uri` 只接受已归一的受管引用（`chips-resource://`，或平台投递前按 [06-资源协议规范](../05-接口与契约/06-资源协议规范.md) §2.6 归一为受管作用域的 `file://`）；裸绝对路径、包内相对路径、`http(s)://` 与 `webdav://` 一律拒绝并返回 `APP_URI_INVALID`（与 [07-应用插件接口](../05-接口与契约/07-应用插件接口.md) §3.4 同口径）。
- 文件关联不代表授权；越权调用返回 `BRIDGE_PERMISSION_DENIED`，应用应向用户提示并引导授权。
- 文件内容读取不是 `openFile` 的隐含能力：受管读取经文档 / 资源链路（`document:*` 能力需 `resources:read`）；`bridge.resource(uri)` 只接受 `chips-resource://` 与 `http(s)://`，收到 `file://` 返回 `RESOURCE_UNSUPPORTED_SCHEME`（[06-资源协议规范](../05-接口与契约/06-资源协议规范.md)）。
- 需要读取用户文件的应用按最小范围申请文件权限，并把资源释放交给会话生命周期（资源句柄随会话销毁归还）。

### 8.4 深链接（deepLinks）

manifest `deepLinks` 声明注册深链接路由（[02-插件清单规范](./02-插件清单规范.md) §7.4）：

| 触发 | 无实例 | `launching` | `active` |
|---|---|---|---|
| 深链接 | 创建实例，`launch`（`source: deep-link`，`url`） | 排队；`launch` 成功后发布 `app:opened-with-url` | 发布 `app:opened-with-url` |

```yaml
deepLinks:
  - scheme: chips-quick-notes
    host: open
    pathPattern: /note/*
```

规则：

- 插件未运行时，URL 随 `ctx.args.url` 送达 `launch`；运行中到达的经标准事件 `app:opened-with-url`（`{ appId, url }`）投递（[05-事件契约规范](../05-接口与契约/05-事件契约规范.md) §4.7）。
- 深链接只做路由，不代表授权；URL 指向的内容访问仍按权限判定。
- URL 解析与参数校验由应用自己完成，非法 URL 返回 `APP_URI_INVALID` 语义的结构化错误。

### 8.5 系统集成能力（菜单、托盘、快捷键、系统信息、电源、传输）

应用插件可经 `ctx.bridge.request`（主逻辑）或 `chips.request`（UI）使用平台系统集成能力；契约与权限见 [04-能力契约规范](../05-接口与契约/04-能力契约规范.md) §7.9、§7.14、§7.15，这里只给用法要点：

| 能力 | 用法要点 | 权限 |
|---|---|---|
| `menu:set` | 在 `launch` 中构建应用 / 托盘菜单；菜单项 `command` 命中时平台调用 `handleCommand` | `menu:manage` |
| `tray:set` | `ui.surface: tray` 时设置托盘图标与 tooltip；点击经 `tray:clicked` 事件投递 | `tray:manage` |
| `shortcut:register` / `shortcut:unregister` | 注册全局快捷键，触发时调用 `handleCommand` 并发布 `shortcut:triggered` | `shortcut:manage` |
| `system:info` | 读取平台版本、OS、架构与路径变量解析值（只读，不提供系统修改） | `system:read` |
| `power:query` / `power:prevent-sleep` | 查询电源状态；长任务期间抑制睡眠，随实例退出自动释放 | `power:read` / `power:manage` |
| `transfer:download` / `transfer:cancel` | 下载资源到授权路径；进度与结果经 `transfer:progress` / `transfer:completed` / `transfer:failed` 投递 | `transfer:manage` |

```typescript
public async launch(ctx: IAppContext): Promise<void> {
  await ctx.bridge.request('menu:set', {
    target: 'app',
    items: [
      { id: 'save', label: '保存', command: 'quick-notes:save' },
      { id: 'export', label: '导出', command: 'quick-notes:export' },
    ],
  });

  await ctx.bridge.request('shortcut:register', {
    shortcutId: 'save',
    accelerator: 'CommandOrControl+S',
  });
}
```

- 菜单、托盘与快捷键绑定随实例退出自动清理；应用不得依赖进程级绑定在实例之外存活。
- 深链接与文件关联见 §8.4、§8.1；事件 payload 以 [05-事件契约规范](../05-接口与契约/05-事件契约规范.md) §4.7、§4.10 为准。
