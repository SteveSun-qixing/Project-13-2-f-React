## 六、编辑面板与布局配置

### 6.1 `content.yaml` 中的 `layout_configs`

箱子可同时保存多个布局的配置，全部集中在 `content.yaml` 的 `layout_configs` 映射中；当前生效项由 `metadata.yaml` 与 `content.yaml` 的 `active_layout_type` 标识，两处必须一致（[02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) 第六节）。

```yaml
# .box/metadata.yaml（节选）
active_layout_type: "chips.layout.grid"
```

```yaml
# .box/content.yaml（节选）
active_layout_type: "chips.layout.grid"
layout_configs:
  chips.layout.grid:
    schema_version: "1.0.0"
    props:
      gap: 16
      show_tags: true
      information_density: "comfortable"
    asset_refs: []
```

| `BoxRenderView` 字段 | 来源 |
|---|---|
| `active_layout_type` | `.box/metadata.yaml` 的 `active_layout_type`（与 `content.yaml` 一致） |
| `layout_config` | `.box/content.yaml` 的 `layout_configs.<active_layout_type>.props` |

绑定关系必须闭合：`metadata.yaml` 的 `active_layout_type`、`content.yaml` 的 `active_layout_type`、`layout_configs` 键、manifest 的 `capabilities.layouts[].id` 四者一致（R20）。

### 6.2 `props` 设计规则

- `props` 是插件自定义参数的自由映射；字段名与默认值由插件定义并**在插件文档中说明**（[02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) 6.5）。
- 只允许 JSON 兼容且可结构化克隆的值（字符串、数字、布尔、`null`、数组、对象）；禁止函数、类实例、`Date`、`Map`、`Set`。
- 禁止持久化：绝对路径、`file://`、运行时临时 URI、会话 ID、凭证、资源句柄、平台内部路径。
- 列数、断点等响应式派生量不进入 `props`；`column_count` 不是网格布局的配置项（第 4.4 节）。
- 字段缺失或非法时逐字段回退内部默认值；`schema_version` 的写入与演进见第 6.6 节。

### 6.3 `asset_refs` 与箱子资源

- 布局需要箱子专属资源（背景图、占位图、插画）时，资源写入包内 `assets/`，路径以 `assets/` 开头，并登记到当前布局配置的 `asset_refs` 数组（[02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) 6.6、第八节）。
- 路径必须是包内相对 POSIX 路径，禁止绝对路径、scheme、临时资源 URL 与凭证。
- 插件自身的静态素材（图标、默认样式）随 `.cpk` 分发，不得复制进箱子 `assets/`；两类资源不得混用。
- 编辑器不得自行写文件；资源写入与清理由编辑链路的正式资源桥承担。需要在编辑面板预览箱子资源时，只能使用编辑链路提供的受管引用与 `window.chips.resource(uri)`（[06-资源协议规范](../05-接口与契约/06-资源协议规范.md)）；不得构造或猜测作用域 URI，句柄必须在使用后 `release()`。
- 网格布局不引用箱子资源，`asset_refs` 为空数组即可。

### 6.4 `ILayoutEditor` 实现与变更回流

`ILayoutEditor` 是布局编辑句柄，完整定义见 [09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) 7.1；成员如下：

| 成员 | 编辑器侧的职责 |
|---|---|
| `state` / `isDirty()` / `getChange()` | 暴露可编辑状态与相对基线的累计变更 |
| `subscribe('change' \| 'dirty')` | 发布变更与脏状态；返回可退订的 `ISubscription` |
| `markCommitted(revision)` | `document:write` 回流成功后推进基线、清除已提交变更 |
| `update(box, revision)` | 会话视图前进时替换基线并回填控件；无待提交变更时调用 |
| `focus()` / `dispose()` | 聚焦入口；释放全部订阅与 DOM，幂等 |

变更载荷 `LayoutChange` 两种形态：

```typescript
type LayoutChange =
  | { kind: 'replace'; config: Record<string, unknown>; schemaVersion: string }
  | { kind: 'patch'; operations: readonly ILayoutPatchOperation[] };
```

- `replace` 提交完整布局配置，配置必须已经过插件归一化；`schemaVersion` 为编辑器写入的当前配置 schema 版本（第 6.6 节）；实现最简单，推荐首选。
- `patch` 只描述 `layout_config` 增量，`path` 使用 RFC 6901 指针（相对 `layout_config` 根、不允许根指针），`op` 为 `add` / `replace` 时 `value` 必填；不改变 `schema_version`。
- 同一任务或同一动画帧内的多次编辑合并为一次变更发布；回流唯一时序为 `getChange` → 校验（`configSchema` + `validateConfig`）→ `document:write`（`{ revision }`）→ `update` → `markCommitted`。
- 编辑器不负责保存；迁移到 React 时挂载根只使用 `@chips/ui` 组件与 Design Tokens，禁止硬编码样式与全局样式（R4）。

### 6.5 布局切换

- 切换布局只读取目标布局的配置应用到同一份条目集合，不修改 `structure.yaml`，不丢失其它布局已保存的配置。
- 切换时同步更新 `metadata.yaml` 与 `content.yaml` 的 `active_layout_type`，两处保持一致。
- 未安装目标布局插件时按插件缺失规则降级，不影响箱子打开。

### 6.6 配置 schema 与版本演进

布局插件必须在 manifest 的 `capabilities.layouts[]` 同时声明 `configSchema`（描述 `props` 的 JSON Schema 2020-12，位于 `assets/`）与 `schemaVersions`（支持的配置 `schema_version` 语义化版本范围，不得为空），见 [02-插件清单规范](02-插件清单规范.md) 7.3。

- `content.yaml` 的 `layout_configs.<type>.schema_version` 必填：语义为该配置由哪个配置 schema 版本写入；编辑器在 `LayoutChange` 的 `replace` 中写入当前 schema 版本（与 `configSchema` 同步维护的常量，必须落在 `schemaVersions` 内），经编辑链路回流、平台持久化；`patch` 不改变它（[09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) 7.1、7.2）。
- 编辑链路在回流与保存前先以 `configSchema` 做结构校验，再调用 `validateConfig` 做语义校验；`validateConfig` 的判定不得比 `configSchema` 宽松。
- 兼容性变更提升 MINOR：放宽 `schemaVersions` 上限即可，旧配置继续可渲染。
- 破坏性变更提升 MAJOR：不兼容旧配置时收窄 `schemaVersions` 下限，旧配置打开时按 `RENDER_SCHEMA_UNSUPPORTED` 确定性降级；需要兼容旧配置时放宽范围并在插件内按 `schema_version` 分支处理。
- 平台不做运行时配置迁移：门禁之外不改写箱子的 `schema_version`，也不为旧配置提供兼容层（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) 2.2）。
