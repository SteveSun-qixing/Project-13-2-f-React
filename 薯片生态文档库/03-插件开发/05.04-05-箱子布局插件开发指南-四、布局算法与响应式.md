## 四、布局算法与响应式

### 4.1 布局输入

`renderLayout` 拿到的 `BoxRenderView` 提供三类输入：

| 输入 | 来源 | 用途 |
|---|---|---|
| `entries` | `.box/structure.yaml` 的 `entries`，按声明顺序 | 条目集合与基础顺序 |
| `layout_config` | `.box/content.yaml` 的 `layout_configs.<active_layout_type>.props` | 布局参数 |
| 容器宽度 | 父帧注入的容器 | 列数、分组与尺寸估算 |

`BoxRenderView.active_layout_type` 来自 `metadata.yaml` 的 `active_layout_type`（字段映射见第 6.1 节）；`schema_version` 属于持久化配置项，不随视图暴露。配置缺失时 `layout_config` 为空对象，插件必须能用内部默认值渲染。

### 4.2 条目集合处理与排序

- 只消费 `enabled` 为 `true` 的条目；`enabled` 为 `false` 的条目不进入布局呈现。
- 基础顺序是 `entries` 数组顺序；`EntryView.order` 是平台派生的呈现顺序，可直接用于排序。
- 排序可消费 `layout_hints` 的可选字段：`sort_key`（排序键）、`group`（分组键）、`priority`（优先级）、`aspect_ratio`（摘要展示宽高比，用于槽位估算）；字段可能缺失，必须回退到基础顺序。
- 排序与分组只影响呈现，不修改箱子数据；拖拽排序的持久化由编辑链路负责，不属于布局渲染。
- 不得假定 `snapshot` 完整；`displayTitle` 由平台派生（`snapshot.title` 或目标文档标题），插件直接使用。

### 4.3 网格算法与条目外壳

网格布局的算法规则：所有条目等宽，列数由容器宽度自动计算；每个条目由「条目帧槽位 + 标题（+ 可选标签）」组成，条目帧负责完整内容，布局只画外壳。

```text
┌──────────────── 布局帧（容器）────────────────┐
│  grid：display: grid; repeat(N, minmax(0,1fr))  │
│  ┌────────────┐ ┌────────────┐ ┌────────────┐  │
│  │ 条目帧槽位  │ │ 条目帧槽位  │ │ 条目帧槽位  │  │
│  ├────────────┤ ├────────────┤ ├────────────┤  │
│  │ 标题       │ │ 标题       │ │ 标题       │  │
│  └────────────┘ └────────────┘ └────────────┘  │
└─────────────────────────────────────────────────┘
```

- 条目外壳只使用 `EntryView` 数据（标题、标签、启用状态、顺序）；不推断封面、不读取条目资源。
- 条目数量为零时显示简体中文空态（如「暂无条目」），不渲染空白网格。
- 单个条目定位失败或内容不可用时，在该槽位显示条目级占位，保留槽位布局，不使整箱失败。

### 4.4 响应式列数

列数是布局算法自行计算的运行时结果，不进入 `props`、不暴露为编辑参数：

1. 列数由容器宽度自动计算：容器变窄列数减少，变宽列数增加；变化只更新网格列定义，不重建已挂载的条目帧。
2. 移动端（窄容器、约 600px 以下）固定两列，不再减少。
3. 用 `ResizeObserver` 监听容器宽度；列数未变化时不触碰样式，避免无效重排。
4. 响应式阈值（移动端断点、最小条目宽度、列数上下限）是实现内部常量，不持久化、不写入 `content.yaml`。

### 4.5 虚拟化与高度

- 条目数超过 200 时必须虚拟化：只为可见范围 ± overscan（默认 2）请求与挂载条目帧；滚出范围的槽位立即释放帧句柄。
- 高度未知时用高度缓存或票证的估算高度占位；条目帧测量完成后由平台回填并触发布局重排。
- 布局总高度由平台按帧协议聚合上报；插件不得直接向外层写入高度，也不得用固定高度加隐藏溢出锁死页面。
- 滚动锚定由平台保证；插件在销毁视口上方槽位时不得修改容器滚动位置。
