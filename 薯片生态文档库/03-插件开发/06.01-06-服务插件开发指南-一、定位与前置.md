## 一、定位与前置

### 1.1 本文定位

按本文顺序执行，可以完成一个可编译、可运行、可发布的最小服务插件：

- 接口与方法签名以[10-服务插件接口](../05-接口与契约/10-服务插件接口.md)（下称 E10）为唯一权威；
- 能力模型、schema 与注册校验以[04-能力契约规范](../05-接口与契约/04-能力契约规范.md)（下称 E4）为唯一权威；
- manifest 字段以[02-插件清单规范](./02-插件清单规范.md)为唯一权威。

本文只写“怎么用”，不重新定义接口与契约。服务插件是四种插件角色中唯一无界面的角色：在主进程后台运行，通过 Cordis 服务与 Bridge 能力为其它插件和平台提供可复用功能（[ADR-005](../01-架构设计/ADR/ADR-005-插件不分类只分角色.md)、[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 2.3.4）。

### 1.4 角色红线（开工前确认）

| 约束 | 说明 |
|---|---|
| 无 UI | 不得创建窗口、不得渲染内容，不得声明 `ui` / `capabilities.cardTypes` / `capabilities.layouts` |
| 主进程 | 禁止直接访问 Node.js / Electron / 系统 API，禁止创建子进程；系统能力一律经 `ctx.bridge` 或内核服务获取（E10 2.4） |
| 权限 | 不得申请窗口类权限；后台访问文件与网络必须说明用途并最小化（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 5.3） |
| 单一角色 | 一个插件只有一个角色；需要多角色能力时拆包并用 `dependencies` 组合（R1） |
| 无 `window.chips` | 服务插件运行在主进程，不存在 `window.chips`；事件订阅使用 `ctx.on` / `ctx.once`（E10 3.7） |
| 可逆副作用 | 启动期间登记的服务、能力、订阅、定时器、资源句柄全部纳入插件 Fork 追踪 |
