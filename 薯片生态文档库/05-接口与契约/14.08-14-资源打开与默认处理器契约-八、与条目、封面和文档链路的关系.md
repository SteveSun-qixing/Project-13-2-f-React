# 资源打开与默认处理器契约

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：资源打开路由的权威契约：打开来源与打开请求模型、manifest 处理器声明与 `primary` / `fallback` 层级、路由解析顺序与投递授权、启动载荷 `resourceOpen` 与业务载荷约定、默认处理器偏好 `platform.fileOpen.defaults` 与槽位治理接口、未安装/停用/卸载的降级与回收、与文档/条目/封面链路的关系；资源 URI 语法、句柄与权限判定本身不在此定义。

## 八、与条目、封面和文档链路的关系

### 8.1 链路边界

| 场景 | 链路 | 说明 |
|---|---|---|
| 打开 `.card` / `.box` 文档 | 资源打开路由 → 处理器应用 → `document:open` | 文档文件作为资源被路由到查看器或编辑引擎（处理器声明 `.card` / `.box`），应用再经文档服务建立会话（[11-文档服务设计](../01-架构设计/01-子系统设计/11-文档服务设计.md)） |
| 卡片内容资源（图片、音频、视频、文件、图包）点击 | 资源打开路由 | 按扩展名与 MIME 命中专用或兜底处理器（§九示例） |
| 箱子条目激活 | 文档打开链路（条目激活模块） | 条目目标是文档引用，不是文件类型路由；条目一律按目标文档打开，不展开目标箱子布局（[02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) §9.4） |
| 封面呈现 | 受控封面渲染接口 + 封面帧 | `.card/cover.html`、`.box/cover.html` 的呈现永不经处理器路由（§8.3） |
| 外部链接（http(s)） | `shell:openExternal` 能力 | 用户点击外部链接属外部打开，不是资源打开（[04-能力契约规范](./04-能力契约规范.md) §7.8） |

### 8.2 条目激活

- 箱子条目的 `url` 是文档引用（内嵌卡片包内相对路径或绝对 URL）；点击后由平台条目激活模块按目标文档打开，经解析与文档链路落地后交给查看器或编辑引擎，不进入处理器匹配。
- 条目目标为箱子时按正式封面呈现，不展开布局、不递归打开（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §7.2、§7.5）。
- 条目定位失败、网络不可达或凭证缺失时按条目失败态呈现，不进入本路由、不阻断整箱打开（[02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) §9.5）。
- 布局插件只发起条目激活请求，不自行打开条目、不硬编码查看器插件（[09-箱子布局插件接口](./09-箱子布局插件接口.md) §6.1）。

### 8.3 封面链

- 封面链是独立的受控渲染链路：封面 URL 由平台受控封面渲染接口返回，在封面帧中呈现，比例取自 `cover_ratio`（[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §7.3、[02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) §9.3）。
- 封面资源（含 PNG、JPEG 等）**永不**进入资源打开路由：封面呈现不使用处理器匹配，也不触发默认处理器偏好。
- 应用层不得把封面内容改写为任意 HTML，不得自行推断封面资源（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §7.2）。

### 8.4 文档打开

- 处理器应用收到文档资源打开后，经 `document:open` 建立会话（`documentId` 取自文档稳定标识，跨会话稳定），渲染与编辑按 [05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md)、[12-编辑引擎设计](../01-架构设计/01-子系统设计/12-编辑引擎设计.md) 执行。
- `edit` 意图路由到编辑引擎应用后，编辑链路按唯一时序执行回流（[12-编辑引擎设计](../01-架构设计/01-子系统设计/12-编辑引擎设计.md) §4.3）；查看器接收 `edit` 意图时按 `view` 处理并在诊断中记录（§2.3）。
- 文档作用域内的资源（卡片内图片、音频等）被打开到其他应用时，跨作用域读取由投递授权覆盖（§4.4）。

### 8.5 查看态点击行为契约

查看态卡片帧与箱子帧内的指针动作统一遵循本节；帧内动作的封套、消息集合与超时以 [05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §9.2、§9.5 为准，本节只定义默认语义与归一结果。

#### 8.5.1 默认语义

| 动作 | 默认语义 |
|---|---|
| 单击（主键，在同一元素上按下并释放） | 对「可打开元素」（图片、音频、视频、文件、网页入口、文档引用）执行其默认动作：表达打开该元素所引用资源的意图（`intent: 'view'`）；非可交互内容的单击只做卡片窗口聚焦 / 选中，不打开资源 |
| 双击（主键） | 不定义独立的打开语义：默认动作由单击承担，双击间隔内对同一目标去重，不得产生第二次打开；双击不进入编辑态，进入编辑只由编辑引擎的显式入口触发 |
| 中键（辅助键，`button === 1`） | 卡片内容不响应：不触发默认动作、不投递 `frame:action`；中键保留给承载表面的平台行为（如查看器标签页中键关闭，[查看器设计](../08-产品与交互/03.06-03-查看器设计-六、多窗口与标签页.md) §6） |
| 键盘等价 | 聚焦的可打开元素上 `Enter` 触发默认动作；`Space` 仅对按钮角色元素触发；焦点环必须可见（[08-基础卡片插件接口](./08-基础卡片插件接口.md) §五） |

规则：

1. 元素是否可打开由内容语义决定并显式标注（可聚焦、按钮 / 链接角色）；纯展示内容不得伪装为可点击目标。
2. 一次用户动作只投递一次；重复触发（双击第二次、长按重复）在帧运行时去重。
3. 动作失败只由 `host:action-error` 回执驱动帧内提示，不改变内容呈现，也不阻断同一帧内其它元素。

#### 8.5.2 `frame:action` 投递与归一

1. 帧内不得直接调用 `resource:open` 或其它能力：内容点击统一经帧运行时句柄投递 `frame:action`，由 RenderHost 做权限判定与归一（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §9.2、[08-基础卡片插件接口](./08-基础卡片插件接口.md) §8.1）。
2. 载荷映射：包内资源与文档引用 → `{ kind: 'open-document', source }`；外部链接（`http(s)://`）→ `{ kind: 'open-external', url }`；复制文本与通知分别对应 `copy-text` / `notify`。
3. 归一结果：`open-document` 归一为 `resource:open` 请求（`intent` 缺省 `view`、`origin: 'frame'`，§2.1）；`open-external` 归一为 `shell:openExternal`，不进入资源打开路由（[04-能力契约规范](./04-能力契约规范.md) §7.8）。
4. RenderHost 校验目标属于当前渲染会话可见引用（文档内容、业务载荷引用或文档作用域内 URI），越界拒绝并记诊断（§2.1）；单次动作默认超时 5s，超时回 `host:action-error`（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §9.5）。
5. 业务上下文（音乐 / 视频 / 电子书等标准载荷）由发起内容按[启动载荷](./14.05-14-资源打开与默认处理器契约-五、启动载荷.md) §5.3、§5.4 组织并随打开意图透传；平台不解释业务字段。
6. 内容不得硬编码目标插件、不得绕过路由自行打开，也不得根据点击次数改变打开目标（[启动载荷](./14.05-14-资源打开与默认处理器契约-五、启动载荷.md) §5.4）。

#### 8.5.3 与资源打开、条目的关系

- 帧内点击属于资源打开的 `frame` 来源（§2.1）：路由、匹配、投递授权与降级完全按本契约第三、四节执行；无候选且不可回退时返回 `RESOURCE_HANDLER_MISSING`，帧内按 `host:action-error` 提示（§4.6）。
- 箱子条目激活不走指针默认语义：条目由平台条目激活模块按目标文档打开（§8.2），布局插件只发起激活请求；条目目标为箱子时按正式封面呈现，不展开布局。
- 图片 / 音频 / 视频 / 文件等具体元素的默认动作与载荷形状以[启动载荷](./14.05-14-资源打开与默认处理器契约-五、启动载荷.md) §5.4 与[卡片文件格式](../04-文件格式规范/01-卡片文件格式.md)各类型「查看态行为」为准；本节不重复逐类型定义。
- 打开 `.card` / `.box` 文档本身（文件关联、拖放、应用内打开）属于资源打开的其它来源，不是内容点击（§2.1）。
