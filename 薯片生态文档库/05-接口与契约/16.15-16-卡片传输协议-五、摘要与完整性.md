# 卡片传输协议

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：`.card` / `.box` 在本地设备与内容服务器之间传输的权威协议：传输会话（创建、预签名、分片、断点续传、取消、恢复）、完整离线卡片与网络资源卡片的可逆改写与还原（含可逆恢复清单）、摘要与完整性校验、预签名与对象存储桶角色、传输队列与 `transfer:*` 事件映射、错误码与安全约束；不覆盖卡片/箱子的包结构语义、渲染链路与服务器产品设计。

---

## 五、摘要与完整性

### 5.1 摘要算法与格式

- 对象摘要统一使用 SHA-256，字符串格式 `sha256:<64 位小写十六进制>`；协议字段中的 `sha256` 只携带十六进制值（不带 `sha256:` 前缀），预签名响应头 `x-amz-meta-chips-sha256` 同。
- 摘要计算范围是对象的完整字节（资源原始字节、网络资源卡片文件字节、箱子源文件字节、渲染产物文件字节），计算在传输前完成。
- 摘要不可省略：`objects:presign`、`complete`、下载计划与恢复清单中的对象摘要均为必填。

### 5.2 生成与提交点

| 阶段 | 摘要动作 |
|---|---|
| 扫描资源 | 传输引擎对每个资源对象计算 SHA-256 |
| 预签名 | `sizeBytes` 与 `sha256` 随对象请求提交；服务器写入对象元数据 |
| 分片上传 | 分片不做整体摘要；对象合并后由服务器与客户端各自校验整体摘要 |
| 改写打包后 | 对网络资源卡片计算 SHA-256，随 `network-card` 预签名提交 |
| 提交 | `complete` 逐对象提交 `objectId` / `sha256`；服务器与本会话记录比对 |
| 下载计划 | 服务器返回每个对象与恢复清单中的摘要 |
| 下载校验 | 传输引擎逐对象校验摘要后才写入与打包 |
| 恢复后 | 按 `zipEntries` 的 `crc32` 与解析结果做归档级校验 |

### 5.3 服务端校验

- 大小：对每个提交对象执行 Head，`Content-Length` 必须等于会话记录与提交值；
- 摘要：对象元数据 `x-amz-meta-chips-sha256` 必须等于会话记录值；对象存储不支持摘要元数据时，服务器必须读取对象流计算 SHA-256；两者都无法完成时拒绝提交（`VALIDATION_ERROR`）；
- 归属：`objectId`、桶与对象键必须属于本会话的对象记录，且对象键前缀等于会话 `resourcePrefix`（箱子源文件前缀为 `boxes/{boxId}/versions/{versionId}`）；
- 内容一致性：网络资源卡片必须引用本会话全部资源 URL，且归档内不得包含这些资源的原始字节（3.6 第 6 步）；
- 分片完整性：`multipart` 对象的分片列表必须连续、无空洞、每片大小合法，方可合并。

### 5.4 客户端校验

- 下载网络资源卡片与每个资源对象后，先校验 `sizeBytes`，再校验 `sha256`；不通过即删除该对象字节并重试（一次）；
- 重试仍不通过时任务失败（`CARD_TRANSFER_DIGEST_MISMATCH`），不得把未校验字节写入输出卡片；
- 重打包后校验 `zipEntries` 的 `crc32` 与 `Store` 模式；校验不通过按还原失败处理。

### 5.5 不一致处理

- 大小不一致：`CARD_TRANSFER_OBJECT_MISMATCH`，不可重试，要求重新预签名并重传该对象；
- 摘要不一致：客户端侧不可重试（重试一次后失败）；服务端侧整体拒绝提交，客户端修复后重新预签名并重传；
- 摘要校验错误必须写审计（对象角色与相对路径，不含字节内容与预签名地址）。
