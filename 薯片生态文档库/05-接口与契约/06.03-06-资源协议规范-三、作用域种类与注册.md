## 三、作用域种类与注册

### 3.1 作用域种类

| 种类（kind） | scope ID | 底层来源 | 生命周期 | 写入 |
|---|---|---|---|---|
| Workspace | `workspace-*` | 用户工作区目录（[13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md)） | 工作区打开期 | 经受控提交（`resources:write`，受 PathGuard 与审计） |
| Document | `card-*` / `box-*` | 目录态或 ZIP Store 的 `.card` / `.box` | 文档会话 | 仅文档保存流程经受控提交；`resource:write` 不适用（见 4.3 节） |
| Plugin | `plugin-*` | `.cpk` 安装目录（开发态为插件目录） | 插件激活期 | 经受控提交（`resources:write`） |
| Platform | `platform` | 平台安装目录与编译期内嵌资源 | 平台进程生命周期 | 禁止（只读） |
| External | `external`（后接 origin） | `http(s)` / `webdav` 代理 | 按 origin 惰性注册 | 禁止（只读） |
| Temporary | `temp-*` | 用户经 `dialog:open` / `dialog:save` 授权的文件系统路径 | 单次写入后或会话结束注销 | 授权后经受控提交（`resource:write` 适用） |
| Memory | `memory` | 运行时内存字节，禁止持久化 | 会话内 | 经受控提交（`resources:write`，不落盘） |

- 底层来源与 Provider 映射见 [04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 2.3、3.3 节。
- `IResourceMetadata.scope` 返回上表种类枚举；文档作用域不区分卡片与箱子（统一链路，R8）。

### 3.2 注册与注销

| 时机 | 种类 | 注册内容 | 注销 |
|---|---|---|---|
| 打开工作区 | Workspace | `workspace-*` scope ID、工作区根目录、所有者、策略 | 工作区关闭 |
| 打开 `.card` / `.box` | Document | scope ID（平台分配）、所有者（所属应用插件）、来源（目录 / ZIP Store）、策略、创建会话 | 文档关闭（`document:closed`） |
| 插件加载 | Plugin | scope ID、插件 ID、`.cpk` 安装目录、策略 | 插件停用、更新、卸载 |
| 平台启动 | Platform | 固定 ID `platform`、平台安装目录与内嵌资源、只读策略 | 平台进程退出 |
| 首次解析到外部引用 | External | 按 origin（scheme + host + port）注册、HttpProvider 来源、`allowed_hosts` 策略 | 缓存清理或平台退出 |
| `dialog:open` / `dialog:save` 用户确认路径 | Temporary | `temp-*` scope ID、授权路径根、可写标记、所属会话 | `dialog:save` 单次写入后自动注销；`dialog:open` 会话结束注销（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 5.4 节） |
| 运行时内存资源创建 | Memory | 固定 `memory` scope、内存字节、所属会话 | 会话结束或显式释放 |

规则：

- 注册时绑定所有者与创建它的资源会话；作用域是授权单元，注册不等于授权（权限见第四节）。
- External 作用域按 origin 惰性注册：语法合法且通过 SSRF 前置校验的 origin 在首次解析时创建注册项；解析失败不创建。
- 注销级联：作用域注销时，其全部句柄失效并释放、流终止、缓存条目清除（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 10.1 节）。
- 注册失败不得降级：文档打开或插件启用以失败收口，不允许以裸路径直读替代。

### 3.3 resourceBase 与引用归一

- 作用域注册结果向渲染层交付规范基址 `resourceBase`：`chips-resource://<scopeId>/`（尾斜杠）。
- 帧初始化时注入 `<base href="{resourceBase}">`，包内相对路径（相对包根）自动解析为作用域 URI：`images/photo.jpg` → `chips-resource://card-7f3a/images/photo.jpg`。
- 引用归一分工：包内相对路径与 `file://` 由文档解析器 / 渲染层归一（R13、[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 5.2 节）；裸 `http(s)://` 与 `webdav://` 按 2.6 节归一为 External URI；`chips-resource://` 原样传递，仍须通过第五节解析流程。
- 注入的 `<base>` 必须是受管作用域 URI；禁止注入 `file://`、裸绝对路径或任意远端地址（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 5.5 节）。

### 3.4 可见性规则

- 平台不提供作用域列举接口；任何插件不得枚举作用域或目录（`platform` 与 `external` 目录不可列举）。
- 作用域 ID 不透明且由平台生成；未注册的作用域返回 `RESOURCE_NOT_FOUND`，已注册但未获授权返回 `RESOURCE_PERMISSION_DENIED`。
- 插件不得通过错误信息、时序或缓存行为推断其他插件作用域的存在与内容；全部资源访问尝试写入审计（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 第八节）。
