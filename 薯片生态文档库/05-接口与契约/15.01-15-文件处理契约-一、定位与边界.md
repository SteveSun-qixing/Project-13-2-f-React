# 文件处理契约

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：通用文件处理（`.card` / `.box` 文档之外的普通文件）的会话与转换编排契约：`file-processing` 服务、打开/预览/转换/另存/比较操作、进度与取消、受控提交与原子替换、大文件流式、错误码与边界；不定义具体格式算法、支持矩阵与原子能力实现

## 一、定位与边界

### 1.1 定位

本文是薯片生态**通用文件处理**的会话与编排契约，是旧《万能文件处理协议》在新架构下的正式承接（旧文档仅存档、不作为依据）：

- 通用文件的处理以 `service` 角色插件的 Cordis 服务形态提供（服务名 `file-processing`）；服务只承载**会话状态与编排机制**，格式算法由内容处理服务提供方承载（[04-能力契约规范](./04-能力契约规范.md) §3.2、§八）；
- 字节访问经资源管理器句柄与受控提交（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md)），文件系统路径不出现在本契约；
- `.card` / `.box` 文档的打开、读取、写入、保存、导出与另存统一走 `document:*`（[11-文档服务设计](../01-架构设计/01-子系统设计/11-文档服务设计.md)、[13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §4.2），本契约不定义文档会话；
- **不新增 Bridge 能力**：内容处理属于业务实现，不登记为平台内置能力（[04-能力契约规范](./04-能力契约规范.md) §3.2）。

旧链路 `file.session.*` / `file.preview.*` / `file.convert.*` / `file.batchConvert` / `file.compare` / `file.versionDiff` 与 `office.document.*` 一律废止：文档会话统一为 `document:*`，通用文件处理统一为本契约；新代码禁止使用上述历史标识。

### 1.3 术语

| 术语 | 定义 |
|---|---|
| 文件处理服务 | 提供 `file-processing` 服务的 `service` 角色插件；官方实现随平台内置分发，服务只做会话与编排 |
| 文件处理会话 | 一次 `openSession` 建立的通用文件处理上下文，绑定一个来源与一个来源句柄；持有在途操作、进度订阅与暂存区 |
| 内容处理服务 | 由 `service` 插件通过 `ctx.provide` 注册、承载具体格式算法（图像编解码、音视频转码、Office 转换、OCR、媒体元数据等）的 Cordis 服务；原子契约见 [04-能力契约规范](./04-能力契约规范.md) §八 |
| 打开 | 探测来源类型与版本、建立会话、获取来源句柄；不读取正文 |
| 预览 | 从来源生成有界的内存预览产物（缩略图、页图、帧图等） |
| 转换 | 把来源编排为指定目标格式的文件产物 |
| 另存 | 把来源字节以原格式复制为文件产物，不做解码与重编码 |
| 比较 | 对会话来源与对侧来源做一次性差异计算；不产生产物、不写文件（`compare`，§3.10） |
| 差异块 | 比较结果中的一段连续差异，带两侧范围与（仅 `semantic`）行文本 |
| 文本类来源 | 可按文本解码与行拆分的来源（`text/*` 与 JSON / YAML / XML、源码与配置类文本）；判定经内容处理服务探测 |
| unified diff | 文本行级差异的标准文本表示（`@@ -起始,行数 +起始,行数 @@` 头与上下文行） |
| 受控提交 | 资源管理器的写入提交接口（一次性 `commit_write` / 流式 `commit_write_stream`），提供同级临时物、原子替换与失败清理 |
| 原子替换 | 产物先完整写入临时物，校验通过后一次替换目标；失败不触碰既有目标 |
| 暂存产物 | 编排过程中位于提供方插件作用域或平台临时作用域的中间文件，绝不作为最终产物 |
| 来源版本戳 | 来源当前的版本标识（`mtime + size`、归档条目 CRC、HTTP `ETag`），口径见 [06-资源协议规范](./06-资源协议规范.md) §6.1 |
| 阶段 | 转换编排的固定进度阶段：`prepare` / `transform` / `stage` / `publish` / `cleanup` / `completed` |
