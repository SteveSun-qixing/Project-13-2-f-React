## 六、条目渲染与资源访问

### 6.1 帧运行时契约

查看态布局插件运行在布局帧内；帧运行时在首次调用 `renderLayout` 前，把运行时句柄注入实现了 `IBoxLayoutRuntimeAware` 的插件入口：

```typescript
interface IBoxLayoutRuntimeAware {
  attachRuntime(runtime: IBoxLayoutFrameRuntime): void;
}

interface FrameNotification {
  level: 'info' | 'warning' | 'error';
  message: string;
}

interface EntryRequest {
  entryIds: readonly string[];
}

interface IBoxLayoutFrameRuntime {
  requestEntries(request: EntryRequest): Promise<EntryTicket[]>;
  mountEntry(ticket: EntryTicket, container: HTMLElement): Promise<Dispose>;
  openDocument(source: string): Promise<void>;
  openExternal(url: string): Promise<void>;
  copyText(text: string): Promise<void>;
  notify(notification: FrameNotification): Promise<void>;
}
```

| 成员 | 契约 |
|---|---|
| `attachRuntime` | 由帧运行时调用，每个渲染帧恰好一次；插件保存句柄并在本帧生命周期内使用，不得转存到跨帧共享的全局状态 |
| `requestEntries` | 请求指定条目的条目票证；平台只为允许范围（可见 ± overscan）返回，其余忽略 |
| `mountEntry` | 把平台管理的条目帧挂载到插件提供的槽位容器，返回释放句柄（幂等）；票证由平台解释并按 `view.kind` 渲染条目卡片视图或目标箱子的正式封面；条目帧的创建、握手、高度聚合与销毁由平台完成 |
| `openDocument` | 经 `frame:action` 请求平台打开条目文档（目标为箱子时走平台条目激活链路，不展开目标布局、不递归打开）；失败以 `ChipsError` 拒绝 |
| `openExternal` | 在系统默认程序中打开外部链接 |
| `copyText` | 复制文本到剪贴板 |
| `notify` | 发送用户通知；`message` 为简体中文 |

规则：

- `EntryTicket` 的完整结构由 [05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 7.2 定义；`requestEntries` 与 `mountEntry` 是该协议在插件侧的正式入口。帧协议的 `host:entries` 响应携带 `requestId` 以关联同一次条目请求（与 [05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 一致），插件不直接消费该字段。
- 上述动作全部经 `frame:action` 转发给 RenderHost，再由 RenderHost 经 Bridge 执行权限判定与审计（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 9.3）。
- 帧内不得使用 `window.chips`、`parent`、`top`、存储 API 或 `fetch`；一切平台访问只经运行时句柄（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 4.5）。
- 不需要条目帧与帧动作的布局插件可以不实现 `IBoxLayoutRuntimeAware`。

### 6.2 条目渲染

- 条目外壳（标题、顺序、启用状态、摘要与布局索引）由布局插件用 `EntryView` 数据渲染。
- 条目完整内容由平台管理的条目帧渲染：布局插件对可见条目调用 `requestEntries` 取得票证，再调用 `mountEntry` 把条目帧挂载进自己的槽位容器。
- 票证结构由 [05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 7.2 定义（`entry_id` / `slotIndex` / `view` / `resourceBase` / `pluginEntries` / `estimatedHeight`）；布局插件不得修改票证，不得自行加载票证指向的模块。
- 条目可引用卡片或箱子：箱子条目一律按被引用箱子的正式封面呈现，不展开布局、不递归展开；插件无需为此特判，可据票证 `view.kind` 决定槽位呈现（例如按 `view.cover.ratio` 预占比例）。
- 条目帧的创建、握手、高度聚合、销毁全部由帧运行时与 RenderHost 完成；插件只提供槽位容器并释放句柄。
- 禁止事项：读取条目文件、解析 YAML、`import` 条目代码、创建非受管 iframe、把条目 `url` 直接赋给 `iframe.src`。
- 条目级失败（文件缺失、格式损坏、插件缺失）由平台在条目帧内呈现降级占位；插件保留槽位布局，不升级为整箱错误。

### 6.3 虚拟化与高度

- 条目数超过 200 时布局插件必须虚拟化：只为可见范围 ± overscan（默认 2）请求与挂载条目帧，滚动时增删槽位并释放滚出范围的句柄。
- 高度未知时用票证的 `estimatedHeight` 或平台高度缓存占位；条目帧测量完成后平台回填并触发布局重排（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 10.2）。
- 布局总高度由平台按帧协议聚合上报；插件不得直接向外层写入高度。
- 滚动锚定由平台保证；插件在销毁视口上方槽位时不得修改容器滚动位置。

### 6.4 资源访问

| 引用形式 | 访问方式 |
|---|---|
| 包内相对路径 | 相对布局帧注入的 `<base href="{resourceBase}">` 解析到箱子作用域 |
| `chips-resource://` | 原样使用，由协议处理器按权限提供 |
| `file://` / `http(s)://` | 不允许在帧内直接使用；需要显示的资源由平台在渲染准备阶段转为受管 URI |

规则：

- 所有资源统一经 `chips-resource://` 体系访问，受限、可审计（R17）；插件不接触文件系统路径。
- 箱子自有资源位于包内 `assets/`，布局配置经 `asset_refs`（以 `assets/` 开头的包内相对路径）引用；布局插件的静态资源（图标、样式、插画）随 `.cpk` 分发，经插件作用域访问（[03-插件包格式](../04-文件格式规范/03-插件包格式.md)、[06-资源协议规范](06-资源协议规范.md)）。
- 条目内容资源属于条目卡片包作用域，由条目帧自行加载；布局插件不得跨作用域拼路径、不得读取条目资源字节。
- 帧内不提供 JS 字节读取接口；需要解码或解析的重活在编辑侧或服务侧完成，帧内只负责呈现。
- 大量并发资源由平台排队与去重；插件不自行实现下载与缓存。
- 资源句柄租约绑定渲染会话，会话 `dispose()` 时统一释放（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 5.3）。

### 6.5 动作与视图更新

- `openDocument(source)` 是打开条目的唯一方式；点击槽位、双击、键盘激活都必须经它转发，不得自行跳转或打开外部程序。
- 视图更新经帧运行时再次调用 `renderLayout(newBox, container)` 完成；插件以新视图为重绘输入，并在重绘前释放上一轮条目帧与观察器（第 3.3 节第 4 条）。
- 动作失败（权限拒绝、文档不可用、超时）以 `ChipsError` 拒绝；插件映射为简体中文提示，不得静默失败。
- 帧销毁后不得再写入容器；异步任务必须能在 `Dispose` 时取消。
