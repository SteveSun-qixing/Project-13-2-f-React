## 五、订阅与退订 API 速查

| 场景 | API | 返回 | 退订 |
|---|---|---|---|
| 主进程订阅 | `ctx.on<TPayload>(eventId, listener)` | `IEventSubscription` | `subscription.dispose()`；随 Fork 自动退订 |
| 主进程一次性订阅 | `ctx.once<TPayload>(eventId, listener)` | `IEventSubscription` | 首次投递后自动退订；未触发时随 Fork 撤销 |
| 主进程发布 | `ctx.emit<TPayload>(eventId, payload)` | `void` | 不适用 |
| 渲染进程订阅 | `window.chips.subscribe(eventId, handler)` | `ISubscription` | `subscription.dispose()`；窗口销毁自动清理 |
| 渲染进程发布 | `window.chips.request('event:publish', input)` | `Promise<unknown>` | 不适用 |

```typescript
// 主进程（Cordis Context）
on<TPayload>(event: string, listener: (payload: TPayload) => void): IEventSubscription;
once<TPayload>(event: string, listener: (payload: TPayload) => void): IEventSubscription;
emit<TPayload>(event: string, payload: TPayload): void;

// 渲染进程（window.chips / IChipsBridge）
subscribe(eventId: string, handler: (payload: unknown) => void): ISubscription;

interface ISubscription {
  dispose(): void;
}
```

规则：

- `dispose()` 幂等；已退订的监听器不再接收事件。
- 订阅使用发布时刻的监听器快照，新增与退订从下一次发布生效。
- 渲染侧 `handler` 只接收 payload，必须做类型收窄（见 4.2 示例）。
- 订阅校验失败（未登记、不满足可见性）时该订阅不建立、不触发；`event:control` 回执只到 preload 与审计，订阅句柄没有错误回调，订阅前必须确认事件已登记且满足可见性。
- 完整签名、错误与生命周期以《[01-Bridge-API规范](./01-Bridge-API规范.md)》为准；主进程订阅语义见《[09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md)》第四节。
