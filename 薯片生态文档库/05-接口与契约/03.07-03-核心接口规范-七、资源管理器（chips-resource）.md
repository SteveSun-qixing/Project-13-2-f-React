## 七、资源管理器（chips-resource）

### 7.1 公开类型与方法

```rust
pub struct ResourceManager {
    /* ScopeRegistry / Provider 注册表 / CacheStore / HandleTable，见 04-资源管理设计 11.1 */
}

pub struct OpenRequest {
    pub uri: String,
    pub session: SessionId,
}

pub struct OpenHandle {
    pub id: HandleId,
    pub metadata: ResourceMetadata,
}

pub struct WriteRequest {
    pub scope: ScopeId,
    pub path: VirtualPath,
    pub bytes: Vec<u8>,
    pub session: SessionId,
}

impl ResourceManager {
    /// 以限额与权限判定观察面构造管理器；`observer` 见 3.5，
    /// 构造期注入、终身不可换。
    pub fn new(limits: ResourceLimits, observer: Arc<dyn DecisionObserver>) -> Self;

    /// 注册资源来源提供者；启动期完成。
    pub fn register_provider(&self, provider: Arc<dyn ResourceProvider>)
        -> Result<(), ChipsError>;

    /// 注册作用域；返回平台分配的 ScopeId。
    pub fn register_scope(&self, registration: ScopeRegistration)
        -> Result<ScopeId, ChipsError>;

    /// 注销作用域；核心不设会话参数、未在册回 `RESOURCE_NOT_FOUND`（非幂等，OQ-4 实读）。
    /// 绑定层 `resourceUnregisterScope(scope, sessionId)` 先行会话归属闸（波 A1 落位，
    /// 见 §7.3 注记），核心签名不动。
    pub fn unregister_scope(&self, scope: &ScopeId) -> Result<(), ChipsError>;

    /// 挂载目录域 Document 作用域：注册 + 挂根 + 绑会话一体，任一步失败全量回滚
    /// （无半挂载残留）；返回规范 `ScopeId`。波 A1 落位，§7.3 薄包装承载。
    pub fn mount_directory(&self, session: SessionId, registration: ScopeRegistration)
        -> Result<ScopeId, ChipsError>;

    /// 挂载归档域 Document 作用域：只读强制，索引构建失败整体回滚；返回规范 `ScopeId`。
    pub fn mount_archive(&self, session: SessionId, registration: ScopeRegistration)
        -> Result<ScopeId, ChipsError>;

    /// 解析、权限判定与打开；失败返回 RESOURCE_* 错误。
    pub async fn open(&self, request: OpenRequest) -> Result<OpenHandle, ChipsError>;

    pub async fn stat(&self, handle: HandleId, session: SessionId)
        -> Result<ResourceMetadata, ChipsError>;

    /// 范围读；与流式游标互斥。
    pub async fn read_range(&self, handle: HandleId, session: SessionId, range: ByteRange)
        -> Result<Vec<u8>, ChipsError>;

    /// 流式拉取；`None` 表示已到结尾。
    pub async fn read_chunk(&self, handle: HandleId, session: SessionId, max_bytes: usize)
        -> Result<Option<Vec<u8>>, ChipsError>;

    /// 释放句柄与租约；未知/墓碑 ID 幂等，跨会话拒绝。
    pub fn release(&self, handle: HandleId, session: SessionId) -> Result<(), ChipsError>;

    /// 写入提交（仅内部与保存流程）；单次上限 8 MiB。
    pub async fn commit_write(&self, request: WriteRequest)
        -> Result<ResourceMetadata, ChipsError>;

    /// 流式写入提交：打开可写流，以 `commit_write_stream` 原子提交。
    pub fn open_write_stream(&self, request: WriteStreamRequest)
        -> Result<WriteStreamHandle, ChipsError>;

    /// 提交流式写入；失败回滚临时物。
    pub async fn commit_write_stream(&self, handle: WriteStreamHandle)
        -> Result<ResourceMetadata, ChipsError>;

    /// 失效作用域全部缓存与句柄。
    pub fn invalidate_scope(&self, scope: &ScopeId, reason: InvalidateReason);
}
```

| 方法           | 语义                                                                                                 | 关键失败码                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `open`         | 解析 URI → 作用域与会话校验 → 权限判定 → 分配句柄                                                    | `RESOURCE_INVALID_URI`、`RESOURCE_NOT_FOUND`、`RESOURCE_PERMISSION_DENIED`                     |
| `stat`         | 读元数据；命中元数据缓存                                                                             | `RESOURCE_HANDLE_RELEASED`、`RESOURCE_HANDLE_INVALIDATED`、`RESOURCE_PERMISSION_DENIED`        |
| `read_range`   | 范围读；不写入 L1 字节缓存                                                                           | `RESOURCE_BUSY`、`RESOURCE_TOO_LARGE`、`RESOURCE_POOL_EXHAUSTED`、`RESOURCE_PERMISSION_DENIED` |
| `read_chunk`   | 单次拉取上限 256 KiB；不拉取即不推进（背压）                                                         | 同上（含 `RESOURCE_PERMISSION_DENIED`）                                                        |
| `release`      | 归还租约、关闭游标、移出句柄表、写审计                                                               | 未知/墓碑 ID 幂等；跨会话拒绝 `RESOURCE_PERMISSION_DENIED`                                     |
| `commit_write` | 临时文件 + 原子替换；归档来源拒绝就地写；单次写入上限 8 MiB，大资源用 `commit_write_stream` 流式提交 | `RESOURCE_READ_ONLY`、`RESOURCE_WRITE_FAILED`、`RESOURCE_TOO_LARGE`                            |

句柄状态机、缓存层级、路径安全与 Provider 契约见 [04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 第四、六、九节；错误码全表见其 §5.5。

N-1 句柄归属闸注记（2026-09-23，任务 #201 臂①，安全巡检残项复核 §一.1 交回上收，《04.11-04-资源管理设计》§11.1 注记同口径）：`stat` / `read_range` / `read_chunk` / `release` 四句柄臂携带 `session: SessionId`，服务端以句柄在册归属（`HandleTable` 条目的 `entry.session`，`open` 时登记）比对调用方会话，跨会话以在册拒绝形 `RESOURCE_PERMISSION_DENIED`（`details.permission = "session"`、`reason = "out_of_scope"`、`target` = 句柄规范 URI）收口。归属闸次序为「状态闸先行、归属闸后行」——未知/墓碑句柄仍按原口径挂 `RESOURCE_HANDLE_RELEASED` / `RESOURCE_HANDLE_INVALIDATED`，`release` 对未知 ID 保持幂等；`read_chunk` 归属比对先于流槽位占用，越权拒绝零副作用（不抢流、不还租约）。此为 `chips-resource` 内部 Rust API，不触 §7.3 Neon 导出面（导出签名只增不改、该波三方锁账 49 项零漂移，`session` 由绑定层进程级句柄↔会话归属账回取，见《04.11-04-资源管理设计》§11.3 注记）。

挂载/注销会话闸注记（2026-09-23，工单036 波 A1 落位，任务 #209，与《04.11-04-资源管理设计》§11.3「挂载/注销会话闸」注记同口径）：`mount_directory` / `mount_archive` 以 `(session, registration)` 一体完成注册 + 挂根/挂档 + 绑会话，会话缺失以 `RESOURCE_PERMISSION_DENIED`（`reason = "out_of_scope"`、`target` = scope 规范 URI、零路径泄漏）收口，失败全量回滚；绑定层 `resourceUnregisterScope(scope, sessionId)` 的会话归属闸为绑定层补齐项（核心 `unregister_scope(&ScopeId)` 签名不动），未绑定前置拒绝，二次注销双形在册（绑定形 `RESOURCE_PERMISSION_DENIED`、核心形 `RESOURCE_NOT_FOUND`）。三导出 `kind` 面绑定层钉死 `ScopeKind::Document`、归档域只读强制；登记与派生规则详见《04.11》§11.3（波 A1，零核心改动）。

权限判定观察面注记（2026-09-23，任务 #178，RFC-权限审计跨层采集sink裁定 §八/§九实施波文档承接）：`resolve` 的 `PermissionChecker` 判定收敛处按判定臂分类发射素材（3.5）——经授予判定的 allow/deny（含 `policy` 类拒绝臂）在各注册表锁外经 `emit_permission_decision` 发射一条素材；免权限直通臂（Platform 公开只读、Plugin 自身作用域读、Document 会话绑定免重复校验）与非权限拒绝臂（`RESOURCE_READ_ONLY`）零发射（RFC §九 9.3-3，工单046 裁定二）。observer 构造期注入、终身不可换；默认无观察的 `Default` 实现随实施波收口移除。

### 7.2 资源会话

```rust
pub struct ResourceSession {
    pub id: SessionId,
    pub kind: SessionKind,
    pub owner: PluginId,
    pub scopes: BTreeSet<ScopeId>,
    pub permissions: BTreeSet<String>,   // 权限快照（`resources:*` 与 `network:http:*` 在册 ID 集合）
    pub parent: Option<SessionId>,       // 父会话（顶层会话为 None）
}

pub enum SessionKind {
    Document,
    Plugin,
    Window,
}

impl ResourceManager {
    /// 创建顶层会话：`scopes` 与 `permissions` 双集入参（薄包装形
    /// `impl IntoIterator`，落表为 BTreeSet）。
    pub fn open_session(
        &self,
        kind: SessionKind,
        owner: &PluginId,
        scopes: impl IntoIterator<Item = ScopeId>,
        permissions: impl IntoIterator<Item = String>,
    ) -> Result<SessionId, ChipsError>;

    /// 派生子会话；`scopes` 与 `permissions` 双集均须为父会话子集，不允许扩权。
    pub fn derive_session(
        &self,
        parent: SessionId,
        scopes: &[ScopeId],
        permissions: &BTreeSet<String>,
    ) -> Result<SessionId, ChipsError>;

    /// 向活会话追加权限字符串集（工单053 点位五，Neon 导出 `resourceGrantSession`
    /// 的唯一 Rust 挂点）：`SessionRegistry::grant_permission` 薄包装，语义三问见下。
    pub fn grant_session(
        &self,
        session: SessionId,
        permissions: impl IntoIterator<Item = String>,
    ) -> Result<(), ChipsError>;

    /// 关闭会话并级联释放全部句柄与租约。
    pub fn close_session(&self, session: SessionId) -> Result<(), ChipsError>;
}
```

会话与渲染会话一一对应；派生子会话用于渲染帧内的基础卡片与布局插件，父会话关闭时级联关闭（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) §11.2）。

会话授权注入语义三问定案（2026-09-23，工单053 点位五，RFC-原生会话授权注入裁定 J §三，导出与 owner 哨兵闸面见《04.11-04-资源管理设计》§11.3 `resourceGrantSession` 行）：①**幂等静默**——重复授予同串走 `BTreeSet::insert` 集语义恒 `Ok`、集不变，与挂载面 `attach_scope` 同方言（绑定层不造第二语义），空数组为合法 no-op，会话不存在回 `RESOURCE_NOT_FOUND`；②**不提供 revoke**——权限只增不减，撤销走 `derive_session` 子集派生（收窄正式形）或 `close_session` 整体终结（权限集随会话记录消亡、零残留），不建活会话第二撤销通道（INV-6 同族纪律），`PermissionDenyReason::Revoked` 词位为 Bridge 能力撤销链预留、资源会话面不用；③**字符串透传**——授予侧对权限串内容零语法判断（仅 string 类型闸），限定形（`resources:write:<scope>`）照投、由 `PermissionChecker` 判定矩阵单点消费（`require()` 臂放行 Workspace / 他人 Plugin 作用域），**Document 写臂不扩限定形**（只认 `resources:write` 精确基串，限定形若入 Document 属《06.04-04-资源协议规范》§4.3 判定矩阵协议变更、须另走 RFC）；grant 不产判定、不发权限判定观察素材（3.5 节观察面零触达）、`scopes` 集零触碰（挂载面与授权面职责分离）。

### 7.4 TypeScript 调用示例

```typescript
import { resourceOpen, resourceRead, resourceRelease } from '../../native';

interface IResourceMetadata {
  uri: string;
  size: number;
  mimeType: string;
  version: string;
  scope: 'workspace' | 'document' | 'plugin' | 'platform' | 'external' | 'temporary' | 'memory';
}

interface IResourceOpenResult {
  handleId: number;
  metadata: IResourceMetadata;
}

/** 按 Range 读取卡片资源；句柄使用后必须释放。 */
export async function readResourceRange(
  uri: string,
  sessionId: number,
  offset: number,
  length: number
): Promise<Uint8Array> {
  const opened: IResourceOpenResult = await resourceOpen(uri, sessionId);

  try {
    const bytes: Buffer = await resourceRead(opened.handleId, offset, length);
    return new Uint8Array(bytes);
  } finally {
    resourceRelease(opened.handleId);
  }
}
```
