## 四、`IBaseCardEditor` 编辑契约

### 4.1 类型定义

```typescript
type EditorState = 'active' | 'disposed';

interface ICardPatchOperation {
  op: 'add' | 'remove' | 'replace';
  path: string;                       // RFC 6901 指针，相对 content 根，不允许根指针
  value?: unknown;                    // op 为 add / replace 时必填
}

type BaseCardChange =
  | { kind: 'replace'; content: Record<string, unknown> }
  | { kind: 'patch'; operations: readonly ICardPatchOperation[] };

interface IBaseCardEditorEventMap {
  change: { change: BaseCardChange };
  dirty: { isDirty: boolean };
}

interface IBaseCardEditor {
  readonly state: EditorState;
  isDirty(): boolean;
  getChange(): BaseCardChange | null;
  markCommitted(revision: number): void;
  update(basecard: BaseCardView, revision: number): void;
  subscribe<TEvent extends keyof IBaseCardEditorEventMap>(
    event: TEvent,
    handler: (payload: IBaseCardEditorEventMap[TEvent]) => void,
  ): ISubscription;
  focus(): void;
  dispose(): void;
}
```

> 布局编辑句柄 `ILayoutEditor` 是另一套独立类型，见 [09-箱子布局插件接口](./09-箱子布局插件接口.md) §7.1；SDK 分别导出两者，不导出笼统的 `IEditor`。

### 4.2 成员说明

| 成员 | 说明 |
|---|---|
| `state` | `active` 可编辑；`disposed` 已释放，除 `state` / `dispose()` 外一切行为为空操作 |
| `isDirty()` | 是否存在尚未回流的变更；等价于 `getChange() !== null` |
| `getChange()` | 返回相对基线的累计变更；无变更返回 `null` |
| `markCommitted(revision)` | 编辑链路成功把 `getChange()` 结果回流到会话后调用；以该 revision 更新基线并清除已提交变更 |
| `update(basecard, revision)` | 会话视图因外部变化前进时调用，以新节点视图替换基线；调用前编辑器必须无待提交变更 |
| `subscribe(event, handler)` | 订阅 `change` / `dirty`；返回 `ISubscription`，`dispose()` 幂等 |
| `focus()` | 请求编辑器获取焦点；由编辑链路在窗口激活、用户进入编辑时调用 |
| `dispose()` | 释放编辑器与其全部订阅；幂等 |

### 4.3 变更回流协议

```
插件编辑器                  编辑链路（IEditSession）            文档服务             渲染会话
    │ getChange()                │                                │                    │
    │───────────────────────────▶│                                │                    │
    │                            │ 校验 configSchema              │                    │
    │                            │ + validateConfig               │                    │
    │                            │ document:write ───────────────▶│                    │
    │                            │◀─────────────── { revision } ──│                    │
    │                            │ 组装新 DocumentView                                │
    │                            │ session.update(view, revision) ──────────────────▶│
    │ markCommitted(revision)    │                                │                    │
    │◀───────────────────────────│                                │                    │
    │（基线前进、清除已提交变更）   │                                                    │
```

规则：

1. 回流唯一时序：`getChange()` → 编辑链路校验（`configSchema` + `validateConfig`）→ `document:write`（输出 `{ revision }`）→ 渲染会话 `update(view, revision)` → `markCommitted(revision)`；顺序不得交换或省略。
2. `change` 与 `dirty` 事件同时可用：编辑链路可订阅事件驱动回流，也可用 `getChange()` 拉取（订阅后立即拉取可避免竞态）。
3. `{ kind: 'replace' }` 提交完整节点内容：`content` 之外的节点字段（`node_id` / `card_type` / `card`）由编辑链路按会话当前视图组装，编辑器不得依赖自己维护的副本。
4. `{ kind: 'patch' }` 只描述 `content` 的增量：`path` 使用 RFC 6901 指针，相对 `content` 根；`op` 为 `add` / `replace` 时 `value` 必填。
5. 编辑器应把同一任务或同一动画帧内的多次编辑合并为一次变更发布，避免逐键触发回流；回流到预览更新 ≤ 100ms（同一 rAF 合并），自动保存默认防抖 500ms（可配），失焦/关闭前 flush（[12-编辑引擎设计](../01-架构设计/01-子系统设计/12-编辑引擎设计.md)）。
6. 回流成功后编辑链路调用 `markCommitted(revision)`；若编辑器在此期间产生了新变更，`isDirty()` 保持为真并等待下一轮回流。
7. 会话视图因查看帧更新、外部文件变更收敛等原因变化时，编辑链路先完成或放弃待提交变更，再调用 `update(basecard, revision)`；`revision` 不大于编辑器已知值时编辑器忽略该调用。
8. 编辑器不负责保存：写回持久化由文档服务完成；`document:write` 只改内存模型，落盘取 `document:save`（[11-文档服务设计](../01-架构设计/01-子系统设计/11-文档服务设计.md)、[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §8.3）。
9. `dispose()` 不发布任何事件、不持久化数据；待提交变更直接丢弃，需要保留时由编辑链路在释放前先行回流。

### 4.4 实现规则

- 编辑器必须在 `dispose()` 中释放全部订阅、定时器、Observer、资源句柄与媒体资源，并停止触碰容器。
- 订阅必须经 `subscribe()` 建立并由 `dispose()` 统一释放；禁止在组件外长期持有订阅而不释放（[05-事件契约规范](./05-事件契约规范.md)）。
- 编辑器允许在变更过程中产生未通过校验的中间状态；校验由 `validateConfig` 与编辑链路在回流/保存时执行（§7.4）。
- 释放后调用 `getChange()` 返回 `null`、`isDirty()` 返回 `false`、`update()` 与 `focus()` 为空操作、`subscribe()` 返回已失效订阅。
