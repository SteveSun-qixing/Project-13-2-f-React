## 九、约束与自检清单

强制规则：

- 命令的展示文案简体中文直写，禁止 i18n key（R5）。
- 命令注册只提交元数据，禁止把函数、句柄或不可序列化对象写入定义。
- 菜单、托盘、工具栏、命令面板与快捷键只消费 `ICommandView` 并经 `command:invoke` 触发，禁止私有动作模型与绕过校验的直调。
- 命令处理函数内的资源访问按各自能力契约独立判定，命令调用不构成资源授权。
- 快捷键、图标、参数 schema 均按本文规则归一与校验；平台不接收未登记的命令错误码。
- 命令能力与权限的登记以 [04-能力契约规范](./04-能力契约规范.md) 与 [08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 为落位；事件以 [05-事件契约规范](./05-事件契约规范.md) 与 [09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md) 为落位。

自检清单：

- [ ] 命令 ID 为 `<domain>:<action>`，域与 owner 命名空间一致，未与能力/权限/事件 ID 重名。
- [ ] 定义字段齐全且通过 §2.2 约束；`paramsSchema` 使用平台子集且顶层 `additionalProperties: false`。
- [ ] `when` 只使用 §2.5 登记的条件键；`state` 由平台求值，未在消费方自行推导。
- [ ] 注册/更新/注销/调用均写审计，审计不含 `payload` 原文。
- [ ] 快捷键归一化、冲突判定与可编辑上下文保护规则已实现并有测试覆盖。
- [ ] ui 目标命令在注册记录与本地处理器之间通过 `(commandId, handlerId)` 正确配对；窗口关闭后本地处理器与平台记录同时清理。
- [ ] 菜单与托盘引用未登记命令时在 `menu:set` 阶段被拒绝。
- [ ] CLI 入口只引用命令 ID，通过 `command:invoke` 执行，未直连插件代码。
- [ ] 权限声明与角色匹配（`command:write` 仅 `app`），未申请未登记权限。
- [ ] 示例与错误码经复核，未出现未登记的 `COMMAND_*` 错误码。
