## 三、公共类型与错误模型（chips-core）

### 3.1 标识别名

```rust
/// 插件 ID：反向域名，例如 chips.official.editor。
pub type PluginId = String;

/// 服务名：小写短名，规范见 01-薯片内核设计 5.1。
pub type ServiceName = String;

/// 事件名：`<domain>:<action>`，规范见 09-事件系统设计 2.2。
pub type EventName = String;

/// 服务值：可跨线程共享并支持类型下转。
pub type ServiceValue = Arc<dyn Any + Send + Sync>;

/// 平台分配、单调递增的 ID 族；数值低于 2^53。
pub type ContextId = u64;
pub type ForkId = u64;
pub type InjectionId = u64;
pub type SessionId = u64;
pub type HandleId = u64;
```

规则：

- ID 由平台分配、单调递增、释放后不复用；跨 JS 边界以 `number` 传输，禁止超过 2^53。
- `SessionId` 是渲染会话与会话级资源租约的统一标识；会话解析与绑定规则见 [02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) §7.4，资源会话见 7.2 节。
- 插件代码不可构造或猜测任何 ID（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) §4.6）。

### 3.2 CancelToken

```rust
#[derive(Debug, Clone, Default)]
pub struct CancelToken {
    /* Arc<AtomicBool> + 通知原语，见实现 */
}

impl CancelToken {
    /// 创建未取消的令牌。
    pub fn new() -> Self;

    /// 触发取消；幂等；可从任意线程调用。
    pub fn cancel(&self);

    /// 是否已取消；可从任意线程调用。
    pub fn is_cancelled(&self) -> bool;

    /// 等待取消；已取消时立即返回。
    pub async fn cancelled(&self);
}
```

| 成员 | 语义 |
|---|---|
| `new` | 生成独立令牌；克隆共享同一状态 |
| `cancel` | 一次触发、永久生效；重复调用为 no-op |
| `is_cancelled` | 轮询式检查点（解析阶段边界、文件循环、chunk 循环） |
| `cancelled` | 等待式检查点（异步任务在取消时结束等待） |

取消是协作式的：持有令牌的任务必须在检查点响应取消并释放已占用资源（[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) §10.4）。解析器与 Bridge 调用共用该类型；Neon 以 `JsBox<CancelToken>` 暴露（见 8.4 节）。

### 3.3 ChipsError

跨边界错误只有一个形状：`ChipsError`。子系统错误保持各自的强类型枚举（`KernelError`、`DocumentError` 等），在 Neon 边界归一为 `ChipsError`。

```rust
use thiserror::Error;

/// 跨语言边界的统一错误。
#[derive(Debug, Clone, Error)]
#[error("{message}")]
pub struct ChipsError {
    code: String,
    message: String,
    details: Option<serde_json::Value>,
    retryable: bool,
}

impl ChipsError {
    /// 以错误码与用户可读消息构造；`retryable` 默认 false。
    pub fn new(code: impl Into<String>, message: impl Into<String>) -> Self;

    /// 附加结构化诊断（JSON Pointer、字段名、目标等）。
    pub fn with_details(self, details: serde_json::Value) -> Self;

    /// 标记可重试；仅当重新执行可能成功时使用。
    pub fn with_retryable(self, retryable: bool) -> Self;

    pub fn code(&self) -> &str;
    pub fn message(&self) -> &str;
    pub fn details(&self) -> Option<&serde_json::Value>;
    pub fn retryable(&self) -> bool;
}
```

| 字段 | 规则 |
|---|---|
| `code` | `<DOMAIN>_<REASON>`，全大写、下划线分隔；同一个 `code` 只有一个含义 |
| `message` | 简体中文、面向用户；不携带堆栈、内部路径与原始输入 |
| `details` | 结构化诊断；字段随域定义，可含 `file`、`pointer`、`permission` 等 |
| `retryable` | 仅作提示：`true` 表示重新执行可能成功；`false` 不得自动重试（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) §9.4） |

错误码命名空间与归一来源：

| 来源 | 码前缀 | 归一方式 |
|---|---|---|
| 内核（`KernelError`） | `KERNEL_*` | `From<KernelError>`；码表见 [01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) §9.1 |
| Bridge（`chips-bridge`） | `BRIDGE_*` | 直接构造；码表见 [02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) §9.2 |
| 文档解析（`DocumentError`） | `DOCUMENT_*` | `From<DocumentError>`；码表见 [06-文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md) §8.2 |
| 资源管理 | `RESOURCE_*` | 直接构造；码表见 [04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) §5.5 |
| 权限系统 | `PERMISSION_*`、`PLUGIN_PERMISSION_DENIED` | 直接构造；`PLUGIN_PERMISSION_DENIED` 只表示权限拒绝（启用、能力注册阶段的权限校验失败）；插件生命周期状态错误使用内核状态码 `KERNEL_*`（如 owner 未 `active` 时注册能力返回 `KERNEL_INVALID_TRANSITION`），码表见 [08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) |
| 事件系统 | `EVENT_*` | 直接构造；码表见 [09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md) §3.4 |
| 原生绑定层（`chips-native`） | `NATIVE_*` | 直接构造；最小码表见本节下表；JS 侧未识别异常反向归一为 Bridge 通道级 `BRIDGE_INTERNAL`（见 5.2、8.5 节） |
| Host 业务实现 | `<DOMAIN>_<REASON>`（如 `FILE_NOT_FOUND`、`DOCUMENT_NOT_OPEN`） | 原样透传，不改写 `code` 与 `retryable` |
| 未识别异常 | `<DOMAIN>_INTERNAL` | 归一为通用文案，诊断写宿主日志，不回传堆栈 |

绑定层码段 `NATIVE_*`（2026-09-20 实测登记，工单006 收口；与 `packages/native/src/error.rs` 的常量与 `error.rs` / `convert.rs` / `handles.rs` / `context.rs` / `runtime.rs` 各构造点逐项一致）：

| 错误码 | 触发条件 | `message` | `details` | `retryable` |
|---|---|---|---|---|
| `NATIVE_TYPE_UNSUPPORTED` | 跨边界值映射收到不可传输的值：JS→Rust 方向的 `undefined`（根位置或数组元素）、含非法 UTF-16 序列的字符串、`BigInt`、`Error` 实例、`Buffer` / `Uint8Array` / `ArrayBuffer` / 其它 TypedArray（二进制必须走 `{ json, bin }` 信封）、函数、类实例或宿主对象、传输白名单外的其它值，以及数组 / 对象读取与属性枚举失败；服务值注册（`contextProvide`）收到数组、非对象非函数值或读取失败；`contextInject` 的 `dependencies` 元素不是字符串 | `值类型不受支持：{detail}` | `{ "pointer": <JSON Pointer>, "detail": <简体中文原因> }` | `false` |
| `NATIVE_VALUE_OUT_OF_RANGE` | 整数超出可精确表示范围（`u64 ≥ 2^53`、`\|i64\| ≥ 2^53`；含 `contextInject` 返回的注入 ID 与 `contextOn` 返回的监听令牌键出边界）；`f64` 非有限（`NaN` / `Infinity`）；`contextUnsubscribe` 的监听令牌不是 `> 0`、整值、有限且 `< 2^53` 的 `number` | 经构造函数归一时为 `值超出可表示范围：{detail}`；`contextUnsubscribe` 的令牌校验为 `监听令牌非法` | 经构造函数归一时为 `{ "pointer": <JSON Pointer>, "detail": <简体中文原因> }`（非有限数的 `detail` 固定为 `NaN / Infinity 不可传输`）；`contextUnsubscribe` 的令牌校验失败时不携带 `details` | `false` |
| `NATIVE_INTERNAL` | 绑定层自身状态异常：绑定层专用 tokio 运行时初始化失败、监听令牌空间耗尽（计数达到 `2^53`）、监听令牌表互斥锁不可用、服务值句柄已释放（`contextGet` 取不回 `Root` 值） | 由构造点给出的简体中文诊断；运行时初始化失败时附底层错误文本 | 不携带 | `false` |

绑定层码段规则：

1. 三个码是绑定层唯一可用码，由 `error.rs` 的 `NATIVE_TYPE_UNSUPPORTED` / `NATIVE_VALUE_OUT_OF_RANGE` / `NATIVE_INTERNAL` 常量与 `type_unsupported()` / `value_out_of_range()` / `internal_error()` 构造函数唯一来源；绑定层不得新增第四个 `NATIVE_*` 码。
2. 转换层内部诊断 `ConvertIssue`（`TypeUnsupported` / `ValueOutOfRange` / `NonFiniteNumber`）经 `into_error()` 归一到本表：`NonFiniteNumber` 归入 `NATIVE_VALUE_OUT_OF_RANGE`，不单独成码；`ConvertIssue` 本身不跨边界暴露。
3. `pointer` 为 RFC 6901 JSON Pointer（根为 `""`，段内 `~` / `/` 转义为 `~0` / `~1`），指向 8.2 节映射递归中出错的具体位置；`detail` 为简体中文一句话原因。
4. 本表三个码只在 Rust ↔ JS 边界内产生，`retryable` 一律为 `false`（`ChipsError::new` 默认值，绑定层不调用 `with_retryable`）；消费方不得据此自动重试。
5. 非法 UTF-16 序列归入 `NATIVE_TYPE_UNSUPPORTED`；二进制值误用（未走 `{ json, bin }` 信封的信封结构错误）使用已登记的 `BRIDGE_INVALID_INPUT`（见 5.2 节与 [04-能力契约规范](04-能力契约规范.md) 第 11.3 节），不占用 `NATIVE_*` 码段。
6. 内核服务类型不匹配的跨语言下转拒绝使用已登记的内核码 `KERNEL_SERVICE_TYPE_MISMATCH`（见 8.4 节），不使用 `NATIVE_*`。

TS 侧错误类（类实现见 [02-SDK-API规范](02-SDK-API规范.md)）：构造统一为 `new ChipsError({ code, message, details?, retryable? })`；`IChipsError` 仅作结构别名：

```typescript
class ChipsError extends Error {
  constructor(options: {
    code: string;
    message: string;
    details?: unknown;
    retryable?: boolean;
  });
  readonly code: string;
  readonly details?: unknown;
  readonly retryable: boolean;
}

interface IChipsError {
  code: string;
  message: string;
  details?: unknown;
  retryable?: boolean;
}
```

Rust 用法示例：

```rust
use std::path::Path;

use chips_core::ChipsError;
use chips_parser::{CardParser, DocumentHandle, ParseOptions};

/// 打开卡片并把解析错误归一为跨边界错误。
pub fn open_card_normalized(path: &Path) -> Result<DocumentHandle, ChipsError> {
    CardParser::new(ParseOptions::default())
        .open(path)
        .map_err(ChipsError::from)
}
```
