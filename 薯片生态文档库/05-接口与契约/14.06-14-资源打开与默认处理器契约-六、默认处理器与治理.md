# 资源打开与默认处理器契约

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：资源打开路由的权威契约：打开来源与打开请求模型、manifest 处理器声明与 `primary` / `fallback` 层级、路由解析顺序与投递授权、启动载荷 `resourceOpen` 与业务载荷约定、默认处理器偏好 `platform.fileOpen.defaults` 与槽位治理接口、未安装/停用/卸载的降级与回收、与文档/条目/封面链路的关系；资源 URI 语法、句柄与权限判定本身不在此定义。

## 六、默认处理器与治理

### 6.1 偏好存储

默认处理器偏好存储在平台配置键 `platform.fileOpen.defaults`（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §2.3；产品与交互见 [05-生态设置面板设计](../08-产品与交互/05-生态设置面板设计.md) §3.7）：

| 项 | 规则 |
|---|---|
| 键 | `platform.fileOpen.defaults`（`platform` 命名空间，非策略键） |
| 值 | `Record<slot-key, pluginId>`；`slot-key` 为 `mime:<mime>` 或 `ext:<ext>`，`pluginId` 为反向域名插件 ID |
| 生效层 | 写入用户层；生效值按平台键覆盖顺序解析（工作区层 → 用户层 → 平台层 → schema 默认） |
| 读取方 | 路由解析（§4.2）；审计与诊断只记录槽位键与结果 |
| 写入方 | 设置类插件经 `config:set`（命名空间 `platform`，需 `config:write:platform` 限定值）；平台卸载回收为主进程内部写入（§7.2） |

槽位键文法：

```text
slot-key  = "mime:" mime | "ext:" ext
mime      = type "/" ( subtype | "*" )
type      = RFC 6838 token（小写）
subtype   = RFC 6838 token（小写）
ext       = "." 1*( lowercase / digit / "." / "-" / "_" / "+" )
```

值 schema 约束：对象最多 256 项；键匹配上述文法；值为长度不超过 256 的插件 ID 字符串。读写示例：

```typescript
/** 读取当前偏好（UI 侧）。 */
const current = await chips.request<IConfigGetOutput>('config:get', {
  namespace: 'platform',
  key: 'fileOpen.defaults',
});

/** 把 ext:.png 的默认处理器设为图片查看器（读改写单条变更）。 */
const preferences: Record<string, string> =
  isRecord(current.value) === true ? (current.value as Record<string, string>) : {};

await chips.request<void>('config:set', {
  namespace: 'platform',
  key: 'fileOpen.defaults',
  value: { ...preferences, 'ext:.png': 'chips.official.photo-viewer' },
  scope: 'user',
});
```

规则：

- 偏好项只对存在的槽位生效：指向未声明候选的插件时被忽略（§4.2），但记录保留并可在治理界面查看与清除。
- 治理界面对同一键的并发写入按到达顺序串行提交；每次提交前重新读取当前值并只修改目标槽位项，避免覆盖其他槽位。
- 清除单条偏好 = 从值对象中移除该键后写回；恢复全部默认 = `config:reset`（键 `fileOpen.defaults`，用户层）。
- 偏好变更落盘后发布 `config:changed`（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §六），路由无需重启即时生效。

### 6.2 槽位视图 `resource:list-handlers`

治理界面与其他只读消费方经 `resource:list-handlers` 获取槽位视图：

| 项 | 值 |
|---|---|
| 能力 ID | `resource:list-handlers` |
| 所需权限 | 无（只读编目：不含资源内容、真实路径与用户数据；调用仍写审计） |
| 输入 | 空对象（`{ type: 'object', additionalProperties: false, properties: {} }`） |
| 输出 | `IListHandlersOutput` |
| 幂等性 | 是 |

```typescript
/** 槽位候选。 */
export interface IHandlerCandidate {
  readonly pluginId: string;
  /** manifest name。 */
  readonly name: string;
  readonly role: 'app' | 'service';
  readonly tier: HandlerTier;
  /** 该候选是否被用户偏好选中（偏好无效时不置位，见 §4.2）。 */
  readonly isPreferred: boolean;
}

/** 处理器槽位。 */
export interface IHandlerSlot {
  /** 槽位键：mime:<mime> 或 ext:<ext>。 */
  readonly slot: string;
  /** 槽位为 MIME 槽位时的 MIME。 */
  readonly mimeType?: string;
  /** 槽位为扩展名槽位时的扩展名。 */
  readonly extension?: string;
  /** 偏好键上的原始记录；可能指向已停用、失败或已卸载插件。 */
  readonly preferencePluginId: string | null;
  /** 当前生效默认：有效偏好优先，否则按 §4.1 排序后的首个候选。 */
  readonly defaultPluginId: string | null;
  /** 候选清单：有偏好且有效时偏好项在前，其后 primary、fallback，同级按安装顺序。 */
  readonly handlers: readonly IHandlerCandidate[];
}

export interface IListHandlersOutput {
  readonly slots: readonly IHandlerSlot[];
}
```

规则：

- 槽位集合 = 全部 `active` 插件声明产生的槽位，加上含偏好记录但当前无候选的槽位（用于展示与清除失效偏好）。
- 无候选且无偏好记录的槽位不出现在结果中，避免无界列表。
- `handlers` 只含 `active` 候选；`preferencePluginId` 原样返回，治理界面据此提示「偏好指向的处理器当前不可用」。
- 顺序固定：偏好项（若有效）在前，其余 primary 先于 fallback，同层级按安装顺序，同刻安装按插件 ID 字典序。
- 视图是即时快照；插件安装、启用、停用、卸载后需重新查询（治理界面订阅 `plugin:*` 事件刷新，见 [05-生态设置面板设计](../08-产品与交互/05-生态设置面板设计.md) §5）。

### 6.3 治理操作

| 操作 | 调用 | 说明 |
|---|---|---|
| 查看槽位 | `resource:list-handlers` | 按扩展名与 MIME 分组展示候选、层级、生效默认与来源 |
| 设为默认 | `config:set`（§6.1） | 写入或覆盖该槽位的偏好项；下一行显示生效层 |
| 清除偏好 | `config:set`（移除该槽位键） | 回落平台优先级（§4.1） |
| 恢复全部默认 | `config:reset` | 移除 `fileOpen.defaults` 用户层覆盖，全部槽位回落平台优先级 |

约束：

- 治理界面属于设置类插件（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §1.2）；平台不内置治理界面，也不向治理界面开放内部注册表。
- 治理只改偏好，不改插件声明、不改权限、不启动插件；偏好不产生任何新的资源访问授权。
- 无候选槽位、失效偏好项必须可见且可清除，不得隐藏或自动改写用户记录（卸载回收除外，§7.2）。
