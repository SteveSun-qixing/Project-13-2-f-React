## 五、Bridge（chips-bridge）

Bridge 内核持有能力注册表与调用收口逻辑；三层职责、权限判定、Schema 校验与并发策略见 [02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md)。

### 5.1 注册

```rust
/// 能力描述：注册与静态发现所需的元数据。
pub struct CapabilityDescriptor {
    /// 能力 ID：`<domain>:<action>[:<target>]`。
    pub id: String,
    /// 输入的 JSON Schema。
    pub schema: serde_json::Value,
    /// 执行该能力所需权限 ID 的并集。
    pub permissions: Vec<String>,
}

/// 并发策略。
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum Concurrency {
    /// 同一能力可并发执行。
    #[default]
    Parallel,
    /// 同一能力 ID 全局串行，队列上限为 `max_queue`。
    Serial,
}

/// 能力输入信封：`json` 走 schema 校验；`bin` 承载 `x-chips-binary` 字段的字节。
pub struct CapabilityInput {
    pub json: serde_json::Value,
    pub bin: BTreeMap<String, Vec<u8>>,
}

/// 能力输出信封；`bin` 表与 `json` 中声明为 `x-chips-binary` 的字段一一对应。
pub struct CapabilityOutput {
    pub json: serde_json::Value,
    pub bin: BTreeMap<String, Vec<u8>>,
}

/// 能力执行的取消与截止信息；对应 TS 侧 `ctx.signal` / `ctx.deadline`。
pub struct CapabilityContext {
    /// 取消信号；会话销毁、能力注销、Bridge 关闭与超时触发。
    pub signal: CancelToken,
    /// 执行截止时刻。
    pub deadline: std::time::Instant,
}

/// 能力执行器：Rust 能力与 TS 能力共用该抽象。
#[async_trait]
pub trait CapabilityExecutor: Send + Sync {
    /// 执行能力；`input.json` 已通过 Schema 校验；错误必须归一为 `ChipsError`。
    /// 实现必须响应 `ctx.signal` 并在 `ctx.deadline` 前收口。
    async fn execute(
        &self,
        ctx: &CapabilityContext,
        input: CapabilityInput,
    ) -> Result<CapabilityOutput, ChipsError>;
}

/// 能力注册项；对应 02-Bridge三层设计 4.1 的注册项：
/// `ICapability` 的元数据抽为 `CapabilityDescriptor`，执行部分抽为 `CapabilityExecutor`。
pub struct CapabilityRegistration {
    pub descriptor: CapabilityDescriptor,
    /// 提供方标识：平台服务域 ID 或服务插件 ID（反向域名）。
    pub owner: String,
    /// 调用超时（毫秒），默认 30000。
    pub timeout_ms: u64,
    pub concurrency: Concurrency,
    /// 串行队列上限，默认 32。
    pub max_queue: usize,
    pub executor: Arc<dyn CapabilityExecutor>,
}

impl Bridge {
    /// 注册能力；失败时提供方启用失败。
    pub fn register(&self, registration: CapabilityRegistration) -> Result<(), ChipsError>;

    /// 注销能力；在途调用按超时/取消收口。
    pub fn unregister(&self, capability_id: &str) -> Result<(), ChipsError>;
}
```

注册校验（注册期一次性完成，热路径不再重复）：ID 格式合法且全局唯一；`schema` 可离线编译；`permissions` 均在权限词表内且已在提供方 manifest 声明；`owner` 已激活。失败码：`BRIDGE_CAPABILITY_CONFLICT`、`BRIDGE_INVALID_SCHEMA`、`PERMISSION_NOT_DECLARED`。能力 ID 与任何权限 ID 不得相同（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) §4.2、§4.3）。

### 5.2 调用

```rust
/// 一次能力调用请求。
pub struct BridgeRequest {
    /// 调用唯一标识（UUID v4），由 preload 生成。
    pub request_id: String,
    pub capability_id: String,
    /// 已由适配层解析的会话。
    pub session: SessionId,
    /// 输入信封；`json` 的 Schema 校验在 `request` 内完成，`bin` 直接透明传递。
    pub input: CapabilityInput,
}

/// 执行器可见的调用上下文。
pub struct InvocationContext {
    pub request_id: String,
    pub capability_id: String,
    pub owner: String,
    pub session: SessionId,
    pub plugin_id: PluginId,
    /// 追踪 ID，与事件、权限审计一致。
    pub trace_id: String,
    /// 取消令牌；取消、超时、会话销毁时触发。
    pub cancel: CancelToken,
    /// 执行截止时刻；与 `CapabilityContext.deadline` 同源。
    pub deadline: std::time::Instant,
}

impl Bridge {
    /// 完成会话校验、注册表命中、权限判定、Schema 校验与并发准入后执行能力。
    pub async fn request(&self, request: BridgeRequest) -> Result<CapabilityOutput, ChipsError>;

    /// 取消会话全部在途调用；幂等。
    pub fn cancel_session(&self, session: SessionId);
}
```

| 阶段 | 行为 | 失败码 |
|---|---|---|
| 会话校验 | 会话不存在或已关闭立即拒绝 | `BRIDGE_SESSION_UNKNOWN` |
| 注册表命中 | 未注册能力拒绝 | `BRIDGE_CAPABILITY_NOT_FOUND` |
| 权限判定 | 会话快照未覆盖能力权限拒绝 | `BRIDGE_PERMISSION_DENIED` |
| Schema 校验 | 输入不合法拒绝，不填充默认值 | `BRIDGE_INVALID_INPUT` |
| 并发准入 | 会话在途超限、串行队列溢出 | `BRIDGE_SESSION_BUSY`、`BRIDGE_QUEUE_OVERFLOW` |
| 执行 | 超时触发 `cancel` 并丢弃迟到结果 | `BRIDGE_TIMEOUT` |
| 取消 | 会话销毁、能力注销、Bridge 关闭 | `BRIDGE_CANCELLED` |
| 归一 | 未识别异常 | `BRIDGE_INTERNAL` |

- 超时不保证无副作用；插件不得仅凭超时假定"未执行"（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) §8.1）。
- Bridge 不自动重试、不去重执行；`request_id` 只用于关联与丢弃迟到结果。
- 完整触发条件与 `retryable` 取值见 [02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) §9.2。

### 5.3 TypeScript 适配层示例

适配层完成会话解析、IPC 编解码与能力执行编排；授权判定与 Schema 校验始终在 Rust 侧（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) §2.1）。

```typescript
// packages/host-electron/src/main/native-bridge.ts：chips-native.node 的类型视图（与 8.6 节导出表一致）
export interface INativeBridgeRequest {
  requestId: string;
  capabilityId: string;
  sessionId: number;
  input: unknown;
  /** 二进制信封：`x-chips-binary` 字段的字节表（键与 input 中引用名一致）。 */
  bin?: Record<string, Uint8Array>;
}

export interface INativeCapabilityContext {
  readonly signal: AbortSignal;
  readonly deadline: number;
}

export interface INativeCapabilityRegistration {
  descriptor: {
    id: string;
    schema: Record<string, unknown>;
    permissions: string[];
  };
  owner: string;
  timeoutMs: number;
  concurrency: 'parallel' | 'serial';
  maxQueue: number;
  handler: (input: unknown, ctx: INativeCapabilityContext) => Promise<unknown>;
}

export interface INativeBridge {
  bridgeRegister(registration: INativeCapabilityRegistration): void;
  bridgeUnregister(capabilityId: string): void;
  bridgeRequest(request: INativeBridgeRequest): Promise<unknown>;
  bridgeCancelSession(sessionId: number): void;
}
```

```typescript
import type { ChipsError, ICapability, IBridgeRequest, IBridgeResponse } from '@chips/bridge';
import { ChipsError as ChipsErrorClass } from '@chips/sdk';
import type { INativeBridge } from './native-bridge';

/** 注册一个由 TS 实现的能力；执行由 Rust 侧发起并经回调返回。 */
export function registerCapability(bridge: INativeBridge, capability: ICapability): void {
  bridge.bridgeRegister({
    descriptor: {
      id: capability.id,
      schema: capability.schema,
      permissions: capability.permissions,
    },
    owner: 'chips.official.host',
    timeoutMs: 30_000,
    concurrency: 'parallel',
    maxQueue: 32,
    handler: (input: unknown, ctx: INativeCapabilityContext): Promise<unknown> =>
      capability.execute(input, ctx),
  });
}

/** 处理一次渲染进程的能力请求。 */
export async function dispatchBridgeRequest(
  bridge: INativeBridge,
  request: IBridgeRequest,
  sessionId: number,
): Promise<IBridgeResponse> {
  try {
    const result = await bridge.bridgeRequest({
      requestId: request.requestId,
      capabilityId: request.capabilityId,
      sessionId,
      input: request.input,
      bin: request.bin,
    });
    return { requestId: request.requestId, ok: true, result };
  } catch (error) {
    return { requestId: request.requestId, ok: false, error: normalizeError(error) };
  }
}

function normalizeError(error: unknown): ChipsError {
  if (error instanceof ChipsErrorClass) {
    return error;
  }
  return new ChipsErrorClass({
    code: 'BRIDGE_INTERNAL',
    message: '桥接内部错误',
    retryable: false,
  });
}
```
