## 三、认证与令牌管理

### 3.1 读写边界

- **公开读接口**：`GET /api/v1/health`、`GET /api/v1/cards/*`、`GET /api/v1/boxes/*` 与查看/封面/受控产物代理路由，无需令牌；私有资源按 404 处理，不暴露存在性。
- **令牌保护接口**：`GET /api/v1/cards/manage`、`PATCH` / `DELETE` 卡片与箱子、全部 `/api/v1/card-transfer/*` 接口。

```http
Authorization: Bearer <API_TOKEN>
```

### 3.2 令牌格式与校验

- 令牌由服务器部署环境变量 `API_TOKEN` 配置，长度不少于 16 字符（[08-服务端部署与运维](../06-开发与运维/08-服务端部署与运维.md) §6.3）。
- 服务器使用常量时间比较校验令牌，避免时序侧信道。
- 校验失败（缺失、格式错误、长度不符、不匹配）统一返回 `401 API_TOKEN_INVALID`；不返回差异细节，不锁定来源，不提供重试次数限制。
- 个人服务器没有账号、角色与权限模型：持有令牌即拥有全部写权限，不存在细粒度权限位。

### 3.3 令牌配置与轮换

- 令牌只在服务器环境变量中维护；不提供在线创建、列举、吊销令牌的接口（单用户模型）。
- 轮换：在部署主机更新 `API_TOKEN` 并重启服务器；新令牌立即生效、旧令牌立即失效。轮换步骤与密钥纪律见 [08-服务端部署与运维](../06-开发与运维/08-服务端部署与运维.md) §6.4。
- 已签发的预签名对象地址由对象存储独立校验签名，其有效期内不随令牌轮换失效。
- 令牌轮换不影响已发布内容与既有对象。

### 3.4 客户端保存与传递

- 客户端传输引擎通过调用输入 `server.baseUrl` 与 `server.accessToken` 携带令牌（`accessToken` 即管理令牌）；凭据保存遵循 Host 凭据管理规则。
- 禁止：令牌写入查询参数、路径、对象键、卡片/箱子文件、恢复清单、前端代码与日志；禁止为多人分发同一令牌（个人服务器无隔离能力）。

### 3.5 可见性口径

- 读接口对 `private` 卡片/箱子与不存在资源一律返回 `404`（`CARD_NOT_FOUND` / `BOX_NOT_FOUND`），不暴露存在性。
- 全部上传会话固定以 `public` 创建；作品发布后可通过 `PATCH` 改为 `private`（5.6 节、6.2 节）。

### 3.6 CORS 与来源放行

- 开发模式（`NODE_ENV=development`）放行全部来源。
- 生产模式放行：`BASE_URL` 同源、薯片 Host 渲染进程来源（`Origin` 以 `chips-render:` 开头或 `file://` 产生的 `null`）、`CORS_EXTRA_ORIGINS` 白名单（逗号分隔）。
- 允许携带凭据；允许方法 `GET/POST/PUT/PATCH/DELETE/OPTIONS`；不允许凭据出现在 URL 或对象键中。
