## 八、脚手架（`@chips/sdk/scaffold`）

### 8.1 职责

- 提供四种角色（`basecard` / `boxlayout` / `app` / `service`）的模板清单与生成器；角色、ID 命名空间与官方示例以 [官方插件与应用目录](../03-插件开发/09-官方插件与应用目录.md) §二、§4.3 为准。
- 生成器是纯函数：只产出文件计划（路径 + 内容）与结构化 manifest，不写磁盘、不联网、不安装依赖。
- 文件写入、依赖安装与 `.cpk` 打包由 `@chips/cli` 执行；工作区与插件工程统一使用 pnpm（唯一包管理器），内部依赖使用 `workspace:*`（[快速开始](../03-插件开发/01-快速开始.md)、[01-代码组织规范](../02-开发规范/01-代码组织规范.md)）。
- 生成结果必须能直接通过 manifest 校验与插件包格式校验，并在 `pnpm install` 后直接执行 `build` / `test` / `package`（[插件清单规范](../03-插件开发/02-插件清单规范.md)、[插件包格式](../04-文件格式规范/03-插件包格式.md)、[构建与打包](../06-开发与运维/02-构建与打包.md) §5.5）。

### 8.2 四角色模板清单

每个角色恰有一个标准模板；`listScaffoldTemplates()` 返回四条记录，`files` 与下表逐项一致。下表中 `<slug>` 为插件 ID 末段（`chips.basecard.markdown` → `markdown`、`chips.layout.grid` → `grid`）：

| 角色        | 生成文件（相对 `targetDir` 的 POSIX 路径）                                                                                                                                                                             | 对应指南                                                                                                      |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `basecard`  | 公共文件 + `vite.render.config.ts` + `src/config.ts`、`src/main.ts`、`src/render.tsx`、`src/index.ts`、`assets/icons/<slug>.svg`、`assets/schemas/<slug>-config.schema.json`、`tests/config.test.ts`                   | [基础卡片插件开发指南](../03-插件开发/04-基础卡片插件开发指南.md) §二                                         |
| `boxlayout` | 公共文件 + `vite.render.config.ts` + `src/config.ts`、`src/main.ts`、`src/render.tsx`、`src/index.ts`、`assets/icons/<slug>.svg`、`assets/schemas/<slug>-config.schema.json`、`tests/setup.ts`、`tests/render.test.ts` | [箱子布局插件开发指南](../03-插件开发/05-箱子布局插件开发指南.md) §二                                         |
| `app`       | 公共文件 + `vite.render.config.ts` + `src/index.ts`、`src/commands/appCommands.ts`、`src/commands/useAppCommands.ts`、`src/ui/AppView.tsx`、`assets/icons/app.svg`、`tests/app.test.ts`、`tests/commands.test.ts`      | [应用插件开发指南](../03-插件开发/03-应用插件开发指南.md) §三、[快速开始](../03-插件开发/01-快速开始.md) §3.2 |
| `service`   | 公共文件 + `src/index.ts`、`assets/schemas/config.schema.json`、`tests/service.test.ts`                                                                                                                                | [服务插件开发指南](../03-插件开发/06-服务插件开发指南.md) §二                                                 |

公共文件指：`manifest.yaml`、`package.json`、`tsconfig.json`、`README.md`、`vite.shared.ts`、`vite.main.config.ts`、`vitest.config.ts`。

规则：

1. `manifest.yaml`、`package.json`、`tsconfig.json` 为全部角色生成；`README.md`、`vite.shared.ts`、`vite.main.config.ts`、`vitest.config.ts` 同样随模板生成，保证工程开箱可读、可构建、可测试；`tsconfig.json` 继承仓库 `tsconfig.base.json`，包内不重复定义编译选项（[01-代码组织规范](../02-开发规范/01-代码组织规范.md) §2.2）。
2. 入口文件与角色接口一一对应：`app` → `IAppPlugin`、`basecard` → `IBaseCardPlugin`、`boxlayout` → `IBoxLayoutPlugin`、`service` → `IServicePlugin`；两个入口均为默认导出对象的 ESM（[07-应用插件接口](./07-应用插件接口.md)、[08-基础卡片插件接口](./08-基础卡片插件接口.md)、[09-箱子布局插件接口](./09-箱子布局插件接口.md)、[10-服务插件接口](./10-服务插件接口.md)、[插件包格式](../04-文件格式规范/03-插件包格式.md) §2.4）。
3. `basecard` 的 `src/index.ts` 只做拆分导出：`src/main.ts` 构建为 `dist/index.js`、`src/render.tsx` 构建为 `render.js`；`boxlayout` 同构（[基础卡片插件开发指南](../03-插件开发/04-基础卡片插件开发指南.md) §2.3、[箱子布局插件开发指南](../03-插件开发/05-箱子布局插件开发指南.md) §2.2）。
4. 构建配置与《构建与打包》§5.5 一致：主进程入口目标 `node18`、自包含单文件 → `dist/index.js`；渲染入口目标 `chrome118`、外部化平台 vendor 并重写为固定 URL → 包根 `render.js`；`vite.shared.ts` 提供构建期 R4 红线守卫（[构建与打包](../06-开发与运维/02-构建与打包.md) §5.5）。
5. 依赖口径：平台提供物（`react`、`react-dom`、`@chips/ui`）与全部构建期依赖一律 `devDependencies`，第三方依赖为精确版本，内部依赖为 `workspace:*`（[依赖管理与锁文件规范](../06-开发与运维/10-依赖管理与锁文件规范.md) §2）。
6. 生成内容必须为完整可构建内容：不含占位符、TODO、未替换变量与简化实现；`pnpm install` 后可直接执行 `build` / `test` / `test:coverage` / `package`。
7. `manifest.yaml` 的 `type` 与角色一致；生成的文件引用一律为包内相对路径且位于 `assets/` 内（[插件清单规范](../03-插件开发/02-插件清单规范.md) §2.3、[插件包格式](../04-文件格式规范/03-插件包格式.md) §2.6）。
8. `service` 模板不生成 `render.js`、`vite.render.config.ts` 与 UI 资源；`vitest.config.ts` 的环境为 Node，`boxlayout` 为 jsdom 且 jsdom 臂随模板生成 `tests/setup.ts` 并接入 `setupFiles`（补齐 jsdom 缺失的 `window.matchMedia` 兜底，antd 响应式观测依赖）（[插件包格式](../04-文件格式规范/03-插件包格式.md) §3.1）。
9. 模板实现位于 `chips-ecosystem/tools/scaffold/src/templates/`；`@chips/sdk/scaffold` 只转发公开面，不复制模板文本。

### 8.3 纯函数生成器与 API

```typescript
type PluginRole = 'basecard' | 'boxlayout' | 'app' | 'service';
type PluginTarget = 'host';
type PluginSurface = 'window' | 'desktop' | 'tray';

// 插件运行目标只有 host：平台不提供 web 浏览器页面运行形态，runtime.targets 不含 'web'（[04-能力契约规范](./04-能力契约规范.md) §6.4）。

/** 插件清单（TS 形状）；字段语义与校验见《02-插件清单规范》。 */
interface IPluginManifest {
  readonly id: string;
  readonly version: string;
  readonly type: PluginRole;
  readonly name: string;
  readonly description?: string;
  readonly author?: string;
  readonly license?: string;
  readonly runtime: IPluginRuntime;
  readonly engines?: IPluginEngines;
  readonly dependencies?: readonly IPluginDependency[];
  readonly permissions?: readonly string[];
  readonly capabilities?: IPluginCapabilities;
  readonly ui?: IPluginUi;
  readonly fileAssociations?: readonly IPluginFileAssociation[];
  readonly deepLinks?: readonly IPluginDeepLink[];
  readonly healthCheck?: IPluginHealthCheck;
  /** `cli.commands` 声明面；形状见本节类型面注记与《02-插件清单规范》§7.6。 */
  readonly cli?: IPluginCli;
}

/** 深链接声明条目；字段语义见《02-插件清单规范》。 */
interface IPluginDeepLink {
  readonly scheme: string;
  readonly host: string;
  readonly pathPattern?: string;
}

interface IPluginRuntime {
  readonly targets: readonly PluginTarget[];
  readonly background?: boolean;
}

/** 平台版本范围门禁；字段语义与校验见《02-插件清单规范》第 3.6 节。 */
interface IPluginEngines {
  readonly chips: string;
}

interface IPluginDependency {
  readonly id: string;
  readonly version: string;
}

/** 卡片导出格式条目；字段语义见《08-基础卡片插件接口》6.3。 */
interface IPluginExportFormat {
  readonly id: string;
  readonly name: string;
  readonly extension: string;
  readonly mimeType: string;
}

/** manifest 中声明的卡片类型条目；字段语义见《08-基础卡片插件接口》6.2。 */
interface IPluginCardType {
  readonly id: string;
  readonly name: string;
  readonly description?: string;
  readonly icon?: string;
  readonly extensions?: readonly string[];
  readonly aliases?: readonly string[];
  readonly configSchema?: string;
  readonly exportFormats?: readonly IPluginExportFormat[];
}

/** manifest 中声明的布局类型条目；字段语义见《09-箱子布局插件接口》2.1。 */
interface IPluginLayoutType {
  readonly id: string;
  readonly name: string;
  readonly icon?: string;
  readonly description?: string;
  readonly configSchema: string;
  readonly schemaVersions: string;
}

interface IPluginCapabilities {
  readonly cardTypes?: readonly IPluginCardType[];
  readonly layouts?: readonly IPluginLayoutType[];
}

/** manifest 中声明的文件关联条目；字段语义见《07-应用插件接口》5.4。 */
interface IPluginFileAssociation {
  readonly extensions: readonly string[];
  readonly action: 'open';
}

interface IPluginUi {
  readonly surface: PluginSurface;
  readonly launcher?: Readonly<Record<string, unknown>>;
}

interface IPluginHealthCheck {
  readonly interval: string;
  readonly timeout: string;
}

// CLI 契约面十名随本入口在册（逐名登记见本节类型面注记；本段不重复字段文法）：
// IPluginCli、IPluginCliCommand、IPluginCliCommandConflict、IPluginCliCommandJob、
// IPluginCliCommandOutput、IPluginCliCommandSurface、IPluginCliCommandTarget、
// IPluginCliParameter、IPluginCliParameterPath 与参数类型标量联合 PluginCliParameterType
// （`IPluginCliParameter` 的 `type` 字段类型）。

/** 一个角色的脚手架模板描述。 */
interface IScaffoldTemplate {
  readonly role: PluginRole;
  readonly description: string;
  readonly files: readonly string[];
}

/** 脚手架生成选项。 */
interface IScaffoldOptions {
  readonly role: PluginRole;
  readonly pluginId: string;
  readonly name: string;
  readonly description?: string;
  readonly author?: string;
  readonly license?: string;
  readonly targetDir: string;
}

/** 生成的文件：path 为相对 targetDir 的 POSIX 路径。 */
interface IScaffoldFile {
  readonly path: string;
  readonly content: string;
}

/** 脚手架计划：纯数据，由调用方落盘。 */
interface IScaffoldPlan {
  readonly targetDir: string;
  readonly template: IScaffoldTemplate;
  readonly manifest: IPluginManifest;
  readonly files: readonly IScaffoldFile[];
}

/** 列出全部角色的脚手架模板。 */
function listScaffoldTemplates(): readonly IScaffoldTemplate[];

/**
 * 生成指定角色的脚手架计划。
 *
 * @param options - 角色、插件 ID、名称与目标目录
 * @returns 文件计划与结构化 manifest
 * @throws {ChipsError} 参数不合法时抛出 SDK_INVALID_SCAFFOLD_OPTIONS
 */
function createScaffoldPlan(options: IScaffoldOptions): IScaffoldPlan;
```

类型面注记（2026-09-23 正式登记，任务 #239 随转发面代码合入翻正）：本节公开类型面为上述 manifest 形状、`IScaffold*` 四型与 CLI 契约面十名——`IPluginManifest` 的 `cli?` 字段对应九个接口类型 `IPluginCli`、`IPluginCliCommand`、`IPluginCliCommandConflict`、`IPluginCliCommandJob`、`IPluginCliCommandOutput`、`IPluginCliCommandSurface`、`IPluginCliCommandTarget`、`IPluginCliParameter`、`IPluginCliParameterPath` 与参数类型标量联合 `PluginCliParameterType`（`IPluginCliParameter` 的 `type` 字段类型，《07-CLI完整参考》§5.2 在册 11 种取值）。十名已纳入全部三层转发面并逐名在册：`@chips/scaffold` 公开入口（`tools/scaffold/src/index.ts`，类型 29 名）、`@chips/sdk/scaffold` 子入口类型转发面（`packages/sdk/src/scaffold/index.ts`，29 名 = 上游公开类型面全集）与 `@chips/sdk` 主入口 manifest 再导出块（`packages/sdk/src/index.ts`，25 名 = §2.2 在册 15 名 + CLI 契约面十名），插件侧可经类型导入路径逐名 `import type` 消费。形状单源为 `tools/scaffold/src/types.ts`，三层均以 `export type` 透传、不存在第二份形状；在册名单由 `tools/scaffold/tests/public-surface.test.ts` 与 `packages/sdk/tests/cli-types-forwarding.test.ts` 两锁测按逐名精确集合锁定（少一名或多一名都红）。CLI 命令声明的字段文法与校验权威仍为《[02-插件清单规范](../03-插件开发/02-插件清单规范.md)》§7.6 与 [07-CLI完整参考](../06-开发与运维/07-CLI完整参考.md) §五。

### 8.4 参数校验

| 参数        | 规则                                                               | 违规结果                       |
| ----------- | ------------------------------------------------------------------ | ------------------------------ |
| `role`      | 必须是四个角色之一                                                 | `SDK_INVALID_SCAFFOLD_OPTIONS` |
| `pluginId`  | 反向域名（如 `chips.official.editor`），小写字母、数字、点与连字符 | `SDK_INVALID_SCAFFOLD_OPTIONS` |
| `name`      | 非空简体中文显示名                                                 | `SDK_INVALID_SCAFFOLD_OPTIONS` |
| `targetDir` | 非空；计划内路径相对该目录                                         | `SDK_INVALID_SCAFFOLD_OPTIONS` |
| `license`   | 省略时为 `MIT`                                                     | —                              |

校验规则：

1. `role` 取值决定模板与 `manifest.type`；`theme` / `module` 等旧角色不存在，传入即拒绝（[官方插件与应用目录](../03-插件开发/09-官方插件与应用目录.md) §一）。
2. `pluginId` 同时用于 `manifest.id` 与默认包名派生；官方角色使用对应命名空间（`chips.official.*` / `chips.basecard.*` / `chips.layout.*` / `chips.service.*`），示例统一使用 `chips.basecard.markdown`（[官方插件与应用目录](../03-插件开发/09-官方插件与应用目录.md) §2.1、§4.3）。实现校验命名空间与角色一致：`chips.official.*` 只允许 `app`、`chips.basecard.*` 只允许 `basecard`、`chips.layout.*` 只允许 `boxlayout`、`chips.service.*` 只允许 `service`；第三方使用自有域（如 `com.example.*`）。
3. 作废的旧式 ID 一律拒绝：`com.chips.*`、`chips-official.*`、`chips.module.*` 前缀与 `.blp` 后缀。
4. 校验失败抛出的 `ChipsError` 不产生部分计划；调用方不得落盘半个工程（[插件清单规范](../03-插件开发/02-插件清单规范.md) §1.3）。
5. `createScaffoldPlan` 不校验 `targetDir` 的当前内容；目标目录的占用与写入冲突由 `@chips/cli` 在执行落盘时判定（[CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §3.5.1）。

### 8.5 角色差异

| 角色        | 生成差异                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `basecard`  | `manifest.capabilities.cardTypes` 至少一项；类型 ID 符合 [插件清单规范](../03-插件开发/02-插件清单规范.md) §7.2 文法，图标与 `configSchema` 文件随类型同时生成且路径一致；`src/main.ts` 承载主进程纯函数（默认导出），`src/render.tsx` 承载 `renderView` / `renderEditor` / `export`（默认导出）；查看/编辑界面使用 React 与 `@chips/ui`，视觉数值取 Design Tokens                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `boxlayout` | `manifest.capabilities.layouts` 至少一项，每项包含 `configSchema` 与 `schemaVersions`；生成布局图标、配置 schema、`tests/setup.ts` 与 `tests/render.test.ts`（jsdom 测试面）；`src/render.tsx` 承载 `renderLayout` / `renderEditor` 并实现 `IBoxLayoutRuntimeAware`（条目帧经 `requestEntries` / `mountEntry` 挂载）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `app`       | 生成 `manifest.ui`（`surface: window` 与 `launcher`）与启动器图标；`src/index.ts` 实现 `IAppPlugin`，`src/ui/AppView.tsx` 为 React 界面根组件并在根组件挂载 `ChipsProvider` 一次（`appId` 与 manifest 一致、`surface` 与 `manifest.ui.surface` 一致）；命令系统样例随模板生成：manifest 声明面为 `cli.commands` 两条（`<域>:open-card` 带 `path` 位置参数与 `surface` 开关、`<域>:refresh-view` 带 `output` 声明，`<域>` 为插件 ID 末段）并随声明 `permissions: ['command:write', 'command:execute']`，消费位为 `src/commands/appCommands.ts`（可序列化 `ICommandDefinition[]` 与处理器工厂）与 `src/commands/useAppCommands.ts`（按《[13-命令系统契约](./13-命令系统契约.md)》§5.6 时序接线 `command:register` → `CommandProvider` 订阅 `command:invoked` 按 `(commandId, handlerId)` 配对派发 → 卸载时幂等注销），`tests/commands.test.ts` 锁定元数据可序列化与注册派发行为；宿主 `command:*` 域尚无生产注册（Host 覆盖矩阵在册缺口），样例只声明消费位形状与 Bridge 不可用时的错误收敛语义，不声称端到端可派发；`deepLinks` 不在默认模板中，按需声明（[应用插件开发指南](../03-插件开发/03-应用插件开发指南.md) §四、[@chips/ui 共享层使用指南](../02-开发规范/08-@chips-ui共享层使用指南.md) §3.1） |
| `service`   | 生成 `manifest.healthCheck` 与 `src/index.ts` 中的 `health()`；`runtime.background` 不强制（缺省 `false`，需要常驻时声明 `true`）；不生成 `render.js`、`vite.render.config.ts` 与 UI 资源（[服务插件开发指南](../03-插件开发/06-服务插件开发指南.md) §2.2）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

### 8.6 完整示例

```typescript
import { createScaffoldPlan, listScaffoldTemplates } from '@chips/sdk/scaffold';

const templates = listScaffoldTemplates();
const basecard = templates.find((template) => template.role === 'basecard');
console.log(basecard?.files);

const plan = createScaffoldPlan({
  role: 'basecard',
  pluginId: 'chips.basecard.markdown',
  name: 'Markdown 卡片',
  targetDir: 'plugins/markdown-card',
});

console.log(plan.manifest.type); // 'basecard'
for (const file of plan.files) {
  // @chips/cli 负责把 file.content 写入 plan.targetDir/file.path
  console.log(file.path);
}
```

生成的 `manifest.yaml` 示例：

```yaml
id: chips.basecard.markdown
version: 0.1.0
type: basecard
name: Markdown 卡片
author: 薯片官方
license: MIT
runtime:
  targets:
    - host
permissions: []
capabilities:
  cardTypes:
    - id: base.markdown
      name: Markdown 卡片
      icon: assets/icons/markdown.svg
      configSchema: assets/schemas/markdown-config.schema.json
```

`plan.files` 与 8.2 节的 `basecard` 模板清单逐项一致；`manifest.yaml` 的 `cardTypes[].id`（`base.markdown`）为 [官方插件与应用目录](../03-插件开发/09-官方插件与应用目录.md) §4.3 登记的正式标识。
