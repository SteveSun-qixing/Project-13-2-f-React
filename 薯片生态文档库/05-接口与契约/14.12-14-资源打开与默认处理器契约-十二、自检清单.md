# 资源打开与默认处理器契约

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：资源打开路由的权威契约：打开来源与打开请求模型、manifest 处理器声明与 `primary` / `fallback` 层级、路由解析顺序与投递授权、启动载荷 `resourceOpen` 与业务载荷约定、默认处理器偏好 `platform.fileOpen.defaults` 与槽位治理接口、未安装/停用/卸载的降级与回收、与文档/条目/封面链路的关系；资源 URI 语法、句柄与权限判定本身不在此定义。

---

## 十二、自检清单

- [ ] 打开来源覆盖 `os-association` / `drop` / `in-app` / `frame`，且各来源的归一与授权路径有明确归属。
- [ ] `resource:open` 与 `resource:list-handlers` 的输入 schema、输出类型、权限与错误码齐全。
- [ ] `fileAssociations` 扩展字段（`mimeTypes`、`tier`）的语义、校验与去重规则完整。
- [ ] 匹配等级（M1/M2/E1）、组内排序（层级 → 安装顺序 → 插件 ID）与偏好覆盖顺序唯一且确定。
- [ ] 启动载荷 `IResourceOpenLaunchArgs` 与 `resourceOpen` 字段齐全，且不含真实路径。
- [ ] 标准载荷（音乐、视频、电子书）登记完整，文件卡片无 payload 的口径与格式文档一致。
- [ ] `platform.fileOpen.defaults` 的键文法、值 schema、写入层与治理操作齐全。
- [ ] 槽位视图包含失效偏好、只含 `active` 候选、排序稳定。
- [ ] 未安装 / 停用 / failed / 卸载 / 更新五种状态对候选、偏好与槽位的影响明确，卸载回收有实现与失败语义。
- [ ] 未命中降级覆盖 External、Directory、Archive、Memory 四类来源，无静默失败。
- [ ] 投递授权的作用域、清单、生命周期与审计明确，且不写入持久授权。
- [ ] 与条目、封面、文档链路的关系边界明确，无交叉路由。
- [ ] 本文件所有链接指向真实文档；术语、类型名与错误码与 [04-能力契约规范](./04-能力契约规范.md)、[06-资源协议规范](./06-资源协议规范.md) 一致。
