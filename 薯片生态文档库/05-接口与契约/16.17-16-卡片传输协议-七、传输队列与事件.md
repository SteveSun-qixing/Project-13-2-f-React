# 卡片传输协议

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：`.card` / `.box` 在本地设备与内容服务器之间传输的权威协议：传输会话（创建、预签名、分片、断点续传、取消、恢复）、完整离线卡片与网络资源卡片的可逆改写与还原（含可逆恢复清单）、摘要与完整性校验、预签名与对象存储桶角色、传输队列与 `transfer:*` 事件映射、错误码与安全约束；不覆盖卡片/箱子的包结构语义、渲染链路与服务器产品设计。

## 七、传输队列与事件

### 7.1 队列模型

- 平台传输队列是 Host 侧统一传输调度机制，`transfer:*` 能力族与卡片传输任务共用同一队列与同一组事件。
- 卡片传输任务由传输引擎提交（其面向插件的绑定另行登记）；`transfer:download` / `transfer:cancel` 是队列的公开能力调用面，面向插件发起的单 URL 下载，不作为卡片会话对象的下载入口。
- 每个任务拥有不透明 `transferId`，由队列分配并在任务生命周期内稳定；任务的 `transferId` 同时是 `transfer:*` 事件载荷中的标识。
- 任务种类：`card-upload`、`card-download`、`open-remote`、`box-upload`。
- 队列任务字段（对调用方可见的最小集）：

| 字段 | 类型 | 语义 |
|---|---|---|
| `transferId` | string | 任务标识 |
| `kind` | string | 任务种类 |
| `state` | string | 7.2 状态 |
| `phase` | string \| null | 7.2 阶段；`queued` 时为 null |
| `cardId` / `boxId` | string \| null | 会话建立后写入 |
| `totalBytes` | number \| null | 预计总字节；对象清单未确定时为 null |
| `transferredBytes` | number | 已完成字节（含已完成对象与分片） |
| `outputPath` | string \| null | 下载类任务的本地目标路径 |
| `communityUrl` | string \| null | 上传类任务的社区地址 |
| `error` | object \| null | 失败时的 `ChipsError` 同构对象 |
| `updatedAt` | string | 最后更新时间（ISO 8601 UTC） |

- 任务在 Host 进程内可跨界面生命周期存续；队列不跨 Host 进程持久化，重启后的恢复以会话与检查点为准（3.5、3.9）。

### 7.2 任务状态与阶段

```text
queued ──▶ running ──▶ completed
              │  ▲
              │  └── resume ── paused
              ├──▶ cancelling ──▶ cancelled
              └──▶ failed
```

| 状态 | 语义 |
|---|---|
| `queued` | 已入队，等待调度 |
| `running` | 正在执行 |
| `paused` | 因网络、宿主或调用方暂停；保留检查点，可恢复 |
| `cancelling` | 已收到取消，正在收口（中止分片、清理临时物） |
| `completed` | 成功终态 |
| `failed` | 失败终态，错误已投递 |
| `cancelled` | 取消终态 |

阶段（`phase`）：

| 任务 | 阶段顺序 |
|---|---|
| `card-upload` | `inspect` → `unpack` → `scan` → `session` → `upload-resources` → `rewrite` →（可选 `render` → `render-cover` → `upload-render`）→ `pack` → `presign-card` → `submit` → `completed` |
| `card-download` | `session` → `download-card` → `unpack` → `restore` → `pack` → `verify` → `completed` |
| `open-remote` | `session` → `download-card` → `open` → `completed` |
| `box-upload` | `inspect` → `unpack` → `collect-loose-cards` → `upload-loose-cards` → `session` → `presign` → `upload-box` → `submit` → `completed` |

- 阶段是任务查询与本地展示字段，不进入 `transfer:*` 事件载荷（事件载荷以[05-事件契约规范](./05-事件契约规范.md) §4.10 为唯一权威）。
- 取消可在任何阶段发起；协作式取消在对象与分片边界生效，取消后按 7.5 收口。

### 7.3 并发、限流与重试

- 并发：队列同时运行的传输任务数、单任务内并发对象数与单对象内并发分片数由平台统一配置；默认策略为按队列顺序调度、任务内按对象顺序推进、同对象分片可并发。
- 限流：进度发布按[05-事件契约规范](./05-事件契约规范.md) §4.10 的最小发布间隔节流；队列不得无界堆积任务，超出并发上限的任务保持 `queued`。
- 重试策略（传输引擎统一执行）：

| 失败类型 | 策略 |
|---|---|
| 网络瞬断、超时、对象存储 5xx / 408 / 429 | 指数退避重试，默认最多 3 次 |
| 控制面 5xx | 退避重试，默认最多 3 次 |
| 401 未授权 / 令牌过期 | 刷新一次令牌后重试；再次失败按 `CARD_TRANSFER_AUTH_EXPIRED` 终态 |
| 403 禁止 | 不重试 |
| 摘要/大小不一致 | 按 5.5 处理 |
| 会话过期 | 不重试；按 3.5.3 新建会话重做 |

- 每次重试前必须检查任务取消信号；取消时立即中止（`CARD_TRANSFER_CANCELLED`）。

### 7.4 `transfer:*` 事件映射

事件名、载荷字段、触发时机、可见性与最小发布间隔以[05-事件契约规范](./05-事件契约规范.md) §4.10 为唯一权威；本节只定义卡片传输任务的取值语义：

| 事件 | 卡片传输取值语义 |
|---|---|
| `transfer:progress` | `transferredBytes` 为任务内已完成对象字节与已完成分片字节之和（含当前对象已下载/已上传部分）；`totalBytes` 为计划总字节（对象清单确定后为各对象 `sizeBytes` 之和，之前为 null） |
| `transfer:completed` | 在服务器确认提交成功（上传）或还原并通过校验（下载/远程打开）后发布；`target` 语义：下载类任务为最终输出路径，上传类任务为网络资源卡片/箱子源文件的规范对象位置，远程打开为本地网络资源卡片路径；`digest` 为任务产物 SHA-256（上传为网络资源卡片或箱子文件的摘要，下载为重建后完整卡片的摘要，远程打开为网络资源卡片摘要） |
| `transfer:failed` | 上传/下载失败或取消后发布；`error` 为归一 `ChipsError`；`cancelled` 标记是否由取消导致；发布时临时物已清理、输出目标未被部分写入 |

- 事件可见性为发起任务的应用插件与平台；订阅方不得依赖逐条投递计算关键状态，应以任务查询或终态事件为准。
- 卡片传输不新增事件名；需要任务阶段与队列信息时使用 7.1 的任务查询。

### 7.5 取消与失败语义

- 取消入口：调用方取消任务（`transfer:cancel` 对队列任务同样有效）或任务所在会话结束；两者等价。
- 取消收口顺序：停止新对象与分片 → 中止 `multipart` → 调用会话 `abort`（上传）→ 清理临时工作副本与 `.part` → 发布 `transfer:failed`（`cancelled: true`）。
- 下载与远程打开的取消不修改服务器内容；未完成的输出文件必须删除，不得留下半个卡片。
- 失败终态必须携带 8.2 的 `CARD_TRANSFER_*` 错误码；失败后任务不可原地重试，须由调用方重新发起（可从检查点恢复）。
