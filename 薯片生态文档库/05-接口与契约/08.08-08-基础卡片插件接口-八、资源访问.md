## 八、资源访问

所有资源访问统一经 `chips-resource://`，受限、可审计（R17、RR-4）。完整 URI 语法、作用域分配、权限与错误码以[06-资源协议规范](./06-资源协议规范.md)为准；插件只使用以下两条正式路径。

### 8.1 协议路径（DOM 引用）

1. 渲染帧加载时注入 `<base href="{resourceBase}">`，`basecard.content` 中的包内相对引用（如 `photo.jpg`，相对卡片包根）可直接用于 `src` / `href` / `url()`，由帧解析到包内资源（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §5.1）。
2. 也可使用 `chips-resource://` 绝对 URI；两者之外一律禁止：`file://`、裸绝对路径、未受管的远端地址不得进入帧（R13）。
3. 帧内 `connect-src 'none'`：不提供 JS 字节读取接口，不发起网络请求；需要解码或解析的重活在编辑侧或服务侧完成，帧内只负责呈现。
4. 帧内用户动作（打开链接、打开文档、复制、通知）必须经帧运行时协议转发（`frame:action`），由 RenderHost 做权限判定（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §9.2）；查看态单击 / 双击 / 中键的默认语义与投递归一以 [14-资源打开与默认处理器契约](./14.08-14-资源打开与默认处理器契约-八、与条目、封面和文档链路的关系.md) §8.5 为准。

### 8.2 句柄路径（元数据、字节与失效感知）

```typescript
async function readTextResource(uri: string): Promise<string> {
  // uri 为调用方提供的受管资源引用；句柄形状与完整语义见 06-资源协议规范
  const handle = window.chips.resource(uri);
  try {
    const bytes = await handle.read();
    return new TextDecoder().decode(bytes);
  } finally {
    handle.release();
  }
}
```

规则：

1. 句柄只在需要元数据、字节或失效感知时使用；纯呈现优先使用协议路径。
2. 句柄只读；大资源用 `readRange()` 或 `stream()`，`read()` 超过 8 MiB 返回 `RESOURCE_TOO_LARGE`（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) §4.4）。
3. 句柄与资源会话绑定：会话关闭、插件停用、作用域失效时强制失效；插件必须在 `dispose()` 中 `release()` 全部句柄并退订 `onInvalidate`。
4. 作用域 ID 由平台分配，插件不得构造、猜测或伪造（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) §2.3）；引用只允许来自卡片数据或调用方提供的解析结果。
5. 句柄不得跨窗口、跨会话、跨插件传递；不得把字节复制进 `basecard.content`。

### 8.3 禁止

| 禁止 | 说明 |
|---|---|
| 帧内访问 `window.chips` | 帧内一律经帧协议；`window.chips` 仅就近渲染容器可用（§5.4） |
| `fetch` / XHR 直连 | 帧内被 CSP 阻断；宿主侧必须经资源协议 |
| 裸路径与 `file://` | 违反 R13、R17 |
| 访问自身作用域外的资源 | 默认拒绝，跨作用域需 `resources:read:<scope>` 授权（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) §5.3） |
