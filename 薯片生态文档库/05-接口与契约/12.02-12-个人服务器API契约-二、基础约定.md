## 二、基础约定

### 2.1 基础路径与数据格式

- API 前缀：`/api/v1`；个人服务器不提供后台 API 前缀。
- 控制面请求与响应：JSON（UTF-8）；`Content-Type: application/json`。
- 文件字节不经 API：源文件、资源与渲染产物全部由客户端直传对象存储，API 只做控制面。
- 时间格式：ISO 8601（UTC）。
- 主键 ID：UUID v4；作品内置 ID（`cardFileId` / `boxFileId`）为 10 位 Base62 字符串。

### 2.2 统一响应信封

成功（单对象）：

```json
{ "data": {} }
```

成功（列表附带分页）：

```json
{
  "data": [],
  "pagination": { "page": 1, "pageSize": 20, "total": 100, "totalPages": 5 }
}
```

失败：

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "请求参数不合法",
    "details": { "traceId": "…" },
    "retryable": false
  }
}
```

- `code` 只取第七节登记值；未登记业务码不得出现在响应中。
- `message` 一律简体中文、面向用户；`details` 为结构化诊断，不含令牌、预签名地址、真实文件系统路径与堆栈。
- `details.traceId` 用于服务端日志关联；`retryable` 为错误是否允许自动重试的权威判定。
- 客户端必须按 `code` 分支处理，禁止匹配 `message` 文本。

### 2.3 健康检查例外

`GET /api/v1/health` 不套用 `data` 信封，直接返回：

```json
{ "status": "ok", "timestamp": "2026-09-19T00:00:00.000Z", "version": "1.0.0" }
```

### 2.4 媒体类型

| 对象 | MIME |
|---|---|
| 网络资源卡片 `.card` | `application/vnd.chips.card+zip` |
| 箱子源文件 `.box` | `application/vnd.chips.box+zip` |
| 控制面请求体 | `application/json`（其余类型返回 400 `VALIDATION_ERROR`） |

### 2.5 协议版本

- API 主版本在路径中（`/api/v1`），传输协议版本由 [16-卡片传输协议](./16-卡片传输协议.md) §1.4 定义。
- v1 内只允许向后兼容变更：新增端点、新增可选请求字段、新增响应字段、新增业务码、放宽校验；删除或改名字段、改变字段语义与状态机必须升主版本。
- 严格请求校验：未登记请求字段一律拒绝；客户端必须忽略响应中未登记的新增字段。
- 不做运行时兼容层与旧字段回退（ADR-010）。
