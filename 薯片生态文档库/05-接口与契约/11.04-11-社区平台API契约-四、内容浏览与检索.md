> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片社区平台服务端（`Chips-CommunityPlatformServer`）对外 HTTP API 的唯一权威契约：基础约定、认证与令牌、内容浏览与检索、管理端接口、卡片与箱子传输控制面、分页/幂等/限流、错误模型与错误码、版本兼容、TLS/CORS/路径安全、示例与自检清单；不覆盖社区网页与后台的产品设计、服务端实现与部署运维，不覆盖个人服务器差异（见 `12-个人服务器API契约`），不覆盖卡片传输的客户端协议细节（见 `16-卡片传输协议`）。

## 四、内容浏览与检索

### 4.1 可见性与返回口径

- 内容可见性只有 `public` 与 `private`（[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) 的 `visibility` 字段；缺省 `public`）。
- 无权访问的私有资源按 `404` 处理（`COMMUNITY_CARD_NOT_FOUND` / `COMMUNITY_BOX_NOT_FOUND` / `COMMUNITY_ROOM_NOT_FOUND`），不得暴露存在性；只有所有者本人（或管理员）可读私有资源。
- 房间公开不代表房间内内容公开：房间内的卡片 / 箱子仍按各自 `visibility` 判定；`cardCount` / `boxCount` 表示当前请求者可见数量。
- 公开列表只返回 `status = ready` 且 `visibility = public` 的内容；本人列表（`/users/me/*`）额外包含私有与未就绪内容。
- 未认证请求可读取公开内容；已认证请求的私有读取按上述规则放行。

### 4.3 用户与个人空间 DTO

```typescript
interface ICommunityUserPublic {
  id: string;
  username: string;
  displayName: string;
  bio: string | null;
  avatarUrl: string | null;
  createdAt: string;
}

interface ICommunityUserMe extends ICommunityUserPublic {
  email: string;
  role: 'user' | 'admin';
  updatedAt: string;
}

interface ICommunitySpace {
  user: ICommunityUserPublic;
  rooms: ICommunityRoom[];         // 当前请求者可见房间
  cards: ICommunityCardSummary[];  // 根目录（roomId 为空）公开就绪卡片，分页
  boxes: ICommunityBoxSummary[];   // 根目录公开就绪箱子，分页
}
```

- `PATCH /api/v1/users/me` 请求体 `{ "displayName"?: string, "bio"?: string | null }`，只允许修改这两个字段；成功返回 `ICommunityUserMe`。
- `PUT /api/v1/users/me/password` 请求体 `{ "currentPassword": string, "newPassword": string }`；成功后除当前会话外的全部 refresh 会话被吊销，返回 `204`。
- `POST /api/v1/users/me/avatar`：`multipart/form-data`，字段名 `file`；服务端校验 MIME 为图片、大小不超过配置上限；成功返回 `ICommunityUserMe`。
- `GET /api/v1/users/me` 返回 `ICommunityUserMe`；公开接口不返回 `email` 与 `role`。

### 4.4 房间 DTO

```typescript
interface ICommunityRoom {
  id: string;
  userId: string;
  name: string;
  slug: string;
  description: string | null;
  coverUrl: string | null;
  visibility: 'public' | 'private';
  cardCount: number;   // 当前请求者可见数量
  boxCount: number;    // 当前请求者可见数量
  createdAt: string;
  updatedAt: string;
}
```

- `POST /api/v1/rooms` 请求体 `{ "name": string, "description"?: string | null, "visibility"?: 'public' | 'private' }`；`slug` 由服务端从 `name` 生成并在用户范围内唯一。
- `GET /api/v1/rooms/:roomId/contents` 返回该房间内当前请求者可见的卡片与箱子摘要，分页；列表项允许同时含 `type: 'card' | 'box'` 区分（房间内容视图模型仅在本接口出现）。
- `POST /api/v1/rooms/:roomId/cover`：`multipart/form-data`，字段名 `file`；成功返回更新后的 `ICommunityRoom`。

### 4.5 卡片 DTO

```typescript
type CommunityVisibility = 'public' | 'private';
type CommunityCardStatus = 'pending' | 'ready' | 'error';
type CommunityViewState = 'pending' | 'rendering' | 'ready' | 'error';

interface ICommunityCardSummary {
  id: string;
  cardFileId: string;        // ← .card/metadata.yaml 的 card_id，10 位 Base62
  userId: string;
  name: string;              // ← metadata.yaml 的 name
  coverUrl: string | null;   // 稳定入口 /api/v1/cards/:cardId/cover；未就绪时为 null
  coverRatio: string;        // ← cover_ratio；缺省 "3:4"
  status: CommunityCardStatus;
  visibility: CommunityVisibility;
  createdAt: string;
  updatedAt: string;
}

interface ICommunityCardDetail extends ICommunityCardSummary {
  roomId: string | null;
  chipStandardsVersion: string;   // ← metadata.yaml 的 chip_standards_version
  tags: Array<string | string[]>; // ← metadata.yaml 的 tags
  fileSizeBytes: number;          // 网络资源卡片对象大小
  sha256: string;                 // 网络资源卡片对象摘要，小写十六进制
  viewUrl: string | null;         // 稳定入口 /api/v1/cards/:cardId/view；viewState=ready 时有值
  renderStatusUrl: string;        // /api/v1/cards/:cardId/render-status
  user: ICommunityUserPublic;     // 作者
}

interface ICommunityCardOpenView {
  id: string;
  cardFileId: string;
  name: string;
  coverUrl: string | null;
  coverRatio: string;
  viewUrl: string | null;
  renderStatusUrl: string;
  viewState: CommunityViewState;
  status: CommunityCardStatus;
  visibility: CommunityVisibility;
  chipStandardsVersion: string;
  user: ICommunityUserPublic;
  createdAt: string;
  updatedAt: string;
}

interface ICommunityCardStatus {
  cardId: string;
  status: CommunityCardStatus;
  viewState: CommunityViewState;
  hasRenderArtifacts: boolean;
  updatedAt: string;
}

interface ICommunityCardRenderStatus {
  cardId: string;
  viewState: CommunityViewState;
  attemptCount: number;
  updatedAt: string;
  viewUrl: string | null;
  error: { code: string; message: string } | null;
}
```

- `status` 语义：`pending` 源对象尚未通过完整性处理，或渲染产物模式下尚未发布客户端产物；`ready` 源文件已保存可用（服务端渲染模式下查看产物可能仍在生成，以 `viewState` 为准）；`error` 处理失败。
- `viewState` 语义：`pending` 源文件已保存、等待生成；`rendering` 正在生成；`ready` 查看入口可用；`error` 生成失败。
- `CommunityCardStatus` 与 `CommunityViewState` 的枚举取值只在本节定义，是本契约与社区平台数据模型的唯一权威；其他文档只引用、不重复定义。卡片状态固定为三值：不存在 `processing` 等流水线中间状态，渲染进行中由 `viewState = rendering` 表达。
- 卡片状态转换与发布形态的产品语义见 [14-社区平台设计](../01-架构设计/01-子系统设计/14-社区平台设计.md) §4.2；本文不重复描述状态机。
- `GET /cards/:cardId` 返回 `ICommunityCardDetail`；`open-view` 返回轻量 `ICommunityCardOpenView`，不返回标签、文件大小与摘要等热路径外字段；`status` 返回 `ICommunityCardStatus`；`render-status` 返回 `ICommunityCardRenderStatus`。
- 卡片打开必须以 `open-view` 的 `viewState` 与 `viewUrl` 为准；`viewUrl` 为稳定入口，服务端对公开内容 `302` 到公开缓存，对私有内容经受控代理读取。

### 4.6 箱子 DTO

```typescript
interface ICommunityBoxSummary {
  id: string;                     // 服务端实体 ID（UUID v4）
  boxFileId: string;              // ← .box/metadata.yaml 的 box_id，10 位 Base62
  userId: string;
  name: string;                   // ← metadata.yaml 的 name
  coverUrl: string | null;        // 箱子封面资源入口；metadata.yaml 无 cover_asset 时为 null
  coverRatio: string;             // ← cover_ratio；缺省 "3:4"
  activeLayoutType: string;       // ← active_layout_type，如 "chips.layout.grid"
  status: CommunityCardStatus;
  visibility: CommunityVisibility;
  createdAt: string;
  updatedAt: string;
}

interface ICommunityBoxEntryRef {
  entryId: string;                       // ← structure.yaml entries[].entry_id
  url: string;                           // ← entries[].url
  title: string | null;                  // ← entries[].snapshot.title
  contentType: 'chips/card' | 'chips/box' | null;
  embedded: boolean;                     // url 为包内相对路径判定为 true
  communityCardId: string | null;        // 命中社区公开就绪卡片时给出
  communityViewUrl: string | null;
  communityRenderStatusUrl: string | null;
}

interface ICommunityBoxDetail extends ICommunityBoxSummary {
  roomId: string | null;
  chipStandardsVersion: string;          // ← metadata.yaml 的 chip_standards_version
  tags: Array<string | string[]>;
  fileSizeBytes: number;
  sha256: string;
  documentUrl: string;                   // /api/v1/boxes/:boxId/view
  entries: ICommunityBoxEntryRef[];      // 按 structure.yaml 声明顺序
  user: ICommunityUserPublic;
}
```

- `GET /boxes/:boxId` 返回 `ICommunityBoxDetail`；条目匹配仅针对社区中公开且就绪的卡片，匹配依据是条目 `snapshot.document_id` 与卡片 `cardFileId`。
- 条目 `contentType = 'chips/box'` 时，浏览态显示被引用箱子的封面，不展开其布局。
- `GET /boxes/:boxId/view` 返回 `text/html; charset=utf-8` 只读箱子文档：名称、描述、条目列表；社区卡片条目输出 `/cards/:communityCardId` 链接，内嵌条目展示包内路径，外部条目展示 `url`；全部用户内容经过 HTML 转义；访问权限与 `GET /boxes/:boxId` 一致。

### 4.7 发现与检索

| 接口 | 查询参数 | 返回 |
|---|---|---|
| `GET /api/v1/discover/cards` | `page`、`pageSize` | 公开就绪卡片摘要，按 `createdAt` 倒序 |
| `GET /api/v1/discover/boxes` | `page`、`pageSize` | 公开就绪箱子摘要，按 `createdAt` 倒序 |
| `GET /api/v1/search?q=` | `q` 必填、`type`（`card` / `box` / `user`，缺省 `card`）、`page`、`pageSize` | 匹配结果摘要 |

- 检索按名称、标签与用户名匹配；`q` 去首尾空白后长度不足 1 返回 `COMMUNITY_VALIDATION_ERROR`。
- 结果只含公开可见内容；不返回私有或未就绪内容的存在性。

### 4.8 内容管理写操作

| 接口 | 请求体 | 语义 |
|---|---|---|
| `PATCH /api/v1/cards/:cardId` | `{ "visibility": 'public' \| 'private' }` | 修改可见性；`public → private` 时必须移除公开桶中的查看/封面缓存并让缓存记录失效 |
| `PATCH /api/v1/boxes/:boxId` | `{ "visibility": 'public' \| 'private' }` | 同上 |
| `DELETE /api/v1/cards/:cardId` | 无 | 删除卡片实体并级联清理卡片作品全部对象；语义见 4.9 |
| `DELETE /api/v1/boxes/:boxId` | 无 | 删除箱子实体并级联清理箱子作品全部对象；语义见 4.9 |
| `DELETE /api/v1/rooms/:roomId` | 无 | 删除房间；房间内内容保留并回到根目录 |

- 删除首次返回 `204`；重复删除返回 `404`（副作用只发生一次）。
- 修改可见性为 `private` 后，未经认证的读取立即返回 `404`；公开直链必须同时失效。

### 4.9 删除清理语义

作品（卡片 / 箱子）删除采用「记录先失效、对象后清理、失败重试」两阶段模型；房间删除不触发内容清理（内容回到根目录）。

1. **受理与不可见**：服务端在同一事务中把作品置为删除中并解除公开可见；列表、详情、查看/封面入口、下载计划与渲染状态接口从该时刻起按 `404` 处理，随后返回 `204`。删除中是服务端内部状态，不出现在任何 DTO 中；作品进入删除中后不可恢复。
2. **资源清单校验**：清理必须以作品落库的资源清单为唯一枚举依据：卡片为 `networkCard` 对象、`resources[]` 每项的 `bucket` / `objectKey`、渲染产物的查看与封面前缀；箱子为 `boxFile` 对象与箱子封面对象；另包含 `restoreManifest` 引用的附属对象。对象键必须落在该作品的 `cards/{cardId}/…` 或 `boxes/{boxId}/…` 前缀内，前缀不符的对象拒绝删除并记录诊断。清单字段缺失或不完整时，按作品前缀枚举对象兜底并在诊断中标记，不得依靠 URL 文本猜测桶与键，不得全桶扫描。
3. **级联清理**：逐项删除网络资源卡片对象、全部资源对象、查看产物对象、封面产物对象、箱子源文件与箱子封面；删除渲染产物记录与缓存记录；中止该作品尚未完成的传输会话并清理其暂存对象；最后删除作品记录。每项删除必须幂等，对象不存在视为成功。
4. **失败与重试**：对象删除失败不阻塞 `204` 受理；服务端把作品保留在删除中并交由清理重试队列处理，按指数退避重试（首档不超过 1 分钟，上限不超过 1 小时），全部对象清理成功后才删除作品记录。超过部署配置的最大尝试次数进入死信并告警，管理端可重放；重试期间作品始终不可见、不可被重建、不可经任何入口读取。
5. **客户端约束**：收到 `204` 后，客户端必须清除本地该作品的缓存与预签名并视其为已删除；不得依赖服务器保留已删除内容；重复删除按幂等语义得到 `404`，不得据此恢复本地状态。
