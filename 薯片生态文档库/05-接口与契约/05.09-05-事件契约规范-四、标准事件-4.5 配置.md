### 4.5 配置

#### config:changed

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `key` | string | 是 | 完整配置键 |
| `layer` | ConfigLayer | 是 | 本次变化影响的层：`platform` / `user` / `workspace` / `plugin` |
| `value` | unknown | 是 | 该层当前值；`null` 表示该层覆盖被移除 |
| `effectiveValue` | unknown | 是 | 变化后的生效值 |
| `isDefault` | boolean | 是 | 生效值是否来自 schema 声明默认值 |
| `origin` | ConfigOrigin | 是 | 变更来源：`platform` / `migration` / `external` / `plugin:<pluginId>` |

触发时机：配置写入或删除提交成功后逐键发布；迁移完成、外部修改被采纳、工作区切换后按生效值变化逐键发布。同值写入不落盘、不发事件；写入被更高层遮蔽时事件仍按发生变化的层发布，订阅方以 `effectiveValue` 判断是否需要响应（见《[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md)》第六节）。
可见性：`platform` 命名空间的事件对持有 `config:read:platform` 的插件可见；`plugins.<pluginId>` 命名空间的事件只对该插件与平台可见。

**订阅示例（主进程）**

```typescript
import type { Context, IEventSubscription } from '@chips/sdk';

type ConfigLayer = 'platform' | 'user' | 'workspace' | 'plugin';

type ConfigOrigin = 'platform' | 'migration' | 'external' | `plugin:${string}`;

interface IConfigChangedPayload {
  key: string;
  layer: ConfigLayer;
  value: unknown;
  effectiveValue: unknown;
  isDefault: boolean;
  origin: ConfigOrigin;
}

export function apply(ctx: Context): void {
  const subscription: IEventSubscription = ctx.on<IConfigChangedPayload>(
    'config:changed',
    (payload) => {
      if (payload.key.startsWith('platform.editor.') && !payload.isDefault) {
        console.info(`配置生效：${payload.key}（${payload.origin}）`);
      }
    },
  );

  void subscription;
}
```
