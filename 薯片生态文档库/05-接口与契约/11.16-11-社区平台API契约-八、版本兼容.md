# 社区平台 API 契约

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片社区平台服务端（`Chips-CommunityPlatformServer`）对外 HTTP API 的唯一权威契约：基础约定、认证与令牌、内容浏览与检索、管理端接口、卡片与箱子传输控制面、分页/幂等/限流、错误模型与错误码、版本兼容、TLS/CORS/路径安全、示例与自检清单；不覆盖社区网页与后台的产品设计、服务端实现与部署运维，不覆盖个人服务器差异（见 `12-个人服务器API契约`），不覆盖卡片传输的客户端协议细节（见 `16-卡片传输协议`）。

## 八、版本兼容

1. **API 主版本在路径中**：`/api/v1` 与 `/admin/api/v1`。v1 内只允许向后兼容变更：新增端点、新增可选请求字段、新增响应字段、新增业务码、放宽校验；删除字段、重命名字段、改变字段语义、改变状态机、改变默认值必须升主版本（`/api/v2`）。
2. **不做运行时兼容层**：不为旧客户端保留旧路径、旧字段或旧语义；升级窗口内客户端与服务端同步发布（ADR-010）。
3. **响应向前兼容**：客户端必须忽略响应中未登记的新增字段；新增字段必须有默认语义，缺省时不得改变既有行为。
4. **严格请求校验**：请求体的未登记字段一律返回 `COMMUNITY_VALIDATION_ERROR`，不静默忽略。
5. **内容版本门禁**：服务端对上传内容执行 `chip_standards_version` 判定；不支持的主版本返回 `COMMUNITY_CARD_VERSION_UNSUPPORTED` / `COMMUNITY_BOX_VERSION_UNSUPPORTED`，服务端不改写、不迁移用户内容；迁移由客户端迁移工具完成（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §6）。
6. **渲染产物版本**：`rendererVersion` 只作记录与排查，不参与协商；服务端发布后不再重新渲染。卡片更新产生新 `versionId`；下载会话不承诺历史版本可下载，缺省只提供当前版本。
7. **版本可观测**：`GET /api/v1/health` 返回 `version`（服务端实现版本）与 `apiVersion`；客户端可在诊断信息中上报两者。
8. **降级原则**：服务端不支持用户主动降级；服务端与客户端均不得在同一主版本下发布两种语义（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §五）。
