## 四、调用生命周期与会话上下文

### 4.1 可用位置

| 位置 | 可用入口 | 说明 |
|---|---|---|
| 渲染进程（插件 UI、卡片视图、箱子视图、应用窗口） | `window.chips` | 本文全部方法 |
| 主进程（服务插件、应用插件的主进程逻辑） | Cordis `ctx` + `ctx.bridge` | 服务经 `ctx.provide` / `ctx.inject`，出站能力与资源访问经 `ctx.bridge`（`IAppBridge` / `IServiceBridge`，第 2.6 节）；不存在 `window.chips` |
| 插件模块顶层（渲染侧） | `window.chips` | preload 先于页面脚本执行，窗口创建后即可调用；是否成功取决于会话状态 |

### 4.2 会话时间线

```text
插件启用（starting）
  ├─ 权限系统生成会话快照（grantedPermissions）
  └─ 创建窗口 / 表面（webContents + frame）
       └─ preload 注入 window.chips
            └─ 会话 active：request / subscribe / resource 正常受理
                 │
                 ├─ 授权变更：主进程经内部通道 session:permissions 推送新快照
                 │                 （preload 刷新预检缓存；后续调用按新快照判定）
                 │
                 └─ 会话关闭（窗口销毁 / 插件停用 / 应用退出）
                      ├─ 新调用：BRIDGE_SESSION_UNKNOWN
                      ├─ 在途调用：取消（调用方仍在线时收到 BRIDGE_CANCELLED）
                      ├─ 订阅：强制清理，不再投递
                      └─ 句柄：强制释放
```

- 会话身份（插件 ID、窗口、框架、权限快照、已打开文档）由 Bridge 层按 IPC 来源解析；插件在参数中自报的身份字段不参与授权。
- 会话权限快照推送通道 `session:permissions`：授权/撤销后由主进程单向推送新快照到 preload，用于同步渲染侧预检缓存；该通道是平台内部通道，不属于标准事件，插件不可订阅、不可伪造、不可依赖其作为授权依据；权威判定始终在主进程（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 5.3、7.6 节）。
- 会话的创建、快照字段与关闭时机见[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 7.4 节；插件启用、停用与更新时序见[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md)。

### 4.3 调用约束

- 默认超时 30 秒；超时后迟到结果按 `requestId` 丢弃，但非幂等能力可能已产生副作用。能力实现经 `ctx.signal` / `ctx.deadline` 感知收口（第 2.6、3.2 节）。
- 无客户端取消入口；会话关闭、超时、能力注销与 Bridge 关闭是仅有的取消来源；能力实现必须按 `ctx.signal` 释放已占用资源。
- 每会话在途调用上限默认 64，超出返回 `BRIDGE_SESSION_BUSY`；串行能力的等待队列上限默认 32，超出返回 `BRIDGE_QUEUE_OVERFLOW`。
- Bridge 不自动重试、不做幂等去重；`retryable: true` 的能力必须由插件确认幂等后再重试。

### 4.4 清理责任

| 资源 | 释放者 | 时机 |
|---|---|---|
| 事件订阅 | 视图 / 插件代码 | 视图卸载、组件卸载、插件停用时 `dispose()` |
| 资源句柄 | 视图 / 插件代码 | 使用完毕立即 `release()`，不得跨视图长期持有 |
| 在途调用 | Bridge 层 | 会话关闭时统一取消 |
| 会话残留 | Bridge 层 | 会话关闭时一次性清理订阅、句柄与转发标记 |

视图卸载时未释放的订阅与句柄，平台会在窗口销毁时强制回收；插件不得把强制回收当作正常清理路径。
