# 卡片传输协议

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：`.card` / `.box` 在本地设备与内容服务器之间传输的权威协议：传输会话（创建、预签名、分片、断点续传、取消、恢复）、完整离线卡片与网络资源卡片的可逆改写与还原（含可逆恢复清单）、摘要与完整性校验、预签名与对象存储桶角色、传输队列与 `transfer:*` 事件映射、错误码与安全约束；不覆盖卡片/箱子的包结构语义、渲染链路与服务器产品设计。

---

## 二、协议模型

### 2.1 角色与信任边界

| 角色 | 位置 | 职责 | 信任级别 |
|---|---|---|---|
| 传输引擎 | 用户设备 Host | 会话驱动、改写与还原、分片与断点、摘要校验、队列任务执行 | 平台受信 |
| 调用方 | 应用插件 | 选择源文件与目标位置、请求上传/下载/远程打开/箱子上传、消费任务状态 | 业务代码，不直接接触对象键与字节通道 |
| 控制面服务器 | 内容服务器 | 鉴权、会话、预签名、清单与元数据持久化、状态与发布、校验对象归属 | 受信 |
| 对象存储 | S3 兼容服务 | 保存资源、网络资源卡片、箱子源文件与渲染产物；公开桶与私有桶 | 受信存储 |
| 内容消费方 | 查看器、编辑器、网页 | 打开网络资源卡片按 URL 在线加载资源；打开完整离线卡片按相对路径读取 | 只读消费 |

- 调用方不持有服务器凭证材料、不构造对象键、不签发预签名地址、不读取对象存储直连地址之外的私有访问路径。
- 服务器不信任客户端提交的路径、大小与摘要：全部在会话内以对象存储 Head 结果与服务端记录交叉校验（第五节）。

### 2.2 控制面与数据面

```text
             控制面（HTTPS JSON，元数据与控制）
调用方 ──▶ 传输引擎 ─────────────────────────────▶ 内容服务器
              │                                      │
              │ 数据面（预签名直传）                  │ 对象归属校验（Head）
              ▼                                      ▼
          对象存储（S3 兼容） ◀──────────────────────┘
```

- 控制面请求一律 `Content-Type: application/json`；对控制面发送文档或资源字节（如 `multipart/form-data`）必须被拒绝（`VALIDATION_ERROR`），服务器不接收 `.card` / `.box` 字节。
- 控制面成功响应为 `{ "data": ... }`，失败响应为 `{ "error": { "code", "message", "details"? } }`；`message` 只用于展示，调用方按 `code` 分支。
- 数据面字节不经服务器：上传直传对象存储，下载从对象存储或受控代理路由读取。
- 控制面与数据面都必须在 TLS 上运行；证书校验不得关闭。

### 2.3 传输方向与形态转换

| 操作 | 输入 | 输出 | 数据面范围 |
|---|---|---|---|
| 卡片上传 | 完整离线卡片文件 | 网络资源卡片 + 资源对象 + 恢复清单（服务器持久化） | 上传全部资源与网络资源卡片 |
| 卡片完整下载 | 卡片 ID（可选版本 ID） | 完整离线卡片（恢复到调用方指定位置） | 下载网络资源卡片与全部资源 |
| 远程打开 | 卡片 ID | 本地临时网络资源卡片 + 查看器会话 | 只下载网络资源卡片 |
| 箱子上传 | `.box` 文件 | 箱子源文件 + 散落卡片资源 + 可选封面/渲染产物 | 上传散落卡片、箱子本体与可选产物 |
| 渲染产物上传 | 与卡片或箱子上传同一会话 | 查看产物与封面产物对象 | 上传 `render-file` / `cover-file` |

```text
完整离线卡片 --上传--> 网络资源卡片 + 对象存储资源 + 恢复清单
网络资源卡片 + 对象存储资源 + 恢复清单 --下载--> 完整离线卡片
```

- 上传与下载的可逆转换语义以[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §2.3、§2.4 为格式级依据；本文定义线上协议与恢复清单 schema。
- 网络资源卡片是正常 `.card` 文件，不是临时产物；所有基础卡片插件必须正式支持 URL 资源。

### 2.4 服务器能力声明

- 创建上传会话的响应必须包含 `capabilities` 对象，声明该服务器对可选协议面的支持：

| 能力项 | 类型 | 语义 |
|---|---|---|
| `renderArtifacts` | boolean | 是否接受客户端渲染产物上传（`render-file` / `cover-file` 角色） |
| `multipart` | boolean | 是否支持大对象分片上传（`multipart` 模式与分片续签） |
| `rooms` | boolean | 是否支持 `roomId` 归属（社区形态为 true，单用户形态为 false） |

- 客户端只能使用服务器声明为 true 的能力；请求与声明不符时服务器必须拒绝，不得静默忽略：
  - `includeRenderArtifacts: true` 且 `capabilities.renderArtifacts = false` → `CARD_TRANSFER_RENDER_UNSUPPORTED`；
  - 非空 `roomId` 且 `capabilities.rooms = false` → `VALIDATION_ERROR`；
  - 对象大小超过单次预签名适用上限且 `capabilities.multipart = false` → `VALIDATION_ERROR`，服务器在 `details` 给出单对象上限。
- 服务器自行渲染（`renderArtifacts = false`）时，完成响应的 `status` 与渲染推进状态由服务器负责；`renderStatusUrl` 仅在服务器提供查看状态查询时返回。
