## 一、定位与范围

### 1.1 定位

Bridge 是插件访问薯片平台能力的唯一运行时入口。渲染进程（插件 UI）通过 preload 注入的 `window.chips` 使用 Bridge；`window.chips` 的方法面与 `IChipsBridge` 完全相同，仅包含 `request` / `subscribe` / `resource` 三个方法。

本文是 `window.chips` 与 `IChipsBridge` 的**方法级权威参考**；Bridge 的三层结构、能力注册表、权限判定算法、Schema 校验流程、IPC 消息格式与超时/并发策略以[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md)为准。

### 1.3 约定

- 术语按生态统一口径：**能力**是 Bridge 的原子功能单元；**权限**是资源访问许可标识；**Host** 仅作角色词，指能力提供方；**会话**是插件一次运行实例与一个渲染宿主的绑定，是身份与限权单位。
- 本文所有错误码均为 `ChipsError.code`；调用方必须按 `code` 分支处理，禁止匹配 `message` 文本。
- 示例使用的能力 ID 与权限 ID 均为已登记标识；能力清单、能力与权限的映射总表以[04-能力契约规范](./04-能力契约规范.md)为准，不得自创未登记能力。
