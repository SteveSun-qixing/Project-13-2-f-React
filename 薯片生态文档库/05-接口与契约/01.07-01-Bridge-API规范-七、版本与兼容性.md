## 七、版本与兼容性

### 7.1 形状冻结

- `IChipsBridge` 自 v1.0.0 起只有 `request` / `subscribe` / `resource` 三个方法，**不含 `context()`**；`window.chips` 与之一致。
- 方法名、参数顺序、泛型位置与错误语义都属于冻结面；实现不得添加未登记的方法、属性或别名。

### 7.2 无兼容层

- 生态采用大爆炸重构：旧版冻结、新库从零建立，**不提供兼容层、废弃别名或迁移转发**（[ADR-010](../01-架构设计/ADR/ADR-010-大爆炸重构策略.md)）。
- 接口升级直接替换为新形状，不保留双轨；旧调用在编译期即失败。

### 7.3 变更流程

- 方法面变更：RFC → 评审 → ADR → 实施 → 质量门禁 → 文档同步（文档与实现同 PR）。
- 新增能力必须先登记进[04-能力契约规范](./04-能力契约规范.md)的能力清单；新增标准事件必须先登记进[05-事件契约规范](./05-事件契约规范.md)；本文不得先行引入未登记 ID。
- 本文与[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md)、[04-能力契约规范](./04-能力契约规范.md)、[06-资源协议规范](./06-资源协议规范.md)必须同 PR 更新，接口改动不得只改一处。

### 7.4 跨端与阶段

- 五端共享同一 Bridge 接口形状：平台优先级为 macOS / Windows → Linux（桌面三端完成）→ Android → iOS（R6、R7，与[07-工程管理/02-开发流程与阶段计划](../07-工程管理/02-开发流程与阶段计划.md)一致）。
- 平台没有能力枚举与版本协商 API；能力不可用只能通过调用结果的 `BRIDGE_CAPABILITY_NOT_FOUND` 判定，插件不得依赖平台内部版本号做分支。
- `@chips/sdk` 的类型与平台实现同 PR 更新，插件只依赖本文与 SDK 导出，不依赖平台实现细节。
