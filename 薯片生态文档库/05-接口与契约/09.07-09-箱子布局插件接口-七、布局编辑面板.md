## 七、布局编辑面板

### 7.1 `ILayoutEditor`

`ILayoutEditor` 是布局编辑器句柄；基础卡片编辑器句柄 `IBaseCardEditor` 是另一套独立类型（变更载荷 `BaseCardChange`、事件映射 `IBaseCardEditorEventMap`、`update` 参数为 `BaseCardView`），两者只共享成员语义、不共享类型名。基础卡片侧定义见 [08-基础卡片插件接口](08-基础卡片插件接口.md) 第四节。

```typescript
type EditorState = 'active' | 'disposed';

interface ILayoutPatchOperation {
  op: 'add' | 'remove' | 'replace';
  path: string;                       // RFC 6901 指针，相对 layout_config 根，不允许根指针
  value?: unknown;                    // op 为 add / replace 时必填
}

type LayoutChange =
  | { kind: 'replace'; config: Record<string, unknown>; schemaVersion: string }
  | { kind: 'patch'; operations: readonly ILayoutPatchOperation[] };

interface ILayoutEditorEventMap {
  change: { change: LayoutChange };
  dirty: { isDirty: boolean };
}

interface ILayoutEditor {
  readonly state: EditorState;
  isDirty(): boolean;
  getChange(): LayoutChange | null;
  markCommitted(revision: number): void;
  update(box: BoxRenderView, revision: number): void;
  subscribe<TEvent extends keyof ILayoutEditorEventMap>(
    event: TEvent,
    handler: (payload: ILayoutEditorEventMap[TEvent]) => void,
  ): ISubscription;
  focus(): void;
  dispose(): void;
}
```

| 成员 | 契约 |
|---|---|
| `state` | `active` 可编辑；`disposed` 已释放，除 `state` / `dispose()` 外一切行为为空操作 |
| `isDirty()` | 是否存在尚未回流的变更；等价于 `getChange() !== null` |
| `getChange()` | 返回相对基线的累计变更；无变更返回 `null` |
| `markCommitted(revision)` | 编辑链路成功回流后调用；以该 revision 更新基线并清除已提交变更 |
| `update(box, revision)` | 会话视图因外部变化前进时调用，以新 `BoxRenderView` 替换基线；调用前编辑器必须无待提交变更 |
| `subscribe(event, handler)` | 订阅 `change` / `dirty`；返回 `ISubscription`，`dispose()` 幂等 |
| `focus()` | 请求编辑器获取焦点；由编辑链路在窗口激活、用户进入编辑时调用 |
| `dispose()` | 释放编辑器与其全部订阅；幂等；待提交变更直接丢弃 |

### 7.2 变更回流协议

```
插件编辑器                  编辑链路（IEditSession）        文档服务          渲染会话
    │ getChange()               │                             │                 │
    │──────────────────────────▶│ 校验 configSchema           │                 │
    │                           │ + validateConfig            │                 │
    │                           │ document:write ────────────▶│                 │
    │                           │◀──────────── { revision } ──│                 │
    │                           │ 组装新 DocumentView                            │
    │                           │ session.update(view, revision) ───────────────▶│
    │ markCommitted(revision)   │                             │                 │
    │◀──────────────────────────│                             │                 │
    │（基线前进、清除已提交变更）  │                                                │
```

规则：

1. `change` 与 `dirty` 事件同时可用：编辑链路可订阅事件驱动回流，也可用 `getChange()` 拉取（订阅后立即拉取可避免竞态）。
2. `{ kind: 'replace' }` 提交完整布局配置：配置必须已经过插件归一化；`schemaVersion` 为编辑器写入的配置 schema 版本（编辑器实现对应的当前版本，必须落在插件 `schemaVersions` 范围内且与 `config` 结构一致），平台以它写入或更新 `content.yaml` 的 `layout_configs.<active_layout_type>.schema_version`，配置项原不存在时即以该版本建立；`revision` 只由平台维护（取自 `document:write` 的输出），编辑器不得依赖自己传入的值。
3. `{ kind: 'patch' }` 只描述 `layout_config` 的增量：`path` 使用 RFC 6901 指针，相对 `layout_config` 根；`op` 为 `add` / `replace` 时 `value` 必填；`patch` 不改变 `schema_version`，持久化时保持原值。
4. 编辑器应把同一任务或同一动画帧内的多次编辑合并为一次变更发布，避免逐键触发回流。
5. 回流成功后编辑链路调用 `markCommitted(revision)`；若编辑器在此期间产生了新变更，`isDirty()` 保持为真并等待下一轮回流。
6. 会话视图因外部变化收敛时，编辑链路先完成或放弃待提交变更，再调用 `update(box, revision)`；`revision` 不大于编辑器已知值时编辑器忽略该调用。
7. 编辑器不负责保存：`document:write` 先行推进内存模型并返回 `{ revision }`，写回持久化由[文档服务](../01-架构设计/01-子系统设计/11-文档服务设计.md)链路完成（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §8.3）。
8. `dispose()` 不发布任何事件、不持久化数据；需要保留待提交变更时由编辑链路在释放前先行回流。
9. 释放后调用 `getChange()` 返回 `null`、`isDirty()` 返回 `false`、`update()` 与 `focus()` 为空操作、`subscribe()` 返回已失效订阅。
10. 回流与保存前，编辑链路按第 5.3 节执行 `configSchema` 结构校验与 `validateConfig` 语义校验；`schemaVersion` 超出插件 `schemaVersions` 或与 `config` 结构不符时拒绝回流并给出简体中文提示。
11. 回流唯一时序与基础卡片侧一致：`getChange()` → 校验 → `document:write`（输出 `{ revision }`）→ 渲染会话 `update(view, revision)` → `markCommitted(revision)`。

### 7.3 界面与边界约束

- 编辑器根节点铺满容器：`width: 100%`、`height: 100%`、`min-height: 0`，滚动由编辑器内部管理。
- 组件只从 `@chips/ui` 导入，样式走 Design Tokens 与 antd token；禁止硬编码样式、禁止第二套组件库（R4）。
- 文案简体中文直写；禁止引入多语言运行时（R5）。
- 编辑面板只编辑配置；不得复制一份内容数据独立维护，不得实现第二套预览渲染（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 8.4）。
- 编辑器必须在 `dispose()` 中释放全部订阅、定时器、Observer、资源句柄与媒体资源，并停止触碰容器。
- 不使用 `any`；异步操作必须处理取消与卸载后的状态写入。
