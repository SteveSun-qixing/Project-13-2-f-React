## 五、解析流程与协议处理器

### 5.1 解析流水线

```text
URI 字符串（规范 URI 或裸 http(s) 输入）
  → 归一化（2.6 节）
  → 语法解析：scheme → scope → path → query        失败：RESOURCE_INVALID_URI / RESOURCE_UNSUPPORTED_SCHEME
  → 作用域查找（ScopeRegistry；External 惰性注册）   失败：RESOURCE_NOT_FOUND
  → 路径校验（PathGuard：解码一次 + NFC + 分段）     失败：RESOURCE_PATH_INVALID
  → 会话解析与作用域归属校验                         失败：RESOURCE_PERMISSION_DENIED
  → 权限判定（跨会话读取、全部写入）                 失败：RESOURCE_PERMISSION_DENIED
  → Provider 选择与地址构建
  → ResourceAddress
```

- 流水线由 Bridge 层与资源管理器执行；渲染层 preload 可基于会话权限快照做快速失败预检，但预检不是安全边界（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 5.3 节）。
- 每一级的失败必须携带对应错误码与 `details`（第七节），不得回退到文件系统直读或直连网络。
- 解析结果对相同输入保持确定性；External origin 的注册状态不改变语法结果。

### 5.2 两条访问路径

```text
句柄路径（生命周期控制与失效感知）
  window.chips.resource(uri)
    → preload 同步预检（URI 合法性 + 会话权限快照）
    → 懒打开代理句柄（非法或明显越权立即抛出 ChipsError，不返回句柄）
    → 首次 metadata / read / readRange / stream 触发 bridge:resource 的 open
    → 主进程：解析 + 作用域与会话校验 + 权限判定（纵深防御）→ 句柄 ID
    → 字节：chips-resource:// 协议处理器按 Range 提供（不经 IPC）
    → release() / 会话关闭 → 归还租约

协议路径（交给渲染引擎加载）
  <img src="chips-resource://card-7f3a/images/photo.jpg">
    → Chromium 网络层
    → 主进程 chips-resource:// 协议处理器
    → 来源帧 → 会话解析 → 作用域归属 + 路径校验 + 权限判定
    → 资源管理器（缓存 / 范围读 / 流式）
    → HTTP 响应数据流（200 / 206）
```

两条路径共享同一解析、作用域与权限规则；句柄路径额外提供失效通知与显式生命周期，协议路径由浏览器按需请求。

### 5.3 协议处理器契约

主进程注册 `chips-resource` 协议处理器（Electron `protocol.handle`），把浏览器请求转交资源管理器（实现见 [04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 7.4 节）：

| 项 | 契约 |
|---|---|
| 来源解析 | 按请求来源帧（`webContents` + frame）解析资源会话；无法解析或会话已关闭时拒绝（403）并写审计。 |
| 方法 | 支持 `GET`、`HEAD`；`OPTIONS` 返回 204 与 CORS 头；其余方法返回 405。 |
| 范围请求 | 解析 `Range: bytes=start-end`，命中范围读返回 206 + `Content-Range` + `Accept-Ranges: bytes`；非法范围返回 416；来源不支持范围请求时按 200 全量输出（External 传递 Range，[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 8.2 节）。 |
| 响应类型 | `Content-Type` 按 MIME 判定规则（扩展名 + External 响应头，[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 3.4 节）；脚本、样式、字体、媒体响应必须与允许类型集匹配，并附带 `X-Content-Type-Options: nosniff`。 |
| CORS | 模块脚本、字体、媒体响应附加 `Access-Control-Allow-Origin: *`（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 4.4 节）。 |
| 缓存 | 响应默认 `Cache-Control: no-store`，或按作用域使用严格缓存策略；平台不依赖 Chromium 缓存，缓存统一由 CacheStore 承担（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 6 节）。 |
| 错误映射 | 错误码到 HTTP 状态的映射见第七节；错误响应体为简体中文纯文本，不含真实路径、堆栈与内部标识。 |
| 安全 | 必须基于 `request.url` 原始字符串重新执行语法解析与 PathGuard，不得信任 URL 解析器的路径折叠结果；越权返回 403 并写审计。 |

约束：

- 资源字节不经 IPC：句柄路径只传元数据与控制消息，字节统一由协议处理器按 Range 提供（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 7.1 节）。
- 帧内禁止用 `file://` 加载包内资源，禁止直连外部网络（`connect-src 'none'`）；资源加载失败不得回退为直接文件系统访问。
- CSP 必须允许 `chips-resource:` 并按资源类型收敛指令（`img-src` / `media-src` / `font-src` / `frame-src` 等），不得放宽 ADR-002 安全基线（R17）。
