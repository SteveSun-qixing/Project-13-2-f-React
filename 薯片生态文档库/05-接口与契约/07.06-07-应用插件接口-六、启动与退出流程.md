## 六、启动与退出流程

### 6.1 启动流程

```
启动意图（启动器 / 文件关联 / 命令）
        │
        ▼
[1] 插件状态检查 ── 非 active ──► 请求启用（依赖解析 → 创建 Fork → 注册启动器与文件关联）
        │                              └─ 启用失败 → 返回结构化错误，不创建实例
        ▼
[2] 实例检查 ── 已有实例 ──► 按 §6.2 投递给运行中实例（结束）
        │ 无实例
        ▼
[3] 构造 IAppLaunchArgs（§4.3）
        ▼
[4] 创建表面：window / desktop 创建主窗口并加载应用 UI；tray 注册托盘入口
        ▼
[5] 调用 launch(ctx) ── 抛出或拒绝 ──► 关闭窗口、回收实例副作用，返回 APP_LAUNCH_FAILED
        ▼
[6] 实例进入 active；发布 app:launched { appId }
```

规则：

- 步骤 1 的启用失败错误来自内核（如 `KERNEL_DEPENDENCY_MISSING`、`KERNEL_APPLY_FAILED`），不产生应用实例。
- 步骤 4 完成时发布 `window:created { windowId, appId }`；`ctx.window.id` 与该 `windowId` 同值。
- 步骤 5 在表面创建后调用；应用负责窗口内容与后续窗口管理，不负责创建主窗口本身。
- 单实例：同一插件代际在同一时刻至多一个应用实例；重复启动不创建第二个实例。
- 启动期间实例处于 `launching`（§6.4）。

### 6.2 运行中投递与重复启动

| 触发 | 无实例 | `launching` | `active` | `exiting` / 已退出 |
|---|---|---|---|---|
| 启动器 | 创建实例，`launch`（`source: launcher`） | 本次启动完成后聚焦主窗口 | 聚焦主窗口 | 丢弃并记录诊断 |
| 文件打开 | 创建实例，`launch`（`source: file-association`，`files`） | 排队；`launch` 成功后逐个 `openFile` | 逐个 `openFile` | 丢弃并记录诊断 |
| 命令 | 创建实例，`launch`（`source: command`，`command` / `commandArgs`） | 排队；`launch` 成功后调用 `handleCommand` | 调用 `handleCommand` | 丢弃并记录诊断 |

规则：

- 启动意图只投递一次：初始文件与命令随 `launch` 的 `ctx.args` 送达；运行中到达的才走 `openFile` / `handleCommand`。
- 排队意图在 `launch` 失败时全部丢弃并记录诊断；平台不自动重试。
- 平台按意图到达顺序依次投递；同一意图内的多文件按顺序串行调用（§3.4）。
- 命令与文件的到达顺序不保证与外部事件时间一致；应用不得依赖跨类型全局顺序。

### 6.3 退出流程

```
[1] 实例标记 exiting：拒绝新的 handleCommand / openFile
        ▼
[2] 触发 beforeExit(reason)（异常与超时被捕获，退出继续）
        ▼
[3] 关闭实例全部窗口、注销托盘入口；发布 window:closed { windowId }
        ▼
[4] 回收实例副作用（渲染会话、订阅、生命周期钩子）
        ▼
[5] 发布 app:exited { appId, exitCode? }
```

规则：

- 退出必定完成、不可取消（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §4.4）；`beforeExit` 只做保存与刷新。
- 平台停用插件时先执行实例退出，再 `dispose()` 插件 Fork；更新插件时已打开窗口保持旧版本直到关闭（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §6.3）。
- 退出后插件仍为 `active`；再次启动创建新实例并重新调用 `launch`。
- 退出流程不删除用户文件与插件配置；卸载时的删除规则见 [03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §4.5。

### 6.4 实例状态与调用约束

| 状态 | 含义 | `launch` | `handleCommand` / `openFile` | `exit()` |
|---|---|---|---|---|
| `launching` | `launch` 执行中 | 恰好一次 | 排队，`active` 后投递 | 允许；退出在 `launch` settle 后执行 |
| `active` | 可用 | 不再调用 | 正常投递 | 允许 |
| `exiting` | 退出流程执行中 | 不再调用 | 拒绝，返回 `APP_STATE_INVALID` | 幂等成功 |

- 状态由平台维护，不在插件包内持久化；插件不得假设跨实例复用任何状态。
- 对不存在或已退出实例的投递返回 `APP_STATE_INVALID`；平台入口（启动器 / 文件关联）无法回传调用方时写入诊断与审计。
