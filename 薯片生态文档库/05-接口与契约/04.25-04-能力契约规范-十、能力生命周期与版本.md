## 十、能力生命周期与版本

### 10.1 状态机

```text
 未注册 ──提供方激活/注册成功──▶ active ──代际切换──▶ draining ──在途收口──▶ 已注销
   ▲                              │                                              │
   └──────────────────────────────┴──────── stop / 崩溃 / Fork dispose ──────────┘
```

| 状态 | 含义 | 进入条件 | 调用行为 |
|---|---|---|---|
| 未注册 | 提供方未激活或能力已注销 | 初始 / 注销完成 | 新调用 `BRIDGE_CAPABILITY_NOT_FOUND` |
| `active` | 能力可调用 | 注册校验通过 | 正常调用 |
| `draining` | 蓝绿更新的旧代际 | 新代际接管注册 | 拒绝新调用；在途调用完成或按超时收口 |
| 已注销 | 注册项摘除 | `stop` / 崩溃 / Fork dispose 完成 | 新调用 `BRIDGE_CAPABILITY_NOT_FOUND` |

不变量：

1. 注册项的生命周期与提供方 Fork 一致；不存在"已注册但提供方不可用"的窗口（`draining` 除外）。
2. 注销按 Fork 逆序撤销，先拒绝新调用，再收口在途调用（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 第 4.4 节）。
3. 平台退出时全部注册项随 Bridge 关闭一并注销，不持久化、不跨启动保留。
4. `draining` 是蓝绿更新的唯一过渡态，切换完成后同一 ID 只有一个生效代际（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 第 6.2 节）。

### 10.2 版本规则

| 对象 | 版本来源 | 规则 |
|---|---|---|
| 内置能力 | 平台版本 | 契约随平台版本演进；破坏性变更随平台主版本发布（第 5.5 节） |
| 第三方能力 | 提供方插件版本 | 契约版本 = 插件版本；消费方以 `dependencies` 版本范围约束 |
| 能力契约文档 | 本文档版本 | 独立版本号；接口改动与 [02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md)、[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md)、[01-Bridge-API规范](./01-Bridge-API规范.md) 同 PR 更新 |

规则：

1. 能力 ID 不含版本、不含环境标识；同一 ID 同时只有一个生效注册，无多版本共存。
2. Bridge 不提供能力级版本协商、兼容别名与废弃过渡层（大爆炸重构）。
3. 废弃能力：先 RFC 评审，再解除登记并从注册表注销实现；移除前不得新增消费者。
4. 记录在案的破坏性变更在发布说明中列出，不提供运行时兼容行为。
