> 状态：正式版

### 5.6 渲染产物规则

- 渲染产物模式由上传会话的 `includeRenderArtifacts: true` 开启（5.3）；开启后服务端不调度服务端渲染，直接校验并发布客户端产物（5.5 完成阶段第 5 步）。
- 产物对象角色：查看产物使用 `render-file`，封面产物使用 `cover-file`（卡片会话）；两个角色只在产物模式会话中签发。客户端必须先在 `objects:presign` 中为全部产物文件申请预签名并直传对象存储（5.4），再在 `complete` 的 `renderArtifacts` 中提交产物清单。
- 产物清单结构（`complete` 请求体中的 `renderArtifacts`）：

```json
{
  "rendererVersion": "chips-client-renderer-1",
  "view": { "entryRelativePath": "index.html", "fileCount": 3, "sizeBytes": 1024 },
  "cover": { "entryRelativePath": "index.html", "fileCount": 2, "sizeBytes": 512 }
}
```

- `rendererVersion` 必填，标识客户端渲染器版本；服务端记录该值用于排查，不参与兼容协商，也不二次渲染。
- `view` / `cover` 的 `entryRelativePath` 必须是该产物目录的入口文件（通常 `index.html`），且必须是本会话已通过 `render-file` / `cover-file` 角色预签名并上传的相对路径；入口文件缺失或对象大小不符返回 `COMMUNITY_FILE_CORRUPT` / `COMMUNITY_OBJECT_SIZE_MISMATCH`。
- `fileCount` / `sizeBytes` 为该产物全部文件的合计；服务端按会话内的产物对象记录校验，不接受清单与对象不一致的提交。

- 产物对象键为 `{cardId}/{cacheVersion}/{relativePath}`，`cacheVersion` 等于会话 `versionId`（5.2）；公开卡片入公开产物桶，私有卡片入私有产物桶并只经受控代理读取。
- `public → private` 可见性变更时，公开产物必须移除并让缓存记录失效（4.8）；`private → public` 不自动恢复旧产物，按源文件与产物记录重新可用。
- 渲染产物不得包含主题标识与语言标识字段（主题系统与多语言系统已废弃，R5）；查看产物在客户端渲染时使用平台当前视觉能力。
- 产物发布成功即 `viewState = ready`；查看入口、封面入口与缓存受控代理按 5.7 执行，卡片打开只以 `open-view` 的 `viewState` 与 `viewUrl` 为准。
- 本契约只定义 HTTP 字段、对象角色与发布语义；客户端渲染算法、产物相对路径组织、入口打包与失败回退以 `16-卡片传输协议` 为唯一权威（5.9）。
