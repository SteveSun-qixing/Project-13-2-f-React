## 七、错误码

### 7.1 错误模型

全部资源错误遵循统一错误模型（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 9.1 节）：

```typescript
class ChipsError extends Error {
  constructor(options: {
    code: string;
    message: string;
    details?: unknown;
    retryable?: boolean;
  });
  readonly code: string;
  readonly details?: unknown;
  readonly retryable: boolean;
}

interface IChipsError {
  code: string;
  message: string;
  details?: unknown;
  retryable?: boolean;
}
```

- `ChipsError` 是唯一错误类（`IChipsError` 仅作结构别名），构造与跨进程归一规则以 [02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 第九节与 [01-Bridge-API规范](./01-Bridge-API规范.md) 为准。
- `message` 一律简体中文、面向用户；`details` 为结构化诊断，不得包含真实文件系统路径、堆栈与内部标识。
- 调用方必须按 `code` 处理错误，禁止匹配 `message` 文本（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 第十一节）。

### 7.2 错误码表

| 错误码 | 触发条件 | retryable | 协议路径 HTTP |
|---|---|---|---|
| `RESOURCE_INVALID_URI` | URI 语法非法：scope 段、受管作用域出现查询串、fragment、非法编码、userinfo | false | 400 |
| `RESOURCE_UNSUPPORTED_SCHEME` | `resource()` 收到 `chips-resource://` 与 `http(s)://` 以外的 scheme（如 `file://`） | false | — |
| `RESOURCE_NOT_FOUND` | 作用域未注册，或作用域内资源不存在 | false | 404 |
| `RESOURCE_PATH_INVALID` | 路径非法：穿越、绝对路径、分隔符、编码、控制字符、长度、符号链接、平台特例 | false | 400 |
| `RESOURCE_PERMISSION_DENIED` | 无权限，或作用域未绑定到调用会话 | false | 403 |
| `RESOURCE_TOO_LARGE` | 超过 `read()` 上限或单资源大小上限 | false | 413 |
| `RESOURCE_BUSY` | 句柄流占用期间调用 `readRange()` | true | 503 |
| `RESOURCE_HANDLE_RELEASED` | 已释放句柄被使用 | false | — |
| `RESOURCE_HANDLE_INVALIDATED` | 已失效句柄被使用；需重新获取 | true | — |
| `RESOURCE_POOL_EXHAUSTED` | 句柄数或读取队列超限 | true | 503 |
| `RESOURCE_READ_ONLY` | 对归档或只读作用域就地写入 | false | — |
| `RESOURCE_ALREADY_EXISTS` | 目标已存在（`rename` / `move` / `copy` 不覆盖） | false | 409 |
| `RESOURCE_NOT_EMPTY` | 目录非空（`delete` 非递归模式） | false | 409 |
| `RESOURCE_NOT_SUPPORTED` | 操作不被当前 Provider 支持（如 Platform / External 作用域不支持列举） | false | 501 |
| `RESOURCE_CROSS_SCOPE` | 操作涉及跨作用域，但调用方无目标作用域权限 | false | 403 |
| `RESOURCE_WRITE_FAILED` | 写入提交失败（磁盘、锁冲突） | true | — |
| `RESOURCE_NETWORK_FAILED` | 外部请求失败：DNS、连接、TLS、超时、HTTP 状态、重定向、SSRF 拦截 | true | 502 |
| `RESOURCE_INTERNAL` | 未归一异常（协议层兜底） | false | 500 |

- 协议路径错误到 HTTP 的映射即上表；"—" 表示该错误只出现在句柄路径或写入提交路径。
- `RESOURCE_HANDLE_*` 与写入类错误不暴露给协议路径：协议请求使用无句柄的短生命周期读取。
- 错误码与 HTTP 状态同时写入审计；审计格式见 [08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 第八节。

### 7.3 details 结构

```typescript
type ResourceUriErrorReason =
  | 'malformed_scheme'
  | 'unsupported_scheme'
  | 'malformed_scope'
  | 'malformed_path'
  | 'query_not_allowed'
  | 'fragment_not_allowed'
  | 'invalid_encoding'
  | 'invalid_origin';

type ResourcePathErrorReason =
  | 'absolute'
  | 'separator'
  | 'segment'
  | 'encoding'
  | 'control'
  | 'unicode'
  | 'length'
  | 'symlink'
  | 'platform';

type ResourceNetworkErrorReason =
  | 'dns'
  | 'connect'
  | 'tls'
  | 'timeout'
  | 'http_status'
  | 'redirect'
  | 'blocked';

interface IResourceUriErrorDetails {
  uri: string;
  reason: ResourceUriErrorReason;
}

interface IResourcePathErrorDetails {
  uri: string;
  path: string;
  reason: ResourcePathErrorReason;
}

interface IResourceSizeErrorDetails {
  uri: string;
  size: number;
  limit: number;
}

interface IResourceNetworkErrorDetails {
  host: string;
  reason: ResourceNetworkErrorReason;
  status?: number;
}

interface IResourcePoolErrorDetails {
  kind: 'handles' | 'queue';
  limit: number;
}

interface IResourceHandleErrorDetails {
  uri: string;
  state: ResourceState;
}

interface IResourceScopeErrorDetails {
  uri: string;
  scope: ResourceScope;
  operation: 'list' | 'write' | 'delete' | 'rename' | 'copy' | 'create_directory';
}
```

| 错误码 | details |
|---|---|
| `RESOURCE_INVALID_URI` | `IResourceUriErrorDetails` |
| `RESOURCE_UNSUPPORTED_SCHEME` | `IResourceUriErrorDetails`（`reason` 为 `unsupported_scheme`） |
| `RESOURCE_PATH_INVALID` | `IResourcePathErrorDetails` |
| `RESOURCE_NOT_FOUND` | `{ uri: string }` |
| `RESOURCE_PERMISSION_DENIED` / `RESOURCE_CROSS_SCOPE` | `IPermissionDeniedDetails`（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 5.4 节），`target` 填规范 URI |
| `RESOURCE_TOO_LARGE` | `IResourceSizeErrorDetails` |
| `RESOURCE_BUSY` | `{ uri: string }` |
| `RESOURCE_HANDLE_RELEASED` / `RESOURCE_HANDLE_INVALIDATED` | `IResourceHandleErrorDetails`（失效时附 `reason: ResourceInvalidateReason`） |
| `RESOURCE_POOL_EXHAUSTED` | `IResourcePoolErrorDetails` |
| `RESOURCE_READ_ONLY` / `RESOURCE_WRITE_FAILED` / `RESOURCE_ALREADY_EXISTS` / `RESOURCE_NOT_EMPTY` | `{ uri: string }`（写入失败附 `cause` 分类，不含路径） |
| `RESOURCE_NOT_SUPPORTED` | `IResourceScopeErrorDetails` |
| `RESOURCE_NETWORK_FAILED` | `IResourceNetworkErrorDetails` |
| `RESOURCE_INTERNAL` | 无（诊断写宿主日志） |

`ResourcePathErrorReason` 词表中的 `unicode` 在册且有明确触发规则：校验细则与归一语义统一见 §2.4 Unicode 行（本节不重复细则）。

### 7.4 处理规则

- 插件必须按 `code` 分支处理；`retryable: false` 的错误不得自动重试。
- `RESOURCE_HANDLE_INVALIDATED` 是"重新获取"信号：重新调用 `resource(uri)`，不得复用旧句柄。
- 图片、媒体加载失败由渲染层显示占位或错误态，不得静默空白（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 5.3 节）。
- 故障排查中的错误码对照见 [04-故障排查手册](../06-开发与运维/04-故障排查手册.md)。
