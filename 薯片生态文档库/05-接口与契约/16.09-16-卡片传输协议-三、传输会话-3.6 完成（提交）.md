# 卡片传输协议

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：`.card` / `.box` 在本地设备与内容服务器之间传输的权威协议：传输会话（创建、预签名、分片、断点续传、取消、恢复）、完整离线卡片与网络资源卡片的可逆改写与还原（含可逆恢复清单）、摘要与完整性校验、预签名与对象存储桶角色、传输队列与 `transfer:*` 事件映射、错误码与安全约束；不覆盖卡片/箱子的包结构语义、渲染链路与服务器产品设计。

### 3.6 完成（提交）

```http
POST /api/v1/card-transfer/upload-sessions/:uploadId/complete
Authorization: Bearer <token>
Content-Type: application/json
```

卡片会话请求体：

```json
{

  "cardFileId": "a1B2c3D4e5",

    "publicUrl": "https://file.example/…/card.card",

  },
  "resources": [
    {

        "sizeBytes": 1048576,

        "sha256": "b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2c3"

    "zipEntries": [
      { "order": 0, "path": ".card/metadata.yaml", "size": 512, "compressedSize": 512, "crc32": 123456789, "isDirectory": false, "compressionMethod": 0, "modifiedTime": 1758268800000 }
    ],
    "richTextContentFiles": []
  },

    "rendererVersion": "chips-client-renderer-1",
    "view": { "entryRelativePath": "index.html", "fileCount": 3, "sizeBytes": 1024 },

  }
}
```

- `restoreManifest` 必填；`resources` 必须覆盖本次上传的全部资源对象。
- `renderArtifacts` 仅在 `includeRenderArtifacts: true` 时提交：`rendererVersion` 必填，`view.entryRelativePath` 与 `cover.entryRelativePath` 必须是已预签名并上传的 `render-file` / `cover-file` 相对路径；未提交产物时服务器将卡片置为待渲染状态（`status = pending`）。
- `networkCard` / `resources` 的 `objectId`、`bucket`、`objectKey`、`sizeBytes`、`sha256` 必须与预签名记录一致，否则 `CARD_TRANSFER_OBJECT_MISMATCH`。

服务器校验顺序（任一失败即整体拒绝，不产生部分提交）：

1. 会话归属、状态与有效期；
2. 提交对象全部属于本会话（以 `objectId` 与对象键前缀交叉校验）；
3. 对每个对象执行 Head：大小与提交一致；摘要与对象元数据 `x-amz-meta-chips-sha256` 一致（5.3）；
4. `multipart` 对象已在服务器侧完成合并；
5. 恢复清单结构合法（4.4）且 `schemaVersion` 受支持；
6. 网络资源卡片内容引用本会话全部资源 URL，且卡内不再包含这些资源的原始字节（防止"模型新 + 资源旧"的混合提交）；
7. 渲染产物（如提交）入口文件已上传且已预签名。

响应（卡片，202）：

```json
{
  "data": {
    "cardId": "1a2b3c4d-…",
    "versionId": "6f7c1d2e-…",
    "status": "ready",
    "communityUrl": "https://www.example.com/cards/{cardId}",
    "renderStatusUrl": "/api/v1/cards/{cardId}/render-status"
  }
}
```

- `status` 取值 `ready`（内容已发布）或 `pending`（服务器渲染模式下等待查看产物；客户端渲染模式未提交产物时同样为 pending）。
- `renderStatusUrl` 只在服务器提供查看状态查询时返回（2.4）。
- `complete` 幂等：同一会话重复提交且内容一致时返回同一结果；内容不一致返回 `CARD_TRANSFER_SESSION_STATE_INVALID`；`aborted` / `expired` 会话返回对应错误。
