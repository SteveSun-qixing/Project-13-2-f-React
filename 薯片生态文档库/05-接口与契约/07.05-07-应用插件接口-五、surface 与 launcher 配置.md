## 五、surface 与 launcher 配置

### 5.1 manifest 片段

```yaml
ui:
  surface: window
  launcher:
    icon: assets/app-icon.svg
    name: 文本查看器
    description: 查看纯文本文件
fileAssociations:
  - extensions: [.txt, .md]
    action: open
deepLinks:
  - scheme: chips-text-viewer
    host: open
```

`ui` 与 `fileAssociations` 的校验规则以 [02-插件清单规范](../03-插件开发/02-插件清单规范.md) 为准；完整示例见 §9.1。

### 5.2 ui.surface 语义

| 值        | 语义         | 表面创建                           | `ctx.window` | 关闭主窗口的行为                                                     |
| --------- | ------------ | ---------------------------------- | ------------ | -------------------------------------------------------------------- |
| `window`  | 标准窗口应用 | 平台在启动时创建主窗口             | `IAppWindow` | `runtime.background` 为 `false` 时触发实例退出；为 `true` 时保持运行 |
| `desktop` | 桌面层应用   | 平台在启动时创建无边框桌面表面     | `IAppWindow` | 不触发实例退出；实例由 `exit()` 或平台动作结束                       |
| `tray`    | 托盘应用     | 平台注册托盘图标与菜单，不创建窗口 | `null`       | 不适用                                                               |

规则：

- 表面窗口由平台按 manifest 创建，插件不得创建原始系统窗口；额外窗口一律经 `window:create` 能力。
- 表面窗口装饰层（`ui.window.chrome` / `ui.window.titleBarStyle`）的语义、取值域、三端降级与 Electron 映射权威见 §5.8。
- 窗口创建使用 R17 安全基线（`nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`）。
- 窗口创建完成与关闭分别发布 `window:created` / `window:closed`（payload 见 §7.2）。

### 5.3 ui.launcher 字段

| 字段          | 类型     | 必需 | 缺省                   |
| ------------- | -------- | ---- | ---------------------- |
| `name`        | `string` | 否   | manifest `name`        |
| `description` | `string` | 否   | manifest `description` |
| `icon`        | `string` | 否   | 插件包默认图标         |

规则：

- 省略 `ui.launcher`：不注册启动器入口，应用只能经文件关联或命令启动，`ctx.launcher` 为 `null`。
- 声明 `ui.launcher`（含空对象）：注册启动器入口，缺省字段按上表补齐，`ctx.launcher` 为补齐后的信息。
- `icon` 为包内相对路径，经 `chips-resource://<pluginId>/...` 解析（[06-资源协议规范](06-资源协议规范.md)）。

### 5.4 fileAssociations

| 字段         | 类型                      | 说明                                                                    |
| ------------ | ------------------------- | ----------------------------------------------------------------------- |
| `extensions` | `string[]`                | 扩展名列表，含点号、小写，如 `[.txt, .md]`；与 `mimeTypes` 至少一项非空 |
| `action`     | `'open'`                  | 当前唯一动作：以打开方式接收文件                                        |
| `mimeTypes`  | `string[]`                | 可选；小写精确 MIME 或主类型通配（`type/*`）；`*/*` 不允许              |
| `tier`       | `'primary' \| 'fallback'` | 可选；处理器层级，缺省 `primary`；`fallback` 只在同等级无专用候选时接管 |

规则：

- 声明即注册文件关联路由；同一槽位存在多个声明方时按匹配等级（精确 MIME ＞ 主类型通配 ＞ 扩展名）与层级解析，用户偏好可改选默认；完整声明形状、校验与解析以 [14-资源打开与默认处理器契约](14-资源打开与默认处理器契约.md) §3、§4 为权威。
- 文件关联只决定路由，不产生持久授权：接收方读取打开投递的资源须声明 `resources:read` 基础权限，跨作用域访问由投递授权覆盖（[14-资源打开与默认处理器契约](14-资源打开与默认处理器契约.md) §4.4）；系统关联与拖放来源不要求 `filesystem:*`。
- 插件未运行时，文件打开请求以 `source: file-association` 启动实例；已运行时投递给 `openFile`（§6.2）；运行中上下文经标准事件 `resource:opened` 先行投递（[05-事件契约规范](05-事件契约规范.md) §4.4）。
- `fileAssociations` 对 `app` 与 `service` 可用，清单字段说明见 [02-插件清单规范](../03-插件开发/02-插件清单规范.md)；`service` 角色的语义见 [10-服务插件接口](10-服务插件接口.md)。

### 5.5 deepLinks（深链接）

| 字段          | 类型     | 说明                                                                |
| ------------- | -------- | ------------------------------------------------------------------- |
| `scheme`      | `string` | 深链接 scheme；必须为平台分配的插件 scheme，不得占用系统保留 scheme |
| `host`        | `string` | 深链接 host，插件内唯一                                             |
| `pathPattern` | `string` | 可选路径模式；省略表示匹配该 host 下全部路径                        |

规则：

- 声明即向平台注册深链接路由；scheme 与 host 的分配以 [02-插件清单规范](../03-插件开发/02-插件清单规范.md) 为准，插件不得自行修改已发布路由。
- 插件未运行时，深链接以 `source: deep-link` 启动实例并随 `ctx.args.url` 送达；已运行时发布标准事件 `app:opened-with-url`（`{ appId, url }`，[05-事件契约规范](05-事件契约规范.md) §4.7）。
- 深链接只做路由与投递，不代表授权；URL 指向的内容访问仍受权限判定。
- 同一深链接匹配多个插件时由平台按启用状态与用户选择路由；无法路由时记录诊断。

### 5.6 注册与生效时机

- 启用：注册启动器入口、文件关联与深链接路由，不创建窗口（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §4.3）。
- 运行：启动器、文件关联、命令与深链接入口均可触达该应用。
- 停用：先完成实例退出（§6.3），再移除启动器、文件关联与深链接路由；再次启用不重新安装。
- 注册表变化只影响后续启动意图；已运行实例的窗口与状态不因注册表变化被改写。

### 5.7 系统集成能力（菜单、托盘、快捷键、系统信息、电源、传输）

下述能力只对 `app` 角色开放（`system:info` / `power:query` / `transfer:*` 另见 [04-能力契约规范](04-能力契约规范.md) §6.3），契约权威在 [04-能力契约规范](04-能力契约规范.md) §7.9、§7.14、§7.15：

| 能力                                        | 应用侧用法                                                                                           | 权限                          |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------- |
| `menu:set`                                  | 在 `launch` 中构建应用菜单或托盘菜单；菜单项 `command` 命中时平台调用 `handleCommand(command, args)` | `menu:manage`                 |
| `tray:set`                                  | 托盘应用（`ui.surface: tray`）设置图标与 tooltip；点击经 `tray:clicked` 事件投递                     | `tray:manage`                 |
| `shortcut:register` / `shortcut:unregister` | 注册全局快捷键；触发时调用 `handleCommand` 并发布 `shortcut:triggered`                               | `shortcut:manage`             |
| `system:info`                               | 读取平台版本、OS、架构与路径变量解析值（只读）                                                       | `system:read`                 |
| `power:query` / `power:prevent-sleep`       | 查询电源与空闲状态；长任务期间抑制睡眠（随实例退出自动释放）                                         | `power:read` / `power:manage` |
| `transfer:download` / `transfer:cancel`     | 下载资源到授权路径；进度与结果经 `transfer:progress` / `transfer:completed` / `transfer:failed` 投递 | `transfer:manage`             |

- 上述调用主逻辑经 `ctx.bridge.request(...)`，UI 经 `chips.request(...)`；失败按 [04-能力契约规范](04-能力契约规范.md) 第 10 节错误码处理。
- 菜单、托盘与快捷键的绑定随实例退出自动清理；应用不得在 `beforeExit` 之外依赖进程级绑定存活。

### 5.8 窗口装饰与标题栏样式（`chrome` / `titleBarStyle`）

本节是窗口装饰面的生态权威：字段形状与取值域、装饰层影响、三端可行取值与降级、Electron 构造映射、`window:create` 参数面扩展与非法值处置。实装归属与时点：宿主窗口端口字段增位、`window:*` 能力族宿主生产注册、manifest 校验对 `ui.window` 的登记与脚手架样例均归 W4–W6 批次（Host/Scaffold 覆盖矩阵 G5 的收口以实装为准）；本节是 W4 派单的单一事实源，本节文面不代表字段在当前版本已经可调用。

#### 5.8.1 字段形状（`ui.window`）

```yaml
ui:
  surface: window
  window:
    chrome: true
    titleBarStyle: standard
```

| 字段                      | 类型      | 必需 | 缺省         | 取值域                                       | 语义                                                                                                                                                                                                                                                                                           |
| ------------------------- | --------- | ---- | ------------ | -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ui.window.chrome`        | `boolean` | 否   | `true`       | `true` / `false`                             | 系统装饰层开关。`true`：系统边框、原生标题栏、系统最小化/最大化/关闭按钮、系统拖拽区、系统调整边框全部由操作系统承载；`false`：无边框，装饰层全部改由应用自绘表面承担（逐要素影响见 §5.8.2）                                                                                                   |
| `ui.window.titleBarStyle` | `string`  | 否   | `'standard'` | `'standard'` / `'hidden'` / `'hidden-inset'` | 标题栏样式，仅与 `chrome: true` 组合有意义（`chrome: false` 时仍参与取值域校验，但不产生装饰效果，直接忽略）。`standard`：原生标题栏完整显示；`hidden`：隐藏标题栏内容区、保留系统窗口控制按钮，内容区顶到窗口上缘；`hidden-inset`：在 `hidden` 基础上将系统按钮改用内嵌位摆放，用于沉浸式头部 |

规则：

- `ui.window` 只允许出现在 `app` 角色且 `ui.surface: window` 的清单中；`desktop` / `tray` 的绑定见 §5.8.7。
- 字段缺省即取缺省值（`chrome: true`、`titleBarStyle: 'standard'`）；显式非法值不回落缺省，按 §5.8.6 处置——「缺失臂」与「非法臂」严格区分，禁止静默修正。
- 两字段均为创建期属性，无运行时可变性：不提供 `window:setChrome` / `window:setTitleBarStyle` 一类动作，变更装饰须关闭窗口后重新创建。
- 读回面不扩展：`window:list` 摘要（`WindowSummary`）不携带装饰字段——装饰不可变，以创建方（manifest 或 `window:create` 输入）为唯一事实源。

#### 5.8.2 `chrome` 开关对装饰层各要素的具体影响

| 装饰要素                   | `chrome: true` | `chrome: false`                                                                                                                                                   |
| -------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 系统边框与圆角             | 操作系统承载   | 移除；外形由应用自绘表面与系统合成器承担                                                                                                                          |
| 原生标题栏（含标题文字）   | 操作系统承载   | 移除；标题文字仍是窗口身份（任务栏与窗口列表读取，值来自创建参数 `title`，可经 `window:setTitle` / `IAppWindow.setTitle` 变更）                                   |
| 最小化 / 最大化 / 关闭按钮 | 操作系统承载   | 移除；应用自绘表面必须提供等价按钮，行为经 `window:setState` 与 `window:close`（`IAppWindow.close`）达成等价语义                                                  |
| 拖拽区                     | 系统标题栏     | 由自绘头部声明 `-webkit-app-region: drag`，其内部按钮局部置 `no-drag`；视觉基线权威为 [09-统一视觉规范](../02-开发规范/09-统一视觉规范.md) §2.6「标题栏拖拽区」行 |
| 调整大小边缘               | 操作系统承载   | `resizable: true` 时仍由系统承担（桌面壳三端无边框窗口保留系统调整边）；应用禁止自绘第三套调整面                                                                  |
| 双击标题栏最大化           | 系统标题栏内建 | 不内建；应用自绘头部如需该行为，自行经 `window:setState` 实现                                                                                                     |
| 窗口阴影                   | 操作系统承载   | 由系统合成器按无边框窗口策略承担，应用不注入阴影层                                                                                                                |

#### 5.8.3 三端可行取值与降级行为（`titleBarStyle` 平台矩阵）

| `titleBarStyle` | macOS                                      | Windows                                             | Linux                            |
| --------------- | ------------------------------------------ | --------------------------------------------------- | -------------------------------- |
| `standard`      | 支持：原生标题栏                           | 支持：原生标题栏                                    | 支持：原生标题栏                 |
| `hidden`        | 支持：标题栏隐藏、红绿灯（交通灯按钮）保留 | 支持：无边框 + 系统绘制窗口控制按钮覆盖层（右上角） | 不支持 → 降级 `standard`，记诊断 |
| `hidden-inset`  | 支持：红绿灯按内嵌位摆放                   | 不支持 → 降级 `hidden`，记诊断                      | 不支持 → 降级 `standard`，记诊断 |

- `chrome: false` 三端全支持（无边框、系统按钮全移除、全自绘），无降级臂。
- 降级只影响装饰档位，不使创建失败：一份 manifest 三端恒可运行是权威承诺；插件零壳感知（SB-3），不按平台名分支，平台负责向最近可行档位对齐。
- 降级臂不返回错误、不发布标准事件（非调用方过错）：宿主 PAL 每次窗口创建记一条 warning 级诊断，`details` 形状为 `{ windowId, field: 'titleBarStyle', requested, effective }`；本形状即权威词表，`window:*` 错误码面不因此新增码。

#### 5.8.4 与 Electron 的映射表（桌面壳构造配方）

映射对象为 `BrowserWindow` 构造选项；R17 / SB-8 安全基线字段（`nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`、生产 `webSecurity: true`）在同一次构造中恒定叠加，不随装饰档位变化，本表不重复列出。

| `chrome` | `titleBarStyle` | macOS                                           | Windows                                                                                                         | Linux                                          |
| -------- | --------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `true`   | `standard`      | `{ frame: true }`                               | `{ frame: true }`                                                                                               | `{ frame: true }`                              |
| `true`   | `hidden`        | `{ frame: true, titleBarStyle: 'hidden' }`      | `{ frame: false, titleBarStyle: 'hidden', titleBarOverlay: { color, symbolColor } }`                            | `{ frame: true }`（按 §5.8.3 降级 `standard`） |
| `true`   | `hidden-inset`  | `{ frame: true, titleBarStyle: 'hiddenInset' }` | `{ frame: false, titleBarStyle: 'hidden', titleBarOverlay: { color, symbolColor } }`（按 §5.8.3 降级 `hidden`） | `{ frame: true }`（按 §5.8.3 降级 `standard`） |
| `false`  | 任意            | `{ frame: false }`                              | `{ frame: false }`                                                                                              | `{ frame: false }`                             |

- `chrome: false` 时不传 `titleBarStyle`、`trafficLightPosition`、`titleBarOverlay`（无边框全自绘，系统按钮连同覆盖层全部移除）。
- 红绿灯像素位不进本细则：`hidden` 与 `hidden-inset` 均不传 `trafficLightPosition`，采用 Electron 内建摆放；如需逐像素定制属新字段，须经能力契约评审另行开面。
- Windows 覆盖层 `titleBarOverlay` 两键取主题 token：`color` ← 头部背景 token、`symbolColor` ← 头部前景图标 token；token 数值唯一权威为 [09-统一视觉规范](../02-开发规范/09-统一视觉规范.md)（含 antd 主题定制口径），本节不复制色值。

#### 5.8.5 `window:create` 能力参数面扩展

表面窗之外的额外窗口经 `window:create` 创建，输入携带同名可选字段，语义、取值域与缺省与 §5.8.1 完全一致（单一定义，不重复解释）：

```typescript
interface IWindowCreateInput {
  title: string;
  width: number;
  height: number;
  resizable?: boolean;
  entry?: string;
  chrome?: boolean;
  titleBarStyle?: 'standard' | 'hidden' | 'hidden-inset';
}
```

对应输入 schema 增项（沿用 [04-能力契约规范](04-能力契约规范.md) §5 JSON Schema 子集与 `window:create` 现行 `additionalProperties: false` 形状）：

```typescript
chrome: { type: 'boolean', default: true },
titleBarStyle: { type: 'string', enum: ['standard', 'hidden', 'hidden-inset'], default: 'standard' },
```

- [04-能力契约规范](04-能力契约规范.md) §7.4 输入表与 schema 登记 `chrome` / `titleBarStyle` 两行的落文，以及宿主窗口端口创建选项的字段增位，均以本节为语义权威，随 W4 实装批次同单修订；本波不动 04 篇目与任何代码。
- 端口纪律不变：schema 校验与权限判定由能力层在调用端口前完成；端口只做系统适配、执行 §5.8.3 / §5.8.4 的映射与降级，不承载判定。

#### 5.8.6 非法值处置

| 判定面        | 触发                                                                                                               | 处置                             | 错误码                                                                                    | 是否回落缺省                               | 诊断                              |
| ------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------ | --------------------------------- |
| manifest 校验 | `chrome` 非布尔；`titleBarStyle` 非枚举值；`ui.window` 含未知键；`ui.window` 出现在 `tray` 表面或 `app` 之外的角色 | 清单读取拒绝，插件安装/启用失败  | `CPK_MANIFEST_INVALID`（校验权威见 [02-插件清单规范](../03-插件开发/02-插件清单规范.md)） | 否（非法即拒，禁静默修正）                 | 记安装/启用失败原因               |
| manifest 校验 | `desktop` 表面声明 `ui.window`（其装饰为 §5.8.7 平台钉死值，声明与钉死值不可共存）                                 | 同上                             | `CPK_MANIFEST_INVALID`                                                                    | 否                                         | 同上                              |
| 能力输入校验  | `window:create` 输入未通过 §5.8.5 schema（类型、枚举、未知键）                                                     | 不创建窗口，直接返回错误         | `BRIDGE_INVALID_INPUT`（`details` 形状见 [04-能力契约规范](04-能力契约规范.md) §5.4）     | 否                                         | 走通道错误面                      |
| 平台降级      | 取值合法但目标平台不支持（§5.8.3 矩阵「不支持」格）                                                                | 按矩阵指定档位降级，窗口正常创建 | 无错误码                                                                                  | 否——不是回落缺省，而是按矩阵格回落指定档位 | warning 诊断一条（形状见 §5.8.3） |

#### 5.8.7 与 `ui.surface` 各形态的绑定

| 表面      | `chrome`                                                                 | `titleBarStyle`             | `ui.window` 声明                    |
| --------- | ------------------------------------------------------------------------ | --------------------------- | ----------------------------------- |
| `window`  | 按声明（缺省 `true`）                                                    | 按声明（缺省 `'standard'`） | 允许                                |
| `desktop` | 平台钉死 `false`（无边框桌面表面，§5.2），拖拽与按钮由桌面层自绘表面承担 | 钉死为不生效                | 禁止，出现即 `CPK_MANIFEST_INVALID` |
| `tray`    | 不适用（无窗口）                                                         | 不适用                      | 禁止，出现即 `CPK_MANIFEST_INVALID` |
