## 二、接口定义

### 2.1 完整签名

```typescript
type Dispose = () => void;

interface IBaseCardPlugin {
  /** 查看态：把一个节点视图渲染到容器；返回释放句柄或 void */
  renderView(basecard: BaseCardView, container: HTMLElement): void | Dispose;

  /** 编辑态：在容器内挂载节点编辑器并返回编辑句柄 */
  renderEditor(basecard: BaseCardView, container: HTMLElement): IBaseCardEditor;

  /** 校验节点内容中的 config；true 通过，false 拒绝 */
  validateConfig(config: unknown): boolean;

  /** 创建新节点时的初始内容（主进程纯函数） */
  createInitialContent(): Record<string, unknown>;

  /** 收集节点内容引用的资源路径（包内相对路径），供资源登记与导出（主进程纯函数） */
  collectResourcePaths(basecard: BaseCardView): string[];

  /** 可选：把节点视图导出为指定格式的产物 */
  export?(basecard: BaseCardView, format: string): Promise<Blob>;
}
```

本文全部接口与类型（`IBaseCardPlugin`、`BaseCardView`、`BaseCardContext`、`IBaseCardEditor`、`IBaseCardEditorEventMap`、`BaseCardChange`、`ICardPatchOperation` 等）均从 `@chips/sdk` 主入口导出，导出清单见 [02-SDK-API规范](./02-SDK-API规范.md) §2.2；`BaseCardView` 见第三节，`IBaseCardEditor` 见第四节；双入口职责见 §2.5。

### 2.2 方法与调用方

| 方法 | 必选 | 调用方 | 执行位置 | 调用时机 |
|---|---|---|---|---|
| `renderView` | 是 | 渲染帧运行时（渲染引擎） | 渲染帧（`sandbox` iframe） | 帧初始化与视图更新；**每个节点一个独立容器**，逐节点调用 |
| `renderEditor` | 是 | 编辑链路（就近渲染容器，经平台插件门面 `IManagedPluginRuntime` 装载） | 应用窗口渲染进程内的编辑容器 | 进入编辑态；每个编辑会话、每个节点一次 |
| `validateConfig` | 是 | 编辑链路；插件编辑器自身 | 调用方所在渲染上下文 | 编辑回流前、保存前、卡片创建与导入时 |
| `createInitialContent` | 是 | 编辑链路（创建节点成员） | 主进程（`dist/index.js`） | 在不存在节点的内容中创建成员时 |
| `collectResourcePaths` | 是 | 渲染引擎 / 文档服务 | 主进程（`dist/index.js`） | 资源登记、导出与包重建前 |
| `export` | 否 | 导出链路 | 渲染入口（`render.js`） | 用户请求导出且类型声明了 `exportFormats` |

### 2.3 实现与装载

- 渲染入口默认导出 `IBaseCardPlugin` 实现（`export default plugin`）；入口内不得同时实现其它角色接口，一个 `.cpk` 只声明一个 `manifest.type`（R1）。
- 平台按内容配置的 `card_type`（与 `.card/structure.yaml` 条目 `type` 对应）选择插件；卡片文件不声明所需插件版本，兼容性由插件自身版本策略（manifest 与能力声明）承担，已装插件不满足内容要求时按 `RENDER_SCHEMA_UNSUPPORTED` 降级（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md)）。
- 插件模块按「插件 ID + 版本」缓存，`plugin:loaded` / `plugin:unloaded` 触发失效；装载失败、入口缺失时帧进入降级占位，不调用任何插件方法（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §3.5、§6.1）。
- 模块级状态只在单个渲染帧内有效：插件不得假设全局唯一实例，也不得跨帧、跨窗口共享可变状态。

### 2.4 方法参考

#### 2.4.1 `renderView(basecard, container): void | Dispose`

| 参数 | 类型 | 说明 |
|---|---|---|
| `basecard` | `BaseCardView` | 只读节点渲染视图（第三节） |
| `container` | `HTMLElement` | 帧运行时为**该节点**提供的独立容器；插件只在此容器内创建 DOM |

返回：`Dispose` 释放本次调用创建的效果；无效果需要释放时返回 `void`。

契约：

1. 必须同步完成首次 DOM 提交；`frame:ready` 由帧运行时上报，插件不触发平台就绪信号。
2. 帧运行时为每个节点创建独立容器，容器与节点一一对应；插件不得跨容器渲染，不得把同一视图渲染到多个容器（禁止多节点共用容器）。
3. 同一容器的节点在视图更新时可能被多次调用：每次调用必须让容器呈现传入 `basecard` 的完整内容（覆盖式更新或自行 diff），不得叠加多份内容。
4. 更新调用创建新效果前，必须自行清理上一次调用创建、生命周期短于帧的效果（事件监听、定时器、Observer、媒体播放），避免重复叠加；返回的 `Dispose` 只负责本次调用建立的效果。
5. 帧运行时按调用顺序收集返回的 `Dispose`，帧销毁时逆序执行；`Dispose` 必须幂等，已释放效果不得再次触碰容器。
6. 不得访问平台与帧外环境（§5.4）；资源按第八节；不得读写存储、发起网络请求。
7. 抛出的异常由帧运行时隔离并按 `RENDER_PLUGIN_FAILED` 做节点级降级；插件必须容忍字段缺失与类型异常，保证坏数据下仍能呈现可读内容。
8. 不得固定容器宽度、不得请求改变外层尺寸；高度由帧运行时测量（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §6.3、§9.4）。

#### 2.4.2 `renderEditor(basecard, container): IBaseCardEditor`

参数与 `renderView` 相同。

返回：`IBaseCardEditor` 编辑句柄（第四节），由调用方在编辑会话结束时 `dispose()`。

契约：

1. 每次调用创建一个独立编辑器实例，并以传入 `basecard` 的内容与配置完成挂载；同一容器不得并存两个 `IBaseCardEditor`。
2. 挂载时把容器内容替换为编辑器 UI；编辑结果不得写文件、不得直接操作渲染会话，只经 `IBaseCardEditor` 变更接口交给编辑链路（§4.3）。
3. 装载与调用只由编辑链路经平台插件门面 `IManagedPluginRuntime` 执行；应用插件不得 import 插件代码（§2.5）。
4. 编辑器运行在应用窗口渲染进程：允许经 `window.chips` 使用能力与资源句柄，权限判定与其它插件一致（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §8.1）；禁止访问 Node.js / Electron API。
5. 抛出的异常由编辑链路按错误边界隔离，不得破坏宿主应用其余界面。
6. 编辑器尺寸由编辑面板布局决定，插件不得改变宿主布局。

#### 2.4.3 `validateConfig(config): boolean`

| 参数 | 类型 | 说明 |
|---|---|---|
| `config` | `unknown` | 节点内容 `config` 字段的原始值；未提供或为空时传入 `undefined` / `null`，此时按插件默认配置渲染 |

返回：`true` 通过；`false` 拒绝。

契约：

1. 必须是纯函数：同步、无副作用、不抛异常；不得访问能力、文件、网络或全局状态（主进程入口 `dist/index.js`）。
2. `undefined` / `null` 表示内容未提供配置：必须返回 `true`，渲染按插件默认配置进行，不得因空配置拒绝。
3. 判定不得比 `configSchema` 宽松：`configSchema` 通过且 `validateConfig` 返回 `true` 才视为合法（第七节）。
4. 可被高频调用（编辑器每次变更），必须保持与配置规模线性的轻量检查。
5. 卡片类型没有配置语义时恒返回 `true`。

#### 2.4.4 `createInitialContent(): Record<string, unknown>`

返回：新节点的初始内容对象；编辑链路在 `document:write` 创建成员时使用该值（[11-文档服务设计](../01-架构设计/01-子系统设计/11-文档服务设计.md) §4）。

契约：

1. 主进程纯函数（`dist/index.js`）；同步、无副作用、不依赖全局状态与时间。
2. 返回内容必须能通过本插件 `validateConfig` 与 `configSchema` 校验（未提供配置时使用默认可通过的空配置）。
3. 返回内容结构应与 `renderView` 读取的内容结构一致（含 `card_type`、`content_format` 等由插件定义的字段）。

#### 2.4.5 `collectResourcePaths(basecard): string[]`

| 参数 | 类型 | 说明 |
|---|---|---|
| `basecard` | `BaseCardView` | 只读节点渲染视图 |

返回：节点内容引用的资源路径数组，元素为包内相对路径（相对卡片包根，`/` 分隔）。

契约：

1. 主进程纯函数（`dist/index.js`）；同步、无副作用。
2. 只收集**包内相对路径**引用；`http(s)://` / `webdav://` / `chips-resource://` 引用不进入资源清单（[06-资源协议规范](./06-资源协议规范.md) §2.2、[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §8.2）。
3. 返回值必须去重且稳定排序；不存在的路径由渲染引擎按缺失资源诊断处理，本函数不做存在性校验。
4. 引用必须与内容保持一致：编辑变更产生的新引用在回流时同步进入资源登记，由文档服务在保存/导出时落地（§4.3）。

#### 2.4.6 `export(basecard, format): Promise<Blob>`

| 参数 | 类型 | 说明 |
|---|---|---|
| `basecard` | `BaseCardView` | 只读节点渲染视图 |
| `format` | `string` | 导出格式 ID，取值必须是 `capabilities.cardTypes[].exportFormats[].id` 之一 |

返回：`Promise<Blob>`；Blob 的 `type` 必须与格式声明的 `mimeType` 一致。

契约：

1. 只在 manifest 声明了 `exportFormats` 时实现；未实现时该类型不提供插件导出入口（§6.2）。
2. `format` 未声明或不支持时必须 reject `CARD_EXPORT_UNSUPPORTED`，不得返回与请求格式不符的内容。
3. 只读使用 `basecard`；不得修改视图、写文件、弹窗或创建窗口；产物持久化由导出链路经能力完成。
4. 导出失败 reject `ChipsError`：`CARD_EXPORT_FAILED`，`message` 为简体中文用户文案，`retryable` 按失败原因设置。
5. 资源访问经第八节；不得依赖仅在渲染帧内可用的环境。

### 2.5 双入口职责

| 入口 | 构建产物 | 承载内容 | 运行位置 |
|---|---|---|---|
| 主进程入口 | `dist/index.js` | 注册转发与纯函数：`validateConfig`、`createInitialContent`、`collectResourcePaths` | 主进程（受管模块加载器加载） |
| 渲染入口 | `render.js` | 渲染方法：`renderView`、`renderEditor`、`export` | 渲染帧 / 编辑容器（经 `chips-resource://<plugin-scope>/render.js` 加载） |

- 源码 `src/index.ts` 只做拆分导出：`export { validateConfig, createInitialContent, collectResourcePaths } from './main'` 与 `export { renderView, renderEditor, exportCard as export } from './render'`；构建按入口分别产出 `dist/index.js` 与 `render.js`。
- 构建外部化白名单为 `react`、`react-dom`、`@chips/ui`（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §2.6）；不得把渲染依赖打进主进程入口。
- `renderView` / `renderEditor` / `export` 只由平台调用；编辑链路与应用插件不得 import 插件代码，必须经平台插件门面 `IManagedPluginRuntime` 装载与调用（`loadBaseCard(cardType)`，见 [05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §3.5、[12-编辑引擎设计](../01-架构设计/01-子系统设计/12-编辑引擎设计.md)）。
