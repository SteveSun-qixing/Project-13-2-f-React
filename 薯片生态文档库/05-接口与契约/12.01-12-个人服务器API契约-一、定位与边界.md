## 一、定位与边界

### 1.1 定位

个人服务器是薯片生态的**单用户内容服务器**：一台服务器对应一个创作者，卡片与箱子作品直接属于服务器本身，访客无需账号即可浏览。

- **单用户**：没有账号体系、注册登录、房间、发现、搜索与管理后台；写权限只由服务器管理令牌 `API_TOKEN` 约束。
- **客户端渲染**：查看与封面渲染产物由客户端传输引擎渲染后上传，服务器只负责接收、存储、发布与展示，不执行渲染、不重建产物、不设置产物 TTL。
- **协议同构**：与社区平台共用 `.card` / `.box` 文件格式、`card-transfer` 控制面、对象存储直传、可逆恢复清单与下载计划；个人服务器只做能力裁剪，不发明第二套上传或下载协议。
- **独立部署**：个人服务器不参与平台运行时，不实现插件角色，不经 Bridge 与 `window.chips`；它是客户端显式发布动作的服务端终点。

### 1.2 消费者

| 消费者 | 形态 | 说明 |
|---|---|---|
| 网页访客 | 浏览器，同源 | 浏览作品主页、查看卡片查看页、箱子只读文档与封面；只读 |
| 客户端传输引擎 | Host 主进程侧传输引擎 | 上传、完整下载、远程打开；控制面经受管网络能力执行（[16-卡片传输协议](./16-卡片传输协议.md)） |
| 第三方工具 | 命令行或脚本 | 只读浏览与传输控制面；不得依赖未登记字段 |

### 1.3 权威范围

- 基础路径、数据格式、统一响应信封与追踪字段；
- `API_TOKEN` 鉴权、令牌配置与轮换、公开读与令牌写边界；
- 卡片与箱子的列表、详情、查看、封面、下载、删除接口与 DTO；
- 个人服务器在 `card-transfer` 控制面上的取值：能力声明、会话创建口径、完成校验、渲染产物发布、下载会话与下载计划；
- 分页、幂等、限额与限流口径；
- HTTP 状态与业务错误码登记；
- TLS、CORS 与路径/对象键安全要求。

### 1.5 术语

| 术语 | 含义 |
|---|---|
| 管理令牌（`API_TOKEN`） | 服务器环境变量配置的单用户写权限令牌；无账号、无会话、无刷新与吊销。 |
| 上传会话 | 一次作品上传的控制面上下文；状态机与字段见 [16-卡片传输协议](./16-卡片传输协议.md) §三。 |
| 预签名 | 服务器为对象存储签发的临时 PUT/GET 地址；文件字节不经过 API。 |
| 逻辑桶 / 物理桶 | 契约层桶名与实际对象存储桶；个人服务器支持单物理桶模式。 |
| 查看产物 / 封面产物 | 客户端渲染的卡片查看 HTML 目录与封面 HTML 目录。 |
| 渲染产物记录 | 一次发布写入卡片的 `render_artifacts`，含查看与可选封面两组。 |
| 网络资源卡片 | 资源字节不在 ZIP 内部、资源字段记录对象存储 URL 的正式 `.card` 形态。 |
| 下载计划 | 一次下载会话返回的对象清单与临时读取地址。 |
| 可见性 | `public` / `private`；私有资源对匿名读请求按不存在处理。 |
