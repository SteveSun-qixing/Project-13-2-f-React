## 六、句柄生命周期

### 6.1 句柄形状

```typescript
type ResourceScope = 'workspace' | 'document' | 'plugin' | 'platform' | 'external' | 'temporary' | 'memory';
type ResourceState = 'open' | 'invalidated' | 'released';
type ResourceInvalidateReason = 'source-changed' | 'session-closed' | 'scope-revoked';

interface IResourceMetadata {
  uri: string;
  size: number;
  mimeType: string;
  version: string;
  scope: ResourceScope;
}

interface IResourceHandle {
  readonly uri: string;
  readonly state: ResourceState;
  metadata(): Promise<IResourceMetadata>;
  read(): Promise<Uint8Array>;
  readRange(offset: number, length: number): Promise<Uint8Array>;
  stream(): ReadableStream<Uint8Array>;
  release(): void;
  onInvalidate(handler: (reason: ResourceInvalidateReason) => void): ISubscription;
}
```

- 本形状为对外唯一契约；方法级参考见 [01-Bridge-API规范](./01-Bridge-API规范.md)，管理器侧语义见 [04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 第四节。
- 句柄只读、不可序列化、不可持久化、不可跨会话传递；跨窗口场景必须各自创建句柄。

### 6.2 获取

1. `resource(uri)` 同步解析 URI 并基于会话权限快照做快速检查；非法或越权立即抛 `ChipsError`，不返回句柄。
2. 返回懒打开的代理句柄；首次 `metadata()` / `read()` / `readRange()` / `stream()` 触发主进程 `bridge:resource` 的 `open`。
3. 主进程再次执行解析、作用域与会话校验、权限判定（纵深防御），分配句柄 ID 并写入句柄表。
4. 打开失败时，首个异步操作以对应错误码拒绝；句柄上限（单插件 64、全局 4096）超限返回 `RESOURCE_POOL_EXHAUSTED`。

### 6.3 续期（租约延续）

- 会话存续期内，句柄每次成功使用刷新 `last_used_at`；句柄不设空闲过期，租约随会话存续。
- 租约绑定会话，不可转移、不可跨会话续期；会话关闭即归还全部租约。
- 失效后不可续期：必须重新调用 `resource(uri)` 获取新句柄（新句柄 ID），旧句柄保持 `invalidated` 直至 `release()`。

### 6.4 释放与失效

释放：`release()` → 归还租约、关闭流与底层读取器、从句柄表移除、写审计；`release()` 幂等，`released` 为终态且句柄 ID 不复用。

| 失效触发 | 影响范围 | 处理 |
|---|---|---|
| `file:changed`（受监视文件） | 对应作用域全部缓存与句柄 | 缓存失效；句柄转 `invalidated`（`source-changed`）并通知订阅者 |
| `document:changed` | 文档作用域 | 缓存失效；句柄转 `invalidated`（`source-changed`） |
| `document:closed` | 文档作用域 | 失效并释放（`session-closed`） |
| 插件更新或卸载 | 插件作用域 | 失效并释放（`scope-revoked`） |
| 权限撤销 | 相关作用域 | 失效并释放（`scope-revoked`） |
| 外部缓存过期 | External 条目 | 惰性失效，下次读取重新拉取 |

- `invalidated` 状态下读操作返回 `RESOURCE_HANDLE_INVALIDATED`；`release()` 仍可调用。
- `onInvalidate` 在句柄已失效后注册时，立即（下一微任务）回调一次 `reason` 并返回已失效订阅。
- 失效同时发布事件 `resource:invalidated`（payload `{ uri, reason }`），登记见 [05-事件契约规范](./05-事件契约规范.md)，事件系统机制见 [09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md)。
- 会话关闭时级联释放全部句柄；窗口关闭时 preload 批量释放该窗口句柄；GC 兜底与泄漏检测见 [04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 10.2 节。

### 6.5 状态机

```text
resource(uri)
      │
      ▼
    open ──release()──▶ released（终态；句柄 ID 不复用）
      │  ▲
      │  └── 同一会话内继续使用 = 租约延续（6.3 节）
      │
   来源变化 / 会话关闭 / 权限撤销
      │
      ▼
 invalidated ──release()──▶ released
      │
      └── 重新获取：再次 resource(uri) → 新句柄
```

### 6.6 读取约束

- 小资源（≤ 8 MiB）：`read()` 返回完整字节，命中内存缓存直接返回。
- 大资源（> 8 MiB）：`read()` 返回 `RESOURCE_TOO_LARGE`，必须使用 `stream()` 或 `readRange()`。
- 同一句柄的并发调用由句柄级互斥串行化；流打开期间 `readRange()` 返回 `RESOURCE_BUSY`。
- 相同 URI 的并发读取由管理器合并（SingleFlight）；句柄之间不共享游标（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 6.4 节）。
