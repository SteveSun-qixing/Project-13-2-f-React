## 五、卡片传输控制面

### 5.1 边界

- 传输由**控制面**（本节的 HTTPS JSON 接口）与**数据面**（对象存储直传）组成；API 不接收、不代理任何文件字节。
- 会话状态机、预签名模式（单次/分片）、断点续传、摘要与完整性、恢复清单 schema、客户端重试策略、`CARD_TRANSFER_*` 客户端错误码以 [16-卡片传输协议](./16-卡片传输协议.md) 为唯一权威；本节只定义个人服务器的端点、能力声明与产品取值。
- 客户端不得自行拼接对象键、不得跨会话复用预签名、不得把预签名写入卡片文件、恢复清单或日志。

### 5.2 能力声明

创建上传会话的响应必须包含 `capabilities`，个人服务器固定取值：

| 能力项 | 取值 | 说明 |
|---|---|---|
| `renderArtifacts` | `true` | 接受客户端渲染产物（`render-file` / `cover-file`），产物提交后作品 `ready` |
| `rooms` | `false` | 不支持 `roomId`；非空 `roomId` 请求返回 400 `VALIDATION_ERROR` |
| `multipart` | 部署能力 | 支持分片上传的部署为 `true`；不支持时超过单对象上限返回 400 `VALIDATION_ERROR`，并在 `details` 给出上限 |

未在 `capabilities` 中声明为 `true` 的能力不得使用；服务器必须显式拒绝而不是静默忽略。

### 5.3 端点

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/v1/card-transfer/upload-sessions` | 令牌 | 创建上传会话（`contentType`: `card` / `box`） |
| POST | `/api/v1/card-transfer/upload-sessions/:uploadId/objects:presign` | 令牌 | 申请对象预签名 |
| POST | `/api/v1/card-transfer/upload-sessions/:uploadId/complete` | 令牌 | 完成上传并发布 |
| POST | `/api/v1/card-transfer/upload-sessions/:uploadId/abort` | 令牌 | 中止上传会话 |
| POST | `/api/v1/card-transfer/download-sessions` | 令牌 | 创建下载会话 |
| GET | `/api/v1/card-transfer/download-sessions/:downloadId/plan` | 令牌 | 读取下载计划 |

请求与响应字段、状态码与语义以 [16-卡片传输协议](./16-卡片传输协议.md) §三为准；个人服务器取值如下：

1. **无房间**：请求不接受 `roomId`（或必须为 `null`）；不接受 `visibility` 字段，上传会话固定公开。
2. **会话有效期**：由部署配置 `UPLOAD_SESSION_TTL_MINUTES` 决定（默认 60 分钟）；过期返回 400 `UPLOAD_SESSION_EXPIRED`。
3. **幂等**：`idempotencyKey` 全局唯一；重复创建返回同一会话（同一 `uploadId` / `versionId`）。
4. **对象角色**：卡片会话使用 `network-card`、`resource`、`render-file`、`cover-file`；箱子会话使用 `box-file` 与箱子 `cover-file`（[16-卡片传输协议](./16-卡片传输协议.md) §6.1）。
5. **完成校验**：对象归属、大小与摘要、渲染入口预签名、恢复清单结构；箱子完成必须提交与 `.box` 源文件一致的 `metadata` / `structure` / `content`，按正式箱子格式校验（[02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md)），不合法返回 400 `FILE_CORRUPT`。
6. **完成结果**：提交渲染产物 → `status = ready`；未提交 → `status = pending`（网页显示"尚未渲染"），个人服务器不提供服务端渲染兜底。
7. **中止**：会话转 `aborted`，返回 `{ "data": { "uploadId": "…", "status": "cancelled" } }`。
8. **下载会话**：`cardId` 必须为公开可见卡片；下载计划中的地址有效期 900 秒；公开对象给公开 URL，私有对象给预签名 GET 地址。

### 5.4 存储桶与对象键

个人服务器使用 [16-卡片传输协议](./16-卡片传输协议.md) §6.2 定义的桶角色，部署取值：

| 桶角色 | 桶名 | 可见性 | 个人服务器写入方 |
|---|---|---|---|
| 卡片资源桶 | `chips-card-resources` | 公开读 | 客户端预签名直传 |
| 卡片源文件桶 | `chips-card-files` | 私有 | 服务器 |
| 箱子源文件桶 | `chips-box-files` | 私有 | 客户端预签名直传 |
| 公开查看产物桶 | `chips-card-render-cache` | 公开读 | 客户端预签名直传 |
| 私有查看产物桶 | `chips-card-render-cache-private` | 私有（受控代理） | 客户端预签名直传 |
| 公开封面产物桶 | `chips-card-cover-cache` | 公开读 | 客户端预签名直传 |
| 私有封面产物桶 | `chips-card-cover-cache-private` | 私有（受控代理） | 客户端预签名直传 |
| 通用封面桶 | `chips-covers` | 公开读 | 客户端预签名直传（箱子封面） |

- 对象键模板与预签名规则见 [16-卡片传输协议](./16-卡片传输协议.md) §6.1、§6.3、§6.4；客户端只消费响应中的 `bucket` / `objectKey` / `publicUrl`，不得假设桶名。
- **单物理桶模式**：部署配置 `S3_BUCKET_NAME` 存在时，全部逻辑桶写入同一物理桶，对象实际键为 `<逻辑桶名>/<对象键>`；`S3_ENDPOINT` 必须使用对象存储通用端点，避免物理桶名被写入对象键。
- **公开访问基址**：`S3_PUBLIC_URL` 配置时使用 `S3_PUBLIC_URL/<逻辑桶>/<对象键>`；开发模式使用 `S3_ENDPOINT/<逻辑桶>/<对象键>`；生产缺省为 `BASE_URL/cdn/<逻辑桶>/<对象键>`（由部署反向代理到对象存储）。
- **私有对象**：`publicUrl` 为空；读访问只经受控代理路由（4.2.5）。
- `cacheVersion` = 上传会话 ID；客户端不得自行定义缓存版本。

### 5.5 渲染产物记录

发布后写入卡片的 `render_artifacts`：

```json
{
  "rendererVersion": "chips-client-renderer-1",
  "themeId": "chips-official.default-theme",
  "locale": "zh-CN",
  "view": {
    "cacheVersion": "会话ID",
    "bucket": "chips-card-render-cache",
    "keyPrefix": "{cardId}/{cacheVersion}",
    "entryObjectKey": "{cardId}/{cacheVersion}/index.html",
    "entryUrl": "对象存储 URL 或受控代理路由",
    "fileCount": 3,
    "sizeBytes": 1024
  },
  "cover": {
    "cacheVersion": "会话ID",
    "bucket": "chips-card-cover-cache",
    "keyPrefix": "{cardId}/{cacheVersion}",
    "entryObjectKey": "{cardId}/{cacheVersion}/index.html",
    "entryUrl": "对象存储 URL 或受控代理路由",
    "fileCount": 2,
    "sizeBytes": 512
  }
}
```

- `rendererVersion` 只作记录与排查，不参与协商；服务端发布后不重新渲染。
- 公开产物入口为对象存储 URL；私有产物入口为受控代理路由。

### 5.6 可见性与清理

- 上传会话固定公开；发布后 `PATCH` 修改可见性时清理查看/封面产物（对象与字段），卡片回到 `pending`，需要重新上传产物。
- 删除作品按 4.2.7 / 4.3.5 的两阶段清理语义执行：记录先失效、按资源清单级联清理、失败进入重试队列；客户端不得依赖服务器保留已删除内容。
- 服务器不设置产物 TTL；产物生命周期与作品一致。
