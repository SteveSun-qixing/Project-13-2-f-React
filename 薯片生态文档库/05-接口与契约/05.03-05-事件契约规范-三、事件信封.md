## 三、事件信封

### 3.1 逻辑事件

发布者向总线提供事件 ID 与 payload；监听器与订阅 handler 只接收 payload：

```typescript
interface IEvent<TPayload = unknown> {
  eventId: string;   // <domain>:<action>，见第二节
  payload: TPayload; // 载荷，类型由事件契约定义
}
```

### 3.2 内核元数据

内核在发布入口补全以下元数据（结构见《[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md)》8.1）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 事件实例唯一 ID（ULID），由内核生成 |
| `source` | string | 发布者身份：平台组件 ID 或插件 ID；由内核按调用上下文记录，插件不可伪冒 |
| `timestamp` | number | 发布时刻，Unix 毫秒（UTC） |
| `traceId` | string \| undefined | 追踪 ID；记录在事件日志与 Bridge 追踪中 |

元数据不进入 payload，也不作为监听器与订阅 handler 的参数；事件契约需要表达来源差异时，在 payload 中定义显式字段。

### 3.3 跨进程信封

向渲染进程投递的事件使用固定封套（定义见《[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md)》7.2）：

```typescript
interface IEventEnvelope {
  eventId: string;   // 登记的标准事件 ID
  payload: unknown;  // 载荷
  emittedAt: number; // 事件产生时间，Unix epoch 毫秒
}
```

- 下行封套不含 `id`、`source` 与 `traceId`；发布者身份与追踪信息只进入日志与 Bridge 追踪。
- 发布者身份由 Bridge 在 `event:publish` 调用点按会话绑定，不取自调用参数。
- 只有第四节登记的事件允许出现在 `event:<eventId>` 通道；`internal:*` 与插件自有域事件不转发。

### 3.4 载荷约束

| 约束 | 规则 |
|---|---|
| 可克隆 | 跨进程 payload 必须可结构化克隆；函数、类实例、`Symbol`、DOM 节点、`Error` 实例被拒绝（`EVENT_PAYLOAD_UNSUPPORTED`）；错误值使用归一 `ChipsError` 普通对象 |
| 体积 | 序列化后不超过 256 KiB；大数据传递资源句柄或 `chips-resource://` URI（`EVENT_PAYLOAD_TOO_LARGE`） |
| 敏感数据 | 不得携带凭证材料、未脱敏用户数据与文件内容（见《[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md)》与《[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md)》） |
| 字段命名 | camelCase；时间戳按事件契约固定为 ISO 8601 UTC 字符串或 Unix 毫秒 |
| 类型唯一 | 每个事件 ID 只有一个 payload 形态；订阅方对未知类型必须收窄 |
