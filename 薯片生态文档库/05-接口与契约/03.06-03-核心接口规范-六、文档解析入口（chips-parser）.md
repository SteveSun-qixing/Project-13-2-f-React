## 六、文档解析入口（chips-parser）

### 6.1 公开类型

```rust
pub enum DocumentKind {
    Card,
    Box,
}

pub struct ParseOptions {
    /// 严格模式：警告升级为错误，并启用完整性哈希校验与未引用文件检查。
    pub strict: bool,
    /// 自动归一化（BOM、Unicode、默认值）并记录诊断。
    pub repair: bool,
    /// 校验 Store 成员 CRC32 与资源哈希。
    pub verify_hashes: bool,
    /// L2 单元并行度，默认 4。
    pub parallelism: usize,
    pub limits: ParseLimits,
}

impl Default for ParseOptions {
    fn default() -> Self {
        Self {
            strict: false,
            repair: true,
            verify_hashes: false,
            parallelism: 4,
            limits: ParseLimits::default(),
        }
    }
}
```

`ParseOptions` 在句柄创建后不可变；`ParseLimits` 字段与默认值见 [06-文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md) §9.1。

### 6.2 入口

```rust
pub struct CardParser {
    /* ParseOptions */
}

impl CardParser {
    pub fn new(options: ParseOptions) -> Self;

    /// 打开并解析到 L0，返回惰性句柄。
    pub fn open(&self, path: &Path) -> Result<DocumentHandle, DocumentError>;

    /// 全量解析（导出、校验、批处理）。
    pub fn parse(&self, path: &Path) -> Result<ParsedCard, DocumentError>;
}

pub struct BoxParser {
    /* ParseOptions */
}

impl BoxParser {
    pub fn new(options: ParseOptions) -> Self;

    /// 打开并解析到 L0；严格 box 入口。
    pub fn open(&self, path: &Path) -> Result<DocumentHandle, DocumentError>;

    /// 全量解析。
    pub fn parse(&self, path: &Path) -> Result<ParsedBox, DocumentError>;
}

/// 自动识别 `.card` / `.box`；扩展名与探测结果矛盾时以探测结果为准。
pub fn open_document(path: &Path, options: &ParseOptions) -> Result<DocumentHandle, DocumentError>;
```

| 入口 | 解析范围 | 失败语义 |
|---|---|---|
| `open` | 阶段 1-3（L0 metadata） | 致命错误返回 `DocumentError`；非致命问题写入句柄诊断 |
| `parse` | 全部阶段（L0-L2，资源字节不读） | 同上；诊断已排序去重 |
| `open_document` | 阶段 1-3 | 扩展名不符记录 `DOCUMENT_EXTENSION_MISMATCH`（警告） |

错误码与诊断码以 [06-文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md) §8 为准；解析算法、双模式数据源与限额不在此重复。

### 6.3 DocumentHandle

```rust
pub struct DocumentHandle {
    /* 惰性层级、诊断与修订，结构见 06-文档解析器设计 5.2 */
}

impl DocumentHandle {
    /// L0：打开时完成，常数时间返回。
    pub fn metadata(&self) -> Arc<DocumentMetadata>;

    /// L1：结构与引用索引，首次访问触发解析。
    pub fn structure(&self) -> Result<Arc<StructureModel>, DocumentError>;

    /// L2：单个内容节点。
    pub fn content(&self, node: &NodeId) -> Result<Arc<ContentNode>, DocumentError>;

    /// L2：条目分页读取。
    pub fn entries(&self, range: Option<Range<usize>>) -> Result<Arc<[Entry]>, DocumentError>;

    /// L3：资源字节流；解析阶段永不读取资源正文。
    pub fn read_resource(
        &self,
        path: &PackagePath,
        range: Option<Range<u64>>,
    ) -> Result<ByteStream, DocumentError>;

    /// 全量诊断快照（已排序去重）。
    pub fn diagnostics(&self) -> Vec<Diagnostic>;

    /// 数据源指纹与索引摘要的组合。
    pub fn revision(&self) -> DocumentRevision;

    /// 全量内容摘要；按需计算。
    pub fn content_digest(&self) -> Result<[u8; 32], DocumentError>;

    /// 严格校验报告。
    pub fn validate(&self) -> Result<ValidationReport, DocumentError>;
}
```

`DocumentHandle` 为 `Send + Sync`，可被多个消费者共享；内部状态由 `OnceLock` / `RwLock` 保护，同一句柄可并发访问。`ParsedCard` / `ParsedBox` 字段见 [06-文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md) §11.2。

### 6.4 Neon 导出

| 导出函数 | 参数 | 返回 |
|---|---|---|
| `openDocument` | `path: string`, `options?: ParseOptions` | `Promise<JsBox<DocumentHandle>>`（自动识别） |
| `openCard` | `path: string`, `options?: ParseOptions` | `Promise<JsBox<DocumentHandle>>`（严格 card） |
| `openBox` | `path: string`, `options?: ParseOptions` | `Promise<JsBox<DocumentHandle>>`（严格 box） |
| `documentMetadata` | `handle` | `Promise<MetadataResult>` |
| `documentStructure` | `handle` | `Promise<StructureResult>` |
| `documentContent` | `handle`, `nodeId: string` | `Promise<ContentResult>` |
| `documentEntries` | `handle`, `range?` | `Promise<EntriesResult>` |
| `documentReadResource` | `handle`, `path`, `range?` | `Promise<Buffer>` |
| `documentValidate` | `handle` | `Promise<ValidationReport>` |
| `buildDocumentView` | `handle`, `session: number` | `Promise<DocumentView>`（文档视图构建器，见 6.6 节） |
| `documentClose` | `handle` | `Promise<void>` |
| `createCancelToken` | — | `JsBox<CancelToken>` |
| `cancelTokenCancel` | `token` | `void` |

`MetadataResult` / `StructureResult` / `ContentResult` / `EntriesResult` 统一携带 `{ kind, value, diagnostics }`，以 `kind` 为判别字段；全量解析经访问器组合获得，不提供 eager 导出。`documentClose` 显式释放归档映射，未关闭时由 GC 终结器兜底。

### 6.5 TypeScript 调用示例

```typescript
import { openCard, documentMetadata, documentContent, documentClose } from '../../native';
import type { CardContent, ChipsError } from '@chips/sdk';

interface IDiagnostic {
  severity: 'error' | 'warning' | 'info';
  code: string;
  message: string;
  file?: string;
  line?: number;
  column?: number;
}

/** 读取卡片主内容；致命诊断返回 null，解析被取消返回 null。 */
export async function loadCardMain(cardPath: string): Promise<CardContent | null> {
  const handle = await openCard(cardPath);

  try {
    const metadata = await documentMetadata(handle);
    const fatal = metadata.diagnostics.some(
      (diagnostic: IDiagnostic) => diagnostic.severity === 'error',
    );
    if (fatal || metadata.kind !== 'card') {
      return null;
    }

    const content = await documentContent(handle, 'main');
    return content.value as CardContent;
  } catch (error: unknown) {
    const failure = error as ChipsError;
    if (failure.code === 'DOCUMENT_PARSE_CANCELLED') {
      return null;
    }
    throw failure;
  } finally {
    await documentClose(handle);
  }
}
```

`CardContent` 等模型类型由 `@chips/sdk` 提供；示例位于主进程 `packages/host/src/main/`，绑定产物位于 `packages/host/native/`。

### 6.6 文档视图构建器与视图类型

文档视图构建器运行在主进程（Rust 核心），把解析句柄 + 会话模型投影为可结构化克隆的 `DocumentView`，供帧初始化、`host:update`、条目票证与编辑链路就近渲染共同使用（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §2.6）。

```rust
/// 构建文档视图；只做字段投影与不透明值保留，不读取资源字节、不拼接资源 URI。
pub fn build_document_view(
    handle: &DocumentHandle,
    session: SessionId,
) -> Result<DocumentView, ChipsError>;
```

Neon 导出：`buildDocumentView(handle, session)`（第 6.4、8.6 节）。

视图类型只登记一次（本节为正式定义，[02-SDK-API规范](./02-SDK-API规范.md) 同步导出，[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §2.5 只列消费字段）：

```typescript
type DocumentView = CardRenderView | BoxRenderView;
type TagView = string | string[];

interface CardRenderView {
  kind: 'card';
  revision: number;
  card_id: string;
  name: string;
  chip_standards_version: string;
  cover_ratio: string;
  tags: TagView[];
  cover: CoverView;
  content_nodes: CardNodeView[];
}

interface CardNodeView {
  node_id: string;
  card_type: string;
  content: Record<string, unknown>;
}

interface BaseCardView {
  kind: 'basecard';
  node_id: string;
  card_type: string;
  content: Record<string, unknown>;
  revision: number;
  card: BaseCardContext;
}

interface BaseCardContext {
  card_id: string;
  name: string;
  chip_standards_version: string;
  cover_ratio: string;
  tags: TagView[];
}

interface CoverView {
  entry: string;
  ratio: string;
}

interface BoxRenderView {
  kind: 'box';
  revision: number;
  box_id: string;
  name: string;
  chip_standards_version: string;
  active_layout_type: string;
  layout_config: Record<string, unknown>;
  cover: CoverView;
  entries: EntryView[];
}

interface BoxCoverView {
  kind: 'box';
  box_id: string;
  name: string;
  chip_standards_version: string;
  cover: CoverView;
}

interface EntryView {
  entry_id: string;
  url: string;
  enabled: boolean;
  snapshot?: Record<string, unknown>;
  layout_hints?: Record<string, unknown>;
}
```

规则：

1. 命名以本节为准：`DocumentView = CardRenderView | BoxRenderView`；`CardView` / `BoxView` 名称作废；节点视图统一为 `BaseCardView`（[08-基础卡片插件接口](./08-基础卡片插件接口.md) 使用），箱子布局视图统一为 `BoxRenderView`（[09-箱子布局插件接口](./09-箱子布局插件接口.md) 使用）。
2. 视图是只读快照：构建后不随会话模型自动变化；`revision` 前进时由编辑链路 `document:write` 成功后触发重新构建。
3. 视图必须可结构化克隆：不得包含句柄、函数、类实例、`Symbol`、循环引用与文件字节。
4. 视图中的资源引用保持文件原样；引用归一由文档解析器负责（[06-文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md) §5），不得回填视图。
5. 构建器无自有缓存；同一解析句柄与同一 `revision` 下输出确定。`BoxCoverView` 供条目目标为箱子时的受控封面渲染使用，不展开布局。
