## 三、客户端封装

### 3.1 唯一调用形状

SDK 客户端实现 `IChipsBridge` 的全部形状，方法面与 `window.chips` 完全一致，不得增删：

```typescript
interface IChipsBridge {
  request<TOutput>(capabilityId: string, input?: unknown): Promise<TOutput>;
  subscribe(eventId: string, handler: (payload: unknown) => void): ISubscription;
  resource(uri: string): IResourceHandle;
}

interface ISubscription {
  dispose(): void;
}
```

方法语义、参数表、错误与生命周期以 [Bridge API 规范](./01-Bridge-API规范.md) 为准；本文不重复逐项说明。

### 3.2 客户端及其创建

```typescript
/** 创建客户端时可注入的选项。 */
interface ICreateClientOptions {
  /** 显式注入的 Bridge 目标；省略时惰性绑定 window.chips。 */
  readonly bridge?: IChipsBridge;
}

/**
 * 创建 SDK 客户端。
 *
 * @param options - 创建选项；省略时绑定 window.chips
 * @returns 绑定目标 Bridge 的客户端
 */
function createClient(options?: ICreateClientOptions): ChipsBridge;

/**
 * SDK 客户端：实现 IChipsBridge，把调用转发给目标 Bridge。
 *
 * 未显式注入目标时，每次调用解析一次 window.chips：
 * 目标不可用时 request 异步拒绝，subscribe 与 resource 同步抛出
 * ChipsError（SDK_BRIDGE_UNAVAILABLE）。
 */
class ChipsBridge implements IChipsBridge {
  constructor(target?: IChipsBridge);
  request<TOutput>(capabilityId: string, input?: unknown): Promise<TOutput>;
  subscribe(eventId: string, handler: (payload: unknown) => void): ISubscription;
  resource(uri: string): IResourceHandle;
  /** CLI 命令发现扩展命名空间；见 3.5 节。 */
  readonly cliCommand: CliCommandApi;
  /** CLI 任务生命周期扩展命名空间；见 3.5 节。 */
  readonly cliTask: CliTaskApi;
}

/** 默认客户端：等价于 createClient()，供插件业务代码直接使用。 */
const chips: ChipsBridge;
```

三者的关系与选用：

| 名称 | 角色 | 使用场景 |
|---|---|---|
| `chips` | 模块级单例 | 插件业务代码的默认入口；因目标按调用解析，测试中安装 Mock 后无需重建 |
| `createClient` | 工厂函数 | 需要注入目标 Bridge 或后续扩展选项时使用；业务代码与工具统一从工厂创建 |
| `ChipsBridge` | 实现类 | 声明参数类型、显式包装某个 `IChipsBridge` 目标时使用 |

目标解析规则：

| 场景 | 行为 |
|---|---|
| 构造时传入 `target` | 全部调用直接转发给 `target` |
| 未传入且 `window.chips` 已注入 | 转发给 `window.chips` |
| 未传入且 `window.chips` 不存在 | `request` 异步拒绝；`subscribe`、`resource` 同步抛出 `SDK_BRIDGE_UNAVAILABLE` |
| 未传入、构造后 `window.chips` 才注入 | 后续调用自动使用新注入的 Bridge（解析发生在每次调用） |

调用链路：

```text
插件代码
  │ chips.request('file:read', input)
  ▼
ChipsBridge（SDK 客户端）
  │ 解析目标：注入的 IChipsBridge ── 或 ── window.chips
  ▼
IChipsBridge（preload 注入，唯一运行时入口）
  │ bridge:request IPC
  ▼
薯片平台 Bridge 层（会话 / 权限 / schema / 路由）→ 能力实现
```

完整示例（标准用法）：

```typescript
import { chips } from '@chips/sdk';
import type { CapabilityInput, CapabilityOutput } from '@chips/sdk';

/**
 * 读取卡片元数据文件内容。
 *
 * @param path - 包内相对路径
 * @returns 文件文本内容
 */
export async function readMetadata(path: string): Promise<string> {
  const input: CapabilityInput<'file:read'> = {
    path,
    encoding: 'utf-8',
  };
  const output: CapabilityOutput<'file:read'> = await chips.request<
    CapabilityOutput<'file:read'>
  >('file:read', input);
  return output.content;
}
```

完整示例（注入客户端）：

```typescript
import { createClient } from '@chips/sdk';
import type { ChipsBridge, IChipsBridge } from '@chips/sdk';

/**
 * 为指定 Bridge 目标构建客户端（测试与工具注入用）。
 *
 * @param target - 已注入的 Bridge 目标
 * @returns 绑定该目标的客户端
 */
export function createInjectedClient(target: IChipsBridge): ChipsBridge {
  return createClient({ bridge: target });
}
```

完整示例（显式包装）：

```typescript
import { ChipsBridge } from '@chips/sdk';
import type { CapabilityOutput, IChipsBridge } from '@chips/sdk';

/**
 * 显式包装一个 Bridge 目标并读取文件。
 *
 * @param target - 已注入的 Bridge 目标
 * @param path - 包内相对路径
 * @returns 文件文本内容
 */
export async function readTextWithBridge(target: IChipsBridge, path: string): Promise<string> {
  const client = new ChipsBridge(target);
  const output: CapabilityOutput<'file:read'> = await client.request<
    CapabilityOutput<'file:read'>
  >('file:read', { path, encoding: 'utf-8' });
  return output.content;
}
```

### 3.3 编译期类型化调用

- `ICapabilityContracts` 是能力 ID 与输入、输出在编译期的唯一映射（[能力契约规范](./04-能力契约规范.md) 第 2.3 节）；插件不得重复定义同名契约接口。
- 调用点用 `CapabilityId` 约束能力 ID，用 `CapabilityInput<TId>` 注解输入，用 `CapabilityOutput<TId>` 标注输出。
- 类型只存在于编译期：运行时仍走 `IChipsBridge.request` 的原始签名，不改变调用语义与错误行为；输出不做运行时校验。

```typescript
import { chips } from '@chips/sdk';
import type { CapabilityId, CapabilityInput, CapabilityOutput } from '@chips/sdk';

/**
 * 类型化能力调用：能力 ID、输入与输出均在编译期检查。
 *
 * @param id - 能力 ID
 * @param input - 与能力 ID 对应的输入
 * @returns 与能力 ID 对应的输出
 */
export async function callCapability<TId extends CapabilityId>(
  id: TId,
  input: CapabilityInput<TId>,
): Promise<CapabilityOutput<TId>> {
  return chips.request<CapabilityOutput<TId>>(id, input);
}
```

### 3.4 资源句柄的同步与异步错误

`resource(uri)` 与 `request` / `subscribe` 的失败时机不同，调用点必须分别处理：

```typescript
import { ChipsError, chips } from '@chips/sdk';
import type { IResourceHandle } from '@chips/sdk';

/**
 * 打开卡片封面并读取元数据。
 *
 * @param uri - chips-resource:// URI
 */
export async function openCover(uri: string): Promise<void> {
  let handle: IResourceHandle;
  try {
    // URI 非法或明显越权：同步抛出 ChipsError
    handle = chips.resource(uri);
  } catch (error) {
    if (error instanceof ChipsError) {
      console.warn(`资源预检失败：${error.code}`);
      return;
    }
    throw error;
  }

  try {
    // 首次 metadata() 触发打开；权限或存在性问题在此异步拒绝
    const metadata = await handle.metadata();
    console.warn(`封面大小：${metadata.size} 字节`);
  } finally {
    handle.release();
  }
}
```

### 3.5 CLI 扩展（`client.cliCommand` / `client.cliTask`）

`ChipsBridge` 在 Bridge 方法面之外附带两个只读扩展命名空间，用于插件 CLI 命令发现与任务生命周期；方法形状、字段与错误码以 [CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §5.6、§5.8 为唯一权威，SDK 只做类型化封装，不定义第二套语义：

```typescript
class ChipsBridge implements IChipsBridge {
  // request / subscribe / resource 见 3.2 节
  readonly cliCommand: CliCommandApi;
  readonly cliTask: CliTaskApi;
}
```

运行位置与传输：

| 运行位置 | 可用方法 | 传输 |
|---|---|---|
| 插件运行时（`chips` / `createClient()`） | `cliTask.active` / `get` / `progress` / `complete` / `fail` | Bridge 能力 `cli:task-*`（空权限、owner 归属校验，能力登记见 [04-能力契约规范](./04-能力契约规范.md) §7.17；语义见 [CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §5.6） |
| `@chips/cli` 与平台组件（注入传输的客户端） | `cliCommand.list` / `get` / `resolve`；`cliTask.create` / `bindInvocation` / `get` / `cancel` | 平台服务路由 `cli.command.*` / `cli.task.*`（[CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §5.8） |

- 扩展命名空间不新增传输通道：调用仍经客户端目标 Bridge 转发，目标解析规则与 3.2 节一致。
- `cliCommand` 只读：读取当前工作区命令索引，不修改插件状态；查询参数非法返回 `CLI_COMMAND_QUERY_INVALID`，多匹配返回 `CLI_COMMAND_CONFLICT`。
- `cliTask` 任务按 owner 归属校验，跨插件读写一律拒绝；终态不可逆，越界上报返回 `CLI_TASK_INVALID`。
- 失败统一归一为 `ChipsError`，`code` 取 CLI 域错误码（[CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §2.5、§2.6）。

主入口随这两个命名空间导出的类型（仅类型，`import type` 消费）：

| 类型 | 用途 |
|---|---|
| `CliCommandTargetType`、`CliCommandQueryOptions` | 发现查询的目标类型与查询参数 |
| `CliCommandApi`、`CliCommandListResult`、`CliCommandView`、`CliCommandIndex`、`CliCommandConflict`、`CliCommandResolveResult` | 命令发现接口与结果 |
| `CliTaskApi`、`CliTaskStatus`、`CliTaskRecord` | 任务接口、任务状态与任务记录 |

完整示例（应用插件侧上报 CLI 任务）：

```typescript
import { chips } from '@chips/sdk';

/**
 * 在命令处理中上报当前 CLI 任务的进度与终态。
 *
 * @param commandId - 运行时命令 ID
 * @param outputPath - 产物路径
 */
export async function reportCliTask(commandId: string, outputPath: string): Promise<void> {
  const active = await chips.cliTask.active(commandId);
  if (active === undefined) {
    return; // 命令未声明 job.wait，无 CLI 任务
  }
  await chips.cliTask.progress(active.taskId, { stage: 'writing', percent: 80 });
  await chips.cliTask.complete(active.taskId, { files: [outputPath] });
}
```

完整示例（发现与调度侧；`@chips/cli` 注入服务路由目标，插件运行时无需注入）：

```typescript
import { createClient } from '@chips/sdk';
import type { IChipsBridge } from '@chips/sdk';

// @chips/cli 内部提供的服务路由目标；插件运行时用默认客户端即可
declare const cliBridge: IChipsBridge;

const client = createClient({ bridge: cliBridge });
const { commands } = await client.cliCommand.list({ targetType: 'app' });
const resolved = await client.cliCommand.resolve({ commandPath: 'office open' });
if (resolved.command !== undefined && resolved.conflicts.length === 0) {
  console.log(resolved.command.entryId, commands.length);
}
```
