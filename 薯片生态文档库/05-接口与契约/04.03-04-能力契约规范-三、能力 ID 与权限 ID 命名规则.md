## 三、能力 ID 与权限 ID 命名规则

### 3.1 文法

```text
capability-id  = domain ":" action [ ":" target ]
domain         = 1*( lowercase / digit / "-" )           ; 语义域，平台登记分配
action         = 1*( lowercase / uppercase / digit / "-" )
target         = 1*( lowercase / digit / "-" / "." )

permission-id  = domain ":" scope [ ":" qualifier ]
domain         = 1*( lowercase / digit / "-" )           ; 内置域，平台维护
scope          = 1*( lowercase / digit / "-" )           ; 域内作用域，平台维护
qualifier      = 按域定义的限定值文法（见 08-权限系统设计 第 4.1 节）
```

规则：

1. 能力 ID 的 `domain`（命名空间段）与 `target` 全部小写，`action` 段允许小写字母、大写字母、数字与连字符；权限 ID 各段全部小写。禁止空白、下划线与中文；`:` 是唯一分隔符；能力 ID 为 2 段或 3 段，4 段及以上非法。
   - camelCase 动作段场景说明：`action` 段常规形态为全小写动词（或连字符短语，如 `list-handlers`、`prevent-sleep`）；当动作语义为多词动词短语且平台登记为独立动作时，允许采用 camelCase 连接。当前经 R19 canonical 总表（第 6.2 节）登记的 camelCase 动作段实例仅三个：`window:setTitle`、`window:setState`、`shell:openExternal`，与生成器 `CAPABILITY_ID_PATTERN`（动作段首字符仍为小写字母，其后允许大写字母）一致。新登记能力优先使用全小写连字符动作段（第九节）；大写形态仅限平台登记时明确批准的独立动作。
2. 能力 ID 与权限 ID 是两个互相隔离的命名空间：`file:read` 永远是能力，`filesystem:read` 永远是权限；禁止同一标识既当能力又当权限（R3）。大小写规则同样区分两者：动作段大写只对能力 ID 开放，权限 ID 的 `domain` 与 `scope` 一律全小写、不存在大写实例。
3. 能力 ID 不携带版本号；版本规则见第十节。
4. 能力 ID 是**登记标识**：内置能力登记于第 6.2 节，第三方 Bridge 能力经平台评审登记（第九节），内容处理服务能力按第八节登记；未登记 ID 不得注册、不得调用。domain 由平台统一登记与分配，插件不得自造 domain、action 或 target。
5. 权限 ID 的 domain/scope 由平台统一维护，第三方插件不得新增域、scope 或 qualifier 文法（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 第 3.2、10.3 节）。
6. `target` 段用于同一动作的细分变体（如 `hello:greet:formal`）；是否为独立 ID 由登记决定。

### 3.2 语义域

以下 domain 为平台语义域，由平台统一登记与分配；第三方能力不得自行占用，只能使用平台在登记时分配给提供方的 ID：

`file`、`resource`、`document`、`window`、`menu`、`tray`、`shortcut`、`system`、`power`、`transfer`、`notification`、`clipboard`、`dialog`、`shell`、`http`、`config`、`credential`、`event`、`command`、`cli`、`permission`。

- `permission` 域为权限治理能力专用（`permission:grant` / `permission:revoke` / `permission:restore` / `permission:audit-read`，工单046 登记，2026-09-21，见第 6.2、7.18 节）。

- 内置能力直接使用上述域（如 `file:read`）。
- 平台可将某个语义域下的 `action` / `target` 分配给经评审的第三方提供方，分配结果计入登记记录并与提供方绑定（第九节）。
- 新领域能力由平台登记新 domain；domain 一经登记即属平台命名空间，不随提供方卸载而废弃。
- **内容处理类实现**（图像编解码/缩放、视频抽帧/转码、Office 格式转换等）不注册为 Bridge 能力，也不进入第 6.2 节全表：这类实现属于业务能力，由**服务插件**通过 `ctx.provide` 注册为 Cordis 服务供其他插件消费（详见 [03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §8）；其能力 ID、归属提供方、输入输出、权限映射与错误码族按第八节登记。平台不固化任何具体算法实现。

### 3.3 能力族占位

能力族记法：`*` 表示目标段由具体标识符替换，`*` 本身不是可注册、可调用的能力 ID。注册表只注册具体目标；调用未登记目标返回 `BRIDGE_CAPABILITY_NOT_FOUND`。

### 3.4 命名禁令

| 禁令                                                                                                                | 处理                                                              |
| ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 注册未登记 ID（含自造 domain / action / target）                                                                    | 注册拒绝，`BRIDGE_CAPABILITY_CONFLICT`                            |
| 注册已登记给他方的 ID                                                                                               | 注册拒绝，`BRIDGE_CAPABILITY_CONFLICT`                            |
| 能力 ID 与权限 ID 相同                                                                                              | 注册拒绝，`BRIDGE_CAPABILITY_CONFLICT`（R3）                      |
| 使用未登记能力 ID 调用                                                                                              | `BRIDGE_CAPABILITY_NOT_FOUND`，不可重试                           |
| 使用未注册权限 ID                                                                                                   | 安装校验 `PERMISSION_UNKNOWN`，能力注册 `PERMISSION_NOT_DECLARED` |
| 把内容处理实现写成 Bridge 能力 ID，或复用已作废的旧标识（`image.*`、`converter.*`、`resource.convertTiffToPng` 等） | 无效标识；内容处理服务能力按第八节文法登记与使用                  |
| 在 ID 中编码版本、环境、租户等动态信息                                                                              | 注册拒绝，`BRIDGE_CAPABILITY_CONFLICT`                            |
