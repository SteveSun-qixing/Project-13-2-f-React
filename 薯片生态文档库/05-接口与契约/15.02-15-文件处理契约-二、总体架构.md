# 文件处理契约

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：通用文件处理（`.card` / `.box` 文档之外的普通文件）的会话与转换编排契约：`file-processing` 服务、打开/预览/转换/另存/比较操作、进度与取消、受控提交与原子替换、大文件流式、错误码与边界；不定义具体格式算法、支持矩阵与原子能力实现

---

## 二、总体架构

### 2.1 分层位置

```text
应用插件主逻辑 / 服务插件（主进程，Cordis）
  │ ctx.inject(['file-processing'])
  ▼
文件处理服务（service 角色插件，服务名 file-processing）
  ├── ctx.inject 内容处理服务（格式算法，04 §八）
  ├── ctx.bridge.request('document:*')    # .card / .box 文档（仅转换来源）
  ├── ctx.bridge.resource(source)         # 来源句柄（只读、持租约）
  └── 受控提交（一次性 / 流式）            # 产物写出：临时物 + 原子替换
  ▼
资源管理器（Rust 核心） · 文档服务 · 内容处理服务提供方
```

- 文件处理服务运行在主进程，由受管模块加载器加载；不得直接访问 Node.js / Electron / 系统 API，不得创建子进程（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §5、[10-服务插件接口](./10-服务插件接口.md) §2.5）。
- 服务以平台身份执行并遵守范围边界：只访问调用方传入的受管引用；句柄获取、写入提交与文档访问仍由 Bridge 与权限系统判定，服务不得扩权、不得缓存授权结果。

### 2.2 参与方职责

| 参与方 | 职责 | 不做什么 |
|---|---|---|
| 文件处理服务 | 会话状态机、操作编排、进度与取消、提供方选择、产物发布、暂存区清理、比较与差异计算 | 不实现格式算法、不解析文件内容、不直接读写文件 |
| 内容处理服务提供方 | 提供原子处理（解码/转码/渲染为中间产物/编码），声明支持矩阵与流式能力 | 不获取句柄、不写目标路径、不接触权限系统 |
| 资源管理器 | 句柄、范围读、流式读、版本戳、受控提交、PathGuard、作用域与缓存 | 不理解格式与业务语义 |
| 文档服务 | `.card` / `.box` 的会话、模型、保存与导出 | 不参与普通文件的字节读写 |
| Bridge 与权限系统 | 能力调用、权限判定、schema 校验、审计、错误归一 | 不感知处理管线 |

### 2.3 服务名与注入

服务名固定为 `file-processing`（文法见 [01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) §5.1），官方实现由平台内置服务插件提供；同一作用域内服务名唯一，不得并存第二实现，替换实现须经平台评审。

主进程消费方经模块声明合并补充类型（[02-SDK-API规范](./02-SDK-API规范.md) §2.4）：

```typescript
import type { IFileProcessingService } from 'chips.service.file-processing/contracts';

declare module '@chips/sdk' {
  interface Context {
    readonly fileProcessing: IFileProcessingService;
  }
}
```

- 消费方必须在 manifest `dependencies` 中声明对提供方插件的依赖；提供方未激活时不注入，调用点按 `FILE_PROCESS_PROVIDER_MISSING` 处理。
- 会话随消费方 Fork 释放自动关闭；服务代际切换（插件更新）时会话不迁移，在途操作按取消收口（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §6.2）。
- 渲染进程（应用 UI）不直接持有本服务：UI 一律经应用主逻辑（应用自有通道）或平台能力处理文件，禁止为绕过而新增 Bridge 能力。

### 2.4 职责边界

| 边界 | 规则 |
|---|---|
| 与 `document:*` | `.card` / `.box` 的打开、读取、写入、保存、导出、另存（两态转换）只经 `document:*`；本契约的预览与另存不适用于文档；文档包装可作为**转换来源**，但提供方必须经 `document:*` 与平台渲染链路消费内容，禁止自行解包、解析或渲染 |
| 与资源管理器 | 一切字节访问经句柄与受控提交；产物写出必须走受控提交（临时物 + 原子替换）；插件不接触真实路径，不调用 Neon / 文件系统接口 |
| 与内容处理服务 | 算法只存在于内容处理服务；文件处理服务按提供方契约静态依赖并编排；原子服务的登记、命名与描述符见 [04-能力契约规范](./04-能力契约规范.md) §八 |
| 与渲染链路 | 卡片与箱子转换所需渲染必须复用平台渲染链路与受控封面渲染接口；禁止第二渲染管线与离屏自建渲染栈 |
| 与编辑链路 | 普通文件的编辑会话、内存模型与撤销/重做不属本契约；编辑后写回由编辑链路按其契约处理 |
| 与默认处理器 | 打开意图路由与默认处理器治理不属本契约；会话请求必须携带已确定的来源引用 |
| 与文档版本历史 | 平台不提供文档版本历史与持久备份版本；版本对比由调用方对两个来源分别取受管引用后调用 `compare`（§3.10），本契约不提供版本解析入口 |

### 2.5 红线

1. 禁止新增 `file:*`（除已登记基础能力）、`file.session.*`、`convert*` 等 Bridge 能力或路由；内容处理不登记为平台能力。
2. 禁止解析文件内容（含 ZIP、YAML、Office 容器）或实现格式算法；解码、探测与转换只经内容处理服务。
3. 禁止直接读写文件、拼接绝对路径、调用 Node.js / Electron / 系统 API。
4. 禁止在目标路径旁自行创建临时物或绕过受控提交发布产物。
5. 禁止在 `.card` / `.box` 文档上旁路 `document:*`；禁止"模型旧 + 字节新"的混用读取。
6. 禁止用事件模拟请求-响应；进度、取消与结果一律经会话方法契约。
7. 禁止实现格式语义比较（Office / PDF / 结构化容器内容对比）：比较只做摘要、字节与文本行级运算，格式语义对比依赖内容处理服务的提取类原子能力（§3.10）。
8. 禁止引入文档版本历史与持久备份版本语义：`compare` 只比较调用方显式给出的两个来源。
