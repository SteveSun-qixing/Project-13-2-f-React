## 六、权限映射（R19 全表）

### 6.1 映射模型

- 能力通过 `permissions` 声明"执行该能力必须持有哪些权限"；manifest 的 `permissions` 是插件申请集合；Bridge 判定按"能力所需权限 ∩ 插件已授予快照"，逐项匹配（R3、[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 第 7.2 节）。
- 能力只声明**基础权限 ID**（`<domain>:<scope>`）；限定值只存在于 manifest 申请与授权记录，判定时与实际调用目标（路径、域名、URL、窗口、命名空间）比对。
- 句柄访问（`resource:*`）与路径访问（`file:*`）分属两套权限；平台会话已授权的句柄在会话内读取免重复校验，写入仍需 `resources:write`。
- 路径限定必须使用目录变量（如 `${userDocuments}`），不得写裸绝对路径。

### 6.2 内置能力与权限总表（R19，canonical）

| 能力 ID | 所需权限 ID |
|---|---|
| `file:read` / `file:list` / `file:watch` | `filesystem:read` |
| `file:write` / `file:mkdir` | `filesystem:write` |
| `file:delete` | `filesystem:delete` |
| `file:move` | `filesystem:write` |
| `file:copy` | `filesystem:read` + `filesystem:write` |
| `resource:read` | `resources:read` |
| `resource:write` | `resources:write` |
| `resource:open` | `resources:read`（目标 `uri` 所在作用域按限定值匹配） |
| `resource:list-handlers` | 无（只读槽位编目，不含资源内容、真实路径与用户数据；调用仍写审计） |
| `document:create` | `resources:write`（目标 `parent` 所在作用域按限定值匹配） |
| `document:open` / `document:read` | `resources:read` |
| `document:write` / `document:save` | `resources:write` |
| `document:export` | 源文档 `resources:read` + 目标路径 `filesystem:write`（目标路径按限定值匹配；导出不修改源文档） |
| `window:create` / `window:list` / `window:focus` / `window:close` / `window:resize` / `window:move` / `window:setTitle` / `window:setState` | `window:control` |
| `menu:set` | `menu:manage` |
| `tray:set` | `tray:manage` |
| `shortcut:register` / `shortcut:unregister` | `shortcut:manage` |
| `system:info` | `system:read` |
| `power:query` | `power:read` |
| `power:prevent-sleep` | `power:manage` |
| `transfer:download` / `transfer:cancel` | `transfer:manage` + 目标路径 `filesystem:write` + URL 逐跳 `network:http` |
| `notification:send` | `notifications:send` |
| `clipboard:read` / `clipboard:write` | `clipboard:access` |
| `dialog:open` / `dialog:save` | `dialogs:use` |
| `shell:openExternal` | `shell:external` |
| `http:request` | `network:http[:<domain>]` |
| `config:get` / `config:snapshot` | `config:read:<namespace>` |
| `config:set` / `config:reset` | `config:write:<namespace>` |
| `credential:get` / `credential:set` / `credential:delete` | `credential:manage` |
| `event:publish` | `events:publish` |
| `command:register` / `command:unregister` | `command:write` |
| `command:list` / `command:get` | `command:read` |
| `command:invoke` | `command:execute` |
| `cli:task-active` / `cli:task-get` / `cli:task-progress` / `cli:task-complete` / `cli:task-fail` | 无（空权限数组；按 owner 归属校验，插件只能读写自身任务） |

本表是能力 → 权限映射的唯一权威：

1. 任何能力 ID 与权限 ID 不得完全相同（R3）。
2. 表中 `:<...>` 与 `[:<...>]` 为限定值占位；能力声明使用基础形式（如 `config:get` 声明 `config:read`），限定值在授权记录中物化。
3. 本表是**内置能力**的登记清单：新增内置能力必须登记进本表（由本规范维护）；第三方 Bridge 能力按第九节登记规则登记，未登记 ID 一律不得注册、不得调用。
4. 权限词表以本表为准对齐：[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 第 4.1 节与 [02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 第 5.5 节的映射示例与本表不一致时，同 PR 修正为与本表一致。
5. 能力权限集合变更属于破坏性变更（第 5.5 节），必须走 RFC。
6. **内容处理服务能力不进入本表**：图像、音视频、Office 等格式算法能力不注册为 Bridge 能力，按第八节登记并由 `service` 插件以 Cordis 服务提供；本表的 60 项计数只统计 Bridge 内置能力。
7. **命令与 CLI 任务能力**：`command:*` 与 `cli:task-*` 属 Bridge 内置能力并进入本表；`cli:task-*` 五项声明空权限数组，按 owner 归属校验；命令域权限 `command:read` / `command:write` / `command:execute` 以 [13-命令系统契约](./13-命令系统契约.md) §6.1 为语义权威。

### 6.3 角色适用性

权限的角色适用性以 [08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 第 5.3 节等价规则执行：窗口类、菜单类、托盘类、快捷键类、对话框类、外部打开类与电源抑制权限的持有者必须是 `app`；`basecard` / `boxlayout` / `service` 不得申请或调用对应能力。`system:info`、`power:query`、`transfer:*` 对全部角色开放（仍按权限词表判定）。命令域中 `command:write` 的持有者必须是 `app`，`command:read` / `command:execute` 对全部角色开放；`cli:task-*` 仅 `app` 角色调用（空权限数组，按 owner 归属校验）。角色规则变化不改变本表映射。

### 6.4 范围外（不提供的能力）

以下事项**不登记为平台能力**，不得以任何未登记 ID 调用：

| 范围外事项 | 说明 |
|---|---|
| OAuth / 登录流程 | 由凭证能力（`credential:*`）与 `http:request` 组合实现，平台不提供登录能力，也不托管第三方授权回调 |
| 平台自动更新 | 属平台自身机制，不向插件暴露接口（插件更新经分发链路完成） |
| `web` 插件目标 | 插件运行目标只有平台定义的桌面/移动形态；`runtime.targets` 不含 `web`，不提供浏览器页面运行形态 |
| 内容处理（图像编解码与缩放、视频抽帧/转码、Office 转换、OCR 等） | 不登记为 Bridge 能力，不进入第 6.2 节全表；由 `service` 插件以 Cordis 服务提供，能力 ID、提供方与错误码族按第八节登记 |
