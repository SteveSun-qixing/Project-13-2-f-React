### 5.7 渲染状态与查看入口

| 接口 | 行为 |
|---|---|
| `GET /cards/:cardId/render-status` | 返回 `ICommunityCardRenderStatus`；客户端轮询直到 `ready` 或 `error`；轮询间隔不低于 1 秒，失败退避 |
| `GET /cards/:cardId/view` | `viewState = ready`：`302` 到查看缓存入口（公开内容为公开桶 / CDN 地址，私有内容为受控代理路径）；`pending` / `rendering`：`202` + `renderStatusUrl` + `Retry-After`；`error`：`409 COMMUNITY_CARD_RENDER_ERROR` |
| `GET /cards/:cardId/cover` | `viewState = ready`：`302` 到封面缓存入口；`pending` / `rendering`：`202` + `Retry-After` 的临时占位页；`error`：`302` 到默认封面（[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §7.6） |
| `GET /cards/:cardId/render-cache/:cacheVersion/*` | 私有卡片查看缓存的受控代理；必须支持 HTTP `Range` 与 `206 Partial Content`，供视频、音频类资源分段读取 |
| `GET /cards/:cardId/cover-cache/:cacheVersion/*` | 私有卡片封面缓存的受控代理；同样支持 `Range` |
| `GET /boxes/:boxId/view` | 只读箱子文档；无渲染队列与缓存状态 |

- `cacheVersion` 由服务端在生成时确定；客户端只能使用 `viewUrl` / 响应头返回的地址，不得自行构造缓存路径。
- 公开缓存入口必须保留 `Range` / `206` 行为；视频类内容缺少分段读取能力时不得发布缓存。
- 渲染产物模式（5.6）下 `viewState` 在 `complete` 成功时即为 `ready`，`render-status` 返回同一终态；服务端渲染模式下由 Worker 推进 `pending → rendering → ready / error`。
- 查看与封面入口、缓存受控代理返回 `Cache-Control: no-store`；轮询类接口同样不得被中间缓存缓存（6.4）。
- 卡片打开必须以 `open-view` 的 `viewState` 与 `viewUrl` 为准（4.5）；`status = ready` 不表示查看产物已生成。
