## 六、自定义事件发布

### 6.1 能力 `event:publish`

渲染进程发布事件的唯一入口是能力 `event:publish`（`bridge.request` 链路）；主进程插件经 `ctx.emit` 发布（见本节末段），不存在其它发布通道。

```typescript
interface IEventPublishInput {
  eventId: string;   // <domain>:<action>，域必须属于调用插件的命名空间（6.2）
  payload: unknown;  // 载荷；空载荷传 {}
}
```

| 项 | 契约 |
|---|---|
| 能力 ID | `event:publish` |
| 所需权限 | `events:publish`（见《[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md)》与基准能力权限总表） |
| 输入校验 | 按能力 schema 校验；完整 schema 见《[04-能力契约规范](./04-能力契约规范.md)》 |
| 输出 | 请求成功表示事件已发布到总线，不表示已被投递（至多一次，见第七节） |
| 发布者身份 | 由 Bridge 按调用会话绑定插件 ID，不取自输入 |
| 失败 | 保留域、越权命名空间或权限缺失返回 `EVENT_PUBLISH_DENIED`；载荷违规返回对应错误码（第八节） |

主进程插件经 `ctx.emit` 发布自有域事件，不经过 Bridge 权限判定，但内核仍校验命名空间归属与保留域。

### 6.2 命名空间约束

- 插件只能发布自有命名空间内的事件；命名空间规则与登记见 2.3。
- 保留域（2.2）一律不可发布。
- 插件自有域事件默认不跨进程；需要跨进程时先登记为标准事件。
- 跨插件协作优先使用服务或能力；确需事件通知时，事件 ID 与 payload 形态由发布方在其命名空间内自行维护，消费方按契约收窄。

### 6.3 发布示例

```typescript
// 主进程：插件发布自有域事件
import type { Context } from '@chips/sdk';

interface IEditorDirtyPayload {
  uri: string;
}

export function apply(ctx: Context): void {
  ctx.emit<IEditorDirtyPayload>('editor:dirty', {
    uri: 'chips-resource://card-7f3a/notes.yaml',
  });
}
```

```typescript
// 渲染进程：经 event:publish 能力发布（需 events:publish 权限）
await window.chips.request('event:publish', {
  eventId: 'editor:dirty',
  payload: {
    uri: 'chips-resource://card-7f3a/notes.yaml',
  },
});
```

### 6.4 禁止事项

| 反模式 | 正确做法 |
|---|---|
| 用事件模拟请求-响应并等待回执 | 使用 `bridge.request` 或 Cordis 服务 |
| 在 payload 中传输大体积数据（图片、文件、文档内容） | 传递资源句柄或 `chips-resource://` URI |
| 发布平台保留域事件 | 使用自有域，或按流程登记为标准事件 |
| 未登记事件期望跨进程投递 | 先登记为标准事件，再经 `event:publish` 发布 |
| 在 payload 中携带凭证或未脱敏用户数据 | 只传标识；凭证经凭证能力访问 |
| 依赖事件必达完成关键状态机 | 以能力请求或查询接口为准；事件只做通知 |
