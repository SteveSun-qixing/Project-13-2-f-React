## 三、认证与令牌

### 3.1 令牌模型

| 令牌 | 载体 | 有效期 | 保存位置 |
|---|---|---|---|
| `accessToken` | 请求头 `Authorization: Bearer <accessToken>` | 短时效，具体时长由服务端配置 | 仅内存；不得落盘、不得写入日志 |
| `refreshToken` | 浏览器：`HttpOnly` Cookie；非浏览器：请求体 / 响应体 | 长时效，服务端可吊销 | 浏览器由 Cookie 自动携带；桌面客户端保存到 Host 凭据 |

- 浏览器 Cookie 属性：`chips_refresh_token`、`HttpOnly`、`Path=/api/v1/auth`、HTTPS 下 `Secure`、`SameSite=Strict`；JavaScript 不可读。
- 非浏览器客户端（Host 渲染进程中的应用插件）无法读取 `HttpOnly` Cookie，登录 / 注册响应体同时返回 `refreshToken` 明文，由客户端安全保存并在刷新时经请求体提交。
- 令牌不得出现在 URL、查询串、对象键、恢复清单、预签名头与日志中。
- 服务端可轮换 `refreshToken`：轮换时刷新响应体返回新的 `refreshToken`，客户端必须原子替换旧值。

### 3.2 注册与登录

| 方法 | 路径 | 认证 | 说明 |
|---|---|---|---|
| POST | `/api/v1/auth/register` | 无 | 创建账号并直接建立会话 |
| POST | `/api/v1/auth/login` | 无 | 建立会话 |

`POST /api/v1/auth/register` 请求体：

```json
{
  "username": "alice",
  "email": "alice@example.com",
  "password": "用户口令",
  "displayName": "Alice"
}
```

- `username`：全小写字母、数字与连字符，3–32 字符，全站唯一。
- `password`：长度由服务端策略配置；只传输、不落日志。
- `displayName` 可缺省，缺省取 `username`。

`POST /api/v1/auth/login` 请求体：

```json
{
  "identifier": "alice@example.com",
  "password": "用户口令"
}
```

- `identifier` 接受邮箱或用户名。
- 连续失败触发账号锁定时返回 `COMMUNITY_AUTH_ACCOUNT_LOCKED`，锁定阈值与时长由服务端配置。

成功响应（两者一致，`201` / `200`）：

```json
{
  "data": {
    "user": {
      "id": "0b6f9c2e-6d5a-4a2f-9c1e-2f3a4b5c6d7e",
      "username": "alice",
      "displayName": "Alice",
      "bio": null,
      "avatarUrl": null,
      "role": "user",
      "createdAt": "2026-09-19T08:00:00.000Z"
    },
    "accessToken": "access-token",
    "refreshToken": "refresh-token"
  }
}
```

### 3.3 令牌刷新

`POST /api/v1/auth/refresh`，无 `Authorization` 要求：

- 浏览器：从 Cookie 读取 refresh token；
- 非浏览器：请求体提交 `{ "refreshToken": "refresh-token" }`。

响应口径：

| 情况 | 状态 | 响应 |
|---|---|---|
| 存在可恢复会话 | `200` | `{ "data": { "accessToken": "...", "refreshToken": "..." } }`；`refreshToken` 字段仅在轮换时出现 |
| 无 refresh token / 已失效 / 已吊销 / 用户不可用 | `204` | 无正文；表示“当前没有可恢复登录态”，不是错误 |

- `204` 时客户端必须清空内存 access token 与本地保存的 refresh token，进入未登录态。
- 刷新接口不区分“令牌不存在”“令牌已失效”“用户不可用”，一律返回 `204`，避免泄露会话状态；请求体本身格式错误（非法 JSON、字段类型错误）返回 `400 COMMUNITY_VALIDATION_ERROR`。

### 3.4 登出

`POST /api/v1/auth/logout`，认证可选：

- 有会话时吊销当前 refresh 会话并清除 Cookie；无会话时同样返回 `204`。
- 幂等：重复调用一律 `204`。
- 登出尽力而为，客户端不得因登出失败保留本地令牌；客户端必须自行删除本地凭据。

### 3.5 桌面客户端凭据保存

桌面客户端（含社区客户端应用插件）按以下规则保存令牌：

| 凭据 | 保存方式 | 说明 |
|---|---|---|
| `accessToken` | 内存 | 每次请求写入 `Authorization: Bearer`；进程退出即丢弃 |
| `refreshToken` | Host 凭据，`credential:set` / `credential:get` / `credential:delete`，凭据名 `community.refreshToken` | 经 `credential:*` 能力读写，需要 `credential:manage` 权限（[04-能力契约规范](./04-能力契约规范.md) §7.12） |

- 服务器地址保存为客户端配置项 `community.server.baseUrl`，默认 `https://www.chipscard.space`。
- 客户端不得把令牌写入卡片 / 箱子文件、工作区文件或日志。

### 3.6 401 自动刷新

客户端对受保护接口的 401 处理：

1. 收到 `COMMUNITY_AUTH_TOKEN_EXPIRED` / `COMMUNITY_AUTH_TOKEN_INVALID` 且本次请求未重试过：调用刷新接口一次；
2. 刷新成功：用新 access token 重放原请求；并发 401 必须在客户端合并为单次刷新（single-flight），其余请求等待结果后重放；
3. 刷新返回 `204` 或失败：清空内存令牌与 `community.refreshToken` 凭据，把 401 错误交给业务层；
4. 每个请求最多重放一次，禁止无限循环。

### 3.7 管理端鉴权

- `/admin/api/v1/*` 全部接口需要有效 access token 且账号 `role = "admin"`；否则 `401`（未认证）或 `403 COMMUNITY_AUTH_INSUFFICIENT_PERMISSION`。
- 管理端会话与前台会话共用同一令牌模型与刷新链路。
