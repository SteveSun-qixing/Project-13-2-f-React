# 核心接口规范

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：Rust 核心（`chips-core` / `chips-cordis` / `chips-bridge` / `chips-parser` / `chips-resource`）的公开类型、方法与语义，以及 Neon 绑定约定、错误映射、线程约束与版本 ABI 边界

## 二、crate 划分与公开面

### 2.1 crate 与职责

| crate | 职责 | 主要公开类型 |
|---|---|---|
| `chips-core` | 公共类型、标识别名、错误模型、取消令牌、版本常量 | `ChipsError`、`CancelToken`、`PluginId` 等别名 |
| `chips-cordis` | Cordis 运行时（Context / Fork / Kernel / 事件总线） | `Context`、`Fork`、`Kernel`、`PluginRunner` |
| `chips-bridge` | Bridge 内核（注册表、权限判定、Schema 校验、路由） | `Bridge`、`CapabilityRegistration`、`CapabilityExecutor` |
| `chips-parser` | `.card` / `.box` 解析 | `CardParser`、`BoxParser`、`DocumentHandle`、`ParseOptions` |
| `chips-resource` | 资源管理（Resolver、Provider、句柄、缓存） | `ResourceManager`、`ResourceProvider`、`ScopeRegistration` |
| `chips-native` | Neon 绑定（`cdylib`） | 全部 JS 导出函数；不定义业务类型 |
| `chips-sync` | 同步引擎 Rust 核心原语（摘要 / 分块 / 变更索引 / 离线队列）；仅由 `sync` Cordis 服务包装消费 | `Digest`、`plan_chunks`、`ChangeIndex`、`OfflineQueue` |

依赖方向：子系统 crate 只依赖 `chips-core`；`chips-native` 组合全部子系统；`chips-sync` 只依赖 `chips-core` 与 `chips-resource`（经资源管理器读写，不直接触碰文件系统）；禁止反向依赖与循环依赖（[代码组织规范](../02-开发规范/01-代码组织规范.md) §4）。

### 2.2 公开面规则

1. 只有 `chips-native` 向 JS 导出；其余 crate 的 `pub` 面只在 Rust workspace 内使用。
2. 公开类型必须 `Send + Sync`，或为 `Clone` 句柄且内部同步（`Arc`、写时复制快照）。
3. 公开函数不得在持锁状态下 `await`、调用插件代码或执行阻塞 IO（[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) §10.3）。
4. 公开 API 必须带文档注释，示例禁止 `unwrap()`；生产代码禁止 `unwrap()` / `panic!`（[Rust 编码规范](../02-开发规范/04-Rust编码规范.md) §十六）。
5. 绑定层只做类型转换与错误映射，业务逻辑全部位于子系统 crate。

### 2.3 命名与序列化约定

| 位置 | 规则 | 示例 |
|---|---|---|
| Rust 类型 / 方法 | PascalCase / snake_case | `DocumentHandle::read_resource` |
| Neon 导出函数 | camelCase，按域加前缀 | `documentReadResource`、`resourceOpen` |
| JS 对象字段 | camelCase | `capabilityId`、`mimeType` |
| JS 时间 | 文档域用 RFC 3339 UTC 字符串；时长与 ID 用 number | `2026-09-19T10:00:00Z` |
| JS 字节 | `Buffer`（Node 侧）/ `Uint8Array`（渲染侧） | 资源字节 |
| 句柄 | JS 侧不透明，无字段、不可序列化 | `handle` |

### 2.4 同步引擎核心原语（chips-sync）

同步引擎的原语层在 Rust 核心，由内核中的 `sync` Cordis 服务包装后经 `ctx.sync` 提供给插件（[07-同步引擎设计](../01-架构设计/01-子系统设计/07-同步引擎设计.md) §9.1）；插件不直接引用本节的 Rust 类型，SDK 也不导出它们。

```rust
/// 文档或块的 SHA-256 摘要；规范序列化见 07-同步引擎设计 §3.2。
pub struct Digest([u8; 32]);

/// 摘要单条字节序列。
pub fn digest_bytes(bytes: &[u8]) -> Digest;

/// 内容定义分块（CDC）计划；参数与边界见 07-同步引擎设计 §4.1。
pub struct ChunkPlan {
    pub chunks: Vec<ChunkSpan>,          // 偏移 + 长度，按偏移升序
    pub chunk_digests: Vec<Digest>,      // 与 chunks 一一对应
}

/// 为指定长度生成分块计划；< 4 MiB 返回单块。
pub fn plan_chunks(size: u64) -> ChunkPlan;

/// 本地变更索引：文档身份、摘要、版本向量、水位与状态。
pub struct ChangeIndex {
    /* 存储与重建规则见 07-同步引擎设计 §3.1 */
}

impl ChangeIndex {
    pub fn open(path: &Path) -> Result<Self, ChipsError>;
    pub fn upsert(&self, record: &IndexRecord) -> Result<(), ChipsError>;
    pub fn get(&self, document_id: &str) -> Result<Option<IndexRecord>, ChipsError>;
    pub fn by_scope(&self, scope_id: &str) -> Result<Vec<IndexRecord>, ChipsError>;
    pub fn remove(&self, document_id: &str) -> Result<(), ChipsError>;
}

/// 离线队列：追加日志 + 压缩，重启、崩溃与插件卸载后不丢失。
pub struct OfflineQueue {
    /* 持久化与消费规则见 07-同步引擎设计 §7.3 */
}

impl OfflineQueue {
    pub fn open(path: &Path) -> Result<Self, ChipsError>;
    pub fn enqueue(&self, entry: QueueEntry) -> Result<(), ChipsError>;
    pub fn peek(&self, limit: usize) -> Result<Vec<QueueEntry>, ChipsError>;
    pub fn ack(&self, seq: u64) -> Result<(), ChipsError>;
    pub fn freeze(&self) -> Result<(), ChipsError>;
}
```

规则：

1. 原语不做权限判定与审计：文档与资源读写分别经文档服务受控写链路与资源管理器；平台数据目录内的索引与队列持久化由核心自身完成（不属于用户文档范围）；网络访问仍经 `http:request` 能力（[07-同步引擎设计](../01-架构设计/01-子系统设计/07-同步引擎设计.md) §八）。
2. 原语不感知插件与远端；提供者、范围、会话状态机位于 `sync` 服务层。
3. 同步引擎整体可选：未启用时原语不初始化、不产生副作用（[07-同步引擎设计](../01-架构设计/01-子系统设计/07-同步引擎设计.md) §1）。
4. 原语为平台内部接口，不属于 ABI（第 9.2 节），不得出现在 `chips-native` 的 Neon 导出面。
