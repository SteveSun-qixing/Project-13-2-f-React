## 九、类型导入路径

### 9.1 允许与禁止

```typescript
// ✅ 插件运行时代码：只从主入口导入
import { chips, ChipsError } from '@chips/sdk';
import type { IBaseCardPlugin, ISubscription } from '@chips/sdk';

// ✅ 测试代码：从 testing 入口导入
import { createMockBridge } from '@chips/sdk/testing';

// ✅ 工具链（仅 @chips/cli）：从 scaffold 入口导入
import { createScaffoldPlan } from '@chips/sdk/scaffold';
```

```typescript
// ❌ 全部禁止
import type { IChipsBridge } from '@chips/bridge';        // 插件不得绕过 SDK
import { createMockBridge } from '@chips/sdk/dist/testing'; // 穿透构建产物
import { chips } from '../../packages/sdk/src';            // 相对路径穿透包边界
import { createMockBridge } from '@chips/sdk';             // 测试工具不得从主入口取
```

规则：

- 插件对 `@chips/*` 的依赖只允许 `@chips/ui` 与 `@chips/sdk`（依赖矩阵见 [代码组织规范](../02-开发规范/01-代码组织规范.md)第 4.2 节）。
- 仅使用类型的导入必须写 `import type`，避免产生运行时依赖与循环。
- 跨包导入只允许包名与 `exports` 声明的子路径；禁止相对路径穿透、禁止引用 `src/` 与 `dist/` 内部文件。
- SDK 不得依赖 `@chips/ui`、`@chips/host` 与任何运行时实现；对 `@chips/bridge` 仅 `import type`。

### 9.2 全局声明

- SDK 主入口附带 `Window.chips` 全局声明，形状为 `readonly chips: IChipsBridge`。
- 插件不得重复声明 `Window.chips`，也不得为 `Window` 添加其他平台对象。
- 需要显式传递 Bridge 目标时，参数类型使用 `IChipsBridge`；禁止使用 `typeof window.chips` 之类的隐式类型。
