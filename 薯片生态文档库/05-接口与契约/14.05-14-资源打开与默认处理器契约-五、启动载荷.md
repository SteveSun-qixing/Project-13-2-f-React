# 资源打开与默认处理器契约

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：资源打开路由的权威契约：打开来源与打开请求模型、manifest 处理器声明与 `primary` / `fallback` 层级、路由解析顺序与投递授权、启动载荷 `resourceOpen` 与业务载荷约定、默认处理器偏好 `platform.fileOpen.defaults` 与槽位治理接口、未安装/停用/卸载的降级与回收、与文档/条目/封面链路的关系；资源 URI 语法、句柄与权限判定本身不在此定义。

## 五、启动载荷

### 5.1 启动参数扩展

资源打开来源下，目标应用实例的启动参数是 `IAppLaunchArgs` 的资源打开扩展；基础字段、来源不变量与投递语义由 [07-应用插件接口](./07-应用插件接口.md) §4.3、§6.2 定义，本契约定义扩展成员：

```typescript
import type { IAppLaunchArgs } from '@chips/sdk';

/** 资源打开上下文。 */
export interface IResourceOpenContext {
  /** 打开意图。 */
  readonly intent: OpenIntent;
  /** 打开来源。 */
  readonly origin: OpenOrigin;
  /** 主资源受管引用；与 args.files[0] 同值。 */
  readonly uri: string;
  /** 归一后的 MIME。 */
  readonly mimeType: string;
  /** 含点小写扩展名；无法判定时缺席。 */
  readonly extension?: string;
  /** 展示用文件名（含扩展名）；无法判定时缺席。 */
  readonly fileName?: string;
  /** 展示用标题；调用方未提供时缺席。 */
  readonly title?: string;
  /** 命中槽位键（mime:<mime> / ext:<ext>）。 */
  readonly slot: string;
  /** 发起方业务上下文；平台原样透传，不解释。 */
  readonly payload?: Readonly<Record<string, unknown>>;
}

/** 资源打开来源下的启动参数。 */
export interface IResourceOpenLaunchArgs extends IAppLaunchArgs {
  readonly source: 'file-association';
  /** 资源打开上下文。 */
  readonly resourceOpen: IResourceOpenContext;
}
```

规则：

- `source` 固定 `file-association`：取 [07-应用插件接口](./07-应用插件接口.md) §5.4 的动作语义「以打开方式接收文件」，不区分触发来自系统关联、拖放、应用内转交还是帧内点击；来源差异由 `resourceOpen.origin` 表达。
- `files` 为受管引用数组；资源打开场景下与 `resourceOpen.uri` 一致，长度为一（多文件按 §2.1 逐次路由）。
- 应用在 `launch` 中读取 `ctx.args`；存在 `resourceOpen` 时按 `IResourceOpenLaunchArgs` 收窄并消费。运行中到达的投递不再进入 `launch`（[07-应用插件接口](./07-应用插件接口.md) §6.2），上下文经 §5.5 投递。
- 启动载荷不携带真实路径：旧版 `targetPath` 已废弃（§2.4）；需要字节时经 `ctx.bridge.resource(uri)` 获取句柄，跨作用域读取由投递授权覆盖（§4.4）。

### 5.2 `resourceOpen` 上下文

- `uri` 是所有场景下唯一的读取入口；`payload` 内的资源引用是补充上下文，接收方不得只依赖 payload 内引用读取主资源。
- `mimeType`、`extension`、`fileName`、`title` 是展示与恢复上下文；缺失时接收方按自身能力与资源元数据补全，不得因缺失拒绝打开。
- `slot` 用于诊断与「本次由哪条声明命中」的记录，应用不得据此改变行为。
- 相对路径归一由平台完成：payload 内可能含发起方视角的 `relativePath`，它只用于日志与展示，不用于读取。

### 5.3 业务载荷约定

1. **标识**：payload 顶层必须有 `kind`（命名空间化标识）与 `version`（语义化版本）；标准载荷使用 `chips.` 前缀，插件自定义载荷使用该插件自有域前缀。
2. **透传**：平台不解释、不裁剪、不重写 payload 的业务字段，只做结构化克隆与体积校验（§2.2）。
3. **版本**：版本遵循语义化版本；消费方按 `version` 主版本判定兼容，不兼容时忽略 payload、仍按主资源打开。
4. **未知载荷**：消费方遇到未知 `kind` 时忽略 payload 并按主资源处理；payload 是可选增强，不是打开的必要条件。
5. **资源引用**：payload 内的 `resources.*` 引用进入投递授权清单（§4.4）；发起方必须保证清单内引用为受管引用。

### 5.4 标准业务载荷

标准载荷登记如下；卡片类型与配置字段以 [01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) 为权威，本节登记 payload 形状。

```typescript
/** 标准载荷信封。 */
export interface IResourceOpenPayloadEnvelope {
  readonly kind: string;
  readonly version: string;
  /** 发起打开的基础卡片类型正式标识。 */
  readonly cardType: string;
}

/** 载荷内的资源引用。 */
export interface IResourceOpenRef {
  /** 受管引用。 */
  readonly uri: string;
  /** 发起方视角的卡片包内相对路径；仅用于日志与展示。 */
  readonly relativePath: string;
  readonly fileName?: string;
  readonly mimeType?: string;
}
```

音乐基础卡片（`base.music`，配置见 [01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §6.8）：

```typescript
export interface MusicCardOpenPayload extends IResourceOpenPayloadEnvelope {
  readonly kind: 'chips.music-card';
  readonly cardType: 'base.music';
  readonly resources: {
    /** 主音频资源；与顶层 resourceOpen.uri 指向同一资源。 */
    readonly audio: IResourceOpenRef;
    readonly cover?: IResourceOpenRef;
    readonly lyrics?: IResourceOpenRef;
  };
  readonly display: {
    readonly title: string;
    readonly artist?: string;
  };
}
```

视频基础卡片（`base.video`，配置见 [01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §6.2）：

```typescript
export interface VideoSubtitleRef extends IResourceOpenRef {
  readonly id: string;
  readonly label?: string;
  readonly language?: string;
  readonly kind: 'subtitles' | 'captions';
  readonly default: boolean;
}

export interface VideoCardOpenPayload extends IResourceOpenPayloadEnvelope {
  readonly kind: 'chips.video-card';
  readonly cardType: 'base.video';
  readonly resources: {
    /** 主视频资源；与顶层 resourceOpen.uri 指向同一资源。 */
    readonly video: IResourceOpenRef;
    readonly cover?: IResourceOpenRef;
    readonly subtitles?: readonly VideoSubtitleRef[];
  };
  readonly display: {
    readonly title: string;
    readonly creator?: string;
    readonly publishTime?: string;
  };
  readonly playback: {
    readonly autoplay: boolean;
    readonly loop: boolean;
    readonly muted: boolean;
    readonly playbackRate: number;
    readonly startTime: number;
  };
}
```

电子书基础卡片（`base.book` 类型；类型标识经 [01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §6.10 的插件定义机制发布）：

```typescript
export interface BookCardOpenPayload extends IResourceOpenPayloadEnvelope {
  readonly kind: 'chips.book-card';
  readonly cardType: 'base.book';
  readonly mode: 'ebook' | 'image-sequence';
  readonly resources: {
    readonly book?: IResourceOpenRef;
    readonly images?: readonly IResourceOpenRef[];
  };
  readonly display: {
    readonly title: string;
    readonly author?: string;
  };
}
```

消费规则：

- `mode: 'ebook'`：阅读器以顶层 `resourceOpen.uri` 为读取入口，用 `resources.book` 与 `display` 恢复书籍上下文。
- `mode: 'image-sequence'`：图片队列按 `resources.images[]` 顺序建立；主资源必须是序列首项，顶层 `resourceOpen.uri` 指向该项。
- 文件基础卡片（`base.file`）不传 payload：以无业务载荷的主资源表达纯打开意图（[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §6.9）。
- 卡片点击行为：音乐卡片点击音频、视频卡片点击视频、文件卡片点击整卡、图片点击等，一律把对应资源经资源打开路由表达为打开意图；基础卡片不得硬编码目标插件、不得绕过路由。

### 5.5 运行中投递：`resource:opened`

已运行实例接收带上下文的打开投递时，平台在调用 `openFile(uri)` 之前发布标准事件 `resource:opened`：

```typescript
/** resource:opened 事件 payload。 */
export interface IResourceOpenedPayload {
  readonly pluginId: string;
  readonly context: IResourceOpenContext;
}
```

规则：

- 触发时机：命中处理器的实例已进入 `active`、平台准备投递 `openFile` 之前；`context.uri` 与随后 `openFile` 的 `uri` 同值，顺序固定为「事件先到、`openFile` 后到」。
- 可见性：定向投递给该插件实例（主逻辑经 `ctx.on`，UI 经 `chips.subscribe`）；其他插件不接收。
- 幂等与失败：事件是通知，不承担请求-响应；未订阅、订阅失败或处理抛错不阻断 `openFile` 投递。
- 新建实例不使用该事件：初始上下文随 `ctx.args.resourceOpen` 送达（§5.1），同一意图只投递一次（[07-应用插件接口](./07-应用插件接口.md) §6.2）。
- 事件信封、约束与投递保证以 [05-事件契约规范](./05-事件契约规范.md) 为准。
