# 卡片传输协议

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：`.card` / `.box` 在本地设备与内容服务器之间传输的权威协议：传输会话（创建、预签名、分片、断点续传、取消、恢复）、完整离线卡片与网络资源卡片的可逆改写与还原（含可逆恢复清单）、摘要与完整性校验、预签名与对象存储桶角色、传输队列与 `transfer:*` 事件映射、错误码与安全约束；不覆盖卡片/箱子的包结构语义、渲染链路与服务器产品设计。

## 四、本地↔网络资源卡片改写与还原

### 4.1 改写职责与边界

- 上传改写与下载还原由传输引擎统一执行；插件、基础卡片插件与查看器不得自行替换 YAML 或 HTML 中的资源字段（[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §2.3）。
- 改写必须确定性：相同输入产生相同输出；同一资源的引用在所有出现位置得到同一 URL。
- 改写只改变资源引用形态，不改变字段语义、卡片结构、`card_id` 与卡片格式版本。
- 改写后的网络资源卡片不再包含任何资源字节；资源文件从网络资源卡片归档中移除。

### 4.2 资源枚举与引用判定

资源枚举（上传前，对解包后的卡片目录执行）：

1. 枚举包内全部文件条目，相对路径规范化（`/` 分隔、NFC、无 `..`、无前导 `/`）；
2. 排除结构性文件（不进入资源对象）：`.card/metadata.yaml`、`.card/structure.yaml`、`.card/cover.html`、`content/*.yaml`；
3. 排除目录条目与系统生成物（`__MACOSX/`、`.DS_Store`、`Thumbs.db`、`desktop.ini` 及其他隐藏条目）；
4. 其余文件全部作为资源对象；`.card/cardcover/` 下的封面资源、网页目录、富文本 `.md`、嵌套 `.card` 等一律按资源处理；
5. 资源相对路径在包内必须唯一；重复路径按归档非法处理（`CARD_TRANSFER_INVALID_INPUT`）。

引用判定（对 `content/*.yaml` 的字符串值与 `.card/cover.html` 的引用值执行）：

- 外部引用不改写：以 `scheme:`（如 `http:` / `https:` / `webdav:` / `data:`）、`//` 或 `#` 开头的值一律视为外部引用；
- 后缀保留：引用中的 `?query` 与 `#fragment` 与路径分离，改写/还原后原样拼回；
- 候选路径：对包内引用按两种候选解析，任一命中资源映射即改写：
  1. 规范化后的卡片根相对路径；
  2. 相对引用所在文件目录的路径（如 `.card/cover.html` 中的 `./cardcover/x.png` → `.card/cardcover/x.png`）。

### 4.3 改写规则

| 位置 | 规则 |
|---|---|
| `content/*.yaml` 一般字符串值 | 命中资源映射的引用整体替换为对应对象的 URL，保留后缀；未命中保持不变 |
| `content/*.yaml` 结构化资源字段 | `source: file` 且 `file_path` 命中映射时，改写为 `source: url` 加 `url: <URL>`；移除 `file_path`；其余字段按一般字符串规则处理 |
| 富文本卡片（`base.richtext`）文件化正文 | `content_source: file` 且 `content_file` 命中文本资源时，改写为 `content_source: inline` 加 `content_text: <Markdown 原文>`；移除 `content_file`；原 `.md` 文件仍作为资源对象上传，并把 `{ configPath, contentFile }` 写入恢复清单 `richTextContentFiles` |
| `.card/cover.html` | 替换全部 `="…"` 属性值与 `url(…)` 内的包内引用为 URL，保留引号与后缀；其余 HTML 字节不改 |
| `.card/metadata.yaml`、`.card/structure.yaml` | 不改写；`structure.yaml` 的 `manifest.resources` 路径与校验值原样保留（[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §5.3、§2.5） |
| 归档打包 | 移除资源文件后按发布侧 ZIP Store 重建网络资源卡片（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §2.3） |

- YAML 改写为"解析 → 改写 → 重新序列化"，允许注释、空行、键序与引号风格的格式化归一，但不得改变字段语义与资源路径（与[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §2.4 的验收口径一致）。
- 改写只处理文本文件；二进制资源不改写，直接上传。
- 改写失败（YAML 无法解析、资源缺失、路径非法）必须中止上传并整体失败（`CARD_TRANSFER_RESTORE_FAILED` 对应的上传侧为 `CARD_TRANSFER_UPLOAD_FAILED`，`details.reason` 给出具体项），不得提交半个网络资源卡片。

### 4.4 可逆恢复清单

恢复清单是上传结果的组成部分，由传输引擎生成并随 `complete` 提交，由服务器随卡片版本持久化；下载计划原样返回。清单不得写入卡片包内，不得包含预签名地址与服务器凭证。

```json
{
  "schemaVersion": "1.0.0",
  "originalFileName": "demo.card",
  "cardId": "1a2b3c4d-5e6f-4a8b-9c0d-2e3f4a5b6c7d",
  "versionId": "6f7c1d2e-8a4b-4c5d-9e0f-1a2b3c4d5e6f",
  "resources": [
    {
      "originalRelativePath": "video.mp4",
      "networkUrl": "https://file.example/chips-card-resources/cards/{cardId}/versions/{versionId}/resources/video.mp4",
      "bucket": "chips-card-resources",
      "objectKey": "cards/{cardId}/versions/{versionId}/resources/video.mp4",
      "sizeBytes": 1048576,
      "mimeType": "video/mp4",
      "sha256": "b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2c3"
    }
  ],
  "zipEntries": [
    {
      "order": 0,
      "path": ".card/metadata.yaml",
      "size": 512,
      "compressedSize": 512,
      "crc32": 123456789,
      "isDirectory": false,
      "compressionMethod": 0,
      "modifiedTime": 1758268800000,
      "externalAttributes": 0,
      "comment": "",
      "extraFields": []
    }
  ],
  "richTextContentFiles": [
    { "configPath": "content/a1B2c3D4e5.yaml", "contentFile": "richtext/a1B2c3D4e5.md" }
  ]
}
```

字段语义：

| 字段 | 类型 | 必填 | 语义 |
|---|---|---|---|
| `schemaVersion` | string | 是 | 清单结构版本，当前 `1.0.0` |
| `originalFileName` | string | 是 | 上传前源文件名（含扩展名），用于建议输出文件名 |
| `cardId` | string | 是 | 卡片稳定标识（`metadata.yaml` 的 `card_id`） |
| `versionId` | string | 是 | 本次上传的版本标识（= 会话 `versionId`） |
| `resources[]` | array | 是 | 上传过的全部资源对象；每项含 `originalRelativePath`、`networkUrl`、`bucket`、`objectKey`、`sizeBytes`、`mimeType`、`sha256` |
| `zipEntries[]` | array | 是 | 原始归档条目快照：`order`（从 0 起的原始顺序）、`path`、`size`、`compressedSize`、`crc32`、`isDirectory`、`compressionMethod`、`modifiedTime`（Unix 毫秒，UTC）；`externalAttributes` / `comment` / `extraFields` 可选，缺省时还原按平台默认重建 |
| `richTextContentFiles[]` | array | 是 | 富文本内联还原映射：`configPath`（`content/*.yaml`）与 `contentFile`（原始 `.md` 相对路径）；无内联时为 `[]` |

- 本节是恢复清单线上 schema 的权威；[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §2.3 规定的是清单必须表达的最小语义，二者为"语义要求 + 线上结构"的关系。
- 可验证替换规则：`resources[].originalRelativePath ↔ networkUrl` 映射加 4.2/4.3 的确定性规则，即构成"每个配置文件中发生过的路径替换位置或可验证替换规则"；还原不需要逐处记录替换位置。
- 封面替换关系由同一规则覆盖：`.card/cover.html` 的引用与 `.card/cardcover/*` 资源都在 `resources` 映射中。

### 4.5 还原流程

1. 获取下载计划，校验 `schemaVersion` 受支持、`restoreManifest` 存在且结构合法（4.4）；
2. 下载网络资源卡片到临时工作目录；
3. 解包网络资源卡片得到目录；
4. 建立 URL → 原始相对路径映射（`resources[].networkUrl → resources[].originalRelativePath`）与富文本映射（`richTextContentFiles`）；
5. 对 `content/*.yaml` 执行逆改写：
   - 一般字符串值命中 URL 映射时还原为原始相对路径并保留后缀；
   - `source: url` 且 `url` 命中映射时还原为 `source: file` 加 `file_path`；
   - 富文本 `content_source: inline` 且该配置在 `richTextContentFiles` 中有映射时还原为 `content_source: file` 加 `content_file`，并把 `content_text` 写回 `.md` 资源文件；
6. 对 `.card/cover.html` 执行逆改写：`="…"` 与 `url(…)` 中命中映射的 URL 还原为原始相对路径；
7. 下载全部资源对象到 `originalRelativePath` 指定位置；写入前先校验摘要（5.4）；
8. 按 `zipEntries` 的 `order` 与 `modifiedTime` 以 ZIP Store 重新打包为完整离线卡片（[11-文档服务设计](../01-架构设计/01-子系统设计/11-文档服务设计.md) §5.4）；
9. 清理临时工作副本、`.part` 文件与检查点；失败时删除未完成的输出文件。

还原规则：

- 还原只接受计划与恢复清单中的映射；未命中的 URL 原样保留，不得猜测或按模式改写。
- `modifiedTime` 缺省的条目使用平台默认时间；重打包不得压缩（Store）、不得产生 ZIP64。
- 还原过程不修改服务器上的网络资源卡片与资源对象。

### 4.6 完整恢复验收

下载得到的完整离线卡片验收标准以[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §2.4 为唯一权威（路径一致、字段语义与资源引用一致、资源字节一致、ZIP 条目顺序与修改时间一致、Store 一致、封面恢复一致、可被平台打开与继续编辑）。协议附加要求：

- 每个资源对象与网络资源卡片在写入前通过 `sha256` 校验（5.4）；
- 还原后的卡片通过平台正式解析与打开校验（`DOCUMENT_*` 错误即视为还原失败）；
- 校验失败时输出 `CARD_TRANSFER_VERIFY_FAILED`，删除输出并保留诊断（不含真实路径与凭证）。

### 4.7 箱子上传的改写边界

- 箱子包内容不改写：`structure.yaml`、内嵌 `.card`、`assets/` 与箱内其他资源按原字节上传；不得把条目 URL 改写为社区地址。
- 散落卡片（`file://` 条目）按本文完整卡片链路处理：先按 4.2–4.4 改写为网络资源卡片并上传，再把卡片上传结果登记到该箱子的 `uploadedCards`。
- 箱子封面使用 `cover-file` 角色：对象键为 `boxes/{boxId}/cover/{relativePath}`，桶为通用封面桶；封面 MIME 由提交方给出。
- 内嵌条目与网络条目在 `skippedCards` 中登记跳过原因，不做任何改写或上传。
