## 八、Neon 绑定约定

### 8.1 模块入口与导出

```rust
use neon::prelude::*;

#[neon::main]
fn main(mut cx: ModuleContext) -> NeonResult<()> {
    cx.export_function("coreVersion", core_version)?;
    cx.export_function("coreAbiVersion", core_abi_version)?;
    cx.export_function("openCard", js_open_card)?;
    cx.export_function("bridgeRequest", js_bridge_request)?;
    // 其余导出见 8.6 节总表，集中在此声明。
    Ok(())
}
```

- `#[neon::main]` 是原生模块唯一入口；导出表在入口函数中集中声明，不允许散落注册。
- 导出函数统一签名 `fn js_xxx(mut cx: FunctionContext) -> JsResult<...>`；`FunctionContext` 只在当前调用内有效，禁止存储或跨线程传递。
- 同步导出只做类型转换与内存操作；任何可能阻塞的导出必须返回 `JsPromise`（见 8.3 节）。
- `chips-native` 不实现业务逻辑，全部转发子系统 crate；禁止在绑定层 `unwrap()` / `expect()` / `panic!()`。

### 8.2 类型映射

| Rust | Neon / JS | 规则 |
|---|---|---|
| `String`、`&str` | `string` | UTF-8；非法 UTF-16 代理对拒绝 |
| `bool`、`u8`–`u32`、`i8`–`i32` | `number` | 整数范围严格 |
| `u64` | `number` | 仅当 `< 2^53`；ID 与尺寸受该约束 |
| `f64` | `number` | 拒绝 `NaN` / `Infinity` |
| `Vec<u8>` / `&[u8]` | `Buffer`（`JsBuffer`） | Rust → JS 复制一次进 `JsBuffer`；JS → Rust 经 `borrow` 读取 |
| `Option<T>` | `T \| undefined` | 可选字段缺省一律 `undefined`，不写 `null` |
| `Vec<T>` | `Array` | 元素按本表递归映射 |
| `serde_json::Value` | 普通对象 / 数组 / 标量 | 必须结构化克隆兼容 |
| DTO 结构体 | 普通对象（无原型方法） | 字段 camelCase；时间按 2.3 节规则 |
| `JsBox<T>` | 不透明句柄 | `T: Finalize`；JS 侧无字段、不可序列化 |
| `Root<T>` | 无 JS 对应 | `Send + Sync`，但只能在创建它的 JS 线程取值 |
| `JsPromise` | `Promise` | `!Send`、`!Sync`，不跨线程 |
| `Channel` | 无 JS 对应 | `Send + Sync`；跨线程回投 JS 的唯一入口 |

规则：

- 绑定层提供 `json_to_js` / `js_to_json` 辅助函数完成 `serde_json::Value` 与 JS 值的双向转换；DTO 优先经 `serde_json::Value` 中转，避免逐字段手写。
- 本表拒绝路径（不可传输类型、越界整数、非有限数、非法 UTF-16）产生的错误码只有 `NATIVE_*` 三个，逐项登记见 3.3 节绑定层码段表。
- 传输值禁止函数、类实例、`Symbol`、DOM 对象、`Error` 实例；错误统一为 `ChipsError` 同构普通对象。
- `JsBuffer` 不用于长生命周期数据：字节读取结果复制一次交付调用方，Rust 侧不保留指针。

### 8.3 异步、Channel 与线程约束

异步导出统一模式：JS 线程发起调用 → Rust 提交到线程池或专用线程 → 完成后经 `Channel` 回投 JS 线程并 settle `JsPromise`。

```rust
fn js_open_card(mut cx: FunctionContext) -> JsResult<JsPromise> {
    let path = cx.argument::<JsString>(0)?;
    let path = path.value(&mut cx);
    let channel = cx.channel();
    let (deferred, promise) = cx.promise();

    std::thread::spawn(move || {
        let result = CardParser::new(ParseOptions::default()).open(Path::new(&path));

        deferred.settle_with(&channel, move |mut cx| match result {
            Ok(handle) => Ok(cx.boxed(handle).upcast()),
            Err(error) => throw_chips_error(&mut cx, ChipsError::from(error)),
        });
    });

    Ok(promise)
}
```

线程约束（强制）：

1. JS 值具有线程亲和性：`Handle`、`JsBox` 借出引用、`JsPromise`、`FunctionContext` 只在 JS 线程使用，禁止跨线程存储或传递。
2. 可跨线程的类型仅限 `Root<T>`、`Channel`、`Deferred`、`JoinHandle`；`Root<T>` 只能在创建它的 JS 线程 `to_inner` / `into_inner`（在其它 JS 线程取值会 panic），未取回值的 `Root` 掉落会触发泄漏告警。
3. 异步任务完成后必须经 `Channel` 回到 JS 线程再操作 JS 值；禁止在 Rust 工作线程直接 settle 或调用 JS。
4. 禁止在 JS 线程同步等待 Rust 结果（不得 `block_on`）；JS 侧等待一律经 `JsPromise`。
5. 禁止在持内核锁或资源锁时 `await`、执行阻塞调用或调用插件代码（[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) §10.3）。
6. 阻塞 IO 与 CPU 密集工作（解析、解压、图像处理、网络）必须离开 JS 线程与内核命令循环执行。
7. Rust 等待 JS 异步结果时使用 `JsPromise::to_future` 或等价回投；二者都不得阻塞 JS 线程。
8. `Deferred` 必须 settle：N-API 6 以下掉落未 settle 的 `Deferred` 会 panic，N-API 6 及以上自动拒绝该 Promise。

### 8.4 句柄与生命周期

- 长生命周期 Rust 对象（`DocumentHandle`、`Context`、`CancelToken`、解析取消令牌）以 `JsBox<T>` 暴露；`T: Finalize`。
- `Finalize` 在主 JS 线程、GC 回收前执行，只做释放与审计标记；不得阻塞、不得抛出异常、不得依赖其它 JS 对象。
- 显式释放优先：`documentClose`、`resourceRelease`、`resourceCloseSession` 必须由调用方在 `finally` 中执行；`Finalize` 只作兜底。
- Rust 需要长期持有 JS 值（能力处理器、监听回调、注入回调）时使用 `Root<T>`；释放时必须在 JS 线程调用 `Root::drop` / `into_inner`，不得依赖 `Drop` 时机。
- TS 插件注册的服务以 `Root<JsValue>` 存入内核服务表，只能在 JS 线程取出使用；Rust 服务以强类型值存入，供 Rust 消费者下转。类型不匹配时 `get_typed` 返回 `KERNEL_SERVICE_TYPE_MISMATCH`，不得尝试跨语言下转。

### 8.5 错误映射

- Rust `ChipsError` 映射为 JS `Error` 实例，并在其上附加自有属性 `code`、`message`、`details`、`retryable`；`message` 为简体中文，`details` 为普通对象。
- 映射后立即 `throw`；不得返回 `{ ok: false }` 之类的替代结构混入成功路径。
- Host 业务错误码原样透传；未识别异常归一为 `<DOMAIN>_INTERNAL`，`details` 不含堆栈与内部路径。
- 归一后的错误对象必须满足 `ChipsError` 同构形状，preload 只还原结构，不修改 `code` 与 `retryable`。
- 绑定层自造错误只使用 `NATIVE_*` 三个码（`NATIVE_TYPE_UNSUPPORTED`、`NATIVE_VALUE_OUT_OF_RANGE`、`NATIVE_INTERNAL`），触发条件、`message` 拼装、`details` 形状与 `retryable` 取值逐项登记于 3.3 节码段表；绑定层不得新增第四个 `NATIVE_*` 码（2026-09-20 工单006 收口登记）。
- JS 抛出的异常反向归一为 `ChipsError`：`code` 满足 `<DOMAIN>_<REASON>` 形状（全大写、数字与下划线、必含 `_`）时原样保留 `code` / `retryable` / `details`，`message` 缺省或为空时使用通用文案「插件执行失败」，`retryable` 缺省为 `false`；其余一律归一为 Bridge 通道级 `BRIDGE_INTERNAL`（见 5.2 节与 [02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 第 9.2 节），不回传堆栈与内部路径。
- `details` 跨边界时经 `json_to_js` 递归转换；转换自身失败即抛出转换错误（3.3 节码段表），不产出缺字段的部分对象。

```rust
use neon::prelude::*;

/// 把 `ChipsError` 抛出为携带 `code` / `details` / `retryable` 的 JS Error。
///
/// 返回类型泛化为 `V`：调用点可直接 `return throw_chips_error(...)`，
/// 也可用于返回非 JS 值的内部辅助函数（如参数解析）的错误路径。
pub fn throw_chips_error<'a, C: Context<'a>, V>(
    cx: &mut C,
    error: ChipsError,
) -> NeonResult<V> {
    let js_error = JsError::error(cx, error.message())?;

    let code = cx.string(error.code());
    js_error.set(cx, "code", code)?;

    let retryable = cx.boolean(error.retryable());
    js_error.set(cx, "retryable", retryable)?;

    if let Some(details) = error.details() {
        // json_to_js：绑定层的 `serde_json::Value` → JS 值辅助函数，见 8.2 节；
        // 第三参数为 details 子树的 JSON Pointer 根（`""`）。
        let details = json_to_js(cx, details, "")?;
        js_error.set(cx, "details", details)?;
    }

    cx.throw(js_error.upcast::<JsValue>())
}
```

- 导出分域，函数名以域前缀开头；同一语义在不同域不得复用同一函数名。

- 内核启动与插件管理的导出不属于本文范围，由插件管理层实现并以 `kernel` / `plugin` 前缀登记。

### 8.7 插件入口与适配层

内核通过 `PluginRunner` 调用插件代码；TS 插件由绑定层实现该 trait，并负责在 JS 线程构造 `ctx` 门面（[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) §6.1）：

```rust
#[async_trait]
pub trait PluginRunner: Send + Sync {
    /// 执行插件 apply；返回前副作用必须已登记到 `ctx` 对应 Fork。
    async fn apply(&self, ctx: &Context, config: &PluginConfig) -> Result<(), KernelError>;

    /// 插件停用回调；正常清理由 Fork 撤销负责。
    async fn stop(&self, ctx: &Context) -> Result<(), KernelError>;
}
```

适配约定：

1. `PluginRunner::apply` 的实现经 `Channel` 在 JS 线程调用插件入口函数，传入由 `JsBox<Context>` 封装的 `ctx` 与 `config`；插件入口的返回值（含 `Promise`）被 await 完成后再返回内核。
2. `ctx` 门面的方法一一映射到 4.5 节的导出函数；门面禁止暴露 `Context` 句柄本身、`ipcRenderer`、`process`、`require`。
3. 注入回调、事件监听与自定义清理均由绑定层以 `Root` 持有 JS 回调，在对应 Fork 撤销或依赖变化时经 `Channel` 调用或释放。
4. 插件代码抛出的异常归一为 `ChipsError` 后返回内核；内核按 `KernelError` 规则进入 `Failed` 并回滚 Fork。
5. 插件模块的加载、校验与生命周期由插件管理层负责（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md)），绑定层不感知 `.cpk`。
