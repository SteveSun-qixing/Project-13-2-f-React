# 资源打开与默认处理器契约

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：资源打开路由的权威契约：打开来源与打开请求模型、manifest 处理器声明与 `primary` / `fallback` 层级、路由解析顺序与投递授权、启动载荷 `resourceOpen` 与业务载荷约定、默认处理器偏好 `platform.fileOpen.defaults` 与槽位治理接口、未安装/停用/卸载的降级与回收、与文档/条目/封面链路的关系；资源 URI 语法、句柄与权限判定本身不在此定义。

## 二、打开来源与打开意图

### 2.1 打开来源

| 来源值 | 触发 | 进入路由的方式 |
|---|---|---|
| `os-association` | 用户双击、右键「打开方式」或在系统对话框中选择本平台 | 平台壳层接收操作系统打开事件，把真实路径归一为受管引用后调用路由 |
| `drop` | 用户把文件、卡片或箱子拖入平台窗口、应用窗口或文档窗口 | 拖放交互链路按落点语义调用路由（[02-拖动与拖放交互规范](../08-产品与交互/02-拖动与拖放交互规范.md) §5） |
| `in-app` | 应用插件主逻辑或 UI 主动打开资源（资源管理器、查看器、编辑器等） | 调用 `resource:open` 能力（§2.2） |
| `frame` | 查看态卡片帧、箱子帧内的用户点击资源 | 帧运行时经 `frame:action` 转发，RenderHost 归一为打开请求后调用路由（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §9.2） |

规则：

- 启动器、命令与深链接**不携带资源**，属于应用启动而非资源打开（[07-应用插件接口](./07-应用插件接口.md) §4.3）；它们不进入本路由。
- `os-association` 与 `drop` 来源的文件由平台创建 **Temporary 作用域**并归一为受管引用；作用域归属本次打开投递的接收方实例，随实例退出注销。接收方按 §4.4 经投递授权获得只读访问，无需申请 `filesystem:*` 权限（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) §5.4）。
- `frame` 来源由 RenderHost 校验请求 URI 属于当前渲染会话可见的引用（文档内容、业务载荷引用或文档作用域内 URI），越界拒绝并记诊断；校验通过后以承载文档会话的应用身份调用路由。
- 帧运行时向基础卡片插件暴露的资源打开入口为 `openResource(request: IResourceOpenRequest)`；消息封套与帧动作集合归 [05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §9.2，本文只定义打开请求模型与归一后的路由行为。
- 同一打开意图只承载一个主资源；多文件来源（多选、批量拖入）按文件顺序逐次路由，每次投递一个 `resourceOpen`（§5.2）。

### 2.2 打开请求模型

打开请求是 `resource:open` 能力的输入，也是帧动作与壳层入口归一后的统一形态：

```typescript
/** 打开意图。 */
export type OpenIntent = 'view' | 'edit';

/** 打开来源。 */
export type OpenOrigin = 'os-association' | 'drop' | 'in-app' | 'frame';

/** 打开请求中的资源描述。 */
export interface IResourceOpenResource {
  /** 目标资源受管引用；能力调用只接受 chips-resource://。 */
  readonly uri: string;
  /** MIME 提示；省略时由平台按扩展名推断（§2.3）。 */
  readonly mimeType?: string;
  /** 展示用文件名（含扩展名）。 */
  readonly fileName?: string;
  /** 展示用标题。 */
  readonly title?: string;
  /** 业务上下文；平台原样透传给命中处理器（§5.3）。 */
  readonly payload?: Readonly<Record<string, unknown>>;
}

/** 打开请求。 */
export interface IResourceOpenRequest {
  /** 打开意图；缺省 view。 */
  readonly intent?: OpenIntent;
  readonly resource: IResourceOpenResource;
}
```

`resource:open` 能力契约：

| 项 | 值 |
|---|---|
| 能力 ID | `resource:open` |
| 所需权限 | `resources:read` |
| 输入 | `IResourceOpenRequest` |
| 输出 | `IResourceOpenResult`（§4.5） |
| 幂等性 | 否（每次调用产生一次投递） |
| 调用约束 | 调用方必须对目标 `uri` 所在作用域持有 `resources:read`；越权返回 `RESOURCE_PERMISSION_DENIED`（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) §5.3） |

输入 schema（JSON Schema 2020-12 平台子集，约定见 [04-能力契约规范](./04-能力契约规范.md) §五）：

```typescript
const resourceOpenInputSchema: JSONSchema = {
  type: 'object',
  additionalProperties: false,
  properties: {
    intent: { type: 'string', enum: ['view', 'edit'] },
    resource: {
      type: 'object',
      additionalProperties: false,
      required: ['uri'],
      properties: {
        uri: { type: 'string', format: 'chips-resource-uri', maxLength: 2048 },
        mimeType: {
          type: 'string',
          pattern: '^[a-z0-9!#$&^_.+-]+/[a-z0-9!#$&^_.+-]+$',
          maxLength: 128,
        },
        fileName: { type: 'string', minLength: 1, maxLength: 255 },
        title: { type: 'string', minLength: 1, maxLength: 128 },
        payload: { type: 'object', maxProperties: 32 },
      },
    },
  },
  required: ['resource'],
};
```

约束：

- `payload` 必须可结构化克隆（可克隆性口径见 [05-事件契约规范](./05-事件契约规范.md) §3.4），序列化后不超过 64 KiB；超限返回 `BRIDGE_INVALID_INPUT`。
- 输入不通过 schema 时返回 `BRIDGE_INVALID_INPUT`，`details` 结构见 [04-能力契约规范](./04-能力契约规范.md) §5.4。
- 打开不产生持久授权：文件关联只决定路由（[07-应用插件接口](./07-应用插件接口.md) §5.4）。

### 2.3 输入归一

路由在解析前对输入执行确定性归一：

1. **URI**：`resource:open` 只接受 `chips-resource://`；壳层与拖放来源的 `file://`、裸路径、`http(s)://`、`webdav://` 由平台入口按 [06-资源协议规范](./06-资源协议规范.md) §2.6 归一为受管作用域引用，归一责任不在插件。
2. **MIME**：调用方提示优先（须为小写 `type/subtype`）；无提示时按扩展名经内置静态表推断（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) §3.4）；仍无法判定时取 `application/octet-stream`。路由阶段不做网络探测、不读取资源字节。
3. **扩展名**：取 `fileName`（缺省时取 URI 路径最后一段并百分号解码）中最后一个 `.` 之后的部分，转为小写并加前缀点（如 `.png`）；无点或结果为空时扩展名缺席。
4. **文件名与标题**：`fileName` 缺省时取 URI 路径最后一段；URI 无文件名时两者均可缺席。
5. **意图**：缺省 `view`；`edit` 只在存在 `edit` 能力处理器时投递，否则按 `view` 解析并在结果与诊断中记录实际意图。

### 2.4 旧版口径处置

| 旧版口径 | 处置 |
|---|---|
| `launchParams.targetPath` | **正式废弃**。启动载荷只含受管引用（§5.1）；平台在内部解析真实路径，插件不接触真实路径（R13） |
| `resource-handler:<intent>:<mime>[@tier]` / `file-handler:<ext>[@tier]` 能力串 | 由 `fileAssociations` 的 `mimeTypes` 与 `tier` 扩展承载（§3.1）；能力串写法不再解析 |
| `capabilityFallbacks`（open-file / save-file 回退） | 不再提供；回退由平台路由统一承担（§4.6），插件以 `tier: fallback` 声明兜底意愿 |
| `resource.open` 动作 | 由 `resource:open` 能力替代（§2.2） |
| `file.session.*` / `file.preview.*` / `file.convert.*` | 不进入新架构：文档打开、读取、写入与保存统一走 `document:*`（[04-能力契约规范](./04-能力契约规范.md) §7.3），格式转换与预览生成属服务插件能力（[04-能力契约规范](./04-能力契约规范.md) §3.2） |
| 系统文件关联注册 | 处理器声明随插件安装与启用生效；操作系统层文件关联跟随启用状态（启用注册、停用与卸载回收），壳层注册流程见 §7.2 |
