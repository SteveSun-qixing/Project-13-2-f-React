## 七、事件与配置访问

### 7.1 访问通道

| 通道 | 主逻辑（主进程） | UI（渲染进程） |
|---|---|---|
| 能力调用 | `ctx.bridge.request<T>(capabilityId, input)` | `chips.request<T>(capabilityId, input)`（`window.chips` 的类型化封装） |
| 事件订阅 | `ctx.on(eventId, handler)` / `ctx.once(...)`（Cordis 事件面） | `chips.subscribe(eventId, handler)`（Bridge 事件面） |
| 事件发布 | `ctx.emit(eventId, payload)`（自有域事件，不跨进程） | `chips.request('event:publish', ...)`（受白名单与权限约束） |
| 资源访问 | `ctx.bridge.resource(uri)` | `chips.resource(uri)` |
| 配置读写 | `ctx.config.get/set/...`（自身命名空间，`key` 为相对键） | `chips.request('config:get' \| 'config:set' \| ...)`（显式携带 `namespace` 与 `key`） |
| 服务注入 | `ctx.inject(dependencies, callback)` | 不适用（渲染进程不使用服务与 Context） |
| 日志 | `ctx.logger.debug/info/warn/error` | — |

规则：

- 主逻辑的全部平台访问只经 `IAppContext` 的访问面（§4.6）；不得访问全局对象、平台内部状态或 Node.js / Electron API。
- 两条路径最终进入同一条 Bridge 链路，权限判定、Schema 校验与审计一致（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) §八）。
- 主逻辑的订阅、注入与清理随实例退出自动撤销；`IAppContext` 与 `IAppWindow` 不得跨实例缓存。
- 插件自有域事件默认不跨进程；需要主逻辑与 UI 协作时，先登记为标准事件（[09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md) §3.3）。

### 7.2 事件订阅

应用插件常用的标准事件：

| 事件 ID | payload 要点 | 对应用的意义 |
|---|---|---|
| `app:launched` | `{ appId }` | 实例进入可用 |
| `app:exited` | `{ appId, exitCode? }` | 实例结束 |
| `app:opened-with-url` | `{ appId, url }` | 运行中收到深链接 |
| `tray:clicked` | `{ button }` | 托盘图标被点击 |
| `shortcut:triggered` | `{ shortcutId }` | 已注册快捷键被按下 |
| `transfer:progress` / `transfer:completed` / `transfer:failed` | `{ transferId, ... }` | 传输进度与结果 |
| `window:created` | `{ windowId, appId? }` | 表面/窗口创建完成 |
| `window:closed` | `{ windowId }` | 窗口关闭、窗口级资源释放 |
| `window:focused` | `{ windowId }` | 窗口获得焦点 |
| `plugin:loaded` / `plugin:enabled` / `plugin:disabled` / `plugin:unloaded` / `plugin:failed` | `{ pluginId, ... }` | 感知自身与依赖插件状态 |
| `config:changed` | `{ key, layer, value, effectiveValue, isDefault, origin }` | 自身或平台配置变更 |
| `file:changed` | `{ uri, kind, previousUri? }` | 关联文件变化 |
| `document:opened` / `document:closed` / `document:changed` / `document:saved` | `{ uri, kind, ... }` | 文档生命周期 |

规则：

- 完整 payload、字段约束与更多事件以 [05-事件契约规范](05-事件契约规范.md) 为准；事件机制见 [09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md)。
- 主逻辑经 `IAppContext.on` / `once` 订阅，句柄随实例退出自动撤销；UI 经 `chips.subscribe` 订阅，返回 `ISubscription`，必须在组件卸载或窗口关闭时 `dispose()`，会话销毁时 Bridge 兜底清理。
- 高频事件必须限流处理；事件只做通知，不承担请求-响应语义。

### 7.3 配置访问

- 命名空间：应用配置固定为 `plugins.<appId>`，读写自身命名空间免权限（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §2.3、§11.3）。
- 主逻辑：`ctx.config.get/snapshot/set/reset/watch`，`key` 为相对键（不含命名空间前缀）；UI：经 `chips.request('config:get' | 'config:set' | ...)` 显式携带 `namespace` 与 `key`。
- 写入层只接受 `user` 与 `workspace`；访问 `platform` 命名空间须经 `ctx.bridge.request('config:get' | 'config:set', { namespace: 'platform', ... })` 并持 `config:read:platform` / `config:write:platform`。
- 默认值：应用包内 `assets/schemas/config.schema.json` 的 `default` 是插件层默认值，默认值不落盘；未声明默认值且无覆盖时读取结果的 `value` 由实现决定（见 [10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md)）。
- 变更通知：写入落盘后逐键发布 `config:changed`；主逻辑用 `ctx.on<IAppConfigChange>` 或 `ctx.config.watch`，UI 用 `chips.subscribe`，响应时以 `effectiveValue` 为准。
- 凭证：schema 中使用 `format: "chips-credential"` 保存引用，实际材料经 `credential:*` 能力访问，禁止写入配置。
- 推荐做法：`launch` 读取自身配置并应用；UI 自行读取并在 `config:changed` 时刷新，不依赖主逻辑转发。
