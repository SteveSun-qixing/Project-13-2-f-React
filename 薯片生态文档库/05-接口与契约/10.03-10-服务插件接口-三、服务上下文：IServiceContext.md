## 三、服务上下文：`IServiceContext`

### 3.1 接口定义

```typescript
import type {
  ICapability,
  IChipsBridge,
  IEventSubscription,
} from '@chips/sdk';

type ConfigLayer = 'platform' | 'user' | 'workspace' | 'plugin';
type ConfigWriteScope = 'user' | 'workspace';

interface IConfigView {
  key: string;                 // 完整键：plugins.<pluginId>.<相对键>
  value: unknown;              // 生效值；未定义且无默认值时由实现决定（见 10-配置系统设计）
  layer: ConfigLayer;          // 生效值所在层
  isDefault: boolean;          // 是否来自默认值
}

interface IConfigChange {
  key: string;
  layer: ConfigLayer;
  value: unknown;
  effectiveValue: unknown;
  isDefault: boolean;
  origin: string;              // 变更来源，插件写入为 plugin:<pluginId>
}

interface IServiceConfig {
  get(key: string): Promise<IConfigView>;
  snapshot(prefix?: string): Promise<Readonly<Record<string, unknown>>>;
  set(key: string, value: unknown, scope: ConfigWriteScope): Promise<void>;
  reset(keys: readonly string[], scope: ConfigWriteScope): Promise<void>;
  watch(prefix: string, handler: (change: IConfigChange) => void): IEventSubscription;
}

type ServiceLogFields = Readonly<Record<string, string | number | boolean | null>>;

interface IServiceLogger {
  debug(message: string, fields?: ServiceLogFields): void;
  info(message: string, fields?: ServiceLogFields): void;
  warn(message: string, fields?: ServiceLogFields): void;
  error(message: string, error?: unknown, fields?: ServiceLogFields): void;
}

type IServiceBridge = Pick<IChipsBridge, 'request' | 'resource'>;

interface ICapabilityRegisterOptions {
  timeoutMs?: number;                          // 调用超时，默认 30000
  concurrency?: 'parallel' | 'serial';         // 并发策略，默认 'parallel'
  maxQueue?: number;                           // 串行队列上限，默认 32
}

interface IServiceContext {
  readonly pluginId: string;
  readonly bridge: IServiceBridge;
  readonly config: IServiceConfig;
  readonly logger: IServiceLogger;

  provide<T extends object>(name: string, service: T): void;
  inject(dependencies: readonly string[], callback: (ctx: IServiceContext) => void): void;

  on<TPayload>(event: string, listener: (payload: TPayload) => void): IEventSubscription;
  once<TPayload>(event: string, listener: (payload: TPayload) => void): IEventSubscription;
  emit<TPayload>(event: string, payload: TPayload): void;

  registerCapability<TInput = unknown, TOutput = unknown>(
    capability: ICapability<TInput, TOutput>,
    options?: ICapabilityRegisterOptions,
  ): void;

  effect(cleanup: () => void): void;
}
```

### 3.2 成员总表

| 成员 | 类型 | 说明 | 权限 |
|---|---|---|---|
| `pluginId` | `readonly string` | 当前插件 ID（反向域名），只读 | — |
| `bridge` | `IServiceBridge` | 主进程出站能力与资源访问（3.7） | 按被调能力声明的权限 |
| `config` | `IServiceConfig` | 自身命名空间配置访问（3.5） | 自身命名空间免权限 |
| `logger` | `IServiceLogger` | 平台日志流（3.6） | 免权限（R19） |
| `provide` | 方法 | 注册 Cordis 服务（3.3） | — |
| `inject` | 方法 | 声明服务依赖并注入回调（3.3） | — |
| `on` / `once` / `emit` | 方法 | 内核事件订阅与发布（3.4） | 按事件契约声明的订阅权限 |
| `registerCapability` | 方法 | 注册 Bridge 能力（第六节） | 能力所需权限须已在 manifest 声明 |
| `effect` | 方法 | 登记可逆副作用清理（3.8） | — |

约束：

- 以上成员构成 `start` 收到的全部可用面；不存在的成员即不可用，插件不得访问全局对象或平台内部结构扩展访问面。
- Context 进入 `Disposing` 后拒绝新的 `provide`、`inject`、`on`、`registerCapability`、`effect`；销毁后一切操作返回 `KERNEL_CONTEXT_DISPOSED`（[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) 3.3）。

### 3.3 服务注册与注入

```typescript
interface IIndexService {
  enqueue(uri: string): Promise<void>;
}

interface IIndexRequested {
  uri: string;
}

// 提供方：注册服务
const index: IIndexService = {
  async enqueue(uri: string): Promise<void> {
    // 业务实现（本示例只展示注册与注入的形状）
    void uri;
  },
};
ctx.provide<IIndexService>('index', index);

// 消费方：声明依赖后使用，不感知提供者身份
ctx.inject(['index'], (ctx) => {
  ctx.on<IIndexRequested>('index:requested', (payload) => {
    void ctx.index.enqueue(payload.uri);
  });
});
```

规则：

- 服务名规范 `^[a-z][a-z0-9]*(-[a-z0-9]+)*$`；作用域内唯一，同名服务以最近祖先为准（内核 5.1、3.2）。
- `provide` 返回后服务即可被解析；同名替换触发代际切换，消费方注入 Fork 按拓扑序级联重建（内核 5.4）。
- `inject` 回调为同步函数；回调内不得缓存跨代际的服务引用，长期任务必须挂到注入 Fork（内核 5.3）。
- 消费其他插件提供的服务时，插件必须通过 `dependencies` 声明对该提供方插件的依赖（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 7.1）。
- 服务值必须是可跨线程共享的对象；服务内部并发与缓存自行负责。

### 3.4 事件

| 成员 | 签名 | 说明 |
|---|---|---|
| `on` | `on<TPayload>(event, listener): IEventSubscription` | 订阅内核事件总线；监听器随当前 Fork 自动撤销 |
| `once` | `once<TPayload>(event, listener): IEventSubscription` | 首次投递后自动退订；未触发时随 Fork 撤销 |
| `emit` | `emit<TPayload>(event, payload): void` | 同步广播自有域事件 |

规则：

- 主进程事件面即内核总线：标准事件与插件自有域事件都经 `ctx.on` / `ctx.emit` 使用（[09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md) 3）。
- `internal:*` 为内核内部事件，插件不得订阅、发布或依赖。
- 监听器不得执行阻塞调用；耗时处理必须转为可取消的后台任务（4.7）。
- 事件只用于通知，不承担请求-响应语义；需要返回值时使用服务或能力。
- 标准事件的订阅权限由事件契约声明；未授权的订阅不建立（[05-事件契约规范](./05-事件契约规范.md)）。

### 3.5 配置

`ctx.config` 是平台对 `config:*` 能力的类型化封装，作用域固定为当前插件自身的命名空间 `plugins.<pluginId>`；权限判定、schema 校验与审计与直接调用能力完全一致（唯一通道不破例）。

| 成员 | 说明 |
|---|---|
| `get(key)` | 读取自身命名空间下相对键的生效值；键未注册返回 `CONFIG_KEY_UNKNOWN` |
| `snapshot(prefix?)` | 返回前缀下合并默认值后的完整生效视图 |
| `set(key, value, scope)` | 在 `user` 或 `workspace` 层写入覆盖；值必须通过 `assets/schemas/config.schema.json` 校验 |
| `reset(keys, scope)` | 移除指定层上的覆盖；缺失覆盖为 no-op |
| `watch(prefix, handler)` | 订阅前缀匹配的变更，返回可退订句柄 |

规则：

- `key` 为插件命名空间下的相对键（如 `timezone`），不得包含命名空间前缀。
- 默认值来自插件包内 `assets/schemas/config.schema.json`；默认值不落盘，只有显式覆盖写入用户层或工作区层（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) 4）。
- 读写 `platform` 命名空间不使用 `ctx.config`，必须经 `ctx.bridge.request('config:get' | 'config:set', { namespace: 'platform', … })`，并持带命名空间限定值的 `config:read` / `config:write`。
- 常见错误码：`CONFIG_SCHEMA_INVALID`、`CONFIG_KEY_INVALID`、`CONFIG_KEY_UNKNOWN`、`CONFIG_VALUE_INVALID`、`CONFIG_SCOPE_INVALID`、`CONFIG_POLICY_LOCKED`、`CONFIG_NAMESPACE_DENIED`、`CONFIG_WRITE_FAILED`。
- 插件卸载时其订阅随 Fork 撤销；插件不得直接读写配置文件。

### 3.6 日志

```typescript
async function fetchRemote(ctx: IServiceContext, url: string): Promise<unknown> {
  try {
    const result = await ctx.bridge.request<unknown>('http:request', { url });
    ctx.logger.info('远端请求完成', { url });
    return result;
  } catch (error) {
    ctx.logger.error('远端请求失败', error, { url });
    throw error;
  }
}
```

规则：

- 日志写入平台日志流，按插件隔离并按限速策略写入；平台自动附加 `pluginId`、`pluginVersion`、`timestamp`、`level`、`traceId`。
- 日志免权限（R19）：按插件命名空间自动归属，写入失败不抛出、不中断服务。
- `message` 面向开发者，使用简体中文；结构化细节放 `fields`，只允许字符串、数字、布尔与 `null` 标量。
- 禁止记录凭证值、文件内容、用户数据与资源字节；禁止在发布路径同步写日志。
- 错误对象经 `error` 参数传入，平台提取类型与消息写入诊断，不写入堆栈到用户可见输出。

### 3.7 出站能力与资源

```typescript
interface IFileReadOutput {
  content: string;
  encoding: 'utf-8' | 'base64';
}

const metadata = await ctx.bridge
  .resource('chips-resource://plugin-001/template.png')
  .metadata();

const file = await ctx.bridge
  .request<IFileReadOutput>('file:read', { path: 'drafts/note.md', encoding: 'utf-8' });
```

规则：

- `IServiceBridge` 只包含 `request` 与 `resource`：主进程内不存在 `window.chips`；事件订阅使用 `ctx.on` / `ctx.once`，`bridge.subscribe` 是渲染进程投影，不在服务上下文暴露（[01-Bridge-API规范](./01-Bridge-API规范.md) 4.1）。
- 主进程调用与插件调用同链路：能力存在性检查 → 权限判定 → JSON Schema 校验 → 路由执行 → 错误归一（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 2.2）。
- 能力调用使用**本插件自己的会话权限快照**；服务插件不得借用调用方权限，也不得代调用方申请权限（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 5.4、11）。
- 资源访问统一使用 `chips-resource://`；句柄使用完毕必须 `release()`，禁止依赖垃圾回收。资源字节不得经能力参数传输大对象，必须经句柄或流式接口读取。

### 3.8 副作用登记

- `effect(cleanup)` 登记任意自定义清理函数；定时器、连接器、观察者等平台未内建追踪的资源必须经 `effect` 包装（[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) 4.2）。
- 撤销顺序为「子 Fork 后序 + 自身副作用 LIFO」；单个清理失败不中断其余撤销（内核 4.3、4.4）。
- `cleanup` 必须幂等、不得抛出；`stop()` 与 `cleanup` 可以并存，但不得重复释放同一资源导致二次副作用。
- 未被 Fork 追踪的副作用视为插件缺陷；平台可检测并审计。
