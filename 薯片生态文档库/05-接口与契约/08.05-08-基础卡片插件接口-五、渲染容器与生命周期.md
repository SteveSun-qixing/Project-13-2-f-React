## 五、渲染容器与生命周期

### 5.1 容器

| 维度 | 查看态容器（`renderView`） | 编辑态容器（`renderEditor`） |
|---|---|---|
| 提供方 | 渲染帧运行时为该节点创建的独立容器 | 编辑链路的 EditorHost 挂载点 |
| 位置 | `sandbox="allow-scripts"` 的 iframe 内 | 应用窗口渲染进程，不经 iframe |
| 粒度 | 每个节点一个容器，容器与 `node_id` 一一对应 | 每个编辑中的节点一个容器 |
| 宽度 | 由父帧容器决定 | 由编辑面板布局决定 |
| 高度 | 帧运行时测量并上报 | 由编辑面板布局决定 |
| 样式 | 仅 `@chips/ui` 组件与 Design Tokens（`tokens` 注入的 CSS 变量） | 同左 |
| 卸载 | 帧销毁时容器整体销毁 | 调用方在 `dispose()` 后清空或移除容器 |

通用规则：

1. 容器由平台所有、插件是租户：只在容器内创建 DOM，不得访问 `document.body`、`parent`、`top` 或其它帧（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §4.5）。
2. 禁止多节点共用容器：帧运行时为每个节点创建独立容器并在容器内调用 `renderView(basecard, container)`，节点级降级在帧内完成；插件不得把多个节点渲染进同一容器。
3. 不得持有跨帧、跨会话的 DOM 引用；上一轮 DOM 在更新或销毁后失效。
4. 不得假设容器为空：更新调用时容器内是上一版内容，必须以新视图覆盖或 diff 到新视图。
5. 编辑容器内只挂载编辑器 UI；预览、工具栏、保存与关闭按钮由编辑链路提供，编辑链路按用户描述保留编辑即时预览。
6. 禁止引入第二套组件库与全局样式；帧内样式不得泄漏到宿主（R4、RR-13）。

### 5.2 生命周期

```
启用（active）
  平台：从 manifest 注册 cardTypes；不加载渲染入口；不执行插件代码
      │
打开卡片（查看）
  平台：按内容 card_type 归一（aliases）并解析插件 → 校验插件能力声明 → 创建渲染帧 → 装载 render.js
  平台：为每个节点创建独立容器
  插件：renderView(basecard, container) 逐节点调用 → 同步提交首帧 DOM
  平台：frame:ready / frame:height
      │
视图更新（revision 前进 / host:update）
  插件：renderView(basecard, container) 再次调用 → 覆盖或 diff 到新视图
      │
进入编辑
  平台：编辑链路经 IPluginRuntime 装载插件并创建编辑容器
  插件：renderEditor(basecard, container) → IBaseCardEditor
  循环：getChange → 校验 → document:write({ revision }) → 会话 update → markCommitted
      │
结束编辑
  平台：editor.dispose() → 清空容器
      │
停用 / 卸载
  平台：注销 cardTypes；销毁渲染帧与编辑器；失效模块缓存
  插件：全部 Dispose 与 IBaseCardEditor.dispose() 逆序执行
```

### 5.3 调用保证

1. `renderView` 与 `renderEditor` 只由平台调用：查看态由渲染帧运行时调用；编辑态由编辑链路经平台插件门面 `IPluginRuntime` 装载并调用；插件不得自行调用、相互调用或从 `export` / `validateConfig` 中调用（§2.5）。
2. `renderView` 在帧存活期间可能被调用任意次；实现必须支持「挂载 + 多次更新」序列，且容器与节点一一对应。
3. `renderView` 抛出的异常做节点级降级并返回 `RENDER_PLUGIN_FAILED`；`renderEditor` 抛出的异常由编辑链路按错误边界隔离；两者都不影响兄弟节点与其它插件（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §6.4）。
4. 停用后不再接收任何调用；未完成的异步任务必须能在 `dispose()` 时取消，不得在释放后回调或更新容器。
5. 插件更新（蓝绿替换）时新请求使用新版本；已挂载实例保持旧版本直到帧销毁或重新渲染，旧版本实例随旧 Fork 释放（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §6.3）。

### 5.4 禁止清单

| 禁止 | 说明 |
|---|---|
| 帧内访问 `window.chips` | 帧内一律经帧协议转发（`frame:action`），由 RenderHost 判定权限；`window.chips` 仅就近渲染容器与其它渲染侧代码可用 |
| 帧内访问 `parent` / `top` / `document.body` | 破坏沙箱边界，视为缺陷 |
| 帧内读写 `localStorage` / `indexedDB` | 帧内不提供存储能力 |
| 帧内网络直连 | `connect-src 'none'`；外部资源统一经资源代理 |
| 多节点共用容器 | 帧运行时为每个节点创建独立容器；共用容器视为缺陷 |
| 固定容器宽度或改变外层尺寸 | 高度与位姿由渲染引擎统一管理 |
| 在 `renderView` 内执行重计算或字节解析 | 需要预处理的内容在编辑侧或服务侧完成，帧内只负责呈现 |
| 编辑结果直接写文件或直接调用渲染会话 | 必须经 `IBaseCardEditor`、编辑链路与文档服务回流 |
