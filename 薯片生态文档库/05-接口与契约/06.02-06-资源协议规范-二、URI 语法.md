## 二、URI 语法

### 2.1 总形式

```text
chips-resource://<scope>/<path>[?<query>]
```

- `<scope>` 位于 authority 位置（`//` 之后、第一个 `/` 之前）：每个作用域在渲染引擎中天然是独立 origin，是帧隔离与 CSP 的基础。
- `<path>` 为作用域内的虚拟路径，相对作用域根。
- `<query>` 仅 External 作用域允许，见 2.5 节。

受管作用域（受管来源，无查询串）：

```text
chips-resource://card-7f3a/images/photo.jpg
chips-resource://box-2c91/.box/cover.html
chips-resource://plugin-001/icon.png
chips-resource://platform/frame.html
```

外部作用域（External 专用形式，origin 编码在路径前两段）：

```text
chips-resource://external/<scheme>/<host>[:<port>]/<path>[?<query>]

chips-resource://external/https/cdn.example.com/banner.png
chips-resource://external/http/api.example.com:8080/v1/items?page=2
```

### 2.2 scheme

- 协议名固定为 `chips-resource`，全小写；输入中的大小写变体一律归一为小写。
- 平台将其注册为自定义标准协议（具备 origin 语义、支持流式响应与 fetch），注册实现见 [ADR-002](../01-架构设计/ADR/ADR-002-Electron作为桌面端壳.md) 与 [04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 7.4 节。
- `window.chips.resource(uri)` 接受 `chips-resource://` 规范 URI，并接受裸 `http(s)://` 输入（按 2.6 节归一为 External URI）；`file://`、`webdav://` 与未知 scheme 一律返回 `RESOURCE_UNSUPPORTED_SCHEME`（`webdav://` 是文件格式引用形式，由解析器与渲染层归一后再进入运行时，见 2.6 节）。
- 文件格式中的引用形式只允许包内相对路径、`file://`、`http(s)://`、`webdav://`、`chips-resource://`（R13）；裸绝对路径禁止写入任何文件格式；`data:` 仅运行时内存形态，禁止持久化，解析器按非法引用处理（[06-文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md) 第 5 节）。

### 2.3 scope

| 规则 | 要求 |
|---|---|
| 语法 | 1–64 个字符，`[a-z][a-z0-9-]*`，全小写 ASCII；大小写变体归一为小写。 |
| 受管作用域 ID | `workspace-<opaque>` / `card-<opaque>` / `box-<opaque>` / `plugin-<opaque>` / `temp-<opaque>`；`<opaque>` 由平台生成（小写字母、数字、连字符），不透明。 |
| 保留字 | `platform`、`external`、`memory` 为固定保留 scope。 |
| 分配 | 作用域 ID 由平台在注册时分配；插件不得构造、命名、猜测或枚举作用域。 |
| 使用 | 插件只能使用平台返回的 `resourceBase`、视图中的引用或已获得句柄的 URI；不得截取 URI 作为文件系统路径使用。 |

`external` 不是独立注册的单一作用域：其后两段编码归一后的 origin（`<scheme>/<host>[:<port>]`），平台按 origin 惰性注册 External 作用域，见 3.2 节。

### 2.4 path

`<path>` 是以 `/` 分隔、相对作用域根、NFC 规范化的虚拟路径；所有 Provider 只接受虚拟路径，不接受原始字符串。

| 规则 | 要求 | 违反时 `details.reason` |
|---|---|---|
| 分隔符 | 只允许 `/`；反斜杠 `\` 一律拒绝 | `separator` |
| 相对性 | 必须相对作用域根；拒绝绝对路径、盘符、UNC | `absolute` |
| 段 | 拒绝空段、`.`、`..`（含其编码形式解码后的结果） | `segment` |
| 编码 | 百分号解码仅一次；解码后按 `/` 重新分段并重新执行全部校验 | `encoding` |
| 控制字符 | 拒绝 `\0` 与 U+0000–U+001F、U+007F | `control` |
| Unicode | 百分号解码一次后的字节序列须为合法 UTF-8 且不含非字符与替换字符：非字符取 Unicode 全集——U+nFFFE/U+nFFFF（n=0–16，全 17 平面，含 U+FFFE/U+FFFF）与非字符区 U+FDD0–U+FDCF，替换字符为 U+FFFD，触发即拒，违反即 `RESOURCE_PATH_INVALID` + `details.reason = unicode`（码归属 2026-09-21 主智能体更正：本表 reason 列为 `ResourcePathErrorReason` 词表，§5.1 流水线中本表违约统一走路径族错误，工单042 裁定④初稿误记 `RESOURCE_INVALID_URI` 已按 §7.3 `IResourcePathErrorDetails` 形状翻正；非字符覆盖面按工单043 裁定 A1 由「未限 n、不含 U+FDD0–U+FDCF」收紧为上述 Unicode 全集，错误码值零改动，实现触发臂随动归 chips-resource 段三收口波）；NFC 规范化差异本身不构成拒绝（归一后校验与比较维持） | `unicode` |
| 长度 | URI 总长度与单段/路径长度上限由平台统一配置；超限拒绝 | `length` |
| 平台特例 | Windows 盘符、UNC、ADS（含 `:` 文件名）、设备名、尾随点与空格一律拒绝 | `platform` |
| 符号链接 | 目录态来源解析后必须仍位于作用域根内；指向根外一律拒绝 | `symlink` |

补充规则：

- 路径区分大小写；目录态来源在大小写不敏感卷上遵循卷语义，归档条目精确匹配（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 9.3 节）。
- 空路径只允许作为 `resourceBase` 基址（`chips-resource://<scope>/`，尾斜杠）；直接请求作用域根返回 `RESOURCE_NOT_FOUND`（目录不可列举）。
- 读面命中作用域内**非根**目录态路径同样返回 `RESOURCE_NOT_FOUND`（`{uri}`）：目录不作为资源直读，读面不因目标态拆分错码（工单044 裁定①）。
- 列举面条目级跳过：目录列举遇符号链接条目（含指向根内）不返回该条目——列举面不跟随，规避根外存在性侧信道；寻址面遇符号链接仍按本表「符号链接」行拒绝出 `RESOURCE_PATH_INVALID`，两层不混用（工单044 裁定⑤，条目面细则见 [04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 4.10 节）。
- 路径校验在服务端唯一入口为 PathGuard；任何快速路径都不得跳过解码与分段校验（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 9.2 节）。

### 2.5 查询参数

| 作用域 | 查询串 | 规则 |
|---|---|---|
| `workspace-*` / `card-*` / `box-*` / `plugin-*` / `platform` / `temp-*` / `memory` | 禁止 | 出现裸 `?` 返回 `RESOURCE_INVALID_URI`（`query_not_allowed`）；字面 `?` 必须编码为 `%3F`。 |
| `external` | 允许 | 原样保留并传递给目标 origin；参与 External 缓存键（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 6.5 节）；不参与作用域归属判定。 |

- fragment（`#`）在任何作用域下一律禁止，出现即返回 `RESOURCE_INVALID_URI`（`fragment_not_allowed`）；字面 `#` 必须编码为 `%23`，解码后作为普通路径字符。
- 平台不通过资源通道注入或管理凭证（Cookie / Authorization）；External 的 query 由调用方自担，是否落盘遵循 External 缓存边界（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 8.4 节）。

### 2.6 转义与归一化

| 项 | 规则 |
|---|---|
| 字符集 | 规范 URI 只含 ASCII；非 ASCII 字符以 UTF-8 字节做百分号编码（十六进制大写）。 |
| `%` | 两位十六进制；非法序列返回 `RESOURCE_INVALID_URI`（`invalid_encoding`）；字面 `%` 必须编码为 `%25`。 |
| `/` | 路径分隔符；编码形式 `%2F` 解码后按分隔符处理并重新分段校验。 |
| 空格 | 必须编码为 `%20`；不接受裸空格与 `+`。 |
| scope | 归一为小写。 |
| 路径 | 不做大小写折叠；NFC 规范化后比较；不折叠 `.`、`..`（出现即拒绝）。 |
| External origin | scheme 与 host 小写；IDN 转 punycode；默认端口（http 80 / https 443）省略；host 尾随点去除。 |
| userinfo | 含 userinfo（`http://user:pass@host`）的外部地址拒绝（`invalid_origin`）。 |

裸 `http(s)://` 引用到 External 规范 URI 的转换：

| 输入 | 归一结果 |
|---|---|
| `https://cdn.example.com/banner.png` | `chips-resource://external/https/cdn.example.com/banner.png` |
| `http://api.example.com:8080/v1/items?page=2` | `chips-resource://external/http/api.example.com:8080/v1/items?page=2` |
| `HTTPS://CDN.EXAMPLE.COM/Banner.PNG` | `chips-resource://external/https/cdn.example.com/Banner.PNG`（path 保持大小写） |
| `https://example.com:443/a` | `chips-resource://external/https/example.com/a` |
| `https://例え.jp/a` | `chips-resource://external/https/xn--r8jz45g.jp/a` |
| `https://user:pass@example.com/a` | 拒绝：`RESOURCE_INVALID_URI`（`invalid_origin`） |
| `https://[2001:db8::1]/a` | `chips-resource://external/https/%5B2001:db8::1%5D/a`（IPv6 方括号编码，解码后按 IP 字面量处理） |

`webdav://` 引用到 External 规范 URI 的转换（WebDAV 引用只在文件格式与文档模型中出现，由解析器归一，不直接传入 `resource()`）：

| 输入 | 归一结果 |
|---|---|
| `webdav://dav.example.com/team/notes.card` | `chips-resource://external/webdav/dav.example.com/team/notes.card` |
| `WEBDAV://DAV.EXAMPLE.COM:8443/team/notes.card` | `chips-resource://external/webdav/dav.example.com:8443/team/notes.card` |
| `webdav://user:pass@dav.example.com/a.card` | 拒绝：`RESOURCE_INVALID_URI`（`invalid_origin`）；凭证由平台凭证存储按授权策略注入，不写入引用 |

包内相对路径与 `file://` 引用不进入上述转换：**归一责任在文档解析器**，由解析器在进入渲染前把二者归一为受管作用域 URI 并随解析输出交付；渲染层只消费归一结果，不重复归一（R13，[06-文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md) §5、[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 5.2 节）。`webdav://` 归一为 External 作用域（scheme 段固定为 `webdav`），由平台 WebDAV 代理承载，凭证不写入引用。

### 2.7 合法与非法示例

| 输入 | 结果 | 错误码 |
|---|---|---|
| `chips-resource://card-7f3a/images/photo.jpg` | 合法 | — |
| `chips-resource://card-7f3a/images/../.card/metadata.yaml` | 拒绝（`..` 段） | `RESOURCE_PATH_INVALID` |
| `chips-resource://card-7f3a/%2e%2e/.card/metadata.yaml` | 拒绝（解码后 `..` 段） | `RESOURCE_PATH_INVALID` |
| `chips-resource://card-7f3a/images/%252e%252e/x` | 解码一次得字面 `%2e%2e`，非穿越；按字面名查找 | 通常 `RESOURCE_NOT_FOUND` |
| `chips-resource://card-7f3a/images\photo.jpg` | 拒绝（反斜杠） | `RESOURCE_PATH_INVALID` |
| `chips-resource://card-7f3a/images/photo.jpg?v=2` | 拒绝（受管作用域查询串） | `RESOURCE_INVALID_URI` |
| `chips-resource://platform/frame.html#top` | 拒绝（fragment） | `RESOURCE_INVALID_URI` |
| `chips-resource://external/https/example.com/a.json?page=1` | 合法 | — |
| `chips-resource://external/webdav/dav.example.com/team/a.card` | 合法（WebDAV 引用的运行时形态） | — |
| `chips-resource://unknown-1/a.png` | 作用域未注册 | `RESOURCE_NOT_FOUND` |
| `file:///Users/me/note.card/a.png`（传入 `resource()`） | 拒绝（不支持 scheme） | `RESOURCE_UNSUPPORTED_SCHEME` |
| `webdav://dav.example.com/team/a.card`（传入 `resource()`） | 拒绝（引用形式，须先由解析器归一） | `RESOURCE_UNSUPPORTED_SCHEME` |
