## 四、Context 与 Fork（chips-cordis）

### 4.1 Context

Context 是插件运行时上下文：服务注册、依赖注入与作用域解析的唯一入口。类型结构、状态机与作用域规则见 [01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) 第三章。

```rust
#[derive(Clone)]
pub struct Context {
    /* ContextId + Kernel 句柄；结构见 01-薯片内核设计 3.1 */
}

impl Context {
    /// 在当前 Context 注册服务；同名服务被替换并触发级联重建。
    pub fn provide<T>(&self, name: ServiceName, value: T) -> Result<(), KernelError>
    where
        T: Any + Send + Sync + 'static;

    /// 声明依赖并注入回调；依赖全部就绪时在注入 Fork 中执行回调。
    pub fn inject<F>(
        &self,
        dependencies: &[ServiceName],
        callback: F,
    ) -> Result<InjectionId, KernelError>
    where
        F: Fn(&Context) + Send + Sync + 'static;

    /// 按作用域链查找服务快照；未命中返回 `KERNEL_SERVICE_NOT_FOUND`。
    pub fn get(&self, name: &str) -> Result<ServiceValue, KernelError>;
}
```

| 方法 | 返回 | 失败 | 语义 |
|---|---|---|---|
| `provide` | `Ok(())` | `KERNEL_SERVICE_*`、`KERNEL_CONTEXT_DISPOSED` | 立即生效；撤销登记到当前 Fork 并按代际匹配 |
| `inject` | 注入 ID | `KERNEL_*`、`KERNEL_CONTEXT_DISPOSED` | 返回 `Ok` 不代表回调已执行；依赖就绪后执行，失效时撤销并重建 |
| `get` | 服务快照 `Arc` | `KERNEL_SERVICE_NOT_FOUND`、`KERNEL_CONTEXT_DISPOSED` | 一次读锁加 `Arc::clone`；内核不在调用路径上 |

规则：

- `Context` 为 `Clone` 句柄；克隆共享同一节点。
- 服务值必须 `Send + Sync`；Rust 服务以强类型值注册，TS 插件注册的服务以 `Root<JsValue>` 承载（见 8.4 节）。
- 绑定完成后，服务调用是直接方法调用，内核只负责解析与注入（[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) §5.1）。
- 销毁中的 Context 拒绝注册类调用；已销毁返回 `KERNEL_CONTEXT_DISPOSED`，销毁操作幂等。
- **服务版本裁决**：不设独立服务版本号。Rust 服务为内核 ABI，随平台版本；插件间服务消费由 manifest `dependencies` 版本范围 + 能力契约版本约束（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §7.1）。
- **重建收敛**：注入与重建回环必须有收敛上限；重建深度 ≤ 16，超限以 `KERNEL_REBUILD_OVERFLOW` 拒绝并记录诊断。
- 提供方进入 `Failed` 时依赖方保持 `Active`：服务条目摘除、注入回到 `Waiting`，调用返回 `KERNEL_SERVICE_NOT_FOUND`；提供方恢复后按拓扑重建。

### 4.2 Fork

Fork 是副作用追踪与撤销单元；插件加载、注入回调、Context 各自持有 Fork。

```rust
pub type ForkId = u64;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ForkState {
    /// 可登记副作用。
    Active,
    /// 正在撤销，拒绝新登记。
    Disposing,
    /// 已撤销，终态。
    Disposed,
}

pub struct Fork {
    /* 字段与登记表见 01-薯片内核设计 4.1 */
}

impl Fork {
    /// 撤销本 Fork 的全部副作用。
    ///
    /// 顺序：先递归销毁子 Fork（后序），再按登记逆序（LIFO）撤销自身副作用。
    /// 幂等；单个副作用撤销失败不中断流程，返回首个错误。
    pub fn dispose(&mut self, kernel: &Kernel) -> Result<(), KernelError>;
}
```

| 成员 | 语义 |
|---|---|
| `ForkState::Active` | 可登记；撤销入口固定为 `dispose` |
| `ForkState::Disposing` / `Disposed` | 拒绝新登记；`Disposed` 后不可复用 |
| `dispose` | 幂等、容错、不重入；失败以 `KERNEL_DISPOSE_FAILED` 上报审计（[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) §4.4） |

生命周期超时（常量定义在内核文档，其他文档只引用）：

| 阶段 | 超时 | 超时行为 |
|---|---|---|
| `apply` | 30s | 强制撤销并报 `KERNEL_LIFECYCLE_TIMEOUT` |
| `stop` | 10s | 强制撤销并报 `KERNEL_LIFECYCLE_TIMEOUT` |
| Fork 强撤 | 30s | 聚合上报 `KERNEL_LIFECYCLE_TIMEOUT` 与 `KERNEL_DISPOSE_FAILED` |

副作用登记入口固定：服务注册走 `provide`，事件监听走 `on` / `once`，自定义清理走 `ctx.effect`，长任务走 `ctx.task`；内核不提供绕过追踪的注册方式。

### 4.3 Kernel（运行时句柄）

`Kernel` 持有命令循环、Context 树与全部注册表；平台启动时创建，生命周期与主进程一致。公开的读取方法：

```rust
impl Kernel {
    /// 按 Context 作用域链查找服务。
    pub fn get_service(&self, from: ContextId, name: &str) -> Result<ServiceValue, KernelError>;

    /// 类型化获取；类型不匹配返回 `KERNEL_SERVICE_TYPE_MISMATCH`。
    pub fn get_typed<T: Any + Send + Sync + 'static>(
        &self,
        from: ContextId,
        name: &str,
    ) -> Result<Arc<T>, KernelError>;
}
```

插件代码不直接持有 `Kernel`；内核启动、命令循环与并发模型见 [01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) 第十章。

### 4.4 插件作者可见的 Context API（TypeScript）

插件通过 `@chips/sdk` 的 `Context` 类型使用内核能力；插件入口由内核在 Starting 阶段调用（签名 `apply(ctx: Context): void | Promise<void>`）。

```typescript
type EventListener<TPayload> = (payload: TPayload) => void;

interface IEventSubscription {
  /** 退订；幂等。 */
  dispose(): void;
}

interface ITaskOptions {
  /** 任务名；用于诊断、配额计量与审计。 */
  name?: string;
  /** 额外的取消信号；内核取消（Fork 撤销、配额停用）同时生效。 */
  signal?: AbortSignal;
}

interface ITaskHandle<T> {
  readonly name: string | undefined;
  /** 可等待结果；任务取消以 ChipsError（KERNEL_CONTEXT_DISPOSED / KERNEL_LIFECYCLE_TIMEOUT 等）reject。 */
  readonly result: Promise<T>;
  /** 请求取消；幂等。 */
  cancel(): void;
}

interface Context {
  /** 注册服务；同名替换旧实现。 */
  provide<T>(name: string, value: T): void;

  /** 声明依赖并注入回调；撤销由内核按依赖与 Fork 生命周期执行。 */
  inject(dependencies: readonly string[], callback: (ctx: Context) => void): void;

  /** 按作用域链获取服务；未注册返回 undefined。 */
  get<T>(name: string): T | undefined;

  /** 订阅事件；监听器随当前 Fork 自动退订。 */
  on<TPayload>(event: string, listener: EventListener<TPayload>): IEventSubscription;

  /** 订阅一次；首次投递后自动退订。 */
  once<TPayload>(event: string, listener: EventListener<TPayload>): IEventSubscription;

  /** 同步广播事件；无监听器零分配。 */
  emit<TPayload>(event: string, payload: TPayload): void;

  /** 登记自定义清理逻辑；随当前 Fork 撤销。 */
  effect(cleanup: () => void): void;

  /** 登记长任务到当前 Fork；参与配额与取消，对应内核 Effect::Task。 */
  task<T>(fn: (signal: AbortSignal) => T | Promise<T>, options?: ITaskOptions): ITaskHandle<T>;
}
```

| 成员 | 语义 | 失败 |
|---|---|---|
| `provide` | 服务立即生效；撤销时按代际匹配 | 名称非法、Context 销毁 → 抛 `ChipsError` |
| `inject` | 依赖就绪后在注入 Fork 中执行回调；依赖失效时撤销回调与其副作用，恢复后重建 | 依赖声明非法 → 抛 `ChipsError` |
| `get` | 内核 `Context::get` 的 TS 视图；泛型参数只作编译期声明，不做运行时校验 | 已销毁 → 抛 `KERNEL_CONTEXT_DISPOSED` |
| `on` / `once` | 形状与派发语义见 [09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md) §2.5 | 事件名非法 → 抛 `ChipsError` |
| `emit` | 同步广播；允许重入，嵌套深度上限 64 | 超限 → `KERNEL_EVENT_DEPTH_EXCEEDED` |
| `effect` | 登记清理闭包；不可单独撤销，随 Fork 撤销 | 已销毁 → 抛 `ChipsError` |
| `task` | 任务登记到当前 Fork；参与插件软配额（任务数、后台时长）与取消；`result` 可等待，取消以 `ChipsError` reject | 已销毁或配额超限 → 抛 `ChipsError` |

规则：

- 依赖列表中的服务在注入回调内同时以属性形式暴露（如 `ctx.image`）；属性访问等价于 `get`，类型由 `@chips/sdk` 的声明合并提供（见 [02-SDK-API规范](02-SDK-API规范.md)）。
- 回调内不得缓存跨代际的服务引用；长期任务必须挂到注入 Fork（[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) §5.3）。
- 角色接口按角色扩展内核 `Context`：`IServiceContext` 以内核 `Context` 成员为基础增加能力注册、配置与日志；`IAppContext` 不是 Cordis `Context`，只承载实例标识、表面与启动参数（服务注入与内核事件面由构造期 `Context` 提供）。完整形状见 [07-应用插件接口](07-应用插件接口.md)、[10-服务插件接口](10-服务插件接口.md)。
- 插件代码的异常与 panic 在内核边界被捕获；插件必须按 `ChipsError.code` 分支处理，禁止匹配 `message` 文本。

示例：

```typescript
import type { Context, IEventSubscription } from '@chips/sdk';

interface IDocumentChangedPayload {
  uri: string;
  kind: 'card' | 'box';
}

interface IIndexService {
  enqueue(uri: string): Promise<void>;
}

/** 插件入口：由内核在 Starting 阶段调用。 */
export function apply(ctx: Context): void {
  ctx.provide<IIndexService>('index', createIndexService());

  ctx.inject(['index'], (injected) => {
    const subscription: IEventSubscription = injected.on<IDocumentChangedPayload>(
      'document:changed',
      (payload) => {
        void injected.get<IIndexService>('index')?.enqueue(payload.uri);
      },
    );

    // 监听器随注入 Fork 自动退订；此处仅演示显式持有句柄。
    void subscription;
  });

  ctx.effect(() => {
    // 自定义清理：随插件 Fork 撤销。
  });
}

function createIndexService(): IIndexService {
  return {
    async enqueue(uri: string): Promise<void> {
      await Promise.resolve(uri);
    },
  };
}
```

### 4.5 Context 的 Neon 绑定面

绑定层以 `JsBox<Context>` 传递上下文句柄；插件入口的 JS `ctx` 由适配层封装（见 8.7 节）。导出函数如下，函数名与 8.6 节总表一致：

| 导出函数 | 参数 | 返回 | 语义 |
|---|---|---|---|
| `contextProvide` | `(handle, name, value)` | `void` | 注册服务；失败抛 `ChipsError` |
| `contextInject` | `(handle, dependencies, callback)` | `number`（注入 ID） | 回调在 JS 线程调用，参数为 `JsBox<Context>` |
| `contextGet` | `(handle, name)` | `unknown \| undefined` | 未注册返回 `undefined` |
| `contextOn` | `(handle, event, listener, once)` | `number`（监听令牌） | 令牌低于 2^53 |
| `contextUnsubscribe` | `(handle, token)` | `void` | 幂等；插件可见面仍是 `IEventSubscription.dispose()` |
| `contextEmit` | `(handle, event, payload)` | `void` | 同步广播 |
| `contextEffect` | `(handle, cleanup)` | `void` | 清理闭包随 Fork 撤销 |

### 4.6 `PluginConfig`（插件配置注入）

内核在 `apply` 前把插件命名空间的生效值视图加载完成并以 `PluginConfig` 注入；配置只在加载时读取一次，运行期变更经 `config:changed` 事件与 `ctx.config` 重新读取（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §3、§6）。

```rust
/// 插件命名空间生效值视图；默认值已合并，键为相对键。
pub struct PluginConfig {
    pub values: BTreeMap<String, serde_json::Value>,
}
```

```typescript
interface PluginConfig {
  /** 键为相对键（不含命名空间前缀）；值已合并 schema 默认值。 */
  readonly values: Readonly<Record<string, unknown>>;
}
```

- 加载时机：插件进入 `Starting` 且依赖就绪后、`apply` 调用前；加载失败（schema 非法、迁移失败）使插件启用失败（`CONFIG_*`）。
- 配置注入是只读快照；插件不得依赖快照与运行期配置的一致性，变更后必须重新读取。
- 唯一暴露路径：面向主进程经 Cordis 服务 `ctx.config`（以及注入的 `PluginConfig`），面向 Neon/渲染侧经 `config:*` 能力；不存在第三条路径（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §11.3）。
