# 卡片传输协议

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：`.card` / `.box` 在本地设备与内容服务器之间传输的权威协议：传输会话（创建、预签名、分片、断点续传、取消、恢复）、完整离线卡片与网络资源卡片的可逆改写与还原（含可逆恢复清单）、摘要与完整性校验、预签名与对象存储桶角色、传输队列与 `transfer:*` 事件映射、错误码与安全约束；不覆盖卡片/箱子的包结构语义、渲染链路与服务器产品设计。

---

## 一、定位与边界

### 1.1 定位

- 本文是卡片与箱子网络传输的唯一权威协议：完整离线卡片上传并生成网络资源卡片、网络资源卡片下载并还原为完整离线卡片、远程打开、箱子上传、客户端渲染产物上传，全部遵循本文。
- 协议由两部分组成：
  - **控制面**：传输引擎与内容服务器之间的 HTTPS JSON 接口，负责鉴权、会话、预签名、恢复清单、元数据、状态与提交；控制面不接收、不代理、不中继任何文档与资源字节。
  - **数据面**：传输引擎与对象存储之间的直传通道，上传使用预签名 `PUT`，下载使用预签名 `GET`（支持 `Range`）。
- 本地侧唯一执行者是**统一卡片传输引擎**（下称传输引擎）：上传时的相对路径→URL 改写、下载时的 URL→相对路径还原、恢复清单生成与消费、完整离线卡片重建，全部由传输引擎执行；任何插件不得自行替换 YAML 或 HTML 中的资源字段（[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §2.3）。
- 传输引擎是 Host 侧正式实现，运行于主进程侧并通过平台传输队列执行任务；其面向插件的绑定（服务名、能力 ID、SDK 导出名）按平台登记规则另行登记，不在本文定义。
- 传输是内容生态的公共契约：社区服务器与个人服务器共用同一控制面协议、同一网络资源卡片格式、同一可逆恢复清单与同一下载计划语义。

### 1.3 术语

| 术语 | 定义 |
|---|---|
| 传输引擎（transfer engine） | Host 侧统一卡片传输实现：执行本文协议，是改写与还原的唯一执行者 |
| 控制面（control plane） | 传输引擎与内容服务器之间的 HTTPS JSON 接口集合 |
| 数据面（data plane） | 传输引擎与对象存储之间的预签名直传通道 |
| 传输会话（transfer session） | 一次上传或下载的控制面上下文；上传会话由服务器创建并持有状态，下载会话由服务器创建并提供可重复获取的计划 |
| 传输队列（transfer queue） | Host 侧统一调度传输任务的机制，卡片传输任务与平台传输能力共用一个队列 |
| 传输任务（transfer task） | 队列中的一个工作单元，拥有不透明 `transferId`，对应一次上传、完整下载、远程打开或箱子上传 |
| 传输对象（transfer object） | 会话内一个待上传或待下载的字节对象（资源、网络资源卡片、箱子源文件、渲染产物文件、封面文件） |
| 对象角色（object role） | 传输对象在协议中的语义：`network-card` / `resource` / `box-file` / `render-file` / `cover-file` |
| 桶角色（bucket role） | 对象存储桶在协议中的职责与可见性分类，见第六节 |
| 对象键（object key） | 对象在桶内的唯一路径；由服务器生成，对客户端不透明 |
| 预签名（presign） | 服务器为单个对象或分片签发的限时上传/下载地址及其方法、头与有效期 |
| 传输对象引用（objectRef） | 服务器为已预签名的传输对象分配的会话内不透明标识 `objectId` |
| 分片（part） | 大对象按服务端给定大小切分后的字节段；分片按序拼接构成完整对象 |
| 检查点（checkpoint） | 传输引擎为断点续传保存的最小本地恢复记录，见 3.5、3.9 |
| 断点续传（resume） | 中断后按服务端权威状态与本地检查点继续未完成对象/分片/字节的行为 |
| 恢复清单（restore manifest） | 随上传提交、随卡片版本持久化的可逆转换记录；下载还原的唯一依据，见 4.4 |
| 完整离线卡片 | 资源字节保存在 ZIP 内部的正式卡片形态（[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §2.1） |
| 网络资源卡片 | 资源字节不在 ZIP 内部、资源字段记录对象存储/CDN URL 的正式卡片形态（同前 §2.2） |
| 渲染产物（render artifacts） | 客户端渲染的查看产物（`render-file`）与封面产物（`cover-file`），只在客户端渲染模式上传 |
| 可见性（visibility） | 服务器侧内容可见性（公开 / 私有）；决定桶角色与产物访问方式 |

### 1.4 协议版本

- 控制面请求与响应中不携带独立协议版本头；会话创建响应、下载计划与恢复清单携带 `schemaVersion`，当前值为 `1.0.0`。
- `schemaVersion` 是传输载荷结构版本，独立于卡片格式版本 `chip_standards_version` 与平台版本；三者语义与升级影响以[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md)为边界。
- `schemaVersion` 变更走 RFC 与评审（[03-变更与决策管理](../07-工程管理/03-变更与决策管理.md)）；不提供多版本并存与运行时降级。
- 客户端发现响应中的 `schemaVersion` 主版本高于其支持版本时拒绝该响应（`CARD_TRANSFER_RESPONSE_INVALID`）。
