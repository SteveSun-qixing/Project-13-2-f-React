## 十二、约束与不变量

1. **全表唯一**：内置能力只能来自第 6.2 节全表；所有能力 ID 必须为已登记标识，未登记 ID 不得注册、不得调用；能力增删必须经 RFC 评审后同步更新本规范第 6.2、第七与第八节。
2. **命名隔离**：能力 ID 与权限 ID 命名空间独立，禁止相同标识；domain 由平台登记分配，插件不得自造。
3. **注册即校验**：ID 登记与 owner、schema、权限四类校验全部通过才可写入注册表；失败原子拒绝。
4. **权限最小化**：能力只声明基础权限 ID；授权、限定值匹配与审计归权限系统，能力不得绕过。
5. **输入强约束**：schema 只描述输入且必须离线可编译、显式 `additionalProperties: false`；输出不做运行时校验。
6. **无枚举 API**：插件侧能力发现为编译期类型 + 静态声明 + 调用期错误语义；平台工具经内部编目只读查询。
7. **单一代际**：同一能力 ID 同时只有一个生效注册，无版本协商与多版本共存。
8. **生命周期绑定**：注册随提供方 Fork 生效与撤销；注销先拒新调用、再收口在途。
9. **错误只认 code**：调用方按 `ChipsError.code` 分支；业务错误码遵守 `<DOMAIN>_<REASON>`。
10. **文档同步**：本规范与 [02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md)、[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md)、[01-Bridge-API规范](./01-Bridge-API规范.md)、[02-SDK-API规范](./02-SDK-API规范.md) 必须同 PR 更新，接口改动不得只改一处。
11. **内容处理不双轨**：内容处理类实现只以 Cordis 服务提供，不注册为 Bridge 能力、不进入第 6.2 节全表；其登记以第八节为唯一权威。
