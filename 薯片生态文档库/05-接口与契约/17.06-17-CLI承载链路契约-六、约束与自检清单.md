> 版本：v1.0.0
> 日期：2026-09-21
> 状态：正式版
> 适用范围：`chips` CLI 进程与宿主承载环境之间跨进程承载链路的唯一权威契约：传输形态（UDS / Windows named pipe）、端点发现（承载登记文件与单一派生源）、握手与消息封套、鉴权与权限判定、路由面、按需启动与错误面；不覆盖 §5.8 路由负载字段语义（权威在《07-CLI 完整参考》§5.8）、命令系统「启动并投递」语义（权威在《13-命令系统契约》§4.4）与 Bridge 内部 IPC 通道（权威在《02-Bridge 三层设计》§7.1）。

## 六、约束与自检清单

### 6.1 不变量

1. 协议字面量、发现文件形状、封套别名、reason 词表、端点派生纯函数**只存在于 `@chips/bridge` 协议分件一处**；任何消费者（host/cli/sdk/测试）出现第二份定义即为违例。
2. `cli.*` 服务路由永不进 Bridge 能力注册表；能力 ID 面 `cli:task-*` 与路由名 `cli.task.*` 永远正交（§4.4-4）。
3. 承载链路零新错误码族：用户可见码一律取自现行 §2.5 表；`details.reason` 词表封闭于 §5.3 六值，扩值须改本契约并递增文档版本。
4. 发现文件删除权只属于宿主写入方（启动前清陈旧 + 停机自删）；CLI 侧只读（§2.5-4）。
5. 握手（含 token 校验）先于且强于一切路由调用；路由调用仍逐次过 §4.4 三门；「进门」永不等「放行」。
6. 单实例锁语义不因承载链路松动：任何波次不得为 CLI 造旁路宿主实例形态。
7. 「不防同用户进程」是在册威胁模型边界（§4.1），实现与后续文档不得宣称密码学进程身份。

### 6.2 自检清单（实现波验收对照）

- [ ] `deriveCarrierEndpoints` 双侧（host/CLI）契约测试锁字节级一致；darwin 超限缩短与 fail-closed 有臂。
- [ ] 发现文件：原子写、`0600/0700`、未知字段拒绝、双判据陈旧、停机顺序（先断入站再毁地址）逐臂有测。
- [ ] 握手：`protocol_mismatch` / `token_invalid` / `handshake_timeout` / `instanceId` 错位四臂；token 常量时间比较。
- [ ] 封套：`requestId` 关联、非在册 `routeId` 拒绝、handler 级既有码如实透传、序列化 camelCase/epoch 毫秒抽查。
- [ ] 路由面：§5.8 全 11 条 + `command:invoke` 逐一可达且负载与 §5.8 表逐字段一致；索引四事件重建钩子。
- [ ] 按需启动：解析成功拉起、解析失败 3、超时 9、dev 工作区必然解析不出且不漂移全局 bin。
- [ ] 回退链：崩溃在途 6（`connection_lost`）、重启任务 `CLI_TASK_NOT_FOUND`、CLI 先死服务端会话回收、`job.cancelOnInterrupt` 不回归。
- [ ] 环境变量：`CHIPS_CARRIER_SOCKET` / `CHIPS_CARRIER_DISABLE` 严格错误语义两臂（5 / 2）与空串按未设置。
- [ ] 权限面：无授权记录目标的拒绝臂（`CLI_PERMISSION_DENIED` → 4）与「宿主不绕自家权限门」用例。
