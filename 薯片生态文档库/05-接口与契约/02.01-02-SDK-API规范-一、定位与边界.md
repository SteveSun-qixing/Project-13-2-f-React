## 一、定位与边界

### 1.1 定位

`@chips/sdk` 是插件开发工具包，向插件开发者提供四类内容：

| 类别 | 内容 |
|---|---|
| 类型定义 | 四种插件角色接口、文档模型、能力契约类型、内核上下文类型、Bridge 协议类型（转发 `@chips/bridge`） |
| 客户端封装 | 把 `window.chips`（`IChipsBridge`）包装为类型安全客户端：`chips`、`createClient`、`ChipsBridge` |
| 辅助函数 | 错误类型守卫 `isChipsError`、错误归一 `toChipsError` |
| 开发期工具 | 测试 Mock（`@chips/sdk/testing`）、脚手架生成器（`@chips/sdk/scaffold`） |

SDK 解决的是"插件如何以类型安全、可测试的方式使用平台"；平台能力本身不在 SDK 中实现。

### 1.2 不承载运行时

SDK 不得实现 Bridge 主逻辑、Cordis 运行时、文档解析、资源管理、权限判定等平台能力（[架构原则](../00-愿景与原则/01-架构原则.md)第 2.4 节）。具体约束：

- 不直接访问 Node.js、Electron、IPC 或文件系统；每个能力调用都转发给注入的 `IChipsBridge`。
- 不创建、不替换、不扩展 `window.chips`；只提供其类型与全局声明。
- SDK 内可执行代码仅限：客户端转发、`ChipsError`、辅助函数、测试工具、脚手架字符串生成——全部是开发期代码或薄转发，不含业务实现。
- SDK 对 `@chips/bridge` 只能 `import type`，不得产生运行时依赖（[代码组织规范](../02-开发规范/01-代码组织规范.md)第 4.2 节）。
