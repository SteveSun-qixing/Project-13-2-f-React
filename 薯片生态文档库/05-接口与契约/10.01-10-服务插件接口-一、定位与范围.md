## 一、定位与范围

### 1.1 定位

服务插件是四种插件角色中唯一无界面的角色：在主进程后台运行，通过 Cordis 服务与 Bridge 能力为其它插件和平台提供可复用功能（[ADR-005](../01-架构设计/ADR/ADR-005-插件不分类只分角色.md)、[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 2.3.4）。

服务插件的完整职责边界：

| 方向 | 入口 | 用途 |
|---|---|---|
| 提供能力 | `ctx.registerCapability(…)` | 注册 Bridge 能力，任意插件经 `request` 调用 |
| 提供服务 | `ctx.provide(name, service)` | 注册 Cordis 服务，其它插件经 `ctx.inject` 消费 |
| 消费平台 | `ctx.bridge`、`ctx.config`、`ctx.on` / `ctx.emit` | 出站能力与资源访问、配置读写、事件订阅与发布 |
| 生命周期 | `start` / `stop` / `health` | 平台调用；全部副作用纳入插件 Fork 追踪与撤销 |

```text
平台启用 service 插件
        │  starting：创建 Fork，调用 start(ctx)
        ▼
     active ── ctx.provide ──────────► 其它插件 ctx.inject 消费
        │      ctx.registerCapability ► 其它插件 Bridge request 调用
        │      周期 health() ─────────► 不健康 → 熔断 → 连续失败停用
        ▼
    stopping：调用 stop() → Fork.dispose() 撤销服务、能力、订阅、定时器
```

### 1.3 约定

- 本文接口类型（`IServicePlugin`、`IServiceContext`、`IServiceBridge` 等）均从 `@chips/sdk` 主入口导入，导出清单见 [02-SDK-API规范](./02-SDK-API规范.md) §2.2；服务插件代码在主进程运行，**不存在 `window.chips`**（[01-Bridge-API规范](./01-Bridge-API规范.md) 4.1）。
- 入口经受管模块加载器（ModuleLoader）加载；需要进程级隔离或重计算的服务逻辑由工具进程承载，见 §2.5。
- 一个插件只有一个角色；`manifest.type` 为 `service` 时入口模块必须实现 `IServicePlugin`（R1、ADR-005）。
- 示例中的能力 ID 与权限 ID 均为已登记标识；未登记标识不得出现在插件包中（[04-能力契约规范](./04-能力契约规范.md)）。
- 错误一律按 `ChipsError.code` 分支处理，禁止匹配 `message` 文本。
