## 七、配置 schema 约定

### 7.1 卡片配置的位置

卡片内容中与呈现相关的可调参数放在内容配置（`content/{10 位 Base62 编号}.yaml`）的 `config` 字段中（内容文件格式见[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md)）：

```yaml
# content/a1B2c3D4e5.yaml
card_type: base.richtext
content_format: markdown
content_source: inline
content_text: |
  薯片生态文档库
  基础卡片插件的最小完整实现。
markdown_capabilities:
  commonmark: true
  gfm: true
  math: true
  highlight: true
  underline: true
  superscript: true
  subscript: true
config:
  fontSize: 16
  lineHeight: 1.6
```

规则：

1. `config` 是不透明映射：解析器不解释其语义，只原样保留（[06-文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md) §6.3）。
2. `renderView` / `renderEditor` 从 `basecard.content.config` 读取；缺失或非法时必须回退到插件内置默认值，保证渲染不因配置问题失败。

### 7.2 `configSchema`

1. 卡片类型通过 `capabilities.cardTypes[].configSchema` 声明 JSON Schema（2020-12 方言），描述 `config` 对象。
2. 文件位于插件包内，路径为包内相对路径且目标位于 `assets/` 内（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) 2.6）；顶层必须为 `type: object`；字段约束、默认值与未知字段策略由插件定义（建议 `additionalProperties: false`）。
3. 禁止远程 `$ref` 与外部网络解析；允许文档内 `#/...` 引用。
4. 该文件只描述卡片内容配置；插件自身设置使用 `assets/schemas/config.schema.json`，两者不是同一文件（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) §4.1）。

### 7.3 `validateConfig` 与 schema 的关系

`configSchema` 与 `validateConfig` 是同一规则的两处实现：平台用 schema 做通用校验，插件用函数实现需要业务逻辑的补充校验。两者都必须通过；`validateConfig` 不得比 schema 宽松。

### 7.4 校验时机

| 时机 | 执行方 | 行为 |
|---|---|---|
| 解析 | 文档解析器 | 不校验插件配置，只保证内容根映射与不透明值可用（部分成功） |
| 编辑变更 | 插件编辑器 | 可调用 `validateConfig` 实时提示，允许中间非法态 |
| 回流 / 保存前 | 编辑链路 | 执行 `configSchema` 校验与 `validateConfig`，任一失败拒绝回流并给出简体中文提示 |
| 创建 / 导入 | 编辑链路 / 应用插件 | 按 schema 校验初始配置 |
| 导出 | 导出链路 | 不强制校验；插件在 `export` 内按自身规则回退或拒绝 |
