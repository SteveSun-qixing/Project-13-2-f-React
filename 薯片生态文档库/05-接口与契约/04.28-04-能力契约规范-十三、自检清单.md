## 十三、自检清单

- [ ] 第 6.2 节全表为平台 Bridge 能力登记的权威副本，64 项能力无未登记 ID、无重命名。
- [ ] 每项内置能力在第七节都有输入 schema 要点、输出类型与调用示例。
- [ ] 所有能力 ID 符合 `<domain>:<action>[:<target>]`，所有权限 ID 符合 `<domain>:<scope>[:<qualifier>]`，无重名。
- [ ] `ICapabilityContracts`（第 2.3 节）覆盖全表 64 项 Bridge 内置能力；输入/输出接口与各域定义一致。
- [ ] 二进制字段一律经 `x-chips-binary` 与 `bin` 表承载，无内联 base64 兜底（第 2.4 节）。
- [ ] schema 均使用第五节允许的关键字；无远程 `$ref`、无 `any`、无未声明字段。
- [ ] 注册校验覆盖 ID 登记、owner、冲突、schema、权限五类，错误码与第 11 节一致。
- [ ] 第三方 Bridge 能力登记前置、语义域分配、冲突矩阵、发现面与实现约束完整可执行。
- [ ] 内容处理服务能力已在第八节登记表登记（13 项、4 个服务）：能力 ID 为 `<service>.<operation>` 点号文法，服务名 `content-` 前缀与插件 `chips.service.*` 命名空间明确，输入/输出与错误码族齐全，且未以 Bridge 能力或旧模块 ID 形式出现。
- [ ] 内容处理提供方契约、`file-processing` 描述符（[15-文件处理契约](./15-文件处理契约.md) §4.2）与第八节登记表三处一致。
- [ ] 生命周期状态、蓝绿代际接管与版本规则与插件架构、Bridge 设计一致。
- [ ] 各域业务错误码与本表权威文档不冲突、不重复定义。
- [ ] 本文与 [02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md)、[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 的能力/权限口径完全一致。
