## 五、布局配置模型

### 5.1 `content.yaml` 中的 `layout_configs`

箱子可同时保存多个布局的配置，全部集中在 `content.yaml` 的 `layout_configs` 映射中；当前生效项由 `metadata.yaml` 与 `content.yaml` 的 `active_layout_type` 标识（两处必须一致）。结构与 schema 以 [02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) 第六节为准。

```yaml
# .box/metadata.yaml（节选）
active_layout_type: "chips.layout.grid"
```

```yaml
# .box/content.yaml（节选）
active_layout_type: "chips.layout.grid"
layout_configs:
  chips.layout.grid:
    schema_version: "1.0.0"
    props:
      columns: 3
      gap: 16
      itemHeight: 200
    asset_refs:
      - "assets/layouts/grid/background.webp"
```

`schema_version` 必填，语义为该配置由哪个配置 schema 版本写入：由布局插件编辑器在 `LayoutChange` 的 `replace` 中给出（第 7.1、7.2 节），经编辑链路回流写入、由平台持久化；打开箱子时由平台以插件 manifest 的 `capabilities.layouts[].schemaVersions` 做兼容门禁（第 2.2 节步骤 2）。配置结构（`props`）由插件 `capabilities.layouts[].configSchema` 描述（[02-插件清单规范](../03-插件开发/02-插件清单规范.md) 7.3）。

### 5.2 字段映射

| `BoxRenderView` 字段 | 来源 |
|---|---|
| `active_layout_type` | `.box/metadata.yaml` 的 `active_layout_type`（与 `content.yaml` 一致） |
| `layout_config` | `.box/content.yaml` 的 `layout_configs.<active_layout_type>.props` |

规则：

- 未找到生效布局的配置项时 `layout_config` 为空对象；插件必须能用内部默认值渲染。
- 生效配置项存在时 `schema_version` 必须通过插件 `schemaVersions` 门禁；缺失、非法或超出范围时平台按 `RENDER_SCHEMA_UNSUPPORTED` 降级占位，不调用插件（第 2.2 节步骤 2）。
- 配置字段缺失或非法时，插件必须逐字段回退内部默认值，不得阻断渲染（`validateConfig` 只服务编辑链路的回流与保存门禁）。
- 切换布局只切换 `metadata.yaml` 与 `content.yaml` 的 `active_layout_type` 及对应配置，不修改条目集合（ADR-005）。
- 未知布局类型的配置不影响箱子打开；由渲染层按插件缺失规则降级。

### 5.3 配置约束

- 值域：仅 JSON 兼容且可结构化克隆的值（字符串、数字、布尔、`null`、数组、对象）；禁止函数、类实例、`Date`、`Map`、`Set`。
- 禁止持久化：绝对路径、`file://` 与临时运行时 URI、会话 ID、凭证、资源句柄、平台内部路径。
- 箱子自有资源位于包内 `assets/`：配置引用的箱子资源必须是 `asset_refs` 中、以 `assets/` 开头的包内相对路径，不得指向包外；布局插件自身的静态素材随 `.cpk` 分发，两类资源不得混用。
- 配置校验在编辑链路回流与保存前执行：先以插件 `capabilities.layouts[].configSchema` 做结构校验，再调用 `validateConfig` 做语义校验，任一失败拒绝回流并给出简体中文提示（第 7.2 节；基础卡片侧同规则见[08-基础卡片插件接口](08-基础卡片插件接口.md) 7.4）。
