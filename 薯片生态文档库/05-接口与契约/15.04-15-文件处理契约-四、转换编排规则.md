> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：通用文件处理（`.card` / `.box` 文档之外的普通文件）的会话与转换编排契约：`file-processing` 服务、打开/预览/转换/另存/比较操作、进度与取消、受控提交与原子替换、大文件流式、错误码与边界；不定义具体格式算法、支持矩阵与原子能力实现

## 四、转换编排规则

### 4.1 阶段职责

本节阶段模型适用于 `convert` 与 `saveAs`；`preview` 与 `compare` 不产生产物，使用 `prepare` → `transform` → `completed`（无 `stage` / `publish` / `cleanup` 阶段，百分比按 §3.7 直接前进）。

| 阶段 | 职责 | 失败语义 |
|---|---|---|
| `prepare` | 归一输入、复查版本戳、选择提供方、创建暂存区 | 版本变化 `FILE_PROCESS_SOURCE_CHANGED`；无提供方 `FILE_PROCESS_PROVIDER_MISSING`；组合不支持 `FILE_PROCESS_TARGET_UNSUPPORTED` |
| `transform` | 调用内容处理服务完成解码/转换/编码；可多步串联 | 原子服务失败归一为 `FILE_PROCESS_TRANSFORM_FAILED`（`details.cause` 保留原始错误） |
| `stage` | 暂存产物落盘、尺寸与摘要计算、提供方声明的可读性校验 | 校验失败 `FILE_PROCESS_TRANSFORM_FAILED`（`details.stage = 'stage'`） |
| `publish` | 经受控提交把暂存产物原子发布到目标 | 目标已存在 `FILE_PROCESS_OUTPUT_EXISTS`；写出/替换失败 `FILE_PROCESS_WRITE_FAILED` |
| `cleanup` | 删除暂存产物与中间目录 | 清理失败只写审计，不改变操作结果 |
| `completed` | 上报 100%，返回结果 | — |

### 4.2 提供方选择与支持矩阵

- 文件处理服务在 manifest `dependencies` 中静态声明其可用的内容处理服务提供方，并在激活时 `ctx.inject` 注入；不支持的组合在 `prepare` 阶段确定性拒绝。
- 原子能力描述符（`sourceFormats` / `targetFormats` / `operations` / `streaming` / 输入上限）、服务名与命名空间由提供方按 [04-能力契约规范](./04-能力契约规范.md) §八 登记与发布；文件处理服务只消费，不改写、不探测式回退。
- 支持矩阵、格式选项语义与警告码随提供方契约发布；本契约不维护第二份矩阵。
- 提供方不可用（未激活、崩溃、draining）时返回 `FILE_PROCESS_PROVIDER_MISSING`（`retryable: true`）；平台不提供静默降级到其他实现或内置兜底算法的路径。

### 4.3 受控提交与原子替换

产物发布只走资源管理器受控提交（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) §4.8）：

1. ≤ 8 MiB 用一次性提交；> 8 MiB 用流式提交（分块 + 背压）。
2. `output.overwrite` 默认 `false`；目标已存在且未允许覆盖时返回 `FILE_PROCESS_OUTPUT_EXISTS`，不写任何字节。
3. `overwrite: true` 时先完整写入同级临时物，校验通过后一次原子替换；替换失败保留原目标并返回 `FILE_PROCESS_WRITE_FAILED`。
4. 临时物使用平台保留前缀、与目标同卷、位于目标同级；绝不进入用户文件树、不被扫描、不被解析器索引（[13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §3.2）。
5. 提交纳入 WriteCoordinator 同一路径锁；同一路径同一时间只有一个写者。
6. 发布成功后服务返回最终产物的 `outputUri` / `size` / `digest`；`digest` 必须基于**已发布字节**重新计算（流式计算），不得复用暂存阶段摘要。
7. 归档来源不可作为通用产物目标（`RESOURCE_READ_ONLY`）；document 挂载内路径不得作为本契约目标，文档产物写回经 `document:*`。

### 4.4 暂存物与清理

- 暂存区位于提供方插件作用域（可重建缓存区）或平台临时作用域；禁止写入用户工作区、目标同级目录或 `.chips/` 保留区。
- 暂存目录按会话隔离（如 `<plugin-scope>/cache/file-processing/<sessionId>/`），会话关闭时删除；提供方缓存策略与容量受插件作用域治理。
- 平台受控提交使用的临时物、备份与提交日志由资源管理器清理（[11-文档服务设计](../01-架构设计/01-子系统设计/11-文档服务设计.md) §5.2 同口径）；提供方不得自行在目标目录旁创建临时物。
- 崩溃残留：插件作用域缓存与平台临时作用域均由平台启动恢复流程清理；会话不提供跨重启恢复。

### 4.5 失败与回滚

| 失败点 | 目标状态 | 暂存物 | 会话状态 |
|---|---|---|---|
| `prepare` 失败 | 未触碰 | 无或已清理 | `opened` |
| `transform` 失败 | 未触碰 | 清理 | `opened` |
| `stage` 校验失败 | 未触碰 | 清理 | `opened` |
| `publish` 提交前失败 | 未触碰 | 清理 | `opened` |
| `publish` 提交中失败 | 原目标保留（原子替换语义） | 平台清理 | `opened` |
| 取消 | 未触碰 | 清理 | `opened` |
| 来源变化 | 未触碰 | 清理 | stale |

- 任何失败都不得产生半写产物、残留暂存物或"目标新、来源旧"的混用状态。
- 失败错误一律归一为本契约错误码；底层 `RESOURCE_*` / `KERNEL_*` / 提供方错误写入 `details.cause`，调用方只按本域码分支（与 [11-文档服务设计](../01-架构设计/01-子系统设计/11-文档服务设计.md) §10.3 同口径）。

### 4.6 可重试判定

| 类别 | 错误码 | 重试指引 |
|---|---|---|
| 可重试 | `FILE_PROCESS_BUSY`、`FILE_PROCESS_PROVIDER_MISSING`、`FILE_PROCESS_CANCELLED`、`FILE_PROCESS_TRANSFORM_FAILED`（`details.retryable` 为真时）、`FILE_PROCESS_PREVIEW_FAILED`、`FILE_PROCESS_WRITE_FAILED` | 按退避重试；重试前必须重新读取来源状态 |
| 不可重试（需更换输入） | `FILE_PROCESS_SOURCE_UNSUPPORTED`、`FILE_PROCESS_TARGET_UNSUPPORTED`、`FILE_PROCESS_OPTION_INVALID`、`FILE_PROCESS_OUTPUT_TOO_LARGE`、`FILE_PROCESS_INPUT_TOO_LARGE` | 调整格式、选项或尺寸后重试 |
| 不可重试（需用户动作） | `FILE_PROCESS_OUTPUT_EXISTS`、`FILE_PROCESS_SOURCE_CHANGED` | 征求覆盖确认或重新打开来源 |
| 不可重试（编程错误） | `FILE_PROCESS_SESSION_NOT_FOUND`、`FILE_PROCESS_SESSION_CLOSED` | 修正会话使用方式 |
