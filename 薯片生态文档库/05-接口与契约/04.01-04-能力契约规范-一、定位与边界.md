## 一、定位与边界

### 1.1 定位

本文是薯片生态**能力体系的唯一契约权威**：平台的每一项 Bridge 能力（内置能力与第三方服务插件注册的能力）都必须以本文规定的模型、命名、schema 与权限映射登记并经注册后才可被调用；内容处理服务能力不进入 Bridge 注册表，按第八节登记并由 `service` 插件以 Cordis 服务提供。`R19 内置能力与权限总表`（编写基准第三节）在本规范内全文固化并随平台能力登记持续维护；任何能力增删或调整都必须经 RFC 评审后同步更新本规范（第 6.2、6.3、8、9、10 节）。

### 1.3 术语

按《文档库编写基准》第四节统一术语表执行。本文额外约定：

| 术语 | 含义 |
|---|---|
| 能力契约 | 一项能力的 ID、输入 schema、输出类型与所需权限构成的稳定约定 |
| 能力登记 | 把能力 ID、提供方绑定、schema、输出类型与所需权限写入平台能力契约数据；内置能力登记于第 6.2 节，第三方 Bridge 能力经评审登记（第九节），内容处理服务能力按第八节登记 |
| 基础权限 ID | `<domain>:<scope>` 形式、不带限定值的权限 ID；能力声明只使用基础形式 |
| 限定值 | 权限 ID 第三段 `<qualifier>`；只存在于 manifest 申请与授权记录，判定时与实际调用目标比对 |
| 能力族 | 以 `*` 目标占位表示的同类能力集合（仅内置表出现），注册表只注册具体目标 |
| 提供方 | 能力的实现者：平台服务域或服务插件（反向域名插件 ID） |
| 消费者 | 经 `window.chips.request` 调用能力的插件或平台组件 |
