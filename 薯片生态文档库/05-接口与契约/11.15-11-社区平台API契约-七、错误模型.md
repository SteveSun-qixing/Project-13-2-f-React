# 社区平台 API 契约

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片社区平台服务端（`Chips-CommunityPlatformServer`）对外 HTTP API 的唯一权威契约：基础约定、认证与令牌、内容浏览与检索、管理端接口、卡片与箱子传输控制面、分页/幂等/限流、错误模型与错误码、版本兼容、TLS/CORS/路径安全、示例与自检清单；不覆盖社区网页与后台的产品设计、服务端实现与部署运维，不覆盖个人服务器差异（见 `12-个人服务器API契约`），不覆盖卡片传输的客户端协议细节（见 `16-卡片传输协议`）。

## 七、错误模型

### 7.1 HTTP 状态

| 状态 | 语义 |
|---|---|
| `200` | 成功 |
| `201` | 资源或会话创建成功 |
| `202` | 已接受、异步处理中（查看入口在缓存未就绪时） |
| `204` | 成功且无正文（登出、刷新无会话、删除、对象分片中止） |
| `302` | 查看/封面入口重定向到缓存地址 |
| `304` | 条件请求命中缓存 |
| `400` | 请求参数或请求体不合法 |
| `401` | 未认证、令牌缺失/失效/过期 |
| `403` | 已认证但无权限 |
| `404` | 资源不存在或对当前请求者不可见 |
| `409` | 状态冲突（渲染未就绪、幂等键冲突、删除重复） |
| `410` | 会话已过期 |
| `413` | 对象、请求体或单作品超过大小上限 |
| `415` | MIME 类型不支持 |
| `422` | 语义校验失败（对象归属、大小/摘要不一致、版本不受支持） |
| `429` | 触发限流 |
| `500` | 服务端内部错误 |
| `503` | 服务暂不可用（维护、依赖不可用） |

### 7.2 错误信封

```json
{
  "error": {
    "code": "COMMUNITY_OBJECT_SIZE_MISMATCH",
    "message": "对象大小与预签名不一致",
    "details": { "expectedBytes": 1024, "actualBytes": 2048 },
    "retryable": false
  }
}
```

- `code` 只取 7.3 登记表的值；未登记业务码不得出现在响应中。
- `message` 一律简体中文且面向用户；`details` 为结构化诊断，不含令牌、预签名地址、真实文件系统路径与堆栈。
- `details.traceId` 用于服务端日志关联（见 2.4）。

### 7.3 业务码登记表

本表是社区平台业务码的唯一登记位置；`code` 采用 `<DOMAIN>_<REASON>` 形式并以 `COMMUNITY_` 统一标识来源。

| 错误码 | HTTP | retryable | 触发条件 |
|---|---|---|---|
| `COMMUNITY_VALIDATION_ERROR` | 400 | false | 参数、查询串或请求体不合法 |
| `COMMUNITY_AUTH_INVALID_CREDENTIALS` | 401 | false | 账号或口令错误 |
| `COMMUNITY_AUTH_USER_EXISTS` | 409 | false | 用户名或邮箱已注册 |
| `COMMUNITY_AUTH_ACCOUNT_LOCKED` | 403 | true | 账号锁定中 |
| `COMMUNITY_AUTH_TOKEN_MISSING` | 401 | false | 未携带 access token |
| `COMMUNITY_AUTH_TOKEN_INVALID` | 401 | false | access token 非法（签名、格式、吊销） |
| `COMMUNITY_AUTH_TOKEN_EXPIRED` | 401 | false | access token 过期；客户端触发刷新 |
| `COMMUNITY_AUTH_INSUFFICIENT_PERMISSION` | 403 | false | 已认证但权限不足（含非管理员访问后台） |
| `COMMUNITY_USER_NOT_FOUND` | 404 | false | 用户不存在 |
| `COMMUNITY_USER_ACCOUNT_DISABLED` | 403 | false | 账号被停用 |
| `COMMUNITY_ROOM_NOT_FOUND` | 404 | false | 房间不存在或不可见 |
| `COMMUNITY_ROOM_FORBIDDEN` | 403 | false | 非房间所有者执行管理操作 |
| `COMMUNITY_CARD_NOT_FOUND` | 404 | false | 卡片不存在或不可见 |
| `COMMUNITY_CARD_FORBIDDEN` | 403 | false | 非所有者执行卡片管理操作 |
| `COMMUNITY_CARD_VERSION_UNSUPPORTED` | 422 | false | 卡片 `chip_standards_version` 不受服务端支持 |
| `COMMUNITY_CARD_RENDER_NOT_READY` | 409 | true | 查看缓存未就绪 |
| `COMMUNITY_CARD_RENDER_ERROR` | 409 | true | 查看缓存生成失败 |
| `COMMUNITY_BOX_NOT_FOUND` | 404 | false | 箱子不存在或不可见 |
| `COMMUNITY_BOX_FORBIDDEN` | 403 | false | 非所有者执行箱子管理操作 |
| `COMMUNITY_BOX_VERSION_UNSUPPORTED` | 422 | false | 箱子 `chip_standards_version` 不受服务端支持 |
| `COMMUNITY_UPLOAD_SESSION_NOT_FOUND` | 404 | false | 上传会话不存在 |
| `COMMUNITY_UPLOAD_SESSION_EXPIRED` | 410 | false | 上传会话已过期 |
| `COMMUNITY_UPLOAD_SESSION_STATE_INVALID` | 409 | false | 会话状态不允许该操作（已完成或已中止） |
| `COMMUNITY_OBJECT_ROLE_INVALID` | 422 | false | 对象角色与内容类型不匹配 |
| `COMMUNITY_OBJECT_OWNERSHIP_MISMATCH` | 422 | false | 对象不属于本会话 |
| `COMMUNITY_OBJECT_PATH_INVALID` | 422 | false | `relativePath` 非法或重复 |
| `COMMUNITY_OBJECT_SIZE_MISMATCH` | 422 | false | 对象大小与预签名不一致 |
| `COMMUNITY_DOWNLOAD_SESSION_NOT_FOUND` | 404 | false | 下载会话不存在 |
| `COMMUNITY_DOWNLOAD_SESSION_EXPIRED` | 410 | false | 下载会话已过期 |
| `COMMUNITY_FILE_TYPE_INVALID` | 415 | false | MIME 或归档类型不支持 |
| `COMMUNITY_FILE_TOO_LARGE` | 413 | false | 对象或单作品超过配置上限（见 6.5）；`details` 携带 `limitKind` / `limitBytes` / `actualBytes` |
| `COMMUNITY_FILE_CORRUPT` | 422 | false | 归档不可读、必需文件缺失或摘要校验失败 |
| `COMMUNITY_IDEMPOTENCY_CONFLICT` | 409 | false | 幂等键相同但请求体不同 |
| `COMMUNITY_RATE_LIMITED` | 429 | true | 触发限流 |
| `COMMUNITY_SERVICE_UNAVAILABLE` | 503 | true | 维护或依赖不可用 |
| `COMMUNITY_INTERNAL_ERROR` | 500 | true | 未归一的服务端异常 |
| `COMMUNITY_RESPONSE_INVALID` | —（客户端侧） | true | 客户端侧归一码：响应信封、字段或业务码不符合本契约 |

### 7.4 ChipsError 映射

客户端消费方必须把 HTTP 失败归一为 `ChipsError`（构造与字段以 [02-SDK-API规范](./02-SDK-API规范.md) 与 [03-核心接口规范](./03-核心接口规范.md) 为准）：

| 层 | 归一结果 | 规则 |
|---|---|---|
| 未到达服务端（DNS、连接、TLS、超时） | `HTTP_REQUEST_FAILED`（经 `http:request`）或 `RESOURCE_NETWORK_FAILED`（经资源代理，`details.reason` 取 `dns` / `connect` / `tls` / `timeout`） | 沿用平台网络错误码，不再包装；`retryable` 按网络语义 |
| 服务端 5xx / 429 | 同名业务码（`COMMUNITY_SERVICE_UNAVAILABLE` / `COMMUNITY_INTERNAL_ERROR` / `COMMUNITY_RATE_LIMITED`） | `code` 与服务端返回一致；`retryable` 取服务端字段或表内值 |
| 服务端 4xx 业务失败 | 同名业务码 | `code` 与服务端返回一致；`details` 保留服务端 `details` 并附加 `httpStatus` |
| 响应不符合本契约（字段缺失、信封非法、业务码未登记） | `COMMUNITY_RESPONSE_INVALID` | 客户端侧归一码，登记于 7.3；`retryable: true`，并记录 `traceId` |
| 刷新返回 `204` | 不作为错误 | 清空本地会话，转入未登录态 |

映射规则：

1. **业务码不改名**：`COMMUNITY_*` 业务码在服务端、客户端与诊断日志中保持同名，禁止前缀改写或二次命名。
2. **只按 `code` 分支**：禁止匹配 `message` 文本；`retryable: false` 不得自动重试。
3. **凭证类错误**：`401` 先走 3.6 的自动刷新；刷新失败后把原始错误交给业务层，不得循环重试。
4. **诊断信息**：客户端记录 `code`、`httpStatus`、`traceId` 与请求路径，不记录令牌、预签名与请求体中的敏感内容。

### 7.5 处理规则

- 服务端只返回已归一异常；内部异常必须转换为 `COMMUNITY_INTERNAL_ERROR` 并记录 `traceId`，不得回显内部堆栈与组件名。
- 管理端与前台共用同一错误模型与业务码；后台接口额外校验角色。
- 错误响应不得暴露私有资源的存在性（见 4.1）。
