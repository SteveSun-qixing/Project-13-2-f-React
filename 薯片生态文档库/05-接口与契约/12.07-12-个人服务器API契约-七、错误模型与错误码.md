> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片个人服务器（`Chips-PersonalServer`）对外 HTTP API 的唯一权威契约：单用户定位、`API_TOKEN` 鉴权与令牌管理、存储桶与对象键取值、内容接口（列表/详情/查看/封面/下载/删除）、卡片传输控制面、与社区平台 API 的差异、错误模型、限额与限流、TLS/CORS 与路径安全、示例与自检清单；不覆盖传输协议与客户端算法（见 [16-卡片传输协议](./16-卡片传输协议.md)）、个人服务器架构与部署（见 [08-服务端部署与运维](../06-开发与运维/08-服务端部署与运维.md)）与社区平台 API（见 [11-社区平台API契约](./11-社区平台API契约.md)）。

## 七、错误模型与错误码

### 7.1 HTTP 状态

| 状态 | 语义 |
|---|---|
| `200` | 成功 |
| `201` | 资源或会话创建成功 |
| `204` | 成功且无正文（删除、中止） |
| `302` | 查看/封面/封面重定向到产物地址 |
| `400` | 请求参数或请求体不合法、会话过期、箱子内容不合法 |
| `401` | 令牌缺失、格式错误或不匹配 |
| `404` | 资源不存在或对匿名访问者不可见 |
| `409` | 状态冲突（查看产物未就绪） |
| `413` | 对象或请求体超过大小上限 |
| `415` | 控制面请求 MIME 类型不支持 |
| `500` | 服务端内部错误 |
| `503` | 服务暂不可用（维护、依赖不可用） |

### 7.2 错误码登记表

个人服务器业务码不设来源前缀；控制面错误码与 [16-卡片传输协议](./16-卡片传输协议.md) §8.3 一致。本表是个人服务器业务码的唯一登记位置。

| 错误码 | HTTP | retryable | 触发条件 |
|---|---|---|---|
| `API_TOKEN_INVALID` | 401 | false | 令牌缺失、格式错误或不匹配 |
| `VALIDATION_ERROR` | 400 | false | 请求参数、查询串或请求体不合法；对象归属或摘要校验失败；能力不支持 |
| `CARD_NOT_FOUND` | 404 | false | 卡片不存在或不可见 |
| `CARD_RENDER_NOT_READY` | 409 | true | 请求查看入口但无查看产物 |
| `BOX_NOT_FOUND` | 404 | false | 箱子不存在、不可见或源文件不可用 |
| `UPLOAD_SESSION_NOT_FOUND` | 404 | false | 上传会话不存在 |
| `UPLOAD_SESSION_EXPIRED` | 400 | false | 上传会话已过期 |
| `DOWNLOAD_SESSION_NOT_FOUND` | 404 | false | 下载会话不存在 |
| `FILE_TOO_LARGE` | 413 | false | 对象、请求体或单作品超过配置上限（限额与执行点见 6.4）；`details` 携带 `limitKind` / `limitBytes` / `actualBytes` |
| `FILE_TYPE_INVALID` | 415 | false | MIME 或归档类型不支持 |
| `FILE_CORRUPT` | 400 | false | 箱子元数据、结构、内容或归档不符合正式格式 |
| `NOT_FOUND` | 404 | false | 未匹配任何路由 |
| `SERVICE_UNAVAILABLE` | 503 | true | 维护或依赖不可用 |
| `INTERNAL_ERROR` | 500 | true | 未归一的服务端异常 |
| `RESPONSE_INVALID` | —（客户端侧） | true | 客户端侧归一码：响应信封、字段或业务码不符合本契约 |

- 客户端侧 `CARD_TRANSFER_*` 错误码由传输引擎登记与处理，见 [16-卡片传输协议](./16-卡片传输协议.md) §8.2。
- 保留未启用的错误码不得出现在响应中；新增业务码必须同步本表并走 RFC（[03-变更与决策管理](../07-工程管理/03-变更与决策管理.md)）。

### 7.3 ChipsError 映射

客户端消费方必须把 HTTP 失败归一为 `ChipsError`：

| 层 | 归一结果 | 规则 |
|---|---|---|
| 未到达服务端（DNS、连接、TLS、超时） | `HTTP_REQUEST_FAILED` / `RESOURCE_NETWORK_FAILED` | 沿用平台网络错误码；`retryable` 按网络语义 |
| 服务端 5xx / 503 | 同名业务码 | `retryable` 取服务端字段 |
| 服务端 4xx 业务失败 | 同名业务码 | `details` 保留服务端字段并附加 `httpStatus` |
| 响应不符合本契约 | `RESPONSE_INVALID` | 客户端侧归一码；记录 `traceId` |

规则：只按 `code` 分支；`retryable: false` 不得自动重试；诊断记录 `code` / `httpStatus` / `traceId`，不记录令牌与预签名。

### 7.4 处理规则

- 服务端只返回已归一异常；内部异常转换为 `INTERNAL_ERROR` 并记录 `traceId`，不回显堆栈与组件名。
- 错误响应不得暴露私有资源的存在性；不得包含真实文件系统路径、存储地址与内部标识。
