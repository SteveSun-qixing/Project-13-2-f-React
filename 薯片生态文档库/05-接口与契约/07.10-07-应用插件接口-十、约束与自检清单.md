## 十、约束与自检清单

### 10.1 强制规则

- 一个应用插件只有一个角色 `app`；需要多角色能力时拆分并用 `dependencies` 组合（R1）。
- 入口模块默认导出实现 `IAppPlugin` 的对象；模块顶层不产生副作用，启动逻辑全部在 `launch` 中。
- 主逻辑只经 `IAppContext` 的访问面（§4.6）访问平台；UI 只经 `chips`（`window.chips`）访问平台。
- 窗口只使用平台表面与 `window:*` 能力，禁止直接创建系统窗口或访问 Electron / Node.js API。
- 配置只经 `ctx.config` 与 `config:*` 能力读写，禁止直接读写配置文件。
- 应用不注册服务与 Bridge 能力；可复用的能力按 R1 拆分为 `service` 插件。
- `beforeExit` 用于保存与刷新，不得假设可以取消退出。
- 标准事件的订阅必须可撤销；UI 组件卸载时必须 `dispose()` 订阅句柄。

### 10.2 禁止事项

- 禁止在模块顶层创建窗口、读取配置或执行业务逻辑；这些动作全部在 `launch` 中进行。
- 禁止跨实例复用 `IAppContext` / `IAppWindow`；实例退出后必须丢弃引用。
- 禁止把包内相对路径、裸绝对路径或远程 URL 传给 `openFile`。
- 禁止用事件模拟请求-响应；应用对外提供数据使用能力或服务（§7.1）。
- 禁止发明未登记的 `APP_*` 错误码。

### 10.3 自检清单

- [ ] manifest 的 `type` 为 `app`，`ui.surface` 取值合法，`ui.launcher` 字段完整。
- [ ] `launch` 处理了 `ctx.args` 的全部四种来源与不变量（含 `deep-link` 的 `url`）。
- [ ] `handleCommand` / `openFile` 的未知输入返回结构化错误，未做静默忽略。
- [ ] `beforeExit` 已释放实例级资源与订阅。
- [ ] 主逻辑与 UI 的事件、配置访问分别使用 `IAppContext` 访问面 / `chips`，且订阅均可撤销。
- [ ] 窗口、文件、配置访问所需权限已在 manifest 中按最小范围声明（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md)）；系统集成能力（菜单 / 托盘 / 快捷键 / 电源 / 传输）已声明对应权限。
