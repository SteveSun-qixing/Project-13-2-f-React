## 三、IBoxLayoutPlugin 接口

### 3.1 接口定义

```typescript
type Dispose = () => void;

interface IBoxLayoutPlugin {
  /** 查看态：把箱子渲染进容器；产生副作用时必须返回释放句柄 */
  renderLayout(box: BoxRenderView, container: HTMLElement): void | Dispose;

  /** 编辑态：把布局配置编辑器挂载到容器，返回编辑器句柄 */
  renderEditor(box: BoxRenderView, container: HTMLElement): ILayoutEditor;

  /** 校验布局配置是否可用于渲染；纯函数、同步、不得抛出 */
  validateConfig(config: unknown): boolean;
}
```

`ILayoutEditor` 的完整定义见本文第 7.1 节；`ISubscription`（`{ dispose(): void }`）定义见 [01-Bridge-API规范](01-Bridge-API规范.md) 2.3。本文全部接口与类型（`IBoxLayoutPlugin`、`BoxRenderView`、`EntryView`、`ILayoutEditor`、`LayoutChange` 等）均从 `@chips/sdk` 主入口导出，导出清单见 [02-SDK-API规范](./02-SDK-API规范.md) §2.2。

实现与装载规则：

- 双入口职责与基础卡片插件一致（[08-基础卡片插件接口](08-基础卡片插件接口.md) §2.5）：主进程入口 `dist/index.js` 承载 `validateConfig` 等纯函数；渲染入口 `render.js` 承载 `renderLayout` / `renderEditor`；`src/index.ts` 只做拆分导出。
- 帧内需要请求条目帧或执行帧动作时，入口可同时实现第 6.1 节的 `IBoxLayoutRuntimeAware`；帧运行时在首次调用 `renderLayout` 前注入句柄。
- 一个入口只实现一个角色接口；插件模块按「插件 ID + 版本」缓存，模块级状态只在单个渲染帧内有效（R1、[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 3.5）。
- `Dispose` 由 `@chips/sdk` 导出，等价于 `() => void`；`Dispose` 必须幂等、不得抛出。

### 3.2 方法总览

| 方法 | 调用方 | 调用时机 | 返回值 | 失败语义 |
|---|---|---|---|---|
| `renderLayout` | 帧运行时（查看态） | 布局帧装载后与每次视图更新 | `void` 或释放句柄 | 抛出 → `RENDER_PLUGIN_FAILED`，帧降级占位，可重试 |
| `renderEditor` | 编辑链路（编辑态，就近渲染，经门面装载） | 编辑会话建立后调用一次 | 必须返回 `ILayoutEditor` | 抛出 → 编辑面板降级，展示错误与重试入口 |
| `validateConfig` | 编辑链路、编辑器自身 | 回流与保存前、编辑变更时 | `boolean` | 抛出视为 `false` 并记录诊断 |

### 3.3 `renderLayout`

契约：

1. 调用环境是布局帧；入口若实现了 `IBoxLayoutRuntimeAware`，帧运行时已在首次调用前注入运行时句柄（第 6.1 节）；`renderLayout` 经该句柄请求条目与执行帧动作。
2. `box`（`BoxRenderView`）是只读的渲染视图：不得修改、不得缓存后跨会话复用、不得写入任何平台对象。
3. 插件决定槽位、排序呈现、滚动容器结构与布局算法；平台不预设任何布局算法。
4. 视图更新时帧运行时以新 `BoxRenderView` 再次调用 `renderLayout`（同一容器）：每次调用必须让容器呈现传入 `box` 的完整内容（覆盖式更新或自行 diff），不得叠加多份内容；创建新效果前必须自行清理上一次调用创建、生命周期短于帧的效果（事件监听、定时器、Observer、已挂载条目帧）。
5. 返回的 `Dispose` 只负责本次调用建立的效果；帧运行时按调用顺序收集，帧销毁时逆序执行。`Dispose` 必须幂等、不得抛出；无效果需要释放时返回 `void`。
6. 插件不得读取条目文件、不得解析 YAML、不得创建非受管 iframe；条目内容一律经帧运行时下发（第 6.2 节）。
7. 容器宽度由父帧决定，插件不得请求改变外层尺寸；高度按平台自适应协议上报（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 9.4）。
8. 不得访问平台与帧外环境；资源按第 6.4 节；不得读写存储、发起网络请求。
9. 抛出的异常由帧运行时隔离并按 `RENDER_PLUGIN_FAILED` 降级；插件必须容忍字段缺失与类型异常，保证坏数据下仍能呈现可读内容。

### 3.4 `renderEditor`

契约：

1. 调用环境是就近渲染（应用 UI 容器，不经 iframe）；宿主为编辑器提供铺满可视区的容器（`width/height: 100%`、`min-height: 0`）。
2. 输入是与查看态同一份解析结果 `BoxRenderView`，不得二次解析、不得读取文件（R8）；视图类型与渲染链路的 `DocumentView = CardRenderView | BoxRenderView` 一致。
3. 必须返回 `ILayoutEditor`；布局没有可配置项时也返回可用句柄，面板显示空态说明。
4. 编辑器只产出配置变更，不写文件、不保存、不修改会话视图；变更经 `ILayoutEditor` 交给编辑链路回流（第 7.2 节）。
5. 编辑器不得实现第二套查看渲染；需要预览时使用会话的 `renderLayout` 输出。
6. 编辑器运行在应用窗口渲染进程：允许经 `window.chips` 使用能力与资源句柄，权限判定与其它插件一致（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 8.1）；禁止访问 Node.js / Electron API。
7. 抛出的异常由编辑链路按错误边界隔离，不得破坏应用其余界面。

### 3.5 `validateConfig`

契约：

1. 输入是布局配置对象（`BoxRenderView.layout_config` 的形状），不是 `content.yaml` 的整个 `layout_configs` 映射；未提供或为空时传入 `undefined` / `null` / `{}`，三者都表示按默认值渲染，必须返回 `true`。
2. 纯函数、同步、无副作用、不得抛出；返回 `true` 表示配置合法，返回 `false` 表示结构非法。
3. 校验结构合法性（类型、范围、枚举、未知字段策略由插件自定），不要求字段完备：缺省字段由插件内部默认值与归一逻辑补齐；`undefined` / `null` / `{}` 一律按默认值渲染，必须返回 `true`。
4. 调用点：编辑链路回流与保存前、编辑器自身实时提示。校验失败时编辑链路拒绝回流并给出简体中文提示；查看态渲染不因配置非法阻断，插件必须回退默认值（第 5.2 节）。
5. 平台不解释插件配置字段；默认值、归一并插件自持（示例见第 8.2 节）。
6. 可被高频调用（编辑器每次变更），必须保持与配置规模线性的轻量检查。

### 3.6 装载与调用时序

查看态：

```
渲染引擎 / RenderHost                    布局帧（帧运行时 + 插件）
   │ 解析 → BoxRenderView → 选择布局插件（门面 loadLayout）
   │ 创建布局帧（sandbox iframe）
   │──── host:init（BoxRenderView / resourceBase / pluginEntries）─────▶│
   │                                      帧运行时注入运行时句柄
   │                                      renderLayout(box, container)
   │◀─── frame:entry-request ──────────────────────────────────│
   │──── host:entries（requestId + tickets）──────────────────▶│
   │◀─── frame:height ─────────────────────────────────────────│
   │◀─── frame:ready ──────────────────────────────────────────│
   │ 视图更新：host:update → renderLayout(newBox, container)    │
```

编辑态：

```
编辑链路（IEditSession，经 IManagedPluginRuntime 门面就近渲染）        布局插件
   │ 以同一解析结果装载布局插件
   │ renderEditor(box, container) ─────────────────────────────▶│
   │◀─────────────────────────────────────────── ILayoutEditor │
   │ getChange() → 校验（configSchema + validateConfig）
   │ document:write（返回 { revision }）
   │ 组装 DocumentView → 会话 update(view, revision)
   │ markCommitted(revision) ───────────────────────────────────▶│
   │ 保存 → 文档服务（不在编辑器内）
```
