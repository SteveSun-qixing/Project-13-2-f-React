### 5.4 预签名与分片

`POST /api/v1/card-transfer/upload-sessions/:uploadId/objects:presign`

请求体：

```json
{
  "objects": [
    {
      "role": "resource",
      "relativePath": "video.mp4",
      "sizeBytes": 104857600,
      "mimeType": "video/mp4",
      "sha256": "b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2c3"
    },
    {
      "role": "network-card",
      "sizeBytes": 2048,
      "mimeType": "application/vnd.chips.card+zip",
      "sha256": "9f2a7c1eb4d6f8a01c3e5f7a9b0d2f4a6c8e0f2a4b6d8f0a2c4e6f8a0b2d4f6a"
    },
    {
      "role": "render-file",
      "relativePath": "index.html",
      "sizeBytes": 1024,
      "mimeType": "text/html",
      "sha256": "1a2b3c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b"
    }
  ]
}
```

| 字段 | 必需 | 规则 |
|---|---|---|
| `role` | 是 | 见 5.2；卡片会话允许 `resource` / `network-card` / `render-file` / `cover-file`，箱子会话只允许 `box-file` 与箱子 `cover-file`；不匹配返回 `COMMUNITY_OBJECT_ROLE_INVALID` |
| `relativePath` | 条件 | `resource` / `render-file` / `cover-file` 必填；必须是以 `/` 分隔的卡片根 / 箱子根相对路径，禁止 `..`、前导 `/`、反斜杠与控制字符（[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §3.3）；`network-card` / `box-file` 禁止携带；非法或重复返回 `COMMUNITY_OBJECT_PATH_INVALID` |
| `sizeBytes` | 是 | 正整数；超过服务端配置的对应角色上限或本会话作品累计上限返回 `COMMUNITY_FILE_TOO_LARGE`（作品上限与执行点见 6.5） |
| `mimeType` | 是 | 与角色要求一致，否则 `COMMUNITY_FILE_TYPE_INVALID` |
| `sha256` | 是 | 64 位小写十六进制；客户端计算的字节摘要，服务端记录并在下载计划中回传；完成阶段摘要不符返回 `COMMUNITY_FILE_CORRUPT` |

响应（`200`）：

```json
{
  "data": {
    "objects": [
      {
        "objectId": "d4e5f6a7-b8c9-4d0e-8f1a-2b3c4d5e6f70",
        "role": "resource",
        "relativePath": "video.mp4",
        "bucket": "chips-card-resources",
        "objectKey": "cards/{cardId}/versions/{versionId}/resources/video.mp4",
        "publicUrl": "https://file.example/chips-card-resources/cards/{cardId}/versions/{versionId}/resources/video.mp4",
        "sizeBytes": 104857600,
        "uploadMode": "multipart",
        "upload": {
          "uploadId": "S3-multipart-upload-id",
          "partSizeBytes": 8388608,
          "partCount": 13,
          "partsUrl": "/api/v1/card-transfer/upload-sessions/{uploadId}/objects/{objectId}/parts:presign",
          "completeUrl": "/api/v1/card-transfer/upload-sessions/{uploadId}/objects/{objectId}/parts:complete",
          "abortUrl": "/api/v1/card-transfer/upload-sessions/{uploadId}/objects/{objectId}/abort"
        }
      },
      {
        "objectId": "a1b2c3d4-e5f6-4a7b-8c9d-0e1f2a3b4c5d",
        "role": "network-card",
        "relativePath": null,
        "bucket": "chips-card-resources",
        "objectKey": "cards/{cardId}/versions/{versionId}/network-card/card.card",
        "publicUrl": "https://file.example/chips-card-resources/cards/{cardId}/versions/{versionId}/network-card/card.card",
        "sizeBytes": 2048,
        "uploadMode": "single",
        "upload": {
          "method": "PUT",
          "url": "https://s3.example/...",
          "headers": {
            "content-type": "application/vnd.chips.card+zip",
            "x-amz-meta-chips-card-id": "{cardId}",
            "x-amz-meta-chips-transfer-role": "network-card"
          }
        }
      }
    ]
  }
}
```

- `uploadMode = 'single'`：对象不超过单次上传上限（与平台 `http:request` 单次请求上限一致，默认 8 MiB）时返回一个 `PUT` 目标；调用方必须使用响应中的 `method`、`url` 与 `headers` 上传。
- `uploadMode = 'multipart'`：超过单次上限的对象必须分片上传；每片大小由服务端给出的 `partSizeBytes` 决定，客户端不得自行假设；每片不超过 8 MiB 以保证客户端经平台网络能力逐片传输。
- `render-file` / `cover-file` 的对象键为 `{cardId}/{cacheVersion}/{relativePath}`，`cacheVersion` 等于会话 `versionId`；箱子 `cover-file` 的对象键为 `boxes/{boxId}/cover/{relativePath}`。服务端只接受本会话记录的完整键，不做前缀宽松匹配。
- 服务端不得为同一会话的同一 `(role, relativePath)` 签发两份不同对象键；重复请求返回同一目标与同一 `objectId`。
- 私有会话的 `publicUrl` 恒为空字符串；客户端不得用对象键直接拼接公开地址。
- 预签名地址是短时凭证：不得写入卡片、恢复清单、检查点、日志与错误详情（5.9、`16-卡片传输协议` §6.4）。

`POST /api/v1/card-transfer/upload-sessions/:uploadId/objects/:objectId/parts:presign`

请求体：`{ "partNumbers": [1, 2, 3] }`；响应：

```json
{
  "data": {
    "parts": [
      { "partNumber": 1, "method": "PUT", "url": "https://s3.example/...", "headers": {} }
    ]
  }
}
```

`POST /api/v1/card-transfer/upload-sessions/:uploadId/objects/:objectId/parts:complete`

请求体：`{ "parts": [{ "partNumber": 1, "etag": "\"etag-1\"" }] }`；服务端完成对象存储分片合并并校验对象存在与大小；成功返回 `204`，分片不完整或摘要不符返回 `COMMUNITY_OBJECT_SIZE_MISMATCH` / `COMMUNITY_FILE_CORRUPT`。

规则：

1. 分片、断点、恢复与重试的客户端算法以 `16-卡片传输协议` §3.3、§3.4、§3.5 为唯一权威；本节只定义控制面端点、字段与错误码。
2. 预签名必须校验会话归属与状态：会话不存在 / 不属于当前用户返回 `404 COMMUNITY_UPLOAD_SESSION_NOT_FOUND`，已过期返回 `410 COMMUNITY_UPLOAD_SESSION_EXPIRED`，已完成或已中止返回 `409 COMMUNITY_UPLOAD_SESSION_STATE_INVALID`。
3. 越权使用其他会话的对象或被篡改的对象键返回 `422 COMMUNITY_OBJECT_OWNERSHIP_MISMATCH`；路径非法返回 `422 COMMUNITY_OBJECT_PATH_INVALID`。
4. 重复预签名同一对象（同角色、同相对路径）按续签处理，返回同一 `objectId` 与同一对象键，可签发新的分片地址。
