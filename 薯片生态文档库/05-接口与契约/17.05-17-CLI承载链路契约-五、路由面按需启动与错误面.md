## 五、路由面、按需启动与错误面

### 5.1 路由面（在册集合，零新增）

- 承载链路可派发的 `routeId` 集合 = §5.8 服务路由全集 + `command:invoke`，逐字冻结如下，**不得扩充、不得别名**：
  - `cli.command.list`、`cli.command.get`、`cli.command.resolve`
  - `cli.task.create`、`cli.task.bindInvocation`、`cli.task.get`、`cli.task.progress`、`cli.task.complete`、`cli.task.fail`、`cli.task.cancel`
  - `command:invoke`（《07-CLI 完整参考》§3.10.3，`source: 'cli'`；「启动并投递」语义按《13-命令系统契约》§4.4 原样）
- 输入输出负载形状逐字段以 [07.12 §5.8](../06-开发与运维/07.12-07-CLI完整参考-五、插件 CLI 命令扩展-5.8 发现与任务服务路由.md) 路由表为唯一权威，本契约只规定其承载方式（§3.4 封套 `capabilityId` 槽）。
- 服务端**独立服务路由表**承载上述集合（§4.4 第 4 条禁入能力注册表）；非在册 `routeId` 一律拒绝：`CLI_TARGET_UNAVAILABLE` + `details.reason = route_unregistered`（防御面，正常客户端不可能发出）。
- 发现索引只读、安装/启用/禁用/卸载后由平台重建、任务存储唯一（`cli-task`）等路由面承诺全部沿用 §5.8 原文，本契约不加码。
- handler 级业务错误（`CLI_COMMAND_QUERY_INVALID`、`CLI_TASK_NOT_FOUND`、`CLI_COMMAND_CONFLICT`、`COMMAND_OWNER_NOT_RUNNING` 等）按既有域码在封套 `error` 内如实返回，走现行退出码映射，**不进 §5.3 reason 词表**（reason 词表只管传输/握手层定性）。

### 5.2 按需启动（§3.10.1 兑现，Q6 裁定采 (c)）

发现阶段失败（无 `CHIPS_CARRIER_SOCKET` 覆盖、发现文件缺失或陈旧、连接失败）时，CLI 的拉起判定链：

1. **仅当能按平台发行包固定布局解析出宿主可执行文件时自动拉起**；解析不出按现行无承载回退（发现阶段 → `CLI_COMMAND_NOT_FOUND`，退出码 3，`packages/cli/src/run.ts:157-166` 在册链）。
2. **bin 相对布局**（本节为该布局的字段级唯一冻结；发行包装配波必须按此产出，产不出的平台其承载面自动落在「解析不出 → 3 回退」的合法灰态）：
   - 解析锚点：CLI 自身正式入口文件的 realpath（`packages/cli/package.json` bin 指向的 `dist/bin.js`）所在目录，自该目录向上**至多 6 级**逐层探测，命中该平台候选即止；
   - darwin 候选：`<D>/Contents/MacOS/Chips`（CLI 与宿主同包：CLI 安装于 `Chips.app/Contents/Helpers/bin/chips`）；
   - win32 候选：`<D>\Chips.exe`（NSIS 安装根布局：CLI 安装于 `<安装根>\resources\cli\bin\`）；
   - linux 候选：`<D>/Chips`（deb `/opt/Chips/`：CLI 安装于 `/opt/Chips/bin/chips`；AppImage 挂载根同形）；
   - 命中后还须是可执行文件（POSIX `X_OK`），否则继续向上探测。
3. **拉起方式**：detached 启动解析出的宿主正常实例（空附加参数；宿主 runtime `start()` 成功即常开承载监听，无「承载专用启动模式」），CLI 不等待其 stdio。单实例锁保证不会拉起第二个宿主。
4. **就绪等待**：轮询发现文件直至出现且双判据新鲜、握手成功；预算 = 既有启动等待常量 30 秒（`packages/cli/src/constants.ts:11`），超时 → `CLI_TIMEOUT`（退出码 9）。
5. **禁止漂移**：monorepo 工作区形态（`pnpm exec chips`，入口 `packages/cli/dist/bin.js`）不在上述发行包布局内 → 必然解析不出，禁止借道全局陈旧 bin 或猜测宿主安装位置；工单019 注入面纪律的同族口径由 `tests/contract/tests/cli-bin-resolution.test.ts:2-5`（工作区 bin 必须锚定当前工作区 `@chips/cli`，不得静默漂移到全局同名陈旧 bin）判定先例守住。工作区 dev/e2e 场景一律走 `CHIPS_CARRIER_SOCKET` 覆盖面（§2.6）。
6. 拉起后宿主的存续/退出语义不入 v1（§1.4 第 5 条）。

### 5.3 错误面（Q5 裁定：零新码族 + `details.reason` 词表冻结）

- 承载链路的传输/握手层失败对用户契约**只有一个码**：`CLI_TARGET_UNAVAILABLE`（对外退出码 6；发现阶段失败按既有回退链定性为 `CLI_COMMAND_NOT_FOUND` / 退出码 3，`run.ts:157-166`）。**不新增 `CLI_CARRIER_*` 码族、不改 §2.5 码表**——把协议内部状态泄进用户契约是被否决项（立项评估 Q5 (b)）。
- `error.details.reason` 词汇表（本契约冻结；代码常量 `CARRIER_HANDSHAKE_REASONS`，`@chips/bridge` 协议分件）：

| `reason` | 触发点 | 收口 |
|---|---|---|
| `protocol_mismatch` | 握手请求 `protocol` 字面量不被服务端支持，或发现文件 `protocol` 字段不匹配 | 握手失败响应 / 视同发现失败（§5.4 行 1） |
| `token_invalid` | bearer token 常量时间比较不等 | 握手失败响应 → 6 |
| `handshake_timeout` | 建连后 `CARRIER_HANDSHAKE_TIMEOUT_MS` 内握手未成 | 关闭连接 → 3（发现阶段） |
| `carrier_unavailable` | 端点不可达：发现文件缺失/陈旧/形状非法、bind 缺失、连接被拒、`instanceId` 错位、socket 覆盖直连但发现文件缺失 | 视同发现失败 → 3；拉起超时 → 9 |
| `connection_lost` | 已建会话后连接中途断（宿主崩溃/重启/端点消失） | 在途请求拒绝 → 6 |
| `route_unregistered` | 服务端收到非 §5.1 在册 `routeId` | 封套错误 `CLI_TARGET_UNAVAILABLE` → 6 |

- `details` 允许携带 `path`、`env` 等非敏感诊断（比照 trust-roots 先例），禁止携带 token 与发现文件内容原文（§2.8）。
- `CLI_TIMEOUT`（9）的「等待任务**或承载链路**超时」在册语义（[07.02 §2.5](../06-开发与运维/07.02-07-CLI完整参考-二、调用约定.md) :147）自本协议实现起可实测。

### 5.4 崩溃与重启回退链（立项评估 §4.4 口径落文）

| 场景 | 行为链 | 用户可见定性 |
|---|---|---|
| 宿主崩溃/未运行 | 发现文件陈旧残留 → CLI 读出后连接失败或握手失败 → 双判据不做删除（清理权 §2.5-4） | 发现阶段失败 → 3（既有回退链，CLI 侧零新码） |
| 在途承载丢失 | 已建会话后 socket 断开 → 在途请求 Promise 以 `CLI_TARGET_UNAVAILABLE`（`reason = connection_lost`）拒绝 | 退出码 6 |
| 任务轮询中宿主重启 | 新宿主实例无该任务（任务存储为宿主内存面，§5.8 无持久化承诺）→ `cli.task.get` 返回 `CLI_TASK_NOT_FOUND`；轮询超预算 → `CLI_TIMEOUT` | 如实收口（1）/ 9；**「重启续投任务」不是 §5.8/§3.10 承诺，不做** |
| 宿主下次启动 | 双判据清陈旧、重新 bind、原子写新记录 | 自愈，无需 CLI 侧动作 |
| CLI 先死 | 连接关闭 → 服务端关闭该承载会话并取消其在途请求（统一会话注册表 onClosed 联动，§4.3） | 服务端资源即时回收 |
| CLI 中断（Ctrl+C） | `job.cancelOnInterrupt: true` 腿走 `cli.task.cancel` 正常路由帧（该臂只处理 CLI 活着的中断，在册语义不变） | 退出码 8 |

### 5.5 `chips dev run` 并轨（Q8 裁定）

- `chips dev run` 的 devHost 适配臂（`packages/cli/src/client/service-router.ts:149-156`）**并入本协议**：开发宿主 = 同一 carrier 协议的工作区实例，不存在第二套 dev 端点协议。
- dev 宿主的承载端点推导 = 同一 `deriveCarrierEndpoints` 纯函数作用于 dev 宿主自身的 `userData` 根；dev/user 两入口「共用同一可执行文件、同一错误模型」（07.01 §1.1）在承载域的平移。
- 波 2 完成 devHost 面与本链路的组装并轨；本契约先行冻结口径，波间不得出现 dev 专用字面量。

### 5.6 服务端实现挂点（契约侧只登记归属，不展开实现设计）

- 宿主侧 carrier 域目录、生命周期接线（runtime `start()` 后开监听、`shutdown()` 逆序先关 carrier）、命令索引重建钩子与任务存储唯一实现归**波 1**；CLI 侧发现组装与 `ICliInvoker` 实装归**波 2**；本契约的全部字段级条款即两波的验收权威。
- app 臂「启动并投递」依赖 `handleStartupInputs` 正式投递装配（现诚实 warn 留痕，`packages/host/src/runtime/host-runtime.ts:399-405`）：风险 R3 登记生效——该面未就绪前 app 臂挂工单039 本账继续，禁止临时投递凑绿；service 臂不受其阻塞。
