## 四、数据模型

### 4.1 `BoxRenderView`

插件接收的 `BoxRenderView` 是解析结果的只读渲染视图：`box_id` / `name` / `chip_standards_version` 与 `active_layout_type` 来自 `.box/metadata.yaml`，`layout_config` 来自 `.box/content.yaml`，`entries` 来自 `.box/structure.yaml`，`cover` 来自 `.box/cover.html`；持久化字段语义、schema 与校验规则以 [02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) 为准，渲染链路的帧组织与条目票证见 [05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 2.5、7.2。

```typescript
interface BoxRenderView {
  readonly kind: 'box';
  readonly box_id: string;
  readonly name: string;
  readonly chip_standards_version: string;
  readonly revision: number;
  readonly active_layout_type: string;
  readonly layout_config: Record<string, unknown>;
  readonly cover: CoverView;
  readonly entries: EntryView[];
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `kind` | `'box'` | 文档类型判别键 |
| `box_id` | `string` | 箱子 ID，来自 `metadata.yaml` 的 `box_id`（10 位 Base62） |
| `name` | `string` | 箱子名称，来自 `metadata.yaml` 的 `name` |
| `chip_standards_version` | `string` | 箱子文件标准版本，来自 `metadata.yaml` 的 `chip_standards_version`，用于兼容门禁（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md)） |
| `revision` | `number` | 会话视图修订号，单调递增；更新视图只增不减 |
| `active_layout_type` | `string` | 当前生效布局类型，来自 `metadata.yaml` 的 `active_layout_type` |
| `layout_config` | `Record<string, unknown>` | 生效布局的配置参数，来自 `content.yaml` 的 `layout_configs.<active_layout_type>.props`，见第五节 |
| `cover` | `CoverView` | 正式封面视图（入口与比例），来自 `.box/cover.html`；定义见[03-核心接口规范](./03-核心接口规范.md) §6.6、消费见[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §2.5 |
| `entries` | `EntryView[]` | 条目列表，按 `structure.yaml` 的 `entries` 数组顺序排列 |

### 4.2 `EntryView`

```typescript
interface EntryView {
  entry_id: string;
  url: string;
  enabled: boolean;
  snapshot?: Record<string, unknown>;
  layout_hints?: Record<string, unknown>;
  displayTitle: string;               // 派生字段：来源为 snapshot.title 或目标文档标题
  order: number;                      // 派生字段：来源为 entries 数组顺序
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `entry_id` | `string` | 条目 ID，来自 `structure.yaml` 的 `entry_id`，箱子内唯一；请求条目帧与打开条目时使用 |
| `url` | `string` | 条目引用，来自 `structure.yaml` 的 `url`；形态与允许的 scheme 见 [02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) 第三节（R13） |
| `enabled` | `boolean` | 是否参与布局展示，来自 `structure.yaml` 的 `enabled` |
| `snapshot` | `Record<string, unknown>`（可选） | 条目摘要快照，来自 `structure.yaml` 的 `snapshot`；键以格式规范为准，可能缺失，不得作为完整内容依据 |
| `layout_hints` | `Record<string, unknown>`（可选） | 布局索引，来自 `structure.yaml` 的 `layout_hints`；排序与分组消费用，可能缺失 |
| `displayTitle` | `string` | 派生展示名：由平台从 `snapshot.title` 派生，缺省时取目标文档标题；无对应持久化字段 |
| `order` | `number` | 派生呈现顺序：由平台按 `entries` 数组顺序派生；无对应持久化字段 |

### 4.3 数据约束

- 模型只读；插件不得修改、不得把字段值写回文件。
- 模型必须可结构化克隆：不含函数、类实例、`Symbol`、循环引用；不含文件字节与绝对路径。
- 条目顺序基准：`structure.yaml` 的 `entries` 数组顺序；`order` 是平台派生的呈现顺序，排序只影响呈现，不影响箱子数据。
- 单条目解析失败时条目保留位置并携带错误状态；插件必须渲染条目级占位，不得使整箱失败。
- `revision` 只增不减；视图更新时帧运行时以新 `BoxRenderView` 再次调用 `renderLayout` 完成整体替换。
