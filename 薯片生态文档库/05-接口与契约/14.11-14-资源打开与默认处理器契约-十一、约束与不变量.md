# 资源打开与默认处理器契约

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：资源打开路由的权威契约：打开来源与打开请求模型、manifest 处理器声明与 `primary` / `fallback` 层级、路由解析顺序与投递授权、启动载荷 `resourceOpen` 与业务载荷约定、默认处理器偏好 `platform.fileOpen.defaults` 与槽位治理接口、未安装/停用/卸载的降级与回收、与文档/条目/封面链路的关系；资源 URI 语法、句柄与权限判定本身不在此定义。

---

## 十一、约束与不变量

| 编号 | 约束 |
|---|---|
| OR-1 | 打开唯一入口：一切打开动作经资源打开路由；调用方不得硬编码目标插件 ID，不得直接启动或调用其他插件。 |
| OR-2 | 单一解析实现：处理器解析只有一处实现，禁止第二套路由、第二套优先级或插件内私建分发。 |
| OR-3 | 平台不做业务：平台不内置任何格式处理器，不按扩展名写死目标插件；能力全部来自声明。 |
| OR-4 | 打开不产生持久授权：文件关联只做路由；投递授权只读、会话级、不落盘。 |
| OR-5 | 不暴露真实路径：启动载荷只含受管引用；`targetPath` 不再存在。 |
| OR-6 | payload 平台不解释：只校验可序列化与体积，业务字段原样透传。 |
| OR-7 | 偏好只选择不扩权：偏好不改变候选资格、不跳过层级以外的规则、不产生授权。 |
| OR-8 | 候选只来自 `active` 插件；`pending` / `starting` / `stopping` / `installed` / `failed` 不参与。 |
| OR-9 | 停用保留偏好，卸载回收偏好；重装视为全新安装。 |
| OR-10 | 路由阶段不读资源字节、不做网络探测。 |
| OR-11 | 未命中必须确定性降级（`shell` / `external`）或返回 `RESOURCE_HANDLER_MISSING`，禁止静默失败。 |
| OR-12 | 槽位键只使用 `mime:` / `ext:` 两种形式；匹配等级固定 M1 ＞ M2 ＞ E1，组内固定 primary ＞ fallback ＞ 安装顺序 ＞ 插件 ID 字典序。 |
| OR-13 | 封面链、条目链与本路由边界固定：封面与条目目标不经处理器匹配（§八）。 |
| OR-14 | 性能数值只引用[架构原则](../00-愿景与原则/01-架构原则.md) §4.2，禁止自造指标。 |
