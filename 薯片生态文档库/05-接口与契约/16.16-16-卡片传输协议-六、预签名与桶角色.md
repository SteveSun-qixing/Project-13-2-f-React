# 卡片传输协议

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：`.card` / `.box` 在本地设备与内容服务器之间传输的权威协议：传输会话（创建、预签名、分片、断点续传、取消、恢复）、完整离线卡片与网络资源卡片的可逆改写与还原（含可逆恢复清单）、摘要与完整性校验、预签名与对象存储桶角色、传输队列与 `transfer:*` 事件映射、错误码与安全约束；不覆盖卡片/箱子的包结构语义、渲染链路与服务器产品设计。

---

## 六、预签名与桶角色

### 6.1 对象角色

| 角色 | 内容 | 适用会话 | 桶角色 | 对象键模板 | 可见性 |
|---|---|---|---|---|---|
| `network-card` | 网络资源卡片 | 卡片 | 卡片资源桶 | `cards/{cardId}/versions/{versionId}/network-card/card.card` | 卡片可见性 |
| `resource` | 卡片内部资源 | 卡片 | 卡片资源桶 | `cards/{cardId}/versions/{versionId}/resources/{relativePath}` | 卡片可见性 |
| `render-file` | 查看产物文件 | 卡片（客户端渲染） | 查看产物桶（公开/私有） | `{cardId}/{cacheVersion}/{relativePath}` | 卡片可见性 |
| `cover-file`（卡片） | 封面产物文件 | 卡片（客户端渲染） | 封面产物桶（公开/私有） | `{cardId}/{cacheVersion}/{relativePath}` | 卡片可见性 |
| `cover-file`（箱子） | 箱子封面目录文件 | 箱子 | 通用封面桶 | `boxes/{boxId}/cover/{relativePath}` | 公开 |
| `box-file` | 箱子源文件 | 箱子 | 箱子源文件桶（私有） | `boxes/{boxId}/versions/{versionId}/box.box` | 私有 |

- `cacheVersion` 由服务器在创建会话时确定并在预签名响应中给出；客户端不得自行定义缓存版本。
- 全部对象键模板由服务器在响应中给出实际值；上表是协议要求的键结构，用于服务器校验与第三方实现对照。

### 6.2 桶角色

| 桶角色 | 默认桶名 | 可见性 | 用途 | 写入方 |
|---|---|---|---|---|
| 卡片资源桶 | `chips-card-resources` | 公开读 | 卡片内部资源、网络资源卡片 | 客户端预签名直传 |
| 卡片源文件桶 | `chips-card-files` | 私有 | 发布态完整 `.card` 源文件（服务器保留副本） | 服务器 |
| 箱子源文件桶 | `chips-box-files` | 私有 | 发布态 `.box` 源文件 | 客户端预签名直传 |
| 公开查看产物桶 | `chips-card-render-cache` | 公开读 | 公开卡片查看产物 | 客户端预签名直传 |
| 私有查看产物桶 | `chips-card-render-cache-private` | 私有 | 私有卡片查看产物 | 客户端预签名直传 |
| 公开封面产物桶 | `chips-card-cover-cache` | 公开读 | 公开卡片封面产物 | 客户端预签名直传 |
| 私有封面产物桶 | `chips-card-cover-cache-private` | 私有 | 私有卡片封面产物 | 客户端预签名直传 |
| 通用封面桶 | `chips-covers` | 公开读 | 箱子封面、房间封面等 | 客户端预签名直传 |
| 头像桶 | `chips-avatars` | 公开读 | 用户头像 | 服务器 |

- 桶名是部署配置项；协议只约束桶角色、可见性与用途。任何实现不得新增与上表重叠职责的第二套桶。
- 私有桶对象不得开放匿名读；只能通过受控鉴权代理路由或短有效期预签名地址访问（6.5）。

### 6.3 对象键规则

1. 对象键由服务器生成并与会话绑定；客户端只使用响应返回值，不得构造、拼接、猜测或跨会话复用对象键。
2. 对象键必须包含会话分配的内容标识与版本标识（`cardId` / `boxId`、`versionId`），使同一内容的不同版本互不覆盖。
3. `resource` 与 `render-file` / `cover-file` 的相对路径段必须经过与卡片路径相同的规范化校验（无 `..`、无反斜杠、无控制字符）；服务器拒绝任何越界键。
4. 对象键大小写敏感、按字节精确匹配；服务器只接受本会话记录的完整键，不做前缀宽松匹配。

### 6.4 预签名 URL 契约

| 项 | 要求 |
|---|---|
| 方法 | 上传为 `PUT`；下载为 `GET`；响应中的 `method` 是唯一合法方法 |
| 头 | 客户端必须原样携带响应 `headers`；不得增删或改写 |
| 有效期 | 每个地址在自身 `expiresAt` 前有效；过期后必须重新签发，不得复用旧地址 |
| 作用域 | 单个地址只对一个对象或一个分片有效；不得用于其他对象、其他会话或其他方法 |
| 保密 | 预签名 URL 是凭证：不得写入卡片、恢复清单、检查点、日志、错误详情与审计正文 |
| 校验 | 服务器在合并对象与提交阶段必须验证对象确由本会话签发地址写入（对象元数据中的会话与角色标记） |
| 重试 | 同一地址在有效期内可重复 `PUT` 同一分片；重试不得改变字节 |

### 6.5 可见性与私有对象访问

- 卡片/箱子可见性由服务器内容记录决定，不从客户端请求推断；客户端不能通过会话参数提升可见性。
- 公开卡片：资源与网络资源卡片位于公开桶，产物入口可用对象存储 URL；私有卡片：资源与网络资源卡片仍按卡片可见性策略访问，产物位于私有桶，入口只能是受控代理路由或短有效期预签名地址。
- 私有媒体产物必须支持 `Range`（视频播放等场景由服务器受控代理流式转发）。
- 预签名地址不得出现在任何卡片内容、恢复清单、分享链接或日志中。

### 6.6 生命周期与清理

- 会话有效期与预签名有效期由服务器配置；协议不固定数值，客户端只使用响应中的时间戳。
- 未提交对象：会话过期或 `abort` 后由服务器回收；`multipart` 未完成对象必须中止。
- 已提交内容：与卡片/箱子版本同生命周期，由服务器在删除内容或变更可见性时按策略清理。
- 客户端临时物：任务完成、取消或失败后必须清理工作副本与 `.part` 文件；崩溃残留按工作区恢复流程清理（[13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §2.3）。
