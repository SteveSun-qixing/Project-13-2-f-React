## 七、manifest 专有字段

### 7.1 完整片段

```yaml
id: chips.service.clock
version: 1.0.0
type: service
name: 时钟服务
description: 为其它插件提供统一时钟与每分钟节拍事件
author: 薯片官方
license: MIT
runtime:
  targets: [host]
  background: true
healthCheck:
  interval: 30s
  timeout: 5s
permissions: []
```

### 7.2 `runtime.background`

| 值 | 规则 |
|---|---|
| `true` | 后台常驻：平台启动恢复阶段按启用偏好自动启用；运行不依赖任何界面会话 |
| `false` / 缺省 | 无后台常驻保障：启动恢复阶段不主动启用，由用户操作或依赖链显式启用 |

- 仅 `service` 角色可声明 `true`；其它角色声明 `true` 按 manifest 校验失败处理（[02-插件清单规范](../03-插件开发/02-插件清单规范.md)）。
- `runtime.targets` 必须包含 `host`：服务在主进程（或经内核调度的工具进程）运行；平台不提供 `web` 目标。
- `background` 为可选字段，缺省为 `false`；与清单规范一致（[02-插件清单规范](../03-插件开发/02-插件清单规范.md) §4.2、§7.5）。

### 7.3 `healthCheck`

- 字段规则见 5.1；仅声明 `healthCheck` 或实现 `health()` 之一不构成完整契约，两者同时满足才启用检查。
- 单位统一为字符串形式（`30s` / `5s`），与清单规范一致；禁止裸数字或毫秒数字写法。
- 约定常量写入 manifest，不允许运行期修改检查周期。

### 7.4 校验与评审要点

- manifest 校验失败终止安装：`.cpk` 不落盘、不注册（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 4.2）。
- 服务插件声明网络与文件权限时，必须说明后台无界面状态下的访问目的；申请范围必须最小化（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 10.1）。
- 服务插件不得声明 `ui`、`capabilities.cardTypes`、`capabilities.layouts` 等非本角色字段；其余字段以[02-插件清单规范](../03-插件开发/02-插件清单规范.md)为准。

### 7.5 文件关联接收通道

`service` 角色可以声明 manifest `fileAssociations`（[02-插件清单规范](../03-插件开发/02-插件清单规范.md) §7.5）；接收通道固定为 `handleFile(uri)`：

| 项 | 契约 |
|---|---|
| 声明 | manifest `fileAssociations`；声明即必须实现 `handleFile`，否则启用校验失败 |
| 投递 | 插件 `active` 期间收到匹配的文件打开请求时调用；插件未启用时平台按文件关联路由尝试启用后投递 |
| 参数 | `uri` 为已归一的受管引用，口径与 [07-应用插件接口](./07-应用插件接口.md) §3.4 一致 |
| 顺序 | 多文件按传入顺序串行调用；单个失败不阻断后续文件 |
| 失败 | 拒绝记录诊断并按 `APP_OPEN_FILE_FAILED` 语义上报；不使插件崩溃、不影响后续投递 |
| 停用 | 停用后不再投递；在途调用的取消与收口按 Bridge 规则 |

- 文件关联只做路由，不代表授权；接收方读取打开投递的资源须声明 `resources:read` 基础权限，跨作用域访问由投递授权覆盖（[14-资源打开与默认处理器契约](./14-资源打开与默认处理器契约.md) §4.4）；系统关联与拖放来源不要求 `filesystem:*`。
- 服务插件无界面：不得弹窗或创建窗口，需要用户确认的流程经通知与后续命令/事件完成。
