## 十一、错误码

### 11.1 错误模型与归属

- 所有跨 Bridge 错误统一为 `ChipsError`（`code` / `message` / `details` / `retryable`），归一规则与通道级错误码以 [02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 第九节为准。
- 错误处理必须按 `code` 分支，禁止匹配 `message` 文本；`message` 一律简体中文、面向用户。
- 错误码命名规则：`<DOMAIN>_<REASON>`，全大写下划线；Bridge 通道级使用 `BRIDGE_` 前缀。

### 11.2 注册与契约错误码

| 错误码 | 触发 | retryable |
|---|---|---|
| `BRIDGE_CAPABILITY_NOT_FOUND` | 调用未注册能力 ID；`draining` 后的新调用 | false |
| `BRIDGE_CAPABILITY_CONFLICT` | 注册冲突：ID 格式非法、未登记 ID、登记提供方与 owner 不一致、内置 ID 被第三方注册、重复注册定义不一致、ID 与权限 ID 相同 | false |
| `BRIDGE_INVALID_SCHEMA` | schema 不符合第五节子集或无法离线编译 | false |
| `PERMISSION_NOT_DECLARED` | 能力所需权限未在提供方 manifest 声明 | false |
| `PERMISSION_UNKNOWN` | `permissions` 引用了未注册的权限 ID | false |

### 11.3 调用错误码

能力调用路径上的通道级错误码（完整表见 [02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 第 9.2 节）；与能力契约直接相关的对应关系：

| 错误码 | 契约含义 |
|---|---|
| `BRIDGE_CAPABILITY_NOT_FOUND` | 调用点使用了未登记能力 ID（含能力族未登记目标） |
| `BRIDGE_PERMISSION_DENIED` | 能力所需权限未被会话快照覆盖；`details` 结构见 [08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 第 9.2 节 |
| `BRIDGE_INVALID_INPUT` | 输入未通过能力 schema 校验；`details` 结构见第 5.4 节 |
| `BRIDGE_TIMEOUT` | 超过注册项 `timeoutMs` 或 `ctx.deadline`；不保证能力未产生副作用 |
| `BRIDGE_CANCELLED` | 会话销毁、能力注销、`ctx.signal` 触发或 Bridge 关闭导致取消 |

`PLUGIN_PERMISSION_DENIED` 的唯一语义是权限拒绝（启用、能力注册阶段的权限校验失败）；插件生命周期状态错误（如注册时 owner 未 `active`）使用内核状态码 `KERNEL_*`，以 [03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 与 [01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) 为准。

规则：

1. 内置能力实现必须返回本表错误码；新增业务错误码需同 PR 更新本节（本规范维护）。
2. `details` 只携带结构化诊断，不得包含输入原文、凭证材料与内部路径。
3. 拒绝与放行都写入审计（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 第八节）；插件不得以错误文案推断授权状态。
