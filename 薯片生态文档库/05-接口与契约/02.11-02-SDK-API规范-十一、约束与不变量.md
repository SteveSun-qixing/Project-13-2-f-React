## 十一、约束与不变量

1. **运行时唯一入口**：插件访问平台只经 `window.chips`；SDK 只封装，不替代、不扩展。
2. **不承载运行时**：不实现 Bridge 主逻辑、Cordis、解析、资源管理与权限判定；对 `@chips/bridge` 仅 `import type`。
3. **方法面冻结**：`ChipsBridge` 只实现 `IChipsBridge` 的 `request` / `subscribe` / `resource` 三个方法；除 CLI 扩展命名空间 `cliCommand` / `cliTask`（3.5 节）外不得增加成员；增删必须走 RFC。
4. **入口隔离**：运行时代码只导 `@chips/sdk`；`testing` 与 `scaffold` 只出现在测试与工具链。
5. **无镜像类型**：Bridge 协议类型一律转发 `@chips/bridge`；能力契约类型与 [能力契约规范](./04-能力契约规范.md) 1:1 对齐，插件不得重复定义同名契约。
6. **错误只认 `code`**：调用与测试断言都必须基于 `code`，禁止匹配 `message` 文本。
7. **脚手架纯函数**：只生成计划与文本，不写盘、不联网、不安装依赖。
8. **目标按调用解析**：客户端未注入目标时每次调用读取 `window.chips`，保证测试安装 Mock 后即时生效。
9. **禁止 `any` 与穿透导入**：符合 [TypeScript 编码规范](../02-开发规范/02-TypeScript编码规范.md) 与 [代码组织规范](../02-开发规范/01-代码组织规范.md)。
10. **文档与代码同 PR**：SDK 导出、入口、版本规则变更必须在同一 PR 内更新本文（[文档编写规范](../02-开发规范/07-文档编写规范.md)）。
11. **旧 module 调用面不导出**：`module.listProviders` / `module.resolve` / `module.invoke` / `module.job.*` 属旧模块角色调用面，SDK 主入口不导出、不提供兼容封装；迁移与处置见 [10-服务插件接口](./10-服务插件接口.md) §6.5。
12. **CLI 扩展只封装不定义**：`cliCommand` / `cliTask` 的方法、字段、错误码以 [CLI 完整参考](../06-开发与运维/07-CLI完整参考.md) §5.6、§5.8 为唯一权威，SDK 不新增传输通道、不维护第二份命令索引或任务模型。
