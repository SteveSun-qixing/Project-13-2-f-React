## 三、方法参考

### 3.1 总览

| 方法 | 用途 | 返回 | 失败通道 |
|---|---|---|---|
| `request` | 调用能力 | `Promise<TOutput>` | reject `ChipsError` |
| `subscribe` | 订阅事件 | `ISubscription`（同步） | 同步抛出 + 订阅回执 |
| `resource` | 获取资源句柄 | `IResourceHandle`（同步） | 同步抛出 `ChipsError` |

### 3.2 `request(capabilityId, input?)`

```typescript
request<TOutput>(capabilityId: string, input?: unknown): Promise<TOutput>;
```

**参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `capabilityId` | `string` | 是 | 能力 ID，`<domain>:<action>[:<target>]`；必须已在能力注册表中注册（内置能力清单见[04-能力契约规范](./04-能力契约规范.md)） |
| `input` | `unknown` | 否 | 能力输入；必须是结构化克隆兼容的 JSON 值，经能力 schema 校验后原样交给 Host |

**返回值**

| 类型 | 说明 |
|---|---|
| `Promise<TOutput>` | 能力执行结果；`TOutput` 仅存在于编译期，Bridge 不对输出做运行时校验 |

**错误（reject）**

| code | 触发 | retryable |
|---|---|---|
| `BRIDGE_CAPABILITY_NOT_FOUND` | 能力 ID 未在注册表中命中 | `false` |
| `BRIDGE_PERMISSION_DENIED` | 会话权限快照未覆盖能力所需权限 | `false` |
| `BRIDGE_INVALID_INPUT` | 输入未通过 JSON Schema 校验 | `false` |
| `BRIDGE_TIMEOUT` | 超过注册项 `timeoutMs` 或 `ctx.deadline`（默认 30000 毫秒） | `true` |
| `BRIDGE_CANCELLED` | 会话销毁、`ctx.signal` 触发、能力注销或 Bridge 关闭导致取消 | `false` |
| `BRIDGE_SESSION_UNKNOWN` | 来源会话无法解析或已关闭 | `false` |
| `BRIDGE_SESSION_BUSY` | 会话在途调用超限（默认 64） | `true` |
| `BRIDGE_QUEUE_OVERFLOW` | 串行能力队列溢出（默认 32） | `true` |
| `BRIDGE_INTERNAL` | 未归一异常 | `false` |
| 宿主业务码 | 如 `FILE_NOT_FOUND`、`DOCUMENT_NOT_OPEN` | 由宿主定义 |

**规则**

- 一次调用只执行一个能力；组合能力通过连续调用完成。
- Bridge 不填充 `default`、不做类型转换；缺省语义由能力实现定义。
- 能力实现经 `ctx.signal: AbortSignal` 与 `ctx.deadline` 感知取消与截止时刻；二者由 Bridge 适配层如实传递（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 8.2 节、[04-能力契约规范](./04-能力契约规范.md) 第 2.1 节）。
- 无客户端取消入口：`request` 没有 AbortSignal 参数，调用方不能比平台更早取消；取消来源仅有会话销毁、超时、能力注销或 Bridge 关闭。
- 渲染进程发布事件的唯一方式是调用能力 `event:publish`；不存在独立发布通道。

### 3.3 `subscribe(eventId, handler)`

```typescript
subscribe(eventId: string, handler: (payload: unknown) => void): ISubscription;
```

**参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `eventId` | `string` | 是 | 事件 ID，`<domain>:<action>`；必须是[05-事件契约规范](./05-事件契约规范.md)登记的标准事件；`internal:*` 与插件自有域事件不可跨进程订阅 |
| `handler` | `(payload: unknown) => void` | 是 | 投递回调；载荷类型由事件契约定义，使用方必须做类型收窄 |

**返回值**

| 类型 | 说明 |
|---|---|
| `ISubscription` | 同步返回；`dispose()` 幂等 |

**错误**

| code | 触发 | 返回方式 |
|---|---|---|
| `EVENT_ID_INVALID` | 事件 ID 不符合 `<domain>:<action>` | `subscribe` 同步抛出 |
| `EVENT_NOT_REGISTERED` | 事件未在事件契约中登记 | `event:control` 错误回执；该订阅不建立 |
| `EVENT_SUBSCRIBE_DENIED` | 缺少事件契约声明的订阅权限 | `event:control` 错误回执；该订阅不建立 |

**投递语义**

- 订阅登记在渲染侧同步完成，主进程确认异步到达；确认前到达的载荷先缓冲，确认后按序派发；确认失败时丢弃缓冲、订阅不建立并写审计。
- 回执失败只到 preload 与审计，`ISubscription` 没有错误回调，插件无法从订阅句柄观察 `EVENT_NOT_REGISTERED` / `EVENT_SUBSCRIBE_DENIED`；订阅前应确认事件已登记且权限已授予。
- 全部事件为**至多一次**投递：不重放、不补发、不确认、不重试；需要可靠结果时必须使用 `request`。
- 同一发布者、同一事件 ID 在单个窗口通道内按发布顺序投递；跨发布者、跨进程不保证顺序。
- 同一 `(eventId, handler)` 多次订阅各自独立；`handler` 抛出的异常被捕获并记录，不影响其他订阅者与后续投递。
- `dispose()` 后不再收到投递；窗口销毁、插件停用或视图卸载时，订阅必须被释放。

### 3.4 `resource(uri)`

```typescript
resource(uri: string): IResourceHandle;
```

**参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `uri` | `string` | 是 | `chips-resource://<scope>/<path>`，或裸 `http(s)://`（按 [06-资源协议规范](./06-资源协议规范.md) §2.6 归一为 External URI）；完整语法（含 external 形式与百分号编码）见 [06-资源协议规范](./06-资源协议规范.md) |

**返回值**

| 类型 | 说明 |
|---|---|
| `IResourceHandle` | 懒打开的代理句柄；首次异步读取触发主进程 `open` |

**错误（同步抛出）**

| code | 触发 | retryable |
|---|---|---|
| `RESOURCE_INVALID_URI` | URI 语法非法 | `false` |
| `RESOURCE_UNSUPPORTED_SCHEME` | scheme 非 `chips-resource` 与裸 `http(s)://`（如 `file://`、`webdav://`） | `false` |
| `RESOURCE_PATH_INVALID` | 路径非法（含目录穿越尝试） | `false` |
| `RESOURCE_PERMISSION_DENIED` | 预检不通过 | `false` |

**规则**

- 同步预检基于会话权限快照，只是快速失败；权威判定在主进程首次 `open` 时执行，预检通过不代表最终放行。
- 句柄绑定创建它的资源会话；会话关闭时强制释放全部句柄（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 4.5 节）。
- 释放必须显式调用 `release()`；插件不得依赖垃圾回收。

### 3.5 `IResourceHandle` 成员参考

**`metadata()`**

| 项 | 说明 |
|---|---|
| 返回 | `Promise<IResourceMetadata>`；重复调用命中元数据缓存 |
| 错误 | 解析与判定错误（`RESOURCE_INVALID_URI`、`RESOURCE_UNSUPPORTED_SCHEME`、`RESOURCE_PATH_INVALID`、`RESOURCE_PERMISSION_DENIED`、`RESOURCE_NOT_FOUND`）；句柄错误（`RESOURCE_HANDLE_RELEASED`、`RESOURCE_HANDLE_INVALIDATED`、`RESOURCE_POOL_EXHAUSTED`）；外部资源网络错误（`RESOURCE_NETWORK_FAILED`） |

**`read()`**

| 项 | 说明 |
|---|---|
| 返回 | `Promise<Uint8Array>`；完整字节，`size` 不超过 8 MiB 时可调用 |
| 错误 | `RESOURCE_TOO_LARGE`（超过上限，改用 `readRange()` / `stream()`）；`RESOURCE_HANDLE_RELEASED`、`RESOURCE_HANDLE_INVALIDATED`、`RESOURCE_NETWORK_FAILED` |

**`readRange(offset, length)`**

| 项 | 说明 |
|---|---|
| 参数 | `offset`：起始偏移；`length`：读取长度 |
| 返回 | `Promise<Uint8Array>` |
| 错误 | `RESOURCE_BUSY`（流已打开）；越界或非法参数按资源错误拒绝（错误码以[06-资源协议规范](./06-资源协议规范.md)为准）；句柄错误同上 |

**`stream()`**

| 项 | 说明 |
|---|---|
| 返回 | `ReadableStream<Uint8Array>` |
| 错误 | 打开流失败按资源错误拒绝；句柄失效或 `release()` 会终止流并返回句柄错误 |
| 约束 | 同一句柄同时只服务一个流；流打开期间 `readRange()` 返回 `RESOURCE_BUSY` |

**`release()`**

| 项 | 说明 |
|---|---|
| 返回 | `void` |
| 行为 | 幂等：重复调用为 no-op；归还租约、关闭流与底层读取器；`released` 为终态且句柄 ID 不复用 |

**`onInvalidate(handler)`**

| 项 | 说明 |
|---|---|
| 参数 | `handler(reason: ResourceInvalidateReason)`：失效回调 |
| 返回 | `ISubscription`；`dispose()` 幂等 |
| 行为 | 句柄已失效后注册时，在下一微任务立即回调一次 `reason`；同时发布标准事件 `resource:invalidated` |

**状态可用性**

| 成员 | `open` | `invalidated` | `released` |
|---|---|---|---|
| `metadata` / `read` / `readRange` / `stream` | 可用 | `RESOURCE_HANDLE_INVALIDATED` | `RESOURCE_HANDLE_RELEASED` |
| `release` | 可用 | 可用 | 幂等 no-op |
| `onInvalidate` | 可用 | 立即回调 | 按 2.4 节统一规则处理 |
