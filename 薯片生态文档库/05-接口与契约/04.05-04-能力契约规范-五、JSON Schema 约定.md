## 五、JSON Schema 约定

### 5.1 方言与关键字子集

- `capability.schema` 统一描述**输入**，方言为 JSON Schema Draft 2020-12 的平台子集。
- schema 只能内联或经 `$defs` 定义；`$ref` 只允许 `#/$defs/<name>` 形式，禁止远程 `$ref`、网络加载、跨文件引用与自定义脚本关键字。
- schema 必须离线可编译；编译失败拒绝注册（`BRIDGE_INVALID_SCHEMA`）。

允许的关键字：

| 类别 | 关键字 |
|---|---|
| 结构 | `type`、`properties`、`required`、`additionalProperties`、`items`、`minItems`、`maxItems`、`uniqueItems`、`minProperties`、`maxProperties`、`propertyNames`、`$defs`、`$ref`（仅内部） |
| 组合 | `allOf`、`anyOf`、`oneOf` |
| 标量约束 | `minLength`、`maxLength`、`pattern`、`minimum`、`maximum`、`exclusiveMinimum`、`exclusiveMaximum`、`multipleOf`、`enum`、`const` |
| 注解 | `title`、`description`、`default`、`deprecated` |
| 平台扩展 | `format`（白名单见 5.3）、`x-chips-binary`（5.3） |

禁止的关键字：`$id`、`$schema`、`if` / `then` / `else`、`dependentSchemas` / `dependencies`、`patternProperties`、`unevaluatedProperties` / `unevaluatedItems`、`contains` / `minContains` / `maxContains`、`prefixItems` 及所有自定义脚本关键字。

### 5.2 编写规则

1. 顶层必须为 `type: "object"` 且显式声明 `additionalProperties: false`；无输入的调用写空对象 schema（`properties: {}`，可不写 `required`）。
2. 字段名一律 camelCase，与 TypeScript 接口一致；禁止未声明字段参与业务。
3. `required` 显式列出必填字段；可选字段必须在 `properties` 中声明，缺省语义由能力实现定义。
4. `default` 仅作注解：Bridge 与能力实现都不因 `default` 改写输入；文档示例中的默认值必须在 `execute` 内显式处理。
5. 数值类型严格：`integer` 不接受浮点值；`number` 不接受 `NaN` / `Infinity`；数组与字符串必须给出上限（`maxItems` / `maxLength`）。
6. 路径字段最小约束为 `minLength: 1`；资源 URI 字段使用 `format: "chips-resource-uri"`；网络 URL 字段使用 `format: "uri"` 并配合 scheme 白名单 `pattern`。
7. 二进制字段使用平台扩展关键字 `x-chips-binary`（见 5.3），不写 `type`；二进制一律经二进制信封的 `bin` 表承载（第 2.4 节），禁止以内联 base64 字符串字段兜底；文本编码选项（如 `file:read` 的 `encoding`）是显式接口语义，不属于二进制承载。
8. schema 只表达结构约束；业务规则（范围一致性、编码内容有效性）由 `execute` 校验并返回结构化错误。
9. 能力实现内部不得再对输入做与 schema 等价的结构校验（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 第 6.2 节）。

### 5.3 `format` 白名单与二进制扩展

| 关键字 | 类型 | 强制语义 |
|---|---|---|
| `format: "date-time"` | string | RFC 3339 日期时间 |
| `format: "uri"` | string | 绝对 URI |
| `format: "chips-resource-uri"` | string | `chips-resource://` URI，语法以 [06-资源协议规范](./06-资源协议规范.md) 为准 |
| `format: "chips-credential"` | string | `credential://<pluginId>/<name>` 引用，仅用于配置 schema（[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md)） |
| `x-chips-binary: <maxBytes>` | object | 属性值必须是 `Uint8Array`；`<maxBytes>` 为允许的最大字节数（省略表示不额外限制）；带该关键字的属性不再声明 `type`；值经二进制信封的 `bin` 表承载（第 2.4 节），输入输出同样适用 |

未列入白名单的 Draft 2020-12 标准 format 仅作注解，不做强制校验；新增自定义 format 必须经 RFC 加入白名单。

### 5.4 校验与错误详情

- 校验时机：注册期编译并缓存校验器；调用期在权限判定通过后使用缓存校验器校验输入（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 第 6.2 节）。
- 校验失败返回 `BRIDGE_INVALID_INPUT`，`details` 统一为：

```typescript
interface IValidationIssue {
  pointer: string;    // JSON Pointer，指向输入中的失败位置
  keyword: string;
  message: string;    // 简体中文
}

interface IInvalidInputDetails {
  capabilityId: string;
  errors: IValidationIssue[];
  truncated: boolean;
}
```

- 错误聚合规则：返回按 JSON Pointer 字典序升序排列的错误列表，最多 16 条；超出时截断并置 `truncated: true`。
- `details` 不得包含用户输入原文、凭证材料与内部路径；`message` 一律简体中文、面向用户。
- 校验通过后 `input` 原样交给 `execute`，Bridge 不做默认值填充与类型转换。

### 5.5 schema 演进

兼容变更（无需新能力 ID，随提供方版本发布）：

- 新增可选输入字段；
- 放宽约束（扩大 `enum`、降低 `minimum`、增大 `maxLength` / `maxItems`）；
- 新增输出字段；
- 在能力族内新增具体目标（如新增编码格式）。

破坏性变更（必须走 RFC，以新能力 ID 或平台主版本发布）：

- 新增必填输入字段、删除或重命名字段；
- 收紧约束（缩小 `enum`、提高 `minimum`、缩小 `maxLength`）；
- 改变字段语义、单位或默认行为；
- 变更所需权限集合。

规则：

1. 不保留双读、别名与兼容分支；破坏性变更不提供过渡期（大爆炸重构）。
2. 第三方能力的契约版本与其提供方插件版本一致，消费方通过 manifest `dependencies` 的版本范围约束（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 第 7.1 节）。
3. Bridge 不做能力级版本协商：同一能力 ID 同时只有一个生效注册。
