## 一、定位与边界

### 1.1 定位

本文是箱子布局插件角色的接口权威：渲染引擎、编辑链路、插件加载器与插件工具链按本文调用布局插件；布局插件按本文实现。接口一经发布即为契约，任何签名扩展或语义变更必须走 RFC 与评审（[变更与决策管理](../07-工程管理/03-变更与决策管理.md)）。

布局插件的职责只有一项：**把箱子的条目组织成可见、可交互的布局**。它不解析文件、不读取资源字节、不打开条目、不写回数据；这些动作全部由平台链路承担，布局插件通过正式接口消费结果。

### 1.3 基本约束

- 一个插件只有一个角色；布局插件的 `manifest.type` 固定为 `boxlayout`（R1、[ADR-005](../01-架构设计/ADR/ADR-005-插件不分类只分角色.md)）。
- 布局只决定箱子的呈现方式；切换布局不修改箱子数据，只切换生效的布局配置（ADR-005）。
- 查看态插件的渲染代码运行在布局帧（`sandbox="allow-scripts"` iframe）；帧内禁止 `window.chips`、`parent`、存储 API 与网络直连（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 4.5）。
- 编辑态布局编辑器经就近渲染挂载在应用 UI 内，由编辑链路经平台插件门面 `IPluginRuntime`（`loadLayout(layoutType)`）装载，复用同一解析结果与同一插件接口（R8）。
- 界面只使用 `@chips/ui`，禁止第二套组件库（R4）；文案简体中文直写（R5）。
