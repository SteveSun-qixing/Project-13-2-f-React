## 六、卡片类型注册（`cardTypes`）

### 6.1 manifest 声明

```yaml
id: chips.basecard.richtext
version: 1.0.0
type: basecard
name: 富文本卡片
description: 最小基础卡片插件示例
author: 薯片官方
license: MIT
runtime:
  targets: [host]
capabilities:
  cardTypes:
    - id: base.richtext
      name: 富文本卡片
      description: 内联 Markdown 文本内容，可配置字号与行高
      icon: assets/icons/richtext.svg
      extensions: [.md]
      aliases: [RichTextCard]
      configSchema: assets/schemas/richtext-config.schema.json
      exportFormats:
        - id: html
          name: HTML 片段
          extension: .html
          mimeType: text/html
```

### 6.2 字段

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | 是 | `string` | 卡片类型 ID（正式 ID）；取值以 [01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) 各类型 Schema 的 `card_type` 为准（如 `base.richtext`、`base.video`、`base.image`、`base.score`、`base.webpage`、`base.music`、`base.file`；04/01 未登记的类型见其 §6.10，由插件定义并随插件发布），文法 `^[A-Za-z][A-Za-z0-9]*(\.[a-z][a-z0-9-]*)*$`（允许点分形式）；全局唯一，发布后不得变更 |
| `aliases` | 否 | `string[]` | 历史别名列表；由插件声明，平台在读取 `.card/structure.yaml` 条目 `type` 与内容 `card_type` 时归一为正式 `id`，归一结果不回写文档；别名不得与其他类型的正式 `id` 或别名冲突 |
| `name` | 是 | `string` | 简体中文显示名 |
| `description` | 否 | `string` | 简体中文描述 |
| `icon` | 否 | `string` | 图标，包内相对路径，供类型选择器与插件市场展示 |
| `extensions` | 否 | `string[]` | 支持的文件扩展名（含点，如 `.txt`），用于导入与文件关联建议 |
| `configSchema` | 条件 | `string` | 卡片配置 schema 文件，包内相对路径且位于 `assets/` 内；类型使用 `config` 时必填 |
| `exportFormats` | 否 | `object[]` | 支持的导出格式；未实现 `export` 时必须省略；条目见 §6.3 |

### 6.3 导出格式条目

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | 是 | `string` | 格式 ID，`^[a-z][a-z0-9-]*$`；`export` 的 `format` 参数取值 |
| `name` | 是 | `string` | 简体中文显示名 |
| `extension` | 是 | `string` | 文件扩展名（含点） |
| `mimeType` | 是 | `string` | 产物 MIME 类型，必须与 `export` 返回的 `Blob.type` 一致 |

### 6.4 注册规则

1. 注册由平台在插件启用时完成，数据来源是 manifest，不执行插件注册代码；停用时注销（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §2.3.1）。插件不得在运行时动态增删卡片类型。
2. `cardType.id` 全局唯一：同一插件内不得重复；跨插件重复时后注册方启用失败，不覆盖既有注册。
3. 一个插件可声明多个卡片类型；每个类型的 `configSchema` 与 `exportFormats` 各自独立。
4. 停用后该类型的已打开视图被销毁并显示内容不可用提示，新的渲染请求被拒绝；文档数据保留在文件中不丢失。
5. 类型 ID 随插件发布即进入文档格式（`.card/structure.yaml` 条目 `type` 与内容配置 `card_type`），不得更名；需要新语义时新增类型。
6. 声明 `configSchema` / `exportFormats` 的路径与格式在安装校验与启用校验阶段确认；缺失或非法时该插件启用失败。
7. 别名只做读取归一：平台在解析后把入口 `type` / `card_type` 映射为正式 `id`，模型、渲染与编辑链路只看到正式 `id`；别名不写入文件、不参与类型选择器展示，同一别名不得被两个类型声明。
