## 三、处理器声明与层级

### 3.1 声明模型

处理器在 manifest `fileAssociations` 中声明（基础字段与校验入口见 [02-插件清单规范](../03-插件开发/02-插件清单规范.md) §7.4、[07-应用插件接口](./07-应用插件接口.md) §5.4）。本契约定义该条目的完整形状与扩展字段：

```typescript
/** 处理器层级。 */
export type HandlerTier = 'primary' | 'fallback';

/** manifest fileAssociations 条目。 */
export interface IFileAssociation {
  /** 扩展名数组：含点、小写、无重复；与 mimeTypes 至少一项非空。 */
  readonly extensions: readonly string[];
  /** 以打开方式接收文件；当前唯一动作。 */
  readonly action: 'open';
  /** MIME 声明：精确 MIME 或主类型通配（type/*）；小写。 */
  readonly mimeTypes?: readonly string[];
  /** 处理器层级；缺省 primary。 */
  readonly tier?: HandlerTier;
}
```

```yaml
id: chips.official.photo-viewer
type: app
ui:
  surface: window
  launcher:
    name: 图片查看器
fileAssociations:
  - extensions: [.png, .jpg, .jpeg, .webp, .gif, .bmp, .svg, .avif]
    mimeTypes: [image/png, image/jpeg, image/webp, image/gif, image/bmp, image/svg+xml, image/avif]
    action: open

# 万能文件查看器的兜底声明（节选）
id: chips.official.universal-file-viewer
fileAssociations:
  - extensions: [.pdf, .epub, .zip, .7z, .txt, .json, .yaml]
    mimeTypes: [application/pdf, application/epub+zip, application/zip, text/*]
    tier: fallback
    action: open
```

规则：

- `extensions` 与 `mimeTypes` **至少一项非空**：只覆盖扩展名的处理器可以省略 `mimeTypes`，只覆盖 MIME（如无扩展名的外部资源）的处理器可以写空扩展名数组 `[]`，两种声明都合法。
- 允许同一插件声明多个条目；同一插件在不同槽位、不同层级可以有不同声明。
- 声明即注册路由；同一槽位存在多个声明方时按 §4.1 解析。
- `basecard` / `boxlayout` 角色不得声明 `fileAssociations`（[02-插件清单规范](../03-插件开发/02-插件清单规范.md) §7.1）。

### 3.2 层级语义

| 层级 | 值 | 适用 | 匹配地位 |
|---|---|---|---|
| 专用处理器 | `primary` | 专用查看器、编辑器等对特定格式有完整实现的处理器 | 同等级候选中优先于兜底处理器 |
| 兜底处理器 | `fallback` | 通用文件查看器等「也能处理，但优先让专用处理器接管」的处理器 | 仅在同等级无专用候选时接管；用户偏好可将任一候选提为默认 |

- 层级不是权限、不是能力等级，只表达匹配优先级；平台不因层级差异限制处理器可声明的格式范围。
- 层级不改变候选资格：`fallback` 声明在专用处理器缺失、停用、失败或被用户偏好改选时正常接管。
- 旧版 `@fallback` 后缀的语义（「我也能处理，但优先让专用处理器接管」）由 `tier: fallback` 完整承接。

### 3.3 声明校验

安装与启用校验（失败返回 `CPK_MANIFEST_INVALID`，不落盘、不注册）：

1. `mimeTypes` 每项匹配 `^[a-z0-9!#$&^_.+-]+/([a-z0-9!#$&^_.+-]+|\*)$`，即小写精确 MIME 或主类型通配；`*/*` 不允许。
2. `extensions` 每项含前导点、全小写、无重复；空数组只在 `mimeTypes` 非空时合法。
3. `tier` 只取 `primary` / `fallback`；缺省 `primary`。
4. 同一条目内、同一插件内出现重复槽位声明时按槽位去重，保留最强声明（`primary` 优先于 `fallback`）并记录诊断。
5. `extensions` 为空且 `mimeTypes` 也为空的条目非法，安装校验失败。

### 3.4 候选集合

候选只来自处于 `active` 状态的插件（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §3.2）：

- `pending` / `starting` / `stopping` / `installed`（已安装未启用）/ `failed` 的插件不产生候选；
- 更新中的插件由生效代际声明候选，蓝绿替换完成后新代际接管（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §6.2）；
- 候选集合是解析时的即时快照；解析完成后发生的启用状态变化不影响本次投递结果。
