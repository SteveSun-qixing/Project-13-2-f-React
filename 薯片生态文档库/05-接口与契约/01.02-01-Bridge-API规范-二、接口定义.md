## 二、接口定义

### 2.1 `IChipsBridge`（唯一对外形状）

```typescript
interface IChipsBridge {
  request<TOutput>(capabilityId: string, input?: unknown): Promise<TOutput>;
  subscribe(eventId: string, handler: (payload: unknown) => void): ISubscription;
  resource(uri: string): IResourceHandle;
}

interface ISubscription {
  dispose(): void;
}
```

约束：

- **不包含 `context()`**：插件上下文由 Cordis 注入的 `ctx` 提供（主进程插件入口）；渲染侧没有 `ctx` 与 `context()`。
- 主进程调用面 `IAppBridge` / `IServiceBridge` 是 `IChipsBridge` 去掉 `subscribe` 的收窄投影（第 2.6 节）。
- 方法面冻结：新增或删除方法必须走 RFC 与评审；实现不得私自扩展。
- `subscribe` 必须返回可退订句柄，`dispose()` 必须幂等。
- 插件发布事件不是 Bridge 方法：渲染侧发布经能力 `event:publish` 走 `request` 链路。

### 2.2 `window.chips`

preload 通过 `contextBridge.exposeInMainWorld('chips', …)` 暴露与 `IChipsBridge` 同形状的对象（[ADR-002](../01-架构设计/ADR/ADR-002-Electron作为桌面端壳.md)）。下例为暴露面示意，`createSubscription` / `createResourceHandle` 属于平台内置实现，不对插件开放：

```typescript
contextBridge.exposeInMainWorld('chips', {
  request: (capabilityId: string, input?: unknown): Promise<unknown> =>
    ipcRenderer.invoke('bridge:request', capabilityId, input),
  subscribe: (eventId: string, handler: (payload: unknown) => void): ISubscription => {
    // 登记本地订阅、挂载监听并返回可退订句柄
    return createSubscription(eventId, handler);
  },
  resource: (uri: string): IResourceHandle => createResourceHandle(uri),
});
```

规则：

- `window.chips` 只暴露上述三个方法；不得额外暴露 `ipcRenderer`、`process`、`require` 等原始对象。
- 插件不得替换、代理、改写 `window.chips`；类型声明由 `@chips/sdk` 提供，插件不自行声明全局类型。
- 仅渲染进程存在 `window.chips`；主进程插件经 Cordis `ctx` 使用服务与注册能力，不得访问 `window`。

### 2.3 `ISubscription`

```typescript
interface ISubscription {
  dispose(): void;
}
```

| 成员 | 说明 |
|---|---|
| `dispose()` | 退订；幂等，可重复调用；调用后不再收到任何投递 |

- `subscribe` 与 `IResourceHandle.onInvalidate` 均返回 `ISubscription`。
- 与内核侧的 `IEventSubscription`（`ctx.on` 返回）是两个不同对象：前者属于渲染侧 Bridge 订阅，后者由 Cordis Fork 追踪；渲染侧订阅必须由视图显式释放，不依赖 Fork。

### 2.4 `IResourceHandle`

```typescript
type ResourceScope = 'workspace' | 'document' | 'plugin' | 'platform' | 'external' | 'temporary' | 'memory';
type ResourceState = 'open' | 'invalidated' | 'released';
type ResourceInvalidateReason = 'source-changed' | 'session-closed' | 'scope-revoked';

interface IResourceMetadata {
  uri: string;
  size: number;
  mimeType: string;
  version: string;
  scope: ResourceScope;
}

interface IResourceHandle {
  readonly uri: string;
  readonly state: ResourceState;
  metadata(): Promise<IResourceMetadata>;
  read(): Promise<Uint8Array>;
  readRange(offset: number, length: number): Promise<Uint8Array>;
  stream(): ReadableStream<Uint8Array>;
  release(): void;
  onInvalidate(handler: (reason: ResourceInvalidateReason) => void): ISubscription;
}
```

| 成员 | 说明 |
|---|---|
| `uri` | 创建句柄时的原始 URI |
| `state` | 句柄状态：`open` / `invalidated` / `released` |
| `metadata()` | 读取元数据；首次调用触发主进程 `open` |
| `read()` | 读取完整字节；超过 8 MiB 返回 `RESOURCE_TOO_LARGE` |
| `readRange()` | 按偏移读取；与 `stream()` 互斥 |
| `stream()` | 流式读取大资源 |
| `release()` | 释放句柄；幂等；终态后除 `uri` / `state` / `release()` 外的方法返回 `RESOURCE_HANDLE_RELEASED` |
| `onInvalidate()` | 订阅失效通知，返回 `ISubscription` |

状态机：

```text
resource(uri) ──▶ open ──release()──▶ released（终态，不可复用）
                   │  ▲
                   │  └── 重新读取必须再次调用 resource(uri)
        来源变化 / 会话关闭 / 权限撤销
                   │
                   ▼
             invalidated ──release()──▶ released
```

- 句柄不可序列化、不可持久化、不可跨会话传递；跨窗口必须各自创建句柄。
- 句柄不提供写入方法；写入经能力 `resource:write` 或文档保存流程提交（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 4.8）。
- 资源字节由 `chips-resource://` 协议处理器按 Range 提供，句柄只负责失效感知与生命周期。

### 2.5 `ChipsError`

```typescript
class ChipsError extends Error {
  constructor(options: {
    code: string;        // <DOMAIN>_<REASON>，如 BRIDGE_PERMISSION_DENIED
    message: string;     // 简体中文、面向用户
    details?: unknown;   // 结构化诊断
    retryable?: boolean;
  });
  readonly code: string;
  readonly message: string;
  readonly details?: unknown;
  readonly retryable: boolean;
}

interface IChipsError {
  code: string;
  message: string;
  details?: unknown;
  retryable?: boolean;
}
```

- 全生态只有 `ChipsError` 一个错误类（唯一名称）；`IChipsError` 仅作结构别名，不得自定义同形错误类。
- 构造统一为 `new ChipsError({ code, message, details?, retryable? })`；`retryable` 缺省为 `false`。
- `request` 与句柄异步方法失败时以 `ChipsError` reject，可用 `instanceof ChipsError` 判定。
- Host 业务错误码原样透传（如 `FILE_NOT_FOUND`、`DOCUMENT_NOT_OPEN`）；Bridge 只产生通道级错误码。
- `retryable` 只是提示；Bridge 不自动重试、不去重执行。

### 2.6 主进程调用面（`IAppBridge` / `IServiceBridge`）

主进程插件没有 `window.chips`；平台按角色提供收窄的调用面，发起能力调用的形状与渲染侧完全一致：

```typescript
type IAppBridge = Pick<IChipsBridge, 'request' | 'resource'>;
type IServiceBridge = Pick<IChipsBridge, 'request' | 'resource'>;
```

| 项 | 说明 |
|---|---|
| 方法面 | 仅 `request` 与 `resource`；**没有 `subscribe`**——主进程的事件订阅走 Cordis `ctx.on` / `ctx.once`（内核事件总线），不占用 Bridge 订阅通道 |
| 注入方式 | 应用插件经 `ctx.bridge`（类型 `IAppBridge`）调用，见 [07-应用插件接口](./07-应用插件接口.md) §4.6；服务插件经 `ctx.bridge`（类型 `IServiceBridge`）调用，见 [10-服务插件接口](./10-服务插件接口.md) §3.7 |
| 会话与判定 | 会话身份在插件激活时绑定；权限判定、schema 校验与审计与渲染侧同源，不得跳过 |
| 取消与超时 | 与渲染侧一致：能力实现收到 `ctx.signal` / `ctx.deadline`（第 3.2 节），调用受注册项超时约束 |
| 资源句柄 | `resource(uri)` 行为与错误码与渲染侧一致（第 3.4 节）；句柄同样绑定会话、不可跨会话传递 |

- 两种类型形状相同、语义相同；分开命名只为角色文档的类型归属清晰，防止主进程误用 `subscribe`。
- 主进程调用不经 preload 与 IPC 通道（同进程直调 Bridge 核心），但所有校验与审计规则不因此减少。
