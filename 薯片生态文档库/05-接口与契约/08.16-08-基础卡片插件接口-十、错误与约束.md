## 十、错误与约束

### 10.1 错误码

| 错误码 | 触发 | 产生方 | retryable |
|---|---|---|---|
| `CARD_EXPORT_UNSUPPORTED` | `export` 收到未声明的 `format` | 插件 | 否 |
| `CARD_EXPORT_FAILED` | `export` 内部失败（编码、资源、模板） | 插件 | 按失败原因设置 |
| `RENDER_PLUGIN_FAILED` | `renderView` 抛错或渲染失败 | 渲染引擎 | 是（重试重走完整链路） |
| `RENDER_PLUGIN_MISSING` | 找不到声明该 `card_type` 的插件 | 渲染引擎 | 否 |
| `RENDER_SCHEMA_UNSUPPORTED` | 已装插件的版本策略与能力声明不满足卡片内容要求 | 渲染引擎 | 否 |
| `RESOURCE_*` | 资源访问失败（路径、权限、大小、失效） | 资源层 | 按错误码 |

规则：

- 插件产生的错误必须是 `ChipsError`（`code` / `message` / `details?` / `retryable?`），`message` 为简体中文、面向用户；不得把内部堆栈、真实路径或字节内容放进 `message`。
- 渲染与资源错误由平台降级为占位呈现；插件不得用空 DOM 或静默失败代替结构化错误。
- 错误码一经发布不得改变语义；新增错误码走变更流程（[03-变更与决策管理](../07-工程管理/03-变更与决策管理.md)）。

### 10.2 约束清单

| 编号 | 约束 |
|---|---|
| BC-1 | `IBaseCardPlugin` 方法面冻结；不得扩展方法或改变签名，变更走 RFC（[01-架构原则](../00-愿景与原则/01-架构原则.md)）。 |
| BC-2 | 双入口职责固定：`dist/index.js` 只承载主进程纯函数（`validateConfig` / `createInitialContent` / `collectResourcePaths`），`render.js` 承载渲染方法（`renderView` / `renderEditor` / `export`）；一个入口只实现一个角色（R1）。 |
| BC-3 | `renderView` 逐节点独立容器调用，支持多次调用与覆盖式更新；`Dispose` 与 `IBaseCardEditor.dispose()` 必须幂等。 |
| BC-4 | 编辑结果只经 `IBaseCardEditor`、编辑链路与文档服务回流（`document:write` 先行并返回 revision）；插件不写文件、不直接操作渲染会话（R8）。 |
| BC-5 | `validateConfig` 为纯函数，判定不宽于 `configSchema`；两者都必须通过。 |
| BC-6 | `export` 不写文件、不修改视图，只返回 `Blob`；格式必须在 `exportFormats` 中声明。 |
| BC-7 | 资源只经协议路径与句柄路径访问；统一经 `chips-resource://`，受限、可审计（R17）。 |
| BC-8 | 渲染帧内禁止 `window.chips`、`parent`、`top`、存储与网络直连（R17、RR-3）。 |
| BC-9 | 视图只读且可结构化克隆；不得在 `BaseCardView` / `content` 上挂载运行时对象。 |
| BC-10 | 组件与样式只来自 `@chips/ui` 与 Design Tokens；禁止第二套组件库与全局样式（R4）。 |
| BC-11 | 卡片类型 ID 全局唯一且发布后不可更名；别名只做读取归一；停用不删除用户数据（R1、R8）。 |
| BC-12 | 插件抛错由调用方隔离；释放后不得再触碰容器、句柄或订阅。 |
| BC-13 | `renderView` / `renderEditor` / `export` 只由平台调用；应用与编辑链路不得 import 插件代码，必须经 `IManagedPluginRuntime` 门面装载（§2.5）。 |
