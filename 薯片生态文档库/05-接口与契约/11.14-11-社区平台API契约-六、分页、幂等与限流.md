# 社区平台 API 契约

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片社区平台服务端（`Chips-CommunityPlatformServer`）对外 HTTP API 的唯一权威契约：基础约定、认证与令牌、内容浏览与检索、管理端接口、卡片与箱子传输控制面、分页/幂等/限流、错误模型与错误码、版本兼容、TLS/CORS/路径安全、示例与自检清单；不覆盖社区网页与后台的产品设计、服务端实现与部署运维，不覆盖个人服务器差异（见 `12-个人服务器API契约`），不覆盖卡片传输的客户端协议细节（见 `16-卡片传输协议`）。

## 六、分页、幂等与限流

### 6.1 分页

- 列表接口统一使用 `page` 与 `pageSize`：`page` 从 1 开始，缺省 1；`pageSize` 缺省 20、最大 100。
- 响应中的 `pagination` 固定为 `page` / `pageSize` / `total` / `totalPages`；`total` 为当前可见范围的总条数。
- 非法分页参数（非整数、超出范围）返回 `COMMUNITY_VALIDATION_ERROR`（`400`）。
- 超过 `totalPages` 的页返回空数组与正确的分页对象，不返回错误。
- 列表排序规则：发现与按用户列表按 `createdAt` 倒序；房间内容按发布时间倒序；排序规则在同一端点内固定，不通过查询参数改变。

### 6.2 幂等

- 幂等键使用请求头 `Idempotency-Key`：8–128 个可见 ASCII 字符。
- 要求幂等的端点：`POST /api/v1/card-transfer/upload-sessions`（必须）、`POST /api/v1/card-transfer/download-sessions`（可选）、`POST /api/v1/rooms`（可选）。
- 语义：同一账号在同一端点上使用相同幂等键重复请求时，若请求体一致则返回首次结果（含状态码与响应体，会话 ID 相同）；请求体不一致返回 `409 COMMUNITY_IDEMPOTENCY_CONFLICT`。
- 幂等记录保留时间由服务端配置，不得低于上传会话有效期；客户端不得把幂等键当成长效凭证。
- 删除、变更可见性、登出、中止按各自语义幂等（见 3.4、4.8、5.5），不要求幂等键。

### 6.3 限流

- 限流按账号与来源 IP 两个维度分别计数；未认证请求按来源 IP 计数。
- 触发限流返回 `429 COMMUNITY_RATE_LIMITED`，并携带 `Retry-After`（秒）；同时返回以下响应头：

| 响应头 | 含义 |
|---|---|
| `X-RateLimit-Limit` | 当前档位窗口内允许的请求数 |
| `X-RateLimit-Remaining` | 当前窗口剩余请求数 |
| `X-RateLimit-Reset` | 当前窗口重置时刻（Unix 秒） |

- 认证类接口与传输控制面使用比浏览接口更严格的档位；具体阈值由服务端配置。
- 客户端收到 `429` 必须按 `Retry-After` 退避并加入抖动，禁止立即重试、禁止并发重试；浏览类轮询遇 `429` 应降频。

### 6.4 条件请求与缓存

- 公开浏览类 `GET` 返回 `ETag`；客户端可携带 `If-None-Match`，命中返回 `304` 无正文。
- 认证、传输控制面、查看/封面入口与渲染状态接口返回 `Cache-Control: no-store`。
- 公开缓存（对象存储/CDN）由对象存储与 CDN 承载，缓存头由服务端在发布产物时写入；客户端不得依赖本 API 自身的响应缓存。

### 6.5 限额

| 项 | 约束 |
|---|---|
| 单卡片作品上限 | 部署配置 `MAX_CARD_SIZE_MB`，默认 500（单位 MiB） |
| 单箱子作品上限 | 部署配置 `MAX_BOX_SIZE_MB`，默认 100（单位 MiB） |
| 单对象上限 | 由对象存储与部署配置共同决定；`capabilities.multipart = false` 时在拒绝响应 `details` 中给出 |
| `restoreManifest` 大小上限 | 服务端部署配置；超出返回 `COMMUNITY_FILE_TOO_LARGE` |

- **卡片作品体积**＝网络资源卡片对象 + `resources[]` 全部对象 + 本次提交的 `render-file` / `cover-file` 产物对象之和；**箱子作品体积**＝`box-file` 对象大小。
- 服务端必须在两个执行点校验：`objects:presign` 阶段按请求声明的 `sizeBytes` 累计校验，`complete` 阶段按对象存储实际大小复核；超限一律返回 `COMMUNITY_FILE_TOO_LARGE`（`413`），`details` 携带 `limitKind`（`card` / `box` / `object`）、`limitBytes` 与 `actualBytes`。
- 超限会话不得完成；已上传对象按 5.5 的完成/中止规则与会话过期清理处理，不进入任何作品列表。
- 客户端传输引擎应在上传前按服务端生效上限预检；不得以分片拼接、对象拆分或多会话并发绕过作品上限。
- 上限由部署配置调整，只影响新会话；默认值不是固定契约，客户端不得把默认值当作硬编码常量。
