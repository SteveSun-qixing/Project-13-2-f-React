## 十、版本与发布

### 10.1 版本规则

- SDK 与 `@chips/bridge`、`@chips/host`、`@chips/ui` 及全部 Rust crate 共用同一平台版本号，任一平台包发布时统一升版，禁止版本漂移（[代码组织规范](../02-开发规范/01-代码组织规范.md)第 3.4 节）。
- 版本起点 `0.1.0`，Phase 4 发布 `1.0.0`；第一版发布前不承诺兼容（[ADR-010 大爆炸重构策略](../01-架构设计/ADR/ADR-010-大爆炸重构策略.md)）。
- 预发布依次使用 `-alpha.N`、`-beta.N`、`-rc.N`；破坏性变更随平台 major，不单独为 SDK 发 major。
- 包内不写死内部依赖版本，一律使用 `workspace:*`。

### 10.2 发布产物

```json
{
  "name": "@chips/sdk",
  "type": "module",
  "main": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" },
    "./testing": { "types": "./dist/testing/index.d.ts", "default": "./dist/testing/index.js" },
    "./scaffold": { "types": "./dist/scaffold/index.d.ts", "default": "./dist/scaffold/index.js" }
  },
  "sideEffects": false,
  "files": ["dist"]
}
```

- 产物为 ESM + `.d.ts` + sourcemap，全部落在 `packages/sdk/dist/`，不入库。
- 三个入口均声明 `types`；未声明子路径在解析阶段直接失败。
- 测试文件、夹具与 `tests/` 不进入发布产物；`testing` 与 `scaffold` 随包发布但只供开发期消费。
- 发布时点、制品校验与自动化流程见 [构建与打包](../06-开发与运维/02-构建与打包.md)、[CI/CD 与质量门禁](../06-开发与运维/05-CICD与质量门禁.md)。

### 10.3 变更与文档同步

- SDK 的类型、导出名称或入口结构变更必须走 RFC 评审，并同 PR 更新本文与 [代码组织规范](../02-开发规范/01-代码组织规范.md)（[变更与决策管理](../07-工程管理/03-变更与决策管理.md)）。
- 能力、事件、资源、角色接口的形状变更以对应接口文档为准；SDK 文档只同步导出清单与入口。
