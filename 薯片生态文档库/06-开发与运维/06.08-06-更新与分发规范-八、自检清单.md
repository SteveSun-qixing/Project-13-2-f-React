# 更新与分发规范

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片平台更新与分发的权威规范：平台更新（更新源与渠道、更新包签名链与信任根、版本比较与防降级、原子替换与失败恢复、灰度与暂缓、离线更新包、重启边界）、插件分发（`.cpk` 来源、市场协议契约、`engines.chips` 兼容门禁、安装包与内置插件首启引导）、版本回退声明、与构建/CICD 的衔接、供应链安全与审计、约束与自检清单。

---

## 八、自检清单

- [ ] 更新源按渠道分根、HTTPS 固定；用户通道仅 `platform.update.channel`（平台层策略键）可改。
- [ ] 更新索引字段与 `chips-update-index-v1` 一致，含 `paused` 与 `rollout`。
- [ ] 签名链与 `.cpk` 同构；客户端从实际下载字节重算 `sha256` / `contentHash`，未登记 `keyId` 一律拒绝。
- [ ] 代码签名与公证校验（macOS / Windows）在替换前完成。
- [ ] 版本比较与防降级矩阵有测试覆盖（更高 / 相等 / 更低 / 预发布）。
- [ ] 下载、校验、替换、首次启动自检的每一步失败都可恢复更新前状态，并有对应错误码。
- [ ] 灰度哈希使用非隐私设备标识；暂缓不阻止用户手动检查与离线安装。
- [ ] 离线包与在线包字节一致；`SHA256SUMS.txt` 校验流程可用。
- [ ] 更新前收敛流程（编辑 flush、会话释放、插件静默、退出原因 `shutdown`）已实现。
- [ ] `.cpk` 三类来源安装校验链一致；市场下载有来源白名单与本地复核。
- [ ] 市场协议五个操作的契约、隐私最小化与失败不阻断语义与 §3.2 一致。
- [ ] `engines.chips` 字段已登记进清单 schema，四处门禁与 `CPK_ENGINE_UNSUPPORTED` 行为一致。
- [ ] 平台与插件均无降级安装入口；重启自检对不满足 `engines` 的插件给出可见提示。
- [ ] 发布产物清单与 §5.2 一致；更新索引由流水线生成并随产物校验。
- [ ] 安装产物含 `builtin-plugins/`（`index.json` 与逐个已签名 `.cpk`）且不进入 asar；清单与包文件同批生成。
- [ ] 首启内置插件引导按"校验 → 装载 → 启用 → 自检"执行；单项失败隔离并审计，平台启动不被阻塞。
- [ ] 内置插件登记 `source: builtin` 且不可卸载；用户停用与授权记录在自检、重装与平台更新后保留。
- [ ] 首启引导由设置面板承载、可跳过、可重跑，状态存于面板自身命名空间，且不产生隐式授权。
- [ ] 审计字段完整且不含凭证与用户数据；错误文案为简体中文。
