# 更新与分发规范

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片平台更新与分发的权威规范：平台更新（更新源与渠道、更新包签名链与信任根、版本比较与防降级、原子替换与失败恢复、灰度与暂缓、离线更新包、重启边界）、插件分发（`.cpk` 来源、市场协议契约、`engines.chips` 兼容门禁、安装包与内置插件首启引导）、版本回退声明、与构建/CICD 的衔接、供应链安全与审计、约束与自检清单。

---

## 七、约束清单

| 编号 | 约束 |
|---|---|
| UD-1 | 平台更新与插件更新是两条独立链路，互不经过对方入口；平台无插件更新接口。 |
| UD-2 | 渠道固定为 `stable` / `beta`（用户可选）与 `rc` / `alpha`（内部）；用户通道只由平台层策略键 `platform.update.channel` 控制。 |
| UD-3 | 更新包必须经"摘要 → contentHash → Ed25519 签名 → 信任根"完整校验，且客户端从实际字节重算摘要。 |
| UD-4 | 签名校验不替代平台代码签名与公证；两者都必须通过。 |
| UD-5 | 只接受严格高于已安装版本的更新；相等 no-op、更低确定性拒绝（防降级）。 |
| UD-6 | 更新必须原子：新版本首次启动自检通过前不算完成；任何失败回到更新前状态。 |
| UD-7 | 同版本 `apply-failed` / `boot-failed` 后不自动重试；只等待更高版本。 |
| UD-8 | 灰度与暂缓由更新索引控制；用户暂缓只跳过具体版本，不改变渠道。 |
| UD-9 | 离线更新包与在线包字节相同、校验相同、防降级相同；不提供静默安装。 |
| UD-10 | 平台更新以重启为边界；更新前必须 flush 编辑会话并收敛运行态。 |
| UD-11 | `.cpk` 三类来源共用同一条安装校验链；市场下载不得跳过归档/结构/清单/签名/摘要校验。 |
| UD-12 | 市场协议只定义发现/详情/下载/更新检查/安装回调；市场服务端由社区实现，平台不内置账户体系。 |
| UD-13 | `engines.chips` 在安装、启用、平台更新后自检、插件更新四处执行；不满足确定性拒绝或停用。 |
| UD-14 | 平台不提供旧版本回退安装；插件不保留历史版本目录，停用/卸载/更新到修复版本是唯一恢复路径。 |
| UD-15 | 发布索引与 `latest` 提要不得手工编辑；必须由发布流水线生成并随产物一同校验。 |
| UD-16 | 更新与分发动作全程审计；审计不含凭证、私钥与用户文件内容。 |
| UD-17 | 内置插件必须是已签名 `.cpk` 并随安装产物分发；安装器只放置产物，不执行插件安装、启用与业务逻辑。 |
| UD-18 | 首启内置插件引导按"校验 → 装载 → 启用 → 自检"固定顺序执行；单项失败隔离并审计，不阻塞平台启动，不产生隐式授权。 |
| UD-19 | 内置插件不进入用户安装区、不可卸载；用户停用与授权记录在自检与重装时保留。 |
| UD-20 | `builtin-plugins/` 清单与包文件由发布流水线同批生成、签名；禁止手工编辑安装产物内的插件集合。 |
