## 五、Monorepo 初始化与常用命令

### 5.1 工作区骨架

仓库根只放工作区配置与文档，六个必需文件如下（完整内容以 [01-代码组织规范](../02-开发规范/01-代码组织规范.md) 第二、八章为准）：

| 文件 | 作用 |
|---|---|
| `package.json` | `"private": true`；声明 `"packageManager": "pnpm@9"` 与聚合脚本；禁止声明业务依赖 |
| `pnpm-workspace.yaml` | 声明 `packages/*`、`plugins/*`、`tools/*`、`examples/plugins/*` 工作区成员 |
| `Cargo.toml` | Rust workspace 清单：`members`、`[workspace.package]` 统一版本与 edition、`[workspace.dependencies]` 统一第三方 crate 版本 |
| `tsconfig.base.json` | 全仓共享 TypeScript 编译选项；所有 TS 包以 `"extends"` 继承 |
| `.gitignore` | 忽略 `node_modules/`、`dist/`、`target/`、`coverage/`、`release/`、`*.node`、`*.cpk` |
| 锁文件 | `pnpm-lock.yaml` 与 `Cargo.lock` 必须提交，保证构建可复现 |

### 5.2 本地检出初始化

初始化流程：

```text
安装工具链（第三、四章）
        ↓
git clone <仓库地址> && cd chips-ecosystem
        ↓
pnpm install                     # 还原 Node 工作区依赖
        ↓
cargo build --workspace          # 编译 Rust workspace，验证 Neon 绑定可构建
        ↓
pnpm typecheck && pnpm lint && pnpm test    # 环境校验
        ↓
pnpm dev                         # 启动开发环境
```

对应命令（macOS / Windows 通用）：

```bash
git clone <仓库地址> chips-ecosystem
cd chips-ecosystem

pnpm install
cargo build --workspace

pnpm typecheck
pnpm lint
pnpm test

pnpm dev
```

说明：

- `pnpm dev` 自带 Rust 增量编译；首次初始化显式执行一次 `cargo build --workspace`，便于把工具链问题与业务问题分开定位。
- `chips-native.node` 由构建流程从 `target/` 复制到 `packages/host/native/`，禁止手工拷贝或入库，产物路径见 [01-代码组织规范](../02-开发规范/01-代码组织规范.md) §7.1。
- 首次 Rust 全量编译耗时较长，属正常现象；后续为增量编译。

### 5.3 常用命令

| 场景 | 命令 |
|---|---|
| 还原依赖 | `pnpm install` |
| 校验锁文件一致性 | `pnpm install --frozen-lockfile` |
| 启动开发环境 | `pnpm dev` |
| 全量构建（Rust → TS 包 → 插件） | `pnpm build` |
| 全仓测试 | `pnpm test` |
| 生成覆盖率报告 | `pnpm test:coverage` |
| 契约测试（核心导出面、角色接口快照、帧协议） | `pnpm test:contract` |
| 文档库门禁（坏链、索引、文档头、API 文档覆盖率） | `pnpm docs:check` |
| 代码检查（ESLint + Prettier + rustfmt + clippy） | `pnpm lint` |
| 类型检查（`tsc -b` 全仓） | `pnpm typecheck` |
| 生成安装包与 `.cpk` | `pnpm package` |
| 清理构建产物 | `pnpm clean` |
| 单包构建 | `pnpm --filter @chips/ui build` |
| 单包测试 | `pnpm --filter @chips/plugin-editor test` |
| 单 crate 构建 | `cargo build -p chips-core` |
| 单 crate 测试 | `cargo test -p chips-parser` |
| 单 crate 检查 | `cargo clippy -p chips-bridge --all-targets -- -D warnings` |
| 单 crate 格式化 | `cargo fmt -p chips-cordis` |

脚本语义与标准脚本清单以 [01-代码组织规范](../02-开发规范/01-代码组织规范.md) §8.1 为准；`pnpm -r` 默认按 workspace 依赖拓扑排序，禁止手工罗列包顺序。

### 5.4 依赖变更

```bash
# 新增第三方 Node 依赖（先完成选型评估，见 5.5）
pnpm --filter @chips/ui add <包名>

# 新增工作区内依赖
pnpm --filter @chips/host add @chips/bridge@workspace:*
```

Rust 第三方依赖统一登记在仓库根 `Cargo.toml` 的 `[workspace.dependencies]`，crate 内按 workspace 引用：

```toml
# Cargo.toml（仓库根）
[workspace.dependencies]
serde = { version = "1", features = ["derive"] }
```

```toml
# crates/chips-parser/Cargo.toml
[dependencies]
serde = { workspace = true }
```

依赖变更后必须更新并提交 `pnpm-lock.yaml` 与 `Cargo.lock`；锁文件由包管理器生成，禁止手工编辑。

### 5.5 工作区约束

- 依赖安装只在仓库根执行；禁止在根 `package.json` 声明业务依赖。
- 内部依赖只允许 `workspace:*`（pnpm）与 `version.workspace = true`（Cargo）；禁止 `file:`、`link:` 与写死的具体版本号。
- 新增依赖（含第三方库与 crate）前必须完成选型评估：用途、许可证、维护状态、包体影响、安全风险、跨端兼容性；改变基础架构、长期运行时依赖或公共协议时按 RFC → 评审 → ADR 流程决策，见 07-工程管理/03-变更与决策管理.md。
- 禁止提交构建产物：`node_modules/`、`dist/`、`target/`、`coverage/`、`release/`、`*.node`、`*.cpk` 与测试夹具。
