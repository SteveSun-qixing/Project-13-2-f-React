# 服务端部署与运维

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片生态服务端产品（社区平台服务器、个人服务器）的部署与运维权威规范：环境与拓扑、域名/HTTPS/证书/CSP/CORS、对象存储、容器化与进程管理、配置与密钥管理、备份恢复、日志监控、升级回滚、服务器连接与口令管理、故障清单与自检清单；不覆盖服务端产品的 API 契约、数据模型与业务模块实现。

## 十二、服务端故障清单

平台侧错误码与客户端故障见[04-故障排查手册](./04-故障排查手册.md)；本表只列服务端部署与运维故障。

| 现象 | 可能原因 | 定位 | 处置 |
|---|---|---|---|
| `502 Bad Gateway`（前台或 API） | `server` 未启动、崩溃、迁移失败 | `docker compose ps`；`logs server` | 修复迁移/配置错误后重建容器 |
| 健康检查失败 | 数据库、Redis 或桶初始化失败 | `logs server` 中启动顺序各阶段 | 按失败阶段修复依赖后重启 |
| 浏览器报 CORS 错误 | 请求来源不在白名单；`BASE_URL` 与访问域名不一致 | 核对 `BASE_URL`、`CORS_EXTRA_ORIGINS` 与响应头 | 修正域名或追加来源后重建容器 |
| 登录成功但很快掉线 | Cookie `secure` 但未走 HTTPS；跨域导致 Cookie 未保存 | 检查访问协议与 Cookie 参数 | 全站 HTTPS；主站入口与 API 同源 |
| 上传 `.card` 后一直处理中 | Worker 未运行、Redis 不可达、私有桶读写失败 | `logs worker`；队列与任务表状态 | 启动 Worker；修复 Redis/桶权限；滞留任务会自动重新入队 |
| 渲染任务持续失败 | 源文件缺失、渲染集成插件路径错误、缓存版本不匹配 | `logs worker`；任务错误记录 | 恢复源文件；核对插件路径与 `CARD_RENDERER_VERSION` |
| 公开资源 404 | 对象 key 与公开 URL 前缀不一致；单桶模式使用了 bucket 专属端点 | 对比上传 path 与 `S3_PUBLIC_URL` 拼接 URL | 改用通用端点；核对逻辑桶前缀 |
| 新上传图片/HTML 乱码 | 对象元数据含 `content-encoding: aws-chunked` | `curl -I` 新对象检查响应头 | 使用 `WHEN_REQUIRED` 校验策略并重新上传 |
| 视频/音频无法播放 | 资源入口不支持 `Range` / `206` | `curl -I -H "Range: bytes=0-1023"` 目标资源 | 修复对象存储/CDN 的分段读取配置 |
| 磁盘将满 | 日志、构建缓存、镜像与数据卷增长 | `df -h`；`docker system df` | 清理无用镜像与构建缓存；配置日志轮转；扩容 |
| 数据库连接拒绝 | PostgreSQL 未启动、密码错误、连接数占满 | `logs postgres`；连接串与 `.env` | 修正密码/连接串；排查连接泄漏 |
| 证书过期告警 | 未续期或续期失败 | 浏览器与 `openssl s_client` 校验 | 按 §9.4 续期并 reload |
| 升级后新窗口打不开（迁移失败） | 迁移与镜像不匹配、备份未覆盖 | `logs server` 迁移输出 | 按 §9.3 回滚镜像并恢复数据库 |
| 同机部署后另一个产品容器被重建 | Compose 项目名冲突 | `docker compose ls`；项目名 | 按 §5.6 固定唯一项目名后重新部署 |
| 后台静态资源 404 或缓存过期 | Nginx 缓存规则与前端路径不匹配 | 检查 `/assets/` 与 `/admin/assets/` 响应头 | 按 §3.6 恢复缓存规则；发布时带哈希 |
| 面板无法登录或暴露公网 | 面板访问限制缺失 | 端口扫描与面板日志 | 限制来源地址、改强密码、关闭公网端口 |
