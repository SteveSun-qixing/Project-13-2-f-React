### 5.6 SDK 接口

`client.cliCommand` 与 `client.cliTask` 随 `@chips/sdk` 主入口导出（客户端创建见 [02-SDK-API规范](../05-接口与契约/02-SDK-API规范.md) §3.2）：

```typescript
import type { CliCommandApi, CliTaskApi } from '@chips/sdk';
import { createClient } from '@chips/sdk';

const client = createClient();
const { index, commands } = await client.cliCommand.list({ targetType: 'app' });
const resolved = await client.cliCommand.resolve({ commandPath: 'office open' });
```

发现接口：
type CliCommandTargetType = 'app' | 'service';

interface CliCommandQueryOptions {
  entryId?: string;
  commandPath?: string | string[];
  pluginId?: string;
  targetType?: CliCommandTargetType;
  includeDisabled?: boolean;
}

interface CliCommandApi {
  list(options?: CliCommandQueryOptions): Promise<CliCommandListResult>;
  get(options: CliCommandQueryOptions): Promise<CliCommandView | undefined>;
  resolve(options: CliCommandQueryOptions): Promise<CliCommandResolveResult>;
}

interface CliCommandListResult {
  index: CliCommandIndex;
  commands: CliCommandView[];
interface CliCommandResolveResult {
  command?: CliCommandView;
  conflicts: CliCommandConflict[];
}
```

`CliCommandView` 同时携带 CLI 侧标识与运行时命令引用：`entryId`（CLI 入口标识）、`commandPath`、`commandId?`（`app` 目标的运行时命令 ID）、`owner`、`enabled`、`declaration` 与 `conflicts`。

任务接口（应用插件侧经 Bridge 能力访问，CLI 与平台组件经服务路由访问，SDK 客户端统一封装）：

| 能力 ID | 输入 | 输出 | 说明 |
|---|---|---|---|
| `cli:task-active` | `commandId` | `{ task? }` | 返回调用插件当前 `running` 任务（owner 归属） |
| `cli:task-get` | `taskId` | `{ task }` | 读取任务（owner 归属；长任务据此检查取消终态） |
| `cli:task-progress` | `taskId`、`progress` | `{ task }` | 上报进度（owner 归属） |
| `cli:task-complete` | `taskId`、`output?` | `{ task }` | 上报完成终态（owner 归属） |
| `cli:task-fail` | `taskId`、`error` | `{ task }` | 上报失败终态（owner 归属） |

这 5 项能力声明空权限数组：任务按所有者归属校验，插件不能读写他人任务，也不需要额外权限（R19 登记见 §5.8）。

```typescript
type CliTaskStatus = 'running' | 'completed' | 'failed' | 'cancelled';

interface CliTaskRecord {
  taskId: string;
  pluginId: string;
  commandId: string;
  commandPath?: string[];
  status: CliTaskStatus;
  createdAt: number;
  updatedAt: number;
  progress?: Record<string, unknown>;
  output?: unknown;
  error?: { code: string; message: string; details?: unknown; retryable?: boolean };
}

interface CliTaskApi {
  create(input: { pluginId: string; commandId: string; commandPath?: string[] }): Promise<CliTaskRecord>;
  bindInvocation(input: { taskId: string; invocationId?: string; sessionId?: string }): Promise<CliTaskRecord>;
  get(taskId: string): Promise<CliTaskRecord>;
  active(commandId: string): Promise<CliTaskRecord | undefined>;
  progress(taskId: string, progress: Record<string, unknown>): Promise<CliTaskRecord>;
  complete(taskId: string, output?: unknown): Promise<CliTaskRecord>;
  fail(taskId: string, error: unknown): Promise<CliTaskRecord>;
  cancel(taskId: string): Promise<CliTaskRecord>;
}
```

调用方约定：

- CLI 调度链路使用 `create` 与 `bindInvocation`（服务路由）；应用插件在 `handleCommand` 中经 `cli:task-active` 取得当前任务，再用 `cli:task-progress` / `cli:task-complete` / `cli:task-fail`，长任务周期性 `cli:task-get` 检查取消终态；SDK `client.cliTask` 对上述两侧做类型化封装。
- `cancel` 是 CLI 侧方法，插件不调用：应用按 `job.cancelOnInterrupt` 对应的取消请求，经 `cli:task-get` 观察到 `cancelled` 后停止并释放资源。
- `active(commandId)` 返回调用插件当前 `running` 的 CLI 任务；无任务（例如 `job.wait: false`）返回 `undefined`；同一 `(pluginId, commandId)` 同时最多一个 `running` 任务，CLI 对同一命令串行调度。
- `fail` 的 `error` 归一为 `{ code, message, details?, retryable? }`；无 `code` 时按 `CLI_TASK_FAILED` 收口。
- 任务只允许所属插件读写（归属校验），越权请求拒绝；`progress` 为任意 JSON 对象，约定 `percent`（0–100）与 `stage`（字符串）参与 CLI 进度展示（§3.10）。
