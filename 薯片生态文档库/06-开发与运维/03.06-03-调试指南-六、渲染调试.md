## 六、渲染调试

### 6.1 渲染追踪字段

`CHIPS_TRACE=render` 开启；帧消息清单、封套与约束见 [05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 第 9 节。

| 字段 | 含义 |
|---|---|
| `sessionId` / `frameId` | 渲染会话与帧标识 |
| `frameRole` | `card` / `box-layout` / `entry` / `cover` |
| `message` | `frame:ready`、`frame:height`、`frame:entry-request`、`frame:action`、`frame:error`、`host:init`、`host:update`、`host:entries`、`host:height-ack`、`host:action-error`、`host:dispose` 等 |
| `protocolVersion` | 封套 `protocol` 值（当前 `chips-frame/1`） |
| `epoch` / `revision` | 高度批次数 / 视图修订号，用于校验单调性 |
| `outcome` / `errorCode` | 投递结果；协议违规为 `RENDER_PROTOCOL_VIOLATION` |

### 6.2 帧与沙箱调试步骤

1. Elements 面板检查目标 iframe：`sandbox="allow-scripts"`、`referrerpolicy="no-referrer"`、无 `allow` 特性；不符即缺陷（D-2）。
2. Network 面板过滤 `frame.html`、`render.js`、封面文档：应经 `chips-resource://` 加载；403/404 转第 6.4 节。
3. 帧内异常在 Console 切换到对应 frame 上下文查看；帧内 `window.chips` 为 `undefined` 属预期。
4. 握手失败（5 秒后 `RENDER_FRAME_TIMEOUT`）检查：帧 URL 是否携带一次性令牌、首条 `postMessage` 是否转移 MessagePort、帧运行时是否加载成功；在追踪中确认 `frame:ready` 是否到达。
5. `RENDER_PROTOCOL_VIOLATION` 检查：消息类型是否在清单内；是否越级发送（条目帧不得直接请求 RenderHost）；`epoch`/`revision` 是否非递增；越级与未知消息按协议违规断链。
6. 高度问题检查：追踪中 `frame:height` 与 `host:height-ack` 是否配对；布局帧是否聚合条目高度后上报；达到 `maxHeight` 后应转帧内滚动且父帧停止更新。
7. 会话释放问题：按 dispose 顺序核对（帧 → 端口 → 资源句柄 → 缓存引用）；`RENDER_SESSION_DISPOSED` 表示调用方持有已释放会话。

### 6.3 降级占位验证

用测试夹具（`tests/fixtures/`）构造下表失败，确认占位使用 `@chips/ui` 组件、简体中文文案、展示错误码与重试入口，且重试重走完整链路。

| 场景 | 构造方法 | 期望错误码 |
|---|---|---|
| 基础卡片插件缺失 | 打开引用未安装 `card_type` 的卡片 | `RENDER_PLUGIN_MISSING` |
| 插件 / 能力 / schema 与内容要求不匹配 | 用超出已装插件 `configSchema` / 能力声明的内容夹具打开 | `RENDER_SCHEMA_UNSUPPORTED` |
| 插件渲染抛错 | 夹具插件在 `renderView` 内抛错 | `RENDER_PLUGIN_FAILED` |
| 资源越权 | 引用未授权作用域资源 | `RENDER_RESOURCE_DENIED` |
| 文档损坏 | 使用解析诊断夹具（[06-文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md) 第 8.3 节） | `RENDER_DOCUMENT_INVALID` |
| 帧握手超时 | 阻断帧运行时加载后打开卡片 | `RENDER_FRAME_TIMEOUT` |

文档格式版本问题（`DOCUMENT_VERSION_OUTDATED` / `DOCUMENT_VERSION_UNSUPPORTED` / `DOCUMENT_VERSION_MISMATCH`）由解析链路在渲染前判定，不产生渲染占位，夹具与验证见 [06-文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md) 第八节。

### 6.4 资源 URI 问题定位

症状：图片/字体裂图、媒体错误态、封面不显示、Console 出现 `chips-resource:` 请求失败。

1. Network 面板确认请求 URI 为 `chips-resource://<scope>/<path>`；帧内出现 `file://` 直载、`blob:` 或远端地址直连即违规（D-3）。内容配置中持久化的 `blob:`、`data:`、系统绝对路径同为格式缺陷（[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md)）。
2. 403：查审计文件中该 `resourceUri` 的拒绝记录与 `reason`，处理方式同第 5.4 节权限分支。
3. 404 或 `RESOURCE_NOT_FOUND`：检查帧内 `<base href>` 是否为受管作用域 URI、引用是否为包内相对路径且大小写一致。
4. `RESOURCE_PATH_INVALID`：引用含 `..`、反斜杠、绝对路径或编码绕过；修正引用，禁止放宽路径校验（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 第 9.2 节）。
5. `RESOURCE_UNSUPPORTED_SCHEME`：使用了协议允许清单外的 scheme；按 [06-资源协议规范](../05-接口与契约/06-资源协议规范.md) 改为允许形式。
6. 包外 `file://` 引用显示失败：引用形态允许，但必须先经资源管理器转为受管作用域 URI 后注入；正式保存链路必须把资源复制进包并改写为包内相对路径（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 第 5.2 节）。
7. 资源字节不得塞进事件或 IPC；大文件用句柄的 `readRange()` / `stream()`（[01-Bridge-API规范](../05-接口与契约/01-Bridge-API规范.md) 第 3.5 节）。

### 6.5 React 渲染层检查点

- 会话与组件一对一：挂载即 `mount`、卸载必须 `unmount`/`dispose`；在 React DevTools 中确认组件卸载后帧已销毁。
- `update(view, revision)` 只在 `ready` 生效且 `revision` 严格递增；回退或重复的 revision 被忽略并记录诊断（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 第 2.4 节）。
- 编辑态就近渲染必须复用同一解析结果与同一套插件接口，出现二次解析即为缺陷（R8）。
