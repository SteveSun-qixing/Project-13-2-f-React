# 服务端部署与运维

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片生态服务端产品（社区平台服务器、个人服务器）的部署与运维权威规范：环境与拓扑、域名/HTTPS/证书/CSP/CORS、对象存储、容器化与进程管理、配置与密钥管理、备份恢复、日志监控、升级回滚、服务器连接与口令管理、故障清单与自检清单；不覆盖服务端产品的 API 契约、数据模型与业务模块实现。

---

## 九、升级与回滚

### 9.1 发布物与版本

1. 服务端产品的一次发布 = 一组带版本标签的发布镜像（服务镜像 + 前端镜像）+ 配置变更清单 + 数据库迁移。
2. 生产镜像必须带版本标签并保留上一版本镜像；Compose 中通过镜像标签或构建结果引用明确版本，禁止在生产现场对源码目录直接 `build` 出不可追溯镜像。
3. 发布前必须通过质量门禁与产物校验（[05-CICD与质量门禁](./05-CICD与质量门禁.md) 第四、五节），并在发布记录中登记版本、镜像摘要、迁移范围与验证结果。

### 9.2 升级流程

```text
[1] 读取发布说明：确认版本、迁移、环境变量变化
        ▼
[2] 备份：数据库全量 + 对象存储源文件（升级前快照）
        ▼
[3] 准备：拉取/导入发布镜像；更新 deploy/.env 与配置
        ▼
[4] 收缩：低峰执行；如需可先停 worker 阻止新渲染任务
        ▼
[5] 替换：docker compose up -d --no-deps --build server worker web admin
        ▼
[6] 迁移：由容器启动自动执行；观察迁移日志
        ▼
[7] 验证：健康检查 → 登录 → 卡片上传/打开 → 缓存生成 → 日志无异常
        ▼
[8] 恢复 worker（如步骤 4 停过）→ 记录发布结果
```

1. 环境变量或 Compose 结构变化时使用完整 `docker compose up -d` 重建；只替换应用服务时使用 `--no-deps` 避免误重建数据库。
2. 迁移只前向、不可回退；发布说明必须明确是否包含 schema 变更。
3. 部署验证最低集合：`/api/v1/health`、前台首页、后台首页、登录、一次公开资源读取。

### 9.3 回滚流程

| 场景 | 回滚方式 |
|---|---|
| 仅应用问题（无 schema 变更） | 将服务与前端镜像切回上一版本并重建应用容器；数据库不动 |
| 含 schema 变更的失败 | 回滚应用镜像 + 用升级前备份恢复数据库；时间点以备份为准 |
| 配置问题 | 恢复上一版本 `deploy/.env` 与 Nginx 配置并重建对应容器 |
| 证书问题 | 恢复上一份可用证书并 reload |

1. 回滚必须在发布窗口内完成演练确认；回滚后同样执行 §9.2 步骤 [7] 的验证集合。
2. 回滚完成前不得清理上一版本镜像与升级前备份。
3. 回滚原因、时间与影响写入发布记录；同一问题修复后必须重新发起完整发布，禁止在原发布上追加修改。

### 9.4 证书续期

1. 证书续期由自动续期或人工续期完成；续期产物替换 `deploy/certs/` 下同名文件。
2. 替换后执行 `nginx -t` 校验并 reload，验证浏览器与命令行均能完成 TLS 握手。
3. 续期失败且剩余有效期不足 7 天时按严重告警处理，优先恢复可用证书。

### 9.5 禁止事项

1. 禁止在容器内直接修改代码或配置；禁止 `docker cp` 覆盖运行中文件。
2. 禁止手工执行数据库 schema 变更；禁止跳过启动迁移。
3. 禁止在生产部署目录直接构建未标记镜像作为发布。
4. 禁止在未备份的情况下执行含迁移的升级。
5. 禁止将 `stable` 之外的客户端渠道机制混入服务端发布；服务端发布以版本标签与发布记录为准。
