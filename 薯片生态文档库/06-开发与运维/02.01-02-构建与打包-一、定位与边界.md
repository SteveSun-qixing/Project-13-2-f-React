## 一、定位与边界

### 1.1 定位

本文是薯片生态构建与打包的唯一权威：构建顺序、工具链版本基线、各产物的形态与命名、签名与信任根、构建缓存策略与产物校验清单，一律以本文为准。

构建链路总览：

```
依赖还原 → Rust 核心（workspace）→ Neon 绑定 → TS 包 → 窗口渲染层与平台帧运行时
        → Electron 安装包（含签名）→ 插件入口产物 → .cpk 打包（含签名）→ 产物校验
```

### 1.3 基本约束

1. **可复现**：`pnpm-lock.yaml` 与 `Cargo.lock` 必须冻结安装；工具链版本精确锁定；`.cpk` 必须字节级可复现（同一输入两次打包得到相同 SHA-256）；安装包因平台签名不做字节级复现要求，以摘要与签名追溯。
2. **产物不入库**：构建产物目录遵守[01-代码组织规范](../02-开发规范/01-代码组织规范.md)第七章；插件包根 `render.js` 是构建产物，仓库 `.gitignore` 必须包含 `plugins/*/render.js`。
3. **门禁前置**：发布构建前必须通过 lint、typecheck、测试门禁；门禁项与数值见[05-CICD与质量门禁](./05-CICD与质量门禁.md)，本文不重复定义。
4. **不做兼容构建**：不为旧平台、旧文档格式、旧插件清单产出兼容产物（[ADR-010](../01-架构设计/ADR/ADR-010-大爆炸重构策略.md)）。
5. **禁止绕过**：不得跳过 lint/typecheck、不得手改 `dist/`、`target/`、`release/` 内产物、不得跳过签名与摘要；缓存只允许加速，不得改变产物字节。
