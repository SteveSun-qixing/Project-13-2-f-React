> 状态：正式版
> 适用范围：薯片生态全部代码仓库的持续集成阶段划分、质量门禁判定、产物校验、发布自动化与门禁失败/豁免规则；门禁数值一律引用《架构原则》与《超大型工程管理体系》，本文只做引用、执行与判定。

## 四、产物校验

### 4.1 产物清单与校验点

| 产物 | 形态 | 校验点 |
|---|---|---|
| Rust crates | `target/`（不入库） | release 构建通过；契约测试通过 |
| Neon 绑定 | `chips-native.node`（构建生成，不入库） | 目标平台构建成功；导出面与 `CORE_ABI_VERSION` 一致 |
| TS 包 | `dist/`（不入库） | 构建通过；`exports` 与类型声明完整；无测试文件与夹具 |
| Electron 安装包 | `release/`（不入库） | 三端构建通过；发布流水线校验签名结果；版本一致 |
| 插件包 | `*.cpk` | 见 4.2 |
| 文档与夹具 | `.card` / `.box` | 见 4.3 |

构建产物一律不入库，不得作为源码事实（《01-代码组织规范》第七章）。

### 4.2 `.cpk` 校验

- 校验与安装完全同源：归档 → 结构 → 清单 → 签名 → 摘要（《03-插件包格式》第五节）；命令为 `pnpm exec chips plugin validate <包>`，不得自行解压抽检替代。
- `Invalid` 一律拒绝；警告级诊断必须随流水线报告展示，不得静默。
- 安装摘要 `sha256:<hex>` 写入产物记录；同一提交重新打包必须得到相同摘要（《03-插件包格式》2.1 节）。
- `.cpk` 不进入版本库（《01-代码组织规范》7.1 节）；流水线工件只作为发布输入。

### 4.3 文件格式校验

- `.card` / `.box` 示例与正常夹具必须通过解析器 `validate`：`Invalid` 拒绝发布；`ValidWithWarnings` 允许发布但必须展示警告（《06-文档解析器设计》6.5 节）。
- 夹具同时提供目录态与归档态，双形态一致性测试作为发布门禁（《06-文档解析器设计》第五节）。
- 用于错误路径的损坏夹具与正常夹具隔离存放，不得混入通过集；严格模式下的期望诊断必须显式断言。
- `chip_standards_version` 必须为合法语义化版本且与平台支持版本兼容（《04-版本与迁移规范》第五节）。
- 迁移工具输出必须逐个通过 `validate` 与资源完整性核对后才计为成功（《04-版本与迁移规范》6.5 节）。

### 4.4 版本一致性校验

- 平台包版本统一（`@chips/bridge`、`@chips/host`、`@chips/sdk`、`@chips/ui` 与全部 Rust crate）；`@chips/antd` 按上游规则独立版本（《04-版本与迁移规范》2.1 节、《01-代码组织规范》3.4 节）。
- 插件 `package.json` 与 `manifest.yaml` 版本一致，由打包与安装校验强制（《03-插件包格式》7.1 节）。
- 发布 tag 与平台版本一致；预发布标识与渠道匹配（第五节）。
- `chip_standards_version` 与格式文档当前版本一致；禁止同一版本下发布两种格式语义（《04-版本与迁移规范》第七节）。
- 任一不一致在产物校验阶段失败，禁止带版本漂移发布。

### 4.5 确定性

- 同一提交、同一输入重新构建与打包，产物摘要、安装摘要与校验报告必须一致（《03-插件包格式》2.1 节、《06-文档解析器设计》6.5 节）。
- 校验报告诊断排序确定；判定不得依赖文件系统遍历顺序或时间戳。
