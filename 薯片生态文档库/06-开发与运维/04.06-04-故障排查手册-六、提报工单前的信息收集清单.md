## 六、提报工单前的信息收集清单

### 6.1 必附信息

| 项 | 说明 |
|---|---|
| 环境 | 平台版本、操作系统与版本、CPU 架构、安装渠道 |
| 复现步骤 | 最小、确定、可重复的操作序列；含打开的文件类型与模式（查看/编辑） |
| 期望与实际 | 期望行为、实际现象（截图或文字描述） |
| 错误对象 | 完整 `ChipsError`：`code`、`message`、`details`（已脱敏）、`retryable` |
| 关联字段 | `traceId`、`requestId`、`sessionId`、`pluginId`、`pluginVersion`、时间窗口（UTC） |
| 状态投影 | 插件 `state` 与 `lastError`；渲染会话 `state` 与 `error`；箱子条目诊断列表 |
| 日志摘录 | 平台主日志、审计日志、插件日志的相关片段（含时间与 `traceId`） |
| 包校验 | `pnpm exec chips plugin validate <路径>` 完整输出（安装/更新类问题必附） |
| 样例文件 | 触发问题的最小文档或插件包（脱敏后可附） |
| 最近变更 | 平台版本、插件版本、配置或授权变更；是否首次出现 |
| 已尝试处置 | 已执行的步骤与结果（含是否已重试、是否已重装） |

### 6.2 日志摘录方法

```bash
# 平台主日志中定位时间窗口（macOS 示例）
rg -n 'BRIDGE_|KERNEL_|RENDER_|RESOURCE_|DOCUMENT_|CPK_' "$HOME/Library/Logs/Chips/main.log" | tail -50

# 审计日志按 traceId 提取完整链路
jq -c 'select(.traceId == "<填写 traceId>")' \
  "$HOME/Library/Application Support/Chips/logs/audit/audit-2026-09-19.jsonl"
```

- 摘录必须包含时间戳、`level`、错误码与 `traceId`；不要只贴 `message` 文案。
- 复现前后各保留一段日志，便于观察状态迁移与先后顺序。

### 6.3 禁止包含

- 凭证材料：口令、令牌、私钥、恢复码（凭证值不得进入任何日志与工单）。
- 用户隐私与用户文件内容：完整文档正文、剪贴板原文、主目录之外的隐私信息。
- 未脱敏的真实绝对路径与内部标识；工单中使用目录变量或占位符表达路径。
- 堆栈之外的平台内部实现细节（如内存地址、内部结构体）。
