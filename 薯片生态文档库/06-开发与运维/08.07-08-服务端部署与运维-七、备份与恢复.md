# 服务端部署与运维

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片生态服务端产品（社区平台服务器、个人服务器）的部署与运维权威规范：环境与拓扑、域名/HTTPS/证书/CSP/CORS、对象存储、容器化与进程管理、配置与密钥管理、备份恢复、日志监控、升级回滚、服务器连接与口令管理、故障清单与自检清单；不覆盖服务端产品的 API 契约、数据模型与业务模块实现。

## 七、备份与恢复

### 7.1 数据分级

| 数据 | 位置 | 是否必须备份 | 说明 |
|---|---|---|---|
| 业务结构化数据 | PostgreSQL | 是 | 账号、卡片与箱子元数据、上传会话、渲染任务与缓存记录 |
| `.card` / `.box` 源文件 | 私有对象桶 | 是 | 用户内容，永久保留，不可重建 |
| 卡片内嵌资源、头像、封面 | 公开对象桶 | 是 | 用户内容，不可重建 |
| 查看/封面渲染缓存 | 公开/私有缓存桶 | 否 | 可由源文件重建；清理与重建是正常运维动作 |
| Redis 数据 | Redis 卷 | 否 | 登录失败计数、令牌吊销、渲染队列；丢失后重建，滞留任务由 Worker 重新入队 |
| 配置与证书 | `deploy/.env`、`deploy/certs/` | 是（加密） | 恢复环境所必需；按机密管理，不进普通备份介质 |
| 源码与 Compose/Nginx 配置 | 部署目录 | 是 | 以 Git 仓库为准；部署目录本地保留一份当前版本 |

### 7.2 备份策略

1. 数据库：每日一次逻辑备份（`pg_dump` 自定义格式），升级前必须额外执行一次；保留最近 30 天，每周备份异地保留一份。
2. 对象存储：私有桶与用户内容桶每日增量同步到备份存储（独立凭据、独立存储空间）；渲染缓存桶不备份。
3. 证书与环境文件：变更后立即备份到加密介质；备份介质中的凭据按机密管理，不与源码备份混放。
4. 备份产物必须校验完整性（数据库备份可列表、对象同步计数一致）；校验失败视为备份失败并当日重跑。
5. 备份命令示例：

```bash
docker compose exec -T postgres pg_dump -U <db_user> -Fc <db_name> > backup/<date>-<db_name>.dump
pg_restore --list backup/<date>-<db_name>.dump > /dev/null
```

6. 对象存储同步使用服务商或通用 S3 工具（如 `rclone` / `aws s3 sync`），凭据只通过环境变量注入，不写入命令参数。

### 7.3 恢复流程

```text
[1] 停止应用入口：docker compose stop nginx worker server
        ▼
[2] 恢复数据库：创建空库 → pg_restore 恢复备份
        ▼
[3] 恢复对象存储：源文件桶、用户内容桶回传
        ▼
[4] 恢复配置与证书：deploy/.env、deploy/certs/
        ▼
[5] 启动：docker compose up -d
        ▼
[6] 验证：健康检查、登录、卡片打开、缓存重建、日志无异常
```

1. 数据库恢复前必须确认目标库为空或已完成转储，禁止覆盖唯一可用副本。
2. 恢复后服务端产品会自动执行迁移到当前版本；不得手工修改表结构。
3. 渲染缓存无需恢复：Worker 上空闲后按需重建；恢复期间缓存缺失表现为首次打开稍慢，不是故障。
4. 恢复完成后必须复核公开资源入口的域名与证书仍然有效（`S3_PUBLIC_URL`、资源入口证书）。

### 7.4 恢复演练

1. 每季度至少执行一次恢复演练，范围至少包括：数据库恢复到独立实例、一个源文件桶的可读性验证。
2. 演练在隔离环境进行，禁止在生产环境原地演练；演练记录写入运维记录。
3. 演练发现的问题必须在下一轮演练前关闭，并在发布记录中留痕。
