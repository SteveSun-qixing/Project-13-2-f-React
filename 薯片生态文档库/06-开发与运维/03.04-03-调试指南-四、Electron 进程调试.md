## 四、Electron 进程调试

### 4.1 主进程（Node/TS）调试

1. 以 Node 调试端口启动开发环境：

```bash
pnpm --filter @chips/host dev -- --inspect=9229
```

2. Chrome/Chromium 打开 `chrome://inspect`，在 Configure 中添加 `localhost:9229`，点击 inspect 附加；断点下在 `packages/host-electron/src/main/`。
3. VS Code 附加配置：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "附加到 Electron 主进程",
      "type": "node",
      "request": "attach",
      "address": "127.0.0.1",
      "port": 9229,
      "skipFiles": ["<node_internals>/**"]
    }
  ]
}
```

4. IPC 断点：在 `ipcMain.handle('bridge:request', …)` 处下断点即可检查 `IBridgeRequest` 封套（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 第 7.2 节）；`bridge:resource`、`event:control` 同理。会话解析失败（`BRIDGE_SESSION_UNKNOWN`）常在此处首次可见。
5. 主进程的 stdout 与日志进入 `pnpm dev` 终端及平台主日志；断点停在同步阻塞代码上会冻结全部窗口，排查结束立即继续。

### 4.2 渲染进程（React）调试

1. 开发构建按 ADR-002 的约定自动打开 detached DevTools；手动打开用 `Cmd+Option+I`（macOS）/ `Ctrl+Shift+I`（Windows）。
2. 多窗口时在 DevTools 右上角切换目标 `webContents`，确认所调窗口与复现窗口一致。
3. React 组件树用 React DevTools 检查；会话挂载点的生命周期由 `useRenderSession` 管理，卸载必须触发 `unmount`/`dispose`（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 第 3.2 节）。
4. 断点下在 `packages/host-electron/src/renderer/`；`window.chips` 只暴露 `request`、`subscribe`、`resource` 三个方法（R2），其余成员缺失属预期。
5. 渲染帧内的脚本运行在独立上下文：在 DevTools Console 左上角上下文选择器切换到对应 frame 后再执行检查。

### 4.3 preload 调试

1. preload 在 `contextIsolation` 隔离世界中运行，主页面 Console 看不到其变量；在 Sources 面板按文件路径定位 preload 脚本，用断点暂停。
2. 校验暴露面：页面 Console 执行 `Object.keys(window.chips)` 应为 `['request', 'subscribe', 'resource']`；出现 `ipcRenderer`、`require`、`process` 即安全缺陷（D-1）。
3. preload 的 `console` 输出显示在渲染进程 DevTools；订阅计数异常（事件收不到或重复）在此处断点检查（第 7.3 节）。

### 4.4 E2E 场景调试

1. 用 Playwright 单场景调试失败用例：

```bash
PWDEBUG=1 pnpm exec playwright test tests/e2e/<场景>.spec.ts
```

2. 在 Playwright Inspector 中单步执行；失败快照与 trace 的产出位置见 [05-测试规范](../02-开发规范/05-测试规范.md) 第六章。
3. E2E 无法复现时回退到 4.1/4.2 的进程内调试；禁止在生产包上开调试口。
