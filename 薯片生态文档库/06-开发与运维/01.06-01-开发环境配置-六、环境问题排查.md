## 六、环境问题排查

### 6.1 排查顺序

```text
工具版本（第二章）→ 依赖安装方式（pnpm，第五章）→ Rust 绑定与架构 → 平台编译前置（Xcode / MSVC）→ 网络与镜像
```

### 6.2 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `cargo: command not found` | rustup 安装后当前 shell 未加载环境变量 | 执行 `source "$HOME/.cargo/env"` 或重开终端；确认 `~/.cargo/bin` 在 `PATH` 中 |
| `error: no such command: fmt`（或 `clippy`） | rustfmt / clippy 组件未安装 | `rustup component add rustfmt clippy` |
| `package ... requires rustc 1.75 or newer` | 本地工具链低于 workspace `rust-version` | `rustup update stable`，确认 `rustc --version` >= 1.75 |
| macOS 编译 Neon 绑定报 `xcrun: error: invalid active developer path` | 未安装 Xcode Command Line Tools | 执行 `xcode-select --install` 后重新构建 |
| Windows 编译报 `LINK : fatal error LNK1181` 或 `link.exe not found` | 缺少 MSVC 与 Windows SDK | 安装 VS 2022 Build Tools 的“使用 C++ 的桌面开发”工作负载后重开终端 |
| `Cannot find module '.../chips-native.node'` | Rust 绑定未构建或未由构建流程复制 | 重新执行 `cargo build --workspace` 后通过根脚本 `pnpm dev` / `pnpm build` 启动；不要手工拷贝产物 |
| Apple Silicon 报 `mach-o file, but is an incompatible architecture` | Node 与 Rust 目标架构不一致（x86_64 / arm64 混用） | 统一使用 arm64 的 Node 与 Rust 工具链；移除本地 `node_modules/` 后重新 `pnpm install` 并重建 |
| `ERR_PNPM_BAD_PM_VERSION`，或提示与 `packageManager` 不符 | pnpm 主版本不是 9 | `corepack prepare pnpm@9 --activate`；不要用 npm / yarn 安装依赖 |
| 误用 npm / yarn 安装后依赖树异常 | 包管理器混用破坏了工作区链接 | 移除本地 `node_modules/`（生成目录），改用 `pnpm install` 重装 |
| Windows 上 `pnpm install` 报 `EPERM: operation not permitted, symlink` | 创建链接权限不足 | 开启 Windows 开发者模式后重试 |
| Node.js 版本过低导致 pnpm 拒绝执行 | 环境不满足 >= 18 LTS | 切换到 18 LTS 或更高的 LTS 版本 |
| 在子目录执行 `pnpm dev` 提示找不到 Electron 或绑定 | 未从仓库根安装依赖、未完成初始化 | 回到仓库根按 §5.2 完成初始化流程后重试 |
| VS Code 中 ESLint / 格式化不生效 | 未安装必需插件、打开目录不是仓库根，或设置被个人配置覆盖 | 安装 §4.1 必需插件；以仓库根为工作区打开；核对 §4.2 设置 |

### 6.3 网络受限处理

依赖或 Electron 二进制下载缓慢、失败时，为当前机器配置镜像后重装（示例地址，可按实际可用镜像替换）：

```bash
# macOS / Linux
export ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
pnpm config set registry https://registry.npmmirror.com
pnpm install
```

```powershell
# Windows PowerShell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
pnpm config set registry https://registry.npmmirror.com
pnpm install
```

镜像配置只作用于本机用户配置与环境变量，不得写入仓库文件；若本机已配置代理，需保证 pnpm、Cargo、Git 使用同一代理。
