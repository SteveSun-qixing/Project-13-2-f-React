## 四、典型故障场景

### 4.1 插件装不上

**现象**：安装中断并返回 `CPK_*` 或 `PERMISSION_*` 错误；插件列表不出现新条目；注册表不产生记录。

**定位**：

```bash
# 与安装完全同源的校验（不安装、不落盘）
pnpm exec chips plugin validate dist/hello-basecard-1.0.0.cpk

# 归档内容与方法
unzip -v dist/hello-basecard-1.0.0.cpk
```

**常见原因与处置**：

| 原因 | 判定 | 处置 |
|---|---|---|
| 归档非 Store / 含嵌套归档 / CRC 失败 | `CPK_ARCHIVE_INVALID` | 用 `zip -r -0 -X` 重打包 |
| 包根有白名单外条目、隐藏文件、`service` 带 UI | `CPK_LAYOUT_INVALID` | 清理包根与角色布局 |
| 缺少或多份 `manifest.yaml` | `CPK_MANIFEST_MISSING` | 清单放到归档根且唯一 |
| manifest schema / 路径引用 / 版本不一致 | `CPK_MANIFEST_INVALID` | 按 `details.pointer` 修正 |
| 缺少入口或入口非文本 ESM | `CPK_ENTRY_MISSING` | 补齐 `dist/index.js` 与角色所需 `render.js` |
| 携带原生载荷 | `CPK_NATIVE_PAYLOAD` | 删除原生文件，改用 Bridge 能力 |
| 路径穿越、符号链接 | `CPK_PATH_UNSAFE` | 用标准工具重新打包 |
| 体积/成员数/单文件超限 | `CPK_LIMIT_EXCEEDED` | 按限额裁剪 |
| 权限 ID 非法/未注册/角色不适用 | `PERMISSION_INVALID` / `PERMISSION_UNKNOWN` / `PERMISSION_ROLE_NOT_ALLOWED` | 修正 manifest 权限声明 |
| 用户拒绝授权 | 无错误码，安装仍可完成 | 首次启用时重新确认；被拒权限保持未记录 |

**验证**：`chips plugin validate` 输出 `结果: valid`；安装后状态为 `installed`，并在首次启用时完成授权确认。

### 4.2 插件加载失败

**现象**：插件状态 `failed` 或停留 `pending`；`plugin:failed` 事件携带 `error`；依赖它的插件保持 `pending`。

**定位**：

1. 插件注册表：`state`、`lastError`、`dependencies`、`permissions` / `grantedPermissions`（经插件管理界面读取）。
2. 生命周期事件：`plugin:failed` → 错误对象；`plugin:loaded` 缺失说明未进入运行态。
3. 平台日志与插件日志：按 `pluginId` 过滤，核对错误码与阶段。

**常见原因与处置**：

| 状态/错误码 | 原因 | 处置 |
|---|---|---|
| `pending` + `KERNEL_DEPENDENCY_MISSING` | 依赖未安装 | 安装依赖后自动继续 |
| `pending` + `KERNEL_DEPENDENCY_VERSION` | 依赖版本不在范围 | 调整依赖版本或更新依赖插件 |
| `failed` + `KERNEL_DEPENDENCY_CYCLE` / `KERNEL_DEPENDENCY_DUPLICATE` | 依赖成环/重复声明 | 打破环或去重 |
| `failed` + `KERNEL_APPLY_FAILED` | 激活入口抛错 | 修复 `start` / 注册 / `launch` 抛错点 |
| `failed` + `KERNEL_INJECT_FAILED` | 注入回调出错 | 修复回调，勿缓存跨代际引用 |
| `failed` + `KERNEL_PLUGIN_PANICKED` | 插件任务 panic | 修复 panic；生产代码禁用 `unwrap()` / `panic!` |
| `failed` + `PLUGIN_PERMISSION_DENIED` / `PERMISSION_NOT_DECLARED` | 能力注册权限未声明 | 补齐 manifest 权限后重新启用 |
| 上次中断残留 | 启动时已回滚为 `installed` | 按当前启用偏好重新启用 |

**验证**：状态回到 `active`；`plugin:loaded` / `plugin:enabled` 事件出现；渲染请求与能力调用恢复。停用必定完成（`stop` 失败不阻断撤销），失败只记录 `KERNEL_DISPOSE_FAILED`。

### 4.3 渲染空白

**现象**：卡片/箱子区域无内容、只有骨架或占位；无可见错误提示。

**定位顺序**：

```text
① 会话状态（opening / ready / error）与 error 事件
      │  error → 按 RENDER_* 码处置
      ▼
② 是否出现占位（含错误码与重试入口）→ 是：占位文案即错误码
      │  否（真空白）→ 继续
      ▼
③ 帧握手：5s 内未收到 frame:ready → RENDER_FRAME_TIMEOUT
      │  正常 → 继续
      ▼
④ 插件装载与渲染：RENDER_PLUGIN_MISSING / RENDER_PLUGIN_FAILED
      │  正常 → 继续
      ▼
⑤ 高度与容器：高度为 0、未 mount、超过 maxHeight
```

**常见原因与处置**：

| 原因 | 判定 | 处置 |
|---|---|---|
| 未安装对应卡片/布局插件 | `RENDER_PLUGIN_MISSING` | 安装插件并确认 `active` |
| 插件渲染抛错 | `RENDER_PLUGIN_FAILED` | 读插件日志修复；重试重走完整链路 |
| 帧运行时加载失败/被 CSP 拦截 | `RENDER_FRAME_TIMEOUT` | 确认 `chips-resource://platform/frame.html` 可加载；CSP 放行 `chips-resource:`；帧内禁止内联脚本 |
| 文档损坏 | `RENDER_DOCUMENT_INVALID` | 按 [3.4](#34-文档解析document_) 修复 |
| 插件 / 能力 / schema 与内容要求不匹配 | `RENDER_SCHEMA_UNSUPPORTED` | 核对内容结构与插件 `configSchema` / 能力声明；升级插件或调整内容；文档格式版本问题按 [3.4](#34-文档解析document_) 处理 |
| 插件未挂载到容器 / 高度为 0 | 无错误码，界面空白 | 确认 `mount(container)` 已调用、容器可见；检查高度上报与 `limits` clamp |
| 编辑态就近渲染未回流 | 查看态正常、编辑态空白 | 确认 `renderEditor` 已调用且 `update()` 回流新 revision |

**验证**：会话 `ready`；`frame:ready` 与 `frame:height` 均出现；占位消失；切换文档与滚动无高度震荡。

### 4.4 资源 404 / 加载失败

**现象**：图片裂图、音视频错误态、`<img>` 空载；句柄读取失败；协议路径返回 400/403/404/413/502。

**定位**：

1. 取错误码与 `details`（URI、path、reason、host）。
2. 审计日志中查该次访问记录（含 HTTP 状态、作用域类型、host、字节数、缓存命中）。
3. 核对 URI 形态：作用域是否为平台分配的 `card-*` / `box-*` / `plugin-*` / `platform` / `external`。

**常见原因与处置**：

| 原因 | 判定 | 处置 |
|---|---|---|
| 作用域未注册 | `RESOURCE_NOT_FOUND` | 确认文档已打开、插件已加载（作用域随会话注册） |
| 包内路径错误/大小写不符 | `RESOURCE_NOT_FOUND` | 卡片资源在包根（允许子目录）、箱子自有资源在 `assets/`；修正引用 |
| 引用未随包携带 | `RESOURCE_NOT_FOUND` | 资源复制进包并改写为包内相对路径 |
| 路径穿越/绝对路径/反斜杠 | `RESOURCE_PATH_INVALID` | 改用包内相对路径 |
| 跨作用域未授权 | `RESOURCE_PERMISSION_DENIED` | 见 [4.5](#45-权限被拒) |
| 文档变更后句柄失效 | `RESOURCE_HANDLE_INVALIDATED` | 重新 `resource(uri)`，不复用旧句柄 |
| 大资源用 `read()` | `RESOURCE_TOO_LARGE` | 改用 `readRange()` / `stream()` |
| 外部资源失败 | `RESOURCE_NETWORK_FAILED` | 按 `reason` 定位 DNS/连接/TLS/超时/重定向/SSRF |
| 帧内使用 `file://` 或裸绝对路径 | 加载被拒 | 统一改用 `chips-resource://`；`<base>` 必须为受管 URI |

**验证**：资源可加载且尺寸正确；文档变更后失效通知与重新获取路径均正常；无句柄泄漏（句柄用后 `release()`）。

### 4.5 权限被拒

**现象**：调用返回 `BRIDGE_PERMISSION_DENIED` / `RESOURCE_PERMISSION_DENIED` / `PLUGIN_PERMISSION_DENIED` / `RENDER_RESOURCE_DENIED`；授权弹窗反复出现；界面提示"操作被拒绝：缺少某权限"。

**定位**：读取拒绝错误的 `details`（结构见 [08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 9.2）：

```typescript
interface IPermissionDeniedDetails {
  capabilityId?: string;
  permission: string;
  required: string[];
  missing: string[];
  granted: string[];
  reason: PermissionDenyReason;   // not_granted | revoked | out_of_scope | user_rejected | policy
  target?: string;
}
```

| `reason` | 含义 | 处置 |
|---|---|---|
| `not_granted` | 未授予 | 引导用户到「设置 → 插件 → 权限」授权；插件不得静默降级后继续调用 |
| `revoked` | 已撤销 | 重新授予后重建会话快照，无需重启插件 |
| `out_of_scope` | 超出限定值 | 收窄调用目标，或按目标补充声明/授权（路径变量、域名、端口） |
| `user_rejected` | 用户拒绝本次调用 | 当前会话不再弹窗；由用户在设置面板恢复 |
| `policy` | 策略禁止 | 属平台策略，按审计记录复核，不尝试绕过 |

**逐项核对清单**：

1. manifest `permissions` 是否声明该基础权限（未声明 = 不可用，声明也不自动授予）。
2. 限定值是否覆盖本次目标：路径按目录变量 + 子路径；域名 `*` 只匹配一个标签（`*.example.com` 不匹配 `example.com`）；端口需显式声明；重定向与子请求逐跳判定。
3. 角色适用性：`window:control`、`dialogs:use`、`shell:external` 仅 `app` 可申请。
4. 免权限范围是否被误判为需授权（自身数据目录、自身配置命名空间、自身资源作用域只读、`platform` 公开只读、已授权句柄会话内读取）。
5. 审计记录 `action: deny` 的 `permission` / `target` / `reason` 是否与调用点一致。

**验证**：授予后同一调用放行并写入审计（`action: allow`）；撤销后立即拒绝；进行中的调用不中断。

### 4.6 箱子不显示条目

**现象**：箱子能打开、封面正常，但布局中无条目或只有部分条目；滚动时条目不出现。

**定位**：

1. 解析诊断：`ENTRY_SOURCE_INVALID` / `ENTRY_TARGET_MISSING` / `ENTRY_FAILED`（单条目失败保留位置，不静默丢弃）。
2. `structure.yaml` 条目字段：`entry_id`、`url`、`enabled` 必须存在；`entry_id` 为 10 位 Base62 且箱内唯一。
3. 布局插件与帧：`RENDER_PLUGIN_MISSING` / `RENDER_PLUGIN_FAILED`；布局帧是否上报可见范围并请求 `frame:entry-request`。

**常见原因与处置**：

| 原因 | 判定 | 处置 |
|---|---|---|
| 条目 `enabled: false` | 解析无诊断 | 该条目不参与布局展示；需要展示时置 `true` |
| `url` 形态非法（裸绝对路径、`blob:`、`data:`、非法 scheme） | `ENTRY_SOURCE_INVALID` | 改为包内相对路径（以 `.card` 结尾）或正式 URL |
| 内嵌引用目标缺失 | `ENTRY_TARGET_MISSING` | 补齐包内目标卡片 |
| 单条目解析失败 | `ENTRY_FAILED` | 按条目诊断修复，其他条目不受影响 |
| `entry_id` 非法/重复 | schema 诊断 | 修正为 10 位 Base62 且箱内唯一 |
| `structure.yaml` 非法 | 条目层级不可用（metadata 仍可用） | 修复结构文件后重新打开 |
| 条目数量超限 | `DOCUMENT_LIMIT_EXCEEDED` | 裁剪条目（默认上限 10000） |
| 布局插件缺失/渲染失败 | `RENDER_PLUGIN_MISSING` / `RENDER_PLUGIN_FAILED` | 安装或修复布局插件 |
| 虚拟化未请求 ticket | 无条目帧产生 | 布局插件须按可见范围 ± overscan 上报并请求条目 ticket；条目帧由布局帧按协议创建 |
| 滚动容器高度为 0 | 无条目帧产生 | 修正布局容器尺寸与高度上报 |

**说明**：条目引用箱子（嵌套）不是错误。浏览态一律显示被引用箱子的正式封面（`.box/cover.html`），不展开其布局、不递归展开（一次进入即可）；条目激活由平台条目激活接口打开目标箱子（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 7.5、[02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) 9.3）。条目引用目标非法由解析链路诊断（`ENTRY_SOURCE_INVALID` / `ENTRY_TARGET_MISSING` / `ENTRY_FAILED`），不产生渲染降级。

**验证**：可见范围内条目帧全部创建；滚动增量加载正常；条目增删后下一 rAF 前完成失效或重建；条目级失败仅影响该条目。
