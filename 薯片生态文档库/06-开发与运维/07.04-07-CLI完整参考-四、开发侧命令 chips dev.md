## 四、开发侧命令 `chips dev`

### 4.1 定位与工作区

- `chips dev` 始终操作**开发工作区**：`--workspace` → `CHIPS_WORKSPACE` → `${userData}/dev/workspace`；不读取、不修改用户工作区（§2.2）。
- 开发工作区中的插件来源优先级为 `development` > `user` > `builtin`；`development` 来源（当前工程、显式插件目录）只在开发构建与开发工作区可用，不得在用户工作区启用（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §4.1、[13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §7.2）。
- 开发工作区数据是夹具与临时数据，不承诺保留、不参与同步、不作为交付物；发布验证必须在正式渠道与用户工作区执行（[13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §7.3、§7.4）。

### 4.2 `chips dev run`

```bash
chips dev run [--dir <插件工程目录>] [--workspace <路径>]
```

面向 `app` 角色插件的窗口联调：

1. 解析开发工作区；`--dir` 缺省为当前目录，目录根必须存在 `manifest.yaml` 且 `type: app`。
2. 执行工程 `build` 脚本（等价 `pnpm --filter <包名> run build`），产出 `dist/index.js` 与 `render.js`。
3. 启动开发宿主：Electron 壳 + 渲染层热更新 + Rust 增量编译（[01-代码组织规范](../02-开发规范/01-代码组织规范.md) §8.1）。
4. 以 `development` 来源装载构建产物，按 manifest `ui.surface` 创建主窗口并调用 `launch`。
5. 退出：主窗口关闭（`runtime.background: false`）或 `Ctrl+C`；退出后开发宿主结束，不常驻。

补充规则：

- 修改源码后重新执行工程 `build` 脚本即可热重载：宿主以蓝绿替换加载新版本，插件保持 `active`，不重启平台、不影响其他窗口（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §6.2、§6.4）。
- `chips dev run` 与 Monorepo 根脚本 `pnpm dev`（`pnpm --filter @chips/host dev`）启动同一开发宿主：前者面向单个插件工程，后者面向平台开发与开发源目录发现（[01-代码组织规范](../02-开发规范/01-代码组织规范.md) §8.2）。
- 非 `app` 角色调用返回 `CLI_ARGUMENT_INVALID`（退出码 2，`details.role` 指明实际角色）；缺少清单返回 `CLI_PATH_NOT_FOUND`（退出码 5）；承载运行时不可用返回 `CLI_TARGET_UNAVAILABLE`（退出码 6）。
- 非 `app` 角色的联调不使用 `dev run`：`basecard` / `boxlayout` 经 `chips dev plugin install` 安装启用后，由查看器、编辑引擎等正式应用打开文档触发加载；`service` 使用 `chips dev service invoke`。

### 4.3 `chips dev service invoke`

```bash
chips dev service invoke --capability <能力ID> [--dir <插件工程目录>] [--input <JSON>] [--input-file <路径>]
```

面向 `service` 角色的能力联调入口：

| 参数 | 必需 | 说明 |
|---|---|---|
| `--capability` | 是 | 目标能力 ID（`<domain>:<action>[:<target>]`），必须已在 [04-能力契约规范](../05-接口与契约/04-能力契约规范.md) 登记 |
| `--dir` | 否 | 插件工程目录；缺省为当前目录；存在 `manifest.yaml` 且 `type: service` 时先执行工程 `build` 脚本 |
| `--input` | 否 | 内联 JSON 入参 |
| `--input-file` | 否 | JSON 文件入参；`--input` 与 `--input-file` 不得同时出现 |

执行链路：

```text
chips dev service invoke
   │ 解析开发工作区 → 构建当前工程（如有）→ 启动开发宿主
   │ 以 development 来源装载 service 插件
   ▼
能力注册表 ── 存在性 → 权限 → Schema → 路由 ──▶ 能力实现
   │                                                │
   └───────────────── 响应 ◀────────────────────────┘
   ▼
stdout: { ok, capability, owner, output }
```

- 入参由能力的 input schema 在 Bridge 层校验；不合法返回 `BRIDGE_INVALID_INPUT`（退出码 1），未登记能力返回 `BRIDGE_CAPABILITY_NOT_FOUND`（退出码 6）。
- 长耗时工作不得阻塞调用：超过注册项 `timeoutMs` 或 `ctx.deadline` 时 Bridge 返回 `BRIDGE_TIMEOUT`（退出码 9）；需要进度与阶段的任务化能力由服务插件自行设计（[01-Bridge-API规范](../05-接口与契约/01-Bridge-API规范.md) §3.2、[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) §二、§十）。
- 调用完成后开发宿主退出，不常驻；这是验证依赖 Electron 运行时（如渲染导出）的服务能力的正式入口。

示例：

```bash
chips dev service invoke \
  --capability translate:run \
  --input '{"text": "Hello chips", "target": "zh"}'
```

### 4.4 开发工作区管理

```bash
chips dev start | stop | status | config | logs | plugin | open | doctor
```

- 子命令、参数、输出与退出码与用户侧同名命令一致（§3.2–§3.6），差异只有三点：固定开发工作区；日志只写开发数据目录；`plugin list` 额外接受 `--source development` 且可见 `development` 来源插件。
- `chips dev plugin install | uninstall | list | info | enable | disable` 安装与操作的是开发渠道的插件副本，供查看器、编辑引擎等正式应用联调加载；重建同 ID 插件后必须重新 `install` 替换旧副本，宿主不会直接从源码目录热挂载（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §4.2）。
- `chips dev open <路径>` 在开发工作区上下文中触发文件关联链路，用于打开开发夹具文档。

示例：

```bash
chips dev plugin install /绝对路径/grid-layout-1.0.0.cpk
chips dev plugin enable chips.layout.grid
chips dev plugin list --role boxlayout
chips dev open ~/dev-fixtures/示例.box
```

### 4.5 TUI 与补全

- `chips dev` 裸命令与 `chips dev --interactive` 的 TUI 契约与用户侧一致（§3.1.2），命令索引来自开发工作区；非交互环境行为同样为裸命令返回 0、显式 `--interactive` 返回 1。
- `chips dev completion <bash|zsh|fish>` 输出注册到 `chips dev` 的补全脚本；脚本调用私有入口 `chips dev __complete`，行为与 §3.9 一致。

### 4.6 开发工作区插件命令调用

```bash
chips dev <命令路径> [参数] [选项]
chips dev --plugin <pluginId> <命令路径> [参数] [选项]
```

- 按 §3.10 的同一执行链路工作；命令索引只包含开发工作区可见的插件（`development` 来源优先）。
- 开发工作区已安装启用的插件命令也可以经 `chips dev <命令路径>` 直接调用；未匹配时返回 `CLI_COMMAND_NOT_FOUND`（退出码 3）。

### 4.7 工程工作流命令映射（正式命令名）

以下映射冻结开发命令的正式名称；旧名一律不再作为命令存在，不作为别名保留：

| 旧命令（历史） | 正式命令 | 说明 |
|---|---|---|
| `init` | — | 工程配置由 `chips plugin create` 生成的脚手架自带，不再需要独立初始化 |
| `create app` | `chips plugin create --role app` | 角色参数化，见 §3.5.1 |
| `create card` | `chips plugin create --role basecard` | 角色名称统一为 `basecard` |
| `create layout` | `chips plugin create --role boxlayout` | 角色名称统一为 `boxlayout` |
| `create module` | `chips plugin create --role service` | 模块插件不存在（R1），能力由服务插件提供 |
| `create theme` | — | 主题系统已废弃（R5、ADR-006） |
| `run` | `chips dev run` | 应用插件窗口联调 |
| `module invoke` | `chips dev service invoke` | 能力联调；参数由 `capability` + `input` 取代 |
| `build` | `pnpm build` / `pnpm --filter <包名> run build` | 构建脚本语义见 [01-代码组织规范](../02-开发规范/01-代码组织规范.md) §8.1 |
| `test` | `pnpm test` | 单元与集成测试；契约快照用 `pnpm test:contract` |
| `lint` | `pnpm lint` | ESLint + Prettier + rustfmt + clippy |
| `e2e` | `pnpm exec playwright test tests/e2e` | E2E 契约见 [05-测试规范](../02-开发规范/05-测试规范.md) §六 |
| `package` | `chips plugin pack` | 签名参数见 §3.5.2 |
| `validate` | `chips plugin validate` | 与安装同源 |
| `server` / `debug` | `chips dev run` | 开发宿主已包含渲染层热更新与调试开关 |
| `preview` | `chips dev run` | 开发宿主即预览入口，不再生成独立预览报告 |
| `component gallery` / `theme inspect` / `theme *` | — | 组件库与主题体系已废弃（R5、ADR-006） |
| `quality gate` | — | 质量门禁由 CI 与根脚本承担（[05-CICD与质量门禁](./05-CICD与质量门禁.md)） |
| `assimilate scan/report` | — | 外部项目同化工具已完成使命，不再提供 |
| `diagnostics` | `chips doctor` / `chips dev doctor` | 诊断入口统一 |
| `login` / `publish` | — | `.cpk` 分发由签名流水线与市场协议承担，市场客户端命令随市场协议阶段（[06-更新与分发规范](./06-更新与分发规范.md) §三、§五） |
| `version` | `chips --version` | 输出版本信息 |
| `help` | `chips help` / `chips dev help` | 帮助入口统一 |
