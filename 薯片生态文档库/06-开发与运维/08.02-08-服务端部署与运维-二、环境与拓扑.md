# 服务端部署与运维

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片生态服务端产品（社区平台服务器、个人服务器）的部署与运维权威规范：环境与拓扑、域名/HTTPS/证书/CSP/CORS、对象存储、容器化与进程管理、配置与密钥管理、备份恢复、日志监控、升级回滚、服务器连接与口令管理、故障清单与自检清单；不覆盖服务端产品的 API 契约、数据模型与业务模块实现。

## 二、环境与拓扑

### 2.1 部署主机与运行环境

| 项 | 要求 |
|---|---|
| 操作系统 | Linux（x86_64 或 arm64），内核支持 Docker 与 cgroup v2 |
| 容器 | Docker Engine + Docker Compose v2；生产不使用 Kubernetes 等集群编排 |
| 部署形态 | 单主机全栈 Compose：同一 Compose 项目包含反向代理、前端、API、Worker 与基础设施容器 |
| 构建前置 | 部署主机必须可访问生态源码（服务端产品的镜像构建上下文是生态工作区根目录），或使用在构建机产出并导入的发布镜像 |
| 本地联调 | Node.js >= 20、pnpm >= 9；Docker 只承担 PostgreSQL / Redis / MinIO 等基础设施，应用进程在宿主 Node 运行 |

约束：

1. 生产环境禁止使用宿主 Node 直接运行 `dist/server.js`：进程管理、日志与重启策略统一由 Docker Compose 承担。
2. 服务端产品镜像内的 Node 版本以镜像基础层为准（当前为 `node:20-alpine`）；本地联调 Node 版本以[01-开发环境配置](./01-开发环境配置.md)为权威。
3. 单主机规格与 Worker 并发（`CARD_RENDER_WORKER_CONCURRENCY`）是当前唯一的容量调节手段；提高并发前必须核对主机 CPU、内存与对象存储带宽。

### 2.2 社区平台服务器拓扑

```text
                        Internet
                           │ 80/443
                    ┌──────▼──────┐
                    │    Nginx    │  证书、跳转、缓存头、反向代理
                    └──┬────┬───┬─┘
             /api/ ────┘    │   └──── /admin/、/admin/api/
          ┌─────────────────▼──────────────┐
          │ /        → web（前台静态）       │
          │ /admin/  → admin（后台静态）     │
          │ /api/    → server:3000（Fastify）│
          └───────┬─────────────────┬──────┘
                  │                 │
        ┌─────────▼──────┐   ┌──────▼──────┐
        │ worker（同镜像）│   │ PostgreSQL  │
        │ 渲染缓存消费    │   │ Redis       │
        └─────────┬──────┘   └─────────────┘
                  │
          ┌───────▼───────────────┐
          │ 对象存储（生产为外部  │
          │ S3 兼容服务；MinIO    │
          │ 仅本地联调/回退）      │
          └───────────────────────┘
```

1. 服务清单：`nginx`、`web`、`admin`、`server`、`worker`、`postgres`、`redis`；本地对象存储模式下额外有 `minio`。
2. `server` 与 `worker` 复用同一个服务镜像，Worker 通过 `command: ["node", "dist/worker.js"]` 切换入口。
3. 只有 `nginx` 发布端口；`server`、`worker`、`postgres`、`redis` 只在 Compose 内部网络可达（端口边界见 §5.3）。
4. 社区平台服务器承担服务端渲染：`worker` 从私有桶读取 `.card` 源文件，调用服务端产品的渲染链路生成查看缓存与封面缓存后写回对象存储。

### 2.3 个人服务器拓扑

```text
                        Internet
                           │ 80/443
                    ┌──────▼──────┐
                    │    Nginx    │  证书、跳转、缓存头、反向代理
                    └──┬───────┬──┘
                 /    │       │ /api/
          ┌───────────▼─┐  ┌──▼──────────────┐
          │ web（前台） │  │ server:3000     │
          └─────────────┘  └──┬──────────────┘
                              │
                       ┌──────▼──────┐
                       │ PostgreSQL  │
                       └─────────────┘
                              │
                       ┌──────▼──────────────┐
                       │ 外部 S3 兼容对象    │
                       │ 存储（生产）        │
                       └─────────────────────┘
```

1. 服务清单：`nginx`、`web`、`server`、`postgres`；生产 Compose 不包含 Redis、Worker 与 Admin。
2. 个人服务器**不做服务端渲染**：渲染产物由客户端上传，卡片状态为 `pending` / `ready` / `error`，服务端只负责发布、存储与会话管理。
3. 主机规格可以低至 1 核 1G；Compose 已按小内存对 PostgreSQL 调优（`shared_buffers=128MB`、`max_connections=50`、`work_mem=4MB`、`maintenance_work_mem=64MB`、`effective_cache_size=384MB`）。
4. 宿主面板（当前使用 1Panel）只用于主机运维，不作为服务端产品的部署入口；面板必须启用强密码与访问限制（§10.6）。

### 2.4 端口与访问矩阵

| 组件 | 容器内端口 | 生产发布 | 本地联调 | 说明 |
|---|---|---|---|---|
| Nginx | 80 / 443 | 是 | 否 | 唯一公网入口；HTTP 与裸域 301 到主站入口 |
| Web（前台） | 80 | 否 | 5173 | 生产由 Nginx 代理，联调由 Vite 提供 |
| Admin（后台） | 80 | 是（社区） | 5174 | 个人服务器无 Admin |
| API | 3000 | 否 | 3000 | 健康检查 `GET /api/v1/health` |
| 渲染 Worker | 无监听 | 否 | 无监听 | 仅消费队列；存活以日志与队列状态判断 |
| PostgreSQL | 5432 | 否 | 可映射本机端口 | 生产禁止对公网发布 |
| Redis | 6379 | 否 | 可映射本机端口 | 生产禁止对公网发布 |
| MinIO | 9000 / 9001 | 否 | 可映射本机端口 | 生产使用外部对象存储时不启动 |

### 2.5 双产品同机共存

社区平台服务器与个人服务器可以部署在同一台主机，必须满足：

1. 两个 Compose 项目声明不同的固定项目名（顶层 `name`），容器名前缀不同（社区 `ccps_*`、个人 `cps_*`）。
2. 主机端口通过 `.env` 中的 `*_HOST_PORT` 变量错开（仅联调场景）；生产环境两者都用 Nginx 独占 80/443，基础设施端口不对公网发布。
3. 两个产品的部署目录、`.env`、证书文件与数据卷互相独立，禁止共用。
4. 同一台主机上的两个产品各自的 Nginx 容器不能同时绑定 80/443：同机部署时只保留一个对外 Nginx，或让另一个产品的 Nginx 改用非标准端口并由外层代理转发。

### 2.6 环境分层

| 环境 | 组成 | 用途 |
|---|---|---|
| 本地联调 | Docker 基础设施（PostgreSQL / Redis / MinIO）+ 宿主 Node 进程 + Vite | 日常开发与接口联调 |
| 生产 | 单主机全栈 Compose + 外部对象存储 | 对外服务 |

- 不设独立预发布环境：候选版本的验证在其自己的生产拓扑上以回滚窗口完成，验证结论写入发布记录（[05-CICD与质量门禁](./05-CICD与质量门禁.md) §5.5）。
- 本地联调禁止连接生产数据库与生产对象存储；环境之间凭据完全隔离（§6.3）。
