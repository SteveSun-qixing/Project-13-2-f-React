## 三、错误码排查表

### 3.1 使用规则

- 按 `code` 分支处理；先确认责任层，再执行处置步骤，不跨层猜测。
- 同一现象可能由多层码共同表达：先看最外层（Bridge / 渲染），再看内层（内核 / 解析 / 资源）。
- 表中"处理步骤"均为正向修复；禁止以关闭校验、放宽权限、跳过安全基线作为处置。

### 3.2 Bridge 通道级（`BRIDGE_*`）

权威码表见 [02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 9.2。

| 错误码 | 现象 | 常见原因 | 处理步骤 |
|---|---|---|---|
| `BRIDGE_CAPABILITY_NOT_FOUND` | 调用立即失败；无副作用 | 能力 ID 拼写错误；能力族目标未登记；提供方已停用并注销能力；更新 draining 期间的新调用 | 1. 核对能力 ID 与[04-能力契约规范](../05-接口与契约/04-能力契约规范.md)登记清单；2. 确认提供方插件为 `active`；3. 属第三方能力时确认其注册成功（`BRIDGE_CAPABILITY_CONFLICT` 会拒绝后注册方） |
| `BRIDGE_CAPABILITY_CONFLICT` | 提供方启用失败 | ID 已占用；使用平台保留 ID；登记提供方与 `owner` 不一致；能力 ID 与权限 ID 相同；schema 结构校验失败 | 1. 查平台日志中冲突的 ID 与 owner；2. 修改能力 ID 或解除与内置 ID 的冲突；3. 确保能力 ID 与权限 ID 分属两套命名空间 |
| `BRIDGE_INVALID_SCHEMA` | 提供方启用失败 | schema 关键字非法；远程 `$ref` 或无法离线编译；非 JSON Schema 2020-12 子集 | 1. 按[04-能力契约规范](../05-接口与契约/04-能力契约规范.md)第五节核对允许关键字；2. 改为内联子 schema；3. 重新启用插件 |
| `BRIDGE_PERMISSION_DENIED` | 调用被拒，`details.reason` 给出原因 | 未授予、已撤销、超出限定值、用户拒绝、策略禁止 | 见 [4.5](#45-权限被拒) |
| `BRIDGE_INVALID_INPUT` | 调用被拒，`details.errors` 给出指针与关键字 | 字段缺失/类型不符/枚举越界；传入了未声明字段（内置能力 `additionalProperties: false`） | 1. 按 `details.errors[].pointer` 修正输入；2. 不做默认值假设（Bridge 不填充 `default`）；3. 重试前确认输入为结构化克隆兼容值 |
| `BRIDGE_TIMEOUT` | 调用超时（默认 30000 ms） | Host 执行过慢；阻塞型实现占用命令循环；外部 IO 未设超时 | 1. 按 `requestId` 确认是否已产生副作用；2. 复核能力实现是否 `spawn_blocking`/异步；3. 仅对幂等能力重试，或调低单次负载 |
| `BRIDGE_CANCELLED` | 调用方收到取消 | 会话销毁、能力注销、Bridge 关闭 | 1. 确认窗口/插件是否被停用或关闭；2. 属正常收口，勿重试已销毁会话的调用 |
| `BRIDGE_SESSION_UNKNOWN` | 调用全部失败 | 来源会话无法解析或已关闭；窗口销毁后继续调用；子框架未登记 | 1. 确认 `windowId` / `frameId` 与会话绑定关系；2. 插件停用后重新启用；3. 不要用负载中自报的 `pluginId` 排查（身份只由 Bridge 解析） |
| `BRIDGE_SESSION_BUSY` | 偶发失败，可重试 | 会话在途调用超限（默认 64） | 1. 降低批量并发；2. 等待在途调用完成后重试；3. 检查是否有未释放的并发流 |
| `BRIDGE_QUEUE_OVERFLOW` | 串行能力偶发失败 | 同一串行能力等待队列溢出（默认 32） | 1. 控制调用节奏，串行提交；2. 确认没有把串行能力用于高频轮询 |
| `BRIDGE_INTERNAL` | 通用失败文案 | 未归一异常 | 1. 在平台主日志中按时间与 `traceId` 找诊断详情；2. 复现后按 [六、信息收集](#六提报工单前的信息收集清单) 提报 |

### 3.3 插件与内核（`PLUGIN_*` / `KERNEL_*` / `PERMISSION_*`）

插件生命周期失败的权威码表是内核码 `KERNEL_*`（[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) 9.1）；插件管理层可映射为 `PLUGIN_*`，本文使用的已登记码为 `PLUGIN_PERMISSION_DENIED`（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 9.1）。

| 错误码 | 现象 | 常见原因 | 处理步骤 |
|---|---|---|---|
| `PLUGIN_PERMISSION_DENIED` | 插件启用或能力注册被拒 | 能力注册时权限未在提供方 manifest 声明；启用阶段权限校验失败 | 1. 对照 [4.5](#45-权限被拒) 核对 `permissions` 与授权；2. 服务插件注册能力前先声明对应基础权限 |
| `PERMISSION_NOT_DECLARED` | 能力注册失败 | `capability.permissions` 未在提供方 manifest 声明 | 1. 在 manifest 补齐权限申请；2. 重新启用插件使注册重跑 |
| `PERMISSION_UNKNOWN` | 安装校验终止 | 权限 domain/scope 未注册 | 1. 对照[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 3.2 内置域表；2. 删除自造权限 ID |
| `PERMISSION_INVALID` | 安装校验终止 | 权限 ID 语法非法；限定值缺失/多余（按域要求） | 1. 核对三段式语法与前两段切分规则；2. 路径限定改用目录变量，不写绝对路径 |
| `PERMISSION_ROLE_NOT_ALLOWED` | 安装校验终止 | 角色不适用该权限（如 `basecard` 申请 `window:control`） | 1. 删除不适用权限；2. 确需窗口能力时拆分为 `app` 插件（R1 单角色约束） |
| `KERNEL_DEPENDENCY_MISSING` | 插件停留 `pending`，不执行代码 | 依赖插件未安装 | 1. 安装被依赖插件；2. 依赖就绪后自动继续启用，无需重装 |
| `KERNEL_DEPENDENCY_VERSION` | 插件停留 `pending` | 已安装版本不在 `dependencies` 范围内 | 1. 升级/降级依赖插件到范围内；2. 或调整依赖声明（须满足全部依赖者） |
| `KERNEL_DEPENDENCY_CYCLE` | 插件 `failed` | 依赖成环或自依赖；返回环路径 | 1. 按环路径打破循环；2. 公共部分下沉为 `service` 插件（§7.4 拆分规则） |
| `KERNEL_DEPENDENCY_DUPLICATE` | 插件 `failed` | 同一依赖重复声明 | 1. 去重 `dependencies`；2. 重新启用 |
| `KERNEL_DEPENDENCY_CONFLICT` | 停用/卸载被拒，附依赖者列表 | 存在 `active` 依赖者；卸载时存在任何依赖者 | 1. 按逆拓扑序先停用依赖者，或显式请求级联停用；2. 卸载前先卸载依赖者 |
| `KERNEL_APPLY_FAILED` | 插件 `failed`，副作用已回滚 | 激活入口（`start` / 注册 / `launch`）抛错 | 1. 读取注册表 `lastError` 与插件日志定位抛错点；2. 修复后显式重试（`failed → starting`） |
| `KERNEL_INJECT_FAILED` | 插件 `failed` | 注入回调执行出错；依赖替换后重建失败 | 1. 检查注入回调内不得缓存跨代际引用；2. 长任务挂到注入 Fork；3. 修复后重试 |
| `KERNEL_DISPOSE_FAILED` | 停用完成但记录错误 | 清理函数抛错或超时；单个副作用撤销失败 | 1. 确认 `dispose()` 幂等且不抛异常；2. 检查未被 Fork 追踪的副作用；3. 审计中复核失败项 |
| `KERNEL_PLUGIN_PANICKED` | 插件 `failed`，依赖方保持 `active` | 插件任务 panic 或同步回调 panic | 1. 在插件日志中定位 panic 点；2. 生产代码禁止 `unwrap()` / `panic!`；3. 修复后重试 |
| `KERNEL_INVALID_TRANSITION` | 卸载被拒 | 在 `active` / `stopping` 状态直接卸载 | 1. 先停用再卸载；2. 用状态字段确认当前状态 |
| `KERNEL_PLUGIN_NOT_FOUND` | 操作失败 | 目标插件未登记或已被卸载 | 1. 刷新插件列表；2. 重新安装 |
| `KERNEL_SERVICE_NOT_FOUND` | 调用失败 | 提供方停用/失败后服务条目摘除；未声明依赖导致注入未建立 | 1. 确认提供方状态；2. 声明 `dependencies` 并用 `ctx.inject` 表达服务注入 |
| `KERNEL_SERVICE_TYPE_MISMATCH` | 调用失败 | 消费方按错误类型下转服务值 | 1. 核对服务契约类型；2. 同名服务被其他作用域遮蔽时按最近祖先原则排查 |
| `KERNEL_CONTEXT_DISPOSED` | 操作被拒 | 对已销毁 Context 继续注册/订阅 | 1. 检查插件是否在停用后仍持有回调；2. 长任务改为取消令牌 + `effect` 清理 |
| `KERNEL_LOCK_POISONED` | 操作失败 | 持锁路径发生 panic | 1. 提报工单并附平台日志；2. 不要在插件代码中阻塞或持锁 `await` |
| `KERNEL_EVENT_DEPTH_EXCEEDED` | 发布失败 | 嵌套派发深度超过 64 | 1. 检查监听器是否递归发布同一事件；2. 事件只作通知，改用服务或能力 |

### 3.4 文档解析（`DOCUMENT_*`）

权威码表见 [06-文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md) 8.2。

| 错误码 | 现象 | 常见原因 | 处理步骤 |
|---|---|---|---|
| `DOCUMENT_NOT_FOUND` | 打开失败 | 入口路径不存在；已移动/重命名 | 1. 核对路径与大小写；2. 由文件事件或资源管理器确认目标仍在 |
| `DOCUMENT_IO` | 打开失败，可重试 | 权限位、占用、映射失败；归档被写入端占用 | 1. 确认文件未被其他进程独占；2. 目录态检查读取权限；3. 重试打开 |
| `DOCUMENT_FORMAT_UNKNOWN` | 打开失败 | 非目录、非 ZIP；文件头非 `PK\x03\x04` / `PK\x05\x06`；严格入口与声明格式不符 | 1. 用 `unzip -v` 确认归档可读；2. 严格入口下改扩展名或改用自动识别入口；3. 损坏文件从备份恢复 |
| `DOCUMENT_METADATA_MISSING` | 打开失败 | 缺少 `.card/metadata.yaml` / `.box/metadata.yaml` | 1. 解包检查 `.card/` 或 `.box/` 配置目录是否存在；2. 确认归档根即包根（无顶层包裹目录） |
| `DOCUMENT_METADATA_INVALID` | 打开失败 | metadata 语法/schema 失败；版本字段非三段式 | 1. 按诊断的 `file:line:column` 与字段指针修正；2. 版本号加引号；3. 修正后重新 `validate` |
| `DOCUMENT_STRUCTURE_INVALID` | metadata 可用、结构层级不可用 | structure 语法/schema 失败（全量解析时致命） | 1. 按诊断修正 `.card/structure.yaml` / `.box/structure.yaml`；2. 检查条目必填字段与类型 |
| `DOCUMENT_VERSION_OUTDATED` | 打开失败 | 文档主版本低于平台支持版本 | 1. 运行迁移工具升级（迁移由用户显式发起）；2. 迁移后必须通过 `validate` 再打开 |
| `DOCUMENT_VERSION_UNSUPPORTED` | 打开失败 | 文档主版本高于平台支持版本 | 1. 升级平台；2. 不做隐式降级与兼容层 |
| `DOCUMENT_ARCHIVE_INVALID` | 打开失败 | 归档损坏、重复路径、加密条目、非法压缩方法、非 UTF-8 文件名 | 1. 用 `unzip -t` 校验完整性；2. 用 `unzip -v` 确认成员方法为 `Stored`；3. 重新打包或从备份恢复 |
| `DOCUMENT_PATH_UNSAFE` | 打开失败 | 包内路径越界、非法字符、zip-slip | 1. 检查包内成员路径（禁 `..`、绝对路径、反斜杠）；2. 用标准工具重新打包 |
| `DOCUMENT_LIMIT_EXCEEDED` | 打开失败，`details` 携带 `{ limit, actual }` | 成员数、解压字节、压缩比、别名或深度超限 | 1. 按超限项裁剪文档（默认：YAML 单文件 8 MiB、条目 10000、解压总量 512 MiB）；2. 拆分大文档 |
| `DOCUMENT_PARSE_CANCELLED` | 打开中断 | 调用方取消 | 1. 确认取消来源（关闭会话/切换文档）；2. 需要时重新打开 |

### 3.5 文档诊断码（非致命）

诊断不阻断打开，按 `severity` 决定是否修复；完整表见 [06-文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md) 8.3。

| 诊断码 | 严重级 | 含义与处置 |
|---|---|---|
| `YAML_SYNTAX_ERROR` | 错误 | 语法错误，含行列；按位置修正 |
| `SCHEMA_REQUIRED_MISSING` | 错误 | 必填字段缺失；补齐字段 |
| `SCHEMA_TYPE_MISMATCH` | 错误 | 类型不符；修正标量写法（版本号、`yes/no` 加引号） |
| `YAML_UNSUPPORTED_TAG` | 错误 | 使用禁用标签（如 `!!binary`）；移除标签 |
| `SCHEMA_UNKNOWN_FIELD` | 警告（严格：错误） | 未知字段；删除或按规范登记 |
| `SCHEMA_DEFAULT_APPLIED` / `DOCUMENT_DEFAULT_APPLIED` | 信息 | 已补齐默认值；无需处理 |
| `STRUCTURE_CONTENT_MISSING` | 错误 | 结构引用的内容文件缺失；补文件或修引用 |
| `STRUCTURE_NODE_FAILED` | 错误 | 单节点解析失败；按节点诊断修复，其他节点不受影响 |
| `ENTRY_SOURCE_INVALID` | 错误 | 条目引用语法非法或 scheme 不允许；改用包内相对路径或允许的 URI |
| `ENTRY_TARGET_MISSING` | 警告 | 包内引用目标不存在；补齐目标或修正 `url` |
| `ENTRY_FAILED` | 错误 | 单条目解析失败、位置保留；按条目诊断修复 |
| `DOCUMENT_RESOURCE_FILE_MISSING` | 警告 | 资源清单条目对应文件缺失；补齐资源或更新清单 |
| `DOCUMENT_RESOURCE_INTEGRITY_MISMATCH` | 警告（严格：错误） | 尺寸/哈希不匹配；重新计算并写回清单 |
| `DOCUMENT_UNREFERENCED_FILE` | 警告（严格） | 存在未被引用的内容或资源；删除或补充引用 |
| `DOCUMENT_GENERATED_FILE_IGNORED` | 信息 | 已忽略系统生成物（`.DS_Store` 等）；无需处理 |
| `DOCUMENT_SYMLINK_IGNORED` | 错误 | 目录态符号链接未纳入索引；改为普通文件 |
| `DOCUMENT_UNICODE_NORMALIZED` | 信息 | 已执行 BOM 剥离/换行归一；无需处理 |
| `DOCUMENT_EXTENSION_MISMATCH` | 警告 | 扩展名与实际结构不符；改名或修正结构 |
| `DOCUMENT_VERSION_MISMATCH` | 警告 | 次版本高于平台支持；未知字段按策略处理，建议升级平台 |

### 3.6 资源（`RESOURCE_*`）

权威码表与协议层 HTTP 映射见 [06-资源协议规范](../05-接口与契约/06-资源协议规范.md) 7.2。

| 错误码 | 现象 | 常见原因 | 处理步骤 |
|---|---|---|---|
| `RESOURCE_INVALID_URI` | 句柄同步抛错；协议 400 | scope 段非法；受管作用域带查询串；fragment；非法编码；userinfo | 1. 核对 URI 语法；2. 字面 `?` / `#` / `%` 必须编码；3. 去掉 fragment 与查询串 |
| `RESOURCE_UNSUPPORTED_SCHEME` | 句柄同步抛错 | `resource()` 收到 `chips-resource://` / `http(s)://` 以外的 scheme | 1. 把 `file://` 改为文档解析器归一后的受管 URI；2. 外部地址使用 `http(s)://` 输入 |
| `RESOURCE_NOT_FOUND` | 裂图/404 | 作用域未注册或资源不存在；路径大小写不符；引用未随包携带 | 1. 确认目标在包内且路径正确（卡片资源在包根，箱子自有资源在 `assets/`）；2. 检查大小写与 NFC；3. 重新打包后重开文档 |
| `RESOURCE_PATH_INVALID` | 裂图/400 | 路径穿越、绝对路径、反斜杠、控制字符、长度超限、符号链接逃逸 | 1. 改用包内相对路径；2. 移除 `..` 与编码变体；3. 目录态改为普通文件 |
| `RESOURCE_PERMISSION_DENIED` | 裂图/403，或句柄同步抛错 | 跨作用域未授权；作用域未绑定到调用会话；撤销后立即失效 | 见 [4.5](#45-权限被拒)；`details.target` 为规范 URI |
| `RESOURCE_TOO_LARGE` | `read()` 失败 / 413 | 单次读取超过 8 MiB 或资源超过 2 GiB | 1. 改用 `readRange()` 或 `stream()`；2. 压缩或拆分资源 |
| `RESOURCE_BUSY` | `readRange()` 失败 / 503 | 同一句柄流已打开 | 1. 等待流结束或 `release()` 后重新获取；2. 不要对同一句柄并发混用流与范围读 |
| `RESOURCE_HANDLE_RELEASED` | 句柄方法失败 | 使用已释放句柄 | 1. 重新 `resource(uri)` 获取新句柄；2. 检查视图卸载后是否仍有残留调用 |
| `RESOURCE_HANDLE_INVALIDATED` | 句柄方法失败 | 来源变化、会话关闭、权限撤销 | 1. 重新获取句柄，不复用旧句柄；2. 用 `onInvalidate` 订阅失效原因 |
| `RESOURCE_POOL_EXHAUSTED` | 打开失败 / 503 | 单插件句柄 64 或全局 4096 超限；读取队列超限 | 1. 排查句柄泄漏（用后立即 `release()`）；2. 收敛并发读取 |
| `RESOURCE_READ_ONLY` | 写入提交失败 | 对归档或只读作用域就地写入；Platform / External 禁写 | 1. 归档写入改由文档保存流程重建归档；2. 不向平台与外部作用域写入 |
| `RESOURCE_WRITE_FAILED` | 写入提交失败，可重试 | 磁盘、锁冲突；写者竞争 | 1. 确认无其他写者；2. 重试提交；3. 检查磁盘空间与权限 |
| `RESOURCE_NETWORK_FAILED` | 外部资源失败 / 502 | DNS、连接、TLS、超时、HTTP 状态、重定向、SSRF 拦截 | 1. 按 `details.reason`（`dns` / `connect` / `tls` / `timeout` / `http_status` / `redirect` / `blocked`）定位；2. 核对 `network:http` 域名限定；3. 检查是否命中私网/环回拦截 |
| `RESOURCE_INTERNAL` | 资源失败 / 500 | 未归一异常 | 1. 在平台主日志按时间定位；2. 提报工单 |

### 3.7 渲染（`RENDER_*`）

权威码表见 [05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 第十一节。

| 错误码 | 现象 | 常见原因 | 处理步骤 |
|---|---|---|---|
| `RENDER_DOCUMENT_INVALID` | 卡片内损坏说明与路径提示 | 解析校验失败（先有 `DOCUMENT_*` 码） | 1. 按 [3.4](#34-文档解析document_) 修复文档；2. 修复后重新打开 |
| `RENDER_PLUGIN_MISSING` | 节点级占位，提示安装插件 | 未安装声明该 `card_type` / `layouts.id` 的基础卡片或布局插件 | 1. 安装对应角色插件；2. 确认插件 `active` 且注册表已登记类型 |
| `RENDER_PLUGIN_FAILED` | 占位 + 重试 | 插件渲染抛错（`renderView` / `renderLayout` / `renderEditor`） | 1. 读插件日志与帧错误消息；2. 修复插件异常后重试（重走完整链路） |
| `RENDER_FRAME_TIMEOUT` | 占位 + 重试 | 帧握手超时（默认 5s）；帧运行时未加载、资源 404、CSP 拦截 | 1. 确认 `chips-resource://platform/frame.html` 可加载；2. 检查 CSP 是否放行 `chips-resource:`；3. 检查渲染帧是否被代理/插件脚本阻塞 |
| `RENDER_RESOURCE_DENIED` | 资源位置显示权限说明 | 帧内资源越权或权限被拒 | 1. 按 [4.5](#45-权限被拒) 核对权限；2. 检查 `resourceBase` 注入是否为受管 URI |
| `RENDER_SCHEMA_UNSUPPORTED` | 占位，提示升级 | 已装插件的版本策略、能力声明或 schema 与内容要求不匹配（文档格式版本问题由解析链路返回 `DOCUMENT_VERSION_*`） | 1. 核对内容结构与插件 `configSchema` / 能力声明；2. 升级插件或调整内容；3. 文档格式版本问题按 [3.4](#34-文档解析document_) 处理 |
| `RENDER_SESSION_DISPOSED` | 调用方错误，记录诊断 | 会话已释放仍被调用 | 1. 检查 `dispose()` 后的残留调用；2. 视图卸载时同步释放订阅与句柄 |
| `RENDER_PROTOCOL_VIOLATION` | 帧通道断开、占位降级 | 帧消息违规：越级发送、重复 `frame:ready`、非递增 `epoch` / `revision`、未知消息类型 | 1. 核对[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 9.3 消息清单；2. 禁止条目帧越级请求 RenderHost；3. 修复插件帧实现 |

### 3.8 插件包（`CPK_*`）

权威码表见 [03-插件包格式](../04-文件格式规范/03-插件包格式.md) 第八节；安装阶段顺序为归档 → 结构 → 清单 → 签名 → 摘要。

| 错误码 | 现象 | 常见原因 | 处理步骤 |
|---|---|---|---|
| `CPK_ARCHIVE_INVALID` | 安装终止 | 非 ZIP、损坏、加密、ZIP64、成员非 Store、CRC 失败、重复路径、嵌套归档 | 1. `unzip -v` 确认全部成员 `Stored`；2. 用 `zip -r -0 -X` 重新打包；3. 删除包内嵌套归档 |
| `CPK_LAYOUT_INVALID` | 安装终止（或警告） | 包根出现白名单外条目；角色布局不符；隐藏文件；无用资源告警 | 1. 对照包根白名单清理（仅 `manifest.yaml`、`dist/`、`render.js`、`assets/`、`signature.json`）；2. `service` 删除 `render.js` 与 UI 资源；3. 清理 sourcemap、测试与源码 |
| `CPK_MANIFEST_MISSING` | 安装终止 | 包根缺少 `manifest.yaml` 或存在多份清单 | 1. 确认清单在归档根；2. 确认无顶层包裹目录；3. 删除多余清单 |
| `CPK_MANIFEST_INVALID` | 安装终止，`details.pointer` 指向字段 | schema 失败；路径引用非法或缺失；与源码 `package.json` 版本不一致 | 1. 按[02-插件清单规范](../03-插件开发/02-插件清单规范.md)逐字段修正；2. 图标等引用改为 `assets/` 内包内相对路径；3. 对齐版本号后重新打包 |
| `CPK_ENTRY_MISSING` | 安装终止 | 缺少 `dist/index.js` 或角色要求的 `render.js`；入口非文本或非 ESM | 1. 补齐入口并确认默认导出对象；2. `service` 不得提供 `render.js`；3. 重新构建 |
| `CPK_NATIVE_PAYLOAD` | 安装终止 | 携带原生可执行载荷（扩展名或魔数命中） | 1. 删除 `.node` / `.dll` / `.so` / `.dylib` / `.wasm` 等；2. 系统能力改用 Bridge；3. 依赖打包进 `dist/index.js` |
| `CPK_PATH_UNSAFE` | 安装终止 | 路径穿越、绝对路径、符号链接、非法字符、保留设备名、大小写冲突 | 1. 用标准工具在暂存目录内归档；2. 移除符号链接与非法路径 |
| `CPK_LIMIT_EXCEEDED` | 安装终止 | 体积、成员数、单文件、清单大小、路径长度或深度超限 | 1. 按[03-插件包格式](../04-文件格式规范/03-插件包格式.md)第四节限额裁剪（包 ≤ 50 MiB、成员 ≤ 512、单文件 ≤ 16 MiB、单入口 ≤ 8 MiB）；2. 优化资源 |
| `CPK_SIGNATURE_REQUIRED` | `builtin` 来源安装终止 | 渠道要求签名而缺失 | 1. 按发布流程签名；2. `user` 来源需在界面明确提示"未签名发布者"后由用户确认 |
| `CPK_SIGNATURE_INVALID` | 安装终止 | 签名结构、`keyId`、`contentHash` 或签名值失败；信任根未注册 | 1. 重新签名；2. 核对信任根注册表；3. 签名有效不免除其余校验 |

### 3.9 其他常见域

| 错误码 | 现象 | 常见原因 | 处理步骤 |
|---|---|---|---|
| `EVENT_ID_INVALID` | 订阅同步抛错 / 发布被拒 | 事件 ID 不符合 `<domain>:<action>` | 1. 修正 ID 命名；2. 平台保留域只能由平台发布 |
| `EVENT_NOT_REGISTERED` | 订阅不建立（仅回执与审计可见） | 订阅未登记事件 | 1. 对照[05-事件契约规范](../05-接口与契约/05-事件契约规范.md)登记清单；2. 插件自有域事件不跨进程 |
| `EVENT_SUBSCRIBE_DENIED` | 订阅不建立 | 缺少事件契约声明的订阅权限；订阅 `internal:*` | 1. 在设置面板补授权；2. 不依赖 `internal:*` |
| `EVENT_PUBLISH_DENIED` | 发布被拒 | 发布保留域、越出自有命名空间、缺少 `events:publish` | 1. 改用插件自有域；2. 申请并授予 `events:publish` |
| `EVENT_PAYLOAD_UNSUPPORTED` | 发布被拒 | payload 不可结构化克隆 | 1. 只传纯数据；2. 错误值改用归一 `ChipsError` 普通对象 |
| `EVENT_PAYLOAD_TOO_LARGE` | 发布被拒 | 序列化后超过 256 KiB | 1. 大对象改走资源句柄或 `chips-resource://` URI |
| `APP_LAUNCH_FAILED` | 应用启动失败，窗口关闭 | `launch` 抛出或拒绝，`details.cause` 携带原因 | 1. 读插件日志定位 `launch` 抛错；2. 修复后从启动器重试 |
| `APP_OPEN_FILE_UNSUPPORTED` / `APP_URI_INVALID` | 文件关联打开失败 | 实例未实现 `openFile`；URI 不是 `file://` / `chips-resource://` | 1. 实现 `openFile`；2. 远程内容先落地再投递 |
| `APP_STATE_INVALID` / `APP_WINDOW_CLOSED` | 命令投递失败 | 实例启动中/退出中/不存在；主窗口已关闭 | 1. 等待实例就绪后重投；2. 由启动器重新启动 |
| `FILE_NOT_FOUND` / `FILE_IO_FAILED` | 文件能力失败 | 目标不存在；磁盘、权限位、占用 | 1. 核对路径与授权范围；2. `FILE_IO_FAILED` 可重试；3. 不绕过 `filesystem:*` 判定 |
| `FILE_NOT_EMPTY` | 删除目录失败 | 非空目录未请求递归删除 | 1. 显式 `recursive: true`；2. 确认目标范围无误；3. `file:delete` 所需权限为 `filesystem:delete`（不是 `filesystem:write`），核对 manifest 声明与授权 |
| `HTTP_REQUEST_FAILED` / `HTTP_BLOCKED` / `HTTP_REDIRECT_DENIED` | 网络请求失败 | DNS/连接/TLS/超时/响应过大；SSRF、私网或端口拦截；重定向超出授权 | 1. 按 [3.6](#36-资源resource_) 的 `RESOURCE_NETWORK_FAILED` 同法定位；2. 核对 `network:http` 限定值 |
| `CONFIG_SCHEMA_INVALID` / `CONFIG_KEY_UNKNOWN` / `CONFIG_VALUE_INVALID` | 配置读写失败 | 值未通过 schema；键未注册；类型不符 | 1. 对照插件 `config.schema.json`；2. 键使用命名空间内相对键 |
| `CONFIG_POLICY_LOCKED` / `CONFIG_NAMESPACE_DENIED` | 配置写入被拒 | 策略锁定的键；跨命名空间访问 | 1. 只读写自身命名空间；2. `platform` 命名空间需带命名空间限定值的授权 |
| `CARD_EXPORT_UNSUPPORTED` / `CARD_EXPORT_FAILED` | 卡片导出失败 | `export` 未声明该格式；编码、资源、模板失败 | 1. 按插件声明的格式导出；2. 按 `retryable` 决定是否重试 |
