# 服务端部署与运维

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片生态服务端产品（社区平台服务器、个人服务器）的部署与运维权威规范：环境与拓扑、域名/HTTPS/证书/CSP/CORS、对象存储、容器化与进程管理、配置与密钥管理、备份恢复、日志监控、升级回滚、服务器连接与口令管理、故障清单与自检清单；不覆盖服务端产品的 API 契约、数据模型与业务模块实现。

## 四、对象存储

### 4.1 逻辑桶与可见性

对象存储使用 S3 兼容协议；逻辑桶固定如下（命名不得修改）：

| 逻辑桶 | 可见性 | 内容 | key 约定 |
|---|---|---|---|
| `chips-card-resources` | 公开 | 卡片内嵌资源（图片、音视频等） | `{userId}/{cardId}/{filename}` |
| `chips-card-render-cache` | 公开 | 公开卡片查看缓存 | `{cardId}/{cacheVersion}/index.html` |
| `chips-card-cover-cache` | 公开 | 公开卡片封面缓存 | `{cardId}/{cacheVersion}/index.html` |
| `chips-avatars` | 公开 | 用户头像 | `{userId}/avatar.{ext}` |
| `chips-covers` | 公开 | 房间/箱子封面 | `rooms/{roomId}/cover.{ext}` |
| `chips-card-files` | 私有 | 发布态 `.card` 源文件（永久） | `{userId}/{cardId}/source.card` |
| `chips-box-files` | 私有 | 发布态 `.box` 源文件（永久） | `{userId}/{boxId}/source.box` |
| `chips-card-render-cache-private` | 私有 | 私有卡片查看缓存 | `{cardId}/{cacheVersion}/index.html` |
| `chips-card-cover-cache-private` | 私有 | 私有卡片封面缓存 | `{cardId}/{cacheVersion}/index.html` |

### 4.2 桶初始化与公开读策略

1. 服务端产品与 Worker 启动时自动执行桶初始化：逐个 `HeadBucket`，不存在则创建；对公开桶设置匿名只读策略；幂等，可重复执行。
2. 初始化失败必须阻止进程继续启动（不得带着不完整存储进入服务）。
3. 私有桶**禁止**设置匿名读策略；公开桶只授予 `s3:GetObject`，不得授予列表、写入或删除权限。
4. 初始化的桶集合以代码为准（当前 9 个逻辑桶）；新增或删除逻辑桶必须同步更新本节表格。

### 4.3 物理桶映射

1. 默认模式：每个逻辑桶对应独立物理桶。
2. 单物理桶模式（设置 `S3_BUCKET_NAME=<物理桶>`）：
   - 公开逻辑桶写入同一物理桶，对象 key 以逻辑桶名为前缀；公开 URL 仍保留逻辑桶前缀，前台与已发布链接不受影响；
   - **私有逻辑桶必须继续使用独立私有物理桶**，不得写入公开物理桶；
   - `S3_ENDPOINT` 必须使用服务商的通用端点（如 `https://s3.<region>.<provider>.com`），禁止使用 bucket 专属端点（会把物理桶名写进对象 key，导致公开 URL 404）。
3. 单物理桶模式下的公开前缀与 DB 中保存的 `viewUrl`、`coverUrl`、`entryUrl` 必须一致，避免缓存入口与资源路径漂移。

### 4.4 公开资源入口

1. 生产必须配置 `S3_PUBLIC_URL` 为资源入口的 HTTPS 域名（自定义域名或 CDN 域名），并在对象存储服务商侧完成域名绑定与证书配置。
2. 未配置 `S3_PUBLIC_URL` 时的回退：开发态使用对象存储直连地址；非开发态使用 `${BASE_URL}/cdn/<逻辑桶>`。生产禁止依赖回退路径，因为它会把资源流量压回主站。
3. 公开资源响应必须满足：
   - 不出现 `content-encoding: aws-chunked`（S3 客户端必须使用 `WHEN_REQUIRED` 校验策略，避免七牛云等兼容存储把流式校验编码持久化为对象元数据）；
   - 文本类资源携带明确字符集（如 `text/html; charset=utf-8`）；
   - 媒体类资源支持 `Range` / `206 Partial Content` 与 `Accept-Ranges: bytes`。
4. 部署后必须验证新上传的图片、HTML、视频各一例，检查响应头与分段读取。

### 4.5 源文件与缓存生命周期

| 对象 | 生命周期 | 说明 |
|---|---|---|
| `chips-card-files` / `chips-box-files` 源文件 | 永久保留 | 任何缓存清理、重建都不得删除源文件 |
| 查看缓存 / 封面缓存 | 最后一次访问后 30 天 | 过期由 Worker 每小时清理；缓存可由源文件重建 |
| Worker 渲染缓存版本 | `CARD_RENDERER_VERSION` 变更即整体失效 | 渲染器或输出契约变化时必须递增该值 |
| 上传会话 | 默认 60 分钟 | 过期会话由服务端产品回收 |

### 4.6 凭据与访问控制

1. 对象存储凭据（Access Key / Secret Key）按环境独立签发，生产凭据不得用于本地联调；本地联调可使用 MinIO 的独立凭据。
2. 凭据权限收敛为：公开桶只读 + 私有桶读写 + 必要的桶管理权限；禁止使用服务商主账号全权限密钥。
3. 凭据只存在于 `deploy/.env`（见 §6），不得写入代码、镜像、Compose 文件、日志与文档。
4. 服务商控制台账号必须启用多因素认证；控制台访问与 API 密钥分离管理。
