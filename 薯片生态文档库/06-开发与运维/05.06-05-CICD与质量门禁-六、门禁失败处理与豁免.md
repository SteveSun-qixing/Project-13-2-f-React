## 六、门禁失败处理与豁免

### 6.1 失败处理

```
门禁失败 → 阻断合并/发布 → 定位失败门禁与证据 → 修复根因 → 全量重跑 → 记录
```

- 失败报告必须包含：失败门禁项、失败命令、关键输出与复现方式。
- 修复后必须全量重跑；禁止只重跑失败项后合并。
- 禁止：重跑碰运气；修改测试迎合实现；删除或弱化断言；跳过阶段；关闭检查；临时注释门禁配置；以"本地通过"或"稍后修复"为由合并。
- 基础设施抖动允许重跑一次，必须记录证据；测试不稳定按缺陷修复，不得反复重试。

### 6.2 flaky 测试

- 不稳定测试必须定位根因（时序、并发、共享状态、真实外部依赖）并修复；禁止以重试掩盖（《测试规范》第十二节）。
- 禁止以隔离替代修复；确需隔离时必须登记技术债务清单、注明原因与偿还期限，并在流水线与测试报告中显式标记。
- 到期未偿还的隔离视为门禁失败；禁止长期或无记录隔离。

### 6.3 豁免的唯一合法形式

- 豁免必须同时满足：
  1. 在 PR 描述与技术债务清单中登记；
  2. 记录要素齐全：门禁项、理由、证据、影响范围、批准人、期限、偿还任务编号；
  3. 只豁免该次判定，不改变门禁本身；
  4. 到期未清偿自动失效，按门禁失败处理。
- 代码内抑制（`#[allow(clippy::...)]`、`eslint-disable`、`it.skip`、`#[ignore]`）必须写明理由并关联登记记录；无理由抑制在评审中拒绝。
- 禁止无痕豁免：口头同意、聊天记录、临时注释、个人本地配置一律不构成豁免。
- 机读消费契约（工单 017 落地）：豁免的判定层消费唯一入口为 G6 覆盖率门禁（G1~G5/G7~G9 无豁免挂点）。
  《技术债务清单》以 `GATE-EXEMPTIONS-BEGIN/END` HTML 注释标记包裹一个 `json` 围栏块（`chips-gate-exemptions/v1`），
  每条登记必须含七要素机读字段：`id`、`gate`（门禁编号）、`group`（判定组 id）、`metric`（统计维度）、
  `deadline`（YYYY-MM-DD，当日结束前有效）、`status`（`active`/`repaid`/`revoked`，仅 `active` 可消费）、
  `approver`、`reason`、`scope`、`evidence`、`repaymentTask`。判定失败时门禁按 `gate+group+metric` 匹配：
  命中有效登记 → 违规转留痕警告（`COVERAGE030`），测量数字照常呈现；过期、要素缺失、状态非 `active`、
  登记文件不可读 → 维持失败判定并留警告痕（`COVERAGE031`）。人读登记与机读块不一致时按「要素缺失」维持失败；
  两处必须同 PR 更新。豁免放行的判定不构成质量达标声明，期限届满未清偿自动失效并按门禁失败处理。

### 6.4 禁止的豁免形态

- 禁止在 PR 级放宽数值门禁（覆盖率、性能预算）。
- 禁止发布豁免：tag 流水线与渠道发布不接受任何未通过门禁的产物。
- 禁止删除或关闭门禁配置（如取消 `-D warnings`、删除 lint 规则、移除 `import/no-cycle`）。
- 禁止扩大覆盖率排除范围、缩小基准夹具、更换测量口径来"通过"门禁。
- 禁止长期保留豁免与长期隔离测试。

### 6.5 数值基线调整

- 门禁数值只存在于《架构原则》《超大型工程管理体系》与各子系统预算表；本文与流水线配置只引用。
- 调整唯一路径：RFC → 评审 → ADR → 同 PR 更新权威文档、测试与流水线配置（R16）。
- 调整必须附数据证明：测量环境、基准数据、复现方法；禁止以"后续优化"推迟（《01-架构原则》4.2、《06-文档解析器设计》9.5 节）。
- 子系统内部分解预算的调整同样走本节流程，由对应子系统文档维护。
