## 二、日志与诊断信息

### 2.1 日志与数据位置

| 数据 | 位置 | 来源 |
|---|---|---|
| 平台主日志 | macOS：`~/Library/Logs/Chips/main.log`；Windows：`%USERPROFILE%\AppData\Roaming\Chips\logs\main.log`；Linux：`~/.config/Chips/logs/main.log` | [ADR-002](../01-架构设计/ADR/ADR-002-Electron作为桌面端壳.md) |
| 审计日志（JSON Lines，按日切分） | `<userData>/logs/audit/audit-YYYY-MM-DD.jsonl`；单日超 10 MB 切换同日序号文件 | [08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 8.3、8.4 |
| 授权记录 | `<userData>/security/permissions.yaml`（平台独占写入，只读排查用） | [08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 6.6 |
| 插件日志 | 平台日志流，按插件隔离并按限速策略写入 | [10-服务插件接口](../05-接口与契约/10-服务插件接口.md) 3.6 |
| 调试追踪（Bridge / 事件 / 渲染 / 资源 / 插件 / 启动） | `<userData>/logs/trace/trace-YYYY-MM-DD.jsonl`，按日切分、异步追加 | [03-调试指南](./03-调试指南.md) 2.1–2.3 |
| 平台/用户/工作区配置 | 目录映射见 [10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) 3.1、3.2；工作区保留目录为 `<workspace>/.chips/` | [10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) |
| 插件包校验输出 | `pnpm exec chips plugin validate <路径或 .cpk>`（与安装完全同源，不落盘） | [03-插件包格式](../04-文件格式规范/03-插件包格式.md) 7.2 |

- `<userData>` 为 Electron 用户数据目录；macOS 对应 `~/Library/Application Support/Chips/`（与配置系统的用户级目录一致）。
- 审计日志 append-only、留存至少 180 天（高/极高风险权限记录至少 365 天）；插件无读写接口，排查时只读打开。
- 未显式配置日志级别时，生效值为平台 schema 默认 `info`；需要更详细输出时调整 `platform.log.level`（`error` / `warn` / `info` / `debug`），见 [10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md) 第 4 节。
- 生产用户问题优先使用审计与平台主日志；调试追踪需显式开启（开关与类别见 [03-调试指南](./03-调试指南.md) 2.2）。

### 2.2 统一日志字段

排查时以下列字段做关联键；同一字段在不同输出中的语义一致：

| 字段 | 含义 | 出现位置 |
|---|---|---|
| `traceId` | 全链路追踪 ID；跨 Bridge、权限审计、事件日志一致 | 审计记录、事件日志、插件日志 |
| `requestId` | 单次能力调用 ID（UUID v4），关联请求与响应、丢弃迟到结果 | Bridge 请求/响应、审计记录 |
| `sessionId` | 插件一次运行实例与窗口渲染进程的绑定；身份与限权单位 | Bridge 会话、审计记录 |
| `pluginId` / `pluginVersion` | 触发插件及版本 | 审计记录、插件日志、事件日志 |
| `frameId` | 帧标识（主框架 routing id），用于区分同一窗口内子框架 | Bridge 会话、帧协议封套 |
| `capabilityId` | 能力调用涉及的审计目标 | 审计记录、Bridge 追踪 |
| `permission` / `qualifier` / `target` | 判定的基础权限、展开后的限定值、本次调用目标 | 审计记录（判定与拒绝） |
| `action` / `actor` / `reason` | 审计动作（`grant` / `revoke` / `deny` / `allow`）、操作者（`user` / `system`）、拒绝原因 | 审计记录 |
| `eventId` / `source` / `publishedAt` / `listenerCount` / `error` | 事件发布与投递的追踪字段 | 事件日志（异步记录） |
| `timestamp` / `level` | ISO 8601 UTC 时间、日志级别 | 审计记录、插件日志 |

审计记录完整字段定义见 [08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 8.2；事件日志字段见 [09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md) 9.4；插件日志自动附加字段见 [10-服务插件接口](../05-接口与契约/10-服务插件接口.md) 3.6。

### 2.3 分析方法

1. **按 `traceId` 串联**：先取首个错误的 `traceId`，在审计日志、事件日志与调试追踪（如已开启）中检索同值记录，还原"能力调用 → 权限判定 → 事件"的完整时间线。
2. **按 `requestId` 定位单次调用**：核对请求是否超时、是否被取消、迟到结果是否被丢弃。
3. **按 `pluginId` 隔离**：只看目标插件的审计、日志与 `plugin:*` 事件，排除其他插件干扰。
4. **按 `sessionId` 还原会话**：会话关闭后全部新调用返回 `BRIDGE_SESSION_UNKNOWN`，在途调用取消、订阅与句柄强制释放。
5. **按事件核对状态迁移**：`plugin:failed`（含 `error`）标识失败；`plugin:enabled` / `plugin:disabled` / `plugin:unloaded` 标识生命周期完成点。

审计日志检索示例（JSON Lines，按 `traceId` 与插件过滤）：

```bash
AUDIT="$HOME/Library/Application Support/Chips/logs/audit/audit-2026-09-19.jsonl"

# 同一 traceId 的全部审计记录
jq -c 'select(.traceId == "t-3b91")' "$AUDIT"

# 某插件的全部拒绝记录（reason 见 4.5 节）
jq -c 'select(.pluginId == "chips.official.editor" and .action == "deny")' "$AUDIT"

# 资源越权拒绝的目标与限定值
jq -c 'select(.resourceUri != null and .action == "deny") | {resourceUri, permission, qualifier, reason}' "$AUDIT"
```

### 2.4 证据采集顺序

```text
错误码与 details（界面/调用方捕获）
      │
      ├──▶ 平台主日志：错误归一、内部告警、诊断详情
      ├──▶ 审计日志：授权、放行、拒绝、资源访问、HTTP 状态
      ├──▶ 插件日志：插件自身处理路径（按 pluginId 过滤）
      ├──▶ 状态投影：插件注册表 state / lastError；渲染会话 state / error
      └──▶ 包校验：chips plugin validate 输出（安装类问题）
```

- 未识别异常统一归一为 `BRIDGE_INTERNAL`，其 `details` 不携带堆栈与内部路径，诊断详情写平台主日志。
- 插件崩溃的诊断信息（错误码、堆栈、插件 ID、版本、阶段、时间）由平台记录，见 [03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 9.2。
