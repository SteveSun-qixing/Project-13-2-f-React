## 七、事件调试

### 7.1 事件追踪字段

`CHIPS_TRACE=event` 开启；字段口径与 [09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md) 第 9.4 节一致：

| 字段 | 含义 |
|---|---|
| `eventId` | 事件 ID，`<domain>:<action>` |
| `source` | 发布者身份：平台组件 ID 或插件 ID |
| `traceId` | 追踪 ID，与 Bridge、审计一致 |
| `publishedAt` | 发布时刻，ISO 8601 UTC |
| `listenerCount` | 本次投递的监听器数量 |
| `error` | 首个监听器错误（成功时省略） |
| `windows` | 跨进程转发命中的窗口计数（0 表示无转发开销） |

### 7.2 主进程事件定位步骤

1. 开启 `CHIPS_TRACE=event`；需要内核派发细节时叠加 `RUST_LOG=chips_cordis=debug`。
2. 复核发布点：插件发布用 `ctx.emit`；保留域事件只由平台发布（[05-事件契约规范](../05-接口与契约/05-事件契约规范.md) 第 2.2 节）。
3. 在追踪中按 `eventId` 过滤，读 `listenerCount`：
   - `listenerCount: 0`：无订阅者，事件被安全丢弃（设计行为）；检查订阅是否挂在插件 Fork 上、是否被提前 `dispose()`。
   - `error` 非空：首个监听器失败；错误被隔离，其余监听器已执行，按发布记录的 `source`/插件 ID 定位该监听器修复。
4. `KERNEL_EVENT_DEPTH_EXCEEDED`：嵌套发布超过 64 层；检查监听器内是否再次发布同链事件（[09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md) 第 2.4 节）。
5. 插件卸载后仍收到事件即生命周期缺陷：监听器必须随 Fork 自动撤销（[09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md) 第 4.2 节）。

### 7.3 渲染进程事件定位步骤

1. 订阅后确认 `event:control` 的 subscribe 计数记录出现；无记录说明 preload 未挂载监听。
2. 订阅未建立时按回执定位：
   - `EVENT_NOT_REGISTERED`：事件未登记；插件自有域事件不跨进程，确需跨进程时先登记为标准事件。
   - `EVENT_SUBSCRIBE_DENIED`：缺少订阅权限或动态可见性不满足。
3. 无投递时检查：窗口订阅计数是否因 `dispose()` 归零、payload 是否可结构化克隆且不超过 256 KiB、事件是否在转发白名单内（`internal:*` 与插件自有域事件不转发）。
4. 渲染侧发布必须经能力 `event:publish`：`EVENT_PUBLISH_DENIED`（保留域或权限）、`EVENT_PAYLOAD_UNSUPPORTED`（不可克隆）、`EVENT_PAYLOAD_TOO_LARGE`（超 256 KiB）。
5. Console 验证片段（订阅 → 复现 → 释放）：

```typescript
interface IDocumentChangedPayload {
  uri: string;
  kind: 'card' | 'box';
}

function isDocumentChangedPayload(payload: unknown): payload is IDocumentChangedPayload {
  if (typeof payload !== 'object' || payload === null) {
    return false;
  }
  const candidate = payload as Record<string, unknown>;
  const kind = candidate.kind;
  return typeof candidate.uri === 'string' && (kind === 'card' || kind === 'box');
}

const subscription = window.chips.subscribe('document:changed', (payload: unknown) => {
  if (isDocumentChangedPayload(payload)) {
    console.warn('document:changed', payload.uri, payload.kind);
  }
});

// 复现操作后释放订阅，避免计数残留
subscription.dispose();
```

### 7.4 投递语义核对

- 全部标准事件为至多一次：无订阅者、窗口销毁、进程崩溃均可能丢失；事件不持久化、不重放（[09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md) 第六章）。
- 跨发布者、跨进程不保证顺序；需要一致性状态时用能力查询（如同步引擎的 `status()`），不得依赖事件序列重建状态。
- 高频事件（如 `sync:progress`）由发布方按最小间隔限流；调试时不得以逐条日志代替状态查询。
