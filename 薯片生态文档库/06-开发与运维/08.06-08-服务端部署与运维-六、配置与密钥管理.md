# 服务端部署与运维

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片生态服务端产品（社区平台服务器、个人服务器）的部署与运维权威规范：环境与拓扑、域名/HTTPS/证书/CSP/CORS、对象存储、容器化与进程管理、配置与密钥管理、备份恢复、日志监控、升级回滚、服务器连接与口令管理、故障清单与自检清单；不覆盖服务端产品的 API 契约、数据模型与业务模块实现。

## 六、配置与密钥管理

### 6.1 配置文件位置与模板

1. 服务端产品的环境文件位置是部署目录下的 `deploy/.env`（由服务端代码显式加载，不扫描仓库根与其他目录）。
2. 仓库内必须维护 `deploy/.env.example`：包含全部变量名、必填标记与占位值；`deploy/.env` 与 `deploy/certs/*` 必须在 `.gitignore` 中排除。
3. 环境变量变更必须走发布流程并记录；禁止在部署主机上直接编辑 `.env` 后不登记。
4. `.env` 文件权限为 `600`，属主为部署用户；禁止 world-readable。

### 6.2 环境变量契约

共享变量（两个服务端产品一致）：

| 变量 | 必填 | 说明 | 机密 |
|---|---|---|---|
| `NODE_ENV` | 是 | 生产固定 `production`；控制 Cookie `secure` 与错误输出 | 否 |
| `BASE_URL` | 是 | 主站入口，精确匹配部署域名（§3.1） | 否 |
| `PORT` / `HOST` | 否 | API 监听，默认 `3000` / `0.0.0.0` | 否 |
| `DATABASE_URL` | 是 | PostgreSQL 连接串；生产必须使用强密码 | 是 |
| `S3_ENDPOINT` | 是 | S3 兼容通用端点 | 否 |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | 是 | 对象存储凭据 | 是 |
| `S3_REGION` | 否 | 区域，默认 `us-east-1` | 否 |
| `S3_FORCE_PATH_STYLE` | 否 | 本地 MinIO 为 `true`；外部存储按服务商要求 | 否 |
| `S3_PUBLIC_URL` | 生产必填 | 资源入口前缀 | 否 |
| `S3_BUCKET_NAME` | 否 | 单物理桶模式的公开物理桶名 | 否 |
| `CORS_EXTRA_ORIGINS` | 否 | 追加 CORS 来源，逗号分隔 | 否 |
| `MAX_CARD_SIZE_MB` / `MAX_BOX_SIZE_MB` | 否 | 上传大小上限，需与 Nginx 上限匹配 | 否 |
| `UPLOAD_SESSION_TTL_MINUTES` | 否 | 上传会话有效期，默认 `60` | 否 |
| `ENABLE_SWAGGER` | 否 | 生产建议关闭 | 否 |

产品专属变量：

| 变量 | 产品 | 说明 | 机密 |
|---|---|---|---|
| `JWT_SECRET` | 社区 | 至少 32 字符 | 是 |
| `JWT_ACCESS_EXPIRES_IN` / `JWT_REFRESH_EXPIRES_IN` | 社区 | 令牌有效期 | 否 |
| `REDIS_URL` | 社区 | Redis 连接串 | 否 |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 社区 | 首次启动初始化管理员；初始化完成后从环境移除或轮换 | 是 |
| `CARD_RENDER_WORKER_CONCURRENCY` | 社区 | Worker 消费并发，默认 `1` | 否 |
| `CARD_RENDER_JOB_MAX_ATTEMPTS` | 社区 | 渲染任务最大尝试次数，默认 `2` | 否 |
| `CARD_RENDER_QUEUE_POLL_TIMEOUT_SEC` | 社区 | 队列阻塞超时，默认 `5` | 否 |
| `CARD_RENDER_CACHE_UPLOAD_CONCURRENCY` | 社区 | 缓存上传并发，默认 `8` | 否 |
| `CARD_RENDER_CACHE_TTL_DAYS` | 社区 | 缓存保留天数，默认 `30` | 否 |
| `CARD_RENDERER_VERSION` | 社区 | 渲染缓存版本键；渲染产物变化必须递增 | 否 |
| `S3_RUNTIME_ENDPOINT` | 社区 | Compose 运行态覆盖 `S3_ENDPOINT`；外部存储时与 `S3_ENDPOINT` 一致 | 否 |
| `HOST_ACTIVE_THEME_ID` / `HOST_*_PLUGIN_PATHS` | 社区 | 服务端渲染集成的主题与插件路径 | 否 |
| `API_TOKEN` | 个人 | 写接口管理令牌，至少 16 字符 | 是 |
| `POSTGRES_PASSWORD` | 个人 | 生产 Compose 的数据库密码 | 是 |

1. 本表是共享变量的权威位置；产品专属变量的完整清单以对应服务端仓库的启动说明为准。
2. Compose 中禁止硬编码生产密码与连接串：基础设施密码、数据库连接串必须来自 `.env` 变量注入。

### 6.3 密钥与口令规则

1. 所有生产密钥与口令随机生成，长度下限：`JWT_SECRET` >= 32、`API_TOKEN` >= 16、数据库与对象存储凭据 >= 16；禁止使用可记忆短语、默认值与示例值。
2. 禁止行为：写入 Git、写入镜像、写入文档、写入聊天记录、写入日志与命令历史、出现在 URL 与前端代码中。
3. 环境隔离：本地、生产使用不同凭据；生产凭据不得下发到个人设备。
4. 最小权限：数据库账号只拥有所属产品的库权限；对象存储凭据按 §4.6 收敛。
5. 密钥只保存在部署主机 `.env`、密码管理器与发布密钥库（签名类）三处；任何其他副本立即删除。
6. 口令与密钥的持有者清单由运维维护，人员变动时同步回收（§10.7）。

### 6.4 轮换与泄露处置

| 事件 | 动作 |
|---|---|
| 疑似泄露（出现在对话、日志、截图、第三方系统） | 立即轮换对应凭据，轮换后复查日志与访问记录 |
| 运维人员变动 | 回收其凭据与管理账号，轮换其接触过的共享口令 |
| 服务商要求或年度周期 | 按到期计划轮换对象存储与数据库凭据 |
| 证书到期 | 按 §9.4 续期 |

轮换步骤：

1. 生成新凭据并在服务端产品侧生效（对象存储凭据在控制台新建、数据库改密）。
2. 更新部署主机 `.env`，重建受影响容器：`docker compose up -d --build server worker`。
3. 执行健康检查与最小写入验证（上传、读取各一例）。
4. 撤销旧凭据，确认无残留调用后销毁旧值。
5. 轮换过程与结果写入发布/运维记录，不记录凭据值。
