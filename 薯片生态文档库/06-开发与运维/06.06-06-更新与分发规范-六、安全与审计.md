> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片平台更新与分发的权威规范：平台更新（更新源与渠道、更新包签名链与信任根、版本比较与防降级、原子替换与失败恢复、灰度与暂缓、离线更新包、重启边界）、插件分发（`.cpk` 来源、市场协议契约、`engines.chips` 兼容门禁、安装包与内置插件首启引导）、版本回退声明、与构建/CICD 的衔接、供应链安全与审计、约束与自检清单。

## 六、安全与审计

### 6.1 供应链安全

| 环节 | 要求 |
|---|---|
| 来源白名单 | 平台更新源与市场端点在编译期或用户显式配置中固定；不跟随任意重定向与第三方地址 |
| 传输 | 仅 HTTPS；TLS 证书校验始终开启；不做"忽略证书"开关 |
| 摘要 | 更新包与 `.cpk` 都必须以本地重算摘要参与校验（§2.2 第 3 条、§3.2 第 1 条） |
| 签名 | 更新包与 `.cpk` 共用 Ed25519 信任根体系；未登记 `keyId` 视为签名无效 |
| 代码签名 | macOS / Windows 产物必须通过平台代码签名与公证；签名覆盖原生模块（`.node`） |
| 密钥 | 私钥只存在于发布密钥库与受保护 CI 环境；禁止入库、禁止进入日志与日志参数；轮换与撤销按 §2.2 第 7 条 |
| 依赖 | 引入新依赖遵循技术选型标准与依赖审计（[05-CICD与质量门禁](../06-开发与运维/05-CICD与质量门禁.md) 安全门禁） |
| 防篡改 | 更新索引被篡改时，实际字节重算的 `contentHash` 与签名不匹配，更新被拒绝；索引不参与信任 |

### 6.2 失败处理与审计

1. 更新与分发的关键动作全部写入审计：检查、下载、校验结果、替换、启动自检、失败恢复、渠道切换、离线安装、插件安装/更新/卸载结果。
2. 审计字段至少包含：时间、动作、目标（平台版本或插件 ID + 版本）、渠道、来源、`keyId`、摘要、结果、失败原因码；不含凭证、私钥与用户文件内容（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) §八）。
3. 安全事件（`UPDATE_PACKAGE_INVALID`、签名无效、信任根未登记）必须记录诊断并在界面提示用户；平台不上传用户数据，只允许用户主动导出诊断。
4. 失败不静默：更新失败、插件安装失败、市场不可达都必须产生可见的中文提示与排查入口（[04-故障排查手册](./04-故障排查手册.md)）。
5. 发布记录构成追溯链：从渠道产物可回溯到提交、门禁报告、签名与 `keyId`（[05-CICD与质量门禁](../06-开发与运维/05-CICD与质量门禁.md) §5.5）。
