# 服务端部署与运维

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片生态服务端产品（社区平台服务器、个人服务器）的部署与运维权威规范：环境与拓扑、域名/HTTPS/证书/CSP/CORS、对象存储、容器化与进程管理、配置与密钥管理、备份恢复、日志监控、升级回滚、服务器连接与口令管理、故障清单与自检清单；不覆盖服务端产品的 API 契约、数据模型与业务模块实现。

## 八、日志与监控

### 8.1 日志来源与保留

| 来源 | 位置 | 内容 |
|---|---|---|
| API | 容器标准输出（Compose 日志） | 请求、迁移、桶初始化、错误堆栈 |
| Worker | 容器标准输出 | 队列消费、渲染结果、缓存清理 |
| Nginx | 容器内 `/var/log/nginx/` | 访问日志、错误日志 |
| PostgreSQL / Redis / MinIO | 容器标准输出 | 数据库、缓存与存储的运行日志 |

规则：

1. 生产容器必须配置日志轮转（`json-file` 驱动的 `max-size` 与 `max-file`），未配置轮转视为部署未完成；单容器日志保留不少于 7 天。
2. 日志禁止输出凭据、令牌、Cookie、对象存储密钥与用户文件内容；错误日志只输出错误码、摘要与 `traceId`（平台侧字段口径见[04-故障排查手册](./04-故障排查手册.md)）。
3. 排查时按容器与时间窗取日志：

```bash
docker compose logs --tail=200 server
docker compose logs --since 30m worker
docker compose logs --tail=100 nginx
```

### 8.2 健康检查

| 对象 | 方法 | 频率 |
|---|---|---|
| 容器存活 | `docker compose ps` 状态与健康检查结果 | 每分钟 |
| API | `GET https://<主站入口>/api/v1/health` | 每分钟 |
| 前端 | `GET https://<主站入口>/` 与 `/admin/` 状态码 | 每 5 分钟 |
| Worker | 容器运行 + 最近日志时间 + 队列积压 | 每 5 分钟 |
| PostgreSQL / Redis | 容器健康检查 | 每分钟 |
| 对象存储 | 公开桶 HEAD + 一次小对象读 | 每 15 分钟 |
| 证书 | 资源入口与主站入口证书剩余有效期 | 每天 |

### 8.3 监控项与阈值

| 指标 | 阈值 | 处置 |
|---|---|---|
| 容器未运行或反复重启 | 任意一次 | 查容器日志；按 §12 定位 |
| 健康检查连续失败 | 2 次 | 触发告警；只读模式保留 Nginx 静态页，不自动重启全部服务 |
| 磁盘使用率 | 80% 告警 / 90% 严重 | 清理构建缓存与过期日志；扩容磁盘 |
| 证书剩余有效期 | 30 天提醒 / 7 天严重 | 按 §9.4 续期 |
| 渲染队列积压 | 持续增长 30 分钟 | 检查 Worker 与对象存储；必要时提升并发 |
| 渲染任务失败率 | 近 1 小时有失败 | 查 `card_render_jobs` 与 Worker 日志 |
| 缓存错误记录 | 出现 `error` 状态 | 检查源文件与渲染链路 |
| PostgreSQL 连接数 | 接近 `max_connections` | 排查连接泄漏；评估主机规格 |
| 上传失败率 | 突增 | 检查对象存储凭据、桶策略与 Nginx 上传上限 |

### 8.4 告警与响应

1. 告警通道由运维统一配置（即时通讯或邮件），告警必须包含对象、时间、指标值与定位命令。
2. 收到告警后按 §12 处置；处置完成后记录原因与动作。
3. 监控数据与告警内容不得包含凭据与用户内容；只允许携带主机、容器、错误码与时间。
