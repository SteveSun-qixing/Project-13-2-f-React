## 二、调用约定

### 2.1 语法与全局选项

```text
chips  [全局选项] <命令> [子命令] [参数] [选项]
chips dev [全局选项] <子命令> [参数] [选项]
```

| 全局选项 | 形式 | 含义 |
|---|---|---|
| `--json` | 开关 | 强制机器可读 JSON 输出；对人读模式命令生效，对默认 JSON 的内建命令无变化 |
| `--plugin <pluginId>` | 取值 | 限定插件命令的 owner；命令路径冲突时用于消解（§5.5） |
| `--workspace <路径>` | 取值 | 指定开发工作区；仅 `chips dev` 接受（§2.2） |
| `--help` | 开关 | 输出当前命令的帮助并退出 0；等价于 `chips help <命令>` |
| `--version` | 开关 | 输出 `chips` 版本与平台版本并退出 0 |
| `--yes` | 开关 | 跳过交互确认（未签名插件安装等）；非交互环境缺少该开关时返回 `CLI_ARGUMENT_INVALID`，不挂起等待 |
| `--` | 分隔符 | 终止选项解析，其后 token 一律按位置参数处理 |

规则：

- 全局选项可出现在命令路径前后任意位置；解析时被剥离，**不进入**插件 payload。
- 未知选项、缺失取值、重复传入单值选项一律返回 `CLI_ARGUMENT_INVALID`（退出码 2）。
- 选项支持 `--name value`、`--name=value` 与短名 `-s value`、`-s=value`；布尔选项以出现为真，可用 `--name=false` 显式置假。
- 位置参数顺序由声明中的 `position` 决定，与选项穿插书写无关。

### 2.2 工作区选择

| 入口 | 解析顺序 | 说明 |
|---|---|---|
| `chips` | 用户工作区绑定值 | 由平台设置面板选择；默认 `${userDocuments}/Chips`；CLI 不提供切换参数 |
| `chips dev` | `--workspace` → `CHIPS_WORKSPACE` → `${userData}/dev/workspace` | 目录不存在时按工作区初始化规则创建；仅开发构建接受（[13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §7.1） |

- 用户侧传 `--workspace` 返回 `CLI_ARGUMENT_INVALID`，`details.hint` 指向设置面板。
- 开发工作区与用户工作区互不写入：开发侧命令不得读取或修改用户工作区内的文档、配置与插件记录（[13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §7.4）。
- 同一目录不得被两个运行实例同时绑定；实例锁冲突返回工作区错误码并保持原状（[13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §2.4）。

### 2.3 固定命令根与插件命令路径

固定命令根（插件命令路径第一段**不得**命中，大小写不敏感）：

```text
help   start   stop   status   config   logs   plugin   update   doctor   open   completion   dev
```

- `host` 为历史二级入口名，一并保留在禁止集合中，防止插件重新占用造成用户混淆；`chips host ...` 返回 `CLI_COMMAND_NOT_FOUND`（退出码 3）。
- `theme` 不再保留：主题系统已废弃，`chips theme ...` 与插件 `theme` 命令路径均为非法。
- 命令路径段文法：`^[a-z0-9][a-z0-9-]*$/i`；路径至少一段。命中固定根或不符合文法的声明由本文 §5.1 判定，随清单校验阶段在打包与安装时拒绝（校验阶段见 [03-插件包格式](../04-文件格式规范/03-插件包格式.md) §五）。
- 执行时按**最长命令路径前缀**匹配已启用插件命令；剩余 token 按声明解析。无匹配时返回 `CLI_COMMAND_NOT_FOUND`（退出码 3）。
- 同一命令路径存在多个已启用匹配时返回 `CLI_COMMAND_CONFLICT`（退出码 3），可用 `--plugin <pluginId>` 消解。

### 2.4 输出约定

1. **stdout 只承载最终结果**：成功时输出单个 JSON 对象/数组，或按 `output.mode: human` 输出摘要文本；进度、阶段、日志与提示一律写 stderr，禁止污染 stdout。
2. **内建命令默认 JSON**：`status`、`config list`、`plugin list` 等内建命令默认输出 JSON，`--json` 不改变其形状。
3. **插件命令默认 JSON**：未声明 `output.mode` 时按 JSON；声明 `human` 时输出人读摘要，用户传 `--json` 强制 JSON（§5.4）。
4. **错误始终结构化**：任何模式下失败时 stdout 输出单个错误对象（§2.6），错误对象不随 `output.mode` 或 `--json` 变化。
5. **结果信封**（插件命令成功时）：

```json
{
  "ok": true,
  "entryId": "chips.official.office.cli.office.open",
  "commandPath": "office open",
  "commandId": "office:open",
  "target": { "type": "app", "pluginId": "chips.official.office" },
  "output": { "files": ["/Users/chips/文档/报告.docx"] },
  "task": { "taskId": "…", "status": "completed" },
  "artifacts": ["/Users/chips/文档/报告.docx"],
  "skipped": false
}
```

- `commandId` 仅 `app` 目标出现（运行时命令 ID）；`service` 目标不含 `commandId`。
- `output`、`task`、`artifacts`、`skipped` 按命令声明与执行结果出现；`skipped: true` 表示输出冲突策略为 `skip` 时未调用目标（§5.2）。
- human 摘要固定为“完成 / 命令 / 目标 / 任务 / 产物 / 输出”六段式，只展示声明 `output.artifacts` 命中的路径与通用 `output` 摘要，不得猜测插件私有字段语义。

### 2.5 退出码

| 退出码 | 含义 | 典型错误码 |
|---|---|---|
| 0 | 成功；含幂等空操作（重复 `stop`、`doctor` 无异常等） | — |
| 1 | 一般失败：命令业务失败或内部错误 | `CLI_COMMAND_FAILED`、`CPK_*`、`CONFIG_*`、`UPDATE_*`、`PLUGIN_*` |
| 2 | 用法或参数错误 | `CLI_ARGUMENT_INVALID`、`CLI_COMMAND_QUERY_INVALID` |
| 3 | 命令不存在或冲突 | `CLI_COMMAND_NOT_FOUND`、`CLI_COMMAND_CONFLICT` |
| 4 | 权限拒绝 | `CLI_PERMISSION_DENIED`、`PLUGIN_PERMISSION_DENIED`、`BRIDGE_PERMISSION_DENIED` |
| 5 | 路径、输出或批量校验失败 | `CLI_PATH_*`、`CLI_OUTPUT_*`、`CLI_BATCH_INVALID`、`FILE_ASSOCIATION_TARGET_INVALID` |
| 6 | 目标不可用 | `PLUGIN_NOT_FOUND`、`PLUGIN_DISABLED`、`CLI_TARGET_UNAVAILABLE`、`BRIDGE_CAPABILITY_NOT_FOUND` |
| 7 | 任务失败终态 | `CLI_TASK_FAILED` |
| 8 | 任务取消终态 | `CLI_TASK_CANCELLED` |
| 9 | 等待超时 | `CLI_TIMEOUT`、`BRIDGE_TIMEOUT` |
| 130 | 用户中断且命令未声明取消策略（`Ctrl+C`），按平台默认中断 | — |

- 脚本必须以退出码与 `code` 判定结果，禁止匹配 `message` 文案。
- 声明 `job.cancelOnInterrupt: true` 的命令在 `Ctrl+C` 时先请求取消，等待取消终态后按退出码 8 结束；未声明的命令不进入取消链路，直接中断（退出码 130）。

### 2.6 错误格式

失败时 stdout 输出：

```json
{
  "error": "输出目录已存在：/Users/chips/out",
  "code": "CLI_OUTPUT_EXISTS",
  "details": { "path": "/Users/chips/out", "policy": "fail" },
  "retryable": false
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `error` | `string` | 简体中文信息；面向用户，不作为判定依据 |
| `code` | `string` | 唯一判定依据；取值见下表与各领域权威文档 |
| `details` | `unknown?` | 结构化诊断：涉及参数、路径、命令 ID、任务、冲突组等 |
| `retryable` | `boolean?` | 拷贝自 `ChipsError.retryable`；`true` 表示重试同一操作可能成功 |

CLI 自有错误码（`cli-command` / `cli-task` 契约登记）：

| 错误码 | 含义 | 退出码 |
|---|---|---|
| `CLI_ARGUMENT_INVALID` | 参数缺失、类型不匹配、未知选项、取值越界 | 2 |
| `CLI_COMMAND_QUERY_INVALID` | 发现查询缺少 `entryId` / `commandPath` 或字段非法 | 2 |
| `CLI_COMMAND_NOT_FOUND` | 无匹配命令路径 | 3 |
| `CLI_COMMAND_CONFLICT` | 同一路径存在多个已启用匹配且无法消解 | 3 |
| `CLI_PERMISSION_DENIED` | 命令声明权限缺失或当前授权快照不满足 | 4 |
| `CLI_PATH_NOT_FOUND` | 声明 `exists: true` 的路径不存在 | 5 |
| `CLI_PATH_INVALID` | 路径类型、扩展名或创建规则不满足 | 5 |
| `CLI_OUTPUT_EXISTS` | 输出路径已存在且策略为 `fail` | 5 |
| `CLI_OUTPUT_RENAME_EXHAUSTED` | `rename` 策略找不到可用名称 | 5 |
| `CLI_BATCH_INVALID` | 批量输入格式或逐项校验失败 | 5 |
| `CLI_TARGET_UNAVAILABLE` | 目标不可用：承载环境缺失、目标类型不受支持 | 6 |
| `CLI_TASK_INVALID` | 任务创建 / 上报请求字段非法 | 1 |
| `CLI_TASK_NOT_FOUND` | 任务 ID 不存在 | 1 |
| `CLI_TASK_FAILED` | 应用报告任务失败终态 | 7 |
| `CLI_TASK_CANCELLED` | 应用报告任务取消终态，或取消请求成功 | 8 |
| `CLI_TIMEOUT` | 等待任务或承载链路超过约定时限 | 9 |
| `CLI_COMMAND_FAILED` | 未归类的 CLI 失败 | 1 |

其他领域错误码按其权威文档产生并保留原样（插件包 `CPK_*`、配置 `CONFIG_*`、更新 `UPDATE_*`、插件生命周期 `PLUGIN_*`、Bridge `BRIDGE_*`），CLI 只负责映射退出码（§2.5）。

### 2.7 环境变量

| 变量 | 作用域 | 含义 |
|---|---|---|
| `CHIPS_WORKSPACE` | `chips dev` | 开发工作区路径；被 `--workspace` 覆盖 |
| `CHIPS_LOG_LEVEL` | 全入口 | 平台日志级别（`error` / `warn` / `info` / `debug`），随承载进程生效 |
| `CHIPS_TRACE` | 全入口 | 调试追踪类别（如 `bridge,event`），随承载进程生效（[03-调试指南](./03-调试指南.md) §2.2） |
| `CHIPS_CLI_JOB_PROGRESS` | 全入口 | 置 `1` 时，非交互环境也把任务进度按行写 stderr |
| `CHIPS_SIGNING_KEY_FILE` | `chips plugin pack --sign` | Ed25519 私钥文件路径；私钥不得出现在命令行参数、环境变量明文与日志中（[02-构建与打包](./02-构建与打包.md) §7.3） |
| `CHIPS_TRUST_ROOTS_FILE` | `chips plugin validate` | 信任注册文件路径（开发/验证期信任根唯一正式命令面注入通道，[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §6.3）；文件形状 `{ "version": 1, "description"?: string, "trustRoots": { "<keyId>": "<SPKI PEM 公钥>" } }`（严格 schema：未知字段拒绝、`version` 必须为数值 1）；文件不存在返回 `CLI_PATH_NOT_FOUND`（退出码 5）、路径非文件返回 `CLI_PATH_INVALID`（5）、JSON 或 schema 非法返回 `CLI_ARGUMENT_INVALID`（2）；空串按未设置处理；公钥内容不落命令行与日志 |

### 2.8 操作日志与脱敏

1. CLI、TUI 与 shell 补全的每次操作都写工作区日志：`namespace: "cli"`、`action: "operation.execute"`，`metadata.source` 取 `cli` / `tui` / `completion`。
2. 记录字段：脱敏后的命令行与 token、工作区摘要、退出码、命令 ID、命令路径、目标类型、耗时、错误码与错误对象；一次用户操作只产生一条主记录，插件命令失败保留插件上下文记录，不追加无上下文的顶层失败记录。
3. 脱敏键名至少覆盖 `token`、`secret`、`password`、`credential`、`apiKey`（大小写与 `-`/`_` 变体归一）；`--名=值` 与紧随其后的取值都替换为 `<redacted>`。
4. 签名私钥只经受保护的文件路径注入，禁止打印、禁止写入日志、禁止拼进命令行。
