## 三、域名、HTTPS 与响应头

### 3.1 域名拓扑与 `BASE_URL`

| 域名 | 职责 |
|---|---|
| `www.chipscard.space` | 主站入口：社区前台、管理后台、API 全部同源 |
| `chipscard.space` | 301 跳转到主站入口（HTTP 与 HTTPS 都跳转） |
| `file.chipscard.space` | 资源入口：对象存储公开资源（渲染缓存、封面、头像、卡片内嵌资源） |
| `file.<个人服务器域名>` | 个人服务器的资源入口（与对象存储/CDN 绑定） |

规则：

1. `BASE_URL` 必须与主站入口完全一致（协议、主机名都精确一致），不得带路径、不得带末尾斜杠。
2. 前台与后台只按同源路径访问 `/api/` 与 `/admin/api/`，生产环境不得跨源直连 API。
3. 主站入口与资源入口必须是不同的域名：资源流量由对象存储/CDN 承担，主站 Nginx 不代理资源字节。
4. 旧 `/cdn/` 入口保留 301 跳转到资源入口，用于收敛历史链接；新链接一律直接使用资源入口。

### 3.2 证书

1. 证书文件放在部署目录的 `deploy/certs/` 下，Nginx 容器只读挂载；文件名固定为 `<主域名>_ca.crt` 与 `<主域名>.key`。
2. 证书必须覆盖证书链（`fullchain`），覆盖域名包括裸域与主站入口域名；资源入口域名在对象存储/CDN 侧单独绑定证书。
3. 证书与私钥**禁止入库**：`deploy/certs/*` 必须在 `.gitignore` 中排除；私钥只存在于部署主机与证书签发/续期系统。
4. TLS 基线：只允许 TLS 1.2 与 TLS 1.3；开启会话缓存；不启用过时套件。
5. 续期后必须执行 `nginx -t` 校验并 reload：`docker compose exec nginx nginx -t && docker compose exec nginx nginx -s reload`。
6. 证书到期监控与告警阈值见 §8.3。

### 3.3 安全响应头与 CSP

Nginx 对主站入口的 HTTPS `server` 块必须输出以下响应头（当前已实现前四项）：

| 响应头 | 值 | 状态 |
|---|---|---|
| `X-Frame-Options` | `SAMEORIGIN` | 已实现 |
| `X-Content-Type-Options` | `nosniff` | 已实现 |
| `X-XSS-Protection` | `1; mode=block` | 已实现 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | 已实现 |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | 要求新增（§11 偏差项） |
| `Content-Security-Policy` | 见下 | 要求新增（§11 偏差项） |

CSP 要求（服务端产品的前台与后台 HTML）：

```text
default-src 'self';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data: https://<资源入口域名>;
media-src 'self' https://<资源入口域名>;
frame-src 'self' https://<资源入口域名>;
connect-src 'self' https://<资源入口域名>;
font-src 'self' data: https://<资源入口域名>;
object-src 'none';
base-uri 'self';
frame-ancestors 'self';
```

1. `style-src` 允许 `'unsafe-inline'` 的唯一原因是官方前端技术栈的组件库在运行时注入样式（[ADR-008](../01-架构设计/ADR/ADR-008-React加fork-antd前端技术栈.md)）；除样式外不得放宽任何指令，禁止 `script-src 'unsafe-inline'`、禁止 `default-src *`。
2. CSP 只允许 `'self'` 与资源入口域名；不得为第三方统计、字体 CDN 等新增白名单。
3. 平台客户端（Electron 渲染进程）的 CSP 由[ADR-002](../01-架构设计/ADR/ADR-002-Electron作为桌面端壳.md)定义，本文件不重复；服务端产品的 CSP 只约束浏览器访问的 HTML。
4. API 响应不设置 CSP；API 的安全响应头由应用框架输出（`crossOriginResourcePolicy: cross-origin`，用于卡片封面与渲染产物被 Host 窗口跨源引用）。

### 3.4 CORS

生产 CORS 白名单（由服务端产品统一实现）：

| 来源 | 说明 |
|---|---|
| `BASE_URL` | 同源浏览器访问 |
| `chips-render:*` | 平台客户端的渲染窗口来源（`chips-render://` 协议） |
| `null` | 沙箱化 iframe 与本地文件上下文 |
| `CORS_EXTRA_ORIGINS` 白名单 | 逗号分隔的显式追加来源，仅在确需第三方调用时填写 |

规则：

1. 开发模式允许 `localhost` 任意端口；生产模式只允许上表来源，其他来源一律拒绝。
2. `credentials` 只允许 `true`；禁止使用 `Access-Control-Allow-Origin: *` 配合凭据。
3. 允许方法固定为 `GET`、`POST`、`PUT`、`PATCH`、`DELETE`、`OPTIONS`。
4. `CORS_EXTRA_ORIGINS` 为空是默认状态；每新增一个来源都要在部署记录中登记原因与有效期。
5. CORS 失败在浏览器侧表现为跨源错误，排查路径见 §12。

### 3.5 会话 Cookie

社区平台服务器的刷新令牌 Cookie 参数固定：

| 参数 | 值 |
|---|---|
| `httpOnly` | `true` |
| `secure` | `NODE_ENV === 'production'` |
| `sameSite` | `strict` |
| `path` | `/api/v1/auth` |
| `maxAge` | 与刷新令牌有效期一致 |

1. 生产必须使用 HTTPS，否则 `secure` Cookie 不会被浏览器保存；HTTP 一律 301 到 HTTPS。
2. `sameSite: strict` 要求前台、后台与 API 严格同源：这是 §3.1 `BASE_URL` 精确一致的直接原因。
3. 个人服务器使用令牌认证（`POST /api/v1/auth/login`，见 API 契约所在仓库）时，`API_TOKEN` 只允许通过 HTTPS 传输，不得写入前端代码或 URL。

### 3.6 反向代理与缓存

| 路径 | 上游 | 缓存头 |
|---|---|---|
| `/assets/` | `web:80` | 隐藏上游头，强制 `public, max-age=31536000, immutable` |
| `/admin/assets/` | `admin:80` | 同上 |
| `/` | `web:80` | `no-cache`（SPA HTML） |
| `/admin/` | `admin:80` | `no-cache`（SPA HTML） |
| `/api/`、`/admin/api/` | `server:3000` | 不写静态缓存头 |
| `/cdn/` | 301 到资源入口 | — |

1. `/assets/` 只承载带构建哈希的静态资源；任何未哈希资源不得放在该路径。
2. 代理必须传递 `Host`、`X-Real-IP`、`X-Forwarded-For`、`X-Forwarded-Proto`；服务端开启 `trustProxy`。
3. 上传请求经过 Nginx 时必须有 `client_max_body_size`（社区平台当前为 `520M`，与上传上限匹配）；使用直传对象存储（presign）的链路不经过该限制。
4. 资源入口必须保留 `Range` / `206` 分段读取能力，否则音视频在浏览器中无法播放。
