## 四、Rust 核心编译与 Neon 绑定

### 4.1 workspace 与 release profile

仓库根 `Cargo.toml`（成员与 workspace 依赖与[01-代码组织规范](../02-开发规范/01-代码组织规范.md) §8.3 一致，此处展开编译相关项）：

```toml
[workspace]
members = ["packages/core-rust/crates/*"]
resolver = "2"

[workspace.package]
version = "0.1.0"
edition = "2021"
rust-version = "1.75"
license = "MIT OR Apache-2.0"

[workspace.dependencies]
serde = { version = "1", features = ["derive"] }
serde_yaml = "0.9"
serde_json = "1"
thiserror = "1"
neon = "1"
tokio = { version = "1", features = ["full"] }

[profile.release]
opt-level = 3
lto = true
codegen-units = 1
```

规则：

- `[profile.release]` 只在 workspace 根生效；crate 内声明 `[profile.*]` 会被 Cargo 忽略，禁止重复声明。
- release profile 固定为 `opt-level = 3`、`lto = true`、`codegen-units = 1`（[Rust 编码规范](../02-开发规范/04-Rust编码规范.md) §1.1）。
- 子系统 crate 只依赖 `chips-core`，`chips-native` 组合全部子 crate（[01-代码组织规范](../02-开发规范/01-代码组织规范.md) §3.1）。
- 基准测试（`benches/`）与测试夹具不得进入发布产物。

发布构建前的固定门禁：

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo test --workspace --doc
cargo build --workspace --release
```

### 4.2 Neon 绑定 crate

`packages/core-rust/crates/chips-native/Cargo.toml`：

```toml
[package]
name = "chips-native"
version.workspace = true
edition.workspace = true
rust-version.workspace = true
license.workspace = true

[lib]
crate-type = ["cdylib"]

[dependencies]
chips-core = { path = "../chips-core" }
chips-cordis = { path = "../chips-cordis" }
chips-bridge = { path = "../chips-bridge" }
chips-parser = { path = "../chips-parser" }
chips-resource = { path = "../chips-resource" }
neon.workspace = true

[build-dependencies]
neon-build = "1"
```

`build.rs`：

```rust
fn main() {
    neon_build::setup();
}
```

规则：

- Neon 基于 Node-API，ABI 稳定：**不执行 `electron-rebuild`**，Electron 打包配置固定 `npmRebuild: false`。
- 绑定产物必须导出 `coreAbiVersion`（对应 `CORE_ABI_VERSION`）；导出面与 ABI 版本规则见[03-核心接口规范](../05-接口与契约/03-核心接口规范.md) §8.2，打包前由契约测试核对。
- 绑定层只做类型转换与错误映射，不承载业务逻辑（[Rust 编码规范](../02-开发规范/04-Rust编码规范.md) §14）。
- 绑定产物按平台编译，禁止把某一平台产物复制到另一平台发布。

### 4.3 绑定产物复制

Cargo 输出名与平台相关：macOS `libchips_native.dylib`、Linux `libchips_native.so`、Windows `chips_native.dll`。构建脚本必须复制并重命名为 `chips-native.node`：

```javascript
// tools/scripts/copy-native.mjs
import { copyFile, mkdir } from 'node:fs/promises';
import { existsSync } from 'node:fs';
import { dirname, join } from 'node:path';
import { fileURLToPath } from 'node:url';

const root = join(dirname(fileURLToPath(import.meta.url)), '..', '..');

const artifactByPlatform = {
  darwin: 'libchips_native.dylib',
  linux: 'libchips_native.so',
  win32: 'chips_native.dll',
};

const artifact = artifactByPlatform[process.platform];
if (artifact === undefined) {
  throw new Error(`不支持的构建平台: ${process.platform}`);
}

const source = join(root, 'target', 'release', artifact);
if (!existsSync(source)) {
  throw new Error(`未找到 Neon 产物: ${source}；请先执行 cargo build --workspace --release`);
}

const target = join(root, 'packages', 'host-electron', 'native', 'chips-native.node');
await mkdir(dirname(target), { recursive: true });
await copyFile(source, target);
console.log(`Neon 绑定已复制: ${target}`);
```

`@chips/host` 的 `build` 脚本第一步调用该脚本（`node ../../tools/scripts/copy-native.mjs`），保证全量构建与定向构建都能先得到绑定产物。

### 4.4 平台矩阵与交叉编译

| 平台 | Rust 目标三元组 | 产物 | 说明 |
|---|---|---|---|
| macOS arm64 | `aarch64-apple-darwin` | `libchips_native.dylib` | 主发布架构 |
| macOS x64 | `x86_64-apple-darwin` | `libchips_native.dylib` | 独立安装包，不产出 universal |
| Windows x64 | `x86_64-pc-windows-msvc` | `chips_native.dll` | MSVC 工具链 |
| Windows arm64 | `aarch64-pc-windows-msvc` | `chips_native.dll` | 独立安装包 |
| Linux x64 | `x86_64-unknown-linux-gnu` | `libchips_native.so` | Phase 4 验证（R6） |

- macOS x64 目标可在 arm64 机器上交叉编译；Windows 目标交叉编译必须使用对应 MSVC 工具链。
- 发布安装包必须在目标平台或其原生 CI runner 上构建；交叉编译产物不得直接发布，必须经目标平台测试与冒烟。
- 平台优先级遵循 R6：macOS / Windows 优先，随后 Linux 完成桌面三端（Phase 4 验证）；Android / iOS 为 Phase 5 预留，不在本文产物范围。

产物核验命令：

```bash
# macOS
file packages/host-electron/native/chips-native.node
otool -hv packages/host-electron/native/chips-native.node        # 核对 cputype: ARM64 / X86_64
# Linux
file packages/host-electron/native/chips-native.node
readelf -h packages/host-electron/native/chips-native.node
# Windows（Developer Command Prompt）
dumpbin /headers packages\host-electron\native\chips-native.node
```
