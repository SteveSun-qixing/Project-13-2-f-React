## 十、服务器连接与口令管理

### 10.1 连接方式

1. 服务器连接只允许 SSH 公钥认证；不允许口令登录作为常规入口。
2. 本机通过 `~/.ssh/config` 为每台服务器配置稳定 Host 别名，命名约定 `<产品>-<环境>`，例如 `chipscard-server`、`chipscard-personal-server`。
3. 别名只表示连接目标，**不得**在文档、脚本与日志中记录真实 IP、登录账号、私钥内容与任何口令；具体地址由运维在本地配置中维护。
4. 典型用法：

```bash
ssh <别名>                      # 交互登录
ssh <别名> 'hostname; date -u'  # 执行单条远程命令
scp <本机文件> <别名>:<目标路径>  # 单文件同步
rsync -avz <本机目录>/ <别名>:<目标目录>/  # 目录同步
```

### 10.2 本机 SSH 配置

模板（写入 `~/.ssh/config`，地址与密钥路径由运维填写）：

```sshconfig
Host <别名>
    HostName <部署主机地址>
    Port <SSH 端口>
    User <登录用户>
    IdentityFile ~/.ssh/<服务器专用私钥>
    IdentitiesOnly yes
    ServerAliveInterval 30
    ServerAliveCountMax 4
    TCPKeepAlive yes
```

配置要点：

- `IdentitiesOnly yes` 只使用指定私钥，避免尝试无关密钥；
- 保活参数保证长时间构建与同步不因空闲断连；
- 每台服务器使用独立密钥，不共用私钥。

连接验证：

```bash
ssh -G <别名> | grep -E '^(hostname|user|port|identityfile|identitiesonly) '
ssh -o BatchMode=yes -o ConnectTimeout=15 <别名> 'hostname; id -un; pwd'
ssh -vvv -o BatchMode=yes <别名> true 2>&1 | grep -E 'Offering public key|Server accepts key|Authenticated'
```

### 10.3 密钥与权限

1. 密钥生成使用 Ed25519：`ssh-keygen -t ed25519 -f ~/.ssh/<服务器专用私钥>`。
2. 公钥追加到服务器对应用户的 `~/.ssh/authorized_keys`；新增运维人员使用其**自己的**公钥，禁止多人共用同一私钥。
3. 本机权限：`~/.ssh` 为 `700`；私钥为 `600`；公钥为 `644`；`~/.ssh/config` 为 `600`。
4. 服务器端权限：家目录 `700`、`~/.ssh` 为 `700`、`authorized_keys` 为 `600`。
5. 私钥禁止复制给他人、禁止提交 Git、禁止写入文档与聊天记录。

### 10.4 服务端 sshd 基线

| 配置项 | 要求 |
|---|---|
| `PubkeyAuthentication` | `yes` |
| `PasswordAuthentication` | `no`（确认公钥稳定后关闭口令登录） |
| `PermitRootLogin` | `prohibit-password`（仅密钥） |
| `AuthorizedKeysFile` | `.ssh/authorized_keys` |

变更流程：

1. 修改前备份 `/etc/ssh/sshd_config`。
2. 修改后执行 `sshd -t` 校验配置。
3. reload SSH 服务；保持一个已建立的会话不退出，用新会话验证密钥登录成功后再关闭旧会话。
4. 关闭口令登录前必须确认至少两把可用公钥已在 `authorized_keys` 中，避免锁死。

### 10.5 远程操作命令范式

1. 部署目录：`/opt/chips-runtime/<服务端产品目录>`，其下 `deploy/` 保存 Compose、Nginx 配置、证书与环境文件。
2. 常用操作：

```bash
ssh <别名> 'cd /opt/chips-runtime/<产品>/deploy && docker compose ps'
ssh <别名> 'cd /opt/chips-runtime/<产品>/deploy && docker compose logs --tail=200 server'
ssh <别名> 'cd /opt/chips-runtime/<产品>/deploy && docker compose build server && docker compose up -d server'
ssh <别名> 'curl -fsS https://<主站入口>/api/v1/health'
```

3. 同步源码前必须明确目标目录；禁止直接同步到仓库根目录或覆盖运行中配置。
4. 远程执行变更命令后必须核对容器状态与健康检查，不能只以命令退出码判断成功。
5. 误放文件按生态规则移入就近 `归档/` 目录，禁止直接删除。

### 10.6 口令管理

1. 所有生产口令由密码管理器保管，采用随机生成；禁止在文档、工单、聊天与代码注释中出现任何真实口令。
2. 每项口令与密钥按 §6.3 标注持有者与用途；共享口令只限必须共享的服务，禁止"一码通"。
3. 主机管理面板（如 1Panel）与对象存储控制台必须：强密码、限制来源地址、开启登录保护与多因素认证；管理端口不对公网开放。
4. 曾以任何形式出现在对话、日志或文档中的口令与密钥，在进入生产前必须全部轮换；轮换后旧值立即失效。
5. 每次人员变动执行 §10.7 的回收流程。

### 10.7 人员变动与凭据回收

新增运维人员：

1. 本人生成密钥对，公钥由本人提交给运维登记。
2. 运维把公钥加入目标服务器 `authorized_keys`，登记密钥用途与到期时间。
3. 按最小权限分配凭据；不得直接复制他人私钥。

离场回收：

1. 从所有服务器 `authorized_keys` 移除其公钥。
2. 回收其密码管理器共享项、控制台账号与数据库账号。
3. 轮换其接触过的共享口令与密钥。
4. 回收结果写入运维记录。
