## 八、性能分析

### 8.1 指标与测量口径

| 指标 | 门禁 | 测量口径 |
|---|---|---|
| 冷启动 | < 1 s（Phase 2 < 2 s） | 主进程启动 → 首个应用窗口可用 |
| 打开卡片 | < 100 ms | `RenderEngine.open()` → 会话 `ready`（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 第 10.1 节） |
| 打开箱子 | < 200 ms | 同上，含首屏条目帧 |
| 持续渲染 | > 60 fps（Phase 2 > 30 fps） | 滚动/编辑场景帧率 |
| 空闲内存 | < 500 MB | 稳定态平台级常驻内存 |
| 插件加载 | < 100 ms | 内核收到 `LoadRequest` → `plugin:loaded` 发布完成（[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) 第 11.1 节） |
| 事件发布 | P99 < 1 μs（无监听器 < 100 ns） | `emit` 入口至监听器调用完毕，不含监听器内部耗时 |
| 服务调用 | < 1 μs | 已绑定服务句柄的一次方法调用 |

门禁数值以[《架构原则》](../00-愿景与原则/01-架构原则.md) §4.2 与附录 R18 为唯一来源，各子系统设计只在其预算内引用；补充指标见 [09-事件系统设计](../01-架构设计/01-子系统设计/09-事件系统设计.md) 第 9.1 节。

### 8.2 启动分析步骤

1. 以 `CHIPS_TRACE=startup,event` 启动；`startup` 类别记录进程启动、平台就绪、逐插件加载、窗口与应用启动、渲染首帧的里程碑时间戳。
2. 逐插件加载耗时用 `plugin:loaded` 事件时间戳与内核测量边界核对；超过 100 ms 时先区分包解压/校验耗时（插件管理层）与 apply 耗时（内核）。
3. 渲染首帧用 DevTools Performance 录制启动，或取渲染进程 `performance.getEntriesByType('navigation')` 与 Paint Timing。
4. 冷启动超限时按顺序排查：主进程同步初始化 → 插件 apply 阻塞 → 渲染首帧前的长任务；定位后把耗时初始化异步化（[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) 第 11.2 节）。
5. 冷启动对比必须使用同一构建类型与同一设备；debug 构建数据只用于相对比较，不作为门禁结论。

### 8.3 渲染性能步骤

1. DevTools Performance 录制目标场景（滚动箱子、打开大卡片、编辑提交），查看 Frames 轨道帧率与 Long Tasks。
2. 检查每个 rAF 的提交次数：高度聚合、位姿提交、条目增删应在同一 rAF 批量完成（[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) 第 10.5 节）。
3. 大箱子（条目 > 200）核对虚拟化：追踪中 `frame:entry-request` 的可见范围与 ticket 数量是否符合可见范围 ± overscan（默认 2）；帧创建并发是否不超过 4。
4. 帧池与缓存：帧池上限 32、解析缓存 64、封面缓存 64；超限应有 LRU 淘汰，持续增长即为泄漏。
5. React 侧用 React DevTools Profiler 检查会话 `update` 引发的重渲染；就近渲染不得触发二次解析（R8）。
6. 高度震荡或滚动跳动：按第 6.2 节第 6 步核对高度算法与滚动锚定。

### 8.4 内存分析步骤

1. 主进程：通过调试端口（第 4.1 节）执行 `process.memoryUsage()` 与 `app.getAppMetrics()`，区分主进程、渲染进程与 GPU 进程占用。
2. 渲染进程：DevTools Memory 分段拍摄 Heap Snapshot（会话打开前后各一次），对比帧相关对象与 detached DOM；用 Allocation instrumentation 观察帧创建/销毁是否成对。
3. 资源句柄：会话关闭后句柄表应为空（[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) 第 10.3 节）；出现 `RESOURCE_POOL_EXHAUSTED` 或退出前未释放告警时，按句柄持有者会话定位。
4. 空闲内存以稳定态（无操作 60 秒后）测量；两次强制 GC 后的快照仍持续增长时，按快照支配树定位持有链。
5. 结论记录：指标、构建类型、设备、场景与数据来源，便于回归对比。

### 8.5 工具与基准清单

| 目标 | 工具 | 使用要点 |
|---|---|---|
| Rust 微基准 | criterion（`cargo bench`） | 覆盖服务查找、事件发布、Fork 撤销、依赖解析等关键路径（[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) 第 11.3 节）；结果纳入 CI 回归（[05-CICD与质量门禁](./05-CICD与质量门禁.md)）。 |
| Rust 热点定位 | `cargo flamegraph` | 本地分析，输出火焰图定位 CPU 热点。 |
| 渲染帧率与长任务 | DevTools Performance | 录制真实交互场景，不用空闲页面代替。 |
| 渲染进程内存 | DevTools Memory | Heap Snapshot 对比 + Allocation instrumentation。 |
| 主进程内存 | Node 调试端口 + `app.getAppMetrics()` | 按进程类型统计。 |
| 门禁阈值回归 | 性能阈值测试 | 按 [05-测试规范](../02-开发规范/05-测试规范.md) 第 7.2 节编写，超限即失败。 |
