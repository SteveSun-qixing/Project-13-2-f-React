## 六、约束与红线

1. **命令命名空间**：插件命令不得占用固定命令根（含历史名 `host`）；不存在 `theme` / `module` 插件角色，两者不属于合法声明；`target.type` 必须与插件角色一致。
2. **不绕桥**：CLI 是调度器，不是插件运行时。`service` 目标经平台能力注册表与调用链路执行，`app` 目标只经 `command:invoke` 派发；CLI 不得 import 插件代码、不得读取插件源码、不得直接调用 `handleCommand`、不得绕过权限与 Schema 校验。
3. **输出纪律**：stdout 只输出最终结果或单个错误对象；进度、提示与跟踪只写 stderr；`--json` 必须强制机器可读。
4. **工作区隔离**：用户侧命令不接触开发工作区；开发侧命令不写用户工作区；`development` 插件不得在用户工作区启用。
5. **权限最小化**：`cli.commands[].permissions` 只能声明已登记权限 ID；CLI 不给插件隐式提权；未授权调用返回退出码 4。
6. **路径与输出安全**：路径参数按声明校验并解析为绝对路径；输出冲突不得静默覆盖；插件不得把 CLI 解析结果拼成 `file://`、`data:` 或裸绝对路径写回文档内容（R13）。
7. **密钥与脱敏**：签名私钥只经 `CHIPS_SIGNING_KEY_FILE` 文件路径注入；命令日志对 token、secret、password、credential、apiKey 一律脱敏（§2.8）。
8. **单一事实源**：命令发现索引只读派生；`chips plugin validate` 与安装校验同源；CLI 不缓存索引、不复制校验逻辑、不定义第二套任务存储。
9. **命令名冻结**：工程命令名以 §4.7 映射表为准；不保留别名、不做新旧双轨（ADR-010）。
10. **阶段边界**：市场发布相关命令随市场协议阶段提供；第一版发布链路为签名流水线与渠道产物（[06-更新与分发规范](./06-更新与分发规范.md) §三、§五），CLI 不提供未定义入口。
11. **术语**：插件角色只有 `basecard` / `boxlayout` / `app` / `service` 四种；能力 ID 与权限 ID 分离；界面与帮助文案简体中文直写（R1、R3、R5）。
