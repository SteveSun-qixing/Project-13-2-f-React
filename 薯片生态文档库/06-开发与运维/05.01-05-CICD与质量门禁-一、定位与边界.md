## 一、定位与边界

### 1.1 定位

本文是薯片生态 CI/CD 与质量门禁的唯一权威定义：

- 流水线五阶段：提交 → 检查 → 测试 → 构建 → 产物校验（第二节）；
- 质量门禁清单 G1-G12：格式、Clippy、ESLint、类型检查、测试、覆盖率、性能预算、契约一致性、架构红线、依赖安全、产物校验、文档门禁（第三节）；
- 产物校验口径：`.cpk` 走安装同源校验，`.card` / `.box` 走解析器 `validate`，并校验版本一致性与确定性（第四节）；
- 发布自动化：版本、签名、渠道与发布记录（第五节）；
- 门禁失败处理与豁免规则：禁止无痕豁免（第六节）。

门禁数值的最终权威是《架构原则》4.1/4.2 与《超大型工程管理体系》第六章；本文不自创指标，不改写口径。

### 1.3 基本原则

1. **单一判定**：同一提交在 PR、main 与 tag 上执行同一套门禁，结论必须一致。
2. **门禁不降级**：任何角色、任何紧急程度都不降低门禁；发布渠道不接受未通过门禁的产物。
3. **同源校验**：产物校验必须复用安装/解析的正式校验实现，禁止另写宽松版校验脚本。
4. **留痕**：门禁结果、豁免记录与发布记录全部可复核；禁止无痕豁免。
5. **确定性**：同一提交、同一输入产生相同校验结果与相同产物摘要（归档确定性见《03-插件包格式》2.1 节）。
