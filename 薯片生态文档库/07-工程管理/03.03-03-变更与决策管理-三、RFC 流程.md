## 三、RFC 流程

### 3.1 流程

```
[1] 提出 RFC
    背景与动机 / 变更方案 / 影响范围 / 实施与验证
        │
        ▼
[2] 评审
    架构一致性 / 接口与契约影响 / 性能与安全影响
    与既有 ADR 关系 / 迁移与门禁可验证性
        ├── 接受或修改后接受 ──→ 进入 [3]
        └── 驳回 ─────────────→ 记录结论，流程终止
        │
        ▼
[3] ADR 记录
    评审通过后、实施前创建 ADR（状态：已接受）
        │
        ▼
[4] 实施
    PR 引用 RFC 与 ADR 编号；改动范围不得超出决策
        │
        ▼
[5] 质量门禁
    全部门禁通过（含文档同步检查）
        │
        ▼
[6] 文档同步
    契约、接口、格式、索引文档与代码同 PR 合入并复核
```

### 3.2 提案

- 提交位置：RFC 文档作为过程材料存放于 `项目日志与笔记/` 中该变更对应的任务目录，不进入文档库（R10）；文件命名 `RFC-<标题>.md`，编号沿用任务编号，不另立决策编号。
- 必备章节：

| 字段 | 内容 |
|---|---|
| 标题 | 一句话描述变更 |
| 背景与动机 | 当前状态与必须变更的问题，只写结论，不写长篇论证 |
| 变更方案 | 单一确定方案；涉及接口、字段、流程时给出准确形状 |
| 影响范围 | 受影响的子系统、契约、三类版本、插件与文档 |
| 文档同步清单 | 需要同步修改的正式文档列表，逐项可执行 |
| 迁移安排 | 涉及用户数据或既有内容时的迁移方式；无则写"无" |
| 实施与验证 | 实施步骤、测试与门禁项、验证方式 |

- 规则：
  - 不设"备选方案"章节（R9）；方案以单一确定提案给出；
  - 不写商业价值、风险分析、时间与人力规划；
  - 涉及接口的提案必须给出目标签名与示例，不允许"待定"。

### 3.3 评审

- 评审至少核对：架构一致性与红线符合性、接口与契约影响（含三类版本）、性能与安全影响、与现行 ADR 的关系、迁移与门禁可验证性、文档同步清单完整性。
- 评审环节的风险评估按[《架构原则》](../00-愿景与原则/01-架构原则.md) §6.1 执行：结论与理由写入 RFC 与评审记录（过程材料），不写入 ADR 正文（R9、§4.2）。
- 结论只有三种：接受、修改后接受、驳回；结论与理由写入 RFC 文档，接受与修改后接受必须同时记录产出的 ADR 编号。
- 实施前必须完成评审；禁止先实施后补流程。

RFC 状态机（记录于 RFC 文件头）：

| 状态 | 含义 |
|---|---|
| 草案 | 提案编写中，未提交评审 |
| 评审中 | 已提交并进入评审 |
| 已接受 | 评审通过（含修改后接受），已创建 ADR |
| 已驳回 | 评审否决，流程终止 |
| 已实施 | 变更已合入并通过全部门禁 |

### 3.4 ADR 记录

- 时机：评审通过后、实施开始前。
- 编号：`ADR-NNN` 顺延，三位数字，不跳号、不复用；存放于 `01-架构设计/ADR/`，命名 `ADR-NNN-标题.md`。
- 内容只允许五类：状态、决策、关键设计、约束、后果（第四节）。
- 追溯：RFC 记录产出的 ADR 编号；ADR 在决策中引用来源任务或提案标识，追溯关系不得缺失。

### 3.5 实施

- PR 描述必须包含：变更说明、RFC 与 ADR 编号（重大变更）、受影响文档清单、门禁与测试结果、技术债登记（如有）。
- 实施范围不得超出 ADR 记录的决策；实施中发现需要改变决策时停止实施并回到提案（[1]），不得在实现中擅自扩大变更。
- 破坏性变更的发布形态：能力变更以新能力 ID 或平台主版本发布；文件格式不兼容变更必须同版交付迁移支持（[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) 第 5.5 节、[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) 第 3.4、7 节）。

### 3.6 质量门禁

- 合并前必须通过全部门禁；门禁项与数值以[01-架构原则](../00-愿景与原则/01-架构原则.md) 第 4 节与[01-超大型工程管理体系](01-超大型工程管理体系.md)为准，本文不自创指标；执行清单与命令见[05-CICD与质量门禁](../06-开发与运维/05-CICD与质量门禁.md)。
- 重大变更的门禁额外要求：ADR 存在且可追溯、文档同步检查通过、版本一致性检查通过（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md)）。
- 门禁失败不得合并，不得以"仅小改动"为由跳过；门禁结果随 CI 记录可追溯。

### 3.7 文档同步

见第五节：重大变更在合入前必须完成受影响文档的同 PR 更新，未完成视为未交付。
