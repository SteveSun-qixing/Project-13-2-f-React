## 十一、强制规则

### 11.1 必须遵守

1. 重大变更走 RFC → 评审 → ADR → 实施 → 质量门禁 → 文档同步。
2. 代码与文档同一 PR 更新；不一致视为缺陷。
3. 阶段出口门禁全部通过方可进入下一阶段；出口前 P0 / P1 技术债清零。
4. 质量门禁数值的权威定义在[《架构原则》](../00-愿景与原则/01-架构原则.md) §4 与附录 R18；本文只引用，调整必须走重大变更流程并同步该文档。
5. 发现问题先登记问题工单与技术债，再按流程修复。
6. 文档只落位在约定分区；新增或移动文档同步更新索引与相对链接。

### 11.2 禁止行为

```
❌ 跳过质量门禁合并代码或发布
❌ 第一版发布前引入兼容层、弃用周期或回退机制
❌ 自创门禁指标或降低基线
❌ 在文档库写入进度、汇报与过程材料
❌ 直接删除文档、ADR 与历史决策
❌ 以"后续优化"为由推迟性能基线达标
❌ 用临时实现、简化版或占位实现替换完整实现
```
