## 四、开发生命周期（六阶段）

### 4.1 总流程

```
Phase 0 文档与预研 → Phase 1 核心平台 → Phase 2 子系统
    → Phase 3 官方插件与生态 → Phase 4 迁移与发布
    → Phase 5 移动端（架构预留，暂不排期）

每个阶段出口：Definition of Done + 质量门禁全部通过
```

### 4.2 阶段与出口

| 阶段 | 目标 | 交付物 | 出口门禁（概要） |
|---|---|---|---|
| Phase 0 | 文档与预研 | 全部文档库、Monorepo 骨架、Cordis / Neon / Bridge POC | 九个分区文档完成并评审；骨架与 CI 就绪；三项 POC 验证通过 |
| Phase 1 | 核心平台 | Rust Cordis 运行时、Bridge、Electron 壳、React 壳、最小原型 | 插件加载 / 卸载与服务注入可用；Bridge 端到端调用、权限判定与 schema 校验生效；最小原型可演示 |
| Phase 2 | 子系统 | 插件系统、渲染引擎、资源管理、文档解析、权限 / 事件 / 配置系统 | 子系统完整可用；测试覆盖率 > 80%；性能达 Phase 2 放宽基线（第六章） |
| Phase 3 | 官方插件与生态 | 应用插件重写（编辑引擎、查看器、资源管理器）、CLI、示例插件、开发者文档 | 官方应用插件可用；CLI 支持创建、打包与校验；示例与开发者文档完整 |
| Phase 4 | 迁移与发布 | 用户数据迁移工具、性能与安全加固、桌面三端验证、v1.0 发布 | 迁移数据完整性校验通过；性能全量达标；安全门禁通过；桌面三端（macOS、Windows、Linux）验证通过 |
| Phase 5 | 移动端 | Android / iOS 平台实现（架构预留） | 暂不排期；格式、Rust 核心与 Bridge 的平台无关设计随 Phase 0-2 落实 |

### 4.3 阶段规则

1. 阶段划分与命名以上表为唯一口径；只写阶段、交付物与完成标准，不设日历排期。
2. 前一阶段的出口门禁未全部通过，不得启动下一阶段的实现工作。
3. 每个阶段出口前完成文档同步：新增或变更的接口、格式、规范、索引全部更新完毕。
4. 每个阶段出口前技术债 P0 / P1 清零（见 8.2）。
5. 桌面端在 Phase 1-4 完成；Phase 5 为架构预留，不得把未实现平台写成已交付。
6. 阶段 Definition of Done 明细、POC 清单与门禁映射见[开发流程与阶段计划](./02-开发流程与阶段计划.md)。
