## 七、变更管理流程

### 7.1 变更分级

| 级别 | 判定范围 | 流程 |
|---|---|---|
| 重大变更 | 核心架构设计、公开 API 接口、文件格式规范、核心依赖、构建与发布流程 | RFC → 评审 → ADR → 实施 → 质量门禁 → 文档同步 |
| 一般变更 | 不改变公开契约的内部重构、实现细节、测试与文档修复 | 直接实施 + 同 PR 文档同步 + 通过提交门禁 |

### 7.2 重大变更流程

```
提出（RFC，格式见 5.1）
   ↓
评审（架构一致性 / 接口与契约影响 / 性能影响 / 安全与权限影响 / 与既有 ADR 关系）
   ↓
ADR（记录决策、关键设计、约束、后果；格式见 5.2）
   ↓
实施（代码 + 测试 + 文档 + 示例同一链路完成）
   ↓
质量门禁（第六章全部适用项）
   ↓
文档同步（正式文档、文档库索引、技术债清单、问题工单状态）
```

- 评审结论（接受 / 驳回 / 修改后接受）写入 RFC；接受的变更必须在实施前产出 ADR。
- 实施不得分批遗留：一步变更内的代码、测试、文档、示例在同一批变更中完成。

### 7.3 第一版发布前的接口与格式变更

- 不提供兼容层、弃用周期与回退机制：破坏性变更直接实施，所有引用方在同一批变更中更新完毕。
- 用户数据与内容文件的变化通过迁移工具解决，不通过兼容读取解决（[版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md)）。
- 公开接口、文件格式、能力与权限清单的变更一律按重大变更处理。
- 版本号命名与升版规则见[变更与决策管理](./03-变更与决策管理.md)与[代码组织规范](../02-开发规范/01-代码组织规范.md)。

### 7.4 文档同步规则

1. 代码、接口、格式、规范变更必须在同一 PR 内更新对应文档；不一致视为缺陷。
2. 新增或移动文档必须同步更新 `docs/README.md` 索引与相对链接；链接失效按缺陷处理。
3. 变更完成后同步更新技术债清单与问题工单状态，未收口事项不得标记完成。
4. 文档同步清单由 RFC 维护，评审时逐项确认可执行。
