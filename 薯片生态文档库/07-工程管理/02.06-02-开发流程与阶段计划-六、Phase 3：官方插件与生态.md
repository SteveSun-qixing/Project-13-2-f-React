## 六、Phase 3：官方插件与生态

### 6.1 目标

以插件形式交付官方核心能力，建立开发者工具与文档，使生态达到可日常使用（ADR-010 成功标准）。

### 6.2 交付物

1. **应用插件重写**：编辑引擎、查看器、资源管理器（`chips.official.*`）；不是迁移旧插件，而是按新架构重写（[《12-编辑引擎设计》](../01-架构设计/01-子系统设计/12-编辑引擎设计.md)、ADR-010）。
2. **配套官方插件**：支撑日常使用所需的首批基础卡片插件与箱子布局插件（文本、图片等，按 ADR-010）。
3. **CLI**：`@chips/cli`，提供插件创建、构建、`.cpk` 打包与清单校验（[代码组织规范](../02-开发规范/01-代码组织规范.md) §三）。
4. **示例插件**：`examples/plugins/` 下至少 5 个示例，覆盖 `basecard` / `boxlayout` / `app` / `service` 四类角色。
5. **开发者文档**：`03-插件开发` 各指南全部完成，接口定义与《05-接口与契约》一致。

### 6.3 Definition of Done

- [ ] 编辑引擎、查看器、资源管理器以正式插件交付，平台不内置业务逻辑（架构原则 §1.2）；
- [ ] 日常任务闭环：创建、打开、编辑、保存 `.card`；组织、打开 `.box`；资源管理可用；
- [ ] CLI 可用：创建、构建、打包、校验全流程走通；
- [ ] 至少 5 个示例插件覆盖四类角色，全部经正式 Bridge 与服务链路运行；
- [ ] `.cpk` 产物通过[插件包格式](../04-文件格式规范/03-插件包格式.md)校验；
- [ ] 开发者文档完整，[快速开始](../03-插件开发/01-快速开始.md)流程可被第三方开发者独立复现；
- [ ] 质量门禁通过；无临时实现与占位功能。
