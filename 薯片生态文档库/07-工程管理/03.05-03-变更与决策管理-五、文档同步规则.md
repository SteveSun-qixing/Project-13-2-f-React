## 五、文档同步规则

### 5.1 基本原则

- 文档是交付物的一部分：代码与文档必须同 PR 更新；PR 中缺失应同步的文档即视为未完成，不得合并。
- 文档与实现不一致视为缺陷：发现即修复，不得"以后再说"；缺陷归属按 5.4 判定。
- 重大变更的文档同步范围由 RFC 的"文档同步清单"列出，并由评审核对完整。

### 5.3 审查要求

- 文档变更与代码变更执行同一 PR 与审查流程；示例必须完整可用，链接必须有效（[07-文档编写规范](../02-开发规范/07-文档编写规范.md) 第 14 节）。
- 审查必须核对：接口与文档签名一致、错误码一致、字段表一致、示例可复现、索引已更新。
- PR 描述中必须逐项列出实际更新的文档；未列出的受影响文档视为遗漏。

### 5.4 不一致的判定与修复

| 情形 | 判定 | 修复方向 |
|---|---|---|
| 实现偏离契约且无 ADR 支撑 | 实现缺陷 | 修正实现，或在完成 RFC 后修订契约 |
| 实现已按新 ADR 变更、文档未更新 | 文档缺陷 | 以 ADR 为准更新文档 |
| 文档与文档之间口径冲突 | 缺陷 | 以该领域权威文档为准修正，另一处同 PR 更新 |
| 文档示例不可运行或链接失效 | 文档缺陷 | 立即修正；示例按规范重写 |

修复必须同 PR 完成并回写对应缺陷记录；不得留下"已知不一致"清单。
