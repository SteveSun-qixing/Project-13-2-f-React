## 二、变更分级

### 2.1 重大变更（必须走 RFC）

凡改变对外可见契约、长期运行时依赖或治理基线的变更，均为重大变更：

| 类别 | 判定 |
|---|---|
| 决策 | 修改、推翻或废除既有 ADR 的决策 |
| 接口 | Bridge 方法面（`IChipsBridge` 三方法）、四类插件角色接口、核心导出面的签名或语义变更 |
| 能力与权限 | 能力 ID、权限 ID、事件 ID、错误码族的新增与调整；内置能力与权限总表变更（[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) 第 6.2 节） |
| 文件格式 | `.card` / `.box` / `.cpk` 的目录、字段、引用形式变更；`chip_standards_version` 变更 |
| 版本 | 平台版本策略、统一版本范围、版本范围语法变更 |
| 结构 | 新增顶层包、新增仓库、依赖方向调整；引入长期运行时依赖或改变基础架构 |
| 基线 | 质量门禁、性能基线、安全基线（R17、R18）的调整 |
| 流程 | 构建、打包、发布、迁移工具链的流程性变更 |

判定规则：

1. 不确定时按重大处理，不得自行降级；
2. 禁止把一个重大变更拆成多个"普通变更"分批合入以规避评审；
3. 重大变更的门禁项必须包含 ADR 与文档同步检查（第三节、第五节）。

### 2.2 普通变更

以下变更不要求 RFC，直接按任务分支与 PR 流程实施：

- 缺陷修复；
- 不改变契约与可观察行为的内部重构与实现优化（含 Neon 绑定层内部优化）；
- 测试补充、性能优化（不改变基线定义）；
- 文档修正与索引更新。

普通变更仍受质量门禁、文档同步与现行 ADR 的约束；不得借"普通"之名引入重大变更的内容。
