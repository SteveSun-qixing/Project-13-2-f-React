## 五、流程制品与记录格式

### 5.1 RFC

位置：`项目日志与笔记/` 对应任务目录；通过评审的结论固化进 ADR 与正式文档。

| 字段 | 要求 |
|---|---|
| 标题 | 一句话描述变更 |
| 背景与动机 | 要解决的问题与触发原因 |
| 方案 | 变更的完整设计：接口、数据、流程的改动 |
| 影响范围 | 受影响的子系统、接口、文件格式、插件与文档 |
| 文档同步清单 | 需要同步修改的正式文档列表 |
| 迁移安排 | 涉及用户数据或既有内容时的迁移方式；无则写"无" |

RFC 不要求列替代方案，不写商业分析、人事与排期。

### 5.2 ADR

位置：`01-架构设计/ADR/`；命名 `ADR-NNN-标题.md`，编号顺延、不复用。

| 章节 | 内容 |
|---|---|
| 元数据 | 状态（已接受 / 已废弃）、日期、影响范围 |
| 决策 | 一句话结论 |
| 关键设计 | 落实决策所需的接口、结构与约束 |
| 约束 | 实施中不可违反的限制 |
| 后果 | 接受该决策带来的直接结果（保持简短） |

ADR 不写替代方案、背景长篇论证与优劣对比；模板与记录细则见[变更与决策管理](./03-变更与决策管理.md) §4.2。

### 5.3 技术债条目

位置：`项目日志与笔记/技术债务清单.md`。

| 字段 | 内容 |
|---|---|
| 债务描述 | 现状与理想状态的差距 |
| 产生原因 | 引入时点与原因 |
| 影响范围 | 受影响的子系统与交付物 |
| 优先级 | P0（阻断）/ P1（严重）/ P2（一般）/ P3（可延后） |
| 偿还动作 | 完成偿还的验收标准 |

### 5.4 问题工单

位置：`项目日志与笔记/问题工单.md`；每个工单同时建立目录 `项目日志与笔记/工单NNN-描述/任务说明.md`（描述用中文）。

触发条件：架构缺口、接口或组件缺失、SDK / 脚手架不可用、文档与代码不一致、工具链与文档漂移。

工单必须写清背景、证据、影响范围、复现步骤、期望行为与暂行处理；不得以临时实现绕过。
