## 六、质量门禁

门禁分三层：**提交门禁**（每次 PR）、**阶段门禁**（阶段出口）、**发布门禁**（Phase 4 发布产物）。门禁数值的权威定义见[《架构原则》](../00-愿景与原则/01-架构原则.md) §4 与附录 R18；本文与其余文档只做引用与执行，任何文档不得自创指标或改写数值。

### 6.1 代码与架构门禁

| 门禁项 | 要求 |
|---|---|
| Rust 格式 | `cargo fmt --all -- --check` 通过 |
| Rust 静态检查 | `cargo clippy --workspace --all-targets -- -D warnings` 无 warning |
| TypeScript 静态检查 | ESLint 无 error；Prettier 检查通过；`tsc -b` 类型检查通过 |
| 测试 | 单元测试与集成测试全部通过 |
| 覆盖率 | 总体 > 80%；Rust 核心（`chips-*` crates）与共享层（`@chips/ui`、`@chips/bridge`）> 90% |
| 依赖方向 | 无循环依赖；ESLint `import/no-cycle` 全仓启用 |
| unsafe | 所有 `unsafe` 代码附带 `# Safety` 说明 |
| 构建 | 全量构建通过；锁文件提交，构建产物不入库 |

### 6.2 性能门禁

数值以[《架构原则》](../00-愿景与原则/01-架构原则.md) §4.2 与附录 R18 为唯一来源，本表为阶段执行口径的引用：

| 指标 | Phase 2（放宽） | Phase 4 起（正式） |
|---|---|---|
| 冷启动 | < 2 s | < 1 s |
| 渲染帧率 | > 30 fps | > 60 fps |
| 空闲内存占用 | < 500 MB | < 500 MB |
| 打开卡片 | < 100 ms | < 100 ms |
| 打开箱子 | < 200 ms | < 200 ms |

性能不达标必须分析原因并优化，不得以"后续优化"为由推迟；放宽值只适用于 Phase 2；调整基线必须走重大变更流程并同步《架构原则》。

### 6.3 安全门禁

| 门禁项 | 要求 |
|---|---|
| Electron 基线 | `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`；生产环境禁止关闭 `webSecurity`（[ADR-002](../01-架构设计/ADR/ADR-002-Electron作为桌面端壳.md)） |
| 依赖安全 | 无已知漏洞；依赖审计通过 |
| 插件权限 | 最小权限；系统能力只经 Bridge 调用且可审计（[权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md)） |
| 资源访问 | 统一经 `chips-resource://`，受限、可审计 |
| 代码签名 | Phase 4 发布产物完成签名配置 |

### 6.4 文档门禁

| 门禁项 | 要求 |
|---|---|
| ADR 覆盖 | 重大决策均有 ADR，状态为已接受或已废弃 |
| 同 PR 更新 | 代码、接口、格式、规范变更与文档在同一 PR 完成；不一致视为缺陷 |
| API 文档 | 公开 API 文档覆盖率 > 95% |
| 链接有效 | 文档内相对链接全部有效；新增或移动文档已更新索引 |
| 阶段交付 | 阶段出口前该阶段涉及的全部文档同步完成 |
