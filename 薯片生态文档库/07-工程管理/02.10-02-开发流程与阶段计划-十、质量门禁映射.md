## 十、质量门禁映射

### 10.1 权威归属

- 门禁的完整清单、CI 流程、执行方式与产物校验：以[《CICD与质量门禁》](../06-开发与运维/05-CICD与质量门禁.md)为准；
- 门禁数值一律引用[《架构原则》](../00-愿景与原则/01-架构原则.md)与[《测试规范》](../02-开发规范/05-测试规范.md)，本计划不自创指标（R16）。

### 10.2 门禁类别与适用阶段

| 门禁类别 | 检查项 | 起始阶段 | 数值/规则来源 |
|---|---|---|---|
| 代码风格 | `cargo fmt`、`clippy` 无 warning、ESLint 无 error、Prettier 通过；TS 无 `any`；Rust 生产代码无 `unwrap()`；`unsafe` 附 `# Safety` | Phase 1 | 架构原则 §4.1、R18、[Rust 编码规范](../02-开发规范/04-Rust编码规范.md)、[TypeScript 编码规范](../02-开发规范/02-TypeScript编码规范.md) |
| 测试 | 单元与集成测试全部通过；覆盖率总体 > 80%，Rust 核心与共享层 > 90% | Phase 1（覆盖率 Phase 2） | [测试规范](../02-开发规范/05-测试规范.md)、R18 |
| 架构 | 无循环依赖、无分层违规；导入红线 R4（`@chips/antd` 仅 `packages/ui` 使用） | Phase 1 | 架构原则 §二、[代码组织规范](../02-开发规范/01-代码组织规范.md)、R4 |
| 契约 | 实现与《05-接口与契约》一致；Bridge 形状符合 R2；能力/权限命名符合 R3 | Phase 1 | R2、R3、[Bridge API 规范](../05-接口与契约/01-Bridge-API规范.md) |
| 文档 | 文档与代码同 PR；无坏链；文档与实现不一致视为缺陷 | Phase 0 | R16、[文档编写规范](../02-开发规范/07-文档编写规范.md) |
| 性能 | 分档执行，见 10.3 | Phase 2 | R18、架构原则 §4.2 |
| 安全 | R17 配置基线、权限最小化、调用可审计；依赖漏洞审计与代码签名 | Phase 1（审计与签名 Phase 4） | R17 |
| 产物 | `.cpk` 通过插件包校验；三端安装包签名与产物校验 | Phase 3（.cpk）、Phase 4（签名） | [插件包格式](../04-文件格式规范/03-插件包格式.md)、[构建与打包](../06-开发与运维/02-构建与打包.md) |
| 迁移 | 迁移输出逐文件 `validate` + 资源清单哈希与尺寸全量核对 | Phase 4 | [版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §6.5 |

### 10.3 性能门禁分阶段档位

| 指标 | Phase 2 档 | Phase 4 最终档 |
|---|---|---|
| 冷启动 | < 2s | < 1s |
| 持续渲染 | > 30fps | > 60fps |
| 空闲内存 | < 500MB | < 500MB |
| 打开卡片 | < 100ms | < 100ms |
| 打开箱子 | < 200ms | < 200ms |

- Phase 0：性能以 POC 通过标准衡量（POC-1、POC-4）；
- Phase 1：以子系统内部预算衡量（内核、Bridge、解析器的设计预算）；
- Phase 2-3：按 Phase 2 档执行，且不得回归；
- Phase 4 起：按最终档执行（R18）。

### 10.4 门禁执行要求

- 门禁在 CI 中自动执行；无法自动化的项（评审、审计）必须有书面结论并存档；
- 阶段准出检查时，门禁记录与 DoD 证据一并复核；
- 门禁基线数值变更属于重大变更，走 RFC → 评审 → ADR → 实施 → 质量门禁 → 文档同步（R16）。
