## 六、技术债管理

### 6.1 记录位置与格式

- 唯一位置：`项目日志与笔记/技术债务清单.md`（仓库根相对路径，R16）。
- 条目格式：

| 字段 | 要求 |
|---|---|
| 编号 | `TD-001` 起顺延，不复用 |
| 债务描述 | 一句话说明现状与理想状态的差距 |
| 产生原因 | 引入时点与原因；附来源任务、PR 或 ADR 编号 |
| 影响范围 | 受影响子系统、契约或交付物 |
| 优先级 | P0 / P1 / P2 / P3（6.2） |
| 偿还动作 | 可执行的确定性动作与验收标准，不是方向性描述 |
| 承接阶段 | 按 R7 阶段填写（Phase 0-5） |
| 状态 | 待偿还 / 处理中 / 已偿还（保留历史，不移除条目） |

- 新增即登记：变更引入债务时，在同一 PR 或紧随其后的登记变更中登记，PR 描述引用条目编号。

### 6.2 优先级与偿还规则

| 优先级 | 定义 | 处置规则 |
|---|---|---|
| P0（阻断） | 阻断发布，或影响数据安全与正确性 | 立即修复；清单存在未偿还 P0 时不得发版 |
| P1（严重） | 违反架构红线、契约不一致、门禁缺口 | 当前阶段结束前清零，纳入阶段 DoD 核对 |
| P2（一般） | 不影响正确性的性能、可维护性改进项 | 纳入下一阶段计划；存在 P2 积压时每阶段至少偿还一项 |
| P3（可延后） | 文档与工具链的轻微改进项 | 随相关文件的变更顺带偿还 |

- 债务不得无限期悬挂：无法偿还的条目必须给出确定性处置结论（替换、迁移或取消），并说明承接版本或阶段。
- 债务不得作为豁免手段：禁止以"登记为技术债"为由提交临时实现、TODO、未完成的契约或降低门禁标准（[01-架构原则](../00-愿景与原则/01-架构原则.md) 第 2.6 节）。
- 缺陷与架构缺口不登记为技术债：缺陷立即修复；架构缺口与生态能力缺失按工单流程登记于 `项目日志与笔记/问题工单.md`。
- 债务不得分散记录：不得在代码注释、PR 或临时文件中维护与清单并行的债务列表。
