## 一、定位与边界

### 1.1 定位

本文是薯片生态变更与决策治理的唯一权威：哪些变更必须评审、按什么流程决策、决策记录到哪里、代码与文档如何同步、技术债如何登记与偿还、版本号如何随变更升级、原则冲突如何收口，一律以本文为准。

流程总口径（R16）：

```
RFC → 评审 → ADR 记录 → 实施 → 质量门禁 → 文档同步
```

- 重大变更必须完整走完上述六步，缺一步即视为流程违规；
- 普通变更不走 RFC，但仍受质量门禁与文档同步约束（第二节分级）；
- 决策的永久记录只有 ADR；RFC 与评审记录是过程材料，不进入文档库（R10）。

### 1.3 基本约束

- 禁止直接违反[架构原则](../00-愿景与原则/01-架构原则.md)：冲突一律按第八节处理，禁止"临时绕过"与"先实施后补记录"。
- 决策记录不可篡改；ADR 只增不改（第四节）。
- 代码与文档必须同 PR 更新，不一致视为缺陷（R16；展开见第五节）。
- 破坏性变更不设弃用期、不设双轨、不留兼容层（[ADR-010](../01-架构设计/ADR/ADR-010-大爆炸重构策略.md)、[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) 第 1.3、8 节）。
- 阶段与门禁是唯一进度口径，不写日历排期（[02-开发流程与阶段计划](02-开发流程与阶段计划.md)）。
