## 二、阶段总览（R7）

### 2.1 六阶段表

| 阶段 | 目标 | 交付物 |
|---|---|---|
| Phase 0 | 文档与预研 | 全部文档库、Monorepo 骨架、Cordis/Neon/Bridge POC |
| Phase 1 | 核心平台 | Rust Cordis 运行时、Bridge、Electron 壳、React 壳、最小原型 |
| Phase 2 | 子系统 | 插件系统、渲染引擎、资源管理、文档解析、权限/事件/配置系统、覆盖率 >80% |
| Phase 3 | 官方插件与生态 | 应用插件重写（编辑引擎、查看器、资源管理器）、CLI、示例插件、开发者文档 |
| Phase 4 | 迁移与发布 | 用户数据迁移工具、性能与安全加固、桌面三端（macOS、Windows、Linux）验证、v1.0 发布 |
| Phase 5 | 移动端 | Android / iOS（架构预留，暂不排期） |

### 2.2 阶段依赖与推进

```
Phase 0  文档与预研 ── 文档库 + Monorepo 骨架 + POC 全部通过
   │
   ▼
Phase 1  核心平台 ── 最小原型：加载插件 → 调用能力 → 显示界面
   │
   ▼
Phase 2  子系统 ── 子系统完整 + 覆盖率与性能门禁达标
   │
   ▼
Phase 3  官方插件与生态 ── 核心插件日常可用 + CLI 与开发者文档就绪
   │
   ▼
Phase 4  迁移与发布 ── 迁移工具 + 三端验证 + v1.0 发布
   │
   ▼
Phase 5  移动端（架构预留，暂不排期；启动需所有者决策）
```

- 不允许跳阶或合并阶段；阶段内允许并行。
- Phase 5 不设排期；不得把未实现平台写成已交付（R6）。

### 2.3 平台覆盖

- Phase 0-3：在 macOS / Windows 上实现与验证；Linux 保持平台无关设计并在 Phase 4 随桌面三端完成验证；Android、iOS 只做架构预留，不排期。
- Phase 4：完成 macOS / Windows / Linux 桌面三端验证（R7）。
- Phase 5：Android / iOS 实现与验证，启动条件见第八章。

平台优先级为 macOS / Windows → Linux（桌面三端完成）→ Android → iOS（R6）。文件格式、Rust 核心与 Bridge 接口自 Phase 0 起按平台无关设计，保证五端共享（[ADR-007](../01-架构设计/ADR/ADR-007-桌面端与移动端分离策略.md)）。
