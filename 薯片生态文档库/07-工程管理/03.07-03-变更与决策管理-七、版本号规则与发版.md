## 七、版本号规则与发版

### 7.1 三类版本

| 版本 | 权威位置 | 变更驱动 | 权威定义 |
|---|---|---|---|
| 平台版本 | 仓库根 workspace 版本（`package.json` 与 `Cargo.toml` 必须一致） | 平台发布；全部平台包统一升版 | [04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) 第 2.1 节 |
| 插件版本 | `.cpk` 的 `manifest.yaml` 中 `version`；源码 `package.json` 必须一致 | 插件独立发布 | 同上 |
| 文档格式版本 | `.card` / `.box` 的 `chip_standards_version` | 文档格式变更，随平台版本发布 | 同上，第 2.2、3.4 节 |

本文只规定变更流程如何驱动版本；格式、范围语法、优先级比较、兼容判定与迁移工具的全部规则以[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md)为准，不得在本文件或他处另立版本口径。

### 7.2 变更与版本升降的对应

- 版本升降含义（平台 / 插件 / 文档格式）以[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) 第 3.3 节为唯一判定表。
- 0.x 阶段（Phase 4 发布 `1.0.0` 前）不承诺兼容：破坏性变更升 `MINOR`，但必须走本文第三节流程，并同版交付迁移步骤（涉及用户数据或内容文件时）。
- 文档格式版本：不兼容变更升 `MAJOR`，必须同版交付迁移工具与转换说明；变更流程见[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) 第 7 节。
- 平台统一版本禁止漂移：任一平台包发布即统一升版；插件版本不并入平台统一版本。
- 版本号更新与变更同 PR 完成；发布后不得修改已发布版本的语义。

### 7.3 发版检查

平台版本发布前必须逐项确认：

| 检查项 | 通过标准 |
|---|---|
| 决策记录 | 本版包含的全部重大变更均有 RFC 与已接受 ADR，编号可追溯 |
| 文档同步 | 受影响文档已随代码合入；索引与示例已更新；无已知不一致 |
| 质量门禁 | 全部门禁通过，含版本一致性检查与文档同步检查 |
| 版本号 | 三类版本按 7.2 完成升降；平台包版本一致；无版本漂移 |
| 迁移 | 涉及不兼容变更时，迁移工具、转换说明与打开时的确定性错误提示同版交付 |
| 发布说明 | 以附注标签与发布 PR 描述给出：版本号、变更条目（引用 ADR/RFC）、破坏性变更、迁移指引、已知问题 |
| 标签 | 按[06-Git工作流规范](../02-开发规范/06-Git工作流规范.md) 第 8 节创建 `v{major}.{minor}.{patch}` 附注标签 |

### 7.4 紧急修复

- 紧急修复走[06-Git工作流规范](../02-开发规范/06-Git工作流规范.md) 第 13 节的 hotfix 流程；修复完成按 `PATCH` 升版。
- 紧急修复只修缺陷：不得顺带实现重大变更、不得修改契约；确需修改契约时按 RFC 流程在正常版本发布。
- 修复必须同时包含测试与文档更新；发布后回写缺陷来源并核对技术债清单。
