## 四、物料清点与产物校验衔接

### 4.1 清点对象

| 对象 | 现行位置 | 目标位置 | 清点用途 |
|---|---|---|---|
| 成品验证物料（样例卡片、箱子、媒体、网页包） | `ProductFinishedProductTestingSpace/` | `tests/fixtures/`（[01-代码组织规范](../02-开发规范/01-代码组织规范.md) 第二节） | 回归与成品验收输入；纳入回归的物料必须通过解析校验 |
| 发布产物（三端安装包、`.cpk`、更新索引、摘要清单） | 打包输出目录（现行 `打包/V0.01/`） | `release/`（[01-代码组织规范](../02-开发规范/01-代码组织规范.md) 第七节） | 发布追溯；由摘要清单校验并登记进发布记录 |

### 4.2 清点脚本清单与职责

| 脚本 | 现行位置 | 目标位置 | 职责 | 输出 | 衔接的校验点 |
|---|---|---|---|---|---|
| `collect-finished-product-materials.mjs` | `scripts/` | `tools/scripts/` | 扫描成品验证物料：按扩展名分类，解析 `.card` / `.box` 归档（ZIP Store、必需条目、metadata、entries、旧工作区 URL 检测），标记归档素材 | JSON 与 Markdown 物料清单 | 纳入回归的物料必须通过解析器校验；`归档/` 内素材排除回归；解析失败写 `parseError` |
| `verify-ecosystem-workspace.mjs` | `scripts/` | `tools/scripts/` | 工作区一致性校验：workspaces 声明、工具链基线、工作区包与脚手架模板依赖 | 退出码与错误清单 | 非 0 即失败，阻断后续清点与打包 |
| `package-ecosystem-release.mjs` | `scripts/` | `tools/scripts/` | 官方插件全量打包：发现插件工程 → `build` → `validate` → `package` → `.cpk` 归档；构建 Host 与 macOS 安装器 | `.cpk` 集合、安装产物 | 每个 `.cpk` 必须先 `validate` 再打包；产物交摘要工具生成摘要清单 |
| `checksums.mjs` | 未落位（权威定义） | `tools/scripts/` | 摘要清单生成与校验 | `release/SHA256SUMS.txt` | `verify` 结果写入发布记录（§3.2、§3.3） |
| `generate-plugin-material-icons.ts`、`icon-targets.mjs`、`sync-plugin-icons.mjs` | `scripts/` | 设计资产工具链 | 图标资产生成与同步到各插件 `assets/icons/` | SVG / PNG / ICO / ICNS | 不参与产物校验；图标落位由插件包校验覆盖 |

规则：

- 清点脚本只报告事实（分类、结构检查、归档标记、解析错误），不代替正式校验判定；合格判定权威在 [02-构建与打包](../06-开发与运维/02-构建与打包.md) 第九节、[05-CICD与质量门禁](../06-开发与运维/05-CICD与质量门禁.md) 第四节。
- 清点脚本不得写入文档库与归档目录；清点报告写入 `项目日志与笔记/` 对应任务目录，摘要与产物清单写入产物目录。
- 现行根脚本入口（`materials:inventory`、`verify:workspace`、`package:pre-release`、`package:list`）保持语义；迁移到目标 Monorepo 时按 [01-代码组织规范](../02-开发规范/01-代码组织规范.md) 第八节落位为 `tools/scripts/` 下的正式脚本。
- 脚本输出中的路径一律使用工作区根相对路径，避免绝对路径进入清单与发布记录。

### 4.3 数据流与衔接规则

```
物料清点（materials:inventory）
   │  分类 / 结构解析 / 归档标记
   ▼
纳入回归的物料 ────► 解析器 validate（Valid / ValidWithWarnings / Invalid）
   │                        │ Invalid → 修复或归档，禁止进入验证基线
   ▼                        ▼
物料清单基线            发布构建（build → validate → package）
                            │
                            ▼
                     摘要生成与校验（checksums generate → verify）
                            │
                            ▼
                     发布记录（产物清单 + 摘要 + 签名 + 门禁 + 渠道）
```

1. 先清点、后构建：物料清单确定回归输入集合；未通过解析校验的物料不得进入回归。
2. 先校验、后记录：发布记录只登记 `validate` 通过、摘要 `verify` 通过的产物（[02-构建与打包](../06-开发与运维/02-构建与打包.md) §9.5）。
3. 归档物料规则：清点结果位于 `归档/` 的素材不纳入回归、不进入发布产物，只作历史参考（对应 §二）。
4. 对账：发布记录中的产物数量与 `.cpk` 集合、摘要清单条目一致；物料清单中回归物料数量的变化，必须能追溯到新增、移除或归档动作。
5. 双形态：`.card` / `.box` 物料同时提供目录态与归档态时，双形态一致性校验结果进入物料清单备注，作为回归输入的一部分（[05-CICD与质量门禁](../06-开发与运维/05-CICD与质量门禁.md) §4.3）。

### 4.4 失败处理

- 物料解析失败（`parseError`）：修复物料或按 §2.6 归档，并在物料清单中保留记录；禁止把失败物料混入通过集。
- 产物校验失败（`Invalid`、摘要不一致、版本漂移）：阻断发布，修复后以新提交重新构建；禁止以"重新打包同一提交"绕过（[05-CICD与质量门禁](../06-开发与运维/05-CICD与质量门禁.md) §4.5）。
- 清点或校验脚本自身缺陷：按问题工单流程登记（[01-超大型工程管理体系](./01-超大型工程管理体系.md) 第五节），不得以手工结果替代脚本输出。
- 产物目录与记录不一致：以摘要清单为对账基准，回查构建日志与门禁报告；对账未完成不得标记发布完成。
