## 四、提交要求

### 4.1 提交粒度

```bash
# ✅ 好的提交：单一职责
git commit -m "feat: 添加卡片解析功能"
git commit -m "test: 添加解析功能测试"
git commit -m "docs: 更新解析功能文档"

# ❌ 不好的提交：混合多个功能
git commit -m "添加解析功能、修复 bug、更新文档"
```

### 4.2 提交频率

```
开发过程：频繁提交（每完成一个小功能）
推送远程：完成完整功能后推送
```
