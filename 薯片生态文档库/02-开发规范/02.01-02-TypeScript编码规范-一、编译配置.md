## 一、编译配置

### 配置的三层落位

| 层 | 文件 | 承载内容 |
|---|---|---|
| 全仓 | `tsconfig.base.json`（仓库根） | 共享 `compilerOptions`（严格选项、声明输出）与 `@chips/*` 的 `paths` 解析锚定 |
| 包 | `packages/<包>/tsconfig.json`、`tools/<工具>/tsconfig.json` | `"extends": "../../tsconfig.base.json"` + `include` + 包内环境差异（如 `types`）；类型检查用，禁止重复定义共享选项与 `paths` |
| 包（产物） | `<包>/tsconfig.build.json` | 产物构建视图：`noEmit: false`、`outDir: dist`、`rootDir: src`，排除测试文件（构建链路口径见 [02-构建与打包](../06-开发与运维/02-构建与打包.md) §5.2） |

### tsconfig.base.json（节选）

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "strict": true,
    "esModuleInterop": true,
    "allowSyntheticDefaultImports": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true,
    "resolveJsonModule": true,
    "isolatedModules": true,
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noImplicitReturns": true,
    "noFallthroughCasesInSwitch": true,
    "exactOptionalPropertyTypes": true,
    "noUncheckedIndexedAccess": true,
    "paths": {
      "@chips/ui": ["./packages/ui/dist/index", "./packages/ui/src/index"],
      "@chips/bridge": ["./packages/bridge/dist/index", "./packages/bridge/src/index"],
      "@chips/sdk": ["./packages/sdk/dist/index", "./packages/sdk/src/index"],
      "@chips/sdk/testing": ["./packages/sdk/dist/testing/index", "./packages/sdk/src/testing/index"],
      "@chips/host": ["./packages/host/dist/types/index", "./packages/host/src/index"],
      "@chips/native": ["./packages/native/types/chips-native"],
      "@chips/*": [
        "./packages/*/dist/index",
        "./packages/*/src/index",
        "./tools/*/dist/index",
        "./tools/*/src/index"
      ]
    }
  }
}
```

### `paths` 解析锚定规则

- `paths` 只在全仓 `tsconfig.base.json` 定义一次，包级配置一律 `extends` 继承，禁止在包内改写或另写一套单应用口径的 `@chips/*` 指向（例如把 `@chips/ui` 直接指向 `./packages/ui/src`：这会绕过包的 `exports` 与产物入口，使包间类型解析与构建产物脱钩）。
- 每个 `@chips/*` 条目的候选顺序固定为「官方产物入口（包 `exports.types` 对应的 `dist/`）优先 → 工作区内已提交源码入口兜底」，两级候选都命中本工作区即止：类型解析必须结构性终结于工作区内部，不得回退到祖先目录 `node_modules` 中的同名外部包。
- 末尾的 `@chips/*` 通配为新增 `packages/*`、`tools/*` 包提供自动锚定，要求目录名与包名末段一致（见 [01-代码组织规范](./01-代码组织规范.md) §3.4）；目录名不一致或新增子路径导出（如 `@chips/sdk/testing`）时，必须在通配之前补精确条目。
- 包间运行时依赖一律用 `workspace:*` 声明（见 [01-代码组织规范](./01-代码组织规范.md) §4），`paths` 只解决类型解析，不替代依赖声明。

### 严格模式要求

必须启用所有严格检查：

```json
{
  "strict": true,
  "noUnusedLocals": true,
  "noUnusedParameters": true,
  "noImplicitReturns": true,
  "noFallthroughCasesInSwitch": true,
  "noUncheckedIndexedAccess": true,
  "exactOptionalPropertyTypes": true
}
```
