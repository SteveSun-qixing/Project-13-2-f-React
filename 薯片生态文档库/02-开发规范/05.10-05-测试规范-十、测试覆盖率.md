## 十、测试覆盖率

### 10.1 生成报告

```bash
# TypeScript 包（各包标准脚本）
pnpm test:coverage

# Rust 工作区
cargo tarpaulin --workspace --out Xml
```

- 报告写入仓库根 `coverage/`（不入库）；TS 输出 text + html + lcov，Rust 输出 XML，随 CI 流水线工件归档。
- 全仓聚合命令为根脚本 `pnpm test:coverage`（[01-代码组织规范](./01-代码组织规范.md) §8.1）。

### 10.2 覆盖率要求

```typescript
// vitest.config.ts（普通包：总体门槛）
export default defineConfig({
  test: {
    coverage: {
      provider: 'v8',
      thresholds: {
        lines: 80,
        functions: 80,
        branches: 80,
        statements: 80,
      },
    },
  },
});
```

```typescript
// packages/ui、packages/bridge 等共享层包的 vitest.config.ts：90% 门槛
// Rust 核心（chips-* crates）由 cargo-tarpaulin 以同一 90% 口径判定
export default defineConfig({
  test: {
    coverage: {
      provider: 'v8',
      thresholds: {
        lines: 90,
        functions: 90,
        branches: 90,
        statements: 90,
      },
    },
  },
});
```

- 口径：总体 > 80%；Rust 核心（`chips-*` crates）与共享层（`@chips/ui`、`@chips/bridge`）> 90%（R18）。
- 四个统计维度（行、函数、分支、语句）分别判定；核心与共享层按 90%，其余按 80%。
- 新增代码不得拉低整体覆盖率；覆盖率下降即失败，不设"先合入再补测试"通道。
