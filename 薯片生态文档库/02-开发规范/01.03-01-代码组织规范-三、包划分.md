## 三、包划分

### 3.1 平台包（packages/）

| 目录 | 包名 / 产物 | 语言 | 职责 |
|---|---|---|---|
| `core-rust/` | Rust crates `chips-*`，产物 `chips-native.node` | Rust | Cordis 运行时、Bridge 内核、文档解析、资源管理；经 Neon 暴露给 Node.js |
| `native/` | `@chips/native` | TypeScript | Neon 绑定包目录：`chips-native.node` 的构建脚本、ABI 与类型视图（crate 本体在 `core-rust/crates/chips-native`） |
| `bridge/` | `@chips/bridge` | TypeScript | Bridge 协议类型与预加载/渲染进程共享的桥接层；不实现 Host 能力 |
| `host/` | `@chips/host` | TypeScript | Electron 主进程、preload、窗口渲染进程、窗口与生命周期、IPC 注册、插件加载、Host 能力实现 |
| `sdk/` | `@chips/sdk` | TypeScript | 插件类型定义、辅助函数、测试 Mock、脚手架导出；不承载运行时 |
| `ui/` | `@chips/ui` | TypeScript | 共享组件、Hooks、Design Tokens；前端唯一导入面 |
| `antd/` | `@chips/antd` | TypeScript | fork 的 antd；仅 `packages/ui` 内部使用 |
| `cli/` | `@chips/cli` | TypeScript | 用户侧与开发侧命令：创建插件、打包 `.cpk`、校验 manifest 与文件格式 |

`core-rust/` 的 crate 划分：

```
packages/core-rust/
└── crates/
    ├── chips-core/       # 公共类型、错误模型、通用工具（无内部依赖）
    ├── chips-cordis/     # Cordis 运行时（内核）
    ├── chips-bridge/     # Bridge 内核（能力注册表、权限判定、schema 校验）
    ├── chips-parser/     # .card / .box 解析
    ├── chips-resource/   # 资源管理
    └── chips-native/     # Neon 绑定（cdylib，导出 chips-native.node）
```

- 子系统 crate 只允许依赖 `chips-core`；`chips-native` 组合全部子 crate。
- 类型归属：协议类型在 `@chips/bridge`，插件开发类型在 `@chips/sdk`；不设独立类型包。

`packages/` 内其余包的结构要求：

```
packages/bridge/
├── src/
│   ├── protocol/       # IChipsBridge / ICapability / 错误模型 / 资源句柄
│   ├── client/         # window.chips 的类型化封装（preload 与渲染进程共用）
│   └── index.ts        # 唯一公开入口
└── package.json

packages/host/
├── src/
│   ├── main/           # Electron 主进程
│   ├── preload/        # contextBridge：暴露 window.chips
│   ├── renderer/       # React 窗口界面
│   └── capabilities/   # Host 侧能力实现
├── native/             # Neon 绑定产物（构建生成，不入库）
└── package.json

packages/sdk/
├── src/
│   ├── types/          # 插件角色接口、模型、能力类型（转发 @chips/bridge）
│   ├── testing/        # 测试 Mock 与断言辅助
│   ├── scaffold/       # 脚手架模板与生成器导出
│   └── index.ts
└── package.json

packages/ui/
├── src/
│   ├── components/     # 薯片共享组件（基于 @chips/antd 封装）
│   ├── hooks/          # 共享 Hooks
│   ├── tokens/         # Design Tokens
│   └── index.ts
└── package.json

packages/antd/          # fork 的 antd 仓库，内部结构沿用上游
└── package.json        # name: @chips/antd
```

### 3.2 官方插件（plugins/）

```
plugins/
├── editor/              # chips.official.editor（编辑引擎）
├── viewer/              # chips.official.viewer（查看器）
└── resource-manager/    # chips.official.resource-manager（资源管理器）
```

- 每个插件目录是一个独立 workspace 包：包名 `@chips/plugin-<目录名>`，根目录含 `manifest.yaml`，构建产物为 `.cpk`。
- 目录名取插件 ID 末段，kebab-case；插件 ID 使用反向域名 `chips.official.<名称>`。
- 插件之间禁止相互 `import`；需要组合时通过 manifest `dependencies` 声明，并通过能力、服务与事件通信。
- 插件不得直接依赖 `@chips/bridge`、`@chips/host` 或任何平台包源码；运行时能力只经 `window.chips` 使用。

### 3.3 工具与示例

```
tools/
├── scaffold/            # 插件脚手架生成器与四角色模板
├── contract-gen/        # 能力/权限/事件 ID 常量生成
├── testing/             # @chips/testing：vitest 工厂、覆盖率口径与聚合门禁
└── gates/               # 门禁脚本（文档、契约、边界、覆盖率）

examples/
└── plugins/
    └── hello-basecard/  # 示例基础卡片插件：manifest.yaml + src/ + package.json
```

示例插件与官方插件使用完全相同的接口、清单与打包链路，不得为示例引入简化写法。

### 3.4 包命名与版本规则

**命名**

| 对象 | 规范 | 示例 |
|---|---|---|
| npm 包 | `@chips/*`；目录名与包名末段一致 | `packages/bridge/` → `@chips/bridge` |
| 私有包 | 不对外发布的包必须 `"private": true` | `@chips/host`、`@chips/bridge` |
| Rust crate | 目录与包名 kebab-case，名以 `chips-` 开头；代码引用时下划线化 | `chips-core` → `chips_core` |
| 官方插件包 | `@chips/plugin-<目录名>`，私有 | `@chips/plugin-editor` |
| 工具包 | 归入 `@chips/*` | `@chips/cli` |

**版本**

- 平台统一版本：`@chips/bridge`、`@chips/host`、`@chips/sdk`、`@chips/ui` 与全部 Rust crate 共用同一版本号，任一平台包发布时统一升版，禁止版本漂移。
- 版本起点为 `0.1.0`，Phase 4 发布 `1.0.0`；第一版发布前不承诺兼容（[ADR-010](../01-架构设计/ADR/ADR-010-大爆炸重构策略.md)）。
- `@chips/antd` 例外：版本跟随上游 antd 主版本，后缀 `-chips.N`（如 `6.0.0-chips.1`），不参与平台统一版本。
- 官方插件独立版本：manifest `version` 按语义化版本独立演进，可单独发布与更新。
- 文件格式 `chip_standards_version` 独立版本，字段定义见 [01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) 与 [02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md)，版本规则见 [04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md)。
- 内部依赖只允许 `workspace:*`（pnpm）与 `version.workspace = true`（Cargo）；禁止写死版本号，禁止 `file:`、`link:` 路径依赖。
- 语义化规则：修复升 patch，向后兼容新增升 minor，破坏性变更升 major；预发布依次使用 `-alpha.N`、`-beta.N`、`-rc.N`。
