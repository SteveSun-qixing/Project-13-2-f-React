## 五、与 fork antd 的关系（仅内部）

### 5.1 包与依赖方向

- `packages/antd-fork` 的包名是 `@chips/antd`，是薯片生态对上游 antd 的 fork；`@chips/ui` 的唯一基础组件依赖（[01-代码组织规范](./01-代码组织规范.md) §3.1、§4.2）。
- `@chips/antd` 唯一合法使用方是 `packages/ui`；其余包、插件与业务代码一律禁止导入，由 ESLint 与构建两道防线拦截（[01-代码组织规范](./01-代码组织规范.md) §6.4、[02-构建与打包](../06-开发与运维/02-构建与打包.md) §5.5）。
- fork 的目标是让基础组件与 Design Tokens 深度集成、去掉生态不需要的能力，并保持与上游一致的组件行为与 API；业务代码把这些组件视为 `@chips/ui` 自己的 API，不感知 fork 版本。

### 5.2 fork 的改造

| 改造 | 说明 |
|---|---|
| 移除多语言与 locale 切换 | 组件文案与日期等格式固定为简体中文；不存在语言包与 i18n 运行时（R5，[ADR-006](../01-架构设计/ADR/ADR-006-主题系统与多语言系统.md)） |
| 深度集成 Design Tokens | 主题令牌由共享层主题实现统一提供，经 `theme.useToken()` 暴露 |
| 移除不需要的组件与能力 | 组件集合按生态需要保留；被移除的组件不在 `@chips/ui` 导出中出现 |

### 5.3 转发规则

- `@chips/ui` 以命名转发暴露基础组件、组件静态成员（如 `Form.useForm`、`Form.Item`）与 Props 类型；组件的受控属性（`disabled`、`status`、`variant` 等）语义与上游一致。
- `theme` 与 `App` 被转发，但用法受限：`theme` 只用 `theme.useToken()`，`App` 只用 `App.useApp()`（第 2.5、2.6 节）。
- 不得从 `@chips/ui` 的导出中寻找 antd 的主题算法、locale、主题包等接口——这些能力在 fork 中已移除或不对业务开放。

### 5.4 版本与升级

- `@chips/antd` 版本跟随上游 antd 主版本、后缀 `-chips.N`；升级由共享层评估并随平台发布生效，业务代码不直接依赖、也不引用其版本（[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §2）。
- `@chips/ui` 与平台统一版本，任一平台包发布时统一升版；第一版发布前不做兼容层与双轨（[ADR-010](../01-架构设计/ADR/ADR-010-大爆炸重构策略.md)）。

### 5.5 构建与样式

- 插件的 `render.js` 必须外部化 `react`、`react/jsx-runtime`、`react-dom`、`react-dom/client`、`@chips/ui` 五个共享模块，由窗口壳与帧运行时的 vendor 模块统一提供（[02-构建与打包](../06-开发与运维/02-构建与打包.md) §5.4、§5.5）。
- 窗口内可出现的全局样式只有 `@chips/ui/global.css`，且只由平台壳窗口渲染层导入；插件不得导入或覆盖全局样式。
- 同一窗口 / 帧内只允许一份 React 与一份 `@chips/ui` 实例；重复打包会使 React 上下文断裂、`ChipsProvider` 与 `CommandProvider` 失效。
