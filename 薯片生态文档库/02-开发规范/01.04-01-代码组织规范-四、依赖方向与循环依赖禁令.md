## 四、依赖方向与循环依赖禁令

### 4.1 分层依赖图

`→` 表示依赖方向：

```
plugins/*  →  @chips/ui、@chips/sdk、window.chips（运行时 Bridge）

packages/host-electron  →  @chips/bridge、@chips/ui、core-rust（chips-native.node）
packages/host-electron  →  插件包（仅经 manifest 加载，不构成包依赖）

packages/sdk  →  @chips/bridge（仅类型）
packages/ui   →  @chips/antd
tools/cli     →  @chips/sdk、@chips/bridge（仅工具链）
```

依赖只能单向向下，禁止反向回指：

- `@chips/ui` 与 `@chips/bridge` 互不依赖，是两个正交基础层。
- `core-rust` 不依赖任何 TypeScript 包；TS 侧只通过 `chips-native.node` 调用 Rust。
- `packages/*` 禁止被插件或工具反向依赖；`tests/` 只能被测试运行器消费。

### 4.2 依赖矩阵

| 消费方 | 允许依赖 | 禁止依赖 |
|---|---|---|
| `plugins/*` | `@chips/ui`、`@chips/sdk`、`window.chips` | 其他 `@chips/*`（含 `@chips/antd`、`@chips/bridge`、`@chips/host`）、其他插件、Node/Electron API |
| `packages/host-electron` | `@chips/bridge`、`@chips/ui`、core-rust 绑定、`electron` | 直接导入 `@chips/antd`、其他包源码 |
| `packages/bridge` | TypeScript 标准库与协议级依赖 | `@chips/ui`、`@chips/sdk`、`@chips/host`、`electron` |
| `packages/sdk` | `@chips/bridge`（仅 `import type`） | `@chips/ui`、`@chips/host`、任何运行时实现 |
| `packages/ui` | `@chips/antd`、`react` | `@chips/bridge`、`@chips/sdk`、`@chips/host` |
| `packages/antd-fork` | `react` 与上游 antd 自身依赖 | 任何 `@chips/*` |
| `core-rust` crates | `chips-core`、`[workspace.dependencies]` 中的 crate | Node/Electron/TS 侧任何包 |
| `tools/*` | `@chips/sdk`、`@chips/bridge`、Node 标准库 | `@chips/host` 内部实现、插件源码 |
| `tests/*` | 任意包（仅测试代码） | 被任何源码反向依赖 |

### 4.3 循环依赖禁令

- 包与包之间、同一包内模块之间，禁止任何形式的循环依赖。
- 检测：TS 侧 ESLint `import/no-cycle` 全仓启用；Rust 侧由编译器强制无环；CI 质量门禁必须通过 `no_circular_dependencies` 检查。
- 打破循环的合法手段：公共类型下沉到 `chips-core`（Rust）或 `@chips/bridge`（TS）；通过能力、事件与服务协作；通过 Cordis 依赖注入（`provide`/`inject`）解耦。
- 禁止用动态 `import()`、重导出或全局注册绕过依赖方向。
