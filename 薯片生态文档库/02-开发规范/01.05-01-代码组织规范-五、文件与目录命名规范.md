## 五、文件与目录命名规范

### 5.1 通用规则

- 目录名一律 kebab-case，禁止空格、下划线、中文（`docs/` 内文档除外）。
- 禁止仅靠大小写区分文件或目录；同一目录内不得出现仅大小写不同的名称，保证 macOS/Windows 行为一致。
- 每个包只有一个公开入口：TS 为 `src/index.ts`，Rust 为 `src/lib.rs`；入口只做导出聚合，禁止写实现逻辑。
- 源码必须位于包的 `src/` 内；插件根目录只允许额外的 `manifest.yaml` 与静态资源目录。

### 5.2 TypeScript 包

| 对象 | 规范 | 示例 |
|---|---|---|
| React 组件 | PascalCase `.tsx` | `CardTile.tsx` |
| 类、主要模块 | PascalCase `.ts` | `PluginManager.ts` |
| 工具函数、Hook、多词模块 | kebab-case `.ts` | `parse-card.ts`、`use-card-data.ts` |
| 包入口 | `index.ts` |  |
| 类型文件 | `types.ts` 或 `types/<域>.ts` | `types/card.ts` |
| 单元测试 | `<被测文件名>.test.ts` | `parse-card.test.ts` |
| 组件测试 | `<组件名>.test.tsx` | `CardTile.test.tsx` |
| 端到端测试 | `<场景>.spec.ts` | `card-editor.spec.ts` |

组件目录内部结构（`index.tsx`、`types.ts`、`hooks.ts` 等）以 [React 组件开发规范](./03-React组件开发规范.md) 为准。

### 5.3 Rust crate

| 对象 | 规范 | 示例 |
|---|---|---|
| crate 目录 | kebab-case，与 crate 名一致 | `crates/chips-core/` |
| 模块文件 | snake_case `.rs` | `resource_manager.rs` |
| crate 入口 | `src/lib.rs` |  |
| 单元测试 | 被测模块同文件 `#[cfg(test)] mod tests` | `src/parser.rs` 内 |
| 集成测试 | crate 内 `tests/`，snake_case `.rs` | `tests/parse_card.rs` |
| 基准测试 | crate 内 `benches/`，snake_case `.rs` | `benches/parse_bench.rs` |

Rust 代码中的引用路径：包内用 `crate::` 绝对路径，跨包用 crate 名（下划线形式，如 `chips_core::`）。

### 5.4 文档与资源

| 对象 | 规范 | 示例 |
|---|---|---|
| 普通文档 | `NN-名称.md`，编号顺延 | `01-代码组织规范.md` |
| ADR 文档 | `ADR-NNN-标题.md` | `ADR-008-React加fork-antd前端技术栈.md` |
| 静态资源 | kebab-case，放包内 `assets/` | `default-avatar.png` |
| 插件清单 | 固定 `manifest.yaml` |  |

代码与资源文件禁止使用中文名；文档库允许中文目录与文件名（R15）。
