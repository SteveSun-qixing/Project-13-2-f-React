## 十四、Neon 绑定

### 14.1 导出函数

```rust
use neon::prelude::*;

fn parse_card(mut cx: FunctionContext) -> JsResult<JsObject> {
    let path = cx.argument::<JsString>(0)?.value(&mut cx);

    let card = match parse_card_internal(&path) {
        Ok(card) => card,
        Err(e) => return cx.throw_error(e.to_string()),
    };

    let obj = cx.empty_object();
    let id = cx.string(&card.id);
    obj.set(&mut cx, "id", id)?;

    Ok(obj)
}

#[neon::main]
fn main(mut cx: ModuleContext) -> NeonResult<()> {
    cx.export_function("parseCard", parse_card)?;
    Ok(())
}
```

### 14.2 绑定约定

- 绑定层只做类型转换与错误映射；业务逻辑必须位于纯 Rust 核心（见 [ADR-003](../01-架构设计/ADR/ADR-003-Rust核心加Node-Native-Module架构.md)）。
- 绑定函数禁止 `unwrap()` / `expect()` / `panic!()`：跨 FFI 边界的 panic 会导致进程终止，错误必须经 `JsResult` / `throw_error` 返回。
- Rust 函数名使用 snake_case；JS 侧导出名使用 camelCase（如 `parseCard`）。
- JS 值具有线程亲和性：异步任务完成后必须经 `Channel` 回到 Node 主线程再操作 JS 值。
- `#[neon::main]` 是原生模块唯一入口，导出表在入口函数中集中声明。
