## 五、集成测试

集成测试使用真实实现，覆盖跨包链路；平台调用不得再用 Mock 替代真实 Bridge 或真实 Rust 绑定。

### 5.1 TypeScript 集成测试

```typescript
// tests/integration/document/card-open.test.ts
import { describe, expect, it } from 'vitest';
import { documentContent, documentClose, documentMetadata, openCard } from '../../../packages/host/native';

describe('文档解析（真实 Rust 绑定）', () => {
  it('打开目录态卡片并读取 metadata 与主内容', async () => {
    const handle = await openCard('tests/fixtures/cards/basic.card');
    try {
      const metadata = await documentMetadata(handle);
      expect(metadata.kind).toBe('card');
      expect(metadata.diagnostics.filter((item) => item.severity === 'error')).toHaveLength(0);

      const content = await documentContent(handle, 'main');
      expect(content.kind).toBe('content');
    } finally {
      await documentClose(handle);
    }
  });
});
```

- 跨包集成测试位于 `tests/integration/`，夹具放 `tests/fixtures/`；平台包测试可以依赖真实实现（[01-代码组织规范](./01-代码组织规范.md) §9.2）。
- Bridge 全链路集成在构建 `chips-native.node` 后执行，覆盖会话解析、权限判定、schema 校验与错误归一。

### 5.2 Rust 集成测试

```rust
// tests/integration/document_card.rs
use chips_parser::{open_document, ParseOptions, ValidationStatus};
use std::path::Path;

#[test]
fn validates_fixture_card() {
    let path = Path::new("tests/fixtures/cards/basic.card");
    let handle = open_document(path, &ParseOptions::default()).expect("目录态卡片应可打开");
    let report = handle.validate().expect("校验可执行");
    assert_ne!(report.status, ValidationStatus::Invalid);
}
```

### 5.3 帧协议契约测试

查看态与编辑态的全部帧消息必须按[05-渲染引擎设计](../01-架构设计/01-子系统设计/05-渲染引擎设计.md) §9 的封套与消息清单做契约测试：

- 覆盖：`frame:ready` / `frame:height` / `frame:entry-request` / `frame:action` / `frame:error` 与 `host:init` / `host:update` / `host:entries` / `host:height-ack` / `host:action-error` / `host:dispose` 的字段、方向与 `protocol` 值（`chips-frame/1`）。
- 判定：消息类型与字段集合之外不得有多余字段；越级发送（条目帧越过布局帧直接请求 RenderHost）、重复 `frame:ready`、`epoch` / `revision` 非递增必须被判定为 `RENDER_PROTOCOL_VIOLATION`。
- 实现：以真实帧运行时（`dist/frame/`）加载协议夹具；测试用例随契约测试执行（`pnpm test:contract`），协议版本升级必须同 PR 更新用例与渲染引擎文档。

### 5.4 角色接口契约快照

四类插件角色接口与 SDK 导出面通过快照测试冻结，防止无意破坏：

- 覆盖：`@chips/sdk` 导出清单与类型签名（含 `IBaseCardEditor` / `ILayoutEditor` / `BaseCardView` / `BoxRenderView` / `IAppBridge` / `IServiceBridge` 等）、四种角色入口对象的形状、`.cpk` 入口默认导出形状、核心 `coreAbiVersion` 与导出函数总表。
- 判定：快照与实现比对无差异；任何导出面变更必须在同一 PR 更新快照、接口文档与 `CORE_ABI_VERSION`，并在 PR 说明变更理由（G8）。
- 实现：vitest 快照 + `cargo test -p chips-native` 导出面断言；快照文件入库，禁止无审阅的批量更新。

### 5.5 插件兼容测试

平台接口、帧协议或能力集发生变更时，官方插件与示例插件必须验证兼容：

- 覆盖：`plugins/` 下官方插件与 `examples/plugins/` 的示例插件在本平台版本上完成加载、渲染与关键调用（复用各自现有测试与其 E2E 冒烟）。
- 判定：插件不得因平台侧变更出现能力缺失、schema 不匹配或路径不兼容；不通过即阻断平台变更，禁止通过修改测试掩盖。
- 阶段要求：Phase 3 起官方插件纳入兼容矩阵；平台主版本变更必须全量运行矩阵。

### 5.6 迁移工具矩阵

按[04-版本与迁移规范](../04-文件格式规范/04-版本与迁移规范.md) §六维护迁移工具的版本矩阵：

- 覆盖：每个受支持的历史格式版本 × 目录态/归档态两个形态；旧版 `.card` / `.box` 夹具逐一迁移。
- 判定：逐文件报告完整，输出逐个通过解析器 `validate`，资源清单的尺寸与哈希全量核对一致；失败不留下半成品。
- 实现：`tests/integration/migration/` 下的参数化用例，夹具按版本分目录；新增格式版本必须同 PR 扩充矩阵。
