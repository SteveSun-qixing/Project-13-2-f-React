# 代码组织规范

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：薯片生态 Monorepo 的顶层目录、包划分、依赖方向、文件命名、导入路径、构建产物、脚本与测试文件组织

---

## 十、强制规则

### 10.1 必须遵守

1. 所有源码必须位于 `packages/`、`plugins/`、`tools/`、`examples/`、`tests/` 之一；仓库根禁止源码。
2. 平台包只允许 3.1 列出的六个；新增顶层包必须先走 RFC → ADR。
3. 依赖必须符合 4.2 依赖矩阵；禁止任何循环依赖。
4. 组件、Hooks、Design Tokens 只能从 `@chips/ui` 导入；`@chips/antd` 仅 `packages/ui` 可用。
5. 跨包导入使用包名与公开入口；禁止相对路径穿透包边界。
6. 文件与目录命名符合第五章；不得出现仅大小写不同的名称。
7. 构建产物全部落在第七章约定目录，且不得入库。
8. 每个包提供 `build`、`test`、`lint`、`clean` 标准脚本，有测试的包提供 `test:coverage`，承载契约快照的包提供 `test:contract`；根脚本只做聚合。
9. 测试文件位置与命名符合第九章。
10. 文档与代码必须在同一 PR 中更新。

### 10.2 禁止行为

```
❌ 在仓库根、docs/ 或五个源码目录（packages/、plugins/、tools/、examples/、tests/）之外散落源码
❌ import { Button } from 'antd' / '@chips/antd'（packages/ui 除外）
❌ 插件直接 import 其他插件、@chips/bridge、@chips/host 或 Node/Electron API
❌ 相对路径穿透包边界（../../packages/ui/src/...）
❌ 提交 dist/、target/、*.node、*.cpk、coverage/、release/
❌ 循环依赖，或用动态 import()、重导出绕过依赖方向
❌ 写死内部依赖版本（file:/link:/具体版本号）
```
