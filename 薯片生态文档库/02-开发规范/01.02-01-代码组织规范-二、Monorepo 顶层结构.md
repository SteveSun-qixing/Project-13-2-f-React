## 二、Monorepo 顶层结构

### 2.1 目录树

```
薯片生态文档库/                       # 《薯片生态文档库》根，与本仓库同级（工作区根，结构与编号见 2.4）
├── 00-愿景与原则/ … 08-产品与交互/    # 文档库分区（完整清单见 2.4）
└── README.md                        # 文档库索引与导航

chips-ecosystem/                     # 仓库根：只放工作区配置与工程文档，禁止存放源码
├── packages/                        # 平台包（见 3.1）
│   ├── core-rust/                   # Rust 核心（crate 列表见 3.1）
│   ├── native/                      # Neon 绑定包（构建脚本、ABI 与类型视图）
│   ├── bridge/                      # Bridge TypeScript 协议与桥接层
│   ├── host/                        # @chips/host：Electron 壳应用
│   ├── sdk/                         # @chips/sdk
│   ├── ui/                          # @chips/ui
│   ├── antd/                        # @chips/antd（fork antd）
│   └── cli/                         # @chips/cli（开发者 CLI）
├── plugins/                         # 官方插件源码（见 3.2）
│   ├── basecards/                   # 基础卡片插件族
│   ├── layouts/                     # 箱子布局插件族
│   ├── services/                    # 服务/模块插件族
│   └── apps/                        # 官方应用插件族
├── server/                          # 服务端产品顶层目录（W6 迁移落位，骨架约定见 2.2 表）
│   ├── community/                   # 社区平台服务器（产品内包划分见《社区平台设计》§2.2）
│   └── personal/                    # 个人服务器（产品内包划分见《个人服务器设计》§二）
├── tools/                           # 工具链（见 3.3）
│   ├── scaffold/                    # 插件脚手架生成器与四角色模板
│   ├── contract-gen/                # 能力/权限/事件 ID 常量生成
│   ├── testing/                     # @chips/testing：覆盖率口径与聚合门禁
│   └── gates/                       # 门禁脚本（文档/契约/边界/覆盖率/入口）
├── examples/                        # 示例
│   └── plugins/                     # 示例插件（hello）
├── tests/                           # 跨包测试工作区包与共享夹具（见 8.3、第九章）
│   ├── contract/                    # @chips/contract-tests：契约快照与一致性判定
│   ├── e2e/                         # @chips/e2e：Playwright 全链路用例与夹具
│   ├── perf/                        # @chips/perf：性能基线
│   ├── unit/                        # 规划：无法归属单个包的跨包单元测试（见 9.1）
│   ├── integration/                 # 规划：跨包集成测试（见 9.1）
│   └── fixtures/                    # 规划：共享夹具（见 9.1）
├── docs/                            # 本仓工程过程文档与模板（不是《薯片生态文档库》分区）

│   └── workflows/                   # 规划：CI/CD 工作流配置（本地等价入口为根 `pnpm ci`，见 8.2）

├── package.json                     # Node workspace 根清单与统一脚本入口（见 8.2）

├── tsconfig.base.json               # 全仓 TypeScript 共享配置与 `@chips/*` 解析锚定
```

`server/` 为服务端产品顶层目录（两产品目录随 W6 服务端迁移落位，本节先行登记骨架约定）：目录名沿用既有顶层命名文法（小写 kebab-case，见[文件与目录命名规范](./01.05-01-代码组织规范-五、文件与目录命名规范.md) §一）；不采用 `apps/server` 形态——`apps` 语义已由 `plugins/apps/`（官方应用插件族）占用，服务端产品不是插件，而是平台进程之外、经 HTTP 与传输协议接入的独立部署单元（[整体架构图](../01-架构设计/00-整体架构图.md) §2.4）。`server/community` 与 `server/personal` 两产品的归属为既有在册裁决（工作区根《重构大计划/02-仓库映射与新工作区.md》§一），本节为其在文档库结构契约中的登记位。

### 2.2 顶层目录职责

| 目录 | 职责 | 约束 |
|---|---|---|
| `packages/` | 平台包 | 只允许 3.1 列出的八个包；新增包必须先走 RFC → ADR |
| `plugins/` | 官方插件源码与 `.cpk` 打包入口 | 插件之间禁止相互依赖，组合通过 manifest `dependencies` 与能力/服务完成 |
| `server/` | 服务端产品根：`server/community/`（社区平台服务器）、`server/personal/`（个人服务器） | 平台进程之外独立部署，不加载 Cordis、不注册能力、不接收平台事件；产品内包划分以[社区平台设计](../01-架构设计/01-子系统设计/14-社区平台设计.md) §2.2 与[个人服务器设计](../01-架构设计/01-子系统设计/15-个人服务器设计.md) §二为权威；`packages/`、`plugins/`、`tools/`、`examples/`、`tests/` 不得依赖 `server/`；工作区成员 glob（[八、常用脚本约定](./01.08-01-代码组织规范-八、常用脚本约定.md) §8.3）随目录落盘同步登记 |
| `tools/` | 开发者工具与自动化脚本 | 禁止被 `packages/` 运行时依赖；工具不得进入发布产物 |
| `examples/` | 教学示例 | 禁止被其他目录依赖；示例必须走正式接口 |
| `tests/` | 跨包测试工作区包与共享夹具 | 禁止被源码 `import`；测试文件不得进入发布产物 |
| `docs/` | 本仓工程过程文档与模板（流程、制品模板、波次记录） | 不是《薯片生态文档库》分区，不承载任何技术契约；接口、格式、字段、错误码、数值基线一律链接文档库（见 2.4） |
| `.github/` | CI/CD 工作流 | 门禁项引用测试规范与质量门禁基线 |

### 2.3 根目录配置文件

- `package.json`：`"private": true`；只声明工作区与工具链级 `devDependencies`，禁止声明业务依赖；`scripts` 只做聚合与排序（见 8.2）。
- `pnpm-workspace.yaml`：声明全部工作区成员（见 8.3）；Node 生态唯一包管理器为 pnpm，禁止 npm/yarn 混用。
- `Cargo.toml`：Rust workspace 根清单（见 8.3）；`[workspace.dependencies]` 统一第三方 crate 版本，`[workspace.package]` 统一版本、许可证与 edition。
- `tsconfig.base.json`：全仓共享的 `compilerOptions`、`paths` 解析锚定与项目引用配置；所有 TS 包必须以 `"extends": "../../tsconfig.base.json"` 继承，禁止在包内重复定义共享选项。
- `tsconfig.json`：`tsc -b` 的 solution 入口，只声明 `references`、不包含源码（[02-构建与打包](../06-开发与运维/02-构建与打包.md) §5.2）。
- `eslint.config.mjs`：ESLint 9 扁平配置，全仓唯一 lint 判定面；包目录内不得再放置独立 ESLint 配置（[TypeScript 编码规范](./02-TypeScript编码规范.md) §十一）。
- 锁文件：`pnpm-lock.yaml` 与 `Cargo.lock` 必须提交，保证构建可复现。
- 根目录禁止出现：业务源码、`src/`、包级测试、构建产物。

### 2.4 文档库位置与目录

《薯片生态文档库》是生态公共契约的唯一发布位置，落位在**工作区根**（与 `chips-ecosystem/` 仓库目录同级，路径 `薯片生态文档库/`），不进入仓库工作区，也不作为任何 workspace 成员；仓库内代码与工程文档只以相对路径链接该库，禁止复制其契约内容。文档库内部固定 9 个分区，不得增减或改名：

```
薯片生态文档库/
├── 00-愿景与原则/
├── 01-架构设计/
│   ├── ADR/
│   └── 01-子系统设计/
├── 02-开发规范/
├── 03-插件开发/
├── 04-文件格式规范/
├── 05-接口与契约/
├── 06-开发与运维/
├── 07-工程管理/
├── 08-产品与交互/
└── README.md
```

- 文档命名：普通文档 `NN-名称.md`，ADR 为 `ADR-NNN-标题.md`；编号在分区内顺延，已用编号不复用。
- 需要移除的文档移入就近 `归档/` 目录，禁止直接删除。
- 索引与导航统一维护在 `README.md`，见 [文档库索引](../README.md)；写作要求见 [文档编写规范](./07-文档编写规范.md)。
- 仓库内 `docs/` 目录（`chips-ecosystem/docs/`）只放工程过程文档与制品模板，其定位与维护规则见该目录自身 README，不得作为契约来源。
