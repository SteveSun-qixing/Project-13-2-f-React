## 十一、测试

### 11.1 单元测试

**测试放在同一文件**：

```rust
// src/card.rs

pub fn parse_title(input: &str) -> Option<String> {
    // ...
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_parse_title_valid() {
        let result = parse_title("# 标题");
        assert_eq!(result, Some("标题".to_string()));
    }

    #[test]
    fn test_parse_title_empty() {
        let result = parse_title("");
        assert_eq!(result, None);
    }

    #[test]
    #[should_panic(expected = "标题为空")]
    fn test_parse_title_invalid() {
        parse_title("invalid").expect("标题为空");
    }
}
```

**要求**：单元测试与实现放在同一文件；测试命名使用 `test_<被测对象>_<场景>`；测试代码允许使用 `unwrap()`。

---

### 11.2 集成测试

**跨模块流程放在 `tests/` 目录**：

```rust
// tests/integration_test.rs
use chips_core::*;

#[test]
fn test_full_workflow() {
    let card = Card::new("test");
    let serialized = serialize_card(&card).unwrap();
    let deserialized = deserialize_card(&serialized).unwrap();
    assert_eq!(card, deserialized);
}
```

### 11.3 基准测试

**性能关键路径必须有基准测试，统一使用 criterion**：

```rust
use criterion::{black_box, criterion_group, criterion_main, Criterion};

fn benchmark_parse(c: &mut Criterion) {
    c.bench_function("parse_card", |b| {
        b.iter(|| parse_card(black_box(INPUT)));
    });
}

criterion_group!(benches, benchmark_parse);
criterion_main!(benches);
```

**要求**：

- 基准测试放在 `benches/` 目录，并在 `Cargo.toml` 声明：

```toml
[[bench]]
name = "parse_card"
harness = false
```

- 基准输入必须使用 `black_box`，避免编译器优化掉被测逻辑；运行命令为 `cargo bench`。
- 基准不得进入生产构建产物。

### 11.4 测试覆盖率

**目标：> 80%（质量门禁，与[《架构原则》](../00-愿景与原则/01-架构原则.md) 第 4.1 节一致）**

```bash
# 使用 cargo-tarpaulin 测量覆盖率
cargo install cargo-tarpaulin
cargo tarpaulin --out Html
```

**要求**：新增代码不得拉低整体覆盖率；覆盖率不达标的模块不得合入。
