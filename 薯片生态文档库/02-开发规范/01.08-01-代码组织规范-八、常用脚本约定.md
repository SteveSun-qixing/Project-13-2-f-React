## 八、常用脚本约定

### 8.1 标准脚本

根脚本只做聚合与排序，禁止包含具体业务逻辑；每个 workspace 包必须提供 `build`、`test`、`lint`、`clean` 四个基础标准脚本，有测试的包提供 `test:coverage`，承载契约快照的包提供 `test:contract`；有开发态的包提供 `dev`，有发布产物的包提供 `package`；`docs:check` 是仓库根的文档维护脚本。

| 脚本 | 语义 |
|---|---|
| `dev` | 启动开发环境：Electron 壳 + 渲染层热更新 + Rust 增量编译 |
| `build` | 全量构建：Rust → TS 包 → 插件，按依赖拓扑顺序执行 |
| `test` | 全量测试：TS 单元/集成 + Rust 单元/集成 |
| `test:coverage` | 覆盖率测量聚合入口：由 `@chips/testing` 统一驱动 TS（vitest + v8）与 Rust（cargo-tarpaulin）测量并输出 `coverage/` 报告，判定唯一执行面为 G6（[测试规范](./05-测试规范.md) §十、[05-CICD与质量门禁](../06-开发与运维/05-CICD与质量门禁.md) §3.2） |
| `test:contract` | 契约一致性测试：核心导出面、能力/事件契约、角色接口快照与帧协议契约（[测试规范](./05-测试规范.md) §五、[05-CICD与质量门禁](../06-开发与运维/05-CICD与质量门禁.md) G8） |
| `lint` | ESLint + Prettier 检查 + `cargo fmt --check` + `cargo clippy -D warnings` |
| `typecheck` | `tsc -b` solution 构建 + 逐包 `tsc --noEmit`，含声明文件一致性 |
| `package` | 生成三端安装包与 `.cpk` |
| `clean` | 删除 `dist/`、`target/`、`coverage/`、`release/` |
| `docs:check` | 文档库门禁：相对链接、索引收录、文档头与公开 API 文档覆盖率检查（[05-CICD与质量门禁](../06-开发与运维/05-CICD与质量门禁.md) G12） |

根级另有门禁与流水线聚合脚本（判定依据见 [05-CICD与质量门禁](../06-开发与运维/05-CICD与质量门禁.md)）：`gates:docs`、`gates:contracts`、`gates:boundaries`、`gates:coverage`、`gates:entries`（G12/G8/G9/G6 与构建期入口校验，逐项对应 `tools/gates/` 下同名脚本）、`gates:all`（工作区级门禁串行聚合）、`gates:test`（门禁脚本自测）、`report:coverage`（覆盖率测量聚合与报告渲染，判定委托 G6）、`ci`（lint → typecheck → test → test:contract → build → gates:all 全链流水线）。这些脚本只做聚合与判定，不含业务逻辑。

### 8.2 根 package.json（节选）

```json
{
  "name": "chips-ecosystem",
  "private": true,
  "packageManager": "pnpm@9",
  "scripts": {
    "dev": "pnpm --filter @chips/host dev",
    "build": "cargo build --workspace --release && pnpm -r --filter \"./packages/*\" --filter \"./plugins/*\" --filter \"./plugins/*/*\" run build",
    "test": "cargo test --workspace && pnpm -r run test",
    "test:coverage": "pnpm --filter @chips/testing run coverage",
    "report:coverage": "pnpm --filter @chips/testing run report",
    "test:contract": "cargo test -p chips-native && pnpm -r run test:contract",
    "test:e2e": "playwright test --config tests/e2e/playwright.config.ts",
    "lint": "eslint . && prettier --check . && cargo fmt --all -- --check && cargo clippy --workspace --all-targets -- -D warnings",
    "typecheck": "tsc -b && pnpm -r run typecheck",
    "package": "pnpm -r run package",
    "clean": "pnpm -r run clean && cargo clean",
    "docs:check": "node tools/gates/check-docs.mjs",
    "gates:all": "node tools/gates/gates-all.mjs",
    "gates:test": "node --test \"tools/gates/tests/**/*.test.mjs\"",
    "ci": "pnpm run lint && pnpm run typecheck && pnpm run test && pnpm run test:contract && pnpm run build && pnpm run gates:all"
  }
}
```

`pnpm -r` 默认按 workspace 依赖拓扑排序，禁止用固定顺序手工罗列包名。覆盖率判定唯一执行面为 G6 `tools/gates/check-coverage.mjs`，`@chips/testing` 负责测量聚合与报告渲染并委托 G6 取得判定（[05-CICD与质量门禁](../06-开发与运维/05-CICD与质量门禁.md) §3.2）。

### 8.3 工作区清单

```yaml
# pnpm-workspace.yaml
packages:
  - 'packages/*'
  - 'plugins/*'
  - 'plugins/*/*'
  - 'tools/*'
  - 'tests/*'
  - 'examples/plugins/*'
```

`tests/*` 与 `examples/plugins/*` 同为工作区成员：`tests/contract`（`@chips/contract-tests`）、`tests/e2e`（`@chips/e2e`）、`tests/perf`（`@chips/perf`）必须随 `pnpm install` 纳入工作区，否则跨包契约、E2E 与性能基线三包脱离拓扑排序与聚合脚本；`plugins/*/*` 覆盖 `plugins/<角色>/<插件>` 两级官方插件目录（见 3.2）。

```toml
# Cargo.toml（仓库根）
[workspace]
resolver = "2"
members = ["packages/core-rust/crates/*", "packages/native"]

[workspace.package]
version = "0.1.0"
edition = "2021"
rust-version = "1.75"
license = "MIT OR Apache-2.0"

[workspace.dependencies]
serde = { version = "1", features = ["derive"] }
thiserror = "1"
```

`members` 覆盖 `packages/core-rust/crates/*` 全部 crate 与 Neon 绑定包 `packages/native`；`rust-version`、release profile、clippy 阈值等编译选项以 [Rust 编码规范](./04-Rust编码规范.md) 为准；TS 严格选项与 ESLint/Prettier 规则内容以 [TypeScript 编码规范](./02-TypeScript编码规范.md) 为准。
