## 一、定位与边界

### 1.1 定位

本文是设计资产（图标、字体与上游素材）的唯一权威规范，覆盖：

- 图标分层：应用、启动器、卡片类型、布局、托盘五层资产各自的载体、命名与消费链路；
- 设计源格式与命名：SVG 设计源、工程内资产与清单引用的命名基线；
- 生成链路：上游字形（锁定提交）→ SVG 设计源 → PNG/ICO/ICNS 位图容器 → 工程内资产 → 溯源文件的单向派生链路，以及上游缓存策略；
- 尺寸与安全区：画布、档位、安全区、ICO/ICNS 容器维度与载荷矩阵、平台消费矩阵；
- 遗留单元归档处置与接收策略：遗留图层与素材的归档目标、触发条件、归档规则与准入口径；
- 字体与上游素材许可证登记：界面字体口径与设计素材的上游、锁定提交、许可证登记；
- 资产目录与禁止事项、约束与自检清单。

使用者：设计资产维护者、插件开发者、打包与发布流水线、安装与启动链路实现者。

### 1.3 术语

| 术语 | 定义 |

## 二、图标分层

### 2.1 分层总表

| 层 | 资产 | 声明 / 入口 | 设计源目录 | 工程内基线 | 消费方 |
|---|---|---|---|---|---|
| L1 应用图标 | 应用插件图标四件套 | 无独立字段；随包发布 | `design-assets/Appicon/` | `<工程>/assets/icons/app-icon.{svg,png,ico,icns}` | 安装器、系统入口与治理展示 |
| L2 启动器图标 | 启动器入口图标 | `ui.launcher.icon` | `design-assets/Appicon/` | `assets/icons/app-icon.*` | 启动台、桌面快捷方式、插件治理列表 |
| L3 卡片类型图标 | 卡片类型选择图标 | `capabilities.cardTypes[].icon` | `design-assets/Basecardicon/`（身份图标） | `assets/icons/<类型短名>.svg`、`assets/icons/basecard-icon.*` | 编辑引擎卡箱库、查看器、治理列表 |
| L4 布局类型图标 | 布局类型选择图标 | `capabilities.layouts[].icon` | `design-assets/Layouticon/`（身份图标） | `assets/icons/<布局短名>.svg`、`assets/icons/layout-icon.*` | 编辑引擎卡箱库、布局选择与治理 |
| L5 托盘图标 | 托盘位图 | `tray:set.iconUri` | 无设计源链路（插件自备） | `assets/icons/tray-icon.png`（及 2x） | 系统托盘（菜单栏 / 通知区域） |

- 每一层只使用本层规定的载体；不得跨层复用文件路径（例如不得把卡片类型图标用作用户入口图标）。
- 分层之外的图片资源（插件自备插画、封面占位图等）不构成本文定义的图标层，仍受 §七 目录与禁止事项约束。

### 2.2 应用图标（L1）

- 载体：插件工程 `assets/icons/app-icon.{svg,png,ico,icns}`；脚手架模板 `Chips-Scaffold/chips-scaffold-app/templates/app-standard/assets/icons/` 提供同名四件套与 `SOURCE.md.tpl`。
- 发布基线：
  - 平台内置插件与官方应用插件：四件套齐全（`.svg`、`.png`、`.ico`、`.icns`）；
  - 第三方应用插件：必须提供 `.svg` 与 `.png`，并为所支持平台提供容器（macOS 需 `.icns`、Windows 需 `.ico`）。
- 消费链路：
  - 安装与分发：macOS 安装器把设置面板插件的 `assets/icons/app-icon.icns` 复制为平台 App 的 `AppIcon.icns`（`Chips-Host/src/main/installer/macos-installer.ts:942-967`）；
  - 系统入口：桌面快捷方式 / 启动台入口经启动器解析链（§2.3）取图标文件路径（`Chips-Host/src/main/services/register-host-services.ts:2764-2812`）；
  - 治理展示：插件治理与快捷方式视图返回解析后的 `iconPath`；
  - 应用窗口不设置插件级窗口图标：manifest 无对应字段，平台壳不按插件图标创建窗口。
- 四件套必须同批生成、同源同框；禁止只更新其中一个扩展名。

### 2.3 启动器图标（L2）

- 声明字段 `ui.launcher.icon`（可选）：省略整个 `ui.launcher` 时不注册启动器入口；声明即注册，字段语义与校验以 [02-插件清单规范](../03-插件开发/02-插件清单规范.md) §7.4 为准；运行时视图经 `chips-resource://<pluginId>/...` 解析（[07-应用插件接口](../05-接口与契约/07-应用插件接口.md) §5.3）。
- 声明基线：应用图标基名固定为 `app-icon`（生成链路、工程资产与平台回退一致）；清单声明指向 `assets/icons/app-icon.png` 或 `assets/icons/app-icon.svg`，声明值必须是包内相对 POSIX 路径且位于 `assets/` 内。不声明平台专属容器（`.ico` / `.icns`）作为清单值——容器由平台变体解析链选择。
- 平台变体解析顺序（正式契约，`Chips-Host/src/main/services/register-host-services.ts:1357-1371`）：

| 平台 | 扩展名优先级 |
|---|---|
| macOS（`darwin`） | `.icns` → `.png` → `.ico` → `.svg` |
| Windows（`win32`） | `.ico` → `.png` → `.svg` → `.icns` |
| 其他（Linux 等） | `.png` → `.svg` → `.ico` → `.icns` |

- 解析算法：先按平台优先级探测与声明文件同基名的变体，声明路径本身最后兜底（`register-host-services.ts:1380-1408`）；未声明或声明目标全部缺失时，按 `assets/icons/app-icon.<ext>`、`assets/icons/icon.<ext>` 顺序探测。
- 治理展示链（快捷方式视图与插件治理接口返回 `iconPath`）使用固定优先级 `.png` → `.svg` → `.ico` → `.icns`（`register-host-services.ts:1373-1435`）；缺失时前端回退到 `@chips/ui` 统一图标组件，不显示 emoji 与路径文本（[05-生态设置面板设计](../08-产品与交互/05-生态设置面板设计.md) §四）。
- 系统入口（桌面快捷方式 / 启动台）只对 `app` 角色创建；创建与移除经平台治理接口，面板与插件不得自行写入系统文件。

### 2.4 卡片类型图标（L3）

- 声明字段 `capabilities.cardTypes[].icon`（可选，包内 `assets/` 内相对路径）：供类型选择器与插件市场展示，编辑引擎卡箱库消费同一清单（[08-基础卡片插件接口](../05-接口与契约/08-基础卡片插件接口.md) §6.1、[01-编辑引擎产品与交互设计](../08-产品与交互/01-编辑引擎产品与交互设计.md) §4.2）。
- 命名：每个卡片类型一个独立文件，`assets/icons/<类型短名>.svg`（如 `richtext.svg`、`video.svg`）；同一插件声明多个类型时不得共用同一文件。
- 身份四件套 `assets/icons/basecard-icon.{svg,png,ico,icns}` 是插件静态身份资产，用于物料清点、治理与后续展示链路；它不是清单引用链路，清单 `icon` 与身份四件套不得互相替代。
- 运行时选择器与治理列表渲染统一走 `@chips/ui` 图标出口（[09-统一视觉规范](./09-统一视觉规范.md) §四 V12、[08-@chips-ui共享层使用指南](./08-@chips-ui共享层使用指南.md) §2.6）；不得在插件内维护第二套图标映射表。

### 2.5 布局类型图标（L4）

- 声明字段 `capabilities.layouts[].icon`（可选，包内 `assets/` 内相对路径）：随 `.cpk` 分发，经插件作用域访问（[09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) §2、§6）。
- 命名：每个布局类型一个独立文件，`assets/icons/<布局短名>.svg`（如 `grid.svg`、`list.svg`）；身份四件套 `assets/icons/layout-icon.{svg,png,ico,icns}` 的定位与 §2.4 身份四件套相同。
- 布局运行时图标仍以布局定义的图标描述为准，由 `@chips/ui` 统一渲染；静态身份四件套不进入运行时渲染链路。

### 2.6 托盘图标（L5）

- 载体与入口：`tray:set` 的 `iconUri`（`chips-resource://` 引用，可选）；权限 `tray:manage`，仅 `app` 角色可申请（[04-能力契约规范](../05-接口与契约/04-能力契约规范.md) §7.9、[02-插件清单规范](../03-插件开发/02-插件清单规范.md) §六）。
- 资产要求：
  - 位于插件包内 `assets/`，经 `chips-resource://<plugin-scope>/assets/icons/...` 引用；插件不得自行拼接作用域 URI；
  - 基线格式为 PNG（透明背景），提供 `tray-icon.png`（16×16）与 `tray-icon@2x.png`（32×32）两档；
  - 不使用 `.ico` / `.icns` 容器作为托盘资产；不使用白底底板；macOS 菜单栏模板图像使用单色透明 PNG；
  - `iconUri` 缺省时仅更新 `tooltip` / `visible`，托盘沿用既有图标。
- `ui.surface: tray` 的应用在平台注册托盘后，应在 `launch` 阶段完成首次 `tray:set`，保证托盘图标与菜单就绪（[07-应用插件接口](../05-接口与契约/07-应用插件接口.md) §5.7）。

#### 2.8.2 归档规则

- 单元粒度：一个可独立说明的目录为一个归档单元；禁止把多个遗留目录合并成一个单元，禁止在归档目录内嵌套多重无语义层级。
- 移动方式：全量原样移动并保留原目录名与全部文件（含 `SOURCE.md`、许可证与来源说明），不复制、不删减、不重写内容；归档内容只读。
- 归档说明：每个单元一份 `归档说明.md`，字段与写法按[归档与发布记录](../07-工程管理/04-归档与发布记录.md) §2.5；状态只取 `保留` / `已替代` / `待处置`。
- 索引登记：归档动作同批更新工作区总索引 `归档/README.md`，索引字段按该文 §2.4。
- 引用清理：移动前全仓检索旧路径（文档、脚本、清单、索引）；仍被现役工程引用的单元不得先行移动，必须与引用方退役同批执行；引用归档内容时必须标注"仅存档、不作为依据"。
- 链路与构建禁令：归档单元不得出现在 `ICON_TARGETS`、生成 / 同步脚本、清单声明与任何构建产物中（§4.4、§7.3）。

#### 2.8.3 接收策略

"接收"指归档对退役素材的准入：满足以下全部条件的单元才可进入归档，不满足时不得以"先存放"为由堆入现役目录。

1. 完整性：单元自带来源说明（`SOURCE.md`）与全部许可证文件；第三方素材缺任一许可证文件时先补齐再接收。
2. 单一来源：一个基名只接收一个单元；同一素材的现役副本（如工程侧同步产物）不重复接收，由现役工程自行处置。
3. 归属清楚：单元有明确退役依据（ADR 编号或裁决条目）与替代者；无替代者必须写明"无"。
4. 不再回迁：归档内容不得回迁现役目录，不得被链路重新生成或引用；确需复用时按新素材重新评估、登记与生成（§6.3）。
5. 许可证延续：归档不解除上游许可证义务；Apache-2.0 / OFL-1.1 等许可证文件随单元保留，复用前重新完成引入评估。

## 三、源格式与命名

### 3.1 设计源格式

- 设计源必须是 SVG（文本、UTF-8），且满足：
  - 根元素为 `<svg>`，含正方形 `viewBox`（生成基线 `viewBox="0 0 960 960"`，根元素 `width`/`height` 为 `512`）；
  - 内容只包含图形元素与 `<title>`；禁止脚本、事件属性、外部引用（`<image href>`、远程 `@import`、外链字体）、位图嵌入与滤镜链；
  - 静态身份资产为白底黑图：白色底板 `<rect>` 覆盖全画布，墨迹 `fill="#000000"`（`scripts/generate-plugin-material-icons.ts:50-69`）；
  - 字形来源为 Material Symbols Rounded 的 24px 网格路径（上游 `viewBox="0 -960 960 960"`），包装时以 `transform="translate(0 960)"` 归正坐标系。
- 禁止用字体码位、HTML 文本渲染或截图方式生成图标（`design-assets/*/SOURCE.md` 更新规则）；禁止手工描摹第二份副本。

### 3.2 设计源命名

- 设计源文件名为 `<SourceBaseName>.svg`，所在目录由资产层决定：

| 层 | 设计源目录 | 基名规则 | 示例 |
|---|---|---|---|
| 应用 / 模板 | `design-assets/Appicon/` | 工程名；脚手架模板目标固定为 `AppIcon` | `BookReader.svg`、`AppIcon.svg` |

| 遗留主题 | `归档/Themeicon/`（已归档，§2.8） | 不再新增 | — |

- 基名在 `scripts/icon-targets.mjs` 的 `ICON_TARGETS` 中登记一次且全局唯一；`kind + sourceBaseName` 组合不得重复。
- 命名一律英文小写或大驼峰工程名，禁止空格、下划线、中文；同一目标的基名一经发布不得更名。

### 3.3 工程内资产命名

| 角色 | 身份四件套 | 清单引用文件 |
|---|---|---|
| `app` | `assets/icons/app-icon.{svg,png,ico,icns}` | `assets/icons/app-icon.png`（或 `.svg`） |
| `basecard` | `assets/icons/basecard-icon.{svg,png,ico,icns}` | `assets/icons/<类型短名>.svg` |
| `boxlayout` | `assets/icons/layout-icon.{svg,png,ico,icns}` | `assets/icons/<布局短名>.svg` |

- 文件名一律小写 kebab-case（`app-icon`、`basecard-icon`、`layout-icon`），扩展名小写；短名使用类型 / 布局 ID 的末段（如 `chips.layout.grid` → `grid.svg`）。
- 同一基名的四件套必须同批生成；`.svg` 与位图的主图内容必须一致（同源同框）。

```yaml
    icon: assets/icons/app-icon.png
# basecard

  cardTypes:

      icon: assets/icons/video.svg
# boxlayout

```

- 引用必须是包内相对 POSIX 路径、位于 `assets/` 内且目标存在（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §2.6）；禁止前导 `/`、`..`、盘符与任何 URI scheme；插件不得自行拼接 `chips-resource://`。
- 命令图标（`ICommandDefinition.icon`）使用同一路径规则，声明与归一化规则归口 [13-命令系统契约](../05-接口与契约/13-命令系统契约.md)；本文只约束其源格式与安全区。

### 3.5 SOURCE.md 溯源文件

- 每个设计源目录一个 `SOURCE.md`，每个工程 `assets/icons/` 一个 `SOURCE.md`（脚手架模板为 `SOURCE.md.tpl`）；内容包含：正式设计源目录、设计源文件（SVG 为唯一源）、Material Symbols 名称、上游 SVG 缓存路径（锁定提交）、SVG 生成脚本、PNG/ICO/ICNS 渲染脚本、同步时间、命名基线表与使用边界。

- `SOURCE.md` 与 `SOURCE.md.tpl` 由 `scripts/generate-plugin-material-icons.ts:191-262` 生成；手工修改会在下次生成时被覆盖，禁止直接编辑。
- 新增图标目标必须出现在对应 `SOURCE.md` 的命名基线表中，且工程 `SOURCE.md` 的「使用边界」必须与本层消费链路一致并与上一条口径一致。

## 四、生成链路（SVG → PNG/ICO/ICNS）

### 4.1 链路总览

```
上游字形（锁定提交）
  └─ 缓存 design-assets/material-symbols/svg/rounded/<name>.svg
       └─ SVG 设计源（512 白底黑图；design-assets/<层目录>/ 与工程 assets/icons/）
            └─ 位图容器（Chip-iconMaker CLI：png / ico / icns @ 512；ICO 载荷 256）
                 └─ 工程内四件套（app / basecard / layout）
                      └─ SOURCE.md 溯源刷新 → 自检（§八）
```

- 链路是单向派生：上游 → 设计源 → 位图 → 工程资产。禁止反向回写（不得用工程位图覆盖设计源 SVG）。
- 链路的唯一目标清单是 `scripts/icon-targets.mjs` 的 `ICON_TARGETS`；禁止在脚本之外维护第二份图标映射表。

### 4.2 上游字形获取

- 上游：`github.com/google/material-design-icons`，锁定提交 `caeba1e66925218b1fd1464171f93e2656f9a0b9`（`design-assets/material-symbols/SOURCE.md:3-11`）；授权 Apache-2.0，许可证文件 `design-assets/material-symbols/LICENSE` 必须随资产保留。
- 本地缓存目录：`design-assets/material-symbols/svg/rounded/<materialName>.svg`；缓存是锁定提交的本地镜像并纳入版本控制，生成流程缓存优先，正常不触网。
- 缓存策略（强制）：
  1. 缓存命中：直接使用缓存文件，不发起网络请求；
  2. 缓存缺失：按锁定提交拉取 `https://raw.githubusercontent.com/google/material-design-icons/caeba1e66925218b1fd1464171f93e2656f9a0b9/symbols/web/<materialName>/materialsymbolsrounded/<materialName>_24px.svg`，校验内容含 `<svg` 与 `<path` 后写回缓存；
  3. 拉取失败或校验不通过：终止并报错，禁止回退到 `master` / `HEAD` 等未锁定引用，禁止写入不完整缓存；
  4. 上游升级：锁定提交、`SOURCE.md`、缓存与全部再生资产必须在同一提交内同步更新；
  5. 缓存可包含已退役目标的历史字形；未被 `ICON_TARGETS` 引用的缓存字形不参与生成、不构成资产登记对象，随上游升级重建缓存时统一收口。
- 实现与常量：锁定提交常量 `scripts/generate-plugin-material-icons.ts:19`、锁定请求基址 `:20`、缓存读取与锁定拉取 `:28-48`。
- 轴映射（`FILL` / `wght` / `GRAD` / `opsz`）以 `design-assets/material-symbols/SOURCE.md:13-20` 为准；该口径只描述上游字形坐标轴，不构成运行时 UI 图标契约（运行时 UI 图标归口 [09-统一视觉规范](./09-统一视觉规范.md)）。

### 4.3 SVG 设计源生成

```bash
# 工作区根执行；tsx 为工作区可用工具
npx tsx scripts/generate-plugin-material-icons.ts
```

- 目标声明：`{ kind, sourceBaseName, materialName, projectDir?, projectIconBaseName? }`；`kind` 只允许 `app` / `template` / `basecard` / `layout` 四种。
- 行为：
  1. 读取（或按 §4.2 缓存策略拉取并缓存）上游字形，提取 `<path d>` 数据；
  2. 包装为 512×512、白底 `#000000`、带 `<title>` 的 SVG（`generate-plugin-material-icons.ts:50-69`）；
  3. 写入对应设计源目录 `<SourceBaseName>.svg`；存在 `projectDir + projectIconBaseName` 时同时写入工程 `assets/icons/<projectIconBaseName>.svg`；
  4. 刷新全部 `SOURCE.md` 与模板 `SOURCE.md.tpl`（§3.5）。
- 常量基线：输出尺寸 `SIZE=512`、同步时间 `SYNC_DATE`、锁定提交与请求基址（`generate-plugin-material-icons.ts:15-20`）。
- 目标 `kind` 只支持现役四类；`module` / `theme` 为遗留取值，脚本与 `ICON_TARGETS` 均不再接受（§2.7、§2.8）。

### 4.4 位图渲染与同步

```bash
# 工作区根执行
node scripts/sync-plugin-icons.mjs
```

- 单次渲染调用（`scripts/sync-plugin-icons.mjs:27-55`）：

```bash
node_modules/.bin/chips iconmaker generate <input.svg> \
  -o <输出目录> -f png,ico,icns -s 512 --json
```

- 成功判定：进程退出码为 0，stdout JSON 的 `ok` 为 `true` 且 `task.status` 为 `completed`；产物列表取 `task.output.files`。
- 同步范围：设计源目录（`design-assets/Appicon`、`Basecardicon`、`Layouticon`）与 `ICON_TARGETS` 中各工程 `assets/icons/`；`FORMATS = ["png","ico","icns"]`、`SIZE = 512`（`sync-plugin-icons.mjs:6-16`）。同一请求档位下各容器按自身能力取档，`.ico` 由渲染链路按 §5.3.1 矩阵降采样为 256 载荷。
- `ICON_TARGETS` 只登记现役四类 target（`app` / `template` / `basecard` / `layout`）；遗留 `module` / `theme` 目标已移除，不得重新加入（§2.7、§2.8）。
- CLI 声明与任务通道：Chip-iconMaker 以 `cli.commands` 声明 `iconmaker generate`，权限 `file.read` / `file.write` / `cli.task`，尺寸参数取值 16–1024 的整数，输出格式可选 `png` / `ico` / `icns`；声明格式与任务终态归口 [07-CLI完整参考](../06-开发与运维/07-CLI完整参考.md) §5。
- 应用内实现边界：图标工坊在 Host surface 内以 Canvas 合成与自研容器编码完成生成，经 SDK / `window.chips.*` 访问系统能力；禁止 Node、Electron、`sips`、`iconutil` 等宿主原生路径（Chip-iconMaker 技术文档 §1、§6）。

### 4.5 容器编码

- PNG：由 Canvas 输出 8-bit RGBA、非隔行；容器尺寸等于请求尺寸。
- ICO：目录维度字段与内嵌 PNG 像素尺寸必须一致（取档矩阵见 §5.3.1）：≤255 写原值、256 写 `0`；内嵌位图上限 256×256，请求档位大于 256 时降采样到 256 后编码，禁止嵌入超限位图（编码实现 `Chip-iconMaker/src/icon-workbench/ico.ts:21-26`，档位封顶 `Chip-iconMaker/src/icon-workbench/generator.ts:13、58-66`）。
- ICNS：块类型与像素尺寸按固定映射（`Chip-iconMaker/src/icon-workbench/icns.ts:5-16`）：

| 块类型 | 像素尺寸 | 说明 |
|---|---|---|
| `ic04` | 16 | 1x 小图标 |
| `ic11` | 32 | 16 的 2x |
| `ic05` | 32 | 1x |
| `ic12` | 64 | 32 的 2x |
| `ic07` | 128 | 1x |
| `ic13` | 256 | 128 的 2x |
| `ic08` | 256 | 1x |
| `ic14` | 512 | 256 的 2x |
| `ic09` | 512 | 1x |
| `ic10` | 1024 | 512 的 2x |

### 4.6 新增图标目标步骤

1. 在 `scripts/icon-targets.mjs` 的 `ICON_TARGETS` 追加一行（`kind` / `sourceBaseName` / `materialName` / `projectDir` / `projectIconBaseName`），基名保持唯一；
2. 运行 `npx tsx scripts/generate-plugin-material-icons.ts` 生成 SVG 设计源与工程 `.svg`，并刷新 `SOURCE.md`；
3. 运行 `node scripts/sync-plugin-icons.mjs` 渲染 `png/ico/icns` 并同步到工程；
4. 在 manifest 中引用包内相对路径（§3.4）；
5. 核对四件套齐全、尺寸与安全区（§5）、`SOURCE.md` 命名基线一致；
6. 提交设计源、工程资产与 `SOURCE.md`，提交信息用中文说明目标与来源。

### 4.7 链路约束

- 禁止手工编辑 `design-assets` 与工程 `assets/icons/` 下的派生位图与 `SOURCE.md`；
- 禁止绕过 `ICON_TARGETS` 直接在某个工程内单独生成图标；
- 设计源目录内的位图必须由 §4.4 渲染产生，不得从上游 PNG/ICO/ICNS 直接复制；
- 脚本或模板改动必须同步更新 `SOURCE.md` 模板文本，并在同一提交内重新生成受影响资产。

## 五、尺寸与安全区

### 5.1 画布与档位

- 主图画布为 **512×512**（生成链路 `-s 512`）；身份四件套一律使用 512 主图。
- 允许的输出档位（图标工坊冻结档位）：`16 / 32 / 48 / 64 / 128 / 256 / 512`；默认档位 256（用户侧生成），发布资产使用 512。
- 同一请求档位下各容器按自身能力取档：`.png` 取请求档位、`.icns` 按 §4.5 映射取块类型、`.ico` 载荷上限 256（§5.3.1）。
- 画布必须为正方形；SVG 设计源的 `viewBox` 必须为正方形，不得使用非等比缩放铺满。

### 5.2 安全区

- 墨迹主体（非白底、非透明的图形像素）必须位于画布中心 **80% × 80%** 区域内，四边留白各 ≥ 10%（512 画布即 ≥ 51 px）。
- 白底底板（静态身份资产）不参与墨迹判定；透明底素材以非透明像素为墨迹。
- 基线核对：现有 83 个身份资产的墨迹宽高占比在 54.3%–77.0%，最小边距 11.5%–21.9%，全部满足下限。

### 5.3 容器规则与平台消费

| 容器 | 规则 |
|---|---|
| `.png` | 512×512、8-bit RGBA、非隔行；主图对外展示与 Linux 系统入口使用 |
| `.ico` | 目录维度与内嵌载荷一致且载荷不超过 256×256；按 §5.3.1 矩阵取档；Windows 系统入口使用 |
| `.icns` | 块类型与像素尺寸按 §4.5 映射表一致；发布基线至少包含 `ic09`（512）；macOS 系统入口使用 |
| `.svg` | 设计源与工程矢量基线；清单引用与治理展示可用，系统入口以 `.icns` / `.ico` 为准 |

- 平台消费矩阵与 §2.3 的平台变体优先级一致；同一平台不得混用两个来源的图标（例如 Windows 入口必须来自同一基名的 `.ico`）。

#### 5.3.1 ICO 目录维度与载荷矩阵

| 请求档位 | 目录维度字段 | 内嵌载荷 | 说明 |
|---|---|---|---|
| 16–255 | 原值 | 同请求档位 | 一一对应 |
| 256 | `0`（规范以 `0` 表示 256） | 256×256 | 一一对应 |
| 257–1024（发布链路为 512） | `0`（规范以 `0` 表示 256） | 256×256（由请求档位降采样） | ICO 无法表达超过 256 的维度；只降采样载荷，不嵌入超限位图 |

- 发布链路统一请求 512：`.png` 为 512、`.icns` 取 `ic09`（512）、`.ico` 按本矩阵降采样为 256 载荷并写目录维度 `0`。
- 目录维度与载荷尺寸不一致（如 256 维度配 512 载荷）为容器缺陷，禁止生成、禁止消费方依赖。

### 5.4 托盘位图

- 尺寸：16×16 与 32×32 两档（1x / 2x），文件基名 `tray-icon`；
- 必须透明背景、无白底底板；macOS 模板图像为单色；
- 安全区规则同 §5.2（以非透明像素为墨迹）。

### 5.5 图标工坊输出产物

- 用户侧产物：按勾选格式生成 `PNG` / `ICO` / `ICNS`，统一以 ZIP Store 打包为 `icons.zip` 下载；未勾选任何格式时禁止生成。
- CLI 侧产物：不打包 ZIP，按 `-f` 直接写出独立文件，文件名沿用输入 basename。
- 产物编码与档位遵守本节规则；ICO 按 §5.3.1 矩阵取档，ICO 与 ICNS 的容器元数据必须与内嵌位图一致。

- 自制素材（设计插图、占位图等）必须登记作者、制作工具与授权口径；工程侧 `SOURCE.md` 记录来源文件与设计口径。
- 新增第三方素材必须先按 [01-架构原则](../00-愿景与原则/01-架构原则.md) §3.1 完成六项评估，再登记进 §6.2 表；未登记素材不得被链路或工程引用；许可证合规的通用义务、署名与随附基线以 [11-第三方参考资产清单](./11-第三方参考资产清单.md) §四为准。
- 本文只登记设计资产与字体素材；参考资产（源码、文档、工具）的登记归口 [11-第三方参考资产清单](./11-第三方参考资产清单.md)，随包携带的第三方素材（应用内嵌渲染字体、样例图片等）按该文 §四的许可要求执行并在本表登记与设计资产相关的条目。
- 归档目录（工作区根 `归档/` 与各层就近归档目录，如 `design-assets/Appicon/归档/`）内的素材仅存档、不作为依据、不进入链路；归档单元的接收与保留按 §2.8 执行，其来源与许可证不随现役链路校验。

## 七、资产目录与禁止事项

### 7.1 目录树

```text
design-assets/
├── Appicon/                # 应用图标设计源（含脚手架 AppIcon 模板目标）
├── Basecardicon/           # 卡片类型插件身份图标设计源
├── Layouticon/             # 布局插件身份图标设计源
├── Moduleicon/             # 遗留：模块身份图标设计源（待随工程退役归档，§2.8）
├── material-symbols/       # 上游字形冻结资产（LICENSE / SOURCE.md / font / variablefont / svg/rounded）
└── 占位符音乐封面.jpg        # 自制占位素材（现役，§2.8.1）

归档/
├── Themeicon/              # 遗留：主题身份图标设计源（仅存档，§2.8）
└── fonts/                  # 遗留：主题设计字体素材（仅存档，§2.8）

scripts/
├── icon-targets.mjs                    # ICON_TARGETS 唯一目标清单
├── generate-plugin-material-icons.ts   # 上游字形 → SVG 设计源 + SOURCE.md
└── sync-plugin-icons.mjs               # SVG → PNG/ICO/ICNS 并同步工程

<工程>/assets/icons/        # 工程内四件套与清单引用文件
```

### 7.2 目录职责

| 目录 | 职责 | 维护方式 |
|---|---|---|
| `design-assets/Appicon|Basecardicon|Layouticon/` | 各层正式设计源 | 仅经 §4.3 / §4.4 链路更新 |
| `design-assets/material-symbols/` | 上游冻结素材与许可证 | 只读；升级需更新锁定提交与登记表（§4.2、§6.2） |
| `design-assets/Moduleicon/` | 遗留设计源 | 不得新增、复制、引用；按 §2.8 随工程退役归档 |
| `归档/Themeicon/`、`归档/fonts/` | 已归档遗留素材 | 只读、仅存档；不得回迁、引用或进入链路（§2.8） |
| `scripts/icon-targets.mjs` | 目标清单唯一事实源 | 新增目标按 §4.6；不得登记遗留目标（§2.7） |
| `<工程>/assets/icons/` | 工程内资产 | 仅经链路写入；`SOURCE.md` 禁止手工编辑（§3.5） |

### 7.3 禁止事项

| 禁止行为 | 判据与正确做法 |
|---|---|
| 使用 emoji、字符图标或占位字形 | 运行时与清单图标一律为图形资产；与 [09-统一视觉规范](./09-统一视觉规范.md) §四 V12 一致 |
| 运行时 UI 直引独立图标包 | 图标只从 `@chips/ui` 导入；禁止 `@ant-design/icons`、`@chips/antd` 与第二图标包（[09-统一视觉规范](./09-统一视觉规范.md) §5.2） |
| 维护第二套图标映射表 | 目标清单唯一来源为 `scripts/icon-targets.mjs`；消费方使用清单与 `@chips/ui` 出口 |
| 用字体码位、HTML 文本渲染或截图生成图标 | 只经 Material Symbols 字形经 §4 链路生成，避免乱码与不可复现产物 |
| 手工编辑派生资产 | `SOURCE.md`、`png/ico/icns` 由脚本生成；改动走脚本与重新生成 |
| 同一图标多源 | 一份图标只有一个设计源基名；禁止跨目录副本（单一事实源） |
| 设计源直接作为运行时资源引用 | 运行时只引用包内 `assets/` 文件，经 `chips-resource://` 解析（[06-资源协议规范](../05-接口与契约/06-资源协议规范.md)） |
| 插件自行拼接 `chips-resource://` URI | 清单与命令图标使用包内相对路径，由平台归一（[03-插件包格式](../04-文件格式规范/03-插件包格式.md) §2.6） |
| 清单声明平台专属容器（`.ico` / `.icns`） | 声明平台中立主图（`.png` / `.svg`），容器由平台变体解析链选择（§2.3） |
| 容器元数据与内嵌位图不一致 | ICO 按 §5.3.1 矩阵取档，目录维度与载荷一致且不超过 256；ICNS 块类型必须与像素尺寸一致（§5.3） |
| 新增或引用遗留图层资产 | 主题、模块与旧运行时图标体系已退出（§2.7）；遗留单元按 §2.8 处置 |
| 引用归档单元或从归档回迁素材 | 归档仅存档、不作为依据；复用须按 §6.3 重新评估、登记与生成（§2.8.3） |
| 引用未登记的上游素材 | 先完成 §6.3 评估与登记，再进入链路 |
| 未归档直接删除设计资产 | 需要移除时按 §2.8.2 移入归档并登记说明与索引，不得直接删除 |

## 八、约束与自检清单

### 8.1 强制约束

1. 五层图标只使用本文规定的载体与命名；清单引用必须位于 `assets/` 且目标存在；
2. 设计源、位图、工程资产与 `SOURCE.md` 全部由 §4 链路生成，禁止手工修改；
3. 主图画布 512×512，安全区满足 §5.2；容器维度与载荷满足 §5.3 与 §5.3.1（ICO 载荷上限 256）；
4. 官方应用插件与脚手架模板四件套齐全；第三方应用插件至少 `.svg` + `.png` + 所支持平台容器；
5. 上游素材必须锁定提交并完成 §6.2 登记；缓存缺失时只按锁定提交拉取（§4.2），许可证文件随资产保留；
6. 遗留图层与遗留素材不得新增、引用与打包；遗留单元按 §2.8 归档，归档内容不得回迁或引用；
7. 新增或调整图标目标时同步更新 `ICON_TARGETS`、`SOURCE.md` 与 manifest 引用，并在同一提交内完成。

### 8.2 自检清单

- [ ] 新增目标是否登记在 `ICON_TARGETS`，基名唯一且符合 §3.2 命名？
- [ ] 设计源 SVG 是否为正方形 `viewBox`、512 尺寸、无脚本 / 外链 / 位图嵌入？
- [ ] 是否经 `generate-plugin-material-icons.ts` 与 `sync-plugin-icons.mjs` 完整生成，而非手工放入文件？
- [ ] 四件套是否同批生成、同源同框，尺寸为 512 且安全区 ≥ 10%？
- [ ] ICO 目录维度与内嵌载荷是否一致且不超过 256（512 请求是否降采样为 256 载荷、维度写 `0`）？ICNS 块类型与像素尺寸是否一致？
- [ ] 托盘图标是否为透明 PNG、16/32 两档，且未使用白底底板？
- [ ] manifest 引用是否为 `assets/` 内相对路径，且未声明 `.ico` / `.icns` 平台容器？
- [ ] `SOURCE.md` 命名基线是否覆盖新目标，且使用边界为平台中立口径、与本层消费链路一致？
- [ ] 上游素材是否保持锁定提交、缓存缺失时只按锁定提交拉取，许可证文件与登记表是否同步？
- [ ] 是否未新增、引用或打包遗留图层与未登记素材？遗留单元归档是否按 §2.8 完成说明与索引，归档内容未被引用？
