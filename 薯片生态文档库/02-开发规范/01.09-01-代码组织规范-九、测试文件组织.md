## 九、测试文件组织

### 9.1 位置与命名

| 测试类型 | 位置 | 命名 |
|---|---|---|
| TS 单元测试 | 与被测文件同目录 | `<被测文件名>.test.ts` |
| TS 组件测试 | 与组件同目录 | `<组件名>.test.tsx` |
| TS 包级集成测试 | `<包>/tests/` | `<场景>.test.ts` |
| 跨包集成测试 | `tests/integration/` | `<场景>.test.ts` |
| E2E 测试 | `tests/e2e/` | `<场景>.spec.ts` |
| Rust 单元测试 | 被测模块同文件 | `#[cfg(test)] mod tests`，`test_<行为>` |
| Rust 集成测试 | crate 内 `tests/` | `<场景>.rs` |
| Rust 基准测试 | crate 内 `benches/` | `<对象>.rs` |

- 单元测试默认与被测代码同目录；`tests/unit/` 只用于无法归属单个包的跨包单元测试。
- 共享夹具放 `tests/fixtures/`；包内私有夹具放 `<包>/tests/fixtures/`。
- 测试文件与夹具禁止进入发布产物：TS 包的 `files`、`.cpk` 打包清单不得包含 `*.test.*`、`*.spec.*`、`tests/`、`fixtures/`。
- 覆盖率输出目录为 `coverage/`；门禁口径（总体 > 80%，Rust 核心与共享层 > 90%）与用例编写要求见 [测试规范](./05-测试规范.md)。

### 9.2 插件测试的 Mock 边界

- 插件测试通过 `@chips/sdk` 提供的 Mock 构造 `window.chips`，禁止在插件测试中直接引用 `@chips/bridge`、`@chips/host` 的内部实现。
- 平台包测试可以依赖真实实现；跨包集成测试放在 `tests/integration/`，使用真实 Rust 绑定或完整 Bridge 链路。
