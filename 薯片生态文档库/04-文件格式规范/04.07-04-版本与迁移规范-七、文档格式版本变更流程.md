## 七、文档格式版本变更流程

### 7.1 流程

```
[1] 提案与评审     RFC → 评审 → ADR 记录（R16）
        │
        ▼
[2] 提升版本号     不兼容变更升 MAJOR；向后兼容新增升 MINOR；修正升 PATCH（§3.4）
        │
        ▼
[3] 交付迁移支持   不兼容变更同版交付迁移工具与转换说明；旧版本文档打开返回确定性错误并提供迁移入口
        │
        ▼
[4] 同步文档       01/02/04 与受影响接口文档、示例同步更新
        │
        ▼
[5] 工具与门禁     迁移工具、校验夹具、CI 版本一致性检查同步更新
        │
        ▼
[6] 发布绑定       随平台版本发布；平台发布说明给出迁移指引
```

### 7.2 规则

1. 文档格式以 [01-卡片文件格式](01-卡片文件格式.md) 与 [02-箱子文件格式](02-箱子文件格式.md) 为唯一权威；变更不引入版本化 schema 注册表，也不引入运行时版本分支；
2. 每个包含不兼容格式变更的平台版本只提升一次文档格式主版本；同一版本号下不得发布两种格式语义；
3. 变更必须同时更新：格式文档、示例、测试夹具、校验夹具、迁移工具与迁移报告；
4. 变更不得引入别名映射、双读字段或旧字段兼容分支；字段重命名与删除一律由迁移工具改写为新格式；
5. 平台不提供旧文档格式的解析路径；旧文档必须先迁移、再解析；
6. 文档与实现不一致视为缺陷，变更必须与代码同 PR 更新（R16）。
