## 六、`content.yaml`

### 6.1 用途

`content.yaml` 保存布局配置信息。配置的具体结构由布局插件定义和解析，不同的布局插件有不同的配置字段；箱子文件只保存配置信息，不包含布局代码。

### 6.2 标准结构与完整示例

```yaml
active_layout_type: "chips.layout.grid"
layout_configs:
  chips.layout.grid:
    schema_version: "1.0.0"
    props:
      column_count: 4
      gap: 16
      cover_ratio: "16:9"
      show_tags: true
      information_density: "comfortable"
    asset_refs:
      - "assets/layouts/grid/background.webp"
  chips.layout.board:
    schema_version: "1.0.0"
    props:
      columns:
        - "未开始"
        - "进行中"
        - "已完成"
```

### 6.3 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `active_layout_type` | string | 当前生效布局类型；必须与 `metadata.yaml` 的 `active_layout_type` 一致 |
| `layout_configs` | object | 各布局类型的配置映射，键为布局类型标识 |

### 6.4 布局配置字段

每个布局配置项包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | string | 必填。该配置由哪个配置 schema 版本写入；由布局插件编辑器经变更回流写入、平台持久化；打开箱子时由平台以插件 `capabilities.layouts[].schemaVersions` 做兼容门禁（[09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) 2.2） |
| `props` | object | 布局插件自定义参数，结构由插件 `capabilities.layouts[].configSchema` 描述 |
| `asset_refs` | array | 布局引用的箱子资源路径 |

说明：

- 生效配置项存在时，`schema_version` 缺失、非法或超出插件 `schemaVersions` 范围，平台按 `RENDER_SCHEMA_UNSUPPORTED` 降级占位，不调用插件；配置项不存在时按空配置与插件内部默认值渲染（门禁规则见 [09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md) 2.2）。

### 6.5 多布局并存与切换

- 一个箱子可以保存多种布局插件的配置（例如同时保存网格布局配置与瀑布流布局配置）；切换布局时读取对应的布局配置，箱子引用的卡片集合不变，只是展示方式改变。
- 切换布局时同步更新 `metadata.yaml` 与 `content.yaml` 的 `active_layout_type`，两处必须一致。
- 未生效布局的配置同样保留，保证切换布局不丢失设置。
- 布局配置包括布局类型选择、排序规则、筛选条件、分页设置、交互行为等；具体字段取决于使用的布局插件类型，插件开发者必须在插件文档中说明支持的配置选项。

### 6.6 约束

1. `props` 只描述布局配置，不保存布局代码。
2. 布局自定义参数允许自由扩展。
3. 布局资源必须引用箱子内 `assets/` 内容，`asset_refs` 每项为以 `assets/` 开头的包内相对路径。
4. 不允许在 `content.yaml` 中写入凭证。
5. 不允许在 `content.yaml` 中保存被引用卡片实体数据。
