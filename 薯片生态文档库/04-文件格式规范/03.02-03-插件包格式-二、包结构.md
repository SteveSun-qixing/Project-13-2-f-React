# 插件包格式（.cpk）

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：`.cpk` 插件包的 ZIP Store 归档要求、包内目录布局、四类角色布局差异、资源与体积限制、安装校验流程、签名与信任根定义、打包命令与错误码。

## 二、包结构

### 2.1 归档要求

| 要求 | 内容 | 违反时错误码 |
|---|---|---|
| 归档格式 | 标准 ZIP；ZIP 文件结构合法、中央目录完整、CRC32 正确 | `CPK_ARCHIVE_INVALID` |
| 压缩方法 | 所有文件成员的压缩方法必须为 `0`（Stored）；压缩前后尺寸相等 | `CPK_ARCHIVE_INVALID` |
| 加密与扩展 | 禁止加密标志、禁止 ZIP64、禁止非标准扩展字段 | `CPK_ARCHIVE_INVALID` |
| 成员路径 | 使用 `/` 分隔的 UTF-8 相对路径；禁止前导 `/`、盘符、`\`、`..`、控制字符、保留设备名（`CON`、`NUL`、`AUX` 等） | `CPK_PATH_UNSAFE` |
| 符号链接 | 禁止符号链接与硬链接成员 | `CPK_PATH_UNSAFE` |
| 重复与大小写 | 禁止重复路径；禁止仅大小写不同的路径 | `CPK_ARCHIVE_INVALID` / `CPK_PATH_UNSAFE` |
| 顶层结构 | 归档根直接是包根，不得出现包裹目录 | `CPK_LAYOUT_INVALID` |
| 目录成员 | 目录条目可省略；校验与限额按文件成员计算 | — |
| 嵌套归档 | 禁止包内出现 `.zip`、`.tar`、`.tgz`、`.7z`、`.cpk` 等归档文件 | `CPK_ARCHIVE_INVALID` |
| 隐藏文件 | 禁止以 `.` 开头的文件与目录 | `CPK_LAYOUT_INVALID` |
| 确定性 | 打包工具按路径字节序升序写入成员，时间戳固定；同一输入必须产生相同安装摘要 | — |

### 2.2 包根布局

```
hello-basecard-1.0.0.cpk (ZIP Store)
├── manifest.yaml            # 包根唯一权威清单（必需）
├── dist/                    # 构建产物目录（必需）
│   └── index.js             # 插件模块入口（必需）
├── render.js                # 渲染入口（basecard / boxlayout / app 必需；service 禁止）
├── assets/                  # 静态资源目录（按需）
│   └── icons/
│       └── hello.svg
└── signature.json           # 签名文件（可选；见第六节）
```

包根只允许上图中出现过的条目；出现白名单外条目（含源码、测试、锁文件、日志、`.map`）时校验拒绝。

### 2.3 根目录白名单

| 条目 | 必需性 | 说明 |
|---|---|---|
| `manifest.yaml` | 必需 | 唯一权威清单；包内不得出现第二份清单 |
| `dist/` | 必需 | 构建产物目录；只允许可执行代码与其模块 |
| `render.js` | 按角色 | 渲染入口；`basecard` / `boxlayout` / `app` 必需，`service` 禁止 |
| `assets/` | 按需 | 静态资源；不得包含代码与 HTML |
| `signature.json` | 按需 | 签名文件；`service` 角色同样允许 |

### 2.4 入口约定

| 入口 | 路径 | 角色 | 说明 |
|---|---|---|---|
| 插件模块入口（主进程部分） | `dist/index.js` | 全部角色 | 只承载主进程可执行部分：卡片类型 / 布局注册转发、配置 schema 校验纯函数（`validateConfig`）等；由 Cordis 运行时经受管模块加载器加载（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) §三.14） |
| 渲染入口（渲染部分） | `render.js` | `basecard` / `boxlayout` / `app` | 承载 `renderView` / `renderEditor` / `renderLayout` / `export` 等渲染侧实现；由 SDK 构建产出的单一 ESM 文件；在宿主文档（帧 / 应用窗口壳）内装载 |

规则：

1. 两个入口都必须是 UTF-8 文本 ESM 模块，默认导出对象；导出形状与角色接口一一对应，接口定义见 [07-应用插件接口](../05-接口与契约/07-应用插件接口.md)、[08-基础卡片插件接口](../05-接口与契约/08-基础卡片插件接口.md)、[09-箱子布局插件接口](../05-接口与契约/09-箱子布局插件接口.md)、[10-服务插件接口](../05-接口与契约/10-服务插件接口.md)。
2. 职责不得越界：`dist/index.js` 不得包含 DOM 渲染逻辑或依赖宿主文档环境；`render.js` 不得包含主进程侧注册、文件 IO 或平台服务逻辑。`service` 角色只有主进程部分（`dist/index.js`），不存在渲染部分。
3. 包内不得包含 `.html` 文档：渲染与应用窗口的宿主文档一律由平台提供（帧使用 `chips-resource://platform/frame.html`，应用窗口壳由平台构建产物提供），插件只提供 ESM 模块。
4. 除 `dist/` 与 `render.js` 外，包内任何位置不得出现 `.js` / `.mjs` / `.cjs` / `.ts` 代码文件。
5. 入口文件各自不超过 8 MiB；超过时打包与安装均拒绝（`CPK_LIMIT_EXCEEDED`）。
6. `render.js` 必须外部化平台共享依赖（React、`react-dom`、`@chips/ui`），不得内联第二套组件库或第二份 React。

### 2.5 静态资源规则（assets/）

允许：

- 图片（`.svg`、`.png`、`.jpg`、`.webp`、`.gif`、`.ico`、`.icns`）；
- 字体（`.woff2`、`.woff`、`.ttf`）；
- 样式（`.css`）；
- 数据与模板（`.json`、`.yaml`、`.yml`、`.md`、`.txt`）。

禁止：

- 任何代码文件、HTML 文档、原生载荷与嵌套归档；
- `service` 角色的任何 UI 资源（图片、字体、样式、图标）；
- 未被清单或代码引用的资源不阻断安装，但必须在诊断中报告（`CPK_LAYOUT_INVALID` 的警告级诊断）；发布包不得包含无用资源。

`.svg` 只能作为图片资源使用，禁止作为文档装载；`.css` 只能由 `render.js` 在宿主文档内注入使用。

### 2.6 manifest 中的路径引用

`manifest.yaml` 内所有文件引用（如卡片类型图标、布局图标、启动器图标）必须满足：

1. 包内相对 POSIX 路径，相对包根书写，例如 `assets/icons/hello.svg`；
2. 禁止前导 `/`、`..`、盘符、URI scheme（`file://`、`chips-resource://`、`http(s)://`）；
3. 引用目标必须存在且位于 `assets/` 内；缺失或越界时 `CPK_MANIFEST_INVALID`（`details.pointer` 指向字段）；
4. 运行时由平台解析为插件作用域资源（如 `chips-resource://<plugin-scope>/assets/icons/hello.svg`），插件不得自行拼接作用域 URI。

### 2.7 开发态目录

- 开发态允许以目录形式加载：目录根布局与 `.cpk` 解包后的包根完全一致；
- 目录态跳过大宗归档校验与签名校验，仍执行 manifest、入口、原生载荷、路径安全与角色布局校验；
- 禁止以目录态分发或安装；发布单位始终是单个 `.cpk`。
