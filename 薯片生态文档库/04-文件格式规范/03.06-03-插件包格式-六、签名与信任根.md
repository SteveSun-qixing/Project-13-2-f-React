## 六、签名与信任根

### 6.1 签名文件

签名文件固定为包根 `signature.json`（JSON 格式），字段如下：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `format` | string | 是 | 固定为 `chips-signature-v1` |
| `keyId` | string | 是 | 签名密钥标识，由发布方信任根注册表解析 |
| `algorithm` | string | 是 | 固定为 `ed25519` |
| `contentHash` | string | 是 | 包内容摘要，`sha256:<小写十六进制>`，按 §6.2 计算 |
| `signature` | string | 是 | 对 `contentHash` UTF-8 字节的 Ed25519 签名（Base64） |

### 6.2 包内容摘要

`contentHash` 的构造规则（对 `signature.json` 自身不参与计算）：

1. 列出包内除 `signature.json` 外的全部文件成员，按路径字节序升序排序；
2. 对每个文件计算 SHA-256（小写十六进制）；
3. 依次拼接 `文件路径 + "\n" + 文件摘要 + "\n"` 的 UTF-8 字节流；
4. 对拼接结果计算 SHA-256，记为 `sha256:<hex>`。

### 6.3 来源渠道校验规则

| 来源 | 签名要求 | 缺失时 | 无效时 |
|---|---|---|---|
| `builtin` | 必须签名 | `CPK_SIGNATURE_REQUIRED`，拒绝安装 | `CPK_SIGNATURE_INVALID`，拒绝安装 |
| `user` | 可选（非强制） | 安装界面明确展示“未签名发布者”，用户确认后继续 | `CPK_SIGNATURE_INVALID`，拒绝安装 |
| `development` | 不适用 | 不检查 | 不检查 |

规则：

- 未签名不得静默安装；必须产生可见提示与用户确认记录；
- 签名有效不得作为跳过归档、结构、清单与载荷校验的理由；
- 信任根注册表、密钥生成、签名工具与分发属于发布链路；本节冻结签名结构、`contentHash` 计算与信任根判定语义，发布链路按[《更新与分发规范》](../06-开发与运维/06-更新与分发规范.md)执行（Phase 3/4 落地）；
- 开发/验证期的信任根注入通道为 `chips plugin validate` 的环境变量 `CHIPS_TRUST_ROOTS_FILE`（[《CLI完整参考》](../06-开发与运维/07-CLI完整参考.md) §2.7 登记，文件形状 `{ "version": 1, "trustRoots": { "<keyId>": "<SPKI PEM 公钥>" } }`），与库面 `trustRoots` 构造注入汇入同一判定实现，判定语义全局唯一；该通道不改变发布链路（宿主编译期内嵌注册表）的职责归属；
- 信任根未注册的 `keyId` 视为签名无效。
