## 二、文件系统表现与包结构

### 2.1 单文件正式形态

- 箱子的正式文件形态是单个 `.box` 文件，例如 `Travel-2026.box`；用户双击 `.box` 文件时，系统用箱子查看器打开。
- `.box` 本质是 ZIP 包，发布侧一律使用 Store（零压缩），确保快速访问，可按成员直接读取与随机访问。
- 读取侧接受 Store 与 Deflate 条目（Deflate 不符合正式发布要求，通过读取归一或提示处理，不因 Deflate 拒绝打开）。
- ZIP64：`.box` 读取侧支持 ZIP64 归档（成员数或尺寸超出经典 ZIP 上限时）；发布侧一律不产生 ZIP64。差异表见[04-版本与迁移规范](04-版本与迁移规范.md) §2.3。
- 用户创建新箱子时，正式产物直接是一个 `.box` 文件，不再额外创建同名文件夹。
- 平台或编辑器在编辑过程中可以解包出内部工作目录，但该目录只能作为临时工作区使用，不得作为箱子的第二种正式文件形态，也不得把这套中间目录结构暴露给用户。
- 归档是标准 PKZIP，配置为 UTF-8 YAML；无自定义头部与专有索引，第三方可用标准 ZIP 工具与 YAML 解析器读写。

### 2.2 标准目录结构

```text
Travel-2026.box                  # 发布态：ZIP Store；归档根直接放置包成员
├── .box/                        # 核心配置目录（必需）
│   ├── metadata.yaml            # 必需：箱子元数据
│   ├── structure.yaml           # 必需：条目引用结构
│   ├── content.yaml             # 必需：布局配置
│   ├── cover.html               # 必需：箱子本体封面入口
│   └── boxcover/                # 可选：箱子封面附属资源
│       └── hero.webp
├── assets/                      # 可选：箱子自有资源
│   ├── placeholders/
│   ├── previews/
│   └── layouts/
└── day-03.card                  # 可选：内嵌卡片，可位于根目录或任意层级
```

成员规则：

| 成员 | 必需性 | 规则 |
|---|---|---|
| `.box/metadata.yaml` | 必需 | 箱子元数据，位于配置目录内 |
| `.box/structure.yaml` | 必需 | 条目引用结构，位于配置目录内 |
| `.box/content.yaml` | 必需 | 布局配置，位于配置目录内 |
| `.box/cover.html` | 必需 | 箱子本体封面入口，位于配置目录内 |
| `.box/boxcover/**` | 可选 | 封面 HTML 的附属资源 |
| `assets/**` | 可选 | 箱子自有资源，推荐子目录见第八节 |
| `.card`（任意层级） | 可选 | 内嵌卡片实体，规则见 2.4 |
| `.box`（包内） | 禁止 | 包内不得出现箱子文件，防止无限嵌套 |

- 核心配置固定在 `.box/` 配置目录内，不散落在包根；除上表成员外，不定义其他配置型成员。
- 包内路径区分大小写，使用 UTF-8 + NFC；包内不得写入运行时 `blob:`、`data:` 地址或系统绝对路径。

### 2.3 归档根与 ZIP Store

- 归档根直接包含 `.box/`、`assets/`、内嵌 `.card` 等包成员；`.box/` 必须位于归档根，归档内不得出现顶层包裹目录。
- 压缩规则（与[04-版本与迁移规范](04-版本与迁移规范.md) §2.3 差异表一致）：发布态全部成员必须使用 Store 方法（不压缩）；读取端接受 Store 与 Deflate；`.box` 读取侧支持 ZIP64（发布不产生）。
- 打包时排除系统生成物（`__MACOSX/`、`.DS_Store`、`Thumbs.db`、`desktop.ini`）与编辑器临时文件。
- 成员数、解压总量与单成员尺寸受解析限额约束，超限由解析链路返回 `DOCUMENT_LIMIT_EXCEEDED`（见[文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md)）。

打包与校验命令：

```bash
# 在箱子目录内打包，使归档根直接包含 .box/
(cd Travel-2026 && zip -r -0 -X ../Travel-2026.box . \
  -x "__MACOSX/*" -x "*.DS_Store" -x "Thumbs.db" -x "desktop.ini")
# -r：递归
# -0：Store 模式（不压缩）
# -X：不写入扩展属性与资源分叉
# -x：排除系统生成物

unzip -l Travel-2026.box          # 确认 .box/ 位于归档根、无顶层包裹目录
zipinfo -v Travel-2026.box        # 逐条查看 compression method，应为 store
```

第三方工具打包同样合法，只需满足上述约束。

### 2.4 内嵌卡片规则

`.box` **允许**在根目录或任意层级存放 `.card` 文件作为内嵌卡片，与 URL 引用条目混用，无数量或比例限制。

1. 允许 `.card` 文件进入包内，可位于根目录或任意层级。
2. **禁止 `.box` 文件进入包内**（防止无限嵌套）。
3. 内嵌卡片保持自身完整的 ZIP Store 形态，随 `.box` 整体打包分发，不得展开其内部成员。
4. 内嵌与否由条目 `url` 形态判定（见第三节），不引入 `internal` / `external` / `location` 位置字段。
5. 内嵌卡片是引用集合的附属实体，引用关系仍通过 `structure.yaml` 条目表达；同一目标卡片也可以被其他箱子按 URL 引用。
6. 箱子自有资源统一写入 `assets/`；内嵌卡片写入包内其他位置（根目录或任意层级），不得把卡片实体写入 `assets/`。
7. 内嵌卡片可以引用其他箱子，但被引用箱子不进入包内；箱子嵌套通过条目的绝对 URL 表达（见 5.4）。
