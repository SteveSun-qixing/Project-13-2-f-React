## 二、两种正式形态

`.card` 存在两种正式形态，二者都是正常 `.card` 文件类型，不是临时产物。两种形态共享相同的配置结构（`.card/metadata.yaml`、`.card/structure.yaml`、`.card/cover.html`、`content/*.yaml`），区别只在资源字段的取值形式。

| 类型 | 资源位置 | 配置中的资源字段 | 典型用途 |
|---|---|---|---|
| 完整离线卡片 | 资源字节保存在 ZIP 内部 | 卡片根相对路径 | 制作、编辑、备份、离线分享、客户端下载结果 |
| 网络资源卡片 | 资源不在 ZIP 内部 | 对象存储 / CDN URL | 社区发布、网页查看、弱服务器分发 |

### 2.1 完整离线卡片

- 资源文件保存在 `.card` ZIP 内部；
- 配置文件和封面 HTML 中的资源引用使用卡片根相对路径；
- 不依赖网络即可查看和编辑；
- 适合本地备份、离线分享和继续编辑。

```text
offline.card (ZIP Store)
├── .card/
│   ├── metadata.yaml
│   ├── structure.yaml
│   └── cover.html
├── content/
│   └── a1B2c3D4e5.yaml
├── video.mp4
├── image.jpg
└── cover-assets/cover.png
```

### 2.2 网络资源卡片

- `.card` 中保留 `.card/metadata.yaml`、`.card/structure.yaml`、`.card/cover.html` 和 `content/*.yaml`；
- 资源文件不放在 ZIP 内；
- 配置文件与封面 HTML 中的资源字段记录对象存储 / CDN URL；
- 必须依赖网络资源才能完整查看；
- 适合社区发布、网页查看和弱服务器分发。

```text
network.card (ZIP Store)
├── .card/
│   ├── metadata.yaml
│   ├── structure.yaml
│   └── cover.html        # 封面引用对象存储 URL
├── content/
│   └── a1B2c3D4e5.yaml   # 资源字段引用对象存储 URL
└── （无外置资源文件）
```

网络资源卡片可以长期保存并被查看器直接打开。所有基础卡片插件必须正式支持 URL 资源，不得把 URL 当作社区临时补丁。

### 2.3 上传与下载的可逆转换

上传把相对路径改写成 URL，下载时还原为原始路径，因此必须保存「可逆恢复清单」（restore manifest）。

```text
完整离线卡片 --上传--> 网络资源卡片 + 对象存储资源 + 恢复清单
网络资源卡片 + 对象存储资源 + 恢复清单 --下载--> 完整离线卡片
```

恢复清单至少记录：

- 原始卡片版本 ID；
- 网络资源卡片对象位置；
- 每个资源的原始相对路径；
- 每个资源上传后的对象键；
- 每个资源写入网络资源卡片后的 URL；
- 每个配置文件中发生过的路径替换位置或可验证替换规则；
- 原始 ZIP 条目顺序；
- 原始 ZIP 条目 Store 模式；
- 原始 ZIP 条目修改时间；
- 原始 ZIP 条目外部属性、注释和必要的 extra fields；
- 原始资源文件名、大小和 MIME；
- 封面资源的原始引用和 URL 替换关系。

客户端统一卡片传输模块负责上传时的 URL 改写与下载时的 URL 恢复；插件不得自行替换 YAML 或 HTML 中的资源字段。

### 2.4 完整恢复验收标准

下载得到的完整离线卡片应尽可能与上传前一致：

- 文件路径一致；
- 配置内容一致（URL 恢复为原始相对路径，资源字段语义逐字段还原；YAML 经解析 → 重写再序列化时允许格式化归一，如注释、空行、键序和引号风格变化，但不得改变字段语义与资源路径）；
- 资源字节一致；
- ZIP Store 条目顺序一致；
- ZIP 条目修改时间一致；
- ZIP 条目 Store 模式一致；
- 封面 HTML 和封面资源恢复一致；
- 下载结果能被正式平台打开、渲染和继续编辑。

说明：网络资源卡片生成与下载恢复都会对 YAML 做解析再序列化（`parse → 改写 → stringify`），因此字节级「配置文本不变」不保证；验收以「字段语义与资源引用一致」为准，不以配置文本逐字节相同为准。

### 2.5 网络资源卡片校验规则

- 配置文件允许 URL 资源字段（`source: url` / `url: https://...`）；
- 本地资源文件可以不存在（ZIP 内不要求包含外置资源字节）；
- URL 必须来自正式上传结果（对象存储 / CDN 地址），不允许引用任意不可信地址；
- `.card/metadata.yaml`、`.card/structure.yaml`、`.card/cover.html` 和 `content/*.yaml` 必须存在。
