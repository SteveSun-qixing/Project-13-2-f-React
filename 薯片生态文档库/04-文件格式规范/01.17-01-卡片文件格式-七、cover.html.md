## 七、cover.html

### 7.1 封面 HTML 规范

`.card/cover.html` 是卡片封面的正式入口，采用标准 HTML 文档：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Card Cover</title>
  <style>
    /* 样式代码 */
    body {
      margin: 0;
      padding: 0;
      width: 100%;
      height: 100%;
      display: flex;
      align-items: center;
      justify-content: center;
    }
  </style>
</head>
<body>
  <!-- 封面内容 -->
  <div class="cover-container">
    <h1>卡片名称</h1>
  </div>
</body>
</html>
```

### 7.2 封面比例元数据

封面比例保存在 `metadata.yaml` 的 `cover_ratio` 字段中，格式为 `宽:高` 的正数比值字符串。

- 默认值：`3:4`；
- 当前正式编辑器支持的九种预设比例：
  - `1:1`
  - `1:1.414`
  - `2:3`
  - `3:4`
  - `1:1.618`
  - `16:9`
  - `2:1`
  - `9:19.5`
  - `1.58:1`
- 横版通过交换宽高得到，例如 `3:4` 的横版保存为 `4:3`；
- 运行时应按规范化后的字符串读取和回写 `cover_ratio`。

### 7.3 正式显示链路

封面显示必须使用平台统一的**受控封面渲染接口**，不允许应用层自行拼接任意 HTML：

```text
应用层请求卡片封面（受控封面渲染接口）
  → 平台读取 .card/cover.html，返回封面视图 { title, coverUrl, ratio? }
  → 应用层把 coverUrl 装载到沙箱 iframe（sandbox = "allow-scripts"）
```

正式约束：

- `coverUrl` 必须指向受控的 `.card/cover.html` 入口；
- `.card/cover.html` 中的相对路径相对于 `.card/` 目录解析，可继续引用 `.card/cardcover/*`；
- 封面 iframe 内容完全由 `cover.html` 决定，平台与应用层不自动注入宿主视觉样式、文案层或复合卡片壳层；
- 应用层不得把封面内容改写为 `srcdoc` 或任意 HTML 字符串。

### 7.4 封面创建方式

当前正式支持两种封面生成方式。

方式 1：在线编辑 HTML 代码

```text
用户在编辑器中编写或粘贴 HTML
  → 系统直接保存到 .card/cover.html
```

方式 2：上传图片并生成封面

```text
用户上传图片
  → 可按当前封面比例打开裁剪弹窗
  → 系统把生成图片保存到 .card/cardcover/
  → 系统生成引用该图片的 .card/cover.html
```

图片生成封面的正式 HTML 约定：

```html
<body
  data-chips-cover-mode="image"
  data-chips-cover-image-source="./cardcover/cover-image.ext"
>
  <img src="./cardcover/cover-image.ext" alt="" />
</body>
```

说明：

- `data-chips-cover-mode="image"` 用于标识该 `cover.html` 来自正式图片封面生成链路；
- `data-chips-cover-image-source` 记录正式图片资源入口；
- `cover-image.ext` 表示实际保存的图片扩展名；未裁剪时会尽量保留原始类型，裁剪输出当前正式实现固定为 PNG；
- 生成的图片封面默认使用 `img { object-fit: cover; }`；
- `.card/cardcover/` 是封面专用资源目录；编辑器保存封面时应以 `.card/cover.html` 中仍被 `src`、`href`、`poster`、`data-chips-cover-image-source` 或 CSS `url(...)` 引用的相对路径为准，清理不再被引用的旧封面资源；
- `cover.html` 引用封面资源时必须使用 `.card/` 内部相对路径，例如 `./cardcover/cover-image.png` 或 `cardcover/cover-image.png`；不得把运行时 `blob:`、`data:` 或系统绝对路径作为封面资源路径写入正式文件。

### 7.5 正式支持边界

封面 HTML 在 iframe 中运行时，必须满足以下正式边界：

- 必须通过受控 `coverUrl` + `sandbox="allow-scripts"` 装载；
- 正式支持的资源引用方式是访问 `.card/` 目录内的相对路径资源；
- 封面文档不得依赖父窗口交互协议；
- 封面文档不得把表单提交、弹窗或外部网络资源作为正式能力前提；
- 应用层不得把封面文档当作同源 DOM 直接读取或挂接私有监听。

### 7.6 默认封面

如果用户未设置封面，系统使用默认封面：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Default Cover</title>
  <style>
    html, body { margin: 0; width: 100%; height: 100%; }
    body {
      display: grid;
      place-items: center;
      background: linear-gradient(135deg, #f5f7fb 0%, #eef3ff 100%);
      font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif;
      color: #111827;
      text-align: center;
      padding: 24px;
      box-sizing: border-box;
      overflow: hidden;
    }
    .card-name {
      font-size: 24px;
      font-weight: 600;
      line-height: 1.4;
      word-wrap: break-word;
    }
  </style>
</head>
<body>
  <div class="card-name">{{CARD_NAME}}</div>
</body>
</html>
```

默认封面不是纯白占位，而是一个中性渐变背景加居中的卡片名称；`{{CARD_NAME}}` 在生成时替换为 `metadata.yaml` 的 `name`。
