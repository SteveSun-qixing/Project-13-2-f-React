## 八、资源组织

### 8.1 两种正式资源模式

卡片存在两种正式资源组织模式，分别对应完整离线卡片和网络资源卡片（见第二节）：

- **完整离线卡片**：内部资源写入卡片根目录一侧，配置中的资源引用使用卡片根相对路径。平台、SDK、编辑器和基础卡片插件不得把运行时 `blob:`、`data:`、系统绝对路径或 `file://` URL 写回正式内容配置。
- **网络资源卡片**：资源字节不写入 ZIP，配置和封面中的资源字段记录对象存储 / CDN URL；URL 必须来自正式上传结果，不得引用任意不可信地址。

```text
# 完整离线卡片
card.card (ZIP Store)
├── .card/
├── content/
├── video.mp4
├── image.jpg
└── subtitle.srt

# 网络资源卡片
network.card (ZIP Store)
├── .card/
├── content/          # 资源字段为对象存储/CDN URL
└── （无外置资源字节）
```

「空壳卡片」「半空壳卡片」这些旧术语不再使用，正式名称为「网络资源卡片」，是正常 `.card` 文件类型，不是社区内部临时产物。资源字段能同时识别相对路径和 URL 两种形态：完整离线卡片用相对路径 + 内置资源，网络资源卡片用 URL + 外部资源。

### 8.2 资源路径格式

允许的写法：

```yaml
# 卡片根相对路径（完整离线卡片）
video_file: "video.mp4"
file_path: "tracks/cover.png"

# 对象存储 / CDN URL（网络资源卡片）
source: "url"
url: "https://file.example/chips-card-resources/cards/.../video.mp4"

# WebDAV 资源（正式引用集合成员）
url: "webdav://dav.example.com/cards/.../video.mp4"

# 外部 URL（仅当对应基础卡片插件的 schema 明确支持时）
source_url: "https://example.com/videos/video.mp4"
```

禁止作为内部资源写回的路径：

```yaml
video_file: "/Users/username/Videos/video.mp4"
video_file: "C:\\Users\\username\\Videos\\video.mp4"
video_file: "file:///Users/username/Videos/video.mp4"
video_file: "blob:https://example.invalid/..."
video_file: "data:video/mp4;base64,..."
```

规则：

- 卡片根相对路径一律相对卡片根目录解析，不相对 `content/` 目录或当前 YAML 文件所在目录；禁止 `..` 路径逃逸；
- 外部 URL 只有在对应基础卡片插件 schema 明确支持时才允许出现，并且不能伪装成卡片内部资源路径；正式引用形式以[06-资源协议规范](../05-接口与契约/06-资源协议规范.md) §2.2 为唯一集合（包内相对路径、`file://`、`http(s)://`、`webdav://`、`chips-resource://`），`data:` 仅运行时内存形态、禁止持久化；
- 网络资源卡片中的资源 URL 必须来自正式上传结果；
- `file://` 与 `webdav://` 在进入渲染前由解析器与资源代理归一为受管作用域 URI（[06-文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md) §3.5、[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) §5.1）；WebDAV 凭证保存在平台凭证存储，不写入卡片文件；
- 运行时统一经 `chips-resource://` 访问，受限、可审计；URI 语法、作用域与权限见[06-资源协议规范](../05-接口与契约/06-资源协议规范.md)。

### 8.3 嵌套卡片访问

- 嵌套卡片不是第一版内部资源访问模型。若卡片根目录中保存 `.card` 文件，它只是一个资源文件或由具体基础卡片 schema 定义的引用对象，不会被通用路径解析器自动当作目录展开。

```text
card-parent.card
├── nested.card
└── other-file.jpg
```

- 箱子可以在包内任意层级保存内嵌 `.card`（见[02-箱子文件格式](02-箱子文件格式.md)），这是箱子的引用模型；卡片自身的嵌套不触发自动展开。

### 8.4 资源缺失处理

当资源缺失时：

1. **卡片仍可打开**：不会因为资源缺失而无法打开；
2. **显示占位符**：缺失的资源位置显示占位图和提示；
3. **重新绑定**：用户可以在设置中重新指定资源路径；
4. **下载选项**：如果资源有网络备份，提供下载选项。
