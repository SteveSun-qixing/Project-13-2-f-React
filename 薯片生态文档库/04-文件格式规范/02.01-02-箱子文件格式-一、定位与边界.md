## 一、定位与边界

### 1.1 定位

箱子（Box）与卡片（Card）是并行概念，箱子不是卡片的一种类型：

- 卡片是单一内容的创作与管理单元；箱子是多个卡片引用的集合组织、展示编排与界面消费容器。
- 卡片可以直接使用，不需要放入箱子；箱子必须至少引用一个卡片才有意义。
- 一个卡片可以被任意多个箱子引用；箱子不复制外部卡片实体（内嵌卡片除外，见 2.4）。

本文件是 `.box` 格式的唯一权威定义：包结构、引用模型、全部字段、封面与资源规则、ZIP Store 打包方式与校验规则。解析实现、渲染实现、插件接口与工具链只能消费本文定义的格式，不得扩展或改写格式语义。

箱子与卡片共用平台统一链路（R8）：解析、资源访问、渲染、打开、导出使用同一条链路与同一套接口，仅在文件格式层区分。

### 1.3 术语

| 术语 | 定义 |
|---|---|
| 箱子（Box） | 卡片引用的集合容器，正式文件为 `.box` |
| 包（package） | 一个 `.box` 的完整内容；发布态为 ZIP Store，编辑态为平台内部工作目录，两者成员同构 |
| 包根（package root） | 发布态为 ZIP 归档根；包内相对路径一律相对包根解析 |
| 包内相对路径 | 以 `/` 分隔、相对包根、UTF-8 + NFC 的规范化路径；禁止 `..`、前导 `/`、反斜杠与控制字符 |
| 配置目录（`.box/`） | 包根下的核心配置目录，存放四个必需文件与封面附属资源 |
| 条目（entry） | `structure.yaml` 中的一条文档引用记录 |
| 条目 ID（`entry_id`） | 条目唯一标识，10 位 Base62 |
| 摘要快照（`snapshot`） | 条目的离线展示信息：文档 ID、标题、摘要、标签、封面摘要、上次已知修改时间、内容类型 |
| 布局索引（`layout_hints`） | 布局可直接消费的排序与分组索引信息 |
| 激活布局（`active_layout_type`） | 当前生效的布局类型标识 |
| 内嵌卡片 | 位于包内、随 `.box` 一起分发的 `.card` 实体 |
| 箱子封面 | `.box/cover.html` 及其附属资源构成的箱子本体封面 |
| 箱子自有资源 | `assets/` 下的布局资源、占位图、摘要封面快照等 |
| 箱子布局插件 | `boxlayout` 角色的插件，提供布局编辑器与布局渲染器 |

### 1.4 核心原则

1. **单文件正式形态**：正式产物是单个 `.box` 文件；编辑工作目录只作内部使用，不暴露为正式形态。
2. **URL 唯一定位**：箱子内部统一使用 `url` 记录卡片引用，不引入第二套位置字段。
3. **摘要优先**：箱子默认保存和输出卡片摘要，而不是卡片完整内容。
4. **平台统一解析**：URL 解析、网络访问、凭证注入、缓存与失败归一都由平台负责。
5. **布局资源独立**：箱子可以保存布局自有资源，但这些资源不等于卡片实体。
6. **按需加载**：运行时不要求一次性解析全部卡片。
7. **内嵌允许、嵌套包禁止**：包内允许放置 `.card`，禁止出现 `.box`（防止无限嵌套）。
