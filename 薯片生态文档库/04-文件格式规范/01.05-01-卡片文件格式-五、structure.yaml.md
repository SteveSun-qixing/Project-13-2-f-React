## 五、structure.yaml

### 5.1 完整 Schema

```yaml
# JSON Schema for structure.yaml
$schema: "https://json-schema.org/draft/2020-12/schema"
title: "Card Structure Schema"
type: object
required:
  - structure
  - manifest
properties:
  structure:
    type: array
    description: "基础卡片列表，按渲染顺序排列"
    items:
      type: object
      required:
        - id
        - type
      properties:
        id:
          type: string
          pattern: '^[0-9a-zA-Z]{10}$'
          description: "基础卡片 ID，对应 content/ 目录下的配置文件"
        type:
          type: string
          description: "基础卡片类型，决定使用哪个渲染器插件"
          examples: ["base.video", "base.image", "base.richtext", "base.score"]
  manifest:
    type: object
    description: "文件清单和元信息，用于快速索引和完整性验证"
    required:
      - card_count
      - resource_count
    properties:
      card_count:
        type: integer
        description: "基础卡片数量"
      resource_count:
        type: integer
        description: "资源文件数量"
      resources:
        type: array
        description: "资源文件清单"
        items:
          type: object
          required:
            - path
            - size
            - type
          properties:
            path:
              type: string
              description: "资源文件相对路径（相对卡片根目录）"
            size:
              type: integer
              description: "文件大小（字节）"
            type:
              type: string
              description: "文件 MIME 类型"
            duration:
              type: number
              description: "时长（秒），仅视频 / 音频文件"
            width:
              type: integer
              description: "宽度（像素），仅图片 / 视频文件"
            height:
              type: integer
              description: "高度（像素），仅图片 / 视频文件"
            language:
              type: string
              description: "语言代码，仅字幕文件"
            checksum:
              type: string
              description: "文件 SHA256 校验值"
```

### 5.2 完整示例

```yaml
# structure.yaml 示例

structure:
  - id: "a1B2c3D4e5"
    type: "base.richtext"

  - id: "f6G7h8I9j0"
    type: "base.video"

  - id: "k1L2m3N4o5"
    type: "base.image"

  - id: "p6Q7r8S9t0"
    type: "base.markdown"

manifest:
  card_count: 4
  resource_count: 5

  resources:
    - path: "intro.rtf"
      size: 2048
      type: "application/rtf"

    - path: "travel-video.mp4"
      size: 52428800
      type: "video/mp4"
      duration: 180.5
      width: 1920
      height: 1080
      checksum: "b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2c3"

    - path: "subtitle-zh.srt"
      size: 8192
      type: "application/x-subrip"
      language: "zh"

    - path: "photo.jpg"
      size: 1048576
      type: "image/jpeg"
      width: 3000
      height: 2000

    - path: "notes.md"
      size: 4096
      type: "text/markdown"
```

示例中的 `size` 与 `checksum` 为示意值，真实值由写入链路在保存 / 打包时计算。

### 5.3 清单规则与校验

- `structure[].id` 必须是 10 位 Base62 编号，并与 `content/` 下同名配置文件一一对应（即 `content/<id>.yaml`）。
- `structure[].type` 决定使用哪个渲染器插件；新写入必须使用基础卡片插件的正式类型标识（如 `base.richtext`、`base.video`、`base.image`、`base.score`、`base.webpage`、`base.music`、`base.file`），历史别名（如 `VideoCard`、`ImageCard`、`ScoreCard`、`WebPageCard`、`MusicCard`、`RichTextCard`、`FileCard`）只能读取归一，不作为新写入值。
- `structure` 按渲染顺序排列；每个基础卡片在数组中只出现一次。
- `manifest.card_count` 必须等于 `structure` 数组长度；`manifest.resource_count` 必须等于 `manifest.resources` 的条目数。
- `manifest.resources[].path` 为资源相对卡片根目录的路径；条目按 `path` 唯一。
- `duration` 仅用于视频 / 音频文件；`width` / `height` 仅用于图片 / 视频文件；`language` 仅用于字幕文件。
- `size`、`checksum` 由写入链路在保存 / 打包时计算，人工编辑工具必须保持其与真实文件同步。
- 资源清单用于快速索引与完整性验证；资源是否可访问仍以内容配置与封面中的引用为准。

### 5.4 职责分离

- `metadata.yaml`：只负责卡片自身元信息；
- `structure.yaml`：只负责结构关系（渲染顺序）与文件索引，不包含任何内容、样式或属性配置；
- `content/*.yaml`：负责具体内容配置。
