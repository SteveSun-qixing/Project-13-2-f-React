## 四、`metadata.yaml`

### 4.1 用途

`metadata.yaml` 记录箱子本身的元信息，是箱子的列表展示与搜索依据；其结构与卡片的元数据类似，但记录的是箱子的信息而非卡片的信息。

### 4.2 必需字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `chip_standards_version` | string | 薯片标准版本号，语义化版本；当前版本 `"1.0.0"`，见第十二节 |
| `box_id` | string | 箱子唯一 ID，10 位 Base62，创建时自动生成，全程保持唯一 |
| `name` | string | 箱子名称，支持用户自定义，用于识别和展示 |
| `created_at` | string | 创建时间，ISO 8601 UTC |
| `modified_at` | string | 修改时间，ISO 8601 UTC |
| `active_layout_type` | string | 当前生效布局类型标识，用于渲染箱子与装载布局插件 |

### 4.3 可选字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `description` | string | 箱子描述 |
| `tags` | array | 箱子标签，与卡片一致，支持简单标签与复杂标签 |
| `cover_ratio` | string | 箱子本体封面比例，`宽:高` 形式（例如 `3:4`），供正式封面渲染链路使用 |
| `cover_asset` | string | 箱子封面资源路径，指向 `assets/` |
| `owner` | string | 逻辑所有者标识 |
| `source` | object | 来源信息 |

### 4.4 取值与写入规则

- `box_id` 由创建工具生成，写入后不变；重新创建、复制产生新箱子时必须重新生成。
- `created_at` 与 `modified_at` 使用 ISO 8601 UTC 字符串（例如 `2026-03-23T09:30:00.000Z`）；每次保存更新 `modified_at`。
- 重命名箱子时，同时更新 `name` 与最终 `.box` 文件名。
- `tags` 为字符串数组，允许字符串项与字符串数组项混用（复杂标签），每项非空。
- `cover_ratio` 采用 `宽:高` 形式（例如 `3:4`）；箱子本体封面由 `.box/cover.html` 渲染，比例值供封面渲染链路使用（见第七节）。
- `cover_asset` 使用包内相对路径，必须以 `assets/` 开头。
- `active_layout_type` 必须存在，且与 `content.yaml` 的 `active_layout_type` 一致。
- 未在 4.2、4.3 定义的字段不得写入正式文件。

### 4.5 完整示例

```yaml
chip_standards_version: "1.0.0"
box_id: "b1C2d3E4f5"
name: "2026 旅行箱"
created_at: "2026-03-23T09:30:00.000Z"
modified_at: "2026-03-23T11:20:00.000Z"
active_layout_type: "chips.layout.grid"
cover_ratio: "3:4"
description: "用于浏览 2026 年旅行卡片集合"
tags:
  - "旅行"
  - ["年份", "2026"]
cover_asset: "assets/placeholders/default-cover.webp"
```
