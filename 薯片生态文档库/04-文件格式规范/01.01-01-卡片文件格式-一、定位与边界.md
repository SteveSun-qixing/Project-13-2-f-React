## 一、定位与边界

### 1.1 定位

卡片（`.card`）是薯片生态自包含的知识单元文件，也是内容生态的最小交付单位。一张卡片包含自身的元数据、结构、内容与资源，不依赖创建它的程序即可被查看器、编辑器和第三方工具读取；可以被箱子引用，也可以直接使用。

本文件是 `.card` 格式的唯一权威定义：目录结构、字段语义、内容 schema 约定、封面规则、资源引用、ZIP Store 打包、版本与完整性校验。全部写入实现（文档服务、迁移工具、第三方工具）与全部读取实现都必须以本文件为准。

### 1.3 术语

| 术语 | 定义 |
|---|---|
| 卡片（Card） | 自包含知识单元，正式文件为 `.card` |
| 基础卡片 | 最小知识单元的内容类型，由基础卡片插件定义 |
| 包（package） | 一个 `.card` 的完整内容；目录态与发布态内容同构 |
| 包根（package root） | 目录态为卡片根目录；发布态为 ZIP 归档根 |
| 卡片根相对路径 | 以 `/` 分隔、相对包根、UTF-8 + NFC 的规范化路径；禁止 `..`、前导 `/`、反斜杠与控制字符 |
| 配置目录（`.card/`） | 包根下的隐藏配置目录，存放三个必需配置文件与封面附属资源 |
| 内容配置（`content/*.yaml`） | 每个基础卡片一个配置文件，扁平存放于 `content/` |
| 卡片资源 | 位于卡片根目录一侧、由内容配置或封面引用的原始字节文件 |
| 完整离线卡片 | 资源字节保存在 ZIP 内部的正式形态 |
| 网络资源卡片 | 资源字节不在 ZIP 内部、资源字段记录对象存储 / CDN URL 的正式形态 |

### 1.4 文件本质与识别

- `.card` 的本质是 ZIP 压缩包，后缀名为 `.card`；编码 UTF-8；MIME 类型 `application/x-card`（客户端传输链路正式 MIME 为 `application/vnd.chips.card+zip`）。
- 发布侧 ZIP 条目一律使用 Store 模式（零压缩率）：无需解压运算、支持随机访问，并且是社区上传、网页查看、客户端下载恢复链路保证条目字节不二次变换的前提。
- 读取侧接受 Store 与 Deflate 条目：发现 Deflate 时正常解析，仅在发布、上传或下载恢复链路中按规范转换为 Store 模式（或提示该文件不符合正式发布要求）；读取端不得因 Deflate 而拒绝打开。
- ZIP64：`.card` 读取侧支持 ZIP64 归档（成员数或尺寸超出经典 ZIP 上限时）；发布侧一律不产生 ZIP64。差异表见[04-版本与迁移规范](04-版本与迁移规范.md) §2.3。
- 操作系统文件关联：双击 `.card` 文件自动用卡片查看器打开；把扩展名改为 `.zip` 后可用任何解压工具查看内部结构。
- 归档是标准 PKZIP，无自定义头部、无自定义校验块、无加密、无专有索引区，第三方可用标准 ZIP 工具直接打开。
