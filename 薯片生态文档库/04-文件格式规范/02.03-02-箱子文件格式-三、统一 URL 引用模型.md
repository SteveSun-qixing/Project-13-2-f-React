## 三、统一 URL 引用模型

### 3.1 URL 唯一定位

- `structure.yaml` 中每个条目都必须包含 `url` 字段；`url` 是箱子定位卡片的唯一正式方式。
- 不再区分"卡片在箱子内部还是外部"两套字段；"内嵌"与"外部"由 `url` 的形态判定，不引入第二套位置字段。
- 其他可被生态正式支持的定位方式，也必须统一折叠为 URL 表达，而不是继续保留另一套路径字段。

### 3.2 URL 形态与判定

| 形态 | 表达 | 示例 |
|---|---|---|
| 外部引用 | 绝对 URL | `file:///Users/name/Cards/day-01.card`、`https://example.com/demo.card` |
| 内嵌引用 | 包内相对路径 | `day-01.card`、`subdir/day-01.card` |

判定规则：`url` 不以 `[a-z][a-z0-9+.-]*://` 形式开头时，视为包内相对路径（内嵌引用），必须以 `.card` 结尾。

### 3.3 绝对 URL 基线

首版正式基线支持的绝对 URL：

1. `file://`（可指向 `.card` 或 `.box`）
2. `http://`
3. `https://`
4. `webdav://`（或由平台正式映射的 WebDAV URL 形式）

- 平台可在基线之外扩展更多 resolver scheme（例如受管资源引用 `chips-resource://`，其语法与权限见[资源协议规范](../05-接口与契约/06-资源协议规范.md)）；无论 scheme 如何扩展，文件格式层始终只记录 URL。
- 内嵌引用与外部引用统一由 `url` 表达，不再引入第二套本地路径字段。
- 运行时归一：`file://`、`http(s)://`、`webdav://` 在进入渲染前由解析器与资源代理归一为受管作用域 URI（`file://` → 文档作用域，`http(s)://` / `webdav://` → external 作用域），规则见[06-资源协议规范](../05-接口与契约/06-资源协议规范.md) §2.2、§2.6 与[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md) §5.1；WebDAV 凭证保存在平台凭证存储，不写入箱子文件（第十一节）。

### 3.4 约束与禁止写法

1. 外部引用必须是绝对 URL；本地文件必须写为 `file://` URL。
2. 内嵌引用必须是以 `.card` 结尾的包内相对路径，不得包含 `..` 穿越，且目标必须存在于包内。
3. 内嵌引用不得指向 `assets/` 下的文件；该目录只存放箱子自有资源。
4. 箱子条目不得使用"是否在内部"字段辅助解析。
5. 认证信息不得写入 URL。
6. 禁止裸绝对路径、`data:` / `blob:` 运行时地址与未列出的 scheme：

```yaml
# 错误：裸绝对路径
url: "/Users/name/day-01.card"

# 错误：Windows 绝对路径（反斜杠；正斜杠形式 C:/Cards/... 同样禁止）
url: "C:\\Cards\\day-01.card"

# 错误：运行时地址
url: "blob:https://example.invalid/9f8e7d"

# 错误：未列出的 scheme
url: "ftp://example.com/day-01.card"

# 错误：目录穿越
url: "../shared/day-01.card"
```

文档服务等写入实现（导出、迁移工具、第三方工具）必须拒绝以上写法；解析链路对非法引用返回 `ENTRY_SOURCE_INVALID`（诊断码见[文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md)）。

### 3.5 摘要信息与实体的分工

- `structure.yaml` 除 `url` 外还保存文档摘要信息（`snapshot`）与布局索引（`layout_hints`）：统一的 `document_id`、标题、摘要、标签、上次已知修改时间、封面摘要、排序信息与启用状态。
- 摘要信息用于布局排序、离线提示和列表预览，但不等于卡片或箱子实体本身（内嵌卡片除外，其实体在包内）。
- 外部引用的卡片文件仍由平台在消费时按 URL 解析，不会被复制进箱子内部；内嵌卡片则随打包进入 `.box`。
