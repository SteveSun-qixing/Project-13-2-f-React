## 八、错误码

安装与打包共用的包校验错误码（均不可重试，`ChipsError.retryable` 为 `false`）：

| 错误码 | 含义 |
|---|---|
| `CPK_ARCHIVE_INVALID` | 非 ZIP、归档损坏、加密、ZIP64、成员非 Store、CRC 失败、重复路径、嵌套归档 |
| `CPK_LAYOUT_INVALID` | 包根出现白名单外条目、角色布局不符、隐藏文件、无用资源告警 |
| `CPK_MANIFEST_MISSING` | 包根缺少 `manifest.yaml` 或存在多份清单 |
| `CPK_MANIFEST_INVALID` | manifest 语法或 schema 失败、路径引用非法或缺失、与源码 `package.json` 版本不一致 |
| `CPK_ENGINE_UNSUPPORTED` | 插件 `engines.chips` 不满足当前平台版本（安装 / 启用拒绝）；字段与门禁见 [02-插件清单规范](../03-插件开发/02-插件清单规范.md) §3.6、[06-更新与分发规范](../06-开发与运维/06-更新与分发规范.md) §3.3 |
| `CPK_ENTRY_MISSING` | 角色要求的 `dist/index.js` 或 `render.js` 缺失、非文本或非 ESM |
| `CPK_NATIVE_PAYLOAD` | 携带原生可执行载荷（扩展名或魔数判定） |
| `CPK_PATH_UNSAFE` | 路径穿越、绝对路径、符号链接、非法字符、保留设备名、大小写冲突 |
| `CPK_LIMIT_EXCEEDED` | 体积、成员数、单文件、清单大小、路径长度或深度超限 |
| `CPK_SIGNATURE_REQUIRED` | 来源渠道要求签名而缺失 |
| `CPK_SIGNATURE_INVALID` | 签名结构、`keyId`、`contentHash` 或签名值校验失败 |

错误统一归一为 `ChipsError`（错误模型见 [01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) 与 [02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md)）：

```json
{
  "code": "CPK_NATIVE_PAYLOAD",
  "message": "插件包包含不受支持的原生可执行文件：native/helper.node",
  "details": { "file": "native/helper.node", "stage": "payload" },
  "retryable": false
}
```

`details` 必须携带：阶段（`archive` / `layout` / `manifest` / `signature` / `hash`）、成员路径、字段指针（如 `capabilities.cardTypes[0].icon`）；面向用户的消息使用简体中文。
