## 五、兼容判定与确定性错误

### 5.1 判定矩阵

| 判定对象 | 规则 | 不满足时的确定性结果 |
|---|---|---|
| 文档 `chip_standards_version` 主版本与平台 | 必须与平台支持的文档格式主版本一致 | 文档主版本低：`DOCUMENT_VERSION_OUTDATED`，打开失败并提示运行迁移工具；文档主版本高：`DOCUMENT_VERSION_UNSUPPORTED`，打开失败并提示升级平台 |
| 文档 `chip_standards_version` 次版本与平台 | 不高于平台支持的文档格式次版本 | `DOCUMENT_VERSION_MISMATCH`（警告），正常打开并透出诊断；未知字段按未知字段策略处理，不得静默丢弃 |
| 文档 `chip_standards_version` 缺失、非法，或含预发布标识 / 构建元数据 | 必须是严格三段式语义化版本 | `DOCUMENT_METADATA_INVALID`，打开失败 |
| 插件依赖范围与提供方版本 | 按第四节范围匹配 | `KERNEL_DEPENDENCY_VERSION`，插件停留 `pending` 等待依赖更新 |
| 插件更新与依赖者范围 | 新版本必须满足全部已安装依赖者的范围 | 拒绝更新，返回结构化错误并列出不满足的依赖者 |
| 插件安装为降级版本 | 目标版本必须高于已安装版本 | 确定性拒绝，不覆盖已安装版本 |
| 平台与插件 | 平台不为旧格式、旧清单 schema、旧接口提供加载路径 | 安装或加载确定性失败；插件须按当前平台重建后重新发布 |

### 5.2 三条铁律

1. **确定性**：每个版本不匹配场景都有明确判定与结构化错误码；同一输入必须得到同一结果。
2. **不静默**：禁止忽略版本判定结果、禁止隐式降级、禁止"尽力解析"；警告必须以诊断形式透出。
3. **不猜测**：缺失、非法、越界的版本字段一律按错误处理，不推断用户意图。

版本错误码沿用各子系统已定义的码族（`DOCUMENT_*`、`RENDER_*`、`KERNEL_*`、`CPK_*`、`CONFIG_*`）；文档格式版本门禁使用 `DOCUMENT_VERSION_OUTDATED`、`DOCUMENT_VERSION_UNSUPPORTED` 与 `DOCUMENT_VERSION_MISMATCH`，诊断码表由 [06-文档解析器设计](../01-架构设计/01-子系统设计/06-文档解析器设计.md) §八维护。错误统一为 `ChipsError`（`code` / `message` / `details` / `retryable`）结构。

### 5.3 判定示例

| 输入 | 平台支持的文档格式版本 | 结果 |
|---|---|---|
| `chip_standards_version: "1.0.0"` | `1.0.0` | 正常解析 |
| `chip_standards_version: "1.1.0"` | `1.0.0` | `DOCUMENT_VERSION_MISMATCH`（警告），正常打开并透出诊断 |
| `chip_standards_version: "0.9.0"` | `1.0.0` | `DOCUMENT_VERSION_OUTDATED`，打开失败，提示运行迁移工具，不自动改写 |
| `chip_standards_version: "2.0.0"` | `1.0.0` | `DOCUMENT_VERSION_UNSUPPORTED`，打开失败，提示升级平台 |
| `chip_standards_version: "1.0.0-beta.1"` | `1.0.0` | `DOCUMENT_METADATA_INVALID`，打开失败（文档格式版本禁止预发布） |
| 缺少 `chip_standards_version` | `1.0.0` | `DOCUMENT_METADATA_INVALID`，打开失败 |
