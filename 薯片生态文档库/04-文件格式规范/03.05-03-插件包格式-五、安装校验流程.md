## 五、安装校验流程

### 5.1 流程

```
用户 / 插件市场 / CLI 提供 .cpk
        │
        ▼
[1] 归档校验     ZIP 可读、Store、无加密、无重复、CRC、路径安全、限额
        │
        ▼
[2] 结构校验     根目录白名单、角色布局、入口存在、无原生载荷、无嵌套归档
        │
        ▼
[3] 清单校验     manifest schema、ID / 版本 / 角色、路径引用、与包内容一致
        │
        ▼
[4] 签名校验     按来源渠道（builtin / user / development）执行
        │
        ▼
[5] 摘要与落盘   计算安装摘要 → 暂存目录 → 原子替换 → 写注册表（installed）
```

### 5.2 各阶段判定

[1] 归档校验：按 §2.1 逐项判定；解包规模不得超过 §4 限额；任何失败立即终止。

[2] 结构校验：

- 包根只允许 §2.3 白名单条目；
- 按 `manifest.type` 校验角色布局（§3.1）：`service` 出现 `render.js` 或 UI 资源、`basecard` / `boxlayout` / `app` 缺少 `render.js` 均为拒绝；
- 原生载荷双重判定：扩展名（`.node`、`.dll`、`.dylib`、`.so`、`.exe`、`.msi`、`.com`、`.bat`、`.cmd`、`.sh`、`.ps1`、`.wasm`）与文件魔数（PE `MZ`、ELF `7F 45 4C 46`、Mach-O `FE ED FA CE` / `FE ED FA CF` / `CA FE BA BE`、WASM `00 61 73 6D`）；命中任一即 `CPK_NATIVE_PAYLOAD`；
- 测试文件、sourcemap（`*.map`）、锁文件、源码目录一律拒绝。

[3] 清单校验：执行 manifest schema 校验与字段级校验（完整规则见 [02-插件清单规范](../03-插件开发/02-插件清单规范.md)）；声明 `engines.chips` 时校验当前平台版本落在范围内（不满足返回 `CPK_ENGINE_UNSUPPORTED`，语义见 [02-插件清单规范](../03-插件开发/02-插件清单规范.md) §3.6、[06-更新与分发规范](../06-开发与运维/06-更新与分发规范.md) §3.3）；校验 `dist/index.js` 与角色要求的 `render.js` 存在且为 UTF-8 文本 ESM；校验 §2.6 的路径引用；包内其它文件不得声明与清单冲突的 ID、版本或角色。

[4] 签名校验：按第六节的来源渠道规则执行；签名校验不替代其它任何校验。

[5] 摘要与落盘：

- 安装摘要定义为 `hash = "sha256:" + SHA-256(整个 .cpk 文件字节)`，写入插件注册表用于完整性校验与更新比对；
- 校验全部通过前不得落盘；落盘采用“临时目录 → 校验 → 原子重命名”；
- 安装失败必须清理临时目录，注册表不得产生记录，不得留下半成品。

### 5.3 与生命周期的衔接

- 安装只产生 `installed` 状态，不自动启用；依赖缺失或版本不满足不阻止安装，只在启用时阻塞；
- 同 ID 更新走蓝绿替换流程；降级默认拒绝；权限集合变化必须重新确认；
- 安装、更新、卸载的状态迁移与失败处理以 [03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 为准。
