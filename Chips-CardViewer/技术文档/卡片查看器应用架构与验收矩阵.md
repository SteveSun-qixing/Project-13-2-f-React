# 卡片查看器应用架构与验收矩阵

## 1. 文档定位

本文档记录 `Chips-CardViewer` 项目内部实现边界和任务029迁移后的验收矩阵。公共接口、SDK 契约、箱子运行时和资源打开规范以 `生态共用技术文档/` 为准；本文不定义新的生态公共协议。

## 2. 项目边界

卡片查看器是 `type: app` 应用插件，是 `.card/.box` 查看入口和 Host 托管显示链路的消费方。

正式边界：

- 不解析 `.card/.box` 内部结构；
- 不直接 import 基础卡片插件、箱子布局插件或旧卡片技能实现；
- 不自行拼接复合 iframe、基础卡片 iframe 或箱子布局页面；
- 不硬编码资源处理器应用 ID；
- 不在应用内私建第二套文件入口或命令系统。

应用只通过 `chips-sdk`、`window.chips.*` 正式 Bridge 和 `@chips/ui` 共享层消费 Host 能力。

## 3. App / Scene / Surface 模型

当前根链路：

- `src/App.tsx`：轻量导出根组件；
- `src/app/AppRoot.tsx`：组合 `ConfigProvider`（antd 苹果风格 + zh-CN）、`ChipsProvider`、`AppRuntimeProvider` 与 `CommandProvider`；
- `src/app/AppRuntimeProvider.tsx`：解析 launch context、surface context、打开目标、错误和 trace；空态使用 `immersive` surface，任一已打开目标使用 `document` surface，使滚动所有权收口到最外层页面；
- `src/app/AppShell.tsx`：注册命令处理与快捷入口，并按 scene 渲染内容；空态使用共享层 `AppChrome` 承载菜单与工具栏；本地文档查看态在左上角提供“返回首页”按钮，清空当前打开目标并回到 `empty` scene；托管文档通过 `plugin.chrome.update` 把插件接管的返回语义、标题和封面切换动作交给 Web 外层宿主渲染。

内部 scene：

- `empty`：空启动，显示拖拽和打开文件入口；
- `document-file`：通过本地 `.card/.box` 文件路径进入正式文档窗口；
- `hosted-document`：通过 `launchParams.webDocumentUrl` 承载 Host 已生成的托管文档 URL。

`hosted-document` 是 CardViewer 内部恢复路径，不在本文提升为新的生态公共启动契约。

## 4. `.card/.box` 文件显示链路

`DocumentFileScene` 把文件目标交给 `CardWindow`。`CardWindow` 只调用：

```ts
client.document.window.render({
  filePath,
  locale,
  mode: "view",
});
```

实际分发由 SDK 完成：

- `.card` 分发到 `client.card.compositeWindow.render(...)`；
- `.box` 分发到 `client.box.documentWindow.render(...)`。

事件消费：

- `onReady`：关闭加载态；
- `onResize`：消费卡片 `chips.composite:resize` 或箱子 `chips.box-layout:resize`，同步撑开内容 iframe；
- `onError`：显示整张文档 fatal 错误；
- `onNodeError`：记录复合卡片节点降级日志，不把单节点失败升级成整张文档失败；
- `onResourceOpen`：调用 `client.resource.open(...)`，失败时通过 `client.platform.showMessage(...)` 显示可诊断错误。

滚动与高度职责：

- 内容 iframe 设置 `scrolling="no"`，不创建中间全高滚动容器；
- `CardWindow` 根据 `onResize` 的正式文档高度更新 iframe 高度；
- `html/body/#root` 与查看器壳层在已打开目标存在时保持普通 document flow，由最外层页面负责滚动；
- 返回空态后恢复 `immersive` surface，并重新使用视口约束。

生命周期：

- 目标变化或组件卸载时，清理 SDK 事件订阅；
- 调用 `FrameRenderResult.dispose()` 释放卡片 render session 或箱子 document window session；
- 从 DOM 移除旧 iframe 后再挂载新 iframe；
- 用户点击查看态左上角返回按钮时，`AppRuntimeProvider.returnHome()` 清空 `openedTarget` 与错误态，文档窗口随 React 卸载走同一套 dispose 清理链路。

## 5. 托管文档承载链路

`HostedDocumentWindow` 用于已经由 Host 提供 `webDocumentUrl` 的场景。该链路直接挂载 `documentUrl` 到 sandbox iframe，并只消费正式运行时消息：

- `chips.composite:ready`
- `chips.box-layout:ready`
- `chips.composite:fatal-error`
- `chips.box-layout:error`
- `chips.composite:resize`
- `chips.composite:resource-open`

sandbox 固定为 `allow-scripts allow-forms`。消息来源允许当前应用 origin、iframe 标记的 `data-chips-origin`，以及 sandbox opaque origin `null`。

高度变化通过 `plugin.surface.resize` 发布，载荷包含 `height`、`contentHeight`、`safeBlockEnd`、`viewportHeight`、`reason` 和 `stable`。

当托管文档来源携带 `coverUrl` 时，查看器在 Web 文档型 surface 中通过外层 chrome 发布封面切换动作；宿主点击该动作后以 `plugin.chrome.action` 回传，查看器切换到 `ViewerCoverSurface`。封面 surface 也通过 `plugin.surface.resize` 发布自身文档高度，避免从长正文切换到封面时沿用旧 iframe 高度。

## 6. 命令系统

当前命令定义位于 `src/commands/card-viewer-commands.tsx`：

- `commandId`: `com.chips.card-viewer.open-file`
- `handlerId`: `open-file`
- 权限：`platform.read`
- 菜单：`menuId=file`
- 工具栏：`toolbarId=main`

命令模型采用共享层 `CommandItem`（中文标题、antd 图标、menuId/toolbarId/group/keywords），由 `useCardViewerCommands()` 通过 `useCommandRegistry().register()` 注册到 `CommandProvider`，空态 `AppChrome` 据此渲染菜单与工具栏。

Host 侧的正式链路保持不变：`client.command.register(cardViewerCommandDefinitions)` 维持 SDK command registry 接入，空态“打开文件”入口仍通过 `client.command.invoke(..., { source })` 进入正式处理器，`onInvoked` 事件消费后由 `AppShell` 调用 `runtime.openFile()`。命令 metadata 只包含 i18n key、IconDescriptor、scope、permission 和 placement，不写原始显示文案。查看态不渲染应用内菜单栏或工具栏，避免文档内容窗口上方出现应用内菜单栏。

## 7. 外观与文案

外观链路：

- 统一使用 `@chips/ui` 的 `appleTheme`（antd `ConfigProvider`），单一亮色外观；
- 组件内取色全部来自 antd token / 固定色值常量，不读取 Host 主题注入、不监听 `theme.changed`；
- `CardWindow` 不再因主题变化重新渲染内容 iframe。

文案链路：

- 界面文案统一简体中文直写，来源为 `src/lib/messages.ts` 中文表；
- `AppRuntimeProvider` 暴露 `t(key, params, fallback)`，组件调用点保留 `runtime.t("...")`，翻译函数只查询中文表；
- 不订阅语言变化事件、不同步 `html[lang]`/`html[dir]`/`data-chips-locale`；
- 命令标题、描述、aria、空态、错误态、加载态和 iframe title 均使用中文文案。

## 9. 任务029闭环边界

任务029闭环后，CardViewer 已完成以下范围：

- `.card/.box` 文件入口对齐 `manifest.yaml` 与 SDK 文档窗口；
- App/Scene/Surface 结构对齐应用插件 vNext 基线；
- 命令、外观（antd `appleTheme`）、中文文案、资源打开和可访问性接入正式链路；
- 真实素材回归覆盖卡片、箱子和复合卡片事件协议。

未实现的产品能力不在当前文档中承诺。后续若要新增最近打开、导出、诊断面板、阅读模式或更多查看工具，应在对应新任务中先核对公共契约与现有代码，再补充项目文档或生态共用技术文档。
