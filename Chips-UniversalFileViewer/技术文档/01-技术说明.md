# 万能文件查看器 技术文档

**版本**：0.1.0
**日期**：2026-08-29

---

## 1. 架构总览

```
Host surface 窗口
└─ 应用壳（antd + @chips/ui：AppRoot → AppRuntimeProvider → AppShell/AppChrome）
   ├─ AppRuntimeProvider        启动编排：launch intake → 资源装载 → 会话状态
   ├─ UniversalViewerStage      舞台：元信息条 + antd 工具栏 + 引擎容器 + 空态/反馈
   ├─ EngineViewer              引擎桥接：createViewer 挂载 + toolbar.render 上下文回传
   ├─ ViewerToolbar             antd 工具栏：消费 PreviewToolbarRenderContext
   └─ viewer-engine/            open-file-viewer core 移植层（MIT，二次开发）
```

边界声明：

1. 不解析 `.card/.box` 内部结构，不硬编码其他应用插件 ID；
2. 不绕过 `window.chips.*` / `chips-sdk` 访问系统能力；
3. 不私建第二套文件关联配置，默认查看器治理走 Host 正式链路；
4. 文案全部经 `src/lib/messages.ts` 简体中文直写，无 i18n 运行时。

## 2. 引擎移植（viewer-engine）

1. 来源：`open-file-viewer` monorepo `packages/core/src`（v0.1.43，MIT License）；
2. 移植方式：整包源码移入 `src/viewer-engine/`，参与本项目 Vite 构建；许可证归属文件 `LICENSE.open-file-viewer` 保留在该目录；
3. 适配改动：
   - `optional-modules.d.ts` 追加 `@mlightcad/cad-simple-viewer`、`@mlightcad/data-model` 模块声明（本工程不安装 GPL-3.0 的 `@mlightcad/libredwg-web`，DWG WebGL 链路保持惰性）；
   - `plugins/cad-webgl.ts` destroy 回调补齐 `error: unknown` 类型；
4. 插件装配：`src/utils/engine-plugins.ts` 按「专用格式优先、fallback 兜底」顺序装配 17 个格式插件；PDF worker 经 Vite `?url` 注入；
5. 依赖版本：与上游 lockfile 已解析版本逐一锁齐（精确版本，无 `^`）；
6. lint 边界：`src/viewer-engine/**` 从本仓 ESLint 排除（模板字符串内含业务空白，不能自动修复），类型正确性由 `tsc` 保证。

## 3. 启动恢复与资源解析

### 3.1 启动目标归一（`src/utils/launch-resource.ts`）

1. `launchParams.resourceOpen.payload` 为 `chips.book-card` + `mode:"image-sequence"` 时，恢复有序图片队列并按顶层资源定位初始索引（相对路径 → 资源基准 URL 推导，逻辑与图片查看器同源）；
2. 其余场景（含 ebook / video / music payload）取 `resourceOpen.filePath ?? launchParams.targetPath ?? resourceOpen.resourceId` 为唯一读取入口（契约要求）；
3. 无任何资源 → 空态场景。

### 3.2 资源装载（`src/utils/source-loader.ts`）

| 资源形态 | 装载策略 |
| --- | --- |
| `video/*`、`audio/*` | `resource.resolve` → URI 串流（解析失败回退原始标识） |
| 本地路径 / `file://` | `file.read(binary)` → File 对象（file:// URL 先解码路径） |
| http(s) | URL 字符串直接交引擎（CSP `connect-src` 已按书籍阅读器先例放开） |
| Host 托管资源 ID | `resource.readBinary` → File 对象 |

装载前经引擎 `isPreviewSupported` 门禁（fallback 兜底不算可用预览），不支持的类型给出「不支持预览」反馈。

## 4. 引擎桥接（`src/views/EngineViewer.tsx`）

1. 挂载：`useEffect` 中对容器调用 `createViewer({ files, locale:'zh-CN', theme:'light', plugins, toolbar })`，`items` 变化整体重建；
2. 工具栏上下文：向引擎传入 `toolbar.render` 回调，返回隐藏挂载点，同时经 `queueMicrotask + flushSync` 把 `PreviewToolbarRenderContext` 回传 React（`onToolbarContext`），回调经 ref 固定避免查看器反复重建；
3. antd 工具栏（`ViewerToolbar`）消费该上下文实现缩放/旋转/页码/搜索/另存/打印/全屏，能力探测用 `canCommand`。

## 5. 会话编排（`src/app/AppRuntimeProvider.tsx`）

1. 就绪门控：`ChipsProvider` 的 `ready` 信号后才执行一次 launch intake（`launchHandledRef`）；
2. 会话令牌：每次装载递增 `sessionTokenRef`，丢弃过期装载结果；
3. 动作：`openFile`（`platform.openFile` 多选）、`dropFile`（`getPathForFile` + `file.path` 兜底）、`reloadCurrent`、`saveCopy`（`saveFile` + `file.copy` / `readBinary` + `file.write`）；
4. 反馈统一走 `ViewerFeedback`（info/success/error 三态浮层）。

## 6. 生态链路

1. 处理器声明：manifest `capabilities` 全部以 `@fallback` 层级声明（约 190 条），覆盖引擎真实可预览格式；`.card/.box/.dwg` 不声明；
2. 打开链路：任意上游 `client.resource.open(...)` → Host 解析（专用优先，兜底次之，偏好最高）→ `plugin.launch` 注入 `launchParams.resourceOpen` → 本插件恢复；
3. 系统文件关联：macOS 安装器扫描本插件 `file-handler:@fallback` 声明注册 Info.plist 文档类型；
4. 命令行入口：`universal-file-viewer open <path>`（`cli.commands`，`mapsTo: targetPath`）。
