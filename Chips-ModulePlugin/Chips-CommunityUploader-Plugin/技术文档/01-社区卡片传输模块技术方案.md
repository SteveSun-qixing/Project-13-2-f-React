# 社区卡片传输模块技术方案

> 模块 ID：`chips.module.chips.community-uploader`
> 能力：`community.card.transfer`
> 更新时间：2026-08-06
> 本模块只在薯片客户端/Host 中运行；Web 浏览器运行时不加载。

## 1. 职责边界

- 在用户设备上处理 `.card` 上传、网络资源卡片生成、远程打开和完整卡片下载恢复；
- `uploadBox` 上传 `.box` 箱子到社区：收集散落卡片（`file://` 引用）逐个走卡片上传链路、内嵌/网络卡片跳过、箱子 structure.yaml 保持原始引用、箱子本体走 `contentType: 'box'` 控制面会话并直传对象存储；
- 只通过 Host `window.chips.*` / `chips-sdk` 正式链路访问系统能力；
- 通过社区 `card-transfer` 控制面 API 与服务器交互，文件字节直传对象存储/CDN；
- 统一处理对象存储 URL 改写与下载恢复，禁止调用方插件自行替换 YAML 或 HTML。
- 富文本 file-backed 内容内联：上传时把 `content_source: file` + `content_file` 内联为 `content_source: inline` + `content_text`，下载恢复时按恢复清单还原为 file-backed 并写回 markdown 资源。

## 2. 能力与契约

- `upload`：上传完整离线卡片，生成网络资源卡片并提交资源清单和恢复清单；
- `download`：按下载计划恢复完整离线卡片；
- `openRemote`：下载社区卡片的网络资源卡片到本地临时目录，通过 `surface.open` 启动本地卡片查看器（`com.chips.card-viewer`）解析渲染，资源按 CDN URL 在线加载；
- `uploadBox`：上传箱子到社区（流程见设计文档 task029 §6.2）：
  1. `box.inspect` 读取 metadata/structure/content 与条目清单；
  2. `box.unpack` 解包到工作目录；
  3. 遍历 `structure.entries`：内嵌（包内相对路径）与网络（http/https/webdav）条目跳过并记入 `skippedCards`；`file://` 条目收集本地卡片（文件缺失记 warning 不阻断）；
  4. 逐个调用 `upload` 完整卡片链路上传散落卡片（进度按窗口缩放合并到箱子上传总进度），单卡失败记 warning 不阻断；
  5. `structure.yaml` 保持原始引用不变（file:// 本地引用、内嵌相对路径、网络 URL 均原样保留）；社区匹配关系由服务器 `enrichCardRefs` 按 `snapshot.document_id` 动态提供，上传时不改写箱子文件内容（改写会导致下载回来的箱子引用社区网页 URL 而非本地卡片文件，卡片查看器无法解析封面）；
  6. 创建 `contentType: 'box'` 上传会话 → `box.pack` 重新打包工作副本 → 预签名 `box-file` 对象 → 直传对象存储 → `complete`（提交 metadata/structure/content JSON + box 对象位置）；
  7. 返回 `{ boxId, versionId, status, communityUrl, boxViewUrl, uploadedCards, skippedCards, warnings? }`。
- `getStatus` / `cancel`：由 Host `module.job.*` 任务链路承载。

输入输出 schema：

- `contracts/upload.input.schema.json`
- `contracts/upload.output.schema.json`
- `contracts/download.input.schema.json`
- `contracts/download.output.schema.json`
- `contracts/openRemote.input.schema.json`
- `contracts/openRemote.output.schema.json`
- `contracts/uploadBox.input.schema.json`
- `contracts/uploadBox.output.schema.json`

箱子上传实现说明：

- 散落卡片先于箱子本体上传（先传卡片再传箱子），保证服务器解析箱子时引用卡片已存在；
- 箱子本体预签名在 `box.pack` 之后执行，确保 `sizeBytes` 与实际上传字节一致（服务器 complete 阶段按对象大小校验）；
- 卡片上传的临时工作目录放在箱子工作区 `scattered-cards/{index}` 下，逐卡隔离互不冲突；
- 结果类型字段与 SDK `CommunityCardTransferBoxUploadInput / CommunityCardTransferBoxUploadedCard / CommunityCardTransferBoxSkippedCard / CommunityCardTransferBoxUploadResult` 对齐，模块侧类型为 SDK 类型的超集（`uploadedCards` 额外携带可选 `entryId`，`documentId` 在条目快照缺省时允许缺省，结果额外携带 `versionId/status/boxViewUrl/warnings`）。

## 4. 错误与任务事件

统一使用 `createCommunityUploaderError(code, message, details, retryable)`：

- `COMMUNITY_TRANSFER_INPUT_INVALID`
- `COMMUNITY_TRANSFER_CANCELLED`
- `COMMUNITY_TRANSFER_NETWORK_FAILED`
- `COMMUNITY_TRANSFER_AUTH_EXPIRED`
- `COMMUNITY_TRANSFER_HTTP_ERROR`
- `COMMUNITY_TRANSFER_RESPONSE_INVALID`
- `COMMUNITY_TRANSFER_OBJECT_UPLOAD_FAILED`
- `COMMUNITY_TRANSFER_OBJECT_DOWNLOAD_FAILED`
- `COMMUNITY_TRANSFER_FILE_LIST_FAILED`
- `COMMUNITY_TRANSFER_CARD_NOT_STORE_ZIP`
- `COMMUNITY_TRANSFER_UPLOAD_FAILED`
- `COMMUNITY_TRANSFER_DOWNLOAD_FAILED`
- `COMMUNITY_TRANSFER_BOX_INVALID`
- `COMMUNITY_TRANSFER_BOX_UPLOAD_FAILED`
- `COMMUNITY_TRANSFER_BOX_CARD_UPLOAD_FAILED`（warning：单卡上传失败不阻断箱子）
- `COMMUNITY_TRANSFER_BOX_CARD_FILE_MISSING`（warning：散落卡片文件缺失不阻断箱子）
- `COMMUNITY_TRANSFER_BOX_ENTRY_URL_INVALID`（warning：file:// 条目无法解析不阻断箱子）

进度阶段：

- 上传：`inspect -> unpack -> scan -> session -> upload-resources -> rewrite -> pack -> submit -> completed`
- 下载：`session -> download-card -> unpack -> restore -> pack -> completed`
- 箱子上传：`inspect -> unpack -> collect -> upload-cards -> rewrite -> box-session -> box-pack -> box-presign -> box-submit -> completed`；散落卡片自身的上传进度按 16%~72% 窗口缩放合并

重试与取消：

- 控制面请求和对象存储 PUT/GET 使用指数退避重试（最多 3 次）；
- 5xx / 408 / 429 视为瞬时失败自动重试；
- 401 / 403 立即抛出 `COMMUNITY_TRANSFER_AUTH_EXPIRED`，由调用方刷新签名后重新发起；
- 每次重试前检查任务信号，取消时抛出 `COMMUNITY_TRANSFER_CANCELLED`。

## 5. 第三方依赖评审

| 依赖 | 用途 | 许可证 | 维护状态 | 包体 | 安全风险 | 跨端 | 替代方案 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `yaml@^2.8.2` | 解析与写出 content/*.yaml 和封面配置，完成 URL 改写与恢复 | MIT | 活跃 | 极小（仅此模块内） | 无已知高危 | 纯 JS，Desktop/Mobile/Headless 均可 | 使用 JSON 配置文件会破坏现有卡片格式；不使用手写 YAML 解析器 |

说明：

- 该模块运行期唯一第三方依赖是 `yaml`，用于读写卡片配置 YAML；
- 已在卡片格式规范与社区 API 契约中收口资源改写语义，`yaml` 只做格式解析，不承担社区文件链路逻辑；
- 对象存储签名、ZIP Store 读写、任务调度均走 Host 正式能力，不新增运行时依赖；
- 开发依赖（vitest / typescript / eslint / esbuild / chips-sdk）只用于构建与测试辅助，不打进产物。

## 7. 权限说明（2026-08-05 补充）

`openRemote` 需要在用户设备上启动本地卡片查看器（`com.chips.card-viewer`），因此模块 manifest 声明以下额外权限：

- `window.control`：`surface.open` 动作的基础权限（创建 surface）；
- `plugin.manage`：`surface.open` 对 `type: plugin` 目标打开时的额外要求（Host 校验 `ensureCallerPermission(routeContext, 'plugin.manage', 'surface.open')`）。

缺少任一权限时，`openRemote` 会在下载 networkCard 成功后于 `surface.open` 阶段抛出 `PERMISSION_DENIED`。

## 8. 权限说明（2026-08-06 补充：uploadBox）

`uploadBox` 通过 Host `box.inspect / box.unpack / box.pack` 动作读取并重建 `.box` 工作副本，模块 manifest 声明以下额外权限：

- `box.read`：`box.inspect` 的基础权限；
- `box.write`：`box.unpack` / `box.pack` 的基础权限。

缺少任一权限时，`uploadBox` 会在对应 Host 动作阶段抛出 `PERMISSION_DENIED`。

## 9. 安装说明

- `openRemote` / `upload` / `download` / `uploadBox` 依赖模块被安装并启用；
- 客户端所在开发工作区（`.chips-host-dev`）必须通过 `chipsdev-r plugin install <cpk>` 安装本模块并 `chipsdev-r plugin enable`；
- 重新构建模块后需要 **先 uninstall 再 install**（`chipsdev-r plugin install` 不会替换已存在副本的 manifest 权限）；
- 若模块未安装，客户端点击社区卡片会回退到打开网页（旧行为），上传也会失败。

## 10. 两种发布模式（2026-08-11 补充：渲染产物上传）

`upload`（及 `uploadBox` 透传给散落卡片）新增 `publish.includeRenderArtifacts` 开关：

- `false`（默认）：仅上传源文件（网络资源卡片），渲染由服务器负责——社区服务器模式，行为与旧版一致；
- `true`：**个人服务器模式**，客户端渲染并直传产物：
  1. 调用 Host 模块代理 `ctx.module.invoke({ capability: 'converter.file.convert', method: 'convert', ... })` 把 `.card` 渲染为 HTML 目录（job 模式轮询，需 `Chips-FileConversion-Plugin` 与 `Chips-CardtoHTML-Plugin` 已安装启用）；
  2. 从解包目录组装封面产物：`.card/cover.html` → `index.html`，`.card/cardcover/*` → `cardcover/*`（封面缺失/空白时生成默认封面 HTML）；
  3. 以 `render-file` / `cover-file` 角色预签名并直传对象存储（产物对象键 `{cardId}/{cacheVersion}/{relativePath}`）；
  4. complete 提交 `renderArtifacts` 摘要（`rendererVersion` = `chips-client-renderer-1`），服务器校验后直接发布，卡片 `status = ready`；
- 转换模块不可用时抛出 `COMMUNITY_TRANSFER_RENDER_UNAVAILABLE`（retryable），提示需要安装转换模块；
- 渲染产物为空时记 `COMMUNITY_TRANSFER_RENDER_ARTIFACTS_EMPTY` warning，卡片保持 `pending`。

进度阶段（开启渲染产物时）：

- 上传：`inspect -> unpack -> scan -> session -> upload-resources -> rewrite -> render -> render-cover -> upload-render -> pack -> submit -> completed`
