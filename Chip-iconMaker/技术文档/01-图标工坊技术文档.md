# 图标工坊技术文档

## 1. 迁移边界

原始开源项目的 Python 与 Swift 实现只作为能力参考，不进入薯片应用插件运行时。原因是原实现依赖 Pillow、cairosvg、Tkinter、AppKit、`sips`、`iconutil` 与本地文件系统，这些都不符合应用插件的 Host surface 运行边界。

迁移后的正式实现位于 `src/icon-workbench/`：

- `IconMakerScene.tsx`：图标生成工作台 UI 与交互状态。
- `types.ts`：来源模式、字体背景、输出格式、尺寸、字体源与默认设置。
- `default-fonts.ts`：Material Symbols、Emoji 与自定义私用区码位图标源定义；Material Symbols 在运行时读取随包 `.codepoints` 资产补齐完整码位集合。
- `canvas-renderer.ts`：字体背景合成、图片适应/填充、字体图标居中渲染。
- `generator.ts`：按当前参数生成 PNG、ICO、ICNS 并打包为 `icons.zip`。
- `ico.ts`：ICO 容器编码。
- `icns.ts`：ICNS 容器编码。
- `zip-store.ts`：ZIP Store 归档编码。
- `image-loader.ts`：浏览器 File 与图片解码入口。
- `cli-runner.ts`：应用插件 CLI 命令执行器，负责读取输入图片、复用图标生成器、写入输出目录并通过 `cli.task` 上报进度与终态。
- `assets/fonts/material-symbols/`：内置 Material Symbols 三套 WOFF2 字体资产与来源追溯。

## 2. 应用插件链路

- `manifest.yaml` 声明 `id: com.chips.iconmaker`、`type: app`、`runtime.targets` 与 `ui.surface`；`permissions` 移除 `theme.read` / `i18n.read`，保留 `command.*`、`cli.task`、`file.*`、`log.write`。
- `src/app/AppRoot.tsx` 挂载 antd `ConfigProvider(zhCN, appleTheme)` + `App` + 共享层 `ChipsProvider` / `CommandProvider` + `AppRuntimeProvider` + `AppShell`。
- `src/app/AppRuntimeProvider.tsx` 通过共享层 `useChips()` 读取 `window.chips.*` 客户端与启动上下文，暴露环境信息、场景与本地诊断。
- `src/app/AppShell.tsx` 承载共享层 `AppChrome`（菜单栏/工具栏/命令面板）与图标工作台；命令通过 Host command 链路投递并在应用侧按 handlerId 处理（含 CLI 生成入口）。
- `src/commands/app-commands.tsx` 维护 Host 注册命令定义（`client.command.register`）与本地 `CommandItem` 命令（菜单/工具栏/命令面板）；所有命令文案为简体中文直写。
- `src/app/app-shell.css` 使用固定苹果风格颜色常量定义工作台布局、组件 surface 背景、预览区和响应式规则。

### 2.1 CLI 命令

`manifest.yaml` 只声明一条命令：

```bash
chips iconmaker generate <input> --output <dir> --formats png,ico,icns --size 256
```

命令目标是当前应用插件自身的 `com.chips.iconmaker.generate-icons` command。CLI 打开应用 surface 后通过 Host command 系统投递 payload，并等待应用通过 SDK `client.cliTask.*` 上报进度与完成结果。应用插件不拆分伴随模块，图片读取、图标生成与文件写入都在应用插件运行时中通过正式 SDK/Bridge 能力完成。

payload 字段：

- `inputPath`：输入图片绝对路径，支持 png/jpg/jpeg/webp/gif/svg。
- `outputDir`：输出目录，CLI 层按声明创建目录。
- `formats`：`png / ico / icns`，默认三种都生成。
- `size`：输出尺寸，默认 256，允许 16 到 1024 的整数。

## 3. 渲染模型

图标生成以当前界面状态为单一输入，不维护批量队列。`RenderIconOptions` 包含输出尺寸、工作台设置、来源模式、图片源、字体源与选中 glyph。

图片模式：

- 适应模式按比例缩放源图并保留约 8% 内边距，画布空白区域保持透明。
- 填充模式按中心裁剪策略把源图铺满画布。

字体模式：

- 默认字体源来自应用随包携带的 Material Symbols 字体资产和系统 Emoji 字体回退。
- Material Symbols 默认先提供最小兜底集合，随后读取 `MaterialSymbolsRounded[FILL,GRAD,opsz,wght].codepoints` 并刷新为完整码位集合。
- Emoji 图标源从 Unicode emoji/pictographic 范围生成候选集合，避免只展示少量样例。
- 自定义字体通过浏览器 `FontFace` 加载并注册到 `document.fonts`。
- 自定义字体选择面板使用从 `U+E000` 开始的私用区码位，当前生成 72 个候选 glyph。
- 字体模式的前景色与背景色通过当前设置实时重绘预览 Canvas；图片模式不绘制额外背景。

## 4. 产物格式

PNG 产物通过 Canvas `toBlob("image/png")` 生成。

ICO 产物写入标准 ICO 头、目录项与 PNG 图像数据。256 像素目录维度按 ICO 规范写入 `0`。

ICNS 产物写入 `icns` 文件头，并按输出尺寸选择合适的 PNG 类型块：

- `ic04`：16px
- `ic05`：32px
- `ic12`：64px
- `ic07`：128px
- `ic08`：256px
- `ic09`：512px

所有已勾选格式统一写入无压缩 ZIP Store，下载文件名固定为 `icons.zip`。该实现只写浏览器内存 ZIP 容器，不调用 Host ZIP 能力，因此 Manifest 不声明 `zip.manage`。

CLI 命令不生成 ZIP，而是按用户选择的格式直接写出独立文件，文件名沿用输入图片安全 basename，例如 `source.png / source.ico / source.icns`。

## 5. 主题与多语言

- 界面文案使用简体中文直写；`src/lib/messages.ts` 维护中文文案表，`IconMakerScene` 通过 `text(key, params)` 插值取值，不再接入多语言系统。
- 视觉样式统一由 antd `appleTheme`（`@chips/ui`）与 `@chips/ui/global.css` 提供；纯结构容器使用原生 `div / section / main`。
- UI 控件使用 antd（`Button`、`Checkbox` 等）与 `@chips/ui` 共享层组件（`AppChrome`、`StateBoundary`、命令系统）。
- 工作台 CSS 使用固定苹果风格颜色常量（`--icon-maker-*`），不读取任何 `--chips-*` 主题变量。
- 运行时图标使用 `@ant-design/icons`；Material Symbols 字体资产仍由工作台作为渲染兜底使用。应用启动图标仍由 `manifest.ui.launcher.icon` 指向 `assets/icons/app-icon.ico`。

## 6. 质量门禁

核心二进制编码由 `tests/unit/icon-encoders.test.ts` 覆盖。应用插件契约由 `tests/unit/commands.test.ts`、`tests/unit/app.test.tsx` 与 `tests/e2e/basic-flow.test.ts` 覆盖。

正式验证链路以项目 `package.json` 为准：

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run validate
```

人工测试 CLI 链路：

```bash
chipsdev-r plugin install Chip-iconMaker/manifest.yaml
chipsdev-r plugin enable com.chips.iconmaker
CHIPS_CLI_JOB_PROGRESS=1 chipsdev-r iconmaker generate /绝对路径/source.png --output /绝对路径/out --formats png,ico,icns --size 256
```

预期：stderr 显示 `CLI task ...` 进度，stdout 输出完成摘要；输出目录中出现对应格式文件。
