# 命令行集成与工作流设计

## 1. CLI 入口

`chipsdev-r` 当前正式支持：

```bash
chipsdev-r create module <targetDir>
```

也支持为模块模板矩阵传入显式参数：

```bash
chipsdev-r create module <targetDir> \
  --template module-html-rendering \
  --plugin-id chips.module.html.render \
  --capability converter.html.render

chipsdev-r create module <targetDir> \
  --template module-orchestration \
  --capability converter.file.convert \
  --consumes converter.card.to-html@^1.0.0 \
  --consumes converter.html.to-pdf@^1.0.0
```

与模块脚手架的集成位于 `Chips-SDK/cli/index.js`，流程如下：

1. 解析 `type === "module"`；
2. 定位 `Chips-Scaffold/chips-scaffold-module`；
3. 确保脚手架包已构建；
4. 构造 `CreateModuleProjectOptions`；
5. 调用 `createModuleProject(options)`；
6. 对生成工程执行工作区注册与 `volta.extends` 适配。

## 2. 默认参数推导

- `projectName`：取目标目录名；
- `slug`：由目标目录名规整化而来；
- `pluginId`：`chips.module.${slug.replace(/-/g, ".")}`；
- `templateId`：默认 `module-standard`，可由 `--template` 覆盖；
- `pluginId`：默认 `chips.module.${slug.replace(/-/g, ".")}`，可由 `--plugin-id` 覆盖；
- `moduleCapability`：默认 `module.${slug.replace(/-/g, ".")}`，可由 `--capability` 覆盖；
- `moduleConsumes`：默认空数组，可用一个或多个 `--consumes capability` 或 `--consumes capability@versionRange` 写入；
- `displayName`：由目录名自动转为标题格式；
- `version`：默认 `0.1.0`。

## 3. 工作区适配

当目标目录位于生态根工作区内时：

- 若当前工作区配置未覆盖该路径，自动把工程加入根 `workspaces`；
- 自动写入相对根目录的 `volta.extends`；
- 不注入 `file:` 或其他临时依赖。

## 4. 错误处理

- 脚手架包缺失：直接报错并停止；
- 脚手架未构建：先触发构建，再继续；
- 模板渲染失败：直接透传明确错误；
- 不支持的 create 类型：列出当前正式支持类型。

## 5. 模板选择约束

- `--template` 只选择 `chips-scaffold-module/templates` 下存在且元数据合法的模板；
- `--plugin-id`、`--capability` 只覆盖最终写入模板的值，不改变默认推导规则；
- `--consumes` 只渲染 `manifest.module.consumes`，不会自动安装或调用下游模块；
- 对编排模板，真实下游能力仍必须通过 Host 模块服务发现和调用；
- Host 运行期会校验 `ctx.module.invoke(...)` 目标 capability 是否已写入当前模块的 `module.consumes`；未声明依赖返回 `MODULE_CONSUME_UNDECLARED`，版本范围无匹配 provider 返回 `MODULE_PROVIDER_NOT_FOUND`。

## 6. 生成工程联调入口

生成工程 README 统一推荐：

```bash
chipsdev-r module invoke \
  --capability <capability> \
  --method <method> \
  --input '<json>' \
  --timeout-ms 60000
```

该命令会先执行正式构建，再在开发工作区安装并启用当前模块 `.cpk`，最后通过 Host `module.invoke` 调用 capability/method。`--timeout-ms` 同时作为 CLI 等待窗口与 Host 方法级超时；sync 方法超时返回 `MODULE_TIMEOUT`，job 方法超时后进入 `failed`。
