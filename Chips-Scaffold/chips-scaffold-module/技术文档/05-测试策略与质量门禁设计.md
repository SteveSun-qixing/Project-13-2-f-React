# 模块插件脚手架测试策略与质量门禁设计

## 1. 测试分层

### 1.1 脚手架仓库单测

- `tests/core/template-engine.test.ts`
- 覆盖模板枚举、全模板矩阵渲染、关键文件存在、核心占位符落地、`module.consumes` 渲染与旧口径阻断。

### 1.2 模板完整性检查

- `scripts/check-templates.cjs`
- 校验 `template.json`、模板继承关系、最小文件集是否齐全。
- 真实渲染每个模板，阻断 `template.json` 泄漏、未渲染占位符、旧模块挂载口径、旧 CLI 文本和生成产物污染。
- 单元测试同时检查 README 是否包含 `.cpk`、`chipsdev-r module invoke`、`MODULE_TIMEOUT`、`MODULE_JOB_CANCELLED` 和 `module.consumes` 等正式发布口径。

### 1.3 生成工程真实 e2e

- `scripts/run-generated-e2e.cjs`
- 在临时生态工作区中通过真实 `chipsdev-r create module` 创建全部模块模板工程。
- 验证模板矩阵关键文件存在，且不会生成 `template.json`、未渲染占位符、旧模块挂载口径、旧 CLI 文本或过程性文档目录。
- 对默认模板生成工程执行根工作区 `npm install` 与生成工程 `npm run verify`，覆盖 `lint/typecheck/test/build/validate/package`。
- 断言生成工程 `manifest.entry`、质量脚本、`volta.extends`、构建产物 `dist/index.mjs` 与 `.cpk` 包命名。
- 使用 Host 正式运行时安装并启用生成 `.cpk`，覆盖 `module.listProviders`、`module.resolve`、同步 `module.invoke`、异步 job、schema 错误路径、`module.job.cancel` 取消和工作区插件记录。

### 1.4 CLI 工作区集成测试

- `Chips-SDK/tests/run-cli-create-module-workspace-tests.cjs`
- 在临时生态工作区中执行：
  - `chipsdev-r create module`
  - `chipsdev-r create module --template ...`
  - 根工作区 `npm install`
  - 生成工程 `lint/build/test/validate/package`
  - 生成包安装启用与 Host `module.invoke`
- SDK 侧测试保留为 CLI 入口兼容性与跨仓回归门禁；脚手架侧 e2e 是当前脚手架模板真实运行闭环的主门禁。

## 2. 质量门禁

第一版正式门禁如下：

1. `chips-scaffold-module` 可构建；
2. 模板矩阵渲染单测通过；
3. 模板目录与生成产物检查通过；
4. 脚手架真实 e2e 通过：模板矩阵真实 CLI 创建、默认模板生成工程 `npm run verify`、`.cpk` Host 安装启用、provider 发现解析、sync/job 调用、schema 错误与取消链路验证；
5. SDK `chipsdev-r create module` 工作区集成测试通过；
6. 模板 README、脚手架根 README、内部需求/技术文档和生态共用技术文档同步更新；
7. 相关问题工单和工作日志同步更新。

## 3. 为什么保留双层测试

- 脚手架单测用于快速定位模板引擎问题；
- 脚手架真实 e2e 用于验证真实开发者路径，不让“脚手架能渲染但 CLI 不可用”再次出现；
- SDK CLI 集成测试用于从开发者 CLI 仓位复核跨仓入口，避免 SDK、脚手架和 Host 链路漂移；
- 多层测试共同约束“模板、CLI、工作区、打包、Host 安装启用、模块调用治理”六条链路。

## 4. 后续增强方向

- 继续扩大生成工程真实 `npm run verify` 覆盖模板数量；
- 增加模板 README 与公共文档同步漂移检测；
- 必要时引入跨仓契约测试，验证模板与 Host/SDK 的模块字段长期一致。
