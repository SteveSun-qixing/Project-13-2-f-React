# 模板目录与文件组织设计

## 1. 模板矩阵

当前脚手架提供以下正式模块模板：

| 模板 ID | 形态 | 默认方法 | 默认权限 | 说明 |
|---|---|---|---|---|
| `module-standard` | 通用模块 | `run`、`runAsync` | `[]` | 同时演示 sync 与 job 基线。 |
| `module-pure-function` | 纯函数处理 | `run` | `[]` | 适合文本、配置、元数据归一。 |
| `module-file-conversion` | 文件转换 | `convert` | `file.read/file.write` | 适合输入文件到输出工件的 job 能力。 |
| `module-html-rendering` | HTML 渲染导出 | `convert` | `file.read/file.write/platform.read` | 通过 Host `platform.renderHtmlToPdf/renderHtmlToImage` 导出。 |
| `module-image-processing` | 图像处理 | `process` | `file.read` | 读取图像二进制并输出稳定分析摘要。 |
| `module-color-extraction` | 颜色提取 | `pick` | `file.read` | 输出 `backgroundColor/accentColor`。 |
| `module-orchestration` | 模块编排 | `execute` | `module.read/module.invoke` | 通过 `ctx.module.invoke/job.*` 调用下游模块。 |

除 `module-standard` 外，其他模板通过 `extends` 继承公共工程骨架，并只覆盖 manifest、README、schema、源码和测试等形态差异文件。

## 2. `module-standard` 公共骨架目录

```text
templates/module-standard/
├─ template.json
├─ .eslintrc.cjs.tpl
├─ .gitignore.tpl
├─ README.md.tpl
├─ chips.config.mjs.tpl
├─ manifest.yaml.tpl
├─ package.json.tpl
├─ tsconfig.json.tpl
├─ vitest.config.mts.tpl
├─ contracts/
│  ├─ run.input.schema.json.tpl
│  ├─ run.output.schema.json.tpl
│  ├─ runAsync.input.schema.json.tpl
│  └─ runAsync.output.schema.json.tpl
├─ src/
│  └─ index.ts.tpl
├─ tests/
│  └─ unit/
│     └─ module-definition.test.ts.tpl
```

初始化生成工程仅复制上述模板资产；`需求文档/`、`技术文档/`（或“技术手册”）与 `开发计划/` 目录不属于模块模板的默认输出范围。

## 3. Overlay 模板目录

形态模板目录示例：

```text
templates/module-file-conversion/
├─ template.json
├─ README.md.tpl
├─ manifest.yaml.tpl
├─ contracts/
│  ├─ convert.input.schema.json.tpl
│  └─ convert.output.schema.json.tpl
├─ src/
│  └─ index.ts.tpl
└─ tests/
   └─ unit/
      └─ module-definition.test.ts.tpl
```

`template.json` 中的 `extends: "module-standard"` 表示先加载公共骨架，再应用本模板覆盖。`excludeFiles` 用于移除父模板中不适合当前形态的 contract 文件，例如纯函数模板会移除 `runAsync.*.schema.json`。

## 4. 生成工程结构

标准模板生成工程结构如下：

```text
module-standard-project/
├─ .eslintrc.cjs
├─ .gitignore
├─ README.md
├─ chips.config.mjs
├─ manifest.yaml
├─ package.json
├─ tsconfig.json
├─ vitest.config.mts
├─ contracts/
│  ├─ run.input.schema.json
│  ├─ run.output.schema.json
│  ├─ runAsync.input.schema.json
│  └─ runAsync.output.schema.json
├─ src/
│  └─ index.ts
└─ tests/
   └─ unit/
      └─ module-definition.test.ts
```

形态模板会保留公共工程文件，并替换为自身的 `contracts/<method>.*.schema.json`、`src/index.ts` 和测试。

## 5. 组织原则

- 方法实现和 schema 契约必须一一对应。
- 所有公共入口统一收敛到 `src/index.ts`。
- 模板仅包含 `README`、源代码、测试、清单与 contract 等目录，不会自动创建 `需求文档/`、`技术文档/` / `开发计划/` 这类文档根目录；需要时由业务仓自行补充。
- 模板不得包含现有业务模块 ID、私有逻辑或直接依赖 Host 内部实现。
- 模板元数据 `template.json` 不进入生成工程。
- 每个模板 README 都必须包含生成工程验证、`.cpk` 打包、`chipsdev-r module invoke` Host 联调、`timeoutMs`、schema 错误、job 取消和 `module.consumes` 边界说明。
- 专用模板 README 可以省略完整目录树，但不能省略正式调用与治理边界。
