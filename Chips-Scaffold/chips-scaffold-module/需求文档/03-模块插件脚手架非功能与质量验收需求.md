# 模块插件脚手架非功能与质量验收需求

> 文档状态：已按模块插件重构实现更新

## 1. 稳定性

- 相同输入必须生成相同文件内容和目录结构。
- `chipsdev-r create module` 不能依赖隐式手工步骤。
- 生成工程必须在无界面运行时场景下可直接被 Host 加载。
- 同一模板在相同 `projectName/pluginId/moduleCapability/moduleConsumes` 输入下必须生成稳定 manifest、schema、测试与 README。
- 标准模板的异步 job 示例必须感知 Host 注入的 `ctx.job.signal` 与 `ctx.job.isCancelled()`，取消后不得继续汇报完成态或返回成功输出。
- 生成 README 中的联调命令必须能够映射到真实 `chipsdev-r module invoke` 参数，不得出现旧命令或未落地入口。

## 2. 一致性

- 文档、模板、CLI、Host、SDK 必须使用同一套模块正式口径。
- 不能同时保留 `module.mount/unmount/query/list` 与 `module.listProviders/resolve/invoke/job.*` 双口径。
- 模板 README、Manifest、schema、测试和打包结果必须一致。
- 模板矩阵必须使用同一套 `manifest.module`、`ctx.host`、`ctx.module` 与 `ctx.job` 口径。
- 模板 README 必须与 Host 已落地的 provider 解析、方法级超时、job 取消事件和 `module.consumes` 校验一致。

## 3. 可维护性

- 模板变量命名必须稳定清晰。
- 模板引擎应保持轻量，公共骨架通过继承 overlay 复用，复杂业务逻辑放在生成工程内部。
- `归档/` 中的历史模板不得再被复制到新工程。

## 4. 代码质量

- 不允许 TODO、FIXME、占位实现、空测试。
- 不允许引入未经批准的新第三方库。
- 生成工程默认代码必须能通过 TypeScript、Vitest、ESLint。

## 5. 验收标准

满足以下条件视为通过：

1. `chips-scaffold-module` 自身 `build/test/test:templates/test:e2e` 全部通过。
2. `chipsdev-r create module` 能在工作区中创建真实模块工程。
3. 生成工程能通过 `lint/typecheck/test/build/validate/package/verify`。
4. 生成模块包能被 Host 安装、启用，并通过 `module.listProviders/module.resolve/module.invoke/module.job.*` 完成 provider 发现、解析、同步调用、异步 job、schema 错误和取消验证。
5. SDK `chipsdev-r create module` 工作区集成测试仍通过，证明跨仓 CLI 入口未漂移。
6. 本仓文档已同步到新口径。
7. 模板 README 检查覆盖 `.cpk`、`chipsdev-r module invoke`、`MODULE_TIMEOUT`、`MODULE_JOB_CANCELLED` 和 `module.consumes` 等发布口径。
