# 工单099：Host单元测试直接依赖未构建源码插件入口导致全量测试失败

## 背景

执行 `task022/任务002-Host-L8原语与Modifier补齐` 时，L8 单项验证已通过：

- `cd Chips-Host && npm run build`
- `cd Chips-Host && npx vitest run tests/unit/declarative-ui.test.ts`

继续执行任务验收要求中的 `cd Chips-Host && npm test`，发现失败集中在 Host 单元测试的插件 fixture 准备链路。

## 证据

- `tests/unit/card-service-rendering.test.ts` 中 18 个用例失败，错误为 `Plugin entry not found: dist/index.mjs`。
- `tests/unit/host-application-render-protocol.test.ts` 中 2 个用例失败，错误为 `Plugin entry not found: dist`。
- Host 插件入口存在性校验是正式完整性校验，不应为了测试放宽。
- 该问题与已解决的 `工单098-Host集成测试直接安装未构建源码插件导致入口校验失败` 同类，但影响的是 Host 单元测试文件。

## 影响范围

- `Chips-Host/tests/unit/card-service-rendering.test.ts`
- `Chips-Host/tests/unit/host-application-render-protocol.test.ts`
- `Chips-Host` 全量 `npm test`
- 后续依赖卡片渲染和 managed protocol 的回归门禁

## 复现步骤

1. 进入 `Chips-Host`；
2. 执行 `npm test`；
3. 观察 `card-service-rendering.test.ts` 和 `host-application-render-protocol.test.ts` 报告插件入口不存在；
4. 核对相关测试准备逻辑，确认测试依赖的插件 manifest 指向正式 `dist` 入口，但当前工作区未保证对应构建产物存在。

## 期望行为

- Host 单元测试应使用自包含正式插件 fixture，或在测试准备阶段写入正式入口产物；
- 测试 fixture 必须保留正式 `manifest.yaml` / `entry` / `dist` 入口链路；
- Host 生产代码中的插件入口存在性校验不得放宽；
- `cd Chips-Host && npm test` 应恢复通过。

## 暂行处理

- 已按任务要求登记工单后直接进入修复；
- 修复方向是沿用工单098的自包含 fixture 思路，改造失败单测的测试准备逻辑。

## 需要协作方

- Host 测试维护方
- 插件运行时维护方
- 卡片服务与 managed render protocol 维护方

## 处理结果

- `Chips-Host/tests/unit/card-service-rendering.test.ts` 已改为在测试工作区中创建富文本与图片基础卡片插件 fixture。
- `Chips-Host/tests/unit/host-application-render-protocol.test.ts` 已改为在测试工作区中创建富文本基础卡片插件与网格布局插件 fixture。
- 所有 fixture 均保留正式 `manifest.yaml` + `entry: dist/index.mjs` + `dist/index.mjs` 入口链路。
- Host 插件入口存在性校验未放宽。
- 验证已通过：
  - `cd Chips-Host && npx vitest run tests/unit/card-service-rendering.test.ts`
  - `cd Chips-Host && npx vitest run tests/unit/host-application-render-protocol.test.ts`
  - `cd Chips-Host && npm run build`
  - `cd Chips-Host && npm test`
