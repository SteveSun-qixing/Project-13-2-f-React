# 薯片生态视觉语言设计

> 日期：2026-05-26  
> 文档性质：task023 视觉语言基准与后续开发执行规范。后续相关界面、主题 token、组件库和应用样张应以本文档与同目录静态样张为视觉依据。  
> 基准样张：`visual-language-demo.html`。该页面当前定稿效果视为本设计语言的第一版视觉原型。  
> 目标：为薯片生态中的应用、卡片、箱子、编辑器、查看器、设置面板和后续软件产品建立统一的高级视觉语言。  

## 1. 核心方向

薯片生态的视觉语言要达到 macOS / iOS 原生软件那种成熟、克制、稳定、精密的质感，但不能完全照抄 Apple 的控件、色值、布局和系统符号。

参考的是“系统级成熟度”，不是“复制一套 Apple UI”。薯片自己的识别点是：中性系统白底面、轻内容片层、微微体积感、液态玻璃般的柔和层次，以及极少量类似 Linear 气质的彩虹 / 极光环境光。

整体应适用于各种软件：设置面板、编辑器、播放器、阅读器、资源管理器、社区页面、卡片查看器和未来更多应用。它不能太艺术化，也不能太营销化；它首先必须像一个可靠的操作系统级生态界面。

## 2. 视觉关键词

1. 系统感：像原生应用一样稳定、清楚、耐用。
2. 中性白：主背景接近冷白和中性浅灰，不发黄，不复古。
3. 微体积：卡片和控件有一点厚度、内高光和软阴影，但不厚重。
4. 液态玻璃感：表面有柔和通透层次、细腻高光和轻微折射，但不做大面积透明炫技。
5. 内容片层：卡片、面板和浮层像轻薄内容片，被有秩序地放在系统空间中。
6. 极光光感：彩色是生态特色，但只作为环境光和局部材质反射出现。
7. 内容优先：视觉质感服务长期阅读、编辑、观看和管理。

## 3. 总原则

### 3.1 对标成熟度，不照抄外观

可以学习 Apple 平台的克制边界、轻阴影、系统蓝强调、圆角节奏、控件体积和转场舒适度，但薯片生态不能直接复制 macOS / iOS 的完整视觉形态。

薯片应有自己的内容片层语言。卡片是生态核心，界面应围绕“内容片层可被组织、组合、移动、编辑”来形成气质。

### 3.2 主界面保持中性

界面大面积区域应使用中性系统白、冷灰白和低彩度浅灰。不要偏黄，不要像旧纸张；也不要过度蓝灰，避免变成普通科技后台。

### 3.3 组件要有微体积

按钮、输入、卡片、标签、开关、菜单和浮层都应有轻微体积感：

1. 顶部有类似主按钮的稳定高光条；
2. 底部有类似主按钮的轻微暗边；
3. 外部有类似 macOS 窗口的多层柔和阴影；
4. 悬停时略微抬起；
5. 按下时轻轻收紧；
6. 选中时通过系统强调色和轻焦点层表达。

体积感必须轻，不能像厚重 3D 按钮。按钮、卡片、面板、菜单和 Toast 的高光、底部压暗与阴影应共用同一套光源逻辑；主按钮的质感是控件体积的基准，白色面板则使用同构的中性白版本。

### 3.4 液态玻璃感要克制

液态玻璃感可以体现在浮层、卡片和控件的表面层次中：

1. 柔和半透明感；
2. 背景轻微模糊；
3. 表面高光；
4. 边界折射感；
5. 光感随层级变化。

但不能让界面变成全透明玻璃。软件生态需要长期使用，透明和模糊必须服务层级，不做纯装饰。

### 3.5 极光光感是环境，不是边框

彩虹 / 极光光感是薯片生态的特色之一，但不能包裹一整圈组件，也不能到处出现。

它不能用简单的一条彩色线表示。更准确的表现方式应接近 Linear 式的柔和发光和液态玻璃 / 珍珠表面的光学反射：有扩散、有柔焦、有局部冷暖色散，有明亮高光核心，也有自然渐隐。它应该像材质受环境光照后自己产生的反射，而不是贴在组件边上的装饰条。

适合出现的位置：

1. 卡片选中状态背后的轻微环境光；
2. 当前焦点对象附近的局部受光区；
3. 拖拽对象抬起时的短反射；
4. 关键完成反馈的一瞬间；
5. 品牌样张中的少量材质展示。

不适合出现的位置：

1. 每个按钮；
2. 所有列表项；
3. 大面积页面背景；
4. 错误和危险状态；
5. 长时间循环动画；
6. 完整彩虹包边。

表现要求：

1. 折射区域应是柔和光斑或短光学带，不是单像素硬线；
2. 色彩边缘需要柔和渐隐；
3. 高光核心可以更亮，但面积必须小；
4. 光感只出现在受光方向或浮起对象背后；
5. 普通状态可以隐藏，悬停、选中、拖拽时增强；
6. 不应从彩色直接渐变到白色导致材质“消失”。

## 4. 材质系统

### 4.1 系统底面

系统底面是应用窗口和页面背景。它应接近操作系统原生浅色背景，干净、中性、稳定。

特征：

1. 冷白或中性浅灰；
2. 几乎无装饰；
3. 承载长期使用；
4. 让内容片层自然浮出。

### 4.2 内容片层

内容片层用于卡片、分组、资源项、设置块和信息面板。

特征：

1. 比底面更亮或更完整；
2. 有轻微边界；
3. 有内高光和软阴影；
4. 悬停时微微抬起；
5. 选中时出现系统强调色和少量折射。

内容片层应有稳定的高光条和阴影。顶部高光条表达受光面，底部暗边表达厚度，外部多层软阴影表达离开底面的距离。高光、阴影和厚度效果要和主按钮同源，只是面积更大、颜色更中性。彩色 / 极光光感只能叠加在这些体积结构之上，不能替代体积本身。

### 4.3 液态浮层

液态浮层用于菜单、Popover、Toast、Dialog 和命令面板。

特征：

1. 比普通卡片更靠近用户；
2. 有更强的背景模糊和表面高光；
3. 边界精细；
4. 阴影柔和但更深，接近 macOS 浮动窗口的多层投影；
5. 不透明度仍要足够，保证文字清晰。

### 4.4 控件片

控件片用于按钮、输入、开关、滑块、分段选择等。

特征：

1. 小体积；
2. 明确可点击；
3. 默认低存在感；
4. 悬停和按下有物理反馈；
5. 主按钮可以使用系统强调色；
6. 不使用花哨渐变抢内容；
7. 普通按钮和白色控件也要有顶部高光、底部暗边和短阴影，不允许完全扁平。

## 5. 色彩语言

主色调：

1. 系统白；
2. 冷灰白；
3. 中性浅灰；
4. 低彩度蓝灰；
5. 系统强调蓝。

状态色：

1. 成功：清爽绿色；
2. 警告：低饱和琥珀；
3. 信息：系统蓝或青蓝；
4. 危险：克制红；
5. 禁用：低对比灰。

彩虹 / 极光色只作为环境光材料，不作为大面积配色。

## 6. 层级语言

界面层级分为五层：

1. 底面层：窗口背景和画布底面；
2. 内容层：卡片、列表项、分组；
3. 操作层：工具栏、筛选器、控制条；
4. 浮层：菜单、Popover、Toast；
5. 聚焦层：Dialog、命令面板、拖拽对象、当前编辑对象。

层级通过表面亮度、模糊程度、内高光、边界清晰度和阴影深度共同表达。

## 7. 卡片语言

卡片是薯片生态的核心对象。卡片应像轻薄的内容片：

1. 默认贴近底面；
2. 悬停时微微抬起；
3. 拖拽时更接近液态玻璃片；
4. 选中时用系统强调色、轻焦点层和短虹彩折射表达；
5. 内容区域保持安静，不让材质抢走内容。

卡片不能过度圆润，不能厚重拟物，也不能完全扁平。

## 8. 动效语言

动效要像原生系统一样短、稳、可中断：

1. 悬停：轻微抬起，阴影展开；
2. 按下：轻轻压下，体积收紧；
3. 浮层出现：轻微位移和透明度变化；
4. 拖拽：对象抬起，阴影和折射增强；
5. 完成：短反馈，不循环闪烁；
6. reduced motion 下应降级为静态状态。

## 9. 应用场景

设置面板：像原生系统设置，分组清晰，控件稳定，状态明确。

编辑引擎：画布安静，卡片有生命感，拖拽和选中反馈清楚。

播放器：内容优先，控制条像轻薄液态浮层。

阅读器：阅读纸面清晰舒适，工具层低存在感。

资源管理器：列表和网格像系统文件管理，但卡片封面保留薯片内容片层特色。

社区页面：不能像营销页，仍要保持应用级界面质感。

## 10. 使用禁区

1. 完全照抄 macOS / iOS 控件；
2. 大面积透明导致文字不清；
3. 整圈彩虹包边；
4. 大面积彩虹背景；
5. 厚重 3D 拟物；
6. 过黄纸张感；
7. 过度蓝紫科技风；
8. 每个控件都发光；
9. 长时间循环炫光；
10. 页面像宣传落地页，而不是软件界面。

## 11. 验收问题

1. 是否接近原生系统软件的成熟度，而不是网页模板？
2. 是否保留薯片自己的内容片层语言？
3. 卡片和控件是否有微微体积感？
4. 液态玻璃感是否克制、清晰、可长期使用？
5. 彩虹 / 极光光感是否只是局部环境光，而非完整包边？
6. 大面积背景是否中性、不发黄？
7. 内容是否仍然是第一主角？
8. 不同类型软件是否能共同使用这套风格？

## 12. 一句话定义

薯片生态的视觉语言是：以系统级中性白为底，以轻薄内容片层承载信息，以微体积和液态玻璃层次建立高级感，并用极少量彩虹 / 极光环境光形成生态识别。

## 13. 设计基准样张

本设计语言以同目录 `visual-language-demo.html` 的当前效果为视觉基准。后续开发不应只按照文字想象风格，而应同时对照该静态样张中的按钮、卡片、面板、浮层、输入框、开关、滑块、标签和分段控制。

样张中的核心结论：

1. 主界面不是营销页，不使用大面积渐变背景，不使用装饰性英雄区。
2. 整体是冷白、中性浅灰、低对比系统界面。
3. 所有主要面板、卡片和控件都有轻微玻璃层次，但不是透明玻璃盒。
4. `button primary` 是体积感的核心参考：顶部内高光、底部内暗边、外层柔和投影共同建立厚度。
5. 卡片、面板、Toast、菜单等都应参考主按钮的阴影结构，但改为更中性、更安静的白色版本。
6. 彩虹 / 极光只作为局部折射或环境光，不作为组件完整边框，不作为页面背景。
7. 不出现卡片侧面，不做立方体、不做厚板、不做明显拟物化结构。

## 14. 光照模型

### 14.1 光源方向

默认光源来自左上方。所有高光、暗边和阴影必须服从同一个方向：

1. 顶部和左侧可以有极细、极淡的高光；
2. 底部可以有轻微内暗边；
3. 外部投影主要向下扩散；
4. 悬浮层越高，阴影范围越大，但透明度仍然克制；
5. 不允许同一个组件同时出现多方向强阴影。

### 14.2 体积感的标准结构

所有可感知为“片层”的对象都使用同一套结构：

1. 表面底色：中性白或浅灰白；
2. 边界：低透明度冷灰线；
3. 顶部内高光：`inset 0 1px 0` 类型；
4. 底部内暗边：`inset 0 -1px 0` 类型；
5. 外层柔和阴影：宽而淡；
6. 近边细阴影：小范围、低透明度，用于边界稳定。

这个结构来自主按钮，但在白色卡片上要更克制。卡片不能看起来像按钮，也不能失去主按钮那种“有厚度但很薄”的材质逻辑。

### 14.3 禁止的体积表达

禁止用以下方式表达厚度：

1. 绘制明显侧面；
2. 使用像立方体一样的斜切边；
3. 使用厚重黑色投影；
4. 使用强烈底部硬阴影；
5. 使用大面积内凹或凸起拟物；
6. 用渐变从彩色直接过渡到白色，造成材质突然消失。

## 15. 参考 Token

本节记录样张中的第一版参考值。后续进入正式主题系统时可以根据组件尺寸微调，但结构和方向不能改变。

| 角色 | 参考值 | 用途 |

| 小圆角 | `8px` | 小标签、小内部元素 |

| 胶囊圆角 | `999px` | 开关、标签、滑块轨道 |

圆角应统一、克制。不要为了“高级感”把所有卡片做成大圆角软糖形态。

## 16. 阴影规范

### 16.1 主按钮阴影

主按钮是整个系统体积感的基准。它使用蓝色表面、顶部内高光、底部内暗边和蓝色柔影：

```css
box-shadow:
  inset 0 1px 0 rgba(255, 255, 255, 0.28),
  inset 0 -1px 0 rgba(20, 54, 128, 0.24),
  0 8px 18px rgba(47, 111, 235, 0.22);
```

悬停时阴影略微展开：

```css
box-shadow:
  inset 0 1px 0 rgba(255, 255, 255, 0.3),
  inset 0 -1px 0 rgba(20, 54, 128, 0.25),
  0 10px 22px rgba(47, 111, 235, 0.24);
```

### 16.2 卡片阴影

卡片参考主按钮结构，但改成中性白版本：

```css
box-shadow:
  inset 0 1px 0 rgba(255, 255, 255, 0.54),
  inset 0 -1px 0 rgba(24, 32, 46, 0.052),
  0 8px 18px rgba(15, 23, 42, 0.06),
  0 1px 4px rgba(15, 23, 42, 0.04);
```

卡片悬停时：

```css
box-shadow:
  inset 0 1px 0 rgba(255, 255, 255, 0.6),
  inset 0 -1px 0 rgba(24, 32, 46, 0.058),
  0 10px 22px rgba(15, 23, 42, 0.072),
  0 2px 6px rgba(15, 23, 42, 0.045);
```

这类阴影应给人“轻轻浮起”的感觉，不应看起来像厚板、立方体或强拟物卡片。

### 16.3 大面板阴影

大面板比卡片更稳定，面积更大，阴影需要宽而柔：

```css
box-shadow:
  inset 0 1px 0 rgba(255, 255, 255, 0.58),
  inset 0 -1px 0 rgba(24, 32, 46, 0.06),
  0 8px 18px rgba(15, 23, 42, 0.075),
  0 1px 5px rgba(15, 23, 42, 0.045);
```

### 16.4 控件阴影

普通按钮、标签、滑块拇指、分段控制活动项使用更小的控件阴影：

```css
box-shadow:
  inset 0 1px 0 rgba(255, 255, 255, 0.5),
  inset 0 -1px 0 rgba(24, 32, 46, 0.04),
  0 2px 7px rgba(15, 23, 42, 0.05);
```

### 16.5 浮层阴影

Toast、菜单、Popover、命令面板和 Dialog 使用浮层阴影：

```css
box-shadow:
  inset 0 1px 0 rgba(255, 255, 255, 0.56),
  inset 0 -1px 0 rgba(24, 32, 46, 0.065),
  0 12px 28px rgba(15, 23, 42, 0.09),
  0 2px 8px rgba(15, 23, 42, 0.045);
```

浮层阴影可以比卡片更明显，但仍然不能发黑、发脏或像网页弹窗。

## 17. 高光与边缘

### 17.1 顶部高光

所有大面板、卡片和浮层顶部都应有极细高光。高光应贴近边缘，通常为 1px 高，左右留出一点距离，让圆角处过渡自然。

参考：

```css
position: absolute;
top: 0;
left: 10px;
right: 10px;
height: 1px;
background-color: rgba(255, 255, 255, 0.44);
```

### 17.2 左侧高光

大面板和部分卡片可以有左侧 1px 高光。它只用于建立左上受光关系，不是边框。

参考：

```css
position: absolute;
top: 10px;
bottom: 10px;
left: 0;
width: 1px;
background-color: rgba(255, 255, 255, 0.28);
```

### 17.3 边界线

边界线使用冷灰低透明度：

1. 普通面板：`rgba(32,36,44,0.095)` 左右；
2. 普通卡片：`rgba(32,36,44,0.09-0.12)`；
3. 悬停：可以增强到 `rgba(82,86,99,0.2)` 左右；
4. 主按钮：使用蓝色透明边界；
5. 焦点：使用蓝色外扩焦点层。

边界不能变成深色描边，也不能用完整彩虹描边。

## 18. 彩虹 / 极光光感规范

### 18.1 当前口径

当前第一版设计语言保留极少量彩虹 / 极光折射作为生态识别，但默认状态不大量显示。静态样张中，最明确的使用位置是主按钮顶部局部短折射。

### 18.2 允许用法

允许在以下场景使用彩虹 / 极光：

1. 主按钮顶部短高光折射；
2. 当前焦点对象的微弱边缘反射；
3. 选中卡片背后的极淡环境光；
4. 拖拽对象浮起时短暂增强；
5. 品牌样张、启动页或展示性材质样本中的克制光感。

### 18.3 禁止用法

禁止：

1. 所有组件都有彩虹；
2. 彩虹完整包裹一圈卡片或按钮；
3. 页面背景使用大面积彩虹渐变；
4. 用单像素硬线代表高级折射；
5. 彩色直接渐变到白色，导致控件厚度消失；
6. 在危险、警告、禁用状态上使用彩虹光；
7. 长时间循环流动，造成干扰。

### 18.4 表现方式

极光效果应像环境光在材质边缘产生的反射。它可以有短距离色散、柔焦和渐隐，但面积要小、透明度要低、层次要轻。

参考折射色带：

```css
linear-gradient(
  90deg,
  rgba(78, 151, 255, 0),
  rgba(78, 151, 255, 0.72),
  rgba(72, 220, 205, 0.58),
  rgba(255, 206, 92, 0.42),
  rgba(226, 92, 165, 0.52),
  rgba(126, 112, 255, 0)
)
```

这个参考值只用于短高光或局部折射，不用于大背景。

## 19. 组件规范

### 19.1 主按钮

主按钮用于页面中最重要的正向操作，例如保存、新建、确认。

要求：

1. 使用系统强调蓝；
2. 背景允许使用非常克制的竖向色阶，增强材质厚度；
3. 文字为白色；
4. 顶部有内高光；
5. 底部有内暗边；
6. 外层有蓝色柔影；
7. 可在顶部右侧出现短彩虹折射；
8. 不要从彩色渐变到白色；
9. 不要做高饱和霓虹按钮。

参考结构：

```css
background:
  linear-gradient(180deg, #4b83f2, #2f6feb),
  #2f6feb;
border-color: rgba(47, 111, 235, 0.28);
```

### 19.2 普通按钮

普通按钮用于次级操作。

要求：

1. 使用半透明白色控件表面；
2. 有 1px 冷灰边界；
3. 有顶部内高光、底部内暗边和短阴影；
4. 悬停时边界略增强、阴影略展开；
5. 按下时只轻微收紧，不需要明显位移；
6. 禁止做纯扁平文字按钮，除非在工具栏中有明确低权重需求。

### 19.3 图标按钮

图标按钮应与普通按钮同材质，只是尺寸固定。推荐 36-40px，圆角约 12-14px。

要求：

1. 图标居中；
2. 图标颜色使用主文字或次级文字；
3. 不要用大面积彩色填充；
4. 激活状态可以使用淡蓝底和控件阴影；
5. 禁止把图标按钮做成强拟物小方块。

### 19.4 卡片

卡片是生态核心内容容器。

默认卡片：

1. 表面使用窗口表面色；
2. 边界低对比；
3. 圆角 12px 左右；
4. 使用卡片阴影；
5. 顶部有 1px 高光；
6. 左侧可有很淡的 1px 高光；
7. 内容区域安静，不使用复杂纹理。

选中卡片：

1. 边界转为系统蓝透明色；
2. 可以有 2px 左右淡蓝 outline 或焦点层；
3. 阴影结构仍保留卡片内高光和内暗边；
4. 允许极淡蓝色环境光；
5. 不允许选中后变成强彩虹边框。

悬停卡片：

1. 阴影略展开；
2. 边界略清晰；
3. 不做明显上移；
4. 不改变布局尺寸。

### 19.5 面板与窗口

面板用于页面大分区、设置分组、编辑器侧栏、资源查看器等。

要求：

1. 使用窗口表面色；
2. 背景模糊比卡片略强；
3. 使用大面板阴影；
4. 顶部和左侧高光要比卡片更稳定；
5. 面板内部不要再嵌套大量“卡片里的卡片”；
6. 面板应像系统窗口的一部分，不像网页广告卡。

### 19.6 输入框

输入框是内凹控件，不使用外浮阴影。

要求：

1. 使用内凹表面；
2. 边界略明显；
3. 内侧顶部有轻微暗影；
4. 底部可有白色反光；
5. 聚焦时使用系统蓝焦点层；
6. 聚焦层柔和，不使用高饱和外发光。

### 19.7 开关

开关使用系统蓝表示开启。

要求：

1. 轨道为胶囊形；
2. 开启状态使用蓝色面；
3. 拇指为白色，有柔和阴影；
4. 开关整体可有淡蓝外投影；
5. 禁止使用彩虹轨道；
6. 禁止过度拟物的金属质感。

### 19.8 滑块

滑块由内凹轨道、强调色进度和浮起拇指组成。

要求：

1. 轨道为低对比浅灰；
2. 进度使用系统蓝；
3. 拇指使用控件表面和控件阴影；
4. 拇指不能过大；
5. 拖拽状态可以略增强阴影；
6. 不使用彩色渐变轨道。

### 19.9 分段控制

分段控制由内凹底槽和浮起活动项组成。

要求：

1. 底槽使用内凹表面；
2. 活动项使用控件表面；
3. 活动项有控件阴影；
4. 文字大小克制；
5. 不使用大面积强调色；
6. 不使用复杂边框。

### 19.10 标签

标签是轻量信息片。

要求：

1. 使用控件表面；
2. 圆角可为胶囊；
3. 边界低对比；
4. 阴影非常轻；
5. 点状状态使用单色，不使用彩虹；
6. 标签不应抢过按钮和卡片的层级。

### 19.11 Toast 与菜单

Toast、菜单和 Popover 是浮层。

要求：

1. 使用浮层阴影；
2. 背景模糊可比卡片更强；
3. 顶部有极细高光；
4. 边界比卡片略清楚；
5. 内容紧凑、清晰；
6. 激活菜单项使用淡蓝底，不使用强填充；
7. Toast 图标可以使用淡蓝小片，但不能太鲜艳。

## 20. 排版规范

### 20.1 字体

优先使用系统无衬线字体栈：

```css
Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont,
"Segoe UI", "Noto Sans SC", sans-serif
```

### 20.2 字号

推荐范围：

1. 页面主标题：20-34px；
2. 面板标题：16px 左右；
3. 卡片标题：14px 左右；
4. 正文：13-14px；
5. 辅助说明：12-13px；
6. 标签和小控件：12px。

不要在普通面板或卡片中使用过大的展示字体。生态软件需要长期使用，排版应像系统应用，而不是宣传页。

### 20.3 字重

推荐：

1. 主标题：700 左右；
2. 控件文字：620-680；
3. 正文：400-500；
4. 辅助信息：400。

### 20.4 字距

字距保持默认，不使用负字距，不使用夸张宽字距。

## 21. 布局规范

### 21.1 软件感优先

布局应优先像真实应用：

1. 工具栏清晰；
2. 内容区域直接出现；
3. 信息密度适中；
4. 常用控件可扫描；
5. 不做营销式大首屏；
6. 不用大面积装饰图形撑场面。

### 21.2 间距

参考间距：

1. 页面外边距：24-32px；
2. 面板间距：18px 左右；
3. 卡片间距：12-14px；
4. 面板内边距：16-18px；
5. 小控件间距：8px；
6. 标题和内容间距：8-14px。

间距应服务扫描和操作效率，不能为了“高级”而过度留白。

### 21.3 卡片网格

卡片网格应稳定：

1. 同一行卡片高度尽量一致；
2. 内容过长时要有合理截断或换行；
3. 悬停、选中和加载状态不能造成布局跳动；
4. 移动端可以改为单列或两列。

## 22. 交互状态

### 22.1 默认状态

默认状态应安静。用户还没有交互时，界面只显示必要的层级，不主动发光。

### 22.2 悬停状态

悬停状态：

1. 阴影略展开；
2. 边界略清楚；
3. 表面亮度可略提升；
4. 不做大幅位移；
5. 不改变组件尺寸。

### 22.3 按下状态

按下状态：

1. 视觉略收紧；
2. 阴影略减弱；
3. 不做明显下沉；
4. 不出现厚重机械按钮效果。

### 22.4 聚焦状态

聚焦状态使用系统蓝焦点层。焦点层应柔和、可见、可访问，但不应像霓虹发光。

### 22.5 禁用状态

禁用状态：

1. 降低透明度；
2. 降低文字对比；
3. 去掉彩色强调；
4. 阴影减弱；
5. 保持布局尺寸不变。

## 23. 动效规范

动效应短、轻、可中断：

1. 常规状态变化：120-180ms；
2. 浮层出现：160-220ms；
3. 拖拽抬起：120-180ms；
4. 完成反馈：不超过 800ms；
5. 禁止长时间循环光效；
6. `prefers-reduced-motion` 下应降低或关闭位移和复杂动效。

动效曲线应接近系统默认的柔和 ease，不使用弹跳、夸张回弹或游戏化曲线。

## 24. 主题落地规则

后续进入正式开发时，应把这套语言拆成主题 token，而不是在每个组件中复制 CSS。

建议 token 类型：

1. 颜色 token：背景、表面、文字、边界、状态色；
2. 材质 token：窗口表面、控件表面、内凹表面、玻璃表面；
3. 阴影 token：控件、控件悬停、卡片、卡片悬停、面板、浮层；
4. 高光 token：顶部高光、左侧高光、内暗边；
5. 圆角 token：小、常规、标准、控件、胶囊；
6. 模糊 token：卡片、面板、浮层；
7. 动效 token：时长、曲线、状态变化；
8. 焦点 token：系统蓝焦点层、选中 outline、错误焦点。

组件实现时必须引用 token，不要在业务页面里散落硬编码样式。只有样张、实验稿和一次性视觉验证文件可以直接写具体值。

## 25. 开发验收清单

每个新组件或新应用页面完成后，应按以下问题验收：

1. 是否以中性系统白和冷灰白为主，不发黄？
2. 是否看起来像软件界面，而不是营销网页？
3. 主要卡片和面板是否使用了顶部内高光、底部内暗边和柔和外阴影？
4. 卡片是否有厚度感，但没有侧面和立方体效果？
5. 主按钮是否延续当前 `button primary` 的体积结构？
6. 普通按钮、标签、分段控制活动项是否有轻微控件阴影？
7. 输入框是否是内凹逻辑，而不是浮起卡片逻辑？
8. Toast、菜单和 Popover 是否比普通卡片更浮起？
9. 彩虹 / 极光是否只作为局部折射或环境光？
10. 是否没有完整彩虹包边？
11. 是否没有大面积渐变背景？
12. 是否没有过度拟物的厚板、侧面、金属、皮革、纸张纹理？
13. 文字是否清晰、低对比但可读？
14. 不同状态是否不造成布局跳动？
15. 在小屏幕下文字和控件是否不会互相挤压或溢出？
16. reduced motion 下是否仍可使用？

## 26. 设计禁区补充

以下做法即使“看起来高级”，也不符合本设计语言：

1. 暖黄、米色、羊皮纸、复古纸张；
2. 深蓝科技后台风；
3. 紫蓝大渐变背景；
4. 大面积毛玻璃透明到看不清内容；
5. 组件外圈完整彩虹描边；
6. 卡片侧面、厚边、斜切面；
7. 强黑投影；
8. 所有卡片都悬浮得很高；
9. 每个控件都使用主按钮蓝；
10. 用装饰图形代替真实控件；
11. 过度圆润的玩具感；
12. 大面积营销式 Hero；
13. 图标和文字拥挤到失去系统感；
14. 只做平面白卡，完全没有高光和阴影；
15. 用随机光效弥补层级设计不足。

## 27. 第一版实施口径

第一版实施时，以“轻悬浮、薄玻璃、低对比、微体积”为主，不追求强烈视觉冲击。

优先级从高到低：

1. 中性系统底面；
2. 稳定内容片层；
3. 主按钮体积结构；
4. 卡片和面板的同构阴影；
5. 输入、开关、滑块、分段控制的完整状态；
6. 浮层的系统窗口感；
7. 极少量彩虹 / 极光折射；
8. 动效和细节微调。

如果某个界面为了炫光牺牲了可读性、稳定性或软件感，应优先削弱光效，而不是削弱内容。

## 28. 设置类应用结构规范

设置类应用应对标 macOS 系统设置的成熟度：左侧是稳定导航，右侧是清晰的设置内容与二级详情。重点是结构清楚、层级克制、长期可用，而不是做成卡片墙或后台表格。

### 28.1 列表与详情

设置页中的对象治理列表应采用“设置条目”结构：

1. 左侧显示对象主信息：名称、图标或身份摘要；
2. 中段显示状态摘要和少量元信息；
3. 右侧只保留几个高频动作；
4. 完整字段、低频操作、危险操作进入详情页；
5. 详情页是当前页面内的二级页面，不使用弹窗承载完整信息；
6. 详情页左上角必须提供返回按钮；
7. 列表行不应因为按钮数量、路径长度或状态标签数量变得拥挤和错位。

列表中可以有多个常用动作，但必须经过筛选。启动、启用、停用、切换、详情通常可以留在列表；卸载、显示安装路径、显示位置、重建快捷方式、移除快捷方式、完整权限或能力信息等应放入详情页。

### 28.2 详情页信息组织

详情页不能把所有字段直接平铺在一个大容器里。推荐结构：

1. 顶部摘要区：名称、简短说明、关键状态标签和常用动作；
2. 基础信息组：ID、版本、发布者、类型等短字段；
3. 运行状态组：当前、可用、启用、禁用、快捷方式状态等；
4. 安装信息组：安装路径、系统入口路径等长字段；
5. 低频操作组：卸载、移除快捷方式、重建入口等。

字段标签应小而稳定，字段值应有足够换行空间。长路径必须允许换行，不得撑破容器。

## 29. 结构容器与组件库使用边界

不是所有容器都需要使用薯片组件库外观组件。

必须优先使用组件库的对象：

1. 按钮、图标按钮、开关、输入、选择器、分段控制等可交互控件；
2. Badge、Tag、Toast、Notification、EmptyState、Loading、ErrorState 等状态和反馈组件；
3. DataGrid、NavigationSplitView、Tabs、Menu、Dialog、Popover 等有正式语义、键盘和可访问性模型的复杂组件；
4. 需要主题 contract、状态、焦点或无障碍语义的组件。

可以使用普通语义 HTML / CSS 的对象：

1. 页面级留白容器；
2. 仅用于网格、分组、对齐和空隙控制的结构层；
3. 详情页字段组、摘要骨架、内部布局容器；
4. 不承载交互、不需要组件状态、不应获得额外主题皮肤的背景结构。

结构容器应尽量干净，避免因为套用组件库外观而出现多层卡片、边框嵌套、内容贴边或主题样式叠加。组件库负责正式控件和语义模型，页面 CSS 负责必要的结构编排、信息密度和响应式。

## 30. 设置页安装入口规范

安装类页面不应同时显示一个固定“拖入安装区域”和一个安装按钮，避免用户看到两个入口却不清楚哪个是主入口。

正式交互应为：

1. 右上角保留明确的安装按钮；
2. 用户也可以把安装包直接拖入整个生态设置面板窗口；
3. 平时不展示大面积拖拽模块；
4. 拖拽文件进入窗口时，才显示轻量覆盖提示；
5. 松手后自动交给当前页面的正式安装链路；
6. 安装成功或失败都必须使用页面反馈系统提示；
7. 拖拽安装仍然必须走 Host / SDK 正式文件路径与安装接口，不允许前端自行解包或复制文件。

覆盖提示应像系统级 drop feedback：轻、短、居中或贴近内容区，不应成为常驻页面模块。

## 31. 标题与字体层级规范

标题层级要对标 Apple 平台的克制节奏：清楚、有层次，但不夸张。设置类页面尤其不能把所有标题做得很大。

推荐层级：

1. 页面标题：用于当前一级设置页，约 26-30px，字重 700 左右，行高紧凑，标题区背景必须与页面窗口背景保持一致；
2. 详情页标题：用于二级详情对象，约 21-24px，字重 680-720，不应大过一级页面太多；
3. 分组标题：用于字段组或设置组，约 13-15px，字重 650-700；
4. 列表项标题：约 13-14px，字重 650-680；
5. 正文与字段值：约 13px，行高 1.5-1.65；
6. 辅助说明与字段标签：约 11-12px，低对比但必须可读；
7. 小药丸、状态标签：约 11-12px，保持紧凑，不抢主标题。

标题之间应通过尺寸、字重、颜色和间距共同区分，不依赖过大的字号差。分组标题不应使用英雄页级别字体。详情页内部的标题和字段组必须服务扫描效率，而不是制造视觉噪音。

详情页头部应按纵向阅读节奏组织：标题独立一行，简介在下一行以辅助文字展示，状态标签和常用按钮位于简介下方。字段分组也应竖向排列，分组标题与说明放在该组字段上方，不使用“左侧分组标题列 + 右侧字段”的横向结构。

## 32. 默认主题与系统身份标识

生态默认主题、当前应用、自管理插件、系统内置项等身份信息应使用小药丸或轻量 Badge 表示。

规则：

1. 默认主题标识应放在主题名称后方，便于扫列表时即时识别；
2. 状态区继续展示“当前生效”“可切换”等运行状态；
3. 身份标识和运行状态不要混在一个地方造成含义不清；
4. 小药丸应紧凑、低对比，不应使用主按钮蓝大面积强调；
5. 小药丸文字必须走 i18n。
