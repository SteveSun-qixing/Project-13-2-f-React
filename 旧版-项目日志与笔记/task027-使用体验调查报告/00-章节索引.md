## 一句话结论

这个体验可以做成“像图片/Word 一样上传、打开、下载”的直觉模型，但底层不能真的简化成一个 HTML 文件或一个服务端页面。更稳的方式是：

- 用户本地软件继续生产正式 .card 文件；
- 社区保留一份不可丢失的原始或发布态 .card 源文件；
- 网页查看走预生成的静态 HTML 缓存 + 原版 CardViewer Web 插件宿主；
- 大资源尽量交给对象存储/CDN，弱服务器只做鉴权、元数据、排队、状态查询和私有资源代理；
- 下载时优先返回保存的原始完整 .card；如果当前只有发布处理包，也必须明确标注，不要从网页缓存反向拼装。
