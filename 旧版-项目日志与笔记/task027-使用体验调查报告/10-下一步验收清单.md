# 10-下一步验收清单

## 这份报告的验收重点

这不是代码实现验收，而是目标体验拆解后的后续检查清单。

如果要把“像 Word 文档或图片一样上传、网页查看、完整下载”真正做成，至少要能通过下面这些场景。

## 卡片文件基础验收

- 一个本地导出的 .card 可以被 Host card.readInfo 正常读取；
- .card 内没有本机绝对路径、file://、blob: 或 Host 临时 URL；
- metadata、structure、content 和 cover.html 都存在；
- 内部资源路径从卡片根目录开始；
- 归档态 .card 能被 card.unpack 解包；
- 解包后再 card.pack，仍能被读取；
- cover.html 能在正式封面链路中渲染；
- 基础卡片类型都能找到对应插件。

## 桌面发布链路验收

- 本地客户端可以从当前卡片进入“发布到社区”；
- CommunityUploader 能读取 card.readInfo；
- 能解包 .card；
- 能扫描图片、音频、视频、文本等资源；
- 能为资源申请预签名 URL；
- 资源能直传对象存储；
- content/*.yaml 和 cover.html 中的资源引用能正确改写；
- 已外置资源能从发布态 .card 中移除；
- processed.card 能重新 pack；
- submit 后社区返回 cardId；
- 上传进度文案对用户可理解；
- 失败后临时目录能清理。

## 网页上传链路验收

- 用户拖入 .card 后前端能识别文件；
- 非 .card 文件会被拒绝；
- 超过大小限制的文件有明确提示；
- 上传中能显示进度；
- 网络中断能显示失败并允许重试；
- 上传成功后进入卡片详情页；
- 服务端能检查 .card 结构；
- 缺资源、本地路径、非法资源 URL 能被拦截；
- 自包含 .card 能上传成功；
- 上传成功后源文件已保存到 chips-card-files；
- 数据库记录 sourceCardBucket、sourceCardKey、sourceCardSha256。

## 原始完整包与发布处理包验收

- 明确当前下载返回的是 original.card 还是 publish.card；
- 如果承诺“完整离线卡片”，必须保存 original.card；
- 如果只返回发布处理包，页面和 API 文档不能称为原始完整包；
- original.card 和 publish.card 的 bucket/key/hash 字段分开；
- 旧数据只有 source.card 时有迁移或降级文案；
- 删除卡片时两类 .card 都有回收策略；
- 重新发布时旧版本如何保留或覆盖有明确规则。

## 渲染缓存验收

- 上传成功后会产生 view render job；
- Worker 能下载 source.card、publish.card 或 original.card；
- Worker 能调用 Headless Host 和 CardtoHTML；
- view cache 能写入 render-cache bucket；
- cover cache 能写入 cover-cache bucket；
- 数据库 viewStatus 能从 pending 变成 cache_ready；
- /api/v1/cards/:cardId/render-status 能返回当前状态；
- /api/v1/cards/:cardId/view 在 ready 后能打开；
- render_failed 时有错误码和可读原因；
- 作者能触发重试或重建；
- 同一个 sourceCardSha256 不重复生成无意义缓存；
- 缓存路径包含版本，避免 CDN 旧内容污染。

## 网页查看验收

- 卡片详情页能调用 open-view；
- cache_ready 时能创建 com.chips.card-viewer Web 插件 session；
- CardViewer iframe 能加载 viewUrl；
- theme.css 能注入；
- bootstrap.js 能提供 window.chips；
- i18n、theme、resource 基础能力可用；
- 图片卡片能显示；
- 音乐卡片能打开音乐播放器；
- 视频卡片能打开视频播放器；
- 电子书卡片能打开阅读器；
- 移动端窄屏不溢出；
- 浏览器刷新后仍能打开；
- render_pending 时不是空白页；
- render_failed 时能返回详情或下载源文件。

## 下载完整 .card 验收

- 存在正式下载 API，例如 GET /api/v1/cards/:cardId/source-card；
- 下载前走统一权限判断；
- 公开卡片按产品策略允许匿名或登录下载；
- 私有卡片未授权用户不能下载；
- 作者禁止下载时普通用户看不到可用下载；
- 作者本人能下载自己的卡片；
- 下载返回原始完整 .card，或清楚标注为发布版 .card；
- 不返回 HTML 缓存；
- Content-Type 正确；
- Content-Disposition 文件名安全且以 .card 结尾；
- 大文件不被 API 整包读入内存；
- 支持 Range 或签名 GET URL；
- 下载次数或审计按策略记录；
- 源文件缺失时前端显示“源文件异常，无法下载”；
- 网页查看失败但源文件存在时仍可下载；
- 下载后的 .card 能被本地客户端打开和继续编辑。

## 私有卡片和权限验收

- 私有卡片详情页未授权不可见；
- 私有卡片 view cache 不进入公开 bucket；
- 私有卡片 cover cache 不公开泄漏；
- 私有卡片资源不会被永久 publicUrl 暴露；
- 分享链接策略清晰；
- 作者能切换公开/私有时，资源和缓存权限能同步；
- 下架、删除、举报状态会阻止查看和下载；
- API、对象存储和 CDN 的权限口径一致。

## 弱服务器验收

- API 不做打开页面实时渲染；
- Worker 并发可配置为 1；
- 上传大资源直传对象存储；
- source.card / original.card 支持预签名直传或至少流式处理；
- 公开 view cache 由对象存储/CDN 承载；
- 公开 cover cache 由对象存储/CDN 承载；
- 下载大 .card 走签名 URL 或流式代理；
- 队列积压时前端显示排队；
- 任务超时时不会卡死 worker；
- 多人同时访问公开卡片时 API 压力很低；
- 管理后台或日志能看到上传、渲染、下载失败原因。

## 安全验收

- .card 中 file://、blob:、本地绝对路径被拒绝；
- cover.html 和 view HTML 在 sandbox 中运行；
- 插件 iframe 权限最小化；
- 资源 URL 不允许访问服务器内网地址；
- 响应头防止文件名注入；
- 对象存储 HTML MIME 正确，不误下载；
- CORS 只开放必要来源；
- 私有资源短期 URL 不长期泄漏；
- 删除卡片后公开缓存不可继续访问；
- 上传恶意 .card 不会执行服务器端代码。

## 删除和回收验收

- 删除卡片后详情页不可访问；
- original.card / source.card 被删除或进入回收流程；
- publish.card 被删除或进入回收流程；
- view cache 被删除或失效；
- cover cache 被删除或失效；
- 外置资源按引用关系回收；
- 删除失败会重试；
- 数据库软删除和对象存储清理状态可追踪；
- CDN 缓存有失效或版本化策略。

## 用户体验验收

- 用户能在 30 秒内理解如何上传；
- 上传后立即知道“卡片已保存成功”；
- 网页查看生成中有明确状态；
- 查看、下载、分享三个动作分得清；
- 失败提示不是技术堆栈；
- 移动端能顺利打开链接；
- 未安装客户端时，下载后的编辑边界有清楚说明；
- 已安装客户端时，下载 .card 后能自然打开；
- 用户不需要理解资源外置、CDN、缓存、bucket、签名 URL。
