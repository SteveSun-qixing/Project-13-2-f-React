# 阶段2开发日志：无压缩归档读取、改写和恢复核心

> 日期：2026-08-05
> 阶段：阶段 2（实现无压缩归档读取、改写和恢复核心）
> 任务清单：P2-01 ~ P2-15

## 目标

客户端可以从完整离线卡片生成网络资源卡片，也可以从网络资源卡片恢复完整离线卡片，并满足恢复一致性。

## 完成内容

### Host ZIP Store 读取与写入（P2-01 / P2-02 / P2-07）

`Chips-Host/packages/zip-service/src/zip-store.ts`：

- `zip.list` 读取条目路径、大小、压缩大小、CRC32、偏移、是否目录、压缩方式、修改时间（P2-01 读取）；
- `compress` 始终写 Store 模式（method 0），不写压缩条目（P2-07）；
- 新增 `compress(inputDir, outputZip, { entryPlan })`：按 `entryPlan`（path + modifiedTime）恢复原始条目顺序与修改时间，未在计划内的文件按字典序追加（P2-10 核心）。
- 新增 `ZipEntryPlan` 类型并导出。
- `card.pack`、`zip.compress` Host 路由新增可选 `entryPlan` 入参并透传。

### Store 模式校验（P2-02）

模块 `publisher.ts` 的 `assertZipStoreEntries` 校验 `.card` 条目压缩方式，发现非 Store 压缩条目时抛出 `COMMUNITY_TRANSFER_CARD_NOT_STORE_ZIP`。

### 资源枚举与配置保留（P2-03 / P2-04）

- `collectResources` 枚举根目录与封面资源（`.card/cardcover/*`），排除结构性文件；
- `isStructuralCardFile` 保留 `.card/metadata.yaml`、`.card/structure.yaml`、`.card/cover.html` 与 `content/*.yaml`。

### URL 改写与恢复（P2-05 / P2-08 / P2-09）

`src/card-rewrite.ts`：

- `replaceYamlResourceUrls`：content/*.yaml 相对路径 → 对象存储 URL，富文本 file-backed 内容内联；
- `restoreYamlResourcePaths`：URL → 原始相对路径；
- `replaceCoverHtmlUrls` / `restoreCoverHtmlPaths`：封面 HTML 引用双向替换；
- `restoreDownloadedCard` 把资源字节写回原始相对路径（P2-08）。

### 可逆恢复清单（P2-06）

`createRestoreManifest` 记录 schemaVersion、原始文件名、cardId/versionId、每个资源的原始相对路径/网络 URL/对象位置/大小/MIME，以及原始 ZIP 条目顺序、压缩方式、修改时间等元数据。

### 大文件内存边界（P2-12）

- `collectResources` 改为只收集元数据（路径、大小、MIME），size 优先用 `file.stat`，不再一次性读取全部资源字节进内存；
- 上传循环逐资源读取字节并上传，峰值内存只保留单个资源。

### 一致性约束（P2-11）

- 不强制 SHA-256，ZIP 格式自身需要的 CRC32 正常保留。

### 第三方库（P2-13）

- ZIP 读写使用 Host 原生 Store ZIP 实现，未新增运行期 ZIP 依赖；
- 卡片配置 YAML 使用 `yaml@^2.8.2`，已在阶段 1 依赖评审中记录。

### 黄金回环测试（P2-14 / P2-15）

新增 `Chips-Host/tests/unit/card-transfer-gold-loop.test.ts`：

- 用真实 StoreZipService + CardPacker 构造完整离线卡片（含 content YAML、封面、资源）；
- 上传转换：解包 → URL 改写 → 删除资源 → 打包为网络资源卡片；
- 下载恢复：解包网络资源卡片 → 恢复相对路径 → 写回资源 → 按原始 entryPlan 重新打包；
- 断言：文件路径与条目顺序一致、资源字节一致、配置内容 URL 恢复、封面引用恢复、条目修改时间一致。
