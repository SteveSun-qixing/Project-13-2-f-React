# 质量缺口修复日志：富文本内联接线、移动端 target、YAML 恢复口径

> 日期：2026-08-05
> 来源：task027 质量评审反馈

## 修复内容

### 【中】富文本 file-backed 内容内联未真正接线

问题：`publisher.ts` 调用 `replaceYamlResourceUrls(..., new Map())` 传空 `textResourceMap`，`collectFileBackedRichTextResourcePaths` 从未被调用；恢复侧也没有 `content_text → content_file` 还原分支。file-backed 富文本卡片的网络资源卡片会失效。

修复：

- `src/publisher.ts`
  - 新增 `collectTextResourceMap`：扫描 `content/*.yaml`，对 file-backed 富文本配置读取 `richtext/*.md` 内容，构造 `candidatePath → markdown` 映射；
  - 新增 `collectRichTextContentFileMap`：记录 `configPath → contentFile`，用于恢复；
  - `writeRewrittenCard` 接收并透传 `textResourceMap`；
  - `createRestoreManifest` 写入 `richTextContentFiles`；
  - `extractRichTextContentFileMap` + `restoreDownloadedCard` 在下载恢复时依据恢复清单还原 file-backed 配置。
- `src/card-rewrite.ts`
  - `restoreInValue` 新增 `content_source: inline` + `content_text` → `content_source: file` + `content_file` 还原分支；
  - `restoreYamlResourcePaths` 增加 `sourceFilePath` 与 `richTextContentFileMap` 参数。
- 测试：
  - 新增 `tests/unit/card-rewrite.test.ts`（6 条）：候选路径收集、内联重写、恢复还原、无映射保持 inline、普通资源字段 round trip；
  - `module-definition.test.ts` 新增上传链路端到端富文本内联测试（共 7 条）。

### 【低】CardViewer manifest mobile: supported 与 P8-15 不一致

问题：`Chips-CardViewer/manifest.yaml` 声明 `preferredKinds.mobile: fullscreen` 且传输模块声明 `mobile: true`，但 `runtime.targets.mobile.supported: false`，与 P8-15“Mobile 客户端可以上传、查看、下载”不一致。

修复：`Chips-CardViewer/manifest.yaml` 的 `mobile.supported` 改为 `true`，与设计方向（P1-03 / P6-14 / P8-15）及传输模块口径一致。`chipsdev validate` 通过。

### 【低】YAML 重排与恢复口径

问题：YAML 经 `parse → stringify` 会丢失注释与原始格式；“配置内容不能改变”仅做到“尽可能”；黄金回环测试用手写字符串而非模块自身逻辑。

处理：

- 生态共用卡片格式规范 1A.4 补充明确口径：YAML 解析→改写→序列化允许格式化归一（注释、空行、键序、引号风格可能变化），但不得改变字段语义与资源路径；验收以字段语义与资源引用一致为准，不以配置文本逐字节相同为准；
- `card-rewrite.test.ts` 新增 round trip 保真测试：改写后 `source: url` + CDN URL，恢复后 `source: file` + 原始相对路径；
- Host 黄金回环测试保持 Host 层 ZIP 完整性验证职责，URL↔路径逻辑由模块 `card-rewrite.test.ts` 覆盖（符合分层边界，不跨仓直接 import）。
