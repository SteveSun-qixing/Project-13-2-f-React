# 阶段7开发日志：移除旧链路和旧假设

> 日期：2026-08-05
> 阶段：阶段 7（移除旧链路和旧假设）
> 任务清单：P7-01 ~ P7-10

## 目标

把所有和最新决策冲突的旧设计清掉，文档、manifest、API、前端页面和测试中不再出现浏览器上传/下载和内部空壳产物口径。

## 完成内容

### 浏览器上传移除（P7-01 / P7-02）

- Web 工作区页改为“客户端发布”信息页，无 dropzone、无文件选择、无上传队列；
- 删除的 `UploadDropzone.tsx`、`UploadQueue.tsx`、`UploadQueueItem.tsx` 已归档到 `packages/web/归档/20260805-浏览器上传组件归档/`；
- Web `src/api` 无任何卡片上传调用（仅剩头像/房间封面上传）。

### 浏览器下载 / ZIP 打包 / 保存 sink 移除（P7-03）

- Web 无浏览器端 `.card` 打包器、下载计划调用或保存 sink；
- 社区卡片详情页只加载查看缓存，并提供“请在薯片客户端中打开并下载”提示（阶段 5 完成）。

### 旧术语与旧方案移除（P7-04 / P7-05 / P7-06 / P7-07）

- 卡片格式规范明确“空壳卡片/半空壳卡片”旧术语不再使用，正式名称为网络资源卡片（阶段 0）；
- 无“空壳保留相对路径 + 数据库运行时映射资源”方案代码；
- 无“下载时浏览器恢复完整卡片”方案代码（下载恢复全部在客户端模块）；
- 卡片文件本身不实现权限字段，只保留社区身份系统登录/归属外层控制（阶段 3）。

### 保留正确方向（P7-08）

- 对象存储目录态：`cards/{cardId}/versions/{versionId}/resources`、`network-card/`（阶段 3）；
- 弱服务器控制面：API 只做鉴权、会话、签名、元数据、恢复清单、状态和任务调度；
- Worker 缓存生成：`CardRenderCacheService` + `worker.ts` 仍负责 view/cover 缓存生成。

### manifest 描述更新（P7-09 / P7-10）

- `Chips-CommunityUploader-Plugin/manifest.yaml` 描述为“上传、网络资源卡片生成、远程打开和完整卡片下载恢复的官方社区卡片传输模块”；
- `Chips-CardViewer/manifest.yaml` 描述 Web target 只查看、Desktop/Mobile 客户端 target 可下载。
