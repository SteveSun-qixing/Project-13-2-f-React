# 阶段3开发日志：改造社区 API 为控制面

> 日期：2026-08-05
> 阶段：阶段 3（改造社区 API 为控制面）
> 任务清单：P3-01 ~ P3-12

## 目标

社区服务器不接收大文件字节，只签发对象地址、保存数据库信息和调度缓存生成。

## 完成内容

### 上传会话（P3-01 / P3-02 / P3-03）

`Chips-CommunityPlatformServer/packages/server/src/routes/card-transfer.ts`：

- `POST /api/v1/card-transfer/upload-sessions`：客户端模块创建上传会话，返回 uploadId、cardId、versionId、resourcePrefix 和 networkCard 对象位置；服务器只保存元数据（P3-01）。
- `POST .../objects:presign`：为资源文件和网络资源卡片签发对象存储 PUT 地址，对象键固定在会话对象布局下（P3-02）。
- `POST .../complete`：JSON 提交网络资源卡片对象位置、资源对象位置、资源清单和可逆恢复清单（P3-03）。

### 校验（P3-04 / P3-05 / P3-06）

- 新增 `assertRestoreManifestStructure`：校验恢复清单 schemaVersion 必填、zipEntries/resources 为数组（P3-04）。
- complete 校验网络资源卡片对象键与会话元数据一致、每个资源对象键必须在会话 resourcePrefix 下、对象大小通过 `headObject` 校验（P3-04）。
- `requireJsonBody` preHandler + Fastify 内容类型解析：`card-transfer` 全部 POST 路由只接受 `application/json`，`multipart .card` 与 octet-stream 卡字节被 415 拒绝（P3-05 / P3-12）。
- API 不代理资源、网络资源卡片、查看缓存或下载文件字节，全部走对象存储 URL（P3-06）。

### 版本状态与缓存调度（P3-07）

- complete 后写 cards 表 sourceCard* 字段与 resourceManifest，状态置 `ready`；
- 通过 `CardRenderCacheService.enqueueForCard` 调度 view/cover 渲染缓存生成。

### 下载会话（P3-08 / P3-09）

- `POST /api/v1/card-transfer/download-sessions` 只面向客户端模块；
- `GET .../plan` 返回网络资源卡片对象位置、资源对象位置和恢复清单，均为对象存储 URL + 预签名 GET 地址，不返回文件字节。

### 权限边界（P3-10）

- 卡片文件本身不处理公开/私有/权限字段；接口只保留社区系统登录（JWT）和内容归属所需的外层控制。

### 旧接口清理（P3-11）

- 旧 `/api/v1/upload-sessions`、`/api/v1/upload-sessions/:id/resources/presign`、`/api/v1/upload-sessions/:id/card`、`/api/v1/upload/card` 已移除，`upload.test.ts` 验证返回 404；
- `/api/v1/upload/box` 只保留箱子上传 multipart，卡片文件被 `FILE_TYPE_INVALID` 拒绝。

### API 集成测试（P3-12）

- `card-transfer.test.ts` 新增：二进制卡字节（octet-stream）提交 upload-sessions / complete / presign 均返回 415，证明 API 进程不经过文件字节；
- 新增：非法恢复清单结构、越权资源对象键均返回 400。
