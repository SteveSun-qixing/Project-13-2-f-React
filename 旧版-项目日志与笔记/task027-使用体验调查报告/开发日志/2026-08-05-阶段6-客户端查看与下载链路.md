# 阶段6开发日志：客户端查看和下载链路

> 日期：2026-08-05
> 阶段：阶段 6（客户端查看和下载链路）
> 任务清单：P6-01 ~ P6-14

## 目标

用户必须在客户端中下载保存完整卡片。

## 完成内容

### CardViewer 客户端接入统一卡片传输模块（P6-01 / P6-02 / P6-03）

`Chips-CardViewer`：

- manifest 增加 `module.invoke`、`network.request`、`platform.external` 权限；
- `AppRuntimeProvider` 新增 `downloadActiveCard()` 与 `canDownloadActiveCard`：
  - 仅当打开目标为社区卡片（community-card）、launch params 携带 `communityServer`（baseUrl + accessToken）且不是 Web 文档型 surface 时可用；
  - 通过 `client.platform.saveFile` 选择输出路径，然后调用 `client.communityCardTransfer.download`；
  - 成功/失败通过 `client.platform.showMessage` 反馈。
- `AppShell` 在沉浸式浮动动作栏与外部 chrome 动作列表中加入“下载卡片”动作（`download-card`）；
- i18n 新增 `card-viewer.actions.downloadCard/downloadingCard/downloadComplete/downloadFailed/downloadUnavailable`（zh-CN / en-US）。

### 下载主流程（P6-04 ~ P6-10）

`Chips-CommunityUploader-Plugin/src/publisher.ts` 的 `downloadCommunityCard`：

- P6-04 `createDownloadSession` 创建 download session；
- P6-05 `getDownloadPlan` 获取网络资源卡片、资源清单和恢复清单；
- P6-06 逐个资源 `downloadBinary` 下载到内存后写盘；
- P6-07 `restoreDownloadedCard` 把配置和封面中的 URL 恢复为原始相对路径；
- P6-08 资源字节写回原始相对路径；
- P6-09 通过 Host `card.pack` 按 ZIP Store 模式重新打包；
- P6-10 `extractEntryPlan` 从恢复清单提取原始 ZIP 条目顺序与修改时间并传给 `card.pack`。

### 下载健壮性（P6-11 / P6-12）

- 取消：任务信号中断；
- 重试 / 断网：`fetchWithRetry` 指数退避；
- 磁盘空间错误与下载失败：catch 中删除输出路径，不留下看似成功的 .card。

### 下载后验证（P6-13）

`verifyRestoredCard` 在打包完成后依次调用 Host `card.readInfo`、`card.render`、`card.open` 验证下载结果；任一步失败抛出 `COMMUNITY_TRANSFER_DOWNLOAD_VERIFY_FAILED` 并清理输出。

### 移动端（P6-14）

- manifest `runtime.targets.mobile.supported: true`；
- 模块文件读写与保存走 Host `file.*` / PAL 能力，浏览器不承担移动下载。
