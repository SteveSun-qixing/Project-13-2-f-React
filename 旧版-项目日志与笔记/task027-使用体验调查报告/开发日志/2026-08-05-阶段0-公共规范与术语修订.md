# 阶段0开发日志：公共规范与术语修订

## 目标

先把“浏览器只查看、客户端上传下载、网络资源卡片是正式卡片类型”写入公共规范，为后续所有阶段提供统一术语和契约基础。

## 完成内容

### 卡片文件格式规范（`生态共用技术文档/文件格式规范/01-卡片文件格式规范.md`）

- 升级文档版本至 1.1.0，更新时间 2026-08-05。
- 1.1 节：明确 `.card` 使用 ZIP Store 模式，补充传输链路正式 MIME `application/vnd.chips.card+zip`。
- 1.2 节：补充 Store 模式是完整恢复一致性前提的说明；明确客户端在发布/下载前必须校验条目压缩方式，发现压缩条目应转换或提示不符合格式要求。
- 新增 1.4 卡片类型：定义完整离线卡片与网络资源卡片两种正式形态，并给出类型对比表。
- 新增 1A 节：完整离线卡片与网络资源卡片
  - 1A.1 完整离线卡片：资源字节在 ZIP 内、配置使用相对路径、可离线查看编辑。
  - 1A.2 网络资源卡片：保留配置与封面、资源字段为对象存储/CDN URL、ZIP 内不保存资源字节，是正式 .card 类型而非“空壳”。
  - 1A.3 上传与下载的可逆转换：定义恢复清单必须记录的字段。
  - 1A.4 完整恢复验收标准：路径、配置、资源字节、条目顺序、条目时间、Store 模式、封面一致。
  - 1A.5 网络资源卡片校验规则：URL 资源字段允许、本地资源文件可缺失、URL 必须来自正式上传结果。
- 7.1/7.2 节：重写资源组织模式为“完整离线卡片（相对路径+内置资源）”和“网络资源卡片（URL+外部资源）”双模式；移除“空壳卡片/半空壳卡片不属于默认保存链路”的旧口径。
- 12.2 节：移除人为文件大小上限建议，改为真实平台、对象存储、磁盘和防攻击策略约束。
- 附录 B 检查清单：补充网络资源卡片约束、可逆恢复清单、不设人为上限等检查项。

### 社区平台 API 契约（`生态共用技术文档/协议与契约/09-社区平台API契约.md`）

- 5.4 节：上传接口清单更新为 `card-transfer` 控制面接口，明确旧 `/upload-sessions`、`/upload/card` 已移除，浏览器卡片上传接口不存在。
- 7.0 节：新增架构边界，明确浏览器只查看、客户端统一传输模块负责上传/下载/客户端查看、服务器只做控制面不代理文件字节。
- 7.1 节：重写卡片上传会话为客户端 → 控制面 → 对象存储链路，新增 upload-sessions / objects:presign / complete / abort 接口契约。
- 7.2 节：新增卡片下载会话与下载计划接口契约（download-sessions / plan）。
- 8 节：从“不在范围”中移除社区内 `.card` 回下载，明确由客户端传输模块承担；补充卡片文件不实现权限管理。

### 薯片协议规范（`生态共用技术文档/协议与接口标准/01-薯片协议规范.md`）

- 新增“社区卡片传输边界”小节：
  - 能力边界：浏览器只查看、客户端统一模块负责上传/下载/客户端查看。
  - 模块能力名：upload / openRemote / download / getStatus / cancel。
  - 文件字节链路：上传与下载的完整流程。
  - 术语：完整离线卡片、网络资源卡片、可逆恢复清单。

### CardViewer manifest（`Chips-CardViewer/manifest.yaml`）

- 更新 description：Web target 只负责查看，不提供上传和下载 .card；Desktop/Mobile 客户端 target 可接入统一卡片传输模块，支持打开社区卡片和下载完整卡片。
