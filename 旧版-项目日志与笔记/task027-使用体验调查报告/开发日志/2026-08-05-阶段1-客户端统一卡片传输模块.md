# 阶段1开发日志：建设客户端统一卡片传输模块

> 日期：2026-08-05
> 阶段：阶段 1（建设客户端统一卡片传输模块）
> 任务清单：P1-01 ~ P1-10

## 目标

所有客户端应用插件都接入同一个模块，不再各自处理上传、下载、查看。

## 完成内容

### 模块能力与契约（P1-01）

`Chips-ModulePlugin/Chips-CommunityUploader-Plugin` 提供正式能力 `community.card.transfer`：

- `manifest.yaml`：能力名、运行目标、权限、输入输出 schema 引用。
- 方法：`upload` / `download` / `openRemote`；`getStatus` / `cancel` 由 Host `module.job.*` 承载。
- 输入输出 schema：`contracts/upload|download|openRemote.input|output.schema.json`。
- 错误码统一通过 `createCommunityUploaderError(code, message, details, retryable)` 生成。

### 运行边界（P1-02 / P1-03 / P1-04）

- Desktop Host：支持上传、下载、远程打开。
- Mobile Host/PAL：按同一能力契约支持。
- Web 浏览器：不支持，浏览器不加载该模块。
- Headless：支持，用于自动化与测试链路。

### SDK 类型化封装（P1-05）

`Chips-SDK/src/api/community-card-transfer.ts` 提供 `client.communityCardTransfer.upload/download/openRemote/getStatus/cancel`，只做类型化封装和调用入口，不承载上传下载主实现。

### 应用插件统一接入（P1-06）

CardViewer、EditingEngine 等应用插件通过 SDK 统一模块入口调用发布、打开社区卡片和下载，不各自实现社区文件链路。模块内 `src/publisher.ts` 是唯一正式文件链路实现。

### 重试、取消、断网恢复、签名刷新、错误状态（P1-07）

在 `src/publisher.ts` 新增 `fetchWithRetry` / `fetchControlPlane`：

- 控制面请求和对象存储 PUT/GET 使用指数退避重试（最多 3 次）；
- 5xx / 408 / 429 视为瞬时失败自动重试；
- 401 / 403 立即抛出 `COMMUNITY_TRANSFER_AUTH_EXPIRED`，由调用方刷新签名后重新发起；
- 每次重试前检查任务 `AbortSignal`，取消时抛出 `COMMUNITY_TRANSFER_CANCELLED`；
- 网络失败统一抛出 `COMMUNITY_TRANSFER_NETWORK_FAILED`（可重试）。

新增单元测试：瞬时 503 重试三次成功；401 抛出 auth-expired 非重试错误。

### URL 改写与下载恢复统一处理（P1-08）

`src/card-rewrite.ts` 统一处理：

- `replaceYamlResourceUrls` / `restoreYamlResourcePaths`：content/*.yaml 资源字段相对路径 ↔ URL；
- `replaceCoverHtmlUrls` / `restoreCoverHtmlPaths`：.card/cover.html 封面引用；
- 富文本 file-backed 内容内联：上传时 `collectFileBackedRichTextResourcePaths` + `collectTextResourceMap` 读取 `richtext/*.md` 内容，把 `content_source: file` + `content_file` 内联为 `content_source: inline` + `content_text`；下载恢复时依据恢复清单 `richTextContentFiles` 映射还原为 file-backed 并写回 markdown 资源；
- 插件禁止自行替换 YAML 或 HTML。

### UI 文案与主题（P1-09）

本模块是无 UI 的 worker 模块（`runtime: worker`、`activation: onDemand`），不承载界面，因此不产生 UI 文案或主题依赖；客户端中由它驱动的界面均走各自多语言与主题系统。

### 第三方库依赖评审（P1-10）

新增 `技术文档/01-社区卡片传输模块技术方案.md`，建立依赖评审记录：运行期唯一第三方依赖 `yaml@^2.8.2`（MIT、活跃维护、包体极小、纯 JS 跨端），用于卡片配置 YAML 解析与写出；对象存储签名、ZIP Store 读写、任务调度均走 Host 正式能力。
