# 薯片卡片全链路体验调查报告（简化版）

调查日期：2026-08-03 ｜ 范围：本机编辑 → 保存 .card → 上传社区 → 网页查看 → 网页下载

## 一句话结论

**"上传→网页查看"已经通了，但"下载"完全没有，"编辑器内一键发布"也没接，"大资源过弱服务器"是最大隐患。**

---

## 1. 当前链路现状

```
本机编辑(EditingEngine) → 导出 .card(ZIP, 资源全内嵌) → 拖到网页上传
→ 服务器存源文件+元数据 → Worker 用整套 Host 渲染成静态HTML → 传对象存储
→ 网页 iframe 加载静态缓存 / 封面
```

要点：
- .card 就是一个 ZIP，资源（图片/视频/音频）**全内嵌**在包里。
- 网页上传一次 multipart 传整个文件（上限 500MB），不走"资源直传"。
- 服务器端渲染 = 服务器上装了完整 Chips Host + 全部插件，把卡片渲染成 index.html + 每张基础卡一个 html + assets/content/ 资源树。
- 缓存命中即 302 到 CDN/对象存储静态入口，**查看的静态流量不经过 Node**；缓存 30 天访问续期，过期按需重渲染。

## 2. 网页渲染机制（为什么是服务器渲染）

- **服务器渲染好静态 HTML，浏览器只负责 iframe 显示，不解析卡片**。
- 好处：网页和本地用同一套 Host 渲染器 → 看到的内容一致；渲染一次、缓存多次 → 弱服务器只被第一次拖累；纯静态 HTML 不依赖生态运行时，能"像图片一样"看。
- 网页查看实际是三层 iframe：社区网页 → 服务端托管的 CardViewer 插件会话 → 卡片静态缓存。观感无感知。

## 3. 资源文件怎么处理

- 本机：资源复制进卡片根目录（全内嵌）。
- 上传：网页不拆资源，整个 .card 过服务器；**预签名"资源直传对象存储"的链路服务端已写好，但没被任何前端使用**。
- 存储：源 .card 存 `chips-card-files`（私有，永久）；渲染时资源被**复制一份**进渲染缓存 `chips-card-render-cache`（公开，CDN 直连）。
- 问题：一份资源存两遍（源文件+缓存），500MB 卡渲染时服务器要再搬 500MB。

## 4. 下载回导（最大缺口）

- **现状：完全没有下载能力**。无下载接口、无下载按钮；源 .card 一直存在对象存储里但没有读取路由。
- 好消息：因为资源全内嵌，源 .card 就是完整卡片，**下载不需要"重新整合"**，把源文件吐出来即可。
- 补齐成本不高：新增一个鉴权下载接口 + 前端加个下载按钮 + 把 `downloadable` 语义入库。数据层早就具备。

## 5. 弱服务器怎么扛

现状是**友好的**：重活只在渲染一次，静态流量走 CDN，Node 热路径只做鉴权+302。真正的压力点：

| 压力点 | 问题 | 建议方向 |
|---|---|---|
| 🔴 大资源过 Node | 500MB 整包上传→解包→重传 | 接上现成的预签名直传，大资源客户端直传对象存储 |
| 🔴 存储翻倍 | 资源在源文件和渲染缓存各一份 | 渲染时评估复用源资源，而非重复复制 |
| 🟡 私有卡流量过 Node | 私有卡静态缓存走 API 代理 | 短时签名 URL 直连对象存储 |
| 🟡 每次查看写库续期 | 热门卡写放大 | Redis 合并写 + 后台 flush |
| 🟡 渲染队列无限速 | 并发=1，过期卡集中被访问会积压 | 优先级排序消费 + 用户触发的 miss 优先 |

## 6. 体验断点（对照"像发微博一样简单"）

| # | 断点 | 程度 |
|---|---|---|
| ① | 保存 ≠ 得到 .card，用户要多一步"导出" | 中 |
| ② | **编辑器内没有"发布到社区"入口**，要手动导出+开网页+拖拽 | 高 |
| ③ | 上传后要等服务器渲染（"准备中"轮询） | 低-中 |
| ④ | **网页无下载按钮/接口** | 高 |
| ⑤ | 无二次创作闭环（下载→本地改→重新上传） | 中-高 |
| ⑥ | 手机可查看可上传，编辑需安装软件（与目标一致） | 低 |

## 7. 优先建议

**第一优先**（目标体验成立 + 弱服务器续命）：
1. 网页下载接口 + 按钮
2. 接上预签名资源直传
3. 编辑器内一键发布衔接

**第二优先**：
4. 权限补齐（downloadable 入库、可见性 UI）
5. 渲染缓存资源复用决策
6. remix 闭环

**第三优先**：touch 合并写、队列限速、插件版本进缓存键、文档收敛。
