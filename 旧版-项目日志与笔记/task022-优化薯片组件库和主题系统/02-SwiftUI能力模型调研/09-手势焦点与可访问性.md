# SwiftUI 调研：手势 / 焦点 / 可访问性

## 1. 这一层解决什么问题

高质量 UI 不只是能点击。它需要鼠标、触控、键盘、焦点、屏幕阅读器、辅助输入都保持一致。SwiftUI 把手势、焦点和可访问性作为框架能力，而不是让每个控件临时补。

## 2. 手势系统

SwiftUI 支持：

- 点击。
- 长按。
- 连续变化手势。
- 空间事件。
- 手势组合。
- 自定义手势。
- 手势状态。
- 激活事件。

这些能力让交互不仅可以绑定到按钮，还可以绑定到任意视图结构上。

## 3. 焦点系统

SwiftUI 通过 `FocusState`、`FocusedValue` 等能力处理焦点状态。焦点不仅服务输入框，也服务键盘导航、命令启用状态和辅助功能。

## 4. 可访问性系统

SwiftUI 的可访问性覆盖：

- 创建可访问元素。
- 标识元素。
- 隐藏装饰元素。
- 组合或拆分子元素语义。
- 为控件提供 label、value、hint。
- 支持不同辅助类型。

## 5. 设计价值

### 5.1 交互输入统一

点击、键盘、手势和辅助输入都应最终驱动同一组件状态，而不是形成多套逻辑。

### 5.2 焦点是系统状态

弹窗、菜单、选择器、表格、树、命令面板如果没有焦点系统，很容易出现键盘不可达、关闭后焦点丢失、屏幕阅读器语义混乱。

### 5.3 a11y 是组件契约的一部分

可访问性不能等视觉完成后再补。它必须是组件设计、contract 和测试矩阵的一部分。

## 6. 对薯片的直接启发

薯片需要：

- 统一 pointer/keyboard/gesture 状态模型。
- `ChipsFocusScope`、`useChipsFocusState`、焦点恢复策略。
- Dialog/Menu/Select/CommandPalette 的 focus trap、roving focus、Escape 关闭、关闭后焦点恢复。
- Tree/DataGrid/List 的 keyboard navigation 和 ARIA 行列/层级语义。
- 每个组件 contract 声明 role、aria、keyboard、focus、screen reader 语义。
- 主题系统强制焦点环、对比度、disabled/invalid/selected 状态可见。
