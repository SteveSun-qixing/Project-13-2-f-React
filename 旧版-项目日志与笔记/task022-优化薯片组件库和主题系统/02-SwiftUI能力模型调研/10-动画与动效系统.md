# SwiftUI 调研：动画与动效系统

## 1. 这一层解决什么问题

SwiftUI 把动画和过渡纳入状态变化模型。开发者不需要手动管理大量 DOM/class/timer，而是声明状态变化如何过渡，系统负责执行。

## 2. 核心能力

| 能力 | 作用 |
|---|---|
| `Animation` | 描述视图随时间变化的方式 |
| `Transition` | 描述视图插入和移除时的变化 |
| `Canvas` | 即时绘制 |
| `Shape` | 2D 图形 |
| `Color` | 可随上下文变化的颜色表示 |
| `Material` | 背景材质 |
| `VisualEffect` | 不改变祖先或后代结构的视觉效果 |
| `PhaseAnimator` | 在多个阶段间自动切换动画 |
| `KeyframeAnimator` | 关键帧动画 |

## 3. 设计价值

### 3.1 动画和状态绑定

动画不是独立装饰，而是状态变化的表现。这样更容易保持界面一致，也更容易关闭或降级动画。

### 3.2 过渡是结构变化的一部分

弹层打开、列表插入、展开折叠、页面切换都需要统一过渡策略，否则应用体验会碎片化。

### 3.3 动效需要安全和性能边界

动画过多会造成性能和可访问性问题。成熟框架必须支持减少动态效果、性能预算和动效安全规则。

## 4. 对薯片的直接启发

薯片已有 `motion` token 方向，但需要升级为框架能力：

- `ChipsMotionProvider`
- `ChipsTransition`
- `ChipsPresence`
- 弹层、菜单、tooltip、accordion、navigation 的统一过渡。
- 主题包定义 motion token，组件只消费语义 token。
- 支持 reduced motion。
- 主题切换、列表重排、拖拽、骨架屏、进度反馈有统一策略。
- 动效时长、曲线、延迟、循环次数进入主题门禁。
