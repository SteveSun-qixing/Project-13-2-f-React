# SwiftUI 调研：导航 / 菜单 / 工具栏

## 1. 这一层解决什么问题

SwiftUI 把页面移动、分栏导航、标签切换、弹层呈现、菜单、命令和工具栏都纳入统一 UI 框架。开发者不需要每个应用单独设计导航栈、快捷键、菜单栏和工具栏状态。

## 2. 导航能力

| 能力 | 作用 |
|---|---|
| `NavigationStack` | 根视图上方压入更多视图的堆栈导航 |
| `NavigationSplitView` | 两列或三列分栏导航 |
| `NavigationLink` | 声明式导航触发 |
| `TabView` | 使用交互元素切换多个子视图 |
| navigation title/bar/sidebar | 标题、导航栏、边栏配置 |

## 3. 呈现能力

SwiftUI 还通过 modifier 处理常见呈现：

- sheet
- popover
- alert
- confirmation dialog

这些能力背后是统一呈现协调，而不是页面随意挂弹层。

## 4. 菜单与工具栏能力

| 能力 | 作用 |
|---|---|
| `Menu` | 动作菜单 |
| `ContextMenu` | 上下文菜单 |
| `Commands` | 应用级命令集合 |
| `CommandMenu` | 顶层命令菜单 |
| `CommandGroup` | 向已有命令区域插入命令 |
| `ToolbarItem` | 工具栏项 |
| `ToolbarItemGroup` | 工具栏项分组 |

## 5. 设计价值

导航、菜单、工具栏和快捷键本质上都依赖同一套命令语义：命令 id、标题、图标、快捷键、启用状态、权限、处理函数和所在位置。

SwiftUI 把这些系统能力放在框架里，避免每个应用出现完全不同的交互模型。

## 6. 对薯片的直接启发

薯片需要：

- `ChipsNavigationStack`
- `ChipsNavigationSplitView`
- `ChipsNavigationLink`
- `ChipsTabs` 页面导航增强
- `ChipsPresentationProvider`
- `ChipsSheet`
- `ChipsAlert`
- `ChipsConfirmationDialog`
- `ChipsCommandRegistry`
- `ChipsCommandMenu`
- `ChipsContextMenu`
- `ChipsToolbar`
- `ChipsToolbarItem`
- `ChipsShortcut`

其中命令系统应该成为菜单栏、右键菜单、工具栏、快捷键和命令面板的同一事实来源。
