# SwiftUI 调研：App / Scene / Window / Document 应用结构

## 1. 这一层解决什么问题

SwiftUI 把应用结构本身纳入声明式模型。开发者不是先手写窗口管理、菜单注册、文档打开、设置页路由，再把页面塞进去；而是通过 `App` 和 `Scene` 描述应用由哪些场景组成，由系统负责生命周期和平台行为。

这一层是 SwiftUI 简化开发的第一层原因：应用不是一堆页面文件，而是有清晰入口、有场景、有窗口、有文档、有设置、有命令的结构体。

## 2. 核心能力

| 能力 | 作用 |
|---|---|
| `App` | 描述应用结构和行为，是 SwiftUI 应用入口 |
| `Scene` | 描述由系统管理生命周期的界面分组 |
| `WindowGroup` | 声明一组结构相同的窗口 |
| `DocumentGroup` | 把文档打开、创建、保存纳入声明式场景 |
| `Settings` | 声明应用设置界面 |
| `MenuBarExtra` | 声明系统菜单栏常驻入口 |
| `ScenePhase` | 观察场景活跃、非活跃、后台等状态 |
| `Commands` | 声明应用级菜单命令与快捷键 |

## 3. 设计价值

### 3.1 应用结构和系统生命周期绑定

`Scene` 的关键不是“多一个容器组件”，而是把 UI 分组交给系统管理生命周期。窗口打开、关闭、激活、后台、恢复都不由业务页面散落处理。

### 3.2 文档应用成为框架能力

`DocumentGroup` 对文档型应用尤其关键。它把打开、创建、保存、文档窗口等能力放进统一模型，让文档应用不用重新搭建一套文件生命周期。

### 3.3 设置、菜单、命令不是业务临时拼接

SwiftUI 把设置窗口、菜单栏、命令组、快捷键都纳入应用结构，保证不同应用在平台行为上统一。

## 4. 对薯片的直接启发

薯片也需要一套 App Framework：

- `ChipsApp`：应用声明入口，绑定 manifest、权限、主题、多语言、运行时上下文。
- `ChipsScene`：统一描述页面场景、窗口场景、卡片场景、箱子场景、设置场景。
- `ChipsWindowGroup`：声明一组同结构应用窗口，由 Host/Electron 管理。
- `ChipsDocumentScene`：声明 `.card/.box/资源文件` 的打开、创建、保存和窗口生命周期。
- `ChipsSettingsScene`：统一设置页入口，绑定配置服务和 i18n。
- `ChipsScenePhase` / `useScenePhase`：观察窗口和插件场景状态。
- `ChipsCommands`：把菜单、工具栏、快捷键、命令面板接入同一命令系统。

这不是复制 Apple API，而是把 Electron/Host 的窗口、文档、插件、权限和工作区能力封装成薯片自己的声明式应用结构。
