# SwiftUI 调研：预览与性能工具

## 1. 这一层解决什么问题

SwiftUI 的开发体验不只来自 API，也来自工具链。Xcode Previews 让开发者动态、交互式查看视图；性能分析工具帮助定位卡顿、长时间视图更新和频繁更新。

这说明“像 SwiftUI 一样简单”不仅是写代码简单，还要调试、预览、验证和优化都简单。

## 2. 预览能力

SwiftUI 预览的价值：

- 快速查看自定义视图。
- 在不同上下文中查看场景。
- 支持交互式预览。
- 支持调试态构建。
- 降低启动完整应用的成本。

## 3. 性能工具能力

SwiftUI 官方工具链强调：

- 检测界面卡顿。
- 分析长时间视图更新。
- 分析频繁发生的视图更新。
- 理解用户界面响应性。

## 4. 设计价值

### 4.1 工具让质量前移

开发者在写组件时就能看到主题、状态、尺寸和语言问题，而不是发布前才发现。

### 4.2 预览也是契约验证

组件预览可以展示所有状态、密度、主题、语言和窗口尺寸，本质上是组件 contract 的可视化验证。

### 4.3 性能需要日常可见

性能不能只靠偶尔 profiling。框架应默认给出渲染、长任务、列表滚动、主题切换、Bridge 调用等指标。

## 5. 对薯片的直接启发

薯片需要自己的开发工具链：

- `chips preview`：预览 app/card/box/layout/theme。
- `chips component gallery`：组件状态矩阵。
- `chips theme inspect`：token、作用域链、对比度、动效、图标。
- `chips a11y audit`：键盘、焦点、ARIA、对比度。
- `chips perf audit`：渲染提交、Bridge、主题切换、长任务、大列表滚动。
- Host mock 与真实 Host 开发工作区两种预览模式。

没有这些工具，组件库即使数量很多，也很难达到 SwiftUI 式开发体验。
