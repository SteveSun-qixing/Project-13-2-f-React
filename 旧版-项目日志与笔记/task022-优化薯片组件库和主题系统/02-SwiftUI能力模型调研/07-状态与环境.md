# SwiftUI 调研：状态与环境

## 1. 这一层解决什么问题

SwiftUI 让数据依赖驱动界面更新。开发者声明视图依赖哪些状态，状态变化后框架更新受影响部分。这个模型减少了手动刷新、事件串联和视图状态同步错误。

## 2. 核心能力

| 能力 | 作用 |
|---|---|
| `State` | 由 SwiftUI 管理的本地可读写状态 |
| `Binding` | 读写外部真实数据源的双向连接 |
| `Environment` | 从视图环境读取上下文值 |
| `EnvironmentValues` | 沿视图树传播的环境值集合 |
| `StateObject` | 创建并持有可观察对象 |
| `ObservedObject` | 订阅外部可观察对象变化 |
| `AppStorage` | 与应用级持久存储绑定 |
| `SceneStorage` | 与场景级持久存储绑定 |
| `FocusState` | 读写焦点状态 |
| `FocusedValue` | 读取当前焦点链上的值 |

## 3. 设计价值

### 3.1 状态有明确归属

本地状态、绑定状态、环境状态、持久状态、焦点状态各有不同归属。这样可以减少“某个组件到底该自己存还是上层存”的混乱。

### 3.2 环境让上下文统一下发

主题、语言、尺寸、平台能力、焦点等上下文不需要层层 props 传递，而是通过环境传播。

### 3.3 绑定让控件和数据源解耦

控件读写 binding，不需要知道数据源来自表单、配置、服务还是模型对象。

## 4. 对薯片的直接启发

薯片需要形成 React 技术栈下的 Chips State / Binding / Environment 模型：

- `useChipsState`：页面本地 UI 状态。
- `useChipsBinding`：表单、选择、导航、焦点等双向绑定。
- `ChipsEnvironmentProvider`：注入 theme、locale、density、workspace、pluginId、permissions、capabilities。
- `useChipsEnvironment`：读取环境。
- `useChipsStorage`：app、scene、workspace 作用域持久状态。
- `useChipsFocusState`：焦点状态。
- `useChipsServiceState`：Host 服务状态的受控读取与写入。

关键边界是：状态工具可以由 SDK 提供开发封装，但真实服务状态必须通过 Host Runtime Client，不允许页面直连 Host 内部实现。
