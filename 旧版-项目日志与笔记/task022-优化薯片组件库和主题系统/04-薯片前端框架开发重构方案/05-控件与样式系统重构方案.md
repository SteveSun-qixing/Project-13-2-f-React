# 重构方案：控件与样式系统

## 1. 目标

补齐并升级薯片控件体系，达到 SwiftUI 基础控件全覆盖，并满足 Web/Electron/薯片生态应用的高级控件需求。所有样式必须走主题 token 和组件 contract。

## 3. 样式系统要求

每个组件必须具备：

- `data-scope`
- `data-part`
- `data-state`
- token 清单。
- part 清单。
- 状态清单。
- motion token。
- density token。
- icon descriptor。
- i18n key。
- a11y 语义。

组件不得硬编码颜色、圆角、阴影、字体、动效和用户可见文案。

## 4. 关键任务

1. 技术栈路线收口：解决 Ark/Zag/Tamagui 与真实实现漂移。
2. 组件目录模块化：每个组件独立实现、类型、contract、token、tests、README。
3. contract validator 分层：普通组件与 iframe 高级组件分离。
4. 建立组件状态矩阵。
5. 建立主题矩阵。
6. 建立组件默认 i18n key。
7. 所有复杂组件采用组合 API。
8. 支持 direct import 和按需加载。

## 5. 验收标准

- SwiftUI 基础控件都有 Chips 对应能力。
- 每个组件通过 contract、token、i18n、a11y、DOM、浏览器和视觉测试。
- 默认主题和暗色主题覆盖所有组件状态。
- 组件 API 可组合，不依赖布尔 props 爆炸。
- 应用不需要自建基础控件。
