# 重构方案：预览与性能工具

## 1. 目标

建立薯片前端开发工具链，让组件、应用、卡片、箱子、主题和性能问题在开发阶段可见、可测、可复现。

## 2. 工具能力

### 2.1 `chips preview`

覆盖：

- app preview。
- component preview。
- card preview。
- box preview。
- layout preview。
- theme preview。
- Host mock preview。
- 真实 chipsdev 工作区 preview。

### 2.2 Component Gallery

自动生成：

- 组件状态矩阵。
- 主题矩阵。
- 密度矩阵。
- 多语言矩阵。
- 长文本矩阵。
- 焦点路径。
- 键盘路径。

### 2.3 Theme Inspector

展示：

- 当前 themeId。
- 作用域链。
- token 来源。
- 缺失 token。
- 对比度。
- 动效。
- 图标字体。
- iframe 刷新。

### 2.4 Quality Gate

统一门禁：

- lint。
- typecheck。
- unit tests。
- DOM tests。
- browser E2E。
- a11y。
- visual regression。
- perf budget。
- token validation。
- contract validation。
- i18n key validation。
- bundle/import analysis。
- Host integration smoke。

## 3. 性能指标

至少记录：

- 首屏可交互。
- 渲染提交 p95。
- 长任务比例。
- Bridge p50/p95。
- 主题切换耗时。
- 大列表滚动。
- DataGrid/Tree 大数据量。
- 弹层打开耗时。
- 内存峰值。
- 包体积。
- 开发启动和热更新耗时。

## 4. 关键任务

1. 定义 preview manifest。
2. 建立 Host mock。
3. 建立真实 chipsdev 工作区预览。
4. 建立组件 story/fixture 规范。
5. 建立视觉快照策略。
6. 建立性能采集和报告格式。
7. 将 quality gate 升级为全前端框架门禁。
8. 脚手架默认生成预览和测试样例。

## 5. 验收标准

- 开发者能不启动完整产品也能预览组件和页面。
- 主题包能看到所有组件覆盖效果。
- 质量门禁能阻断 token、i18n、a11y、视觉和性能问题。
- 性能报告能定位 Bridge、渲染、主题切换和大数据组件问题。
- 脚手架生成的新应用默认具备预览和测试入口。
