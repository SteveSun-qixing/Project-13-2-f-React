# 重构方案：状态与环境

## 1. 目标

建立 Chips State / Binding / Environment 系统，让应用可以清晰处理本地 UI 状态、领域状态、Host 服务状态、主题、多语言、权限、焦点和场景持久化。

## 2. 推荐能力

- `ChipsEnvironmentProvider`
- `useChipsEnvironment`
- `useChipsState`
- `useChipsBinding`
- `useChipsStorage`
- `useChipsSceneStorage`
- `useChipsFocusState`
- `useChipsServiceState`
- `useChipsPermission`
- `useChipsCapability`

## 3. 环境值基线

建议环境至少包含：

- `themeId`
- `themeVersion`
- `locale`
- `density`
- `workspace`
- `pluginId`
- `appId`
- `sceneId`
- `windowId`
- `permissions`
- `capabilities`
- `platform`
- `colorScheme` 等价语义，但以 themeId 为准，不作为主题包内 light/dark 分支。

## 4. 状态边界

| 状态类型 | 来源 | 写入方式 |
|---|---|---|
| Local UI state | 页面/组件本地 | React state 或 Chips state |
| Binding state | 表单、选择、导航、焦点 | `useChipsBinding` |
| Domain state | 应用业务模型 | 应用自有模型 |
| Service state | Host 服务 | Runtime Client / UI Hooks |
| Environment state | Host 注入与 Provider | Host + Provider |
| Scene storage | 场景持久化 | Host window/config 服务 |

## 5. 关键任务

1. 定义环境值 schema。
2. 定义 Binding 接口。
3. 表单组件接入 Binding。
4. 选择类组件接入 Binding。
5. 导航、焦点、命令状态接入 Binding。
6. Host 服务状态通过 Runtime Client 暴露。
7. 建立预览和测试 mock。
8. 建立语言、主题、权限变化后的更新策略。

## 6. 验收标准

- 组件和页面可以统一读取 theme、locale、density、permissions。
- 表单、选择、导航和焦点有统一 binding 模型。
- 服务状态不绕过 Runtime Client。
- 预览工具可以注入不同环境组合。
- 状态变化只更新受影响区域。
