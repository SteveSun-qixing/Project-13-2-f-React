# 任务024.08：基础卡片开发技能 vNext 更新

## 1. 任务目标

在 `chips-scaffold-basecard` vNext 升级与公共契约收口后，更新或重建本地基础卡片开发相关技能，避免后续开发继续沿用旧架构、旧技术实现和旧模板心智。

## 2. 背景

当前可用的基础卡片开发技能包含旧架构经验，仍可作为历史参考资料，但不能直接作为 vNext 架构下的开发准则。任务024实施期间应以生态设计原稿、生态共用技术文档、当前真实代码、Manifest、SDK/Host/编辑引擎链路和新脚手架验证结果为准。

## 3. 范围

- 审查现有卡片相关技能中的旧口径。
- 基于任务024最终产物和公共文档，整理新的 vNext 基础卡片插件开发流程。
- 必要时创建新的技能，覆盖基础卡片插件开发、资源桥、编辑器接入、主题/多语言、测试和验证。
- 明确旧技能中哪些内容仅保留为历史参考，哪些内容需要删除、改写或迁移。

## 4. 开发内容

1. 对照任务024提交后的 `chips-scaffold-basecard` 模板、测试、README 和公共文档，提取稳定开发流程。
2. 重新编写技能触发条件，避免把旧 Host/Bridge/编辑器实现细节当成新架构规则。
3. 将 vNext 必须遵守的内容写入技能：
   - 三件套导出与 `basecardDefinition` 契约；
   - card-root 资源相对路径；
   - `importResource / resolveResourceUrl / releaseResourceUrl / deleteResource / openResource` 等上下文回调；
   - React、组件库、主题 token、多语言；
   - 生成工程正式验证命令与质量门禁；
   - 公共文档与项目日志边界。
4. 若技能系统需要保留旧内容，必须显式标注“旧架构参考，不可直接套用”。

## 5. 验收标准

- 新技能或更新后的技能与任务024最终公共契约一致。
- 后续基础卡片插件开发不会因为技能误导而回到旧架构。
- 技能中不包含临时实现、过期 CLI 口径或未冻结接口。

## 6. 验证方式

- 对照 `生态共用技术文档/插件开发/03-卡片插件开发.md`、`06-Manifest配置规范.md` 和 `chips-scaffold-basecard` 最新模板逐条核对。
- 通过一次只读技能审查报告确认旧口径已清除或标注。

## 7. 注意事项

- 本任务应在任务024主要实现和公共文档收口后执行。
- 不把任务过程、预研记录或临时策略写入技能；技能只保留稳定可复用流程。
