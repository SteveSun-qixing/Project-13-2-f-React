# 任务029.02：AppRuntime 与 Document Scene 框架迁移

## 1. 任务目标

将 `Chips-CardViewer` 从旧单根 `App.tsx` 结构迁移到应用脚手架 vNext 的 App/Scene/surface/Environment 架构，同时保持任务029.01冻结的行为不变。

## 2. 背景

当前 `src/App.tsx` 同时承担启动上下文解析、SDK client 创建、主题、语言、打开文件、目标状态和场景分发。新框架要求形成 `AppRoot`、`AppProviders`、`AppRuntimeProvider`、`AppShell`、`scene-registry`、`runtime/`、`scenes/` 等分层，让应用开发体验靠近 SwiftUI 的 App/Scene/Environment 心智。

## 3. 开发内容

1. 新建或迁移 `src/app/AppRoot.tsx`、`AppProviders.tsx`、`AppRuntimeProvider.tsx`、`AppShell.tsx`、`scene-registry.ts`。
2. 新建 `src/runtime/chips-client.ts` 和 `src/runtime/launch-context.ts`，集中读取 `platform.getLaunchContext()` 与 fallback surface context。
3. 通过 `ChipsEnvironmentProvider` 注入单例 SDK client、launchContext、surface、theme、locale、permissions 和 diagnostics。
4. 将现有 `OpenedTarget` 语义迁移为明确 scene：空启动 scene、文件文档 scene、托管文档 scene。
5. 保持 `App.tsx` 为轻量 re-export，真实根组件交给 `AppRoot`。
6. 收敛私有 `useChipsClient` 与 `useChipsBridge` 的职责；若仍需监听正式 Bridge 事件，必须集中在 runtime 层。

## 4. 验收标准

- `src/App.tsx` 不再承载真实业务运行时。
- SDK client 不在多个业务组件中重复创建。
- 空启动、文件文档和托管文档场景均通过 AppRuntime/Scene 模型分发。
- 迁移后首屏和文件打开行为与任务029.01冻结结果一致。
- 不引入新第三方库，不直接访问 Electron 或 Node 私有能力。

## 5. 验证命令

```bash
cd Chips-CardViewer
npm run lint
npm test
npm run build
```
