# 任务035：视频播放器应用迁移

## 1. 任务目标

将 `Chips-VideoPlayer` 迁移到新前端框架基线，使它成为视频资源打开、播放控制、字幕、全屏和媒体诊断的正式应用插件。

## 2. 对应阶段任务

- `05-开发任务方案/任务20-现有应用插件全量迁移.md`
- `05-开发任务方案/任务23-模块插件能力契约与运行时迁移.md`

## 3. 涉及项目

- `Chips-VideoPlayer`
- `Chips-Host`
- `Chips-SDK`
- `Chips-ComponentLibrary`
- `Chips-BaseCardPlugin/video-BCP`
- `Chips-ModulePlugin/*`

## 4. 开发内容

1. 重新核对 `manifest.yaml` 中 video resource-handler、file-handler、权限和保存 fallback。
2. 改造为 App/Scene/Document surface 结构，支持资源打开、文件打开和空启动。
3. 用组件库重构播放控件、时间轴、音量、字幕、倍速、画面比例、全屏、画中画、错误态和诊断面板。
4. 视频元数据、转码、缩略图、字幕解析等通用能力优先走 Host/模块正式接口。
5. 与视频基础卡片 `openResource` 链路对齐，确保查看态点击视频资源可以交给播放器处理。
6. 接入命令和快捷键：播放/暂停、快进、后退、音量、全屏、字幕、倍速。
7. 接入主题、多语言、焦点、媒体键、a11y、减少动效和性能监控。
8. 增加 MP4/WEBM/MOV、字幕、错误资源、资源释放、全屏恢复和主题切换测试。

## 5. 验收标准

- 迁移后现有用户可见功能、交互路径、使用逻辑、状态流转和数据语义保持不变；本任务只切换到新框架架构与正式生态链路，不做产品行为重设计。
- 视频播放器通过 Host 资源打开链路运行。
- 不在应用层复制通用视频处理模块能力。
- 播放控件与视频基础卡片查看态体验一致。
- 高负载播放场景有性能诊断和稳定 cleanup。

## 6. 验证命令

```bash
cd Chips-VideoPlayer
npm run lint
npm test
npm run build
npm run validate
```

## 7. 注意事项

- 媒体处理能力缺失时登记模块/Host 工单，不做临时硬编码。
- 本任务开发前必须重新核对 SwiftUI media/commands/accessibility 能力、视频基础卡片和当前播放器代码。
