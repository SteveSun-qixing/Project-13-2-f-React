# 任务034：富文本编辑器应用迁移

## 1. 任务目标

将 `Chips-RichTextEditor` 迁移到新前端框架基线，使它成为以富文本基础卡片为核心的单文档写作应用，并保持正式 `.card` 数据模型。

## 2. 对应阶段任务

- `05-开发任务方案/任务20-现有应用插件全量迁移.md`
- `05-开发任务方案/任务21-基础卡片插件全量迁移.md`

## 3. 涉及项目

- `Chips-RichTextEditor`
- `Chips-Host`
- `Chips-SDK`
- `Chips-ComponentLibrary`
- `Chips-BaseCardPlugin/richtext-BCP`

## 4. 开发内容

1. 重新核对 `manifest.yaml`、`.card` 读写权限、当前保存逻辑和富文本基础卡片 schema。
2. 改造为 App/Scene/Document surface 结构，以单复合卡片文档作为正式数据源。
3. 将编辑器壳层、工具栏、格式菜单、文档信息、导入导出、错误态和保存状态纳入 View/Modifier 模型。
4. 富文本内容的渲染和编辑尽量复用 `richtext-BCP` 的正式能力，不复制第二套卡片 schema。
5. 接入 commands：新建、打开、保存、另存、撤销、重做、查找、格式、预览、导出。
6. 接入主题、多语言、焦点、键盘、a11y、输入法稳定性和减少动效。
7. 增加单文档创建、打开、保存、重新打开、导出、资源引用和异常恢复测试。
8. 与卡片查看器验证同一个输出 `.card` 的查看一致性。

## 5. 验收标准

- 迁移后现有用户可见功能、交互路径、使用逻辑、状态流转和数据语义保持不变；本任务只切换到新框架架构与正式生态链路，不做产品行为重设计。
- 富文本编辑器保存的数据是正式复合卡片文件，不产生旁路私有文档格式。
- 富文本基础卡片 schema、渲染和查看链路保持一致。
- 编辑体验具备完整命令、焦点、键盘和错误恢复。
- 输出文件可以由卡片查看器正常打开。

## 6. 验证命令

```bash
cd Chips-RichTextEditor
npm run lint
npm test
npm run build
npm run validate
```

## 7. 注意事项

- 不因为单文档场景创建额外页面分类。
- 本任务开发前必须重新核对 SwiftUI Document/commands 模型、富文本基础卡片代码和卡片文件规范。
