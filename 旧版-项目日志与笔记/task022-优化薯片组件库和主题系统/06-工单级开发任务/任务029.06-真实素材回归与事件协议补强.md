# 任务029.06：真实素材回归与事件协议补强

## 1. 任务目标

补齐 `Chips-CardViewer` 对真实 `.card/.box` 文件、复合卡片事件协议、箱子布局事件、缺失插件、主题切换、语言切换和 cleanup 的测试回归。

## 2. 背景

任务029不仅要求迁移应用架构，也要求查看器能作为 `.card` 与 `.box` 的正式查看入口。必须用成品测试空间和真实素材验证 Host/SDK/组件库/插件链路，而不是只验证 mock 空壳。

## 3. 开发内容

1. 选择 `ProductFinishedProductTestingSpace` 中代表性 `.card/.box` 素材，覆盖富文本、Markdown、图片、音乐视频、复合卡片和美食网格箱子。
2. 补齐 e2e 或集成测试：空启动、打开按钮、拖拽、Host `targetPath` 启动、`webDocumentUrl` 托管文档启动。
3. 覆盖 `chips.composite:ready`、`chips.composite:resize`、`chips.composite:node-error`、`chips.composite:fatal-error`、`chips.composite:resource-open`。
4. 覆盖 `chips.box-layout:ready`、`chips.box-layout:error` 和 SDK box runtime bridge 的打开条目路径。
5. 覆盖缺失插件、不支持文件、资源打开失败、渲染失败和 cleanup。
6. 覆盖主题切换、语言切换后应用壳层与内容 iframe 的一致性。
7. 如测试需要公共 mock 或 Host simulator 能力补强，优先在 SDK/测试工具正式链路补齐，不在查看器里写临时 mock 旁路。

## 4. 验收标准

- 真实 `.card/.box` 样例至少覆盖一个复合卡片和一个箱子。
- 事件协议测试能证明查看器通过 SDK 正式接口消费 iframe 事件。
- 缺失插件和渲染失败有可诊断错误态。
- cleanup 测试能证明 render session、box session 和 iframe 均释放。
- 主题和语言切换测试覆盖应用壳层与内容区。

## 5. 验证命令

cd Chips-CardViewer

npm run build
npm run validate
```

```
