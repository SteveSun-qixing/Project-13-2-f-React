# 任务028.04：主题 Contract 诊断与预览质量入口

## 1. 任务目标

在任务028主线中，为 `Chips-EcoSettingsPanel` 增加正式的主题 contract 状态、缺失 token 诊断、预览与质量报告入口，让设置面板成为主题治理和开发工具可见性的统一消费端。

## 2. 背景

任务028要求设置面板成为主题矩阵、组件 contract、主题 contract、缺失 token、预览与性能工具的正式入口。当前设置面板已完成组件展示矩阵、AppRuntime/Commands 和 SDK Platform Domain API 收口，但仍缺少面向主题运行时 contract/resolve 结果的页面级诊断。

启动前复核确认，首批可直接消费现有正式链路：

- `client.theme.contract.get()`
- `client.theme.resolve([])`
- `theme.changed` Host 事件
- `chipsdev preview/component gallery/theme inspect/quality gate/diagnostics` 正式报告命令口径

同时存在两个边界：

- 跨主题实时 contract 矩阵当前没有指定 `themeId` 的 Host/SDK 查询接口，本任务不在前端读取 ThemePack 私有目录替代。
- 组件矩阵、质量门禁和诊断完整 JSON 报告当前没有运行时读取 API，本任务先提供正式命令入口和状态说明，不在应用运行时代码中读取本地私有报告文件。

## 3. 开发内容

1. 新增主题诊断 Scene，展示当前主题 `theme.contract.get()` 的 summary、coverage、组件覆盖行和 blocking/warning diagnostics。
2. 新增主题解析诊断 view model，消费 `theme.resolve([])` 展示当前主题链、诊断摘要和缺失 token 信息。
3. 新增预览与质量入口 Scene，展示 `chipsdev preview`、`component gallery`、`theme inspect`、`quality gate`、`diagnostics` 的正式命令、目标、产物用途与当前消费边界。
4. 将新增 Scene 纳入 `menu-registry`、`scene-registry`、命令注册、侧栏、窄屏菜单、菜单栏、工具栏和命令面板。
5. 补齐中英文 i18n、页面单测、runtime service 单测、菜单顺序单测和根组件渲染断言。
6. 同步 `Chips-EcoSettingsPanel` 内部技术文档和 README，说明新增入口的数据来源、禁止来源和后续接口边界。
7. 在工作日志中记录本任务验证结果。

## 4. 验收标准

- 新增 UI 不读取 Host、ThemePack、组件库或工作区私有文件路径。
- 主题 contract 与缺失 token 诊断只来自 SDK/Bridge 正式接口。
- 预览与质量入口只展示正式 `chipsdev` 命令与报告消费边界，不显示假数据或伪造通过状态。
- 新增文案全部走 i18n，新增视觉样式走主题 token 和既有组件库组件。
- Scene 命令、菜单、工具栏、窄屏入口均能访问新增页面。
- `Chips-EcoSettingsPanel npm run verify` 通过。

## 5. 验证命令

