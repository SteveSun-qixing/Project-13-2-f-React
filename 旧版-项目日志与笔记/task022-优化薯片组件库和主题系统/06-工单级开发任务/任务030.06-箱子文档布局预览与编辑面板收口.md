# 任务030.06：箱子文档、布局预览与编辑面板收口

## 1. 任务目标

收口编辑引擎中的 `.box` 文档创建、打开、预览、布局配置编辑、内容列表管理、卡片/箱子嵌套导入、封面和保存链路，确保箱子在编辑引擎中走正式 Host box runtime 与布局插件契约。

## 2. 背景

设计原稿要求箱子窗口只负责预览和窗口控制，内容由布局插件渲染，右侧编辑面板承载配置与内容列表。历史工单064、079、080已收口箱子单文件模型、封面、统一编辑目标和会话幂等性，本任务在新框架迁移中保持并强化这些边界。

## 3. 开发内容

1. 复核 `box-document-service`、`useBoxDocumentSession`、`useBoxLayoutDefinition`、`BoxWindow`、`BoxPreviewSurface`、`BoxCoverSurface`、`BoxEditorPanel`。
2. 确保箱子预览通过布局插件 `layoutDefinition.renderView` 和 Host/SDK runtime 数据能力，不在编辑引擎内复制布局运行时。
3. 确保箱子配置编辑通过布局插件 `renderEditor` 与正式配置归一/校验链路。
4. 收口内容列表：导入卡片/箱子、删除条目、拖拽排序、嵌套箱子封面、列表项不暴露底层路径。
5. 收口箱子文档设置：名称、描述、标签、封面和比例通过正式设置弹窗保存，不混入右侧基础卡片编辑器。
6. 收口箱子窗口尺寸、滚动、空态、错误态、加载态、主题和语言。
7. 补充箱子 service、窗口、预览 surface、编辑面板和 e2e 基础流程测试。

## 4. 验收标准

- 编辑引擎不私建箱子布局运行时，不直接 import 布局插件源码。
- 箱子窗口内容区铺满可用宽高，布局页面不被固定高度或 overflow hidden 截断。
- 拖拽卡片/箱子到箱子窗口会导入当前箱子，而不是打开新窗口。
- 箱子选中进入右侧箱子编辑面板，卡片选中进入基础卡片编辑器，共用统一编辑目标模型。
- 箱子保存和重新打开后内容、布局配置、封面和排序一致。
