# 任务040.01：富文本基础卡片契约与数据模型收口

## 1. 任务目标

将 `Chips-BaseCardPlugin/richtext-BCP` 的入口导出、`manifest.yaml`、配置 schema、模板与测试统一收敛到新基础卡片契约，使富文本卡片以 `base.richtext` 作为正式类型，以 Markdown 作为唯一正式持久化内容源。

## 2. 开发内容

1. 复核 `manifest.yaml` 与 `basecardDefinition`：
   - `pluginId = chips.basecard.richtext`
   - `cardType = base.richtext`
   - `capabilities.cardTypes[0] = base.richtext`
   - `IconDescriptor` 使用正式运行时图标描述符。
2. 收口 `src/schema/card-config.ts`：
   - 正式 `card_type` 归一为 `base.richtext`。
   - `content_format` 固定为 `markdown`。
   - `content_source` 仅允许 `inline | file`。
   - Markdown/GFM/数学公式/上下标/高亮/下划线能力在 schema 中显式表达。
   - 内部资源路径统一为卡片根目录相对路径，禁止绝对路径、`file://`、`blob:`、`data:`、查询串、片段和 `..` 逃逸。
3. 明确 200 字分流：
   - 纯文本长度 `<= 200` 写入 `content_text`。
   - 纯文本长度 `> 200` 写入卡片根目录 `.md` 资源，并在配置中记录 `content_file`。
4. 收口 `collectResourcePaths`：
   - 收集 `content_file`。
   - 收集 Markdown 正文中显式引用的卡片根目录相对资源路径。
5. 更新默认模板、README/内部技术文档中与当前实现直接相关的字段口径。

## 3. 验收标准

- `basecardDefinition` 与 `manifest.yaml` 身份完全一致。
- 新建配置输出正式 `base.richtext`，不再把旧 `RichTextCard` 作为正式持久化值。
- schema、模板、测试与入口导出使用同一份字段口径。
- 非法资源路径不会进入正式配置或资源清单。
