# 任务030.02：AppRuntime、Scene 与 Environment 骨架迁移

## 1. 任务目标

将 `Chips-EditingEngine` 的应用入口从当前 `App.tsx` 承载大量初始化和业务分发的结构，迁移到 AppRuntime / Scene / Environment / surface 骨架，为后续命令、编辑运行时、箱子链路和工作台 UI 并行收口提供稳定根基。

## 2. 背景

当前 `src/App.tsx` 同时处理 SDK client、主题、语言、初始化、工具窗口、工作区文件事件、拖拽目标解析、卡片/箱子窗口创建和设置弹窗。按照任务022新框架目标，复杂应用需要形成清晰的 App / Scene / Document / Environment 心智，但不能改变现有工作台行为。

## 3. 开发内容

1. 新建或迁移 `src/app/`、`src/runtime/`、`src/scenes/` 等骨架，保持 `src/App.tsx` 为轻量入口。
2. 集中创建 SDK client、读取 launch context、surface context、权限、诊断、主题和语言。
3. 用 `ChipsEnvironmentProvider` 注入统一环境；保留并逐步迁移现有 `SettingsProvider`、`UIProvider`、`EditorProvider`、`EditorRuntimeProvider`、`CardProvider`、`EditorSelectionProvider`。
4. 定义编辑引擎内部 scene：工作台场景、卡片文档场景、箱子文档场景、设置场景、工具窗口场景。
5. 将初始化流程拆分为可测试运行时动作：基础卡片注册表同步、i18n 初始化、工作区初始化、默认工具窗口创建。
6. 保持 `theme.changed`、`language.changed`、插件安装/启用/禁用/卸载等正式事件的现有行为。
7. 补充根组件与初始化行为测试，避免迁移后重复初始化、工具窗口重复创建或语言主题脱节。

## 4. 验收标准

- SDK client 不在多个业务组件中重复创建。
- 根应用入口职责清晰，业务初始化进入 Runtime/Scene 层。
- 默认工具窗口、工作区文件打开、卡片/箱子窗口恢复、设置弹窗行为与任务030.01冻结结果一致。
- 主题与语言仍通过正式 Host 事件进入应用，不在业务组件中私造状态。
- 不直接访问 Electron/Node 私有能力，不绕过现有 services/SDK/Bridge 边界。

## 5. 验证命令

```bash
cd Chips-EditingEngine
npm run lint

npm run build
```

视改动范围补跑完整：

```bash

```
