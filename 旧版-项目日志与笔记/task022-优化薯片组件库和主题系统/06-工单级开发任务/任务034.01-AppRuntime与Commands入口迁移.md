# 任务034.01：富文本编辑器 AppRuntime 与 Commands 入口迁移

## 1. 任务目标

将 `Chips-RichTextEditor` 从旧的单文件应用入口迁移到应用插件 vNext 根结构，使应用具备标准 `AppRoot / AppProviders / AppRuntimeProvider / AppShell / commands` 分层，并通过 Host command registry 承载文件、信息和基础编辑动作入口。

## 2. 开发范围

- `Chips-RichTextEditor/src/app/`
- `Chips-RichTextEditor/src/runtime/`
- `Chips-RichTextEditor/src/commands/`
- `Chips-RichTextEditor/src/App.tsx`
- `Chips-RichTextEditor/src/main.tsx`
- `Chips-RichTextEditor/manifest.yaml`
- 必要测试与项目内部技术文档

## 3. 开发内容

1. 新增标准应用根组件结构：
   - `AppRoot`
   - `AppProviders`
   - `AppRuntimeProvider`
   - `AppShell`
2. 使用 `ChipsEnvironmentProvider` 注入 SDK client、初始主题、语言、启动上下文、surface 和权限。
3. 将 `platform.getLaunchContext()` 与 `surfaceContext` 解析收口到运行时层。
4. 建立富文本编辑器命令定义，至少覆盖：
   - 新建
   - 打开
   - 保存
   - 另存为
   - 当前信息
   - 撤销
   - 重做
   - 查找
   - 格式
   - 预览
   - 导出
5. 将现有右上角操作菜单改为消费命令视图，不再维护一套与 Host command registry 脱节的私有动作模型。
6. `manifest.yaml` 补齐 `command.read / command.write / command.invoke` 权限。
7. 保持首屏、操作路径和用户心智不变：仍是极简单文档写作界面，不新增管理型布局。

## 4. 验收标准

- 应用入口符合应用插件 vNext 结构，`src/App.tsx` 只保留标准 re-export。
- 命令 metadata 只使用 `titleKey / descriptionKey / ariaLabelKey`，不得写原始显示文案。
- 菜单触发通过 `client.command.invoke()` 和插件侧 `command.invoked` 处理，不直接调用业务函数。
- 命令注册失败有明确状态反馈，不影响正文编辑器已可用路径。
- 用户可见功能与原应用一致。
