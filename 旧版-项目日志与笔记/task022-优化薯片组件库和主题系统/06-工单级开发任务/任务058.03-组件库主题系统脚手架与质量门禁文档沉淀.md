## 4. 开发内容

1. 明确组件库只负责 L10 无头结构、状态、a11y 和契约，不写主题视觉皮肤。
2. 更新 `data-scope/data-part/data-state`、组件 contract、组件覆盖矩阵和质量门禁口径。
3. 更新 token 权重链、主题包 `tokens/theme.css/contract`、图标字体和 motion token 的正式说明。
4. 更新 `quality:gate`、`verify`、主题 `validate:theme`、脚手架 `test:e2e` 的第一版质量门禁用途。
5. 同步五类脚手架生成工程基线：五类默认可 build/test/validate；基础卡片、箱子布局、功能模块和主题包模板的 `verify` 串联 package；应用模板当前不声明 npm `package` 脚本，应用打包通过 `chipsdev package` 或工程显式脚本完成。
6. 明确主题脚手架必须与当前组件契约同步，包括 `rating` 等新增组件 token。

## 5. 验收标准

- 文档与当前组件契约、主题 token、脚手架模板和报告产物一致。
- 文档不把主题视觉实现写进组件库职责。
- 文档不把脚手架内部模板渲染实现误写为公共契约。
- 文档明确质量门禁机器口径和报告文件用途。
- 未实现的未来组件、未来主题和未来平台能力不写成第一版完成。
