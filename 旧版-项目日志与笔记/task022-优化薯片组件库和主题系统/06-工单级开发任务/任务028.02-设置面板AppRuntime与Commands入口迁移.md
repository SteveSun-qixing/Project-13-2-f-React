# 任务028.02：设置面板 AppRuntime 与 Commands 入口迁移

## 1. 任务目标

在任务028主线中，将 `Chips-EcoSettingsPanel` 从旧的本地菜单壳层推进到应用插件 vNext 入口结构：`AppRoot / AppProviders / AppRuntimeProvider / scene-registry / commands`，并保持现有页面功能、菜单顺序、交互路径和数据语义不变。

## 2. 背景

任务028要求设置面板改造为 App/Scene/surface/commands 结构，并接入统一导航、菜单、工具栏、命令面板、主题、多语言、a11y 和错误诊断。

任务028.01 已经先修复组件展示矩阵与组件库正式组件清单漂移。本任务继续迁移应用入口与命令消费主链路，作为后续 SDK Domain API 收口、主题矩阵、诊断入口、预览入口和权限不足测试的基础。

## 3. 开发内容

1. 新增 `AppRoot`、`AppProviders`、`AppRuntimeProvider`、`AppShell` 与 `scene-registry`，让 `src/App.tsx` 只保留标准 re-export。
2. 保留现有 `RuntimeProvider` 与 `I18nProvider` 作为当前设置治理运行时来源，同时通过组件库 `ChipsEnvironmentProvider` 与 `ChipsThemeProvider` 注入正式应用环境。
3. 从当前菜单注册表派生 Scene 定义，保持 `themes / languages / app-plugins / card-plugins / layout-plugins / module-plugins / component-gallery` 的顺序和页面装配不变。
4. 新增 `settings-commands.ts` 与 `useSettingsCommands.ts`，为每个 Scene 生成稳定 command id、`handlerId`、i18n key、`IconDescriptor`、菜单/工具栏/命令面板 placement，并通过 SDK `client.command.*` 注册、调用和清理。
5. 在 `AppShell` 中接入 `ChipsCommandProvider`、`ChipsMenuBar`、`ChipsToolbar` 与 `ChipsCommandPalette`，让侧栏、窄屏切换器和命令消费组件共享同一套 command metadata。
6. 补齐 `manifest.yaml` 与 e2e 测试中的 `command.read / command.write / command.invoke` 权限断言。
7. 更新中英文 i18n、项目 README 与内部技术文档，记录新的 AppRuntime/Scene/Commands 入口。
8. 升级根组件单测 mock，使其覆盖 `client.command.register/list/invoke/onInvoked/unregister` 链路。

## 4. 验收标准

- 根组件真实入口为 `AppRoot`，旧 `src/app/App.tsx` 不再承载业务壳层实现。
- 设置面板当前用户可见页面、菜单顺序、窄屏切换器和治理功能保持不变。
- Scene 导航 command metadata 不写原始用户文案，只使用 i18n key、IconDescriptor 和稳定 handler id。
- 命令注册、调用和卸载清理走 SDK `client.command.*`。
- manifest 声明 command 权限，测试覆盖权限基线与根组件 mock。
- `Chips-EcoSettingsPanel` 正式验证链路通过。

## 5. 验证命令

```bash
cd Chips-EcoSettingsPanel

```
