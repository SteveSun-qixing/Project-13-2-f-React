# 任务055.01：预检与开发工作区安装态抽样

## 1. 任务目标

在任务055正式展开前，重新核对安装打包发布链路的公共契约、当前代码入口和官方插件工程状态，并用开发工作区完成五类插件与主题包的安装态抽样，确认后续验收不会把源码目录误当作 Host 运行入口。

## 2. 背景

任务055覆盖 Host、SDK、脚手架、五类插件、主题包、`.cpk`、`.card`、`.box` 与安装器发布链路。第一阶段必须先验证生态根工具链、插件打包脚本、CPK 格式和开发工作区隔离，避免后续验收建立在错误入口上。

## 3. 开发内容

1. 复核 `生态设计原稿/03-底层内核和打包模式.md`、`生态设计原稿/07-插件系统架构.md`、`生态共用技术文档/开发与运维/04-打包与安装路径手册.md`、CPK 打包格式、Host CLI 和 chipsdev CLI。
2. 检查官方 `app / card / layout / module / theme` 五类工程是否具备 `build / validate / package` 入口。
3. 检查当前 `.cpk` 产物结构，确认包根存在 `manifest.yaml` 与 `dist/`，并确认包内没有嵌套旧 `.cpk`、重复 manifest 或发布辅助文件。
4. 使用临时开发工作区验证主题包、应用插件、基础卡片插件、箱子布局插件、模块插件可安装与启用。
5. 验证默认主题可 `theme apply` 与 `theme validate`。
6. 执行工作区级预检，确认开发工作区与用户工作区没有混用。
7. 如发现工具链缺口，按工单规则登记问题，并继续推进不受阻的验证部分。

## 4. 验收标准

- 五类插件均有正式构建、校验、打包入口或已登记明确缺口。
- 抽样 `.cpk` 均满足当前 CPK 打包格式规范。
- 临时开发工作区中可安装并启用五类插件与默认主题包。
- 默认主题包在开发工作区可应用和校验。
- `.chips-host-dev` 与用户态工作区边界明确，不能把开发工作区当作终端用户运行目录。

## 5. 验证命令

```bash
npm run verify:workspace

cd ThemePack/Chips-default
npm run build
npm run validate:theme
npm run package

chipsdev plugin install <theme-cpk>
chipsdev plugin enable theme.theme.chips-official-default-theme
chipsdev theme apply chips-official.default-theme
chipsdev theme validate
```

可按插件类型补充执行：

```bash
npm run build
npm run validate
npm run package
chipsdev plugin install <plugin-cpk>
chipsdev plugin enable <pluginId>
```
