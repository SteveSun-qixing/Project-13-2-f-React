# 任务029.01：卡片查看器现状冻结与启动契约复核

## 1. 任务目标

在正式迁移 `Chips-CardViewer` 代码前，冻结当前用户可见行为和 Host 启动契约，确认 `manifest.yaml`、权限、file-handler、surface、启动上下文、测试链路与任务029目标一致。

## 2. 背景

任务029要求迁移到新前端框架基线，但不能改变现有用户可见功能、交互路径、使用逻辑、状态流转和数据语义。当前查看器已有 `.card/.box` file-handler 和 `client.document.window.render(...)` 主显示链路；本子任务先把这些真实现状记录为后续迁移的对照基线。

## 3. 开发内容

1. 复核 `Chips-CardViewer/AGENTS.md`、任务029、相关启动前复核草稿、查看器设计原稿、卡片渲染机制、应用插件开发规范和复合卡片窗口标准。
2. 复核 `Chips-CardViewer/manifest.yaml` 的 `file-handler:.card/.box`、`permissions`、`runtime.targets`、`ui.surface`、`ui.launcher` 和 `ui.layout`。
3. 冻结当前启动路径：空启动、`launchParams.targetPath`、`launchParams.webDocumentUrl`、拖拽文件、打开文件按钮。
4. 冻结当前状态语义：加载态、错误态、不支持文件提示、资源打开失败、托管文档 iframe、文档窗口 cleanup。
5. 复核当前测试覆盖与缺口，确认后续迁移必须保留的测试场景。
6. 如发现公共契约与当前代码明显冲突，按项目日志工单规则登记问题；不在查看器内用临时旁路绕过。

## 4. 验收标准

- 当前用户可见行为已形成可验证清单。
- `.card/.box` 启动、空启动、拖拽、打开按钮、托管文档路径的现状均被记录。
- 权限和 manifest 风险点明确，尤其是 `command.*`、`i18n.write`、`resource.open` 和 web target 边界。
- 后续迁移不得删除或改变已冻结行为，除非先登记明确工单。

## 5. 验证命令

```bash
cd Chips-CardViewer
npm run lint
npm test
```

## 6. 后续衔接

完成本任务后进入 `029.02`，按已冻结现状迁移 AppRuntime、Provider 和 Document Scene 框架。
