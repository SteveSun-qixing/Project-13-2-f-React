# 任务055.07：`.card/.box` 安装态渲染编辑保存导出验收

## 1. 任务目标

在安装副本或安装副本等价语境下，验证 `.card` 与 `.box` 样例可打开、渲染、编辑、保存、导出，并确认卡片查看器、编辑引擎、基础卡片插件、箱子布局插件、主题和模块导出能力能够协同工作。

## 2. 背景

前序阶段已验证开发工作区、用户工作区、模块能力、安装器产物和系统入口。任务055还必须覆盖内容文件的真实使用链路，不能只证明包能安装。

## 3. 开发内容

1. 复核 `.card`、`.box` 文件格式规范、卡片查看器迁移结果、编辑引擎迁移结果、基础卡片插件和箱子布局插件迁移结果。
2. 使用 `ProductFinishedProductTestingSpace` 中真实样例作为验收材料，至少覆盖：
   - `富文本基础卡片.card`
   - `美食网格箱子.box`
   - 必要时补充图片、视频音乐或集成样例。
3. 在临时用户工作区或安装副本等价工作区安装并启用必要插件：
   - 默认主题；
   - 卡片查看器；
   - 编辑引擎；
   - 富文本基础卡片插件；
   - 网格箱子布局插件；
   - 导出相关模块插件。
4. 验证 `chips open` 或安装副本入口可打开 `.card` 与 `.box`，并分发到正确应用插件。
5. 验证 Host `card.render`、`card.renderEditor`、`card.pack`、`card.unpack`、`box.openView`、`box.renderLayoutFrame`、`box.renderLayoutEditor`、`box.pack`、`box.unpack` 等正式服务链路。
6. 验证编辑引擎中对 `.card` 的可编辑状态、保存回写和导出 `.card / HTML / PDF / image` 的可用性；格式可用性受当前模块 provider 支持情况约束，缺 provider 要记录为发布阻断或能力缺口。
7. 验证箱子文档可打开、布局预览、布局编辑、保存回写和重新打包。
8. 如图形界面自动化无法完整覆盖，必须写清已自动验证部分、未自动验证部分和人工验收步骤。

## 4. 验收标准

- `.card` 样例可通过正式 Host 链路打开和渲染。
- `.card` 可进入编辑态，修改后可保存并重新打包。
- `.card` 至少完成 `.card` 自身导出；HTML/PDF/image 导出按 provider 实际能力验证或登记阻断。
- `.box` 样例可打开、读取条目、渲染布局 frame，并能进入布局编辑器。
- `.box` 修改后可保存并重新打包。
- 主题、多语言、资源桥和插件权限不能通过临时硬编码绕开。
- 所有未覆盖的真实 GUI 操作必须进入最终人工验收清单。
