# 任务030.07：工作台、画布、工具窗口、主题 i18n、焦点与 A11y 收口

## 1. 任务目标

将编辑引擎主工作区、无限画布、工作台布局、工具窗口、Dock、文件管理器、卡箱库、拖拽、焦点、键盘、主题、多语言和可访问性统一收口到新前端框架质量基线。

## 2. 背景

编辑引擎的用户体验集中在复杂工作台：无限画布、工具窗口、卡箱库、文件管理器、编辑面板和窗口层必须协同工作。迁移到新框架不能改变交互逻辑，但需要减少散落状态、硬编码视觉和不可访问路径。

## 3. 开发内容

1. 复核 `InfiniteCanvas`、`Workbench`、`BaseWindow`、`ToolWindow`、`Dock`、`FileManager`、`CardBoxLibrary`、`DragDrop`、`WindowMenu`。
2. 收口主工作区布局：页面根、窗口层、画布层、工具层、Dock 和设置弹窗的 surface 语义。
3. 收口拖拽：基础卡片创建、插入、工作区文件打开、卡片/箱子导入、插入指示线、拖拽手柄。
4. 收口焦点与键盘：工具窗口移动/收起/关闭、菜单、文件树、卡箱库、编辑面板、弹窗关闭和焦点恢复。
5. 收口主题：所有窗口、面板、空态、错误态、加载态、焦点环和选中态使用主题 token，不新增硬编码单色视觉。
6. 收口 i18n：用户可见文案、aria、状态提示、菜单和错误均走本地语言包与 Host 语言事件。
7. 收口 a11y：region、dialog、menu、tree/list、toolbar、status/alert、拖拽提示和键盘路径测试。
8. 如发现组件库缺少必要组件或 a11y 工具，按问题工单规则登记，不在编辑引擎内写长期私有替代物。

## 4. 验收标准

- 现有无限画布平移/缩放、复合卡片交互代理和局部滚动所有权保持不变。
- 工具窗口、Dock、文件树、卡箱库、菜单和弹窗均有明确语义和键盘路径。
- UI 文案不新增硬编码正式文本，视觉不新增脱离主题 token 的硬编码皮肤。
- 焦点关闭恢复、Escape 关闭、roving 或列表导航路径经过测试覆盖。
- 工作台在默认主题与暗色/高对比主题下没有明显主题脱节。
