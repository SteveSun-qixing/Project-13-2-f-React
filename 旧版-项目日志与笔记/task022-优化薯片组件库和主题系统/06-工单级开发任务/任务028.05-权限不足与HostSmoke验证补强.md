# 任务028.05：权限不足与 Host Smoke 验证补强

## 1. 任务目标

补齐设置面板在正式 Host/SDK 权限治理下的错误态、权限不足、主题切换、语言切换和 Host 集成 smoke 验证，确保任务028迁移后的治理入口不仅能在 mock 中渲染，也能在真实开发工作区链路中保持可靠。

## 2. 背景

任务028已逐步完成组件矩阵、AppRuntime/Commands、SDK Platform Domain API 和主题诊断入口。后续需要验证 manifest 权限、SDK Domain API 消费、Host Bridge 权限拒绝、主题/语言事件刷新和真实开发工作区启动链路之间没有漂移。

028.05 启动前复核报告由子代理提前写入 `08-草稿笔记`，主任务开始时需要结合该报告与当前代码确认最终实施边界。

## 3. 开发内容

1. 复核 `manifest.yaml` 权限与当前 `SettingsRuntimeService`、hooks、Scene 命令实际消费的 SDK Domain API 是否一致。
2. 使用 SDK mock host 或现有测试辅助补权限不足错误态，覆盖主题读取、主题写入、语言写入、插件治理、平台对话框和命令注册等关键路径。
3. 补强主题切换与语言切换事件刷新测试，确保 `theme.changed`、`language.changed` 到页面状态和 AppRuntime 状态的传播稳定。
4. 增加或完善 Host 集成 smoke 测试入口，优先复用 `chipsdev run`、`chipsdev validate`、SDK mock host 或项目已有 e2e 机制，不新建平行 Host 启动器。
5. 更新项目技术文档中的权限基线、测试策略和 Host smoke 执行说明。
6. 在工作日志中记录验证命令、结果和仍需后续任务处理的边界。

## 4. 验收标准

- manifest 权限与设置面板实际 SDK Domain API 消费一致。
- 权限不足错误以统一 `SettingsPanelError` 展示，不泄漏 Host/Electron 原始异常前缀。
- 主题和语言事件刷新路径有测试覆盖。
- Host smoke 使用正式工具链，不直接调用 Host 私有模块或伪造运行时。
- `Chips-EcoSettingsPanel npm run verify` 通过；如新增跨仓测试，受影响仓库验证同步通过。

## 5. 验证命令

```bash
cd Chips-EcoSettingsPanel
npm test -- runtime-service.test.ts runtime-hooks.test.tsx app.test.tsx basic-flow.test.ts
npm run verify
```

如实施中新增 Host/SDK 契约或 smoke 入口，还需补跑对应仓库正式验证。
