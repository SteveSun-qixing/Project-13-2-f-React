# 任务033.02：AppRuntime、Scene、Environment 与启动链路迁移

## 1. 任务目标

将 `Chips-PhotoViewer` 从旧单体 `src/App.tsx` 入口迁移到应用脚手架 vNext 的 AppRuntime、Scene、surface 与 Environment 架构，同时保持图片查看器现有功能、交互路径、状态流转和数据语义不变。

## 2. 背景

当前 `src/App.tsx` 同时承担 SDK client 创建、Bridge 事件订阅、主题语言初始化、启动上下文解析、文件选择、资源解析、图片会话、保存和反馈状态。新框架要求业务运行时进入 `src/app/`、`src/runtime/` 与 `src/scenes/` 分层，应用根通过 `ChipsEnvironmentProvider` 与 `ChipsThemeProvider` 注入 Host 运行上下文。

## 3. 开发内容

1. 新建 `src/app/AppRoot.tsx`、`AppProviders.tsx`、`AppRuntimeProvider.tsx`、`AppShell.tsx`、`scene-registry.ts`。
2. 新建 `src/runtime/chips-client.ts`、`launch-context.ts`、`environment-client.ts`、`theme-runtime.ts`，集中管理 SDK client、Host launch context、surface fallback、Environment client 与主题快照。
3. 将 `src/App.tsx` 收敛为轻量 re-export，真实业务入口迁入 AppRuntime 和 AppShell。
4. 将图片会话建模为明确 scene：空启动、图片查看、错误反馈；scene 不改变现有产品视觉和操作逻辑。
5. 保留并复用 `resolveLaunchImageTarget(...)` 对 `targetPath`、`resourceOpen.filePath/resourceId` 和 `chips.book-card` 图片序列 payload 的解析。
6. 继续通过 SDK 正式接口调用 `platform.openFile/saveFile`、`resource.resolve/readBinary`、`file.copy/write`，不复制 Host 资源转换、颜色提取或文件处理基础设施。
7. 补充 AppRuntime、launch context、Environment provider、scene 选择和启动只处理一次的测试。

## 4. 验收标准

- SDK client 不在多个业务 hook 中重复创建。
- `src/App.tsx` 不再承载真实业务运行时。
- `launchParams.resourceOpen`、`launchParams.targetPath`、手动打开、拖拽打开和图片序列浏览行为保持不变。
- 主题、语言、surface、permissions 和 diagnostics 通过 Environment/Theme provider 统一进入 React 树。
- 不直接访问 Electron/Node 私有能力，不新增第三方库。

## 5. 验证命令

```bash
cd Chips-PhotoViewer
npm run lint
npm test -- --run tests/unit/app.test.tsx tests/unit/launch-resource.test.ts tests/unit/image-viewer.test.ts
npm run build
```

视改动范围补跑完整 `npm test` 与 `npm run validate`。
