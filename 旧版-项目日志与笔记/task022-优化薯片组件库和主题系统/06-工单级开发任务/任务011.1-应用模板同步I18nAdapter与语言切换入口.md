# 任务011.1：应用模板同步 I18n Adapter 与语言切换入口

## 1. 任务目标

在任务011的 React Environment Provider 基础上，补齐应用模板同步 i18n adapter 与语言切换入口，让生成应用在渲染期、命令 UI 和示例组件中使用同一套语言状态。

## 2. 背景

任务011已让 `chips-scaffold-app` 标准模板通过 `ChipsEnvironmentProvider/useChips*` hooks 消费 Host 环境，并用 `useChipsI18n().locale` 驱动本地资源 fallback。

当前仍存在后续缺口：

- `useChipsI18n().translate/t` 是异步接口，React 渲染期仍需要同步文案 adapter；
- 应用模板需求中包含语言切换示例，但标准模板当前没有正式切换入口；
- 若语言切换需要调用 `client.i18n.setCurrent()`，模板 manifest 权限与测试 mock 需要同步确认。

## 3. 涉及项目

- `Chips-ComponentLibrary/packages/hooks`
- `Chips-ComponentLibrary/packages/testing`
- `Chips-Scaffold/chips-scaffold-app`
- `生态共用技术文档/协议与接口标准/03-多语言规范.md`

## 4. 开发内容

1. 定义渲染期同步 i18n adapter 使用口径。
2. 评估是否在组件库 hooks 中提供同步 `useChipsI18nText` / `useChipsLocaleText` 类辅助。
3. 应用模板增加语言切换入口或正式示例。
4. 若需要写入语言状态，补齐 manifest 权限、mock client 行为和生成工程测试。
5. 更新应用脚手架 README、内部需求/技术文档与生态公共多语言规范。

## 5. 验收标准

- 生成应用渲染期文案、命令组件 i18n、示例组件文案使用同一语言状态。
- 语言切换入口不绕过 SDK/Environment。
- 模板测试和 e2e 覆盖语言切换或同步 adapter 行为。
- 不引入新的第三方 i18n 库。

## 6. 验证命令

```bash
cd Chips-ComponentLibrary && npm run verify
cd ../Chips-Scaffold/chips-scaffold-app && npm test && npm run test:templates && npm run test:e2e
```
