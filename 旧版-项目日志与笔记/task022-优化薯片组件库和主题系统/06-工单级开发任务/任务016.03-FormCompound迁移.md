# 任务016.03：Form Compound 迁移

## 1. 任务目标

把 `Form` 迁移为正式 Compound API，收口表单根节点、分区、字段、标签、控件、错误和提示的 slot 规则。

## 2. 父任务

- `任务016-组件库复杂组件Compound迁移.md`
- 对应阶段任务：`05-开发任务方案/任务09-复杂组件Compound-API与样式契约.md`

## 3. 涉及项目

- `Chips-ComponentLibrary/packages/components`
- `Chips-ComponentLibrary/packages/theme-contracts`
- `Chips-Host/src/renderer/declarative-ui`
- `Chips-Host/tests/unit`
- `生态共用技术文档/组件库`

## 4. 开发内容

1. 为 `Form` 建立 `Root / Section / Field / Label / Control / Error / Hint` Compound API。
2. 与既有 `ChipsFormField / ChipsFormGroup` 的职责边界对齐，统一 `helper/hint` 与 `form-field/field` 口径。
3. 补齐 TypeScript 声明、组件测试、a11y 规则、component contract 和公共文档。
4. 补齐 Host L8 `StandardCompoundSlotSchemas` 中本批组件对应 slot schema 与诊断测试。

## 5. 验收标准

- `Form.Root/Section/Field/Label/Control/Error/Hint` 运行时、类型、contract 和 Host schema 使用同一套命名。
- 表单 label/control/error/hint 的 `aria-describedby / aria-invalid / required` 主流程测试覆盖。
- 组件库不承载业务校验逻辑，只提供字段结构、ARIA 关联和状态挂点。
- 如新增正式 `form` scope，必须同步组件 contract、token、主题包和公共文档。
