## 4. 开发内容

1. 明确 Host 是唯一运行时承载，SDK 不承载 Host 主实现。
2. 明确插件访问系统能力只能通过 `window.chips.*`、Bridge 或 `chips-sdk`。
3. 明确服务间调用必须走 Kernel 路由，禁止跨服务直接 `import`。
4. 更新 Bridge / SDK 调用、错误、事件、权限、重试和超时公共口径。
5. 更新 App / Scene / surface / launcher / command 的公共运行模型。
6. 更新 L8 / L9 当前已经稳定的声明式 UI 与统一渲染公共契约。
7. 删除或改写仍在文档中暗示旧架构、旧前端框架、独立页面框架或 SDK 承载 runtime 的表述。

## 5. 验收标准

- 公共文档和当前 Host / SDK 代码、`manifest.yaml`、测试结果一致。
- 文档中没有把 Host 内部实现细节误写为插件开发者必须依赖的公共 API。
- 文档明确 `surface` 是应用容器主语义，`window` 只是桌面映射。
- 文档明确命令系统使用 `commandId/titleKey/handlerId/scope` 等结构化元数据。
- 不把任务过程、临时验证命令或工单细节写入生态公共文档。
