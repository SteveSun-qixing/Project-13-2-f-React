# 任务055.05：模块 Job、取消与 Provider 清理验收

## 1. 任务目标

补齐模块插件异步 job、取消、provider 状态治理、禁用启用恢复和卸载清理验收，确认模块能力不会在插件生命周期变化后残留错误可调用状态。

## 2. 背景

模块插件是生态共享能力底座。发布链路不仅要证明模块可以调用，还要证明 provider 在禁用、启用、卸载、job 取消和异常场景下可被 Host 正确治理。

## 3. 开发内容

1. 复核模块能力契约中的 `module.invoke`、`module.job.get`、`module.job.cancel`、provider 查询和解析规则。
2. 扩展或运行 Host 集成测试，覆盖同步方法、job 方法、超时、取消、取消事件和 consumes 权限校验。
3. 增加 provider 生命周期断言：`plugin.disable` 后 provider 不应再被 `module.resolve` 选中。
4. 验证 `plugin.enable` 后 provider 恢复可发现与可调用。
5. 验证 `plugin.uninstall` 后 provider 列表清空，调用返回 `MODULE_PROVIDER_NOT_FOUND`。
6. 执行真实 packaged 模块 e2e，验证 `.cpk` 安装启用后返回 job 并生成输出产物。

## 4. 验收标准

- Host 集成测试覆盖模块同步调用、job 调用、取消、超时、权限和 provider 生命周期。
- 禁用模块后 enabled/running provider 查询为空，`module.resolve` 不选中该 provider。
- 启用模块后 provider 恢复。
- 卸载模块后 provider 记录清空，调用失败码符合契约。
- 至少一个 packaged 模块插件 e2e 通过，并生成真实输出。

## 5. 验证命令

```bash
cd Chips-Host
npm test -- --run tests/integration/host-services.test.ts

cd ../Chips-ModulePlugin/Chips-HtmltoPDF-Plugin
npm run e2e
```
