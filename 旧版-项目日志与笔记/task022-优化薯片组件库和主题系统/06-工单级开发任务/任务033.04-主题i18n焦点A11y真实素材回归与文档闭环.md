# 任务033.04：主题、i18n、焦点 A11y、真实素材回归与文档闭环

## 1. 任务目标

完成图片查看器迁移后的质量收口：主题 token 化样式、多语言文案完整性、焦点/键盘/A11y、图片交互回归、真实素材和文档日志验收。

## 2. 背景

图片查看器属于面向用户的官方应用插件。迁移后不能只完成运行时骨架，还必须确保用户可见文案走多语言、视觉样式走主题 token、图像和错误态使用组件库公开契约，且拖拽、滚轮、指针、键盘导航和保存链路均可验证。

## 3. 开发内容

1. 清理应用层硬编码颜色、字号、阴影和焦点样式，改为使用主题 CSS 变量和组件库公开 data scope/part 入口；必要的布局尺寸只表达结构，不写业务私有视觉值。
2. 补齐 `i18n/zh-CN.json` 与 `i18n/en-US.json` 中命令、状态、错误、菜单、工具栏、A11y label 和图片序列文案。
3. 为图片舞台、空态、加载态、错误态、反馈、底部命令 dock、图片序列状态补齐 `role`、`aria-label`、`aria-live`、焦点顺序和键盘路径。
4. 保持拖拽平移、滚轮缩放、双击或快捷命令缩放、上一张/下一张键盘导航、适应窗口、实际大小和保存行为不变。
5. 对 PNG/JPG/WEBP/GIF/SVG/AVIF、错误图片、超大图、图片序列、Host 托管资源保存、资源释放风险进行单元或 smoke 覆盖；无法真实运行的部分在日志中说明证据和剩余风险。
6. 更新 `Chips-PhotoViewer/技术文档`、`需求文档` 或 `开发计划` 中与实际代码不一致的内部信息；通用契约如有新增，另同步生态共用技术文档。
7. 在 `07-工作日志` 写任务033阶段日志，最终记录验证命令与结果。

## 4. 验收标准

- 用户可见功能、交互路径、使用逻辑、状态流转和数据语义与迁移前保持一致。
- 图片查看器通过正式资源打开链路运行，不硬编码上游应用或 Host 内部实现。
- 不在应用层复制 Host 图像转换、颜色提取或资源管理基础设施。
- 图片交互不破坏窗口焦点、键盘和 a11y。
- 主题和语言切换不会破坏应用壳层或命令入口。
- `npm run lint`、`npm test`、`npm run build`、`npm run validate` 均通过，或明确记录外部阻塞证据。

## 5. 验证命令

```bash
cd Chips-PhotoViewer
npm run lint
npm test
npm run build
npm run validate
```
