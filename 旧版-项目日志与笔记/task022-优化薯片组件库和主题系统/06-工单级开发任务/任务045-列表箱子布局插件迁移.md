# 任务045：列表箱子布局插件迁移

## 1. 任务目标

将 `Chips-BoxLayoutPlugin/list-BLP` 迁移到新前端框架基线，使列表布局成为箱子线性浏览、信息密度、键盘导航和批量操作的高质量样板。

## 2. 对应阶段任务

- `05-开发任务方案/任务22-箱子布局插件全量迁移.md`

## 3. 涉及项目

- `Chips-BoxLayoutPlugin/list-BLP`
- `Chips-Host`
- `Chips-SDK`
- `Chips-ComponentLibrary`
- `Chips-CardViewer`
- `Chips-EditingEngine`

## 4. 开发内容

1. 重新核对 `manifest.yaml` 中 `layout.layoutType`、权限、`layoutDefinition` 和测试。
2. 补齐 layoutDefinition：pluginId、layoutType、displayName、IconDescriptor、默认配置、normalize、validate、renderView、renderEditor。
3. 查看态使用 `listEntries`、`renderEntryCover`、`readEntryDetail`、`openEntry` 实现按需详情。
4. 编辑态支持行密度、封面尺寸、显示字段、排序、分组、顶部内容区和背景配置。
5. 使用组件库 List/Table/Form/Toolbar/Menu/Checkbox/EmptyState/ErrorState。
6. 接入键盘上下导航、焦点保持、批量选择、屏幕阅读器语义和性能基线。
7. 增加 manifest/layoutType 对齐、分页、详情读取、打开条目、配置保存、a11y 和 cleanup 测试。

## 5. 验收标准

- 列表布局只消费 Host box runtime，不直接解析 `.box`。
- 大量条目下键盘导航和渲染性能稳定。
- 查看器和编辑引擎中行为一致。
- 通过插件 build/test/lint/validate。

## 6. 验证命令

```bash
cd Chips-BoxLayoutPlugin/list-BLP
npm run lint
npm test
npm run build
npm run validate
```

## 7. 注意事项

- 若组件库缺少高质量 Table/List 能力，先完成组件库任务或登记工单。
- 本任务开发前必须重新核对箱子业务文档、box runtime 契约和当前列表插件代码。
