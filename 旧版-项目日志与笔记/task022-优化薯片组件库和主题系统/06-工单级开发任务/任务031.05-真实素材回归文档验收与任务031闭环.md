# 任务031.05：真实素材回归、文档验收与任务031闭环

## 1. 任务目标

对任务031阅读器应用迁移做最终验收，补齐 EPUB、PDF、TXT、Markdown、FB2、RTF、DOCX/重型格式错误态等真实或最小样本回归、Host 启动链路、配置保存、资源释放、README、项目技术文档、公共契约同步、工作日志、验证记录和后续问题边界。

## 2. 背景

任务031会触及 AppRuntime、Scene、资源打开、阅读格式加载、命令系统、组件库壳层、主题、多语言、焦点、A11y、阅读配置和真实素材。最终阶段必须重新核对当前代码、manifest、测试和正式运行链路，再决定哪些信息应写入 `Chips-BookReader` 项目内部技术文档，哪些属于生态共用技术文档。

## 3. 开发内容

1. 复核 `031.01` 至 `031.04` 的提交、工作日志、验证结果和未闭环边界。
2. 准备或定位真实/最小样本，覆盖 EPUB/EPUB3、PDF、TXT、Markdown、FB2、RTF 和重型格式明确错误态。
3. 补充测试：空启动、打开按钮、拖拽、`targetPath`、`resourceOpen`、`chips.book-card` payload、远程 URL、阅读进度、书签、搜索、偏好保存、窗口恢复和资源释放。
4. 将 `tests/e2e/basic-flow.test.ts` 从占位测试升级为能证明基础流程的真实回归或明确迁入正式 Host smoke。
5. 更新 `Chips-BookReader/README.md`，确保支持矩阵、运行命令、AppRuntime/Scene、命令系统、主题、多语言、A11y 和验证脚本与当前真实代码一致。
6. 更新 `Chips-BookReader/技术文档/02-书籍阅读器实现说明.md`，补齐 AppRuntime、Document Scene、命令、阅读引擎、格式边界、主题/i18n/A11y 和测试矩阵。
7. 如公共资源打开、阅读 payload、格式支持矩阵、模块解析能力或命令契约发生变化，同步 `生态共用技术文档/` 中对应正式规范。
8. 汇总最终验证命令、结果、已登记工单和不属于任务031的后续边界。

## 4. 验收标准

- 任务031所有子任务均有任务文档、工作日志和阶段提交记录。
- 迁移后现有用户可见功能、交互路径、状态流转和数据语义保持不变。
- 阅读器通过正式 Host `resource.open` 链路被唤起，并正确消费 `launchParams.resourceOpen` 与 `chips.book-card` payload。
- 应用层不保存临时资源 URL 或绝对路径作为长期数据。
- 默认主题与暗色主题下阅读体验可读、稳定、可访问。
- README、项目技术文档和必要公共契约描述当前真实代码、manifest、测试和运行链路。
- 未闭环的架构缺口都有问题工单或后续任务说明。
