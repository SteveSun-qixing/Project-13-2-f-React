# 任务031：阅读器应用迁移

## 1. 任务目标

将 `Chips-BookReader` 迁移到新前端框架基线，使它成为电子书、PDF、Markdown、文本和文档类资源的统一阅读应用插件。

## 2. 对应阶段任务

- `05-开发任务方案/任务20-现有应用插件全量迁移.md`
- `05-开发任务方案/任务27-开放项目同化样本工程.md`

## 3. 涉及项目

- `Chips-BookReader`
- `Chips-Host`
- `Chips-SDK`
- `Chips-ComponentLibrary`
- `Chips-ModulePlugin/*`

## 4. 开发内容

1. 重新核对 `manifest.yaml` 中 resource-handler、file-handler、网络权限、配置权限和 surface。
2. 改造为 App/Scene/Document surface 结构，支持空启动、资源启动和文件启动。
3. 将阅读视图、目录、书签、搜索、进度、字体、分页/滚动模式、缩放和设置改为统一 View/Modifier 模型。
4. 阅读格式解析优先走 Host/模块插件正式能力，缺失能力先登记工单，不在应用内复制底层解析基础设施。
5. 使用组件库实现工具栏、侧栏、目录、搜索、弹层、阅读设置和错误状态。
6. 接入主题、阅读安全区、焦点、键盘翻页、a11y、减少动效和多语言。
7. 增加 EPUB、PDF、TXT、Markdown、DOCX 等启动和回归样本。
8. 增加阅读进度、配置保存、窗口恢复、资源释放和错误诊断测试。

## 5. 验收标准

- 迁移后现有用户可见功能、交互路径、使用逻辑、状态流转和数据语义保持不变；本任务只切换到新框架架构与正式生态链路，不做产品行为重设计。
- 阅读器通过正式资源打开链路被 Host 唤起。
- 应用层不保存临时资源 URL 或绝对路径作为长期数据。
- 阅读体验在默认主题和暗色主题下可读、稳定、可访问。
- 可作为外部 Web 阅读项目同化的参考样板。

## 6. 验证命令

```bash
cd Chips-BookReader
npm run lint
npm test
npm run build
npm run validate
```

## 7. 注意事项

- 不新增额外页面分类，阅读器仍是普通应用插件。
- 解析能力不足时登记 Host/模块能力工单，不做临时内置方案。
- 本任务开发前必须重新核对 SwiftUI Document/Navigation/List 模型、阅读器 manifest 和当前代码。

## 8. 子任务拆分

任务031覆盖阅读器 AppRuntime、Document Scene、资源启动、阅读引擎、命令系统、组件库壳层、主题、多语言、焦点、A11y、真实素材和文档闭环。按当前 `Chips-BookReader` 真实工程量，拆为以下 5 个中等颗粒度子任务；子任务已在任务031开始前一次性拆分完成，后续不再机械细拆。如需补充实施细节，直接完善对应子任务文档。

1. `任务031.01-阅读器现状冻结任务拆分与资源契约复核.md`
2. `任务031.02-AppRuntime-Scene-Environment与启动链路迁移.md`
3. `任务031.03-命令系统菜单工具栏快捷键与阅读动作注册.md`
4. `任务031.04-组件库壳层主题i18n焦点键盘与A11y收口.md`
5. `任务031.05-真实素材回归文档验收与任务031闭环.md`

执行原则：

- 先冻结现有用户可见功能、交互路径、状态语义和格式支持矩阵，再迁移框架结构。
- 保持阅读器现有沉浸式阅读体验：空态居中导入，阅读态默认隐藏控制层，点击阅读区后显示临时控制层和抽屉面板。
- 资源启动、文件启动、电子书基础卡片 payload 和远程 URL 入口必须全部纳入 Document Scene/launch context，不改变原有使用逻辑。
- EPUB/PDF/TXT/Markdown/FB2/RTF 当前可渲染链路作为本轮迁移的行为基线；MOBI/AZW/AZW3/DJVU/DOC/DOCX 等重型格式正式解码器缺口复用既有工单093，不在阅读器内追加临时解析器。
- 所有可见文案走 i18n，同步渲染期文案使用组件库 adapter；所有视觉样式走主题 token，阅读背景偏好不得变成第二套主题系统。
- 菜单、工具栏、快捷键和命令面板消费同一组 Host command registry metadata；命令定义只写 i18n key 和 IconDescriptor。
- 每个子任务完成后写入 `07-工作日志` 并提交阶段 Git 记录。
