# 任务016.07：NavigationSplitView Compound 迁移

## 1. 任务目标

把 `NavigationSplitView` 迁移为正式 Compound API，明确它与现有 `ChipsSplitView` 布局原语的职责边界。

## 2. 父任务

- `任务016-组件库复杂组件Compound迁移.md`
- 对应阶段任务：`05-开发任务方案/任务09-复杂组件Compound-API与样式契约.md`

## 3. 涉及项目

- `Chips-ComponentLibrary/packages/components`
- `Chips-ComponentLibrary/packages/theme-contracts`
- `Chips-Host/src/renderer/declarative-ui`
- `Chips-Host/tests/unit`
- `生态共用技术文档/组件库`

## 4. 开发内容

1. 明确 `NavigationSplitView` 与 `ChipsSplitView` 的职责边界，避免导航语义组件和布局原语混写。
2. 为 `NavigationSplitView` 建立 `Root / Sidebar / Content / Detail` Compound API。
3. 如新增独立 scope，补齐 `navigation-split-view` runtime、类型、contract、token、主题包、测试和公共文档。
4. 补齐 Host L8 `StandardCompoundSlotSchemas.NavigationSplitView` 与诊断测试。

## 5. 验收标准

- NavigationSplitView 有明确 scope、parts、types、Host schema 和 contract。
- 导航分栏 role、aria label、两栏/三栏结构和 divider parts 测试覆盖。
- 不把 `split-view` 的通用布局职责改成导航业务职责。
