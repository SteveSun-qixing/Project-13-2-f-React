# 任务056.02：卡片箱子真实服务链路回归

## 1. 任务目标

使用任务056.01冻结的真实 `.card/.box` 素材，扩展 Host、卡片查看器、编辑引擎和箱子布局链路的正式服务回归，确保卡片与箱子不只在少量样本上可用，而是能覆盖真实成品素材集合。

## 2. 背景

任务055已证明少量 `.card/.box` 可通过安装态等价服务路由打开、渲染、编辑器渲染、解包、打包和重新校验。任务056需要扩大到成品测试空间中的真实素材，覆盖富文本、图片、音乐、视频、图书、网页、评分、超链接、组合卡片，以及美食箱子里的条目封面和条目打开。

## 3. 开发内容

1. 复核卡片文件格式规范、箱子文件格式规范、卡片信息与打开契约、箱子布局运行时契约和当前 Host 服务实现。
2. 对正式纳入回归的 `.card` 执行 `card.validate`、`card.readInfo`、`card.renderCover`、`card.render`、`card.renderEditor`、`card.unpack`、`card.pack` 和重新校验。
3. 对正式纳入回归的 `.box` 执行 `box.validate`、`box.inspect`、`box.openView`、`box.renderLayoutFrame`、`box.renderLayoutEditor`、`box.renderEntryCover`、`box.getLayoutInitialQuery`、条目打开和重新校验。
4. 覆盖 `ProductFinishedProductTestingSpace/美食卡片成品` 下的美食卡片集合和 `美食网格箱子.box`。
5. 补强卡片查看器对真实启动参数、真实文档路径和 Host 返回结果的消费断言。
6. 遇到 P0/P1 真实素材缺陷时优先修复；如果属于架构缺口或正式链路缺失，按工单规则登记，不处理用户明确暂缓的发布前人工验收项。

## 4. 验收标准

- 所有纳入正式回归的 `.card` 至少通过读取信息、封面、查看态渲染和校验链路。
- 至少一个真实复合卡片通过编辑器渲染、解包、打包和重新校验。
- `美食网格箱子.box` 通过箱子查看态、编辑态、条目封面和条目打开链路。
- 真实素材失败项记录到任务056报告输入中，P0/P1 已修复或登记。
- 新增测试不依赖源码目录私有捷径，走 Host/SDK/Bridge 正式边界。
