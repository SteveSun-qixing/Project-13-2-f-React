# 任务033.01：图片查看器现状冻结与资源契约复核

## 1. 任务目标

在修改 `Chips-PhotoViewer` 前冻结当前产品行为、启动入口、资源打开上下文、文件处理能力、图片序列 payload 与保存语义，明确本轮迁移只改变架构承载方式，不重设计图片查看器的用户功能和交互逻辑。

## 2. 背景

任务033要求图片查看器迁移到新前端框架基线，并继续作为图片资源查看、缩放、拖拽、保存和资源转换结果预览的正式应用插件。当前项目已经具备 `resource-handler:view:image/*`、`file-handler`、`launchParams.resourceOpen`、`chips.book-card` 图片序列 payload 和基本查看交互，但仍需重新核对公共契约与当前代码是否一致。

## 3. 开发内容

1. 复核根目录 `AGENTS.md`、任务033说明、生态设计原稿中的插件系统、查看器、公共基础层与 SDK/Bridge 设计。
2. 复核公共技术文档中的应用插件开发、资源打开、命令系统、资源图像转换、图像颜色提取、组件库、主题、多语言、A11y 规范。
3. 核对 `Chips-PhotoViewer/manifest.yaml` 的 `type`、`entry`、`runtime.targets`、`ui.surface`、`capabilities`、`permissions` 与正式契约一致性。
4. 梳理当前 `src/App.tsx`、`PhotoViewerStage`、`usePhotoViewerCamera`、`launch-resource`、测试与项目内部文档中已落地功能。
5. 形成启动前勘察草稿与阶段日志，作为后续任务执行基线。

## 4. 验收标准

- 明确图片查看器当前可保留的产品行为：空启动、手动打开、资源打开、文件关联、图片序列、缩放、平移、拖拽、保存、主题和语言跟随。
- 明确后续迁移必须补齐的架构差距：AppRuntime/Scene/Environment、Host command registry、组件库命令消费、主题 token 化样式、A11y 焦点与键盘状态。
- 不修改其他并行任务项目，不引入第三方库，不执行 Git 操作。

## 5. 验证命令

本任务以勘察和文档为主，代码验证进入后续子任务执行。必要时可先运行：

```bash
cd Chips-PhotoViewer
npm test -- --run tests/unit/launch-resource.test.ts tests/unit/image-viewer.test.ts
```

## 6. 并行衔接

本任务完成后进入 `033.02`，所有代码迁移以本任务冻结的行为与契约为准。
