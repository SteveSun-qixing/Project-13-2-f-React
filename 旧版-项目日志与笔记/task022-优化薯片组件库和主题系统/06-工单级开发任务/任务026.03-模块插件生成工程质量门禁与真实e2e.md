# 任务026.03：模块插件生成工程质量门禁与真实 e2e

## 1. 任务目标

补齐模块插件脚手架生成工程的真实质量闭环，使 `chipsdev create module` 生成的工程默认具备 `verify/package` 心智，并能通过开发工作区 Host 安装、启用和 `module.invoke` 实测。

## 2. 范围

- `Chips-Scaffold/chips-scaffold-module/scripts/run-generated-e2e.cjs`
- `Chips-Scaffold/chips-scaffold-module/templates/**/package.json.tpl`
- `Chips-Scaffold/chips-scaffold-module/templates/**/README.md.tpl`
- `Chips-Scaffold/chips-scaffold-module/tests`
- 必要时只读核对 `Chips-SDK/tests/run-cli-create-module-workspace-tests.cjs`
- 必要时只读核对 `Chips-SDK/tests/run-cli-module-invoke-tests.cjs`

## 3. 开发内容

1. 将生成工程 e2e 改为在临时生态根中真实执行 `chipsdev create module <targetDir>`。
2. 生成工程后执行 `npm install` 与 `npm run verify`。
3. 断言 `manifest.entry`、构建产物、`.cpk` 输出和 workspace 注册状态。
4. 在开发工作区安装并启用生成的模块 `.cpk`。
5. 通过 `chipsdev module invoke` 或等价正式 CLI 链路调用生成模块能力。
6. 覆盖同步返回、异步 job、错误路径、取消和 cleanup 基线测试。

## 4. 验收标准

- 生成工程默认脚本包含 `lint/typecheck/test/build/validate/package/verify`。
- 真实 e2e 能证明模块插件可安装、启用并被 Host 正式调用。
- `npm run build`、`npm test`、`npm run test:templates`、`npm run test:e2e` 通过。

## 5. 验证命令

```bash
cd Chips-Scaffold/chips-scaffold-module
npm run build
npm test
npm run test:templates
npm run test:e2e
```

## 6. 注意事项

- 不通过直接修改 `.chips-host-dev` 替代正式 CLI。
- 不复制 Host 模块运行时主实现到 SDK 或脚手架。
