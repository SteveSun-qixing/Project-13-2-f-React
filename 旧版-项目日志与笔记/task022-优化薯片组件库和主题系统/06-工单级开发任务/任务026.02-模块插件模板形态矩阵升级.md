# 任务026.02：模块插件模板形态矩阵升级

## 1. 任务目标

将 `chips-scaffold-module` 从单一通用示例升级为覆盖常见模块形态的模板矩阵，避免后续业务模块把自身特殊实现反推回脚手架。

## 2. 范围

- `Chips-Scaffold/chips-scaffold-module/src`
- `Chips-Scaffold/chips-scaffold-module/templates/module-standard`
- 必要时新增同仓内模块模板目录
- `Chips-Scaffold/chips-scaffold-module/tests`
- `Chips-Scaffold/chips-scaffold-module/scripts/check-templates.cjs`

## 3. 开发内容

1. 重新核对现有五类模块样本：卡片转 HTML、颜色提取、文件转换、HTML 转图片、HTML 转 PDF。
2. 设计并实现可扩展模板选择模型，覆盖纯函数转换、文件转换、图像处理、颜色提取、HTML 渲染等形态。
3. 每类模板均输出正式 manifest、能力契约、输入输出 schema、错误码和最小测试。
4. 强化模板检查，阻断旧身份、未渲染占位符、旧 CLI 文本和生成产物污染。
5. 更新脚手架内部需求文档与技术文档。

## 4. 验收标准

- 新建模块工程可以按模板形态生成不同能力骨架。
- 模板不写死任何现有业务模块 ID 或私有逻辑。
- `npm run build`、`npm test`、`npm run test:templates` 通过。

## 5. 验证命令

```bash
cd Chips-Scaffold/chips-scaffold-module
npm run build
npm test
npm run test:templates
```

## 6. 注意事项

- 不新增技术选型之外的依赖。
- 不把模块业务实现迁移混入脚手架模板升级。
