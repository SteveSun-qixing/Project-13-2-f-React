# 任务030.05：工作区、文件、资源、保存、封面与导出链路收口

## 1. 任务目标

收口编辑引擎的工作区、文件服务、资源生命周期、自动保存、卡片封面、箱子封面、导出和重新打开链路，确保编辑结果始终落到正式 `.card/.box` 文件结构，并通过 Host/SDK/模块能力完成系统操作。

## 2. 背景

编辑引擎是文档生产工具，最重要的质量边界是数据不能丢、资源不能泄漏、导出不能是假进度。历史工单已闭环 YAML、资源 URL、封面、ZIP 导入、导出等关键契约；本任务把这些能力统一纳入新框架运行时与测试矩阵。

## 3. 开发内容

1. 复核 `workspace-service`、`file-service`、`resource-service`、`zip-service`、`card-service`、封面工具和导出面板。
2. 确保文件读写、目录创建、资源导入、ZIP 导入、TIFF 转 PNG、导出转换、打开系统路径等能力只通过 SDK/Bridge/模块能力调用。
3. 收口卡片创建、打开、保存、另存、导出、重新打开、重命名、删除、工作区同步。
4. 收口资源生命周期：待导入资源、待删除资源、引用收集、保存后清理、预览期间稳定资源 URL。
5. 收口卡片封面与箱子封面：正式入口分别为 `.card/cover.html` 与 `.box/cover.html`，不使用本地占位视图冒充封面。
6. 收口导出链路：`.card`、HTML、PDF、图片等导出均必须真实落盘并通过正式能力回报进度和结果。
7. 补充保存、导出、封面、资源和工作区同步测试。

## 4. 验收标准

- 自动保存、显式保存和退出前 flush 不丢失合法编辑结果。
- 资源导入/删除不会产生未引用残留或提前删除仍被引用资源。
- 导出链路不保留假进度、占位成功或前端私有转换旁路。
- 封面显示和编辑使用正式 Host/SDK 链路，不手写第二套封面解析。
- 重新打开保存后的 `.card/.box` 与当前编辑状态一致。
