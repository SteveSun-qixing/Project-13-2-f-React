# 任务033：图片查看器应用迁移

## 1. 任务目标

将 `Chips-PhotoViewer` 迁移到新前端框架基线，使它成为图片资源查看、缩放、拖拽、保存和资源转换结果预览的正式应用插件。

## 2. 对应阶段任务

- `05-开发任务方案/任务20-现有应用插件全量迁移.md`
- `05-开发任务方案/任务23-模块插件能力契约与运行时迁移.md`

## 3. 涉及项目

- `Chips-PhotoViewer`
- `Chips-Host`
- `Chips-SDK`
- `Chips-ComponentLibrary`
- `Chips-ModulePlugin/Chips-ColorPicker`
- `Chips-BaseCardPlugin/image-BCP`

## 4. 开发内容

1. 重新核对 `manifest.yaml` 中 image resource-handler、file-handler、权限和保存 fallback。
2. 改造为 App/Scene/Document surface 结构，支持资源打开、文件打开和空启动。
3. 用组件库重构工具栏、缩放控件、适应窗口、实际大小、旋转、保存、信息面板和错误态。
4. 图片资源读取、TIFF 转 PNG、缩略图、颜色提取等能力通过 Host/模块正式接口调用。
5. 与图片基础卡片 `openResource` 和资源解析链路对齐。
6. 接入手势：拖拽平移、滚轮缩放、双击缩放、键盘导航、焦点管理和 a11y。
7. 接入主题、多语言、减少动效和高对比度状态。
8. 增加 PNG/JPG/WEBP/GIF/SVG/AVIF、错误图片、超大图、资源释放和保存回归测试。

## 5. 验收标准

- 迁移后现有用户可见功能、交互路径、使用逻辑、状态流转和数据语义保持不变；本任务只切换到新框架架构与正式生态链路，不做产品行为重设计。
- 图片查看器通过正式资源打开链路运行。
- 不在应用层复制 Host 图像转换和颜色提取基础设施。
- 图片交互不破坏窗口焦点、键盘和 a11y。
- 与图片基础卡片的资源打开体验一致。

## 6. 验证命令

```bash
cd Chips-PhotoViewer
npm run lint
npm test
npm run build
npm run validate
```

## 7. 注意事项

- SVG 等潜在风险资源必须遵守 Host 安全策略。
- 本任务开发前必须重新核对 SwiftUI gestures/accessibility 能力、资源图像转换模块和当前查看器代码。
