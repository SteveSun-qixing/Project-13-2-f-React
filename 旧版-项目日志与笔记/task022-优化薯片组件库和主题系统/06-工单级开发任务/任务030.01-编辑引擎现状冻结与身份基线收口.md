# 任务030.01：编辑引擎现状冻结与身份基线收口

## 1. 任务目标

在正式迁移 `Chips-EditingEngine` 代码前，冻结当前用户可见功能、工程身份、启动契约、测试基线和历史工单风险，并清理仍残留的脚手架/模板身份，确保后续迁移以真实编辑引擎为基准。

## 2. 背景

任务030是复杂生产力应用迁移，不允许边迁移边改变产品行为。子代理勘察确认任务主体是 `Chips-EditingEngine`，`Chips-RichTextEditor` 是相关但独立的单文档富文本应用。历史工单046仍提示 `config/app-config.ts`、独立 `i18n/*.json`、`src/components/ExamplePanel.tsx`、`template.json` 可能存在模板残留，本子任务先收口这些身份风险。

## 3. 开发内容

1. 复核 `Chips-EditingEngine/AGENTS.md`、任务030主文档、编辑引擎设计原稿、公共编辑运行时标准、应用插件开发规范、命令系统契约、主题与多语言规范。
2. 复核 `manifest.yaml`、`package.json`、`chips.config.mjs`、README、应用图标说明、项目内历史日志和当前测试。
3. 冻结当前用户可见功能：工作区打开、默认工具窗口、卡箱库、卡片窗口、箱子窗口、编辑面板、设置弹窗、拖拽创建/导入、封面、导出、主题语言切换。
4. 清理或归档仍未使用且误导工程身份的模板残留；禁止直接删除历史文件，确需移除时移入就近 `归档/`。
5. 确认工单035、037、039、040、064、079、080、092、068等已闭环内容可作为当前基线；确认工单046剩余风险已在本任务收口。
6. 建立任务030验证基线，记录当前 `lint/test/build/validate` 与重点专项测试现状。
7. 写入 `07-工作日志`，记录现状冻结、清理结果、验证结果和后续子任务注意事项。

## 4. 验收标准

- 任务030主体项目、相关项目边界和不可改变的用户行为已明确。
- README、manifest、运行配置、i18n 顶层身份和测试断言不再出现脚手架占位身份。
- 工单046剩余模板残留已修复或按问题工单规则登记后停止相关错误口径传播。
- 后续迁移可基于一份明确的现状清单推进，不依赖早期任务001旧迁移清单中的过期描述。

```

```
