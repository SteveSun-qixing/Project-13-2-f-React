# 任务023.01：应用模板 vNext 目录结构与质量脚本

## 1. 任务目标

先把 `chips-scaffold-app` 生成工程从旧的单文件示例结构升级为 vNext 应用基线目录，让后续 App/Scene、命令、视图和预览能力有稳定落点。

本任务只处理目录结构、工程脚本、模板身份清理和质量扫描，不完整展开所有交互样板。

## 2. 范围

- `Chips-Scaffold/chips-scaffold-app/templates/app-standard`
- `Chips-Scaffold/chips-scaffold-app/scripts/check-templates.mjs`
- `Chips-Scaffold/chips-scaffold-app/scripts/run-generated-e2e.mjs`
- `Chips-Scaffold/chips-scaffold-app/tests/template-engine.test.ts`

## 3. 开发内容

1. 生成 `src/app/`、`src/scenes/`、`src/views/`、`src/testing/`、`src/preview/` 目录结构。
2. 根入口改为薄入口：`src/App.tsx` 只导出正式 `AppRoot`。
3. `package.json` 默认补齐 `typecheck`、`preview:smoke`、`quality:gate`、`verify`。
4. `tests/e2e` 从空断言升级为预览报告 smoke。
5. 模板检查补齐：
   - 禁止生成工程泄露 `app-standard`、`ExamplePanel` 等模板身份；
   - 禁止源码 inline style；
   - 检查 vNext 目录、脚本和预览 smoke；
   - 继续禁止旧 Bridge、Electron、Node 直连。

## 4. 验收标准

- 生成工程具备 vNext 应用目录骨架。
- 生成工程默认可执行 `npm run verify`。
- 模板不泄露脚手架身份为应用身份。
- 质量门禁能捕获缺失目录、缺失脚本、空 e2e、inline style 与旧直连模式。

## 5. 验证命令

```bash
cd Chips-Scaffold/chips-scaffold-app
npm run build
npm test
npm run test:templates
npm run test:e2e
```
