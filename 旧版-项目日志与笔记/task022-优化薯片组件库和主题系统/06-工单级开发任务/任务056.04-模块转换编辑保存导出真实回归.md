# 任务056.04：模块转换、编辑保存与导出真实回归

## 1. 任务目标

使用真实卡片、箱子、网页和媒体素材验证模块插件能力、编辑引擎保存链路和导出链路，确认 CardToHTML、HtmlToImage、HtmlToPDF、FileConversion、ColorPicker 等模块能服务真实素材场景。

## 2. 背景

任务046到任务050已迁移模块插件，任务055已验证模块能力发现、调用、job、取消和 provider 生命周期。任务056需要把模块能力放回真实素材场景，证明转换结果、编辑保存和导出结果可被后续应用继续消费。

## 3. 开发内容

1. 复核模块能力契约、文件转换能力契约、资源图像转换契约、图像颜色提取模块能力契约和当前模块插件实现。
2. 使用真实 `.card` 验证 CardToHTML 转换输入、输出 HTML、资源引用和错误诊断。
3. 使用真实 HTML 或 CardToHTML 输出验证 HtmlToImage、HtmlToPDF 转换链路。
4. 使用真实图片、音频、视频或网页包验证 FileConversion 的正式支持范围与失败诊断。
5. 使用真实图片或卡片封面验证 ColorPicker/颜色提取能力。
6. 结合编辑引擎当前真实素材测试，验证至少一个真实卡片的编辑器渲染、保存、导出和重新打开链路。
7. 如果真实素材暴露模块契约缺口，优先修复；如属于生态架构缺陷，登记工单并明确后续责任边界。

## 4. 验收标准

- CardToHTML、HtmlToImage、HtmlToPDF、FileConversion、ColorPicker 至少完成真实素材输入的自动化或可复现实测记录。
- 模块调用走 Host 模块服务与正式 provider，不跨服务直接 import。
- 编辑保存导出链路生成的结果能被重新读取或被下一步模块消费。
- 失败项包含素材路径、能力 ID、输入摘要、错误码和复现命令。
- 不引入临时转换脚本替代正式模块能力。

依赖 `056.01` 的素材清单。可与 `056.02`、`056.03` 并行推进，但最终结果必须在 `056.05` 汇总。

已完成实现与验证准备。

## 8. 本轮实现记录（2026-05-26）

### 8.1 自动化覆盖

- 新增 `Chips-ModulePlugin/tests/real-materials.ts` 作为模块插件真实素材测试工具，统一从当前 worktree 的 `ProductFinishedProductTestingSpace` 解析真实素材，不硬编码旧工作区路径。
- `converter.card.to-html/convert`：使用真实 `富文本基础卡片.card`，校验 ZIP Store 结构、真实富文本/图片/音乐资源清单、Host `card.render` 调用、资源离线重写、`conversion-manifest.json` 和导出 HTML 结构。
- `converter.html.to-image/convert`：使用真实 `昙花/index.html` 派生正式目录态 HTML 中间产物，补齐 `conversion-manifest.json` 后验证 Host `platform.renderHtmlToImage` 调用、诊断输出和最终图片提交口径。
- `converter.html.to-pdf/convert`：使用真实 `昙花/index.html` 派生正式目录态 HTML 中间产物，验证 Host `platform.renderHtmlToPdf` 调用、等待参数、PDF 输出摘要和上游 manifest 诊断延续。
- `converter.file.convert/convert`：使用真实 `富文本基础卡片.card` 验证 `card -> image` 编排流水线，确认 `converter.card.to-html -> converter.html.to-image` 均通过 `ctx.module.invoke` 调用；同时验证真实图片、音频、视频、网页 ZIP 当前不在首版正式支持矩阵时返回结构化 `CONVERTER_INPUT_INVALID`，且不会误触发下游 provider。
- `image.color.pick/pick`：使用真实 `图片.jpg` 验证 Host `file.stat/file.read` 路径、JPEG 解码、调色板、背景色/强调色和采样诊断。

### 8.2 修复项

- 修正 `Chips-HtmltoPDF-Plugin` 对 CardToHTML 上游 manifest 的读取口径：优先读取 `source.requestedLocale` 与 `source.requestedThemeId`，再回退旧字段 `locale/themeId`，保证真实 CardToHTML -> PDF 链路不会丢失主题和语言诊断。

### 8.3 编辑保存与导出边界

- 本轮未修改 `Chips-EditingEngine`，原因是该目录存在既有 WIP 且本任务明确要求尽量避开。当前 056.04 已在模块导出侧补强真实素材回归，后续编辑引擎导出入口可复用这些模块级断言继续做端到端保存/导出/重开验证。
