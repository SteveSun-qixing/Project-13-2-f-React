# 任务030：编辑引擎应用迁移

## 1. 任务目标

将 `Chips-EditingEngine` 迁移到新前端框架基线，形成薯片生态最重要的生产力应用样板，统一卡片创作、箱子编辑、基础卡片装配、资源、保存、预览、主题和多语言链路。

## 2. 对应阶段任务

- `05-开发任务方案/任务20-现有应用插件全量迁移.md`
- `05-开发任务方案/任务21-基础卡片插件全量迁移.md`
- `05-开发任务方案/任务22-箱子布局插件全量迁移.md`

## 3. 涉及项目

- `Chips-EditingEngine`
- `Chips-RichTextEditor`（相关但独立的后续应用，本任务只作为边界参考，不作为任务030主体）
- `Chips-Host`
- `Chips-SDK`
- `Chips-ComponentLibrary`
- `Chips-BaseCardPlugin/*`
- `Chips-BoxLayoutPlugin/*`
- `生态共用技术文档/组件库/08-编辑引擎基础卡片装配与编辑运行时标准.md`

## 4. 开发内容

1. 重新核对 `manifest.yaml`、权限、当前服务层、基础卡片装配、箱子链路、资源生命周期和测试。
2. 改造应用入口为 App/Scene/Document/Window/surface/commands 结构。
3. 将主工作区、无限画布、工具窗口、文件管理、卡箱库、编辑面板、箱子面板统一纳入 View/Modifier 与 Environment 模型。
4. 继续遵守官方编辑引擎编辑态本地运行时特例，不复制到其他应用。
5. 通过已安装并启用基础卡片插件的 `basecardDefinition` 建立注册表，不按具体 cardType 写主流程硬编码。
6. 通过布局插件 `layoutDefinition` 加载箱子预览和箱子配置编辑，不私建箱子布局运行时。
7. 重构命令系统：新建、打开、保存、导入、导出、撤销、重做、搜索、设置、布局切换、预览。
8. 接入统一拖拽、焦点、快捷键、a11y、主题、语言、动效和性能诊断。
9. 补充真实素材回归：卡片创建、编辑、保存、导出、重新打开、资源增删、箱子嵌套和布局切换。

## 5. 验收标准

- 迁移后现有用户可见功能、交互路径、使用逻辑、状态流转和数据语义保持不变；本任务只切换到新框架架构与正式生态链路，不做产品行为重设计。
- 编辑引擎没有临时旁路运行时、无主流程 cardType 硬编码分支。
- 基础卡片和箱子布局插件能独立安装、启用、禁用并被编辑引擎正确消费。
- 自动保存、资源生命周期、预览和导出链路稳定。
- 编辑引擎能作为新框架复杂应用的最高质量样板。

## 6. 验证命令

```bash
cd Chips-EditingEngine
npm run lint
npm test
npm run build
npm run validate
```

## 7. 注意事项

- 编辑引擎是正式复杂应用，不允许做简化版迁移。
- 影响公共编辑契约的内容必须同步到生态共用技术文档。
- 本任务开发前必须重新核对 SwiftUI App/Scene/Document/commands 模型、编辑引擎设计原稿和当前真实代码。

## 8. 串并行执行策略

任务030覆盖编辑引擎完整生产力应用，采用“串行骨架 + 并行模块”的推进方式：

1. `030.01` 必须先行，冻结现状、清理身份/模板残留、确认工单046剩余风险与真实验证基线。
2. `030.02` 是主线骨架，先建立 AppRuntime / Scene / Environment / surface / launch context 结构，后续模块在此基础上并行。
3. `030.03`、`030.04`、`030.05` 可在 `030.02` 的运行时入口稳定后分块并行：
   - `030.03` 处理命令、菜单、工具栏、快捷键和历史命令接入；
   - `030.04` 处理基础卡片装配、编辑会话、插件注册表和资源桥；
   - `030.05` 处理工作区、文件、资源生命周期、自动保存、封面和导出。
4. `030.06` 在 `030.04/030.05` 基本稳定后推进箱子文档、布局预览、箱子编辑面板和嵌套导入。
5. `030.07` 对主工作区、无限画布、工具窗口、拖拽、焦点、主题、多语言与 a11y 做全局收口，可与 `030.06` 后半段交错推进，但最终必须统一验证。
6. `030.08` 做真实素材回归、内部/公共文档、任务030闭环和最终提交验收。

后续使用子代理时，优先把可独立验证且写入范围清晰的模块分给子代理；不再机械拆成大量小任务文档。
