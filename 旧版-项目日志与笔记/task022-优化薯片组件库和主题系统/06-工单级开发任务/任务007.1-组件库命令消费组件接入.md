# 任务007.1：组件库命令消费组件接入

## 1. 任务目标

让组件库中的 Toolbar、Menu、CommandPalette、ContextMenu、Shortcut 相关组件消费 Host command registry，而不是各自维护动作模型。

## 2. 插入原因

任务007已建立 Host `command.*` 服务域、Bridge 子域、SDK `client.command.*` 与公共命令系统契约。组件库消费层属于后续 UI 组件落地工作，不应混入 Host registry 基础提交，但必须在任务014/015/016前明确收口。

## 3. 涉及项目

- `Chips-ComponentLibrary/packages/components`
- `Chips-SDK`
- `生态共用技术文档/协议与契约/13-命令系统契约.md`

## 4. 开发内容

1. `ChipsToolbar / ChipsToolbarItem` 支持从 command view 渲染动作。
2. `ChipsMenuBar / ChipsContextMenu` 支持从 `menuPlacement` 分组生成菜单项。
3. `ChipsCommandPalette` 支持从 `command.list({ source: "palette" })` 获取命令。
4. 命令图标统一走 `ChipsIcon + IconDescriptor`。
5. 命令文案只消费 i18n key，不接收 raw title/description。
6. disabled/hidden/checked 状态消费 `CommandView.diagnostic` 与 state。

## 5. 验收标准

- 同一个 command 可被 Toolbar、Menu、Shortcut、CommandPalette 复用。
- 组件不直接绑定业务函数，所有触发走 `command.invoke`。
- a11y label 通过 i18n key 解析。
- 样式只走主题 token 与 component contract。

## 6. 验证命令

```bash
cd Chips-ComponentLibrary
npm run verify
npm run quality:gate
```
