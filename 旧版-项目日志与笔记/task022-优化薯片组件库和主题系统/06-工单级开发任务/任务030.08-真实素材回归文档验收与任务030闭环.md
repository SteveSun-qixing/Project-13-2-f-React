# 任务030.08：真实素材回归、文档验收与任务030闭环

## 1. 任务目标

对任务030编辑引擎应用迁移做最终验收，补齐真实素材回归、项目 README、必要内部技术文档、公共契约同步、工作日志、验证记录和后续问题边界，确保编辑引擎成为复杂应用新框架最高质量样板。

## 2. 背景

任务030覆盖卡片创作、基础卡片装配、编辑会话、箱子编辑、资源、保存、导出、工作台、主题、多语言和命令系统。最终阶段必须重新核对当前代码、manifest、测试和正式运行链路，再决定哪些信息应沉淀到项目内部文档或生态共用技术文档。

## 3. 开发内容

1. 复核 `030.01` 至 `030.07` 的提交、工作日志、验证结果和未闭环边界。
2. 补充真实素材回归：新建卡片、编辑富文本/图片/网页等基础卡片、资源导入删除、保存、导出、重新打开、箱子嵌套、布局切换和主题语言切换。
3. 更新 `Chips-EditingEngine/README.md`，确保项目说明、运行方式、应用结构、公共边界和验证脚本与当前真实代码一致。
4. 如存在项目内部技术文档，补齐 AppRuntime、Scene、基础卡片运行时、编辑会话、箱子链路、命令、主题、i18n、资源和测试矩阵。
5. 如公共编辑契约、SDK、基础卡片装配、箱子 runtime、命令、主题或多语言链路发生变化，同步 `生态共用技术文档/` 中对应正式规范。
6. 汇总最终验证命令、结果、已登记工单和不属于任务030的后续边界。
7. 执行最终验证并提交闭环记录。

## 4. 验收标准

- 任务030所有子任务均有任务文档、工作日志和阶段提交记录。
- README 与内部技术文档描述当前真实代码、manifest、测试和运行链路。
- 公共生态信息已同步到 `生态共用技术文档/`，项目内部实现细节留在 `Chips-EditingEngine` 项目内。
- 未闭环架构缺口都有问题工单或后续任务说明。
- 编辑引擎最终验证通过，必要时 Host/SDK/组件库/基础卡片/布局插件相关验证同步通过。

## 5. 验证命令

```bash
cd Chips-EditingEngine
npm run lint
npm test
npm run build
npm run validate
```

视最终改动范围补跑：

```bash
cd Chips-SDK
npm test

cd ../Chips-Host
npm test

cd ../Chips-ComponentLibrary
npm run verify
```

## 6. 后续衔接

任务030闭环后，按顺序进入后续应用迁移任务。若 `Chips-RichTextEditor` 被排入后续应用迁移，应单独创建对应任务并复用任务029/030沉淀的 AppRuntime、命令、主题、i18n 和验证模式。
