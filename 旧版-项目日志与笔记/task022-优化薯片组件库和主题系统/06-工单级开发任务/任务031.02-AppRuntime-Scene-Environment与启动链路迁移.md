# 任务031.02：AppRuntime、Scene、Environment 与启动链路迁移

## 1. 任务目标

将 `Chips-BookReader` 从旧单体 `src/App.tsx` 入口迁移到应用脚手架 vNext 的 App/Scene/surface/Environment 架构，同时保持任务031.01冻结的空启动、文件启动、资源启动、电子书基础卡片 payload、远程 URL 和阅读状态语义不变。

## 2. 背景

当前 `src/App.tsx` 同时承担 SDK client 创建、Bridge 事件订阅、主题、语言、启动上下文解析、文件/资源读取、远程 URL 下载、书籍加载、章节渲染和反馈状态。新框架要求形成 `AppRoot`、`AppProviders`、`AppRuntimeProvider`、`AppShell`、`scene-registry`、`runtime/`、`scenes/` 等分层，让阅读器按照 SwiftUI `App / Scene / DocumentGroup / Environment` 心智运行。

## 3. 开发内容

1. 新建 `src/app/AppRoot.tsx`、`AppProviders.tsx`、`AppRuntimeProvider.tsx`、`AppShell.tsx`、`scene-registry.ts`。
2. 新建 `src/runtime/chips-client.ts`、`launch-context.ts`、`environment-client.ts`、`theme-runtime.ts`，集中创建 SDK client、读取 launch context、适配 Environment client 和主题快照。
3. 使用 `ChipsEnvironmentProvider` 注入 client、theme、locale、surface、launchContext、permissions 和 diagnostics。
4. 将阅读器状态建模为明确 scene：空启动 scene、阅读文档 scene、错误/不可渲染文档 scene；Document Scene 必须携带资源来源、文件名、MIME、标题和 payload 上下文。
5. 将 `src/App.tsx` 收敛为轻量 re-export，真实业务入口迁入 AppRuntime/Scene。
6. 将旧 `useChipsClient` 和 `useChipsBridge` 的职责收口到 runtime 层；如仍需事件订阅，优先通过 SDK client/events 或 Environment provider。
7. 补充 AppRuntime、launch context、surface fallback、资源目标归一、启动只处理一次和语言/主题初始化测试。

## 4. 验收标准

- `src/App.tsx` 不再承载真实业务运行时。
- SDK client 不在多个业务组件或 hook 中重复创建。
- 空启动、文件选择、拖拽、`targetPath`、`resourceOpen`、`chips.book-card` payload 和远程 URL 入口行为与任务031.01冻结结果一致。
- 主题和语言通过 Environment/Theme provider 统一进入 React 树。
- 不直接访问 Electron/Node 私有能力，不新增第三方库。

## 5. 验证命令

```bash
cd Chips-BookReader
npm run lint
npm test -- --run tests/unit/app.test.tsx tests/unit/launch-resource.test.ts
npm run build
```

视改动范围补跑完整 `npm test` 与 `npm run validate`。
