# 任务032.03：命令系统、播放队列与媒体动作接入

## 1. 目标

将音乐播放器的播放动作、文件打开、保存、快进、音量、静音、循环和队列动作接入 Host command registry，并把单曲播放会话升级为可表达播放队列的正式模型。

## 2. 范围

- `Chips-MusicPlayer/manifest.yaml`
- `Chips-MusicPlayer/src/commands/**`
- `Chips-MusicPlayer/src/app/AppRuntimeProvider.tsx`
- `Chips-MusicPlayer/src/hooks/useMusicPlayerController.ts`
- `Chips-MusicPlayer/src/components/MusicPlayerStage.tsx`
- `Chips-MusicPlayer/src/utils/music-player.ts`
- `Chips-MusicPlayer/i18n/*.json`
- 相关单元测试

## 3. 开发内容

1. 补齐 command 权限声明：`command.read / command.write / command.invoke`。
2. 定义稳定命令 ID、i18n key、handlerId、图标、快捷键、菜单/工具栏 placement。
3. 通过 SDK `client.command.register / onInvoked / setState` 接入 Host 命令系统，不把业务函数传给 Host。
4. 将文件选择和拖放中多首音频归一为播放队列；单曲仍是队列长度为 1 的普通状态。
5. 接入上一首 / 下一首 / 播放暂停 / 快进快退 / 音量 / 静音 / 循环 / 打开文件 / 保存副本命令。
6. 保持原有键盘语义，同时让 Host 快捷键、菜单、工具栏、命令面板共享同一 command metadata。

## 4. 验收标准

- 命令定义不包含 `title / description / ariaLabel` 原始文案字段。
- 命令权限已在 manifest 中声明。
- command handler 由插件侧注册和消费，Host 只保存 metadata。
- 多文件打开时可建立队列，上一首 / 下一首按队列移动。
- 命令状态会根据当前是否有曲目、是否可保存、是否有前后曲目更新。
