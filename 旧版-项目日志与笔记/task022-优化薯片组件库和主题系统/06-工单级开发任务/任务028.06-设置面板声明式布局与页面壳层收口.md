# 任务028.06：设置面板声明式布局与页面壳层收口

## 1. 任务目标

将 `Chips-EcoSettingsPanel` 的页面组织继续向组件库正式布局原语、统一页面结构和主题 token 收敛，降低设置面板内部手写壳层样式的维护成本。

## 2. 背景

任务028要求使用 View/Stack/Grid/Form/List 等统一声明式布局组织设置页，不保留手写页面壳层样式。当前设置面板已经使用组件库控件和共享 UI 封装，但仍存在较多项目内页面结构 class 与手写 CSS。028.06 的目标是做架构收口，不改变现有用户功能、交互路径和数据语义。

## 3. 开发内容

1. 复核组件库当前公开的布局原语、系统 UX 组件和设置面板现有共享 UI。
2. 将重复页面结构沉淀到设置面板内部共享组件，或直接迁移到组件库正式布局原语。
3. 收敛治理列表、卡片网格、状态摘要、诊断摘要和命令入口区域的页面组合方式。
4. 清理仅为旧壳层存在的样式，保留必要的项目级布局 glue code，所有颜色、间距、圆角和状态表达继续走主题 token。
5. 补齐响应式、窄屏菜单、长文案换行和按钮区域稳定尺寸验证。
6. 更新页面结构相关技术文档和测试策略。

## 4. 验收标准

- 现有主题、语言、插件、组件展示、主题诊断、预览质量入口的功能与使用逻辑不变。
- 页面结构复用度提升，不再为同类区域重复编写分散壳层样式。
- 不引入新第三方 UI 或布局库。
- 所有新增/保留视觉值均使用主题 token 或组件库正式样式接口。
- `Chips-EcoSettingsPanel npm run verify` 通过。

## 5. 验证命令

```bash
cd Chips-EcoSettingsPanel
npm run verify
```

如改动影响页面响应式布局，需要补充浏览器截图或静态渲染断言。
