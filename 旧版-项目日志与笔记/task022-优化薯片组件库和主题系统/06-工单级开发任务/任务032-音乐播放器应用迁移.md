# 任务032：音乐播放器应用迁移

## 1. 任务目标

将 `Chips-MusicPlayer` 迁移到新前端框架基线，使它成为音频资源打开、播放控制、歌词、队列和媒体状态的正式应用样板。

## 2. 对应阶段任务

- `05-开发任务方案/任务20-现有应用插件全量迁移.md`
- `05-开发任务方案/任务23-模块插件能力契约与运行时迁移.md`

## 3. 涉及项目

- `Chips-MusicPlayer`
- `Chips-Host`
- `Chips-SDK`
- `Chips-ComponentLibrary`
- `Chips-ModulePlugin/*`
- `Chips-BaseCardPlugin/music-BCP`

## 4. 开发内容

1. 重新核对 `manifest.yaml` 中音频 resource-handler、file-handler、权限和保存 fallback。
2. 改造为 App/Scene/Document surface 结构，支持资源打开、文件打开和播放队列启动。
3. 用组件库重构播放条、进度条、音量、播放队列、歌词、封面、错误态、加载态和设置。
4. 音频资源读取、封面解析、格式转换、TIFF 转 PNG 等能力优先走 Host/模块正式接口。
5. 与音乐基础卡片的 `openResource` 链路对齐，确保查看态点击音乐资源可以交给播放器处理。
6. 接入命令和快捷键：播放/暂停、上一首、下一首、快进、音量、循环、随机、打开文件。
7. 接入主题、动效、焦点、媒体键、a11y 和多语言。
8. 增加音频格式、资源路由、歌词、封面、播放状态和 cleanup 回归测试。

## 5. 验收标准

- 迁移后现有用户可见功能、交互路径、使用逻辑、状态流转和数据语义保持不变；本任务只切换到新框架架构与正式生态链路，不做产品行为重设计。
- 音乐播放器可被 Host 资源打开链路和音乐卡片正式唤起。
- 不在播放器内复制宿主级图像转换或资源转换基础设施。
- 播放控件、状态、快捷键和 a11y 达到组件库统一质量。
- 默认主题与暗色主题下媒体界面一致可用。

## 6. 验证命令

```bash
cd Chips-MusicPlayer
npm run lint
npm test
npm run build
npm run validate
```

## 7. 注意事项

- 应用插件只负责播放界面和业务编排，底层通用处理能力应沉到 Host 或模块插件。
- 本任务开发前必须重新核对 SwiftUI media control 相关控件、资源图像转换设计和当前播放器代码。
