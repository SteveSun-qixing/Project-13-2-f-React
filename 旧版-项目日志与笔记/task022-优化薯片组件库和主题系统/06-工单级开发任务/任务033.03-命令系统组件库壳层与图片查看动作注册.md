# 任务033.03：命令系统、组件库壳层与图片查看动作注册

## 1. 任务目标

将图片查看器的打开、保存、上一张、下一张、放大、缩小、适应窗口、实际大小等用户动作接入 Host command registry，并使用组件库命令消费组件承载工具栏和菜单入口。

## 2. 背景

当前 `PhotoViewerStage` 内部直接渲染私有按钮并绑定业务回调。新框架要求菜单、工具栏、快捷键、命令面板和上下文入口共享同一组 command metadata；文案只能使用 i18n key，图标使用 `IconDescriptor`，执行入口由 Host `command.invoke` 调度，插件本地根据 `handlerId` 执行业务 handler。

## 3. 开发内容

1. 在 `manifest.yaml` 补齐 `command.read`、`command.write`、`command.invoke` 权限，并保留资源、文件、平台、主题、多语言权限。
2. 新建 `src/commands/photo-viewer-commands.ts`，集中定义稳定 command id、handlerId、titleKey、descriptionKey、ariaLabelKey、IconDescriptor、permission、menuPlacement、toolbarPlacement、shortcut 与初始状态。
3. 新建 `usePhotoViewerCommands()`，通过 `createCommandAdapter(client)` 注册、注销、监听 `command.invoked` 并触发本地 handler。
4. 将打开、保存、上一张、下一张、放大、缩小、适应窗口、实际大小统一接入命令系统；命令 enabled 状态需跟随当前是否有图片、是否正在保存、是否处于序列边界。
5. 使用 `ChipsCommandProvider`、`ChipsToolbar`、`ChipsMenuBar` 承载命令入口；保留底部浮动 dock 的产品位置，不把功能改成全新布局。
6. `PhotoViewerStage` 不再维护第二套私有按钮事实来源，图片视口仍负责拖拽、滚轮、指针和图片加载事件。
7. 补充命令定义、raw 文案禁用、权限、状态更新、事件调度和工具栏渲染测试。

## 4. 验收标准

- command definition 不包含 `title`、`description`、`ariaLabel`、`label` 等原始文案字段。
- 菜单、工具栏和快捷键消费同一组 command metadata。
- 原有底部操作路径、快捷动作语义和图片序列浏览逻辑保持不变。
- 命令关闭、surface 结束或应用卸载时能清理注册。
- 组件库图标、文本和命令消费链路满足主题与 i18n 规范。
