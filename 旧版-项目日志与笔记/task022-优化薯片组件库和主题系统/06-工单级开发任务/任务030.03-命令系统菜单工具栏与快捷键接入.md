# 任务030.03：命令系统、菜单、工具栏与快捷键接入

## 1. 任务目标

将编辑引擎的新建、打开、保存、导入、导出、撤销、重做、搜索、设置、布局切换、预览等动作接入 Host command registry 和组件库命令消费层，形成统一菜单、工具栏、快捷键和命令面板事实来源。

## 2. 背景

当前编辑引擎已有内部 `CommandManager` 管理撤销/重做历史，但这不是 Host command registry。任务030需要保留内部命令历史语义，同时把应用级动作 metadata、权限、菜单/工具栏 placement 和快捷键调度纳入正式命令系统。

## 3. 开发内容

1. 复核 `生态共用技术文档/协议与契约/13-命令系统契约.md` 和组件库命令消费入口。
2. 在 `manifest.yaml` 中补齐必要的 `command.read/write/invoke` 权限，避免注册或调用失败。
3. 新建 `src/commands/`，集中定义稳定 command id、handlerId、i18n key、IconDescriptor、permission、menuPlacement、toolbarPlacement、shortcut 和状态。
4. 将 `WindowMenu`、`Dock`、`HeaderBar`、`LayoutSwitcher`、设置入口、导出入口、撤销/重做等 UI 动作迁移为 command 消费。
5. 区分 Host command registry 与内部撤销/重做 `CommandManager`：Host command 负责调度入口，内部 CommandManager 负责可撤销业务命令栈。
6. 命令启用状态跟随当前工作区、选中卡片/箱子、脏状态、权限和运行时能力变化。
7. 补充命令 metadata、权限、菜单/工具栏、快捷键和调用路径测试。

## 4. 验收标准

- command definition 不包含 raw title/description/ariaLabel 文案，只引用 i18n key。
- 菜单、工具栏、快捷键和命令面板消费同一组 command metadata。
- 撤销/重做仍保持现有业务历史语义，不被 Host command registry 替代。
- 没有绕过 SDK 直接调用私有 `command.*` Bridge action。
- 命令关闭、应用卸载或 surface 结束时能清理注册。
