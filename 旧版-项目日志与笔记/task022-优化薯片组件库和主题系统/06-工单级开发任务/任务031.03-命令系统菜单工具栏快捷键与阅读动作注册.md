# 任务031.03：命令系统、菜单工具栏快捷键与阅读动作注册

## 1. 任务目标

将阅读器的打开文件、打开链接、目录、搜索、书签、偏好、翻页、章节切换、字体与阅读模式等用户动作纳入 Host command registry，使菜单、工具栏、快捷键、命令面板共享同一组 command metadata 和 i18n 文案。

## 2. 背景

当前 `ReaderChrome`、`SourcePanel`、`PreferencesPanel` 和交互层直接绑定业务回调，命令语义散落在 UI 和键盘处理器中。任务031要求阅读器迁移到新框架，必须接入公共命令契约：command definition 只写 i18n key、IconDescriptor、handlerId、scope、permission、menu/toolbar/shortcut placement；真实 handler 仍由插件本地执行。

## 3. 开发内容

1. 复核 `生态共用技术文档/协议与契约/13-命令系统契约.md`、`生态共用技术文档/插件开发/02-应用插件开发.md` 与组件库命令消费入口。
2. 在 `manifest.yaml` 中补齐 `command.read`、`command.write`、`command.invoke` 权限，保留已有 `platform.read`、`network.request`、`config.*` 等业务权限。
3. 新建 `src/commands/`，集中定义稳定 command id、handlerId、titleKey、descriptionKey、ariaLabelKey、IconDescriptor、permission、menuPlacement、toolbarPlacement、shortcut 和状态。
4. 建立 `useBookReaderCommands()`，通过 `createCommandAdapter(client)` 注册、注销、监听 `command.invoked` 并转换到本地 handler。
5. 将现有打开文件、打开 URL、目录、搜索、书签、偏好、上一页/下一页、上一章/下一章、字体增减、阅读模式切换等动作接入命令系统。
6. `ReaderChrome`、空态/导入面板和必要快捷键入口消费 command invocation，不再各自维护第二套动作事实来源。
7. 补充 command metadata、raw 文案禁用、权限、菜单/工具栏 placement、调用上下文和事件调度测试。

## 4. 验收标准

- command definition 不包含 `title`、`description`、`ariaLabel`、`label` 等原始文案字段。
- 菜单、工具栏、快捷键和命令面板消费同一组 command metadata。
- 原有沉浸式控制层和阅读交互不被产品重设计，只替换底层命令调度。
- manifest 权限与实际命令注册/调用路径匹配。
- 命令关闭、surface 结束或应用卸载时能清理注册。
