# 任务034.02：单文档 card 持久化与富文本基础卡片链路收口

## 1. 任务目标

收口 `Chips-RichTextEditor` 的正式 `.card` 数据链路，确保应用只保存“单复合卡片 + 单 `base.richtext` 基础卡片”模型，并继续复用 Host 托管 `card.editorPanel` 和富文本基础卡片正式 schema。

## 2. 开发范围

- `Chips-RichTextEditor/src/lib/card-document.ts`
- `Chips-RichTextEditor/src/lib/card-persistence.ts`
- `Chips-RichTextEditor/src/lib/richtext-card.ts`
- `Chips-RichTextEditor/src/components/EditorFrame.tsx`
- `Chips-RichTextEditor/tests/`
- 必要项目内部技术文档

## 3. 开发内容

1. 复核 `base.richtext` 当前正式 schema、别名和资源收集规则。
2. 确认打开链路只接受单富文本基础卡片复合卡片。
3. 确认保存链路写入：
   - `.card/metadata.yaml`
   - `.card/structure.yaml`
   - `.card/cover.html`
   - `content/<baseCardId>.yaml`
   - 根目录资源文件
4. 强化 `manifest.resources` 重建、资源导入、资源删除和运行时工作目录 cleanup。
5. 保存前增加应用内卡片文件结构校验，确保 `.card/metadata.yaml`、`.card/structure.yaml`、`.card/cover.html`、`content/<baseCardId>.yaml`、根目录资源与 `manifest.resources` 互相一致后才允许打包。
6. 增加或完善以下测试：
   - 新建构建与回读；
   - 非法结构拒绝；
   - 文件型 Markdown 资源保存；
   - 资源清单重建；
   - 启动参数 `.card` 解析。
7. 不在应用层直接 import `richtext-BCP` 源码，不复制基础卡片编辑实现。

## 4. 验收标准

- 输出文件为正式复合 `.card` 文件，不产生私有文档格式。
- `structure.yaml` 中只有一个 `base.richtext` 节点。
- 基础卡片配置与 `richtext-BCP` 当前 schema 保持一致。
- 保存后的 `.card` 能被本应用再次打开。
- 资源路径只保存卡片根目录相对路径，不写入 `blob:`、`data:` 或系统绝对路径。
- 当结构、ID、正文模式、资源路径或资源清单不符合卡片文件结构时，保存流程必须在 `client.card.pack(...)` 前阻断并给出错误状态。
