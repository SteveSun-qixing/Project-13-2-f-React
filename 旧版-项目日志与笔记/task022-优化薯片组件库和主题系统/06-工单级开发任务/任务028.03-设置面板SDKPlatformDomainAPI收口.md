# 任务028.03：设置面板 SDK Platform Domain API 收口

## 1. 任务目标

在任务028主线中，清除 `Chips-EcoSettingsPanel` 运行时服务里残留的裸 `client.invoke("platform.*")` 调用，并把系统文件选择、确认弹窗、消息弹窗、显示路径统一收口到 SDK `client.platform.*` Domain API。

## 2. 背景

任务028启动前复核指出，设置面板主体治理链路已使用 SDK Domain API，但 `SettingsRuntimeService` 仍直接拼接以下 Host action：

- `platform.shellShowItemInFolder`
- `platform.dialogOpenFile`
- `platform.dialogShowConfirm`
- `platform.dialogShowMessage`

开发中进一步发现 `client.platform.openFile()` 的正式类型缺少 `filters`，Host PAL 也未完整转发文件过滤器，导致设置面板如果直接迁移到 SDK API 会丢失插件包扩展名过滤行为。因此本任务先登记工单104并直接修复公共契约缺口，再迁移设置面板调用点。

## 3. 开发内容

1. 登记 `工单104-platformOpenFile文件过滤器契约缺口阻断设置面板DomainAPI收口`。
2. 在 SDK `PlatformDialogFileOptions` 中补充 `filters?: PlatformDialogFileFilter[]`，并导出类型。
3. 在 Host PAL `DialogFileOptions` 中补充 `filters`，Electron `showOpenDialog`、macOS/Linux/Windows fallback 均尽量映射正式扩展名过滤器。
4. 将 `SettingsRuntimeService.revealPath()` 迁移为 `client.platform.shellShowItemInFolder(path)`。
5. 将 `SettingsRuntimeService.openPluginFileDialog()` 迁移为 `client.platform.openFile({ mode: "file-or-directory", allowMultiple: false, filters })`，保留插件包目录或 manifest 文件均可作为输入的治理意图。
6. 将 `showConfirm()` 与 `showMessage()` 分别迁移为 `client.platform.showConfirm()` 与 `client.platform.showMessage()`。
7. 更新设置面板、SDK、Host 聚焦测试。
8. 同步公共 SDK 使用指南、系统接口标准、运行时设置治理接口标准、SDK 内部平台封装文档和设置面板内部运行时文档。

## 4. 验收标准

- `Chips-EcoSettingsPanel/src` 中不再出现裸 `client.invoke("platform.*")`。
- 文件选择器仍保留插件包扩展名过滤口径：`cpk / yaml / yml / json`。
- SDK、Host PAL 和公共文档均能表达 `client.platform.openFile({ filters })` 正式口径。
- 设置面板、SDK、Host 的相关测试通过。
