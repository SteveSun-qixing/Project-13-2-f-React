# 任务029.04：组件库壳层与命令系统接入

## 1. 任务目标

用组件库 vNext 能力重构查看器应用壳层，把打开文件、刷新、诊断、路径信息和后续可扩展操作纳入 Host command registry 与组件库命令消费层。

## 2. 背景

任务029要求使用新组件库重构工具栏、路径栏、错误态、加载态、空态、最近打开、导出入口和诊断面板。但应用迁移统一原则要求保持现有用户可见功能不变。因此本任务只迁移和标准化已有行为；当前不存在的产品入口不得凭空扩展为新功能，可作为命令位、诊断边界或后续工单记录。

## 3. 开发内容

1. 建立 `src/commands/`，定义稳定 command id、i18n key、IconDescriptor、handlerId、menu/toolbar placement。
2. 接入 `ChipsCommandProvider`、`createCommandAdapter(client)`、`ChipsToolbar`、`ChipsMenuBar`、必要时接入 `ChipsCommandPalette`。
3. 将现有“打开文件”动作迁入 command handler，同时保持空态按钮与拖拽入口行为不变。
4. 根据 Host/SDK 真实权限校验补齐 manifest 命令权限，不照抄失效口径。
5. 用组件库正式组件或布局原语收口空态、加载态、错误态、路径栏和诊断入口。
6. 所有命令文案只写 i18n key，不在 command schema 写原始文案。
7. 如发现命令权限口径与 Host 实现冲突，登记问题工单并在任务文档中记录暂行边界。

## 4. 验收标准

- 打开文件动作可通过原空态按钮继续触发，也能由 command registry 统一驱动。
- command definition 不包含 `title`、`description`、`label` 等原始文案字段。
- manifest 权限与当前实际命令注册/调用路径匹配。
- UI 壳层使用组件库正式能力和主题 token，不扩大 inline style。
- 不新增会改变产品使用逻辑的最近打开、导出或诊断行为；如需新增，先登记后续任务。
