# 任务21：基础卡片插件全量迁移

## 1. 任务目标

把所有基础卡片插件迁移到新框架的组件库、主题、i18n、SDK、资源桥和质量门禁上，确保卡片在 Host 通用链路、编辑引擎和查看器中表现一致。

## 2. 迁移范围

基础卡片插件：

- `Chips-BaseCardPlugin/book-BCP`
- `Chips-BaseCardPlugin/hyperlink-BCP`
- `Chips-BaseCardPlugin/image-BCP`
- `Chips-BaseCardPlugin/music-BCP`
- `Chips-BaseCardPlugin/richtext-BCP`
- `Chips-BaseCardPlugin/score-BCP`
- `Chips-BaseCardPlugin/video-BCP`
- `Chips-BaseCardPlugin/webpage-BCP`

## 3. 涉及项目

- `Chips-BaseCardPlugin/*`
- `Chips-ComponentLibrary`
- `ThemePack/*`
- `Chips-SDK`
- `Chips-Host`
- `Chips-EditingEngine`
- `Chips-CardViewer`

## 4. 开发内容

1. 导出契约核对。
   - `renderBasecardView`
   - `renderBasecardEditor`
   - `basecardDefinition`
   - `createInitialConfig`
   - `normalizeConfig`
   - `validateConfig`
   - `collectResourcePaths`
   - cleanup 返回。

2. manifest 对齐。
   - `type: card`。
   - `capabilities.cardTypes`。
   - `entry` 指向构建产物。
   - 权限最小化。

3. 资源桥迁移。
   - `resolveResourceUrl`。
   - `releaseResourceUrl`。
   - `openResource`。
   - `importResource`。
   - `deleteResource`。
   - archive/tiff 等特殊资源能力走正式接口。

4. UI 迁移。
   - 渲染态和编辑态都使用组件库。
   - 不硬编码主题视觉。
   - 文案走 i18n。
   - 图标走 `IconDescriptor` 和 `ChipsIcon`。

5. 主题和 contract。
   - 卡片 shell、编辑面板、错误态、空态、加载态走主题 token。
   - 组件 contract 与 ThemePack 对齐。

6. 测试。
   - 配置归一/校验。
   - 渲染挂载/cleanup。
   - 编辑器 onChange。
   - 资源桥调用。
   - Host 托管渲染 smoke。

## 5. 验收标准

- 所有基础卡片插件 build/test/lint/validate 通过。
- 每个插件导出契约与公共文档一致。
- 编辑引擎和查看器消费同一导出，不写宿主私有分支。
- 资源生命周期 cleanup 完整。
- 主题和 i18n 统一。

## 6. 验证命令

每个基础卡片插件运行：

```bash
npm run lint
npm test
npm run build
npm run validate
```

联动验证：

```bash
cd Chips-Host && npm run build && npm test
cd Chips-EditingEngine && npm run build && npm test && npm run validate
cd Chips-CardViewer && npm run build && npm test && npm run validate
```

## 8. 风险与注意事项

- 不要把基础卡片私有逻辑写进 Host 或编辑引擎。
- 不要绕开 card-root 资源桥直接读文件。
- 不要让编辑态和查看态使用两套不一致配置模型。
