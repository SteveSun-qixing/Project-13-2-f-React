# 任务07：统一布局系统与页面结构原语

## 1. 任务目标

补齐 Chips Layout System，让应用工具界面和普通网页式页面结构都能由同一套布局原语表达。

这里不新增页面应用分类；插件市场详情页、主题展示页、帮助文档、教程、社区、长文阅读、图文混排、卡片网格都应归入统一 `View/Stack/Grid/Form/List` 模型。

## 2. 当前基础

已核对：

- `生态共用技术文档/架构设计/17-L8声明式UI实现与接口细则.md`
- `Chips-Host/src/renderer/declarative-ui/primitives.ts`
- `Chips-ComponentLibrary/packages/components/src/index.js`
- `ThemePack/Chips-default/styles/components/layout-containers.css`
- `ThemePack/*/tokens/layout.json`

当前有基础组件和 layout token，但布局原语不够系统，缺少面向应用和普通页面的统一结构规范。

## 4. 开发内容

1. 定义布局原语清单。
   - `ChipsView`
   - `ChipsBox`
   - `ChipsStack`
   - `ChipsInline`
   - `ChipsGrid`
   - `ChipsSection`
   - `ChipsScrollView`
   - `ChipsSpacer`
   - `ChipsDivider`
   - `ChipsForm`
   - `ChipsList`
   - `ChipsTable`
   - `ChipsSplitView`
   - `ChipsNavigationSplitView`
   - `ChipsPanel`
   - `ChipsToolbarArea`

2. 统一语义属性。
   - `orientation`
   - `gap`
   - `align`
   - `justify`
   - `density`
   - `scroll`
   - `surfaceRole`
   - `landmark`
   - `responsive`
   - `min/max/ideal` 约束。

3. 与 L8/L9 对齐。
   - 每个布局组件映射 L8 节点 type。
   - L9 可校验布局属性和响应式约束。
   - 禁止传入硬编码视觉值作为布局组件主 API。

4. 主题 token 对接。
   - gap、density、container、breakpoint、z-index、scrollbar、focus ring 等进入 layout token。
   - 主题包提供 CSS 变量和默认样式。
   - 不在组件库中硬编码视觉。

5. 响应式与 surface 适配。
   - Desktop window。
   - Web route。
   - Mobile fullscreen/sheet 预留。
   - headless 不承载交互界面。

6. 脚手架使用。
   - 默认模板用布局原语组织页面。
   - 不再手写大段 inline style。

## 6. 验收标准

- 布局原语覆盖常见应用界面和普通页面结构。
- 所有布局组件输出标准 `data-scope/data-part/data-state`。
- 布局组件具备 a11y landmark 支持。
- 主题包提供必要 layout token。
- 脚手架模板使用布局原语替代大段手写 CSS。
- L9 能校验布局属性。

## 9. 风险与注意事项

- 不要创建“内容型页面组件族”。
- 不要把布局组件设计成视觉卡片集合。
- 不要让每个应用继续手写自己的页面 CSS 骨架。
