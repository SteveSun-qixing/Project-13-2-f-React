# 任务20：现有应用插件全量迁移

## 1. 任务目标

把现有应用插件分批迁移到新前端框架默认路径，统一使用 SDK/hooks、App/Scene/surface、统一布局、组件库、主题系统、多语言系统、命令系统、a11y 和质量门禁。

本任务覆盖所有 `type: app` 的现有应用插件。

## 2. 迁移范围

应用插件清单：

- `Chips-EcoSettingsPanel`
- `Chips-CardViewer`
- `Chips-EditingEngine`
- `Chips-BookReader`
- `Chips-MusicPlayer`
- `Chips-PhotoViewer`
- `Chips-RichTextEditor`
- `Chips-VideoPlayer`

## 3. 涉及项目

- 上述应用插件。
- `Chips-SDK`
- `Chips-ComponentLibrary`
- `ThemePack/*`
- `Chips-Host`

## 4. 开发内容

1. 逐个读取项目规则。
   - 读取项目 `AGENTS.md`。
   - 读取 `manifest.yaml`。
   - 读取 `package.json`。
   - 读取源码入口、i18n、主题、测试。

2. manifest 对齐。
   - `type: app`。
   - `runtime.targets`。
   - `ui.surface`。
   - `permissions` 最小化。
   - `ui.launcher` 正确。
   - 资源 handler 能力走正式 `capabilities`。

3. 运行时调用迁移。
   - 用 `chips-sdk` 和官方 hooks 替代直接 Bridge 调用。
   - 禁止直接 Electron/Node。
   - 资源打开走 `client.resource.open`。
   - surface 打开走 `client.surface.open`。
   - 配置、主题、多语言走 Host 正式服务。

4. UI 结构迁移。
   - 使用 `ChipsView/Stack/Grid/Form/List/Section`。
   - 使用组件库控件。
   - 去除硬编码视觉皮肤。
   - 普通页面结构也纳入统一布局模型。

5. 文案迁移。
   - 所有用户可见文案进入 `i18n/zh-CN.json` 和 `i18n/en-US.json`。
   - 组件 title、button、menu、empty state、error message 都不能硬编码。

6. 命令与导航迁移。
   - 统一 command registry。
   - toolbar/menu/shortcut 复用 command。
   - 多窗口/资源处理应用使用 App/Scene/surface 结构。

7. 质量迁移。
   - 补齐 lint/typecheck/test/build/validate。
   - 补 a11y 和关键交互测试。
   - 接入 preview/diagnostics。

## 5. 建议迁移顺序

1. `Chips-EcoSettingsPanel`：治理入口样板。
2. `Chips-CardViewer`：卡片查看链路样板。
3. `Chips-EditingEngine`：复杂生产力应用样板。
4. `Chips-BookReader`：阅读类应用样板。
5. `Chips-MusicPlayer`、`Chips-PhotoViewer`、`Chips-VideoPlayer`：媒体处理类应用。
6. `Chips-RichTextEditor`：编辑器类应用。

## 6. 验收标准

- 所有应用插件通过自身正式脚本。
- 所有应用 manifest 对齐 `surface` 口径。
- 应用代码不直接操作 Electron/Node。
- 应用 UI 文案走 i18n。
- 应用视觉走主题 token 和组件库。
- 至少核心流程通过真实 Host 启动验证。

## 7. 验证命令

每个应用至少运行：

```bash
npm run lint
npm test
npm run build
npm run validate
```

若项目有 `verify`：

```bash
npm run verify
```

全局联动：

```bash
npm run verify:workspace
```

## 9. 风险与注意事项

- 不要一次迁移所有应用；必须按批次验证。
- 不要在应用层保留长期私有组件替代物。
- 如果发现 SDK 或组件库缺口，先登记工单或回到底层任务补齐。
