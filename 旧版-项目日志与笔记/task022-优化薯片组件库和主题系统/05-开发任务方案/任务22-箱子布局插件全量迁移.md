# 任务22：箱子布局插件全量迁移

## 1. 任务目标

把现有箱子布局插件迁移到新框架的布局原语、组件库、主题、i18n、SDK 和 Box Runtime 契约上，确保箱子页面和应用页面共享统一前端质量。

## 2. 迁移范围

箱子布局插件：

- `Chips-BoxLayoutPlugin/grid-BLP`
- `Chips-BoxLayoutPlugin/list-BLP`

## 3. 涉及项目

- `Chips-BoxLayoutPlugin/*`
- `Chips-Host`
- `Chips-SDK`
- `Chips-ComponentLibrary`
- `ThemePack/*`
- `Chips-CardViewer`
- `Chips-EditingEngine`

## 4. 开发内容

1. 导出契约核对。
   - `layoutDefinition`
   - `createDefaultConfig`
   - `normalizeConfig`
   - `validateConfig`
   - `getInitialQuery`
   - `renderView`
   - `renderEditor`
   - cleanup 返回。

2. manifest 对齐。
   - `type: layout`。
   - `layout.layoutType`。
   - `layout.displayName`。
   - 权限基线：通常只需要 `box.read`、`theme.read`、`i18n.read`。

3. Box Runtime 对接。
   - `listEntries`
   - `readEntryDetail`
   - `renderEntryCover`
   - `resolveEntryResource`
   - `readBoxAsset`
   - `prefetchEntries`
   - `openEntry`

4. UI 迁移。
   - 使用统一布局原语。
   - 网格/列表/详情/空态/加载态/错误态走组件库。
   - 不使用固定高度和 overflow hidden 截断宿主滚动。
   - 主题 token 和 i18n 全接入。

5. 性能迁移。
   - 大量条目使用虚拟列表或分页。
   - 图片/封面资源按需加载。
   - prefetch 行为可控。

6. 测试。
   - 配置归一/校验。
   - 首屏渲染。
   - 分页和排序。
   - openEntry。
   - 资源释放。

## 5. 验收标准

- 所有布局插件 build/test/lint/validate 通过。
- 布局插件不直接读取文件系统或网络。
- Box Runtime 调用走正式接口。
- 主题、多语言、组件库接线完整。
- 在查看器和编辑引擎中表现一致。

## 6. 验证命令

每个布局插件运行：

```bash
npm run lint
npm test
npm run build
npm run validate
```

联动验证：

```bash
cd Chips-Host && npm run build && npm test
cd Chips-CardViewer && npm run build && npm test && npm run validate
cd Chips-EditingEngine && npm run build && npm test && npm run validate
```

## 8. 风险与注意事项

- 不要把布局插件变成卡片文件定位器。
- 不要绕开 Host box 服务读取箱子文件。
- 不要在宿主和布局插件之间写私有数据传递协议。
