## 4. 开发内容

1. 公共文档更新。
   - 把完成实现的能力写入正式规范。
   - 标明 Host/SDK/组件库/主题包/脚手架边界。
   - 删除旧口径或移动到归档。

2. 项目内部文档更新。
   - Host 内部实现说明。
   - SDK 封装策略。
   - 组件库实现和测试策略。
   - 脚手架模板说明。
   - 主题包技术说明。
   - 插件 README。

3. 工单闭环。
   - `问题工单.md` 标记处理结果。
   - 每个工单目录补验证命令和结果。
   - 未解决项拆成后续任务。

4. 旧资料归档。
   - 不删除文件。
   - 失效草案移动到就近 `归档/`。
   - 归档说明写明原因和替代文档。

5. 文档一致性检查。
   - 文档和代码接口一致。
   - 文档和脚手架输出一致。
   - 文档和主题 contract 一致。
   - 文档和社区平台 API 一致。

## 5. 验收标准

- 所有公共契约都在 `生态共用技术文档/` 有正式位置。
- 项目日志不再是唯一公共信息来源。
- 所有已解决工单有闭环记录。
- 所有未解决问题有后续任务。
- 文档中没有旧架构口径残留。
