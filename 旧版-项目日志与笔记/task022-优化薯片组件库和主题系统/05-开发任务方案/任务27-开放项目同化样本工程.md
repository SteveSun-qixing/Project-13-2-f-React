# 任务27：开放项目同化样本工程

## 1. 任务目标

选择开放项目处理空间中的真实项目，验证任务16的 Web 项目同化能力能否支撑薯片生态快速吸收外部软件。

这不是把外部项目简单打包运行，而是形成可复用的同化方法：扫描、报告、包装、接线、主题化、i18n、组件替换、质量验证。

## 2. 候选样本

当前可选样本：

- `OpenSourceProjectHandlingFolder/DPlayer-master`
- `OpenSourceProjectHandlingFolder/MusicPlayer-main`
- `OpenSourceProjectHandlingFolder/thorium-reader-develop`

建议分级：

- 第一阶段：`MusicPlayer-main`，静态 Web 项目，适合作为低复杂度样本。
- 第二阶段：`DPlayer-master`，播放器组件项目，适合作为媒体组件同化样本。
- 第三阶段：`thorium-reader-develop`，复杂 Electron/阅读器项目，适合作为长期大型软件重做样本。

## 3. 涉及项目

- `OpenSourceProjectHandlingFolder/*`
- `Chips-SDK`
- `Chips-Scaffold/chips-scaffold-app`
- `Chips-ComponentLibrary`
- 可能生成的薯片应用插件样本目录。

## 4. 开发内容

1. 样本选择和授权记录。
   - 读取 LICENSE。
   - 记录来源。
   - 记录不可复制/不可内置的资源。

2. 同化扫描。
   - 项目类型。
   - 构建方式。
   - 入口文件。
   - 依赖。
   - DOM/API 使用。
   - 样式硬编码。
   - 文案硬编码。
   - 文件/网络/媒体/快捷键能力。

3. 生成迁移报告。
   - 同化评分。
   - 必修项。
   - 可自动项。
   - 风险项。
   - 组件替换建议。
   - 主题 token 迁移建议。

4. 生成薯片包装工程。
   - 标准 app manifest。
   - `runtime.targets`。
   - `ui.surface`。
   - SDK client 接线。
   - i18n 初稿。
   - theme provider。

5. 人工同化样板。
   - 替换基础控件。
   - 替换资源访问。
   - 替换样式 token。
   - 接入质量门禁。

6. 形成同化方法论。
   - 哪些能自动。
   - 哪些必须人工。
   - 哪些需要 Host/SDK/组件库补能力。

## 5. 验收标准

- 至少一个低复杂度外部项目生成完整同化报告。
- 至少一个样本能作为标准 app 插件运行。
- 报告中所有阻断问题都有后续任务或工单。
- 同化过程不产生临时插件规范。

## 6. 验证命令

按样本项目和生成工程实际脚本执行。生成的薯片 app 插件至少运行：

```bash
npm run lint
npm test
npm run build
npm run validate
```

同化工具验证：

```bash
cd Chips-SDK && npm test
cd Chips-Scaffold/chips-scaffold-app && npm run test:e2e
```

## 8. 风险与注意事项

- 不要忽略开源许可证。
- 不要把复杂项目一次性同化到底；先低复杂度样本闭环。
- 不要为了跑起来而绕过 Host/SDK/主题/i18n。
