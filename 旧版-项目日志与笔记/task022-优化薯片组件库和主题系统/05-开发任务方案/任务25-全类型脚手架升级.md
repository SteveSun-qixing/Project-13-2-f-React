# 任务25：全类型脚手架升级

## 1. 任务目标

把所有官方脚手架升级到新生态框架口径，确保未来新增应用插件、基础卡片插件、箱子布局插件、模块插件、主题包都默认符合新架构。

脚手架是避免旧模式继续扩散的关键。

## 2. 迁移范围

脚手架：

- `Chips-Scaffold/chips-scaffold-app`
- `Chips-Scaffold/chips-scaffold-basecard`
- `Chips-Scaffold/chips-scaffold-boxlayout`
- `Chips-Scaffold/chips-scaffold-module`
- `Chips-Scaffold/chips-scaffold-theme`

## 3. 涉及项目

- `Chips-Scaffold/*`
- `Chips-SDK`
- `Chips-ComponentLibrary`
- `ThemePack/*`
- `生态共用技术文档/插件开发/*`
- `生态共用技术文档/主题系统/*`

## 4. 开发内容

1. 应用脚手架。
   - 默认 App/Scene/surface。
   - 默认 SDK/hooks。
   - 默认布局原语。
   - 默认 i18n/theme/command/test/preview。

2. 基础卡片脚手架。
   - 默认导出 `renderBasecardView`、`renderBasecardEditor`、`basecardDefinition`。
   - 默认资源桥。
   - 默认组件库和主题 contract。
   - 默认 config normalize/validate。

3. 箱子布局脚手架。
   - 默认导出 `layoutDefinition`。
   - 默认 Box Runtime 消费。
   - 默认视图和编辑器。
   - 默认分页、空态、加载态、错误态。

4. 模块脚手架。
   - 默认 capability + method。
   - 默认 schema。
   - 默认 `ctx.host.invoke`、`ctx.module.invoke`、`ctx.job` 示例。
   - 不生成 React、DOM mount、主题 CSS。

5. 主题脚手架。
   - 默认 token 结构。
   - 默认 contract。
   - 默认 icon variable font 资源结构。
   - 默认 build/validate/test。
   - 一包一外观。

6. 脚手架质量门禁。
   - 模板检查。
   - 生成工程 e2e。
   - 禁止残留模板占位符。
   - 生成工程默认验证通过。

## 5. 验收标准

- 每个脚手架生成工程都可 build/test/validate。
- 生成工程不包含 TODO、空实现、模板占位符。
- 生成工程不创建无意义的文档空目录。
- 生成工程默认使用正式 SDK/Host/组件库/主题链路。
- 公共文档与脚手架输出一致。

## 6. 验证命令

对每个脚手架运行：

```bash
npm run build
npm test
npm run test:templates
npm run test:e2e
```

`chips-scaffold-theme` 当前没有 `test:templates/test:e2e` 时，需要先补齐或记录工单。
