# 任务23：模块插件能力契约与运行时迁移

## 1. 任务目标

把所有模块插件迁移到正式 capability + method 契约和 Host 托管运行时上，确保模块能力可发现、可校验、可调度、可审计。

模块插件不参与 UI 框架，但它们是生态底层能力的重要组成部分，必须和新 SDK、Host 服务域、权限、质量门禁保持一致。

## 2. 迁移范围

模块插件：

- `Chips-ModulePlugin/Chips-CardtoHTML-Plugin`
- `Chips-ModulePlugin/Chips-ColorPicker`
- `Chips-ModulePlugin/Chips-FileConversion-Plugin`
- `Chips-ModulePlugin/Chips-HtmltoImage-Plugin`
- `Chips-ModulePlugin/Chips-HtmltoPDF-Plugin`

## 3. 涉及项目

- `Chips-ModulePlugin/*`
- `Chips-Host`
- `Chips-SDK`
- `生态共用技术文档/协议与契约/06-模块能力契约.md`
- `生态共用技术文档/插件开发/05-模块插件开发.md`

## 4. 开发内容

1. manifest 对齐。
   - `type: module`。
   - `module.apiVersion`。
   - `module.runtime`。
   - `module.activation`。
   - `module.provides`。
   - `module.consumes`。
   - input/output schema。

2. 入口迁移。
   - 使用正式模块定义对象。
   - 不导出 UI mount。
   - 不包含 React 运行时。
   - 不创建窗口。

3. Host 上下文迁移。
   - 使用 `ctx.host.invoke` 调用 Host 正式动作。
   - 使用 `ctx.module.invoke` 调用其他模块。
   - 使用 `ctx.job` 报告进度和响应取消。
   - 禁止直接 import Host 内部服务。

4. 能力链路治理。
   - 文件转换编排模块和原子模块通过 capability 串联。
   - 色彩提取模块输出 schema 稳定。
   - HTML/PDF/Image 转换能力走 Host/PAL 正式动作。

5. 测试。
   - schema 校验。
   - sync/async 调用。
   - job progress。
   - cancel。
   - 权限不足。
   - provider resolve。

## 5. 验收标准

- 所有模块插件 build/test/lint/validate 通过。
- 模块插件不导出 UI mount。
- 模块间调用走 Host 模块服务。
- 所有 capability 和 method 有 schema。
- Host 能发现、解析、调用、取消模块任务。

## 6. 验证命令

每个模块插件运行：

```bash
npm run lint
npm test
npm run build
npm run validate
```

`Chips-HtmltoPDF-Plugin` 额外运行：

```bash
npm run e2e
```

联动验证：

```bash
cd Chips-Host && npm run build && npm test && npm run test:contract
cd Chips-SDK && npm test
```

## 8. 风险与注意事项

- 不要把模块插件做成页面插件。
- 不要通过 `ctx.host.invoke` 调 `module.*`，模块能力调用必须走 `ctx.module.*`。
- 不要在模块插件里直接 import Electron。
