# 任务32：第一版发布前冻结与后续路线

## 1. 任务目标

在全生态重构、最终验收和正式文档沉淀完成后，执行第一版发布前冻结，明确哪些能力进入第一版、哪些能力延后、哪些契约冻结。

这是发布前最后一道产品和工程决策任务。

## 2. 冻结范围

需要冻结：

- Host 服务域和 Bridge API。
- SDK public API。
- App/Scene/surface/commands。
- L8/L9 公开语义。
- 组件库组件清单和 contract。
- 主题 token 和主题包结构。
- 五类插件 manifest 和导出契约。
- 脚手架生成产物。
- CLI 命令。
- 社区平台数据契约不纳入当前冻结；原应用市场方向已取消，后续社区平台应按卡片和箱子分享平台重新设计。
- 打包安装链路。

## 3. 涉及项目

- 全生态工作区。
- `生态共用技术文档/`
- `项目日志与笔记/`

## 4. 开发内容

1. 发布范围确认。
   - 第一版必须包含。
   - 第一版可选包含。
   - 第一版明确不包含。
   - 后续路线。

2. 契约冻结。
   - public API。
   - manifest。
   - plugin exports。
   - theme contract。
   - component contract。
   - CLI command。

3. 版本基线。
   - Host。
   - SDK。
   - ComponentLibrary。
   - ThemePack。
   - Scaffold。
   - 官方插件。

4. 发布检查清单。
   - 构建。
   - 测试。
   - 安装。
   - 打包。
   - 真实素材。
   - 文档。
   - 工单。

5. 后续路线。
   - 第二批组件。
   - 更多主题。
   - 更多外部项目同化。
   - Web Host Shell。
   - Mobile WebView/Capacitor 方向。
   - 社区分享平台增强。

## 5. 验收标准

- 第一版发布范围明确。
- 冻结契约有正式文档位置。
- 未进入第一版的能力不影响当前发布。
- 所有 P0/P1 工单关闭或明确阻断发布。
- 后续路线不混入当前发布任务。

## 6. 验证方式

本任务以发布决策和文档确认为主。执行前必须已完成：

- [任务30-最终全生态质量门禁与发布验收.md](./任务30-最终全生态质量门禁与发布验收.md)
- [任务31-正式文档全量沉淀与工单闭环.md](./任务31-正式文档全量沉淀与工单闭环.md)

