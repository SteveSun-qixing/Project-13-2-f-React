# 任务18：示例应用与真实迁移验证

## 1. 任务目标

通过真实应用验证前端框架重构成果，确保不是只在组件库或脚手架中“看起来可用”。

需要至少完成一组新脚手架示例和若干现有应用迁移验证。

## 2. 当前基础

当前仓库已有多个应用插件：

- `Chips-EcoSettingsPanel`
- `Chips-CardViewer`
- `Chips-EditingEngine`
- `Chips-BookReader`
- `Chips-MusicPlayer`
- `Chips-PhotoViewer`
- `Chips-RichTextEditor`
- `Chips-VideoPlayer`

同时存在外部项目处理空间：

- `OpenSourceProjectHandlingFolder/`

## 3. 涉及项目

- `Chips-Scaffold/chips-scaffold-app`
- `Chips-EcoSettingsPanel`
- 至少 2 个现有应用插件。
- 至少 1 个外部 Web 项目同化样本。
- `ProductFinishedProductTestingSpace` 如用于成品验证。

## 4. 开发内容

1. 新建标准示例应用。
   - 使用 vNext 脚手架生成。
   - 包含 App/Scene/surface。
   - 包含 View/Stack/Grid/Form/List。
   - 包含 theme/i18n/hooks。
   - 包含 command/toolbar。
   - 包含基础表单和列表。

2. 迁移生态设置面板。
   - 改用官方 SDK/hooks。
   - 改用布局原语。
   - 接入组件矩阵和主题矩阵。

3. 选择一个工具类应用迁移。
   - 建议候选：`Chips-CardViewer` 或 `Chips-EditingEngine`。
   - 重点验证 surface、navigation、command、theme、i18n。

4. 选择一个媒体/阅读类应用迁移。
   - 建议候选：`Chips-BookReader`、`Chips-MusicPlayer`、`Chips-PhotoViewer`、`Chips-VideoPlayer`。
   - 重点验证普通页面结构、媒体组件、状态、资源打开。

5. 外部 Web 项目同化验证。
   - 运行同化 CLI。
   - 生成报告。
   - 人工完成关键接线。
   - 输出迁移成本与缺口清单。

6. 记录问题。
   - 缺组件。
   - 缺 SDK API。
   - 缺 Host 服务。
   - 缺主题 token。
   - 缺脚手架模板。
   - 缺测试能力。

## 5. 建议文件范围

具体文件取决于选定应用。每次迁移前必须读取目标应用自己的 `AGENTS.md`、`manifest.yaml`、`package.json` 和现有源码。

可能范围：

- `Chips-EcoSettingsPanel/*`
- `Chips-CardViewer/*`
- `Chips-EditingEngine/*`
- `Chips-BookReader/*`
- `Chips-MusicPlayer/*`
- `Chips-PhotoViewer/*`
- `Chips-VideoPlayer/*`
- `OpenSourceProjectHandlingFolder/*`
- `ProductFinishedProductTestingSpace/*`

## 6. 验收标准

- 至少一个新脚手架应用完整通过验证。
- 至少两个现有应用完成迁移或形成明确缺口报告。
- 至少一个外部 Web 项目完成同化报告。
- 所有迁移应用不绕开 Host/SDK 正式链路。
- 迁移过程中发现的生态缺口已登记工单。

## 7. 验证命令

按具体应用运行其 `package.json` 中正式脚本，至少包括：

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run validate
```

若应用提供 `verify`：

```bash
npm run verify
```

全局联动：

```bash
npm run verify:workspace
```

## 9. 风险与注意事项

- 不要大范围迁移所有应用后才验证；应选择样本逐个闭环。
- 不要在应用层写私有替代组件。
- 不要用迁移应用反向污染公共契约；公共能力先沉淀到底层。
