# 任务26：社区平台与应用市场前端对齐（已取消）

## 0. 当前状态

- 状态：已取消。
- 取消时间：2026-05-26。
- 取消原因：本任务将社区平台设计为“应用市场/插件分发平台”方向，与用户最新确认的生态方向不一致。
- 最新口径：当前薯片生态不需要应用市场；社区平台的正确定位是薯片生态卡片和箱子分享平台，围绕卡片、箱子、房间、空间、内容分享、在线查看和下载等链路重新设计。
- 执行要求：本任务不再作为后续任务051或最终验收依赖。若后续推进社区平台，需要基于“卡片和箱子分享平台”重新编写任务文档，不沿用本任务内容。

## 1. 任务目标

以下为历史错误口径，仅保留为取消记录，不再作为执行依据。

把 `Chips-CommunityPlatformServer` 中的 Web/Admin 前端与薯片前端框架的设计系统、组件库、主题 token、插件/主题/应用市场数据模型对齐。

社区平台不是 Host 插件运行时，但它是生态分发和应用市场的重要组成部分，视觉、组件、数据契约和治理口径不能与主生态割裂。

## 4. 开发内容

1. API 契约核对。
   - 插件发布。
   - 主题发布。
   - 版本信息。
   - 截图/预览资源。
   - 权限声明。
   - 审核状态。
   - 下载与安装元数据。

2. Web/Admin 前端 UI 对齐。
   - 使用薯片组件库或等价 contract。
   - 使用主题 token 或可映射 token。
   - 文案走平台 i18n。
   - 表单、表格、筛选、详情页、审核页统一组件模式。

3. 应用市场数据模型对齐。
   - app/card/layout/module/theme 五类插件。
   - `runtime.targets`。
   - `ui.surface`。
   - module capability。
   - theme contract。

4. 质量门禁。
   - build。
   - lint。
   - test。
   - API contract test。
   - 前端组件一致性检查。

5. 与 Host/SDK 协同。
   - 市场返回数据应能被 Host 安装链路消费。
   - 不让社区平台发明另一套插件 manifest。

## 5. 验收标准

- 社区平台插件/主题数据模型与生态 manifest 口径一致。
- Web/Admin 前端视觉与薯片设计系统一致。
- 社区平台不会输出 Host 无法安装的插件元数据。
- build/lint/test 通过。
