# 任务24：主题包全量升级与视觉一致性

## 1. 任务目标

把所有正式主题包升级到新组件库 contract、layout token、motion token、图标系统和 Host Theme Runtime 口径，保证全生态视觉一致。

## 2. 迁移范围

主题包：

- `ThemePack/Chips-default`
- `ThemePack/Chips-theme-default-dark`

后续新增主题也必须以这两个主题包作为质量基线。

## 3. 涉及项目

- `ThemePack/*`
- `Chips-ComponentLibrary`
- `Chips-Host`
- `Chips-EcoSettingsPanel`
- `生态共用技术文档/主题系统/*`
- `生态共用技术文档/组件库/*`

## 4. 开发内容

1. token 全量升级。
   - `ref`。
   - `sys`。
   - `layout`。
   - `motion`。
   - `comp/*`。

2. 组件 contract 对齐。
   - 每个正式组件都有 token。
   - 每个 part/state 都可被主题命中。
   - required token 不缺失。
   - 冗余 token 有清理或归档策略。

3. 图标系统对齐。
   - Material Symbols variable font 保持正式资源。
   - `ChipsIcon + IconDescriptor` 作为运行时图标入口。
   - 启动图标仍由 `manifest.ui.launcher.icon` 管。

4. CSS 输出升级。
   - 所有 token 输出 CSS variables。
   - 组件样式基于 `data-scope/data-part/data-state`。
   - motion CSS 使用 motion token。
   - reduced motion 支持。

5. 主题包验证。
   - `build:tokens`。
   - `build:css`。
   - `validate:theme`。
   - contract test。
   - 与 Host `theme.apply` 联调。

6. 视觉一致性回归。
   - 应用插件。
   - 基础卡片插件。
   - 箱子布局插件。
   - 设置面板组件矩阵。
   - 默认主题与暗色主题对照。

## 5. 验收标准

- 两个主题包均通过 build/test/validate。
- Host 能安装、启用、应用、解析主题。
- 组件矩阵在默认主题和暗色主题下无明显缺失。
- 所有新增组件 contract 均有主题实现。
- 不在单个主题包中混合 light/dark。

## 6. 验证命令

```bash
cd ThemePack/Chips-default
npm run build
npm run validate:theme
npm test

cd ../Chips-theme-default-dark
npm run build
npm run validate:theme
npm test

cd ../../Chips-ComponentLibrary
npm run test:contracts
npm run quality:gate

cd ../Chips-Host
npm run build
npm test
```

## 8. 风险与注意事项

- 不要在主题包中实现 Host 运行时逻辑。
- 不要用组件库默认样式掩盖主题缺失。
- 不要只更新默认主题，暗色主题必须同步。
