# 任务12：手势、焦点、可访问性与键盘交互

## 1. 任务目标

建立全生态统一的 Gesture / Focus / Accessibility / Keyboard Interaction 体系，让组件和应用具备专业软件级交互质量。

这项任务是组件库质量能否对标 SwiftUI 的关键。组件数量够不够是一部分，交互语义和可访问性完整度同样重要。

## 2. 当前基础

已核对：

- `Chips-ComponentLibrary/packages/a11y/src/index.js`
- `Chips-ComponentLibrary/packages/components/tests/a11y-stage9.test.mjs`
- `Chips-ComponentLibrary/packages/components/tests/system-ux-integration.test.mjs`
- `Chips-ComponentLibrary/packages/testing/src/index.js`
- `Chips-Host/src/renderer/declarative-ui/events.ts`

当前已有 a11y 工具和部分键盘交互，但缺少统一焦点域、手势抽象和跨组件键盘规则。

## 3. 涉及项目

- `Chips-ComponentLibrary`
- `Chips-Host`
- `Chips-SDK`
- `Chips-Scaffold/chips-scaffold-app`

## 4. 开发内容

1. 焦点系统。
   - `FocusScope`
   - focus trap。
   - focus restore。
   - roving tabindex。
   - keyboard navigation map。
   - surface focus context。

2. 键盘交互标准。
   - Button：Enter/Space。
   - Menu：Arrow/Home/End/Escape/Enter。
   - Tabs：Arrow/Home/End。
   - Dialog：Escape、focus trap、return focus。
   - Select/ComboBox：typeahead、Arrow、Enter、Escape。
   - Tree/DataGrid：方向键、展开折叠、多选。

3. 手势抽象。
   - press。
   - long press。
   - drag。
   - resize。
   - swipe 预留。
   - pointer + keyboard 等价行为。

4. a11y contract。
   - role。
   - aria-label / labelledby。
   - aria-describedby。
   - aria-expanded。
   - aria-selected。
   - aria-checked。
   - aria-invalid。
   - live region。

5. L8/L9 校验。
   - accessibility modifier。
   - focusScope modifier。
   - 缺失标签诊断。
   - 键盘不可达诊断。

6. 测试体系。
   - a11y 单测。
   - 键盘交互单测。
   - focus restore 测试。
   - gesture state transition 测试。

## 6. 验收标准

- 所有交互组件可键盘访问。
- Dialog/Popover/Menu/Select 等覆盖 focus trap/restore。
- a11y 测试覆盖新增和已有核心组件。
- L8/L9 能报告关键可访问性问题。
- 脚手架生成应用默认无明显 a11y 错误。
