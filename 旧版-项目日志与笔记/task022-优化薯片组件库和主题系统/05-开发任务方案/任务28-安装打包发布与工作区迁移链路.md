# 任务28：安装、打包、发布与工作区迁移链路

## 1. 任务目标

把新框架重构后的插件、主题包、模块、应用和 Host 安装打包链路打通，确保开发态、用户态、发布态都能一致运行。

## 2. 当前基础

已核对：

- `Chips-Host/src/main/installer/*`
- `Chips-Host/tests/unit/macos-installer.test.ts`
- `Chips-Host/tests/e2e/cli.test.ts`
- `Chips-SDK/cli/index.js`
- `生态共用技术文档/文件格式规范/03-CPK打包格式规范.md`
- `生态共用技术文档/开发与运维/04-打包与安装路径手册.md`

## 3. 涉及项目

- `Chips-Host`
- `Chips-SDK`
- `Chips-Scaffold/*`
- `ThemePack/*`
- 所有插件项目。

## 4. 开发内容

1. CPK 打包链路。
   - app/card/layout/module/theme 五类插件统一检查。
   - manifest 校验。
   - dist 入口校验。
   - contract/schema 校验。
   - 权限校验。

2. 安装链路。
   - plugin install。
   - plugin enable/disable。
   - theme apply/validate。
   - module provider discovery。
   - app shortcut 创建。

3. 工作区迁移。
   - `chips` 用户工作区。
   - `chipsdev` 开发工作区。
   - 插件记录和主题状态隔离。
   - 旧开发产物清理策略。

4. 发布前检查。
   - Host installer。
   - 主题包 cpk。
   - 插件 cpk。
   - 应用入口图标。
   - 运行时图标字体。
   - docs 和 contract 一致。

5. CLI 报告。
   - 打包报告。
   - 安装报告。
   - contract 报告。
   - 工作区状态报告。

## 5. 验收标准

- 五类插件都能通过正式打包校验。
- 主题包可安装、启用、应用和校验。
- 应用插件可通过 Host 正式启动链路打开。
- 模块插件可被 Host 发现和调用。
- 用户工作区和开发工作区状态不混用。

## 6. 验证命令

```bash
cd Chips-Host
npm run build
npm test
npm run test:contract

cd ../Chips-SDK
npm test
```

对各插件运行：

```bash
npm run build
npm run validate
```

主题包：

```bash
npm run build
npm run validate:theme
npm test
```
