# 任务01：公共契约冻结与任务基线

## 1. 任务目标

在正式开发前，先把薯片前端框架 vNext 的公共口径冻结，避免 Host、SDK、组件库、脚手架、主题包各自实现一套不一致的解释。

本任务不开发具体功能，重点产出“能开发的稳定边界”：

- 前端框架能力域清单。
- Host/SDK/组件库/脚手架/主题包/生态设置面板的职责边界。
- App/Scene/surface、View/Modifier、State/Environment、Navigation/Commands、Theme/Contract、Preview/Quality 的公共术语。
- 现有文档、代码和测试之间的漂移清单。

## 4. 开发内容

1. 建立“前端框架能力域总表”。
   - App/Scene/surface/commands。
   - View/Modifier/layout。
   - State/Environment/Binding/Focus。
   - Navigation/Menu/Toolbar/Command。
   - Gesture/Focus/a11y。
   - Motion/Animation。
   - Theme/Token/Contract。
   - Preview/Performance/Quality。
   - Web 项目同化。

2. 明确每个能力域的现有项目落点。
   - Host：运行时主实现。
   - SDK：类型化封装、CLI、测试辅助。
   - ComponentLibrary：无头组件、状态机、a11y、contract。
   - ThemePack：token、CSS、图标字体、组件契约。
   - Scaffold：默认模板与生成链路。
   - EcoSettingsPanel：可视化治理入口。

3. 核对当前代码与文档漂移。
   - L8/L9 文档与 `Chips-Host/src/renderer/declarative-ui`、`Chips-Host/packages/unified-rendering` 是否一致。
   - `manifest.yaml` 中 `runtime.targets`、`ui.surface` 与共享规范是否一致。
   - SDK route manifest、Bridge action、Host schema 是否一致。
   - 组件库 token contract 与主题包 `contracts/`、`tokens/comp/` 是否一致。
   - 脚手架模板是否仍有硬编码主题、硬编码文案、直接 Bridge 私有调用。

4. 复用或补充已登记工单。
   - 已存在 `工单094-组件库冻结技术栈与质量门禁覆盖漂移`，后续组件库技术栈、contract、质量门禁漂移优先补充该工单。
   - 如果发现新的 Host/SDK/Scaffold 漂移，按 `项目日志与笔记/AGENTS.md` 新增工单。

## 5. 输出物

- 一份正式开发前的“能力域与落点确认文档”。
- 一份“文档-代码-测试漂移清单”。
- 必要时更新 `项目日志与笔记/问题工单.md` 和独立工单目录。
- 后续任务可以引用的术语表。

## 6. 验收标准

- 每个能力域都有唯一优先落点，不再出现默认新建陌生项目的口径。
- 公共文档和任务方案都明确：普通页面结构归入统一 `View/Stack/Grid/Form/List`，不新增页面应用分类。
- 后续开发任务能直接引用本任务冻结的术语和边界。
- 所有发现的漂移都已登记或明确复用现有工单。

## 7. 验证方式

建议执行：

```bash
rg -n "独立应用框架|独立前端框架|独立同化工具|独立页面应用分类" 项目日志与笔记 生态共用技术文档
rg -n "runtime.targets|ui.surface|surface.open|View/Stack/Grid/Form/List" 生态共用技术文档 Chips-Host Chips-SDK Chips-Scaffold
```

如本任务仅更新文档，不需要运行代码测试；如同步了公共契约或测试基线，需要至少运行：

```bash
npm run verify:workspace
```

## 8. 依赖任务

无。此任务是所有后续开发任务的入口。

## 9. 风险与注意事项

- 不要把项目日志里的过程性判断直接当作生态公共契约。
- 如果公共契约需要沉淀，必须同步到 `生态共用技术文档/`。
- 不要为了拆任务而新建项目；先用现有工程边界承载能力。
