## 2. 当前 basecard scaffold 真实现状

- `chips-scaffold-basecard` 本体很薄：`package.json` 只有 `build/test/test:templates/test:e2e` 四类脚本，核心 API 只有 `listBasecardTemplates()` 与 `createBasecardProject()`，实际渲染由 `src/core/template-engine.ts` 完成。
- 当前模板目录包含 `manifest.yaml.tpl`、`package.json.tpl`、`src/render`、`src/editor`、`src/schema`、`src/shared`、`i18n`、`tests`、`assets/icons` 等。模板元数据仍声明 `"componentLibrary": false`。
- 当前 manifest 模板基本符合卡片插件基线：`type: card`、`entry: dist/index.mjs`、`capabilities.cardTypes`、`runtime.targets.desktop/headless=true`。依赖只含 React/ReactDOM，未接入组件库。
- 当前入口模板已导出三件套，但上下文不完整：`BasecardRenderContext` 缺 `openResource`，`BasecardEditorContext` 缺 `importArchiveBundle/convertTiffToPng`，`basecardDefinition` 缺 `collectResourcePaths`。
- 当前编辑器模板使用原生表单和私有 CSS，且有硬编码视觉值与径向渐变。渲染模板也默认包了独立 surface、圆角、边框、阴影，这与编辑引擎标准中“装配层不再额外包裹边框、圆角、阴影”的方向冲突。
- 当前测试偏浅：只测 schema、基本挂载、编辑输入与简单集成流；`test:e2e` 直接调用 scaffold API 并跑 `tsc/vitest`，不是通过 `chipsdev create card` 和生成工程正式脚本。

## 3. vNext 差距清单

### Host 唯一运行时

当前模板没有直接 import Host，方向正确；但资源、打开、持久化职责没有完整体现为宿主上下文回调。公共契约要求插件不得直接写文件或依赖宿主状态机。

### SDK 正式链路

当前只从 `chips-sdk` 引入 `IconDescriptor`。需要补齐资源打开 payload 类型意识，并保持 `chips-sdk` semver 依赖。`chipsdev create card` 已接线到 basecard scaffold。

### React 入口

当前已使用 React `createRoot`，但未接入组件库、组件库 hooks 或测试 mock。组件库已提供 `ChipsTextField/ChipsTextArea/ChipsForm/ChipsErrorState`。

### 主题系统

当前 CSS 有 token fallback，但仍有硬编码阴影、圆角、背景、渐变。公共要求是使用 `--chips-*` token，且宿主可能以完整 CSS 或变量注入主题。

### 多语言系统

当前有 `i18n/zh-CN.json.tpl`、`en-US.json.tpl` 和本地 translator，但 schema 校验错误仍硬编码中文。需要让错误态显示也走 i18n key。

### manifest 契约

当前 card manifest 模板基本正确。注意：`ui.surface` 只能用于 app 插件，card 不应添加。

### 资源链路

缺 `openResource`、`importArchiveBundle`、`convertTiffToPng`、`collectResourcePaths` 与 card-root 相对路径校验。公共文档要求资源路径相对卡片根目录，不得持久化 `blob:`、`data:` 或绝对路径。

### 测试质量门禁

缺 cleanup 断言、重复挂载、资源 resolve/release、import/delete、openResource、manifest 对齐、生成工程正式脚本、占位符残留检查。公共测试策略要求查看态、编辑态、schema、cleanup、Host/编辑引擎链路集成。
