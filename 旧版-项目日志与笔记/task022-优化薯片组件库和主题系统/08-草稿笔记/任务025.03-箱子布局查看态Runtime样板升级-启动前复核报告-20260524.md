## 1. 025.03 目标边界与不做事项

### 目标边界

025.03 的核心目标是升级 `boxlayout-standard` 查看态模板，让新生成的箱子布局插件默认以正式 Box Runtime 查看链路工作：

1. 首屏先消费 `initialView.items`，不等待全量条目解析；
2. 后续分页通过 `runtime.listEntries({ cursor, limit, ... })` 获取；
3. 条目封面优先调用 `runtime.renderEntryCover(entryId)`；
4. 直接显示 Host 托管文档封面时接入 `EmbeddedDocumentFrame`，只在明确卡片专用包装场景才使用 `CardCoverFrame`；
5. 点击封面或标题只调用 `runtime.openEntry(entryId)`；
6. 按需使用 `runtime.prefetchEntries`、`runtime.readEntryDetail`、`runtime.readBoxAsset`，不把它们变成首屏强依赖；
7. 补齐加载态、空态、错误态、分页态、cleanup 和异步取消测试；
8. 查看态可见文案进入 `i18n/*.json.tpl`，视觉样式改为主题 token / 组件库契约可承接的中性样板；
9. 根节点至少铺满宿主可视区，并允许内容自然向下增长，不用固定高度和隐藏溢出截断宿主滚动。

### 不做事项

1. 不改 Host / SDK 架构来适配模板旧字段；正式链路应以公共契约和当前 SDK/Host 代码为准。
2. 不在布局插件中解析磁盘、拼接卡片路径、直接打开应用插件或自行实现新窗口逻辑。
3. 不把 `grid-BLP` 或 `list-BLP` 的业务偏好固化为所有新布局模板的唯一范式；只能借鉴正式 runtime 接线方式。
4. 不实现编辑器资产桥、资源导入/删除、schema 资产路径深度校验；这些属于 025.04。
5. 不改真实 CLI e2e、生成工程 package/verify 公共文档收口；这些属于 025.05。
6. 不迁移真实 `grid-BLP/list-BLP` 业务插件本体；后续应走任务22全量迁移或单独插件任务。
7. 不触碰主题包任务、组件库 token 任务或基础卡片脚手架任务。

## 2. 当前模板查看态与公共契约差距

### P0：会阻断正式 runtime 样板验收

1. 模板仍有旧 Box Runtime 类型口径。
   证据：`templates/boxlayout-standard/src/shared/types.ts.tpl` 当前存在 `snapshot.cardId`、`readEntryDetail.fields: "cardInfo"`、`resolveEntryResource.kind: "cardFile"`、`prefetchEntries.targets: "cardInfo"`、`openEntry.mode: "card-window"`。
   契约要求：`08-箱子布局运行时契约.md`、`插件开发/04-布局插件开发.md`、`Chips-SDK/src/api/box.ts` 和真实 `grid-BLP/list-BLP/src/shared/types.ts` 使用 `documentId/documentInfo/documentFile/document-window`。
   建议：若 025.02 已修，这一项在 025.03 开始前重扫确认；若仍存在，025.03 不能继续扩展查看态，应先补齐契约字段。

2. 查看态默认使用 `CardCoverFrame` 和 `cardId`，不符合“直接显示文档封面优先 EmbeddedDocumentFrame”的公共口径。
   证据：`templates/boxlayout-standard/src/view/page.tsx.tpl` 导入 `CardCoverFrame`，并向组件传入 `cardId={entry.snapshot.cardId ?? entry.entryId}`。
   契约要求：`renderEntryCover` 返回 `coverUrl/title/ratio`，布局插件应把 Host 托管文档 URL 当作 iframe 入口交给 `EmbeddedDocumentFrame`；条目可能是卡片也可能是箱子，默认不应卡片化。

3. 模板没有分页样板，`initialView` 只在 mount 时被压成固定 `entries` props。
   证据：`src/view/runtime.ts.tpl` 只传 `entries: options.initialView.items`；`src/view/page.tsx.tpl` 没有 `nextCursor` 状态、`listEntries` 调用、分页加载状态或分页错误恢复。
   契约要求：摘要优先、按需分页；`BoxEntryPage` 正式包含 `nextCursor`。

4. 查看态测试仍接受旧打开结果，且没有断言禁止旧字段和旧组件。
   证据：`tests/unit/layout-definition.test.tsx.tpl` 的 `openEntry` mock 返回 `mode: "card-window"`，并断言存在 `[data-scope="card-cover-frame"]`。
   建议：测试应改为 `document-window`，并断言渲染走 `[data-scope="embedded-document-frame"]`，扫描无 `cardId/cardInfo/cardFile/card-window`。

### P1：会影响查看态质量和 Host 协作

1. 预取范围过粗。
   证据：当前模板在有条目时对全部 enabled entries 一次性 `prefetchEntries({ targets: ["cover"] })`。
   建议：保留温和预取样板，但限制到首屏或当前页条目，分页加载后再预取新增页；错误不应影响主渲染。

2. 空态、加载态、错误态过薄。
   证据：空态只返回 `<div>{layout.empty}</div>`；封面错误和无封面都归到简单文本块；缺少分页加载/分页错误/重试样板。
   建议：空态保持白色/中性背景和本地化提示；封面错误只降级单条目；分页错误显示页尾错误与重试按钮，不让整页崩溃。

3. cleanup 只覆盖 React root 卸载，缺少异步取消断言。
   证据：模板组件内部已用 `cancelled` 阻止封面 promise resolve 后 setState，但测试没有覆盖“cleanup 后 promise resolve 不写入 DOM/不报警告”；分页请求未来也需要同类取消。

4. `readEntryDetail` 没有最小字段示例。
   证据：模板未使用 `readEntryDetail`；真实 `list-BLP` 只请求 `fields: ["documentInfo"]` 并从详情提取创建时间，可作为按需取数参考。
   建议：标准模板不必强制展示创建时间，但可以示范一个可开关/轻量的“按需详情”路径，或至少在测试中保证不会首屏无条件请求详情。

5. `readBoxAsset` 没有查看态资源样板。
   证据：模板查看态没有背景/顶部 frame region，也没有任何 `readBoxAsset` 消费。真实 `grid-BLP/list-BLP` 的 `FrameRegionSurface` 使用 `readBoxAsset` 展示箱子自有背景/顶部内容区。
   建议：025.03 如果引入查看态 `readBoxAsset`，只做读取与展示 Host 句柄，不做导入/删除；更重的资产编辑留给 025.04。

### P2：可与 025.03 同步改善，但不应扩大任务

1. 样式仍有硬编码私有视觉值。
   证据：`page.tsx.tpl` 中有 `#475569`、多处 `rgba(...)`、`linear-gradient(...)` 和 iframe/status 内联样式。
   建议：改成中性 CSS 变量或 Chips theme token fallback；不要把 grid/list 现有视觉原样复制。

2. 根节点没有明确 `minHeight: "100%"` / `width: "100%"` / `minWidth: 0` 等宿主约束样板。
   证据：当前 root 是 grid 容器，只有 `display/gridTemplateColumns/gap/padding/alignItems`。
   建议：外层使用 `section` 作为页面根，至少铺满宿主可视区并允许内容自然增长；避免根层 `height: 100% + overflow: hidden`。

3. 任务输入路径有轻微漂移，需要主代理按当前真实文件操作。
   证据：用户清单提到 `src/runtime/BoxLayoutRuntimeView.tsx.tpl`，当前模板实际是 `src/view/runtime.ts.tpl` 与 `src/view/page.tsx.tpl`；用户清单提到 `Chips-Plugin-BoxLayout`，当前工作区真实目录是 `Chips-BoxLayoutPlugin/grid-BLP` 与 `Chips-BoxLayoutPlugin/list-BLP`。
   建议：报告和实施记录写清以当前真实路径为准，避免误删或新建重复旧路径。

## 4. 建议新增/更新的测试断言

1. 首屏摘要优先：`renderView` 后立即显示 `initialView.items` 中的 enabled 条目，不调用 `listEntries` 才能显示首屏。
2. 分页：当 `initialView.nextCursor` 存在时显示本地化加载更多控件；点击后调用 `runtime.listEntries({ cursor: nextCursor, limit: ... })`，追加新条目并更新/清空 cursor。
3. 分页错误：`listEntries` reject 时不清空现有条目，显示本地化错误和重试按钮；重试再次调用 `listEntries`。
4. 封面链路：每个可见条目优先调用 `runtime.renderEntryCover(entryId)`；ready 后渲染 `[data-scope="embedded-document-frame"]`，不出现 `[data-scope="card-cover-frame"]`。
5. 封面失败：单个 `renderEntryCover` reject 时只显示该条目的本地化占位/错误态，其他条目继续渲染。
6. 打开动作：点击封面或标题只调用 `runtime.openEntry(entryId)`；测试不允许出现路径拼接、`card.open`、应用插件启动 mock 或 `card-window` 返回口径。
7. 预取：对当前页条目调用 `runtime.prefetchEntries({ entryIds, targets: ["cover"] })`；预取失败被吞掉，不影响页面内容。
8. 详情按需：如果模板展示详情字段，则只请求 `fields: ["documentInfo"]`，且在空态或不需要详情时不调用 `readEntryDetail`。
9. 箱子条目：`snapshot.contentType: "chips/box"` 的条目仍通过 `renderEntryCover/openEntry`，不展开子箱子布局，不使用卡片专用组件。
10. cleanup：调用 cleanup 后容器为空；未决 `renderEntryCover/listEntries/readEntryDetail/readBoxAsset` resolve 后不会重新写入 DOM 或触发 React act 警告。
11. i18n：空态、加载态、错误态、重试、条目类型文案来自 `i18n` key，中文/英文 key 对齐。
12. 静态阻断：模板或生成工程中扫描不到 `cardId|cardInfo|cardFile|card-window|CardCoverFrame`；若保留 `CardCoverFrame` 只允许出现在明确卡片专用示例注释之外，但本任务建议默认查看态不保留。
13. 滚动友好：根节点存在正式 scope，样式不包含根层固定高度截断组合；至少断言没有在查看态 root 上设置 `overflow: hidden`。

## 6. 可直接用于实现的具体建议

1. 将查看态拆成轻量状态层：`items`、`nextCursor`、`isLoadingNext`、`pageError`、`isDisposed/cancelled`。初始值来自 `initialView`，分页成功后追加 enabled items。
2. `EntryTile`/`EntryRow` 独立处理封面状态：`loading -> ready/error/empty`，内部只调用 `renderEntryCover` 和 `openEntry`；标题 fallback 用 `snapshot.title ?? snapshot.documentId ?? entryId`。
3. `EmbeddedDocumentFrame` 用法参考真实插件：`title={view.title || title}`、`src={view.coverUrl}`、`ratio={view.ratio ?? fallbackRatio}`、`onActivate={() => runtime.openEntry(entry.entryId)}`。
4. 比例处理保持简单：优先 `coverView.ratio`，其次 `layoutHints.aspectRatio`，最后模板默认 `"3:4"`；只做字符串到 CSS `aspect-ratio` 的安全转换，不解析文件。
5. 预取策略限制在当前 items 或新增页 items：`targets: ["cover"]`，失败 `.catch(() => undefined)`。
6. 分页按钮不要自动无限拉取；标准模板用明确“加载更多”更容易测试，也避免默认大量取数。
7. `readEntryDetail` 如果要示范，放在可选信息区域，字段固定为 `documentInfo`；不要请求 `coverDescriptor` 后绕开 `renderEntryCover`。
8. `readBoxAsset` 如果在查看态示范背景/顶部资源，只读取 `asset_refs` 或配置中的 `assets/...` 路径，并把 `resource.resourceUrl` 交给受控显示区域；不要持久化 Host 返回 URL。
9. 样式使用 `data-scope="chips-box-layout-view"` 或保留现有 scope，但 root 采用 `width: 100%`、`minWidth: 0`、`minHeight: 100%`，内容区自然增长；不要根层固定 `height: 100%` 加 `overflow: hidden`。
10. 新增文案先补 i18n key，再改组件；测试同时断言中英文 key 数量或关键 key 存在。
11. 025.03 开始前建议先运行只读扫描：

```bash

```
