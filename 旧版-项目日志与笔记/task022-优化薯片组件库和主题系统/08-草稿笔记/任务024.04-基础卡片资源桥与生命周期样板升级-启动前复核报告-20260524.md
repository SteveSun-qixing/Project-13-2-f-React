## 2. 024.04 真实目标、范围与验收标准

### 2.1 真实目标

024.04 的目标不是迁移某个具体业务基础卡片，也不是把 Host / EditingEngine 的资源持久化职责塞进脚手架模板，而是让 `chips-scaffold-basecard` 生成工程默认具备一套可复制的正式资源桥样板：

- 查看态演示内部资源路径如何经 `resolveResourceUrl(resourcePath)` 转成运行时 URL；
- 查看态在 cleanup 或 effect disposal 中调用 `releaseResourceUrl(resourcePath)`；
- 查看态演示 `openResource(...)` 只是可选的资源打开意图表达，不硬编码播放器、阅读器、图片查看器等 app plugin；
- 编辑态演示通过 `importResource({ file, preferredPath })` 导入资源，只保存返回的 card-root 相对 `path`；
- 编辑态演示替换/移除资源时通过 `deleteResource(resourcePath)` 登记删除；
- 保留 `importArchiveBundle(...)`、`convertTiffToPng(...)` 的类型与测试入口，但不把网页、音乐、电子书等业务私有解析流程写入基础模板；
- 测试覆盖 mount、cleanup、重复挂载、资源 resolve/release、import/delete、openResource payload，并证明插件自身不直接读写文件系统。

### 2.2 范围边界

本轮应聚焦：

- `templates/card-standard/src/render/*`
- `templates/card-standard/src/editor/*`
- `templates/card-standard/src/schema/*`
- `templates/card-standard/tests/**`
- 必要时补 `scripts/check-templates.cjs` 的轻量资源桥存在性检查，但大规模质量门禁留给 024.05。

本轮不应做：

- 不提前迁移 `Chips-BaseCardPlugin/*` 中的具体业务卡片插件；
- 不把音乐卡片、网页卡片、电子书卡片的业务流程写进通用模板；
- 不新增未冻结第三方库；
- 不让模板绕过 Host/EditingEngine 资源上下文直接 `fs`、Bridge、SDK 文件写入或打开应用；
- 不运行会写入大量产物的 e2e/build，本复核阶段仅使用 `rg/sed/find/git status` 等只读命令。

### 2.3 验收标准

按任务文档与公共规范汇总，024.04 完成后应满足：

- 资源路径只保存 card-root 相对路径，不保存绝对路径、`blob:`、`data:`、`file://` 或 Host 临时 URL；
- `cleanup` 完整释放 React root、容器样式、已解析的资源 URL、监听器/计时器；
- 测试证明资源桥全部来自上下文回调，插件不直接读写文件；
- `importArchiveBundle` 与 `convertTiffToPng` 保留正式类型和测试入口，但模板不嵌入具体业务卡片私有逻辑；
- 以主代理完成 024.03 后的代码为准，继续保留 React、组件库、主题 token 与 i18n 样板。

## 3. 当前模板资源桥与 lifecycle 差距

### 3.1 已具备的基线

- `src/index.ts.tpl` 已声明 `openResource`、`importArchiveBundle`、`convertTiffToPng`、`collectResourcePaths` 等 024.02 所需类型与入口，并在 `basecardDefinition.renderView/renderEditor` 中透传上下文回调。
- `src/schema/card-config.ts.tpl` 已有 `resource_path?: string`、`isCardRootResourcePath`、`collectBasecardResourcePaths`，并拒绝绝对路径、URL scheme、`?/#`、控制字符和 `..` 段。
- `src/render/runtime.ts.tpl` 已能创建 React root、注入 `themeCssText` 与样式，并在 cleanup 中 `unmount` 和清空容器。
- `src/editor/runtime.ts.tpl` 已捕获并恢复 `html/body/container` 的 inline 样式，创建编辑根节点并在 cleanup 中调用 `__chipsDispose`、恢复样式、清空容器。
- EditingEngine 真实链路已提供对应能力：`EditorHost` 有 `resolveResourceUrl`、`releaseResourceUrl`、`importResource`、`deleteResource`、`convertTiffToPng`、`importArchiveBundle`；`session-store` 与 `CardService` 负责 pending imports/deletions、`collectResourcePaths` 引用判断、持久化与最终删除。

### 3.2 `resolveResourceUrl / releaseResourceUrl` 差距

- `BasecardView` 当前只渲染 title/body，虽然 config 带 `resource_path`，但查看态没有调用 `resolveResourceUrl`，也没有显示资源预览、资源链接、资源错误或静态回退。
- `mountBasecardView` 只把 `ctx` 中的 `config/themeCssText` 传给 React，未传 `resolveResourceUrl/releaseResourceUrl/openResource`。
- cleanup 当前只 unmount root 与清空容器，没有资源 URL 释放断言；若后续 view 内异步 resolve，需避免 unmount 后 setState，并在 effect cleanup 中 release 当前 path。
- 测试 `render-view.test.tsx.tpl` 的 config 包含 `resource_path: "assets/cover.png"`，但未断言 resolve 被调用、release 在 cleanup 被调用、无 callback 时回退到相对路径。

建议 024.04 处理：在查看态加入一个最小资源样板区，优先 `resolveResourceUrl(config.resource_path)`，未提供时回退 `config.resource_path`，组件卸载或路径变化时 release 原路径；资源 resolve 失败显示 i18n 错误态或文本状态，避免抛到宿主整页。

### 3.3 `openResource` 差距

- `src/index.ts.tpl` 有 `BasecardOpenResourceInput` 和上下文透传，但查看 UI 没有任何触发 open 的控件或回调。
- `Chips-EditingEngine/src/basecard-runtime/contracts.ts` 当前 `BasecardRenderContext` 还没有 `openResource` 字段，而公共文档与脚手架入口已有。编辑引擎预览链路不提供 openResource 不阻断 024.04，因为 openResource 是可选能力；模板应优雅降级。

建议 024.04 处理：查看态可添加一个资源打开按钮/图标（按 024.03 最终组件库能力选择），仅在 `resource_path` 存在且 `openResource` 存在时启用；调用 payload 使用通用样板，例如：

```ts
openResource({
  resourceId: resolvedUrl,
  title: config.title,
  fileName: basename(config.resource_path),
  payload: {
    kind: "chips.basecard.resource-sample",
    version: "1.0.0",
    cardType: config.card_type,
    relativePath: config.resource_path,
  },
});
```

不要硬编码音乐播放器、图片查看器、阅读器或具体 app plugin id。

### 3.4 `importResource / deleteResource` 差距

- `BasecardEditorProps` 已声明 `importResource/deleteResource`，`mountBasecardEditor` 已透传，但 `BasecardEditor` 没有文件选择控件，也没有任何导入、移除、替换资源的流程。
- 编辑 UI 目前只能编辑 title/body；`resource_path` 只是随着已有 config 保留。
- 测试 `editor-panel.test.tsx.tpl` 只验证 title 输入后 `resource_path` 不丢失，没有验证导入成功后保存返回 path、替换旧资源时 delete 旧 path、缺少 importResource 时显示错误、不保存临时 URL。

建议 024.04 处理：在编辑面板加一个最小资源字段，使用组件库已有控件；如果组件库没有正式文件上传控件，允许使用视觉上受控的原生 `input type="file"` 作为文件选择能力，但要避免回退到旧原生表单样板，并在报告/实现说明中标注这是浏览器文件选择基础能力，不是私有视觉控件。导入流程应：

1. 没有 `importResource` 时显示 i18n 错误，不读文件、不写本地；
2. 有文件后调用 `importResource({ file, preferredPath: sanitize(file.name) })`；
3. 只把返回的 `path` 写入 `resource_path`；
4. 如果旧 `resource_path` 存在且不同，调用 `deleteResource(oldPath)` 登记删除；
5. 删除按钮调用 `deleteResource(currentPath)` 后把 `resource_path` 清空并 `onChange`。

### 3.5 `importArchiveBundle / convertTiffToPng` 差距

- 类型已在 `src/index.ts.tpl` 和 `BasecardEditorProps` 中存在。
- 当前没有测试证明它们被保留为可用上下文入口，也没有编辑 UI 显示“需要业务卡片再使用”的边界。
- 024.04 不应实现网页包、图片包或音乐封面转换业务逻辑；这些属于具体业务卡片。

建议 024.04 处理：补类型/透传层测试即可，例如创建 editor root 或通过 `mountBasecardEditor` 传入 spy callbacks，确认 props 接线不会丢；或在类型层用最小 fake handler 覆盖可调用性。不建议在通用模板 UI 里放 ZIP/TIFF 按钮，否则会把业务场景误导为所有基础卡片默认能力。

### 3.6 cleanup / lifecycle 差距

- 查看态已有 root unmount 和容器清空，但没有资源 release、重复挂载 cleanup 测试、异步 resolve 防竞态测试。
- 编辑态 runtime 已恢复 `html/body/container` 样式，但缺少测试覆盖恢复行为、重复挂载、`__chipsDispose` 调用后容器清空。
- 编辑 panel 的 `createBasecardEditorRoot` 只 unmount React root；如果新增资源 preview effect，需要在 React effect cleanup 中 release 当前 resource path。
- integration test 目前没有保存 dispose 函数，重复 `mountBasecardView` 时也没有 cleanup 旧挂载，024.04 应避免继续强化这个坏示例。

建议 024.04 处理：

- `render-view.test.tsx.tpl`：增加 resolve/release、cleanup、重复挂载、无 callback 回退、resolve reject 错误态。
- `editor-panel.test.tsx.tpl`：增加 import/delete、缺少资源桥错误态、只持久化返回 path、不持久化 `blob/data/file`。
- `card-flow.test.ts.tpl`：把 view/editor 的 dispose 闭环纳入测试，避免示例中直接重复 mount 不清理。
- `schema.test.ts.tpl`：可补 `http://`、`https://`、`content/foo`、空段、反斜杠归一等边界；`content/foo` 是否禁止需按公共规范判断，当前规范只说内部资源相对卡片根目录且不得相对 `content/`，建议禁止 `content/` 前缀以免业务配置误指 content 目录。
