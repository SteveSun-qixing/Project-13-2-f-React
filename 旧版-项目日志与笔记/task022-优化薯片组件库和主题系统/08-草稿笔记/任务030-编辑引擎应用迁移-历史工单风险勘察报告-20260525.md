## 2. 030拆分时必须进入验收标准的风险

建议把 030 第一阶段先做“身份与文档基线收口”：清掉 `app-config`、独立 JSON 词典、`ExamplePanel`、`template.json` 的模板残留，确认 README、manifest、运行配置、i18n 顶层命名一致。

后续子任务验收必须覆盖：

- 编辑引擎不得恢复 `SDK compositeWindow` 作为编辑态主渲染入口；当前基线是 `basecard-runtime` 装配单基础卡片 iframe。
- 编辑面板不得恢复通用占位编辑器正式兜底；`PluginHost -> EditorHost -> BasecardDescriptor.renderEditor` 是主链路。
- 资源型基础卡片必须走现有资源桥，运行时 URL 不得污染持久化 YAML。
- 卡片封面、箱子封面、箱子预览继续走 Host/SDK 正式链路。
- 拖拽插入、无限画布交互、编辑失焦保存、箱子编辑会话不能回退到旧 mock/stub 行为。
- 所有界面正式文案走 `src/i18n` / `useTranslation`，避免新增硬编码回退文案。
