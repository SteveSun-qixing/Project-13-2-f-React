## 2. 当前 Tree 现状矩阵

| 维度 | 当前现状 | 与 016.05 目标的关系 |
|---|---|---|
| Runtime API | `ChipsTree` 是 `React.forwardRef` 单体组件，主要 props 为 `nodes / expandedIds / defaultExpandedIds / selectedId / defaultSelectedId / expandIconContent / collapseIconContent / onExpandedIdsChange / onSelectedIdChange / onStateChange`。 | 仍是 `nodes[]` 数据驱动 API，没有 `ChipsTree.Root/Item/Branch/Leaf/Disclosure` 静态子组件。 |
| Runtime 结构 | 根节点为 `ul[data-scope="tree"][data-part="root"]`，可见节点扁平化渲染为 `li[data-part="node"]`，子结构包含 `button[data-part="toggle"]`、`span[data-part="label"]`、`span[data-part="children"]`。 | 当前公开 part 为 `root/node/toggle/label/children/status`，与目标 `root/item/branch/leaf/disclosure` 命名不一致。 |

| 数据工具 | `flattenTreeNodes(nodes, expandedIds)`、`findTreeParentId(nodes, targetId)` 已存在，测试覆盖展开扁平化和 parent 查询。 | 可复用为 Root 状态机内部工具，但不等同 Compound API。 |

| 组件测试 | `index.test.mjs` 覆盖导出、`buildComponentContract("tree")` 旧 token、`flattenTreeNodes/findTreeParentId`。`a11y-stage9.test.mjs` 只通过 helper 校验 root role/label。 | 没有 Compound 子组件导出测试、DOM 结构测试、键盘路径测试、`treeitem/group` 深度 a11y 测试。 |

## 3. 目标 Compound API 命名差距

任务016.05 文档要求 Tree 正式 API 为：

- `Tree.Root`
- `Tree.Item`
- `Tree.Branch`
- `Tree.Leaf`
- `Tree.Disclosure`

用户提示中另有 `Root / Item / Branch / Leaf / Toggle / Label` 或任务文档口径。结合当前代码和任务文本，建议冻结如下口径：

| 目标子组件 | 建议 data-part | 当前对应 | 建议说明 |
|---|---|---|---|
| `Root` | `root` | `root` | Root 负责 expanded、selected、active/roving focus、禁用/加载/错误状态和上下文分发。 |
| `Item` | `item` | `node` | 通用 treeitem 容器；如果保留 `Branch/Leaf`，`Item` 可作为共享底层或显式可用节点入口。 |
| `Branch` | `branch` | 有 children 的 `node` | 表示可展开节点，应输出 `role="treeitem"`、`aria-expanded`、层级集合属性，并包含 `Disclosure` 和子 `group`。 |
| `Leaf` | `leaf` | 无 children 的 `node` | 表示不可展开节点，不输出 `aria-expanded`。 |
| `Disclosure` | `disclosure` | `toggle` | 任务文档写 `Disclosure`，建议优先于 `Toggle`；`Toggle` 容易与任务015 `ToggleButton` 及开关语义混淆。 |
| `Label` | `label` | `label` | 任务文档未列 Label，但用户提示提到 Label，且当前 runtime/contract 已有 label；建议纳入正式子组件或至少作为公开 part，否则无法稳定挂载节点文本/图标/二级信息。 |
| 子节点容器 | `group` 或不公开 | `children` 装饰 span | ARIA tree 要求子树容器使用 `role="group"`。建议若 DOM 中存在子组容器，应公开为 `group` part 或明确它是 Branch 内部结构 part，不叫 `children`。 |
| 状态 | `status` | `status` | 错误 live region 可保留。 |

推荐正式 API 形态：

```tsx
<ChipsTree.Root aria-label="Project files" defaultExpandedIds={["src"]}>
  <ChipsTree.Branch id="src">
    <ChipsTree.Disclosure aria-label="Toggle src" />
    <ChipsTree.Label>src</ChipsTree.Label>
    <ChipsTree.Leaf id="index">index.ts</ChipsTree.Leaf>
  </ChipsTree.Branch>
</ChipsTree.Root>
```

如果主代理严格执行任务文档的五件套，不新增 `Label`，也应保留 `label` 作为公开 `data-part`，并在公共文档说明 `Item/Branch/Leaf` 的文本区域由内部 label part 承载。更优方案是把 `Label` 纳入 Tree Compound API，因为当前旧口径已有 label，且 a11y 名称、图标+文本组合、行内辅助信息都需要稳定 slot。

## 4. A11y 风险与必须覆盖点

当前 Tree 已有基础语义：

- 根节点 `role="tree"`、`tabIndex=0`、`aria-label`。
- 节点 `role="treeitem"`。
- 有 children 的节点输出 `aria-expanded`。
- 节点输出 `aria-level`。
- 选中节点输出 `aria-selected`。
- 键盘支持 ArrowUp、ArrowDown、Home、End、ArrowRight、ArrowLeft、Enter/Space。
- 节点采用 roving tabindex：active 节点 `tabIndex=0`，其他为 `-1`。

主要风险：

1. `aria-setsize` 与 `aria-posinset` 缺失。当前只输出 `aria-level`，读屏无法完整感知同层总数和位置。迁移时应在 flatten 或 Compound registry 中计算同层 `setsize/posinset`。
2. 子树容器没有 `role="group"`。当前 `children` 是装饰 span，并不承载真实嵌套 DOM；Compound 迁移若改回嵌套结构，Branch 子节点容器必须是 `role="group"`。
3. Tree 根节点和 active treeitem 同时可聚焦。当前 root `tabIndex=0`，active item 也 `tabIndex=0`，容易出现两个 tabbable 节点。正式 roving tabindex 推荐只有 tree 容器或当前 item 成为 Tab 停靠点，需要选择一种并测试焦点路径。若保留 item roving，Root 不应同时进入 Tab 序列；若采用 `aria-activedescendant`，Root 可聚焦但 item 不应 tabbable。
4. `Disclosure` 当前按钮 `tabIndex=-1` 且 aria-label 等于节点 label。迁移后应明确披露按钮是否单独可聚焦。树控件常见做法是 treeitem 处理左右键展开折叠，Disclosure 作为视觉按钮可 pointer 点击但不进入 Tab；若可聚焦，则需要避免破坏树的单一 roving 焦点模型。
5. `Enter/Space` 当前只选择节点，不切换展开。任务要求包含展开折叠、选择和键盘导航；建议明确：ArrowRight 展开、ArrowLeft 折叠/回父级；Enter/Space 选择当前节点。如产品想 Space 展开，需要在公共 a11y 基线写清。
6. `aria-selected` 当前每个 treeitem 都输出 `true/false`。单选树可以接受；若后续支持多选，需要 `aria-multiselectable`、范围选择、`Shift`/`Cmd` 语义另行设计，不建议混入 016.05。
7. 禁用节点跳过逻辑已有 `getNextEnabledIndex`，但没有真实 DOM 键盘测试证明 disabled treeitem 不可选、不可 roving。
8. 错误状态 live region 仍在 root 下，需确保不会破坏 `tree` 的允许子结构；必要时把 status 放在 tree 外层 wrapper，或确认 `role=tree` 下包含非 treeitem 是否可接受。
9. 默认展开/折叠图标走 `ChipsIcon` 装饰模式，这很好；但 Disclosure 需要独立可访问名称或由 treeitem label 关联，不能让装饰图标承担语义。
10. 视觉层必须保持可见 focus ring。默认和暗色主题当前只给 root focus outline，迁移后如果焦点落到 item/branch/leaf，应新增对应 focus token/CSS。

建议测试矩阵：

- `Root` 必须有可访问名称：`aria-label` 或 `aria-labelledby`。
- `Branch` 输出 `role="treeitem"`、`aria-expanded=true/false`、`aria-level`、`aria-setsize`、`aria-posinset`。
- `Leaf` 输出 `role="treeitem"`，不输出 `aria-expanded`。
- 子节点容器输出 `role="group"`。
- 选中项输出 `aria-selected=true`，未选中项按当前策略输出 false 或不输出，需统一。
- ArrowDown/ArrowUp 移动 active，Home/End 到首末可用项。
- ArrowRight 展开可展开未展开 Branch；ArrowLeft 折叠已展开 Branch，或移动到父 Branch。
- Enter/Space 触发选择，并跳过 disabled。
- roving tabindex 或 `aria-activedescendant` 二选一，测试 Tab 序列只有一个入口。

## 6. Host L8 Schema 现状和建议测试

当前 Host L8 `StandardCompoundSlotSchemas` 现状：

- 已有：`Dialog / Tabs / Popover / Menu / Select / Form / DataGrid`。
- 缺少：`Tree`。
- 公共 L8 文档 `17-L8声明式UI实现与接口细则.md` 的标准复杂组件 slot schema 公开基线仍只列到 `DataGrid`，也缺 Tree。

建议新增 Tree schema：

```ts
Tree: {
  item: { type: ['View', 'Section'], required: false, multiple: true, part: 'item', role: 'treeitem' },
  branch: { type: ['View', 'Section'], required: false, multiple: true, part: 'branch', role: 'treeitem' },
  leaf: { type: ['View', 'Text', 'Section'], required: false, multiple: true, part: 'leaf', role: 'treeitem' },
  disclosure: { type: 'Command', required: false, multiple: true, part: 'disclosure' },
  label: { type: 'Text', required: false, multiple: true, part: 'label' },
  group: { type: ['List', 'Section'], required: false, multiple: true, part: 'group', role: 'group' }
}
```

需要主代理决策的点：

- Tree 是否要求至少一个 `item/branch/leaf`。当前 L8 schema 机制按 slot 名校验 `required`，无法表达“branch 或 leaf 至少一个”的互斥/联合必填规则；如果要强校验，需要增强 schema 表达能力，或用测试先覆盖合法/非法基础结构。
- `Disclosure` 是否允许 multiple。每个 Branch 最多一个 Disclosure，但 L8 当前 schema 只按全局 slot 计数，无法表达“每个 Branch 一个”。建议 schema 层允许 multiple，组件库/文档说明 Branch 内部最多一个。
- `Label` 是否进入正式任务口径。若纳入，Host schema 同步加 `label`；若不纳入，公共文档至少说明 label 是 DOM part 而非 Compound slot。

建议 Host 单测：

- `StandardCompoundSlotSchemas.Tree` 合法 compose：包含 branch、leaf、disclosure、label、group，validate 为空。
- 未声明旧 slot `toggle` 产生 `DECLARATIVE_UI_SLOT_UNDEFINED`。
- `disclosure` 使用非 `Command` 节点产生 `DECLARATIVE_UI_SLOT_TYPE_MISMATCH`。
- 若定义 `group`，非 `List/Section` 节点产生类型错误。
- 如果增强联合必填，空 Tree 或只有 disclosure/label 应产生 required 诊断。
- 公共 L8 文档同步新增 Tree schema，避免 Host 代码领先公共规范。

   - `ChipsTree` 改为带静态子组件的类型。
   - `TreeNode/TreeProps` 若作为内部辅助或短期 fallback，应避免继续被正式文档推荐。

   - Host 单测覆盖合法、旧 slot undefined、类型错误和必填/联合规则。
   - 同步公共 L8 文档。

7. 同步生态共用组件文档。
   - `组件库/01` 增加 `ChipsTree.Root / Item / Branch / Leaf / Disclosure`。
   - `组件库/02` 增加 Tree 正式 parts、states、ARIA。

8. 跑验证并写工作日志。

## 10. 工单候选

本轮只做报告，未登记正式工单。以下是后续执行中若无法在 016.05 内收口时建议登记的候选：

1. L8 slot schema 缺少“联合必填 / 子级约束”表达能力。
   - 证据：Tree 需要表达 `branch` 或 `leaf` 至少一个、每个 Branch 最多一个 Disclosure；当前 schema 只能按 slot 全局 required/multiple/type 校验。
   - 影响：Host L8 只能做浅层 Tree slot 校验，无法完整约束树结构。

2. Tree 当前 runtime 存在硬编码缩进尺寸。
   - 证据：`ChipsTree` 节点使用 `paddingLeft: node.depth * 16px`。
   - 影响：组件库 L10 无头原则与主题 token 接口不完全一致。
   - 建议：016.05 内能改则直接收口；若牵涉布局 token 设计，登记独立工单。

3. Tree a11y 公共基线尚未沉淀。
   - 证据：`组件库/05-可访问性与质量基线.md` 当前覆盖到 Dialog/Popover/Tabs/Menu/Select，未写 Tree 的 `tree/treeitem/group`、`aria-level/setsize/posinset`、方向键规则。
   - 影响：后续实现缺少公开验收口径。
   - 建议：016.05 同步公共文档；若需要跨 DataGrid/List 抽象统一 roving focus 工具，登记到任务018。

4. Tree 旧 contract/token 与目标 Compound parts 全量漂移。
   - 证据：组件库、ThemePack、theme-interface contract 均为 `node/toggle/children`。
   - 影响：只改 runtime 会导致主题失效；只改主题会导致 contract 失真。
   - 建议：016.05 必须同轮完成，不建议拆出纯主题临时工单。

## 11. 结论

016.05 的起点不是“给旧 `nodes[]` Tree 加几个静态属性”，而是把 Tree 的公开结构从 `node/toggle/children` 旧数据驱动口径，迁移到 `Root / Item / Branch / Leaf / Disclosure` 的正式 Compound 口径，并同步 runtime、类型、contract、token、ThemePack、Host L8 schema、公共文档和测试。

当前 Tree 已有展开、选择、基础方向键和 `tree/treeitem/aria-level` 基础，适合作为迁移状态机基础；最大风险是命名与主题契约漂移，以及 a11y 层级集合属性、`group`、roving tabindex 没有深测。建议主代理先冻结 `Disclosure` 与 `Label/group` 决策，再从 Root context 和 Branch/Leaf 语义切入，最后收口主题与 Host schema。
