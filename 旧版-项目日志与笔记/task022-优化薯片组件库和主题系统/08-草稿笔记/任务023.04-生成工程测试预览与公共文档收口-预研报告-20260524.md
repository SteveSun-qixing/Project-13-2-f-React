### 2.3 quality gate

023.04 应明确 quality gate 的正式边界：

- 当前 `chipsdev quality gate --json --out reports/quality/quality-gate.json` 是统一读取型摘要。

- 它检查 SDK `src/contracts/route-manifest.json` 是否存在。
- 它读取组件库最新 `reports/quality-gate/quality-gate-latest.json` 与 `reports/perf/perf-stage9-latest.json`。
- 它运行主题 inspect 汇总主题包状态。
- 它不替代各仓正式验证命令，也不执行生成工程自身的 lint/typecheck/test/build/validate。

建议 023.04 补强：

- 在生成工程 e2e 结束后读取 `reports/quality/quality-gate.json`，断言 `kind = chipsdev.quality.gate`、`summary.failedCheckCount === 0`、至少包含 `project.package`、`project.chipsConfig`、`project.manifest`、`sdk.routeManifest`、`theme.inspect`。

## 8. 发现的文档与代码不一致或易误读点

本节只列证据和建议，不创建问题工单，留给主代理判断。

1. `生态共用技术文档/插件开发/02-应用插件开发.md` 已写入较新的模板基线，例如 `AppRuntimeProvider / useAppRuntime()`、命令 adapter、禁止私有 `useChipsBridge`。当前代码与这些点基本一致，但公共文档还没有完整写出目录树、报告路径和 `verify` 脚本链路。
   - 建议：023.04 以当前模板为准补齐“目录 + 脚本 + 报告边界”。

2. `任务023.04` 写“预览 smoke 报告和质量 gate 报告归档到 `reports/`”。当前模板已写入生成工程 `reports/preview` 与 `reports/quality`，但 `.gitignore.tpl` 忽略 `reports`。
   - 建议：明确“归档”是生成工程本地报告落点，默认不纳入版本控制；若要提交基线报告，需要调整 `.gitignore.tpl` 和 README 口径。

3. `chipsdev preview` 支持 `--mode host` 参数，但当前 `createPreviewReport` 对 mock/host 都是 reportOnly，并不会启动真实 Host。
   - 建议：公共文档继续写“真实应用窗口联调用 `chipsdev run`”，不要把 `preview --mode host` 描述成真实 UI 自动化。

4. `chipsdev quality gate` 名称容易被理解为会执行全量质量门禁；当前实现是读取型汇总。
   - 建议：应用插件文档和 README 明确 `npm run verify` 中的 lint/typecheck/test/build/validate 才是生成工程自身执行型门禁，`quality:gate` 是生态报告摘要。

5. 模板运行时源码禁止 Node/Electron 直连，但 `src/preview/preview-smoke.js.tpl` 与生成工程 e2e 测试使用 Node `fs`。
   - 建议：文档明确 `src/preview` 与 `tests` 是开发验证脚本，不属于 Host 托管应用运行时代码。

6. 当前模板启动图标 SVG 有硬编码颜色；运行时 UI 文档要求视觉走主题 token。
   - 建议：将 `manifest.ui.launcher.icon` 的品牌资源与运行时 `ChipsIcon / IconDescriptor` 分层写清。应用启动图标不等同于运行时 UI 主题皮肤。

## 9. 最高优先级风险

最高优先级风险是：023.04 若只看 `npm run test:e2e` 已执行 `npm run verify`，但不读取并断言生成工程 `reports/preview` 与 `reports/quality`，就可能出现“命令跑过了，但报告语义已经漂移或弱化”的盲区。

建议主代理优先把两个 JSON 报告的机器断言补进 `run-generated-e2e.mjs`，再同步 README 与公共应用插件文档。这样 023.04 的代码门禁、生成工程说明和公共口径才能真正闭环。
