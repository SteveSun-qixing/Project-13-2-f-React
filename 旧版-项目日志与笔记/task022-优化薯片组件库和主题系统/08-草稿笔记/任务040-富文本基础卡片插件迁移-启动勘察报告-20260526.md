## 2. 当前现状

`richtext-BCP` 已具备 vNext 基础形态：`manifest.yaml` 声明 `base.richtext`，入口导出 `renderBasecardView`、`renderBasecardEditor` 和 `basecardDefinition`，内部使用 Milkdown 渲染/编辑 Markdown，支持 inline/file 双存储，并已有资源 URL 解析与 `file://` 文本读取逻辑。

## 3. 主要差距

1. 配置正式值仍以 `card_type: RichTextCard` 持久化，与 `basecardDefinition.cardType = base.richtext` 不一致。
2. schema 尚未显式表达 Markdown/GFM/数学公式/高亮/下划线/上下标能力。
3. `collectResourcePaths` 只收集 `content_file`，尚未收集 Markdown 正文中的内部资源引用。
4. 编辑态 UI 主要是手写 DOM/CSS，尚未接入 `@chips/component-library` 运行时图标组件。
5. 编辑态缺少状态栏，无法直接反馈存储模式、可见字符数和当前校验状态。
6. 查看态内部链接目前只改写为 URL，尚未优先通过 `openResource(...)` 上抛资源打开意图。
7. `package.json` 缺少 `typecheck`、`package`、`verify` 正式脚本。
8. 插件内部文档与当前公共契约存在字段口径漂移，需要随代码同步更新。
