## 2. 028.05 建议目标与最小边界

### 2.1 合理任务目标

任务028.05 建议聚焦为“设置面板正式权限与 Host 真实链路测试补强”，目标是证明当前设置面板在 vNext AppRuntime/Commands、SDK Domain API 和运行时治理链路下：

1. manifest 权限声明与实际 SDK Domain API 消费一致。
2. 缺少关键权限时，设置面板能收到标准 `PERMISSION_DENIED`，进入可读错误态或反馈态，不伪造成功状态。
3. 主题切换、语言切换、插件治理、快捷方式和 Scene command 在 mock Host 与 Host service smoke 中都走正式路由。
4. Host smoke 使用现有 `Chips-Host` / `Chips-SDK` 正式测试入口，不在设置面板里私造 Host、Electron 或 Bridge 运行时。

### 3.2 实际 SDK Domain API 消费

当前设置面板实际消费与权限匹配：

- `SettingsRuntimeService.listThemes()` 调 `client.plugin.query({ type: "theme" })`、`client.theme.list()`、`client.theme.getCurrent()`；安装主题走 `plugin.install -> plugin.enable`；切换主题走 `theme.apply`（`Chips-EcoSettingsPanel/src/shared/runtime/settings-runtime-service.ts:118`、`:161`、`:170`）。
- 语言治理走 `client.i18n.listLocales()`、`client.i18n.getCurrent()`、`client.i18n.setCurrent(locale)`（`settings-runtime-service.ts:186`、`:207`）。
- 应用插件治理走 `plugin.query/getShortcut/install/enable/disable/uninstall/launch/createShortcut/removeShortcut`（`settings-runtime-service.ts:215`、`:259`、`:300`、`:316`、`:324`、`:332`）。
- 卡片/布局/模块插件治理走 `plugin.query({ type })`、`plugin.install()` 后 `plugin.get()` 校验类型，再启停卸载（`settings-runtime-service.ts:267`、`:285`）。
- 文件选择、显示位置、确认和消息已通过 SDK platform Domain API：`client.platform.openFile()`、`shellShowItemInFolder()`、`showConfirm()`、`showMessage()`，不再裸 `client.invoke("platform.*")`（`settings-runtime-service.ts:340`、`:348`、`:372`、`:380`）。
- AppRuntime 使用 `client.platform.getLaunchContext()` 读取启动上下文（`Chips-EcoSettingsPanel/src/app/AppRuntimeProvider.tsx:54`）。
- AppProviders 注入组件库 `ChipsEnvironmentProvider`，其中 `SETTINGS_PANEL_PERMISSIONS` 与 manifest 当前一致（`Chips-EcoSettingsPanel/src/app/AppProviders.tsx:23`、`:150`）。
- Scene commands 通过 `client.command.register/onInvoked/unregister/invoke`（`Chips-EcoSettingsPanel/src/commands/useSettingsCommands.ts:42`、`:57`、`:75`、`:84`）。

### 3.3 权限缺口判断

当前未发现“设置面板 manifest 少声明了已消费 SDK API 所需权限”的缺口。按 SDK route manifest 复核，所有当前消费动作都有对应权限：

- `theme.list/apply/getCurrent/contract.get/resolve` 分别需要 `theme.read/write/read/read/read`。
- `i18n.getCurrent/listLocales/setCurrent` 分别需要 `i18n.read/read/write`。
- `plugin.query/install/enable/disable/uninstall/get/launch/getShortcut/createShortcut/removeShortcut` 分别需要 `plugin.read/manage/manage/manage/manage/read/manage/read/manage/manage`。
- `platform.dialogOpenFile/dialogShowMessage/dialogShowConfirm/shellShowItemInFolder` 分别需要 `platform.read/read/read/external`。
- `command.register/unregister/list/invoke/setState` 分别需要 `command.write/write/read/invoke/write`。

028.05 暂不建议新增 `control.read` / `control.write`、`window.control`、`resource.read`、`card.read`、`box.read` 等权限。`surface.open(target=plugin)` 真实需要 `window.control + plugin.manage`，但当前设置面板启动应用插件走 `plugin.launch()`，未消费 `client.surface.open()`；如果 028.05 改为用 surface 预览应用插件，就会越出最小边界。

## 8. 推荐实施顺序

1. 先登记公共文档漂移工单  
   仅登记，不要在 028.05 开头顺手改公共文档；正文证据见第 7 节。

2. 锁定权限清单  
   从 `manifest.yaml`、`AppProviders.SETTINGS_PANEL_PERMISSIONS`、SDK route manifest 自动/半自动比对当前设置面板实际 action，补 `basic-flow` 或新增 `permissions.test.ts`，防止 manifest 与前端环境权限清单漂移。

   对 `theme.apply`、`i18n.setCurrent`、`plugin.install/enable/disable/uninstall/createShortcut/removeShortcut/launch`、`platform.openFile/shellShowItemInFolder/showConfirm/showMessage` 注入标准 `PERMISSION_DENIED`，断言 `SettingsRuntimeService` 不吞错、不改状态、错误 code/message 可读。

   在 `useSettingsCommands` 或专门 command hook 测试中让 `client.command.register` 和 `client.command.invoke` 拒绝，断言 `phase === "error"`、`errorCode === "PERMISSION_DENIED"`，并保证卸载清理不抛未处理异常。

   使用 SDK mock Host 或现有 hook harness，覆盖 `theme.apply -> theme.changed -> listThemes/RuntimeProvider refresh` 与 `i18n.setCurrent -> language.changed -> listLanguages/RuntimeProvider refresh`，不要只测单个事件回调。

## 10. 启动结论

任务028.05 可以启动，但应先把它收束为权限与 smoke 测试补强，不扩张为新功能页实现。当前设置面板 manifest 与实际 SDK Domain API 消费基本一致，最大缺口在测试：缺权限不足负例、缺设置面板自身 Host smoke、缺主题/语言切换完整动作链路。Host/SDK 底座已有正式测试和脚本，应优先复用。

唯一需要先登记的风险是公共文档漂移：`06-Chips-Host对外接口基线.md` 漏列已经落地的 `command` 子域/服务域，`07-运行时设置治理接口标准.md` 的设置面板权限基线也滞后于 vNext command 与 `platform.external` 现实。登记后，028.05 可继续在设置面板范围内补测试，不需要等待 Host/SDK 新能力。
