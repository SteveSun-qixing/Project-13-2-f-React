## 4. `check-templates.cjs` 建议增加的门禁

建议把门禁拆成三层，避免误杀模板变量和测试中的安全示例。

### 4.1 原始模板结构门禁

- 模板目录非空，`template.json`、`manifest.yaml.tpl`、`package.json.tpl`、`chips.config.mjs.tpl`、`README.md.tpl`、`tsconfig.json.tpl`、`vitest.config.mts.tpl`、`.eslintrc.cjs.tpl`、`i18n/*.json.tpl`、`src/**`、`tests/**` 必备。
- `template.json.supports.sdk === true`，`supports.componentLibrary === true`。
- `.tpl` 中只允许已知占位符：`PROJECT_NAME/TARGET_DIR/TEMPLATE_ID/PLUGIN_ID/CARD_TYPE/DISPLAY_NAME/VERSION/AUTHOR_NAME/AUTHOR_EMAIL`。
- 原始模板不得出现 `TODO`、`FIXME`、`app-standard`、`chips dev`、`chips-scaffold-basecard`（模板内部脚本自身检查字符串除外）。
- card manifest 模板不得出现 `ui.surface`。

### 4.2 生产源码门禁

适用 `templates/card-standard/src/**/*.{ts,tsx,css}` 和生成后的同类文件：

- 禁止 `node:fs`、`fs.`、`window.chips`、`localStorage`、`sessionStorage`、系统绝对路径、`file://` 作为业务实现路径。
- 禁止持久化 `blob:`、`data:`、`http://`、`https://` 作为资源路径；测试中的非法路径样例可豁免。
- 禁止 `box-shadow`、`radial-gradient`、`rgba(`、硬编码十六进制色值等运行时视觉值；静态 `assets/icons/*.svg.tpl` 需单独白名单或独立资产规则。
- 禁止旧原生表单样板 `<input`、`<textarea`、私有旧类名 `chips-basecard-editor__input`；若 024.04 最终需要浏览器文件选择控件，应以明确 `input type="file"` 白名单处理，不回退旧表单样板。
- 生产源码不得直接写用户可见中文/英文句子；允许稳定 i18n key、技术字段名、测试文件中的断言文案和 `i18n/*.json.tpl`。

### 4.3 渲染后生成工程门禁

建议 `check-templates.cjs` 直接用模板引擎渲染到 `os.tmpdir()` 后检查：

- 生成结果不包含 `{{ ... }}`。
- 生成结果不包含 `chips-scaffold-basecard`、`app-standard`、不应保留的 `card-standard` 模板身份。
- 不生成 `需求文档/`、`技术文档/`、`技术手册/`、`开发计划/`。
- `manifest.yaml` 满足 `type: card`、`entry: dist/index.mjs`、完整 `runtime.targets`、`capabilities.cardTypes[0]`。

## 5. `run-generated-e2e.cjs` 是否应改为正式 CLI 链路

结论：应改为正式 `chipsdev create card` 链路。当前 CLI 已支持，不存在“CLI 不支持所以只能替代验证”的阻断。

### 5.1 CLI 支持证据

- `Chips-SDK/cli/index.js` 的 `handleCreate(args)` 解析 `chipsdev create <type> <targetDir>`。
- 同文件存在 `type === 'card'` 分支：
  - 定位 `Chips-Scaffold/chips-scaffold-basecard`；
  - 要求 `dist/src/index.js`；
  - 调用 `createBasecardProject(options)`；
  - 调用 `adaptWorkspaceDependencies(options.targetDir)` 完成工作区注册与 `volta.extends`。
- `Chips-SDK/tests/run-cli-create-card-workspace-tests.cjs` 已通过 sandbox 方式验证：
  - `node cli/index.js create card validation-projects/card-smoke`；
  - 根 `workspaces` 包含生成工程；
  - 生成工程 `volta.extends === "../../package.json"`；
  - 执行 `npm install`；
  - 执行 `npm run lint`、`npm run build`、`npm test`、`npm run validate`、`node cli/index.js package`。

因此，`scripts/run-generated-e2e.cjs` 中“chips dev 尚未实现 create 集成”的注释已经是旧口径风险。

### 5.2 推荐 e2e 方案

建议 024.05 将 `run-generated-e2e.cjs` 改为：

1. 在 `os.tmpdir()` 创建临时生态工作区，不再写入脚手架自身 `node_modules/`。
2. 写入临时根 `package.json`，包含 `chips-ecosystem-workspace`、`workspaces`、`volta` 和必要 overrides。
3. symlink 当前 worktree 的 `Chips-SDK`、`Chips-Scaffold`、`Chips-ComponentLibrary`、必要时 `ThemePack` 到 sandbox。
4. 设置 `CHIPS_ECOSYSTEM_ROOT=sandboxRoot` 与独立 npm cache。
5. 调用 `node <sandbox>/Chips-SDK/cli/index.js create card validation-projects/basecard-e2e`。
6. 在 sandbox 根执行 `npm install`。
7. 在生成工程执行 `npm run verify`；若未新增 `verify`，则显式执行：
   - `npm run lint`
   - `npm run build`
   - `npm test`
   - `npm run validate`
   - `npm run package` 或 `node <cliPath> package`
8. 断言：
   - 根工作区注册了生成工程；
   - 生成工程 `volta.extends` 正确；
   - `dist/index.mjs` 存在；
   - `.cpk` 产物存在；
   - `manifest.yaml` 与 `src/index.ts` 契约对齐；
   - 构建产物不残留 `process.env.NODE_ENV`。
9. finally 删除 sandbox。

### 5.3 最优替代验证方案

如果 024.05 实施时主代理发现当前 CLI 因最新主线变化临时不可用，应先给出真实错误证据。最优替代不是回退到长期直接调用模板引擎，而是：

- 短期保留 `renderTemplateToTarget` 作为脚手架核心单元测试；
- 在 `test:e2e` 中仍构造临时生态工作区，并尽量通过 `Chips-SDK/cli/index.js` 的 create 分支触发；
- 若 create 分支真实缺失或阻断，登记工单后临时把 `run-generated-e2e.cjs` 标注为“CLI 缺口替代验证”，且必须继续执行生成工程 `lint/build/test/validate/package`。

按当前复核证据，不需要走替代方案。
