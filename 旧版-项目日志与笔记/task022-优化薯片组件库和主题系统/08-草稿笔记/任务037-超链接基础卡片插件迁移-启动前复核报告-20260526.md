## 当前状态

`hyperlink-BCP` 已有基础 `renderBasecardView`、`renderBasecardEditor`、`basecardDefinition`、schema、i18n 与测试，但仍停留在简单 URL + 锚文本形态。

主要缺口：

- 查看态缺少描述、图标、打开方式、密度和安全提示。
- 当前 `openHyperlinkInSystemBrowser()` 在缺少 `openResource` 时回退 `transfer.openExternal` / `platform.openExternal`，这不符合任务037要求的正式基础卡片边界。
- schema 只校验 `http/https`，没有输出结构化安全状态、风险提示和 URL 归一结果。
- 编辑器尚未使用组件库正式表单/输入/按钮/提示组件。
- 测试未覆盖危险链接提示、宿主回调缺失降级、键盘打开、扩展字段和 a11y 语义。

## 正式迁移方向

1. 超链接卡片只表达外部链接资源打开意图，不直接调用系统浏览器。
2. 有效链接点击时调用宿主 `openResource({ resourceId, mimeType: "text/html", title, fileName, payload })`，由外层容器统一进入 Host `resource.open`。
3. 宿主未提供 `openResource` 时，查看态降级为不可打开的静态状态并展示多语言提示。
4. 配置扩展为 `anchor_text/url/description/icon_url/open_mode/display_density/show_security_hint`，保留 `HyperlinkCard` 作为内容别名，并通过 `basecardDefinition.cardType = "base.hyperlink"` 对齐正式类型。
5. UI 文案全部进入插件 i18n，视觉使用 `--chips-*` token 与组件库公开接口点。
