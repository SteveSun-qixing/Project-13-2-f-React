## 4. 数值解析、边界、键盘与 a11y 建议

### 4.1 共享数值模型

建议在组件库内部抽出私有共享 helper，覆盖 `NumberInput / Stepper / Slider`：

- `toFiniteNumber(value, fallback)` 可参考现有实现，但第五批需要处理空值和解析失败。
- `normalizeNumericRange({ min, max, step })`
  - `min` 默认 `0`。
  - `max` 默认 `100`。
  - `max <= min` 时不做沉默反转；建议输出诊断并回退到 `0..100`，避免无声改变业务语义。
  - `step` 必须为正有限数，默认 `1`。
- `clampNumericValue(value, min, max)`
  - 将提交后的数值夹取到 `[min, max]`。
- `alignNumericStep(value, { min, step, precision })`
  - 步进时以 `min` 为基准做 step 对齐。
  - 小数 step 需要按 step/min/value 的小数精度做 rounding，避免 `0.1 + 0.2` 这类浮点误差暴露给 UI。
- `getNextNumericValue(current, direction, modifiers)`
  - `direction` 为 increment/decrement。
  - `PageUp/PageDown` 可使用 `largeStep`，默认 `step * 10`。

### 4.2 NumberInput 解析与提交时机

建议：

- 控制值和显示文本分层：
  - `value?: number | null` 表示已解析数值。
  - 内部 `textValue` 表示用户正在编辑的原始文本。
  - `onInputChange(text, event)` 可选通知原始输入。
  - `onValueChange(value, details, event)` 只在成功解析或清空提交时通知正式数值。
- 不建议每次按键都强制 clamp，否则用户输入 `-`、`.`、`1.`、`0.0` 等中间态会被破坏。
- 建议在 blur、Enter、stepper 按钮、ArrowUp/Down 时提交并 clamp。
- 空输入：
  - 如果 `required=false`，允许 `null` 并输出 `data-empty="true"`。
  - 如果 `required=true`，blur 时进入 error 或通过业务传入 error 表达。
- 解析失败：
  - 不应静默变成 `0`。
  - 应保持原文本，输出 `aria-invalid="true"`，通过 status part 暴露错误信息。
  - 错误文案必须由 props/i18n 传入或 fallback，经统一 i18n 解析；组件里不要硬编码用户可见中文/英文。

### 4.3 min/max/step/clamp 规则

建议统一：

- `min`、`max`、`step` 均接受 number，非有限数走默认值并输出诊断。
- `step` 默认 `1`；`step <= 0` 走默认值并输出诊断。
- increment/decrement 后总是按 step 对齐并 clamp。
- `NumberInput` 与 `Stepper` 在到达边界时：
  - 根输出 `data-at-min/max`。
  - 对应按钮设置 `disabled`。
  - 同步 `aria-disabled="true"`，但不要新增非标准 `data-state="min|max"`。
- `Slider` 到达边界时：
  - 根或 thumb 输出 `data-at-min/max`。
  - thumb 仍可聚焦，除非组件整体 disabled。

### 4.4 键盘操作建议

`NumberInput`：

- 输入框使用 `role="spinbutton"` 或原生 number spinbutton 语义二选一；基于部分输入态和跨浏览器一致性，建议使用 `type="text" inputMode="decimal" role="spinbutton"`。
- `ArrowUp` 增加 `step`。
- `ArrowDown` 减少 `step`。
- `PageUp` 增加 `largeStep`，默认 `step * 10`。
- `PageDown` 减少 `largeStep`。
- `Home` 设置为 `min`。
- `End` 设置为 `max`。
- `Enter` 提交当前文本并 clamp。
- `Escape` 可恢复上一次 committed value；若实现该能力，需要测试和文档同步。

`Stepper`：

- 增减按钮使用真实 `button`，保留 Space/Enter 原生激活。
- 当焦点在 root 或 value part 上时，可支持 `ArrowUp/ArrowRight` 增加、`ArrowDown/ArrowLeft` 减少、`Home/End` 到边界。
- 横向/纵向方向要通过 `data-orientation` 与键盘语义明确；RTL 如需支持，建议在文档中明确 ArrowLeft/Right 是否反向。

`Slider`：

- thumb 使用 `role="slider"`，可聚焦。
- `ArrowRight / ArrowUp` 增加一步。
- `ArrowLeft / ArrowDown` 减少一步。
- `PageUp / PageDown` 使用 `largeStep`。
- `Home / End` 跳转到 `min / max`。
- pointer drag 和 track click 需要更新同一数值模型，并输出同一 `onValueChange`。

### 4.5 a11y 语义建议

通用：

- 三个控件都必须通过 `label/labelKey/aria-label/aria-labelledby` 提供可访问名称。
- 描述、错误信息使用 `aria-describedby` 串接 description/status。
- error 时输出 `aria-invalid="true"`。
- disabled 时输出 `aria-disabled`，真实可禁用控件同步设置 `disabled`。
- loading 时应阻止交互并进入 `data-state="loading"`。

`NumberInput`：

- control 输出 `role="spinbutton"`。
- 输出 `aria-valuemin / aria-valuemax / aria-valuenow`。
- 如果显示格式和数值不同，输出 `aria-valuetext`。
- 解析失败或空值时谨慎处理 `aria-valuenow`；无有效数值时不应输出错误的 now。

`Stepper`：

- root 使用 `role="group"` 或等价语义。
- decrement/increment 按钮必须有 `aria-label` 或 `aria-labelledby`。
- value part 可使用 `aria-live="polite"`，但不要对每次按住连续更新造成过度播报；可让业务决定是否显示 live value。

`Slider`：

- thumb 输出 `role="slider"`、`tabIndex=0`、`aria-valuemin/max/now`、`aria-valuetext`。
- root 可使用 `role="group"` 承载 label/description/status。
- track/range 视觉元素应 `aria-hidden="true"`，避免重复读屏。

## 6. 风险点与建议批次拆分

### 6.1 风险点

1. `NumberInput` 的“正在编辑文本”和“已提交数值”容易混淆
   如果每次输入都自动 clamp，用户无法输入负号、小数点、中间态；如果完全不解析，又无法正确输出 spinbutton aria value。建议明确 raw text 与 committed value 两层模型。

2. 小数 step 精度风险
   `0.1`、`0.01` 等 step 容易产生浮点误差。建议统一用 step/min/value 推导精度后 round，不要直接暴露 JS 浮点结果。

3. `NumberInput` 与 `Stepper` 的关系风险
   如果 NumberInput 内部直接嵌套完整 Stepper scope，主题 CSS、事件和可访问名称会出现双组件边界。建议共享 helper 和按钮行为，不强行嵌套完整独立组件。

4. 边界状态不能污染 `data-state`
   `min / max / empty / invalid` 不属于公共标准状态集合。建议使用 `data-at-min/max`、`data-empty`、`data-invalid`，`data-state` 保持标准集合。

5. Slider pointer 与 keyboard 一致性风险
   track click、drag thumb、方向键、PageUp/PageDown、Home/End 必须走同一数值模型，否则容易出现 UI ratio 与 aria value 不一致。

6. 主题命中面积与视觉尺寸风险
   Slider thumb 和 Stepper 按钮需要可操作命中面积，但组件库不能硬编码视觉皮肤。建议用 token/CSS 保证触控面积，同时组件只输出稳定结构。

7. 主题 contract 组件数同步风险
   默认主题与暗色主题 contract 当前均为 60 个组件。第五批新增后，主题 contract、token、CSS、测试断言必须同步，否则 `validate:theme` 会阻断。

8. 主代理并行修改风险
   当前主代理正在本地实现第四批 `SegmentedControl / ComboBox`。第五批实现时不要复用或覆盖主代理正在修改的选择控件区域；如发现同一文件已有新改动，应先读取并合并上下文。

### 6.2 建议拆分

建议第五批分为三段推进：

1. 数值模型与 contract 草案先落地
   先完成共享数值 helper、token 命名、contract 文件和公共文档草案，保证三组件规则一致。

2. `NumberInput / Stepper` 同批实现
   两者共享 min/max/step、边界禁用、按钮递增递减、spinbutton/按钮 a11y 语义，适合同一批完成。

3. `Slider` 独立实现
   Slider 涉及 thumb、track、range、pointer drag、orientation、ratio CSS 变量，交互路径和视觉结构更独立，建议单独实现和验证。
