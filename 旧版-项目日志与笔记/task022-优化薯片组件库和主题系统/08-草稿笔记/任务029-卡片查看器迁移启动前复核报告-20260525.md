## 1. 任务029目标与验收口径摘要

任务目标：

- 将 `Chips-CardViewer` 迁移到新前端框架基线。
- 让 `Chips-CardViewer` 成为 `.card` 与 `.box` 的正式查看入口。
- 保持查看器定位为 Host 统一卡片显示链路的消费方和应用壳层。

- `.card/.box` 从 Host 启动上下文进入查看器后的行为保持一致。

- 箱子显示只消费 Host box runtime 和已安装布局插件，不在查看器内重写布局逻辑。
- 查看器与编辑引擎查看态共享同一显示契约。
- 主题和语言变化需要同步到应用壳层与内容 iframe。
- 正式验证命令至少覆盖：

```bash
cd Chips-CardViewer

npm test
npm run build
```

### 2.4 卡片/箱子显示链路

文件与关键符号：

- `Chips-CardViewer/src/components/CardWindow.tsx`
  - `CardWindow` 接收 `filePath`、`locale` 和各种状态文案。
  - 调用 `client.document.window.render({ filePath, locale, mode: "view" })`。
  - 渲染结果 `FrameRenderResult.frame` 被挂入 `containerRef`。
  - 监听 `client.document.window.onReady(...)`。
  - 监听 `client.document.window.onError(...)`。
  - 监听 `client.document.window.onResourceOpen(...)` 并调用 `client.resource.open(...)`。
  - cleanup 时执行 `frameResult.dispose()` 并移除 iframe。
- `Chips-SDK/src/api/document.ts`
  - `DocumentApi.detectType(filePath)` 识别 `.card/.box`。
  - `document.window.render(...)` 对 `.card` 调用 `cardApi.compositeWindow.render(...)`。
  - `document.window.render(...)` 对 `.box` 调用 `boxApi.documentWindow.render(...)`。
  - `document.window.onReady(...)` 同时监听 `chips.composite:ready` 与 `chips.box-layout:ready`。
  - `document.window.onError(...)` 同时处理 `chips.composite:fatal-error` 与 `chips.box-layout:error`。
  - `document.window.onResourceOpen(...)` 当前只代理 `cardApi.compositeWindow.onResourceOpen(...)`。
- `Chips-SDK/src/api/card.ts`
  - `card.compositeWindow.render(...)` 调用 Host `card.render`，要求 mode 仅为 `view | preview`，由 Host 返回 `view.documentUrl` 后创建 iframe。
  - `card.compositeWindow.onResourceOpen(...)` 监听 `chips.composite:resource-open`。
- `Chips-SDK/src/api/box.ts`
  - `box.documentWindow.render(...)` 先 `box.inspect`，再 `box.readLayoutDescriptor`、`box.normalizeLayoutConfig`、`box.getLayoutInitialQuery`、`box.openView`、`box.renderLayoutFrame`。
  - iframe dispose 时执行 `box.releaseRenderSession` 与 `box.closeView`。
  - `attachBoxLayoutRuntimeBridge(...)` 桥接布局 iframe 的 `chips.box-layout:runtime-request`，支持 `listEntries`、`readEntryDetail`、`renderEntryCover`、`resolveEntryResource`、`readBoxAsset`、`prefetchEntries`、`openEntry`。

结论：

- 主文档显示链路已经基本符合“查看器只消费 SDK/Host 正式文档窗口”的方向。
- `.box` 当前由 SDK/Host box runtime 分发到布局插件，查看器没有重写布局加载和箱子资源定位，这是任务029应保留的核心基础。
- `document.window.onResourceOpen(...)` 只代理卡片复合窗口资源打开；箱子布局条目打开多数通过 `box.documentWindow.runtime.openEntry -> box.openEntry` 在 SDK runtime bridge 内部处理。若任务029想把箱子布局资源打开也统一暴露给查看器壳层，需要先核对或补充公共契约，不应由查看器私自扩展事件协议。

### 2.5 托管文档分支

文件与关键符号：

- `Chips-CardViewer/src/components/HostedDocumentWindow.tsx`
  - 通过 `documentUrl` 创建 iframe。
  - 直接监听 `window.message`。
  - 处理 `chips.composite:ready`、`chips.composite:resize`、`chips.composite:fatal-error`、`chips.composite:resource-open`。
  - 通过 `bridge.emit("plugin.surface.resize", payload)` 发布 `plugin.surface.resize`。
  - iframe `sandbox="allow-scripts allow-same-origin allow-popups"`。
  - 文档标题硬编码为 `title="Hosted Card Document"`。

用途判断：

- `App.tsx` 中只有 `launchParams.webDocumentUrl` 会进入 `OpenedTarget.kind === "document"`，因此它可能是 web route 或 Host 托管文档嵌入场景。
- 该分支属于用户可见使用逻辑的一部分，任务029不能无证据删除。
- 迁移时应先确认 Host 侧是否仍会传入 `launchParams.webDocumentUrl`；如果保留，应映射为正式 Document scene/surface 模型，并优先复用 `EmbeddedDocumentFrame` 或 SDK/组件库正式事件订阅能力。
- 当前 message handler 只检查 `event.source === frame.contentWindow`，没有复用 SDK `subscribeToFrameMessage` 的 origin 白名单逻辑；迁移时应作为安全与契约复核点处理。

| Scene | `OpenedTarget` 在 `App.tsx` 内部分支 | `scene-registry.ts` 显式 scene | 建议拆 `empty/document-file/hosted-document` 场景 |
| LaunchContext | `App.tsx` 直接读 `client.platform.getLaunchContext()` | `readLaunchContext(...)` 生成正式 surfaceContext fallback | 迁移 `targetPath`、`webDocumentUrl`、`surfaceContext.documentContext` |
| Commands | 无 `src/commands` | `app-commands.ts + useAppCommands.ts` | 打开文件入口至少应注册为 command |
| 菜单/工具栏/快捷键 | 无 | `ChipsCommandProvider`、`ChipsMenuBar`、`ChipsToolbar`、`ChipsCommandPalette` | 第一阶段可最小接入，不改变首屏主操作 |
| i18n | `messages.ts` 私有同步解析 | `localeBundles + useChipsI18nText + useAppText` | 命令和业务文案统一走同步 adapter |
| 主题 | 读取 DOM 注入 + `ChipsThemeProvider` | Environment hook 读取 Host theme 状态 | 保留 Host 注入校准，收敛到 AppRuntime |
| 质量脚本 | `lint/test/build/validate` | 额外 `typecheck/preview:smoke/quality:gate/verify` | 补脚本时必须对应真实检查 |
| 测试辅助 | 组件级 mock | `src/testing/mock-environment.ts` 与 `render-with-chips.tsx` | 引入环境级渲染测试，覆盖 runtime |

## 4. 必须保持不变的用户功能、交互和使用逻辑

以下行为在任务029迁移中应作为冻结基线：

1. 空启动进入导入首屏。
   - 当前文案来自 `i18n/*.json`：标题“拖入卡片或箱子文件”，主按钮“打开文件”。
   - 旧测试明确 `App` 首屏不展示额外“卡片查看器”品牌标题。

2. 支持拖拽 `.card/.box` 文件到窗口打开。
   - 当前入口：`DropZone.handleDrop(...)`。
   - 路径解析：优先 `window.chips.platform.getPathForFile(file)`，fallback 到 `file.path`。

3. 支持点击“打开文件”按钮调起 Host 文件选择器。
   - 当前入口：`App.handleOpenFile(...)`。
   - Host 能力：`client.platform.openFile(...)`。

4. 只接受 `.card` 和 `.box`。
   - 当前判断：`client.document.detectType(...)`。
   - 不支持时显示 `card-viewer.errors.unsupportedFile`。

   - 当前读取：`client.platform.getLaunchContext().launchParams.targetPath`。
   - 触发来源可能包含 `file-association`、`app-shortcut`、`chipsdev.run`。

6. 保留 `webDocumentUrl` 托管文档场景，除非主代理确认 Host 已废弃。
   - 当前读取：`launchParams.webDocumentUrl`。
   - 当前组件：`HostedDocumentWindow`。

7. `.card` 与 `.box` 显示都走 `client.document.window.render({ filePath, mode: "view" })`。
   - `.card` 由 SDK 分发到 `card.compositeWindow.render(...)`。
   - `.box` 由 SDK 分发到 `box.documentWindow.render(...)` 和 Host box runtime。

8. 加载态、错误态、资源打开失败提示保留可诊断信息。
   - 当前组件：`CardWindow`、`HostedDocumentWindow`。
   - 当前错误提示：`documentContainerError`、`documentFatalError`、`documentRenderError`、`resourceOpenFailed`。

9. 资源打开必须继续通过 `client.resource.open(...)`。
   - 不得硬编码图片查看器、音乐播放器、阅读器或具体 app plugin id。

10. 主题与语言变化要继续影响应用壳层。
    - 当前事件：`theme.changed`、`language.changed`。
    - 迁移后应通过组件库 Environment/AppRuntime 接线，而不是取消响应能力。

11. 文档窗口的沉浸式显示语义保持。
    - 当前 `surfaceMode: "immersive"` 使用满高、隐藏外层滚动。
    - `HostedDocumentWindow` 的 `surfaceMode: "document"` 使用自然高度和 `plugin.surface.resize`。

12. cleanup 必须保持。
    - `CardWindow` 当前移除 frame、注销事件、调用 `dispose()`。
    - `HostedDocumentWindow` 当前移除 message/resize 监听、清理 animation frame 和 timer。

## 7. 风险点与主代理现场复核证据位置

1. `web.supported: true` 是否真实成立。
   - 证据：`Chips-CardViewer/manifest.yaml`。
   - 现状：代码依赖本地路径、文件对话框、拖拽路径、`webDocumentUrl`。
   - 建议：先核对 Host web route 当前传参和能力，不能为了模板统一随手改成 false 或保留 true。

2. `webDocumentUrl` 是否仍是正式启动参数。
   - 证据：`Chips-CardViewer/src/App.tsx` 的 `resolveWebDocumentUrl(...)` 与 `HostedDocumentWindow`。
   - 风险：如果这是 Host/外部 route 仍在使用的入口，删除会破坏用户路径；如果已废弃，应登记依据后再收口。

3. `HostedDocumentWindow` 的 postMessage 安全口径。
   - 证据：`Chips-CardViewer/src/components/HostedDocumentWindow.tsx` 只检查 `event.source`。
   - 对照：`Chips-SDK/src/api/document.ts` 的 `subscribeToFrameMessage(...)` 还检查 `isAllowedFrameOrigin(...)`。
   - 建议：迁移时优先复用 SDK/组件库正式 iframe 事件能力。

4. `document.window.onResourceOpen(...)` 只代理 card composite 资源打开。
   - 证据：`Chips-SDK/src/api/document.ts` 中 `onResourceOpen` 返回 `cardApi.compositeWindow.onResourceOpen(...)`。
   - 影响：当前 CardWindow 的资源打开监听对 `.box` 布局文档不一定生效；箱子条目打开由 `box.documentWindow.runtime.openEntry` 内部处理。
   - 建议：不要在 CardViewer 内私自扩展箱子事件；若任务029需要统一资源打开诊断，先补 SDK/公共契约。

5. 多 SDK client 实例可能导致命令和事件状态分裂。
   - 证据：`src/App.tsx`、`CardWindow.tsx`、`HostedDocumentWindow.tsx` 都通过 `useChipsClient(...)` 创建 client。
   - 建议：迁移到 `src/runtime/chips-client.ts` 单例和 `ChipsEnvironmentProvider`。

6. Commands 接入会触发 manifest 权限约束。
   - 证据：`生态共用技术文档/协议与契约/13-命令系统契约.md`，`Chips-SDK/src/api/command.ts`，`Chips-Host/src/main/services/register-host-services.ts`。
   - 风险：command definition 里的 `permission` 必须已在 manifest 中声明，注册调用方也要有 `command.write`。

7. 现有 README 已落后于代码。
   - 证据：`Chips-CardViewer/README.md` 仍写 `client.card.compositeWindow.render({ cardFile, mode: 'view' })`，但当前 `CardWindow` 实际使用 `client.document.window.render({ filePath, locale, mode: "view" })`。
   - 建议：任务029完成后更新 README，不要在第一阶段先改 README 造成与代码二次漂移。

8. DropZone 拖拽路径链路在 web route 上可能不可用。
   - 证据：`DropZone.resolveNativeFilePath(...)` 使用 `window.chips.platform.getPathForFile` 或 `file.path`。
   - 建议：desktop/window 保留；web/route 若支持，应走正式 launch/resource/document context，而不是要求浏览器 File 暴露路径。

9. 主题 token 仍有硬编码。
   - 证据：`CardWindow.css` 中 document-flow `background: #ffffff`；`DropZone.tsx` 中大量 inline size/radius/shadow。
   - 建议：作为迁移整理项处理，但不应在第一阶段重做视觉。

10. 缺少真实文件样本回归。
    - 证据：`tests/` 当前主要是 jsdom mock。
    - 建议：主代理需要现场查找 `ProductFinishedProductTestingSpace/` 或其他测试素材，确认 `.card/.box` 样本路径，再补回归。
