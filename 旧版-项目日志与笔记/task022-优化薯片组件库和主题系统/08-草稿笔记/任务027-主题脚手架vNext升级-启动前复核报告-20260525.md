## 3. 相关设计与公共规范要点

### 3.1 主题系统边界

- Host 主责 L1-L9 运行时，组件库只做 L10 无头组件，SDK 只做类型、封装、脚手架和测试辅助。证据：`生态设计原稿/06-前端多样化和主题系统.md:3-8`。
- 主题包负责颜色、字体、圆角、阴影、边框、动效与图标；组件库不承载视觉样式。证据：`生态设计原稿/06-前端多样化和主题系统.md:21-24`。
- 一个主题包只承载一种完整外观；暗色外观必须作为独立 `themeId` 主题包交付。证据：`生态设计原稿/06-前端多样化和主题系统.md:25`。
- 主题运行时正式链路为安装 `type: theme` 插件、启用后进入 Host 可用主题集合，再由 `theme.list/getCurrent/getAllCss/resolve/apply` 执行。证据：`生态设计原稿/06-前端多样化和主题系统.md:33-44`。

### 3.2 插件与 Manifest 口径

- 插件类型固定为 `app/card/layout/module/theme` 五类。主题插件是视觉样式包，包含 tokens、components、motions、icons 等视觉资源。证据：`生态设计原稿/07-插件系统架构.md:19-31`。
- 主题包标准结构包含 `manifest.yaml`、`tokens/`、组件样式、motion、`icons/variablefont/*`、contracts 与 preview。证据：`生态设计原稿/07-插件系统架构.md:40-55`。
- `manifest.yaml` 基础字段必填 `id/name/version/type/entry`；`theme` 类型的 `entry` 必须为对象并声明 `tokens` 与 `themeCss`。证据：`生态共用技术文档/插件开发/06-Manifest配置规范.md:15-49`。
- 所有正式插件应声明完整 `runtime.targets` 四目标矩阵。证据：`生态共用技术文档/插件开发/06-Manifest配置规范.md:50-83`。
- `type: theme` 应声明 `runtime.targets`，入口继续使用 `entry.tokens / entry.themeCss`。证据：`生态共用技术文档/插件开发/06-Manifest配置规范.md:232-235`。

### 3.3 主题包正式工程口径

- 主题包开发指南要求 CPK 包含 `tokens/ref.json/sys.json/motion.json/layout.json/comp/`、`src/build-tokens.ts/build-contracts.ts/build-css.ts/validate-theme.ts`、`dist/tokens.json/theme.css/icons/variablefont/*.woff2`、contracts 等。证据：`生态共用技术文档/主题系统/01-主题包开发指南.md:7-60`。
- 主题 Manifest 示例要求 `entry.tokens: dist/tokens.json`、`entry.themeCss: dist/theme.css`、`themeId`、`displayName`、`ui.layout.contract`、`ui.layout.minFunctionalSet`。证据：`生态共用技术文档/主题系统/01-主题包开发指南.md:62-92`。
- 正式主题包必须声明并覆盖组件库当前全部正式 component contract，公共来源为 `Chips-ComponentLibrary/packages/theme-contracts/contracts/components/*.contract.json` 和 `@chips/theme-contracts` API。证据：`生态共用技术文档/主题系统/01-主题包开发指南.md:98-114`。
- `dist/tokens.json` 正式结构是 `ref/sys/comp/motion/layout` 五层，Theme Runtime 按 `ref -> sys -> motion/layout -> comp` 解析引用。证据：`生态共用技术文档/主题系统/01-主题包开发指南.md:115-132`、`生态共用技术文档/架构设计/15-主题系统设计.md:246-260`。
- 运行时正式产物只有 `dist/tokens.json`、`dist/theme.css` 和 `dist/icons/variablefont/*.woff2`。证据：`生态共用技术文档/主题系统/01-主题包开发指南.md:148-157`。

### 3.4 图标、motion 与 CSS contract

- 运行时 UI 图标统一使用 `ChipsIcon + IconDescriptor`，主题包必须把 Material Symbols variable font 交付到 `dist/icons/variablefont/`。证据：`生态设计原稿/06-前端多样化和主题系统.md:82-87`。
- 主题包源码必须包含三套 Material Symbols variable font，并在构建阶段复制到 `dist/icons/variablefont/`；`dist/theme.css` 必须注入对应 `@font-face`。证据：`生态共用技术文档/主题系统/03-图标与字体系统设计规范.md:202-210`。
- 图标 token 基线包含 `chips.sys.icon.color/color-muted/color-accent/color-danger/color-disabled/size/size-dense/size-toolbar/size-compact/fill/fill-emphasis/wght/wght-strong/wght-muted/grad/grad-emphasis/grad-muted/opsz`。证据：`生态共用技术文档/主题系统/03-图标与字体系统设计规范.md:212-235`。
- motion 正式基线包含 `duration/easing/delay/stagger/distance/opacity/scale/reduced/scene/overlay/menu/list/drag/theme`，`styles/motions.css` 至少提供 fade/overlay/menu/scene/list/drag/theme 七类入口并支持 reduced motion。证据：`生态共用技术文档/主题系统/01-主题包开发指南.md:400-451`。
- 主题 CSS 覆盖门禁至少要确认每个正式 component contract 的 `scope` 存在对应 `data-scope="<scope>"` 选择器。证据：`生态共用技术文档/组件库/03-Token与主题对接标准.md:300-315`。

SDK tooling 的 `theme inspect` 会读取主题 manifest、entry、contracts、tokens、dist 产物，并检查 required token 缺失，但它只是诊断报告，不替代生成工程的正式 Host install/apply smoke。证据：`Chips-SDK/src/tooling/developer-tools.cjs:275-393`、`396-424`。

### 4.5 Host 主题运行时当前状态

Host `PluginRuntime` 会把 `type: theme` manifest 解析为 `theme` 元信息，要求 `themeId`、`displayName/name`、`entry.tokens`、`entry.themeCss`，并读取 `ui.layout.contract` 作为 contract path。证据：`Chips-Host/src/runtime/plugin-runtime.ts:1084-1123`。

Host 只从已启用 `type: theme` 插件加载主题；加载时读取 `dist/tokens.json`、`dist/theme.css` 与 contract，并重写 CSS 资源 URL。证据：`Chips-Host/src/main/services/register-host-services.ts:889-927`。

`theme.resolve` 通过 `resolveThemeChain -> mergeThemeLayers -> resolveThemeFromLayers` 解析，返回 resolved、tokens、diagnostics、summary；`theme.apply` 前会调用 `validateThemeContractWithTokens()` 阻断缺失 required token 的主题。证据：`Chips-Host/src/main/services/register-host-services.ts:2958-3050`、`4002-4025`。

Host token 解析算法已支持按 `ref -> sys -> motion/layout -> comp` 解析，并允许本层递归引用、检测循环引用。证据：`Chips-Host/src/main/theme-runtime/resolve-algorithm.ts:163-194`。这与已解决工单102一致。

Host preload 会在插件窗口中并行调用 `theme.getCurrent`、`theme.getAllCss`、`theme.resolve`，注入主题 CSS、`data-chips-theme-id`、`data-chips-theme-version` 与 CSS variables，并监听 `theme.changed` 刷新。证据：`Chips-Host/src/preload/plugin-window.ts:186-240`。

## 5. 已一致的点

1. 公共文档、Host 和两个正式主题包已经统一到“主题插件 + dist/tokens.json + dist/theme.css + contract”的主链路。
2. 两个正式主题包均遵守“一包一外观”，默认主题与暗色主题分别有独立 `themeId`。
3. 两个正式主题包已接入 `@chips/theme-contracts`，contract 与 min functional set 均从组件库正式 contract 生成。
4. 两个正式主题包已具备 Material Symbols 三套 variable font 源码和 dist 产物，`build-css` 会注入 `@font-face`。
5. Host `theme.resolve/apply/getAllCss/contract.get` 已转向已启用主题插件数据源，并在 `theme.apply` 前执行 required token contract 阻断。
6. `chipsdev package` 的 ZIP Store、包根 manifest、dist 产物收集规则基本符合主题包 CPK 结构需要。
7. 根工作区当前已声明 `chips-host` / `chips-sdk` devDependencies，可降低全局旧 CLI 误命中的风险。证据：`package.json:25-28`。

## 6. 漂移、缺口与风险

### P0：脚手架模板仍是旧 token / contract 骨架

`chips-scaffold-theme` 当前模板仍以 `global/semantic/typography/components` 为源，组件 token 和 CSS 都是 button/input 最小样例，contract 只有旧式 button 极小集合。这与任务027要求的 `ref/sys/motion/layout/comp/*.json`、70 组件 contract、正式 CSS scope 覆盖完全不一致。

风险：若直接进入生成工程 E2E，默认新主题包很可能无法通过 `validate:theme`、`theme.apply` 和 Host contract guard。

推荐处理：以 `ThemePack/Chips-default` 当前结构为基线，把模板源目录、build scripts、contracts、tests、styles 分批回灌到 `theme-standard`。

### P0：模板 `validate-theme` 维护私有 token 白名单

模板 `src/validate-theme.ts.tpl` 当前的 `REQUIRED_THEME_TOKENS` 是私有最小列表，与任务027“默认接入组件库正式 theme contract 校验，不维护脚手架私有最小 token 列表”直接冲突。

风险：新增组件 contract 后，脚手架生成主题仍可能“本地 validate 通过但 Host apply 阻断”。

推荐处理：改为引入 `@chips/theme-contracts`，复用官方主题包 `validate-theme.ts` 与 `build-contracts.ts` 的模型。

### P0：脚手架缺少生成工程 Host 安装/启用/切换 smoke

任务027要求“增加生成主题包安装到 Host 开发工作区后的 smoke 测试”，当前脚手架自身只有普通 Vitest，生成工程测试也只检查文件存在。

风险：模板可能通过本地 build/test，但 `chipsdev package -> chipsdev plugin install/enable -> chipsdev theme apply/current/validate` 链路失败时无法提前发现。

推荐处理：新增生成工程 E2E，至少覆盖 `create -> npm install/依赖就绪 -> npm run build -> npm run validate:theme -> npm test -> chipsdev validate -> chipsdev package -> 隔离 CHIPS_HOME Host install/enable/apply/current/validate`。

### P1：`chipsdev create theme` 参数与 ID 推导不可靠

当前 SDK CLI 写死 `themeId: 'chips-official:default-theme'`，且未消费 create 参数；脚手架自动 pluginId 推导对冒号形式会生成 `theme.default-theme.chips-official`，与官方 `theme.theme.chips-official-default-theme` 不一致。

风险：生成多个主题时 ID 冲突或不符合官方命名；也可能继续扩散历史冒号 themeId 形式。

推荐处理：在 `chipsdev create theme` 中正式支持 `--theme-id`、`--display-name`、`--plugin-id`、`--publisher`、`--template`、`--parent-theme-id`、`--version` 等参数；默认从目标目录推导第三方安全 ID，不应写死官方默认主题 ID。

### P1：`chips.config.mjs` 使用 `distDir`，CLI 主字段是 `outDir`

模板和 ThemePack 的 `chips.config.mjs` 都写 `distDir: "dist"`，当前 `chipsdev` 读取 `outDir`，未读取 `distDir`。由于默认 `outDir` 回退也是 `dist`，当前未直接爆炸，但字段名存在漂移。

风险：后续主题工程如果改 `distDir`，`chipsdev validate/package/publish` 仍会使用默认 `outDir`，造成验证和打包错目录。

推荐处理：任务027可二选一收口：模板改为 `outDir: "dist"`；或 SDK CLI `loadProjectConfig()` 明确兼容 `distDir` 并沉淀公共配置口径。

### P1：SDK `chipsdev validate` 对 theme 缺少专属语义门禁

当前 `chipsdev validate` 只检查 Manifest 和资源存在，不检查 theme contract 等值、五层 token 引用可解析、字体 dist 产物、CSS scope 覆盖等。`theme inspect` 有报告能力，但不是 validate 的阻断门禁。

风险：生成主题工程的 `npm run validate` 若只走 `chipsdev validate`，无法替代 `validate:theme` 和 Host smoke。

推荐处理：生成工程 package scripts 明确区分：

- `validate`：`chipsdev validate && npm run validate:theme`
- `verify`：`npm test && npm run build && npm run validate && npm run package && npm run smoke:host`

若要让 `chipsdev validate` 本身懂 theme 语义，可能需要另开 SDK tooling 收口工单。

### P1：Host contract guard 未把 `motionConstraints[].tokenKeys` 合并进 required token

组件库 `@chips/theme-contracts` 会把 `motionConstraints[].tokenKeys` 合并进 required token；但 Host `contract-guard.ts` 当前 `normalizeRequiredTokens()` 只读取 `requiredTokens ?? tokens`，未显式合并 `motionConstraints[].tokenKeys`。证据：`Chips-Host/src/main/theme-runtime/contract-guard.ts:56-65`。官方 ThemePack 生成后的随包 contract 已把 motion token 合入 `requiredTokens`，因此当前官方主题不会暴露问题；但第三方主题如果手写 contract 且遗漏合并，Host 可能放过缺失 motion token。

风险：公共规范要求 Host/SDK/主题包校验器共享诊断模型，Host 与 `@chips/theme-contracts` 在手写 contract 输入下存在潜在漂移。

推荐处理：任务027可先保证脚手架生成 contract 始终由 `@chips/theme-contracts` 生成；若主代理判断这是 Host 公共门禁缺口，应登记新工单补强 Host contract guard。

### P2：旧脚手架内部文档仍描述 `global/semantic/typography/components` 源层

`chips-scaffold-theme/技术文档/01-主题包插件脚手架技术架构与模板设计.md` 仍写源 token 为 `global/semantic/typography/motion/components`，与当前公共主题包开发指南和任务027要求不一致。证据：`Chips-Scaffold/chips-scaffold-theme/技术文档/01-主题包插件脚手架技术架构与模板设计.md:67-75`、`156-158`、`171-194`。

风险：任务027代码改完后，内部文档会继续误导后续维护者。

推荐处理：任务027实现后，按“修改文档前重新核对代码”的要求，同步更新脚手架内部技术文档/需求文档/README；跨生态正式口径仍以 `生态共用技术文档/主题系统` 为主。

## 7. 建议改动范围与顺序

### 7.1 第一优先级：把模板源结构升级为 ThemePack vNext 同构

建议主代理先以 `ThemePack/Chips-default` 为基线，升级 `templates/theme-standard/`：

- `tokens/global.json.tpl` -> `tokens/ref.json.tpl`
- `tokens/semantic.json.tpl` -> `tokens/sys.json.tpl`
- `tokens/components/*.json.tpl` -> `tokens/comp/*.json.tpl`
- 补齐 `motion.json.tpl` 为 `chips.motion.*`
- 补齐 `layout.json.tpl` 为正式 `chips.layout.*`
- 至少让生成工程的 `dist/tokens.json` 能通过官方 contract required token 覆盖。

如果全量复制 70 个组件 token/CSS 体量过大，仍不建议保留旧 button/input 私有最小模板。更安全的选择是把官方主题包当前 tokens、styles、scripts、tests 作为 `theme-standard` 的完整默认基线，再由用户修改外观值。

### 7.2 第二优先级：接入 `@chips/theme-contracts`

建议模板默认包含：

- `src/build-contracts.ts`
- `src/validate-theme.ts`
- `contracts/theme-interface.contract.json`
- `contracts/theme-min-functional-set.json`
- `package.json.tpl` 中的 `@chips/theme-contracts` file 依赖与 `build:contracts`

并让 `npm run build` 顺序与官方主题包一致：

```bash
npm run build:tokens && npm run build:contracts && npm run build:css
```

### 7.3 第三优先级：生成工程脚本与质量门禁

建议生成工程补齐脚本：

- `build:tokens`
- `build:contracts`
- `build:css`
- `build`
- `validate:theme`
- `validate`
- `package`
- `smoke:host`
- `verify`
- `test`

其中 `validate` 建议为 `chipsdev validate && npm run validate:theme`，`verify` 覆盖 build/test/validate/package/smoke。

### 7.4 第四优先级：脚手架自身测试升级

建议 `chips-scaffold-theme` 补齐：

- 模板文件存在与禁止占位符检查；
- 生成工程结构检查；
- 生成工程 `npm run build` / `npm test` / `npm run validate:theme`；
- 生成工程 `chipsdev validate` / `chipsdev package`；
- 隔离 `.chips-host-dev` 或 `CHIPS_HOME` 的 Host smoke；
- 检查生成工程不包含 `TODO`、旧 `global/semantic/components` 源目录、旧 `tokens` contract 字段。

### 7.5 第五优先级：SDK CLI create theme 参数收口

建议同步修改 `Chips-SDK/cli/index.js` 的 `handleCreate(type === 'theme')`：

- 消费 `--template`;
- 新增/消费 `--theme-id`、`--display-name`、`--version`、`--publisher`、`--parent-theme-id`、`--plugin-id`;
- 默认 themeId/pluginId 从目标目录推导，不使用官方默认主题；
- 生成后仍调用 `adaptWorkspaceDependencies()`。

该部分属于任务027涉及的 `chipsdev create` 闭环，若主代理认为范围偏大，至少应在报告中登记为同任务后半段或后续子任务。

## 9. 潜在新增工单候选

以下只列候选，不在本次子代理范围内登记正式工单：

1. **Host contract guard 与 `@chips/theme-contracts` 的 motionConstraints required token 合并口径漂移**  
   Host 当前依赖随包 contract 已合并 required token；若第三方手写 contract，`motionConstraints[].tokenKeys` 可能不进入 Host required token 阻断。建议主代理判断是否登记 Host 主题契约门禁补强工单。
