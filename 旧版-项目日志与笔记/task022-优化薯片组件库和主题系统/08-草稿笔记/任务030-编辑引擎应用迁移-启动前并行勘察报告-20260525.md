# 任务030启动前并行勘察报告

## 1. 项目确认

任务030真实目标应为 `Chips-EditingEngine`，不是 `Chips-RichTextEditor`。

证据：

- `Chips-EditingEngine/AGENTS.md` 明确本项目是“编辑引擎正式应用工程”。
- `06-工单级开发任务/任务030-编辑引擎应用迁移.md` 指定项目为 `Chips-EditingEngine`。
- `Chips-RichTextEditor` 是单一富文本编辑器应用，有自己的 `技术手册/需求文档/开发计划`，可作历史参考，但不应作为任务030主迁移对象。

本次只读勘察未修改文件，未执行 `git add/commit/branch`，未启动长期服务。

## 2. 当前架构现状

`Chips-EditingEngine` 已经不是空白旧项目，底层编辑能力已有较多正式实现。

现有入口和壳层：

- `manifest.yaml` 已是 `type: app`、`entry: dist/index.html`，并声明 `ui.surface.defaultKind: window`。
- 正式脚本已有 `dev/run/build/test/lint/validate`。
- 当前根仍是单体 `src/App.tsx`，初始化、工具窗口、工作区事件、拖拽创建、主题语言事件都集中在这里。
- Provider 仍是旧式 `src/context/index.tsx` 组合，没有 `src/app/AppRuntimeProvider.tsx / AppShell.tsx / scene-registry.ts` 这种 vNext 应用骨架。

编辑运行时：

- 基础卡片注册中心已存在，能通过 Host `plugin.query({ type: "card" })` 按 `installPath + entry` 动态加载已安装卡片插件。
- 内置描述符直接从工作区源码导入 `Chips-BaseCardPlugin/*/src/index`，符合“内置描述符”过渡口径，但后续需收口为明确的官方内置来源边界。
- `CompositeCardAssembler`、`BasecardFrameHost`、`EditorHost`、`EditorSessionStore` 基本对齐共享标准中的编辑态本地运行时特例。

箱子链路：

- 箱子预览已经通过 `client.document.window.render({ filePath, documentType: "box" })`。
- 箱子配置编辑已经通过 `client.box.editorPanel.render(...)` 和 `client.box.normalizeLayoutConfig(...)`。
- 卡箱库布局列表走 `client.box.listLayoutDescriptors()`。

## 3. 与任务029 CardViewer vNext 基线差距

CardViewer 已形成清晰的 vNext 应用骨架：

- `src/app/AppRoot.tsx` 轻量组合 Provider 和 Shell。
- `AppRuntimeProvider` 统一解析 launch/surface/scene/theme/i18n/error。
- `scene-registry.ts` 明确内部 scene。
- commands 通过 SDK command registry 注册，并接入组件库 adapter。

EditingEngine 主要差距：

- 缺 `src/app/` vNext 应用运行时骨架。
- 缺正式 `src/commands/` Host command registry 接入。
- 现有 `core/command-manager.ts` 是内部 undo/redo 历史栈，不等同于生态命令系统。
- README 快速开始路径仍指向旧 worktree `Project-13-2-f-task008-图标系统搭建`。
- 项目还没有 `Chips-EditingEngine/技术文档/`，内部架构验收矩阵可在任务030闭环时补齐。

## 4. 建议的任务030.x混合串并行拆分

建议不要机械细拆，按“壳层基线 -> 运行时契约 -> 功能链路 -> 验收闭环”拆分。

建议主线：

- `030.03`：Commands 正式接入与内部历史栈分界。

## 5. 必须保持不变的用户可见功能

迁移时必须保持这些行为：

- 启动后默认出现文件管理器、编辑面板、卡箱库三个工具窗口。
- 工作区从 launch params 的 `workspacePath/workspace` 恢复；没有 workspace 时进入不崩溃的空绑定状态。
- 文件管理器支持新建卡片、新建箱子、打开、重命名、删除、刷新、搜索、拖拽。
- 卡箱库从已安装基础卡片描述符和箱子布局描述符生成条目，不按固定 cardType 写死。
- 卡片窗口保留编辑/查看锁定、封面切换、设置、最小化/收起、标题重命名、封面 iframe、内容驱动高度、画布滚动代理。
- 箱子窗口预览和右侧编辑面板保持：配置/内容列表两个标签、导入作品、排序、布局配置。
