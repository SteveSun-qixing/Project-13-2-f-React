## 任务017目标与边界

任务017目标是为组件库和应用统一 State、Environment、Binding 与表单状态模型，落点以 `@chips/hooks` 和 `@chips/components` 为主。

验收重点：

- `useChipsState / useChipsAsyncState / useChipsFormState / createBinding / useBinding` 有运行时、类型声明和测试。
- `Input/TextField/Select/Checkbox/Switch/Form` 的绑定消费方式一致，优先适配既有 `value/onValueChange`、`checked/onCheckedChange`、`open/onOpenChange` 口径。
- async 状态明确覆盖 `idle/loading/success/error` 或等价状态转换。
- 测试覆盖本地状态、异步成功/失败、字段绑定、表单字段更新/错误/重置等转换。

不应做事项：

- 不把 Host runtime 主实现搬进 SDK 或 hooks；系统能力仍只走 `window.chips.*` / Bridge / `chips-sdk`。
- 不在 `ChipsForm` 组件本体里实现业务校验、dirty/touched、持久化或配置写入；这些属于 hook/form state 层。
- 不新增第三方状态库或表单库。
- 不扩展 016.08 质量门禁收口、018 焦点键盘 a11y、019 测试工具门禁、020+ 主题包升级范围。

## 当前代码现状

已存在能力：

- `@chips/hooks` 已有 `ChipsEnvironmentProvider`、`useChipsEnvironment`、`useChipsClient`、`useChipsTheme`、`useChipsI18n`、`useChipsI18nText`、`useChipsSurface`、`useChipsPermission`、`useChipsCommand`、`useChipsDiagnostics`。
- `@chips/testing` 已有 `createMockChipsClient/createMockChipsEnvironment`，可支撑 Provider 测试。
- `chips-sdk/testing` 已有真实 SDK client 驱动的 mock Host/Bridge、权限错误、timeout/retry、surface/theme/i18n/command 模拟器。
- `ChipsForm` 已落地 `Root/Section/Field/Label/Control/Error/Hint`，公共文档中 `form-field/form-group/helper` 已归档。
- 组件内部已有私有 `useControllableState`，`Select/SegmentedControl/ComboBox/DatePicker/TimePicker` 等已按受控/非受控模式运行；`Checkbox/Switch` 使用 `checked/defaultChecked/onCheckedChange`。

主要缺口：

- `@chips/hooks` 尚无 `useChipsState/useChipsAsyncState/useChipsFormState/createBinding/useBinding/useFieldBinding` 运行时与类型。
- hook 测试目前主要覆盖导出、theme/i18n mock 与变量注入，缺状态转换测试。
- 组件没有公开统一 Binding helper；现状是各控件直接消费各自受控 props。
- app-standard 模板已接入 Environment Provider，但示例表单仍是 `ChipsInput` + 本地无绑定示例，未展示统一 Binding/Form state。
- Host L8 `bindings` 当前只校验非空字符串映射并在 L9 normalizer 中透传；没有 React Binding path 解析实现。这符合边界，任务017不应把状态实现写进 L8/L9。

可能漂移：

- 任务方案/调研文档仍写“缺少统一 Environment”，但当前代码已完成任务011环境入口；后续报告应改按“Environment 已有，017 扩展 State/Binding/Form”表述。
- 公共组件文档已有 Environment Hooks 小节，但尚无正式 State/Binding/Form hooks 使用口径。
- `ChipsForm.Control` 克隆自定义 Chips 控件时会注入 `id/aria-*`，而部分输入控件会把 `id` 落在根节点、不是内部 control；建议任务017补专项测试，必要时在任务017或018范围内修正。

## 建议最小实施顺序

1. 先冻结 hook API：优先看 `Chips-ComponentLibrary/packages/hooks/src/index.js` 与 `Chips-ComponentLibrary/packages/hooks/src/index.d.ts`，新增 State/Async/Binding/Form state 运行时与类型。
2. 先用 helper 适配既有控件 props，不建议 P0 给每个组件新增 `binding` prop；Binding 应输出 `value/onValueChange`、`checked/onCheckedChange`、`open/onOpenChange` 等标准 props。
3. 补测试：`Chips-ComponentLibrary/packages/hooks/tests/index.test.mjs` 覆盖状态转换、async 成功/失败、binding set/reset、form field 更新和错误。
4. 再看组件一致性：`Chips-ComponentLibrary/packages/components/src/index.js` 的 `ChipsInput/ChipsTextField/ChipsSelect/ChipsCheckbox/ChipsSwitch/ChipsForm`，只在必要时补兼容 Binding 的 props 转发或测试。
5. 若更新 mock，优先复用 `chips-sdk/testing`，组件库 testing 只做 Provider-ready 包装。
6. 脚手架模板不是任务017主范围；如要展示新 Binding 示例，再改 app-standard 模板和模板测试。
