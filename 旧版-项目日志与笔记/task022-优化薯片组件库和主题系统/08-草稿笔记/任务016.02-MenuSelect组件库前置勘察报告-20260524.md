## 2. 总体结论

`ChipsSelect` 和 `ChipsMenu` 当前都还是单体 props API，不具备任务 016.02 要求的 Compound 静态子组件导出。

- Select 当前通过 `value/defaultValue/open/defaultOpen/options[]` 管理选择与展开，运行时 part 是 `root / trigger / value / icon / list / option / status`。目标 API 是 `Select.Root / Trigger / Content / Option / Value`，最大差距是 `Content` 与当前公开 part `list` 的命名冲突，以及当前没有高亮索引、`aria-activedescendant` 和方向键选择闭环。
- Menu 当前通过 `open/defaultOpen/items[]/closeOnSelect` 管理展开、高亮和选择，运行时 part 是 `root / trigger / content / item / status`。目标 API 是 `Menu.Root / Trigger / Content / Item / Group / Separator`，最大差距是没有 `Group / Separator` 运行时、类型、contract、token 和 CSS 挂点。
- Host L8 目前已有 `StandardCompoundSlotSchemas.Menu`，且包含 `group/separator`；但组件库 runtime/contract 尚未补齐。Host L8 尚无 `StandardCompoundSlotSchemas.Select`。
- 主题 contract 与默认/暗色主题目前支持 Select 的 `list`，不支持 Select `content`；Menu 主题只覆盖 `content/item`，不覆盖 `group/separator`。016.02 如果一次性收口公开 part，必须同步 contract/token/CSS 后续任务，不能只改组件库运行时。

- Root：`div`，`aria-disabled`，`data-open`。

- Content：`ul role="menu"`，`id=contentId`。
- 外层 item wrapper：`li role="none"`。
- Item 按钮：`button role="menuitem"`，高亮项 `tabIndex=0`，其他 `tabIndex=-1`，禁用项输出 `disabled` 和 `aria-disabled`。
- 当前未使用 `aria-activedescendant`；菜单焦点模型是 roving tabIndex。

## 5. 与 016.02 目标 Compound API 的差距

### 5.1 Menu 目标差距

目标：

- `Menu.Root`
- `Menu.Trigger`
- `Menu.Content`
- `Menu.Item`
- `Menu.Group`
- `Menu.Separator`

当前差距：

- 只有 `ChipsMenu` 单体导出；`ChipsMenu.Root/Trigger/Content/Item/Group/Separator` 均不存在。
- `items[]` 数据驱动模式无法表达任意 children slot、分组标题、分隔线或自定义 item 内容。
- `Group` 和 `Separator` 没有运行时 part、类型声明、contract、token、CSS selector 和测试。
- Host L8 已有 `StandardCompoundSlotSchemas.Menu`，包含 `group/separator`，但组件库 contract 和 runtime 未对齐。
- 当前高亮状态只输出 `data-highlighted`，而 contract/token/CSS 主要围绕 `data-state` 的 `hover/active` 写法。迁移时应明确 item state 的映射规则。

### 5.2 Select 目标差距

目标：

- `Select.Root`
- `Select.Trigger`
- `Select.Content`
- `Select.Option`
- `Select.Value`

当前差距：

- 只有 `ChipsSelect` 单体导出；`ChipsSelect.Root/Trigger/Content/Option/Value` 均不存在。
- `options[]` 数据驱动模式无法表达显式 slot，也无法让 `Select.Value` 从上下文读取并渲染选中项。
- 当前弹层公开 part 是 `list`；目标子组件名是 `Content`。任务文本要求“统一 Select 的 `Content/list` 公共命名”，这是本工单的核心收口点。
- Host L8 当前没有 `StandardCompoundSlotSchemas.Select`。
- 当前没有 highlighted option、方向键、Home/End、Enter 选择、`aria-activedescendant` 和 option id。
- 当前选中项只输出 `data-selected`，但默认/暗色主题 CSS 依赖 `option[data-state="active"]` 做 selected 视觉。

## 6. 推荐完整实现方案

### 6.1 总原则

- 采用 Compound Components，`Root` 是唯一知道状态实现的 Provider。
- 子组件只消费上下文、注册自身 metadata、输出 DOM/ARIA/data attributes，不自行维护完整业务状态。
- 不为当前未发布第一版保留长期双 API。若主代理认为需要短期迁移辅助，应在同一任务内清理到单一正式 API，不把 `items[]/options[]` 与 children Compound 长期并列为公开标准。
- 不引入新第三方库；沿用现有 React、`useControllableState`、`useInteractiveState`、`normalizeItems`、`getNextEnabledIndex`、`createScopeAttributes`、`isKeyboardActivationKey` 等本地能力。
- item/option 级视觉状态要从上下文派生：disabled、highlighted、selected 应能稳定落到 `data-state` 或明确的公开 data attribute；主题 contract 和 CSS 必须按同一口径消费。

### 6.2 Menu Root 上下文建议

`MenuRootContext` 建议包含：

state：

- `open: boolean`
- `disabled: boolean`
- `loading: boolean`
- `error: StandardErrorLike | null`
- `state: InteractiveState`
- `highlightedValue: string | null`
- `items: Array<{ value: string; disabled: boolean; textValue?: string; id: string; ref?: HTMLElement | null }>`
- `closeOnSelect: boolean`

actions：

- `setOpen(nextOpen: boolean, event?: EventLike): void`
- `openMenu(event?: EventLike): void`
- `closeMenu(event?: EventLike): void`
- `toggleOpen(event?: EventLike): void`
- `registerItem(meta): () => void`
- `highlightValue(value: string | null): void`
- `highlightFirst(): void`
- `highlightLast(): void`
- `highlightNext(loop?: boolean): void`
- `highlightPrevious(loop?: boolean): void`
- `selectValue(value: string, event?: EventLike): void`

meta：

- `baseId: string`
- `triggerId: string`
- `contentId: string`
- `scope: "menu"`
- `orientation: "vertical"`
- `onSelect?: (value: string, details?: { source: "keyboard" | "pointer"; value: string }) => void`

子组件职责：

- `Menu.Root`：创建 context，输出 `data-scope="menu" data-part="root"`，承载 `data-open`、`aria-disabled`、统一状态和错误 status。
- `Menu.Trigger`：消费 `open/disabled/contentId`，输出 button、`aria-haspopup="menu"`、`aria-expanded`、`aria-controls`、`id=triggerId`；处理 click、Enter/Space、ArrowDown、ArrowUp。
- `Menu.Content`：仅在 `open` 时渲染或使用 `hidden` 收口，输出 `role="menu"`、`id=contentId`、可选 `aria-labelledby=triggerId`；处理 Escape、方向键、Home、End、Enter/Space。
- `Menu.Item`：注册 value/id/disabled/textValue，输出 `role="menuitem"`，可继续用 roving tabIndex；disabled 输出 `disabled/aria-disabled`；highlighted 输出稳定视觉状态。
- `Menu.Group`：输出 `role="group"` 与 `data-part="group"`；如果有 label，应生成 label id 并通过 `aria-labelledby` 关联；Group 自身不参与 item 高亮索引。
- `Menu.Separator`：输出 `role="separator"`、`aria-orientation="horizontal"`、`data-part="separator"`，不参与 item 高亮索引。

键盘和关闭策略：

- Trigger `ArrowDown`：打开，highlight first enabled，并在打开后聚焦 content 或 highlighted item。
- Trigger `ArrowUp`：打开，highlight last enabled。
- Trigger Enter/Space：切换 open；打开时默认 highlight first enabled。
- Content Escape：关闭并恢复焦点到 trigger。
- Content ArrowDown/ArrowUp：循环跳过 disabled item。
- Content Home/End：跳到首/尾 enabled item。
- Content Enter/Space：选择 highlighted item；按 `closeOnSelect` 关闭并恢复焦点。
- 点击 content 外关闭不在当前实现中已有；若主代理要加，应作为完整交互策略和测试一起落地，不做临时外部监听。

ARIA 建议：

- Menu 可以继续采用 roving tabIndex，不强制 `aria-activedescendant`。这样与当前 `button role="menuitem"` 模型一致。
- `aria-controls` 始终由 Trigger 指向 Content。
- `aria-expanded` 始终与 open 一致。
- `aria-labelledby` 建议由 Content 指回 Trigger，Group 指回 Group label。

### 6.3 Select Root 上下文建议

`SelectRootContext` 建议包含：

state：

- `value: string`
- `open: boolean`
- `disabled: boolean`
- `loading: boolean`
- `error: StandardErrorLike | null`
- `state: InteractiveState`
- `highlightedValue: string | null`
- `selectedOption: OptionMeta | null`
- `options: Array<{ value: string; disabled: boolean; textValue?: string; label?: ReactNode; id: string; ref?: HTMLElement | null }>`
- `placeholder?: ReactNode`

actions：

- `setOpen(nextOpen: boolean, event?: EventLike): void`
- `openList(event?: EventLike): void`
- `closeList(event?: EventLike): void`
- `toggleOpen(event?: EventLike): void`
- `registerOption(meta): () => void`
- `highlightValue(value: string | null): void`
- `highlightSelectedOrFirst(): void`
- `highlightFirst(): void`
- `highlightLast(): void`
- `highlightNext(loop?: boolean): void`
- `highlightPrevious(loop?: boolean): void`
- `selectValue(value: string, event?: EventLike): void`

meta：

- `baseId: string`
- `triggerId: string`
- `contentId: string`
- `activeOptionId?: string`
- `scope: "select"`
- `onValueChange?: (value: string, details?: { source: "keyboard" | "pointer"; option?: OptionMeta }) => void`
- `onOpenChange?: (open: boolean) => void`

子组件职责：

- `Select.Root`：创建 context，输出 `data-scope="select" data-part="root"`，承载 `data-open`、`aria-disabled`、错误 status。
- `Select.Trigger`：消费 `open/contentId/activeOptionId/disabled`，输出 button、`aria-haspopup="listbox"`、`aria-expanded`、`aria-controls=contentId`、`aria-activedescendant=activeOptionId`。如果选择沿用 button trigger，应在 trigger 保持 DOM focus，通过 `aria-activedescendant` 指向 highlighted option。
- `Select.Value`：从上下文读取 selected option 的 label/text，未选中时渲染 placeholder；输出 `data-part="value"`。
- `Select.Content`：建议公开 part 一次性改为 `content`，输出 `role="listbox"`、`id=contentId`，并承载 option children。若主代理决定保留 `list` 作为 DOM part，则公共文档、Host schema、contract 必须明确“Select.Content 子组件对应 data-part=list”，否则会形成 `Content/list` 双口径。
- `Select.Option`：注册 value/id/disabled/textValue，输出 `role="option"`、`aria-selected`、`aria-disabled`、`data-selected`、`data-highlighted`，并输出与主题一致的 item/option state。

键盘和关闭策略：

- Trigger Enter/Space：打开；若已打开，选择 highlighted option。
- Trigger ArrowDown：打开并 highlight selected 或 first enabled；已打开则 highlight next。
- Trigger ArrowUp：打开并 highlight selected 或 last enabled；已打开则 highlight previous。
- Trigger Home/End：已打开时跳首/尾 enabled option。
- Trigger Escape：已打开时关闭并保持焦点在 trigger。
- Option click：选择 option、触发 `onValueChange`、关闭并恢复焦点到 trigger。
- Content 可以不接管 DOM focus；如果焦点留在 trigger，则键盘处理集中在 Trigger，`aria-activedescendant` 指向 highlighted option。

ARIA 建议：

- Trigger 保持 `button role="button"`，`aria-haspopup="listbox"`。
- `aria-expanded`、`aria-controls` 始终由 Trigger 指向 Content。
- 打开时 `aria-activedescendant` 指向 highlighted option id；关闭时可移除。
- Content 使用 `role="listbox"`。
- Option 使用 `role="option"` 和 `aria-selected`。
- Disabled option 输出 `aria-disabled`，并在键盘导航中跳过。

### 6.4 Select Content/list 命名建议

建议 016.02 一次性采用：

- 子组件名：`Select.Content`
- DOM part：`content`
- contract part：`content`
- Host L8 schema slot：`content`
- 主题 CSS selector：`[data-scope="select"][data-part="content"]`
- token：新增 `chips.comp.select.content.surface`、`chips.comp.select.content.border` 或至少 `chips.comp.select.content.radius/surface`，具体 token 由主代理按主题系统现有粒度收口。

理由：

- 任务文本明确目标 API 是 `Select.Content`，并要求统一 `Content/list` 公共命名。
- Menu/Dialog/Popover/Tooltip 都使用 `content` 表示弹层主体；Select 统一到 `content` 可以减少复杂组件 slot 口径。
- 当前仍未发布第一版，不建议保留 `list` 作为长期兼容 part。

需要注意：
