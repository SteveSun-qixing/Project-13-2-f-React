## 2. 建议新增或迁移文件

建议以 CardViewer vNext 骨架为参考，但按编辑引擎复杂工作台拆成更厚的 Runtime 层。

- `Chips-EditingEngine/src/app/AppRoot.tsx`：轻量组合 `AppProviders + AppShell`，让 `src/App.tsx` 最终只导出 `<AppRoot />`。
- `Chips-EditingEngine/src/app/AppProviders.tsx`：统一包裹 `ChipsEnvironmentProvider`、`ChipsThemeProvider` 和现有业务 Provider。现有 `src/context/index.tsx` 可改名或继续作为 `EditingEngineStateProviders`，避免一次性打散 `Settings/UI/Editor/Card/Selection/EditorRuntime`。
- `Chips-EditingEngine/src/app/AppRuntimeProvider.tsx`：承载 SDK client、trace/runtime diagnostics、launch/surface、初始化状态、插件事件订阅、语言/主题同步、工作区启动动作。
- `Chips-EditingEngine/src/app/AppShell.tsx`：只负责选择 scene、渲染主工作台、Dock、设置弹窗，消费 runtime/context，不直接做 Host 初始化。
- `Chips-EditingEngine/src/app/scene-registry.ts`：定义内部 scene，如 `workspace-empty`、`workspace-bound`、`card-document`、`box-document`、`settings`、`tool-window`。030.02 先用于运行时心智和测试断言，不需要把所有窗口都改成独立路由。
- `Chips-EditingEngine/src/runtime/chips-client.ts`：把 `services/bridge-client.ts` 的 SDK 单例升级为正式 runtime client 入口，可保留旧导出转发，减少爆炸式改动。
- `Chips-EditingEngine/src/runtime/launch-context.ts`：读取 `client.platform.getLaunchContext()`，归一化 `workspacePath/workspace`、surface、presentation、launchParams。
- `Chips-EditingEngine/src/runtime/environment-client.ts`：适配 `ChipsEnvironmentProvider` 所需 `ChipsClientLike`，包含 theme/i18n/platform/command 入口。
- `Chips-EditingEngine/src/runtime/theme-runtime.ts`：抽出默认主题状态、DOM 初始主题读取、`theme.changed` 后刷新逻辑。
- `Chips-EditingEngine/src/runtime/boot-actions.ts` 或 `src/runtime/workspace-runtime.ts`：集中实现 `syncInstalledBasecardDescriptors`、`i18nService.initLocale`、`workspaceService.initialize`、默认工具窗口创建等可测试动作。

## 3. App.tsx 迁移边界

当前 `App.tsx` 中建议迁走：

- `App` 中 SDK client 创建、`themeEventSource`、`themeState`、初始 `theme/i18n` 同步、`theme.changed/language.changed` 订阅：移入 `AppProviders + AppRuntimeProvider + theme-runtime`。
- `MainWorkspace` 中 `hasInitializedRef` 初始化流程：移入 `AppRuntimeProvider` 或 `boot-actions`，保留“只初始化一次”的 ref/状态机。
- 默认工具窗口 `FileManager/EditPanel/CardBoxLibrary` 创建：移入 runtime action，如 `ensureDefaultToolWindows`，但仍通过 `useUI().createToolWindow` 执行。
- 插件安装/启用/禁用/卸载后刷新基础卡片注册表：移入 runtime 层事件订阅，继续调用 `basecard-runtime/registry.ts`。
- `workspace:file-opened/file-created/file-renamed` 事件到卡片/箱子窗口的分发：可放入 `WorkspaceSceneRuntime` 或 `useWorkspaceWindowBindings`，030.02 不建议和 UI 布局重构混在一起。
- 画布 drop 创建/插入逻辑：可先留在 `WorkbenchScene`，因为它强依赖 `useUI/useCard/useEditorSelection/InfiniteCanvas`；030.02 只把它从根 App 拆到 scene，不要改变行为。
- 设置弹窗状态：放到 `AppShell` 或 `SettingsSceneRuntime`，Dock 仍只触发 `onOpenSettings`。

## 5. 风险与逐步策略

- 最大风险是 React StrictMode 下重复初始化。必须保留 `hasInitializedRef` 或改成 runtime boot 状态机，并测试工具窗口不重复创建。
- `ChipsEnvironmentProvider` 自身会调用 `refresh()`，不要再让外层和内层同时各自刷新 theme/i18n/surface 造成竞态。建议由 `AppProviders` 提供 initial state，`AppRuntimeProvider` 只消费稳定环境。
- `app-config.ts` 的模板 appId 残留应由 030.01 收口；030.02 不应基于 `{{ PLUGIN_ID }}` 继续扩散。
- 不要一次性把 `UIProvider/CardProvider/EditorProvider` 重写为新 runtime store。先把 Provider 包装位置规范化，业务状态后续再拆。
- `useChipsBridge.ts` 是旧直读 `window.chips` Hook，030.02 可不主动碰；只要新骨架不要继续引入它。
- 建议迁移顺序：先新增 runtime/app 文件并保持旧 `MainWorkspace` 行为，再把初始化 effect 搬到 runtime，最后把 workspace 事件和 canvas scene 从 `App.tsx` 分离。

## 6. CardViewer 可复用与不可照搬

可复用：

- `AppRoot -> AppProviders -> AppRuntimeProvider -> AppShell -> Scene` 的层次。
- SDK client 单例文件、launch-context 归一化、environment-client 适配 `ChipsEnvironmentProvider`。
- 用 scene-registry 描述内部 scene，而不是让根组件直接写业务分支。
- App 级 jsdom 测试方式：mock runtime client，验证启动上下文、语言主题事件和渲染结果。

不能照搬：

- CardViewer 是单文档查看器，scene 只在 empty/file/hosted-document 间切换；EditingEngine 是多窗口工作台，scene 不能替代窗口管理器。
- CardViewer 的 `openedTarget` 单状态不适合编辑引擎；EditingEngine 要保留 `UIProvider + window-manager + CardProvider + workspaceService`。
- CardViewer 可在 `AppRuntimeProvider` 里直接处理打开文件；EditingEngine 的文件、卡片、箱子、拖拽链路更复杂，应拆成 workspace/window/canvas runtime hooks。
- CardViewer 的 command chrome 模式属于任务030.03，030.02 只预留 command client，不宜提前重做菜单命令。
