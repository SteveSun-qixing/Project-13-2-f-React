## 2. 023.03 应在 023.02 基础上强化的能力清单

### P0：把命令消费闭环从“同源 metadata”强化到“同源 registry 查询与三入口断言”

当前 `AppShell.tsx.tpl` 已让 `ChipsCommandProvider / ChipsMenuBar / ChipsToolbar / ChipsCommandPalette` 共享 `appCommandViews` 与同一个 `commands.adapter`，`useAppCommands.ts.tpl` 也从 `useChipsClient()` 创建 `createCommandAdapter(client)`，并通过 `client.command.register/invoke/onInvoked/unregister` 接入 SDK。023.03 应继续强化：

- `tests/unit/commands.test.ts.tpl` 增加 `client.command.list({ source: "menu" | "toolbar" | "palette" })` 的断言，证明三入口可查询同一注册结果，而不只是手写 metadata 同源。
- 增加 `resolveCommandToolbarItems / resolveCommandMenuGroups / resolveCommandPaletteItems` 的纯函数断言，证明同一 command view 能派生 toolbar、menu、palette 三种视图。
- 增加 `command.setState` 或 disabled command 的最小断言，证明 disabled/visible 状态由 command registry 元数据驱动，而不是按钮本地状态另起一套。
- 如果 UI 侧继续保留侧边栏里直接调用 `invokeCommand(APP_COMMAND_IDS.xxx, "toolbar")` 的按钮，应明确它只是“导航快捷入口”，并补测试防止它成为菜单/工具栏之外的第二套业务 handler。

### P0：补齐 `ChipsDialog / ChipsErrorState / ChipsIcon / ChipsView / ChipsGrid` 样板

任务023.03 明确默认 UI 要覆盖命令、导航、表单、列表、空态、错误态、主题 token 与多语言 key。当前模板已覆盖 `ChipsForm`、`ChipsVirtualList`、`ChipsEmptyState`、`ChipsNavigationSplitView`、`ChipsCommandPalette`，但未实际使用 `ChipsDialog`、`ChipsErrorState`、`ChipsIcon`、`ChipsView`、`ChipsGrid`。建议：

- 在 `EnvironmentStatusView.tsx.tpl` 或 `StateBindingView.tsx.tpl` 增加 `ChipsDialog` 的完整 compound 示例：`Trigger / Content / Header / Body / Footer / Actions / Close`，文案全部走 i18n。
- 用 `ChipsIcon descriptor={{ name, style }}` 展示运行时 UI 图标，并保留 README 中“运行时 UI 图标不同于 `manifest.ui.launcher.icon`”的口径。
- 用 `ChipsView` 包 App Shell 主区域或 scene root，用 `ChipsGrid` 替换当前 `.app-view-grid` / `.app-status-grid` 中一部分手写 CSS grid，让模板更接近 L8 `View/Stack/Grid/Form/List` 心智。

## 3. 当前 app-standard 真实现状与缺口

### 命令系统

现状：

- `manifest.yaml.tpl` 未声明 `commands:`，权限包含 `command.read/write/invoke`。
- `src/commands/app-commands.ts.tpl` 定义 `APP_COMMAND_IDS`、`handlerId`、`CommandDefinitionInput[]`、`appCommandViews`，命令字段使用 `titleKey / descriptionKey / ariaLabelKey`，含 `menuPlacement / toolbarPlacement / paletteKeywords / icon / scope / state`。
- `src/commands/useAppCommands.ts.tpl` 从 `useChipsClient()` 取得 SDK client，创建 `createCommandAdapter(client)`，注册、注销、调用并监听 `command.invoked`。
- `src/app/AppShell.tsx.tpl` 用 `ChipsCommandProvider` 包裹，并把同一 `commands.adapter` 和 `appCommandViews` 传给 `ChipsMenuBar / ChipsToolbar / ChipsCommandPalette`。
- `tests/unit/commands.test.ts.tpl` 已覆盖 raw 文案字段禁用、SDK mock host 的 register/list/invoke、handlerId 事件处理。

缺口：

- 当前测试只证明 `client.command.list({ source: "toolbar" })` 可调用，未分别验证 menu、toolbar、palette 的同源派生。
- `appCommandViews = appCommandDefinitions as unknown as ChipsCommandView[]` 是当前类型桥接，运行上可接受，但测试应锁定它只作为组件库消费视图，不替代 Host registry。
- 命令 UI 的错误态目前主要是 `<ChipsText>{text(errorWithCode)}</ChipsText>`，未用 `ChipsErrorState` 展示标准错误。
- 当前两个命令都没有 `permission` 字段。公共契约允许 command-specific permission，023.03 可考虑给 `refreshTheme` 声明 `theme.read`，给 open workspace 声明 `command.invoke` 或保持无业务权限；若增加，需确保 manifest permissions 已覆盖。

### 导航与场景

现状：

- `src/app/scene-registry.ts.tpl` 管理 main/settings scene。
- 并行快照中 `src/app/AppRuntimeProvider.tsx.tpl` 从 `useChipsSurface()` 与 launch context 推导 runtime scene。
- `AppShell.tsx.tpl` 使用 `ChipsNavigationSplitView.Sidebar / Content / Detail` 三个 slot，Content 渲染 `MainScene` 或 `SettingsScene`，Detail 放命令面板与运行状态。
- `SceneListView.tsx.tpl` 使用 `ChipsVirtualList` 展示 sceneDefinitions，并通过 `ChipsButton pressed` 选择 scene。

缺口：

- 当前模板未使用 `ChipsView` 作为 scene root，也未使用 `ChipsGrid` 替代手写 grid class。
- 导航侧边栏仍主要是 `ChipsButton` 列表，缺少“scene registry 是单一事实来源”的断言，例如所有 sidebar scene action 来自 registry。
- `ChipsNavigationSplitView` 的 L8 文档 slot 要求 sidebar/content/detail；当前实现符合，但测试未显式锁定三 slot 都存在。

### 主题

现状：

- `AppProviders.tsx.tpl` 用 `ChipsEnvironmentProvider` 注入 `initialTheme`，`RuntimeThemeProvider` 再用 `useChipsTheme()` 的结果传给 `ChipsThemeProvider`。
- `theme/theme-runtime.ts.tpl` 提供 `defaultThemeState` 与 `resolveThemeLabel()`。
- `WorkspaceOverviewView.tsx.tpl`、`EnvironmentStatusView.tsx.tpl` 展示当前主题标签。
- `app-shell.css.tpl` 大部分视觉值来自 `--chips-*` token，React 组件中未见 `style={{`。

缺口：

- `useChipsTheme().apply(themeId)` 没有样板；当前只有 `refreshTheme`。023.03 可以不强行加入主题切换，因为主题治理属于设置面板/后续任务，但可在报告或 README 中明确模板只展示读取与刷新。
- 当前未展示 `ChipsIcon`，因此图标 token 和运行时 IconDescriptor 的样板缺失。
- `check-templates.mjs` 当前禁止 inline style 和旧入口，但还未看到对硬编码颜色、阴影、原始 CSS 色值的完整扫描。

### 多语言

现状：

- 根 i18n 文件 `i18n/zh-CN.json.tpl`、`i18n/en-US.json.tpl` 覆盖当前 shell、scene、commands、workspace、errors。
- `src/i18n/locales.ts.tpl` 导出 `localeBundles`、`supportedLocales`、`translateLocalKey()`。
- `src/i18n/useAppText.ts.tpl` 使用 `useChipsI18n()` 读取当前 locale，并通过 `useChipsI18nText()` 和 `resolveI18nText()` 提供同步 text resolver。
- `AppShell.tsx.tpl` 的语言切换调用 `runtime.setLocale(nextLocale(locale))`，底层来自 `useChipsI18n().setLocale()`。
- 单元测试已覆盖 fallback locale、参数插值、缺失 key 返回 key。

缺口：

- 新增 Dialog/ErrorState/Icon/command disabled reason 后需补全双语 key。
- 当前测试未遍历所有 command key 与视图 key，仍可能出现模板新增 `text("...")` 后漏写 JSON 的情况。
- 公共架构手册中提到 i18n key 统一语义 `i18n.<domain>.<id>`，而当前应用模板使用 `app.*` key；这与 `生态共用技术文档/插件开发/02-应用插件开发.md` 中脚手架样例 `app.commands.*` 一致。建议不在 023.03 改 key 命名，只在后续公共文档收口时由主代理判断是否需要统一说明。

## 4. 组件库真实可用 API / props 速查

### `ChipsCommandProvider`

真实类型：`React.FC<ChipsCommandProviderProps>`

关键 props：

- `adapter?: ChipsCommandAdapter`
- `commands?: ChipsCommandView[]`
- `query?: ChipsCommandQueryOptions`
- `i18n?: I18nTextSource | ((key, params, fallback?) => string)`
- `children?: React.ReactNode`

建议用法：

- 放在 App Shell 命令消费区域外层。
- `adapter` 由 `createCommandAdapter(client)` 生成。
- `commands` 可传本地 command views 作为首屏/测试基线，但正式注册与调用仍应走 SDK/Host command registry。

### `ChipsMenuBar`

真实类型：`React.ForwardRefExoticComponent<MenuBarProps & RefAttributes<HTMLElement>>`

关键 props：

- 继承 `CommandConsumerBaseProps`：`commands / adapter / i18n / query / payload / invocationContext / disabled / loading / error / onCommandInvoke`
- `menus?: Array<{ menuId: string; label?: React.ReactNode }>`
- `ariaLabel?: string`

建议用法：

- `menus` 的 `menuId` 对齐 command `menuPlacement[].menuId`。
- 触发后组件库会经 adapter 以 menu source 调用 command；测试应验证 command payload/source。

### `ChipsToolbar`

真实类型：`React.ForwardRefExoticComponent<ToolbarProps & RefAttributes<HTMLDivElement>>`

关键 props：

- 继承 `CommandConsumerBaseProps`
- `toolbarId?: string`
- `groupId?: string`
- `ariaLabel?: string`

建议用法：

- `toolbarId="main"` 对齐 command `toolbarPlacement[].toolbarId`。
- `groupId` 可用于展示单组；默认可由组件库派生命令项。

### `ChipsCommandPalette`

真实类型：`CommandPaletteCompoundComponent`

Root props：

- `commands?: ChipsCommandView[]`
- `adapter?: ChipsCommandAdapter`
- `i18n?: ChipsCommandProviderProps["i18n"]`
- `commandQuery?: ChipsCommandQueryOptions`
- `payload?: Record<string, unknown>`
- `invocationContext?: Record<string, unknown>`
- `inputPlaceholder?: string`
- `ariaLabel?: string`
- `onSelect?: (item: CommandPaletteItem) => void`

Compound slots：

- `ChipsCommandPalette.Root`
- `Input`
- `List`
- `Item`
- `Group`

建议用法：

- 当前模板使用 root shorthand 已足够；若 023.03 要展示 compound slot，可新增小型自定义 palette 区，但不要复制第二套 command handler。

### `ChipsNavigationSplitView`

真实类型：`NavigationSplitViewCompoundComponent`

Root props：

- `children`
- `disabled / loading / error`
- `ariaLabel / ariaLabelledBy`

Compound slots：

- `Root`
- `Sidebar`
- `Content`
- `Detail`

Region props：

- `as?: keyof React.JSX.IntrinsicElements`
- `children`
- `ariaLabel / ariaLabelledBy`

建议用法：

- 当前模板 slot 用法是正确方向。
- 组件库未导出 `ChipsNavigation`；不要在 023.03 写不存在的 React 组件。

### `ChipsButton`

真实类型：`React.ForwardRefExoticComponent<ButtonProps & RefAttributes<HTMLButtonElement>>`

关键 props：

- `children`
- `type?: "button" | "submit" | "reset"`
- `disabled / loading / error`
- `toggleable / pressed / defaultPressed`
- `onPress?: (MouseEvent | KeyboardEvent) => void`
- `[key: string]: unknown`

建议用法：

- 命令按钮优先通过 Toolbar/Menu/Palette 消费 command registry。
- 普通场景切换按钮可用 `pressed` 表示 active scene。

### `ChipsBadge`

真实类型：`React.ForwardRefExoticComponent<BadgeProps & RefAttributes<HTMLSpanElement>>`

关键 props：

- `label / labelKey / labelParams / fallbackLabel`
- `count / max`
- `tone?: "neutral" | "accent" | "success" | "warning" | "error"`
- `icon`
- `decorative / disabled / error`

建议用法：

- 状态徽标可用 `label={text(key)}`，也可用 `labelKey + i18n`；当前模板使用 `label={text(...)}` 可接受。

### `ChipsIcon`

真实类型：`React.ForwardRefExoticComponent<ChipsIconProps & RefAttributes<HTMLSpanElement>>`

关键 props：

- `descriptor: { name: string; style?: "outlined" | "rounded" | "sharp"; tone?: "default" | "muted" | "accent" | "danger" | "disabled"; fill?: 0 | 1; wght?: number; grad?: number; opsz?: number; decorative?: boolean; label?: string }`
- `size?: number | string`
- `color?: string`
- `tone?: ChipsIconTone`

建议用法：

- 优先传 `descriptor`，不要手写 SVG。
- 不建议传 `color` 硬编码；图标颜色应由 `tone` 与主题 token 控制。

### `useChipsTheme`

真实返回：

- `theme: ChipsThemeState | null`
- `status: "idle" | "loading" | "ready" | "error"`
- `error: ChipsRuntimeDiagnostic | null`
- `refresh(): Promise<ChipsThemeState | null>`
- `apply(themeId: string): Promise<ChipsThemeState | null>`

建议用法：

- 模板默认读当前主题并刷新即可。
- 主题切换治理不建议在 023.03 扩大为完整设置面板能力。

### `useChipsI18n`

真实返回：

- `locale: string | null`
- `status`
- `error`
- `t(key, params): Promise<string>`
- `translate(key, params): Promise<string>`
- `refresh(): Promise<string | null>`
- `setLocale(locale): Promise<string | null>`

建议用法：

- UI 渲染期不要直接 await `t()`，使用 `useChipsI18nText()` + 本地 bundle 做同步解析。
- 语言切换入口可调用 `setLocale()`，manifest 必须含 `i18n.write`，当前模板已含。

### `useChipsI18nText`

真实签名：

- `useChipsI18nText(options?: Omit<ChipsI18nTextOptions, "locale">): (key, params?, fallback?) => string`

关键 options：

- `bundles?: Record<string, Record<string, unknown>>`
- `defaultLocale?: string`
- `fallbackLocale?: string`
- `fallbackLocales?: string[]`
- `missingText?: (...) => string`
