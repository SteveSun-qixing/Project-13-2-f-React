### 4.1 组件库 DataGrid runtime

文件：

- `Chips-ComponentLibrary/packages/components/src/index.js`

当前 `ChipsDataGrid` 是单体 `React.forwardRef`，主要 props：

- `columns`
- `rows`
- `sort/defaultSort/onSortChange`
- `selectedRowIds/defaultSelectedRowIds/onSelectedRowIdsChange`
- `disabled/loading/error`
- `ariaLabel`
- `onStateChange`

当前能力：

- `applyDataGridSort(rows, sort)` 纯函数。
- 支持列排序：header 点击后在 `asc/desc` 间切换。
- 支持行选择：点击或键盘激活当前行后切换 selected row id。
- 支持键盘上下/Home/End 改变 active row，Enter/Space 切换当前行选择。
- 根节点 `div` 使用 `role="grid"`、`tabIndex=0`、`aria-label`。
- 内部渲染真实 `<table>`，并为 table/header/row/cell/status 输出 `data-scope="data-grid"` 与相应 `data-part`。

当前公开 data-part：

- `root`
- `table`
- `header`
- `row`
- `cell`
- `status`

当前缺口：

- 没有 `DataGrid.Root/Toolbar/Header/Row/Cell/Pagination` 静态子组件。
- `toolbar` 与 `pagination` runtime part 不存在。
- `children` 不作为正式 Compound 主入口。
- `columns/rows` 数据 API 仍是主要结构输入。
- 行选择当前输出 `data-selected`，但主题 CSS 使用 `[data-part="row"][data-state="active"]` 表达 selected surface，存在“选择状态属性”和“主题选择器”不一致风险。
- 当前 root 自身是 `role="grid"`；若后续把 toolbar/pagination 放入 Root 内部，需要重新确认 ARIA 结构，避免 grid 直接包含非 row/grid 子项。

## 5. 推荐 016.04 实施边界

### 5.1 应该迁移的 public compound parts

建议本任务只迁移 DataGrid 自身的 Compound API，不提前做筛选器、列配置菜单、虚拟滚动、树表、远程数据源或业务分页状态模型。

推荐正式 public Compound API：

- `ChipsDataGrid.Root`
- `ChipsDataGrid.Toolbar`
- `ChipsDataGrid.Header`
- `ChipsDataGrid.Row`
- `ChipsDataGrid.Cell`
- `ChipsDataGrid.Pagination`

推荐导出形态沿用 016.01/016.02 当前模式：

```ts
export const ChipsDataGrid = Object.assign(DataGridRoot, {
  Root: DataGridRoot,
  Toolbar: DataGridToolbar,
  Header: DataGridHeader,
  Row: DataGridRow,
  Cell: DataGridCell,
  Pagination: DataGridPagination
});
```

建议 `columns/rows` 数据 API 可以继续作为 Root 的默认子树生成输入，用于内部生成 Header/Row/Cell fallback；但正式文档主路径应展示 Compound 子组件组合，避免继续把复杂结构压进单体 props。当前第一版未发布，不建议为旧单体 API 设计长期兼容层。

### 5.2 `table` part 决策建议

建议区分“Compound public subcomponent”和“DOM structural part”：

- 不建议新增 `ChipsDataGrid.Table` 公开子组件。
- `DataGrid.Root/Toolbar/Header/Row/Cell/Pagination` 是对外组合面。
- `table` 若继续存在，应被明确标注为内部结构 DOM，不能作为 L8 slot，也不能让业务层通过 `DataGrid.Table` 组合。

有两个可选收口方案：

1. 严格 slot/contract 对齐方案：从 public contract、metadata 和 ThemePack contract 中移除 `table`，实际 `<table>` 不输出 `data-part="table"`。这最符合 `Root/Toolbar/Header/Row/Cell/Pagination` 的公开 API，但如果主题要控制 table layout，需要改为通过 root/header/row/cell token 完成。
2. 结构 part 保留方案：保留 `data-part="table"`，但在公共文档和 contract 中明确它是“结构性 public data-part，不是 Compound slot”。Host `StandardCompoundSlotSchemas.DataGrid` 仍不增加 `table` slot。该方案改动较小，但需要文档写清楚，避免业务层误以为存在 `DataGrid.Table`。

本勘察推荐方案 1，原因：

- 当前 ThemePack CSS 实际没有使用 `[data-part="table"]`。
- Host L8 schema 和任务016.04目标均未包含 `table` slot。
- 继续保留 `table` 作为 public contract part 容易让 compound slot 与真实 table DOM 混成一层。

若主代理为了真实 table/grid 容器语义必须保留 `table`，请采用方案 2 并在 `生态共用技术文档/组件库/02-组件契约标准.md` 中显式写清“结构 part 与 Compound slot 的区别”。

### 5.3 公开 data attributes 与状态建议

DataGrid 应保持公共 contract 强制字段：

- `data-scope="data-grid"`
- `data-part`
- `data-state`
- `aria-*`

建议公开 parts：

- `root`
- `toolbar`
- `header`
- `row`
- `cell`
- `pagination`
- `status`

如果采用 `table` 保留方案，则公开 parts 增加：

- `table`，但仅为结构 part，不是 Compound 子组件或 L8 slot。

建议公开标准状态：

- `idle`
- `hover`
- `focus`
- `active`
- `disabled`
- `loading`
- `error`

建议公开 DataGrid 专属 data attributes：

- root:
  - `data-loading="true|false"` 可选；如果已有 `data-state="loading"` 可不单独增加。
  - `data-sort-key` 和 `data-sort-direction` 可选，用于诊断和测试，不建议主题强依赖业务 key。
- header:
  - `aria-sort="none|ascending|descending"` 必须保留。
  - `data-sort="none|ascending|descending"` 建议公开，便于主题显示排序态。
  - `data-sortable="true|false"` 建议公开。
- row:
  - `aria-selected="true|false"` 必须保留。
  - `data-selected="true|false"` 建议作为公开状态属性。
  - `data-active="true|false"` 建议表示键盘 active row，不等同 selected。
  - `data-row-id` 可用于测试，但应谨慎公开，避免主题依赖业务 id。
- cell:
  - `role="gridcell"` 或实际 table cell 语义必须稳定。
  - `data-column-key` 可用于测试，但不建议主题依赖。
- pagination:
  - 建议使用 `role="navigation"`，并要求 `aria-label` 或 `aria-labelledby`。
  - 可公开 `data-page`、`data-page-count`，但本任务若只做结构 slot，可暂不引入分页状态模型。
- toolbar:
  - 建议使用 `role="toolbar"`，并要求 `aria-label` 或 `aria-labelledby`。

重要：`row.surface.selected` token 应绑定到 `[data-selected="true"]`，不要继续依赖 `[data-state="active"]` 表示 selected。`data-state="active"` 更适合表达按压/当前交互状态，`data-active` 更适合键盘 active row，`data-selected` 更适合选择状态。

### 5.4 推荐 a11y 结构

加入 Toolbar/Pagination 后不建议让 `Root` 本身继续无条件承载 `role="grid"`，否则 Root 内直接包含 toolbar/pagination 时会破坏 ARIA grid 子结构。

推荐：

- `Root`：容器，`data-part="root"`，可使用 `role="group"` 或 `role="region"`，由 `aria-label/aria-labelledby` 提供整体名称。
- 内部 grid/table 区域：如果保留真实 `<table>`，由 `<table role="grid">` 承载 grid 语义；若不公开 table part，也不影响 Header/Row/Cell 的 public part。
- `Toolbar`：在 grid/table 前。
- `Pagination`：在 grid/table 后，使用 `role="navigation"`。
- `Header`：`role="columnheader"`，保留 `aria-sort`。
- `Row`：`role="row"`，保留 `aria-selected`。
- `Cell`：`role="gridcell"`。

如果主代理决定 Root 仍是 `role="grid"`，则 Toolbar/Pagination 应位于 Root 外或通过合规的 wrapper 处理；但这会让 `DataGrid.Root` 不再自然包住全部 Compound parts，因此不推荐。

## 8. 风险清单

1. `table` part 决策不清会继续造成 contract、Host schema 和 DOM 结构三方漂移。
   - 建议主代理先冻结：不导出 `DataGrid.Table`，优先移除 public `table` part；如保留则明确它只是结构 part。

2. Root 的 ARIA role 可能需要调整。
   - 当前 Root 是 `role="grid"`，加入 toolbar/pagination 后不宜继续直接包住非 grid 子项。建议 Root 作为 group/region，内部表格区域承载 grid 语义。

3. selected row 当前 runtime 与主题 CSS 不一致。
   - Runtime 输出 `data-selected`，ThemePack CSS 使用 `[data-state="active"]`。016.04 应把 selected 作为公开 DataGrid 专属属性，并让 CSS/token 对齐。

4. Compound API 不能只改类型。
   - 必须同时更新 runtime、type、tests、contract、tokens、ThemePack、Host L8 schema tests、公共文档和工作日志。

5. 不要把分页业务模型做大。
   - 016.04 只需要 `Pagination` part/slot 和可访问边界；完整分页状态、远程数据源、页码控制器可留给后续 DataGrid 高级能力任务。

6. 不要引入新表格库或虚拟化库。
   - 当前技术选型不允许未经决策新增第三方库。DataGrid 迁移应复用现有 React、自研状态和组件库 helper。

7. DataGrid 与 L8 `Table` 原语关系需要谨慎。
   - Host schema 用 `Table` 类型承载 header/row/cell slot，但组件库 runtime 不应把 Host L8 实现搬入组件库；组件库只负责 L10 结构、状态、a11y 和 contract。

8. ThemePack 只做必要同步。
   - 新增 toolbar/pagination token 必须同步默认和暗色主题；但不要在 016.04 扩大为任务020/021/022 的主题包全量升级。

9. 公共文档当前已有 016.02 未提交更新。
