## 旧技能过期点

1. 顶层新建工程命令过期。

   `SKILL.md` 与 `references/scaffold-workflow.md` 都写了：

   ```bash
   cd /Users/sevenstars/Documents/ChipsCard/Develop/Project-13-2-f
   npx chipsdev create card <target-dir>
   ```

   任务024后的公共手册口径是生态根工作区安装后使用正式独立命令：

   ```bash
   cd <生态根工作区>
   chipsdev create card <targetDir>
   ```

   技能中不应硬编码旧 `Project-13-2-f` 路径，也不应继续推荐 `npx chipsdev`。如需给命令示例，应使用 `<生态根工作区>` 或当前任务工作区变量，并以 `chipsdev create card <targetDir>` 为准。

2. 验证命令不完整。

   旧技能顶层只列 `npm run lint / npm test / npm run build / npm run validate`，reference 也缺少任务024冻结的生成工程默认门禁。当前正式生成工程必须包含并推荐：

   ```bash
   npm run lint
   npm run typecheck
   npm test
   npm run build
   npm run validate
   npm run package
   npm run verify
   ```

   其中 `verify` 串联 `lint/typecheck/test/build/validate/package`，应作为生成工程默认本地质量门禁。

3. `scaffold-workflow.md` 的模板能力状态过期。

   旧 reference 写 `supports.componentLibrary: false`；当前 `templates/card-standard/template.json` 是 `componentLibrary: true`，`check-templates.cjs` 也强制模板声明支持组件库，并要求 README 说明 `@chips/component-library` 接入。

4. `official-contracts.md` 的 `importArchiveBundle` 类型过期。

   旧 reference 中请求结构只写到 `file/preferredRootDir/entryFile`，结果只写 `rootDir/entryFile/resourcePaths`。当前公共文档和模板已冻结更完整结构：请求包含 `include.mimeTypes/extensions`、`stripSingleRootDir`、`excludeSystemArtifacts`；结果包含 `entries`、`discardedEntries`、压缩大小、CRC、offset、目录标记、压缩方式、修改时间等审计字段。

5. 资源打开示例存在误导风险。

   `resource-and-app-integration.md` 的示例把 `openResource.resourceId` 写成 `resolvedUrl`，容易让后续代理误以为必须把临时 URL 当作资源身份传递。任务024公共文档和标准模板更稳的表达是：查看态通过可选 `openResource(...)` 表达资源打开意图，业务上下文放入 `payload`，Host 只负责透传；基础卡片不直接启动应用、不硬编码目标 app 插件 ID。vNext 技能应避免把临时 URL 示例写成唯一推荐形态。

6. 对 Bridge/Host 能力的表述需要收窄到基础卡片插件上下文。

   旧技能写“插件访问系统能力只能通过 `window.chips.*` / Bridge / `chips-sdk` 正式链路”，这是生态总边界，但对基础卡片模板而言更具体的规则是：查看态和编辑态优先只消费传入 context callbacks，例如 `resolveResourceUrl/releaseResourceUrl/openResource/importResource/importArchiveBundle/deleteResource/convertTiffToPng`；编辑器不得直接调用 `CardService`、Bridge 写文件或直连文件系统。

7. reference 中包含较多业务插件历史经验，缺少“仅作模式参考”的显式边界。

   `image-and-music-patterns.md`、`editor-ui-patterns.md` 可保留，但必须标注为历史/业务模式参考，使用前要重新核对当前 `Chips-BaseCardPlugin/*` 真实代码、Manifest 和测试；不能把旧业务插件中的 payload、schema 或 UI 细节当作基础卡片 vNext 标准模板契约。

8. 技能缺少任务024最终模板与脚本的固定参考入口。

- `package.json`：正式 semver 依赖、`@chips/component-library`、`chips-sdk`、不引入未批准新依赖、脚本含 `lint/typecheck/test/build/validate/package/verify`。

- `src/schema/card-config.ts`：默认值、归一化、校验、资源路径收集。
- `src/render` / `src/editor`：React 挂载、context callbacks、cleanup。
- `i18n/`：用户可见文案只保留 key，不在源码硬编码。
- `templates/` 与 `tests/`：默认配置、参数说明、单元与集成测试与真实 schema 同步。

### 4. 实现红线

vNext 技能必须明确：

- Host 是唯一运行时承载；基础卡片插件不复制 Host、编辑引擎或 SDK 的运行时主实现。
- 普通应用和第三方集成不得直接扫描目录或 import 插件源码；官方编辑引擎仅按 Host 已安装启用插件记录加载 `manifest.entry` 构建产物。
- 编辑器不直接调用 `CardService`、Bridge 写文件、`window.chips.invoke` 或文件系统；资源与持久化只通过 context callbacks 和宿主会话层。
- 卡片插件不直接创建窗口、不启动应用、不硬编码目标 app plugin ID。
- card manifest 不声明 `ui.surface`，应用插件专属字段不得写入基础卡片模板。
- 所有内部资源路径都是卡片根目录相对路径，禁止持久化绝对路径、`file://`、`blob:`、`data:`、查询串、片段或 `..` 逃逸。
- UI 必须使用 React、组件库公开接口、`--chips-*` token 和 i18n；不得硬编码可见中文文案、私有色板、临时样式体系。
- cleanup 必须真实卸载 React root、清理 DOM、监听器、定时器、临时资源 URL，并恢复被修改的容器/document 样式。
- 不创建临时、简化、占位实现；不留下 TODO/FIXME；不引入未批准依赖；不做兼容性包袱设计。
