# 任务054：Thorium 长期同化评估报告

## 1. 结论摘要

本轮评估对象为 `OpenSourceProjectHandlingFolder/thorium-reader-develop` 与 `OpenSourceProjectHandlingFolder/thorium-reader-repowiki`。Thorium Reader 是一个成熟的大型 Electron + React + Redux + Redux-Saga + Readium 桌面阅读器，当前工程版本为 `EDRLab.ThoriumReader@3.4.1-alpha.1`，源码许可证为 `BSD-3-Clause`。它适合作为薯片生态阅读器长期能力地图、阅读格式解析边界、OPDS/LCP/注释书签/朗读/A11y 的参考样本，但不适合未经拆解直接并入 Host、BookReader 或 book-BCP。

对薯片生态的核心判断如下：

- 短期应吸收 Thorium 的产品能力清单和阅读配置模型，补齐 `Chips-BookReader` 的长期路线，而不是迁入 Thorium 的 Electron 主进程、Redux 全局状态和 UI 组件。
- 中期应把 EPUB/WebPub/AudioBook/Divina/PDF 包装、OPDS、LCP、全文索引、注释书签导入导出、阅读定位、TTS/Media Overlays 等能力拆到 Host 托管模块插件或公共协议层。
- 长期可评估 Readium 相关包或同等能力作为阅读核心候选，但必须经过许可证、依赖、沙箱、Bridge、权限、构建体积、性能和安全边界审查。
- Thorium 的开放源码不包含生产级 LCP 组件；README 明确说明生产级 LCP 需要额外保密组件与 EDRLab 协作维护。因此 LCP/DRM 只能沉淀为能力需求和接口边界，不能视为可直接复制的完整实现。

## 4. 进程模型与通信模型

Thorium README 和 wiki 明确其应用由三部分构成：

- 一个 Node.js Electron main process。
- 一个 library window renderer。
- 一个到多个 reader window renderer。

主进程职责：

- 初始化全局 converter、LCP 插件、协议处理器。
- 创建 Redux 主 store。
- 管理 BrowserWindow、reader window map、library window。
- 管理 Publication、OPDS、LCP、LSD、Device、Storage、Streamer 等服务。
- 通过 IPC/RPC 与 renderer 同步状态和请求。

Renderer 职责：

- Library renderer 负责出版物列表、OPDS 浏览、设置和导入。
- Reader renderer 负责打开 publication、阅读 UI、设置、目录、注释、书签、搜索、朗读、PDF/Divina 特化渲染。
- PDF 还通过 webview + preload + pdf.js viewer 形成内部事件总线。

对薯片生态的同化判断：

- Thorium 的 Electron 进程模型不能直接并入薯片生态。薯片 Host 已是唯一运行时承载，应用插件不能自行拥有 Electron 主进程、BrowserWindow 生命周期、Node 文件系统或 IPC 主实现。
- 可吸收的是“Library/Reader 分工”“Document Scene 与多阅读窗口状态”“主进程托管重型能力、renderer 只消费视图模型”的思想。
- 在薯片中应映射为：
  - `Chips-BookReader`：应用插件 surface，承载阅读 UI 与 Document Scene。
  - Host：资源打开、文件解析、受控文档 URL、权限、凭证、缓存、进度持久化。
  - 模块插件：EPUB/PDF/WebPub/Divina/OPDS/LCP/索引/转换等无界面能力。

## 5. Redux/Sagas 与状态模型

Thorium 状态模型特征：

- 主进程持有中心 Redux store。
- renderer 通过 IPC 同步有限 action。
- Redux-Saga 承担应用初始化、窗口管理、Publication、Streamer、Auth、LCP、Catalog、Reader、Keyboard、Persistence、Telemetry 等副作用。
- 持久化使用 patch、JSON 文件、Publication data 文件夹、键盘快捷键文件、OPDS auth token 文件、LCP secrets 文件等。
- Reader 层有独立 reader root state，包含 config、locator、tts、mediaOverlay、highlight、divina、search、pdfConfig 等。

可吸收内容：

- 将阅读状态拆成清晰域：文档元数据、locator、阅读偏好、搜索结果、注释书签、朗读状态、PDF/漫画格式状态。
- 将副作用集中在 Host/模块能力调用与应用 runtime hook 中，而不是散落在 UI 回调。
- 对阅读配置采用“默认配置 + 文档级覆盖 + 用户配置 + 运行时临时态”的层级。
- 对持久化使用防抖和结构化 patch 思路，但在薯片中应落到 Host preference/document state 服务，不在应用里自建文件系统。

不可直接复用内容：

- 中心 Redux store 同步多个 Electron renderer 的 IPC 方案。
- `diMainGet` + Inversify 的主进程服务定位方式。
- renderer 直接依赖 Electron IPC、webview、Node path/process 的实现。
- 原有 class component 巨型 Reader 容器结构，不符合薯片 SwiftUI-like App/Scene/View/Environment 目标。

## 6. 阅读核心与格式支持

### 6.1 阅读核心

Thorium 阅读核心由以下部分组合：

- Readium R2 navigator/streamer/shared/lcp/opds 相关源码与模型。
- `installNavigatorDOM(...)` 将 EPUB/WebPub 类内容装入 `publication_viewport`。
- `computeReadiumCssJsonMessage(...)` 和 ReadiumCSS 对排版、主题、分页、字体、间距、MathJax 进行处理。
- PDF 通过 `pdf.js` fork，先由 `pdfPackager` 把 `.pdf` 包装为 Readium WebPub，再由 reader 内部 PDF webview 显示。
- Divina/漫画视觉叙事通过 `divina-player-js`，支持 `single/double/scroll/guided` 阅读模式和声音。
- TTS 与 Media Overlays 通过 `readium-speech` 与 R2 navigator 的朗读接口集成。

### 6.2 格式支持矩阵

从 `src/common/extension.ts`、导入 sagas、Publication Management wiki 和源码判断：

| 格式 | Thorium 状态 | 证据与说明 | 薯片吸收判断 |
|---|---|---|---|
| EPUB / EPUB3 / PNLD | 原生核心支持 | `EpubParsePromise`，`.epub/.epub3/.pnld` accepted extension | 长期核心格式，优先模块化 |
| PDF | 支持 | `.pdf` 经 `pdfPackager` 包装为 WebPub；`.lcpdf` 作为 Readium publication | 需要 Host/模块级 PDF 包装与受控 viewer |
| WebPub | 支持 | `.webpub` 读取 `manifest.json` | 可沉淀为 publication manifest 模块能力 |
| AudioBook | 支持 | `.audiobook/.lcpa/.lcpaudiobook`，RDFType Audiobook | 可作为后续有声书模块能力 |
| Divina / 漫画视觉叙事 | 支持 | `.divina` + `divina-player-js`，ComicStrip/ComicStory/VisualNarrative RDFType | 可作为漫画图片序列/视觉叙事长期参考 |
| DAISY | 支持转换 | `.daisy/.zip/.opf/ncc.html` 通过 `DaisyParsePromise` 转 Readium WebPub | 可列为中长期无障碍阅读格式 |
| LPF | 支持转换为 audiobook | `.lpf` 经 `lpfToAudiobookConverter` | 适合进入模块插件候选 |
| OPDS acquisition | 支持 | OPDS link 支持 EPUB/LCP/PDF/WebPub/AudioBook/LPF/HTML/XHTML 等 | 适合 Host/模块服务，不放入 BookReader UI 内核 |
| DOCX / DOC | MIME 表存在 | `mimeTypes.ts` 有 doc/docx 相关类型，但 accepted extension 与导入链路未纳入主阅读格式 | 不可视为 Thorium 已支持；薯片继续沿工单093/重型文档解码路线 |
| TXT / Markdown / FB2 / RTF | 本源码主 accepted extension 未列入 | `marked` 用于 markdown 内容和注释，不等于出版物导入支持 | 不能从 Thorium 直接吸收；以 Chips-BookReader 已有链路为基线 |
| MOBI / AZW / AZW3 / DJVU | 未见正式 accepted extension | `mimeTypes` 有 `azw`，但无正式导入阅读链路 | 继续按工单093处理 |
| CBZ / CBR | CBZ 被注释 | `extension.ts` 中 `cbz` 注释掉 | 不直接吸收，漫画路线优先考虑 Divina/图片序列自有模型 |

### 6.3 PDF 链路

Thorium PDF 路线：

1. `importFromFsService` 识别 `.pdf`。
2. `pdfPackager(pdfPath)` 使用 `extractPDFData` 读取 PDF 元数据和首图。
3. `pdfManifest` 生成 Readium WebPub manifest。
4. `createWebpubZip` 将 `publication.pdf` 和 `cover.png` 打成 zip。
5. `importPublicationFromFS` 再按 Readium publication 导入。
6. Reader 中 `pdfMount` 创建 webview，加载 pdf.js viewer，并通过 `pdf-eventbus` 同步搜索、页码、缩放、缩略图、复制和键盘事件。

薯片吸收建议：

- Host/模块插件负责“PDF -> 受控阅读文档模型/封面/页数/索引/缩略图”。
- `Chips-BookReader` 只通过 `resource.open`/Document Scene 获取受控 viewer URL 或 renderer descriptor。
- PDF 搜索、缩略图、页码和打印权限需要公共能力契约，不能在应用内私有 webview eventbus 长期存在。

### 6.4 漫画/图片序列链路

Thorium 的漫画方向主要是 Readium Divina 视觉叙事：

- 支持 `.divina` 包。
- 使用 schema.org ComicStrip/ComicStory/VisualNarrative RDFType 识别。
- `divina-player-js` 支持 readingModes：`single`、`double`、`scroll`、`guided`。
- 支持连续 webtoon、翻页、语言、声音、缩放、手势、滚轮。

薯片吸收建议：

- book-BCP 当前需要支持电子书文件或图片序列包，Thorium 的 Divina 可作为“图片序列规范化为 manifest + 受控 viewer”的参考，而不是直接把 `divina-player-js` 放入基础卡片插件。
- 图片序列/漫画导入应由 Host/模块插件完成解包、排序、封面提取、缩略图和 manifest 生成。
- BookReader 或专门漫画查看模块消费统一阅读文档模型，book-BCP 仍只保存 card-root 相对资源路径并调用 `openResource`。

## 7. OPDS、LCP、DRM、注释书签、搜索、朗读

### 7.1 OPDS

Thorium 能力：

- 支持 OPDS feed 浏览、搜索、分页、acquisition link。
- 支持 OPDS Authentication：Basic、Digest、OAuth Password、API App OAuth、OAuth Implicit、Local、SAML 2.0 等类型。
- 使用 OPDS view converter 将 R2 OPDS 模型转为 UI view model。
- OPDS token 按 host/URL 存储，支持刷新和擦除。

薯片吸收建议：

- OPDS 应是 Host/模块插件能力，不属于 BookReader 应用私有功能。
- 需要公共 capability，例如 `catalog.opds.fetch`、`catalog.opds.authenticate`、`catalog.opds.acquire`、`catalog.opds.search`。
- 凭证和 token 必须由 Host 凭证服务保存，应用插件只发起授权 surface。
- OPDS acquisition 的出版物导入要落到 Host 资源库/下载/阅读文档导入流程。

### 7.2 LCP / DRM

Thorium 能力：

- 开源库支持 LCP Basic Encryption Profile。
- LCP secret 加密存储，按 publication/provider 复用。
- LCP License Status Document 支持 license check、renew、return。
- 能向 EPUB、Audiobook、Divina、LCP-PDF 注入或更新 `license.lcpl`。
- 使用文件锁避免并发 license 更新。

限制：

- README 明确生产级 LCP 组件不在开源代码库。
- LCP/DRM 涉及保密组件、授权、合规、供应链和安全审计。

薯片吸收建议：

- 只沉淀能力边界，不直接同化实现。
- Host 需要专门 DRM/LCP 权限域、凭证存储、文件锁、审计、错误码和 UI 授权流程。
- 阅读器应用只能消费 Host 判定后的可读资源或结构化错误，不处理密钥、license 注入和 LSD 网络细节。

### 7.3 注释与书签

Thorium 能力：

- 注释和书签共享 `INoteState` 类数据模型，以 `group` 区分 annotation/bookmark。
- 注释支持 `solid_background`、`underline`、`strikethrough`、`outline` 等绘制类型。
- 支持颜色、评论、标签、导出、筛选。
- 书签根据 EPUB/PDF/Divina/Audiobook 使用不同可见性判断：EPUB 通过 locator 可见性，音频按时间，PDF/Divina 按 href。
- 使用 Locator/MiniLocatorExtended 保存位置。

薯片吸收建议：

- 可沉淀为 `reader.annotation` / `reader.bookmark` 公共模型。
- 位置模型应兼容 EPUB CFI/range、PDF page+offset、图片序列 pageIndex、音频时间轴。
- 注释不应写入 `.card` 或 `.box` 内容实体；用户阅读状态和个人标注应由 Host/应用状态服务保存，分享时再显式导出。

### 7.4 搜索

Thorium 能力：

- EPUB/WebPub 搜索遍历资源缓存，结果转 highlight 并可导航。
- PDF 搜索走 pdf.js eventbus。
- Library 搜索用 Lunr.js 支持 title/author/tag 等。
- 搜索结果包含上下文、rangeInfo、href、uuid。

薯片吸收建议：

- 全文索引应为模块能力，按 publication/documentId 建索引。
- 阅读器应用需要统一搜索 UI 和结果模型，不应按格式暴露不同事件总线。
- PDF/EPUB/图片 OCR/文档格式可以由不同 provider 提供同一 `reader.search` capability。

### 7.5 朗读、TTS 与 Media Overlays

Thorium 能力：

- 使用 `readium-speech` 和浏览器 `SpeechSynthesisVoice`。
- 支持语音列表、语言/地区筛选、播放速度、句子检测、连续播放、跳过结构、TTS/Media Overlay 高亮。
- EPUB3 Media Overlays 与 TTS 有统一控制栏，允许强制 TTS。
- TTS 与注释/书签互斥处理，例如播放中提示先停止。

薯片吸收建议：

- TTS 是生态级可复用能力，应沉淀到 Host/模块插件或公共 runtime capability。
- BookReader 只注册朗读相关 command，消费统一 reader audio state。
- 朗读高亮样式需走主题 token 和 a11y 设置，不能采用应用私有色值长期固化。

## 8. 国际化、主题、A11y、快捷键

### 8.1 国际化

Thorium：

- 使用 `i18next`。
- locale JSON 约 31 个，本地 README 列出 28 个语言，wiki 描述 39+，当前源码以实际 locale 文件为准。
- 生成 typed i18n 类型：`en.translation.d.ts` 与 `en.translation-keys.d.ts`。
- 支持 translator service、English fallback、内容多语言字段 helper。

薯片吸收建议：

- 借鉴 typed i18n 与 key 生成检查，但继续使用薯片 `ChipsEnvironmentProvider`、`useChipsI18nText()`、Host i18n 服务。
- Thorium 文案体系不能直接成为薯片公共 key；只能作为阅读器场景 key 覆盖清单参考。

### 8.2 主题与阅读样式

Thorium：

- 应用 UI 使用 SCSS modules、CSS variables、`data-theme=light/dark/system`。
- 阅读内容使用 ReadiumCSS 与 reader config 生成 CSS 注入消息。
- 阅读主题包括 neutral、sepia、night、paper、contrast1-4。
- 支持字体、字号、页边距、字距、词距、段距、行高、分页、列数、对齐、MathJax、减少动效等。

薯片吸收建议：

- 阅读偏好应作为 BookReader 的文档级 View/Modifier 状态，并映射到生态 theme token。
- 主题 UI 控件必须使用 `@chips/component-library` 与 `ChipsThemeProvider`，不复制 Thorium 的 SCSS modules。
- 阅读内容的 publisher CSS、用户 CSS 和主题 token 需要清晰优先级，避免形成第二套主题系统。

### 8.3 A11y

Thorium：

- README 强调照顾 NVDA、JAWS、Narrator 等屏幕阅读器用户。
- Publication view 提取 EPUB Accessibility metadata：accessMode、accessibilityFeature、hazard、conformance、summary、certification 等。
- 键盘、焦点、skip link、ARIA 文案和高对比阅读主题较完整。
- MathJax 注入可包含 a11y/semantic-enrich。

薯片吸收建议：

- 可把出版物可访问性元数据映射为 `BookPublicationAccessibility` 公共模型。
- UI 交互必须沿 `@chips/a11y` 的 FocusScope、roving tabindex、键盘 action 与测试 helper。
- 高对比阅读主题应通过生态 token 和用户偏好服务表达。

### 8.4 快捷键

Thorium：

- `src/common/keyboard.ts` 定义默认快捷键，按 reader/catalogs/bookshelf scope 组织。
- 支持实体键位、修饰键、作用域、用户自定义、文件持久化。
- renderer 有黑名单逻辑，避免在 input/textarea/contenteditable 中误触。
- 设置 UI 支持搜索、编辑、重复检测、键盘布局显示。

薯片吸收建议：

- 快捷键能力应进入 Host command registry/shortcut 链路，BookReader 只声明 command metadata 和 shortcut placement。
- 可借鉴作用域、重复检测、输入控件黑名单、用户自定义 UI，但需要用 `client.command.*` 和组件库命令消费组件实现。

## 9. 可沉淀到薯片生态的内容

### 9.1 Chips-BookReader

适合沉淀：

- Document Scene：空启动、文件/资源启动、OPDS acquisition 启动、book-BCP payload 启动。
- 阅读域状态：locator、history、reader config、search、bookmark、annotation、TTS、media overlay、format-specific state。
- UI 能力：目录、页码/位置、搜索、书签、注释、出版物信息、阅读设置、TTS/Media 控制、PDF 缩放/页模式、漫画阅读模式。
- 阅读偏好：主题、字体、字号、分页/滚动、列数、行距、字距、词距、段距、减少动效、高对比、publisher override。
- 错误态：DRM 未授权、格式不支持、资源缺失、索引失败、PDF/EPUB 解析失败、网络超时。

不适合沉淀：

- Electron BrowserWindow、webview、IPC。
- Thorium Redux/Saga 的跨进程状态同步。
- Thorium 私有 CSS/组件。

### 9.2 book-BCP

适合沉淀：

- 资源卡片模型：书名、作者、封面、格式、文件大小、资源路径、打开入口、错误态。
- 图片序列/漫画包作为“可打开资源”，但不内置完整 reader。
- 导入时仅保存 card-root 相对路径，资源生命周期由基础卡片资源桥处理。

不适合沉淀：

- 解析 EPUB/PDF/DOCX/漫画包的完整实现。
- OPDS/LCP/TTS/搜索/注释等阅读器能力。
- 直接复制 Thorium 的 publication storage 或 database。

### 9.3 模块插件

适合拆分为模块插件能力：

- `reader.publication.parse`：EPUB/WebPub/AudioBook/Divina/DAISY/LPF 解析为统一 publication manifest。
- `reader.pdf.package`：PDF 元数据、封面、页数、缩略图、受控 viewer 入口。
- `reader.search.index` / `reader.search.query`：全文索引与搜索。
- `reader.annotation.export` / `reader.annotation.import`：注释/书签导出导入。
- `catalog.opds.*`：OPDS feed/auth/acquisition。
- `reader.drm.lcp.*`：LCP license、secret、LSD、rights 状态。该类能力需要额外合规审批。
- `reader.tts.*`：TTS 声音、播放状态、Media Overlay、高亮同步。
- `reader.cover.extract`：封面抽取、fallback 生成。

### 9.4 Host

适合 Host 承载：

- 资源打开与应用唤起：`resource.open` -> BookReader surface。
- 受控文档 URL 和资源代理。
- 凭证、密钥、令牌、安全审计、权限。
- 文件系统读取、网络下载、缓存、锁、临时目录清理。
- 模块 provider 发现、权限校验、任务治理。
- 阅读状态和用户偏好持久化。

### 9.5 公共文档

- 阅读资源打开 payload。
- 阅读搜索结果模型。
- 阅读注释/书签模型。

## 11. 安全与权限边界

Thorium 中需要特别关注的安全点：

- 阅读内容会加载 HTML/XHTML/SVG/图片/音频/PDF/脚本能力边界。
- `navigator.epubReadingSystem`、ReadiumCSS、MathJax、drag/copy 注入会改变内容文档行为。
- OPDS 需要网络访问、认证、token 刷新和媒体代理。
- LCP 需要密钥、license、rights、LSD 网络请求、文件锁和 ZIP 注入。
- PDF viewer webview 需要 sandbox/webSecurity/partition/preload 设置。
- 出版物导入会处理 ZIP、manifest、PDF、DAISY、LPF 等复杂文件，需防 Zip Slip、路径逃逸、过大文件、恶意 HTML、外链加载、资源耗尽。

薯片正式边界建议：

- 应用插件不得直接访问文件系统、网络凭证、Electron API 或 DRM 密钥。
- Host 负责创建受控 URL、资源代理、权限快照和生命周期清理。
- 模块插件按 capability 声明最小权限，处理输入 schema、路径归一化和任务取消。
- 阅读内容 iframe 必须是受控文档容器，CSP、sandbox、外链打开、复制/打印权限都由 Host 策略决定。
- OPDS/LCP/DRM 必须有独立权限域和审计事件。
- `.card`/`.box` 不保存临时 URL、绝对路径、密钥或凭证。

## 15. 最终判断

Thorium 是高价值参考样本，但不是薯片框架的可直接移植底座。它的价值主要在于：

- 证明专业阅读器需要把格式解析、出版物模型、状态持久化、朗读、搜索、注释、OPDS、DRM、安全和 A11y 作为系统工程处理。
- 提供 EPUB/PDF/Divina/AudioBook/DAISY/OPDS/LCP 的成熟能力地图。
- 帮助薯片生态判断哪些能力应进入 Host、哪些进入模块插件、哪些进入 BookReader、哪些只作为 UI/产品参考。

薯片生态应沿自己的 Host/Bridge/SDK/插件/组件库/主题/i18n/a11y 架构重建这些能力。最终目标不是把 Thorium 搬进来，而是把 Thorium 证明过的复杂阅读器能力拆解成薯片生态可长期演进的公共能力。
