## 2. 任务024目标、范围、验收标准拆解

### 2.1 目标

任务024要升级 `Chips-Scaffold/chips-scaffold-basecard`，让新建基础卡片插件默认符合 vNext 的基础卡片正式基线：

- 入口默认导出 `renderBasecardView`、`renderBasecardEditor`、`basecardDefinition`。
- schema 默认具备默认值、normalize、validate、resource collect。
- 查看态与编辑态基于 React，接入组件库、主题 token、多语言文件。
- 资源操作只通过上下文回调：`resolveResourceUrl`、`releaseResourceUrl`、`importResource`、`deleteResource`、`importArchiveBundle`、`convertTiffToPng`、`openResource`。
- manifest 与 `basecardDefinition.cardType` 对齐，声明 `type: card`、`entry: dist/index.mjs`、`capabilities.cardTypes`、完整 `runtime.targets`、最小权限。
- 生成工程可直接进入编辑引擎和查看器加载链路。

### 2.3 验收标准

任务文档给出的正式验收可拆成四组：

1. 生成工程加载能力：
   - 新基础卡片插件可被编辑引擎和查看器加载。
   - `manifest.entry` 指向真实构建产物，`basecardDefinition` 可被编辑引擎运行时读取。

   - 脚手架自身：`npm run build`、`npm test`、`npm run test:templates`、`npm run test:e2e`。

### 3.4 SDK / Host / EditingEngine 接线

当前模板：

- 只从 `chips-sdk` 引入 `IconDescriptor` 类型。
- 不直接 import Host，也不使用 Electron/Node 运行时能力，这是正确方向。
- `BasecardRenderContext` 只有 `container/config/themeCssText/resolveResourceUrl/releaseResourceUrl`，缺 `openResource`。
- `BasecardEditorContext` 有 `importResource/deleteResource`，缺 `importArchiveBundle/convertTiffToPng`。
- `basecardDefinition` 有 `pluginId/cardType/displayName/icon/commitDebounceMs/createInitialConfig/normalizeConfig/validateConfig/renderView/renderEditor`。
- `basecardDefinition` 缺 `aliases` 示例、缺 `description`、缺 `previewPointerEvents` 示例、缺 `collectResourcePaths`。

当前 EditingEngine 真实契约：

- `Chips-EditingEngine/src/basecard-runtime/contracts.ts` 已定义 `importArchiveBundle`、`convertTiffToPng`、`previewPointerEvents`、`collectResourcePaths`。
- `registry.ts` 会从 Host `plugin.query({ type: 'card' })` 的 `installPath + entry` 加载插件构建产物，校验 `basecardDefinition`、`IconDescriptor` 和 `previewPointerEvents`。
- `EditorHost.tsx` 已提供 `resolveResourceUrl/releaseResourceUrl/importResource/importArchiveBundle/deleteResource/convertTiffToPng`。
- `CardService` 通过 `descriptor.collectResourcePaths(config)` 参与资源持久化与 `structure.yaml manifest.resources` 重建。

结论：模板已避开 Host 私有 import，但正式上下文能力明显落后于当前 EditingEngine / 公共文档。

### 3.5 card-root 资源链路

当前模板：

- `schema/card-config.ts.tpl` 只有 `card_type/theme/title/body/locale`，没有资源字段，也没有内部资源路径校验。
- 没有 `collectResourcePaths`，因此生成工程无法给宿主持久化阶段提供内部资源清单。
- 编辑器 props 虽传入 `resolveResourceUrl/releaseResourceUrl/importResource/deleteResource`，但实际 UI 没有资源导入、预览、删除或释放用例。
- 查看态没有 `openResource`，无法示范资源打开意图上抛。

现有插件最佳实践：

- `image-BCP`、`video-BCP`、`music-BCP`、`book-BCP` 等已通过 `openResource` 表达打开意图。
- `book-BCP`、`webpage-BCP` 使用 `importArchiveBundle`。
- `music-BCP` 使用 `convertTiffToPng`。
- 多个插件已实现 `collectResourcePaths`。

结论：任务024应把“资源桥完整形状 + 中性资源示例 + collectResourcePaths + 路径合法性测试”收进模板，但不能把图片、音乐、网页或电子书的业务字段固化为唯一基线。

当前模板主题：

- `render/view.tsx.tpl` 和 `editor/panel.tsx.tpl` 使用部分 `--chips-*` token。
- 但存在硬编码视觉值和装饰：
  - `border-radius: 22px`
  - `box-shadow: 0 10px 28px rgba(...)`
  - `radial-gradient(...)`
  - fallback 颜色、圆角、阴影、focus glow 等
- 查看态默认增加独立 `chips-basecard__surface` 壳层，与编辑引擎标准“装配层不额外包裹边框、圆角、阴影；基础卡片不默认制造外层壳视觉”方向冲突。

结论：vNext 模板要改为组件库控件/布局 + 主题 token，不应继续展示硬编码卡片壳层和私有表单视觉。

### 3.7 测试与 e2e 覆盖

## 4. 与 023 应用脚手架 vNext 模式的复用边界

当前 023 应用脚手架已形成一套值得 024 复用的质量模式。由于 023.04 仍有并行改动，本报告只提取稳定模式，不建议复制 app 业务结构。

   - 检查 package scripts、正式 semver 依赖、manifest 字段。
   - 禁止残留 `TODO/FIXME`、旧命令、模板身份、未替换占位符。
   - 扫运行时代码禁止 Node/Electron/Host 私有直连。

不应照搬：

- App 的 `App/Scene/surface/commands` 目录和权限，card 插件没有 `ui.surface`、没有命令注册默认需求。
- App 的 `manifest.permissions` 中 `command.*`、`i18n.write` 等权限不应默认进入 card。
