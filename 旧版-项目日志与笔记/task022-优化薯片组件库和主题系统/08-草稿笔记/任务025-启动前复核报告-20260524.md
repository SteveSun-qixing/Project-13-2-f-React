## 2. 任务025目标、范围、验收标准拆解

### 2.1 目标

任务025要升级 `Chips-Scaffold/chips-scaffold-boxlayout`，让新建箱子布局插件默认符合 vNext 布局插件正式基线：

- 入口默认导出 `layoutDefinition`，并包含 `pluginId/layoutType/displayName/icon/createDefaultConfig/normalizeConfig/validateConfig/getInitialQuery/renderView/renderEditor`。
- `layoutDefinition.layoutType` 与 `manifest.yaml layout.layoutType`、`.box metadata.active_layout_type`、`content.yaml layout_configs` 键保持一致。
- 查看态默认消费 `initialView`，再按需调用 `runtime.listEntries/readEntryDetail/renderEntryCover/resolveEntryResource/readBoxAsset/prefetchEntries/openEntry`。
- 编辑态默认输出完整归一化配置，通过 `readBoxAsset/importBoxAsset/deleteBoxAsset` 管理箱子自有资源，不直接写文件。
- 默认提供空态、加载态、错误态、分页/增量、资源预览、cleanup 和 manifest 对齐测试。
- 生成工程使用 React、组件库、主题 token 与 i18n 文件，且可通过正式 build/test/lint/validate/template/e2e 门禁。

### 2.3 验收标准

任务文档给出的正式验收可拆为四组：

1. 生成工程加载能力：
   - 新布局插件可被 Host Box Runtime 通过 `layout.layoutType -> installPath + entry -> layoutDefinition` 正式加载。
   - `manifest.entry` 指向真实构建产物，`layoutDefinition` 与 manifest identity 对齐。

2. 运行时与资源：
   - 布局插件不拼接卡片路径，不直接打开应用插件。
   - 条目封面走 `runtime.renderEntryCover`，激活走 `runtime.openEntry`。
   - 箱子资源只通过 `readBoxAsset/importBoxAsset/deleteBoxAsset`，配置只保存 `assets/` 相对路径和 `assetRefs`。
   - 不持久化绝对路径、`file://`、`blob:`、`data:`、Host 临时 URL、凭证或 session ID。

3. 前端基线：
   - React 技术栈。
   - 使用组件库和主题 token，至少示范 `EmbeddedDocumentFrame`、布局原语、表单/选择/错误状态等正式能力。
   - 用户可见文案进入 `i18n/zh-CN.json` 与 `i18n/en-US.json`。
   - 查看态有空态、加载态、错误态和自然滚动/响应式约束；编辑态是紧凑配置流，不使用嵌套卡片。

4. 质量门禁：
   - 脚手架自身：`npm run build`、`npm test`、`npm run test:templates`、`npm run test:e2e`。
   - 生成工程：`npm run lint`、`npm run build`、`npm test`、`npm run validate`，建议收口为 `npm run verify`。
   - e2e 应优先走真实 `chipsdev create layout`，并验证生成工程 `chipsdev package` 产出 `.cpk`。
   - 模板不得残留 `TODO/FIXME`、未替换占位符、旧 Bridge/Electron/Node 直连、模板身份泄漏或过期 box runtime 字段。

### 3.5 查看态模板

当前 `src/view/page.tsx.tpl`：

- 使用 `CardCoverFrame`。
- 调用 `runtime.renderEntryCover(entryId)`。
- 点击标题/封面调用 `runtime.openEntry(entryId)`。
- 对全部 enabled entries 调用 `prefetchEntries({ targets: ["cover"] })`。
- 使用固定 `gridTemplateColumns: repeat(columnCount, ...)`。
- 空态只是裸 `<div>暂无条目</div>`。
- 大量 inline style、硬编码颜色、渐变、focus ring、字号、间距。

主要差距：

- 正式布局插件应优先使用 `EmbeddedDocumentFrame` 承载 `renderEntryCover` 返回的受控文档 URL；`CardCoverFrame` 只适用于明确是卡片的专用包装。
- 模板默认不应继续展示手工列数模型；官方 grid/list 已迁到自动响应式和移动端两列。
- 没有分页或 `nextCursor/listEntries` 示例，无法体现任务025要求的运行时分页。

- 没有 `readBoxAsset`、背景/顶部区域或占位资源示例。
