# 任务026.04：模块插件 Host/SDK/CLI 契约复核补强启动前复核报告

## 复核方式

子代理 Banach 只读复核，未写入文件、未提交、未运行破坏性命令。

## 026.04 目标理解

026.04 应在 026.02 模板矩阵和 026.03 真实 e2e 之后，复核并补强模块插件的正式链路：模块只能通过 `module.listProviders / module.resolve / module.invoke / module.job.*` 被发现、解析、调用和治理；SDK 只做类型化封装与辅助；CLI 必须驱动真实 Host 链路；文件转换继续作为 module capability，不新增 `conversion.*` Host 服务域。

## 当前契约链路

- Manifest：`module.provides`、方法 schema、`module.consumes` 已由 `Chips-Host/src/runtime/plugin-runtime.ts` 解析校验。
- Host：provider 同步、解析、运行时加载、`ctx.host/ctx.module/ctx.job` 注入和 `module.*` 服务注册集中在 `Chips-Host/src/main/services/register-host-services.ts`。
- SDK：`createModuleApi` 暴露 typed wrapper，覆盖 provider、resolve、invoke、job get/cancel，见 `Chips-SDK/src/api/module.ts`。
- CLI：`chipsdev create module` 支持模板参数；`chipsdev module invoke` 会启动 Electron Host runner，见 `Chips-SDK/cli/index.js`。
- 脚手架：`chips-scaffold-module` 已包含 `module-standard/pure-function/file-conversion/html-rendering/image-processing/color-extraction/orchestration` 模板。

## 已经满足

- Host 是模块运行时承载者，SDK 未承载 Host 主实现。
- `ctx.host.invoke("module.*")` 已被禁止，模块间调用入口是 `ctx.module.*`。
- Host 会校验模块输入/输出 schema，并支持 sync/job 两种模式。
- `platform.renderHtmlToPdf`、`platform.renderHtmlToImage` 可作为模块内 Host 正式动作使用。
- CLI invoke 已走真实 Host runner，不是纯本地 mock。

## 潜在漂移与风险

1. `timeoutMs` 是最大优先级风险：SDK、CLI、Host route 都声明了它，但 `invokeModuleInternal` 当前未实际执行超时控制。文档要求 Host 负责“超时与取消”。
2. `module.consumes` 已解析、模板也生成，但运行期未看到对调用方 consumes 声明的治理校验。建议 026.04 至少明确并测试：未声明依赖是否允许 `ctx.module.invoke`。
3. cancel 语义需要收口：`module.job.cancel` 会置 `cancelled` 但发 `module.job.failed`；异步任务 abort 后成功返回时可能只置 `cancelled` 不发终态事件。需要测试或文档明确。
4. provider 默认排序用字符串比较版本号，`1.10.0` 可能排在 `1.9.0` 后。建议改用 semver 比较。
5. 文档里 `module.listProviders` 的 status 口径偏窄，代码/SDK 已有 `disabled/error`。这更像 026.05 文档收口点，但 026.04 若新增测试应避免扩大漂移。
6. CLI `module invoke` 参数解析目前会忽略未知参数，可能掩盖拼写错误；建议补测试后收紧。
