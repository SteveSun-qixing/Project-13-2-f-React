## 与公共文档/设计原稿的一致性

一致部分：

- 设计原稿和公共文档都明确布局插件是箱子前端页面，Host 负责 `.box` 解析、URL/凭证/缓存、封面与资源句柄；当前 Host/SDK 已提供对应动作面。
- `manifest.yaml.tpl` 的 `type: layout`、`layout.layoutType`、最小权限和 `runtime.targets` 与 Manifest 规范基本一致。
- 模板入口 `layoutDefinition` 的总体字段与 `插件开发/04-布局插件开发.md`、`协议与契约/08-箱子布局运行时契约.md` 一致。
- `chipsdev create layout <targetDir>` 在 SDK CLI 已接入 `chips-scaffold-boxlayout/dist/src/index.js`，默认生成 `pluginId/layoutType: chips.layout.<slug>` 并调用 `adaptWorkspaceDependencies()`。

不一致证据：

- 公共契约要求 `BoxEntrySnapshot.snapshot.documentId`，模板仍是 `cardId`：`Chips-Scaffold/chips-scaffold-boxlayout/templates/boxlayout-standard/src/shared/types.ts.tpl`。
- 公共契约要求 `readEntryDetail` 字段 `documentInfo`，模板仍是 `cardInfo`；`prefetchEntries` target 也仍是 `cardInfo`。
- 公共契约要求 `resolveEntryResource.kind` 包含 `documentFile`，模板仍是 `cardFile`。
- 公共契约要求 `openEntry` 返回 `document-window | external`，模板仍是 `card-window | external`。
- 设计原稿 `10-布局插件结构.md` 明确当前正式网格箱子不再让用户手工设置列数，模板默认仍暴露 `columnCount` 并用 `gridTemplateColumns: repeat(columnCount, ...)`。
- `插件开发/04-布局插件开发.md` 要求直接显示文档封面优先使用 `EmbeddedDocumentFrame`；模板查看态仍使用 `CardCoverFrame`，且传 `cardId`。
- `文件格式规范/02-箱子文件格式规范.md` 要求布局资源路径使用 `assets/` 包内相对路径；模板 schema 未校验该约束。
- `命令行工具/02-Chips-Dev开发者命令行手册.md` 已把基础卡片生成工程 `verify` 固化为 `lint/typecheck/test/build/validate/package`，布局插件联调也要求 `build/test/lint/validate/package`；模板生成工程未提供 `typecheck/package/verify`。
