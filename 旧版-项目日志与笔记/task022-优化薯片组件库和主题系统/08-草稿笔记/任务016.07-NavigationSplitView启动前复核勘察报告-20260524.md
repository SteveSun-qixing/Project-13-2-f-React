## 建议 API / parts / token / L8 schema

### API 建议

最小正式 API：

```tsx
<ChipsNavigationSplitView.Root aria-label="Workspace navigation">
  <ChipsNavigationSplitView.Sidebar aria-label="Sources">
    ...
  </ChipsNavigationSplitView.Sidebar>
  <ChipsNavigationSplitView.Content aria-label="Items">
    ...
  </ChipsNavigationSplitView.Content>
  <ChipsNavigationSplitView.Detail aria-label="Detail">
    ...
  </ChipsNavigationSplitView.Detail>
</ChipsNavigationSplitView.Root>
```

导出建议：

- `ChipsNavigationSplitView` 等同 `ChipsNavigationSplitView.Root`。
- 静态子组件：`Root / Sidebar / Content / Detail`。
- 可选纳入：`Toolbar`。若纳入，应明确它只是 `navigation-split-view` 内部 toolbar slot wrapper，可承载现有 `ChipsToolbar`，不创建第二套 command/toolbar 语义。

Props 建议：

- `Root`：`children`、`columnVisibility/defaultColumnVisibility/onColumnVisibilityChange`、`variant`、`disabled/loading/error`、`ariaLabel/ariaLabelledBy`、`onStateChange`。
- `Sidebar`：`children`、`ariaLabel/ariaLabelledBy`、可选 `collapsed/defaultCollapsed/onCollapsedChange`。不要扩散 `showSidebar/hasSidebar/withDetail` 等 boolean mode props。
- `Content`：`children`、`ariaLabel/ariaLabelledBy`，可选；两栏模式可省略。
- `Detail`：`children`、`ariaLabel/ariaLabelledBy`，建议必填。

### Scope 与 parts 建议

建议新增独立 scope：

- `data-scope="navigation-split-view"`

建议公开 parts：

- `root`
- `sidebar`
- `content`
- `detail`
- `divider`
- `toolbar`（如纳入可选 slot）
- `status`

不建议公开为正式 parts：

- `primary / secondary`：这是 `split-view` 布局原语口径。
- `navigation-link`：应留给后续导航栈/导航项任务。
- `route / stack / destination`：超出 016.07，不应在组件库内提前实现 Host 路由。

### Token 建议

最小 required token：

- `chips.comp.navigation-split-view.root.surface`
- `chips.comp.navigation-split-view.sidebar.surface`
- `chips.comp.navigation-split-view.content.surface`
- `chips.comp.navigation-split-view.detail.surface`
- `chips.comp.navigation-split-view.divider.color`
- `chips.comp.navigation-split-view.focus.outline`
- `chips.comp.navigation-split-view.status.color.error`

如纳入 toolbar：

- `chips.comp.navigation-split-view.toolbar.surface`

可选 token：

- `chips.comp.navigation-split-view.sidebar.border.color`
- `chips.comp.navigation-split-view.content.border.color`
- `chips.comp.navigation-split-view.detail.border.color`

布局尺寸建议引用 `chips.layout.*`：

- sidebar 最小宽度可引用 `chips.layout.size.navigation-primary-min`。
- content/detail 分栏宽度可复用 `chips.layout.size.split-secondary-min` 或新增前先评估是否需要公共 layout token。
- divider 厚度引用 `chips.layout.divider.thickness`。
- focus ring 引用 `chips.layout.focus.outline-width` 与 `chips.layout.focus.outline-offset`。

### Host L8 schema 建议

建议新增：

```ts
NavigationSplitView: {
  sidebar: { type: 'Navigation', required: true, multiple: false, part: 'sidebar', role: 'navigation' },
  content: { type: ['View', 'Stack', 'Section', 'List'], required: false, multiple: false, part: 'content' },
  detail: { type: ['View', 'Stack', 'Section'], required: true, multiple: false, part: 'detail', role: 'region' },
  toolbar: { type: 'Toolbar', required: false, multiple: false, part: 'toolbar' }
}
```

建议负例：

- `primary`、`secondary` 作为 `NavigationSplitView` slot 应产生 `DECLARATIVE_UI_SLOT_UNDEFINED`。
- `sidebar` 传 `View` 而非 `Navigation` 应产生 `DECLARATIVE_UI_SLOT_TYPE_MISMATCH`，除非主代理决定 sidebar 可接受 `Section`；若放宽，应在公共文档同步。
- 重复 `sidebar/detail/toolbar` 应产生 `DECLARATIVE_UI_SLOT_MULTIPLE_FORBIDDEN`。
- 缺失 `sidebar` 或 `detail` 应产生 `DECLARATIVE_UI_SLOT_REQUIRED`。

3. ThemePack contract equality 风险。
   - 新增 `navigation-split-view` 后，组件库 contract、组件 token、ThemePack contract、ThemePack token、CSS、`theme.css` 和 `theme-min-functional-set.json` 必须同步。
   - 仅 `validate:theme` 通过不一定证明 parts/states/requiredTokens 与组件库完全等值，016.08 仍需全量 equality 门禁。

4. L8 公共 schema 风险。
   - 当前公共 L8 文档尚未冻结 `CommandPalette` 和 `NavigationSplitView`。
   - 016.07 应在实现时同步公共 L8 文档，避免 Host 代码领先公共契约。

5. A11y 角色风险。
   - `Sidebar` 应有明确导航 landmark 或可访问名称；`Detail` 应有 region 名称；divider 多数情况下应 `aria-hidden`。
   - 若 Root 默认 `role="group"`，必须提供 `aria-label` 或 `aria-labelledby`；若使用更强 landmark，应避免重复嵌套无名 region/navigation。

6. Token 命名风险。
   - 不要复用 `chips.comp.split-view.primary.*` 来样式化 `NavigationSplitView.Sidebar`。
   - 不要临时发明不存在的 `chips.sys.color.*`；需要新增系统 token 时应另行冻结公共契约。

7. 功能范围膨胀风险。
   - 016.07 不应实现完整 NavigationStack、NavigationLink、路由系统、资源管理器业务逻辑或 Host command registry。
   - 只做导航分栏结构、状态、a11y、theme contract 和 L8 slot schema。
