## 2. 024.03 真实目标、范围、验收标准

### 2.1 真实目标

024.03 不是继续扩展 024.02 的导出契约，也不是先做资源桥深度示例。它的核心目标是把基础卡片脚手架生成的查看态和编辑态样板升级为正式 React + 组件库 + 主题 token + 多语言样板：

- 生成工程默认依赖并从 `@chips/component-library` 聚合入口消费稳定组件。
- 编辑态表单从原生 `<form>/<label>/<input>/<textarea>` 与私有 CSS 改为 `ChipsForm`、`ChipsTextField`、`ChipsTextArea`、`ChipsErrorState` 和布局原语。
- 查看态不再默认包私有 surface、边框、阴影、圆角壳层；只负责内容语义与基础排版。
- 用户可见文案和错误展示走 i18n key；React render 期使用组件库同步 i18n adapter。
- 视觉值走 `--chips-*` token 或组件库公开 contract，不再硬编码色值、阴影、私有渐变。

## 3. 当前模板差距

### 3.1 查看态

当前 `src/render/view.tsx.tpl` 仍然存在私有视觉壳层：

- `VIEW_STYLE_TEXT` 中 `.chips-basecard__surface` 设置 `padding: 20px 24px`、`border-radius: 22px`、`border`、`background`、`box-shadow`。
- CSS 中有硬编码 fallback：`#111827`、`#ffffff`、`#475467`、`rgba(15, 23, 42, ...)`。
- DOM 中默认包 `<div className="chips-basecard__surface">`。
- 标题和正文直接渲染为原生 `h2/div`，未使用组件库展示组件或布局原语。

这与 `生态设计原稿/14-编辑引擎设计.md` 的“基础卡片之间不再额外包裹边框、圆角和阴影，装配层只负责结构编排”以及 `任务024.03` 的“移除私有视觉壳层”不一致。建议 024.03 将查看态改为 `ChipsBox/ChipsStack/ChipsText` 或等价组件库原语，只保留 `width: 100%`、`box-sizing`、`white-space: pre-wrap` 这类结构性最低样式，颜色/字体交给组件库与主题。

### 3.2 编辑态

当前 `src/editor/panel.tsx.tpl` 仍然是旧样板：

- 使用原生 `<form>`、`<label>`、`<input>`、`<textarea>`。
- 通过 `.chips-basecard-editor__input`、`.chips-basecard-editor__textarea` 自建输入控件视觉。
- `EDITOR_STYLE_TEXT` 中存在硬编码色值、`rgba()`、`radial-gradient`、`box-shadow`、`border-radius`、`transform` 和私有 hover/focus 样式。
- 错误态用 `<div><ul><li>` 自行展示，未使用 `ChipsErrorState` 或 `ChipsForm.Error`。
- 测试通过 `.chips-basecard-editor__input` 私有类定位输入框，变更组件库后应改成基于 label/role 或 `data-scope` 的稳定查询。

组件库真实导出已满足 024.03 所需能力：`@chips/component-library` 聚合了 `ChipsForm`、`ChipsTextField`、`ChipsTextArea`、`ChipsText`、`ChipsBox`、`ChipsStack`、`ChipsErrorState`、`createChipsI18nText`、`useChipsI18nText`。不存在必须先补组件库的新阻断。

### 3.3 UI 与主题

当前模板虽部分使用 `var(--chips-*)`，但 fallback 与私有样式仍然太重：

- 查看态使用 `var(--chips-comp-card-shell-*, fallback)`，但基础卡片不应默认套 `CardShell` 视觉。
- 编辑态自建输入视觉等同于绕过组件库 contract，主题包无法稳定通过组件库 `data-scope/data-part/data-state` 接口点覆盖。
- `template.json` 仍标注 `"componentLibrary": false`，与 024.03 目标直接冲突。
- `package.json.tpl` 只依赖 `react/react-dom`，缺 `@chips/component-library`。

建议 024.03 删除大部分私有控件 CSS，只保留根容器铺满与滚动结构；组件样式由主题包覆盖组件库公开 contract。确需保留 CSS 时只使用 `--chips-*` token，不提供硬编码颜色 fallback。

### 3.4 i18n

当前 `src/shared/i18n.ts.tpl` 是自建 `createTranslator(locale)`：

- 能读取本地 `zh-CN/en-US` 包，但没有使用公共规范要求的组件库同步 adapter。
- `schema/card-config.ts.tpl` 的 `validateBasecardConfig` 返回硬编码中文：`card_type 必须与插件声明一致`、`标题不能为空。`、`内容不能为空。`、`资源路径必须是卡片根目录内的相对路径。`
- `i18n/*.json.tpl` 已有部分 validation key，但当前 schema 没用这些 key。

建议 024.03 将 `shared/i18n.ts.tpl` 调整为围绕 `createChipsI18nText` 的本地 bundle adapter，例如导出 `localeBundles` 与 `createBasecardText(locale?)`。编辑组件 render 期传入 `i18n={t}`，组件字段使用 `labelKey`、`fallbackLabel`、`placeholder` 或 `ariaLabelKey` 等正式 props。对于 schema，建议先把 `errors` 改为稳定错误 key 或错误 code，再由编辑态显示层翻译；若 024.02 已固定 `errors: Record<string,string>`，024.03 至少不要在 UI 展示硬编码中文，应通过字段名映射到 i18n key。

### 3.5 component-library

真实组件库状态：

- `@chips/component-library` `package.json` 版本为 `0.1.0`，导出 `types` 与 `index.d.ts`。
- 聚合入口转发 `@chips/hooks`、`@chips/components`、`@chips/card-runtime`。
- `@chips/components` 已导出 `ChipsTextField`、`ChipsTextArea`、`ChipsForm`、`ChipsErrorState`、布局原语。
- `@chips/hooks` 已导出 `createChipsI18nText`、`useChipsI18nText`。

因此 024.03 可以直接依赖 `@chips/component-library: "^0.1.0"` 或按当前工作区正式 semver 口径使用 `0.1.0`/`^0.1.0`，但不能写 `file:`。
