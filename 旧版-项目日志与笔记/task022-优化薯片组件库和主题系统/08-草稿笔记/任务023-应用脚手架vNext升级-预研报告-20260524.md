说明：

- `src/main.tsx` 只负责 DOM mount 与 StrictMode，避免把运行时初始化散落在入口。

- `src/commands/*` 继续集中维护 command metadata、handlerId、owner/scope 与事件分发，不让菜单/工具栏直接绑定业务函数。
- `src/testing/*` 固化 SDK mock 和 Provider 包装，给生成项目后续业务测试复用。
- `src/preview/*` 只做预览 smoke 输入与断言，不承载运行时主实现。

### 4.2 权限建议

- 默认保留 `theme.read`，因为模板会读取当前主题并监听 `theme.changed`。
- 默认保留 `i18n.read`，因为模板会读取当前 locale 和本地同步 i18n adapter。
- `i18n.write` 只在模板默认包含“切换语言”功能时声明；如果任务023改为只展示读取状态，不提供切换按钮，应收窄默认权限，移除 `i18n.write`。
- 默认保留 `command.read/write/invoke`，用于注册模板命令、菜单、工具栏和命令面板 smoke。
- 不默认声明 `plugin.manage`、`file.read/write`、`resource.read`、`platform.external` 等业务权限。模板应通过注释性文档说明如何按业务增加，而不是默认扩大权限面。

### 4.3 commands 字段口径

任务023描述里提到 “manifest.yaml 中 ... commands ... 元信息”。结合当前正式文档与代码，建议任务023不要新增 `manifest.commands` 字段：

- 当前脚手架检查显式禁止 `manifest.commands`。证据：`scripts/check-templates.mjs:114-119`、`tests/template-engine.test.ts:107-110`。
- 当前公共命令契约要求应用通过 SDK/Host command registry 运行时注册命令，Host 不接收函数，组件库从 `command.list` 消费。证据：`生态共用技术文档/协议与契约/13-命令系统契约.md`。
- 如果后续确实要冻结 manifest 静态 command metadata，必须先同步更新 `生态共用技术文档/插件开发/06-Manifest配置规范.md`、Host manifest schema、Host command registry、SDK 类型、scaffold 检查与官方应用，而不是在模板中单点引入。

### 4.4 壳层视觉字段

- 当前模板 `backgroundColor: "#ffffff"` 和 EditingEngine `"#fafafa"` 都属于潜在主题绕开。建议任务023默认移除 `backgroundColor`，使用 Host/主题注入的页面背景；若 Host 当前要求该字段，则应在报告或后续小工单中明确“壳层背景如何接受主题 token”的公共契约。
- `ui.launcher.icon` 是系统入口图标文件，不是运行时 `IconDescriptor`；模板 README 应保留这一区分。

## 5. 默认代码入口建议

### 5.1 AppRoot / Providers

- `src/runtime/chips-client.ts` 创建单例 `createClient({ environment: "auto" })`，并允许测试注入 mock client。
- `AppProviders`：
  - 使用 `ChipsEnvironmentProvider client={chipsClient}`。
  - 从 `useChipsTheme()` 读当前 theme，传给 `ChipsThemeProvider`。
  - 使用 `eventSource={environment.eventSource}` 和 `eventName="theme.changed"`。
  - 提供 `ChipsErrorBoundary`、`ChipsLoadingBoundary`、`ChipsEmptyState`、`ChipsErrorState` 的标准状态出口。
- 不在业务组件中重复 `createClient()`；需要 SDK 的地方通过 `useChipsClient()`。

### 5.2 Scene / surface

- `MainScene` 读取：
  - `const surface = useChipsSurface()`
  - `const client = useChipsClient<Client>()`
  - `const launchContext = client.platform.getLaunchContext()`
- 以 `sceneId/surfaceId/kind/launchParams/documentContext/commandContext` 驱动场景选择。
- 不生成 `window.open`、`BrowserWindow`、`ipcRenderer`、Node `fs` 示例。
- 若需要打开新界面，用 `client.surface.open({ target: { type: "plugin", pluginId }, kind, context })` 或文档允许的 `client.plugin.launch()`。

### 5.3 View / Modifier / Layout

- 默认 UI 应用 `ChipsView/ChipsStack/ChipsGrid/ChipsSection/ChipsScrollView/ChipsNavigationSplitView` 组织，不再用大量 `<div style={...}>`。
- 表单示例使用 `ChipsForm` + `useChipsFormState`；列表示例使用 `ChipsVirtualList` 或 `ChipsDataGrid`；状态示例使用 `useChipsState/useChipsAsyncState`。
- 视觉仅通过组件库公开 props、`data-scope/data-part/data-state`、主题 CSS 变量和主题包 contract 进入，不在模板中写业务色板、阴影、圆角、字体大小。
- 可保留最小 CSS 文件用于页面根结构，但应使用语义 class 和 token 变量，且 `check-templates` 应扫描模板源码中的 `style={{`、明显 hex/rgb 色值、可见硬编码文案。

### 5.4 Commands

- `app-commands.ts` 保持 `commandId/titleKey/descriptionKey/ariaLabelKey/icon/scope/handlerId/menuPlacement/toolbarPlacement/paletteKeywords/state`。
- `use-app-commands.ts`：
  - 从 `useChipsClient()` 获取同一个 client。
  - 注册命令时处理重复注册和卸载清理；至少在组件卸载时注销本模板命令，或确认 Host session cleanup 足够并在测试中证明。
  - 监听 `client.command.onInvoked()`，按 `handlerId` 分发到本地 handler。
- UI 消费：
  - `ChipsCommandProvider adapter={createCommandAdapter(client)} i18n={text}`
  - `ChipsMenuBar`、`ChipsToolbar`、`ChipsCommandPalette` 只消费 registry，不直接绑定业务函数。

### 5.5 i18n

- `i18n/zh-CN.json`、`i18n/en-US.json` 是生成工程的本地词典。
- `src/i18n/locales.ts` 导出 `localeBundles`、`supportedLocales`，供 `useChipsI18nText` 同步渲染期使用。
- 所有可见文案和 aria label 都用 key；避免 `t(key) || "中文"` 这种历史迁移 fallback。
- 如果默认保留语言切换按钮，使用 `useChipsI18n().setLocale()`，并声明 `i18n.write`；否则不声明该权限。

### 5.6 Theme / Icon / Motion

- 默认图标使用组件库 `ChipsIcon` / command `IconDescriptor`，图标字体由主题包注入，不在模板里引入图标字体 CSS。
- motion 示例只使用组件库/主题包已定义的 motion token 或系统组件动效，不写具体 CSS keyframes 作为默认应用示范。
- 任务022主代理正在更新组件库 token 和主题包；任务023实施前应再次核对 `@chips/component-library` 与 ThemePack 最新导出，尤其是图标字体和 motion token 名称。
