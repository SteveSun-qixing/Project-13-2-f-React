## 风险与依赖

1. 并行脏改风险。
   - 当前 `git status --short` 显示 ComponentLibrary、Host、ThemePack、生态共用技术文档等多处 016.05 相关改动，另有无关 `Chips-Scaffold/chips-scaffold-basecard/node_modules/@types/node/*` 脏文件。
   - 016.06 正式开发前必须先让主代理完成 016.05 提交或明确当前可接续 diff，避免在 Tree token/contract/Host schema 上产生交叉覆盖。

2. CommandPalette 命名漂移风险。
   - 当前 runtime part 是 `search`，任务目标是 `Input`；当前 token 是 `result.*`，runtime part 是 `item`。
   - 如果只改 runtime 不改 contract/token/ThemePack/CSS/build 产物，会导致主题包能通过局部 token 校验但视觉挂点失效。

3. Command 系统边界风险。
   - `CommandPalette` 与 Host command registry 关系紧密。迁移 Compound 时不能把业务 handler、Host 服务调用或 SDK Runtime Client 主实现写进组件库。
   - `Item` 的选择动作应继续通过注入 adapter 或 command view 走 `source="palette"` 的命令调用。

4. L8 schema 与组件库 contract 不同步风险。
   - 016.06 需要同时补 Host `StandardCompoundSlotSchemas.CommandPalette` 与公共 L8 文档，否则 L8 声明树无法校验新 Compound 结构。
   - 旧 `search/result` slot 应作为负例进入 Host 单测。

5. 主题包 contract equality 风险。
   - 当前主题包 `validate:theme` 更偏 required token 覆盖，不能单独证明主题包 contract 的 parts/states/requiredTokens 与组件库 contract 完全等值。
   - 016.08 应补跨包 equality 检查，尤其覆盖 Dialog/Popover/Menu/Tree/CommandPalette/NavigationSplitView。

6. A11y 与键盘测试不足风险。
   - 当前 `CommandPalette` 仅有较浅 a11y helper 规则，正式 Compound 后应覆盖 `combobox/listbox/option/group`、`aria-activedescendant`、高亮项、disabled item 跳过、Escape、Home/End、Enter/Space。

7. 016.07 依赖 016.06。
   - NavigationSplitView 的 `Toolbar`、`Command`、`Navigation` 等语义会依赖前序 command 与 Compound slot 经验。不要在 016.06 尚未收口时提前改 `split-view` 或新增半套 navigation scope。
