## 1. 025.04 目标边界与不做事项

### 目标边界

025.04 的核心目标是升级 `boxlayout-standard` 编辑态模板，让新生成的箱子布局插件默认具备正式编辑器和箱子自有资源生命周期样板：

1. `renderEditor -> mountLayoutEditor -> LayoutEditorPanel` 全链路实际消费 `readBoxAsset/importBoxAsset/deleteBoxAsset`，而不是只在类型和参数里透传。
2. 编辑器通过正式组件库表单、选择、按钮、工具栏/错误态等控件编辑中性布局配置，不直接写 `.box/content.yaml`、`structure.yaml`、`assets/` 或文件系统。
3. 配置结构继续示范 `schemaVersion + props + assetRefs` 运行时对象；写回 `.box/content.yaml` 的 `schema_version/asset_refs` 转换由 Host/编辑引擎正式链路负责，025.04 不应在插件内绕过 Host 自行写 YAML。
4. 背景、顶部内容区等箱子自有资源通过 `importBoxAsset({ file, preferredPath })` 导入到 `assets/` 相对路径，并同步进 `assetRefs`。
5. 资源替换、切换模式或清空时调用 `deleteBoxAsset` 删除旧资源；删除失败应反馈到编辑器错误态，但不能让配置写入绝对路径或临时 URL。
6. 图片预览只通过 `readBoxAsset(assetPath)` 获取 Host 受控资源句柄，显示 `resourceUrl`，不把 `resourceUrl` 持久化进配置。
7. schema 归一与校验阻断绝对路径、反斜杠、`file://`、`blob:`、`data:`、任意 scheme、查询串、片段和 `..` 逃逸。
8. 所有用户可见文案进入 `i18n/zh-CN.json.tpl` 与 `i18n/en-US.json.tpl`，key 对齐。
9. 补齐编辑器 mount、onChange、资产导入/替换/清空/删除、缺失回调、资源读取错误、cleanup 和 schema 安全测试。

### 不做事项

1. 不改 Host / SDK 架构来迁就模板；正式链路以 `生态共用技术文档/协议与契约/08-箱子布局运行时契约.md`、`Chips-Host/packages/box-service` 和 `Chips-SDK/src/api/box.ts` 为准。
2. 不把真实 `grid-BLP/list-BLP` 的业务偏好、视觉风格或布局专属字段固化为所有新布局模板的唯一范式；只能借鉴资产桥、FrameRegion、cleanup 和宿主尺寸处理模式。
3. 不做真实 CLI e2e、生成工程 `verify`、`.cpk` 包验证或公共文档最终收口；这些应留给后续生成工程验证任务。
4. 不迁移真实业务插件本体，不批量改 `Chips-BoxLayoutPlugin/grid-BLP` 或 `list-BLP`。
5. 不抢修主题包、组件库 token、基础卡片脚手架、模块插件脚手架或 Host 编辑引擎写回链路。
6. 不登记正式问题工单；本次若发现架构缺口或文档/代码不一致，仅在报告中列证据和建议。

## 2. 当前模板编辑器与资产桥相对公共契约的差距

### P0：会直接阻断 025.04 验收

1. 编辑器 UI 没有实际消费资产桥回调。
   证据：`src/editor/panel.tsx.tpl` 的 props 声明包含 `readBoxAsset/importBoxAsset/deleteBoxAsset`，但组件解构只取 `entries/config/locale/onChange`，界面只渲染排序下拉和 `Preview` 文本；`src/index.ts.tpl` 与 `src/editor/runtime.ts.tpl` 只是把 025.02 新增的回调透传到 panel。
   影响：生成工程无法导入、读取、预览、替换或删除箱子自有资源，无法满足 025.04 “资产桥样板升级”核心目标。
   建议：新增中性的 `FrameRegionEditor` 或等价编辑区，覆盖 `background` 与 `topRegion` 两个正式通用配置示例；上传时调用 `importBoxAsset`，替换/清空时调用 `deleteBoxAsset`，预览时调用 `readBoxAsset`。

2. 资源路径安全校验不完整。
   证据：`src/schema/layout-config.ts.tpl` 的 `isSafeBoxAssetPath` 要求 `assets/` 开头、禁止开头 scheme、反斜杠和 `.`/`..` path segment，但没有阻断查询串、片段，以及 `assets/file://x`、`assets/blob:x`、`assets/data:x` 这类把 scheme 放进后续 segment 的路径。`contracts/layout-config.schema.json.tpl` 只用 `^assets/.+` 约束，也不阻断 `..`、反斜杠、查询串和片段。
   影响：配置可能持久化不应进入 `.box/content.yaml` 的不安全路径或临时 URL 片段，违反任务 025.04 和公共 `.box` 资源规范。
   建议：统一抽出并导出 `isSafeBoxAssetPath` 或 `normalizeBoxAssetPath`；至少禁止 `?`、`#`、`\`、空 segment、`.`、`..`、任意 `:`，并要求每个资源路径以 `assets/` 开头。JSON schema 的 `assetPath` 与 `assetRefs.items` 使用同一正则口径，例如只允许不含 `:?#\` 的 `assets/...` 包内路径。

3. `assetRefs` 本身没有独立校验，且测试只覆盖同步结果。
   证据：`normalizeLayoutConfig` 先从输入读取 `assetRefs`，随后 `syncAssetRefs` 用背景/顶部区域的 image `assetPath` 覆盖；`validateLayoutConfig` 只校验 `background.assetPath` 与 `topRegion.assetPath`，没有遍历 `config.assetRefs`。当前 `tests/unit/schema.test.ts.tpl` 只断言非法旧 `assetRefs` 被同步结果覆盖，没有断言 `assetRefs` 含不安全路径时 validate 报错。
   影响：后续如果布局扩展更多资源引用字段，或 Host/编辑器传入非同步资源，模板缺少对 `assetRefs` 的正式防线。
   建议：`validateLayoutConfig` 对 `assetRefs` 逐项校验；`syncAssetRefs` 只收集当前 props 中安全的 image 资源，去重并稳定排序或保持字段顺序；测试覆盖 `assetRefs: ["assets/a.png?x=1"]`、`["assets/../a.png"]`、`["assets/file://a"]` 等失败场景。

4. 编辑器没有缺失资产桥回调的错误态。
   证据：当前 panel 没有上传/读取资源 UI，自然也没有 `importBoxAsset` 缺失、`readBoxAsset` reject、`deleteBoxAsset` reject 的展示或阻断。
   影响：生成工程在没有 Host 资产桥或桥接异常时不能给出可理解状态，可能静默失败，违背“完整样板”要求。
   建议：当进入 image 模式但缺少 `importBoxAsset/readBoxAsset` 时，在对应字段显示本地化错误或禁用上传按钮；导入/读取失败进入字段级错误态；删除失败不要吞掉，应显示错误并避免误报删除成功。

5. 编辑器测试仍停留在“有 select、无 number input”的最低断言。
   证据：`tests/unit/layout-definition.test.tsx.tpl` 的编辑器测试只查询 `select` 并断言没有 number input，未覆盖资产桥、配置快照、错误态、cleanup 或 `assetRefs`。
   影响：025.04 的主要行为没有质量门禁，后续模板可能再次退回“只透传不消费”的状态。
   建议：重写编辑器测试为用户行为测试：切换背景模式、上传文件、断言 `importBoxAsset` preferredPath、断言 `onChange` 完整快照含 `props.background.assetPath` 和 `assetRefs`、替换时删除旧资源、清空时删除资源、缺失回调显示错误、cleanup 后未决预览 promise resolve 不写 DOM。

### P1：会影响生成工程质量和 Host/编辑引擎协作

1. 运行时对象字段与 `.box/content.yaml` 存储字段需要明确转换边界。
   证据：公共文件格式规范示例使用 `schema_version` 与 `asset_refs`；Host `normalizeContent` 读取 `.box/content.yaml` 时把 `schema_version/asset_refs` 转为 SDK/插件侧 `schemaVersion/assetRefs`；SDK `BoxLayoutConfig` 与真实插件均使用 camelCase 运行时对象。
   影响：这不是简单的文档错误，但模板 README 与 schema 容易让插件作者误以为应直接写 `.box` camelCase 字段。
   建议：025.04 代码继续以 Host 注入的 camelCase 对象为插件运行时契约，不在插件里写 YAML；README 或后续公共文档收口任务需说明“`.box` 存储字段为 snake_case，Host/SDK/插件运行时对象为 camelCase”。025.04 报告/实现记录中先显式标注，避免误改 Host 正式转换。

2. 编辑器根节点尺寸与宿主样式 cleanup 不如真实插件样板完整。
   证据：模板 `mountLayoutEditor` 直接 `createRoot(options.container)`，cleanup 只 `root.unmount()` 和 `container.replaceChildren()`；真实 `grid-BLP/list-BLP` 会保存并恢复 `html/body/container` 的 `display/width/height/minHeight/overflow`，让 `#chips-box-layout-editor-root` 铺满宿主并由插件内部滚动。
   影响：Host `box.renderLayoutEditor` 文档根节点已要求铺满编辑面板，模板内部若不设置 `height/minHeight/overflow`，复杂编辑区容易被外层裁切或出现双滚动。
   建议：借鉴真实插件的 style snapshot/restore 模式，但命名使用模板中性 scope；内部 body 使用 `overflowY: auto`，外层宿主只负责 flex/full-size，cleanup 恢复原样。

3. 组件库接入不足。
   证据：任务 025.04 要求“组件库表单、列表、工具栏和错误态控件”；当前 panel 使用原生 `select/label/strong` 和硬编码内联样式。组件库当前已导出 `ChipsForm`、`ChipsSelect`、`ChipsSegmentedControl`、`ChipsButton`、`ChipsTextArea`、`ChipsToolbar`、`ChipsErrorState`、`EmbeddedDocumentFrame` 等。
   影响：模板仍像临时样板，不能体现主题系统与组件库正式接口。
   建议：排序用 `ChipsSelect` 或 `ChipsSegmentedControl`；资源区域用 `ChipsForm.Section/Field/Label/Hint/Error`；上传/清空/替换用 `ChipsButton` 或 `ChipsToolbar`；错误用 `ChipsErrorState` 或 Form error，避免引入第三方库。

4. i18n key 缺口明显。
   证据：当前 `i18n/*.json.tpl` 只有空态、加载、封面缺失和排序相关 key；panel 里还有硬编码英文 `Preview`、`entries`。
   影响：新增资源 UI 后如果不先补 key，会违反“所有用户可见文案进入 i18n”。
   建议：补齐 `editor.section.layout`、`editor.section.assets`、`editor.background_title`、`editor.top_region_title`、`editor.frame_mode_none/image/html`、`editor.upload_image`、`editor.replace_image`、`editor.clear_asset`、`editor.preview`、`editor.asset_path`、`editor.asset_bridge_missing`、`editor.import_failed`、`editor.delete_failed`、`editor.read_failed`、`editor.entry_count` 等中英文 key。

5. 真实插件可参考但仍有不宜照搬之处。
   证据：`grid-BLP/list-BLP` 的 `FrameRegionEditor` 已实现上传、清空、预览和删除旧资源，但样式里有较多硬编码颜色、圆角和业务文案；`grid-BLP/src/schema/layout-config.ts` 仍未做路径安全校验，`list-BLP` 与当前模板更接近。
   影响：照搬真实插件会把业务视觉和未完全收口的旧安全口径带入标准模板。
   建议：只借鉴结构：`FrameRegionEditor`、`FrameRegionSurface`、`safeDeleteAsset`、style snapshot/restore、preferredPath 前缀；样式和字段保持模板中性，并加强安全校验。

## 4. 建议新增/更新的测试断言

### schema 测试

1. 默认配置包含 `schemaVersion: "1.0.0"`、`props.sortMode`、`props.background/topRegion` 和空 `assetRefs`。
2. `normalizeLayoutConfig` 对 `background/topRegion` 的 image `assetPath` 自动同步 `assetRefs`，去重且不会保留输入中的陈旧资源。
3. 合法路径示例：`assets/layouts/{{ LAYOUT_TYPE }}/background/hero.webp` 或中性 `assets/layouts/background/hero.webp`。
4. 非法路径全部失败或被归一移除，并由 `validateLayoutConfig` 报错：`/tmp/a.png`、`../a.png`、`assets/../a.png`、`assets/a/../../b.png`、`file:///tmp/a.png`、`blob:abc`、`data:image/png;base64,...`、`https://example.com/a.png`、`assets/a.png?token=1`、`assets/a.png#hash`、`assets\\a.png`、`assets/file://a.png`、空字符串。
5. `assetRefs` 中任一非法项返回明确错误 key，例如 `assetRefs[0]`。
6. `mode: "image"` 必须有安全 `assetPath`；`mode: "html"` 必须有非空 html；`mode: "none"` 不应保留 `assetPath/html`。
7. `validateConfig(layoutDefinition.normalizeConfig(input))` 对合法配置为 valid，对非法路径不被 normalize 悄悄变成 valid，除非测试明确断言 normalize 的安全降级策略。

### 编辑器测试

1. `renderEditor` 挂载后存在正式编辑器 root/scope，显示本地化排序、背景、顶部区域和条目数量文案。
2. 修改排序后调用 `onChange`，输出完整 normalized config，不是只输出 patch。
3. 选择背景 image 模式但缺少 `importBoxAsset/readBoxAsset` 时，上传入口禁用或显示本地化错误；不调用 undefined 回调。
4. 上传背景图片时调用 `importBoxAsset({ file, preferredPath })`；`preferredPath` 以 `assets/layouts/` 下的布局专属中性目录开头，且不包含绝对路径。
5. 导入成功后 `onChange` 输出 `props.background = { mode: "image", assetPath }`，`assetRefs` 包含该路径。
6. 背景已有旧资源时再次上传新资源，先更新配置或导入成功后调用 `deleteBoxAsset(oldAssetPath)`；断言不会删除新资源。
7. 清空 image 资源时调用 `deleteBoxAsset(assetPath)`，`onChange` 输出 `mode: "none"` 且 `assetRefs` 移除该路径。
8. 切换 image -> html 或 none 时删除旧 image 资源；切换 html -> none 不调用 delete。
9. `readBoxAsset` 成功后预览使用 Host 返回 `resourceUrl`；测试只断言显示/传入受控 URL，不把 `resourceUrl` 写入 `onChange` config。
10. `readBoxAsset/importBoxAsset/deleteBoxAsset` reject 时显示本地化字段错误，保留可恢复操作，不让整个编辑器崩溃。
11. cleanup 后容器为空，html/body/container 样式恢复；未决 `readBoxAsset/importBoxAsset/deleteBoxAsset` resolve/reject 后不再写 DOM 或触发 React act 警告。
12. 所有新增可见文案来自 i18n key；中文/英文 JSON key 集合一致。

### 模板/生成测试

2. 静态扫描模板和生成工程中不存在 `Preview`、`entries` 等硬编码英文用户文案。

## 6. 可直接用于实现的具体建议

1. 保持配置模型中性：`sortMode`、`background`、`topRegion`、`assetRefs` 足够示范 025.04，不要新增 grid/list 专属列数、密度、列表方向等必填字段。
2. 新增 `FrameRegionEditor` 的 props 贴近真实插件：`region`、`title`、`description`、`preferredAssetPrefix`、`readBoxAsset`、`importBoxAsset`、`deleteBoxAsset`、`onChange`、`locale`。
3. `preferredAssetPrefix` 使用模板变量可生成的中性路径，例如 `assets/layouts/{{ LAYOUT_TYPE }}/background` 和 `assets/layouts/{{ LAYOUT_TYPE }}/top-region`；如担心 `LAYOUT_TYPE` 含点号，先用固定 `assets/layouts/background` / `assets/layouts/top-region`，不要引入路径 slug 复杂逻辑。
4. 上传流程建议顺序：拿到 file -> 调 `importBoxAsset` -> 校验返回 `assetPath` 安全 -> `onChange(updateProps(...))` -> 若旧路径存在且不同，再 `deleteBoxAsset(oldPath)`；删除失败显示 warning/error，但不要回滚到 Host 临时 URL。
5. 清空流程：若当前 image 有 `assetPath`，先调 `deleteBoxAsset`，成功后 `onChange({ mode: "none" })`；如果删除失败，显示错误并让用户重试，避免 UI 假装资源已删。
6. 预览流程：`image + assetPath` 时 `readBoxAsset(assetPath)`；使用取消标记或 request id，cleanup/region 变化后忽略旧 promise；返回的 `resourceUrl` 只进入预览组件。
7. html 模式只把用户输入保存在 `props.*.html`，不生成 assetRefs；不要在模板里做 HTML 清洗或执行，预览用受控 iframe/srcDoc。
8. `syncAssetRefs` 只从当前 props 中收集 image `assetPath`，保证配置快照与当前 UI 一致；不要保留已经清空/替换的旧 assetRefs。
9. `isSafeBoxAssetPath` 可以采用保守规则：`value === value.trim()`、`value.startsWith("assets/")`、不包含 `\\`、`?`、`#`、`:`，按 `/` 分段后每段非空且不是 `.`/`..`。
10. 组件库优先级：表单结构用 `ChipsForm`；模式选择用 `ChipsSegmentedControl`；排序用 `ChipsSelect`；操作按钮用 `ChipsButton`；html 输入用 `ChipsTextArea`；错误用 `ChipsForm.Error` 或 `ChipsErrorState`。
11. 编辑器根节点参考真实插件 `mountLayoutEditor` 的 style snapshot/restore，但不要把 `grid/list` scope 和硬编码业务色板照搬。
12. `layoutDefinition.renderEditor` 的 `onChange(next)` 继续传 normalized complete snapshot；如 `FrameRegionEditor` 输出局部 region，panel 层统一调用 `updateConfig` 和 `normalizeLayoutConfig` 后再 `onChange`。
13. 完成后建议运行：

```bash
cd Chips-Scaffold/chips-scaffold-boxlayout
npm test
npm run test:templates
```

如主代理改动了模板引擎或生成工程依赖，再追加：

```bash
npm run build
```
