## 2. 任务016.03目标复述

任务016 是 task022 中“复杂组件 Compound API 与样式契约”的总迁移任务。016.01 已处理 Dialog / Popover / Tabs，016.02 将处理 Menu / Select，016.03 是下一批 Form Compound 迁移，目标是把表单从当前 `ChipsFormField / ChipsFormGroup` 等单体结构，收口为正式 `Form.Root / Form.Section / Form.Field / Form.Label / Form.Control / Form.Error / Form.Hint` Compound API。

016.03 在整个序列中的位置：

- 继承 016.01 的 Root 子组件、上下文、slot part、ARIA 关系和 Host L8 schema 同步模式。
- 等待 016.02 对 Menu / Select 的命名收口经验，尤其是 `Content/list` 这类 part 口径统一经验。
- 重点解决 Form 自身命名漂移：`form-field/field`、`form-group/section`、`helper/hint`。
- 为后续 016.04 DataGrid、016.05 Tree、016.06 CommandPalette、016.07 NavigationSplitView 留出同一套 contract/schema/test 收口路径。

016.03 不应提前处理的后续工作：

- 不应提前做默认主题和暗色主题的整体视觉重设计、密度重调、对比度全量矩阵、主题展示页或主题包长期治理。这些属于主题包升级、016.08 全量契约一致性或任务14主题治理范围。
- 不应把业务校验、字段注册、dirty/touched/submitted 状态、配置持久化和 `useChipsFormState/useFieldBinding` 全量模型塞进本任务。这些属于任务017和阶段任务10。
- 不应迁移 DataGrid、Tree、CommandPalette、NavigationSplitView 等后续 Compound 组件。
- 不应为了兼容旧 API 同时长期保留两套公开命名。当前第一版未发布，016.03 应一次性明确正式命名；如保留内部 helper，不能作为公开主 API 继续扩散。

## 4. 关键差距清单

### 4.1 必须在016.03解决

1. 补正式 `ChipsForm` Compound runtime API。
   - 证据：`Chips-ComponentLibrary/packages/components/src/index.js` 未发现 `ChipsForm` 或 `Form.Root` 导出；`index.d.ts` 未发现 Form Compound 类型。
   - 判断：016.03 的验收目标是 `Form.Root/Section/Field/Label/Control/Error/Hint`，当前 L10 没有对应运行时入口。

2. 统一 `helper/hint` 口径。
   - 证据：`form-field.contract.json`、`COMPONENT_TOKEN_MAP["form-field"]`、ThemePack token/CSS 均使用 `helper`；`生态共用技术文档/架构设计/17-L8声明式UI实现与接口细则.md` 与 016.03 任务文档使用 `hint`。
   - 判断：这是 016.03 最明确的命名漂移。建议以 `Hint` / `data-part="hint"` / `chips.comp.form.*.hint.*` 或同等正式新口径为准，同步 runtime、类型、contract、token、CSS、公共文档和测试。

3. 统一 `form-field/field` 与 `form-group/section` 职责边界。
   - 证据：当前组件库公开 `ChipsFormField` 和 `ChipsFormGroup`；Host L8 schema 使用 `field`、`section`；任务016.03 要求 `Form.Section / Form.Field`。
   - 判断：建议主代理在 016.03 明确 `Form` 作为正式 scope，`Field/Section` 作为 part 或子 scope 的最终命名。若旧 `ChipsFormField/ChipsFormGroup` 保留为内部实现或独立旧组件，也不能与新 Form contract 形成两个长期公开主口径。

4. 补 Form contract、token 与主题 CSS 的最小正式闭环。
   - 证据：没有 `Chips-ComponentLibrary/packages/theme-contracts/contracts/components/form.contract.json`，没有 `packages/tokens/tokens/comp/form.json`，ThemePack 默认/暗色也没有 `tokens/comp/form.json` 和 `data-scope="form"` CSS。
   - 判断：如果 016.03 新增正式 `form` scope，必须同步组件库 contract、组件库 token、ThemePack 默认/暗色 token、ThemePack CSS 与 contract JSON。否则 Host schema 和 L10 contract 会继续断开。

5. 补 TypeScript 声明和测试。
   - 证据：`index.d.ts` 只有 `FormFieldProps` 与 `FormGroupProps`；`index.test.mjs` 只覆盖旧 form-field/form-group contract 和导出。
   - 判断：需要新增 `FormRootProps / FormSectionProps / FormFieldProps / FormLabelProps / FormControlProps / FormErrorProps / FormHintProps` 或同等命名，并声明 `ChipsForm` 的 Compound 静态子组件。

6. 建立 label/control/error/hint 的 DOM 与 ARIA 关系。
   - 证据：`ChipsFormField` 内部能为自己创建 `inputId/descriptionId/errorId`，但没有泛化给任意子控件；`Checkbox/RadioGroup/Switch/Slider` 等控件的错误、hint 和外部 label 关联没有统一 Form context。
   - 判断：Form.Root/Field 应负责生成稳定 id、required/invalid/disabled/readOnly 状态、describedby 列表；Label/Control/Error/Hint 消费同一 context，保证 `htmlFor/id/aria-describedby/aria-invalid/aria-required` 一致。

7. 对齐 Host L8 `StandardCompoundSlotSchemas.Form`。
   - 证据：当前 `field` slot 的 `type` 是 `Form`，`control` slot 是 `View | Command`，`label/error/hint` 是 `Text`；这不直接表达 `Form.Field` 子结构，也无法区分 label/control/error/hint 是否在同一个 field 内。
   - 判断：016.03 应复核 schema 是否需要调整为更贴近新 Compound contract 的结构，至少增加 missing/repeated/type mismatch 诊断测试，避免 L8 允许的树和 L10 组件真实结构不一致。

### 4.3 建议主代理登记问题工单候选

1. Host L8 Form schema 与 L10 FormField 命名长期漂移。
   - 证据：`Chips-Host/src/renderer/declarative-ui/composition.ts` 有 `StandardCompoundSlotSchemas.Form`，但组件库没有 `ChipsForm`，只有 `form-field/form-group`；公共 L8 文档用 `hint`，组件库与主题用 `helper`。
   - 判断：若 016.03 能一次性收口，不需要额外工单；若主代理发现必须新增 L8 `Field` 语义原语或跨任务调整 L8/L9 类型系统，建议登记为架构工单候选。

2. 旧 `ChipsInput` 类型允许任意 props，但 runtime 未转发 aria/rest props。
   - 证据：`InputProps` 有 `[key: string]: unknown`，a11y 测试可对 `input` scope 传入 `aria-label`；`ChipsInput` runtime 仅解构固定 props，不把 `aria-label/aria-describedby/id/name` 等外部属性传到 DOM。
   - 判断：如果 016.03 需要将旧 `ChipsInput` 作为正式 Form.Control 子控件，这会影响 label/control 关联。若不在 016.03 处理，建议登记组件 runtime/type/a11y 漂移工单。

3. 旧 Checkbox / RadioGroup / Switch 的错误描述关联不足。
   - 证据：这些控件有 status/error 展示，但未形成可由外部 Form.Field 统一注入的 `aria-describedby` 主链路。
   - 判断：如果 Form.Control 要支持所有表单控件，这属于 016.03 相关风险；若主代理选择先保证新 Form 原语，再分控件接入，则建议登记后续 a11y 接入工单。

4. 设计原稿中的技术栈旧口径需要复核。
   - 证据：`生态设计原稿/13-公共基础层设计.md` 仍出现“Ark UI 作为 Vue 3 框架绑定层”表述；当前 AGENTS 和 `生态共用技术文档/架构设计/19-前端框架vNext公共契约与术语冻结.md` 明确官方前端统一 React。
   - 判断：本报告按当前更高优先级规范和代码现状使用 React 口径。该原稿漂移不阻断 016.03，但适合后续由主代理评估是否登记文档漂移工单。

## 5. 推荐实施顺序

1. 冻结 Form 命名与结构。
   - 文件：`Chips-ComponentLibrary/packages/components/src/index.js`
   - 建议先定义内部 Form context 与 id 生成规则：root id、field id、label id、control id、hint id、error id、describedby 顺序、required/invalid/disabled/loading/readOnly 状态来源。
   - 建议正式 API 为 `ChipsForm.Root / Section / Field / Label / Control / Error / Hint`，并通过 `Object.assign` 或当前项目已有 Compound 模式导出统一入口。

2. 实现 runtime Compound 子组件。
   - 文件：`Chips-ComponentLibrary/packages/components/src/index.js`
   - `Root` 输出 `data-scope="form"`、`data-part="root"`，可使用原生 `form`，只处理结构状态和 `onSubmit` 语义，不实现业务校验。
   - `Section` 输出 `section` 或 `fieldset` 语义，明确与旧 `form-group` 的关系。
   - `Field` 建立每个字段的上下文，聚合 required/invalid/describedby。
   - `Label` 自动读取 `htmlFor` 并允许外部覆盖。
   - `Control` 支持原生控件和 Chips 控件，至少要保证 `id/aria-describedby/aria-invalid/aria-required/disabled/readOnly` 可落到真实可交互节点；如果 clone 子元素，必须覆盖冲突策略并测试。
   - `Error` 与 `Hint` 只负责结构、id、aria-live 或描述文本，不承载校验规则。

3. 同步类型声明。
   - 文件：`Chips-ComponentLibrary/packages/components/src/index.d.ts`
   - 新增 Form Compound 类型、各子组件 props、ref 类型与 `ChipsForm` 导出声明。
   - 若保留旧 `FormFieldProps/FormGroupProps`，明确它们不是新 Compound 主入口，避免类型层鼓励旧模式。

4. 同步组件 metadata 与 build contract helper。
   - 文件：`Chips-ComponentLibrary/packages/components/src/index.js`
   - 更新 `COMPONENT_TOKEN_MAP`、`buildComponentContract` 的组件映射、`P0_DATA_FORM_COMPONENTS` 或同类 metadata。
   - 如果正式新增 `form` scope，metadata 应包含 `root / section / field / label / control / error / hint / status` 或主代理最终冻结的 parts。

5. 同步 theme-contracts。
   - 文件：`Chips-ComponentLibrary/packages/theme-contracts/contracts/components/form.contract.json`
   - 文件：`Chips-ComponentLibrary/packages/theme-contracts/tests/component-contract.test.mjs`
   - 文件：`Chips-ComponentLibrary/packages/theme-contracts/tests/validator.test.mjs`
   - 新增或迁移 Form contract。不要让 `form-field.helper` 与 `form.hint` 同时作为未解释的正式公开 part。

6. 同步组件 token。
   - 文件：`Chips-ComponentLibrary/packages/tokens/tokens/comp/form.json`
   - 文件：`Chips-ComponentLibrary/packages/tokens/tests/token-contract.test.mjs`
   - 文件：`Chips-ComponentLibrary/scripts/validate-tokens.mjs`
   - token 命名建议与新 parts 对齐，例如 `chips.comp.form.field.gap`、`chips.comp.form.label.color`、`chips.comp.form.hint.color`、`chips.comp.form.error.color`、`chips.comp.form.focus.outline`。最终以主代理冻结命名为准。

7. 同步 ThemePack 默认和暗色主题。
   - 文件：`ThemePack/Chips-default/tokens/comp/form.json`
   - 文件：`ThemePack/Chips-theme-default-dark/tokens/comp/form.json`
   - 文件：`ThemePack/Chips-default/styles/components/layout-containers.css` 或更合适的组件 CSS
   - 文件：`ThemePack/Chips-theme-default-dark/styles/components/layout-containers.css` 或更合适的组件 CSS
   - 文件：`ThemePack/*/contracts/theme-interface.contract.json`
   - 文件：`ThemePack/*/contracts/theme-min-functional-set.json`
   - 只做 contract 必需的 token/CSS 挂点同步，不扩大为主题视觉重做。

8. 同步 Host L8 schema 和单测。
   - 文件：`Chips-Host/src/renderer/declarative-ui/composition.ts`
   - 文件：`Chips-Host/tests/unit/declarative-ui.test.ts`
   - 复核 `StandardCompoundSlotSchemas.Form` 的 slot 类型、必填、单例/多例和 `part` 是否与新 Form contract 一致。
   - 增加缺失 `field/control`、未知 `helper`、错误 `hint` 类型、重复单例等诊断测试。

9. 同步公共组件文档。

## 6. 测试建议

### 6.1 最小验证命令


若只想先跑针对性 Host 单测，可用：

```bash
cd Chips-Host
npm test -- tests/unit/declarative-ui.test.ts
```

### 6.2 组件库专项单测建议

- `ChipsForm.Root` 输出 `data-scope="form"`、`data-part="root"`、正确 form role/submit 行为，并且不写入视觉样式。
- `Form.Field` 自动生成稳定 id；多个字段不会冲突。
- `Form.Label` 自动关联当前 field control，输出 `htmlFor` 或 `aria-labelledby`。
- `Form.Control` 可承载原生 `input/textarea/select`，并注入 `id/required/aria-required/aria-invalid/aria-describedby`。
- `Form.Control` 可承载 `ChipsTextField/ChipsTextArea/ChipsCheckbox/ChipsSwitch/ChipsSlider/ChipsNumberInput` 的代表路径，确保不会丢失控件原有 role 和 keyboard 行为。
- `Form.Hint` 和 `Form.Error` 同时存在时，control 的 `aria-describedby` 包含二者 id，顺序稳定。
- `Form.Error` 存在时 field/root/control 的 `data-state`、`aria-invalid` 和 live region 表达一致。
- `required/disabled/loading/error/readOnly` 组合状态下，Form context 和子控件状态不互相覆盖错误。
- 未提供 Label 且 Control 没有可访问名称时，组件或 a11y helper 能报告明确错误。

### 6.3 Host L8 专项测试建议

- `StandardCompoundSlotSchemas.Form` 合法树通过：至少包含 `field` 和 `control`，可选 `section/label/error/hint`。
- 缺失必填 `field` 或 `control` 输出 `DECLARATIVE_UI_SLOT_REQUIRED`。
- 未声明 slot 例如 `helper` 输出 `DECLARATIVE_UI_SLOT_UNDEFINED`，前提是 016.03 正式冻结 `hint`。
- slot 类型不匹配输出 `DECLARATIVE_UI_SLOT_TYPE_MISMATCH`。
- 如果某些 slot 是单例，重复时输出 `DECLARATIVE_UI_SLOT_MULTIPLE_FORBIDDEN`。
- root props 中 `showHint/isInline/withError` 这类 boolean 模式仍应被 `guardAgainstBooleanModeProps` 拦截。

### 6.4 已知失败项判定建议

- 本轮只读勘察前后，`git status --short` 显示存在并行或既存未提交改动，包括 `Chips-Scaffold/chips-scaffold-basecard/node_modules/@types/node/*`，以及 016.02 相关的 `Chips-ComponentLibrary/packages/components/src/index.js`、`ThemePack/*/tokens/comp/menu.json`、`ThemePack/*/tokens/comp/select.json`、`ThemePack/*/styles/components/*`、`ThemePack/*/contracts/theme-interface.contract.json` 等。016.03 验证若出现与这些文件相关的失败，主代理需要先区分是否来自并行 016.02 或既存状态，不要在 016.03 回退他人修改。
- 若组件库测试失败集中在 `menu/select` contract 或 part 命名，主代理需要先确认是否来自 016.02 并行改动。
- 若 ThemePack 测试只因新增 `form` contract 未同步默认/暗色 token 失败，则属于 016.03 必须修复的契约同步问题。
- 若失败涉及 `useChipsFormState/useBinding` 缺失，应判断是否被 016.03 新代码主动依赖。016.03 不应依赖尚未完成的任务017状态模型。

## 7. 风险提醒

1. a11y 是本任务最高风险。Form 的核心不是视觉分组，而是 label/control/error/hint 的可访问关系。`aria-describedby`、`aria-invalid`、`aria-required`、`htmlFor/id`、live region 和 required indicator 必须同轮测试。

2. Form.Control 注入策略需要谨慎。当前很多已有控件自己管理 label、description、status；如果 Form.Field 同时接管 label/hint/error，容易出现双 label、双 describedby、重复 error 或可访问名称冲突。

3. 受控/非受控值不应在 016.03 被 Form.Root 统一接管。现有控件已经分别支持 `value/onValueChange`、`checked/onCheckedChange` 等模式；016.03 应保证结构和 context 不破坏这些模式，完整 binding 留给任务017。

4. `helper/hint` 不能继续漂移。任务016.08 已明确不要留下未解释的 `helper/hint` 等命名漂移；016.03 是收口点。

5. `form-field` 与 `form` scope 的关系需要一次性说清。若新增 `data-scope="form"`，ThemePack 和 contract 必须同步；若继续使用 `form-field` 作为 field 子 scope，也必须在公共文档和 Host schema 中明确映射。

6. 键盘交互要保护已有控件行为。Checkbox、Radio、Switch、Slider、NumberInput、TextField 等已有各自键盘路径，Form.Control 不应吞掉 Enter、Space、方向键、Home/End、PageUp/PageDown。

7. data-part/data-state 与 token/CSS 必须同源。`Form.Hint` 如果输出 `data-part="hint"`，主题 CSS 不能还只写 `[data-part="helper"]`；contract tokens 也不能继续只声明 `chips.comp.form-field.helper.color`。

8. ThemePack 修改只做契约必要同步。不要在 016.03 扩大为主题包视觉改版，否则会和后续主题专项及并行任务冲突。

## 8. 主代理接手摘要

016.03 的起点不是“给旧 FormField 改名”，而是建立正式 Form Compound API，并让 L10 runtime、类型、组件 contract、token、ThemePack CSS、Host L8 schema、公共文档和测试使用同一套命名。当前最需要先冻结的决策是：

- 是否新增正式 `form` scope。
- `Form.Section` 与旧 `form-group` 的关系。
- `Form.Field` 与旧 `form-field` 的关系。
- `Hint` 是否替代旧 `helper` 作为唯一正式口径。
- `Form.Control` 如何把 `id/aria-describedby/aria-invalid/required` 安全传递给原生控件和 Chips 控件。

建议主代理先用最小 Form Compound API 打通一个文本输入字段主流程，再扩展到 Checkbox/Switch/Slider 等不同 control 形态，最后同步 ThemePack 和 Host L8 诊断测试。
