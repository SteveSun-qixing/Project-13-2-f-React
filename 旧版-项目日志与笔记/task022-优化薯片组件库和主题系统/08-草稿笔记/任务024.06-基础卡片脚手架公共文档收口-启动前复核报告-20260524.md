## 高优先级差异

1. 公共文档缺少“生成工程默认目录”的完整收口。

   `03-卡片插件开发.md` 当前推荐结构只覆盖 `src/index.ts`、`src/render`、`src/editor`、`src/schema`、`src/shared`。真实 `card-standard` 模板和 README 还包含 `.eslintrc.cjs`、`chips.config.mjs`、`config/logging.ts`、`i18n/zh-CN.json`、`i18n/en-US.json`、`templates/default-card-config.yaml`、`templates/parameters.md`、`vitest.config.mts`、`tests/unit/schema.test.ts`、`assets/icons/SOURCE.md` 等。024.06 应在 `03-卡片插件开发.md` 增加“基础卡片脚手架默认生成工程结构”小节，避免开发者只按旧简化结构建项目。

2. 公共 CLI 文档未显式说明 card 生成工程默认脚本。

   `02-Chips-Dev开发者命令行手册.md` 已列出 `chipsdev create card`、`build/test/lint/validate/package`，也提到 `npm run verify` 是各仓库正式验证命令之一；但没有明确基础卡片脚手架生成工程当前默认包含 `dev/build/test/lint/typecheck/validate/package/verify`，且 `verify` 串联 `lint -> typecheck -> test -> build -> validate -> package`。真实 `package.json.tpl` 当前已经包含这些脚本。024.06 应在命令行手册的“创建工程”或“构建、打包与校验”处补基础卡片生成工程说明。

3. 公共文档没有集中说明 `resource_path` 作为基础模板默认资源字段。

   `03-卡片插件开发.md` 已说明卡片内部资源必须是卡片根目录相对路径，并说明资源桥动作；但配置示例仍是富文本 `content_text/content_file`，没有把 `card_type/theme/title/body/locale/resource_path` 这个脚手架默认配置模型写清。真实模板 `card-config.ts.tpl`、`default-card-config.yaml.tpl` 和 README 都已经以 `resource_path` 为默认资源样板。024.06 应补充“脚手架默认 schema 只是通用样板，业务卡片可扩展，但内部资源字段必须走 card-root 相对路径校验与 `collectResourcePaths`”。

4. README 模板仍未完全反映真实生成工程目录。

   当前 `README.md.tpl` 已加入验证链路和 `chipsdev` 口径，但项目结构还漏列 `vitest.config.mts`、`tests/unit/schema.test.ts`，也没有列出 `typecheck/package/verify` 在 `package.json` 中的存在。由于 024.06 范围包含 `README.md.tpl`，建议主代理同步修 README；公共文档再引用 README 的目录口径。

   默认配置模板已有 `resource_path: ""`，schema 和测试也围绕 `resource_path` 做校验，但参数说明只列到 `locale`。这属于生成工程内部文档与模板不一致，建议 024.06 顺手补齐。

3. `03-卡片插件开发.md` 的测试策略仍偏抽象。

   文档已有查看态、编辑态、schema、cleanup、Host 通用链路、编辑引擎链路测试要求，但没有体现基础卡片脚手架当前模板的默认测试文件：`schema.test.ts`、`render-view.test.tsx`、`editor-panel.test.tsx`、`card-flow.test.ts`。建议补一段“脚手架默认测试覆盖”而不是替换通用测试策略。

4. `Manifest配置规范.md` 对 card manifest 示例不够完整。

   `06-Manifest配置规范.md` 已要求 card 插件声明 `runtime.targets`，但 `03-卡片插件开发.md` 中 manifest 示例仍是简化版，没有展示 `runtime.targets`。为避免重复定义，建议 `03` 只给最小示例并明确“完整字段以 `06-Manifest配置规范.md` 为准”，或把示例补到与当前 `manifest.yaml.tpl` 一致。

5. 组件库/i18n/主题的脚手架默认样板在公共文档中还不够明确。

   `03-卡片插件开发.md` 只写“主题适配”和“推荐 shared/i18n.ts”，没有明确当前基础卡片脚手架默认使用 `@chips/component-library`、`ChipsBox/ChipsStack/ChipsText`、`ChipsForm/ChipsTextField/ChipsTextArea/ChipsErrorState`、`createChipsI18nText()`、`i18n/zh-CN.json` 与 `i18n/en-US.json`。这会让新开发者低估组件库和多语言的默认强制性。

6. `template.json` 会被模板引擎复制到生成工程。

   `template-engine.ts` 会遍历并写入模板目录全部文件，`template.json` 也会进入生成工程。当前测试也读取生成后的 `template.json`。若 024.05/024.06 认为“生成工程不泄露模板身份”包括不保留 `template.json` 或不保留 `card-standard`，需要先澄清实现口径；若保留 `template.json` 是正式工程元数据，公共文档和门禁应明确它不是泄露身份。
