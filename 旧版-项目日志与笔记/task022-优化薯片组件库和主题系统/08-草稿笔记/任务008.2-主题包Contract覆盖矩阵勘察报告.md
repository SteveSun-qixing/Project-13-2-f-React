## 4. 主题包测试与验证脚本现状

两个主题包 `package.json` 脚本结构一致：

| 脚本 | 命令 | 对应文件/链路 |
|---|---|---|
| `build:tokens` | `tsx src/build-tokens.ts` | 合并 `tokens/ref.json`、`tokens/sys.json`、`tokens/motion.json`、`tokens/layout.json` 与 `tokens/comp/*.json` 到 `dist/tokens.json` |
| `build:css` | `tsx src/build-css.ts` | 合并 `styles/base.css`、`styles/components/*.css`、`styles/motions.css`，复制图标字体到 `dist/` |
| `build` | `npm run build:tokens && npm run build:css` | 构建 tokens 与 CSS |
| `validate:theme` | `tsx src/validate-theme.ts` | 使用本包硬编码 `REQUIRED_THEME_TOKENS` 校验 `dist/tokens.json` |
| `test` | `vitest run` | 运行 `tests/*.spec.ts` |

现状判断：

- 两个主题包的 `contracts/theme-interface.contract.json` 都只声明 `button/input`，没有同步组件库 46 个正式 contract。
- 两个主题包的 `contracts/theme-min-functional-set.json` 都只声明 `button`，甚至没有包含 `input`。
- 默认主题 `src/validate-theme.ts` 不是只校验 `button/input`：它还校验 18 个布局原语相关 required token 与 6 个 `chips.sys.icon.*` token。但它仍是手工白名单，只覆盖布局原语、图标、button、input，没有读取组件库正式 46 个 contract。
- 暗色主题 `src/validate-theme.ts` 当前只校验图标、button、input，未校验布局原语，因此没有挡住暗色主题缺 `view/box/stack/inline/grid/section/scroll-view/spacer/divider/split-view`。
- 两个主题包的 `tests/contract.spec.ts` 都只是复用本包 `REQUIRED_THEME_TOKENS`，不会发现 `theme-interface.contract.json` 与组件库正式 contract 分叉，也不会发现命令消费组件缺 token。
- `tests/tokens.spec.ts` 只校验五层结构存在；`tests/build.spec.ts` 只校验构建和图标字体；暗色主题额外 `tests/dark-theme.spec.ts` 校验身份、`color-scheme: dark` 与暗色基准色。

应扩展的位置：

- `ThemePack/Chips-default/src/validate-theme.ts`
- `ThemePack/Chips-default/tests/contract.spec.ts`
- `ThemePack/Chips-theme-default-dark/src/validate-theme.ts`
- `ThemePack/Chips-theme-default-dark/tests/contract.spec.ts`
- 必要时扩展 `tests/tokens.spec.ts`，检查 `dist/tokens.json` 中的 `comp.chips.comp` 覆盖组件库 46 个正式组件节点。

推荐验证口径是直接消费 `@chips/theme-contracts` 的 `buildThemeContractView` 或等价 validator API，读取 `Chips-ComponentLibrary/packages/theme-contracts/contracts/components` 的正式 contract 作为唯一基线，而不是继续维护主题包本地硬编码 required token 白名单。

- 两个主题包运行 `npm run build` 后应刷新 `dist/tokens.json` 与 `dist/theme.css`。
- 如果当前打包链路要求提交 `.cpk-stage`，还需要通过正式打包/校验链路刷新 `.cpk-stage/contracts/*` 与 `.cpk-stage/tokens/*`，不要手工直接拼临时产物。

### 5.2 必须同步核对的组件库与文档

建议主代理同步核对：

- `Chips-ComponentLibrary/packages/theme-contracts/contracts/components/*.contract.json`
- `Chips-ComponentLibrary/packages/theme-contracts/src/validator.js`
- `Chips-ComponentLibrary/scripts/validate-theme-contracts.mjs`
- `生态共用技术文档/主题系统/01-主题包开发指南.md`
- `生态共用技术文档/主题系统/02-主题接口规范.md`
- `生态共用技术文档/组件库/02-组件契约标准.md`
- `生态共用技术文档/组件库/03-Token与主题对接标准.md`

文档同步重点：

- 明确官方主题包的 `theme-interface.contract.json` 是否必须完整镜像组件库正式 46 个 component contract。
- 明确 `theme-min-functional-set.json.requiredComponents` 的正式语义：是最低可启动集合，还是当前主题应用阻断集合。当前两个主题都只写 `button`，与 008.2 的完整 contract guard 目标不一致。
- 明确主题包 validator 必须消费组件库正式 contract 与统一诊断 schema，避免各主题包继续维护私有硬编码 token 白名单。
- 若新增命令消费组件和布局原语 token，需要把组件清单、token 前缀和 required token 口径同步到组件库与主题系统文档。
