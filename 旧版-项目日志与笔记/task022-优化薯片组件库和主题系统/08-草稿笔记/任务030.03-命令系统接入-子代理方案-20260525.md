## 2. 公共链路现状

公共契约要求 Host command registry 是菜单、工具栏、快捷键、命令面板和上下文菜单的唯一事实来源。SDK 已提供 `client.command.register/unregister/get/list/setState/invoke` 与 `onRegistered/onUnregistered/onChanged/onInvoked`。Host 已实现 `command.read/write/invoke/manage` 权限校验、scope 校验、placement/schema 校验、状态派生和快捷键注册清理。

组件库已有命令消费层：

- `ChipsCommandProvider`
- `createCommandAdapter(client)`
- `ChipsToolbar / ChipsToolbarItem`
- `ChipsMenuBar`
- `ChipsContextMenu`
- `ChipsCommandPalette`
- `ChipsShortcut`
- `resolveCommandToolbarItems / resolveCommandMenuGroups / resolveCommandPaletteItems`

组件库运行实现会从 `titleKey / descriptionKey / ariaLabelKey` 解析文案，使用 `ChipsIcon` 渲染 `IconDescriptor`，并在点击时以 `source="toolbar" / "menu" / "context-menu" / "palette"` 调用 adapter。030.03 不需要自建 UI registry。

## 3. manifest 权限

`Chips-EditingEngine/manifest.yaml` 当前缺少命令权限。030.03 开始时应补齐：

- `command.read`：菜单、工具栏、命令面板读取命令视图。
- `command.write`：编辑引擎注册、注销、更新自己拥有的命令。
- `command.invoke`：本应用 UI、快捷键和命令面板触发命令。

不建议声明 `command.manage`，因为编辑引擎不应跨 owner 管理全局命令。

说明：

- 撤销/重做不能用 Host registry 替代 `core/command-manager`。Host command 只负责调度，handler 内部继续调用 `getCommandManager().undo()/redo()`。
- `permission` 不应全部写成 `command.invoke`。涉及文件创建/删除/重命名、配置写入、主题读取等动作，必须保留业务权限。
- `enabledWhen` 在首批可先使用显式 `state.enabled`，因为现有组件库和 Host 已支持 `command.setState`；后续再接结构化 condition 与 State/Binding 环境。

## 5. 可迁移入口

030.03 可优先迁移低冲突入口：

- `Dock` 的设置入口：从 `onOpenSettings` 直接回调迁移为 `settings.open` command 调用。
- `HeaderBar` 预留 toolbar：渲染 `ChipsToolbar toolbarId="workspace"`，布局和主题按钮改由 command view 消费。
- `FileManager` 顶部新建卡片、新建盒子、搜索按钮：迁移到 `file.new-card/new-box/search.workspace`。
- `FileManager/ContextMenu` 的新建、打开、重命名、删除、刷新：迁移为 `ChipsContextMenu` 或由同一 command metadata 派生本地右键菜单。
- `HistoryPanel` 的撤销/重做：按钮触发 Host command invoke，handler 仍调用内部 `CommandManager`。
- `LayoutSwitcher` / `HeaderBar` 的布局切换：迁移为 `view.toggle-layout`。
- `EngineSettingsDialog` 打开入口：迁移为 `settings.open`，弹窗内部分类切换和重置先保留本地状态。

暂缓迁移：

- 卡片窗口 `WindowMenu` 的锁定、封面、设置：需要 030.04/030.05 形成稳定 document/window runtime context 后再决定 `document` scope 和 `documentId`。
- 卡片导出、封面保存、箱子导入条目：依赖 030.05 工作区/资源/保存链路收口。
- 箱子布局预览与编辑面板内命令：依赖 030.06 箱子文档 runtime。
- 命令面板全局 UI：建议先完成注册与 toolbar/menu 消费，再在 030.07 工作台 UI 收口时决定展示位置和焦点模型。

## 6. 030.02 应预留的接口

030.02 的 AppRuntime/Scene 骨架应避免把命令系统实现写死，但需要预留以下边界：

- `AppRuntimeContext` 暴露唯一 `client`，后续 `createCommandAdapter(runtime.client)` 不再重复 `createClient()`。
- `AppRuntimeContext` 暴露 `environment` 或最少 `appId / sceneId / surfaceId / launchParams`，命令注册可据此生成 app/scene/surface scope。
- `AppShell` 保留 `openSettings()` 状态入口，030.03 可把它绑定到 `settings.open` handler。
- `WorkspaceScene` 保留工作区场景的稳定 scene id，如 `workspace`，后续 command query context 可包含 `{ sceneId: "workspace" }`。
- 不要在 030.02 提前把菜单、工具栏、快捷键业务函数塞进 runtime provider。runtime provider 只管理环境、启动、主题/i18n、插件事件；command 注册和 handler dispatch 放到 `src/commands/`。
- 默认工具窗口创建仍通过 `useUI().createToolWindow`，避免命令系统直接依赖 window manager 私有对象。

## 7. 测试建议

030.03 应新增或调整：

- `tests/unit/manifest-permissions.test.ts`：断言 manifest 包含 `command.read/write/invoke`，且不包含 `command.manage`。
- `tests/unit/commands-definition.test.ts`：断言 commandId/handlerId 稳定、无 raw `title/description/label/ariaLabel`、所有文案字段是 key、所有 icon 为 `IconDescriptor`、placement 排序稳定。
- `tests/unit/commands-runtime.test.tsx`：mock `client.command.register/unregister/setState/onInvoked`，断言挂载注册、卸载注销、重复挂载不重复注册。
- `tests/unit/commands-invocation.test.tsx`：模拟 `command.invoked`，断言 `settings.open` 打开设置、`edit.undo/redo` 调用内部 `CommandManager`、file commands 调用 `workspaceService`。
- `tests/unit/app.test.tsx`：根组件包裹 `ChipsCommandProvider` 后仍渲染工作台，注册失败时不阻断工作区启动。
- `tests/unit/file-manager.test.tsx`：右键菜单和工具栏不再分叉出两套动作，invoke 后仍创建/打开/重命名/删除文件。

关键断言：

- 菜单、工具栏、右键菜单、命令面板消费同一 `CommandView[]`。
- 触发来源分别传入 `source="menu" / "toolbar" / "context-menu" / "palette"`。
- disabled command 不调用业务 handler。
- 撤销/重做状态随内部历史更新后通过 `command.setState` 同步。
- language/theme 事件后命令 UI 文案与图标仍由 i18n 和 `ChipsIcon` 解析。
