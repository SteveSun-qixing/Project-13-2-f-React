## 1. 016.06 正式目标 API 建议

任务016.06 的正式 Compound API 应以任务文档冻结的结构为主：

```tsx
<ChipsCommandPalette.Root>
  <ChipsCommandPalette.Input />
  <ChipsCommandPalette.List>
    <ChipsCommandPalette.Group>
      <ChipsCommandPalette.Item />
    </ChipsCommandPalette.Group>
  </ChipsCommandPalette.List>
</ChipsCommandPalette.Root>
```

建议导出形态：

- `ChipsCommandPalette` 本身等同 `ChipsCommandPalette.Root`，延续 016.01/016.02/016.03 已采用的 `Object.assign(Root, { Root, ... })` 口径。
- 正式静态子组件最小集合：`Root / Input / List / Item / Group`。
- 正式公开 DOM parts 至少应覆盖：`root / input / list / item / group / group-label / shortcut / status`。

关于是否补充 `Empty / Status / Trigger / Shortcut`：

- `Status`：建议属于本任务范围内的公开 part，但不必强制成为静态子组件。当前 runtime 已有 `status` part 用于错误 live region，且组件库复杂组件普遍保留 `status` part；迁移时应继续保留 `data-part="status"` 并补 a11y 测试。若主代理希望让应用自定义状态行，可额外导出 `CommandPalette.Status`，但这会扩大任务文档未列出的静态 API。
- `Empty`：不建议作为 016.06 必须完成的静态子组件。空结果是有效 UX，016.06 可以先通过 `status` live region 或 `List` 内部空状态处理完成无结果提示；若要新增 `CommandPalette.Empty` / `data-part="empty"`，必须同步 contract、token、默认/暗色主题 CSS 和测试。若本轮不做，应列入候选后续任务或 018 a11y/UX 收口。
- `Trigger`：当前旧 runtime 有 `trigger` part 和 `triggerLabel` props，但任务016.06 的目标 API 没有 `Trigger`。建议不要把 `Trigger` 作为必填 slot；如保留单组件 fallback 用法，可将 `trigger` 作为内部/可选 part 继续存在，或在公共文档中明确 `Trigger` 不属于 016.06 的正式 Compound 子组件。
- `Shortcut`：当前每个 item 可展示快捷键，建议保留 `shortcut` part；不建议新增 `CommandPalette.Shortcut` 静态子组件，优先由 `Item` 通过 `shortcut` prop 或 command view 派生。

主代理进入 016.06 前，建议先明确一条决策：`CommandPalette` 是否仍默认渲染本地触发按钮。如果继续支持 `<ChipsCommandPalette triggerLabel="Commands" />`，contract 中可保留 `trigger` part；如果命令面板改为外部控制打开，则应把 `trigger` 从正式 contract 中移除或归档旧口径，并同步脚手架/公共文档示例。

```ts
  },
  group: {
    type: 'Section',
    required: false,
    multiple: true,
    part: 'group',
    role: 'group'
  },
  status: {
    type: 'Text',
    required: false,
    multiple: false,
    part: 'status',
    role: 'status'
  }
}
```

说明：

- `input`：L8 当前没有专门的 `Input`/`TextField` 语义原语，`SEMANTIC_PRIMITIVE_TYPES` 只有 `View / Stack / Grid / Form / List / Section / ScrollView / Text / Image / Media / Table / Navigation / Toolbar / Command / Slot`：`types.ts:1-17`。为避免在 016.06 扩大到 L8 原语设计，建议先用 `View` 或 `Slot` 承载 `role="combobox"` 的输入语义。
- `list`：已有 `List` primitive，适合 `role="listbox"`。
- `item`：使用 `Command`，与 command registry 语义一致。建议 `required:false`，因为 CommandPalette 可从 Host command registry/adapter 动态加载，静态声明树也可能合法处于空结果状态。组件测试仍应覆盖至少一个 `Item` 的主路径。
- `group`：使用 `Section`，可重复，映射 `role="group"`。
- `status`：如果主代理坚持 L8 schema 只覆盖任务目标五个 slot，可不放入 `StandardCompoundSlotSchemas.CommandPalette`，但 runtime/contract 仍应保留 `status` part。若放入 schema，建议 optional。

如果主代理希望像 `Menu.item` / `Select.option` 一样强制 `item.required=true`，则需要同时决定是否新增 `empty` slot，因为当前 schema 工具无法表达 “item 或 empty/status 至少一个存在” 这种条件。

## 6. 与任务017 Binding、任务018 Focus/A11y 的边界

### 6.1 任务017 Binding 边界

任务017 目标是统一 State/Environment/Binding 与表单状态模型：

- `任务017-组件库状态环境与表单Binding.md` 要做 `createBinding/useBinding` 和表单控件受控/非受控一致性。
- 阶段方案 `任务10-State-Environment-Binding模型.md` 明确 L8 `bindings` 只是声明路径，React hooks 负责实际状态实现。

016.06 应做：

- 保留并测试当前已有的受控/非受控 props：`open/defaultOpen/onOpenChange`、`query/defaultQuery/onQueryChange`。
- Root 负责本地 open/query/highlighted state 与 command adapter loading/error state。
- 子组件通过 Compound context 消费 Root 状态与动作。
- 类型设计避免和后续 `useBinding` 冲突，例如不要在 016.06 发明私有 `binding` prop。

016.06 不应做：

- 不实现 `createBinding/useBinding`。
- 不把 CommandPalette 的 query/open 状态接入未完成的全局 Binding 模型。
- 不把 command enabled/visible/checked 状态复制成组件库私有状态源。

### 6.2 任务018 Focus/A11y 边界

任务018 目标是统一 FocusScope、focus trap/restore、roving tabindex、keyboard map 与 a11y testing helper：

- `任务018-组件库焦点键盘与A11y基线.md`
- 阶段方案 `任务12-手势焦点可访问性与键盘交互.md`
- 重构方案 `04-薯片前端框架开发重构方案/08-手势焦点与可访问性重构方案.md` 明确提到 Dialog/Menu/Select/CommandPalette 重构焦点行为。

016.06 应做到的基线：

- `Input` 必须有可访问名称：`aria-label` 或 `aria-labelledby`。
- `Input` 使用 `role="combobox"`、`aria-expanded`、`aria-controls`，建议补 `aria-activedescendant` 指向高亮 `Item`。
- `List` 使用 `role="listbox"`。
- `Item` 使用 `role="option"`、`aria-selected`、`aria-disabled`，disabled item 不可被键盘选择。
- `Group` 使用 `role="group"`，有 label 时用 `aria-labelledby` 关联 `group-label`。
- 键盘保住当前已有行为：`Escape` 关闭，`ArrowDown/ArrowUp` 移动高亮，`Home/End` 跳首尾，`Enter/Space` 选择。
- 鼠标悬停和键盘高亮输出统一 `data-highlighted`，高亮状态和 `data-state` 要与主题 contract 可消费。
- `Status` 用 live region 表达错误或加载/空状态，不把错误信息写死在组件内部；错误文本来自 props 或 command adapter 错误。

016.06 不应扩大到：

- 不实现全生态 `FocusScope`。
- 不实现通用 focus trap/restore 抽象。
- 不实现全局快捷键注册或 Command+K 打开，这应继续由 Host command/shortcut 或后续任务处理。
- 不把 Playwright 级真实浏览器焦点回归作为 016.06 必须项，除非主代理已有相应测试工具链和时间窗口。

建议本轮可做的轻量焦点改进：

- 打开时将焦点移动到 `Input`。
- `Escape` 或选择关闭后，如本组件自己渲染了 trigger，可把焦点还给 trigger。
- 如果没有内部 trigger，只调用 `onOpenChange(false)`，让调用方或后续 FocusScope 接管恢复。

## 9. 风险清单

- `trigger` 是否保留尚未在任务016.06目标中写明。若 runtime 继续输出 `trigger`，contract/doc 必须明确它的身份；若移除，脚手架当前 `<ChipsCommandPalette triggerLabel=... />` 示例会受影响。
- `search -> input` 与 `result -> item` 是跨 runtime、types、tests、contract、token、ThemePack CSS、生成 CSS、ThemePack 本地 contract 的全链路改名，不能只改组件库 runtime。
- 当前 ThemePack 测试对 command-palette 没有专项断言，容易漏掉 `search/result` 残留；建议新增 token/contract 级断言。
- `CommandPalette.Group` 会引入 `group/group-label` part 和 token。若只改 runtime 不补 CSS，会出现结构可用但主题无挂点。
- `aria-activedescendant` 当前 runtime 缺失。016.06 若新增高亮 item id，需要同时保证过滤后 id 稳定，避免 query 改变导致 aria 指向不存在元素。
- L8 当前没有 `Input` 语义原语。若主代理坚持 `input` slot type 必须是正式 `Input` primitive，会扩大到 Host L8 公共原语设计；建议 016.06 先用 `View/Slot + role=combobox`。
- `item.required` 的 schema 决策存在取舍：required=true 更像 Menu/Select；required=false 更适合 command registry 动态加载和空结果。当前 schema 工具无法表达 “item 或 empty 至少一个”。
- 当前 worktree 有 016.03 Form 相关并行改动和无关 node_modules 脏文件，016.06 实施时不要回退不属于自己的变更。

## 10. 候选工单

以下为候选项，本报告不创建工单，等待主代理判断：

1. L8 标准语义原语缺少 `Input` / `TextField`。CommandPalette.Input、ComboBox 输入、SearchField 等复杂控件在 L8 schema 中只能暂映射为 `View` 或 `Slot`。如果后续多个 schema 都需要输入语义，建议新增独立工单冻结 L8 输入原语。
