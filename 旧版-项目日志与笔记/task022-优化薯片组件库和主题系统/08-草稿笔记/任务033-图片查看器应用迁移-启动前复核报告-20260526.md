## 2. 当前代码事实

`Chips-PhotoViewer` 当前已经具备：

1. `manifest.yaml` 声明 `type: app`、`entry: dist/index.html`、`ui.surface`、`runtime.targets`。
2. `capabilities` 已声明 `resource-handler:view:image/*` 与 `.png/.jpg/.jpeg/.webp/.gif/.bmp/.svg/.avif` 文件处理器。
3. `src/utils/launch-resource.ts` 已能解析：
   - `launchParams.targetPath`
   - `launchParams.resourceOpen.filePath`
   - `launchParams.resourceOpen.resourceId`
   - `chips.book-card` 的 `image-sequence` payload
4. `src/hooks/usePhotoViewerCamera.ts` 已收口 fit/manual 缩放、锚点缩放、滚轮缩放、指针平移和双指捏合。
5. `src/App.tsx` 当前仍是大组件，直接创建 SDK client、读取 Bridge、管理主题语言、资源解析、保存、图集索引和反馈。
6. `src/components/PhotoViewerStage.tsx` 当前直接渲染私有 toolbar button，未接入 Host command registry 或组件库命令消费组件。
7. `src/global.css` 当前存在大量硬编码颜色、阴影、字号、圆角和按钮视觉。
8. 测试已有 `launch-resource`、`image-viewer` 和最小 App 导出基线，但缺命令系统、Environment、scene、A11y 和命令状态覆盖。

## 3. 契约差距

1. **AppRuntime / Scene / Environment**：尚未采用应用脚手架 vNext 的 `src/app`、`src/runtime`、`src/scenes` 目录心智，`ChipsEnvironmentProvider` 未接入。
2. **Commands**：打开、保存、缩放、适应窗口、实际大小、上一张、下一张仍是私有按钮回调，未注册到 Host command registry。
3. **组件库壳层**：底部 dock 仍由应用私有 button 组成，未消费 `ChipsToolbar / ChipsMenuBar / ChipsCommandProvider`。
4. **主题系统**：应用 CSS 仍有大量视觉硬编码，应转为主题 token fallback 和组件库公开接口点。
5. **A11y / 键盘**：图片舞台、反馈、空态、命令 dock 和序列状态需要补齐 `role`、`aria-label`、`aria-live`、焦点与键盘路径。
6. **公共能力边界**：任务033提到 TIFF 转 PNG、缩略图、颜色提取。当前应用不应复制这些 Host/模块能力；如接入颜色提取或 TIFF 转换，应只通过 `client.resource.convertTiffToPng(...)` 或 `client.module.invoke({ capability: "image.color.pick", method: "pick" })`。本轮先保证查看器不私造算法。

## 5. 实施策略

1. 先迁移运行时骨架，保留现有 `launch-resource` 和 `image-viewer` 纯函数，降低行为漂移。
2. 再把用户动作收敛为 command metadata + 本地 handler，工具栏通过组件库命令消费组件触发。
3. 最后处理主题、i18n、A11y 和测试，确保“用户看到和使用的图片查看器仍是同一个产品”。

## 6. 风险记录

1. 组件库命令消费组件是否完全满足底部浮动 dock 形态需要用当前 API 验证；若样式只能通过外层定位解决，应只做结构定位，不改命令组件内部实现。
2. 现有 Host/SDK 是否有显式 `resource.release` 公开动作需继续核对。当前可通过图片元素替换和 React 生命周期释放对象 URL；若正式资源释放契约缺失且影响 Host 托管资源，应登记问题工单。
3. TIFF 转 PNG 与颜色提取是正式 Host/模块能力，图片查看器本轮不能复制算法。若产品必须立即暴露入口但 SDK/模块权限不足，应登记问题工单，而不是临时实现。
