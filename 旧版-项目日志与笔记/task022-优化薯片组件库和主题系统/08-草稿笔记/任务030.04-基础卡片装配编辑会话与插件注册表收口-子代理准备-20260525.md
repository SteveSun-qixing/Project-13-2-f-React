## 2. 真实代码路径与数据流

### 2.1 注册表与启动刷新

- `Chips-EditingEngine/src/runtime/boot-actions.ts`
  - `bootEditingEngine(...)` 启动时调用 `syncInstalledBasecardDescriptors(runtime.client)`。
  - `subscribeInstalledBasecardRefresh(client)` 监听 `plugin.installed/enabled/disabled/uninstalled` 后重新同步。
- `Chips-EditingEngine/src/scenes/WorkspaceScene.tsx`
  - 首次进入工作区时调用 `bootEditingEngine(...)`，同时订阅插件刷新。
- `Chips-EditingEngine/src/basecard-runtime/registry.ts`
  - 内置描述符：`richtextBasecardDescriptor/imageBasecardDescriptor/webpageBasecardDescriptor`。
  - 已安装插件：`client.plugin.query({ type: 'card' })`，过滤 `record.type === 'card' && record.enabled && entry/installPath`，通过 `installPath + entry` 生成 `file://` 模块 URL 动态 import，读取 `basecardDefinition`。
  - 统一维护 `descriptorMap`、`aliasMap`、`installedDescriptorMap`、`registryVersion` 与订阅者。
- `Chips-EditingEngine/src/components/CardBoxLibrary/data.ts`
  - 当前卡箱库基础卡片条目来自 `getInstalledBasecardDescriptors()`，并订阅 registry 变化。

### 2.2 卡片数据与装配

- `Chips-EditingEngine/src/core/card-service.ts`
  - `createCard/openCard/addBasicCard/updateBasicCard` 通过 `normalizeBasecardType/createInitialBasecardConfig/normalizeBasecardConfig` 进入描述符层。
  - `updateBasicCard(...)` 接收 `BasecardResourceOperations`，把待导入资源挂到 `basicCard.pendingResourceImports`，把待删除资源挂到 `card.pendingResourceDeletions`。
  - `persistCard(...)` 写 `.card/metadata.yaml`、`.card/structure.yaml`、`content/*.yaml`，并写入待导入资源。
  - `finalizeCardResources(...)` 在显式保存阶段按 `collectResourcePaths(...)` 决定删除。
- `Chips-EditingEngine/src/components/CardWindow/CardWindow.tsx`
  - 读取 `openCards.get(config.cardId)`，把 `structure.basicCards` 交给 `CompositeCardAssembler`。
  - 通过 `toCardRootFileUrl(cardInfo.path)` 给单卡 iframe 注入卡片根目录 `file://` base URL。
  - `themeRuntime.cacheKey` 作为主题变更重渲染输入。
  - `onBaseCardSelect` 回写 `setActiveCard/setSelectedBaseCard/selectCard`。
- `Chips-EditingEngine/src/basecard-runtime/CompositeCardAssembler.tsx`
  - 按 `basicCards` 顺序渲染 `BasecardFrameHost`。
  - 汇总容器高度并回传 `onHeightChange`。
  - 汇总 loading/error 状态并回传上层。
- `Chips-EditingEngine/src/basecard-runtime/frame-host.tsx`
  - 创建 `srcdoc` iframe，注入透明 `html/body` 和可选 `<base href="...">`。
  - 调用描述符 `renderView({ container, config, themeCssText, resolveResourceUrl, releaseResourceUrl })`。
  - 通过 `ResizeObserver + requestAnimationFrame` 测量高度。
  - pending import 优先解析为 `blob:`，否则回退到 `resourceBaseUrl + resourcePath`。
  - `previewPointerEvents='shielded'` 时渲染透明选择层。
  - `delegate` 模式下把 iframe wheel 转为 `CompositeInteractionPayload`。

### 2.3 编辑会话

- `Chips-EditingEngine/src/context/index.tsx`
  - `EditorRuntimeProvider` 包在 `CardProvider` 外层，为编辑会话提供单例 store。
- `Chips-EditingEngine/src/components/EditPanel/EditPanel.tsx`
  - 统一读取 `EditorSelectionContext`：选中 box 时走 `BoxEditorPanel`；选中 card/basecard 时走 `PluginHost`。
  - 基础卡片编辑变更通过 `updateBasicCard(..., { persist: false })` 回到 `CardService`，面板失焦时再 `saveCard(...)`。
- `Chips-EditingEngine/src/components/EditPanel/PluginHost.tsx`
  - 目前是 `EditorHost` 的薄包装；没有再承担 SDK iframe editorPanel 职责。
- `Chips-EditingEngine/src/editor-runtime/session-store.ts`
  - `cardId + baseCardId` 生成 key。
  - 保存 `sourceConfig/draftConfig/validation/dirty/isCommitting/errorMessage`。
  - 保存待导入资源与待删除资源队列。
  - `descriptor.commitDebounceMs ?? 260` 控制提交节流。
  - 资源只有在配置已经引用导入资源，或删除资源已不再被配置引用时允许提交。
- `Chips-EditingEngine/src/editor-runtime/EditorHost.tsx`
  - 解析 descriptor，创建/订阅 session。
  - 直接调用 `descriptor.renderEditor(...)` 挂载普通 DOM 容器。
  - 提供 `resolveResourceUrl/importResource/importArchiveBundle/deleteResource/convertTiffToPng/releaseResourceUrl`。
  - `visibilitychange(hidden)/pagehide/beforeunload/unmount` 时尝试 flush。

## 3. 旧架构、旁路、硬编码与测试残留事实

1. `CardBoxLibrary/data.ts` 当前只展示 `getInstalledBasecardDescriptors()`，不展示内置描述符。若内置富文本/图片/网页没有同时作为 Host 已安装插件返回，卡箱库会缺少内置基础卡片。
2. `basecard-runtime/registrations/*.ts` 当前直接从 `../../../../Chips-BaseCardPlugin/*-BCP/src/index` 引入内置描述符。它不是运行时扫描源码，但形成了编辑引擎到基础卡片插件源码的跨项目编译依赖；主代理需要判断这是否符合“内置描述符”正式口径，或应改为稳定内置导出/构建产物入口。
3. `basecard-runtime/contracts.ts` 的 `BasecardRenderContext` 没有 `openResource(...)`，而 `生态共用技术文档/插件开发/03-卡片插件开发.md` 中的查看态上下文包含 `openResource(...)`。`生态共用技术文档/组件库/08-编辑引擎基础卡片装配与编辑运行时标准.md` 当前也未列出该字段。这里存在公共契约不一致。
4. `EditorHost` 的 flush effect 依赖 `commitSession`，而 `commitSession` 又依赖 `snapshot`。草稿变化导致 `commitSession` 身份变化时，旧 effect cleanup 可能在组件仍然挂载时执行，从而提前提交上一版草稿，削弱防抖语义。现有测试覆盖了同一个 `act` 内的快速输入，但未覆盖分帧/分轮输入。
5. `EditorHost` 的资源回调大体已用 `useCallback`，但 `resolveResourceUrl` 依赖 `pendingResourceImports` prop。CardService 持久化窗口内 pending map 身份变化时，编辑器仍有重挂载风险；需用 ref 稳定外部 pending imports 输入。
6. `CardWindow` 接收 `CompositeCardAssembler.onErrorChange(firstError)` 后会渲染整张预览 overlay。`BasecardFrameHost` 已经有单卡错误隔离，整张 overlay 可能违背“单卡错误不得影响整张卡片稳定性”的要求。
7. `BasecardFrameHost` 渲染 loading/error 文案为硬编码中文。030.04 若改动该组件，建议把用户可见文案参数化或接入 i18n；否则可留给 030.07 全局 i18n/a11y 收口。
8. `components/EditPanel/DefaultEditor.tsx` 和 `DefaultEditor.css` 未被当前正式链路引用，但文件内仍有 `Mocked schema parsing`、`Simplistic validation`、`Basic verification stub` 注释。它像旧的通用占位编辑器残留；030.04 可考虑移入归档，避免与“不得保留通用占位编辑器正式兜底”冲突。
9. `basecard-runtime/theme-css.ts` 注入 `.chips-basecard` 背景、padding 等样式。若插件自身以 `.chips-basecard` 作为根类，这会让宿主注入视觉壳层。需确认这是否仍是基础卡片自身样式基线，还是旧壳层残留。
10. `registry.ts` 对已安装插件只验证 `basecardDefinition` 基本字段，没有验证 `definition.cardType` 是否在 `manifest.capabilities.cardTypes` 中。若 `PluginRecord` 可提供 capabilities，建议补验证；若 Host 记录不提供，需要在公共契约或问题工单中明确。
11. `syncInstalledBasecardDescriptors(...)` 目前单个插件加载/校验失败会让整个同步抛错，可能影响启动或保留旧 registry 状态。建议改为单插件错误隔离：有效插件继续注册，错误插件上报诊断/日志。
12. 测试中仍有大量 `RichTextCard/ImageCard/WebPageCard` 别名输入。这可以作为 descriptor alias 覆盖，但建议 030.04 补一组主流程使用正式 `base.*` 类型的测试，避免测试长期只证明旧别名可用。

## 4. 建议主代理执行方案

### 4.1 注册表

- 将卡箱库基础卡片列表改为使用 `getRegisteredBasecardDescriptors()` 或新增明确的 `getAvailableBasecardDescriptors()`，确保内置与已安装启用插件都能出现在库中。
- 为 `syncInstalledBasecardDescriptors(...)` 增加单插件错误隔离：一个插件 entry/basecardDefinition 无效时，不阻断其他插件和内置卡片；同时保留错误日志。
- 如果 `PluginRecord` 含 capabilities，补充 `definition.cardType` 与 `capabilities.cardTypes` 对齐校验；否则主代理应判断是否登记公共契约缺口。
- 补测试：
  - 内置 + 已安装插件同时出现在可用 registry。
  - plugin enabled/disabled/uninstalled 后 registry version 与订阅刷新。
  - 单个坏插件不拖垮内置和其他好插件。
  - 不从工作区源码路径加载已安装插件，只从 `installPath + entry` 生成 URL。

### 4.2 BasecardFrameHost / CompositeCardAssembler / CardWindow

- 保持单卡 iframe 的透明背景、base href、主题变量注入、pending import 资源解析、height 测量和 cleanup。
- 调整错误隔离：CardWindow 不应因为一个单卡 error 覆盖整张复合卡片；可仅保留单卡 overlay，或在窗口壳层显示非遮挡状态。
- 补充 `BasecardFrameHost` 对 `renderView` 抛错、cleanup 抛错或异步资源 resolve 后卸载的测试。
- 若公共契约决定支持 `openResource(...)`，应把字段加入 `contracts.ts` 和 `BasecardFrameHost`，并通过正式资源打开链路传递；若不在 030.04 实现，应登记/同步公共文档。
- 补测试：
  - 父层回调身份变化不重建 iframe。
  - 单卡错误不遮挡/破坏其他基础卡片。
  - theme cache key 变化时确实重新注入主题。
  - `previewPointerEvents='shielded'` 与 native 两种点击路径。
  - pending import blob cleanup 和 releaseResourceUrl。

### 4.3 EditorHost / EditorSessionStore / PluginHost

- 用 ref 固定 flush 入口：`latestCommitSessionRef.current = commitSession`，unmount/visibility/pagehide/beforeunload effect 只注册一次或只依赖稳定 key，避免草稿更新触发 cleanup 提交。
- 把 `pendingResourceImports` prop 放入 ref，让 `resolveResourceUrl` 身份稳定，同时仍能读取最新 pending imports。
- 审查 `importResource/deleteResource/convertTiffToPng/importArchiveBundle` 回调身份，确保普通草稿变化不会导致 `renderEditor` 重挂载。
- 明确 `importArchiveBundle(...)` 当前直接落位卡片根目录的正式语义：如果继续保留，需要 030.05 接手未引用目录资源的清理；如果改为 pending imports，需要评估大目录内存压力。
- 对 `PluginHost` 保持薄包装，不恢复 SDK iframe editorPanel。
- 对 `DefaultEditor` 残留进行归档或移除引用确认。按工作区规则不能删除，应移到就近 `归档/` 并补测试确认正式链路不依赖它。
- 补测试：
  - 分轮输入不提前提交，必须等 debounce 或 flush。
  - unmount/visibility/pagehide 才 flush 最后一版合法草稿。
  - pending imports prop 变化不重挂载编辑器。
  - 无效草稿不提交，错误只显示在当前编辑面板。
  - 导入资源后未被配置引用时不提交；引用后立即或按规则提交。
  - 删除资源后仍被配置引用时不提交删除；移除引用后提交删除意图。

### 4.4 CardService 接线

- 030.04 不建议大改持久化，但需要确认 `updateBasicCard(..., { persist: false })` 与编辑面板失焦保存配合不丢预览态 pending imports。
- 对 `pendingResourceImports` 清理、`collectResourcePaths`、`pendingResourceDeletions` 的最终落盘测试可先保留在 030.05；030.04 只需覆盖从 EditorHost 到 CardService 的 resourceOperations 入参。

## 5. 潜在风险

- 如果主代理在 030.04 同时改注册表、EditorHost、CardWindow 错误隔离和 DefaultEditor 归档，测试面会比较宽，建议分两段提交：先注册表/卡箱库/装配错误隔离，再 EditorHost/SessionStore 稳定性。
- `openResource(...)` 公共契约冲突需要先定口径；直接实现可能牵到资源打开、跨应用协作和权限，超出 030.04。
- `DefaultEditor` 归档可能影响未被搜索到的懒加载或外部文档引用；归档前应再跑全量 `rg DefaultEditor` 与项目测试。
