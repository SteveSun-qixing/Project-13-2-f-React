## 发现的问题

1. `生态共用技术文档/架构设计/薯片生态-架构设计手册.md`
   - 具体口径：`5.1 插件类型` 中仍写 `app` 是“独立窗口应用插件”。
   - 影响：与 `02-应用插件开发.md`、`06-Manifest配置规范.md`、`07-Bridge-API使用指南.md` 已沉淀的正式口径不完全一致；当前正式语义应以 Host 托管 `surface` 为主，Desktop 只是映射为窗口。
   - 建议：改为“Host 托管的跨平台 surface 应用插件；Desktop 当前由 PAL 映射为窗口”。

2. `Chips-BookReader/src/hooks/useChipsBridge.ts`、`Chips-EditingEngine/src/hooks/useChipsBridge.ts`
   - 具体口径：两个官方应用源码目录中仍存在私有 `useChipsBridge` 入口文件。
   - 影响：当前 `rg` 未发现运行时入口实际引用这些文件，官方应用主链路仍走 `chips-sdk`、`ChipsEnvironmentProvider`、`AppRuntimeProvider` 和 launch context；因此不阻断 058.01 公共契约沉淀。但它们位于 active `src/`，容易让后续维护者误以为私有 Bridge hook 仍是允许入口。
   - 建议：后续应用迁移或质量收口时将未引用的旧 Bridge hook 移入就近 `归档/`，或彻底替换为 SDK / Provider 入口；不要在 058.01 公共文档中把它们写成正式能力。

## 证据摘要

- App 脚手架 `manifest.yaml.tpl` 已声明 `type: app`、`entry: dist/index.html`、完整 `runtime.targets.desktop/web/mobile/headless`、`ui.launcher`、`ui.surface.defaultKind` 与各平台 `preferredKinds`。
- App 脚手架默认权限包含 `theme.read`、`i18n.read`、`i18n.write`、`command.read`、`command.write`、`command.invoke`，与 `02-应用插件开发.md` 对脚手架基线描述一致。
- App 脚手架 `AppProviders.tsx.tpl` 使用 `ChipsEnvironmentProvider` 注入 `chipsClient`、launch context、surface、theme、locale、permissions 和 diagnostics，并在内部挂载 `AppRuntimeProvider`。
- App 脚手架 `runtime/launch-context.ts.tpl` 通过 `client.platform.getLaunchContext()` 读取 Host 注入的 launch context，并归一 `pluginId/sessionId/sceneId/surfaceId/kind/presentation/surfaceContext/launchParams`。
- App 脚手架命令定义使用 `commandId/titleKey/descriptionKey/ariaLabelKey/icon/scope/handlerId/menuPlacement/toolbarPlacement/state`，命令 hook 通过 `client.command.register/onInvoked/invoke/unregister` 接入 Host command registry。
- 8 个官方应用 manifest 均为 `type: app`、`entry: dist/index.html`，均声明完整 `runtime.targets`、`ui.launcher`、`ui.surface.defaultKind: window`、`preferredKinds.desktop: window`、`preferredKinds.web: route`、`preferredKinds.mobile: fullscreen`、`preferredKinds.headless: window`。
- 官方应用运行时入口普遍存在 `createClient()`、`ChipsEnvironmentProvider`、`AppRuntimeProvider`、`readLaunchContext(client)` / `client.platform.getLaunchContext()`、`client.command.register/onInvoked/invoke` 等正式链路；未发现应用运行时主动解析 Host 私有启动状态、直接创建 `BrowserWindow` 或直接 import Host 内部包。
- `Chips-EditingEngine/src/services/workspace-service.ts` 中出现的 `electron-user-data` 仅是 Host runtime 根目录保护列表字符串，不是 Electron API 访问。
- 正式公共文档未发现“应用市场 / 安装市场”作为当前开发、发布或验收前提；`插件开发/01-插件开发规范.md` 已明确当前第一版不包含应用市场，虽然该文件不属于本次重点阅读范围。
