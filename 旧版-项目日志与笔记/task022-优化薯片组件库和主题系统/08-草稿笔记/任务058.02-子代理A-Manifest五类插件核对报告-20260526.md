# 任务058.02 子代理A Manifest五类插件核对报告

## 核对结论

需修正。

当前五类插件主模型已经基本一致：正式插件类型为 `app / card / layout / module / theme`，官方样本和五类脚手架模板均使用根目录 `manifest.yaml`，并声明 `runtime.targets`；应用插件使用 `ui.surface`，卡片插件使用 `capabilities.cardTypes`，布局插件使用 `layout.layoutType`，模块插件使用 `module.provides / module.consumes`，主题包使用对象形式 `entry.tokens / entry.themeCss`。

需要修正的内容主要是公共文档局部旧口径、Manifest 公共必填字段描述不足，以及 `chipsdev` 默认配置注释中仍残留 `i18n` 第六类插件口径。未发现五类官方样本需要阻断 058.02 的 Manifest 主链路问题。

## 发现的问题

### 1. `01-插件开发规范.md` 仍有旧 CLI 与工程配置口径

文件：`生态共用技术文档/插件开发/01-插件开发规范.md`

具体口径：

- 第 5 行仍写“安装薯片开发工具包chips-dev-tools”。
- 第 11 行仍写“运行chips create命令创建新插件项目”。
- 第 13 行仍写“生成的配置文件包括cpk.config.js打包配置”。
- 第 29-31 行把权限声明写成“可选配置项”，但当前 Host 与 SDK CLI 都要求 `manifest.permissions` 是数组，空权限也要写 `permissions: []`。

建议：

- 改为 `chipsdev create app|card|layout|module|theme <targetDir>`。
- 工程配置改为 `chips.config.mjs`、`package.json`、`tsconfig.json`、`manifest.yaml`。
- Manifest 基础必填字段补充 `permissions`，并明确“可以为空数组，但字段必须存在”。

证据：

- `Chips-SDK/cli/index.js` 的 `handleCreate()` 只支持 `app/card/layout/module/theme`。
- `Chips-SDK/cli/index.js` 的 `validateManifestShape()` 要求 `manifest.permissions` 必须存在且为数组。
- `Chips-Host/src/runtime/plugin-runtime.ts` 的 `readManifest()` 对 `permissions` 调用 `asStringArray(...)`，未提供数组会报错。
- 五类脚手架 Manifest 模板和官方样本均声明 `permissions`，无权限时使用 `permissions: []`。

### 2. `01-插件契约规范.md` 安装阶段把 `ui.layout` 写成统一要求

文件：`生态共用技术文档/协议与契约/01-插件契约规范.md`

具体口径：

- 第 154 行写“安装阶段提供完整元数据（名称、版本、依赖、权限、`ui.layout` 声明；布局插件还必须声明 `layout.layoutType/displayName`...）”。

问题：

- 当前官方卡片、布局、模块插件 Manifest 不声明 `ui.layout`。
- 当前公共文档同一文件第 241-247 行已经把 `ui.layout` 定义为可选布局元数据或资源索引容器，不是所有插件统一必填字段。
- 当前 Host 只禁止非 app 插件声明 `ui.surface` / `ui.launcher`，并不要求所有插件声明 `ui.layout`。

建议：

- 把安装阶段表述改为：所有插件必须提供 `id/name/version/type/entry/permissions/runtime.targets` 等基础元数据；类型专属字段按 `ui.surface`、`capabilities.cardTypes`、`layout.layoutType`、`module.provides`、`entry.tokens/themeCss` 分别声明；`ui.layout` 仅在 app/page/theme contract 等需要布局元数据或资源索引时使用。

证据：

- `Chips-BaseCardPlugin/richtext-BCP/manifest.yaml`：`type: card`，无 `ui.layout`。
- `Chips-BoxLayoutPlugin/grid-BLP/manifest.yaml`：`type: layout`，无 `ui.layout`，使用 `layout.layoutType`。
- `Chips-ModulePlugin/Chips-FileConversion-Plugin/manifest.yaml`：`type: module`，无 `ui.layout`，使用 `module.provides / consumes`。
- `ThemePack/Chips-default/manifest.yaml`：主题包使用 `ui.layout.contract / minFunctionalSet`，属于主题契约资产索引场景。

### 3. 布局插件公共示例缺少 `runtime.targets`

文件：`生态共用技术文档/插件开发/04-布局插件开发.md`

具体口径：

- 第 100-113 行布局插件 Manifest 示例包含 `type/entry/permissions/layout`，但没有 `runtime.targets`。

建议：

- 在布局插件示例中补齐完整 `runtime.targets`，与当前脚手架和官方布局插件一致：`desktop: true`、`web: false`、`mobile: false`、`headless: true`。

证据：

- `Chips-Scaffold/chips-scaffold-boxlayout/templates/boxlayout-standard/manifest.yaml.tpl` 第 14-23 行声明完整 `runtime.targets`。
- `Chips-BoxLayoutPlugin/grid-BLP/manifest.yaml` 第 14-23 行声明完整 `runtime.targets`。
- `Chips-SDK/cli/index.js` 的 `validateManifestShape()` 对所有类型要求 `manifest.runtime.targets.desktop/web/mobile/headless.supported` 为布尔值。

### 5. Manifest 总规范对类型专属字段写得不够完整

文件：`生态共用技术文档/插件开发/06-Manifest配置规范.md`

具体口径：

- 第 29-35 行必填基础字段未列 `permissions`。
- 第 224-235 行对 `layout/module/theme` 只给了简略要求，未完整列出当前 Host、脚手架和官方样本正在使用的字段。

建议：

- 基础必填字段增加 `permissions`。
- `layout` 补充：`layout.displayName`、不声明 `ui.surface`、常见权限基线 `box.read/theme.read/i18n.read`。
- `module` 补充：`module.apiVersion`、`module.runtime: worker`、`module.activation: onDemand|eager`、`module.provides[].methods[].name/mode/inputSchema/outputSchema`、`module.consumes[].capability/versionRange`。
- `theme` 补充：`themeId`、`displayName/name`、`isDefault`、`parentTheme`、`ui.layout.contract`、`ui.layout.minFunctionalSet` 作为主题契约资产索引字段。
- 明确 `chipsdev validate` 与 Host 安装解析的覆盖边界：SDK CLI 当前强校验基础字段、`runtime.targets`、app `ui.surface`、`capabilityFallbacks`、module provider 契约和 manifest 声明资产存在；Host 安装解析还会校验 type 枚举、theme entry、layout object、module semver/consumes 等。

证据：

- `Chips-Host/src/runtime/plugin-runtime.ts` 第 151 行插件类型只有 `app/card/layout/module/theme`。
- `Chips-Host/src/runtime/plugin-runtime.ts` 第 167-178 行要求数组字段为数组；第 863-870 行解析 `permissions`。
- `Chips-Host/src/runtime/plugin-runtime.ts` 第 1084-1123 行解析主题 `themeId/displayName/entry.tokens/entry.themeCss/ui.layout.contract`。
- `Chips-Host/src/runtime/plugin-runtime.ts` 第 1126-1138 行解析布局 `layout.layoutType/displayName`。
- `Chips-Host/src/runtime/plugin-runtime.ts` 第 1141-1303 行解析模块 `apiVersion/runtime/activation/provides/consumes`。
- `Chips-SDK/cli/index.js` 第 1092-1255 行是 SDK CLI 当前 Manifest 形状校验。

### 6. `chipsdev init` 默认配置注释仍残留 `i18n` 第六类插件

文件：`Chips-SDK/cli/index.js`

具体口径：

- 第 671-675 行默认 `chips.config.mjs` 模板注释为 `type: app | card | layout | module | theme | i18n`。

问题：

- 当前正式插件类型是五类，不包含语言包插件作为第六类。
- `handleCreate()` 报错信息明确当前支持 `app、card、layout、module、theme`。

建议：

- 删除注释中的 `| i18n`，保持与五类插件正式口径一致。

证据：

- `Chips-Host/src/runtime/plugin-runtime.ts` 第 151 行 `pluginTypes` 为 `['app', 'card', 'layout', 'module', 'theme']`。
- `Chips-SDK/cli/index.js` 第 1952-1954 行 `chipsdev create` 支持类型也是 `app、card、layout、module、theme`。

## 证据摘要

### 五类官方样本字段

- 应用插件：8 个官方应用均为 `type: app`、`entry: dist/index.html`，声明完整 `runtime.targets`、`ui.surface.defaultKind`、四平台 `preferredKinds`、`ui.launcher` 和权限数组。部分资源类应用声明 `capabilities` 数组，例如 `resource-handler:view:image/*`、`file-handler:.card`。
- 卡片插件：8 个基础卡片插件均为 `type: card`、`entry: dist/index.mjs`，声明 `capabilities.cardTypes` 和完整 `runtime.targets`，不声明 `ui.surface`。
- 布局插件：`grid-BLP`、`list-BLP` 均为 `type: layout`、`entry: dist/index.mjs`，声明 `layout.layoutType/displayName`、`box.read/theme.read/i18n.read` 和完整 `runtime.targets`，不声明 `ui.surface`。
- 模块插件：5 个模块插件均为 `type: module`、`entry: dist/index.mjs`，声明 `module.apiVersion: 1`、`module.runtime: worker`、`module.activation: onDemand`、`module.provides[].capability/version/methods`，编排模块额外声明 `module.consumes`。
- 主题插件：2 个主题包均为 `type: theme`，`entry` 为对象并包含 `tokens: dist/tokens.json`、`themeCss: dist/theme.css`，同时声明 `themeId/displayName/isDefault/parentTheme` 与 `ui.layout.contract/minFunctionalSet`。

### 五类脚手架字段

- `chips-scaffold-app`：生成 `type: app`、`entry: dist/index.html`、`permissions`、完整 `runtime.targets`、`capabilityFallbacks`、`ui.layout`、`ui.launcher`、`ui.surface`、`ui.window.chrome`。
- `chips-scaffold-basecard`：生成 `type: card`、`entry: dist/index.mjs`、`capabilities.cardTypes`、`permissions: []`、完整 `runtime.targets`。
- `chips-scaffold-boxlayout`：生成 `type: layout`、`entry: dist/index.mjs`、`permissions`、完整 `runtime.targets`、`layout.layoutType/displayName`。
- `chips-scaffold-module`：所有模块模板生成 `type: module`、`entry: dist/index.mjs`、`permissions`、完整 `runtime.targets`、`module.apiVersion/runtime/activation/provides/consumes`。
- `chips-scaffold-theme`：生成 `type: theme`、`permissions`、完整 `runtime.targets`、对象形式 `entry.tokens/themeCss`、`themeId/displayName/isDefault/parentTheme`、`ui.layout.contract/minFunctionalSet`。

## 未覆盖风险

- 未逐行核对 8 个应用插件的所有运行时代码，只核对 Manifest、脚手架关键入口和公共契约相关字段。
- `ThemePack/*/.cpk-stage/manifest.yaml` 属于打包暂存目录，当前 worktree 有其它任务 WIP，本报告未把暂存 Manifest 作为正式源结论。
- `Chips-SDK/cli/index.js` 与 `Chips-Host/src/runtime/plugin-runtime.ts` 当前 Manifest 校验覆盖范围不完全一致；如果 058.02 要冻结“CLI 与 Host 完全同等校验”的标准，需要由主代理后续决定是更新 CLI 校验实现，还是在公共文档中明确两者边界。
