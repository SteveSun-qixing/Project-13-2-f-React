## 4. 现有 ChipsDateTime 能力结论

### 4.1 公开 API 与实现

`Chips-ComponentLibrary/packages/components/src/index.d.ts:831-848`：

- `DateTimeProps` 包含 `id`、`label`、`ariaLabel`、`value/defaultValue`、`min/max/step`、`disabled/loading/error/readOnly`、`iconContent`、`onValueChange`、`onStateChange`。
- 值类型为 string，没有显式日期对象、timezone、locale 或 formatter/parser 类型。

`Chips-ComponentLibrary/packages/components/src/index.d.ts:1151`：

- 仅导出 `ChipsDateTime`，没有导出 `ChipsDatePicker` 或 `ChipsTimePicker`。

`Chips-ComponentLibrary/packages/components/src/index.js:7458-7556`：

- 根节点是 `div`，`data-scope="date-time"`、`data-part="root"`。
- 控件核心是原生 `input`，`data-part="input"`，`type="datetime-local"`。
- 支持受控/非受控 `value/defaultValue`，`onChange` 后回调 `onValueChange(value)`。
- 直接透传原生 `min/max/step`。
- 错误态输出 `aria-invalid` 和 `status` live region。
- 图标通过 `iconContent` 或默认 `calendar` 图标槽位提供。

值得注意的证据：

- `Chips-ComponentLibrary/packages/components/src/index.js:7510-7517` 如果传入 `label`，实际渲染为 `label` 元素，但 `createScopeAttributes("date-time", "icon", state)` 将 label 标成 `data-part="icon"`。
- `Chips-ComponentLibrary/packages/components/src/index.js:7535-7542` 图标 span 也使用 `data-part="icon"`。
- 这意味着现有 `date-time` contract 没有公开 `label` part，且 label 与 icon 共用 `icon` part，拆分 `DatePicker / TimePicker` 时不建议复用这个 part 语义。

## 6. 解析、格式化、键盘、a11y、i18n、时区与 locale 边界建议

### 6.1 不引入未确认第三方库

任务015明确“不引入未确认第三方库”。第六批建议优先基于 Web 标准能力实现：

- `Date`
- `Intl.DateTimeFormat`
- 原生 input 基础能力
- 组件库现有 a11y / keyboard / scope helper
- 现有 React 与组件库状态工具

如果正式实现需要复杂日历算法、非公历历法、时区数据库、自然语言解析或高级区间选择，不应直接新增依赖，应先沉淀架构决策或用户确认。

### 6.2 值模型建议

DatePicker 推荐：

- 对外 value 优先使用 ISO local date 字符串：`YYYY-MM-DD`。
- `min/max` 同样使用 `YYYY-MM-DD`。
- 输入解析只接受明确格式，避免隐式 `Date.parse()` 对不同浏览器/locale 产生歧义。
- `onValueChange(value, details)` 可在 details 中提供 `{ date, valid, reason }`，但正式类型要避免强迫业务消费 `Date` 对象。

TimePicker 推荐：

- 对外 value 优先使用 local time 字符串：`HH:mm` 或带秒 `HH:mm:ss`，由 `precision` 决定。
- `min/max/step` 与 value 保持同一 local time 语义，不绑定日期。
- 支持 `hourCycle`：`h12 / h23 / h24 / h11`，展示格式由 locale/hourCycle 推导，存储值仍保持规范化 24 小时字符串。

DateTime 与两个新控件的关系：

- `ChipsDateTime` 可继续作为 `datetime-local` 相邻能力保留。
- `ChipsDatePicker` 和 `ChipsTimePicker` 应是独立基础控件，有独立 scope、token、contract、类型、测试和文档。
- 不建议把 `date-picker` / `time-picker` 简化成 `ChipsDateTime` 的 mode，因为任务015矩阵已明确需要独立 scope，且主题契约需要按独立组件覆盖。

### 6.3 格式化建议

- 展示格式使用 `Intl.DateTimeFormat(locale, options)`。
- 输入规范值与展示标签分离：内部 canonical value 保持稳定字符串，展示层按 locale 格式化。
- 提供 `formatValue` / `parseValue` 或同形扩展点时，必须保证失败诊断和错误态进入统一 `status` / `aria-invalid` 链路。
- 不要在组件内硬编码中文、英文、月份名、AM/PM 文案；所有用户可见文案应支持 `labelKey`、`descriptionKey`、`placeholderKey`、`triggerAriaLabelKey`、`previousMonthAriaLabelKey` 等 i18n key 或同步 i18n adapter。

### 6.4 键盘与焦点建议

- DatePicker 不能只依赖浏览器原生日期输入键盘行为；如果提供弹层日历，必须完整定义 grid 导航、月份导航、关闭与焦点回收。
- TimePicker 不能只依赖原生 `input type="time"`；如果提供列表/分栏选择，必须完整定义 listbox 或分栏控件键盘语义。
- 弹层打开后焦点应进入可操作区域或保留输入并通过 `aria-activedescendant` 管理活动项，正式实现需二选一并写入文档。
- `Escape` 关闭弹层后焦点回到 trigger/input；点击外部关闭不应丢失当前有效值。
- 禁用项、越界日期/时间、只读态都必须可预测地处理键盘路径。

### 6.5 a11y 建议

- label、description、error 必须通过 `aria-labelledby` / `aria-describedby` 串联，不应只提供视觉文本。
- 错误态必须输出 `aria-invalid="true"`，错误文案通过 `role=status` 或 live region 暴露。
- 弹层触发按钮必须有可访问名称，且 `aria-expanded` 与 `aria-controls` 同步。
- 日历网格活动日期、选中日期、今天、不可选日期需要清晰读屏表达。
- 时间选项需要输出当前选中、高亮和不可用状态；如果使用 `aria-activedescendant`，必须保证 id 稳定。
- 控制型图标必须支持外部槽位覆盖，不能写死用户可见字符；可复用 `ChipsIcon` / `IconDescriptor` 模式。

### 6.6 i18n、locale 与时区边界建议

- locale 只负责展示、读屏标签和月份/星期/时间周期格式，不应改变 canonical value。
- DatePicker 的 `YYYY-MM-DD` 建议表示用户 locale 下的本地日历日期，不隐式转换 UTC。
- TimePicker 的 `HH:mm[:ss]` 建议表示本地墙钟时间，不携带 timezone。
- 若后续需要 timezone-aware DateTime，应作为独立能力或 `ChipsDateTime` 深化议题，不应混入本批 DatePicker/TimePicker 的最小基础控件契约。
- `firstDayOfWeek`、`calendarSystem`、`timeZone` 可作为后续扩展项，但本批最小闭环建议先明确：
  - 默认 locale 来源：props > i18n/runtime locale > 浏览器默认。
  - 默认时区：仅用于展示当前日期/时间，不改变存储值。
  - 非公历历法：暂不承诺，避免引入未确认库或不完整算法。

## 8. 风险点与建议拆分

### 8.1 风险点

1. `ChipsDateTime` 不是 DatePicker/TimePicker 等价能力。
   它是 `datetime-local` 输入封装，缺少独立 `date-picker` / `time-picker` scope 与 picker 结构。如果直接复用或改名，会违背任务015矩阵对独立控件的要求。

2. 当前 `date-time` 的 label part 语义不清晰。
   源码中 label 和图标都使用 `data-part="icon"`。第六批新增控件应显式公开 `label` part，避免主题包继续依赖错误语义。

3. 日期/时间解析容易出现浏览器差异。
   隐式 `Date.parse()`、本地化输入、UTC 转换和 DST 边界都可能导致值漂移。建议 canonical value 使用稳定字符串，解析只接受明确格式。

4. picker 键盘与 a11y 复杂度明显高于原生输入。
   日历 grid、月份导航、时间 listbox/分栏、弹层焦点回收、错误消息关联都需要专项测试。

5. token 颗粒度不足风险。
   现有 `date-time` token 只有输入、图标、焦点，无法表达日历单元格、今天、选中、不可用、时间选项高亮等视觉状态。新增 token 需要一次性覆盖主题可表达面。

6. 时区和 locale 容易扩大范围。
   本批建议只承诺本地日期和本地墙钟时间。timezone-aware DateTime、非公历历法和自然语言解析应拆到后续独立议题，避免引入未确认依赖。

### 8.2 建议拆分

建议按以下顺序推进正式实现：

1. 契约冻结：先确认 `date-picker` / `time-picker` 的 parts、states、requiredTokens、a11y 规则和 canonical value。
2. 无头实现：新增 `ChipsDatePicker` 与 `ChipsTimePicker`，优先交付输入 + 弹层选择 + 受控/非受控 + 错误链路。
3. 测试闭环：补导出、contract、token、a11y、键盘、解析/格式化、主题切换和语言切换测试。
4. 主题闭环：默认主题与暗色主题分别补 token、CSS、contract、theme-min-functional-set 与主题包测试。
5. 文档同步：再更新生态公共组件文档和组件库内部技术文档。

不建议在同一批里同时加入 DateRangePicker、timezone-aware DateTime、自然语言解析、复杂 recurrence 或非公历日历；这些能力会显著增加 contract、a11y 和测试面。
