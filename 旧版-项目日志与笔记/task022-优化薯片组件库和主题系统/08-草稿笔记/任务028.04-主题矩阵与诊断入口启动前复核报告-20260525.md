## 1. 后续扩展目标与验收口径

任务028后续目标是在 `Chips-EcoSettingsPanel` 中补齐主题与质量治理入口，使设置面板成为以下能力的正式消费端：

- 主题矩阵：展示当前工作区可用主题与组件契约覆盖、主题包预览场景、当前主题状态。
- 组件 contract 状态：展示组件库正式 contract 的组件、scope、parts、states、required/optional token 覆盖与最新质量/性能摘要。
- 主题 contract 状态：展示 Host 当前主题 `theme.contract.get()` 返回的 `ThemeContractView`，包含组件 coverage、diagnostics、summary。
- 缺失 token 诊断入口：只消费 Host `theme.resolve()` / `theme.contract.get()` 的结构化 diagnostics，或 `chipsdev theme inspect` 正式报告；不得前端自行扫描主题包私有文件并伪造诊断。
- 预览入口：组件预览、应用插件预览、卡片预览、箱子布局预览必须经组件库、SDK `preview` 报告、SDK `card/box/surface/plugin` 正式链路承载。
- 性能工具入口：优先展示 `chipsdev quality gate` / 组件库 perf 最新正式报告摘要；运行时性能数据可消费 SDK `client.controlPlane.metrics()`，不得读 Host 内部 metrics 文件或私有状态。

验收口径沿用任务028：主题、语言、插件、contract、诊断和质量状态以 Host / SDK / 正式报告为唯一事实来源；所有 UI 文案走 i18n，视觉走组件库与主题 token；新增入口必须纳入 Scene / command registry / 测试 / 文档；不做临时版、占位版或前端假数据。

第一批可立即做：

1. 增加 `theme-diagnostics` Scene：展示当前主题 `theme.contract.get()` 与 `theme.resolve([])` 的 summary、coverage、缺失 token diagnostics。数据源完整、权限仍为 `theme.read`，不需要新增 Host 接口。

第二批建议等报告消费链路明确后做：

- 主题矩阵跨主题对比：当前 SDK/Host `theme.contract.get()`只返回当前主题；非当前主题不能靠前端读取 ThemePack 私有目录，应等 Host 支持指定 themeId 的公开 contract 查询，或由 `chipsdev theme inspect --out` 生成正式报告后展示。

- 性能工具深度面板：先展示 `quality/perf` 报告摘要；实时 Host metrics 接入需要 manifest 增加 `control.read`，`diagnose` 需要 `control.write`，应单独评估权限与 UI 暴露范围。

## 7. 风险点与可能需要登记的新工单

### 风险一：设置面板运行时没有正式“读取 CLI 报告”的 Host/SDK API

证据：

- `生态共用技术文档/插件开发/02-应用插件开发.md` 定义 `reports/` 为生成工程本地验证产物，`preview:smoke` 与 `quality:gate` 是报告级 smoke。
- `Chips-SDK/src/tooling/developer-tools.cjs` 只提供 Node tooling 报告生成器，未在 `chips-sdk` runtime client 上暴露读取报告文件的 Domain API。
- `Chips-EcoSettingsPanel` 当前无 `reports/` 或 `src/preview/` 目录。

影响：若要在应用运行时展示 component gallery / quality gate / diagnostics 完整 JSON，需要先明确报告产物如何作为应用资源或 Host 正式 report API 暴露。否则只能展示“运行命令入口”和 Host 当前主题 contract 实时数据。

建议：如果任务028.04要求在运行时直接读报告，应登记“SDK/Host 缺少正式开发报告读取接口”工单；若只做命令入口和当前主题诊断，则可先不登记。

### 风险二：非当前主题的 Host contract 诊断接口不足

证据：

- `Chips-SDK/src/api/theme.ts` 的 `contract.get(component?)` 只接受 component，不接受 `themeId`。
- `Chips-Host/src/main/services/register-host-services.ts` 中 `theme.contract.get` 使用 `resolveThemeContext(state, [])`，返回当前主题上下文。

影响：主题矩阵若要对“已安装但非当前主题”逐个展示真实 contract 状态，不能用现有 Host API 完成。用 ThemePack 源文件或前端 token flatten 替代会越界。

建议：首批只展示当前主题 contract；跨主题 contract 矩阵需新增 Host/SDK `theme.contract.get({ themeId?, component? })` 或正式 `theme.inspect` report 消费链路。若产品验收坚持全主题实时状态，应登记接口扩展工单。

### 风险三：性能工具入口权限需要重新评估

证据：

- `生态共用技术文档/插件开发/08-SDK使用指南.md` 写明 `client.controlPlane.metrics()` 与 `diagnose()` 存在，且 `diagnose` 需要 `control.write`。
- `Chips-EcoSettingsPanel/manifest.yaml` 当前没有 `control.read` / `control.write`。

影响：设置面板若接入实时 metrics 或 diagnose，会触发权限与治理范围变更。首批仅展示 `quality/perf` 正式报告摘要更稳。

建议：若要接 `controlPlane.metrics()`，先新增 `control.read` 权限并补公共/项目文档和权限不足测试；`diagnose()` 不建议在本阶段接。

### 风险四：预览入口可能误变成应用内 mock

证据：

- `生态共用技术文档/架构设计/04-渲染架构设计.md` 明确 L9 `RenderResult` 输出 diagnostics/qualityGate，SDK、CLI、预览工具和设置面板不得重新定义平行诊断结构。
- `Chips-SDK/src/api/card.ts`、`Chips-SDK/src/api/box.ts` 已有正式 iframe render 链路。

影响：如果为追求快速 UI，在设置面板中构造假卡片、假箱子或假布局，会破坏任务028红线。

建议：预览入口首批做“选择文件并调用正式 SDK render”或“打开 preview report”；没有输入样本时展示未配置状态，不放示例假数据。

## 8. 本阶段不应做的事

- 不要修改 Host 私有主题运行时、组件库 contract、ThemePack 源 token 来适配设置面板页面。
- 不要从设置面板运行时代码读取 `Chips-Host/src/main/theme-runtime/*`、`.chips-host-dev`、`ThemePack/*/tokens`、`Chips-ComponentLibrary/packages/theme-contracts` 等本地私有路径。
- 不要在前端实现 token flatten、contract validator、主题解析器或性能打分器。
- 不要新增第三方图表/表格/数据请求库；现有组件库能力不足时先登记工单。
- 不要把 `controlPlane.diagnose()` 暴露成普通用户入口，除非权限、文档、审计和测试都同步收口。
- 不要调整 Git 分支、提交、清理其他任务未提交文件或触碰主代理任务028.03进行中的业务改动。

## 9. 启动结论

当前不需要先中断任务登记必提工单，原因是任务028.04首批最小可交付可以完全消费现有正式链路：`client.theme.contract.get()`、`client.theme.resolve()`、当前组件库组件预览、`chipsdev preview/component gallery/theme inspect/quality gate/diagnostics` 报告命令入口。

但有两个边界必须写进实现计划：

1. 跨主题 contract 矩阵不能在运行时实时完成，除非新增 Host/SDK 指定 `themeId` 的 contract 查询或正式报告读取链路。
2. component gallery / quality gate / diagnostics 的完整报告展示需要先明确报告产物消费方式；首批可以先做报告生成入口和状态摘要，不要前端直接读仓库私有文件。
