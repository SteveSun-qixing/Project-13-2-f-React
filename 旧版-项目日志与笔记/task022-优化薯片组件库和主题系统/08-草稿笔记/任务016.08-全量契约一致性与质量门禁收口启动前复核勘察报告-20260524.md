## 可能的漂移风险列表

### 1. ThemePack contract 与组件库正式 contract 不等值

证据：

- `Chips-ComponentLibrary/packages/theme-contracts/contracts/components/dialog.contract.json` 当前 Dialog parts 是 `root/trigger/backdrop/content/header/body/footer/actions/close/status`。
- `ThemePack/Chips-default/contracts/theme-interface.contract.json` 与 `ThemePack/Chips-theme-default-dark/contracts/theme-interface.contract.json` 当前 Dialog parts 仍是 `root/trigger/backdrop/content/title/description/close/status`，缺 `header/body/footer/actions`，多 `title/description`；required token 缺 `chips.comp.dialog.header.color / body.color / footer.gap / actions.gap`，多 `chips.comp.dialog.title.color`。
- 两个主题包的 Popover contract 仍多 `positioner` part。
- 两个主题包的 Menu contract 缺 `group-label` part，而 `ThemePack/Chips-default/styles/components/layout-containers.css:395` 和暗色同名文件已有 `[data-scope="menu"][data-part="group"] > [data-part="group-label"]` selector。

影响：`validate:theme` 可以显示 token coverage complete，但设置面板、Theme Contract View、CSS 选择器和组件库正式 contract 仍可能对外暴露不同结构。

### 2. 现有主题校验只验证 token 存在，不验证官方主题包 contract 等值

证据：

- `ThemePack/Chips-default/src/validate-theme.ts` 和暗色主题同名文件通过 `buildThemeContractView(contract, buildContractTokenTree(tokens), ...)` 校验主题自身 contract 声明的 token 覆盖。
- `Chips-ComponentLibrary/packages/theme-contracts/src/validator.js` 的 `buildComponentContractView` 会返回 parts/states，但 diagnostics 只针对 missing required/optional tokens。
- `ThemePack/*/tests/contract.spec.ts` 当前主要断言 component count、coverage、缺失 token diagnostic schema，没有拿组件库 `contracts/components/*.contract.json` 做 parts/states/requiredTokens 等值比较。
- `Chips-ComponentLibrary/scripts/run-quality-gate.mjs` 聚合 lint/typecheck/test/contracts/a11y/perf/build，但没有跨 ThemePack equality 步骤。

影响：016.08 若只跑现有 `quality:gate` 与主题包 `validate:theme`，仍可能遗漏 ThemePack contract 漂移。

### 3. NavigationSplitView 尚未进入任何正式矩阵

证据：

- 当前未发现 `ChipsNavigationSplitView`。
- 当前 `Chips-ComponentLibrary/packages/theme-contracts/contracts/components/` 和 `packages/tokens/tokens/comp/` 均无 `navigation-split-view` 文件。
- 两个 ThemePack 的 `tokens/comp/`、`contracts/theme-interface.contract.json`、`theme-min-functional-set.json` 当前只包含 `split-view`，不包含 `navigation-split-view`。
- `Chips-Host/src/renderer/declarative-ui/composition.ts` 当前 `StandardCompoundSlotSchemas` 到 `CommandPalette`，无 `NavigationSplitView`。
- `生态共用技术文档/架构设计/17-L8声明式UI实现与接口细则.md` 当前标准复杂组件 slot schema 到 `CommandPalette`，无 `NavigationSplitView`。

影响：016.08 必须等 016.07 完成后重新复核。若 016.07 未冻结独立 `navigation-split-view`，主代理需要按问题工单流程登记架构缺口，不应在 016.08 临时用 `split-view` 冒充导航语义组件。

### 4. `ChipsSplitView` 合法布局语义可能被误判为 NavigationSplitView

证据：

- `Chips-ComponentLibrary/packages/components/src/layout-primitives.js` 当前 `ChipsSplitView` scope 为 `split-view`，公开 `primary/secondary/detail/divider/status`，是布局原语。
- `生态共用技术文档/组件库/02-组件契约标准.md` 仍把 `split-view` 列为布局 scope。
- 两个 ThemePack CSS 中 `[data-scope="split-view"][data-part="primary"]` 和 `[data-part="secondary"]` 是当前布局原语的合法选择器。

影响：016.08 的旧口径扫描不能机械禁止 `split-view.primary/secondary`，但必须禁止把它们当成 `NavigationSplitView.Sidebar/Content/Detail` 的 contract。

### 5. L8 测试已有覆盖，但仍不是最终 10 组件矩阵

证据：

- `Chips-Host/src/renderer/declarative-ui/composition.ts` 当前有 `Dialog / Tabs / Popover / Menu / Select / Form / DataGrid / Tree / CommandPalette`。
- `Chips-Host/tests/unit/declarative-ui.test.ts` 覆盖 Tree 旧 `node/toggle`、CommandPalette 旧 `search/result` 等 undefined 诊断，但测试标题仍写“Dialog, Popover, Tabs, Menu, Select, Form, and DataGrid”，且没有 `NavigationSplitView`。

影响：016.08 应把 L8 schema 测试改成表驱动矩阵，覆盖 10 个目标组件的合法 compose、缺 required slot、重复单例、未知 slot、类型错误、boolean mode props。

### 6. 质量报告和构建产物容易形成无说明脏文件

证据：

- 当前已有未跟踪 `Chips-ComponentLibrary/reports/quality-gate/quality-gate-2026-05-24T054315664Z.json`。
- `Chips-ComponentLibrary/scripts/run-quality-gate.mjs` 会写 `reports/quality-gate/quality-gate-<timestamp>.json` 与 `quality-gate-latest.json`。
- 主题包 `npm run build` 会刷新 `dist/tokens.json`、`dist/theme.css`，工作日志中也出现过手动同步根 `theme.css` 的步骤。

影响：016.08 正式跑全量门禁后，应明确哪些报告和构建产物纳入提交，哪些只是本地证据，避免留下不可解释的脏文件。
