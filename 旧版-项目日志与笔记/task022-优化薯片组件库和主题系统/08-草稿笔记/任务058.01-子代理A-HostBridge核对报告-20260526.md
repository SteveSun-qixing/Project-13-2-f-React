## 发现的问题

1. `生态共用技术文档/协议与接口标准/02-Bridge-API规范.md`：第 6 节 `platform` 子域动作清单列出了 `getInfo/getCapabilities/getScreenInfo/listScreens/powerGetState/powerSetPreventSleep/renderHtmlToPdf/renderHtmlToImage`，但当前 `ChipsBridge['platform']` 还正式暴露 `openExternal(url)` convenience 方法，并由 `BridgeTransport.platform.openExternal()` 调用 `platform.openExternal` route。建议在动作清单和返回结构说明中补充 `openExternal(url): Promise<void>`，低层 route 为 `window.chips.invoke("platform.openExternal", { url })`，返回 `{ ack: true }`。

2. 旧口径回扫未发现阻断项：`file子域`、`chips.d.ts`、服务器地址/认证初始化、正向依赖 `BrowserWindow`、让应用解析命令行或 Host 私有状态等表述未在本次核对范围内作为正式推荐口径出现。`storage API` 仅出现在“不要假设存在通用 storage API”的禁止性提示中，不构成旧口径残留。

## 证据摘要

- `exposeBridgeToMainWorld()` 暴露的 `window.chips` 子域为 `window/dialog/plugin/clipboard/shell/surface/command/transfer/association/platform/notification/tray/shortcut/ipc`，与公共文档当前子域表一致。
- `BridgeTransport` 核心入口包含 `invoke/on/once/emit`，`createBridgeForKernel()` 额外为 Electron runtime 绑定 `invokeScoped/emitScoped`；`emit` 通过 `ipcRenderer.send(CHIPS_EMIT_CHANNEL, ...)` 发送，`bindKernelToElectronIpc()` 的 `emitHandler` 仅投递 `kernel.events.emit(...)`，因此文档“不承诺业务确认”的口径准确。
- `platform.getLaunchContext()` 由 `createExposedPlatformBridge()` 注入，`cloneLaunchContext()` 返回 `pluginId/sessionId/sceneId/surfaceId/kind/presentation/surfaceContext/launchParams`，与当前文档字段一致；`plugin-window.ts` 从 `--chips-bridge-context` 解析同组上下文。
- `SurfaceOpenRequest` 在 `packages/pal/src/types.ts` 中的 `target.type="plugin"` 包含 `pluginId/url/sessionId/permissions/launchParams`，请求级包含 `context?: SurfaceContext`；`register-host-services.ts` 的 `surface.open` 在插件目标下额外调用 `ensureCallerPermission(..., "plugin.manage", "surface.open")`，并进入 `openPluginSurface()` 创建插件 session。
- `openPluginSurface()` 写入 `session.sessionId`、`session.permissions`、`surfaceContext`，并发出 `scene.created/scene.active/surface.opened/window.opened/plugin.launched`；`host-services-pal-routing.test.ts` 覆盖了插件 surface 打开、权限不足和 session 清理。
- `normalizeCommandStatePatch()` 接受 `disabledReasonKey`，并在缺失时把 `state.reasonKey` 归一到 `disabledReasonKey`；`13-命令系统契约.md` 已描述该历史输入别名。
- `command.invoke` 只派发 `command.invoked`，返回 `dispatched: true`，业务 handler 不通过 Bridge 传给 Host；文档对 command registry + 插件侧 handler 的表述准确。
