# 差距分析：手势 / 焦点 / 可访问性

## 1. 对标目标

薯片框架需要统一处理 pointer、keyboard、gesture、focus、a11y。复杂组件必须有明确键盘行为、焦点管理和屏幕阅读器语义。

## 2. 当前薯片已有基础

- `@chips/a11y` 包已存在。
- `Chips-ComponentLibrary` 有 `test:a11y` 脚本。
- 组件 contract 标准要求 `aria-*`、`data-scope/data-part/data-state`。
- 阶段文档中已有 a11y 和键盘交互要求。

## 3. 当前主要差距

### 3.1 真实复杂交互测试不足

当前质量门禁能通过，但还需要补真实浏览器级验证：

- Dialog focus trap。
- Menu roving focus。
- Select keyboard navigation。
- DataGrid 单元格导航。
- Tree 展开折叠与层级语义。
- CommandPalette 搜索和方向键。

### 3.2 Focus Scope 未框架化

缺少统一：

- focus scope。
- focus trap。
- focus restore。
- roving focus。
- focus visible。
- modal/non-modal 焦点策略。

### 3.3 Gesture / Pointer 模型不足

拖拽、拖放、滚轮、长按、双击、上下文菜单、resize handle、split pane 拖拽需要统一抽象，目前还未成为框架层能力。

### 3.4 a11y 与主题关系还需强化

可访问性不仅是 ARIA，还包括：

- 对比度。
- 焦点环。
- disabled 状态可见性。
- 错误状态可读性。
- reduced motion。
- 文案和 aria label i18n。

## 4. 差距等级

严重等级：高。

原因：如果手势、焦点和 a11y 不完整，组件种类再多也达不到 SwiftUI 质量等级。

## 5. 后续判断

需要建立统一 Input/Focal/A11y 子系统，并把它作为组件 contract、测试门禁和主题门禁的一部分。
