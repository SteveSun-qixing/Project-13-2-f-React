# 差距分析：预览与性能工具

## 1. 对标目标

薯片框架需要预览和性能工具，覆盖组件、应用、卡片、箱子、主题、多语言、窗口尺寸、权限、错误态、a11y 和性能预算。

## 2. 当前薯片已有基础

- `Chips-ComponentLibrary` 有 `verify`、`quality:gate`、`test:a11y`、`test:perf` 等脚本。
- 有 `reports/quality-gate` 报告。
- token 和 contract 校验已经存在。
- 生态有脚手架方向和 chipsdev 开发工作区概念。

## 3. 当前主要差距

### 3.1 缺少可交互预览

当前没有等价于 SwiftUI Preview 的 `chips preview`：

- 组件预览。
- 应用页面预览。
- 主题预览。
- 卡片/箱子预览。
- Host mock 预览。
- 真实 Host 开发工作区预览。

### 3.2 缺少组件状态矩阵

组件应自动展示：

- 状态矩阵。
- 主题矩阵。
- 密度矩阵。
- 多语言矩阵。
- 长文本和极端数据。
- 焦点和键盘路径。

### 3.3 缺少视觉回归

当前质量门禁没有完整视觉回归，难以证明主题切换、组件状态、窗口尺寸、iframe 内容在视觉上稳定。

### 3.4 性能指标还不够贴近真实应用

需要增加：

- 渲染提交 p95。
- Bridge 调用延迟。
- 主题切换耗时。
- 大列表滚动。
- DataGrid/Tree 大数据量。
- 弹层打开延迟。
- 长任务比例。
- 包体与按需导入。

## 4. 差距等级

严重等级：高。

原因：没有预览和性能工具，开发者体验无法接近 SwiftUI；组件质量也难以前移验证。

## 5. 后续判断

预览和质量工具应作为薯片前端框架的一等模块，不应只作为组件库内部脚本存在。
