# 差距分析：导航 / 菜单 / 工具栏

## 1. 对标目标

薯片框架需要统一导航、呈现、菜单、工具栏、快捷键和命令面板。命令系统应成为这些入口的同一事实来源。

## 2. 当前薯片已有基础

- 已有 `ChipsTabs`、`ChipsMenu`、`ChipsDialog`、`ChipsPopover`、`ChipsTooltip`。
- 已有 `ChipsCommandPalette`。
- Workbench 已有 `SplitPane/DockPanel/ToolWindow/PanelHeader` 等。
- Host 架构有 window 服务方向。

## 3. 当前主要差距

### 3.1 缺少统一路由与导航栈

缺少：

- `NavigationStack`
- `NavigationSplitView`
- `NavigationLink`
- route schema。
- 页面离开保护。
- 嵌套路由。
- breadcrumb。

### 3.2 呈现层未统一

Dialog、Popover 存在，但缺少统一 presentation coordinator：

- 弹层栈。
- z-index 管理。
- focus trap 管理。
- Escape 行为。
- 关闭后焦点恢复。
- sheet、alert、confirmation dialog。

### 3.3 命令系统未统一

当前 `CommandPalette` 只是组件能力，不等于完整命令系统。缺少：

- command registry。
- 快捷键绑定。
- 菜单栏 placement。
- toolbar placement。
- context menu placement。
- 权限与 enabled 状态。
- i18n title。
- icon descriptor。

### 3.4 工具栏还不是框架能力

编辑器、资源管理器、插件市场、主题编辑器都需要工具栏，但当前没有统一 `Toolbar/ToolbarItem/ToolbarGroup`。

## 4. 差距等级

严重等级：高。

原因：导航、菜单、工具栏和命令是桌面应用质量核心。没有统一系统，生态应用体验会迅速分裂。

## 5. 后续判断

需要把命令系统放在 App Framework 或 Navigation/Command 模块中，由 Host/Electron 菜单、快捷键、工具栏、右键菜单、命令面板共同消费。
