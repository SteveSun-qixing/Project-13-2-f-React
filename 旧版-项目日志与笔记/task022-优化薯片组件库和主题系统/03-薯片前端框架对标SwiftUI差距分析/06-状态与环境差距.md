# 差距分析：状态与环境

## 1. 对标目标

薯片框架需要拥有状态与环境系统，覆盖本地 UI 状态、绑定状态、领域状态、Host 服务状态、主题环境、多语言环境、权限环境、焦点状态和场景级持久状态。

## 2. 当前薯片已有基础

- 架构设计中已有三层状态：Local UI state、Domain state、Service state。
- UI Hooks 设计方向包含 `useTheme/useI18n/useFile/useWindow/usePlugin/useConfig`。
- Theme Runtime、i18n、config、window、resource 等 Host 服务域已有架构定义。
- React 技术栈提供 hooks、context 和 state 基础。

## 3. 当前主要差距

### 3.1 缺少统一 Chips Environment

当前 theme、locale、workspace、pluginId、permissions、capabilities、density、sceneId 等上下文没有形成统一环境模型。

影响：

- 应用可能各自读取环境。
- 测试和预览难以统一 mock。
- 组件难以知道当前主题、语言、密度和权限上下文。

### 3.2 缺少 Binding 模型

表单、选择、导航、焦点、配置项都需要双向绑定。当前还没有统一 `Binding` 抽象。

影响：

- 表单字段重复写受控逻辑。
- 配置页难以自动和 Host config 服务绑定。
- 复杂选择状态难以跨列表、工具栏、属性面板共享。

### 3.3 服务状态边界未产品化

文档中规定应用不能直接越级访问 Host，但开发者体验还需要更清晰的封装：什么状态本地存，什么状态通过 Runtime Client，什么状态可以缓存，什么状态需要订阅。

### 3.4 焦点状态尚未成为环境能力

焦点与菜单、快捷键、命令启用、表单错误定位、弹层关闭恢复都有关。当前缺统一 Focus State。

## 4. 差距等级

严重等级：高。

原因：没有状态与环境系统，应用开发者仍然要自己拼接 React state、Host 调用、主题、多语言和焦点，无法达到 SwiftUI 式简单。

## 5. 后续判断

应建设 `@chips/state` 或同等能力，并把它接入 App Framework、UI Hooks、组件库和预览工具。
