# 差距分析：动画与动效系统

## 1. 对标目标

薯片框架需要动画和动效系统，覆盖状态变化、页面切换、弹层、菜单、展开折叠、列表重排、拖拽、骨架屏、主题切换和 reduced motion。

## 2. 当前薯片已有基础

- 主题系统已有 `motion` token 层。
- 架构设计中要求动效参数安全校验。
- 组件有 loading、skeleton、toast 等部分系统 UX 组件。

## 3. 当前主要差距

### 3.1 动效 API 不完整

缺少：

- `ChipsMotionProvider`
- `ChipsTransition`
- `ChipsPresence`
- `ChipsAnimateLayout`
- 弹层进入/退出标准。
- 列表插入/删除/重排标准。
- navigation transition 标准。

### 3.2 motion token 未覆盖组件状态矩阵

当前 motion token 存在，但还需要覆盖：

- hover/focus/active 过渡。
- dialog/popover/menu/tooltip。
- accordion/disclosure。
- toast/notification。
- split pane resize。
- drag/drop。
- theme switching。

### 3.3 reduced motion 与性能预算不足

需要明确：

- 用户减少动态效果时的降级策略。
- 动效最大时长。
- 动效曲线白名单。
- 长动画和循环动画门禁。
- 动画对渲染性能的影响指标。

## 4. 差距等级

严重等级：中高。

原因：动效不是第一阻塞，但它会直接影响高级应用品质、主题一致性和可访问性。

## 5. 后续判断

动效系统应和主题系统一体设计，组件只消费 motion token，不在组件中硬编码动画。
