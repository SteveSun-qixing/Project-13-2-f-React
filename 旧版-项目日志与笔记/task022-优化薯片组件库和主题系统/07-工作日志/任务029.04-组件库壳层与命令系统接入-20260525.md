# 任务029.04：组件库壳层与命令系统接入

## 时间

2026-05-25

## 背景

任务029.04要求卡片查看器接入组件库 vNext 壳层与 Host command registry，把现有“打开文件”动作迁移到统一命令链路，同时保持空态按钮、拖拽入口和当前查看逻辑不变，不提前新增最近打开、导出或诊断等产品行为。

## 本次处理

- 新增 `Chips-CardViewer/src/commands/`：
  - 定义稳定命令 `com.chips.card-viewer.open-file`；
  - 使用 `titleKey / descriptionKey / ariaLabelKey`，不在 command schema 写原始文案；
  - 设置 `IconDescriptor`、`handlerId`、app scope、`platform.read` 执行业务权限、菜单与工具栏 placement；
  - 通过 `useCardViewerCommands()` 注册/注销命令，监听 `command.invoked` 后回调原有 `runtime.openFile()`。
- 更新 `AppShell`：
  - 接入 `ChipsCommandProvider` 与 `createCommandAdapter(client)`；
  - 空态“打开文件”按钮改为调用 `command.invoke`，再由 command invoked handler 进入原打开文件流程；
  - 文档/文件已打开后显示 `ChipsMenuBar` 与 `ChipsToolbar`，空态首屏保持原有导入提示，不新增“卡片查看器”标题。
- 更新 `CardViewerShell`：
  - 使用组件库 `ChipsMenuBar / ChipsToolbar` 消费 command views；
  - 命令行禁用状态反映注册错误，错误码通过状态文本暴露；
  - 壳层样式继续使用主题 token 与组件库 `data-scope` 输出。
- 更新 `DropZone`：
  - 将大段 inline style 收口到 `DropZone.css`；
  - `ChipsButton` 使用组件库正式 `onPress` 入口；
  - 保留拖拽路径解析、空态文案与错误提示行为。
- 更新 `manifest.yaml` 与组件库环境权限快照：
  - 补齐 `command.read / command.write / command.invoke`；
  - 保留打开文件所需 `platform.read`。
- 补充中英文 i18n key：
  - open-file 命令标题、描述、aria label；
  - 文件菜单与工具栏 aria label。
- 新增 `tests/unit/commands.test.ts`：
  - 验证 command metadata；
  - 验证禁用 raw 文案字段；
  - 验证菜单/工具栏 placement 与 i18n 解析；
  - 验证 manifest 命令权限。

## 行为保持

- 首屏仍展示“拖入卡片或箱子文件”和“打开文件”。
- 首屏仍不展示“卡片查看器”标题。
- 拖拽入口仍直接通过正式路径解析进入 `openFilePath()`。
- 文件选择仍调用 `client.platform.openFile({ title, mode: "file", allowMultiple: false, mustExist: true })`。
- `.card / .box` 渲染仍由 SDK/Host `document.window.render` 统一链路处理。
- 未新增最近打开、导出、诊断面板或产品逻辑重设计。
