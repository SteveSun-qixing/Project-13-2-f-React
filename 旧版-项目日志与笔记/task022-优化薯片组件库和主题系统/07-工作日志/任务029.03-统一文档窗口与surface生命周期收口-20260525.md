## 完成内容

1. `HostedDocumentWindow` iframe sandbox 收口为正式窗口基线：
   - 从 `allow-scripts allow-same-origin allow-popups` 改为 `allow-scripts allow-forms`。
   - 移除 `allow-same-origin`，与 SDK `card.compositeWindow.render(...)` / `box.documentWindow.render(...)` 当前正式策略一致。
2. 为托管文档 iframe 记录 `data-chips-origin`：
   - 通过 `documentUrl` 解析 frame origin。
   - `chips-render:` 等 opaque origin 会记录为 `null`。
3. message 监听补齐来源过滤：
   - 继续要求 `event.source === frame.contentWindow`。
   - 接受 `origin === "null"`。
   - 接受当前窗口 origin 或 `frame.dataset.chipsOrigin`。
   - 拒绝不匹配来源并输出诊断日志。
4. 托管文档事件覆盖扩展：
   - ready：`chips.composite:ready`、`chips.box-layout:ready`。
   - error：`chips.composite:fatal-error`、`chips.box-layout:error`。
   - resize：继续使用 `chips.composite:resize` 驱动 `plugin.surface.resize`，保持任务029.01冻结行为。
   - resource open：继续只消费 `chips.composite:resource-open`，资源路由仍走 `client.resource.open(...)`。
5. 资源打开事件新增 payload 校验：
   - 缺少有效 `resourceId` 时不再调用 `client.resource.open(...)`。
   - 通过 `client.platform.showMessage(...)` 显示可诊断错误。
6. 托管文档 iframe title 从硬编码英文改为 i18n key：
   - `card-viewer.viewer.hostedDocumentFrameTitle`
7. 单元测试补齐：
   - sandbox 与 iframe title。
   - `data-chips-origin`。
   - 不匹配 origin 被忽略。
   - `null` origin 被接受。
   - 缺少 `resourceId` 时不调用 `resource.open` 且显示错误。
