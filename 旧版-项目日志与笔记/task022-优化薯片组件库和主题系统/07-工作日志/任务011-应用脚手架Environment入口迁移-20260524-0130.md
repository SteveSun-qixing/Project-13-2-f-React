# 任务011：应用脚手架 Environment 入口迁移

时间：2026-05-24 01:30:00 CST (+0800)

## 本阶段目标

在任务011第一阶段已有 `ChipsEnvironmentProvider/useChips*` 的基础上，迁移官方应用脚手架标准模板，让新生成应用默认通过 SDK client + React Environment hooks 消费 Host 环境，不再生成本地 `useChipsBridge` 私有入口。

## 主要改动

1. `chips-scaffold-app/templates/app-standard`
   - `App.tsx.tpl` 使用 `ChipsEnvironmentProvider` 注入 `chipsClient`。
   - 使用 `useChipsTheme/useChipsI18n/useChipsSurface/useChipsPermission/useChipsDiagnostics` 展示 Host 环境状态。
   - `ChipsThemeProvider` 改为消费 Environment 中的主题状态与事件源。
   - `useAppCommands.ts.tpl` 改为通过 `useChipsClient()` 取得同一个 SDK client，再注册、监听和调用 `client.command.*`。
   - 旧 `src/hooks/useChipsBridge.ts.tpl` 移入脚手架仓内部 `归档/`，不再进入生成工程。

2. 测试与门禁
   - `template-engine.test.ts` 增加 Environment hooks、`useChipsClient` 和旧私有 Bridge hook 不生成的断言。
   - `scripts/check-templates.mjs` 递归扫描 active `src/**` 模板源码，并增加 React Environment 正式入口检查。
   - `scripts/run-generated-e2e.mjs` 增加生成工程 Environment 入口检查。

3. 文档同步
   - 更新应用模板 README、脚手架内部需求/技术文档。
   - 更新生态公共《应用插件开发》和《前端框架 vNext 公共契约与术语冻结》，记录官方 app 模板默认 Environment Provider 接线。
   - 保存子代理勘察报告到 `08-草稿笔记`。
   - 插入后续 `任务011.1-应用模板同步I18nAdapter与语言切换入口.md`，用于处理同步 i18n adapter 和语言切换入口。

## 验证

已通过：

- `cd Chips-Scaffold/chips-scaffold-app && npm run test:templates`
- `cd Chips-Scaffold/chips-scaffold-app && npm run build`
- `cd Chips-Scaffold/chips-scaffold-app && npm test`
- `cd Chips-Scaffold/chips-scaffold-app && npm run test:e2e`

## 结论

任务011第二阶段已完成。官方应用模板现在默认走 React Environment Provider 与 SDK client 注入链路，命令系统、主题、多语言、surface、权限和诊断状态都有正式 hook 示例；生成工程不再带出 `useChipsBridge` 旧入口。
