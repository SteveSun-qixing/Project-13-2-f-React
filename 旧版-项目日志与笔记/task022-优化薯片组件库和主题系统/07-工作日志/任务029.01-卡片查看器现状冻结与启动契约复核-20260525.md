## 冻结的当前用户可见行为

1. 空启动：
   - 首屏显示居中拖拽/打开文件入口。
   - 中文文案为“拖入卡片或箱子文件”和“打开文件”。
   - 首屏不显示额外“卡片查看器”品牌标题。

2. Host `targetPath` 启动：
   - `App.tsx` 通过 `client.platform.getLaunchContext()` 读取 `launchParams.targetPath`。
   - 当 `targetPath` 是 `.card` 或 `.box` 时，进入文件文档查看态。
   - 当文件类型不支持时，显示 `card-viewer.errors.unsupportedFile` 对应错误。

3. Host `webDocumentUrl` 启动：
   - `App.tsx` 优先读取 `launchParams.webDocumentUrl`。
   - 存在该参数时进入托管文档查看态，使用 `HostedDocumentWindow` 承载 iframe。
   - 该路径当前是已存在用户可见行为，后续迁移不得无证据删除。

4. 打开文件按钮：
   - 通过 `client.platform.openFile({ title, mode: "file", allowMultiple: false, mustExist: true })` 打开系统文件选择器。
   - 返回第一个文件路径后进入 `handleResolvedFilePath`，只接受 `.card/.box`。
   - 选择失败时显示 Host action 失败提示。

5. 拖拽文件：
   - `DropZone` 接收拖拽文件。
   - 优先通过 `window.chips.platform.getPathForFile(file)` 解析本地路径。
   - fallback 使用 `file.path`。
   - 成功解析后与打开按钮共享同一文件类型判断和打开路径。

6. 文档窗口：
   - `CardWindow` 通过 `client.document.window.render({ filePath, locale, mode: "view" })` 渲染 `.card/.box`。
   - SDK 内部按扩展名分发：`.card` 进入 `card.compositeWindow.render(...)`，`.box` 进入 `box.documentWindow.render(...)`。
   - 查看器不扫描卡片或箱子内部资源，不 import 基础卡片插件或布局插件源码。

7. 资源打开：
   - `CardWindow` 通过 `client.document.window.onResourceOpen(...)` 监听复合卡片资源打开事件。
   - 收到资源打开请求后调用 `client.resource.open(...)`。
   - 资源打开失败时调用 `client.platform.showMessage(...)` 展示错误。

8. 托管文档高度：
   - `HostedDocumentWindow` 监听 `chips.composite:ready`、`chips.composite:resize`、`chips.composite:fatal-error`、`chips.composite:resource-open`。
   - 根据内容高度发布 `plugin.surface.resize`。
   - 高度收缩等待 stable 窗口后再发布稳定高度。

9. 主题与语言：
   - 启动时先读取文档上的 `data-chips-theme-id` / `data-chips-theme-version`。
   - 随后调用 `client.theme.getCurrent()` 与 `client.i18n.getCurrent()` 校准。
   - 监听 `language.changed` 后只更新本地 locale 并重渲染。
   - `CardWindow` 依赖 `useThemeRuntime().cacheKey` 在主题变化后重新渲染文档窗口。

## 后续风险与分配

以下风险不阻塞任务029.01完成，但必须在后续子任务中收口：

1. `HostedDocumentWindow` sandbox 与公共复合窗口标准存在差异。
   - 当前：`allow-scripts allow-same-origin allow-popups`。
   - SDK 正式 `card.compositeWindow` 与 `box.documentWindow` 当前使用 `allow-scripts allow-forms`。
   - 分配到任务029.03处理。

2. `HostedDocumentWindow` 手写 message 监听只检查 `event.source`。
   - SDK `document.window` / `card.compositeWindow` / `box.documentWindow` 事件订阅包含 origin/null-origin 过滤。
   - 分配到任务029.03处理。

3. `Chips-ComponentLibrary` 的 `CompositeCardWindow` 默认 sandbox 仍是 `allow-scripts allow-same-origin`。
   - 任务029当前不直接依赖该默认值。
   - 若后续接入组件库高级 iframe 组件，必须显式传入正式 sandbox 或另行登记组件库收口工单。

4. README 主显示链路与当前代码不一致。
   - README 仍写 `client.card.compositeWindow.render({ cardFile, mode: 'view' })`。
   - 当前真实主链路是 `client.document.window.render({ filePath, locale, mode: "view" })`。
   - 分配到任务029.07更新 README。

5. web target 真实能力边界需要保持谨慎。
   - manifest 声明 `web.supported: true`。
   - 当前用户可见 web 路径主要体现为 `webDocumentUrl` 托管文档恢复；本地 `.card/.box` 文件打开仍依赖本地路径和平台文件选择。
   - 后续迁移不得扩大 web 行为承诺。

6. `client.document.window.onResourceOpen(...)` 当前只代理卡片复合资源事件。
   - 箱子条目打开当前由 SDK box runtime bridge 处理。
   - 后续不得在查看器内私造箱子资源打开协议；若需要统一箱子资源打开事件，先补 SDK/公共契约。
