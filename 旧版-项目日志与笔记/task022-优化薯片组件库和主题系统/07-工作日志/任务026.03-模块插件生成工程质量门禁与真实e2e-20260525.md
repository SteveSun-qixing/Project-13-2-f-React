# 任务026.03：模块插件生成工程质量门禁与真实 e2e

## 时间

2026-05-25

## 本次目标

将 `chips-scaffold-module` 的生成工程 e2e 从模板渲染 smoke 升级为真实开发者链路验证，确保默认模块工程可以通过 CLI 创建、安装依赖、执行质量门禁、打包为 `.cpk`，并被 Host 正式安装、启用和调用。

## 主要改动

- 升级 `Chips-Scaffold/chips-scaffold-module/scripts/run-generated-e2e.cjs`：
  - 在临时生态工作区中通过真实 `chipsdev create module` 创建 7 个模块模板工程；
  - 检查模板矩阵关键文件、未渲染占位符、旧模块挂载口径、旧 CLI 文本和 `template.json` 泄漏；
  - 对默认模板生成工程执行根工作区 `npm install` 与生成工程 `npm run verify`；
  - 断言生成工程质量脚本、`volta.extends`、`manifest.entry`、`dist/index.mjs` 和 `.cpk` 包命名；
  - 通过 Host 正式运行时安装启用生成 `.cpk`，验证 `module.listProviders`、`module.resolve`、同步 `module.invoke`、异步 job、schema 错误路径、`module.job.cancel` 与工作区插件记录。
- 升级 `module-standard` 默认异步 job 样板：
  - 增加 `ctx.job.signal` 与 `ctx.job.isCancelled()` 取消感知；
  - 增加 `MODULE_JOB_CANCELLED` 结构化错误；
  - 更新生成工程单测覆盖取消路径；
  - 更新模板 README 说明。
- 更新模块脚手架内部需求与测试策略文档，明确真实 e2e 与 Host 运行链路质量门禁。
