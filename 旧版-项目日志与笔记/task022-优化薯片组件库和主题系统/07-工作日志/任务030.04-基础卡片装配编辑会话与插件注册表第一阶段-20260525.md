# 任务030.04：基础卡片装配、编辑会话与插件注册表第一阶段

## 时间

- 2026-05-25

## 本阶段目标

根据 `任务030.04-基础卡片装配编辑会话与插件注册表收口.md`，优先收口编辑引擎本地基础卡片运行时的第一批稳定性问题：

1. 基础卡片注册表必须统一覆盖内置描述符与 Host 已安装启用插件。
2. 卡箱库展示入口必须来自正式可用注册表，而不是只显示已安装插件。
3. 单个基础卡片预览失败必须隔离在单卡范围内，不遮挡整张复合卡片。
4. `EditorHost` 的资源回调与 flush 入口必须稳定，避免普通草稿变化导致编辑器重挂载或提前提交。

## 已完成

- 复核 `生态设计原稿/14-编辑引擎设计.md`、`生态共用技术文档/组件库/08-编辑引擎基础卡片装配与编辑运行时标准.md`、`生态共用技术文档/插件开发/03-卡片插件开发.md` 与当前 `Chips-EditingEngine` 实现。
- `src/basecard-runtime/registry.ts`
  - 注册表可用列表改为按 `cardType` 去重的“内置 + 已安装启用插件”集合。
  - 已安装插件加载改为单插件错误隔离，一个坏插件不会拖垮内置卡片和其他有效插件。
  - 校验 `basecardDefinition.cardType` 必须存在于 Host 暴露的 `manifest.capabilities` 中，保持与公共卡片插件契约一致。
- `src/components/CardBoxLibrary/data.ts`
  - 卡箱库基础卡片列表改为读取 `getRegisteredBasecardDescriptors()`，确保内置富文本、图片、网页等描述符也能进入正式拖拽入口。
- `src/components/CardWindow/CardWindow.tsx`
  - 移除整张复合卡片错误遮罩，单卡错误继续由 `BasecardFrameHost` 自己显示，外层仅记录诊断日志。
- `src/basecard-runtime/frame-host.tsx`
  - `pendingResourceImports` 改为 ref 读取，避免待落盘资源映射变更导致单卡 iframe 重新挂载。
- `src/editor-runtime/EditorHost.tsx`
  - `pendingResourceImports` 改为 ref 读取，资源预览回调身份保持稳定。
  - flush 入口改为 `commitSessionRef`，避免草稿变化时 effect cleanup 提前提交中间草稿。
- 补充专项测试：
  - `basecard-registry.test.ts` 覆盖内置 + 已安装插件合并、坏插件隔离、构建产物入口 URL。
  - `card-window.test.tsx` 覆盖单卡错误不触发整卡遮罩。
  - `plugin-host.test.tsx` 覆盖分帧输入不提前提交、待落盘资源映射变化不重挂载编辑器。
