## 阶段进展

- 将 `converter.html.to-pdf/convert` 收口为只消费带 `conversion-manifest.json` 的目录态 HTML 中间产物：
  - manifest 必须为 `type: "card-to-html"`；
  - `entryFile` 省略时优先使用 manifest 的 `output.entryFile`；
  - 输出保留上游 `semanticHash / locale / themeId / renderDiagnostics / renderConsistency / contentFiles` 摘要。
- 扩展 PDF 输入输出契约：
  - 输入增加 `overwrite`、`preferCSSPageSize`、`headerFooter`、`wait`；
  - 输出增加 `entryFile`、`mimeType: "application/pdf"`、`byteLength`、`manifest`、`diagnostics`。
- 模块输出改为事务式发布：
  - Host 先写入临时 `final/` PDF；
  - 默认拒绝覆盖既有目标；
  - `overwrite=true` 时先备份旧 PDF 到临时 `backup/`，新文件提交失败时尽力恢复旧输出；
  - 失败或取消后清理临时根目录。
- Host PAL `platform.renderHtmlToPdf` 补强：
  - 正式接收并传递 `preferCSSPageSize`、页眉页脚模板和等待策略；
  - HTML 导出 readiness 脚本返回图片、iframe、复合卡片等待诊断；
  - 返回 `byteLength` 和 `diagnostics`。
- SDK platform 类型同步 `renderHtmlToPdf` 的高级输入和诊断输出。
- e2e fixture 增加 `conversion-manifest.json`，确保打包态验证走正式中间产物契约。
