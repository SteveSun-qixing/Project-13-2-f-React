# 任务016.03 Form Compound 迁移

## 背景

任务016第三批处理 `Form` 复杂组件 Compound API。按照 `任务016.03-FormCompound迁移.md`，本批目标是把早期 `FormField/FormGroup` 与 `helper` 口径收口为正式 `ChipsForm.Root / Section / Field / Label / Control / Error / Hint`，并同步运行时、类型、contract、token、主题包、Host L8 schema 和公共文档。

## 本次改动

- 新增正式 `ChipsForm` Compound API：`Root / Section / Field / Label / Control / Error / Hint`。
- 表单正式 scope 统一为 `form`，公开 part 统一为 `root / section / field / label / required / control / hint / error / status`。
- `Field` 负责字段级 `id`、`required/disabled/readOnly/error` 状态、`aria-describedby` 聚合、`aria-invalid` 和上下文分发。
- `Label` 自动关联当前字段 control；`Hint` 与 `Error` 自动注册描述文本；`Error` 输出字段错误语义与 `role="alert"`。
- `Control` 对原生 `input/textarea/select/button` 输出 `data-scope="form"` 与 `data-part="control"`；对自定义 Chips 控件只注入语义属性，不覆盖其自身 scope/part。
- 移除正式公开导出的 `ChipsFormField / ChipsFormGroup`，旧 `form-field / form-group / helper` contract 与 token 已归档，不再参与正式契约校验。
- `Chips-ComponentLibrary/packages/theme-contracts/src/validator.js` 跳过 `归档/` 目录，避免历史 contract 被正式校验重新拾取。
- 同步组件库类型声明、导出测试、a11y 规则、contract 测试、token 测试和内部 Data-Form 文档。
- 默认主题包和暗色主题包同步 `form` token、contract、CSS 和测试；旧主题 token 移入对应 `归档/task016.03-form-compound/`。
- 默认主题包补齐 light ref 色板中被日期时间 token 引用的 `gray-50..950`、`blue-50/100/400/600/700`、`red-400` 等层级，修复 Host 全量测试中的 token 引用阻断。
- Host L8 `StandardCompoundSlotSchemas.Form` 与诊断测试同步 `section/field/label/control/error/hint` 结构。
- 生态共用文档同步：
  - `组件库/01-组件库对外使用总览.md`
  - `组件库/02-组件契约标准.md`
  - `组件库/03-Token与主题对接标准.md`
  - `组件库/05-可访问性与质量基线.md`
  - `架构设计/17-L8声明式UI实现与接口细则.md`

## 边界说明

- 本批只提供表单结构、状态挂点与 ARIA 关联，不实现业务校验、dirty/touched 或任务017 的 Binding 状态模型。
- 本批没有扩大为主题视觉升级，只做 contract/data-part 改动强制牵动的主题包最小同步，以及修复已暴露的默认主题 ref token 引用缺口。
- `chips.comp.form.field.gap` 派生出的 CSS 变量名为 `--chips-comp-form-field-gap`，表示 `form.field.gap` token，不代表旧 `form-field` scope 复活。
- 旧 `form-field / form-group / helper` 只作为归档与文档说明出现，不再是正式公开表单契约。
