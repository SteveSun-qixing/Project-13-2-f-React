## 已完成内容

1. 统一 7 个模块模板 README：
   - `module-standard`
   - `module-pure-function`
   - `module-file-conversion`
   - `module-html-rendering`
   - `module-image-processing`
   - `module-color-extraction`
   - `module-orchestration`
2. README 统一补充以下正式口径：
   - 模块插件是 Host 托管的无界面能力模块，不创建窗口、不做 DOM 挂载；
   - 生成工程通过 `npm run verify` 串联 lint、typecheck、test、build、validate 和 package；
   - `npm run package` 输出 `.cpk`，必须能被 Host 安装启用并通过模块服务调用；
   - `chipsdev module invoke` 是真实 Host 联调入口；
   - `--timeout-ms`、`MODULE_TIMEOUT`、`MODULE_SCHEMA_INVALID`、`MODULE_JOB_CANCELLED` 等治理语义必须与 Host 一致；
   - `module.consumes` 只声明下游能力依赖，不自动安装或启用 provider；
   - 模块之间调用必须通过 `ctx.module.invoke(...)`，不能跨目录 import 下游模块源码。
3. 新增 `Chips-Scaffold/chips-scaffold-module/README.md`，作为模块脚手架包级维护入口，说明模板矩阵、创建命令、生成工程验证、Host 联调和维护门禁。
4. 补强 `template-engine` 测试，断言生成 README 必须包含 `.cpk`、`chipsdev module invoke`、`MODULE_TIMEOUT`、`MODULE_JOB_CANCELLED` 和 `module.consumes` 等关键口径。
5. 同步脚手架内部需求与技术文档：
   - 模块插件脚手架需求总览；
   - 功能需求规格；
   - 非功能与质量验收需求；
   - 总体架构设计；
   - 模板目录与文件组织设计；
   - 命令行集成与工作流设计；
   - 测试策略与质量门禁设计。
6. 同步生态公共文档：
   - `生态共用技术文档/插件开发/05-模块插件开发.md`；
   - `生态共用技术文档/命令行工具/02-Chips-Dev开发者命令行手册.md`。
