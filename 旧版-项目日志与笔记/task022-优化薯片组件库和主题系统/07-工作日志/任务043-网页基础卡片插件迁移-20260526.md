## 初始差距

- 工程已具备 `basecardDefinition`、`renderBasecardView`、`renderBasecardEditor`、网页视口协议、ZIP 导入和基础测试。
- `package.json` 尚未声明正式 `@chips/component-library` 依赖，`template.json` 仍标记 `componentLibrary: false`。
- 编辑器仍主要使用自建按钮、输入框和分段控件，需要迁移到组件库公开组件与 `data-scope/data-part` 主题契约。
- `BasecardArchiveImportRequest` 缺少正式 `include/stripSingleRootDir/excludeSystemArtifacts` 字段，网页 ZIP 导入调用也未显式传递这些通用目录导入规则。
- `BasecardRenderContext` 尚未暴露 `openResource`，查看态没有把远程 URL 或网页包入口的打开意图交给宿主资源打开链路。
- URL 校验仍允许 `file:`；任务和公共文档中网页远程来源应收敛到 `http/https`，卡片内网页文件走 `bundle_root + entry_file`。

## 本轮处理计划

1. 补齐组件库依赖、模板能力标记与正式上下文类型。
2. 收紧 URL 安全校验为 `http/https`，保留卡片根网页包资源通过 `resolveResourceUrl` 读取。
3. 编辑器改用 `ChipsForm`、`ChipsSegmentedControl`、`ChipsTextField`、`ChipsButton`、`ChipsIcon`，继续保留“比例 -> 模式 -> 条件输入”的原交互。
4. ZIP 导入补齐 `include`、`stripSingleRootDir`、`excludeSystemArtifacts`，并清洗导入结果的卡片根相对路径。
5. 查看态新增可选打开按钮，通过 `openResource(...)` 只表达网页来源打开意图，不硬编码目标应用。
6. 更新测试、README/技术文档/需求文档，并运行正式验证命令。

## 完成结果

- 已将 `Chips-BaseCardPlugin/webpage-BCP` 接入正式 `@chips/component-library`，编辑器使用 `ChipsForm / ChipsSegmentedControl / ChipsTextField / ChipsButton / ChipsIcon`，继续保持“显示比例 -> 网页模式 -> 条件输入 -> 当前来源”的原交互顺序。
- 已补齐 `BasecardArchiveImportRequest.include / stripSingleRootDir / excludeSystemArtifacts`，网页 ZIP 导入通过 `importArchiveBundle(...)` 传递入口文件、过滤规则、单根目录剥离和系统噪声排除，配置只保存卡片根目录相对 `bundle_root / entry_file / resource_paths`。
- 已将远程网页 URL 安全口径收敛为 `http/https`；本地网页文件不再作为 `source_url`，必须通过网页 ZIP 包导入为卡片根目录资源。
- 已增强资源路径清洗，拒绝协议 URL、查询串、片段和路径逃逸；bundle 配置校验要求资源清单包含 `bundle_root/index.html`。
- 已在查看态接入可选 `openResource(...)`，通过“打开来源”按钮把远程 URL 或网页包入口的打开意图交回宿主资源打开链路，不硬编码目标应用。
- 已补齐 i18n、README、需求文档、技术文档、模板参数和测试，新增 JSDOM 类型声明用于本插件测试类型检查。
- 已补齐 `typecheck / package / verify` 脚本并同步根 `package-lock.json`。
- 主代理复核时将 schema 校验错误从中文文本收口为 `webpage.validation.*` 语言包 key，并补齐中英文语言包，避免后续编辑引擎或统一校验面板直接暴露单插件硬编码文案。
