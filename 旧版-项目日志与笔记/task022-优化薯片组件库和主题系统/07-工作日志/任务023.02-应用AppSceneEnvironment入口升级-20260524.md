## 关键改动

1. 新增 `AppRuntimeProvider / useAppRuntime`
   - 由 `useChipsTheme/useChipsI18n/useChipsSurface/useChipsPermission/useChipsDiagnostics` 汇总应用运行时。
   - 从 `surfaceContext` 与 `launchContext` 解析当前 scene，保留 `sceneId / surfaceId / sessionId / kind / launchParams`。
   - 提供统一 `environment`、`status`、`permissions`、`diagnostics`、`refreshEnvironment`、`setLocale`、`refreshTheme`、`pushDiagnostic` 等入口。

2. `AppProviders` 分层升级
   - `ChipsEnvironmentProvider` 继续注入 SDK client、初始主题、初始语言、surface、launch context 和权限。
   - `ChipsThemeProvider` 继续接入 Host 主题状态。
   - 新增 `onDiagnostic` 默认处理，诊断统一进入应用运行时日志口径。

3. App Shell 与业务视图改为消费应用运行时
   - `AppShell` 不再自己拼接 scene/surface/permission/diagnostics。
   - `WorkspaceOverviewView`、`EnvironmentStatusView`、`StateBindingView` 改为通过 `useAppRuntime()` 获取环境状态和诊断动作。
   - 生成工程开发者默认只面对 `useAppRuntime()` 与业务场景组件，不需要手写 Host Bridge 初始化。

4. 测试和门禁同步
   - 模板检查要求生成 `AppRuntimeProvider`，并扫描 `useAppRuntime`、Environment hooks 和正式入口。
   - 生成工程 e2e 与 `template-engine` 测试加入 `AppRuntimeProvider` 文件断言。
   - 单元测试覆盖从 surface / launch context 解析 scene，以及运行时诊断对象生成。

5. 公共文档同步
   - 更新 `生态共用技术文档/插件开发/02-应用插件开发.md` 的官方应用脚手架基线，明确 `AppRuntimeProvider / useAppRuntime()` 是当前模板汇总 App / Scene / Environment 的正式入口。
