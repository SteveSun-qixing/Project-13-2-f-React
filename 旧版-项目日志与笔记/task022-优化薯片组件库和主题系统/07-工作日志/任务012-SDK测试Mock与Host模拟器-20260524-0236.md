# 任务012-SDK测试Mock与Host模拟器

## 本阶段目标

- 为 SDK 增加统一测试辅助入口，避免应用模板、组件库 hooks 和 SDK 自身测试各自维护分散 mock。
- 模拟公开 Host Bridge action、事件、surface context、权限错误、延迟、timeout/retry 等测试场景。
- 让应用脚手架模板命令测试复用 SDK testing helper。
- 同步公共文档、内部测试策略文档与子代理勘察报告。

## 实施内容

- `Chips-SDK`
  - 新增 `src/testing/mock-host.ts` 与 `src/testing/index.ts`。
  - 新增 `chips-sdk/testing` 子入口，同时根入口导出常用 testing helper。
  - `createMockChipsHost()` 支持 calls/state/events/transport/action handler/fault/delay/permission denied/Bridge 安装。
  - `createMockChipsClient()` 通过真实 `createClient()` 创建 SDK client，默认安装测试用 `window.chips`，覆盖 plugin Bridge 与 `platform.getLaunchContext()` 路径。
  - 新增 `tests/testing.test.ts`，覆盖 theme/i18n 事件、launch context、surface、command、permission denied、timeout/retry。
  - 将 testing 测试纳入 `npm test`。

- `Chips-ComponentLibrary`
  - 扩展 `@chips/testing` 的 mock client，使其具备 Host-like calls/state/events/fault 语义。
  - 新增 surface/launch/permission/theme diagnostic fixture。
  - hooks 测试补充 command event 与 permission fault 覆盖。
  - README 说明 `@chips/testing` 与 `chips-sdk/testing` 的职责边界。

- `Chips-Scaffold/chips-scaffold-app`
  - 应用模板 `tests/unit/commands.test.ts.tpl` 改为从 `chips-sdk/testing` 导入 `createMockChipsClient`。
  - command 单元测试覆盖 `client.calls` 与 `command.onInvoked` 事件链路。
  - 模板检查脚本、生成工程测试与 E2E 断言同步要求 `chips-sdk/testing`。

- 文档与记录
  - 更新 `生态共用技术文档/插件开发/08-SDK使用指南.md`，新增 SDK testing helper 使用与边界。
  - 更新 `生态共用技术文档/架构设计/13-测试架构设计.md`，补充 SDK Host 模拟器正式职责。
  - 更新 `生态共用技术文档/组件库/01-组件库对外使用总览.md`，明确组件库 testing 与 SDK testing 边界。
  - 更新 `Chips-SDK/技术文档/09-测试策略与质量门禁设计.md`。
  - 更新 `Chips-Scaffold/chips-scaffold-app/技术文档/05-测试策略与质量门禁设计.md`。
  - 保存子代理勘察报告到 `08-草稿笔记/任务012-SDK测试Mock与Host模拟器前置勘察报告.md`。

## 备注

- 当前实现没有复制 Host 主运行时，SDK testing 只模拟公开 action、Bridge、事件与标准错误形态。
- 组件库原生 Node ESM 测试无法直接消费 SDK 当前 TS 源入口，因此 `@chips/testing` 先保持组件测试适配层，并按 SDK testing 的 calls/state/events/fault 形态对齐；应用模板和 SDK 自身测试已使用正式 `chips-sdk/testing`。
