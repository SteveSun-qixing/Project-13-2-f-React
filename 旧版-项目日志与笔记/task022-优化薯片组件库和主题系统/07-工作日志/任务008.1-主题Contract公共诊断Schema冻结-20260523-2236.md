# 任务008.1：主题 Contract 公共诊断 Schema 冻结

- 冻结主题治理公共 Schema：`ThemeContractView`、组件 contract view、`ThemeDiagnostic`、`ThemeDiagnosticSummary`、coverage 与 `theme.changed` 诊断摘要。
- Host Theme Runtime 已输出统一结构：
  - `theme.resolve` 返回 `resolved / tokens / diagnostics / summary`。
  - `theme.contract.get` 返回完整 `ThemeContractView`。
  - `theme.changed` 事件携带 `themeVersion / diagnosticsSummary`。
  - `THEME_CONTRACT_INVALID` 详情携带结构化 `diagnostics / summary`。

  - `ThemeContractView`
  - `ThemeDiagnostic`

  - `ThemeChangedPayload`
  - `theme.onChanged()`

- 按公共组件契约标准，移除普通组件 contract 中错误的 `iframe` 扩展字段，仅保留 `card-cover-frame` 与 `composite-card-window`。

- Host 与 SDK 内部技术/需求文档已同步接口类型口径。
- SDK create-workspace 系列集成测试的临时生态根补充 `tldts/tldts-core@7.0.30` overrides，用于规避当前 npm 镜像缺失 `tldts-core@7.0.31` 导致的测试安装失败；该改动只影响测试沙箱，不改变生成工程依赖声明。

## 关键结论

- `ThemeDiagnostic` 是后续 Host、SDK、主题包、组件库、设置面板和 CLI 的唯一公共主题诊断模型。
- `ThemeContractView.components[].coverage` 是设置面板展示主题覆盖率、缺失 token 与阻断原因的正式数据源。
- `theme.changed.diagnosticsSummary` 只承担快速状态摘要，不替代 `theme.resolve` 和 `theme.contract.get` 的完整诊断视图。
- 暗色主题缺布局原语 token、主题包完整 contract 补齐属于既有 `任务008.2`，本任务不混入主题 token 补齐实现。
