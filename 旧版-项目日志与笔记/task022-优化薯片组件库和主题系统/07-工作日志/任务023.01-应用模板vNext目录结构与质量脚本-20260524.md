# 任务023.01：应用模板 vNext 目录结构与质量脚本

## 本次范围

- 按 `任务023.01-应用模板vNext目录结构与质量脚本.md` 执行 `chips-scaffold-app` 第一阶段升级。
- 生成工程从旧单文件示例根组件切换为 `src/app`、`src/scenes`、`src/views`、`src/runtime`、`src/theme`、`src/testing`、`src/preview` 的 vNext 应用骨架。
- `src/App.tsx` 改为薄入口，真实根组件落在 `src/app/AppRoot.tsx`。
- 旧 `src/components/ExamplePanel.tsx.tpl` 已从生成模板移出，并按工作区规则保存在脚手架归档目录：`Chips-Scaffold/chips-scaffold-app/归档/task023.01/ExamplePanel.tsx.tpl`。

## 关键改动

1. 应用运行入口：
   - 新增 `AppProviders`，通过 `ChipsEnvironmentProvider` 注入 SDK client、launch context、surface context、初始主题、初始语言和权限。
   - 新增 `RuntimeThemeProvider`，将 Environment 中的主题状态接入组件库 `ChipsThemeProvider`。
   - 新增 `scene-registry`，为后续 App / Scene 扩展提供稳定注册表。

2. 视图与状态样板：
   - 新增主场景、设置场景、工作区概览、状态绑定、场景列表、环境状态视图。
   - 所有用户可见文案走 `i18n/*.json` 与 `useAppText`。
   - 组件样式走 `app-shell.css` 与 `--chips-*` token，不在 React 组件中使用 inline style。

3. 命令与 i18n：
   - 命令 namespace 从旧示例语义清理为 `app.commands.*`。
   - 命令注册继续通过 `client.command.*`，不写入 `manifest.commands`。
   - 命令定义保留 SDK 注册表面，同时导出组件库消费用 `appCommandViews`，避免 TS 类型表面漂移污染运行链路。

4. 质量脚本：
   - 生成工程默认新增 `typecheck`、`preview:smoke`、`quality:gate`、`verify`。
   - `preview:smoke` 会读取 `chipsdev preview --mode mock --target app` 报告并校验关键检查项。
   - `run-generated-e2e.mjs` 改为执行生成工程完整 `npm run verify`。
   - 模板检查新增 vNext 必备文件、脚本、旧身份泄漏、inline style、旧 Bridge / Electron / Node 直连扫描。
