# 任务026.04：模块插件 Host / SDK / CLI 契约复核补强

## 本次目标

复核并补强模块插件从 Host 到 SDK / CLI 的正式调用链路，确保 provider 解析、方法调用、异步 job、超时、取消与模块间依赖声明均走统一 Host 模块服务。

## 已完成内容

1. Host 模块 provider 解析补强：
   - `module.resolve` 与未指定 `pluginId` 的 `module.invoke` 只选择 `enabled` 或 `running` provider；
   - provider 排序从字符串排序升级为语义化版本排序，确保 `1.10.0` 高于 `1.9.0`，正式版本高于同版本 prerelease；
   - `module.listProviders` 支持 `disabled/error` 状态和 `versionRange` 过滤口径。
2. Host 模块调用治理补强：
   - `module.invoke.timeoutMs` 进入 Host 模块服务；
   - sync 方法调用与输出 schema 校验受方法级超时约束；
   - job 方法返回 `jobId` 后继续受方法级超时治理，超时进入 `failed`，错误码为 `MODULE_TIMEOUT`；
   - 取消运行中 job 后进入 `cancelled`，错误码为 `MODULE_JOB_CANCELLED`，并发出 `module.job.cancelled` 事件。
3. 模块间调用治理补强：
   - `ctx.module.invoke(...)` 调用外部 capability 时，Host 运行期校验调用方 `manifest.module.consumes`；
   - 未声明依赖返回 `MODULE_CONSUME_UNDECLARED`；
   - 声明了 capability 但版本范围无匹配 provider 返回 `MODULE_PROVIDER_NOT_FOUND`；
   - 调用自身 provider 不需要额外声明，但同样只允许 `enabled/running` 状态。
4. SDK / CLI 补强：
   - SDK 测试覆盖 `timeoutMs` 会随 `client.module.invoke(...)` 传给 Host；
   - `chipsdev module invoke` 支持 `--flag=value` 与空格两种参数形式；
   - `chipsdev module invoke` 对未知参数 fail-fast，不再静默忽略；
   - Electron 开发调用入口把 `timeoutMs` 写入 Host `module.invoke` payload。
5. 公共文档已同步：
   - 模块能力契约；
   - 模块插件开发指南；
   - SDK 使用指南；
   - Host 服务域设计；
   - Chips Dev 命令行手册。
