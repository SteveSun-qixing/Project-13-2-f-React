# 任务008.2 默认与暗色主题 Contract 补齐

时间：2026-05-23 23:05:31 CST

## 本次目标

任务008 已接入 Host 主题运行时与 contract guard，官方默认主题和暗色主题必须先满足当前组件库正式 component contract，避免后续 `theme.apply`、`theme.resolve` 因 required token 缺失进入 blocked 状态。

本任务只处理 contract guard 的前置阻断：完整 contract 声明、required token 覆盖、主题包本地校验和诊断 schema。完整主题视觉升级、图标字体细节和 motion 表现仍归后续任务020/021/022。

## 勘察结论

- 组件库正式 contract 当前为 46 个组件，来源：`Chips-ComponentLibrary/packages/theme-contracts/contracts/components`。
- 默认主题原 contract 只声明 `button/input`，实际缺 `context-menu/menu-bar/shortcut/toolbar` 4 个命令消费组件 token，共 27 个 required token。
- 暗色主题原 contract 也只声明 `button/input`，实际缺 10 个布局原语与 4 个命令消费组件，共 71 个 required token。
- 暗色主题缺的是 `chips.comp.<layout-primitive>.*` 组件级 token，不是 `chips.layout.*` 公共布局层 token。
- 两个主题包原 `validate:theme` 和 `tests/contract.spec.ts` 维护本地硬编码白名单，已不适合作为任务008 后的主题契约门禁。

## 实施内容

1. 默认主题补齐命令消费组件 required token：
   - `context-menu`
   - `menu-bar`
   - `shortcut`
   - `toolbar`
2. 暗色主题补齐布局原语与命令消费组件 required token：
   - 布局原语：`view/box/stack/inline/grid/section/scroll-view/spacer/divider/split-view`
   - 命令组件：`context-menu/menu-bar/shortcut/toolbar`
3. 两个官方主题包的 `contracts/theme-interface.contract.json` 与 `theme-min-functional-set.json` 均改为覆盖组件库当前 46 个正式 component contract，并同步 `.cpk-stage/contracts`。
4. 两个主题包的 `src/validate-theme.ts` 改为读取本包 contract 与 `dist/tokens.json`，调用组件库 `@chips/theme-contracts` validator 生成 `ThemeContractView`。
5. 两个主题包的 `tests/contract.spec.ts` 改为验证完整 contract 基线和缺失 required token 的 `ThemeDiagnostic` schema。
6. 更新主题包内部 README 与技术文档，去除旧的“关键组件白名单”口径。
7. 更新生态公共主题/组件文档，明确主题包本地校验不得维护独立 token 白名单，必须消费正式 contract 与统一 validator schema。
