# 工单134 任务说明：第一阶段新前端基线与共享公共文档漂移

## 背景

task030 第一阶段已经把应用侧前端迁移方向定为 `antd + @chips/ui`，并将原 `Chips-ComponentLibrary`、`ThemePack` 与应用侧主题/i18n Provider 归档或停止作为新工程默认接线。第二阶段需要继续解决 Host、SDK、共享 UI、应用开发与主题/视觉治理之间的职责收口，因此必须先保证公共文档和实际代码使用同一条链路。

## 证据

1. `Chips-Ui/package.json` 与 `Chips-Ui/src/index.ts` 已提供 `@chips/ui` 入口、`ChipsProvider`、命令注册和统一主题 token。
2. `Chips-PhotoViewer/package.json` 使用 `antd`、`@ant-design/icons`、`dayjs` 和 `@chips/ui`。
3. `归档/Chips-ComponentLibrary/`、`归档/ThemePack/` 已存在，根 workspace 已移除原仓库作为当前前端工程依赖。
4. `生态共用技术文档/插件开发/08-SDK使用指南.md` 仍示例化 `@chips/component-library`、`ChipsEnvironmentProvider`、`useChipsTheme`、`useChipsI18n`。
5. `生态共用技术文档/插件开发/02-应用插件开发.md` 与 `生态共用技术文档/架构设计/19-前端框架vNext公共契约与术语冻结.md` 仍按旧 Provider 和主题/i18n 运行时描述应用接线。

## 影响范围

- 公共开发者入口和脚手架生成结果；
- Host 页面主题注入、Bridge 权限、SDK 类型封装的边界解释；
- 第二阶段应用 DSL、共享 UI、主题治理和质量门禁的设计依据；
- 社区开发者按照文档新建项目时的可运行性。

## 复现步骤

1. 在目标工作区执行 `rg -n "@chips/component-library|ChipsEnvironmentProvider|ChipsThemeProvider|useChipsI18n" 生态共用技术文档`。
2. 对照非归档应用的 `package.json` 与 `Chips-Ui/src/index.ts`。
3. 使用文档中的旧 Provider 示例创建工程，会得到与第一阶段模板和当前依赖不同的接线方式。

## 期望行为

1. 先由架构负责人确认 `antd + @chips/ui` 是否冻结为第一阶段之后的公共前端基线。
2. 确认后，将公共文档统一改写为：Host 负责运行时和 Bridge；SDK 负责类型化 API、CLI、脚手架与测试辅助；`@chips/ui` 负责应用侧共享 UI、antd ConfigProvider、Apple token、命令 UI 壳和无 Host 测试接线；应用只负责业务状态和页面组合。
3. 对每份文档补充最小可运行示例、Manifest 权限边界、Browser/Host 两种运行态、测试入口和正式验证命令。
4. 用脚手架真实生成工程，并执行 `typecheck`、`test`、`build`、`validate`、`package`；文档示例必须与生成产物同构。
