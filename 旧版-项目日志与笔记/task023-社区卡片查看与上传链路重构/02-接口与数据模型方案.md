# 接口与数据模型方案

## 1. 数据模型原则

社区数据模型必须区分三类对象：

1. 源文件：永久保存的 `.card`；
2. 外置资源：由本地上传器上传到资源服务器的图片、视频、音频等资源；
3. 渲染缓存：服务器从 `.card` 派生出的网页查看产物，最后一次访问后 30 天过期。

源文件和外置资源是内容资产；渲染缓存是可重建缓存。任何接口和数据库字段都不能把渲染缓存当作唯一内容来源。

## 2. cards 表字段

当前已落地源文件字段：

```ts
sourceCardBucket: text('source_card_bucket')
sourceCardKey: text('source_card_key')
sourceCardUrl: text('source_card_url')
sourceCardSha256: text('source_card_sha256')
sourceCardStoredAt: timestamp('source_card_stored_at', { withTimezone: true })
resourceManifest: jsonb('resource_manifest')
publishedByClient: text('published_by_client')
publishedClientVersion: text('published_client_version')
publishedAt: timestamp('published_at', { withTimezone: true })
```

字段说明：

- `sourceCardBucket` / `sourceCardKey`：永久 `.card` 源文件对象定位；
- `sourceCardUrl`：公开源文件可读 URL 或内部引用；私有内容不应返回长期公开 URL；
- `sourceCardSha256`：源文件内容摘要，用于渲染缓存版本键、ETag、重复检测；
- `fileSizeBytes`：处理后 `.card` 文件大小，复用原字段；
- `resourceManifest`：发布时外置资源快照；
- `publishedByClient` / `publishedClientVersion`：上传工具来源；
- `publishedAt`：源文件发布完成时间。

建议保留但降级字段：

- `htmlUrl`：不再作为主查看入口，可迁移为渲染缓存入口或最终废弃；
- `coverUrl`：继续作为列表封面入口，可来自渲染缓存封面或 `.card/cover.html` 派生产物；
- `status`：如果第一阶段沿用当前枚举，`ready` 应表示源 `.card` 可用，不再表示 HTML 已生成。

## 4. upload_session_resources 表

上传过程中的资源拆出资源表：

```ts
uploadSessionResources = {
  id: uuid,
  uploadSessionId: uuid,
  relativePath: text,
  bucket: text,
  objectKey: text,
  publicUrl: text,
  sizeBytes: bigint,
  sha256: text,
  mimeType: text,
  status: 'presigned' | 'uploaded' | 'verified' | 'error',
  createdAt: timestamp,
  updatedAt: timestamp
}
```

提交 `.card` 时以该表和对象存储 Head 结果为准，校验资源是否属于本次上传会话。

## 5. card_render_caches 表

当前已落地渲染缓存字段：

```ts
cardRenderCaches = {
  id: uuid,
  cardId: uuid,
  sourceCardSha256: text,
  rendererVersion: text,
  renderProfile: text,
  themeId: text | null,
  themeVersion: text | null,
  locale: text,
  pluginVersionManifest: jsonb,
  status:
    | 'queued'
    | 'rendering'
    | 'ready'
    | 'error'
    | 'deleting'
    | 'deleted',
  cacheBucket: text,
  cacheKeyPrefix: text,
  entryObjectKey: text,
  entryUrl: text,
  coverObjectKey: text | null,
  coverUrl: text | null,
  renderManifest: jsonb,
  sizeBytes: bigint,
  generatedAt: timestamp | null,
  lastAccessedAt: timestamp | null,
  expiresAt: timestamp | null,
  errorCode: text | null,
  errorMessage: text | null,
  createdAt: timestamp,
  updatedAt: timestamp
}
```

当前真实生效的缓存版本键包含：

```text
rendererVersion
themeId
locale
renderProfile
sourceCardSha256
```

`card_render_caches` 保留 `pluginVersionManifest` 与 `themeVersion` 字段，供后续采集插件 renderer 版本和主题版本后接入缓存失效规则；本轮实现暂不把这两个未采集字段写入 `cacheVersion`。

同一个卡片可以保留多个历史缓存记录，但 `open-view` 只选择与当前版本键匹配且 `status = ready`、`expiresAt > now` 的缓存。

当前渲染 profile：

- `community-web`：完整卡片查看缓存；
- `community-cover`：独立卡片封面缓存。

建议索引：

```text
card_render_caches(card_id, status, expires_at)
card_render_caches(card_id, source_card_sha256, renderer_version)
card_render_caches(expires_at)
card_render_caches(status, updated_at)
```

## 6. card_render_jobs 表

当前已落地渲染任务字段：

```ts
cardRenderJobs = {
  id: uuid,
  cardId: uuid,
  renderCacheId: uuid | null,
  sourceCardSha256: text,
  rendererVersion: text,
  renderProfile: text,
  locale: text,
  status:
    | 'queued'
    | 'processing'
    | 'succeeded'
    | 'failed'
    | 'cancelled',
  priority: integer,
  attemptCount: integer,
  maxAttempts: integer,
  lockedBy: text | null,
  lockedAt: timestamp | null,
  runAfter: timestamp,
  lastError: text | null,
  createdBy: 'upload' | 'view_miss' | 'cover_miss' | 'manual' | 'system_rebuild',
  createdAt: timestamp,
  updatedAt: timestamp,
  finishedAt: timestamp | null

```

同一版本键的渲染任务需要去重，避免热门卡片缓存过期后被并发访问时创建大量重复任务。

## 7. 对象存储 bucket

当前逻辑 bucket：

```text
chips-card-files
chips-card-resources
chips-card-render-cache
chips-card-render-cache-private
chips-card-cover-cache
chips-card-cover-cache-private
chips-avatars
chips-covers
```

路径建议：

```text
chips-card-files/{userId}/{cardId}/source.card
chips-card-resources/users/{userId}/uploads/{uploadId}/resources/{relativePath}
chips-card-render-cache/{cardId}/{cacheVersion}/index.html
chips-card-render-cache/{cardId}/{cacheVersion}/assets/*
chips-card-render-cache/{cardId}/{cacheVersion}/manifest.json
chips-card-cover-cache/{cardId}/{cacheVersion}/index.html
chips-card-cover-cache/{cardId}/{cacheVersion}/cardcover/*
```

`chips-card-render-cache*` 与 `chips-card-cover-cache*` 中的内容都是 30 天访问续期缓存。删除缓存时只删除对应 `cacheVersion` 目录，不影响源 `.card` 和正式资源。

## 8. API 方案

### 8.1 创建上传会话

```http
POST /api/v1/upload-sessions
Authorization: Bearer <access_token>
Content-Type: application/json
```

请求：

```json
{
  "contentType": "card",
  "fileName": "demo.card",
  "roomId": null,
  "visibility": "public",
  "client": {
    "name": "chips-official-uploader",
    "version": "0.1.0",
    "platform": "macos"
  },
  "idempotencyKey": "client-generated-key"
}
```

响应：

```json
{
  "data": {
    "uploadId": "uuid",
    "resourcePrefix": "users/<userId>/uploads/<uploadId>/resources/",
    "expiresAt": "2026-05-24T10:00:00.000Z"
  }
}
```

### 8.2 签发资源上传目标

```http
POST /api/v1/upload-sessions/:uploadId/resources/presign
Authorization: Bearer <access_token>
Content-Type: application/json
```

请求：

```json
{
  "resources": [
    {
      "relativePath": "images/photo.png",
      "sizeBytes": 1024,
      "sha256": "...",
      "mimeType": "image/png"
    }
  ]
}
```

响应：

```json
{
  "data": {
    "resources": [
      {
        "relativePath": "images/photo.png",
        "publicUrl": "https://file.chipscard.space/chips-card-resources/...",
        "uploadUrl": "https://...",
        "method": "PUT",
        "headers": {
          "content-type": "image/png",
          "x-amz-meta-chips-sha256": "...",
          "x-amz-meta-chips-upload-session": "uuid"
        },
        "expiresAt": "2026-05-24T10:00:00.000Z"
      }
    ]
  }
}
```

### 8.3 提交处理后的卡片源文件

```http
POST /api/v1/upload-sessions/:uploadId/card
Authorization: Bearer <access_token>
Content-Type: multipart/form-data
```

字段：

- `file`：处理后的 `.card`；
- `manifest`：资源 manifest JSON 字符串。

响应：

```json
{
  "data": {
    "cardId": "uuid",
    "status": "ready",
    "renderStatus": "queued",
    "renderStatusUrl": "/api/v1/cards/uuid/render-status",
    "communityUrl": "https://www.chipscard.space/cards/uuid"
  }
}
```

提交成功只代表源 `.card` 已保存。渲染缓存生成是异步过程。

### 8.5 受控查看入口

```http
GET /api/v1/cards/:cardId/view
```

行为：

1. 校验访问权限；
2. 查找有效渲染缓存；
3. 缓存 ready 时更新访问时间和 30 天过期时间；
4. 返回 `302 Location: <render-cache-entry-url>`；
5. 缓存缺失时创建渲染任务并返回 `202`。

`202` 响应：

```json
{
  "data": {
    "cardId": "uuid",
    "viewState": "rendering",
    "renderStatusUrl": "/api/v1/cards/uuid/render-status",
    "retryAfterSeconds": 3
  }
}
```

### 8.6 渲染状态接口

```http
GET /api/v1/cards/:cardId/render-status
```

响应：

```json
{
  "data": {
    "cardId": "uuid",
    "status": "rendering",
    "viewState": "rendering",
    "attemptCount": 1,
    "updatedAt": "2026-05-24T00:00:00.000Z",
    "viewUrl": "/api/v1/cards/uuid/view",
    "error": null
  }
}
```

### 8.7 独立封面入口

```http
GET /api/v1/cards/:cardId/cover
```

行为：

1. 校验访问权限；
2. 查找 `community-cover` 有效封面缓存；
3. 缓存 ready 时更新访问时间和 30 天过期时间；
4. 返回 `302 Location: <cover-cache-entry-url>`；
5. 缓存缺失时创建 `cover_miss` 渲染任务并返回 `202 text/html` 准备中封面。

## 9. 服务端校验规则

提交处理后的 `.card` 时，服务端至少校验：

1. 文件扩展名；
2. ZIP 魔数；
3. ZIP entry 路径安全，禁止 path traversal；
4. 文件数量、单文件大小、总展开大小；
5. `.card/metadata.yaml` 存在；
6. `.card/structure.yaml` 存在；
7. `.card/cover.html` 存在；
8. metadata `id` 合法；
9. metadata `name` 合法；
10. `cover_ratio` 合法；
11. content YAML 可解析；
12. `.card` 内已经外置的资源 URL 与本次 upload session manifest 一致；
13. 对象存储中资源存在；
14. sha256 与 size 匹配；
15. 用户拥有目标 room；
16. 用户配额未超限。

Worker 拉取源 `.card` 渲染时也要再次做安全校验。上传校验负责拒绝明显不合规文件；渲染校验负责保护渲染运行时。

## 10. 缓存过期规则

渲染缓存生命周期：

```text
generatedAt = 渲染成功时间
lastAccessedAt = 最近一次成功进入 viewUrl 的时间
expiresAt = lastAccessedAt + 30 天
```

首次渲染成功时：

```text
lastAccessedAt = generatedAt
expiresAt = generatedAt + 30 天
```

每次成功查看时：

```text
lastAccessedAt = now
expiresAt = now + 30 天
```

清理时：

```text
如果 expiresAt < now，则删除 chips-card-render-cache/{cardId}/{cacheVersion}/
如果 expiresAt < now，则删除 chips-card-cover-cache/{cardId}/{cacheVersion}/
```

源 `.card`、`chips-card-resources` 中的正式资源、卡片数据库记录不受该规则影响。
