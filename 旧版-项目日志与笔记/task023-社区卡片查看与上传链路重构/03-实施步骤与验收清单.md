# 实施步骤与验收清单

## 1. 实施原则

- 不开发 Web Host Runtime；
- 不做微服务架构拆分；
- 继续沿用当前 Fastify API + PostgreSQL + Redis + Worker + S3 / MinIO 的总体架构；
- `.card` 源文件永久保存；
- 渲染缓存是可删除、可重建的派生产物；
- 缓存最后一次访问后 30 天无人再次访问则删除；
- 每个阶段都要有测试和文档同步。

## 2. 阶段一：数据模型与对象存储

目标：建立源文件、渲染缓存和任务队列的数据地基。

工作项：

1. 新增 `chips-card-files` 永久源文件 bucket；
2. 新增 `chips-card-render-cache` 渲染缓存 bucket；
3. 新增 `chips-card-cover-cache` 独立封面缓存 bucket；
4. 新增或调整 `cards` 源文件字段；
5. 新增 `upload_sessions` 和 `upload_session_resources`；
6. 新增 `card_render_caches`；
7. 新增或改造 `card_render_jobs`；
8. 更新对象存储初始化与部署说明。

验收：

- `.card` 源文件有稳定 bucket/key/sha256；
- 渲染缓存有独立记录和对象路径；
- 缓存字段包含 `lastAccessedAt` 与 `expiresAt`;
- 现有 `htmlUrl` 不再作为卡片源文件字段使用；
- migration、schema、DTO 单元测试通过。

## 3. 阶段二：上传会话与源文件保存

目标：上传处理后的 `.card` 后，服务器保存永久源文件并触发渲染任务。

工作项：

1. 创建上传会话接口；
2. 资源上传目标签发接口；
3. 上传资源归属和对象 Head 校验；
4. 处理后 `.card` 提交接口；
5. `.card` 结构与安全校验；
6. 保存源 `.card` 到 `chips-card-files`；
7. 写入 `cards` 源文件字段；
8. 创建完整查看缓存渲染任务；
9. 创建独立封面缓存渲染任务。

验收：

- 上传成功后源 `.card` 永久保存；
- 上传成功后不依赖旧 `card_pipeline_jobs` 的旧语义；
- 上传成功后不要求同步生成 HTML；
- 资源 URL 必须属于本次上传会话或符合允许策略；
- 跨用户资源 URL、资源缺失、room 权限失败都有测试覆盖。

## 4. 阶段三：Worker 渲染缓存生成

目标：Worker 基于源 `.card` 生成网页查看缓存。

工作项：

1. 用新的源文件保存与渲染缓存生成职责替代旧 `runCardPipeline`；
2. Worker 从 `chips-card-files` 拉取源 `.card`；
3. Worker 使用服务器端正式 Host 渲染能力生成查看产物；
4. 只加载查看所需插件能力，富文本只加载 renderer，不加载 editor；
5. 产物写入 `chips-card-render-cache/{cardId}/{cacheVersion}/`；
6. 封面产物写入 `chips-card-cover-cache/{cardId}/{cacheVersion}/`；
7. 写入 `card_render_caches`；
8. 渲染失败写入结构化错误；
9. 同一版本键任务去重。

验收：

- 一张真实 `.card` 可生成可访问渲染缓存；
- 渲染失败不会破坏源 `.card`；
- 重复访问或重复任务不会并发生成多个相同版本缓存；
- Worker 停止不影响普通 API 启动；
- 插件缺失、资源缺失、卡片损坏都有错误态测试。

## 5. 阶段四：查看入口与访问续期

目标：用户访问缓存时自动续期 30 天。

工作项：

1. `open-view` 返回 `viewUrl`、`viewState`、`renderStatusUrl`；
2. 新增 `GET /api/v1/cards/:cardId/view`；
3. `view` endpoint 校验权限；
4. 缓存 ready 时 302 到缓存入口；
5. 缓存 ready 时更新 `lastAccessedAt` 与 `expiresAt = now + 30 days`；
6. 缓存缺失时创建渲染任务并返回 `202 rendering`；
7. `GET /api/v1/cards/:cardId/cover` 单独访问封面缓存并续期；
8. 封面缓存缺失时创建 `cover_miss` 任务，并返回可嵌入的准备中 HTML；
9. 前台支持 `cache_ready`、`rendering`、`render_error` 状态。

验收：

- 缓存存在时用户直接进入查看页面；
- 每次成功查看后 `expiresAt` 续期到 30 天后；
- 缓存缺失时前台显示准备中并轮询渲染状态；
- 私有卡片无权限访问仍按 404 处理；
- 删除或封禁卡片后 view endpoint 不再返回缓存。

## 6. 阶段五：缓存清理任务

目标：自动删除最后访问后超过 30 天的渲染缓存。

工作项：

1. 在 Worker 或独立清理进程中新增 Render Cache Cleaner；
2. 周期扫描 `expiresAt < now` 的缓存；
3. 删除前二次确认缓存没有被续期；
4. 删除对象存储目录；
5. 更新缓存记录为 `deleted`；
6. 记录删除日志和失败重试；
7. 如接入 CDN，补充 CDN purge 或 TTL 策略。

验收：

- 过期缓存会被删除；
- 未过期缓存不会被误删；
- 删除缓存不影响源 `.card`；
- 删除后再次访问会重新排队渲染；
- 并发访问和清理同时发生时，以访问续期为准。

## 7. 阶段六：前台查看页改造

目标：社区前台不再依赖 `htmlUrl`，而是通过受控 `viewUrl` 查看缓存。

工作项：

1. 更新 `CardOpenView` 类型；
2. `/cards/:cardId` 使用 `viewState` 控制 UI；
3. 缓存 ready 时 iframe 或导航到 `viewUrl`；
4. 渲染中显示准备状态并轮询 `renderStatusUrl`；
5. 渲染失败显示错误和重试入口；
6. 列表封面使用独立 `coverUrl`；
7. 移除前台对 `remote-card-file` / `community-card-file` 的当前主链路依赖。

验收：

- `htmlUrl` 为空时不影响新查看链路；
- `viewUrl` ready 时可以打开渲染缓存；
- `rendering` 时不会显示“卡片不存在”；
- `render_error` 可被拥有者识别并重试。

## 8. 阶段七：旧 pipeline 归档

目标：让旧 pipeline 不再承担“上传发布中心”的职责，并从正式源码中移出。

工作项：

1. 旧 `CardPipelineQueueService` 不再作为上传必经路径；
2. 旧 `runCardPipeline`、URL 替换和旧转换队列源码移入 `packages/server/归档/20260524-旧卡片转换流水线/`；
3. 正式 schema 导出移除 `card-pipeline-jobs`；
4. 迁移 `0003_drop_legacy_card_pipeline.sql` 删除 `card_pipeline_jobs` 与旧枚举；
5. 普通 API 不在请求内执行渲染；
6. `htmlUrl` 不参与打开判断；
7. 更新部署、运维、监控文档。

验收：

- 普通 API 不执行卡片渲染；
- Worker 停止时，源文件上传仍可成功，但查看进入 `rendering`；
- Worker 恢复后可继续消费任务；
- 旧 `htmlUrl` 字段不参与打开判断。
- 旧 pipeline 正式源码不再被 TypeScript build 或 Vitest 扫描。

## 9. 阶段八：官方上传器模块插件

目标：官方上传器不做图形化应用，作为无界面模块插件提供发布能力。

工作项：

1. 新增 `Chips-CommunityUploader-Plugin`；
2. 声明 `community.card.publish/publish` job 能力；
3. 通过 Host `card.unpack` 解包 `.card`；
4. 通过 Host `file.*` 扫描资源、读取内容、写回改写后的 YAML 和封面 HTML；
5. 通过上传会话 API 申请资源直传地址；
6. 使用签名 header 将资源直传对象存储；
7. 删除已外置资源并通过 Host `card.pack` 重新打包；
8. 提交处理后的 `.card`；
9. 补充契约、README、单元测试、build 和 validate。

验收：

- 模块不创建 UI；
- 模块不直接持有对象存储长期密钥；
- 处理后的 `.card` 不包含已外置资源；
- `content/*.yaml` 与 `.card/cover.html` 中的资源引用被替换为资源服务器 URL；
- `npm test`、`npm run build`、`npm run validate` 通过。

服务器：

- 上传会话创建；
- 资源 presign；
- 处理后 `.card` 提交；
- 源 `.card` 保存；
- 渲染任务创建；
- 渲染缓存生成；
- open-view；
- view endpoint；
- render-status；
- 缓存续期；
- 缓存清理；
- 删除清理；
- 权限校验。

前台：

- `/cards/:cardId` ready 缓存打开；
- rendering 状态轮询；
- render_error 状态展示；
- 私有卡片权限失败；
- 缓存删除后再次访问。

渲染：

- 富文本 renderer-only；
- 图片、音频、视频基础卡片；
- cover 显示；
- 外置资源加载；
- 缺失资源错误态；
- 插件版本变化触发新缓存。

端到端：

- 官方上传器上传真实 `.card`；
- 社区列表出现；
- 首次渲染完成；
- 社区详情打开缓存；
- 30 天 TTL 续期字段正确变化；
- 模拟过期清理后再次访问可重新渲染。
