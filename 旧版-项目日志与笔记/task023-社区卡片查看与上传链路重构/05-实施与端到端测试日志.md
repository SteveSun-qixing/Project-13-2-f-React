# 实施与端到端测试日志

## 1. 记录范围

本日志记录 `task023-社区卡片查看与上传链路重构` 的最终实施结果、验证结果和提交前状态。

本轮任务不在 `问题工单.md` 中记录，所有过程性方案与日志均保存在本任务目录内。

本日志最后核对时间：2026-05-26。

## 2. 关键决策回顾

本轮讨论和实施过程中，最终确定的架构口径如下：

1. `.card` 仍然是社区发布的永久源文件。
2. 官方本地上传器在用户设备上完成资源上传、资源链接替换和处理后 `.card` 打包。
3. 社区服务器接收处理后的 `.card`，不再在上传请求内做旧式转换。
4. 社区服务器保留服务器端渲染能力，但渲染产物是可删除、可重建的派生缓存。
5. 完整查看缓存和封面缓存分开保存、分开访问、分开续期。
6. 渲染缓存保存 30 天，每次成功访问后续期为“最后一次访问后 30 天”。
7. 超过 30 天无人访问的缓存由 Worker 清理，源 `.card` 不删除。
8. 不开发 Web Host Runtime。
9. 不改成微服务架构，继续沿用当前 Fastify API + PostgreSQL + Redis + Worker + S3 / MinIO 的架构。
10. 官方上传器不做图形界面，作为无界面模块插件提供发布能力。

## 3. 实施内容总览

### 3.1 数据模型和迁移

新增或调整的核心数据模型：

- `cards` 增加源 `.card` 保存字段、发布客户端字段、资源 manifest 字段；
- `upload_sessions` 保存上传会话、客户端信息、源文件保存结果和过期时间；
- `upload_session_resources` 保存本次上传会话中的外置资源记录；
- `card_render_jobs` 保存完整查看缓存和封面缓存的异步渲染任务；
- `card_render_caches` 保存渲染缓存版本、对象存储路径、状态、访问时间和过期时间。

新增迁移：

- `0002_card_source_render_cache.sql`：建立源 `.card`、上传会话、渲染任务和渲染缓存相关结构；
- `0003_drop_legacy_card_pipeline.sql`：移除旧 `card_pipeline_jobs` 表和旧流水线枚举。

### 3.2 对象存储

新增或正式启用的 bucket：

- `chips-card-files`：永久保存处理后的 `.card` 源文件；
- `chips-card-resources`：保存本地上传器外置后的正式资源；
- `chips-card-render-cache`：公开完整查看缓存；
- `chips-card-render-cache-private`：私有完整查看缓存；
- `chips-card-cover-cache`：公开封面缓存；
- `chips-card-cover-cache-private`：私有封面缓存。

本地开发环境下，公开对象 URL 直接使用 MinIO `S3_ENDPOINT` 生成，避免依赖 80 端口反向代理。

### 3.3 上传会话链路

新增正式链路：

1. `POST /api/v1/upload-sessions`
   - 创建上传会话；
   - 记录内容类型、可见性、房间、客户端名称、版本、平台和过期时间；
   - 支持 `idempotencyKey`。

2. `POST /api/v1/upload-sessions/:uploadId/resources/presign`
   - 由服务器签发本次会话资源的 S3 PUT URL；
   - 返回必须随 PUT 携带的 `content-type` 和 `x-amz-meta-*` 头；
   - 写入 `upload_session_resources`。

3. 客户端直传资源到对象存储
   - 客户端不持有对象存储长期密钥；
   - 资源服务器承接大文件带宽；
   - 社区服务器只做签发和归属校验。

4. `POST /api/v1/upload-sessions/:uploadId/card`
   - 接收已经处理好的 `.card`；
   - Head 校验资源是否已上传；
   - 校验已上传资源不再以内部文件形式留在 `.card` 中；
   - 校验 `.card` 的 metadata、structure、content 和 cover 中引用了本次已上传资源 URL；
   - 保存源 `.card` 到 `chips-card-files`；
   - 创建 `community-web` 和 `community-cover` 渲染任务。

保留兼容入口：

- `POST /api/v1/upload/card`
  - 仍然支持网页端直接上传 `.card`；
  - 上传后保存源 `.card` 并入队渲染任务；
  - 不再使用旧卡片转换流水线作为主链路。

### 3.4 渲染缓存链路

新增 `CardRenderCacheService` 作为服务器端渲染缓存服务，职责包括：

- 计算缓存版本键；
- 按卡片可见性选择公开或私有 cache bucket；
- 入队渲染任务；
- 查询 ready 缓存；
- 成功访问后续期；
- Worker 处理任务；
- 生成完整查看缓存；
- 生成独立封面缓存；
- 清理过期缓存；
- 删除卡片相关所有缓存。

缓存版本键当前由以下字段组成：

- `CARD_RENDERER_VERSION`
- `renderProfile`
- `HOST_ACTIVE_THEME_ID`
- `locale`
- `sourceCardSha256`

当前 render profile：

- `community-web`：完整卡片查看缓存；
- `community-cover`：独立封面缓存。

### 3.5 Worker

Worker 启动时执行：

1. 数据库迁移；
2. Redis 连接；
3. 对象存储 bucket 初始化；
4. Host 集成初始化；
5. 卡片查看器、图片查看器、基础卡片插件、箱子布局插件、转换模块插件和主题插件安装启用；
6. 重排 stale processing 任务；
7. 启动渲染队列消费循环；
8. 周期执行过期渲染缓存清理。

Worker 处理任务时：

- 从 `chips-card-files` 下载源 `.card`；
- `community-web` 使用 Host 模块能力转换为 HTML 目录；
- `community-cover` 只解包 `.card/cover.html` 和 `.card/cardcover/`；
- 上传产物到对应 cache bucket；
- 更新 `card_render_caches`；
- 更新卡片的 `htmlUrl` 或 `coverUrl`；
- 失败时写入结构化错误，源 `.card` 不受影响。

### 3.6 查看入口

新增和改造的查看接口：

- `GET /api/v1/cards/:cardId/open-view`
  - 返回 `viewUrl`、`viewState`、`renderStatusUrl`、`renderCache` 和 `coverUrl`；
  - 不再依赖旧 `htmlUrl` 判断卡片是否可以打开。

- `GET /api/v1/cards/:cardId/render-status`
  - 返回 `cache_ready`、`rendering` 或 `render_error`；
  - 返回最新错误信息和 `viewUrl`。

- `GET /api/v1/cards/:cardId/view`
  - 校验权限；
  - ready 时续期并 302 到完整查看缓存；
  - cache miss 时入队渲染并返回 202。

- `GET /api/v1/cards/:cardId/cover`
  - 校验权限；
  - ready 时续期并 302 到封面缓存；
  - cache miss 时入队封面渲染并返回可嵌入的准备中 HTML。

- `GET /api/v1/cards/:cardId/render-cache/:cacheVersion/*`
  - 私有完整查看缓存代理入口。

- `GET /api/v1/cards/:cardId/cover-cache/:cacheVersion/*`
  - 私有封面缓存代理入口。

### 3.7 前台查看页

社区 Web 前台已经改为：

- `CardDetailPage` 首先读取 `open-view`；
- `viewState = cache_ready` 时创建 CardViewer 插件会话；
- `viewState = rendering` 时轮询 `render-status`；
- `viewState = render_error` 时显示错误；
- `DocumentPluginRoutePage` 传入 `viewUrl` 给 CardViewer；
- 列表和详情中使用独立 `coverUrl`。

### 3.8 箱子引用

箱子解析卡片条目时不再返回旧 `communityHtmlUrl`，改为返回：

- `communityViewUrl`
- `communityRenderStatusUrl`

这样箱子条目也走新的受控查看和渲染状态链路。

### 3.10 官方上传器模块插件

新增模块插件：

`Chips-ModulePlugin/Chips-CommunityUploader-Plugin`

模块能力：

- capability：`community.card.publish`
- method：`publish`

插件职责：

1. 调用 Host `card.readInfo` 和 `card.unpack`；
2. 枚举卡片结构文件和资源文件；
3. 识别需要外置的内部资源；
4. 对富文本 `content_source=file` 的 Markdown 正文做用户设备侧内联；
5. 请求社区服务器创建上传会话；
6. 请求资源 presign；
7. 使用预签名 URL 直传资源；
8. 改写 `content/*.yaml` 和 `.card/cover.html` 中的资源链接；
9. 删除已外置的内部资源；
10. 调用 Host `card.pack` 生成处理后的 `.card`；
11. 提交处理后的 `.card` 到社区服务器；
12. 返回 `cardId`、`communityUrl` 和 `renderStatusUrl`。

插件不创建图形界面，不持有对象存储长期密钥，不直接调用社区服务器内部实现。
