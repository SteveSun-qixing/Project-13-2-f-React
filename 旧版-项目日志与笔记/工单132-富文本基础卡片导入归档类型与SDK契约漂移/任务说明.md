# 工单132 任务说明：富文本基础卡片导入归档类型与 SDK 契约漂移

## 背景

task030 antd 迁移收尾阶段执行全量 `npx tsc --noEmit` 时，`Chips-EditingEngine/src/basecard-runtime/registrations/richtext.ts` 报 `TS2322`：`richtextDescriptor` 无法赋值给 `chips-sdk` 的 `BasecardDescriptor`。该错误**非本次 antd 迁移引入**（迁移未改动该文件、未改动 chips-sdk 版本），属于既有问题，收尾任务按边界规则不做修改并登记工单。

## 证据

- `npx tsc --noEmit` 输出（Chips-EditingEngine 目录）：
  ```
  src/basecard-runtime/registrations/richtext.ts(4,14): error TS2322: Type '{ ... renderEditor: (ctx: { ... }) => () => void }' is not assignable to type 'BasecardDescriptor'.
  ```
- 错误链：`BasecardEditorContext.importArchiveBundle` 参数类型为 `BasecardArchiveImportRequest`，其 `entries` 字段为 `BasecardArchiveImportedEntry[]`；而 chips-sdk 侧 `BasecardArchiveImportRequest`/`BasecardArchiveImportResult` 的 `entries` 为 `Record<string, unknown>[]`，二者不可互相赋值。
- `git diff HEAD -- src/basecard-runtime/registrations/richtext.ts` 为空：文件与最近一次提交（41854a1c）完全一致，迁移期间未改动。
- 仓库 `package.json` 未声明 chips-sdk 依赖（工作区根依赖），antd 迁移未升级 SDK，错误在迁移前即存在。
- 同源问题还波及 BCP 依赖的 node_modules 类型链（`mdast-util-mark`、`micromark-extension-mark` 的 `ConstructName` 类型漂移），属于 Chips-BaseCardPlugin 富文本插件依赖问题。

## 影响范围

- `Chips-EditingEngine/src/basecard-runtime/registrations/richtext.ts`
- `chips-sdk` 的 `BasecardArchiveImportRequest/Result` 类型
- `Chips-BaseCardPlugin/richtext-BCP` 的 `basecardDefinition.renderEditor` 内联上下文类型
- 全量 typecheck 门禁（`npx tsc --noEmit` 无法达到 0 错误）

## 复现步骤

1. 在 `Chips-EditingEngine` 目录执行 `npx tsc --noEmit`；
2. 观察 `src/basecard-runtime/registrations/richtext.ts(4,14)` 的 TS2322 错误。

## 期望行为

- `chips-sdk` 与 BCP 双方对 `importArchiveBundle` 的输入/输出类型（`BasecardArchiveImportRequest`、`BasecardArchiveImportResult`、`BasecardArchiveImportedEntry`）口径一致（建议 SDK 侧类型对齐 BCP 的实际产物模型，或 BCP 侧改用 SDK 正式类型）；
- `npx tsc --noEmit` 全量 0 错误。

## 暂行处理

- 本次收尾不改动 BCP 文件、不改动 richtext.ts 注册类型，错误作为既有遗留疑问记录；
- 涉及 `mdast-util-mark` / `micromark-extension-mark` 的类型漂移建议在 SDK/BCP 工具链专项中一并处理（`ConstructName` 升级或声明补丁）。
