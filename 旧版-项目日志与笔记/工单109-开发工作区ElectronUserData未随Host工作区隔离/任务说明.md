# 工单109-开发工作区ElectronUserData未随Host工作区隔离

## 背景

用户需要把开发版 Host 安装或运行在虚拟环境 / 当前工作区文件夹中，避免污染电脑上已经安装的正式版 Host 与相关插件。生态公共文档已经规定 `chipsdev` 使用项目链路中的 `.chips-host-dev` 作为开发工作区，与 `chips` 的用户工作区 `~/.chips-host` 隔离。

## 证据

1. `生态共用技术文档/开发与运维/03-命令行拆分与使用指南.md` 规定 `chipsdev` 默认使用 `.chips-host-dev`，开发工作区保存开发态联调需要的全部 Host 状态，与用户工作区完全隔离。
2. `生态共用技术文档/命令行工具/02-Chips-Dev开发者命令行手册.md` 规定 `chipsdev run` 解析开发工作区 `.chips-host-dev`，并在开发工作区中安装、启用、运行插件。
3. `Chips-Host/src/main/electron/app-entry.ts`、`dev-run-app.ts`、`dev-invoke-module.ts` 已将业务工作区通过 `--workspace` 传入 Host 主进程。
4. 当前代码中未发现 `app.setPath("userData")` 或等价逻辑，Electron 默认 `userData` 仍可能写入系统应用支持目录。

## 影响范围

- `chipsdev run`
- `chipsdev module invoke`
- 带 `--workspace` 的 Electron Host 启动
- Electron Chromium 缓存、LocalStorage、Session、IndexedDB 等运行态数据
- 开发版 Host 与正式版 Host 的本机环境隔离

## 复现步骤

1. 在工作区执行 `rg -n "app\\.setPath|userData" Chips-Host/src/main Chips-Host/tests -S`；
2. 确认 Host 业务工作区解析存在，但 Electron `userData` 未绑定到该工作区；
3. 通过 `chipsdev run` 拉起真实 Electron Host，业务状态会写入 `.chips-host-dev`，Electron 应用数据目录仍由 Electron 默认规则决定。

## 期望行为

当 Host 使用显式工作区启动时，Electron `userData` 应固定到该工作区内的受控目录，例如 `.chips-host-dev/electron-user-data`。开发态 Host 的插件记录、主题配置、运行日志和 Electron 应用数据均应留在当前开发工作区内，不与正式版 Host 共享。

## 暂行处理

本轮按正式工作区模型补齐 Electron `userData` 隔离能力，并增加单元测试覆盖。不得通过手工设置全局系统目录、复制正式版数据或临时脚本绕过。

## 需要协作方

- Host 启动链路维护方
- SDK / chipsdev 工具链维护方

## 处理结果

1. 已新增 `Chips-Host/src/main/electron/workspace-paths.ts`，统一将 Electron `userData` 解析为 `<workspace>/electron-user-data`。
2. `Chips-Host/src/main/electron/app-entry.ts` 在申请 Electron 单实例锁前配置 `userData`，避免单实例锁和后续 Chromium 状态落入默认系统目录。
3. `Chips-Host/src/main/core/main-process.ts` 在进入 `app.whenReady()` 前再次配置 `userData`，覆盖开发态 runner 与普通 Electron Host 启动。
4. `Chips-Host/tests/unit/app-entry.test.ts` 与 `Chips-Host/tests/unit/main-process-lifecycle.test.ts` 已验证路径和启动顺序。
5. `Chips-Host/技术文档/08-Electron宿主化与IPC通道打通.md`、`生态共用技术文档/开发与运维/03-命令行拆分与使用指南.md`、`生态共用技术文档/命令行工具/02-Chips-Dev开发者命令行手册.md` 已同步工作区隔离口径。
6. 已执行 `npx vitest run tests/unit/app-entry.test.ts tests/unit/main-process-lifecycle.test.ts`、`npm run build`、`npm test`，均通过。
