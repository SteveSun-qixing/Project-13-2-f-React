# 工单153-工作区扫描与文件操作无Host服务动作：任务说明

## 1. 背景

Host 有 workspace 概念（config.workspace.json、launchParams.workspacePath），但没有「工作区文件树扫描、卡片/箱子识别、创建、重命名、删除」服务动作。编辑引擎本地实现全部工作区语义，社区客户端、未来文件浏览器无法复用。

## 2. 证据

- `Chips-EditingEngine/src/services/workspace-service.ts`（534 行）：buildTree 递归扫描识别（.card/ 目录、.card/.box 文件、文件夹）、HOST_RUNTIME_ROOT_ENTRIES 排除清单（硬编码 10 项 Host 运行时目录）、createCard/createBox/createFolder/renameFile/deleteFile；
- 卡片重命名直接在应用侧改写 `.card/metadata.yaml`（本地 YAML 序列化，即重复实现证据 #3 的第三份副本）；
- Host 动作注册表：无 workspace 域；
- 工作区根路径仅经 launchParams.workspacePath 透传，无服务语义。

## 3. 影响范围

- Chips-Host file/workspace 语义、Chips-EditingEngine workspace-service；
- 未来文件管理类软件、社区客户端工作区浏览。

## 4. 复现步骤

1. 编辑引擎文件管理器扫描工作区，观察识别/排除逻辑全部在应用内；
2. 检索 Host 动作，无 workspace.scan 或等价能力；
3. 确认卡片重命名在应用侧直接写 YAML。

## 5. 期望行为

Host 提供工作区动作：

- `workspace.scan`：递归扫描、结构化树输出（含 metadata 摘要、Host 运行时目录排除）；
- `workspace.createCard / createBox / createFolder`：创建并登记到树（复用 card.init / box.create）；
- `workspace.rename / delete`：文档级改名（改写 metadata + 重打包）与删除；
- 编辑引擎 workspace-service.ts 收缩为「订阅 Host 扫描结果 + 本地视图缓存」，不再拼 YAML；
- 冻结排除清单与卡片目录识别规则为公共契约（与工单152 联动）。

## 6. 暂行处理

无。本工单由 task034 迁移任务 M6 直接修复。

## 7. 需要协作方

Chips-Host 服务域维护方、Chips-SDK 维护方、Chips-EditingEngine 维护方。

## 8. 处理结果（2026-08-11，M6 完成）

- Host 新增 `workspace.scan` 动作（`packages/workspace-service/`），识别规则（卡片目录 .card/metadata.yaml、.card/.box 文件、文件夹）与 Host 运行时目录排除清单冻结为公共契约；箱子 metadata 经注入 box-service 读取（解耦）；
- `card.init` 契约扩展支持指定 cardId；
- SDK 新增 WorkspaceApi.scan；route-manifest 同步；
- 编辑引擎 workspace-service 扫描/创建卡片改走 Host 动作，本地识别逻辑删除；
- 验证：Host workspace 契约测试 6 用例 + SDK + 编辑引擎消费测试 5 用例全部通过；
- 详情见 `task034-编辑引擎能力整合/16-M6实施记录.md`。
