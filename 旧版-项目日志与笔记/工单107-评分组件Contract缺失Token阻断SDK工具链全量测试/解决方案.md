# 工单107解决方案：评分组件 Contract 缺失 Token 阻断 SDK 工具链全量测试

## 1. 解决状态

- 状态：已闭环。
- 解决提交：`92023563 修复工单107评分组件主题契约与Token缺口`
- 复核日期：2026-05-26

本方案是工单107的过程性闭环方案，归档在工单文件夹内；评分组件对外 contract 与 token 的正式口径以组件库 contract、组件库 token 源文件、两个官方主题包 token 文件和生态共用组件规范为准。

## 2. 根因

`Chips-ComponentLibrary/packages/theme-contracts/contracts/components/rating.contract.json` 已作为正式组件 contract 进入 `chipsdev component gallery` 质量门禁，但组件库 token 构建产物和官方主题包缺少该 contract 声明的 14 个 `chips.comp.rating.*` required token。

因此 `cd Chips-SDK && npm test` 在 `run-cli-tooling-tests.cjs` 的 `chipsdev component gallery --json` 断言处失败，表现为：

- `summary.status = "failed"`
- `summary.missingRequiredTokenCount = 14`
- 失败组件为 `rating`

## 3. 修复原则

1. 不从正式 gallery 中移除评分组件，不把已公开 contract 降级为草稿。
2. 让 contract、组件库 token 源、官方主题包 token 和测试门禁同向收口。
3. 不在 SDK tooling 测试中绕过 `rating`，继续让 `chipsdev component gallery` 作为正式漂移门禁。
4. 新增测试覆盖 contract/token 映射，防止以后组件 contract 新增后 token 源未同步。

## 4. 落地内容

### 4.1 组件库 contract

文件：

- `Chips-ComponentLibrary/packages/theme-contracts/contracts/components/rating.contract.json`

正式声明：

- `component: "rating"`
- `scope: "rating"`
- parts：`root`、`label`、`item`、`icon`、`status`
- states：`idle`、`hover`、`focus`、`active`、`disabled`、`loading`、`error`
- required tokens：
  - `chips.comp.rating.root.gap`
  - `chips.comp.rating.item.size`
  - `chips.comp.rating.item.radius`
  - `chips.comp.rating.item.surface.idle`
  - `chips.comp.rating.item.surface.hover`
  - `chips.comp.rating.item.surface.active`
  - `chips.comp.rating.item.surface.disabled`
  - `chips.comp.rating.icon.color.idle`
  - `chips.comp.rating.icon.color.active`
  - `chips.comp.rating.icon.color.heart-active`
  - `chips.comp.rating.icon.color.disabled`
  - `chips.comp.rating.label.color`
  - `chips.comp.rating.status.color.error`
  - `chips.comp.rating.focus.outline`
- a11y 约束：
  - 根节点按 `radiogroup` 语义必须具备 `aria-label` 或 `aria-labelledby`；
  - item 按 `radio` 语义必须具备 `aria-checked`。

### 4.2 组件库 token 源

文件：

- `Chips-ComponentLibrary/packages/tokens/tokens/comp/rating.json`

补齐 `chips.comp.rating.*` token 源，并让 `npm run build:tokens` 生成后的 dist JSON 可以解析所有 rating required token。

### 4.3 官方主题包 token

文件：

- `ThemePack/Chips-default/tokens/comp/rating.json`
- `ThemePack/Chips-theme-default-dark/tokens/comp/rating.json`
- `ThemePack/Chips-default/contracts/theme-interface.contract.json`
- `ThemePack/Chips-theme-default-dark/contracts/theme-interface.contract.json`

默认主题与暗色默认主题同步 rating token，使主题包随包 contract 与组件库正式 contract 等值，并避免 Host / SDK 质量门禁在官方主题场景下继续报告 missing required token。

### 4.4 组件库导出与测试

涉及文件：

- `Chips-ComponentLibrary/packages/components/src/index.js`
- `Chips-ComponentLibrary/packages/components/src/index.d.ts`
- `Chips-ComponentLibrary/packages/components/tests/index.test.mjs`
- `Chips-ComponentLibrary/packages/theme-contracts/tests/component-contract.test.mjs`
- `Chips-ComponentLibrary/packages/testing/src/component-quality-matrix.js`

收口内容：

- `COMPONENT_TOKEN_MAP.rating` 包含全部 14 个 required token；
- `buildComponentContract("rating")` 能返回稳定 parts、states、tokens 与 a11y 规则；
- `ChipsRating` 渲染节点使用 `data-scope="rating"`、`data-part` 与标准状态；
- 组件质量矩阵纳入 `rating` 的 radiogroup a11y fixture。

## 6. 防回归要求

- 以后新增或修改正式 component contract 时，必须同步组件库 token 源、官方主题包 token、组件导出的 `COMPONENT_TOKEN_MAP` 与 contract 测试。
- 不允许在 SDK tooling 测试中为单个组件硬编码跳过 required token 缺口。
- 官方主题包随包 contract 必须继续与组件库正式 contract 在 `component/scope/parts/states/requiredTokens/optionalTokens` 上保持等值。
- 若未来 rating contract 扩展文字颜色推荐、半星、只读态等新 token，应按“contract -> 组件库 token -> 官方主题 token -> 测试门禁”的顺序一次性同步。
