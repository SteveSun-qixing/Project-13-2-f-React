# 工单104：platform.openFile 文件过滤器契约缺口阻断设置面板 Domain API 收口

## 背景

任务028要求 `Chips-EcoSettingsPanel` 的治理能力消费 SDK/Bridge 正式接口，避免业务应用直接拼接 Host action。设置面板当前在插件包、主题包安装场景中仍直接调用 `client.invoke("platform.dialogOpenFile")`，并传递文件过滤器和打开文件/目录属性。

## 证据

- `Chips-EcoSettingsPanel/src/shared/runtime/settings-runtime-service.ts` 的 `openPluginFileDialog()` 直接调用 `client.invoke("platform.dialogOpenFile")`。
- `Chips-SDK/src/api/platform.ts` 已有 `client.platform.openFile(options)`，但 `PlatformDialogFileOptions` 没有 `filters` 字段。
- `Chips-Host/packages/pal/src/types.ts` 的 `DialogFileOptions` 同样没有 `filters` 字段。
- `Chips-Host/packages/pal/src/node-adapter.ts` 的 Electron `showOpenDialog` 调用没有转发 `filters`。
- `生态共用技术文档/协议与接口标准/05-系统接口标准.md` 仍把 `filters/properties` 作为系统打开对话框 options 的公共描述。

## 影响范围

- 设置面板无法在保留文件过滤行为的同时完全迁移到 SDK Platform Domain API。
- 新应用可能复制裸 `client.invoke("platform.dialogOpenFile")` 调用，扩大 Host action 字符串在业务层散落的问题。
- SDK、Host/PAL 与公共文档对文件选择器参数的正式口径不一致。

## 复现步骤

1. 查看 `SettingsRuntimeService.openPluginFileDialog()`，确认裸 `client.invoke("platform.dialogOpenFile")` 调用。
2. 查看 SDK `PlatformDialogFileOptions`，确认缺少 `filters`。
3. 查看 PAL `DialogFileOptions` 与 `NodePALSelection.openFile()`，确认缺少 `filters` 类型与 Electron 转发。
4. 查看公共系统接口标准，确认文档声称打开文件对话框支持 `filters/properties`。

## 期望行为

- SDK `client.platform.openFile()` 正式支持 `filters`，并通过 `mode: "file-or-directory"` 表达插件包目录或 manifest 文件均可作为输入的治理场景；
- Host PAL 类型和 Electron 实现转发 `filters`；
- 设置面板通过 `client.platform.openFile()`、`client.platform.showConfirm()`、`client.platform.showMessage()`、`client.platform.shellShowItemInFolder()` 消费平台能力；
- 公共文档与 SDK 内部文档同步，后续应用迁移不再需要裸 Host action。
