# task029 设计方案：箱子内嵌卡片与统一上传链路

**版本**：1.0.0  
**日期**：2026-08-06  
**状态**：设计冻结（各仓库按此实现）

---

## 1. 设计目标

1. 箱子支持内嵌卡片（`.card` 直接放在 `.box` 根目录），支持混合模式（一部分 URL 引用、一部分内嵌）；
2. 箱子上传与卡片上传共用 `card-transfer` 控制面链路，字节走对象存储直传；
3. 上传箱子时自动收集"散落卡片"（structure.yaml 中 `file://` 指向的本地卡片）一并上传；网络资源卡片（http/https）跳过；
4. 社区服务器保留 `.box` 源文件到对象存储，不再删除；
5. 社区箱子详情页与卡片引用正常展示、可打开。

---

## 2. 内嵌卡片格式设计（格式层）

### 2.1 包结构

`.box` 允许在**根目录或任意层级**存放 `.card` 文件：

```
Travel.box
├── .box/
│   ├── metadata.yaml
│   ├── structure.yaml
│   ├── content.yaml
│   └── cover.html
├── cards/
│   ├── day-01.card        # 内嵌卡片（任意层级）
│   └── day-02.card
└── assets/                # 箱子自身资源（不变）
```

约束：

1. 允许 `.card` 文件进入包内；
2. **禁止 `.box` 文件进入包内**（防止无限嵌套）；
3. 内嵌卡片保持 ZIP Store 模式；
4. 内嵌卡片在包内路径不限层级。

### 2.2 条目引用模型（structure.yaml）

条目 `url` 字段支持两种形态，**其余字段不变**：

| 形态 | 表达 | 示例 |
|---|---|---|
| 外部引用 | 绝对 URL（现有白名单） | `file:///Users/name/Cards/day-01.card`、`https://example.com/card.card` |
| 内嵌引用 | 包内相对路径（新增） | `cards/day-01.card`、`day-01.card` |

**判定规则**：`url` 不以 `[a-z][a-z0-9+.-]*://` 形式开头时，视为包内相对路径（内嵌引用）；必须以 `.card` 结尾。

**校验规则**：

1. 内嵌路径必须是包内存在的文件（打包/解析时对照 knownFiles 校验）；
2. 内嵌路径禁止 `..` 穿越、禁止绝对路径开头 `/`；
3. `content_type` 快照字段仍为 `chips/card`；
4. 摘要 `snapshot` 的 `document_id` 与卡片 `metadata.card_id` 对应，用于社区端匹配。

### 2.3 不引入新字段

不新增 `internal`/`embedded` 等位置字段；判定完全由 url 形态决定，保持"URL 唯一定位模型"的语义统一。

## 3. Host 消费链路设计（Host 侧）

### 3.1 校验放开

`box-service.ts` `validateZipEntries`：

- 删除 `.card` 禁令（保留 `.box` 禁令）；
- 保留 STORE 校验、必需 4 文件校验。

### 3.2 条目解析

`normalizeEntries`：

- 识别内嵌路径（不以 scheme 开头 → 相对路径）；
- 校验相对路径格式（`.card` 结尾、无 `..`、无前导 `/`）；
- 校验包内存在性（knownFiles，仅 archive 形态；directory 形态对照目录文件集合）。

### 3.3 运行时解析

`resolveEntryLocator`：内嵌路径 → 解析为解包目录内的绝对路径（`path.join(extractedDir, relativePath)`），后续按本地卡片分支处理（readCardInfo / renderCover / openCardFile 全部复用）。

影响动作：`readEntryDetail.documentInfo/status`、`renderEntryCover`、`resolveEntryResource(documentFile)`、`openEntry`。

### 3.4 打包

`loadDirectoryPackage`（pack 输入）与 `zip.compress` 的 `collectFiles` 已递归收集全部目录文件，内嵌卡片放在工作目录任意位置即可被打包；只放开校验即可。

## 4. 编辑引擎设计

`Chips-EditingEngine/src/services/box-document-service.ts`：

1. `serializeEntry`：`url` 直接序列化（内嵌路径原样写入），无需改动序列化结构；
2. 新增动作 `addEmbeddedCard`（或等价命名）：把本地 `.card` 文件复制到箱子会话工作目录根目录，并登记一条内嵌条目（url = 相对路径，snapshot 摘要从卡片读取）；
3. `box.pack` 打包时内嵌卡片自动进入 `.box`（collectFiles 递归）。

## 5. 社区服务器存储设计

### 5.1 数据模型对齐（修复漂移）

`packages/server/src/types/box.ts` 对齐正式格式：

```ts
interface BoxMetadata {
  chip_standards_version: string;
  box_id: string;              // 原错误使用 id
  name: string;
  created_at: string;
  modified_at: string;         // 原错误使用 updated_at
  active_layout_type: string;  // 原错误使用 layout_plugin
  cover_ratio?: string;
  description?: string;
  tags?: Array<string | string[]>;
  cover_asset?: string;
}

interface BoxEntryRef {
  entry_id: string;
  url: string;
  enabled: boolean;
  snapshot?: {
    document_id?: string;
    title?: string;
    summary?: string;
    tags?: Array<string | string[]>;
    cover?: { mode: 'asset' | 'runtime' | 'none'; asset_path?: string; mime_type?: string; width?: number; height?: number };
    last_known_modified_at?: string;
    content_type?: string;
  };
  layout_hints?: Record<string, unknown>;
}

interface BoxStructure {
  entries: BoxEntryRef[];      // 原错误使用 cards
}
```

`BoxService`：

- `create` 读取 `box_id` / `active_layout_type` / `modified_at`；`boxFileId` / `layoutPlugin` 正确落库；
- `unpackBox` 补充 `content.yaml` 与 `cover.html` 存在性校验（对齐 Host 4 必需文件）；
- `enrichCardRefs` 改为遍历 `structure.entries`，用 `snapshot.document_id`（或内嵌卡片的 `metadata.card_id`）匹配 `cards.cardFileId`，返回 `communityCardId / communityViewUrl / communityRenderStatusUrl`；同时为内嵌条目返回 `embedded: true` 与包内路径。

### 5.2 boxes 表扩展（保留源文件）

新增字段：

```sql
source_box_bucket text,
source_box_key text,
source_box_url text,
source_box_sha256 text,
source_box_stored_at timestamptz,
```

并新增对象存储 bucket：`chips-box-files`（内部读，同 `chips-card-files` 私有）。

### 5.3 BoxService.create 新形态

签名调整为接收"源对象信息 + 解包解析结果"（metadata/structure/content），不再从 multipart 临时文件解包；源 `.box` 由 transfer 控制面保存到对象存储，create 负责：

1. 解析并校验正式格式；
2. 落库（含 source_box_* 字段）；
3. 封面 URL 落地：若 `cover_asset` 存在，生成 `chips-covers/boxes/{boxId}/cover.ext` 对象并写入 `coverUrl`（对象复制由控制面完成，见 6.4）。

## 6. 统一上传链路设计（控制面）

### 6.1 会话模型

复用 `/api/v1/card-transfer/*`，`contentType: 'box'`：

**创建上传会话** `POST /api/v1/card-transfer/upload-sessions`

```json
{
  "contentType": "box",
  "fileName": "Travel.box",
  "roomId": null,
  "idempotencyKey": "client-key",
  "client": { "name": "...", "version": "0.1.0", "platform": "darwin" }
}
```

响应增加 `boxFile` 目标：

```json
{
  "data": {
    "uploadId": "uuid",
    "boxId": "uuid",
    "versionId": "uuid",
    "expiresAt": "...",
    "resourcePrefix": "boxes/{boxId}/versions/{versionId}",
    "boxFile": {
      "bucket": "chips-box-files",
      "objectKey": "boxes/{boxId}/versions/{versionId}/box.box",
      "publicUrl": "https://file.example/chips-box-files/boxes/{boxId}/versions/{versionId}/box.box"
    }
  }
}
```

- 同一路由按 `contentType` 分流；card 走原逻辑，box 走新逻辑；
- 上传会话 `clientMetadata` 增加 `transferKind: 'box-source'`、`boxId`。

**预签名** `POST .../objects:presign`：支持 `role: 'box-file'`（单对象，key 固定为 boxFile.objectKey）。

**完成** `POST .../complete`（JSON，非 multipart）：

```json
{
  "title": "2026 旅行箱",
  "boxFileId": "b1C2d3E4f5",
  "layoutPlugin": "chips.layout.grid",
  "coverRatio": "3:4",
  "boxFile": { "bucket": "chips-box-files", "objectKey": "boxes/.../box.box", "publicUrl": "...", "sizeBytes": 2048, "mimeType": "application/vnd.chips.box+zip" },
  "metadata": {},
  "structure": {},
  "content": {}
}
```

服务器行为：

1. `assertTransferSessionMetadata` 支持 box 会话；
2. `assertUploadedObject` 校验 box 对象归属与大小；
3. `BoxService.create` 落库（保留源对象信息）；
4. 封面资源复制：若 `metadata.cover_asset` 存在，从客户端提交的 cover 资源对象（见 6.3）复制为 `chips-covers/boxes/{boxId}/cover.{ext}`；
5. 返回 `boxId / status / communityUrl / boxViewUrl`。

**中止**：同现有 abort。

### 6.2 传输模块 `uploadBox`（客户端）

`Chips-ModulePlugin/Chips-CommunityUploader-Plugin` 新增能力 `uploadBox`（挂在现有 capability `community.card.transfer` 下）：

流程：

1. **inspect**：`box.inspect` 读取 metadata/structure/content；
2. **unpack**：`box.unpack` 到工作目录；
3. **收集散落卡片**：遍历 `structure.entries`：
   - `url` 为包内相对路径（内嵌）→ **跳过**（跟随箱子本体）；
   - `url` 为 `http(s)://` 或 `webdav://`（网络资源卡片）→ **跳过**；
   - `url` 为 `file://` → **收集**：文件存在则加入待上传列表，读取卡片 `card_id` 与标题做摘要；
4. **上传散落卡片**：对每个收集到的卡片调用 `uploadCommunityCard`（复用现有完整链路），得到 `communityCardId / communityUrl`，维护 `document_id → communityCardId` 映射；
5. **装箱**：`structure.yaml` **保持原始引用不变**（file:// 本地引用、内嵌相对路径、网络 URL 均原样保留）。社区匹配关系由服务器 `enrichCardRefs` 按 `snapshot.document_id` 动态提供（`communityCardId / communityViewUrl`），**不在上传时改写箱子文件内容**——改写会导致下载回来的箱子引用社区网页 URL 而非本地卡片文件，卡片查看器无法解析封面；
6. **上传箱子本体**：创建 box 上传会话 → 预签名 `box-file` → 直传对象存储 → complete（提交 metadata/structure/content JSON + box 对象位置）；
7. 返回 `boxId / communityUrl / uploadedCards[] / skippedCards[]`。

**注意**：散落卡片上传与箱子本体上传顺序上先传卡片再传箱子，保证服务器解析箱子时引用卡片已存在。

### 6.3 封面资源

客户端在 `complete` 时可选提交 `coverResource`（来自 `metadata.cover_asset` 或 `assets/previews` 首图，上传为 `chips-covers/boxes/{boxId}/cover.{ext}`）；服务器把 `coverUrl` 指向该对象。

### 6.4 SDK

`Chips-SDK/src/api/community-card-transfer.ts` 增加：

```ts
client.communityCardTransfer.uploadBox({ boxFile, server, publish, workspace })
// → { boxId, communityUrl, uploadedCards, skippedCards }
```

## 7. 社区查看设计

### 7.1 服务器 DTO

- `Box Detail`（`GET /api/v1/boxes/:boxId`）：
  - `metadata` / `structure` 返回正式格式解析结果；
  - `cards` 为 `enrichCardRefs` 输出：`{ url, entry_id, document_id, title, cover_url, content_type, embedded, communityCardId, communityViewUrl, communityRenderStatusUrl }`；
  - `documentUrl` 落地：返回社区只读箱子文档 URL（`/api/v1/boxes/:boxId/view`，见 7.2）。

### 7.2 社区箱子只读文档（documentUrl 落地）

- 新增 `GET /api/v1/boxes/:boxId/view`：服务端根据已保存 metadata/structure 生成只读箱子文档 HTML（展示箱子名称、描述、条目列表；条目为社区卡片时提供社区卡片链接；内嵌条目提供包内路径说明），浏览器可直接访问；
- `BoxService.create` 时把 `documentUrl` 写为 `/api/v1/boxes/{boxId}/view`；
- 该文档为工单097 的暂行正式文档源；Host Web 导出能力补齐后替换为 `box.renderLayoutFrame` 输出。

### 7.3 Web 端

- `BoxDetailPage` 保持 CardViewer 统一承载链路，`documentUrl` 落地后即可正常显示；
- `WorkTile` 箱子封面渲染保持 img 分支（coverUrl 落地后显示封面）。

## 10. 边界与不做项

1. 不做 Host render session Web 导出（工单097 长期项），documentUrl 用只读文档暂行；
2. 不做箱子渲染缓存 Worker（卡片同款 view/cover 渲染队列），封面用 cover_asset 复制方案；
3. 不做箱子下载会话（工单121 一并收口，本任务只保证源文件保留）；
4. 不做布局插件端"内嵌条目"特殊展示（布局插件消费的是 Host 归一后的条目数据，无需感知 url 形态）。
