# 工单100：SDK 正式测试脚本遗漏 Domain API 单元测试导致契约漂移不可见

## 背景

执行 `task022/任务010-SDK-DomainAPI补齐与类型同步` 时，子代理勘察与主线验证共同确认：`Chips-SDK` 中已有 `tests/client.test.ts`、`tests/card.test.ts`、`tests/resource.test.ts`、`tests/route-manifest.test.ts`、`tests/tooling/contract-drift.test.ts` 等 Vitest 测试，但 `package.json` 的正式 `npm test` 只串行执行 CLI 与脚手架集成脚本。

这意味着 SDK Domain API wrapper 的 payload、返回 envelope 解包、错误校验和 route manifest 漂移测试不会随正式 `npm test` 自动执行。

## 证据

- `Chips-SDK/package.json` 原 `scripts.test` 只包含：
  - `tests/run-cli-smoke-tests.cjs`
  - `tests/run-cli-host-managed-tests.cjs`
  - `tests/run-cli-create-workspace-tests.cjs`
  - `tests/run-cli-create-card-workspace-tests.cjs`
  - `tests/run-cli-create-layout-workspace-tests.cjs`
  - `tests/run-cli-create-module-workspace-tests.cjs`
  - `tests/run-cli-module-invoke-tests.cjs`
  - `tests/run-cli-package-compatibility-tests.cjs`
- 任务010 已新增或更新多个 SDK Domain API wrapper，如果只执行原 `npm test`，不会覆盖这些 wrapper 的单元行为。
- `Chips-SDK/tests/tooling/contract-drift.test.ts` 也不会被正式测试脚本执行，导致 route manifest 漂移在正式门禁中不可见。

## 影响范围

- `Chips-SDK/package.json`
- `Chips-SDK/tests/client.test.ts`
- `Chips-SDK/tests/card.test.ts`
- `Chips-SDK/tests/resource.test.ts`
- `Chips-SDK/tests/route-manifest.test.ts`
- `Chips-SDK/tests/tooling/contract-drift.test.ts`
- SDK Domain API 与 Host route manifest 的长期一致性门禁

## 复现步骤

1. 进入 `Chips-SDK`；
2. 查看 `package.json` 的 `scripts.test`；
3. 确认脚本未调用 `vitest run tests/client.test.ts tests/card.test.ts tests/resource.test.ts tests/route-manifest.test.ts tests/tooling/contract-drift.test.ts`；
4. 修改 SDK Domain API wrapper 后执行 `npm test`，原脚本无法覆盖 wrapper 单元断言。

## 期望行为

- `cd Chips-SDK && npm test` 必须先执行 SDK Domain API 与 route manifest 契约 Vitest；
- 通过后再执行 CLI 与脚手架集成测试；
- 后续新增 SDK wrapper 时，正式测试门禁能够自动捕获 payload、返回解包、错误校验和 route manifest 漂移。

## 暂行处理

- 已按用户要求登记工单后直接修复；
- 修复方向为把 Vitest Domain API / route manifest 契约测试加入 `Chips-SDK/package.json` 的正式 `npm test` 前置阶段。

## 需要协作方

- SDK 维护方
- chipsdev CLI 维护方
- Host route manifest 契约维护方

## 处理结果

- `Chips-SDK/package.json` 的 `npm test` 已改为先运行：
  - `tests/client.test.ts`
  - `tests/card.test.ts`
  - `tests/resource.test.ts`
  - `tests/route-manifest.test.ts`
  - `tests/tooling/contract-drift.test.ts`
- 原 CLI 与脚手架集成脚本继续保留在同一条正式测试链路中。
