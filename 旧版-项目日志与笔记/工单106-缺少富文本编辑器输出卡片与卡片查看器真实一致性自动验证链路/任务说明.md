# 工单106：缺少富文本编辑器输出卡片与卡片查看器真实一致性自动验证链路

## 背景

`任务034-富文本编辑器应用迁移` 的验收标准要求富文本编辑器输出的 `.card` 能由卡片查看器正常打开。当前富文本编辑器自身已经可以通过 SDK `card.pack/unpack` 风格的保存与重新打开测试证明产物结构正确，但这仍不是 CardViewer/Host 文档窗口真实链路的端到端验证。

## 证据

1. `Chips-RichTextEditor/tests/unit/card-persistence.test.ts` 已验证保存后重新打开、`base.richtext` 配置、Markdown 资源和 `manifest.resources`。
2. `Chips-CardViewer/src/components/CardWindow.tsx` 通过 `client.document.window.render(filePath)` 渲染文件。
3. `Chips-SDK/src/api/document.ts` 对 `.card` 的正式路径是 `document.window.render -> card.compositeWindow.render(...)`。
4. 当前未发现“生成 RichTextEditor `.card` -> 交给 CardViewer/Host document window -> 等待 ready”的自动 smoke 脚本。

## 影响范围

- `Chips-RichTextEditor` 任务034真实跨应用验收；
- `Chips-CardViewer` 对新应用输出的 `.card` 回归覆盖；
- Host 文档窗口、复合卡片窗口和基础卡片渲染链路；
- 后续所有应用迁移任务中“输出文件可被查看器打开”的验收证据。

## 复现步骤

1. 进入 `Chips-RichTextEditor`，运行正式验证脚本，确认本应用自身通过。
2. 检查 `Chips-CardViewer` 测试，确认没有消费 RichTextEditor 新产物的测试夹具。
3. 检查 SDK document API，确认真实查看链路需要 Host/iframe runtime 才能证明 ready/error 事件。

## 期望行为

提供正式跨应用 smoke：

1. 生成一个包含单 `base.richtext` 节点的 `.card`；
2. 通过 CardViewer 或 Host `document.window.render` 渲染；
3. 等待 `chips.composite:ready`；
4. 断言无 fatal error、无 node error；
5. 覆盖内联正文与 Markdown 文件资源两种模式。

## 暂行处理

任务034先在 RichTextEditor 内部补齐保存、重新打开、资源引用与非法结构拒绝测试，并将该跨应用真实窗口 smoke 缺口登记为独立工单。

## 关闭说明

用户确认：需要由卡片查看器真实打开时可以手动操作；只要富文本编辑器按卡片文件结构保存信息即可，不应把缺少跨应用自动 smoke 视为本任务阻塞问题。

任务034已将处理重点调整为富文本编辑器自身保存前结构校验：

1. 保存前校验 `.card/metadata.yaml`、`.card/structure.yaml`、`.card/cover.html` 与 `content/<baseCardId>.yaml`；
2. 校验复合卡片只有一个 `base.richtext` 节点；
3. 校验富文本基础卡片配置符合 Markdown schema，`inline/file` 模式互斥；
4. 校验资源路径只使用卡片根目录相对路径，不写入绝对路径、`blob:`、`data:` 或 `content/` 目录；
5. 校验 `manifest.resources` 与富文本配置引用的资源一致，并确认清单资源文件已存在；
6. 保存候选不符合上述结构时，在 `client.card.pack(...)` 前阻断保存。
