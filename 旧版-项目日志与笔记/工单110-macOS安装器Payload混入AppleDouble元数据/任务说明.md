# 工单110-macOS安装器Payload混入AppleDouble元数据

## 背景

任务055进入 Host macOS 正式安装器产物验收阶段后，真实执行 `npm run build:installer:macos` 已能生成 `Chips.app` 与 `.pkg`。继续检查 `.pkg` payload 时，发现安装包内混入大量 `._*` AppleDouble 元数据文件。

## 证据

验证命令：

```bash
pkgutil --payload-files release-artifacts/task055-stage4-macos-installer-20260526/Chips-Host-0.1.0-macos.pkg | rg '/\._|^\._'
```

典型输出包含：

- `./Applications/Chips.app/Contents/MacOS/._Chips`
- `./Applications/Chips.app/Contents/Resources/._electron.icns`
- `./Applications/Chips.app/Contents/Resources/app/dist/packages/.../._index.js`

这些文件不是工作区真实文件，而是 macOS 打包工具把扩展属性 / 资源叉写入 payload 后形成的 AppleDouble 副本。

## 影响范围

- `Chips-Host/src/main/installer/macos-installer.ts`
- Host macOS `.pkg` 正式发布包
- 任务055安装打包发布链路验收

## 复现步骤

1. 进入 `Chips-Host`；
2. 执行 `npm run build:installer:macos -- --output=../release-artifacts/task055-stage4-macos-installer-20260526`；
3. 执行 `pkgutil --payload-files ../release-artifacts/task055-stage4-macos-installer-20260526/Chips-Host-0.1.0-macos.pkg | rg '/\._|^\._'`；
4. 观察 payload 中存在 `._*` AppleDouble 文件。

## 期望行为

Host 安装器 payload 只包含正式 `Chips.app` 运行时、内置插件、运行依赖、Info.plist、postinstall 等必要文件，不包含 AppleDouble `._*`、`.DS_Store`、`CodeResources` 等复制元数据。

## 处理结果

1. `macos-installer.ts` 已在 component pkg 生成后展开 `Payload`，用 `cpio` 还原 payload 内容并重新生成 gzip payload 与 BOM，移除 `._*`、`.DS_Store`、`CodeResources` 等复制元数据。
2. `sanitizeFlatProductArchive` 已改为普通 `pkgutil --expand/--flatten`，避免最终 product archive 整理阶段再次深度展开组件包并重新污染 payload。
3. `defaultRunCommand` 支持调用级 `env` 叠加，`pkgbuild/productbuild` 仍显式携带 `COPYFILE_DISABLE=1` 作为辅助约束。
4. `macos-installer.test.ts` 已增加真实 macOS `.pkg` 净化测试，构造带扩展属性的最小 app bundle 并断言最终 `pkgutil --payload-files` 不含 AppleDouble 条目。
5. 任务055.06离线展开最终 product archive 时，补充发现 component pkg 的 `Scripts/` 目录仍可能残留 `._postinstall`；现已在 component pkg 和最终 product archive flatten 前递归清理展开包目录，确保非 payload 元数据也被移除。
