# 旧主工作区架构调整清单

旧主工作区 `develop` 的新增提交中包含若干已经越过“单点功能修复”的架构调整。迁移时必须把这些调整作为正式输入逐项核对，并融合到当前 worktree 的新架构中。

| 架构调整 | 旧源码证据 | 当前融合落点 |
|---|---|---|
| `CardViewerSource` 结构化来源模型 | `Chips-CardViewer/src/types/viewer-source.ts`、`Chips-SDK/src/types/card-viewer.ts` | `Chips-SDK` 公共类型、`Chips-CardViewer` 启动解析、Host 文件关联和社区 Web 插件路由统一使用 `launchParams.cardSource`。 |
| `document.window` 统一文档窗口事件补齐 | `Chips-SDK/src/api/document.ts` | 在当前 `client.document.window.render/onReady/onError/onNodeError/onResourceOpen` 基础上补齐 resize 订阅和 iframe 文档类型标记，不丢失当前新架构已存在的 node-error 链路。 |
| Host 打开入口改传结构化来源 | `Chips-Host/packages/card-open-service/src/card-open-service.ts`、`Chips-Host/src/main/core/file-association.ts` | `card.open`、`.card` 和 `.box` 文件关联向查看器传递 `cardSource`，`targetPath/fileOpenMode` 仅作为旧输入识别，不再作为新主口径。 |
| CardViewer 来源、舞台和壳层职责拆分 | `ViewerSourceProvider.tsx`、`ViewerStage.tsx`、`ViewerChrome.tsx`、旧 `App.tsx` | 不恢复旧单体 `App.tsx`。将来源解析并入当前 `AppRuntimeProvider`，将舞台选择并入 `scene-registry/AppShell`，将壳层动作并入当前 `CardViewerShell`、Scene action slot 和 command 体系。 |
| 查看器封面来源与封面 surface | `ViewerCoverSurface.tsx/css`、`ViewerSourceProvider.tsx`、相关测试 | 在当前 CardViewer Scene/runtime 内实现 cover/content 模式，封面 iframe 使用组件库 `EmbeddedDocumentFrame`，比例校验和面积归一逻辑迁移到新组件并接入主题 token 与 i18n。 |
| 社区 Web 文档插件路由与宿主 | `DocumentPluginRoutePage.tsx`、`HostedPluginSurface.tsx`、社区详情页改造 | 融合到当前社区 Web 插件宿主，不恢复旧自研查看页；通过 `cardSource` 启动 `com.chips.card-viewer`，由 `plugin.surface.resize` 驱动 document 模式高度。 |
| 社区源 `.card`、渲染缓存和上传会话 | `card-render-cache.service.ts`、`upload-session.service.ts`、`card-render.ts`、`upload-sessions.ts`、worker | 以永久源 `.card`、资源 manifest、渲染任务、可重建 view/cover 缓存和 worker 为最终架构，旧 pipeline 只作为被替代历史归档。 |
| 社区上传模块插件 | `Chips-ModulePlugin/Chips-CommunityUploader-Plugin` | 用当前模块插件脚手架和模块能力契约重建，不直接复用旧导出结构或旧本地 pipeline。 |
| BookReader iframe 键盘接管 | `Chips-BookReader/src/interaction/interaction-manager.ts` | 融合进当前 `InteractionManager.attachToFrame`，保留新架构下的阅读引擎、导航锁和输入上下文判断。 |

后续每个子任务必须在实施记录中引用本清单，标记对应项的处理结果：已融合、已替代、已归档、不迁移或需工单。
