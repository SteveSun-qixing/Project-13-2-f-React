# 主工作区架构调整融合范围

本节定义旧主工作区提交中需要迁移的架构调整。它们不按旧目录结构直接合并，而是作为当前 worktree 新架构的增强项融合落地。

必须融合的架构调整：

- `CardViewerSource` 成为查看器、Host 打开入口、社区 Web 插件路由和 SDK 公共类型之间的统一来源模型。
- `document.window` 成为 `.card/.box` 文档窗口的统一 SDK 事件面，包含 ready、resize、error、node-error、resource-open 和 render session cleanup。
- Host `card.open`、文件关联和箱子打开入口优先传递 `launchParams.cardSource`，减少旧 `targetPath/fileOpenMode` 平行协议。
- CardViewer 继续使用当前 `AppRuntimeProvider / scene-registry / AppShell / Scene` 架构，吸收旧 `ViewerSourceProvider / ViewerStage / ViewerChrome` 的职责，不恢复旧单体根组件。
- 封面/内容切换纳入当前查看器运行时状态，封面来源与比例校验成为正式壳层能力。
- 社区 Web 插件宿主使用 `DocumentPluginRoutePage`、`HostedPluginSurface` 和 document surface resize 语义承载查看器，不恢复社区自研查看页。
- 社区服务器以源 `.card`、上传会话、资源直传、渲染任务、view/cover 缓存和 worker 形成可重建链路。
- CommunityUploader 作为模块插件进入生态能力模型，不把上传处理长期留在 Web 前端或服务器旧 pipeline 中。

融合时禁止：

- 用旧主工作区 `App.tsx`、旧查看页或旧 pipeline 目录覆盖当前新架构文件。
- 把旧提交中的过渡字段升级为新的公共契约。
- 只迁移 UI 结果而遗漏 Host、SDK、Bridge、manifest、测试和文档中的架构口径。
