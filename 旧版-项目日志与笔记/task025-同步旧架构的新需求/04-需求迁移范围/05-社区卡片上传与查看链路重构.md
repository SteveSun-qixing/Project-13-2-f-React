# 社区卡片上传与查看链路重构

最终目标以 `d3c6d0b0` 的需求为准：

- `.card` 是社区永久源文件。
- 服务器只保存处理后的源 `.card`、资源 manifest 和渲染状态。
- 完整查看 HTML 与封面 HTML 是可删除、可过期、可重建的缓存。
- 查看缓存与封面缓存分离，最后访问后续期，缺失时重新排队渲染。
- 新增上传会话，支持资源直传 presign、资源 Head 校验、处理后 `.card` 提交和渲染任务入队。
- Worker 从源 `.card` 拉取并生成 community-web 与 community-cover 缓存。
- 旧 `card_pipeline_jobs`、`runCardPipeline`、CDN 上传、富文本内联、URL 替换等旧 pipeline 不再作为正式源码主链路；需要保留时移入就近 `归档/`，并确保不被构建和测试扫描。
- 箱子条目解析返回新的 `communityViewUrl` 与 `communityRenderStatusUrl` 语义，避免继续扩散 `communityHtmlUrl`。

服务端新增/调整能力：

- 数据表：源文件字段、上传会话、上传资源、渲染任务、渲染缓存。
- 接口：upload-sessions、resource presign、resource head confirm、source card submit、open-view、render-status、view、cover、私有缓存代理。
- 存储：源文件、资源、完整查看缓存、封面缓存分离 bucket 或逻辑前缀。
- Worker：渲染任务消费、缓存续期、过期清理、失败重试和状态回写。

前端新增/调整能力：

- 工作区上传页改为上传会话模型，不再直接把旧 pipeline 响应当最终结果。
- 卡片详情页使用 open-view + render-status + `cardSource` 创建 `com.chips.card-viewer` 会话。
- 列表使用独立 coverUrl，不再用 htmlUrl 判断是否可打开。
