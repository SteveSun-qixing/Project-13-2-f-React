# 阶段 1：公共契约与类型先行

1. 在 SDK 增加 `CardViewerSource` 类型，覆盖：
   - `local-file`，通过 `documentKind: "card" | "box"` 区分本地卡片和本地箱子；
   - `community-card`
   - `community-box`
   - `remote-card-file`
2. 定义 `ViewerCoverSource`、封面比例校验、社区 view/status/cover 字段和标题日期字段。
3. 为 `document.window` 补齐 resize 事件类型与订阅接口，同时保留当前 worktree 已有的 `onNodeError` 事件面。
4. 为 SDK iframe 结果补齐文档类型标记，便于查看器、测试和诊断统一识别 `.card/.box`。
5. 更新 Host `card.open`、文件关联和箱子打开入口的计划口径：统一向查看器传递 `cardSource`。
6. 同步准备公共文档更新点：
   - Bridge API 规范；
   - 卡片信息与打开契约；
   - 箱子布局运行时契约；
   - SDK 使用指南；
   - 复合卡片窗口与 SDK 显示链路标准；
   - 社区平台 API 契约。

验收：

- SDK 类型测试覆盖 `CardViewerSource` 正常与异常来源；
- Host/SDK route manifest 不漂移；
- `document.window` resize 与 node-error 两类事件都被测试覆盖；
- 公共文档只在代码和 manifest 核对后更新。
