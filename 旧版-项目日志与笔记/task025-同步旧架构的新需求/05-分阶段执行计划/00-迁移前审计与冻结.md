# 阶段 0：迁移前审计与冻结

1. 再次核对 `develop` 提交 patch，抽取需求、接口、测试、文档和架构调整，不合并代码。
2. 核对当前 worktree 的 `manifest.yaml`、`package.json`、Host route manifest、SDK API 和社区服务器迁移状态。
3. 对旧提交里的“已被后续提交替代”内容做明确标记。
4. 若发现当前公共契约缺失、文档与代码不一致、脚手架无法生成目标结构，先登记工单并停止对应实现。
5. 每个迁移子任务开始前必须建立源码一比一对照记录：列出旧源码文件、旧测试文件、旧文档、旧运行入口、旧数据结构、旧错误处理、旧架构职责调整、旧验证命令，以及它们在当前新架构中的目标落点。
6. 每个旧架构调整都必须分类为：融合迁移、职责重映射、被后续提交替代、归档不迁移或需要工单。

产出：

- 本迁移计划；
- 后续实施任务拆分清单；
- 每个子任务的源码一比一对照记录和架构融合记录；
- 必要时新增问题工单。
