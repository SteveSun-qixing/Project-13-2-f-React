# task025 同步旧架构新需求迁移计划

## 1. 背景与目标

当前工作区是 `task022-优化薯片组件库和主题系统` 重构 worktree，已经采用前端框架 vNext、App / Scene / surface、Host L1-L9、SDK 类型封装、组件库、主题与多语言的新架构。原主工作区 `develop` 仍处在较旧架构上，但在本 worktree 分出后继续提交了一批有效的新需求和体验修复。

本任务目标不是把 `develop` 的代码直接合并进来，而是把其中已经验证过的功能设计、交互需求、接口需求、性能需求和验收口径抽取出来，再按当前重构架构重新实现。

迁移时必须遵守：

- Host 是唯一运行时承载，插件只能通过 `window.chips.*`、Bridge 或 `chips-sdk` 调用系统能力。
- 应用插件使用 React、AppRuntime、Scene、surface 和 command registry，不恢复旧式单体入口或私有 Bridge 入口。
- 查看器不解析 `.card/.box`，不自行拼装 iframe，不维护第二套卡片/箱子读取逻辑。
- 社区 Web 侧继续承载原版 `type: app` 插件，不恢复社区自研临时查看页。
- 服务器无界面能力优先走 Host、模块插件、正式队列和公开 HTTP API 契约，不保留旧 pipeline 临时主链路。
- 所有用户可见文案走 i18n，样式走主题 token，公共契约变更同步沉淀到 `生态共用技术文档/`。

## 3. 迁移总原则

1. **以需求为源，不以旧代码为源**：旧提交只提供行为、接口、测试和文档证据；实际实现必须贴合当前重构后的目录、Provider、Scene、SDK 和 Host 服务。
2. **以后续提交覆盖前序方案**：`d3c6d0b0` 已替代 `6e6b20fb` 中旧 `card_pipeline_jobs/runCardPipeline` 主链路，迁移时保留“异步化、队列化、缓存化”的需求，不恢复旧 pipeline 主实现。
3. **统一来源模型**：卡片查看器入口统一收口到结构化 `cardSource`，避免继续扩散 `targetPath`、`webDocumentUrl`、`htmlUrl`、`communityHtmlUrl` 等平行私有字段。
4. **查看器壳层只做壳层能力**：封面/内容切换、返回按钮、顶部信息和 action slot 属于查看器壳层；卡片正文和箱子页面仍由 Host/SDK 正式文档链路承载。
5. **社区 Web 不复制桌面 Host**：社区 Web 插件宿主只实现浏览器侧 session、entry、bootstrap、resource-open-plan、surface 映射和高度同步；公共 Host WebShell 能力若要对外发布，另开正式任务。
6. **上传链路两端分工清晰**：用户设备侧模块插件负责解包、资源扫描、资源外置、YAML/cover HTML 改写和重新打包；服务器负责上传会话、对象存储、源文件保存、渲染缓存和公开访问控制。
7. **文档先核对后更新**：真正改动公共契约前，必须重新核对 Host/SDK/manifest/测试/运行链路，不能直接照搬旧工作区文档。

## 4. 需求迁移范围

### 4.1 卡片查看器统一来源与文档承载

目标：

- 新增并冻结 `CardViewerSource` 结构化来源模型，覆盖本地卡片、本地箱子、社区卡片、社区箱子和未来远程卡片文件。
- `Chips-CardViewer` 启动时优先解析 `launchParams.cardSource`，保留 `targetPath` 作为本地文件关联回退。
- 当前 `webDocumentUrl` 只作为迁移过渡兼容输入，不作为新文档主口径。
- 本地 `.card/.box` 继续通过 `client.document.window.render({ filePath })` 进入 Host/SDK 正式链路。
- 社区卡片/箱子通过社区提供的 `viewUrl` 或文档 URL 进入 `HostedDocumentWindow`，但来源、标题、日期、封面和状态统一由 `cardSource` 承载。
- `HostedDocumentWindow` 的高度事件补齐 `height/contentHeight/viewportHeight/safeBlockStart/safeBlockEnd/reason/stable`，并以稳定窗口合并收缩。
- `HostedPluginSurface(surfaceMode=document)` 只消费 `plugin.surface.resize` 调整 iframe 高度，不自行测量卡片内容。

当前新架构落点：

- `Chips-CardViewer/src/app/AppRuntimeProvider.tsx`
- `Chips-CardViewer/src/app/scene-registry.ts`
- `Chips-CardViewer/src/scenes/DocumentFileScene.tsx`
- `Chips-CardViewer/src/scenes/HostedDocumentScene.tsx`
- `Chips-CardViewer/src/components/CardWindow.tsx`
- `Chips-CardViewer/src/components/HostedDocumentWindow.tsx`
- `Chips-SDK/src/api/document.ts`

不直接迁移的旧实现：

- 旧提交中的单体 `App.tsx` 重构片段；
- 旧 `ViewerSourceProvider` 若与当前 `AppRuntimeProvider` 职责重复，不原样复制；
- 社区旧 `CardViewerPageShell` 专属查看 UI 不恢复。

### 4.2 封面/内容切换查看能力

目标：

- 查看器支持 `content` 与 `cover` 两种查看模式。
- 有封面时显示“查看封面/查看内容”壳层动作；无封面时不显示切换按钮。
- 本地卡片封面通过 `client.card.readInfo(filePath, ["cover"])` 或当前正式封面 API 读取。
- 本地箱子封面通过 `client.box.renderCover(filePath)` 读取。
- 社区来源直接携带 `coverUrl/coverFragmentUrl/coverRenderMode/coverRatio` 等封面字段。
- 封面读取失败只降级为不显示封面切换，不影响正文查看。
- 封面 iframe 使用受控、sandboxed 文档承载；点击封面返回正文。
- 封面比例必须校验，非法值回退默认比例，不能让任意字符串进入 CSS。
- 封面视觉尺寸采用面积归一策略：横版、竖版、方形和极端比例围绕相近视觉面积推导宽高，同时受视口、安全区和移动端约束。
- 封面下方展示当前卡片或箱子名称，最多两行。

当前新架构落点：

- 在当前 CardViewer Scene / runtime 内增加查看模式状态，不新增平行运行时。
- 新增封面组件时应放在 `Chips-CardViewer/src/components/`，并通过当前 i18n 和主题 token 接入。
- action 触发由当前壳层或 Scene action slot 接入，后续如接入 command registry，metadata 必须只写 i18n key 和 IconDescriptor。

### 4.4 社区打开页轻量化、预取与分页索引

目标：

- 新增或重写 `GET /api/v1/cards/:cardId/open-view`，只返回打开页必要字段。
- open-view 权限与卡片详情一致：公开卡片可匿名读取，私有卡片仅所有者读取，无权访问按 `CARD_NOT_FOUND` 处理。
- open-view 不读取详情热路径外的大 JSON 字段。
- 卡片详情页用 open-view 驱动打开态，并通过 render-status 轮询处理状态。
- 作品卡在 hover、focus、接近视口时预取 open-view；失败后清理内存 Promise 缓存。
- 启动时为对象存储资源域名注入 `dns-prefetch/preconnect`。
- 列表和发现类接口改为数据库分页，不再查全量后 slice。
- 卡片、箱子、房间、后台列表使用 summary DTO，避免列表热路径读取 metadata/structure 大字段。
- `cover_ratio` 等列表/打开页常用字段下沉为普通列并加索引。
- 箱子 enrichment 改为批量查询，避免 N+1。

### 4.5 社区卡片上传与查看链路重构

最终目标以 `d3c6d0b0` 的需求为准：

- `.card` 是社区永久源文件。
- 服务器只保存处理后的源 `.card`、资源 manifest 和渲染状态。
- 完整查看 HTML 与封面 HTML 是可删除、可过期、可重建的缓存。
- 查看缓存与封面缓存分离，最后访问后续期，缺失时重新排队渲染。
- 新增上传会话，支持资源直传 presign、资源 Head 校验、处理后 `.card` 提交和渲染任务入队。
- Worker 从源 `.card` 拉取并生成 community-web 与 community-cover 缓存。
- 旧 `card_pipeline_jobs`、`runCardPipeline`、CDN 上传、富文本内联、URL 替换等旧 pipeline 不再作为正式源码主链路；需要保留时移入就近 `归档/`，并确保不被构建和测试扫描。
- 箱子条目解析返回新的 `communityViewUrl` 与 `communityRenderStatusUrl` 语义，避免继续扩散 `communityHtmlUrl`。

服务端新增/调整能力：

- 数据表：源文件字段、上传会话、上传资源、渲染任务、渲染缓存。
- 接口：upload-sessions、resource presign、resource head confirm、source card submit、open-view、render-status、view、cover、私有缓存代理。
- 存储：源文件、资源、完整查看缓存、封面缓存分离 bucket 或逻辑前缀。
- Worker：渲染任务消费、缓存续期、过期清理、失败重试和状态回写。

前端新增/调整能力：

- 工作区上传页改为上传会话模型，不再直接把旧 pipeline 响应当最终结果。
- 卡片详情页使用 open-view + render-status + `cardSource` 创建 `com.chips.card-viewer` 会话。
- 列表使用独立 coverUrl，不再用 htmlUrl 判断是否可打开。

### 4.6 社区上传模块插件

目标：

- 新增 `Chips-CommunityUploader-Plugin`，类型为 `module`。
- 能力：`community.card.publish/publish`。
- 插件在用户设备侧执行：
  - 解包 `.card`；
  - 扫描卡片资源；
  - 向社区服务器申请上传会话和资源直传 URL；
  - 上传资源；
  - 改写 YAML 与 cover HTML；
  - 删除已外置资源；
  - 重新 pack `.card`；
  - 提交处理后的源 `.card`。
- 插件不提供 UI，不持有对象存储长期密钥。
- 插件必须采用当前模块插件脚手架和 manifest 契约，不直接复用旧导出实现。

当前新架构落点：

## 7. 风险与处理策略

| 风险 | 影响 | 处理 |
|---|---|---|
| `cardSource` 公共契约未冻结就写入多处实现 | 后续字段漂移、社区与桌面启动不一致 | 阶段 1 先冻结 SDK 类型和公共文档，再动业务实现。 |
| 旧 `webDocumentUrl/htmlUrl/communityHtmlUrl` 与新 `cardSource.viewUrl` 并存过久 | 打开链路继续分叉 | 只允许旧字段作为过渡输入；新代码和新文档只写 `cardSource`。 |
| 旧 pipeline 与新源 `.card` 缓存链路混用 | 上传结果不可重建，缓存和源文件职责混乱 | 以 `d3c6d0b0` 的源 `.card` 模型为最终口径，旧 pipeline 归档。 |
| 社区 Web 宿主承担过多 Host 通用职责 | 社区内部实现误变成公共 Host WebShell 契约 | 只在社区文档记录内部实现；公共 WebShell 另开任务。 |
| 封面 iframe 高度与正文 iframe 高度共用旧缓存 | 切换封面时空白或滚动跳动 | 封面挂载、ready/error、视口变化和 stable resize 都要独立发布。 |
| iframe 焦点键盘接管影响输入框 | 阅读器正文、搜索框、可编辑内容快捷键冲突 | 键盘处理器保留当前编辑上下文判断，测试覆盖输入场景。 |
| 上传模块插件需要新增第三方库 | 违反技术选型 | 优先复用现有 Host/SDK/ZIP/YAML 能力；确需新增先记录并等待用户决策。 |
