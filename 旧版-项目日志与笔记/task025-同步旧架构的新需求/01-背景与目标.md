# 1. 背景与目标

当前工作区是 `task022-优化薯片组件库和主题系统` 重构 worktree，已经采用前端框架 vNext、App / Scene / surface、Host L1-L9、SDK 类型封装、组件库、主题与多语言的新架构。原主工作区 `develop` 整体仍处在较旧架构上，但在本 worktree 分出后继续提交了一批有效的新需求、体验修复和局部架构调整。

本任务目标不是把 `develop` 的代码直接合并进来，而是把其中已经验证过的功能设计、交互需求、接口需求、性能需求、验收口径和有价值的架构调整抽取出来，再按当前重构架构重新实现，形成融合后的新架构版本。

迁移判断以“双轨输入”为准：

- 功能轨：旧提交中新增或修复的用户行为、接口、数据流、错误处理、性能优化和测试断言。
- 架构轨：旧提交中已经沉淀出的公共类型、启动参数、Host/SDK/Bridge 责任划分、Web 插件宿主、源文件与缓存分层、模块插件化等架构设计。

如果旧主工作区某段代码属于旧目录结构、旧单体入口或旧临时实现，但其中包含合理的架构意图，应只迁移架构意图和行为约束，不迁移旧代码形态。

迁移时必须遵守：

- Host 是唯一运行时承载，插件只能通过 `window.chips.*`、Bridge 或 `chips-sdk` 调用系统能力。
- 应用插件使用 React、AppRuntime、Scene、surface 和 command registry，不恢复旧式单体入口或私有 Bridge 入口。
- 查看器不解析 `.card/.box`，不自行拼装 iframe，不维护第二套卡片/箱子读取逻辑。
- 社区 Web 侧继续承载原版 `type: app` 插件，不恢复社区自研临时查看页。
- 服务器无界面能力优先走 Host、模块插件、正式队列和公开 HTTP API 契约，不保留旧 pipeline 临时主链路。
- 所有用户可见文案走 i18n，样式走主题 token，公共契约变更同步沉淀到 `生态共用技术文档/`。
