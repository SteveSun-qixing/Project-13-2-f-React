# 质量缺口修复日志：富文本内联接线、移动端 target、YAML 恢复口径

> 日期：2026-08-05
> 来源：task027 质量评审反馈

## 修复内容

### 【中】富文本 file-backed 内容内联未真正接线

问题：`publisher.ts` 调用 `replaceYamlResourceUrls(..., new Map())` 传空 `textResourceMap`，`collectFileBackedRichTextResourcePaths` 从未被调用；恢复侧也没有 `content_text → content_file` 还原分支。file-backed 富文本卡片的网络资源卡片会失效。

修复：

- `src/publisher.ts`
  - 新增 `collectTextResourceMap`：扫描 `content/*.yaml`，对 file-backed 富文本配置读取 `richtext/*.md` 内容，构造 `candidatePath → markdown` 映射；
  - 新增 `collectRichTextContentFileMap`：记录 `configPath → contentFile`，用于恢复；
  - `writeRewrittenCard` 接收并透传 `textResourceMap`；
  - `createRestoreManifest` 写入 `richTextContentFiles`；
  - `extractRichTextContentFileMap` + `restoreDownloadedCard` 在下载恢复时依据恢复清单还原 file-backed 配置。
- `src/card-rewrite.ts`
  - `restoreInValue` 新增 `content_source: inline` + `content_text` → `content_source: file` + `content_file` 还原分支；
  - `restoreYamlResourcePaths` 增加 `sourceFilePath` 与 `richTextContentFileMap` 参数。
- 测试：
  - 新增 `tests/unit/card-rewrite.test.ts`（6 条）：候选路径收集、内联重写、恢复还原、无映射保持 inline、普通资源字段 round trip；
  - `module-definition.test.ts` 新增上传链路端到端富文本内联测试（共 7 条）。

### 【低】CardViewer manifest mobile: supported 与 P8-15 不一致

问题：`Chips-CardViewer/manifest.yaml` 声明 `preferredKinds.mobile: fullscreen` 且传输模块声明 `mobile: true`，但 `runtime.targets.mobile.supported: false`，与 P8-15“Mobile 客户端可以上传、查看、下载”不一致。

修复：`Chips-CardViewer/manifest.yaml` 的 `mobile.supported` 改为 `true`，与设计方向（P1-03 / P6-14 / P8-15）及传输模块口径一致。`chipsdev validate` 通过。

### 【低】YAML 重排与恢复口径

问题：YAML 经 `parse → stringify` 会丢失注释与原始格式；“配置内容不能改变”仅做到“尽可能”；黄金回环测试用手写字符串而非模块自身逻辑。

处理：

- 生态共用卡片格式规范 1A.4 补充明确口径：YAML 解析→改写→序列化允许格式化归一（注释、空行、键序、引号风格可能变化），但不得改变字段语义与资源路径；验收以字段语义与资源引用一致为准，不以配置文本逐字节相同为准；
- `card-rewrite.test.ts` 新增 round trip 保真测试：改写后 `source: url` + CDN URL，恢复后 `source: file` + 原始相对路径；
- Host 黄金回环测试保持 Host 层 ZIP 完整性验证职责，URL↔路径逻辑由模块 `card-rewrite.test.ts` 覆盖（符合分层边界，不跨仓直接 import）。

# 阶段1开发日志：建设客户端统一卡片传输模块

> 日期：2026-08-05
> 阶段：阶段 1（建设客户端统一卡片传输模块）
> 任务清单：P1-01 ~ P1-10

## 目标

所有客户端应用插件都接入同一个模块，不再各自处理上传、下载、查看。

## 完成内容

### 模块能力与契约（P1-01）

`Chips-ModulePlugin/Chips-CommunityUploader-Plugin` 提供正式能力 `community.card.transfer`：

- `manifest.yaml`：能力名、运行目标、权限、输入输出 schema 引用。
- 方法：`upload` / `download` / `openRemote`；`getStatus` / `cancel` 由 Host `module.job.*` 承载。
- 输入输出 schema：`contracts/upload|download|openRemote.input|output.schema.json`。
- 错误码统一通过 `createCommunityUploaderError(code, message, details, retryable)` 生成。

### 运行边界（P1-02 / P1-03 / P1-04）

- Desktop Host：支持上传、下载、远程打开。
- Mobile Host/PAL：按同一能力契约支持。
- Web 浏览器：不支持，浏览器不加载该模块。
- Headless：支持，用于自动化与测试链路。

### SDK 类型化封装（P1-05）

`Chips-SDK/src/api/community-card-transfer.ts` 提供 `client.communityCardTransfer.upload/download/openRemote/getStatus/cancel`，只做类型化封装和调用入口，不承载上传下载主实现。

### 应用插件统一接入（P1-06）

CardViewer、EditingEngine 等应用插件通过 SDK 统一模块入口调用发布、打开社区卡片和下载，不各自实现社区文件链路。模块内 `src/publisher.ts` 是唯一正式文件链路实现。

### 重试、取消、断网恢复、签名刷新、错误状态（P1-07）

在 `src/publisher.ts` 新增 `fetchWithRetry` / `fetchControlPlane`：

- 控制面请求和对象存储 PUT/GET 使用指数退避重试（最多 3 次）；
- 5xx / 408 / 429 视为瞬时失败自动重试；
- 401 / 403 立即抛出 `COMMUNITY_TRANSFER_AUTH_EXPIRED`，由调用方刷新签名后重新发起；
- 每次重试前检查任务 `AbortSignal`，取消时抛出 `COMMUNITY_TRANSFER_CANCELLED`；
- 网络失败统一抛出 `COMMUNITY_TRANSFER_NETWORK_FAILED`（可重试）。

新增单元测试：瞬时 503 重试三次成功；401 抛出 auth-expired 非重试错误。

### URL 改写与下载恢复统一处理（P1-08）

`src/card-rewrite.ts` 统一处理：

- `replaceYamlResourceUrls` / `restoreYamlResourcePaths`：content/*.yaml 资源字段相对路径 ↔ URL；
- `replaceCoverHtmlUrls` / `restoreCoverHtmlPaths`：.card/cover.html 封面引用；
- 富文本 file-backed 内容内联：上传时 `collectFileBackedRichTextResourcePaths` + `collectTextResourceMap` 读取 `richtext/*.md` 内容，把 `content_source: file` + `content_file` 内联为 `content_source: inline` + `content_text`；下载恢复时依据恢复清单 `richTextContentFiles` 映射还原为 file-backed 并写回 markdown 资源；
- 插件禁止自行替换 YAML 或 HTML。

### UI 文案与主题（P1-09）

本模块是无 UI 的 worker 模块（`runtime: worker`、`activation: onDemand`），不承载界面，因此不产生 UI 文案或主题依赖；客户端中由它驱动的界面均走各自多语言与主题系统。

### 第三方库依赖评审（P1-10）

新增 `技术文档/01-社区卡片传输模块技术方案.md`，建立依赖评审记录：运行期唯一第三方依赖 `yaml@^2.8.2`（MIT、活跃维护、包体极小、纯 JS 跨端），用于卡片配置 YAML 解析与写出；对象存储签名、ZIP Store 读写、任务调度均走 Host 正式能力。

## 完成内容

### 上传会话（P3-01 / P3-02 / P3-03）

`Chips-CommunityPlatformServer/packages/server/src/routes/card-transfer.ts`：

- `POST /api/v1/card-transfer/upload-sessions`：客户端模块创建上传会话，返回 uploadId、cardId、versionId、resourcePrefix 和 networkCard 对象位置；服务器只保存元数据（P3-01）。
- `POST .../objects:presign`：为资源文件和网络资源卡片签发对象存储 PUT 地址，对象键固定在会话对象布局下（P3-02）。
- `POST .../complete`：JSON 提交网络资源卡片对象位置、资源对象位置、资源清单和可逆恢复清单（P3-03）。

### 校验（P3-04 / P3-05 / P3-06）

- 新增 `assertRestoreManifestStructure`：校验恢复清单 schemaVersion 必填、zipEntries/resources 为数组（P3-04）。

- `requireJsonBody` preHandler + Fastify 内容类型解析：`card-transfer` 全部 POST 路由只接受 `application/json`，`multipart .card` 与 octet-stream 卡字节被 415 拒绝（P3-05 / P3-12）。
- API 不代理资源、网络资源卡片、查看缓存或下载文件字节，全部走对象存储 URL（P3-06）。

### 版本状态与缓存调度（P3-07）

- complete 后写 cards 表 sourceCard* 字段与 resourceManifest，状态置 `ready`；
- 通过 `CardRenderCacheService.enqueueForCard` 调度 view/cover 渲染缓存生成。

### 下载会话（P3-08 / P3-09）

- `POST /api/v1/card-transfer/download-sessions` 只面向客户端模块；
- `GET .../plan` 返回网络资源卡片对象位置、资源对象位置和恢复清单，均为对象存储 URL + 预签名 GET 地址，不返回文件字节。

### 权限边界（P3-10）

- 卡片文件本身不处理公开/私有/权限字段；接口只保留社区系统登录（JWT）和内容归属所需的外层控制。
