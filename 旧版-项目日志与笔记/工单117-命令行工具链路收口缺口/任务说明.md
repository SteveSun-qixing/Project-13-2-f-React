# 工单117-命令行工具链路收口缺口

## 背景

2026-05-29 对 `chips` / `chipsdev` 实际代码、共享命令行文档、命令系统契约、脚手架模板和 CLI 相关测试进行端到端审查时，确认 Host CLI 的插件命令发现、参数解析、模块命令执行、应用命令执行、TUI、completion、日志记录和 SDK 封装已经具备主体链路，但仍存在多处与正式契约、开发工作区口径或真实运行闭环不一致的问题。

这些问题涉及 Host CLI、SDK `chipsdev` 委托层、Electron 应用 CLI runner、manifest 校验、脚手架模板和共享文档。若继续在此基础上沉淀正式命令行能力，需要先收口这些缺口，避免开发者按文档使用时命中错误工作区、命令卡死、日志重复或包校验通过但 Host 安装失败。

## 证据

- `Chips-Host/src/main/cli/index.ts` 的 `renderCompletionScript()` 固定输出 `chips __complete` 和 `complete ... chips`，而 `chipsdev completion <shell>` 只是把命令委托给 Host CLI。生成脚本安装后会调用用户侧 `chips`，无法继续保留开发工作区 `CHIPS_HOME` 和 `CHIPS_WORKSPACE_KIND=dev`。
- `生态共用技术文档/命令行工具/02-Chips-Dev开发者命令行手册.md` 声明 `chipsdev completion <shell>` 的脚本每次补全都会读取开发工作区动态插件命令索引，但当前脚本硬编码 `chips`，与该口径不一致。
- `Chips-Host/tests/e2e/cli.test.ts` 中 `opens app plugin surfaces from plugin CLI commands` 在本次针对性验证中 30 秒超时，并留下 `cli-app-command-runner.ts --chips-cli-app-request=...` Electron 子进程。该链路对应 app 插件 CLI surface 打开，不只是普通断言失败。
- `Chips-Host/src/main/cli/index.ts` 的应用 CLI 子进程执行器只等待子进程 `exit` 后解析 stdout envelope，没有外层超时或子进程清理兜底；runner 侧在写出结果后调用 `mainProcess.stop({ quitElectronApp: true })`，若 Electron 事件循环没有退出，父进程会一直等待。
- `Chips-SDK/cli/index.js` 先用 `COMMANDS` 白名单拦截顶层命令，未知根会直接返回“未知命令”，没有把非内建插件命令透传给开发工作区 Host CLI；但 `chipsdev` 的 TUI 和 completion 又会显示开发工作区插件命令，直接执行体验存在不一致。
- `Chips-Host/src/main/cli/index.ts` 的插件命令失败会在 `tryRunPluginCliCommand()` 内记录一次带插件上下文的失败日志，随后抛到 `runCli()`，而 `shouldRecordTopLevelCliOperation()` 对非零退出码返回 true，可能再次记录一次通用失败日志。
- `Chips-Host/src/main/cli/index.ts` 的 `plugin list` 直接读取 `plugins.json` 并输出 `{ id, manifestPath, enabled }`，而 `plugin query` 才走 Host runtime `plugin.query`。共享 Host CLI 文档声明 list 应显示插件 ID、名称、版本、状态等信息。
- `Chips-Host/src/main/cli/index.ts` 的 `start` / `stop` 只写入或删除 `host-state.json`，没有真正启动或停止 Host/Electron 后台进程；`update check/install` 直接返回硬编码 `0.1.0`。共享 Host CLI 文档描述的是启动应用、优雅停止、连接更新服务器和安装更新。
- `Chips-SDK/cli/index.js` 的 `appendCliCommandManifestErrors()` 对 `manifest.cli.commands` 的校验弱于 Host runtime parser，例如没有完整校验 `titleKey`、命令路径 segment 正则、target 必填字段和 target `pluginId` 与声明插件 ID 的一致性，可能出现 `chipsdev validate/package` 通过但 Host `plugin.install` 拒绝的包。

## 复现步骤

1. 在 `Chips-SDK` 执行 `chipsdev completion bash`，检查生成脚本，确认脚本内部调用 `chips __complete` 且注册目标为 `chips`，不是 `chipsdev` 或携带开发工作区环境的补全入口。
2. 在开发工作区安装并启用 app/module 插件 CLI 命令后，使用上述 `chipsdev completion` 脚本触发补全，补全会转向用户 `chips` 工作区，不能保证读取 `.chips-host-dev` 的动态命令索引。
3. 在 `Chips-Host` 执行 `npm test -- tests/e2e/cli.test.ts tests/unit/cli-app-task.test.ts tests/unit/cli-interactive.test.ts tests/unit/plugin-runtime.test.ts`，本次验证中 app 插件 CLI surface 打开用例超时，并残留 Electron runner 子进程。
4. 执行一个会失败的插件 CLI 命令，例如传入不存在的 path 参数，再导出 `chips logs`，检查是否同时存在插件上下文失败日志和顶层通用失败日志。
5. 执行 `chips plugin list` 与 `chips plugin query`，对比输出字段，确认 list 没有使用 runtime view 中的 name/version/type/capabilities 等信息。
6. 执行 `chips start` / `chips status` / `chips stop`，确认只改变 `host-state.json`，没有真实 Host/Electron 进程生命周期。
7. 构造缺少 `titleKey`、target 字段不完整或 target `pluginId` 不匹配的 `manifest.cli.commands`，对比 `chipsdev validate/package` 和 Host `plugin.install` 的校验结果。

## 期望行为

- `chipsdev completion <shell>` 生成的脚本必须保持开发工作区语义；可以生成 `chipsdev __complete` 私有入口，也可以在脚本中固定注入开发工作区环境，但需要与共享文档和测试统一。
- app 插件 CLI 命令执行必须有可回收、可超时、可错误上报的 Electron runner 链路；父进程不能无限等待，子进程不能残留。
- `chipsdev` 对开发工作区插件命令的 TUI、completion 和直接执行口径应统一；若直接执行不支持，需要文档、帮助和补全明确排除，若支持则应透传给 Host CLI 的插件命令执行器。
- CLI 操作日志应保证一次用户操作只有一个主记录，插件命令失败时保留插件上下文，避免重复统计和审计噪音。
- `plugin list` 应与 Host runtime 插件视图一致，至少输出文档承诺的 ID、名称、版本、类型、状态等字段。
- `start` / `stop` / `update` 要么实现正式生命周期和更新链路，要么在共享文档中明确当前阶段语义；不能让文档描述后台 daemon 和更新服务器，而代码只做状态标记或硬编码返回。
- `chipsdev validate/package` 与 Host runtime parser 应共享或等价执行 CLI manifest 校验规则，确保打包通过的插件不会在安装时因同一契约被拒绝。

## 处理结果

- `chipsdev completion <shell>` 现在生成注册到 `chipsdev` 的补全脚本，并通过 `chipsdev __complete` 私有入口保持开发工作区语义。
- `chipsdev <commandPath>` 可将未知顶层命令透传给开发工作区 Host CLI，由 Host 插件 CLI 执行器统一做最长前缀匹配、冲突消解、参数解析和正式路由执行。
- 应用插件 CLI Electron runner 已增加结构化输出即结算、超时和子进程终止兜底，修复 app surface CLI 测试超时和残留进程问题。
- `chips plugin list` 已改为使用 Host runtime 插件视图，输出名称、版本、类型、启用状态等正式字段。
- 插件 CLI 失败日志已去重，同一失败操作保留带插件上下文的主记录，不再追加无插件上下文的顶层失败记录。
- SDK `chipsdev validate/package` 已补齐 `manifest.cli.commands` 关键校验：`titleKey`、命令路径 segment、target 必填字段、target `pluginId` 与 `manifest.id` 一致性、参数唯一性、权限声明、output/job/conflict 元数据等。
- 共享命令行文档、命令系统契约和命令行拆分指南已同步当前正式口径。
- 验证通过：
  - `cd Chips-Host && npm run build`
