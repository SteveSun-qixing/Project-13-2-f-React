# 工单131 任务说明：社区服务器迁移 meta 管理口径与迁移文件漂移

## 背景

task029 社区服务器实施时发现，`Chips-CommunityPlatformServer/packages/server/src/db/migrations/` 的迁移文件与 `meta/_journal.json` 登记口径不一致：

- journal 只登记 `0000_workable_maggott`、`0001_community_open_view_cache_base`；
- `0001_community_server_performance`、`0002_card_source_render_cache`、`0003_drop_legacy_card_pipeline` 是手写补充迁移文件，未登记 journal；
- drizzle-orm `migrate()`（`db/migrate.ts`）只执行 journal 登记的条目，未登记文件永远不会被 `db:migrate` 自动执行；
- `meta/0001_snapshot.json` 已过期（仍含已废弃 `card_pipeline_jobs`，缺少 `upload_sessions`、`card_render_*` 等表）。

## 证据

- `packages/server/src/db/migrations/meta/_journal.json`：entries 仅 2 条；
- `packages/server/src/db/migrations/`：共 6 个 `.sql` 文件；
- `node_modules/drizzle-orm/pg-core/dialect.js` `migrate()`：按 journal 的 `folderMillis` 与数据库 `drizzle.__drizzle_migrations.created_at` 比较，只执行 journal 条目；
- `meta/0001_snapshot.json` tables 键：`users/rooms/cards/boxes/card_pipeline_jobs`，与当前 schema（含 upload_sessions 等）不符。

## 影响范围

- `Chips-CommunityPlatformServer/packages/server/src/db/migrations/*`
- 社区服务器 `db:migrate` 与 `db:generate` 工具链；新部署数据库 schema 完整性

## 复现步骤

1. 阅读 `meta/_journal.json` 与 `db/migrations/` 文件清单，可见 0002/0003 未登记；
2. 新数据库执行 `pnpm db:migrate`，未登记文件对应的列/表不会创建；
3. 运行 `pnpm db:generate`，基于过期 snapshot 生成包含大量无关历史变更的迁移。

## 期望行为

- 明确迁移管理口径：journal 全量登记，或采用"合并式基线文件 + 定期刷新 snapshot"单一权威路径；
- `meta/*_snapshot.json` 与当前 `src/db/schema/**` 保持一致，`drizzle-kit generate` 可正常使用。

## 暂行处理

- task029 新增 `0004_box_source_files.sql` 采用"手写幂等 SQL（`ADD COLUMN IF NOT EXISTS`）+ 登记 journal"方式，保证 `db:migrate` 自动生效且可重复执行；
- 0002/0003 未登记问题保持原状，不修改已应用迁移文件（避免 hash 变化导致迁移记录不一致）。
