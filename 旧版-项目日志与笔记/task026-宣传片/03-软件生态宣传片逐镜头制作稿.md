# 软件生态宣传片逐镜头制作稿

> 片名：把日常软件，重新做一遍  
> 片长：90 秒  
> 核心任务：只介绍软件生态，让观众理解“薯片要重新做普通人每天会用的软件”。  
> 核心句：免费、无广告、开源、简洁、美观，重新做每个人都需要的软件。

## 1. 成片基调

这支片子更具体、更日常。不要过多讲卡片文件概念，只讲软件生态的价值：普通人每天要用很多软件，但大多臃肿、割裂、打扰、重复。薯片软件生态要用统一底座重新做它们。

全片视觉节奏：软件混乱 -> 干净底座出现 -> 多个日常软件依次亮相 -> 统一协作 -> 价值宣言。

## 2. 逐镜头表

### S01 / 00:00-00:07 / 日常软件的打扰

**镜头目的**：建立用户痛点，但不要丑化具体产品。

**画面**：

1. 冷灰背景中出现多个抽象软件窗口。
2. 每个窗口内都有不同干扰：弹窗占位块、会员提示占位块、广告横幅占位块、复杂工具栏、重复文件导入框。
3. 所有干扰文字使用抽象词，如“提示”“推荐”“升级”“更多功能”，不出现真实品牌。
4. 画面整体稍显拥挤，但不能脏乱到廉价。

**运动**：

1. 窗口依次弹出，间隔 8 帧。
2. 弹窗出现速度略快，制造被打断感。
3. 摄影机不移动，靠窗口叠加制造压迫。

**字幕**：

左下：

“普通软件，越来越多。”

**旁白**：

“我们每天打开很多软件。”

**声音**：

多个不悦耳但克制的提示音叠加，音量控制在不刺耳。

**转场**：

所有弹窗同时静音，画面亮度降低一点。

### S02 / 00:07-00:15 / 软件越来越重

**镜头目的**：表达臃肿、重复和割裂。

**画面**：

1. 原本的窗口变成 8 个软件图标轮廓，每个图标下方有抽象重量条。
2. 重量条逐渐增长，图标轻微下沉。
3. 画面右侧出现重复能力词：播放、查看、导入、保存、导出、设置。这些词在不同窗口间重复出现。

**运动**：

1. 重量条增长持续 3 秒。
2. 图标下沉不超过 `24 px`，不要卡通化。
3. 重复能力词出现后淡化，表示浪费。

**字幕**：

左下：

“重复、臃肿、割裂。”

**旁白**：

“它们重复、臃肿、割裂，也常常打断我们。”

**声音**：

低频轻压，音乐仍然克制。

**转场**：

画面中央出现干净白色光面，从中心擦除混乱窗口。

### S03 / 00:15-00:23 / 薯片底座出现

**镜头目的**：引出统一软件生态底座。

**画面**：

1. 混乱窗口被一层干净白色系统底面替换。
2. 中央出现一个简洁的生态底座图形：不是芯片，不是电路，而是一块轻薄系统平台。
3. 平台上浮现 5 个空白软件入口位置。
4. 背景恢复 `#F6F7FA`。

**运动**：

1. 白色底面从中心向四周扩散，持续 20 帧。
2. 系统平台从下方轻微上浮，`y +40 px -> 0`。
3. 入口位置依次点亮。

**字幕**：

居中：

“如果软件可以从同一个干净底座开始呢？”

**旁白**：

“如果日常软件，可以从同一个干净底座重新开始呢？”

**声音**：

混乱提示音消失，音乐进入清晰节拍。

**转场**：

第一个入口扩展为图片查看器窗口。

### S04 / 00:23-00:31 / 图片查看器

**镜头目的**：展示“简单、漂亮、无打扰”的软件产品感。

**画面**：

1. 一个图片查看器窗口居中打开。
2. 窗口比例 `16:10`，占画面宽度 `58%`。
3. 内容是一张高质量图片，周围是极简工具栏：上一张、下一张、缩放、信息。
4. 工具栏为轻薄浮层，不遮挡主体。
5. 没有广告、没有推荐、没有多余侧栏。

**运动**：

1. 窗口打开为轻微放大淡入。
2. 图片完成一次平滑缩放，从 `92%` 到适配窗口。
3. 工具栏在鼠标靠近时淡入，随后降低透明度。

**字幕**：

左下：

“看图片，安静清楚。”

**旁白**：

“看图片，就只是清楚地看图片。”

**声音**：

窗口打开轻音，缩放时有柔和滑动声。

**转场**：

图片窗口向左滑出，右侧音乐播放器滑入。

### S05 / 00:31-00:39 / 音乐播放器

**镜头目的**：展示软件生态覆盖娱乐工具。

**画面**：

1. 音乐播放器窗口位于画面右侧偏中。
2. 左侧是专辑封面抽象图，右侧是歌曲列表和播放控制。
3. 播放进度条从 35% 走到 42%。
4. 列表界面干净，不出现推荐流、广告卡片、会员按钮。

**运动**：

1. 专辑封面有极轻微光照变化。
2. 播放按钮从暂停切换到播放，控制条响应。
3. 波形或频谱只做低幅度、低透明度运动。

**字幕**：

左下：

“听音乐，不被打扰。”

**旁白**：

“听音乐，不需要被别的东西打扰。”

**声音**：

音乐主题中短暂加入更明确节拍，但不能变成播放器里的歌曲。

**转场**：

播放器窗口缩小成为软件入口图标，电子书阅读器窗口放大。

### S06 / 00:39-00:47 / 电子书阅读器

**镜头目的**：展示长期阅读的舒适感。

**画面**：

1. 阅读器窗口占画面宽度 `54%`，居中。
2. 页面是干净书页，左右留白充足。
3. 顶部只有书名、进度、目录按钮。
4. 右侧出现极轻的阅读进度浮层，随后自动收起。

**运动**：

1. 页面翻页一次，翻页不是纸张拟物，而是横向滑动过渡。
2. 翻页时间 16 帧。
3. 文字始终清晰，不出现大面积模糊。

**字幕**：

左下：

“读书，回到内容本身。”

**旁白**：

“读书，回到文字和内容本身。”

**声音**：

轻微页面滑动声。

**转场**：

阅读器窗口向后退，编辑器窗口从前景出现。

### S07 / 00:47-00:56 / 文本与笔记工具

**镜头目的**：展示创作类软件。

**画面**：

1. 文本编辑器或笔记工具窗口打开。
2. 左侧为文档列表，中央为编辑区域，右侧为轻量信息面板。
3. 用户输入一行文字：“把灵感整理成清楚的内容。”
4. 画面显示自动保存状态，但不出现复杂设置。

**运动**：

1. 文本逐字输入，速度自然，每秒约 5-6 个汉字。
2. 自动保存状态从“正在保存”变为“已保存”，但只占很小位置。
3. 右侧面板轻微滑入。

**字幕**：

左下：

“写作、记录、整理，都应该简单。”

**旁白**：

“写作、记录、整理，都应该简单、稳定、可信。”

**声音**：

极轻键盘声，只出现 1.5 秒，不能抢旁白。

**转场**：

编辑器窗口缩到一组软件入口中。

### S08 / 00:56-01:04 / 更多日常软件排布

**镜头目的**：表达生态规模，但不承诺已完成所有软件。

**画面**：

1. 画面出现 10 个软件入口卡片，采用统一系统视觉。
2. 入口名称：图片查看器、音乐播放器、视频播放器、电子书阅读器、文本编辑器、笔记工具、资源管理器、卡片查看器、编辑工具、设置面板。
3. 每个入口都是轻薄片层，不使用拟物图标。
4. 已展示过的 4 个入口有轻微点亮状态。

**运动**：

1. 入口从中心向网格位置展开。
2. 网格排列为 5 x 2。
3. 摄影机轻微拉远，展示整体。

**字幕**：

居中：

“普通人每天用的软件，值得被重新做一遍。”

**旁白**：

“普通人每天用的软件，值得被重新做一遍。”

**声音**：

音乐进入更完整节奏。

**转场**：

所有入口向下方同一个底座连接。

### S09 / 01:04-01:13 / 统一底座与共享能力

**镜头目的**：说明软件不是孤立岛屿，而是生态内协作。

**画面**：

1. 10 个软件入口悬浮在上方。
2. 下方是一条干净的生态底座线，不是电路板。
3. 从软件入口向底座延伸细线，表示共享基础能力。
4. 底座上以小字出现：文件、主题、语言、资源、插件、设置。每个词出现后停留。

**运动**：

1. 连接线从入口向底座生长，持续 1.5 秒。
2. 每个能力词淡入，间隔 5 帧。
3. 连接线不能像复杂网络图，保持简洁。

**字幕**：

左下：

“一个底座，承载很多工具。”

**旁白**：

“它们可以像独立软件一样使用，也可以共享同一个生态底座。”

**声音**：

连接线生长时有低音脉冲，温和。

**转场**：

底座变成真实桌面空间，多个窗口同时工作。

### S10 / 01:13-01:20 / 多软件协作场景

**镜头目的**：展示软件生态的使用感。

**画面**：

1. 画面中同时出现三个窗口：图片查看器、笔记工具、音乐播放器。
2. 图片查看器中的一张图片被拖入笔记工具，成为笔记中的图片块。
3. 音乐播放器在底部小窗保持播放。
4. 整体界面安静，窗口层级清晰。

**运动**：

1. 拖拽图片时图片缩略图轻微抬起，阴影增强。
2. 放入笔记后图片块自动对齐到内容流。
3. 窗口之间的运动保持慢，不要像演示软件教程。

**字幕**：

左下：

“工具彼此协作，体验保持统一。”

**旁白**：

“工具彼此协作，体验保持统一。”

**声音**：

拖拽有轻微抬起声，放下有柔和落位声。

**转场**：

三个窗口收拢成一组整齐片层。

## 3. 必须传达的观众认知

成片结束后，观众应明确理解：

1. 薯片软件生态要重新做普通人每天使用的软件。
2. 这些软件追求免费、无广告、开源、简洁、美观、好用。
3. 软件体验像独立应用，但底层来自同一个生态。
4. 软件之间能保持统一体验并协作。
