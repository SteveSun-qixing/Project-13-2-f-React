# 卡片生态宣传片逐镜头工业制作方案总执行说明

> 适用范围：只适用于《信息，有了自己的形状》这支卡片生态宣传片。  
> 上游依据：`01-统一制作规范.md`、`02-卡片生态宣传片逐镜头制作稿.md`、`06-旁白字幕总表.md`。  
> 制作目标：把现有导演稿拆成可由 Three.js / HTML / SVG / Canvas 制作智能体直接执行的镜头级方案。

## 1. 核心表达

本片只讲卡片生态，不讲软件生态，不展示复杂应用窗口，不展开 Host、SDK、插件、Bridge 等技术架构。

观众看完必须形成四个认知：

1. 卡片不是普通便签，而是一种新的信息载体。
2. 一张卡片可以包含文字、图片、视频、音乐等不同内容。
3. 卡片可以组合、嵌套、保存、打开、分享。
4. 卡片让信息从具体软件里独立出来，回到用户手里。

片中概念必须符合生态设计：

1. 画面里的“卡片”对应可保存的复合卡片，是 `.card` 文件的视觉化表达。
2. 卡片内部出现的文字、图片、视频、音频、清单等块，对应基础卡片内容，不要把基础卡片表现成可以独立保存的文件。
3. “箱子”是卡片引用集合，不是真实厚盒子，不保存卡片实体；镜头里只能表现为轻量集合区域、分区或空间视图。
4. 分享时表现 `.card` 作为独立文件被发送和打开，不表现被某个聊天软件或云平台锁定。

## 2. 工程母版

1. 母版分辨率：`3840 x 2160`。
2. 帧率：`25 fps`。
3. 总时长：`90 s`，总帧数 `2250`。
4. 色彩空间：`Rec.709`，最终输出前统一检查白场和灰阶，不允许过曝。
5. 主体安全区：核心视觉主体保持在画面中央 `60%` 区域，兼顾后续竖版和方版裁切。
6. 字幕安全区：左右至少 `240 px`，上下至少 `160 px`。
7. 字体：优先 `PingFang SC`，跨平台使用 `Source Han Sans SC`。
8. 全片不使用临时占位文字，不使用 `Lorem ipsum`，不使用真实第三方品牌标识。

## 3. Three.js 空间约定

制作智能体统一使用以下世界空间，避免各镜头尺度漂移：

1. Three.js 场景中心为画面中心。
2. `x` 轴向右，`y` 轴向上，`z` 轴从画面内向摄影机方向为正。
3. 主合成平面位于 `z = 0`。
4. 在主合成平面上，横版可视宽度定义为 `38.4 unit`，高度定义为 `21.6 unit`，即 `1 unit = 100 px`。
5. 默认摄影机看向原点，镜头保持水平，不做手持晃动。
6. UI 类内容优先放在 `z = 0` 到 `z = 2.4` 的浅景深空间；远景碎片和轮廓可放在 `z = -4` 到 `z = -12`。
7. 卡片厚度不使用实体侧面表达；所有厚度感通过边界、高光、阴影和微小视差完成。

默认推荐实现：

1. 主摄影机使用 `PerspectiveCamera`，等效焦距按镜头在 `50 mm`、`70 mm`、`90 mm` 之间切换。
2. UI 与字幕可使用单独的正交覆盖层，但最终视觉必须与 Three.js 主场景对齐。
3. HTML/SVG 生成的界面元素应先离屏渲染为高分辨率纹理，再贴到 Three.js 平面上。
4. 中文文字纹理至少按目标显示尺寸 `2x` 生成，避免 4K 下边缘发虚。
5. 圆角卡片使用 SDF 圆角遮罩或 Canvas/SVG 预烘焙纹理，不要用低边数圆角几何造成锯齿。

## 4. 统一卡片材质

所有镜头里主卡片必须使用同一套视觉参数：

1. 表面：`rgba(255, 255, 255, 0.86)`。
2. 边线：`rgba(32, 36, 44, 0.10)`，4K 下视觉厚度 `1 px`。
3. 圆角：4K 母版 `44 px`，对应 `0.44 unit`。
4. 阴影一：`0 18px 42px rgba(15, 23, 42, 0.08)`。
5. 阴影二：`0 2px 8px rgba(15, 23, 42, 0.05)`。
6. 顶部内高光：`inset 0 1px 0 rgba(255, 255, 255, 0.58)`。
7. 底部内暗边：`inset 0 -1px 0 rgba(24, 32, 46, 0.06)`。
8. 局部极光反射只能出现在卡片右上短高光、抬起瞬间和片尾 Logo 附近，不得成为大面积背景。

卡片常用比例：

1. 主概念卡：`16:10`。
2. 封面卡：`3:4`。
3. 媒体卡：`16:9`。
4. 方形内容卡：`1:1`。

## 5. 资产制作原则

1. 规范化 UI、卡片结构、文件图标、波形、网页块、清单、标签、封面等，应优先使用 HTML、SVG 或 Canvas 生成，再转为纹理。
2. 真实感图片、视频封面、风景、桌面、设计草图等可以使用 AI 生图，但必须保持干净、明亮、无商标、无水印、无可识别真人肖像。
3. AI 生图服务配置只能放在制作环境变量或安全凭据中，不要把密钥写入工程、文档、日志或渲染输出。推荐变量名：`IMAGE_API_KEY`、`IMAGE_API_BASE_URL`、`IMAGE_API_MODEL`。
4. 所有生成图片需要保存原始提示词、生成时间、模型名和用途说明，放入最终素材授权说明中。
5. 视频缩略图和音频波形不需要真实长视频或真实音频文件；可以用 Canvas/Shader 生成可循环的微动画，但画面必须像真实内容，不像加载占位。

## 6. 动效和曲线

全片统一缓动：

1. 进入：`cubic-bezier(0.16, 1, 0.3, 1)`。
2. 退出：`cubic-bezier(0.7, 0, 0.84, 0)`。
3. 状态切换：`cubic-bezier(0.33, 1, 0.68, 1)`。

动作原则：

1. 每个镜头只保留一个明确视觉主语。
2. 卡片移动像系统级产品动效，不像游戏道具飞入。
3. 不使用弹簧过冲、高速旋转、翻牌、扑克牌飞散、粒子爆炸。
4. 每个镜头都要有开始姿态、主动作、收束姿态，转场动作必须为下一镜头服务。
5. 摄影机运动幅度宁少勿多，优先靠物体组织和构图变化推进叙事。

## 7. 分层渲染建议

推荐每个镜头按以下层级组织：

1. `BG`：冷白或冷灰背景、极低噪声、柔和环境渐变。
2. `DepthFragments`：远景信息碎片、半透明轮廓、轻失焦对象。
3. `MainCards`：主要卡片、内容块、封面。
4. `InteractionGuides`：插入线、连接线、指针、轻量标签。
5. `TextOverlay`：字幕和片尾品牌文字。
6. `LightFX`：局部高光、极光反射、接收状态亮起。

导出时保留可重渲染工程，并尽量保留关键分层，方便后期微调字幕、色彩和声音。

## 9. 验收口径

每个镜头完成后单独验收：

1. 画面是否一眼能看出本镜头视觉主语。
2. 字幕是否在横版、竖版、方版裁切安全区内。
3. 卡片是否轻薄、克制、统一。
4. 内容关系是否准确，基础内容块不能被误解为独立 `.card` 文件。
5. 动效是否平稳，没有明显卡顿、抖动、穿帮和重叠。
6. 没有真实第三方 App、商标、系统 UI 复制痕迹。
7. 没有密钥、开发日志、调试面板、临时标识出现在画面或工程公开文件中。
