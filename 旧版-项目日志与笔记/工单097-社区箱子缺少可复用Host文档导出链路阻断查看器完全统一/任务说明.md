# 工单097：社区箱子缺少可复用 Host 文档导出链路阻断查看器完全统一

## 背景

统一卡片查看器重构要求社区 `/cards/:cardId` 与 `/boxes/:boxId` 都通过 `com.chips.card-viewer` 应用插件查看内容，社区页面只负责解析资源与承载插件 iframe。

卡片已有 CDN `htmlUrl`，可以直接作为 `community-card.documentUrl` 交给 CardViewer。箱子当前只有数据库中的 metadata、structure、封面产物和引用列表，没有可交给 CardViewer 的正式箱子查看文档 URL。

## 证据

1. `Chips-CommunityPlatformServer/packages/server/src/services/box.service.ts` 在上传时解包 `.box` 后保存 metadata/structure，并删除上传临时文件。
2. `Chips-SDK/src/api/box.ts` 的 `box.documentWindow.render` 需要真实 `boxFile`，并通过 `box.openView` 建立 Host 会话。
3. `Chips-Host/packages/box-service/src/box-service.ts` 的 `box.renderLayoutFrame` 生成的是 Host 管理 render session 文档 URL，不是社区 Web CDN 可直接访问的发布文档。

## 影响范围

- 社区箱子详情页迁移到 CardViewer。
- 社区箱子发布态文档源生成。
- Host 箱子布局 render session 的 Web 导出能力。
- SDK / 共享文档对远程或社区箱子来源的正式描述。

## 复现步骤

1. 上传 `.box` 到社区服务器。
2. 查看数据库中的 box 记录，确认只有 metadata、structure、cover 相关字段。
3. 尝试创建 CardViewer `community-box` source，发现没有可传入的 `documentUrl`。
4. 尝试直接调用 `box.documentWindow.render`，发现需要本地 `boxFile` 和 Host 内部 render session，不适合当前社区 Web CDN 发布态。

## 期望行为

社区箱子应能通过正式 Host 箱子布局链路生成 Web 可访问文档源，再由 CardViewer 统一承载。Host 需要提供 render session Web 导出能力，社区服务器需要保存或重建 `.box` 正式输入，并把输出产物发布为稳定 `documentUrl`。

## 暂行处理

本轮先为社区发布态箱子补齐 `documentUrl` 字段与 CardViewer 统一承载入口，使用服务端根据已保存 metadata/structure 生成的只读文档源承载箱子摘要，不继续保留社区专属箱子详情 UI。后续 Host Web 导出能力补齐后，再替换为完全复用 `box.renderLayoutFrame` 的正式文档输出。
