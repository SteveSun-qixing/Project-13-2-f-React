# 工单108：视频资源首帧封面与缩略图正式模块能力缺口

## 背景

任务042迁移视频基础卡片插件时，需要让视频资源、封面、字幕和播放参数全部接入新基础卡片插件架构、组件库、主题 token、多语言和 SDK/Host 正式资源链路。

任务文档明确要求首帧、缩略图、转码或字幕解析等通用媒体能力通过 Host/模块正式接口处理。

## 原始证据

- 初始迁移实现曾在 `Chips-BaseCardPlugin/video-BCP/src/editor/panel.tsx` 上传视频后调用 `extractVideoCoverFile(...)`。
- 旧 `Chips-BaseCardPlugin/video-BCP/src/shared/video-cover.ts` 基于浏览器 `video + canvas` 抽取首帧并生成封面 `File`，现已移动到 `Chips-BaseCardPlugin/video-BCP/归档/video-cover-任务042-工单108-20260526.ts`，不再进入正式运行时代码。
- 初始核对 `Chips-SDK`、`Chips-Host`、`Chips-ModulePlugin` 和生态共用技术文档时，没有正式视频首帧抽取、缩略图生成或视频元数据预处理能力契约。

## 收口结果

- Host 已新增正式 `resource.extractVideoFrame` 服务动作、schema、route manifest、权限声明与 PAL `offscreenRender.extractVideoFrame(...)` 能力声明，路由权限为 `resource.read`、`file.read`、`file.write`，超时为 30 秒。
- Host 资源图像服务已把本地视频源识别、输出路径、覆盖策略和 PAL 错误归一为 `RESOURCE_VIDEO_FRAME_*` 错误命名空间，远程 URL 不再复用 TIFF 错误码。
- SDK 已新增 `client.resource.extractVideoFrame(...)` 类型化 API，并在 `client.card.editorPanel.render({ resources })` 的资源桥中新增 `extractVideoThumbnail` 动作；该动作支持显式回调，也支持 `rootPath + Host route` 回退路径。
- 官方编辑引擎本地 `BasecardEditorContext` 已注入 `extractVideoThumbnail(...)`，沿用 TIFF 转换模型：待导入源资源先暂存，调用 Host/SDK 抽帧，读回输出文件，排队写入卡片根目录，清理临时文件并释放旧资源 URL。
- `Chips-BaseCardPlugin/video-BCP` 上传视频后通过宿主 `ctx.extractVideoThumbnail` 生成默认 `cover_image`；若抽帧失败，视频导入仍保留，面板显示可恢复错误提示，用户可以手动上传封面。
- 生态共用技术文档 `生态共用技术文档/协议与契约/11-资源图像转换契约.md` 已沉淀 `resource.extractVideoFrame`、编辑器 `extractVideoThumbnail`、输入输出、权限、错误码、格式/尺寸/质量/时间参数、性能预算和基础卡片消费边界。
- 生态共用技术文档 `生态共用技术文档/插件开发/03-卡片插件开发.md` 已把 `extractVideoThumbnail(...)` 加入 `BasecardEditorContext` 正式资源型编辑能力集合。

## 影响范围

- `Chips-BaseCardPlugin/video-BCP`
- 视频播放器应用从 `chips.video-card` payload 恢复上下文的封面与字幕体验
- 资源管理器未来视频缩略图
- 卡片封面自动生成
- SDK/Host/模块插件媒体预处理能力

## 复现步骤

1. 打开 `Chips-BaseCardPlugin/video-BCP/归档/video-cover-任务042-工单108-20260526.ts`。
2. 确认旧视频封面生成只能由插件内部浏览器 API 完成，不能作为正式公共能力沉淀。
3. 搜索 Host/SDK/模块插件，确认没有正式视频抽帧或缩略图生成接口。
4. 对照任务042要求，确认通用媒体预处理能力缺口仍存在。

## 期望行为

- 新增正式 Host/模块能力，例如 `media.video.thumbnail.extractFrame` 或同等稳定接口。
- SDK 提供类型化封装。
- 编辑引擎 `BasecardEditorContext` 或资源桥按正式契约注入该能力。

- 公共技术文档补齐格式支持、输入输出、错误码、性能预算和测试素材要求。

## 历史暂行处理

- 任务042本轮不绕开资源链路：视频、封面和字幕仍只通过 `importResource(...)` 写入卡片根目录，删除通过 `deleteResource(...)`，查看态打开通过 `openResource(...)`。
- 任务042已从正式代码中移除插件内浏览器抽帧，视频导入只写入视频资源并清空旧封面，查看态可继续回退显示视频首帧。
- 后续正式视频预处理能力落地后，应通过 Host/模块接口生成缩略图并由基础卡片编辑器调用该正式能力。
