# 工单105：Host对外接口基线漏列command子域与设置面板权限基线漂移

## 1. 背景

任务028.05 需要验证生态设置面板在正式 Host/SDK 权限治理下的 Scene command 注册、调用、权限不足和 Host smoke 链路。复核公共文档与当前代码时发现，`command` 服务域已经在 Bridge、Host 服务域、SDK route manifest 和设置面板 manifest 中落地，但 `06-Chips-Host对外接口基线.md` 与 `07-运行时设置治理接口标准.md` 没有同步更新。

## 2. 证据

- `生态共用技术文档/协议与接口标准/02-Bridge-API规范.md` 已列出 `command` 子域，并定义 `command.register/unregister/get/list/setState/invoke` 与 `command.read/write/invoke/manage`。
- `生态共用技术文档/架构设计/14-Host服务域设计.md` 已将 `command` 列为第 6 个 Host 服务域。
- `Chips-SDK/src/contracts/route-manifest.json` 已包含 `command.get/list/register/unregister/setState/invoke` 正式路由。
- `Chips-EcoSettingsPanel/manifest.yaml` 已声明 `command.read`、`command.write`、`command.invoke`。
- `Chips-EcoSettingsPanel/src/commands/useSettingsCommands.ts` 已通过 `client.command.register/onInvoked/unregister/invoke` 消费正式 SDK Domain API。
- `生态共用技术文档/协议与接口标准/06-Chips-Host对外接口基线.md` 的 Bridge 子域和公开服务命名空间未列 `command`。
- `生态共用技术文档/协议与接口标准/07-运行时设置治理接口标准.md` 的最小权限仍缺少 `platform.external` 与 `command.read/write/invoke`。

## 3. 影响范围

- 设置面板权限不足测试与 Host smoke 的公共口径。
- 后续应用插件迁移任务的 command 权限声明。
- 应用脚手架、组件库命令入口、Host/SDK 公共文档的一致性。

## 4. 复现步骤

1. 核对 `02-Bridge-API规范.md` 和 `14-Host服务域设计.md`，确认 `command` 已是正式子域/服务域。
2. 核对 `Chips-SDK/src/contracts/route-manifest.json`，确认 command 路由和权限已落地。
3. 核对 `Chips-EcoSettingsPanel/manifest.yaml`，确认设置面板已经声明 command 权限。
4. 打开 `06-Chips-Host对外接口基线.md`，确认漏列 `command`。
5. 打开 `07-运行时设置治理接口标准.md`，确认设置面板 vNext 最小权限未包含 `platform.external` 与 `command.read/write/invoke`。

## 5. 期望行为

- `command` 必须被纳入 Host 对外接口基线的 Bridge 子域和公开服务命名空间。
- 设置面板 vNext 最小权限必须包含 `platform.external` 与 `command.read/write/invoke`。
