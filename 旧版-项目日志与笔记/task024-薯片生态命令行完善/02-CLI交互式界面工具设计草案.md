# CLI 交互式界面工具设计草案

## 1. 目标

`chips` 与 `chipsdev` 在不带任何子命令、直接回车时，应进入一个键盘优先的终端交互界面。该界面用于帮助用户逐级构建命令、理解可用插件能力、填写参数并执行命令。

目标不是替代传统 CLI，而是补齐一种更适合探索、选择、配置和低记忆负担使用的模式。用户仍然可以直接输入完整命令并执行。

## 2. 入口

```bash
chips
chipsdev
```

进入界面后：

- `chips` 读取用户工作区插件命令索引；
- `chipsdev` 读取开发工作区插件命令索引；
- 两者使用同一套交互模型；
- 两者只访问各自工作区，不互相污染。

## 3. 基础布局

界面采用上下结构：

```text
┌────────────────────────────────────────────────────────────┐
│ chips icon generate --formats png,ico                      │
├────────────────────────────────────────────────────────────┤
│ › generate   生成图标资源                                  │
│   inspect    检查图标源文件                                │
│   presets    查看可用预设                                  │
└────────────────────────────────────────────────────────────┘
```

顶部是命令框：

- 显示当前正在构建的完整命令；
- 用户可以直接输入、删除、移动光标；
- 当命令满足执行条件时，按回车执行；
- 当命令尚未满足执行条件时，按回车优先选择当前列表项或进入下一层。

下方是上下文列表：

- 初始展示一级或二级命令关键词；
- 选择某个命令后展示下一层命令、参数或控件；
- 当前选中项使用高亮；
- 每一项显示关键词、简短说明、来源插件和必要状态。

## 4. 命令构建流程

### 4.1 直接拼写

用户可以像普通 CLI 一样直接输入：

```bash
chips icon generate app.svg --formats png,ico --out ./dist
```

界面根据输入实时解析：

- 高亮已识别片段；
- 标出缺失参数；
- 展示可继续补全的选项；
- 命令完整时显示可执行状态。

### 4.2 列表选择

用户可以使用方向键选择列表中的项：

- `↑ / ↓`：移动选中项；
- `Enter`：选择当前项并追加到命令框；
- `Esc`：返回上一级或关闭弹层；
- `Backspace`：删除命令片段；
- `Tab`：补全当前高置信候选；
- `Ctrl+C`：退出界面或取消正在执行的任务；
- `Ctrl+L`：清空当前命令；

当前正式口径：TUI 不提供历史命令搜索或回放入口，CLI / TUI 的执行、补全和错误结果进入 Host 统一操作日志。

### 4.3 层级推进

命令树按层级推进：

```text
chips
  icon
    generate
      <input>
      --formats
      --out
      --background
```

每次选择后：

- 命令框自动拼接对应片段；
- 下方列表切换为下一层可选项；
- 如果下一项是参数，则显示对应控件；
- 如果命令已经可执行，则显示执行状态和可选参数。

## 5. 参数控件

交互式界面需要支持多种终端控件。控件由 CLI 扩展声明和参数 schema 驱动。

### 5.1 单选列表

用于选择枚举值：

```text
输出格式
› png
  ico
  icns
  iconset
```

### 5.2 多选列表

用于选择多个格式或能力：

```text
输出格式
☑ png
☑ ico
☐ icns
☐ iconset
```

键盘：

- `Space`：切换选中；
- `Enter`：确认。

### 5.3 开关

用于布尔参数：

```text
圆角蒙版  [开]
柔和阴影  [关]
```

键盘：

- `Space` / `Enter`：切换。

### 5.4 数字步进

用于尺寸、数量、质量等数值：

```text
尺寸: 512
```

键盘：

- `← / →`：减少或增加；
- `Shift+← / Shift+→`：大步进；
- 直接输入数字覆盖。

### 5.5 左右滑动条

用于比例、质量、透明度等连续数值：

```text
压缩质量: [██████────] 60
```

键盘：

- `← / →`：调整；
- `Home / End`：最小或最大。

### 5.6 路径粘贴框

用于输入文件或目录：

```text
输入文件: /Users/demo/app.svg
```

能力：

- 支持直接粘贴；
- 支持拖入终端后解析路径；
- 支持相对路径；
- 支持路径存在性校验；
- 可调用 Host/CLI 工作区路径规范化。

### 5.7 多行粘贴框

用于 JSON、批量路径、长文本：

```text
粘贴 JSON 输入，按 Ctrl+D 结束
```

要求：

- 不破坏 shell；
- 支持取消；
- 支持 schema 校验错误定位。

## 6. 可执行状态

界面需要明确告诉用户当前命令是否可执行：

```text
状态: 缺少 input 参数
状态: 可执行，按 Enter 运行
状态: 需要安装或启用插件 com.chips.icon
状态: 缺少 file.write 权限
```

命令执行前应完成：

- 命令路径解析；
- 插件来源确认；
- 权限检查；
- 参数 schema 校验；
- 路径规范化；
- 输出冲突检查。

## 7. 执行结果

执行后界面显示：

- 标准输出；
- 错误信息；
- 生成文件路径；
- job 进度；
- 可复制的最终命令；
- 重新执行、编辑参数、退出等动作。

## 8. 插件声明需要补充的元数据

为驱动交互式界面，CLI 扩展声明不能只有命令路径，还需要：

- 命令标题、说明、示例；
- 参数类型；
- 参数必填状态；
- 参数默认值；
- 参数分组；
- 参数控件建议；
- 参数校验规则；
- 参数之间的依赖关系；
- 执行前确认规则；
- 输出说明；
- job 支持策略；
- 命令来源插件；
- app target 或 module target。

## 9. 应用插件命令场景

应用插件可声明需要界面参与的命令：

```bash
chips editor open demo.card --scene edit
```

执行策略可以是：

- 打开新 surface；
- 复用已打开 surface；
- 聚焦应用；
- 投递 command payload；
- 等待应用返回 ack；
- 若应用命令启动 Host job，则 CLI 进入 job 进度展示。

应用插件不得让 CLI 直接 import 应用源码；必须通过 Host surface、plugin launch 或 command registry 正式链路。

## 10. 模块插件命令场景

模块插件可声明无界面能力命令：

```bash
chips icon generate app.svg --out ./dist
```

执行策略：

- CLI 将参数映射为 module input；
- Host 解析 provider；
- Host 执行 schema 校验、权限校验和 job 治理；
- CLI 展示结果或 job 进度。

模块插件不得独立实现绕过 Host 的系统 CLI 程序。

## 11. 后续验证目标

- `chips` 空命令进入用户态交互界面；
- `chipsdev` 空命令进入开发态交互界面；
- 可通过键盘选择二级、三级指令；
- 可通过控件填写路径、枚举、多选、布尔、数字和长文本；
- 可执行 app target 命令；
- 可执行 module target 命令；
- 可显示 job 进度和取消；
- 可输出最终可复制命令；
- 可在无交互环境下自动退回 help 或报错，避免阻塞 CI。
