# 工单128：箱子格式不支持内嵌卡片阻断混合存储与散落卡片收集

## 背景

产品要求箱子支持把卡片实体直接保存在 `.box` 文件根目录（内嵌），并支持与 URL 引用混用。当前格式规范、设计原稿与 Host 校验都禁止 `.card` 进入 `.box`，编辑引擎也没有"添加内嵌卡片"能力。

## 证据

1. `生态共用技术文档/文件格式规范/02-箱子文件格式规范.md` §4.4、§11.3：禁止 `*.card` 进入包内。
2. `生态设计原稿/06-箱子文件格式.md`：箱子不保存卡片实体。
3. `Chips-Host/packages/box-service/src/box-service.ts:1613`：`validateZipEntries` 拒绝 `.card`/`.box` 条目。
4. `Chips-Host/packages/box-service/src/box-service.ts:1799,1924`：`assertSupportedUrl` 只接受绝对 URL。
5. `Chips-EditingEngine/src/services/box-document-service.ts:209`：`serializeEntry` 只支持 URL 条目。

## 影响范围

- 文件格式规范、设计原稿
- `Chips-Host/packages/box-service/src/box-service.ts`
- `Chips-SDK/src/api/box.ts`
- `Chips-EditingEngine/src/services/box-document-service.ts`

## 期望行为

- 规范允许 `.card` 位于 `.box` 根目录或任意层级（禁止 `.box` 内嵌，防循环）；
- structure.yaml 条目 `url` 支持包内相对路径（如 `cards/day-01.card`）；
- Host 校验/解析/封面/打开/资源链路支持内嵌条目；
- 编辑引擎支持添加内嵌卡片（复制卡片到工作目录 + 登记条目）。
