# 工单166：Host 资源 MIME 推断与办公处理器路由冲突

## 基本信息

- 工单编号：工单166
- 日期：2026-09-01
- 发现阶段：资源打开契约审查
- 问题类型：Host 公共路由契约与插件 manifest 不一致
- 状态：待处理

## 问题描述

`Chips-Host/packages/resource-open-service/src/resource-open-service.ts` 的私有 `MIME_BY_EXTENSION` 仅覆盖少量图片、电子书、DOCX/PDF 类型，缺少 `.xlsx`、`.xlsm`、`.csv`、`.pptx`、`.ppt`、`.mp4`、`.webm`、`.mov`、`.tif/.tiff` 等正式处理器扩展。共享 MIME 表同样未完整覆盖办公类型。

当调用方只提供 opaque `resourceId` 且未显式 `mimeType` 时，Host 无法稳定命中 `Chips-Sheet`/`Chips-Slide`；当前只能依赖本地绝对路径或上游额外注入 MIME，违背资源打开契约的统一路由预期。

同时 `Chips-BookReader/manifest.yaml` 仍以 primary 能力声明 PDF、DOC、DOCX（resource-handler 与 file-handler），会与 `com.chips.pdf`、`com.chips.word` 竞争同一扩展名，处理器选择结果依安装顺序变化。

## 期望行为

- 统一 Host 与共享层 MIME/扩展名推断表，并覆盖全部官方查看器与四个办公插件；
- 增加 opaque resourceId 无 MIME 时的路由回归测试；
- 删除 BookReader 的 PDF/DOC/DOCX primary 声明，或按正式契约改为 fallback 能力；
- 明确处理器优先级并在 resolver 集成测试中锁定 `com.chips.pdf` / `com.chips.word` / `com.chips.sheet` / `com.chips.slide` 命中结果。

## 暂行处理

四个新插件当前继续支持显式 `resourceOpen.mimeType`、文件名扩展名和真实本地路径；不在插件内猜测 Host 处理器，也不修改 BookReader manifest 规避公共路由问题。

## 需要协作方

Chips-Host resource-open-service、Chips-SDK/共享 MIME 契约、Chips-BookReader 与四个办公插件维护方。
