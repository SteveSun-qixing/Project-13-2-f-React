# 工单118-社区服务器本地启动链路阻断

## 背景

2026-06-29 启动本地 `Chips-CommunityPlatformServer` 社区服务器时，按项目内部运行文档核对了本地开发链路：

- Docker 基础设施：PostgreSQL、Redis、MinIO；
- API：`pnpm --filter @ccps/server dev`；
- Worker：`pnpm --filter @ccps/server worker:dev`；
- 社区前台：`pnpm --filter @ccps/web dev`；
- 管理后台：`pnpm --filter @ccps/admin dev`。

基础设施和 Vite 前端可启动，但 API 与 Worker 被当前代码和生态依赖状态阻断。

## 证据

### 1. 基础设施与前端可启动

`docker compose --env-file deploy/.env -f deploy/docker-compose.yml ps` 显示：

- `ccps_postgres`：healthy，映射 `5432`;
- `ccps_redis`：healthy，映射 `6380`;
- `ccps_minio`：healthy，映射 `9000/9001`。

前台与后台启动后可访问：

- `http://localhost:5173/` 返回 `HTTP/1.1 200 OK`;
- `http://localhost:5174/admin/` 返回 `HTTP/1.1 200 OK`。

### 2. API 被 TypeScript 语法错误阻断

执行：

```bash
pnpm --filter @ccps/server dev
```

报错：

```text
Error: Transform failed with 1 error:
packages/server/src/services/box.service.ts:266:10: ERROR: Expected ":" but found ";"
```

对应源码片段位于 `Chips-CommunityPlatformServer/packages/server/src/services/box.service.ts` 的 `BoxService.enrichCardRefs()`，`communityCards` 三元表达式没有完整的 `: []` 分支，且后续出现了残留的 `return { ...ref }` / `cardsByFileId` 逻辑片段。

结果：

- API 未监听 `3000`;
- `curl http://127.0.0.1:3000/api/v1/health` 超时失败。

### 3. Worker 被默认主题契约门禁阻断

执行：

```bash
pnpm --filter @ccps/server worker:dev
```

Worker 已完成：

- 数据库迁移；
- Redis 连接；
- 对象存储 bucket 初始化；
- Host 集成层插件安装。

随后在应用默认主题时报错：

```text
[CardRenderWorker] Failed to start:
code: THEME_CONTRACT_INVALID
message: Theme contract validation failed: missing required tokens
route: theme.apply
themeId: chips-official.default-theme
```

涉及链路：

- `Chips-CommunityPlatformServer/packages/server/src/services/host-integration.ts`;
- `Chips-CommunityPlatformServer/packages/server/src/config/env.ts`;
- `ThemePack/Chips-default`;
- `Chips-Host/src/main/theme-runtime/contract-guard.ts`;
- `Chips-Host/src/main/services/register-host-services.ts`。

### 4. `chips-host` file 依赖快照缺失构建产物

初次启动 API 与 Worker 时，二者都报：

```text
Error: Cannot find module '../../../src/shared/theme-css-units'
Require stack:
.../node_modules/.pnpm/chips-host@file+..+Chips-Host_.../node_modules/chips-host/dist/packages/card-service/src/card-service.js
```

核对结果：

- `Chips-Host/src/shared/theme-css-units.ts` 存在；
- `Chips-Host/dist/src/shared/theme-css-units.js` 与 `.d.ts` 存在；
- `Chips-CommunityPlatformServer/node_modules/.pnpm/.../chips-host/dist/src/shared/` 中缺少该文件；
- 对比源仓 `dist` 与社区项目 `node_modules` 快照，快照缺失 28 个构建文件。

为继续定位后续阻断，曾将 `../Chips-Host/dist` 同步到社区项目的 `chips-host` file 依赖快照中。该动作只影响本机 `node_modules` 安装产物，不是正式源码修复。

### 5. 独立 `pnpm install` 无法解析生态本地组件库

执行：

```bash
pnpm install
```

报错：

```text
ERR_PNPM_FETCH_404 GET https://registry.npmmirror.com/@chips%2Fcomponent-library: Not Found - 404
This error happened while installing the dependencies of chips.basecard.richtext@0.1.0
```

原因指向：

- `Chips-BaseCardPlugin/richtext-BCP/package.json` 依赖 `"@chips/component-library": "0.1.0"`；
- 社区服务器是独立 `pnpm-workspace.yaml`，只包含 `packages/*`；
- `@chips/component-library` 是生态本地包，位于 `Chips-ComponentLibrary/packages/component-library`，没有被社区项目独立 workspace 正式解析。

## 2026-06-29 追加调查结论

### 1. API 语法错误来源

结论：这是已提交源码回归，不是本机环境问题。

证据：

- 当前 `git status --short -- Chips-CommunityPlatformServer/packages/server/src/services/box.service.ts` 无输出，说明该文件没有本地未提交改动；
- `git blame -L 248,288 -- packages/server/src/services/box.service.ts` 显示错误片段来自 `54623dd9 重构社区服务端上传会话与渲染缓存链路`；
- `git show 54623dd9^:Chips-CommunityPlatformServer/packages/server/src/services/box.service.ts` 中该段原本是：

```ts
const communityCards = cardFileIds.length
  ? await db.query.cards.findMany(...)
  : [];
const cardsByFileId = new Map(
  communityCards
    .filter((card) => card.cardFileId)
    .map((card) => [card.cardFileId as string, card]),
);
```

- `git show 54623dd9 --word-diff` 显示该提交把 `: []` 与 `cardsByFileId` 构造删掉，并插入了一段无法成立的 `return { ...ref }` 片段；
- `pnpm --filter @ccps/server build` 同样报 `TS1005 ':' expected` 等语法错误。

判断：

- “之前可以启动”对应的是 `54623dd9` 之前的版本，或该错误提交前的本地代码；
- 当前 HEAD 的 API 无法启动是源码层面的确定性问题。

### 2. 默认主题契约失败来源

结论：Worker 失败的直接原因是社区项目 `node_modules` 中的默认主题 file 依赖快照过期，不是 Docker、Redis、MinIO 或数据库问题。

关键证据：

- `ThemePack/Chips-default/dist/tokens.json` 当前大小约 63KB，包含 `avatar`、`badge`、`box`、`combo-box`、`rating` 等 71 个组件 token；
- 用 Host `resolveThemeFromLayers` 等价算法展开当前源仓 `dist/tokens.json` 后，`theme-interface.contract.json` 的 722 个 required token 全部覆盖，缺失数为 0；
- 但 Worker 实际安装目录 `Chips-CommunityPlatformServer/packages/server/.chips-server-host-worker/plugins/theme.theme.chips-official-default-theme/dist/tokens.json` 只有约 20KB，只包含 32 个旧组件 token，缺少 `avatar`、`badge`、`box`、`combo-box`、`rating` 等大量组件，展开后缺 538 个 required token；
- 社区项目 `node_modules/.pnpm/theme.theme.chips-official-default-theme@file+..+ThemePack+Chips-default_.../node_modules/theme.theme.chips-official-default-theme/` 中没有 `dist/tokens.json`，且其内容与源仓当前文件集明显不同步；
- `HostIntegrationService.preparePluginInstallSource()` 安装目录型主题时，会从其 `manifest.yaml` 声明的首段资源根复制资产，实际使用的是 pnpm file 依赖快照，而不是源仓最新 `ThemePack/Chips-default`。

补充说明：

- 2026-06-29 复核执行 `ThemePack/Chips-default npm run validate:theme`，当前结果为通过：`Theme contract validation passed: 71 components, 722 required tokens.`；
- 因此默认主题源仓当前不是 538 个 required token 缺失的来源；Worker 的 538 个缺失来自其已安装运行目录中的旧 `dist/tokens.json`。

判断：

- “之前可以启动”很可能依赖旧的主题 contract 与旧主题 token 快照彼此匹配；
- 后续默认主题源仓升级后，社区项目 pnpm file 快照没有同步，导致 Host 运行时读取旧 token 对新 contract，触发 `THEME_CONTRACT_INVALID`。

### 3. `chips-host` 快照缺构建产物来源

结论：同样是社区项目 pnpm `file:` 依赖快照过期。

证据：

- 初次启动 API / Worker 时，`chips-host/dist/packages/card-service/src/card-service.js` 运行时 `require('../../../src/shared/theme-css-units')` 失败；
- `Chips-Host/src/shared/theme-css-units.ts` 与 `Chips-Host/dist/src/shared/theme-css-units.js` 在源仓存在；
- 社区项目 `node_modules/.pnpm/chips-host@file+..+Chips-Host_.../node_modules/chips-host/dist/src/shared/` 初始缺少该构建产物；
- 将 `../Chips-Host/dist` 同步到该快照后，`theme-css-units.js` 缺失问题消失，后续才暴露 API 语法错误和 Worker 主题门禁错误；
- 同步后对比源仓和快照，快照仍缺少新 `.ts` 源文件，但运行所需 `dist/src/shared/theme-css-units.js` 已存在。

判断：

- 这是本机社区项目 `node_modules` 里的 pnpm file 包快照没有随 `Chips-Host` 构建产物更新；
- 不应把手动复制 `dist` 视为正式修复，正式修复应让依赖安装/构建链路可重复生成正确快照。

### 4. `pnpm install` 404 来源

结论：社区服务器作为独立 pnpm workspace 时，不具备解析整个生态本地包的完整规则。

证据：

- 根工作区 `package.json` 使用 npm workspaces，包含 `Chips-ComponentLibrary/packages/*`、`Chips-BaseCardPlugin/*`、`Chips-ModulePlugin/*` 等；
- 根目录 `node_modules/@chips/component-library` 是指向 `Chips-ComponentLibrary/packages/component-library` 的 npm workspace 链接；
- `Chips-CommunityPlatformServer/pnpm-workspace.yaml` 只包含 `packages/*`；
- `Chips-CommunityPlatformServer/pnpm-lock.yaml` 中没有 `@chips/component-library`、`@chips/theme-contracts`、`chips-sdk` 记录；
- 基础卡片插件如 `Chips-BaseCardPlugin/richtext-BCP/package.json` 依赖 `"@chips/component-library": "0.1.0"` 和 `"chips-sdk": "^0.1.0"`；
- 在 `Chips-CommunityPlatformServer` 内执行 `pnpm install` 时，pnpm 只能把这些依赖当远端包解析，于是访问 `https://registry.npmmirror.com/@chips%2Fcomponent-library` 并返回 404。

判断：

- 旧的社区 `node_modules` 能跑到某些阶段，是因为已有 pnpm file 快照留存，而不是当前文档化的独立 pnpm 安装链路可从干净环境重建；
- 只执行 `pnpm install` 无法刷新 Host / ThemePack 快照，反而会被生态本地包解析缺口阻断。

1. 修复 API 源码语法错误；
2. 为社区项目补齐正式依赖解析策略，例如把必要生态本地包纳入 pnpm workspace、使用明确 `file:` 依赖，或改为从根 npm workspace 统一安装；
3. 为社区 Worker 增加默认主题安装前后的快照一致性校验，确保实际安装目录中的 `dist/tokens.json` 与当前 ThemePack 构建产物一致，并通过 Host `theme.apply` 门禁；

5. 增加 CI/本地验证，至少覆盖 `pnpm --filter @ccps/server build`、Worker Host theme apply、干净安装或等价依赖校验。

风险：

- 涉及社区项目、Host、ThemePack、组件库/插件依赖治理，范围比单纯启动更大，但这是可长期稳定的方向。
