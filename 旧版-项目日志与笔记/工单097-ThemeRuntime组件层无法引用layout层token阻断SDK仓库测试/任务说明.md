# 工单097：ThemeRuntime 组件层无法引用 layout 层 token 阻断 SDK 仓库测试

## 背景

在执行 task022 `任务001-Host服务域与Bridge契约审计` 时，Host/SDK route manifest 漂移已经收口，但继续执行 `cd Chips-SDK && npm test` 时，SDK 的 host-managed CLI 测试在主题命令阶段失败。

## 证据

失败命令：

```bash
cd Chips-SDK && npm test
```

关键错误：

```text
THEME_TOKEN_MISSING
Token "chips.comp.grid.root.gap" references missing token
details.lastError.value = "{chips.layout.gap.md}"
```

已核对：

- `ThemePack/Chips-default/tokens/layout.json` 已定义 `chips.layout.gap.md`。
- `ThemePack/Chips-default/tokens/comp/grid.json` 使用 `{chips.layout.gap.md}`。
- `Chips-Host/src/main/theme-runtime/resolve-algorithm.ts` 当前先解析 `comp`，后解析 `layout`，导致组件层引用布局层时被错误判定为缺失。

## 影响范围

- Host L11 Theme Runtime 的五层 token 解析。
- 默认主题与暗夜主题等正式主题包。
- `chipsdev theme current/apply/resolve` 等 CLI 链路。
- SDK 仓库正式 `npm test`。
- 后续组件 token 对 `chips.layout.*`、`chips.motion.*` 公共 token 的正式复用能力。

## 复现步骤

1. 进入 `Chips-SDK`。
2. 执行 `npm test`。
3. 观察 `run-cli-host-managed-tests.cjs` 失败。
4. 检查错误中的 `chips.comp.grid.root.gap -> {chips.layout.gap.md}`。
5. 检查默认主题 `tokens/layout.json`，确认 `chips.layout.gap.md` 实际存在。
6. 检查 Theme Runtime 解析顺序，确认 `comp` 早于 `layout` 被解析。

## 期望行为

- Theme Runtime 应先解析 `ref/sys`，再解析不依赖组件层的 `motion/layout`，最后解析 `comp`。
- 组件层可以稳定引用 `chips.layout.*` 与 `chips.motion.*`。
- 不允许在主题包里把合法引用改成硬编码值绕过运行时缺陷。
- SDK 官方测试恢复通过。

## 暂行处理

按用户最新要求，本工单登记后直接修复，不暂停等待。

## 需要协作方

- Host Theme Runtime 维护方
- 主题包维护方
- SDK CLI 测试维护方

## 当前状态

已解决。

## 处理结果

1. `Chips-Host/src/main/theme-runtime/resolve-algorithm.ts` 已将五层 token 解析顺序调整为 `ref -> sys -> motion/layout -> comp`。
2. `comp` 层解析时合并 `ref/sys/motion/layout` 已解析 token，组件 token 可正式引用 `chips.layout.*` 与 `chips.motion.*`。
3. `Chips-Host/tests/unit/theme-runtime.test.ts` 已补充 `chips.comp.grid.root.gap -> {chips.layout.gap.md}` 回归测试。
4. 已同步更新：
   - `Chips-Host/技术文档/15-主题运行时实现说明.md`
   - `生态共用技术文档/架构设计/15-主题系统设计.md`
   - `生态共用技术文档/组件库/03-Token与主题对接标准.md`
