> 本文件汇总重构过程中的风险、常见坑与边界情况，供主代理与子代理执行时对照。执行中发现新风险时回写本文件。

## 2. 常见坑（子代理必读）

1. **antd 版本 API 差异**：`Flex` 需 antd ≥5.10；`Table virtual` 需 ≥5.9；Segmented 的 `value` 而非 `defaultValue` 语义——以 M1 锁定版本的官方文档为准；
2. **Form 的受控陷阱**：antd `Form` 的 `initialValues` 只生效一次；用 `form.setFieldsValue` 或 `onValuesChange` 双向控制（04-8 节做法 B）；
3. **Modal 的 open 控制**：旧 `visible` → antd `open`；`onCancel` 必传，否则点遮罩/关闭无响应；
4. **message/notification 在 React 18 StrictMode 下的静态方法警告**：统一用 antd `App` 组件包裹 + `App.useApp()`（08-2 节）；
5. **Select 的 option 结构**：antd 用 `{ label, value }`，注意 `children` 写法迁移；
6. **Popover/Dropdown 定位**：Electron 窗口边缘可能裁剪，`getPopupContainer` 绑定 `#root`（02-4.2 节）；
7. **图标语义化**：替换 `ChipsIcon` 时选语义正确的图标（如 `MoreOutlined`、`CloseOutlined`），不要用 `QuestionCircleOutlined` 代替功能图标；图标名在重构完成后由走查核对；
8. **Typography 溢出**：长标题用 `ellipsis`；不要用 `word-break` 破坏中文排版；
9. **CSS-in-JS 与 CSP**：antd 需要 `style-src 'unsafe-inline'`（已允许）；不要新增 `unsafe-eval`；
10. **测试中的 async**：antd 弹层动画导致 `fireEvent` 后元素未出现——用 `await screen.findBy*` 或 `waitFor`；现有测试模式保持不变，只在需要时调整等待方式；
11. **React key**：antd 列表/表格用 `rowKey`/`key` 字段，缺失会导致渲染错乱（参考工单 115 的教训）；
12. **归档路径**：删除的文件必须移入归档，禁止 `rm`。

## 3. 边界情况

1. **空数据/大数据的渲染**：DataGrid→Table 时保留分页/空态/加载态；VirtualList 场景（book-BCP 书目、iconMaker 场景列表）按数据量选择 Table virtual 或 List；
2. **不可见的 UI 状态**：`disabled`、`readOnly`、`loading`、拖拽状态（drag-over）必须保留视觉与语义；
3. **键盘导航**：antd 组件自带键盘支持；自定义交互（如播放器快捷键）保持原行为，不因 antd 而丢失；
4. **窗口控制**：Electron 无边框窗口的拖拽区（`-webkit-app-region: drag`）与菜单栏布局保持；
5. **缩略图/封面**：视频首帧、音乐封面、图片缩略图的渲染链路不动（工单 108 相关能力是业务功能）；
6. **右键菜单**：原 `ChipsContextMenu` 用 antd `Dropdown trigger=contextMenu` 等价实现，禁止用浏览器原生菜单替代；
7. **多选/批量操作**（社区作品、卡片列表）：`Checkbox` 状态管理与批量操作按钮逻辑等价迁移；
8. **表单校验文案**：antd 校验消息默认中文（zhCN），自定义规则消息写中文；
9. **`window.chips` 在纯浏览器环境缺失**：CommunityClient 等需在浏览器运行的场景，`ChipsProvider` 必须提供"无 Host 降级态"（等价现状 mock/降级行为，不能因此崩溃）。

## 4. 停止条件（触发即停止当前批，上报用户）

1. 共享层缺口（子代理需要但未冻结的新组件/API）；
2. Host/SDK 契约与计划假设不符（权限、类型、命令）；
3. 用户决策点未定（packages/web 纳入等）导致范围不清；
4. 单仓出现超出任务卡的改动需求（如发现该仓库有其他隐藏依赖）。

## 5. 回滚与安全网

1. Git 分支与提交由用户管理；每批开始前由用户确认当前分支干净（或建立 task030 专用分支，命名 `task030-卸担计划-antd重构` 待用户确认）；
2. 每批完成但未验收时，仓库保留可回滚点（由用户决定提交时机）；
3. 重构前后各仓库的 `tests/` 是等价性的自动保险，任何批次的测试失败 = 停止并审查；
4. 严禁对归档目录做任何修改。
