# 09-基础卡片与布局插件重构标准

> 本文件定义 BCP（基础卡片插件 ×8）与 BLP（布局插件 ×11）的重构标准。两者体量小、结构高度同构（脚手架生成），适合批量处理；但涉及**卡片/箱子运行时契约**，必须严格等价还原。
> 参考文档：生态共用技术文档/插件开发/03-卡片插件开发.md、04-布局插件开发.md。

---

## 1. BCP 结构（重构前后）

```
book-BCP/           (8 个同类)
├── manifest.yaml   # type: card；权限调整同 05-5/08-4
├── src/
│   ├── render/
│   │   └── view.tsx        # 卡片渲染视图（antd 化）
│   ├── editor/
│   │   └── panel.tsx       # 编辑面板（antd 化，04-8 节做法 A）
│   └── (业务逻辑目录，不动)
└── tests/
```

### 1.1 渲染视图等价还原要点

- 渲染视图是"卡片在查看器/编辑器中的外观"，**视觉与交互必须原样还原**（卡片格式与渲染契约不变）；
- `ChipsImage`→`Image`、`ChipsBadge`→`Tag`、`ChipsButton`→`Button`、`ChipsIcon`→`@ant-design/icons`、`ChipsEmptyState`→`Empty`、`ChipsProgress`→`Progress`、`ChipsRating`→`Rate`、`ChipsText`→`Typography.Text`；
- 渲染容器的尺寸/布局语义（如封面图比例、元信息区）用 CSS 原样还原，不改变 DOM 结构与数据绑定；
- 渲染视图**不得**依赖 `window.chips.*` 以外的运行时，不得引入 antd 弹层（卡片渲染场景不需要）。

### 1.2 编辑面板等价还原要点

- 面板字段、默认值、校验、联动逻辑原样迁移；
- 表单实现按 04-8 节做法 A（受控 State）为主，面板 `onChange` 语义保持；
- `ChipsToolbar`（音乐卡片等）→ 共享层 `Toolbar`；
- `ChipsErrorState` → `Result` + 重试；
- `ChipsVirtualList`（book-BCP 的书目列表）→ `Table`/`List` 按数据量选择；
- 面板测试（tests/）同步更新（11 章）。

## 2. BLP 结构（重构前后）

```
grid-BLP/           (11 个同类)
├── manifest.yaml   # type: layout
├── src/
│   ├── view/
│   │   └── page.tsx            # 布局渲染页（antd 化）
│   ├── editor/
│   │   ├── panel.tsx           # 布局配置面板
│   │   └── frame-region-editor.tsx  # 帧区域编辑（ChipsForm 等）
│   └── shared/
│       └── frame-region.tsx    # EmbeddedDocumentFrame 容器（换共享层实现）
└── tests/
```

### 2.1 特殊点：EmbeddedDocumentFrame

- 所有 BLP 的 `view/page.tsx` 与 `shared/frame-region.tsx` 引用 `EmbeddedDocumentFrame`（卡片嵌入帧）；
- 统一替换为 `@chips/ui` 的 `EmbeddedDocumentFrame`，**调用参数、渲染语义、交互回调**原样迁移（接口以试点收口后的共享层 API 为准）；
- frame-region 的标题栏/操作按钮（添加卡片、移除、缩放）antd 化，交互与数据回调不动。

### 2.2 布局渲染页

- 各布局形态（grid/masonry/coverFlow/timeline/cardStack/map/scattered/list/documentLibrary/infiniteCanvas）的布局算法与 CSS 效果是**业务核心**，只做组件替换，不得改布局计算逻辑；
- `ChipsButton`→`Button`、`ChipsCheckbox`→`Checkbox` 等按 04 章映射；
- 布局页 CSS 保留（局部），仅移除 `--chips-sys-*` 引用。

### 2.3 编辑面板

- 同 BCP 1.2 节规则；`ChipsSegmentedControl`→`Segmented`、`ChipsNumberInput`→`InputNumber`、`ChipsSelect`→`Select`、`ChipsCheckbox`→`Checkbox`、`ChipsTextArea`→`Input.TextArea`、`ChipsForm`→做法 A；
- `StandardErrorLike`/`toComponentStandardError` 类型引用改到 `chips-sdk` 或本地类型（05-4 节）。

## 3. 卡片/箱子契约红线

1. **manifest.yaml** 的 `capabilities`（`resource-handler:*`、`file-handler:*` 等）与 `runtime.targets` 完全不动；
2. 卡片文件格式（.card）、箱子文件格式（.box）序列化/反序列化逻辑不动；
3. 卡片渲染输出的 DOM 语义（可选中文本、媒体元素、超链接）不动；
4. 与 Host 的交互（`window.chips.*` 调用，如资源读取、卡片保存）不动；
5. 编辑面板产出的**属性数据模型**不动（字段名、类型、默认值、单位）；
6. 不得改变卡片在查看器（CardViewer）、编辑器（EditingEngine）、布局帧（BLP）三处的渲染一致性（参考工单 106 的教训——有专门的一致性验证链路，测试必须保持）。

## 4. 批量处理策略

- 8 个 BCP 结构完全一致 → 按 BCP 任务卡批量（10 章）；
- 11 个 BLP 结构完全一致 → 按 BLP 任务卡批量；
- 每个插件独立验证（`chipsdev test` + `chipsdev validate`）；
- BCP 先做一个样板（如 image-BCP 或 book-BCP），确认标准后再铺开其余 7 个；BLP 同理（grid-BLP 做样板）；
- 样板输出的差异回写 04 章映射表 v2。

## 5. 验收

1. 渲染视图与编辑面板视觉、交互与重构前等价（走查比对）；
2. `rg "@chips/component-library"` 在 src/tests 零命中（归档除外）；
3. 卡片/布局契约测试、一致性测试全绿；
4. `chipsdev validate` 通过（含 manifest 校验）；
5. 无 CSS 变量 `--chips-sys-*` 残留。
