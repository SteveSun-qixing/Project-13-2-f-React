# 11-测试与质量门禁

> 本文件定义重构后各仓库的测试改造要求与统一质量门禁。门禁是每批子代理作业的出口条件（10 章）。
> 现状：每个插件用 Vitest（`chipsdev test` 封装），有 tests/unit 与 tests/e2e；测试辅助 `src/testing/render-with-chips.tsx` 依赖组件库。

---

## 1. 测试改造要点

### 1.1 测试辅助统一

| 旧 | 新 |
|---|---|
| `render-with-chips.tsx`（组件库 Provider 包裹） | `render-with-antd.tsx`：`ConfigProvider(zhCN, appleTheme) + ChipsProvider + CommandProvider + antd App` 包裹，其余 API（render/screen/fireEvent）不变 |
| `mock-environment.ts`（组件库类型 mock） | 改为本地类型（05-2 节），mock `window.chips.*` 形态不变 |
| 测试中的 `createChipsI18nText(...)` | 删除（文案直写后不需要翻译层） |
| 测试中的 `ChipsThemeProvider` | 删除（ConfigProvider 替代） |

### 1.2 测试断言等价

- 文案断言：旧 `expect(screen.getByText(t("app.open"))).toBeTruthy()` → `expect(screen.getByText("打开")).toBeTruthy()`；
- 组件断言：`getByRole("button", { name: ... })` 等保持（antd 无障碍属性完备）；
- 事件断言：点击/输入/键盘交互用例原样保留；
- 新增视觉层断言（可选）：`ConfigProvider` 存在性、`zhCN` 生效（antd 组件文案为中文，如 Modal 的"确 定/取 消"）；
- 删除针对废弃系统的测试（i18n 解析、主题运行时、组件画廊注册表）。

### 1.3 各仓库测试文件范围

| 类型 | 处理 |
|---|---|
| unit 测试（app/commands/业务逻辑） | 同步改造，保留全部用例 |
| unit 测试（i18n/theme-runtime/组件库相关） | 删除（移入归档） |
| e2e 测试（basic-flow 等） | 同步改造，保留（文案/选择器更新） |
| 契约/一致性测试（卡片渲染链路） | 保留不动，改造后必须全绿（09-3 节红线） |

## 2. 共享层 @chips/ui 自身测试

- 必须自带测试：`appleTheme`（token 完整性）、`CommandProvider`（注册/触发）、`EmbeddedDocumentFrame`（渲染/加载态）、`ChipsProvider`（mock window.chips 下取值）；
- 测试文件位于 `Chips-Ui/tests/`，纳入根 workspace `npm run test`。

## 3. 质量门禁（每批出口条件）

对每个重构仓库，依次执行（命令以该仓库 package.json 正式脚本为准，通常为 chipsdev 封装）：

```
1. npm run typecheck     # 或 npx tsc --noEmit；0 错误
2. npm run lint          # 0 错误（eslint 现状配置）
3. npm run test          # vitest 全绿
4. npm run validate      # 若存在（manifest/契约校验）
5. npm run build         # chipsdev build 产物正常（app 类型）
6. 残留扫描（见 3.1）
```

### 3.1 残留扫描清单（必须零命中，归档目录除外）

```bash
rg "@chips/component-library" <repo>/src <repo>/tests
rg "chips-sys|data-chips-theme|ChipsThemeProvider|useChipsTheme|theme-runtime" <repo>/src <repo>/tests
rg "useChipsI18n|useChipsI18nText|localeBundles|createChipsI18nText" <repo>/src <repo>/tests
rg "ChipsCommandProvider|createCommandAdapter|resolveCommand" <repo>/src <repo>/tests   # 共享层命名例外
rg "TODO|FIXME" <repo>/src
```

### 3.2 全生态回归（M6）

```bash
# 根目录
npm run verify:workspace        # 现有工作区验证脚本
# 全部仓库各自执行 3 节 1~5 步（脚本化批量执行）
```

## 4. 社区网页版（packages/web）的验证差异

- packages/web **不是** chipsdev 工程，门禁命令不同：
  ```
  1. npm run build        # tsc -p tsconfig.json && vite build（自身脚本）
  2. npm run lint         # 若存在
  3. npm run test         # 若存在测试
  4. npm run dev          # 手动走查站点页面
  ```
- 残留扫描（11-3.1 节）同样适用，另加：`rg "runtime/theme|runtime/i18n|dictionaries" src` 零命中；
- 浏览器人工走查：首页/登录/注册/作品详情/内嵌插件表面各页面，中文文案、站点导航（SiteHeader/SiteFooter）完整（工单 126 教训）。

## 5. 视觉验收（人工，配合 03-8 节）

- 试点（M2）后由用户对 PhotoViewer 做首次视觉走查，确认苹果风格方向；
- 每批至少抽 1 个仓库做人工走查（启动 `chipsdev run` 或 Host 运行）；
- M6 全量走查：每个应用启动检查关键页面（主界面、设置/面板、空态、错误态、弹层）。

## 6. 测试数据与快照

- 不引入快照测试（antd 类名变化频繁，快照脆弱）；断言用角色/文本/状态语义；
- 若现有测试使用快照，改造时移除并改为语义断言。

## 7. 性能与包体抽查（M6 可选）

- 抽查 1~2 个应用构建产物大小（antd 全量打包后），记录基线；
- 不设硬性预算（demo 阶段），仅记录供后续优化参考。
