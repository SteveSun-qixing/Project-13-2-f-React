## 背景

将 `Chips-PersonalServer` 部署到生产服务器（1Panel 管理、Debian 12、1 核 1G、国内源），对象存储使用七牛云单 bucket，域名 `www.chipscard.space`。

## 服务器信息

- IP：`103.185.248.114`（SSH 别名 `chipscard-personal-server`，见《服务器连接手册/01-SSH免密连接使用手册.md》）
- 系统：Debian 12 (bookworm) x86_64，1 核 / 961MB 内存 / 30G 磁盘，已加 2G swap（`/swapfile`，fstab 持久化）
- 管理：1Panel 面板（含 Docker 29.7.2 + Compose v5.4.0）
- 部署目录：`/opt/chips-runtime/Chips-PersonalServer`
- 生产 compose：`deploy/docker-compose.prod.yml`（固定项目名 `cps`，无 Redis/MinIO）

## 关键配置

- 七牛云：单 bucket `chipscardspace`（S3 兼容、path style），`S3_PUBLIC_URL=https://file.chipscard.space`
- 域名：`BASE_URL=https://www.chipscard.space`，nginx 挂载 TRUSTASIA 证书（2026-08-12 ~ 2026-11-10）
- PostgreSQL 1G 调优参数（shared_buffers 128MB 等）
- 构建优化：`NODE_OPTIONS=--max-old-space-size=512`、pnpm 低并发、`shamefully-hoist`（@chips/ui types 指向 src 的解析需要）、`/app/node_modules` 符号链接
- 生产 API_TOKEN 与 POSTGRES_PASSWORD 为随机生成（保存在本机 `/var/folders/.../opencode/` 临时目录）

## 过程问题与解决

1. **compose 项目名冲突**（本地）：两个仓库 compose 同在 `deploy/` 目录，默认项目名相同导致容器互相重建 → 个人服务器 compose 顶层 `name: cps`。
2. **SSH 公钥认证被禁用**：服务器 `PubkeyAuthentication no` → 备份配置后开启并 reload。
3. **构建内存耗尽卡死**：1G 无 swap，`pnpm install + tsc` 导致系统卡死、SSH 不可达 → 云控制台重启 + 加 2G swap + 构建内存/并发限制 + 分步构建（先 web 后 server）。
4. **Docker 构建 tsc 解析失败**：`@chips/ui` types 指向 src，pnpm `--filter` 安装时 peer 依赖（react/antd）未提升 → `shamefully-hoist=true` + `/app` 下 node_modules 链接。
5. **七牛 CDN 域名 `file.chipscard.space` HTTPS 证书过期**（旧 TRUSTASIA 证书 2026-08-01 到期）→ 待用户到七牛控制台更新 CDN 证书（可复用 2026-08-12 的新证书）。

## 七牛单桶模式关键修复

**问题**：使用 bucket 专属端点（`chipscardspace.s3.ap-southeast-1.qiniucs.com`）时，S3_BUCKET_NAME 模式下物理桶名被写入对象 key（实际 key 变为 `chipscardspace/chips-card-render-cache/...`），CDN 路径与实际 key 不一致 → 公开资源 404。

**修复**：
1. `S3_ENDPOINT` 改用通用端点 `https://s3.ap-southeast-1.qiniucs.com`；
2. `s3.ts` 单桶模式下全部逻辑桶（含私有桶）映射到同一物理桶，key 前缀为逻辑桶名；
3. `init.ts` 单桶模式只初始化一个物理桶，不在七牛额外创建 bucket；
4. 清理了 36 个坏 key 测试对象并重传验证。

**注意**：私有对象（`.box` 源文件等）在单桶模式下位于公开空间内，CDN 可直接访问，发布内容时注意隐私。
