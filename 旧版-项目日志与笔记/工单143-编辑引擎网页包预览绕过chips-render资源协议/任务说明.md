# 工单143：编辑引擎网页包预览绕过 chips-render 资源协议

## 背景

编辑引擎中的网页基础卡片可以正常导入网页 ZIP：网页包目录、`index.html`、CSS 和 JavaScript 均写入卡片根目录，配置也保存了完整的 `resource_paths`。但打开该卡片进行预览时，网页只显示 HTML 结构，网页包中的 CSS 和 JavaScript 没有加载。

## 证据

1. `Chips-EditingEngine/src/components/CardWindow/CardWindow.tsx:23-35` 的 `toCardRootFileUrl` 将卡片目录手工拼为 `file://` URL，`CardWindow.tsx:74` 将其作为 `previewResourceBaseUrl` 传给 `CompositeCardAssembler`。
2. `Chips-EditingEngine/src/basecard-runtime/frame-host.tsx:297-325` 在有 `resourceBaseUrl` 时继续用 `new URL(resourcePath, resourceBaseUrl)` 解析网页资源，因此网页基础卡片的入口最终得到 `file:///.../webpage-bundle-*/index.html`。
3. `Chips-Host/packages/card-service/src/card-service.ts:2040-2047,2679-2691` 已提供正式的卡片资源 URL 解析；Electron 环境应返回 `chips-render://card-root/<token>/<path>`，用于“相对资源解析与沙箱 iframe 内加载”。`Chips-Host/src/main/services/register-host-services.ts:6791-6805` 和 `Chips-SDK/src/api/card.ts:480-491` 已注册并封装 `card.resolveResourceUrl`。
4. 当前正式资源解析只在 `Chips-EditingEngine/src/editor-runtime/EditorHost.tsx:278-320` 使用，编辑引擎预览链路没有调用 `card.resolveResourceUrl`，仍保留旧的本地 `file://` 基址。
5. 真实 Electron 复现使用 `ProductFinishedProductTestingSpace/昙花网页.zip` 导入后的卡片目录：
   - 卡片根目录中存在 `webpage-bundle-fi4oia/index.html`、`styles.css`、`script.js`，SHA-256 与原始测试素材一致；
   - 预览内页地址为 `file:///tmp/.../webpage-bundle-fi4oia/index.html`；
   - Chromium 控制台明确报错：`Not allowed to load local resource: file:///tmp/.../styles.css` 和 `Not allowed to load local resource: file:///tmp/.../script.js`；
   - 将同一个入口改为 Host 正式返回的 `chips-render://card-root/.../index.html` 后，CSS 生效、JavaScript 执行，页面动态元素正常出现。
6. `Chips-BaseCardPlugin/webpage-BCP/src/render/view.tsx:653-658` 有意使用不含 `allow-same-origin` 的沙箱 iframe。该安全边界下直接依赖 `file://` 相对资源会被 Electron/Chromium 拒绝，不能把 `file://` 作为预览资源协议。

## 影响范围

- 编辑引擎中网页基础卡片的网页 ZIP 查看态预览；
- 所有依赖本地卡片根目录相对资源的网页 CSS、JavaScript、图片、字体、音视频、WASM 等资源；
- 预览表现会被错误标记为可用：`BasecardFrameHost` 对无法访问的沙箱内页走不可测量回退，用户看到的是未样式化或静态 HTML，而不是明确的资源加载错误。

## 复现步骤

1. 启动编辑引擎，打开一个包含网页基础卡片的卡片文件。
2. 通过网页基础卡片编辑面板导入 `ProductFinishedProductTestingSpace/昙花网页.zip`，确认显示“已导入 3 个文件”。
3. 在编辑引擎预览区查看网页。
4. 打开该预览内页的 Chromium 控制台，观察 `styles.css`、`script.js` 的 `Not allowed to load local resource` 错误。
5. 检查 DOM，确认入口是 `file://`；手动替换为 `card.resolveResourceUrl` 返回的 `chips-render://` URL 后页面恢复完整样式和脚本交互。

## 期望行为

- 编辑引擎预览必须沿 Host / Bridge / SDK 正式链路解析卡片根目录资源；
- Electron 环境的网页包入口及其相对资源使用 Host 返回的 `chips-render://card-root/...` 受控 URL，非 Electron 环境才允许按正式降级规则使用 `file:`；
- 预览链路与编辑面板资源解析链路使用同一资源 URL 契约，不得由 `CardWindow` 或基础卡片运行时手工拼接 `file://`；
- 网页包 CSS、JavaScript 和其他相对资源在保留网页 iframe 沙箱安全边界的前提下正常加载；若资源无法加载，应显示明确的加载错误而不是静默显示未样式化 HTML。

## 修复结果

- `CardWindow` 已移除卡片根目录 `file://` 拼接，改为通过 `getChipsClient().card.resolveResourceUrl(cardRootDir, resourcePath)` 向基础卡片运行时注入正式解析器。
- `BasecardFrameHost` 已移除 `srcdoc` 中的本地 `<base>`，持久化资源和资源打开意图统一经注入解析器获得 Host 运行时 URL；待提交资源仍由本地 Blob URL 提供，并只在释放时回收 Blob。
- 网页基础卡片单元/集成样例已改用 `chips-render://card-root/...` 正式协议回归，防止测试继续固化 `file://` 预览假设。
- 真实 Electron 复现已验证：使用 `chips-render://card-root/.../index.html` 后网页包 CSS 生效、JavaScript 执行，动态元素正常出现。
