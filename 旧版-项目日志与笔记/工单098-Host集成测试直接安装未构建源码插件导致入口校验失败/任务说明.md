# 工单098：Host 集成测试直接安装未构建源码插件导致入口校验失败

## 背景

修复工单097后，执行 Host 主题运行时与服务集成测试时发现 3 个集成用例失败，错误均为 `Plugin entry not found: dist`。

## 证据

失败命令：

```bash
cd Chips-Host
npx vitest run tests/unit/theme-runtime.test.ts tests/integration/host-services.test.ts
```

失败用例：

- `lists enabled box layout plugins through the box service chain`
- `renders card through unified rendering target options`
- `supports card.render theme and locale overrides`

已核对：

- `Chips-BoxLayoutPlugin/grid-BLP/manifest.yaml` 的正式入口是 `entry: dist/index.mjs`。
- `Chips-BaseCardPlugin/richtext-BCP/manifest.yaml` 的正式入口是 `entry: dist/index.mjs`。
- 当前工作区这些插件目录没有 `dist/`。
- Host 插件运行时会把 manifest entry 作为必须存在的资产根校验，缺失时抛出 `PLUGIN_ENTRY_NOT_FOUND`。

## 影响范围

- `Chips-Host/tests/integration/host-services.test.ts`
- Host 插件安装、启用、布局描述符和卡片渲染集成测试
- 测试对外部源码插件构建状态的隐式依赖

## 复现步骤

1. 进入 `Chips-Host`。
2. 执行 `npx vitest run tests/integration/host-services.test.ts`。
3. 观察相关用例失败并报告 `Plugin entry not found: dist`。
4. 检查被安装插件的 manifest，确认入口指向 `dist/index.mjs`。
5. 检查插件源码目录，确认当前缺少 `dist/`。

## 期望行为

- 集成测试使用自包含、具备正式 `dist/index.mjs` 入口的插件 fixture。
- 测试继续覆盖 Host 插件安装与启用链路。
- Host 不放宽插件入口存在性校验。
- 测试不依赖外部插件工程是否已经人工构建。

## 暂行处理

按用户最新要求，本工单登记后直接修复，不暂停等待。

## 需要协作方

- Host 测试维护方
- 插件运行时维护方
- 基础卡片与布局插件维护方

## 当前状态

已解决。

## 处理结果

1. `Chips-Host/tests/integration/host-services.test.ts` 已新增自包含插件 fixture 创建逻辑。
2. 布局插件 fixture 使用正式 manifest 字段、`layout.layoutType` 与 `dist/index.mjs` 入口，并导出 `layoutDefinition`。
3. 富文本基础卡片 fixture 使用正式 manifest 字段、`capabilities.cardTypes` 与 `dist/index.mjs` 入口，并导出 `basecardDefinition`。
4. 相关测试改为安装测试工作区生成的 fixture，不再依赖外部源码插件是否已经人工构建。
5. Host 插件入口存在性校验保持不变，测试继续通过正式安装/启用/渲染链路验证。
