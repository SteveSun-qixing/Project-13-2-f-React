# 工单095：社区服务器开发基础设施端口发布配置漂移

## 背景

在本地启动社区服务器供卡片查看页效果检查时，按 `Chips-CommunityPlatformServer/技术文档/07-启动与运行说明.md` 的推荐开发模式启动 Docker 基础设施，再由本机 Node 进程运行 API 服务。

## 证据

- `Chips-CommunityPlatformServer/deploy/.env.example` 中开发态 `DATABASE_URL` 指向 `localhost:5432`，`REDIS_URL` 指向 `localhost:6379`，`S3_ENDPOINT` 指向 `localhost:9000`。
- `Chips-CommunityPlatformServer/技术文档/07-启动与运行说明.md` 明确推荐使用本地开发分拆模式：Docker 负责 PostgreSQL、Redis、MinIO，本机 Node 进程运行 `packages/server`。
- 启动时检查发现 `deploy/docker-compose.yml` 的 `postgres`、`redis`、`minio` 服务没有发布宿主机端口，`docker port ccps_postgres 5432`、`docker port ccps_minio 9000` 均返回未发布。
- 因此本机 API 服务无法按正式 `.env` 连接 Docker 内的 PostgreSQL 与 MinIO。

## 影响范围

- `Chips-CommunityPlatformServer/deploy/docker-compose.yml`
- `Chips-CommunityPlatformServer/deploy/.env.example`
- `Chips-CommunityPlatformServer/技术文档/07-启动与运行说明.md`
- 本地开发分拆模式下的 API 服务启动、对象存储初始化与 Web `/cdn` 代理

## 复现步骤

1. 在生态根目录执行：
   `docker compose -f Chips-CommunityPlatformServer/deploy/docker-compose.yml --env-file Chips-CommunityPlatformServer/deploy/.env up -d postgres redis minio`
2. 执行：
   `docker port ccps_postgres 5432`
3. 执行：
   `docker port ccps_minio 9000`
4. 观察到宿主机端口未发布。
5. 再按文档启动本机 API 服务，服务会按 `.env` 尝试连接 `localhost:5432` 与 `localhost:9000`，无法连到对应容器服务。

## 期望行为

本地开发分拆模式应与文档和 `.env.example` 保持一致，并允许本机已有服务占用默认端口时通过环境变量显式覆盖宿主端口：

- PostgreSQL 默认发布 `5432:5432`
- Redis 默认发布 `6379:6379`
- MinIO S3 API 默认发布 `9000:9000`
- MinIO Console 默认发布 `9001:9001`

这样本机 API 服务和 Web 开发代理可以稳定使用 `localhost` 入口完成联调。

## 暂行处理

本轮已将 `deploy/docker-compose.yml` 中三个基础设施服务的端口发布配置补齐，并允许通过 `POSTGRES_HOST_PORT`、`REDIS_HOST_PORT`、`MINIO_HOST_PORT`、`MINIO_CONSOLE_HOST_PORT` 覆盖宿主端口。当前机器已有 Redis 占用 `6379`，本地 `deploy/.env` 已把社区 Redis 宿主端口设为 `6380`。
