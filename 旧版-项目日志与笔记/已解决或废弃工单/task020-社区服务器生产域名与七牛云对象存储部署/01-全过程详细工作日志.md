## 6. 对象存储迁移

旧部署中的对象资源原本保存在 MinIO 中。本次将旧 MinIO 对象迁移到七牛云单物理 bucket `chipscardspace`。

迁移策略：

- 保留社区服务器业务上的四类逻辑 bucket；
- 不在七牛云创建四个物理 bucket；
- 使用一个物理 bucket `chipscardspace`；
- 把逻辑 bucket 名作为对象 key 的一级前缀。

逻辑 bucket 与物理 key 映射如下：

```text
逻辑 bucket: chips-card-html
业务 key: user-1/card-1/index.html
物理 bucket: chipscardspace
物理 key: chips-card-html/user-1/card-1/index.html
公开 URL: https://file.chipscard.space/chips-card-html/user-1/card-1/index.html
```

迁移的旧对象统计：

- `chips-card-resources`：27 个对象
- `chips-card-html`：42 个对象
- `chips-avatars`：1 个对象
- `chips-covers`：4 个对象

## 7. S3 Endpoint 口径确认

用户提供的七牛 S3 Endpoint 形如 bucket 域名入口。实际测试后，生产写入应使用七牛区域 S3 API 入口：

```text
https://s3.ap-southeast-1.qiniucs.com
```

最终生产写入配置口径：

```env
S3_ENDPOINT=https://s3.ap-southeast-1.qiniucs.com
S3_RUNTIME_ENDPOINT=https://s3.ap-southeast-1.qiniucs.com
S3_REGION=ap-southeast-1
S3_FORCE_PATH_STYLE=true
S3_BUCKET_NAME=chipscardspace
```

说明：

- `S3_ENDPOINT` 保留给非 Docker 运行时或本地 Node 进程读取；
- `S3_RUNTIME_ENDPOINT` 在 Docker Compose 中覆盖容器内 `S3_ENDPOINT`；
- `S3_BUCKET_NAME` 表示四类逻辑 bucket 写入同一个物理 bucket；
- `S3_FORCE_PATH_STYLE=true` 符合本次七牛云 S3 兼容写入要求。


- 新上传资源将直接生成 `https://file.chipscard.space/...`；
- 主站不再承担长期资源代理流量；
- 旧的 `/cdn/...` 链接保留跳转能力；
- 七牛云成为公开资源的正式承载入口。

### 10.1 环境变量解析

文件：

```text
Chips-CommunityPlatformServer/packages/server/src/config/env.ts
```

调整内容：

- 新增 `S3_BUCKET_NAME` 环境变量；
- 用显式布尔解析替换 `z.coerce.boolean()`；
- 修复字符串 `"false"` 被错误解析为 `true` 的风险；
- `S3_FORCE_PATH_STYLE` 改为可靠的显式布尔解析；
- `ENABLE_SWAGGER` 改为可靠的显式布尔解析。

调整原因：

- 生产 `.env` 中的布尔值通常以字符串形式存在；
- `z.coerce.boolean()` 对非空字符串的行为容易造成生产开关误判；
- 本次生产环境需要明确关闭 Swagger；
- 本次生产环境需要明确启用 path style。

### 10.2 S3 单 bucket 映射

文件：

```text
Chips-CommunityPlatformServer/packages/server/src/storage/s3.ts
```

调整内容：

- 新增逻辑 bucket 到物理 bucket 的映射；
- 当 `S3_BUCKET_NAME` 存在时，物理 bucket 固定为 `S3_BUCKET_NAME`；
- 物理 key 自动加逻辑 bucket 前缀；
- 公开 URL 继续保留逻辑 bucket 路径；
- `buildObjectUrl()` 支持 `https://file.chipscard.space/...`；
- `parseObjectUrl()` 同时支持对象存储公开域名和旧 `${BASE_URL}/cdn/...`；
- 修复 `deleteObjectsByPrefix()` 在单物理 bucket 模式下删除时仍使用逻辑 bucket 的问题。

关键修复点：

```text
列举对象：Bucket = chipscardspace, Prefix = chips-card-html/...

```

修复前风险：

- 列举能找到对象；
- 删除命令却发往逻辑 bucket；
- 七牛单 bucket 模式下可能无法正确清理资源。

抽查线上历史卡片 HTML，发现响应头中存在异常元数据：

```text
content-encoding: aws-chunked
```

该响应头出现在通过 `uploadFile(...)` 流式上传的对象上，包括卡片 HTML 与图片资源。浏览器通过 `file.chipscard.space` 直接打开这类对象时，可能按 `aws-chunked` 编码尝试解码，从而导致 HTML 或图片显示乱码。

### 22.4 受控复现

在生产 Server 容器中使用同一个七牛云 bucket、同一个公开域名做了受控上传测试。

测试结论：

- 使用 `Buffer` 作为 `PutObjectCommand.Body` 上传时，公开响应头正常，不出现 `content-encoding: aws-chunked`；
- 使用 `fs.createReadStream(...)` 作为 `Body` 且采用 AWS SDK 默认 S3 客户端配置上传时，公开响应头会出现 `content-encoding: aws-chunked`；
- 使用 `fs.createReadStream(...)` 但在 `S3Client` 中配置以下参数后，公开响应头恢复正常：

```ts
requestChecksumCalculation: 'WHEN_REQUIRED'
responseChecksumValidation: 'WHEN_REQUIRED'
```

因此根因不是七牛云自定义域名、HTTPS 证书或 bucket 权限配置，而是服务端 S3 客户端默认流式校验编码与七牛云 S3 兼容接口的元数据处理不兼容。
