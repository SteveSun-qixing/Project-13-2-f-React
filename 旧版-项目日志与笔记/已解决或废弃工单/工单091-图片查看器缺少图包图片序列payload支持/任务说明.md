# 工单091：图片查看器缺少图包图片序列 payload 支持

## 背景

电子书基础卡片支持 ZIP/CBZ 漫画图片包。图片包导入后不保存原压缩包，而是保存有序图片资源。查看态点击图包时，基础卡片会以第一张图片作为主资源，同时在 `resourceOpen.payload.resources.images` 中传递完整图片序列。

当前图片查看器已能消费电子书基础卡片图包序列，同时保留普通单图打开能力。

## 证据

- `Chips-PhotoViewer/manifest.yaml`
  - 已声明 `resource-handler:view:image/*`，因此可以被第一张图片命中。
- `Chips-PhotoViewer/src/utils/launch-resource.ts`
  - 已新增 `resolveLaunchImageTarget(...)`，返回图片队列、初始索引和标题。
  - 当 payload 为 `chips.book-card` 且 `mode === "image-sequence"` 时，会读取 `payload.resources.images[]`。
  - 普通单图仍从 `targetPath`、`resourceOpen.filePath`、`resourceOpen.resourceId` 恢复。
- `Chips-PhotoViewer/src/App.tsx`
  - 已维护当前图片索引、队列状态、资源解析状态与保存链路。
- `Chips-PhotoViewer/src/components/PhotoViewerStage.tsx`
  - 已提供上一张、下一张、当前序号和边界禁用状态。
- `book-BCP` 查看态 payload：
  - `kind: "chips.book-card"`
  - `mode: "image-sequence"`
  - `resources.images[]` 按阅读顺序传递所有图片资源描述。

## 影响范围

- 用户点击漫画图包后，可在图片查看器中按 payload 顺序上一张/下一张浏览。
- 普通单图打开不受图包模型影响。
- 后续电子书阅读器或图片查看器可以复用 `chips.book-card` 图片序列 payload 口径。

## 复现步骤

1. 在电子书基础卡片中上传包含多张图片的 ZIP/CBZ。
2. 查看态点击卡片。
3. Host 按第一张图片命中 `Chips-PhotoViewer`。
4. 图片查看器启动后读取 `payload.resources.images[]`，建立图片队列，并以主资源匹配初始索引。

## 期望行为

1. 图片查看器启动层识别 `resourceOpen.payload.kind === "chips.book-card"`。
2. 当 `payload.mode === "image-sequence"` 时，读取 `payload.resources.images[]` 建立有序图片队列。
3. 初始索引优先匹配 `resourceOpen.resourceId` 或 `resourceOpen.filePath`，否则使用第一张。
4. UI 支持上一张/下一张、边界状态、当前序号和单张加载错误隔离。
5. 保留普通单图打开行为，不让图包逻辑影响现有图片查看。

## 暂行处理

已完成本工单范围内的正式收口。`book-BCP` 继续只传递正式图包 payload，不内置图片查看器，也不硬编码 `com.chips.photo-viewer`。

1. `Chips-PhotoViewer/src/utils/launch-resource.ts` 已支持图包 payload。
2. `Chips-PhotoViewer/src/App.tsx` 已支持图片队列、索引切换和无本地路径资源保存。
3. `Chips-PhotoViewer/src/components/PhotoViewerStage.tsx` 已支持序列导航 UI。
4. `Chips-PhotoViewer/tests/unit/launch-resource.test.ts` 已覆盖图包 payload 和普通单图启动。
