# 工单089-基础卡片脚手架创建命令文档与CLI实现漂移

## 背景

在创建 `chips-basecard-plugin-dev` 技能时，需要把“新基础卡片插件项目必须使用基础卡片脚手架初始化”写成可执行流程。按工作区规则，写入技能前重新核对了基础卡片脚手架文档和当前 `chipsdev` CLI 实现，发现两者对创建命令的描述不一致。

## 证据

- `Chips-Scaffold/chips-scaffold-basecard/技术文档/04-命令行集成与工作流设计.md` 描述了 `chips dev create my-basecard --type card` 以及带 `--type card` 的非交互式示例。
- `Chips-SDK/cli/index.js` 当前 `handleCreate(args)` 使用 `const [type, targetDir = '.'] = args`，并通过 `type === 'card'` 进入基础卡片脚手架分支。
- 真实实现中，基础卡片创建路径对应 `chipsdev create card <targetDir>`。

## 影响范围

- 新基础卡片插件项目初始化流程容易被旧文档误导；
- 技能、README、共享命令行文档和脚手架内部文档可能继续传播不同命令；
- 如果后续自动化或 E2E 按旧命令编写，会无法进入当前 CLI 的 `card` 分支。

## 复现步骤

1. 打开 `Chips-Scaffold/chips-scaffold-basecard/技术文档/04-命令行集成与工作流设计.md`。
2. 搜索 `--type card` 和 `chips dev create`。
3. 打开 `Chips-SDK/cli/index.js`。
4. 搜索 `handleCreate`，确认参数顺序是 `<type> <targetDir>`。
5. 搜索 `type === 'card'`，确认基础卡片脚手架由 `card` 类型参数触发。

## 期望行为

- CLI 帮助、共享命令行文档、基础卡片脚手架文档和真实实现应保持同一命令入口；
- 若正式入口为 `chipsdev create card <targetDir>`，应更新旧文档；
- 若正式入口调整为 `chipsdev create <targetDir> --type card`，应同步修改 CLI 解析、帮助、测试和脚手架调用。

## 暂行处理

- 本轮 `chips-basecard-plugin-dev` 技能以当前代码为准，写入 `npx chipsdev create card <target-dir>`；
- 不在技能中把旧文档命令作为正式推荐；
- 后续修改脚手架或 CLI 文档时，应先以此工单为依据完成收口。

- 基础卡片脚手架维护方
- 命令行工具文档维护方
