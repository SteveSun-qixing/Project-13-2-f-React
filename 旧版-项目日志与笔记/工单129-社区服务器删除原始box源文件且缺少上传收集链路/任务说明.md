# 工单129：社区服务器删除原始box源文件且缺少箱子上传收集与查看链路

## 背景

社区服务器在上传 `.box` 后解包并删除原始 `.box` 临时文件，只保留 metadata/structure JSONB，社区无法下载、无法重建正式箱子；上传时不会收集散落卡片；社区箱子 `documentUrl` 恒为 null，网页详情挂起。

## 证据

1. `Chips-CommunityPlatformServer/packages/server/src/services/box.service.ts:199`：上传后删除 `.box`。
2. `Chips-CommunityPlatformServer/packages/server/src/db/schema/boxes.ts`：无源文件对象存储字段。
3. `Chips-CommunityPlatformServer/packages/server/src/storage/buckets.ts`：无箱子源文件 bucket。
4. `Chips-CommunityPlatformServer/packages/server/src/routes/upload.ts:62`：multipart 箱子上传无客户端调用方。
5. `Chips-ModulePlugin/Chips-CommunityUploader-Plugin/src/publisher.ts`：只有单卡片上传，无 uploadBox。
6. `Chips-CommunityClient/src/community/pages/WorkspacePage.tsx:68`：文件过滤器只允许 `.card`。
7. `Chips-CommunityPlatformServer/packages/web/src/pages/BoxDetailPage.tsx:47-61`：依赖 `box.documentUrl`（恒 null）。

## 影响范围

- 服务器 boxes 表、BoxService、card-transfer 控制面、storage buckets
- CommunityUploader 模块（新增 uploadBox 能力）
- 社区客户端（.box 上传入口）
- 社区 Web 箱子详情页

## 期望行为

- `.box` 源文件保留到对象存储（`chips-box-files` bucket），boxes 表记录对象位置；
- 传输模块 `uploadBox`：收集散落卡片（file://）上传、网络卡片（http/https）跳过、内嵌卡片跟随箱子；
- 客户端支持选择 `.box` 上传；
- 社区箱子 `documentUrl` 落地（只读文档源先行），详情页可打开。
