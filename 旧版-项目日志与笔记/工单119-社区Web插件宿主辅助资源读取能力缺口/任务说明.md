# 工单119-社区Web插件宿主辅助资源读取能力缺口

## 背景

社区服务器中，用户从卡片页面点击音乐基础卡片后，会通过正式 `resource.open` 打开 `com.chips.music-player`。音乐基础卡片已经在 payload 中携带 `chips.music-card` 上下文，包括主音频、封面、歌词与展示标题、歌手等信息。

本地桌面 Host 链路可正常恢复，但社区 Web Host 中播放器页面出现信息、封面、歌词无法完整显示的问题。

## 证据

1. 音乐基础卡片查看态会构造 `MusicCardOpenPayload`，并把 `resources.audio`、`resources.cover`、`resources.lyrics` 放入 `resource.open` payload。
2. 社区 Web 宿主会把 `resource.open` payload 透传到目标应用的 `launchParams.resourceOpen.payload`。
3. 修复前社区 Web bootstrap 只本地支持 `resource.resolve`，缺少 `resource.readBinary` 与 `resource.readMetadata`。
4. 修复前音乐播放器只在 `metadataReadTarget` 存在时消费 payload 中的封面和歌词；社区服务器远端 HTTP 音频通常会被视为可直接播放 URI，不进入嵌入元数据读取分支。

## 影响范围

1. `Chips-CommunityPlatformServer` 浏览器插件宿主；
2. `Chips-MusicPlayer` 的 `resource.open` 启动恢复；
3. 使用 payload 辅助资源的音乐、视频、电子书等基础卡片到应用插件链路；
4. 未来需要在 Web Host 中读取辅助资源字节或元数据的应用插件。

## 复现步骤

1. 在社区服务器打开包含音乐基础卡片的卡片页面；
2. 点击音乐基础卡片进入音乐播放器；
3. 观察播放器主音频可进入播放链路，但封面、歌词或音乐卡片展示上下文未完整恢复；
4. 检查浏览器控制台，可看到辅助资源读取能力缺失或未被触发；
5. 对照桌面 Host 链路，确认本地 `resource.readBinary` 能力存在，社区 Web bootstrap 能力不完整。

## 期望行为

1. 社区 Web Host 应提供与 SDK 正式资源 API 兼容的 `resource.resolve/readBinary/readMetadata` 能力；
2. 音乐播放器应优先恢复 `MusicCardOpenPayload` 中的封面、歌词和展示信息，再回退到嵌入元数据、伴生文件与默认封面；
3. 远端 HTTP/HTTPS 主音频可直接播放时，不应导致 payload 辅助资源被跳过；
4. Host 只负责资源路由和 payload 透传，不解释业务 payload 内部语义。

## 正式处理

1. `Chips-CommunityPlatformServer/packages/server/src/routes/host-runtime.ts` 为 Web bootstrap 补齐 `resource.readBinary` 与 `resource.readMetadata`；
2. `Chips-MusicPlayer/src/app/AppRuntimeProvider.tsx` 将音乐卡片封面、歌词恢复移出嵌入元数据读取分支；
3. `Chips-CommunityPlatformServer/packages/server/src/routes/host-runtime.test.ts` 补充 Web 资源读取测试；
4. `Chips-MusicPlayer/tests/unit/launch-resource.test.ts` 补充社区 Web 远端资源 payload 回归测试；
5. `Chips-CommunityPlatformServer/技术文档/08-社区Web插件宿主链路.md` 与 `Chips-MusicPlayer/技术文档/02-启动恢复与音频资源解析设计.md` 已同步正式链路说明。
