# 工单116-SDKCliCommand类型错误阻断应用插件typecheck

## 背景

`Chip-iconMaker` 应用插件完成界面重构后，需要通过项目正式验证链路。执行 `npm run verify` 时，`lint` 通过，但 `typecheck` 被 `Chips-SDK` 当前源码类型错误阻断。

## 证据

在 `Chip-iconMaker` 中执行：

```bash
npm run typecheck
```

报错位置：

- `../Chips-SDK/src/api/cli-command.ts(216,70)`
- `../Chips-SDK/src/api/cli-command.ts(223,44)`
- `../Chips-SDK/src/api/cli-command.ts(225,49)`
- `../Chips-SDK/src/api/cli-command.ts(226,48)`
- `../Chips-SDK/src/api/cli-command.ts(227,50)`

核心错误为 `unknown` 或 `{ } | null` 未收窄到 `string`、`string[]`、`CliCommandTargetType` 或可选字段类型。

## 影响范围

- 依赖 `chips-sdk` 类型入口的应用插件本地 `typecheck`。
- `Chip-iconMaker` 的 `npm run verify` 链路。
- SDK 对外类型声明稳定性。

## 复现步骤

1. 进入 `Chip-iconMaker`。
2. 执行 `npm run verify` 或 `npm run typecheck`。
3. 观察 `tsc -p tsconfig.json --noEmit` 穿透到 `../Chips-SDK/src/api/cli-command.ts` 并失败。

## 期望行为

SDK 对外类型入口应稳定，应用插件类型检查不应被 SDK 内部未收口源码错误阻断。`normalizeQueryOptions()` 应完成明确类型守卫和字段收窄。

## 暂行处理

本轮不修改 SDK，不在 `Chip-iconMaker` 中改类型检查脚本绕过。`Chip-iconMaker` 已继续执行可独立验证的测试、构建、Manifest 校验、预览 smoke 与质量门禁。
