## 二、问题清单（按优先级）

### P0 — 与生态决策冲突的残留（建议尽快处理）

**1. 卡片主题选择面板（ThemePanel）仍在使用旧主题系统**

- 位置：`src/components/CardSettings/panels/ThemePanel.tsx` + `ThemePanel.css`，挂载于 `CardSettingsDialog.tsx` 的"主题"页签
- 问题：仍调用 `client.theme.list() / client.theme.getCurrent()`（Host 主题服务），让用户为卡片选择明/暗主题。task030 已废弃主题系统（全生态单一苹果风格、`07-主题系统移除规范.md`），此面板是唯一的旧体系运行时消费点，且卡片已不再消费 `themeCssText`
- 建议：移除"主题"页签与 ThemePanel（移入 `归档/`）；卡片配置的 `theme` 契约字段保留但不提供 UI 选择，或改为静态提示"使用默认外观"；同步清理 `ThemePanel.css` 与 messages 中的相关 key
- 影响：移除后 `client.theme` 调用面消失，可进一步确认 Host 侧 theme 服务面后续清理范围

### P1 — 死代码与未使用资产

**2. HeaderBar 组件无消费者**

- 位置：`src/components/HeaderBar/HeaderBar.tsx` + `HeaderBar.css`
- 问题：E3 迁移时已 props 化（接收 CommandItem[]），但全仓无渲染点（rg 仅命中自身与 messages key）。E1 遗留疑问 5 已指出"旧 HeaderBar 未挂载（死代码）"
- 建议：移入 `归档/`，同步清理 `src/lib/messages.ts` 中仅被 HeaderBar 使用的 key（如 `commands.menu.*` 菜单相关）

**3. useTranslation 调用风格不一致（8 个文件仍在用）**

- 位置：`src/hooks/useTranslation.ts`；调用方：Workbench.tsx、Dock.tsx、HistoryPanel.tsx、EditPanel.tsx、BaseWindow.tsx、ToolWindow.tsx、BoxWindow.tsx 等
- 问题：hook 本身已改为 `formatMessage` 包装（功能等价、无残留风险），但与其他组件"中文直写"的风格不一致，且调用处大量 `t('key') || '中文'` 双写模式（如 HistoryPanel 的 `t('history_panel.undo') || '撤销'`）——key 查不到时兜底，可读性差、维护两份文案
- 建议：低优先级统一——逐步将 `t('key') || '中文'` 收敛为直接中文常量；或保留 hook 但移除双写兜底
- 处理状态（task031 收尾，2026-08）：已收敛全部 `t('key') || '中文'` 双写（src 下零命中）；`useTranslation` hook 与全部消费点清零并归档至 `归档/task031-useTranslation/`；`src/lib/messages.ts` 中无引用的死 key（HeaderBar/ThemePanel 相关等 245 个）已清理；测试断言从原始 key 改为实际中文文案。

### P2 — 视觉/苹果风格一致性

**4. CSS 硬编码颜色与苹果 token 不一致**

- 位置：各组件 CSS（抽查）
  - `CoverMaker.css`：#e5e5e5（9 处）、#1a1a1a（8 处）、#3b82f6（旧蓝，5 处）
  - `HistoryPanel.css`：#e0e0e0、#999999
  - `CardSettings/panels/CoverPanel.css`：#111827
  - `FileManager.css`：#f0f0f0
  - 部分与苹果 token（#f5f5f7/#6e6e73/#0a84ff/#1d1d1f）混用
- 问题：demo 阶段可接受，但颜色来源分散，后续统一改 token 时容易漏；`#3b82f6`（Tailwind 蓝）与系统蓝 `#0a84ff` 并存会让界面"两种蓝"
- 建议：统一为苹果 token 色板（可后续引入 CSS 变量集中管理：`--ee-surface/--ee-text/--ee-accent` 等）；至少替换 `#3b82f6 → #0a84ff`

**5. 毛玻璃/玻璃质感缺失**

- 位置：Dock、BaseWindow/ToolWindow 标题栏、WindowMenu
- 问题：苹果风格的核心质感（半透明 + backdrop-filter 模糊）在编辑引擎中几乎未使用（grep backdrop/blur 无命中），Dock 与窗口浮层偏"平板"
- 建议：Dock 与窗口标题栏/浮层加 `backdrop-filter: saturate(180%) blur(20px)` 玻璃效果（Electron 支持良好），参考共享层 MenuBar 的做法

**6. 高度计算使用 100vh 的溢出风险**

- 位置：`CardSettingsDialog.css`（`min(720px, calc(100vh - 48px))` 等 2 处）、`CoverMaker/TemplatePreview.tsx` 与 `CoverMaker/templates/index.ts`（4 处 `height: 100vh`）
- 问题：应用由 AppChrome 承载后视口即容器高度，`100vh` 在嵌套滚动/缩放窗口时可能溢出或截断
- 建议：弹窗高度改为相对容器（`100%`/`dvh`）或 antd Modal 的 `height` 约束；CoverMaker 模板预览的 100vh 改为 `100%`

**7. WorkspaceScene 根节点 `width: 100vw`**

- 位置：`src/scenes/WorkspaceScene.tsx`（`width: 100vw, overflow: hidden`）
- 问题：滚动条出现时 `100vw` 会比容器宽，造成横向溢出/抖动；与 AppChrome 内容区宽度不一致
- 建议：改为 `width: 100%`

### P3 — 健壮性

**8. 无错误边界**

- 位置：全局（rg ErrorBoundary 零命中）
- 问题：任一组件运行时异常将导致整个工作区白屏（React 默认行为），编辑中的卡片数据有丢失风险
- 建议：在 AppShell 层加 antd `ErrorBoundary` + `Result`（共享层 StateBoundary 或 antd ErrorBoundary），并保留"重置工作区/回到安全态"入口

**9. 工作台空态/加载态不完整**

- 位置：Dock、Workbench 主区域、FileManager 空目录等
- 问题：无卡片/空目录时没有引导性空态（antd Empty），初始加载无 Spin 反馈
- 建议：工作台无窗口时显示空态（"打开或新建卡片开始编辑"）；文件树空目录、卡箱库空列表补 Empty；初始 boot 阶段补 Spin/Skeleton

**10. 快捷键双触发风险需核实**

- 位置：`src/commands/editing-engine-commands.tsx`（Enter/F2/Delete/Mod+F 等）+ FileManager 本地键盘处理（E3 说明 FileManager 命令已本地化）
- 问题：共享层 `useCommandShortcuts` 与组件本地 keydown 可能同时响应（如 F2 重命名、Delete 删除、Enter 打开），需实测是否存在双触发（当前测试未覆盖）
- 建议：核实后统一快捷键分发归属（命令注册表优先或组件本地优先），补键盘交互测试

### P4 — 性能与代码质量

**11. 无 React.memo/性能优化**

- 位置：全局（React.memo 零使用）
- 问题：工作台窗口多（卡片窗口 + 工具窗口）时，任何 context 状态变化（如 focusWindow、selection）会重渲大量子树；Dock/WindowMenu 高频 hover 状态也无隔离
- 建议：对窗口容器（CardWindow/BoxWindow/ToolWindow）、Dock、MainArea 做 memo；context 拆分（UI context 与 selection context 已分开，可进一步细化）

**12. 测试覆盖缺口**

- 位置：`tests/unit/`（42 文件 157 用例）+ `tests/e2e/basic-flow.test.tsx`（1 个）
- 问题：覆盖良好但缺口明显——无 ThemePanel/主题相关测试（随移除）、无键盘快捷键防双触发测试、无 Dock/工作台空态测试、无错误边界测试；e2e 仅基础流
- 建议：随上述修复补对应测试；e2e 增补"打开卡片→编辑→保存"主路径

### P5 — 文档

- 位置：`技术文档/01-编辑引擎vNext架构说明.md`（已同步）；仓库根 `需求文档/`、`开发计划/`、`项目日志/` 目录缺失或未核对（`ls 技术文档/` 仅 1 篇）
