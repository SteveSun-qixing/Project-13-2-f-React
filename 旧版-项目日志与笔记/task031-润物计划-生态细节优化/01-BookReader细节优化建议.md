## 一、现状画像与对标结论

### 1.1 现状优势（应保留并发扬的底子）

经通读全部源码，Chips-BookReader 已有扎实的工程底子：

| 能力 | 现状 |
|---|---|
| 排版引擎 | 自研 DocumentController：分页/滚动双模式、RTL 与 CJK 竖排 CSS（ReadiumCSS 全套）、跨章节无缝翻页、锚点恢复 |
| 交互层 | 点击分区翻页（26%/48%/74%）、触屏滑动翻页、滚轮累积判定、全键盘覆盖、导航锁防抖 |
| 动效 | 自定义缓动（easeOutCubic/easeInOutCubic/easeOutBack）、面板滑入、dock 入场 |
| 可访问性 | roving tabindex、aria 全量、prefers-reduced-motion、焦点恢复 |
| 阅读偏好 | 4 种背景色调、2 种字体、字号、列宽、双阅读模式，偏好持久化 |
| 附加能力 | 全文搜索（分批流式+高亮）、书签（位置持久化）、目录树、拖拽开书 |

### 1.2 与世界级阅读器的核心差距（一句话结论）

**"读"的能力已达标，"沉浸感与人性化细节"差距明显**：缺翻页动画与翻页反馈、缺文本选择工具（高亮/笔记——阅读器的灵魂功能）、排版自由度不足、进度/目录/书签/搜索的呈现缺少"巧思"，chrome 信息架构偏"工具"而非"作品"。

### 1.3 对标基准

| 维度 | 对标对象 |
|---|---|
| 翻页与动效 | Apple Books（仿真翻页/滑入）、微信读书（拖拽翻页+边缘折叠） |
| 排版自由度 | 微信读书（字号/行距/字距/对齐/字体五维） |
| 选择与标注 | 微信读书、Kindle、Readwise（高亮/笔记/复制/搜索浮动条） |
| 沉浸感 | Apple Books（极简 chrome、自动隐藏） |
| 进度与恢复 | 微信读书（进度条书签点、阅读恢复提示） |

## 二、核心阅读体验（P0，强烈建议首批实施）

### 2.1 翻页动画与翻页反馈 —— 当前最大的体验短板

**现状**：分页模式翻页 = 帧内 `scrollTo` + easeOutCubic 平滑滚动；边界切换章节时直接换 iframe 内容（无过渡）。翻页"瞬移"感强，没有"纸"的感觉；用户不知道翻页是否生效、方向是否正确。

**建议方案（分三个层级，可按序实施）**：

**L1 方向感知与微反馈（成本低，收益立竿见影）**
- 翻页瞬间在对应边缘显示"翻页方向光晕"（next→右侧 4px 高光弧线从亮到透明 180ms，previous→左侧），让用户确认翻页发生；
- 章节边界切换时，新章节首屏做 200ms 淡入（opacity 0.92→1）+ 4px 上移复原，消除"硬切"感；
- 到达全书开头/结尾时，翻页触发一个 120ms 的轻微回弹（scroll 到边界后 overshoot 2px 弹回），提示"到头了"而不是静默无响应。

**L2 滑入式翻页（推荐，性价比最高的"丝滑感"来源）**
- 分页模式下引入**双视口滑入动画**：当前页内容整体左移 30% + 淡出（180ms），下一页从右侧 8% 滑入 + 淡入（220ms），共享缓动 `cubic-bezier(0.22, 0.61, 0.36, 1)`；
- 实现思路：不复制 iframe。将帧内 `body` 包一层可 transform 的滚动容器（引擎已有布局层），翻页时对该容器做位移动画，动画结束后 `scrollTo` 落位并归位 transform。此方案引擎改动集中在 `AnimationController` 与 `DocumentController.turnPage`；
- 上一页方向反向（左滑入右侧）对称处理；
- 提供 `prefers-reduced-motion` 回退（已具备降级基建）。

**L3 拖拽翻页（对标微信读书/Apple Books，工作量最大，可作为二期）**
- 触摸/鼠标按住页面右缘区域拖动时，当前页跟随手指水平位移，露出下层页面边缘阴影（深度感），松手超过阈值（位移 > 屏宽 18%）则翻页，否则回弹；
- 实现：帧内加 `touchmove`/`pointermove` 捕获 + 位移映射 + 回弹动画；需小心与现有滑动翻页手势（48px 阈值）的优先级协调（拖拽起点在页面中部 26%~74% 区才启用，边缘点击区不启用）。

### 2.2 文本选择 → 高亮/笔记/复制/搜索（功能缺口最大，P0）

**现状**：帧内文本可选中，但没有任何选择后的工具栏；选中即选中，无后续能力。世界级阅读器的"灵魂功能"缺失。

**建议方案**：
1. **选择检测**：帧内 `selectionchange` + `mouseup` 监听，选区非空且在正文内（排除标题/页眉）时，在选区上方显示浮动工具条（毛玻璃胶囊，样式对齐 03 章）；
2. **工具条动作**：
   - **高亮**（4 色可选：黄/绿/蓝/粉，微信读书式色板；长按"高亮"展开色板）
   - **下划线**（可选）
   - **笔记**（打开迷你笔记输入框，锚定在该位置）
   - **复制**（写入剪贴板）
   - **搜索**（把选中文本填入现有 SearchPanel）
   - 快捷提示：`Cmd+C` 复制、`Cmd+H` 高亮
3. **持久化模型**：扩展现有 `useBookmarks` 的 configClient 存储，新增 `annotations`（`{ id, bookSourceId, sectionIndex, startCfi/字符偏移, endCfi, type: "highlight"|"underline"|"note", color, text, note?, createdAt }`）。位置用"章节 + 文档内字符偏移"（或构造简易 CFI），保证字号/布局变化后仍可定位；
4. **渲染**：帧内加载时注入高亮样式（`mark.chips-annotation`），点击高亮弹出笔记气泡；高亮列表并入书签面板（或独立"笔记"页签）；
5. **数据出口**：支持导出（复制纯文本/Markdown），为生态"卡片化"预留。

### 2.3 排版自由度深化（P0）

**现状**：仅 字号(0.85–1.4)、列宽(560–980px)、衬线/无衬线、4 色调。微信读书是"字号/行距/字距/对齐/字体"五维可调。

**建议**：
1. **行高（line-height）滑块**：1.4–2.0 步进 0.1，默认 1.65；通过 ReadiumCssManager 注入 `--user-line-height` 变量实现（引擎已有 CSS 变量注入链路，改动小）；
2. **字距（letter-spacing）滑块**：0–0.06em 步进 0.01em（中文阅读敏感项，默认 0.01em）；
3. **对齐方式**：左对齐/两端对齐切换（默认两端对齐；中文书籍两端对齐更美观）；
4. **字体扩展**：serif/sans 之外增加"圆体（中文）"与"系统默认"，并支持**字体预览**（面板中每项直接用对应字体渲染标签文本）；
5. **段落间距与首行缩进**（进阶）：`段间距 0/8px`、`首行缩进 2em/无`——国内出版书习惯缩进，网络阅读习惯空段；
6. **即时预览**：所有滑块拖动时，iframe 实时生效（引擎 update() 已有 1 帧节流，可直连），并显示当前值（"17px / 行距 1.7"）；字号改为显示 px 而非 % 更直觉（可用 `clamp` 映射 12–28px）。

### 2.4 主题与夜间模式（P0）

**现状**：4 种固定色调（theme/warm/mist/night），"theme"是写死的米黄 #f5f2ea，不跟随系统。

**建议**：
1. **跟随系统**：新增"跟随系统"选项（默认），读取 `prefers-color-scheme`，系统切暗时自动应用 night；在 `PreferencesPanel` 排序为第一项；
2. **主题切换过渡**：切换背景色时对帧内 `body` 做 300ms 的颜色过渡（`transition: background-color 300ms, color 300ms`），避免"咔哒"感；这是质感提升的隐藏细节；
3. **亮度遮罩（护眼）**：全局亮度滑块 60%–100%，实现为帧上层半透明黑色遮罩（`pointer-events:none`），暗色阅读时降低刺眼度（微信读书标配）；
4. **色温**（二期）：暖光滤镜（`sepia` 微调），与亮度合并为"护眼"面板；
5. 夜晚自动提醒（可选，三期）：23 点后首次打开提示切换夜间模式。

### 2.5 沉浸模式与智能 Chrome（P0）

**现状**：点击中央切换 chrome 显隐；chrome 含顶部 metaCard + 底部 dock + 进度条，信息量大。

**建议**：
1. **自动隐藏**：阅读中 3.5s 无操作自动隐藏 chrome（不打断翻页——翻页不重置计时器，仅在点击/移动/按键时重置）；手动显隐仍保留；
2. **极简模式（"专注模式"）**：隐藏后仅保留一条 1px 顶部细线 + 右侧 12px 章节名小字（半透明，悬停变亮），进度变化时细线微动——Apple Books 式克制；
3. **metaCard 再设计**：现状为"书卡"（章节位置+书名+作者+进度）信息过载。建议：顶部只保留**当前章节标题**（17px 中等字重）与**进度百分比**（右对齐小字）；书名/作者信息折叠到"点按标题展开"的浮层；
4. **底部 dock 加文字标签**：纯图标对新手不友好；改为"图标+9px 标签"竖排（微信读书式），dock 呈半透明毛玻璃胶囊（现有 dock 已有毛玻璃，补齐标签即可）；
5. 增加**全屏切换**按钮（Host 侧如有 surface 全屏能力则接入；否则 `requestFullscreen` 帧内全屏）。

## 三、导航与进度（P1）

### 3.1 进度条增强（P1）

**现状**：底部 Slider 显示章节内进度 + 整书百分比；tooltip 显示百分比。

**建议**：
1. **书签标记点**：进度条上叠加书签小圆点（现有 bookmarks 数据可算位置：sectionIndex→段权重→百分比），点击圆点跳书签；
2. **章节分隔标记**：细刻度线表示章节边界，拖动时 tooltip 显示"章节名 + 百分比"（现在只显示百分比）；
3. **整书进度拖拽**：当前 Slider 只控制章节内进度（sectionFraction）。增加整书比例模式：拖动越过章节边界时切换章节并继续（用现有 sectionWeights 计算，改动在 seekToFraction 之上封装一层 `seekToBookFraction`）；
4. **快速定位**：进度条左右两端加"上一章/下一章"小按钮（键盘已有，补触控入口）；
5. 进度条**自动隐藏**与 chrome 联动（已并入 2.5）。

### 3.2 目录（TOC）增强（P1）

**现状**：NavigationTree 扁平渲染全部项（缩进 14px/级），当前章节项高亮但**不会自动滚动到可视区**；无展开/收起。

**建议**：
1. **自动定位**：打开目录时，当前章节项自动滚入可视区（`scrollIntoView({block:"center"})`），并做 600ms 背景高亮脉冲（从 `rgba(10,132,255,0.18)` 渐隐到透明）；
2. **可折叠层级**：父项支持展开/收起（`aria-expanded` 已埋点），默认展开当前章节路径、收起其余；带子项的行显示小箭头（12px，旋转 90°）；
3. **目录搜索**：顶部搜索框过滤目录项（前端过滤即可，大书可用现有 SearchEngine 的按章节索引）；
4. **页码/进度标注**：右侧对齐显示每个章节的起始进度百分比（小字 #6e6e73），阅读时对"还有多久读完这章"有直觉；
5. 层级指示：圆点/竖线引导线（当前纯缩进，视觉识别弱）。

### 3.3 书签增强（P1）

**现状**：书签只记位置（章节+页/百分比+时间），列表按章节分组倒序。

**建议**：
1. **内容摘录**：创建书签时抓取该位置前后 ~40 字作为摘录（从帧内 DOM 取文本，注意跨元素截断处理），列表显示"章节名 + 摘录首行 + 时间"，大幅提升辨识度（微信读书式）；
2. **当前书签卡片**：书签面板顶部显示"当前页书签"快捷卡（如已有则高亮）；
3. **编辑**：书签可重命名/加备注（小对话框）；
4. **与高亮统一**：二期将"高亮/笔记/书签"统一为"标注"列表，页签切换（书签/高亮/笔记）；
5. 创建书签的反馈：现有 toast 可升级为**微型动画**（dock 上书签图标 1 次 pop 缩放 + 顶部出现"已添加书签"胶囊 1.6s 后滑走）。

### 3.4 搜索增强（P1）

**现状**：按章节分组、分批流式、帧内高亮当前章节匹配；摘录**不**高亮匹配词。

**建议**：
1. **匹配词高亮**：摘录中匹配部分加 `<mark>` 样式（现有高亮机制可复用）；
2. **结果总数**：状态行显示"共 N 个结果 · 当前章节 M 个"；
3. **跳转后聚焦**：点击结果→切换章节后，等帧渲染完成（现有 pendingBoundary 机制扩展），自动滚动到首个匹配并 `scrollIntoView`，匹配项闪烁一次（500ms 脉动）；
4. **结果间跳转**：面板底部"上一条/下一条"（↑↓ 已有 roving，补显式按钮），帧内高亮随 current 移动；
5. 搜索建议（二期）：大小写敏感/全字匹配开关、搜索历史（最近 8 条，configClient 持久化）。

## 四、界面与视觉（P1）

### 4.1 空态与开书体验（P1）

**现状**：空态卡片美观（36px 圆角+毛玻璃+大标题），但缺"氛围"。

**建议**：
1. **书架感**：空态改为"书架"隐喻——居中一本书的封面占位（CSS 绘制：书脊+封面渐变色块+书名），下方"打开图书…"主按钮 + "从 URL 打开"次按钮；拖拽提示放在封面下方；
2. **最近阅读**（如果 configClient 可持久化书源历史）：空态展示最近打开的 3 本书（封面+书名+进度），点击续读——阅读器的最强召回路径；
3. **加载态**：打开大书时目前只有 overlay 胶囊。建议：胶囊下方加书籍名 + 解析进度百分比（epub 解析有分节过程，可上报进度）；胶囊加 12px 呼吸动画（scale 1→1.04 循环）；
4. **错误态**：解析失败/不支持格式时，显示 Result 式卡片（icon+原因+重试按钮），并列出支持格式（已有 supported 文案，落到卡片上）。

### 4.2 面板体验统一（P1）

**现状**：PanelShell 抽屉从右侧滑入（320ms），内容区是列表。

**建议**：
1. **毛玻璃统一**：抽屉背景改为半透明毛玻璃（`rgba(245,242,234,0.86)` + backdrop-filter blur 24px + 细边框），对齐苹果风；
2. **抽屉宽度响应式**：`min(420px, 92vw)`；窄屏（<720px）全宽；
3. **面板头部**：标题 + 右侧关闭；增加"面板切换"快捷：在目录/书签/搜索/偏好间左右滑动切换（触控）或顶部页签（桌面）——减少返回再进入的步骤；
4. **偏好面板分组**：用分段卡片（"阅读模式 / 排版 / 主题"三个分组），排版组内滑块紧凑排列；当前为 5 个 section 纵向堆叠，密度低。

### 4.3 反馈与提示（P1）

**现状**：FeedbackToast 底部居中胶囊，2.2s 自动消失。

**建议**：
1. 成功反馈改为**顶部横幅**（不遮挡阅读区底部 dock），错误保留底部；
2. 反馈图标化：成功勾、信息 i、错误 !，胶囊底色用对应语义色 12% 浅底；
3. 章节切换时（非用户操作触发）显示"章节名"过渡横幅 1.4s（居中，毛玻璃，淡入淡出）——微信读书/Apple Books 均有此细节，阅读位置感极佳。

## 五、交互细节（P1）

### 5.1 点击翻页反馈（P1）

**现状**：左右 26% 区点击翻页，无视觉反馈。

**建议**：点击瞬间在边缘显示"按压涟漪"（对应侧 120px 半径半透明圆弧，120ms 扩散淡出）或边缘短亮线；键盘方向键翻页同样给方向光晕（2.1 L1 复用）。

### 5.2 触摸与指针增强（P1）

1. **双指缩放字号**（触控平板）：pinch 手势映射字号 ±0.05/级，缩放时显示"字号 17px"气泡（现有 GestureRecognizer 只跟踪单指，需扩展双指——工作量中等，可二期）；
2. **长按选择**：触屏长按 500ms 进入选择模式（移动端选择工具栏复用 2.2）；
3. **横向滑动在滚动模式**：滚动模式下滑动主要纵向；横向滑动 48px 阈值以上是否翻章？现状纵向边界判定已处理，横向无。建议横向滑动 80px 以上翻章（与分页模式对称）；
4. **触控目标**：dock 按钮 ≥ 44px（当前 36px，提升易点性）。

### 5.3 键盘体验（P1）

**现状**：方向键/空格/Home/End/[ ]/- = 全覆盖，非常好。

**建议补充**：
1. `Cmd+P` 打开偏好面板（与共享层 CommandPalette 快捷键冲突需协调——共享层用 Mod+P 开命令面板，BookReader 建议 Mod+Shift+P 或直接注册为面板命令）；
2. `N` 下一章 / `P` 上一章（Kindle 惯例）；
3. `F` 全屏；`T` 主题切换（循环 4 色调）；
4. 输入框聚焦时现有 `isEditableTarget` 已豁免，保持；
5. 帮助浮层：长按 `?` 或菜单"快捷键"项弹出快捷键一览（毛玻璃卡片）——目前快捷键无发现途径。

### 5.4 竖排/横排切换入口（P1）

**现状**：ReadiumCSS 已内置 cjk-vertical 全套 CSS，但 UI 无切换入口——**能力已备、入口缺失**。

**建议**：偏好面板新增"排版方向"分段（横排/竖排），竖排时内容宽度自动适配（窄列），仅对 CJK 内容生效；ReadiumCssManager 已有注入链路，成本低，回报独特（对标 Apple Books 中文竖排）。

## 六、阅读状态与持久化（P1）

### 6.1 阅读进度恢复（P1）

**现状**：书签持久化，但**阅读进度本身不持久化**——关闭重开后回到章节开头（launch-resource 会重新打开书，但位置丢失）。这是阅读器的基本盘。

**建议**：
1. 阅读位置节流写入 configClient（`reading-position`：sectionIndex + 页/滚动分数 + 时间戳，节流 2s/次）；
2. 重新打开书时检测上次位置，显示"已恢复到 85%（上次阅读于 昨天 22:41）"横幅 3s，带"从头开始"小链接（Apple Books 式）；
3. 位置恢复的锚点逻辑复用现有 pendingBoundary/controller.goToSpread 机制。

### 6.2 阅读统计（P2）

- 记录每日阅读时长（会话计时+切章事件），偏好面板或独立"统计"页签展示：今日 X 分钟、连续阅读 N 天、本周阅读时长柱状图（7 根细柱，克制设计）；
- 统计存储 configClient（`reading-stats`）。

## 七、性能与工程质量（P2）

1. **大书分页性能**：万页级书籍首次分页可能卡顿——分页计算加空闲分片（`requestIdleCallback` 批次），先渲染前 3 屏，后台补齐（现 engine mount 后统一 alignToViewport，可分层）；
2. **图片懒加载**：帧内 `loading="lazy"` 注入（ReadiumCssManager 处理 img 时补属性）+ 视口外图片延迟解码 `decoding="async"`；
3. **搜索节流**：输入 300ms 防抖（当前每击键触发搜索取消重启，输入中文时 IM 抖动明显）；
4. **内存**：章节切换后释放旧帧 DOM（iframe srcdoc 替换即释放，确认无泄漏：PositionTracker/controller 已随 useReaderEngine 重建）；
5. **首屏渲染**：封面章节优先加载；开书体验 4.1-2 的进度提示与分片配合。
