# 工单111-chipsdevBuild未识别主题包正式构建脚本

## 背景

本轮需要创建本地开发工作区，并打包安装主题包、应用插件、基础卡片插件、箱子布局插件和模块插件。按公共命令行文档，五类插件工程应优先使用 `chipsdev build / validate / package` 完成正式构建与打包。

## 证据

1. 在 `ThemePack/Chips-default` 执行 `chipsdev build` 时失败，错误为 `Could not resolve entry module "src/main.ts"`。
2. `ThemePack/Chips-default/chips.config.mjs` 只声明 `type: "theme"`、`srcDir: "src"`、`distDir: "dist"`、`manifest: "manifest.yaml"`，未声明 `entry`。
3. `Chips-SDK/cli/index.js` 的 `loadProjectConfig()` 在缺少 `entry` 时对非 app 工程默认推导 `src/main.ts`。
4. `ThemePack/Chips-default/package.json` 已声明正式 `build` 脚本，串联 `build:tokens`、`build:contracts`、`build:css`。

## 影响范围

- `ThemePack/Chips-default`
- `ThemePack/Chips-theme-default-dark`
- `chipsdev build`
- 全量开发工作区初始化和全量插件打包安装流程

## 复现步骤

1. 进入 `ThemePack/Chips-default`；
2. 执行 `chipsdev build`；
3. 观察 Vite/Rollup 尝试解析 `src/main.ts` 并失败；
4. 对照主题包 `package.json`，确认主题包正式构建入口应是 `npm run build`。

## 期望行为

`chipsdev build` 应识别 `type: "theme"` 工程，优先委托主题包自身非递归 `build` 脚本，或提供主题包专用构建分支，完成 tokens、contracts、CSS 构建，而不是使用通用插件入口 `src/main.ts`。

## 暂行处理

本轮不修改 `chipsdev` 工具链代码。主题包按照自身 `package.json` 正式脚本执行 `npm run build`、`npm run validate:theme` 和 `npm test`，之后继续使用 `chipsdev validate`、`chipsdev package`、`chipsdev plugin install`、`chipsdev plugin enable` 完成开发工作区安装。

## 第一版边界与后续落点

本工单不阻断第一版结构、契约、主题注入和发布冻结。当前默认主题包和深色默认主题包可以通过自身正式脚本完成 tokens、contracts、CSS 构建与主题验证，再继续通过 `chipsdev validate/package/install/enable` 完成开发工作区安装和启用。

后续 SDK / chipsdev 工具链任务需要让 `chipsdev build` 对 `type: "theme"` 工程分流到主题包正式 `build` 脚本，或提供主题包专用构建链路，避免五类插件一键构建时再次按通用 `src/main.ts` 入口推导。
