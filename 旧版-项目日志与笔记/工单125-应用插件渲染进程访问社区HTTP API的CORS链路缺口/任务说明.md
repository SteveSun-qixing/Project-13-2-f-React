# 工单125：应用插件渲染进程访问社区 HTTP API 的 CORS 链路缺口

## 背景

- 开发薯片社区客户端（`com.chips.community-client`，type: app）时，客户端核心职责是浏览社区内容（用户主页、卡片、箱子等），需要调用社区服务器 HTTP API；
- 社区服务器生产环境 CORS 只允许 `BASE_URL` 同源或 `!origin`（无 Origin 头）请求（`packages/server/src/app.ts:46-59`）；
- 应用插件运行在 Host 渲染进程，页面通过 `file://` 或 `chips-render://` 协议加载；渲染进程 `fetch` 社区 API 时，请求会携带非空 Origin（`file://` 或 `chips-render://...`），生产环境会被 CORS 拒绝；
- SDK / Host 当前没有正式的网络请求封装或网络代理 Bridge，应用插件访问外部 HTTP API 缺少统一正式链路。

## 证据

- `Chips-CommunityPlatformServer/packages/server/src/app.ts:54`：`if (!origin || origin === env.BASE_URL)`，生产只放行同源或空 Origin；
- `Chips-Host/src/main/electron/render-document-protocol.ts`：`chips-render` 注册为 standard+secure 协议，渲染进程页面拥有独立 origin；
- `Chips-SDK/src/types/client.ts`：`Client` 域名 API 中没有 network/http 请求能力；
- `生态共用技术文档/协议与接口标准/05-系统接口标准.md`：服务域总表中没有网络请求域；
- 社区 Web 前端通过同源 `/api` 代理（Vite/Nginx）访问，不跨域；桌面客户端没有同源代理。

## 影响范围

- 薯片社区客户端等所有需要访问外部 HTTP API 的应用插件；
- 社区平台 API 契约的"客户端"消费场景；
- Host 渲染进程对外部网络资源的正式访问链路。

## 复现步骤

1. 以 `NODE_ENV=production`、`BASE_URL=https://www.chipscard.space` 启动社区服务器；
2. 在应用插件渲染进程 `fetch('https://www.chipscard.space/api/v1/discover/cards')`；
3. 观察请求因 CORS 被拒绝（Origin 非空且不等于 BASE_URL）。

## 期望行为

- 建立应用插件渲染进程访问外部 HTTP API 的正式链路，二选一（或组合）：
  - 社区服务器生产 CORS 放行薯片 Host 客户端来源（如 `chips-render://` 或空 Origin 的客户端请求）；
  - Host 提供正式网络请求能力（如 `network.request` 域），由 Host 主进程代理，绕开渲染进程 CORS 限制；
- 对应 SDK 类型化封装、权限模型、CSP 基线同步收口；
- 更新社区平台 API 契约与系统接口标准。

## 暂行处理

- 本轮薯片社区客户端开发使用社区服务器开发模式（`NODE_ENV=development`，CORS 全放行）联调；
- 生产部署依赖本工单收口后正式链路，不在客户端内自建临时网络桥；
- 客户端 CSP `connect-src` 在开发阶段放行社区 API 来源，正式链路收口后按 Host 统一基线调整。

## 需要协作方

- 社区服务器维护方（CORS / 客户端来源放行）
- Host 维护方（网络请求能力与权限模型）
- SDK 维护方（类型化封装）

## 修复说明（2026-08-05）

已在社区服务器侧收口客户端访问链路：

1. **CORS 放行客户端来源**：`Chips-CommunityPlatformServer/packages/server/src/app.ts` 生产模式新增放行：
   - Origin 以 `chips-render:` 开头的薯片 Host 客户端来源；
   - `null` Origin（file:// 页面加载的客户端）；
   - `CORS_EXTRA_ORIGINS` 环境变量白名单（逗号分隔）中的来源；
   - 判定逻辑提取为导出函数 `isClientCorsOriginAllowed`，便于测试与复用。
2. **认证链路支持客户端**：`Chips-CommunityPlatformServer/packages/server/src/routes/auth.ts` 登录 / 注册响应体新增 `refreshToken` 字段（同时保留 HttpOnly Cookie 写入，网页同源场景行为不变）；刷新接口原本已支持请求体 `refreshToken`，客户端可直接使用。
3. **环境变量**：`Chips-CommunityPlatformServer/packages/server/src/config/env.ts` 新增 `CORS_EXTRA_ORIGINS`（默认空）。
4. **契约更新**：`生态共用技术文档/协议与契约/09-社区平台API契约.md` 升版 v1.3，新增 1.5 客户端来源与 CORS、更新 2.2/2.3 认证契约（响应体返回 refreshToken 明文说明）。
5. **测试**：新增 `Chips-CommunityPlatformServer/packages/server/src/routes/auth.test.ts`（登录/注册返回 refreshToken + CORS 客户端来源判定），服务端全量测试 62 项通过，`tsc --noEmit` 通过。
