# 工单113：应用命令快捷键全局注册导致富文本编辑触发未保存确认

## 背景

用户反馈富文本编辑器无法正常编写内容，每次编辑都会跳出“内容还没有保存”一类提示。按照工作区规则，排查前已复核富文本编辑器、基础卡片插件、Host 命令系统、PAL 快捷键实现以及编辑运行时相关公共文档。

本问题不是富文本编辑控件本身在每次输入时主动弹窗，而是输入后文稿进入 dirty 状态，随后被应用命令快捷键或页面生命周期路径触发未保存保护。

## 证据

1. `Chips-RichTextEditor/src/app/RichTextEditorScene.tsx` 中 `confirmDiscardIfNeeded()` 在 `session.dirty === true` 时调用 `client.platform.showConfirm(...)`，文案使用 `app.discardPromptTitle` 与 `app.discardPromptMessage`。
2. 同一文件中新建、打开和 `openDocumentByPath()` 会调用 `confirmDiscardIfNeeded()`，因此只要 dirty 后触发这些命令，就会弹出应用内“放弃当前修改”确认。
3. `Chips-RichTextEditor/src/app/RichTextEditorScene.tsx` 注册了 `window.beforeunload`，在 `sessionRef.current.dirty` 或 `saveState === "saving"` 时调用 `event.preventDefault()` 与 `event.returnValue = ""`，这会触发浏览器/Electron 的系统级未保存离开页面提示。
4. `Chips-RichTextEditor/src/commands/rich-text-editor-commands.ts` 给应用命令注册了文本编辑敏感快捷键，包括：
   - `Mod+N` 新建；
   - `Mod+O` 打开；
   - `Mod+S` 保存；
   - `Mod+Shift+S` 另存为；
   - `Mod+P` 预览。
5. `Chips-RichTextEditor/src/commands/useRichTextEditorCommands.ts` 在应用启动后通过 `client.command.register(definition)` 注册上述 command metadata。
6. `Chips-Host/src/main/services/register-host-services.ts` 的 `registerCommandShortcuts()` 把 command shortcut 交给 `ctx.pal.systemUi.shortcut.register(shortcut.accelerator, ...)`。
7. `Chips-Host/packages/pal/src/node-adapter.ts` 中 `NodeShortcut.register()` 在 Electron 环境实际调用 `this.electron.globalShortcut.register(accelerator, ...)`。
8. 因此，当前应用命令快捷键不是窗口/Surface/焦点作用域快捷键，而是 Electron 全局快捷键；它会绕过富文本编辑 iframe 和 contenteditable 的焦点语义，把输入场景中的快捷键直接派发为应用命令。

## 影响范围

- `Chips-RichTextEditor`：富文本输入被未保存确认打断，用户无法稳定编辑。
- `Chips-Host` command registry：应用级 command shortcut 与系统全局快捷键边界混淆。
- PAL / Electron：`systemUi.shortcut` 当前只有 globalShortcut 落地，缺少聚焦窗口/Surface 作用域快捷键。
- 未来所有编辑类应用：编辑器、阅读器搜索、设置表单、插件市场搜索框等带输入焦点的场景都可能误触发应用命令。
- SDK 和共享命令契约：需要明确 command shortcut、platform global shortcut、焦点上下文、when 条件和可编辑区域接管规则。

## 复现步骤

1. 启动 `Chips-RichTextEditor` 并新建或打开文稿；
2. 在富文本编辑区输入任意内容，使当前 session 变为 dirty；
3. 在编辑区焦点内触发 `Mod+N`、`Mod+O`、`Mod+P` 等应用命令快捷键，或触发导致页面/窗口生命周期变化的路径；
4. 观察应用内弹出放弃修改确认，或出现浏览器/Electron 系统级“内容还没有保存”离开页面提示；
5. 对照 Host 代码确认该快捷键通过 Electron `globalShortcut` 注册，而不是按当前聚焦 surface 派发。

## 期望行为

- Host command shortcut 应由当前聚焦窗口、surface、scene、document、编辑上下文和 command scope 共同决定是否派发。
- 应用级 command shortcut 不应使用系统全局快捷键承载；系统全局快捷键应作为 `platform.shortcut` 一类独立能力，且需要显式权限和产品意图。
- 快捷键派发前应重新读取 command state，校验 enabled/visible、权限、scope、焦点上下文和可编辑区域规则。
- 对 `input`、`textarea`、`contenteditable`、富文本 iframe 和 IME 组合输入场景，默认保留编辑语义；只有明确声明可在编辑上下文接管的命令才能截获。
- 富文本编辑器的未保存确认应只发生在明确破坏性操作上，普通输入和编辑区快捷键不应反复触发弹窗。
- `beforeunload` 在编辑运行时中应优先用于冲刷保存或清理资源；是否阻断关闭应由 Host 窗口关闭/文档关闭语义统一管理。

## 暂行处理

已按正式架构修复 Host command shortcut 作用域派发，不在富文本编辑器内删除快捷键、屏蔽 `beforeunload` 或绕过 dirty 保护。

处理结果：

1. `Chips-Host/src/main/services/register-host-services.ts` 中 command shortcut 不再调用 PAL `systemUi.shortcut.register`，避免应用命令进入 Electron `globalShortcut`。
2. 新增 `Chips-Host/src/preload/command-shortcuts.ts`，由插件窗口 preload 在当前 surface 内监听快捷键，按 `launchContext` 过滤 command，并通过 `command.invoke(source="shortcut")` 派发。
3. 快捷键派发会避开 `input`、`textarea`、`contenteditable`、富文本 iframe 事件路径与 IME 组合输入，普通富文本编辑不再触发新建/打开等未保存确认。
4. `platform.shortcutRegister/Unregister/List/Clear` 仍保留为系统级全局快捷键能力，与 command shortcut 明确分层。
5. 已同步更新公共命令系统契约与应用插件开发文档。
