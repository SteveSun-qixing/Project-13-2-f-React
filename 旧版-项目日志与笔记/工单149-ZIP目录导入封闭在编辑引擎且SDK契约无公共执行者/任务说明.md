# 工单149-ZIP目录导入封闭在编辑引擎且SDK契约无公共执行者：任务说明

## 1. 背景

SDK 已定义 `importArchiveBundle` 完整契约（CardEditorArchiveImportRequest/Result），但契约只能由编辑引擎应用本地实现执行，Host 侧没有公共执行者。与「目录解包能力应作为通用资源导入能力设计」（`生态设计原稿/13-公共基础层设计.md`）的正式方向不符。

## 2. 证据

- `Chips-SDK/src/api/card.ts`：`CardEditorArchiveImportRequest/Result` 类型完整定义（根探测、entryFile、include 过滤、stripSingleRootDir、excludeSystemArtifacts、discardedEntries 分类）；
- `Chips-EditingEngine/src/editor-runtime/archive-import.ts`（592 行）：resolveArchivePayloadRoot / resolveGenericPayloadRoot、detectImageMimeType（魔数嗅探）、MIME/扩展名过滤、__MACOSX/.DS_Store 清理、暂存→移动→失败回滚；
- Host 动作注册表：无 `resource.importArchive` 或等价动作。

## 3. 影响范围

- Chips-SDK 编辑器资源桥契约、Chips-Host resource 服务域、Chips-EditingEngine EditorHost；
- 第三方编辑器宿主、未来移动端编辑产品；
- 大文件导入的进度/取消语义缺失。

## 4. 复现步骤

1. 在编辑引擎编辑器导入 ZIP 资源包，观察全部导入逻辑在应用内执行；
2. 检索 Host 动作，无 `resource.importArchive` 或等价动作；
3. 确认 SDK 契约在 Host 侧无执行者。

## 5. 期望行为

Host 提供 `resource.importArchive` 动作：

- 输入输出与 SDK `CardEditorArchiveImportRequest/Result` 对齐（一次收口两端）；
- 路径逃逸校验、过滤、清理、回滚由 Host 主进程统一把关；
- 大文件进度走 module.job 任务模型（progress 事件 + 取消支持）；
- 语义冻结：`zip.extract` 是原语（解到指定目录），`resource.importArchive` 是业务语义（根探测/过滤/清理/回滚）；
- 编辑引擎 archive-import.ts 整体迁入 Host 后删除本地实现（测试同步迁移）。

## 6. 暂行处理

无。本工单由 task034 迁移任务 M4 直接修复。

## 7. 需要协作方

Chips-Host resource 服务域维护方、Chips-SDK 维护方、Chips-EditingEngine 维护方。

## 8. 处理结果（2026-08-11，M4 完成）

- Host 落地 `resource.importArchive` 动作（60s 超时、file.read/file.write/resource.read），实现于 `packages/zip-service/src/archive-import.ts`（根探测/过滤/魔数嗅探/系统垃圾清理/暂存回滚），契约测试 7 用例；
- SDK 新增 `resource.importArchive` API 与类型（与 CardEditorArchiveImportRequest/Result 对齐），route-manifest 同步；
- 编辑引擎 EditorHost.importArchiveBundle 改为消费 Host 动作，本地实现与测试移入归档（`Chips-EditingEngine/归档/task034-archive-import/`）；
- 验证：Host/SDK/编辑引擎全量无新增失败；
- 详情见 `task034-编辑引擎能力整合/14-M4实施记录.md`。
