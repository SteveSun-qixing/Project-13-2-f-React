# 工单165：办公插件能力边界与 GenOffice 运行时迁移缺口

## 基本信息

- 工单编号：工单165
- 日期：2026-09-01
- 发现阶段：Word、Slide、Sheet、PDF 应用插件代码审查
- 问题类型：应用插件架构边界缺口 / 功能迁移不完整 / 第三方依赖治理缺口
- 状态：待处理

## 背景与证据

GenOffice 原项目依赖 Electron preload、Node 文件系统和 XLSX Rust sidecar；插件必须由 Host 承载并通过 Bridge/SDK 访问系统能力。当前迁移代码虽已完成四个浏览器 React 入口和基础编辑链路，但边界仍未完全收口：

1. `OpenSourceProjectHandlingFolder/GenOffice/genoffice-main/apps/sheets/src/main/xlsx-sidecar-client.ts` 通过 `node:child_process` 启动 Rust sidecar；`Chips-Sheet` 未提供 Host module/service 替代，当前 XLSX 读写已缩减为浏览器 `exceljs` + Univer 能力，无法宣称完整迁移。
2. `Chips-Word/vendor/pptx-engine` 以及其媒体、布局、写出路径仍有 `Buffer`、`node:fs`、`node:stream/promises` 等 Node-only 代码；Word 仍将该 vendor 作为依赖，浏览器运行边界未被正式验证。
3. GenOffice 原 docs/slides/pdf 还包含 PDFium、OCR、PDF→DOCX、复杂字体/图片编辑等主进程能力，当前 Chips-PDF/Slide 需求和实现未形成完整能力矩阵，迁移范围与“完整彻底移植”表述不一致。
4. Sheet/PDF 未附独立 GenOffice/第三方 NOTICE 清单，发布包无法证明 Apache-2.0、Univer、pdf.js、pdf-lib、字体等许可证归属已闭环。

## 影响范围

- Chips-Word、Chips-Slide、Chips-Sheet、Chips-PDF 的功能承诺、浏览器构建和发布合规；
- Chips-Host 模块服务、文件转换能力和未来 XLSX/PDF 高保真能力；
- 第三方依赖、许可证与分发包审计。

## 复现步骤

1. 在四个插件分别执行 `npm run verify`，基础门禁可通过，但不会验证 GenOffice 全量能力等价性。
2. 在 Word vendor 中搜索 `node:` / `Buffer`，可见浏览器入口之外仍存在 Node-only 写出路径。
3. 对照 GenOffice sheets sidecar 与 `Chips-Sheet/src/sheet/workbook-io.ts`，确认 Rust sidecar 能力没有 Host 路由实现。
4. 检查 `Chips-Sheet`、`Chips-PDF` 发布目录，未见独立第三方告知文件。

## 期望行为

- 冻结四插件正式能力矩阵，明确“已迁移、由 Host 模块提供、暂不迁移”的能力边界；
- 为 XLSX sidecar 与 PDFium/OCR 等主进程能力设计 Host module/service 正式契约，插件只调用 SDK；
- 清理或隔离所有进入浏览器构建的 Node-only vendor 代码，并增加产物扫描门禁；
- 四插件分别生成完整第三方 NOTICE/许可证清单和修改声明。

## 暂行处理

- 本轮保留现有浏览器能力，不在插件内 spawn sidecar、直连 Node 或伪造高保真能力；
- 对外文档应明确当前 Sheet/PDF 的真实能力范围，待 Host/SDK 契约收口后再扩展。

## 需要协作方

Chips-Host、Chips-SDK、四个应用插件维护方及发布合规维护方。
