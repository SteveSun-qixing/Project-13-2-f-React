# 工单115：DataGrid 复合子节点内部容器缺少 key

## 背景

生态设置面板前端重做时，治理列表从 `ChipsDataGrid.Root` 数据驱动模式迁移为 `ChipsDataGrid.Root/Header/Row/Cell` compound 结构，以避免业务层通过 CSS 强行覆盖 `<table>` 显示模型造成列对齐不稳定。

迁移后设置面板单元测试均通过，但 React 在多个治理页面测试中输出缺少 key 的警告。

## 证据

设置面板侧已经为以下节点提供稳定 key：

- `ChipsDataGrid.Header key="header"`
- rowgroup 容器 `key="body"`
- 每个 `ChipsDataGrid.Row key={row.id}`
- 每个 `ChipsDataGrid.Cell key={row.id + columnId}`

警告仍然出现，堆栈指向 `Chips-ComponentLibrary/packages/components/src/index.js:12173` 附近的 `DataGridRoot`。

组件库实现中 `DataGridRoot.renderCompoundChildren()` 返回数组：

```ts
return [
  ...beforeGrid,
  gridChildren.length > 0 ? renderGridContainer(gridChildren) : null,
  ...afterGrid,
];
```

其中 `renderGridContainer(gridChildren)` 创建的内部 `<div role="grid">` 没有 key。

## 影响范围

- 使用 `ChipsDataGrid.Root` compound children 的页面会在 React SSR/测试渲染中出现 key 警告。
- 设置面板治理列表已采用该正式结构，因此测试输出存在非阻断噪音。
- 如果后续把 React warning 作为失败门禁，该问题会阻断使用正式 DataGrid compound API 的业务页面。

## 复现步骤

1. 在 `ChipsDataGrid.Root` 中使用 `ChipsDataGrid.Header` 与自定义 rowgroup/row/cell children。
2. 使用 React server render 或 Vitest 渲染该页面。
3. 观察 `Each child in a list should have a unique "key" prop.` 警告。
4. 给业务侧 header、rowgroup、row、cell 均补 key 后警告仍存在。
5. 检查 `DataGridRoot.renderCompoundChildren()`，确认内部 grid 容器没有 key。

## 期望行为

- `DataGridRoot` 在 compound children 分支创建内部 grid 容器时应提供稳定 key。
- 组件库应补充 compound DataGrid 渲染测试，覆盖 header + 自定义 rowgroup + row/cell 的无警告场景。
- 业务项目使用正式 compound API 时不应因为组件库内部数组元素缺 key 产生 React 警告。

## 暂行处理

设置面板继续使用正式 `ChipsDataGrid.Root/Header/Row/Cell` compound 结构，不回退到业务层 `<table>` 显示模型覆盖。设置面板侧已补齐可控子节点 key，并将该问题登记为组件库缺口。
