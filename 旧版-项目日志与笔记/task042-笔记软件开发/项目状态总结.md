## 🏗️ 技术架构

### 目录结构
```
Chips-Notes/
├── src/
│   ├── app/
│   │   ├── AppRoot.tsx              # 根组件 + Providers
│   │   └── AppShell.tsx             # 应用外壳
│   ├── layouts/
│   │   └── NotesLayout.tsx          # FlexLayout 三列布局
│   ├── panels/
│   │   ├── DirectoryTreePanel.tsx   # 目录树（已集成服务）
│   │   ├── NoteEditorPanel.tsx      # 编辑区（已集成服务）
│   │   └── CardLibraryPanel.tsx     # 卡片库（已集成服务）
│   ├── services/
│   │   ├── notebook-service.ts      # 笔记本管理
│   │   └── note-service.ts          # 笔记管理
│   ├── context/
│   │   ├── NotebookContext.tsx      # 笔记本状态
│   │   └── NoteContext.tsx          # 笔记状态
│   ├── styles/
│   │   └── global.css               # 全局样式
│   └── runtime/
│       ├── AppRuntimeProvider.tsx   # 运行时 Provider
│       └── chips-client.ts          # SDK 客户端
├── manifest.yaml                     # 插件配置
├── package.json                      # 项目配置
└── README.md                         # 项目说明
```

### 数据流
```
用户操作
  ↓
Panel 组件（UI）
  ↓
Context Hook（useNotebook / useNote）
  ↓
Service 层（notebook-service / note-service）
  ↓
Chips SDK（client.workspace / client.box / client.card）
  ↓
文件系统（.box / .card 文件）
```

### 关键技术点
- **FlexLayout**：可调整大小的三列布局
- **React Context**：全局状态管理
- **Chips SDK**：与主机通信
- **Ant Design**：UI 组件库
- **YAML**：配置文件格式

## 📝 重要决策记录

### 1. 使用 FlexLayout 而非自定义布局
**原因**：
- 用户明确要求
- 可调整列宽
- 成熟稳定
- 符合专业笔记软件体验

### 2. 使用 Context API 而非 Redux
**原因**：
- 项目规模适中
- 减少依赖
- React 18+ 性能优化
- 薯片生态轻量化原则

### 3. 目录树有"工作区"根节点
**原因**：
- 统一操作入口
- 避免根级操作歧义
- 清晰的层级结构
- 符合常见交互模式

### 4. 阶段二不实现基础卡片渲染
**原因**：
- 聚焦数据流打通
- 基础卡片渲染复杂，需专门实现
- 需要详细研究编辑引擎
- 分阶段降低风险
