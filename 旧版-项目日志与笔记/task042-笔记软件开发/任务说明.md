# Task 042 - 薯片笔记软件开发

> 任务创建时间：2026-09-04  
> 任务状态：进行中  
> 插件 ID：`chips-official.notes`

## 1. 任务目标

基于复制的 Chips-EditingEngine 代码库，重新设计并实现 Chips-Notes 笔记应用，目标是打造一款使用体验类似传统 Markdown 笔记软件，但底层完全基于薯片生态卡片和箱子文件系统的现代笔记应用。

## 2. 核心设计理念

### 2.1 用户体验层

- **笔记本概念映射**：用户创建的"笔记本"本质是采用文档库布局的 `.box` 箱子文件
- **笔记概念映射**：用户编写的"笔记"本质是 `.card` 基础卡片文件
- **使用体验**：完全模仿传统 Markdown 笔记软件的交互方式，用户无需理解底层的箱子和卡片概念
- **编辑体验**：类似传统笔记软件的流式编辑，支持直接输入、插入不同类型的内容块

### 2.2 技术架构层

- **底层存储**：完全使用薯片生态的 `.card` 和 `.box` 文件格式
- **卡片装配**：复用编辑引擎的基础卡片运行时、装配系统和编辑链路
- **箱子管理**：通过 Host `box-service -> chips-sdk` 正式链路管理箱子
- **布局系统**：使用 FlexLayout 重构前端布局架构，替代原有的无限桌面布局

### 3.2 左侧：目录树面板

**功能职责**：
- 展示笔记本（箱子）和笔记（卡片）的树形结构
- 支持创建、删除、重命名、移动操作
- 支持拖拽排序和移动
- 根目录可直接存放未分类的笔记

**实现要点**：
- **不使用箱子自带的前端显示模块**，由笔记应用自己解析箱子内容并构建目录树
- 使用 `chips-sdk` 的 `client.box.*` API 读取箱子条目列表
- 使用 antd Tree 组件实现树形展示
- 支持右键菜单：新建笔记本、新建笔记、删除、重命名、导出

**数据结构**：
```typescript
interface TreeNode {
  key: string;           // 唯一标识
  title: string;         // 显示名称
  type: 'root' | 'notebook' | 'note';  // 节点类型
  path?: string;         // 文件路径（.box 或 .card）
  children?: TreeNode[]; // 子节点
  icon?: React.ReactNode; // 图标
}
```

### 3.3 中间：卡片编辑/预览区

**功能职责**：
- 流式展示当前笔记的所有基础卡片内容
- 支持直接内嵌编辑（主要是富文本卡片）
- 对于非富文本卡片，点击后右侧切换到对应编辑面板

**编辑模式**：
1. **富文本卡片**：直接在中间区域内嵌编辑面板，用户像使用传统笔记软件一样直接输入
2. **其他卡片**：点击卡片后，右侧面板切换为对应的编辑面板；编辑完成点击"保存"按钮
3. **插入新卡片**：从右侧卡片库选择或拖拽，自动插入到光标位置或列表末尾

**实现要点**：
- 复用编辑引擎的 `BasecardFrameHost` 和基础卡片装配运行时
- 每个基础卡片在独立 iframe 中渲染（透明单卡 iframe）
- 注入苹果风格帧样式、资源回调（`resolveResourceUrl`、`releaseResourceUrl`、`importResource` 等）
- 维护卡片顺序和编辑状态

### 3.4 右侧：卡片选择/编辑面板

**两种模式**：

#### 模式一：卡片选择库（默认模式）
- 展示所有可用的基础卡片类型（从基础卡片注册表加载）
- 网格或列表形式展示卡片图标和名称
- 点击或拖拽插入到中间编辑区

#### 模式二：卡片编辑面板（编辑模式）
- 当用户在中间区域点击非富文本卡片时自动切换到此模式
- 显示对应基础卡片的完整编辑面板
- 底部显示"保存"按钮，保存后自动切回卡片选择库模式

**实现要点**：
- 使用状态控制两种模式的切换
- 编辑面板复用编辑引擎的 `EditorHost` 组件
- 支持编辑面板的完整生命周期（草稿、校验、资源导入、保存）

## 4. 核心功能设计

### 4.1 笔记本管理

**创建笔记本**：
```typescript
async function createNotebook(name: string, parentPath?: string): Promise<string> {
  // 1. 使用 SDK 创建新箱子
  const boxPath = await client.box.create({
    name,
    layoutType: 'document-library', // 固定使用文档库布局
    location: parentPath || workspace.rootPath
  });
  
  // 2. 初始化箱子元数据
  await client.box.updateMetadata(boxPath, {
    createdAt: Date.now(),
    modifiedAt: Date.now()
  });
  
  return boxPath;
}
```

**打开笔记本**：
```typescript
async function openNotebook(boxPath: string): Promise<Notebook> {
  // 1. 读取箱子元数据
  const metadata = await client.box.readMetadata(boxPath);
  
  // 2. 列出所有条目（卡片）
  const entries = await client.box.listEntries(boxPath);
  
  // 3. 构建笔记列表
  return {
    path: boxPath,
    name: metadata.name,
    notes: entries.map(entry => ({
      id: entry.id,
      name: entry.name,
      path: entry.path,
      modifiedAt: entry.modifiedAt
    }))
  };
}
```

### 4.2 笔记管理

**创建笔记**：
```typescript
async function createNote(notebookPath: string | null, name: string): Promise<string> {
  // 1. 创建基础卡片文件（默认富文本类型）
  const cardPath = await client.card.create({
    type: 'rich-text',
    name,
    location: notebookPath || workspace.rootPath
  });
  
  // 2. 如果在笔记本中，添加到箱子
  if (notebookPath) {
    await client.box.addEntry(notebookPath, {
      cardPath,
      sortKey: generateSortKey() // 生成排序键
    });
  }
  
  return cardPath;
}
```

**编辑笔记**：
```typescript
async function editNote(cardPath: string): Promise<void> {
  // 1. 使用 CardService 解包卡片
  const unpackedCard = await cardService.unpack(cardPath);
  
  // 2. 读取卡片结构和内容
  const structure = await cardService.readStructure(unpackedCard);
  const contents = await cardService.readContents(unpackedCard, structure);
  
  // 3. 渲染编辑区（中间面板）
  renderEditingArea(structure, contents);
}
```

**保存笔记**：
```typescript
async function saveNote(cardPath: string, contents: CardContent[]): Promise<void> {
  // 1. 校验内容
  const validation = await validateContents(contents);
  if (!validation.valid) {
    throw new Error(validation.errors.join(', '));
  }
  
  // 2. 通过 CardService 保存
  await cardService.save(cardPath, {
    structure: buildStructure(contents),
    contents: contents,
    resources: collectResources(contents)
  });
  
  // 3. 重新打包为 .card ZIP 文件
  await cardService.pack(cardPath);
}
```

### 4.3 流式编辑体验

**核心设计**：
```typescript
interface NoteEditingState {
  noteId: string;
  notePath: string;
  
  // 卡片内容列表（按顺序）
  cardContents: Array<{
    id: string;                    // 基础卡片实例 ID
    type: string;                  // 基础卡片类型
    config: unknown;               // 卡片配置
    editing: boolean;              // 是否正在编辑
    dirty: boolean;                // 是否有未保存更改
  }>;
  
  // 当前编辑的卡片
  activeCardId: string | null;
  
  // 右侧面板模式
  rightPanelMode: 'card-library' | 'card-editor';
}
```

**富文本直接编辑**：
- 富文本卡片的编辑面板直接内嵌在中间区域
- 用户可以像传统笔记软件一样持续输入
- 实时保存草稿，定时或手动触发最终保存

**其他卡片点击编辑**：
1. 用户点击中间区域的非富文本卡片（如图片、视频、网页）
2. 右侧面板自动从"卡片库"模式切换到"编辑面板"模式
3. 加载对应基础卡片的编辑面板
4. 用户编辑完成后点击"保存"按钮
5. 保存成功后自动切回"卡片库"模式

**插入新卡片**：
- 方式一：点击右侧卡片库中的卡片类型，自动插入到当前位置
- 方式二：拖拽卡片类型到中间区域的目标位置
- 插入后自动进入编辑状态（非富文本自动切换右侧为编辑面板）

**资源回调统一处理**：
```typescript
const resourceCallbacks = {
```

- **编辑模式切换**：需要确保右侧面板的模式切换流畅自然
- **保存时机**：需要平衡自动保存和手动保存，避免数据丢失或过度保存
- **性能问题**：大量卡片渲染可能影响性能，需要考虑虚拟滚动

### 11.3 架构风险
- **与编辑引擎的差异**：笔记应用的编辑模式与编辑引擎有本质区别，需要重新设计状态管理
- **文件系统依赖**：需要确保 SDK 的文件和箱子 API 足够完善
