# 工单142：documentLibrary-BLP schema 测试动态导入在并行跑测时超时

## 背景

documentLibrary-BLP 执行全量 `npm test` 时，`tests/unit/schema.test.ts` 的 "exported layoutDefinition validation rejects unsafe raw assetRefs" 用例在 vitest 默认 5000ms 超时内无法完成。该用例通过 `await import("../../src/index")` 动态导入完整插件入口（React / antd / @chips/ui 全依赖图），冷转换在并行跑测负载下超过 5s；单独运行该文件可稳定通过（约 3.9s）。该问题与本轮"布局形态骨架"空状态改动无关，属于既有测试基线问题。

## 证据

1. 单独运行 `npx vitest run tests/unit/schema.test.ts`：8/8 通过，用例耗时约 3910ms（紧贴 5000ms 阈值）；
2. 全量 `npm test`：该用例 "Test timed out in 5000ms" 多次复现（实际耗时 5000-9100ms 区间），其余 18 个用例全部通过；
3. 将本轮改动 `git stash` 后运行全量测试：同样失败（17 passed + 1 timed out），证明与本轮改动无关，是既有问题。

## 影响范围

- documentLibrary-BLP 的 `npm test` / `verify` 链路无法全绿；
- 相同模式（用例内 `await import` 完整插件入口）的其他布局插件测试存在同样隐患（冷转换进入用例计时）。

## 复现步骤

1. 在 `Chips-BoxLayoutPlugin/documentLibrary-BLP` 目录执行 `npm test`；
2. 观察 `tests/unit/schema.test.ts` 的 "exported layoutDefinition validation rejects unsafe raw assetRefs" 超时（并行负载下高概率复现）；
3. 单独执行 `npx vitest run tests/unit/schema.test.ts` 则通过。

## 期望行为

- 全量 `npm test` 稳定全绿；
- 建议修复方向（任选其一，需确认口径后执行）：
  - 将该用例改为静态导入 `layoutDefinition`（与 `layout-definition.test.tsx` 一致），消除动态导入冷转换进入用例计时；
  - 或对该用例单独放宽 timeout（如 15000ms）；
  - 或预热/缓存转换产物，避免冷转换计入用例计时。

## 暂行处理

- 本轮"布局形态骨架"任务不修改 `schema.test.ts`（不在任务范围）；任务相关用例 `tests/unit/layout-definition.test.tsx` 11 个用例全绿；
- 全量测试的 1 个失败为既有问题，修复口径等确认后执行。
