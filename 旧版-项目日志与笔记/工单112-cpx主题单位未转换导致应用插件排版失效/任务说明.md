# 工单112-cpx主题单位未转换导致应用插件排版失效

## 背景

用户反馈 `Chips-EcoSettingsPanel` 应用插件界面排版完全乱套。初始排查确认问题不应在设置面板内用临时 `px` 覆盖处理，后续修复已收敛到 Host 主题注入边界。

设置面板是正式 `type: app` 应用插件，壳层按照技术文档使用 `ChipsNavigationSplitView` 承载左侧导航和右侧内容区，页面内部使用 `ChipsStack / ChipsGrid / ChipsSection / ChipsDataGrid` 等组件库正式结构。按生态规范，视觉与布局常量应由主题系统和 token 提供。

## 证据

1. `Chips-EcoSettingsPanel/src/app/styles.css` 中 `.settings-app-shell` 使用：
   - `grid-template-columns: minmax(var(--chips-layout-size-navigation-primary-min, 280px), 300px) ...`
   - `gap: var(--chips-layout-gap-md, 18px)` 等主题 layout token。
2. `ThemePack/Chips-default/tokens/layout.json` 中布局 token 值为生态逻辑单位：
   - `chips.layout.size.navigation-primary-min = "160cpx"`
   - `chips.layout.size.split-secondary-min = "220cpx"`
   - `chips.layout.gap.md = "12cpx"`
3. `ThemePack/Chips-default/dist/theme.css` 中同样保留大量 `cpx` 值，包括 `minmax(..., 160cpx)`、`min-inline-size: 180cpx`、`min-block-size: 32cpx` 等。
4. `Chips-Host/src/preload/plugin-window.ts` 的 `applyThemeVariables()` 当前只执行：
   - `target.style.setProperty("--" + tokenKey.replaceAll(".", "-"), String(tokenValue))`
   - 未看到 `cpx -> px`、容器宽度换算或 CSS 注册单位处理。
5. `Chips-Host/packages/unified-rendering/src/layout-compute.ts` 存在 L9 布局计算使用的 `cpxToPx()`，但当前 app window 的普通 CSS 主题注入链路没有调用该转换。
6. `Chips-EcoSettingsPanel` 的基础验证通过：
   - `npm run typecheck`
   - `npm run build`
   - `npm test -- --run tests/unit/app.test.tsx tests/e2e/basic-flow.test.ts tests/e2e/host-smoke.test.ts`
   说明问题不是 TypeScript 编译、应用入口或基础 Host smoke 失败，而是运行时样式落地缺口。

## 影响范围

- `Chips-EcoSettingsPanel` 设置面板应用插件；
- 所有使用组件库布局原语并依赖主题 layout token 的应用插件；
- `ThemePack/Chips-default` 和 `ThemePack/Chips-theme-default-dark`；
- Host 插件窗口 preload 主题注入链路；
- 组件库布局原语真实浏览器渲染验收；
- 生态 `cpx` 逻辑单位从 L8/L9 到普通 Web CSS 的正式边界。

## 复现步骤

1. 构建或安装 `Chips-EcoSettingsPanel`；
2. 确保 Host 当前主题为默认主题或暗色默认主题；
3. 启动设置面板应用插件；
4. 检查页面排版，重点观察左侧导航栏、命令菜单/工具栏/命令面板行、页面 Section 和组件展示页；
5. 在 DevTools 中查看 `document.documentElement.style`，确认 `--chips-layout-size-navigation-primary-min` 等变量值为 `160cpx`、`12cpx` 这类普通 CSS 不识别的单位；
6. 查看相关元素 computed style，确认 grid/gap/min-size 等声明未按预期生效或被浏览器丢弃。

## 期望行为

- 生态应正式定义 `cpx` 在 app window 普通 CSS 中的落地策略；
- Host Theme Runtime 或 ThemePack 构建产物应把进入浏览器 CSS 的 `cpx` 转为合法 CSS 长度，或提供正式可验证的运行时 CSS 单位支持；
- 组件库布局原语、主题包 CSS、Host preload 注入和应用插件页面应消费同一套单位规则；
- 应新增真实浏览器或等价渲染测试，验证默认主题下注入后的关键布局属性有效。

## 处理结果

已在 Host 主题注入和渲染文档生成边界统一解决：

1. 新增 `Chips-Host/src/shared/theme-css-units.ts`，把进入浏览器普通 CSS 的 `cpx` 按 1024 设计基准转换为 `vw`，例如 `12cpx -> 1.171875vw`、`160cpx -> 15.625vw`。
2. `Chips-Host/src/preload/plugin-window.ts` 在应用插件窗口注入主题 CSS 和 token CSS variables 前执行转换，修复 `Chips-EcoSettingsPanel` 这类应用窗口的布局变量失效问题。
3. `Chips-Host/packages/card-service/src/card-service.ts` 与 `Chips-Host/packages/box-service/src/box-service.ts` 同步使用该转换工具，避免卡片 iframe、基础卡片编辑器、复合卡片和箱子布局文档继续注入 raw `cpx`。
4. 已补充单元测试覆盖转换工具、卡片渲染和箱子渲染的浏览器安全 CSS 输出。
