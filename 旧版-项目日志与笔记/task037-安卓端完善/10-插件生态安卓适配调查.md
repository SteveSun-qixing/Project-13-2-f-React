# 插件生态 Android 适配调查

## 1. Manifest 统计

仅统计正式源目录，不统计 `.chips-host-dev`、服务器安装副本、dist 和测试临时目录：

| 类型 | 数量 | mobile=true | mobile=false |
|---|---:|---:|---:|
| app | 10 | 1 | 9 |
| card | 8 | 0 | 8 |
| layout | 10 | 0 | 10 |
| module | 7 | 1 | 6 |
| 合计 | 35 | 2 | 33 |

声明支持移动端的只有：

- `com.chips.card-viewer`；
- `chips.module.chips.community-uploader`。

## 2. 声明与代码的矛盾

### CardViewer

优点：

- React/Web 入口，适合 WebView；
- mobile preferred surface 为 fullscreen；
- 主要经 SDK 调用 card/box/plugin/resource/module/network/command。

问题：

- `os` 仍只有 darwin/win32/linux，没有 Android 口径；
- 依赖的基础卡片和布局插件全部声明 mobile=false；
- 社区下载依赖 CommunityUploader module；
- 尚无 Android WebView/Bridge 测试。

结论：适合作为首个认证 app，但当前不能视为已支持。

### CommunityUploader

优点：

- 多数文件和网络操作通过 Host route；
- manifest 声明 mobile=true。

问题：

- 源码直接导入 `node:path`、`node:os`、`node:url`；
- 当前 module runtime 依赖 Node 动态 import；
- 仍声明 `os: darwin/win32/linux`；
- 大二进制存在 Buffer/array 跨 Bridge 风险；
- 部分路径模型以绝对路径和临时目录为中心。

结论：当前 `mobile: true` 与实现不一致，必须在认证前修正实现或撤销声明。

## 3. 五类插件适配要求

### App 插件

- 入口 HTML 在受控 origin 加载；
- 不依赖 Electron/Node/绝对路径；
- 使用 `surface.*`，不依赖多桌面窗口；
- 通过 Android back stack 正确退出；
- 处理 pause/resume/session restore；
- 通过 Bridge capability 做功能判断。

本任务不要求重新设计响应式布局，但必须保证页面不会阻止 Host 启动、Bridge 握手、文档打开和返回导航。

### Card 插件

- `.mjs` 描述符需要可移植加载；
- render/edit 文档在 Android WebView 支持；
- iframe 消息、高度、触摸、媒体和资源协议通过；
- 禁止 Node import；
- 每种卡片有移动 contract/E2E 测试后才能设 true。

### Layout 插件

- 与 card 类似，需要可移植模块加载；
- 手势、滚动嵌套和 iframe 生命周期需验证；
- `box.read` 在 Android document handle 上工作；
- 大量卡片时内存/虚拟化受控。

### Module 插件

这是最大技术风险。当前 contract 写 `runtime: worker`，实现却在 Host 进程通过 Node import 加载模块对象。Android 必须冻结：

- worker 的真实隔离边界；
- 允许的 JS/标准库；
- Host capability 注入；
- CPU/内存/时间/并发配额；
- 进程死亡与 job 恢复；
- 禁止 native payload；
- 签名和来源治理。

### Theme 插件

本次正式源目录未发现 `ThemePack`，但 Host 内置插件链路可能从其他工作区源复制主题。Android 发布前必须重新盘点真实内置主题来源，验证 token、CSS、字体和资源 URL，不得仅依据当前目录缺失作结论。

## 4. 插件移动认证状态

建议 manifest 除布尔值外增加认证元数据，但要先走公共契约变更：

```yaml
runtime:
  targets:
    mobile:
      supported: true
      certified:
        android:
          minApi: 26
          hostContract: "1"
          verifiedAt: "2026-..."
```

布尔值表示作者声明，认证字段表示生态 CI/设备测试证明。两者不能混为一谈。

## 5. 推荐认证顺序

1. Host 内置诊断 app；
2. CardViewer；
3. richtext/image/score 基础卡片；
4. grid/list 布局；
5. CommunityUploader；
6. music/video/photo viewer 与媒体卡片；
7. BookReader；
8. EditingEngine/RichTextEditor；
9. EcoSettingsPanel/CommunityClient；
10. 其余 module/layout/card。

## 6. 插件门禁

每个 `mobile: true` 必须通过：

- manifest/CPK 校验；
- 禁止 Node/Electron import 静态扫描；
- Android WebView load/handshake；
- Bridge 权限正反测试；
- pause/resume/process restore；
- 核心业务 E2E；
- 内存、崩溃、ANR、日志门禁；
- 至少最低 API、当前 API、目标 API 三档设备验证。

未通过时保持 `mobile: false`，Host 应拒绝启动并给出 `PLUGIN_TARGET_UNSUPPORTED`。
