# Android 测试策略与设备矩阵

## 1. 测试目标

测试不只证明“页面能打开”，还要证明 Host 的平台抽象、权限、插件隔离、文档事务、生命周期恢复和发布产物可靠。

## 2. 测试分层

### L1 纯逻辑单元测试

- Kernel router/registry/event/lifecycle；
- manifest/permission/schema；
- resource locator；
- URI/path 正规化；
- capability/fallback；
- session checkpoint/restore；
- CPK 安全校验。

### L2 PAL 契约测试

同一套契约测试运行于 Desktop、Headless、Android fake 和 Android instrumentation，验证返回形状、错误码、capability snapshot 和 unsupported 语义。

### L3 Bridge 契约与安全测试

- invoke/response/event/once/unsubscribe；
- scoped caller；
- 权限拒绝；
- token 重放；
- origin/frame 隔离；
- 限流、超时、取消、超大 payload；
- navigation/surface destroy 撤销。

### L4 Android instrumentation

- Activity lifecycle；
- SAF picker（可用 test provider）；
- WebView resource loader；
- intent/deep link/share；
- notification/clipboard/permission；
- process recreation；
- Keystore/credential。

### L5 插件 E2E

- 安装/启用/启动/禁用/替换/回滚；
- CardViewer 打开 card/box；
- card/layout iframe 渲染；
- CommunityUploader 上传/下载；
- 主题/i18n 注入；
- Android back、旋转、后台、进程死亡。

### L6 发布验收

- signed APK/AAB；
- clean install/upgrade；
- Play pre-launch report；
- 崩溃、ANR、安全、包体、性能；
- 数据清理和恢复。

## 3. 必测设备矩阵

| 维度 | 最低要求 |
|---|---|
| API | minSdk、一个中间版本、target/current 版本 |
| WebView | 当前稳定版 + 较旧可支持版 |
| 架构 | arm64-v8a；如支持 x86_64 则加模拟器 |
| 设备 | Pixel/原生、Samsung、小米/OPPO/vivo 至少一种国内 ROM |
| 内存 | 低内存设备、主流设备 |
| 网络 | 离线、弱网、切网、代理/证书异常 |
| 存储 | internal、Downloads、云盘 provider、撤销权限 |
| 屏幕 | 手机竖屏/横屏；不做响应式设计验收，但验证 Host surface 稳定 |

## 4. 本机起始矩阵

当前可立即使用 `Medium_Phone_API_36.1` 模拟器做目标 API 冒烟。仍需补：

- 最低 API AVD；
- 一台真机；
- 一台厂商 ROM；
- 测试 document provider；
- CI emulator 配置。

## 5. 金链路用例

1. 安装 debug APK；
2. 首次启动完成 Host 初始化；
3. 查看 platform/capability；
4. 安装/启用签名测试 CPK；
5. SAF 打开 `.card`；
6. CardViewer + richtext/image 卡片渲染；
7. 返回/重新进入；
8. 旋转；
9. 切后台并通过测试手段杀进程；
10. 恢复 scene/document；
11. 分享导出文件；
12. 升级 APK 后重复打开；
13. 卸载验证数据清理。

## 6. 负向和安全用例

- ZIP Slip、重复 entry、压缩炸弹；
- manifest target=false 强行启动；
- CPK 签名/哈希篡改；
- 插件请求未授权 action；
- 远程网页尝试调用 Bridge；
- iframe 冒充顶层 app；
- content URI 权限撤销；
- provider 返回错误长度/无 displayName；
- 大 card/box 导致内存压力；
- Bridge 洪泛；
- 恶意导航、下载和弹窗；
- release WebView debugging/cleartext 检查。

## 7. 性能预算建议

预算需在原型阶段基于设备数据冻结，至少覆盖：

- 冷启动到诊断 surface；
- 热启动；
- Bridge P50/P95/P99；
- 首卡可见时间；
- 100 张卡箱子打开；
- 100MB card/box 导入峰值内存；
- 后台 30 分钟功耗；
- APK/AAB 下载和安装体积；
- WebView 数量上限和回收策略。

不应在没有测量前写死“完美”数值。M1 原型采基线，M2 冻结预算，之后作为 CI/设备门禁。

## 8. 通过条件

- 所有 P0/P1 金链路全绿；
- 零已知 crash/ANR/数据丢失/越权；
- 设备矩阵中无阻塞差异；
- Android 与 Desktop 公共契约测试一致；
- 每个 `mobile: true` 插件都有对应设备认证报告；
- release 构建通过安全、依赖、许可证和政策检查。
