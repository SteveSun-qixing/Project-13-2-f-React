# 构建、签名、安装与发布链路

## 1. 当前缺失

Host 当前只有 TypeScript build、Node CLI 和 macOS installer。没有：

- Android application module；
- Gradle wrapper；
- AndroidManifest；
- debug/release product flavors；
- APK/AAB task；
- signing config；
- ProGuard/R8；
- Android CI；
- release artifact manifest/SBOM；
- Play Console 配置。

## 2. 工程建议

Android 工程应归属于 `Chips-Host`，因为 Host 是唯一安装包。建议结构由 ADR 最终确认：

```text
Chips-Host/
├── android/
│   ├── gradlew / gradle/
│   ├── settings.gradle.kts
│   ├── build.gradle.kts
│   └── app/
│       ├── build.gradle.kts
│       └── src/{main,debug,androidTest,test}/
├── packages/portable-*/
└── scripts/android-*.mjs
```

禁止依赖开发机全局 Gradle；使用 wrapper 固定版本。JDK、AGP、Kotlin、compileSdk、targetSdk、minSdk 必须依据实施时官方兼容矩阵统一冻结。

## 3. 构建变体

| 变体 | 用途 | 插件来源 | WebView 调试 |
|---|---|---|---|
| debug | 本地开发/ADB | 内置 + 本地明确侧载 | 开启 |
| staging | 集成/设备实验室 | 签名测试源 | 受控 |
| release | 生产 | 内置 + 受信发布源 | 关闭 |

debug 的便利能力不得进入 release，例如任意目录插件加载、忽略签名、任意证书、开放 Bridge 调试端点。

## 4. APK/AAB 与签名

- debug APK 用于本地 `adb install`；
- staging APK 用于设备测试；
- release AAB 用于 Google Play；
- release APK 仅用于明确的非 Play 分发场景；
- 签名密钥不得入库；
- CI 使用受控 secret/密钥服务；
- 产物记录 versionName/versionCode、commit、依赖锁、hash、SBOM 和签名指纹。

## 5. 内置插件

首发 APK 应捆绑最小可启动插件集，避免首次启动依赖网络：

- 诊断/恢复 surface；
- 默认主题和字体；
- CardViewer；
- 首批已认证 card/layout；
- 必要的基础模块。

内置 CPK 也必须经过同一 manifest、hash、签名/来源和安装事务校验，不能因为打包在 APK 内就绕过门禁。

## 6. 插件更新与 Play 政策

- 禁止下载 dex/JAR/.so；
- 动态内容仅限受控 Web/解释型插件；
- release 插件源必须有发布者信任链和撤销机制；
- 插件市场内容纳入应用内容政策、年龄分级、举报和审核；
- Host 更新与插件更新分离，但公共 contract 不匹配时必须阻止激活；
- 建议首个公开版本先限制为官方签名插件，第三方市场在安全治理完成后开放。

## 7. CI 流水线

```text
checkout
 -> lockfile/依赖完整性
 -> TypeScript lint/typecheck/test
 -> portable-core contract tests
 -> Android unit/lint
 -> assembleDebug
 -> emulator instrumentation/E2E
 -> bundleRelease
 -> dependency/license/security scan
 -> SBOM + artifact manifest
 -> signing
 -> staged distribution
```

## 8. 本机环境行动项

当前已有 ADB、SDK、build-tools 和 AVD，可复用。需要：

- 安装/固定项目要求的 JDK，而不是默认使用 Java 23；
- 通过 Gradle wrapper 固定工具链；
- 启动 `Medium_Phone_API_36.1` 验证当前 API；
- 另建最低 API 和无 Play Services 镜像；
- 接入至少一台真实 Android 手机；
- 配置 USB/Wi-Fi debugging、logcat 和 WebView inspect 的 debug 流程。

## 9. 首个可安装里程碑

只有满足以下条件才叫“可安装 Host 骨架”：

- `assembleDebug` 成功；
- `adb install -r` 成功；
- launcher 启动不崩溃；
- Host 初始化状态可见；
- 内置诊断 surface 通过 Bridge 获取 platform/capabilities；
- 后台/前台切换和旋转不丢失基本状态；
- logcat 无 fatal/ANR；
- 测试 APK 可卸载并清理预期数据。
