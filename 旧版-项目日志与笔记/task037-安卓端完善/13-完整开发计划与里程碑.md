# 完整开发计划与里程碑

> **选型确认后更新（2026-08-12）**：本文保留为原 Android 专项的概览。全生态正式方案已确认为 React/Web 插件 + Rust Host Core + Electron Desktop Shell + Tauri 2 Mobile Shell + Kotlin/Swift PAL。可直接执行的完整任务以第 18–22 章为准，它们取代本文中“Host Core 承载方式待选”和 Android 单端排期口径。

## 1. 计划原则

- 先冻结架构和契约，再编码；
- 先让 Host 自身可移植，再建立 Android 壳；
- 先打通一条 CardViewer 金链路，再扩展插件矩阵；
- 每个阶段都交付代码、测试、文档和可复核产物；
- 不用临时 Bridge、假 PAL 或远程网页壳跨越阶段；
- 下列工期只在人员和依赖明确后估算，本报告以退出条件管理进度。

## 2. M0 决策冻结与基线清理

任务：

- 建立 Android 架构 ADR；
- 选择 Host Core 承载方式；
- 固定 minSdk/targetSdk/JDK/AGP/Kotlin；
- 冻结 Android capability matrix；
- 冻结 ResourceLocator/DocumentHandle；
- 冻结 module executor；
- 建立 Node/Electron 直连清单；
- 解决工单157及关联工单边界。

退出条件：ADR 全部批准，依赖评估完成，公共契约变更有评审结论。

## 3. M1 Host Core 可移植化

任务：

- 拆出 storage/archive/crypto/log/plugin/module/resource/network/credential ports；
- HostCore 移除 `fs/path/process.cwd()/Electron` 直连；
- card/box/zip/packer 改走 ports；
- 服务注册中的离屏渲染下沉 PAL；
- Node Desktop/Headless adapter 适配新 ports；
- 建立 portable contract tests。

退出条件：Desktop/Headless 回归全绿；portable core 在无 Node globals 环境可构建和跑核心测试。

## 4. M2 Android 工程与 MobileHostShell

任务：

- 创建 Gradle/Kotlin Android application；
- 实现 Application、MainActivity、Navigation、SurfaceRegistry；
- 实现初始化、日志、崩溃捕获、状态恢复骨架；
- 捆绑诊断插件/页面；
- 建立 debug/staging/release 变体；
- CI 构建 debug APK。

退出条件：debug APK 可安装、启动、旋转、切前后台；诊断 surface 可显示 Host 初始化状态。

## 5. M3 Android PAL 核心分面

任务：

- environment/capability；
- storage/selection/transfer/association；
- surface/device/systemUi/background；
- network/credential/crypto/resource；
- 明确 tray/shortcut/window 等 unsupported；
- Android PAL contract tests。

退出条件：所有首发 capability 有真实实现或正式 unsupported；无 stub success。

## 6. M4 WebView Resource 与 Bridge

任务：

- WebViewAssetLoader/私有 origin；
- 插件资源 resolver；
- WebMessage transport；
- `window.chips.*` bootstrap；
- session/origin/permission/rate binding；
- resource/blob handle；
- WebView security settings；
- Bridge instrumentation/security tests。

退出条件：诊断 app 在 WebView 内通过 SDK 调用 Kernel；远程页面和越权请求被稳定拒绝。

## 7. M5 插件安装与执行模型

任务：

- CPK staging/校验/签名/hash/原子激活/回滚；
- Android 禁止 native executable payload；
- plugin registry 和版本迁移；
- card/layout descriptor executor；
- module worker/executor 正式实现；
- 进程死亡后的 module job 恢复；
- 插件来源与 release 策略。

退出条件：五类插件的装载规则有实现和测试；至少一个测试 module 可隔离执行。

## 8. M6 CardViewer 金链路

任务：

- 认证 CardViewer；
- 认证 richtext/image/score card；
- 认证 grid/list layout；
- SAF 打开 card/box；
- 主题、字体、资源、iframe 协议；
- 返回、旋转、进程恢复、分享导出。

退出条件：第 12 章金链路在模拟器和至少一台真机全绿，无数据丢失和越权。

## 9. M7 服务完整性

任务：

- config/i18n/theme/log；
- notification/clipboard/external open；
- network/credential；
- HTML/PDF/image/video frame 能力；
- command/surface/deep link；
- background jobs；
- EcoSettingsPanel 移动治理能力。

退出条件：公共 Host API 按 Android capability matrix 全部覆盖或正式拒绝。

## 10. M8 插件生态认证

任务：

- CommunityUploader 去 Node 化并认证；
- 媒体播放器/卡片；
- BookReader；
- EditingEngine/RichTextEditor；
- CommunityClient/EcoSettingsPanel；
- 其余 card/layout/module；
- 更新脚手架和 `chipsdev-r validate` 移动扫描。

退出条件：所有设为 `mobile: true` 的插件都有认证；未认证插件保持 false 且 Host 拒绝启动。

## 11. M9 生产发布

任务：

- 性能、内存、功耗、包体优化；
- 厂商设备矩阵；
- 安全审计和渗透测试；
- Play 政策、隐私、数据安全、内容治理；
- AAB、签名、SBOM、供应链；
- staged rollout、崩溃/ANR 监控、回滚。

退出条件：第 15 章最终验收全部通过，发布负责人签字。

## 12. 每阶段固定交付物

- 设计/ADR；
- 实现代码；
- 单元/契约/集成/E2E 测试；
- 迁移和回滚说明；
- capability 与 API 文档；
- 验证命令和结果；
- 风险更新；
- 相关工单状态；
- 可复核构建产物。

## 13. 当前最近一步

应先执行 M0，不应直接创建“能显示网页”的临时 APK。M0 的第一个技术 spike 只用于比较 Host Core 承载候选，产物不得冒充正式实现；选型确认后，spike 应归档，正式代码按冻结架构重建或演进。
