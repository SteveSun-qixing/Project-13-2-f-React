# 工单171：SDK mock-host 格式校验缺口与文档缺失

## 工单信息

- 工单编号：工单171
- 日期：2026-09-03
- 发现阶段：办公文档拆分任务静态代码审查
- 问题类型：SDK mock 工具链缺陷 / 文档漂移
- 状态：待处理

## 背景

Chips-SDK 的 mock-host 提供了 office.document.* 的 mock 实现，用于插件的单元测试。但 mock 实现与 Host 真实行为存在多处不一致，且缺少文档说明，影响开发者的测试正确性。

## 发现1：mockOfficeCreate 不校验 format 参数（中）

### 位置
- `Chips-SDK/src/testing/mock-host.ts` 第 872 行

### 描述
```typescript
const format = String(record.format ?? "binary");
```
mock 直接用 `String()` 把任何值转为字符串后使用，不校验是否为有效 format。Host `normalizeFormat` 在 format 非法时会抛出 `INVALID_ARGUMENT` 错误。mock 的宽松行为会导致测试无法发现插件传入非法 format 的问题。

### 建议修复
在 mock 中对 format 进行校验，与 Host 行为一致：
```typescript
const VALID_FORMATS = new Set(['docx', 'pptx', 'xlsx', 'pdf', 'binary']);
const format = VALID_FORMATS.has(record.format) ? record.format : 'binary';
```
或复用 Host 的 `normalizeFormat`（如果可导入）。

## 发现2：mockOfficeOpen 返回空 bytes 无警告（中）

### 位置
- `Chips-SDK/src/testing/mock-host.ts` 第 888 行

### 描述
```typescript
const bytes = new Uint8Array();
```
mock 的 open 总是返回空 bytes，而 Host 的 open 会从真实文件系统读取文件内容。这导致：
1. 测试无法验证实际文件内容处理
2. 开发者误以为 mock 返回了文件内容
3. `parseDocxBytes` 会因空 bytes 抛出"不是有效 ZIP"错误，但测试不会发现这个问题

### 建议修复
在 mock-host 头部文档注释中明确说明 mock office 的限制：
```typescript
/**
 * Mock Office Document Service
 * 注意：mockOfficeOpen 总是返回空 bytes（无虚拟文件系统）。
 * 如需测试真实文件内容，请在测试中自行注入：
 * host.state.officeSeed[filePath] = actualBytes;
 */
```

## 发现3：mockOfficeWrite 没有 offset 语义（中）

### 位置
- `Chips-SDK/src/testing/mock-host.ts` 第 899-903 行

### 描述
mock 的 write 直接替换整个 bytes，忽略 offset 参数。Host 的 write 在有 offset 时执行区间写入（保留旧文件头部和尾部）。这导致测试无法验证区间写入场景。

### 建议修复
在 mock 中实现与 Host 一致的 offset 写入语义：
```typescript
function mockOfficeWrite(payload: unknown, host: MockChipsHost): { document: Record<string, unknown> } {
  const session = mockOfficeRequire(payload, host);
  const newBytes = mockOfficeBytes(toRecord(payload).bytes);
  const offset = toRecord(payload).offset;
  
  if (offset === undefined) {
    session.bytes = newBytes;
  } else {
    const combined = new Uint8Array(Math.max(session.bytes.length, offset + newBytes.length));
    combined.set(session.bytes);
    combined.set(newBytes, offset);
    session.bytes = combined;
  }
  // ... 更新 descriptor
}
```

## 发现4：mockOfficePersist 没有实际写文件（中）

### 位置
- `Chips-SDK/src/testing/mock-host.ts` 第 911-916 行

### 描述
mock 的 persist 只是更新 descriptor 的 filePath/fileName 和 status，没有实际写入文件系统。这导致测试无法验证 persist 后的文件内容。

### 建议修复
在 mock 中引入虚拟文件系统：
```typescript
// 在 MockChipsHostState 中添加可选字段
interface MockChipsHostState {
  // ...existing fields
  officeFiles?: Map<string, Uint8Array>;
}

// mockOfficePersist 中实现实际写入
function mockOfficePersist(payload: unknown, host: MockChipsHost): { document: Record<string, unknown> } {
  const session = mockOfficeRequire(payload, host);
  const filePath = String(toRecord(payload).filePath ?? session.document.filePath ?? "");
  
  if (host.state.officeFiles) {
    host.state.officeFiles.set(filePath, session.bytes);
  }
  // ...
}
```

## 影响范围

## 复现步骤

1. 在插件测试中使用 `client.office.create({format: "invalid"})`
2. 观察 mock 接受但 Host 拒绝
3. 在插件测试中使用 `client.office.write(sessionId, bytes, {offset: 100})`
4. 观察 mock 完全替换 bytes 而非区间写入

## 期望行为

1. mock-host 的 office API 行为与 Host 一致
2. mock 明确标注其限制和特殊行为
3. 开发者可以自行注入虚拟文件内容进行测试
