# 04-箱子文档域能力分析

## 1. 现状：箱子文档域能力分布

### 1.1 Host 已提供（打包/检查/渲染/布局）

Host `box` 域已非常完整地覆盖**查看与布局**链路（`box-service.ts` 2916 行）：

- 打包解包：`box.pack` / `box.unpack`
- 检查读取：`box.inspect` / `box.validate` / `box.readMetadata` / `box.renderCover`
- 布局：`listLayoutDescriptors` / `readLayoutDescriptor` / `normalizeLayoutConfig` / `validateLayoutConfig` / `getLayoutInitialQuery` / `renderLayoutFrame` / `renderLayoutEditor`
- 查看会话：`openView` / `listEntries` / `readEntryDetail` / `renderEntryCover` / `renderEntryDocument` / `openEntry` / `resolveEntryResource` / `readBoxAsset` / `prefetchEntries` / `closeView`

**关键缺口：Host box 域没有「编辑会话」——没有任何动作支持在会话内增删条目、调整顺序、改写布局配置、编辑封面并自动保存。**

### 1.2 编辑引擎本地自实现

| 能力 | 位置 | 说明 |
|---|---|---|
| 箱子编辑会话（open/save/close，会话工作目录 `.chips-editing-engine/box-sessions/`） | `src/services/box-document-service.ts`（1135 行） | 解包到工作目录，改完重打包写回原文件 |

## 2. 问题与重复证据

1. **序列化逻辑双份**：编辑引擎 `box-document-service.ts` 的 `serialize*` 系列与 Host `box-service.ts` 内部解析模型（inspect/readMetadata 的读取端）成对出现，但写入端（snake_case 字段回写）只在编辑引擎存在；
2. **条目排序键语义**：`layoutHints.sortKey` 的维护（增删/拖拽后重建）在编辑引擎本地完成，与 `box.structure.yaml` 的正式格式强相关——该语义属于箱子文件格式契约（`生态共用技术文档/协议与契约/02-箱子业务.md`），应由 Host 提供一致性保证；
3. **会话工作目录管理**：`.chips-editing-engine/box-sessions/` 目录与「临时工作区」生命周期属于系统级资源管理，编辑引擎按应用路径硬编码，其他应用无法复用；
4. **条目摘要生成**：`deriveEntryTitle/createEmptySnapshot` 从 URL 推导标题/封面模式，查看器与社区客户端也有类似需求（读 box.readEntryDetail），但编辑场景需要「未读文件时生成摘要」，目前只在编辑引擎有。

## 3. 上移方案（建议）

### 3.1 目标形态：Host box 服务域扩展「文档编辑会话」能力

| 建议动作 | 职责 | 对应编辑引擎代码 |
|---|---|---|
| `box.session.open` | 解包到托管会话工作目录（Host 管理，不再由应用指定），返回 sessionId | `openBox` |
| `box.session.get` | 会话快照（metadata/content/entries/assets/coverHtml/dirty） | getSession |
| `box.session.addEntry` | 添加条目（支持 URL 与文件导入） | `addEntry/importDocumentFiles` |
| `box.session.updateEntry` | 更新条目（url/snapshot/layoutHints） | `updateEntry` |
| `box.session.moveEntry` | 移动条目（方向或目标索引），重建 sortKey | `moveEntry/moveEntryToIndex` |
| `box.session.removeEntry` | 删除条目 | `removeEntry` |
| `box.session.addEmbeddedCard` | 内嵌卡片（复制 .card + 摘要）——**接口开放**（用户决策：架构上允许，一般默认链接引用；官方编辑引擎自身不提供内嵌操作入口，但接口对第三方开发者开放） | `addEmbeddedCard` |
| `box.session.updateLayoutConfig` | 改写布局配置 | `updateLayoutConfig` |
| `box.session.importBoxAsset` / `deleteBoxAsset` | 资源管理 | 同名方法 |
| `box.session.updateCover` | 封面编辑 | `updateCover` |
| `box.session.persist` | 序列化落盘 + 重打包写回原文件 + inspect 校验 | `saveBox` |
| `box.session.undo` / `redo` / `history` | **文档历史闭环**（与卡片域共用历史模块） | 复用历史模块 |
| `box.session.close` | 清理会话工作目录 | `closeBox` |
| `box.create` / `box.rename` | 新建/重命名（Host 完成解包改写重打包） | `createBoxFile/renameBoxFile` |

设计要点：

- **会话工作目录由 Host 分配与回收**（可复用 Host 临时目录管理，替代 `.chips-editing-engine/box-sessions/` 应用私有路径）；
- **自动保存防抖与串行化进 Host**，应用订阅 `box.session.*` 事件即可；
- **序列化与解析收敛到 box-service 单一实现**，编辑写入与 Host 读取共用同一模型，杜绝双份口径漂移（当前已存在工单 127/128 系列反映解析模型漂移风险）；
- 条目摘要生成（未读文件推导）作为 `box.session.addEntry` 的服务端行为，返回结构化摘要，应用不再拼 URL 语义。

### 3.2 收益

- 消除箱子序列化双份实现与排序键语义漂移风险；
- 社区服务器（HeadlessHostShell 集成）未来可直接调用 `box.session.*` 实现服务端箱子编辑；
- 查看器与社区客户端可复用「条目摘要生成」「内嵌卡片」能力。

### 3.3 边界与风险

- 会话工作目录与 `box.unpack` 的现有语义需明确区分（unpack 是显式解包到指定目录，session.open 是托管会话），避免动作含义混叠；
- 自动保存并发写回原文件时需串行化（编辑引擎现有 pendingAutoSaves 逻辑可作输入基线）；
- 内嵌卡片会复制实体进箱子——与「箱子不直接保存被引用卡片实体」的设计存在张力（见 `生态设计原稿/03-层次结构.md` 与工单 128「箱子格式不支持内嵌卡片」），上移前需先收口内嵌卡片在格式协议中的正式语义。
