# 03-卡片文档域能力分析

## 1. 现状：卡片文档域能力分布

### 1.1 Host 已提供（打包态/渲染态）

| 动作 | 用途 | 权限 |
|---|---|---|
| `card.pack` | 解包目录 → 标准 `.card` 压缩产物 | card.write |
| `card.unpack` | `.card` → 解包目录 | card.read |
| `card.readMetadata` | 读取 `.card` 元数据 | card.read |
| `card.readInfo` | status/metadata/cover 信息 | card.read |
| `card.parse` | 解析出 ast | card.read |
| `card.validate` | 结构校验 | card.read |
| `card.render` / `card.renderCover` / `card.renderEditor` | 渲染文档/封面/编辑器 iframe | card.read/card.write |
| `card.resolveDocumentPath` / `card.resolveResourceUrl` | 受控 URL 解析 | card.read |
| `card.open` | 卡片打开路由（card-window） | card.read |

对应实现：`Chips-Host/packages/card-service`（2717 行）、`card-packer`（342 行）、`card-info-service`、`card-open-service`。

**关键缺口：Host 没有「解包态目录的读写编辑」能力。** 打开一个 `.card` 后，编辑引擎在解包目录上执行的所有操作（读文档、改文档、写文档、资源生命周期）都不在 Host 契约中。

### 1.2 编辑引擎本地自实现（本次上移的核心对象）

| 能力 | 位置 | 说明 |
|---|---|---|
| 卡片内存模型与选中态 | `src/core/card-service.ts`（1155 行） | openedCards Map、selectedCardId/selectedBasicCardId |
| 解包目录文档读取（metadata/structure/cover/content 加载与归一） | `openCard()` | yaml.parse + normalizeBasecardConfig |
| 文档序列化与持久化 | `persistCard()` | 重建 `.card/metadata.yaml`、`.card/structure.yaml`、`.card/cover.html`、`content/{id}.yaml`；清理孤儿 content 文件 |
| 资源清单重建 | `buildResourceManifest()` | 扫描卡片根目录（排除 `.card/`、`content/`），产出 manifest.resources（path/size/type） |
| 封面资源 reconcile | `reconcileCoverResources()` | 正则收集 cover.html 引用（src/href/poster/data-chips-cover-image-source/url()），删除未引用 `.card/cardcover/` 资源，剪枝空目录 |
| 待导入/待删除资源队列 | `updateBasicCard()` + `finalizeCardResources()` | 引用关系来自描述符 `collectResourcePaths(config)` |
| 防抖自动保存循环 | `runPersistLoop()` | revision 计数、并发合并、失败保留 dirty |
| 基础卡片增删/排序 | `addBasicCard/removeBasicCard/moveBasicCard` | 含资源回收登记 |
| 卡片目录骨架初始化 | `src/core/card-initializer.ts`（96 行） | 新建卡片五件套文档 |
| 默认封面/比例规范化 | `src/utils/card-cover.ts`（147 行） | createDefaultCoverHtml、normalizeCoverRatio（默认 3:4） |

## 2. 重复实现证据（卡片域）

1. **MIME 猜测**：编辑引擎 `card-service.ts guessMimeType` 与 Host `card-packer.ts guessMimeType` 逻辑几乎一致（png/jpg/gif/webp/svg/bmp/avif/mp4/webm/mp3/wav/json/pdf/txt）；
2. **相对资源路径规范化**：编辑引擎 `card-service.ts normalizeResourcePath` 与 Host `card-service.ts normalizeRelativeResourcePath`、SDK `card.ts normalizeRelativeResourcePath` 逻辑一致；
3. **默认封面 HTML**：Host 渲染链路（renderCover）与编辑引擎各自有默认封面逻辑，未共用同一生成器；
4. **ID 生成**：编辑引擎 `generateId62` vs Host `createId`。

## 3. 上移方案（建议）

### 3.1 目标形态：Host card 服务域扩展「文档编辑会话」能力

在 `Chips-Host/packages/card-service` 内新增一组动作（建议命名）：

| 建议动作 | 职责 | 对应编辑引擎代码 |
|---|---|---|
| `card.session.open` | 打开解包目录，加载并归一文档模型，返回 sessionId | `CardService.openCard` + registry 归一 |
| `card.session.get` | 读取会话快照（metadata/structure/cover/basicCards） | getState |
| `card.session.updateBasicCard` | 更新基础卡片配置 + 资源操作（导入/删除登记） | `updateBasicCard` |
| `card.session.updateMetadata` | 更新元数据（name/description/tags/theme/coverRatio） | `updateCardMetadata` |
| `card.session.updateCover` | 更新封面 HTML/比例/资源 | `updateCardCover` |
| `card.session.add/remove/moveBasicCard` | 基础卡片结构编辑 | 同名方法 |
| `card.session.persist` | 序列化落盘 + 资源清单重建 + 封面 reconcile + 孤儿清理 | `persistCard` 全流程 |
| `card.session.undo` / `redo` / `history` | **文档历史闭环**（undo/redo 作为会话公共语义，合并窗口/上限/跳转以编辑引擎 command-manager 为基线） | `command-manager.ts`（291 行，迁移后删除本地实现） |
| `card.session.close` | 释放会话 | `closeCard` |
| `card.init` | 新建卡片骨架（解包目录） | `card-initializer.ts` |

设计要点：

- 会话状态（dirty/revision/自动保存队列）留在 **Host 主进程**，自动保存防抖循环由 Host 管理，应用只需订阅 `card.session.dirty/persisted` 事件（复用内核事件总线）；
- 基础卡片配置的归一/校验（normalize/validateConfig）依赖**基础卡片插件的描述符**——Host 已持有插件运行时与已安装插件入口，天然具备该条件；编辑引擎 registry 中的归一逻辑应作为 Host 能力而非应用逻辑；
- 资源生命周期（pendingResourceImports/Deletions、collectResourcePaths 引用收集、封面 reconcile）全部进 Host，应用不再接触磁盘资源细节；
- 保留 `card.pack/unpack` 不动，编辑会话工作在解包目录语义上，与打包动作天然衔接。

### 3.2 收益

- 查看器/社区客户端/第三方工具可消费同一套编辑语义（如社区「在线编辑」直接复用）；
- 消除 MIME/路径规范化/默认封面/ID 的多处重复；
- 编辑引擎 card-service 从 1155 行收缩为纯会话调用层；
- 未来多端（移动端）编辑产品直接复用 Host 会话服务，不必移植编辑引擎的本地实现。

### 3.3 边界与风险

- 解包目录的路径安全（防 `..` 逃逸）必须由 Host 统一把关（编辑引擎现有 normalizeResourcePath 可作输入基线）；
- 会话与渲染会话（render session）需定义生命周期关系，避免应用关闭窗口后残留会话；
- 自动保存的失败语义（保留 dirty + 错误事件）需在契约中冻结，与编辑引擎当前行为对齐。
