# 06-封面与资源加工能力分析

## 1. 现状

封面能力横跨「卡片封面」与「箱子封面」两条链路（`.card/cover.html` 与 `.box/cover.html`），分为**运行时展示**与**编辑加工**两部分：

### 1.1 运行时展示（已公共化，形态正确）

- Host `card.renderCover` / `box.renderCover` 返回受控 `coverUrl`；
- SDK `card.coverFrame.render` / `box.renderCover` + `EmbeddedDocumentFrame` 承载；
- 编辑引擎 CardWindow/BoxWindow 均已按正式链路使用；
- 封面运行时与主题、多语言解耦（`生态设计原稿/14-编辑引擎设计.md`）。

### 1.2 编辑加工（编辑引擎本地自实现，约 2700 行）

| 能力 | 位置 | 规模 | 说明 |
|---|---|---|---|
| 默认封面 HTML 生成 | `src/utils/card-cover.ts` `createDefaultCoverHtml` | 147 行 | 中性渐变 + 居中名称；卡片与箱子共用 |
| 图片封面 HTML 生成 | `createImageCoverHtml` | 同上 | object-fit + `data-chips-cover-image-source` 标记 |
| 封面比例规范化 | `normalizeCoverRatio`（默认 3:4，九种预设 1:1、1:1.414、2:3、3:4、1:1.618、16:9、2:1、9:19.5、1.58:1） | 同上 | 容忍 `/` 与 `:` 混写 |
| 封面编辑面板 | `CardSettings/panels/CoverPanel.tsx` | 604 行 | 左预览 + 右编辑；比例/方向/图片/HTML 双模式；草稿 diff |
| 画布裁剪弹窗 | `CoverCropDialog.tsx` + `cover-crop-layout.ts` | 501 行 | contain 几何、比例锁定框、四角锚点缩放、Pointer Capture、canvas.drawImage → PNG blob |
| 封面制作器 | `CoverMaker/*` | 约 620 行 | image/html/zip 三模式（模板模式与 8 套模板已于 2026-08-11 移除并归档） |
| 封面资源写入语义 | `card-service.reconcileCoverResources`、`box-document-service.updateCover` | 分属两域 | 引用收集与孤儿清理 |

## 2. 问题与重复证据

1. **比例预设双处定义**：`card-cover.ts` 的九种预设与 `生态设计原稿/14-编辑引擎设计.md` 的约定一致，但 Host/SDK 侧 `cover_ratio` 字段只透传字符串，**没有规范化校验**——不同软件写 `3:4` 或 `3/4` 都会落盘，语义由各应用各自兜底；
2. **默认封面生成无公共实现**：Host `renderCover` 在 cover.html 缺失时的兜底与编辑引擎 `createDefaultCoverHtml` 不是同一实现，未来其他软件（如查看器导出封面）会再次重复；
3. **图片封面引用标记（data-chips-cover-image-source）** 只在编辑引擎内部被识别（`extractGeneratedImageSource`），属于封面文件格式的可契约化语义，当前未进共享文档；
4. **裁剪画布能力**：纯前端能力，若提取为共享组件，封面编辑器、头像裁剪等场景可复用；
5. **封面资源写入逻辑分裂**：卡片域（reconcileCoverResources）与箱子域（updateCover）各自实现一套「写资源 + 清理旧资源」逻辑。

## 3. 上移方案（已按用户 2026-08-11 决策定案）

> 决策：封面**能力**（无界面部分）归属**共享功能模块**（模块插件，经 `module.invoke` 消费）；封面 **UI**（编辑面板、裁剪弹窗、制作器）**不迁移**，保留在编辑引擎页面域。

### 3.1 共享模块：封面无界面能力（建议 `chips.module.cover`）

| 能力 | 说明 |
|---|---|
| `cover.createDefaultHtml(title)` | 默认封面 HTML（中性渐变 + 居中名称），卡片与箱子共用；与 Host renderCover 兜底统一 |
| `cover.createImageHtml(resourcePath)` | 图片封面 HTML + `data-chips-cover-image-source` 标记语义 |
| `cover.normalizeRatio(input)` | 九种比例预设规范化（默认 3:4，容忍 `/` 与 `:` 混写） |
| `cover.validateRatio(value)` | cover_ratio 字段公共校验，杜绝各软件各自兜底 |
| `cover.collectReferences(html)` | cover.html 引用收集（src/href/poster/data-chips-cover-image-source/url()），供卡片/箱子域 reconcile 统一使用 |

- 作为独立模块插件发布（独立版本号、语义化版本、可独立替换升级）；
- 消费方式：`client.module.invoke('cover', 'createDefaultHtml', ...)`（capability + method 协议）；
- Host `renderCover` 兜底默认封面与编辑引擎 `createDefaultCoverHtml` 统一消费同一模块，杜绝视觉漂移；
- 编辑引擎 `utils/card-cover.ts` 迁移后只保留 UI 侧需要的薄适配或直接删除本地实现。

### 3.2 保留在编辑引擎（UI 部分，不迁移）

| 能力 | 说明 |
|---|---|
| 封面编辑面板（比例/方向/图片/HTML 双模式） | `CoverPanel.tsx` 保留，直接消费 3.1 模块能力 |
| 裁剪弹窗（几何 + canvas 导出 PNG） | `CoverCropDialog.tsx` + `cover-crop-layout.ts` 保留（纯前端裁剪，不迁移） |
| 封面制作器（image/html/zip 三模式） | `CoverMaker/*` 保留（模板模式已移除归档，不在范围内） |

### 3.3 收益

- Host renderCover 兜底与编辑引擎默认封面统一，杜绝视觉漂移；
- cover_ratio 语义在公共契约冻结，未来多软件写封面不再各搞一套；
- 封面引用收集统一实现，消除卡片域与箱子域两套「写资源 + 清理旧资源」的引用判定差异。

### 3.4 边界与风险

- `cover_ratio` 字段规范化若改变既有文件的取值（如 `3/4` → `3:4`），需要确认是否影响存量文件读取（当前编辑引擎 normalizeCoverRatio 已做读取端容错，可保持兼容读、统一写）；
- 封面 HTML 是用户数据，模块公共化只约束「生成的产物」，不应限制用户手写 HTML（编辑引擎当前 HTML 模式原样保存的设计保持不变）；
- 模块方法需要同步提供 SDK 封装（`client.module` 或 `client.cover` 专用封装），保持调用体验一致。
