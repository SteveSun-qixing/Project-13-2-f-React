# 工单101：插件契约规范强制 ui.layout 与 Manifest 配置规范漂移

## 背景

任务024 准备升级 `chips-scaffold-basecard` 时，需要确认基础卡片插件 manifest 是否应声明 `ui.layout`。复核公共文档与当前代码后发现，旧 `协议与契约/01-插件契约规范.md` 仍写“所有插件必须包含 `ui.layout`”，但当前主发布 Manifest 规范、SDK CLI、Host 插件运行时和现有基础卡片插件并不以此为正式要求。

## 证据

- `生态共用技术文档/协议与契约/01-插件契约规范.md` 第 6.2 节写明所有插件 manifest 必须包含 `ui.layout`。
- `生态共用技术文档/插件开发/06-Manifest配置规范.md` 中：
  - 所有正式插件应声明 `runtime.targets`；
  - `app` 插件必须声明 `ui.surface`；
  - `card` 插件正式解析依据是 `capabilities.cardTypes`。
- `Chips-SDK/cli/index.js` 的 `validateManifestShape()` 不要求 `card` 插件声明 `ui.layout`。
- `Chips-Host/src/runtime/plugin-runtime.ts` 读取 `ui.layout` 为可选字段，并通过 `capabilities.cardTypes` 解析 card 插件能力。
- 当前八个 `Chips-BaseCardPlugin/*-BCP/manifest.yaml` 均无 `ui.layout`。

## 影响范围

- 公共 Manifest 契约文档。
- 所有官方脚手架 Manifest 模板。
- 任务024 基础卡片脚手架 vNext 升级。
- 后续第三方插件开发者对 `ui.layout` 字段的理解。

## 复现步骤

1. 阅读 `生态共用技术文档/协议与契约/01-插件契约规范.md` 第 6.2 节。
2. 阅读 `生态共用技术文档/插件开发/06-Manifest配置规范.md` 第 3、4、7 节。
3. 阅读 `Chips-SDK/cli/index.js` 中 `validateManifestShape()`。
4. 阅读 `Chips-Host/src/runtime/plugin-runtime.ts` 中 manifest 解析与校验逻辑。
5. 检查 `Chips-BaseCardPlugin/*-BCP/manifest.yaml`。

## 期望行为

- `协议与契约/01-插件契约规范.md` 改为引用并服从 `插件开发/06-Manifest配置规范.md` 的主发布口径。
- 不再声明所有插件都必须包含 `ui.layout`。
- 明确各类型插件的专属字段：
  - `app`：`ui.surface`；
  - `card`：`capabilities.cardTypes`；
  - `layout`：`layout.layoutType`；
  - `theme`：`entry.tokens / entry.themeCss`；
  - `module`：`module.provides / module.consumes` 等模块能力契约。
- `ui.layout` 保持为可选布局/页面/主题接口元数据，不作为所有插件必填字段。
