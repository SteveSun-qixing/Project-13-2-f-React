# 工单175：Chips-SDK mock-host 缺少 file.session.* 能力

## 背景

task041「万能文件链路」迁移后，应用插件统一走 `client.file.session.*`（契约见 `Chips-SDK/src/contracts/file.ts`，`FILE_ACTIONS` 已注册 create/open/read/write/get/persist/close 路由）。但 `Chips-SDK/src/testing/mock-host.ts` 的 `createMockChipsClient()` 只内置了旧 `office.document.*` 的 action 实现，未注册任何 `file.session.*` action：应用侧用官方 mock 做集成测试时，所有 file.session 调用一律返回 `SERVICE_NOT_FOUND`，打开/保存链路无法测试。

该缺口在 Chips-Office 四件套测试收口过程中被两个独立测试任务同时发现（分别以进程内 mock 绕行）。

## 证据

- `Chips-SDK/src/testing/mock-host.ts`：仅有 `office.document.*` action 注册，Grep `file.session` 无命中；
- `Chips-SDK/src/contracts/file.ts`：`FILE_ACTIONS` 完整声明 file.session 六个 action；
- `Chips-SDK/src/api/file.ts`：`FileSessionApi` 接口声明对应方法；
- 复现：用 `createMockChipsClient()` 后调用 `client.file.session.open(...)` → `SERVICE_NOT_FOUND`；
- Chips-Office 侧绕行实例：`Chips-Office/src/testing/mock-environment.ts` 已按契约自行补了最小 file.session mock（进程内实现），`Chips-Office/tests/unit/file-session-integration.test.ts` 与 `tests/unit/sheet-editor-state.test.ts` 各自实现了内存版 mock。

## 影响范围

- 全生态使用 `createMockChipsClient()` / SDK 官方 mock 做集成测试的应用与模块插件；
- 脚手架模板生成的测试（依赖 mock-host）在涉及文件链路时无法工作；
- 每个项目各自实现 file.session mock 造成重复劳动与口径漂移。

## 复现步骤

1. 在任意消费方 `import { createMockChipsClient } from "chips-sdk/testing"`（或等效入口）；
2. 调用 `client.file.session.create({ fileName: "a.xlsx", initialBytes })`；
3. 观察返回 `SERVICE_NOT_FOUND`。

## 期望行为

- `mock-host.ts` 按契约内置内存版 `file.session.*` 全量 action（会话表、字节读写、revision/dirty/status、persist 落盘语义、FILE_* 错误码），与 `FileSessionApi` 行为一致；
- 保留 mock 扩展点（如 `setActionHandler`）可覆盖默认实现；
- 补充 SDK 侧单测覆盖 mock 的 file.session 生命周期；
- 建议将 Chips-Office 内已实现的两份内存版 mock 口径择一沉淀回收，避免三处漂移。

## 暂行处理

- Chips-Office 已在自身测试设施内按契约实现 file.session mock（`src/testing/mock-environment.ts` + 各集成测试），测试可正常进行；
- 不阻塞 Chips-Office 构建/测试门禁。
