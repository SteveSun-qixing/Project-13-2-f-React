# 工单102：Theme Runtime 系统层同层 token 引用解析缺口

## 背景

在 `任务026.04-模块插件HostSDKCLI契约复核补强` 的提交前验证中，模块插件契约相关测试已通过，但 Host 全量集成测试暴露默认主题解析失败。该问题属于 Theme Runtime 正式链路缺口，会阻断 `theme.resolve`、`theme.apply`、卡片渲染和应用窗口主题初始化。

## 证据

- `Chips-Host` 集成测试报错：`THEME_TOKEN_MISSING: Token "chips.sys.icon.color-accent" references missing token`。
- `ThemePack/Chips-default/tokens/sys.json` 中 `chips.sys.icon.color-accent` 引用 `{chips.sys.color.primary}`。
- `ThemePack/Chips-default/tokens/sys.json` 中 `chips.sys.icon.color-danger` 引用 `{chips.sys.color.danger}`。
- 原 `Chips-Host/src/main/theme-runtime/resolve-algorithm.ts` 在解析 `sys` 层时只把 `ref` 层作为可查找引用，无法解析 `sys` 层内部语义 token 之间的引用。

## 影响范围

- Host Theme Runtime 五层 token 解析算法。
- 默认主题包与暗色主题包的图标 token 语义映射。
- 主题公共文档中 token 引用规则与错误码。
- Host 集成测试、主题应用、卡片渲染、应用窗口主题初始化、原生窗口背景推导。

## 复现步骤

1. 进入 `Chips-Host`。
2. 执行 `npx vitest run tests/integration/host-services.test.ts tests/contract/route-manifest.contract.test.ts`。
3. 观察主题相关用例失败，错误指向 `chips.sys.icon.color-accent` 引用缺失。
4. 核对 `ThemePack/Chips-default/tokens/sys.json` 与 `Chips-Host/src/main/theme-runtime/resolve-algorithm.ts`。

## 期望行为

- Theme Runtime 按 `ref -> sys -> motion/layout -> comp` 顺序递归解析 token。
- 每一层允许引用本层 token。
- 跨层引用保持单向：
  - `ref` 可引用 `ref`；
  - `sys` 可引用 `ref` 和 `sys`；
  - `motion/layout` 可引用 `ref`、`sys` 和本层；
  - `comp` 可引用 `ref`、`sys`、`motion`、`layout` 和 `comp`。
- 循环引用必须以 `THEME_TOKEN_CYCLE` 阻断。
- 引用不存在的 token 必须以 `THEME_TOKEN_MISSING` 阻断。
