# 02 · 内核设计

> 【不变式】内核是平台的宪法执行者与唯一全局知情者；一切跨边界行为都必须经过内核。

---

## 1. 定位

内核只做五件事：**路由、注册、事件、生命周期、治理**。

- 它不认识业务、不渲染界面、不实现存储细节；
- 它是系统中唯一"知道全局"的组件——其它所有组件只知道"我与内核的关系"；
- 【不变式】任何服务之间、插件与平台之间、外部与平台之间的调用，都必须经过内核。

### 五条内核不变量

1. **唯一通道**：跨边界调用只有一条合法路径（见 06 篇调用链）。
2. **身份自证无效**：调用方身份由物理通道重建，绝不采信载荷自报。
3. **契约先行**：没有契约（schema + 权限 + 超时 + 错误），不允许注册任何行为。
4. **作用域隔离**：任何注册、订阅、句柄、作业、副作用都必须归属一个作用域。
5. **副作用可逆**：任何对系统状态的修改都必须登记并可完整撤销。

---

## 2. 路由

### 命名与形态

- 路由键统一为 `namespace.action`（点语义），例如 `document.session.open`、`surface.request`、`module.invoke`；
- 支持 `exact / prefix / wildcard` 三种匹配。

### 路由契约（RouteDescriptor）

```
RouteDescriptor = {
  key: string                    // namespace.action
  schemaIn: SchemaRef            // 输入契约（单一源生成）
  schemaOut: SchemaRef           // 输出契约
  permission: PermissionRef[]    // 所需权限
  timeoutMs: number              // 必填；无超时即非法
  idempotent: boolean            // 幂等声明，决定是否允许自动重试
  streaming: false | 'unary' | 'server' | 'duplex'   // 流式支持声明
  scopeRequired: ScopeKind[]     // 要求调用方处于何种作用域
  handler: ImplementationRef     // 实现引用（服务/模块/内置）
}
```

**【不变式】注册即契约**：没有 `RouteDescriptor` 的路由不存在；内核在注册时生成 `route-manifest`，供 SDK、测试与门禁校验。

### 调度流程

```
入站 → 物理通道鉴权 → 身份重建 → schema 校验 → 权限判定
     → 超时/配额/熔断检查 → 作用域绑定 → 分发执行
     → 结果归一 / 标准错误 → 审计与指标 → 出站
```

- 非法参数、越权、超时、熔断都有**唯一的标准错误对象**（见第 8 节）；
- 调度层不做业务判断；它只保证"契约与秩序"。

### 幂等与重放保护

- 幂等路由可安全重试（由客户端运行时按指数退避）；
- 非幂等路由必须携带 `requestId`，内核在时间窗内去重，防止重放。

### 流式路由

- 流式调用（文件传输、事件订阅、长任务输出）不返回单值，而是建立**受控流**（见 04 篇"流"基元）；
- 流必须支持：取消、背压、deadline、错误中继、作用域绑定。

## 3. 注册

内核维护五类注册表，**全部可动态注册与注销**（注销即可逆）：

| 注册表 | 内容 |
|---|---|
| Service Registry | 服务域及其路由 |
| Capability Registry | 模块能力（capability + method + schema） |
| Plugin Registry | 已安装/启用的插件与其会话能力 |
| Command Registry | 面向用户的命令（菜单/快捷键/命令面板的唯一来源） |
| Handler Registry | 文件/资源处理器（打开方式）与内容类型映射 |

**【不变式】注册必须携带作用域**：注册随作用域销毁自动注销；不允许"永久注册"。

---

## 4. 事件

### 类型化事件

- 事件是离散的、已发生的事实；命名采用点语义（`document.changed`、`plugin.activated`、`job.completed`）；
- 事件载荷必须契约化（schema + 版本）；
- 事件是不可变的、只追加的。

### 订阅与投递

- 订阅必须**绑定作用域**：作用域销毁 → 订阅自动解除；
- 投递语义显式声明：`at-most-once`（默认）或 `at-least-once`（需要去重键）；
- 支持过滤（类型、来源、作用域）与超时；
- 跨进程/跨端投递由传输层保证顺序与去重。

### 事件溯源

**【设计】** 会话类状态（文档会话、作业、插件生命周期、审计）以**只追加的类型化事件日志**为唯一真源：

- 可回放：崩溃恢复、状态重建、移动端进程死亡后会话重建；
- 可审计：所有治理事件永续记录；
- 可调试：问题现场可复现。

普通高频数据（进度、输入、媒体帧）属于**流**，不进事件溯源。

---

## 5. 生命周期

### 服务状态机

```
unloaded → loading → ready → running → stopping → stopped
                        ↘ error ↗（可重试回 ready）
```

### 插件会话状态机

```
installed → activated → session-active ⇄ suspended
                  ↘ deactivated → uninstalled
```

- **崩溃恢复**：会话崩溃后，内核依据事件日志与句柄记录重建最小可用状态；
- **挂起/恢复**（移动端）：挂起时冻结作用域、释放非必要句柄；恢复时重建；
- **更新**：先激活新版本于新作用域，再切换句柄，再停用旧作用域——全程不中断。

---

## 6. 治理

内核的治理职责（应用户不可见，即"厚而无感"的制度基础）：

| 治理项 | 机制 |
|---|---|
| 权限 | 每个路由声明权限；调用前按调用方权限快照判定；拒绝即标准错误 |
| 配额 | 每作用域的 CPU/内存/消息频率/存储/并发流软配额；超限降级而非崩溃 |
| 熔断 | 同路由连续失败触发软熔断；半开探测自动恢复 |
| 背压 | 流与消息队列满时向调用方传导背压 |
| 审计 | 越权、安装、卸载、更新、凭证访问等敏感行为永续记录 |
| 可观测 | 统一字段：`traceId / requestId / pluginId / scopeId / namespace / action / durationMs / result / errorCode` |

## 7. 调用上下文

```
InvocationContext = {
  requestId: string
  traceId: string
  caller: {
    kind: 'plugin' | 'service' | 'module' | 'shell' | 'external'
    id: string
    pluginId?: string
    sessionId?: string
    scopeId: string
    permissions: PermissionSnapshot   // 由内核维护，不可自报
  }
  target: { namespace: string; action: string }
  deadline: number                    // 必填
  source: { channel: string; platform: string }
}
```

## 8. 错误模型

```
StandardError = {
  code: string          // 机器可读，命名空间化
  message: string       // 简体中文、面向用户
  details?: unknown     // 结构化诊断（不进界面）
  retryable?: boolean
  requestId: string
  traceId: string
}
```

错误码分层：

- `BRIDGE_*`：通道与传输错误；
- `PLATFORM_*`：能力缺失、降级、配额、权限；
- `DOMAIN_*`：服务域语义错误（如 `DOCUMENT_NOT_FOUND`）；
- `APP_*`：插件自身错误。

**【不变式】界面不出现技术堆栈**：错误文案面向用户；诊断信息只进日志与诊断面板。

---

## 9. 作用域系统

**【设计】作用域是平台的隔离与生命周期单元**，层级如下：

```
platform
└── workspace            （用户态 / 开发态 / 多工作区）
    └── app             （插件实例）
        └── session     （文档会话 / 作业 / 表面会话 / Agent 会话）
            └── component（组件级临时作用域）
```

规则：

- **一切注册、订阅、句柄、作业、副作用、配额都归属某个作用域**；
- 作用域销毁时，其下所有资源**级联释放**（可逆）；
- 作用域是权限与配额的判定边界；
- 同一进程内可有多个作用域并存——"多个人格共处一室"。

---

## 10. 可逆副作用框架

**【不变式】任何对系统状态的修改都必须登记并可撤销。**

- 插件/服务通过内核提供的 effect 登记点进行注册（订阅、注册表项、句柄、定时器、外部连接）；
- 内核自动记录副作用与其作用域；
- 卸载、停用、崩溃时**级联撤销**；
- **可逆性是门禁**：安装前的静态检查与卸载后的残留检查都必须通过。

---

## 11. 内核不做的事

- 不解析业务数据（卡片、文档格式由服务域负责）；
- 不渲染（表现运行时负责）；
- 不直接持有原生平台对象（由 PAL 分面负责）；
- 不实现存储细节（由存储类服务负责）；
- 不做任何用户可见的产品决策。

---

## 12. 实现建议（可替换）

- 内核与跨平台服务以可移植语言实现（建议 Rust），或由等价的可移植实现承担；
- 内核与壳之间使用**认证的本地双向 RPC**（请求/响应、事件、流、取消、deadline、背压、反向调用）；
- 性能预算：路由调度开销为常量级；流式路径零拷贝优先；审计写入异步化。
