# 13 · 可观测性与性能设计

> 【设计】平台默认内建隔离、回退、熔断、可观测；问题必须在用户感知前被发现，在用户报告前能被诊断。

---

## 1. 可观测四件套

| 能力 | 内容 |
|---|---|
| 日志 | 结构化、分级、可导出 |
| 指标 | 延迟、错误、吞吐、配额、资源 |
| 追踪 | 全链路 `traceId` 贯穿通道→内核→服务→PAL |
| 审计 | 敏感行为永续记录（见 09 篇） |

## 2. 统一字段（全平台强制）

```
traceId / requestId / pluginId / scopeId
namespace / action / durationMs / result / errorCode
```

- 每条跨边界调用必须携带 `traceId` 与 `requestId`；
- 日志与指标共享同一字段口径；
- 应用日志与平台日志同构，可按作用域过滤。

## 3. 采集与存储

- 本地：环形缓冲 + 文件轮转；用户可查、可导出；
- 敏感字段脱敏（凭证、路径、个人数据）；
- 遥测（可选开启）：匿名崩溃与性能数据；默认最小化、可关闭；
- 企业场景：支持集中采集（见 14 篇）。

## 4. 诊断能力

| 工具 | 用途 |
|---|---|
| 诊断面板 | 路由延迟分布、错误 TOP、权限拒绝 TOP、配额超限、插件健康 |
| 现场快照 | 崩溃/异常时保留上下文（含事件日志片段） |
| 事件回放 | 依据事件溯源日志复现问题路径（见 02 篇） |
| 链路追踪视图 | 单次调用全链路耗时分解 |
| 能力快照视图 | 当前端各分面能力与降级状态 |

## 5. 性能预算

| 指标 | 预算基线 |
|---|---|
| 启动到可用（boot → ready） | 桌面：秒级；移动：秒级；Web：首屏级 |
| 单次路由调度 | 常量级开销；不随注册表规模线性增长 |
| 渲染提交 | 桌面 p95 ≤ 32ms；移动/Web p95 ≤ 48ms |
| 流吞吐 | 逼近传输带宽；零拷贝优先 |
| 内存峰值 | 按能力等级设限；移动端更严格 |
| 包体 | 插件包（不含运行时）按类型设上限；增量更新优先 |
| 移动端功耗 | 挂起即休眠；后台任务受系统配额 |

超出预算 = 缺陷，进入门禁与工单流程。

## 6. 性能治理原则

1. **并行化**：独立请求并行，禁止瀑布式串行；
2. **增量与虚拟化**：大列表/表格/树默认虚拟化；渲染增量提交；
3. **就近工作**：交互式编辑就近会话，避免高频往返（见 04 篇文档基元）；
4. **缓存策略**：读多写少用 TTL/SWR；写操作幂等校验 + 回写确认；
5. **零拷贝优先**：流路径避免不必要拷贝；
6. **预算化**：每个页面/插件有性能预算，门禁校验。

## 7. 故障治理

| 机制 | 说明 |
|---|---|
| 失败隔离 | 组件级错误边界；单点失败不拖垮页面 |
| 回退 | 能力缺失走降级路径；布局非法回退安全模板 |
| 熔断 | 同路由连续失败触发软熔断，半开探测恢复 |
| 配额 | 超限降级（限频、暂停后台、告警）而非崩溃 |
| 恢复 | 崩溃后依据事件溯源与检查点恢复会话 |

## 8. 责任划分

| 角色 | 负责 |
|---|---|
| 平台核心 | 路由性能、服务健康、审计、系统级指标 |
| 表现运行时 | 渲染性能、无障碍、动效预算 |
| 插件 | 页面级交互性能、自身业务指标 |
| 工具链 | 门禁校验、预算检查、报告生成 |
