# 10 · 分发与市场设计

> 【设计】分发是平台的入口能力：让软件像内容一样被获取、安装、更新、卸载——全程可逆、可信、无感。

---

## 1. 分发对象

| 对象 | 形态 | 通道 |
|---|---|---|
| 插件 | `.cpk` | 市场 / 私有源 / 本地文件 |
| 官方能力包 | 平台组件 | 随平台更新 |
| 核心与壳 | 平台安装器 | 平台自更新 |
| 表现运行时 | 平台组件 | 随平台更新 |
| 内容 | 卡片 / 箱子 | 社区 / 本地文件 / 分享链接 |

## 2. 来源分级

| 级别 | 来源 | 信任处置 |
|---|---|---|
| 官方 | 平台团队签名 | 完整信任；原生能力包仅此级可用 |
| 认证开发者 | 实名/审核开发者签名 | 常规权限；敏感权限需用户确认 |
| 第三方 | 任意开发者签名 | 完整沙箱；敏感权限逐项确认 |
| 本地自装 | 无签名 `.cpk` | 仅开发态或用户显式开启；强警示 |

**【不变式】** 来源分级影响权限与信任，但**不豁免**任何安全流水线。

## 3. 签名体系

- 开发者签名（身份）+ 平台签名（官方能力包）；
- 安装时校验签名与内容哈希；
- **撤销列表**：被盗签名或恶意版本可撤销，已装实例在下次联网校验时拒绝；
- 签名密钥存于安全存储；支持轮换。

## 4. 市场形态

- 浏览 / 搜索 / 分类 / 评分 / 举报；
- **权限透明**：安装前完整展示插件申请的权限与来源；
- 版本历史与变更说明；
- 依赖与兼容信息（支持的端、所需平台版本）；
- 更新推送与一键更新；
- 企业/私有源：内网市场与企业策略分发。

## 5. 安装与更新协议

```
下载（增量优先） → 校验（签名/哈希） → 暂存 → 激活（原子）
                                        ↘ 失败即回滚
```

- **增量更新**：按文件级差量下载；
- **原子替换**：新旧版本切换点明确，切换失败自动回滚；
- **灰度**：官方与认证插件支持分阶段放量；
- **渠道**：stable / beta / dev；
- **强制更新**：仅用于安全修复；插件可声明最低平台版本。

## 6. 平台更新与插件更新解耦

- 契约稳定是解耦基础：平台更新不破坏已装插件；
- 平台更新分两阶段：先升级运行时与核心（保持契约），再按需升级壳；
- 插件不因平台更新而必须重新发布——除非使用的新能力超出其声明的最低版本，此时获得**确定性错误**而非静默失败。

## 7. 离线与本地分发

- `.cpk` 可直接分发（U 盘、内网、网站），拖拽或命令行安装；
- 离线安装同样执行完整校验（除联网撤销校验外）；
- 导出已装插件清单，便于迁移与复现环境。

## 8. 审核与治理

- **自动化优先**：门禁（契约、权限、安全、质量）自动判定；
- 人工只处理例外（申诉、敏感能力、官方推荐位）；
- 下架与撤销：可远程禁用已装实例的指定版本；
- 举报与处置闭环；恶意行为纳入来源分级降级。

## 9. 远期经济（可选）

- 付费下载、订阅、内购由平台统一承载（若做）；
- 开发者收益与分成规则由平台运营制定；
- 内容与软件的支付分离（内容由社区能力承载）。
