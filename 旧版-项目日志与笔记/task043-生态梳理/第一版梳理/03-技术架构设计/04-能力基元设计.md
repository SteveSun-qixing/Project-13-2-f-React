# 04 · 能力基元设计

> 【设计】基元是平台的"元素周期表"。**组合优于特判**：任何新品类软件，都应能由基元组合出来，而不是让平台为它新增特例。

---

## 1. 为什么需要基元

判据：**一类新软件到来时，是否需要平台新增 API？**

- 需要 → 说明基元抽象不完整，先补基元；
- 不需要 → 平台健康，软件只是新的组合。

九大基元：**表面、文档、作业、流、句柄、权限、作用域、命令、事件**。

## 2. 基元总览

| 基元 | 回答的问题 | 典型契约面 |
|---|---|---|
| 表面 Surface | 界面存在于哪里 | 创建、能力、状态、关闭 |
| 文档 Document | 内容如何被打开、编辑、保存、观察 | 会话、读取、写入、提交、观察 |
| 作业 Job | 长时间的工作如何被执行与观察 | 提交、进度、取消、结果、恢复 |
| 流 Stream | 连续数据如何被传输 | 建立、读取、写入、背压、取消 |
| 句柄 Handle | 资源如何被安全引用 | 获取、使用、续期、撤销 |
| 权限 Permission | 能力如何被授权 | 声明、授予、判定、审计 |
| 作用域 Scope | 生命周期与隔离如何被界定 | 创建、归属、级联销毁 |
| 命令 Command | 用户意图如何被表达 | 定义、绑定、触发、状态 |
| 事件 Event | 状态变化如何被播报与回溯 | 发布、订阅、溯源、回放 |

---

## 3. 各基元设计

### 3.1 表面（Surface）

**定义**：用户可见的界面容器。一切界面都存在于某个表面中。

- **形态**：`window / sheet / tab / fullscreen / panel / overlay / offscreen`；
- **上下文**：`{ surfaceId, kind, sizeClass, safeArea, inputModes, displays, density }`——这是"自适应"的信息基础；
- **能力**：请求全屏、请求尺寸、置顶、沉浸模式、关闭；能力按端查询，缺失即降级；
- **跨端映射**：桌面＝窗口；移动＝页面/全屏卡片/底部卡片；Web＝页面/弹层；无头＝离屏画布；
- **生命周期**：`create → active ⇄ suspended → closed`；崩溃后可按会话重建。

**组合示例**：任何 app 插件 = 表面 + 命令 + 内容（文档或原生内容）。

### 3.2 文档（Document）

**定义**：有身份、可打开、可编辑、可观察、可提交的内容实体。

- **会话模型**：`open → read/write（工作副本）→ watch → persist（原子提交）→ close`；
- **工作副本 + 原子提交**：编辑发生在副本，提交换入；外部工具永远看到完整文件；
- **外部共存**：文件被其它软件修改时发布 `document.external-change`，由应用决定合并或重载；
- **检查点与恢复**：异常退出后可恢复到最近检查点；
- **两个世界**：生态原生格式（卡片/箱子）与通用文档（docx/xlsx/psd/代码仓库）走**同一会话模型**，格式差异由处理器承担；
- **无路径暴露**：应用只持有文档句柄。

**组合示例**：Office＝表面 + 文档 + 作业 + 命令；笔记＝文档 + 表面；代码工具＝文档 + 作业 + 流。

### 3.3 作业（Job）

**定义**：有时间跨度的、可观察、可取消的工作单元。

- **形态**：`瞬时（sync）` / `短任务` / `长任务（job）` / `可恢复任务（resumable）`；
- **契约**：`submit → jobId`；`progress` 事件；`cancel`；`result`；`resume`；
- **执行器**：模块运行时、内核调度器、应用内执行器（本地作业）；
- **持久化**：作业记录进事件溯源日志——可审计、可恢复；
- **配额**：作业受作用域配额约束；超限降级或排队。

**组合示例**：格式转换、导出、索引、构建、Agent 长任务。

### 3.4 流（Stream）

**定义**：连续数据与事件的传输通道。

- **形态**：字节流（大文件、媒体）、事件流（订阅）、输出流（任务日志）、双向流（终端）；
- **语义**：背压、取消、deadline、错误中继、作用域绑定；
- **与事件的区别**：事件是离散事实（可溯源）；流是连续数据（不溯源）；
- **跨端**：弱网/移动端支持降级（分块、重连、断点续传）。

**组合示例**：大文件编辑、媒体预览、AI 流式输出、终端。

### 3.5 句柄（Handle）

**定义**：对平台管理资源的安全引用。

- **类型**：`resourceHandle / documentHandle / surfaceHandle / jobHandle`；
- **租约**：每个句柄有生命周期与租约（TTL、续期、撤销）；撤销即失效；
- **规则**：跨边界不传路径；句柄绑定作用域；越权使用返回标准错误；
- **跨端**：各端底层存储完全不同（文件系统/沙箱/虚拟文件系统），句柄语义统一。

**组合示例**：一切资源访问的底座。

### 3.6 权限（Permission）

**定义**：能力的授权凭证。

- **链条**：清单声明 → 用户/策略授予 → 运行时快照 → 每次调用判定；
- **粒度**：**能力级**（如"读取工作区文件"），不是服务级粗放授权；
- **三态**：`granted / denied / prompt`（可交互授权的场景）；
- **审计**：敏感权限（文件写、凭证、外部打开、进程）永续记录；
- **跨端**：移动端系统权限映射（相机、相册、通知）由平台翻译。

### 3.7 作用域（Scope）

**定义**：生命周期与隔离的边界（见 02 篇第 9 节）。

- **层级**：`platform > workspace > app > session > component`；
- **级联释放**：作用域销毁 → 其下注册、订阅、句柄、作业、副作用全部撤销；
- **判定边界**：权限与配额在作用域上判定；
- **组合示例**：同时打开十个文档＝十个会话作用域；多 Agent 并行＝多会话作用域。

### 3.8 命令（Command）

**定义**：用户意图的唯一表达。

- **一源多消费**：命令定义一次，菜单/快捷键/命令面板/工具栏/移动端操作表全部消费同一来源；
- **契约**：`{ id, title（简体中文）, icon, shortcut?, scope, enabled, handler }`；
- **分发**：命令服务 + 内核路由；按键冲突由平台统一仲裁（单一执行者原则）；
- **跨端**：移动端无菜单栏 → 自动映射为命令面板/操作表。

### 3.9 事件（Event）

**定义**：状态变化的播报与回溯。

- **类型化、只追加、可溯源**；
- **订阅绑定作用域**（作用域销毁即解除）；
- **事件溯源**：会话类状态（文档会话、作业、插件生命周期、审计）由事件日志重建；
- **回放**：崩溃恢复、问题复现、状态审计。

## 4. 组合验证（用基元解释全品类）

| 软件品类 | 基元组合 |
|---|---|
| Office | 表面 + 文档 + 作业 + 命令 + 权限 |
| 浏览器 | 表面（内容表面）+ 流 + 权限 + 句柄 |
| 开发工具 | 文档（代码）+ 作业（构建）+ 流（终端）+ 命令 |
| Agent 工具 | 作业（会话）+ 流（模型输出）+ 事件 + 文档 + 权限 |
| 图像/视频创作 | 表面 + 文档 + 作业（渲染/导出）+ 流（预览 + 媒体） |
| 游戏 | 表面（全屏）+ 流（资源）+ 权限（高性能豁免） |
| 系统 UI / 启动器 | 表面 + 命令 + 平台集成 + 权限 |
| 笔记 | 文档 + 表面 + 命令 |

**结论**：九大基元可以解释并承载全部目标品类，无需任何品类专属 API。

---

## 5. 基元与契约

- 基元是契约体系的骨架：每个基元的类型（句柄、会话、作业、权限快照等）都进入**契约单一源**，生成四语言实现并配金标向量（见 06 篇）；
- 基元最小集**保持稳定**：新增基元的门槛是"无法由现有基元组合且被多品类共同需要"；
- 基元的版本演进走契约版本机制，不采用破坏式变更。
