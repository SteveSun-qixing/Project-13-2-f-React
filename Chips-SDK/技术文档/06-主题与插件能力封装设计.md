## 1. 主题能力封装

### 1.1 API 设计

```ts
export interface ThemeApi {
  list(publisher?: string): Promise<ThemeMeta[]>;
  apply(themeId: string): Promise<void>;
  getCurrent(options?: { appId?: string; pluginId?: string }): Promise<ThemeState>;
  getAllCss(): Promise<{ css: string; themeId: string }>;
  resolve(chain: string[]): Promise<{
    resolved: Array<{ id: string; displayName: string; version: string; order: number }>;
    tokens: Record<string, unknown>;
    diagnostics: ThemeDiagnostic[];
    summary: ThemeDiagnosticSummary;
  }>;
  contract: {
    get(component?: string): Promise<ThemeContractView>;
  };
  onChanged(handler: (payload: ThemeChangedPayload) => void): () => void;
}
```

### 1.2 契约对齐

- 所有类型与字段必须对齐：
  - 《主题接口规范》：`生态共用技术文档/主题系统/02-主题接口规范.md`
  - 《Host 服务域设计》：`生态共用技术文档/架构设计/14-Host服务域设计.md`
- 若发现 Host 实现与文档不一致（如 `theme.resolve` 响应结构），必须先提工单处理，禁止在 SDK 层自行发明折衷结构。

### 1.3 常见用法示例（设计级）

- 获取所有主题并应用：

  ```ts
  const themes = await client.theme.list();
  await client.theme.apply(themes[0].id);
  ```

- 获取当前主题 CSS 并注入到页面（容器应用）：

  ```ts
  const { css, themeId } = await client.theme.getAllCss();
  // 容器应用负责将 CSS 注入到 <style> 或 Shadow DOM，并记录当前 themeId
  ```

---

### 1.4 当前实现补充（2026-03-10）

- `theme.list()` 的结果来源于当前工作区中已启用主题插件，不包含未启用主题；
- `theme.getAllCss()` 的返回结构为 `{ css, themeId }`，供应用建立显式主题快照；
- `theme.resolve()` 透传 Host 的 `tokens/diagnostics/summary`，SDK 不重新解释诊断；
- `theme.contract.get()` 返回生态公共 `ThemeContractView`，供设置面板和 CLI 展示 coverage 与缺失 token；
- `theme.onChanged()` 订阅 `theme.changed`，事件载荷包含 `themeVersion` 与 `diagnosticsSummary`；
- 应用启动时必须优先使用 Host 当前主题或 preload 注入的文档主题状态，不能在 SDK 消费端写死默认主题；
- 当主题切换后，依赖主题运行时缓存键的复合窗口应主动重建内容，而不是只刷新外层壳层。

## 2. 配置与多语言封装

### 2.1 config 封装

```ts
export type ConfigScope = 'user' | 'workspace' | 'system';

export interface ConfigApi {
  get<T = unknown>(key: string): Promise<T | undefined>;
  set<T = unknown>(key: string, value: T, options?: { scope?: ConfigScope }): Promise<void>;
  batchSet(entries: Record<string, unknown>, options?: { scope?: ConfigScope }): Promise<void>;
  reset(key?: string, options?: { scope?: ConfigScope }): Promise<void>;
}
```

注意事项：

- 不在 SDK 层引入额外配置层级或默认值逻辑，默认值由调用方控制。
- SDK `config.get` 对 Host `{ value }` 响应做解包；写操作丢弃 Host `{ ack: true }`，对调用方保持 `Promise<void>`。
- `config.batchSet` 的 `entries` 必须保持 Host 正式契约中的 record 形态，不再使用数组条目形态。
- 对写操作必须尊重 Host 权限与错误返回。

### 2.2 i18n 封装

```ts
export interface I18nApi {
  getCurrent(): Promise<string>;
  setCurrent(locale: string): Promise<void>;
  translate(key: string, params?: Record<string, unknown>): Promise<string>;
  listLocales(): Promise<string[]>;
  onChanged(handler: (payload: { locale: string }) => void): () => void;
}
```

`i18n.setCurrent` 对调用方保持 `Promise<void>`，Host 返回 `{ ack: true }` 只作为路由确认；语言变化订阅统一走 `language.changed` 点语义事件。

## 3. 插件能力封装

### 3.1 插件信息查询

```ts
export interface PluginApi {
  getSelf(): Promise<PluginInfo>;
  list(options?: { type?: PluginType; capability?: string }): Promise<PluginInfo[]>;
  get(pluginId: string): Promise<PluginInfo | undefined>;
  getCardPlugin(cardType: string): Promise<PluginInfo | undefined>;
  getLayoutPlugin(layoutType: string): Promise<PluginInfo | undefined>;
  install(manifestPath: string): Promise<{ pluginId: string }>;
  enable(pluginId: string): Promise<void>;
  disable(pluginId: string): Promise<void>;
  uninstall(pluginId: string): Promise<void>;
  query(options?: { type?: PluginType; capability?: string }): Promise<PluginRecord[]>;
}
```

类型定义：

- `PluginInfo` 与 Bridge API 规范保持一致。
- `PluginType`：`'app' | 'card' | 'layout' | 'theme' | 'module'`。
- `PluginRecord` 对应 Host `plugin.query` 返回的运行时记录结构，包含治理列表所需的标准元数据与类型专属字段。

### 3.2 管理操作（谨慎封装）

- SDK 已提供 `list/get/getSelf/getCardPlugin/getLayoutPlugin/install/enable/disable/uninstall/query` 插件能力，严格映射到 Host `plugin.*` 服务动作：
  - `list/get/getSelf/getCardPlugin/getLayoutPlugin/query` 属于读取动作，统一使用 `plugin.read` 权限；
  - `install/enable/disable/uninstall` 属于治理变更动作，统一使用 `plugin.manage` 权限；
  - SDK 不做额外的缓存或“智能重试”，仅包装为类型安全的调用入口；
  - 插件管理行为（安装/卸载/启停）应主要用于 Host 自身、开发工具与运维脚本场景，在普通业务插件中不推荐直接调用。

---

### 3.3 开发工具集成

- `chipsdev-r` 已正式复用 Host 命令核心，在开发工作区内提供 `start/stop/status/config/logs/plugin/theme/update/doctor/open/completion`；
- SDK 层不额外发明另一套开发态插件或主题管理协议，而是复用 Host `plugin.*` 与 `theme.*` 服务；
- 开发者若需要联调主题问题，应优先使用 `chipsdev-r plugin.*` 与 `chipsdev-r theme.*`，避免直接编辑 `.chips-host-dev`。

## 4. 窗口与模块能力封装

### 4.1 window 封装

```ts
export interface WindowApi {
  open(config: WindowConfig): Promise<WindowState>;
  focus(id: string): Promise<void>;
  resize(id: string, size: { width: number; height: number }): Promise<void>;
  setState(id: string, state: Partial<WindowState>): Promise<void>;
}
```

注意：

- `WindowConfig` 与 `WindowState` 必须与 Host 对外接口定义一致。
- 高风险能力（如关闭窗口、全屏等）应在文档中明确使用场景与权限要求。

### 4.2 module 封装

```ts
export interface ModuleApi {
  listProviders(options?: {
    capability?: string;
    pluginId?: string;
    status?: "enabled" | "disabled" | "running" | "error";
    versionRange?: string;
  }): Promise<ModuleProviderRecord[]>;
  resolve(
    capability: string,
    options?: { versionRange?: string }
  ): Promise<ModuleProviderRecord>;
  invoke(request: ModuleInvokeRequest): Promise<ModuleInvokeResult>;
  job: {
    get(jobId: string): Promise<ModuleJobRecord>;
    cancel(jobId: string): Promise<void>;
  };
}
```

约束：

- SDK 对外只暴露 `listProviders/resolve/invoke/job.get/job.cancel`；
- `listProviders` 负责 provider 枚举，`resolve` 负责默认 provider 解析；
- `invoke` 统一收敛同步结果与异步 job 结果；
- SDK 在调用前校验 `capability/method/jobId` 等必填字段；
- SDK 不保存模块 registry、运行时实例或 job 状态，所有治理都交给 Host。

## 5. 平台能力封装

```ts
export interface PlatformApi {
  getInfo(): Promise<PlatformInfo>;
  getCapabilities(): Promise<PlatformCapabilities>;
  openExternal(url: string): Promise<void>;
  openFile(options?: PlatformDialogFileOptions): Promise<string[] | null>;
  saveFile(options?: PlatformDialogSaveOptions): Promise<string | null>;
  showMessage(options: PlatformDialogMessageOptions): Promise<number>;
  showConfirm(options: PlatformDialogMessageOptions): Promise<boolean>;
  clipboardRead(format?: "text" | "image" | "files"): Promise<PlatformClipboardPayload>;
  clipboardWrite(data: PlatformClipboardPayload, format?: "text" | "image" | "files"): Promise<void>;
  shellOpenPath(path: string): Promise<void>;
  shellOpenExternal(url: string): Promise<void>;
  shellShowItemInFolder(path: string): Promise<void>;
  notificationShow(options: PlatformNotificationOptions): Promise<void>;
  traySet(options?: PlatformTrayOptions): Promise<PlatformTrayState>;
  trayClear(): Promise<void>;
  trayGetState(): Promise<PlatformTrayState>;
  shortcutRegister(accelerator: string, options?: { eventName?: string }): Promise<boolean>;
  shortcutUnregister(accelerator: string): Promise<void>;
  shortcutIsRegistered(accelerator: string): Promise<boolean>;
  shortcutList(): Promise<string[]>;
  shortcutClear(): Promise<void>;
  ipcCreateChannel(options: PlatformIpcCreateOptions): Promise<PlatformIpcChannelInfo>;
  ipcSend(channelId: string, payload: string, options?: { encoding?: "utf8" | "base64" }): Promise<void>;
  ipcReceive(channelId: string, options?: { timeoutMs?: number }): Promise<PlatformIpcMessage>;
  ipcCloseChannel(channelId: string): Promise<void>;
}
```

要求：

- 不在 SDK 层扩展平台能力语义，仅按 Host `platform.*` 正式动作做参数整理、返回解包和 `{ ack: true }` 丢弃。
- `openFile / saveFile / showMessage / showConfirm / clipboard* / shell* / notificationShow / tray* / shortcut* / ipc*` 均属于 Host 平台服务域公共封装，不应在业务代码中直接散落 `client.invoke("platform.*")`。
- `openFile(options.filters)` 使用 `{ name, extensions }` 描述原生文件选择器扩展名过滤，`extensions` 不写点号；SDK 仅负责透传正式 options，Host/PAL 负责映射到平台原生对话框。
- `openFile(options.mode)` 支持 `file / directory / file-or-directory`；其中 `file-or-directory` 用于插件包目录或 manifest 文件均可作为输入的治理场景。
- `notificationShow(options.icon)`、`traySet(options.icon)` 是操作系统壳层图标路径，不属于运行时 `IconDescriptor`。
- 对 `openExternal`、`shellOpenExternal`、`shellOpenPath` 必须强调安全风险，调用前建议二次确认。
