# 01-前端技术选型

> 状态：正式（task030 卸担计划定稿，2026-08）
> 适用范围：全部前端插件（app/card/layout）、社区网页版、脚手架模板
> 决策过程与选型核对记录：`项目日志与笔记/task030-卸担计划/02-技术选型与依赖策略.md`

## 1. 选型结论

| 层 | 选型 | 版本 | 说明 |
|---|---|---|---|
| 框架 | React | `^18.2.0` | 全生态统一，antd v6 官方支持 `react >= 18.0.0` |
| 组件库 | **Ant Design（antd）** | `6.5.4` | 唯一组件库；默认简体中文、覆盖度 100%、MIT、Electron 兼容成熟 |
| 图标 | `@ant-design/icons` | `6.3.2` | 与 antd 同源，等价替换旧 `ChipsIcon` 图标体系 |
| 日期 | `dayjs` | `1.11.21` | antd 内置依赖，直接使用 |
| 共享前端层 | `@chips/ui` | `0.1.0` | workspace 内部包（src 源码导出），视觉 token、全局样式、运行时与通用组件唯一落点 |
| 构建 | Vite（经 `chipsdev-r`） | 现状 | 构建链路不动 |
| 测试 | Vitest（经 `chipsdev-r`） | 现状 | 测试链路不动 |
| 样式方案 | antd CSS-in-JS + 共享层 `global.css` | — | 见 `02-统一视觉规范.md` |

**废弃**：`@chips/component-library`、`@chips/a11y`、ThemePack、多语言系统（task030），存量代码随重构移除，不得新增依赖。

## 2. 依赖引入规则

1. 所有前端插件统一新增依赖：`antd`、`@ant-design/icons`、`dayjs`、`@chips/ui`（workspace 依赖，`"@chips/ui": "0.1.0"`）。
2. 版本一律锁定精确版本（不用 `^`），避免上游变更影响。
3. 禁止引入第二套组件库（MUI/Arco 等），禁止混用不同 antd 版本。
4. 新增第三方依赖必须经过选型核对（用途、许可证、维护状态、包体影响、安全风险、跨端兼容性）；涉及架构或长期运行时依赖先记录方案并等待确认。
5. 依赖注入方式：各插件独立打包 antd 与 `@chips/ui`（不采用 external + Host 全局注入方案）。

## 3. 工程兼容性核查

- **CSP**：保持现状即可（`style-src 'self' 'unsafe-inline'` 已允许 antd CSS-in-JS 内联样式；antd 不使用 eval；`@ant-design/icons` 无外部资源）。重构中禁止放宽 CSP。
- **Electron**：antd 官方支持 Chromium；弹层（Modal/Popover）定位异常时通过 `ConfigProvider` 的 `getPopupContainer` 绑定到 `#root`。
- **TypeScript**：各插件 tsconfig 保持现状（`"jsx": "react-jsx"`）；antd v6 类型完备，`@chips/ui` 源码随插件构建直接类型检查（须满足严格配置）。

## 4. antd v6 实测要点

- `Modal` 的 `styles` 无 `content` 键，用 `body`。
- `MenuProps["items"]` 不能直接作为 JSX children，用 `Dropdown` 内联渲染。
- 含 JSX（如图标组件定义）的命令文件必须使用 `.tsx` 后缀。
- 两字中文按钮文案 antd 会自动插入空格（如"确 定/取 消"），测试断言按 `textContent` 或语义定位。
