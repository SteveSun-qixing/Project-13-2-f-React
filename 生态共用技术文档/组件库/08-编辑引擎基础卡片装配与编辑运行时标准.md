# 编辑引擎基础卡片装配与编辑运行时标准

## 1. 适用范围

本标准适用于官方 `Chips-EditingEngine` 的正式编辑态基础卡片预览、编辑与资源链路。

本标准不替代以下对外公开能力：

- `client.card.compositeWindow.render(...)`
- `client.card.editorPanel.render(...)`
- `client.card.coverFrame.render(...)`

上述接口仍是普通应用、查看器与第三方宿主的正式 Host 托管路径。官方编辑引擎的正式例外仅在于“由自己装配复合卡片窗口”，但单卡查看态和编辑态仍统一消费 Host `basecard.*` 会话能力，基础卡片插件的归一、校验、主题来源与正式类型契约继续由 Host 与共享规范统一定义。

## 2. 正式定位

编辑引擎采用“Host 托管基础卡片运行时 + 应用内装配壳层”的正式架构。

- Host 是基础卡片运行时唯一权威方。
- 编辑引擎负责复合卡片级别的装配、布局、选中态、桌面交互代理与文件保存编排。
- 编辑引擎不再在应用内静态注册插件源码，也不再自行实现第二套基础卡片规范化逻辑。

正式目标：

- 用户在新设备上只需安装 Host、编辑引擎应用插件和基础卡片插件，即可直接完成编辑。
- 基础卡片插件只维护一套正式运行时代码，由 Host 同时服务查看态、Host 托管编辑器和编辑引擎编辑态。
- 编辑引擎继续拥有复合卡片窗口级别的控制权，而不是退回到整张复合 iframe 黑盒。

## 3. 正式链路

### 3.1 预览链路

1. 编辑引擎从 `CardService` 读取当前复合卡片与基础卡片配置。
2. `CompositeCardAssembler` 按基础卡片顺序创建单卡宿主。
3. `BasecardFrameHost` 调用 Host `basecard.openSession`。
4. Host 根据 `cardType` 找到基础卡片插件，执行：
   - `getBasecardDescriptor`
   - `createInitialBasecardConfig`
   - `normalizeBasecardConfig`
   - `validateBasecardConfig`
   - `collectReferencedResources`
5. `BasecardFrameHost` 调用 Host `basecard.renderView` 获取单卡 iframe。
6. 编辑引擎订阅 `chips.basecard:*` 事件，汇总高度、错误和选中态。
7. 编辑引擎销毁节点或切换输入时，调用 Host `basecard.closeSession`。

### 3.2 编辑链路

1. 用户在复合卡片窗口中选中基础卡片。
2. `EditPanel -> PluginHost -> EditorHost` 调用 Host `basecard.openSession`。
3. `EditorHost` 读取 Host 会话返回的权威配置、校验结果、资源引用和 `commitDebounceMs`。
4. `EditorHost` 调用 Host `basecard.renderEditor` 获取单卡编辑 iframe，并向该 iframe 注入正式资源桥。
5. 插件编辑器通过 `chips.basecard:change` 输出下一版权威草稿配置。
6. `EditorHost` 负责资源导入、解析、释放、删除，并把资源操作和权威配置统一提交回 `CardService.updateBasicCard(...)`。
7. 编辑器卸载、切换节点或重建时，调用 Host `basecard.closeSession`。

## 4. Host 正式能力

编辑引擎正式依赖以下 Host 路由：

- `basecard.openSession`
- `basecard.renderView`
- `basecard.renderEditor`
- `basecard.closeSession`

`basecard.openSession` 返回的正式会话信息至少包括：

- `sessionId`
- `pluginId`
- `cardType`
- `baseCardId`
- `displayName`
- `normalizedConfig`
- `validation`
- `referencedResources`
- `commitDebounceMs`
- `supportsEditor`

正式约束：

- 编辑引擎不得自己扫描插件目录后直连源码。
- 基础卡片的规范化、校验、资源收集必须以 Host 会话结果为准。
- 编辑引擎可以决定如何装配这些单卡 iframe，但不能绕开 Host 重写插件运行时权威逻辑。

## 5. 编辑引擎壳层职责

### 5.1 CompositeCardAssembler

负责：

- 按 `basicCards` 顺序装配基础卡片；
- 读取 `layout.padding/layout.gap` 组织布局；
- 汇总单卡高度、加载态、错误态；
- 把总高度回传给 `CardWindow`；
- 管理当前选中基础卡片。

正式视觉约束：

- 装配层不额外提供统一边框、圆角、阴影。
- 装配层只负责结构编排和状态聚合。

### 5.2 BasecardFrameHost

负责：

- 打开/关闭 Host 基础卡片会话；
- 装载 `basecard.renderView` 返回的 iframe；
- 订阅 `ready/height/select/interaction/error`；
- 把交互意图转交编辑引擎壳层。

稳定性要求：

- 只有 `cardPath/baseCardId/cardType/config/themeCacheKey/interactionPolicy` 等有效渲染输入变化时才允许重建会话。
- 单卡失败必须被隔离在当前节点，不得拖垮整张复合卡片。

### 5.3 EditorHost

负责：

- 打开/关闭 Host 编辑会话；
- 以 Host 会话结果为权威初始化单卡编辑 iframe；
- 调用 `basecard.renderEditor` 获取 Host 托管编辑器；
- 维护资源解析缓存、待导入资源和待删除资源；
- 把权威配置与资源操作提交回 `CardService`。

正式约束：

- 编辑器会话防抖节流以 Host 返回的 `commitDebounceMs` 为准。
- 编辑器运行时不直接写卡片文件。
- `PluginHost` 在编辑引擎中只是 `EditorHost` 的外层包装，不再承担本地插件装载职责。

## 6. 资源链路标准

### 6.1 统一规则

- 卡片内部资源路径统一以卡片根目录为基准记录。
- 正式记录值不得依赖 `.card/`、`content/` 当前所在目录做相对换算。
- `referencedResources` 必须输出卡片根目录相对路径，例如 `assets/example.png`。

### 6.2 基础卡片预览与编辑

- Host 在 `basecard.renderView` 与 `basecard.renderEditor` 生成的文档中注入 `<base href="file:///.../卡片根目录/">`。
- 因此查看态 iframe 与编辑态 iframe 中使用 `./assets/example.png`、`assets/example.png` 等写法时，最终都以卡片根目录解析。
- 官方编辑引擎自己的编辑面板不依赖 `<base>`，而是通过正式资源桥解析和释放资源 URL。
- 插件不得私自拼系统绝对路径。

### 6.3 编辑器资源导入

- 插件编辑器如需操作资源，应通过正式资源桥：
  - `resolveResourceUrl(resourcePath)`
  - `releaseResourceUrl(resourcePath)`
  - `importResource({ file, preferredPath? })`
  - `deleteResource(resourcePath)`
- 编辑引擎接到请求后，把文件写入卡片根目录正式资源位置。
- 正式资源路径以卡片根目录为基准记录，具体保存到根目录下哪个子路径由宿主链路统一分配；基础卡片插件只消费返回的正式相对路径，不自行约定宿主落盘策略。
- `importResource(...)` 返回结果至少必须包含 `path`，且该值必须是卡片根目录相对路径。

### 6.4 封面资源

- `cover.html` 仍保存在 `.card/cover.html`。
- 封面引用的资源文件保存在卡片根目录，例如 `cardcover/cover-image.png`。
- `cover.html` 必须带有指向卡片根目录的基准路径，使 `./cardcover/...` 按卡片根目录解析。

## 7. 基础卡片插件正式契约

基础卡片插件入口必须导出：

```ts
export function renderBasecardView(ctx): (() => void) | void;
export function renderBasecardEditor(ctx): (() => void) | void;
export function getBasecardDescriptor(): {
  cardType: string;
  displayName: string;
  commitDebounceMs?: number;
};
export function createInitialBasecardConfig(baseCardId: string): Record<string, unknown>;
export function normalizeBasecardConfig(input: Record<string, unknown>, baseCardId: string): Record<string, unknown>;
export function validateBasecardConfig(config: Record<string, unknown>): {
  valid: boolean;
  issues: Array<{ path: string; message: string; code?: string }>;
};
export function collectReferencedResources(config: Record<string, unknown>): string[];
```

正式要求：

- `normalizeBasecardConfig`、`validateBasecardConfig`、`collectReferencedResources` 是正式运行时契约，不可省略。
- 插件描述符只声明一个正式 `cardType`，Host 与 EditingEngine 仅按该正式类型精确匹配。
- `collectReferencedResources` 必须返回卡片根目录相对路径。
- `renderBasecardEditor` 应允许通过正式资源桥接入宿主资源能力。

## 8. 主题与多语言

- 基础卡片运行时主题注入仍由 Host 负责。
- 编辑引擎外层壳层继续使用自己的主题与多语言系统组织界面。
- 基础卡片插件内部应消费正式 `--chips-*` token，不写死应用壳层颜色。
- 封面链路不继承主题与多语言运行时。

## 9. 禁止事项

- 不允许编辑引擎重新维护本地基础卡片插件注册表作为正式路径。
- 不允许编辑引擎自行重写插件规范化、校验或资源收集逻辑。
- 不允许插件直接写卡片文件、直接访问文件系统或私接宿主内部状态。
- 不允许把资源路径记录成依赖当前文档目录的临时相对路径。
- 不允许同时保留“本地源码运行时”和“Host 会话运行时”两套编辑态正式实现。

## 10. 与通用 SDK 链路的边界

- 查看器、第三方宿主和普通应用继续使用 `compositeWindow/editorPanel/coverFrame`。
- 官方编辑引擎编辑态使用 Host 基础卡片会话能力，但自行完成复合卡片装配。
- 两条链路共享同一套基础卡片插件包、正式类型匹配规则、主题 token 与资源规则。
