# 应用插件开发

## 文档定位

本文档说明 `type: app` 插件的正式开发口径。

当前关键变化：

- 应用插件已升级为跨平台界面插件
- 正式容器语义从 `window` 升级为 `surface`
- Manifest 必须声明 `runtime.targets` 与 `ui.surface`

## 1. 应用插件的正式定义

应用插件不是“只能在桌面独立窗口里运行的 HTML 页面”，而是：

- 由 Host 托管
- 通过 `surface` 语义启动
- 可按宿主映射到不同界面容器的跨平台界面插件

当前映射：

- Desktop：`window`
- Web：预留 `route / tab / modal`
- Mobile：预留 `fullscreen / sheet`

## 2. 基本结构

应用插件工程至少包括：

- 工程根 `manifest.yaml`
- 前端入口文件
- 构建产物目录 `dist/`
- 静态资源

正式约束：

- `entry` 应指向构建产物，例如 `dist/index.html`
- 入口页必须声明正式 `Content-Security-Policy`
- 静态资源路径必须支持 Host 以本地入口方式加载

## 3. 必填 Manifest 重点字段

应用插件必须重点声明：

```yaml
type: app
entry: dist/index.html
runtime:
  targets:
    desktop:
      supported: true
    web:
      supported: false
    mobile:
      supported: false
    headless:
      supported: false
ui:
  surface:
    defaultKind: window
    preferredKinds:
      desktop: window
      web: route
      mobile: fullscreen
      headless: window
```

可选但常用字段：

- `ui.window.chrome`
- `ui.launcher`
- `capabilityFallbacks`
- `capabilities`

## 4. 启动链路

当前应用插件正式启动方式有两条：

1. `client.surface.open({ target: { type: "plugin", pluginId } })`
2. `client.plugin.launch(pluginId, launchParams?)`

推荐顺序：

- 新的跨平台调用优先使用 `surface.open(target=plugin)`
- 已有桌面兼容代码可以继续使用 `plugin.launch`

### 启动上下文

应用插件如果要知道“为什么被打开”，必须读取 launch context：

```ts
const launchContext = client.platform.getLaunchContext();
```

或：

```ts
const launchContext = window.chips.platform.getLaunchContext();
```

返回：

```ts
{
  pluginId?: string;
  sessionId?: string;
  sceneId?: string;
  surfaceId?: string;
  kind?: "window" | "tab" | "route" | "modal" | "sheet" | "fullscreen";
  presentation?: {
    title?: string;
    width?: number;
    height?: number;
    resizable?: boolean;
    alwaysOnTop?: boolean;
    visible?: boolean;
  };
  surfaceContext?: {
    surfaceId?: string;
    sceneId: string;
    pluginId?: string;
    sessionId?: string;
    kind: "window" | "tab" | "route" | "modal" | "sheet" | "fullscreen";
    presentation: {
      title?: string;
      width?: number;
      height?: number;
      resizable?: boolean;
      alwaysOnTop?: boolean;
      visible?: boolean;
    };
    launchParams?: Record<string, unknown>;
    documentContext?: {
      documentId: string;
      title?: string;
      url?: string;
    };
    commandContext?: {
      commandId: string;
      source?: string;
      payload?: Record<string, unknown>;
    };
  };
  launchParams: Record<string, unknown>;
}
```

`surfaceContext` 是 App / Scene 运行心智的正式上下文：

- `sceneId` 标识一次由 Host 管理生命周期的界面场景。
- `surfaceId` 标识当前宿主容器。Desktop 当前映射为窗口，但应用代码不得依赖 `BrowserWindow`。
- `kind` 表示公共 surface 语义，实际宿主形态由 PAL 映射。
- `presentation` 表示 Host 解析后的标题、尺寸、可调整性、初始可见性和壳层呈现基线；`visible: false` 只表示容器后台承载，应用仍必须通过 Bridge / SDK 正式链路运行。
- `documentContext` 与 `commandContext` 供后续 Document Scene 和 Commands 链路复用。

常见触发来源：

- `app-shortcut`
- `file-association`
- `chipsdev.run`
- `resource.open`

## 5. Commands 注册与调度

应用插件的菜单、工具栏、快捷键和命令面板统一使用共享层 `@chips/ui` 的**本地命令模型**（`CommandItem`），不依赖 Host 命令运行时。

命令数据模型（`@chips/ui` 导出 `CommandItem`）：

```ts
interface CommandItem {
  id: string;
  title: string;          // 简体中文直写
  shortcut?: string;      // "Mod+O" / "ArrowLeft" 等
  icon?: ReactNode;       // @ant-design/icons 图标实例
  group?: string;         // 命令面板分组名（中文）
  menuId?: string;        // 所属菜单 id（与 MenuBarGroup.menuId 对应）
  toolbarId?: string;     // 所属工具栏 id（AppChrome 按此过滤工具栏项）
  enabled?: boolean;
  visible?: boolean;
  keywords?: string[];    // 命令面板搜索关键词
  run: () => void;
}
```

最小注册示例（`src/commands/app-commands.ts` + `src/commands/useAppCommands.ts`）：

```ts
// app-commands.ts
import type { CommandItem } from "@chips/ui";
import { FolderOpenOutlined } from "@ant-design/icons";

export function createAppCommands(ctx: AppCommandContext): CommandItem[] {
  return [
    { id: "app.open-file", title: "打开文件…", shortcut: "Mod+O", icon: <FolderOpenOutlined />, group: "文件", menuId: "file", toolbarId: "main", run: () => ctx.openFile() },
  ];
}
```

```ts
// useAppCommands.ts
import { useEffect, useMemo } from "react";
import { useCommandRegistry } from "@chips/ui";

export function useAppCommands(): CommandItem[] {
  const { register } = useCommandRegistry();
  const commands = useMemo(() => createAppCommands(ctx), [/* 依赖 */]);
  useEffect(() => {
    register(commands);
  }, [commands, register]);
  return commands;
}
```

渲染与分发：

- `AppChrome`（共享层）内置 macOS 风格菜单栏、工具栏与命令面板挂载点，从 `useCommandRegistry()` 读取命令，触发统一走 `invoke(commandId)`；菜单/工具栏项按 `menuId / toolbarId / visible / enabled` 过滤；
- 快捷键由共享层 `useCommandShortcuts` 分发（`AppChrome` 已内置），格式如 `Mod+O`、`Mod+P`、`ArrowLeft`；在 `input`、`textarea`、`contenteditable` 等可编辑目标中默认保留编辑器自身键盘语义；
- 命令定义文件含图标 JSX 时必须使用 `.tsx` 后缀。

可选链路（保留 SDK 命令注册说明）：

- 若应用命令需要与 Host 命令系统互操作（例如被 Host CLI 执行器投递、被其他插件调用、进入 `cli.commands` 执行链路），仍可通过 `chips-sdk` 的 `client.command.*` 或 `window.chips.command.*` 注册到 Host command registry，并按对应契约声明 `command.read / command.write / command.invoke` 权限；
- Host 校验通过后发出 `command.invoked` 事件，载荷包含 `invocationId / commandId / handlerId / ownerPluginId / ownerSessionId / source / sceneId / surfaceId / documentId / payload`；
- 插件 surface 关闭、插件禁用或卸载时，Host 会清理该 session/plugin 注册的 commands。

官方应用脚手架基线：

- `chips-scaffold-app` 生成的标准应用默认声明 `command.read / command.write / command.invoke`（不再声明 `theme.read / i18n.read`）。
- 模板根组件统一为 `ConfigProvider locale={zhCN} theme={appleTheme} + antd App + ChipsProvider + CommandProvider`（见 5.1 节目录与 `生态共用技术文档/前端基础/03-共享层使用指南.md`）。
- `AppRuntimeProvider / useAppRuntime()` 汇总 `surfaceContext`、`launchContext` 与业务运行时状态，供业务场景统一消费；`sceneId / surfaceId / sessionId / kind / launchParams` 保持来自 Host 的正式 surface 语义。
- 生成工程使用 `src/commands/` 集中维护 `CommandItem` 命令数据与插件侧事件处理；本地中文文案（key → 简体中文 + `formatMessage` 插值）集中在 `src/lib/messages.ts`。
- 模板测试必须证明根组件使用 React 环境与正式入口，命令定义不包含 i18n key、不依赖主题/多语言运行时，不生成私有 `useChipsBridge` 入口，不绕过 SDK 直连 Bridge action，不直接访问 Electron / Node 系统能力。

### 5.1 官方应用脚手架 vNext 工程基线

官方应用脚手架生成的 `type: app` 工程默认采用以下目录心智：

```text
<project>/
├─ manifest.yaml
├─ package.json
├─ chips.config.mjs
├─ config/
├─ src/
│  ├─ App.tsx
│  ├─ main.tsx
│  ├─ app/
│  │  ├─ AppRoot.tsx
│  │  ├─ AppShell.tsx
│  │  └─ scene-registry.ts
│  ├─ scenes/
│  ├─ components/
│  ├─ commands/
│  │  ├─ app-commands.ts
│  │  └─ useAppCommands.ts
│  ├─ runtime/
│  │  ├─ chips-client.ts
│  │  └─ launch-context.ts
│  ├─ lib/
│  │  └─ messages.ts
│  ├─ styles/
│  │  └─ app.css
│  ├─ utils/
│  └─ testing/
│     ├─ mock-environment.ts
│     └─ render-with-antd.tsx
└─ tests/
   ├─ unit/
   └─ e2e/
```

正式边界：

- `src/App.tsx` 只作为轻量 re-export，真实根组件由 `src/app/AppRoot.tsx` 承载。
- `src/app/AppRoot.tsx` 统一为 `ConfigProvider locale={zhCN} theme={appleTheme}` + antd `App` + `ChipsProvider` + `CommandProvider`（均为 `@chips/ui` 提供）；无独立 theme / i18n Provider。
- `src/app/AppShell.tsx` 使用共享层 `AppChrome`（appName + menus + toolbarItems + 命令面板）承载场景内容。
- `src/commands/` 只保存 `CommandItem` 命令数据（简体中文 title、图标、快捷键、分组）与注册逻辑；命令注册、查询、调用与状态更新走共享层 `CommandProvider`。
- `src/lib/messages.ts` 是本地简体中文文案映射模块（key → 中文 + `formatMessage(key, params)` 插值），替代旧 i18n 语言包；工程不再创建 `i18n/`、`theme/` 目录。
- `src/runtime/` 保留 `window.chips.*` 客户端与启动参数解析；`src/testing/render-with-antd.tsx` 提供 antd 包裹的测试渲染辅助。
- `src/preview/` 是开发脚本目录，可以读取本地报告文件；不得把 Node.js 文件系统能力带入应用运行时源码。
- `manifest.yaml` 权限模板为 `command.read / command.write / command.invoke`（按业务需要保留 `resource.read / file.* / platform.read` 等），**不再声明 `theme.read / i18n.read`**。

默认质量脚本：

- `npm run lint`：执行工程源码规范检查。
- `npm run typecheck`：执行 TypeScript 类型检查。
- `npm test`：执行单元测试与工程 smoke。
- `npm run build`：生成 `dist/` 构建产物。
- `npm run validate`：校验 `manifest.yaml`、`runtime.targets`、`ui.surface` 与入口资产。
- `npm run preview:smoke`：执行 `chipsdev-r preview --mode mock --target app --json --out reports/preview/app-preview-smoke.json`，随后由工程内 smoke 脚本校验报告。
- `npm run quality:gate`：执行 `chipsdev-r quality gate --json --out reports/quality/quality-gate.json`，汇总当前工程与生态态势摘要。
- `npm run verify`：按顺序串联 `lint / typecheck / test / build / validate / preview:smoke / quality:gate`，作为生成应用工程的默认本地总门禁。

`reports/` 是生成工程的本地验证产物目录，默认不纳入版本管理。`preview:smoke` 是报告级 smoke，不启动真实 Host UI；真实窗口联调仍使用 `chipsdev-r run`。`quality:gate` 是统一读取型生态态势摘要，不替代各仓库自己的正式验证脚本；`failed` 检查应阻断发布或提交，`warning` 需要开发者结合报告判断。

## 6. 系统入口与快捷方式

应用插件可以通过 `ui.launcher` 声明系统入口元数据。

当前正式链路：

1. 治理应用调用 `plugin.createShortcut`
2. Host 读取 `ui.launcher.displayName` 与 `ui.launcher.icon`
3. Host 通过 PAL / Shell 创建平台入口
4. 用户触发入口后，Host 统一走应用插件正式启动链路

约束：

- 应用插件不得自行创建 `.lnk`、`.app` 或其他系统快捷方式文件

## 7. 命令行入口声明

应用插件可以在 `manifest.yaml` 中声明 `cli.commands`，用于让 Host 动态发现命令行入口。该声明只描述命令路径、参数和应用目标，不把应用插件变成独立 OS CLI 程序。

```yaml
cli:
  commands:
    - commandPath: editor open
      target:
        type: app
        pluginId: chips.app.editor
        commandId: chips.app.editor.open
        surface:
          open: true
          focus: true
          reuse: preferred
      titleKey: editor.cli.open.title
      descriptionKey: editor.cli.open.description
      permissions:
        - file.read
      arguments:
        - name: path
          position: 0
          type: path
          required: true
          mapsTo: path
```

约束：

- `target.type` 必须是 `app`。
- `target.pluginId` 必须等于当前插件 `id`。
- `titleKey / descriptionKey` 是 Host CLI 契约字段（Host 内部解析，Host 服务面仍保留 i18n 能力），与插件前端多语言系统无关；插件侧按脚手架模板写入稳定 key 即可，不再维护插件语言包。
- `permissions` 中的权限必须已经出现在插件顶层 `permissions` 中。
- 后续 CLI 执行器真正执行时仍通过 Host `plugin.launch / surface.open / command.invoke` 链路投递，不直接调用应用源码；声明 `target.commandId` 的执行类命令会使用 `surface.open` 与 `presentation.visible: false` 的后台 surface，普通打开类命令仍可见。
- 应用命令需要像模块 job 一样被 CLI 等待时，应声明 `job.wait: true` 并在顶层权限中声明 `cli.task`。CLI 会创建任务并把 `taskId` 写入 `launchParams.cli.taskId` 与 `command.invoke.context.taskId`；应用插件通过 `client.cliTask.progress/complete/fail/cancel` 上报进度与终态。
- 从 CLI 视角看，应用插件和模块插件都可以声明专用命令、参数映射、输出和进度；差异只在 Host 调度链路不同。应用插件不得为了获得 CLI 能力而额外拆出模块插件。

官方应用脚手架默认生成一条 `cli.commands` 入口，命令路径第一段由项目名派生为只含字母、数字和连字符的安全根段，并避开 Host 固定命令根。默认打开类命令通过 `surface.open` 打开当前应用，并把可选位置参数写入 launch context 的 `cli.payload.subject`；声明 `target.commandId` 的执行类命令由 Host 在后台 surface 中加载应用、等待 command 注册后再投递。安装启用后，该入口会同时进入 `cli.command.list`、传统 `chips <commandPath>` 执行器、TUI 命令树和 shell completion 候选。应用插件仍不是独立 OS CLI 程序。

## 8. 资源处理器

如果应用插件要承担资源查看 / 处理职责，应声明：

```yaml
capabilities:
  - resource-handler:view:image/*
  - file-handler:.png
  - file-handler:.jpg
```

上游应用应统一调用：

```ts
await client.resource.open({
  intent: "view",
  resource: {
    resourceId,
    mimeType,
    title,
    fileName,
  },
});
```

应用侧应从 launch context 中读取：

- `launchParams.resourceOpen`
- `launchParams.resourceOpen.payload`
- 必要时读取 `launchParams.targetPath`

说明：

- `launchParams.resourceOpen.payload` 用于接收上游通过正式 `resource.open` 透传的结构化上下文；
- 资源处理器应用可以据此恢复业务态，例如音乐播放器恢复音乐基础卡片里的封面、歌词和标题，但不得要求上游绕开 `resource.open` 私传插件私有参数。

## 9. 前端栈与 UI 规则

- 官方前端栈统一采用 React 18 + antd v6 + `@ant-design/icons` + `@chips/ui`（共享层），不引入第二套组件库
- 界面文案简体中文直写（见 `生态共用技术文档/前端基础/04-简体中文文案规范.md`）
- 视觉统一为苹果风格单一主题：antd `ConfigProvider theme={appleTheme}`（`@chips/ui`），任何插件禁止私改 token（见 `生态共用技术文档/前端基础/02-统一视觉规范.md`）
- 应用外壳（菜单栏/工具栏/命令面板）、命令模型、`ChipsProvider` 运行时与通用组件（`AppChrome` / `EmbeddedDocumentFrame` / `StateBoundary` / `PanelHeader`）统一来自 `@chips/ui`，禁止在插件内复制共享层实现
- 不得依赖 Electron 私有 API

## 10. 能力调用规则

应用插件访问 Host 能力必须使用：

- `chips-sdk`
- `window.chips.*`

不得：

- 直接访问 Node.js API
- 直接操作原生窗口对象
- 私下约定跨应用启动协议绕过 Host

## 11. 当前开发建议

1. 新工程直接使用官方 Scaffold 生成。
2. 发布前至少执行：
   - `chipsdev-r validate`
   - `chipsdev-r package`
3. 开发运行优先使用 `chipsdev-r run`，由完整 Host 链路托管应用插件。
