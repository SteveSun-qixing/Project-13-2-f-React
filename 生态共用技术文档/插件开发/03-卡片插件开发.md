# 卡片插件开发

## 概述

卡片插件为基础卡片提供渲染和编辑能力。每个基础卡片类型对应一个卡片插件，定义该类型卡片在查看器和编辑器中如何显示和编辑。

## 插件结构

卡片插件包含渲染组件和编辑组件两部分。

vNext 补充要求：每个基础卡片插件包需完整包含以下模块（除播放器、文本编辑器等底层通用模块外）：

- 前端渲染窗口模块
- 编辑器模块
- 插件元信息与配置文件
- 内容模板
- 参数表与填写说明

渲染组件负责在查看器中显示卡片内容。渲染组件是一个HTML模板，包含结构、CSS接口点和JavaScript逻辑。渲染组件运行在iframe中，与主页面隔离。

编辑组件负责在编辑器中编辑卡片内容。编辑组件是一个用户界面，提供参数配置表单。编辑组件运行在编辑器提供的面板中。

## manifest配置

卡片插件的manifest.yaml需要配置特定的字段。

type字段设置为card表示这是一个卡片插件。capabilities字段声明插件支持的卡片类型标识，例如VideoCard表示视频卡片。dependencies字段声明依赖的模块，如视频播放器模块。

## 渲染组件开发

渲染组件开发涉及HTML模板、CSS样式和JavaScript逻辑三个方面。

HTML模板定义卡片的显示结构。模板使用占位符嵌入动态数据，占位符格式为{{variableName}}。模板支持条件渲染和循环渲染。

CSS样式通过CSS类和CSS变量定义。类名遵循BEM命名规范如video-card__play-button。变量使用--前缀如--primary-color。样式使用变量引用主题值，实现主题适配。

JavaScript逻辑处理数据初始化、事件绑定、状态管理等功能。逻辑代码导出初始化函数，接收配置数据和容器元素作为参数。

渲染产物规范：渲染模块应将内容填充到模板后生成完整网页，并交付 iframe 窗口供上层调用。

## 编辑组件开发

编辑组件开发涉及表单设计、数据验证、保存逻辑三个方面。

表单设计根据卡片类型创建对应的输入控件。视频卡片需要文件选择器、封面选择器、字幕管理等功能。表单使用组件库提供的控件构建。

数据验证确保用户输入的合法性。验证规则包括文件类型检查、数值范围检查、必填项检查等。验证失败显示错误提示。

保存逻辑将表单数据转换为卡片配置格式。vNext 冻结口径下，基础卡片编辑链路必须通过 Host `card.getBaseCard / card.renderBaseCardEditor / card.updateBaseCard` 闭环，不再允许应用直接读取插件文件或私有写 `.card` 包内容。

### 基础卡片插件正式导出契约

基础卡片插件入口文件必须对 Host 暴露以下能力：

```ts
export interface BasecardRenderContext {
  container: HTMLElement;
  config: BasecardConfig;
  themeCssText?: string;
}

export interface BasecardEditorContext {
  container: HTMLElement;
  initialConfig: BasecardConfig;
  themeCssText?: string;
  onChange(next: BasecardConfig): void;
}

export interface BasecardNormalizeContext {
  nodeId: string;
  cardType: string;
  rawConfig: Record<string, unknown>;
  rawContentPath: string;
  cardRoot: string;
}

export interface BasecardSerializeContext {
  nodeId: string;
  cardType: string;
  config: BasecardConfig;
  previousRawConfig: Record<string, unknown>;
  rawContentPath: string;
  cardRoot: string;
}

export function renderBasecardView(ctx: BasecardRenderContext): () => void;
export function renderBasecardEditor(ctx: BasecardEditorContext): () => void;
export function normalizeBasecardConfig?(ctx: BasecardNormalizeContext): BasecardConfig | Promise<BasecardConfig>;
export function serializeBasecardConfig?(ctx: BasecardSerializeContext): Record<string, unknown> | Promise<Record<string, unknown>>;
```

约束：

- `renderBasecardView` 与 `renderBasecardEditor` 都必须返回可重复调用的卸载函数。
- `normalizeBasecardConfig` 负责把 `content/*.yaml` 原始结构转换成插件内部编辑模型。
- `serializeBasecardConfig` 负责把编辑模型写回正式卡片配置结构；不得由应用端私自拼 YAML。
- `themeCssText` 由 Host 正式主题系统注入，插件不得绕过主题系统硬编码整套主题。

### 基础卡片编辑器宿主协议

基础卡片编辑器运行在 Host 所有权的 iframe 中，消息协议如下：

- 子 iframe -> 宿主：
  - `chips.basecard-editor:ready`
  - `chips.basecard-editor:config-change`
  - `chips.basecard-editor:config-synced`
  - `chips.basecard-editor:fatal-error`
- 宿主 -> 子 iframe：
  - `chips.basecard-editor:sync-config`

字段口径：

- `config-change` 负载必须包含 `nodeId / cardType / pluginId / config`。
- `ready` 负载必须包含 `protocolVersion`，用于编辑引擎核对协议版本。
- `sync-config` 用于撤销/重做、自动保存回滚、外部规范化回写后的编辑器重同步。

### Host / SDK 正式动作

基础卡片编辑不得自行发明私有保存链路，必须经由以下动作：

- `card.getBaseCard({ cardFile, nodeId })`
- `card.renderBaseCardEditor({ cardFile, nodeId })`
- `card.updateBaseCard({ cardFile, nodeId, config })`

其中：

- `getBaseCard` 返回标准化后的基础卡片配置和插件归属信息；
- `renderBaseCardEditor` 返回可直接挂载到 iframe `srcdoc` 的编辑器文档；
- `updateBaseCard` 由 Host 负责安全解包、写回、更新时间戳并重新打包。

## 配置数据结构

不同类型的卡片有不同的配置数据结构。

视频卡片配置包含video_file视频文件路径、cover_file封面图片路径、subtitles字幕列表、playback_settings播放设置等字段。

图片卡片配置包含image_file图片路径、title标题、alt_text替代文本、fit_mode显示模式等字段。

代码卡片配置包含code代码内容、language编程语言、show_line_numbers是否显示行号、theme高亮主题等字段。

## 资源引用

渲染组件可能需要引用卡片文件中的资源。

相对路径引用卡片内部资源，如{{video_file}}会解析为相对于卡片根目录的路径。

资源URL生成使用Bridge API的方法，将相对路径转换为可访问的URL。

## 生命周期管理

渲染组件有完整的生命周期管理。

初始化阶段创建DOM结构，绑定事件，初始化状态。

更新阶段响应配置变化，刷新显示内容。

销毁阶段清理事件监听，释放资源，防止内存泄漏。

## 主题适配

渲染组件需要适配不同主题。

使用CSS变量引用主题颜色如var(--text-color)。使用类名应用组件样式如.video-card--playing。

主题切换时iframe会自动重新加载，应用新的样式。

## 错误处理

渲染组件需要处理各种错误情况。

资源加载失败显示占位符和错误提示。用户可以重新绑定资源。

配置错误显示友好的错误信息，指导用户修正。

## 性能优化

渲染组件需要关注性能。

懒加载对非关键资源延迟加载。图片使用懒加载属性。

缓存避免重复计算。状态变化使用节流防抖。

## 测试策略

卡片插件需要专项测试。

渲染测试验证各种数据组合的显示效果。编辑测试验证表单功能和验证逻辑。集成测试验证在查看器和编辑器中的表现。

链路补充测试：验证通过 SDK 统一显示接口调用时，基础卡片分发、渲染和复合拼接行为一致。
