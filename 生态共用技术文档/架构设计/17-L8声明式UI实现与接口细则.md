## 1. 定位与边界

- L8（Declarative UI）是 Host 运行时能力，对外提供**语义层**，不提供视觉样式实现。
- L8 只允许依赖 L7（UI Hooks）与 L10（组件语义层），禁止直接访问 Host 服务细节。
- L8 对外关注点：
  - 语义原语
  - 声明树节点模型
  - 组合模式规则
  - 事件与副作用模型

---

## 2. 核心语义原语（公开）

统一语义原语：

- `View`
- `Stack`
- `Grid`
- `Form`
- `List`
- `Section`
- `ScrollView`
- `Text`
- `Image`
- `Media`
- `Table`
- `Navigation`
- `Toolbar`
- `Command`
- `Slot`

语义原语必须只表达布局与交互语义，不得包含颜色、阴影、圆角、字体大小等视觉硬编码参数。

## 3. 声明树节点模型（公开契约）

```ts
interface UINode {
  id: string;
  type:
    | 'View'
    | 'Stack'
    | 'Grid'
    | 'Form'
    | 'List'
    | 'Section'
    | 'ScrollView'
    | 'Text'
    | 'Image'
    | 'Media'
    | 'Table'
    | 'Navigation'
    | 'Toolbar'
    | 'Command'
    | 'Slot'
    | string;
  props?: Record<string, unknown>;
  state?: Record<string, unknown>;
  bindings?: Record<string, string>;
  events?: Record<string, string>;
  themeScope?: string;
  modifiers?: NodeModifiers;
  children?: UINode[];
}

interface NodeModifiers {
  themeScope?: string;
  i18nKey?: string;
  layout?: LayoutModifier;
  accessibility?: AccessibilityModifier;
  focusScope?: string | FocusScopeModifier;
  shortcut?: ShortcutModifier | ShortcutModifier[];
  permission?: PermissionModifier;
  presentation?: PresentationModifier;
  motion?: MotionModifier;
  testId?: string;
}

interface DeclarativeUIDiagnostic {
  nodeId: string;
  type: UINode['type'];
  path: string;
  stage: 'node-normalize' | 'slot-validate' | 'event-bind' | 'effect-dispatch';
  severity: 'error' | 'warning' | 'info';
  code: string;
  message: string;
  suggestion?: string;
  details?: unknown;
}
```

### 3.1 字段约束

- `id`：必填，不能为空。
- `type`：必填，不能为空；推荐优先使用标准语义原语。
- `props`：仅语义属性（布局、结构、行为标识），不得使用视觉值。
- `bindings`：声明数据绑定关系（`field -> source.path`），键和值都必须是非空字符串。
- `events`：仅声明事件语义与 handler 标识映射，禁止内嵌函数或可执行对象。
- `themeScope`：主题解析作用域，不得绕过主题运行时直接注入视觉参数；与 `modifiers.themeScope` 同时存在时必须一致。
- `modifiers`：声明主题、多语言、布局、无障碍、焦点、快捷键、权限、呈现、动效和测试语义；不得承载解析后的视觉值。

### 3.2 Modifier 公开语义

- `themeScope`：主题作用域线索，供 L11 Theme Runtime 解析作用域使用。
- `i18nKey`：多语言文案 key，不直接写死最终本地化文案。
- `layout`：语义布局提示，只允许 `display/direction/alignment/distribution/gap/columns/priority/scrollAxis` 等抽象字段。
- `accessibility`：无障碍语义，承载 `role/label/labelledBy/describedBy/live/current` 等信息。
- `focusScope`：焦点域声明，支持字符串 id 或 `{ id, trap, restore, order }`。
- `shortcut`：快捷键到 command id 的声明绑定，不执行命令实现。
- `permission`：权限动作与资源声明，以及 `hide/disable/readonly/reject` 语义 fallback。
- `presentation`：窗口、路由、modal、sheet、fullscreen 等呈现语义。
- `motion`：动效 preset 与阶段语义，必须引用语义 preset，不写具体 CSS 动画值。
- `testId`：稳定测试标识，仅用于测试与诊断。

### 3.3 视觉硬编码禁区

L8 节点的 `props` 不允许出现 `style/css/sx/className/color/background/backgroundColor/borderRadius/shadow/fontSize/width/height/margin/padding` 等视觉或尺寸硬编码字段。视觉表达必须进入组件 contract、主题 token 和 L11 Theme Runtime。

## 4. 组合模式规范（Vercel 组合模式）

### 4.1 必须遵守

- 复杂节点优先 Compound Components。
- 通过显式 slot 组合结构，不通过 boolean 模式控制多变体。
- Provider 负责状态实现，L8 只消费注入状态与动作。

### 4.2 禁止行为

- 禁止 boolean 模式扩张（如 `isCompact/isInline/showFooter` 组合）。
- 禁止 slot 未声明即注入节点。
- 禁止在组合层引入视觉硬编码字段。

### 4.3 Slot Schema（公开契约）

复杂组件必须通过显式 slot schema 描述结构：

```ts
interface SlotSchemaEntry {
  type?: UINode['type'] | UINode['type'][];
  required?: boolean;
  multiple?: boolean;
  part?: string;
  role?: string;
  description?: string;
}

type SlotSchema = Record<string, SlotSchemaEntry>;
```

校验规则：

- `required=true` 的 slot 必须传入。
- `multiple=false` 的 slot 只能传入一个节点。
- `type` 声明存在时，slot 节点 `type` 必须命中允许列表。
- 未在 schema 中声明的 slot 必须拒绝。
- `part` 对应组件库 `data-part`，`role` 对应无障碍语义线索；L8 只验证契约，不直接渲染 DOM。

### 4.4 标准复杂组件 Slot Schema（公开基线）

- `Dialog`：`trigger/content/header/body/footer/actions/close`
- `Popover`：`trigger/content/arrow`
- `Tabs`：`list/trigger/panel`
- `Menu`：`trigger/content/item/group/separator`
- `Select`：`trigger/content/value/option`
- `Form`：`section/field/label/control/error/hint`
- `DataGrid`：`toolbar/header/row/cell/pagination`
- `Tree`：`item/branch/leaf/disclosure/label/group`
- `CommandPalette`：`input/list/group/item/shortcut/status`
- `NavigationSplitView`：`sidebar/content/detail`

后续新增复杂组件必须先在 slot schema 中冻结结构，再进入组件库实现和主题 contract。

`Form` 的正式 slot 中 `field` 和 `control` 为必填可重复项，`label/error/hint` 为可选可重复项，`section` 为可选可重复项。`hint` 是唯一正式说明文本 slot，旧 `helper` 不属于 L8 公开 schema；声明树传入未声明 slot 必须产生 `DECLARATIVE_UI_SLOT_UNDEFINED` 诊断。

`DataGrid` 的正式 slot 中 `header` 为必填单例，`row` 和 `cell` 为必填可重复项，`toolbar` 与 `pagination` 为可选单例。`toolbar` 与 `pagination` 只接受 `Toolbar` 节点，`header/row/cell` 只接受 `Table` 节点；`table` 不属于公开 slot，声明树传入 `slots.table` 必须产生 `DECLARATIVE_UI_SLOT_UNDEFINED` 诊断。L8 仅校验结构契约，组件库 L10 负责将 `Root / Toolbar / Header / Row / Cell / Pagination` 映射到 `data-grid` 的公开 part 与实际 `role="grid"` 语义。

`Tree` 的正式 slot 中 `item / branch / leaf / disclosure / label / group` 均为可选可重复项；`item` 接受 `View / Section`，`branch` 接受 `View / Section`，`leaf` 接受 `View / Text / Section`，`disclosure` 只接受 `Command`，`label` 只接受 `Text`，`group` 接受 `List / Section`。`node / toggle / children` 不属于公开 slot，声明树传入这些旧 slot 必须产生 `DECLARATIVE_UI_SLOT_UNDEFINED` 诊断。L8 仅校验结构契约，组件库 L10 负责将 `Root / Item / Branch / Leaf / Disclosure` 映射到 `tree` 的公开 part、`role="tree/treeitem/group"` 语义、展开折叠和 roving focus 行为。

`CommandPalette` 的正式 slot 中 `input` 与 `list` 必填且单例，`group / item / shortcut` 可重复，`status` 可选单例；`input` 只接受 `Text`，`list` 只接受 `List`，`group` 接受 `List / Section`，`item` 只接受 `Command`，`shortcut/status` 只接受 `Text`。`search / result` 不属于公开 slot，声明树传入这些旧 slot 必须产生 `DECLARATIVE_UI_SLOT_UNDEFINED` 诊断。L8 仅校验结构契约，组件库 L10 负责将 `Root / Input / List / Item / Group` 映射到 `command-palette` 的公开 part、`combobox/listbox/option/group` 语义、键盘高亮与 `source="palette"` 命令触发行为。

`NavigationSplitView` 的正式 slot 中 `sidebar` 与 `detail` 必填且单例，`content` 可选单例；`sidebar` 只接受 `Navigation`，`content` 接受 `View / Stack / Section / List`，`detail` 接受 `View / Stack / Section`。`primary / secondary` 属于 `ChipsSplitView` 布局原语口径，不属于 `NavigationSplitView` 公开 slot，声明树传入这些旧 slot 必须产生 `DECLARATIVE_UI_SLOT_UNDEFINED` 诊断。L8 仅校验结构契约，组件库 L10 负责将 `Root / Sidebar / Content / Detail` 映射到 `navigation-split-view` 的公开 part 与 `group/navigation/region` 语义。

## 5. 事件与副作用模型（公开契约）

### 5.1 事件绑定

- `events` 仅声明语义事件（例如 `onSubmit`、`onOpenFile`）。
- 事件执行器在页面域注册，不在声明树中嵌入可执行逻辑。
- `validateNodeEventBindings` 类诊断能力必须能在不执行 handler 的前提下输出结构化事件绑定诊断。

### 5.2 副作用分级

- `ui-effect`：滚动、聚焦、过渡等 UI 层副作用。
- `runtime-effect`：调用 Runtime Client 的系统能力副作用。
- `telemetry-effect`：日志、指标、埋点副作用。

### 5.3 强制规则

- 禁止在渲染阶段直接触发 `runtime-effect`。
- `runtime-effect` 只能在事件回调或 commit 后调度执行。

## 7. 质量门禁（生态共用）

- L8 单测必须覆盖：
  - 原语创建
  - modifier 创建、归一化与非法结构拒绝
  - 节点模型校验
  - 组合模式约束
  - slot schema 必填、单例、可重复、类型和未声明 slot 诊断
  - 事件绑定与派发
  - 副作用分级
  - 渲染阶段 runtime-effect 禁止规则
- 任何接入仓必须保证：
  - `build` 通过
  - L8 相关测试通过
  - 文档与实现一致

---

## 8. 与其他层协同

- 与 L7：事件处理器内通过 Runtime Client 调用系统能力。
- 与 L9：L9 负责 Normalize/Validate/Resolve/Compute/Commit/Dispatch，L8 负责声明语义输入。
- 与 L11：L8 通过 `themeScope` 提供主题作用域线索，不直接处理 token 合并算法。

## 9. 实施建议

- 新项目接入时先落地节点契约与组合模式，再接入业务事件与效果分发。
- 任何生态共用能力变更，先更新本文件，再更新具体仓实现。
