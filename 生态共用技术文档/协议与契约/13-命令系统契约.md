# 命令系统契约

## 1. 定位

命令系统是 Host 统一管理运行时动作的公共契约。菜单、工具栏、快捷键、命令面板、上下文菜单都必须消费同一条 command 记录。

命令系统不承载业务 handler 函数。插件通过 SDK 在本地维护 handler，Host 只保存可序列化 metadata、owner、scope、permission、placement 与状态。

## 2. Command Schema

```ts
type CommandSource = "menu" | "toolbar" | "shortcut" | "palette" | "context-menu" | "api";
type CommandScopeKind = "global" | "app" | "scene" | "surface" | "document";

interface CommandDefinition {
  commandId: string;
  titleKey: string;
  descriptionKey?: string;
  ariaLabelKey?: string;
  icon?: IconDescriptor;
  shortcut?: CommandShortcut | CommandShortcut[];
  scope?: CommandScope;
  permission?: string | string[];
  enabledWhen?: boolean | CommandCondition;
  visibleWhen?: boolean | CommandCondition;
  checkedWhen?: boolean | CommandCondition;
  handlerId: string;
  menuPlacement?: CommandMenuPlacement[];
  toolbarPlacement?: CommandToolbarPlacement[];
  paletteKeywords?: string[];
  state?: CommandState;
}
```

`CommandState` 允许 `enabled / visible / checked / busy / value / disabledReasonKey / hiddenReasonKey` 等状态字段。当前 Host 还接受 `state.reasonKey` 作为历史输入别名，并归一为 `disabledReasonKey`；新文档和新代码应优先写 `disabledReasonKey` 或 `hiddenReasonKey`。

强制规则：

- `commandId` 必须稳定且全生态唯一，推荐使用 `插件ID.动作名`。
- `titleKey` 必填，`descriptionKey / ariaLabelKey` 可选但只能是 i18n key。
- 禁止 `title / description / ariaLabel / label` 原始文案字段。
- `icon` 必须是运行时 `IconDescriptor`，最终由 `ChipsIcon` 渲染。
- `handlerId` 是插件侧处理器标识，Host 不接收函数。
- `permission` 是执行 command 所需权限，注册方插件必须在 manifest permissions 中声明。

## 3. Scope

```ts
interface CommandScope {
  kind: "global" | "app" | "scene" | "surface" | "document";
  appId?: string;
  sceneId?: string;
  surfaceId?: string;
  documentId?: string;
}
```

scope 规则：

- `app`：普通应用插件默认 scope，`appId` 必须等于 owner plugin id。
- `scene`：必须携带 `sceneId`。
- `surface`：必须携带 `surfaceId`。
- `document`：必须携带 `documentId`。
- `global`：只允许 Host 或拥有 `command.manage` 的调用方注册。

## 4. Conditions

`enabledWhen / visibleWhen / checkedWhen` 只接受：

- boolean；
- 结构化 condition：

```ts
interface CommandCondition {
  key: string;
  equals?: unknown;
  notEquals?: unknown;
  in?: unknown[];
  truthy?: boolean;
}
```

不得引入字符串表达式、脚本表达式或第三方表达式语言。后续 State / Environment / Binding 接入时继续扩展结构化 condition，而不是替换模型。

## 5. Host Actions

Host command service 提供：

- `command.register`
- `command.unregister`
- `command.get`
- `command.list`
- `command.setState`
- `command.invoke`

服务级权限：

- `command.read`：查询 command。
- `command.write`：注册、注销和更新自己拥有的 command。
- `command.invoke`：调用 command。
- `command.manage`：跨 owner 管理或注册全局 command。

`command.invoke` 必须执行以下校验：

1. command 是否存在；
2. 调用上下文是否匹配 scope；
3. 调用方是否具备 `command.invoke`；
4. 调用方是否具备 command-specific permissions；
5. command 是否 visible；
6. command 是否 enabled。

## 6. Events

标准事件：

- `command.registered`
- `command.unregistered`
- `command.changed`
- `command.invoked`

`command.invoked` 载荷至少包含：

```ts
{
  invocationId: string;
  commandId: string;
  command: CommandView;
  handlerId: string;
  ownerPluginId?: string;
  ownerSessionId?: string;
  source: CommandSource;
  sceneId?: string;
  surfaceId?: string;
  documentId?: string;
  payload?: Record<string, unknown>;
}
```

事件命名必须采用点语义。

## 7. 生命周期清理

Host 必须在以下场景清理对应 commands 与 shortcut 映射：

- owner surface 关闭；
- owner plugin session 停止；
- owner app 插件禁用；
- owner app 插件卸载。

## 8. 后续消费入口

组件库、脚手架和官方应用后续必须基于本契约消费命令：

- Toolbar / Menu / CommandPalette 从 `command.list` 读取 command；
- 快捷键触发走 `command.invoke`；
- command `shortcut` 属于当前 Host 托管 surface 的窗口内命令入口，不等同于 `platform.shortcut*` 的系统全局快捷键；
- Host 派发 command `shortcut` 时必须使用当前聚焦 surface 的 `pluginId / sceneId / surfaceId / documentId` 上下文，并重新经过 `command.invoke` 的 scope、权限、visible、enabled 校验；
- `input`、`textarea`、`contenteditable`、富文本 iframe 与 IME 组合输入等编辑上下文默认保留文本编辑语义，command `shortcut` 不得在这些上下文中穿透触发，除非未来命令模型显式声明可接管编辑上下文；
- 新应用模板不得让菜单或工具栏直接绑定业务函数；
- 文案和图标分别走 i18n 与 `ChipsIcon`。

## 9. CLI 命令发现契约

应用插件和模块插件可以在 `manifest.yaml` 中声明 `cli.commands`，Host 负责解析这些声明并暴露只读发现路由。CLI 命令发现契约不替代运行时 command registry；它用于把插件能力登记为命令行入口，真实执行仍必须回到 Host 正式服务。

命令路径保留规则：

- Host 固定命令根包括 `help / host / start / stop / status / config / logs / theme / plugin / update / doctor / open / completion`。
- 插件 `cli.commands[].commandPath` 第一段不得使用上述固定命令根。
- `chipsdev-r validate / package` 与 Host `plugin.install` 都必须拒绝占用固定命令根的插件命令。

Host 已落地路由：

- `cli.command.list`
- `cli.command.get`
- `cli.command.resolve`

查询输入：

```ts
interface CliCommandQueryOptions {
  commandPath?: string | string[];
  commandId?: string;
  pluginId?: string;
  targetType?: "app" | "module";
  includeDisabled?: boolean;
}
```

索引输出：

```ts
interface CliCommandIndex {
  schemaVersion: 1;
  version: string;
  updatedAt: string;
  workspacePath: string;
  commands: CliCommandView[];
  conflicts: CliCommandConflict[];
}
```

命令记录：

```ts
interface CliCommandView {
  commandId: string;
  commandPath: string[];
  commandPathKey: string;
  owner: {
    pluginId: string;
    pluginType: "app" | "module";
    pluginName: string;
    pluginVersion: string;
    source?: "official" | "third-party" | "local";
  };
  enabled: boolean;
  declaration: CliCommandDeclaration;
  conflicts: CliCommandConflict[];
}
```

冲突规则：

- 两个或更多已启用命令拥有相同 `commandPathKey` 时形成冲突。
- `cli.command.resolve` 在没有 `pluginId` 或 `commandId` 限定时不会自动选择冲突命令。
- `cli.command.get` 遇到多个匹配命令时返回 `CLI_COMMAND_CONFLICT`。
- 禁用插件的命令默认不参与可执行结果；治理视图可用 `includeDisabled: true` 查询。
- 传统命令行执行器按最长 `commandPath` 前缀匹配；冲突路径必须由 `--plugin <pluginId>` 或后续治理配置显式消解。
- `chips completion <bash|zsh|fish>` 输出 shell 补全脚本；补全脚本调用 `chips __complete ...` 获取候选。`chipsdev-r completion <bash|zsh|fish>` 委托 Host CLI 生成注册到 `chipsdev-r` 的脚本；该脚本调用 `chipsdev-r __complete ...`，由 SDK 先解析开发工作区再转发 Host CLI 私有补全入口。`__complete` 是 shell completion 私有入口，只返回换行分隔候选，不作为插件命令根开放。
- shell completion 每次补全都通过 Host `cli.command.list` 读取当前已启用插件命令，并同时合并 Host 固定命令树；插件安装、启用、禁用或卸载后，下一次补全请求即反映最新索引，不要求重装补全脚本或重启 Host。

SDK 封装：

```ts
const client = createClient();

const { index, commands } = await client.cliCommand.list({
  targetType: "app",
});

const resolved = await client.cliCommand.resolve({
  commandPath: "icon generate",
  pluginId: "chips.module.icon",
});
```

应用插件在 CLI 任务执行期间可通过 SDK `client.cliTask.*` 上报任务状态：

```ts
await client.cliTask.progress(taskId, { stage: "writing", percent: 75 });
await client.cliTask.complete(taskId, { files: ["/tmp/icon.png"] });
```

执行边界：

- 模块目标执行必须走 `module.invoke` 和 `module.job.*`。
- 应用目标执行必须走 `plugin.launch / surface.open / command.invoke`。声明 `target.commandId` 的执行类应用命令由 Host 创建后台 surface（`presentation.visible: false`）承载应用运行时，等待 SDK/Bridge 注册 command 后再投递，不直接显示或聚焦窗口。从 CLI 视角看，应用插件与模块插件都可以声明参数、输出、进度和取消策略；差异只在 Host 调度的正式目标链路不同，不代表模块拥有额外 CLI 特权。
- 应用目标若声明 `job.wait` 未显式为 `false` 且提供 `target.commandId`，CLI 会在打开应用 surface 前创建 `cli.task`，把 `taskId` 写入 launch params 与 `command.invoke.context`，随后轮询 `cli.task.get` 直到 `completed / failed / cancelled`。
- CLI 和 TUI 不得直接 import 插件代码，不得绕过 Host 读取模块实现。
- CLI 参数映射结果写入目标 payload；`path / jsonFile / textFile` 等文件参数在 CLI 层解析并执行存在性、类型、扩展名和按需创建校验。
- `path.role: output` 是输出路径的正式声明，`path.overwrite` 支持 `fail / overwrite / rename / skip`。输出冲突默认不得隐式覆盖；`rename` 必须在调用目标前改写 payload 中的路径，`skip` 必须不调用插件目标并返回结构化 skipped 结果。
- `textFile` 的 `batch.format: lines` 与 `jsonFile` 的 `batch.format: json-array` 是当前正式批量输入格式；批量项可以通过 `batch.itemType: path` 与 `batch.itemPath` 逐项解析和校验。
- 成功输出默认是结构化 JSON；命令可声明 `output.mode: human` 作为默认人读摘要展示，用户传入 `--json` 时必须强制输出完整机器可读 JSON。
- `output.artifacts` 是结果对象内的点分路径列表，human 输出可用它提取生成路径或关键产物；若未声明 artifacts，human 输出只能对 `output` 做通用摘要，不得猜测插件私有字段语义。
- 文件路径错误、输出冲突和批量输入错误分别使用 `CLI_PATH_*`、`CLI_OUTPUT_*`、`CLI_BATCH_INVALID` 等结构化错误码，脚本集成应按错误码而不是错误文案判断。
- 模块 job 与应用 cli task 终态统一按 `completed / failed / cancelled` 处理；失败与取消应映射为结构化 CLI 错误和非零退出码。
- CLI 等待模块 job 或应用 cli task 时必须支持展示 `progress`。当进度载荷包含 `percent` 时，传统 CLI 应在人可读进度输出中展示百分比进度条；当进度载荷包含 `stage` 时，应展示当前阶段。进度输出必须写入 stderr，stdout 保持最终结构化结果，避免破坏脚本解析。
- CLI / TUI 操作必须写入 Host 结构化日志，覆盖内建命令、插件命令、TUI 执行和 shell completion 请求；当前正式日志记录为 `namespace: "cli"`、`action: "operation.execute"`，`metadata.source` 区分 `cli / tui / completion`，并记录脱敏后的命令行、token、工作区类型、退出码、命令 ID、命令路径、目标类型、耗时和错误码。一次用户操作只应产生一个主操作记录；插件命令失败时应保留插件上下文记录，避免再追加无插件上下文的顶层失败记录。TUI 不维护历史命令搜索或回放文件。

## 10. 组件库消费契约

组件库命令消费层是 Host command registry 的无头 UI 适配层，不是第二套 command registry。

正式消费入口：

- `ChipsCommandProvider`：接收 `CommandAdapter`、静态 command views、i18n adapter 与默认查询上下文。
- `createCommandAdapter(client)`：把 SDK `client.command` 转为组件库消费的 adapter。
- `ChipsToolbar / ChipsToolbarItem`：消费 `toolbarPlacement`，触发时必须以 `source="toolbar"` 调用 `command.invoke`。
- `ChipsMenuBar`：消费 `menuPlacement`，触发时必须以 `source="menu"` 调用 `command.invoke`。
- `ChipsContextMenu`：消费 `menuPlacement`，触发时必须以 `source="context-menu"` 调用 `command.invoke`。
- `ChipsCommandPalette`：消费 command views 时必须以 `source="palette"` 调用 `command.invoke`。
- `ChipsShortcut`：只负责展示 accelerator；真实快捷键注册、权限校验和触发仍由 Host 负责。

前端消费规则：

- 组件库只接受 `CommandView` 或同形对象，不接受业务函数作为正式 command handler。
- `titleKey / descriptionKey / ariaLabelKey` 通过注入的 i18n adapter 解析；组件不得把 raw title 写回 command schema。
- 图标必须传递 `IconDescriptor` 并由 `ChipsIcon` 渲染。
- hidden command 默认不渲染；disabled/checked 状态来自 `state` 与 `diagnostic`。
- `menuPlacement / toolbarPlacement` 的分组和排序由组件库纯函数派生，Host 仍是 command 元数据与调度的唯一事实来源。
