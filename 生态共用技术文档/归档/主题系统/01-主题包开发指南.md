# 主题包开发指南

## 概述

主题包是定义生态视觉外观的插件类型。主题包通过 CSS 变量和类名定义界面的颜色、字体、圆角、阴影、动画等视觉属性。主题包可以完全改变软件的视觉风格而不影响功能逻辑。

## 文件结构

主题包源码工程包含以下组成部分：

```
theme-package/
├── manifest.yaml                   # 主题包配置文件
├── tokens/                         # 设计令牌目录
│   ├── ref.json                    # 原始值 Token
│   ├── sys.json                    # 语义值 Token
│   ├── motion.json                 # 动效 Token
│   ├── layout.json                 # 布局 Token
│   └── comp/                       # 组件级 Token
│       ├── button.json
│       ├── input.json
│       └── ...
├── styles/                          # 主题 CSS 源码
│   ├── base.css                    # 全局基线与派生变量
│   ├── motions.css                 # 动效 CSS
│   └── components/                 # 组件样式目录
│       ├── button.css              # 按钮的完整视觉实现
│       ├── input.css               # 输入框
│       ├── overlays.css            # 弹窗、浮层、命令消费组件
│       └── ...                     # 所有组件
├── src/                            # 构建与校验脚本
│   ├── build-tokens.ts
│   ├── build-contracts.ts
│   ├── build-css.ts
│   └── validate-theme.ts
├── dist/                           # Host Theme Runtime 消费的正式产物
│   ├── tokens.json
│   ├── theme.css
│   └── icons/variablefont/*.woff2
├── icons/                          # 图标资源目录
│   ├── README.md                   # 图标资源说明
│   ├── SOURCE.md                   # 来源追溯
│   └── variablefont/               # Material Symbols variable font
│       ├── MaterialSymbolsOutlined[FILL,GRAD,opsz,wght].woff2
│       ├── MaterialSymbolsRounded[FILL,GRAD,opsz,wght].woff2
│       └── MaterialSymbolsSharp[FILL,GRAD,opsz,wght].woff2
├── decorations/                    # 装饰资源目录
│   ├── backgrounds/                # 背景图片/纹理
│   ├── patterns/                   # 装饰图案
│   └── cursors/                    # 自定义光标（可选）
├── fonts/                         # 自带 UI 字体（可选；未声明字体文件时不进入运行时包）
│   ├── Inter-Regular.woff2
│   └── Inter-Bold.woff2
├── contracts/                      # 契约目录
│   ├── theme-interface.contract.json  # 主题接口契约
│   └── theme-min-functional-set.json  # 最小功能集声明
└── preview/                        # 预览资源目录
    ├── preview.png                # 主题预览截图
    └── preview.html               # 预览页面（可选）
```

正式 `.cpk` 包只发布 Host 运行时需要读取的文件，不把源码 `tokens/`、`styles/`、`src/` 当作安装期契约。当前正式打包范围以 `manifest.yaml`、`dist/` 和 manifest 显式引用的资源为准：

```text
theme.cpk/
├── manifest.yaml
├── contracts/
│   ├── theme-interface.contract.json
│   └── theme-min-functional-set.json
└── dist/
    ├── tokens.json
    ├── theme.css
    └── icons/variablefont/*.woff2
```

## manifest 配置

主题包的 manifest.yaml 有特定的配置要求：

```yaml
schemaVersion: "1.0.0"
id: theme.theme.chips-official-default-theme
name: 薯片官方 · 默认主题
type: theme
entry:
  tokens: dist/tokens.json
  themeCss: dist/theme.css
themeId: chips-official.default-theme  # 主题唯一标识符
displayName: 默认主题                  # 显示名称
version: 1.0.0                      # 语义化版本
isDefault: false                    # 是否为默认主题
parentTheme: ""                     # 可选，父主题实现继承
ui:
  layout:
    owner: page
    unit: cpx                      # 逻辑尺寸单位
    baseWidth: 1024                 # 基准宽度
    contract: ./contracts/theme-interface.contract.json
    minFunctionalSet: ./contracts/theme-min-functional-set.json
```

其中：

- `entry.tokens` 必须指向构建产物 `dist/tokens.json`；
- `entry.themeCss` 必须指向构建产物 `dist/theme.css`；
- Host Theme Runtime 只消费 `dist/` 中的正式产物，不直接读取源目录 `tokens/` 或 `styles/`。
- `ui.layout.contract` 与 `ui.layout.minFunctionalSet` 必须指向随主题包发布的契约产物，Host、CLI 和质量门禁按这些路径读取主题接口与最小功能集。

### 主题包语义约束

> **重要约束**：一个主题包仅承载一种外观，不在包内区分白天/夜间、light/dark 或其他模式标签。外观切换通过切换 `themeId` 到另一个主题包完成。

### 主题 Contract 基线

正式主题包必须声明并覆盖当前组件库发布的全部正式 component contract。当前公共来源为：

- `Chips-ComponentLibrary/packages/theme-contracts/contracts/components/*.contract.json`
- `@chips/theme-contracts` validator/generator API：`loadComponentContracts`、`buildThemeInterfaceContract`、`buildThemeMinFunctionalSet`、`compareThemeInterfaceContract`、`compareThemeMinFunctionalSet`、`buildThemeContractView`、`buildComponentContractView`、`validateComponentContract`

主题包的 `contracts/theme-interface.contract.json` 使用 `schemaVersion/contractVersion/components[]` 结构；组件条目统一使用 `component/scope/parts/states/requiredTokens/optionalTokens`。历史 `tokens` 字段只作为旧 contract 输入兼容，新增主题包 contract 必须写 `requiredTokens`。

组件 contract 中的 `motionConstraints[].tokenKeys` 属于主题运行时硬性依赖。`@chips/theme-contracts` 在生成 `theme-interface.contract.json`、构建 `ThemeContractView` 和执行 `validateComponentContract` 时，会把这些 token key 合并进 required token 集合；缺失时必须输出阻断级 `THEME_REQUIRED_TOKEN_MISSING`。主题包不得只复制 `motionConstraints` 字段而不提供对应 `chips.motion.*` 或组件级 motion token。

主题包的 `contracts/theme-min-functional-set.json` 必须声明当前主题包承诺覆盖的 `requiredComponents`。官方基础主题在 Host contract guard 接入阶段必须覆盖组件库当前全部正式组件，避免 `theme.apply` 与 `theme.resolve` 因 required token 缺失进入 blocked 状态。

官方主题包的 `contracts/theme-interface.contract.json` 必须由 `@chips/theme-contracts` 从 `Chips-ComponentLibrary/packages/theme-contracts/contracts/components/*.contract.json` 生成。该文件是 Host 安装运行时读取的发布产物，不是人工维护源；等值字段包括 `component` 集合、`scope`、`parts`、`states`、`requiredTokens`、`optionalTokens`、`a11yConstraints`、`motionConstraints` 与 iframe 附加契约。官方主题包不得多声明组件库未公开的 part，也不得保留已归档的历史 part/token 口径；视觉升级只能在不改变这些公共契约字段的前提下扩展 token 值和 CSS 实现。

主题包校验必须生成与 Host、SDK、组件库一致的 `ThemeContractView`、`ThemeDiagnostic` 与 `ThemeDiagnosticSummary`。缺失 required token 使用 `THEME_REQUIRED_TOKEN_MISSING`，并定位到 `component/part/state/tokenKey/layer`。

## 设计令牌（Token 体系）

设计令牌是主题的基础构建块，采用 `ref/sys/comp/motion/layout` 五层架构设计。Token 定义使用 JSON 格式，构建后生成 `dist/tokens.json`，由 Host Theme Runtime 的 `theme.resolve` 解析并注入 CSS variables。

> **注意**：薯片生态采用**自管理前端架构**，组件库只负责功能逻辑、结构和布局，完全不包含样式。所有视觉表现由主题包通过 CSS 变量提供。

### Token 引用规则

Token 引用使用 `{chips.<layer>...}` 完整路径。Host Theme Runtime 会按 `ref -> sys -> motion/layout -> comp` 顺序递归解析引用，并允许同一层内部引用本层已经定义或稍后定义的 token；例如 `chips.sys.icon.color-accent` 可以引用同一主题内的 `chips.sys.color.primary`。

跨层引用必须遵循单向依赖：

- `ref` 只能引用 `ref` 本层 token；
- `sys` 可以引用 `ref` 与 `sys` 本层 token；
- `motion` 与 `layout` 可以引用 `ref`、`sys` 与本层 token；
- `comp` 可以引用 `ref`、`sys`、`motion`、`layout` 与 `comp` 本层 token。

循环引用会被视为主题错误并以 `THEME_TOKEN_CYCLE` 阻断解析；引用不存在的 token 会以 `THEME_TOKEN_MISSING` 阻断解析。主题包不得依赖调用方、组件库或 CSS fallback 来补齐这些错误引用。

### Token 文件结构

```
tokens/
├── ref.json          # 原始值
├── sys.json          # 语义值
├── motion.json       # 动效 Token
├── layout.json       # 布局 Token
└── comp/             # 组件级 Token
    ├── button.json
    ├── input.json
    └── ...
```

### 运行时产物结构

主题工程的源文件需要经过构建，最终运行时只使用以下正式产物：

```text
dist/
├── tokens.json                  # Theme Runtime 消费的 ref/sys/comp/motion/layout 五层结构
├── theme.css                    # 注入插件窗口与卡片渲染链路的完整主题 CSS
└── icons/variablefont/*.woff2   # 正式运行时图标字体产物
```

### 运行时图标资源要求

- 主题包运行时 UI 图标统一采用 Material Symbols variable font；
- 不再维护 `icons.css + svg` 作为正式主链路；
- `icons/variablefont/*.woff2` 必须进入版本控制，并在构建时复制到 `dist/icons/variablefont/`；
- `dist/theme.css` 必须注入三套 `@font-face`，供 `ChipsIcon` 按 `data-icon-style` 消费；
- 每次替换字体文件后，必须同步更新 `icons/SOURCE.md`。

### 运行时 UI 字体资源要求

- 第一版官方主题已落地的强制字体资产链路是 Material Symbols 图标字体；UI 文本字体可以先使用系统字体或主题 CSS 中声明的字体族回退链。
- 主题包只有在 `fonts/` 中真实包含字体文件，并由 `dist/theme.css` 通过 `@font-face` 声明时，才算发布了对应 UI 字体资产。
- 公共字体设计目标可以使用 Roboto Flex、Noto Sans、Noto Sans SC/TC/JP/KR 与 Noto Sans Mono，但不得把尚未随主题包发布的字体文件写成已经安装可用的运行时依赖。

### 构建产物

官方主题包使用本包 `src/build-tokens.ts` 将 `tokens/ref.json/sys.json/motion.json/layout.json/comp/*.json` 合并为 `dist/tokens.json`。Theme Runtime 在 `theme.resolve` 中解析 `{chips.ref.*}`、`{chips.sys.*}`、`{chips.motion.*}`、`{chips.layout.*}` 引用，并把扁平 token 视图注入为 `--chips-*` CSS variables。

主题包不得要求调用方直接读取源 token 目录，也不得把 `dist/theme.css` 当成自包含 token 变量表；正式运行时消费模型是 `dist/theme.css + theme.resolve(tokens)`。

## 组件样式

组件样式定义各个 UI 组件的视觉表现，使用 CSS 变量引用 token。

> **设计理念**：薯片生态采用**无头组件库**架构。组件库（如 `@chips/component-library`）只负责功能逻辑、结构和布局，完全不包含样式。所有视觉表现由主题包通过 CSS 类名和 CSS 变量提供。

### 组件样式示例

主题包中的按钮样式定义：

```css
[data-scope="button"][data-part="root"] {
  background-color: var(--chips-comp-button-root-surface-idle);
  color: var(--chips-comp-button-label-color-idle);
  border: none;
  border-radius: var(--chips-comp-button-root-radius);
  padding: var(--chips-ref-space-2) var(--chips-ref-space-3);
  font: inherit;
  transition: background-color var(--chips-motion-duration-fast) var(--chips-motion-easing-standard);
}

[data-scope="button"][data-part="root"][data-state="focus"],
[data-scope="button"][data-part="root"]:focus-visible {
  outline: var(--chips-layout-focus-outline-width, 1px) solid var(--chips-comp-button-focus-outline);
  outline-offset: var(--chips-layout-focus-outline-offset, 2px);
}
```

### CSS 变量命名规范

主题包中的 CSS 变量必须遵循以下命名规范：

```css
:root {
  /* ref 层 */
  --chips-ref-color-blue-500: #2563eb;
  --chips-ref-color-gray-0: #ffffff;

  /* sys 层 */
  --chips-sys-color-primary: var(--chips-ref-color-blue-500);
  --chips-sys-color-surface: var(--chips-ref-color-gray-0);

  /* comp 层 */
  --chips-comp-button-root-radius: var(--chips-ref-radius-md);
  --chips-comp-button-root-surface-idle: var(--chips-sys-color-primary);
  --chips-comp-button-label-color-idle: #ffffff;

  /* motion/layout 层 */
  --chips-motion-duration-fast: 150ms;
  --chips-layout-focus-outline-width: 1px;
}
```

### 契约挂点

组件样式必须包含以下数据属性以支持主题契约校验：

```css
[data-scope="button"][data-part="root"][data-state="idle"] {
  background-color: var(--chips-comp-button-root-surface-idle);
}
```

## 动画效果

动画定义组件的过渡和动效，使用 `styles/motions.css` 与 `chips.motion.*` token：

```css
/* 过渡效果 */
.chips-overlay-enter,
.chips-overlay-exit,
[data-motion="overlay-enter"],
[data-motion="overlay-exit"] {
  transition:
    opacity var(--chips-motion-overlay-enter-duration, 250ms)
      var(--chips-motion-overlay-easing, cubic-bezier(0, 0, 0.2, 1)),
    transform var(--chips-motion-overlay-enter-duration, 250ms)
      var(--chips-motion-overlay-easing, cubic-bezier(0, 0, 0.2, 1));
}

[data-motion="overlay-enter"] {
  opacity: var(--chips-motion-opacity-enter, 0);
  transform:
    translateY(var(--chips-motion-overlay-distance, 8px))
    scale(var(--chips-motion-overlay-scale, 0.98));
}

@media (prefers-reduced-motion: reduce) {
  [data-motion] {
    animation: none !important;
    transition-duration: var(--chips-motion-reduced-duration, 0ms) !important;
    transition-delay: 0ms !important;
    transform: none !important;
  }
}
```

正式 motion token 基线包含：

- `chips.motion.duration.instant | fast | normal | slow | emphasized`
- `chips.motion.easing.standard | entrance | exit | emphasized`
- `chips.motion.delay.none | short | medium`
- `chips.motion.stagger.none | item | group`
- `chips.motion.distance.xs | sm | md | lg`
- `chips.motion.opacity.enter | exit | visible`
- `chips.motion.scale.enter | pressed | drag`
- `chips.motion.reduced.duration | distance | scale | opacity`
- `chips.motion.scene.*`
- `chips.motion.overlay.*`
- `chips.motion.menu.*`
- `chips.motion.list.*`
- `chips.motion.drag.*`
- `chips.motion.theme.*`

`styles/motions.css` 应至少提供 `fade / overlay / menu / scene / list / drag / theme` 七类公共 motion class 或等价 `data-motion` 入口。`prefers-reduced-motion: reduce` 下必须关闭非必要动画和位移，保留颜色、焦点、状态等可访问反馈。

## 图标资源

运行时 UI 图标统一使用 Material Symbols variable font 与 `ChipsIcon`，主题包负责提供字体资源和图标 token：

- `icons/variablefont/*.woff2` 必须进入源码并复制到 `dist/icons/variablefont/`。
- `dist/theme.css` 必须声明三套 `@font-face`。
- 图标颜色、大小和可变轴通过 `chips.sys.icon.*` 与 `chips.comp.icon.*` 控制。
- `ChipsIcon` 通过 `data-tone="default|muted|accent|danger|disabled"` 暴露语义色调；主题 CSS 必须以 `chips.comp.icon.root.* -> chips.sys.icon.*` 的顺序解析对应 tone、强调轴和禁用态。
- `fill / wght / grad / opsz` 只有在 `IconDescriptor` 显式传入时才由组件写入 CSS 变量；主题包必须为未显式传入轴的图标提供完整默认轴 token。
- `toolbar / menu-bar / context-menu / icon-button` 等组件的图标尺寸、颜色和状态必须通过自身 `chips.comp.*.icon.*` token 或 `chips.comp.icon.*` / `chips.sys.icon.*` 回退表达，不得在 CSS 中硬编码一套私有图标规格。
- 应用启动图标、快捷方式图标和启动台图标仍由 `manifest.ui.launcher.icon` 文件路径承载，不属于 `ChipsIcon` 运行时图标模型。

## 主题继承

主题支持继承机制，子主题可以继承父主题的样式：

- 在 manifest 中声明 `parentTheme` 字段指定父主题
- 子主题只需覆盖需要修改的部分，未覆盖的部分自动继承父主题
- 继承可以实现主题系列如浅色主题、深色主题基于同一套色彩方案
- 官方基础主题仍遵守“一包一外观”；浅色与暗色主题作为独立 `themeId` 发布，不在一个主题包内通过 light/dark 分支切换。

## 作用域链

主题采用级联作用域链，利用 CSS 自定义属性的天然级联特性实现多层级主题覆盖。

### 层级架构

```
主题权重从低到高：

全局主题        ← 最低权重
应用级主题
箱子级主题
复合卡片级主题
基础卡片级主题
组件级主题      ← 最高权重（最小组件）
```

查找规则（逐层向上回退）：
`component -> base-card -> composite-card -> box -> app -> global`

### CSS 变量级联实现

利用 CSS 自定义属性的天然级联特性：

```css
/* 全局主题（注入到最顶层） */
:root {
  --chips-sys-color-primary: #2563eb;
  --chips-sys-color-surface: #ffffff;
  --chips-ref-radius-md: 10px;
}

/* 应用级主题覆盖 */
[data-chips-app="editor"] {
  --chips-sys-color-primary: #1976d2;
}

/* 箱子级主题覆盖 */
[data-chips-box="abc123"] {
  --chips-sys-color-surface: #f0f0f0;
}

/* 复合卡片级主题覆盖 */
[data-chips-composite-card="card-shell-01"] {
  --chips-sys-color-surface: #f5f5f5;
}

/* 基础卡片级主题覆盖 */
[data-chips-base-card="card-node-09"] {
  --chips-sys-color-surface: #f5f5f5;
}

/* 组件级主题覆盖 */
[data-chips-component="btn-save"] {
  --chips-comp-button-root-surface-idle: #4caf50;
}
```

### 覆盖规则

1. **作用域优先级**：近者优先（component > base-card > composite-card > box > app > global）
2. **选择器特异性**：特异性越高越优先
3. **声明顺序**：同一作用域内，后声明的覆盖先声明的

## cpx 逻辑尺寸单位

生态统一使用 `cpx` 作为逻辑尺寸单位，页面基准宽度为 `1024cpx`。

### 换算公式

```
px = cpx * (containerWidthPx / 1024)
```

### 工程规范

- 所有布局常量以 `cpx` 声明，渲染前统一换算到 `px`
- 换算结果保留 3 位小数，提交到 DOM/CSS 前按策略裁剪：
  - 字体：四舍五入到 `0.5px`
  - 边框：最小 `1px` 可见阈值
  - 位移：允许亚像素渲染

## 主题契约门禁

每个主题包在发布前必须通过以下校验：

### 1. Token 完整性校验

- 检查 `ref/sys/comp/motion/layout` 五层是否完整
- 检查是否存在冗余 token
- 检查 token 引用链是否完整（无循环引用）
- 验证 JSON 格式符合主题包五层 token 源结构

### 2. 组件接口点校验

- 检查组件是否包含 `data-scope` 和 `data-part` 属性
- 检查状态是否投影到 `data-state`
- 官方主题包必须执行组件库官方契约等值门禁，确保本地 `contracts/theme-interface.contract.json` 与组件库正式 component contract 在 `component/scope/parts/states/requiredTokens/optionalTokens/a11yConstraints/motionConstraints/iframe` 上完全一致
- 官方主题包必须检查 `dist/theme.css` 覆盖每个正式 contract scope 的 `data-scope` 选择器

### 2.1 主题矩阵快照

官方基础主题应维护可被测试或设置面板复用的主题矩阵快照，至少记录应用窗口、基础卡片 iframe、箱子布局 iframe 与模块配置面板四类运行场景的关键 token/CSS 入口。矩阵快照可以先以结构化 JSON 或 Markdown 表记录在主题包 `preview/` 或测试报告中；进入公共展示链路后，设置面板只消费该快照和 `theme.contract.get` 结果，不重新解析主题包私有文件。

### 3. 动效参数安全校验

- 检查最大动画时长是否超过阈值（建议 500ms）
- 检查缓动曲线是否为白名单曲线
- 检查所有 `motionConstraints[].tokenKeys` 都已进入 required token 覆盖集合
- 检查 `prefers-reduced-motion: reduce` 下非必要位移、缩放、无限动画已被关闭或降级为状态反馈

### 4. 颜色对比度校验

- 检查文本与背景的 WCAG 对比度
- 建议文本对比度 >= 4.5:1，大文本 >= 3:1

## 预览功能

主题包可以包含预览功能：

- `preview/` 目录存放主题预览图片
- 系统会在主题管理界面显示预览
- `preview.html` 可以包含预览页面代码，用于展示主题效果

## 发布流程

主题包开发完成后：

1. **打包**：使用 `chipsdev build` 与 `chipsdev package` 生成 `.cpk` 文件
2. **校验**：先执行 `chipsdev validate`，再在开发工作区使用 `chipsdev plugin install <cpk路径>`、`chipsdev plugin enable <主题插件ID>`、`chipsdev theme apply <themeId>` 与 `chipsdev theme validate` 完成 Host 侧契约门禁校验
3. **发布准备**：保留 `.cpk`、发布说明、构建日志和校验结果，供后续正式分发系统或人工交付流程使用
4. **用户态安装抽样**：需要验证真实用户工作区时，再使用 `chips plugin install <cpk路径>` 安装，并执行 `chips plugin enable <主题插件ID>`，主题才会出现在用户态主题管理界面的可用主题列表中
5. **切换**：开发态使用 `chipsdev theme apply <themeId>`；用户态抽样使用 `chips theme apply <themeId>`

主题 `.cpk` 需要遵循与普通插件一致的安装包契约：包根目录保留 `manifest.yaml`，主题构建产物位于 `dist/`，并采用 ZIP Store 模式输出。建议每次发布前都执行一次完整联调：`plugin install -> plugin enable -> theme apply -> theme validate`。

## 最佳实践

主题开发应遵循以下最佳实践：

- 使用语义化的令牌名称如 `primary` 而非 `blue-500`
- 保持令牌的层级结构便于管理
- 确保对比度满足可访问性要求
- 提供足够的变体覆盖各种使用场景
- 测试在不同设备和浏览器上的显示效果
- 每个主题包仅承载一种外观，不在包内区分模式
- 使用 `cpx` 作为布局尺寸单位
- 组件样式必须包含契约挂点（`data-scope`、`data-part`、`data-state`）
