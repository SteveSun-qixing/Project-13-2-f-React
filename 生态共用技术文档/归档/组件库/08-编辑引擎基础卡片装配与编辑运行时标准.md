# 编辑引擎基础卡片装配与编辑运行时标准

## 1. 适用范围

本标准仅适用于官方 `Chips-EditingEngine` 的编辑态复合卡片预览与编辑链路。

本标准不替代：

- `CardCoverFrame`
- `CompositeCardWindow`
- `client.card.editorPanel.render(...)`

上述链路仍然是生态对外公开的通用 Host 托管方案；官方编辑引擎在编辑态使用本标准定义的本地运行时，是生态内唯一正式例外。

## 2. 正式定位

编辑引擎编辑态采用“双运行时、单数据源”架构：

- 显示链路：`BasecardDescriptor -> BasecardFrameHost -> 单卡 iframe -> CompositeCardAssembler -> CardWindow`
- 编辑链路：`BasecardDescriptor.renderEditor -> EditorSessionStore -> EditorHost -> EditPanel`
- 数据源：`CardService` 中的解包态 `.card/` 数据

该链路的设计目标是：

- 保留每个基础卡片独立 iframe 的失败隔离与交互边界；
- 去掉整张复合卡片最外层的统一 iframe；
- 让编辑引擎壳层直接掌握节点选中、布局汇总和编辑会话编排；
- 不在主流程里为任意单一卡片类型保留特殊分支。

## 3. 核心契约

### 3.1 BasecardDescriptor

编辑引擎本地运行时以 `BasecardDescriptor` 作为统一入口：

```ts
interface IconDescriptor {
  name: string;
  style?: "outlined" | "rounded" | "sharp";
  fill?: 0 | 1;
  wght?: number;
  grad?: number;
  opsz?: number;
  decorative?: boolean;
  label?: string;
}

interface BasecardTiffToPngRequest {
  resourcePath: string;
  outputPath: string;
  overwrite?: boolean;
}

interface BasecardTiffToPngResult {
  path: string;
  mimeType: "image/png";
  sourceMimeType: "image/tiff";
  width?: number;
  height?: number;
}

interface BasecardDescriptor {
  pluginId: string;
  cardType: string;
  displayName: string;
  description?: string;
  icon?: IconDescriptor;
  aliases?: readonly string[];
  commitDebounceMs?: number;
  previewPointerEvents?: "native" | "shielded";
  createInitialConfig(baseCardId: string): Record<string, unknown>;
  normalizeConfig(input: Record<string, unknown>, baseCardId: string): Record<string, unknown>;
  validateConfig(config: Record<string, unknown>): { valid: boolean; errors: Record<string, string> };
  collectResourcePaths?(config: Record<string, unknown>): string[];
  renderView(ctx: {
    container: HTMLElement;
    config: Record<string, unknown>;
    themeCssText?: string;
    resolveResourceUrl?(resourcePath: string): Promise<string>;
    releaseResourceUrl?(resourcePath: string): Promise<void> | void;
    openResource?(input: {
      resourceId: string;
      mimeType?: string;
      title?: string;
      fileName?: string;
      payload?: Record<string, unknown>;
    }): void;
  }): (() => void) | void;
  renderEditor?(ctx: {
    container: HTMLElement;
    initialConfig: Record<string, unknown>;
    onChange(next: Record<string, unknown>): void;
    resolveResourceUrl?(resourcePath: string): Promise<string>;
    releaseResourceUrl?(resourcePath: string): Promise<void> | void;
    importResource?(input: { file: File; preferredPath?: string }): Promise<{ path: string }>;
    importArchiveBundle?(input: {
      file: File;
      preferredRootDir?: string;
      entryFile?: string;
      include?: {
        mimeTypes?: string[];
        extensions?: string[];
      };
      stripSingleRootDir?: boolean;
      excludeSystemArtifacts?: boolean;
    }): Promise<{
      rootDir: string;
      entryFile?: string;
      resourcePaths: string[];
      entries: Array<{
        sourcePath: string;
        resourcePath: string;
        fileName: string;
        mimeType?: string;
        size: number;
        compressedSize: number;
        crc32: number;
        offset: number;
        isDirectory: boolean;
        compressionMethod: number;
        modifiedTime?: number;
      }>;
      discardedEntries: Array<{
        sourcePath: string;
        reason: "directory" | "system-artifact" | "filter-mismatch" | "unsafe-path";
        fileName?: string;
        mimeType?: string;
      }>;
    }>;
    deleteResource?(resourcePath: string): Promise<void>;
    convertTiffToPng?(input: BasecardTiffToPngRequest): Promise<BasecardTiffToPngResult>;
  }): (() => void) | void;
}
```

约束：

- 描述符注册由编辑引擎运行时通过“内置描述符 + Host 已安装并启用的卡片插件入口导出的 `basecardDefinition`”统一完成；
- 主流程统一通过 `cardType` 或别名解析描述符；
- `RichTextCard -> base.richtext` 这类别名归一属于描述符层能力，不得散落在业务组件中；
- 资源型卡片的正式配置只保存“相对于卡片根目录”的资源路径；
- `collectResourcePaths(...)` 用于收集配置中引用的内部资源，供持久化阶段重建 `structure.yaml manifest.resources`；
- 编辑引擎允许保留 `base.richtext` 与 `base.image` 作为内置描述符，但它们在运行时注册中心中的地位与其他已安装插件一致，不是主流程特判；
- 对已安装插件的加载必须基于 Host `plugin.query({ type: 'card' })` 返回记录中的 `installPath + entry` 构造构建产物模块 URL，不得回退到工作区源码；
- 若查看态基础卡片需要在编辑引擎中预览尚未落盘的内部资源，可通过 `renderView` 上下文中的 `resolveResourceUrl/releaseResourceUrl` 获取当前会话可用的运行时 URL。
- Markdown、纯文本、JSON 等需要先读取正文再解析的资源，不再使用类型专属正文读取接口；插件应基于 `resolveResourceUrl(...)` 返回的正式运行时 URL，自行完成读取与解析。
- 查看态若需要把图片、音频、电子书、链接等资源打开动作交回外层容器，必须消费可选 `openResource(...)`；编辑引擎本地运行时会把相对资源标识归一到当前卡片根目录运行时 URL，并由上层卡片窗口统一调用 Host `resource.open` 路由。
- `BasecardDescriptor.icon` 必须是正式 `IconDescriptor`；编辑引擎卡箱库和相关运行时 UI 统一通过 `ChipsIcon` 渲染。
- 当某类基础卡片在编辑引擎预览态必须屏蔽 iframe 内部指针交互时，应通过 `previewPointerEvents = 'shielded'` 显式声明，由运行时统一提供透明选择层；不得在主流程里按具体 `cardType` 硬编码特判。

### 3.2 BasecardFrameHost

`BasecardFrameHost` 负责：

- 为单个基础卡片创建空白 `srcdoc` iframe；
- 为该 iframe 与其 `html/body` 初始文档显式施加透明背景，避免单卡窗口出现独立底色矩形；
- 在已知卡片根目录时向 iframe 文档注入对应的 `<base href>`；
- 在 iframe 内挂载 `renderView`；
- 向 `renderView` 注入 `openResource(...)`，把基础卡片查看态的资源打开意图上抛到复合卡片窗口，不允许基础卡片 iframe 直接启动目标应用；
- 从外层包装节点采集 `--chips-*` 主题变量，生成注入 CSS；
- 使用 `ResizeObserver + requestAnimationFrame` 测量单卡高度；
- 对外汇报 `loading/ready/error` 三态；
- 在 `preview` 场景下把指针选中回调给上层；
- 当描述符声明 `previewPointerEvents = 'shielded'` 且当前处于 `preview` 选中场景时，在 iframe 之上渲染透明选择层，阻止内部网页抢占点击；
- 在 `delegate` 场景下输出归一化后的交互意图。

稳定性要求：

- 父层回调身份变化不得导致基础卡片 iframe 被反复重挂载；
- 真实重建条件只能来自 `cardType/baseCardId/normalizedConfig/themeCacheKey` 等有效渲染输入变化；
- 错误必须在单卡范围内隔离，不得拖垮整张复合卡片。
- 当单卡已经进入 `ready` 后，后续因配置增量刷新触发的重新挂载不得再次显示首屏 loading 遮罩；旧内容必须尽量保持可见，避免输入和批量资源导入期间的持续闪烁。

### 3.3 CompositeCardAssembler

`CompositeCardAssembler` 负责：

- 按 `CardService` 当前 `basicCards` 顺序装配单卡 iframe；
- 读取 `layout.padding/layout.gap` 组织纵向布局；
- 汇总每个节点的高度、加载态和错误态；
- 把聚合后的高度回传给 `CardWindow`；
- 维护当前选中节点与可选状态。

当前正式视觉约束：

- 装配层不再额外包裹边框、圆角、阴影；
- 每个基础卡片在编辑引擎中的边缘应保持无感，外层只负责结构编排，不负责附加视觉装饰。
- 单卡 iframe 自身与其空白背景必须保持透明；若基础卡片内容不主动绘制壳层，外层复合卡片底色应连续可见。

### 3.4 EditorSessionStore

`EditorSessionStore` 负责：

- 以 `cardId + baseCardId` 生成稳定会话键；
- 保存 `sourceConfig/draftConfig/validation/dirty/isCommitting/errorMessage`；
- 保存待导入资源与待删除资源的运行时操作队列；
- 在源配置被外部刷新且会话未脏时同步草稿；
- 以 `descriptor.commitDebounceMs` 控制提交节流；
- 在卸载、切换节点时 flush 最后一版合法草稿；
- 当草稿已经引用待导入或待删除资源时，必须提升为立即提交，不得继续沿用普通文本编辑节流窗口。
- 单纯“资源已进入待导入/待删除队列，但草稿配置尚未引用这些变化”的中间态，不得单独提交；否则会产生“资源已写盘、正式配置未更新”的脏状态。

默认约束：

- 若描述符未声明 `commitDebounceMs`，默认提交节流为 `260ms`；
- 提交统一回到 `CardService.updateBasicCard(...)`，不得在编辑器组件中直接写文件。

### 3.5 EditorHost

`EditorHost` 负责：

- 根据 `cardType` 解析描述符；
- 确保当前会话存在并订阅其快照；
- 直接把 `renderEditor` 挂载到编辑面板容器；
- 为资源型编辑器提供 `resolve/import/importArchiveBundle/delete/convertTiffToPng/releaseResourceUrl` 正式宿主能力；
- 接收编辑器 `onChange`，更新草稿；
- 按会话状态防抖提交；
- 在 `visibilitychange(hidden)`、`pagehide`、`beforeunload` 时主动冲刷当前合法会话；
- 在错误时只影响当前编辑面板，而不影响预览链路。

正式约束：

- 官方编辑引擎的编辑器主链路不再使用 iframe 宿主；
- `PluginHost` 在编辑引擎中仅作为 `EditorHost` 的薄包装，不再承担 SDK iframe 编辑器职责。
- 传递给基础卡片编辑器的 `resolve/import/delete/releaseResourceUrl` 回调身份必须稳定；草稿变化只能更新会话状态，不能因为宿主回调重新创建而导致编辑器重挂载、输入失焦或选区丢失。
- `resolveResourceUrl(...)` 必须优先命中当前会话中的待导入资源；若当前会话已经提交但 `CardService` 仍持有待落盘资源，则必须继续命中该待落盘资源；只有在两处都不存在时，才允许回退到卡片根目录真实文件；
- 对“已落盘的卡片根目录资源”，编辑引擎本地运行时应优先返回稳定的 `file://` URL，而不是重新把磁盘文件读成一次性 `blob:`；
- `resolveResourceUrl(...)` 返回的运行时 URL 只定义“如何定位该资源”，不等价于统一的字节读取协议：
  - 图片、视频等直接交给 DOM 消费的资源，可以把返回 URL 直接用作 `src/href`；
  - Markdown、纯文本、JSON 等正文型资源，应由请求方基于该 URL 自行读取和解析；
  - 当运行时 URL 为 `file://` 时，请求方应通过正式文件服务读取正文，而不是把 `file://` 强行当作可直接 `fetch` 的统一协议；
  - 当运行时 URL 为 `blob:`、受控渲染协议 URL 或其他可访问 URL 时，请求方可以按该协议自行读取。
- `importResource(...)` 必须为当前卡片根目录挑选可用文件名，避免覆盖已有资源；
- `importArchiveBundle(...)` 必须由正式宿主链路完成 ZIP 条目校验、解压、过滤和最终目录落位；它是通用目录导入契约，不包含面向网页、图片或其他业务场景的开关字段；
- `entryFile` 表示必需入口文件；网页基础卡片传 `index.html`，电子书图片包不传入口文件而通过 `include` 过滤图片资源；
- `include.mimeTypes/extensions` 表示条目保留规则，`stripSingleRootDir` 表示是否剥离单一载荷根目录，`excludeSystemArtifacts` 表示是否排除 `__MACOSX`、`.DS_Store`、`._*` 等系统噪声；
- 官方 `Chips-EditingEngine` 若提供网页 ZIP 导入能力，其应用 `manifest.permissions` 必须包含 `zip.manage`，以便正式调用 `zip.list/zip.extract`；
- 当当前运行环境无法通过 `platform.getPathForFile(file)` 暴露所选 ZIP 的真实磁盘路径时，官方编辑引擎应先通过正式文件服务把该 `File` 暂存到当前卡片会话导入目录，再继续复用 `zip.list/zip.extract` 完成校验与解压；
- `importArchiveBundle(...)` 返回的 `rootDir/entryFile/resourcePaths/entries[*].resourcePath` 都必须是相对于卡片根目录的正式值；
- `entries` 必须保留 ZIP 条目元数据，包括原始路径、最终路径、MIME、大小、CRC、压缩方式、目录标记和可用的 `modifiedTime`；`discardedEntries` 必须记录目录、系统噪声、过滤不匹配和不安全路径；
- 当基础卡片需要把卡片内部 TIFF 资源归一为 PNG 时，`EditorHost` 必须通过正式 `resource.convertTiffToPng` 链路完成，不得在编辑器 iframe 或业务插件里私自复制第二套图像转换实现；
- 对音乐基础卡片这类“音频嵌入封面提取”场景，编辑器可以先把源 TIFF 登记为待导入资源，再由 `EditorHost` 暂存源文件、调用转换服务、读回 PNG 二进制并把最终 PNG 重新登记为当前会话待导入资源；正式配置只能引用最终 PNG 路径；
- 当待导入或待删除资源已经被当前正式配置引用时，即使配置签名本身未变化，`EditorHost + EditorSessionStore` 也必须允许这批资源变更按正常节流窗口提交，不能把它们错误地滞留到卸载时才写盘。
- `deleteResource(...)` 只登记删除意图，最终物理删除时机由持久化阶段依据真实引用关系决定。
- 对需要连续输入的大文本编辑器，正式推荐把“编辑期内存草稿刷新”和“卡片目录落盘保存”拆开：编辑期优先只更新运行时内存态；当用户焦点离开编辑面板、显式保存或宿主即将退出时，再统一调用持久化。
- 当基础卡片存在“编辑面板输入”和“复合卡片实时预览”双目标时，推荐进一步拆为三段：
  - 编辑器本地草稿：只服务输入稳定性；
  - 运行时预览草稿：以短防抖节奏驱动复合卡片刷新；
  - 正式持久化配置：只在失焦 flush、显式保存或宿主退出前收敛并写盘。

## 4. 数据与状态流

### 4.1 单一真实数据源

- `CardService` 中的 `CompositeCard.structure.basicCards[*].data` 是唯一正式数据源；
- `App.tsx`、`CardService.createCard/openCard/addBasicCard/updateBasicCard` 必须统一走描述符归一；
- 编辑器只维护草稿，不直接成为正式数据源。

### 4.2 标准流转

1. `CardService` 打开或创建卡片时，对 `cardType` 与 `data` 做统一规范化；
2. `CardWindow` 把当前 `basicCards` 交给 `CompositeCardAssembler`；
3. 用户在预览中点击节点，`BasecardFrameHost` 通过本地回调把 `baseCardId` 传给壳层；
4. `EditPanel -> PluginHost -> EditorHost` 打开当前基础卡片会话；
5. 编辑器修改草稿；
6. 若编辑器发生资源导入/删除，`EditorHost` 先把这些操作登记到当前会话；
   网页基础卡片、电子书图片包等整目录导入场景，通过 `importArchiveBundle(...)` 先把过滤后的目录资源落到卡片根目录，再更新草稿引用；
   音乐基础卡片这类嵌入封面提取场景，若真实封面格式为 TIFF，则通过 `convertTiffToPng(...)` 把导入的源封面转换为最终 PNG 后，再更新草稿引用；
7. `EditorSessionStore` 调用 `CardService.updateBasicCard(...)` 提交合法配置；若当前草稿已经引用待保存资源，则这一步必须立即执行；
8. `CardService` 自动持久化时把待导入资源写入卡片根目录，并基于 `collectResourcePaths(...)` 与真实根目录文件重建 `structure.yaml manifest.resource_count/resources`；
9. 在 `EditorSessionStore` 已提交、但 `CardService` 尚未完成落盘的时间窗内，编辑器与预览都必须继续通过待导入资源映射提供稳定预览，禁止提前退回卡片根目录文件路径；
10. 待删除资源只在显式 `saveCard` 等最终持久化阶段执行，且必须先确认没有剩余配置引用，以避免破坏编辑器回退与会话稳定性；
11. `CardWindow` 因数据变更刷新对应基础卡片 iframe 与整体高度。

## 5. 主题与交互正式要求

### 5.1 主题

- 主题来源仍然是编辑引擎外层 `ChipsThemeProvider`；
- 单卡 iframe 通过提取当前文档的 `--chips-*` 变量生成注入 CSS，同时必须转送父文档中由 Host preload 注入的完整主题 CSS；
- 完整主题 CSS 中的组件样式与 Material Symbols `@font-face` 不会被 iframe 自动继承，只复制变量会导致基础卡片查看态中的 `ChipsIcon` 显示图标名文本；
- 本地 `BasecardFrameHost` 只转送 Host 已解析、已改写资源 URL 的主题 CSS，不直接读取主题包文件，也不在基础卡片插件内打包图标字体；
- 基础卡片自身应使用 `--chips-*` token，而不是硬编码应用主题值。

### 5.2 交互

- `interactionPolicy = 'delegate'` 时，单卡 iframe 输出与 `CompositeInteractionPayload` 同形的滚轮交互载荷；
- 当前正式实现接管的是滚轮滚动与 `ctrl/meta + wheel` 缩放意图；
- `CardWindow` 负责把这些意图映射为无限画布 `panByInput/zoomByFactorAtPoint`。
- 若描述符声明 `previewPointerEvents = 'shielded'`，编辑引擎预览态必须优先命中外层透明选择层；点击应选中基础卡片并打开对应编辑面板，而不是把事件直接交给 iframe 内部内容。
- 编辑引擎应用壳层的 CSP 不得先于基础卡片运行时拦截网页基础卡片正式允许的远程 `http/https` iframe；若网页目标站点自身通过 `X-Frame-Options`、`frame-ancestors` 或等效策略拒绝嵌入，错误处理仍由网页基础卡片查看态承担。

## 6. 基础卡片插件侧要求

要进入官方编辑引擎链路，基础卡片插件必须满足以下条件：

- 在插件入口导出 `renderBasecardView` 与 `renderBasecardEditor`；
- 在插件入口导出完整 `basecardDefinition`；
- 视图导出必须是“挂载到容器并返回 cleanup”的纯函数；
- 编辑导出必须允许直接挂载到普通 DOM 容器，而不是假定自己必然运行在 Host 编辑器 iframe 中；
- 需要的配置 schema、默认值、清洗逻辑应作为可复用模块暴露，供描述符层消费；
- 若插件存在 TIFF 封面抽取、图片归一化等需求，应消费 `renderEditor(...)` 上下文提供的 `convertTiffToPng(...)`，而不是自行依赖宿主平台命令；
- 插件代码不得把 `cardType` 解析、会话管理、自动保存职责反推给编辑引擎。

## 7. 禁止事项

- 不允许在编辑引擎主流程里为任意卡片类型保留硬编码分支；
- 不允许同时保留“本地装配链路”和“复合 iframe 链路”作为编辑态双正式路径；
- 不允许引入通用空壳编辑器作为正式兜底；
- 不允许在运行时扫描工作区源码目录，也不允许动态 import 未经过 manifest `entry` 声明的源码入口；
- 不允许绕开 `CardService` 直接写 `.card/content/*.yaml`。
- 不允许把 `blob:`、`data:`、系统绝对路径等运行时 URL 写回正式 YAML；
- 不允许把卡片内部资源错误地写入 `content/` 或其他非卡片根目录位置。

## 8. 与通用 Host 托管链路的边界

- `CompositeCardWindow + editorPanel` 继续服务查看器、第三方集成和其他 Host 托管场景；
- 官方编辑引擎只在编辑态使用本地运行时；
- 两条链路共享基础卡片插件导出、`cardType` 匹配规则和主题 token 体系；
- 若未来其他应用希望复用编辑引擎本地运行时，必须先把该应用纳入正式生态决议，不能自行复制实现。
