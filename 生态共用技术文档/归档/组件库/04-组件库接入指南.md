# 组件库接入指南

## 1. 适用场景

- 新建插件项目接入薯片组件库
- 新建应用页面按统一契约直接使用组件库
- 首发主题包按 token 体系接入

## 2. 接入原则

1. 先接入契约，再接入视觉
2. 优先接入 P0 核心组件，再扩展高级组件
3. 禁止过渡桥接代码进入主线
4. 新项目不包含历史迁移策略

## 3. 标准接入步骤

1. 建立任务分支（`task-<task>`）
2. 接入组件库 provider 与主题运行时
3. 对齐 `data-scope/data-part/data-state`
4. 对齐主题权重与查找链（`global -> app -> box -> composite-card -> base-card -> component`，高权重优先回退）
5. 跑完契约测试、a11y、性能测试
6. 跑完组件矩阵覆盖门禁 `quality:coverage`
7. 通过后合并到 `develop`

TypeScript 接入基线：

- 必须保持 `strict` 打开
- 必须直接使用组件库正式声明文件
- 禁止在应用侧添加本地声明兜底、`as any` 降级或关闭类型门禁
- 如果组件库缺少正式声明或导出冲突，必须先提交工单再处理

State / Binding / Form 接入基线：

- 页面本地 UI 状态优先使用 `useChipsState`，并通过返回的 `binding` 适配组件受控 props。
- 异步加载、保存和刷新状态优先使用 `useChipsAsyncState`，状态集合固定为 `idle / loading / success / error`。
- 表单页优先使用 `useChipsFormState` 管理值、错误、触达、dirty 和字段绑定；业务校验和 Host 配置读写仍留在应用层或 SDK client。
- 控件接线使用 `value/onValueChange`、`checked/onCheckedChange`、`open/onOpenChange` 或原生 `value/onChange`；不得为单个组件私造 `binding` prop。
- 详细规范见 `10-状态环境与Binding模型.md`。

焦点、键盘与 A11y 接入基线：

- 弹层、菜单、选择器、标签页、表格、树和命令面板必须通过组件库正式键盘行为接入，不得在业务层长期复制私有方向键或焦点恢复逻辑。
- 自定义复合组件需要复用 `@chips/a11y` 的 `createKeyboardMap`、`createFocusScope`、`createRovingTabIndex` 和 ARIA 校验工具。
- 测试必须覆盖键盘打开/关闭、方向键移动、Home/End、Enter/Space 激活、Escape 关闭、focus trap、关闭后焦点恢复和 `aria-activedescendant`。
- 新增公开组件时必须同步 `@chips/testing` 组件质量矩阵，覆盖 contract attr fixture、ARIA fixture、状态优先级和必要的 perf smoke 场景。
- 详细规范见 `11-焦点键盘与A11y交互模型.md`。

卡片显示场景必须额外接入：

- 卡片封面显示统一使用 `CardCoverFrame`
- 箱子封面、箱子条目封面和其他受控文档 iframe 区域统一使用 `EmbeddedDocumentFrame`
- 通用查看态复合卡片显示统一使用 `CompositeCardWindow`
- 通用查看态的渲染拼接统一由 Host 内置渲染运行时处理（可通过 SDK 显示接口调用）
- 官方编辑引擎的编辑态预览与编辑链路不走 `CompositeCardWindow/editorPanel` 主路径，必须遵循 `生态共用技术文档/组件库/08-编辑引擎基础卡片装配与编辑运行时标准.md`

## 4. 风险控制

- 对高频组件采用分批接入与灰度开关
- 保留回滚点（tag 或 release 分支）
- 每批次接入必须有回归测试记录

## 5. 阻断条件

遇到以下情况必须先提工单：

- 缺少生态标准组件导致无法接入
- SDK/Theme Runtime 接口不满足组件运行需求
- 主题契约缺失且无法补齐

工单路径：`项目日志与笔记/问题工单.md`。
