# 数据模型与接口映射

## 0. 当前链路核对结论

最后核对时间：2026-08-06。

当前社区服务器卡片链路已经调整为：

- `.card` 源文件永久保存到 `chips-card-files`；
- 上传成功后的 `cards.status = ready` 表示源 `.card` 已保存，不表示查看缓存已生成；
- 完整网页查看缓存使用 `community-web` 渲染 profile，保存到 `chips-card-render-cache` 或 `chips-card-render-cache-private`；
- 卡片封面缓存使用 `community-cover` 渲染 profile，保存到 `chips-card-cover-cache` 或 `chips-card-cover-cache-private`；
- 完整查看缓存和封面缓存都按“最后一次访问后 30 天”续期，过期后由 Worker 清理；
- `htmlUrl` 保留为历史字段，不再是社区前台打开卡片的主判断条件。

## 1. 现有接口复用结论

本轮前端重构**原则上不新增后端接口**，优先复用当前已存在能力。

## 2. 个人页接口映射

### 2.1 用户信息

- 接口：`GET /api/v1/users/:username`
- 用途：头像、昵称、简介、用户名。

### 2.2 卡片列表

- 接口：`GET /api/v1/users/:username/cards`
- 用途：获取该用户公开且已完成处理的卡片。

### 2.3 箱子列表

- 接口：`GET /api/v1/users/:username/boxes`
- 用途：获取该用户公开箱子。

## 3. 本人状态接口映射

- 接口：`GET /api/v1/users/me`
- 用途：判断当前访问者是否为本人，并驱动“+”入口显隐。

## 4. 工作区接口映射

### 4.1 卡片上传

- 接口：`POST /api/v1/upload-sessions` + `POST /api/v1/upload-sessions/:uploadId/card`
- 入参：先创建 `contentType=card` 的上传会话，再以 `multipart/form-data` 提交 `file` 和 `manifest`
- 默认：`visibility=public`

### 4.2 卡片状态

- 接口：`GET /api/v1/cards/:cardId/render-status`
- 用途：渲染缓存链路轮询，直到 `viewState=cache_ready` 或 `render_error`。
- 访问口径：与 `GET /api/v1/cards/:cardId` 一致，按卡片可见性决定是否可读，不再要求必须登录。

查看缓存轮询使用：

- `GET /api/v1/cards/:cardId/render-status`

实际查看入口使用：

- `GET /api/v1/cards/:cardId/open-view`
- `GET /api/v1/cards/:cardId/view`
- `GET /api/v1/cards/:cardId/cover`

### 4.3 箱子上传

箱子链路已并入 card-transfer 控制面（task029 收口，字节直传对象存储）：

- 接口：`POST /api/v1/card-transfer/upload-sessions`（请求体 `contentType: 'box'`）
  - 服务端创建 box 上传会话并落库箱子占位记录（`BoxService.createPlaceholder`）；
  - 响应 `boxFile` 目标（`chips-box-files` bucket 内的 `box.box` 对象）；
- 接口：`POST /api/v1/card-transfer/upload-sessions/:uploadId/objects:presign`
  - 仅支持 `role: 'box-file'` 单对象，key 固定为 `boxFile.objectKey`；
- 接口：`POST /api/v1/card-transfer/upload-sessions/:uploadId/complete`
  - 校验 box 对象归属与大小，`BoxService.create` 落库（含 `source_box_*` 源对象字段）；
- 接口：`POST /api/v1/card-transfer/upload-sessions/:uploadId/abort`（通用中止）

保留的多部分上传入口：

- 接口：`POST /api/v1/upload/box`
- 入参：`file` + 默认 `visibility=public`
- 服务端解包校验（4 必需文件）后，源 `.box` 上传到 `chips-box-files` 保留，不再删除源对象。

箱子只读文档：

- 接口：`GET /api/v1/boxes/:boxId/view`（optionalAuthenticate，权限同 `GET /boxes/:boxId`）
- 返回 `text/html` 只读箱子文档（名称、描述、条目列表；社区卡片条目提供 `/cards/:id` 链接，内嵌条目显示包内路径）。
- `BoxService.create` 落库时 `documentUrl` 写为 `/api/v1/boxes/{boxId}/view`。

## 5. 不再作为前端主消费接口的能力

以下能力暂时保留在后端，但不再作为社区前端 V2 的主界面入口：

## 6. 页面内部统一模型

### 6.1 作品模型

```ts
type CommunityWorkItem = {
  id: string;
  type: 'card' | 'box';
  title: string;
  coverUrl: string | null;
  href: string;
  createdAt: string;
};
```

补充说明：

- `card.coverUrl` 在卡片场景中表示独立封面 HTML 入口，当前为 `/api/v1/cards/:cardId/cover`；
- `box.coverUrl` 仍表示箱子封面资源地址；
- `card.viewUrl` / `card.renderStatusUrl` 是卡片打开主入口，社区前台通过 `/cards/:cardId` 创建 `com.chips.card-viewer` Web 插件会话，并由原版 `CardViewer` 以托管文档方式承载 `/api/v1/cards/:cardId/view`；
- `card.htmlUrl` 是历史字段，不再作为前端主打开口径；
- 卡片内部图片、音乐、视频、电子书等资源点击后，不再停留在静态 HTML 中，而是通过正式 `resource.open` 路由优先在新标签页进入 `/host/plugins/:sessionId` 插件宿主页，由对应原版 Web 应用插件接管查看；若浏览器拦截新标签页，则回退为当前页导航。

### 6.2 上传模型

```ts
type UploadQueueItem = {
  localId: string;
  type: 'card' | 'box';
  status: 'queued' | 'uploading' | 'processing' | 'success' | 'error';
  progress: number;
  resultHref?: string;
  errorMessage?: string;
};
```

## 7. 前端需要显式隐藏的旧能力

- 房间选择；
- 房间管理；
- 作品删除；
- 资料编辑；
- 发现搜索；
- 平台级导航入口。

这些能力不是后端删除，而是本轮前端明确不暴露。

## 8. 社区前台新增 Host Runtime 接口映射

本轮为正式 Web 插件宿主新增以下社区内部接口：

- `POST /api/v1/host/plugin-sessions`
  - 创建 Web 应用插件会话。
- `GET /api/v1/host/plugin-sessions/:sessionId`
  - 读取插件会话视图。
- `DELETE /api/v1/host/plugin-sessions/:sessionId`
  - 关闭插件会话。
- `POST /api/v1/host/resource-open-plan`
  - 在服务端按正式 `resource-handler / file-handler` 能力解析 Web 资源打开目标。
- `GET /api/v1/host/plugin-sessions/:sessionId/entry`
  - 返回注入 bootstrap 后的插件 HTML 入口。
- `GET /api/v1/host/plugin-sessions/:sessionId/bootstrap.js`
  - 返回浏览器侧 `window.chips` bootstrap。
- `GET /api/v1/host/plugin-sessions/:sessionId/assets/*`
  - 返回该插件会话所需静态资源。

这些接口只服务社区服务器自己的 Web 插件宿主链路，不作为生态公共 API 主发布位置。
