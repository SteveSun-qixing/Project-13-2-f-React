# 工作区上传页技术方案

## 1. 页面目标

工作区页只围绕上传任务建模，不再承担工作台聚合职责。

## 2. 输入方式

必须同时支持两种输入路径：

1. 拖拽文件进入页面；
2. 点击拖拽区调起文件选择器。

## 3. 文件识别

前端根据文件扩展名直接判定类型：

- `.card` -> 卡片上传
- `.box` -> 箱子上传

不再保留旧版手动模式切换。

## 4. 上传默认参数

为保持页面极简，前端统一采用：

- `roomId: undefined`
- `visibility: 'public'`

也就是默认上传到用户根目录并公开发布。

## 5. 队列模型

推荐统一使用：

```ts
type UploadQueueItem = {
  localId: string;
  file: File;
  type: 'card' | 'box';
  status: 'queued' | 'uploading' | 'processing' | 'success' | 'error';
  progress: number;
  remoteId?: string;
  resultHref?: string;
  errorMessage?: string;
};
```

## 6. 卡片上传流程

正式推荐的卡片发布链路由 `Chips-CommunityUploader-Plugin` 承担本地资源外置和重打包：

1. 调用 `POST /api/v1/upload-sessions` 创建上传会话；
2. 本地解包 `.card`，扫描卡片内部资源、封面资源和文件态富文本；
3. 调用 `POST /api/v1/upload-sessions/:uploadId/resources/presign` 获取资源直传地址；
4. 模块插件将资源 PUT 到预签名地址；
5. 模块插件改写 `content/*.yaml` 与 `.card/cover.html` 中的资源 URL，删除已外置资源并重新打包 `.card`；
6. 调用 `POST /api/v1/upload-sessions/:uploadId/card` 提交处理后的源 `.card`；
7. 服务器保存源 `.card` 到 `chips-card-files`，并入队生成 view 与 cover 渲染缓存；
8. 客户端轮询 `GET /api/v1/cards/:cardId/render-status`；
9. 缓存 ready 后通过 `GET /api/v1/cards/:cardId/view` 与 `GET /api/v1/cards/:cardId/cover` 打开。

当前 Web 工作区页面也走上传会话提交源 `.card`。浏览器页面不做本地资源外置；完整资源外置发布能力由 `Chips-CommunityUploader-Plugin` 提供。

## 7. 箱子上传流程

1. 调用 `POST /api/v1/upload/box`；
2. 上传成功即进入成功态；
3. 为结果卡片写入 `resultHref`。

## 8. 并发策略

- 前端工作区队列采用有限并发调度，当前并发上限为 `3`；
- 每个任务从 `queued` 进入 `uploading` 后独立完成上传、卡片状态轮询或箱子成功收口；
- 卡片任务进入服务端 `processing` 后不会继续阻塞其他 queued 文件启动上传；
- 服务端上传接收阶段采用流式写入临时文件，不把完整 `.card` / `.box` 先聚合成内存 Buffer；
- 资源文件由 CommunityUploader 通过上传会话预签名地址直传对象存储；
- view/cover 渲染缓存由服务端 worker 生成，缓存目录上传对象存储时采用有限并发；
- 缓存上传并发由服务端环境变量 `CARD_RENDER_CACHE_UPLOAD_CONCURRENCY` 控制，默认值为 `8`；
- worker 并发和重试由 `CARD_RENDER_WORKER_CONCURRENCY`、`CARD_RENDER_JOB_MAX_ATTEMPTS`、`CARD_RENDER_QUEUE_POLL_TIMEOUT_SEC` 控制。

## 9. 页面反馈

### 9.1 空闲态

- 显示大拖拽区；
- 给出支持格式与拖拽提示。

### 9.2 有队列时

- 拖拽区仍保留；
- 下方显示最近上传队列；
- 成功项允许一键返回个人页或打开内容。
