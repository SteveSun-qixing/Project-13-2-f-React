# 启动与运行说明

## 1. 环境要求

- Node.js >= 20、pnpm >= 9
- Docker（本地联调用：PostgreSQL / MinIO）
- 对象存储：可使用外部 S3 兼容服务（七牛云、Cloudflare R2 等）或本地 MinIO

## 2. 环境变量

复制 `deploy/.env.example` 为 `deploy/.env` 并按实际修改：

| 变量 | 必填 | 说明 |
|---|---|---|
| `BASE_URL` | 是 | 外部访问地址 |
| `DATABASE_URL` | 是 | PostgreSQL 连接串 |
| `S3_ENDPOINT` / `S3_ACCESS_KEY` / `S3_SECRET_KEY` | 是 | 对象存储端点与凭据 |
| `S3_PUBLIC_URL` | 否 | 公开资源域名前缀 |
| `S3_BUCKET_NAME` | 否 | 单物理桶模式（逻辑桶以 key 前缀映射） |
| `API_TOKEN` | 是（≥16 字符） | 写接口管理令牌 |
| `PORT` / `HOST` | 否 | 监听地址（默认 3000 / 0.0.0.0） |
| `MAX_CARD_SIZE_MB` / `MAX_BOX_SIZE_MB` | 否 | 上传大小限制 |
| `UPLOAD_SESSION_TTL_MINUTES` | 否 | 会话有效期（默认 60） |
| `ENABLE_SWAGGER` | 否 | API 文档开关 |

## 3. 本地联调

```bash
pnpm install
pnpm start:local        # 拉起 Docker 基础设施 + server + web
pnpm status:local
pnpm logs:local server
pnpm stop:local
```

- API：`http://127.0.0.1:3000`（Swagger：`/api/docs`）
- Web：`http://127.0.0.1:5173`

## 4. 单独启动

```bash
pnpm --filter @cps/server dev          # API（tsx watch）
pnpm --filter @cps/web dev             # Web（vite 5173）
```

## 5. 生产部署

```bash
cd deploy
docker compose up -d --build
```

> 注意：`docker-compose.yml` 顶层声明了固定项目名 `name: cps`，避免与社区服务器（其 compose 同样位于 `deploy/` 目录、默认项目名冲突）互相重建容器。个人服务器与社区服务器可同机并行部署，端口通过 `.env` 中的 `*_HOST_PORT` 错开。

- `docker-compose.yml`：postgres / minio / server / web / nginx；
- 无 Redis 与 worker / admin 服务；
- `nginx/nginx.conf` 已移除 admin 与 /cdn/ 重定向段；
- 证书挂载：`certs/chipscard.space_ca.crt`、`certs/chipscard.space.key`。

### 5.0 单物理桶模式（七牛云）配置要点

- `S3_ENDPOINT` 必须使用**通用端点**（如 `https://s3.ap-southeast-1.qiniucs.com`），不能使用 bucket 专属端点（`chipscardspace.s3...`）；
- bucket 专属端点会把物理桶名写入对象 key（对象实际 key 变为 `chipscardspace/chips-card-render-cache/...`），导致 CDN 访问路径（`file.chipscard.space/chips-card-render-cache/...`）与实际 key 不一致而 404；
- 单桶模式下**所有逻辑桶（含私有桶）都写入同一个物理桶**，以逻辑桶名作为 key 前缀；
- 私有对象（`.box` 源文件等）位于公开空间内，通过公开 CDN 域名可直接访问，单桶模式固有特性，发布前请注意内容隐私。

### 5.1 资源要求与 PostgreSQL 调优

个人服务器无服务端渲染，可在 1 核 1G 的服务器上流畅运行。compose 内 PostgreSQL 已按小内存调优：

| 参数 | 值 | 说明 |
|---|---|---|
| `shared_buffers` | 128MB | 共享缓冲区（约内存的 1/8） |
| `max_connections` | 50 | 单用户低并发足够 |
| `work_mem` | 4MB | 排序/哈希工作内存 |
| `maintenance_work_mem` | 64MB | VACUUM/索引维护 |
| `effective_cache_size` | 384MB | 系统缓存估算（约内存的 1/3） |

若使用外部托管的 PostgreSQL（云数据库），无需额外调优；若自建并调整服务器内存规格，按内存比例同步调整以上参数即可。

## 6. 验证

```bash
pnpm lint              # ESLint（packages/*/src）
pnpm test              # 服务端 vitest
pnpm build             # server tsc + web vite build
```

## 7. 客户端发布

- 桌面客户端使用 `Chips-CommunityUploader-Plugin` 发布；
- `server.baseUrl` 指向个人服务器地址，`server.accessToken` 填 `API_TOKEN`；
- 需要服务器直接发布渲染产物时，`publish.includeRenderArtifacts: true`（个人服务器推荐）；
- 仅上传源文件时 `publish.includeRenderArtifacts: false`（社区服务器模式，个人服务器上卡片将保持"尚未渲染"）。
