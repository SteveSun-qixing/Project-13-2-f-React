# 架构与边界

## 1. 定位

个人服务器（`Chips-PersonalServer`）是薯片生态的单用户内容服务器，由社区服务器（`Chips-CommunityPlatformServer`）裁剪改造而来：

- 去掉多用户、认证、房间、发现、搜索、管理后台；
- 去掉服务端渲染链路（HeadlessHostShell、Worker 队列、渲染缓存 TTL）；
- 上传链路扩展为"客户端渲染产物上传"模式。

## 2. 运行形态

```
薯片客户端 (Host + CommunityUploader 模块)
   │  渲染产物 + 网络资源卡片 + 资源（直传对象存储）
   ▼
个人服务器 API（Fastify，单进程，无 Worker）
   ├── PostgreSQL：作品与上传会话元数据
   └── S3/MinIO：源文件、资源、渲染产物
        ▼
Web 前端（Vite SPA）→ 浏览器直接加载渲染产物
```

## 3. 能力边界

| 能力 | 归属 |
|---|---|
| 卡片/箱子制作与渲染 | 客户端 Host |
| 渲染产物上传 | 客户端传输模块 + 个人服务器控制面 |
| 元数据/状态/签名/下载计划 | 个人服务器 API |
| 文件字节 | 对象存储 |
| 页面展示 | 个人服务器 Web 前端 |

## 4. 鉴权模型

- 读接口公开；
- 写接口与传输控制面要求 `Authorization: Bearer <API_TOKEN>`；
- `api-token.plugin.ts` 使用常量时间比较（`crypto.timingSafeEqual`）防时序侧信道；
- 客户端传输模块的 `server.accessToken` 字段即携带管理令牌，客户端无需改动。

## 5. 关键差异（与社区服务器）

1. `cards.status`：`pending`（等待渲染产物）/ `ready` / `error`，不再有 `processing`；
2. 渲染产物记录在 `cards.render_artifacts`，生命周期与卡片一致；
3. `upload_sessions` 增加 `include_render_artifacts` 列，幂等键全局唯一；
4. 无 `users` / `rooms` / `card_render_caches` / `card_render_jobs` 表；
5. 无 `worker` 进程、无渲染队列、无 Redis；
6. 单物理桶模式（`S3_BUCKET_NAME`）：全部逻辑桶（含私有桶）映射到同一物理桶，key 前缀为逻辑桶名；`S3_ENDPOINT` 必须使用对象存储通用端点，避免物理桶名被写入对象 key。
6. 上传会话缓存版本号（cacheVersion）即会话 ID，产物对象键为 `{cardId}/{cacheVersion}/{relativePath}`。

## 6. 归档说明

- 所有从社区服务器复制但未使用的源码、页面、文档均保留在 `归档/from-community-server/`，禁止直接删除；
- 部署配置中的 worker / admin 服务已移除。
