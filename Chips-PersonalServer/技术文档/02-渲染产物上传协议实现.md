# 渲染产物上传协议实现

本文档描述个人服务器对"客户端渲染产物上传"的具体实现。公共协议口径见 `生态共用技术文档/协议与契约/09-社区平台API契约.md` 与 `10-个人服务器API契约.md`。

## 1. 会话创建

`POST /api/v1/card-transfer/upload-sessions`

- 请求体新增 `includeRenderArtifacts?: boolean`（默认 false）；
- 会话记录该标志（`upload_sessions.include_render_artifacts`）；
- 卡片会话元数据（`client_metadata`）同时记录：
  - `renderCacheVersion`（= 会话 ID，作为产物缓存版本号）；
  - `renderObjects`（已预签名的渲染产物对象清单，供 complete 校验）。

## 2. 产物预签名

`POST /api/v1/card-transfer/upload-sessions/:uploadId/objects:presign`

对象角色：

| 角色 | 目标 bucket | 对象键 | 说明 |
|---|---|---|---|
| `render-file` | `chips-card-render-cache`（公开）或 `-private` | `{cardId}/{cacheVersion}/{relativePath}` | 查看产物文件 |
| `cover-file`（卡片会话） | `chips-card-cover-cache`（公开）或 `-private` | `{cardId}/{cacheVersion}/{relativePath}` | 封面产物文件 |
| `cover-file`（箱子会话） | `chips-covers` | `boxes/{boxId}/cover/{relativePath}` | 箱子封面目录 |

- bucket 按会话 `visibility` 选择（公开卡片进公开桶，私有进私有桶）；
- 每次预签名后 `renderObjects` 追加到会话 `client_metadata`；
- 私有桶对象不返回公开 URL（`publicUrl` 为空字符串）。

## 3. 完成校验与发布

`POST /api/v1/card-transfer/upload-sessions/:uploadId/complete`

处理顺序：

1. 校验网络资源卡片与资源对象（对象归属 + 大小）；
2. 若提交了 `renderArtifacts`：
   - 校验 `renderObjects` 非空且全部对象已上传（Head 校验大小）；
   - 校验 `view.entryRelativePath` / `cover.entryRelativePath` 对应的入口对象已预签名；
   - 构造 `CardRenderArtifacts` 记录（含 `entryUrl`：公开走 `buildObjectUrl`，私有走受控代理路由）；
   - 更新卡片 `htmlUrl` / `coverUrl` / `render_artifacts` / `rendered_at`，`status = ready`；
3. 未提交 `renderArtifacts`：卡片 `status = pending`（网页显示"尚未渲染"）；
4. 响应：`status` 为 `ready` 或 `pending`，不含 `renderStatus` 字段。

## 4. 查看与封面入口

- `GET /api/v1/cards/:cardId/view`：有查看产物 → 302 到 `entryUrl`；无 → 400 `CARD_RENDER_NOT_READY`；
- `GET /api/v1/cards/:cardId/cover`：有封面产物 → 302；无 → 200 默认占位 HTML；
- 私有产物代理路由：
  - `GET /api/v1/cards/:cardId/render-cache/:cacheVersion/*`
  - `GET /api/v1/cards/:cardId/cover-cache/:cacheVersion/*`
  - 校验 `cacheVersion` 与卡片 `render_artifacts` 一致后流式读取对象（支持 Range 请求，供视频播放器使用）；
  - 资产路径归一化，禁止路径穿越。

## 5. 产物清理

- 修改可见性或删除卡片时，按 `render_artifacts.view/cover` 的 `keyPrefix` 删除对象存储产物，并清空卡片产物字段（`CardService.deleteRenderArtifacts`）；
- 服务器不做 TTL 过期清理，产物生命周期与卡片一致。

## 6. 客户端实现（Chips-CommunityUploader-Plugin）

- `publish.includeRenderArtifacts`（默认 false）控制两种模式；
- 开启时：
  1. 通过 `ctx.module.invoke({ capability: 'converter.file.convert', method: 'convert', ... })` 调用 Host 文件转换模块，把 `.card` 渲染为 HTML 目录（job 模式轮询）；
  2. 从解包目录组装封面产物（`.card/cover.html` → `index.html`，`.card/cardcover/*` → `cardcover/*`；封面缺失时生成默认封面）；
  3. 枚举产物文件，以 `render-file` / `cover-file` 角色预签名并直传；
  4. complete 提交 `renderArtifacts` 摘要（`rendererVersion` 固定为 `chips-client-renderer-1`）；
- 转换模块不可用时返回 `COMMUNITY_TRANSFER_RENDER_UNAVAILABLE`；
- 箱子上传透传 `includeRenderArtifacts` 给散落卡片。
