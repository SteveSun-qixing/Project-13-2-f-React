# 产品定位与范围

## 1. 产品目标

- 个人服务器是薯片生态的**单用户内容服务器**：自己的卡片与箱子统一沉淀在一个清爽、克制、有质感的空间里，随时可以被任何人浏览；
- 卡片与箱子的**查看与封面渲染产物由客户端 Host 渲染后上传**，服务器只负责存储、发布与展示；
- 与社区服务器共用同一套文件格式（`.card` / `.box`）、传输协议（card-transfer 控制面）与内容模型。

## 2. 本轮范围

### 2.1 必做

- 单用户作品主页：主页展示全部公开卡片与箱子；
- 卡片查看页：直接加载客户端渲染的查看产物；
- 箱子查看页：加载服务器生成的箱子只读文档；
- 发布说明页：向创作者说明客户端发布流程；
- 客户端渲染产物上传链路：上传会话支持 `includeRenderArtifacts` 两种模式；
- 管理令牌保护写接口；
- 部署与本地开发脚本（去 worker / admin）。

### 2.2 明确不做

- 多用户、注册登录、头像、角色；
- 房间、发现、搜索；
- 管理后台；
- 服务端渲染（HeadlessHostShell / Worker 队列 / 渲染缓存 TTL 清理）；
- 浏览器内上传与打包。

## 3. 内容组织原则

- 主页展示服务器内**全部公开作品**（卡片与箱子统一按创建时间倒序）；
- 未上传渲染产物的卡片在网格中照常展示，打开时提示"尚未渲染"；
- 展示单位统一称为"作品"。

## 4. 交互主线

1. 访客打开主页浏览公开作品；
2. 创作者在薯片客户端中制作内容，通过统一传输模块发布（可选择是否上传渲染产物）；
3. 访客进入卡片或箱子页面阅读；
4. 创作者（持有管理令牌）可删除或调整作品可见性。

## 5. 范围边界

- 本手册约束 `packages/server`、`packages/web` 与 `deploy`；
- 卡片/箱子上传与下载统一由客户端传输模块（`Chips-CommunityUploader-Plugin`）完成，网页不提供上传入口；
- 公共协议（card-transfer 控制面、渲染产物角色）以 `生态共用技术文档/协议与契约/` 为准。
