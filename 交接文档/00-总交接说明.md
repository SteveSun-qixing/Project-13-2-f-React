## 一、项目背景与目标

### 1.1 薯片生态是什么

薯片生态是**用户态操作系统级的跨平台软件环境**：一个平台底座（Cordis 运行时 + Rust 核心 + 能力 Bridge + 文档/资源/渲染/编辑五链）+ 无限插件（四角色）+ 用户内容（`.card`/`.box` 文件）。目标是"一份代码五端运行、承载全领域软件、内容十年不死"。

### 1.2 新架构（当前唯一正确版本）

| 维度 | 设计 |
|---|---|
| 运行时 | Cordis（Rust 重实现）：Context 树 / Fork 可逆副作用 / 服务暂存代际 / 依赖拓扑 / 事件广播+入队 / 命令循环单写者 |
| 集成 | Neon（Rust ↔ Node.js）；二进制 `{json,bin}` 信封一次拷贝 |
| 壳 | Electron（桌面，当前）；无头宿主已定；移动端 Tauri 2 / React Native 预选（ADR-007 待二次裁决）；浏览器宿主明确不在范围 |
| 前端 | React + fork antd（`@chips/antd`，仅 `@chips/ui` 内部）+ `@chips/ui` 唯一导入面；Design Tokens；简体中文直写；无主题/多语言 |
| 插件 | 四角色：`basecard` / `boxlayout` / `app` / `service`；`.cpk`（ZIP Store）+ Ed25519 签名；受管模块加载器；工具进程（Phase 4） |
| 契约 | `window.chips`：`request` / `subscribe` / `resource`；能力↔权限分离；JSON Schema 2020-12 输入校验；会话=身份与限权单位 |
| 内容 | 五链一条线（解析/资源/渲染/封面/编辑+写入）；唯一分支 `DocumentKind`；解析只读、文档服务唯一写口、渲染只读投影；目录态工作副本 + 归档态导出 |
| 编辑 | 编辑链路（`IEditSession` + `IPluginRuntime` 门面 + `IBaseCardEditor`/`ILayoutEditor`）；回流唯一时序 `document:write → update(view,revision) → markCommitted` |
| 文件系统 | 一切皆挂载、一切皆句柄、差异止于 Provider；`file:*`（路径）与 `resource:*`（地址）同一引擎两张能力面 |
| 治理 | R1-R20 规则编号（架构原则附录）；RFC→ADR→门禁→文档同步；无兼容包袱；归档不删除 |

### 1.3 为什么要重构（旧实现问题摘要）

旧实现（22 个仓库）存在：插件装载双轨（编辑器内嵌插件源码 + `file://` 动态 import）、单卡渲染协议双实现、卡片/箱子两套编辑架构、频繁拆包重打、非原子写与无锁竞争、God module（8807 行）、多套解析器、主题/i18n 残留、L8/L9 假实现等。详见 `薯片生态文档库/01-架构设计/ADR/ADR-010-大爆炸重构策略.md` 与旧审查材料。
