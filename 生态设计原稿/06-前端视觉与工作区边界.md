# 前端视觉与工作区边界

> task030 修订（2026-08）：主题系统与多语言系统已废弃，本文承接原《06-前端多样化和主题系统》中仍然有效的设计事实（原文见 `归档/06-前端多样化和主题系统.md`）。现行实施口径以 `生态共用技术文档/前端基础/` 为准。

## 视觉口径（task030 后现行）

- 组件库统一使用 **antd（唯一组件库）**，共享前端层为 **`@chips/ui`**（视觉 token、全局样式、运行时与通用组件唯一落点）。
- 视觉样式统一走 `@chips/ui`（`appleTheme`、`global.css`）与 antd 主题定制（`theme.useToken()`）；组件内取色禁止散落硬编码。
- 界面文案一律简体中文直写，不再存在语言包与运行时文案切换机制。
- 图标统一使用 `@ant-design/icons`（替代旧 ChipsIcon + IconDescriptor 体系）；应用启动图标仍由 `manifest.ui.launcher.icon` 与 Host 快捷方式链路负责。

## 前端的多样化（仍然有效）

薯片生态允许同一后端能力对应多个前端实现。应用层可以使用不同的技术栈、不同的交互方式，但必须通过统一协议接入 Host，不能绕开生态底层自行建立一套平行运行时。

前端多样化的边界如下：

- 业务调用统一走 Host 对外接口与 Bridge API；
- 卡片显示统一走 Host 统一卡片显示链路；
- 组件视觉统一走 `@chips/ui` 与 antd 主题定制，不允许在应用层和组件层硬编码一套独立皮肤体系；
- 插件、窗口、配置、日志都必须落在当前工作区内闭环管理。

## 工作区边界（仍然有效）

薯片生态同时存在两类正式工作区：

- `chips`：用户工作区，默认位于 `~/.chips-host`；
- `chipsdev`：开发工作区，默认位于项目链路中的 `.chips-host-dev`。

两类工作区的插件记录与运行状态彼此隔离。开发态看到的结果，只能以开发工作区为准；用户态看到的结果，只能以用户工作区为准。

## Host 内部保留能力说明

- Host 内部保留 `theme` / `i18n` 服务域作为内部能力（服务路由仍严格校验），但**插件侧不再消费**：不再声明 `theme.read/i18n.read` 权限，不再注入主题 CSS 与变量，`theme.list` 无主题包时返回空列表。
- 渲染链路（`card.render`、`card.renderEditor`、`box.renderLayoutFrame` 等）在缺省主题下以空主题上下文降级，不再抛 `THEME_NOT_FOUND`。
- Host 侧主题/多语言服务的完整清理后续单独立项处理。
- 卡片 metadata 的 `theme` 字段按文件格式规范保留（默认为空），当前版本不消费。
