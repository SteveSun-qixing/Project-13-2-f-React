# 阶段三：核心编辑域迁移

## 1. 阶段目标

完成最核心的业务域迁移，使编辑引擎具备基本可用的文件与编辑能力。

## 2. 任务清单

1. 迁移工作区状态模型。
2. 迁移文件打开 / 新建 / 保存 / 导入导出主链路。
3. 迁移编辑域、选中态、命令域和撤销重做骨架。
   - 已落地基础卡片编辑会话模型：选中节点、当前权威配置、脏状态、保存状态、错误状态；
   - 已落地命令域基础实现：配置快照历史、`canUndo/canRedo`、撤销/重做状态迁移；
   - 已落地单测：覆盖会话初始化、配置变更、保存成功/失败、撤销/重做状态切换。
4. 接入基础卡片编辑面板加载机制。
   - 已接入预览 iframe 节点选中 -> `getBaseCard` -> `renderBaseCardEditor` 正式链路；
   - 已接入编辑器 iframe 生命周期事件：`onReady`、`onConfigChange`、`onConfigSynced`、`onFatalError`。
5. 建立自动保存与错误回退机制。
   - 已落地基础卡片配置变更防抖保存；
   - 已落地保存成功后的权威配置回推与预览刷新；
   - 已落地保存失败后的错误态保留与后续继续编辑能力。

## 3. 阶段验收

- 能打开和创建卡片；
- 能编辑并自动保存；
- 撤销重做主链路可用；
- 核心领域具备单测和集成测试。
- 编辑会话状态在工作台中可见并可追踪。

## 4. 工单触发条件

- 正式编辑面板挂载契约不存在；
- 文件写入或卡片保存链路与文档不符；
- 撤销重做无法接入正式工作区状态模型。

## 5. 当前进展（2026-03-11）

- 已落地工作区文档会话 Provider，支持 `.card` 与 `.box` 两类目标文件的统一打开。
- 已接入 `card.parse`、`card.validate`、`card.render` 预览链路与 `box.inspect` 检查链路。
- 已接入最近目标配置持久化与启动上下文目标恢复。
- 已落地工作区目录浏览链路，基于 `file.list/file.stat` 构建根目录与树节点，并接入工作台壳层。
- 已落地设置注册中心，替代壳层中的分散控制按钮，并沉淀为可扩展分类注册表。
- 已落地基础卡片编辑工作台 `BaseCardWorkbench`，在 `.card` 文档预览右侧挂载正式编辑器面板。
- 已落地编辑域会话模型 `BaseCardEditSession`，统一承载选中节点、历史栈、最后保存配置、待保存配置、脏标记、保存状态和错误信息。
- 已落地 `editor-command-service`，使用纯函数维护配置变更、撤销/重做以及保存状态流转。
- 已将编辑会话编排从展示组件中下沉到 `useBaseCardEditingSession`，并通过 `base-card-editor-runtime-service` + `editor-save-scheduler` 固定正式适配边界。
- 已落地自动保存主链路：编辑器配置变更 -> 防抖调度 -> `card.updateBaseCard` -> `syncConfig` 回推 -> 刷新当前预览文档。
- 已落地撤销/重做主链路：按钮触发与 `Cmd/Ctrl+Z`、`Cmd/Ctrl+Shift+Z`、`Cmd/Ctrl+Y` 快捷键均已接入，并覆盖编辑器 iframe 与宿主窗口。
- 已落地会话观测面：编辑面板展示当前基础卡片标题、保存状态、历史统计、脏/净状态，检查器继续展示文档 / 会话 / 运行时摘要。
- 已落地编辑面板治理状态：折叠 / 展开、宽度预设、选中节点时自动展开，且通过 `config.*` 正式持久化。
- 已落地设置中心“编辑面板”治理入口，工作台设置与设置中心共用同一状态来源。

## 6. 阶段内剩余事项

- 补齐编辑链路的集成测试与 Host 联调记录，覆盖自动保存失败恢复、撤销/重做回推和预览刷新一致性。
- 继续评估是否需要把当前单文档编辑会话上提为工作区级 Provider，以承接后续多文档并行编辑与退出前统一 flush。
- 继续完成 `card-package-domain`：基础卡片新增、删除、重排、`metadata.editor_state.mode` 切换、事务回滚与集成测试。

## 7. 架构补充决议（2026-03-11）

- EditingEngine 获准直接使用 Host 的低层 `file.*` / `zip.*` 能力治理 `.card` 文档；
- Host 只需提供宽松、较底层的通用接口，不再为每个编辑动作补专用业务 route；
- 文档级正式约束转移到共享文件格式规范、权限规则和 EditingEngine 自身事务实现；
- 后续开发按“先文档冻结、再代码落地、最后测试收口”执行。
