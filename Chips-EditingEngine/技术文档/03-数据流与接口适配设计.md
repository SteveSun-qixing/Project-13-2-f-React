# 数据流与接口适配设计

> 文档目标：冻结关键工作流的正式链路，避免开发时混入旧项目直连思路

---

## 1. 启动链路

1. Host 装载 `manifest.yaml` 指定的 `dist/index.html`。
2. 页面启动后进入应用 bootstrap。
3. 初始化主题、多语言、日志、错误边界、Bridge 适配层。
4. 拉取工作区初始状态、当前主题、当前语言、必要配置。
5. 进入默认布局并渲染主工作区。

要求：

- 启动链路失败时必须给出可见错误态；
- 禁止假定某个 Host 事件一定先于 React 渲染完成；
- 主题和语言优先从 Host 当前状态拉取，再监听运行时事件变化。

## 2. 文件工作流链路

### 2.1 打开文件

1. 用户通过菜单、工具窗口或拖拽输入文件。
2. 适配层调用 `platform.dialogOpenFile` 或拖拽解析逻辑。
3. 文件域调用 `card.parse` / `card.validate` / `file.*` 等正式接口获取必要数据。
4. 工作区状态更新为“已打开且激活”。
5. 当前布局接收工作区变更并渲染对应内容。

### 2.2 自动保存与文档写回

当前正式链路拆分为两类：

1. 基础卡片编辑器挂载与语义读取：继续使用 `card.getBaseCard`、`card.renderBaseCardEditor`；
2. 单个基础卡片配置保存：继续使用 `card.updateBaseCard`，复用 Host 已有插件序列化能力；
3. 文档结构写入与模式切换：使用 `card-package-domain`，内部复用 `zip.extract` + `file.*` + `zip.compress`。

文档写回正式链路（2026-03-11 调整后）：

1. 预览 iframe 通过 `chips.composite:node-select` 选中基础卡片节点；
2. 编辑引擎调用 `card.getBaseCard(cardFile, nodeId)` 获取当前基础卡片权威配置，并创建本地编辑会话；
3. 编辑引擎调用 `card.renderBaseCardEditor({ cardFile, nodeId })` 挂载正式编辑器 iframe；
4. 编辑器通过 `chips.basecard-editor:config-change` 上报标准化配置；
5. 编辑域先更新本地历史快照与脏状态，再进入防抖保存调度；
6. 防抖期满后，保存调度器仍调用 `card.updateBaseCard`，由 Host 完成插件级配置序列化与单节点写回；
7. 对新增、删除、重排和查看/编辑模式切换，则由 `card-package-domain` 负责解压 `.card`、改写正式文件、重新打包并清理临时目录；
8. 写回成功后，编辑引擎通过 `sync-config` 回推权威配置，并刷新当前预览文档；
9. 若保存失败，编辑面板进入错误态，保留当前选中节点、历史栈和未保存配置，等待下一次变更或手动刷新。

`card-package-domain` 承接：

- 新增基础卡片；
- 删除基础卡片；
- 调整基础卡片顺序；
- 切换 `metadata.yaml.editor_state.mode`。

约束：

- ZIP/文件系统细节只能位于 `src/domains/card-package/**`；
- React 组件不得直接改写临时目录；
- 工作区级统一保存队列仍是后续优化项，但单文档事务边界必须先完整闭环。

### 2.3 当前已落地的工作区文件会话基线

- 当前阶段已建立 `WorkspaceSessionProvider`，负责工作区打开文档、激活文档、关闭文档、最近目标持久化。
- 文件选择统一通过 `platform.dialogOpenFile`。
- `.card` 文件通过原始 route 包装服务调用 `card.parse`、`card.validate`、`card.render`，生成正式预览数据。
- `.box` 文件通过原始 route 包装服务调用 `box.inspect`，生成箱子摘要视图。
- 最近目标通过 `config.get/config.set` 存储在 `editing-engine.workspace.recent-targets`。
- 工作区目录浏览通过 `file.list` + `file.stat` 构建根目录与树节点，由 `workspace-repository-service.ts` 统一装配。
- 资源树节点点击文档后继续复用 `WorkspaceSessionProvider.openDocument()`，避免目录树和会话树分叉。

### 2.4 当前已落地的设置注册中心基线

- 设置中心采用注册中心模型，当前内置 `workspace/editor/layout/theme/locale/runtime` 六类面板。
- 布局、主题、语言三个治理入口全部通过正式运行时 Provider 转发到 `config.*`、`theme.*`、`i18n.*`。
- 设置面板定义与展示顺序集中维护在 `src/features/settings/editor-settings-registry.tsx`，避免壳层页面堆叠硬编码按钮。

### 2.5 当前已落地的编辑面板治理基线

- 编辑面板治理状态由 `EditorPanelProvider` 统一维护，不再散落在 `BaseCardWorkbench` 的局部状态中；
- 当前治理状态字段：
  - `collapsed`
  - `widthPreset`
  - `autoOpenOnSelection`
- 当前通过 `config.get/config.set(editing-engine.editor.panel-state)` 持久化；
- 工作台、检查器、设置中心三处共享同一状态来源；
- 当 `autoOpenOnSelection === true` 且面板已收起时，预览选中基础卡片会先展开面板，再进入正式编辑会话链路。

### 2.6 当前已落地的基础卡片编辑会话基线

- 当前编辑会话模型为 `BaseCardEditSession`，包含：
  - `selectedNode`
  - `baseCard`
  - `history.past/present/future`
  - `historyLimit`
  - `lastCommand`
  - `lastSavedConfig`
  - `pendingSaveConfig`
  - `dirty`
  - `saveState`
  - `error`
- 当前命令域采用纯函数形式维护配置编辑历史，而不是在 UI 层直接拼接撤销/重做逻辑。
- 当前会话编排位于 `useBaseCardEditingSession`，并通过 `base-card-editor-runtime-service` 固定正式 SDK 适配边界。

## 3. 编辑链路

### 3.1 选中基础卡片

1. 用户在主视图中选中某基础卡片。
2. 编辑域更新当前选中对象。
3. 预览 iframe 通过 `chips.composite:node-select` 返回 `nodeId / cardType / pluginId / title`。
4. 编辑引擎调用 `card.getBaseCard` 获取权威配置，初始化本地编辑会话。
5. 编辑引擎调用 `card.renderBaseCardEditor`，由 Host 生成基础卡片编辑器 iframe 文档并挂载。
6. 编辑器准备就绪后，通过 `onReady` / `onFatalError` / `onConfigSynced` 事件维持加载态与异常态。

### 3.2 变更内容

1. 编辑面板发出 `chips.basecard-editor:config-change`。
2. 编辑域通过 `applyConfigChange()` 记录当前节点的最新标准化配置，并把会话标记为 `dirty + pending`。
3. 保存调度器进入防抖期，并准备对当前节点执行 `card.updateBaseCard`。
4. `card.updateBaseCard` 成功后，编辑引擎通过 `markSaveSucceeded()` 更新权威配置，再通过 `chips.basecard-editor:sync-config` 回推规范化后的权威配置。
5. 主视图刷新当前 `.card` 预览。
6. 若保存失败，编辑域通过 `markSaveFailed()` 保留当前会话与未保存变更，并在界面上暴露失败状态。

### 3.3 撤销 / 重做

当前正式链路（2026-03-11 已落地）：

1. 用户通过按钮或快捷键触发撤销 / 重做；
2. 工作台根据当前会话分别调用 `undoConfigChange()` / `redoConfigChange()`；
3. 编辑引擎通过 `chips.basecard-editor:sync-config` 将历史快照回推到基础卡片编辑器 iframe；
4. 回推后的配置继续复用同一自动保存链路，由 Host 写回文件；
5. 保存成功后刷新预览，保持预览区与编辑器中的权威配置一致。

当前快捷键范围：

- `Cmd/Ctrl + Z`
- `Cmd/Ctrl + Shift + Z`
- `Cmd/Ctrl + Y`

当前绑定范围：

- 编辑引擎宿主窗口；
- 已挂载的基础卡片编辑器 iframe。

### 3.4 会话观测面

当前已落地的用户可见观测面：

- 编辑面板状态栏展示当前基础卡片标题、保存状态、历史统计、脏 / 净状态；
- 编辑错误通过编辑区域错误条展示；
- 检查器继续展示文档、会话、运行时摘要，承接工作区级上下文观测；
- 预览刷新与编辑器权威配置回推形成可见闭环。

当前未落地的观测项：

- 结构化 traceId / telemetry 日志；
- 工作区级统一保存队列观测；
- 多文档或多基础卡片并发编辑观测。

### 3.5 结构编辑与模式切换

1. 新增/删除/重排/模式切换命令统一进入 `card-package-domain`；
2. 命令服务在临时目录中改写 `structure.yaml`、`content/*.yaml`、`metadata.yaml.editor_state.mode`；
3. 重打包成功后刷新当前工作区文档，并根据结果修正选中节点、脏状态与撤销/重做快照；
4. 若任一文件步骤失败，命令服务必须丢弃临时目录并维持原始文档不变。

## 4. 布局链路

### 4.1 布局切换

1. 用户触发布局切换。
2. 布局域持久化当前布局快照。
3. 工作区保持打开文件与激活上下文不丢失。
4. 切换到新布局渲染器。
5. 工具窗口和编辑上下文按新布局规则恢复。

### 4.2 工具窗口协同

- 文件管理器、编辑面板、卡箱库、程序坞必须共享统一工作区上下文。
- 工具窗口的显示状态与位置状态属于布局域或窗口域，不应散落在组件局部状态中。

当前实现补充（2026-03-11）：

- 工作台中的编辑面板折叠 / 展开与宽度预设已经具备正式状态来源；
- 该状态尚未提升为“跨布局共享的完整窗口治理模型”，后续进入无限画布与更多工具窗口时仍需继续抽象。

## 5. 主题与多语言链路

### 5.1 主题链路

1. 启动时读取 `theme.getCurrent()`。
2. 使用 `ChipsThemeProvider` 挂载主题上下文。
3. 监听 `theme.changed` 事件。
4. 原生窗口视觉与 Web 内容视觉保持同一主题快照。

### 5.2 多语言链路

1. 启动时读取 `i18n.getCurrent()` 和本地语言包。
2. 建立翻译函数与运行时上下文。
3. 监听 `language.changed` 事件。
4. 语言切换后重渲染界面。

## 6. 错误与日志链路

- 错误对象必须标准化，至少包含错误码、消息、上下文。
- 日志应记录 traceId、模块名、动作名、关键 payload 摘要。
- 用户态错误提示与开发态调试日志分离。

当前实现补充（2026-03-11）：

- 当前编辑链路已具备用户可见错误态，但尚未接入结构化 trace 级日志；
- 因此“会话观测面”当前以界面状态观测为主，不应误判为日志治理已经完成。

## 7. 当前需要重点验证的适配点

1. 基础卡片选中、编辑器挂载、自动保存与预览刷新链路是否在真实 Host 运行时保持一致；
2. 当前已接入的撤销/重做回推链路在真实 Host 中，`sync-config / config-synced` 是否稳定承接频繁历史回放；
3. 布局切换所需状态恢复点是否在当前生态文档中已有明确定义；
4. 多窗口与工具窗口治理是否完全满足编辑引擎需求；
5. 是否需要正式生态提供更上层的统一保存调度 / 退出前 flush 能力，以支撑后续多文档编辑。

若上述任一点在实现前确认不存在正式能力，则必须先提工单。
