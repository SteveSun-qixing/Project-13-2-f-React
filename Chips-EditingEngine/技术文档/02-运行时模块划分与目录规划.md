# 运行时模块划分与目录规划

> 文档目标：提前冻结推荐目录结构与模块边界，避免迁移过程中目录失控、职责混乱

---

## 1. 当前工程状态

本项目已使用官方应用插件脚手架完成初始化，当前具备：

- `manifest.yaml`
- `package.json`
- `src/` React 基线
- `config/`
- `i18n/`
- `tests/`

后续开发将基于该骨架逐步扩展，而不是重新搭一套工程结构。

截至 2026-03-11，围绕核心编辑域已经形成首批正式落地结构：

- `src/app/providers/`：运行时 Provider、工作区会话 Provider、工作区资源树 Provider；
- `src/domains/workspace/`：工作区文档与资源树纯业务模型；
- `src/domains/editor/`：基础卡片编辑会话类型与配置历史 / 保存状态纯函数；
- `src/features/editor/`：基础卡片编辑工作台；
- `src/features/shell/`：工作台壳层、检查器、标签页与容器布局；
- `src/shared/runtime/`：当前阶段的运行时 route 包装与 i18n / runtime helper。

说明：

- 由于当前工程仍处于阶段三，`shared/runtime/` 暂时承担了原建议结构中一部分 `bridge/` 职责；
- `domains/editor/` 当前同时承载编辑会话与配置历史命令逻辑，尚未进一步拆分出独立 `domains/commands/` 目录。

## 3. 模块边界说明

### 3.1 `app/`

- 只放应用初始化、Provider、根壳层、全局错误边界。
- 不放具体业务规则。

### 3.2 `bridge/`

- 负责所有 Host / SDK 调用适配。
- 对上层暴露稳定、类型明确的接口。
- 禁止业务模块直接散落调用 `window.chips.invoke`。

当前落地映射：

- 当前工程使用 `src/shared/runtime/editor-route-service.ts` 承接 route 包装；
- 当前工程使用 `src/shared/runtime/base-card-editor-runtime-service.ts` 固定基础卡片编辑器的 Host / SDK 适配边界；
- 当前工程通过 `EditorPanelProvider` + `config.*` 管理编辑面板折叠、宽度和自动展开治理状态；
- 后续若出现更多编辑器能力，可继续沿同一方向补齐正式 bridge / adapter 层，而不是回退到 feature 直连 SDK。

### 3.3 `domains/`

- 放纯业务域逻辑、状态模型、命令对象、用例函数。
- 尽量不感知 UI 组件结构。

当前落地映射：

- `src/domains/workspace/`：文档类型、工作区树、最近目标等纯数据模型；
- `src/domains/editor/types.ts`：`BaseCardEditSession`、保存状态、历史快照类型；
- `src/domains/editor/editor-command-service.ts`：配置变更、撤销/重做、保存状态流转纯函数；
- `src/domains/editor/editor-save-scheduler.ts`：基础卡片配置防抖保存、串行化 flush 规则。

### 3.4 `features/`

- 承载面向用户的功能组合单元。
- 允许组合多个 domain，但不允许重新实现底层适配。

当前落地映射：

- `src/features/editor/BaseCardWorkbench.tsx` 保持渲染壳层职责，组合预览区、编辑区和状态展示；
- `src/features/editor/useBaseCardEditingSession.ts` 负责编辑会话应用层编排、选择切换、保存调度、快捷键与 iframe 生命周期；
- `src/features/settings/panels/EditorPanelSettingsPanel.tsx` 与设置对话框中的 editor tab 共享同一编辑面板治理状态；
- `src/features/shell/EditorShell.tsx` 负责工作台级拆栏、检查器和设置中心入口；
- `src/features/workspace/` 与 `src/features/settings/` 已分别承接资源树和设置中心等组合能力。

### 3.5 `components/`

- 以通用界面组件为主。
- 优先组合组件库，不重复实现生态已有组件。

## 4. 状态管理建议

首版状态模型建议分三层：

1. 运行时上下文状态：主题、语言、Bridge 就绪状态、权限快照；
2. 工作区状态：当前文件、打开项、脏状态、选中对象、布局模式；
3. 功能子域状态：拖拽态、命令栈、面板展开态、窗口停靠态。

要求：

- 业务状态与 UI 瞬时状态分离；
- 自动保存、撤销重做、布局切换相关状态必须可追踪；
- 不允许所有状态都堆进单一根 store。

截至 2026-03-11 的实际落地分层：

1. 运行时上下文状态：`EditorRuntimeProvider`；
2. 工作区会话状态：`WorkspaceSessionProvider`；
3. 资源树状态：`WorkspaceExplorerProvider`；
4. 编辑面板治理状态：`EditorPanelProvider`，统一承接折叠、宽度预设、自动展开并持久化到 `config.*`；
5. 编辑会话状态：由 `useBaseCardEditingSession` 组合 `BaseCardEditSession`、保存调度器、运行时适配层，并把快照上送到 `EditorShell` 检查器。

当前阶段判断：

- `BaseCardEditSession` 已把基础卡片编辑链路中的脏状态、保存状态、历史状态沉淀为可测试的数据结构；
- 编辑面板治理状态已经从组件局部状态中抽离，可在工作台与设置中心之间共享；
- 撤销/重做与自动保存已经具备可追踪状态，且保存调度、快捷键绑定、编辑器适配编排已从展示组件中抽离；
- 下一步应评估是否把当前 hook 级编辑会话进一步上提为工作区级 Provider，以支撑多文档并行编辑与更统一的退出前 flush。

## 5. 旧项目代码迁移组织策略

- 旧项目中可复用的逻辑先按业务域拆分，再决定是否迁入 `domains/`。
- 旧项目中的 Vue 组件结构不直接照搬到 `features/`，需先抽取行为和状态模型。
- 旧项目中与 Electron / preload / 本地文件系统强绑定的逻辑不迁移，直接重写。

## 6. 文档与代码同步规则

- 新增正式目录前，先更新本文件。
- 若后续需要新增横切模块，例如 `telemetry/` 或 `perf/`，必须先说明职责边界，避免目录泛滥。
- 若阶段内先以现有目录承接推荐模块职责，必须在本文件注明“当前落地映射”和后续拆分时机，避免文档仍停留在纯理想结构。

## 6. 新增模块规划（2026-03-11）

为承接新的低层文档治理方案，运行时目录补充如下：

- `src/domains/card-package/`：`.card` 解压、读写、重打包、临时目录清理、事务回滚；
- `src/domains/card-package/codecs/`：`metadata.yaml`、`structure.yaml`、`content/*.yaml` 编解码；
- `src/domains/card-package/commands/`：基础卡片新增、删除、重排、模式切换命令；
- `src/shared/runtime/editor-route-service.ts`：补齐 `file.*` / `zip.*` 运行时适配；
- `src/features/editor/`：挂接结构编辑 UI 与文档模式治理 UI。

目录边界要求：

- 直接文件治理逻辑不得散落在 React 组件中；
- UI 只能调用命令服务，不直接拼接 ZIP/文件系统细节；
- 解析/编码逻辑必须可单测，不依赖 DOM。
