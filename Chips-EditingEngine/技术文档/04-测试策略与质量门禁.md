# 测试策略与质量门禁

> 文档目标：提前规划迁移期测试结构，确保后续不是“先写代码，最后补测试”

---

## 1. 测试分层

### 1.1 单元测试

覆盖：

- 领域命令；
- 状态转换；
- 保存调度器；
- 错误映射；
- 文件输入解析；
- 布局状态恢复算法。

### 1.2 集成测试

覆盖：

- 工作区 + 文件域联动；
- 编辑面板 + 命令域 + 自动保存链路；
- 布局切换 + 工具窗口恢复；
- 主题 / 多语言运行时刷新。

### 1.3 端到端测试

覆盖：

- Host 启动编辑引擎；
- 打开卡片；
- 编辑并自动保存；
- 拖拽创建；
- 布局切换；
- 撤销重做；
- 设置变更生效。

## 2. 迁移专项测试清单

### 2.1 旧功能回归测试

每迁移一个旧项目能力，都需要补：

- 最小单测；
- 至少一个集成或 E2E 验证；
- 对应迁移矩阵项的结果记录。

### 2.2 生态适配测试

重点验证：

- Host 窗口打开与主题同步；
- Bridge 调用错误处理；
- 多语言切换事件；
- 文件对话框与拖拽输入；
- `chipsdev build/test/validate` 全链路。

## 3. 阶段性质量门禁

### 阶段一：文档冻结

- 需求、技术、计划文档完成；
- 风险点被识别；
- 工单阻断规则明确。

### 阶段二：壳层与适配层

- 基础工程能运行在 Host 中；
- 主题、多语言、日志、错误边界接通；
- 基础测试框架可运行。

### 阶段三：核心业务迁移

- 文件主链路、编辑主链路、自动保存、撤销重做闭环；
- 单测和集成测试覆盖核心域。

### 阶段四：布局与交互迁移

- 双布局、工具窗口、拖拽、快捷键闭环；
- E2E 覆盖主要使用路径。

### 阶段五：验收与发布准备

- 所有门禁通过；
- 文档与实现一致；
- 没有开放状态的阻断工单；
- 满足合并回 `develop` 条件。

## 4. 当前阶段执行原则

- 测试文件结构从现在开始就按正式分层组织。
- 若某一能力暂未实现，其测试用例也不允许写成“永远跳过”的占位用例。
- 若需要新增测试工具，而该工具不在技术选型中，必须先提工单并等待确认。
