# 功能需求与旧项目迁移矩阵

> 文档目标：把旧项目“已有正确业务能力”映射到新生态正式实现方式，确保迁移不丢功能、不走错底层

---

## 1. 旧项目能力基线

根据 `归档/Chips-Editor` 现有代码、README、需求文档和技术文档，旧项目已具备以下能力域：

补充迁移口径（2026-03-12 冻结）：

- 迁移以旧项目上层行为为基线，要求优先复制旧项目上层代码与模型，再将底层依赖替换为新生态正式接口；
- 不接受“看起来类似但交互语义不同”的新实现；
- 已完成的新壳层能力必须继续保留，但只能作为底层承载与适配基座，不得替代旧项目原本的产品语义。

1. 编辑器主壳层与双布局切换；
2. 文件管理器、卡箱库、编辑面板、程序坞；
3. 复合卡片窗口、封面窗口、箱子窗口；
4. 拖拽、快捷键、撤销重做；
5. 自动保存、主题切换、多语言、设置；
6. 集成测试、性能测试、Vitest 体系；
7. Electron 主进程、preload、本地文件服务等旧底层实现。

迁移原则是：

- 保留前六类上层业务目标；
- 重构第七类底层实现，替换为新生态正式机制。

## 2. 新架构下的正式能力映射

| 旧项目能力 | 新生态正式落点 | 本项目要求 |
|---|---|---|
| Electron 主进程 / preload | `Chips-Host` 主机运行时 | 从应用仓删除独立主进程职责 |
| 本地 SDK Connector | `window.chips.*` + `chips-sdk` | 统一走 Bridge / Runtime Client |
| 本地窗口管理器 | `window.open` / `window.*` 动作 | 接入 Host 窗口机制 |
| 本地文件服务 | `file.*` / `platform.dialog*` / `card.*` | 使用正式文件与卡片服务 |
| 自维护主题切换 | `theme.*` + `ChipsThemeProvider` | 主题状态与 CSS 统一来自 Host |
| 自维护 i18n 服务 | `i18n.*` + 本地语言包 | 语言切换遵循正式事件与加载链 |
| 组件与样式 | `@chips/component-library` + 主题 token | 不允许硬编码视觉旁路 |
| 本地设置存储 | `config.*` / `storage.*` | 运行时治理与设置读写走正式服务 |

## 3. 功能需求分组

### 3.1 编辑器壳层需求

- 应提供稳定的应用壳层、导航区域、内容区域和工具窗口挂载区。
- 应接入 Host 主题、多语言、日志、错误边界。
- 应为多布局和多窗口扩展预留正式模块边界。

### 3.2 文件工作流需求

- 支持打开卡片、创建卡片、创建箱子、重命名、删除、导入、导出。
- 支持系统文件拖拽进入编辑器。
- 自动保存必须具备正式脏状态管理、保存节流和错误回退提示。

当前已落地范围（2026-03-11）：

- `.card` / `.box` 文件打开、激活、关闭、最近目标持久化已落地；
- 基础卡片编辑配置自动保存已落地，当前以基础卡片配置链路为主，不覆盖新建 / 导入导出；
- 自动保存已具备脏状态、保存中、保存成功、保存失败等用户可见状态；
- 保存成功后会刷新当前预览文档，保存失败后保留当前编辑会话并允许继续修改或手动刷新。

### 3.3 编辑能力需求

- 支持根据基础卡片类型加载对应编辑面板。
- 支持复合卡片内基础卡片增删改序。
- 支持查看/编辑锁定状态切换。
- 支持撤销重做与快捷键。

当前已落地范围（2026-03-11）：

- 已支持在复合卡片预览中选中基础卡片后加载对应正式编辑器 iframe；
- 已支持基础卡片配置编辑的会话化状态管理，包括选中节点、权威配置、历史栈、脏状态、保存状态和错误状态；
- 已支持基础卡片配置编辑范围内的撤销/重做与快捷键；
- 已支持编辑面板中的会话观测面，展示保存状态、历史计数、脏/净状态；
- 复合卡片内基础卡片增删改序、锁定状态切换已进入当前正式迁移范围，采用 `file.* + zip.* + 卡片文件格式规范` 的低层文档治理方案实现。

### 3.4 布局与窗口需求

- 支持无限画布布局和工作台布局作为首批迁移目标。
- 布局切换时保持已打开文件与编辑上下文。
- 工具窗口支持收起、最小化、恢复、重新聚焦。
- 复合卡片窗口、封面窗口与工具窗口必须统一纳入 Host 窗口治理模型。

### 3.5 体验系统需求

- 所有正式文案必须接入多语言资源。
- 所有视觉必须遵循主题系统和组件库标准。
- 错误要使用统一错误模型，并以用户可理解方式展示。
- 日志要可追踪关键链路：启动、文件、拖拽、保存、窗口、布局切换。

## 4. 迁移优先级矩阵

### P0：不完成不能进入可用状态

- 应用壳层与 Host 启动链路；
- 文件打开 / 创建 / 保存主链路；
- 编辑面板挂载主链路；
- 基础主题 / 多语言 / 日志 / 错误处理接入；
- 基础单测、集成测试和运行校验。

截至 2026-03-11 的完成快照：

- 文件打开主链路已完成；
- 基础卡片编辑面板挂载主链路已完成；
- 基础卡片配置自动保存主链路已完成；
- 对应领域单测已补齐编辑命令域核心状态迁移；
- 创建 / 导入导出与编辑链路集成测试仍待补齐。

### P1：不完成不能达到旧项目等效体验

- 无限画布布局；
- 工作台布局；
- 旧窗口模型（聚焦、最小化、恢复、拖拽、工具窗口职责分层）；
- 拖拽与快捷键；
- 撤销重做；
- 文件管理器、程序坞、卡箱库。

截至 2026-03-11 的完成快照：

- 工作台布局基础壳层已完成；
- 编辑域快捷键与撤销/重做已在基础卡片配置编辑范围内接通；
- 无限画布、多类型拖拽、完整文件管理器 / 程序坞 / 卡箱库仍在后续范围。

### P2：首版完成前尽量补齐

- 封面工作流；
- 高级设置项；
- 更细粒度性能优化；
- 更完整的国际化文案覆盖和体验微调。

## 5. 验收矩阵

### 5.1 功能验收

- 每一项旧项目核心功能都要有“新实现位置 + 测试用例 + 验证结果”。
- 任何无法按正式生态链路实现的功能都不能用临时代码替代。

### 5.2 迁移验收

- 新工程中不得继续保留旧项目的独立 Electron 主进程代码。
- 新工程中不得继续保留直连 Node 文件系统的运行时业务调用。
- 新工程必须在 Host 环境中完成联调。

### 5.3 文档验收

- 功能需求必须可追溯到旧项目能力与生态设计文档。
- 技术设计必须可追溯到 Host / SDK / Bridge / 主题 / i18n 正式文档。
- 开发计划必须能落到可执行任务粒度。
