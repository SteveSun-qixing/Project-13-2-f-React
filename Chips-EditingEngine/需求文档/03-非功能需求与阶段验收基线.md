# 非功能需求与阶段验收基线

> 文档目标：冻结质量门槛，避免后续为了赶进度牺牲稳定性和架构质量

---

## 1. 架构质量基线

### NFR-ARCH-001 层次依赖

- 仅允许编辑引擎应用层依赖生态公开契约、SDK、组件库及本项目内部模块。
- 禁止在应用层直接耦合 Host 私有实现细节。
- 禁止在项目内自建第二套 Bridge、主题系统、多语言系统或窗口系统。

### NFR-ARCH-002 模块化与复用

- 业务模块应按壳层、工作区、布局、工具窗口、编辑域、文件域、桥接适配层拆分。
- 模块边界必须清晰，禁止“大一统 store / utils / service”继续膨胀。
- 新增抽象必须能服务长期复用，不允许为了当前任务写一次性胶水层。

### NFR-ARCH-003 无临时实现

- 不允许占位组件、假实现、模拟成功、空壳 API 适配。
- 若生态能力缺失导致正式实现不可完成，必须提工单并暂停。

## 2. 稳定性与性能基线

### NFR-RUN-001 启动稳定性

- 应用在 `chipsdev run` 与正式 Host 安装运行两种场景下都必须可稳定启动。
- 首屏不能依赖脆弱的竞态初始化顺序。

### NFR-RUN-002 自动保存稳定性

- 自动保存必须具备失败提示、重试策略或用户可感知的异常状态。
- 不能因为单次保存失败导致整个编辑状态静默丢失。

### NFR-RUN-003 性能要求

- 首屏加载、布局切换、拖拽、面板切换和撤销重做必须保持可接受交互延迟。
- 大文件或多窗口场景下要有明确性能观测点与后续优化策略。

## 3. UI 与体验基线

### NFR-UX-001 主题系统

- 不允许硬编码正式视觉值绕过主题系统。
- 原生窗口背景、标题栏、页面壳层、组件状态都必须接入主题链路。

### NFR-UX-002 多语言系统

- 所有正式用户文案必须走语言包。
- 语言切换后必须在运行时生效，禁止靠重启应用刷新。

### NFR-UX-003 可维护交互

- 快捷键、拖拽、面板焦点、窗口操作必须具备统一交互模型。
- 复杂交互场景必须补测试，而不是只靠人工回归。

## 4. 测试与发布门禁

### NFR-TEST-001 基础门禁

以下任一未通过，不得进入合并阶段：

- `npm run lint`
- `npm test`
- `npm run build`
- `npm run validate`

### NFR-TEST-002 迁移专项门禁

在进入“可审核首版”前，至少应具备：

- 旧项目核心功能迁移矩阵的逐项验收记录；
- Host 联调记录；
- 关键工作流的集成测试；
- 关键交互的回归测试；
- 主题 / 多语言 / 文件 / 拖拽 / 自动保存专项验证。

### NFR-TEST-003 文档门禁

- 需求文档、技术文档、开发计划未更新，不得合并实现代码。
- 若实现与文档不一致，先修正文档或方案，再继续提交代码。

## 5. Git 与协作规范

### NFR-GIT-001 分支策略

- 当前任务分支采用 `codex/` 前缀命名。
- 仅在通过当前阶段门禁后，才允许合并回 `develop`。

### NFR-GIT-002 变更边界

- 当前阶段仅修改 `Chips-EditingEngine` 及必要文档。
- 不得回滚用户已有未归因变更。
- 不得修改与当前任务无关的仓库目录。

### NFR-GIT-003 归档规则

- 若需要移除或替换文件，必须迁移到归档目录，不得直接删除。

## 6. 工单阻断规则

出现以下任一情况，必须先提工单并停止相关开发：

1. 组件库缺失正式所需组件；
2. SDK 接口与文档不符，无法支持正式链路；
3. Host 窗口、文件、卡片、设置、主题、多语言链路存在正式缺口；
4. 脚手架模板存在结构性错误，导致新工程无法按生态标准推进；
5. 出现只能通过临时兼容代码解决的问题。

## 7. 当前审核结论要求

只有在本文件约定被明确认可后，才进入正式迁移开发。
