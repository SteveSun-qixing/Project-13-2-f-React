# 编辑引擎迁移项目需求总览

> 文档状态：待审核基线稿
> 当前目标：先冻结迁移方向、约束和验收基线，经审核后再进入正式开发

---

## 1. 项目背景

旧项目 `Chips-Editor` 已完成较完整的上层业务能力，但其底层运行方式、通信机制、窗口机制、文件机制与当前薯片生态的正式架构已经不一致：

- 旧项目是独立 Electron + Vue 应用，自带主进程、preload 和本地运行时；
- 新生态要求编辑引擎作为 `type: app` 的应用插件运行在 `Chips-Host` 内部；
- 新生态要求统一通过 Host 的 Bridge、服务域、主题系统、多语言系统、文件/窗口协议和 SDK 封装接入底层能力；
- 用户体验目标是不改变原有产品能力和使用结果，但底层实现必须完全迁移到新生态标准之上。

因此，本项目不是“继续维护旧工程”，而是“以新架构重建编辑引擎应用插件，并迁移旧工程成熟业务能力”。

## 2. 北极星目标

### 2.1 产品目标

交付一个可在薯片主机中正式运行的编辑引擎应用插件，使用户在功能层面获得与旧编辑器一致或更好的体验，包括但不限于：

- 卡片创建、打开、编辑、删除、导入、导出；
- 多布局工作模式；
- 复合卡片窗口、封面窗口、工具窗口、编辑面板；
- 拖拽创建、拖拽排序、外部文件拖入；
- 自动保存、撤销重做、搜索、设置、主题、多语言。

### 2.2 架构目标

交付一个面向未来长期发展的编辑引擎应用插件架构，满足：

- 底层能力不在应用仓中重复实现，而是复用 Host / SDK / 组件库 / 生态服务；
- 上层业务域高度模块化、可替换、可测试、可扩展；
- 布局、工具窗口、编辑面板、文件工作流之间低耦合；
- 不做旧版兼容回退、不保留双架构并存、不允许临时绕过链路。

## 3. 范围定义

### 3.1 本期纳入范围

1. 使用官方应用插件脚手架初始化 `Chips-EditingEngine` 工程。
2. 编写需求文档、技术文档、开发计划，并冻结首版迁移方案。
3. 基于旧项目能力清单，建立逐项迁移矩阵和验收标准。
4. 后续开发阶段迁移以下正式能力：
   - 编辑引擎应用壳层；
   - 布局系统；
   - 工具窗口体系；
   - 文件工作流与自动保存；
   - 编辑面板与基础卡片编辑接入；
   - 拖拽、撤销重做、搜索、设置；
   - 主题、多语言、日志、错误处理、测试。

### 3.2 本期明确不纳入范围

- 旧版架构兼容层、双栈运行时、回退机制；
- 未在生态技术选型中的新第三方库引入；
- 超出编辑引擎项目边界的 Host / SDK / 组件库正式能力扩展实现；
- 任何“先在本项目临时补一个底层能力，以后再替换”的过渡性方案。

## 4. 强制约束

### 4.1 架构约束

- 编辑引擎必须作为应用插件运行，不再保留独立 Electron 主进程架构。
- 所有系统能力必须走 `window.chips.*` / SDK / Host 服务域，不允许越层直连。
- 运行时主实现归 Host，SDK 只做封装与开发辅助，应用仓不重复实现 Bridge 主链路。
- 组件视觉必须接入薯片主题系统，禁止硬编码全局视觉常量绕过主题。
- 所有界面文案必须接入多语言资源，不允许直接在界面内留下正式中文硬编码。

### 4.2 交付约束

- 不允许临时版、简化版、占位版。
- 不允许删除文件；如需移除，只能迁移到归档目录。
- 任务必须在任务分支上推进，并在门禁通过后合并回 `develop`。
- 若发现生态正式缺口，先提工单、建任务文件夹、记录详情，然后停止当前相关开发。

## 5. 干系人和依赖关系

### 5.1 直接干系模块

- `Chips-EditingEngine`：业务壳层、迁移主体、文档与测试。
- `Chips-Host`：窗口、服务域、运行时、插件装载。
- `Chips-SDK`：Bridge 类型封装、开发工具链、统一接口。
- `Chips-ComponentLibrary`：无头组件与主题消费入口。
- `Chips-Scaffold/chips-scaffold-app`：应用插件初始化基线。

### 5.2 外部约束文档

本项目必须严格遵守：

- 插件开发规范；
- Manifest 规范；
- Bridge API 规范；
- Host 对外接口基线；
- 多语言规范；
- 主题接口规范；
- 运行时设置治理接口标准；
- 编辑引擎设计原稿。

## 6. 成功标准

迁移项目只有同时满足以下条件，才算完成：

1. 新编辑引擎在 Host 内可正常启动、创建窗口并完成主要工作流。
2. 旧项目核心功能被完整迁移，并通过明确测试验证。
3. 所有能力均通过正式生态链路实现，没有临时绕过。
4. 架构文档、需求文档、开发计划、测试基线完整可追溯。
5. `lint`、`test`、`build`、`validate` 及后续集成验收全部通过。

审核通过后，再进入正式代码迁移与架构落地阶段。
