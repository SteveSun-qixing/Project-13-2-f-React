# 富文本编辑器界面壳与视觉基线

> 本文档描述重构后的界面壳实现。主题系统与多语言系统已随生态 task030 规范废弃：界面统一使用共享层 `appleTheme` 的单一苹果风格，文案全部简体中文直写。

## 1. 界面结构

首版界面由以下正式元素组成：

1. Electron 原生窗口标题栏；
2. 中央连续正文编辑区；
3. 按需出现的信息弹窗（antd `Modal`）与底部轻提示。

常驻页面不保留额外文件信息条或底部状态栏。正文承载区内部只放正式富文本基础卡片编辑器 iframe，不再额外套纸张式卡片壳。

## 2. 应用壳与命令编排

### 2.1 AppRoot

`AppRoot` 串联 antd `ConfigProvider(theme={appleTheme}, locale={zhCN})`、antd `App`、共享层 `ChipsProvider` 与 `CommandProvider`，作为全应用唯一 Provider 根。

### 2.2 AppChrome

`AppShell` 使用共享层 `AppChrome` 渲染：

1. `CommandPalette`：命令面板，快捷键 `Mod+Shift+P`（预览命令保留 `Mod+P`）；
2. 内容区挂载 `RichTextEditorScene`。

应用窗口顶部不再渲染菜单栏（`MenuBar`）与工具栏（`Toolbar`），文件 / 查看 / 编辑 / 格式四类命令统一收口到命令面板与快捷键。

### 2.3 命令本地化

命令定义在 `src/commands/rich-text-editor-commands.tsx`，模型为共享层 `CommandItem`（id / title / shortcut / icon / group / menuId / toolbarId / enabled / keywords / run）。`useRichTextEditorCommands()` 通过 `useCommandRegistry().register(...)` 注册：

- 文件组：新建、打开、保存、另存为、导出；
- 查看组：预览、当前信息；
- 编辑与格式组：撤销、重做、查找、格式，保持禁用，由富文本基础卡片编辑器内部接管具体输入行为，`run` 仅给出提示。

快捷键（Mod+N / Mod+O / Mod+S / Mod+Shift+S / Mod+P / Mod+Z / Mod+Shift+Z / Mod+F）由共享层 `useCommandShortcuts` 分发，`enabled: false` 的命令不参与快捷键拦截。

## 3. 信息弹窗与轻提示

### 3.1 信息弹窗

信息弹窗使用 antd `Modal` + `Descriptions` 展示三组正式信息：

1. 当前卡片：标题、文件路径、`cardId`、`baseCardId`、创建与修改时间；
2. 富文本：正文格式、存储方式、正文资源路径、正文语言、正文主题、资源计数；
3. 运行时：保存状态、编辑器状态、自动保存状态、上次保存时间。

### 3.2 轻提示

- 打开中、保存中、保存成功、保存失败等状态使用底部轻提示反馈；
- 成功与普通提示自动消失，错误提示保留直到后续状态覆盖；
- 状态提示刷新不得触发编辑器 iframe 重建。

## 4. 视觉基线

- 应用背景使用 `@chips/ui` 导出的 `appleTheme` token（`colorBgBase: #f5f5f7`、`colorPrimary: #0a84ff`、`colorTextBase: #1d1d1f` 等）；
- 中央编辑区不额外绘制圆角卡片、描边和纸张阴影；
- 弹窗和轻提示只在需要时出现；
- `src/global.css` 只保留应用私有布局样式（`rte-*` 前缀），不引入第二套强调色，不使用废弃的 `--chips-sys-*` 主题变量。

## 5. 文案规范

- 全部界面文案为简体中文直写，不经过多语言系统；
- 需要插值的文案（如“卡片文件已保存到 {path}”）通过 `src/lib/messages.ts` 的 `formatMessage` 收敛，该模块同时作为应用中文文案总表。

## 6. 交互稳定性要求

1. 普通输入、命令面板开合、弹窗开合、状态提示刷新不得导致编辑器 iframe 重建；
2. 只有在新建文稿、打开其他文稿、明确重置会话时才允许重新挂载编辑器；
3. 资源桥和编辑器事件回调必须保持稳定身份，避免重复装配。
