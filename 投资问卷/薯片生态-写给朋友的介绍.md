# 薯片生态——写给朋友的介绍

# 一句话说，薯片生态是什么？

一个装在电脑里的"软件级生态系统"：用户只安装一个叫"薯片主机"的底层软件，其他所有软件——编辑器、播放器、阅读器、文件管理器——都以插件的形式运行在它里面；同时，所有内容都保存成一种开放的卡片文件（`.card`），不锁死在任何软件里。

它同时做两件事，对应两个类比：

- 软件层面，它像微信。微信是唯一的主程序，小程序都在微信里运行。薯片主机是唯一的主程序，所有软件都是主机里的"小程序"。
- 内容层面，它像 Word 和 PDF。内容保存为独立文件，双击就开，发给谁都能打开，不依赖任何一个在线服务。

但小程序的内容锁在腾讯的服务器里，Word 文件能装的东西又太单一。薯片生态把这两件事合在一起：软件插件化，内容文件化。

# 它要解决什么问题？

两个很真实的问题。

第一个：复杂内容没办法作为一个整体流通。

你想分享一套教程，里面有 1 个视频、5 张手写笔记截图、1000 字说明、10 步操作清单和几个参考文件。今天你只能拆开处理：视频传视频平台，截图和文字发微信，清单放进待办软件，资料打成压缩包。接收者拿到的是一堆碎片和链接，而不是一份完整的东西。根源在于每种内容都被不同的软件分管：图片归相册，视频归播放器，文字归笔记，没有一个"容器"能把它们装在一起、还保留它们之间的结构。

第二个：内容被软件绑架。

你在一个笔记软件里写了三年笔记，页面结构、引用关系、附件全都存在它的私有数据库里。哪天你想换软件，或者软件停止服务，这些内容很难完整搬走。你攒下的内容资产，实际上不属于你，属于那个软件。

薯片生态对这两个问题的回答，就是它的两大目标：

- 卡片生态：把信息保存为卡片，让信息脱离程序。
- 软件生态：把常用软件重做一遍，让软件之间不再彼此隔绝。

# `.card` 卡片是什么？

卡片是薯片生态的基本内容单元。它像一个更通用的 Word/PPT 文件，也像一个可以离线保存的网页：把文字、图片、视频、音乐、电子书、网页、待办清单、资源文件等内容，连同它们之间的结构（顺序、嵌套、层级）一起保存进一个文件。

它有几个关键性质：

- 自包含。内容、结构、资源、元数据都在文件里，不依赖创建它的软件，也不依赖网络。备份就是复制文件。
- 双击即开。核心理念是"让复杂内容像打开图片一样简单"——不管里面装了多少东西，对操作系统和用户来说都只是一个文件。
- 开放。它本质是个压缩包，用解压工具就能打开，看到里面每一样东西；格式有公开文档，任何第三方软件都可以读写它。
- 可以嵌套。卡片里可以再放卡片，层层嵌套，像网页可以互相引用，但最终保存成一个文件。

最小不可拆分的内容形态（一段文字、一张图片、一个视频）叫基础卡片；能独立保存成文件的完整容器叫复合卡片，也就是 `.card` 文件本身。

# `.box` 箱子是什么？

有了卡片为什么还要箱子？因为卡片是"一份内容"，箱子是"一组内容的组织方式"。

箱子不装内容本身，只装两样东西：引用了哪些卡片，以及这些卡片用什么方式排布。它很像音乐 App 里的歌单——歌单不包含歌曲文件，只记录歌曲清单和顺序。

这个设计带来一个有意思的能力：内容和展示是分离的。同一个箱子，今天用网格封面墙看，明天换成看板或时间线，引用的数据一个字节都不用变。就像同一份歌单可以按歌名排序也可以按歌手排序，歌还是那些歌。内容的组织和内容的呈现从此互不牵连。

# 薯片主机（平台）是什么？

对操作系统来说，薯片生态只有一个软件：薯片主机。编辑引擎、卡片查看器、视频播放器、音乐播放器、电子书阅读器、资源管理器、设置面板，全都是运行在主机内部的插件。用户双击桌面快捷方式，感觉是启动了一个独立软件，实际上是主机开了一个窗口、加载了对应的插件。

这么设计的理由：

- 多个软件共享同一个运行环境和底层能力，比各装各的省资源得多。
- 所有软件共享同一套文件格式、界面组件和权限系统，体验一致，学一个会一类。
- 装一个新"软件"就是装一个插件，卸载就是卸插件，干净彻底，不留残余。
- 第三方开发者做的软件和官方软件地位完全一样，都只是插件。

# "一切皆插件"是什么意思？

这是整个生态最重要的设计决策，要推到极致来理解。

不光播放器、阅读器这种"软件"是插件，连"一种卡片类型"也是插件——视频卡片长什么样、怎么编辑，由一个视频卡片插件定义；"一种箱子的排布方式"也是插件——看板、网格、时间线、无限画布，各自是独立的布局插件。

推到极致的结果是：平台预装的东西可以非常少，内核保持极小，用户想要什么功能就装什么插件。今天它是个笔记工具，装几个插件后变成媒体库，再装几个变成项目管理工具。生态最终长成什么样，不是官方定义的，是所有插件共同决定的。

# 它对谁有什么用？

对内容创作者：一套教程、一份攻略、一个项目资料，可以组织成一张卡片整体发送、整体收藏、整体二次编辑，不用再拆成视频、截图、链接、压缩包分头发送。

对普通用户：装一个主机，按需添加软件；所有软件操作逻辑一致；更重要的是，内容是自己的——软件可以随时换，内容还在，十年后还能打开。

对开发者：底层的文件读写、媒体播放、渲染、权限都由平台提供，只需要写自己的业务；而且界面和数据是分离的，可以只给现有的后端能力换一个自己喜欢的界面，数据和其他人的界面完全互通。

# 有哪些有趣的关键想法？

挑几个我觉得最值得讲的。

**文件格式先于软件。** 一般软件的思路是先做产品，再决定数据存在哪。薯片生态反过来：先把 `.card` 和 `.box` 的文件格式定死、公开，再围绕格式长出软件。因为格式才是生态的地基——格式开放，内容才可能流通；内容能流通，软件才可能被替换。做软件的公司很多，认真做内容承载格式的很少。

**官方软件没有特权。** 官方插件和第三方插件走同一套接口、同一套权限、同一套生命周期，官方的编辑器没有任何内核后门。这条规则保证生态不会退化成"官方吃肉、第三方喝汤"，也是生态可信的基础。检验标准很朴素：第三方能不能做出和官方一模一样的事。

**一个后端，多种界面。** 前后端完全分离：同一个待办能力，可以有列表风格、看板风格、日历风格三个软件，它们共享同一个后端，只是脸不同。用户选自己喜欢的界面，数据完全互通。这打破了一个惯例——软件的界面和数据必须绑死在同一个产品里。

**标签文件系统。** 传统文件夹是一棵树，一个文件只能待在一个位置，找东西得记住"当时放在哪了"。薯片用标签组织内容：路径变成了"标签筛选路径"，所谓的文件夹是按标签动态生成的虚拟视图。一张"日本旅行"的卡片，可以同时出现在"旅行""2024""已整理"三个视图里。内容不再有唯一归属，只有多重身份。

**模块之间互不认识。** 所有软件模块之间不直接调用，全部经由内核中转：请求发给内核，内核验证格式和权限，再转给目标模块，结果原路带回。每个模块都是孤岛，只认识内核，像所有人都只记总机号码。好处是任何一个模块都可以被整体替换掉，其他部分毫无感知。

**内容单元和软件单元是同构的。** 这是我个人觉得最妙的一点：内容的最小单位是基础卡片，软件的最小单位是插件，而"视频卡片"既是内容类型又是插件。内容和承载内容的软件在同一个粒度上对齐了，所以任何新内容类型都能即插即用——装一个插件，生态就多认识一种内容。

# 背后的哲学思想是什么？

- **原子化与可组合。** 把复杂系统拆到最小的原子——一种卡片、一种布局、一个能力——价值来自组合而不是堆叠。乐高逻辑：单块简单，组合无限。
- **平台思维，平台不做业务。** 平台提供"文件读写"，但不知道怎么"编辑文本"；提供"渲染框架"，但不知道怎么"渲染视频"。所有业务逻辑都在插件里。克制是平台能活很久的前提，一旦平台自己下场做业务，生态就死了。
- **开放。** 格式开放、协议开放、决策过程透明。判断标准不是"我们说开放"，而是第三方能否做出同等的东西。
- **本地优先。** 数据存在用户自己的设备上，核心功能离线可用，平台不默认上传任何数据。云能力由用户主动安装的插件提供，而不是平台替你做主。
- **可逆性。** 安装可以卸载，修改可以回退，副作用可以被干净地撤销。鼓励尝试，不留负担。
- **长期思维。** 架构按十年设计。用户今天存的卡片，十年后还要能打开；宁可前期慢，不做将来要还的债。

这几个哲学最后会变成一把筛子，每个设计决策都过一遍：它是原子的吗？可组合吗？开放吗，第三方能做同样的事吗？数据所有权在用户手里吗？可逆吗？十年后还成立吗？答案都是肯定的，才动手。

# 未来要往哪里走？

两条主线。

软件生态这条线：先把桌面三端（macOS、Windows、Linux）做完整，再扩展到移动端（Android、iOS），五个平台共享同一套文件格式。常用软件——编辑器、查看器、播放器、阅读器、资源管理器——逐个以插件形态重做一遍，全部可替换。

卡片生态这条线：让卡片真正流通起来。一是内容社区，用户可以把卡片和箱子放到社区分享、浏览、收藏；二是第三方集成，博客、知识库、课程平台可以直接嵌入和渲染卡片文件，卡片成为互联网上一种新的可流通内容形态。

长期愿景是：用户设备上长期运行一个薯片主机，需要什么软件就装什么插件；所有重要的内容都以卡片形式保存和流转；内容像图片一样，在人和软件之间自由移动。

# 说点实话：这件事难在哪？

最难的是先有鸡还是先有蛋：没有用户就没有插件开发者，没有插件生态用户就没有理由来。破法是官方先把最核心的软件（编辑器、查看器）做出来，让生态在只有官方插件时就完整可用，第三方插件是锦上添花而不是必需品。

其次是理解成本：大多数人没想过"文件格式"是个可以自己定义的东西，"为什么要一种新文件格式"本身就需要解释。所以第一版产品的目标不是功能多，而是让一个人在三十秒内体会到"一堆碎片内容作为一个整体被打开"的感觉——体验到了，剩下的不用解释。

最后一个风险是工程量：这是一个生态级的系统，却从小团队起步。对策是不做兼容包袱、把系统拆成足够小的原子逐个击破，同时守住一条纪律：宁可慢，不做将来要推翻重来的简化版。

# 为什么值得做？

AI 正在让一个人生产多模态内容的速度暴涨，人人都在同时处理文字、图片、视频、网页和代码。未来真正稀缺的不是生成内容的能力，而是把一组内容组织成可理解、可保存、可复用、可传播的结构的能力。

同时，AI 也在让个性化小软件泛滥，每个工具都有自己的数据格式——数据孤岛问题会变得更严重，而不是更轻。开放的内容格式加上插件化的软件生态，恰好是对这两个趋势的回答：内容不锁死在软件里，软件不固化为孤岛。

一句话收尾：我们想让复杂内容像图片一样简单，想让内容资产真正属于用户，想让软件世界从一堆孤岛变成一片可以自由组合的大陆。
