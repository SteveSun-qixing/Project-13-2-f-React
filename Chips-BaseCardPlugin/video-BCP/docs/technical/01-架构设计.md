# 视频基础卡片插件架构设计

版本：0.1.0  
状态：正式版

## 1. 设计目标

本插件采用“纯插件导出 + 宿主资源桥 + React UI”架构，为视频基础卡片提供正式的查看、编辑和资源生命周期能力。

核心目标：

- 与图片、音乐基础卡片保持一致的卡片根目录资源模型
- 在查看态通过统一资源打开契约唤起视频播放器
- 在编辑态完成视频导入、手动封面导入、字幕导入、播放入口参数与补充信息编辑
- 让配置 schema、查看态、编辑态、模板和测试共用同一套字段口径

## 2. 模块划分

### 2.1 `src/schema/card-config.ts`

负责：

- 视频卡片正式配置类型定义
- 默认配置
- 配置归一函数
- 配置校验函数
- `collectResourcePaths(...)` 的输入来源，覆盖视频、封面和全部字幕资源

### 2.2 `src/shared/utils.ts`

负责：

- 卡片根目录相对路径归一
- 视频 MIME 推导
- 字幕 MIME 推导
- 内部资源路径收集
- 文件名与展示标题辅助逻辑

### 2.3 `src/render/view.tsx`

负责：

- 查看态 React 组件（antd 化：`ChipsImage` → `Image`、`ChipsBadge` → `Tag`、`ChipsEmptyState` → `Empty`、`ChipsIcon` → `@ant-design/icons`；查看态不依赖组件库）
- 视频与封面资源 URL 解析
- 封面显示、首帧回退、悬浮遮罩与播放图标
- 字幕资源 URL 解析与释放
- 点击视频时通过 `openResource(...)` 把打开意图转交给外层宿主，主 `resourceId` 使用卡片根目录相对视频路径，`chips.video-card` payload 透传封面、字幕和播放入口上下文

### 2.4 `src/editor/panel.tsx`

负责：

- 标题分组 + 列表行式编辑布局与响应式排版
- 视频导入、URL 下载导入与手动封面导入
- 封面上传、替换、移除
- 字幕上传、URL 下载导入、替换、删除和默认轨道设置
- 播放入口参数编辑：自动播放、循环、静音、默认倍速、起始秒数
- 视频标题、创作者、发布时间编辑
- 文本输入本地草稿与失焦后统一提交
- 错误提示与资源状态反馈

编辑器 UI 基于 Ant Design（antd），按 `项目日志与笔记/task030-卸担计划/04-组件映射对照表.md` 第 12 节做等价替换：`ChipsForm` → 受控 state 面板（做法 A）、`ChipsTextField` → `Input`、`ChipsSwitch` → `Switch`、`ChipsNumberInput` → `InputNumber`、`ChipsProgress`（indeterminate）→ `Spin`、`ChipsMedia` → 原生 `video` 标签、`ChipsImage` → `Image`、`ChipsErrorState` → `Result status="error"`、`ChipsBadge` → `Tag`、`ChipsButton` → `Button`；渲染根节点统一套 `ConfigProvider locale={zhCN} theme={appleTheme}`（`antd/locale/zh_CN` + `@chips/ui`）。

> task030 起全生态废弃多语言系统，界面文案简体中文直写；文案总表维护在 `src/lib/messages.ts`，旧 `src/shared/i18n.ts` 与 `i18n/` 语言档案已移入 `归档/`（详见 `项目日志与笔记/task030-卸担计划/06-多语言系统移除规范.md`）。

## 3. 宿主契约

### 3.1 查看态

- `renderBasecardView({ container, config, themeCssText, resolveResourceUrl, releaseResourceUrl, openResource })`
- `themeCssText` 为宿主契约保留字段；task030 起插件侧不再读取、不再渲染该主题 CSS（单一苹果风格，见 `项目日志与笔记/task030-卸担计划/07-主题系统移除规范.md`）。
- `video_file` 与 `cover_image` 优先通过宿主提供的 `resolveResourceUrl(...)` 解析。
- `subtitles[*].file_path` 同样通过宿主资源桥解析，并在组件卸载时通过 `releaseResourceUrl(...)` 释放。
- 当 `cover_image` 为空时，查看态直接使用 `<video>` 的首帧作为回退封面。
- 当宿主提供 `openResource(...)` 时，点击视频卡片会把视频资源意图上抛给外层统一走 `resource.open`。
- `openResource(...)` 的主 `resourceId` 不使用临时 `blob:` URL，而是使用稳定的卡片根目录相对路径；目标应用需要的结构化上下文放在 `payload` 中。

### 3.2 编辑态

- `renderBasecardEditor({ container, initialConfig, onChange, resolveResourceUrl, releaseResourceUrl, importResource, deleteResource })`
- 编辑页不内嵌卡片预览，也不使用多层卡片壳布局，避免窄侧栏里产生拥挤层级。
- 文本字段先写入编辑器本地草稿；当用户离开元信息输入区后，再统一调用 `onChange(...)` 输出正式配置，减少复合卡片刷新闪烁。
- 资源区提供“点击/拖拽上传”与“URL 输入导入”两条正式入口；URL 导入会先下载成 `File`，再通过 `importResource(...)` 写入卡片根目录。
- 视频上传链路：
  1. 选择本地视频文件
  2. 调用 `importResource(...)` 写入卡片根目录
  3. 清空旧 `cover_image`，避免旧封面误指向新视频
  4. 通过 `onChange(...)` 输出新的正式配置
- 替换视频或封面时，旧资源通过 `deleteResource(...)` 登记删除。
- 替换或移除字幕时，旧字幕资源通过 `deleteResource(...)` 登记删除。
- 编辑器可见文本统一简体中文直写（`src/lib/messages.ts`）；校验结果返回 i18n key，面板展示前再按 key 查中文文案表翻译。

## 4. 关键设计决策

- `video_file` 是唯一必填正式资源字段，其他字段全部允许为空。
- 查看态标题和次信息只在用户填写时显示，不自动占位。
- 当前不在插件内生成持久化默认封面；查看态在 `cover_image` 为空时继续回退到视频第一帧。
- 资源打开不在基础卡片内部直接启动视频播放器，而是统一交给宿主资源打开路由。
- 编辑页采用居中收窄的设置面板式结构，保证在编辑器侧栏中仍有稳定留白和清晰层级。
- 编辑页内部只保留分组标题与列表行，不再叠加额外信息说明块和嵌套卡片容器。
- 资源操作保持立即提交；文本元信息改为失焦提交，以平衡输入稳定性和宿主刷新成本。
- 当资源已经存在时，上传区切换为资源预览项；视频显示视频画面，封面显示图片，删除动作通过悬浮显露的按钮触发。
- 当前生态尚未提供正式 Host/模块级视频抽帧接口；该缺口已登记为工单108。旧浏览器端抽帧实现已移动到插件 `归档/` 作为历史参考，不进入正式运行时代码。
