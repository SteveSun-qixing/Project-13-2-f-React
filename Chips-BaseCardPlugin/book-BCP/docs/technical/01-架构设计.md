# 电子书基础卡片架构设计

## 插件身份

- 插件 ID：`chips.basecard.book`
- 基础卡片类型：`base.book`
- 运行时别名：`BookCard`
- 入口：`dist/index.mjs`

插件入口导出 `renderBasecardView`、`renderBasecardEditor` 和 `basecardDefinition`，与现有音乐、图片、网页基础卡片保持一致。

## 模块划分

- `src/schema/card-config.ts`：配置类型、默认值、归一化、校验。
- `src/shared/utils.ts`：资源路径、格式识别、MIME 推断、payload 构造辅助、资源清单收集。
- `src/shared/use-resolved-resources.ts`：查看态与编辑态共用的宿主资源 URL 解析 Hook（竞态取消、失败不落表、仅对成功解析路径释放）。
- `src/shared/archive.ts`：EPUB 元数据解析所需的 ZIP 条目读取辅助，条目名按 general purpose bit 11 判断 UTF-8，未置位时按 CP437 解码。
- `src/shared/epub.ts`：EPUB `container.xml`、OPF 元数据和封面解析。
- `src/editor/panel.tsx`：上传、封面、元数据、图片序列列表和排序编辑器。
- `src/render/view.tsx`：查看态展示与 `openResource` 意图传递。

## 配置结构

```ts
interface BasecardConfig {
  card_type: "base.book";
  theme?: string;
  source_type: "ebook" | "image-sequence";
  book_file: string;
  book_format: string;
  book_name: string;
  book_author: string;
  cover_image: string;
  image_sequence: BookImageItem[];
  image_sort_basis: "filename" | "entry-time";
  resource_paths: string[];
}
```

`resource_paths` 是显式资源清单，归一化时会与 `book_file`、`cover_image`、`image_sequence[*].file_path` 去重合并。宿主可通过 `basecardDefinition.collectResourcePaths(...)` 重建卡片结构资源清单。

`book_format` 只接受受支持的电子书与图片包格式白名单（`SUPPORTED_EBOOK_FORMATS` + `ARCHIVE_FORMATS`），归一化会统一为小写规范名（如 `markdown` → `md`），校验阶段对白名单外的值报错。

## 电子书导入

普通电子书导入流程：

1. 识别文件扩展名并写入 `book_format`。
2. 若为 EPUB/EPUB3，解析 `META-INF/container.xml` 找到 OPF。
3. 从 OPF 读取 `dc:title`、`dc:creator` 与封面 manifest 条目。
4. 通过 `importResource` 导入电子书文件。
5. 若解析到封面，则通过 `importResource` 导入封面图片。
6. 输出 `source_type = "ebook"`，清空 `image_sequence`。

非 EPUB 格式不尝试不可靠的内嵌元数据解析，书名与作者保持空字符串。

## 图片包导入

ZIP/CBZ 图片包导入流程：

1. 调用宿主 `importArchiveBundle(...)`，传入 `include` 图片 MIME/扩展名过滤、`stripSingleRootDir: true` 和 `excludeSystemArtifacts: true`。
2. 宿主解包到以压缩包名为前缀的卡片根目录子目录，并返回最终 `entries/resourcePaths/discardedEntries`。
3. 根据 `entries[*].sourcePath/resourcePath/mimeType/modifiedTime` 生成 `image_sequence`。
4. 按文件名或 ZIP 条目时间排序，时间缺失或不可区分时回退文件名。
5. 输出 `source_type = "image-sequence"`，`book_file` 为空，`cover_image` 默认为排序后的第一张图片。

当前插件不支持 CBR/RAR，不引入额外第三方解压库。

## 查看态打开

普通电子书 payload：

- `kind: "chips.book-card"`
- `version: "1.0.0"`
- `cardType: "base.book"`
- `mode: "ebook"`
- `resources.book`
- `display.title / author`

图片包 payload：

- `mode: "image-sequence"`
- `resources.images` 按阅读顺序传递全部图片资源描述

插件只调用宿主传入的 `openResource(...)`，不直接选择 `Chips-BookReader` 或 `Chips-PhotoViewer`。

## 查看态资源解析

- 查看态只通过 `resolveResourceUrl` 解析当前展示所需的封面 URL，不解析 `book_file` 与整本 `image_sequence`；打开意图始终携带相对路径 payload，由宿主负责打开阶段解析。
- 解析失败或尚未完成时显示占位图标分支，不把未解析的相对路径回退为图片 `src`；antd `Image` 配置 `fallback`，已解析 URL 加载失败时降级为同风格占位图。
- 解析循环在每次迭代检查取消标志，卸载时只对成功解析过的路径调用 `releaseResourceUrl`，避免释放失败或未完成的路径。

## 外部消费链路

当前 `Chips-BookReader` 已消费 `chips.book-card` 普通电子书 payload，并正式接入 EPUB/EPUB3、PDF、TXT/Markdown、FB2、RTF；MOBI/AZW/AZW3/DJVU/DOC/DOCX 会被识别为电子书启动目标，但仍需要生态级正式解码器才能在应用内渲染正文。

当前 `Chips-PhotoViewer` 已消费 `chips.book-card` 图片序列 payload，可以按 `resources.images[]` 顺序浏览 ZIP/CBZ 图片包。

通用 `importArchiveBundle(...)` 已由 SDK / EditingEngine / Host ZIP 元数据链路收口为目录导入契约，不再使用面向网页或图片的场景开关字段。
