## 一、目标

在 `chips-ecosystem/tools/gates/` 交付零第三方依赖、可独立执行、可被 CI 与本地统一调用的门禁脚本集：

1. `check-docs.mjs`：文档门禁（G12）——相对链接、文档头、ADR 元数据、拆分件一致性、README 索引收录。
2. `check-contracts.mjs`：契约一致性门禁（G8）——能力 / 权限 / 事件与 `@chips/contract-gen` 生成物逐项一致。
3. `check-boundaries.mjs`：架构红线门禁（G9）——工作区包依赖方向、内部依赖协议、源码导入边界、Rust crate 依赖方向与依赖环。
4. `check-coverage.mjs`：覆盖率门禁（G6）——读取阈值配置与覆盖报告（vitest v8 json-summary、cargo-tarpaulin XML）并逐组逐维度判定。
5. `check-entries.mjs`：插件入口校验（《构建与打包》§5.6 ×《03-插件包格式》§2.4），必需入口集合按 `manifest.yaml` 角色判定（`service` 只校验 `dist/index.js`），由插件构建脚本按目录调用。
6. 统一入口 `gates:all`：串行执行前四项门禁，只要有失败即以非零退出码结束；单门禁可独立运行。
7. 脚本自测：`pnpm gates:test`，基于 `tests/fixtures/` 夹具验证每个门禁的通过 / 失败路径与退出码契约。

权威依据：

- `薯片生态文档库/06-开发与运维/05-CICD与质量门禁.md`（§3 门禁清单、§6 失败处理与豁免）

## 三、接口设计

### 3.1 CLI 约定（全部脚本一致）

```bash
node tools/gates/check-docs.mjs      [--workspace-root <dir>] [--config <file>] [--json] [--no-report] [--help]
node tools/gates/check-contracts.mjs [--generated-dir <dir>] [--capability-doc <file>] [--permission-doc <file>] [--event-dir <dir>]
node tools/gates/check-boundaries.mjs
node tools/gates/check-coverage.mjs  [--ts-report <file>] [--rust-report <file>]
node tools/gates/check-entries.mjs   [插件目录] [--max-bytes <n>]
node tools/gates/gates-all.mjs       [--only <gate,...>] [--json] [--no-report] [--help]
```

| 退出码 | 含义                                                      |
| ------ | --------------------------------------------------------- |
| 0      | 通过                                                      |
| 1      | 门禁失败（存在违规项）                                    |
| 2      | 用法或配置错误（参数非法、配置缺失/格式错误、路径不存在） |
| 3      | 工具内部错误（未预期异常、报告写入失败）                  |

与《CLI 完整参考》§2.5 的 0 / 1 / 2 语义一致；3 对应工具自身错误。

### 3.2 报告结构（`--json` 与报告文件同构）

```json
{
  "gate": "docs",
  "status": "pass | fail",
  "startedAt": "2026-09-19T00:00:00.000Z",
  "finishedAt": "2026-09-19T00:00:00.000Z",
  "summary": {},
  "violations": [
    {
      "code": "DOCS001",
      "file": "01-示例/01-示例文档.md",
      "line": 12,
      "message": "相对链接指向不存在的路径：./缺失.md"
    }
  ],
  "warnings": []
}
```

`gates-all` 聚合报告含 `gates[]`，违约项带 `gate` 字段。

### 3.3 契约生成物契约（`check-contracts.mjs` 唯一认可的输入）

位置（`gates.config.json` → `contracts.generated.dir`，默认 `packages/sdk/src/generated`），由 `@chips/contract-gen` 生成：

| 文件                        | 门禁读取的导出                              |
| --------------------------- | ------------------------------------------- |
| `capability-ids.ts`         | `CAPABILITY_IDS`（R19 内置能力 ID 数组）    |
| `permission-ids.ts`         | `PERMISSION_IDS`（内置权限词表数组）        |
| `event-ids.ts`              | `EVENT_IDS`（标准事件 ID 数组）             |
| `capability-permissions.ts` | `CAPABILITY_PERMISSIONS`（能力 → 权限映射） |

规则：门禁独立解析生成物并与文档权威表双向比对（缺失 / 多余 / 映射 / 文法 / 重复 / 命名空间冲突 / 声明计数）；ID 文法与 `@chips/contract-gen` 的 `CAPABILITY_ID_PATTERN`、`PERMISSION_ID_PATTERN`、`EVENT_ID_PATTERN` 一致；门禁不代行生成职责，不 import 生成器实现（保持独立校验）。

### 3.4 覆盖率门禁输入

- TS：`coverage/ts/coverage-summary.json`（vitest + v8 `json-summary` reporter，根 `vitest.config.ts` 的 `reportsDirectory`）。
- Rust：`coverage/rust/cobertura.xml`（`cargo tarpaulin --workspace --out Xml Json Lcov --output-dir coverage/rust`）；
  维度按工具实际输出判定——总量层可判 `lines` 与 `branches`（`branches-valid > 0` 时），核心面层只有 `lines`（tarpaulin 不产函数、语句维度与逐文件分支计数）。
- 阈值来自 `gates.config.json` → `coverage`，数值权威为《架构原则》附录 R18 与《测试规范》§10.2：总体各维度 > 80%，
  共享层（`@chips/ui`、`@chips/bridge`）与 Rust 核心（`chips-*` crates）各维度 > 90%；判定为严格大于。
- 统计面（与 `@chips/testing` 侧同源，2026-09-20 04:40 收口）：TS 侧 `coverage.groups` 只含共享层，其余并入 `total`；
  Rust 侧两条独立判定 `rust-overall`（`defaultThreshold`）与 `rust-core`（`coverage.rust.coreThreshold`，缺省 90），
  核心面按 `coverage.rust.coreMatch` 的 crate 路径前缀（`packages/core-rust/crates/chips-`、`packages/native/`）逐 `<class>` 聚合行条目。
  Neon 绑定 crate `chips-native` 命中 `chips-*` 命名，属于 90% 核心面：不设豁免、不另计统计面（《测试规范》一、`:28`）。
- 报告缺失、格式非法、必需组无数据（含核心面前缀内无行条目）、任一维度不达标 → 失败。
- 禁止以放宽阈值、扩大 `coreMatch` 之外的排除、更换测量口径的方式通过门禁（《CICD与质量门禁》6.4）；需要例外时按 6.3 走豁免登记。

## 四、各门禁检查项

### 4.1 check-docs.mjs（G12）

| 代码    | 检查项                                  | 判定 |
| ------- | --------------------------------------- | ---- |
| DOCS001 | 相对链接目标不存在                      | 失败 |
| DOCS002 | 相对链接越出文档库根                    | 失败 |
| DOCS010 | 文档头四行缺失 / 适用范围为空           | 失败 |
| DOCS011 | 文档头四行顺序错误                      | 失败 |
| DOCS012 | 状态取值非 `正式版` / `已废弃`          | 失败 |
| DOCS013 | 日期非 `YYYY-MM-DD`、版本非 `vX.Y.Z`    | 失败 |
| DOCS014 | 文件结尾缺 `**文档结束**`               | 失败 |
| DOCS015 | ADR 元数据缺失或状态/日期非法           | 失败 |
| DOCS020 | 拆分件无法定位母文档 / 章节与标题不一致 | 失败 |
| DOCS021 | 拆分件未被母文档目次收录（孤儿件）      | 失败 |
| DOCS022 | 拆分件无正文标题且内容不足（错位空壳）  | 失败 |
| DOCS023 | 拆分件标题与同母文档既有拆分件重复      | 失败 |
| DOCS024 | 拆分件首段与同母文档既有拆分件重复      | 失败 |
| DOCS030 | 正式文档未被 README 索引收录            | 失败 |
| DOCS090 | 短章节（正文 < 3 行且命名一致）         | 警告 |

范围：`薯片生态文档库/` 全部 Markdown（跳过 `归档/` 等）；代码块与行内代码中的链接默认跳过（`--raw` 关闭）；ADR 不要求四行文档头。

| CONTRACT020 / 021 | 权限 ID 缺失 / 多余                                              |
| CONTRACT030 / 031 | 事件 ID 缺失 / 多余                                              |
| CONTRACT040       | 能力 / 权限 / 事件命名空间冲突                                   |
| CONTRACT041       | 映射引用词表外权限                                               |
| CONTRACT042       | 解析能力数与文档声明计数不一致                                   |

### 4.3 check-boundaries.mjs（G9）

| 代码        | 检查项                                               |
| ----------- | ---------------------------------------------------- |
| BOUNDARY001 | 工作区存在未在配置中登记规则的包                     |
| BOUNDARY010 | 内部依赖不在允许集合（含反向依赖、插件互相依赖）     |
| BOUNDARY011 | 内部依赖未使用 `workspace:*`（含 `file:` / `link:`） |
| BOUNDARY012 | 根 `package.json` 声明业务依赖                       |
| BOUNDARY020 | 源码导入禁止模块 / 禁止的 Node 内置模块              |
| BOUNDARY021 | 源码导入未声明的 `@chips/*` 包                       |
| BOUNDARY022 | 仅允许 `import type` 的包被运行时导入                |
| BOUNDARY030 | 包级或 Rust crate 循环依赖                           |
| BOUNDARY040 | Rust crate 依赖超出允许集合                          |
| BOUNDARY041 | Cargo workspace 成员缺少 `Cargo.toml`                |
| BOUNDARY042 | 出现未登记的 `chips-*` crate                         |

测试文件不参与源码导入检查；子路径导入按包名归一；`allowedDevInternal` 允许测试基础设施（`@chips/testing`）作为 `*.config.*` 开发文件的 devDependency。

边界表以 `gates.config.json` → `boundaries.rules` 为唯一事实源；`packages/sdk → @chips/scaffold` 为按《02-SDK-API规范》§8.2 规则 9 的 RFC 裁决放行的唯一脚手架转发有向边（依赖 + 源码 import 两层），其他跨包边判定强度不变。

### 4.5 check-entries.mjs（构建与打包 §5.6 ×《03-插件包格式》§2.4）

角色感知判定（工单 021 收口）：角色来源为插件目录包根 `manifest.yaml` 顶层 `type`，判定表唯一事实源 `lib/plugin-entries.mjs`，与 CLI `cpk-validate.ts` `validateLayout` 角色分支、scaffold `RENDER_ENTRY_BY_ROLE` 同源。`dist/index.js` 全部角色必需；`render.js` 对 `basecard` / `boxlayout` / `app` 必需、对 `service` 禁止。角色不可判定（manifest 缺失 / `type` 缺失 / 未知角色）为用法错误（退出码 2），fail-closed。

| 代码           | 检查项                                                        |
| -------------- | ------------------------------------------------------------- |
| ENTRY001       | 缺少角色必需的入口文件（`service` 不因缺 `render.js` 报 001） |
| ENTRY002 / 003 | 超过 8 MiB / 非 UTF-8                                         |
| ENTRY004       | `service` 角色携带 `render.js`（与 CLI validate 同向）        |
| ENTRY010       | 非法模块引用（主入口零引用；渲染入口仅 vendor 绝对 URL）      |

## 六、风险与处理

| 风险                                       | 处理                                                                  |
| ------------------------------------------ | --------------------------------------------------------------------- |
| 文档库迁移到 `chips-ecosystem/docs/`       | 只需修改 `gates.config.json` 的 `docs.root`，脚本不改                 |
| 契约生成器输出结构变化                     | 门禁解析器与夹具同步更新；生成物契约以 `contracts.generated` 配置为准 |
| 04.03 §3.1 与 R19 canonical 文法冲突       | 已登记工单 003；门禁以 CONTRACT091 警告绕开，裁决后收敛为失败或撤警   |
| 覆盖率报告目录分散                         | 明确根 `coverage/` 汇总口径；各包独立报告不作为门禁输入               |
| 真实仓库当前缺覆盖率报告与两条 README 索引 | 门禁按设计失败并给出定位信息；先完成对应 W1 任务后自然转绿            |
