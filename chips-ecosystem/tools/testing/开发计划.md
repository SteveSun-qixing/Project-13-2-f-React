## 一、目标

在 `chips-ecosystem/tools/testing/` 交付全仓统一的测试基础设施，使「运行环境、测试文件范围、覆盖率口径、
门禁判定」在 14 个包内不出现第二套写法：

1. **vitest 项目工厂** `defineChipsProject`：各包 `vitest.config.ts` 一行继承，统一 `environment`、`globals`、
   include/exclude、setup 注入、`testTimeout`、`passWithNoTests` 与 v8 覆盖率配置；
2. **覆盖率口径单一事实源** `src/thresholds.ts`：总体 80%、Rust 核心与共享层 90%（R18）与共享层 glob、
   Rust 核心前缀、报告路径全部集中于此，其他位置禁止另写数值；
3. **覆盖率聚合门禁** `src/coverage/`：解析 vitest v8 `json-summary` 与 cargo-tarpaulin JSON，
   按分组（TS 总体 / 各共享层 glob / Rust 总体 / Rust 核心）逐维度判定，产出机器可读 JSON 与 `summary.md`；
4. **全量覆盖率流程编排** `src/coverage/run.ts`：Rust → TS → 聚合三段串联，作为根脚本 `pnpm test:coverage` 唯一入口；
5. **共享 DOM setup** `src/dom-setup.ts`：jsdom 项目自动获得 `@testing-library/jest-dom` 断言扩展，
   且**不安装任何平台 Mock**；
6. 门禁产物与退出码对 CI 可判定（0 / 1 / 2 三态）。

## 三、目录与公开面

```
tools/testing/
├── src/
│   ├── vitest.ts        # defineChipsProject / ChipsProjectOptions / ChipsCoverageTier（工厂）
│   ├── thresholds.ts    # 阈值、共享层 glob、Rust 核心前缀、报告路径（单一事实源）
│   ├── dom-setup.ts     # jsdom 项目的共享 setup（仅 jest-dom 扩展）
│   └── coverage/
│       ├── model.ts     # CoverageCount / Counts / CoveredFile / Group / Verdict / Section / GateReport
│       ├── parse.ts     # vitest json-summary 与 tarpaulin JSON → CoveredFile[]（纯函数，不触盘）
│       ├── gate.ts      # 分组聚合、阈值判定、Markdown 渲染（纯函数，输出固定排序）
│       ├── runner.ts    # 读报告 → 判定 → 写 reports/coverage/，退出码 0/1/2
│       ├── run.ts       # 根 `test:coverage` 编排：rust → ts → 聚合
│       └── cli.ts       # 根 `report:coverage` 的 tsx 入口
├── tests/               # 5 个测试文件（工厂、阈值、解析、判定、执行器）
├── package.json / tsconfig.json / vitest.config.ts
└── 开发计划.md / 开发日志.md
```

公开面（`package.json` `exports`）：`./vitest` → `src/vitest.ts`、`./thresholds` → `src/thresholds.ts`。
**以 TS 源码直接导出，不产物化**：`build` 与 `typecheck` 同为 `tsc -p tsconfig.json --noEmit`，包内无 `dist/`。
`src/coverage/**` 不经 `exports` 暴露，只由本包脚本（`coverage` / `report`）与根脚本调用。

脚本面：

| 脚本            | 命令                                  | 语义                                                                             |
| --------------- | ------------------------------------- | -------------------------------------------------------------------------------- |
| `build`         | `tsc -p tsconfig.json --noEmit`       | 与 typecheck 同形（不产物化，仅静态类型验证）                                    |
| `test`          | `vitest run`                          | 包内自测（本包配置以相对路径 `./src/vitest` 导入，无需 `--configLoader runner`） |
| `test:coverage` | `vitest run --coverage`               | 本包覆盖率（`tier` 缺省 `standard` → 80%）                                       |
| `coverage`      | `tsx src/coverage/run.ts`             | 根 `pnpm test:coverage` 的唯一入口（全流程编排）                                 |
| `report`        | `tsx src/coverage/cli.ts`             | 根 `pnpm report:coverage` 入口（只读已有报告做聚合门禁）                         |
| `lint`          | `eslint src tests vitest.config.ts`   | 不含 `prettier --check`（见 §七 缺口 3）                                         |
| `clean`         | `node -e "…rm coverage .tsbuildinfo"` | 清理覆盖率输出与构建信息                                                         |

## 四、接口设计

### 4.1 `defineChipsProject(options)`

`ChipsProjectOptions` 十项键与默认值：

| 键                | 默认值                                                                  | 说明                                                                  |
| ----------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `name`            | 缺省（由 vitest 依包名推断）                                            | 显式给出时写入 `test.name`                                            |
| `environment`     | `node`                                                                  | `jsdom` 时自动前置 `dom-setup.ts` 并注入 `@vitejs/plugin-react`       |
| `tier`            | `standard`                                                              | `standard` → 80%，`core` / `shared` → 90%（取 `COVERAGE_THRESHOLDS`） |
| `include`         | `src/**/*.{test,spec}.{ts,tsx}`、`tests/**/*.test.{ts,tsx}`             | 测试文件范围                                                          |
| `exclude`         | vitest 默认 + `**/dist/**` + `**/tests/contract/**`                     | 契约测试由 `pnpm test:contract` 单独执行                              |
| `setupFiles`      | `[]`（jsdom 额外前置 DOM setup）                                        | 追加式，不替换                                                        |
| `testTimeout`     | `5_000`                                                                 | 单用例超时                                                            |
| `coverageInclude` | `src/**/*.{ts,tsx}`                                                     | 包内覆盖率统计范围                                                    |
| `coverageExclude` | 追加在默认排除项（测试、`tests/`、`dist/`、`*.d.ts`、`*-setup.ts`）之后 | 用于入口聚合文件等                                                    |
| `overrides`       | 无                                                                      | 同名键整体覆盖 `test` 配置                                            |

恒定项（不允许包内改写）：`globals: true`、`passWithNoTests: false`、
`coverage.provider: 'v8'`、`reporter: ['text','html','lcov']`、`reportsDirectory: './coverage'`、`reportOnFailure: true`。

**运行约束**：继承本工厂的包，其 `test` / `test:coverage` 必须带 `--configLoader runner`
（工厂以 TS 源导出，vitest 默认 bundle 加载器会把工作区包外置为 Node ESM 而无法解析）。该约束写在
`src/vitest.ts` 头注与根 `vitest.config.ts` 头注两处。

### 4.2 `src/thresholds.ts` 导出面

`CoverageMetric`（`lines` / `functions` / `branches` / `statements`）、`COVERAGE_METRICS`（固定顺序，保证产物确定性）、
`CoverageThreshold`、`OVERALL_COVERAGE_THRESHOLD = 80`、`CORE_SHARED_COVERAGE_THRESHOLD = 90`、
`COVERAGE_THRESHOLDS = { overall, core, shared }`、`SHARED_LAYER_GLOBS = ['packages/ui/**', 'packages/bridge/**']`、
`CORE_RUST_CRATE_PREFIX = 'packages/core-rust/crates/chips-'`、
`NATIVE_CRATE_PATH_PREFIX = 'packages/native/'`（Neon 绑定 crate `chips-native` 的当前落位目录，目录漂移见工单 007）、
`CORE_RUST_CRATE_PATH_PREFIXES = [CORE_RUST_CRATE_PREFIX, NATIVE_CRATE_PATH_PREFIX]`（Rust 核心统计面前缀集），
`COVERAGE_REPORT_PATHS = { vitestSummary: 'coverage/ts/coverage-summary.json', tarpaulinJson: 'coverage/rust/tarpaulin-report.json', outputDir: 'reports/coverage' }`。
根 `vitest.config.ts` 直接 `import` 本模块生成 `coverage.thresholds[glob]`，与聚合门禁共用同一份清单。

### 4.3 覆盖率门禁分层

- `parse.ts`、`gate.ts` 为**纯函数**（不触碰文件系统），路径归一为仓库相对路径；
- 分组口径：TS = `ts-overall` + 每个共享层 glob 一个分组（与根配置逐项对应）；Rust = `rust-overall`（工作区总量，> 80%）
  - `rust-core`（核心统计面，> 90%），核心面由 `gate.ts` 导出的 `isCoreRustPath()` 按 `CORE_RUST_CRATE_PATH_PREFIXES` 判定；
    分组依据是 **crate 名 `chips-*`**（《架构原则》附录 R18、《测试规范》§一 与 §10.2），故 `chips-native` 属于核心面，
    不设覆盖豁免、也不另立统计面；`chips-*` 之外的 Rust/TS 代码并入总体（《测试规范》一、`:28`）；
- 判定容差 `EPSILON = 1e-9`（允许 89.999999… 表示误差）；总量为 0 时该维度返回 `null`（口径不适用，不误判为 0%）；
- `runner.ts` 退出码：`0` 全部通过；`1` 报告可解析但未达标；`2` 报告缺失或解析失败（基础设施/流水线问题）；
- 产物：`reports/coverage/coverage.json`（机器可读）+ `reports/coverage/summary.md`（人读，Markdown 渲染顺序固定）。

## 五、依赖与选型

- 运行时：零第三方运行期依赖（`src/coverage/**` 只用 `node:fs` / `node:path` / `node:url` / `node:child_process`）。
- 开发依赖（精确版本）：`@vitejs/plugin-react`、`jsdom`、`@testing-library/jest-dom`、`vitest`、`typescript`、`tsx`、`@types/node`。
  `tsx` 是本包独有选型，用于直接执行 TS 源门禁脚本（与「不产物化」策略配套）。
- 依赖边界：`tools/gates/gates.config.json` 以 `allowedDevInternal: ["@chips/testing"]` 允许各包在
  `*.config.*` 等开发文件中把本包作为 devDependency 导入（`packages/ui` 是当前唯一消费方）；
  子路径导入按包名归一判定，`@chips/testing/vitest` 不误报未声明依赖。
