# contract-gen 开发计划（契约常量生成器）

> 任务：W1 · 契约常量生成器
> 日期：2026-09-19
> 状态：已完成
> 归属：`chips-ecosystem/tools/contract-gen/`

---

## 一、目标与范围

从 `薯片生态文档库/` 的权威表解析能力 / 权限 / 事件 / 错误码，生成 `@chips/sdk` 可消费的 TypeScript 常量与字面量联合类型，并提供门禁用一致性校验脚本与单测。

**单一事实源**：文档库。生成物与常量一律由生成器产出，禁止手写常量；生成物头部标注事实源与再生成命令。

范围外：内容处理服务能力的逐项码（由提供方契约发布，文档库只登记代表性码）；服务器 HTTP API 错误码（属 HTTP 响应码模型，不是 `ChipsError`）；`internal:*` 内核内部事件（不公开契约）。

## 三、产物

生成到 `chips-ecosystem/packages/sdk/src/generated/`（相对路径固定）：

- `capability-ids.ts`：`Capability` 常量对象 + `CapabilityId` + `CAPABILITY_IDS`。
- `capability-permissions.ts`：`CAPABILITY_PERMISSIONS`（能力 → 基础权限 ID 数组）。
- `permission-ids.ts`：`Permission` + `PermissionId` + `PERMISSION_IDS`。
- `event-ids.ts`：`StandardEvent` + `EventId` + `EVENT_IDS`。
- `error-codes.ts`：`ERROR_CODES` + `ErrorCode`。
- `index.ts`：统一导出。

命名规则：ID 按 `:` 与 `-` 分段、驼峰边界拆分后大写蛇形（`window:setTitle` → `WINDOW_SET_TITLE`）；命名冲突视为错误。

门禁接入：契约一致性门禁（G8）`tools/gates/check-contracts.mjs` 按 `gates.config.json` → `contracts.generated` 读取上述 TS 生成物并与文档库权威表逐项比对；生成物的渲染格式必须同时满足仓库根 `prettier --check .`（根 lint 门禁 G3）。

## 四、架构与数据流

```
DocReader ──▶ load（按 sources 读取声明文件）
          ──▶ parse（能力/权限/事件/错误码 → ContractModel + 文档声明事实）
          ──▶ validate（文法、唯一性、命名空间隔离、映射完整性、计数断言）
          ──▶ emit（确定性文本渲染）
          ──▶ write / check（写盘或与磁盘比对，门禁退出码）
```

模块划分（`src/`）：

| 模块          | 职责                                               |
| ------------- | -------------------------------------------------- |
| `types.ts`    | 契约模型、文档源声明、校验问题类型                 |
| `sources.ts`  | 唯一一份来源清单（文件 + 章节 + 表头锚点）         |
| `markdown.ts` | 章节定位、表格解析（转义感知）、内联码与引号码提取 |
| `load.ts`     | `DocReader` 抽象 + 文件系统实现 + 按源装载         |
| `parse.ts`    | 各类权威表 → 模型；解析失败抛出可定位错误          |
| `naming.ts`   | ID → TS 常量名；冲突检测                           |
| `validate.ts` | 全部门禁规则（见第五节）                           |
| `emit.ts`     | 确定性文件渲染（无时间戳，换行固定 `\n`）          |
| `generate.ts` | 编排：构建 / 写盘 / 比对                           |
| `cli.ts`      | `generate` / `check` / `validate` 命令与退出码     |
| `index.ts`    | 公共 API 导出                                      |

## 五、校验规则（门禁）

1. 文法：能力 `domain:action`（action 允许驼峰，按 canonical 表实际拼写）；权限基础形式两段小写；事件 `domain:action`；错误码 `<DOMAIN>_<REASON>` 全大写。
2. 唯一性：各命名空间内 ID 唯一；常量名唯一。
3. 命名空间隔离（R3）：`CapabilityId` 与 `PermissionId` 无交集，且均不与 `EventId` 交集。
4. 映射完整性：`CAPABILITY_PERMISSIONS` 引用的权限全部存在于 §4.1 词表；§4.1 每项权限被域词表覆盖；§4.3 引用的能力全部存在于 R19 表。
5. 计数断言：R19 解析数 == 文档声明「N 项计数」；事件逐域解析数 == §2.2 声明数；`internal` 域不得进入产物。
6. 产物一致性：`check` 重新渲染并与磁盘比对，任何差异（缺失、内容不符、生成目录出现多余人写 `.ts`）均失败。

## 六、测试计划

- 单测（vitest，样例输入 → 输出断言）：markdown 解析、四类表解析、命名、校验规则（正/反例）、emit golden 断言。
- 幂等：同输入连续两次生成字节一致；`check` 对已写产物通过。
- 集成：以真实 `薯片生态文档库` 全量解析 + 校验 + 与已提交生成物比对；用 TypeScript 编译器 API 对生成物做 `noEmit` 类型检查。
- 门禁接入：`pnpm -r run test:contract` → 本包 `tsc && node dist/cli.js check`；根工作区测试发现依赖包内 `vitest.config.ts`（`tools/*/vitest.config.ts`）。

---

## 七、依赖与约束

- 运行时零第三方依赖（Node 内置模块）；devDependencies：typescript、vitest、@types/node（workspace 统一版本）。
- 产物目录只读语义：任何手写常量必须移出 `generated/`；文档变更与再生成必须同一提交。
- 不引入兼容层、不做临时实现；解析失败必须显式报错（含文件与章节）。

## 九、验收命令

```bash
pnpm --filter @chips/contract-gen run typecheck       # 严格类型检查（含 test）
pnpm --filter @chips/contract-gen run test            # 单测（样例→输出、幂等、真实文档集成）
pnpm --filter @chips/contract-gen run generate        # 生成到 packages/sdk/src/generated/
pnpm --filter @chips/contract-gen run check           # 文档↔生成物一致性（供门禁）
pnpm --filter @chips/contract-gen run test:contract   # 根 test:contract 聚合入口
pnpm gates:contracts                                  # G8 契约一致性门禁（tools/gates）
```
