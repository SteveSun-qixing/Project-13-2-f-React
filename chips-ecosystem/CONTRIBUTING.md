2. **领域文档**：按任务类型查[《重构大计划/03》§二 必读文档索引](../重构大计划/03-并行开发与子智能体规范.md)；接口契约、格式规范、开发规范、工程管理各自读全文。
3. **任务单据**：从台账/任务清单领取任务，核对 `deps` 已完成，认领文件并写入 `owner`（同一文件 owner 唯一）。

## 二、八步开发流程

### 1. 读文档

完成第一节全部阅读；在开发日志中记录实际阅读的文档路径与章节，不做未读即写的实现。

### 2. 写开发计划

在目标包根写 `开发计划.md`，使用[开发计划模板](./docs/模板/开发计划模板.md)，至少覆盖：范围与产物、接口与契约对齐、依赖、测试与验收命令、风险与对策。计划先行，范围不得在实施中私自扩张。

### 3. 写开发日志

在目标包根写 `开发日志.md`，使用[开发日志模板](./docs/模板/开发日志模板.md)；每完成一个阶段追加一节（时间、内容、证据、遗留），只追加不回改历史条目。

### 4. 开发

- 契约先行：实现必须对齐《薯片生态文档库》，文档与实现不一致视为缺陷，同一变更内修正。
- 先写测试后写实现（或同步）；禁止临时实现、简化版与未完成标记。
- 依赖变更：新增第三方库必须先完成选型评估；改变基础架构、长期运行时依赖或公共协议时先走 RFC → 评审 → ADR，不得先实现后补流程。

### 5. 包内验证

```bash
pnpm --filter <包名> run typecheck
pnpm --filter <包名> run lint
pnpm --filter <包名> run test
pnpm --filter <包名> run test:coverage   # 有覆盖率的包
pnpm --filter <包名> run test:contract   # 承载契约快照的包
cargo fmt --all -- --check && cargo clippy --workspace --all-targets -- -D warnings   # Rust 改动
```

### 6. 门禁验证

按[根 README §四 质量门禁](./README.md)执行与改动范围匹配的门禁项；失败即修复根因并全量重跑，禁止跳过、弱化断言或扩大排除范围。

### 7. 台账回写

```bash
python3 ../重构大计划/工具/重构台账.py dispose --help   # 按帮助回写裁决
python3 ../重构大计划/工具/重构台账.py stats            # 核对状态统计
```

- 文件级：`status` 推进到 `已验证`，`evidence` 记录命令与结果；`disposition` 取 `迁移/重写/保留设计/废弃/归档`。
- 符号级：仅对"迁移/重写"的文件展开；"保留设计"必须落到文档库章节或新实现的说明，禁止悬空。
- 旧仓库只读：迁移采用"复制 + 适配"，不修改旧文件；旧功能核对清单逐条闭合（功能 → 新实现位置 → 测试名）。

### 8. 汇报与波次记录

- 向主代理返回 ≤ 5 行摘要：任务号、交付物、验证结果、阻塞与遗留。
- 波次收尾由主代理按[ADOPS 模板](./docs/模板/ADOPS-波次记录模板.md)出具记录，落位 [`docs/ADOPS/`](./docs/ADOPS/README.md)（台账统计 + 阻塞项 + 下一波准入判定）。

## 四、红线

- Host 是唯一运行时承载；插件访问系统能力只经 `window.chips` / Bridge / `chips-sdk` 正式链路。
- 服务间调用必须走内核路由；禁止跨服务直接 `import`、禁止跨层直连。
- 前端统一 React + antd + `@chips/ui`；文案简体中文直写；样式只用 Design Tokens 与 antd 主题定制，禁止硬编码样式与第二套组件库。
- 插件不得直接 `import` 其他插件、平台包源码或 Node/Electron API。
- 不引入未完成项、临时实现、简化版与兼容性包袱；不做任务范围外的修改。
- 文档与实现同一次变更内更新；新增或移动文档同步更新索引。

## 五、Git 与提交

- 分支创建、切换、合并、归档与提交均由用户管理；子智能体不得自行执行上述 Git 操作。
- 收到用户明确指令后，提交信息用中文编写，内容全面详细：任务号、范围、关键实现、验证结果与遗留。

## 六、问题、阻塞与债务

发现架构缺口、组件/接口缺失、SDK 或脚手架不可用、文档与代码不一致、工具链漂移时：先在 `../项目日志与笔记/问题工单.md` 登记，并建立 `工单NNN-描述/任务说明.md` 写清背景、证据、影响范围、复现步骤、期望行为与暂行处理；登记后继续推进不受影响的部分，不得以临时实现绕过。工单、技术债与 RFC 的完整流程以[《变更与决策管理》](../薯片生态文档库/07-工程管理/03-变更与决策管理.md)为准。
