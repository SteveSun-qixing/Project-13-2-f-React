## 一、角色与波次

| 角色     | 职责                                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------------------- |
| 主代理   | 波次划分与任务派发、文件认领串行化、台账汇总、波次收尾出具 `docs/ADOPS/ADOPS-W<n>.md`、判定下一波准入       |
| 子智能体 | 按《03》开工八步执行单个任务：读文档 → 计划 → 日志 → 开发 → 验证 → 台账回写 → 摘要汇报；同一文件 owner 唯一 |
| 用户     | 分支管理、提交指令、重大决策确认                                                                            |

波次序列 W0→W7、各波次目标与准出（DoD）与并行度见《00》阶段路线图；当前波次以《00》"当前波次"章节为唯一口径。任一阶段出口未通过，不得启动下一阶段的实现工作。

## 二、开工八步

1. **读全局文档**：`薯片生态文档库/README.md`、`00-愿景与原则/*`、`01-架构设计/00-整体架构图.md`、任务相关子系统设计全文、[施工规范套件](../../项目日志与笔记/task043-生态梳理/施工规范/00-任务背景与目标.md)、`重构大计划/00~03`。
2. **读领域文档**：按任务类型查《03》§二必读索引；接口契约、格式规范、开发规范、工程管理各自读全文。
3. **读任务单据**：核对 `deps` 已完成；认领文件并写入台账 `owner`。
4. **写开发计划**：目标包根 `开发计划.md`，使用[开发计划模板](./模板/开发计划模板.md)。
5. **写开发日志**：目标包根 `开发日志.md`，使用[开发日志模板](./模板/开发日志模板.md)。
6. **开发**：契约先行、先测后码；禁止临时实现、简化版、未完成标记与兼容性包袱。
7. **验证**：包内 `build/test/lint/typecheck` 与覆盖率、契约测试，按改动范围执行根门禁（`README.md` §四）；结果粘贴进日志。
8. **回写与汇报**：台账 `status/evidence` 回写、任务状态更新、向主代理返回 ≤5 行摘要。

## 三、制品落点

| 制品     | 落点                                                      | 说明                                                  |
| -------- | --------------------------------------------------------- | ----------------------------------------------------- |
| 包说明   | `<包>/README.md`                                          | 使用[包-README模板](./模板/包-README模板.md)          |
| 开发计划 | `<包>/开发计划.md`                                        | 开工必写，范围不得事后私自扩张                        |
| 开发日志 | `<包>/开发日志.md`                                        | 每阶段追加一节，只追加不回改                          |
| 波次记录 | `docs/ADOPS/ADOPS-W<n>.md`                                | 主代理在波次收尾时汇总                                |
| 问题工单 | `项目日志与笔记/问题工单.md` + `工单NNN-描述/任务说明.md` | 架构缺口、接口/组件缺失、文档与代码不一致、工具链漂移 |
| 技术债   | `项目日志与笔记/技术债务清单.md`                          | 字段与优先级见《变更与决策管理》§6                    |
| RFC      | 任务所在目录 `RFC-<标题>.md`                              | 评审通过后创建 ADR                                    |
| ADR      | 文档库 `01-架构设计/ADR/ADR-NNN-标题.md`                  | 唯一模板见《变更与决策管理》§4.2                      |

正式技术契约不落在本仓库 `docs/`；需要沉淀到文档库的内容按[文档同步规则](../../薯片生态文档库/07-工程管理/03-变更与决策管理.md)在变更内更新。

## 四、计划与日志规范

- 计划必须覆盖：范围与产物、接口与契约对齐、依赖、测试与验收命令、风险与对策、台账回写点；验收命令必须可直接执行。
- 日志格式：`## <YYYY-MM-DD> <阶段名>` + 内容 / 证据 / 遗留三项；证据为命令与结果，遗留无内容时写"无"。
- 日志是过程材料，只保留追加序列；历史条目修订以追加更正节的方式完成，不改写旧条目。
- 波次收尾记录使用[ADOPS 模板](./模板/ADOPS-波次记录模板.md)，落位与命名见[ADOPS/README.md](./ADOPS/README.md)。

## 五、验证与门禁

| 层级     | 命令                                                                                                                          |
| -------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 包内     | `pnpm --filter <包名> run build / test / lint / typecheck / test:coverage / test:contract`                                    |
| Rust     | `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test -p <crate>`                |
| 流水线   | `pnpm ci`（根 `package.json` 唯一聚合入口，见下）                                                                             |
| 仓库门禁 | `README.md` §四 G1–G12；数值与判定以[《CI/CD 与质量门禁》](../../薯片生态文档库/06-开发与运维/05-CICD与质量门禁.md)为唯一权威 |
| 文档     | `pnpm docs:check`（坏链、索引、文档头、公开 API 覆盖率）                                                                      |

门禁失败不得合并；修复根因后全量重跑；豁免的唯一合法形式见《CI/CD 与质量门禁》§六。覆盖率、性能等数值门禁禁止在 PR 级放宽。

`pnpm ci` 按 `lint` → `typecheck` → `test`（`cargo test --workspace` + `pnpm -r run test`）→ `test:contract`（含 `tests/contract` 快照契约）→ `build` → `gates:all` 的顺序串行执行，覆盖 G1–G5、G6 判定、G8、G9、G12，与[《CI/CD 与质量门禁》§2.3](../../薯片生态文档库/06-开发与运维/05-CICD与质量门禁.md) 的五阶段命令等价、失败即停；本仓库不绑定任何托管平台，该命令即唯一流水线入口（本地一次跑完同用此命令）。G6 判定的输入报告由 `pnpm test:coverage` 单独产出（需 `cargo-tarpaulin`），不在 `pnpm ci` 链路内；G7 性能预算（`pnpm bench` 与 `tests/perf`）、G10 依赖审计与 G11 产物校验需要额外工具、网络或已打包产物，由流水线按阶段单独调用。

## 六、台账回写

```bash
python3 ../../重构大计划/工具/重构台账.py stats    # 波次进度核对
python3 ../../重构大计划/工具/重构台账.py next     # 认领待评估文件
python3 ../../重构大计划/工具/重构台账.py dispose  # 回写裁决（参数见 --help）
python3 ../../重构大计划/工具/重构台账.py report   # 生成仓库报告骨架
```

- 文件状态：`待评估 / 评估中 / 已裁决 / 进行中 / 已完成 / 已验证 / 阻塞`；裁决：`迁移 / 重写 / 保留设计 / 废弃 / 归档`。
- 完成证据：所属包验证命令与结果；每完成一个旧仓库批次，在仓库报告中维护《旧功能覆盖矩阵》（功能 → 新实现位置 → 测试名）。
- 旧仓库只读；迁移"复制 + 适配"，不修改旧文件；"保留设计"必须落到文档库章节或新实现的说明。

## 七、冲突预防

- 文件与包 owner 唯一；同一文件被多任务需要时由主代理串行化并指定唯一 owner。
- 跨包接口以文档库契约为准，禁止私改；公共工具（SDK、UI、契约常量）改动必须走 RFC 并在日志标注影响面。
- 模板与流程改动同步更新本文件、`docs/README.md` 与 `CONTRIBUTING.md`。

## 八、变更、工单与债务

| 触发                                        | 流程                                                                             |
| ------------------------------------------- | -------------------------------------------------------------------------------- |
| 重大变更（接口、格式、架构、依赖引入）      | RFC → 评审 → ADR → 实施 → 门禁 → 文档同步，见《变更与决策管理》§3、§4            |
| 架构缺口、组件/接口缺失、SDK 或脚手架不可用 | 登记问题工单与 `工单NNN-描述/任务说明.md`，继续推进不受影响部分                  |
| 技术债                                      | 登记 `技术债务清单.md`（`TD-NNN`），P0/P1 在当前阶段清零，见《变更与决策管理》§6 |
| 文档与实现不一致                            | 视为缺陷，同一变更内修复，见《变更与决策管理》§5                                 |
