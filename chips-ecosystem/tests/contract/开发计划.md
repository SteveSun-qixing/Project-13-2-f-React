## 一、目标

把 G8「契约一致性」从人工审阅变成可机器判定的测试：

1. **以文档库为唯一事实源**：能力 / 权限 / 事件 / 错误码 / 角色接口 / SDK 导出 / 帧协议七类权威表
   由本包解析器从 `薯片生态文档库/` Markdown 中读出，实现侧登记表与之逐项比对；
2. **四类判定手段**：集合逐项一致（`diffSets`）、子集判定（部分实现域）、双向闭合（帧消息代码块 ↔ 清单表）、
   快照锁定（声明形状、payload、导出清单）；
3. **偏差可自证**：以内存文档改写夹具驱动完整管线，每个注入都必须让对应检查产出预期偏差
   —— 即「检查器本身不会漏判」也被测试；
4. **差异必须显式评审**：快照只在 `CHIPS_CONTRACT_SNAPSHOT_UPDATE=1` 下更新，普通运行绝不静默覆盖；
5. **CI 工件**：无论通过或失败都输出 `reports/contract/contract-report.json` 与 `.md`（逐条偏差文本），
   门禁判定仍由 vitest 退出码承担。

## 四、接口与关键决策

1. **来源清单单点**：`src/docs/sources.ts` 是全包唯一写「文档路径 + 章节标题」的地方，文档重构（改名、拆章）只改本文件，
   检查逻辑不变；条目为 `{file, level, heading, section?}` 三元/四元选择器，另给出 6 个按域精确比对用的关键来源常量。
2. **解析失败必须显式抛出**：`markdown.ts` 与 `docs/*` 的章节或表未命中即抛错（含文件与章节标注），禁止静默跳过
   —— 静默跳过会让「契约缺失」被误报为「一致」。
3. **声明归一**：`docs/ts-declarations.ts` 用 TypeScript 编译器只取不带注释的 `getText()`（含 `getStart()` 语义），
   因此**文档注释改动不进快照**，而成员名、可选性、类型与顺序的改动必然进入差异；角色接口与帧协议共用该归一面。
4. **错误码分域视图**：同一错误码可被多处引用（如 `BRIDGE_TIMEOUT` 同时出现在 Bridge 表与能力调用表），
   注册表按来源保留分域视图，另给出全库去重并集用于「不得自造错误码」判定；
   章节内含表头为「错误码 / code」的登记表时以该表为来源权威码集，正文散句引用的他域码不进入来源域。
5. **实现侧读取方式（W1 过渡）**：`code/bridge.ts`、`code/host.ts` 以相对路径直接 import
   `packages/bridge/src/protocol/*`、`packages/host/src/platform/errors`、`packages/host/src/protocol/resource-error`，
   只读纯数据类型与常量模块，不引入 Electron / Node 依赖。头注钉明：包入口与构建产物发布后，
   `code/bridge.ts` 是唯一需要切换导入路径的位置。
6. **快照模式**：`snapshots/` 四个 JSON 随包提交（供差异评审），`SNAPSHOT_SCHEMA_VERSION = 1`；
   更新只允许显式环境变量触发，差异清单同时进入失败消息与报告。
7. **偏差夹具**：`fixtures/deviations.ts` 以内存 `DocReader` 替换文件系统，不写回真实文档；
   `replaceOnce` 要求目标文本恰好命中一次，未命中即夹具自身失败（防止偏差注入静默失效）；
   偏差用例的验收标准是「必须失败」。
8. **报告器不判定**：`reporter.ts` 使用 `onTestRunEnd`，保证断言失败、收集失败与进程未捕获错误都进入报告，
   但不修改退出码。

## 五、依赖与选型

- 零第三方运行时依赖：只用 `node:fs` / `node:path` / `node:url` 与 vitest；
  唯一实质第三方能力是 **TypeScript 编译器 API**（`typescript` devDependency，用于声明归一），属仓库根已锁定的工具链，无新增选型。
- 不依赖 `@chips/sdk` / `@chips/bridge` 的构建产物，因此**不引入构建顺序依赖**（代价是 §四.5 的过渡式相对导入）。
- 不使用 `@chips/testing` 工厂：本包需要自定义 reporters 与 30 s 超时，且 `tools/*`、`tests/*` 的边界规则
  只放行测试基础设施包作为 `*.config.*` 的 devDependency，故采用独立 `defineConfig`。

## 七、现状缺口与风险

| # | 缺口 / 风险 | 现状证据 | 处置口径 |
| --- | --- | --- | --- |
| 1 | **G8 判定分散在 6 个 `test:contract` 脚本，其中两处为空** | 根 `test:contract` = `cargo test -p chips-native && pnpm -r run test:contract`；`packages/sdk`（`vitest.contract.config.ts` 的 include 指向不存在的 `tests/contract/**`）与 `packages/bridge`（同）**实跑均为 `No test files found`，退出码 1**；`packages/host` 的 `vitest run tests/contract` 靠文件名子串命中 `tests/contract-matrix.test.ts`（24 用例）而偶然通过，包内并无 `tests/contract/` 目录 | 需统一收口：要么在各包补齐契约目录，要么把跨包判定集中到本包并由根脚本单独调用；属脚本/配置改动，本轮（纯文档）未动 |
| 2 | 实现侧过渡式相对导入 | `src/code/bridge.ts`、`src/code/host.ts` 深读 `packages/*/src/**`，绕过包入口与 `exports`；一旦 bridge/host 源码移动路径，本包编译期即断 | 头注已钉切换点；收口时机为 `@chips/bridge` 发布 `exports` 与构建产物后（同文件单点改动） |
