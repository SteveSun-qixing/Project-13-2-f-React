## 一、目标

在 `chips-ecosystem/tests/perf/` 交付可执行、可回归、可被 CI 消费的性能基线与测量工具：

1. **指标定义**：把《架构原则》§4.2 / R18、渲染引擎与文档解析器预算、内核与事件性能约束中的全部性能门禁编码为唯一注册表（含口径、统计量、权威来源引用），工具内不自创任何门禁数值。
2. **测量方法**：标记点（markers）时间线 → 阶段耗时；采样（帧时间戳 → 帧率分桶；RSS 采样 → 稳定态）；统计（多轮取中位数，输出 P50/P95/P99/均值/极值/标准差）。
3. **报告格式**：同一份测量的 JSON（机器消费）+ Markdown（评审证据）双格式报告，随流水线归档。
4. **回归比较**：基准报告 vs 候选报告的绝对门禁判定 + 相对回归判定；容差、噪声下限、采样轮次、空闲窗口均可配置；环境/构建类型不可比时给出显式结论（不作门禁结论）。
5. **自测**：合成数据（golden / regressed 两套场景）端到端驱动真实测量管线与判定逻辑，验证「达标必过、劣化必拦」。
6. **接入契约**：`PerfAdapter` 接口 + `ingest` 命令，供 W2 金链路（Host/RenderEngine/解析器）与 Rust criterion 结果接入，不在工具内放占位实现。

## 四、依赖

- 仅依赖 Node.js 内置模块与开发期工具（typescript、vitest、tsx、eslint），零运行时第三方依赖。
- 包需加入 pnpm workspace（`pnpm-workspace.yaml` 增补 `tests/*`），workspace install 后按包脚本运行。
- 被测量系统通过 `PerfAdapter` 注入，工具不直接依赖 `@chips/host` / `@chips/sdk`（W1 尚未就绪），避免跨层直连。

## 五、接口设计要点

1. `PerfAdapter.run(context)` 返回四类原始信号：`markers`（标记点时间线）、`frameTimestampsMs`（rAF 时间戳）、`memorySamples`（RSS 采样）、`metricSamples`（显式样本，用于解析基准与内核 μs 级指标）。
2. 场景按 `kind` 选择测量路径：`markers`（多轮取中位数 + 阶段分解）、`frames`（10s 采样 → 分桶帧率）、`memory`（空闲窗口稳定态）、`samples`（外部样本直报）。
3. 门禁判定：`gateStatistic`（median/mean/p95/p99/max）+ `gateComparison`（lt/lte/gt/gte）逐指标显式声明，直接映射文档口径。
4. 报告：`schemaVersion` + `meta`（构建类型、设备、Phase、适配器、场景、环境）+ 指标明细（样本、统计、门禁、判定、引用）+ 阶段分解 + 汇总。
5. 回归比较：绝对门禁失败 → `gate-fail`；超容差劣化 → `regression`；构建类型/设备/Phase/模式不一致 → `incomparable`（退出码 3，不作为门禁结论）。

## 六、测试与验收

| 验收项           | 命令（workspace install 后）                                              | 当前环境验证方式                                                    |
| ---------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------- |

| 自测（合成数据） | `pnpm --filter @chips/perf run selftest`                                  | `node_modules/.bin/tsx src/cli.ts selftest`                         |
| 回归比较样例     | `pnpm --filter @chips/perf run compare -- --baseline ... --candidate ...` | 由 selftest 直接产出并校验                                          |

DoD：

- `test`/`typecheck`/`lint` 全绿；自测输出 golden 全过、regressed 全拦、比较判定为 fail；
- 报告中每个门禁均可回溯权威文档引用；工具内无 TODO/占位/临时实现；
- `reports/` 产物不入库；README 说明接入契约与 CI 用法。

## 七、风险与对策

| 风险                                       | 对策                                                                                       |
| ------------------------------------------ | ------------------------------------------------------------------------------------------ |
| 被测量系统尚未实现（W1 并行中）            | 工具以 `PerfAdapter` 解耦；自测用合成数据覆盖全管线，真实接入留接口契约与 README 说明      |
| 门禁数值被转述漂移                         | 指标注册表与引用同记录；测试用冻结期望表比对                                               |
| 统计口径歧义（中位数 vs 均值 vs P95）      | 每指标显式 `gateStatistic`，与文档口径一一对应                                             |
| 环境不可比导致误判                         | 可比性检查（构建类型/设备/Phase），不可比输出 `incomparable`，退出码 3，不作门禁结论       |
| 文档测量窗口不一致（空闲 5 分钟 vs 60 秒） | 空闲窗口可配，默认取门禁表 G7 的 5 分钟；60 秒快检模式在配置中显式声明；差异登记于开发日志 |
