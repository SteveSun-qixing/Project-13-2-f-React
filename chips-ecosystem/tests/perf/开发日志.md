## 截至 2026-09-20 现状核验：六个职责面的落位

- 门禁面（`src/metrics.ts`）：性能门禁的**唯一编码处**，注册表 21 项指标，门禁值与 `citation` 同记录编码
  （《架构原则》§4.2 与 R18 五项基线、渲染引擎 §10.1/§10.4、解析器 §9.2/§9.5、内核 §11.1/§11.3、事件系统 §9.1），
  逐指标显式声明 `gateStatistic`（median / mean / p95 / p99 / max）与 `gateComparison`（lt / lte / gt / gte）；
  文档未指定统计量的延迟类指标统一按「多轮取中位数」协议；`tests/metrics.test.ts` 以冻结期望表校验编码与权威值一致。
- 策略面（`src/thresholds.ts` + `perf.config.json`）：门禁值不写入本文件，只承载工具策略 ——
  `schemaVersion 1.0.0`（版本不匹配即拒绝加载）、`phase: 4`、`allowGateOverride: false`（覆盖项必须显式给理由）、
  按单位的回归容差（ms / us / count 10%，fps / mb 5%）与绝对噪声下限、测量策略（5 轮 + 1 预热轮、
  空闲窗口 300000 ms 即 G7 的 5 分钟口径）、报告输出目录。
- 测量面（`src/markers.ts` / `fps.ts` / `memory.ts` / `parser-bench.ts` / `scenarios.ts` / `runner.ts`）：
  标记点时间线与 CHIPS_TRACE JSON 导入；帧时间戳 → 每秒分桶帧率、长帧比例与帧时间统计（帧预算常量
  `FRAME_BUDGET_MS = 1000 / 60`）；RSS 采样 → 稳定态 / P50 / 峰值 / 趋势；解析基准执行器（预热 + 多轮、可注入时钟）；
  场景注册表 10 个（`cold-start` / `open-card` / `open-box` / `scroll-fps` / `idle-memory` / `parse-card-10mb` /
  `parse-metadata` / `parse-box-10k` / `kernel-latency` / `resource-caps`），按 `markers` / `frames` / `memory` /
  `samples` 四类路径选择测量方式；`runner.ts` 编排场景 → `MetricResult` / `PhaseResult`。
- 判定面（`src/compare.ts`）：绝对门禁失败 → `gate-fail`、超容差劣化 → `regression`、
  构建类型 / 设备 / Phase / 模式不一致 → `incomparable`（退出码 3，不作门禁结论）；容差与噪声下限取自策略面，
  与门禁值分列。
- 报告与接入面（`src/report.ts` / `src/adapters.ts` / `src/cli.ts` / `src/index.ts`）：JSON + Markdown 双格式报告，
  `meta` 含构建类型、设备、Phase、适配器、场景与环境，逐指标携带样本、统计、门禁、判定与引用，读入即校验、
  JSON 往返一致；`PerfAdapter.run(context)` 返回标记点 / 帧时间戳 / RSS 采样 / 显式样本四类原始信号；
  CLI 提供 `list` / `selftest` / `measure` / `ingest` / `compare` 五个子命令；公共导出面聚合于 `src/index.ts`。
- 自测面（`src/fixtures/synthetic.ts` + `selftest.ts`）：种子确定性合成数据（golden / regressed 两档，头注钉明
  合成值非门禁值）；自测只替换数据来源，测量编排、统计、门禁判定、报告与回归比较全部走真实实现，共 9 个检查项。
