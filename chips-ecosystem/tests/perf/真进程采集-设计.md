## 一、目标与形态

把 `@chips/perf` 既有测量管线（markers / frames / memory / samples 四类信号路径与
`assertValidAdapter` 校验）接上**真实宿主进程**，产出可被 `pnpm run ingest` 消费的外部样本
JSON（落点 `reports/real-samples-<scenario>.json`，形状 = cli ingest 契约
`{ meta?, samples }`），覆盖五指标场景：`cold-start`、`open-card`、`open-box`、
`scroll-fps`、`idle-memory`。

正式采集命令（旗标门控，命名与 `CHIPS_E2E_REQUIRE_APP` 惯例同族）：

```
CHIPS_PERF_REAL=1 pnpm exec tsx src/real/collect.ts --scenario all
```

单场景可分别执行（`--scenario cold-start|open-card|open-box|scroll-fps|idle-memory`）。
采集脚本退出码只反映「采集是否完成」，不反映门禁判定（门禁判定归段B）。

## 二、真进程承载（复用面）

- 复用 `@chips/e2e` 公开面（`tests/e2e/src/index.ts`）：`resolveHostApp`、`launchHostApp`、
  `closeHostApp`、`createTestWorkspace`、`openDocument`——经 `src/real/e2e-runtime.ts`
  **运行时动态装载**（`pathToFileURL` + 动态 `import`，非静态模块边）。
  - 被否决形态①：在 `tests/perf/package.json` 增列 `@chips/e2e` / `@playwright/test` 依赖
    ——本单禁改任何 package.json，且会破坏本包「零运行时第三方依赖」的既定架构（计划 §四）。
  - 被否决形态②：自造 Electron 直启 + 裸 CDP 客户端——绕开 e2e 既有承载辅助，重复造启动/
    就绪判定语义，违背「采样口径全部走既有 API」的要求。
  - 被否决形态③：以 Playwright spec 形态挂进 `tests/e2e/specs`——属跨包写入（`tests/e2e/**`
    禁改），且 Playwright 用例形态无法消费 `@chips/perf` 的 markers/frames/memory 管线。
- 真产物判据：宿主入口取 `packages/host` 构建产物（正式启动面 `dist/main/app.js`，即
  `pnpm --filter @chips/host app` 的 bootstrap 窗口入口——`package.json#main` 指向的
  `dist/main/main.js` 是装配库不自举窗口，实测以首窗口就绪探测直接失败，故冷启动/空闲内存
  取 `app.js`；文档能力面取在册 E2E 承载 `dist/main/e2e-app.js` +
  `host-wiring/e2e-document-wiring.cjs`，即 `CHIPS_E2E_REQUIRE_APP` 金链路同源通道）。
  构建产物缺失时采集器**如实 fail-closed** 并提示正式构建命令，不造假数据、不读死值。
- Playwright 求值契约（实测钉桩，见 `tests/real-process.test.ts` rAF 替身用例）：
  1. **页面侧**：函数源码一律以纯 JS 字符串承载（tsx/esbuild `keepNames` 会给含内部具名
     绑定的序列化函数注入浏览器侧不存在的 `__name`，实测 `ReferenceError`）；且字符串表达式
     求值**不会被自动调用**（实测「字符串 + 实参」形态回包为 `undefined`），实参必须以
     IIFE 调用表达式内联承载（`(${SRC})(${JSON.stringify(arg)})`）。
  2. **主进程侧**（`electronApp.evaluate`）：与页面侧不同，其字符串表达式在 node 上下文裸
     求值且 `require` 不可用（实测 `ReferenceError: require is not defined`）；只有**真函数**
     入参会被以 `require('electron')` 模块为首参调用。故 `collectHostRssBytes` 用内联
     匿名单表达式箭头（零内部具名绑定，规避 `__name` 注入面）。

## 三、五指标口径 → 外部可观测映射（宿主侧无内建标记）

宿主当前**没有内建 `CHIPS_TRACE` 标记点导出**（渲染引擎标记与 `startup:*` / `render:*`
里程碑不在 W2 交付面）。段A 一律用外部可观测量归一，数值全部来自实测采样：

| 场景        | 权威口径（§8.1 / R18）             | 外部可观测代理                                                                                                                                                    | 口径差登记                                                                                                                                                                          |
| ----------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| cold-start  | 主进程启动 → 首个应用窗口可用      | `electron.launch` 发起前时刻 → `launchHostApp` 返回（含首窗口 + Bridge 就绪两步探测，与 e2e 启动器就绪判定同口径）                                                | 含 Playwright 侧启动调用与就绪探测往返开销（偏保守）                                                                                                                                |
| open-card   | `RenderEngine.open()` → 首帧提交   | `document:open` 请求发出 → 回包 resolve（Bridge 往返，含真实原生解析 + 会话建立）                                                                                 | 「首帧提交」不可外部观测（卡片 DOM 渲染臂为在册集成缝 #99）；三阶段分解（parse / frame-ready / first-commit）缺测臂                                                                 |
| open-box    | 同上，含首屏条目帧                 | **不可测**：`kind:'box'` 视图面主进程构建侧在册闸诚实拒绝（`BRIDGE_INVALID_INPUT`，刀3 `document-view-builder.ts`，箱子视图随 W4 箱子波）；条目首屏无任何可观测量 | 采集器真进程探针坐实拒绝码后产出「不可测」结论文件，不产样本                                                                                                                        |
| scroll-fps  | 滚动/编辑场景持续 10 s rAF 帧率    | 壳窗口 `requestAnimationFrame` 时间戳（≥10 s）+ 持续 `mouse.wheel` 滚动                                                                                           | W2 期 RenderEngine 帧池不进壳窗口滚动路径（卡片 DOM 渲染臂未接通），帧率为宿主窗口合成器口径；`render_update_ms`（单帧更新任务 P95）属渲染引擎内部标记，外部无在册导出 → **缺测臂** |
| idle-memory | 稳定态平台级 RSS（G7 空闲 5 分钟） | Electron 主进程 `app.getAppMetrics()` 全进程 RSS 求和，按 5 s 间隔采样满空闲窗口（§8.4 工具清单在册路径）                                                         | 与 `process.memoryUsage()` 单进程口径无关，取平台级（主+渲染+GPU 全进程）合计                                                                                                       |

### 宿主侧标记缺口登记（交段B / 后续波）

1. 宿主无 `CHIPS_TRACE` 标记点导出 → cold-start 的 `startup:*` 里程碑、open-card 的
   `render:*` 阶段边界全部缺位；本轮以外部时间戳代理，阶段分解缺测。
2. 「首帧提交」（`render:first-frame-commit` / `render:entries-first-screen-commit`）
   无任何外部可观测量：卡片/箱子 DOM 渲染臂未接通（#99），箱子视图面随 W4。
3. `render_update_ms`（单帧更新任务耗时，P95 ≤ 16 ms）需渲染引擎内部计时导出，外部不可测。
4. `open-box` 整场景不可测（视图面 W4 前无交付），本轮只产出「不可测」结论与真进程证据。

## 四、样本组装与 ingest 契约

- 每场景样本文件：`{ meta: { buildType, deviceLabel, hostVersion, notes }, samples: { <metricId>: number[] } }`，
  `samples` 一律过 `validateMetricSamples` 与「场景声明指标」双闸（与 `metricsFromIngest` 同语义）。
- `buildType` 如实标注：本地开发构建产物非 release 打包形态 → `debug`；正式门禁结论须由
  CI release 构建复测（G7），本轮不构成正式基线。
- 轮次、空闲窗口、采样间隔一律读自 `perf.config.json`（`loadConfigFile`）；工具与本包代码
  **零自创门禁数值**（判定值唯一来源仍是 `src/metrics.ts` 注册表）。
- 测量语义复用：cold-start / scroll-fps / idle-memory 走 `measureScenario` 真实管线
  （markers 多轮中位数输入 / `summarizeFrames` 分桶 / `summarizeMemory` 稳定窗），从报告
  提取样本入 ingest 文件；open-card 因阶段标记缺测不走 `measureScenario`（其 markers 路径
  强制要求阶段标记点），由 `MarkerTimeline` 按 `totalSpan` 逐轮求时长——同一标记点语义，
  仅阶段分解缺测。
- `open-box` 产物为 `reports/real-unmeasurable-open-box.json`（结论 + 原因 + 探针证据），
  形状刻意区别于 ingest 契约，防止被误消费为样本。
