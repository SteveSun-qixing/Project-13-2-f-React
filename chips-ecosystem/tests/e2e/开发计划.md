## 一、范围与产物

- 目标：在 `chips-ecosystem/tests/e2e/` 交付可执行、可演进、可被 CI 消费的 Playwright Electron E2E 骨架：启动器、断言工具、金链路用例、产品级夹具，以及 `pnpm test:e2e` 入口。
- 交付物：

| 产物         | 落点                                      | 完成标准                                                                                                             |
| ------------ | ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 启动器       | `src/launcher.ts`                         | 解析构建产物与 Electron 运行时，启动宿主、等待首窗口与 Bridge 就绪、逆序关闭；参数构造为纯函数且可单测               |
| 断言工具     | `src/assertions.ts`                       | 覆盖窗口、渲染帧、资源句柄、文档会话四类断言；全部经 `window.chips` 与 DOM 可观察面，不引入调试端口                  |
| 金链路用例   | `specs/golden-path.spec.ts`               | 打开卡片 → 渲染 → 编辑 → 保存 → 落盘复核全链路断言，只使用文档库契约能力                                             |
| 夹具自检用例 | `specs/harness.spec.ts` + `fixtures/app/` | 用受控的夹具 Electron 应用验证启动器与断言工具本身可用                                                               |
| 产品级夹具   | `fixtures/generate-fixtures.mjs` 与产物   | 最小 `.card`（目录态 + ZIP Store 归档态）与最小 `.box`，逐字节可复现，字段符合《01-卡片文件格式》《02-箱子文件格式》 |
| 临时工作区   | `src/workspace.ts`                        | 每个用例独立工作区（`--workspace=`），用例间零共享状态                                                               |
| 单测         | `tests/*.test.ts`                         | 参数构造、环境解析、工作区装配、夹具清单校验在 vitest 下可跑                                                         |
| 入口         | 根 `package.json`                         | `pnpm test:e2e`、`pnpm test:e2e:fixtures`、`pnpm test:e2e:fixtures:check` 可执行                                     |
| 文档         | `README.md`、`开发计划.md`、`开发日志.md` | 使用说明、权威来源、接入契约与证据齐全                                                                               |

- 不在范围：W2 金链路实现（Host/渲染/编辑链路本体）、W3 全链路测试矩阵、性能基线（`tests/perf`）、契约测试（`tests/contract`）；宿主构建与运行由 `packages/host` 及上游任务提供。

## 四、实施步骤

1. 固件层：校正 `fixtures/generate-fixtures.mjs` 与 `manifest.json`，确保最小卡片/箱子为产品级数据且可逐字节复现。
2. 环境层：`environment.ts` 增加宿主构建检测与夹具应用解析；`workspace.ts` 提供每用例独立工作区与夹具装配。
3. 启动层：`launcher.ts` 构造启动参数（纯函数）、启动 Electron、等待首窗口与 Bridge 就绪、逆序关闭。
4. 断言层：`assertions.ts` 提供窗口、帧、资源、文档会话四类工具与 `waitForEvent`。
5. 夹具自检：`fixtures/app/` 夹具 Electron 应用 + `specs/harness.spec.ts` 证明工具链可用。
6. 金链路：`specs/golden-path.spec.ts` 打开 → 渲染 → 编辑 → 保存 → 落盘复核。
7. 单测与门禁：`tests/*.test.ts`、`vitest.config.ts`、`playwright.config.ts`（harness / golden-path 双 project；金链路在 W2 准出前由 `CHIPS_E2E_GOLDEN_PATH=1` 启用，CI 门禁使用 `CHIPS_E2E_REQUIRE_APP=1`）。
8. 文档：README、开发计划、开发日志；回写验证证据。

## 五、测试与验收命令

```bash
cd chips-ecosystem
pnpm test:e2e:fixtures:check                                        # 夹具与生成结果逐字节一致
pnpm test:e2e                                                       # Playwright：harness 自检（宿主未构建时明确提示）
CHIPS_E2E_REQUIRE_APP=1 pnpm test:e2e                               # 严格模式：宿主缺失即失败（CI 与 W2 准出）
pnpm -C tests/e2e test                                              # 骨架单测（vitest）
pnpm -C tests/e2e typecheck
pnpm -C tests/e2e lint
```

- 覆盖率要求：引用[《测试规范》§一](../../../薯片生态文档库/02-开发规范/05.01-05-测试规范-一、测试策略.md)与[《CI/CD 与质量门禁》](../../../薯片生态文档库/06-开发与运维/05-CICD与质量门禁.md) G6 的判定口径，本计划不转述数值。
- DoD：夹具检查、单测、typecheck、lint 全绿；`pnpm test:e2e` 可执行且行为确定；金链路用例在 W1-HOST 构建产物就绪后自动纳入执行。

## 六、风险与对策

| 风险                                                 | 对策                                                                                                |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 宿主（W1-HOST）尚未产出构建产物，金链路无法执行      | Playwright 配置按构建检测纳入 golden-path project；`CHIPS_E2E_REQUIRE_APP=1` 严格模式防止静默跳过   |
| 金链路依赖的应用窗口归属不明确（壳窗口 vs 应用窗口） | 启动器等待首窗口；帧断言与文档会话断言允许按全部窗口扫描定位，不硬编码窗口数量                      |
| 帧内为不透明源，无法按 origin 判定                   | 只按 DOM 可观察面（沙箱属性、尺寸、帧内文本）断言，与《渲染引擎设计》§9 的信任模型一致              |
| 宿主任一环节未就绪导致超时难定位                     | 启动器分阶段超时（启动、首窗口、Bridge 就绪、帧就绪）并输出阶段名与截图，失败产物入 `test-results/` |
| 夹具漂移（手工修改产物）                             | `generate-fixtures.mjs --check` 逐字节校验；单测再校验字段与 ID 规范                                |
