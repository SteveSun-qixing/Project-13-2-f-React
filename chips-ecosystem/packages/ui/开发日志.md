- 计划显式登记的八项关键决策，其中三项影响后续契约收口：
  1. **命令类型双源**（§四.1）：本包不依赖 `@chips/bridge` / `@chips/sdk`，命令契约形状在 `src/command/contract.ts`

  3. **平台访问端口**（§四.3）：命令运行时经 `ICommandBridgePort`（`request` + `subscribe` 的最小结构投影）访问平台，

## 截至 2026-09-20 现状核验：测试夹具口径

`tests/helpers/harness.tsx` 是共享层唯一的测试装配面，其口径与真实窗口挂载方式一一对应：

- **端口注入而非全局伪造**：Mock 实现 `ICommandBridgePort`（记录 `calls`、能力桩 `handle`、事件 `emit`、
  `subscribed` 清单、`reset`），经 `CommandProvider` 的 `port` 传入；夹具不写 `window.chips` 全局。
  头注登记后续替换点：`@chips/sdk/testing` 落位后由其 `installMockBridge` 承担（本包不新增 `@chips/sdk` 依赖）。
- **`makeCommandView`**：以最小覆盖参数构造 `ICommandView`，`owner` 缺省为
  `{ kind: 'plugin', pluginId: 'chips.test.app', sessionId: null }`、`state` 缺省为
  `{ visible: true, enabled: true, checked: false }`、`target` 缺省 `'ui'`，用例只覆盖被断言的字段。
- **`windowEnvironmentRoot` / `renderWithWindowEnvironment`**：`ChipsProvider` 经主题根安装 antd `App` 根节点，
  该节点才是被测组件树在挂载容器内的实际根；夹具把它作为返回结果的 `container`，
  使结构断言直接指向被测组件自身（`container.firstElementChild` 即被测组件根元素），
  不依赖主题根的实现细节；找不到该根时以简体中文错误显式失败，不静默回退。
- **环境经 `wrapper` 挂载**：`rerender` 只替换被测组件，提供者树（令牌、主题根、命令运行时）保持不变，
  与真实窗口一致；`renderWithApp` 提供运行环境，`renderWithCommands` 额外包裹 `CommandProvider`。

## 遗留与阻塞

1. **`lint` 仍为红灯（产物面）**：`lint` 脚本为 `eslint . && prettier --check .`，本包目录不含 `.prettierignore`，
   仓库根 `.prettierignore` 未覆盖包内 `dist/**`，`prettier --check .` 因此把 `dist/` 的 92 个产物文件判为不合规
   （`eslint .` 本身已通过，`ignores` 含 `dist/**`）。`packages/antd` 与 `tests/e2e` 是各自带 `.prettierignore` /
   忽略清单才通过的。修法是包内补忽略项或脚本改为只检源面，属配置改动，本轮（纯文档）未动。
2. **包内缺 `README.md`**：`开发计划.md` §八 交付判定要求本包 README 齐备，现状只有 `开发计划.md` 与 `开发日志.md`。
3. **命令契约类型双源**：`src/command/contract.ts` 与 `@chips/sdk` 各有一份《13》结构投影，
   `ICommandSubscription` 亦为本包独立命名；收口约定为 W3 契约测试，见计划 §四.1、§七 风险表首行。
4. **帧内令牌注入未在本包落地**：帧运行时注入 `--chips-*` 并在帧根安装同一套主题配置的链路属集成任务
   （计划 §四.8），本包只提供主题配置与 fork 的 CSS 变量契约；集成点已在计划中登记。
5. **覆盖率判定为全局面**：`defineChipsProject` 的阈值作用于 `All files`，
   `src/tokens` 分支覆盖率 77.77% 低于 90% 但不触发门禁（全局面 92.74%）。若门禁需要收紧到目录级，
   须由 `@chips/testing` 统一决定，本包不单方面改配置。
6. **`tests/` 目录无测试文件**：包内用例全部与源码同目录（`src/**/*.test.tsx?`），
   `tests/` 仅有 `setup.ts` 与 `helpers/harness.tsx`；工厂默认 `include` 已覆盖两种位置，故不构成问题，
   但包级集成测试若要落 `tests/`，需与本包 20 个同目录测试文件划分职责以免重复断言。
