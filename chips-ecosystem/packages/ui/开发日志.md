## 截至 2026-09-20 现状核验：测试夹具口径

`tests/helpers/harness.tsx` 是共享层唯一的测试装配面，其口径与真实窗口挂载方式一一对应：

- **端口注入而非全局伪造**：Mock 实现 `ICommandBridgePort`（记录 `calls`、能力桩 `handle`、事件 `emit`、
  `subscribed` 清单、`reset`），经 `CommandProvider` 的 `port` 传入；夹具不写 `window.chips` 全局。
  头注登记后续替换点：`@chips/sdk/testing` 落位后由其 `installMockBridge` 承担（本包不新增 `@chips/sdk` 依赖）。
- **`makeCommandView`**：以最小覆盖参数构造 `ICommandView`，`owner` 缺省为
  `{ kind: 'plugin', pluginId: 'chips.test.app', sessionId: null }`、`state` 缺省为
  `{ visible: true, enabled: true, checked: false }`、`target` 缺省 `'ui'`，用例只覆盖被断言的字段。
- **`windowEnvironmentRoot` / `renderWithWindowEnvironment`**：`ChipsProvider` 经主题根安装 antd `App` 根节点，
  该节点才是被测组件树在挂载容器内的实际根；夹具把它作为返回结果的 `container`，
  使结构断言直接指向被测组件自身（`container.firstElementChild` 即被测组件根元素），
  不依赖主题根的实现细节；找不到该根时以简体中文错误显式失败，不静默回退。
- **环境经 `wrapper` 挂载**：`rerender` 只替换被测组件，提供者树（令牌、主题根、命令运行时）保持不变，
  与真实窗口一致；`renderWithApp` 提供运行环境，`renderWithCommands` 额外包裹 `CommandProvider`。
