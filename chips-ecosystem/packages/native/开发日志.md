## 2026-09-19 阶段 1：编译错误修复与实现收口（FIX-NATIVE 修复轮）

### 背景

工单 008 登记 `chips-native` 自身 8 项编译错误；修复过程中又暴露出被前置签名错误
抑制的若干潜在缺陷（E0283 / E0599 / E0308 / E0499）。本轮一并收口。

### 根因与修复点

1. **Neon 类型导入缺失**
   - `convert.rs`：`JsBigInt` 不在 `neon::prelude`，补 `use neon::types::JsBigInt;`。
   - `runtime.rs`：`Deferred` 不在 `neon::prelude`，补 `use neon::types::Deferred;`。
2. **名称遮蔽（Neon trait 被同名字段/枚举遮蔽）**
   - `error.rs`：`use serde_json::Value` 遮蔽 `neon::prelude::Value` trait。改为
     `use serde_json::Value as JsonValue;`；`throw_chips_error` 签名收口为
     `NeonResult<V>`（不要求 `V: Value`）——Neon 1.1 的 `Context::throw<T: Value, U>`
     只约束抛出值 `T`，返回值 `U` 任意，因此该助手可直接用于返回 `Vec<String>` 等
     非 JS 值的内部参数解析函数。
   - `handles.rs`：`use chips_cordis::Context` 遮蔽 Neon `Context<'a>` trait。改为
     `use chips_cordis::Context as KernelContext;`，结构字段与回投参数改用别名。
3. **句柄与数组参数映射收口（核心接口规范 §8.4）**
   - `context.rs::context_argument`：返回类型由非法的
     `JsResult<'cx, NativeContextHandle>` 改为 `NeonResult<KernelContext>`；句柄仍以
     `JsBox<NativeContextHandle>` 从 JS 接收，内部取回内核 `Context` 克隆，7 处调用点
     去掉 `.0` 间接层。
   - `context.rs::string_array_argument`：返回类型由非法的 `JsResult<'cx, Vec<String>>`
     改为 `NeonResult<Vec<String>>`；元素非字符串时经 `throw_chips_error` 抛
     `NATIVE_TYPE_UNSUPPORTED`（`/dependencies` 指针）。
4. **被前置错误抑制的潜在缺陷**
   - `convert.rs`：`global.upcast()` 推断歧义，显式 `upcast::<JsValue>()`。
   - `envelope.rs`：`JsBuffer` / `JsUint8Array` 的 `as_slice` 来自 `TypedArray` trait，
     补 `use neon::types::buffer::TypedArray;`。
   - `error.rs`：`js_error.upcast::<JsValue>()` 显式化，消除 `Context::throw` 的 `U`
     推断歧义。
   - `runtime.rs`：`Deferred::settle_with` 的闭包按值接收 `Cx`，`settle` 调用改为
     `settle(&mut cx, value)`、错误路径 `throw_chips_error(&mut cx, error)`。
   - `handles.rs`：三处回调调用在同一表达式中二次可变借用 `cx`（E0499），先取
     `let undefined = cx.undefined();` 再 `function.call(&mut cx, undefined, …)`。
5. **clippy / 死代码收口**
   - `convert.rs`：去掉尾表达式多余的 `return`（`needless_return`）。
   - 对「已交付、待接线」的模块与测试/诊断专用访问器加**逐项 scoped
     `#[allow(dead_code)]`**，并标注原因：`envelope` 模块级（Bridge 能力导出被工单005
     阻塞）；`runtime`（异步导出未落地）；`error::BRIDGE_INTERNAL` /
     `chips_error_from_js` / `unrecognized_error` / `is_normalized_code` /
     `error_shape`；`handles::JsServiceValue::kind`、`abi::EXPORT_NAMES`、
     `cancel::is_cancelled`、`context::ListenerRegistry::len`、`convert::ConvertIssue::pointer`。
     工单005 与异步导出落地时随接线移除对应属性；未使用 `unwrap` / `expect` / `panic`。
6. **（无）业务逻辑新增**：绑定层仍只做类型转换、错误归一与线程回投；未引入
   `chips-bridge` 相关实现（工单005 未收口）。
7. **格式归一**：`cargo fmt -p chips-native` 按 stable rustfmt 输出归一（含既有漂移），
   归一后 `cargo fmt -p chips-native -- --check` 为 0 diff。

## 2026-09-20 阶段 3：工单005 剩余面（W2）——Bridge 域四导出落地

### 背景与目标

交付工单005 剩余的 Bridge 域四个 Neon 导出：`bridgeRegister`、
`bridgeUnregister`、`bridgeRequest`、`bridgeCancelSession`，全部转发已入库的

与线程回投；注册表 / 权限判定 / Schema 校验 / 并发准入 / 超时取消语义全在内核侧。

### 交付内容

- 新增 `src/bridge.rs`：进程级 `Bridge` 单例（`OnceLock<Bridge>`，`Bridge` 为
  `Arc` 句柄，`Clone` 共享内核状态）；四个导出；`TsCapabilityExecutor`
  （`CapabilityExecutor` trait 实现）把内核调用回投 JS 线程执行 `handler`；
  `JsHandler`（`Root<JsFunction>` + `Channel`）持有并释放 JS 回调；
  `create_abort_controller` / `abort_controller` 经 `Reflect.construct` 桥接
  JS 原生 `AbortSignal`；纯 helper 与内核交互单测（6 个 `#[test]`）。
- `src/envelope.rs`：新增 `js_with_bin_to_json` / `walk_with_bin`（handler 返回值
  的 `Uint8Array` / `Buffer` 叶子抽取进 `bin`，指针占位），与 `json_with_bin_to_js`
  互逆；移除文件级 `#![allow(dead_code)]`，仅对确无消费者的 `bin_to_js` 保留
  最小作用域 `#[allow(dead_code)]` + 中文原因。
- `src/convert.rs` / `src/error.rs`：`js_to_json`、`convert_js_value/_array/_object`、
  `is_plain_object`、`is_other_typed_array`、`chips_error_from_js` 泛化为双生命周期
  `<'a, 'v, C: Context<'a>>(cx: &mut C, value: &Handle<'v, JsValue>)`，使
  `JsPromise::to_future` 回调（句柄与上下文生命周期必然不同）可直接复用（§8.3 规则 7）。
- `src/runtime.rs`：`RUNTIME` / `runtime()` / `spawn_result` 去 `dead_code`；
  `settle_json` 保留最小作用域 `#[allow(dead_code)]`（`bridgeRequest` 走
  `output_settle` 信封合并入口）。
- `src/error.rs`：移除 `BRIDGE_INTERNAL` / `chips_error_from_js` / `unrecognized_error`
  / `is_normalized_code` 的 `dead_code`（现由 §8.5 反向归一消费）。
- `src/abi.rs`：`export_table!` 追加四导出（顺序与清单/d.ts 一致）。
- `Cargo.toml`：登记 `chips-bridge` path 依赖、`async-trait`、`neon` 增 `futures` feature。
- 三方一致性：`abi/export-surface.json`（四导出转 `exports`、`blocked: []`）、
  `types/chips-native.d.ts`（四函数声明 + `INativeCapabilityContext.deadline` 转必填）、
  `tests/typecheck/fixtures.ts`（正例 + 4 `@ts-expect-error` 负例）同步更新。
- `README.md`：导出面表新增 Bridge 域，目录树登记 `bridge.rs`。

### 契约对齐点

- §5.1 / §5.2 / §5.3：四方法签名与 `INativeBridgeRequest` /
  `INativeCapabilityRegistration` / `INativeBridge` 的 camelCase 字段、
  `handler` 回调、`Promise` 返回一致。
- §8.1 集中导出表：四导出仅在 `abi.rs` 声明，实现在 `bridge.rs`。
- §8.3 线程约束：`bridgeRequest` 异步返回 `JsPromise`，JS 线程只做参数解析与
  信封编码，内核 `Bridge::request` 提交绑定层 tokio 运行时，结果经 `Channel`
  回投 settle；禁止 JS 线程 `block_on`。TS 能力 `handler` 经 `Channel` 回投
  JS 线程、`to_future`（§8.3 规则 7）await Promise。
- §8.4 Root 持有回调：`JsHandler` 持 `Root<JsFunction>`，`Drop` 与 `AbortController`
  释放一律回投 JS 线程，不依赖 `Drop` 时机。
- §8.5 错误映射：Rust → JS 仅 `NATIVE_*` 三码 / 内核 `ChipsError`；JS → Rust
  经 `chips_error_from_js` 反向归一，保留 `<DOMAIN>_<REASON>` 形状，否则落
  `BRIDGE_INTERNAL`。
- ctx `{ signal, deadline }`（§5.3）：`signal` 为 JS 原生 `AbortSignal`，内核
  `CancelToken` 触发时经 Channel 回投 `controller.abort()`；`deadline` 为 Unix
  epoch 毫秒。取消收口返回内核 `BRIDGE_CANCELLED`。
- `bridgeCancelSession` 精确映射 `chips-bridge::cancel_session`（幂等、会话保持可用），
  与 `close_session` 区分，无缺口。

### 依赖登记

`packages/native/Cargo.toml`：`chips-bridge = { path = "../core-rust/crates/chips-bridge" }`、
`async-trait.workspace = true`、`neon = { version = "1", features = ["futures"] }`
