  `bridgeCancelSession`：载体 `chips-bridge` crate 未交付（工单005）。

  资源管理器任务；本包 `export_table!` 只增不改，落地后按同一入口追加。

  属插件管理层。
- 同步引擎原语：不属于 ABI（《核心接口规范》§2.4、§9.2），不得导出。

集成约定：

1. 根 `Cargo.toml` 的 `members` 为 `["packages/core-rust/crates/*", "packages/native"]`；
   本包只落地自身清单，不修改工作区根配置。

3. 子系统 crate 只依赖 `chips-core`；本包组合子系统，禁止反向依赖。

## 三、关键设计决策

| # | 决策 | 依据 |
|---|---|---|
| N1 | 导出函数在 `abi.rs` 用 `export_table!` 集中声明：宏同时生成 `EXPORT_NAMES` 与 `register()`，导出名表不可能与实际注册漂移 | 核心接口规范 §8.1、§8.6 |
| N2 | `abi/export-surface.json` 为导出清单事实源（`exports` + `blocked`）；Rust 单测直接内嵌并比对清单，`check-abi.mjs` 比对清单 ↔ Rust ↔ d.ts 并校验阻塞项引用的工单目录真实存在 | 契约先行；工单不悬空 |
| N3 | `JsBox<T>` 要求 `T: Finalize`，子系统 crate 类型不能实现外部 trait：以透明包装 `NativeContextHandle` / `NativeCancelToken` 承载；对 JS 保持不透明句柄 | 核心接口规范 §8.4；orphan rule |
| N4 | JS 服务值与回调一律 `Root` 持有；释放经 `Channel` 回投 JS 线程（`Drop` 时 `try_send` 掉 `Root`），通道关闭时退回 Neon 的 GC 兜底路径 | 核心接口规范 §8.4、§10.1 规则 3 |
| N5 | 异步导出统一 `cx.promise()` + `Deferred::settle_with(&channel, …)`，工作提交到绑定层专用 tokio 运行时；`Root` 只在创建它的 JS 线程取值 | 核心接口规范 §8.3 |
| N6 | 监听令牌由绑定层分配（`number < 2^53`），`ListenerRegistry` 维护 `number → ListenerToken` 翻译；条目随 `JsListenerSink::Drop`（`once` 触发、Fork 撤销、显式退订）清理；内核令牌不对外暴露 | 核心接口规范 §4.5；内核令牌为内部类型 |
| N7 | 二进制信封输入按 TS 侧已拆分的 `bin` 表读取（`Uint8Array` / `Buffer` 各一次拷贝）；输出提供合并助手；纯结构校验（指针解析、占位为字符串）在本层完成，schema 约束留给 Bridge | Bridge 三层设计 §3.6 |
| N8 | 绑定层错误码 `NATIVE_TYPE_UNSUPPORTED` / `NATIVE_VALUE_OUT_OF_RANGE` / `NATIVE_INTERNAL` 使用中并登记工单006，等待文档收口；非法 UTF-16 归入 `NATIVE_TYPE_UNSUPPORTED`，不新增第四个码 | 核心接口规范 §3.3、§8.5；红线「自造错误码」 |
| N9 | 对象传输白名单：普通对象（原型为 `null` 或 `Object.prototype`）、数组、标量；函数、类实例、`Error`、`BigInt`、`ArrayBuffer` / TypedArray（二进制走信封）拒绝 | 核心接口规范 §8.2、§8.3（传输值禁止清单） |
| N10 | 监听器与回调抛出的 JS 异常在被投递的 JS 线程内吞掉并不改变内核状态（事件 `emit` 的语义是入队成功；注入回调为 `Fn`，无错误通道） | 内核设计 §8.2；核心接口规范 §4.5 |

## 八、W1-COV-NATIVE 覆盖率补测轮（2026-09-20）

> 目标：`chips-native` 行覆盖率（tarpaulin 源码插桩，行数口径）提升至 >90%。
> owner：rust-cov-native。

### 8.1 范围与口径

- 只补真实单测（`src/*.rs` 内联 `#[cfg(test)]`），与既有风格一致；不写空断言、不调阈值/
  门禁、不改 `tools/`、不删改既有断言、不引入兼容性包袱。
- 纯逻辑（convert / envelope / error / cancel / context 的令牌与分类 / abi 清单）优先直接
  单测；Neon 运行时函数（依赖 `Context` / `Channel` / `Deferred` / `Root`）见 8.3 与工单012。

### 8.2 本轮补测项（真实用例）

| 文件 | 新增用例（覆盖的既有可执行分支） |
|---|---|
| `convert.rs` | 负整数 `as_i64` 分支与 `< -2^53` 越界；有限浮点映射；`2^53` 含界保型 / 越界转浮点；`ConvertIssue::ValueOutOfRange` → `into_error` |
| `envelope.rs` | `resolve_pointer` 落入标量后下钻、非数字数组索引、空键段；`unescape_pointer_segment` 空/恒等/结尾裸 `~`/未知转义；`validate_bin_table` 空表与根指针占位 |
| `error.rs` | `error_shape` 含 `details` 分支；`unrecognized_error` 兜底 `BRIDGE_INTERNAL`；`is_normalized_code` 数字段与非法字符（空格/连字符） |
| `context.rs` | `classify_service` 非 `ServiceNotFound` 内核错误透传；`ListenerRegistry::allocate_key` 单调分配；`token_from_js_number` 错误码与 `2^53` 边界 |

### 8.3 无法在 crate 内覆盖的函数（架构缺口，登记工单012）

`chips-native` 主体可执行行是 §8.1 规定的 napi 运行时适配（绑定层不做业务逻辑），需要真实
napi `Env`/V8 isolate。neon 1.1.1 无 mock/测试 `Context`、Rust 侧无 `create_env`、
tarpaulin 源码插桩不归因 Node 子进程，故以下函数在 `cargo test` 口径下不可覆盖：

`abi::register/core_version/core_abi_version`、`cancel::js_*`、`handles::JsServiceValue::*`
与 `JsCallback::*`、`context::js_context_*` 与 `context_argument/string_array_argument/
kernel_error/JsListenerSink::enqueue`、`convert::json_to_js/js_to_json/convert_js_*`、
`envelope::bin_from_js/bin_to_js/json_with_bin_to_js/binary_bytes`、
`error::throw_chips_error/chips_error_from_js`、`runtime::spawn_result/settle_json/
id_to_js_number`。逐文件理由见 `开发日志.md`。

### 8.4 验收

- `cargo test -p chips-native`、`cargo test --workspace` 全绿；
- `cargo clippy -p chips-native --all-targets -- -D warnings`、`cargo fmt -p chips-native -- --check` 通过；
- 覆盖率为纯逻辑可测上限；绑定层运行时函数覆盖待工单012 收口后由生态统一口径复测。
