## 一、目标

`@chips/sdk` 是插件侧唯一的开发期类型与客户端封装入口：

1. 把生态契约（Bridge 协议、内置能力、事件、资源、命令、配置、资源打开、内核上下文、文档模型、渲染视图、角色类型）
   以**类型**形式提供给插件代码，形状权威一律指向文档库，SDK 不复制内容；
2. 提供类型化客户端（`chips` 单例 / `createClient` / `ChipsBridge`），只做目标解析与转发，不承载任何平台逻辑；
3. 提供统一错误模型（`ChipsError` / `isChipsError` / `toChipsError`）；
4. 提供测试工具入口 `@chips/sdk/testing`（Mock Bridge、安装/卸载、错误断言），使插件测试不依赖真实运行时；
5. 承载 `tools/contract-gen` 从文档库生成的契约常量（`src/generated/`），作为 ID 联合类型与常量的单一来源；
6. 声明 `Window.chips` 全局形状，钉死「插件 → SDK → 注入的 Bridge」的依赖方向。

## 四、接口与关键决策

1. **目标解析（§3.2、§11 约束 8）**：`ChipsBridge` 方法面冻结为 `request` / `subscribe` / `resource`，每次调用解析目标——
   构造传入 `target` 时全部转发；未传入时读 `window.chips`；不存在时 `request` 异步拒绝、`subscribe` 与 `resource` 同步抛
   `SDK_BRIDGE_UNAVAILABLE`；构造后注入的 Bridge 在后续调用自动生效（解析发生在每次调用，故 `installMockBridge` 无需重建单例）。
2. **错误口径（§6.4、§11 约束 6）**：平台错误已由 Bridge 归一，客户端原样透传 `code` / `message` / `details` / `retryable`；
   SDK 自身只产生 `SDK_BRIDGE_UNAVAILABLE` 与 `SDK_UNKNOWN_ERROR` 两个码，不复制平台码表。
3. **测试工具边界（§7.1、§7.2）**：Mock 只模拟调用结果，**不做权限判定与 schema 校验**；行为口径固定为——
   同一能力后注册覆盖先注册、未注册能力拒绝 `BRIDGE_CAPABILITY_NOT_FOUND`、`emit` 同步派发且无订阅时丢弃、
   `calls` 按时序只记录 `request`（`resource()` 不经能力通道）、URI 语法非法同步抛 `RESOURCE_INVALID_URI`、
   句柄 `release()` 后拒绝 `RESOURCE_HANDLE_RELEASED`、失效后拒绝 `RESOURCE_HANDLE_INVALIDATED`、
   `subscriptionCount` 返回有效订阅数、`reset` 清空桩/记录/订阅并恢复资源夹具。
   Mock 使用的错误码从 `src/generated/error-codes.ts` 口径取值，由 `codes.test.ts` 门禁核对，不维护第二份清单。
4. **`installMockBridge` 写入面**：只写 `window.chips` 一个成员，不注入、不替换、不扩展 `window` 上其他对象；
   支持嵌套安装，按后进先出恢复前值，未安装时卸载为无操作（§4）。
5. **`assertChipsError`**：只按 `code` 分支，禁止匹配 `message` 文本；失败消息同时给出期望与实际错误码。
6. **依赖方向**：对 `@chips/bridge` 只允许 `import type`（`tools/gates/gates.config.json` 的 `packages/sdk` 规则为
   `allowedInternal: ["@chips/bridge"]` + `typeOnlyInternal: ["@chips/bridge"]`），运行时零内部依赖、零第三方依赖。
7. **生成物消费**：`CapabilityId` 等 ID 联合类型由 `src/generated/` 提供，主入口只导出 `CapabilityId`；
   生成物内部自洽与到导出面的引用路径由 `tests/generated-contracts.test.ts` 判定，文档库权威表逐项比对由
   `@chips/contract-gen` 的 `test:contract`（`cli.js check`）与 `pnpm gates:contracts` 负责。
   契约测试归位（W1 收口裁决，2026-09-21）：SDK 契约判定的 G8 唯一执行面为工作区包
   `@chips/contract-tests`（`tests/contract/`，导出面快照与能力/权限/事件/错误码表对照），包内不维护第二套
   契约用例或快照（原悬空 `vitest.contract.config.ts` 已移入 `归档/`）；本包 `test:contract` 脚本委托
   `pnpm --filter @chips/contract-tests run test:contract`。
8. **版本口径**：`PLATFORM_VERSION` 与全部 `@chips/*` 包及 Rust crate 同值（当前 `0.1.0`），由 `src/version.test.ts`
   与 `package.json` 的 `version` 核对，禁止版本漂移（§10.1、《01-代码组织规范》§3.4）。

## 五、依赖与选型

- 运行时依赖：`@chips/bridge`（`workspace:*`，仅类型）；无第三方运行期依赖，不引入组件库、Electron、Node API。
- 开发依赖：`rimraf`（`clean`）；`typescript` / `vitest` / `eslint` / `typescript-eslint` 由仓库根统一精确锁定。
- 测试环境为 `node`，不引入 jsdom：客户端目标解析只读 `window.chips`，由 `tests/helpers/window.ts` 提供可写的最小
  `window` 宿主并在 `afterEach` 还原，避免用例间污染。
