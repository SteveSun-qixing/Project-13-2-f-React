## 截至 2026-09-20 现状核验：关键口径落位（头注即口径）

以下口径直接钉在各模块头注中，本波次逐条与规范核对一致，记录以免规范与代码脱节：

1. **目标解析四态**（`src/client/chips-bridge.ts` ↔ §3.2、§11 约束 8）：构造传入 `target` 时全部转发；
   未传入且 `window.chips` 已注入时转发；未传入且不存在时 `request` 异步拒绝、`subscribe` 与 `resource` 同步抛
   `SDK_BRIDGE_UNAVAILABLE`；构造后才注入的 Bridge 在后续调用自动生效（解析发生在每次调用）。
   该规则是 `installMockBridge` 无需重建 `chips` 单例的前提。
2. **错误透传**（§6.4、§11 约束 6）：客户端不改写平台错误的 `code` / `message` / `details` / `retryable`；
   SDK 自身只产生 `SDK_BRIDGE_UNAVAILABLE` 与 `SDK_UNKNOWN_ERROR` 两码，包内不维护平台码表。
3. **Mock 行为表**（`src/testing/mock-bridge.ts` ↔ §7.1、§7.2）：Mock 只模拟调用结果，不做权限判定与 schema 校验；
   同一能力后注册覆盖先注册、未注册能力拒绝 `BRIDGE_CAPABILITY_NOT_FOUND`、`emit` 同步派发且无订阅时丢弃、
   `calls` 只按时序记录 `request`（`resource()` 不经能力通道故不记录）、URI 语法非法同步抛 `RESOURCE_INVALID_URI`、
   句柄 `release()` 后 `RESOURCE_HANDLE_RELEASED`、失效后 `RESOURCE_HANDLE_INVALIDATED`、
   `subscriptionCount` 返回有效订阅数、`reset` 清空桩/记录/订阅并恢复资源夹具。
4. **`installMockBridge` 写入面**（§4）：只写 `window.chips` 一个成员，不注入/替换/扩展 `window` 上其他对象；
   嵌套安装按后进先出恢复前值，未安装时卸载为无操作。
5. **`assertChipsError`**（§7.2、§11 约束 6）：只按 `code` 分支，禁止匹配 `message` 文本，失败消息同时给出期望与实际码。
6. **`codes.ts` 不双源**（§11 约束 5）：`MOCK_ERROR_CODES` 六个码的取值与 `src/generated/error-codes.ts` 的一致性由
   `src/testing/codes.test.ts` 门禁核对，本模块不维护第二份清单。
7. **测试环境不引 jsdom**（`tests/helpers/window.ts` 头注）：运行时目标解析只读 `window.chips`，
   夹具提供可写最小 `window` 并在 `afterEach` 还原为「无 window」原判据，避免用例间污染。
8. **版本口径**（`src/version.ts` ↔ §10.1、《01-代码组织规范》§3.4）：`PLATFORM_VERSION = '0.1.0'`
   与 `package.json` 的 `version` 由 `src/version.test.ts` 强制核对，禁止版本漂移。
