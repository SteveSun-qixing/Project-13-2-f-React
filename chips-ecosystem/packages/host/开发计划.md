## 一、范围

本包是薯片生态桌面壳（Shell）的唯一实现，对应[《跨端 Shell 与平台抽象设计》](../../../薯片生态文档库/01-架构设计/01-子系统设计/17-跨端Shell与平台抽象设计.md)中的"桌面壳"形态与[ADR-002](../../../薯片生态文档库/01-架构设计/ADR/ADR-002-Electron作为桌面端壳.md)。

### 1.1 本任务交付

### 1.2 明确不在本任务范围

- 平台核心（Cordis 内核、Bridge 内核、解析器、资源管理器）：属 `packages/core-rust`、`packages/native`、`packages/bridge`。
- Host 侧其余 PAL 分面（dialog / notification / clipboard / menu / tray / shortcut / power / transfer / shellOpen / http）：后续任务实现；本包按真实实现生成能力矩阵（缺失分面 `false`，不注册、不伪造成功）。
- 打包、签名与平台自更新器（Phase 4）。

### 1.3 边界与依赖

- 依赖方向：`packages/host` → `@chips/bridge`、`@chips/ui`、`core-rust` 绑定、`electron`（[01-代码组织规范 §4.2](../../../薯片生态文档库/02-开发规范/01.04-01-代码组织规范-四、依赖方向与循环依赖禁令.md)）。
- 平台核心尚未装配时，本包通过**平台运行时端口**（`src/platform/contracts.ts`）反向依赖注入：壳不实现第二个能力注册表、第二套权限判定；核心装配由组合根（`src/main/runtime-provider.ts`）提供。
- PAL 类型属平台内部类型：不经 `@chips/sdk` 导出、不出现在 `window.chips`（17 §4.1、SL-5）。

## 二、接口与契约

### 2.1 壳 → 核心：`IPlatformRuntime`（平台运行时端口）

```typescript
interface IPlatformRuntime {
  start(host: IPalHost): Promise<void>; // 内核 → 解析器/资源 → Bridge 内置能力注册
  restorePlugins(): Promise<void>; // 按启用偏好恢复插件（拓扑序）
  stopPlugins(): Promise<void>; // 停用插件、Fork 撤销；app 插件关闭窗口
  shutdown(): Promise<void>; // Bridge 关闭、能力注销、核心停机
  readonly ipc: IPlatformIpcEndpoint; // 会话解析后的 IPC 端点（宿主适配层调用）
  forwardEvents(sink: IEventSink): () => void; // 事件下行转发注册；返回注销函数
}
```

规则：壳只经该端口把"已按来源解析的会话 + 已编解码的消息"交给核心；会话有效性、权限、schema、路由与错误归一全部在核心（Bridge 层），壳不重复实现（17 §3.2、SB-1/2/6）。

### 2.2 核心 → 壳：`IPalHost`（PAL 端口）

```typescript
interface IPalHost {
  readonly info: IShellInfo;
  readonly matrix: IPalCapabilityMatrix;
  readonly ports: IPalPorts; // 本任务实现 window 分面；其余分面按真实实现为空
}
```

壳自检：`matrix` 中声明的可用分面必须有对应端口实现，缺端口/多余端口/声明不一致终止启动（17 §2.4）。

### 2.3 IPC 通道（固定，不得自定义或拼接）

| 通道                  | 方向      | 负载                                                   |
| --------------------- | --------- | ------------------------------------------------------ |
| `bridge:request`      | 渲染 → 主 | `IBridgeRequest` → `IBridgeResponse`                   |
| `bridge:resource`     | 渲染 → 主 | `IResourceControlRequest` → `IResourceControlResponse` |
| `event:control`       | 渲染 → 主 | `IEventControlRequest` → `IEventControlResponse`       |
| `event:<eventId>`     | 主 → 渲染 | `IEventEnvelope`                                       |
| `session:permissions` | 主 → 渲染 | `ISessionPermissionsUpdate`                            |

### 2.4 资源协议处理器契约

- 特权注册：`standard: true`、`secure: true`、`supportFetchAPI: true`、`corsEnabled: true`、`stream: true`、`codeCache: true`。
- 方法：`GET`/`HEAD` 放行；`OPTIONS` → 204 + CORS；其余 → 405。
- 基于 `request.url` 原始字符串重新执行语法解析与路径分段校验（不信任 URL 解析器的路径折叠结果）。
- 错误码 → HTTP：400（`RESOURCE_INVALID_URI` / `RESOURCE_PATH_INVALID`）、404（`RESOURCE_NOT_FOUND`）、403（`RESOURCE_PERMISSION_DENIED`）、413（`RESOURCE_TOO_LARGE`）、409、501、502、500（兜底 `RESOURCE_INTERNAL`）；响应体为简体中文纯文本，不含真实路径与堆栈。
- 响应头：`X-Content-Type-Options: nosniff`、`Cache-Control: no-store`（或核心给出的严格缓存策略）、模块脚本/字体/媒体附加 `Access-Control-Allow-Origin: *`。

### 2.5 会话解析

- IPC 路径：`event.sender`（`webContents.id` → `windowId`）+ `event.senderFrame.routingId`（`frameId`）解析来源会话；解析失败返回 `BRIDGE_SESSION_UNKNOWN`。
- 协议路径：Electron `protocol.handle` 不提供来源帧；壳为每个窗口分配独立 session partition，按 partition → 窗口 → 会话解析（详见开发日志"平台约束"节）。
- 权威判定在核心；壳只做来源解析与转发。
