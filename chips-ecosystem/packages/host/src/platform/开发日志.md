## 2026-09-20 W1 修复波次 FIX-HOST：包级 10 个失败用例根因与证据

范围：`src/main/**`、`src/protocol/**`、`src/runtime/**` 实现修复 + 4 处测试替身机制修正；
未删除用例、未放宽任何断言。基线 10 失败/411 通过 → 现状 421 通过/0 失败。

实现侧根因：

1. `createElectronRuntime` 形状诊断按声明顺序报告首个不可调用方法，替身对象经 `{ ...fake.app }`
   展开后丢失原型方法，导致把完全缺失的 `whenReady` 报成缺失项，掩盖被真实破坏的 `getVersion`。
   修复为分桶诊断：显式存在但不可调用优先命名，完全缺失按清单汇总。
2. `startHostMain` 只把 `application.start()` 纳入启动 try/catch，`createPalHost` /
   `createRuntime` / `HostApplication` 构造在保护外抛出，未触发 `app.exit(1)`。
   依据 17 号文档 §2.4 步骤 1–3：构造 `IPalHost`、壳自检、启动核心同属启动阶段，
   任一环节失败即“终止启动”，故整段并入同一失败收口（退出码 1 + 上抛 `HostStartupError`）。
3. `resource-uri` 段校验把 `^[A-Za-z]:` 一律判为 `absolute`，使 ADS 形态 `a:b` 误报；
   改为仅独立成段的盘符（`C:/x.png` 的 `C:`）判 `absolute`，段内其余 `:` 归 `platform`
   （06-资源协议规范 §2.4 相对性行先于平台特例行；04-资源管理设计 §9.3“拒绝含 `:` 的文件名”）。
4. `normalizePath` 静默 `normalize('NFC')`，使 `unicode` 原因永不可达，且把非规范输入伪装成合法路径；
   改为解码一次后若 `decoded.normalize('NFC') !== decoded` 直接拒绝（§2.4 Unicode 行、
   04-资源管理设计 §9.4 要求覆盖“Unicode 规范化差异”）。
5. `self-check-runtime` 范围读取把越界起点裁剪到末字节，越界 `Range` 误返回 206；
   改为起点 `>= size`（或尺寸为 0、起点为负）即不可满足范围 → 416 + `Content-Range: bytes */size`
   （06-资源协议规范 §5.3“非法范围返回 416”、RFC 9110 §14.1.7）。
6. `toCanonicalResourceUri` 对 External 追加 `?query`，与“规范 URI 定位器”口径冲突；
   改为不含查询串（§2.5 查询不参与作用域归属判定），§2.6 归一结果的 query 仍由
   `ResourceUriParseSuccess.uri` 与 `parsed.query` 完整保留；§9.4 要求审计中 query 脱敏。

测试替身机制修正（断言原样保留，均为替身无法满足被测契约）：

7. `tests/preload-entry.test.ts`：写死回包 `requestId: 'r1'`，而 preload 按 §7.2 生成随机关联键并
   校验响应回填（`tests/preload-bridge.test.ts` 要求不匹配即拒绝），改为按 `payload.requestId` 回显。
8. `tests/preload-resource-handle.test.ts`：门控 `fetchImpl.mockImplementation` 泄漏到流结束后的
   `readRange`，第二个门控 Promise 无人释放导致 `arrayBuffer()` 挂死超时，改为 `mockImplementationOnce`。
9. 同文件“取消流后释放互斥标记”期望 `readRange(0, 1)` 返回全 4 字节，与 Bridge API 规范 §3
   `readRange(offset, length)`（长度参数）及同文件通过用例矛盾，改为期望 `[1]`。
10. `tests/resource-protocol.test.ts`：`new Request('…/%2e%2e/secret.txt')` 在构造期被 WHATWG
    折叠为合法路径（实测 `request.url` 已丢失 `..` 段），处理器按 §5.3 只能基于 `request.url`
    重新解析，故改用编码分隔符形态 `a%2F%2e%2e%2Fsecret.txt`（实测不被折叠，解码一次后为穿越）。
