## 一、目标

在 `@chips/host` 内交付**桌面壳（macOS）平台抽象层**的完整实现：

1. **端口契约**：按《17-跨端 Shell 与平台抽象设计》§4.2 定义 `IShellInfo` / `IPalCapabilityMatrix` / `IPalPorts` / `IPalHost`，端口方法与非插件可见的能力动作一一对应；PAL 类型不出现在 `@chips/sdk` 与 `window.chips`。
2. **macOS 实现**：窗口、文件、对话框、通知、剪贴板、菜单、托盘、快捷键、电源、系统信息、传输、外部打开、HTTP 共计 13 个端口的 Electron API 封装；平台差异只存在于本目录。
3. **能力可用性声明与降级**：端口实现存在性与能力矩阵严格一致（壳自检，缺端口 / 多端口 / 声明不一致终止启动）；环境级不可用（通知不支持、剪贴板缺失、电源读取失败等）返回已登记域错误码，不空实现、不伪造成功。
4. **可注入 Electron**：PAL 只依赖本包定义的 Electron 结构契约 `IElectronApi`；真实 Electron 模块由壳入口注入，测试注入 `tests/helpers/electron-mock.ts`（**mock 仅存在于测试**）。
5. **单元测试**：端口行为、错误码映射、降级语义、shell 自检、目录变量解析、网络重定向逐跳授权与传输原子替换全覆盖；覆盖率门禁 ≥ 90%（核心/共享层基线，见《02-开发规范/05-测试规范》）。

## 四、关键设计决策

1. **窗口 ID 语义**：能力契约 §7.4 与事件契约 §4.7 规定 `windowId` 为 Electron `webContents.id`（number）；17 号文档 §4.2 端口示例的 `string` 为示例笔误，实现与测试以能力/事件契约为准（已登记工单 003）。
2. **错误模型**：端口抛出 `PalPortError`（`code` / `message` / `details` / `retryable`），与 `ChipsError` 同构；未识别异常一律归一为 `BRIDGE_INTERNAL`（SB-7）。启动期自检失败抛壳内部 `PalBootstrapError`，不经 Bridge。传输失败回调 `TransferFailure` 同样携带 `retryable`，供壳构造 `transfer:failed` 事件载荷中的 `ChipsError`（事件契约 §4.10）。
3. **降级分层**（17 号文档 §5.1）：
   - 端口缺失（Electron API 不存在）→ 矩阵 false → 该能力域整体不注册；
   - 端口存在但环境不可用（`Notification.isSupported()===false`、`pmset` 读取失败、剪贴板调用抛错）→ 能力注册，运行时返回 `NOTIFICATION_UNAVAILABLE` / `POWER_INFO_UNAVAILABLE` / `CLIPBOARD_UNAVAILABLE` 等域错误码；
   - 系统限制（快捷键被占用、托盘图标不可解码）→ `SHORTCUT_CONFLICT` / `TRAY_ICON_INVALID` 等。
4. **平台标识双值**：PAL 内部 `PlatformId` 按 17 号文档 §4.2 取 `macos`；`system:info.platform` 按能力契约 §7.14 输出 `darwin`（Electron/Node 口径）。17 号文档 §4.4 明确插件可见值以能力契约 §7.14 为准，由系统端口的 `resolveSystemInfoPlatform` 完成映射，不构成文档冲突。
5. **目录变量**：壳解析 `${userHome}` 等 9 个变量；存储端口只接收已解析的绝对路径，不感知变量语义。
6. **网络**：端口内不静默跟随重定向；每跳调用 `authorizeRedirect`（由能力层接权限判定），最多 5 跳；超时按资源管理设计 §8.2（连接 10s / 首字节与空闲 30s）；重定向跨源剥离 `Authorization`。
7. **传输**：临时文件 + `sha256` 校验 + 原子替换；失败/取消清理临时物、目标路径不被修改；进度回调最小间隔 200ms（事件契约 §4.10）。
8. **无业务逻辑**：端口不做权限判定、不做 schema 校验、不发布业务事件；OS 信号（窗口关闭/聚焦、托盘点击、快捷键触发）通过订阅接口交给壳转发事件总线。
9. **安全基线**：窗口创建固定 `nodeIntegration:false`、`contextIsolation:true`、`sandbox:true`、`webSecurity:true`，壳提供的窗口选项不能覆盖关闭；`shell:openExternal` 仅放行 `http/https/mailto`。
10. **注入与测试**：`createMacPalHost(electronModule, options)` 接受原始模块并做形状校验；测试注入 mock，生产由 `loadElectronModule()` 提供真实模块。mock 不进入 `src/`。
11. **删除语义**：`file:delete` 对目录按契约分为两档——空目录直接删除（`rmdir` 语义），非空目录且未请求 `recursive` 返回 `FILE_NOT_EMPTY`；不使用会拒绝一切目录的 `fs.rm(recursive:false)`。
12. **覆盖率门禁范围**：`vitest.config.ts` 的覆盖率统计范围收口为 `src/platform/**`，阈值 90%（PAL 为壳内部共享基础设施，按 90% 基线执行）；`main` / `protocol` / `runtime` 由所属任务补齐测试后扩展 include，避免并行任务未交付测试的目录拉低本层门禁。

## 七、风险与对策

| 风险                                       | 对策                                                                                             |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| Electron 版本 API 漂移                     | 只使用 ADR-002 现状注记与 Electron 40 类型中稳定存在的 API；结构契约集中在一个文件，便于后续跟随 |
| 网络端口测试不可依赖外网                   | 全部经注入的 `IElectronNetApi` mock 驱动，断言请求构造与状态机，不发生真实网络                   |
| `pmset` 输出格式差异                       | 解析器宽松匹配并保留 `batteryLevel:null` 的合法降级；失败不伪造数据                              |
| 与并行任务（Bridge/Host 能力实现）接口冲突 | 端口契约以文档库为唯一来源并对每个方法附权威引用；改动端口契约需更新本计划与日志                 |
