## 2026-09-20 W1 修复波次 FIX-HOST：包级 10 个失败收口（10 失败/411 通过 → 421/421）

范围：`src/main/**`、`src/protocol/**`、`src/runtime/**` 的 6 处实现修复 + 3 个测试文件内的 4 处替身机制修正；
未删除用例、未放宽任何断言。逐条根因与文档依据的完整版本见 `src/platform/开发日志.md` 的「2026-09-20 W1 修复波次 FIX-HOST」一节，此处为包级汇总。

实现侧根因与修复：

1. `src/main/electron-adapter.ts`：`createElectronRuntime` 的形状诊断按声明顺序报告首个不可调用方法，替身经 `{ ...fake.app }` 展开后
   丢失原型方法，导致把完全缺失的 `whenReady` 报成缺失项、掩盖真实被破坏的 `getVersion`。改为分桶诊断：显式存在但不可调用优先命名，
   完全缺失按清单汇总。
2. `src/main/main.ts`：`startHostMain` 只把 `application.start()` 纳入启动 try/catch，`createPalHost` / `createRuntime` / `HostApplication`
   构造在保护外抛出不触发 `app.exit(1)`。依据《17》§2.4 步骤 1–3（构造 `IPalHost`、壳自检、启动核心同属启动阶段，任一失败即终止启动），
   整段并入同一失败收口（退出码 1 + 上抛 `HostStartupError`）。
3. `src/protocol/resource-uri.ts`：段校验把 `^[A-Za-z]:` 一律判为 `absolute`，使 ADS 形态 `a:b` 误报。改为仅独立成段的盘符判 `absolute`，
   段内其余 `:` 归 `platform`（《06-资源协议规范》§2.4 相对性行先于平台特例行；《04-资源管理设计》§9.3「拒绝含 `:` 的文件名」）。
4. `src/protocol/resource-uri.ts`：`normalizePath` 静默 `normalize('NFC')` 使 `unicode` 拒绝原因永不可达。改为解码一次后
   `decoded.normalize('NFC') !== decoded` 即拒绝（§2.4 Unicode 行、§9.4 要求覆盖 Unicode 规范化差异）。
5. `src/protocol/resource-uri.ts`：`toCanonicalResourceUri` 对 External 作用域追加 `?query`，与「规范 URI 定位器」口径冲突。
   改为规范 URI 不含查询串（§2.5 查询不参与作用域归属判定），解析结果的 `query` 仍完整保留（§9.4 要求审计中 query 脱敏）。
6. `src/runtime/self-check-runtime.ts`：范围读取把越界起点裁剪到末字节，使越界 `Range` 误返回 206。改为起点 `>= size`
   （或尺寸为 0、起点为负）即不可满足范围 → 416 + `Content-Range: bytes */size`（《06-资源协议规范》§5.3、RFC 9110 §14.1.7）。

测试替身机制修正（断言原样保留，均为替身无法满足被测契约）：
