## 二、接口与依赖

### 2.1 公开面（`src/index.ts`）

- `runCli(argv, deps)` / `runDevCli(argv, deps)`：程序化入口，`deps.client: CliClient` 可注入（测试与平台嵌入的唯一接缝）；
- `main(argv, options?)` / `bin`：可执行入口；
- `createServiceRouterClient({ invoker })`：`cli-command` / `cli-task` 对接层（`invoker` 为 `IChipsBridge` 的结构子集，生产由 `@chips/sdk` `createClient({ bridge })` 提供）；
- 错误模型（`ChipsError`）、退出码、命令定义查询（`listCliCommands`）、补全/帮助消费的声明模型。

### 2.2 依赖方向

- 运行期依赖：`@chips/bridge`（协议类型与错误模型的目标来源）、`@chips/sdk`（客户端与脚手架）；本包以**端口 + 运行时校验**隔离二者尚未落地的实现，不复制其定义（见 `开发日志.md`"跨包接缝"）。
- 第三方依赖：`yaml`（唯一新增，YAML 1.2 解析；清单规范要求，许可证 MIT、维护活跃、零传递风险，根工作区已锁定 `2.8.2`）。
- 禁止：`@chips/ui` / `antd`（非前端包）、`electron`、宿主实现包 `@chips/host`（反向依赖）。

### 2.3 目录结构

```text

├── src/
│   ├── index.ts             # 公开出口

│   ├── plugin-cli/          # 插件命令索引、匹配与消解、payload、执行与任务
│   ├── artifacts/           # ZIP Store、semver、清单校验、cpk 打包/校验、脚手架落盘
```

## 三、关键决策

1. **端口隔离**：平台访问全部经 `CliClient` / `CliInvoker` 端口，命令实现零平台直连；`createServiceRouterClient` 是唯一把端口映射到 `cli.command.*` / `cli.task.*` / `command:invoke` 的位置（单一事实源）。
2. **参数模型单一解析器**：内建命令与插件命令共用同一参数声明与解析引擎，避免两套解析逻辑。
3. **无兼容层**：不保留旧命令名、不提供别名；旧名按 `CLI_COMMAND_NOT_FOUND`（退出码 3）处理。
4. **本地引擎归属**：`plugin pack` / `plugin validate` 的五阶段实现属 CLI（《插件包格式》§7.1）；清单校验所需的权限/卡片类型登记表通过目录端口注入，内置目录取自《插件清单规范》§6.2（该表即 manifest 申请侧视图的权威副本，不在本包另写第二份数值）。
5. **承载链路缺失的确定性行为**：无承载环境时返回 `CLI_TARGET_UNAVAILABLE`（退出码 6），不虚构协议、不静默降级。

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| `@chips/bridge` / `@chips/sdk` 尚未交付 | 端口 + 运行时校验隔离；命令级测试全部注入假 Client；跨包接缝写入开发日志并在工单登记承载链路缺口 |
| CLI ↔ 平台承载协议未定义 | 本任务不实现传输；`--json`、退出码、错误对象保证脚本可编程；工单 003 |
| 打包引擎体量大 | 分层实现 + 逐阶段单测；确定性打包用两次打包字节比对断言 |
| TUI 终端差异 | `ITerminal` 端口 + 纯函数渲染；Node 实现只做 ANSI 与 raw mode 包装 |
