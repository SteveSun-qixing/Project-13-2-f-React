## 一、范围与边界

### 1.1 本次交付

| crate | 内容 |
|---|---|
| `chips-core` | 标识别名（`PluginId` / `ServiceName` / `EventName` / `ServiceValue` / `ContextId` / `ForkId` / `InjectionId` / `SessionId` / `HandleId`）、`CancelToken`、`ChipsError`、语义化 `Version` / `VersionRange`、`PLATFORM_VERSION` / `CORE_ABI_VERSION` |
| `chips-cordis` | Context 树、Fork 可逆副作用、`ServiceRegistry`（暂存代际 / 原子发布 / 级联重建 / 反向索引）、`PluginManager`（状态机 / 依赖解析 / 拓扑序 / 环检测 / 加载与卸载事务）、`EventBus`（同步广播 + 入队语义）、命令循环（单写者）、任务与取消、生命周期超时与配额常量、`KernelError` |

### 1.2 不在本次范围

- `chips-native`（Neon 绑定，W1-Neon）：`PluginRunner` / `EventSink` / `ConfigProvider` 是内核为适配层预留的正式接口，由绑定层实现。
- `chips-bridge` / `chips-parser` / `chips-resource` / `chips-sync`（其他子智能体）。
- 插件发现、`.cpk` 解包、权限授予、配置系统：内核只接收已校验的 `LoadRequest` 与 `PluginConfig` 快照。

```
packages/core-rust/

    ├── chips-core/                 # 公共类型与错误模型
```

- `packages/core-rust/crates/` 目录结构对齐《核心接口规范》§2.1 与术语表（核心 = `packages/core-rust/crates/` 下的 crate 集合）。
- 根 `chips-ecosystem/Cargo.toml` 的 `members` 需从 `["packages/core-rust", "packages/native"]` 调整为 `["packages/core-rust/crates/*", "packages/native"]`：`packages/core-rust` 不是单一包，而是子 crate 目录入口。

## 三、关键设计决策

| # | 决策 | 依据 |
|---|---|---|
| D1 | 状态寄存器由 `Mutex<KernelState>` 串行写入；服务表、监听表、Context 树以 `RwLock<Arc<快照>>` 发布只读快照 | 内核设计 §2.2、§7.1、§10.2 |
| D2 | 生命周期命令（load / enable / disable / unload）经 mpsc 命令循环串行执行；`apply` / `stop` 在循环外以任务执行并带超时，循环在等待期间继续处理其他命令 | 内核设计 §6.3 规则 3、§10.2、§10.4 |
| D3 | 同步登记入口（`provide` / `inject` / `on` / `once` / `emit` / `effect` / `task`）由调用线程执行，仅短时持有状态锁；调用插件回调前必须释放状态锁 | 内核设计 K-4、§10.3 |
| D4 | 暂存代际按 Fork 保存为有序表；插件进入 `Active` 时一次原子发布并触发级联重建；apply 失败随 Fork 丢弃 | 内核设计 §5.2、§6.3 |
| D5 | 反向依赖索引键为 `(提供方 Fork, 代际, 服务名)`；注入绑定时记录「声明依赖 + 回调内实际查询」两类条目 | 内核设计 §5.4、§7.1 |
| D6 | 重建按插件依赖拓扑序执行，深度计数上限 16，超限中止本轮并报 `KERNEL_REBUILD_OVERFLOW` | 内核设计 §5.4、§7.5 |
| D7 | `EventBus` 监听器分 Rust（发布线程同步调用）与 Queued（`EventSink::enqueue`，入队即成功）两类；JS 适配层实现 `EventSink` | 内核设计 §8.3；事件系统设计 §2.4 |
| D8 | 任务（`ctx.task`）由 tokio 任务承载，协作式取消经 `TaskSignal`；Fork 撤销时触发取消并等待至多 `FORK_FORCE_DISPOSE_TIMEOUT` | 内核设计 §4.2、§6.7、§10.4 |
| D9 | 版本范围语义在 `chips-core` 实现（`Version` / `VersionRange`），内核只消费；解析失败映射为 `KERNEL_DEPENDENCY_VERSION` | 版本与迁移规范 §3、§4；内核设计 §7.4 |
| D10 | 依赖解析区分「暂不满足（有候选版本）→ `Pending`」与「互斥（候选集合无交集）→ `Failed`」；已登记的可用版本列表作为候选来源 | 内核设计 §7.4、插件架构设计 §7.2 |
| D11 | `KernelError` 新增 `InvalidName { kind, name }`（`KERNEL_INVALID_NAME`）：内核设计 §9.1 的错误枚举未覆盖服务名 / 事件名校验失败，而《核心接口规范》§4.4 要求名称非法必须抛错；已登记工单待文档收口 | 核心接口规范 §4.4；内核设计 §5.1、§8.1 |
| D12 | 插件角色（`PluginRole`）仅作为 `plugin:loaded` 载荷字段随 `LoadRequest` 传入，内核不按角色分支 | ADR-005；内核设计 §6.3 |
| D13 | 配置以 `ConfigProvider` 接口注入（默认空快照）；`apply` 前取一次只读快照 | 核心接口规范 §4.6；配置系统设计 §3、§11.3 |
| D14 | 名称与事件域校验（服务名文法、事件名文法、保留域、插件自有域）在发布 / 注册入口执行，与事件系统设计 §5.1、§5.2 一致 | 内核设计 §8.1；事件系统设计 §2.2、§5 |

## 四、公共接口面（对齐《核心接口规范》）

- `Context`：`provide` / `inject` / `get` / `get_typed` / `on` / `once` / `emit` / `effect` / `task` / `id` / `create_child` / `dispose`。
- `Kernel`：`new` / `with_options` / `root_context` / `get_service` / `get_typed` / `load` / `enable` / `disable` / `unload` / `plugin_state` / `shutdown` 等。
- `Fork`：`dispose` 语义（子 Fork 后序 + 自身副作用 LIFO、幂等、容错、代际安全）。
- `PluginRunner` / `EventSink` / `ConfigProvider`：适配层与配置系统的正式实现接口。
- 公开项全部带文档注释；生产代码零 `unwrap()` / `panic!` / 未标注 `unsafe`（本包 `#![forbid(unsafe_code)]`）。

## 七、风险

1. 内核设计 §9.1 错误枚举与《核心接口规范》的名称校验要求不一致（D11，已登记工单）。
2. 级联重建与插件失败回滚存在相互递归：以重建深度上限 + 错误隔离收敛，测试覆盖深度超限路径。
3. 生命周期超时默认值（30s / 10s / 30s）不便测试：`KernelOptions` 允许宿主覆盖，默认值即文档常量。
