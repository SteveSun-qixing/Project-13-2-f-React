# @chips/bridge 开发计划（W1-BRIDGE）

> 目标：在 `packages/bridge/` 实现 Bridge 三层（TS 侧）：会话解析、能力注册表与校验、权限判定与快照、
> JSON Schema 校验（Draft 2020-12 子集）、路由与调用上下文（`signal` / `deadline`）、事件通道、
> 错误归一（`ChipsError`）、IPC 消息编解码（`{ json, bin }`），并交付单元测试与契约测试骨架。

本包职责（与代码组织规范一致）：Bridge 协议类型 + TS 侧桥接实现；不实现 Host 能力（文件/窗口/资源等实现属 `@chips/host`），
不承载插件开发类型（属 `@chips/sdk`），不依赖 `@chips/ui`、`@chips/sdk`、`@chips/host`、`electron`、Node/Electron API。

## 二、目录与公开面

```
packages/bridge/
├── src/
│   ├── protocol/   # 协议类型与契约常量（IChipsBridge / ICapability / ChipsError / IPC 消息 / 权限词表 / 能力登记表 / 事件登记表 / 资源 URI）

│   ├── client/     # preload 与渲染进程共用壳：window.chips 等价封装、订阅、资源句柄代理、快速失败预检
│   └── index.ts    # 唯一公开入口

└── package.json / tsconfig*.json / vitest.config.ts / eslint.config.mjs
```

## 三、接口与实现要点

1. **协议层（`protocol/`）**
   - `IChipsBridge` / `ISubscription` / `IResourceHandle` / `ICapability` / `ICapabilityContext` / `JSONSchema`；
   - `ChipsError`（唯一错误类，`toPlain()` / `fromPlain()`），Bridge 通道错误码表（11 项，含 `retryable` 与简体中文文案）；
   - IPC 通道常量与消息类型（`IBridgeRequest` / `IBridgeResponse` / 资源控制 / 事件控制 / 会话权限下行）与编解码、结构化克隆约束校验、事件载荷体积约束（256 KiB）；
   - 权限词表（26 项基础权限 + qualifier 文法元数据）、R19 能力→权限登记表（60 项内置能力，含限定值匹配目标字段）、标准事件登记表（39 项，含可见性）。
2. **Schema（`schema/`）**：白名单关键字、`$defs` 内联 `$ref`、禁止关键字在编译期拒绝（`BRIDGE_INVALID_SCHEMA`）；
   调用期校验返回 `IValidationIssue[]`（按 pointer 字典序、最多 16 条、`truncated`）；`integer` 严格、`number` 拒绝 `NaN/Infinity`；
   `format` 白名单（`date-time` / `uri` / `chips-resource-uri` / `chips-credential`）；`x-chips-binary` 只允许声明在 `properties`；
   编译缓存以内容 SHA-256 为键、上限 256、LRU 淘汰。
3. **核心（`core/`）**
   - 会话注册表：`(windowId, frameId) → session` 解析、权限快照（`ReadonlySet` + 版本号）、已打开文档、关闭清理（中止在途信号）；
   - 能力注册表：ID 文法、契约登记与 owner 绑定、R3 冲突、schema 编译、权限词表与 manifest 声明校验、幂等重复注册、注销幂等与 owner 记忆；
   - 权限判定：按能力声明顺序短路；限定值匹配分派（路径变量前缀 / 域名通配 / URL / 窗口模式 / 资源作用域 / 配置命名空间）；
     免权限范围（插件数据目录、自身配置命名空间、自身资源作用域、平台作用域只读、会话内已打开文档读取、自身窗口）；
     拒绝详情 `IPermissionDeniedDetails`；
   - 路由：会话解析 → 注册表 → 权限 → 信封拆分 → Schema 校验 → 并发闸门 → 上下文（`AbortController` + `deadline`）→ 执行 → 错误归一；
     `BRIDGE_TIMEOUT` / `BRIDGE_CANCELLED` / `BRIDGE_SESSION_BUSY` / `BRIDGE_QUEUE_OVERFLOW` 全覆盖，迟到结果按 `requestId` 丢弃；
   - 事件通道：`event:control` 订阅/退订回执（`EVENT_ID_INVALID` / `EVENT_NOT_REGISTERED` / `EVENT_SUBSCRIBE_DENIED`）、
     按窗口计数投递、`event:<eventId>` 信封、会话关闭清理；定向事件可见性由登记表 + 宿主解析器判定（fail-closed）；
   - 信封：按 `x-chips-binary` 描述符拆分 `{ json, bin }`、校验键集合与字节上限、执行前按键合并回 `Uint8Array`。
4. **客户端（`client/`）**：通过注入 `IIpcTransport`（`invoke` / `on`）实现 `IChipsBridge`；`requestId` 关联与迟到丢弃、订阅本地计数 + 回执前缓冲
   （缓冲并入主进程下行同一上限 1024 条，确认失败丢弃且订阅不建立）、`handler` 异常隔离、`dispose()` 幂等；
   会话权限快照预检（非安全边界，仅语法与基础权限/限定值明显越权时同步抛错）、资源句柄代理（懒打开、`open→invalidated→released`
   状态机、8 MiB 上限、`release()` 幂等、`onInvalidate` 即时回调语义）；字节读取经注入的 `IResourceByteSource`（preload 由
   `chips-resource://` 协议路径提供，属 Host 侧职责，本包不实现资源读取）。

## 四、测试与验收

- 单元测试与被测文件同目录（`*.test.ts`），包级集成测试在 `tests/`；
- 契约测试归位（W1 收口裁决，2026-09-21）：Bridge 契约判定（R19 能力总表 60 项、权限映射、标准事件、Bridge 错误码
  逐项对照 `薯片生态文档库/` 权威表）由工作区包 `@chips/contract-tests`（`tests/contract/`）作为 G8 唯一判定面承担，
  包内不再维护第二套用例或快照（原计划的包内 `tests/contract/` 骨架不落地，指向它的 `vitest.contract.config.ts`
  已移入包内 `归档/`）；本包 `test:contract` 脚本委托
  `pnpm --filter @chips/contract-tests run test:contract`，运行即真实执行到 bridge 契约用例；
- 覆盖率门禁：共享层 > 90%（vitest v8）；
- 验收命令：`pnpm typecheck && pnpm lint && pnpm test && pnpm test:coverage && pnpm build && pnpm test:contract`。

## 五、依赖与风险

- 仅引入开发期依赖：`typescript`、`vitest`、`@vitest/coverage-v8`、`eslint`、`typescript-eslint`；运行期零第三方依赖；
- 风险：Bridge 核心在最终架构中由 Rust 核心承载（02-Bridge三层设计 §2.1），本包以同语义 TS 实现并提供
  `ICapabilityInvoker` / 会话与事件注册表等接缝，后续可由 Neon 实现替换而不改消费方；TS 侧与 Rust 侧语义必须逐条对齐（已按文档实现并测试）。
- 未决口径（已写入开发日志，待主代理确认）：内置能力 `owner` 标识文档未给出具体值，本包以 `PLATFORM_OWNER_ID = 'chips.platform'` 作为默认内置提供方标识，可由宿主注入覆盖。
