## 一、范围

在 `chips-ecosystem/examples/plugins/hello/` 交付首个 app 角色最小示例插件（金链路首个被测插件），与 `@chips/sdk/scaffold` 的 `app` 角色模板同构：

1. `manifest.yaml`：app 角色、窗口表面、启动器入口、最小权限集合。
2. `src/index.ts`：`IAppPlugin` 实现（主进程纯逻辑 + 命令注册与处理）。
3. `src/ui/AppView.tsx`：React + `@chips/ui` 窗口界面（`render.js` 源码）。
4. 命令与能力调用示例：`command:register` / `notification:send`（主进程）与 `config:get` / `clipboard:write`（渲染进程）。
5. 构建配置：`vite.shared.ts`、`vite.main.config.ts`、`vite.render.config.ts`（R4 入口防线与依赖外部化）。
6. 单测：`src/index.test.ts`（主逻辑）、`src/ui/AppView.test.tsx`（组件）、`vitest.config.ts`。
7. 文档：`README.md`、`开发计划.md`、`开发日志.md`。

不在范围：`.cpk` 打包与本地安装（依赖 `@chips/cli`，W1 其它任务交付后执行）；脚手架生成器本身（W1-SCAFFOLD）。

## 二、功能设计

| 项               | 说明                                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------------------- |
| 插件 ID          | `chips.example.hello`（示例命名空间，不冒充官方）                                                       |
| 显示名           | 你好世界                                                                                                |
| 表面             | `ui.surface: window`，`runtime.background: false`                                                       |
| 配置             | `title`（窗口标题）、`greeting`（界面问候语），schema 位于 `assets/schemas/config.schema.json`          |
| 命令             | `hello:set-greeting`（写用户配置）、`hello:notify`（调用通知能力）、`hello:exit`（结束实例）            |
| 权限             | `command:write`（注册命令）、`notifications:send`（通知）、`clipboard:access`（复制问候语），无多余权限 |
| 主进程能力链路   | `ctx.bridge.request('notification:send', ...)`                                                          |
| 渲染进程能力链路 | `chips.request('config:get'                                                                             | 'clipboard:write', ...)`、`chips.subscribe('config:changed', ...)` |

## 三、接口与契约对齐

| 契约                 | 对齐点                                                                                                                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 应用插件接口 07      | 默认导出 `IAppPlugin` 实例；模块顶层只声明；`launch` 恰好一次；`beforeExit` 只收尾；实例字段只读不跨实例复用                                                                 |
| 命令系统契约 13      | 命令 ID `<domain>:<action>`，域取插件 ID 末段 `hello`；`paramsSchema` 顶层 `object` + `additionalProperties: false`；注册后由平台以 `handleCommand(commandId, payload)` 派发 |
| 插件清单规范 02      | `app` 必须声明 `ui.surface`；权限按已登记权限 ID 且最小化；路径引用位于 `assets/` 内                                                                                         |
| 构建与打包 02 §5.5   | `dist/index.js` 完全自包含、无模块引用；`render.js` 外部化 `react` / `react-dom` / `@chips/ui` 并重写为平台 vendor URL；两入口均为单文件 ESM                                 |
| @chips/ui 指南 02/08 | 入口挂载 `ChipsProvider` 一次；组件与令牌只从 `@chips/ui` 导入；样式只用 Design Tokens 与内联布局                                                                            |
| 测试规范 02/05       | vitest + jsdom；平台调用经 `@chips/sdk/testing` 的 Mock Bridge；测试文件与被测文件同目录                                                                                     |

## 五、风险

1. 脚手架（W1-SCAFFOLD）与 SDK/UI 包尚未落位：本示例先按文档库手写，保持与 `app` 模板同构；工具落位后按模板回归比对（已登记工单 001）。
2. `@chips/sdk` / `@chips/ui` 未交付前，`test` / `build` 无法执行：主逻辑单测（仅类型导入）可先独立验证，其余在依赖落位后补验。
3. 契约类型（`CapabilityInput` / `CapabilityOutput` / `ICommandDefinition`）以 SDK 导出为准，若 SDK 与文档不一致，先登记工单再修正。
