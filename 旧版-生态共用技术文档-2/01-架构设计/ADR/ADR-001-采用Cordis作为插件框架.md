# ADR-001: 采用 Cordis 作为插件框架

## 状态

**已接受** - 2026-09-19

## 背景

薯片生态定位为软件级生态系统，需要一个能够支撑原子化模块、可逆副作用、动态组合的插件框架。传统插件系统（如 VS Code Extension API）难以满足以下需求：

1. **原子化模块**：生态中每个功能都必须是独立可替换的最小单元
2. **可逆副作用**：插件的安装、卸载、更新必须完全可逆，不能污染系统状态
3. **动态组合**：插件之间需要支持运行时动态组合和依赖注入
4. **热插拔**：用户在不重启软件的情况下完成插件的安装、更新和卸载
5. **跨语言调用**：Rust 核心需要与插件进行高效的跨语言通信

经过对现有方案的系统性调研（自研、VS Code Extension API、ECMAScript Plugin API、Cordis），最终选择 Cordis 作为插件框架基础。

## 决策

完整引入 **Cordis** 作为薯片生态的插件运行时框架，并进行深度定制以适配薯片生态需求。

### Cordis 核心特性适配

| 特性 | 薯片生态适配方案 |
|------|------------------|
| 原子化模块 | 每个插件定义为一个独立的 Module，支持细粒度能力暴露 |
| 可逆副作用 | 采用事务性安装/卸载机制，失败自动回滚 |
| 动态组合 | 支持运行时依赖注入和服务发现 |
| 热插拔 | 基于 ESM 的动态导入实现插件动态加载 |
| 跨语言桥接 | 通过 N-API 与 Rust 核心通信 |

### 定制化扩展

1. **Manifest 扩展**：在 Cordis ModuleDescriptor 基础上扩展薯片特有的 manifest schema
2. **权限模型**：集成薯片生态的权限声明和校验机制
3. **生命周期钩子**：扩展 BeforeInstall、AfterUninstall 等钩子
4. **隔离策略**：实现 iframe 级别的插件隔离

## 后果

### 优势

1. **成熟的原子化模型**：Cordis 的 Module 概念天然契合薯片生态的原子化设计哲学
2. **完善的生态工具**：Cordis 已有配套的开发工具、测试框架和文档
3. **活跃的社区支持**：持续的更新和问题修复
4. **类型安全**：TypeScript 原生支持，提供完整的类型定义
5. **可逆性保证**：内置的 Undo/Redo 机制支持插件操作的完全可逆
6. **性能优化**：基于 ESM 的懒加载策略，优化启动性能

### 劣势

1. **学习曲线**：开发者需要学习 Cordis 的 Module 和 Service 概念
2. **迁移成本**：现有插件需要适配新的插件模型
3. **额外依赖**：增加一个核心依赖，需要关注上游版本更新
4. **Rust 集成复杂度**：需要通过 N-API 实现 Rust 与 Cordis 的高效通信

### 风险

1. **Cordis 上游更新可能引入不兼容变更**：需要锁定版本并建立版本策略
2. **性能开销**：动态组合机制可能带来一定的运行时开销
3. **内存管理**：插件卸载时的资源清理需要严格验证

## 替代方案

### 方案 1：自研插件系统

**优点**：
- 完全可控，不依赖外部依赖
- 可针对薯片生态进行极致优化

**缺点**：
- 开发周期长，需要处理大量边界情况
- 缺乏经过大规模验证的原子化模型
- 维护成本高

**结论**：不采用。成本过高，且不如成熟的 Cordis 可靠。

### 方案 2：采用 VS Code Extension API

**优点**：
- 开发者熟悉度高
- 有大量现成的插件可参考

**缺点**：
- VS Code API 面向代码编辑器场景，不适合通用软件生态
- 原子化模型不足
- 热插拔支持有限

**结论**：不采用。API 设计理念与薯片生态不匹配。

### 方案 3：采用 ECMAScript Plugin API

**优点**：
- 标准化提案，浏览器兼容性好
- 原生 JavaScript 支持

**缺点**：
- 提案尚未成熟
- 功能有限，不支持复杂的服务组合

**结论**：不采用。太不成熟，无法满足薯片生态的复杂需求。

## 实现计划

### Phase 1: 基础集成
- 引入 Cordis 核心包
- 实现 TypeScript 类型定义扩展
- 搭建基础插件加载流程

### Phase 2: 薯片定制
- 扩展 Manifest schema
- 集成权限模型
- 实现生命周期钩子

### Phase 3: 高级特性
- 实现热插拔机制
- 完善隔离策略
- 性能优化
