# ADR-010: 多语言 i18n 架构

## 状态

**已接受** - 2026-09-19

**修订说明**：根据 task030 决议，界面文案一律简体中文直写，不再使用多语言运行时切换机制。本 ADR 描述的是设计阶段的多语言架构方案。

## 背景

薯片生态定位为国际化产品，需要支持多语言用户界面。传统 i18n 实现存在以下问题：

1. **运行时开销**：每次翻译都需要查找
2. **内存占用**：所有语言包常驻内存
3. **格式化复杂**：日期、数字、货币格式化分散
4. **RTL 支持**：需要特殊处理从右到左的语言
5. **占位符处理**：变量插值实现不一致

## 决策

采用 **分层 i18n 架构**，在设计阶段规划完整方案：

### 架构分层

```
┌─────────────────────────────────────────────────────────────┐
│                    i18n Architecture                         │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  Layer 1: Translation Layer (翻译层)                   │  │
│  │  - Key-based translations                              │  │
│  │  - Pluralization rules                                 │  │
│  │  - Context-aware translations                          │  │
│  └───────────────────────────────────────────────────────┘  │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  Layer 2: Formatting Layer (格式化层)                   │  │
│  │  - Date/Time formatting                                │  │
│  │  - Number formatting                                   │  │
│  │  - Currency formatting                                 │  │
│  │  - Relative time formatting                            │  │
│  └───────────────────────────────────────────────────────┘  │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  Layer 3: Pluralization Layer (复数层)                  │  │
│  │  - Language-specific plural rules                      │  │
│  │  - Cardinal/Ordinal support                           │  │
│  │  - Zero handling                                      │  │
│  └───────────────────────────────────────────────────────┘  │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  Layer 4: RTL/LTR Layer (文本方向层)                    │  │
│  │  - Logical properties (margin-inline-start)           │  │
│  │  - Direction isolation                                │  │
│  │  - Icon mirroring                                    │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

### 翻译文件格式

#### JSON 格式

```json
// locales/zh-CN.json
{
  "common": {
    "button": {
      "confirm": "确认",
      "cancel": "取消",
      "save": "保存",
      "delete": "删除"
    },
    "message": {
      "success": "操作成功",
      "error": "操作失败",
      "loading": "加载中..."
    }
  },
  "card": {
    "editor": {
      "title": "卡片编辑器",
      "addContent": "添加内容",
      "removeContent": "移除内容"
    }
  }
}
```

#### ICU MessageFormat

支持复杂格式化场景：

```json
{
  "greeting": "你好，{name}！",
  "items": "{count, plural, =0{没有项目} =1{1个项目} other{#个项目}}",
  "date": "{date, date, medium}",
  "currency": "{amount, number, ::currency/CNY}",
  "relative": "{time, relative, short}"
}
```

### 格式化 API

```typescript
// i18n/formatters.ts
export interface Formatters {
  // 日期格式化
  date(value: Date | number | string, options?: DateFormatOptions): string;
  time(value: Date | number | string, options?: TimeFormatOptions): string;
  datetime(value: Date | number | string, options?: DateTimeFormatOptions): string;
  
  // 数字格式化
  number(value: number, options?: NumberFormatOptions): string;
  percent(value: number, options?: PercentFormatOptions): string;
  currency(value: number, currency: string, options?: CurrencyFormatOptions): string;
  
  // 相对时间
  relative(value: Date | number, options?: RelativeTimeFormatOptions): string;
  
  // 列表格式化
  list(values: string[], options?: ListFormatOptions): string;
}
```

```typescript
  'margin-inline-start': { ltr: 'margin-left', rtl: 'margin-right' },
  'margin-inline-end': { ltr: 'margin-right', rtl: 'margin-left' },
  'padding-inline-start': { ltr: 'padding-left', rtl: 'padding-right' },
  'padding-inline-end': { ltr: 'padding-right', rtl: 'padding-left' },
  'text-align-start': { ltr: 'left', rtl: 'right' },
  'text-align-end': { ltr: 'right', rtl: 'left' },
};
```

### React Hooks

```typescript
// i18n/hooks.ts
import { useTranslation, useLocale, useDirection } from '@chips/i18n';

// 基础翻译 Hook
function MyComponent() {
  const { t, tm } = useTranslation();
  
  return (
    <button>{t('common.button.confirm')}</button>
    <p>{t('card.items', { count: 5 })}</p>
  );
}

// 格式化 Hook
function DateDisplay({ date }) {
  const { formatDate, formatNumber } = useLocale();
  
  return (
    <span>{formatDate(date, { style: 'medium' })}</span>
  );
}

// 方向 Hook
function DirectionalContent() {
  const direction = useDirection();
  
  return (
    <div style={{ direction }}>
      {/* 内容 */}
    </div>
  );
}
```

### 懒加载策略

```typescript
// i18n/lazy.ts
export function useLazyLocale(locale: string) {
  return useAsync(() => import(`./locales/${locale}.json`), [locale]);
}

// Provider 配置
<I18nProvider
  defaultLocale="zh-CN"
  locales={['zh-CN', 'en-US', 'ja-JP']}
  loadLocale={async (locale) => {
    const module = await import(`./locales/${locale}.json`);
    return module.default;
  }}
>
  {children}
</I18nProvider>
```

### 复数规则

```typescript
// i18n/plurals.ts
const pluralRules: Record<string, PluralRules> = {
  // 中文：无复数
  'zh': (n) => 'other',
  
  // 英文：单复数
  'en': (n) => {
    if (n === 1) return 'one';
    return 'other';
  },
  
  // 俄语：复杂复数
  'ru': (n) => {
    const mod10 = n % 10;
    const mod100 = n % 100;
    if (mod10 === 1 && mod100 !== 11) return 'one';
    if (mod10 >= 2 && mod10 <= 4 && (mod100 < 12 || mod100 > 14)) return 'few';
    return 'many';
  },
  
  // 阿拉伯语：六种复数
  'ar': (n) => {
    if (n === 0) return 'zero';
    if (n === 1) return 'one';
    if (n === 2) return 'two';
    if (n >= 3 && n <= 10) return 'few';
    if (n >= 11 && n <= 99) return 'many';
    return 'other';
  },
};
```

## 后果

### 优势

1. **结构清晰**：分层设计，易于理解和维护
2. **性能优化**：懒加载策略减少内存占用
3. **格式一致**：统一的格式化 API
4. **RTL 完善**：完整的从右到左支持
5. **类型安全**：TypeScript 类型推导
6. **可扩展**：易于添加新语言

### 劣势

1. **初始复杂度**：分层架构有一定学习成本
2. **翻译成本**：需要专业翻译团队
3. **维护成本**：多语言翻译同步更新

### 风险

1. **翻译质量**：第三方翻译可能不准确
2. **文化适配**：某些表达可能在不同文化中有不同含义
3. **字符串膨胀**：多语言导致资源文件增大

## 替代方案

### 方案 1：简单 key-value

**优点**：
- 实现简单
- 易于理解

**缺点**：
- 不支持复杂格式化
- 缺少复数和 RTL 支持

**结论**：不采用。无法满足国际化需求。

### 方案 2：使用现有 i18n 库

**优点**：
- 成熟稳定
- 功能完善

**缺点**：
- 依赖外部库
- 可能与生态集成困难

**结论**：参考。吸收其最佳实践，但不直接依赖。

## 实现计划

### Phase 1: 基础架构
- 设计 token 格式
- 实现核心 API
- 配置构建系统

### Phase 2: 格式化
- 实现日期/数字格式化
- 实现复数规则
- 实现 RTL 支持

### Phase 3: 工具链
- 开发翻译管理工具
- 配置 CI/CD 翻译流程
- 编写文档和示例
