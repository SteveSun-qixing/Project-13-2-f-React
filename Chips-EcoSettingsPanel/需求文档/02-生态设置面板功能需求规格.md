# 生态设置面板功能需求规格

## 1. 信息架构

当前左侧菜单由 `MENU_REGISTRY` 注册表驱动，固定提供以下一级入口：

| 菜单 ID | 菜单名称 | 目标 |
| --- | --- | --- |
| `themes` | 主题管理 | 管理已安装主题包，安装新主题，切换当前主题，卸载主题 |
| `theme-diagnostics` | 主题诊断 | 展示当前主题 contract/resolve 诊断、覆盖率、解析链和组件状态 |
| `languages` | 多语言 | 查看已安装语言并切换当前语言 |
| `app-plugins` | 应用插件 | 管理应用插件安装、启用、停用、卸载 |
| `card-plugins` | 卡片插件 | 管理基础卡片插件安装、启用、停用、卸载和卡片类型标识 |
| `layout-plugins` | 箱子布局插件 | 管理箱子布局插件安装、启用、停用、卸载和布局类型标识 |
| `module-plugins` | 模块插件 | 管理功能模块插件安装、启用、停用、卸载和能力集合 |
| `component-gallery` | 组件展示 | 使用当前主题预览薯片组件库组件 |
| `preview-quality` | 预览与质量 | 展示 `chipsdev-r` 预览、组件矩阵、主题检查、质量门禁和诊断命令入口 |

菜单系统必须采用“注册表驱动”模式实现，后续增加新菜单时只新增配置和页面模块，不允许把菜单逻辑散落在多个组件中。

## 2. 主题管理

### FR-THEME-001 列表展示

- 页面左上显示标题“主题管理”。
- 页面右上显示“安装主题”主操作按钮。
- 中央区域显示已安装主题列表；列表项至少包含：主题名称、主题 ID、版本、发布者、可切换状态、当前生效状态。
- 当前正在使用的主题必须有明确标识。
- 默认主题包必须在主题名称后方使用紧凑小药丸标识，而不是只放在状态区域，便于用户扫列表时立即识别生态默认包。
- 当前正式布局使用 macOS 系统设置式设置条目列表，不使用主题条目卡片墙布局，也不使用传统多列表格堆叠字段。
- 列表中只保留“切换”和“详情”等高频动作；卸载、安装路径、完整身份信息等低频内容进入主题详情页。

### FR-THEME-002 安装主题

- 点击“安装主题”后，调用正式文件选择能力选择主题包。
- 主题包也可以直接拖入整个生态设置面板窗口完成安装；页面不常驻显示固定拖入安装区域。
- 仅接受 Host 正式支持的主题安装输入（如 `.cpk`、插件目录、`manifest.yaml` 所在目录或清单文件路径）。
- 安装成功后立即刷新列表；安装失败时展示错误信息和失败原因。

### FR-THEME-003 切换主题

- 每个可用主题项提供“切换”动作。
- 每个主题项提供“详情”动作，点击后在当前 Scene 内进入二级详情页，左上角提供返回按钮。
- 切换成功后必须立即刷新当前主题标记，并驱动页面主题同步更新。
- 如果目标主题已经是当前主题，应禁用或弱化该动作，避免重复提交。

### FR-THEME-004 卸载主题

- 主题详情页提供“卸载”动作；主题列表不直接展示卸载按钮，避免列表动作过多造成混乱。
- 当前主题卸载前必须给出明确阻断提示或先要求切换到其他主题。
- 卸载成功后刷新列表与当前主题状态。

### FR-THEME-005 主题详情页结构

- 主题详情页应采用清晰的信息结构，而不是把字段直接平铺在一个拥挤容器中。
- 顶部区域必须按纵向阅读顺序组织：第一行单独展示主题名称和默认主题小药丸，第二行展示简介小字，下方再展示状态标签和常用动作。
- 字段区域采用竖向独立信息组：基础信息展示主题 ID、版本、发布者；安装信息展示安装路径等长文本字段。分组标题不得作为单独左列，避免信息被横向切碎。
- 卸载等低频或高风险动作应与基础字段形成视觉分区。
- 仅用于页面留白、网格、信息分组和结构骨架的背景容器，可以使用普通语义 `section / article / div / dl`；不要求全部使用薯片组件库外观组件。按钮、Badge、输入、状态反馈、正式列表语义等交互或主题 contract 对象仍必须优先使用 `@chips/component-library`。

## 3. 多语言

### FR-I18N-001 语言列表

- 页面展示当前已安装语言列表。
- 每个语言项至少包含语言名称、语言代码、当前状态。
- 当前语言必须高亮显示。
- 当前正式布局使用列表，并为每个语言项提供“详情”入口，进入当前 Scene 内二级详情页。

### FR-I18N-002 切换语言

- 用户点击目标语言后立即切换语言。
- 切换后页面文案应通过正式 i18n 机制刷新，不允许整页重载。
- 页面必须监听 `language.changed` 事件，确保与 Host 运行时保持一致。

## 4. 应用插件

### FR-APPPLUGIN-001 列表展示

- 页面展示所有已安装 `type: app` 插件的列表。
- 列表项至少包含：名称、插件 ID、版本、启用状态、安装时间。
- 系统自身设置面板插件若出现在列表中，当前正式规则为“不允许在自身界面中停用或卸载”，并在界面和文档中明确标识该限制。
- 当前正式布局使用列表，不使用插件条目卡片墙布局；每个插件项提供“详情”入口，进入当前 Scene 内二级详情页。

### FR-APPPLUGIN-002 安装插件

- 支持按钮选择文件安装。
- 支持把插件包拖入整个生态设置面板窗口安装；页面不常驻显示固定拖入安装区域。
- 安装完成后刷新运行时列表。

### FR-APPPLUGIN-003 启用与停用

- 已安装但未启用的插件提供“启用”动作。
- 已启用插件提供“停用”动作。
- 操作成功后必须即时刷新列表状态。

### FR-APPPLUGIN-004 卸载

- 应用插件卸载属于低频或高风险动作，应放入应用插件详情页；列表只保留启动、启用/停用和详情等常用动作。
- 如果存在生态约束不允许卸载，必须在交互中给出明确说明，而不是静默失败。

### FR-APPPLUGIN-005 快捷方式治理

- 插件项提供应用快捷方式状态展示，至少包含“已创建 / 未创建”与目标位置（Windows 桌面 / macOS 启动台）。
- 快捷方式创建、重建、移除和显示位置等低频操作应放入应用插件详情页，避免列表按钮过多。
- 快捷方式治理必须通过 Host 正式接口完成，不允许前端直接创建 `.lnk`、`.app` 或其他平台文件。
- 快捷方式创建后，用户应可在 Host 静默待机时直接从快捷方式启动对应应用插件。

## 5. 组件展示

### FR-GALLERY-001 真实组件预览

- 页面以 Bento 布局展示薯片组件库当前正式导出的组件。
- 所有展示必须直接使用 `@chips/component-library` 中的真实组件，不允许复制样式或自造近似组件。
- 每个展示卡片需尽量覆盖默认、悬停、激活、禁用、错误等关键状态中的至少一种。

### FR-GALLERY-002 组件分组

页面至少按以下分组展示：

- P0 交互基础组件：`ChipsButton`、`ChipsInput`、`ChipsCheckbox`、`ChipsRadioGroup`、`ChipsSwitch`、`ChipsSelect`、`ChipsDialog`、`ChipsPopover`、`ChipsTabs`、`ChipsMenu`、`ChipsToolbar`、`ChipsMenuBar`、`ChipsContextMenu`、`ChipsShortcut`、`ChipsTooltip`
- P0 数据表单组件：`ChipsForm` Compound、`ChipsVirtualList`
- Stage 7 高级数据组件：`ChipsDataGrid`、`ChipsTree`、`ChipsDateTime`、`ChipsCommandPalette`、`ChipsNavigationSplitView`
- Stage 7 工作台组件：`ChipsSplitPane`、`ChipsDockPanel`、`ChipsInspector`、`ChipsPanelHeader`、`ChipsCardShell`、`ChipsToolWindow`
- Stage 8 系统体验组件：`ChipsErrorBoundary`、`ChipsLoadingBoundary`、`ChipsNotification`、`ChipsToast`、`ChipsEmptyState`、`ChipsSkeleton`

### FR-GALLERY-003 主题验证

- 切换主题后，组件展示页必须自动刷新并呈现真实主题效果。
- 该页面作为主题验收基准之一，后续新增正式组件时必须同步纳入展示清单。

## 6. 主题诊断

### FR-DIAGNOSTICS-001 当前主题 contract 诊断

- 页面必须通过 SDK `client.theme.contract.get()` 读取当前主题 contract view。
- 页面必须通过 SDK `client.theme.resolve([])` 读取当前主题解析链、token 汇总和诊断摘要。
- 页面展示内容至少包含当前主题标识、版本、contract/schema 版本、required/optional token 覆盖率、组件覆盖状态、主题链和诊断条目。
- 页面不得读取 ThemePack、组件库 contract 源目录或 Host 工作区私有文件来绕过正式接口。

### FR-DIAGNOSTICS-002 诊断边界

- 当前页面只诊断当前主题。
- 跨主题实时 contract 矩阵必须等待 Host/SDK 提供指定主题查询或正式报告消费链路后再进入运行时页面。

## 7. 预览与质量

### FR-QUALITY-001 正式命令入口

- 页面展示 `chipsdev-r preview --target app|component|card|box|layout|theme`、`chipsdev-r component gallery`、`chipsdev-r theme inspect`、`chipsdev-r quality gate`、`chipsdev-r diagnostics` 等正式开发工具命令。
- 页面必须明确区分运行时治理状态与开发期报告入口，不伪造报告通过状态。
- 当前运行时页面不得直接读取 `reports/`、ThemePack、组件库 contract 源目录或 Host 私有目录。

## 8. 卡片、布局与模块插件治理

### FR-RUNTIMEPLUGIN-001 列表展示

- 卡片插件页通过 `plugin.query({ type: "card" })` 展示基础卡片插件。
- 箱子布局插件页通过 `plugin.query({ type: "layout" })` 展示布局插件。
- 模块插件页通过 `plugin.query({ type: "module" })` 展示功能模块插件。
- 列表项至少包含名称、插件 ID、版本、启用状态、安装路径和能力/类型标识。

### FR-RUNTIMEPLUGIN-002 安装与类型校验

- 三类页面均支持右上角安装按钮选择文件，也支持把插件包拖入整个生态设置面板窗口安装；页面不常驻显示固定拖入安装区域。
- 安装完成后必须通过 `plugin.get(pluginId)` 或下一次 `plugin.query({ type })` 校验真实插件类型，禁止把错误类型包混入当前列表。
- 文件选择必须走 SDK `client.platform.openFile()`，不得在页面层裸调 Host action。

### FR-RUNTIMEPLUGIN-003 启停与卸载

- 已安装但未启用的插件提供“启用”动作，已启用插件提供“停用”动作。
- 卸载前必须弹出正式确认。
- 所有操作成功后必须重新读取 Host 运行时状态，不允许前端手改治理状态。

## 9. 通用交互要求

- 左侧菜单切换不能造成整个应用刷新或丢失当前运行时状态。
- 窄屏场景必须提供正式菜单切换控件；当前实现采用顶部切换器，不允许仅依赖被压缩的桌面侧边栏。
- 所有 destructive 操作必须有明确确认或风险提示。
- 异步处理中需呈现加载态，防止重复提交。
- 空列表、错误态、权限不足、文件格式错误等场景必须有正式 UI 与可读提示。
