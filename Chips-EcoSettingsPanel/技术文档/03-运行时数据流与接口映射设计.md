# 运行时数据流与接口映射设计

## 1. 原则

生态设置面板是治理类应用，不直接消费底层文件结构，而是统一通过 Host 正式服务域获取运行时状态。所有接口都必须经过项目内服务适配层归一化后再供页面使用。

## 2. 页面与接口映射

| 页面 | 读取接口 | 写入接口 | 事件 |
| --- | --- | --- | --- |
| 主题管理 | `plugin.query({ type: 'theme' })`、`theme.list()`、`theme.getCurrent()` | `plugin.install()`、`theme.apply()`、`plugin.uninstall()` | `theme.changed`、`plugin.installed`、`plugin.uninstalled` |
| 主题诊断 | `theme.contract.get()`、`theme.resolve([])` | 无 | `theme.changed` |
| 多语言 | `i18n.getCurrent()`、`i18n.listLocales()` | `i18n.setCurrent()` | `language.changed` |
| 应用插件 | `plugin.query({ type: 'app' })`、`plugin.getShortcut(pluginId)` | `plugin.install()`、`plugin.enable()`、`plugin.disable()`、`plugin.uninstall()`、`plugin.createShortcut()`、`plugin.removeShortcut()` | `plugin.installed`、`plugin.enabled`、`plugin.disabled`、`plugin.uninstalled`、`plugin.shortcut.changed` |
| 组件展示 | 组件库导出清单、`theme.getCurrent()`、必要时 `theme.contract.get()` | 无 | `theme.changed` |
| 预览与质量 | `chipsdev-r preview/component gallery/theme inspect/quality gate/diagnostics` 正式报告命令口径 | 无 | 无 |
| 应用 Scene 导航 | `command.list()`、本地 `scene-registry.ts` | `command.register()`、`command.unregister()`、`command.invoke()` | `command.invoked`、`command.changed` |

## 2.1 App Runtime 与命令入口

当前应用入口已经迁移为 vNext 结构：

- `AppRoot` 是根组件，负责组合 `AppProviders` 与 `AppShell`。
- `AppProviders` 统一注入 SDK client、组件库 Environment、主题 Provider、设置面板 AppRuntime 与 i18n Provider。
- `AppRuntimeProvider` 从 `client.platform.getLaunchContext()` 读取 Host launch context 与 surface context，并派生 `pluginId`、`surfaceId`、`sessionId`、`surfaceKind`、`launchParams`、当前 active scene、主题、语言和运行时错误态。
- `settings-commands.ts` 为每个 Scene 生成稳定 command id：`com.chips.eco-settings-panel.scene.<sceneId>`，插件侧 handler id 固定为 `open-scene:<sceneId>`。
- `useSettingsCommands()` 在应用启动时通过 `client.command.register()` 注册 Scene 命令，通过 `client.command.onInvoked()` 接收 Host 调度事件，并在卸载时调用 `client.command.unregister()` 清理。
- 侧栏导航与窄屏切换器通过同一套 command metadata 进入 Scene 切换，避免桌面与窄屏入口各自维护业务动作；当前页面顶部不再渲染额外的命令菜单、工具栏或命令面板。

## 3. 主题治理口径

当前主题管理列表必须区分两类数据：

1. **已安装主题记录**：来源于 `plugin.query({ type: 'theme' })`，用于展示所有已安装主题和卸载动作。
2. **可切换主题集合**：来源于 `theme.list()`，只表示当前工作区“已启用”的主题。

页面需要在适配层把两类数据合并，生成统一的主题视图模型，明确：

- 是否已安装
- 是否已启用
- 是否为当前主题
- 是否允许切换
- 是否允许卸载

## 4. 文件安装流程

文件选择与拖拽安装必须遵循正式治理契约：

- 文件对话框调用 SDK `client.platform.openFile()`，底层对应 Host `platform.dialogOpenFile`；
- 安装动作统一调用 `plugin.install(manifestPath)`；
- 页面只负责解析用户输入来源，不负责自行解包或扫描插件包；
- 安装结果刷新时以 Host 返回的运行时记录为准，不以本地临时状态伪造成功结果。

当前实现落地方式：

- `SettingsRuntimeService.openPluginFileDialog()` 统一发起 `client.platform.openFile()`，并通过 `filters` 限制 `cpk / yaml / yml / json`
- 页面层通过 i18n 传入对话框标题与过滤器名称
- 拖拽安装采用整窗监听：`useWindowFileDrop` 只在文件进入窗口时激活 `WindowDropOverlay` 轻量提示，平时不渲染固定拖入安装区域；松手后把 `File` 交给 `platform.getPathForFile()` 解析，再复用相同安装入口

## 5. 事件同步

页面层必须通过统一事件订阅机制同步 Host 运行时变化：

- `theme.changed`：同步当前主题、刷新展示页与主题标签。
- `language.changed`：同步当前语言、触发文案重算。
- `plugin.*`：刷新应用插件页与主题管理页的安装状态。
- `plugin.shortcut.changed`：用于后续增强场景下刷新快捷方式状态；当前实现仍以动作完成后的主动刷新为主。

事件处理必须幂等，不能因为重复事件造成列表重复插入或状态错乱。

当前实现约束：

- 页面级刷新统一走 `useHostRefresh()`
- 主题页监听：`theme.changed`、`plugin.installed`、`plugin.uninstalled`
- 语言页监听：`language.changed`
- 应用插件页监听：`plugin.installed`、`plugin.enabled`、`plugin.disabled`、`plugin.uninstalled`
- `useHostRefresh()` 内部使用稳定事件名快照与最新回调引用，避免组件重渲染时重复拆装同一组 Host 订阅，同时保证事件到达时始终执行最新刷新逻辑
- 当前设置面板插件的“不可停用 / 不可卸载”限制同时存在于页面按钮层和 `useAppPluginGovernance()` 动作层，避免仅靠 UI 禁用造成结构性绕过

## 6. 应用快捷方式治理口径

应用插件页的快捷方式状态来自两层正式数据：

1. `plugin.query({ type: 'app' })`：提供应用插件基础运行时记录；
2. `plugin.getShortcut(pluginId)`：提供该应用插件在当前工作区下的系统快捷方式状态。

当前实现落地方式：

- `SettingsRuntimeService.listAppPlugins()` 先拉取全部应用插件记录，再逐个调用 `client.plugin.getShortcut(record.id)` 合并为页面视图模型；
- `createPluginShortcut(pluginId, replace)` 直接映射 `client.plugin.createShortcut(pluginId, { replace })`；
- `removePluginShortcut(pluginId)` 直接映射 `client.plugin.removeShortcut(pluginId)`；
- “显示位置”动作统一复用 `shell.showItemInFolder`，不自行拼装系统命令。
- 应用插件列表图标展示优先读取 `shortcut.iconPath` 并转成 `file://` 资源 URL；缺失时回退到运行时 `ChipsIcon + IconDescriptor`，不展示路径文本、不回退 emoji。

需要明确的技术细节：

- Host 返回的 `shortcut.exists` 才是正式真值，前端不得自行判断文件是否存在；
- `shortcut.location` 只承担展示语义，不用于推导真实路径；
- `shortcut.args` 是 Host 实际写入快捷方式的参数快照，可用于诊断“错误工作区”或“错误插件”问题；
- 当快捷方式已存在时，页面创建动作当前会以 `replace = true` 触发更新，从而确保图标、名称与目标路径可刷新到最新状态。

## 6.1 主题诊断与预览质量入口

主题诊断入口的数据来源必须保持为 Host/SDK 正式接口：

- `SettingsRuntimeService.getThemeContract(component?)` 映射 `client.theme.contract.get(component?)`
- `SettingsRuntimeService.resolveThemeDiagnostics(chain)` 映射 `client.theme.resolve(chain)`
- 首批页面只查询当前主题，即 `theme.contract.get()` 与 `theme.resolve([])`

该入口不承担跨主题实时矩阵计算。当前 SDK/Host 的 `theme.contract.get()` 不接受 `themeId`，非当前主题的完整 contract 诊断不能由前端扫描 ThemePack 私有目录替代。

预览与质量入口只展示正式开发工具命令：

- `chipsdev-r preview --target app|component|card|box|layout|theme`
- `chipsdev-r component gallery`
- `chipsdev-r theme inspect`
- `chipsdev-r quality gate`
- `chipsdev-r diagnostics`

完整 JSON 报告如需在应用运行时展示，应先补 Host/SDK 正式报告消费链路；设置面板运行时代码不得直接读取 `reports/`、ThemePack、组件库 contract 源目录或 Host 工作区私有文件。

## 7. 错误归一化

适配层需要把 Host/SDK 错误统一映射为页面可消费结构，例如：

```ts
interface SettingsPanelError {
  code: string;
  message: string;
  messageKey?: string;
  retryable: boolean;
  details?: unknown;
  requestId?: string;
  traceId?: string;
  permission?: PermissionDiagnostic;
}
```

页面层只依赖归一化错误，不直接读取散落的原始异常对象字段。

应用壳层中的 Host 启动期错误同样必须走统一错误结构，不允许直接把英文异常字符串泄漏到 UI。

当前实现约束：

- SDK Bridge 适配层需要先解码 Host IPC 返回的标准错误封装，再进入设置面板自身的 `normalizeSettingsError()`
- 页面层不得直接展示 Electron `Error invoking remote method ...` 这类宿主异常前缀
- `PERMISSION_DENIED` 与 `SERVICE_PERMISSION_DENIED` 必须保留 SDK 标准 `permission.required/granted/action/messageKey/pluginId` 诊断，页面和测试以该字段识别权限不足，不从原始异常字符串中解析权限名

## 8. 权限基线

当前 manifest 必须覆盖以下权限：

- `theme.read`
- `theme.write`
- `i18n.read`
- `i18n.write`
- `plugin.read`
- `plugin.manage`
- `platform.read`
- `platform.external`
- `command.read`
- `command.write`
- `command.invoke`

当前实现已将同一权限清单集中在 `src/app/settings-permissions.ts`，并通过测试比对：

- `manifest.yaml` 的 `permissions`
- `AppProviders` 注入组件库 `ChipsEnvironmentProvider` 的 `initialPermissions`
- `Chips-SDK/src/contracts/route-manifest.json` 中设置面板实际消费 route 的 `permission`

如未来新增设置项需要更多平台能力，必须同步更新 manifest 与本技术文档。
