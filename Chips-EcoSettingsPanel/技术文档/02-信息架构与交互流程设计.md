# 信息架构与交互流程设计

## 1. 页面壳层

采用经典设置面板布局：

- 窗口外壳采用 Host 正式窗口契约，在 `manifest.yaml` 中声明 `ui.window.chrome.frame: true` 与 `titleBarStyle: default`，由 Electron 原生标题栏承接窗口标题与系统控制按钮。
- 左侧：固定宽度菜单栏，包含应用标题、搜索框、按分类分组的一级菜单和预留扩展入口。
- 右侧：滚动内容区，顶部显示页面标题与上下文操作按钮，下方显示具体内容。
- 左侧菜单栏只保留导航职责，不再附加当前主题 / 当前语言运行时信息小窗；桌面端采用 macOS 系统设置式侧边栏，包含搜索框、分类标题、中性浅色图标片、紧凑导航行和低饱和选中态。
- 右侧内容区采用 macOS 系统设置式分组观感：窗口背景为浅灰，页面标题区和 `settings-page-stack` 直接落在背景页面中，不再额外绘制外框、描边或独立底色；只有真实成组内容如治理列表、摘要区、详情字段组和组件预览项使用主题 token 派生的轻薄内容片层。治理列表不再按传统多列表格堆满字段和按钮，而是统一为精简设置条目：左侧图标与名称，右侧只保留几个真正高频动作与“详情”入口；状态徽章、版本、类型、安装信息等中间信息一律不展示，统一进入详情页查看。
- 当前页面头部统一保留大标题和必要上下文操作按钮；标题字号按系统设置主标题层级处理，头部背景保持透明，不在 `PanelHeader` 中追加副标题简介或营销式说明区。
- 壳层结构使用 `ChipsNavigationSplitView` 表达导航侧栏与内容详情区域，一级菜单项使用组件库按钮状态表达当前 Scene，但视觉上按设置导航项处理，不沿用普通主操作按钮的蓝色填充样式；左侧导航和窄屏切换器继续消费同一套 Host command metadata。

菜单栏需要支持后续继续添加分类，不允许把当前 9 个 Scene 写死成不可扩展结构。主题诊断属于主题 contract、token 覆盖率与开发验收工具，应归入“开发者”分类，而不是个人化分类。

## 2. 主题管理流程

1. 页面进入时读取已安装主题记录与当前主题。
2. 用户点击右上角“安装主题”或把主题包拖入整个设置面板窗口，进入文件安装流程；页面不常驻显示大面积拖入安装区域。
3. 安装成功后刷新列表并同步当前主题状态。
4. 用户点击“切换”后执行主题应用流程，成功后通过 `theme.changed` 触发页面刷新。
5. 用户点击“详情”时，右侧内容区进入主题二级详情页，左上角提供返回按钮。
6. 主题详情页展示完整字段与卸载等低频操作；用户点击“卸载”时弹出确认，成功后刷新列表。

## 3. 多语言流程

1. 页面进入时读取当前语言和可用语言列表。
2. 用户可先点击“详情”进入语言二级详情页，查看语言条目完整信息。
3. 用户点击目标语言项后立即提交切换。
4. 收到成功响应和 `language.changed` 事件后刷新页面文案。

## 4. 应用插件流程

1. 页面进入时读取全部应用插件运行时记录。
2. 用户点击右上角安装按钮选择文件，或把插件包拖入整个设置面板窗口安装；页面不常驻显示固定拖拽安装模块。
3. 页面根据插件启用状态渲染“启用”或“停用”动作。
4. 页面同步读取每个应用插件的快捷方式状态，并显示“未创建 / 已创建”与目标位置。
5. 应用插件列表只保留“启动”“启用/停用”和“详情”等高频动作；快捷方式创建、重建、移除和“显示位置”统一进入应用插件详情页。
6. 若列表项是当前设置面板自身插件，则停用和卸载动作必须被正式阻断，并显示限制说明。
7. 正式阻断不能只停留在按钮禁用层；页面动作入口与 hook 动作层都必须拒绝执行自停用 / 自卸载请求，避免后续 UI 复用时绕过限制。
8. 每个插件项都提供“详情”动作，进入二级详情页查看完整治理信息。
9. 其他插件卸载前弹出确认，处理完成后刷新列表。

快捷方式治理的正式交互约束：

- 页面只能调用 Host 正式接口，不允许前端直接创建 `.lnk` 或 `.app`；
- Windows 文案统一显示为“桌面快捷方式”，macOS 文案统一显示为“启动台入口”；
- “显示位置”只在 Host 返回了 `launcherPath` 时可用；
- 创建 / 删除成功后必须重新拉取当前插件的运行时记录与快捷方式状态，不允许直接前端改值。

## 5. 组件展示页布局

组件展示页采用无分组 showcase 组件矩阵布局，遵循以下原则：

- 高优先级组件可使用更宽卡片面积，便于对比主题效果，但不再使用营销式 Bento 卡片墙。
- 页面直接列出所有正式组件，不再按基础交互、表单数据、高级数据、工作台系统体验、系统体验等分组展示。
- 每个卡片只保留组件名称与真实预览，不显示组件介绍、scope 角标、parts footer 或分组计数。
- 页面仍必须覆盖所有正式组件预览，作为主题验收和视觉回归的真实基线。

当前实现约束：

- 页面按 `getComponentGroups()` 注册数据扁平化生成一个完整组件矩阵，不再生成多个 `PageSection` 分组区块，也不再显示分组标题、分组说明或分组计数。
- 每个组件卡片都包含组件名和真实预览内容；组件卡片只作为重复项内容片层出现，不显示介绍文案、scope 或 parts。
- 卡片尺寸通过 `hero / wide / standard` 三种强调级别控制，并由共享 `ShowcaseCardGrid` 负责响应式展示密度，形成稳定的组件矩阵信息层级。
- 预览文案全部进入本地 i18n 资源，避免展示页成为未国际化的“演示孤岛”。
- 主题诊断与预览质量页面复用 `PageSection / SummaryPanel / CardGrid / MetricCard / CardDescription`，摘要、指标、主题链、组件覆盖列表、诊断条目和命令入口维持同一页面节奏；诊断页不得再把所有内容包进一个额外大容器，`LoadingBoundary` 只承担状态语义，不在正常内容态绘制外框；旧的 `diagnostics-page`、`preview-quality-page`、`gallery-bento-grid` 等页面私有壳层 class 不再作为交互或测试契约。

## 6. 响应式策略

- 桌面宽屏：左侧菜单固定，右侧内容自适应。
- 中等宽度：保持左右布局，但允许右侧卡片布局自动换列。
- 窄屏场景：菜单折叠为顶部切换器或抽屉；当前实现已采用顶部切换器，桌面侧边栏导航在窄屏下隐藏。
- 主题、多语言、应用插件和运行时插件治理页统一采用 `SettingsRecordList / SettingsRecordItem` 承载设置条目，并保留 `ChipsDataGrid.Root/Row/Cell` 正式结构；桌面态按主信息（图标 + 名称）与动作区两个稳定区域显示，列表外层使用浅内容片层和细分隔线，不使用传统表格重边框；状态、版本、类型等中间信息不在列表展示，详情页承载完整字段；窄屏时折叠为单列记录，单元格内容和动作区语义不变。
- 详情页不再使用弹窗承载完整信息。主题、语言、应用插件、卡片插件、布局插件和模块插件的详情均为当前 Scene 内二级页面，左上角提供返回按钮，完整字段、危险操作和低频操作集中在详情页，列表只保留几个常用动作。详情页头部按“对象标题单独一行、简介小字、状态标签与常用按钮”的纵向顺序排布；字段分组也采用纵向排列，分组标题不再占据独立左列。
- 组件展示页的 showcase 卡片在桌面按自动适配列数展开，宽卡片最多跨两列；中宽和窄屏收敛为普通列宽，不再渲染分组标题、分组说明或分组计数标签。
