# 应用架构与模块边界设计

## 1. 总体目标

生态设置面板采用“应用壳层 + 功能模块 + 服务适配层 + 共享基础层”四层结构，确保页面持续扩展时依旧保持清晰边界。

## 2. 目录规划

当前实现已将 `src/` 组织为如下结构：

```text
src/
├─ App.tsx              # 标准入口轻量 re-export
├─ app/                 # AppRoot、Provider、AppRuntime、Scene 注册、全局 Shell
├─ commands/            # Host command registry metadata 与插件侧 handler 映射
├─ features/
│  ├─ themes/
│  ├─ theme-diagnostics/
│  ├─ languages/
│  ├─ app-plugins/
│  ├─ component-gallery/
│  └─ preview-quality/
├─ shared/
│  ├─ ui/
│  ├─ hooks/
│  ├─ i18n/
│  └─ runtime/          # Host/SDK 适配器、错误归一、事件源
└─ test-support/
```

## 3. 职责划分

### 3.1 应用壳层

- `src/App.tsx` 只保留标准应用插件入口 re-export，真实根组件由 `src/app/AppRoot.tsx` 承载。
- `AppProviders` 负责串联 `chips-sdk` client、组件库 `ChipsEnvironmentProvider`、`ChipsThemeProvider`、设置面板运行时 Provider 与本地 i18n Provider。
- `AppRuntimeProvider` 汇总 Host launch context、surface context、当前 scene、主题、语言、权限、错误态和刷新动作，功能模块优先通过应用运行时上下文消费这些状态。
- `scene-registry.ts` 由菜单注册表派生设置面板 Scene，保持现有菜单顺序和页面装配语义。
- `AppShell` 负责窗口级布局：左侧导航、窄屏切换器、反馈栈和右侧内容区。窗口级分栏使用组件库正式 `ChipsNavigationSplitView`，页面纵向组织使用 `ChipsStack / ChipsBox` 等布局原语；设置面板只保留必要的响应式、内容密度和场景组合样式，不再维护独立手写导航容器体系，也不得在业务层覆盖主题组件的长期皮肤。
- 桌面端壳层采用 macOS 系统设置式结构：侧边栏包含应用标题、搜索框和按分类分组的紧凑导航行，导航图标使用中性浅色图标片，当前项使用低饱和主题蓝选中态；右侧内容区使用浅灰窗口背景、轻薄内容片层、稳定列表列宽和紧凑操作按钮。
- 设置导航与 Host command metadata 的运行时 UI 图标统一由 `src/app/settings-scene-icons.ts` 管理，图标名必须选自当前 Material Symbols variable font codepoints 中已确认存在的 ligature 名称；禁止使用 SF Symbols、emoji 或未验证字符名，避免字体缺字形后在 Host 中显示为乱码。
- 窗口原生外壳由 `manifest.yaml -> ui.window.chrome` 声明，当前正式方案为保留 Electron 原生标题栏，不在前端重复自绘标题区。
- 应用壳层只做运行时装配、Scene 切换和公共反馈，不承载具体业务治理逻辑。
- 左侧导航和窄屏切换器必须消费同一套 `src/commands/settings-commands.ts` command metadata，通过 `chips-sdk client.command.*` 注册、查询和调用；页面顶部不再额外铺设命令菜单、工具栏或命令面板。

### 3.2 功能模块

每个一级菜单是一个独立功能模块。当前实现采用“页面组件 + 专属治理 hook”组合：

- `ThemePage.tsx` / `useThemeGovernance.ts`
- `ThemeDiagnosticsPage.tsx` / `useThemeDiagnostics.ts` / `view-model.ts`
- `LanguagePage.tsx` / `useLanguageGovernance.ts`
- `AppPluginsPage.tsx` / `useAppPluginGovernance.ts`
- `ComponentGalleryPage.tsx` / `registry.tsx`
- `PreviewQualityPage.tsx` / `view-model.ts`

这样做的原因是当前任务028基线功能规模仍可控，但读取、变更、事件刷新逻辑已经与页面结构分离，后续如果单个模块复杂度继续上升，再向 `model/` 或更细粒度的 `components/` 细分。

主题诊断模块只消费 `SettingsRuntimeService.getThemeContract()` 与 `resolveThemeDiagnostics([])`，并在 feature 层映射为页面 view model；该模块不得读取 ThemePack、组件库 contract 源目录或 Host 工作区私有文件。预览与质量模块只声明 `chipsdev-r` 正式报告命令入口，不在运行时读取本地报告 JSON。

### 3.3 服务适配层

服务适配层位于 `src/shared/runtime/settings-runtime-service.ts`，只负责把 Host / SDK 的原始响应映射成页面可消费的模型，例如：

- `ThemeInstallRecord -> ThemeListItemViewModel`
- `PluginRecord -> AppPluginListItemViewModel`
- `locale string -> LanguageListItemViewModel`

页面层不得直接拼接 Host 返回结构，避免契约扩散到全工程。

### 3.4 共享基础层

- 通用空状态、错误态、加载态组件。
- 窗口级拖拽安装、操作确认对话框、治理列表、页面 frame、页面段落、摘要面板、卡片网格、组件展示网格、指标卡和详情字段列表等可复用 UI。`PageFrame` 使用 `ChipsPanelHeader + ChipsStack`，`PageLayout` 统一封装 `PageStack / PageSection / SummaryPanel / CardGrid / ShowcaseCardGrid / CardGridItem / CardDescription / MetricCard`，`GovernanceList` 继续服务诊断类表格信息，`SettingsRecordList / SettingsRecordItem` 使用 `ChipsDataGrid.Root/Row/Cell` compound 结构承载设置项列表，统一主信息、状态摘要、元信息和高频动作区，`SettingsDetailPage` 承载 macOS 系统设置式二级详情页、左上返回、完整字段和低频操作，`StatusBadge` 使用 `ChipsBadge`，`useWindowFileDrop / WindowDropOverlay` 负责整窗拖拽文件进入时的轻量覆盖提示。旧固定 `DropZone` 安装区域已归档，不再作为正式安装入口。
- 组件展示、主题诊断、预览质量页面共享同一套页面结构：分组标题通过 `ChipsSection`，状态摘要通过 `SummaryPanel`，重复卡片通过 `CardGrid` 或 `ShowcaseCardGrid`，指标数字通过 `MetricCard`。页面级样式只保留响应式、内容密度和场景组合约束，颜色、间距、圆角、阴影和焦点态继续走主题 token 与组件库 contract。
- 公共 hooks，例如事件订阅、异步状态管理、Host 错误归一化。
- 反馈队列与通知栈统一由 `useFeedbackQueue` + `NotificationStack` 管理，`NotificationStack` 基于组件库 `ChipsToast` 渲染顶部居中的浮层提醒栈，每条消息独立呈现为药丸形短提醒，避免页面内出现大长条式提醒，也避免每个页面自行拼装消息状态。

## 4. 技术选型约束

- 状态管理优先使用 React 原生能力（Context、Reducer、自定义 hooks），不额外引入状态管理库。
- 数据请求层优先使用 `chips-sdk` 客户端与项目内适配器，不引入新的网络/查询框架。
- 组件预览页直接使用薯片组件库导出组件，不复制组件实现代码。

## 5. 扩展策略

设置页扩展必须通过注册表完成。新增设置页时只允许：

1. 新增功能模块目录；
2. 在菜单注册表中声明 `id`、`titleKey`、`order`、`component`、`capabilityTags`；
3. 确认 `scene-registry.ts` 可以从菜单注册表派生 Scene 定义；
4. 在 `commands/settings-commands.ts` 中为新增 Scene 补充稳定 command id、`handlerId`、i18n key、`IconDescriptor`、Host command placement 和权限；
5. 在测试中补充对应页面注册、命令 metadata 和最小渲染覆盖。

不允许修改多个页面组件中的 if/else 分支来“追加一个新菜单”。

## 6. 源码基线约束

- 正式源码只保留 TypeScript / TSX 文件。
- 脚手架或转译过程中遗留的同名 `.js` 副本必须移出主源码目录，统一归档到 `归档/`。
- 测试、构建、联调全部以 TypeScript 源码为唯一基线。
