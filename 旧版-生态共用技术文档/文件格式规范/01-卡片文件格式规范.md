# 卡片文件格式规范

**版本**: 1.1.0  
**更新时间**: 2026-08-05
**状态**: 正式版

---

## 1. 文件格式概述

### 1.1 文件本质

卡片文件(`.card`)的本质是一个ZIP压缩包,后缀名改为`.card`。

- **压缩算法**: ZIP存储模式(零压缩率, Store)
- **编码**: UTF-8
- **文件扩展名**: `.card`
- **MIME类型**: `application/x-card`（客户端传输链路正式 MIME 为 `application/vnd.chips.card+zip`）

### 1.2 零压缩率说明

使用ZIP存储模式而不压缩的原因:
- 最快的文件访问速度
- 简化解析流程
- 支持随机访问
- 文件体积影响可以忽略(多数资源已压缩)
- 社区上传、网页查看、客户端下载恢复链路要求 ZIP 条目字节不二次变换，Store 模式是完整恢复一致性的前提

`.card` 的 ZIP 条目必须使用 Store 模式。任何客户端在发布或下载 .card 前都必须校验条目压缩方式；发现 Deflate 等压缩条目时应按规范转换为 Store 模式，或提示该文件不符合正式格式要求。

### 1.3 文件识别

操作系统文件关联:
- 双击`.card`文件 → 自动用卡片查看器打开
- 修改扩展名为`.zip` → 可用任何解压工具打开查看内部结构

### 1.4 卡片类型

`.card` 存在两种正式形态，二者都是正常 `.card` 文件类型，不是临时产物：

| 类型 | 资源位置 | 配置中的资源字段 | 典型用途 |
| --- | --- | --- | --- |
| 完整离线卡片 | 资源字节保存在 ZIP 内部 | 卡片根相对路径 | 制作、编辑、备份、离线分享、客户端下载结果 |
| 网络资源卡片 | 资源不在 ZIP 内部 | 对象存储/CDN URL | 社区发布、网页查看、弱服务器分发 |

两种类型共享相同的配置结构（`.card/metadata.yaml`、`.card/structure.yaml`、`.card/cover.html`、`content/*.yaml`）。区别只在于资源字段的取值形式：完整离线卡片写相对路径并在 ZIP 内保存资源字节；网络资源卡片写对象存储/CDN URL，ZIP 内不保存这些资源字节。

## 1A. 完整离线卡片与网络资源卡片

### 1A.1 完整离线卡片

完整离线卡片是用户制作、编辑、备份和本地保存时最常见的卡片形态。

特征：

- 资源文件保存在 `.card` ZIP 内部；
- 配置文件和封面 HTML 中的资源引用使用卡片根相对路径；
- 不依赖网络即可查看和编辑；
- 适合本地备份、离线分享和继续编辑。

```
offline.card (ZIP Store)
├── .card/
│   ├── metadata.yaml
│   ├── structure.yaml
│   └── cover.html
├── content/
│   └── a1B2c3D4e5.yaml
├── video.mp4
├── image.jpg
└── cover-assets/cover.png
```

### 1A.2 网络资源卡片

网络资源卡片是正式 `.card` 文件类型，不是社区内部临时发布产物，也不是“空壳”占位。

特征：

- `.card` 中保留 `.card/metadata.yaml`、`.card/structure.yaml`、`.card/cover.html` 和 `content/*.yaml` 等配置与封面文件；
- 资源文件不放在 ZIP 内；
- 配置文件与封面 HTML 中的资源字段记录对象存储/CDN URL；
- 必须依赖网络资源才能完整查看；
- 适合社区发布、网页查看和弱服务器分发。

```
network.card (ZIP Store)
├── .card/
│   ├── metadata.yaml
│   ├── structure.yaml
│   └── cover.html        # 封面引用对象存储 URL
├── content/
│   └── a1B2c3D4e5.yaml   # 资源字段引用对象存储 URL
└── （无外置资源文件）
```

网络资源卡片可以长期保存并被查看器直接打开。所有基础卡片插件必须正式支持 URL 资源，不应把 URL 当作社区临时补丁。

### 1A.3 上传与下载的可逆转换

上传会把相对路径改写成 URL，下载时又要还原为原始路径，因此必须保存“可逆恢复清单”（restore manifest）。

转换关系：

```
完整离线卡片 --上传--> 网络资源卡片 + 对象存储资源 + 恢复清单
网络资源卡片 + 对象存储资源 + 恢复清单 --下载--> 完整离线卡片
```

恢复清单至少记录：

- 原始卡片版本 ID；
- 网络资源卡片对象位置；
- 每个资源的原始相对路径；
- 每个资源上传后的对象键；
- 每个资源写入网络资源卡片后的 URL；
- 每个配置文件中发生过的路径替换位置或可验证替换规则；
- 原始 ZIP 条目顺序；
- 原始 ZIP 条目 Store 模式；
- 原始 ZIP 条目修改时间；
- 原始 ZIP 条目外部属性、注释和必要的 extra fields；
- 原始资源文件名、大小和 MIME；
- 封面资源的原始引用和 URL 替换关系。

客户端统一卡片传输模块负责上传时 URL 改写与下载时 URL 恢复，插件不得自行替换 YAML 或 HTML 中的资源字段。

### 1A.4 完整恢复验收标准

下载得到的完整离线卡片应尽可能与上传前一致：

- 文件路径一致；
- 配置内容一致（URL 恢复为原始相对路径，资源字段语义逐字段还原；YAML 经解析→重写再序列化时允许格式化归一，如注释、空行、键序和引号风格可能变化，但不得改变字段语义与资源路径）；
- 资源字节一致；
- ZIP Store 条目顺序一致；
- ZIP 条目修改时间一致；
- ZIP 条目 Store 模式一致；
- 封面 HTML 和封面资源恢复一致；
- 下载结果能被正式 Host 打开、渲染和继续编辑。

说明：网络资源卡片生成与下载恢复都会对 YAML 做解析再序列化（`parse -> 改写 -> stringify`），因此字节级“配置文本不变”不保证。验收以“字段语义与资源引用一致”为准，不以配置文本逐字节相同为准。

### 1A.5 网络资源卡片校验规则

网络资源卡片是正式格式，校验规则如下：

- 配置文件允许 URL 资源字段（`source: url` / `url: https://...`）；
- 本地资源文件可以不存在（ZIP 内不要求包含外置资源字节）；
- URL 必须来自正式上传结果（对象存储/CDN 地址），不允许引用任意不可信地址；
- `.card/metadata.yaml`、`.card/structure.yaml`、`.card/cover.html` 和 `content/*.yaml` 必须存在。

## 2. 目录结构

### 2.1 根目录结构

```
card-example.card (ZIP压缩包)
│
├── .card/                    # 核心配置目录(隐藏文件夹)
│   ├── metadata.yaml         # 卡片元数据
│   ├── structure.yaml        # 卡片结构定义
│   ├── cover.html            # 封面HTML
│   └── cardcover/            # 封面资源(可选)
│       ├── cover-image.jpg
│       └── cover-style.css
│
├── content/                  # 基础卡片配置目录
│   ├── a1B2c3D4e5.yaml      # 基础卡片配置文件
│   ├── f6G7h8I9j0.yaml      # 基础卡片配置文件
│   └── ...
│
├── video.mp4                 # 资源文件(根目录)
├── image.jpg                 # 资源文件(根目录)
├── subtitle-zh.srt          # 资源文件(根目录)
├── nested-card.card         # 嵌套的复合卡片(可选)
└── ...
```

### 2.2 文件组织原则

1. **配置集中**: 所有配置文件在`.card/`文件夹
2. **内容扁平**: 基础卡片配置在`content/`目录,不使用子文件夹
3. **资源根放**: 所有资源文件直接放在根目录,不分类
4. **隐藏配置**: `.card/`文件夹为隐藏文件夹(Unix/Linux标准)

补充正式约束:
- 基础卡片配置中记录的卡片内部资源路径,统一相对于卡片根目录;
- 官方资源导入与保存链路必须把内部资源写入卡片根目录,不得写入`content/`或其他临时目录;
- 运行时生成的`blob:`、`data:`、系统绝对路径不得写回正式内容配置。

## 3. 元数据文件 (metadata.yaml)

### 3.1 完整Schema定义

```yaml
# JSON Schema for metadata.yaml
$schema: "http://json-schema.org/draft-07/schema#"
title: "Card Metadata Schema"
type: object
required:
  - chip_standards_version
  - card_id
  - name
  - created_at
  - modified_at
  
properties:
  # === 基础信息 ===
  chip_standards_version:
    type: string
    pattern: '^\d+\.\d+\.\d+$'
    description: "薯片标准版本号"
    example: "1.0.0"
    
  card_id:
    type: string
    pattern: '^[0-9a-zA-Z]{10}$'
    description: "卡片唯一ID,10位62进制编号"
    example: "a1B2c3D4e5"
    
  name:
    type: string
    maxLength: 500
    description: "卡片名称,最长500字符"
    example: "我的学习笔记"
    
  created_at:
    type: string
    format: date-time
    description: "创建时间,ISO 8601格式,UTC时区"
    example: "2026-01-15T08:00:00.000Z"
    
  modified_at:
    type: string
    format: date-time
    description: "最后修改时间"
    example: "2026-01-30T10:30:00.000Z"
    
  # === 主题设置 ===
  theme:
    type: string
    description: "主题包标识,格式: '发行商:主题包名称'"
    default: ""
    example: "薯片官方:默认主题"

  cover_ratio:
    type: string
    pattern: '^\d+(\.\d+)?:\d+(\.\d+)?$'
    description: "封面比例,使用宽:高字符串保存,默认3:4"
    default: "3:4"
    example: "3:4"
    
  # === 标签系统 ===
  tags:
    type: array
    description: "标签数组,支持简单标签和结构化标签"
    items:
      oneOf:
        - type: string
          description: "简单标签"
        - type: array
          items:
            type: string
          minItems: 2
          description: "结构化标签,第一个元素为键,后续为值"
    examples:
      - ["动漫"]
      - ["时间戳", "15:20"]
      - ["地点", "日本", "东京"]
      - ["项目", "网站改版"]
      
  # === 可选扩展属性 ===
  visibility:
    type: string
    enum: ["public", "private", "unlisted"]
    default: "private"
    description: "可见性设置"
    
  downloadable:
    type: boolean
    default: true
    description: "是否允许下载"
    
  remixable:
    type: boolean
    default: true
    description: "是否允许二次创作"
    
  commentable:
    type: boolean
    default: true
    description: "是否允许评论"
    
  license:
    type: string
    description: "许可证类型"
    examples: ["CC-BY-4.0", "CC-BY-NC-4.0", "All Rights Reserved"]
    
  age_rating:
    type: string
    enum: ["all", "pg", "pg13", "r", "nc17"]
    description: "年龄分级"
    
  content_warning:
    type: array
    items:
      type: string
    description: "内容警告标签"
    examples: [["violence", "adult_content"]]
    
  # === 文件信息(系统自动生成) ===
  file_info:
    type: object
    properties:
      total_size:
        type: integer
        description: "卡片总大小(字节)"
      file_count:
        type: integer
        description: "文件总数"
      checksum:
        type: string
        description: "完整性校验值,SHA256"
        example: "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
      generated_at:
        type: string
        format: date-time
        description: "文件信息生成时间"
```

### 3.2 完整示例

```yaml
# metadata.yaml 示例

# 基础信息
chip_standards_version: "1.0.0"
card_id: "a1B2c3D4e5"
name: "日本旅行 2026"
created_at: "2026-01-15T08:00:00.000Z"
modified_at: "2026-01-30T10:30:00.000Z"

# 主题设置
theme: "薯片官方:默认主题"
cover_ratio: "3:4"

# 标签系统
tags:
  - "旅行"
  - ["地点", "日本", "东京"]
  - ["时间", "2026年", "一月"]
  - ["类型", "个人记录"]
  - ["评分", "五星"]

# 可选属性
visibility: "public"
downloadable: true
remixable: true
commentable: true
license: "CC-BY-4.0"
age_rating: "all"
content_warning: []

# 文件信息(系统生成)
file_info:
  total_size: 52428800
  file_count: 15
  checksum: "a3f5c9b1e4d2f8a7b6c5d4e3f2a1b0c9d8e7f6a5b4c3d2e1f0"
  generated_at: "2026-01-30T10:30:00.000Z"
```

### 3.3 字段说明

**用户数据 vs 系统数据**:
- 用户使用数据(观看进度、浏览历史、收藏状态等)不保存在卡片文件中
- 这些数据保存在查看器/编辑器的本地数据库中
- 卡片文件只包含内容本身的信息

## 4. 结构文件 (structure.yaml)

### 4.1 完整Schema定义

```yaml
# JSON Schema for structure.yaml
$schema: "http://json-schema.org/draft-07/schema#"
title: "Card Structure Schema"
type: object
required:
  - structure
  - manifest

properties:
  # === 结构定义 ===
  structure:
    type: array
    description: "基础卡片列表,按渲染顺序排列"
    items:
      type: object
      required:
        - id
        - type
      properties:
        id:
          type: string
          pattern: '^[0-9a-zA-Z]{10}$'
          description: "基础卡片ID,对应content/目录下的配置文件"
        type:
          type: string
          description: "基础卡片类型,决定使用哪个渲染器"
          examples: ["VideoCard", "ImageCard", "RichTextCard", "MarkdownCard"]
          
  # === 清单索引 ===
  manifest:
    type: object
    description: "文件清单和元信息,用于快速索引和完整性验证"
    required:
      - card_count
      - resource_count
    properties:
      card_count:
        type: integer
        description: "基础卡片数量"
        
      resource_count:
        type: integer
        description: "资源文件数量"
        
      resources:
        type: array
        description: "资源文件清单"
        items:
          type: object
          required:
            - path
            - size
            - type
          properties:
            path:
              type: string
              description: "资源文件相对路径"
            size:
              type: integer
              description: "文件大小(字节)"
            type:
              type: string
              description: "文件MIME类型"
            duration:
              type: number
              description: "时长(秒),仅视频/音频文件"
            width:
              type: integer
              description: "宽度(像素),仅图片/视频文件"
            height:
              type: integer
              description: "高度(像素),仅图片/视频文件"
            language:
              type: string
              description: "语言代码,仅字幕文件"
            checksum:
              type: string
              description: "文件SHA256校验值"
```

### 4.2 完整示例

```yaml
# structure.yaml 示例

structure:
  - id: "a1B2c3D4e5"
    type: "RichTextCard"
    
  - id: "f6G7h8I9j0"
    type: "VideoCard"
    
  - id: "k1L2m3N4o5"
    type: "ImageCard"
    
  - id: "p6Q7r8S9t0"
    type: "MarkdownCard"

manifest:
  card_count: 4
  resource_count: 5
  
  resources:
    - path: "intro.rtf"
      size: 2048
      type: "application/rtf"
      
    - path: "travel-video.mp4"
      size: 52428800
      type: "video/mp4"
      duration: 180.5
      width: 1920
      height: 1080
      checksum: "b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1"
      
    - path: "subtitle-zh.srt"
      size: 8192
      type: "application/x-subrip"
      language: "zh"
      
    - path: "photo.jpg"
      size: 1048576
      type: "image/jpeg"
      width: 3000
      height: 2000
      
    - path: "notes.md"
      size: 4096
      type: "text/markdown"
```

### 4.3 设计说明

**职责分离**:
- `structure.yaml`: 只负责结构关系和文件索引
- `content/*.yaml`: 负责具体内容配置
- `metadata.yaml`: 负责卡片自身元信息

## 5. 内容配置 (content/*.yaml)

### 5.1 通用字段

所有基础卡片配置文件都包含以下通用字段:

```yaml
# 通用字段Schema
type: object
required:
  - card_type
properties:
  card_type:
    type: string
    description: "基础卡片类型标识"
    
  theme:
    type: string
    description: "该卡片专属主题(可选),为空则使用上级主题"
    default: ""
    
  layout:
    type: object
    description: "布局参数"
    properties:
      height_mode:
        type: string
        enum: ["auto", "fixed"]
        default: "auto"
        description: "高度模式"
      fixed_height:
        type: integer
        description: "固定高度(像素),仅height_mode为fixed时有效"
      aspect_ratio:
        type: string
        description: "宽高比,格式: '宽:高'"
        examples: ["16:9", "4:3", "1:1"]
```

### 5.2 视频卡片配置

```yaml
# VideoCard配置Schema
$schema: "http://json-schema.org/draft-07/schema#"
title: "Video Card Config Schema"
type: object
required:
  - card_type
  - video_file

properties:
  card_type:
    const: "VideoCard"
    
  video_file:
    type: string
    description: "视频文件路径(相对于卡片根目录的正式资源路径)"
    examples: ["video.mp4", "travel/demo-video.mp4"]
    
  cover_image:
    type: string
    description: "封面图片路径(相对于卡片根目录的正式资源路径，可选)"

  subtitles:
    type: array
    description: "外挂字幕资源列表，可为空数组"
    items:
      type: object
      required:
        - id
        - file_path
      properties:
        id:
          type: string
          description: "字幕轨唯一标识"
        label:
          type: string
          description: "字幕轨展示名称，可选"
        language:
          type: string
          description: "BCP 47 语言标识，可选，如 zh-CN / en-US"
        kind:
          type: string
          enum: ["subtitles", "captions"]
          default: "subtitles"
          description: "字幕轨语义类型"
        file_path:
          type: string
          description: "字幕文件路径(相对于卡片根目录的正式资源路径)"
        default:
          type: boolean
          default: false
          description: "是否为默认字幕；同一视频卡片最多一个字幕轨为 true"

  playback:
    type: object
    description: "播放入口参数；播放器应用可按能力选择消费"
    properties:
      autoplay:
        type: boolean
        default: false
      loop:
        type: boolean
        default: false
      muted:
        type: boolean
        default: false
      playback_rate:
        type: number
        minimum: 0.25
        maximum: 4
        default: 1
      start_time:
        type: number
        minimum: 0
        default: 0

  video_title:
    type: string
    description: "视频标题，可选；填写后显示在封面下方"

  publish_time:
    type: string
    description: "发布时间，可选；填写后与创作者一起显示"
```

## 6. 封面文件 (cover.html)

### 6.1 封面HTML规范

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Card Cover</title>
  <style>
    /* 样式代码 */
    body {
      margin: 0;
      padding: 0;
      width: 100%;
      height: 100%;
      display: flex;
      align-items: center;
      justify-content: center;
    }
  </style>
</head>
<body>
  <!-- 封面内容 -->
  <div class="cover-container">
    <h1>卡片名称</h1>
  </div>
</body>
</html>
```

### 6.2 封面比例元数据

封面比例保存在 `metadata.yaml` 的 `cover_ratio` 字段中,格式为 `宽:高` 的正数比值字符串。

- 默认值: `3:4`
- 当前正式编辑器支持的预设比例:
  - `1:1`
  - `1:1.414`
  - `2:3`
  - `3:4`
  - `1:1.618`
  - `16:9`
  - `2:1`
  - `9:19.5`
  - `1.58:1`
- 横版通过交换宽高得到,例如 `3:4` 的横版保存为 `4:3`
- 运行时应按规范化后的字符串读取和回写 `cover_ratio`

### 6.3 正式显示链路

封面显示必须使用正式 Host + SDK 链路,不允许应用层自行拼接任意 HTML:

```text
card.renderCover({ cardFile })
  -> { view: { title, coverUrl, ratio? } }
  -> client.card.coverFrame.render({ cardFile })
  -> iframe(src = coverUrl, sandbox = "allow-scripts")
```

正式约束:

- `coverUrl` 必须指向受控的 `.card/cover.html` 入口
- `.card/cover.html` 中的相对路径相对于 `.card/` 目录解析,可继续引用 `.card/cardcover/*`
- 封面 iframe 内容完全由 `cover.html` 决定,Host/SDK 不自动注入主题系统、多语言系统或复合卡片壳层
- 应用层不得把封面内容改写为 `srcdoc` 或任意 HTML 字符串

### 6.4 封面创建方式

当前正式支持两种封面生成方式:

**方式1: 在线编辑 HTML 代码**
```
用户在编辑器中编写或粘贴 HTML
↓
系统直接保存到 .card/cover.html
```

**方式2: 上传图片并生成封面**
```
用户上传图片
↓
可按当前封面比例打开裁剪弹窗
↓
系统把生成图片保存到 .card/cardcover/
↓
系统生成引用该图片的 .card/cover.html
```

图片生成封面的正式 HTML 约定如下:

```html
<body
  data-chips-cover-mode="image"
  data-chips-cover-image-source="./cardcover/cover-image.ext"
>
  <img src="./cardcover/cover-image.ext" alt="" />
</body>
```

说明:

- `data-chips-cover-mode="image"` 用于标识该 `cover.html` 来自正式图片封面生成链路
- `data-chips-cover-image-source` 记录正式图片资源入口
- `cover-image.ext` 表示实际保存的图片扩展名；未裁剪时会尽量保留原始类型，裁剪输出当前正式实现固定为 PNG
- 生成的图片封面默认使用 `img { object-fit: cover; }`
- `.card/cardcover/` 是封面专用资源目录；编辑器保存封面时应以 `.card/cover.html` 中仍被 `src`、`href`、`poster`、`data-chips-cover-image-source` 或 CSS `url(...)` 引用的相对路径为准，清理不再被引用的旧封面资源。
- `cover.html` 引用封面资源时必须使用 `.card/` 内部相对路径，例如 `./cardcover/cover-image.png` 或 `cardcover/cover-image.png`；不得把运行时 `blob:`、`data:` 或系统绝对路径作为封面资源路径写入正式文件。

### 6.5 正式支持边界

封面 HTML 在 iframe 中运行时,必须满足以下正式边界:

- 必须通过受控 `coverUrl` + `sandbox="allow-scripts"` 装载
- 正式支持的资源引用方式是访问 `.card/` 目录内的相对路径资源
- 封面文档不得依赖父窗口交互协议
- 封面文档不得把表单提交、弹窗或外部网络资源作为正式能力前提
- 应用层不得把封面文档当作同源 DOM 直接读取或挂接私有监听

### 6.6 默认封面

如果用户未设置封面,系统使用默认封面:

```html

<html lang="zh-CN">
<head>
  <meta charset="UTF-8">

    html, body { margin: 0; width: 100%; height: 100%; }
```

## 7. 资源组织模式

### 7.1 正式资源模式

卡片存在两种正式资源组织模式，分别对应完整离线卡片和网络资源卡片（见 1.4、1A 节）：

- **完整离线卡片**：内部资源写入卡片根目录，配置中的资源引用使用卡片根相对路径。Host、SDK、编辑器和基础卡片插件不得把运行时 `blob:`、`data:`、系统绝对路径或 `file://` URL 写回正式内容配置。
- **网络资源卡片**：资源字节不写入 ZIP，配置和封面中的资源字段记录对象存储/CDN URL。URL 必须来自正式上传结果，不得引用任意不可信地址。

```text
# 完整离线卡片
card.card (ZIP Store)
├── .card/
├── content/
├── video.mp4
├── image.jpg
└── subtitle.srt

# 网络资源卡片
network.card (ZIP Store)
├── .card/
├── content/          # 资源字段为对象存储/CDN URL
└── （无外置资源字节）
```

“空壳卡片”“半空壳卡片”这些旧术语不再使用，正式名称为“网络资源卡片”，是正常 `.card` 文件类型，不是社区内部临时产物。资源字段能同时识别相对路径和 URL 两种形态：完整离线卡片用相对路径 + 内置资源，网络资源卡片用 URL + 外部资源。

### 7.2 资源路径格式

**相对路径**(资源在卡片内部, 完整离线卡片):
```yaml
video_file: "video.mp4"
file_path: "cover.png"
```

**对象存储/CDN URL**(网络资源卡片):
```yaml
source: "url"
url: "https://file.example/chips-card-resources/cards/.../video.mp4"
```

**禁止作为内部资源写回的路径**：

```yaml
video_file: "/Users/username/Videos/video.mp4"
video_file: "C:\\Users\\username\\Videos\\video.mp4"
video_file: "file:///Users/username/Videos/video.mp4"
video_file: "blob:https://example.invalid/..."
video_file: "data:video/mp4;base64,..."
```

**外部 URL**：

```yaml
source_url: "https://example.com/videos/video.mp4"
```

外部 URL 只有在对应基础卡片插件 schema 明确支持时才允许出现，并且不能伪装成卡片内部资源路径。网络资源卡片中的资源 URL 必须来自正式上传结果。

### 7.3 嵌套卡片访问

嵌套卡片不是第一版内部资源访问模型。若卡片根目录中保存 `.card` 文件，它只是一个资源文件或由具体基础卡片 schema 定义的引用对象，不会被通用路径解析器自动当作目录展开。

```
card-parent.card
├── nested.card
└── other-file.jpg
```

### 7.4 资源缺失处理

当资源缺失时:

1. **卡片仍可打开**: 不会因为资源缺失而无法打开
2. **显示占位符**: 缺失的资源位置显示占位图和提示
3. **重新绑定**: 用户可以在设置中重新指定资源路径
4. **下载选项**: 如果资源有网络备份,提供下载选项

## 8. 文件命名规范

### 8.1 命名规则

1. **编码**: 使用UTF-8编码,支持中文文件名
2. **特殊字符**: 避免使用 `< > : " / \ | ? *`
3. **扩展名**: 使用小写(`.mp4`而非`.MP4`)
4. **空格**: 建议使用连字符`-`或下划线`_`代替空格
5. **长度**: 文件名建议不超过255字符

### 8.2 配置文件命名

```
content/目录:
  - 文件名格式: {10位62进制ID}.yaml
  - 示例: a1B2c3D4e5.yaml
  - 字符集: 0-9, a-z, A-Z
```

### 8.3 资源文件命名

**保留原名**: 用户导入的文件保留原文件名
```
用户导入 "my-video.mp4" → 保存为 "my-video.mp4"
```

**自动命名**: 编辑器创建的新内容使用卡片名称
```
卡片名: "旅行日记"
创建视频 → 保存为 "旅行日记-视频.mp4"
创建图片 → 保存为 "旅行日记-图片.jpg"
```

**冲突处理**: 文件名冲突时自动添加编号
```
photo.jpg        (第1个)
photo-2.jpg      (第2个)
photo-3.jpg      (第3个)
```

### 8.4 路径分隔符

**统一使用正斜杠**:
```yaml
# 正确
path: "folder/subfolder/file.jpg"

# 错误(Windows风格,不跨平台)
path: "folder\\subfolder\\file.jpg"
```

## 9. 版本兼容

### 9.1 版本号字段

```yaml
# metadata.yaml
chip_standards_version: "1.0.0"
```

### 9.2 版本演进策略

**主版本号变更** (1.x.x → 2.x.x):
- 不兼容的格式变更
- 查看器需要专门适配
- 提供格式转换工具

**次版本号变更** (1.0.x → 1.1.x):
- 向后兼容的功能新增
- 旧查看器可以忽略新字段
- 新查看器兼容旧格式

**修订号变更** (1.0.0 → 1.0.1):
- 向后兼容的问题修正
- 不影响文件格式
- 完全兼容

### 9.3 兼容性检查

查看器打开卡片时:

```javascript
// 伪代码
function checkCompatibility(cardVersion, viewerVersion) {
  const [cardMajor, cardMinor] = cardVersion.split('.');
  const [viewerMajor, viewerMinor] = viewerVersion.split('.');
  
  if (cardMajor !== viewerMajor) {
    return 'INCOMPATIBLE'; // 主版本不同,不兼容
  }
  
  if (parseInt(cardMinor) > parseInt(viewerMinor)) {
    return 'PARTIAL'; // 卡片版本更新,可能有未知字段
  }
  
  return 'COMPATIBLE'; // 完全兼容
}
```

## 10. 完整性验证

### 10.1 校验流程

打开卡片文件时:

1. **ZIP完整性**: 验证ZIP文件是否损坏
2. **必需文件**: 检查必需文件是否存在
3. **YAML格式**: 验证YAML文件格式正确性
4. **Schema验证**: 检查字段是否符合Schema定义
5. **资源清单**: 对比manifest中的资源是否存在
6. **校验值**: 可选,验证文件SHA256校验值

### 10.2 修复策略

**自动修复**:
- 缺少默认值的字段自动补充
- 错误的enum值修正为默认值

**提示修复**:
- 缺少必需文件时提示用户
- 资源缺失时提示重新绑定

**拒绝打开**:
- ZIP文件严重损坏
- metadata.yaml格式完全错误

## 11. 安全性

### 12.1 路径遍历防护

防止恶意路径访问父目录:

```
禁止的路径:
- ../../../etc/passwd
- ..\..\..\windows\system32

允许的路径:
- video.mp4
- folder/video.mp4
```

### 12.2 文件大小边界

生态不设置人为的“最大卡片安全上限”。真实实现只受平台、对象存储、磁盘和防攻击策略约束：

- ZIP 自身技术边界（如 4GB 上限需要 ZIP64 扩展，当前 Store 模式实现暂不支持时如实报错）；
- 对象存储单对象大小限制；
- 客户端磁盘可用空间；
- 反恶意文件保护（ZIP bomb、路径穿越、磁盘写满、异常条目）。

限制应来自真实平台能力和安全防护，而不是产品上的随意上限。

### 12.3 内容安全

- HTML封面: 通过正式 `card.renderCover` / `coverFrame.render` 链路加载到受控 iframe
- JavaScript: 仅在封面 iframe 内部运行,不作为生态正式对外接口
- 外部资源: 不属于正式支持范围,兼容性不做保证
