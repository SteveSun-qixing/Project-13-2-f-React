# 万能文件处理协议

> **版本**：v1.0
> **状态**：正式版
> **适用范围**：所有文件处理相关的应用插件、模块插件、Host 服务与生态共用 SDK
> **更新日期**：2026-09-03
> **取代**：原 `office.document.*` 链路（详见《迁移指南/office-to-file-migration.md》）

---

## 1. 文档定位

本文档定义薯片生态统一的万能文件处理链路，替代原有的 `office.document.*` 链路，提供一套覆盖所有文件类型的通用文件处理能力，是 `file.*` 路由、SDK 类型封装 `Chips-SDK/src/contracts/file.ts` 与 `api/file.ts`、Host file 服务实现以及应用/模块/资源处理器能力声明的共同对外口径。

### 1.1 设计背景

原有 `office.document.*` 链路仅针对办公文档（Word、Slide、Sheet、PDF），存在以下问题：

1. **范围局限**：无法覆盖图片、视频、代码、压缩包、电子书等其他常见文件类型；
2. **链路分叉**：办公文档与其他文件使用不同的处理路径与错误码，增加复杂度；
3. **扩展困难**：新增文件类型需要修改多个链路与处理器实现；
4. **与 `resource.open` 重复**：跨应用资源转交与会话编辑逻辑互相覆盖，缺少清晰职责划分。

### 1.2 设计目标

1. **统一入口**：`file.*` 命名空间作为唯一的文件处理入口；
2. **万能支持**：支持任意文件类型（文档、图片、视频、音频、代码、压缩包、电子书等）；
3. **协议标准化**：统一的读写、转换、预览、对比、编辑与版本管理接口；
4. **可扩展性**：新文件类型只需声明能力，无需修改 Host 路由；
5. **生态一致性**：与 `resource.open`、`card.*`、`box.*` 保持清晰的职责划分（详见《10-资源打开契约.md》第 10 节）；
6. **严格路由**：所有调用方必须经由 Host 内核路由，SDK 通过 `client.invoke('file.*')` 或 `window.chips.invoke('file.*')` 转发。

### 1.3 与 `office.document.*` 的关系

`office.document.*` 是已经冻结的历史链路。SDK 内部仍以兼容形式提供 `client.office.*`，但所有新插件、新 Host 服务与新模块插件必须使用 `file.*`，详见《生态共用技术文档/迁移指南/office-to-file-migration.md》。

## 3. 核心接口设计

### 3.1 文件会话接口

文件会话是文件处理的核心抽象，提供有状态、原子化的文件读写能力。所有编辑型应用（Word/Sheet/Slide/代码编辑器、PDF 查看器等）都应基于会话操作文件。

#### 3.1.1 会话描述符

```ts
interface FileSessionDescriptor {
  sessionId: string;
  documentId: string;
  filePath: string;
  fileName: string;
  format: FileFormat;
  mimeType: string;
  size: number;
  revision: number;
  status: FileSessionStatus;  // "clean" | "dirty" | "watching" | "closed"
  createdAt: string;
  updatedAt: string;
}
```

#### 3.1.2 创建会话

```ts
interface FileSessionCreateRequest {
  format?: FileFormat;
  fileName?: string;

    mimeType?: string;

  };
}
```

#### 3.1.3 打开会话


### 3.7 处理器匹配结果

```ts
interface FileHandlerCapability {
  kind: "file-handler";
  action: "view" | "edit" | "convert" | "preview" | "compare" | "metadata";
  target: string;           // 精确 MIME / 主类型通配 / 扩展名 / "*"
  tier: "primary" | "fallback";
}

interface FileHandlerResolution {
  capability: FileHandlerCapability;
  matchedBy: "exact-mime" | "wildcard-mime" | "extension" | "wildcard" | "user-default";
  pluginId: string;
  pluginName?: string;
  isPreferred: boolean;
}
```

`FileHandlerResolution` 是 Host 在执行 `resource.open`、会话入口与 `file.preview.generate` 等动作时返回给 SDK 的诊断信息，可用于日志、错误提示以及"已在设置面板修改默认查看器"等提示。

## 4. 能力声明

### 4.1 处理器能力声明格式

应用插件如果需要参与万能文件处理链路的处理、转换或预览，必须在 `manifest.yaml` 的 `capabilities` 中声明 `file-handler` 能力串：

```yaml
capabilities:
  - file-handler:view:application/pdf
  - file-handler:edit:application/pdf
  - file-handler:preview:application/pdf
  - file-handler:convert:application/pdf->image/png

  # MIME 类型通配
  - file-handler:view:image/*
  - file-handler:view:video/*

  # 扩展名声明
  - file-handler:.pdf
  - file-handler:.docx

  # 兜底层级
  - file-handler:view:*@fallback
```

### 4.2 能力格式规范

```
file-handler:<action>:<mime-or-ext>[@tier]
```

| 组成部分 | 说明 | 示例 |
|---|---|---|
| `file-handler` | 固定前缀 | `file-handler` |
| `<action>` | 操作类型 | `view`、`edit`、`convert`、`preview`、`compare`、`metadata` |
| `<mime-or-ext>` | MIME 类型或扩展名 | `application/pdf`、`.pdf`、`image/*`、`*` |
| `[@tier]` | 可选层级后缀 | 省略表示 `primary`，`@fallback` 表示兜底 |

### 4.3 操作类型与权限

| 操作类型 | 说明 | 权限要求 |
|---|---|---|
| `view` | 查看/预览文件 | `file.read` |
| `edit` | 编辑文件内容 | `file.write` |
| `preview` | 生成预览/缩略图 | `file.read` |
| `convert` | 格式转换 | `file.read`、`file.write` |
| `compare` | 文件对比 | `file.read` |
| `metadata` | 读取/修改元数据 | `file.read` / `file.write` |

### 4.4 层级后缀

| 层级 | 说明 | 使用场景 |
|---|---|---|
| 省略（默认） | `primary` 专用处理器 | 图片查看器、视频播放器、办公编辑器等专用处理器 |
| `@fallback` | `fallback` 通用兜底 | 通用文件查看器（如 `com.chips.universal-file-viewer`）等兜底应用 |

约束：除 `@fallback` 外不允许其他 `@` 后缀；携带未知后缀的声明视为非法能力串，Host 解析时直接忽略。`plugin.query({ capability })` 与 `plugin.listHandlers` 按归一化能力串匹配（剥离层级后缀）。

### 4.5 转换能力声明

转换能力需要声明源格式和目标格式：

```yaml
capabilities:
  # PDF 转图片
  - file-handler:convert:application/pdf->image/png
  - file-handler:convert:application/pdf->image/jpeg

  # 文档转 PDF
  - file-handler:convert:application/vnd.openxmlformats-officedocument.wordprocessingml.document->application/pdf

  # 图片格式互转
  - file-handler:convert:image/webp->image/png
  - file-handler:convert:image/png->image/jpeg
```

源/目标两端支持精确 MIME、主类型通配（如 `image/*`）或扩展名（如 `.docx`）。两端必须同时具备可识别的格式信息，否则视为非法能力串。

### 4.6 能力匹配规则

1. **用户默认处理器偏好优先**：Host 配置 `fileOpen.defaults` 中存在当前请求命中的偏好键时，优先使用用户设置的默认处理器（详见《10-资源打开契约.md》第 4.5 节）；
2. **精确匹配优先**：精确 MIME > 主类型通配 > 扩展名 > 全局通配；
3. **专用处理器优先**：同类型能力中，`primary` 层级优先于 `fallback` 层级；
4. **安装顺序**：同层级按插件安装顺序；
5. **操作类型优先**：同格式的情况下，`edit` > `view` > `preview`。

### 4.7 与 `resource-handler` 的关系

- `file-handler`：万能文件处理链路专用能力声明，由 Host 在 `file.session.*` / `file.preview.*` / `file.convert.*` 等动作内部消费；
- `resource-handler`：资源打开路由的能力声明，由 Host 在 `resource.open` 中消费；
- 两者可以同时声明，Host 会按调用链路选择匹配的能力。详细关系见《10-资源打开契约.md》第 10 节。

### 5.3 会话生命周期

```
create/open → read/write → persist → close
```

- `create`：在工作区创建新文件并建立会话；
- `open`：从指定路径打开文件并建立会话；
- `read`：读取会话的全部或部分内容；
- `write`：修改会话内容（默认替换全部内容；传 `offset` 时为区间写入）；
- `persist`：将内存内容写回磁盘或指定路径；
- `close`：关闭会话，释放资源。

**状态转换**：

```
clean → dirty（write 后）
dirty → clean（persist 后）
any   → closed（close 后）
```

## 6. 错误处理

### 6.1 错误码规范

| 前缀 | 含义 | 示例 |
|---|---|---|
| `FILE_SESSION_*` | 文件会话错误 | `FILE_SESSION_NOT_FOUND`、`FILE_SESSION_CLOSED` |
| `FILE_CONTENT_*` | 文件内容错误 | `FILE_CONTENT_INVALID`、`FILE_CONTENT_TOO_LARGE` |
| `FILE_FORMAT_*` | 文件格式错误 | `FILE_FORMAT_UNSUPPORTED`、`FILE_FORMAT_MISMATCH` |
| `FILE_CONVERT_*` | 转换错误 | `FILE_CONVERT_FAILED`、`FILE_CONVERT_OUTPUT_EXISTS` |
| `FILE_COMPARE_*` | 对比错误 | `FILE_COMPARE_FAILED` |
| `FILE_PREVIEW_*` | 预览错误 | `FILE_PREVIEW_FAILED`、`FILE_PREVIEW_UNSUPPORTED` |
| `FILE_HANDLER_*` | 处理器错误 | `FILE_HANDLER_MISSING` |
| `FILE_WATCH_*` | 监听错误 | `FILE_WATCH_TIMEOUT` |

完整错误码常量见 `FILE_ERROR_CODES`（`Chips-SDK/src/contracts/file.ts`）。所有错误均归一化为 `StandardError`（见《Chips-SDK/src/types/errors.ts》）。

### 6.2 典型错误处理建议

| 错误码 | 说明 | 处理建议 |
|---|---|---|
| `FILE_SESSION_NOT_FOUND` | 会话不存在 | 重新创建或打开会话 |
| `FILE_SESSION_CLOSED` | 会话已关闭 | 检查 sessionId 是否仍在生命周期内 |
| `FILE_SESSION_DIRTY` | 会话有未保存修改 | 提示用户保存或显式放弃 |
| `FILE_CONTENT_INVALID` | 文件内容无效 | 重新选择或让用户回退到原文件 |
| `FILE_CONTENT_TOO_LARGE` | 文件过大 | 使用分块读写 |
| `FILE_FORMAT_UNSUPPORTED` | 格式不支持 | 提示用户安装对应处理器 |
| `FILE_CONVERT_FAILED` | 转换失败 | 检查源文件完整性与目标格式 |
| `FILE_CONVERT_OUTPUT_EXISTS` | 输出文件已存在 | 提示覆盖或换名 |
| `FILE_HANDLER_MISSING` | 无可用处理器 | 回退到万能文件查看器兜底 |
| `FILE_WATCH_TIMEOUT` | 监听超时 | 重新发起 `file.session.watch` |

## 8. 迁移策略

### 8.1 SDK 迁移步骤

1. 把 `import { createClient } from 'chips-sdk'` 与 `client.office.*` 替换为 `client.file.session.*` / `client.file.preview.*` / `client.file.convert.*` / `client.file.compare.*`；
2. 把 `sessionId` 字符串入参替换为 `{ sessionId }` 对象入参；
3. 把 `client.office.read(sessionId, options)` 的返回 `{ document, bytes }` 改为 `client.file.session.read({ sessionId, options })` 的返回 `{ sessionId, documentId, bytes, offset, length, totalSize, revision }`；
4. `client.office.persist(sessionId, filePath?)` 替换为 `client.file.session.persist({ sessionId, options: { filePath } })`；
5. 如果插件使用了文件类型检测，统一改为 `client.file.detect.detectType(path, options?)`。

完整迁移示例与映射表见《生态共用技术文档/迁移指南/office-to-file-migration.md》。

### 8.2 应用编辑器集成

| 编辑器 | 当前调用 | 目标调用 |
|---|---|---|
| Word 编辑器 | `client.office.create/open/read/write/persist/close` | `client.file.session.*` |
| Sheet 编辑器 | `client.office.*` | `client.file.session.*` |
| Slide 编辑器 | `client.resource.write` | `client.file.session.open/write/persist` |
| PDF 查看器 | `client.office.read` | `client.file.session.open/read` |

### 8.3 Host 服务兼容

Host 仍然挂载 `office.document.*` 服务并保留 `office-document-service` 包以提供历史兼容路径；所有新 Host 服务、新模块插件、新应用插件必须使用 `file.*` 路由。`office.*` 的废弃与最终移除时间见《迁移指南/office-to-file-migration.md》。

## 10. 实现约束

### 10.1 会话管理

1. **会话隔离**：每个会话独立管理文件状态，不得共享内部状态；
2. **资源清理**：会话关闭时必须释放所有相关资源；
3. **超时机制**：长时间未操作的会话应自动释放；
4. **并发控制**：同一文件的并发写入需要显式锁定；
5. **浏览器抽象**：所有文件系统动作必须经由 PAL `storage` 子域，浏览器/Desktop/Headless 各自实现对齐。

### 10.2 内存管理

1. **大文件处理**：超过阈值的大文件必须使用流式读写；
2. **内存限制**：单个会话的内存占用应有上限；
3. **分块读写**：支持按 `offset/length` 分块读取大文件；
4. **二进制传输**：Bridge 传输中的 Buffer、ArrayBuffer、Buffer JSON 必须由 SDK 归一化为 `Uint8Array`。

### 10.3 安全约束

1. **路径验证**：不得访问工作区外的文件路径；
2. **文件名清理**：新建文件时必须清理路径分隔符和控制字符；
3. **重名处理**：新建文件重名时自动分配 `-2`、`-3` 后缀；
4. **权限校验**：所有操作必须校验调用方权限（`file.read` / `file.write`）。

### 10.4 格式检测

1. **优先 Magic Number**：优先使用文件头检测格式，扩展名作为回退；
2. **MIME 推断**：Host 与 SDK 共用同一份 `MIME_BY_EXTENSION` 表，调用方不得维护私有表；
3. **未知格式**：无法识别的格式使用 `binary` 类型并通过 Host 兜底查看器渲染。

## 11. SDK 接口封装

### 11.1 类型与运行时分离

- 纯类型契约集中在 `Chips-SDK/src/contracts/file.ts`；
- 类型化运行时封装集中在 `Chips-SDK/src/api/file.ts`，按 `FileApi` 接口对外暴露：
  - `client.file.session.*`：会话管理；
  - `client.file.ops.*`：基础文件系统操作；
  - `client.file.detect.*`：类型检测；
  - `client.file.preview.*`：预览生成；
  - `client.file.convert.*`：格式转换；
  - `client.file.compare.*`：对比与版本差异；
  - `client.file.read/write/stat/list/mkdir/delete/move/copy/watch/detectType`：基础入口（向后兼容）。
- 兼容旧版入口：`client.office.*` 通过 SDK 兼容层转发到 `file.session.*`，详细迁移步骤见《迁移指南/office-to-file-migration.md》。

### 11.2 调用示例

```ts
import { createClient, FILE_ACTIONS } from 'chips-sdk';

const client = createClient();

// 1. 打开文档并建立会话
const session = await client.file.session.open({
  filePath: '/workspace/example.docx',
  format: 'docx',
  options: { readOnly: false, watch: true },
});

// 2. 读取会话内容
const read = await client.file.session.read({ sessionId: session.sessionId });
console.log(read.bytes.byteLength);

// 3. 写入修改
await client.file.session.write({
  sessionId: session.sessionId,
  bytes: modifiedBytes,
});

// 4. 持久化并关闭
await client.file.session.persist({ sessionId: session.sessionId });
await client.file.session.close({ sessionId: session.sessionId });

// 5. 生成预览
const preview = await client.file.preview.generate({
  filePath: '/workspace/example.pdf',
  options: { format: 'png', page: 1, thumbnail: true },
});

// 6. 格式转换
const converted = await client.file.convert({
  source: { filePath: '/workspace/example.docx' },
  target: { format: 'application/pdf' },
  output: { filePath: '/workspace/example.pdf' },

// 7. 文件对比
const diff = await client.file.compare({
  left: { filePath: '/workspace/a.txt' },
```
