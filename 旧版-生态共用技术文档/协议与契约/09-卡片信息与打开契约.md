# 卡片信息与打开契约

**版本**：1.0.0  
**更新时间**：2026-03-24  
**状态**：正式版

---

## 1. 文档定位

本文档定义整个生态统一使用的卡片信息中心与卡片打开动作。

核心原则：

1. 卡片信息统一由 Host `card.readInfo` 提供；
2. 卡片新窗口打开统一由 Host `card.open` 提供；
3. 箱子、资源管理器、选择器、查看器和编辑器都不应各自散落实现第二套卡片信息读取或打开逻辑。

---

## 2. `card.readInfo`

### 2.1 请求

```ts
type CardInfoField = 'status' | 'metadata' | 'cover';

interface CardReadInfoRequest {
  cardFile: string;
  fields?: CardInfoField[];
}
```

### 2.2 响应

```ts
interface CardReadInfoRouteResponse {
  info: CardReadInfoResult;
}

interface CardReadInfoResult {
  cardFile: string;
  info: {
    status?: {
      state: 'ready' | 'missing' | 'invalid';
      exists: boolean;
      valid: boolean;
      errors?: string[];
    };
    metadata?: {
      raw: Record<string, unknown>;
      chipStandardsVersion?: string;
      cardId?: string;
      name?: string;
      createdAt?: string;
      modifiedAt?: string;
      theme?: string;
      coverRatio?: string;
      tags?: Array<string | string[]>;
    };
    cover?: {
      title: string;
      resourceUrl: string;
      mimeType: 'text/html';
      ratio?: string;
    };
  };
}
```

### 2.3 正式要求

1. `metadata.raw` 是卡片元数据的正式原始视图；
2. `metadata.*` 归一字段用于生态通用消费；
3. `cover.resourceUrl` 必须是 Host 受控资源地址；
4. `cover.mimeType` 当前正式固定为 `text/html`，对应 `.card/cover.html`；
5. `fields` 为空时，Host 默认返回全部稳定字段。

## 3. `card.open`

### 3.1 请求

```ts
interface CardOpenRequest {
  cardFile: string;
}
```

### 3.2 响应

```ts
interface CardOpenResponse {
  result: {
    mode: 'card-window';
    windowId?: string;
    pluginId?: string;
  };
}
```

### 3.3 正式要求

1. Host 必须优先复用正式卡片查看器 / 应用插件文件处理能力；
2. 若当前环境没有专门处理器，Host 可以使用自身宿主窗口承载正式查看态；
3. 调用方不得自行假设具体查看器实现、窗口标题和打开参数；
4. `card.open` 是生态正式卡片打开入口，箱子 `box.openEntry` 应在本地卡片场景下复用它。

补充边界：

1. `card.open` 只负责“打开整张卡片”；
2. 若应用需要打开卡片内部的图片、附件或其他资源，应统一改走 `resource.open`；
3. 卡片查看器等容器不得把卡片内部资源点击继续硬编码进 `card.open`。

## 4. 卡片查看器启动来源契约

卡片查看器应用插件是卡片与箱子的统一查看入口。Host、社区服务器和其他宿主启动 `com.chips.card-viewer` 时，正式通过 `launchParams.cardSource` 描述来源，不再使用散落的 `targetPath`、`fileOpenMode` 或 `webDocumentUrl` 作为查看器正式入口。

正式来源结构：

```ts
type CardViewerSource =
  | { kind: "local-file"; documentKind: "card" | "box"; filePath: string }
  | {
      kind: "community-card";
      cardId: string;
      title: string;
      createdAt?: string;
      documentUrl: string;
      canonicalUrl?: string;
      coverUrl?: string;
      coverFragmentUrl?: string;
      coverRenderMode?: "fragment-shadow" | "iframe";
      coverRatio?: string;
    }
  | {
      kind: "community-box";
      boxId: string;
      title: string;
      createdAt?: string;
      documentUrl: string;
      canonicalUrl?: string;
      coverUrl?: string;
      coverFragmentUrl?: string;
      coverRenderMode?: "fragment-shadow" | "iframe";
      coverRatio?: string;
    }
  | { kind: "remote-card-file"; url: string; title?: string; createdAt?: string };
```

要求：

1. `local-file` 只能由具备本地文件访问能力的 Host 使用，查看器必须再通过 SDK / Host 正式文档窗口链路渲染；
2. `community-card` 与 `community-box` 必须提供宿主可直接 iframe 承载的 `documentUrl`；
3. `remote-card-file` 表示未来远程 `.card` 文件来源，查看器不得直接私自下载解析，应等待宿主或社区服务先解析为正式文档来源；
4. `card.open` 打开本地卡片时，Host 应优先启动卡片查看器并传入 `{ kind: "local-file", documentKind: "card", filePath }`；
5. 箱子文件关联和箱子条目打开本地箱子时，应传入 `{ kind: "local-file", documentKind: "box", filePath }`。
6. `community-card` 与 `community-box` 可携带封面 surface 字段，查看器用于在内容查看态与封面查看态之间切换；封面字段必须来自社区服务或 Host 受控产物，不得传入任意内联 HTML。
