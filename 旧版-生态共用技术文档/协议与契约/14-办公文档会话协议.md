# 办公文档会话协议

> **状态**：已废弃（Deprecated）  
> **适用范围**：历史遗留链路维护；当前 SDK 与 Host 仍保留兼容入口，但不再演进功能  
> **废弃日期**：2026-09-03  
> **迁移指引**：请使用《15-万能文件处理协议》中的 `file.session.*` 链路；完整迁移步骤见《生态共用技术文档/迁移指南/office-to-file-migration.md》

---

## 1. 废弃说明

本文档描述的 `office.document.*` 链路已被万能文件处理链路（`file.session.*`）替代。

### 1.1 废弃原因

1. **范围局限**：`office.document.*` 仅针对办公文档，无法覆盖图片、视频等其他文件类型
2. **链路分叉**：办公文档与其他文件使用不同处理路径，增加复杂度
3. **架构统一**：用户要求统一的 `file.*` 命名空间
4. **与正式架构方向不一致**：万能文件处理链路（`file.*`）是 vNext 冻结后的唯一正式入口

### 1.2 迁移策略

1. 当前版本同时保留 `office.document.*` 与 `file.session.*` 双链路；SDK 在 `Chips-SDK/src/api/office-document.ts` 中以独立路由调用的方式提供 `client.office.*` 兼容入口；
2. 所有新插件、新模块插件、新 Host 服务必须使用 `file.*`；
3. 应用编辑器按《迁移指南/office-to-file-migration.md》逐步替换调用方式；
4. 完整替换计划与里程碑由 Host 工程团队与生态发布团队约定，不在本协议文档中固化时间表。

## 2. 历史链路定义（仅供参考）

### 2.1 路由与权限

| 路由 | 权限 | 语义 |
| --- | --- | --- |
| `office.document.create` | `office.write` | 在工作区 `documents/` 中创建并落盘新文档会话 |
| `office.document.open` | `office.read` | 从 Host 路径读取原始字节并建立会话 |
| `office.document.read` | `office.read` | 读取完整或指定区间的会话字节 |
| `office.document.write` | `office.write` | 替换完整字节或按偏移更新内存会话字节并递增 revision |
| `office.document.get` | `office.read` | 获取会话描述符与状态 |
| `office.document.persist` | `office.write` | 将当前字节写回原路径或新路径 |
| `office.document.close` | `office.write` | 关闭会话；`persist=true` 时先保存脏数据 |

### 2.2 会话生命周期

`create/open -> read/write -> persist -> close`。`create` 会立即写入工作区，确保新建文档拥有可重新打开的文件路径；创建的空白 DOCX/PPTX/XLSX 是 ZIP Store 容器，PDF 具备最小 PDF 头尾。`write` 只改变会话内存，`persist` 才更新磁盘并将状态置为 `clean`。`write` 未传 `offset` 时替换完整文档；传入 `offset` 时才进行区间写入。

会话描述符包含 `sessionId/documentId/filePath/fileName/format/mimeType/size/revision/status/createdAt/updatedAt`。关闭后 sessionId 立即失效。Host 不提供隐式自动保存，应用编辑器按自身防抖策略调用 `persist`，这样可以复用编辑引擎的保存节奏并避免跨格式耦合。

### 2.3 字节与格式

- SDK `client.office.create/open/read/write/persist/close` 是唯一插件入口。
- `read` 返回 `Uint8Array`；Bridge 传输中的 Buffer、ArrayBuffer、Buffer JSON 由 SDK 归一化。
- `docm/dotx` 映射为 `docx`，`pptm/potx` 映射为 `pptx`，`xlsm/xltx` 映射为 `xlsx`；未知扩展名为 `binary`。
- Host 不信任插件提交的路径名。新建文件名只取 basename，并清理路径分隔符和控制字符；新建文件发生重名时自动分配 `-2`、`-3` 后缀。

### 2.4 失败处理

空路径、非法 session、非法偏移或非二进制 payload 返回标准错误。解析失败属于插件格式解析层错误；插件应在调用 `office.document.read` 后自行校验 ZIP/PDF 容器并向用户展示可操作的错误信息。

## 3. 迁移指南

### 3.1 路由映射

| 旧路由 | 新路由 |
|---|---|
| `office.document.create` | `file.session.create` |
| `office.document.open` | `file.session.open` |
| `office.document.read` | `file.session.read` |
| `office.document.write` | `file.session.write` |
| `office.document.get` | `file.session.get` |
| `office.document.persist` | `file.session.persist` |
| `office.document.close` | `file.session.close` |

### 3.2 SDK 迁移示例

**旧代码**：
```typescript
import { createClient } from 'chips-sdk';

const client = createClient();

// 创建文档会话
const doc = await client.office.create({
  format: 'pdf',
  fileName: 'document.pdf'
});

// 读取内容
const { bytes } = await client.office.read(doc.sessionId);

// 写入修改
await client.office.write(doc.sessionId, modifiedBytes);

// 保存并关闭
await client.office.persist(doc.sessionId);
await client.office.close(doc.sessionId);
```

**新代码**：
```typescript
import { createClient } from 'chips-sdk';

const client = createClient();

// 创建文件会话
const session = await client.file.session.create({
  format: 'pdf',
  fileName: 'document.pdf'
});

// 读取内容
const { bytes } = await client.file.session.read({
  sessionId: session.sessionId
});

// 写入修改
await client.file.session.write({
  sessionId: session.sessionId,
  bytes: modifiedBytes
});

// 保存并关闭
await client.file.session.persist({
  sessionId: session.sessionId
});
await client.file.session.close({
  sessionId: session.sessionId
});
```

### 3.3 新链路优势

| 特性 | `office.document.*` | `file.session.*` |
|---|---|---|
| 文件类型覆盖 | 仅办公文档 | 所有文件类型 |
| 命名空间 | 分散 | 统一 `file.*` |
| 转换能力 | 无 | `file.convert.*` |
| 预览能力 | 无 | `file.preview.*` |
| 对比能力 | 无 | `file.compare.*` |
| 扩展性 | 有限 | 完整 |

### 3.4 SDK 兼容入口（实际实现）

`Chips-SDK/src/api/office-document.ts` 仍然提供 `client.office.*` 兼容入口，但实现方式是**直连 `office.document.*` 路由**（不是把请求转发到 `file.session.*`），目的是在过渡期内为未迁移的存量代码保留可用调用面：

```typescript
// Chips-SDK/src/api/office-document.ts（节选）
export interface OfficeDocumentApi {
  create(input: { format: OfficeDocumentFormat; fileName?: string; initialBytes?: Uint8Array }): Promise<OfficeDocumentDescriptor>;
  open(input: { filePath: string; format?: OfficeDocumentFormat }): Promise<OfficeDocumentDescriptor>;
  read(sessionId: string, options?: { offset?: number; length?: number }): Promise<{ document: OfficeDocumentDescriptor; bytes: Uint8Array }>;
  write(sessionId: string, bytes: Uint8Array, options?: { offset?: number }): Promise<OfficeDocumentDescriptor>;
  get(sessionId: string): Promise<OfficeDocumentDescriptor>;
  persist(sessionId: string, filePath?: string): Promise<OfficeDocumentDescriptor>;
  close(sessionId: string, options?: { persist?: boolean }): Promise<void>;
}
```

约束：

1. 兼容入口不会把 `client.office.*` 调用映射为 `file.session.*`；两套链路在 Host 内并存；
2. 兼容入口只负责路由调用与二进制归一化，不维护"office 与 file 描述符互转"逻辑；
3. 新插件、新编辑器、新模块不得再使用 `client.office.*`；完整迁移步骤见《迁移指南/office-to-file-migration.md》。
