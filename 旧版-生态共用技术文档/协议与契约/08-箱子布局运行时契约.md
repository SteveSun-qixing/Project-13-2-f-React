# 箱子布局运行时契约

**版本**：1.1.0
**更新时间**：2026-08-11
**状态**：正式版

---

## 1. 文档定位

本文档定义 Host、查看器与布局插件在箱子消费阶段的正式运行时契约。

主旨只有一条：  
**布局插件负责前端页面，Host 负责数据与资源解析，双方通过会话化、按需、最小化的数据接口协作。**

---

## 2. 核心原则

1. **Host 唯一解析权**：URL 解析、凭证、缓存、失败状态归一都由 Host 负责；
2. **布局摘要优先**：布局插件默认先消费封面、名称、标签、摘要与状态；
3. **卡片信息中心唯一口径**：卡片详细信息统一来自 Host `card.readInfo` 模块，不再由箱子层散落拼装；
4. **Host 统一激活**：点击封面后是否打开新窗口、如何打开，统一由 Host `box.openEntry` 决定；
5. **按需取数**：不要求首屏返回全部卡片详细信息；
6. **会话隔离**：所有运行时读操作都必须绑定到 `sessionId`；
7. **最小暴露**：布局插件不直接拿到凭证和底层文件句柄；
8. **资源分层**：箱子自有资源与卡片资源严格分层。
9. **Host 统一装载布局插件**：布局插件查询、`layoutDefinition` 装载、配置归一/校验和查看/编辑文档生成都由 Host `box-service` 负责；
10. **应用只消费正式接口**：查看器、编辑引擎与其他应用只通过 Host `box.*` 动作或 SDK `client.box.* / client.document.window.*` 使用布局能力。
11. **完整内容仍由 Host 渲染**：布局需要展开卡片时，只能通过 `box.renderEntryDocument` 获取 Host 托管文档，不得把原始 `.card` 文件地址直接交给 iframe。

---

## 3. 角色边界

| 角色 | 职责 | 禁止事项 |
|---|---|---|
| Host | 解析 `.box`、维护会话、解析 URL、返回数据/资源 | 把所有卡片资源全量无差别灌给布局插件 |
| 布局插件 | 渲染页面、组织布局、按需申请资源 | 自行扫描磁盘、直接访问网络、直接读取凭证 |
| 查看器/应用插件 | 承载布局插件输出、管理窗口和页面 | 复制一套箱子资源解析逻辑、直接 import 布局插件构建产物 |

## 4. 会话模型

### 4.1 `box.openView`

打开箱子必须先创建查看会话。

#### 请求

```ts
interface BoxOpenViewRequest {
  boxFile: string;
  layoutType?: string;
  initialQuery?: BoxEntryQuery;
}
```

#### 响应

```ts
interface BoxOpenViewResponse {
  sessionId: string;
  box: BoxSessionInfo;
  initialView: BoxEntryPage;
}
```

#### 会话信息

```ts
interface BoxSessionInfo {
  boxId: string;
  boxFile: string;
  name: string;
  activeLayoutType: string;
  availableLayouts: string[];
  coverRatio?: string;
  tags?: Array<string | string[]>;
  coverAsset?: string;
  capabilities: {
    listEntries: true;
    readEntryDetail: true;
    renderEntryCover: true;
    renderEntryDocument: true;
    releaseEntryDocument: true;
    resolveEntryResource: true;
    readBoxAsset: true;
    prefetchEntries: true;
    openEntry: true;
  };
}
```

### 4.2 会话关闭

```ts
interface BoxCloseViewRequest {
  sessionId: string;
}
```

```ts
interface BoxCloseViewResponse {
  ack: true;
}
```

`box.closeView` 会先把当前箱子会话标记为关闭并阻止新操作，等待已经开始的条目文档渲染/释放操作结束，再兜底释放会话仍持有的全部条目文档子渲染会话，最后释放箱子解包目录。渲染结果即使晚于关闭请求返回，也必须先登记回原箱子会话并由关闭流程回收，不能成为无主子会话。布局仍应在切换条目或卸载子 iframe 时优先显式调用 `box.releaseEntryDocument`，不能只依赖兜底回收。

## 5. 摘要态条目模型

布局插件默认消费条目摘要页。

```ts
interface BoxEntrySnapshot {
  entryId: string;
  url: string;
  enabled: boolean;
  snapshot: {
    documentId?: string;
    title?: string;
    summary?: string;
    tags?: Array<string | string[]>;
    cover?: {
      mode: 'asset' | 'runtime' | 'none';
      assetPath?: string;
      mimeType?: string;
      width?: number;
      height?: number;
    };
    lastKnownModifiedAt?: string;
    contentType?: string;
  };
  layoutHints?: {
    sortKey?: string | number;
    aspectRatio?: number;
    group?: string;
    priority?: number;
  };
}
```

### 5.0 url 形态说明

条目 `url` 支持两种形态（与文件格式规范一致）：

1. **外部引用**：绝对 URL（`file://` / `http://` / `https://` / `webdav://`）；
2. **内嵌引用**：包内相对路径（不以 scheme 开头，以 `.card` 结尾），如 `cards/day-01.card`。

布局插件消费的是 Host 归一后的条目数据，无需感知 url 形态；Host 负责把内嵌条目解析为可消费的本地资源（封面、详情、打开均复用本地卡片链路）。

### 5.1 分页结果

```ts
interface BoxEntryPage {
  items: BoxEntrySnapshot[];
  total: number;
  nextCursor?: string;
}
```

### 5.2 查询结构

```ts
interface BoxEntryQuery {
  cursor?: string;
  limit?: number;
  filter?: Record<string, unknown>;
  sort?: {
    key: string;
    direction: 'asc' | 'desc';
  };
}
```

### 6.3 `box.renderEntryCover`

布局插件在需要显示条目正式封面时，应优先使用 `renderEntryCover`。

#### 请求

```ts
interface BoxRenderEntryCoverRequest {
  sessionId: string;
  entryId: string;
}
```

#### 响应

```ts
interface BoxRenderEntryCoverResponse {
  view: {
    title: string;
    coverUrl: string;
    mimeType: string;
    ratio?: string;
  };
}
```

说明：

- `title` 是封面显示链路返回的正式标题字段，供应用层、布局前端或封面组件外层 UI 使用；
- `coverUrl` 是 Host 托管的正式封面入口，Electron 桌面端可返回 `chips-render://...` 等受控协议地址；布局插件只能把它当作可直接挂载到 iframe 的文档 URL，不得转换为本地文件路径或自行读取封面 HTML；
- 若条目引用的是 `.box`，Host 必须继续复用目标箱子的 `.box/cover.html` 正式封面入口；
- 直接显示条目封面时，推荐把 `coverUrl/ratio/title` 交给正式 `EmbeddedDocumentFrame` 组件消费；若当前条目明确是卡片，也可以继续使用 `CardCoverFrame` 这一专用包装组件；
- 标题是否显示、显示在封面下方还是旁侧，由应用层和布局前端决定，不属于 `box.renderEntryCover` 自身职责。

### 6.4 `box.renderEntryDocument`

布局需要在当前页面内显示完整卡片内容时，使用该动作请求 Host 创建条目文档子渲染会话。

#### 请求

```ts
interface BoxRenderEntryDocumentRequest {
  sessionId: string;
  entryId: string;
  options?: {
    mode?: 'view' | 'preview';
    interactionPolicy?: 'native' | 'delegate';
    locale?: string;
    themeId?: string;
  };
}
```

布局 Runtime 只开放 `mode` 与 `interactionPolicy`；`locale/themeId` 由 SDK 从外层箱子文档窗口继承并写入 Host 请求。

#### 响应

```ts
interface BoxRenderEntryDocumentResponse {
  view: {
    entryId: string;
    documentType: 'card';
    title: string;
    documentUrl: string;
    renderSessionId: string;
  };
}
```

说明：

1. Host 必须校验箱子查看会话所有权、条目存在性、启用状态和文档类型；
2. Host 解析 `entryId` 对应的本地或箱子包内卡片，并复用正式 `card.render(target='card-iframe')`，布局插件不会获得卡片绝对路径；
3. `documentUrl` 是可直接挂载到受控 iframe 的 Host 托管网页入口，`renderSessionId` 用于显式释放；
4. 当前正式实现不递归内嵌 `.box`，子箱子条目继续显示封面或使用 `box.openEntry`；
5. 当前正式实现不在布局层下载远程卡片；`http/https/webdav` 条目返回 `BOX_ENTRY_DOCUMENT_UNAVAILABLE`，继续使用封面、摘要或外部打开链路；
6. 布局同时只应保留当前实际可见的完整卡片子会话，不应对整箱条目预渲染完整内容。

### 6.5 `box.releaseEntryDocument`

#### 请求

```ts
interface BoxReleaseEntryDocumentRequest {
  sessionId: string;
  renderSessionId: string;
}
```

#### 响应

```ts
interface BoxReleaseEntryDocumentResponse {
  ack: true;
}
```

Host 只允许释放由当前 `sessionId` 创建的条目文档子会话。切换选中条目、切换为封面态、布局卸载和外层箱子关闭时都必须进入释放链路。

### 6.6 `box.resolveEntryResource`

当布局插件需要真正的资源句柄时使用。

#### 请求

```ts
interface BoxResolveEntryResourceRequest {
  sessionId: string;
  entryId: string;
  resource: {
    kind: 'cover' | 'preview' | 'documentFile' | 'custom';
    key?: string;
    sizeHint?: {
      width?: number;
      height?: number;
    };
  };
}
```

#### 响应

```ts
interface BoxResolveEntryResourceResponse {
  resource: ResolvedRuntimeResource;
}
```

说明：

1. `renderEntryCover` 用于“直接显示封面”的正式链路；
2. `resolveEntryResource` 仍用于封面之外的预览、卡片入口资源和自定义资源；
3. 布局插件默认不应再把 `resolveEntryResource(kind='cover')` 当作首选封面接口。
4. `resolveEntryResource(kind='documentFile')` 返回的是原始卡片/箱子文档资源定位，不是 HTML 渲染结果；不得把它直接赋给 iframe。完整卡片必须使用 `renderEntryDocument`。

### 6.10 `box.renderLayoutFrame`

箱子查看态文档由 Host 统一生成。

#### 请求

```ts
interface BoxRenderLayoutFrameRequest {
  layoutType: string;
  sessionId: string;
  box: BoxSessionInfo;
  initialView: BoxEntryPage;
  config: Record<string, unknown>;
  locale?: string;
  themeId?: string;
}
```

#### 响应

```ts
interface BoxRenderLayoutFrameResponse {
  view: {
    title: string;
    documentUrl: string;
    sessionId: string;
    layoutType: string;
    pluginId: string;
  };
}
```

说明：

1. Host 必须根据 `layoutType` 查询并装载已安装布局插件；
2. Host 必须把 `box + initialView + config + runtime` 注入 `layoutDefinition.renderView`；
3. `documentUrl` 是供 SDK / 应用直接挂载到 iframe 的正式 Host 托管文档入口，调用方不得假定它一定是 `file://`；Electron 桌面端应优先使用受控渲染协议，避免沙箱 iframe 直接加载本地临时文件；
4. 应用层不得绕过该动作自行创建布局查看文档。
5. Host 生成查看态布局文档时，必须同时注入当前主题 `theme.getAllCss` 的完整 CSS 与 `theme.resolve.tokens` 生成的 CSS variables；完整 CSS 中的 Material Symbols `@font-face` 是 `ChipsIcon` 正常显示的必要条件，不能只注入 token 变量。
6. Host 应在写入布局文档前把完整主题 CSS 与 token 变量中的 `cpx` 长度转换为浏览器可识别单位，并保证文档 CSP 的 `font-src` 覆盖当前主题字体资源来源。

### 6.11 `box.renderLayoutEditor`

箱子布局编辑器文档也由 Host 统一生成。

#### 请求

```ts
interface BoxRenderLayoutEditorRequest {
  layoutType: string;
  entries: BoxEntrySnapshot[];
  initialConfig: Record<string, unknown>;
  locale?: string;
  themeId?: string;
}
```

#### 响应

```ts
interface BoxRenderLayoutEditorResponse {
  view: {
    title: string;
    documentUrl: string;
    sessionId: string;
    layoutType: string;
    pluginId: string;
  };
}
```

补充约束：

1. Host 生成的箱子布局编辑器文档根节点必须铺满宿主提供的编辑面板可视区；
2. 正式编辑器宿主根节点是 `#chips-box-layout-editor-root`，至少应满足 `width: 100%`、`height: 100%`、`min-height: 0` 与可控溢出；官方布局编辑器应与基础卡片编辑器保持同类结构，由插件编辑器内部提供可滚动编辑区，避免外层宿主裁切内容；
3. 布局插件自己的编辑页面根节点应在此基础上至少铺满可视区，并允许内容继续自然增长或由自身管理滚动。

说明：

1. Host 必须使用与查看态相同的布局插件装载结果；
2. Host 必须把 `entries + initialConfig + onChange + asset bridge` 注入 `layoutDefinition.renderEditor`；
3. `documentUrl` 与查看态一样是 Host 托管的正式文档入口，调用方只负责挂载，不得按本地文件 URL 语义解析；
4. 应用层只负责挂载文档和消费消息协议，不直接调用 `renderEditor` 导出。
5. Host 生成编辑器文档时必须沿用查看态同一套主题注入模型：完整主题 CSS（含组件样式与 Material Symbols `@font-face`）+ 解析后 token variables + 编辑器宿主基础样式。
6. 编辑器 iframe 不继承编辑引擎父文档的 `@font-face`；若只注入 token 变量，布局编辑器中的 `ChipsIcon` 会显示图标名文本而不是图标。

### 6.12 `box.releaseRenderSession`

释放 `box.renderLayoutFrame / box.renderLayoutEditor` 创建的渲染会话。

#### 请求

```ts
interface BoxReleaseRenderSessionRequest {
  sessionId: string;
}
```

#### 响应

```ts
interface BoxReleaseRenderSessionResponse {
  ack: true;
}
```

说明：

1. 查看会话 `box.openView/box.closeView` 与渲染会话 `box.renderLayoutFrame/box.releaseRenderSession` 是两条不同的资源生命周期；
2. SDK 或应用销毁箱子查看 iframe / 编辑器 iframe 时，必须回收对应渲染会话；
3. 通过 SDK `client.box.documentWindow.render(...)` 或 `client.document.window.render(...)` 打开的箱子文档，销毁时应同时关闭查看会话并释放渲染会话。
4. 箱子查看文档必须在初始渲染、内容变化和视口变化后向父级发送 `chips.box-layout:resize`，载荷至少包含 `height`、`reason`、`sessionId`、`layoutType` 与 `pluginId`；SDK `client.document.window.onResize(...)` 会把该事件归一为统一文档窗口高度事件。

### 6.13 嵌套卡片事件

布局内挂载条目卡片 iframe 时必须校验 `event.source === iframe.contentWindow`，并校验文档 URL 的预期 origin；受控协议和 `file:` sandbox 文档使用不透明 origin 时，只接受 `null`。

| 事件 | 布局职责 |
|---|---|
| `chips.composite:ready` | 结束子卡片加载态 |
| `chips.composite:resize` | 更新子 iframe 高度；外层箱子高度继续由布局文档的 `chips.box-layout:resize` 汇报 |
| `chips.composite:resource-open` | 原样转发给外层查看器，由应用使用正式资源打开链路处理 |
| `chips.composite:node-error` | 转发节点级诊断，不把单节点失败升级为整卡失败 |
| `chips.composite:fatal-error` | 显示完整卡片失败态并转发给外层查看器 |
| `chips.composite:interaction` | `interactionPolicy='delegate'` 时转发交互意图 |

## 7. 统一资源句柄

布局插件不直接拿到底层文件句柄，而是拿到统一资源句柄。

```ts
interface ResolvedRuntimeResource {
  resourceUrl: string;
  mimeType: string;
  cacheKey?: string;
  expiresAt?: string;
  width?: number;
  height?: number;
}
```

### 7.1 句柄要求

1. `resourceUrl` 必须可被当前布局会话安全消费；
2. 不得把凭证直接拼到 URL；
3. 资源可以是临时 URL、受控本地句柄或 Host 内部桥接地址；应用和布局插件不得依赖具体协议形态；
4. 同一资源可复用 `cacheKey`。

## 8. 安全与权限

### 8.1 权限

布局插件消费箱子运行时数据需要 `box.read`。

### 8.2 会话所有权

- `sessionId` 只能由打开该箱子的查看器 / 布局插件会话使用；
- 不允许跨插件窃取其他会话数据；
- Host 必须校验调用方是否属于当前箱子会话。

### 8.3 凭证与网络

- 布局插件永远不直接访问凭证；
- 网络 URL 的认证、刷新、重试由 Host 统一处理；
- 失败时返回结构化错误，不把底层鉴权细节暴露给布局插件。

---

## 9. 事件模型

Host 可以向布局插件发出箱子会话相关事件。

### 9.1 推荐事件

| 事件名 | 用途 |
|---|---|
| `box.session.updated` | 条目状态、分页或摘要变化 |
| `box.session.entryStateChanged` | 指定条目资源状态变化 |
| `box.session.closed` | 会话关闭 |

### 9.2 原则

- 事件只推送变化事实；
- 大数据量仍通过 `box.*` 读接口重新拉取；
- 不以事件直接推送整箱完整数据。

## 10. 错误码

| 错误码 | 含义 |
|---|---|
| `BOX_VIEW_SESSION_NOT_FOUND` | 会话不存在 |
| `BOX_LAYOUT_ACCESS_DENIED` | 当前布局插件无权访问该会话 |
| `BOX_ENTRY_NOT_FOUND` | 条目不存在 |
| `BOX_ENTRY_DOCUMENT_UNAVAILABLE` | 条目当前不能作为完整卡片文档渲染，例如禁用、缺失或远程条目 |
| `BOX_ENTRY_DOCUMENT_TYPE_UNSUPPORTED` | 条目类型不支持内嵌，当前包括子箱子 |
| `BOX_ENTRY_RENDER_SESSION_NOT_FOUND` | 子渲染会话不存在或不属于当前箱子会话 |
| `BOX_ENTRY_RENDER_FAILED` | 条目已解析，但正式卡片渲染失败 |
| `BOX_OPEN_FAILED` | 条目激活失败 |
| `BOX_RESOURCE_NOT_FOUND` | 请求的卡片资源不存在 |
| `BOX_ASSET_NOT_FOUND` | 请求的箱子资源不存在 |
| `BOX_URL_SCHEME_UNSUPPORTED` | URL 协议未被 Host 支持 |
| `BOX_RESOLVE_FAILED` | 解析或加载失败 |

## 11. 设计结论

首版正式箱子运行时契约只认以下事实：

1. 布局插件是页面，不是解析器；
2. Host 是解析中心，不是被动文件搬运工；
3. 箱子消费默认摘要优先，但布局可以按当前可见条目请求完整卡片内容；
4. 数据与资源都必须按需申请；
5. 箱子自有资源与卡片资源严格隔离。
