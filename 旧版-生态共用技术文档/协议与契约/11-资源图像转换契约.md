# 资源图像与视频缩略图转换契约

> 文档状态：首版冻结稿
> 适用范围：Host `resource` 服务、`chips-sdk` 资源 API、生态内需要把 TIFF 资源归一为 PNG 文件或从本地视频资源抽取封面帧的调用方

## 1. 定位

资源图像与视频缩略图转换继续构建在 Host `resource` 服务之上：

- 不新增新的服务域；
- 不引入新的插件类型；
- 调用方通过正式 `resource.convertTiffToPng` 与 `resource.extractVideoFrame` 动作访问能力；
- 平台差异继续收敛到 PAL，调用方不感知底层平台细节。

## 2. 正式动作

- 动作名：`resource.convertTiffToPng`
- SDK 对应封装：`client.resource.convertTiffToPng(...)`
- 动作名：`resource.extractVideoFrame`
- SDK 对应封装：`client.resource.extractVideoFrame(...)`
- 基础卡片编辑器上下文封装：`BasecardEditorContext.extractVideoThumbnail(...)`

## 3. TIFF 转 PNG 输入契约

```ts
interface ResourceConvertTiffToPngRequest {
  resourceId: string;
  outputFile: string;
  overwrite?: boolean;
}
```

约束：

- `resourceId` 只允许本地文件路径或 `file://` 本地资源；
- 输入文件必须是合法 TIFF 文件；
- `outputFile` 必须指向 `.png` 文件路径；
- `overwrite` 默认视为 `false`。

## 4. TIFF 转 PNG 输出契约

```ts
interface ResourceConvertTiffToPngResult {
  outputFile: string;
  mimeType: "image/png";
  sourceMimeType: "image/tiff";
  width?: number;
  height?: number;
}
```

语义：

- `outputFile` 指向已经落盘完成的 PNG 文件；
- `width/height` 是 Host 在输出 PNG 上读取到的像素尺寸；
- 当前正式结果不返回二进制正文，调用方若需要继续读文件，应再走 `file.read` 或 `resource.readBinary`。

## 5. 视频抽帧输入契约

```ts
interface ResourceExtractVideoFrameRequest {
  resourceId: string;
  outputFile: string;
  overwrite?: boolean;
  options?: {
    timeSeconds?: number;
    format?: "png" | "jpeg";
    width?: number;
    height?: number;
    fit?: "contain" | "cover";
    quality?: number;
  };
}
```

约束：

- `resourceId` 只允许本地文件路径或 `file://` 本地资源；
- Host 当前按文件头识别 `video/mp4`、`video/webm`、`video/ogg` 与 QuickTime 视频；
- `outputFile` 必须与 `options.format` 对应：`png` 输出 `.png`，`jpeg` 输出 `.jpg` 或 `.jpeg`；
- `overwrite` 默认视为 `false`；
- `timeSeconds` 默认 `0`，不得小于 `0`；若超过视频时长，由 PAL 在合法范围内夹取；
- `format` 默认由 PAL 选用 `png`；
- `width/height` 默认 `1280 x 720`，传入时必须大于 `0`；
- `fit` 默认 `contain`，可取 `contain | cover`；
- `quality` 仅对 JPEG 有实际意义，取值范围为 `1-100`。

## 6. 视频抽帧输出契约

```ts
interface ResourceExtractVideoFrameResult {
  outputFile: string;
  mimeType: "image/png" | "image/jpeg";
  sourceMimeType: string;
  width: number;
  height: number;
  format: "png" | "jpeg";
  frameTimeSeconds: number;
  durationSeconds?: number;
}
```

语义：

- `outputFile` 指向已经落盘完成的封面帧图片；
- `sourceMimeType` 是 Host 对输入视频字节头识别到的视频 MIME；
- `frameTimeSeconds` 是实际抽取帧对应的时间点；
- `durationSeconds` 在底层运行时可取得视频时长时返回；
- 当前正式结果不返回二进制正文，调用方若需要继续读文件，应再走 `file.read` 或 `resource.readBinary`。

## 7. 基础卡片编辑器桥接契约

基础卡片编辑器不直接调用 Host 文件系统，也不在插件内维护通用媒体处理算法。资源型编辑器通过宿主注入的 `BasecardEditorContext.extractVideoThumbnail(...)` 消费视频抽帧能力：

```ts
interface BasecardVideoThumbnailRequest {
  resourcePath: string;
  outputPath: string;
  overwrite?: boolean;
  options?: {
    timeSeconds?: number;
    format?: "png" | "jpeg";
    width?: number;
    height?: number;
    fit?: "contain" | "cover";
    quality?: number;
  };
}

interface BasecardVideoThumbnailResult {
  path: string;
  mimeType: "image/png" | "image/jpeg";
  sourceMimeType: string;
  width: number;
  height: number;
  format: "png" | "jpeg";
  frameTimeSeconds: number;
  durationSeconds?: number;
}
```

桥接约束：

- `resourcePath` 与 `outputPath` 都必须是卡片根目录相对路径；
- SDK `client.card.editorPanel.render({ resources })` 可以通过显式 `resources.extractVideoThumbnail` 回调桥接，也可以在存在 `resources.rootPath` 与 SDK client 时把相对路径解析为 Host `resource.extractVideoFrame` 调用；
- 官方编辑引擎本地运行时必须沿用 TIFF 转换模型：若源资源仍是待导入资源，先暂存为临时源文件，再调用 Host/SDK 抽帧，读回输出文件，作为待导入资源排队写回卡片根目录，最后清理临时文件；
- 基础卡片配置只允许保存返回的 `path`，不得保存 `blob:`、`data:`、系统绝对路径或 `file://` URL；
- 抽帧失败不得破坏已经完成的视频资源导入，编辑器应给出可恢复提示并允许用户手动上传封面。

## 8. 权限与执行约束

- 所需权限：`resource.read`、`file.read`、`file.write`
- `resource.convertTiffToPng` Host 路由超时：15 秒
- `resource.extractVideoFrame` Host 路由超时：30 秒
- 输出目录由 Host 创建；若目标文件已存在且 `overwrite !== true`，必须直接失败；
- 视频抽帧依赖 PAL `offscreenRender.videoFrame` 能力；无该能力的 Host 必须返回不支持错误，而不是让调用方私自降级到浏览器 `video + canvas`。

## 9. 错误码基线

当前首版冻结以下错误语义：

- `RESOURCE_TIFF_UNSUPPORTED_URI`：输入不是本地文件路径或 `file://` 本地资源
- `RESOURCE_TIFF_INVALID_SOURCE`：输入文件不是合法 TIFF
- `RESOURCE_TIFF_SOURCE_NOT_FOUND`：输入文件不存在
- `RESOURCE_TIFF_INVALID_OUTPUT`：输出路径非法或不是 `.png`
- `RESOURCE_TIFF_OUTPUT_EXISTS`：输出文件已存在且未允许覆盖
- `RESOURCE_TIFF_CONVERSION_UNSUPPORTED`：当前 Host 运行时不具备 TIFF 转 PNG 能力
- `RESOURCE_TIFF_CONVERSION_FAILED`：底层转换执行失败
- `RESOURCE_VIDEO_FRAME_UNSUPPORTED_URI`：视频输入不是本地文件路径或 `file://` 本地资源
- `RESOURCE_VIDEO_FRAME_INVALID_SOURCE`：输入文件不是当前 Host 可识别的视频文件
- `RESOURCE_VIDEO_FRAME_SOURCE_NOT_FOUND`：视频输入文件不存在
- `RESOURCE_VIDEO_FRAME_INVALID_OUTPUT`：输出路径非法或扩展名与目标格式不匹配
- `RESOURCE_VIDEO_FRAME_OUTPUT_EXISTS`：输出文件已存在且未允许覆盖
- `RESOURCE_VIDEO_FRAME_UNSUPPORTED`：当前 Host 运行时不具备视频抽帧能力
- `RESOURCE_VIDEO_FRAME_EXTRACTION_FAILED`：底层抽帧执行失败

## 10. 性能预算

- TIFF 转 PNG 面向单个本地图片资源，调用方应避免在主交互线程同步等待批量转换；
- 视频抽帧面向单个本地视频文件的一帧封面图，Host 路由预算为 30 秒；
- 基础卡片插件默认生成封面时应使用受控尺寸，官方视频基础卡片默认使用 `1280 x 720`、`fit: "cover"`、`format: "png"`；
- 批量缩略图、转码、字幕解析、长任务进度等能力不复用本同步动作，应另行通过模块任务或 Host 异步任务契约扩展。

## 11. 设计边界

- 该契约当前冻结 `TIFF -> PNG` 与本地视频单帧缩略图抽取，不在本轮扩展完整转码、字幕解析或视频元数据索引；
- 输出始终是磁盘文件，不定义内存态返回；
- 基础卡片消费边界是“请求宿主生成资源并保存相对路径”，不是在卡片插件内部实现媒体算法；
- 若未来需要更多图片格式归一化或媒体预处理能力，应在保持 `resource` 服务语义统一的前提下扩展，不新增第二套路由体系。
