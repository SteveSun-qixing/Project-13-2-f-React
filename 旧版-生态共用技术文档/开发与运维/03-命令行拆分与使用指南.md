# 薯片生态命令行拆分与使用指南

> 本文档定义 `chips` 与 `chipsdev-r` 的职责边界、工作区模型和协作方式，是生态内所有命令行实现与文档的统一依据。

## 1. 总体结构

薯片生态提供两套正式命令行：

- `chips`：面向终端用户与运维，管理用户工作区中的 Host 运行时；
- `chipsdev-r`：面向开发者，管理开发工作区中的工程流程与 Host 联调能力。

旧写法 `chips host`、`chips dev` 已全部废弃。

## 2. 工作区边界

### 2.1 用户工作区

`chips` 默认使用 `~/.chips-host`，可通过 `CHIPS_HOME` 覆盖。

用户工作区保存：

- Host 运行状态
- 用户侧插件记录
- 用户侧主题配置
- 用户侧日志与诊断信息
- Electron 运行态数据目录（位于用户工作区内的 `electron-user-data`）

### 2.2 开发工作区

`chipsdev-r` 默认使用项目链路中的 `.chips-host-dev`：

- 先从当前目录向上查找 `.chips-host-dev`
- 找到即复用
- 找不到则在当前工程根创建

开发工作区保存开发态联调需要的全部 Host 状态，与用户工作区完全隔离。

真实 Electron Host 在开发态启动时，会把 Electron `userData` 固定到开发工作区内的 `electron-user-data` 目录。因此，Chromium 缓存、LocalStorage、Session、IndexedDB 等运行态数据也属于当前工作区状态，不得跨用户工作区和开发工作区共享。

### 2.3 隔离原则

以下数据不得跨工作区共享：

- 当前主题
- 主题插件启用状态
- 插件安装与启停记录
- Host 配置
- 运行日志
- Electron 运行态数据

因此，出现“`chips` 已切换暗夜主题，但 `chipsdev-r run` 仍是默认主题”时，首先应检查是否处于不同工作区。

## 3. `chips` 的职责

`chips` 只负责用户工作区中的 Host 管理和插件 CLI 执行：

- `start/stop/status`
- `config`
- `logs`
- `plugin install/uninstall/list/enable/disable/query`
- `theme list/current/apply/resolve/contract/validate`
- `update check/install`
- `doctor`
- `open`

`chips start/stop/status` 管理的是用户工作区状态标记和诊断视图；插件命令执行会按需启动短生命周期 Host 或 Electron 承载链路，不要求先运行 `chips start`。`chips` 不负责工程创建、构建、测试、打包。

## 4. `chipsdev-r` 的职责

`chipsdev-r` 负责两类能力：

### 4.1 工程工作流

- `init`
- `create`
- `server`
- `debug`
- `module invoke`
- `build`
- `test`
- `lint`
- `e2e`
- `package`
- `validate`
- `login`
- `publish`
- `run`

### 4.2 开发工作区 Host 管理

`chipsdev-r` 额外提供与 `chips` 同级的 Host 管理命令，但所有操作落在开发工作区：

- `start/stop/status`
- `config`
- `logs`
- `plugin`
- `theme`
- `update`
- `doctor`
- `open`

实现方式上，`chipsdev-r` 会把这些命令委托给 Host CLI 核心，但通过开发工作区路径和 `CHIPS_WORKSPACE_KIND=dev` 固定其上下文。`chipsdev-r completion <shell>` 生成的脚本注册 `chipsdev-r` 自身，并通过 `chipsdev-r __complete` 私有入口保持开发工作区语义；未知顶层命令会作为开发工作区插件 CLI 命令候选转发给 Host CLI 执行器。

### 4.3 开发侧 Electron 联调入口

`chipsdev-r` 中真正拉起 Electron Host 的正式命令目前有两类：

- `chipsdev-r run`：面向 `manifest.type === "app"` 的应用插件窗口联调；
- `chipsdev-r module invoke`：面向模块插件 capability/method 的 Electron 宿主联调。

职责边界如下：

- `chipsdev-r start/plugin/theme/open/...` 负责开发工作区 Host 状态与安装管理；
- `chipsdev-r run` 负责应用插件窗口会话；
- `chipsdev-r module invoke` 负责模块能力调用与 job 结果回收；
- 依赖 `BrowserWindow` 的模块能力，不能只用 `chipsdev-r start` 验证。

### 4.4 开发者治理报告

`chipsdev-r` 还提供开发期只读报告命令：

- `chipsdev-r preview`：读取当前工程配置与 manifest，生成 Host mock / 真实 Host 预览链路报告。
- `chipsdev-r component gallery`：读取组件库 contract 与 token 构建产物，生成组件 part/state/token 矩阵。
- `chipsdev-r theme inspect`：读取主题包 manifest、contracts、tokens 和 dist 资产，输出主题覆盖诊断。
- `chipsdev-r quality gate`：汇总当前工程、SDK route manifest、组件库 quality/perf 最新报告和主题检查摘要。
- `chipsdev-r assimilate scan/report`：扫描外部 Web 项目，输出薯片 manifest、SDK/Bridge、主题、多语言和组件同化建议。
- `chipsdev-r diagnostics`：汇总 route、组件矩阵、主题检查和质量门禁摘要。

这些命令默认输出人读摘要，`--json` 输出完整机器可读报告，`--out <file>` 写入完整 JSON。它们不替代各项目的正式构建、测试、打包或真实 Electron 联调命令。

## 5. 典型工作流

### 5.1 用户侧运行

```bash
chips plugin install /绝对路径/主题包.cpk
chips plugin enable theme.theme.chips-official-default-dark-theme
chips theme apply chips-official.default-dark-theme
chips open /绝对路径/示例.card
```

### 5.2 开发侧联调

```bash
cd /Users/sevenstars/Documents/ChipsCard/Develop/Project-13-2-f/Chips-CardViewer
chipsdev-r plugin install /绝对路径/主题包.cpk
chipsdev-r plugin enable theme.theme.chips-official-default-dark-theme
chipsdev-r theme apply chips-official.default-dark-theme
chipsdev-r run
```

### 5.3 主题包开发与验收

```bash
chipsdev-r build
chipsdev-r validate
chipsdev-r package
chipsdev-r plugin install /绝对路径/产物.cpk
chipsdev-r plugin enable <pluginId>
chipsdev-r theme validate
```

### 5.4 模块插件 Electron 能力联调

```bash
cd /Users/sevenstars/Documents/ChipsCard/Develop/Project-13-2-f/Chips-ModulePlugin/Chips-HtmltoImage-Plugin
chipsdev-r module invoke \
  --capability converter.html.to-image \
  --method convert \
  --input-file /绝对路径/request.json
```

说明：

- 若当前目录是模块插件工程，命令会先构建当前工程；
- 命令会在开发工作区中重新安装并启用当前模块；
- 若模块返回 job，命令会等待到终态后再退出。

## 6. 主题链路约束

主题链路必须满足以下约束：

- 只有已启用主题插件才能进入 `theme.list/getCurrent/resolve/apply`；
- 主题插件安装、启用、禁用、卸载后，Host 必须刷新主题运行时状态；
- 应用启动初始主题必须从 Host 当前主题读取，不得写死默认值；
- 复合卡片窗口必须在主题运行时缓存键变化后重新渲染；
- 原生窗口背景在应用未显式提供时，必须取自当前主题 token；
- 卡片渲染服务不得写死 `color-scheme: light` 之类的覆盖样式。

## 7. 迁移说明

若旧文档中仍出现以下描述，均按当前方案理解：

- `chips dev ...` -> `chipsdev-r ...`
- `chips host ...` -> `chips ...`
- “开发命令不负责插件和主题管理” -> 已失效，当前 `chipsdev-r` 已提供开发工作区的正式插件与主题管理能力

## 8. 质量门禁

命令行相关实现与文档必须同时满足：

- 边界清晰：用户工作区与开发工作区不混用；
- 行为一致：`chips` 与 `chipsdev-r` 在各自工作区内提供同口径 Host 管理能力；
- 文档一致：命令示例、技术文档、设计原稿和工单记录保持统一；
- 可验证：主题安装、启用、切换、查看器显示、卡片渲染与窗口背景均可通过正式命令链路复核。
