# 插件开发规范

## 开发环境

开发环境是进行插件开发的基础设施。开发者需要安装 Node.js 和包管理器，并通过生态根工作区安装 `chips-sdk`，从而获得正式 `chipsdev-r` 开发者命令。配置本地开发服务器用于测试和调试。

开发目录结构包括源代码目录 `src` 存放 TypeScript 源码，输出目录 `dist` 存放编译后的运行时代码，测试目录 `tests` 存放测试用例，资源目录 `assets` 存放图片、字体等静态资源，配置文件包括 `manifest.yaml`、`chips.config.mjs`、`package.json`、`tsconfig.json` 等。

## 项目初始化

项目初始化使用官方提供的脚手架工具。运行 `chipsdev-r create app|card|layout|module|theme <targetDir>` 创建新插件项目，脚手架会根据插件类型生成相应的项目结构和配置文件。

生成的配置文件包括 `manifest.yaml`、`chips.config.mjs`、`tsconfig.json`、`package.json` 等。`manifest.yaml` 是插件工程唯一正式清单源，`chips.config.mjs` 用于声明工程构建输入输出和测试目录。

### 脚手架产物约定

薯片生态官方脚手架仅输出运行时与工程必要的基础目录（如 `src/`、`tests/`、`contracts/`、`manifest.yaml`、`README` 等），不会默认创建 `需求文档/`、`技术文档/`（或“技术手册”）与 `开发计划/` 这样的文档根目录。如需补充此类资料，应在业务仓或生态共用文档中另行维护，而不是在生成工程中预留空目录。

## 类型定义

类型定义由 `chips-sdk`、组件库公开类型和 Host Bridge 公共契约共同提供。应用插件应优先通过 `chips-sdk` 的 `createClient()` 与 domain API 获得类型安全；确需直接访问低层 Bridge 时，以生态共用 `Bridge API` 规范和 Host 当前 `ChipsBridge` 形状为准。

主要类型包括：SDK client 配置、各能力域请求与响应、标准错误对象、事件回调、`platform.getLaunchContext()` 返回的 `surfaceContext`、命令定义和 manifest 结构。开发者应充分利用类型检查减少运行时错误，不再依赖模板内置的单一 `chips.d.ts` 作为正式类型来源。

## 清单配置

manifest.yaml是插件的核心配置文件，定义了插件的元数据和能力。

必填配置项包括：插件唯一标识符使用反向域名格式，插件显示名称，遵循语义化版本规范的版本号，插件类型如 `app`、`card`、`layout`、`module`、`theme`，插件入口文件路径，权限数组 `permissions`，以及完整 `runtime.targets`。无权限插件也必须显式写入 `permissions: []`。

可选配置项包括：作者信息和联系方式，插件功能描述，图标文件路径，项目主页 URL，开源许可证类型，关键词数组用于搜索，截图数组用于展示，以及依赖声明。类型专属字段必须按 `app` 的 `ui.surface`、`card` 的 `capabilities.cardTypes`、`layout` 的 `layout.layoutType`、`module` 的 `module.provides / module.consumes`、`theme` 的对象形式 `entry.tokens / entry.themeCss` 分别声明。

## 打包配置

打包配置定义如何将源代码转换为 `.cpk` 插件包。`chips.config.mjs` 指定构建输入输出，`manifest.yaml` 指定 Host 安装后加载的入口文件路径。`.cpk` 由 `chipsdev-r package` 生成，并采用 ZIP Store 模式。

资源处理包括：需要包含的静态资源文件，需要排除的源文件，资源文件的复制规则。

代码转换包括：TypeScript编译选项的目标版本，模块系统的目标格式，源代码映射的生成规则。

## 图标资产

所有插件的静态身份图标统一采用「Material Symbols Rounded 白底黑图标」视觉基线，通过正式工具链生成，禁止手工绘制游离资产或使用 emoji、字体码位截图产物。

正式资产布局：

- 应用插件：`assets/icons/app-icon.svg/.png/.ico/.icns`，`manifest.yaml -> ui.launcher.icon` 声明 `assets/icons/app-icon.ico`，供系统入口、快捷方式与启动台消费；
- 基础卡片插件：`assets/icons/basecard-icon.svg/.png/.ico/.icns`，不进入 manifest，作为插件静态身份资源；
- 箱子布局插件：`assets/icons/layout-icon.svg/.png/.ico/.icns`，不进入 manifest，作为插件静态身份资源；
- 模块插件：`assets/icons/module-icon.svg/.png/.ico/.icns`，不进入 manifest，作为模块静态身份资源。

正式设计源与生成链路：

- 设计源目录：`design-assets/Appicon/`、`design-assets/Basecardicon/`、`design-assets/Layouticon/`、`design-assets/Moduleicon/`（主题包身份图标在 `design-assets/Themeicon/`）；
- SVG 设计源生成：`scripts/generate-plugin-material-icons.ts` 按 `scripts/icon-targets.mjs` 登记表生成并同步各工程 `assets/icons/*.svg`；
- PNG/ICO/ICNS 渲染：`scripts/sync-plugin-icons.mjs` 通过 `chips iconmaker generate` 命令行链路渲染并同步各工程 `assets/icons/*.png/.ico/.icns`；
- 每个插件必须有唯一图标；新增插件时先在 `scripts/icon-targets.mjs` 登记，再运行上述两个脚本。

运行时 UI 图标不属于本资产链路：界面内图标一律通过 `ChipsIcon + IconDescriptor` 渲染，不消费 `assets/icons/` 静态文件。

## 尺寸单位

薯片生态使用 `cpx`（chips pixel）作为统一的逻辑尺寸单位。

- 逻辑基准宽度：1024cpx
- 换算公式：`px = cpx * (容器宽度 / 1024)`

所有布局常量应以 cpx 声明，渲染前统一换算到 px。换算结果保留 3 位小数。

- 字体：四舍五入到 0.5px
- 边框：最小 1px 可见阈值
- 位移：允许亚像素渲染

SDK 提供 `@chips/layout-math` 统一函数，禁止应用侧重复实现。

## 权限声明

权限声明定义插件需要的系统能力。权限在 manifest.yaml 的 permissions 字段中声明。

常用权限采用命名空间格式：

| 权限名称 | 说明 |
|----------|------|
| `file.read` | 读取文件 |
| `file.write` | 写入文件 |
| `file.stat` | 文件状态 |
| `file.list` | 列出目录 |
| `network.request` | 发起网络请求 |
| `clipboard.read` | 读取剪贴板 |
| `clipboard.write` | 写入剪贴板 |
| `window.control` | 窗口管理 |
| `global-shortcut` | 全局快捷键 |
| `theme.read` | 读取主题 |
| `theme.write` | 应用主题 |
| `i18n.read` | 读取国际化 |
| `i18n.write` | 修改语言 |
| `log.write` | 写入日志 |
| `log.read` | 读取日志 |
| `credential.manage` | 凭证管理 |
| `plugin.read` | 读取插件与主题治理信息 |
| `plugin.manage` | 插件管理 |
| `module.manage` | 模块管理 |
| `box.read` | 读取箱子会话、条目与资源句柄 |
| `box.write` | 打包、解包和写回箱子文件 |

权限声明应遵循最小权限原则，只请求实际需要的权限。

布局插件权限基线：

- 布局插件通常只需要 `box.read`、`theme.read`、`i18n.read`；
- 不得为了读取箱子条目而额外申请 `file.*`、`network.request` 或 `credential.manage`；
- 只有编辑器、导出工具或箱子维护工具才应申请 `box.write`。

## 本地测试

本地测试是开发流程的重要环节。`chipsdev-r` 命令启动开发模式，自动编译源代码并重新加载插件。开发模式下可以实时查看代码修改的效果。

调试功能包括：浏览器开发者工具用于前端调试，日志输出用于追踪执行流程，断点调试用于精确定位问题。

测试策略包括：单元测试验证独立函数和类，集成测试验证组件间协作，端到端测试验证完整功能流程。

## 发布流程

发布流程用于生成可安装、可验证的 `.cpk` 插件包。首先进行版本号规划，遵循语义化版本规范。然后运行项目正式验证脚本，执行打包命令生成 `.cpk` 文件，并保留发布说明、构建日志和校验结果。当前薯片生态第一版不包含线上插件分发平台，插件分发、安装和启停以 Host、`chipsdev-r` 与正式安装链路为准。

发布前检查清单包括：所有测试通过，类型检查无错误，打包过程无警告，manifest配置完整正确，图标和截图准备齐全。

## 安装与分发

本地 `.cpk` 插件包进入用户环境前必须通过 manifest 校验、权限校验、入口资产校验和构建产物完整性校验。当前本地开发与本地安装链路按 `source = local` 处理，不要求签名作为安装前置条件；非本地来源、远端发布和来源审核需要在独立发布安全契约中冻结后再进入正式流程。开发态优先使用 `chipsdev-r run`、`chipsdev-r package`、`chipsdev-r plugin install`、`chipsdev-r plugin enable`、`chipsdev-r plugin query` 等正式链路验证。

后续如果生态引入新的分发平台，应先沉淀独立公共契约与安全审核规范，再更新本文档；在此之前不得把线上插件分发平台作为开发、发布或验收前提。
