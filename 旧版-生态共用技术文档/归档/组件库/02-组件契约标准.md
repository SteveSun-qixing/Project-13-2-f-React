# 组件契约标准

## 1. 契约目标

统一生态组件结构和状态语义，保证主题包、测试工具、自动化扫描工具可稳定工作。

## 2. 强制字段

每个组件必须暴露：

- `data-scope`：组件名（小写短横线）
- `data-part`：部件名（root/label/icon/...）
- `data-state`：当前状态
- `aria-*`：无障碍语义属性

## 3. 状态模型

标准状态集合：

`idle | hover | focus | active | disabled | loading | error`

非标准状态需要额外在组件文档中声明并说明优先级。

## 4. 命名规则

- `data-scope`：`button`、`input`、`dialog`
- `data-part`：`root`、`trigger`、`content`、`label`、`icon`
- `data-state`：使用上述标准状态，不允许自造同义词

## 5. 兼容要求

- 契约字段变更视为破坏性变更
- 主题包不得依赖未公开 part 名称
- 控制型图标（展开/折叠/关闭/时间等）必须支持外部槽位覆盖，禁止写死用户可见字符

## 6. 示例

```html
<button
  data-scope="button"
  data-part="root"
  data-state="loading"
  aria-disabled="true"
>
  <span data-part="label">保存</span>
  <span data-part="spinner" aria-hidden="true"></span>
</button>
```

## 6.1 受控状态与 Binding 规则

组件公开契约只暴露标准 React 受控 props，不暴露组件私有 `binding` prop：

- 值控件：`value / defaultValue / onValueChange`
- 布尔选择控件：`checked / defaultChecked / onCheckedChange`
- 展开类控件：`open / defaultOpen / onOpenChange`
- 原生控件：`value / defaultValue / onChange`

`@chips/hooks` 的 `ChipsBinding` 负责把页面状态、表单字段、配置项或其他真实状态源适配为上述 props。组件自身仍只负责无头结构、状态机、ARIA 和主题挂点；业务校验、保存、权限判断和 Host 配置读写不得沉淀到组件内部。详细状态模型见 `10-状态环境与Binding模型.md`。

## 6.2 焦点与键盘契约

交互组件必须暴露稳定键盘和焦点语义：

- 弹层触发器必须输出 `aria-haspopup / aria-expanded / aria-controls`。
- 弹层关闭后必须恢复到触发元素或显式 fallback。
- modal dialog 必须启用 Tab focus trap。
- 复合列表类组件必须使用 roving tabindex：当前项 `tabIndex=0`，非当前项和禁用项 `tabIndex=-1`。
- 通过输入框或触发器承载虚拟焦点时，必须使用 `aria-activedescendant` 指向当前高亮项。
- 方向键、Home、End、Enter、Space、Escape 必须按 `11-焦点键盘与A11y交互模型.md` 的 keyboard map 执行。

这些行为属于组件库 L10 状态机和 a11y 职责，不属于主题包或业务页面职责。主题包只负责为 `data-state="focus"`、`data-highlighted`、`data-selected`、`aria-disabled` 等状态提供可见视觉。

## 7. iframe 高级组件附加契约

只有 iframe 高级组件需要声明 iframe 附加契约。当前正式范围为 `CardCoverFrame`、`CompositeCardWindow`，必须额外声明：

- iframe 安全策略（sandbox/allow）
- frame 生命周期事件（`ready/error`）
- 降级状态（如 `degraded`）
- 跨 iframe 通信边界（仅受控事件通道）

普通无头组件和布局原语不声明 iframe 字段，契约校验不应要求它们提供 `iframe.requiredSandbox`。

## 8. 主题 Contract View 对接字段

组件 contract 进入主题系统时统一归一为 `ThemeContractComponentView`：

- `component`：组件技术名，使用小写短横线。
- `scope`：运行时 `data-scope`。
- `parts`：公开 `data-part` 集合。
- `states`：公开 `data-state` 集合。
- `requiredTokens`：主题包必须实现的 token key，缺失会产生 `THEME_REQUIRED_TOKEN_MISSING` 阻断诊断。
- `optionalTokens`：主题包可选实现的 token key，缺失只产生非阻断诊断。
- `a11yConstraints`：可选的组件可访问性约束引用，由设置面板和测试工具展示。
- `motionConstraints`：可选的组件动效约束引用，由主题包校验器和设置面板展示。
- `coverage`：required/optional token 覆盖率。
- `diagnostics`：该组件下的主题诊断列表。

当前组件库源码 contract 仍以 `tokens` 作为 raw source 字段，`Chips-ComponentLibrary/packages/theme-contracts/tests/component-contract.test.mjs` 也按该字段断言源码形态。进入主题系统、官方主题包生成产物或 Host/CLI public view 时，validator 必须把 raw `tokens` 归一为 `requiredTokens`，并把缺省 `optionalTokens` 视为空数组。raw schema 统一迁移前，不得把源码 contract 误写成已经全部使用 `requiredTokens / optionalTokens`。

## 8.1 官方主题 Contract 生成规则

组件库正式 contract 目录 `Chips-ComponentLibrary/packages/theme-contracts/contracts/components/*.contract.json` 是官方主题包 component contract 的唯一来源。官方主题包内的 `contracts/theme-interface.contract.json` 与 `contracts/theme-min-functional-set.json` 是随主题包发布给 Host 读取的生成产物，不是人工维护源。

`@chips/theme-contracts` 必须提供并维护以下公共 API：

- `loadComponentContracts(contractDir?)`
- `buildThemeInterfaceContract(componentContracts, options?)`
- `buildThemeMinFunctionalSet(componentContracts, options?)`
- `compareThemeInterfaceContract(themeContract, componentContracts)`
- `compareThemeMinFunctionalSet(minFunctionalSet, componentContracts)`

官方主题包构建时必须从组件库正式 contract 生成本包 contract 产物；校验时必须比较 `component/scope/parts/states/requiredTokens/optionalTokens/a11yConstraints/motionConstraints/iframe` 等公开字段，阻止本地 contract 与组件库来源漂移。Host 运行时仍只读取已安装主题包内 manifest 指向的 contract 文件，不能依赖开发工作区源码。

- `ChipsForm`：正式 Compound 子组件为 `Root / Section / Field / Label / Control / Error / Hint`，`data-scope="form"`，公开 part 为 `root / section / field / label / required / control / error / hint / status`，状态为标准交互状态集合。`Root` 只负责表单结构、提交禁用保护、禁用/加载/错误/只读/必填状态和上下文分发；`Field` 负责字段 id、label/control/error/hint 关联、`aria-describedby` 聚合、`aria-invalid` 与状态挂点；`Control` 只在原生控件上输出 `data-part="control"`，自定义 Chips 控件不得被覆盖自身 `data-scope/data-part`；`Hint` 是正式说明文本 part，旧 `helper` 不再作为公开 part。`form-field` 与 `form-group` 已归档，不再作为正式公开 scope。

已落地任务016第四批复杂组件 Compound API 的正式组件导出：

- `ChipsDataGrid`：正式 Compound 子组件为 `Root / Toolbar / Header / Row / Cell / Pagination`，`data-scope="data-grid"`，公开 part 为 `root / toolbar / header / row / cell / pagination / status`，状态为标准交互状态集合。`Root` 是外层容器，默认使用 `role="group"`，实际网格语义由内部 `role="grid"` 区域或默认数据驱动 `table role="grid"` 承载；`table` 是内部 DOM 结构，不是公开 `data-part`。`Toolbar` 使用 `role="toolbar"`，`Pagination` 使用 `role="navigation"`；`Header` 表达表头行，`Cell header=true` 表达列头并输出 `role="columnheader"`、`aria-sort`、`data-sort` 与 `data-sortable`；普通 `Cell` 输出 `role="gridcell"`；`Row` 输出 `role="row"`、`aria-selected`、`data-selected` 与 `data-active`。选中行视觉必须使用 `data-selected="true"`，`data-state="active"` 只保留给标准交互 active 状态。

已落地任务016第五批复杂组件 Compound API 的正式组件导出：

- `ChipsTree`：正式 Compound 子组件为 `Root / Item / Branch / Leaf / Disclosure`，`data-scope="tree"`，公开 part 为 `root / item / branch / leaf / disclosure / label / group / status`，状态为标准交互状态集合。`Root` 负责展开、选择、活动项、禁用/加载/错误状态和上下文分发；`Item / Branch / Leaf` 使用 `role="treeitem"`，输出 `aria-level / aria-setsize / aria-posinset / aria-selected / data-selected / data-active`；`Branch` 额外输出 `aria-expanded`，其子节点容器使用 `group role="group"`；`Disclosure` 是分支内展开折叠控制，默认不进入 Tab 顺序。旧 `node / toggle / children` 已收口，不再作为公开 part 或主题/L8 依赖入口。选中节点视觉必须使用 `data-selected="true"`，`data-state="active"` 只保留给标准交互 active 状态。

已落地布局原语的正式组件导出：

- `ChipsView`：页面、区域或主视图容器，默认 `role="region"`，标题可通过 `title/titleId/aria-label/aria-labelledby` 建立可访问名称。
- `ChipsBox`：通用结构容器，承载 padding、radius 与基础状态 token。
- `ChipsStack`：纵向或横向堆叠容器，支持 `direction/gap/align/justify/wrap`。
- `ChipsInline`：行内容器，默认可换行，支持 `gap/align/justify/wrap`。
- `ChipsGrid`：响应式网格容器，支持 `columns/minItemSize/gap`。
- `ChipsSection`：局部内容分区，默认 `role="region"`，支持标题、描述、正文、页脚与错误状态。
- `ChipsScrollView`：滚动区域，默认 `role="region"`，必须通过 `aria-label` 或 `aria-labelledby` 提供名称。
- `ChipsSpacer`：弹性留白，只作为装饰结构，必须 `aria-hidden="true"`。
- `ChipsDivider`：分割线，非装饰模式必须 `role="separator"` 并暴露方向。
- `ChipsSplitView`：主从或三栏视图容器，默认 `role="group"`，必须通过 `aria-label` 或 `aria-labelledby` 提供名称。

布局原语主题实现必须覆盖默认主题和暗色主题，且样式只能通过 `chips.comp.*` 与 `chips.layout.*` token、CSS 变量和公开 `data-scope/data-part/data-state` 挂点实现。网格最小条目、SplitView 栏宽、焦点环、分割线厚度等结构尺寸不得在主题 CSS 中写成私有固定值，应分别回到 `chips.layout.size.*`、`chips.layout.focus.*` 与 `chips.layout.divider.*`。

已落地命令消费组件的正式导出：

- `ChipsCommandProvider`：命令消费上下文，接收应用注入的 `CommandAdapter`、静态 command views、i18n adapter 与查询默认值。
- `ChipsToolbar`：`data-scope="toolbar"`，默认 `role="toolbar"`，按 `toolbarPlacement.toolbarId/groupId/order` 渲染 command。
- `ChipsToolbarItem`：`data-scope="toolbar"`、`data-part="item"`，渲染 command 图标、文案、快捷键提示并触发 command。
- `ChipsMenuBar`：`data-scope="menu-bar"`，默认 `role="menubar"`，按 `menuPlacement.menuId/groupId/order` 生成菜单结构。
- `ChipsContextMenu`：`data-scope="context-menu"`，提供右键/点击触发的无头上下文菜单结构。
- `ChipsShortcut`：`data-scope="shortcut"`，只负责快捷键视觉与可访问名称，不负责注册系统快捷键。
- `ChipsCommandPalette`：`data-scope="command-palette"`，正式子组件为 `Root / Input / List / Item / Group`，公开 part 为 `root / input / list / group / group-label / item / shortcut / status`；可从 command views 派生命令条目，`Item` 选择仍走 command invoke，旧 `search / result` 不再是公开 contract。
- `ChipsNavigationSplitView`：`data-scope="navigation-split-view"`，正式子组件为 `Root / Sidebar / Content / Detail`，公开 part 为 `root / sidebar / content / detail / divider / status`。`Sidebar` 默认是 `navigation` landmark，`Content / Detail` 默认是具名 `region`；`primary / secondary` 属于 `ChipsSplitView` 布局原语，不属于 `navigation-split-view` 公开 part、主题 contract 或 L8 slot。

命令消费组件新增的公开部件：

- `toolbar`：`root / group / item / icon / label / shortcut / status`
- `menu-bar`：`root / menu / content / group / item / shortcut / status`
- `context-menu`：`root / trigger / content / group / item / shortcut / status`
- `command-palette`：`root / input / list / group / group-label / item / shortcut / status`
- `navigation-split-view`：`root / sidebar / content / detail / divider / status`
- `shortcut`：`root / key / separator`

这些组件不得直接绑定业务函数；业务动作必须由 Host command registry 调度。图标必须通过 `ChipsIcon` 渲染，文案必须通过命令 i18n key 解析。

## 10. 图标组件正式契约

- 运行时图标统一由 `ChipsIcon` 承担；
- `ChipsIcon` 的正式输入是图标描述符对象，而不是字符串、emoji 或业务自定义枚举；
- `ChipsIcon` 根节点必须暴露：
  - `data-scope="icon"`
  - `data-part="root"`
  - `data-icon-style="outlined|rounded|sharp"`
- 装饰图标默认 `aria-hidden="true"`；
- 功能图标必须通过 `label` 或外部可访问名称提供语义；
- 任何组件默认图标、空态图标、工具栏图标都必须最终回到 `ChipsIcon`，不得在组件内部继续维护一套硬编码 SVG 主链路。
