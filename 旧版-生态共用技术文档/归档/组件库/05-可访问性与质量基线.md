# 可访问性与质量基线

## 1. 可访问性基线

所有组件必须满足：

- 键盘可完整操作
- 焦点可见且顺序正确
- 语义 role 正确
- 读屏信息完整（label/description/error）
- 图标按钮最小热区 44px
- `IconButton` 必须提供 `aria-label` 或 `aria-labelledby`；`ToggleButton` 必须暴露 `aria-pressed`。
- `Spinner` 独立使用必须 `role="status"` 并有可访问名称，装饰性嵌入场景必须 `aria-hidden="true"`。
- `Progress` 必须 `role="progressbar"`；确定进度输出 `aria-valuemin / aria-valuemax / aria-valuenow`，不确定进度不得输出 `aria-valuenow`。
- `Rating` 根节点必须使用 `role="radiogroup"` 并提供可访问名称；每个评分项必须使用 `role="radio"` 与 `aria-checked` 表达当前值，键盘必须支持方向键与 Home/End 调整，禁用和只读状态必须阻止提交。`readOnly` 只表达不可提交语义，应保留已选评分项的视觉与 `aria-checked` 状态；只有 `disabled/loading` 才允许把评分项置为 `disabled`。
- `TextField / TextArea / SearchField / SecureField` 必须通过 `label/labelKey/aria-label/aria-labelledby` 提供可访问名称，并通过 `aria-describedby` 关联描述和错误状态。
- `SearchField` 根节点必须使用 `role="search"`，`Enter` 触发搜索语义，清空按钮必须有可访问名称。
- `SecureField` 可见性切换必须是按钮并输出 `aria-pressed="true|false"`，不得使用 `aria-checked` 表达密码可见性。
- `SegmentedControl` 根节点必须使用 `role="radiogroup"` 并提供可访问名称，分段项必须使用 `role="radio"` 与 `aria-checked` 表达单选状态，键盘方向键/Home/End 应在可用项之间移动。
- `ComboBox` 输入控件必须使用 `role="combobox"`、`aria-autocomplete="list"`、`aria-expanded`、`aria-controls` 和 `aria-activedescendant` 关联弹层；展开状态缺少 `aria-controls` 必须视为 a11y 违规。
- `NumberInput` 输入控件必须使用 `role="spinbutton"` 并提供可访问名称，输出 `aria-valuemin / aria-valuemax`，有有效数值时输出 `aria-valuenow`，描述和错误必须通过 `aria-describedby` 关联。
- `Stepper` 根节点必须使用 `role="group"` 并提供可访问名称，递增和递减必须是真实按钮且有独立可访问名称，边界禁用必须同步 `disabled / aria-disabled`。
- `Slider` 的 `thumb` 必须使用 `role="slider"` 并提供可访问名称，输出 `aria-valuemin / aria-valuemax / aria-valuenow / aria-valuetext`，方向通过 `aria-orientation` 表达，键盘必须支持方向键、PageUp/PageDown、Home/End。
- `DatePicker` 输入控件必须使用 `role="combobox"` 并提供可访问名称，展开状态必须输出 `aria-expanded="true|false"`，展开时必须通过 `aria-controls` 关联日历容器并通过 `aria-activedescendant` 指向当前日期格；日历格必须表达 `aria-selected`、禁用日期必须同步 `disabled / aria-disabled`，键盘必须支持方向键、PageUp/PageDown、Home/End、Enter、Escape。
- `TimePicker` 输入控件必须使用 `role="combobox"` 并提供可访问名称，展开状态必须输出 `aria-expanded="true|false"`，展开时必须通过 `aria-controls` 关联 listbox 并通过 `aria-activedescendant` 指向当前时间选项；选项必须使用 `role="option"` 与 `aria-selected`，键盘必须支持方向键、PageUp/PageDown、Home/End、Enter、Escape。
- `Image` 非装饰模式必须提供 alt 或等价可访问名称，根节点使用 `role="group"`；装饰模式必须 `aria-hidden="true"` 且空 alt，不得把装饰图片暴露给读屏。
- `Media` 根节点必须使用 `role="group"` 并提供可访问名称；音频和视频必须通过 title 或 i18n title key 提供可访问标题，通用媒体在无标题时必须提供 children 作为内容边界。
- `ErrorState` 根节点必须使用 `role="alert"` 并提供 `aria-label` 或 `aria-labelledby`；错误详情应使用 `details` part 展示，重试/返回等动作必须是真实按钮且受 disabled/loading 状态约束。
- `Dialog` Compound API 必须由 `Root` 统一管理 open 状态；`Trigger` 必须输出 `aria-haspopup="dialog" / aria-expanded / aria-controls`；`Content` 必须使用 `role="dialog"` 并按 modal 状态输出 `aria-modal`；关闭入口必须是真实按钮；Esc 关闭、关闭按钮关闭和可配置遮罩关闭必须可验证。
- `Popover` Compound API 必须由 `Root` 统一管理 open 状态；`Trigger` 必须输出 `aria-haspopup="dialog" / aria-expanded / aria-controls`；`Content` 必须使用非 modal `role="dialog"`；Esc 关闭必须可验证；`Arrow` 必须是 `aria-hidden="true"` 的装饰结构。
- `Tabs` Compound API 必须由 `Root` 统一管理选中值；`List` 必须使用 `role="tablist"`；`Trigger` 必须使用 `role="tab"`、输出 `aria-selected / aria-controls` 并支持方向键、Home、End roving focus；`Panel` 必须使用 `role="tabpanel"` 并通过 `aria-labelledby` 关联 Trigger。
- `Menu` Compound API 必须由 `Root` 统一管理 open 和高亮项；`Trigger` 必须输出 `aria-haspopup="menu" / aria-expanded / aria-controls`；`Content` 必须使用 `role="menu"`；`Item` 必须使用 `role="menuitem"` 并支持方向键、Home、End、Enter、Space、Escape；禁用项不得被键盘选中；`Group` 必须使用 `role="group"`，`Separator` 必须使用 `role="separator"`。
- `Select` Compound API 必须由 `Root` 统一管理 value/open 和高亮选项；`Trigger` 必须输出 `aria-haspopup="listbox" / aria-expanded / aria-controls`，展开时通过 `aria-activedescendant` 指向高亮 option；`Content` 必须使用 `role="listbox"`，默认 `data-placement="bottom-start"`，并作为触发器下方的非文档流浮层呈现，不得因展开而改变周边布局尺寸；`Option` 必须使用 `role="option"` 与 `aria-selected`；键盘必须支持方向键、Home、End、Enter、Space、Escape，禁用 option 不得被选择。
- `Form` Compound API 必须由 `Root`、`Section` 和 `Field` 统一管理结构语义；`Field` 必须为 `Label / Control / Error / Hint` 生成稳定关联，`Control` 必须输出 `id / aria-labelledby / aria-describedby / aria-invalid / aria-required` 等字段语义；原生控件可使用 `data-scope="form" data-part="control"`，自定义 Chips 控件必须保留自身 scope；错误必须通过 `Error` 与 `aria-live` 可感知，说明文本正式使用 `Hint`，不得继续扩散 `helper` 口径。组件库不实现业务校验、dirty/touched 或 Binding 状态。
- `DataGrid` Compound API 必须由 `Root` 统一管理排序、选择、禁用/加载/错误状态和键盘导航；`Root` 是外层容器，默认使用 `role="group"` 并提供可访问名称；实际网格区域或默认数据驱动 `table` 必须使用 `role="grid"` 并提供可访问名称；`Toolbar` 必须使用 `role="toolbar"`，`Pagination` 必须使用 `role="navigation"`；`Header / Row / Cell` 必须保留 row、columnheader、gridcell 语义，列头排序通过 `aria-sort` 表达，行选择通过 `aria-selected` 和 `data-selected` 表达。
- `Tree` Compound API 必须由 `Root` 统一管理展开、选择、活动项、禁用/加载/错误状态和键盘导航；`Root` 必须使用 `role="tree"` 并提供可访问名称；`Item / Branch / Leaf` 必须使用 `role="treeitem"`，输出 `aria-level / aria-setsize / aria-posinset`，选择状态通过 `aria-selected` 和 `data-selected` 表达；`Branch` 必须通过 `aria-expanded` 表达展开状态，并用 `group role="group"` 承载子树；`Disclosure` 默认不进入 Tab 顺序，方向键负责树级展开折叠。键盘必须支持 ArrowUp/ArrowDown、Home/End、ArrowRight 展开或进入子项、ArrowLeft 折叠或回父级、Enter/Space 选择，并跳过 disabled 节点。
- `CommandPalette` Compound API 必须由 `Root` 统一管理 open、query、高亮条目、禁用/加载/错误状态和命令触发边界；`Input` 必须使用 `role="combobox"`、提供可访问名称，并在展开时通过 `aria-controls` 关联 `List`，高亮条目通过 `aria-activedescendant` 或等价关系暴露；`List` 必须使用 `role="listbox"`；`Item` 必须使用 `role="option"` 与 `aria-selected / aria-disabled`；`Group` 必须使用 `role="group"`，有标题时通过 `aria-labelledby` 关联 `group-label`。键盘必须支持 ArrowUp/ArrowDown、Home/End、Escape、Enter/Space，选择命令仍走 Host command registry 或注入 adapter，不直接绑定业务函数。
- `NavigationSplitView` Compound API 必须由 `Root / Sidebar / Content / Detail` 显式组合；`Root` 必须使用 `role="group"` 并提供可访问名称；`Sidebar` 必须使用 `role="navigation"` 或原生 `nav` landmark 并提供可访问名称；`Content / Detail` 必须使用具名 `region`；分割线必须是装饰结构并 `aria-hidden="true"`。该组件只表达导航分栏语义和结构，不承载完整路由栈、NavigationLink 或命令注册逻辑。

## 2. 测试基线

- 单组件最少 5 个测试用例
- 契约测试 100% 通过
- 关键路径集成测试覆盖
- 回归测试包含主题切换与语言切换场景

## 3. 性能基线

- 主题切换可见完成 <= 150ms
- 渲染提交 p95 <= 32ms
- 长任务占比 <= 5%
- 组件库阶段性能力必须提供可复现基线脚本与报告（命令、数据规模、p95结果可追溯）

## 4. 发布基线

发布前必须通过：

- lint
- type-check
- unit test
- contract test
- a11y test
- perf test

任何一项失败即发布阻断。

阶段十发布补充门禁：

- `release:check`（发布包字段 + 门禁报告状态）
- 生态接入验收模板校验（`validate:ecosystem-acceptance`）

当前组件库仓库使用 `npm run verify` 作为聚合门禁入口，覆盖 `validate:tokens / build:tokens / validate:contracts / test:types / test`。
阶段九新增 `npm run quality:gate` 作为发布阻断入口，覆盖 `lint / typecheck / test:types / test / test:contracts / test:a11y / test:perf / quality:coverage / build`。
任务015第七批基线结果：默认主题和暗色主题的组件 contract view 已覆盖 `image / media / error-state` 的 token、CSS、contract 和测试；组件数量以当前组件库正式 contract 目录为准，完整发布阻断仍以本仓最新 `npm run quality:gate` 输出为准。

任务019质量门禁补充：

- `npm run quality:gate` 必须包含 `quality:coverage`。
- `quality:coverage` 读取组件库正式 contract 目录 `packages/theme-contracts/contracts/components`，并以 `@chips/testing` 的 `CHIPS_COMPONENT_QUALITY_MATRIX` 作为组件矩阵来源。
- 新增公开组件 contract 时，必须同一提交补齐矩阵条目、contract attr fixture、ARIA fixture、状态优先级、必要的 perf smoke 场景和对应测试。
- 组件矩阵漂移、缺失 `data-scope/data-part/data-state` fixture、缺失 ARIA fixture、状态优先级未覆盖 contract states、perf smoke 场景缺失，均为发布阻断。
- `quality:coverage` 必须输出机器可读报告：`reports/quality-gate/component-quality-coverage-latest.json`。
- `quality:gate` 顶层报告必须包含机器可读 `schemaVersion`、`summary` 与全部阻断步骤状态。
- 第一版当前机器基线以最新报告为准：`quality-gate-latest.json` 状态为 `passed`，9 个步骤全部通过；`component-quality-coverage-latest.json` 状态为 `passed`，包含 71 个组件 contract、71 个质量矩阵条目、676 个 raw required token、71 个 a11y fixture、71 个 contract attr fixture 和 3 个 perf smoke 场景。该 `676` 数字是 raw contract token 覆盖统计，主题 contract view 仍会额外合并 `motionConstraints[].tokenKeys` 作为主题应用门禁 required token。

## 5. iframe 高级组件附加基线

- `CardCoverFrame` 与 `CompositeCardWindow` 的主题 contract 必须声明 `iframe.requiredSandbox: true`，生命周期事件为 `ready/error`；普通无头组件不声明 iframe contract。
- iframe 沙箱权限必须最小化
- 复合卡片节点失败时必须可降级，不可整窗崩溃
- SDK 显示接口在查看器/编辑器场景表现必须一致

## 6. 日志与可观测性

组件级错误至少包含：

- `traceId`
- `component`
- `action`
- `errorCode`
- `durationMs`

用于问题定位与质量审计。

## 7. A11y 工具基线

组件库应提供可复用基础工具，并在组件实现中统一复用：

- 键盘意图识别（activate/navigate/dismiss）
- ARIA 规则校验与断言
- 焦点元素收集与顺序移动工具
- `FocusScope` 焦点域、focus trap 和关闭后焦点恢复工具
- roving tabindex 模型与方向键/Home/End 映射工具
- 键盘测试、焦点恢复测试、active descendant 测试辅助

禁止在各组件内部重复实现不一致的键盘/焦点逻辑。

正式工具与交互模型见 `11-焦点键盘与A11y交互模型.md`。`Dialog / Menu / Select / Tabs / DataGrid` 的重点键盘路径必须纳入 `npm run test:a11y`；后续新增复杂组件时，必须先补组件级键盘和焦点回归，再进入质量门禁。
