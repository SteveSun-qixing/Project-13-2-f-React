# 焦点键盘与 A11y 交互模型

> 文档状态：生态共用公开规范
> 适用范围：应用插件、卡片插件、布局插件、组件库、脚手架、测试工具
> 修订日期：2026-05-24

## 1. 定位

`@chips/a11y` 是薯片生态 L10 无头组件层的焦点、键盘和可访问性基础工具包。它只提供 DOM 语义、焦点顺序、键盘意图和 ARIA 校验工具，不承载 Host 运行时能力，也不直接调用 `window.chips.*`。

L8 声明式 UI 的 `focusScope` modifier 只声明焦点域语义；具体 DOM 焦点收集、focus trap、焦点恢复和 roving tabindex 由 L10 组件库执行。应用业务层不得绕开组件库维护另一套长期焦点系统。

## 2. 键盘模型

所有可键盘操作组件必须先把原始 `event.key` 归一化，再映射为语义 action：

- `normalizeKeyboardKey(eventOrKey)`：归一化 `Esc -> Escape`、`Spacebar/Space -> " "`、`Up/Down/Left/Right -> Arrow*`。
- `createKeyboardMap(definition)`：把 action 映射到一个或多个标准 key。
- `getKeyboardAction(eventOrKey, keyboardMap)`：返回当前 key 对应 action。
- `getKeyboardIntent(key)`：返回 `activate / dismiss / navigate / unknown`。

正式默认 action：

| action | key |
|---|---|
| `activate` | `Enter`、`Space` |
| `dismiss` | `Escape` |
| `navigate` | `Tab` |
| `next` | `ArrowDown`、`ArrowRight` |
| `previous` | `ArrowUp`、`ArrowLeft` |
| `first` | `Home` |
| `last` | `End` |

方向性 roving 组件必须使用方向专用 map：

- 横向：`ArrowRight / ArrowLeft / Home / End`
- 纵向：`ArrowDown / ArrowUp / Home / End`

## 3. 焦点域模型

`FocusScope` 是一组可聚焦元素的运行时焦点域，正式能力包括：

- 收集可聚焦元素：`getFocusableElements(root)`
- 聚焦第一个/最后一个元素：`focusFirst()`、`focusLast()`
- 在域内移动焦点：`move({ direction })`
- 拦截 Tab 循环：`trap(event)` 或 `handleKeyDown(event)`
- 恢复打开前焦点：`restore()`

Dialog、Menu、Select、CommandPalette 等弹层组件必须记录打开前焦点，并在关闭后恢复到触发元素或显式 fallback。Modal Dialog 必须启用 Tab focus trap；非 modal Popover 可关闭但不强制 trap。

## 4. Roving Tabindex

复合列表类组件必须使用 roving tabindex 表达单一 Tab 入口：

- 当前可操作项：`tabIndex=0`
- 其他可操作项：`tabIndex=-1`
- 禁用项：`tabIndex=-1`，并同步 `disabled` 或 `aria-disabled`

正式工具：

- `createRovingTabIndex(items, options)`
- `getRovingIndexByKey(items, currentIndex, eventOrKey, options)`
- `getRovingTabIndexProps(rovingItem)`

适用组件：

- `Tabs.Trigger`
- `Menu.Item`
- `Select.Option`
- `SegmentedControl` 分段项
- `Tree` 活动节点
- `CommandPalette.Item`

虚拟焦点组件如果焦点停留在输入框或触发器上，必须通过 `aria-activedescendant` 指向当前高亮项。

## 5. ARIA 校验

`validateAriaProps(props, rules)` 与 `assertAriaProps(props, rules)` 是组件库和测试工具共享的基础校验入口。正式规则支持：

- `requireLabel`
- `role` 单值或列表
- `requiredProps`
- `requireControlsWhenExpanded`
- `requireActiveDescendantWhenExpanded`
- `requireSelected`
- `requireChecked`

组件级完整规则仍以 `05-可访问性与质量基线.md` 为主发布位置；本文件只定义共享工具和交互模型。

## 6. Testing Helper

`@chips/testing` 提供与本模型配套的测试辅助：

- `createKeyboardEventFixture`
- `runKeyboardSequence`
- `assertRovingTabIndex`
- `assertActiveDescendant`
- `assertFocusRestored`
- `createFocusTrapFixture`

组件库 `npm run test:a11y` 必须覆盖：

- `@chips/a11y` 单元测试
- 组件 ARIA 规则测试
- Dialog/Menu/Select/Tabs/DataGrid 重点键盘路径

质量门禁 `npm run quality:gate` 必须包含 `test:a11y`。后续新增复杂组件时，必须同步补充键盘和焦点回归测试。
