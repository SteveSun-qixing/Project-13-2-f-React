# 组件库对外使用总览

## 1. 组件库定位

薯片组件库是生态统一的无头组件标准实现，提供：

- 稳定交互行为
- 标准化结构语义
- 统一主题接口点
- 可访问性基础能力

技术基线：React + Ark UI + Style Dictionary + Tamagui (Core)。

官方统一接入包名为 `@chips/component-library`。该包是组件库聚合入口，正式聚合：

- `@chips/hooks`
- `@chips/components`
- `@chips/card-runtime`

焦点、键盘和可访问性工具由 `@chips/a11y` 独立提供；测试辅助由 `@chips/testing` 独立提供。二者是生态公共能力包，可被组件库、脚手架和应用测试直接消费，但不承载 Host 运行时能力。

正式 TypeScript 工程必须直接消费这些包随包发布的声明文件：

- 聚合入口 `@chips/component-library` 已正式提供 `types` / `exports.types`
- 子包 `@chips/hooks`、`@chips/components`、`@chips/card-runtime` 已同步提供声明入口
- 子包 `@chips/a11y`、`@chips/testing` 已同步提供声明入口
- 禁止在业务工程本地补写 `declare module '@chips/component-library'`

## 2. 使用边界

允许：

- 在应用插件、卡片插件、布局插件中直接使用组件库导出组件
- 按主题契约覆盖视觉表现
- 通过组合模式构建业务 UI

禁止：

- 绕过组件库直接复制 Ark UI 内部实现作为生态标准
- 在业务页面硬编码组件视觉值
- 改写组件契约字段语义

## 3. 最小接入步骤

1. 安装组件库与对应 peer 依赖
2. 在页面根节点接入组件库 Provider
3. 保证主题变量注入可用
4. 使用组件库基础组件替代自建基础控件
5. 完成契约测试与 a11y 检查

生态一方仓库内，组件库依赖统一声明为正式 semver 版本，并由根工作区自动链接到本地 `@chips/component-library` 包；禁止继续通过 `file:` 指向 `Chips-ComponentLibrary/packages/...`。

## 4. 对主题包的要求

- 主题包必须覆盖组件契约要求的 token key
- 必须支持 `data-scope/data-part/data-state` 选择器
- 不允许在主题中修改组件结构语义
- 必须遵循主题权重链（低 -> 高）：`global -> app -> box -> composite-card -> base-card -> component`
- token 查找必须按“高权重优先，缺失逐层向上回退”执行

`ChipsText / ChipsLabel / ChipsIcon` 是任务015第一批基础展示控件。它们只提供语义、状态、a11y 和主题 contract 挂点：`Text` 用于普通文本输出，`Label` 用于控件标签和必填/错误状态，`Icon` 用于运行时 Material Symbols 图标渲染。业务应用不得继续维护私有文本、标签或运行时图标基础控件。

`ChipsIconButton / ChipsToggleButton / ChipsBadge / ChipsTag / ChipsAvatar / ChipsSpinner / ChipsProgress / ChipsRating` 是任务015第二批基础控件。`IconButton` 和 `ToggleButton` 采用独立 `data-scope`，但复用按钮族交互语义；`Badge / Tag / Avatar` 承担轻量展示和标识；`Spinner / Progress` 承担加载与进度反馈；`Rating` 承担有限项评分展示和选择，使用 `radiogroup/radio` 语义、方向键/Home/End 键盘模型与 `IconDescriptor` 图标。业务应用不得继续私造这些基础控件，也不得把 `ChipsButton toggleable`、按钮内部 `spinner` part、私有图标按钮组或错误边界等相邻能力口头等同为这些正式控件。

`ChipsTextField / ChipsTextArea / ChipsSearchField / ChipsSecureField` 是任务015第三批基础输入控件。四者分别使用 `text-field / text-area / search-field / secure-field` 独立 scope，并统一暴露 `label / control / description / status` 语义；`SearchField` 额外暴露 `search-icon / clear`，`SecureField` 额外暴露 `visibility-toggle / visibility-icon`。业务应用不得继续把旧 `ChipsInput`、私有搜索框或密码框样式等同为这些正式控件。

`ChipsSegmentedControl / ChipsComboBox` 是任务015第四批选择扩展控件。`SegmentedControl` 使用 `segmented-control` 独立 scope，公开 `root / item / indicator / label / status`，采用 `radiogroup/radio` 语义表达单选分段选择；`ComboBox` 使用 `combo-box` 独立 scope，公开 `root / label / control / trigger / list / option / description / status`，采用 `combobox/listbox/option` 语义表达输入过滤、弹层和 `aria-activedescendant`。业务应用不得把 `ChipsRadioGroup`、`ChipsSelect` 或旧输入框组合口头等同为这些正式控件。

`ChipsNumberInput / ChipsStepper / ChipsSlider` 是任务015第五批数值控件。`NumberInput` 使用 `number-input` 独立 scope，公开 `root / label / control / decrement / increment / description / status`，采用 `spinbutton` 语义表达可编辑数值输入、解析、步进、边界和错误状态；`Stepper` 使用 `stepper` 独立 scope，公开 `root / label / decrement / value / increment / status`，采用真实按钮和 `group` 语义表达离散增减控制；`Slider` 使用 `slider` 独立 scope，公开 `root / label / track / range / thumb / value / status`，由 `thumb` 承载 `role="slider"`、键盘增减、指针拖拽和值文本语义。业务应用不得继续用旧 `ChipsInput`、私有按钮组合、只读文本或私造 range 控件作为过渡替代这些正式数值控件。

`ChipsImage / ChipsMedia / ChipsErrorState` 是任务015第七批图像、媒体和静态错误展示控件。`Image` 使用 `image` 独立 scope，公开 `root / media / fallback / caption / status`，负责静态图片、装饰图片、加载/错误 fallback、说明文本和 alt 语义；`Media` 使用 `media` 独立 scope，公开 `root / content / controls / control / caption / status`，负责音频、视频或通用媒体内容边界和可访问标题；`ErrorState` 使用 `error-state` 独立 scope，公开 `root / icon / title / description / details / action / status`，负责静态错误展示、详情和重试动作视觉。业务应用不得把 `ChipsAvatar`、`ChipsErrorBoundary` 或 `ChipsEmptyState` 口头等同为这些正式控件。

`ChipsDialog / ChipsPopover / ChipsTabs` 是任务016第一批复杂组件 Compound API。复杂组件正式推荐通过静态子组件组合，不再把可变结构塞入单体 props：

```tsx
<ChipsDialog.Root defaultOpen={false}>
  <ChipsDialog.Trigger aria-label="Open settings">Open</ChipsDialog.Trigger>
  <ChipsDialog.Content>
    <ChipsDialog.Header>Settings</ChipsDialog.Header>
    <ChipsDialog.Body>Dialog body</ChipsDialog.Body>
    <ChipsDialog.Footer>
      <ChipsDialog.Actions>
        <ChipsDialog.Close aria-label="Close settings">Close</ChipsDialog.Close>
      </ChipsDialog.Actions>
    </ChipsDialog.Footer>
  </ChipsDialog.Content>
</ChipsDialog.Root>

<ChipsPopover.Root>
  <ChipsPopover.Trigger aria-label="Open details">Details</ChipsPopover.Trigger>
  <ChipsPopover.Content>
    <ChipsPopover.Arrow />
    Popover content
  </ChipsPopover.Content>
</ChipsPopover.Root>

<ChipsTabs.Root defaultValue="general">
  <ChipsTabs.List aria-label="Settings sections">
    <ChipsTabs.Trigger value="general">General</ChipsTabs.Trigger>
    <ChipsTabs.Trigger value="advanced">Advanced</ChipsTabs.Trigger>
  </ChipsTabs.List>
  <ChipsTabs.Panel value="general">General panel</ChipsTabs.Panel>
  <ChipsTabs.Panel value="advanced">Advanced panel</ChipsTabs.Panel>
</ChipsTabs.Root>
```

`Dialog` 的公开 part 为 `root / trigger / backdrop / content / header / body / footer / actions / close / status`；`Popover` 的公开 part 为 `root / trigger / content / arrow / status`，内部定位容器不得作为主题包或业务层依赖的公开 part；`Tabs` 的公开 part 为 `root / list / trigger / panel / status`。Dialog Esc/Close、Popover Esc、Tabs 方向键/Home/End roving focus 都属于组件库 L10 状态机职责，业务层只组合 slot 和注入语义内容。

任务018后，`Dialog` 正式通过 `FocusScope` 执行 modal Tab focus trap，并在关闭后恢复到触发元素；`Tabs.Trigger`、`Menu.Item` 和 `Select.Option` 的 roving tabindex 统一由 `@chips/a11y` 模型计算。业务层不得为这些组件另写长期私有焦点环、方向键移动或关闭恢复逻辑。

`ChipsMenu / ChipsSelect` 是任务016第二批复杂组件 Compound API。`Menu` 的正式子组件为 `Root / Trigger / Content / Item / Group / Separator`，公开 part 为 `root / trigger / content / item / group / group-label / separator / status`；`Group` 可通过 `label` 生成 `group-label`，`Separator` 必须使用 `role="separator"`，菜单项高亮通过 `data-highlighted="true"` 与标准 `data-state="hover"` 同步表达。`Select` 的正式子组件为 `Root / Trigger / Content / Option / Value`，公开 part 为 `root / trigger / value / icon / content / option / status`；`Select.Content` 对应唯一正式 DOM part `content`，不再公开 `list` 口径；展开时 `Content` 是锚定 `Root/Trigger` 下方的非文档流 listbox 浮层，默认 `data-placement="bottom-start"`，并通过 `--chips-select-content-gutter / --chips-select-content-min-inline-size / --chips-select-content-max-block-size` 结构变量控制间距、触发器宽度对齐和滚动边界；`Option` 必须使用 `role="option"`、`aria-selected`，并用 `data-highlighted / data-selected` 与标准 `data-state` 同步表达高亮和选中。

`ChipsForm` 是任务016第三批复杂组件 Compound API。正式子组件为 `Root / Section / Field / Label / Control / Error / Hint`，公开 part 为 `root / section / field / label / required / control / error / hint / status`，统一使用 `data-scope="form"`；`Field` 负责字段级 required/disabled/readOnly/error 状态、稳定 id、`aria-describedby` 聚合和上下文分发；`Label` 关联当前字段 control；`Control` 只在原生 `input/textarea/select/button` 上输出 `form/control` part，自定义 Chips 控件保持自己的 `data-scope`，只接收 id、`aria-labelledby`、`aria-describedby`、`aria-invalid`、required/disabled/readOnly 等语义属性；`Error` 与 `Hint` 只表达错误和说明文本，不承载业务校验。`form-field`、`form-group` 和 `helper` 不再是正式公开表单契约。

`ChipsDataGrid` 是任务016第四批复杂组件 Compound API。正式子组件为 `Root / Toolbar / Header / Row / Cell / Pagination`，公开 part 为 `root / toolbar / header / row / cell / pagination / status`，统一使用 `data-scope="data-grid"`；`Root` 负责排序、选择、禁用/加载/错误状态、键盘导航和上下文分发，默认数据驱动模式仍渲染真实 `table role="grid"`，但 `table` 不再是主题包或 L8 可依赖的公开 part；`Toolbar` 使用 `role="toolbar"`，`Pagination` 使用 `role="navigation"`；`Header` 表达表头行，`Cell header=true` 表达列头并输出 `aria-sort`、`data-sort` 与 `data-sortable`；`Row` 使用 `aria-selected`、`data-selected` 与 `data-active` 表达选择和活动行。主题包必须使用 `data-selected="true"` 表达选中行视觉，不得把选中行绑定到标准 `data-state="active"`。

`ChipsTree` 是任务016第五批复杂组件 Compound API。正式子组件为 `Root / Item / Branch / Leaf / Disclosure`，公开 part 为 `root / item / branch / leaf / disclosure / label / group / status`，统一使用 `data-scope="tree"`；`Root` 负责展开、选择、活动项、禁用/加载/错误状态、方向键/Home/End/Enter/Space 键盘导航和上下文分发。`Branch / Leaf / Item` 都承载 `role="treeitem"`，输出 `aria-level / aria-setsize / aria-posinset / aria-selected / data-selected / data-active`，`Branch` 额外输出 `aria-expanded` 并通过 `group role="group"` 承载子节点。`Disclosure` 只作为分支的展开折叠控制，不进入 Tab 顺序；旧 `node / toggle / children` 不再是公开 part 或 L8 slot。主题包必须使用 `data-selected="true"` 表达选中节点视觉，层级缩进通过 `--chips-tree-level` 与 `chips.comp.tree.branch.indent` token 计算，不在组件运行时硬编码像素。

`ChipsNavigationSplitView` 是任务016第七批复杂组件 Compound API。正式子组件为 `Root / Sidebar / Content / Detail`，公开 part 为 `root / sidebar / content / detail / divider / status`，统一使用 `data-scope="navigation-split-view"`；`Root` 是导航分栏语义容器，默认 `role="group"` 并必须通过 `aria-label` 或 `aria-labelledby` 提供可访问名称。`Sidebar` 默认渲染为 `nav role="navigation"`，`Content / Detail` 默认渲染为 `section role="region"`，三者都必须提供可访问名称。`NavigationSplitView` 不等同 `ChipsSplitView`：前者表达导航侧栏、内容栏和详情栏的语义结构，后者仍是通用 `primary / secondary / detail` 布局原语；主题包和 L8 slot 不得把 `primary / secondary` 当作 `navigation-split-view` 的公开入口。

布局原语是组件库的无头布局基座，只提供结构、状态、ARIA 与主题契约入口；默认视觉由主题包按 token 和 `data-scope/data-part/data-state` 实现。布局原语禁止在业务层复制私有版本，应用、卡片插件、箱子布局插件应优先通过 `@chips/component-library` 消费上述正式导出。

聚合入口如果遇到跨子包同名 helper，必须通过正式别名收口，不允许让业务层依赖 `export *` 的歧义结果。当前正式别名为：

- `toComponentStandardError`
- `toCardRuntimeStandardError`

具体契约见：`02-组件契约标准.md`。

## 5.1 命令消费组件

命令消费组件以 Host `command.*` registry 为唯一动作来源：

- `ChipsToolbar / ChipsToolbarItem`：消费 `toolbarPlacement`，触发时以 `source="toolbar"` 调用 command。
- `ChipsMenuBar`：消费 `menuPlacement`，触发时以 `source="menu"` 调用 command。
- `ChipsContextMenu`：消费 `menuPlacement`，触发时以 `source="context-menu"` 调用 command。
- `ChipsCommandPalette`：正式 Compound API 为 `Root / Input / List / Item / Group`，可继续通过 `items` 数据驱动 fallback 或消费 command views；当接入 command views 时，`Item` 选择仍以 `source="palette"` 调用 command。
- `ChipsShortcut`：只负责快捷键视觉语义展示，真实快捷键注册与触发仍由 Host command/shortcut 链路承担。

组件库不直接持有 Host runtime，也不把 SDK 运行时主实现搬入组件内部。应用或脚手架应通过 `createCommandAdapter(client)` 或同形 adapter 注入：

```tsx
<ChipsCommandProvider adapter={createCommandAdapter(client)} i18n={t}>
  <ChipsToolbar toolbarId="main" ariaLabel="Main toolbar" />
  <ChipsMenuBar ariaLabel="Application menu" />
  <ChipsCommandPalette ariaLabel="Command palette" inputPlaceholder="Search commands" />
</ChipsCommandProvider>
```

命令文案必须来自 `titleKey / descriptionKey / ariaLabelKey`，组件只做 i18n key 解析和 fallback，不接收 `title / description / ariaLabel / label` 等原始命令字段作为正式 command schema。

## 5.2 React Environment Hooks

React 应用的 Host 环境接入应优先使用 `@chips/hooks`，并可通过 `@chips/component-library` 聚合入口直接消费。

当前正式环境入口包括：

- `ChipsEnvironmentProvider`
- `useChipsEnvironment`
- `useChipsClient`
- `useChipsTheme`
- `useChipsI18n`
- `createChipsI18nText`
- `useChipsI18nText`
- `useChipsSurface`
- `useChipsPermission`
- `useChipsCommand`
- `useChipsDiagnostics`

当前正式 State / Binding / Form 入口包括：

- `createBinding`
- `useBinding`
- `useChipsBinding`
- `useChipsState`
- `useChipsAsyncState`
- `useChipsFormState`
- `useFieldBinding`

使用边界：

- Provider 接收 SDK `createClient()` 创建的 client，或测试中注入的同形 mock client；
- hooks 内部只通过 SDK client / Bridge 正式链路读取 theme、i18n、surface、permission、command 与 diagnostics；
- hooks 不直接访问 Host 内部模块，不复制 Host runtime 主实现；
- `useChipsCommand()` 只暴露 SDK command API，命令 UI 仍通过 `ChipsCommandProvider/createCommandAdapter` 消费 Host `command.*` registry；
- `useChipsI18nText()` 提供 React render 可同步调用的本地语言包 adapter，读取 `useChipsI18n().locale` 并按当前 locale、fallback locale、默认 locale 顺序解析 key；
- 测试可用 `@chips/testing` 的 `createMockChipsClient/createMockChipsEnvironment` 构造组件 Provider mock 环境；需要验证 SDK action、Bridge、权限、timeout/retry 等语义时，以 `chips-sdk/testing` 为正式 Host 模拟器入口。

组件库测试边界：

- `@chips/testing` 主责组件契约断言、ARIA/状态 fixture、主题 fallback fixture 与 React Provider 注入适配；
- `@chips/testing.createMockChipsClient()` 保持与 SDK mock helper 同形的 calls/state/events/fault 语义，方便 hooks 测试；
- `chips-sdk/testing` 是应用插件和工具链测试公开 Host simulator 的主发布位置，后续跨项目测试 fixture 应优先沉淀到 SDK testing，而不是在组件库复制 Host 语义。

推荐根接线：

```tsx
const client = createClient();

<ChipsEnvironmentProvider client={client}>
  <ChipsThemeProvider themeId="chips-official.default-theme" version="1.0.0">
    <App />
  </ChipsThemeProvider>
</ChipsEnvironmentProvider>
```

同步文案接线：

```tsx
const text = useChipsI18nText({
  bundles: localeBundles,
  defaultLocale: "zh-CN",
  fallbackLocale: "en-US"
});

<ChipsCommandProvider adapter={createCommandAdapter(client)} i18n={text}>
  <ChipsToolbar toolbarId="main" ariaLabel={text("app.toolbar")} />
</ChipsCommandProvider>
```

`useChipsI18n().translate/t` 保持异步 Host 翻译接口语义；组件 render、命令标题解析与示例面板文案应使用同步 adapter，避免在渲染期等待异步翻译。

状态和表单绑定推荐通过 `useChipsState`、`useChipsFormState` 与 `ChipsBinding` 适配到组件现有受控 props。组件库不新增私有 `binding` prop；输入、选择、复选、开关和展开类组件继续分别使用 `value/onValueChange`、`checked/onCheckedChange`、`open/onOpenChange` 或原生 `value/onChange`。正式规范见 `10-状态环境与Binding模型.md`。

## 6. 统一文档显示链路共识

- 查看器、编辑器等应用通过 SDK 统一显示接口传入卡片文件或箱子文件。
- `EmbeddedDocumentFrame` 是统一的受控文档 iframe 基组件，可消费受控 `src` 或受控 `srcDoc`。
- 卡片封面显示必须走 `Host card.renderCover -> SDK client.card.coverFrame.render(...) -> CardCoverFrame` 正式链路。
- 箱子本体封面必须走 `Host box.renderCover -> SDK client.box.renderCover(...) -> EmbeddedDocumentFrame` 正式链路。
- 箱子条目封面必须优先走 `box.renderEntryCover`，再由应用层把 `coverUrl` 交给 `EmbeddedDocumentFrame` 或更高层包装组件。
- `CardCoverFrame` 只消费受控 `coverUrl`，不得通过 `srcdoc` 或任意 HTML 字符串拼接封面。
- `EmbeddedDocumentFrame` 的 `srcDoc` 只适用于受控本地生成内容，例如布局编辑器背景预览、顶部内容区等，不得把正式卡片 / 箱子封面链路退化为任意 HTML 字符串直传。
- 封面 iframe 内容完全由 `.card/cover.html` 决定，资源按 `.card/` 目录解析。
- 箱子封面 iframe 内容完全由 `.box/cover.html` 决定，资源按 `.box/` 目录解析。
- 复合窗口模式仅 `view | preview`，禁止自定义未约定 mode 值。
- Host 内置渲染运行时负责基础卡片分发、模板编译、iframe 拼接；SDK 仅提供开发封装。
- 复合卡片 iframe 事件应按窗口来源与 origin 白名单双重过滤。
- 应用层仅承担窗口承载与业务外壳，不重复实现渲染引擎。
