# 主题接口规范

## 概述

主题接口规范定义主题系统与外部模块之间的交互方式。规范包括主题查询、加载、应用等核心接口。

> **设计理念**：薯片生态采用**自管理前端架构**，组件库只负责功能逻辑、结构和布局，完全不包含样式。所有视觉表现由主题包提供，主题系统负责管理这些视觉资源的生命周期。

## 固定公开接口

以下接口为生态统一的公共接口，所有实现必须遵循：

| 接口 | 说明 | 幂等 |
|---|---|---|
| `theme.list` | 获取当前工作区中所有已启用主题列表 | 是 |
| `theme.apply` | 切换当前主题 | - |
| `theme.getCurrent` | 获取当前活动主题 | 是 |
| `theme.getAllCss` | 获取当前主题的完整 CSS | 是 |
| `theme.resolve` | 解析主题依赖链 | 是 |
| `theme.contract.get` | 获取主题契约接口 | 是 |

### theme.list

获取当前工作区中所有已启用主题列表。

```typescript
// 请求
{ publisher?: string }

// 响应
{
  themes: Array<{
    id: string;
    displayName: string;
    version: string;
    isDefault: boolean;
    publisher?: string;
  }>
}
```

### theme.apply

切换当前主题。

```typescript
// 请求
{ id: string }

// 响应
{ success: boolean; themeId: string }
```

### theme.getCurrent

获取当前活动主题。

```typescript
// 请求
{ appId?: string; pluginId?: string }

// 响应
{
  themeId: string;
  displayName: string;
  version: string;
}
```

### theme.getAllCss

获取当前主题的完整 CSS 代码与当前 `themeId`。

```typescript
// 请求
{}

// 响应
{ css: string; themeId: string }
```

`theme.getAllCss` 返回的是主题包 `dist/theme.css` 及其父链 CSS 的拼接结果，负责 `@font-face`、基础 CSS 与组件 `data-scope/data-part/data-state` 样式。完整 token 变量不在该接口内展开，调用方必须同时消费 `theme.resolve` 的 `tokens` 并注入为 `--chips-*` CSS variables。Host 内置插件窗口、卡片 iframe 与箱子布局链路都必须使用 `theme.getAllCss + theme.resolve` 的组合模型。

主题包源码和 `theme.getAllCss` 可以保留生态布局逻辑单位 `cpx`。当 Host 将主题 CSS 或 `theme.resolve.tokens` 注入浏览器普通 CSS 环境时，必须先把数值型 `cpx` 长度按 1024 设计基准转换为浏览器可识别的响应式长度；例如 `12cpx` 注入为 `1.171875vw`，`160cpx` 注入为 `15.625vw`。应用插件、基础卡片、复合卡片和箱子布局不得在业务层自行把主题 token 硬改为 `px`。

### theme.resolve

解析主题及其依赖链。该接口必须返回解析后的 token 视图、主题链、诊断列表与诊断摘要；调用方不得只依赖异常判断主题健康状态。

```typescript
// 请求
{ chain: string[] }

// 响应
{
  resolved: Array<{
    id: string;
    displayName: string;
    version: string;
    order: number;
  }>;
  tokens: {
    [key: string]: unknown; // 解析后的主题 token 视图（按作用域链与覆盖规则合并）
  };
  diagnostics: ThemeDiagnostic[];
  summary: ThemeDiagnosticSummary;
}
```

### theme.contract.get

获取主题契约接口定义。

```typescript
// 请求
{ component?: string }

// 响应
{
  schemaVersion: string;
  themeId: string;
  themeVersion: string;
  contractVersion: string;
  components: ThemeContractComponentView[];
  summary: ThemeDiagnosticSummary;
}
```

该接口读取已安装主题包 manifest 指向的 `contracts/theme-interface.contract.json`。官方主题包中的该文件必须由组件库正式 component contract 生成；Host 运行时不直接访问开发工作区中的组件库源码。

### 主题 Contract View

`theme.contract.get` 的响应是主题治理公共视图，Host、SDK、主题包校验器、组件库 validator 和设置面板必须使用同一 schema。

```typescript
interface ThemeContractView {
  schemaVersion: string;
  themeId: string;
  themeVersion: string;
  contractVersion: string;
  components: ThemeContractComponentView[];
  summary: ThemeDiagnosticSummary;
}

interface ThemeContractComponentView {
  component: string;
  scope: string;
  parts: string[];
  states: string[];
  requiredTokens: string[];
  optionalTokens: string[];
  a11yConstraints: ThemeConstraint[];
  motionConstraints: ThemeConstraint[];
  coverage: ThemeContractCoverage;
  diagnostics: ThemeDiagnostic[];
}

interface ThemeContractCoverage {
  requiredTokenCount: number;
  coveredRequiredTokenCount: number;
  missingRequiredTokenCount: number;
  optionalTokenCount: number;
  coveredOptionalTokenCount: number;
  missingOptionalTokenCount: number;
  requiredCoverage: number; // 0-1
  optionalCoverage: number; // 0-1
  status: 'complete' | 'warning' | 'blocked';
}

interface ThemeConstraint {
  key: string;
  messageKey?: string;
  details?: Record<string, unknown>;
}
```

旧组件 contract 文件中的 `tokens` 字段在公共 view 中统一归一为 `requiredTokens`。新增 contract 应优先写 `requiredTokens / optionalTokens`。

### 主题诊断 Schema

```typescript
interface ThemeDiagnostic {
  severity: 'info' | 'warning' | 'error';
  code: string;
  messageKey: string;
  themeId?: string;
  sourceThemeId?: string;
  component?: string;
  part?: string;
  state?: string;
  tokenKey?: string;
  layer?: 'ref' | 'sys' | 'comp' | 'motion' | 'layout';
  scope?: string;
  suggestionKey?: string;
  details?: unknown;
  blocking: boolean;
}

interface ThemeDiagnosticSummary {
  total: number;
  blocking: number;
  bySeverity: Record<'info' | 'warning' | 'error', number>;
  byCode: Record<string, number>;
  status: 'complete' | 'warning' | 'blocked';
  coverage?: ThemeCoverageSummary;
}

interface ThemeCoverageSummary {
  componentCount: number;
  coveredComponentCount: number;
  requiredTokenCount: number;
  coveredRequiredTokenCount: number;
  missingRequiredTokenCount: number;
  optionalTokenCount: number;
  coveredOptionalTokenCount: number;
  missingOptionalTokenCount: number;
  requiredCoverage: number; // 0-1
  optionalCoverage: number; // 0-1
}
```

`blocking=true` 的诊断会阻断 `theme.apply`；非阻断诊断用于设置面板、CLI 和测试报告展示。

## 事件接口

### theme.changed

主题切换事件。当主题发生变化时触发。

当前事件载荷必须包含：`previousThemeId`、`themeId`、`themeVersion`、`timestamp`、`diagnosticsSummary`。

```typescript
// 事件载荷
{
  previousThemeId: string;
  themeId: string;
  themeVersion: string;
  timestamp: number;
  diagnosticsSummary: ThemeDiagnosticSummary;
}

// 订阅方式
window.chips.on('theme.changed', (payload) => {
  console.log('主题已切换:', payload.themeId);
});
```

> **注意**：事件命名统一采用点语义 `theme.changed`，禁止使用冒号或其他分隔符。

## 作用域链

主题系统支持级联作用域，利用 CSS 自定义属性的天然级联特性实现多层级主题覆盖。

### 层级架构

```
主题权重从低到高：

全局主题        ← 最低权重
应用级主题
箱子级主题
复合卡片级主题
基础卡片级主题
组件级主题      ← 最高权重（最小组件）
```

解析顺序（高权重优先，缺失逐层向上）：
`component -> base-card -> composite-card -> box -> app -> global`

### 覆盖规则

1. **作用域优先级**：近者优先（component > base-card > composite-card > box > app > global）
2. **选择器特异性**：特异性越高越优先
3. **声明顺序**：同一作用域内，后声明的覆盖先声明的

## 错误处理

所有主题操作遵循统一错误结构：

```typescript
interface ThemeError {
  code: string;
  message: string;
  details?: unknown;
  retryable?: boolean;
}
```

### 标准错误码

| 错误码 | 说明 | 可重试 |
|---|---|---|
| `THEME_NOT_FOUND` | 主题不存在 | false |
| `THEME_CONTRACT_INVALID` | 主题契约无效 | false |
| `THEME_DEPENDENCY_ERROR` | 依赖主题加载失败 | true |
| `THEME_PERMISSION_DENIED` | 权限不足 | false |
| `THEME_LOAD_FAILED` | 主题加载失败 | true |
| `THEME_CSS_PARSE_ERROR` | CSS 解析错误 | false |
| `THEME_TOKEN_MISSING` | token 引用目标不存在 | false |
| `THEME_TOKEN_CYCLE` | token 存在循环引用 | false |

### 错误示例

```typescript
// 主题不存在
{
  code: "THEME_NOT_FOUND",
  message: "主题 chips-official.default-theme 不存在",
  details: { themeId: "chips-official.default-theme" },
  retryable: false
}

// 权限不足
{
  code: "THEME_PERMISSION_DENIED",
  message: "当前用户无权限切换主题",
  details: { requiredPermission: "theme.write" },
  retryable: false
}
```

## 类型定义

```typescript
// 主题信息
interface ThemeInfo {
  id: string;
  displayName: string;
  version: string;
  isDefault: boolean;
  publisher?: string;
  parentTheme?: string;
}

// 主题配置
interface ThemeConfig {
  id: string;
  tokens: {
    ref: Record<string, unknown>;
    sys: Record<string, unknown>;
    comp: Record<string, unknown>;
    motion: Record<string, unknown>;
    layout: Record<string, unknown>;
  };
  contracts: ThemeContract[];
}

// 解析结果
interface ThemeResolveResult {
  resolved: ThemeInfo[];
  tokens: Record<string, unknown>;
  diagnostics: ThemeDiagnostic[];
  summary: ThemeDiagnosticSummary;
}

// 主题契约
interface ThemeContract {
  version?: string;
  contractVersion?: string;
  components: Array<{
    component?: string;
    name?: string;
    scope: string;
    parts: string[];
    states: string[];
    requiredTokens?: string[];
    optionalTokens?: string[];
    tokens?: string[]; // 旧字段，进入 ThemeContractView 时视为 requiredTokens
    a11yConstraints?: ThemeConstraint[];
    motionConstraints?: ThemeConstraint[];
  }>;
}

// 统一错误
interface StandardError {
  code: string;
  message: string;
  messageKey?: string;
  details?: unknown;
  retryable?: boolean;
  requestId?: string;
  traceId?: string;
  permission?: {
    domain?: string;
    action?: string;
    resource?: string;
    required: string[];
    granted: string[];
    messageKey?: string;
    callerId?: string;
    callerType?: string;
    pluginId?: string;
  };
}
```

## 扩展接口（可选实现）

以下接口为扩展功能，非必须实现：

| 接口 | 说明 |
|---|---|
| `theme.preview` | 会话级预览主题（不保存） |
| `theme.reset` | 重置为系统默认主题 |

> 扩展接口仅在需要时实现，不属于生态统一公共接口范畴。
