# task041 移植架构方案 — Chips-Office 完美移植

> 日期：2026-09-04
> 目标：把 GenOffice（Word/Sheet/Slide/PDF 四件套）**完整、无功能缺失**地移植为薯片应用插件 `com.chips.office`。
> 核心原则（用户明确）：**只做架构适配，不重新开发、不重构、功能零缺失**。

## 1. 移植总策略

GenOffice 的代码分三层，移植策略各不相同：

| 层 | GenOffice 侧 | 移植策略 |
| --- | --- | --- |
| 渲染层（renderer） | 四个 app 的 `src/renderer/**`，纯浏览器 React 代码，零 Node 依赖 | **原样搬运**，仅删除 AI 目录/引用；UI 组件、编辑器、Ribbon、对话框、样式 CSS 全部保留 |
| 引擎层（packages） | docx-engine / pptx-engine / pptx-render / i18n / ui 等，零构建 TS 源码包 | **原样搬运**为 `vendor/` 目录，用 vite alias + tsconfig paths 保持原包名 `@genoffice/*` 导入不变 |
| 主进程层（src/main + preload） | Electron 文件 IO、对话框、AI、打印、sidecar spawn | **不搬运**；按职责矩阵重定位到薯片正式链路（file.session / platform / 命令系统 / Host 服务） |

**桥接适配层**：在插件内实现与 GenOffice preload 桥**同签名**的 `window.desktop`（Word）、`window.desktopApi`（Sheet）、`window.slidesApi`（Slide）、`window.pdfApi`（PDF）对象，底层走 chips-sdk（`client.file.session.*`、`client.platform.*`）与 Host 引擎路由。renderer 代码对桥的调用点零修改。

`tsconfig.json` paths 与 vite alias 同步映射：`@genoffice/docx-engine → vendor/docx-engine/src/index.ts`（含 `./math`、`./metafile`、`./custgeom` 等子路径），四个 app 内部相对导入（`../shared/`、`../domain/`）靠目录镜像保持不变。

## 3. 主进程职责重定位矩阵

| GenOffice 主进程职责 | 薯片正式去向 |
| --- | --- |
| 文件打开/保存/另存为/原子写 | `client.file.session.open/read/write/persist/close`（Host file-session 服务） |
| 系统打开/保存对话框 | `client.platform.openFile / saveFile` |
| 从卡片/资源打开（Finder/Explorer 拖入等价物） | `launchParams.resourceOpen`（resource-open-service 路由）+ `platform.getPathForFile` |
| xlsx sidecar（calamine + ironcalc） | Host 新服务 `office.engine.*`（spawn 原生二进制，见 §5） |
| OOXML 保存计划（sheets gateway，纯 JS） | 插件内原样运行（src/apps/sheet/gateway），仅 zip 重组走 `office.engine.saveArchive` |
| 密码加密 docx（officecrypto-tool，Node crypto） | bridge 内 WebCrypto 等价实现（ECMA-376 agile encryption） |
| PDF 导出/打印（pdf-lib） | renderer 内直接 pdf-lib；打印走浏览器打印 |
| 系统字体度量（font-metrics，Node fs） | vendor 仅留类型；bridge 用 FontFace/canvas 度量 fallback（docs `line-metrics.ts` 启发式已有） |
| harfbuzzjs shaping（slides） | renderer 内直接运行（harfbuzzjs 本身即 wasm） |
| 菜单栏命令 | 薯片命令系统（`src/commands/`，AppChrome 命令面板） |
| 最近文件 / 应用设置 / 自动保存开关 | `client.config` / window typed data（实现时按 SDK 实际能力落位） |
| 崩溃恢复副本 | file.session 的 Host 托管会话状态 + bridge 恢复链路 |
| AI（agent/provider/search/附件抽取/file-parse） | **全部删除** |
| markdown 应用 | **整体删除** |
| shell（标签页/更新器/analytics/star-prompt/cloud-projects） | Host 已承载，不移植 |
| 系统 OCR（pdf 扫描件文字识别、pdf2docx ocr-vision） | Electron/OS-only 能力，本轮不移植，记入能力矩阵与工单 |

## 4. 生态侧配套改动（本任务范围内）

### 4.1 Host `file.session.*` 正式实现（工单175 关联收口）

- 新建 `Chips-Host/packages/file-session-service/`：以既有 `office-document-service`（未提交、已验证）为基线泛化为全格式会话服务——`create/open/read/write/get/persist/close/watch`，描述符/错误码/状态机严格对齐《15-万能文件处理协议》。
- `register-host-services.ts` 注册 `file.session.*` 路由；`register-schemas.ts` 注册 schema 对。
- `office.document.*` 保留为 deprecated 兼容路径（协议 14 §3.4 口径）。
- SDK `testing/mock-host.ts` 补 `file.session.*` 全量 mock（工单175）；SDK 测试补 file API 契约用例。
- Chips-Office 全部走 `client.file.session.*`，不使用 deprecated 的 `client.office.*`。

### 4.2 Host `office.engine.*` xlsx 引擎服务

- 新建 `Chips-Host/packages/xlsx-engine-service/`：spawn 原生 `xlsx-sidecar` 二进制（本任务已验证 cargo release 构建成功，7.7MB），JSON 行协议转发，会话表管理，崩溃自动重启。
- sidecar 二进制按平台构建（darwin-arm64/x64 优先随包落地；win32/linux 交叉构建脚本随包提供，`SOURCE.md` 记录来源与 Apache-2.0 许可证）。
- 路由逐命令显式注册：`office.engine.open/readRange/readFormulaCells/readMedia/recalc/archiveManifest/readEntries/scanEntries/convertWorkbook/saveArchive/cancel/close`；读类权限 `office.read`，落盘类（saveArchive/convertWorkbook）`office.write`。
- 保存流程中需要临时目录落盘的环节（`writePlanContents` 的 plan 内容物化）在 Host 路由实现内完成：插件传 XML 字符串/字节，Host 写临时目录后调 sidecar。

### 4.3 Chips-Office manifest

- `id: com.chips.office`、`name: 薯片办公`；permissions：`resource.read, file.read, file.write, platform.read, office.read, office.write, command.read, command.write, command.invoke`。
- capabilities 声明 **primary 层级**（与 UFV 的 fallback 形成专用/兜底层级差）：
  - `resource-handler:view:<office mime>` + `resource-handler:edit:<office mime>`（docx/xlsx/pptx/pdf 四个 MIME）；
  - `file-handler:<.docx/.xlsx/.pptx/.pdf/...>`（含 legacy .doc/.xls/.ppt 经 convertWorkbook 支持打开）。
- runtime.targets：desktop supported（web/mobile/headless false，与 Host 现状一致）。

## 8. 能力边界（如实声明，随实现更新）

- OCR（扫描 PDF 文字识别）为 OS-level 能力，浏览器/Host 不移植；
- slides 内嵌字体"安装到系统"（font-store）为 OS 能力，改由插件内私有字体注册（FontFace）承载渲染，"安装"语义不复存在；
- web/mobile target 当前 Host 未支持，manifest 如实声明 desktop-only。
