## 三、主智能体验收裁定（2026-09-21，任务 #134 随单）

1. **范围前提翻正**：#134 任务书原载「write/delete 臂按《04.05》§5.4 'Directory provider 写入显式排除' 返回不支持」系**任务书误引**——《04.05》§5.4 实文为「临时作用域（用户授权路径）」全库无该排除句；权威表《04.03》§3.3 明文 DirectoryProvider「支持 `write`/`delete`/`rename`/`copy`/`create_directory`/`list_directory`，写入：支持（document 挂载写入只对文档服务开放）」。据「断言与文档冲突以文档为准」铁律，**交回写族实现与权威文档一致，判合规**；B3 范围相应重定为「ArchiveProvider（ZIP Store）+ `open_write_stream` + Manager 层 WriteCoordinator 路径锁」，不再包含目录写族。
2. ①②④⑤⑥⑦⑨ 七条：**批准方案 A**（读面目录态统一 `RESOURCE_NOT_FOUND{uri}`；列举面目标错配 `RESOURCE_NOT_FOUND`（种类门仍归 Manager 先行，两层不混用）；非 NotFound IO 错误 `RESOURCE_INTERNAL`（禁止 EACCES 折映射 `PERMISSION_DENIED` 混两语义）；列举条目级跳过符号链接（不跟随最高不变式，规避根外存在性侧信道）；NOT_EMPTY 采原始目录保守口径（删除不可逆）；mkdir 同名文件占位 `ALREADY_EXISTS`（与不覆盖同族）；非 UTF-8 文件名条目跳过不 lossy 转写（保二次寻址往返一致）。落文归《06.02》§2.4/《06.07》§7.2/《04.03》§3.3/《04.04》§4.9 注记。
3. ③：**批准方案 A（零自造词表）**，本波 `WRITE_FAILED` details 维持 `{uri}` 单键；`cause` 分类词表属规格缺位，归本单落文波由文档侧定义后随网络面补形——禁止实现侧先造词表再倒逼文档。
4. ⑧-1：**批准方案 A**——目录域（Workspace/Document/Plugin）持久挂载**不**随 `close_session` 自动摘除，注销时机=宿主显式 `unregister_scope`（同步 detach 根，句柄级联失效在册）；《06.03》§3.2 表中 Temporary「会话结束注销」的执行位裁定归段三 dialog 接线波随单（宿主侧投递，非内核 close_session 顺手做）。
5. ⑧-2：**暂行维持两臂现状形（锁测固化），终裁=目标精确 uri 统一形**——与工单042 残留 `permission.rs:5` 旧口径注释清理同归 chips-resource **段二 B3 波随单**翻正（B2 波 permission.rs 为禁改面；B3 本就要动 manager 写族公共面），落文时《06.07》§7.3 加「details.uri 取目标资源 uri」一句。
6. ⑧-3：**批准方案 A**——`resolve_within_root` 空 uri 由 `DirectoryProvider::locate` 调用层回填目标规范 URI，满足 §7.3 `IResourcePathErrorDetails.uri` 必填；下沉 path_guard 改写段一在册形态被否。
