# 工单053 任务说明：原生绑定 JS 面会话写权限缺口——授权注入面未承接

> 登记人：主智能体（依任务 #213 波 A2b 前置勘查附带发现，2026-09-23）
> 状态：开放·在册待波 C 前置处置
> 关联：工单036（§11.3 资源域扩表）、《RFC-原生承载面扩表裁定》裁定G（七导出承接面）、W3 §五 裁决I-⑧
> 性质：**前瞻性架构缺口**（当前生产不可触发），非现役故障。

## 一、背景

`chips-resource` 内核的权限模型要求会话在创建时拿到授权集，Document 域的写臂（受控提交、落盘序列化）
恒定要求 `resources:write`；而 Neon 绑定层的会话创建导出 `resourceOpenSession` 在构造会话时**恒传空绑定/空权限集**，
「谁有权写」这件事在 JS 面没有任何入口可以表达。裁定G《RFC-原生承载面扩表裁定》批准的七项新导出
（挂载/注销、点位三换算、点位四序列化等）里也不包含授权注入面，因此该缺口不在已批准的扩表范围内。

后果分两个层面：

- **读臂不受影响**：内核读路径走 `session_bound()` 直通、免重复校验，所以文档打开、列表、渲染链路今天可以正常跑通。
- **写臂恒不可用**：任何经 JS 面创建的会话去写受管资源，必定被 `resources:write` 判定拒绝。
  工单036 波 C（事务引擎 + 受控提交）一落地就会撞上这面墙。

同一勘查波还发现另一处相邻缺陷（不在本工单范围，但在裁决I-① 已登记）：宿主 `nativeSession` 目前是
TypeScript 侧自增计数器，不是 `resourceOpenSession` 的真实返回值；拿假 id 去过分层归属闸会恒判不存在。
两处必须在同一时序面上收口，否则「写不进去」会被误读成「权限闸误伤」。

## 三、影响范围

- **当下**：零影响。`document:*` 能力未在生产组合根装载（`packages/host/src/capabilities/document/adapters/production-wiring.ts:188-229`
  缺位即整体不装载并诚实回退），`resourcePorts` 全仓唯一注入方是 E2E 替身 `packages/host/src/main/e2e-app.ts:73-77`。
- **即将**：工单036 波 A2b（正式 scope 适配器 + 装载开闸）落地即开读臂；波 C（点位四受控提交 + 事务引擎 + 恢复扫描）
  落地即撞写臂。因此本缺口的偿还终点必须**不晚于波 C 起手**。
- **不改的后果**：文档「能看不能存」，编辑回流与受控保存链路整体无法闭合（这是金链路的最后一公里）。

## 四、期望行为

内核已有的能力（会话自带绑定集与权限判定入口）需要一个**单点、最小、不破坏归属闸语义**的绑定层出口，
使宿主在打开文档会话时能表达「该会话拥有 `resources:write`」。期望形态约束：

1. **不新增第二套权限模型**：判定仍在 `chips-resource::permission` 单点，绑定层只负责投递授权素材。
2. **不放开哨兵边界**：授权注入只能由官方文档服务持有（`DOCUMENT_SCOPE_OWNER = chips.official.document-service`），
   插件侧不可经 SDK/Bridge 直接构造权限集。
3. **不扩导出面到有损粒度**：若需要新增导出，必须按裁定G §8.6「只增不改」与 `CORE_ABI_VERSION` 口径走 RFC 变更流程，
   并同步三方锁（`abi/export-surface.json`、`types/chips-native.d.ts`、宿主镜像清单）。
4. **写臂失败必须可诊断**：注入缺失时的拒绝码/原因要能与「真无权限」区分，避免排查期误判。

## 五、暂行处理

无绕过。当前不存在写需求的生产链路，因此不需要也不允许造临时绕过（例如放宽权限判定或伪造授权集）。
波 A2b 的正式 scope 适配器在注释面如实登记本工单号与现状（读臂可用、写臂恒拒、归波 C 前置），
并补一条锁测钉住「JS 面会话写必被拒」这一实态——待本工单收口时该锁测翻正为「按授权注入结果判定」，
翻正方向在册、不可静默放宽。
