# 正式解决方案

## 总体设计

在箱子布局 Runtime 增加“条目完整文档渲染”能力。布局只传入当前箱子会话的 `entryId`，Host 负责解析条目、校验类型、调用现有 `card.render`、创建子渲染会话并返回受控文档描述。

正式链路：

```text
CardViewer
  -> client.document.window.render(boxFile)
  -> 箱子布局 iframe
  -> runtime.renderEntryDocument(entryId, options)
  -> SDK 布局 Runtime Bridge
  -> Host box.renderEntryDocument
  -> 箱子会话解析 entryId
  -> Host card.render
  -> 托管复合卡片 documentUrl
  -> 布局内嵌子 iframe
```

## 公共契约

布局 Runtime 新增：

```ts
interface BoxLayoutRuntime {
  renderEntryDocument(
    entryId: string,
    options?: {
      mode?: "view" | "preview";
      interactionPolicy?: "native" | "delegate";
    },
  ): Promise<BoxEntryDocumentView>;

  releaseEntryDocument(renderSessionId: string): Promise<void>;
}
```

返回结构：

```ts
interface BoxEntryDocumentView {
  entryId: string;
  documentType: "card";
  title: string;
  documentUrl: string;
  renderSessionId: string;
}
```

底层 Host 路由为：

- `box.renderEntryDocument`；
- `box.releaseEntryDocument`。

`box.renderEntryDocument` 使用 `box.read` 权限，并继续校验箱子会话所有权。布局页面不直接调用 `card.render`，不获取 `cardFile`。

## Host 会话模型

每个箱子查看会话记录自己创建的条目子渲染会话：

```ts
entryDocumentRenderSessions: Map<renderSessionId, entryId>
```

规则：

1. 渲染前校验 `sessionId` 所有权、`entryId` 存在、条目已启用且文档类型为卡片。
2. 引用 `.box` 的条目返回明确的不可内嵌错误，浏览态继续显示其正式封面。
3. 渲染成功后把 `card.render` 返回的 session 登记到当前箱子会话。
4. `releaseEntryDocument` 只能释放当前箱子会话名下的子渲染会话。
5. `closeView` 先标记会话关闭并等待进行中的条目文档渲染/释放操作，再回收所有未显式释放或关闭期间晚到的子渲染会话，最后删除箱子解包目录。
6. SDK `FrameRenderResult.dispose()` 仍负责外层布局渲染会话与箱子查看会话的最终释放。

## 嵌套文档事件

布局内的卡片 iframe 需要处理：

- `chips.composite:ready`：结束加载态；
- `chips.composite:resize`：按卡片真实高度更新子 iframe；
- `chips.composite:resource-open`：由布局页面转发给外层宿主；
- `chips.composite:node-error`：保留非致命节点诊断，不升级为整张卡片失败；
- `chips.composite:fatal-error`：显示可诊断错误态；
- `chips.composite:interaction`：当 `interactionPolicy="delegate"` 时转发交互意图。

消息必须校验 `event.source === iframe.contentWindow`，并只接受文档 URL 的预期 origin 或 sandbox 不透明 origin `null`。

卡片子 iframe 高度更新后，布局文档自有 `ResizeObserver` 会继续发出 `chips.box-layout:resize`，CardViewer 无需了解内层卡片的布局细节。

## 文档库布局

`treeNodes` 的条目节点增加表现层字段：

```ts
presentation: "content" | "cover"
```

- 卡片条目默认为 `content`，右侧显示完整卡片。
- `content` 右侧只显示 Host 托管卡片文档，不重复显示箱子摘要标题、类型、摘要、标签和打开按钮，也不增加外层卡片边框或内边距。
- 用户可在布局编辑器中将指定节点切换为 `cover`。
- 组节点不保存 `presentation`。
- 引用箱子的节点始终使用 `cover`，不递归展开子箱子。
- 切换左侧节点时，新请求和旧请求通过取消标记隔离；旧卡片渲染会话在新卡片挂载前释放。

## 文档库查看态交互与高度

- 在查看态工具栏增加目录显示/隐藏按钮，使用 `aria-expanded`、`aria-controls` 和本地化标签表达状态。
- 隐藏目录只改变当前页面会话的呈现，不修改 `treeNodes` 或其他布局配置；右侧选中条目和 Host 卡片文档会继续保持。
- 目录显示时主区域为“目录 + 预览”双列，隐藏后切换为单列；主网格使用 `grid-auto-rows: max-content`、`align-content: start`、`height: fit-content`，预览也使用内容高度，避免网格默认拉伸造成右侧与目录等高。
- 目录保留独立滚动约束，卡片文档 iframe 继续通过 `chips.composite:resize` 更新自身高度。

## 性能策略

- 文档库右侧同时只保持一个完整卡片子渲染会话。
- 封面节点继续使用 `renderEntryCover`，不生成复合卡片文档。
- 不对整箱条目预渲染完整内容；只在选中需要展开的卡片时请求。
- 分页和封面预取保持现有按需链路。

## 错误码

新增或明确：

- `BOX_ENTRY_DOCUMENT_UNAVAILABLE`：条目不能作为完整卡片文档渲染；
- `BOX_ENTRY_DOCUMENT_TYPE_UNSUPPORTED`：条目为箱子或其他未支持的文档类型；
- `BOX_ENTRY_RENDER_SESSION_NOT_FOUND`：子渲染会话不存在或不属于当前箱子会话；
- `BOX_ENTRY_RENDER_FAILED`：条目已解析，但卡片渲染失败。
