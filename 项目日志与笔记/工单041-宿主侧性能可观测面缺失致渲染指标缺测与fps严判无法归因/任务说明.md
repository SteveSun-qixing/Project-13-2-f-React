# 工单041 任务说明

## 一、背景

W2-P1-6 性能五指标真进程基线实测（任务 #121 段A 交付、#127 接管收口，提交 2f6768300）首次以真 Electron 宿主跑出正式 ingest 管线判定：cold_start_ms（中位 366.40ms）、open_card_ms（中位 3.33ms）、idle_memory_mb（中位 361.38MB）三指标通过《架构原则》§4.2/R18 门禁；但另有两指标无法给出可信终判、一指标如实失败，根因均指向**宿主侧性能可观测面缺失**——性能采集只能从进程外部（CDP/ps/rAF 桶）观测，宿主内部标记无一导出。测量链设计与缺口定性见 `chips-ecosystem/tests/perf/真进程采集-设计.md` §六/§七。

## 二、缺口清单（四项，事实+证据行号）

1. **宿主无 `CHIPS_TRACE` 导出**：`document:open` 三阶段（路由→解析→回包）分段耗时外部不可测，cold-start/open-card 只有端到端往返值（证据：`tests/perf/src/real/observations.ts` 样本 notes 与缺测声明；真样本仅单值臂）。
2. **`render_update_ms` 无外部导出**：单帧更新任务耗时属渲染引擎内部标记，宿主无导出，外部不可测——该 R18 指标 P95≤16ms 整体**无数据**（证据：`tests/perf/src/real/observations.ts:132` 缺测臂 reason 在册；终判报告 ingest EXIT=1 如实）。
3. **卡片 DOM 渲染臂未接通**：卡片窗口装载路径（#99/#100 编排链）首帧提交无可观测锚点，「开卡<100ms」现行口径只覆盖 IPC 往返、不含真实首帧提交（证据：设计文档 §七 项③定性）。
4. **`sustained_fps` 严判失败待归因**：实测均值 59.90（10 桶 59~61，滚动窗口含建窗期桶）对 `>60` 门禁如实判失败（ingest EXIT=1）；无法区分**测量口径问题**（桶边界/建窗期样本混入）与**真实掉帧**（合成层未生效），因缺口③致两假设均不可证实。门禁值与判定逻辑零改动零让步。

（另：箱子视图闸 `document-view-builder.ts:29-30` 的 `BRIDGE_INVALID_INPUT` 属工单035 裁定③在册 W4 面，open_box_ms 已按 W3 计划裁决A 显式豁免，不在本单范围。）

## 三、影响

- W2 终验判据②「性能基线实测」留有二指标不可信 + 一指标失败记录，收尾报告必须如实呈现，不得以「三过两豁免」口径掩盖。
- 后续所有波次（W3 落盘链、W4 箱子渲染、W6 性能回归基线对比）继承同一观测盲区。

## 四、复现步骤


## 五、期望行为与验收

1. 宿主导出结构化性能标记通道（建议 trace 事件面，具体形态由 RFC/裁定先行，禁止散落 console 计时）：覆盖 `document:open` 三阶段与渲染引擎单帧更新耗时；`render_update_ms` 经正式管线出真数据判定。
2. 卡片首帧提交锚点入观测面，「开卡」口径升级为首帧提交完成（或在《架构原则》测量规范在册修订口径，二选一经裁定）。
3. `sustained_fps` 归因调查出结论：若测量口径（建窗期桶混入），采法修正后重测仍须如实呈现；若真掉帧，修实现。全程禁改门禁值。
4. 五指标全部真数据终判（豁免仅 open_box_ms UI 段，随 W4）；设计文档 §七 缺口逐项闭环回写。
