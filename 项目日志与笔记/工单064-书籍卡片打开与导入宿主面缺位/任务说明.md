## 一、背景

旧基础卡族 `book-BCP` 按覆盖矩阵行（`旧功能覆盖矩阵-三插件仓库-2026-09-20.md` :39 及 :34~:37、:44~:45 装配行）迁移为 `chips-ecosystem/plugins/basecards/book/`。交付过程中确认：查看态「打开阅读」臂依赖的宿主面与编辑态导入臂依赖的资源写入链路均未就绪，本包按「如实登记缺位、解析与渲染照常交付」推进。

## 二、缺位明细与证据

1. **书籍阅读器处理器未实现**
   - 《09-官方插件与应用目录》§4.2 book 行状态「已设计」；§7.2 `chips.official.book-reader` 状态「已设计」，处理器 `primary`：EPUB/EPUB3、PDF、TXT、Markdown、FB2、RTF（《10-官方内容处理与阅读服务设计》§2.2）。
   - `resource:open` 路由（《14-资源打开与默认处理器契约》）在电子书槽位无任何候选：primary/fallback 均未注册，§7 未安装降级面对 `.epub/.pdf/.txt` 无 shell 回退（归档态成员不可回退）。
2. **渲染帧插件执行通道未交付**
   - `packages/host/src/renderer/entries/frame.ts` 头注：插件内容装载臂属插件执行通道波次（工单025 剩余 / #85 RFC 落波）。
   - 帧内 `window.chips` 不注入（08 §5.4），帧内打开臂正式通道 `frame:action` 未接；当前就近渲染容器侧经 SDK `chips` 客户端真调可用。
3. **编辑器资源导入通道缺位**
   - 旧 book-BCP 的编辑器由旧 Host 注入 `importResource` / `importArchiveBundle` / `deleteResource` / `resolveResourceUrl` 通道（`book-BCP/src/index.ts` 注入面、`src/editor/panel.tsx` 消费面）：EPUB 上传解析元数据回填、ZIP/CBZ 解包出图（`archive.ts` 全量条目提取）、封面写入。
   - 新架构编辑器契约（08 §4）只承载配置回流，不写文件；文件落卡片的导入编排归属资源写入链路，未开放给基础卡片编辑器。EPUB/ZIP 解析器（`epub.ts` / `archive.ts`）与资源解析 Hook（`use-resolved-resources.ts`）已随包交付并测毕（67 项测试），待通道就绪后接线（非兼容层，是通道归属未定）。

## 三、影响范围

- 受阻：书籍卡片查看态打开臂（点击 → `resource:open` → 书籍阅读器 / 图片查看器）。当前点击在就近容器返回 `RESOURCE_HANDLER_MISSING` 类失败、帧内通道不可用，界面以行内简体中文提示如实呈现，不伪造成功。
- 不受阻：ZIP/EPUB 纯解析（真实字节夹具 67 项测试）、阅读卡渲染（封面/标题/作者/格式元信息/空态）、编辑面板（来源形态、路径与信息表单、图片序列条目编辑、排序依据）、`validateConfig` / `createInitialContent` / `collectResourcePaths`、包构建与五阶段校验（`book-0.1.0.cpk` 校验通过、结果 valid）。
