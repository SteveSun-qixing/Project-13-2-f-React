# 工单027 —— G6 覆盖率门禁 §6.3 机读豁免按「组+指标」匹配、粒度过粗：期限内的任意新增 Rust crate 可搭便车豁免 TD-001

> 登记日期：2026-09-20
> 来源：task043 生态梳理波次对门禁设计面的专项核查；豁免机制本体（工单017 落地）与 TD-001 登记（工单012 裁决）均按各自口径正确工作，本单登记的是匹配粒度的设计缺陷。
> 性质：只登记问题，不含解决办法。

## 一、背景

《CI/CD 与质量门禁》§6.3 的机读豁免由 `chips-ecosystem/tools/gates/lib/exemption.mjs` 解析《项目日志与笔记/技术债务清单.md》的 `GATE-EXEMPTIONS` JSON 围栏，并由 G6（`tools/gates/check-coverage.mjs`）在未达标时消费。当前在册唯一豁免 TD-001：`group="rust-core"`、`metric="lines"`、期限 2026-10-19、偿还动作 = W3 集成层实测覆盖 `chips-native` 462 行 napi 残留。其登记文本（《技术债务清单.md》「影响范围」要素与机读块 `scope` 字段）明确声明：「仅豁免由 chips-native 造成的未达部分；其余 crate 判定不受影响」。

## 二、证据（文件:行号，均于 2026-09-20 复核）

1. 匹配逻辑只比对组与指标：`tools/gates/lib/exemption.mjs:128-150`，核心判定在 `:135` —— `entry.group === group && entry.metric === metric` 即命中，无任何按文件、按 crate、按成因的次级匹配；命中即 `kind: 'active'` 放行。
2. 消费面把整组聚合值交给匹配：`tools/gates/check-coverage.mjs:182-195` `aggregateCoreLines` 将 `coreMatch` 前缀命中的**全部**文件行数据求和后作为 `rust-core` 组判定（`:384` `judge('rust-core', …)`）；`judgeGroup`（:197-255）在组未达标时调用 `matchExemption(exemptionCtx, group, metric)`（:210），命中 active 即置 `pass = true` 并只出 `COVERAGE030` 警告（:211-225）。
3. 组边界天然吞并新成员：`tools/gates/gates.config.json` 的 `coverage.rust.coreMatch = ["packages/core-rust/crates/chips-", "packages/native/"]`，且 `check-coverage.mjs` USAGE（:24-27）自述「Neon 绑定 crate chips-native 按 crate 命名属于核心面，统计面不设豁免、不另计」——任何名字落在 `packages/core-rust/crates/chips-*` 或 `packages/native` 下的新 Rust crate 自动并入 `rust-core` 组，与 chips-native 共用同一条组级判定线。
4. 结论：TD-001 的 `scope` 声明（只放行 chips-native 成因）在机读与判定层**没有任何执行机构**；放行决策与债务成因之间无绑定。

## 四、影响范围

- TD-001 有效期内（至 2026-10-19），W2/W3 恰好要新增 Rust 成员（`chips-parser` 已在途、`chips-resource` 归 W3，见工单015 裁决与审计报告面 3 第 2、4 条）：任何新 crate 在自身测试未跟上、拉低 `rust-core` 组聚合时，G6 照常绿（仅 COVERAGE030 警告），覆盖率红线静默失守，且失败归因会被豁免文案误导为「chips-native 残留」。
- 与《技术债务清单》§6.3 七要素登记的「影响范围」承诺不符：登记声称其余 crate 判定不受影响，机制上无法兑现。
- 涉及门禁：G6 全组 `rust-core>90%` 判定（R18 核心红线）。

## 五、期望行为

豁免放行只应覆盖其登记成因范围内的未达部分：豁免条目声明的作用对象（crate/文件/路径集合）与被放行的未达量之间必须存在可判定的绑定关系；任何不属于登记范围的新增代码拉低组聚合时，G6 应维持失败。粒度语义应与《CI/CD 与质量门禁》§6.3 七要素（尤其 `scope`）的文档口径互为印证、单一事实源。

## 六、收口记录（2026-09-20，W2 任务 #57）

### 6.1 修复方案（对应 §五 期望行为）

- 机读豁免 schema 升级为 `chips-gate-exemptions/v2`：每条登记必须携带 `scopePaths`（`scope` 承诺的机读形态——生效范围的仓库相对路径前缀数组）；缺失或非法一律按「要素缺失」fail-closed 不构成豁免（v1 旧形态登记从此不可消费）。
- G6 判定面引入成因归因：`check-coverage.mjs` 为每个判定组构建逐成员明细（成员粒度＝crate/包目录，`memberKeyOf` 按 `src` 段/`crates` 段截取），组内某维度未达标且命中 active 登记时执行 `attributeExemption`——**组内全部未达标成员都被有效登记的 `scopePaths` 覆盖**（`coversScopeMember` 路径段对齐，兄弟前缀不搭便车）才转 COVERAGE030 留痕放行（消息点名未达标成员与实际覆盖的登记，多条联合署名）；存在未登记成员未达标 → 维持 COVERAGE010 并出 COVERAGE031「组级豁免不得吞并范围外成员」；无成员可归因 → COVERAGE031 fail-closed 维持失败。阈值、分组、`coreMatch` 统计面与测量口径零改动。
- TD-001 机读块补登 `scopePaths: ["packages/native/"]`，合法消费保持（真实报告 `rust-core=pass(TD-001)` 83.00% 照常呈现），其余 crate 判定从此在机制上不受该豁免吞并——兑现登记文本「仅豁免由 chips-native 造成的未达部分」。
