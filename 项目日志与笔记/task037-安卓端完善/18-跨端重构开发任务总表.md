# 跨端重构开发任务总表

## 1. 已确认目标

正式目标是 React/Web 插件 + Rust Host Core + Electron Desktop Shell + Tauri 2 Mobile Shell + Kotlin Android PAL + Swift iOS PAL + Rust Headless + Web PAL。

本计划不考虑改造工程量，不保留长期兼容层，不建立双 Kernel。迁移期的 TypeScript 实现只用于行为对照，最终唯一 Kernel/Services 位于 Rust Core。

## 2. 任务完成定义

每个任务必须同时满足：

1. 代码不存在 stub、TODO、假成功或临时旁路；
2. 单元、契约、集成和需要的端到端测试通过；
3. 受影响 manifest、schema、route manifest 和生成代码同步；
4. 正式文档与真实实现、测试和运行链路一致；
5. Desktop/Mobile/Web/Headless 能力要么实现，要么返回契约化 unsupported；
6. 有可复核的构建产物、测试记录和退出条件证据。

## 3. 工作流与严格依赖

```text
W0 决策与基线
 -> W1 契约单一源
 -> W2 Rust Kernel
 -> W3 Rust Services/PAL traits
 -> W4 插件与 module runtime
 -> W5 Desktop Electron 薄 Shell
 -> W6 Android Tauri/Kotlin
 -> W7 iOS Tauri/Swift
 -> W8 Web/Headless
 -> W9 SDK/脚手架/官方插件/社区
 -> W10 系统测试、安全与发布
 -> W11 旧实现收口与文档归一
```

W5、W6、W7、W8 在 W1–W4 的共用边界稳定后可并行；W9 可随各端金链路分批推进；W11 只能在所有替代链路验收后开始。

## 6. 禁止的排期方式

- 不先做“能显示网页”的临时 Android 壳；
- 不在契约生成和 golden corpus 前同时手写 Rust/Kotlin/Swift API；
- 不在 module profile 冻结前将 Node module 直接塞进移动端；
- 不在平台认证前将 manifest target 改为 supported；
- 不为赶进度跳过 Desktop 回归、移动进程死亡恢复或签名校验。
