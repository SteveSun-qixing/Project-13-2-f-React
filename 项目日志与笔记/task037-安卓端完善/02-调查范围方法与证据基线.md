# 调查范围、方法与证据基线

## 1. 调查顺序

本次按照工作区规则依次核查：

1. `生态设计原稿/` 中生态定位、架构原则、分层、插件、SDK 与跨平台愿景；
2. `生态共用技术文档/` 中 PAL、Host 服务域、Bridge、Manifest、插件、CPK 和安装路径规范；
3. `Chips-Host` 的 package、Shell、HostCore、PAL、IPC、preload、服务注册、插件 runtime、模块 runtime、安装器和测试；
4. `Chips-SDK` 的 Bridge adapter、client、目标校验和 CLI；
5. 正式源目录中的插件 `manifest.yaml` 与两项 `mobile: true` 插件源码；
6. 本机 Android SDK、ADB、AVD 与 Java 环境；
7. Android 和 Google Play 官方资料。

## 2. 证据优先级

结论按以下优先级形成：

1. 当前可执行代码、package script、构建配置和测试；
2. 当前正式 `manifest.yaml`；
3. 生态共用技术文档；
4. 生态设计原稿；
5. README、历史报告和任务说明。

当设计愿景与实现不同，以实现判断“现在能否运行”，以设计原稿判断“后续应向哪里收敛”。

## 5. 本机 Android 环境事实

已发现：

- Android SDK：`~/Library/Android/sdk`；
- Platform：Android 36；
- System image：Android 36.1 Google APIs Play Store arm64-v8a；
- Build tools：35.0.0、36.1.0；
- ADB：36.0.0；
- AVD：`Medium_Phone_API_36.1`；
- 当前没有已连接设备；
- Java：OpenJDK 23.0.1。

注意：Java 23 只是当前机器安装情况，不应直接成为项目基线。实际 JDK 版本必须依据所选 Android Gradle Plugin 官方兼容矩阵固定，并在 CI 与开发文档中一致。

## 6. 调查限制

- 没有 Android 工程，无法执行 Gradle 构建、安装、启动或仪器测试；
- 没有连接真机，无法验证厂商 WebView、文件选择器、后台限制和内存回收差异；
- 工作区存在大量用户改动，本报告没有运行全仓测试，避免把其他任务的预存失败混入 Android 调查；
- 第三方容器和 JS 引擎尚未选型，因此计划不把任一候选依赖写成既成事实。
