# 存储、文件关联、生命周期与后台能力

## 1. 存储域划分

Android Host 必须明确四种数据域：

| 数据域 | 位置 | 典型内容 | 卸载行为 |
|---|---|---|---|
| Host 私有持久数据 | internal files/database | 配置、插件、session、凭证引用 | 删除 |
| Host 私有缓存 | cache | render、临时解包、网络缓存 | 可随时清理 |
| 用户文档 | SAF provider | `.card/.box` 和导出文件 | 独立于应用 |
| 媒体库 | MediaStore/Photo Picker | 图像、音视频 | 按用户授权 |

插件不得知道真实 Android 私有路径，只通过 Host resource/document API 操作。

## 2. `.card/.box/.cpk` 打开链路

建议统一：

1. Android IntentRouter 接收 VIEW/SEND/OPEN_DOCUMENT 结果；
2. 读取 `content://` 元数据、MIME、显示名和授权；
3. Host `file.detectType` 验证 magic/结构，不只信后缀；
4. 为外部文档创建 `DocumentHandle`；
5. 按策略选择原位访问或事务导入；
6. 启动对应 app plugin surface；
7. launchContext 只传 handle/业务参数，不传 Android 对象；
8. surface 关闭时释放临时授权和缓存。

## 3. 保存模型

卡片/箱子 ZIP 文件不应在外部 provider 上边改边写。正式保存流程：

1. 在 Host 私有 workspace 生成完整新版本；
2. validate + pack + hash；
3. 写到 provider 临时目标或输出流；
4. flush/close；
5. 更新文档 handle 与版本元数据；
6. 失败保留内部恢复副本并报告可恢复错误。

当 provider 不支持原子替换时，UI 和错误必须诚实表达；不能假设 POSIX rename。

## 4. 文件关联和分享

AndroidManifest 需要为正式 MIME 和可接受扩展名配置 intent-filter，并处理：

- `ACTION_VIEW`：从文件管理器打开；
- `ACTION_SEND/ACTION_SEND_MULTIPLE`：接收分享；
- 分享导出：FileProvider/ContentProvider URI + 临时授权；
- App Links：打开社区 card/box URL；
- 冷启动和已运行实例的 `onNewIntent`；
- 恶意/超大/无效 URI 输入。

Android 文件关联不是创建桌面 launcher 文件，现有 `PALAssociation/PALLauncher` 的桌面语义需在 capability matrix 中分开。

## 5. 生命周期状态机

建议 Host 状态：

```text
cold -> initializing -> foreground
foreground -> background-suspended
background-suspended -> foreground
any -> checkpointing -> process-dead
process-dead -> restoring -> foreground
```

关键 checkpoint：

- 已安装/启用插件索引；
- 活动 scene/surface/back stack；
- 插件 session 可恢复描述，不保存可伪造权限 token；
- 打开的 DocumentHandle；
- card/box session snapshot、dirty、undo/redo 必要状态；
- 未完成 job 的持久记录；
- 当前主题、语言和设置版本。

恢复时生成新 token，重新校验插件版本、权限、document URI 授权和资源存在性。

## 6. 后台任务分类

| 类型 | Android 机制 | 示例 |
|---|---|---|
| UI 短任务 | coroutine + lifecycle scope | 读取元数据 |
| 可恢复延迟任务 | WorkManager | 索引、清理、同步 |
| 用户发起长传输 | 正式数据传输 job/前台服务 | 上传下载大卡片 |
| 媒体播放 | MediaSession + foreground service | 音乐播放 |
| 不可后台运行 | 暂停并恢复 | 隐藏 WebView 交互任务 |

每个 module job 方法应声明 background policy、可恢复性、幂等键、进度持久化和取消语义。

## 7. 凭证与隐私

- access token 不写入普通 JSON/config；
- 使用 Android Keystore 加密凭证，Host credential service 只返回逻辑 key；
- WebView cookie 与 Host credential 分离；
- 日志脱敏 URI、token、授权 header 和用户路径；
- 导出诊断前再次脱敏；
- 清除数据、卸载、插件卸载分别定义凭证处理。

## 8. 验收场景

- 从系统文件管理器打开 card/box；
- 从聊天软件分享 card 到 Host；
- 从云盘 provider 打开并持久访问；
- provider 离线、撤销授权、文件被移动时给出可恢复错误；
- 编辑中切后台后被系统杀进程，重开恢复 dirty 文档；
- 上传中断后按照 job 语义续传或可靠失败；
- 分享导出的接收方可读取，授权不永久泄漏。
