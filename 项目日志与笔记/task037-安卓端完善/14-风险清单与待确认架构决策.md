# 风险清单与待确认架构决策

## 1. 必须先确认的 ADR

| ADR | 决策内容 | 不确认的后果 |
|---|---|---|
| ADR-A01 | Host Core 在 Android 的承载方式 | 无法确定工程和重构边界 |
| ADR-A02 | JS engine/容器依赖 | 模块、包体、许可、安全不确定 |
| ADR-A03 | ResourceLocator/DocumentHandle | 文件 API 在 Android 持续漂移 |
| ADR-A04 | WebView Bridge transport | 安全模型和 SDK 无法稳定 |
| ADR-A05 | module worker/executor | module 插件无法运行 |
| ADR-A06 | 插件签名与信任链 | 动态插件无法安全发布 |
| ADR-A07 | Android surface/window fallback | app 插件行为不一致 |
| ADR-A08 | 后台任务模型 | 任务丢失、功耗或政策违规 |
| ADR-A09 | 最低 API 和工具链 | 兼容范围与依赖无法冻结 |
| ADR-A10 | Play 与非 Play 分发边界 | 插件更新策略冲突 |

## 2. 第三方依赖评估模板

任何 Android 容器、JS 引擎、WebView 辅助库、ZIP、图像、媒体或安全库在引入前必须记录：

- 用途和不可替代性；
- 许可证与 NOTICE；
- 活跃维护和发布频率；
- 已知 CVE 与响应能力；
- 下载量/使用成熟度只是参考，不代替审计；
- APK/AAB 包体和 ABI；
- 冷启动、内存、线程和性能；
- minSdk/targetSdk/AGP/Kotlin 兼容；
- 离线构建与供应链锁定；
- Android/Google Play 合规；
- iOS 等未来平台的架构影响；
- 移除/替换成本。

本报告没有授权引入 Capacitor、QuickJS、Node-on-Android 或任何同类长期依赖。

## 3. 高风险问题

### R1：HostCore 伪平台化

风险：只新增 AndroidPalAdapter，但 Host 服务仍直接调用 Node API，最终形成大量 conditional 和 polyfill。

控制：M1 以“无 Node globals 的 portable tests”为门禁。

### R2：Bridge 权限逃逸

风险：WebView 中远程页面/iframe 获得高权限原生对象。

控制：独立 origin、消息端口、endpoint 身份绑定、frame 分权、导航撤销、负向测试。

### R3：模块插件无法移植

风险：`.mjs` 依赖 Node 标准库或动态 import 语义，Android executor 无法运行。

控制：冻结移动 module profile，CLI 静态扫描，首批只认证 profile 内模块。

### R4：文档丢失

风险：content URI、provider 行为、进程死亡和非原子保存导致 card/box 损坏。

控制：内部事务 workspace、checkpoint、hash/validate、恢复副本、故障注入测试。

### R5：Play 审核风险

风险：动态插件、下载代码、高权限 WebView Bridge、第三方内容触发拒审。

控制：官方签名插件先行、禁止 native payload、内容治理、安全审计、预发布政策审查。

### R6：性能和内存

风险：多 WebView、嵌套 iframe、大 card/box、JSON 二进制导致 OOM/ANR。

控制：surface 池、resource handles、流式 IO、预算、低内存测试、回收协议。

### R7：当前文档口径漂移

风险：设计原稿说“未来支持”，部分 manifest 已写 true，使用者误以为可运行。

控制：工单157；在实现前不把预留写成可用；实现后同步正式公共文档。

## 4. 关联既有风险

- 工单143：编辑引擎网页包预览绕过资源协议，Android 资源 origin 会放大该问题；
- 工单147/148/149/150/151/156：会话、导入、历史、渲染双轨直接影响进程恢复和跨端一致性；
- 工单152/153/154：文件识别、工作区、公共工具收口影响 URI/路径模型；
- 工单155：全量测试预存失败会影响 Android 改造回归可信度。

## 5. 停止条件

出现以下任一情况应停止编码并回到 ADR/工单：

- 需要改变 Host 唯一运行时或中心路由原则；
- 候选依赖需要 GPL/不可接受许可或高风险 native binary；
- 必须给不可信 WebView 开放通用 Bridge 才能运行；
- 公共文件 API 无法表达 content URI 且调用方开始私自处理；
- module 插件只能通过下载 native code 工作；
- 为通过测试需要伪造 capability 或跳过签名/权限。
