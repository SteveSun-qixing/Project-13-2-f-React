# 测试、安全、发布与文档收口详细任务

## 1. W10-01 多端 CI 与可复现构建

### 构建矩阵

| 产物 | 必须目标 |
|---|---|
| Rust Core | macOS x64/arm64、Windows x64/arm64、Linux x64，Android ABI，iOS device/simulator，server targets |
| Electron Desktop | Windows/macOS/Linux 正式包、签名前后校验 |
| Android | debug APK、release AAB、指定 ABI 和 16KB page 校验 |
| iOS | simulator test bundle、signed archive/TestFlight candidate |
| Web | production assets、CSP/asset manifest/service deployment |
| Headless | server/worker/CLI binary、container image |
| SDK/脚手架/插件 | npm/workspace package、`.cpk`、hash/signature metadata |

### 实施动作

1. 锁定 Rust/Node/pnpm/JDK/Android/Xcode 工具链并记录供应链来源；
2. 建立依赖缓存但不缓存未验证产物；
3. 对 Rust/JS/Gradle/Swift 依赖运行 license/advisory/lockfile 检查；
4. 对相同源码与工具链运行双次构建并比较可复现字段；
5. 生成 SBOM、provenance、checksum 和签名产物清单；
6. 构建产物只能从 CI 签名流程进入发布候选。

**完成判据**：新环境可根据文档从零产出相同结构的所有产物；不依赖开发机私有路径或全局包。

## 2. W10-02 契约、差分与故障注入测试

### 测试层级

- **Schema tests**：所有公共输入/输出/错误/manifest；
- **Rust unit tests**：Kernel、services、codecs、plugin/module runtime；
- **PAL conformance**：Desktop/Android/iOS/Web/Headless 同一 suite；
- **Transport contract**：Electron RPC、Tauri bridge、Web remote transport；
- **Differential tests**：TypeScript 基线与 Rust 新实现；
- **Plugin certification**：每个 manifest target 真实宿主测试；
- **E2E**：打开、查看、编辑、保存、导出、分享、恢复；
- **Visual/DOM tests**：Desktop Chromium、Android WebView、WKWebView、Web；
- **Soak tests**：长时运行、重复开关文档、插件更新与弱网。

### 故障注入矩阵

1. 写入 staging/commit/fsync 各点中断；
2. Rust Core/Electron/WebView/Activity 任意进程崩溃；
3. RPC 断线、半包、慢消费者、重放和乱序；
4. 插件安装中断、签名撤销、版本回滚；
5. module 超时、超内存、死循环、大输出与取消竞态；
6. Android/iOS 低内存、后台终止、URI/security scope 失效；
7. 私钥/系统凭据不可用、网络超时、断点续传失败。

**完成判据**：每个故障都有确定错误、审计记录、可预期回滚/恢复和无资源泄漏证据。

## 3. W10-03 安全、Fuzz、渗透与供应链

### 威胁模型

分别为恶意 `.cpk`、恶意 `.card/.box`、被攻陷插件、远程网页、伪造本地 RPC peer、恶意 module、中间人社区连接、丢失设备和供应链攻击建立数据流与信任边界。

### Fuzz targets

- ZIP/card/box/cpk parser；
- manifest/YAML/JSON Schema；
- RPC/Bridge frame decoder；
- resource path/URL/mime parser；
- route input/output canonicalizer；
- module ABI/input/output；
- image/archive import 元数据。

### 渗透测试

- Electron preload/IPC sender 伪造、导航和 window-open；
- Android/iOS WebView message/origin/frame 越权；
- 插件跨 session/resource/handle 访问；
- RPC socket/pipe 访问、token 窃取和重放；
- 插件签名、hash substitution、降级和撤销；
- module sandbox escape 与配额绕过；
- 日志、崩溃包和备份的敏感数据泄露。

### 供应链

锁定依赖、禁止未审核 git 依赖、校验 npm/crate/Gradle/Swift 来源、运行 advisory/license scan、保护签名密钥、生成 SBOM/provenance，定义高危漏洞响应 SLA。

## 4. W10-04 性能、内存、功耗与包体

### 必须建立的预算

- Host 冷/热启动到首 surface 可交互；
- Rust Core 启动、RPC 往返 p50/p95/p99、route overhead；
- 打开单卡/复合卡/大箱子时间；
- 每 WebView/iframe/module instance 增量内存与回收延迟；
- 编辑自动保存延迟、写放大和 checkpoint 大小；
- HTML->PDF/image、解包/打包、上传/下载吞吐；
- Android/iOS 前台/后台电量、网络与热状态；
- 各平台安装包和首次安装资源大小。

### WebView 差异专项

对 Chromium、Android System WebView 和 WKWebView 建立 CSS/DOM/IME/media/canvas/WebGL/font/printing 特性表；用相同测试卡片比较截图、尺寸、事件序列和媒体结果。

**完成判据**：预算不是参考数字，CI/release gate 对超限失败；调整预算必须有证据和审批。

## 5. W10-05 签名、更新和发布

### Desktop

- Electron/Core 二进制组合打包，启动前校验 Core hash/version；
- Windows code signing、macOS hardened runtime/notarization、Linux 包签名；
- 安装/卸载、文件关联、单实例、静默/交互更新和失败回滚；
- Electron 跟随最近受支持版本的升级节奏，不宣称不存在的长期 LTS。

### Android

- debug/staging/release 密钥分离，Play App Signing 策略；
- AAB/APK、version code/name、ABI、R8、native symbols 和 mapping 上传；
- internal/closed/open/production track、staged rollout、crash/ANR gate 和回滚；
- privacy/data safety/content/plugin policy 审查；
- 动态插件只包含政策允许的 Web/受限解释资产。

### iOS

- certificate/profile/entitlement/privacy manifest；
- archive、symbol、TestFlight、phased release 和崩溃回退门禁；
- App Store 对动态代码与内容分发的审核策略独立验证。

### Web/Headless

- container/image 签名、数据库/存储迁移、蓝绿/滚动部署、兼容性健康检查；
- Web assets 使用 CSP、SRI/cache/version 治理。

## 6. W10-06 可观测与运维

## 7. W11-01 移除 TypeScript Kernel/Services 正式入口

**前置条件**：Desktop、Android、iOS、Web/Headless 所有计划交付目标已通过；Rust differential suite 无未解释差异；官方插件全部认证。

**动作**：

1. 将 package exports/bin/import 指向 Rust Core/transport 后的正式入口；
2. 删除生产构建对 TypeScript Kernel/service registration 的依赖；
3. 服务器、CLI、测试不再从 Host TS 内部包直接 import；
4. 运行静态扫描，确认只剩 Electron Shell/PAL 可 import Electron/Node 系统 API；
5. 原 TypeScript 行为基线保留为测试 corpus，不保留可运行生产旁路。

**完成判据**：禁用/移除 TypeScript Kernel 产物后全生态正式测试仍通过。

## 8. W11-02 归档与依赖清理

**动作**：按 AGENTS 规则将被替代文件移入就近 `归档/`，不直接删除；清理不再使用的 Node 实现依赖、重复 codec、重复 schema、临时 transport 和迁移脚本；更新 lockfile/SBOM/license inventory。

**完成判据**：依赖图无不可达包、无同一公共协议的双实现、无开发机遗留产物。

## 9. W11-03 文档全量收口

### 设计原稿

修订 Host 定义、内核语言、Shell 矩阵、Bridge 传输、单 Host 概念、移动生命周期和动态插件政策；不再将 Electron/Capacitor 写成全生态唯一假设。

### 生态共用文档

更新 PAL、Kernel、Plugin Runtime、Bridge、安全、Host Services、整体架构图、Bridge API、Host 对外基线、manifest、五类插件、SDK、CLI、文件格式、打包发布和开发环境。公共文档不记录子进程启动参数等 Host 私有细节。

### Host 内部文档

记录 Rust crate 结构、Desktop RPC、Electron PAL、Tauri Mobile integration、Kotlin/Swift PAL、WebView resource server、session recovery、安装事务、module sandbox、发布产物和排障。

### 文档验证

扫描过时技术断言、死链接、重复协议定义、与 schema/route manifest/manifest 不一致的示例；使用实际构建和设备测试结果更新支持状态。

## 10. W11-04 最终生态验收

**验收清单**：

1. 用户在 Desktop/Android/iOS 只安装一个 Host；
2. 同一签名 Web 插件包可在已认证目标运行；
3. 所有服务调用经 Rust Kernel route；
4. 所有插件系统能力经 `window.chips.*` / SDK；
5. `.card/.box/.cpk` 在各端解析、修改和打包语义一致；
6. 插件安装、撤销、权限、更新和审计完整；
7. 编辑引擎在 Desktop 完整验收，在 Android/iOS 保证正确性与数据安全；
8. 社区与个人服务器使用 Rust Headless Core；
9. 所有发布产物有签名、SBOM、provenance、回滚和运维证据；
10. 旧 TypeScript Kernel 无生产入口，正式文档无技术口径冲突。

只有以上全部通过，才能把“跨端 Host 重构”标记为完成。
