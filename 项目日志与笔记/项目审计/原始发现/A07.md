## 发现 F-A07-04

**[P2] `chips-ecosystem/` 未登记 `repos`：按设计"不在旧版范围、不是消灭目标"，但新侧缺逐文件台账，对账只能单向覆盖旧侧**

- 判定：**不是消灭目标，也不应补进 `repos`；它是消灭的目的地**。证据链：
  1. 工具发现函数显式排除：`重构台账.py:433-435` `if name == "chips-ecosystem": continue`（在 `旧版-*`/`Chips-*`/assets 白名单判定之后再点名跳过）；`重构台账.py:85` `NEW_WS = os.path.join(ROOT, "chips-ecosystem")` 作为独立常量存在。
  2. 《01》§一 schema 注释："`repos` 旧仓库/旧文档库登记（**全部标记为旧版**）"；《02-仓库映射与新工作区.md》§三标题即"新 workspace 结构（`chips-ecosystem/`）"，§一表头为"旧仓库 → 新归属"。
  3. 数据面：`SELECT count(*) FROM repos WHERE path LIKE '%chips-ecosystem%'` = 0（唯一命中的 `Chips-EcoSettingsPanel` 是 `LIKE '%chips-eco%'` 大小写不敏感误命中）；`SELECT count(*) FROM files WHERE repo_id LIKE '%ecosystem%' OR rel_path LIKE 'chips-ecosystem%'` = 0；`files.repo_id NOT IN repos` = 0（无孤儿 repo_id）。
  4. 新侧覆盖机制（替代逐文件登记）：`TARGET_CHECK_PREFIXES=("chips-ecosystem/","薯片生态文档库/","重构大计划/")` 落点存在性校验 + `closure` 通道③结构在册扫描（`RESIDUAL-TOPDIR` 白名单 `known_top`，`.cargo/` 已于 #221 补登记）；`REPO_TARGET_PREFIXES` 把 22 个代码仓映射到新侧前缀。
- 缺口（记 P2）：`chips-ecosystem/` 现有 **1333 个 git 跟踪文件**、`薯片生态文档库/` **1107 个**，两者均无 `files` 行（无 sha1/无逐文件状态），因此"台账 vs 磁盘"对账**只覆盖旧侧**；新侧只能靠结构级 closure 与 `target_path` 落点抽样。W7 终验若要"新旧两侧同口径"，需要明确新侧对账通道（是否新增登记表），否则对账结论永远单向。
- 证据：上列 SQL 与 `重构台账.py:85,173,202-231,433`；`git ls-files chips-ecosystem | wc -l` = 1333；`git ls-files 薯片生态文档库 | wc -l` = 1107；《02》§三结构注记。
- 位置：`重构大计划/工具/重构台账.py:85,433`；《01》§一；《02》§一/§三。
