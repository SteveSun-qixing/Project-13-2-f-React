## 结论

- **无 P0**：库物理完整性健康——`PRAGMA integrity_check=ok`，6 表 9 索引与 01 文档 §一 schema 逐列一致，无重复键、无孤儿行、无枚举越界、`repos.file_count` 与 `files` 实数 12793 全等，真库 md5 全程未变且与 `台账操作.log` 记载的写通道终值一致。

## 发现 F-A05-04 / P1

**「只读子命令」在代码层先打开可写连接并具备 DDL 能力，与 01 §4.1/§4.7 真库只读红线不符**

**事实**

1. `main()`（2538–2540 行）对**每个**子命令（含 `stats`/`next`/`report`/`verify`/`preflight`/`migrate-manifest`/`closure`）先调用 `ensure_indexes()`。
2. `ensure_indexes()`（404–416 行）`conn = connect(write=True)` → `isolation_level=None` 的可写连接，并 `conn.execute(ddl)` 执行 `ALTER TABLE … ADD COLUMN` / `CREATE INDEX …`；异常时 `except sqlite3.OperationalError: pass` **静默吞掉**。
3. 文档口径：01 §4.1 标题「**只读**与基础命令」、`next`「**只读**取样」；§4.7「**真库红线**：除 `set-status` 外全部只读」；工具 1584 行注释「真库只读纪律：preflight/migrate-manifest/closure 一律 `connect()`（不写库）」。
4. 本轮因铁律未在真库执行工具（仅在 `/tmp` 沙箱副本执行），故未观测真库字节变化；但代码路径确定：只读子命令对真库持有的是**可写连接**，并在幂等失败时静默跳过（索引/列缺失不报错）。

**证据（SQL/代码与输出）**

```text
重构大计划/工具/重构台账.py:2538-2540
    if args.cmd:
        ensure_indexes()
重构大计划/工具/重构台账.py:404-416
    conn = connect(write=True)          # ← 可写连接
        for table, col, ddl in INCREMENTAL_COLUMNS: ... conn.execute(ddl)
        for ddl in INCREMENTAL_INDEXES: conn.execute(ddl)
    except sqlite3.OperationalError:
        pass                            # ← 静默跳过
重构大计划/工具/重构台账.py:386-395  connect(): isolation_level=None if write else ""；PRAGMA journal_mode=WAL
```

**影响**

- 与文档声称的「只读」不一致：只读子命令具备建列/建索引能力，绕开 `run_write()` 单事务与 `台账操作.log` 留痕纪律（DDL 不产生留痕行）；在只读文件系统、被锁库或权限受限环境下表现为**静默降级**而非显式失败，索引缺失会拖慢认领扫描且无人察觉。
- 审核/审计场景（如本轮铁律「禁止任何写入」）无法安全地对真库直接跑工具，必须做副本沙箱，这与 §4.1 把 `stats`/`next` 归为只读基础命令的预期相悖。

**建议**

1. 把 `ensure_indexes()` 收敛到**显式写入口**（`run_write()` 内）或独立 `migrate` 子命令；只读子命令保持纯 `connect()`，严格对齐 §4.7 红线。
2. 若确需在只读路径保底建索引，至少改用只读连接探测 + 显式告警（不得静默 `pass`），并在 01 §4.5 把「所有子命令执行前补建」的描述与红线口径对齐。
3. 为「只读子命令不改库」补一条回归断言（沙箱副本跑 `stats/next/report/verify/preflight/closure` 前后 md5 相等），纳入 `工具/test_重构台账迁移通道.py`。
