# 工单160-工作区校验脚本与根工作区显式workspaces漂移

## 基本信息

- 工单编号：工单160
- 日期：2026-08-29
- 发现阶段：文件基础卡片插件（file-BCP）开发收尾期，执行工作区级校验
- 问题类型：工具链漂移（校验脚本与根工作区 package.json 口径不一致）
- 状态：待处理

## 背景

提交 `fa42125e`（工作区依赖治理：根 npm workspace 显式化并排除 Chips-PersonalServer）已将生态根 `package.json` 的 `workspaces` 从 `"Chips-*"` 通配模式改为显式目录列表（如 `Chips-BaseCardPlugin/*`、`Chips-ModulePlugin/*`、`Chips-Scaffold/*` 加上逐一列出的其他目录）。

但工作区级校验脚本 `scripts/verify-ecosystem-workspace.mjs` 的 `expectedWorkspacePatterns` 仍然期望根 `package.json` 声明 `"Chips-*"` 通配模式。

## 证据

1. `scripts/verify-ecosystem-workspace.mjs` 中：

   ```js
   const expectedWorkspacePatterns = [
     "Chips-*",
     "Chips-BaseCardPlugin/*",
     "Chips-ModulePlugin/*",
     "Chips-Scaffold/*"
   ];
   ```

2. 生态根 `package.json` 当前（含 fa42125e 提交后状态）`workspaces` 为显式目录列表，不再包含 `"Chips-*"`。
3. 在生态根执行 `npm run verify:workspace` 输出：

   ```text
   生态工作区校验失败：
   - 缺少根 workspace 模式：Chips-*
   ```

## 影响范围

- 生态根正式校验链路 `npm run verify:workspace` 当前必然失败，无法作为工作区级质量门禁使用；
- 工作区治理口径出现两套表述：`package.json`（显式列表，权威）与校验脚本（通配模式，过期）。

## 复现步骤

1. 在生态根目录执行 `npm run verify:workspace`；
2. 观察输出「缺少根 workspace 模式：Chips-*」。

## 期望行为

- `scripts/verify-ecosystem-workspace.mjs` 与根 `package.json` 的 workspaces 口径重新对齐：按「显式列表」口径校验（校验必需的显式条目存在，或校验由白名单驱动的等价规则），不再要求 `"Chips-*"` 通配；
- 若治理方向仍希望保留通配模式，则应回退 `package.json` 的显式化改造，两处只能保留一个口径；
- 校验脚本更新后，`npm run verify:workspace` 应恢复全绿，并纳入后续插件/应用新增工作区条目时的例行核对。

## 暂行处理

- 本工单登记期间，插件/应用级验证继续使用各工程自身 `npm run verify`（lint/typecheck/test/build/validate/package），不依赖工作区级校验结论；
- 不在未对齐口径前修改 `scripts/verify-ecosystem-workspace.mjs` 或根 `package.json`。
