# 工单144：工作区前端工具链与传递依赖存在高危安全漏洞

## 背景

在修复评分基础卡片 iframe 内 antd 样式注入问题时，按工作区新增依赖核对要求执行了 npm 安全审计。当前 npm 默认镜像 `https://registry.npmmirror.com` 不实现 audit API，改用 npm 官方 registry 后发现根 workspace 与链接包依赖树中存在多个已公告漏洞。

本问题与评分插件新增的 `@ant-design/cssinjs@2.1.2` 无直接关系；npm audit 没有把该包列为漏洞来源。

## 证据

在工作区根目录执行：

```bash
npm audit --omit=dev --workspace=chips.basecard.score --audit-level=high --registry=https://registry.npmjs.org
```

审计结果：

- 合计 12 个漏洞：1 个 low、1 个 moderate、9 个 high、1 个 critical；
- critical：`vitest <3.2.6`，当前工作区使用 `vitest@3.2.4`；
- high：包含 `vite 7.0.0 - 7.3.3`（当前构建日志显示 `vite@7.3.1`）、`esbuild 0.27.3 - 0.28.0`、`brace-expansion`、`glob`、`js-yaml`、`lodash`、`nanoid`、`picomatch`、`postcss`、`undici` 等；
- moderate：`yaml 2.0.0 - 2.8.2`；
- 多数项有可用修复，但 `esbuild` 审计提示需要 `--force` 升级到可能改变工具链行为的版本。

`--workspace=chips.basecard.score` 仍报告根 workspace 和 `Chips-SDK/node_modules` 中的项目，说明 npm workspace 审计结果不能等同于“评分插件生产包可达依赖”，修复前必须按具体仓库、生产/开发边界与实际可达性复核。

## 影响范围

- 根 npm workspace 的依赖锁定、Vite 构建与开发服务、Vitest 测试服务；
- Chips-SDK 工具链与其传递依赖；
- 应用、基础卡片、布局和模块插件的构建/测试环境；
- Windows 开发环境、对外监听的开发服务和处理不可信 YAML/网络输入的链路。

## 复现步骤

1. 在工作区根目录执行上述 npm audit 命令。
2. 确认输出包含 `vitest`、`vite`、`esbuild`、`undici` 等漏洞条目。
3. 执行 `npm ls vitest vite esbuild undici --all`，定位各版本的直接或传递来源。
4. 分别在受影响 workspace 执行正式 `typecheck / lint / test / build / validate`，建立升级前基线。

## 期望行为

1. 对每个漏洞记录依赖来源、可达性、生产/开发边界、补丁版本和升级风险。
2. 优先升级可非破坏性修复的 critical/high 依赖，不使用无差别 `npm audit fix --force`。
3. Vite/esbuild/Vitest 等基础工具版本调整必须通过所有受影响 workspace 的正式门禁和 Electron/Windows 核心链路回归。
4. 将安全审计纳入定期门禁，显式使用支持 npm audit API 的 registry，并对已审查且不可达的条目建立有期限的例外记录。

## 暂行处理

- 本轮未执行 `npm audit fix` 或 `npm audit fix --force`；
- 新增 `@ant-design/cssinjs@2.1.2` 只作为 antd 6.5.4 已存在的同源传递依赖的直接声明，不引入新的依赖树；
- 相关升级完成前，不应把 Vite/Vitest 开发服务暴露到不可信网络。

## 需要协作方

- 生态工具链维护方；
- Chips-SDK 维护方；
- 各前端 workspace 维护方。
