# 工单003：17-跨端 Shell 文档端口示例的 `windowId` 类型与能力契约不一致

> 登记日期：2026-09-19
> 登记任务：W1-MAC（Mac 兼容层 / 平台抽象层）
> 状态：待处理

---

## 一、问题描述

《17-跨端 Shell 与平台抽象设计》§4.2 的 `IPalWindowPort` 示例把 `windowId` 声明为 `string`；
《04-能力契约规范》§7.4 的 `window:*` 能力输入输出把 `windowId` 声明为 `number`（Electron
`webContents.id`）。同一概念在两份正式文档中类型不一致，PAL 端口契约与测试无法同时对齐两者。

## 二、证据

- `薯片生态文档库/01-架构设计/01-子系统设计/17-跨端Shell与平台抽象设计.md:234`
  `create(options: WindowCreateOptions): Promise<{ windowId: string }>;`
- 同文件 `:236`–`:241`：`focus` / `close` / `resize` / `move` / `setTitle` / `setState` 的
  `windowId` 均为 `string`。
- `薯片生态文档库/05-接口与契约/04.11-04-能力契约规范-七、内置能力契约（逐项）-7.4 窗口 window-.md:34`
  `windowId: number;`（`:40`、`:51` 同样为 `number`）。
- 同文件约束段（能力契约 §7.4 文末）：“`windowId` 为 Electron `webContents.id`”。

## 三、影响范围

- PAL 端口契约 `src/platform/contracts/window.ts` 与 `WindowSummary`；
- 窗口端口实现与全部窗口端口测试；
- 壳 → 核心会话映射（`webContents.id` 作为会话窗口标识）；
- 事件契约 `window:created` / `window:closed` / `window:focused` 的 `windowId` 载荷口径。

## 四、复现步骤

1. 打开 17 号文档 §4.2，阅读 `IPalWindowPort` 示例；
2. 打开能力契约 §7.4，阅读 `IWindowCreateOutput` / `IWindowInfo` 等接口；
3. 对比同一 `windowId` 的类型声明。

## 五、期望行为

两份正式文档对 `windowId` 的类型声明一致；以能力契约 §7.4 与事件契约载荷为权威口径时，
17 号文档 §4.2 示例应与之保持一致（或其他唯一权威口径，由文档收口方裁定）。

## 六、暂行处理

- W1-MAC 实现与测试按能力契约 §7.4 的 `number`（Electron `webContents.id`）执行，并在
  `packages/host/src/platform/开发计划.md` 记录该口径；
- 本工单未关闭前，后续文档与新代码不得再引入 `string` 口径。
