# 工单029：编辑引擎基础卡片编辑组件宿主契约缺失

## 1. 背景

`Chips-EditingEngine` 当前已经完成：

- 运行时 Provider 接入；
- 工作区文档会话；
- 工作区目录浏览；
- 设置中心治理入口；
- `.card` / `.box` 打开、预览、检查链路。

按阶段三计划，下一步应进入：

1. 编辑域与命令域迁移；
2. 基础卡片编辑面板挂载；
3. 编辑结果回写与自动保存。

在正式进入第 2、3 步前，对生态契约进行了复核。

## 2. 发现的问题

### 2.1 设计稿要求存在，但共享正式宿主契约未闭环

`生态设计原稿/14-编辑引擎设计.md` 明确要求：

- 用户选中基础卡片时，编辑引擎通过内核加载对应编辑组件插件；
- 编辑面板只是容器和挂载点；
- 真实编辑界面由基础卡片插件负责。

这说明“编辑面板宿主能力”不是可选增强，而是编辑引擎正式主链路的一部分。

### 2.2 卡片插件文档声明有编辑组件，但 Host/SDK 未提供正式挂载入口

`生态共用技术文档/插件开发/03-卡片插件开发.md` 声明：

- 卡片插件包含“渲染组件 + 编辑组件”；
- 编辑组件运行在编辑器提供的面板中；
- 保存逻辑提到 `card.update`。

但在当前 Host / SDK 中实际可见的正式能力只有：

- `card.parse`
- `card.render`
- `card.validate`
- `plugin.getCardPlugin`
- `module.mount`

未发现：

- 基础卡片编辑组件的标准入口路由；
- 编辑面板宿主动作；
- `card.update` 正式动作；
- 基础卡片配置读取/提交的正式接口。

### 2.3 基础卡片插件已输出编辑器入口，但生态未消费

在 `Chips-BaseCardPlugin/richtext-BCP/src/index.ts` 中，插件已经实际导出：

- `renderBasecardView(ctx)`
- `renderBasecardEditor(ctx)`

但检索 `Chips-Host` 后，当前 Host 卡片渲染服务只消费 `renderBasecardView`，未看到针对 `renderBasecardEditor` 的正式宿主调用链路。

这意味着基础卡片插件侧已经开始形成编辑器入口，但生态底层尚未把这条链路正式打通。

### 2.4 `module.mount` 的 SDK 与 Host 契约漂移，不能作为可信兜底方案

当前：

- `Chips-SDK/src/api/module.ts` 暴露的是 `module.mount(slot, moduleId)`；
- `Chips-Host/src/main/services/register-host-services.ts` 实际接收的是 `module.mount({ slot, module })`。

因此，即使尝试用 `module` 服务承接编辑面板宿主，也会遇到 SDK / Host 契约不一致的问题，不能把它当作编辑引擎继续推进的正式基线。

## 3. 为什么这是阻断问题

编辑引擎不能采用以下做法：

- 直接动态导入插件安装目录中的 `dist/index.mjs`；
- 通过非正式文件路径私自读取插件产物；
- 自行假定 `renderBasecardEditor` 的上下文签名；
- 绕过正式路由，直接改写 `.card` 文件结构；
- 在没有正式保存接口的情况下做“只改前端内存态”的伪编辑器。

这些都属于临时开发或私有契约，会破坏生态统一架构。

因此，在生态先补齐正式契约前，`Chips-EditingEngine` 不能继续推进编辑面板挂载与自动保存这条开发线。

## 4. 闭环方案与实际落地

2026-03-11 已按生态正式契约完成闭环，落地内容如下：

1. 基础卡片编辑器宿主契约
   - Host 正式新增：
     - `card.getBaseCard({ cardFile, nodeId })`
     - `card.renderBaseCardEditor({ cardFile, nodeId })`
     - `card.updateBaseCard({ cardFile, nodeId, config })`
   - 编辑器宿主统一由 Host 生成 iframe `srcdoc` 文档，不再允许应用直接 import 插件文件。
   - 正式冻结 `chips.basecard-editor:*` 消息协议，并写入共享文档。
2. 基础卡片配置读写契约
   - Host `card` 服务已具备基础卡片配置读取、标准化、回写、更新时间戳、重新打包能力。
   - SDK 已提供对应高层封装，并补齐相关类型与测试。
3. 编辑面板与命令域协作边界
   - `config-change` 作为编辑器 -> 宿主的标准变更事件；
   - `sync-config / config-synced` 作为撤销、重做、回滚后的标准回推机制。
4. `module` 服务与 SDK 契约一致性
   - SDK `module.mount` 已与 Host 对齐为 `{ slot, module }`；
   - 文档、路由清单与测试已同步更新。

## 5. 当前结论

该工单所描述的生态缺口已正式闭环，`Chips-EditingEngine` 可以继续基于共享正式契约推进：

- 基础卡片编辑面板挂载；
- 编辑结果回写与自动保存；
- 后续撤销/重做与预览同步。
