## 二、缺口与证据（复现于 2026-09-21，全部命令 `> /tmp/mg-*.log 2>&1; echo EXIT=$?` 取真实退出码）

### 缺口①（G1）：无 vendor 增量登记通道

1. `重构台账.py:51-54` 的 `EXCLUDE_DIRS` 含 `"vendor"`——`scan` 的目录遍历（`:400-401` `dirnames[:] = [d for d in dirnames if d not in EXCLUDE_DIRS]`）永久跳过任何名为 `vendor` 的目录。实测 `Chips-Office/vendor/` 磁盘 421 个文件，台账 `SELECT COUNT(*) FROM files WHERE rel_path LIKE 'vendor/%'` = **0**（任何仓库均无 vendor 行）。
2. `scan` 是唯一登记 files/symbols 行的入口（`:394` INSERT INTO repos、`:415` INSERT INTO files、`:430-436` symbols 重建），且为**全库重建语义**：现存 28,047 个已裁决符号下，不带 `--force` 直接拒绝——实测 `python3 重构大计划/工具/重构台账.py scan` 退出码 **5**，输出「已有 28047 个符号落裁决：重扫会 DELETE 并重建 symbols、清空这些判定」（`/tmp/mg-scan.log`）；带 `--force` 则清空九路并行波的全部符号判定成果，不可接受。
3. 无任何 `--repo`/`--dir` 限定的增量登记子命令（`main()` 子命令全集 `:1249-1340` 逐一核对）。
4. 补登规模预估（只读复用工具自身 `category_of`/`extract_symbols` 实测，非幻想）：按工具遍历口径 417 个文件（类别分布 code 160 / test 228 / config 13 / doc 10 / other 5 / asset 1），可抽取符号 **2,175** 个。

### 缺口②（G2/G4）：无「已裁决符号」的跨路复裁通道

1. 全库 `symbols WHERE disposition IS NULL` = **0**——G2 的 597 个、G4 的 44 个符号均已由 `ledger-sym-office-b/c`、`ledger-sym-plugins`、`ledger-sym-engine-host` 等路落裁决（status=已裁决）。
2. `symbols-claim` 的认领条件是 `s.disposition IS NULL AND s.wave_owner IS NULL`（`:905`、`:914` UPDATE 守卫）——对已裁决符号恒不可认领。
3. `symbol-dispose` 写权限两路 `files.owner == --owner OR symbols.wave_owner == --owner`（`:837`）；`ledger-matrix-gap` 在库中 0 行认领（files.owner 与 symbols.wave_owner 均 0 命中），所属文件行 owner 为 `ledger-apps` 等历史路。实测 dry-run（不落库）：
   - G4 44 个符号：`symbol-dispose --owner ledger-matrix-gap --symbol <44 ids> --disposition 废弃 --dry-run` → 退出码 0，输出「命中 44 个，可裁决 0 个，越权 44 个」（`/tmp/mg-g4dry.log`）；
   - Office G2 493 个符号：同法 → 「命中 493 个，可裁决 0 个，越权 493 个」（`/tmp/mg-g2dry.log`）。
4. 文件级 `dispose-batch --allow-unclaimed` 只放行 owner 为空的行、且只作用 files 表，不构成符号面复裁通道；`release` 会清空他人裁决，属破坏性操作，禁止用于本场景。
