# 工单140：社区链路封面跨源拦截与传输模块未安装

## 背景
task030 卸担计划后验证社区完整链路（Electron 客户端 ↔ 社区服务器）时发现两个链路缺口。

## 证据
1. **封面图跨源拦截**：客户端请求 `http://127.0.0.1:3000/api/v1/cards/{id}/cover`，响应头含 `Cross-Origin-Resource-Policy: same-origin`（@fastify/helmet 默认），Electron 渲染进程以 `<img>` 跨源加载被拦截 → `ERR_BLOCKED_BY_RESPONSE`。
2. **传输模块未安装**：客户端 `module.invoke` capability `community.card.transfer` 报 `MODULE_PROVIDER_NOT_FOUND`——`host-integration.ts` 的 `defaultModulePlugins` 只含 CardtoHTML 与 FileConversion，未包含 `Chips-CommunityUploader-Plugin`（提供 community.card.transfer）。

## 影响范围
- 客户端打开含封面的卡片（封面图不显示）；
- 客户端社区上传/下载/远程打开卡片链路全部不可用。

## 复现步骤
1. 启动社区服务器（pnpm start:local）；
2. 客户端窗口打开社区卡片详情 → 封面加载失败（ERR_BLOCKED_BY_RESPONSE）；
3. 客户端触发上传/下载 → MODULE_PROVIDER_NOT_FOUND community.card.transfer。

## 期望行为
- API 图片/资源可被跨源 `<img>`/`<iframe>` 正常加载（crossOriginResourcePolicy: cross-origin）；
- CommunityUploader-Plugin 随服务器 Host 集成默认安装并启用。

## 暂行处理
正式修复：helmet 调整 crossOriginResourcePolicy；defaultModulePlugins 增加 CommunityUploader-Plugin。

## 状态
已处理（2026-08-11 修复 + 验证），待用户确认闭环。

## 补充根因（2026-08-11 二次排查）
- **封面 202 占位 / 下载 404 / 渲染 key 不存在的根因**：deploy/.env 设置了 `S3_BUCKET_NAME=ccps`，storage/s3.ts 的 `toStorageTarget` 将公开桶对象映射到 `ccps` 桶（key 加 bucket 前缀），但 `buildObjectUrl` 生成的公开 URL 仍指向逻辑桶直连（`http://127.0.0.1:9000/chips-card-resources/...`），URL 与实际存储位置不一致：
  - 封面/渲染缓存对象实际在 `ccps/chips-card-cover-cache/...`，公开 URL 指向 `chips-card-cover-cache/...` → 404；
  - 历史数据（8-06 上传）对象在逻辑桶（旧配置无 S3_BUCKET_NAME），8-11 上传对象在 ccps 桶，新旧不一致。
- **处理**：移除 .env 的 S3_BUCKET_NAME（恢复对象直存逻辑桶，与公开 URL 和历史数据一致）；迁移 ccps 桶中 8 个对象（network-card/resource 2 个 + cover-cache 1 个 + render-cache 6 个）到各自逻辑桶。
- **验证**：封面接口 302→200（默认封面 HTML）；渲染缓存入口 200；源文件直连 200。
