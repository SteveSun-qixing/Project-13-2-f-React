### 1.1 台账 DB 表结构与数据现状

表结构（查询原文：`sqlite3 "file:重构大计划/重构台账.db?mode=ro" ".schema"`）：

- 全部写通道经 `run_write()`：`BEGIN IMMEDIATE` 单事务 + 失败回滚 + `database is locked` 指数退避重试 8 次，锁耗尽退出码 4（:180-206；退出码常量 :154-157）。

## 三、工具设计稿（新通道建议）

总原则：**不改 schema、不改既有通道语义、不加第三方依赖**（单文件 stdlib 纪律，01 文档 §四头注）；新通道全部落 `重构大计划/工具/重构台账.py`，与台账 DB/旧仓库同在生态过程域，不进 chips-ecosystem 产品仓。

### 3.1 三个新通道 + 统一回执

**通道① `preflight`（迁移前核对，只读）**

```
python3 重构台账.py preflight --repo <id>[,<id>...] [--json] [--receipt <file>]
```

- 检查序列（全部只读 files/symbols + 磁盘）：
  1. 双零前置：本仓 `status<>'已裁决'` 行数 = 0、迁移/重写空 target = 0；
  2. 快照漂移：walk 本仓磁盘（沿用 EXCLUDE_DIRS + `files.sha1` 逐行比对），报 新增/变更/删除 三类（变更=旧仓被违规改动，直接红）；
  3. target 归一化：内置归一化文法（剥「计划归属：」前缀、剥括注 `（…）`、`#` 锚分离、`server/` 视为 `chips-ecosystem/server/` 的 W6 别名）→ 输出 canonical target；解析失败行进 `unparsed` 清单人工裁；
  4. 映射一致性：编码 02 §一 表为常量 `REPO_TARGET_PREFIXES: repo_id → 允许 canonical 前缀集`，逐行校验 canonical target ∈ 允许集；
  5. 红线机检（见 3.3）；
  6. sweep 一致性/孤儿行本仓切片（复用 verify 判据 SQL）。
- 输出：人读文本 +（`--json`）回执；有红项退出码 3，警告项不改变退出码但入册。

**通道② `migrate-manifest`（迁移中执行清单，只读库、可写清单文件）**

```
python3 重构台账.py migrate-manifest --repo <id> --class expand [--out <dir>] [--check-dest]
```

- 从 DB 读本仓 disposition∈(迁移,重写) 的 files 行 + 名下展开符号计数，经通道① 同一归一化函数产 canonical 落点；
- 产出（默认 `/tmp/manifest-<repo>/`，不写 DB）：`manifest-<repo>.tsv`（列：file_id, repo_id, rel_path, sha1, disposition, canonical_target, anchor_count, notes 摘要）、`manifest-<repo>.json`（同构+摘要回执）、按 canonical 目标目录聚合的 `by-zone/` 搬运分组清单（执行者按组搬运/改写，一组一提交）；
- `--check-dest`：目标区同名冲突检测 + 多源行同 target 合并冲突检测；对 `server/` 未创建落点降级为 WARN（与 02 表 W6 行「仓库未创建」注记一致）；
- 清单头部嵌入 `SELECT COUNT(*)` 自检行（行数=DB 命中数），执行波逐组消费后凭回执做 B4 回写。

**通道③ `closure`（迁移后闭环校验 + 矩阵闭合闸，只读）**

```
python3 重构台账.py closure [--repo <id>] [--matrix <glob>] [--json] [--strict]
```

- (a) 落点实落：本仓 迁移/重写 行逐条 `exists(chips-ecosystem/<canonical_target>)`（等价 verify :1359-1397 的仓级切片 + 归一化升级，含 server/ 面与符号 target 锚前段）；重写行另允许 `#点名任务` 尾注豁免到波次结束；
- (b) 矩阵勾稽：解析 `项目日志与笔记/重构计划/旧功能覆盖矩阵-*.md` §一 计数表（markdown 表定向解析，列序固定：仓库|废弃|重写|迁移|保留设计|归档|合计），与 `files GROUP BY repo_id, disposition` 逐项比对；矩阵「新实现位置（证据）」列的路径 token 抽样存在性复核（`文件:行` 引用只核路径，不核行号）；
- (c) 残留扫描：新工作区 walk，命中 (i) 凭据模式文件名、(ii) 废弃/归档行的 `repo_id/rel_path` 同名尾部、(iii) 未在册的顶层目录 → 分别报红；**双零残留终口径 = 待评估 0 + 幻想 target 0 + 残留 0**（第三项由本通道新造）；
- (d) status 终验：`--strict` 下 迁移/重写 行 status 未到「已验证」计红（对齐消灭流程步骤 [6]）。

### 3.2 读写分级与 claim 互斥协议兼容

- 三通道均**只读库**：`connect(write=False)`（:293）+ 不做任何 UPDATE/INSERT/DELETE；WAL 读不阻塞裁决路写，BEGIN IMMEDIATE 协议（:180-206）不受影响；
- 不触碰 owner/wave_owner：preflight/closure 无认领语义；manifest 是 DB 投影非认领单；执行波回写 B4 建议**新增最小写通道 `set-status`**（`--owner --id-file --status {进行中,已完成,已验证} [--evidence]`，仅允许 owner 原路回写 status 与 notes 追加，禁碰 disposition/target，复用 run_write + log_operation）——避免借道 dispose-batch 造成的「claim 条件不再命中、owner 校验无合法入口」断层；除 `set-status` 外**本设计稿不新增任何写通道**；
- 与 `symbol-redecide` 复裁协议兼容：closure 报出的矛盾行只出点名清单（symbols.id 级），复裁仍走工单032 通道② 的 `--from-owner` 越权拒绝协议，本设计不旁路。

### 3.3 两条安全红线的机检规则形态

- **凭据红线**（preflight 检查 5 + closure (c)(i)）：
  - 规则=三段断言：① 台账面：`rel_path` 命中凭据模式集（`*/deploy/.env`、`.env`（排除 `.env.example`/`.envrc` 命名面单列）、`*.pem`、`*.key`、`id_rsa*`、`secrets.*`）⇒ 断言 disposition∈(废弃,归档) 且 canonical_target 不得落 `chips-ecosystem/**`——现状 3 真值 .env 已判废弃（1.4 抽样6），该断言今天即可全绿；
  - ② 新仓面：closure walk `chips-ecosystem/**` 命中同名模式 ⇒ 直接红（搬运残留闸）；
  - ③ 轮换登记：preflight 回执为每条命中凭据行输出固定 issue 码 `CRED-ROTATION`（含 repo/rel_path），带「须由主智能体在 W6 完成轮换并签收」的 requires-ack 字段——回执文件是人审闭环的载体，工具本身不声称验证了轮换（防止机检越权虚假绿灯）。
- **永不入库红线**（preflight 检查 5 + closure (c)(iii)）：
  - 规则=四段断言：① DB 面 `repos`/`files` 对 `cordis-main`、`deepseek-harness-master` 行数为 0（现状实测 0，即可回归为基线）；② `git ls-files -- cordis-main deepseek-harness-master` 输出为空（子进程只读命令，stdlib subprocess 可承受）；③ manifest 任何一行 rel_path 前缀不得命中两目录名（搬运清单入口拦截）；④ 建议项（本单只设计不改）：根 `.gitignore` 增加两条显式 ignore，使 ② 从「恰好没 add」升级为「git 层面不可能 add」——登记为 W4 前工具落地波的一行变更，由主智能体派发。
