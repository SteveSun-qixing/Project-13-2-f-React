# 工单073：G9 边界门禁副作用导入检测缺口

> 登记日期：2026-10-03 ｜ 登记方：W6 服务端迁移臂（server/community 首臂，G9 扩权批） ｜ 状态：开放
> 影响域：`chips-ecosystem/tools/gates/check-boundaries.mjs`（G9 架构边界门禁，tools/gates 门禁维护域独占）

## 一、背景

W6 服务端首臂按 G9 扩权批交付 `server` 边界规则（`tools/gates/gates.config.json`）时，按 RFC 验收要求对 fail-closed 语义做反向验证：向 `@chips/community-server` 注入禁用的 `@chips/ui` 依赖与导入，确认 `BOUNDARY010` / `BOUNDARY020` 如期命中。反向验证第二段发现：源码闸（BOUNDARY020）对**副作用导入形态**存在旁路。

## 二、证据

1. `tools/gates/check-boundaries.mjs` `extractImports()` 的提取管线：行首判定 `^\s*(?:import|export)\b` 命中后，以 `complete()`（要求 `from '…'` 或 `require('…')` / `import('…')` 调用形态）续行拼块，最终仅从 `fromMatch` / `callMatch` 取说明符——**无 `from`、无调用括号的裸副作用导入 `import '包名';` 不产出任何 specifier**。
2. 实测（2026-10-03，工作区分支「第五次重构」）：
   - 在 `server/community/packages/server/src/routes/health.ts` 顶部注入 `import '@chips/ui';` 并在 `package.json` 声明 `@chips/ui` 依赖 → `node tools/gates/check-boundaries.mjs` 仅报 1 条 `BOUNDARY010`（依赖声明面），源码导入零违规，EXIT 仍按违规计红但 **BOUNDARY020 缺席**；
   - 移除依赖声明、仅保留源码 `import '@chips/ui';` → `gates:boundaries` **EXIT=0 全绿**，BOUNDARY020/021 均未命中（旁路成立）；
   - 换 `import { config } from '@chips/ui';` 形态 → `BOUNDARY020` 命中（同文件同包）。
3. 同构旁路面：`forbiddenModules`（如 electron）与 `forbidNodeBuiltins`（如浏览器插件环境注入 `import 'node:fs';`）两闸同样只作用于 `extractImports` 产出物，副作用导入形态一律绕过。

## 三、影响范围

- G9 架构边界门禁的源码检测面：BOUNDARY020（禁止导入）、BOUNDARY021（未声明内部依赖）、BOUNDARY022（仅允许 import type）对副作用导入形态零检出，fail-closed 语义在该形态下失守；
- 依赖声明面（BOUNDARY010/011）不受影响：跨包内部依赖仍须在 `package.json` 声明，先被 BOUNDARY010 拦一道；纯源码级旁路（不声明依赖直接副作用导入未声明内部包）当前完全无检出；
- 本工单不影响 W6 服务端首臂交付面（`server` 规则登记 + RFC-G9服务端产品域边界规则），登记方已按「验证物即删」清理反向验证残留。

## 四、复现步骤

1. 任选在册包（如 `server/community/packages/server`）任一 src 源文件，顶部加一行 `import '@chips/ui';`（不声明依赖、不加 from）；
2. 运行 `node tools/gates/check-boundaries.mjs`：零新增违规（期望：BOUNDARY021「源码导入未声明的内部依赖」命中）；
3. 声明 `@chips/ui` 依赖后复跑：仅 BOUNDARY010 命中（期望：并报 BOUNDARY020「源码禁止导入」）；
4. 对照组：改写为 `import { x } from '@chips/ui';` 复跑，BOUNDARY020 如期命中。

## 五、期望行为

1. `extractImports` 补副作用导入形态：`import 'x';` / `export * from 'x';`（后者现已被 from 形态覆盖）单独成块时也提取说明符，进入同一判定管线（BOUNDARY020/021/022）；
2. `tools/gates/tests` 门禁自测补对应用例：副作用导入的内部包、forbiddenModules、Node 内置三断言；
3. 收口后本工单在《问题工单.md》更新状态与结论。

## 六、暂行处理

无（无临时绕过）。本工单属 tools/gates 门禁维护域独占，登记方按独占目录纪律不改门禁代码；W6 服务端臂的 RFC 反向验证已改用 from 导入形态完成，登记后本轮继续推进可交付部分（AGENTS「登记后继续推进」口径）。
