# 工单046：编辑引擎仍未真正切到“Host 已安装基础卡片插件即自动可用”的正式链路

## 1. 工单目标

本工单用于记录并推动解决以下正式阻断：

- 编辑引擎当前仍依赖本地静态基础卡片注册表和源码导入；
- 这与“用户在新设备上只安装 Host、编辑引擎应用插件，并在 Host 中安装基础卡片插件后即可正常使用”的正式目标冲突；
- 在该缺口处理完成前，不应继续把当前实现当作基础卡片链路重构的最终完成态。

## 2. 发现背景

在工单043后续全链路复核中，对以下范围做了交叉核对：

- `Chips-EditingEngine`
- `Chips-Host`
- `Chips-SDK`
- `Chips-BaseCardPlugin/*`
- `生态共用技术文档/`
- `生态设计原稿/`
- `项目日志与笔记/工单043-完成编辑引擎插件链路的重构/`

复核目标是确认当前实现是否已经真正满足：

1. Host 是基础卡片插件唯一正式事实来源；
2. 编辑引擎不再保留本地静态注册作为正式主链路；
3. 用户只需在 Host 安装基础卡片插件即可获得完整编辑能力。

结果确认：当前尚未满足。

## 3. 证据

### 3.1 编辑引擎仍保留本地静态基础卡片注册表

文件：

- [registry.ts](/Users/sevenstars/Documents/ChipsCard/Develop/Project-13-2-f-editing-engine-plugin-chain-refactor/Chips-EditingEngine/归档/basecard-runtime-static-registry/src/basecard-runtime/registry.ts)

当前实现直接写死：

- `imageBasecardDescriptor`
- `richtextBasecardDescriptor`

这说明编辑引擎仍然以本地编译期注册表作为基础卡片描述符来源。

### 3.2 编辑引擎仍直接导入基础卡片插件源码

文件：

- [image.ts](/Users/sevenstars/Documents/ChipsCard/Develop/Project-13-2-f-editing-engine-plugin-chain-refactor/Chips-EditingEngine/归档/basecard-runtime-static-registry/src/basecard-runtime/registrations/image.ts)
- [richtext.ts](/Users/sevenstars/Documents/ChipsCard/Develop/Project-13-2-f-editing-engine-plugin-chain-refactor/Chips-EditingEngine/归档/basecard-runtime-static-registry/src/basecard-runtime/registrations/richtext.ts)

当前实现仍直接 import：

- `../../../../Chips-BaseCardPlugin/image-BCP/src/index`
- `../../../../Chips-BaseCardPlugin/richtext-BCP/src/index`

这说明编辑引擎包仍要求这些基础卡片插件源码被纳入自身构建。

### 3.3 编辑态仍依赖本地描述符，否则直接失败

文件：

- [EditorHost.tsx](/Users/sevenstars/Documents/ChipsCard/Develop/Project-13-2-f-editing-engine-plugin-chain-refactor/Chips-EditingEngine/src/editor-runtime/EditorHost.tsx)

当前逻辑：

1. `EditorHost` 先调用 `getBasecardDescriptor(cardType)`；
2. 若未命中本地描述符，直接报错：
   - `未注册基础卡片编辑器`
3. 即使 Host 已安装该插件，编辑态仍不能继续。

这说明编辑引擎的编辑链路并未真正建立在 Host 已安装插件之上。

### 3.4 卡箱库仍扫描工作区仓库目录，而不是 Host 已安装插件

文件：

- [data.ts](/Users/sevenstars/Documents/ChipsCard/Develop/Project-13-2-f-editing-engine-plugin-chain-refactor/Chips-EditingEngine/src/components/CardBoxLibrary/data.ts)

当前实现：

- `import.meta.glob('../../../../Chips-BaseCardPlugin/**/manifest.yaml')`

这说明卡箱库展示的基础卡片类型仍来源于当前 monorepo 中的源码目录，而不是 Host 的插件安装与启用状态。

## 4. 与正式目标的冲突

当前实现与以下正式目标直接冲突：

### 4.1 用户目标冲突

用户明确要求：

1. 新设备安装 Host；
2. 安装编辑引擎应用插件；
3. 在 Host 安装基础卡片插件；
4. 编辑引擎直接可用。

但当前实现实际上要求：

1. 基础卡片插件还必须被静态编译进 `Chips-EditingEngine`；
2. 卡箱库还必须能在本地仓库里扫描到对应 `manifest.yaml`；
3. 编辑态还必须能在本地描述符注册表中找到该类型。

### 4.2 文档结论冲突

以下文档已经把“不保留本地静态注册正式双路径”写成正式结论：

但当前代码仍保留关键静态路径，因此代码与正式文档再次漂移。

## 5. 影响范围

### 5.1 对用户体验的影响

- Host 已安装但未被编辑引擎内置的基础卡片插件，不会自动出现在卡箱库中。
- 某些基础卡片类型即使查看态能通过 Host 单卡会话渲染，编辑态仍会失败。
- “安装即用”的生态体验目标当前尚未达成。

### 5.2 对工程架构的影响

- Host 与编辑引擎继续并存两套插件事实来源；
- 新增基础卡片插件仍有被迫修改编辑引擎源码的风险；
- 后续若继续迁移更多基础卡片插件，会把静态依赖面进一步放大。

## 6. 期望正式能力

为实现用户目标，至少需要补齐以下正式能力之一，并统一架构决策：

### 方案能力要求

1. 编辑引擎获取基础卡片可用列表时，必须以 Host 已安装且已启用插件为唯一事实来源。
2. 编辑引擎编辑态必须能在不静态内置插件源码的前提下装载基础卡片编辑器运行时。
3. 编辑引擎查看态与编辑态都要共享同一套 Host 权威插件发现、类型匹配、资源桥和主题注入规则。
4. 卡箱库、创建链路、查看链路、编辑链路必须同时切换，不能只改其中一段。

### 需要明确的设计决策

1. 编辑态最终是：
   - Host 托管编辑器 iframe；
   - 还是 Host 提供某种正式可装配运行时描述，再由编辑引擎拼接；
   - 还是其他正式能力；
2. 若继续要求编辑引擎本地直接挂载 `renderBasecardEditor`，那么 Host 应如何正式提供该运行时，而不是依赖 monorepo 源码 import；
3. 卡箱库应通过哪条正式 Host / SDK 能力查询基础卡片插件列表与元数据。

## 7. 处理结果

2026-03-16 已完成以下正式修复：

1. `Chips-EditingEngine/src/editor-runtime/EditorHost.tsx` 已切到 Host `basecard.openSession + basecard.renderEditor + basecard.onReady/onChange/onError` 链路，不再以本地 `BasecardDescriptor` 或源码 import 作为编辑态前置条件。
2. `Chips-EditingEngine/src/components/CardBoxLibrary/CardBoxLibrary.tsx` 已改为通过 `Chips-EditingEngine/src/services/card-plugin-catalog.ts` 从 Host `plugin.query({ type: 'card' })` 获取已安装且已启用的基础卡片类型。
3. `Chips-EditingEngine/src/components/CardBoxLibrary/data.ts` 已移除基础卡片 `manifest.yaml` 扫描正式路径，保留布局插件本地清单逻辑。
4. `Chips-SDK/src/api/card.ts` 已补齐 `basecard.renderEditor({ sessionId, resources })` 资源桥封装，供编辑引擎正式消费。
5. 已新增并通过单测：
   - `Chips-EditingEngine/tests/unit/plugin-host.test.tsx`
   - `Chips-EditingEngine/tests/unit/card-plugin-catalog.test.ts`
   - `Chips-SDK/tests/card.test.ts`
6. 已按仓库规则把退出正式主链路的静态注册遗留实现移入归档目录：
   - `Chips-EditingEngine/归档/basecard-runtime-static-registry/`

## 8. 当前结论

当前“新设备只安装 Host、编辑引擎应用插件，并在 Host 安装基础卡片插件后即可正常编辑”的正式目标已经在本工单范围内闭环。

仍保留在 `basecard-runtime/registry.ts` 与 `registrations/*` 中的旧静态描述符仅作为遗留测试/对照代码存在，不再参与编辑引擎卡箱库与编辑态正式主链路。
