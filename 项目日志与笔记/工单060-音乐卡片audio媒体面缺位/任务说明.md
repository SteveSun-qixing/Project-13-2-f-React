# 工单060：音乐卡片 audio 媒体面缺位

> 登记日期：2026-09-30
> 登记方：W4 music 迁移原子任务（`chips.basecard.music`）
> 状态：开放
> 性质：宿主能力缺位登记（非本包缺陷）；解析与渲染照常交付，打开臂如实降级。

## 一、背景

旧基础卡族 `music-BCP` 按覆盖矩阵行（`旧功能覆盖矩阵-三插件仓库-2026-09-20.md` :40 及 :34~:37、:44~:45 装配行）迁移为 `chips-ecosystem/plugins/basecards/music/`。交付过程中确认：查看态「播放」臂依赖的三层宿主面均未就绪，本包按「如实登记缺位、解析与渲染照常交付」推进。

## 二、缺位明细与证据

1. **音乐播放器处理器未实现**
   - 《09-官方插件与应用目录》§4.2 music 行权限列「无（仅平台链路）」、状态「已设计」；§5.2 `chips.official.music-player` 状态「已设计」，处理器 `primary`：`audio/*`。
   - `resource:open` 路由（《14-资源打开与默认处理器契约》）在 audio 槽位无任何候选：primary/fallback 均未注册，§7 未安装降级面对 `.mp3/.flac/.m4a` 无 shell 回退（归档态成员不可回退）。
2. **渲染帧插件执行通道未交付**
   - `packages/host/src/renderer/entries/frame.ts` 头注（:13~:14）：「插件内容装载臂（按 pluginEntries 加载基础卡片插件执行 renderView 到节点容器）属插件执行通道波次（工单025 剩余 / #85 RFC 落波）」。
   - 帧内 `window.chips` 不注入（08 §5.4），帧内打开臂正式通道 `frame:action` 未接；当前就近渲染容器侧经 SDK `chips` 客户端真调可用。
3. **编辑器资源导入通道缺位**
   - 旧 music-BCP 的编辑器由旧 Host 注入 `importResource` / `deleteResource` / `convertTiffToPng` / `resolveResourceUrl` 通道（`music-BCP/src/editor/panel.tsx` :39~:51、`src/index.ts` :50~:58 注入面）。
   - 新架构编辑器契约（08 §4）只承载配置回流，不写文件；音频文件落卡片的导入编排（含嵌入元数据自动补全：解析 → 写封面/歌词资源 → 回填配置，`audio-metadata.ts` 已随包交付）归属资源写入链路，未开放给基础卡片编辑器。

## 三、影响范围

- 受阻：音乐卡片查看态播放臂（点击 → `resource:open` → 音乐播放器）。当前点击在就近容器返回 `RESOURCE_HANDLER_MISSING` 类失败、帧内通道不可用，界面以行内简体中文提示如实呈现，不伪造成功。
- 不受阻：ID3v2/MP4/FLAC 元数据解析（纯模块 + 42 项测试）、播放卡渲染（封面/标题/歌手/元信息/空态）、编辑面板（路径与信息表单 + 制作团队）、`validateConfig` / `createInitialContent` / `collectResourcePaths`、包构建与五阶段校验（`music-0.1.0.cpk` 校验通过）。

## 四、复现步骤

1. 构建并安装 `plugins/basecards/music`（`chips plugin pack` + `chips plugin install`）。
2. 创建 `base.music` 节点，配置合法 `audio_file`（如 `tracks/demo.mp3`）。
3. 查看态点击播放面：`chips.request('resource:open', …)` 无 audio 处理器命中 → 行内提示「音频暂时无法打开：当前渲染环境未提供播放通道，请稍后重试」。

## 五、期望行为

1. `chips.official.music-player` 按《14》§9.2（载荷 `chips.music-card` v1.0.0）与《09》§5.2 落波，注册 `audio/*` primary 处理器；本包打开臂零改动回填可用。
2. 帧插件执行通道（工单025 剩余 / #85）交付后，帧内打开臂自 SDK 客户端切换为 `frame:action` 正式通道。
3. 编辑器资源导入通道归属裁定（资源写入链路 / 编辑链路扩展）后，在 `editor.tsx` 接线音频导入编排并消费 `audio-metadata.ts` 自动补全（《01》§6.8 补充说明第 3~5 条全量落地，含 TIFF→PNG 约束）。
4. 《09》§4.2 music 行状态翻正「已迁移」并补实现路径（与本批交付同步完成）。

- 打开臂真实调用 `resource:open`，失败行内如实提示，不 mock 成功、不临时自建 `<audio>` 播放面、不引入第二套播放实现。
- 嵌入元数据解析器以纯模块 + 真实字节夹具测试交付，等待导入通道接线，不做半接线假流程。
