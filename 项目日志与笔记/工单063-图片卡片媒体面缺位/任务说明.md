# 工单063：图片卡片媒体面缺位

> 登记日期：2026-09-30
> 登记方：W4 image 迁移原子任务（`chips.basecard.image`）
> 状态：开放
> 性质：宿主能力缺位登记（非本包缺陷）；渲染与编辑照常交付，打开臂与导入臂如实降级。

## 一、背景

旧基础卡族 `image-BCP` 按覆盖矩阵行（`旧功能覆盖矩阵-三插件仓库-2026-09-20.md` :43 及 :34~:38、:44~:46 装配行）迁移为 `chips-ecosystem/plugins/basecards/image/`。交付过程中确认：查看态「查看大图」臂与编辑态「本地导入」臂依赖的宿主面未就绪，本包按「如实登记缺位、渲染与编辑照常交付」推进。

## 二、缺位明细与证据

1. **图片查看器处理器未实现**
   - 《09-官方插件与应用目录》§5.2 `chips.official.photo-viewer` 状态「已设计」，处理器 `primary`：
     `image/png`、`image/jpeg`、`image/webp`、`image/gif`、`image/bmp`、`image/svg+xml`、`image/avif`。
   - `resource:open` 路由（《14-资源打开与默认处理器契约》）在图片槽位无候选：primary/fallback 均
     未注册，§7 未安装降级面对归档态成员不可回退系统默认打开方式；W5 媒体查看器重写波次未落。
2. **渲染帧插件执行通道未交付**（与工单060 ②、工单061 ③同源）
   - 帧内 `window.chips` 不注入（08 §5.4），帧内打开臂正式通道 `frame:action` 未接
     （工单025 剩余 / #85 RFC 落波）；当前就近渲染容器侧经 SDK `chips` 客户端真调可用。
3. **编辑器资源导入通道缺位**（与工单060 ③、工单062 ③同源）
   - 旧 image-BCP 由旧 Host 注入 `importResource` / `deleteResource` / `importArchiveBundle` /
     `convertTiffToPng` 通道（`image-BCP/src/index.ts` :101~:104 注入面、`src/editor/panel.tsx`
     拖放导入面）。
   - 新架构编辑器契约（08 §4）只承载配置回流；本地图片文件落卡片的导入编排（选择/拖放 → 资源
     写入 → 路径回填）归属资源写入链路，未开放给基础卡片编辑器。
   - TIFF→PNG 转换依赖内容处理服务族（《09》§6.2 处置表：`converter.*` / `image.*` 作废 ID 禁止
     复活为 Bridge 能力，按 `IServicePlugin` 重写，服务波次待落）；本包不迁移旧转换臂。

## 三、影响范围

- 受阻：图片卡片查看态「查看大图」臂（点击 → `resource:open` → 图片查看器）。当前点击在就近容器
  返回 `RESOURCE_HANDLER_MISSING` 类失败、帧内通道不可用，界面以行内简体中文提示如实呈现，
  不伪造成功；编辑态本地文件导入臂不可用，面板内行内提示如实说明。
- 不受阻：四种布局渲染（单图/网格/纵向长图/横向滚动，含溢出角标与加载失败占位）、链接添加与替换、
  既有配置（含 file 来源图片）的信息与排版编辑、拖拽排序与删除、`validateConfig` /
  `createInitialContent` / `collectResourcePaths`、包构建与四闸。

## 四、复现步骤

1. 构建并安装 `plugins/basecards/image`（`chips plugin pack` + `chips plugin install`）。
2. 创建 `base.image` 节点，配置合法图片（如 file 来源 `photo.jpg` 或 url 来源远程图）。
3. 查看态点击图片：`chips.request('resource:open', …)` 无 image 处理器命中 → 行内提示
   「图片暂时无法打开：当前渲染环境未提供查看通道，请稍后重试」。
4. 编辑态「添加图片」面板：无本地文件入口，行内提示「本地图片文件导入依赖编辑器资源导入通道
   （工单063）」。

## 五、期望行为

1. `chips.official.photo-viewer` 按《14》§3/§4（image/* primary 处理器）与《09》§5.2 落波；
   本包打开臂零改动回填可用。
2. 帧插件执行通道（工单025 剩余 / #85）交付后，帧内打开臂自 SDK 客户端切换为 `frame:action`
   正式通道。
3. 编辑器资源导入通道归属裁定（资源写入链路 / 编辑链路扩展）后，在 `editor.tsx` 接线本地图片
   导入编排；TIFF→PNG 按《15-文件处理契约》以内容处理服务落波后回填导入链路
   （《01》§6.3 补充说明第 2~3 条全量落地）。
4. 《09》§4.2 image 行状态翻正「已迁移」并补实现路径（与本批交付同步完成）。

## 六、暂行处理（零绕过）

- 打开臂真实调用 `resource:open`，失败行内如实提示；不 mock 成功、不临时自建灯箱/缩放查看面、
  不引入第二套查看实现。
- 编辑器不伪造导入流程：承接链接添加、选中图片信息编辑（标题/替代文本/替换链接）、拖拽排序与
  删除、排版设置；file 来源图片的既有配置可正常编辑。
