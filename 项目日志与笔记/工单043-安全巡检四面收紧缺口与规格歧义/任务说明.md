# 工单043：安全巡检四面收紧缺口与规格歧义（W3-P1-4）

> 登记：主智能体，2026-09-21。来源：任务 #140 安全渗透面巡检（`项目日志与笔记/W3-P1-4-安全渗透面巡检/巡检报告.md`，四面 24 已防/4 真缺口/3 暂行/3 信息，无高危）。本单收编四条需裁决项（A1–A4），主智能体逐条裁定与归属如下；A5（External SSRF）系段二在册交付位，不另立。

## 背景与证据（全部写前核证）

- **A1（低·规格歧义+收紧缺口）**：`chips-resource/src/path_guard.rs:228-234` `is_forbidden_unicode` 平面封顶 `(code_point >> 16) <= 10`（注释自述 n=1..10），且不含 U+FDD0–U+FDCF；《06.02》§2.4（`薯片生态文档库/05-接口与契约/06.02-06-资源协议规范-二、URI 语法.md:70`）写「非字符（U+nFFFE/U+nFFFF）」未限 n。Unicode 标准非字符全集为 **n=0–16 全 17 平面**（U+11FFFE…U+10FFFF 可达且现不触发）+ **U+FDD0–U+FDCF**（现不触发，测试 `:553` 明示）。
- **A2（低·两面收紧口径漂移）**：`packages/cli/src/artifacts/cpk-validate.ts:487-493` `createPublicKey` 后无 `asymmetricKeyType==='ed25519'` 断言；宿主 `packages/host/src/loader/trust-roots.ts:89-102` 有。注入含 RSA/EC PEM 时 CLI 按该钥自身算法 one-shot 验签，`algorithm:'ed25519'` 字段成装饰性声明（非独立可乘路径：注入文件由操作员供给）。
- **A3（中·执行位悬空）**：user 渠道缺签「未签名发布者需用户确认」全链无强制承载位——`signature.ts:123-127` skip+标记、`validate.ts:499-501` 仅警告文本、`plugin-activation.ts:173-176` 注明「本波维持」；全仓 `unsignedPublisher` 无 UI/确认闸消费者（grep 实测 4 处）。非绕过（契约 §6.3 明文允许），但确认闸无归属波次号。
- **A4（中·纵深防御）**：PAL 窗口 `packages/host/src/main/app-launch.ts:92-99`、`self-check.ts:38-42` 的 `webPreferences` 仅钉 preload+partition，未过 `buildWindowWebPreferences`/`assertSecureWebPreferences`（该函数在 `window-security.ts:79` 实存，两文件实测零引用）；sandbox/contextIsolation/nodeIntegration 依赖 Electron ≥20 缺省值。当前缺省形态安全，风险面=Electron 升级缺省漂移或该面被复用装载不可信内容。

## 影响范围

- A1：资源 URI 校验面（缓存键/比较面可进畸形非字符）；文档面《06.02》/《06.07》措辞。
- A2：CLI `pack/validate` 信任根装载点；不改变现有合法包判定结果。
- A3：user 渠道安装语义承诺（「需用户确认」暂无执行位）。
- A4：PAL 启动/自检两窗口构造路径。

## 复现步骤

- A1：构造 URI 百分号编码 U+10FFFF 或 U+FDD0 → PathGuard 放行（现行为，测试 `:553` 为在案自证）。
- A2：信任根文件注入 RSA 公钥 PEM + `algorithm:'ed25519'` 声明 → CLI 装载不拒（宿主拒）。
- A3：安装无 `signature.json` 的 user 渠道包 → 仅警告文本，无确认闸。
- A4：读 `app-launch.ts:92-99` 对照 `window-security.ts` 断言链即结构性复现。

## 主智能体裁定与归属（2026-09-21）

1. **A1 采「规格全集」方向**：《06.02》§2.4 非字符措辞收紧为「U+nFFFE/U+nFFFF（n=0–16 全平面）与 U+FDD0–U+FDCF 非字符区，另 U+FFFD」，《06.07》词表注记随动；实现随动 = `is_forbidden_unicode` 平面封顶放宽至 `>> 16 <= 16` + 增 FDD0–FDCF 触发臂，测试翻转（`:553` 案）+ `error_code_lock` 同型随动，**错误码值零改动**（仍 `RESOURCE_PATH_INVALID`+`reason=unicode`）。归属：**实现随 chips-resource 段三收口波（TD-002 偿还同单）**；文档面为纯措辞收紧、可先行单独小单（波次冲突账由主智能体掌握）。
2. **A2 归工单028 同波**：Base64/SPKI 编码统一裁决（028 在案）落地时把 `assertEd25519Spki` 口径镜像到 CLI 装载点（`createPublicKey` 后断言 `asymmetricKeyType==='ed25519'`，不合即严格错误），两两面单点收敛；不单派小单，防与 028 用户裁决面撞口径。
3. **A3 归「更新与分发 Phase」立项裁决**（028 同族波）：届时定义确认闸契约（UI 承载位 + lifecycle 安装前拦截点 + user 渠道策略形状）；**本轮暂行**=维持现状（警告+激活锚定在册，不新增临时确认 UI——禁临时实现红线）。本单把「未挂波次号」翻正为「挂 028 同族波」，即视为执行位归属结案。
4. **A4 归宿主组合根整理波**（#135 工单041 修复波验收后与 025/036 后续整理同单）：PAL 两窗口构造并入 `buildWindowWebPreferences` 缺省 + `assertSecureWebPreferences` 硬闸，配 host 包测试锁（显式钉死 nodeIntegration:false/contextIsolation:true/sandbox:true 不依赖 Electron 缺省）；**不在本波单派**（packages/host 为 #135 独占在途面）。
