# 工单152-文件类型识别三套语义并存：任务说明

## 1. 背景

文件类型识别在生态内存在三套并存语义，无统一公共能力：SDK `document.detectType` 仅按 .card/.box 后缀判断；编辑引擎 `drag-drop-manager.detectFileType` 按 MIME + 扩展名 + chip 特殊扩展名完整识别；编辑引擎 `workspace-service.buildTree` 按 `.card/` 目录存在性识别卡片目录。拖放路由、工作区扫描、打开路由各自为政。

## 2. 证据

- `Chips-SDK/src/api/document.ts`（186-198 行）：detectDocumentType 仅 endsWith('.card') / endsWith('.box')；
- `Chips-EditingEngine/src/core/drag-drop-manager.ts`：detectFileType（MIME + 扩展名 + chip 特殊扩展名）；
- `Chips-EditingEngine/src/services/workspace-service.ts`（201-240 行）：buildTree 按 `.card/metadata.yaml` 存在性识别卡片目录；
- Host 无统一识别动作（file 域无 detectType）。

## 3. 影响范围

- Chips-SDK document API、Chips-EditingEngine 拖放/工作区/卡箱库；
- 未来文件管理器类软件、社区客户端文件识别。

## 4. 复现步骤

1. 对比三处实现的文件类型判定逻辑；
2. 对同一文件调用 document.detectType 与 drag-drop-manager.detectFileType，返回粒度不同；
3. 确认无 Host 侧统一识别动作。

## 5. 期望行为

- Host 提供 `file.detectType` 结构化识别动作（documentType / mimeType / category），输出正式契约；
- SDK `document.detectType` 增强为同语义（与 Host 一致，或直接消费 Host 动作）；
- 编辑引擎 drag-drop-manager 与 workspace-service 消费公共实现，删除本地 MIME 表；
- 冻结「卡片目录识别规则」与「Host 运行时目录排除清单」为公共契约。

## 6. 处理进展（2026-08-11，M1 部分完成）

- Host 新增 `file.detectType` 动作（`register-host-services.ts`），逻辑收敛于 `src/shared/detect-type.ts` 纯函数（documentType/mimeType/category 结构化输出），含契约测试 `tests/unit/shared-detect-type.test.ts`；
- SDK `file.detectType` API 与类型（FileDetectTypeResult/FileDocumentType/FileCategory）落地，route-manifest 契约同步；
- 编辑引擎 `drag-drop-manager.detectFileType` 扩展名兜底改走 SDK `guessMimeType`（MIME 表收口）；
- 剩余项：workspace-service 卡片目录识别改走统一识别（随 M6 工作区扫描上移完成）。

## 7. 需要协作方

Chips-Host file 服务域维护方、Chips-SDK 维护方、Chips-EditingEngine 维护方。

## 8. 当前状态
