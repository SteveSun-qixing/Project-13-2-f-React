## 一、目标与非目标

**目标**（《08.08》链路四全量落位）：

1. `IPermissionAuditEntry`（§8.2 十六字段，计数按裁定F 2026-09-21 对 §8.2 代码块实读翻正）契约同型类型入协议层，全链单一事实源；
2. `<userData>/logs/audit/audit-YYYY-MM-DD.jsonl` 落盘：按日切分+10MB 序号轮转、异步追加失败不阻塞判定、append-only、180 天/高风险 365 天留存清理、§8.5 脱敏；
3. 运行时判定（放行与拒绝）全量记录（裁定一权威口径），`permission:granted`/`permission:denied`/`security:audit` 三事件有真实生产者；
4. 免权限直通不产审计条目（裁定二），仅经授予判定的 allow 与 deny 入流；
5. 审计挂点唯一判定面（裁定三禁双挂点），硬绑工单025 剩余项③判定面统一之后；
6. Rust 侧（chips-bridge/chips-resource）拒绝/放行出站信号接口形态经 RFC 裁定后接线（裁定三.4）。

**非目标**：

- 授权存储 `permissions.yaml` 与授予/撤销交互链本体（链路二独立立项，本册段一只锁审计所需字段与事件，不实现 grant/revoke 流程；`revoked`/`user_rejected` 两 reason 的产生位随链路二翻正）；
- Chips-EcoSettingsPanel 审计消费 UI（面板仓库独立波次，依赖本册段一能力表登记完成后方可开工）；
- 命令系统 `ICommandAuditEntry`（13.06 §6.2 共存储，写入器建成后另单随附）；
- 「逐码」段（PERMISSION 族四码三方一致）——工单013 已收口，本立项书不重复验收；剩余逐码面是 reason 五枚举产生位映射。

## 二、四段拆分（每段独立可验收、串行依赖显式）

### 段一：横切与契约先行（可与落文波并行筹备，实施面涉及 host/bridge/sdk，须待 #147 交回后派单）

- traceId/requestId 全链路传递：`InvocationContext.traceId` 自 preload→`bridge:request`→router→事件下行贯通（host-trace.ts:14-16 头注自认缺口在册）；审计条目 `traceId/requestId` 字段以此为源，禁另造关联键。
- `IPermissionAuditEntry` 十六字段入 `@chips/bridge` 协议层与 SDK 生成面，形状逐字对《08.08》§8.2 表；现存异型 `IPermissionAuditRecord`（7 字段，permission-evaluator.ts:278-287）收口为别名或迁移，禁三型并存。
- ULID：cordis `ulid.rs` 提公开面或独立 TS 设施，二选一拍板后锁测试覆盖单调性与跨日翻卷。
- 能力契约登记（《04》审计读取/授予/撤销恢复三条目）已由 t046-auditdoc-agent 落文波承接，本段仅核证登记面与后续实现码表一致。
- **验收**：契约快照增量锁测、bridge/sdk/host 三面包 build/test/lint 定点闸 0、链检 0。

### 段二：审计写入器基础设施（纯 host 主进程新模块，依赖段一类型与 ULID）

- JSONL 写入器：同序异步队列形态复用 host-trace 工程母型（host-trace.ts:238-270），但**常开、不受 CHIPS_TRACE 门控**（诊断≠审计，工单041 隔离口径）；写失败→内部告警（onDiagnostic/onFault 通道）不阻塞判定，dropped 计数入告警载荷。
- 轮转/留存：按日文件名+同日 10MB 序号后缀；启动期+跨日界到期清理（180 天基线档、高风险 365 天档，风险级别由《08》词表判定）；读取接口仅平台侧（段一登记的审计能力），插件无读写。
- 脱敏：§8.5 规则入写入器单点（resourceUri query 腿沿用 resource-uri.ts:484 在册口径）。
- **验收**：写入器单测矩阵（轮转边界/留存清理/失败隔离/脱敏逐值）、锁文件与多窗口并发用例、TD-002 型覆盖率口径登记。

### 段三：判定面挂钩与三事件发射（硬绑工单025 剩余项③，先决条件不满足不开工）

- 前置：统一判定面裁决落地（宿主 router 与 bridge 包 router 二选一收口，W3-P1-5 G4 报告 §六.2 口径）；G1 缺省 provisioner `grantedPermissions:['*']` 臂同波收口为正式权限快照（025③ 验收判据在册）。
- `createHostCapabilityRouter` 注入 `audit` 挂点：allow/deny 全量落条目+发射 `permission:denied`/`permission:granted`；`security:audit` 增量事件经订阅面广播（events.ts:56-58 登记面、payload=§8.2 同型）；免权限直通臂（裁定二）显式不记录并锁测该不记录臂。
- 「写入失败不阻塞」验收母本：bridge/core/router.ts:141-150 既有锁测语义平移。
- **验收**：三事件发射位 E2E 锁测（契约快照 payload 逐字段）、直通不产条目锁测、G1 收口判据复跑。

### 段四：跨层采集 sink RFC（chips-bridge/chips-resource 出站信号，公共协议变更走 RFC）

- RFC 议题：`DecisionObserver`/sink trait 形态、回调线程语义（拒绝热路径禁阻塞）、与 cordis 事件面关系、crate 无 tracing 现状（两 crate `tracing|log::` 0 命中）下出站信号的最小接口；chips-resource 侧挂点已随 046 勘查建议并入段三捆绑单（以 #151 落盘验收为准）。
- 实施单在 RFC 批准后另立；Bridge 内核接线波（工单025 主线）复撞风险由本段消除。

## 三、风险与在册冲突防护

- 禁双套判定并存期各挂一钩（裁定三）；段三开工前先验 025③ 状态。
- 审计流刷屏：Platform 免权限恒放行（permission.rs:219-221）+ self-scope 直通——裁定二豁免+锁测防护。
