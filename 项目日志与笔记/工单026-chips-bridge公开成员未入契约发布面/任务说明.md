# 工单026 —— `chips-bridge` 公开面已从契约登记的 4 方法扩到 18 成员，接口名与签名从未进入契约发布面（宿主无口径接线）

> 登记日期：2026-09-20
> 来源：task043《契约-代码漂移审计-2026-09-20》面 3 第 5 条与面 5 第 2 条（W2 P0，需 RFC，审计原文判「同单」；即审计报告系统性结论 C），登记前已到代码复核。
> 性质：只登记问题，不含解决办法；对外发布口径需 RFC 裁定。

## 一、背景

《03-核心接口规范》§5 登记的 `impl Bridge` 公开面只有 4 方法：`register` / `unregister`（`薯片生态文档库/05-接口与契约/03.05-03-核心接口规范-五、Bridge（chips-bridge）.md:83-90`）、`request` / `cancel_session`（`:124-130`）。《04-能力契约规范》§4.4（`04.04-04-能力契约规范-四、能力注册、发现与注销.md:71-82`）只发布「行为与触发表」，不发布 Rust 侧接口名与签名。而实际交付的 `chips-bridge` crate 已经把注册、代际接管、会话生命周期等实现为一组远大于契约的公开 API 面。审计报告系统性结论 C：「内核可测、但宿主不可接」。

## 二、证据（文件:行号，均于 2026-09-20 复核；行号以本轮 grep 实测为准）

1. `chips-ecosystem/packages/core-rust/crates/chips-bridge/src/bridge.rs` 公开方法实测 15 个：`activate_provider`:323、`deactivate_provider`:352、`grant_capability_id`:373、`register`:409、`takeover_register`:423、`unregister`:532、`begin_draining`:551、`open_session`:571、`close_session`:594、`cancel_session`:600、`shutdown`:610、`is_shutdown`:622、`invocation_context`:628、`has_capability`:655、`capability_state`:664。
2. `chips-ecosystem/packages/core-rust/crates/chips-bridge/src/lib.rs:100-104`：再导出 `CapabilityState` / `ProviderKind` / `ProviderRegistration` 三类型与 `DEFAULT_MAX_QUEUE` 等 5 常量——连同第 1 条构成审计统计的 18 个公开成员（超出契约 4 方法的 11 方法 + 3 类型 + 5 常量，其中契约在册仅 `register` / `unregister` / `request` / `cancel_session`）。
3. `薯片生态文档库/` 全库 grep `takeover_register|begin_draining|CapabilityState|grant_capability_id|activate_provider` 0 命中（本轮实测）——这批 API 名在契约发布面完全不存在。
4. 契约与实现的语义差：`bridge.rs:405-408` 的 `register` 文档注释已引用《能力契约规范》§4.4 行为条款并把代际覆盖指向 `takeover_register`，即实现以契约行为为纲、但契约没有这批接口的名字与签名可供宿主按文接线。

## 三、影响范围

- 文档缺位 + 依赖倒挂：对外契约未发布这批成员，宿主、绑定层（见工单025）与任何第三方 Rust 消费者都无从依据契约使用，只能读源码；而未发布即被内部依赖，等价于以 crate 源码为事实上的公共 API。
- 《04-能力契约规范》§4.4 的三条触发表（工单005 剩余面②在途实现的行为面）没有「触发 → 具体 API」映射，行为承诺不可执行化。
- 涉及文档：`05-接口与契约/03-核心接口规范` §5、`05-接口与契约/04-能力契约规范` §4.4；涉及消费者：宿主集成层（W3 前置）、chips-native 绑定扩展面。

## 四、复现步骤

3. 在 `薯片生态文档库/` 全库检索 `takeover_register` 等任一名 —— 0 命中。

## 五、期望行为

`chips-bridge` 的公开 API 面与《核心接口规范》§5、《能力契约规范》§4.4 的发布面一一对应：宿主侧任何接线所需的接口名、签名、语义都能在契约中找到；契约未发布的成员不对生态内其它 crate/进程成为必需依赖。发布口径（哪些收进 §5、哪些定为 crate 内部面）属跨包公共协议变更，需 RFC 裁定。
