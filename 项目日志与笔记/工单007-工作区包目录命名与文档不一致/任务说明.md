## 一、背景

新工作区 `chips-ecosystem/` 的实际包目录为 `packages/{bridge,sdk,host,ui,antd,cli,...}`（见 `chips-ecosystem/README.md` 目录结构与实际文件系统），而文档库中的正式规范与 ADR 使用 `packages/host-electron/`、`packages/antd-fork/`、`tools/cli/` 等命名。两套口径并存会导致按文档复制的路径命令（tsconfig references、Vite 配置路径、构建脚本示例）指向不存在的目录。

## 二、证据

1. **实际工作区**：`chips-ecosystem/README.md:25` 为 `packages/host/`、`:28` 为 `packages/antd/`、`:29` 为 `packages/cli/`；`ls chips-ecosystem/packages` 实际为 `antd bridge cli core-rust host native sdk ui`，不存在 `host-electron`、`antd-fork`、`tools/cli`。
2. **代码组织规范**：`薯片生态文档库/02-开发规范/01.03-01-代码组织规范-三、包划分.md:18` 表项为 `host-electron/`、`:20` 为 `antd-fork/`、`:49` 示例目录树为 `packages/host-electron/`、`:74` 为 `packages/antd-fork/`；§3.3 工具目录写为 `tools/cli/`。
3. **构建与打包**：`薯片生态文档库/06-开发与运维/02.05-02-构建与打包-五、前端构建.md:17-20`、`:43`、`:75`、`:134` 均以 `packages/host-electron/...` 为路径示例。
4. **ADR-008**：`薯片生态文档库/01-架构设计/ADR/ADR-008-React加fork-antd前端技术栈.md:48`、`:64-65` 使用 `antd-fork/`（同文档"现状注记"第 4 条同时声明"fork antd 的包名、目录与依赖方向以《代码组织规范》与《构建与打包》为准"，而这两份文档自身口径与现状不一致）。
5. **过程记录**：`chips-ecosystem/开发日志.md` 中 W1-DOCS 与 W1-ROOT 条目已分别记录工作区布局差异与 `tools/contract-gen`、`docs/` 等口径差异，均标注"待主代理裁决后同步文档或目录"。

## 三、影响范围

- 子智能体与插件模板按文档复制的路径命令（`tsconfig.json` references、Vite 配置注释、构建脚本）指向不存在目录；
- `packages/antd` 与 `packages/ui` 的依赖边界规则在两套目录命名下表述不同，代码审查与门禁脚本的路径判断存在歧义；
- ADR-008 与《代码组织规范》互相引用时形成口径循环，无法确定唯一事实源。

## 四、复现步骤

1. 在 `chips-ecosystem/` 执行 `ls packages`，输出无 `host-electron`、`antd-fork`；
2. 打开 `薯片生态文档库/02-开发规范/01.03-01-代码组织规范-三、包划分.md` 对照 §3.1 表与 §3.1 目录树，路径为 `host-electron/`、`antd-fork/`；
3. 打开 `薯片生态文档库/06-开发与运维/02.05-02-构建与打包-五、前端构建.md` §5.2 示例 `"path": "./packages/host-electron"`，该目录不存在。

## 五、期望行为

1. 包目录命名在全生态收敛为唯一口径，并在《代码组织规范》《构建与打包》《仓库映射与新工作区》与 `chips-ecosystem/README.md` 四处保持一致；
2. `@chips/antd`（fork antd）与 `@chips/host` 的目录名、包名、依赖方向表述不再互相引用为对方依据；
3. 按文档复制的路径类命令可直接执行。
