# 工单061：网页卡片嵌套帧臂与资源读宿主面缺位

> 登记日期：2026-09-30
> 登记方：W4 webpage 迁移原子任务（`chips.basecard.webpage`）
> 状态：开放
> 性质：宿主能力与帧策略缺位登记（非本包缺陷）；内容模型、视口协议与双臂加载代码照常交付，帧加载臂按环境如实降级。

## 一、背景

旧基础卡族 `webpage-BCP` 按覆盖矩阵行（`旧功能覆盖矩阵-三插件仓库-2026-09-20.md` :38「网页卡片资源加载」**重写**裁决及 :34~:37、:44~:45 装配行）迁移为 `chips-ecosystem/plugins/basecards/webpage/`。交付过程中确认：查看态「网页帧加载」臂依赖的宿主面与帧策略均未就绪，本包按「如实登记缺位、双臂代码照常交付、行内简体中文如实提示」推进。

## 二、缺位明细与证据

1. **`resource:read` 能力宿主侧处理器未注册**
   - 契约面在册：`packages/bridge/src/protocol/capability-contracts.ts:62` `contract('resource:read', ['resources:read'], [target('resources:read', 'uri')])`；`packages/sdk/src/generated/capability-ids.ts:16/:85` 与 `capability-permissions.ts:19`（`'resource:read': ['resources:read']`）生成表在册；权限 `resources:read` 为《插件清单规范》§6 在册词（授予 `resource:read` 等能力），本包 manifest 已按最小面申请。
   - 运行面缺位：`packages/host/src/` 全量 grep `'resource:read'` 零命中——host loader（`packages/host/src/loader/activation.ts` 的 `registerCapability` 注册面）无任何 resource 域处理器注册，内核路由无目标可命中。`chips.request('resource:read', { uri })` 在就近渲染容器（主窗口语境、`window.chips` 已注入）必然失败返回。
   - 后果：srcdoc 臂（读入口 HTML → `<base href=包目录URI>` 组装 srcdoc，相对引用由帧内资源协议解析）在当前所有环境回退 src 臂；srcdoc 臂为平台补注册后零改动生效。
2. **查看态渲染帧 CSP `frame-src 'none'`，嵌套帧臂在查看帧不可达**
   - `packages/host/src/main/window-security.ts:61/:76`：`RENDER_FRAME_CSP` 的 `frame-src 'none'`（卡片帧臂），头注 :48~:50 明示「host 当前生产面唯一活帧形即卡片帧」「布局帧臂 `frame-src chips-resource:` 的按帧种类下发机制归箱子渲染波次（#190 勘查登记）」。
   - 主窗口面 `MAIN_WINDOW_CSP`（:31）`frame-src chips-resource:` 放行受管 URI：src 臂在就近渲染容器（主窗口语境）真实可达；查看帧内 url 臂与 src 臂的嵌套帧加载均被 CSP 拦截，呈加载超时/失败语义（10 秒时限，`EMBED_DETECTION_TIMEOUT_MS`）。
   - 帧策略属平台决策（按帧种类下发 CSP，#190 在册）；本包 url/src/srcdoc 三臂代码就绪，平台放行后零改动生效。
3. **渲染帧插件执行通道未交付（与工单060 第②条同源）**
   - `packages/host/src/renderer/entries/frame.ts` 头注：「插件内容装载臂（按 pluginEntries 加载基础卡片插件执行 renderView 到节点容器）属插件执行通道波次（工单025 剩余 / #85 RFC 落波）」；帧内不加载 `window.chips`（沙箱帧无 preload 语境，08-基础卡片插件接口 §5.4）。
   - 后果：查看帧内 srcdoc 臂的 SDK 客户端调用不可用（`SDK_BRIDGE_UNAVAILABLE` 异步拒绝），自动落 src 臂；帧内打开臂正式通道 `frame:action`（14-资源打开与默认处理器契约 §8.5）未接，旧 `openResource` 打开意图臂不迁移、不假接线。
4. **编辑器资源导入桥缺位（与工单060 第③条同源）**
   - 旧 webpage-BCP 由旧 Host 注入 `importArchiveBundle` / `deleteResource`（`webpage-BCP/src/index.ts:86~:87`、`src/editor/panel.tsx:25` 注入面），承担网页 ZIP 解压导入与旧包资源清理。
   - 新架构编辑器契约（08 §4）只承载配置回流，不写文件；资源写入与清理由编辑链路正式资源桥承担（《05-渲染引擎设计》§6.3、《09-官方插件与应用目录》§7.3），该桥未见交付。本包编辑器以「安全路径输入（归一校验）+ 资源清单逐行维护」承接已导入内容的配置面，不伪造上传入口。

## 三、影响范围

- 受阻：网页卡片查看态网页帧加载（url 直载 / bundle srcdoc 组装）在查看帧内不可达；bundle srcdoc 臂在全部环境回退 src 臂。界面以行内简体中文如实提示（「该网页禁止被 iframe 嵌入。」「网页加载失败。」「网页包加载失败。」），不伪造成功。
- 不受阻：内容模型与校验（`validateConfig` / `createInitialContent` / `collectResourcePaths`，66 项测试）、URL 安全分析（http(s) 白名单、凭据拒绝）、srcdoc 安全组装（属性/脚本双重转义、`</script` 防逃逸、沙箱基线 `allow-scripts allow-forms allow-popups`）、视口同步协议（postMessage 下发 + 文档直写 + 内容高度回报，fixed 7:16 / free 展开封顶宽 20 倍）、编辑面板（模式切换 / 路径与清单维护 / 行内校验）、双入口构建（`dist/index.js` 自包含 + `render.js` vendor 外部化）与四闸（test 66 通过 / typecheck / lint / build 全绿）。

## 四、复现步骤

1. 构建并安装 `plugins/basecards/webpage`（`chips plugin pack` + `chips plugin install`）。
2. 创建 `base.webpage` 节点，`source_type=url` 配置合法 http(s) 地址，在查看帧打开：帧加载被 `frame-src 'none'` 拦截，10 秒后呈「该网页禁止被 iframe 嵌入。」。
3. `source_type=bundle` 配置包内网页目录，在就近渲染容器（主窗口语境）查看：`chips.request('resource:read', …)` 无宿主处理器命中 → 自动回退 src 臂（帧内资源协议直载），srcdoc 臂不生效。

## 五、期望行为

1. host 侧按《04-能力契约规范》与 bridge 在册契约注册 `resource:read` 处理器（资源管理器读路径，8 MiB 单次上限口径见《06-资源协议规范》），srcdoc 臂零改动回填可用。
2. 按帧种类下发 CSP（#190 勘查落波）：卡片帧开设网页帧臂（`frame-src http(s) https:` 或经资源代理的受管形式，由平台帧策略裁定），url 臂与 src 臂零改动生效。
3. 帧插件执行通道（工单025 剩余 / #85）交付后，帧内 SDK 调用与 `frame:action` 打开臂按正式通道接线。
4. 编辑链路资源桥交付后，`editor.tsx` 接线网页 ZIP 解压导入编排（ZIP 导入 → 写包内目录资源 → 回填 `bundle_root` / `resource_paths`），与工单060 第③条同波收口。
5. 《09-官方插件与应用目录》§4.2 webpage 行状态随本批交付翻正「已迁移」并补实现路径与 `resources:read` 权限口径（已同步完成）。
