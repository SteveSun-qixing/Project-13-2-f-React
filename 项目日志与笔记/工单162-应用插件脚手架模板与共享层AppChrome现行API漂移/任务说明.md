# 工单162-应用插件脚手架模板与共享层AppChrome现行API漂移

## 基本信息

- 工单编号：工单162
- 日期：2026-08-29
- 发现阶段：薯片绘图（Chips-Photo）应用插件开发期，使用官方脚手架初始化工程
- 问题类型：脚手架漂移（模板与共享层现行 API 不一致，工单137 收口后的跟进缺口）
- 状态：待处理

## 背景

工单137 收口后，`@chips/ui` 的 `AppChrome` 已精简为「命令面板 + 可滚动内容区」的极简外壳，不再渲染菜单栏与工具栏；`MenuBar` / `Toolbar` 组件保留导出供内容区局部 UI 使用。

但 `Chips-Scaffold/chips-scaffold-app/templates/app-standard` 模板仍停留在精简之前的 API 上：模板 `AppShell.tsx.tpl` 向 `AppChrome` 传递 `appName`、`menus`、`toolbarItems` 三个 props，而这三个 props 在现行 `AppChromeProps`（`Chips-Ui/src/components/AppChrome.tsx`）上不存在。

## 证据

1. `Chips-Ui/src/components/AppChrome.tsx` 现行 props 仅为：`paletteShortcut / immersive / immersiveContentClass / children / footer / contentStyle`。
2. `Chips-Scaffold/chips-scaffold-app/templates/app-standard/src/app/AppShell.tsx.tpl` 传递 `<AppChrome appName menus toolbarItems paletteShortcut="Mod+P">`，按现行类型定义预期 typecheck 报错。
3. 模板 `tests/e2e/basic-flow.test.ts.tpl` 仍断言 AppShell 源码包含 `MenuBarGroup`，与「命令收敛到命令面板」的新口径不一致。
4. 由该模板生成、尚未重写前端的 `Chips-Word`、`Chips-Sheet` 工程同样存在此问题（AppShell 与模板逐字节一致）。

## 影响范围

- 所有新由 `chipsdev-r create app` 生成的工程在未重写 AppShell 前无法通过 `npm run typecheck`；
- 模板 e2e 结构守卫与共享层口径不一致，会误导后续开发。

## 复现步骤

1. 在生态根执行 `chipsdev-r create app Test-App`；
2. 对生成工程执行 `npm run typecheck`，预期出现 AppChrome 未知 props 类型错误；
3. 对照 `Chips-Ui/src/components/AppChrome.tsx` 与模板 `AppShell.tsx.tpl`。

## 期望行为

1. 模板 `AppShell.tsx.tpl` 移除 `appName / menus / toolbarItems` 传参，按现行 AppChrome API 使用（菜单类能力如需保留，改用内容区局部 `MenuBar` 或全部收敛到命令面板）；
2. 模板 e2e 守卫断言同步更新（移除 `MenuBarGroup` 断言或改为断言现行口径）；
3. 已生成的 `Chips-Word`、`Chips-Sheet` 同步收口。

## 暂行处理

- 薯片绘图（Chips-Photo）前端为全量重写，AppShell 按现行 AppChrome API 实现，不受此漂移影响；
- 未重写前端的既有生成工程保持现状，待工单处理时统一收口。

## 需要协作方

- Chips-Scaffold 维护方（chips-scaffold-app 模板）
- Chips-Word、Chips-Sheet 维护方
