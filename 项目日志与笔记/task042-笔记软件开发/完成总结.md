## 关键决策记录

### 1. 布局方案
**决策**：使用 FlexLayout 替代无限桌面  
**原因**：
- 笔记应用需要固定的三栏布局
- FlexLayout 提供了成熟的面板管理能力
- 可以保留无限桌面作为可选视图

### 2. 基础卡片复用
**决策**：完全复用编辑引擎的基础卡片运行时  
**原因**：
- 避免重复开发
- 保证一致的卡片渲染效果
- 简化后续维护

### 3. 状态管理
**决策**：使用 React Context 而非 Redux  
**原因**：
- 应用状态相对简单
- Context 足够满足需求
- 减少依赖和复杂度

### 4. 文档优先
**决策**：先完善文档再实现功能  
**原因**：
- 明确需求和技术方案
- 指导后续开发
- 便于团队协作
