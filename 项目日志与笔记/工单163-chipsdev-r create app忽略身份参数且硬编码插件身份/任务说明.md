# 工单163-chipsdev-r create app忽略身份参数且硬编码插件身份

## 基本信息

- 工单编号：工单163
- 日期：2026-08-29
- 发现阶段：薯片绘图（Chips-Photo）应用插件开发期，使用官方脚手架初始化工程
- 问题类型：工具链缺口（CLI 参数解析与实际消费不一致，正式插件身份被硬编码为示例身份）
- 状态：待处理

## 背景

`chipsdev-r create app <targetDir>` 用于从官方脚手架生成应用插件工程。CLI 参数解析器 `parseCreateArgs`（`Chips-SDK/cli/index.js`）已支持 `--plugin-id / --display-name / --version / --template` 等选项，脚手架侧 `CreateAppProjectOptions`（`chips-scaffold-app/src/core/types.ts`）也已具备接收 `pluginId / displayName / version / authorName / authorEmail` 的能力。

但 `handleCreate` 的 `type === 'app'` 分支完全不消费这些选项，全部字段硬编码派生：

| 字段 | 现状取值 |
|---|---|
| pluginId | `com.example.<slug>`（硬编码前缀） |
| displayName | projectName 按 `-_` 拆词后 Title Case |
| version | `'0.1.0'`（硬编码） |
| templateId | `'app-standard'`（硬编码） |
| authorEmail | `` `${slug}@example.invalid` `` |

## 证据

1. `Chips-SDK/cli/index.js` `handleCreate`（约 L2249–2281）：`--plugin-id`、`--display-name`、`--version` 仅在 `theme` 与 `module` 分支被消费，`app` 分支忽略；
2. 生态内正式应用插件身份口径为 `com.chips.<name>`（如 `com.chips.photo-viewer`、`com.chips.word`），而 `create app` 生成的 `manifest.yaml` 中 `id: com.example.<slug>` 属示例身份，需要人工二次修改；
3. `chips-photo@example.invalid` 之类 author 邮箱为占位身份；
4. `parseCreateArgs` 未定义 `--author-name / --author-email` 选项，脚手架 API 已支持对应字段但 CLI 无法传入。

## 影响范围

- 每个新应用插件工程生成后都必须人工修改 manifest.yaml / index.html / config / src 中的插件身份，易遗漏、易漂移；
- `com.example.*` 示例身份若被遗漏进入提交，会污染正式插件治理链路（Host plugin id、快捷方式、CLI commandPath 归属）。

## 复现步骤

1. 在生态根执行 `chipsdev-r create app Chips-Photo --plugin-id com.chips.photo --display-name 薯片绘图`；
2. 检查生成 `manifest.yaml`：`id` 仍为 `com.example.chips-photo`，`name` 仍为 Title Case 派生值，选项被静默忽略。

## 期望行为

1. `create app` 分支接入已解析的 `createOptions`（`--plugin-id / --display-name / --version / --template`），并补充 `--author-name / --author-email` 解析；
2. 未显式提供时的派生兜底行为可保留，但 pluginId 前缀不应硬编码 `com.example.`，建议按工程名/交互确认或要求显式传入正式 id；
3. 与脚手架 API（`CreateAppProjectOptions`）字段完全对齐。

## 暂行处理

- 薯片绘图（Chips-Photo）生成后已将 `com.example.chips-photo` 统一收口为 `com.chips.photo`、`Chips Photo` 收口为 `薯片绘图`，身份已在工程内修正；
- 其他工程在工单收口前继续人工修正身份字段。
