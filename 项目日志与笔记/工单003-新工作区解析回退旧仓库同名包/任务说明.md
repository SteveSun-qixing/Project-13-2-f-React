# 工单 003：新工作区 TypeScript 解析回退旧仓库同名包

> 登记：W1-ROOT（2026-09-19）
> 状态：待处理
> 影响：全部 `import ... from '@chips/ui'` 的类型检查、ESLint 类型感知规则与构建；W1 准出判定（`pnpm typecheck` / `pnpm lint` / `pnpm build`）；架构红线"旧版冻结、单一实现"

---

## 一、背景

`chips-ecosystem/` 位于旧仓库根目录内，旧仓库根 `node_modules/` 由旧 npm workspace 生成，其中存在与工作区新包同名的符号链接 `@chips/ui -> ../Chips-Ui`（旧仓库 `Chips-Ui/package.json` 的 `name` 为 `@chips/ui`，且其 `exports` 直接指向 `./src/index.ts`）。

新工作区的 `packages/ui` 以 `exports.types -> ./dist/index.d.ts` 声明类型入口；在 `dist/` 未构建时，TypeScript 判定该包无法解析后**不报错终止，而是继续向祖先 `node_modules` 查找**，最终命中旧仓库的旧 `@chips/ui` 并按旧源码解析。旧 `Chips-Ui` 源码内部再引用旧 SDK（`chips-sdk -> Chips-SDK`），于是整棵旧实现被编译进新包的检查程序。

## 三、影响范围

- **架构红线**：新代码的类型检查与 lint 静默编译旧仓库实现，与"旧版冻结、单一事实源、无第二实现"直接冲突；该解析一旦进入 CI，可产生"假绿"。
- **W1 准出**：`pnpm typecheck` / `pnpm lint` 在 `packages/ui` 未构建时无法给出可信判定；`examples/plugins/hello` 的 127 处 lint 报错同源。
- **打包**：Vite 构建走包内 `node_modules` 与外部化清单，暂不受影响；但任何基于 `tsc` 的声明产出与类型检查都受影响。
- **范围**：当前旧仓库根 `node_modules/@chips` 中与工作区同名的包为 `@chips/ui`（另有 `editing-engine`、`notes`，新工作区无同名包）。新工作区后续新增与旧包同名的包（如 `@chips/sdk`、`@chips/bridge`）时，同类风险自动出现。

## 四、复现步骤

1. 确认 `chips-ecosystem/packages/ui/dist/` 不存在（未执行 `pnpm --filter @chips/ui build`）。
2. 在 `chips-ecosystem/` 执行 `pnpm --filter @chips/plugin-hello run typecheck`。
3. 观察报错中出现 `Chips-Ui/src/**`、`Chips-SDK/src/**` 路径的编译错误，以及 `Module '"@chips/ui"' has no exported member ...`。
4. 执行 `pnpm --filter @chips/plugin-hello exec tsc --noEmit -p tsconfig.json --traceResolution`，检索 `Chips-Ui/src/index.ts`，可见回退解析全过程。

## 五、期望行为

1. `@chips/*` 的模块解析只能命中 `chips-ecosystem/` 工作区内的包；工作区包类型/产物缺失时必须报"找不到模块/找不到类型"，不得回退到旧仓库或任何工作区外同名包。
2. 工作区内外同名包的隔离策略必须有唯一权威口径（工作区移出旧仓库 / 统一 `paths` 或项目引用解析 / 旧仓 `node_modules` 隔离），并落入文档库。

## 六、暂行处理

- 无。本轮不引入临时修复（不做 `paths` 局部映射、不手工清理旧仓 `node_modules`），避免形成双轨解析口径。
- 本工单作为 W1 准出阻塞项登记；`pnpm build`（先构建 `@chips/antd`、`@chips/ui`）后再执行类型检查时，现象暂时消失，但不能作为收口依据。
