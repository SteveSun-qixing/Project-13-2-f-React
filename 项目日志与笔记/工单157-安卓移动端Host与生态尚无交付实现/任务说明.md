# 工单157：Android 移动端 Host 与生态尚无交付实现

## 1. 背景

用户计划开始 Android 平台测试。对设计原稿、生态共用技术文档、Host、SDK、正式插件 manifest、构建脚本和本机 Android 环境进行核查后，确认当前仓库只有 Desktop/Headless Host，Mobile 只存在类型和契约预留，没有可安装 Android 产物。

## 2. 证据

- 共用接口基线明确写明 Web/Mobile Shell 尚未交付；
- `Chips-Host/src/main/shells` 只有 desktop/headless；
- `Chips-Host/packages/pal/src` 只有 Node adapter；
- Host 主入口为 Electron app-entry；
- Bridge 依赖 Electron ipcMain/ipcRenderer/contextBridge；
- 安装器脚本只有 macOS；
- 全仓无 Gradle、AndroidManifest、APK/AAB 构建配置；
- HostCore/card/box/zip/plugin/module 等仍大量直接依赖 Node API；
- 35 个正式插件中只有 2 个声明 mobile=true，且源码/`os` 声明仍有移动端不一致；
- 没有 Android instrumentation/E2E/设备 CI。

## 3. 影响范围

- Chips-Host Shell、PAL、Core、Services、Bridge、Plugin Runtime、Module Runtime、Installer；
- Chips-SDK transport/types/CLI；
- 五类插件 manifest、构建与移动认证；
- `.card/.box/.cpk` 的 Android 文件/分享链路；
- 生态共用架构、协议、插件、运维和发布文档。

## 4. 复现步骤

1. 在 `Chips-Host` 查找 AndroidManifest/Gradle，结果为空；
2. 查看 package scripts，只存在 TypeScript build 和 macOS installer；
3. 查看 shells/PAL，只存在 desktop/headless 与 Node adapter；
4. 执行 `adb devices -l`，即使 Android 工具可用，也没有可安装 Host APK；
5. 尝试寻找 `assembleDebug` 或 APK 产物，无入口。

## 5. 期望行为

- 正式 `MobileHostShell`；
- 正式 Android PAL 与 capability snapshot；
- 可移植 Host Core，平台能力全部经 ports/PAL；
- 安全 WebView resource/Bridge/surface/session；
- Android 文件、URI、生命周期、后台和凭证能力；
- 五类插件移动执行与认证模型；
- debug APK、release AAB、签名和 CI；
- 模拟器/真机测试和正式文档闭环。

## 6. 暂行处理

不做临时网页壳或伪 PAL。本轮仅完成详细调查、目标方案和开发计划：

`项目日志与笔记/task037-安卓端完善/`

Android 真机功能测试须等待“可安装 Host 骨架”里程碑完成。当前可先开展工具链校准、ADR、portable core 和 Android Shell 开发。
