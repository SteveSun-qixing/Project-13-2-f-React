# 工单145：箱子布局缺少条目完整文档渲染契约

## 背景

`card.render` 已能把本地 `.card` 渲染为 Host 托管的复合卡片文档，箱子布局也由 Host 生成受控网页。但两条链路之间没有以箱子条目为边界的正式转换契约，导致布局只能获取封面或请求 Host 新开文档窗口。

## 证据

- `生态共用技术文档/协议与契约/08-箱子布局运行时契约.md` 只定义了摘要、详情、封面、资源、预取和打开动作。
- `Chips-SDK/src/api/box.ts` 的 `BoxLayoutRuntimeAction` 与文档窗口 Bridge 没有条目完整文档渲染动作。
- `Chips-Host/packages/box-service/src/box-service.ts` 注入布局页面的 Runtime 不包含完整卡片渲染方法。
- `Chips-BoxLayoutPlugin/documentLibrary-BLP/src/view/page.tsx` 右侧预览只调用 `renderEntryCover`，激活时调用 `openEntry`。
- `Chips-Host` 和 `Chips-SDK` 已有 `card.render` / `client.card.compositeWindow.render` 完整卡片渲染链路，因此不需要新建第二套渲染器。

## 影响范围

- 箱子 Runtime 公共契约与错误码；
- Host 箱子条目解析、卡片渲染协调、会话所有权和资源回收；
- SDK Box API、嵌入式 Runtime Bridge、路由清单和测试；
- 布局插件公共类型与脚手架模板；
- 文档库布局右侧内容区的显示配置、嵌套 iframe 事件和生命周期。

## 复现步骤

1. 打开一个使用文档库布局的箱子。
2. 在左侧目录选择卡片条目。
3. 观察右侧只显示封面、摘要和打开按钮。
4. 检查布局 Runtime，无法根据 `entryId` 请求完整卡片文档。

## 期望行为

Host 以 `sessionId + entryId` 解析条目，验证条目类型和会话所有权，复用卡片服务生成受控复合卡片文档。布局只挂载返回的 `documentUrl`，处理正式消息事件，并在替换或卸载时释放子渲染会话。

## 暂行处理

不允许布局插件直读 `.card`、导入卡片插件、拼接文件 URL 或把原始 `.card` 直接赋给 iframe。工单处理期间继续使用已有封面与 `openEntry` 链路，不加入绕过 Host 的临时实现。

## 需要协作方

Chips-Host、Chips-SDK、Chips-Scaffold、Chips-BoxLayoutPlugin、Chips-CardViewer 和生态公共文档维护方。

## 当前状态

已解决（2026-08-11）。`task033-完善箱子链路` 已完成以下收口：

1. Host 新增 `box.renderEntryDocument/box.releaseEntryDocument`，复用正式 `card.render`，并建立箱子会话对子渲染会话的所有权。
2. 箱子关闭会等待进行中的条目文档操作，显式释放失败可保留归属供关闭流程重试，关闭期间晚到的渲染结果也会被回收。
3. SDK 已提供直接 Box API 和受箱子 iframe 来源、会话、语言及主题约束的 Runtime Bridge。
4. 文档库布局可按节点选择 `content/cover`，默认内嵌完整卡片；子箱子保持封面态。
5. 全部官方布局公共类型、箱子布局脚手架、生态设计原稿和公共技术文档已同步。
