## 二、架构总览（canonical）

### 2.1 一句话

薯片生态 = **薯片平台（Cordis 运行时 + 能力 Bridge + 文档引擎 + 资源管理 + 渲染框架）+ 插件生态（应用/基础卡片/箱子布局/服务四类角色）**；桌面优先（macOS/Windows），Android 次之；文件格式、Rust 核心、Bridge 接口全平台共享；数据本地、格式开放。

### 2.2 分层

```
┌──────────────────────────────────────────────────────┐
│ 插件生态层                                            │
│  应用插件 · 基础卡片插件 · 箱子布局插件 · 服务插件     │
└──────────────────────────────────────────────────────┘
                      ↕ Bridge（能力导向）
┌──────────────────────────────────────────────────────┐
│ 薯片平台层                                            │
│  Cordis 运行时 · Bridge · 文档解析 · 资源管理          │
│  渲染框架 · 权限系统 · 事件系统 · 配置系统             │
└──────────────────────────────────────────────────────┘
                      ↕ Neon（Rust ↔ Node.js Native Module）
┌──────────────────────────────────────────────────────┐
│ 壳与系统层                                            │
│  Electron 壳（主进程/渲染进程/preload） · 操作系统      │
└──────────────────────────────────────────────────────┘
```

### 2.3 核心机制速览

| 机制 | 内容 |
|---|---|
| 插件运行时 | Cordis（Rust 重实现）：`Context` / `Fork` / `provide` / `inject` / 事件 / 生命周期 / 可逆副作用 |
| 能力系统 | 能力导向 Bridge：插件请求 `Capability`，Bridge 负责注册表、权限、校验、路由 |
| 核心语言 | Rust：Cordis 运行时、Bridge、文档解析、资源管理；经 Neon 暴露给 Node.js |
| 壳 | Electron：主进程承载平台，渲染进程运行 React，preload 暴露 `window.chips` |
| 前端 | React 18 + `@chips/antd`（fork antd）+ `@chips/ui`；Design Tokens；简体中文直写 |
| 文件格式 | `.card` / `.box`：YAML + 目录结构 + ZIP Store（发布态不压缩归档） |
| 插件包 | `.cpk`：ZIP Store，根目录 `manifest.yaml` |
| 统一链路 | 卡片与箱子的解析、资源访问、渲染**共用同一条链路**，仅在文件格式层区分 |
| 平台 | macOS / Windows 优先；Android 次之（架构预留）；Linux / iOS 后续；五端共享格式/核心/Bridge |
| 重构 | 大爆炸重构：旧版冻结，新库从零建立，不做兼容 |

## 三、关键决策与冲突裁决（canonical，所有文档必须遵守）

> 本节是解决既有文档矛盾的最终裁决；与本裁决冲突的旧表述一律以本节为准，并在修复时同步更正。

**R1 · 插件角色只有 4 种**
`basecard`（基础卡片）、`boxlayout`（箱子布局）、`app`（应用）、`service`（服务）。
- 白皮书中"能力插件、布局插件、模块插件"的 5 类口径**作废**：
  - "能力插件" → 即服务插件（`service`）；
  - "布局插件" → 统一称"箱子布局插件"（`boxlayout`）；
  - "模块插件" → **不存在**（原子化由 Cordis 服务与能力体系承担）。
- 一个插件只有一个角色；需要多角色能力时拆成多个插件，用 `dependencies` 组合（ADR-005）。

**R2 · Bridge 对外契约（唯一权威形状）**
```typescript
interface IChipsBridge {
  request<TOutput>(capabilityId: string, input?: unknown): Promise<TOutput>;
  subscribe(eventId: string, handler: (payload: unknown) => void): ISubscription;
  resource(uri: string): IResourceHandle;
}
interface ISubscription { dispose(): void }
```
- **不包含 `context()`**：插件上下文由 Cordis 注入的 `ctx` 提供（ADR-004 中的 `context()` 作废，ADR-007/ADR-002 口径生效）。
- `window.chips` 暴露与 `IChipsBridge` 相同的 3 个方法；`subscribe` 必须返回可退订句柄。

**R3 · 能力 ID 与权限 ID 的命名与关系**
- 能力 ID：`<domain>:<action>[:<target>]`，如 `file:read`、`image:encode:jpeg`、`window:create`。
- 权限 ID：`<domain>:<scope>[:<qualifier>]`，如 `filesystem:read`、`network:http:*.example.com`。
- 能力声明自己需要的权限（`capability.permissions: string[]`）；manifest 的 `permissions` 是插件申请集合；Bridge 在调用时按两者交集判定。
- 禁止同一标识既当能力又当权限；文档必须给出"能力 → 权限"的映射示例表。

**R4 · 前端导入唯一面是 `@chips/ui`**
- 插件与共享层业务代码**只能**从 `@chips/ui` 导入组件、Hooks 与 Design Tokens。
- `@chips/antd`（fork antd）仅允许 `packages/ui` 内部使用；禁止任何其他包直接 `import from '@chips/antd'`。
- 禁止 `antd`、`@mui/*`、`@chakra-ui/*` 等第二套组件库。
- ESLint `no-restricted-imports` 必须同时拦截 `antd`、`antd/*`、`@chips/antd`（`packages/ui` 例外）、`@mui/*`、`@chakra-ui/*`。
- ADR-006/ADR-008 中 `import { ConfigProvider } from '@chips/antd'` 的示例作废，改为从 `@chips/ui` 导入。

**R5 · 主题系统与多语言系统已废弃**
- 不存在主题包、语言包、Theme Runtime、i18n 运行时；文档中不得出现"主题系统/多语言系统"作为平台组成部分或交付物。
- 视觉统一由 `@chips/ui` + Design Tokens + antd 主题定制承担；文案简体中文直写。
- 白皮书与路线图中的"主题系统/多语言系统"表述作废。

**R6 · 平台优先级**
- 实现优先级：**macOS / Windows（桌面）→ Android → Linux → iOS**。
- 五端共享：`.card`/`.box` 文件格式、Rust 核心、Bridge 接口。
- 移动端为 Phase 5（架构预留，见 R7）；不得把未实现平台写成已交付。

**R7 · 阶段路线（唯一权威，替代所有其他版本）**
| 阶段 | 目标 | 交付物 |
|---|---|---|
| Phase 0 | 文档与预研 | 全部文档库、Monorepo 骨架、Cordis/Neon/Bridge POC |
| Phase 1 | 核心平台 | Rust Cordis 运行时、Bridge、Electron 壳、React 壳、最小原型 |
| Phase 2 | 子系统 | 插件系统、渲染引擎、资源管理、文档解析、权限/事件/配置系统、覆盖率 >80% |
| Phase 3 | 官方插件与生态 | 应用插件重写（编辑引擎、查看器、资源管理器）、CLI、示例插件、开发者文档 |
| Phase 4 | 迁移与发布 | 用户数据迁移工具、性能与安全加固、三端验证、v1.0 发布 |
| Phase 5 | 移动端 | Android / iOS（架构预留，暂不排期） |
- 不写日历年份与具体日期；只写阶段、交付物、Definition of Done。
- ADR-007 中"移动端 Phase 5（2028+）"改为"Phase 5（架构预留，暂不排期）"。

**R8 · 卡片与箱子统一链路**
- 解析、资源访问、渲染、打开、导出共用同一条链路与同一套接口；接口内部按文件格式（`.card`/`.box`）分支。
- 编辑态允许界面就近渲染，但必须复用同一套插件接口与同一份解析结果。
- 禁止为卡片和箱子各写一套并行管线。

**R9 · 零冗余的边界**
- 文档不写：设计原因的长篇论证、商业价值、优劣对比、备选方案、风险分析、人事与时间规划。
- ADR 只记录：状态、决策、关键设计、约束、后果（简短）。不写备选方案章节。
- 《架构原则》第 6 节中 RFC"至少 2 个替代方案"的要求废止；改为"重大变更走 RFC + 评审 + ADR 记录"。

**R10 · 文档库只放正式技术内容**
- `Phase0-进度报告.md`、`工作总结.md`、`工作汇报.md` 为过程材料，移到 `项目日志与笔记/task043-生态梳理/归档-文档库过程材料/`。
- 库内不新增进度类、汇报类文档；README 只做索引与导航。

**R11 · 插件包格式**
- `.cpk` = ZIP Store：根目录 `manifest.yaml` + 构建产物目录 + 静态资源。
- manifest 为唯一权威清单；包内不得携带原生可执行载荷（Rust 能力属于平台）。
- 服务插件的 Node/JS 依赖必须随包携带或声明为平台提供的能力。

**R12 · 文件格式以原始设计为唯一权威（卡片与箱子）**
- 权威来源：`旧版-生态设计原稿/05-卡片文件格式.md`、`06-箱子文件格式.md`；`旧版-生态共用技术文档/文件格式规范/01-卡片文件格式规范.md`（v1.1.0）、`02-箱子文件格式规范.md`。
- `.card`（提要）：`.card/`（`metadata.yaml`、`structure.yaml`、`cover.html`、`cardcover/`） + `content/{10位62进制ID}.yaml` + 卡片根目录资源（卡片根相对路径，允许子目录）+ 可选嵌套 `.card`；两种正式形态：完整离线卡片、网络资源卡片；版本字段为 `chip_standards_version`。
- `.box`（提要）：以原规范为准（`.box/` 四个必需文件 + `boxcover/`），不得自行发明目录（如 `cards/`、`boxes/`、`layout_configs/`）或字段。
- ADR-009 只保留原则性内容；任何与原规范冲突之处，以原规范为准并同步修正 ADR-009。
- 发布态统一 ZIP Store；不得把 `blob:`、`data:`、系统绝对路径或 `file://` 写回内容配置。

**R13 · 资源引用路径基准**

- 插件只能经 Bridge 访问系统；权限最小化、调用可审计。

**R18 · 性能与质量基线（引用一致）**
- 冷启动 < 1s（Phase 2 可放宽到 < 2s）；渲染 > 60fps（Phase 2 > 30fps）；空闲内存 < 500MB；打开卡片 < 100ms；打开箱子 < 200ms。
- 测试覆盖率 > 80%；Clippy 无 warning；`unsafe` 必须有 `# Safety` 注释。

**R19 · 内置能力与权限总表（canonical，供 A2/A4/A8/A10 与 E1/E4/E5 统一）**

能力（Capability）表达"做什么"，权限（Permission）表达"被允许访问什么范畴"；能力声明所需权限，调用按 manifest 申请与权限授予的交集判定。**任何能力 ID 与权限 ID 不得完全相同（R3）。**

| 能力 ID | 所需权限 ID |
|---|---|
| `file:read` / `file:list` / `file:watch` | `filesystem:read` |
| `file:write` | `filesystem:write` |
| `file:delete` | `filesystem:delete` |
| `resource:read` | `resources:read` |
| `resource:write` | `resources:write` |
| `document:open` / `document:read` | `resources:read` |
| `document:write` / `document:save` | `resources:write` |
| `window:create` / `window:focus` / `window:close` / `window:setState` | `window:control` |
| `notification:send` | `notifications:send` |
| `clipboard:read` / `clipboard:write` | `clipboard:access` |
| `dialog:open` / `dialog:save` | `dialogs:use` |
| `shell:openExternal` | `shell:external` |
| `image:decode` / `image:encode:*` / `image:resize` | `image:process` |
| `http:request` | `network:http[:<domain>]` |
| `config:get` | `config:read:<namespace>` |
| `config:set` | `config:write:<namespace>` |
| `credential:get` / `credential:set` / `credential:delete` | `credential:manage` |
| `event:publish` | `events:publish` |

规则：
- 句柄访问（`resource:*`）与路径访问（`file:*`）分属两套权限；平台会话已授权的句柄在会话内读取免重复校验，写入仍需 `resources:write`。
- 路径限定必须使用目录变量（如 `${userDocuments}`），不得写裸绝对路径。
- 新增能力必须登记进本表（由 E4 维护），不得自创未登记能力。
- 插件自身日志无需权限（日志按插件命名空间自动归属）；接口文档不得要求 `log:write`。

**R20 · 标识符规范（canonical）**
- 基础卡片类型 ID：以 `04-文件格式规范/01` 各类型章节的正式类型标识为准（含历史别名的读取归一规则；新写入一律使用正式标识）。用于：`content/*.yaml` 的 `card_type`、`.card/structure.yaml` 条目 `type`、基础卡片插件 manifest `capabilities.cardTypes[].id`。
- 布局类型 ID：`chips.layout.<name>`（如 `chips.layout.grid`）。用于：箱子 `metadata.yaml` 的 `active_layout_type`、`content.yaml` 的 `layout_configs` 键、布局插件 manifest `capabilities.layouts[].id`。
- 插件 ID：反向域名（`chips.official.*` / `chips.basecard.*` / `chips.layout.*` / `chips.service.*` / 第三方自有域）。
- 错误码分层：文档格式版本问题用 `DOCUMENT_VERSION_*`（由 04/06 维护）；渲染期插件缺失用 `RENDER_PLUGIN_MISSING`、插件/能力/schema 不匹配用 `RENDER_SCHEMA_UNSUPPORTED`。

## 五、接口与命名规范（canonical）

### 5.1 TypeScript 接口

```typescript
// Bridge —— 唯一对外形状（R2）
interface IChipsBridge {
  request<TOutput>(capabilityId: string, input?: unknown): Promise<TOutput>;
  subscribe(eventId: string, handler: (payload: unknown) => void): ISubscription;
  resource(uri: string): IResourceHandle;
}
interface ISubscription { dispose(): void }

// 能力定义（ADR-004）
interface ICapability<TInput = unknown, TOutput = unknown> {
  id: string;                      // <domain>:<action>[:<target>]
  execute(input: TInput): Promise<TOutput>;
  schema: JSONSchema;              // input 的校验 schema
  permissions: string[];           // <domain>:<scope>[:<qualifier>]
}

// 四种插件角色（ADR-005）
interface IBaseCardPlugin {
  renderView(card: Card, container: HTMLElement): void | Dispose;
  renderEditor(card: Card, container: HTMLElement): IEditor;
  validateConfig(config: unknown): boolean;
  export?(card: Card, format: string): Promise<Blob>;
}
interface IBoxLayoutPlugin {
  renderLayout(box: Box, container: HTMLElement): void | Dispose;
  renderEditor(box: Box, container: HTMLElement): IEditor;
  validateConfig(config: unknown): boolean;
}
interface IAppPlugin {
  launch(ctx: IAppContext): Promise<void>;
  handleCommand?(command: string, args: unknown): Promise<void>;
  openFile?(uri: string): Promise<void>;
}
interface IServicePlugin {
  start(ctx: IServiceContext): Promise<void>;
  stop(): Promise<void>;
  health?(): Promise<boolean>;
}
```

### 5.2 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 插件 ID | 反向域名 | `chips.official.editor` |
| 能力 ID | `<domain>:<action>[:<target>]` | `file:read`、`image:encode:jpeg` |
| 权限 ID | `<domain>:<scope>[:<qualifier>]` | `filesystem:read`、`network:http:*.example.com` |
| 事件 ID | `<domain>:<action>` | `file:changed`、`plugin:loaded`、`document:changed` |
| 资源 URI | `chips-resource://<scope>/<path>` | `chips-resource://card-001/image.jpg`、`chips-resource://plugin-001/icon.png` |
| 包名 | `@chips/*` | `@chips/sdk`、`@chips/ui`、`@chips/antd` |

### 5.3 错误模型

```typescript
interface ChipsError {
  code: string;        // <DOMAIN>_<REASON>，如 CARD_NOT_FOUND
  message: string;     // 简体中文、面向用户
  details?: unknown;   // 结构化诊断
  retryable?: boolean;
}
```
- Rust 侧 `ChipsError`（thiserror）；TS 侧同构映射；跨 Bridge 时归一为上述结构。

## 六、文档写作规范

### 6.1 文档头（每份文档必须）


### 6.2 结构要求

- 定位 → 核心设计 → 接口/数据结构 → 流程（文字+简单图）→ 约束与规则 → 自检清单（可选）。
- 每份文档自包含、可独立阅读；跨文档引用使用相对路径 Markdown 链接，且**链接必须真实有效**。
- 图用纯文本 ASCII/代码块，不依赖外部工具。

### 6.3 零冗余（强制）

- 不写设计原因的长篇论证、商业价值、优劣对比、备选方案、风险分析、人事与时间规划。
- 已废弃概念（主题系统、多语言系统、模块插件、能力插件、Host 整体名）不得出现。
- 每个事实只写一处；其余文档引用。

### 6.4 代码示例

- TypeScript 示例必须符合《02-开发规范/02-TypeScript编码规范》风格；Rust 示例必须符合《04-Rust编码规范》。
- 示例要完整、可编译风格，不用 `...` 省略关键逻辑（可省略非关键部分但需注释）。
- 示例中禁止 `any`（TS）与 `unwrap()`（Rust 生产代码）。

### 6.5 交叉引用与清单

- 文档末尾附"相关文档"链接列表。
- 接口文档必须给出：接口定义、字段说明表、最少 1 个完整示例。
