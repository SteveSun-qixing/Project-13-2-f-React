# 00 · 设计总览与阅读路径

> 状态：全新设计稿（无历史包袱版），逐篇评审中。
> 世界观底座：《01-生态总纲-理解稿.md》。
> 前提：不考虑历史实现、兼容性与工程量；只求最终效果最好——五端一致、全品类承载、写一次、厚而无感。

---

## 1. 设计约束（不可违背）

1. **全平台**：Windows / macOS / Linux / Android / iOS，外加 Web 与 Headless 两种非交互形态。
2. **全品类**：从笔记、Office、浏览器、开发工具、Agent 到媒体创作、游戏，都由同一套底座承载。
3. **写一次**：应用与业务逻辑只写一份；平台承担全部平台差异。
4. **平台运行时为默认**：表现运行时、能力运行时、契约运行时由平台提供；特殊软件可自带（例外，允许）。
5. **动态可组合**：一切皆插件、无特权核心、副作用可逆、作用域隔离、事件溯源。
6. **平台抽象**：声明式、语义化、自适应。
7. **厚而无感**：所有约束翻译成能力与默认；使用无限制、感受无存在。
8. **逻辑架构是宪法，物理实现可换届**：本套设计只定义架构、契约与机制；语言、框架、库的选择属于"实现建议"，可替换。

## 2. 设计方法

- 只定义**逻辑架构 + 契约 + 机制**；实现细节留给各自仓库。
- 每个机制必须回答四问：解决哪个基元问题；对开发者呈现什么语义；跨端如何表现；失败如何降级。
- 三类陈述必须区分并标记：
  - **【不变式】**：宪法级，任何实现不得违背；
  - **【设计】**：本套设计定义的口径，可评审修改；
  - **【实现建议】**：可替换的技术选择。

## 5. 关键概念速览

| 概念 | 定义 |
|---|---|
| 薯片平台 | 整体：能力运行时 + 表现运行时 + 契约运行时 + 治理 |
| 薯片核心 | 可移植的跨平台实现主体（内核、服务、模块运行时、契约） |
| 薯片内核 | 核心中的路由/注册/事件/生命周期/治理中枢 |
| 壳（Shell） | 平台接入实现：桌面壳、移动壳、Web 壳、无头壳 |
| 插件 | 生态软件的存在形式：app / card / layout / module（+ theme 内部保留） |
| 应用 | 用户可感知的插件（app 类型） |
| 基元 | 组合一切软件的不可再分能力单元（9 个） |
| 契约 | 跨越边界的唯一合法约定（schema + 权限 + 错误 + 版本） |
| 作用域 | 生命周期与权限的隔离单元（工作区/应用/文档/会话/组件） |

## 6. 与旧体系的主要差异（一页对照）

| 主题 | 旧体系 | 新设计 |
|---|---|---|
| 名称 | Host / 薯片主机 | 薯片平台；Host 降级为角色词 |
| 运行时 | 每插件自带 antd + 共享层 | 平台运行时为默认，自带为例外 |
| 跨端 | Electron 单底座，移动未交付 | 五端一等公民，核心可移植、壳可替换 |
| 插件治理 | 扁平权限、单向副作用 | 作用域 + 可逆副作用 + 事件溯源 |
| 能力面 | 分散的动作清单 | 9 大基元 + 服务域 |
| 契约 | 多份手写、编号冲突 | 契约单一源 + 多语言生成 + 金标向量 |
| 内容 | 卡片/箱子为中心 | 卡片/箱子与通用文档双世界平等 |
| 视觉 | 每应用打包样式 | 平台托管外观；系统更新惠及所有软件 |
