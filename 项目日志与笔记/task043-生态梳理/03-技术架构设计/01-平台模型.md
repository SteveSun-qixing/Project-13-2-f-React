# 01 · 平台模型

> 【不变式】本篇定义薯片平台的根本结构与边界；所有后续设计与实现都从本篇展开。

---

## 1. 平台是什么

薯片平台 = **能力运行时 + 表现运行时 + 契约运行时 + 治理**。

- 它运行在原生系统之上，承担软件的运行、能力、界面、分发与治理；
- 它向开发者提供语义化的能力面与表现面，向用户提供一致的使用环境；
- 它由**可移植核心**与**平台壳**组成：核心一次编写，壳逐平台实现。

### 三种身份

| 身份 | 说明 |
|---|---|
| 核心（Chips Core） | 跨平台的实现主体：内核、服务、模块运行时、契约运行时 |
| 壳（Shell） | 平台接入实现：桌面壳 / 移动壳 / Web 壳 / 无头壳 |
| 宿主（Host，角色词） | 运行时角色：承载并执行插件的那个进程/环境 |

## 2. 逻辑分层（L0–L9）

| 层 | 名称 | 职责 | 归属 |
|---|---|---|---|
| L0 | 宿主（Shell + OS） | 窗口、输入、系统集成、打包更新、离屏渲染 | 壳 |
| L1 | 平台抽象层 PAL | 平台能力分面 + 能力快照 + 适配 | 壳/核心 |
| L2 | 内核 Kernel | 路由、注册、事件、生命周期、治理 | 核心 |
| L3 | 服务域 Services | 能力公共池：内容、系统、运行、体验 | 核心 |
| L4 | 模块运行时 Module Runtime | 无界面能力执行器（portable / builtin） | 核心 |
| L5 | 通道 Bridge | 消息、流、句柄的传输与鉴权 | 核心 + 壳 |
| L6 | 客户端运行时 Client Runtime | 编解码、错误归一、重试、流、句柄缓存 | 核心（随平台发行） |
| L7 | 能力接口 Capability API | 语义 API、Hooks——开发者的主编程面 | 平台 |
| L8 | 表现运行时 Presentation Runtime | 组件、令牌、布局、动效、无障碍 | 平台 |
| L9 | 应用域 App Domain | 业务逻辑与编排 | 插件 |

**【不变式】依赖方向**：仅允许 `Ln → Ln-1` 或 `Ln → 公共契约层`；禁止跨层跳跃。

**【不变式】归属边界**：L0–L8 随平台发行；L9 属于插件。第三方插件不得实现或替换 L0–L8 的任何部分（自带表现库为例外，见 07 篇）。

### 三类运行时的层映射

| 运行时 | 覆盖层 | 作用 |
|---|---|---|
| 契约运行时 | 贯穿 L1–L7 | 契约的单一源、生成、校验、版本 |
| 能力运行时 | L1–L4 + L5–L7 | 系统能力的提供与调用链 |
| 表现运行时 | L8 | 界面能力与外观的统一提供 |

## 3. 核心与壳的边界

**【不变式】核心不得认识壳**：核心代码中不得出现任何平台特有名（Electron、Tauri、WebView、Activity、BrowserWindow 等）。

**壳的职责（只做四件事）**：

1. 实现 PAL 分面（把原生能力翻译成平台语义）；
2. 承载表面（把 Surface 映射为窗口/页面/卡片）；
3. 提供系统集成（通知、托盘、快捷键、分享、文件关联、自启动）；
4. 负责打包、安装、更新与签名验证。

**壳的最小化原则**：壳越薄，跨端越稳。任何能被核心吸收的逻辑都不留在壳里。

## 4. 平台抽象层（PAL）

### 分面模型

每个平台能力是一个**分面（facet）**，例如：

`fs / window / screen / input / clipboard / notification / share / power / network / media / offscreen / ids / paths / secrets / permissions`

- 每个分面有独立的接口契约与能力快照；
- 分面之间不得互相依赖；
- 分面是实现细节的唯一栖息地。

### 能力快照

**【设计】** 每个分面必须返回结构化能力快照：

```
CapabilitySnapshot = {
  facet: string
  status: 'supported' | 'degraded' | 'unsupported'
  level?: number          // degraded 时的能力等级
  details?: Record<string, unknown>
  reason?: string         // unsupported / degraded 的原因
}
```

**三态语义**：

| 状态 | 含义 | 平台义务 |
|---|---|---|
| supported | 完整等价 | 与其它端行为等价 |
| degraded | 部分可用 | 明确降级面与替代路径 |
| unsupported | 无法提供 | 返回正式错误，不得静默 |

**【不变式】禁止空实现假成功**：任何 unsupported 必须如实报告；任何 degraded 必须可被查询。

## 5. 生命周期

### 平台生命周期

```
boot → ready → running → updating → shutdown
                ↘ suspended（移动/后台）↗
```

- **boot**：加载核心、校验契约版本、恢复工作区、构建能力快照；
- **running**：接受插件激活与调用；
- **suspended**：移动端后台挂起；恢复时必须重建会话（见下）；
- **updating**：核心/壳更新；插件继续以旧契约运行或排队等待；
- **shutdown**：有序停用插件、刷新持久化状态。

### 插件会话生命周期

```
install → validate → stage → activate → session
                                      ↘ suspend / resume
                              deactivate → uninstall
```

- **移动端进程死亡**是常态：会话必须**可重建**（事件溯源 + 句柄重放）；
- 会话崩溃不得影响其它会话（隔离）；
- 卸载必须**完全可逆**（见 02 篇"可逆副作用"）。

## 6. 工作区与身份

- **工作区（Workspace）**是平台的一等概念：用户态与开发态严格隔离，多工作区可并存；
- 工作区是所有作用域的根（见 02 篇"作用域系统"）；
- **身份三层**：设备身份（本地）、插件身份（清单签名）、会话身份（运行时分配）；
- **平台不强制账号**：本地使用零账号；账号只属于网络与社区能力。

## 7. 平台与原生系统

- **共存原则**：平台默认与原生系统共存（作为普通应用运行）；
- **深化可能**：桌面接管（第三方 Shell）是**独立产品线**，按平台单独立项；平台只需保证：壳可替换、表面可接管、全局能力可扩展；
- **不承诺**：平台不承诺替换系统组件（除产品明确立项外），不依赖未公开 API 维持核心功能。

## 8. 平台自更新

- **更新对象分层**：核心（可移植）、壳（平台特有）、运行时（表现/能力/契约）、插件；
- **更新原则**：原子替换、可回滚、旧插件继续工作（契约稳定）；
- **更新来源**：签名验证 + 来源分级（见 10 篇）；
- **效果**：平台更新后，所有使用平台运行时的软件**自动获得新外观与新行为**。
