# 15 · 工程与治理规范

> 【不变式】单一事实源、先核代码、先开工单、归档不删除、变更可追溯。

---

## 1. 仓库策略

| 类别 | 策略 |
|---|---|
| 核心 / 壳 / 运行时 | 分仓；契约独立成仓（契约源仓） |
| 官方能力包 | 独立仓库，随平台版本联合发布 |
| SDK / 脚手架 / 工具 | 独立仓库 |
| 插件 | 每插件独立仓库、独立版本、独立发布 |
| 社区 / 服务器 | 独立仓库，独立版本线 |

跨仓协作只通过**契约与模板**，不通过源码耦合。

## 2. 工作区与形态

| 形态 | 用途 |
|---|---|
| 用户工作区 | 用户数据与已装插件 |
| 开发工作区 | 开发、调试、实验；与用户态严格隔离 |
| 发布态 | 正式发行产物 |
| 安装副本 | 用户设备上的已安装实例 |

**【不变式】** 开发态结果只以开发工作区为准；用户态结果只以用户工作区为准，互不串用。

## 3. 版本纪律

| 版本 | 规则 |
|---|---|
| 平台版本 | 核心+壳+运行时整体；对外统一 |
| 契约版本 | 各域独立；wire 兼容规则约束；生成物无 diff |
| 插件版本 | 语义化；变更说明必填 |
| 内容格式版本 | 独立演进；破坏性变更走主版本 + 迁移工具 |

- 第一版之前不留兼容包袱；第一版之后**契约稳定是第一纪律**；
- 弃用必须公告期 + 确定性错误，禁止静默破坏。

## 4. 文档治理

- **单一事实源**：每个事实只有一处权威，其余引用；
- **分层归属**：总纲（定位与哲学）→ 架构设计（本套）→ 契约与协议（对外正式）→ 仓库内部文档；
- **文档随代码**：改代码必须同步对应文档；文档与实现漂移视为缺陷；
- **写前核对**：更新文档前必须核对代码、清单、测试与真实链路；
- **命名与术语**：术语表为唯一口径（见 00 篇速览），禁止同义词漂移。

## 5. 质量纪律

- 门禁全绿才算完成；客观证据（测试全绿 + 真实启动）先于声明；
- 禁止临时实现、简化版、占位实现与 TODO；
- 禁止复制共享层或运行时实现；
- 不引入第二套组件库/视觉体系；
- 新增第三方依赖必须经过选型核对（用途、许可证、维护、包体、安全、跨端）。

## 6. 变更与决策治理

| 产物 | 用途 |
|---|---|
| ADR（架构决策记录） | 重大决策的背景、选项、结论与影响 |
| 工单 | 问题登记、缺口、漂移、缺陷；先登记后处理 |
| 评审 | 设计文档逐篇评审；实现随门禁与抽查 |
| 归档 | 失效内容移入归档，不删除 |

**【不变式】** 任何与本文档冲突的实现，要么修实现，要么走 ADR 改文档——不存在"第三种状态"。

## 7. 命名规范（速查）

| 对象 | 规范 |
|---|---|
| 平台 | 薯片平台（Chips Platform） |
| 核心 | 薯片核心（Chips Core） |
| 内核 | 薯片内核（Chips Kernel） |
| 运行时 | 表现运行时 / 能力运行时 / 契约运行时 |
| 壳 | 桌面壳 / 移动壳 / Web 壳 / 无头壳 |
| 插件 | app / card / layout / module |
| 宿主 | "Host"仅作角色词（插件宿主），不再作为整体名 |
| 代码标识 | `chips.*`、`com.chips.*`（官方）、反向域名（第三方） |

## 8. 协作纪律

- 分支与提交由所有者管理；代理人只交付改动与报告；
- 提交信息使用简体中文，完整说明改动与验证；
- 验证范围与改动范围匹配；未验证的改动不提交；
- 发现问题先登记工单，再决定是否在本次范围内处理。

## 9. 设计评审与冻结

- 本套设计逐篇评审：评审通过即冻结为"正式设计"；
- 冻结后变更走 ADR；
- 实现与设计不一致时，以实现修复为默认方向（除非 ADR 说明设计变更）。

## 10. 本套设计的后续维护

- 本套设计由平台团队维护；
- 与契约源、术语表、ADR 三者联动：契约变化 → 更新设计引用；术语变化 → 全仓统一；决策变化 → 更新对应篇章并记录 ADR。
