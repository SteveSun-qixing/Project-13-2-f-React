# 05 · 插件体系设计

> 【不变式】一切皆插件：生态中的软件、内容能力、界面能力、无界面能力，全部以同一套插件机制存在、安装、组合、替换。

---

## 1. 定位

插件是生态的**生长机制**与**替换机制**：

- 官方与第三方同构：同一套清单、同一套工具、同一道门禁；
- 每个插件独立仓库、独立版本、独立发布；
- 插件之间不直接依赖，只通过能力契约协作。

## 2. 插件类型（四类）

| 类型 | 是什么 | 形态 |
|---|---|---|
| `app` | 用户可感知的产品（应用） | 受控 Web 表面 |
| `card` | 一种基础卡片内容能力（渲染 + 编辑） | ESM + 文档挂载 |
| `layout` | 箱子的一种展示方式（页面） | ESM + 页面挂载 |
| `module` | 无界面能力提供者（capability + method） | 沙箱执行（JS/WASM） |

> **注**：新设计不再存在 `theme` 插件类型——视觉由平台表现运行时统一托管（见 07 篇）。

## 3. 插件身份与清单

### 身份

- `pluginId`：反向域名（如 `com.chips.notes`），全局唯一且不可变；
- `version`：语义化版本；
- 签名：官方签名 / 开发者签名 / 未签名（本地自装，仅开发态）。

### 清单（manifest）

```yaml
id: com.example.notes
name: 笔记
version: 1.2.0
type: app

runtime:
  targets: [desktop, android, ios, web, headless]     # 声明支持范围
  requirements:
    presentation: ">=1.0"                              # 表现运行时版本
    capabilities: [document.session, surface.window]   # 需要的能力

permissions:                                           # 能力级权限
  - workspace.file.read
  - workspace.file.write
  - document.session
  - network.http

entries:
  app: dist/index.html

contributions:                                         # 贡献点（见第 6 节）
  commands: [notes.new, notes.export]
  handlers: []
```

**【不变式】**：清单是插件与平台的唯一契约入口；声明之外的能力一律不可用。

## 4. 生命周期

```
install → validate → stage → activate → session ⇄ suspended
                                  ↘ deactivate → uninstall
```

| 阶段 | 关键动作 |
|---|---|
| install | 接收 `.cpk`（本地文件 / 市场 / 私有源） |
| validate | 清单与 schema 校验、签名与哈希校验、运行目标检查 |
| stage | 解压到暂存区，**限制解包**（路径穿越、炸弹、符号链接防护） |
| activate | 权限审查 → 权限快照 → 沙箱注入 → 注册贡献点（原子激活） |
| session | 创建插件作用域与会话；分配资源配额 |
| suspend / resume | 移动端后台挂起与重建；挂起释放非必要句柄 |
| deactivate | 撤销一切副作用（注册、订阅、句柄、作业），释放配额 |
| uninstall | 删除文件与记录；**零残留**（可逆性门禁验证） |

- 全程**不重启平台**；
- 更新 = 新版本在新作用域激活 → 句柄切换 → 旧作用域停用（原子、可回滚）；
- 崩溃：会话可依据事件溯源重建。

## 5. 隔离模型

| 插件类型 | 隔离形态 | 原生代码 |
|---|---|---|
| app / card / layout | 独立 Web 上下文（受控 origin、CSP、进程/站点隔离） | 禁 |
| module | 受限执行器沙箱（JS 或 WASM），CPU/内存/时间/并发/网络/存储配额 | 禁 |
| 官方能力包 | 平台签名、随平台分发 | 允许（平台侧） |

**【不变式】** 可下载插件**不得携带原生可执行载荷**（桌面端同样遵守，移动端强制）；需要原生能力的，走官方能力包或壳扩展（见 03 篇三条生长路径）。

## 6. 贡献点（扩展机制）

插件通过**声明式贡献点**扩展平台，而非修改平台：

| 贡献点 | 说明 |
|---|---|
| `commands` | 命令（菜单/快捷键/面板自动消费） |
| `handlers` | 文件/资源处理器（打开方式、内容类型） |
| `cardTypes` | 基础卡片类型（card 类型专属） |
| `layouts` | 箱子布局类型（layout 类型专属） |
| `capabilities` | 模块能力（module 类型专属） |
| `settings` | 设置页（可选） |
| `scenes` | 应用场景/入口（app 类型专属） |

规则：贡献点在**激活时注册、停用时注销**（可逆）；注册冲突由平台仲裁并给出确定性错误。

## 7. 会话与作用域

- 每个插件实例 = 一个 **app 作用域**（见 02 篇）；
- 其下可创建 session 作用域（文档、作业、表面、Agent 会话）；
- 配额、权限、副作用、句柄全部挂在作用域上；停用即级联释放。

## 8. 插件间协作

- 只能通过：**内核路由**（服务）、**模块能力**（capability）、**事件**（作用域内订阅）协作；
- 禁止：直接 import 彼此源码、共享可变内存、私有协议；
- 插件可声明 `consumes`（依赖的能力）与可选 `provides`（模块类插件）；
- 平台负责依赖解析、版本选择、缺失降级。

## 9. 热插拔

- 安装、更新、卸载不中断其它插件；
- 更新采用**双作用域原子切换**；
- 卸载执行**可逆性验证**（注册清零、订阅清零、句柄释放、文件清理）。

## 10. 移动端与 Web 端约束

- 移动端：无后台常驻假定；会话必须可重建；系统权限（相机/相册/通知）由平台翻译；
- Web 端：插件运行于浏览器，无本地文件系统——通过虚拟文件系统与远端宿主连接补齐；
- 无头端：无界面插件（module）与服务正常工作，app/card/layout 不激活。

## 11. 开发体验

- `create`：从模板生成工程（身份参数化，模板随平台更新）；
- `dev`：开发宿主运行、热更新、能力模拟（含降级场景模拟）；
- `preview`：组件与页面预览、五端尺寸矩阵；
- `test`：单元 + 契约 + 集成 + 门禁；
- `package` → `publish`：打包 `.cpk`、签名、上架市场（见 10 篇）。
