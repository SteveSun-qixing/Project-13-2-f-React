# 07 · 能力接口与表现运行时

> 【不变式】平台默认提供能力接口（L7）与表现运行时（L8）；插件只写业务。自带表现库是允许的例外，但自担责任。

---

## 第一部分：能力接口（L7）

## 1. 语义 API

**【设计】能力接口只表达意图，不暴露实现。**

| 反例（实现语义） | 正例（意图语义） |
|---|---|
| `electron.dialog.showOpenDialog` | `document.pickAndOpen()` |
| `window.maximize()` | `surface.request({ mode: 'maximized' })` |
| `fs.readFile(path)` | `document.session.read(handle, range)` |
| `new Worker(url)` | `job.submit({ capability, method, input })` |

特征：

- **意图化**：命名描述"要做什么"，不描述"怎么做到"；
- **可发现**：按基元与服务域组织，SDK 提供类型与文档；
- **权限感知**：调用前可查询可用性与所需权限；
- **诚实**：能力缺失时返回标准错误，不静默。

## 2. 接口形态

| 形态 | 场景 |
|---|---|
| SDK Domain API | 所有语言（TS 为主）中的类型化调用 |
| React Hooks | UI 场景中的响应式接入 |
| 事件订阅 | 状态变化与通知 |
| 流接口 | 连续数据 |
| CLI | 脚本化与自动化（见 12 篇） |

**【不变式】** 所有形态背后是同一个客户端运行时、同一条调用链、同一套契约。

---

## 第二部分：表现运行时（L8）

## 3. 定位

表现运行时是"平台托管外观"的实现：**系统更新，所有软件焕新**。

构成：

| 组成 | 内容 |
|---|---|
| 组件库 | 语义化组件（按钮、输入、列表、表格、容器、表面壳…） |
| 设计令牌 | 颜色、字体、间距、圆角、阴影、层级的分层令牌 |
| 布局系统 | 响应式单位、尺寸类、安全区、容器查询、页面自治 |
| 动效系统 | 时长与曲线令牌、标准过渡、减少动效红线 |
| 无障碍 | 语义角色、焦点管理、键盘等价 |
| 图标 | 统一图标集与语义命名 |
| 文案 | 简体中文规范（术语表、用户语言优先） |

## 4. 语义化组件与令牌

- 组件 API 表达**角色与意图**：`variant="primary"`、`tonal="surface"`、`elevation="floating"`；
- 令牌分三层：`原始（primitive）→ 语义（semantic）→ 组件（component）`；
- **应用只消费语义层**，不得引用原始色值；平台可随时重排底层值；
- 组件行为（键盘、焦点、无障碍）由平台保证，应用不重复实现。

## 5. 自适应布局

- **响应式单位**：屏幕宽度归一化为固定份数（`cpx` 或等价），运行时换算像素；
- **尺寸类与安全区**：由表面上下文提供，组件与页面据此重排；
- **页面自治**：每页定义自己的断点、重排与降级策略；平台不提供全局横竖模板；
- **移动优先适配**：同一页面在手机/平板/桌面自动重排，不写平台分支。

## 6. 动效与体验基线

- 动效令牌：标准时长（180–240ms 级别）、标准曲线、标准过渡；
- 状态完整：悬停、按压、焦点、禁用、加载、错误、空态、结束态；
- 键盘与指针等价；`prefers-reduced-motion` 全量降级；
- 性能即体验：合成层、增量渲染、虚拟化由平台默认提供。

## 7. 交付机制

**【设计】表现运行时由平台提供，插件默认不打包。**

- 插件构建时外部化运行时依赖；
- 平台在插件上下文注入运行时（受控模块解析）；
- 运行时版本随平台演进，插件声明所需版本区间，握手协商；
- 多插件共享同一运行时实例（内存与体积收益）。

## 8. 自带例外

允许有特殊需要的软件（游戏、专业创作、浏览器等）自带表现库与代码：

| 规则 | 说明 |
|---|---|
| 声明 | 清单中声明"自带表现层" |
| 自担 | 自行负责一致性、无障碍底线、性能 |
| 不豁免 | 仍受全部契约、权限、作用域、隔离约束 |
| 可共存 | 可与平台运行时混用（局部自带，其余托管） |

## 9. 主题与外观

- 平台为**单一外观**（当前为苹果风格），由平台统一管理；
- 不存在用户可见的多主题切换；外观演进由平台版本驱动；
- 应用不得私改令牌、不得引入第二套组件库；
- 未来若引入外观变体，仍由平台统一提供，应用零改动受益。
