# 14 · 生态与社区设计

> 【设计】社区是平台之上的内容与人的公共层：分享、发现、协作；它不侵入核心，但被核心的契约所支撑。

---

## 1. 生态角色

| 角色 | 利益 |
|---|---|
| 用户 | 用一个环境获得软件与内容；数据自主 |
| 开发者 | 写一次、只写业务、获得分发与收益 |
| 官方 | 维护平台、规范、核心应用与质量 |
| 运营/社区 | 内容治理、活动、生态增长 |

## 2. 社区组织模型（新）

> 旧的"房间/空间"概念已搁置。新模型以**内容与关系**为中心：

```
用户（个人主页）
  └── 合集（Collection，可含卡片与箱子，可嵌套）
  └── 动态（发布、更新、互动）
话题（Topic/标签流）——跨用户的公共发现入口
关注流——订阅创作者与话题
```

- **分享单元**：卡片或箱子（也可发布合集）；
- **发现路径**：话题流、关注流、检索、榜单；
- **权限**：内容级可见性（公开/链接可见/私密）；合集可见性独立于内容；
- **互动**：收藏、评论、转发（远期按需）。

## 3. 服务器形态

| 形态 | 说明 |
|---|---|
| 社区平台 | 多用户：账号、合集、话题、互动、治理 |
| 个人服务器 | 单用户：作品发布与展示；写操作令牌保护；客户端渲染上传 |
| 网页版 | 社区内容的浏览器访问与轻互动 |
| 企业/私有部署 | 内网知识库与内容协作（复用同一协议） |

- 三者**同构**：同一套文件格式、传输协议与内容模型；
- 渲染产物可由客户端生成并上传（个人服务器模式）或由服务器侧处理（社区模式）。

## 4. 平台与社区的技术关系

- 社区是**平台之上的应用/服务**，通过公开协议通信；
- 本地插件经平台网络能力与社区交互（不直连系统网络栈）；
- 社区 API 与平台契约保持独立版本线；平台不依赖社区可用性。

## 5. 内容流转

| 动作 | 机制 |
|---|---|
| 上传 | 引用模型（卡片/箱子 URL 语义）→ 服务端存储与渲染产物 |
| 下载 | 完整回下载（源文件与产物均可），断点续传 |
| 引用分享 | 链接 / 嵌入（受控渲染） |
| 同步 | 本地 ↔ 社区按需双向；冲突以时间戳+显式选择处理 |

## 6. 插件市场与社区的关系

- **市场**：软件（插件）的分发与更新（见 10 篇）；
- **社区**：内容（卡片/箱子/合集）的分享与发现；
- 二者互不隶属，但共享账户体系与信任机制（远期）。

## 7. 开发者生态

- 认证开发者计划（身份、签名、推荐位）；
- 贡献路径：插件、卡片类型、布局、模块能力、官方能力包共建；
- 收益机制（远期）：付费、订阅、分成；
- 治理：违规处置、撤销、申诉。

## 8. 内容治理

- 自动化优先：格式校验、恶意内容扫描、版权投诉闭环；
- 举报与处置流程透明；
- 撤销与下架不影响用户已下载的本地文件（内容归用户所有）。

## 9. 增长与度量（运营视角）

- 北极星：活跃创作者与活跃用户的双增长；
- 观察指标：插件安装量、内容分享量、留存、崩溃率、开发者转化率；
- 度量不进入平台核心逻辑，只作为运营系统的输入。
