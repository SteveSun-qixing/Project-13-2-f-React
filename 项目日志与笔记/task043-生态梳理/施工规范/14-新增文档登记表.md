## 一、用途与规则

1. **先查后增**：新增任何文档前，先在本表检索主题与权威范围，确认未被既有文档覆盖；同时核对 [README 索引](../../../薯片生态文档库/README.md)。
2. **禁止重复**：主题已被覆盖时修订既有文档；确需新建时，权威范围不得与既有文档重叠（绝对原子化，见 [09-文档编写与交付规范](./09-文档编写与交付规范.md) §三）。
3. **串行写入**：本表由主代理串行维护；子智能体不得并发改写本文件，新增登记在交付说明中列出，由主代理汇总写入。
4. **入库三件套**：登记 + README 索引更新 + 链接检查 0 坏链；三件齐全才算完成。
5. 路径一律以生态工作区根为基准书写。

### 1.1 字段定义

| 字段 | 含义 |
|---|---|
| 编号 | 文档在目标分区内的编号（与文件名前缀一致）；唯一性由路径保证 |
| 文档名 | 文档标题（与文档内一级标题一致） |
| 路径 | 工作区根相对路径 |
| 权威范围 | 该文档是哪些概念与规则的最高权威；不得与既有文档重叠 |
| 依赖 | 该文档直接依赖的权威文档（引用而非复制） |
| 状态 | `在编` / `待评审` / `已入库（正式版）` / `已废弃`（废弃须有 ADR 或裁决依据） |
| 负责人 | 子智能体标识（如 `A-03`、`B-11`）或收口小组名；主代理维护 |

## 三、新增登记流程

1. 查本表 + 查 README 索引 + 全库检索主题关键词，确认无重复。
2. 确定目标分区与编号：编号在目标分区内顺延，不复用、不跳号。
3. 在交付说明中列出拟登记项（字段齐全），并写明"为何不能并入既有文档"。
4. 主代理核对后写入本表；同时在 README 索引追加条目。
5. 运行链接检查（见 [09-文档编写与交付规范](./09-文档编写与交付规范.md) §4.1），0 坏链后状态改为 `已入库（正式版）`。
6. 文档被取代时：旧文档移入就近 `归档/`，状态改 `已废弃` 并注明取代者；登记行保留，不删除。
