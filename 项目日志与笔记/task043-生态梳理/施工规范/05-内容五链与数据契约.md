> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：卡片与箱子的五链一条线（解析、资源、渲染、封面、编辑 + 写入）、渲染视图数据契约、唯一写口、两态转换与工作区两态；类型名与机制以《本轮架构收口裁决》与对应子系统设计为准

## 一、五链一条线（R8）

卡片与箱子的**解析、资源、渲染、封面、编辑 + 写入**共用同一条链路、同一套接口；唯一分支点是 `DocumentKind`（`.card` / `.box`），分支后立即归一为 `DocumentView`。**禁止并行管线、禁止第二套解析器、禁止第二个写口。**

| 链 | 权威设计 | 关键约束 |
|---|---|---|
| 解析链 | [文档解析器设计](../../../薯片生态文档库/01-架构设计/01-子系统设计/06-文档解析器设计.md) | 只读；目录态与 ZIP Store 双模式；schema 校验；增量解析；错误修复不掩盖问题 |
| 资源链 | [资源管理设计](../../../薯片生态文档库/01-架构设计/01-子系统设计/04-资源管理设计.md) | 句柄制；一切皆挂载、差异止于 Provider；缓存只是优化不是事实源 |
| 渲染链 | [渲染引擎设计](../../../薯片生态文档库/01-架构设计/01-子系统设计/05-渲染引擎设计.md) | 只读投影；渲染帧 iframe 沙箱；资源代理注入；高度自适应；编辑态就近渲染 |
| 封面链 | [卡片文件格式](../../../薯片生态文档库/04-文件格式规范/01-卡片文件格式.md)、[箱子文件格式](../../../薯片生态文档库/04-文件格式规范/02-箱子文件格式.md) | `cover.html` + `cardcover/` / `boxcover/`；条目目标为箱子时按正式封面渲染 |
| 编辑 + 写入链 | [文档服务设计](../../../薯片生态文档库/01-架构设计/01-子系统设计/11-文档服务设计.md)、[编辑引擎设计](../../../薯片生态文档库/01-架构设计/01-子系统设计/12-编辑引擎设计.md) | 唯一写口：会话模型、内存修订、原子提交、ZIP Store 重建、外部修改检测 |

**状态所有权（内容架构最重要的纪律）**：

- 解析器**只读**；
- 文档服务**唯一写口**（工作副本 → 校验 → 原子替换 → 崩溃恢复）；
- 渲染会话**只读投影**；
- 进入渲染帧的**只有已解析模型与资源句柄**，帧内不读文件；
- 缓存只加速，不拥有真相。

## 二、数据契约（渲染视图模型）

类型命名以《裁决》§一为准，`CardView` / `BoxView` 名称作废（避免与 `@chips/ui` 组件名冲突）：

```typescript
type DocumentView = CardRenderView | BoxRenderView;

interface CardRenderView {
  kind: 'card';
  revision: number;                        // 单调递增
  card_id: string;
  name: string;
  chip_standards_version: string;
  cover_ratio: string;                     // 缺省 '3:4'
  tags: TagView[];
  cover: CoverView;                        // .card/cover.html
  content_nodes: CardNodeView[];           // 按 structure.yaml 声明顺序
}

interface CardNodeView {
  node_id: string;
  card_type: string;
  content: Record<string, unknown>;
}

interface BaseCardView {                    // 一个基础卡片节点实例
  kind: 'basecard';
  node_id: string;
  card_type: string;
  content: Record<string, unknown>;
  revision: number;                        // 与会话修订号同序列
  card: BaseCardContext;                   // card_id / name / chip_standards_version / cover_ratio / tags
}

interface BoxRenderView {
  kind: 'box';
  revision: number;
  box_id: string;
  name: string;
  chip_standards_version: string;
  active_layout_type: string;
  layout_config: Record<string, unknown>;  // layout_configs[active_layout_type].props
  cover: CoverView;                        // .box/cover.html
  entries: EntryView[];                    // 按声明顺序
}
```

约束：

- **只读**：渲染层与插件不得修改视图；仅编辑态由编辑链路在 `document:write` 成功后产出新版本视图交给 `update(view, revision)`。
- **可结构化克隆**：不得包含函数、类实例、`Symbol`、循环引用。
- 视图不携带文件字节；资源一律通过 `resourceBase` 与映射表按需读取。
- **生产者**：渲染引擎解析阶段的**文档视图构建器**（`buildDocumentView(handle, session)`，运行在主进程 Rust 核心）；类型登记在核心接口规范与 SDK API 规范。
- `BaseCardView` 由帧运行时按节点构建：从帧初始化载荷的 `nodes[]` 逐节点取 `node_id` / `card_type` / `containerId`，用卡片级上下文组装 `card`，以当前会话 `revision` 组装完整节点视图。

## 三、解析链与资源链

### 3.1 解析链

- 解析器只读：不写入文档、不迁移、不修改；打开时完成格式识别、schema 校验与版本门禁。
- 双模式：目录态（目录枚举 + 惰性读取）与 ZIP Store 归档态（中央目录 + 按需成员读取）。
- 解析限额（512 MiB / 1 万条等）是**可配置的安全防护默认值**，不是"不设任何上限"。
- `chip_standards_version` 是版本闸门：禁止预发布（严格三段式）；不满足平台支持范围时确定性失败，提示迁移工具，不自动改写。

### 3.2 资源链

- 统一寻址 `chips-resource://`；句柄制（读、区间、流、释放）；一切皆挂载、差异止于 Provider。
- 引用形式唯一集合（R13）：包内相对路径、`file://`、`http(s)://`、`webdav://`、`chips-resource://`；`data:` 仅运行时内存形态，禁止持久化。
- 写入只允许插件作用域与临时作用域；document 挂载内的写入全部经文档服务受控提交；缓存只是优化不是事实源。

## 四、渲染链

- **查看态 = 单个卡片帧**：帧运行时为**每个节点创建独立容器**，并在容器内调用 `renderView(basecard, container)`；节点级降级只替换该节点容器的内容；**禁止多节点共用容器**。
- 卡片渲染流程：按 `content_nodes` 声明顺序逐节点渲染 → 按 `card_type` 查询插件（含 `aliases` 别名归一）→ 校验 `chip_standards_version` → 资源准备 → 创建帧与独立容器。
- 箱子渲染：布局插件经 `BoxRenderView` 渲染；条目帧渲染条目目标视图——卡片视图（逐节点独立容器）或**箱子封面**（条目目标为箱子时按 `.box/cover.html` 正式封面渲染，不展开布局、不递归）。
- 帧沙箱：所有渲染帧固定 `sandbox="allow-scripts"`；帧与父帧只经 MessagePort 通信；握手超时（默认 5s）返回 `RENDER_FRAME_TIMEOUT` 并降级占位。
- 高度自适应：宿主与内容经帧协议测量与上报高度；帧内不得访问 `parent`、`top`、`window.chips`、`localStorage`、`indexedDB`。

## 五、编辑链

### 5.1 装载门面与会话

- 编辑链路由 `IEditSession` 持有：绑定渲染会话与插件门面；就近渲染容器在该会话内创建与释放。
- 插件模块只能经平台门面 **`IPluginRuntime`** 装载：`loadBaseCard(cardType)` / `loadLayout(layoutType)` → 受管门面；**应用插件不得自行加载插件模块**。
- 就近渲染必须复用：同一套插件接口（`renderView` / `renderEditor` / `renderLayout` / `IBaseCardEditor` / `ILayoutEditor`）、同一份解析结果（会话内 `DocumentView`，禁止二次解析）、同一 `resourceBase` 与句柄租约。
- 权限边界不变：就近渲染的插件代码仍只能经 `window.chips` 访问系统。

### 5.2 回流唯一时序

```
getChange() → 编辑链路校验（configSchema + validateConfig）
  → document:write（输出 { revision }）
  → 渲染会话 update(view, revision)
  → markCommitted(revision)
```

- 顺序固定且不可交换；`revision` 只能取自 `document:write` 的返回值，编辑链路不得自行推算。
- `update` 失败返回 `RENDER_UPDATE_FAILED`，保留旧帧；编辑链路保持编辑器脏状态并允许重试，**不得因渲染失败回退已提交的 `document:write`**。
- 不存在帧内编辑回流路径；禁止绕过编辑链路直接调用 `renderEditor` / `renderView`。

### 5.3 `document:write` 扩展语义

| 编辑操作 | part | 载荷 |
|---|---|---|
| 节点内容 / 配置变更 | `content` | `{ nodeId, value: 完整内容模型切片 }` |
| 插入节点 | `structure` + `content` | `structure` 整体替换；`content` 以**不存在的 `nodeId` + 初值**创建成员 |
| 删除节点 | `structure` + `content` | `structure` 整体替换；目标成员 `value: null` 删除 |
| 重排节点 | `structure` | `structure` 整体替换 |
| 卡片元数据 | `metadata` | 合并后的完整切片 |
| 箱子条目 / 布局配置 | `structure` / `entries` / `content` | 对应模型切片（布局含 `schema_version`） |

- 插入节点初值优先调用插件 `createInitialContent()`，未提供或返回 `undefined` 时使用 `{}`。
- `node_id` 由编辑链路生成（10 位 Base62，卡片内唯一）；插件不得自行生成或复用。
- `structure` 替换与内容成员变更必须在**同一次保存**中一致，不允许出现"结构已引用、内容缺失"的中间落盘状态。

### 5.4 自动保存、预览与撤销

- 自动保存默认防抖 **500ms**（可配 100–5000ms）；失焦 / 最小化、关闭窗口、切换文档 / 工作区、应用退出、显式保存时强制 flush。
- 实时预览预算：回流到预览更新 **≤ 100ms**（从 `document:write` 成功起算）；同一 rAF 内多次回流合并为一次 `update`。
- 保存失败（`DOCUMENT_SAVE_FAILED` / `DOCUMENT_SOURCE_CHANGED` / `DOCUMENT_WRITE_CONFLICT`）保留脏状态与历史栈，自动退避重试（2s、最多 3 次）后等待用户操作。
- 撤销 / 重做：会话级历史栈，覆盖节点内容 / 结构 / 元数据 / 条目 / 布局配置；**不回退 revision**（按新内容生成一次新回流）；必须走与普通编辑完全相同的时序；默认上限 100 条。

## 六、写入链与两态转换

### 6.1 唯一写口

- 文档服务是 `document:*` 能力的服务端实现：会话模型、内存修订、变更集、两阶段提交、ZIP Store 重建、摘要与外部修改检测。
- 目录态只写变更集（临时物 + 原子替换）；归档态重建归档后整体原子替换；写入前 `validate`，失败回滚。
- **写路径唯一化**：document 挂载（目录态与归档态）内所有写入经文档服务受控提交；`resource:write` 仅限插件作用域与临时作用域；归档态重建纳入 WriteCoordinator 同一路径锁。
- 大资源流式写：`resource:write` 支持流式（`stream()` 可写 + `commit_write_stream`）；`file:copy` 支持流式。
- 外部修改闭环：`document:changed` 只**刷新作用域版本戳**（不重建作用域）；外部修改时查看会话冻结并提示重载，禁止"模型旧 + 资源新"混用。

### 6.2 `document:export` 与两态转换

```typescript
type DocumentExportForm = 'archive' | 'directory';

interface IDocumentExportInput {
  documentId: string;
  form: DocumentExportForm;
  target: string;                 // 受管引用：工作区作用域或临时作用域路径
  overwrite?: boolean;            // 默认 false
}
```

- 能力覆盖导入、导出与另存：`directory → archive` 导出；`archive → directory` 导入；同形态为另存。
- 权限映射：源文档 `resources:read`；目标落点 `filesystem:write`（工作区内以 `${workspace}` 限定值匹配；`dialog:save` 临时作用域免权限）。
- 导出不改动源文档；原子性由同级平台保留临时物 + `validate` + 原子重命名保证；卡片支持两形态，**箱子只有单文件形态，仅支持 `archive`**（请求 `directory` 返回 `DOCUMENT_PART_UNSUPPORTED`）。
- 导入必须为复制语义、落点必须为可编辑目录态工作副本；版本门禁不通过时提示迁移工具，不自动改写。

## 七、封面链

- 正式封面入口：卡片固定 `.card/cover.html`，箱子固定 `.box/cover.html`；资源目录 `cardcover/` / `boxcover/`。
- 封面渲染接口统一名称为**受控封面渲染接口**；条目帧与封面帧只渲染封面文档，不参与内容拼装。
- 条目目标为箱子时按正式封面渲染（`BoxCoverView`），不展开布局、不创建子帧。
- 封面资源写入经资源管理受控提交；封面操作不提供资源级撤销。

---

## 八、工作区两态

- **目录态（`*.card/`）**：工作形态，长期驻留工作区、持续编辑；打开成本低；保存只写变更集；不参与同步。
- **归档态（`*.card` / `*.box`）**：交付形态，ZIP Store 单文件，用于分享、同步、归档、备份；重建归档后整体原子替换。
- 箱子正式形态只有单文件 `.box`；编辑期临时解包目录为平台保留目录（`.chips-unpack-<随机>`），不进入扫描、不被作为文档打开、不参与同步。
- 工作区目录含用户文件与 `.chips/` 保留区；保留区与保留前缀受保护，转换目标落在保留区返回 `WORKSPACE_RESERVED_PATH`。
- 扫描、文件树、变更事件与外部修改提示以 [工作区设计](../../../薯片生态文档库/01-架构设计/01-子系统设计/13-工作区设计.md) 为准。

## 九、施工自检

- [ ] 是否复用五链一条线，没有为卡片 / 箱子新建并行管线或第二解析器？
- [ ] 视图类型是否为 `CardRenderView` / `BoxRenderView` / `BaseCardView`，是否只读、可结构化克隆？
- [ ] 查看态是否为单卡片帧 + 逐节点独立容器，没有多节点共用容器？
- [ ] 编辑态是否经 `IEditSession` + `IPluginRuntime` 就近渲染，应用插件未加载插件模块？
- [ ] 回流是否严格按 `document:write → update(view, revision) → markCommitted` 时序，revision 是否取自 write 返回值？
- [ ] 节点插入 / 删除是否使用成员创建 / `value: null` 语义，结构变更是否与内容在同一次保存中一致？
- [ ] 写入是否全部经文档服务受控提交，没有第二个写者？
- [ ] 两态转换是否经 `document:export`，箱子是否只支持 `archive`？
- [ ] 预览预算是否 ≤ 100ms 且同 rAF 合并，`update` 失败是否保留旧帧？
