# 前端与跨端

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：前端技术栈与唯一导入面、视觉与文案规范、渲染进程与帧沙箱、编辑态就近渲染的隔离边界、插件 UI 状态边界、五端架构与平台优先级；规范以 R4 / R5 / R17 与对应文档为准

---

## 一、前端技术栈

- 框架：React 18+；组件库：fork antd（唯一组件库）；共享层：`@chips/ui`。
- 官方前端（平台壳、`@chips/ui`、官方插件）统一使用该技术栈；第三方插件可以使用其他技术栈，自担风险，但不得破坏帧协议与权限边界。
- 核心技术栈已确定，不得随意更改；如需更改必须提 RFC 并经过充分评审。

---

## 二、唯一导入面与视觉规范（R4）

```
第三方 / 业务代码 ──只能从这里导入──▶ @chips/ui（组件 + 令牌 + 布局）
                                        │
                                        ▼
                                   @chips/antd（fork antd，仅 @chips/ui 内部使用）
```

- **唯一导入面**：业务代码（含官方插件与共享层业务代码）只能从 `@chips/ui` 导入组件、Hooks 与 Design Tokens。
- `@chips/antd` 仅允许 `packages/ui` 内部使用；**禁止任何其他包直接 `import '@chips/antd'`**。
- 禁止引入第二套组件库（`antd`、`@mui/*`、`@chakra-ui/*` 等）。
- ESLint `no-restricted-imports` 必须同时拦截 `antd`、`antd/*`、`@chips/antd`（`packages/ui` 例外）、`@mui/*`、`@chakra-ui/*`。

### 2.1 样式

- 视觉数值（颜色、间距、圆角、字号、阴影、层级）一律取自 `theme.useToken()` 返回的 **Design Tokens**；禁止硬编码颜色、尺寸与动效值。
- 状态样式优先使用 `@chips/ui` 组件自身的受控属性（`disabled`、`status`、`variant`），不用类名拼装。
- 禁止 CSS Modules、独立样式文件（`styles.css`）与 `classnames` 之类按类名拼装样式的依赖。
- 插件产物 `render.js` 禁止 `import './x.css'`；样式一律走 `@chips/ui` 组件、Design Tokens 与内联样式。
- 应用窗口等壳层如需全局基础样式，只允许由平台壳的窗口渲染层统一引入 `@chips/ui` 提供的全局样式；插件不得自带全局样式或覆盖组件库样式。

## 三、文案与已废弃系统（R5）

- 文案一律**简体中文直写**，不使用 i18n key。
- **主题系统与多语言系统已废弃**（ADR-006）：不存在主题包、语言包、Theme Runtime、i18n 运行时；文档中不得再出现"主题系统 / 多语言系统"作为平台组成部分或交付物。
- 视觉统一由 `@chips/ui` + Design Tokens + antd 主题定制承担；不得新增主题或 i18n 相关依赖。
- 禁止自建主题上下文、主题 Hook、主题包或 i18n 运行时。

---

## 四、渲染进程与帧沙箱

### 4.1 渲染进程结构

- 渲染进程只做 UI 与业务表达：React 壳（窗口 / 工作区 / 编辑宿主）+ 渲染帧（iframe 沙箱）。
- 全部系统访问走 `window.chips`；渲染进程不直接触碰 Node / Electron API。
- RenderHost 负责帧的创建、编排、高度测量与生命周期；应用插件把 `IRenderSession` 挂载到窗口内任意容器。

### 4.2 帧类型与沙箱

| 帧 | 文档源 | `sandbox` | 渲染内容 |
|---|---|---|---|
| 卡片查看帧 | `chips-resource://platform/frame.html` | `allow-scripts` | 逐节点独立容器中的 `renderView` 输出 |
| 箱子布局帧 | `chips-resource://platform/frame.html` | `allow-scripts` | `renderLayout` 输出与条目帧槽位 |
| 条目帧 | `chips-resource://platform/frame.html` | `allow-scripts` | 条目目标视图（卡片视图 / 箱子封面） |
| 封面帧 | `chips-resource://<scope>/.card/cover.html` 或 `.box/cover.html` | `allow-scripts` | `cover.html` 独立渲染 |

- 所有渲染帧固定 `sandbox="allow-scripts"`，由 RenderHost 设置，插件与内容不可覆盖；**禁止 `allow-same-origin`**，禁止 `allow-top-navigation`、`allow-popups`、`allow-forms`、`allow-modals`、`allow-downloads` 等。
- 帧元素固定 `referrerpolicy="no-referrer"`，不授予摄像头、麦克风、剪贴板、地理位置等任何 `allow` 特性。
- 禁止关闭 `webSecurity`；开发构建的调试能力不得进入生产包（R17）。

### 4.3 帧通信与 CSP

- 信任边界是**一次性握手令牌 + 端口所有权**：沙箱帧为不透明源（`origin` 恒为 `"null"`），不依赖 `event.origin` 白名单。
- 帧与父帧只允许 postMessage / MessagePort 通道；帧内禁止访问 `parent`、`top`、`window.chips`、`localStorage`、`indexedDB`；父帧不得读取子帧 DOM、不得注入脚本、不得访问 `iframe.contentDocument`。
- 帧内禁止内联脚本；初始化数据一律经 MessagePort 注入；帧文档只加载 `chips-resource://platform/` 下的模块。
- 渲染帧 CSP：`default-src 'none'`、`script-src chips-resource:`、`connect-src 'none'`（帧内不能直接发起网络请求，外部资源统一经资源代理）。
- 主窗口 CSP 的 `script-src 'self' chips-resource:` 受控放宽仅用于编辑宿主经 `IPluginRuntime` 门面装载受管插件模块；安全边界是 `chips-resource://` 协议处理器的作用域校验与权限判定。

## 五、编辑态就近渲染的隔离边界

- 编辑态允许把插件视图 / 编辑器直接挂载到应用窗口的 UI 容器（不经 iframe），但装载与调用统一由编辑链路经 `IEditSession` 与 `IPluginRuntime` 门面完成。
- **应用插件不得 import 插件代码、不得自行拼装插件入口 URL、不得自行加载插件模块**。
- 就近渲染必须复用同一套插件接口、同一份解析结果与同一 `resourceBase`；禁止二次解析、禁止第二套编辑预览渲染逻辑。
- 权限边界不变：就近渲染的插件代码仍只能经 `window.chips` 访问系统，权限判定与审计不因就近渲染而放宽。
- 就近渲染容器不写文件；保存由文档服务链路完成。

## 六、插件 UI 状态与持久化边界

- 插件自管自己的状态；跨插件共享只能经**事件、服务与配置**三条合法路径。
- 持久化只能经**文档服务与配置系统**；插件不得绕过平台直接写文件。
- 插件私有数据目录、自身配置命名空间、自身资源作用域属免权限范围，但仍经受管接口访问。

## 七、跨端架构

### 7.1 五端共享

- 五端共享：`.card` / `.box` 文件格式、Rust 核心、Bridge 接口契约、`@chips/ui` 语义（Web 端可降级实现）。
- 文件格式、Rust 核心与 Bridge 接口从 Phase 0 起即按平台无关设计。

### 7.2 壳差异被吃掉

- 窗口、菜单、文件对话框、通知、快捷键、剪贴板、托盘等由壳实现；插件永远只见 Bridge。
- 插件不得按平台名分支；**按能力注册表声明的可用性做能力探测与降级**。

### 7.3 平台优先级（R6）

**macOS / Windows → Linux（桌面三端完成）→ Android → iOS**。

- 桌面三端在 Phase 4 完成验证；移动端为 **Phase 5 架构预留**（ADR-007），不得把未实现平台写成已交付。
- 移动端架构预留、实现分离：移动壳（Tauri 2 等）在 Phase 5 引入，共享格式、核心与 Bridge 接口。
- `runtime.targets` 不设 `web` 插件目标：Web 端只作为共享语义的降级实现方向，不提供 web 插件运行时。

- [ ] 帧是否固定 `sandbox="allow-scripts"`，通信是否只走 MessagePort？

- [ ] 跨端分支是否按能力探测而不是平台名？
