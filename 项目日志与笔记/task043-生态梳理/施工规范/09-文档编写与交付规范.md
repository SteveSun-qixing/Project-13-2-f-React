# 文档编写与交付规范

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：《施工规范套件》09 分册：子智能体编写与交付文档时必须遵守的格式、原子化、链接、语言与登记规则；文档格式的完整定义以《07-文档编写规范》为唯一权威，本分册只规定施工动作与交付检查点

---

## 一、总则

1. 本分册约束两类文档：
   - 进入 `薯片生态文档库/` 的正式文档（新建或修订）；
   - `施工规范/` 与 `梳理表/` 下的过程文档（格式参照正式文档执行，只放宽"必须入 README 索引"一条）。
2. 文档格式的模板、层级、代码块、表格、图片、引用等细则以 [07-文档编写规范](../../../薯片生态文档库/02-开发规范/07-文档编写规范.md) 为唯一权威，本分册不复制其内容。
3. 写文档前先核对代码、清单与运行链路；不得依赖 README、脚手架模板文本或历史任务说明（AGENTS 开工顺序）。
4. 文档与实现不一致视为缺陷；修改实现必须在同一交付中同步文档（R16）。

## 二、文档头与结构

### 2.1 文档头四行（每份文档必须）

```markdown
> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：一句话说明本文覆盖与不覆盖的内容
```

- 四行齐全、顺序固定；缺任一行即文档缺陷（[07-文档编写规范](../../../薯片生态文档库/02-开发规范/07-文档编写规范.md) §11.1）。
- 状态只取 `正式版` 或 `已废弃`；废弃文档注明取代者。
- 不设"更新记录"表：修订由 Git 历史承载，正文只保留当前有效口径。

### 2.2 章节结构

- 结构按文档类型取值：子系统设计、开发规范、接口契约、指南教程、ADR 的模板与示例以《07-文档编写规范》§2、§17 为准。
- 所有文档必须包含 **"相关文档"章节**（结尾"文档结束"之前），列出本分册与库内所有直接依赖及被依赖文档的真实链接。
- 所有文档必须以 **`**文档结束**`** 结尾，结尾前用 `---` 分隔。
- 标题层级最多四级；禁止跳级。

### 2.3 结尾固定形态

```markdown
---

## 相关文档

- [文档名](./真实路径.md)

---

**文档结束**
```

## 三、一节一文档与绝对原子化

### 3.1 一节一文档

- 一个文档只讲一个主题，主题用文档名与"适用范围"表达；主题变大时拆分为多个文档，不把无关内容塞进同一篇。
- 能力域必须有文档：每个能力、契约、链路、模块、接口、入口都要有唯一落位文档（[最终任务](../最终任务：薯片生态完整文档库与最佳架构设计.md) §6）。

### 3.2 绝对原子化

- **一个概念只在一处定义**；定义只写一次，其他文档只引用、不复制。
- 禁止把同一表格、同一类型签名、同一错误码表在第二处再写一份；需要局部说明时，用链接指向权威位置并只写"本处只引用，不定义"。
- 跨文档依赖通过文档引用实现；引用必须写明权威文档名与其负责的范围。
- 发现两处定义同一概念：立即收敛为一处定义 + 一处引用，并在交付说明中记录。
- 模板、枚举、数值（性能基线、覆盖率、超时、配额）一律引用权威文档，禁止转述。

## 四、引用与链接

- 引用真实路径：相对链接从当前文档所在目录解析，必须指向真实存在的文件或目录。
- 库内文档引用库内稳定路径（README 索引中的路径）；过程文档引用库内文档使用相同的真实相对路径。
- 禁止：死链、指向不存在文件、指向 `归档/` 内容作为依据、用文件名简称代替链接。
- 归档文档可以出现在历史说明中，但必须标注"仅存档、不作为依据"。

### 4.1 链接检查（强制）

- 命令（在生态工作区根目录执行）：

```bash
python3 项目日志与笔记/task043-生态梳理/工具/检查文档链接.py
```

- 判定：**0 坏链**才算通过；存在坏链即交付不合格，必须修复或移除链接。需要复核代码块内链接时追加 `--raw`。
- 工具默认扫描 `薯片生态文档库/`；`施工规范/`、`梳理表/` 等库外文档的链接由作者在交付前逐条对照文件系统核实，同样禁止死链。

## 五、语言与内容边界

### 5.1 语言

- 一律简体中文直写；专有名词与代码保持英文（React、TypeScript、Rust、Bridge）。
- 不使用 i18n key、不引入第二语言文案（R5）。
- 技术文档使用正式风格；只有生态设计原稿允许口语化表达。
- 术语、类型名、错误码、数值必须与[本轮架构收口裁决](../本轮架构收口裁决.md)及[术语与裁决速查](./12-术语与裁决速查.md)一致。

### 5.2 内容边界

- 不写与产品开发无关的内容：人事、商业、日程、运营分析、设计原因长篇论证、优劣对比。
- 零冗余、最小复杂度：只写技术决策、接口定义、实现细节、使用示例。
- 文档即代码：全面详细、包含全部项目细节，准确到"另一个团队可完美理解、不产生误会、能按文档复刻"。
- 过程材料不进正式库：进度报告、工作总结、排查笔记只在 `项目日志与笔记/`（R10）。

## 六、新增文档登记（强制）

1. 新增任何文档前，先查 [14-新增文档登记表](./14-新增文档登记表.md)，确认主题未被既有文档覆盖；同时核对 [README 索引](../../../薯片生态文档库/README.md)。
2. 主题已被覆盖时，修订既有文档，不新建第二篇；确需新建时，权威范围不得与既有文档重叠。
3. 登记字段：编号、文档名、路径、权威范围、依赖、状态、负责人（子智能体标识）。
4. 并发纪律：登记表由主代理串行写入；子智能体在交付说明中列出拟登记项，不直接并发改写同一文件。
5. 入库三件套：登记 + README 索引更新 + 链接检查 0 坏链；三件齐全才算完成。

## 七、交付前检查清单

- [ ] 文档头四行齐全、顺序正确、状态取值合法
- [ ] 章节结构符合文档类型；标题层级不跳级
- [ ] 含"相关文档"章节，链接全部为真实路径
- [ ] 以 `**文档结束**` 结尾
- [ ] 无 TODO、无占位符、无"待定/后续优化"式表述
- [ ] 无复制粘贴的定义；概念只在权威位置定义一次
- [ ] 术语、类型、错误码、数值与裁决一致
- [ ] 简体中文正式风格；无与产品开发无关内容
- [ ] 新增文档已查登记表并在交付说明中列出登记项
- [ ] 链接检查 0 坏链；库外文档链接人工核实
- [ ] 受影响既有文档同步修订完成
