## 八、第三方能力注册规则

### 8.1 注册主体与登记

- 只有 `service` 角色插件可以注册能力；其他角色（`basecard` / `boxlayout` / `app`）只能消费能力。
- 注册随服务插件激活生效：`start` 成功后注册，`stop`、崩溃、卸载或 Fork dispose 时撤销（第四、九节）。
- 第三方能力实行**登记前置**：提供方在插件发布前向平台提交能力契约，经评审登记后，能力 ID 与提供方绑定并进入平台能力契约数据；插件激活注册时以登记记录校验 ID 与 `owner`（第 4.2 节）。
- 登记内容至少包括：能力 ID、提供方插件 ID、输入 schema、输出类型、所需基础权限、用途说明；登记经 RFC 与评审（[03-变更与决策管理](../07-工程管理/03-变更与决策管理.md)）。
- 未登记 ID 不得注册；第三方插件不得注册内置能力 ID，内置能力 ID 由平台服务域持有（[02-Bridge三层设计](../01-架构设计/01-子系统设计/02-Bridge三层设计.md) 第 4.3 节）。

### 8.2 命名空间

能力 ID 的 `domain` 是平台统一登记与分配的语义域（第 3.2 节），提供方不得自造 domain：

| 能力 ID 示例 | 提供方插件 ID | 登记说明 |
|---|---|---|
| `hello:greet` | `chips.service.hello` | 平台在 `hello` 语义域下分配的示例能力 |
| `hello:echo` | `chips.service.hello` | 同一提供方的第二个能力，`action` 区分 |

> 上表只说明分配方式：实际可注册的第三方能力 ID 以平台能力契约数据中的登记记录为准；未出现在登记记录中的示例 ID 不得用于插件实现。内容处理类实现（图像、音视频、Office 转换等）不注册为 Bridge 能力，由服务插件通过 Cordis 服务提供（第 3.2 节）。

规则：

1. `domain`、`action`、`target` 均由平台登记分配；注册时校验 `id` 的登记提供方与注册上下文 `owner` 一致（`BRIDGE_CAPABILITY_CONFLICT`）。
2. `action` 使用小写字母、数字、连字符，语义为动词短语；`target` 用于细分变体。
3. 能力 ID 一旦登记发布即稳定，不得重命名；废弃能力走注销流程（第九节）。
4. 第三方能力不得把权限 ID 用作能力 ID（R3）；不得使用未分配的语义域。
5. 同一语义域下允许多个提供方共存（不同 `action` / `target`），每个 ID 只属于一个提供方。

### 8.3 冲突处理

| 冲突场景 | 处理 |
|---|---|
| 注册未登记 ID（含自造 domain / action / target） | 拒绝注册，`BRIDGE_CAPABILITY_CONFLICT` |
| 登记提供方与注册上下文 `owner` 不一致 | 拒绝注册，`BRIDGE_CAPABILITY_CONFLICT` |
| 注册内置能力 ID | 拒绝注册，`BRIDGE_CAPABILITY_CONFLICT`（内置 ID 已登记给平台服务域） |
| 同一 owner、同一代际内重复注册同 ID | 幂等：定义完全一致时视为已注册；`schema` / `permissions` 不一致时拒绝，`BRIDGE_CAPABILITY_CONFLICT` |
| 蓝绿更新的代际接管 | 唯一允许的同 ID 覆盖：新代际注册后旧代际进入 `draining`，切换完成后旧代际注销不影响新注册（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 第 6.2 节） |
| 注销后重新注册 | 仅允许登记绑定的提供方；注册校验与首次注册一致 |
| 其他 owner 抢占已注销 ID | 拒绝，`BRIDGE_CAPABILITY_CONFLICT`（登记绑定不可转让、不可继承） |

### 8.4 第三方能力的发现与调用

| 发现面 | 机制 |
|---|---|
| 依赖声明 | 消费方在 manifest `dependencies` 中声明提供方插件与版本范围；提供方未激活时调用失败（[03-插件架构设计](../01-架构设计/01-子系统设计/03-插件架构设计.md) 第 7 节） |
| 契约来源 | 提供方随插件发布已登记的契约（ID、输入 schema、输出类型、所需权限），或以 SDK 类型包形式发布；消费方按契约编写调用代码 |
| 运行时校验 | 输入 schema 由 Bridge 在调用期强制校验（第 5.4 节）；ID 不存在返回 `BRIDGE_CAPABILITY_NOT_FOUND` |
| 状态观察 | 提供方可用性经 `plugin:enabled` / `plugin:disabled` / `plugin:failed` 标准事件观察 |
| 平台工具 | 插件管理界面与诊断经平台内部能力编目读取（第 4.3 节），插件不可访问 |

### 8.5 第三方能力实现约束

1. `permissions` 只能引用平台已注册的基础权限 ID；不得自造权限（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 第 5.4 节）。
2. 能力实现内部访问系统必须经 Bridge 能力或自身 Cordis 服务；不得直接访问 Node.js / Electron / 系统 API（R17）。
3. 能力实现产生的资源句柄、订阅与临时副作用必须纳入提供方 Fork，随注销清理。
4. 服务插件不得借用调用方权限：其内部访问使用自身会话快照判定（[08-权限系统设计](../01-架构设计/01-子系统设计/08-权限系统设计.md) 第 5.4 节）。
5. 能力不得读取或代理其他插件的数据；不得把调用方输入用于未声明用途。
6. 能力包内不得携带原生可执行载荷（R11）。
7. 输出必须是结构化克隆兼容值；不得返回函数、类实例、DOM 对象或 `Error` 实例。

注册示例（ID 的登记提供方为 `chips.service.hello`）：

```typescript
import type { ICapability, JSONSchema } from '@chips/sdk';

interface IGreetInput {
  name: string;
  greeting?: string;
}

interface IGreetOutput {
  text: string;
}

interface IGreetBackend {
  greet(name: string, greeting: string): Promise<string>;
}

const greetInputSchema: JSONSchema = {
  type: 'object',
  additionalProperties: false,
  required: ['name'],
  properties: {
    name: { type: 'string', minLength: 1, maxLength: 64 },
    greeting: { type: 'string', maxLength: 32, default: '你好' },
  },
};

export function createGreetCapability(
  backend: IGreetBackend,
): ICapability<IGreetInput, IGreetOutput> {
  return {
    id: 'hello:greet',
    permissions: [],
    schema: greetInputSchema,
    async execute(input: IGreetInput, ctx) {
      if (ctx.signal.aborted) {
        throw new Error('调用已取消');
      }
      const text = await backend.greet(input.name, input.greeting ?? '你好');
      return { text };
    },
  };
}
```

> **注**：服务插件注册能力的完整流程（`ctx.provide` 服务、激活入口、manifest 声明）见 [10-服务插件接口](./10-服务插件接口.md)。需要权限、审计或跨渲染进程调用的第三方能力才注册为 Bridge 能力；纯主进程内的类型化调用注册为 Cordis 服务（第 2.2、3.2 节）。
