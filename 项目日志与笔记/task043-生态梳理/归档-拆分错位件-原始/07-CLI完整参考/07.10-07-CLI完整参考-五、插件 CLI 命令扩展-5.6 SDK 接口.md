### 5.3 目标与执行语义

#### 5.3.1 `service` 目标

```yaml
target:
  type: service
  pluginId: chips.service.translate
  capability: translate:run
```

- `pluginId` 必须等于声明插件的 ID；`capability` 必须已登记且由该插件注册（示例能力 `translate:run` 的登记提供方为 `chips.service.translate`，[10-服务插件接口](../05-接口与契约/10-服务插件接口.md) §6.1）。
- CLI 经平台能力注册表与调用链路调用能力：存在性 → 权限 → Schema → 路由 → 实现，与插件调用完全一致；不做任何旁路。
- 调用是同步的：输出单个响应对象；不创建 `cli-task`、不声明 `job`。

#### 5.3.2 `app` 目标

```yaml
target:
  type: app
  pluginId: chips.official.iconmaker
  surface:
    open: true
    focus: false
    reuse: preferred
```

| 字段 | 必需 | 语义 |
|---|---|---|
| `pluginId` | 是 | 必须等于声明插件的 ID |
| `surface.open` | 否 | 是否请求打开应用的常规表面（可见窗口）；缺省 `false` |
| `surface.focus` | 否 | 打开后是否聚焦；缺省 `false` |
| `surface.reuse` | 否 | `always` / `never` / `preferred`：复用已有实例、总是新建、优先复用；缺省 `preferred` |

入口级 `commandId`（§5.1）是应用目标执行的核心：它指向该应用经 `command:register` 登记的命令记录，CLI 按 [13-命令系统契约](../05-接口与契约/13-命令系统契约.md) §4.4 的"启动并投递"执行。

应用目标执行时序：

```text
chips <命令路径>
   │ 解析声明、参数与路径校验 → 构造 payload
   ▼
cli.task.create（job.wait !== false 且声明了 entry 级 commandId）
   │
   ▼
确保 owner 应用实例运行
   │ 未运行：按正式启动链路启动并等待入口级 commandId 注册（13-命令系统契约 §4.4）
   ▼
command:invoke（source: 'cli'，payload 为参数映射结果）
   │ 平台校验：命令存在 → 作用域 → 权限 → when → paramsSchema → owner active
   ▼
应用 handleCommand(commandId, payload) 执行
   │ 需要进度时经 cli:task-active（SDK client.cliTask.active）取得任务并上报 progress / complete / fail
   ▼
CLI 等待任务终态；应用未上报终态时以 command:invoke 结果收口任务
   ▼
stdout: { ok, entryId, commandPath, target, task, output, artifacts }
```

- **后台呈现**：未声明 `surface.open: true` 时，CLI 请求后台启动——本次实例不创建可见窗口，`ctx.window` 可能为 `null`；应用必须按“无可见窗口也可完成命令”实现（与 `ui.surface: tray` 的要求一致，[07-应用插件接口](../05-接口与契约/07-应用插件接口.md) §4.4）。`surface.open: true` 时按声明打开并可选聚焦常规表面，用于交互式命令（如 `office open`）。
- **不声明入口级 `commandId`**：CLI 只启动（或激活）应用实例并立即返回 `{ "ok": true, "launched": … }`，不创建任务、不调用 `command:invoke`；适用于“打开/聚焦应用”类入口。
- **声明入口级 `commandId` 且 `job.wait !== false`**：CLI 创建 `cli-task`，应用在完成、失败、取消时都应上报终态（§5.7）；`command:invoke` 对 `main` 目标始终等待处理完成（13 §4.2），应用未上报终态时 CLI 以调用结果收口。
- **`job.wait: false`**：CLI 不创建任务、不建立进度通道，但仍调用 `command:invoke` 并等待其返回（`main` 目标的固有语义）；`job.cancelOnInterrupt` 只在等待任务时有意义。
- **等待与超时**：等待应用启动与命令注册的超时沿用内核 `LIFECYCLE_APPLY_TIMEOUT` 常量（[01-薯片内核设计](../01-架构设计/01-子系统设计/01-薯片内核设计.md) §6.7），超时返回 `CLI_TIMEOUT`（退出码 9）；`COMMAND_OWNER_NOT_RUNNING` 由 CLI 内部处理为“先启动再调用”，不直接暴露给用户。

### 5.4 输出与产物

`output` 字段：

| 字段 | 取值 | 语义 |
|---|---|---|
| `mode` | `human` / `json` | 缺省 `json`；`human` 时未传 `--json` 输出摘要 |
| `json` | `supported` / `required` / `unsupported` | `required` 表示命令只支持 JSON 输出；`unsupported` 时传 `--json` 返回 `CLI_ARGUMENT_INVALID` |
| `artifacts` | `string[]` | 结果对象内的点分路径；human 输出据此提取产物路径 |

规则：

1. `output.artifacts` 指向 `output` 结果对象内的路径，数组值展开为多行产物；未声明时 human 输出只做通用摘要。
2. human 摘要不得猜测插件私有字段语义；上下文不足以摘要时退回 JSON 输出。
3. `skipped: true` 的结果不包含 `output` / `artifacts` / `task`，只含 `ok`、`entryId`、`commandPath`、`target`。
4. stdout 纪律与错误格式见 §2.4、§2.6。

### 5.5 冲突与消解

- 命令路径键 `commandPathKey` 为命令路径段小写并用单个空格连接；两个或更多已启用命令拥有相同键时形成冲突。
- `conflict.priority`（数值，缺省 0）高的命令在冲突时优先参与自动解析；同优先级仍为冲突，必须由 `--plugin <pluginId>` 显式消解。
- `conflict.namespace` 只用于治理分组与诊断展示，不参与自动解析。
