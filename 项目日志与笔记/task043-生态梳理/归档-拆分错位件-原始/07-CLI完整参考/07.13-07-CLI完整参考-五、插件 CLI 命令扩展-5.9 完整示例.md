`CliCommandView` 同时携带 CLI 侧标识与运行时命令引用：`entryId`（CLI 入口标识）、`commandPath`、`commandId?`（`app` 目标的运行时命令 ID）、`owner`、`enabled`、`declaration` 与 `conflicts`。

任务接口（应用插件侧经 Bridge 能力访问，CLI 与平台组件经服务路由访问，SDK 客户端统一封装）：

| 能力 ID | 输入 | 输出 | 说明 |
|---|---|---|---|
| `cli:task-active` | `commandId` | `{ task? }` | 返回调用插件当前 `running` 任务（owner 归属） |
| `cli:task-get` | `taskId` | `{ task }` | 读取任务（owner 归属；长任务据此检查取消终态） |
| `cli:task-progress` | `taskId`、`progress` | `{ task }` | 上报进度（owner 归属） |
| `cli:task-complete` | `taskId`、`output?` | `{ task }` | 上报完成终态（owner 归属） |
| `cli:task-fail` | `taskId`、`error` | `{ task }` | 上报失败终态（owner 归属） |

这 5 项能力声明空权限数组：任务按所有者归属校验，插件不能读写他人任务，也不需要额外权限（R19 登记见 §5.8）。

```typescript
type CliTaskStatus = 'running' | 'completed' | 'failed' | 'cancelled';

interface CliTaskRecord {
  taskId: string;
  pluginId: string;
  commandId: string;
  commandPath?: string[];
  status: CliTaskStatus;
  createdAt: number;
  updatedAt: number;
  progress?: Record<string, unknown>;
  output?: unknown;
  error?: { code: string; message: string; details?: unknown; retryable?: boolean };
}

interface CliTaskApi {
  create(input: { pluginId: string; commandId: string; commandPath?: string[] }): Promise<CliTaskRecord>;
  bindInvocation(input: { taskId: string; invocationId?: string; sessionId?: string }): Promise<CliTaskRecord>;
  get(taskId: string): Promise<CliTaskRecord>;
  active(commandId: string): Promise<CliTaskRecord | undefined>;
  progress(taskId: string, progress: Record<string, unknown>): Promise<CliTaskRecord>;
  complete(taskId: string, output?: unknown): Promise<CliTaskRecord>;
  fail(taskId: string, error: unknown): Promise<CliTaskRecord>;
  cancel(taskId: string): Promise<CliTaskRecord>;
}
```

调用方约定：

- CLI 调度链路使用 `create` 与 `bindInvocation`（服务路由）；应用插件在 `handleCommand` 中经 `cli:task-active` 取得当前任务，再用 `cli:task-progress` / `cli:task-complete` / `cli:task-fail`，长任务周期性 `cli:task-get` 检查取消终态；SDK `client.cliTask` 对上述两侧做类型化封装。
- `cancel` 是 CLI 侧方法，插件不调用：应用按 `job.cancelOnInterrupt` 对应的取消请求，经 `cli:task-get` 观察到 `cancelled` 后停止并释放资源。
- `active(commandId)` 返回调用插件当前 `running` 的 CLI 任务；无任务（例如 `job.wait: false`）返回 `undefined`；同一 `(pluginId, commandId)` 同时最多一个 `running` 任务，CLI 对同一命令串行调度。
- `fail` 的 `error` 归一为 `{ code, message, details?, retryable? }`；无 `code` 时按 `CLI_TASK_FAILED` 收口。
- 任务只允许所属插件读写（归属校验），越权请求拒绝；`progress` 为任意 JSON 对象，约定 `percent`（0–100）与 `stage`（字符串）参与 CLI 进度展示（§3.10）。

### 5.7 应用任务生命周期

```text
running ── complete ──▶ completed
   │  ├── fail ──────▶ failed
   │  └── cancel ────▶ cancelled
   └── 用户中断（声明 cancelOnInterrupt）──▶ cancel 请求 ──▶ cancelled
```

规则：

1. 终态不可逆：`completed` / `failed` / `cancelled` 之后的任何上报返回 `CLI_TASK_INVALID`。
2. `complete` 可携带 `output`，CLI 将其作为结果信封的 `output` 输出；`fail` 可携带应用错误对象，CLI 以其 `code` 作为错误码（缺省 `CLI_TASK_FAILED`）。
3. 取消：CLI 收到 `Ctrl+C` 且命令声明 `job.cancelOnInterrupt: true` 时调用 `cancel`；应用必须响应取消（停止后续步骤、释放已占用资源）并在退出前上报终态，随后 CLI 按退出码 8 结束。
4. 应用实例退出前必须上报终态：未上报即退出的，CLI 以 `CLI_TASK_FAILED` 收口并把任务详情写入 `details.task`。
5. 应用未创建或未上报任务时，CLI 以 `command:invoke` 的返回结果收口任务；`cancel` 请求对未上报任务的应用由 CLI 在 `Ctrl+C` 后直接以 `CLI_TASK_CANCELLED` 结束。
6. 任务不跨工作区、不跨插件、不跨进程重启保留；`CHIPS_CLI_JOB_PROGRESS` 只影响展示，不影响等待。

### 5.8 发现与任务服务路由

插件访问面为 `cli:task-*` 能力（§5.6），能力 ID 登记进 [04-能力契约规范](../05-接口与契约/04-能力契约规范.md) R19。平台内部服务路由如下（CLI 与 SDK 消费；插件不得直接调用内核路由，只能走 Bridge 能力或 SDK 客户端）：

| 路由 | 输入 | 输出 |
|---|---|---|
| `cli.command.list` | `CliCommandQueryOptions` | `{ index, commands }` |
| `cli.command.get` | `entryId` 或 `commandPath`（可带 `pluginId`） | `CliCommandView`；多匹配返回 `CLI_COMMAND_CONFLICT` |
| `cli.command.resolve` | 同上 | `{ command?, conflicts }` |
| `cli.task.create` | `pluginId`、`commandId`（运行时命令 ID）、`commandPath?` | `{ task }` |
| `cli.task.bindInvocation` | `taskId`、`invocationId?`、`sessionId?` | `{ task }` |
| `cli.task.get` | `{ taskId }` 或 `{ commandId, activeOnly: true }`（owner 作用域） | `{ task }` |
| `cli.task.progress` | `taskId`、`progress` | `{ task }` |
| `cli.task.complete` | `taskId`、`output?` | `{ task }` |
| `cli.task.fail` | `taskId`、`error` | `{ task }` |
| `cli.task.cancel` | `taskId` | `{ task }` |

- 发现索引只读：安装、启用、禁用、卸载后由平台重建；CLI、补全与 TUI 每次读取最新索引，不缓存、不推断。
- 查询参数非法返回 `CLI_COMMAND_QUERY_INVALID`；任务不存在返回 `CLI_TASK_NOT_FOUND`。
- 本表是 CLI 扩展的唯一服务路由集合；不得新增第二套命令索引或任务存储。

应用侧实现（主进程入口，`dist/index.js`；示例以 4 KiB 以内的文本文件为前提，超限由应用自行分批编排）：

```typescript
import { ChipsError, type IAppContext, type IAppPlugin } from '@chips/sdk';

const COMMAND_ID = 'translate:file';

interface ITranslateRequest {
  readonly inputPath: string;
  readonly target: string;
  readonly outputPath: string;
}

interface ICliTaskView {
  readonly taskId: string;
  readonly status: 'running' | 'completed' | 'failed' | 'cancelled';
}

export default class TranslateApp implements IAppPlugin {
  private ctx: IAppContext | null = null;

  public async launch(ctx: IAppContext): Promise<void> {
    this.ctx = ctx;
    await ctx.bridge.request('command:register', {
      definition: {
        id: COMMAND_ID,
        title: '翻译文本文件',
        description: '读取文本文件、调用翻译服务并把结果写入输出文件',
        icon: 'assets/icons/translate.svg',
        scope: { kind: 'app' },
        paramsSchema: {
          type: 'object',
          additionalProperties: false,
          required: ['inputPath', 'target', 'outputPath'],
          properties: {
            inputPath: { type: 'string', minLength: 1 },
            target: { type: 'string', pattern: '^[a-z]{2}(-[A-Za-z]{2})?$' },
            outputPath: { type: 'string', minLength: 1 },
          },
        },
        keywords: ['翻译', '文本'],
        group: '工具',
      },
    });
  }

  public async handleCommand(command: string, args: unknown): Promise<void> {
    const ctx = this.ctx;
    if (ctx === null) {
      throw new ChipsError({ code: 'COMMAND_EXECUTION_FAILED', message: '应用实例尚未就绪' });
    }
    if (command !== COMMAND_ID) {
      throw new ChipsError({ code: 'COMMAND_NOT_FOUND', message: `不支持的命令：${command}` });
    }
    const request = args as ITranslateRequest;
    const active = await ctx.bridge.request<{ task?: ICliTaskView }>('cli:task-active', {
      commandId: COMMAND_ID,
    });
    const taskId = active.task?.taskId;
    try {
      if (taskId !== undefined) {
        await ctx.bridge.request('cli:task-progress', {
          taskId,
          progress: { stage: 'reading', percent: 20 },
        });
      }
      const source = await ctx.bridge.request<{ content: string }>('file:read', {
        path: request.inputPath,
        encoding: 'utf-8',
      });
      const translated = await ctx.bridge.request<{ text: string }>('translate:run', {
        text: source.content,
        target: request.target,
      });
      await ctx.bridge.request<void>('file:write', {
        path: request.outputPath,
        data: translated.text,
        encoding: 'utf-8',
      });
      if (taskId !== undefined) {
        await ctx.bridge.request('cli:task-complete', {
          taskId,
          output: { files: [request.outputPath] },
        });
      }
    } catch (error) {
      if (taskId !== undefined) {
        await ctx.bridge.request('cli:task-fail', { taskId, error });
      }
      throw error;
    }
  }
}
```
