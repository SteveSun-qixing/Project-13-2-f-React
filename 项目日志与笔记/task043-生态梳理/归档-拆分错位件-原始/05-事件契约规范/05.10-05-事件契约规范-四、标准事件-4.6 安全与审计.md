### 4.3 文件

#### file:changed

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `uri` | string | 是 | 发生变化的文件或目录 URI |
| `kind` | `'created' \| 'modified' \| 'deleted' \| 'renamed'` | 是 | 变化类型 |
| `previousUri` | string | 否 | 旧 URI；仅 `renamed` 时出现，此时 `uri` 为新 URI |

触发时机：被监视的文件或目录发生变化时发布（`file:watch` 监视生效）。
可见性：公开；URI 一律为合法资源 URI，不含裸绝对路径。

**订阅示例（渲染进程；`subscribe`、`isRecord` 沿用 4.2）**

```typescript
interface IFileChangedPayload {
  uri: string;
  kind: 'created' | 'modified' | 'deleted' | 'renamed';
  previousUri?: string;
}

function isFileChangedPayload(value: unknown): value is IFileChangedPayload {
  if (!isRecord(value)) {
    return false;
  }
  const changedKind = value.kind;
  const isKindValid =
    changedKind === 'created' ||
    changedKind === 'modified' ||
    changedKind === 'deleted' ||
    changedKind === 'renamed';
  const isPreviousUriValid = value.previousUri === undefined || typeof value.previousUri === 'string';
  return typeof value.uri === 'string' && isKindValid && isPreviousUriValid;
}

const fileBadgeSubscription: ISubscription = subscribe<IFileChangedPayload>(
  'file:changed',
  isFileChangedPayload,
  (payload) => {
    console.info(`文件${payload.kind}：${payload.uri}`);
  },
);

// 视图卸载时释放；窗口销毁时 preload 亦会自动清理
fileBadgeSubscription.dispose();
```

### 4.4 资源

#### resource:invalidated

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `uri` | string | 是 | 失效的资源 URI |
| `reason` | ResourceInvalidateReason | 是 | `source-changed`（来源变化）/ `session-closed`（会话关闭）/ `scope-revoked`（作用域撤销） |

触发时机：资源来源变化、会话关闭或作用域撤销导致句柄失效时发布；句柄转为 `invalidated` 后不再可读（见《[04-资源管理设计](../01-架构设计/01-子系统设计/04-资源管理设计.md)》四、五节）。
可见性：公开；经 `event:resource:invalidated` 投递到对应渲染会话。

**订阅示例（渲染进程；`subscribe`、`isRecord` 沿用 4.2）**

```typescript
type ResourceInvalidateReason = 'source-changed' | 'session-closed' | 'scope-revoked';

interface IResourceInvalidatedPayload {
  uri: string;
  reason: ResourceInvalidateReason;
}

function isResourceInvalidatedPayload(value: unknown): value is IResourceInvalidatedPayload {
  if (!isRecord(value)) {
    return false;
  }
  const invalidateReason = value.reason;
  const isReasonValid =
    invalidateReason === 'source-changed' ||
    invalidateReason === 'session-closed' ||
    invalidateReason === 'scope-revoked';
  return typeof value.uri === 'string' && isReasonValid;
}

const resourceSubscription: ISubscription = subscribe<IResourceInvalidatedPayload>(
  'resource:invalidated',
  isResourceInvalidatedPayload,
  (payload) => {
    console.info(`资源已失效：${payload.uri}（${payload.reason}）`);
  },
);

resourceSubscription.dispose();
```

### 4.5 配置

#### config:changed

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `key` | string | 是 | 完整配置键 |
| `layer` | ConfigLayer | 是 | 本次变化影响的层：`platform` / `user` / `workspace` / `plugin` |
| `value` | unknown | 是 | 该层当前值；`null` 表示该层覆盖被移除 |
| `effectiveValue` | unknown | 是 | 变化后的生效值 |
| `isDefault` | boolean | 是 | 生效值是否来自 schema 声明默认值 |
| `origin` | ConfigOrigin | 是 | 变更来源：`platform` / `migration` / `external` / `plugin:<pluginId>` |

触发时机：配置写入或删除提交成功后逐键发布；迁移完成、外部修改被采纳、工作区切换后按生效值变化逐键发布。同值写入不落盘、不发事件；写入被更高层遮蔽时事件仍按发生变化的层发布，订阅方以 `effectiveValue` 判断是否需要响应（见《[10-配置系统设计](../01-架构设计/01-子系统设计/10-配置系统设计.md)》第六节）。
可见性：`platform` 命名空间的事件对持有 `config:read:platform` 的插件可见；`plugins.<pluginId>` 命名空间的事件只对该插件与平台可见。
