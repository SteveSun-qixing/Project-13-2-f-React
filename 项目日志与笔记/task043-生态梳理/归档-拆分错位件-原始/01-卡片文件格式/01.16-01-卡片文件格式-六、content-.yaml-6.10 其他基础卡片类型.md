> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：`.card` 文件格式的权威定义：文件本质与 ZIP Store、完整离线卡片与网络资源卡片、目录结构、`metadata.yaml` / `structure.yaml` / `content/*.yaml` 字段模型、`cover.html` 与封面链路、资源组织与路径规则、命名规范、版本兼容、完整性验证与安全性。

```yaml
# content/k1L2m3N4o5.yaml
card_type: "base.image"
theme: ""

images:
  - id: "cover-1"
    source: "file"
    file_path: "photo.jpg"
    title: "东京塔夜景"
    alt: "东京塔夜景照片"
  - id: "cover-2"
    source: "url"
    url: "https://example.com/tokyo-night-2.jpg"
    title: "备用网络图"
    alt: "东京夜景补充图片"

layout_type: "grid"
layout_options:
  grid_mode: "2x2"
  spacing_mode: "comfortable"
  single_width_percent: 100
  single_alignment: "center"
```

补充说明：

- `images` 可以为空数组，此时图片基础卡片显示为空状态；
- `source = file` 时必须提供 `file_path`，且路径必须相对于卡片根目录；
- `source = url` 时必须提供合法的 `http(s)://` 或 `webdav://` 地址；`data:`（含 `data:image/*`）仅运行时内存形态，禁止写入配置；
- 正式保存链路会把导入文件写入卡片根目录，并在配置中仅记录相对路径，例如 `photo.jpg`；
- 当 `images.length <= 1` 时，运行时有效布局强制视为 `single`，即使配置中的 `layout_type` 为其他值；
- 当 `images.length > 1` 且传入 `layout_type = "single"` 时，归一化结果必须改写为 `grid`；
- `spacing_mode = "none"` 表示图片零间距且无圆角，`spacing_mode = "comfortable"` 表示图片保留适当间距并使用小圆角；
- `long-scroll` 为纵向完整展开布局，不允许再通过配置引入固定高度子滚动窗口。

### 6.4 评分卡片（base.score）

```yaml
# base.score 配置 Schema
$schema: "https://json-schema.org/draft/2020-12/schema"
title: "Score Card Config Schema"
type: object
required:
  - card_type
  - style
  - score
  - total_score
properties:
  card_type:
    const: "base.score"
    description: "评分基础卡片正式类型标识；历史别名 ScoreCard 只允许读取归一，不作为新写入值"
  style:
    type: string
    enum: ["stars", "hearts", "score", "progress"]
    description: "评分展示样式"
  score:
    type: number
    minimum: 0
    description: "获得分数"
  total_score:
    type: number
    minimum: 1
    maximum: 100000
    description: "总分。星星和爱心样式固定归一为 5"
  locale:
    type: string
    description: "内容语言"
```

示例 1：星星评分

```yaml
# content/s1C2o3R4e5.yaml
card_type: "base.score"
theme: ""
style: "stars"
score: 4
total_score: 5
locale: "zh-CN"
```

示例 2：进度条评分

```yaml
# content/s1C2o3R4e5.yaml
card_type: "base.score"
theme: ""
style: "progress"
score: 82.5
total_score: 100
locale: "zh-CN"
```

补充说明：

- 正式类型标识为 `base.score`，运行时别名可以是 `ScoreCard`；新写入使用正式标识；
- `style = stars` 与 `style = hearts` 时，评分固定为五分制，`total_score` 必须归一为 `5`，`score` 必须为 `0-5` 的整数；
- `style = score` 与 `style = progress` 时，编辑器提供 `total_score` 与 `score` 两个输入字段；
- `score` 不得小于 `0`，且不得超过 `total_score`；
- 查看态只负责展示评分结果，不得自行写回配置或承担持久化职责；
- 查看态不应额外添加最外层卡片描边、背景色或阴影，外层装配视觉由平台渲染层负责。

### 6.5 网页卡片（base.webpage）

```yaml
# base.webpage 配置 Schema
$schema: "https://json-schema.org/draft/2020-12/schema"
title: "Web Page Card Config Schema"
type: object
required:
  - card_type
  - source_type
  - display_mode
  - fixed_ratio
  - max_height_ratio
properties:
  card_type:
    const: "base.webpage"
    description: "网页基础卡片正式类型标识；历史别名 WebPageCard 只允许读取归一，不作为新写入值"
  source_type:
    type: string
    enum: ["url", "bundle"]
  source_url:
    type: string
    description: "远程网页地址（source_type=url 时使用）"
  bundle_root:
    type: string
    description: "网页目录在卡片根目录中的相对路径（source_type=bundle 时使用）"
  entry_file:
    type: string
    description: "网页目录入口文件，正式必须为 index.html"
    default: "index.html"
  resource_paths:
    type: array
    description: "网页目录中所有已纳入卡片资源清单的文件路径"
    items:
      type: string
  display_mode:
    type: string
    enum: ["fixed", "free"]
  fixed_ratio:
    const: "7:16"
  max_height_ratio:
    const: 20
```

示例 1：远程网页

```yaml
# content/w1E2b3P4g5.yaml
card_type: "base.webpage"
source_type: "url"
source_url: "https://example.com/demo"
bundle_root: ""
entry_file: "index.html"
resource_paths: []
display_mode: "fixed"
fixed_ratio: "7:16"
max_height_ratio: 20
```

示例 2：卡片内网页目录

```yaml
# content/w1E2b3P4g5.yaml
card_type: "base.webpage"
source_type: "bundle"
source_url: ""
bundle_root: "webpage-bundle-a1b2c3"
entry_file: "index.html"
resource_paths:
  - "webpage-bundle-a1b2c3/index.html"
  - "webpage-bundle-a1b2c3/assets/app.js"
  - "webpage-bundle-a1b2c3/assets/style.css"
display_mode: "free"
fixed_ratio: "7:16"
max_height_ratio: 20
```

补充说明：

- 网页 ZIP 包、电子书 ZIP/CBZ 图片包等目录资源导入后，正式产物不是压缩包本身，而是卡片根目录中的过滤后资源目录；
- 网页目录入口文件必须为 `index.html`；
- `bundle_root`、`entry_file`、`resource_paths` 都必须相对于卡片根目录记录；
- 网页卡片查看态正式支持两种显示模式：
  - `fixed`：固定为宽:高 `7:16` 视口，并在该窗口内滚动网页；
  - `free`：按页面实际高度展开，但最高不超过当前宽度的 `20` 倍；
- `fixed_ratio` 当前正式固定为 `7:16`，用于声明固定比例模式的标准比例。

### 6.6 富文本卡片（base.richtext）

```yaml
# base.richtext 配置 Schema
$schema: "https://json-schema.org/draft/2020-12/schema"
title: "Rich Text Card Config Schema"
type: object
required:
  - card_type
  - content_format
  - content_source
  - markdown_capabilities
properties:
  card_type:
    const: "base.richtext"
    description: "富文本基础卡片正式类型标识；历史别名 RichTextCard 只允许读取归一，不作为新写入值"
  content_format:
    const: "markdown"
    description: "富文本基础卡片正式只保存 Markdown 内容"
  content_source:
    type: string
    enum: ["file", "inline"]
    description: "Markdown 内容来源"
  content_file:
    type: string
    description: "卡片根目录相对 Markdown 文件路径（content_source 为 file 时必需）"
  content_text:
    type: string
    description: "内联 Markdown 文本（content_source 为 inline 时必需）"
  locale:
    type: string
    description: "内容语言"
  markdown_capabilities:
    type: object
    description: "当前富文本 Markdown 能力矩阵，必须显式写入，以便查看器、编辑器和迁移工具按同一能力解析"
    required:
      - commonmark
      - gfm
      - math
      - highlight
      - underline
      - superscript
      - subscript
    properties:
      commonmark:
        type: boolean
      gfm:
        type: boolean
      math:
        type: boolean
      highlight:
        type: boolean
      underline:
        type: boolean
      superscript:
        type: boolean
      subscript:
        type: boolean
```

正式存储规则：

- 富文本基础卡片以 Markdown 为唯一持久化格式，卡片文件中只保存 Markdown 数据，不保存编辑器内部 HTML；
- 当 Markdown 提取后的纯文本字符数 `<= 200` 时，必须写入 `content_text`；
- 当 Markdown 提取后的纯文本字符数 `> 200` 时，必须把正文写入卡片根目录下的 `.md` 文件，并在配置中通过 `content_file` 引用；
- `content_file` 必须是卡片根目录相对路径，不能写成绝对路径，也不能相对于 `content/` 目录；
- `inline` 与 `file` 两种模式互斥，正式配置中不得同时保存 `content_text` 与 `content_file`；
- `markdown_capabilities` 必须显式声明当前解析能力，默认全部为 `true`；
- 编辑器悬浮工具框属于运行时行为，不属于持久化配置字段。

示例 1：短内容内联保存

```yaml
# content/a1B2c3D4e5.yaml
card_type: "base.richtext"
content_format: "markdown"
content_source: "inline"
content_text: |
  # 旅行日记

  这次东京之旅非常精彩。
locale: "zh-CN"
theme: ""
markdown_capabilities:
  commonmark: true
  gfm: true
  math: true
  highlight: true
  underline: true
  superscript: true
  subscript: true
```

示例 2：长内容文件化保存

```yaml
# content/a1B2c3D4e5.yaml
card_type: "base.richtext"
content_format: "markdown"
content_source: "file"
content_file: "richtext/a1B2c3D4e5.md"
locale: "zh-CN"
theme: ""
markdown_capabilities:
  commonmark: true
  gfm: true
  math: true
  highlight: true
  underline: true
  superscript: true
  subscript: true
```

```md
# richtext/a1B2c3D4e5.md
# 东京旅行日记

这次东京之旅非常精彩...

- 参观了浅草寺
- 登上了东京塔
- 品尝了地道拉面
```

### 6.8 音乐卡片（base.music）

```yaml
# base.music 配置 Schema
$schema: "https://json-schema.org/draft/2020-12/schema"
title: "Music Card Config Schema"
type: object
required:
  - card_type
  - audio_file
properties:
  card_type:
    const: "base.music"
    description: "音乐基础卡片正式类型标识；历史别名 MusicCard 只允许读取归一，不作为新写入值"
  audio_file:
    type: string
    description: "音频资源在卡片根目录中的相对路径"
  music_name:
    type: string
    description: "歌曲名"
  album_cover:
    type: string
    description: "专辑封面资源在卡片根目录中的相对路径"
  lyrics_file:
    type: string
    description: "歌词文件在卡片根目录中的相对路径"
  production_team:
    type: array
    description: "制作团队列表"
    items:
      type: object
      required:
        - id
        - role
        - people
      properties:
        id:
          type: string
        role:
          type: string
        people:
          type: array
          items:
            type: string
  release_date:
    type: string
    pattern: "^\\d{4}-\\d{2}-\\d{2}$"
    description: "发行日期，推荐使用 YYYY-MM-DD"
  album_name:
    type: string
    description: "专辑名字"
  language:
    type: string
    description: "语种"
  genre:
    type: string
    description: "流派"
```

示例：

```yaml
# content/m8N9o0P1q2.yaml
card_type: "base.music"
theme: ""
audio_file: "tracks/midnight-echo.mp3"
music_name: "Midnight Echo"
album_cover: "tracks/midnight-echo-cover.jpg"
lyrics_file: "tracks/midnight-echo-lyrics.lrc"
production_team:
  - id: "team-a1b2c3"
    role: "歌手"
    people:
      - "Alice"
      - "Bob"
  - id: "team-d4e5f6"
    role: "作曲"
    people:
      - "Caro"
release_date: "2026-04-18"
album_name: "Northern Lights"
language: "日语"
genre: "流行"
```

补充说明：

- `audio_file` 必填，且必须是卡片根目录相对路径；
- `album_cover` 与 `lyrics_file` 可选，但存在时也必须是卡片根目录相对路径；
- 运行时允许根据音频嵌入元数据自动补全 `music_name`、`album_name`、`production_team`，以及自动生成 `album_cover`、`lyrics_file` 对应资源；
- 若音频嵌入封面的真实图片格式是 TIFF，则正式 `album_cover` 资源必须先转换并落盘为 PNG 文件，再把最终 PNG 相对路径写回配置；不得把 TIFF 字节以伪装的 JPEG/PNG 扩展名直接写入卡片；
- 自动补全生成的封面与歌词文件仍然属于卡片内部正式资源，必须写入卡片根目录，而不是把内存 URL 直接写回配置；
- `music_name` 允许为空；当它为空时，查看态与编辑态展示标题可从 `audio_file` 的文件名派生，但正式配置字段仍保持空字符串；
- 查看态点击音乐卡片时，正式行为是把 `audio_file` 对应资源通过平台资源打开链路交给音乐播放器处理。

### 6.9 文件卡片（base.file）

```yaml
# base.file 配置 Schema
$schema: "https://json-schema.org/draft/2020-12/schema"
title: "File Card Config Schema"
type: object
required:
  - card_type
  - file_file
  - file_name
  - file_extension
properties:
  card_type:
    const: "base.file"
    description: "文件基础卡片正式类型标识"
  file_file:
    type: string
    description: "卡片内文件资源的卡片根目录相对路径（必填）"
  file_name:
    type: string
    description: "展示用文件名（不含后缀），由编辑器在导入文件时自动识别"
  file_extension:
    type: string
    description: "展示用文件后缀（小写、不含点），由编辑器在导入文件时自动识别"
  cover_image:
    type: string
    description: "可选的自定义封面资源（卡片根目录相对路径）"
```

示例：导入的 PDF 文件

```yaml
# content/f1L2e3F4i5.yaml
card_type: "base.file"
theme: ""
file_file: "docs/季度报告.pdf"
file_name: "季度报告"
file_extension: "pdf"
cover_image: ""
```

补充说明：

- 正式类型标识为 `base.file`，运行时别名可以是 `FileCard`；
- `file_file` 必填，且必须是卡片根目录相对路径，不得写入绝对路径、`file://`、`blob:`、`data:`、查询串、片段标识或 `..` 路径逃逸；
- `file_name` 与 `file_extension` 由编辑器在导入文件时按原始文件名自动识别，不提供手工编辑字段；字段缺失时查看态从 `file_file` 派生；
- `cover_image` 可选；未提供时按 `file_extension` 解析文件类别（document / spreadsheet / presentation / archive / audio / video / image / text / code）使用插件内置类别默认封面，未登记任何类别的后缀回退为带后缀文字的文件图标占位；
- 插件必须返回 `file_file` 与 `cover_image` 中全部有效的卡片根目录相对资源路径并去重；
- 替换或删除文件时，旧配置中不再被引用的内部资源必须通过平台资源管理链路登记删除；
- 查看态点击整卡时通过平台资源打开接口表达「打开该文件」的意图：资源 ID 为 `file_file` 卡片根目录相对路径，MIME 类型由插件按后缀内置映射表推断，不传业务载荷；平台按资源处理器能力与扩展名推断路由，未命中时回退系统默认打开方式。

### 6.10 其他基础卡片类型

其他基础卡片类型的 schema 由对应基础卡片插件定义并随插件发布；文档级只校验通用信封（根映射与 `card_type`），插件专有字段作为不透明值原样保留。插件接口、`BaseCardView` 节点渲染视图与编辑器契约见[08-基础卡片插件接口](../05-接口与契约/08-基础卡片插件接口.md)。
