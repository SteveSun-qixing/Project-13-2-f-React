# 卡片传输协议

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：`.card` / `.box` 在本地设备与内容服务器之间传输的权威协议：传输会话（创建、预签名、分片、断点续传、取消、恢复）、完整离线卡片与网络资源卡片的可逆改写与还原（含可逆恢复清单）、摘要与完整性校验、预签名与对象存储桶角色、传输队列与 `transfer:*` 事件映射、错误码与安全约束；不覆盖卡片/箱子的包结构语义、渲染链路与服务器产品设计。

---

服务器校验顺序（任一失败即整体拒绝，不产生部分提交）：

1. 会话归属、状态与有效期；
2. 提交对象全部属于本会话（以 `objectId` 与对象键前缀交叉校验）；
3. 对每个对象执行 Head：大小与提交一致；摘要与对象元数据 `x-amz-meta-chips-sha256` 一致（5.3）；
4. `multipart` 对象已在服务器侧完成合并；
5. 恢复清单结构合法（4.4）且 `schemaVersion` 受支持；
6. 网络资源卡片内容引用本会话全部资源 URL，且卡内不再包含这些资源的原始字节（防止"模型新 + 资源旧"的混合提交）；
7. 渲染产物（如提交）入口文件已上传且已预签名。

响应（卡片，202）：

```json
{
  "data": {
    "cardId": "1a2b3c4d-…",
    "versionId": "6f7c1d2e-…",
    "status": "ready",
    "communityUrl": "https://www.example.com/cards/{cardId}",
    "renderStatusUrl": "/api/v1/cards/{cardId}/render-status"
  }
}
```

- `status` 取值 `ready`（内容已发布）或 `pending`（服务器渲染模式下等待查看产物；客户端渲染模式未提交产物时同样为 pending）。
- `renderStatusUrl` 只在服务器提供查看状态查询时返回（2.4）。
- `complete` 幂等：同一会话重复提交且内容一致时返回同一结果；内容不一致返回 `CARD_TRANSFER_SESSION_STATE_INVALID`；`aborted` / `expired` 会话返回对应错误。

### 3.7 取消与过期

```http
POST /api/v1/card-transfer/upload-sessions/:uploadId/abort
Authorization: Bearer <token>
```

- 响应 `{ "data": { "uploadId": "…", "status": "cancelled" } }`；`abort` 幂等：重复调用返回同一结果。
- 取消必须执行：中止全部未完成的 `multipart` 对象、清理会话未提交临时对象；不影响已提交的其他会话。
- 已完成会话执行 `abort` 返回 `CARD_TRANSFER_SESSION_STATE_INVALID`，不改变已发布内容。
- 服务器按会话有效期把超期会话置为 `expired`；过期后的预签名地址即使未到期也不得再被接受。

### 3.9 下载分片与断点

1. 网络资源卡片按整对象下载；资源对象按 `Range` 分片下载（分片大小由引擎统一配置，默认 8 MiB）。
2. 每个对象下载到临时工作目录的 `.part` 文件；引擎按对象记录已下载字节偏移。
3. 中断后重新获取计划并续传：对未完成对象发送 `Range: bytes=<offset>-`；服务端不支持范围请求时必须按整对象重新下载。
4. 每个对象下载完成后立即校验 `sizeBytes` 与 `sha256`（5.4），通过后原子重命名到工作副本的最终路径。
5. 下载顺序：先网络资源卡片，再资源对象；`openRemote` 只下载网络资源卡片，不下载资源、不重建完整离线卡片。
6. 下载会话的本地检查点至少包含：`transferId`、`kind`、`serverBaseUrl`、`cardId`、`outputPath`、`phase`、每个对象的 `objectKey` 与已下载偏移；检查点同样不得包含预签名地址。

### 3.10 箱子上传会话

箱子与卡片共用同一控制面，通过 `contentType: 'box'` 分流；字节仍直传对象存储。流程：

1. 传输引擎在本地解包 `.box` 工作副本（正式形态只有单文件 `.box`，解包目录是临时物，[13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §4.5）；
2. 遍历 `structure.entries`（[02-箱子文件格式](../04-文件格式规范/02-箱子文件格式.md) §三）：
   - 包内相对路径（内嵌条目）与 `http(s)://` / `webdav://` 网络条目跳过，并记入 `skippedCards`；
   - `file://` 本地条目收集为散落卡片，逐个按卡片上传链路（本文全部规则）上传；单卡失败或文件缺失记警告不阻断箱子（8.4）；
3. 箱子内容不改写：`structure.yaml`、内嵌卡片与箱子资源按原字节保留；散落卡片与社区内容的匹配由服务器按条目快照与公开卡片标识建立，不由客户端改写箱子；
4. 创建 `contentType: 'box'` 会话（3.2），可选预签名并上传箱子封面（`cover-file`，对象键 `boxes/{boxId}/cover/{relativePath}`）；
5. 预签名 `box-file` 单个对象（MIME `application/vnd.chips.box+zip`），重新打包箱子工作副本后直传；
6. 提交 `complete`：`boxFile`（对象引用与大小）、可选 `coverObject`、`metadata` / `structure` / `content`（YAML 解析结果）、`title` / `boxFileId` / `layoutPlugin` / `coverRatio`；
7. 响应（200）：

```json
{
  "data": {
    "boxId": "3c4d5e6f-…",
    "versionId": "6f7c1d2e-…",
    "status": "ready",
    "communityUrl": "https://www.example.com/boxes/{boxId}",
    "boxViewUrl": "/api/v1/boxes/{boxId}/view"
  }
}
```

规则：

- 散落卡片必须先于箱子本体上传成功：服务器解析箱子时需要已有卡片记录；先传卡片再传箱子是协议顺序要求。
- 箱子本体预签名必须在打包完成后执行，确保 `sizeBytes` 与实际上传字节一致。
- 箱子上传结果必须返回 `uploadedCards` 与 `skippedCards`（见 3.6.1）。

#### 3.10.1 箱子上传任务结果（本地）

以下结构是任务完成时返回给调用方的本地结果，不属于控制面上传载荷；`cardFile` 等本地路径字段不上传服务器。

```json
{
  "boxId": "3c4d5e6f-…",
  "communityUrl": "https://www.example.com/boxes/3c4d5e6f-…",
  "uploadedCards": [
    {
      "entryId": "a1B2c3D4e5",
      "documentId": "a1B2c3D4e5",
      "cardFile": "/Users/me/cards/day-01.card",
      "communityCardId": "1a2b3c4d-…",
      "communityUrl": "https://www.example.com/cards/1a2b3c4d-…"
    }
  ],
  "skippedCards": [
    { "entryId": "f6G7h8I9j0", "url": "cards/day-02.card", "reason": "embedded" },
    { "entryId": "k1L2m3N4o5", "url": "https://example.com/day-03.card", "reason": "network" }
  ],
  "warnings": []
}
```

- `reason` 只允许 `embedded` / `network`；`documentId` 在条目快照缺失时可省略。
- `warnings` 项为 8.4 定义的警告码与说明。
