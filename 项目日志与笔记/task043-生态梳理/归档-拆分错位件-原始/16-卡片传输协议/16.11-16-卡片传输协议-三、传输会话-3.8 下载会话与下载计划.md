# 卡片传输协议

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：`.card` / `.box` 在本地设备与内容服务器之间传输的权威协议：传输会话（创建、预签名、分片、断点续传、取消、恢复）、完整离线卡片与网络资源卡片的可逆改写与还原（含可逆恢复清单）、摘要与完整性校验、预签名与对象存储桶角色、传输队列与 `transfer:*` 事件映射、错误码与安全约束；不覆盖卡片/箱子的包结构语义、渲染链路与服务器产品设计。

---

#### 3.5.2 本地检查点

传输引擎必须为进行中的上传任务保存最小检查点；检查点存放在工作区临时工作目录（平台保留前缀，[13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §3.2），并在崩溃后按工作区恢复流程参与清理登记。检查点至少包含：

| 字段 | 语义 |
|---|---|
| `schemaVersion` | 检查点版本（与协议主版本一致） |
| `transferId` | 队列任务标识 |
| `kind` | `card-upload` / `box-upload` |
| `serverBaseUrl` | 控制面基础地址 |
| `uploadId` / `versionId` | 会话标识 |
| `contentType` | `card` / `box` |
| `sourcePath` | 源文件受管路径 |
| `outputPath` | 本地工作副本位置（含网络资源卡片输出路径） |
| `cardId` / `boxId` | 服务器分配的内容标识（创建响应后写入） |
| `phase` | 当前阶段（7.2） |
| `updatedAt` | 最后更新时间 |

- 检查点不保存分片状态、对象键或预签名地址：分片状态以 3.5.1 查询为准，预签名地址一律重新签发。
- 检查点不得包含服务器凭证材料与预签名 URL。

#### 3.5.3 恢复流程

1. 读取检查点，确认会话 `status = created / uploading` 且未过期；
2. 调用 3.5.1 查询对象与分片状态；
3. 对未完成对象按 3.3.1 续签缺失分片或对未预签名对象重新预签名；
4. 跳过 `completed` 对象与已上传分片，继续上传；
5. 若会话已过期或 `aborted`，丢弃检查点并按 3.2 新建会话，从头执行上传（不提供跨会话对象复用）；
6. 恢复后任务重新进入队列，`transfer:progress` 从权威已传字节继续累计。

POST /api/v1/card-transfer/upload-sessions/:uploadId/complete
Authorization: Bearer <token>
Content-Type: application/json
