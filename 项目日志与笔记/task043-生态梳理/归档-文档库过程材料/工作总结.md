## 三、核心内容

### 3.1 技术架构确定

**整体架构**
```
插件层（Plugins）
    ↕
运行时层（Cordis Runtime + Bridge）
    ↕
核心层（Rust Core）
    ↕
平台层（Electron）
```

**技术栈**
- 核心：Rust + Neon (Node Native Module)
- 运行时：Cordis + TypeScript
- 前端：React 18 + fork antd + @chips/ui
- 平台：Electron（桌面端）
- 构建：pnpm workspace (Monorepo)

**插件角色**
- BaseCard Plugin：基础卡片插件
- BoxLayout Plugin：箱子布局插件
- App Plugin：应用插件
- Service Plugin：服务插件

**文件格式**
- .card 文件：YAML + 目录结构 + ZIP Store
- .box 文件：YAML + 目录结构 + ZIP Store

---

### 3.2 核心设计决策

#### 1. 插件系统：Cordis 运行时

**决策**：使用 Cordis 作为插件运行时

**核心机制**
- 插件生命周期管理
- 服务依赖注入
- 中间件系统
- 热插拔支持

#### 2. 核心架构：Rust + Node Native Module

**决策**：Rust 实现核心算法，通过 Neon 绑定到 Node.js

**职责划分**
- Rust 核心：文档解析、资源管理、加密、同步
- Node.js 层：插件运行时、UI 渲染、系统集成

#### 3. Bridge 系统：能力导向设计

**决策**：采用 Capability-Oriented Bridge 设计

**核心概念**
- 能力（Capability）：平台提供的原子化功能单元
- 三层架构：插件层 ↔ Bridge 层 ↔ Host 层
- 权限系统：细粒度权限控制

#### 4. 插件分类：只分角色不分类

**决策**：插件不按功能分类，只按角色区分

**四种角色**
- BaseCard：定义卡片类型
- BoxLayout：定义箱子布局
- App：独立应用
- Service：后台服务

#### 5. 前端技术栈：React + fork antd

**决策**：React + fork antd + @chips/ui 共享层

**架构红线**
- 唯一组件库：@chips/ui（禁止直接引入 antd）
- 禁止硬编码样式（使用 antd token）
- 简体中文直写（禁止多语言系统）

#### 6. 文件格式：YAML + ZIP Store

**决策**：YAML 作为主格式，ZIP Store 归档

**核心原则**
- 人类可读（YAML）
- 开放标准（第三方工具可读写）
- 跨平台兼容
- 高性能（Store 模式不压缩）

#### 7. 跨平台策略：双平台分离

**决策**：桌面端和移动端分离开发，三层统一

**三层统一**
- 文件格式统一
- Rust 核心复用
- Bridge 接口统一

#### 8. 重构策略：大爆炸重构

**决策**：完全推倒重来，不做兼容

**核心原则**
- 新系统完全独立开发
- 不考虑旧系统兼容性
- 不做渐进式迁移
- 第一版发布前不考虑兼容性设计

### 3.3 开发规范建立

#### TypeScript 编码规范

- 严格模式（strict: true）
- 命名规范（PascalCase、camelCase、SCREAMING_SNAKE_CASE）
- 类型注解要求
- ESLint 配置
- Prettier 配置

#### React 组件开发规范

- 组件结构模板
- Hooks 使用顺序
- 性能优化（memo、useMemo、useCallback）
- 测试要求

#### Rust 编码规范

- Cargo 配置
- 命名规范
- 错误处理（thiserror）
- 异步编程（tokio）
- Neon 绑定

#### 测试规范

- 测试金字塔（70% 单元，20% 集成，10% E2E）
- 覆盖率要求（> 80%）
- 测试工具（vitest、playwright、criterion）

#### Git 工作流规范

- 分支命名（task-{编号}-{任务名称}）
- 提交规范（feat/fix/docs/test/chore）
- PR 流程
- 合并策略（Squash and Merge）

#### 文档编写规范

- 文档分类（ADR、子系统设计、开发规范、API、用户文档）
- 文档结构模板
- 零冗余原则
- 文档即代码
