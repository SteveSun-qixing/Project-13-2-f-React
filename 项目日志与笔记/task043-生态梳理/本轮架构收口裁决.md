# 本轮架构收口裁决（唯一施工依据）

> 日期：2026-09-19
> 状态：生效
> 用途：本轮对 `薯片生态文档库/` 的收口修订，所有断言、命名、类型、机制与冲突裁决以本文为准；文档库内的表述如与本文冲突，按本文修订。
> 原则：以现有新架构（Cordis + Rust 核心 + Neon + Electron + React/@chips/ui）为准；不引入临时实现、不引入兼容层、不新增第二事实源。

## 一、命名与类型收口

| 项 | 裁决 |
|---|---|
| 渲染会话视图 | `DocumentView = CardRenderView \| BoxRenderView`；`CardView`/`BoxView` 名称作废（避免与 `@chips/ui` 组件名冲突） |
| 节点渲染视图 | `BaseCardView`（一个基础卡片节点实例）：`kind:'basecard'`、`node_id`、`card_type`、`content`、`revision`、`card`（卡片级上下文：`card_id`/`name`/`chip_standards_version`/`cover_ratio`/`tags`） |
| 布局渲染视图 | `BoxRenderView`（由 09-箱子布局插件接口使用；原 `Box` 名称作废） |
| 编辑句柄 | 拆分 `IBaseCardEditor` 与 `ILayoutEditor`；共同形状见 08/09；SDK 分别导出，不导出笼统 `IEditor` |
| 编辑链路 | 统一定名"编辑链路"，权威设计见新增《12-编辑引擎设计》；"编辑引擎"仅指官方编辑引擎应用（`chips.official.editor`） |
| 插件装载门面 | `IPluginRuntime`（渲染侧插件运行时，平台提供）：`loadBaseCard(cardType)` / `loadLayout(layoutType)` → 受管门面；应用与编辑链路不得自行加载插件模块 |

| 工具进程 | Electron Utility Process，由壳提供、内核调度；承载服务插件隔离执行与重计算；主进程插件当前以受管模块加载器为准（见 §三.14） |
| 错误类 | 统一 `ChipsError`（唯一名称，构造函数 `new ChipsError({ code, message, details?, retryable? })`）；`IChipsError` 仅作结构别名 |

## 二、运行时内核裁决（A 组）

1. **事件派发模型**：删除内核"五种分发模式/决策型事件"表述；事件总线仅同步广播。内核内部 Rust 订阅者同步调用；JS 插件监听器经 Channel 异步投递，`emit` 语义=入队成功（不等待 JS 执行）；同一发布者同事件 FIFO。
2. **生命周期超时**：`apply` 30s、`stop` 10s、Fork 强撤 30s；超时进入强制撤销并报 `KERNEL_LIFECYCLE_TIMEOUT`。常量定义在内核文档，其他文档引用不再自写数值。
3. **任务 API**：新增 `ctx.task(fn, { name?, signal? })`，返回可等待句柄；任务登记到当前 Fork，参与配额与取消；内核 `Effect::Task` 与之对应。
4. **服务代际原子切换**：`Starting` 阶段的 `provide` 只入**暂存代际**，不对外可见；插件进入 `Active` 时一次原子发布并触发级联；apply 失败回滚暂存。
5. **依赖方状态**：提供方 `Failed` 时，依赖方保持 `Active`，服务条目摘除、调用返回 `KERNEL_SERVICE_NOT_FOUND`；提供方恢复后按拓扑重建。插件文档与此对齐。
6. **反向依赖索引**：键改为 `(ProviderFork/Generation, ServiceName)`；只有受该代际影响的注入才重建。
7. **服务版本**：不设独立服务版本号。Rust 服务为内核 ABI，随平台版本；插件间服务消费由 `dependencies` 版本范围 + 能力契约版本约束。注入/重建回环加收敛上限（重建深度 ≤ 16，超限报 `KERNEL_REBUILD_OVERFLOW`）。
8. **配额**：内核定义插件软配额（内存、任务数、消息速率、后台时长）与计量点；超限状态机：限流 → 暂停 → 停用；默认值写入内核文档；插件/服务文档引用。
9. **取消传播**：`ICapability.execute(input, ctx)`，`ctx.signal: AbortSignal`、`ctx.deadline`；Bridge 适配层如实传递；能力契约与 SDK 同步。
10. **二进制信封**：Bridge 调用信封 = `{ json, bin }`；`json` 走 schema 校验，声明为 `x-chips-binary` 的字段值改为 `bin` 表的键；Rust 侧 `CapabilityInput { json, bin: BTreeMap<String, Vec<u8>> }`；Neon 边界二进制一次拷贝。删除"二进制经 base64"的兜底表述。
11. **事件名文法**：`^[a-z][a-z0-9-]*:[a-z][a-z0-9-]*$`（禁止点号）；插件自有域取插件 ID 末段；内核文档与事件文档一致。
12. **`plugin:loaded` payload**：`{ pluginId, version, role }`；内核事件构造改为结构化。
13. **安装与授权**：安装只登记权限申请；首次启用逐项授权；拒绝不阻断启用（该权限保持未授权）。03-插件架构与 08-权限系统对齐。
14. **主进程插件执行载体**：受管模块加载器（ModuleLoader）——只允许插件作用域 `chips-resource://` 与平台白名单模块（`@chips/sdk` 类型、平台提供物）；禁止 `node:*`、`electron`、裸路径；加载器是完整性门禁。服务插件的进程级隔离由工具进程承担，作为 03-插件架构中的正式执行形态登记。
15. **崩溃重启**：受控重启策略——10 分钟窗口内最多 3 次，指数退避；超限进入 `Failed` 等待显式启用。内核与插件/服务文档对齐。
16. **蓝绿**：`app` 角色旧窗口全部关闭前不强制撤销（标记冻结、拒绝新调用）；draining 上限仅适用于非 `app` 角色。
17. **配置注入**：定义 `PluginConfig`（插件命名空间生效值视图 + 加载时机）与 ConfigStore 唯一暴露路径（面向主进程经 Cordis 服务，面向 Neon 经核心接口）；删除双路径表述。
18. **`resources.*` 配置**：迁移为 `platform.resources.*` 并登记 schema。
19. **事件标准表**：09-事件系统 §8 补齐 `resource:invalidated`、`permission:granted`、`permission:denied`（payload 以 05-事件契约规范为准）。
20. **杂项**：内核"不提供 off"与事件文档统一为 `off(token)`；`KERNEL_LOCK_POISONED` 改为 `retryable:false`；`notification:show` 全库改 `notification:send`。

## 三、内容链路裁决（B 组）

1. **卡片帧与节点容器**：查看态 = 单个卡片帧；帧运行时为**每个节点创建独立容器**并在容器内调用 `renderView(basecard, container)`；节点级降级在帧内完成；禁止多节点共用容器。
2. **编辑态**：编辑链路由 `IEditSession` 通过平台插件门面就近渲染节点视图与编辑器；按用户描述保留"编辑即时预览"；应用插件绝不 import/加载插件代码。
3. **编辑回流唯一时序**：`IBaseCardEditor.getChange()` → 编辑链路校验（configSchema + validateConfig）→ `document:write`（输出 `{ revision }`）→ 渲染会话 `update(view, revision)` → `markCommitted(revision)`。05/08/09/11 图表统一。
4. **`document:write` 扩展**：`part:'content'` + 不存在的 `nodeId` = 创建成员（值来自插件 `createInitialContent` 或编辑链路）；`value:null` = 删除成员；`structure` 替换与内容成员必须在同一保存中一致。
5. **基础卡片接口补充**：`createInitialContent()`、`collectResourcePaths(basecard)`；`aliases`（manifest `capabilities.cardTypes[].aliases`）+ 读取归一规则（别名→正式 ID 由插件声明、平台读取时归一）。
6. **DocumentView 生产者**：渲染引擎解析阶段（主进程，Rust 核心）的**文档视图构建器**：输入解析句柄 + 会话模型，输出可结构化克隆的 `DocumentView`；类型登记 03-核心接口规范与 02-SDK-API 规范。
7. **写路径唯一化**：document 挂载（目录态与归档态）内所有写入经文档服务受控提交；`resource:write` 仅限插件作用域与临时作用域；归档态重建纳入 WriteCoordinator 同一路径锁；`file:delete` 权限=`filesystem:delete`；登记 `file:move`/`file:copy`/`file:mkdir` 为能力。
8. **大资源流式写**：`resource:write` 支持流式（`stream()` 可写 + `commit_write_stream`）；`file:copy` 支持流式；大资源导入流程（资源登记 → 流式提交 → 原子替换 → 事件）写入 11/04。
9. **缓存与外部修改闭环**：`document:changed` 只**刷新作用域版本戳**（不重建作用域）；外部修改时查看会话冻结并提示重载，禁止"模型旧 + 资源新"混用。
10. **版本与门禁**：`chip_standards_version` 禁止预发布（严格三段式）；删除"使用对应版本查看器"；`layout_configs.*.schema_version` 门禁在 04-版本与迁移规范中作为插件级版本门禁的正式例外说明。
11. **解析器限额**：512 MiB/1 万条等限额定位为"可配置的安全防护默认值"，格式规范承认其存在；删除"不设任何上限"的口径。
12. **两态转换**：新增能力 `document:export`（把文档以 `archive` 或 `directory` 形态写到目标路径，覆盖导入/导出/另存）；导入归档→工作区目录态、目录态→归档导出的正式流程写入《13-工作区设计》。
13. **实时预览预算**：回流到预览更新 ≤ 100ms（同一 rAF 合并）；`update` 失败报 `RENDER_UPDATE_FAILED`，保留旧帧；自动保存默认防抖 500ms（可配），失焦/关闭前 flush（写入 12-编辑引擎设计）。
14. **封面链**：条目目标为箱子时按正式封面渲染（`.box/cover.html`），不展开布局；封面渲染接口名统一为"受控封面渲染接口"，在 01/02 与 05 中使用同一名称。
15. **ZIP/格式/引用**：见 §一 相关裁决；01/02/03/04 四份格式文档与本裁决对齐；`webdav://` 正式纳入引用集合并补归一规则。
16. **同步引擎**：定位为"可选、按需加载的平台服务插件形态"，不启用时零副作用；核心只提供摘要/分块原语（登记 03-核心接口）；应用插件可调用 `enable/resolveConflict`；字段名改 `card_id`/`box_id`、`modified_at`；目录态不参与同步（打包后纳入，转换链接至 §三.12）。

## 四、契约裁决（C 组）

1. **能力总表校正**：三处"31 项"改为与实际一致（28 项 + 本轮新增能力后如实计数）；彻底删除 `image:*` 类型、错误码、权限；7.9 编号补齐；ADR-004 加"现状注记"。
2. **新增能力（登记进能力契约、权限系统、SDK、事件契约）**：
   - `window:list`、`window:resize`、`window:move`、`window:setTitle`
   - `menu:set`（应用菜单与托盘菜单）
   - `tray:set`（图标/tooltip）；事件 `tray:clicked`
   - `shortcut:register` / `shortcut:unregister`；事件 `shortcut:triggered`
   - `system:info`（平台版本/OS/架构/路径变量只读）
   - `power:query` / `power:prevent-sleep`
   - `transfer:download` / `transfer:cancel`；事件 `transfer:progress` / `transfer:completed` / `transfer:failed`
   - `document:export`（§三.12）
   - `config:snapshot` / `config:reset`（配置系统已定义，补登记）
   - `file:move` / `file:copy` / `file:mkdir`
   - 深链接：manifest 增加 `deepLinks` 声明；`AppLaunchSource` 增加 `deep-link`；投递事件 `app:opened-with-url`
3. **不提供的能力（在总表"范围外"明示）**：OAuth/登录流程（由凭证 + http 能力组合实现）、平台自动更新的插件接口（平台自更新）、`web` 插件目标（删除 `runtime.targets` 的 `web` 取值并说明）。
4. **`IEditor` 拆分**：`IBaseCardEditor`（08）/`ILayoutEditor`（09）；`getChange()` 返回各自变更类型；SDK 同步导出。
5. **角色接口同步**：08 使用 `BaseCardView`、`createInitialContent`、`collectResourcePaths`、`aliases`；09 使用 `BoxRenderView`；四份角色接口与 §一/§二 一致。
6. **主入口/渲染入口职责**：`dist/index.js` 只承载主进程可执行部分（注册转发、`validateConfig` 等纯函数）；`render.js` 承载 `renderView`/`renderEditor`/`export`；`src/index.ts` 拆分导出；构建外部化白名单（react、react-dom、`@chips/ui`）；修正 03-插件包格式、06-构建与打包、两份开发指南。
7. **SDK 导出补全**：`IAppBridge`、`IServiceBridge`、`IAppWindow`、`EntryView`、`LayoutChange`、`BaseCardView`、`BoxRenderView`、`IBaseCardEditor`、`ILayoutEditor`、`IPermissionDeniedDetails`、`installMockBridge` 等；SDK 导出清单与角色文档强制互相标注。
8. **错误码**：`PLUGIN_PERMISSION_DENIED` 仅表示权限拒绝；"owner 未 active"改用内核状态码；`RESOURCE_*` 解析器诊断码改 `DOCUMENT_RESOURCE_*`；04-资源管理 §5.4 引用统一改 §5.5。
9. **mail：`documentId`** 以 11-文档服务设计为准（= `card_id`/`box_id`，跨会话稳定）；04-能力契约修正"随会话创建"的表述。
10. **资源协议**：`resource()` 接受裸 `http(s)://`（按 §2.6 归一）；`notification:send` 全库统一；`credential:read/write` 改 `credential:manage`；`healthCheck` 单位统一字符串（`30s`/`5s`）；`ChipsError` 统一构造。
11. **ADR 注记**：ADR-001/002/003/004/005/007/008 增加"现状注记"章节（不删原文），写明被哪些正式文档取代/修订；ADR-006 保持废弃注记；ADR-007 的跨端能力示例改用已登记 ID，JNI/Swift FFI 表述与 03-核心接口对齐（Phase 5 再引入。
12. **示例修复**：服务插件指南的 `node:crypto` 示例改为平台能力/服务；`notification:show`、`pdf:export`、`window:resize` 等未登记 ID 全部修正；`file://` 示例标注"仅目录态、进入运行前归一"。

## 六、规范与治理裁决（E 组）

1. **覆盖率口径**：以架构原则/工程管理体系为准，统一"总体 > 80%、Rust 核心与共享层 > 90%"；测试规范与 CI 给出可执行配置；删除 95% 自创指标（或提升为工具链包指标并写明依据）。
2. **平台优先级**：统一为 macOS/Windows → Linux（桌面三端完成）→ Android → iOS；同步 R6、白皮书、ADR-007、阶段计划、构建文档。
3. **阶段口径**：ADR-010 删除日历时长，改用 Phase 口径；其他 ADR 的实施小节改名"实施顺序"，不与阶段路线冲突。
4. **R1-R20 入库**：在 `00-愿景与原则/01-架构原则.md` 增加"附录：规则编号表"，从编写基准搬运 R1-R20 全文并保持编号稳定；全库对 R 编号的引用即可解析。
5. **前端规范重写**：TypeScript/React 规范删除主题系统残留（`useTheme`/`ThemeContext`/CSS Modules/`styles.css`），改为 Design Tokens + `theme.useToken()` + `@chips/ui`；删除 Worker 旧表述与 TODO 示例。
