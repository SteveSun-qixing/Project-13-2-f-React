# 工单031：六扩展导出落地单派单落地面与禁改清单互斥——§8.6 Neon 面属 `chips-native`（packages/native），非 `chips-bridge` crate

> 类型：派单口径漂移 / 任务前置事实错误（架构落地面归属错误 + 授权面互斥）

## 一、背景

派发单要求「在 chips-bridge crate 按 RFC-026 §五.3 裁定实现六扩展导出名（`bridgeActivateProvider`、`bridgeDeactivateProvider`、`bridgeGrantCapabilityId`、`bridgeOpenSession`、`bridgeCloseSession`、`bridgeShutdown`，Neon export）」，并「`export-surface.json` 与 `.d.ts` 同步扩面（三方一致）」；同时禁改清单第 1 条明示「`packages/**`（全部 TS 面）零触碰」、验收闸全部限定 `-p chips-bridge`（core-rust 隔离工作区，members 仅 `crates/*`）。

经全量核查，该派单的前提「六扩展导出名在 chips-bridge crate 缺位」不成立：§8.6 Neon 导出面的唯一落地面是 `packages/native`（`chips-native` crate），`export-surface.json` 与 `chips-native.d.ts` 均在 `packages/native/` 下；chips-bridge 是不含 neon 依赖的纯 Rust 内核 crate，且其六个 backing 方法早已完整交付。派单落地面与禁改清单因此完全互斥，本单无可执行交付面。

## 二、证据（全部实测，2026-09-21）

1. **RFC-026 §五.3 原文**（`项目日志与笔记/RFC-chips-bridge契约发布面裁定/RFC-chips-bridge契约发布面裁定.md:94`）：六导出名「扩展导出」落地时「必须同 PR 更新《核心接口规范》§8.6 导出总表与 `packages/native/abi/export-surface.json`、`.d.ts` 三方一致」——三个改动面全部指向 `packages/native` 与文档库，无一指向 chips-bridge crate。
2. **§8.6 是 `chips-native` 的 Neon 导出总表**（`薯片生态文档库/05-接口与契约/03.08-03-核心接口规范-八、Neon 绑定约定.md`）：Bridge 域现登记四导出（§8.6 总表 :149）；§8.1 明文「`chips-native` 不实现业务逻辑，全部转发子系统 crate」「导出表在入口函数中集中声明」；§8.6 规则 3（:157）「内核启动与插件管理的导出……由插件管理层实现并以 `kernel`/`plugin` 前缀登记」——「预留域」指 native 模块导出表的登记域，不是 chips-bridge crate 内部。
3. **落地点实测**：Neon 导出注册表在 `packages/native/src/abi.rs:40-43`（`bridgeRegister` 等四项，`=> crate/bridge::js_bridge_*` 薄转发）；`packages/native/abi/export-surface.json` 现 15 导出；`packages/native/types/chips-native.d.ts` 同面镜像。core-rust 全仓 `find` 不存在任何 `export-surface.json` / `.d.ts`（唯一命中在 `packages/native`）。
4. **chips-bridge 无 Neon 面且不应有**：`crates/chips-bridge/Cargo.toml` 无 `neon` 依赖（grep 0 命中）；若在该 crate 内「实现 Neon export」，即把绑定层职责搬进内核 crate，直接违反 §8.1「绑定层零业务、内核层零绑定」的架构红线与 RFC-026 §三总则，属自改架构。
5. **六个 backing 方法在 chips-bridge 早已全功能交付**（`crates/chips-bridge/src/bridge.rs` 实测行号）：`activate_provider` :334（权限词表校验 → `PERMISSION_UNKNOWN`；shutdown 后 → `BRIDGE_CANCELLED`；重复激活覆盖）、`deactivate_provider` :363（级联注销+在途取消收口，幂等）、`grant_capability_id` :384（文法/内置保留/改绑 → `BRIDGE_CAPABILITY_CONFLICT`；owner 未激活 → `KERNEL_INVALID_TRANSITION`）、`open_session` :582、`close_session` :605、`shutdown` :621——参数校验、错误码归一、「未装配诚实错误码」均已逐码对齐契约码表，无任何缺位需要本单补齐；crate 内 136 用例逐成员覆盖（本单复跑三面全绿，见第五节）。
6. **工单025 原文自证落地面**：剩余项① 标题即写「绑定层激活/会话扩展导出（**`packages/native`**，本单边界只读不代修）」，6.3 建议「剩余项 1 为最小可独立收口单元（**改动集中在 `packages/native` + 文档三方同步**）」；宿主镜像 `packages/host/src/main/native-bridge.ts:23-25` 注释同样登记「尚未在 `packages/native` 落地」。
7. **三方锁现状一致且未扩面**：`export-surface.json`（15 项）↔ `abi.rs` 注册表 ↔ `chips-native.d.ts` 逐项一致，宿主 `tests/native-bridge.test.ts` 的 §8.6 必备六项（元信息 2 + Bridge 域 4，为已交付项）装载闸锁定通过——本次派发单未改动任何一面，既有锁面无扰动。
