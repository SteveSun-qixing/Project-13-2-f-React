## 一、开发计划（开工前定案）

### 1.1 契约面

| 项 | 取值 | 权威 |

### 1.2 查看态消费链定案

- Markdown → 安全 HTML 一律经 `chips.service.markdown` 公开契约方法面（`renderHtml`，输入/输出形状与 `plugins/services/markdown/contracts/render-html.*.schema.json` 同一口径）消费；**禁止直接 import 服务包内部**（04-能力契约规范 §八：内容处理服务不注册 Bridge 能力，消费方按提供方契约的类型化接口调用）。
- 渲染面注入缝沿用母型 grid 的 `attachRuntime` 形制：包内定义 `attachMarkdownRendering(source)` 注入点，平台帧运行时（插件执行通道，工单025 剩余 / #85）交付后注入契约实现；**当前宿主侧未注册调用面，接缝 fail-closed、如实登记缺位，禁假接线**（#257 交付判定公式、#264「宿主侧未注册调用面如实登记缺位禁假接线」同口径）。
- 未通能力域（如实登记，不伪造）：① 帧内服务调用通道（`chips.service.markdown` 为 Cordis 服务，渲染帧无 `window.chips`、无 basecard 侧 runtime 注入接口，通道归 #85）；② file 来源 `.md` 正文读取（帧内禁 `fetch`/`window.chips`，资源域接线归 W4 §七 条件四）；③ `markdown_capabilities` 中 math/highlight/underline/superscript/subscript 五项扩展语法在服务契约（`breaks/linkify/typographer` 三选项）中无承载面，查看态按能力声明如实降级提示，不建第二份 Markdown 渲染器（工单057 §六红线）。

### 1.3 编辑臂定案

- 旧编辑态基于 Milkdown（第三方）。**未经选型评估与用户确认，禁止引入任何新第三方运行时依赖**；文档库与裁决台账均无 Milkdown 授权在册 → **Milkdown 所见即所得编辑引擎不实现，登记「编辑引擎候用户选型」缺位**。
- `renderEditor` 为 08 §2.2 必选方法，不得缺位：按 04-基础卡片插件开发指南 §九官方完整示例的基线形制交付（Markdown 源文 TextArea + 展示 config 表单 + 200 字内联/文件化阈值提示），这是契约文档自身的规范形态，非临时占位；富文本编辑运行时候选型后升级。

## 三、登记项（冲突与缺位）

### 3.1 LEGACY_RICHTEXT_CARD_TYPE 兼容面不迁移（矩阵措辞冲突，本单裁决）

- 冲突：矩阵 :41 依据栏写「LEGACY_RICHTEXT_CARD_TYPE 兼容面随迁」；但《AGENTS.md》生态宪法与 ADR-010 为「无第一版发布、零兼容、不留旧 ID 别名」，且音乐富文本矩阵 G-5 对同一 `LEGACY_RICHTEXT_CARD_TYPE = "RichTextCard"` 明裁「清除 legacy 别名（ADR-010 不留兼容映射）」。两处矩阵措辞互相矛盾，本单按上位裁决执行：**不迁移**任何 legacy 别名读取归一面。
- 处置：`01.12 §6.6` schema 描述「历史别名 RichTextCard 只允许读取归一」属文件格式文档措辞，与本单口径的最终收口（改 schema 描述或在平台层统一归一）登记为待裁事项，不由本包私设兼容层。

### 3.2 编辑引擎候用户选型（缺位）

- Milkdown（旧仓授权依赖）在新生态无选型评估与用户确认记录，本包不引入；富文本所见即所得编辑引擎缺位，`renderEditor` 按 04 §九契约基线形制（Markdown 源文表单编辑 + 展示配置 + 200 字阈值提示）交付，候选型后以正式编辑引擎升级。对照 `08-官方应用功能总览` §十二：富文本编辑器应用（W5）「包装 base.richtext 基础卡片正式编辑器」，故该缺位同时阻塞 W5 应用编辑体验升级，登记在案。

### 3.3 未通能力域（如实登记，禁假接线）

1. **帧内服务调用通道**：`chips.service.markdown` 以 Cordis 服务提供（不注册 Bridge 能力，04.23 §8.5「渲染进程不得直接注入内容处理服务」）；basecard 角色无 `IBoxLayoutRuntimeAware` 同类注入接口，渲染帧插件执行通道未交付（工单025 剩余 / #85）。本包以 `attachMarkdownRendering` 契约注入缝承接，未注入时查看态 fail-closed 呈现简体中文状态行，不伪造渲染成功。
2. **file 来源正文读取**：帧内禁 `fetch`/`window.chips`（04 §8.4），`.md` 正文读取归资源/文档域接线（W4 §七 条件四）；未通前 file 来源查看态按缺位提示呈现。
3. **扩展语法渲染**：`markdown_capabilities` 五项扩展（math/highlight/underline/superscript/subscript）在 markdown 服务契约选项面（breaks/linkify/typographer）无承载；本包按能力矩阵对照如实降级提示，不建第二份 Markdown 渲染器（工单057 §六红线）。扩展语法承载面（服务契约扩项或独立渲染臂）候主智能体裁定。
