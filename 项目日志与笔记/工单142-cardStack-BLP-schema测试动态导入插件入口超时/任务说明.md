# 工单142：cardStack-BLP schema 测试动态导入插件入口超时

## 背景

cardStack-BLP 执行 `npm test` 时，`tests/unit/schema.test.ts` 的 "exported layoutDefinition validation rejects unsafe raw assetRefs" 用例稳定超时（vitest 默认 `testTimeout: 5000ms`），导致该仓库测试套件无法全绿。该失败与布局空状态骨架任务无关，属于既有问题。

## 证据

1. **用例内容**：`tests/unit/schema.test.ts:178-202` 通过 `await import("../../src/index")` 动态导入整个插件入口，以验证导出契约。`src/index.ts` 的依赖图包含 `editor/runtime.ts` → `editor/panel.tsx` → antd 6.5.4、`@chips/ui`、react-dom 等，冷启动导入耗时约 2.5s；在全量套件（两个测试文件并行）下超过 5s 被判定超时。
2. **基线复现**：`git stash` 后（不含任何工作区改动，处于提交 `2d293c96`）执行 `npm test`，同一用例仍超时（耗时 10252ms）——非本次任务改动引入。
3. **延长超时可过**：单独运行该用例并设置 `--testTimeout=30000`，通过且仅耗时 2554ms。
4. **同模式测试分布**：`await import("../../src/index")` 断言导出布局定义的模式同样存在于 documentLibrary-BLP（schema.test.ts:176）、map-BLP（:167）、masonry-BLP（:166）、timeline-BLP（:164），存在同类风险。

## 影响范围

- cardStack-BLP `npm test` 无法全绿（22 个用例中 21 通过、1 超时），阻塞 `npm run verify` 等质量门禁；
- 不影响查看态/编辑态运行时代码，不影响空状态骨架功能。

## 复现步骤

1. `cd Chips-BoxLayoutPlugin/cardStack-BLP`；
2. `npm test`；
3. 观察 `tests/unit/schema.test.ts > layout-config > exported layoutDefinition validation rejects unsafe raw assetRefs` 报 `Error: Test timed out in 5000ms`。

## 期望行为

- `npm test` 全绿。建议二选一：
  - 将 `layoutDefinition` 改为静态导入（复用 `layout-definition.test.tsx` 的顶部 `import { layoutDefinition } from "../../src/index"` 模式，利用模块缓存），用例改为同步断言；
  - 或仅为该用例单独提高 `testTimeout`（如 `it(..., 20000)`），并在注释中说明原因。

## 暂行处理

- 本工单仅登记，不改动 `schema.test.ts`（超出空状态骨架任务范围，避免混入任务外改动）；
