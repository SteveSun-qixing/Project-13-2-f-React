# 01-编辑引擎能力全景

本文档逐项盘点 `Chips-EditingEngine` 的全部能力点：能力描述、是否本地自实现、是否调用 SDK/Host、代码位置与规模。数据基于 2026-08-11 源码快照。

## 1. 总览统计

- 源文件约 200 个，src 目录约 2.3 万行，tests 约 1 万行（46 个文件）。
- 直接访问 `window.chips` 的代码点：仅 `src/hooks/useChipsBridge.ts`（9 行）。
- 统一 SDK client 入口：`src/runtime/chips-client.ts` → `src/services/bridge-client.ts`（`getChipsClient()` 单例）。
- 本地自实现（未走 Host）的能力合计约 1.1 万行，集中在文档领域、交互/窗口 UI、工具函数。

## 4. 服务层调用关系图（简化）

```text
编辑引擎组件/页面域
    │
    ├─ workspaceService ──────────► client.file.* / client.box.* / client.card.*
    ├─ cardService（本地文档模型）─► fileService ──► client.file.*
    ├─ boxDocumentService（本地会话）► client.box.* / client.card.* / fileService
    ├─ EditorHost（本地会话）─────► client.card.resolveResourceUrl / client.resource.* / zipService / fileService
    ├─ BasecardFrameHost ─────────► client.card.resolveResourceUrl（注入）
    ├─ CardWindow / BoxWindow ────► client.card.coverFrame / client.box.renderCover /
    │                                client.document.window / client.resource.open
    ├─ SettingsContext ───────────► client.config.*
    └─ 命令/快捷键 ───────────────► @chips/ui useCommandRegistry ──► client.command.*
```

所有系统原语调用均收敛于 `getChipsClient()`（SDK createClient → Bridge 适配），无绕层直连。

## 5. 结论要点

1. **系统原语层已全部接 Host**，编辑引擎的「套壳度」在底层已经达标；
2. **文档领域（卡片/箱子/编辑会话/封面/导入）是最大缺口**：约 6900 行纯本地业务逻辑，是其他软件无法复用的核心资产；
3. **UI 交互层（画布/窗口/拖拽/文件树）约 4900 行**：属于布局插件与编辑类应用的公共需求，应沉淀共享组件层；
4. **命令历史悬空**：undo/redo 栈完整但从未接入真实文档操作，需要在能力上移时一并决策；
5. **存在多处跨仓重复实现**（MIME、路径规范化、YAML 序列化、file URL、ID），详见 09 篇的重复实现证据表。
