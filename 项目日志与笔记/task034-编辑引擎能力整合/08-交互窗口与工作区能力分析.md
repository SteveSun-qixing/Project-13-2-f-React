# 08-交互窗口与工作区能力分析

## 1. 现状

交互/窗口/工作区是编辑引擎本地自实现规模最大的领域（约 4900 行）。该领域的能力性质与文档领域不同：**大部分属于 UI/交互层（组件与页面域）**，少数属于系统语义（工作区扫描、文件类型识别、文档历史）。

### 1.1 无限画布与布局（纯本地，无第三方库）

| 能力 | 位置 | 规模 |
|---|---|---|
| 画布数学内核（平移/锚点缩放/滚轮增量解析/坐标变换/fitToContent） | `InfiniteCanvas/use-canvas.ts` | 330 行 |
| 交互表面路由（desktop-background / composite-delegate / local-window / ignore） | `interaction-routing.ts` | 44 行 |
| 放落目标解析（elementFromPoint 命中/插入索引/指示线几何） | `canvas-drop-target.ts` | 240 行 |
| 画布组件（原生非 passive wheel、触摸代理单指平移+双指捏合、缩放抑制序列、网格背景） | `InfiniteCanvas.tsx` | 499 行 |
| 桌面层/窗口层/缩放控件 | `DesktopLayer/WindowLayer/ZoomControl/CanvasContext` | 322 行 |
| 工作台布局（三栏/键盘调宽/标签页导航） | `Workbench/*` | 592 行 |
| 布局切换状态机 | `use-layout-switch.ts` | 134 行 |

> 依据 `生态设计原稿/14-编辑引擎设计.md`，无限画布/工作台都是**布局插件**（每种布局是独立插件，用户可安装更多布局插件）。当前布局实现却内置在编辑引擎应用内，并非独立插件包。

## 2. 问题与重复证据

1. **布局插件契约未落地**：设计原稿要求每种布局是独立插件（通过布局宿主装载 `layoutDefinition`），当前 InfiniteCanvas/Workbench 硬编码在应用内，卡箱库的 LayoutTypeGrid 也只是静态展示 `client.box.listLayoutDescriptors`（箱子布局）与本地布局列表——**编辑引擎自身的桌面布局还没有插件化**；
2. **窗口系统无公共形态**：编辑引擎窗口状态机（422 行）与窗口 chrome（1530 行）是「多文档桌面」的通用需求（资源管理器、未来的 IDE 类插件都需要），当前封闭在应用内；
3. **文件类型识别重复**：`drag-drop-manager.detectFileType`（按 MIME+扩展名+chip 特殊扩展名）与 SDK `document.detectType`（仅 .card/.box 后缀）、workspace-service 的目录识别逻辑三者并存，语义不统一；
4. **命令历史悬空且无公共方案**：Host command 域只有注册/调度/状态，无 undo/redo 语义；编辑引擎的 CommandManager 完整但未接入文档操作——这暴露了「文档编辑历史」的生态缺口（卡片/箱子文档操作的可回滚性，未来任何编辑器都需要）；
5. **工作区语义半公共**：Host 有 workspace 概念（config.workspace.json 等），但「工作区文件树扫描、卡片/箱子识别、创建重命名删除」没有服务动作，编辑引擎自实现，社区客户端/文件浏览器无法复用。

## 3. 上移方案（已按用户 2026-08-11 决策定案）

> 决策：**取消「无限画布/工作台作为独立布局插件」的设计**（该方向不再推进）；画布、工作台、窗口系统、拖拽系统、文件树等 UI/交互能力**全部保留在编辑引擎页面域，不迁移**。本领域本次只迁移「系统语义」类能力：文件类型识别、工作区扫描、文档历史。

### 3.1 保留在编辑引擎页面域（不迁移，本次不动）

| 能力 | 说明 |
|---|---|
| 无限画布（平移/缩放/滚轮/触摸代理/网格） | `InfiniteCanvas/*` 保留 |
| 工作台布局（三栏/键盘调宽/标签页） | `Workbench/*` 保留 |
| 窗口生命周期状态机 + 窗口 chrome | `window-manager.ts` + `*Window*` 保留 |
| 拖拽系统（状态机/排序列表/幽灵/指示线） | `DragDrop/*` 保留 |
| 文件树 UI、卡箱库、Dock、历史面板 UI | `FileManager/CardBoxLibrary/Dock/HistoryPanel` 保留 |
| 布局切换状态机 | `use-layout-switch.ts` 保留 |

> 原「布局插件化」「窗口系统进共享层」等建议随布局插件设计一并取消，不再执行。

### 3.2 文件类型识别统一（本次迁移）

将 `drag-drop-manager.detectFileType` 的完整语义（文档类型 + MIME + 扩展名 + chip/box 特殊扩展名）上移为公共能力：

| 归属 | 说明 |
|---|---|
| Host 服务动作（如 `file.detectType` 或 `document.detectType` 增强） | 提供结构化识别结果（documentType/mimeType/category） |
| SDK `document.detectType` 同步增强 | 替换当前仅按后缀判断的弱实现，语义与 Host 一致 |
| 编辑引擎 | `drag-drop-manager` 与 `workspace-service` 消费公共识别结果，删除本地 MIME 表 |

### 3.3 工作区扫描与文件操作进 Host（本次迁移）

| 建议动作 | 职责 | 对应编辑引擎代码 |
|---|---|---|
| `workspace.scan` | 递归扫描工作区，识别卡片目录（`.card/`）、`.card`/`.box` 文件、文件夹，返回结构化树（含 metadata 摘要、排除 Host 运行时目录） | `workspace-service.buildTree` 全流程 |
| `workspace.createCard` | 创建卡片（复用卡片域 `card.init`）并登记到树 | `workspace-service.createCard` |
| `workspace.createBox` / `createFolder` | 创建箱子/文件夹 | 同名方法 |
| `workspace.rename` / `delete` | 重命名（卡片/箱子走文档级改名：改写 metadata + 重打包）、删除 | `renameFile/deleteFile` |

- 编辑引擎 `workspace-service.ts` 收缩为「订阅 Host 扫描结果 + 本地视图缓存」，不再拼 YAML 写 metadata.yaml（消除重复实现证据 #3 的第三份副本）。

### 3.4 文档历史（undo/redo）闭环进 Host 会话服务（本次迁移）

- undo/redo 作为**卡片/箱子文档会话服务的公共语义**（见 03/04 篇）：Host 会话记录操作历史（每个 `session.update*` 动作入栈），提供 `session.undo / session.redo / session.history` 动作与事件；
- 历史语义（合并窗口、历史上限、跳转、栈溢出策略）以编辑引擎 `command-manager.ts`（291 行）为输入基线，由 Host 会话服务统一实现；
- 编辑引擎 `command-manager.ts` 迁移后删除本地实现，历史面板改为消费 `client.card.session.history` / `client.box.session.history` 事件；
- 卡片与箱子文档的每次变更操作**全部接入历史栈**（当前悬空状态闭环）。

### 3.5 收益

- 文件类型识别、工作区扫描、文档历史成为公共语义，查看器/社区/资源管理器直接复用；
- 命令历史从「悬空状态」落地为真实能力；
- 编辑引擎本地实现的系统语义部分（约 1200 行）迁移完毕，剩余全部为页面域 UI。

### 3.6 边界与风险

- 工作区扫描需要冻结「Host 运行时目录排除清单」（当前硬编码 HOST_RUNTIME_ROOT_ENTRIES）与「卡片目录识别规则」为公共契约；
- undo/redo 入栈范围需要冻结：哪些 `session.update*` 可撤销、合并窗口时长、跨卡片操作的语义；
- 迁移时保持 `tests/unit/workspace-service`、`drag-drop` 相关测试全部回归。
