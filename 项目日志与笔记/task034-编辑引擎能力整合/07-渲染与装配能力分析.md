# 07-渲染与装配能力分析

## 1. 现状

编辑引擎的渲染装配分两层：**Host 托管链路**（正式渲染，供查看等场景）与**应用内本地运行时**（编辑态预览，编辑引擎专属）。

### 1.1 Host 托管链路（已公共化）

Host `card-service`（2717 行）已完整实现：

- `card.render`：生成复合卡片渲染文档（basecard iframe 文档、交互代理脚本、主题 CSS 注入、高度上报脚本、CSP 约束）；
- `card.renderCover` / `card.renderEditor`：封面与编辑器文档生成；
- SDK `card.compositeWindow.render / coverFrame.render / editorPanel.render` 全套事件订阅（onReady/onResize/onInteraction/onNodeSelect/onResourceOpen/onNodeError/onFatalError）；
- 编辑引擎当前**不使用** Host 的 compositeWindow/editorPanel 作为编辑主链路（`生态设计原稿/19-SDK与协议.md` 明确：官方编辑引擎改为应用内本地基础卡片运行时）。

### 1.2 应用内本地运行时（编辑引擎自实现）

| 能力 | 位置 | 规模 | 说明 |
|---|---|---|---|
| 基础卡片注册表 | `src/basecard-runtime/registry.ts` | 234 行 | 内置描述符 + `plugin.query({type:'card'})` 装载已安装插件入口，别名/校验 |
| iframe 帧宿主 | `frame-host.tsx` | 596 行 | srcdoc 文档、透明背景、高度测量、blob URL 缓存（待导入资源）、选中事件、滚轮/触摸代理、错误态 |
| 复合装配 | `CompositeCardAssembler.tsx` | 187 行 | 按 structure 顺序装配单卡 iframe、gap/padding、状态聚合 |
| 本地主题 CSS | `theme-css.ts` | 60 行 | 固定苹果色值注入（task030 后不读 Host 主题） |
| 描述符本体 | `registrations/*.ts` | 各 4 行 | re-export Chips-BaseCardPlugin（外仓） |

## 2. 问题与重复证据

1. **两套「单卡 iframe 文档 + 高度上报 + 交互代理」实现**：
   - Host `card-service.ts` `createBasecardFrameDocument`（约 200 行模板字符串：CSP、高度上报、wheel/touch 代理脚本）；
   - 编辑引擎 `frame-host.tsx`（srcdoc + 测量 + wheel 代理）。
   两者语义相同（内容驱动高度、delegate 交互代理、资源 URL 注入），但实现完全独立，已在多处出现行为漂移风险（如工单 143「编辑引擎网页包预览绕过 chips-render 资源协议」、工单 136 封面切换动画时序）；
2. **基础卡片注册表装载逻辑**（registry.ts）与 Host 插件运行时重复：Host 已持有插件安装路径与 entry，编辑引擎再次用 file:// 动态 import 装载插件入口——装载策略（校验、失败隔离、版本）应属 Host；
3. **「编辑态预览」与「正式查看」的渲染差异**是当前架构的刻意设计（编辑态需要选中/编辑交互），但**单卡渲染文档的生成器**（CSP/高度/代理/资源基址）是通用能力，两处重复没有必要；
4. 主题 CSS：task030 决策后主题系统废弃，编辑引擎本地固定苹果色值属于既定现状（不作为上移候选，但 Host 侧 `createBasecardThemeCss` 仍保留主题变量注入——两处样式语义不一致，编辑态与查看态视觉可能漂移）。

## 3. 上移方案（已按用户 2026-08-11 决策定案：收敛程度 1）

> 决策：**保留编辑引擎本地装配层**（CompositeCardAssembler、编辑态选中/拖拽交互），但**单卡 iframe 文档生成（CSP/资源基址/高度上报/交互代理）统一由 Host 提供**，消灭双份实现。

### 3.1 单卡 iframe 文档生成器收敛到 Host（本次迁移落地项）

将 Host `card-service.ts` 中的单卡帧文档生成（CSP/高度上报/交互代理脚本/资源基址注入）作为**正式公共生成器**，导出为 Host 内部可复用模块（如 `chips-host/card-frame` 包或 `card-service` 新导出）：

- 编辑引擎 `BasecardFrameHost` 改为消费同一生成器产出的**文档与脚本**，本地不再维护 frame 文档模板、高度上报脚本、滚轮/触摸代理脚本；
- 目标：编辑态与查看态的单卡渲染协议**同一实现**，只在装配层（是否选中态、是否屏蔽指针）做差异；
- 收敛后编辑引擎帧宿主保留：iframe 挂载、srcdoc 填入 Host 生成文档、高度事件接收、选中/交互事件转发、资源 URL 缓存——**协议语义与 Host 链路完全一致**；
- 迁移时保持 `tests/unit/basecard-frame-host.test.tsx` 全部回归。

### 3.2 基础卡片描述符装载进 Host

- Host 提供基础卡片描述符的**解析与装载动作**（`card.listBasecardDescriptors` 或经 `plugin` 域增强），输出统一描述符视图（cardType/aliases/icon/displayName/校验状态），应用不再用 file:// import 插件入口；
- 编辑引擎 `registry.ts` 收敛为「订阅 Host 描述符列表 + 本地缓存视图」，别名归一、权限校验（capabilities 包含 cardType）由 Host 保证。

### 3.3 复合装配与帧宿主

- 复合装配（CompositeCardAssembler）属于**编辑态语义，保留在编辑引擎页面域**（用户决策，不迁移到共享组件层）；
- 其中高度测量统一复用 Host 生成器产出的协议消息（`chips.basecard:height`），编辑引擎不再维护第二套本地测量语义。

### 3.4 收益

- 消除单卡渲染文档/代理脚本双份实现，杜绝行为漂移（工单 136/143 类问题）；
- 基础卡片插件清单成为公共能力，第三方软件可渲染/编辑同一套卡片；
- 为未来「编辑态预览整体收敛到 Host 渲染链路」（程度 2，远期）预留接口。

### 3.5 边界与风险

- 编辑态交互（选中、插入指示、拖拽插入）不能因收敛而退化——Host 生成器需支持「编辑模式」参数（现有 `mode: preview` 语义与装配层差异要冻结清楚）；
- 不改变「编辑引擎编辑态预览不再使用 compositeWindow/editorPanel 主链路」的既定决策，只统一底层单卡协议；
- Host 生成器导出后，Host 自身 `card.render` 与编辑引擎必须消费同一函数，禁止再次分叉。
