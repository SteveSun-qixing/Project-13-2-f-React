# 10-开发迁移方案（实施指导手册）

> 本方案依据 2026-08-11 用户决策定案（见 [00-总览与结论.md](./00-总览与结论.md) §3.5 决策记录），
> 是 M1-M8 各阶段实施时的详细指导。配套证据与分析见 01-08 篇。

## 1. 方案目标

1. 将编辑引擎的**文档领域能力**（卡片会话、箱子会话、编辑器资源、封面生成、公共工具）工程化上移到 Host，成为生态公共能力；
2. undo/redo 历史栈闭环为 Host 会话服务的公共语义；
3. 编辑态预览收敛程度 1：单卡 iframe 文档生成统一由 Host 提供，编辑引擎保留本地装配层；
4. 迁移全程按平台级/系统级规范进行：小模块拆分、解耦、契约化、高质量实现；
5. 编辑引擎最终形态为「页面域瘦壳」：只保留 UI 编排，全部业务经 SDK 消费 Host 能力。

## 2. 目标架构总览

```text
┌─ 编辑引擎（页面域）─────────────────────────────────────────────┐
│ 工作区UI │ 卡片窗口 │ 箱子窗口 │ 编辑面板 │ 封面UI │ 画布/窗口/拖拽 │
└──────────────┬───────────────────────┬──────────────────────────┘
               │ SDK（chips-sdk）      │
┌──────────────▼───────────────────────▼──────────────────────────┐
│ Host 主进程（L2-L3 服务域）                                      │
│  card.session.*（编辑会话+自动保存+历史）  box.session.*（同左）  │
│  resource.importArchive / 会话资源协议    workspace.scan 等       │
│  card.listBasecardDescriptors / 单卡帧生成器（内部模块）          │
│  公共工具：MIME/路径/ID/fileURL/detectType                      │
├─ 共享功能模块（模块插件）                                        │
│  chips.module.cover（封面生成/比例/引用收集）                     │
└──────────────────────────────────────────────────────────────────┘
```

## 3. 模块拆分设计（工程化核心）

### 3.1 卡片编辑会话服务（Host packages/card-service 扩展）

**模块结构**（每模块独立文件、单一职责）：

| 模块文件 | 职责 | 迁入来源 |
|---|---|---|
| `session/types.ts` | 会话快照、dirty/revision、资源操作类型 | card-service.ts 类型 |
| `session/constants.ts` | 动作名、错误码（CARD_SESSION_*）、事件名 | 新建 |
| `session/session-store.ts` | 会话注册表、生命周期、快照克隆 | card-service.ts 状态部分 |
| `session/document-codec.ts` | metadata/structure/content YAML 解析与序列化 | card-service.ts 解析/持久化部分 |
| `session/resource-lifecycle.ts` | 待导入/待删除队列、引用收集（collectResourcePaths 经描述符）、孤儿回收 | card-service.ts 资源部分 |
| `session/cover-reconcile.ts` | 封面引用收集与清理、空目录剪枝 | card-service.ts reconcile 部分 |
| `session/autosave.ts` | 防抖调度、revision 并发合并、失败保留 dirty | card-service.ts runPersistLoop |
| `session/history.ts` | undo/redo 栈、合并窗口、上限、跳转 | command-manager.ts |
| `session/service.ts` | 动作注册与实现编排 | 新建 |
| `init/initializer.ts` | 卡片骨架初始化 | card-initializer.ts |

**动作契约**（草案，最终以契约文档为准）：

| 动作 | 输入要点 | 输出 | 权限 | 幂等 |
|---|---|---|---|---|
| `card.init` | name、初始基础卡片、parentPath | cardDir、sessionId | card.write | 否 |
| `card.session.open` | cardDir（解包目录） | sessionId、snapshot | card.write | 否（同目录重复开返回同会话） |
| `card.session.get` | sessionId | snapshot | card.read | 是 |
| `card.session.updateBasicCard` | basicCardId、data、resourceOperations | snapshot | card.write | 否 |
| `card.session.addBasicCard` / `removeBasicCard` / `moveBasicCard` | 类型/位置 | snapshot | card.write | 否 |
| `card.session.updateMetadata` | 字段 patch | snapshot | card.write | 否 |
| `card.session.updateCover` | html、ratio、resources | snapshot | card.write | 否 |
| `card.session.persist` | sessionId | snapshot、manifest | card.write | 是（按 revision 判定） |
| `card.session.undo` / `redo` | sessionId | snapshot | card.write | 否 |
| `card.session.history` | sessionId | 历史栈视图 | card.read | 是 |
| `card.session.close` | sessionId | ack | card.write | 否 |

**自动保存职责**：Host 持有每个会话的自动保存调度器（防抖窗口、revision 并发合并），应用只订阅事件：
`card.session.opened / updated / dirty / persisted / persist-error / closed`。

**undo/redo 闭环规则**：
- 入栈范围：updateBasicCard / addBasicCard / removeBasicCard / moveBasicCard / updateMetadata / updateCover（含资源操作）；persist/undo/redo 本身不入栈；
- 合并窗口：同一基础卡片 500ms 内连续更新合并为一步（基线：command-manager 合并设计）；
- 历史上限：默认 100 步，可配置；
- undo 语义：恢复上一状态快照（含资源操作反推），redo 同理；资源导入/删除随状态回滚（物理文件在 persist 时按引用关系处理）。

### 3.2 箱子编辑会话服务（Host packages/box-service 扩展）

**模块结构**：

| 模块文件 | 职责 | 迁入来源 |
|---|---|---|
| `session/types.ts` / `constants.ts` | 会话快照、错误码（BOX_SESSION_*） | box-document-service.ts |
| `session/session-store.ts` | 会话注册表、工作目录托管（Host 临时目录）、open/close | 同上 |
| `session/document-codec.ts` | metadata/content/structure/cover 序列化（与 box-service 解析端共用模型） | serialize* 系列 |
| `session/entry-manager.ts` | 条目增删/排序键重建/摘要生成/内嵌卡片 | addEntry 等 |
| `session/asset-manager.ts` | 资源导入/删除/引用清理 | importBoxAsset/deleteBoxAsset |
| `session/autosave.ts` | 180ms 防抖 + 串行化保存 + 重打包 | flushAutoSave |
| `session/history.ts` | undo/redo（与卡片域共用历史模块） | 复用 |
| `session/service.ts` | 动作注册与实现编排 | 新建 |

**动作契约**（草案）：

| 动作 | 输入要点 | 输出 | 权限 | 幂等 |
|---|---|---|---|---|
| `box.create` | name、layoutType、parentPath | boxFile、metadata | box.write | 否 |
| `box.rename` | boxFile、newName | boxFile、metadata | box.write | 否 |
| `box.session.open` | boxFile | sessionId、snapshot | box.write | 否 |
| `box.session.get` | sessionId | snapshot | box.read | 是 |
| `box.session.addEntry` | url 或 filePath（file 模式服务端生成摘要） | snapshot | box.write | 否 |
| `box.session.addEmbeddedCard` | cardFile、preferredName | snapshot | box.write | 否（接口开放，官方编辑引擎不调用） |
| `box.session.updateEntry` / `moveEntry` / `removeEntry` | 条目操作 | snapshot | box.write | 否 |
| `box.session.updateLayoutConfig` | layoutType、config | snapshot | box.write | 否 |
| `box.session.importAsset` / `deleteAsset` | 资源操作 | snapshot | box.write | 否 |
| `box.session.updateCover` | html、ratio、resources | snapshot | box.write | 否 |
| `box.session.persist` | sessionId | snapshot | box.write | 是 |
| `box.session.undo` / `redo` / `history` | sessionId | snapshot/视图 | box.write/read | — |
| `box.session.close` | sessionId | ack（Host 清理工作目录） | box.write | 否 |

**要点**：
- 会话工作目录由 Host 在系统临时区分配与回收（替代编辑引擎 `.chips-editing-engine/box-sessions/` 应用私有路径）；
- 序列化与 box-service 解析端**共用同一模型**（新增 `document-codec` 双向模块），杜绝口径漂移（关联工单 127/128）；
- 内嵌卡片：动作开放但官方编辑引擎不提供入口（决策 6）。

### 3.3 编辑器资源会话与导入（Host 服务域）

**模块结构**：

| 模块文件 | 职责 | 迁入来源 |
|---|---|---|
| `import/archive-import.ts` | ZIP 目录导入全流程（根探测/过滤/魔数/清理/回滚） | archive-import.ts（592 行整体迁入，测试同步迁移） |
| `import/types.ts` / `constants.ts` | 输入输出类型（与 SDK CardEditorArchiveImportRequest/Result 对齐）、错误码（IMPORT_*） | SDK card.ts 契约 |
| `session/editor-session.ts` | 编辑器资源会话（草稿/校验/dirty/资源队列/转换编排） | EditorHost 会话部分 + session-store.ts |

**动作契约**（草案）：

| 动作 | 输入要点 | 输出 | 权限 | 幂等 |
|---|---|---|---|---|
| `resource.importArchive` | zipFile、targetRoot、include 过滤、entryFile、stripSingleRootDir、excludeSystemArtifacts | rootDir、entryFile、resourcePaths、entries、discardedEntries | file.write + resource.read | 否 |
| `editor.session.open` / `get` / `update` / `persist` / `close` | 编辑器会话（草稿配置、资源操作队列） | 会话快照 | card.write | 否 |
| 编辑器资源协议动作 | resolve/import/delete/convertTiffToPng/extractVideoThumbnail 的会话编排 | 同 SDK CardEditorResourceBridge 语义 | card.write | — |

**要点**：
- `resource.importArchive` 与 `zip.extract` 的语义差异必须冻结：extract 是原语（解到指定目录）；importArchive 是业务语义（根探测/过滤/清理/回滚）；
- 大文件导入进度走 module.job 任务模型（progress 事件）；
- blob URL 缓存语义由 Host 会话管理，编辑引擎 EditorHost 收敛为「消息分发 + 状态订阅」薄层；
- 编辑器资源桥：SDK `editorPanel.render({ resources })` 的本地桥保留为兼容形态或直接切换为 Host 会话动作（无其他消费者时一步收口）。

## 4. 实施步骤（分阶段详细计划）

### M1 公共工具收口

1. Host `src/shared` 新增 `mime.ts`、`path.ts`（规范化）、`id.ts`（现有 createId 保留，编辑引擎迁移调用）；
2. SDK 新增 `src/utils` 工具（file URL、路径规范化），替换 SDK card.ts 内部私有实现；
3. Host 新增 `file.detectType` 动作（结构化识别：documentType/mimeType/category），SDK `document.detectType` 改为消费 Host 或与 Host 同语义；
4. 编辑引擎全局替换：`guessMimeType`/`normalizeResourcePath`/`generateId62`/`createFileUrl` 改走公共实现；`drag-drop-manager` 文件识别改走 `client.file.detectType`；
5. 测试：Host shared 契约测试 + SDK 单测 + 编辑引擎回归。

### M2 卡片编辑会话上移

1. Host card-service 按 §3.1 拆分模块并实现动作；
2. 自动保存调度器 + 历史模块（复用 command-manager 语义）落地；
3. SDK `src/api/card.ts` 新增 `session` API 封装与事件订阅（onDirty/onPersisted/onUndo/onRedo）；
4. 编辑引擎改造：
   - `card-service.ts` 整体替换为 `client.card.session.*` 消费层（状态快照映射回 CompositeCard 视图）；
   - `card-initializer.ts` 改走 `card.init`；
   - 历史面板改消费 `client.card.session.history`；
   - 原 card-service 测试迁移为 Host 会话契约测试 + 编辑引擎会话消费测试；
5. 权限/文档同步：manifest 增加对应权限；`06-Chips-Host对外接口基线.md` 更新。

### M3 箱子编辑会话上移

1. Host box-service 按 §3.2 拆分模块并实现动作（document-codec 双向模型先行）；
2. SDK box.ts 新增 `session` API 与事件订阅；
3. 编辑引擎改造：`box-document-service.ts` 替换为 `client.box.session.*` 消费层；`useBoxDocumentSession` 改订阅事件；
4. 测试迁移与回归；manifest 权限更新。

### M4 编辑器资源会话与导入上移

1. Host 按 §3.3 落地 `resource.importArchive` 与编辑器会话动作（archive-import.ts 整体迁入，测试同步）；
2. SDK card.ts/box.ts 资源桥动作与 importArchive 封装对齐新契约；
3. 编辑引擎：EditorHost 瘦身为会话消费层（消息分发 + 订阅）；archive-import.ts 删除；
4. 大文件进度事件接入 module.job。

### M5 封面能力共享模块

1. 新建 chips.module.cover 插件包（含 manifest、module 能力声明、实现、SDK 封装建议）；
2. Host renderCover 兜底与 card/box 封面 reconcile 改消费模块；
3. 编辑引擎 CoverPanel/CoverMaker 改走 `client.module.invoke('cover', ...)`；
4. 删除编辑引擎 `utils/card-cover.ts` 中的生成/规范化本地实现（UI 适配保留）。

### M6 工作区与描述符上移

1. Host 新增 `workspace.scan/createCard/createBox/createFolder/rename/delete` 动作；
2. Host 新增 `card.listBasecardDescriptors`（描述符装载与校验）；
3. 编辑引擎 `workspace-service.ts` 改消费 workspace 动作（删除本地 YAML 改写）；`registry.ts` 改订阅描述符列表；
4. 冻结工作区契约（排除清单、识别规则）。

### M7 渲染单卡协议收敛（程度 1）

1. Host card-service 将单卡帧文档生成（CSP/高度/交互代理/资源基址）抽取为公共导出（`chips-host/card-frame` 或 card-service 导出）；
2. 编辑引擎 `frame-host.tsx` 改消费 Host 生成文档与协议（保留装配/事件转发/资源缓存壳）；
3. 冻结 `chips.basecard:*` 协议（消息名/载荷/CSP 基线）；
4. 双份 wheel/touch 代理脚本与高度上报脚本统一；frame-host 测试回归。

### M8 收尾

1. 全生态文档同步（生态共用技术文档：服务协议标准、Host 对外接口基线、文件格式协议、SDK 文档、编辑引擎技术文档 01）；
2. 编辑引擎技术文档更新（vNext 架构说明同步新服务面）；
3. 旧实现归档（`归档/` 目录，禁止删除）；
4. 全量验证：各仓 `validate/build/test/lint`；编辑引擎真实素材回归（real-materials-regression）；
5. 无残留 TODO、无旁路实现检查。

## 7. 风险与回退

| 风险 | 缓解 | 回退 |
|---|---|---|
| 会话模型契约冻结不充分导致应用行为变化 | 先冻结契约再迁移；自动保存语义与现状逐条对齐（防抖窗口/revision 语义） | 保留旧 service 文件至 M8 验收后才归档 |
| 序列化口径变化导致存量文件不可读 | document-codec 双向模型先行，读端兼容（如 3/4 与 3:4）；真实素材回归把关 | 兼容读、统一写 |
| 大 ZIP 导入主进程阻塞 | module.job 任务模型 + 进度事件；超时与取消支持 | 导入动作不落同步路径 |
| 编辑器资源桥双轨期行为不一致 | M4 一步收口（SDK 桥仅剩兼容形态，无其他消费者） | 保留 SDK 桥直至会话动作稳定 |
| 渲染协议收敛后编辑态交互退化 | 冻结协议时保留「编辑模式」参数；frame-host 测试全量回归 | 单卡生成器可加装配参数，不回流双实现 |

## 8. 验收标准（完成定义）

1. 编辑引擎删除的本地实现文件全部在 `归档/`，无直接删除；
