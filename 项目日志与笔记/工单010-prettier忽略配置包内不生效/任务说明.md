# 工单 010：包目录内 prettier 不加载根 `.prettierignore` 导致生成物被误检的工具链配置缺口

> 登记：W1-SYNC（2026-09-20）
> 状态：待处理（已实施暂行处理，配置缺口未收口）
> 类型：工具链与文档漂移 / 单一事实源缺口
> 影响：`chips-ecosystem` 全工作区 `lint` 门禁（根、各包、CI、新人环境）与格式化判定面

---

## 一、背景

工作区的格式检查存在两种执行语境：

- **仓库根**：`chips-ecosystem/package.json:25` 的 `lint` 为
  `eslint . && prettier --check . && cargo fmt --all -- --check && cargo clippy ...`，
  此时 prettier 以仓库根为 cwd，能加载根 `.prettierignore`；
- **各包目录**：`pnpm -r --if-present run lint` 会进入每个包的目录执行其 `lint` 脚本
  （`packages/antd`、`packages/host`、`packages/ui`、`tests/e2e`、`tests/perf` 等均含
  `prettier --check .`）。prettier 只加载与 **当前工作目录** 最近的忽略文件，
  不向上查找仓库根 `.prettierignore`。

包目录内构建（`dist/`）、覆盖率（`coverage/`）、压测报告（`reports/`）等生成物一旦落盘，
就会被纳入格式检查面并被判定为不合规，使 `lint` 在完全正常的代码状态下红灯。
W1 波次实测（2026-09-19）曾出现 `packages/host` 在 `dist` 重建后 161 个生成文件被误检。

暂行处理是把根忽略文件显式传给包内脚本（`--ignore-path ../../.prettierignore`），
该写法已在 5 个包脚本中各自重复一份，忽略规则从此分散在「根文件 + 包内文件 + 脚本参数」三处，
属单一事实源缺口，需裁决收口方式（本工单不给修法）。

## 二、证据

以下均为 2026-09-20 现场复测结果（工作目录 `chips-ecosystem/`）。

### 2.1 包目录内 `prettier --check .` 误检生成物（不带 `--ignore-path`）

| 命令 | 结果 |
|---|---|
| `cd packages/host && npx prettier --check .` | `Code style issues found in 161 files.`（`dist/types` 61、`dist/{main,preload,renderer}` 4、`coverage/**` 96，全部为生成物，无一个 `src/` 文件） |
| `cd packages/host && npx prettier --check --ignore-path ../../.prettierignore .` | `All matched files use Prettier code style!` |
| `cd packages/ui && npx prettier --check .` | `Code style issues found in 234 files.`（`dist/components` 52、`dist/{command,theme,tokens,utils,base,index.js,index.d.ts}` 40、`coverage/**` 142，全部为生成物） |
| `cd packages/ui && npx prettier --check --ignore-path ../../.prettierignore .` | `All matched files use Prettier code style!` |

生成物规模（现场统计）：`packages/host/dist` 79 文件、`packages/host/coverage` 101 文件、
`packages/ui/dist` 185 文件。W1 波次同期记录见
`chips-ecosystem/packages/host/开发日志.md:105-108`（“实测 161 个文件报未格式化”）与
`:126-130`（根因 + 暂行处理）；`chips-ecosystem/packages/ui/开发日志.md:115-118`
（同型问题，当时记为 `dist/` 92 个产物文件）。

### 2.2 根忽略规则齐备，但在包内不生效

`chips-ecosystem/.prettierignore`（13 行）已覆盖全部生成物面：
`node_modules/`、`dist/`、`target/`、`coverage/`、`release/`、`reports/`、`test-results/`、
`playwright-report/`、`fixtures/`、`*.node`、`*.cpk`、`pnpm-lock.yaml`、`**/归档/**`。
2.1 的实测证明该文件在包 cwd 下不被加载。

### 2.3 暂行处理分散在多个包脚本（`--ignore-path ../../.prettierignore`）

| 文件:行 | `lint` 脚本 |
|---|---|
| `packages/antd/package.json:25` | `eslint . && prettier --check --ignore-path ../../.prettierignore .` |
| `packages/host/package.json:18` | `eslint . && prettier --check --ignore-path ../../.prettierignore .` |
| `packages/ui/package.json:28` | `eslint . && prettier --check --ignore-path ../../.prettierignore .` |
| `tests/e2e/package.json:12` | `eslint . --config ../../eslint.config.mjs --max-warnings 0 && prettier --check --ignore-path ../../.prettierignore .` |
| `tests/perf/package.json:12` | `eslint . --max-warnings 0 && prettier --check --ignore-path ../../.prettierignore .` |

相对路径层级（`../../`）与包在工作区中的深度写死绑定；新增嵌套包（如 `plugins/*/*`、`tools/*`）
时该参数不可直接复用，属易漏项。

同轮补齐的其它忽略面（同为分散配置的组成部分）：根 `.prettierignore` 与
`chips-ecosystem/eslint.config.mjs:69` 各新增一条 `**/归档/**` 忽略（归档目录现存在 4 处：
仓库根 `归档/`、`packages/host/归档`、`tests/perf/归档`、`tools/scaffold/归档`）。

### 2.4 忽略面已存在三口径并存、互不相同

- 根 `.prettierignore`（13 项，含 `**/归档/**`、`reports/`）；
- `packages/antd/.prettierignore`（4 项：`dist/`、`coverage/`、`patches/`、`node_modules/`，
  **无** `**/归档/**`、**无** `reports/`）——该包在不带 `--ignore-path` 时正是靠它通过（2.1 对照实测：
  `cd packages/antd && npx prettier --check .` → `All matched files use Prettier code style!`）；
- `tests/e2e/.prettierignore`（`node_modules/`、`test-results/`、`playwright-report/`、
  `fixtures/cards/`、`fixtures/boxes/`）；
- 脚本参数 `--ignore-path ../../.prettierignore`（2.3）。
- 反例：`packages/sdk/package.json:30` 的 `lint` 只有 `eslint .`，完全没有 prettier 判定面，
  与工作区其它包不同口径。

### 2.5 `tests/perf` 的 `reports/` 产物堆积在忽略体系之外

- `tests/perf/reports/` 现有 180 个生成文件（`*-cold-start.{json,md}`、`*-open-card.*` 等，
  带时间戳持续堆积），仅被 `tests/perf/.gitignore:2`（`reports/`）挡在版本控制之外；
- 该包无包内 `.prettierignore`，`cd tests/perf && npx prettier --check reports` 与
  `npx prettier --check .` 当前均为 `All matched files use Prettier code style!` ——
  即产物 **仍在格式判定面内**，今天不红灯只是因为生成器输出恰好符合 prettier 风格，
  一旦生成器或 prettier 版本变更即回归为误检；只有依赖 `--ignore-path`（2.3）时根文件的
  `reports/` 规则才生效。

### 2.6 文档口径与实际可执行口径不一致

- `薯片生态文档库/02-开发规范/01.08-01-代码组织规范-八、常用脚本约定.md:42` 给出的 `lint` 范本为
  `eslint . && prettier --check . && cargo fmt ...`，未区分执行语境，也未规定包内如何加载忽略文件
  （按 2.1 实测，该写法在包目录内必然误检生成物）；
- `薯片生态文档库/06-开发与运维/05.02-05-CICD与质量门禁-二、CI 流程.md:78` 的 CI 步骤为
  `pnpm exec eslint . && pnpm exec prettier --check .`，只在仓库根语境成立，CI 定义里
  没有 `pnpm -r run lint`（包内语境）这一层的忽略面处理；
- `薯片生态文档库/02-开发规范/02.12-02-TypeScript编码规范-十二、Prettier 配置.md:10-26`
  只规定 `.prettierrc` 内容，全篇未出现 `.prettierignore`，忽略规则在生态公共文档里没有权威条目。

## 三、影响范围

1. **门禁可信度**：`pnpm -r --if-present run lint` 的红绿不再只反映源码格式，
   而取决于“是否先跑过 build / coverage / bench”，同一份代码可给出两种结论；
2. **CI 与新人环境漂移**：忽略规则的正确性依赖 5 处脚本参数与 3 份互不相同的忽略文件；
   新克隆仓库、新加入的包或嵌套层级的包，以及按 2.6 文档范本手写的脚本，都会在首次 build 后红灯；
3. **单一事实源缺口**：`dist/coverage/reports/test-results/fixtures/归档` 等生成物面本应一处定义，
   现为“根文件 + 包内文件 + 相对路径参数”三处，任一处更新（如本轮新增 `**/归档/**`）都需人工同步；
4. **判定面污染**：`tests/perf/reports/`、各包 `dist/`、`coverage/` 在包内语境下属于 prettier 判定对象
   （2.1、2.5），格式化统计与差异报告混入生成物噪声；
5. **口径不齐**：`packages/sdk` 无 prettier 面（2.4），`tests/perf` 仍是 ESLint 8 旧栈
   （`chips-ecosystem/开发日志.md` 遗留条目），包级 `lint` 之间不可横向比较；
6. 本缺口不改变任何对外协议与运行时行为，属工程配置面。

## 四、复现步骤

1. `cd chips-ecosystem && pnpm install`；
2. `pnpm --filter @chips/host build && pnpm --filter @chips/ui build`（生成 `dist/`），
   再 `pnpm --filter @chips/ui test:coverage`（生成 `coverage/`）；
3. 观察暂行处理后的现状：`pnpm -r --if-present run lint` 退出码 0（2.3 的脚本参数生效）；
4. 去掉包内脚本参数复现缺口：
   `cd packages/host && npx prettier --check .` → `Code style issues found in 161 files.`；
   `cd packages/ui && npx prettier --check .` → `Code style issues found in 234 files.`
   （两次的 `--ignore-path ../../.prettierignore` 版本均为 `All matched files use Prettier code style!`）；
5. 验证忽略文件加载语境：`cd chips-ecosystem && npx prettier --check .` 在根目录一次通过
   （根 `.prettierignore` 生效），包目录内同样命令则不生效；
6. 验证 `reports/` 堆积面：`cd tests/perf && npx prettier --check reports`（180 个生成文件在判定面内，
   当前恰好通过）。

   `playwright-report/`、`fixtures/`、`target/`、`release/`、`*.node`、`*.cpk`、`归档/`）
