# 工单 009：前端组件契约文档与 `@chips/ui` 实现口径不一致（`SettingsGroup` / `StateBoundary` 的 `children`）

> 登记：W1-SYNC（2026-09-20）
> 状态：待处理
> 类型：文档与代码不一致（公开契约漂移）
> 影响：《08-@chips-ui共享层使用指南》§2.2 组件 Props 契约 ↔ `packages/ui` 的 `StateBoundary`、`SettingsGroup`；官方应用与第三方插件的编码依据

---

## 一、背景

《08-@chips-ui共享层使用指南》是 `@chips/ui` 的对外唯一使用契约（§2.2 逐组件给出 Props 定义），
官方应用与插件按该文档编码；`packages/ui` 的源码类型定义是实际可执行面。
本轮逐组件核对 §2.2 的 16 个组件接口与 `packages/ui/src/components/**/types.ts`，发现
`StateBoundary`、`SettingsGroup` 两个组件的 `children` 必填性在文档与实现之间相反：
文档声明为必填（`children: ReactNode`），实现声明为可选（`children?: ReactNode`），
且实现另有「省略 `children` 时的规定行为」，文档完全没有登记。

其余带 `children` 的组件（`AppChrome`、`Toolbar`、`LayoutSkeleton`、`SettingsLayout`）经核对口径一致，
本工单只覆盖上述两处的漂移，不预设应以文档还是以实现为准。

## 三、影响范围

1. **契约消费面**：`@chips/ui` 是官方应用与插件的唯一 UI 导入面
   （`chips-ecosystem/packages/ui/src/components/index.ts:13-14` 导出 `SettingsGroup` / `SettingsGroupProps`，
   `:29-30` 导出 `StateBoundary` / `StateBoundaryProps`），文档是唯一对外契约源；
   按错误契约编码后，`typecheck` 与实现之间必然一侧红灯。
2. **能力被契约否定**：`StateBoundary` 的「纯状态占位 + 骨架」、`SettingsGroup` 的「空卡片容器」两种
   已实现、已测的行为，在对外契约里等于不存在；使用方无法据此设计空态与设置分组，或使用时被判定为违约。
3. **禁止事项放大风险**：`薯片生态文档库/02-开发规范/08.06-08-@chips-ui共享层使用指南-六、禁止事项.md:18`
   明令禁止插件内自行复制 `StateBoundary` 等共享组件实现——使用方没有绕开错误契约的合法出路。
4. **示例未覆盖分歧路径**：`薯片生态文档库/02-开发规范/08.07-08-@chips-ui共享层使用指南-七、完整示例.md:180-200`
   的 `StateBoundary` 用法一律带 `children`，示例不能暴露该不一致，也无法作为口径参照。
5. **门禁不拦截**：见 2.5，同类漂移（其它组件、其它 Props）同样可静默累积。
6. 当前工作区内 `packages/host`、`packages/sdk`、`plugins/`、`examples/` 尚无这两个组件的实际调用点
   （全仓检索零命中），故本轮无实现回归，属纯契约口径缺口。
