## Issue Title

`useDelayState` leaks pending timers on unmount — `setTimeout`/raf callbacks fire after component unmount (breaks jsdom test teardown)

## Issue Body（English）

**Package**: `@rc-component/util@1.13.0` (also present in `lib/` build)
**File**: `es/hooks/useDelayState.js` (line 30: `setTimeout` branch; line 32: `raf` branch)

### Problem

`useDelayState` schedules a pending state update via `setTimeout` (or `raf`) and stores the cancel handle in `delayRef` (`delayRef.current = [false, setTimeout(...)]` / `[true, raf(...)]`), exposing `cancelPending`. However, **no cleanup effect ever calls `cancelPending`** — neither on unmount nor on dependency change. When the component unmounts (or the test environment tears down) before the delay elapses, the timer still fires and calls `setValue` on an unmounted component.

This is the same class of bug that `@rc-component/trigger@3.10.1` already fixed in its `useDelay` hook (`es/hooks/useDelay.js` has `React.useEffect(() => () => clearDelay(), [])`).

### Real-world trigger chain (antd 6.6.4)

- `antd/es/form/hooks/useDebounce.js:6-8` → `setCacheValue(value, { ms: value.length ? 0 : 10 })` — every `Form.Item` mount schedules a 10ms timer;
- `antd/es/form/FormItem/ItemHolder.js:44-45`, `es/form/ErrorList.js:43-44`, `es/button/Button.js:130` consume `useDelayState`;
- In jsdom-based test suites (vitest/jsdom), any test that unmounts a form within the 10ms window gets `Uncaught Exception: ReferenceError: window is not defined` **after** test-environment teardown — all assertions pass but the process exits non-zero. Under load this reproduces frequently (we measured ~1 in 9 full-suite runs).

### Suggested fix

Add an unmount cleanup effect, mirroring `@rc-component/trigger`:

```js
React.useEffect(
  () => () => {
    cancelPending();
  },
  [],
);
```

(`lib/` mirror needs the same change.)

### Reproduction

Mount any antd `Form.Item` (antd 6.6.4) in a jsdom test, unmount within 10ms, flush timers after teardown → `ReferenceError: window is not defined` from `useDelayState.js:30`.

### Impact

Affects every consumer mounting antd `Form`/`Button` in jsdom test environments (vitest/jest). Not a runtime functional bug, but produces flaky, hard-to-diagnose CI failures.

## 中文对照（备存）

`useDelayState` 卸载时不调用 `cancelPending`（尽管内部提供了该能力），导致 `setTimeout`/raf 回调在组件卸载后仍触发 `setValue`；antd 6.6.4 的 `Form.Item`（useDebounce 10ms）、`Button`（innerLoading）均走此 hook，jsdom 测试在窗口期内卸载即于环境拆除后抛 `ReferenceError: window is not defined`（用例全过、进程退出码 1，负载下高频复现）。同族 `@rc-component/trigger` 的 `useDelay` 已有卸载清理先例。建议补 `React.useEffect(() => () => cancelPending(), [])`（es/lib 两份）。
