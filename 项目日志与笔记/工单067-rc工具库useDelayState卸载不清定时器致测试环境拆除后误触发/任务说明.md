# 工单067：@rc-component/util `useDelayState` 卸载不清理定时器，测试环境拆除后仍触发（document-library 偶发退出码 1）

> 登记日期：2026-10-01
> 登记来源：W4 迁移·document-library 测试卫生终验（原子任务「teardown 后定时器泄漏修复」）
> 状态：开放·待派单（缺陷在上游第三方包，须用户裁定处置通道）

## 一、背景

`@chips/plugin-document-library` 测试（46/46 全过）偶发被 vitest 记为失败：`Test Files 2 passed`、`Tests 46 passed`，但文末出现 `Errors N errors`（实测一次 5、一次 10），退出码 1。错误为「Uncaught Exception：`ReferenceError: window is not defined`」，且 vitest 明示「This error was caught after test environment was torn down. Make sure to cancel any running tasks before test finishes: cancel timeouts using clearTimeout」。

## 二、根因（证据）

泄漏源不在任何工作区包内，而在上游第三方依赖 `@rc-component/util@1.13.0`：

- 泄漏 hook：`node_modules/.pnpm/@rc-component+util@1.13.0_react-dom@18.3.1_react@18.3.1__react@18.3.1/node_modules/@rc-component/util/es/hooks/useDelayState.js`（`lib/` 同构副本）。
  - 该 hook 提供 `cancelPending`（`raf.cancel` / `clearTimeout`），但**从未在任何卸载 effect 中调用**——卸载/依赖变更后到期的 `setTimeout` 与 raf 无清理，属上游真实代码卫生缺陷。
  - 触发行即报错栈第 30 行：`delayRef.current = [false, setTimeout(() => setValue(nextValue), delayConfig.ms)];`；第 32 行 raf 分支同病。
- 触发链（document-library 渲染路径实测在册）：
  - antd `6.6.4` `es/form/hooks/useDebounce.js:6-8`：`setCacheValue(value, { ms: value.length ? 0 : 10 })` → 每次 `Form.Item` 挂载/值变更都排一个 `setTimeout`（默认 errors 为空数组 → `ms=10`）；
  - antd `es/form/FormItem/ItemHolder.js:44-45`、`es/form/ErrorList.js:43-44` 消费 `useDebounce(errors/warnings)`；`es/button/Button.js:130` 的 `innerLoading` 亦走 `useDelayState`；
  - 本插件 `plugins/layouts/document-library/src/render.tsx` 编辑态渲染 `Form`/`Form.Item`（TreeEditor、FrameRegionFields）与 `Button`，故每个 ItemHolder 挂载即排定时器；组件在 10ms 窗口内卸载或测试文件在窗口内收尾时，回调在 jsdom 环境拆除后触发 `setValue` → react-dom `getCurrentEventPriority` 抛 `ReferenceError: window is not defined`。
- 报错栈原文（2026-10-01 实测）：`Timeout._onTimeout …/@rc-component/util/es/hooks/useDelayState.js:30:51` → `dispatchSetState` → `ReferenceError: window is not defined`。
- 同族反证：`@rc-component/trigger@3.10.1` 的 `es/hooks/useDelay.js` 有 `React.useEffect(() => () => clearDelay(), [])` 卸载清理；`useDelayState` 缺的正是这一段。
- 包内排查结论：本插件 `src/`（main.ts / index.ts / config.ts / render.tsx）grep `setTimeout|requestAnimationFrame|delayRef` 零命中；`@chips/ui` src 仅 `EmbeddedDocumentFrame` 含定时器且已带 `clearTimeout` 清理（`packages/ui/src/components/EmbeddedDocumentFrame/index.tsx:130-135`）。本包无 raf 封装，无包内可修点。

## 三、影响范围

- 全部在测试环境（jsdom + vitest）中挂载 antd `Form`/`Form.Item`/`Button` 的包：document-library 实测中招，其余 W4/W5 内容卡片与设置面同链路同险。
- 症状仅限测试链路「用例全过但进程退出码 1」的偶发假红；生产运行时行为与功能不受影响（定时器回调只是对已卸载组件 `setState`）。
- 负载越高越易复现（末尾 10ms 窗口与测试收尾的时序漂移）。
