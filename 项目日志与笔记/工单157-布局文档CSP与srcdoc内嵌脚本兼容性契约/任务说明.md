# 工单157-布局文档CSP与srcdoc内嵌脚本兼容性契约：任务说明

## 1. 背景

布局插件（grid-BLP 等）的「顶部内容区」按需求（2026-08-11 会话）实现 autoHeight 自适应高度：`@chips/ui` `EmbeddedDocumentFrame` 向 srcdoc 注入 inline 高度上报脚本（postMessage `chips.embedded-frame:height`）。真实运行（Electron）中发现该脚本被布局文档 CSP 阻止，导致顶部照片无法按原图比例显示（容器高度塌陷为固定小区域）。测试环境（jsdom 不执行 CSP）未暴露。

## 2. 证据

- 布局文档 CSP：`script-src 'nonce-...'`（无 inline 允许）；
- 运行时报错：`about:srcdoc:12 Executing inline script violates CSP 'script-src 'nonce-...''`；
- CSP 规范：script-src 同时含 nonce 与 `'unsafe-inline'` 时 `'unsafe-inline'` 被忽略（初次修复无效的根因）；
- 修复：script-src 增加高度上报脚本内容 hash `sha256-p6qnAKKz6lQAhoLtV8hXdLgzG6dHjyK+iL44pLbQ0SM=`（浏览器报错给出），布局查看文档与布局编辑器文档均生效；
- 跨仓一致性测试：`Chips-Host/tests/unit/box-layout-csp.test.ts`（从 @chips/ui 源码提取脚本字面量计算 hash，断言与 Host 常量一致）。

## 3. 影响范围

- Chips-Host box-service 布局文档/布局编辑器文档 CSP；
- @chips/ui EmbeddedDocumentFrame autoHeight 能力（顶部内容区、未来其他 srcdoc 场景）；
- 全部布局插件（grid/list/cardStack 等含顶部区域的布局）；
- 卡片系列文档（单卡帧/复合卡片/编辑器帧）当前不使用 srcdoc 内嵌脚本，不受影响。

## 4. 复现步骤

1. 启动编辑引擎（Electron），创建/打开含顶部照片（topRegion image 模式）的箱子；
2. 观察顶部照片区域高度塌陷（固定小区域，非原图比例）；
3. 打开 DevTools console，可见 CSP 阻止 srcdoc inline 脚本的报错；
4. 修复后（CSP 含脚本 hash）顶部照片按原图比例全尺寸显示。

## 5. 期望行为（已达成 + 契约固化）

- 布局文档 CSP script-src 包含高度上报脚本 hash（常量 `SRCDOC_HEIGHT_REPORT_SCRIPT_SHA256`）；
- 跨仓一致性测试锁定 hash 与 @chips/ui 脚本内容一致（@chips/ui 变更时测试失败提醒同步）；
- 契约已写入 `生态共用技术文档/插件开发/04-布局插件开发.md`（布局文档 CSP 与 srcdoc 内嵌脚本一节）；
- 约束：布局插件不得依赖其他无 nonce 的 inline 脚本；新 srcdoc 内嵌脚本能力需与 Host 协商 hash。

## 6. 远期方向（记录，暂不实施）

- 高度上报脚本改为外部 JS 资源（CSP 用来源白名单而非 hash），从根上解耦 @chips/ui 与 Host CSP——涉及 @chips/ui 改造，改动面大；
- 卡片系列文档若未来引入 srcdoc 内嵌脚本，需复用同一 hash 机制。

## 7. 需要协作方

Chips-Host box-service 维护方、Chips-Ui EmbeddedDocumentFrame 维护方。
