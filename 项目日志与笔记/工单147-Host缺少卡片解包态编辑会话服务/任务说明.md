# 工单147-Host缺少卡片解包态编辑会话服务：任务说明

## 1. 背景

Host `card` 服务域只有打包态/渲染态动作（pack/unpack/parse/readMetadata/readInfo/render/renderCover/renderEditor/validate/open/resolveDocumentPath/resolveResourceUrl/releaseRenderSession），没有「解包态 `.card` 目录的编辑会话、持久化、资源生命周期、自动保存」能力。编辑引擎被迫在应用内完整自实现，任何其他软件无法复用。

## 2. 证据

- `Chips-EditingEngine/src/core/card-service.ts`（1155 行）：卡片内存模型、YAML 序列化（persistCard）、资源清单重建（buildResourceManifest）、封面 reconcile（reconcileCoverResources）、待导入/删除资源队列（finalizeCardResources）、防抖自动保存循环（runPersistLoop）；
- `Chips-EditingEngine/src/core/card-initializer.ts`（96 行）：新建卡片骨架；
- `Chips-Host/src/main/services/register-host-services.ts` card 域动作清单：无编辑会话动作；
- `Chips-SDK/src/api/card.ts`：无解包目录编辑 API；
- 重复实现：MIME 猜测（与 Host card-packer 重复）、路径规范化（与 SDK/Host 重复）、默认封面（与 Host renderCover 兜底不同实现）。

## 3. 影响范围

- Chips-Host card 服务域、Chips-SDK card API、Chips-EditingEngine；
- 未来消费卡片编辑能力的全部软件（查看器、社区客户端、第三方编辑器、移动端）。

## 4. 复现步骤

1. 编辑引擎打开卡片目录编辑并保存，观察全部文档逻辑在应用内执行；
2. 检索 Host/SDK 契约，无「打开解包目录进行编辑」动作；
3. 对比 Host card-service 与编辑引擎 card-service.ts，确认能力双份。

## 5. 期望行为

Host 提供卡片编辑会话动作（契约草案见 `task034-编辑引擎能力整合/10-开发迁移方案.md` §3.1）：

- `card.init`：新建卡片骨架；
- `card.session.open / get / updateBasicCard / addBasicCard / removeBasicCard / moveBasicCard / updateMetadata / updateCover / persist / undo / redo / history / close`；
- 会话与自动保存由 Host 主进程管理，应用只订阅事件（`card.session.opened/updated/dirty/persisted/persist-error/closed`）；
- 编辑引擎 card-service.ts 与 card-initializer.ts 本地实现删除（移入归档），改为纯会话消费层。

## 6. 暂行处理

无。本工单由 task034 迁移任务 M2 直接修复。

## 7. 需要协作方

Chips-Host card-service 维护方、Chips-SDK 维护方、Chips-EditingEngine 维护方。

## 8. 处理结果（2026-08-11，M2 完成）

- Host 落地 `card.init` + 14 个 `card.session.*` 动作（含自动保存、undo/redo、资源生命周期），模块化拆分于 `packages/card-service/src/session/`（types/constants/document-codec/resource-lifecycle/cover-reconcile/autosave/history/service/basecard-adapter/default-cover）；
- SDK 新增 `CardSessionApi` 与 6 个事件订阅，route-manifest 契约同步；
- 编辑引擎 `card-service.ts`（原 1155 行本地实现）重写为会话消费层，`command-manager.ts` 重写为会话历史适配层（undo/redo 闭环）；
- 验证：Host 契约测试 16 用例 + SDK 封装测试 6 用例 + 编辑引擎消费测试 7 用例全部通过；Host/SDK/编辑引擎全量无新增失败；
- 详情见 `task034-编辑引擎能力整合/12-M2实施记录.md`。
