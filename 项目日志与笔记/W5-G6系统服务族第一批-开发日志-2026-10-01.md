## 一、开工勘查结论（码级实读）

1. **PAL 四端口已在册且为 Electron 真实承载**：`platform/mac/dialog-port.ts`（`showOpenDialog`/`showSaveDialog`、
   过滤器点号归一）、`clipboard-port.ts`（读空归一 `null`）、`notification-port.ts`（`isSupported` 分闸 +
   `NOTIFICATION_UNAVAILABLE`/`NOTIFICATION_FAILED` 两码）、`shell-open-port.ts`（系统级 scheme 白名单
   `http:`/`https:`/`mailto:` 兜底 + `SHELL_SCHEME_DENIED`/`SHELL_OPEN_FAILED`）。注入形制＝壳入口
   `createMacPalHost(electronModule)` → `createElectronApi` 结构切片校验 → 端口构造；能力模块零 `electron` import。
2. **注册形制**：单注册表 `runtime/capability/registry.ts`（注册七项校验、幂等注销、draining）＋组合根
   `production-assembly.ts:179` `createBuiltinCapabilities` 清单；路由（`router.ts`）管线＝注册表命中 →
   `evaluateHostPermissions` 权限判定 → 顶层 `required` 准入 → 执行 → `toWireError` 归一；**深度 schema 校验由域入口承担**
   （document 族 `validation.ts` 同判例）。
3. **分面语义**（17 §5.2）：分面缺失 → 该域**整体不注册**（调用得真实 `BRIDGE_CAPABILITY_NOT_FOUND`）；
   分面在册而环境不可用 → 能力仍注册、端口返回正式域错误码。`system:info` 母型的「端口缺位抛
   `SYSTEM_INFO_UNAVAILABLE`」属防御臂（`systemInfo` 分面恒在），四新域按分面闸语义实现。
4. **权限面**：R19 映射 `dialog:*`→`dialogs:use`（APP_ONLY）、`clipboard:*`→`clipboard:access`、
   `notification:send`→`notifications:send`、`shell:openExternal`→`shell:external`（APP_ONLY，限定值目标 `url`，
   Bridge 登记表 `capability-contracts.ts:102`）；词表四 ID 全在册（`loader/manifest.ts:124-127`，`forbidden`
   限定值语义＝申请不得携带限定值段）。现行组合根平台会话授权 `['*']`（`host-runtime.ts:210`），判定面随
   Rust 内核会话权威接管后逐项生效。
5. **消费方实证**：`plugins/apps/photo-viewer`（manifest 声明裸 `dialogs:use`、角色 app）真调
   `dialog:open`（`usePhotoSession.ts:444`）与 `dialog:save`（`:470`），入参形状与 §7.7 schema 逐字吻合。
6. **文档随动在途**：工作树中 `04.11`/`03.06` 两文档表正由主批随动（C3 补登名），`document-native-*` 两锁测的

## 三、关键裁定（随账留痕）

1. **权限声明逐字 R19**：四域描述符 `permissions` 按 §6.2 全表声明（区别于 `system:info` 的
   `permissions: []` 平台免权限特例——该特例属 P0-1 时点产物，R19 权威映射不因母型特例放宽；平台会话现行
   `['*']` 授权下判定面等价放行，内核接管后逐项生效）。owner 不自报，由组合根 `defaultOwner` 单点决定（document 同判例）。
2. **协议白名单口径**：派单文本「仅放行 http/https」与契约 §7.8「仅允许 http/https/**mailto**」存在表述差；
   按「逐字对齐契约、禁自造」采契约口径（`mailto:` 放行，schema pattern 与端口白名单双层同集），
   `file:`/脚本/自定义 scheme 双层全拒。差异已在本节登记，候主批如需收紧属契约变更（破坏性，须 RFC）。
3. **通知 `iconUri` fail-closed**：受管引用 → 本地图标路径的物化通道（作用域注册表/PathGuard 归资源域核心）
   宿主面缺位，语法闸照契约执行、物化臂以登记码 `NOTIFICATION_FAILED` 如实拒绝，不伪造无图标成功；
   **工单068** 已登记（`项目日志与笔记/问题工单.md` 行 068 + `工单068-通知图标受管引用物化通道缺位/任务说明.md`）。
4. **对话框返回路径绝对性单点落位**：落 PAL `dialog` 端口（系统级约束面，与 `storage` 端口同源同口径），
   能力层不复制第二道（免双重判定漂移）；用户取消原样返回（§7.7「取消不是错误」）。
5. **clipboard 端口无调用上下文**：`IPalClipboardPort` 契约不收 `PortCallContext`（读写不阻塞，17 §4.2
   规则 2 的「可能阻塞」口径不适用），能力层按契约零参调用，不为形制统一而扩契约面。

## 四、测试（先测后码）

- **错误面逐字**：端口 `PalPortError`（`DIALOG_FAILED`/`CLIPBOARD_UNAVAILABLE`/`NOTIFICATION_UNAVAILABLE`/
  `NOTIFICATION_FAILED`/`SHELL_SCHEME_DENIED`/`SHELL_OPEN_FAILED`/`BRIDGE_CANCELLED`）原样透传断言
  （code + retryable + `name`）；`BRIDGE_INVALID_INPUT` details 形态 `{capabilityId, reason}`。
- **权限拒绝路径**：真实运行时路由（`createHostRuntime` + 会话供给替身），未授予对应权限 →
  `BRIDGE_PERMISSION_DENIED` 且 `details.{capabilityId, permission}` 逐字指认；授予 → 放行达端口。
- **schema 拒绝**：逐字段越界（未声明字段、类型、`maxLength`/`minLength`/`maxItems`/`minItems`、
  `filters.extensions` 点号文法、协议白名单正例 3 + 反例 12）确定性拒绝；边界正例（空 filters、空 title、
  `mailto:`）放行。
- **契约镜像锁**：读 `@chips/sdk` 生成源与 `@chips/bridge` 登记表原文比对（不建依赖边），任一侧漂移即红。
- **Electron 面**：真实承载按仓内既有 e2e 纪律验证——`CHIPS_HOST_SMOKE=1 vitest run tests/e2e-host`
  （真 Electron spawn `dist/main/app.js`：四域随 `createMacPalHost` 全分面在册、`registerAll` 进真实注册表，
