## 一、文档修订清单

### 1. 《04.03-04-能力契约规范-三、能力 ID 与权限 ID 命名规则》（已修订）

1. **§3.1 文法**：能力 ID 的 `action` 产生式由 `1*( lowercase / digit / "-" )` 改为 `action = 1*( lowercase / uppercase / digit / "-" )`；`domain`、`target` 与权限 ID 全部产生式不变。
2. **§3.1 规则 1**：原「全部小写，禁止空白、大写、下划线与中文」改写为按段约束——`domain`（命名空间段）与 `target` 全小写，`action` 段允许小写/大写/数字/连字符；权限 ID 各段一律全小写；空白、下划线、中文禁令与「`:` 唯一分隔、2/3 段、4 段及以上非法」保持原义不变。
3. **§3.1 规则 1 新增 camelCase 场景说明**：动作段常规为全小写动词或连字符短语（`list-handlers`、`prevent-sleep`）；多词动词短语经平台登记为独立动作时允许 camelCase；在册实例仅三个——`window:setTitle`、`window:setState`、`shell:openExternal`（均登记于 04.06 §6.2）；与生成器 `CAPABILITY_ID_PATTERN`（动作段首字符小写、其后允许大写）一致；新登记优先全小写连字符，大写形态仅限平台登记时明确批准的独立动作。
4. **§3.1 规则 2 补充两者区分**：大写许可只对能力 ID 的动作段开放；权限 ID 的 `domain`/`scope` 全小写、当前无任何大写实例（现场核对 04.06 全表权限列确认），故其规则保持不动。
5. **§3.2 平台语义域清单**：补入 `command`、`cli` 两域，消除与 04.06 §6.2（`command:*`、`cli:task-*` 已登记为 Bridge 内置能力，见其注 7）的既有矛盾；属「最小改动 + 与裁决一致」处理。
