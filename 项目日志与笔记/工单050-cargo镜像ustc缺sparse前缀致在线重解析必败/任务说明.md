# 工单050任务说明：cargo 镜像配置 ustc 缺 `sparse+` 前缀致在线重解析必败

- 登记：2026-09-23，主智能体（源自 #174 criterion bench 基线构造波实测复现，升级③处置升单）
- 状态：开放·用户级全局配置待用户裁决
- 性质：工具链环境配置缺陷（生态级，非仓库代码面）

## 背景

W3 段四核心 crate 波（#174）为 criterion bench 前后差构造 HEAD 基线 workspace 副本（/tmp 下独立副本，需在线解析 criterion 传递依赖树）。副本 cargo 解析在 stable 1.93 下失败，暴露 `~/.cargo/config.toml` 的 ustc 镜像配置形态问题。

## 证据

- 复现命令：`/tmp/w174_baseline` 副本内 `cargo build --benches`（volta PATH，允许在线、不 --offline）。
- 失败输出：`git fetch https://mirrors.ustc.edu.cn/crates.io-index` → `repository not found`，EXIT=101（日志 `/tmp/w174_baseline_build.log`）。
- 配置现形：`[source.ustc] registry = "<git 索引 URL>"`（无 `sparse+` 前缀）+ `git-fetch-with-cli = true`——sparse 索引站不支持 git 协议拉取，该组合等价于把一个仅 sparse 可用的镜像当 git index 使用。
- 对照实证：副本内新增 `.cargo/config.toml` 局部覆盖为 `sparse+https://mirrors.ustc.edu.cn/crates.io-index/`、`git-fetch-with-cli=false`（仍走 ustc 镜像）→ EXIT=0（日志 `/tmp/w174_baseline_build2.log`）。

## 影响范围

- 既有仓库工作区因锁文件 + 本地缓存命中不触发重解析而**当前幸存**；中招场景=任何需在线重新解析依赖的干净 workspace：bench 基线副本、新 crate 起手、干净机/CI 复现、锁文件重生成。
- 影响全生态所有沿用该用户级 cargo 配置的环境。

## 期望行为

`~/.cargo/config.toml` 的 ustc source 翻正为 `sparse+https://mirrors.ustc.edu.cn/crates.io-index/`；`git-fetch-with-cli` 按镜像实况取舍（sparse 协议下无必要，建议去除或置 false）。

## 暂行处理（已在册通行判据）

需要在线重解析的波次一律在**副本内** `.cargo/config.toml` 局部 sparse 覆盖，不改用户级全局配置（#174 实证有效）。本单不自主修改 `~/.cargo/`（用户级资产，主智能体不代改），处置权归用户：可直接改配置后销单，或授权另派机械小波翻正。
