# 工单015：《核心接口规范》 declared 的 Rust 核心 crate（chips-parser / chips-resource / chips-sync）未交付且无工单追踪

## 背景

task043 重构 W1 期间对 Rust 工作区做实测核对。《核心接口规范》§2.1 将 chips-core、chips-cordis、chips-native、chips-bridge、chips-parser、chips-resource、chips-sync 列为 Rust 核心的正式成员，且 §5/§6/§7 与《02-Bridge三层设计》§10、《04-资源管理设计》§11、《06-文档解析器设计》§11-§13 已给出各 crate 的公开面、Rust 侧设计与测试策略（解析器要求覆盖率 > 80% 且每个对外错误码必须有对应用例）。

## 证据

1. `chips-ecosystem/packages/core-rust/Cargo.toml` members 与 `cargo metadata --no-deps` 实测：工作区仅存在 3 个 crate——`chips-core`、`chips-cordis`、`chips-native`（`packages/native` 提供 chips-native）。
2. `cargo test -p chips-parser -p chips-resource -p chips-bridge` exit 101：包不存在。
3. `chips-ecosystem/packages/core-rust/开发日志.md`（2026-09-20 节）明确记录：「缺口性质是『实现未交付』而非『测试不足』」，且 `chips-parser` / `chips-resource` / `chips-sync` 「暂无对应工单」。
4. `chips-bridge` 缺口已由工单005 登记；parser/resource/sync 三者至今无任何工单、无波次归属。
5. 历史文档口径曾把三者误记为「幻影 crate（文本笔误）」，已于 2026-09-20 在《W1-波次报告》§二修正为「实现未交付」。

## 影响

- 文档与代码不一致：《核心接口规范》对外承诺的成员清单与工作区实际可构建集合不符，任何按规范消费 Rust 核心的包（Host 渲染引擎、CLI、bridge 内核路由）都会在 W2 金链路撞上缺位实现。
- 缺口无追踪：parser/resource/sync 不在任何工单、波次准出或台账裁决面上，W2「打开→解析→渲染→编辑→保存」金链路的解析与资源环节没有可归属的交付路径。
- 覆盖率与门禁口径被污染：`pnpm gates:boundaries` 报 crates=3、rust-core 覆盖率分母仅含 3 crate，与规范的 7 成员口径无声分歧。

- 本工单只登记问题与证据，解决方案（补 crate 骨架、调整波次排期或修订文档措辞）由主智能体与用户裁决后另行落地。
