# 工单045-BASECARD-IMAGE-HOST-RESOURCE-IMPORT-CONTRACT-GAP

## 1. 背景

当前正在把 `Chips-BaseCardPlugin/image-BCP` 从旧架构彻底迁移到新的基础卡片正式链路。

用户对本任务的硬性要求包括：

- 必须完美复刻旧版图片基础卡片的所有功能；
- 资源 URL 必须以卡片文件夹根目录为基准记录；
- 资源导入、保存、删除、预览、恢复的整条链路必须正式打通；
- 不能临时开发，不能兼容回退，不能私自改变架构设计。

## 2. 当前核对结论

已核对以下实现与文档：

- `Chips-BaseCardPlugin/image-BCP/src/editor/panel.tsx`
- `Chips-EditingEngine/src/services/basecard-service.ts`
- `生态共用技术文档/插件开发/03-卡片插件开发.md`
- `生态共用技术文档/组件库/08-编辑引擎基础卡片装配与编辑运行时标准.md`

当前新链路公开给基础卡片编辑器的正式资源导入能力为：

```ts
resources?.importResource?.({
  accept?: string[];
})
```

其实际语义是：

1. 基础卡片请求导入某类资源；
2. Host/EditingEngine 自己打开系统文件选择器；
3. 由宿主把用户选中的文件写入卡片根目录；
4. 返回 `{ path, url, name, size, mimeType }`。

## 3. 阻断点

旧图片基础卡片有一项不能丢失的正式功能：用户可以把本地图片文件直接拖放到编辑区中导入。

该能力要求：

1. 插件在浏览器侧拿到拖放产生的 `File`；
2. 插件把这个 `File` 提交给宿主；
3. 宿主把文件写入卡片根目录；
4. 插件拿到正式相对路径并继续维护预览、删除、撤销、恢复等后续链路。

但当前正式能力并不支持这件事，因为：

- `resources.importResource(...)` 不接受 `File`；
- `Chips-EditingEngine/src/services/basecard-service.ts` 只支持宿主自行弹系统文件选择器，不支持接收插件已持有的文件对象；
- Host / SDK / 共用文档中也没有任何等价正式接口可以承担“插件上传本地文件到卡片根目录”这个职责。

## 4. 为什么这不是图片卡片内部可以自行解决的问题

这不是 `image-BCP` 单仓实现细节，而是生态正式契约缺口。

原因如下：

- 若严格遵守当前正式契约，则必须放弃拖放本地文件直接导入，无法完美复刻旧版功能；
- 若图片卡片继续保留旧的 `importResource({ file, preferredPath })` 私有桥接口，则会和当前“新基础卡片正式链路唯一入口”冲突；
- 若让插件自己写文件或绕过 Host 落盘，则违反资源链路边界与正式架构要求。

因此，当前阻断必须先在 Host/SDK/EditingEngine/共用文档层完成决议与正式能力补齐，不能在 `image-BCP` 中私自拍板。

## 5. 建议的正式解决方向

建议冻结以下两种方案之一：

### 方案 A：扩展现有 `resources.importResource`

把正式能力扩展为同时支持：

```ts
resources?.importResource?.({
  accept?: string[];
  file?: File;
})
```

语义：

- 未传 `file` 时，保持“由宿主打开文件选择器”的标准路径；
- 传入 `file` 时，由宿主把该文件写入卡片根目录并返回正式资源结果。

优点：

- 仍保持单一资源导入入口；
- 能覆盖点击上传与拖放上传两类交互；
- 对基础卡片插件来说最容易理解和复用。

### 方案 B：新增单一职责正式能力

保留现有 `resources.importResource({ accept })` 用于系统选文件；
新增一个职责清晰的同级能力，例如“导入插件已持有的文件到卡片根目录”。

优点：

- 语义更显式；
- 宿主区分“宿主选文件”和“插件提供文件”两条链路更清楚。

代价：

- 需要增加新的正式能力名与文档口径；
- 脚手架和插件实现要学习两套入口。

## 6. 需要同步修改的仓库

一旦正式方案确认，需要同步更新以下模块：

- `Chips-Host`
- `Chips-SDK`
- `Chips-EditingEngine`
- `Chips-Scaffold/chips-scaffold-basecard`
- `生态共用技术文档`
- `Chips-BaseCardPlugin/image-BCP`

## 7. 当前处理决定

按照仓库规则，已登记本问题工单。

在该正式能力缺口处理完成前，当前不继续推进 `image-BCP` 的新架构迁移，以避免：

- 牺牲旧版正式功能；
- 在业务项目里私接非正式接口；
- 把未冻结能力写进正式文档和正式实现。
