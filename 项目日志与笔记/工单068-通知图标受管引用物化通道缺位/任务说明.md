# 工单068：通知图标受管引用物化通道缺位——任务说明

> 登记日：2026-10-01。登记来源：G6 系统服务族第一批（dialog / clipboard / notification / shell 四域宿主注册）交付勘查。
> 状态：**开放**（交付侧已按 fail-closed 落地，候资源域物化面接线后销单）。

## 一、背景

`notification:send` 能力契约（《04-能力契约规范》§7.5）声明输入 `iconUri` 可选，取值为
`chips-resource://` 规范受管引用。PAL 通知端口契约
（`chips-ecosystem/packages/host/src/platform/contracts/notification.ts` 的 `iconPath` 字段注记）明确分工：

> 能力输入 `iconUri`（`chips-resource://`）由能力层解析为本地路径后传入；端口不感知资源协议。

同构缺口将随 `tray:set`（《04》§7.9 `iconUri` 可选）在 G6-desktop-shell 批次复现。

## 二、证据（路径级）

1. 宿主面**不存在**通用的受管引用 → 本地路径解析器：
   - 作用域注册表与 PathGuard 归资源域核心（《06-资源协议规范》§四/§五；`storage-port.ts` 头注「端口不做
     PathGuard 权限判定；只做系统级约束与错误归一」同口径）；
   - 目录态文档包作用域由 document 能力装载段按会话登记（`packages/host/src/capabilities/document/adapters/scope-ledger.ts`），
     账目以 `managedUri ↔ localPath` 双向换算服务于文档会话，不是全局 URI 寻址面；
   - 归档态文档（ZIP）成员没有真实文件路径可给 Electron `Notification` 的 `icon` 参数。
2. `chips-resource://` **语法闸**已在能力层接线（`packages/host/src/protocol/resource-uri.ts`
   `parseResourceUri`，与协议处理器、preload 预检同一实现）；缺的是**语义解析**（scope → 根 → 成员 →
   本地图标路径）的在册消费面。
3. 交付现场：`packages/host/src/runtime/capabilities/notification.ts` iconUri 臂 fail-closed——
   合法受管引用在物化通道缺位时以登记码 `NOTIFICATION_FAILED`（retryable，`04` §11.4）如实拒绝，
   不伪造「无图标发送成功」（17 号文档 §5.2 SB-5）。

## 三、影响范围

- 携带 `iconUri` 的 `notification:send` 调用确定性失败；当前官方插件对该字段**零调用**
  （帧动作 `notify` 臂传 `{level, message}`，属 #85 帧执行通道波次的另一在册缺口），消费面未受阻。
- `title` / `body` / `silent` 主链不受影响。
- 后批 `tray:set` 图标臂将复现同问，销单时一并收口。

## 四、期望行为

资源域正式绑定波交付全局受管引用物化面（作用域注册表查询 → 目录态成员本地图标路径），
或裁定通知/托盘图标改走端口原生数据臂（`nativeImage.createFromDataURL` 等价面）后：

- 能力层原位接线解析端口，去 fail-closed 临时臂；
- 解析失败仍以登记码如实拒绝，不得静默降级为无图标发送。

## 五、暂行处理（零绕过）

- `iconUri` 语法闸照契约执行（非 `chips-resource://` 规范引用 → `BRIDGE_INVALID_INPUT`）；
- 物化缺位以 `NOTIFICATION_FAILED` 如实拒绝并在模块头注留痕（工单068）；
- 不在能力层私建第二作用域表、不做临时文件导出旁路、不伪造成功。
