# 工单150-编辑引擎undo-redo历史栈悬空：任务说明

## 1. 背景

编辑引擎 `command-manager.ts` 实现了完整命令模式 undo/redo，但生产代码从未调用 `execute()` 压入命令——卡片/箱子文档的变更操作不经过历史栈，撤销/重做功能实际不可用，历史面板只读空栈。同时暴露生态缺口：文档编辑历史没有公共语义。

## 2. 证据

- `Chips-EditingEngine/src/core/command-manager.ts`（291 行）：undoStack/redoStack、tryMergeWithLast（时间窗合并）、enforceHistoryLimit（历史上限）、goToHistory（跳转）、command:* 事件广播；
- 全仓生产代码检索：无任何 `execute()` 调用点；card-service.ts / box-document-service.ts 的文档操作不经过命令栈；
- `src/components/HistoryPanel/HistoryPanel.tsx`（263 行）：只读空栈。

## 3. 影响范围

- Chips-EditingEngine 撤销/重做功能与历史面板；
- 未来 Host 卡片/箱子会话服务的 undo/redo 语义设计（本工单直接为其提供输入基线）。

## 4. 复现步骤

1. 启动编辑引擎，修改卡片内容，点击撤销——无任何效果；
2. 检查 command-manager 栈状态恒为空；
3. 检索生产代码对 execute() 的调用——不存在。

## 5. 期望行为

- undo/redo 作为 Host 会话服务公共语义：`card.session.undo/redo/history`、`box.session.undo/redo/history`；
- 入栈范围：updateBasicCard / addBasicCard / removeBasicCard / moveBasicCard / updateMetadata / updateCover（含资源操作）；persist/undo/redo 本身不入栈；
- 合并窗口：同一基础卡片 500ms 内连续更新合并为一步（基线：command-manager 合并设计）；
- 历史上限：默认 100 步可配置；
- 资源导入/删除随状态回滚（物理文件在 persist 时按引用关系处理）；
- 编辑引擎 command-manager.ts 本地实现删除（移入归档），历史面板消费会话历史事件。

## 6. 暂行处理

无。本工单由 task034 迁移任务 M2/M3 直接修复。

## 7. 需要协作方

Chips-Host 会话服务设计方、Chips-EditingEngine 维护方。

## 8. 处理结果（2026-08-11，M2 完成）

- Host 会话服务内置 undo/redo 历史（`session/history.ts`：合并窗口 500ms、上限 100 步、undo/redo/history 动作），历史在**修改前入栈**（恢复修改前快照，含资源操作反推）；
- 编辑引擎 `command-manager.ts` 重写为会话历史适配层，撤销/重做命令与历史面板代理到 `card.session.undo/redo/history`；
- 验证：Host 历史闭环契约测试（撤销/重做/空历史）通过；编辑引擎 undo/redo 代理测试通过；
- 箱子域历史随 M3 会话服务落地（同一历史模块复用）。
