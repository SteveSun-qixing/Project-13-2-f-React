# 薯片生态爆炸式重构 · 总计划与路线图

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：执行中
> 基准：`薯片生态文档库/`（唯一契约权威）；旧资产以 `项目日志与笔记/重构计划/重构跟踪.db` 为准

## 一、总目标与原则

**目标**：以最快速度、最高质量，把旧生态（39 个仓库/目录、29537 个文件）彻底重构为文档库定义的新生态（Cordis 内核 + Rust 核心 + Neon + Electron 壳 + React/@chips/ui），并完成官方插件、应用、服务端与工具链的迁移。

**原则**：

1. **质量第一**：不缩减工程量、不降低质量；任何"先这样以后再改"视为失败。
2. **逐文件消灭**：每个旧文件、每个符号（函数/类/接口/类型）都要有明确决策（迁移/重写/保留设计/归档/废弃），来源、理由、执行证据写入跟踪库。
3. **契约先行**：接口与契约已冻结；实现不得偏离文档库；发现冲突先改文档（RFC），再改代码。
4. **无限并行**：波次内并行数量不设上限（目标 20 → 40 → 100），以文件所有权隔离冲突。
5. **断点可续**：每波产出分片与任务状态入库；上游中断不影响已完成产物。

## 二、决策口径（逐文件/逐符号三问）

1. 该功能在新生态中是否仍然存在？（否 → `drop` + 理由）
2. 该设计是否已被文档库覆盖？（是 → 代码按新契约重写 = `rewrite`；设计有价值但代码不可复用 = `keep-design`）
3. 代码是否可直接迁移复用？（是 → `migrate`；仅历史价值 → `archive`）

记录要求：`files.decision` + `decision_reason` + `owner`；符号级决策写入 `symbols.decision` + `note`。禁止无证据结论。

## 五、并行与依赖规则

1. **文件所有权**：一个文件只有一个执行者；跨包接口以文档库为唯一依据，不得口头约定。
2. **依赖顺序**：`chips-core` ← 其他 crate；`chips-native` ← host-electron；`@chips/bridge` ← sdk/host；渲染引擎 ← R2 金链路。R1 内被依赖方先行（R1-01/02 最先），其余可同时开工。
3. **冲突处理**：同名文件并发修改视为缺陷；由先完成者保留，后到者改为引用。
4. **评审代理**：每波结束派 2-4 个审查代理（不一致/坏例/TODO/契约偏离），修复后方进入下一波。

## 六、验收与门禁（每波 DoD）

- 代码：`cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test`、`pnpm typecheck/lint/test` 全绿；
- 契约：能力/权限/事件/错误码与文档库逐条一致，未登记 ID 为零；
- 测试：核心不变量有单测；跨包有契约测试；金链路有 E2E（R2 起）；
- 文档：新增实现与文档同 PR；无 TODO/占位/临时实现；
- 跟踪库：任务状态、文件决策、符号决策实时更新。

## 七、时间与质量约束

- "两小时内完成"作为 R1+R2 的目标窗口；R3-R6 按波次连续推进，**不以缩工减料换时间**。
- 每波结束产出：波次报告（完成项/证据/风险/下一波输入）写入 `项目日志与笔记/重构计划/`。
- 上游额度中断等外部因素：记录断点，恢复后从任务库续跑。
