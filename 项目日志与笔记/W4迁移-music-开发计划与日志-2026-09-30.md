## 二、交付面（计划）

1. `src/shared/audio-metadata.ts`：747 行 ID3v2/MP4/FLAC 纯解析**逐字迁移**，零 Host 依赖；
   唯一内部依赖 `resolveFileName` 随 `src/shared/utils.ts` 逐字随迁。
2. `src/shared/default-cover.ts` + `assets/placeholders/*` + `assets/icons/basecard-icon.svg`：素材随迁；
   默认封面经 Vite `?inline` 以数据 URL 进 render.js（渲染帧插件资产寻址臂未落波前不依赖包内相对 URL 解析）。
3. 配置模型 `src/config.ts` + `assets/schemas/music-card-config.schema.json`：字段名与《01》§6.8 一致
   （audio_file/music_name/album_cover/lyrics_file/production_team/release_date/album_name/language/genre），
   `readConfig` 归一 + `validateConfig`「出现即校验」不宽于 schema。
4. 查看态播放卡 `src/view.tsx`：封面（默认占位兜底）/标题派生/歌手派生/元信息行 + 空态；
   打开臂经 SDK `chips.request('resource:open', …)` 携 §9.2 载荷，失败以行内简体中文提示如实呈现。
5. 编辑态 `src/editor.tsx`：表单面板（资源路径 + 歌曲信息 + 制作团队），经 `IBaseCardEditor` 回流 replace 变更。
6. 主入口 `src/main.ts`：validateConfig / createInitialContent / collectResourcePaths（音频、封面、歌词，去重稳定排序）。
7. 测试先测后码：`tests/audio-metadata.test.ts` 用**构造的真实字节夹具**（ID3v2.3 / ID3v2.4 syncsafe /
   MP4 ilst / FLAC Vorbis Comment+Picture 最小帧，不 mock 解析器）；渲染面 jsdom
   （`tests/render.test.ts`、配置面 `tests/config.test.ts`）。

## 四、缺位登记（工单060）

音乐卡片「播放」臂依赖的宿主 audio 媒体面未就绪，本包如实登记并照常交付解析与渲染：

1. `chips.official.music-player`（audio/* primary 处理器）在《09》§4.2/§5.2 为「已设计」，
   W5 重写波次未落；`resource:open` 路由后无处理器命中。
2. 渲染帧插件执行通道（工单025 剩余 / #85 RFC 落波）未交付：帧内 `renderView` 装载臂未接，
   帧内打开臂正式通道 `frame:action` 不可用；就近渲染容器侧走 SDK `chips` 客户端可真调。
3. 编辑器资源导入通道缺位：旧 BCP 由旧 Host 注入 importResource/deleteResource/TiffToPng 通道，
   新架构编辑器契约（08 §4）只承载配置回流，音频文件落卡片的资源导入臂归属资源写入链路（未开放给编辑器）。
   故嵌入元数据自动补全（解析 → 写封面/歌词资源 → 回填配置）在本包以纯解析模块交付，
   导入编排等通道就绪后接线（非兼容层，是通道归属未定）。

详见 `项目日志与笔记/工单060-音乐卡片audio媒体面缺位/任务说明.md`。
