# task040-优化生态文件系统，添加万能文件查看器应用插件 任务日志

- 日期：2026-08-29
- 任务目标：新增「万能文件查看器」应用插件（`com.chips.universal-file-viewer`），把开源项目 open-file-viewer core 完整移植为薯片生态的通用兜底查看器；同时在 Host 侧建立「默认查看器 + 可选应用」的文件打开方式治理架构，并在生态设置面板新增「文件打开方式」设置页。

## 一、需求口径

1. 专用查看器优先：已有图片查看器、视频播放器、书籍阅读器、音乐播放器覆盖的格式，仍由专用查看器打开，万能文件查看器不得因安装顺序抢占。
2. 兜底接管：Host 转发文件打开需求时，若某格式没有已安装的专用查看器，由万能文件查看器统一预览，避免落入「无处理器」报错或直接交给系统。
3. 桌面式打开方式架构：Host 从设计上支持「同一文件类型多个处理器应用 + 默认处理器」，平时用户无需选择，默认处理器自动生效；需要时在生态设置面板调整。
4. 完整移植：开源项目 open-file-viewer core（MIT）以二次开发方式整体移植为插件内引擎层，非临时封装。

## 二、正式身份与关键决策

| 项 | 取值 |
| --- | --- |
| 插件 ID | `com.chips.universal-file-viewer` |
| 显示名 | 万能文件查看器 |
| 工程目录 | `Chips-UniversalFileViewer` |
| 引擎来源 | open-file-viewer `packages/core/src`（v0.1.43，MIT），整包源码移植于 `src/viewer-engine/`，许可证归属文件随源码保留 |
| 处理器声明 | manifest `capabilities` 约 190 条，全部以 `@fallback` 兜底层级声明 `resource-handler:view:<mime>@fallback` 与 `file-handler:<ext>@fallback` |
| 图标 | `scripts/icon-targets.mjs` 登记 `UniversalFileViewer → folder_open`，四件套经正式工具链生成 |
| 偏好配置键 | Host 配置 `fileOpen.defaults`（user 作用域），值 `Record<preferenceKey, pluginId>`，偏好键 `mime:<mime>` / `ext:<ext>` |
| 治理路由 | 新增 `plugin.listHandlers`（权限 `plugin.read`，幂等，3s） |
| CLI 入口 | `universal-file-viewer open <path>`（`cli.commands`，`mapsTo: targetPath`） |

关键架构决策：

1. **能力层级（tier）契约扩展**：处理器能力串新增 `@fallback` 后缀（省略为 primary 专用层级）。解析顺序为「用户偏好 → 精确 MIME → 通配 MIME → 扩展名」，同一候选内 primary 先于 fallback、同级保持安装序；未知 `@` 后缀整串拒绝。该设计让专用查看器与兜底查看器共存时天然有序，且专用查看器卸载后兜底自动接管，与安装顺序无关。
2. **解析唯一实现**：`Chips-Host/packages/resource-open-service/src/handler-resolver.ts` 纯函数模块为唯一口径，`resource.open` 主链路、`association.openPath` 内核路由、OS 文件关联（`src/main/core/file-association.ts`）三处共用，杜绝口径分裂。
3. **`PluginRuntime.query` 层级归一**：capability 过滤改为按归一化能力串匹配（剥离层级后缀），`file-handler:.png@fallback` 能被 `capability: 'file-handler:.png'` 命中；macOS 安装器 Info.plist 文档类型注册同步归一。
4. **DWG 不声明**：上游唯一 GPL-3.0 依赖 `@mlightcad/libredwg-web` 不安装，DWG 二进制格式不声明能力（回退系统处理），DXF 等文本 CAD 格式正常覆盖；引擎内相关适配代码仅运行时动态加载，不会打包分发。许可证逐包核查：30 个新增依赖全部为 MIT / Apache-2.0 / BSD-2-Clause / ISC / MIT-0 / 双许可宽松侧。
5. **资源装载策略**：音视频走 `resource.resolve` URI 串流；本地路径与 `file://` 读字节构造 File；http(s) 直通引擎（CSP `connect-src` 按书籍阅读器先例放开）；Host 托管资源走 `resource.readBinary`。装载前经引擎 `isPreviewSupported` 门禁（fallback 兜底不算可用预览）。
6. **启动恢复兼容**：优先读 `launchParams.resourceOpen`，回退 `targetPath`；兼容消费 `chips.book-card` 图片序列 payload（恢复有序图片队列，逻辑与图片查看器同源）；ebook/video/music 卡片 payload 场景按契约以顶层 `resourceOpen.filePath ?? resourceId` 为读取入口。
