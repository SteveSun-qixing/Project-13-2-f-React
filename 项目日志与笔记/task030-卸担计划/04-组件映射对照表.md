# 04-组件映射对照表

> 本文件是批量子代理重构的**核心作业依据**：每个旧组件 → antd 对应物、属性差异、示例、注意点。
> 映射表以实测的全生态使用面为准（见 01 章）；M2 试点后回收到 v2 版本定稿。
> 表中 `ChipsXxx` 均为 `@chips/component-library` 导出。

---

## 1. 使用总则

1. **等价还原**：仅替换 UI 呈现层，组件承载的业务逻辑、事件数据、状态语义不变；
2. **就近映射**：找不到 1:1 组件时用 antd 组合实现，禁止自研新组件（除非列入共享层）;
3. **需要进共享层的组件**（多个仓库重复使用、antd 无对应物）：`EmbeddedDocumentFrame`、`AppChrome`（窗口壳）、`StateBoundary`（错误/加载边界）、`PanelHeader`，在 `@chips/ui` 中实现，映射时直接引用；
4. **属性名差异处理**：旧属性（如 `title`/`onPress`）按 antd 官方 API 改名（如 `title`/`onClick`），逻辑等价；
5. **禁用语义保留**：`disabled`、`loading`、`readOnly` 等状态必须保留。

## 8. ChipsForm 等价替换规则（重点）

实测 `ChipsForm` 在各 BCP/BLP 编辑面板中大量使用，语义为**受控值 + 变更回调**（`value`/`onChange` 模式）。antd `Form` 是非受控 + 校验模型。等价替换两种做法（按场景选择）：

**做法 A：保留受控状态（推荐用于简单面板）**
```tsx
// 旧
<ChipsForm value={values} onChange={setValues}>
  <ChipsTextField field="title" />
</ChipsForm>

// 新
<Space direction="vertical" style={{ width: "100%" }} size={12}>
  <Flex vertical gap={4}>
    <span className="form-label">标题</span>
    <Input value={values.title} onChange={(e) => onChange({ ...values, title: e.target.value })} />
  </Flex>
</Space>
```

**做法 B：antd Form 受控化（用于校验/提交型面板）**
```tsx
<Form form={form} initialValues={values} onValuesChange={(_, all) => onChange(all)} layout="vertical">
  <Form.Item name="title" label="标题"><Input /></Form.Item>
</Form>
```

规则：
- 编辑面板（BCP/BLP）无提交校验需求 → 做法 A（改动最小）；
- 有必填/格式校验的页面（设置面板、表单页）→ 做法 B；
- 面板级 `onChange` 必须触发，保证编辑链路（卡片的 undo/redo、属性同步）不变；
- 面板实现统一由共享层提供 `FieldRow`（label + 控件，`Flex` 组合）以保持一致性。

## 9. 映射时禁止做的事

1. 禁止把旧组件"包装 shim"留在源码中（如 `import { ChipsButton } from "./shims"`）——必须直接用 antd；
2. 禁止引入 `@chips/component-library`（即使只是类型引用）；
3. 禁止复制旧组件库源码到应用内；
4. 禁止改变业务事件语义（onClick/onChange/onSubmit 触发的业务副作用）；
5. 禁止为"省事"删掉 disabled/loading/empty/error 等状态分支——必须等价还原；
6. 禁止用 `any` 绕过类型（antd 类型完备）；
7. 禁止新增第二套视觉（不应用 antd 默认蓝以外的强调色）。

## 12. BLP 样板（grid-BLP）实证补充 —— 批量阶段依据
