# 10-批量执行流程与子代理作业规范

> 本文件定义整个重构的执行流程、分批策略与子代理作业规范（任务卡模板、输入输出、防串改规则）。
> 目标：可并行、可复现、可审查，子代理按统一标准"等价替换、原封不动还原"。

---

## 1. 总体流程

```
M0 计划评审（决策点已确认：packages/web 纳入、新建 Chips-Ui、antd 最新版 6.x）
   ↓
M1 基建：共享层 @chips/ui + 脚手架模板 + 映射表 v1
   ↓
M2 试点：PhotoViewer 重构 → 走查 → 映射表 v2 + 标准模板定稿
   ↓
M3 应用插件批量（分 4 批）：
   批1: MusicPlayer、VideoPlayer、CardViewer
   批2: BookReader、RichTextEditor、CommunityClient
   批3: CommunityClient 完成后即并行 packages/web（同源同构）
   批4: EcoSettingsPanel、iconMaker
   批5: EditingEngine（单仓单独成批）
   ↓
M4 卡片/布局插件批量：BCP 样板 + BLP 样板 → 剩余 7 BCP + 10 BLP
   ↓
M5 收尾：EcoSettingsPanel 页面处置确认、组件库/ThemePack/脚手架-主题归档、文档同步
   ↓
M6 全量回归与验收（12 章）
```

## 2. 分批策略与并行度

| 批 | 仓库 | 并行子代理数 | 说明 |
|---|---|---|---|
| M2 试点 | Chips-PhotoViewer | 1 | 主代理亲自执行或 1 个子代理 + 主代理全程审查 |
| M3-1 | MusicPlayer、VideoPlayer、CardViewer | 3 | 独立仓库，无互相依赖 |
| M3-2 | BookReader、RichTextEditor、CommunityClient | 3 | CommunityClient 完成后启动 M3-2b |
| M3-2b | CommunityPlatformServer/packages/web | 1~2 | 与 CommunityClient 同源同构，对照处理；非 chipsdev 工程，走自身 vite build |
| M3-3 | EcoSettingsPanel、iconMaker | 2 | 面板类 |
| M3-4 | EditingEngine | 1 | 单独，2.3 万行，命令系统最深，需重点审查 |
| M4-1 | BCP 样板（image-BCP） | 1 | 输出 BCP 标准 |
| M4-2 | BLP 样板（grid-BLP） | 1 | 输出 BLP 标准 |
| M4-3 | 其余 7 BCP | 2~3 | 按样板批量 |
| M4-4 | 其余 10 BLP | 3~4 | 按样板批量 |

**并行约束**：
- 同一时间最多 4~5 个子代理并行（避免文件冲突与审查积压）；
- 每批完成必须通过质量门禁（11 章）后才能启动下一批；
- 共享层（@chips/ui）在批量期间处于**冻结状态**，只允许主代理修改；子代理发现共享层缺口时停止并汇报，由主代理统一补充。

## 3. 子代理任务卡模板

每个仓库一张任务卡（主代理生成），内容如下：

```markdown
# 任务卡：Chips-<仓库名> antd 重构

## 目标
将该仓库前端从自研组件库(@chips/component-library)重构为 antd + @chips/ui，
功能等价、行为不变。严格遵循 task030-卸担计划文档：
- 04-组件映射对照表.md（映射规则）
- 06-多语言系统移除规范.md（中文直写）
- 07-主题系统移除规范.md（主题移除）
- 08-应用插件重构标准.md / 09-基础卡片与布局插件重构标准.md（标准结构）

## 输入
- 仓库路径：<path>
- 现有代码：<src 清单>
- 本次需要替换的组件库 API：<该仓库实测导入清单>

## 输出
- 重构后的完整代码（源码 + 测试）
- 变更清单：<文件列表 + 每文件改动摘要>
- 文案对照表：i18n key → 中文
- 遗留疑问：<共享层缺口/契约疑问，禁止自行解决>

## 等价还原要求
1. 业务逻辑、状态分支(loading/error/empty/disabled)、事件语义不变
2. window.chips.* 调用链不变
3. manifest.yaml 只调整 i18n.read/theme.read（按规范），其余不动
4. 禁止引入 @chips/component-library（含类型）
5. 禁止留下 TODO/占位/简化实现

## 验证（必须全部通过）
- npm install（workspace 内）
- npm run typecheck（或 chipsdev 对应命令）
- npm run lint
- npm run test
- npm run validate（如适用）
- rg "@chips/component-library|chips-sys|useChipsI18n" src tests  → 零命中（归档除外）

## 审查清单（子代理自查后提交）
[ ] 映射表逐项核对
[ ] 中文文案规范核对
[ ] 视觉规范核对（03 章）
[ ] 测试全绿
[ ] 变更清单完整
```

## 4. 子代理作业规范

1. **只改任务卡范围内的文件**；需要动共享层/其他仓库时，写入"遗留疑问"汇报，禁止越界修改；
2. **先读后改**：动手前必须通读该仓库相关文档（技术文档/需求文档）与关键源码，理解功能后再替换；
3. **等价优先**：不确定的替换宁可不换（标注疑问），不可自作主张改行为；
4. **一次一仓**：每个子代理只处理一个仓库（EditingEngine 可按文件域拆分子任务，但需主代理协调）；
5. **提交物**：只输出代码变更与文档性交付物（变更清单、疑问清单），不做 Git 提交（提交由用户管理）；
6. **汇报格式**：按任务卡"输出"节逐项汇报，含验证命令输出摘要；
7. 子代理必须报告它发现的任何"文档与代码不一致/契约缺口"，由主代理统一登记工单（13 章）。

## 5. 主代理职责（每批）

1. 生成批内任务卡（含该仓库组件库导入实测清单）；
2. 启动子代理并行作业；
3. 逐仓审查子代理输出（12 章自审/交叉审）；
4. 汇总疑问 → 补充共享层 / 更新映射表 / 登记工单；
5. 全批质量门禁通过后启动下一批；
6. 每批结束更新本计划文档的执行进度表。
