# 13-文档同步与归档规范

> 本文件定义重构过程中的文档更新、归档与工单登记规则。遵守 AGENTS.md：禁止删除文件（统一移入归档）、文档与代码同步、生态共用文档保存全局信息。

---

## 1. 原则

1. **文档跟随代码**：代码改到哪里，相关文档同步更新；完成 M2 试点后，涉及文档立即定稿，不拖到 M6；
2. **生态共用技术文档**保存未来仍会使用的全局信息；废弃体系的信息标注废弃状态并归档，但**保留"为什么废弃"的说明**（避免后人重复造轮子）；
3. **归档**：禁止删除，统一移动至就近 `归档/` 目录；
4. **工单**：执行中发现契约缺口、文档与代码漂移、SDK 不可用等，按 AGENTS.md 流程登记。

## 3. 归档操作规范

1. 移动目标：就近 `归档/`（如各插件 `src/i18n/` → 该插件 `归档/src-i18n/`；组件库 → 工作区 `归档/Chips-ComponentLibrary/` 或仓库内归档，**按 AGENTS.md"就近"原则执行**）；
2. 归档内容保留 README 说明（为何归档、何时归档、任务编号 task030）；
3. `package.json` workspaces 列表同步调整（组件库、ThemePack 移出后，根 `verify:workspace` 脚本若遍历 workspaces 需要适配——登记工单或更新脚本）；
4. 归档后全局搜索确认无引用（残留扫描 11-3.1 节）。

## 4. 工单登记规则

执行中遇到以下情况，按 AGENTS.md 流程登记工单（`项目日志与笔记/问题工单.md` + 独立目录 `工单NNN-描述/任务说明.md`）：

1. Host manifest 校验强制要求 `theme.read/i18n.read` 权限，无法按计划移除（契约缺口）；
2. `chips-sdk` 暴露组件库/主题类型，插件无法摆脱对废弃包的引用（SDK 契约漂移）；
3. `chipsdev` 工具链（build/test/validate）对组件库有隐含依赖（如契约测试）；
4. 文档与代码不一致（引用文档内容与实测代码不符）；
5. Host 的 `verify:workspace` 或工作区脚本对已归档仓库的依赖；
6. 共享层 `@chips/ui` 需要依赖现有 SDK 但 SDK 接口不可用。

> 登记工单后按 AGENTS.md：继续推进可推进部分，规则沉淀绕开未收口口径。

- 执行完成后本目录保留（属任务过程材料，不迁入生态共用技术文档）；
- 沉淀到生态共用技术文档的正式结论：antd 技术选型（02 章核心）、统一视觉规范（03 章）、组件映射（04 章）、重构后应用结构（08 章）——M6 时整理成正式文档落位（建议新建 `生态共用技术文档/前端基础/` 目录，需用户确认目录名）。
