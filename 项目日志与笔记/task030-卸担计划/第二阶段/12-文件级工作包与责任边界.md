## 2. 工作包详细要求

### WP-HOST-01：Surface/session

输入：当前 Manifest、Bridge、Surface API。

步骤：

1. 列出每个 session 的创建者、owner、surfaceId、launchContext 字段；
2. 把插件加载、Bridge 安装、主题注入、页面关闭和资源回收写成状态机；
3. 为非法顺序、重复关闭、页面崩溃和权限拒绝增加测试；
4. 用真实 `chipsdev-r run` 打开应用并检查日志字段。

输出：状态机图、类型、Host 集成测试、诊断样例。

### WP-SDK-01：typed runtime facade

输入：Host Bridge action/schema 和错误类型。

步骤：

1. 生成或手写收口的 domain API 类型；
2. 为每个 API 写权限、错误、超时、重试和测试 mock；
3. 把 Browser no-Host 和 Host Bridge 两种 transport 用同一 `Client` 接口表达；
4. 严禁在 SDK 中复制 Host service 实现。

输出：公开入口、testing 入口、CLI inspect/validate、API 文档。

### WP-UI-01/02：App 门面和组合

输入：SDK Client、launch context、antd ConfigProvider。

步骤：

1. `mountChipsApp` 建立一次 Provider 树；
2. 默认主题、locale、popup container 和 CSS 在门面内统一；
3. command UI 只消费 command schema；
4. 状态边界、面板头、嵌入容器用统一错误/文案 key；
5. 对外导出 docs、类型和测试。

输出：应用只写业务页面的可运行示例。

### WP-SCAFFOLD-01/02：脚手架

输入：已冻结的 `@chips/ui/app` API 和 Manifest schema。

步骤：

1. 模板占位符定义和参数校验；
2. 生成后检查无占位符、无旧包、无旧目录；
3. 生成 package.json 精确依赖、脚本和 README；
4. 真实执行 build/test/validate/package；
5. 每次共享层入口变化同步模板和测试。

输出：模板快照、生成 e2e 报告、开发者 README。

### WP-THEME-01/02：Recipe

输入：`@chips/ui` 语义 token、Host Theme Runtime、antd ThemeConfig。

步骤：

1. 先定义 recipe schema 和允许的 override；
2. 实现 resolve、validate、CSS/ConfigProvider/Manifest 生成；
3. 生成默认 Apple 主题并对比现有视觉基线；
4. 以 Host 安装/应用/iframe 预览验证；
5. 固定 source/dist hash 和诊断报告。

输出：主题 scaffold、默认 theme recipe、测试和作者指南。

### WP-APP-01/02/03：应用迁移

每个应用都按以下顺序：

1. 列出现有业务入口、命令、Host action、资源、Manifest 权限和测试；
2. 先替换框架接线，再替换叶子 UI，保持业务行为；
3. 删除重复 runtime/i18n/theme 文件前先确认无引用；
4. 将跨应用缺口回报 `@chips/ui`，不在应用写永久私有替代；
5. 运行真实门禁和 Host smoke；
6. 更新应用 README、Manifest 和测试报告。

### WP-CARD-01：BCP/BLP

1. 保留卡片/布局协议、资源路径和编辑器语义；
2. 使用共享 `EmbeddedDocumentFrame` 和主题 CSS 注入；
3. 验证 iframe `@font-face`、CSP、清理和跨文档错误；
4. 先处理 SDK/BCP 类型工单132，再进行 RichText/EditingEngine 批次；
5. 真实打开 `.card/.box`，不以页面截图代替文件链路验证。

### WP-DOC-01：公共文档

1. 以代码、Manifest、测试和正式运行结果重新核对所有示例；
2. 删除旧组件库 Provider 作为默认接线的示例，历史材料移入归档；
3. 发布 Host/SDK/`@chips/ui`/app/theme 的职责矩阵；
4. 在文档中同时提供 minimal app、standard app、theme recipe 和 Browser no-Host 示例；
5. 运行文档示例验证脚本，不能只人工检查文字。

## 3. 交付顺序约束

```text
Host/SDK 契约
  → @chips/ui runtime/app
  → 脚手架
  → PhotoViewer
  → 低风险应用
  → 高风险应用和 BCP/BLP
  → Theme Recipe/默认主题
  → 公共文档发布与全量验收
```

任意下游工作包不得通过复制上游未收口实现来“先跑起来”。遇到缺口按工单规则停线。
