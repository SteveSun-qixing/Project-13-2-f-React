# 08 测试、质量门禁与性能基线

## 1. 门禁原则

“verify 通过”必须代表真实工程质量，不允许用 `node --check` 冒充 TypeScript、不允许用关键字扫描冒充 lint、不允许用契约文件计数冒充行为覆盖率。每个门禁都要能回答“哪条正式链路被验证、失败后谁负责”。

## 2. 分层测试矩阵

### 2.1 Host

| 层 | 必测 |
|---|---|
| route | 输入 schema、权限、超时、错误归一、返回 envelope |
| Bridge | invoke/on/once/emit、取消订阅、scope token、最小暴露面 |
| Plugin Runtime | manifest、session、surface、launch context、卸载清理 |
| Theme Runtime | 安装、解析、CSS 顺序、字体、作用域、回退、切换事件 |
| Command | owner/scope/permission、注册、更新、注销、invoke 事件 |
| 渲染链 | iframe/document 完整 CSS、资源 URL、CSP 和关闭清理 |

### 2.2 SDK

必须使用 `chips-sdk/testing` 的 mock Host 覆盖：

- 正常 client 创建、Bridge unavailable、timeout、retryable error；
- permission denied 的 `permission.required/granted/messageKey`；
- surface open/focus/close；
- command register/invoke/unregister；
- theme get/apply/resolve/changed；
- file/resource/card 等高频 domain 的输入校验和结果归一。

### 2.3 `@chips/ui`

- Provider 注入和 Browser no-Host；
- ConfigProvider、locale、主题 token 和 popup container；
- AppChrome 菜单、工具栏、命令面板和快捷键；
- StateBoundary 的 loading/error/empty/children 四态；
- EmbeddedDocumentFrame 的 loading/ready/error、ratio、iframe onLoad/onError、卸载；
- command adapter 与 Host registry 的重复注册、清理和错误；
- 主题切换后 CSS/ConfigProvider 生效。

### 2.4 应用

每个应用至少有：

- 根挂载和默认场景单元测试；
- 关键业务流程测试；
- command handler 测试；
- Bridge mock/权限拒绝测试；
- `chipsdev-r run` 的 Playwright 基本流程；
- `validate/package` 真实 Manifest 结果。

### 2.5 主题包

- Recipe 输入 schema、默认值、非法值和引用循环；
- token/CSS/manifest/contracts 的生成一致性；
- 每个官方主题完整构建，不允许消费陈旧 dist；
- 组件矩阵视觉快照和差异阈值；
- font/icon/CSP/iframe 资源加载；
- 缺 token、对比度不足、未知 override 时构建失败。

## 3. Playwright 真实浏览器矩阵

高风险交互至少覆盖以下场景：

1. Dialog/Drawer/Popover/Dropdown：打开、Escape、外部点击、焦点恢复、滚动；
2. Select/Tree/Tabs/Menu：键盘导航、选中、disabled、长列表；
3. Form：必填校验、异步提交、错误恢复、重复提交保护；
4. Table/List/Virtual：滚动、选择、空态、错误、窗口 resize；
5. App surface：启动参数、命令、Host action、权限拒绝和关闭清理；
6. Theme：默认主题、主题包主题、切换、iframe 完整 CSS、字体和图标。

每条场景要在失败时输出截图、DOM 快照、console、网络/Bridge action 记录和 traceId。

## 4. A11y 门禁

- 使用 axe 浏览器扫描作为自动基线；
- 手动断言可键盘到达、焦点顺序、可见 focus ring、Dialog focus trap/restore；
- 任何图标按钮有可访问名称，Tooltip 不作为唯一 label；
- 表单字段关联 label、错误状态和描述；
- 颜色对比度由主题构建和浏览器测试双重检查；
- reduced motion 下不依赖动画完成事件才能使用；
- iframe/document 场景明确 title、sandbox、跨文档键盘边界。

## 5. 真实质量门禁脚本

### 5.1 应用仓库

```text
npm run lint        # 真实 ESLint
npm run typecheck   # tsc --noEmit
npm test            # Vitest/正式测试
npm run build       # chipsdev-r build / Vite build
npm run validate    # Manifest、依赖、权限、残留、产物
npm run package     # 真实 cpk（适用时）
npm run verify      # 上述命令的严格串联
```

### 5.2 脚手架

```text
npm run build
npm test
npm run test:templates
npm run test:e2e
```

`test:e2e` 必须调用真实 CLI 生成工程；不能把模板文件直接当生成结果测试。

### 5.3 主题

```text
npm run build:theme
npm run validate:theme
npm run preview:theme
npm test
```

每次校验前清理 dist，确保源文件、生成产物和包内文件没有漂移。

### 5.4 工作区

根 `verify:workspace` 至少检查：

- workspace 成员、归档目录、版本锁定和 volta；
- 所有 active app 依赖统一；
- 脚手架与已迁移 app 结构同构；
- 文档示例不引用归档包（工单134闭环后恢复为阻断）；
- 真实生成/构建/测试报告可追溯。

## 6. 性能基线

先测量现状，再冻结预算，禁止拍脑袋写一个“性能通过”。必须记录：

- Host surface 从打开到首次可交互（TTI）；
- 应用 bundle 原始/gzip、首屏 JS、异步 chunk；
- 首次 React commit、命令注册完成、主题注入完成；
- 大列表滚动 FPS、长任务、内存增量；
- Dialog/Select 打开耗时和 Portal 布局次数；
- 主题切换 CSS 注入耗时。

基线完成后为每类应用设置预算：

| 指标 | 预算制定要求 |
|---|---|
| 启动 TTI | 以 PhotoViewer、EditingEngine 分别测 p50/p95，再由评审冻结 |
| 首屏 bundle | 记录 antd 公共基线，重型页面必须 lazy load |
| 列表滚动 | 给出数据量、窗口尺寸、设备和 p95 帧时间 |
| 内存 | 记录打开/关闭/重复打开后的增量和回收结果 |
| 主题切换 | 记录 CSS 注入和重绘时间，避免整页重建 |

使用 React/构建最佳实践：Promise 并行化、动态 import 重型场景、直接子路径导入、避免重复全局 listener、在 render 中派生状态、事件处理器中执行交互副作用、使用 functional setState 和 ref 管理瞬时值。

## 7. 质量报告

每批迁移生成 JSON/Markdown 报告，包含：

```text
commit/工作区状态（由用户管理，不自动提交）
package、Node、npm、React、antd 精确版本
执行命令和退出码
失败测试、截图、trace、错误码
bundle/performance/a11y 数值
未闭环工单和阻断项
```

没有完整报告时，不得把批次标记为完成。
