# 13 文档同步与发布规则

## 1. 文档分层

| 内容 | 正式归属 |
|---|---|
| Host/Bridge/SDK/Manifest/Theme/应用公共协议 | `生态共用技术文档/` |
| Host 内部实现和调试细节 | `Chips-Host/技术文档/` |
| SDK CLI/模板实现细节 | `Chips-SDK/`、`Chips-Scaffold/` 内部技术文档 |
| `@chips/ui` API、适配器、测试说明 | `Chips-Ui/` 技术文档；跨仓公共口径同步共用文档 |
| 单个应用业务设计和迁移记录 | 应用仓库内部文档或本目录 |
| 批次计划、工单、审查、报告 | `项目日志与笔记/` |

本第二阶段目录只保存方案和过程，不作为社区开发者的最终 API 入口。

## 4. 文档示例必须可执行

公共文档中的代码示例分三类：

1. **正式可复制示例**：必须能在生成工程中直接 typecheck/build；
2. **协议片段**：必须标注只展示类型/字段，不可直接运行；
3. **历史归档示例**：必须显式标记“归档，不作为新开发入口”。

不得把内部文件路径、临时 mock、旧包名或未发布 API 写成正式示例。新 API 的文档发布顺序为：类型 → 实现 → 测试 → CLI/脚手架 → 公共文档 → 示例生成验证。

## 5. 版本和发布规则

- 版本由用户和仓库维护方管理，本任务不提交或发布；
- `@chips/ui`、SDK、Host、脚手架和主题 Recipe 的公共 API 变更要记录精确版本和生成器版本；
- 主题产物记录 source hash、generatorVersion、themeId、appearance 和 token coverage；
- 归档材料禁止继续修改，新的有效文档放在 active 目录并在索引中说明替代关系；
- 任何文档与代码不一致都视为阻断问题，不通过“在 README 里补一句说明”长期掩盖。
