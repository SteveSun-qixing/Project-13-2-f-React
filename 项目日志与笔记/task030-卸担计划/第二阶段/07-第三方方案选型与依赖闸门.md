# 07 第三方方案选型与依赖闸门

## 1. 选型原则

第一阶段已经实测并锁定 React 18、antd 6.5.4、`@ant-design/icons` 6.3.2、dayjs 1.11.21。第二阶段优先继续使用这套成熟底座，不再因为“想要更像自研组件库”而增加另一套交互库。

任何新增依赖在进入代码前都必须提交选型记录，核对：

1. 许可证和 NOTICE 义务；
2. 发布与维护状态、issue 响应、版本策略；
3. React 18、Vite、Electron/Chromium 和 Browser preview 兼容性；
4. 包体、tree-shaking、初始化副作用和 CSP；
5. 安全公告、供应链风险、transitive dependencies；
6. 键盘、a11y、SSR/iframe（如果适用）和资源释放；
7. 是否会改变 Host、SDK、Theme Runtime 或公共协议。

涉及基础架构、长期运行时依赖或公共协议的依赖必须先得到用户确认；本方案本身不代替该确认。

## 2. 默认技术栈

| 领域 | 默认方案 | 使用边界 | 说明 |
|---|---|---|---|
| React | React 18 | 全生态统一 | 不在本阶段升 React 19；先消化现有模板和测试 |
| UI 行为 | antd 6.5.4 | 应用叶子组件和成熟交互 | 作为主要稳定行为底座，禁止同时引入第二套完整 UI 库 |
| 图标 | `@ant-design/icons` 6.3.2 | 应用 UI 图标 | 生态图标语义在 `@chips/ui/icons` 收口；launcher 资源仍走 Manifest |
| 日期 | dayjs 1.11.21 | antd 日期组件和格式化 | 不在业务中混用 moment/date-fns，除非有专项选型 |
| 样式 | antd CSS-in-JS + `@chips/ui` global CSS | 共享 token 和局部布局 | 不引入 Tailwind、UnoCSS、第二套 token 体系 |
| 表单 | antd Form | 结构化表单、校验、字段状态 | 业务 schema 与 UI schema 分离 |
| 测试 | Vitest + Testing Library + Playwright | 单元/组件/真实浏览器 | 逐仓库核对实际已安装版本和正式脚本 |
| a11y | Playwright axe 集成 | 浏览器级自动检查 | 自动检查不能替代键盘/焦点人工断言 |
| 构建 | Vite + chipsdev-r | 插件和主题 preview | 不在应用自行更换构建器 |

## 3. 按需候选，不默认加入运行时

### 3.1 复杂表格和虚拟列表

候选：`@tanstack/react-table`、`@tanstack/react-virtual`。

仅当 antd `Table` 的列模型、虚拟滚动、树表或大数据量性能实测不满足要求时，才在 `@chips/ui/adapters/table` 引入。应用不直接消费 TanStack 类型；共享层输出 Chips 的列、行、选择和错误状态接口。

准入测试：10 万行数据滚动、键盘选行、固定列、窗口 resize、卸载、内存增长和 Browser/Electron 两端结果。

### 3.2 拖放

候选：社区维护成熟的 React DnD 方案，优先选择能满足键盘拖放、触摸/指针、跨容器和卸载清理的方案。`@dnd-kit` 等候选不可直接写入运行时依赖，必须按当前维护状态和许可证重新核对。

准入测试：鼠标、键盘、触摸（若目标支持）、拖入/拖出、取消、ESC、滚动容器、跨 iframe 边界和资源清理。

### 3.3 外部状态

默认使用 React `useState/useReducer/useSyncExternalStore`。只有跨 scene 共享状态、复杂 undo/redo 或需要独立订阅时才评估 Zustand 或 Redux Toolkit；不得为了减少几个 hook 把所有页面状态搬到全局 store。

准入要求：状态快照可序列化、actions 有类型、订阅粒度可测、销毁后无 listener、测试可独立运行、不会把 Host client 放入持久化状态。

### 3.4 远程服务器状态

只有社区 Web 或确实存在缓存/失效/并发请求需求时，才评估 TanStack Query 等成熟方案。Host Bridge domain 调用不自动当成 query；文件/资源/卡片操作必须遵守 SDK 生命周期和权限语义。

## 4. 明确不选的方案

| 方案 | 不选理由 |
|---|---|
| 第二套完整 UI 库（MUI/Arco 等） | 与 antd 重复，造成 token、Portal、a11y 和包体双轨 |
| 在 `@chips/ui` 内重做所有 antd 控件 | 重新承担成熟框架的行为和回归成本 |
| 未经评估的 Ark/Zag/Radix/Tamagui 运行时替换 | 会改变第一阶段基线和组件层长期依赖；需另立选型门 |
| 自研日期/弹层/焦点/拖放状态机 | 高风险浏览器行为没有必要重新实现 |
| Tailwind/UnoCSS 作为第二 token/样式体系 | 与共享 Apple token、主题 Recipe 冲突 |
| 将 npm 包通过 Host 全局 external 注入 | 依赖 Host 版本和 CSP，增加运行时耦合，除非有包体专项数据支持 |

## 5. 依赖评估记录模板

新增包必须创建或更新内部选型记录，至少包含：

```text
包名 / 精确版本 / 使用仓库
解决的实际问题与现有方案缺口
许可证与 NOTICE
维护/发布/安全状态核对日期
React 18 / Vite / Electron / Browser 兼容性
包体（原始、gzip、异步分包后）
CSP、iframe、a11y、键盘和资源清理结果
测试计划与失败回滚方式
是否改变基础架构/公共协议
批准人和结论
```

## 6. 依赖门禁实现

在根工作区和各仓库增加真实校验：

1. 锁文件与 `package.json` 精确版本一致；
2. 禁止同一包出现多版本，或给出明确例外和原因；
3. 检查许可证报告和高风险安全公告；
4. 检查应用是否直接 import 适配器内部第三方类型；
5. 记录 bundle-size 和初始化副作用；
6. CI 中执行依赖审计，但不得用关键字扫描代替构建、测试或 a11y。

## 7. 本阶段的实际建议

先完成 antd/`@chips/ui` 的门面和质量门禁，再根据真实缺口逐项评估 TanStack table/virtual 或拖放库。不要因为旧组件库曾经自己实现过某个能力，就自动把它当成必须迁移的自研资产；稳定性优先于导出数量。
