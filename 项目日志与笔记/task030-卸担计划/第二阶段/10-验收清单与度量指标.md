# 10 验收清单与度量指标

## 1. 应用开发体验验收

### 1.1 最小应用

- [ ] CLI 可生成 `app-minimal`，无未回填占位符、旧 import、旧目录和 TODO；
- [ ] `src/main.tsx` 只负责创建 SDK client 和调用 `mountChipsApp`；
- [ ] 应用不手写 `AppProviders`、`AppRuntimeProvider`、theme runtime、window keydown listener；
- [ ] 应用业务入口可在 1 个文件中组合页面；
- [ ] 无 Host Browser preview 可运行，系统能力显示标准 unavailable 状态；
- [ ] Host surface 可读取 launch context 并执行一个正式 SDK action；
- [ ] command 菜单、工具栏、快捷键和命令面板消费同一 registry；
- [ ] 关闭 surface 后命令、事件和资源无泄漏。

### 1.2 建议度量

以下为需要在 M2 试点测量并经评审冻结的目标，不在没有基线时伪造“已达标”：

| 指标 | 目标方向 |
|---|---|
| 最小应用框架文件 | 只保留入口、App、配置、业务和测试；框架 Provider 文件为 0 |
| 首个业务页面接线 | 新开发者只需修改 1~2 个业务文件 |
| 平台样板代码 | 相比第一阶段 app-standard 模板显著下降，记录删除行数和新增共享层行数 |
| 直接 Bridge 调用 | 业务源码 0 次，全部经过 SDK/domain hook |
| 私有基础控件/token | 审计 0 个；例外必须有工单和期限 |
| 生成工程可运行性 | create 后一次 `verify` 通过 |

## 2. `@chips/ui` 验收

- [ ] 根入口和子路径 exports 有明确边界；
- [ ] React 18 类型、antd 精确版本和 `volta` 工作区规则一致；
- [ ] `mountChipsApp` 在 Host、Browser、Vitest 三种环境可用；
- [ ] Provider 不创建重复 client、不安装重复全局 listener；
- [ ] command adapter 支持 register/unregister/invoke、owner/session、权限和错误；
- [ ] AppChrome、StateBoundary、EmbeddedDocumentFrame 有完整状态和 a11y 测试；
- [ ] shared token 只在一个事实源维护；
- [ ] 共享层不包含应用业务字段和私有路径；
- [ ] package build/typecheck/test 通过，生成 `.d.ts` 与源码一致。

## 3. 组件稳定性验收

对每个高风险组件填写矩阵：

- [ ] controlled/uncontrolled 行为；
- [ ] disabled/readOnly/loading/empty/error；
- [ ] keyboard/focus/ARIA；
- [ ] Portal/滚动/窗口 resize；
- [ ] mount/unmount 清理；
- [ ] 默认主题和至少一个 Recipe 主题；
- [ ] Desktop Host 和 Browser preview；
- [ ] Playwright trace/screenshot；
- [ ] axe 无新增严重/高等级问题；
- [ ] 性能基线无超预算长任务或内存增长。

不以“导出了多少组件”作为完成标准。组件只有在行为和质量矩阵通过后才加入公共文档和脚手架索引。

## 4. 主题 Recipe 验收

- [ ] 一个主题的作者源文件不需要手写每个组件 CSS；
- [ ] `chipsdev-r theme create --mode recipe` 生成完整工程；
- [ ] Recipe 编译生成 `manifest/tokens/theme.css/config/contracts/preview`；
- [ ] 全量 token coverage = 100%；未知 token/override 让构建失败；
- [ ] 对比度、字体、图标、CSP、路径和包体检查通过；
- [ ] Host 安装、列出、应用、注入、切换、回退全链路通过；
- [ ] iframe/document 看到完整 CSS 和 `@font-face`；
- [ ] 两个 themeId 之间切换无旧 CSS 残留；
- [ ] 源 hash 与 dist hash 一致，禁止陈旧产物发布；
- [ ] 主题包不含 React、SDK、Host 私有实现或远程资源。

## 5. Host/SDK/Manifest 验收

- [ ] active app 的 Manifest 与实际 SDK action/权限一致；
- [ ] surface session 启动顺序、launchContext 字段、关闭清理有 Host 测试；
- [ ] Bridge 最小权限暴露，Browser 没有 Bridge 时行为可预测；
- [ ] route timeout、retry、permission denied、standard error 保持一致；
- [ ] command registry 的 owner/scope/permission/handlerId 语义通过；
- [ ] theme runtime 的默认/自定义/失败回退通过；
- [ ] 文档示例、脚手架模板和实际代码同构；
- [ ] `chipsdev validate`、`package` 和真实 Host `run` 可连续执行。

## 6. 质量和性能出口

- [ ] `tsc --noEmit` 0 错误；
- [ ] ESLint 0 error，warning 有明确处理或基线记录；
- [ ] Vitest 通过；
- [ ] Playwright 高风险矩阵通过；
- [ ] axe 和键盘专项通过；
- [ ] bundle、TTI、滚动、内存、主题切换有 p50/p95 报告；
- [ ] 没有用静态关键字扫描替代上述任何真实检查；
- [ ] 所有阻断工单已闭环或经用户明确接受为阶段外风险。

## 7. 抽样验收用例

### 用例 A：创建普通应用

1. 执行 `chipsdev-r create app --template app-minimal`；
2. 只修改 App 页面和一个 command handler；
3. 执行 `npm run verify`；
4. 用 `chipsdev-r run` 打开；
5. 通过命令面板执行打开文件；
6. 拒绝文件权限并确认页面显示可理解错误；
7. 关闭窗口并检查 command/event/resource 清理。

### 用例 B：创建主题包

1. 执行 `chipsdev-r theme create --mode recipe`；
2. 只修改 palette、typography、shape；
3. 执行 build/validate/preview；
4. 在预览矩阵检查控件状态；
5. 安装到开发 Host，应用主题到 PhotoViewer；
6. 打开卡片/布局 iframe，确认字体和图标显示；
7. 引入未知 override，确认构建阻断；
8. 删除主题或模拟解析失败，确认回退默认主题。

## 8. 阶段完成判定

第二阶段只有在“应用体验、组件行为、主题产物、Host/SDK 链路、真实门禁和公共文档”六类均有报告时才可标记完成。任何一类只有 README 或静态扫描，没有对应真实测试，均视为未完成。
