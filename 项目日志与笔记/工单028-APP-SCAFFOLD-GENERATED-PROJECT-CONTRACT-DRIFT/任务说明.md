# 工单028：应用插件脚手架生成工程存在模板元数据泄漏与文档/模板契约漂移

## 1. 背景

在为 `Chips-EditingEngine` 执行应用插件脚手架初始化、并准备进入编辑引擎迁移方案评审时，对 `chips-scaffold-app` 的生成结果进行了核对。

本次核对的目标不是修改脚手架，而是确认“官方应用插件脚手架”是否已经满足编辑引擎项目的正式初始化基线。

## 2. 发现的问题

### 2.1 模板元数据文件被错误复制进生成工程

通过脚手架初始化后，生成工程中出现了：

- `/Users/sevenstars/Documents/ChipsCard/Develop/Project-13-2-f/Chips-EditingEngine/template.json`

该文件属于模板元数据，本应只存在于：

- `/Users/sevenstars/Documents/ChipsCard/Develop/Project-13-2-f/Chips-Scaffold/chips-scaffold-app/templates/app-standard/template.json`

它不应作为业务工程运行时或源码组成部分出现在正式生成工程中。

### 2.2 模板 README 与实际生成结构存在漂移

生成工程 `README.md` 中声明存在：

- `src/layouts/`

但当前标准模板并未生成该目录。

这会导致新项目初始化后，项目说明与真实结构不一致，影响后续项目规范化推进。

### 2.3 模板示例与规范存在轻微偏差

根据当前脚手架模板与生态文档比对，还观察到以下偏差：

- 部分示例文案仍以硬编码形式保留在模板代码中，与“正式用户文案必须走多语言资源”的项目规范不完全一致；
- `tests/e2e/basic-flow.test.ts` 名义上属于 E2E，但当前更接近 Vitest 级别示例测试，而非真实浏览器/Host 端到端链路验证。

## 3. 影响范围

- 所有通过 `chipsdev create app` 初始化的新应用插件工程；
- 编辑引擎项目的正式初始化基线；
- 后续其他应用插件项目对官方脚手架输出质量的信任度；
- README、目录结构、测试分层等规范的一致性。

## 4. 根因判断

当前 `chips-scaffold-app` 的模板渲染实现采用“整目录复制 + 占位符替换”的方式，未显式排除模板元数据文件 `template.json`。

同时，模板 README 与测试示例的维护未完全和模板真实输出结构、生态当前质量门禁同步更新，造成了文档/模板契约漂移。

## 5. 复现步骤

1. 在生态根目录运行应用插件脚手架初始化，创建新工程 `Chips-EditingEngine`。
2. 查看生成目录。
3. 观察生成工程中包含 `template.json`。
4. 打开生成工程 `README.md`，观察其中描述的目录与实际结构不完全一致。
5. 对照模板代码与生态共用技术文档，观察文案与测试命名存在偏差。

## 6. 期望行为

- 生成工程不应包含任何模板内部元数据文件；
- 生成工程 README 应严格反映真实目录结构与实际开发规范；
- 模板示例文案应完全符合多语言规范；
- E2E 示例命名与实际测试层级应一致，避免误导。

## 7. 暂行处理

- 已先记录工单，不对脚手架做临时本地绕过修补；
- 当前编辑引擎项目已完成“脚手架初始化 + 文档规划”，但根据仓库规则，不继续推进后续正式开发；
- 等待脚手架问题由相应维护方处理或明确裁定后，再继续下一阶段。

## 8. 需要协作方

- `Chips-Scaffold/chips-scaffold-app` 维护方
- `Chips-SDK` / `chipsdev create` 链路维护方
- 生态文档与质量门禁维护方

## 9. 当前结论

该问题属于官方应用插件脚手架输出质量与正式契约的一致性问题。虽然不影响“空工程生成成功”，但会影响编辑引擎等正式项目的初始化基线质量，因此应先作为正式工单处理。


## 10. 正式处理结果（2026-03-11）

- `Chips-Scaffold/chips-scaffold-app/src/core/template-engine.ts` 已新增模板内部文件排除逻辑，`template.json` 不再写入生成工程。
- `Chips-Scaffold/chips-scaffold-app/tests/template-engine.test.ts` 与 `scripts/run-generated-e2e.mjs` 已补充“生成工程不得出现 template.json”断言。
- `Chips-Scaffold/chips-scaffold-app/templates/app-standard/README.md.tpl` 已修正文档结构漂移，移除错误目录并明确 `tests/e2e` 的 smoke 定位。
- `Chips-Scaffold/chips-scaffold-app/templates/app-standard/src/App.tsx.tpl`、`src/components/ExamplePanel.tsx.tpl`、`i18n/*.json.tpl` 已完成文案去硬编码与运行时主题/语言基线修正。
- `Chips-EditingEngine` 已将泄漏进工程的 `template.json` 与旧脚手架示例代码归档，并基于修正后的基线开始阶段二开发。
- 验证结果：脚手架仓 `npm test`、`npm run test:templates`、`npm run test:e2e` 通过；编辑引擎仓 `npm run lint`、`npm test`、`npm run build`、`npm run validate` 通过。
