# 工单065：打包器与安装校验的 assets 扩展名白名单缺 `.codepoints` 登记

- 登记日期：2026-10-01
- 登记方：W5 图标工坊业务迁移路（`plugins/apps/icon-maker`，W5 派单行表 #6 第③段）
- 状态：开放·待派单（工具链面归 `packages/cli` 与 `packages/host` 独占，本路禁改）

## 背景

《旧功能覆盖矩阵-SDK与工具类-2026-09-20.md》§三对 `chips.official.iconmaker` 的迁移裁决把
「Material Symbols 字体 woff2×3 + codepoints + SOURCE.md（5 件）」列为**迁移**资产；《09-官方插件与应用目录》:228
登记图标工坊「字体选形（default-fonts+codepoints+woff2 迁移）」。W5 第③段迁移已按裁决把四件字体资产
（Rounded/Outlined/Sharp woff2 + `MaterialSymbolsRounded[FILL,GRAD,opsz,wght].codepoints`）落入
`plugins/apps/icon-maker/assets/fonts/material-symbols/variablefont/`，领域层 `default-fonts.ts` 以包内相对
URL 拉取该码位表构建完整字形集合（36 条精选字形为离线兜底）。

## 证据（机检实测，2026-10-01）

1. `chips plugin pack`（`packages/cli/src/artifacts/cpk-pack.ts` 打包链）执行 `chips plugin validate` 五阶段时，
   manifest 阶段之后在 layout 阶段拒绝：

   ```text
   assets/ 只允许登记的资源类型：assets/fonts/material-symbols/variablefont/MaterialSymbolsRounded[FILL,GRAD,opsz,wght].codepoints
   code: CPK_LAYOUT_INVALID
   ```

2. 权威清单两处同源缺登记：
   - `packages/cli/src/artifacts/cpk-validate.ts:75-93` `ASSET_EXTENSIONS`（无 `.codepoints`）；
   - `packages/host/src/loader/validate.ts:86-104` `ASSET_EXTENSIONS`（无 `.codepoints`，安装校验同口径）。
3. 上游冻结母本（`design-assets/material-symbols/`，阶段04任务09）以 `.codepoints` 为正式文件名形态，
   生态单一来源与其 SOURCE.md 文件清单均按此名登记；`.txt` 后缀改名即偏离母本命名与矩阵裁决资产名。

## 影响范围

- 图标工坊的 `.cpk` 打包与安装链路（应用分发态）无法携带码位表资产；四闸（test/typecheck/lint/build）
  与包内功能不受阻，受阻面仅在打包/安装校验阶段。
- 未来任何携带「字典/映射表类文本资产」的官方包（如其他图标字体 codepoints、码位字典）复现同缺口。

## 复现步骤

1. `cd chips-ecosystem/plugins/apps/icon-maker`
2. `npx -y pnpm@9 exec chips plugin pack --out dist/`
3. 观察上述 `CPK_LAYOUT_INVALID`（stage=layout，file=codepoints 路径）。
