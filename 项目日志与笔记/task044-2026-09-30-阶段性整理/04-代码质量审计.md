# 04 · 代码质量审计

> task044 · TS 六包 + Rust 五 crate + 插件七包 + 工具四件，独立抽样 + 红线扫描

## 一、总裁定

**代码本体质量：高，可信。** 用户「质量无法确认」的怀疑在代码域**缺乏证据支撑**：零 TODO/FIXME、零 any（TS src 面）、零 unsafe（Rust 全 crate `#![forbid(unsafe_code)]`）、零非测试 panic、零第二组件库、零绕桥直连；架构红线（内核路由/window.chips 唯一门/SDK 不承载运行时/分层禁反向依赖）逐项核对无违规。问题全部集中在**过程层**（未提交、门禁失守、文档漂移），不在代码层。

## 三、Rust 五 crate（A6）

chips-core 1,554 行 / chips-cordis 9,101（测试占 31%）/ chips-bridge 4,193（57%）/ chips-parser 14,075（23%）/ chips-resource 17,244（32%）。

架构要求逐项落实（证据在 `chips-cordis/src/`）：命令循环单写者（command.rs:13,147-157）、Fork 可逆副作用 LIFO（fork.rs:1-60）、暂存代际原子发布（kernel.rs:114,665-764）、不持锁 await、崩溃隔离 catch_unwind 四处包裹（kernel.rs:572 等）、熔断 10min≤3 次+退避（constants.rs:46-55）、生命周期超时/配额常量齐全（constants.rs:11-43）、解析器只读合规。

chips-resource 锁中毒惯用法：`.lock().expect("…锁不得中毒")` src 面 28 处——风格选择而非错误处理缺失，但与「崩溃隔离」哲学张力，建议后续收口（非阻断）。

native：单入口 `#[neon::main]`→`export_table!` 宏同源生成 56 导出与清单，契约测试锁死；离线可测注入点齐备（工单012 收口有效）。
