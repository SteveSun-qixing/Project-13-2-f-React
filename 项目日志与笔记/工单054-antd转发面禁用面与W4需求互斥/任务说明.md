## 一、背景

W4（三插件仓）与 W5（13 应用仓）在把旧仓界面迁到 `antd + @chips/ui` 合规面时，需要一个「数值输入 / 树形导航 / 取色 / 二次确认」四类常用件。#214 的切分审计把 Tree 与 ColorPicker 记成「`@chips/ui` 供给面缺件、W4 硬阻塞」，#224 的收支波进一步把 InputNumber 与 Popconfirm 记成「代码未转发的缺件」并建议派「补件波」。

主智能体复核后判定：**该定性不成立**。这四枚组件不是「漏转发」，而是被一条**显式禁止清单**排除在生态公共面之外；同时脚手架门禁已经在按这条禁面执法。因此「补件波」这一处置方式会直接改动一个已裁定的封闭设计面，属架构级取舍，不能由派单侧自行决定。

## 三、影响范围

- 直接受阻面：W4 三插件仓的编辑器面板（数值参数：尺寸、间距、圆角、时长、分值），W5 的 `Chips-Notes` 目录树面板、`Chips-UniversalFileViewer` 工具栏、`Chips-EcoSettingsPanel` 组件画廊。
- 连带面：若维持禁面不动，上述面板迁移时需逐处改写为已允许件（`Form` + `Input` + 自校验、`List` 手写树、`Popover` 手写二次确认），改写量随仓数放大且会偏离旧仓交互一致性。
- 不受影响面：卡片/布局渲染主链、宿主与内核链路、Rust 侧资源面——本单纯前端公共组件面。

## 四、复现步骤

1. 在 `chips-ecosystem/packages/antd` 下运行 `pnpm test`（或定向 `vitest run tests/export-surface.test.ts`），可见 42 项允许面 + 28 项禁面双向锁测；把 `InputNumber` 加入 `packages/antd/src/components/index.ts` 转发面即触发禁面锁测红。
2. 在 `chips-ecosystem/tools/scaffold` 运行 `pnpm test`（templates 面），生成模板若出现 `InputNumber` 字样即红（`:251`）。
3. 任一上层应用 import `InputNumber`：生态面无合法导入路径（`@chips/ui` 未导出、fork 直连违反《08》§2.5 禁止事项）。

## 五、期望行为（三条候选路，如实并列，不预设结论）

- **A 扩表入白名单**：把需求确证的件（至少 `InputNumber`，按需 `Tree`/`Popconfirm`）从禁面移入 42 项允许面，同步 ①`packages/antd/src/components/index.ts` 转发与 fork 锁测、②《09-统一视觉规范》§3.4 组件级 token 定制基线随动（否则该件无定制口径）、③《08》§2.6 列举与 `@chips/ui` README 收支、④脚手架反向锁测改写为「允许面语义」。代价：公共组件面永久变宽，主题与可访问性口径需逐件补齐。
- **B 由 `@chips/ui` 自研封装件承载**：fork 面一字不动，禁面继续执法，由共享层新增自研件（如数值输入、树形导航）承担需求，对外只暴露 `@chips/ui` 导入面。代价：共享层承担实现与维护成本、与旧仓交互差异需回归；收益是生态「唯一导入面」叙事最干净。
- **C 维持禁面、上层改写**：本单转为「迁移改写规范」条目，W4/W5 派单书点名四类件一律用已允许件重写。代价：逐处重复实现、跨仓一致性靠人盯；收益：设计面零变化。

## 六、暂行处理

零。本轮不私自扩白名单、不自造绕过件、不让上层仓直连 antd、不放宽任何锁测。W4/W5 派单书在本项裁定前一律点名回避四类件（禁改清单式表述），确需该四类件的面不派。
