# 工单030：tools/testing vitest 配置无扩展名 ESM 导入致根级 vitest 启动即崩

> 登记：W2 工单024 波F（#76）交回时登记，主智能体核证后入册
> 日期：2026-09-20

## 一、问题

`chips-ecosystem/tools/testing/src/vitest.ts` 第 35 行使用无扩展名相对导入：

```ts
import { COVERAGE_THRESHOLDS, type CoverageThreshold } from './thresholds';
```

该文件在两个执行面下行为分叉：

- 由各包 `vitest.contract.config.ts` / 包内配置经 vite 打包器解析加载时，bundler 解析允许无扩展名，正常工作；
- 由 **chips-ecosystem 根目录**直接 `pnpm vitest run tests/contract/<任意契约测试文件>`（根级 Node ESM 加载配置链）时，Node ESM 严格解析拒绝无扩展名相对导入，配置加载即抛 `ERR_MODULE_NOT_FOUND`，**任何**契约测试文件（含既有 `tests/contract/tests/errors.test.ts`）在根级启动即崩，尚未进入测试执行。

## 二、影响范围

- 代码面：`chips-ecosystem/tools/testing/src/vitest.ts`（导入语句）；`thresholds.ts` 本身无需改动。
- 消费面：根级 vitest 直跑契约测试的命令口径不可用；各包内 `test:contract` 不受影响（经打包器解析路径），已验收入库的各波（含工单024 波F 锚点）结论不受影响。
- 附带影响：根级口径不可用迫使验收绕行包内直跑，增加口径漂移风险。

## 三、证据

1. `chips-ecosystem/tools/testing/src/vitest.ts:35`（无扩展名相对导入逐字核实）。
2. 波F 执行记录：根级 `pnpm vitest run tests/contract/tests/chips-error-uniqueness.test.ts` 启动即崩；同命令对既有 `errors.test.ts` 同样崩（证明非新锚点文件问题）；包内直跑（`tests/contract` 目录内 `pnpm exec vitest run ...`）EXIT=0。
3. 崩溃归因定位：`tools/testing/src/vitest.ts:35` 对 `./thresholds` 的无扩展名 ESM 导入。

## 四、期望行为与验收口径

- 期望：根级 `pnpm vitest run tests/contract/<文件>` 与包内直跑两口径均可启动并执行（导入改为 ESM 兼容形式，不改任何断言语义与覆盖率阈值表内容）。
- 验收：
  1. 根级 `pnpm vitest run tests/contract/tests/errors.test.ts` 与包内直跑同文件均 EXIT=0；
  2. `pnpm -r run test:contract` 结果与当前基线一致（唯一红仍为 cpk-fixtures，归 #56 段三在册口径）；
  3. 覆盖率阈值表（`thresholds.ts`）内容零变化，各包覆盖闸行为不变。
- 暂行处理：验收一律走包内直跑口径；根级口径在本工单收口前不作为权威命令。
