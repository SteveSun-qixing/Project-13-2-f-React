## 一、问题

`chips-ecosystem/tools/testing/src/vitest.ts` 第 35 行使用无扩展名相对导入：

```ts
import { COVERAGE_THRESHOLDS, type CoverageThreshold } from './thresholds';
```

该文件在两个执行面下行为分叉：

- 由各包 `vitest.contract.config.ts` / 包内配置经 vite 打包器解析加载时，bundler 解析允许无扩展名，正常工作；
- 由 **chips-ecosystem 根目录**直接 `pnpm vitest run tests/contract/<任意契约测试文件>`（根级 Node ESM 加载配置链）时，Node ESM 严格解析拒绝无扩展名相对导入，配置加载即抛 `ERR_MODULE_NOT_FOUND`，**任何**契约测试文件（含既有 `tests/contract/tests/errors.test.ts`）在根级启动即崩，尚未进入测试执行。

## 二、影响范围

- 代码面：`chips-ecosystem/tools/testing/src/vitest.ts`（导入语句）；`thresholds.ts` 本身无需改动。
- 消费面：根级 vitest 直跑契约测试的命令口径不可用；各包内 `test:contract` 不受影响（经打包器解析路径），已验收入库的各波（含工单024 波F 锚点）结论不受影响。
- 附带影响：根级口径不可用迫使验收绕行包内直跑，增加口径漂移风险。

## 六、收口记录（2026-09-21，W2 任务 #84）

### 6.1 根因复确认

- Node v24.11.1 原生 type-stripping 下实测（/tmp 探针）：`.ts` 文件的 ESM 导入说明符**不做** `.js`→`.ts` 映射，`./thresholds.js` 同样抛 `ERR_MODULE_NOT_FOUND`；只有**真实带扩展名**（`./thresholds.ts`）或**可经 exports 解析的 bare 子路径**在 Node 严格解析下可达。故修复形态取显式扩展名/exports 子路径，而非 `./thresholds.js` 惯例写法。
- `tools/testing` 无 dist 产物面（`build` 即 `tsc --noEmit` 类型检查，`exports` 直接指向 TS 源），源码为唯一形态，修复即两形态（默认 bundle 加载器 / `--configLoader runner`）同时成立。

### 6.2 改动清单（全部限于 tools/testing 配置源码面，阈值表与断言零变化）

| 文件 | 改动 |
| --- | --- |
| `chips-ecosystem/tools/testing/src/vitest.ts` | 崩溃点：`from './thresholds'` → `from '@chips/testing/thresholds'`（包内自引用 exports 子路径；Node ESM 严格解析、tsx、esbuild 打包加载器、vite-node runner 加载器四解析面均可达，且不会要求消费方包（如 `@chips/ui`，禁改面）的 tsconfig 开 `allowImportingTsExtensions`）；头注同步登记 ESM 说明符纪律 |
| `chips-ecosystem/tools/testing/src/coverage/cli.ts` / `run.ts` / `gate.ts` / `model.ts` / `parse.ts` / `runner.ts` | 同类无扩展名相对导入一次清全：全部改为显式 `.ts` 扩展名（`./runner.ts`、`./gate.ts`、`../thresholds.ts` 等，共 13 处）；该面当前仅经 tsx/vite 加载（宽松），本项为消除第二处潜在崩溃的预防性清面 |
| `chips-ecosystem/tools/testing/tsconfig.json` | 增 `allowImportingTsExtensions: true`（该包 `noEmit` 类型检查形态，合法前提）；使上述 `.ts` 说明符与 `@chips/testing/thresholds` 自引用在 tsc 下均通过 |

- 消费包 `@chips/ui` 的 typecheck 经 paths 把 `src/vitest.ts` 拉入其编译面，故该文件不能用显式 `.ts` 相对说明符（会触发消费方 TS5097，而 `packages/**` 为禁改面）——自引用 exports 子路径是两全形态，已在 `@chips/ui` typecheck/test 实测验证。
- `thresholds.ts`、`dom-setup.ts`、各包配置、tests/contract 断言、根 `vitest.config.ts`：零改动；无扩展名问题的其余出现面（tools/testing 自身 tests、包内 `vitest.config.ts` 的 `./src/vitest`）经 vite/esbuild 打包器解析路径加载，实测无崩溃，不属本单清面范畴。
