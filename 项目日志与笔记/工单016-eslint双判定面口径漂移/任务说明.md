# 工单016：eslint 双判定面口径漂移——包级配置非类型感知导致包 lint 永绿、根口径可红

> 状态：已收口（2026-09-20）——唯一权威判定面=根 `eslint.config.mjs`；5 份包级配置入各包 `归档/eslint-config-工单016收口/`，树内配置结构性唯一；蕴含性双向负证据与全工作区 lint 真实退出码见同目录 `RFC-lint判定面统一.md` §三（`开发计划.md` 记录形态修订过程）。

## 背景

task043 重构 W1 的 FIX-LINT-ROOT（#9/#13）过程中反复出现同一结构性现象：各包自己的 `eslint.config.mjs` 与根 `eslint.config.mjs` 是两套互不相干的规则面，包级 `pnpm --filter <pkg> lint` 长期绿灯，而根口径 `npx eslint .` 同期可对同批文件报出上百条错误。#9 收口后该结构原样保留，属工具链与门禁设计缺口，不在本轮修复范围内，按《问题发现与工单》规则登记。

## 证据

1. 规则面差异（2026-09-20 实测读取）：
   - `chips-ecosystem/packages/bridge/eslint.config.mjs`：仅挂 `js.configs.recommended` + `tseslint.configs.recommended`（**非类型感知**）+ 三条自定义规则。
   - `chips-ecosystem/eslint.config.mjs:83`：`...tseslint.configs.recommendedTypeChecked` + `parserOptions.projectService`（**类型感知**），另含 import 边界限制与 `eslint-config-prettier`。
2. 漂移显形记录（`项目日志与笔记/task043-生态梳理/00-工作日志.md` Checkpoint 05/06）：`packages/cli` 在包级 lint 与 typecheck、465 用例全绿的同时，根配置口径报 108~119 errors（含 ~103 条 `require-await` 类仅类型感知可见规则），直至 #13 专项收口才归零。
3. `chips-ecosystem/package.json` 根 `lint` 脚本 = `eslint . && prettier --check . && cargo fmt --check && cargo clippy`，与包脚本 `"lint": "eslint ."`（各包目录内、读包级配置）并行存在，两者判定结果互不蕴含。
4. Checkpoint 06 同时记录的根配置细节缺口：根 `no-unused-vars` 缺 `varsIgnorePattern`；`no-base-to-string` 存在盲区残留。

## 影响

- 假绿风险：包级门禁（`pnpm -r lint`）永远发现不了类型感知类缺陷（悬空 Promise、误用 thenable、无意义 await 的 async 标注等），这类错误只在根口径显形，而根口径修复成本被推迟集中爆发（本轮 245→0 即为该债务的一次性清偿）。
- 门禁语义不清：CI 聚合 `pnpm ci` 跑根 lint；包级脚本保留第二口径，两者对「lint 通过」的定义不一致，后续智能体与开发者以哪面为准无文档规定。
- 与《代码组织规范》的单一事实源原则冲突。

## 期望行为（验收）

- lint 判定面收敛为单一事实源：包级配置与根配置的规则集合要么同源继承（包配置显式复用根配置/共享 preset），要么文档明确规定唯一权威判定面并废弃另一面的独立口径。
- 任一执行面红必须蕴含另一执行面对同批文件红（或差异有文档化的白名单解释）。
- 收口过程不允许通过放宽根类型感知规则或加 disable 注释来拉平差异。
- 本工单只登记问题与证据，具体收敛方案（共享 preset 或判定面合并）由 RFC 裁决后落地。
