# 工单 018：gitignore 通配吞没在用源码，已提交历史与 fresh-clone 完整性受损

> 登记日期：2026-09-20

> 发现途径：工单 017 收口提交前 `git status` 异常（大面积改动不可见），`git check-ignore -v` 定位

## 一、问题

仓库根 `chips-ecosystem/.gitignore` 与生态工作区根 `.gitignore` 中的多条通配规则按"产物目录/产物文件名"直觉书写，未做路径锚定，导致同名**在用源码与门禁测试输入**被整体忽略、从未入库：

1. `chips-ecosystem/.gitignore` 的 `coverage/`（未锚定，等价任意深度匹配）吞掉 `tools/testing/src/coverage/` 整个覆盖率判定子系统源码（`cli.ts / g6.ts / gate.ts / model.ts / parse.ts / run.ts / runner.ts` 共 7 个源文件）。该目录同时是 vitest 报告产物名，规则按目录名匹配无法区分二者。
2. 工作区根 `.gitignore` 的 `output/`（未锚定）吞掉 `chips-ecosystem/packages/cli/src/output/`（`io.ts / progress.ts / result.ts`），而这三个文件被 `main.ts:7`、`tui/run.ts:6`、`plugin-cli/execute.ts:16-17`、`commands/*` 直接 import，是 CLI 运行链路的一部分。
3. `chips-ecosystem/.gitignore` 的 `render.js`（裸文件名）按名字吞掉一切 `render.js`——包括《CI/CD 与质量门禁》G5 入口门禁明确要求的插件入口：`examples/plugins/hello/render.js` 与 `tools/gates/tests/fixtures/entries-{good,bad,binary}/render.js`。
4. `tools/gates/tests/fixtures/coverage-*/coverage/*`（9 组门禁测试的报告输入夹具）被 `**/coverage/` 吞掉；`tools/gates/tests/fixtures/entries-*/dist/index.js`（check-entries 门禁的入口夹具）被 `**/dist/` 与 `chips-ecosystem/.gitignore` 的 `dist/` 双层吞掉。这些夹具从不在库中，`pnpm gates:test` 在新克隆上不可复现。

## 二、证据

- `git check-ignore -v` 实测（修复前）：
  - `chips-ecosystem/.gitignore:3:coverage/` → `tools/testing/src/coverage/g6.ts`、`gate.ts`
  - `.gitignore:26:output/` → `packages/cli/src/output/io.ts`、`progress.ts`、`result.ts`
  - `chips-ecosystem/.gitignore:5:render.js` → `examples/plugins/hello/render.js`、`tools/gates/tests/fixtures/entries-good/render.js`（bad/binary 同）
- `git ls-files tools/testing/src` 修复前仅 3 个文件（`dom-setup.ts / thresholds.ts / vitest.ts`），`src/coverage/` 下 0 个；`git log --oneline -1 -- chips-ecosystem/.gitignore` 显示该文件系 `50a76bc0`（2026-09-20）一次性引入，规则未区分产物与源码。
- 修复前全仓审计（`git ls-files --others --ignored --exclude-standard` 过滤产物与 node_modules 后）确认受吞没人用源文件即上述四组，无其他残余。

## 三、影响

- **资产缺失**：工单 017 之前的历次提交（如"覆盖率门禁双执行面收口"）声称完成的 `tools/testing` 覆盖率子系统，其核心源码实际从未入库；同名隐患同样适用于 CLI 输出层与 G5 入口夹具。
- **fresh-clone 断裂面**：新克隆缺失 ①`@chips/testing` 覆盖率运行器与 G6 委托执行（`report:coverage`、`test:coverage` 判定链直接崩）；②`@chips/cli` 的 output 模块（build 与 test 均断）；③`pnpm gates:test` 中 check-coverage / check-entries 的 fixture 用例（读不到输入即失败）；④hello 示例插件与 G5 入口门禁夹具。
- **门禁可信度**：本地全绿（lint/typecheck/test/gates/build 均 exit 0）掩盖了库内事实上的文件缺失，CI 环境一旦从干净检出运行即显红。
