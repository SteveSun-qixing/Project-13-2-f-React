## 二、P0：必须立即修复的问题（Bug 级）

### 2.1 快捷键三重触发（严重 Bug）

**现状**：同一按键在三个层级同时生效：

1. 共享层 `useCommandShortcuts`（window keydown）：`togglePlayback=" "`、`rewind10="ArrowLeft"`、`forward10="ArrowRight"`、`volumeUp="ArrowUp"`、`volumeDown="ArrowDown"`、`toggleMute="M"`、`toggleLoop="L"`（`music-player-commands.tsx`）
2. `MusicPlayerStage` 的 `controller.handleKeyDown`（shell keydown，`useMusicPlayerController.ts:168`）：空格/方向键/M/L 同样处理
3. 浏览器原生：焦点在任意 `<button>` 上按空格会触发按钮 click

**后果**：
- 焦点在"播放/暂停"按钮上按空格 → 按钮 click + shell keydown + window keydown = **播放状态翻转 3 次**（看起来"没反应"）；
- 焦点在任意按钮上按 → 方向键 = **后退/前进 20 秒**（双重触发）；
- 与 `@chips/ui` 命令面板等共享层快捷键存在全局冲突面。

**修复方案**：
- 明确快捷键唯一归属：**所有快捷键统一走共享层 `useCommandShortcuts`（命令系统）**，删除 `handleKeyDown` 中重复分支，或反之（二选一，推荐前者）；
- `useCommandShortcuts` 的排除列表补充 `button`/`[role="button"]`（共享层改动，注意其他应用影响——需评估后统一）；
- `handleKeyDown` 中 `isInteractiveTarget` 增加 `button` 排除，且 shell keydown 先 `event.preventDefault()` 再分发，避免与按钮原生行为叠加；
- 增加一条回归测试：焦点在播放按钮上按空格只触发一次播放/暂停。

### 2.2 空格键在 IME/按钮场景的误触发

`useCommandShortcuts` 与 `handleKeyDown` 对中文输入法（IME 组合中按空格选词）无防护——`isEditableTarget` 只查 input/textarea/contenteditable，不查 `isComposing`。应在两个入口都加 `event.isComposing` 判断。

### 2.3 音量静音态与滑块不同步

`volumeinput` 的 `value` 在静音时显示 0（`MusicPlayerStage.tsx:886`），但 `setVolumeLevel` 中 `normalized > 0` 才记录 `previousVolume`——**滑块拖到 0 时不会静音恢复**（拖到 0 再点静音图标，恢复的是旧值而非 0）。语义应为：拖到 0 = 静音，拖离 0 = 取消静音。

## 三、交互与功能重新设计（对标世界级）

### 3.1 播放模式体系（高优先级）

**现状**：只有 `loop one / off` 两种（`useMusicPlayerController.ts`），播放完队列最后一首**直接停止**。

**世界级标准**（Apple Music/Spotify 三态 + 随机）：

| 模式 | 行为 | 优先级 |
|---|---|---|
| 顺序播放（默认） | 播放完最后一首停止（当前行为） | — |
| 列表循环 | 播放完最后一首回到第一首继续 | P0（缺失） |
| 单曲循环 | 当前行为 | ✓ |
| 随机播放 | 洗牌队列；上一首回到随机历史 | P1 |

实现要点：
- `loopMode: "off" | "queue" | "one"` 三态循环按钮（图标：箭头、列表循环、单曲循环，激活态高亮）；
- 随机用 Fisher-Yates 洗牌 + 历史栈（`previousTrack` 在随机模式下回退到上一首，而不是换一首），这是"专业感"关键；
- 循环/随机模式**持久化**（见 3.8）。

### 3.2 队列面板（高优先级）

**现状**：队列只是文本 "3 / 10"（`queueStatus`），无任何队列 UI；打开新文件**整队替换**（`AppRuntimeProvider.tsx:573`），无追加选项。

**世界级标准**（Spotify 右侧队列面板）：

- **打开文件对话框增加"追加到队列 / 替换队列"选项**（`platform.openFile` 的 allowMultiple 已有，补一个选择语义）；
- 新增队列抽屉（右侧滑出，毛玻璃，`@chips/ui` 或 antd Drawer 定制）：
  - 当前播放行高亮 + 呼吸指示条；
  - 点击行跳转播放；拖拽排序（可用 HTML5 drag 或简化上下箭头）；
  - 行右键菜单：播放、从队列移除、移动到顶部、清除队列；
  - 显示每首时长、封面缩略图；
  - 空队列状态引导"拖入或打开音频文件"；
- 队列状态文本变为可点击（点击打开队列面板）。

### 3.3 歌词交互（高优先级）

**现状**：歌词只读展示，不可交互；无双语/翻译；无逐字效果。

**世界级标准**（Apple Music 歌词页）：

- **点击歌词行跳转到该时间点**（timed 模式下 `seekTo(line.startTime / 1000)`），悬停显示小手+时间提示；
- 长歌词自动分页/缩放字号（当前 40px 大字，长句换行后滚动布局复杂——建议按歌词长度动态 clamp）；
- **逐字卡拉 OK**（可选，P1）：按字节时长分布 `--lyric-char-progress`，从"逐行填充"升级为"逐字填充"，是最大惊喜点；
- 歌词翻译/罗马音（P2，需歌词源）；
- 歌词显示开关（P1：菜单"查看 > 显示歌词"，用户可能只想看封面）；
- 无歌词时给出"编辑/导入歌词"入口（P2，配合生态 lrc 文件格式）。

### 3.4 播放过渡与防爆音（高优先级）

**现状**：`audio.pause()` / 切歌直接切 `src`，无淡出；`autoPlay` 直开。

**世界级标准**：
- **播放/暂停淡入淡出**：暂停时 120~180ms 线性淡出再 `pause()`；播放时 80ms 淡入。实现：`togglePlayback` 用 volume 斜坡（`setVolume` 步进）而非一次性切换——注意与用户音量区分（用临时 ramp 覆盖 + 恢复）；
- **切歌防爆音**：新歌 `audio.volume` 从 0 在 60ms 内升至设定音量；封面切换与新歌音频加载同步，避免"画面先切、声音后到"的割裂；
- 可选：曲目间 300ms 无缝衔接（gap-less，P2，需先解码下一首）。

### 3.5 系统集成（高优先级，Electron 加分项）

**现状**：无 Media Session、无系统媒体键（MediaPlayPause 缺失，只有 Previous/Next）。

**世界级标准**：
- **Media Session API**（`navigator.mediaSession`）：
  - `metadata`（title/artist/album/artwork）随曲目更新——**通知栏/锁屏/任务栏媒体控件直接可用**；
  - `setActionHandler`：play/pause/previoustrack/nexttrack/seekto/seekbackward/seekforward——**系统媒体键、耳机线控、蓝牙设备全部接管**；
  - 播放状态同步 `playbackState`；
  - 这些与命令系统快捷键互为补充（Media 键走 MediaSession，普通键走本地命令）。
- **Electron 集成**（经 `window.chips.*`/SDK 评估后决定）：macOS Now Playing（`MediaRemote`）、触摸栏播放控制——先查 SDK/Host 是否有对应能力，没有则登记工单；
- **系统通知**：切歌时（可选，P1）macOS 通知展示封面+曲名，可配置关闭。

### 3.6 迷你播放器 / 画中画（P1）

- 窗口缩小到迷你尺寸（如 320×120）时自动切换为"封面+播放/暂停+进度条"极简布局；
- Web 端可用画中画 API（Picture-in-Picture，P2）；
- 这是"丝滑好用"的标志性功能。

### 3.7 全屏与展示模式（P1）

- 双击封面/快捷键进入全屏（`requestFullscreen`），全屏时隐藏 AppChrome、显示大封面+歌词切换；
- 歌词模式（类似 Apple Music 的全屏歌词）。

### 3.8 偏好持久化（P1）

**现状**：音量默认 0.82、循环模式每次启动重置；退出后不记忆。

**世界级标准**：
- 用 SDK `config`/`storage` 能力（或 `window.chips.config`）持久化：音量、静音、循环模式、随机开关、上次播放位置（曲目 id + 秒数，重新打开可续播）；
- 挂载时恢复，卸载时保存（防抖 500ms）；
- 如果 SDK 无此能力，登记工单补齐（生态级能力）。

### 3.9 更多交互细节（P1-P2 合集）

| 项 | 现状 | 建议 |
|---|---|---|
| 封面点击 | 有曲目时单击=打开文件选择器（`svgcontainer` onClick），易误触 | 有曲目时：单击=无操作或打开"文件信息"；空态=打开；长按/双击=全屏 |
| 上一首语义 | 直接上一首 | 播放 >3s 时按上一首应先回到本曲开头（Apple Music 惯例），二次按才真正上一首 |
| 进度条 | 无缓冲显示、无悬停预览 | 增加缓冲条（`bufferedUntil` 已计算，未使用！）；悬停显示时间气泡（预览 seek 位置） |
| 时间显示 | 开始/剩余 | 悬停进度条时显示目标时间，松手跳转 |
| 音量交互 | 独立滑块+按钮 | 点击图标弹出音量浮层（antd Popover 定制），滑块更宽、可点击轨道跳转 |
| 右键菜单 | 无 | 封面/队列行/歌词右键菜单（在 Finder 显示、复制路径、清除队列等） |
| 键盘完整 | 部分 | 补 `J/K/L`（YouTube 惯例可选）、`Ctrl+Left/Right` 跳曲、`F11` 全屏 |
| 播放历史 | 无 | 队列面板中"最近播放"列表（P2） |
| 睡眠定时器 | 无 | P2 |

## 四、视觉与动效细节打磨

### 4.1 与 AppChrome 的视觉冲突（重要设计决策）

**现状**：AppChrome 菜单栏/工具栏是**浅色毛玻璃**（`rgba(255,255,255,0.55)`），而播放器主体是**深色封面氛围**（canvas blur + 暗色文字 + 白色发光控件）。打开应用即看到"浅色顶栏 + 深色内容"的割裂感，这是目前最显眼的视觉问题。

**建议**（二选一，推荐 A）：
- **A. 沉浸式顶栏**：音乐播放器不走标准菜单栏。AppChrome 的菜单栏改为跟随氛围的深色毛玻璃（`--control-accent-*` 驱动背景），命令入口收进"更多"菜单（⋮）；文件/播放命令保留在快捷键与右键菜单中。视觉上更接近 Apple Music。
- **B. 完全隐藏菜单栏**：AppChrome 不渲染菜单栏（`menus=[]`），顶部只留极细的窗口拖拽区；所有命令进命令面板（Mod+P）与右键菜单。最沉浸，但发现性差。
- 同时：`@chips/ui` 的 AppChrome/MenuBar/Toolbar 增加"深浅色玻璃"变体支持（token 化），避免每个应用各自 hack（这是共享层增强，需纳入 task031 共享层部分）。

### 4.2 封面区域（P0 细节）

| 细节 | 建议 |
|---|---|
| 封面尺寸 | 420px 固定 → `clamp(260px, 34vh, 420px)`，4K/高分屏下更大；与窗口高度联动 |
| 封面圆角 | 10px → 建议 14~16px（苹果风格圆角体系）或跟随主题 token |
| 封面阴影 | `0 0 32px #0003` → 分层阴影（`0 2px 8px / 0 12px 40px`），当前单层发灰 |
| 播放中封面动效 | 可选：微弱呼吸缩放（1.00→1.015，60s 周期，reduced-motion 关闭）；不做旋转唱片（俗套） |
| 封面 hover | 增加"打开文件/显示来源"提示浮层（半透明黑底），替代裸 scale |
| 封面加载 | 增加淡入（0.3s opacity），当前换封面是硬切 |

### 4.3 歌词区（P1 细节）

| 细节 | 建议 |
|---|---|
| 当前行字号 | 40px 恒定 → 当前行 1.15 倍缩放 + 加粗（现在只有透明度变化，层次感弱） |
| 歌词行间距 | 固定 72px → 按行高动态（当前测量逻辑已有基础） |
| 歌词滚动过渡 | setTimeout 逐行 stagger → 单次 transform 动画（当前实现复杂且滚动瞬间会"跳"） |
| 边缘渐隐 | mask 35%/65% → 20%/80% 更宽的自然渐隐（现在渐隐带过窄，行出界生硬） |
| 当前行指示 | 增加左侧细竖线或圆点（Apple Music 有），颜色取 `--control-accent-base` |

### 4.4 控件与工具 dock（P1 细节）

| 细节 | 建议 |
|---|---|
| 播放按钮尺寸 | 44px / 图标 34px → 56px / 42px，主按钮视觉权重不足 |
| 辅助按钮 | 36px 无底 → 悬停时浅色圆底（`rgba(255,255,255,0.12)`）再缩放，当前悬停只有位移，反馈弱 |
| 激活态（循环/静音） | 仅发光 → 增加圆底 + 高亮色，状态一目了然 |
| dock 分组 | 7 个按钮一行无分组 → 分组（跳曲组/播放组/循环音量组），间距 8/16px 分层 |
| 音量区 | 文字"音量"+原生 range → 隐藏文字，图标+滑块一体化（图标点击弹层） |
| tooltip | 自定义 CSS 0.55s 延迟 OK，但 disabled 按钮无提示 → 统一用共享层 Tooltip 组件或给 disabled 按钮包一层 span（antd Tooltip 支持 disabled 子元素包裹） |

### 4.5 背景与氛围（P1 细节）

| 细节 | 建议 |
|---|---|
| 背景动画 | 20s 循环的 background-size/position 动画 + canvas 每帧绘制 + blur(30px) → **性能大户**；建议：canvas 动画帧率降到 30fps（或仅切歌时 4s 过渡后静止），背景径向渐变去掉位移动画改静态微动（transform 只动一层）；实测帧耗时后定 |
| 氛围色应用 | 目前只用于背景/控件发光 → 扩展应用到：进度条填充色、歌词当前行、tooltip 强调色、封面阴影色（氛围一致性是"高级感"关键） |
| 空态背景 | 灰色默认氛围 → 空态用柔和渐变 + 居中插画引导，而非纯灰 |
| prefers-reduced-motion | **全局缺失**：所有动画（背景 movement、canvas 动画、歌词滚动、封面 hover、按钮按压）都应检测 `prefers-reduced-motion` 并降级为静态/瞬时——无障碍红线 |

### 4.6 排版与文字（P2 细节）

- 曲名 17px 加粗、艺术家/专辑 13px 次级——字号层级可再拉开（曲名 19px）；
- 长曲名截断 ellipsis OK，但 hover 应显示完整标题（title 属性已有则补）；
- 时间数字用 tabular-nums（`font-variant-numeric: tabular-nums`）防止跳动——当前时间数字宽度变化会轻微抖动。

## 五、架构与工程重构建议

### 5.1 巨型组件拆分（P0，重构）

`MusicPlayerStage.tsx`（977 行）混含 5 类职责，任何 `timeupdate`（4Hz）都会触发整个 Stage 重渲染 + 歌词 rAF 逐行操作 DOM：

| 拆分 | 职责 | 渲染隔离 |
|---|---|---|
| `AtmosphereCanvas` | 封面取色、canvas 动画、CSS 变量注入 | 独立，仅随 artworkUri 变化 |
| `ArtworkPanel` | 封面、时间、元信息、进度条 | 进度条内部自订阅时间 |
| `SeekBar` | 进度条+缓冲+悬停预览 | **用 rAF/局部 state 更新，不触发父级渲染** |
| `TransportControls` | 播放/暂停/跳曲/循环/静音 | 只依赖 controller 状态 |
| `LyricsPane` | 歌词渲染/滚动/填充 | 仅随 lyrics 与 activeIndex 变化 |
| `MobilePager` | 分页容器与手势 | 仅移动端 |

**丝滑关键**：`currentTime` 不再作为 Stage state 逐帧传导。方案：`useMusicPlayerController` 内部用 rAF 驱动一个可订阅的时间源（或 `useSyncExternalStore`），只有 `SeekBar`/时间文本订阅；其余组件订阅低频状态（isPlaying/duration 等）。这能把 timeupdate 引起的重渲染从"整树"降到"两个小组件"。

### 5.2 控制器分层（P1）

`useMusicPlayerController`（339 行）把 DOM 事件、状态、命令逻辑、快捷键混在一起。建议分层：

- `audio-engine.ts`（纯逻辑，可单测）：play/pause/seek/volume/loop 状态机 + 事件归一化（不含 React）；
- `useAudioEngine`（React 绑定）：挂载/卸载、事件订阅、state 暴露；
- `MediaSessionBridge`（新）：系统媒体键 ↔ engine 双向绑定；
- 好处：快捷键、Media Session、UI 三处调用同一 engine，彻底消除 2.1 的多重触发问题。

### 5.3 播放队列提升为独立模块（P1）
