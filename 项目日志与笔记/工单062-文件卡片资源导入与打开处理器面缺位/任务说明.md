# 工单062：文件卡片资源导入与打开处理器面缺位

> 登记日期：2026-09-30
> 登记方：W4 file 迁移原子任务（`chips.basecard.file`）
> 状态：开放
> 性质：宿主能力缺位登记（非本包缺陷）；文件类型识别与封面呈现体系照常交付，导入臂与打开臂如实降级。

## 一、背景

旧基础卡族 `file-BCP` 按覆盖矩阵行（`旧功能覆盖矩阵-三插件仓库-2026-09-20.md` :42 及 :34~:37、:43~:46 装配行）迁移为 `chips-ecosystem/plugins/basecards/file/`。交付过程中确认：「导入臂」（文件落卡片）与「打开臂」（文件交给处理器）依赖的宿主面均未就绪，本包按「如实登记缺位、识别与呈现照常交付」推进（music 工单060 判例同口径）。

## 二、缺位明细与证据

1. **资源打开处理器族未实现**
   - 《09-官方插件与应用目录》§5.2 `chips.official.universal-file-viewer`（`fallback`：文本与代码、版式文档、Office、压缩包等广谱兜底）状态「已设计」，W5 重写波次未落；专用查看器族同样未落。
   - `resource:open` 路由（《14-资源打开与默认处理器契约》）在 file 卡投递的各类别 MIME（document/spreadsheet/presentation/archive/audio/video/image/text/code）槽位无任何候选：primary/fallback 均未注册；§7 未安装降级面对归档态成员不可回退系统默认打开方式。
2. **渲染帧插件执行通道未交付**
   - `packages/host/src/renderer/entries/frame.ts` 头注：插件内容装载臂属插件执行通道波次（工单025 剩余 / #85 RFC 落波）。
   - 帧内 `window.chips` 不注入（08 §5.4），帧内打开臂正式通道 `frame:action` 未接；当前就近渲染容器侧经 SDK `chips` 客户端真调 `resource:open` 可用。
3. **编辑器资源导入通道缺位**
   - 旧 file-BCP 的编辑器由旧 Host 注入 `importResource` / `deleteResource` / `importArchiveBundle` / `convertTiffToPng` 通道（`file-BCP/src/editor/panel.tsx` 拖放导入面、`src/index.ts` 注入面）。
   - 新架构编辑器契约（08 §4）只承载配置回流，不写文件；《01-卡片文件格式》§6.9 补充说明第 3~5 条（导入时按原始文件名自动识别 `file_name` / `file_extension`、替换或删除文件时旧资源经平台资源管理链路登记删除）的导入编排归属资源写入链路，未开放给基础卡片编辑器。
   - 本包编辑器先行承接资源路径编辑与自动识别派生（`file_name` / `file_extension` 只读派生展示，不提供手工编辑字段）；`sanitizeImportedFileName` 等导入清洗纯函数已随包交付待消费。

## 三、影响范围

- 受阻：文件卡片查看态打开臂（点击 → `resource:open` → 处理器投递）与编辑态导入臂（文件选择 → 资源写入 → 自动识别回填）。当前点击在就近容器返回处理器缺失类失败、帧内通道不可用，界面以行内简体中文提示如实呈现，不伪造成功。
- 不受阻：9 类别文件类型判定体系（147 项判定表测试）、类别默认封面呈现（9 张功能性封面素材随迁内联）、后缀徽标占位回退、空态、`validateConfig` / `createInitialContent` / `collectResourcePaths`、编辑面板路径编辑与派生展示、包构建与五阶段校验（`file-0.1.0.cpk` 校验通过）。

## 四、复现步骤

1. 构建并安装 `plugins/basecards/file`（`chips plugin pack` + `chips plugin install`）。
2. 创建 `base.file` 节点，配置合法 `file_file`（如 `docs/季度报告.pdf`）。
3. 查看态点击整卡：`chips.request('resource:open', …)` 无处理器命中 → 行内提示「文件暂时无法打开：当前渲染环境未提供打开通道，请稍后重试」。

## 五、期望行为

1. 万能文件查看器（`fallback`）与专用查看器族按《14》§3/§4 与《09》§5.2 落波，注册各类别 MIME 处理器；本包打开臂零改动回填可用。
2. 帧插件执行通道（工单025 剩余 / #85）交付后，帧内打开臂自 SDK 客户端切换为 `frame:action` 正式通道。
3. 编辑器资源导入通道归属裁定（资源写入链路 / 编辑链路扩展）后，在 `editor.tsx` 接线文件导入编排（含 `file_name` / `file_extension` 自动识别回填、封面选择、替换 / 删除时旧资源登记删除，《01》§6.9 补充说明第 3~5 条全量落地，含 TIFF→PNG 约束）。
4. 《09》§4.2 file 行状态翻正「已迁移」并补实现路径（与本批交付同步完成）。

## 六、暂行处理（零绕过）

- 打开臂真实调用 `resource:open`，失败行内如实提示，不 mock 成功、不临时自建下载 / shell 打开旁路、不引入第二套打开实现。
- 导入清洗纯函数以模块 + 测试交付，等待导入通道接线，不做半接线假流程。
