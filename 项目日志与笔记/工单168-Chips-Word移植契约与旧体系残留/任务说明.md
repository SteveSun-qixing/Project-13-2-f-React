# 工单168：Chips-Word 移植契约与旧体系残留

## 基本信息

- 工单编号：工单168
- 日期：2026-09-01
- 发现阶段：Chips-Word 二次移植审查，核对 GenOffice 编辑器、应用插件规范与资源打开链路
- 问题类型：应用插件移植边界、视觉契约与 Manifest 最小权限漂移
- 状态：待处理

## 背景

Chips-Word 已完成最小 docx 打开、TipTap 编辑和字节补丁保存链路，但仍带有 GenOffice 历史实现边界，尚未完全收口到当前薯片生态前端与插件契约。若直接作为正式插件发布，会产生主题表现不一致、权限扩大和供应链语义残留等问题。

## 证据

1. `Chips-Word/src/styles/document-editor.css:143-317` 仍包含 `[data-theme='dark']` 与 `@media (prefers-color-scheme: dark)` 两套主题覆盖；task030 已废弃插件主题系统，统一视觉事实源应为 `@chips/ui` 的 `appleTheme`。
2. `Chips-Word/manifest.yaml:23-33` 声明 `config.read`、`config.write`、`network.request`，当前 Word 源码没有配置服务调用，远程读取也未形成正式 Host 资源解析口径，违反最小权限原则并可能与 Host-only 系统能力边界冲突。
3. `Chips-Word/package.json:21` 直接声明 `@genoffice/pptx-engine`，Word 源码未直接使用；该依赖由 `vendor/docx-engine/src/parse.ts` 的 `custgeom` 子路径间接需要，需明确由 vendor 包内部封装还是保留应用顶层依赖。
4. `Chips-Word/vendor/docx-engine` 与 `vendor/pptx-engine` 仍保留 GenOffice AI 相关注释、`aidocs` 资源命名和从零生成模板描述。应用源码已移除 AI 入口，但供应链代码与审计扫描边界尚未统一。
5. Word 当前起始页仍将功能描述、支持格式和快捷键作为可见说明文本；现行前端体验约束要求以直接可操作的起始页为主，需与四个办公插件统一起始页设计收口。
6. Word 需求文档和 README 将“新建空白文档”列为不支持，但移植进来的 `vendor/docx-engine/src/blank.ts` 已导出 `buildBlankDocx`，并由 `vendor/docx-engine/tests/blank-template.test.ts` 验证空白包可解析、可保存、可再次解析；应用 Runtime/起始页没有接入该能力，形成产品文档与实际引擎能力的矛盾。
7. `src/lib/document-io.ts` 原先对空字节和任意非 ZIP 数据直接调用 JSZip，用户会看到底层英文压缩包错误；本轮已在 Word I/O 边界增加 ZIP 魔数预检，并在 `tests/unit/document-io.test.ts` 固化回归。

## 影响范围

- Chips-Word 正式安装包的权限审计、主题一致性与供应链合规检查；
- Host 资源打开、远程资源读取与浏览器/Web 宿主的运行边界；
- Chips-Slide 对共享 `vendor/pptx-engine` 的移植与 AI 残留扫描；
- 四个办公插件起始页视觉和交互一致性。

## 复现步骤

1. 在 Chips-Word 执行 `rg -n "data-theme|prefers-color-scheme" src/styles/document-editor.css`，可见插件私有暗色主题覆盖。
2. 对照 `manifest.yaml` 权限逐项搜索 `src/`，确认 `config.*` 没有实际调用，`network.request` 仅由浏览器 `fetch` 路径隐含使用。
3. 在 `vendor/docx-engine`、`vendor/pptx-engine` 执行 `rg -n -i "AI|assistant|copilot|aidocs"`，可见历史语义残留。

## 期望行为

- Word 应移除插件级暗色主题覆盖，所有壳层视觉通过 `@chips/ui` 和 antd token 提供；文档纸张的固定数据色需单独标注并经过视觉复核。
- Manifest 只声明实际调用的权限；远程资源必须明确通过 Host/SDK 资源链路或声明经审计的网络能力。
- 明确 `@genoffice/pptx-engine` 的 vendor 内部依赖边界，避免 Word 应用层重复声明并同步影响 Slide 打包。
- GenOffice AI 相关入口、命名和无关模板不进入正式办公插件运行包；保留的历史许可证与移植说明应独立于运行时代码。
- 四个办公插件采用同一套简约起始页交互与视觉基线。
- 明确新建空白文档的产品口径：若纳入正式能力，应把 `buildBlankDocx` 接入 Word Runtime，补充起始页入口、未命名文档另存为流程、dirty/关闭状态和对应测试，并同步更新需求与 README；若暂不纳入，则应移除/隔离该模板及其“新建”语义，避免文档与代码互相矛盾。

## 暂行处理

- Chips-Word 应用源码已清理 `ai-docs-*` 事件、AI 注释和 copilot token，并增加静态测试禁止残留；已移除顶部 `MenuBar`，对齐当前 `AppChrome` 命令面板语义。
- 在本工单收口前，不将当前暗色 CSS、过宽权限和 vendor 历史注释视为正式契约，不据此向其他插件复制。
