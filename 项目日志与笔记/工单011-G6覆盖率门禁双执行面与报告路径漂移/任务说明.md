# 工单011：G6 覆盖率门禁双执行面与报告路径/阈值双事实源漂移

> 登记时间：2026-09-20
> 登记人：主智能体（task043 生态重构总攻 · W1 阶段）
> 状态：待处理

## 问题

工作区对"覆盖率门禁（G6）"存在两个互不一致的执行面，且各自的报告输入路径与阈值来源是两套独立事实源：

1. **执行面 A（门禁侧）**：`chips-ecosystem/tools/gates/check-coverage.mjs`，由 `pnpm gates:all` 聚合执行，输入路径来自 `chips-ecosystem/tools/gates/gates.config.json` 的 `coverage.inputs`：
   - TS：`coverage/coverage-summary.json`（required）
   - Rust：`coverage/tarpaulin.xml`（required）
   - 阈值：`coverage.defaultThreshold`（80）与 `coverage.groups`（shared 90 / core 90）
2. **执行面 B（测试工具侧）**：`chips-ecosystem/tools/testing/src/coverage/run.ts` → `runner.ts`（根脚本 `pnpm test:coverage`），产物与读取路径来自 `chips-ecosystem/tools/testing/src/thresholds.ts` 的 `COVERAGE_REPORT_PATHS`：
   - TS：`coverage/ts/coverage-summary.json`
   - Rust：`coverage/rust/tarpaulin-report.json`
   - 阈值：`thresholds.ts` 中 `OVERALL_COVERAGE_THRESHOLD=80`、`CORE_SHARED=90`

全仓库没有任何脚本向 `coverage/coverage-summary.json` 或 `coverage/tarpaulin.xml` 写入内容；执行面 A 配置的输入路径是"只读不产"的悬空路径。

附带口径问题：执行面 A 的 `core` 组匹配 `packages/core-rust/`、`packages/native/`，该组名与匹配路径作用于 TS json-summary 分组时与执行面 B 的 `SHARED_LAYER_GLOBS`（`packages/ui/**`、`packages/bridge/**`）和 Rust 侧（chips-* crates）分组口径不重合，两侧对"core/shared 到底覆盖哪些文件"的定义不一致。

## 影响

- W1 准出要求"覆盖率达标 + 门禁全绿"：即使完整跑完官方 `pnpm test:coverage` 且覆盖率真实达标，`pnpm gates:all` 的 G6 仍必然以 COVERAGE001（报告缺失×2）失败，门禁与真实质量状态脱钩。
- 阈值/分组口径双事实源：未来任何一侧调整（如《架构原则》《测试规范》阈值变更）都会造成两个执行面静默漂移，违背宪法"单一事实源"原则。
- CI 聚合脚本（`pnpm ci`，见 gates 接线智能体交付）串联 `gates:all`，该漂移会长期以假失败阻塞 CI 判定，诱发"绕门禁"风险。

## 证据

- 命令与输出（2026-09-20，gates 接线智能体实测）：`pnpm gates:all` → docs/contracts/boundaries 通过，coverage 失败 `COVERAGE001×2`（TS 与 Rust 报告缺失），而当时 `coverage/ts/coverage-summary.json`（101KB，官方流程产物）已存在。
- 文件：
  - `chips-ecosystem/tools/gates/gates.config.json`（`coverage.inputs.ts.path=coverage/coverage-summary.json`、`coverage.inputs.rust.path=coverage/tarpaulin.xml`）
  - `chips-ecosystem/tools/gates/check-coverage.mjs`（`runCheck` 按上述路径 `path.resolve(workspaceRoot, ...)` 判缺失）
  - `chips-ecosystem/tools/testing/src/thresholds.ts`（`COVERAGE_REPORT_PATHS`、`OVERALL_COVERAGE_THRESHOLD`、`SHARED_LAYER_GLOBS`）
  - `chips-ecosystem/tools/testing/src/coverage/run.ts`（官方流程产物目录 `coverage/ts`、`coverage/rust`）
  - `chips-ecosystem/vitest.config.ts`（`reportsDirectory: 'coverage/ts'`，json-summary  reporter）
- 该缺口已由 gates 接线智能体记录于 `chips-ecosystem/tools/testing/开发计划.md` §七 缺口 1（待裁决），本工单为正式登记。

## 关联节点

- 《测试规范》《架构原则》：阈值 80/90 的权威出处。
- W1 准出：全部门禁全绿；`pnpm ci` 聚合链路。
