# 工单 004：文档库工作区布局与实际目录不一致

> 登记：W1-ROOT（2026-09-19）
> 状态：待处理
> 影响：《代码组织规范》《构建与打包》《TypeScript 编码规范》的目录/路径条款与全部并行子智能体的落位判断；`chips-ecosystem/` 骨架、根脚本与各包配置

---

## 一、背景

`chips-ecosystem/` 骨架按《重构大计划/02-仓库映射与新工作区》与主代理指令落位（`packages/host`、`packages/antd`、`packages/cli`、`packages/native`、`tools/{scaffold,contract-gen,gates,testing}`、`tests/{contract,e2e,perf}`；文档库位于工作区外 `薯片生态文档库/`），但《薯片生态文档库/02-开发规范/01-代码组织规范》仍按另一套目录口径书写（`packages/host-electron`、`packages/antd-fork`、`tools/cli`、`tools/scripts`、`docs/` 为文档库根），《构建与打包》的配置示例同样引用旧目录名。两套口径并存会导致子智能体按不同名称落位、根配置与文档门禁判定漂移。

## 二、证据

### 2.1 《代码组织规范》口径（现状）

- `薯片生态文档库/02-开发规范/01.02-01-代码组织规范-二、Monorepo 顶层结构.md`：
  - 第 16 行：`├── docs/                            # 《薯片生态文档库》根`
  - 第 20 行：`│   ├── host-electron/               # Electron 壳应用`
  - 第 22 行：`│   ├── antd-fork/                   # @chips/antd`
  - 第 49 行：`| docs/ | 《薯片生态文档库》唯一落位 |`
- `薯片生态文档库/02-开发规范/01.03-01-代码组织规范-三、包划分.md`：
  - 第 18 行：`| host-electron/ | @chips/host | ...`
  - 第 20 行：`| antd-fork/ | @chips/antd | ...`
  - 第 49 行：`packages/host-electron/`（包结构示例）
  - 第 74 行：`packages/antd-fork/     # fork 的 antd 仓库`
- `薯片生态文档库/02-开发规范/01.08-01-代码组织规范-八、常用脚本约定.md` 第 57-61 行：`pnpm-workspace.yaml` 示例只含 `packages/*`、`plugins/*`、`tools/*`、`examples/plugins/*`，不含 `tests/*`。

### 2.2 《构建与打包》口径（现状）

- `薯片生态文档库/06-开发与运维/02.05-02-构建与打包-五、前端构建.md`：
  - 第 17-20 行：产物路径 `packages/host-electron/dist/{main,preload,renderer,frame}/`。
  - 第 43 行：根 `tsconfig.json` 引用 `{ "path": "./packages/host-electron" }`。
  - 第 75 行：`packages/host-electron/vite.renderer.config.ts`。
  - 第 107 行：`packages/host-electron/dist/frame/`。
  - 第 324 行：插件 `build` 脚本使用 `node ../../tools/scripts/check-entries.mjs .`。

### 2.3 实际工作区（代码事实）

```bash
ls chips-ecosystem/packages          # antd bridge cli core-rust host native sdk ui
ls chips-ecosystem/tools             # contract-gen gates scaffold testing
ls chips-ecosystem                    # 无 packages/host-electron、无 packages/antd-fork、无 docs/、无 tools/scripts
ls -d 薯片生态文档库                   # 文档库位于工作区外（仓库根）
cat chips-ecosystem/tsconfig.json     # "files": [], "references": []
cat chips-ecosystem/pnpm-workspace.yaml  # 含 tests/*（tests/contract、tests/e2e、tests/perf 为工作区包）
```

- `chips-ecosystem/packages/host/package.json` 的 `name` 为 `@chips/host`；`chips-ecosystem/packages/antd/package.json` 的 `name` 为 `@chips/antd`。
- `chips-ecosystem/tools/gates/check-entries.mjs` 已存在（W1-GATES 交付），与 §2.2 第 324 行的 `tools/scripts/check-entries.mjs` 不一致。
- 《TypeScript 编码规范》的两处示例同样漂移：
  - `02.01-...-一、编译配置.md` 第 36-37 行 `paths` 将 `@chips/ui` 指向 `./packages/ui/src`（单应用口径，与工作区包解析模型冲突）。
  - `02.11-...-十一、ESLint 配置.md` 第 12 行以 `.eslintrc.js` 为例；仓库实际采用 ESLint 9 扁平配置 `eslint.config.mjs`（已在 `chips-ecosystem/开发日志.md` 记录为决策，文档待同步）。

### 2.4 关联工单

- 入口校验脚本落位问题已在[工单 001](../工单001-脚手架app模板清单与插件构建契约不一致/任务说明.md)（第 4 条）登记，本工单不重复处理该条，只在布局口径中引用。

## 三、影响范围

- 子智能体按文档落位会创建 `packages/host-electron` 等第二套目录，或按 `tools/scripts` 写脚本引用，导致骨架二义。
- 根 `tsconfig.json` 的 solution 引用若照抄文档会指向不存在的路径；`pnpm-workspace.yaml` 若照抄文档会漏掉 `tests/*` 工作区包（`@chips/perf`、`@chips/e2e`、`@chips/contract-tests`）。
- 文档门禁要求"文档与实现同一 PR 更新"，当前漂移违反该规则，并在并行开发中持续放大。

## 四、复现步骤

1. 打开《代码组织规范》§2.1/§3.1，按其中的 `packages/host-electron` 路径在工作区查找：不存在。
2. 打开《构建与打包》§5.2，按其中 `references` 内容配置根 `tsconfig.json`，`tsc -b` 指向不存在的工程。
3. 打开《构建与打包》§5.5 第 324 行，执行 `ls tools/scripts/check-entries.mjs`：不存在（实际在 `tools/gates/check-entries.mjs`）。
4. 按《代码组织规范》§8.3 的 `pnpm-workspace.yaml` 示例还原，`pnpm install` 后 `tests/*` 下的三个包不再是工作区成员。

## 五、期望行为

裁决并统一唯一口径，二选一：

1. 以现行骨架为准（推荐）：修订《代码组织规范》《构建与打包》《TypeScript 编码规范》中的目录名、脚本路径、workspace 清单与配置示例，使文档与 `chips-ecosystem/` 实际一致；文档库位置（工作区外 `薯片生态文档库/`）与 `tests/*` 工作区成员写入规范。
2. 以文档为准：调整工作区目录（含根 `tsconfig.json`、`pnpm-workspace.yaml`、全部包名与引用）并同步《重构大计划/02》。

无论何种口径，均需同步更新 `chips-ecosystem/README.md`、`开发计划.md` 与相关门禁配置。
