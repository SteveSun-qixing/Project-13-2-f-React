## 一、落地内容

### 缺陷①：`chips` bin 解析漂移

1. **工作区根 bin 锚点**：`chips-ecosystem/package.json` `devDependencies` 声明
   `"@chips/cli": "workspace:*"`（锁文件同步）——`pnpm exec chips` 自任意 workspace 子包
   （含 `examples/plugins/hello`，其自有依赖清单不变，G9 examples 允许集不含 `@chips/cli`，`tools/gates/**` 零改动）
   解析到当前工作区 `node_modules/.bin/chips`，杜绝静默回退命中仓库外全局 `~/.volta/bin/chips` 陈旧构建。
2. **脚手架模板锚点**：`tools/scaffold/src/templates/index.ts` `packageDevDependencies`
   为全部角色补 `"@chips/cli": "workspace:*"`——新生成工程自带正确 bin 锚点
   （模板 `package` 脚本 `pnpm exec chips plugin pack --out dist/` 的解析前提，注释登记用途与工单号）。
3. **契约测试固化（G8）**：`chips-ecosystem/tests/contract/tests/cli-bin-resolution.test.ts` 三用例——
   ① `pnpm exec which chips` 在插件子包内解析到工作区 `node_modules/.bin/chips`（工作区外即红）；
   ② `pnpm exec chips --version` 与工作区构建入口 `packages/cli/dist/bin.js --version` 输出逐字节一致（漂移守卫）；
   ③ `package` 脚本链端到端：`pnpm --filter @chips/plugin-hello run package` → 产物经正式引擎
   `plugin validate` EXIT=0，用例自清理不留脏产物。
   并含跨进程互斥锁：`pnpm -r test:contract` 下 `@chips/contract-tests` 存在直跑与
   `packages/bridge` 转发两条并发执行面，双方在同一绝对路径 pack/清理产物会互踩
   （嵌套归档拒绝是既有校验强度，属执行面串扰而非产品缺陷）。锁实现：原子 `mkdir` 建锁 +
   owner PID 存活性/锁龄 3 分钟双路残锁接管（pnpm fail-fast 击杀持有者后 ≤1s 恢复）+
   用例显式 240s 超时包住 90s 等待预算（防 vitest 默认 30s 超时在临界区内制造残锁）；
   不放宽任何断言，双进程并发实测两实例均 3/3 通过。
