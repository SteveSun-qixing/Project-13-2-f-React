# 工单023 —— manifest 契约类型 15 项只在 `@chips/sdk/scaffold` 可达，主入口缺位致插件运行时无合法获取路径

> 登记日期：2026-09-20
> 来源：task043《契约-代码漂移审计-2026-09-20》面 1 第 4 条（W2 P0），登记前已逐条到代码复核。
> 性质：只登记问题，不含解决办法。

## 一、背景

《02-SDK-API规范》§2.2（`薯片生态文档库/05-接口与契约/02.02-02-SDK-API规范-二、导出入口.md:56`）把 `IPluginManifest`、`PluginRole`、`PluginTarget`、`PluginSurface`、`IPluginRuntime`、`IPluginEngines`、`IPluginDependency`、`IPluginCapabilities`、`IPluginCardType`、`IPluginLayoutType`、`IPluginExportFormat`、`IPluginFileAssociation`、`IPluginUi`、`IPluginHealthCheck`、`IPluginDeepLink` 共 15 项 manifest 类型登记为**主入口** `@chips/sdk` 的类型导出。同时 §2.2 规则（同文件 `:25`）规定：插件运行时代码只允许导入主入口，`@chips/sdk/scaffold` 是开发期入口、不得进入运行时依赖图。两条规则叠加后，插件运行时获得 manifest 类型的唯一合法路径就是主入口导出。

## 二、证据（文件:行号，均于 2026-09-20 复核）

1. `chips-ecosystem/packages/sdk/src/index.ts` 全文 grep `IPluginManifest|PluginRole` 0 命中（本轮实测，无任何 manifest 导出段）。
2. `chips-ecosystem/packages/sdk/src/scaffold/index.ts:23-43`：上述 15 项类型当前的唯一导出落位（`:33` 即 `IPluginManifest`），只在 `./scaffold` 子路径可达。
3. `chips-ecosystem/packages/sdk/src/index.ts:9-10`：主入口头注释自述「§2.2 清单中的 manifest 与 CLI 扩展类型尚未随本入口落地」——缺口自知但未进工单台账（CLI 扩展部分另立工单022）。

## 三、影响范围

- 断链 + 规则互斥：插件按契约无法合法获得任何 manifest 类型——从主入口导入必报 TS2305；改从 `@chips/sdk/scaffold` 导入则直接违反 §2.2「scaffold 不得进运行时依赖图」与 §8.2 规则 9 的入口分工。
- 涉及面：全部四角色插件的运行时类型化代码（读取 `manifest.yaml` 派生信息、按 `PluginRole` / `PluginSurface` 分支的逻辑）、`@chips/sdk/scaffold` 模板生成代码若引用这些类型同样受限。
- 与工单001（脚手架模板清单，已收口）正交：001 解决的是模板事实源，本单是类型导入面。

## 四、复现步骤

1. `chips-ecosystem` 内构建 `@chips/sdk`。
2. 在任一插件工程源码中写 `import type { IPluginManifest } from '@chips/sdk';` —— `tsc` 报 TS2305。
3. 写 `import type { IPluginManifest } from '@chips/sdk/scaffold';` —— 编译通过，但与 §2.2 运行时导入白名单规则（`:25`）冲突，属契约违例。

## 五、期望行为

契约 §2.2 主入口类型清单与 `packages/sdk` 实际导出面收敛为一致：插件运行时代码存在一条既合法、又可编译的 manifest 类型获取路径；或契约明文修订 15 项类型的落位与规则，消除互斥。
