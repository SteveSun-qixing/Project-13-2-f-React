- 判据注：本单三条均为**模板面真缺陷**，非门禁误报；门禁常跑段（不含 e2e 臂）自始 EXIT=0

## 一、背景

覆盖矩阵缺口 G1「脚手架生成工程端到端门禁缺位」由 #226 补齐：新增门禁以四角色（basecard / boxlayout / app / service）现场转译装载脚手架、生成落 tmp 沙箱，跑六层结构判据，另有 `CHIPS_SCAFFOLD_E2E=1` 开关臂真起 pnpm workspace 做 install + typecheck + build + test。

常跑段全绿（EXIT=0，`roles=4 files=55 tsChecked=33 manifests=8 parser=yaml`）。开关臂真跑两次（22.35s / 22.74s，EXIT=1）抓出 basecard、boxlayout 两角色的编译与测试缺陷三条；app、service 两角色全绿。install 与 `workspace:*` 符号链接传递闭包全通，说明缺陷不在门禁环境搭建，而在模板 emitted 源码本身。

## 二、证据（复现日志 /tmp/e2e_055.txt）

### 缺陷① basecard：具名再导出指向无该导出的模块

```
gen/basecard/src/index.ts(2,10): error TS2614:
  Module '"./main"' has no exported member 'validateConfig'.
  Did you mean to use 'import validateConfig from "./main"' instead?
gen/basecard/src/render.tsx(25,3): error TS6133:
  'validateConfig' is declared but its value is never read.
```

模板侧根因候形（`chips-ecosystem/tools/scaffold/src/templates/basecard.ts`）：

- `:112` `main.ts` 段写 `import { DEFAULT_CONFIG, validateConfig } from './config';`——只在段内使用，全段无 `export { validateConfig }`／`export ... from './config'` 再导出；
- `:498` `index.ts` 段写 `export { validateConfig, createInitialContent, collectResourcePaths, mainPlugin } from './main';`——`main` 模块并不导出 `validateConfig`，TS2614 由此产生；
- `:145-147` `mainPlugin: Pick<..., 'validateConfig' | 'createInitialContent' | 'collectResourcePaths'>` 依赖 `./config` 引入形，与 index 面的导出路径不一致；
- `render.tsx` 的 TS6133 为同族次生症状（引入未用），修口时须一并核对该成员在渲染面的真实用途，禁以「删断言/删导入」凑绿而不解决导出形状。

### 缺陷② boxlayout：渲染插件对象字面量缺必填成员

```
gen/boxlayout/src/render.tsx(500,14): error TS2322:
  Type '{ attachRuntime; renderLayout; renderEditor }' is not assignable to
  type 'IBoxLayoutPlugin & IBoxLayoutRuntimeAware'.
  Property 'validateConfig' is missing in type ... but required in type 'IBoxLayoutPlugin'.
```

模板侧根因候形（`templates/boxlayout.ts`）：`:633` `export const renderPlugin: IBoxLayoutPlugin & IBoxLayoutRuntimeAware = {` 的对象字面量只含 `attachRuntime`/`renderLayout`/`renderEditor` 三成员；同文件 `:127` `mainPlugin: Pick<IBoxLayoutPlugin, 'validateConfig'> = { validateConfig }` 与 `:647` `export { validateConfig } from './config';` 均已具备该函数，唯渲染面漏挂。

### 缺陷③ boxlayout：生成工程测试段缺 DOM 环境

```
gen/boxlayout  pnpm test → exit 1
 ❯ beginWork  react-dom@18.3.1/cjs/react-dom.development.js:21626:16
 ❯ beginWork$1 ... :27465:14
```

模板侧事实（`templates/boxlayout.ts`）：`:767-768` `container = document.createElement('div'); document.body.replaceChildren(container);`、`:801` `renderEditor(box, document.createElement('div'))`、`:809` `document.querySelector('form')`——测试用例直取 DOM。

工具链侧事实：`grep -rn "vitest.config|jsdom" chips-ecosystem/tools/scaffold/src/*.ts` **零命中**，即脚手架从不为生成工程 emit vitest 配置、也不声明 DOM 测试环境依赖；vitest 默认 `environment: 'node'` 下 `document` 不存在，React 挂载路径必炸。生态既有选型（`pnpm-workspace` 内）：`packages/antd` jsdom 26.1.0、`packages/host` jsdom 28.1.0、`packages/ui` jsdom 28.1.0——jsdom 系在册选型件，非新引入第三方。
