## 一、实测复核结论（先于改动的事实基线）

1. 根口径基线：`npx eslint .`（仓库根）→ EXIT=0，0 error 0 warning（`/tmp/t016-root-eslint-baseline.log`，空文件）。
2. 真正的独立判定面漂移 = 5 个包自带 `eslint.config.mjs`（非类型感知或另立规则集）：
   `packages/host`、`packages/bridge`、`packages/cli`、`packages/sdk`、`packages/antd`。
3. 其余包无包级配置，其裸 `eslint` 依赖 ESLint 9 的「自 cwd 向上查找」隐式解析。`--debug` 实测确认
   `packages/ui`、`tests/contract`、`tests/perf`、`tools/scaffold`、`examples/plugins/hello` 五处
   均已隐式命中根配置（base path = 仓库根）——但属隐式依赖，本轮统一改为显式委托，消除解析歧义。
   （注：任务书「漂移面清单」将 ui/tests/contract/tools/scaffold 列为裸形态待补全，实测其当前判定结果
   与根口径一致，本轮做的是形态显式化，不改判定语义。）
4. 各包基线 lint 全部 EXIT=0（`/tmp/t016-<pkg>-baseline.log`），委托到根口径不会显红（根全绿 ⟹ 任意子集全绿）。
5. `tools/testing` 的裸 `eslint src tests vitest.config.ts` 形态虽在清单思路内，但属禁改面
   （其 lint 收口由主智能体在 G6 合并代理收口后串行处理），本轮不碰。
6. `packages/native` 的 `lint` 为 ABI 检查脚本、`plugins/**` 无 lint 脚本，均非 eslint 判定面，不处置。

## 二、改动清单

### 2.1 形态裁决修订记录（实测后，2026-09-20 落地时补充）

初版计划按裁决采 tests/e2e 先例形态 `eslint . --config ../../eslint.config.mjs`。落地实测发现该形态
在 ESLint 9.39 下机制性偏离根口径：`--config <路径>` 会把配置 base path 置为执行 cwd（`--debug` 与
`--print-config` 双证据，见 RFC §五），导致根配置 `packages/ui/**`、`packages/antd/**` 路径特例块在包
目录内不命中——packages/ui 显红 22 条、packages/antd 显红 94 条误报（ui 合法 import fork antd 被判违例），
包面红而根面（正确 base path）绿，直接违背工单016 验收第 2 条「蕴含性」。该红不是「包在根口径下显红」，
而是委托命令形态本身偏离根口径，按「修实现」处置会反向摧毁 @chips/ui 共享层架构，属违规操作。

修订后的落地形态（保持裁决意图：委托根配置、按包目录限定范围、根配置一字不改）：

- 包级配置归档后，包目录内 `eslint .`（或既有范围参数）经 ESLint 9 向上查找唯一命中根配置，
  base path = 仓库根，与根面 `eslint .` 对同批文件的判定逐字节等价（`--print-config` 实测等价，见 RFC §五）。
- 「委托」由结构保证：树内不再存在任何第二份 eslint 配置，无劫持可能。
- tests/e2e 既有的 `--config` 形态本轮不动（其目录无路径特例块依赖，判定等价；形态隐患记入 RFC 遗留建议）。

### 2.3 形态决策记录

- `--max-warnings 0` 不向新面包尾随扩散：根面未设该参数，包面若自行加严会制造「包红/根绿」非蕴含漂移；
  tests/perf 与 tests/e2e 既有设置沿用不删。

## 三、验证方案（全部 `cmd > /tmp/xxx.log 2>&1; echo EXIT=$?` 取真实退出码）

1. 根 `pnpm lint` EXIT=0。
2. 每个受影响包 `pnpm --filter <pkg> lint` EXIT=0（5 个归档包 + ui + contract + perf + scaffold + hello）。
3. 蕴含性负证据：在委托包（packages/bridge）src 下临时创建仅触发类型感知规则（`@typescript-eslint/require-await`）
   的小 ts 文件 → 包 lint 必须 EXIT≠0 且报出该规则 → 同文件在根面 `npx eslint packages/bridge` 同样显红（双向
   等价证据）→ 删除该临时文件（本轮自建，删除合规）→ 复跑回绿。
4. `pnpm -r --if-present run lint` EXIT=0 全工作区总验证。
5. 全程不跑 cargo/tarpaulin 重型任务（磁盘约 12Gi；根 pnpm lint 内的 cargo fmt/clippy 为需求 1 指定动作）。
