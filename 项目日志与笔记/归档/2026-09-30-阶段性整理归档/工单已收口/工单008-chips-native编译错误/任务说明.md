# 工单 008：`packages/native` 存在 8 项自身编译错误

> 登记：FIX-KERNEL（2026-09-19）
> 状态：已修复（FIX-NATIVE，2026-09-19）
> 影响：`packages/native`（W1-Neon 交付范围）、根工作区 `chips-ecosystem` 整体构建与 `cargo test`

---

## 一、背景

FIX-KERNEL 修复了内核侧 `crates/chips-cordis/src/task.rs` 的 E0433 / E0282（tokio 特性缺失）后，`chips-cordis` 与 `chips-core` 已可在根工作区编译。但根工作区整体构建仍在 `chips-native` 上失败；经逐条核对，剩余 8 个错误全部位于 `packages/native/` 自身源码，与内核公开面无关，属 W1-Neon 交付范围内的未收口实现。

## 二、证据

1. 复现命令：`cd chips-ecosystem && cargo build --workspace`。
2. 8 个错误：
   - `packages/native/src/convert.rs:222`：E0425 `cannot find type JsBigInt in this scope`（缺少 Neon 类型导入）；
   - `packages/native/src/error.rs:53`：E0404 `expected trait, found enum Value`（`serde_json::Value` 遮蔽 `neon::prelude::Value`，`throw_chips_error` 泛型约束失效）；
   - `packages/native/src/handles.rs:28 / 69 / 111`：E0404 `expected trait, found struct Context`（`chips_cordis::Context` 遮蔽 `neon::prelude::Context` trait，`C: Context<'a>` 三处失效）；
   - `packages/native/src/runtime.rs:38`：E0425 `cannot find type Deferred in this scope`（缺少 Neon `Deferred` 导入）；
   - `packages/native/src/context.rs:142`：E0277 `NativeContextHandle` 未实现 `neon::prelude::Value`（`context_argument` 直接以自定义结构作为 `JsResult` 返回类型，应走 `JsBox<NativeContextHandle>` 或实现 `Value`）；
   - `packages/native/src/context.rs:151`：E0277 `Vec<String>` 未实现 `neon::prelude::Value`（`string_array_argument` 的返回类型需改为 JS 数组构造路径）。
3. 内核侧同期验证：`cargo build -p chips-cordis -p chips-core` 与
   `cargo test -p chips-cordis -p chips-core` 在根工作区均通过（74 通过 / 0 失败），
   证明上述错误不来自内核。

## 三、影响范围

- 根工作区无法执行整体 `cargo build` / `cargo test` / `cargo clippy --workspace`；
- `chips-native` 的 Neon 导出面与 ABI 自检（`scripts/check-abi.mjs`）无法运行；
- 宿主与渲染侧无法通过 Node 侧加载内核，阻断后续端到端链路。

## 四、复现步骤

1. `cd chips-ecosystem`
2. `cargo build --workspace`
3. 观察 `chips-native` 的 8 个编译错误（Rust 1.93.0，neon 1.1.1）。

## 五、期望行为

1. 修复导入与名称遮蔽：显式导入 `JsBigInt`、`Deferred`；对 Neon trait 使用限定名或别名（如 `neon::context::Context as NeonContext`、`neon::prelude::Value as NeonValue`）。
2. 按《核心接口规范》§8.4 / §8.6 收口 Context 句柄与字符串数组的映射：句柄以 `JsBox<NativeContextHandle>` 传递；数组参数在 Rust 侧接收后构造返回值，返回类型改为合法的 Neon `Value` 实现（不得以 `Vec<String>` 直接作为 `JsResult`）。
3. 修复后根工作区 `cargo build --workspace`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test -p chips-native` 全绿。

## 六、验收标准

- `cargo build --workspace` 0 错误；
- `cargo test -p chips-cordis -p chips-core` 保持 74 通过 / 0 失败；
- native 的导出面与 `scripts/check-abi.mjs` 通过（工单 005 收口前，能力执行相关导出按现状绕开）。

## 七、暂行处理

- FIX-KERNEL 不修改 `packages/native/`（超出本轮内核修复范围）；
- 内核侧验证改用隔离工作区 `packages/core-rust/` 与根工作区 `-p chips-cordis -p chips-core` 执行；
- 在 `packages/core-rust/开发日志.md` 与本工单标注该阻塞。

## 八、修复记录（FIX-NATIVE，2026-09-19）

### 8.1 修复内容

1. **Neon 导入缺失**：`convert.rs` 补 `neon::types::JsBigInt`；`runtime.rs` 补
   `neon::types::Deferred`（两者均不在 `neon::prelude`）。
2. **名称遮蔽**：`error.rs` 的 `serde_json::Value` 改名 `JsonValue`，`throw_chips_error`
   收口为 `NeonResult<V>`（不要求 `V: Value`）；`handles.rs` 的 `chips_cordis::Context`
   别名 `KernelContext`。
3. **句柄与数组映射（§8.4）**：`context_argument` 返回 `NeonResult<KernelContext>`
   （句柄仍以 `JsBox<NativeContextHandle>` 传递）；`string_array_argument` 返回
   `NeonResult<Vec<String>>`，类型错误抛 `NATIVE_TYPE_UNSUPPORTED`。
4. **前置错误抑制的潜在缺陷一并收口**：`upcast::<JsValue>()` 显式化（`convert.rs` /
   `error.rs`）、`envelope.rs` 补 `TypedArray` trait、`runtime.rs` settle 闭包按
   `&mut cx` 调用、`handles.rs` 三处回调调用消除二次可变借用（E0499）。
5. **工程门禁**：去掉 `needless_return`；对「已交付、待接线」的模块与测试/诊断访问器
   加逐项 scoped `#[allow(dead_code)]` 并标注工单005 原因；`cargo fmt -p chips-native`
   归一（stable rustfmt；`fmt --check` 0 diff）。
