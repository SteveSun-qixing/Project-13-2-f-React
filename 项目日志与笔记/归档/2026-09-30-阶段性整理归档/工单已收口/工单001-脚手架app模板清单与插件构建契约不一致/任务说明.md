# 工单 001：脚手架 app 模板清单与插件构建契约不一致

> 登记：W1-EXAMPLE（2026-09-19）
> 状态：待处理
> 影响：`@chips/sdk/scaffold`（W1-SCAFFOLD）、`@chips/cli`（W1-CLI）、插件构建门禁（W1-GATES）、`examples/plugins/*` 与 `plugins/*` 全部插件

---

## 一、背景

`examples/plugins/hello/` 作为金链路首个 app 插件示例，需要与 `@chips/sdk/scaffold` 的 `app` 角色模板同构。按文档库实现时发现「模板生成文件清单」与「插件构建契约」相互矛盾，按任一单一口径实现都会留下不可构建或与模板不一致的结果。

## 二、证据

1. **模板文件清单（6 项，无构建配置）**
   - `薯片生态文档库/05-接口与契约/02.08-02-SDK-API规范-八、脚手架（@chips/sdk-scaffold）.md` §8.2：
     `app` 角色生成文件为 `manifest.yaml`、`package.json`、`tsconfig.json`、`src/index.ts`、`src/ui/AppView.tsx`、`assets/icons/app.svg`；并规定 `files` 与清单逐项一致、生成结果必须可直接 `build`。
2. **构建契约要求 vite 配置存在**
   - `薯片生态文档库/06-开发与运维/02.05-02-构建与打包-五、前端构建.md` §5.5：插件构建产出 `dist/index.js`（node18，无外部化）与 `render.js`（chrome118，外部化 `react` / `react/jsx-runtime` / `react-dom` / `react-dom/client` / `@chips/ui` 并重写为平台 vendor URL），并给出 `vite.shared.ts`、`vite.main.config.ts`、`vite.render.config.ts` 的完整配置与 `package.json` 标准脚本。
   - §5.6：打包前必须执行入口校验脚本，路径写为 `tools/scripts/check-entries.mjs`。
   - `薯片生态文档库/04-文件格式规范/03.02-03-插件包格式-二、包结构.md` §2.6：`render.js` 必须外部化平台共享依赖；没有对应构建配置无法满足。
3. **README 口径不一致**
   - `薯片生态文档库/06-开发与运维/07.03-07-CLI完整参考-三、用户侧命令 chips.md` §3.5.1：`chips plugin create` 生成内容「包含 `manifest.yaml`、`package.json`、`tsconfig.json`、角色入口源码、`assets/` 与 README」，与 §8.2 的 6 项清单不一致。
4. **工具脚本落位不一致**
   - §5.6 写 `tools/scripts/check-entries.mjs`；`重构大计划/02-仓库映射与新工作区.md` 与 `chips-ecosystem/package.json`（`docs:check` 指向 `tools/gates/check-docs.mjs`）登记的是 `tools/gates/`。
5. **示例目录层级差异**
   - §5.5 的 `build` 脚本按 `plugins/<名称>/`（两层）书写 `../../tools/...`；`examples/plugins/<名称>/` 为三层，相对路径需变化，文档未说明。
6. **附加发现：`render.js` 未被忽略**
   - `薯片生态文档库/02-开发规范/01.07-...-七、构建产物目录.md` §7.1 的 `.gitignore` 清单列出 `dist/`、`*.cpk` 等，但 `render.js` 输出在插件包根，未被任何忽略规则覆盖，存在误提交构建产物的风险。

## 三、影响范围

- W1-SCAFFOLD 若严格按 §8.2 生成，产物无法按 §5.5 构建，违反「生成结果必须能直接通过构建」的条款。
- 插件构建脚本中入口校验脚本的相对路径与落位目录无法确定，W1-GATES 与 W1-CLI 可能各自实现一次。
- 全部 `plugins/*` 与 `examples/plugins/*` 的构建脚本存在同类偏差风险。

## 四、复现步骤

1. 按 §8.2 的 6 文件清单生成一个 app 插件工程。
2. 读取 `package.json` 的 `build` 脚本（§5.5 标准脚本），执行 `pnpm --filter <包> run build`。
3. 观察：`vite` 找不到 `vite.main.config.ts` / `vite.render.config.ts`，构建失败；`chips plugin validate` 因缺少 `dist/index.js` / `render.js` 失败。

## 五、期望行为

1. 统一权威口径：app 模板文件清单补齐构建所需文件（至少 `vite.shared.ts`、`vite.main.config.ts`、`vite.render.config.ts` 与 `README.md`），或明确由 `@chips/cli`/SDK 提供统一的构建命令并同步修改 §5.5。
2. 统一入口校验脚本的落位目录与文件名（`tools/gates/` 或 `tools/scripts/`），并给出 `examples/plugins/*` 的相对路径写法。
3. `01.07 §7.1` 的忽略清单补充插件根 `render.js`（例如 `**/render.js`）。

## 六、暂行处理

- `examples/plugins/hello/` 按 `02.05 §5.5` 手写三份 vite 配置并进行平台 vendor 外部化；入口校验脚本临时引用 `tools/gates/check-entries.mjs`（与 W0 骨架的 `tools/gates/` 口径一致），等待工单收口后回归。
- 已按「与模板同构」保留其余结构与 `app` 模板一致（另加 `assets/schemas/config.schema.json` 与测试文件，见插件自身开发计划）。
