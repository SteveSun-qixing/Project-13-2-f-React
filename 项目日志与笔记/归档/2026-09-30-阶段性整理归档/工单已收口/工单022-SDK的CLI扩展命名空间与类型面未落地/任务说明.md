# 工单022 —— SDK `ChipsBridge` 的 CLI 扩展命名空间 `cliCommand` / `cliTask` 与主入口 CLI 扩展类型面整体未落地

> 登记日期：2026-09-20
> 来源：task043《契约-代码漂移审计-2026-09-20》面 1 第 1、2 条与面 5 第 3 条（W2 P0），登记前已逐条到代码复核。
> 性质：只登记问题，不含解决办法。

## 一、背景

《02-SDK-API规范》§3.5 为 `ChipsBridge` 承诺两个只读扩展命名空间 `cliCommand: CliCommandApi` 与 `cliTask: CliTaskApi`（`薯片生态文档库/05-接口与契约/02.03-02-SDK-API规范-三、客户端封装.md:60`（类体声明）、`:225-247`（§3.5 全节，含方法与路由表））；《02-SDK-API规范》§2.2 与 CLI 完整参考 §5.6 要求这批 CLI 扩展类型从 `@chips/sdk` 主入口可达（`06/07-CLI完整参考` §5.6 权威示例以 `import type { CliCommandApi, CliTaskApi } from '@chips/sdk'` 起手）；§11 约束 3（`05/02.11:14`）明确「除 CLI 扩展命名空间外不得增加成员」，即该命名空间是契约设计的一部分而非可选增强。同时《04-能力契约规范》§7.17 的 `cli:task-*` 五项能力的「SDK 类型化封装」层按 §3.5/§5.6 承诺落在这对命名空间上。

## 二、证据（文件:行号，均于 2026-09-20 复核）

1. `chips-ecosystem/packages/sdk/src/client/chips-bridge.ts:56-119`：`ChipsBridge` 类体只有 `request`（:87）、`subscribe`（:105）、`resource`（:116）三个方法与私有 `#target()`，无任何 `cliCommand` / `cliTask` 成员；文件头注释（:4-5）自述「方法面冻结为 request / subscribe / resource 三个方法」。
2. 全 `packages/sdk/src` 目录 grep `cliCommand|CliCommandApi` 0 命中（本轮实测）；`cliTask` 作为命名空间成员同样 0 命中（仅存在 `CliTaskRecord` 等类型名）。
3. `chips-ecosystem/packages/sdk/src/index.ts:142-156`：主入口 CLI 域类型只导出 `CliTaskRecord`、`CliTaskStatus` 与五对 `ICliTask*Input/Output`，无任何 `CliCommand*` 类型、无 `CliCommandApi` / `CliTaskApi`。
4. `chips-ecosystem/packages/sdk/src/index.ts:9-10`：入口头注释自述「§2.2 清单中的 manifest 与 CLI 扩展类型尚未随本入口落地，缺口登记见包内说明与波次报告」——缺口自知但未进工单台账（manifest 部分另立工单023）。
5. 能力契约类型侧已就位：`chips-ecosystem/packages/sdk/src/types/capabilities/cli-task.ts` 定义 `cli:task-*` 五项能力的输入/输出契约，但没有任何客户端封装消费它们（第 2 条 grep 佐证）。

## 三、影响范围

- 断链：契约文档中 `client.cliTask.active()` 一类正式示例代码在真实工程中不可运行；CLI 完整参考 §5.6 权威示例整体不可编译（类型导入即失败）。
- 能力缺位：`cli:task-*` 能力虽有类型、可被裸 `request` 调用，但契约承诺的「SDK 类型化封装」层不存在，调用方被迫裸调字符串能力 ID 或绕行 `@chips/cli` 包内私有类型面（后者与工单台账中「SDK 不维护第二份命令索引或任务模型」的 §11 约束 12 相抵触，相关双份事实源问题即审计报告面 1 第 3 条，P1，留审计台账）。
- 涉及包：`@chips/sdk`（客户端与主入口）、`@chips/cli`（消费侧）、全部按 §5.6 示例编写的插件/平台组件代码。

## 四、复现步骤

1. `chips-ecosystem` 内构建 `@chips/sdk`。
2. 在挂接工作区的 TS 工程中写 `import type { CliCommandApi } from '@chips/sdk';` —— `tsc` 报 TS2305（模块无导出的成员）。
3. 运行 `const bridge = new ChipsBridge(); bridge.cliCommand.list(...)` —— 运行时 `cliCommand` 为 `undefined`，TypeError。
4. 对照文档 `02.03-02-SDK-API规范-三、客户端封装.md:225-247` 与代码 `packages/sdk/src/client/chips-bridge.ts:56-119`，差额即上述两成员。

## 五、期望行为

契约与代码收敛为同一事实源：要么 SDK 落地 §3.5 命名空间与 §2.2/§5.6 类型导出、使文档示例逐字可运行；要么契约修订并显式撤回该承诺。在裁定作出前，任何按现契约编写的调用代码都无法通过构建。
