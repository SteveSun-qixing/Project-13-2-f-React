# 工单 002：应用窗口 UI 根环境（ChipsProvider）挂载责任口径不一致

> 登记：W1-EXAMPLE（2026-09-19）
> 状态：已收口（2026-09-20，裁决=UI 根环境由插件入口挂载、平台窗口壳不提供；五处文档口径统一，见同目录 收口记录.md）
> 影响：`@chips/ui` 指南与 app 插件开发指南的示例、全部 app 插件窗口 UI、平台窗口壳（W1-HOST）与金链路 UI 验证

---

## 一、背景

应用窗口 UI 的根组件（`render.js` 默认导出组件）是否需要自行挂载 `ChipsProvider`（以及 `CommandProvider`），文档库存在两套口径；按任一口径实现都可能出现「令牌不可用」或「重复挂载主题根」的缺陷。

## 二、证据

1. **要求入口挂载**：`薯片生态文档库/02-开发规范/08.03-08-@chips-ui共享层使用指南-三、ChipsProvider 与命令运行时.md` §3.1
   - 「挂载方：应用窗口 UI 入口（`render.js` 默认导出组件，即 `AppRoot`）挂载一次，包裹整个应用界面树」；
   - 同一窗口内不得重复挂载 `ChipsProvider`，不得在子树上另建主题根。
2. **完整示例挂载**：`薯片生态文档库/02-开发规范/08.07-...-七、完整示例.md` §7.2——`AppRoot` 挂载 `ChipsProvider` + `CommandProvider` 并默认导出。
3. **示例不挂载**：
   - `薯片生态文档库/03-插件开发/01.03-01-快速开始-三、创建第一个应用插件.md` §3.5：`AppView` 直接返回 `<div>`，未包裹 `ChipsProvider`；
   - `薯片生态文档库/05-接口与契约/07.09-...-九、完整示例.md` §9.4：`AppView` 直接返回 `<Spin />` / `<div>`；
   - `薯片生态文档库/03-插件开发/03.11-...-十一、完整示例.md` §11.4：`AppView` 使用 `theme.useToken()`，但同样未挂载任何主题根。
4. **平台壳职责未明**：`03-插件开发/03.03-...-三、项目结构.md` 只说明「宿主文档由平台提供」，未说明平台窗口壳是否已提供主题根；`08.03 §3.1` 又要求插件入口挂载。

## 三、影响范围

- 若窗口壳不提供主题根：按 01.03 / 07.09 / 03.11 编写的 UI 调用 `theme.useToken()` 将在运行期报错或拿不到令牌。
- 若窗口壳提供主题根：按 08.03 / 08.07 挂载将造成重复挂载（08.03 明文禁止）。
- 金链路中「打开窗口 → 界面渲染 → 令牌生效」缺少唯一的权威口径。

## 四、复现步骤

1. 任选上述两套文档之一实现一个最小 app 插件的 `AppView` 并通过 `render.js` 装载。
2. 与另一口径核对：挂载/不挂载 `ChipsProvider` 的行为互相矛盾，无法同时满足两份文档。

## 五、期望行为

1. 明确应用窗口壳与插件入口各自的 UI 根环境职责：若壳层提供，则从 08.03/08.07 移除入口挂载要求；若插件入口提供，则明确壳层不得提供，并统一更新 01.03 / 07.09 / 03.11 的示例。
2. 同步说明 `CommandProvider` 的挂载条件（仅使用 ui 目标命令时需要），避免示例无差别挂载。

## 六、暂行处理

- `examples/plugins/hello/src/ui/AppView.tsx` 暂按 `@chips/ui` 指南（08.03/08.07）在根组件挂载 `ChipsProvider`（`surface="window"`，与 manifest 一致）；本示例不注册 ui 目标命令，故未挂载 `CommandProvider`。
- 该约定以工单收口结论为准；若确认壳层已提供主题根，本示例将同步移除包裹。
