# 卡片传输协议

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：正式版
> 适用范围：`.card` / `.box` 在本地设备与内容服务器之间传输的权威协议：传输会话（创建、预签名、分片、断点续传、取消、恢复）、完整离线卡片与网络资源卡片的可逆改写与还原（含可逆恢复清单）、摘要与完整性校验、预签名与对象存储桶角色、传输队列与 `transfer:*` 事件映射、错误码与安全约束；不覆盖卡片/箱子的包结构语义、渲染链路与服务器产品设计。

## 三、传输会话

### 3.1 上传会话生命周期

```text
created ──首次预签名──▶ uploading ──complete 成功──▶ completed
   │                        │                          │
   │                        ├──abort──▶ aborted        │
   └────────── 超期 ────────┴──▶ expired               └── 终态，不可再变更
```

| 状态 | 含义 | 允许操作 |
|---|---|---|
| `created` | 会话已创建，尚未签发任何对象 | 预签名、查询、abort、complete（仅空会话不允许） |
| `uploading` | 已签发至少一个对象；对象与分片可继续上传 | 预签名、分片续签、查询、abort、complete |
| `completed` | `complete` 成功，服务器已接收对象与恢复清单 | 查询；重复 complete 幂等；abort 返回状态错误 |
| `aborted` | 调用方取消，未提交对象已清理 | 查询；其余操作返回状态错误 |
| `expired` | 超过会话有效期，服务器已使其失效 | 查询；其余操作返回 `CARD_TRANSFER_SESSION_EXPIRED` |

规则：

1. 会话有效期由服务器配置并在创建响应中以 `expiresAt`（ISO 8601 UTC）返回；预签名地址有效期不得超过会话剩余有效期，每个地址在自己的 `expiresAt` 前有效。
2. 过期判定以服务器时钟为准；客户端不得以本地时钟提前或推迟判定。
3. 状态变更由服务器持久化；`completed` / `aborted` / `expired` 为终态。
4. 同一服务器同一用户的 `idempotencyKey` 重复创建返回同一会话（幂等）；不同请求体复用同一键视为同一会话，服务器以首次创建内容为准。
5. 未提交的已完成对象在会话过期或 abort 后由服务器按清理策略回收；`completed` 的会话产物不回收。

### 3.2 创建上传会话

```http
POST /api/v1/card-transfer/upload-sessions
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "contentType": "card",
  "fileName": "demo.card",
  "roomId": null,
  "idempotencyKey": "chips-client-7f3a91",
  "includeRenderArtifacts": false,
  "client": {
    "name": "Chips Card Transfer",
    "version": "1.0.0",
    "platform": "darwin"
  }
}
```

请求字段：

| 字段 | 类型 | 必填 | 语义 |
|---|---|---|---|
| `contentType` | `'card' \| 'box'` | 否 | 默认 `card`；`box` 走箱子上传分支（3.10） |
| `fileName` | string | 否 | 源文件名，用于默认标题；最长 500 字符 |
| `roomId` | string \| null | 否 | 归属房间；需 `capabilities.rooms` |
| `idempotencyKey` | string | 否 | 幂等键；客户端生成，同一用户内唯一 |
| `includeRenderArtifacts` | boolean | 否 | 默认 `false`；`true` 时客户端渲染并上传产物 |
| `client` | object | 否 | `name` / `version` / `platform`，用于发布信息与诊断 |

卡片会话响应（201）：

```json
{
  "data": {
    "schemaVersion": "1.0.0",
    "uploadId": "6f7c1d2e-8a4b-4c5d-9e0f-1a2b3c4d5e6f",
    "versionId": "6f7c1d2e-8a4b-4c5d-9e0f-1a2b3c4d5e6f",
    "cardId": "1a2b3c4d-5e6f-4a8b-9c0d-2e3f4a5b6c7d",
    "expiresAt": "2026-09-19T12:00:00.000Z",
    "resourcePrefix": "cards/{cardId}/versions/{versionId}/resources",
    "capabilities": { "renderArtifacts": false, "multipart": true, "rooms": true },
    "networkCard": {
      "bucket": "chips-card-resources",
      "objectKey": "cards/{cardId}/versions/{versionId}/network-card/card.card",
      "publicUrl": "https://file.example/chips-card-resources/cards/{cardId}/versions/{versionId}/network-card/card.card"
    }
  }
}
```

箱子会话响应（201）：

```json
{
  "data": {
    "schemaVersion": "1.0.0",
    "uploadId": "6f7c1d2e-8a4b-4c5d-9e0f-1a2b3c4d5e6f",
    "versionId": "6f7c1d2e-8a4b-4c5d-9e0f-1a2b3c4d5e6f",

    "expiresAt": "2026-09-19T12:00:00.000Z",
    "resourcePrefix": "boxes/{boxId}/versions/{versionId}",

      "bucket": "chips-box-files",
      "objectKey": "boxes/{boxId}/versions/{versionId}/box.box",
      "publicUrl": ""
    }

```

- `versionId` 与 `uploadId` 是同一会话标识：`versionId` 是内容版本语义，`uploadId` 是控制面资源定位语义。
- `resourcePrefix`、`objectKey`、`publicUrl` 由服务器生成；客户端不得构造、拼接或裁剪对象键。
- 箱子源文件桶为私有桶，`publicUrl` 恒为空字符串。

### 3.3 对象与分片预签名

```http
POST /api/v1/card-transfer/upload-sessions/:uploadId/objects:presign
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "objects": [
    { "role": "resource", "relativePath": "video.mp4", "sizeBytes": 1048576, "mimeType": "video/mp4", "sha256": "b2c3…b2c3" },
    { "role": "resource", "relativePath": "tracks/echo.mp3", "sizeBytes": 8388608, "mimeType": "audio/mpeg", "sha256": "c3d4…c3d4" },
    { "role": "network-card", "sizeBytes": 2048, "mimeType": "application/vnd.chips.card+zip", "sha256": "d4e5…d4e5" },
    { "role": "render-file", "relativePath": "index.html", "sizeBytes": 512, "mimeType": "text/html", "sha256": "e5f6…e5f6" },
    { "role": "cover-file", "relativePath": "index.html", "sizeBytes": 256, "mimeType": "text/html", "sha256": "f6a7…f6a7" }
  ]
}
```

请求规则：

1. 单次请求对象数不超过服务器上限（默认 1000）；超出返回 `VALIDATION_ERROR`。
2. `role` 取值与适用会话：

| 角色 | 卡片会话 | 箱子会话 | 对象内容 |
|---|---|---|---|
| `network-card` | 必需 | 不允许 | 网络资源卡片 |
| `resource` | 卡片资源对象 | 不允许 | 卡片内部资源字节 |
| `render-file` | 仅 `renderArtifacts` | 不允许 | 查看产物文件 |
| `cover-file` | 仅 `renderArtifacts` | 可选（箱子封面） | 封面产物/封面文件 |
| `box-file` | 不允许 | 必需 | 箱子源文件 |

3. `relativePath` 必须是规范化卡片根相对路径（[01-卡片文件格式](../04-文件格式规范/01-卡片文件格式.md) §3.3、§8.2）：`/` 分隔、UTF-8 + NFC、无 `..`、无前导 `/`、无控制字符；服务器必须重新校验，非法即拒绝。
4. `sizeBytes` 与 `mimeType` 必填；`sha256` 为对象字节的 SHA-256 十六进制（小写，64 位），见第五节。
5. 同一会话内同一 `relativePath` 只允许一个 `resource` / `render-file` / `cover-file` 对象；重复预签名视为续签并返回同一 `objectId`。
6. 服务器决定每个对象的传输模式：`sizeBytes` 不超过服务端分片阈值时为 `single`（单次 `PUT`）；超过时为 `multipart`（分片上传），并在响应中返回 `multipart` 计划与首批分片地址。分片大小与单对象上限由服务器决定，客户端不得假设固定值。

响应（200）：

```json
{

    "objects": [
      {
        "objectId": "obj-7f3a91",
        "role": "resource",

        "publicUrl": "https://file.example/chips-card-resources/cards/{cardId}/versions/{versionId}/resources/video.mp4",

        "mimeType": "video/mp4",
        "sha256": "b2c3…b2c3",
        "mode": "single",
        "upload": {
          "method": "PUT",

          "headers": {
            "content-type": "video/mp4",

            "x-amz-meta-chips-card-version-id": "{versionId}",
            "x-amz-meta-chips-transfer-role": "resource",
            "x-amz-meta-chips-sha256": "b2c3…b2c3"
          },

        }
      },
      {
        "objectId": "obj-7f3a92",
        "role": "resource",
        "relativePath": "tracks/echo.mp3",
        "bucket": "chips-card-resources",
        "objectKey": "cards/{cardId}/versions/{versionId}/resources/tracks/echo.mp3",
        "publicUrl": "https://file.example/…/tracks/echo.mp3",
        "sizeBytes": 8388608,
        "mimeType": "audio/mpeg",
        "sha256": "c3d4…c3d4",

        "multipart": {
          "partSizeBytes": 4194304,
          "partCount": 2,
          "uploadedParts": []
        },
        "parts": [
          { "partNumber": 1, "method": "PUT", "url": "https://file.example/…&partNumber=1&X-Amz-Signature=…", "headers": {}, "expiresAt": "2026-09-19T11:00:00.000Z" },
          { "partNumber": 2, "method": "PUT", "url": "https://file.example/…&partNumber=2&X-Amz-Signature=…", "headers": {}, "expiresAt": "2026-09-19T11:00:00.000Z" }
        ]
      }
    ]
  }
}
```

- `uploadedParts` 是该对象当前已完成分片（断点恢复时非空），每项 `{ partNumber, sizeBytes, etag }`；服务器以对象存储权威结果为准，不信任客户端上报的分片状态。
- `parts` 只返回本次签发的分片地址，数量受服务器单次签发上限约束；缺口通过 3.3.1 续签补齐。
- 客户端必须原样使用响应中的 `method`、`url`、`headers` 上传；不得改写、增删或复用地址访问其他对象。
- 预签名地址视为凭证：不得写入卡片、恢复清单、日志、错误详情或任何持久化位置。

> 本文 JSON 示例中的摘要、对象键、URL 与预签名参数为示意值；真实值由服务器、对象存储与传输引擎生成。

#### 3.3.1 分片地址续签

```http
POST /api/v1/card-transfer/upload-sessions/:uploadId/objects:parts:presign
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "objects": [
    { "objectId": "obj-7f3a92", "partNumbers": [2] },
    { "objectId": "obj-7f3a93" }
  ]
}
```

- `partNumbers` 省略时，服务器返回该对象全部未完成分片的地址（受单次上限约束，客户端分批申请直到覆盖全部分片）。
- 服务器必须对每个分片地址重新校验对象归属与会话状态。
- 响应 `objects` 项与 3.3 的 `multipart` / `parts` 结构一致；已上传分片只出现在 `uploadedParts`，不重复签发。

### 3.4 分片上传

上传顺序（卡片会话）：

1. 预签名全部资源对象与渲染产物对象；
2. 按对象逐个上传，同一对象内分片可并发但必须按 `partNumber` 独立完成；不同对象之间的并发数受队列任务并发配置约束（7.3）；
3. 全部资源与产物对象完成后，执行改写并打包网络资源卡片；
4. 预签名 `network-card` 对象并上传；
5. 提交 `complete`（3.6）。

分片规则：

1. 分片字节序列按 `partNumber` 升序拼接后必须等于对象完整字节；分片边界不得重叠或缺失。
2. 同一分片的预签名地址在有效期内可重复 `PUT`（覆盖式幂等）；重试不得改变分片内容。
3. 分片仅记录 `partNumber`、`sizeBytes` 与 `ETag`；对象整体摘要（`sha256`）在 `complete` 阶段校验（5.3）。
4. 取消、失败或过期时，服务器必须对未完成的 `multipart` 对象执行中止（AbortMultipartUpload），释放未完成分片；已 completed 的对象不受影响。
5. `single` 时代的对象不得因重试改为 `multipart`，同一会话内对象模式由服务器固定。

### 3.5 断点与恢复

#### 3.5.1 服务端断点查询

```http
GET /api/v1/card-transfer/upload-sessions/:uploadId
Authorization: Bearer <token>
```

响应（200）：

```json
{
  "data": {
    "uploadId": "6f7c1d2e-…",
    "contentType": "card",
    "status": "uploading",
    "expiresAt": "2026-09-19T12:00:00.000Z",
    "capabilities": { "renderArtifacts": false, "multipart": true, "rooms": true },
    "objects": [
      {
        "objectId": "obj-7f3a92",
        "role": "resource",
        "relativePath": "tracks/echo.mp3",
        "bucket": "chips-card-resources",
        "objectKey": "cards/{cardId}/versions/{versionId}/resources/tracks/echo.mp3",
        "publicUrl": "https://file.example/…/tracks/echo.mp3",
        "sizeBytes": 8388608,
        "mimeType": "audio/mpeg",
        "sha256": "c3d4…c3d4",
        "mode": "multipart",
        "multipart": { "partSizeBytes": 4194304, "partCount": 2, "uploadedParts": [{ "partNumber": 1, "sizeBytes": 4194304, "etag": "…" }] },
        "completed": false
      }
    ]
  }
}
```

- 该接口是断点恢复的服务端权威视图；客户端重启后必须先查询会话，再续签缺失分片或补齐对象。
- `completed` 为 true 的对象不再重复签发上传地址。

#### 3.5.2 本地检查点

传输引擎必须为进行中的上传任务保存最小检查点；检查点存放在工作区临时工作目录（平台保留前缀，[13-工作区设计](../01-架构设计/01-子系统设计/13-工作区设计.md) §3.2），并在崩溃后按工作区恢复流程参与清理登记。检查点至少包含：

| 字段 | 语义 |
|---|---|
| `schemaVersion` | 检查点版本（与协议主版本一致） |
| `transferId` | 队列任务标识 |
| `kind` | `card-upload` / `box-upload` |
| `serverBaseUrl` | 控制面基础地址 |
| `uploadId` / `versionId` | 会话标识 |
| `contentType` | `card` / `box` |
| `sourcePath` | 源文件受管路径 |
| `outputPath` | 本地工作副本位置（含网络资源卡片输出路径） |
| `cardId` / `boxId` | 服务器分配的内容标识（创建响应后写入） |
| `phase` | 当前阶段（7.2） |
| `updatedAt` | 最后更新时间 |

- 检查点不保存分片状态、对象键或预签名地址：分片状态以 3.5.1 查询为准，预签名地址一律重新签发。
- 检查点不得包含服务器凭证材料与预签名 URL。

#### 3.5.3 恢复流程

1. 读取检查点，确认会话 `status = created / uploading` 且未过期；
2. 调用 3.5.1 查询对象与分片状态；
3. 对未完成对象按 3.3.1 续签缺失分片或对未预签名对象重新预签名；
4. 跳过 `completed` 对象与已上传分片，继续上传；
5. 若会话已过期或 `aborted`，丢弃检查点并按 3.2 新建会话，从头执行上传（不提供跨会话对象复用）；
6. 恢复后任务重新进入队列，`transfer:progress` 从权威已传字节继续累计。

```json
    ],
    "richTextContentFiles": []
  },
  "renderArtifacts": {
    "rendererVersion": "chips-client-renderer-1",
    "view": { "entryRelativePath": "index.html", "fileCount": 3, "sizeBytes": 1024 },
    "cover": { "entryRelativePath": "index.html", "fileCount": 2, "sizeBytes": 512 }

```

- `restoreManifest` 必填；`resources` 必须覆盖本次上传的全部资源对象。
- `renderArtifacts` 仅在 `includeRenderArtifacts: true` 时提交：`rendererVersion` 必填，`view.entryRelativePath` 与 `cover.entryRelativePath` 必须是已预签名并上传的 `render-file` / `cover-file` 相对路径；未提交产物时服务器将卡片置为待渲染状态（`status = pending`）。
- `networkCard` / `resources` 的 `objectId`、`bucket`、`objectKey`、`sizeBytes`、`sha256` 必须与预签名记录一致，否则 `CARD_TRANSFER_OBJECT_MISMATCH`。

服务器校验顺序（任一失败即整体拒绝，不产生部分提交）：

1. 会话归属、状态与有效期；
2. 提交对象全部属于本会话（以 `objectId` 与对象键前缀交叉校验）；
3. 对每个对象执行 Head：大小与提交一致；摘要与对象元数据 `x-amz-meta-chips-sha256` 一致（5.3）；
4. `multipart` 对象已在服务器侧完成合并；
5. 恢复清单结构合法（4.4）且 `schemaVersion` 受支持；
6. 网络资源卡片内容引用本会话全部资源 URL，且卡内不再包含这些资源的原始字节（防止"模型新 + 资源旧"的混合提交）；
7. 渲染产物（如提交）入口文件已上传且已预签名。

响应（卡片，202）：

```json
{
  "data": {
    "cardId": "1a2b3c4d-…",
    "versionId": "6f7c1d2e-…",
    "status": "ready",
    "communityUrl": "https://www.example.com/cards/{cardId}",
    "renderStatusUrl": "/api/v1/cards/{cardId}/render-status"
  }
}
```

- `status` 取值 `ready`（内容已发布）或 `pending`（服务器渲染模式下等待查看产物；客户端渲染模式未提交产物时同样为 pending）。
- `renderStatusUrl` 只在服务器提供查看状态查询时返回（2.4）。
- `complete` 幂等：同一会话重复提交且内容一致时返回同一结果；内容不一致返回 `CARD_TRANSFER_SESSION_STATE_INVALID`；`aborted` / `expired` 会话返回对应错误。

### 3.7 取消与过期

```http
POST /api/v1/card-transfer/upload-sessions/:uploadId/abort
Authorization: Bearer <token>
```

- 响应 `{ "data": { "uploadId": "…", "status": "cancelled" } }`；`abort` 幂等：重复调用返回同一结果。
- 取消必须执行：中止全部未完成的 `multipart` 对象、清理会话未提交临时对象；不影响已提交的其他会话。
- 已完成会话执行 `abort` 返回 `CARD_TRANSFER_SESSION_STATE_INVALID`，不改变已发布内容。
- 服务器按会话有效期把超期会话置为 `expired`；过期后的预签名地址即使未到期也不得再被接受。
