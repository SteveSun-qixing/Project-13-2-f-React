## 三、E2E 承载方式结论（W2 风险登记第 3 条）

1. **本机（macOS）可跑，无需 Xvfb**：`pnpm test:e2e`（harness）实测 EXIT=0；Electron headful 短暂起窗自收。`_electron.launch`（`launcher.ts:85-94`）不支持 Electron 无头模式，macOS 有窗口服务器故本机即 CI 级承载。
2. **无显示 Linux 环境口径**：`playwright.config.ts` 全文无任何 headless/xvfb 配置；`tests/e2e/开发日志.md:78-79` 已自认承载说明缺失。结论口径：**Linux 无显示环境用 `xvfb-run -a pnpm test:e2e` 包裹**（Playwright 官方对 Electron 的标准方案），本机暂无法实测，W3 若接 CI 需在 Linux runner 落地并实测一次。
3. **`CHIPS_E2E_REQUIRE_APP=1` 首跑条件链**（缺一即红）：
   - a) 宿主构建产物入口**自带 bootstrap**：当前 `dist/main/main.js` 无自举（实测失败点 `launcher.ts:107`）；过渡可用 `CHIPS_E2E_APP_ENTRY=./dist/main/self-check.js` 覆盖（`environment.ts:72-76` 支持），但自检页非金链路渲染面，最终仍需生产入口；
   - b) 产物新鲜度：`packages/host/dist` 现存 17:22 构建（在途源已再度变更），收口后需重跑 `pnpm --filter @chips/host build`（**本轮我未跑重型构建，属跳过的验证**）；
   - c) 单实例锁：`main.ts:67-70 requestSingleInstanceLock` 决定 golden-path 必须 `workers:1`（config:31 已如此），且残留 Electron 进程会导致后续运行假失败。
4. 可复现命令与判定：
   - `pnpm test:e2e; echo EXIT=$?` → 期望 0（harness 2/2）；实测 0。
   - `CHIPS_E2E_REQUIRE_APP=1 pnpm test:e2e` → 当前 1（golden-path 30s 无窗）；W2 收口后期望 3/3。
   - 失败产物：`tests/e2e/test-results/**/trace.zip`（`pnpm exec playwright show-trace` 消费）。

## 五、覆盖率门禁消费链与 W3 扩测口径影响

1. **链路现状**：`pnpm test:coverage`（根 :16）→ `@chips/testing coverage`（`tools/testing/src/coverage/run.ts:14-27` 两阶段 tarpaulin+vitest，:57-73 委托 G6 判定，工单017 唯一判定面）→ `tools/gates/check-coverage.mjs`（阈值/分组单一事实源 `tools/gates/gates.config.json` coverage 段；`tools/testing/src/thresholds.ts` 为其装载器，根 `vitest.config.ts:20-46` 同源消费）。豁免链：`coverage.exemption.registry → ../项目日志与笔记/技术债务清单.md` 的 `GATE-EXEMPTIONS` JSON fence（`exemption.mjs:13-14` 正则消费；现仅 TD-001：rust-core/lines，期限 2026-10-19，实测 COVERAGE030 留痕放行生效）。
2. **W3 扩测的口径影响（三条必须写进 W3 派单书）**：
   - **rust-core 统计面自动扩大**：`gates.config.json` `coreMatch = ["packages/core-rust/crates/chips-", "packages/native/"]` 前缀匹配——chips-parser 收口、chips-resource（W3 交付）落地后**自动并入 >90% 核心判定**；当前 coverage 快照（9/20 06:32）不含 parser/resource 行。
