# 工单173：SDK 主入口 file 类型重复导出

## 背景

task041「万能文件链路」任务建立 `Chips-SDK/src/contracts/file.ts` 新契约层（`file.*` 协议正式类型源），迁移过程中在 `Chips-SDK/src/index.ts` 末尾追加了来自 `./contracts/file` 的导出块，但未同步处理主入口前部既有的 `./api/file`（旧实现层）类型导出块，两个块对同一批类型名重复 `export type`，产生 TypeScript 重复标识符错误。该问题属于 task041 因额度中断的遗留，阻塞所有通过类型入口穿透 SDK 源码的应用插件 typecheck。

## 证据

在 Chips-Office 执行 `npx tsc -p tsconfig.json --noEmit`（chips-sdk 以 workspace 软链接方式被类型解析）报错 32 处，全部为 `../Chips-SDK/src/index.ts` 的 TS2300 Duplicate identifier：

```
../Chips-SDK/src/index.ts(430,3): error TS2300: Duplicate identifier 'FileCompareRequest'.
../Chips-SDK/src/index.ts(431,3): error TS2300: Duplicate identifier 'FileCompareResult'.
../Chips-SDK/src/index.ts(435,3): error TS2300: Duplicate identifier 'FileConvertRequest'.
../Chips-SDK/src/index.ts(436,3): error TS2300: Duplicate identifier 'FileConvertResult'.
../Chips-SDK/src/index.ts(441,3): error TS2300: Duplicate identifier 'FileDeleteOptions'.
../Chips-SDK/src/index.ts(446,3): error TS2300: Duplicate identifier 'FileHandlerTier'.
../Chips-SDK/src/index.ts(451,3): error TS2300: Duplicate identifier 'FileSessionCreateRequest'.
... （共 32 处，涵盖 FileSession*/FileConvert*/FileCompare*/FileVersionDiff*/FileWatchEventPayload 等）
```

根因定位：`Chips-SDK/src/index.ts` 中存在两段 file 类型导出——

- 前部（约 95-140 行）：`export type { ... } from "./api/file"`（旧实现层类型，`FileSessionCreateRequest` 等定义于 `api/file.ts`）；
- 末部（约 424-466 行）：`export { FILE_ACTIONS... }` + `export type { ... } from "./contracts/file"`（task041 新契约层，`contracts/file.ts` 中同名类型几乎同形，如 `FileSessionCreateRequest` 仅 `encoding` 字段从字面量联合改为 `FileTextEncoding` 别名）。

两段重复导出同名类型 → TS2300。`git status` 显示 `contracts/file.ts` 为未跟踪新文件、`index.ts` / `api/file.ts` 均有未提交修改，符合 task041 中断现场。

## 影响范围

- 所有以 `chips-sdk` 类型入口执行 `tsc --noEmit` 的应用插件与模块插件的 typecheck / verify 门禁（与工单116 的 SDK 类型穿透机制相同）；
- Chips-Office 当前验证链路（typecheck 阶段被阻断，lint/test/build 不受影响）；
- task041 万能文件链路迁移清单中「Chips-SDK 包主入口中只 import 来自 contracts/file.ts 的类型」这一验收项无法达成。

## 复现步骤

1. `cd Chips-Office`（或任意类型解析穿透到 chips-sdk 源码的插件仓库）；
2. 执行 `npm run typecheck` 或 `npx tsc -p tsconfig.json --noEmit`；
3. 观察 32 处 `../Chips-SDK/src/index.ts` TS2300 Duplicate identifier 错误。

## 期望行为

- `Chips-SDK/src/index.ts` 对每个导出名只保留唯一来源：按迁移指南验收项，共享 file 类型以 `contracts/file.ts` 为唯一类型源；
- `api/file.ts` 旧实现层的同名类型定义收敛为从 `contracts/file.ts` 导入/再导出（或实现层直接引用契约类型），`FileSessionApi / FileOperationsApi / FilePreviewApi / FileConvertApi / FileCompareApi` 等纯实现层接口保留在 api 层；
- Chips-SDK 自身 `npm test`（含 office-document.test.ts、client.test.ts、route-manifest.test.ts、contract-drift.test.ts）与消费方 typecheck 全部通过；
- 不引入任何 skip / 临时类型别名掩盖。

## 处理结果（2026-09-03，已闭环）

### 类型源统一方案

- **contracts/file.ts 为唯一类型源**：`file.*` 全部共享协议类型（63 个类型 + 4 个常量）以 `Chips-SDK/src/contracts/file.ts` 为唯一定义处，未做任何改动（仅消费方式收口）。
- **api/file.ts 收敛**：与契约重复的 37 个类型定义（FileFormat/FileCategory/FileDocumentType/FileSessionStatus/FileWatchEvent、FileSession* 10 个、FileReadOptions/FileStat/FileListOptions/FileWatchOptions/FileMkdirOptions/FileDeleteOptions/FileEntry/FileWatchEventPayload、FileDetectType* 2 个、FilePreview* 3 个、FileConvert*/FileBatchConvert* 6 个、FileCompare*/FileVersionDiff* 5 个）全部删除，改为从 `../contracts/file` 导入并再导出，`../api/file` 既有引用路径不失效；实现代码直接使用契约类型，`FileApi.write` 的 options 参数同步收敛为契约 `FileWriteOptions`。api 层特有类型 `FileContent` 与 `FileSessionApi / FileOperationsApi / FileTypeDetectionApi / FilePreviewApi / FileConvertApi / FileCompareApi / FileApi` 保留在 api 层。
- **api/plugin.ts 收敛**：`FileHandlerTier` 重复定义删除，改为从 `../contracts/file` 导入并再导出；plugin 层特有的 `FileHandlerKind / FileHandlerSlot / FileHandlerSlotPlugin` 不动。
- **index.ts 去重**：前部 `./api/file` 导出块收敛为 8 个 api 层特有类型（FileApi/FileContent/FileSessionApi/FileOperationsApi/FileTypeDetectionApi/FilePreviewApi/FileConvertApi/FileCompareApi）；末部 `./contracts/file` 导出块扩为完整 63 个契约类型（修复前仅 41 个，缺 FileStat/FileEntry/FilePreview* 等由旧前部块导出的契约类型）+ 原有 4 个常量值；plugin 导出块移除 `FileHandlerTier`。每个导出名现在只有唯一来源。

### 导出面核验

修复前后 file 相关导出名并集均为 78 个（74 类型 + 4 常量）：旧前部块 45 名 ∪ 旧 plugin 块 4 名 ∪ 旧末部块 41 名去重 = 新前部块 8 名 ∪ 新 plugin 块 3 名 ∪ 新末部块 63 名 + 4 常量。经 TypeScript 编译器 API 对 `src/index.ts` 模块导出枚举比对：无缺失、无重复、无新增（迁移前后所有消费方可导入的名字不变）。
