## 一、收口方案（单一事实源裁决）

判定基准：**门禁与 `chips plugin validate`（CLI `cpk-validate.ts` `validateLayout`）对四角色入口的期望同源一致**，互斥面归零。

| 层面                 | 落位                                                                                                                                                                                                                                                              |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 规范权威（判定依据） | 《04-文件格式规范/03-插件包格式》§2.3 根目录白名单（`render.js` 「按角色：`basecard` / `boxlayout` / `app` 必需，`service` 禁止」）与 §2.4 入口约定规则 2（「`service` 角色只有主进程部分」）。 |
| 角色输入（事实源）   | 插件工程包根 `manifest.yaml` 顶层 `type`（与 CLI `parseManifestText` → `validateManifest` 的 `role`、安装校验、自检清单同一来源）。**不做目录名嗅探、不接受调用方猜测**。                         |
| 门禁判定表（新增）   | `chips-ecosystem/tools/gates/lib/plugin-entries.mjs`：`PLUGIN_ROLES` 四角色清单（`:23`）与 `ROLE_RENDER_ENTRY_REQUIREMENTS` 渲染入口要求表（basecard/boxlayout/app → `required`，service → `forbidden`，`:39-44`）+ `resolvePluginRole()`（`:70-91`，fail-closed）。 |
| 既有同源消费面       | CLI：`packages/cli/src/artifacts/cpk-validate.ts:343-366`（`service` 携带 `render.js` → `CPK_LAYOUT_INVALID`；非 service 缺 `render.js` → `CPK_ENTRY_MISSING`）；scaffold：`tools/scaffold/src/templates/index.ts:18-22`（`RENDER_ENTRY_BY_ROLE`，service 无渲染入口）。三消费面取值集合一致，注释互指。 |

行为变更（只增不减，无豁免开关、无 `--skip-*`）：

1. `service`：只校验 `dist/index.js`；**缺 `render.js` 不再报 ENTRY001**（工单复现步骤 4 的红转绿）；携带 `render.js` → 新增违规码 **ENTRY004**（与 CLI「带 render.js 才错」同向，互斥面归零，工单期望 #2 成立）。
2. `basecard` / `boxlayout` / `app`：维持双入口校验，缺 `render.js` 仍报 ENTRY001（判定强度不变）。
3. 角色不可判定（`manifest.yaml` 缺失或不可读、缺顶层 `type`、`type` 不在四角色）：抛 `UsageError` → CLI **退出码 2**，`runCheck` 以拒绝态抛出（工单期望 #6 的工作区根无参伪检查随转为确定性用法错误：`pnpm gates:entries` 不带目录参数在仓库根 → 2）。
4. `summary` 新增 `role` / `renderRequirement`；`service` 时 `renderSpecifiers=null` 表示不校验。
