### 2.2 数据存储结论

**两仓均无 SQLite、无文件型数据库**：关系面＝PostgreSQL（drizzle 迁移链见 §1.4），对象面＝S3 兼容桶，队列面＝CPS Redis。W6 新仓库按契约生成**初始迁移**，旧增量链不随迁（《矩阵》#17/#7「保留设计」裁决）。

### 2.3 与旧 SDK / 旧宿主的耦合点（新生态重写时必须切断的面）

1. **CPS server 端 `chips-host` npm 直依赖**：`Chips-CommunityPlatformServer/packages/server/package.json` dependencies `"chips-host": "0.1.0"`；唯一导入点 `services/host-integration.ts:1` `import { HeadlessHostShell } from 'chips-host/headless-host-shell'`；启动钩子 `worker.ts:11` `import { hostIntegration } from './services/host-integration'`。→ W6 判重写，改接新平台无头壳交付物（《矩阵》:36；《17-跨端Shell与平台抽象设计》§七）。
2. **浏览器插件宿主链路整体废弃**：`routes/host-runtime.ts` + `services/web-resource-open-plan.ts` + `web/src/components/HostedPluginSurface.tsx` 等（《矩阵》#11，`《14》§6.5:339-346` 明令废止、不留兼容）。
3. **跨仓 workspace 链接**：CPS `pnpm-workspace.yaml` 挂 `../Chips-Host`、`../Chips-SDK`、`../Chips-Ui`；PS 挂 `../Chips-Ui`、`../Chips-SDK`（两文件实测全文）。→ 判废弃（《矩阵》:35、#21/#12），新仓库统一 `workspace:*` 规范（`重构大计划/02-仓库映射与新工作区.md:74`）。
