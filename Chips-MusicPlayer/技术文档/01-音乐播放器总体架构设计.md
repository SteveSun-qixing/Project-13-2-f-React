# 音乐播放器总体架构设计

## 1. 项目角色

`Chips-MusicPlayer` 是薯片生态中的应用插件音乐播放器。它不承载自研解码器、媒体库索引或转码服务，只负责：

1. 恢复要播放的音频目标；
2. 为当前音频目标构建正式播放会话；
3. 发现并解析歌词、封面与嵌入元数据；
4. 承载左封面右歌词界面；
5. 调用 Host 正式文件、资源、平台、主题、多语言和命令能力。

## 2. 分层结构

当前实现分为六层：

### 2.1 App Runtime / Scene

- 文件：
  - `src/App.tsx`
  - `src/app/AppRoot.tsx`
  - `src/app/AppProviders.tsx`
  - `src/app/AppRuntimeProvider.tsx`
  - `src/app/AppShell.tsx`
  - `src/app/scene-registry.ts`
- 职责：
  - 通过 `ChipsEnvironmentProvider` 注入 SDK client、主题、语言、surface、权限与诊断；
  - 读取 App / Scene / surface 上下文；
  - 恢复启动上下文；
  - 归一音频源；
  - 管理播放队列、当前曲目、反馈、保存状态和 Host 平台信息；
  - 协调打开、保存、拖放、伴生文件发现与嵌入元数据解析。

`src/App.tsx` 只保留轻量 re-export，真实根组件由 `src/app/AppRoot.tsx` 承载。

### 2.2 Runtime Client

- 文件：
  - `src/runtime/chips-client.ts`
  - `src/runtime/environment-client.ts`
  - `src/runtime/launch-context.ts`
  - `src/runtime/theme-runtime.ts`
- 职责：
  - 创建并复用同一个 `chips-sdk` client；
  - 将 SDK client 适配为组件库 Environment 可消费接口；
  - 读取和规范化 Host launch context；
  - 读取文档注入主题快照，作为 Host 主题加载前的首屏输入。

### 2.3 Commands

- 文件：
  - `src/commands/music-player-commands.tsx`
  - `src/commands/useMusicPlayerCommands.ts`
- 职责：
  - 定义稳定 command id、handler id、i18n key、图标、快捷键和菜单 / 工具栏 placement；
  - 通过 `useCommandRegistry` 注册到 `@chips/ui` CommandRegistry，由 `AppChrome` 的 `useCommandShortcuts` 统一分发快捷键；
  - 根据播放状态、队列状态、静音、循环和保存状态更新命令可用性；
  - 不向 Host 传递业务函数，Host 只保存可序列化 metadata。

### 2.4 Audio Engine 与 Playback Controller

- 文件：
  - `src/engine/audio-engine.ts`
  - `src/hooks/useMusicPlayerController.ts`
- 职责：
  - `audio-engine.ts` 为纯 TS 状态机（不含 React、不依赖 DOM 环境）：`attach` 注入 audio 元素接口，收口播放、暂停、seek、音量、静音、循环、事件归一化、钳制与媒体错误码映射；事件监听与快捷键均不在此层；
  - `useMusicPlayerController` 是 React 绑定：挂载 / 卸载、事件订阅（`onStateChange` 同步快照）、把 `<audio>` 元素经 `fromHTMLMediaElement` 交给 engine；
  - 当前曲目自然结束且队列存在下一首时，回调运行时切换到下一首；
  - 快捷键统一归属共享层命令系统，`handleKeyDown` 只保留焦点在 shell 上且不与命令冲突的导航扩展点。

### 2.5 View Stage

- 文件：`src/components/MusicPlayerStage.tsx`
- 职责：
  - 只负责展示与事件绑定；
  - 不直接知道 Host 路由细节；
  - 组合封面区、时间轴、控制 dock、歌词区与反馈浮层。

### 2.6 Pure Utils

- 文件：
  - `src/utils/music-player.ts`
  - `src/utils/launch-resource.ts`
  - `src/utils/lyrics.ts`
  - `src/utils/lyrics-layout.ts`
  - `src/utils/color.ts`
  - `src/utils/audio-metadata.ts`
- 职责：
  - 保持纯函数；
  - 处理文件名、格式支持、启动参数归一、歌词解析、歌词布局计算、按钮取色、时间格式化与 MP3 / FLAC / MP4 / Ogg / Opus 元数据读取。

## 3. 依赖边界

项目只依赖：

1. React
2. `@chips/component-library` 的主题运行时壳层与 `ChipsIcon`
3. `chips-sdk`
4. 原生 HTML5 `<audio>`
5. 浏览器内建 `TextDecoder`、`Blob`、`URL.createObjectURL`

项目不依赖：

1. Electron 私有对象
2. Host 内部源码模块
3. 第三方音频播放器 npm 运行时
4. 第三方标签解析 npm 包
5. 应用侧私有 Bridge hook 主路径

## 4. 参考项目适配策略

本项目参考 `MusicPlayer-main` 的部分思路包括：

1. 左封面右歌词的双栏布局；
2. 轻量控制区与大号歌词视觉层级；
3. 同时处理音频、歌词、封面这组三元资源。

正式实现不直接导入参考仓库脚本，而是按薯片生态规范重写为：

1. `useMusicPlayerController(...)`
2. `MusicPlayerStage`
3. `parseLyricsText(...)`
4. `getLyricsLayoutPosition(...)`
5. `parseEmbeddedAudioMetadata(...)`

这样可以保证背景、歌词和主视觉仍贴近参考项目，但正式契约、多语言系统、Host 接线与资源处理链路全部服从薯片生态标准。
