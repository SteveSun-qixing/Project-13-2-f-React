# 播放会话与歌词交互控制设计

## 1. 控制器职责

实现位置：

- `src/engine/audio-engine.ts`（纯逻辑状态机，不含 React，可单测）
- `src/hooks/useMusicPlayerController.ts`（React 绑定）

分层约定：

- `audio-engine.ts` 通过 `attach(audio)` 注入 audio 元素接口，只依赖结构类型（`AudioElementLike`），不依赖 DOM 环境；所有播放 / 暂停 / seek / 音量 / 静音 / 循环动作与媒体事件归一化都收敛在这一层，并通过 `onStateChange` 推送不可变快照。
- `useMusicPlayerController` 只做挂载 / 卸载、事件订阅与状态暴露，事件处理器逐项转发给 engine；对外 `MusicPlayerController` 接口（surfaceRef / audioRef / 各状态字段与动作方法）保持不变。

控制器统一管理以下状态：

1. `isReady`
2. `isPlaying`
3. `isBuffering`
4. `isMuted`
5. `volume`
6. `duration`
7. `currentTime`
8. `bufferedUntil`
9. `loopMode`
10. `errorKey`

## 2. 状态来源

状态只来自两类输入：

1. 原生 `<audio>` 事件：
   - `loadedmetadata`
   - `canplay`
   - `playing`
   - `pause`
   - `waiting`
   - `ended`
   - `timeupdate`
   - `progress`
   - `volumechange`
   - `error`
2. 应用层传入的 `sessionKey`

## 3. 控制动作

控制器对外暴露：

1. `togglePlayback`
2. `seekBy`
3. `seekTo`
4. `setVolumeLevel`
5. `toggleMute`
6. `toggleLoopMode`
7. `handleKeyDown`

运行时队列与 Host 命令不直接写进控制器。控制器只处理当前 `<audio>` 元素；`AppRuntimeProvider` 负责队列推进，`useMusicPlayerCommands` 负责把 Host command invocation 映射到控制器动作。

## 4. 快捷键模型

快捷键唯一归属共享层命令系统，避免多重触发：

1. 空格（播放 / 暂停）、左右方向键（前后 10 秒）、上下方向键（音量加减）、`M`（静音切换）、`L`（单曲循环切换）全部由 `music-player-commands.tsx` 注册到 `@chips/ui` CommandRegistry，经 `AppChrome` 的 `useCommandShortcuts` 在 window 层统一分发；
2. 播放器 shell 的 `handleKeyDown` 不再处理与命令系统重叠的按键，只保留"焦点在 shell 上且不与命令冲突"的键盘导航扩展点（当前无冲突键；Tab 焦点管理依赖浏览器原生行为）；
3. 焦点在按钮上按空格 / 方向键只触发一次动作：按钮原生 click 生效，命令系统排除按钮目标，shell 不再拦截；
4. 命令系统同时服务菜单、工具栏、命令面板与宿主快捷键，所有动作共享同一份 command metadata。

补充限制（依赖共享层 `useCommandShortcuts` 的排除项）：

1. 当焦点在 `input/textarea/select` 或 `contenteditable` 目标上时不抢快捷键；
2. 排除 `button` / `[role="button"]` 目标，避免与按钮原生行为叠加；
3. 中文输入法组合中（`event.isComposing`）不触发快捷键。

## 5. 音量与静音语义

`setVolumeLevel(0)` 视为静音：

1. 同步置 `audio.muted = true`、`isMuted = true`；
2. 记录静音前的非零音量用于恢复（`previousVolume` 始终保持非零）；
3. 从 0 拖离（`setVolumeLevel(v)`，`v > 0`）自动取消静音并更新恢复音量；
4. `toggleMute` 静音时保存当前非零音量，取消静音时恢复到保存值，无保存值时回退默认音量。

音量、静音、循环偏好的变更只作用于 audio 元素与会话偏好，不重置播放进度与播放状态；只有 `sessionKey` 变化才触发会话重置。

## 6. 歌词高亮模型

实现位置：

- `src/utils/lyrics.ts`
- `src/utils/lyrics-layout.ts`
- `src/components/MusicPlayerStage.tsx`

当前策略：

1. 歌词来源优先级固定为：`伴生歌词文件 > 嵌入时间轴歌词 > 嵌入纯文本歌词 > 空态`
2. 先把 LRC 解析成 `{ timeMs, text }[]`
3. 播放时基于当前 `currentTime * 1000` 二分查找当前高亮索引
4. 视图层按参考项目 `GetLyricsLayout / UpdateLyricsLayout` 的同构逻辑，基于真实行高和 `viewportHeight / 3.5` 计算每一行位移
5. 当前激活行不再整句直接跳白，而是根据“当前句开始时间 -> 下一句开始时间”的区间计算亮色遮罩进度；
6. 已播过的句子保持完整亮色遮罩，当前句按播放进度渐进填充，未播句保持暗态；
7. 相邻歌词仍按与高亮行的距离叠加 `blur(...)`，保留参考项目的空间层次
8. 亮色遮罩不再只依赖 `<audio>` 的 `timeupdate` 频率，而是播放时直接读取 `audio.currentTime` 做帧级更新，暂停 / 拖动时再做一次静态校准；
9. 逐行位移更新使用分段延迟，保留参考项目的滚动节奏
10. 歌词容器尺寸变化时通过 `ResizeObserver` 触发布局重算，避免右侧区域展开动画或窗口尺寸变化后歌词堆叠错位

若当前歌词不是时间轴歌词，则切换为静态文本模式，不做自动滚动。

## 7. 会话切换

当 `sessionKey` 变化时，控制器会：

1. 停止当前播放；
2. 重置进度、缓冲、错误与就绪状态；
3. 保留当前音量与循环偏好；
4. 等待新的 `<audio>` 元素建立元数据与播放状态。

这样可以保证切歌时不会把上一首的瞬时状态带进下一首。

## 8. 播放队列

实现位置：

- `src/app/AppRuntimeProvider.tsx`
- `src/utils/music-player.ts`

规则：

1. 手动选择或拖放多首音频时，`resolveFileSelection(...)` 会保留 `audioPaths` 队列，同时继续输出 `audioPath` 作为首曲兼容字段。
2. 单曲打开、文件关联打开和音乐基础卡片打开都被归一为队列长度为 1 的播放会话。
3. 上一首 / 下一首只移动当前队列索引，不重新解释 Host 启动上下文。
4. 当前曲目自然结束且不是单曲循环时，如果队列中存在下一首，则自动切换下一首。
5. 队列只表达当前打开批次，不承担媒体库、随机播放或持久播放列表。
