# 运行联调与质量门禁

## 1. 本地联调步骤

### 1.1 前置

- 社区服务器本地运行中：API `http://127.0.0.1:3000`、Worker、PostgreSQL、Redis（6380）、MinIO（9000）；
- 开发工作区 `.chips-host-dev` 已安装并启用：
  - `chips.module.chips.community-uploader`（社区卡片传输模块）
  - `com.chips.card-viewer`（本地卡片查看器）
  - `com.chips.community-client`（本客户端）

### 1.2 开发工作区预置服务器地址

开发工作区 Host `config.json`（user scope）预置了社区服务器地址，客户端启动时自动读取，无需手动配置：

```json
{
  "community.server.baseUrl": "http://127.0.0.1:3000"
}
```

- 客户端 `loadCommunityServerUrl` 通过 `client.config.get("community.server.baseUrl")`（无 scope）读取，Host 按 user → workspace → system → defaults 顺序解析；
- 预置地址可覆盖代码默认值（`https://www.chipscard.space`），生产环境由发布配置决定；
- 在客户端设置页修改地址后，会写回该配置并立即切换 API 指向。

### 1.3 启动客户端

```bash
cd Chips-CommunityClient
npm install        # 首次
npm run build      # 生成 dist/
npm run package    # 生成 .cpk（开发工作区安装清单引用该产物）
chipsdev-r run       # 拉起真实 Host 并打开客户端窗口
```

修改代码后重新执行 `npm run build`、`chipsdev-r package`、`chipsdev-r plugin install`，再重启 `chipsdev-r run` 生效。

### 1.4 功能验证

| 功能 | 操作 | 预期 |
| --- | --- | --- |
| 浏览 | 欢迎页 → 注册 / 登录 | 注册后跳转个人主页 |
| 个人主页 | 浏览作品网格、管理作品 | 删除确认弹窗可用 |
| 卡片查看 | 点击卡片 → 卡片详情 → 「在本地查看器中打开」 | 传输模块下载网络资源卡片并拉起本地卡片查看器窗口渲染 |
| 完整下载 | 卡片详情 → 「下载完整卡片」 | 保存对话框 → 完整 `.card` 写入目标路径 |
| 上传 | 工作区 → 「选择 .card 文件并上传」 | 进度推进 → 上传完成 → 可打开卡片页面 |
| 设置 | 修改服务器地址 / 退出登录 | 生效并持久化 |

## 2. 正式质量脚本

| 命令 | 内容 |
| --- | --- |
| `npm run lint` | 源码规范检查 |
| `npm run typecheck` | `tsc -p tsconfig.json --noEmit` |
| `npm test` | Vitest 单元测试（应用基线、命令契约、传输服务、服务器配置、预览 smoke） |
| `npm run build` | 正式构建 → `dist/` |
| `npm run validate` | manifest / runtime.targets / ui.surface / 入口资产校验 |
| `npm run preview:smoke` | `chipsdev-r preview --mode mock` + 报告校验 |
| `npm run quality:gate` | 汇总 SDK / 组件库 / 主题质量报告 |
| `npm run verify` | 上述全部串联的总门禁 |

## 3. 已知注意事项

- `cardFileId` 数据库列为 `varchar(10)`，传输模块读取 `.card` 的 10 位卡片文件 ID，属合法值；手工构造超长值会在 complete 阶段报 500；
- 下载会话 `versionId` 传 `null` 会被契约校验拒绝；客户端 SDK 输入为可选字符串，不传即可；
- 生产域名当前不可达时，上传 / 下载 / 本地查看均不可用（会话创建依赖 API），需先配置可达的服务器地址。
