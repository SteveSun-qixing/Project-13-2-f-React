# Chips-Office 移植架构说明

> 任务：task041 Office 四件套移植
> 性质：应用插件工程内部技术文档
> 上游：GenOffice（Apache-2.0）

## 1. 移植原则

用户明确的移植原则：**完美移植、功能零缺失、尽可能只做架构适配，不重新开发、不重构**。

据此，GenOffice 三层代码的移植策略：

| 层 | GenOffice 侧 | 移植方式 |
| --- | --- | --- |
| 渲染层 | 四应用 `src/renderer/**`（纯浏览器 React，零 Node 依赖） | **原样搬运**至 `src/apps/{word,sheet,slide,pdf}/renderer/`，仅剥离 AI |
| 引擎层 | `packages/*`（零构建 TS 源码包，exports 直指 src） | **原样搬运**至 `vendor/`，以 vite alias + tsconfig paths 保持 `@genoffice/*` 包名导入不变 |
| 主进程层 | `src/main` + `src/preload`（Electron 文件 IO、对话框、AI、sidecar spawn） | **不搬运**；职责重定位到薯片正式链路（见 §3） |

## 2. 桥接适配层（src/bridge/）

GenOffice renderer 与主进程的全部通信集中在四个 preload 桥接口；移植时在插件内实现**同签名**的桥对象，底层改走 chips-sdk：

| 桥对象 | 契约来源（已随应用搬运） | 消费方 |
| --- | --- | --- |
| `window.desktop` | `src/apps/word/shared/ipc.ts` 的 `DesktopApi` | Word renderer |
| `window.desktopApi` | `src/apps/sheet/shared/desktop-api.ts` | Sheet renderer |
| `window.slidesApi` | `src/apps/slide/shared/ipc.ts` | Slide renderer |
| `window.pdfApi` | `src/apps/pdf/shared/ipc.ts` | PDF renderer |

安装时机：各场景模块装载时同步安装（`installXxxBridge(chipsClient)`），保证先于应用 App 首次渲染。

共享设施：

- `src/bridge/document-session.ts`：`file.session.*` 链路封装（open/create/read/write/persist/close + 错误归一化），四桥共用；
- `src/bridge/new-document.ts`：新建文档工厂（buildBlankDocx / createBlankPptx / pdf-lib 空白 PDF → `file.session.create` 立即落盘；表格新建走 Univer 内存工作簿、首次保存时建会话——GenOffice 原生流程）；
- `src/bridge/launch-target.ts`：启动目标解析（与万能文件查看器同口径：`resourceOpen.filePath ?? targetPath ?? resourceId`）。

## 3. 主进程职责重定位矩阵

| GenOffice 主进程职责 | 薯片去向 |
| --- | --- |
| 文件打开/保存/另存为/原子写 | `client.file.session.*`（Host file-session 服务） |
| xlsx sidecar（calamine+ironcalc） | Host `office.engine.*` 服务（spawn 原生二进制，JSON 行协议转发） |
| OOXML 保存计划（sheets gateway 纯 JS） | 插件内原样运行（`src/apps/sheet/gateway/`）；临时目录物化与 zip 重组由 `office.engine.saveArchive` 在 Host 完成 |
| 系统 open/save 对话框 | `client.platform.openFile / saveFile` |
| 资源打开（Finder/Explorer 拖入等价） | `launchParams.resourceOpen`（Host resource-open-service 路由） |
| 加密 docx 解密（officecrypto-tool） | Host `office.crypto.decrypt` 路由（Node 域加密能力；桥负责加密容器检测与密码 UI 流程） |
| PDF 导出/打印（pdf-lib） | 插件内 pdf-lib（浏览器可运行）+ 浏览器打印链路 |
| 系统字体度量（font-metrics，Node fs） | 浏览器不可行；vendor/font-metrics 仅保留类型，桥用 `document.fonts` + canvas 度量近似，缺失时走 renderer 原生启发式 fallback（GenOffice 契约内的正式路径）；Node 实现保留在 `vendor/font-metrics/src/node/` 供 Host 未来复用 |
| harfbuzzjs shaping | renderer 内直接运行（harfbuzzjs 本身是 wasm） |
| 崩溃恢复副本 | `client.window.setTypedData`（按桥的实现为准，见各桥说明） |
| 最近文件 / 应用设置 | `client.config` 域 |
| 菜单栏命令 | 薯片命令系统（AppChrome 命令面板 Mod+P） |
| AI（agent-core/ai-provider/ai-search/file-parse/project-store） | 全部移除 |
| Markdown 应用 / Electron shell / 更新器 | 不属于插件范围（shell 职责由 Host 承担） |
| 系统 OCR（pdf 扫描件识别） | OS 级能力，本轮不移植（见 §6 能力边界） |

## 4. 构建与别名

- `vite.config.ts`：`@genoffice/<pkg>`（含子路径）alias 到 `vendor/<pkg>/src/`；pdfjs 的 cmaps/standard_fonts/wasm 经 vite-plugin-static-copy 拷至 `dist/pdfjs/`；manualChunks 按 Univer/pdf/slides/tiptap/xml 分包；worker format es。
- `package.json` 的 build 脚本为 `vite build`（chipsdev-r build 检测到非递归 build 脚本时委托执行，属 CLI 正式机制）。
- `tsconfig.json`：paths 与 vite alias 一致；`vendor/` 纳入编译；`vendor/font-metrics/src/node`、`vendor/pdf2docx/src/ocr-vision.ts` 等 Node-only 文件排除。

## 5. 引擎包浏览器安全分层

| 包 | 处理 |
| --- | --- |
| docx-engine | 整包浏览器安全，原样 |
| pptx-engine | 原样（入口 index.ts 引用的 zip.ts/sections.ts/media-insert.ts 含 node:crypto/zlib——renderer 打包经由 pptx-render 只依赖其安全子路径；若构建产物出现 node: 外部化告警，需按此线索收口） |
| pptx-render | 整包浏览器安全，原样 |
| ui | 删除 AiComposer/AiTypingIndicator，其余原样 |
| i18n | 原样；默认 locale 固定 zh（薯片文案规范为简体中文直写；移植代码内建 i18n 非.Host 级多语言系统） |
| pdf2docx | 纯计算主体原样；`ocr-vision.ts`（Node OCR）排除；`src/rebuild` 对 font-metrics Node 函数的引用由浏览器 shim 承接（见 src/bridge/pdf/） |
| font-metrics | 类型层 `src/types.ts` + Node 实现 `src/node/`（不参与浏览器编译） |

## 6. 能力边界（如实声明）

1. **OCR**：GenOffice 的扫描 PDF 文字识别依赖 OS 级 OCR 二进制（pdf2docx/ocr-vision.ts），浏览器与当前 Host 均不可用，本轮不移植；
2. **字体度量精度**：桥接层的浏览器度量（canvas/FontFace）与原生 sfnt 解析存在精度差异；GenOffice 的 fallback 契约保证缺省时可用；
3. **主题**：编辑器内容区保持 GenOffice 自身 token（light）；插件壳层走 @chips/ui appleTheme；不实现暗色切换（薯片主题系统已随 task030 废弃）；
4. **多语言**：renderer 内建 i18n 机制保留，界面 locale 固定 zh；
5. **web/mobile target**：Host 当前未支持，manifest 如实声明 desktop-only。
