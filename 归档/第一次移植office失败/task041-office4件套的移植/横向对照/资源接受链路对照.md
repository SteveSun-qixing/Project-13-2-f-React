# 横向对照 — 资源接受链路（5 个应用）

> 调查时间：2026-09-03
> 调查范围：Chips-PhotoViewer / Chips-VideoPlayer / Chips-BookReader / Chips-Word / Chips-Slide / Chips-Sheet / Chips-PDF
> 调查方式：只读静态分析（grep + 文件读取）

## 1. 资源接受入口对照

| 应用 | 资源接受主入口 | 优先级解析链 | 备注 |
|---|---|---|---|
| Chips-PhotoViewer | `src/utils/launch-resource.ts` `resolveLaunchImageTarget` | `resourceOpen.filePath` > `targetPath` > `resourceOpen.resourceId` | 单张图 |
| Chips-VideoPlayer | `src/utils/launch-resource.ts` `resolveLaunchVideoTarget` | `resourceOpen.filePath` > `targetPath` > `resourceOpen.resourceId` | 视频 |
| Chips-BookReader | `src/utils/launch-resource.ts` `resolveLaunchBookTarget` | `resourceOpen.filePath` > `targetPath` > `resourceOpen.resourceId` | 电子书 |
| Chips-Word | `src/utils/launch-resource.ts` `resolveLaunchDocumentTarget` | `resourceOpen.filePath` > `targetPath` > `resourceOpen.resourceId` | office 会话 |
| Chips-Slide | `src/utils/launch-resource.ts` `resolveLaunchFileTarget` | `resourceOpen.filePath` > `targetPath` > `resourceOpen.resourceId` | 命名略泛（应改为 `resolveLaunchSlideTarget`） |
| Chips-Sheet | `src/utils/launch-resource.ts` `resolveLaunchSpreadsheetTarget` | `resourceOpen.filePath` > `targetPath` > `resourceOpen.resourceId` | office 会话 |
| Chips-PDF | `src/utils/launch-resource.ts` `resolveLaunchPdfTarget` | `resourceOpen.filePath` > `targetPath` > `resourceOpen.resourceId` > HTTP URL > 拖放 | office 会话，5 层嵌套 payload |

**所有应用解析优先级一致**（除 PDF 增加 HTTP/拖放回退）。

## 2. 远程 URL 加载链路

| 应用 | 远程 URL 处理 | 是否走 office 会话 |
|---|---|---|
| Photo/Video/Book | `client.resource.readBinary` + HTTP fallback | 不适用 |
| Word/Sheet | `client.resource.readBinary` 读字节 → 转 ArrayBuffer → 注入 office 会话 | ✅ 是 |
| Slide | `client.resource.readBinary` → office.create 或 office.open | ✅ 是 |
| PDF | `client.resource.readBinary` + `fetch` fallback；远程 PDF **不走** office 会话 | 仅本地 PDF 是 |

**关键差异**：PDF 在远程场景下没有 office 会话，保存走下载；其他 office 三件套都建立 office 会话。

## 4. MIME 归一化

| 应用 | 实现位置 | 范围 |
|---|---|---|
| Photo/Video/Book | SDK 层（`@chips/sdk` 内部） | 全部图片/视频/电子书 |
| Word/Sheet | SDK 层 | `docm→docx`, `xlsx→xlsm→xlsx`, `pptm→pptx` |
| Slide | 当前**未在解析链路**归一 | 应由 Host 处理 |

**Slide 解析链路未做 MIME 归一**：是缺口，应在 `resolveLaunchFileTarget` 内部或 Host 端补齐。

## 6. 二进制字节处理统一语义

| 应用 | 字节流向 |
|---|---|
| Photo | `Uint8Array` → Blob → ObjectURL → `<img>` |
| Video | `Uint8Array` → Blob → ObjectURL → `<video>` |
| Book | `Uint8Array` → 解压 EPUB/PDF |
| Word/Sheet | `Uint8Array` → ArrayBuffer → office 会话 |
| Slide | `Uint8Array` → ArrayBuffer → office 会话 |
| PDF | `Uint8Array` → ArrayBuffer → pdf.js |

**差异点**：图片/视频/电子书走 Blob + ObjectURL；office 三件套走 ArrayBuffer 直接进入会话；PDF 走 ArrayBuffer 进入 pdf.js 引擎。

## 7. 会话管理

| 应用 | 会话策略 |
|---|---|
| Photo/Video/Book | 无会话，单文件 |
| Word/Sheet | `officeSessionIdRef` 复用/替换旧 session |
| Slide | `officeSessionIdRef` 复用/替换旧 session |
| PDF（仅本地） | `PdfRuntimeProvider` 内建立 office 会话，unmount 关闭 |

**所有 office 三件套一致**：`officeSessionIdRef` 机制 + unmount 时关闭会话。

## 10. 主要差距与建议

### A. 二进制语义缺失
当前《14-办公文档会话协议》未明确 `Uint8Array` 与 `ArrayBuffer` 的边界：
- 何时用 `Uint8Array`（从 `resource.readBinary` 拿到）
- 何时转 `ArrayBuffer`（office 会话入口）
- 何时转 Blob（图片/视频/电子书入口）

**建议**：在《14-办公文档会话协议》中补充 `binary` 语义章节，统一 7 个应用的口径。

### B. MIME 归一缺口
Slide 解析链路未做 MIME 归一。

**建议**：在 `resolveLaunchFileTarget` 内部统一处理 `pptm→pptx`；或在 Host 层补齐（推荐后者）。

### C. 路径清理缺失
7 个应用均未做路径清理。

**建议**：在 SDK 层（`@chips/sdk` 的 `resource.open` 内部）统一过滤非法字符。

### D. file.detectType 缺口
SDK 的 `file.detectType` 协议：
- ✅ 支持零字节 PDF（返回 `application/pdf`）
- ❌ 零字节 docx/xlsx/pptx 失败
- ❌ 未知 MIME 返回 null

**建议**：在问题工单登记 file.detectType 缺口。

### E. 远程 PDF 保存预期
远程 URL 加载的 PDF 不进入 office 会话，保存走下载。需要产品确认该行为是否符合预期。

## 12. 结论

7 个应用的资源接受链路**架构一致、命令系统一致、错误兜底一致、会话管理一致**，主要差距是：
1. 二进制语义未文档化（需补充《14-办公文档会话协议》）
2. Slide MIME 归一缺口（小问题）
3. file.detectType 缺口（需登记工单）
4. 路径清理未实现（需在 SDK 层统一）

无阻断性架构问题，可进入修复阶段。
