# Chips-PDF 技术方案

> 插件 ID：`com.chips.pdf` · 版本：0.1.0

## 一、架构总览

Chips-PDF 遵循薯片生态应用插件规范：Host 是唯一运行时承载，插件所有系统能力
（文件、平台对话框、资源、命令、外链）只通过 `chips-sdk` / `window.chips.*` 正式链路消费。

```text
┌────────────────────────────────────────────────────────────┐
│ index.html（CSP：worker-src 'self' blob: 等）               │
│ ┌────────────────────────────────────────────────────────┐ │
│ │ AppRoot                                                │ │
│ │  ConfigProvider(zhCN, appleTheme)                      │ │
│ │   └ AntdApp ─ ChipsProvider(chipsClient)               │ │
│ │      └ CommandProvider                                 │ │
│ │         └ AppRuntimeProvider（场景/启动环境/诊断）       │ │
│ │            └ PdfRuntimeProvider（文档生命周期/字节/保存）│ │
│ │               └ AppShell                               │ │
│ │                  ├ StartScene（起始页：拖放/打开）       │ │
│ │                  ├ DocumentScene（工具栏+侧栏+滚动视图） │ │
│ │                  └ PasswordDialog（加密文档）           │ │
│ └────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────┘
```

- **Provider 顺序固定**：`ConfigProvider(zhCN, appleTheme)` > `AntdApp` > `ChipsProvider(chipsClient)` > `CommandProvider` > `AppRuntimeProvider` > `PdfRuntimeProvider` > `AppShell`。
- **场景注册表**（`src/app/scene-registry.ts`）：`start`（起始页）与 `document`（查看/批注）两个场景；启动处理只解析一次 launchParams（ref 哨兵），打开目标成功后切换到 `document`，取消/关闭回到 `start`。

## 三、pdf.js 资源与 Worker

### Worker

```ts
import workerUrl from "pdfjs-dist/build/pdf.worker.min.mjs?url";
GlobalWorkerOptions.workerSrc = workerUrl;
```

Vite 将 `?url` 解析为产物内 worker 文件地址（`dist/assets/pdf.worker.min-*.mjs`），
配合 index.html 的 `worker-src 'self' blob:` 生效。

### 静态资源（cmaps / standard_fonts）

CJK PDF 依赖 cmaps，未嵌入字体的 PDF 依赖 standard_fonts。处理链路：

1. `prebuild` 执行 `scripts/copy-pdfjs-assets.mjs`：将
   `node_modules/pdfjs-dist/cmaps` → `public/pdfjs/cmaps`、
   `node_modules/pdfjs-dist/standard_fonts` → `public/pdfjs/standard_fonts`。
2. Vite 构建按默认 publicDir 原样输出到 `dist/pdfjs/`（验收硬指标：构建后
   `ls dist/pdfjs/cmaps` 必须非空，e2e 静态测试在 dist 存在时自动断言）。
3. `getDocument` 统一携带参数（`src/pdf/pdfjs.ts` 的 `DOC_OPTIONS`）：

```ts
getDocument({ data, password?, ...DOC_OPTIONS })
// DOC_OPTIONS = {
//   cMapUrl: `${PDFJS_ASSET_BASE}cmaps/`,   // 基于 document.baseURI
//   cMapPacked: true,
//   standardFontDataUrl: `${PDFJS_ASSET_BASE}standard_fonts/`,
// }
```

### build 选型决策

GenOffice 原版在 Electron 渲染进程使用 legacy build 属于其打包特有原因；
Chips-PDF 为浏览器/宿主 webview 环境，采用 pdf.js 标准 build（`pdfjs-dist`
默认入口）。标准 build 在当前目标环境（Chromium webview）无已知兼容问题；
若未来出现宿主兼容性问题，再评估切换 legacy build 并在此记录决策。

## 四、文档生命周期（PdfRuntimeProvider）

```text
openTarget(target)
  ├─ 读字节：readPdfBytes（file.read binary / resource.readBinary；无 Host 的 HTTP 预览才 fetch）
  ├─ getDocument({ data, ...DOC_OPTIONS })
  │    └─ PasswordException → status="password" → PasswordDialog → submitPassword 重试
  ├─ 逐页读取 viewport 尺寸与 /Rotate → sizes/baseRots
  ├─ buildFormCatalog（AcroForm 控件目录）
  ├─ getOutline（书签树）
  └─ status="ready" → DocumentScene
```

- 加载令牌（`loadTokenRef`）保证并发打开时旧任务作废，`loadingTask.destroy()` 释放。
- 保存链路见下节；保存成功后 `reload()` 重新解析文档，批注状态清零。
- web 宿主（`hostKind === "web"`）跳过保存路径对话框，直接通过 `<a download>` 下载；下载不会把当前资源目标改写为无效路径。

## 五、批注保存链路（pdf-lib）

`use-document-viewer.buildSaveRequest()` 汇总会话内编辑 → `SavePdfRequest`
（`markups / drawings / noteEdits / formValues / stamps / rotations / deletedPages`）→
`save-pdf.ts: applySaveRequest(bytes, request)`：

1. **表单值**：pdf-lib Form API（TextField/RadioGroup/CheckBox/Dropdown·OptionList）。
   外观生成失败（WinAnsi 外字符）时降级设置 `/NeedAppearances` 并跳过外观重建。
2. **页面旋转**：先应用旋转增量（`/Rotate` 90 的倍数），使标记外观按最终朝向绘制。
3. **文本标记**：构造 `/AP /N` 外观流——高亮以 Multiply 混合 ExtGState 模拟荧光笔，
   下划线/删除线沿视觉底边画线（兼容 90/270 旋转）。
4. **绘图批注**：Ink（InkList + 路径外观流）、Square/Circle（四段贝塞尔近似椭圆）、
   Line/Arrow（含箭头线段）；便签为标准 Text 批注，含 Contents/T/CreationDate/M，
   回复走 `/IRT + RT=R`（`replyToLocalId` 先映射本会话新便签，`replyToSaved`
   按矩形 + 内容定位文件中已有便签，对象号仅消歧）。
5. **便签改写**：按（对象号 + 矩形顶点 + 旧内容）匹配已有 Text 批注后替换 Contents；
   未匹配静默跳过（与原版一致）。
6. **印章**：`embedPng` 后按 PDF 坐标绘制（水印整页、页眉页脚条）。
7. **删除页**：最后降序执行 `removePage`，保证其余操作始终使用原始页下标。

产出 `Uint8Array`；桌面本地 PDF 经 `client.office.write(sessionId, bytes)` + `client.office.persist(sessionId, path)` 持久化；无会话或 web 宿主才回退 `client.file.write` / 浏览器下载
写回原路径，「另存为」先 `client.platform.saveFile` 选路径，写入成功后当前目标切换为新文件；Web
宿主统一走下载回退，不调用文件写入或路径选择接口。

坐标约定：批注数据一律存 PDF 用户空间（y 向上、未缩放），显示层由 `geometry.ts`
按页面旋转映射到视图坐标并乘以缩放，因此批注随缩放/旋转保持稳定。

## 六、视觉与文案规范落点

- 主题：`@chips/ui` `appleTheme`；自写 TSX 禁止硬编码颜色与内联 `style={{}}`。
- 动态几何（页面盒、标记矩形、印章预览、定位钉等）通过 `geometry-style.ts`
  写入 CSS 自定义属性，规则统一在 `src/styles/pdf-viewer.css` 与 `src/app/app-shell.css`
  消费；颜色变量取生态苹果色固定值（#0a84ff / #f5f5f7 / #1d1d1f / #6e6e73 / #86868b / #ffffff）。
- 界面文案：`src/lib/messages.ts` 集中维护，`formatMessage(key, params)` 做简体中文
  插值；不引入 i18n 框架。
- 图标：`@ant-design/icons`；不使用 emoji。

## 七、命令系统

- `src/commands/app-commands.tsx`：
  - `pdfCommandDefinitions`：可序列化 `CommandDefinitionInput`（scope=app、
    menuPlacement 文件/视图/批注、paletteKeywords），经 `client.command.register`
    提交宿主；
  - `createPdfCommands(bridge)`：本地 `CommandItem[]`（中文标题、快捷键、分组），
    经 `useCommandRegistry().register` 驱动菜单/工具栏/快捷键/命令面板。
- `viewer-bridge.tsx`：`PdfViewerBridge` 由 DocumentScene 挂载时写入，命令与宿主
  `command.invoked` 转发统一经桥调用；文档未打开时安全降级。

- `tests/unit/commands.test.ts`：命令定义契约（可序列化、scope、必配命令）、CommandItem 中文标题与快捷键、桥转发、mock host 注册/调用。
- `tests/unit/app.test.tsx`（jsdom）：App 完整渲染 + 起始页中文文案 + 场景注册表 + 文案插值。
- `tests/e2e/basic-flow.test.ts`（jsdom）：静态断言——无 AI/OCR 引用、无 node: 导入、无内联 style、无模板残留、manifest/index.html/依赖版本合规、dist 存在时断言 pdfjs 资源。
- `tests/setup.ts`：ResizeObserver / IntersectionObserver / matchMedia mock；jsdom 下补齐 pdf.js 模块顶层的 DOMMatrix / Path2D；为真实 `chipsClient` 安装测试宿主桥（`chips-sdk/testing`），使其以插件环境工作。
