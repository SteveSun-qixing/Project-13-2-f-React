## 2. 来自 GenOffice 的清单

### 2.1 vendor 引擎（TS 源码整体引入）

- `vendor/docx-engine/`：docx 解析（带 docxIndex 锚点的块树）、OOXML 片段生成、段落补丁保存；`exports` 指向 `src/index.ts`。
- `vendor/pptx-engine/`：被 docx-engine 以子路径 `@genoffice/pptx-engine/custgeom` 引用（自定义几何解析），随 `file:` 依赖打包。

### 2.2 编辑器核心（apps/docs/src/renderer → src/editor/ 等）

| 模块 | 说明 |

### 2.3 界面层

GenOffice 的 React 界面（App、组件、ribbon 等）**未**移植；Chips-Word 界面为 antd 6 + `@chips/ui` 全新实现，仅复用其编辑器核心与引擎。

## 3. Node → 浏览器替换清单

| 位置 | Node 实现 | 浏览器实现 |
| --- | --- | --- |
| pptx-engine `src/zip.ts` | `node:crypto` `createHash().update().digest("hex")` | WebCrypto `crypto.subtle.digest("SHA-256", …)`（异步化，调用方已适配） |
| pptx-engine `src/sections.ts` | `node:crypto` `randomUUID()` | 标准 Web API `crypto.randomUUID()` |
| pptx-engine `src/media-insert.ts` | `node:zlib` `deflateSync` | `fflate` `deflateSync`（纯 JS） |
| Electron 主进程保存/打开 IPC（`window.desktop`） | `ipcRenderer` 对话框与文件写入 | 薯片生态链路：`platform.openFile` / `platform.saveFile` + `client.office.open/read/write/persist`（web 宿主降级 `<a download>`） |
| docs 渲染进程 i18n（`@genoffice/i18n`） | 键值翻译 | `src/lib/messages.ts` 中文直写文案表 + `formatMessage` 插值 |
| docx-engine | 无 `node:` 导入（依赖 `crypto.subtle`、`DecompressionStream`、`TextDecoder` 等浏览器标准 API） | — |

工程层面替换：

- vendor 两个包的 `tsconfig.json` 去除对 GenOffice 仓库 `tsconfig.base.json` 的 extends，改为自包含配置。
- `package.json` 以 `file:vendor/docx-engine`、`file:vendor/pptx-engine` 引入，exports 直接指向 TS 源码，由 vite 统一打包。

## 4. 剔除项（不移植）

| 剔除内容 | 原因 |
| --- | --- |
| `renderer/ai/` 整目录、AiAskPopover、ai-queue-anchors | AI 能力不属于本应用；相关纯函数已提取为无 AI 语义的 `src/editor/doc-ops.ts` |
| `@genoffice/agent-core`、`@genoffice/ai-provider`、`@genoffice/i18n` 依赖 | 生态规范：禁止 AI 相关代码与文案；文案走 MESSAGES 表 |
| Electron `window.desktop` IPC 链路 | 纯浏览器实现，系统能力只经 `chips-sdk` |
| 预览导出（pagination-preview/pv-*）UI | 浏览器端以打印替代导出；对应打印死规则已剔除 |

`tests/e2e/basic-flow.test.tsx` 以静态断言长期守护以上边界：src 中无 AI 语义引用、无 `node:` 导入、无内联样式、无 `{{` 模板占位残留。
