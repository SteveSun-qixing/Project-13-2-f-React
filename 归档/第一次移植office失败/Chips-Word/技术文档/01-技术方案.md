# Chips-Word 技术方案

> 插件 ID：`com.chips.word`　基于 GenOffice Docs（Apache-2.0）二次开发

## 1. 架构总览（文字版）

```
┌──────────────────────────────────────────────────────────────────┐

└──────────────┬───────────────────────────────────────────────────┘
               │
┌──────────────▼───────────────────────────────────────────────────┐
│ vendor 引擎（GenOffice TS 源码，Node → 浏览器已适配）                │

```

分层约束：

- 插件只经 `chips-sdk`（`window.chips.*`）访问系统能力，无任何宿主进程 IPC（GenOffice 原版的 Electron `window.desktop` 链路全部剔除）。
- 视觉统一走 antd 6 + `@chips/ui`（appleTheme），TSX 无内联样式、无硬编码色值；界面文案集中在 `src/lib/messages.ts` 的 `MESSAGES` 表，`formatMessage(key, params)` 做 `{param}` 插值。
- 场景注册表 `src/app/scene-registry.ts` 定义 `start` 与 `document` 两场景；实际场景由运行时状态推导（持有文档或存在加载错误 → document）。

## 3. 打开链路

1. **启动目标解析（只一次）**：`AppRuntimeProvider` 挂载后以 `hasResolvedLaunchContextRef` 哨兵保证每次启动只解析一次 `client.platform.getLaunchContext()`。
2. **目标优先级**（`src/utils/launch-resource.ts` 的 `resolveLaunchDocumentTarget`）：
   `resourceOpen.filePath` → `launchParams.targetPath`（兼容回退）→ `resourceOpen.resourceId`。
   无可用目标返回 `null`，应用停留起始页。
3. **字节读取三通道**（`readDocumentBytes`）：
   - 目标是本地路径（含 `file://`）→ `client.office.open({ filePath, format: "docx" })` + `client.office.read(sessionId)`；
   - http(s) URL → `fetch`（带 docx Accept 头）；
   - 其余 → `client.resource.readBinary(sourceId)`。
   返回值统一经 `src/lib/binary.ts` 的 `unwrapBinaryPayload` + `normalizeBinaryContent` 解包（兼容 Uint8Array / ArrayBuffer / base64 / `{data}` / `{content}` 包装与 Buffer JSON 形状）。
4. **解析**：`parseDocxBytes` 先做 OLE 魔数检测（口令加密 docx 不是 zip），随后 `parseDocx` 得到块树与 docxIndex 锚点；`blocksToPmDoc` 组装 ProseMirror 文档，`docStyleCss` 生成文档级 CSS，`readSections`/`readSectionSettings` 提供分节几何。
5. **装载**：编辑器未就绪时载荷进入 pending 队列，`registerEditor` 时消费；装载前 `primeEditorForParsed` 预置字距表、列表编号样式与版式；装载后丢弃撤销栈（跨文档历史隔离）。

对话框打开（`platform.openFile`，filters `[{ name: "Word 文档", extensions: ["docx"] }]`）与拖放打开（`platform.getPathForFile` → `(file as File & { path?: string }).path` 兜底）最终汇入同一条 `openTarget` 链路。`openTarget` 为每次读取/解析分配递增序列号；连续打开或拖放触发并发请求时，只有最后一次请求可以提交文档状态，关闭文档也会使未完成请求失效，避免旧文档异步覆盖新文档。

## 4. 保存链路（字节保真补丁原理）

docx 是 zip 容器；GenOffice 引擎在解析时为每个块记录 `docxIndex` 与原始 XML 片段。保存时不重排整个 `word/document.xml`，而是：

1. `editor.getJSON()` → `pmDocToSavePlan`（`src/editor/convert.ts`）：与原块树逐块对比，内容未变的块输出 `{ kind: "original" }`（直接复用原字节片段），被编辑的块才重新生成 OOXML 片段（`{ kind: "generated" }`）。
2. 图表数据编辑另行通过 `patchChartPartXml` + `patchChartWorkbookXlsxBase64` 打补丁到对应 chart part 与内嵌 xlsx，经 `partXml`/`partBinary` 传入。
3. `saveDocx(parsed, plan.saveBlocks, options)`：重组 `word/document.xml` 中被改写部分的字节，zip 其余成员按原字节保留，产出新 `.docx` 字节。
4. **落盘**：desktop 宿主优先使用 `client.office.write(sessionId, bytes)` + `client.office.persist(sessionId, path)`；另存为先走 `platform.saveFile` 对话框；web 宿主（`platform.getInfo().hostKind === "web"`）——Blob + `<a download>` 浏览器下载（manifest `capabilityFallbacks.save-file: download`）。新建先由 `buildBlankDocx` 生成完整模板，再调用 `client.office.create` 写入工作区 `documents/`。
5. **重锚定**：保存产物重新 `parseDocx`，使 docxIndex 指向新字节；新内容与编辑器现状 `doc.eq` 相等时跳过 `setContent` 重写，撤销栈/光标/滚动位置全部保留（GenOffice save-actions 既定做法）；不一致时才重写并重置历史。

「另存为」在无原路径（如 web 下载后的文档）时自动以首个 `docHeading` 派生默认文件名（`deriveAutoFileName`）。

## 5. 引擎移植说明（Node → 浏览器）

vendor 引擎为 GenOffice 的 TypeScript 源码，`exports` 直接指向 `src/index.ts`，由 vite 随应用打包。已完成的浏览器适配：

| 位置 | 原 Node 实现 | 浏览器实现 |
| --- | --- | --- |
| pptx-engine `zip.ts` | `node:crypto` `createHash` | WebCrypto `crypto.subtle.digest`（异步化，API 兼容） |
| pptx-engine `sections.ts` | `node:crypto` `randomUUID` | 标准 `crypto.randomUUID` |
| pptx-engine `media-insert.ts` | `node:zlib` `deflateSync` | `fflate` `deflateSync` |
| docx-engine | 无 `node:` 导入（`crypto.subtle`/`DecompressionStream`/`TextDecoder` 均为浏览器标准 API） | — |

工程层面：两个 vendor 包的 `tsconfig.json` 已自包含（不再 extends GenOffice 仓库的 `tsconfig.base.json`），`package.json` exports 指向 TS 源码；docx-engine 对 pptx-engine 的唯一跨包子路径导入为 `@genoffice/pptx-engine/custgeom`（parse.ts），以 `file:` 依赖解析。`Buffer` 使用仅存在于未被浏览器打包路径引用的模块（图表工作簿补丁等经部分列表传入），不影响浏览器构建。

## 6. 编辑器核心移植

自 `apps/docs/src/renderer/` 移植的模块（import 闭包完整，全部纯浏览器）：

- schema/扩展：`extensions.ts`（≈4.5k 行）、`marks.ts`、`pagination-gaps.ts`、`direction.ts`、`table-sizing.ts`、`decoration-extensions.ts`、`revisions.ts`、`column-layout.ts`、`caret-marks.ts`、`table-handle.ts`、`inactive-selection.ts`、`paste-cleanup.ts`、`page-gap-nav.ts`/`page-gap-sync.ts`、`pagination.ts`、`note-format.ts`、`numbering.ts`、`equation.ts`、`shape-svg.ts`、`protected-render.ts`、`hf-dom.ts`、`active-editor.ts`（子编辑器路由，纯浏览器事件实现，文本框/表格子编辑可完整工作）、`move-block.ts`、`indent.ts`、`word-count.ts`、`font-list.ts`、`font-check.ts`、`preset-geometry.ts`、`wordart-presets.ts`、`para-border-merge.ts`、`doc-state.ts`、`doc-style-css.ts`、`line-metrics.ts`。
- 转换：`convert.ts`（blocksToPmDoc / pmDocToSavePlan / 表格模型互转）。
- 纯函数提取：GenOffice `file-actions.ts` 自 `./ai/protocol` 引用的 `isBlankDocument` / `parseHtmlFragment` / `replaceBlockRange` 等非 AI 纯函数提取为 `src/editor/doc-ops.ts`，不携带任何 AI 语义命名与代码。
- 字体：`fonts/` → `src/assets/fonts/`（Carlito/Caladea/Liberation TTF、Noto CJK/阿拉伯/韩文/泰米尔 woff2 子集、`fonts.css`、许可说明），`line-metrics.cssFontFamily` 映射与 `font-check` 缺字体检测随编辑器工作。
- 样式：docs renderer 编辑器相关 CSS 提炼为 `src/styles/document-editor.css`（白纸页面、灰底、页间隙、分节页面盒、`@media print`），并按本应用类名修正打印 chrome 规则、剔除未移植特性的死规则。

**排除项（绝不移植）**：`renderer/ai/` 整目录、AiAskPopover、ai-queue-anchors、一切 `@genoffice/agent-core` / `@genoffice/ai-provider` / `@genoffice/i18n` 引用与 Electron IPC。测试 `tests/e2e/basic-flow.test.tsx` 以静态断言守护这些边界（无 AI 引用、src 无 `node:` 导入、无内联样式、无模板占位残留）。
