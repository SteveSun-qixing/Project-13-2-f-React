# Chips-Slide 移植与许可说明

本工程基于 **GenOffice（Apache-2.0）** 二次开发：将 GenOffice Slides（PowerPoint 应用）从 Electron 架构移植为薯片生态应用插件 Chips-Slide。本文记录 Node → 浏览器的全部引擎补丁、移植排除清单与许可合规口径。

## 一、Node API → 浏览器 API 替换清单

原版引擎跑在 Electron 主进程，使用了 Node 内建模块。vendor 化时逐个修补，**对外 API 与产出字节保持不变**。修补统一收敛在 `vendor/pptx-engine/src/bytes.ts`（浏览器字节/文本等价层），调用点就地异步化。

| # | 触点 | 原实现（Node） | 现实现（浏览器） | 位置 |
| --- | --- | --- | --- | --- |
| 1 | zip 原件归档哈希 | `node:crypto createHash('sha256').update(bytes).digest('hex')` | `crypto.subtle.digest('SHA-256', bytes)`（`sha256Hex`，调用点 `await` 异步化） | `bytes.ts:85-91`，调用点 `zip.ts:37` |
| 2 | UTF-8/ASCII/Base64 编解码、`Buffer.alloc/concat` | `node:buffer` `Buffer.from/alloc/concat` | `TextEncoder`/`TextDecoder`/`atob`/`btoa` + 手写字节工具（`utf8Encode/utf8Decode/asciiEncode/base64Decode/base64Encode/allocBytes/concatBytes` 等） | `bytes.ts` 全文件 |
| 3 | 分节 UUID | `node:crypto randomUUID` | `crypto.randomUUID`（`randomId()`；对无 `randomUUID` 的旧 jsdom 以 `getRandomValues` 回退） | `bytes.ts:93-100`，调用点 `sections.ts` 等 |
| 4 | PNG 压缩（媒体插入） | `node:zlib deflateSync` | `fflate` 的 `deflateSync`（同 deflate 算法，`media-insert.ts:14` 引入） | `vendor/pptx-engine/src/media-insert.ts` |

排查口径：`grep -rn "node:\|Buffer\." vendor/pptx-engine/src vendor/pptx-render/src`——残余命中全部为注释（说明替换语义），源码无任何 Node 内建模块引用。

### 其他浏览器化要点

- 字节流进出：`openPptx(bytes)`/`savePptx(opened)` 全程 `Uint8Array`；zip 读写在 jszip 上完成。
- TIFF 解码：主进程无此路径；浏览器端以 `utif2` 解码 RGBA 后经 canvas 编码（`src/slides/render/tiff-decode.ts`，替代原 pngjs 编码路径）。
- JPEG EXIF 方向：原 `main/jpeg-orientation.ts`（主进程像素旋转）→ 浏览器端 `createImageBitmap({ imageOrientation: 'from-image' })` 等价实现（`src/slides/render/jpeg-orientation.ts`）。
- 文字排版：`pptx-render` 的 `layoutText`（opentype.js 字体度量 + bidi-js 双向排序）随 vendor 包在渲染进程内直接可用；主进程的 harfbuzzjs 精修不移植（见下）。

## 二、移植排除清单（绝不移植/未移植项）

| 排除项 | 原位置 | 排除原因 |
| --- | --- | --- |
| AI 全链路（provider、slides-skill、apply_ops 工具描述等） | `renderer/ai/` 整目录、`main/ai-ipc.ts` | 薯片生态明确禁止任何 AI 相关代码或文案；本工程源码与文档零 AI 引用（e2e 静态契约断言） |
| 布局脚本解释器 | `layout-script*`、acorn 解释器 | 主进程侧 AI 布局能力链路，随 AI 一并排除 |
| 布局审计/大纲导出/质检 | `layout-audit`、`outline-json`、`slide-qc` | AI/CI 面向的调试与审计工具，不属于产品功能 |
| harfbuzzjs 复杂文字精修 | `main/`（harfbuzzjs 集成） | 主进程级可选增强；浏览器端排版由 opentype.js + bidi-js 版式引擎承担 |
| pngjs | `main/` | PNG 编码以 canvas 等价替换（`tiff-decode.ts`） |
| MasterView 母版编辑视图 | `renderer/MasterView.tsx` | 依赖主进程精修与母版编辑 op 链路，浏览器端未移植；母版/版式内容以只读装饰节点渲染（RenderTree `decoration` 节点，不可选中） |
| `@genoffice/ui`、`@genoffice/i18n` 依赖 | 原版内部包 | 组件统一替换为 antd + `@chips/ui`（唯一组件库），文案替换为简体中文直写（`src/lib/messages.ts`）；不引入第二套组件库与 i18n 框架 |

## 三、引擎能力边界（如实说明）

- 幻灯片级操作：引擎注册表提供 `addBlankSlide`/`duplicateSlide`/`deleteSlide`，会话层与界面完整实现；未提供页序重排类 op（引擎无对应能力），界面不造假入口。
- 撤销/重做：op 执行器配套快照历史，会话层实现 undo/redo。
- 新建空白演示文稿：复用 vendor 引擎 `createBlankPptx` 生成合法 OOXML，再由 Host `client.office.create` 写入工作区；不依赖已有 zip。
