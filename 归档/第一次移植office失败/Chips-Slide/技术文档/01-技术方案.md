# Chips-Slide 技术方案

## 一、架构总览

### 1.1 与原版（GenOffice Slides）的核心架构差异

原版将 pptx 解析/补丁保存引擎（`@genoffice/pptx-engine`）与 op 执行器放在 **Electron 主进程**（`slides-main.ts` 持有 `OpenedPptx` 会话），渲染进程通过 IPC（`shared/ipc.ts` 的 op 契约）调用。本移植的**唯一架构级变化**是：引擎全部进入浏览器渲染进程，IPC 边界消失，取而代之的是渲染进程内的**本地会话类 `SlidesDocumentSession`**——op 类型契约与执行语义保持不变，界面（React）直接调用会话。

```
┌────────────────────────── Chips Host（唯一运行时承载） ──────────────────────────┐
│  window.chips.* / Bridge / chips-sdk                                            │
│  ┌────────────────────────── Chips-Slide（app 插件） ─────────────────────────┐  │
│  │ React 组件层   AppShell / StartHomeStage / EditorScene / SlideStage /      │  │
│  │               SlideToolbar / SlideCanvasStage / 覆盖层组件                 │  │
│  │      ▲ useDeck() 本地状态中枢（deck-store）                                │  │
│  │      │                                                                     │  │
│  │ 会话层         SlidesDocumentSession（快照历史 + runTxn + rebuild + save）  │  │
│  │      │                          │                                          │  │
│  │ 引擎层         @genoffice/pptx-engine（openPptx/savePptx/op 模型写回）      │  │
│  │               @genoffice/pptx-render（buildRenderSlide → RenderTree）      │  │
│  │      │                          │                                          │  │
│  │ 渲染适配层     konva-adapter（RenderTree → Konva 机械映射）+ react-konva    │  │
│  └───────────────────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────────────┘
```

- Host 是唯一运行时承载：文件对话框/读写、启动上下文、命令注册等系统能力只经 `chips-sdk`（`window.chips.*`）正式链路，不跨层直连。
- `@genoffice/pptx-engine`、`@genoffice/pptx-render` 以 TS 源码形态 vendor 进本工程（`vendor/`），已按浏览器环境修补（详见技术文档 02）。

## 二、Provider 与场景

`src/app/AppRoot.tsx`（顺序固定）：

```
ConfigProvider(zhCN, appleTheme)
└─ AntdApp

      └─ CommandProvider
         └─ AppRuntimeProvider
            └─ DeckProvider（文档状态中枢，AppShell 与各场景消费）
               └─ AppShell（AppChrome + 场景分发 + 命令注册 + 启动目标处理）
```

场景注册表 `src/app/scene-registry.ts`：`start`（起始页）、`deck`（编辑）两个场景；宿主 sceneId 解析不到时回落 `start`。

## 三、文件打开链路（核心协议）

1. **目标解析**（`src/utils/launch-resource.ts` 的 `resolveLaunchFileTarget`）：
   先合并 `surfaceContext.launchParams` 与顶层 `launchParams`（顶层优先），再读取 `launchParams.resourceOpen`；打开目标优先级 `resourceOpen.filePath ?? launchParams.targetPath ?? resourceOpen.resourceId`。
2. **一次性处理**：`AppShell` 持 ref 哨兵，`deck.launchTarget` 就绪后仅执行一次 `openFromLaunchTarget`；无目标停留起始页。
3. **字节读取 Host 通道**：
   - 本地 PPTX → `client.office.open/read`，会话贯穿后续写回与持久化；
   - 其他资源 ID → `client.resource.readBinary(sourceId)`；无 Host 的开发预览才由上层回退浏览器 `fetch`。
4. **拖放**：`StartHomeStage` 整页 `dragenter/dragover/dragleave`（深度计数器）`/drop`；`deck.openDroppedFile` 内部经 `client.platform.getPathForFile(file)` 取路径，回退 `(file as File & {path?:string}).path`；web 宿主直接读 File 字节。
5. **新建**：`createBlankPptx` 生成含单张空白页的合法 OOXML，`client.office.create` 立即写入工作区 `documents/`，随后进入与打开文件相同的 `SlidesDocumentSession`。

## 四、本地会话层（替代主进程）

`src/slides/session.ts` —— `SlidesDocumentSession`：

| 能力 | 实现 |
| --- | --- |
| `open(bytes, path)` | `openPptx` 解析为 `OpenedPptx`（zip 原件按 SHA-256 归档，供逐字节透传） |
| `applyOp(op)` / `applyTxn(req)` | 先 dry-run 校验（无效请求不污染历史），通过后压入快照历史再执行 `runTxn`；执行失败由执行器回滚模型并弹出快照；事务支持 `atomic`/逐项两种隔离 |
| `rebuild(i)` / `rebuildAll()` | `buildRenderSlide` 重出 RenderTree（fitWidth 视口 + 媒体解析器 + 页码） |
| `rebuildWithReparse(i)` | 结构变更（增删页/表格结构/主题等）后 `materializeSlide` 烘焙字节再整页重出 |
| `undo()/redo()` | 会话级快照历史（`SessionHistory`），undo/redo 后整册重出 |
| `save()` | `savePptx` 打补丁式重建 zip：未修改页逐字节透传、修改页仅重写该页 XML；成功后 `commitSaved` 烘焙补丁（等价重新打开后的状态） |
| `setMeta()` | 另存为成功后更新会话保存路径与文件名，后续“保存”写入新目标 |
| `getElement(i, id)` | 读取引擎元素模型（工具栏属性回显） |

### op 流转链路

```
UI 动作（工具栏/画布/命令）
  → deck-store.apply(op)
    → session.applyOp(op)             # dry-run → 历史压栈 → runTxn（失败回滚）
      → ops/executor.ts               # 注册表分发（registry.ts + 分组实现模块）
        → 引擎模型写回（文本/变换/填充/描边/表格/图片/幻灯片级 op）
    → session.rebuild(currentIndex)   # 重出 RenderTree
  → deck-store 更新 slides / historyVersion
  → SlideCanvasStage 重绘 Konva 舞台
```

op 分组（`src/slides/ops/`）：`core-ops`（目标解析/组等公共）、`text-ops`（setText/setFont/setParagraphFormat）、`element-ops`（变换/填充/描边/裁剪/翻转/层级/成组）、`insert-ops`（文本框/表格/图片/媒体）、`table-ops`（表格结构）、`slide-ops`（addBlankSlide/duplicateSlide/deleteSlide）。`op-docs.ts` 维护全部 op 的一行签名表（供执行器引导式错误使用，测试断言签名表与注册表一致）。

## 五、RenderTree 渲染链路

```
OpenedPptx.deck.slides[i]（引擎元素模型）
  → buildRenderSlide（pptx-render：文本排版 layoutText（opentype.js + bidi-js）、
     预设几何、渐变/图案填充、图表 build-chart、scene3d 等）→ RenderSlide（纯数据渲染列表）
  → konva-adapter.ts：RenderSlide → Konva 节点机械映射（fill/stroke/text/picture/chart…）
  → react-konva 舞台（SlideCanvasStage：背景 + renderNode + 选择 chrome）
  → 覆盖层组件：TextEditOverlay（contentEditable 就地编辑）、CropOverlay（非破坏裁剪）、
    InkOverlay（墨迹）、ChartBody（图表离屏 flat 化）
```

- 缩略图：`SlideThumb` 以独立小舞台离屏渲染（`pointer-events:none`）。
- 媒体：`media-resolver` 按关系解析图片字节 → `media-mime` 识别类型 → TIFF 用 utif2 解码、JPEG 方向经 `createImageBitmap({imageOrientation:'from-image'})` 校正（`jpeg-orientation.ts`）→ `image-loader` 统一异步加载并驱动重绘。
- 导出 PNG：`export-render.tsx` 离屏挂载 react-konva Stage 渲染单页，`canvas.toDataURL` 产出 base64（2× 分辨率）。
- 缩放：画布容器 CSS transform 缩放；缩放手势期间 `zoom-preview.ts` 派发预览事件，编辑框描边等按帧反向补偿。

## 六、命令系统

- `src/commands/app-commands.tsx`：宿主侧 `CommandDefinitionInput[]`（`client.command.*` 元数据，`scope: {kind:"app", appId:"com.chips.slide"}`）+ 本地 `CommandItem[]`（`useCommandRegistry().register()` 注册，`AppChrome` 提供面板与快捷键）。
- `AppShell` 仅挂载命令注册与按启动目标切换场景；`AppChrome` 提供命令面板（Mod+P），编辑器内部工具栏承载高频操作。新版共享层不再由应用外壳渲染顶部菜单栏。

## 七、测试策略

- `vitest.config.ts`：范围限定 `tests/`；`konva` 别名到浏览器入口 `konva/lib/index.js`（其 package.json `main` 指向依赖原生 canvas 的 node 入口，构建链路经 `browser` 字段自动解析，不受影响）。
- 单元：launch-resource 解析优先级回归（10 例）、session（open → 渲染树 → setText → save 往返可再次 open、未修改页逐字节透传、undo/redo、复制页，6 例）、commands 契约（5 例）、App 渲染与文案（5 例）。
- e2e（jsdom）：App 渲染起始页 + 静态契约（src 无 `node:` 导入、无 AI 引用、无 JSX 内联样式对象、无 TODO/FIXME、夹具为合法 pptx zip，6 例）。
- 工程门禁：`npm run verify` = lint + typecheck + test + build + validate + preview:smoke + quality:gate。
