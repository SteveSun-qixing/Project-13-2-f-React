# 设计禁区与验收

## 设计禁区

以下外观即使单独看起来“高级”，也不符合默认主题设计语言：

- 完全照抄 macOS / iOS 控件、图标、色值或窗口外观；
- 暖黄、米色、羊皮纸、复古纸张感；
- 深蓝科技后台风、紫蓝大渐变背景；
- 大面积透明导致文字不清；
- 装饰性彩色光效、大面积渐变背景或完整彩色包边；
- 每个控件都发光、每个状态都使用主按钮蓝；
- 厚重 3D 拟物、卡片侧面、斜切面、金属和皮革材质；
- 强黑投影、硬底部投影、脏阴影；
- 所有卡片都高悬浮，层级没有区别；
- 过度圆润的玩具感；
- 用装饰图形代替真实控件外观；
- 长时间循环炫光、闪烁、弹跳或游戏化动效；
- 完全扁平白卡，缺少高光、暗边和阴影；
- 通过随机光效弥补层级不足。

## 外观验收清单

默认主题相关组件或样张完成后，应按以下问题验收：

1. 大面积背景是否保持中性冷白，不发黄、不深蓝？
2. 整体是否像长期使用的软件界面，而不是营销网页？
3. 主要片层是否包含顶部内高光、底部内暗边和柔和外阴影？
4. 卡片是否轻薄有体积，但没有侧面和厚板效果？
5. 主按钮是否延续系统蓝、白字、内高光、内暗边和蓝色柔影结构？
6. 普通按钮、标签、分段控制活动项是否有轻微控件体积？
7. 输入框是否遵守内凹逻辑，而不是外浮卡片逻辑？
8. Toast、Menu、Popover 和 Dialog 是否比普通卡片更浮起但仍克制？
9. 是否没有装饰性彩色光效、完整彩色包边和大面积渐变背景？
10. 状态色是否清楚、低噪声，并保持可读性？
11. 文字字号、字重和行高是否符合工具型软件密度？
12. hover、active、focus、selected、disabled 是否不造成布局跳动？
13. reduced motion 下是否关闭或降级复杂动效？
14. 视觉实现是否通过 token 与公开主题挂点落地，而不是业务页面硬编码？

如果某个界面为了炫光、装饰或局部冲击牺牲了可读性、稳定性、可维护性或软件感，应优先削弱装饰效果，而不是削弱内容。
