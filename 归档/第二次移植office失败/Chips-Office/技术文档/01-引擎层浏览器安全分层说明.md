# Chips-Office 引擎层浏览器安全分层说明

> 关联：工单172（pptx 引擎 Node.js 内置模块与浏览器构建冲突，已闭环）。
> 本文档描述 `src/engine/` 内部实现分层，不包含对外协议；对外文件协议见生态共用技术文档《15-万能文件处理协议》。

## 1. 运行环境约束

Chips-Office 是薯片生态的应用插件，运行在 Host 的沙箱化浏览器渲染进程中（Electron `sandbox: true`，无 Node 能力）。因此插件源码内凡是会被浏览器打包链路（`chipsdev-r build`，Vite/Rollup）可达的代码：

- 禁止引用 `Buffer` 与任何 `node:*` 内置模块；
- 字节操作统一走 `src/engine/shared/bytes.ts`；
- 确需 Node 专属能力的函数必须收敛到 `node-io` 类独立入口，且不得被浏览器侧代码引用。

引擎代码移植自 GenOffice（原 Node 侧运行），已按上述约束完成浏览器安全改造。

## 2. 目录分层

```
src/engine/
├── shared/
│   └── bytes.ts            # 共享字节工具（浏览器 + Node 通用，Web 标准 API 实现）
├── docx-engine/src/        # DOCX 解析/补丁/生成（浏览器安全）
├── pptx-engine/src/
│   ├── index.ts            # PPTX 主引擎（浏览器安全；buildZip 为 @internal）
│   ├── node-io.ts          # Node 侧专用 IO（savePptxToFile 流式写盘），浏览器禁止引用
│   └── ...                 # 其余模块（浏览器安全）
├── pptx-render/src/        # PPTX 渲染树构建（浏览器安全）
├── file-parse/src/
│   ├── pdf.ts              # PDF 文本抽取（浏览器安全，pdfjs-dist 浏览器构建）
│   └── parse|doc|ppt|pptx|xlsx|docx|vendor.ts  # Node 侧文本抽取管线（word-extractor / ppt-to-text），浏览器禁止引用
├── font-metrics/src/       # 字体度量（node:fs 扫描系统字体，Node 侧专用），浏览器禁止引用
└── index.ts                # 统一导出入口（仅重导出浏览器安全面，注释写明分层边界）
```

## 3. 共享字节工具 `shared/bytes.ts`

| API | 替代的 Node 写法 | 说明 |
| --- | --- | --- |
| `encodeUtf8(text)` | `Buffer.from(str, 'utf8')` | TextEncoder |
| `decodeUtf8(bytes)` | `Buffer.from(bytes).toString('utf8')` | TextDecoder |
| `bytesToBase64(bytes)` | `Buffer.from(bytes).toString('base64')` | 分块转换，大数组安全 |
| `base64ToBytes(base64)` | `Buffer.from(base64, 'base64')` | 容忍空白符与 URL-safe 变体 |
| `concatBytes(...parts)` | `Buffer.concat([...])` | — |
| `bytesEqual(a, b)` | `Buffer.equals` | — |
| `sha256Hex(bytes)` | `createHash('sha256')...digest('hex')` | Web Crypto，异步 |

`tests/unit/engine-shared-bytes.test.ts` 以 node:zlib / node:crypto 为参照做逐字节一致性回归。

## 4. 特殊实现说明

- **PNG 占位图（media-insert.ts `solidPng`）**：原实现依赖 `node:zlib.deflateSync`，现改为纯 JS 的 RFC 1950 zlib 封装 + RFC 1951 stored（无压缩）块 + 大端 Adler-32，同步、零依赖，产物可被任何标准 zlib 解码器还原。
- **`pptx-engine/index.ts` 的 `buildZip`**：标注 `@internal`，仅供 `node-io.ts` 流式保存使用；浏览器侧保存一律走 `savePptx()` 返回 `Uint8Array`，再经 `file.*` 会话链路写回。
- **PDF worker 注册（usePdf.tsx / file-parse/pdf.ts）**：静态/动态副作用导入 `pdfjs-dist/build/pdf.worker.mjs` 顶层注册 `globalThis.pdfjsWorker`，使 pdfjs 在未设置 `workerSrc` 时 fake worker 回退可用；`standardFontDataUrl` 通过 `new URL('pdfjs-dist/standard_fonts/', import.meta.url)` 由 Vite 资产化。

## 5. 修改守则

1. 引擎新增代码需要字节操作时，只能导入 `shared/bytes`，不得新增 Node 依赖；
2. 需要 Node 专属能力时，新建或扩展 `node-io` 入口并在 `engine/index.ts` 注释中登记边界，浏览器侧不得 import；
3. 改动后运行 `npm run build`，确认构建日志无 `Module "node:..." has been externalized for browser compatibility` 告警；
4. 引擎层的浏览器/Node 分层如需对生态公开，应沉淀到生态共用技术文档，而不是仅留在本项目。
