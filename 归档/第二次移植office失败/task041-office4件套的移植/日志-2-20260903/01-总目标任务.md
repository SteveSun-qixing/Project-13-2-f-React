# 01 总目标任务

## 1. 任务由来

用户决定为薯片生态新增一套办公应用插件 **Chips-Office**，选定开源项目 GenOffice（位于 `OpenSourceProjectHandlingFolder/GenOffice`）作为引擎与功能蓝本，进行**完整、彻底的二次开发移植**，使其成为符合薯片生态全部规范的标准应用插件，而不是简单套壳。

任务编号：task041（office4件套的移植）。工作目录：`Chips-Office/`。

## 2. 目标定义

### 2.1 产品目标

把 GenOffice 移植为薯片生态的 **Office 四件套应用插件**，覆盖四种文档类型：

| 应用 | 文档格式 | 定位 |
| --- | --- | --- |
| Word 编辑器 | .docx | 文字文档查看与编辑 |
| Sheet 编辑器 | .xlsx | 表格查看与编辑 |
| Slide 编辑器 | .pptx | 演示文稿查看与编辑 |
| PDF 查看器 | .pdf | PDF 查看与文本抽取 |

### 2.2 移植边界（明确裁剪）

- **AI 功能全部移除**：原项目 AI 侧边栏、AI 对话、AI 解析等能力不移植；
- **Markdown 功能删除**：不进入薯片版本；
- 除此之外的文档处理能力（解析、渲染、编辑、保存、批注、图表、媒体、页面布局等）要求**完整移植，不做简化版、临时版、占位实现**。

### 2.3 架构目标

1. **标准应用插件形态**：通过薯片应用插件脚手架初始化（`chipsdev-r create app Chips-Office`），以 manifest 声明能力、以 `chips-sdk` 访问宿主能力，可被 Chips-Host 安装与承载；
2. **接入万能文件链路**：不新建独立的 office.document 链路，统一走 `file.*` 命名空间（`file.session.*` 会话：create/open/read/write/persist/close），为未来任意文件类型的工作软件复用同一链路；
3. **引擎层浏览器安全**：插件运行在宿主沙箱化渲染进程（Electron `sandbox: true`，无 Node 能力），移植自 Node 环境的引擎代码必须完成浏览器安全改造，浏览器构建与运行双通过；
4. **前端完全生态化**：React + antd（唯一组件库）+ `@chips/ui` 共享层 + 统一视觉规范 + 简体中文文案，清除原项目的自带 UI 框架与主题体系。

### 2.4 质量目标

- `chipsdev-r` 正式验证链路（lint / typecheck / test / build / validate / preview:smoke / quality:gate）全绿；
- 引擎层具备字节级往返回归测试（生成→解析→编辑→保存→重开）；
- 发现的生态级缺口一律走《问题工单》流程登记，不做临时绕过。
