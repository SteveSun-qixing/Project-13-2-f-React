### 1.1 目标

实现完整 DOCX 文档查看/编辑器，集成 `docx-engine`，接入 `AppShell`。

### 1.2 关键产出

```text
src/apps/word/
├── WordEditor.tsx           # 主编辑器（含 32 项单测覆盖核心逻辑）

├── components/
│   ├── Toolbar.tsx           # 撤销/重做、字号、颜色、对齐、表格、图片、批注
│   ├── PageCanvas.tsx        # 单页渲染容器
│   ├── BlockRenderer.tsx     # 段落/标题/列表/表格/图片块渲染器
│   ├── TableEditor.tsx       # 表格单元格编辑
│   ├── ImageInsert.tsx       # 图片插入面板
│   └── CommentPanel.tsx      # 批注侧边栏
├── hooks/
│   └── useDocument.ts        # 文档状态 + 撤销/重做
├── lib/
│   └── messages.ts           # 简体中文文案 + formatMessage
├── types.ts                  # WordDocumentContent 模型
├── styles/
│   └── word-editor.css       # 编辑器私有样式（仅结构）
└── index.ts                  # 入口导出
```

### 1.3 关键决策

- **撤销/重做**：本地栈实现，状态在 `WordEditor` 内 useState 管。
- **保存路径**：`saveDocx` 来自 `engine/docx-engine/src/patch`，保证 patch-aware 写入而非整包重写。
- **SDK 调用**：`client.office.document.create / open / read / write / persist / close` 全链路。
- **视觉**：`@chips/ui` `appleTheme` + antd 6.5.4 + `WordToolbar`；编辑器私有样式在 `word-editor.css` 通过 token 取色。

### 1.4 遇到的问题

| 问题 | 现象 | 解决方案 |
| --- | --- | --- |
| `parseDocxBytesToFullDoc` 来自子路径，import 不便 | TS 报错找不到模块 | 走 `'../engine/docx-engine/src/patch'` 子路径 |
| 编辑器初始字节变化触发 parse，需用 useEffect 监听 | 重复解析 | 通过 `useEffect([initialBytes])` 监听 |
| 批注侧栏折叠状态缺失 | 用户看不到批注入口 | 在 Toolbar 加按钮联动 `toggleCommentPanel` |

### 1.5 单测覆盖

### 2.2 关键产出


### 2.3 关键决策

- **解析路径**：依赖 `cfb` + `jszip` 解压 .xlsx，将 SharedStrings、Sheet 数据映射为 `WorkbookModel`。
- **公式**：本期先实现字符串入/出，不在宿主内做求值（求值走 SDK 后续扩展）。
- **CSV 导出**：`xlsxModelToCsv` 自研转换器，保证中文、逗号、引号转义正确。
- **SDK 调用**：`client.platform.openFile` 选择 → `client.office.document.open/read/write/persist` 写回。
- **中断说明**：子代理在额度耗尽前已交付可运行代码，未跑完整验证；后续由本任务负责人补齐单测。

### 2.4 遇到的问题

| 问题 | 现象 | 解决方案 |
| --- | --- | --- |
| CSV 转义中文与逗号场景 | 简单拼接会破坏数据 | 严格 RFC4180：包含 `,`、`"`、换行的字段加双引号并双写内部引号 |
| 多工作表 active 索引 | 切换 sheet 后选中态丢失 | `setActiveSheet` 时同步重置 selection 到 A1 |
| `useSheet` 状态对外暴露 client | 类型上 `client: null` 会断类型 | 把 client 移到 actions 参数，不再进入 runtime value |

## 阶段 4：PDF 查看器开发（子代理 9d6c1965-4101-4610-aff5-df6eabe96cbd）

### 4.1 目标

实现 PDF 阅读能力，集成 pdfjs-dist，支持缩放、缩略图、搜索、批注。

### 4.2 关键产出

```text
src/apps/pdf/
├── PdfViewer.tsx            # 主容器
├── components/
│   ├── Page.tsx             # 单页渲染（含 text-layer）
│   ├── Toolbar.tsx          # 缩放/旋转/搜索/批注
│   ├── ThumbnailSidebar.tsx # 缩略图
│   ├── SearchPanel.tsx      # 搜索面板
│   └── AnnotationLayer.tsx  # 批注层
├── hooks/
│   ├── usePdf.tsx           # PDF 文档状态 + 渲染
│   └── PdfRuntimeProvider.tsx
├── types.ts
└── index.ts
```

### 4.3 关键决策

- **渲染**：使用 `pdfjs-dist` 的 `getDocument` + `getPage` + `render`，文本层用 DOM 覆盖（保留可复制、可搜索）。
- **缩放**：自定义 `MIN_SCALE=0.1 / MAX_SCALE=10` 限制；fit-width / fit-page / 百分比三档。
- **SDK 调用**：
  - 主路径：`client.office.document.open → read → 拿到 Uint8Array → 喂给 pdfjs`。
  - 备路径：`client.resource.readBinary(resourceId)`（当 host 已在资源上下文中时优先）。
- **虚拟化**：缩略图按需渲染（IntersectionObserver）。

### 4.4 遇到的问题

| 问题 | 现象 | 解决方案 |
| --- | --- | --- |
| text-layer 文本位置漂移 | 字体度量不一致 | 跟随 pdfjs 自带 `renderTextLayer` 思路，但用自写 div 兜底以控制 transform |
| 搜索跨页高亮 | 一次只能看到当页 | 维护 `searchResults` 数组 + `searchCurrentIndex`，`Ctrl+F` 全局快捷键 |
| 文档关闭时遗留 sessionId | 重新打开报错 | `closeDocument` 在 unmount/再次打开前调 `client.office.close` |
| 高 DPI 显示模糊 | 文本/线条不锐利 | 使用 `outputScale = window.devicePixelRatio` 放大 canvas |

### 4.5 验证结果

- `npm run lint`：✅ 通过。
- `npm run typecheck`：✅ 通过。
- 单测：`tests/unit/pdf-viewer.test.ts`（覆盖关键流程：打开、渲染、搜索、关闭）。

## 阶段 6：万能文件链路架构设计（进行中，子代理 92f334c4-9157-45a2-a5a0-041a4044d06e）

### 6.1 触发原因

- 用户评审后指出 `office.document.*` 命名空间狭窄，无法覆盖图片、视频、代码、压缩包等所有文件类型。
- 现有 SDK API 只服务 Office 三件套 + PDF，需要扩展为通用 `file.*` 命名空间。

### 6.2 设计目标

1. **统一抽象**：所有"有状态"文件操作（open/read/write/persist/close）走 `client.file.*`。
2. **多模态**：支持 Office 文档、PDF、图片、视频、代码、压缩包、二进制等。
3. **会话/无会话双模式**：大文件走 session（流式读写），小文件走一次性 `client.resource.read/write`。
4. **零破坏**：旧 `office.document.*` 标记 deprecated，内部直接转发到 `file.*`，4 件套逐步迁移。

### 6.3 拟定接口

```ts
export interface FileSession {
  sessionId: string;
  fileId: string;          // resourceId or file path
  fileName: string;
  mimeType: string;
  size: number;
  revision: number;
  status: 'clean' | 'dirty' | 'closed';
  createdAt: string;
  updatedAt: string;
}

export interface FileApi {
  open(input: { fileId?: string; filePath?: string; mimeType?: string }): Promise<FileSession>;
  read(sessionId: string, opts?: { offset?: number; length?: number }): Promise<{ session: FileSession; bytes: Uint8Array }>;
  write(sessionId: string, bytes: Uint8Array, opts?: { offset?: number }): Promise<FileSession>;
  get(sessionId: string): Promise<FileSession>;
  persist(sessionId: string, fileId?: string): Promise<FileSession>;
  close(sessionId: string, opts?: { persist?: boolean }): Promise<void>;
}
```

## 关键决策小结

1. **渲染策略**：Word/Sheet 用 React DOM，Slide 用 react-konva，PDF 用 pdfjs-dist + Canvas。四套独立但共用 antd 主题。
2. **状态管理**：4 件套各自 useXxx Hook，不引入全局状态库；撤销/重做走本地栈。
3. **SDK 演进**：先实现 4 件套（短期）→ 再抽象 `client.file.*`（长期），分两步走避免阻塞。
4. **样式**：编辑器私有样式放 `*.css` 走 token，无内联颜色；统一前缀 `word-editor*` / `sheet-editor*` / `slide-editor*` / `pdf-viewer*`。
5. **测试**：核心逻辑 100% 覆盖（Word 32 项、Slide 14 项、PDF/Sheet 关键路径），HTML 渲染层不强制 DOM 测试。

## 经验沉淀

- **Konva 性能**：大量元素时禁用 `perfectDrawEnabled` 与 `shadowForStrokeEnabled`，避免微抖动。
- **DOCX patch-aware 保存**：只重写 `document.xml` 与必要的 `word/_rels/document.xml.rels`，不要全量重打包。
- **PDF text-layer**：用 pdfjs 的 `getTextContent()` 自渲染覆盖 div，比直接用 `renderTextLayer` 更可控。
- **SDK 调用频次**：每个文件操作尽量合并，不要在 render 路径中触发 `client.invoke`，否则会拖垮编辑器。
- **撤销/重做**：用结构化数据（AST/Model）做快照比用 HTML 字符串轻得多，回放也更稳定。
