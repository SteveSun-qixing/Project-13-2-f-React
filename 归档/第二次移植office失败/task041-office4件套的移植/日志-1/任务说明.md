## 2. 任务背景

薯片生态需要一套完整的 Office 文档处理能力，覆盖 Word、Excel、PowerPoint 与 PDF 四种最常见的文档形态，使用户能在生态内完成查看、编辑、保存、分享全链路闭环。本次任务基于以下前提：

- 第一版尚未发布，无需兼容历史代码或旧协议。
- 生态内已具备 `chips-sdk`（含 `client.resource`、`client.platform`、`client.command`）、`@chips/ui` 共享层、antd 组件库、命令系统、`AppRuntimeProvider`、`AppChrome`、`StateBoundary` 等基础设施。
- 已存在 `docx-engine`、`pptx-engine`、`pptx-render`、`file-parse`、`font-metrics` 等引擎子模块（位于 `Chips-Office/src/engine/`）。
- 前一阶段任务 `task040` 已落地万能文件查看器应用插件与统一文件处置链路雏形，本次 Office 4 件套需要在该链路下收口。

## 3. 任务目标

### 3.1 主要目标

1. **Word 编辑器（DOCX）**：实现完整 Word 文档查看与编辑能力，含段落、样式、表格、图片、批注、撤销/重做、保存。
2. **Sheet 编辑器（XLSX）**：实现电子表格查看与编辑能力，含单元格编辑、公式、合并、行列操作、多工作表、撤销/重做、CSV 导出。
3. **Slide 编辑器（PPTX）**：实现演示文稿查看与编辑能力，含幻灯片列表、大纲、动画、元素编辑、保存，使用 Konva 渲染。
4. **PDF 查看器（PDF）**：实现 PDF 阅读能力，含页面渲染、缩放、缩略图、搜索、批注。
5. **生态 SDK 万能文件链路**：重构 `client.office.document.*` → 通用 `client.file.*` 命名空间，使所有文件类型（文档、图片、代码、媒体）共用同一套会话模型。

### 3.2 质量目标

- 全部走 `chips-sdk` + `window.chips.*` 正式链路，禁止跨层直连 Host。
- 视觉统一使用 antd 6.5.4 + `@chips/ui` 共享层 + 苹果主题，文案简体中文直写。
- 测试 100% 通过（单元测试 + lint + typecheck）。
- 文档（README、共用技术文档、问题工单）与代码同步更新。

## 4. 任务范围

### 4.1 包含范围

- `Chips-Office/` 仓库下：
  - `src/apps/word/`（Word 编辑器/查看器）
  - `src/apps/sheet/`（Sheet 编辑器）
  - `src/apps/slide/`（Slide 编辑器）
  - `src/apps/pdf/`（PDF 查看器）
  - `src/scenes/`（场景路由：MainScene、WordEditorScene、SheetScene、SlideScene、DocumentScene）
  - `src/engine/`（解析引擎：DOCX、PPTX、PDF、字体度量、文件解析）
- `Chips-SDK/` 仓库下：
  - `src/api/file.ts`（统一文件 API）
  - `src/api/office-document.ts`（旧 API 标注弃用）
  - 协议契约 `src/contracts/route-manifest.json`
- `生态共用技术文档/`：
  - `协议与契约/office-文档协议.md`（迁移前后两版并陈）
  - `迁移指南/office-文档会话迁移指南.md`
  - `架构设计/万能文件链路设计.md`

### 4.2 不包含范围

- 不实现复杂办公特性：协同编辑、宏、邮件合并、受保护工作表。
- 不实现完整 Office 渲染保真度（保证结构保真即可，像素级还原不在本期范围）。
- 不引入新组件库；视觉完全通过 antd token + `@chips/ui` 共享层走。
- 不做兼容性包袱设计；旧 `office.document.*` API 直接重写为 `file.*`，旧代码同步迁移。
- 不修改其他应用插件（如 Chips-PhotoViewer、Chips-VideoPlayer），由后续任务接入新链路。

## 6. 关键技术决策

### 6.1 SDK 调用

| 编辑器 | SDK 调用 | 备注 |
| --- | --- | --- |
| Word | `client.office.document.*` | 旧版，待迁移到 `client.file.*` |
| Sheet | `client.office.document.*` | 同上 |
| Slide | `client.resource.read/write`、`client.platform.openFile/saveFile` | 资源直存为主 |
| PDF | `client.office.document.*` + `client.resource.readBinary` | 旧版，待迁移 |

### 6.2 渲染技术栈

- Word：React + 自研 BlockRenderer（基于 `docx-engine` AST）。
- Sheet：React + 虚拟滚动 + Canvas 混合（基于 `cfb` + 自研解析器）。
- Slide：React + react-konva 9.3.20。
- PDF：pdfjs-dist 6.2.108 + Canvas。

### 6.3 架构决策

- 4 件套统一通过 `AppChrome` + `AppShell` 装载，复用 `CommandProvider`、`AppRuntimeProvider`。
- 内部 store：使用 React Hooks（`useDocument`、`useSheet`、`useDeck`、`usePdf`），不引入 Redux/Zustand。
- 撤销/重做：Word/Sheet 使用本地栈；Slide 使用 `useDeck` 内置历史。
- 主题：完全跟随 `@chips/ui` 的 `appleTheme`，禁止硬编码颜色。

## 7. 不做的事

- 不实现临时版/简化版，所有 4 件套的核心编辑能力必须完整。
- 不在代码中留 TODO，所有功能必须收口。
- 不自己提交代码、合并分支、切换分支——分支管理由用户负责。
- 不擅自引入第三方库，必须先评估许可证、维护状态、包体影响。
- 不破坏生态架构红线：禁止跨服务直接 import、禁止 SDK 承载 Host 逻辑、禁止引入第二套组件库。
