## 2. 任务背景

薯片生态需要一款本地笔记应用，区别于直接生成 Markdown 文件的做法，所有数据均通过 **薯片卡片（`.card`）** 与 **薯片箱子（`.box`）** 进行存储，使得笔记内容与生态其它应用（如卡片查看器、富文本编辑器）完全互通。

- 第一版尚未发布，无需兼容旧版结构或保留任何兼容代码。
- 生态内已具备 `chips-sdk`、`@chips/ui`、`base.richtext` 基础卡片、文档库布局箱子等可直接复用的模块。
- 用户流程参考传统 Markdown 软件：左侧目录树 + 顶部工具栏 + 右侧编辑区。

## 3. 任务目标

- 构建一个独立的 `type: app` 应用插件 `chips.notes`。
- 数据完全符合薯片卡片与箱子文件标准（`chip_standards_version: 1.0.0`）。
- 编辑器、目录树、命令系统等均按照薯片生态前端基础规范开发：
  - React 18 + antd v6 + `@chips/ui` 共享层
  - 简体中文 UI 直写
  - 主题统一通过 `@chips/ui` 的 `appleTheme` token
- 提供完整的单元测试、清单验证与 .cpk 打包能力。
- 不沿用 `documentLibrary-BLP` 布局插件的前端视图，自己解析箱子内容构建目录树。

## 4. 关键决策

- 数据模型：每篇笔记是符合《Chips 卡片文件规范》的 `base.richtext` 复合卡片（`.card` ZIP Store 文件），**以内嵌卡片形式保存在笔记本对应的 `.box` 箱子文件内部**；每个笔记本是一个符合《Chips 箱子文件规范》的 `.box` 文件。
- 数据链路：全部通过 `chips-sdk` 正式接口——箱子走 `box.session.create/rename/open/get/updateEntry/addEmbeddedCard/removeEntry/persist`，卡片走 `card.pack/unpack/validate`，配置走 `client.config`，工作目录默认取 `client.workspace.getContext()`。
- 富文本存储：遵循 base.richtext 规范的 inline（≤200 纯文本字符）/ file（`richtext/<baseCardId>.md`）互斥双模式，`markdown_capabilities` 7 项显式全写。
- 布局探测：创建笔记本首选 `chips.layout.documentlibrary.blp`（文档库布局箱子），插件未安装时经 `box.listLayoutDescriptors()` 回退到已注册布局（当前为 grid）。
- 编辑面板：使用 `textarea` + 工具栏的轻量实现（`MarkdownEditor` forwardRef 命令式句柄），不复用 `richtext-BCP` 卡片编辑器，但卡片文件格式严格符合 `base.richtext` 标准。
- 自动保存：500ms 防抖延迟，通过 `AUTO_SAVE_DEBOUNCE_MS` 常量统一控制；切换笔记前强制落盘。
- 工作区：默认 `Host 工作区根路径/ChipsNotes/`，支持用户重新选择其它工作目录，配置经 `client.config`（user 作用域）持久化。
- 命令系统：6 条命令（新建笔记本 / 新建笔记 / 保存 / 删除 / 加粗 / 斜体）注册到 `@chips/ui` 的 `useCommandRegistry`，handlers 由场景层提供真实实现，全局快捷键由 `AppChrome` 统一挂载。
