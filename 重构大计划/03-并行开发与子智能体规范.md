## 一、开工流程（每个子智能体必须逐步执行）

1. **读全局文档**（全部读完再动手）：`薯片生态文档库/README.md`、`00-愿景与原则/*`、`01-架构设计/00-整体架构图.md`、`01-架构设计/01-子系统设计/01~17`（至少读与任务相关者全文）、`施工规范/*`、本目录 `00~03`。
2. **读领域文档**：任务相关的接口契约（`05-接口与契约/*`）、格式规范（`04-文件格式规范/*`）、开发规范（`02-开发规范/*`）、工程管理（`07-工程管理/*`）。
3. **读任务单据**：从台账/任务清单领取任务；核对 deps 是否已完成；用 `重构台账.py claim` 认领文件（写 owner，见 §五-5.1）。
4. **写开发计划**：在目标仓库/包内写 `开发计划.md`（范围、接口、依赖、测试、风险、验收命令）。
5. **写开发日志**：在目标仓库/包内写 `开发日志.md`，每完成一个阶段追加一节（时间、内容、证据、遗留）。
6. **开发**：严格按契约；禁止临时实现/TODO/兼容层；先写测试后写实现（或同步）。
7. **验证**：运行该包 `build/test/lint/typecheck` + 相关契约测试/门禁；粘贴结果到日志。
8. **回写**：更新台账（文件 status/evidence）、任务状态、开发日志；向主代理返回 ≤5 行摘要。

## 三、交付标准（每个任务）

- 代码：无 TODO/占位/兼容层；类型严格；Rust 无 warning；公开 API 有文档注释。
- 测试：单测覆盖核心路径；契约测试通过；覆盖率达标（总体 >80%，核心/共享层 >90%）。
- 文档：包内 README + 开发计划 + 开发日志；接口变更同 PR 更新文档库。
- 证据：构建/测试/门禁命令与结果写入日志与台账。

## 四、日志规范

- 载每题一次开发日志，格式：`## <时间> <阶段名>` + 内容/证据/遗留。
- 波次收尾由主代理汇总为《波次报告》（台账统计 + 阻塞项 + 下一波准入判定）。

## 五、冲突预防

- 包/文件 owner 唯一；跨包接口以文档库契约为准，禁止私改。
- 公共工具改动（SDK/UI/契约常量）必须走 RFC 记录并在日志标注影响面。
- 同一文件被多任务需要时，由主代理串行化并指定唯一 owner。

### 5.1 台账认领的机器闸口（裁决类任务强制）

- 领面**只有一条路**：`重构台账.py claim --owner <本智能体标识> --repo ... [--category] [--ext] [--dir]`。禁止用 `dispose` / `dispose-batch` 直接改不属于自己的行，禁止手工 SQL 写 owner。
- owner 唯一由 `claim` 的单事务条件（`status='待评估' AND owner IS NULL`）保证；已被他人认领的行只报跳过数、不改动，撞面的表现是"认领 0 行 / 退出码 5"，此时换面或回报主代理，不得绕过。
- 一个仓库面（或子目录面）在同一波次内只允许一个 owner 标识；一次 `claim` 的规模建议 ≤ 一批可通读的量（如 `-n 300`），分批认领、分批裁决。
- 裁决回写走 `dispose-batch`（文件级，`--id-file` 或 `--repo` + `--dir` 限定，整仓库一把梭被工具拒绝）与 `symbol-dispose`（符号级，仅限本 owner 认领文件的符号）。
- 每批落库后跑 `verify`（幻想 target / 孤儿行会被列出，退出码 3 需处理；`迁移`+`重写` 的规划落点在实现开工前是提示级，收口时用 `verify --strict` 清零）与 `stats` 核对符号进度。
- `target_path` 只写一个路径（可带 `#符号名` 锚点），计划归属、波次标注等说明一律写进 `notes`；在路径后拼中文说明会被 `verify` 判为幻想 target。
- 让面、返工、演练复位统一用 `release --owner <标识> [--repo/--dir/--id-file] [--force|--keep-disposition]`，不留悬空认领。
- 所有写操作自动追加 `重构大计划/台账操作.log`（时间/命令/owner/行数/裁决分布），该日志是裁决过程留痕的唯一入口。
