## 一、开工流程（每个子智能体必须逐步执行）

1. **读全局文档**（全部读完再动手）：`薯片生态文档库/README.md`、`00-愿景与原则/*`、`01-架构设计/00-整体架构图.md`、`01-架构设计/01-子系统设计/01~17`（至少读与任务相关者全文）、`施工规范/*`、本目录 `00~03`。
2. **读领域文档**：任务相关的接口契约（`05-接口与契约/*`）、格式规范（`04-文件格式规范/*`）、开发规范（`02-开发规范/*`）、工程管理（`07-工程管理/*`）。
3. **读任务单据**：从台账/任务清单领取任务；核对 deps 是否已完成；认领文件（写 owner）。
4. **写开发计划**：在目标仓库/包内写 `开发计划.md`（范围、接口、依赖、测试、风险、验收命令）。
5. **写开发日志**：在目标仓库/包内写 `开发日志.md`，每完成一个阶段追加一节（时间、内容、证据、遗留）。
6. **开发**：严格按契约；禁止临时实现/TODO/兼容层；先写测试后写实现（或同步）。
7. **验证**：运行该包 `build/test/lint/typecheck` + 相关契约测试/门禁；粘贴结果到日志。
8. **回写**：更新台账（文件 status/evidence）、任务状态、开发日志；向主代理返回 ≤5 行摘要。

## 三、交付标准（每个任务）

- 代码：无 TODO/占位/兼容层；类型严格；Rust 无 warning；公开 API 有文档注释。
- 测试：单测覆盖核心路径；契约测试通过；覆盖率达标（总体 >80%，核心/共享层 >90%）。
- 文档：包内 README + 开发计划 + 开发日志；接口变更同 PR 更新文档库。
- 证据：构建/测试/门禁命令与结果写入日志与台账。

## 四、日志规范

- 载每题一次开发日志，格式：`## <时间> <阶段名>` + 内容/证据/遗留。
- 波次收尾由主代理汇总为《波次报告》（台账统计 + 阻塞项 + 下一波准入判定）。

## 五、冲突预防

- 包/文件 owner 唯一；跨包接口以文档库契约为准，禁止私改。
- 公共工具改动（SDK/UI/契约常量）必须走 RFC 记录并在日志标注影响面。
- 同一文件被多任务需要时，由主代理串行化并指定唯一 owner。
