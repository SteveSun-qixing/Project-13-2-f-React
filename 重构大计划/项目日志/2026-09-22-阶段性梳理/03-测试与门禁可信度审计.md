# 三、测试脚本与质量门禁可信度审计（独立审核 · 2026-09-22）

> 背景：用户明确表示无法确认开发团队制作的质检/测试脚本是否可信。本节为对 `chips-ecosystem` 的只读审计 + 实跑验证。

## 1. 门禁脚本逐个评估

门禁位于 `chips-ecosystem/tools/gates/`，共用 `gates.config.json`，均带退出码语义（0/1/2/3）与报告落盘，且**门禁脚本自身有 69 项自测（`gates:test` 实跑 69 pass / 0 fail）**——可信度加分项。

| 脚本 | 实际检查内容 | 评估 |
|---|---|---|
| `check-boundaries.mjs`（G9，609 行） | 逐文件正则提取 import/export/动态 import，对照允许集判定；Rust 侧解析 Cargo.toml + 循环依赖 DFS | **实质检查**。允许集 fail-closed（新包未登记即违规）。仅两处窄口径豁免 |
| `check-contracts.mjs`（G8，458 行） | 从文档库权威表解析能力/权限/事件清单，与 SDK 生成物逐项 diff；撞名检测；计数核对 | **实质检查**。当前真实红态（见 §5），证明不是摆设 |
| `check-coverage.mjs`（G6，550 行） | TS json-summary + Rust tarpaulin XML 按组聚合判定（TS>80%、共享层/Rust核心>90%）；豁免须《技术债务清单》机读登记 + scopePaths 归因，否则 fail-closed | **实质检查**。豁免逻辑设计罕见严格 |
| `check-docs.mjs`（G12，437 行） | 相对链接有效性、文档头字段校验、ADR 元数据、拆分件重复检测、README 索引收录 | 实质检查 |
| `check-entries.mjs`（166 行） | 插件 dist 入口存在性/字节数/UTF-8/角色合法性 | 实质检查；**但不在 gates:all 与 ci 链内**（覆盖面缺口） |
| `gates-all.mjs` | 聚合四门禁，任一失败退出 1 | 正确聚合无吞错 |

红旗扫描本身被产品化：`packages/host/tests/plugin-activation.test.ts:305` 与 `tools/scaffold/tests/templates.test.ts:74` 把"源码零 TODO/FIXME/占位"固化为常跑测试。

**结论：门禁脚本整体为真实检测器，未发现形同虚设的检查。** 两点保留：① 无 `.github/workflows`，`ci` 脚本是否被真实 CI 挂钩仓内无法核实；② entries 门禁未入聚合链。

## 2. 质量红旗扫描

全仓（排除 node_modules/dist/归档/fixtures）命中 152~273 处（口径不同），**逐条抽样核实：无一处是真实未完成标记**。全部为领域词汇：`占位`=UI 空态/降级组件（`packages/ui/src/components/BoxEmptyState/index.tsx` 等）与 placeholder 属性；`临时`=原子写临时文件协议描述（`packages/host/src/platform/contracts/storage.ts:92` 等）；`Temporary`=Rust `ScopeKind::Temporary` 枚举。**TODO/FIXME/HACK/XXX 在 src 代码面为零**。

## 3. 测试可疑模式扫描

- `test.skip/it.skip/xit/xdescribe`：**零**。仅两处环境条件化 `describe.skip`（`packages/host/tests/e2e-host/app-smoke.test.ts:25`、`native-artifact-gate.test.ts:40`，需 `CHIPS_HOST_SMOKE=1` 显式启用，属真机 Electron 冒烟门控，可接受但应文档登记）。
- 空断言（`expect(true).toBe(true)` 类）：**零**。
- 断言被注释 / try-catch 吞错：抽样未见（catch 均为「expect.unreachable + 断言错误码」标准模式）。
- 快照滥用：更新须显式 `CHIPS_CONTRACT_SNAPSHOT_UPDATE=1`（`tests/contract/src/snapshot.ts:43`），全历史仅 2 次提交触及，无静默重录。
- Rust `#[ignore]`：零。

## 4. 核心包测试抽查（实跑）

- packages/bridge：vitest 实跑 **23 文件 / 306 用例全绿**，断言校验具体错误码/状态机行为，非烟雾级。
- tests/contract：permission-errors 7/7 绿。
- Rust crates：permission.rs/scope.rs/envelope.rs 等均含行为断言测试。

## 5. 已知问题核实：permission:* 契约红

实跑 `node tools/gates/check-contracts.mjs`：**失败 8 条**——`packages/sdk/src/generated/capability-ids.ts` 与 `capability-permissions.ts` 缺 `permission:grant/revoke/restore/audit-read`。文档库先行登记、SDK 生成物未重跑，属流程待收口（#155 在途）而非测试造假；门禁如实拦截。

另实跑 `check-boundaries.mjs`：**失败 1 条**——`chips-resource` 依赖 `chips-parser` 未在 `gates.config.json` 的 `rust.allowedDeps` 登记（BOUNDARY040）。

## 6. 覆盖率配置核查

根 `vitest.config.ts` exclude 仅测试/夹具/dist/.d.ts，**无排除 src 花招**；阈值单一事实源 `gates.config.json`。唯一留意点：`packages/host/vitest.config.ts` 包级 coverage include 只含 `src/platform/**`（注释声明待补测试后扩展）——属包内进度口径，根级 G6 聚合仍统计全量，不构成放水。

## 7. 问题清单

1. [当前红] 契约生成物滞后：缺 permission:* 四能力（gates:contracts 8 违规）——需重跑生成，#155 在途。
2. [当前红] `gates.config.json:130-135` chips-resource 未登记 chips-parser 依赖（BOUNDARY040）。
3. [缺口] check-entries.mjs 未纳入 gates:all/ci 聚合链。
4. [缺口] 无 .github/workflows，CI 挂钩无法仓内核实。
5. [残留] `packages/host/归档/document-service-errors.test.ts.disabled.bak`（新套件已复活，归档件按纪律保留）。
6. [低风险] 两处默认 skip 冒烟门控依赖环境变量开启。

## 8. 总体结论

**测试与门禁体系评定：可信（部分收口未完成）。** 门禁为逐项 diff/逐行解析的真实检测器，自带 69 项自测；无空断言、无 skip 滥用、无快照滥用、无覆盖率排除花招；豁免机制（技术债务清单 + scopePaths 归因 + fail-closed）设计严格。最有力证据：**门禁当前如实报红两处而非绿态粉饰**。主要保留意见是 CI 挂钩与 entries 门禁未入聚合链。
