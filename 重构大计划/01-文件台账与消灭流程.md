# 文件台账与逐个消灭流程

> 版本：v1.0.0
> 日期：2026-09-19
> 状态：执行中
> 适用范围：重构台账数据库（`重构台账.db`）的 schema、文件与函数裁决标准、逐个消灭流程与工具命令。

---

## 一、数据库 schema

```sql
-- 旧仓库/旧文档库登记（全部标记为旧版）
CREATE TABLE repos (
  id TEXT PRIMARY KEY, name TEXT, path TEXT, kind TEXT,      -- repo|doclib|assets|tools
  file_count INTEGER DEFAULT 0, status TEXT DEFAULT '旧版',
  marked_at TEXT, notes TEXT
);

-- 文件台账：旧生态每一个文件一行
CREATE TABLE files (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  repo_id TEXT, rel_path TEXT, ext TEXT, size INTEGER, lines INTEGER, sha1 TEXT,
  category TEXT,            -- code|doc|config|asset|test|data|other
  status TEXT DEFAULT '待评估',   -- 待评估/评估中/已裁决/进行中/已完成/已验证/阻塞
  disposition TEXT,         -- 迁移/重写/保留设计/废弃/归档
  target_path TEXT,         -- 新归属（新包/插件/文档 路径）
  owner TEXT, wave TEXT, notes TEXT,
  UNIQUE(repo_id, rel_path)
);

-- 符号台账：代码文件的函数/类型级
CREATE TABLE symbols (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  file_id INTEGER, kind TEXT, name TEXT, line INTEGER, exported INTEGER,
  status TEXT DEFAULT '待评估', disposition TEXT, target TEXT, notes TEXT
);

-- 波次与任务
CREATE TABLE waves (id TEXT PRIMARY KEY, name TEXT, goal TEXT, status TEXT, started_at TEXT, finished_at TEXT);
CREATE TABLE tasks (
  id TEXT PRIMARY KEY, wave_id TEXT, title TEXT, scope TEXT, owner TEXT,
  status TEXT DEFAULT '待开工',   -- 待开工/进行中/阻塞/完成/已验证
  deps TEXT, log_path TEXT, started_at TEXT, finished_at TEXT, evidence TEXT
);
```

## 二、裁决标准（每个文件必答三问）

1. **功能价值**：该文件承载的功能在新架构中是否仍然需要？（是→迁移/重写；否→废弃/归档）
2. **架构符合**：实现方式是否符合新架构（Cordis/能力/Bridge/单一链路/无兼容）？（符合→迁移；不符合但功能保留→重写）
3. **复用程度**：是否有可复用资产（算法/数据/schema/文案/图标）？（有→随裁决一并搬运；无→不搬运）

| 裁决 | 含义 | 动作 |
|---|---|---|
| 迁移 | 功能保留且实现基本可复用 | 搬运 + 适配新契约 + 测试 |
| 重写 | 功能保留但实现不可复用 | 按文档库权威设计重写 + 测试 |
| 保留设计 | 仅保留设计意图/数据格式/文案，不保留代码 | 提炼入文档库或新实现说明 |
| 废弃 | 功能被替代或不再需要 | 记录理由；旧仓库保留（归档不删除） |
| 归档 | 过程材料/历史证据 | 移入就近 `归档/`，登记 |

## 三、逐个消灭流程（文件级 → 函数级）

```
[1] 认领：从台账领取 files WHERE status='待评估' AND owner IS NULL（按 repo/wave 过滤）
[2] 评估：读文件与关联文档；回答三问；对代码文件逐个符号（函数/类型）判定
[3] 裁决：写 disposition/target_path/owner；符号级只对"迁移/重写"的文件展开
[4] 消灭：迁移或重写；旧功能核对清单逐条打勾（功能名→新实现位置→测试名）
[5] 验证：所属包 build/test/lint/typecheck 全绿 + 契约测试 + 冒烟/性能（按需）
[6] 回写：status='已验证'，evidence 记录命令与结果；更新波次任务状态
```

规则：

- 同一文件不得由两个任务同时认领（台账 owner 唯一）。
- "保留设计"必须落到文档库的具体章节或新实现的注释级说明，禁止悬空。
- 旧仓库只读；迁移采用"复制 + 适配"，不修改旧文件。
- 每完成一个 repos 批次，生成《旧功能覆盖矩阵》（功能→新实现→测试），追加到该仓库重构报告。

## 四、工具命令

```bash
python3 重构大计划/工具/重构台账.py scan           # 扫描全部旧仓库，登记文件与符号
python3 重构大计划/工具/重构台账.py mark-old       # 写入旧版标记文件
python3 重构大计划/工具/重构台账.py stats          # 状态/裁决/仓库统计
python3 重构大计划/工具/重构台账.py next -n 20     # 取下一批待评估文件
python3 重构大计划/工具/重构台账.py dispose --file <id> --disposition 重写 --target <path> --owner <sid>
python3 重构大计划/工具/重构台账.py report --repo <id>   # 生成仓库重构报告骨架
```
