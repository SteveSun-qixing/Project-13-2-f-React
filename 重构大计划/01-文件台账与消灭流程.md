## 一、数据库 schema

```sql
-- 旧仓库/旧文档库登记（全部标记为旧版）
CREATE TABLE repos (
  id TEXT PRIMARY KEY, name TEXT, path TEXT, kind TEXT,      -- repo|doclib|assets|tools
  file_count INTEGER DEFAULT 0, status TEXT DEFAULT '旧版',
  marked_at TEXT, notes TEXT
);

-- 文件台账：旧生态每一个文件一行
CREATE TABLE files (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  repo_id TEXT, rel_path TEXT, ext TEXT, size INTEGER, lines INTEGER, sha1 TEXT,
  category TEXT,            -- code|doc|config|asset|test|data|other
  status TEXT DEFAULT '待评估',   -- 待评估/评估中/已裁决/进行中/已完成/已验证/阻塞
  disposition TEXT,         -- 迁移/重写/保留设计/废弃/归档
  target_path TEXT,         -- 新归属（新包/插件/文档 路径）
  owner TEXT, wave TEXT, notes TEXT,
  UNIQUE(repo_id, rel_path)
);

-- 符号台账：代码文件的函数/类型级
CREATE TABLE symbols (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  file_id INTEGER, kind TEXT, name TEXT, line INTEGER, exported INTEGER,
  status TEXT DEFAULT '待评估', disposition TEXT, target TEXT, notes TEXT,
  wave_owner TEXT             -- 符号波认领标识（NULL=未认领）；W2 新增列，不改任何既有列语义
);

-- 波次与任务
CREATE TABLE waves (id TEXT PRIMARY KEY, name TEXT, goal TEXT, status TEXT, started_at TEXT, finished_at TEXT);
CREATE TABLE tasks (
  id TEXT PRIMARY KEY, wave_id TEXT, title TEXT, scope TEXT, owner TEXT,
  status TEXT DEFAULT '待开工',   -- 待开工/进行中/阻塞/完成/已验证
  deps TEXT, log_path TEXT, started_at TEXT, finished_at TEXT, evidence TEXT
);
```

## 二、裁决标准（每个文件必答三问）

1. **功能价值**：该文件承载的功能在新架构中是否仍然需要？（是→迁移/重写；否→废弃/归档）
2. **架构符合**：实现方式是否符合新架构（Cordis/能力/Bridge/单一链路/无兼容）？（符合→迁移；不符合但功能保留→重写）
3. **复用程度**：是否有可复用资产（算法/数据/schema/文案/图标）？（有→随裁决一并搬运；无→不搬运）

| 裁决 | 含义 | 动作 |
|---|---|---|
| 迁移 | 功能保留且实现基本可复用 | 搬运 + 适配新契约 + 测试 |
| 重写 | 功能保留但实现不可复用 | 按文档库权威设计重写 + 测试 |
| 保留设计 | 仅保留设计意图/数据格式/文案，不保留代码 | 提炼入文档库或新实现说明 |
| 废弃 | 功能被替代或不再需要 | 记录理由；旧仓库保留（归档不删除） |
| 归档 | 过程材料/历史证据 | 移入就近 `归档/`，登记 |

## 三、逐个消灭流程（文件级 → 函数级）

```
[1] 认领：从台账领取 files WHERE status='待评估' AND owner IS NULL（按 repo/wave 过滤）→ `claim`
[2] 评估：读文件与关联文档；回答三问；对代码文件逐个符号（函数/类型）判定 → `symbols`
[3] 裁决：写 disposition/target_path/owner；符号级只对"迁移/重写"的文件展开 → `dispose-batch` / `symbol-dispose`
[4] 消灭：迁移或重写；旧功能核对清单逐条打勾（功能名→新实现位置→测试名）
[5] 验证：所属包 build/test/lint/typecheck 全绿 + 契约测试 + 冒烟/性能（按需）+ `verify` 体检 0 异常
[6] 回写：status='已验证'，evidence 记录命令与结果；更新波次任务状态；返工或让面用 `release`
```

规则：

- 同一文件不得由两个任务同时认领（台账 owner 唯一）。
- "保留设计"必须落到文档库的具体章节或新实现的注释级说明，禁止悬空。
- 旧仓库只读；迁移采用"复制 + 适配"，不修改旧文件。
- 每完成一个 repos 批次，生成《旧功能覆盖矩阵》（功能→新实现→测试），追加到该仓库重构报告。

### 4.1 只读与基础命令

```bash
python3 重构大计划/工具/重构台账.py scan           # 扫描全部旧仓库，登记文件与符号

python3 重构大计划/工具/重构台账.py report --repo <id>   # 生成仓库重构报告骨架
```

- `next` 是**只读**取样（不写 owner），过滤参数与 `claim` 一致；并行裁决以 `claim` 为准，不以 `next` 为准。
- `stats` 的 `== 符号 ==` 段给出符号级裁决进度（总数 / 已裁决 / 全裁决文件数 / 部分裁决文件数）与 **`wave_owner` 认领一行**（认领总量 / 其中未裁决 / 未认领未裁决存量），`== 认领分布 ==` 段给出各 owner 的非“待评估”行数——即准出标准③的机读口径。

### 4.2 批量认领与批量裁决（并行闸口）

```bash
# 认领：把命中的 status='待评估' AND owner IS NULL 行一次性打上 owner
python3 重构大计划/工具/重构台账.py claim --owner ledger-host-scaffold \
    --repo Chips-Host --repo Chips-Scaffold --category code --ext .ts -n 200 --wave W2

# 批量裁决（id 清单模式：claim 输出第 1 列转存后逐行喂入）
python3 重构大计划/工具/重构台账.py dispose-batch --owner ledger-host-scaffold \
    --disposition 废弃 --target "" --notes "旧 Store 链路被 Cordis 能力面替代，功能不再保留" \
    --id-file /tmp/ids.txt [--print-ids] [--dry-run]

# 批量裁决（目录限定模式：同一目录、同一理由成批裁决，输出按目录分组统计）
python3 重构大计划/工具/重构台账.py dispose-batch --owner ledger-host-scaffold \
    --disposition 归档 --notes "过程材料，移入就近归档" \
    --repo Chips-Host --dir src/utils --dir src/legacy
```

语义与约束：

- `claim` 的 owner 唯一由 SQL 条件（`status='待评估' AND owner IS NULL`）在单事务内保证，不靠智能体自律；已被他人认领的行**只统计不改动**，输出末行报告 `认领 N 行 / 命中 M 行 / 跳过 K 行`。
- `dispose-batch` 必须带 `--owner`，且只更新 `owner` 等于该值的行；`--disposition` 限定五种取值，`--notes`（理由）必填。
- **整仓库一把梭被拒绝**：既无 `--id-file` 又无 `--repo` + `--dir` 组合、或 `--dir` 为空串/仓库根，一律以退出码 5 拒绝。
- `--allow-unclaimed` 仅用于 `--id-file` 精确点名的补裁决场景；`--status` 默认 `已裁决`，进入实现的行可写 `进行中`。
- `--dry-run` 只报命中/可写/越权行数，不落库。
- 单行裁决保留原命令与原参数（新增五种裁决取值校验、单事务与操作留痕，输出行不变）：
  `python3 重构大计划/工具/重构台账.py dispose --file <id> --disposition 重写 --target <path> --owner <sid> --notes <理由>`

### 4.2.1 限定范围增量登记（`scan-incr`，2026-09-21 增补，工单032 通道①）

背景：`scan` 是全库重建语义（唯一 files/symbols INSERT 入口，重扫即 DELETE 重建 symbols），存量符号裁决落库后无法为「磁盘上被排除或漏登的范围」补登记；`EXCLUDE_DIRS` 含 `vendor` 等目录名排除，使 `Chips-Office/vendor/` 这类需要入台账裁决的范围 0 行可登。`scan-incr` 提供**只 INSERT、不重建、不触碰已裁决行**的增量登记通道：

```bash
# dry-run 预览（默认不落库）：登记 Chips-Office/vendor/（含嵌套 vendor 目录）的磁盘新行
python3 重构大计划/工具/重构台账.py scan-incr --repo Chips-Office --dir vendor \
    --allow-excluded vendor --owner ledger-matrix-gap --wave W2
# 预览计数无误后加 --write 落库（单事务 + 台账操作.log 留痕）
python3 重构大计划/工具/重构台账.py scan-incr --repo Chips-Office --dir vendor \
    --allow-excluded vendor --owner ledger-matrix-gap --wave W2 --write
```

语义与约束：

- `--repo` 必填且只允许一个；`--dir` 为显式路径清单（仓库内相对目录，可多值，空串/仓库根拒绝）——拒绝整仓库无范围登记，整库重建仍只认 `scan --force`。
- `--allow-excluded <目录名>` 在本次登记范围内显式覆盖 `EXCLUDE_DIRS` 的目录名排除（如 `vendor`，**含嵌套同名目录**；点名值必须属于 `EXCLUDE_DIRS`），未点名的排除目录（`node_modules`、`dist` 等）仍照常跳过。
- 增量语义：范围内已登记的 files 行**整行跳过**（连同其符号与裁决零触碰），只 INSERT 磁盘新增行；写路径带 `ON CONFLICT(repo_id, rel_path) DO NOTHING` 兜底并发。范围内容均为已登记行时 `--write` 以退出码 5 拒绝（幂等重跑安全）。
- 新文件行直接归 `--owner`（`status=进行中`、写 `wave`），新符号行打 `wave_owner=--owner`——后续即可走既有 `dispose-batch`（文件行）与 `symbol-dispose` / `symbol-sweep`（符号行）通道落裁决，与并行路的互斥语义一致。
- 与 `scan` 同口径复用 `category_of` / `extract_symbols` / sha1 计算，`repos.file_count` 在落库时按实更新。

### 4.3 符号级裁决

```bash
python3 重构大计划/工具/重构台账.py symbols --file 4591     # 列出该文件符号与裁决状态

python3 重构大计划/工具/重构台账.py symbol-dispose --owner ledger-host-scaffold \
    --symbol 14687,14688 --disposition 保留设计 \
    --target "薯片生态文档库/01-架构设计/00-整体架构图.md" --notes "只保留插件注册表设计意图"

python3 重构大计划/工具/重构台账.py symbol-dispose --owner ledger-host-scaffold \
    --file 4591 --only-pending --disposition 迁移 \
    --target "chips-ecosystem/packages/host/src/x.ts" --notes "逐符号判定完成" --auto-file-status
```

- `--symbol`（symbols.id 列表）与 `--file`（该文件全部符号）二选一；`--only-pending` 跳过已裁决符号。
- 符号写入权限为**两路任一命中即可**（W2 符号波口径）：所属文件行 `files.owner == --owner`（历史裁决路），**或** 符号行 `symbols.wave_owner == --owner`（符号波认领路）；两路均不命中的符号一律跳过并计数报告。
- `--auto-file-status` 在该文件符号清零时把 `files.status` 回写为 `已裁决`（仅当该文件仍属本 owner）。

### 4.3.1 符号波认领与继承批量面（2026-09-20 增补，主智能体 W2 裁决口径）

背景：文件级已 12,372/12,372 全裁决；符号级 28,047 中仅 551 已裁决（服务端两仓展开先例），待评估 27,496。旧工具把符号裁决权限绑死在 `files.owner`（历史裁决路），新派发的多路并行符号裁决波无法合法写入，因此引入 `symbols.wave_owner` 符号波认领模型。

**机读终验口径**：符号收口 = **全部符号 `status='已裁决'`（待评估 = 0）**，分两类达成：

- **继承类**（所属文件 disposition ∉ {迁移, 重写}，实测 17,472 个 pending）：由 `symbol-sweep` 批量落裁决，符号 disposition 直接镜像所属文件裁决；target 口径——废弃→空 target；归档→说明性 target（镜像文件 target，文件为空时兜底 `就近归档`，与既有归档口径一致）；保留设计→按文件 target。notes 固定句式 `按文件裁决继承（symbol-sweep，源文件 disposition=X）`。
- **展开类**（迁移/重写文件的符号，实测 10,024 个 pending）：由波次智能体**逐符号真判定**，经 `symbol-dispose` 落库（沿用五值与 target 纪律：target 只写路径可带 `#锚点`，说明进 notes）。`symbol-sweep` 对展开类一律拒绝落库并计数报告，防止继承面误吞真判定。

```bash
# 认领：仅对 disposition IS NULL 且 wave_owner IS NULL 的符号置 wave_owner；按仓+类别划分保证并行路互斥
python3 重构大计划/工具/重构台账.py symbols-claim --owner sweep-host-expand \
    --repo Chips-Host --repo Chips-Scaffold --class expand -n 500 [--print-ids]
#   --class expand=迁移/重写文件的符号 / inherit=其余已裁决文件的符号 / all=两类都要（默认 all）
#   重复认领（wave_owner 已有值）直接跳过并报告（退出码 5），互斥由 SQL 条件在单事务内机器保证

# 继承批量落裁决：只处理本 owner 已认领 × 未裁决 × 继承类的符号；默认 dry-run 预览，--write 才落库
python3 重构大计划/工具/重构台账.py symbol-sweep --owner sweep-host-expand [--repo R] [--write]
```

- `symbols-claim` / `symbol-sweep` 与 `claim` / `dispose-batch` 同走 `run_write()` 单事务与 `台账操作.log` 留痕；不改动 `files` 表任何列。
- 展开类符号经 `symbols-claim --class expand` 认领后，即可用 `symbol-dispose --owner <同一标识>` 经 `wave_owner` 路逐文件/逐符号落判定，无需再认领所属文件行。
- 文件级 `release` 不回收 `wave_owner`（符号波面与文件裁决面相互独立）；符号波认领的归属变更同样只认 `symbols-claim` 的机器互斥。

### 4.3.2 已裁决符号精确点名复裁（`symbol-redecide`，2026-09-21 增补，工单032 通道②）

背景：全库符号裁决收口后，缺口收口类需求（如矩阵 §五.2/§五.4 的桥面与 i18n 裁定回写）要对**他人已裁决**的符号复裁：`symbols-claim` 认领条件（`disposition IS NULL AND wave_owner IS NULL`）恒不可达，`symbol-dispose` 两路权限（`files.owner` / `wave_owner`）对收口路一律判越权。`symbol-redecide` 是这类需求的唯一正式复裁入口（禁止手写 SQL 或 `release --force` 破坏性绕行）：

```bash
# notes 精确条件点名（必须 --repo 限定仓库面）：维持 disposition，只在 notes 末尾追加收口句
python3 重构大计划/工具/重构台账.py symbol-redecide --owner ledger-matrix-gap \
    --from-owner ledger-sym-office-c --from-owner ledger-sym-plugins \
    --notes-like '%G2%' --repo Chips-Office --repo Chips-ModulePlugin \
    --append-notes "桥面废弃、由 Bridge/window.chips.* 正式链替代（矩阵 §五.2，工单032 口径）"
# id 清单点名 + 改判：覆写 disposition 并显式清空 target（--target "" 即清空）
python3 重构大计划/工具/重构台账.py symbol-redecide --owner ledger-matrix-gap \
    --from-owner ledger-sym-office-c --symbol 6541,6542,... \
    --disposition 废弃 --target "" --append-notes "<改判依据>"
# 预览计数无误后加 --write 落库（单事务 + 台账操作.log 留痕）
```

语义与约束：

- **精确点名两选一**：`--symbol <symbols.id 清单>`（逗号/空格分隔）或 `--notes-like <条件>`（必须含字面文本，裸 `%`/`_` 拒绝，且必须同时带 `--repo` 限定仓库面）——拒绝整表/整仓一把梭。
- **机器互斥保留**：`--from-owner` 显式点名可复裁的**原裁决路**（可多值，匹配 `symbols.wave_owner` 或 `files.owner`，必填）；未点名裁决路所裁的符号一律计入「越权拒绝」不落库，命中面全部越权/未裁决时退出码 5。`--owner` 是本路执行者标识，进操作留痕。
- 只作用于**已裁决**符号（`disposition IS NOT NULL`）；命中面里的未裁决符号跳过并提示改走 `symbols-claim` / `symbol-dispose` 落首裁。
- 覆写项至少给一个：`--disposition`（五值之一）/ `--target`（显式给值才覆写，`""` 即清空；不给则维持原 target）/ `--notes`（整条覆写）/ `--append-notes`（「；」分隔追加到既有 notes 末尾，**保留历史逐符号判定理由**）；未给的项原值不动，`status` 维持 `已裁决`。
- 默认 dry-run 只报「命中 / 可复裁 / 越权拒绝 / 未裁决跳过」计数，`--write` 才落库。
- 注意 sweep 一致性口径：改判**继承类**（所属文件裁决 ∉ {迁移, 重写}）符号的 disposition 会触发 `verify` 的 sweep 不一致红，收口复裁若需偏离文件裁决只作用于展开类符号（如工单032 G4 的 12 个 strings 聚合常量，其所属文件行维持「重写」不变）。

```bash
python3 重构大计划/工具/重构台账.py release --owner ledger-host-scaffold --repo Chips-Host --force
```

- `verify` 输出：状态计数、裁决计数、认领分布、符号裁决进度与**机读终验口径行**（`status<>'已裁决'` 的符号数，收口目标 0）、**符号波认领分布**（按 `symbols.wave_owner` 给出各认领路总数与未裁决存量）、**sweep 一致性**（继承类符号的 `disposition` 必须与所属文件一致，不一致计入异常；只查已落裁决的继承类符号，不影响现存文件级异常基线）、**孤儿行**（`disposition` 非空但 `status` 仍为 `待评估`）、符号裁决悬空（提示级）、**target 落盘校验**（防“幻想 target”）。发现异常时退出码 3；`--allow-issues` 只出报告不失败；`--show N` 放大清单。
- target 落盘校验分三档，只对指向 `chips-ecosystem/`、`薯片生态文档库/`、`重构大计划/` 的 target 生效：
  - **幻想 target（计异常）**：`disposition` 为 `保留设计` / `归档` / `废弃`（这三类的 target 就是“去处即落点”，不需要实现），或 `status` 已声称 `进行中` / `已完成` / `已验证`，但路径不存在。
  - **规划中未落地（提示级，默认不计数）**：`disposition` 为 `迁移` / `重写` 且 `status` 仍为 `待评估` / `评估中` / `已裁决`——新包/新文件尚未开工，属正常态；消灭收口时用 `verify --strict` 升级为异常，逐条清零。
  - **写法不校验**：含通配符，或写成 `只读参考` / `不搬运` / `就近归档` 等说明性文字。
- **target 书写口径**：`target_path` 只写一个路径（可带 `#符号名` 锚点），计划说明、波次标注一律写进 `notes`；在路径后追加中文说明会被判为幻想 target 或无法校验。
- `release` 是归还认领/返工复位的**唯一正式入口**（禁止手工 SQL）：`status='待评估'`、`owner=NULL`，并连带复位所属符号。默认拒绝回收已落裁决的行，需 `--force`；只想归还认领而保留裁决用 `--keep-disposition`。
- `scan` 会按 `file_id` 重建 `symbols`，符号级裁决落库后重扫即清零成果；因此存在符号裁决时 `scan` 直接拒绝（退出码 5），必须显式 `scan --force` 才重扫。

### 4.5 事务、并发与过程留痕

- 所有写命令（`claim` / `symbols-claim` / `dispose` / `dispose-batch` / `symbol-dispose` / `symbol-sweep` / `symbol-redecide` / `scan-incr --write` / `release`）走 `run_write()`：`BEGIN IMMEDIATE` 单事务、异常回滚、`database is locked` 指数退避重试 8 次。
- 退出码：`0` 成功；`2` 参数错误 / 执行失败已回滚；`3` `verify` 发现一致性问题；`4` 写锁重试耗尽；`5` 无匹配行、越权改写或被安全闸口拒绝。
- 每次写操作追加一行到 `重构大计划/台账操作.log`：`时间  cmd=子命令  owner=…  rows=…  disposition/状态/目录组/跳过数等明细`，作为台账变更的过程留痕。
  注意：根 `.gitignore` 的 `**/*.log` 规则当前会把该日志排除在版本控制之外（`git check-ignore` 实测），需要主代理决定是否加白名单，否则留痕只存在于本机。
- 本轮 schema 增量（只新增、不删列不改列义）：索引 `idx_files_owner_status(owner, status)`、`idx_symbols_file(file_id)`、`idx_symbols_wave_owner(wave_owner)`；列 `symbols.wave_owner TEXT`（符号波认领标识，NULL=未认领，W2 增补）。均由 `ensure_indexes()` 在所有子命令执行前幂等补建（先补列后建索引），加速认领扫描与符号进度核算。

### 4.7 迁移核对四通道与「回执即闸」（2026-09-23 增补，W3-P1-3 波1 #139/#141；工单048 #162/#169 判据随批）

背景：W4 逐仓迁移执行需要「迁移前核对 → 执行清单 → 迁移后闭环 → 执行态回写」的机器化闸门。设计权威为 #137 勘查稿 §七 九条裁定（方案 C 独立通道+回执即闸），实现随 #139/#141 落地为本节四通道。**真库红线**：除 `set-status` 外全部只读；写类回归一律打 `/tmp` 沙箱副本库（回归面 `重构大计划/工具/test_重构台账迁移通道.py`，39 例）；`scan --force` 与裸 SQL 写对迁移波次一律禁止。

```bash
T=重构大计划/工具/重构台账.py
# 通道① 迁移前核对（只读库+只读磁盘）：红项退出码 3
python3 $T preflight --repo Chips-Host[,…] [--json] [--receipt /tmp/pre.json]
# 通道② 迁移中执行清单（只读库、可写清单文件）
python3 $T migrate-manifest --repo <REPO_ID> [--class expand] [--out DIR] [--check-dest]
# 通道③ 迁移后闭环校验+矩阵闭合闸（只读）
python3 $T closure [--repo <REPO_ID>[,…]] [--matrix GLOB] [--json] [--strict]
# 通道④ 执行波回写（唯一最小写通道）
python3 $T set-status --owner <与行 owner 一致> --id-file /tmp/ids.txt \
    --status 进行中|已完成|已验证 [--evidence "证据文本"]
```

- **preflight（通道①）**：双零前置（每仓 `PENDING-NOT-ZERO`、`EXPAND-EMPTY-TARGET` 两红臂）、源仓快照漂移（sha1 对磁盘 walk）、target 归一化、02 映射一致性（`REPO_TARGET_PREFIXES` 常量↔02 表镜像自检）、两红线机检（凭据三段式+永不入库四断言）、`verify` 同源判据的仓级切片。`--repo` 必填（逗号或多值）；`--json`/`--receipt` 出机读回执。
- **migrate-manifest（通道②）**：按仓导出「迁移+重写」files 行及名下展开符号计数，经归一化产 canonical 落点，输出 TSV/JSON/by-zone 分组（默认 `/tmp/manifest-<repo>`）；行数=DB 命中自检行入清单头部；`--check-dest` 做同名与多源同目标合并冲突预检（`server/` 未建落点降 WARN 不计红）。
- **closure（通道③）**：(a) 落点实落（含符号锚段，重写行点名任务豁免）；(b) 矩阵 §一 计数勾稽+证据路径抽样存在性（`--matrix` 默认 `项目日志与笔记/重构计划/旧功能覆盖矩阵-*.md`）；(c) 残留三红（凭据/废弃归档同名/未在册顶层目录）；(d) 迁移/重写未到「已验证」在 `--strict` 下计红。终口径「双零残留」= 待评估 0 + 幻想 target 0 + 残留 0。
- **set-status（通道④）**：执行波回写 status 与 notes 的**唯一正式写通道**——仅允许 `owner` 原路回写 `进行中/已完成/已验证` 三态（`SET_STATUS_VALUES`，不含「已裁决」、不回退裁决态），`--evidence` 以「；」追加进 notes 保留历史判定理由；**禁碰 disposition/target**，越权整批拒绝（退出码 5）。复用 `run_write()` 单事务与 `台账操作.log` 留痕。W4 逐仓迁移执行波（#158 试点起）一律以此通道落执行态，禁手工 SQL。
- **PENDING 判据单一事实源（工单048 #162）**：登记态口径 = `PENDING_STATUSES = ("待评估", "评估中")` 单一常量派生 `PENDING_STATUS_SQL`，preflight 与 closure 共用——`set-status` 合法回写进展态（进行中/已完成/已验证）**不再钉红**；红触发面只针对仍处登记态的行。
- **两通道红面对称（#169）**：`PENDING-NOT-ZERO` 同一 code 双通道共用——preflight 按仓计红（双零前置未成立，`repo_id` 定位）；closure 全局计红（`repo=None`，不受 `--strict` 门控，同残留三红母型，双零残留终口径未成立）。closure 回执 JSON 既有键名/键序零改动、仅 issues 面增红项，该键形由回归锁测钉锁（顶层 11 键+内层 3 键）。
- **回执即闸**：`--json`/`--receipt` 的机读回执是人审闭环载体——波次验收以回执红项多重集为准（主智能体复跑比对基线回执，如 `/tmp/w162_closure_after.log` 判例），不依赖人眼通读输出。
