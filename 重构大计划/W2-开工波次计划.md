## 一、波次目标与准出条件（引自总纲）

一条金链路三件套全数端到端通过：

1. **卡片链**：一张 `.card` 完成「打开→解析→渲染→编辑→保存」。
2. **插件链**：一个插件完成「装载→能力→事件」（`.cpk` 真实包）。
3. **CLI 链**：CLI 全流程（脚手架→构建→打包→安装/驱动宿主）。

准出：端到端 E2E 通过 + 性能基线实测达标（冷启动<1s、开卡<100ms、开箱<200ms、60fps、内存<500MB，数值唯一来源《架构原则》§4.2/R18，实测回写）。

## 三、缺口分解（承 W1 §五-10 就绪审计）

### P0（不开工即断链）

1. **Host 生产组合根**：`main.ts` 无自举、无能力注册——插件链/卡片链的共同前置。
2. **`document:open/read/write/save` 宿主侧实现**：卡片链四动作的 Host 端缺位。
3. **插件端到端三段**：装载器、`.cpk` 装载 spec、真实 `.cpk` 夹具全缺。
4. **渲染引擎未进宿主**：卡片链「渲染」环节。
5. **（源自工单015，已裁决：chips-parser 归 W2 交付）** `chips-parser` crate 按《核心接口规范》§2.1/《06-文档解析器设计》交付（`.card`/`.box` 解析 + `CardParser`/`BoxParser`/`DocumentHandle`/`ParseOptions` 公开面，解析器覆盖率 >80% 且每个对外错误码有对应用例），卡片「解析」环节以 Rust crate 为准绳路线；`chips-resource` 归 W3、`chips-sync` 归 W6（依赖序 core→resource→sync 满足）。
