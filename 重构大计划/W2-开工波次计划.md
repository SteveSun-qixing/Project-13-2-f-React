## 一、波次目标与准出条件（引自总纲）

一条金链路三件套全数端到端通过：

1. **卡片链**：一张 `.card` 完成「打开→解析→渲染→编辑→保存」。
2. **插件链**：一个插件完成「装载→能力→事件」（`.cpk` 真实包）。
3. **CLI 链**：CLI 全流程（脚手架→构建→打包→安装/驱动宿主）。

准出：端到端 E2E 通过 + 性能基线实测达标（冷启动<1s、开卡<100ms、开箱<200ms、60fps、内存<500MB，数值唯一来源《架构原则》§4.2/R18，实测回写）。

## 三、缺口分解（承 W1 §五-10 就绪审计）

### P0（不开工即断链）

1. **Host 生产组合根**：`main.ts` 无自举、无能力注册——插件链/卡片链的共同前置。
2. **`document:open/read/write/save` 宿主侧实现**：卡片链四动作的 Host 端缺位。
3. **插件端到端三段**：装载器、`.cpk` 装载 spec、真实 `.cpk` 夹具全缺。
4. **渲染引擎未进宿主**：卡片链「渲染」环节。
5. **（新增，源自工单015）** 解析/资源 crate：`chips-parser`/`chips-resource` 交付前，卡片「解析」只能依赖 TS 侧现有实现路径——开工前需按裁决结果确认技术路线。

### P1（开工后第一批）

6. 性能真实测量：criterion bench + `PerfAdapter` 实现 + 基线回写。
7. CLI 进程级 E2E 入口与宿主承载适配器。
8. `sdk/scaffold` 导出缺位补齐。

### P2（收口质量）

9. golden-path 门控 `CHIPS_E2E_REQUIRE_APP=1` 首跑。
10. 卡片链细断言补强；e2e/perf/cli README 补全。

## 四、派单编排（吸取 W1 触顶停摆教训）

- 粒度：单智能体只管一个可验收缺口文件面（如「Host main.ts 自举 + 能力注册」一单、「.cpk 装载器 + 夹具」一单），预计 15~25 轮内可收口；跨包公共资产（Bridge 协议、@chips/ui、契约常量、门禁）一律先 RFC 后落地。
- 串行闸门：P0-1/2（组合根+文档能力）先行；P0-3/4（装载器+渲染）依赖组合根就位后并行派发；P1 在 P0 全绿后开。
- 快照纪律：每路智能体在途产物由主智能体先 `git add -u` 快照提交防丢，验收（真实退出码复跑）后再转「已验收」；提交信息不代因归属，先对 owner 表（W1 CP05/06 教训）。
- 验证命令一律 `> log 2>&1; echo EXIT=$?` 取真实退出码；磁盘 <10Gi 时先清 `target/` 再继续 cargo 任务。
