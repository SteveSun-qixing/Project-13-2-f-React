## 二、旧版标记规则

1. 每个旧仓库根写入 `旧版-标记.md`（含冻结说明与替代文档指针），由台账工具生成，禁止手工修改。
2. 旧文档库沿用 `旧版-*` 目录名，不再改动。
3. 所有旧仓库在台账 `repos.status` 为 `旧版`；未经主代理批准不得修改旧仓库文件。

## 三、新 workspace 结构（`chips-ecosystem/`）

```
chips-ecosystem/
├── package.json                 # 私有根包；脚本只做聚合
├── pnpm-workspace.yaml          # packages/*、plugins/*、plugins/*/*、server/community/packages/*、server/personal/packages/*、tools/*、tests/*、examples/plugins/*
├── tsconfig.base.json
├── Cargo.toml                   # Rust workspace
├── .cargo/
│   └── config.toml              # 工作区级 Cargo 源覆盖（USTC 稀疏索引重定义 URL），已入库
├── README.md
├── packages/
│   ├── core-rust/               # 内核（Cordis Rust）与子系统 crate 入口
│   ├── native/                  # Neon 绑定（chips-native）
│   ├── bridge/                  # Bridge 三层（TS 侧适配）
│   ├── host/                    # Electron 壳与主进程（含 Mac 兼容层/PAL）
│   ├── sdk/                     # @chips/sdk（类型 + 客户端 + 测试辅助）
│   ├── ui/                      # @chips/ui（唯一前端导入面）
│   ├── antd/                    # fork antd（仅 @chips/ui 内部使用）
│   └── cli/                     # @chips/cli（用户侧与开发侧命令）
├── plugins/
│   ├── basecards/               # W4
│   ├── layouts/                 # W4
│   ├── services/                # W4
│   └── apps/                    # W5
├── server/                      # 服务端产品根（W6；骨架约定见文档库 01.02 §2.1/§2.2）
│   ├── community/               # 社区平台服务器（packages/{server,web,admin}，社区平台设计 §2.2）
│   └── personal/                # 个人服务器（packages/{server,web}，个人服务器设计 §二）
├── tools/
│   ├── scaffold/                # 脚手架生成器与四角色模板
│   ├── contract-gen/            # 能力/权限/事件 ID 常量生成
│   ├── testing/                 # @chips/testing：vitest 工厂、覆盖率口径与聚合门禁
│   └── gates/                   # 门禁脚本（文档/契约/边界/覆盖率/入口校验）
├── examples/plugins/            # 示例插件（hello、richtext 最小实现）
├── tests/                       # 全链路 E2E、契约测试、性能基线（三包均为 workspace 成员）
└── docs/                        # 本仓工程过程文档与制品模板（《薯片生态文档库》在仓库外的工作区根）
```

规则：仓库根只放工作区配置与文档；源码只落在上述目录；跨包依赖只允许 `workspace:*`。

顶层在册结构注记（台账 closure 通道③ (c) 残留三红之 `RESIDUAL-TOPDIR` 白名单，实现见 `工具/重构台账.py` 的 `known_top`）：上述树内目录一律在册，`.cargo/` 于 2026-09-23 由主智能体裁定补登记（#184 裁②兑现）——它是工作区级 Cargo 源覆盖配置目录，`chips-ecosystem/.cargo/config.toml` 已被 git 跟踪，与 `packages/`、`tools/` 同属在册构建配置结构；未在册的顶层目录仍一律计红（判据不放宽、不降 WARN）；`server/` 于 2026-10-01 随 W6 行 0 落文批补登记（用户六项裁决执行批）。
