# 05 · 开发笔记与重要经验（接管团队省弯路指南）

> 全部为本会话实测踩坑，按「环境怪癖 → 门禁特性 → 架构要点 → 失败模式」组织。

## 一、环境怪癖（每次开工先看）

1. **pnpm 版本**：本机全局 pnpm 是 v8，chips-ecosystem 要求 ≥9。两种解法（均已验证）：`npx -y pnpm@9 <cmd>`，或用垫片 `/tmp/pnpm9-shim/pnpm`（`exec npx -y pnpm@9 "$@"`，供测试子进程 spawn 'pnpm' 时继承 PATH——`packages/cli/tests/process-dist.test.ts` 会真 spawn pnpm 构建，垫片缺失即超时假红）。
2. **根目录是 npm workspaces**（旧接线，指向 22 个冻结仓）；chips-ecosystem 内才是 pnpm workspace。在仓库根跑 pnpm 命令必报 "configured to use npm"。
3. **安装锁**：并行路各自 `pnpm install` 会竞争 lockfile——统一用目录锁 `/tmp/w4-lockguard`（`while ! mkdir /tmp/w4-lockguard 2>/dev/null; do sleep $((RANDOM%7+3)); done; npx -y pnpm@9 install; rmdir /tmp/w4-lockguard`）。会话中断可能留下 stale 锁——接管前确认无安装进程后可清。
4. **`-r --if-present run test/lint` 在首败中止**：看全量清单用 `--no-bail` 或逐包跑。历史上首败曾掩盖 3 个包 25 个存量 lint 错。
5. **cli process-dist 测试**构建钩子已放宽至 120s（超时是环境慢非断言）。
6. **jsdom 测试挂 antd Form/Button** 曾有「用例全过但退出码 1」假红——根因是上游 @rc-component/util useDelayState 不清定时器，已按 antd 补丁先例打了仓内补丁（`packages/antd/patches/@rc-component__util@1.13.0.patch`，工单067），上游提单稿已备未发。

## 二、门禁特性（tools/gates/）

1. **gates:all 五臂=G12(docs)/G8(contracts)/G9(boundaries)/G6(coverage)/G1(generated-project)**。已知特性：G6 判 09-21 快照无新鲜度绑定（359/466 文件）；G1 的 e2e 臂需 `CHIPS_SCAFFOLD_E2E=1`；check-entries 不在聚合内（手动 `gates:entries`）；三条 e2e 逃生门需显式 env（`CHIPS_HOST_SMOKE=1` / `CHIPS_E2E_REQUIRE_APP=1` / `CHIPS_SCAFFOLD_E2E=1`）。
2. **G8 只解析 §6.2 权限映射表**（docsCapabilities=64）——往 04.23 §8.4 内容处理服务表加行**不影响** G8 计数。
3. **G9**：白名单机制=全局 `allowedDevInternal`（现为 @chips/testing+@chips/cli）+ 规则级 `allowedInternal`（plugins 规则=[ui,sdk]；**plugins-apps 规则**=[ui,sdk,plugin-book,plugin-music]——应用复用兄弟插件纯逻辑公开面走 RFC 增名）；**Node 内置模块禁令对插件源码生效（含 vite/vitest.config.ts）**——配置文件路径锚点用 `new URL('.', import.meta.url).pathname`（grid 判例）。server 产品域规则已单列（Node 内置合法）。
4. **G12**：文档四行头/日期格式/相对链接；改文档库后必跑 `gates:docs`。
5. **覆盖率门禁**：判 `coverage-summary.json` 快照（09-21 生成，无新鲜度绑定）+ TD-001/002 豁免（rust-core 85.28%<90%，期限 2026-10-19）——这是在册已知债，接管后建议加 mtime 绑定并重跑 coverage。

## 三、架构要点（写码前默念）

1. **document 域**：`service.ts`（1081 行）是四能力+export/create 的实现本体；存储经 `storage-adapter.ts`（changeset 两相）——**export/create 目标必须先 `ensureTargetScope` 注册进账本**（resolveTarget fail-closed），用完走 INV-2 两拍释放（先 unregisterScope 后 closeSession，禁倒置禁第二注销形）。序列化器强制声明形态=数据源实际形态——跨形态转换需 Rust 侧 file_info 目标形态重算（T-exp-B 的 Rust 面）。
2. **文档 ID**：10 位 Base62，CSPRNG 拒绝采样 b<248（禁 ULID 派生/时间戳/机器标识），生成方=Rust 受控写口（`generate_member_id`+native `generateDocumentId` 已交付）。
3. **宿主能力注册两形**：G6 系统域=`runtime/capabilities/` + createBuiltinCapabilities 按域序 + 分面闸（isFacetReady 单一判据，分面缺位整体不注册）；document 族=`capabilities/document/descriptors.ts` + 组合根 reserved 槽位覆盖。**能力模块零 electron import**（PAL 端口注入）。
4. **服务互调**：插件/服务间一律 `ctx.inject`（Cordis 服务名注入）或内核路由——**禁直接 import 兄弟插件/服务任何内部模块**；纯逻辑公开导出复用例外（RFC-G9应用复用，白名单显式增名）。
5. **G9 对生成物同样生效**：脚手架模板不得含 Node 内置导入；新增白名单/规则必走 RFC（`项目日志与笔记/RFC-*/` 四份判例）。
6. **台账两把锁**：根 lockfile=目录锁 /tmp/w4-lockguard；台账 DB=owner 单写（release→dispose-batch 通道，owner 不匹配即越权拒绝；误 release 会把裁决行放回待评估——修复脚本模式见 02 节引用的会话记录）。
7. **覆盖矩阵是迁移裁决的唯一权威**：每族迁移前 grep 对应矩阵文件行，逐文件照办（迁移/重写/废弃/归档）。
8. **FORBIDDEN_ANTD_EXPORTS 现为 27 项**（InputNumber 已放行）；新包必须自查零命中（词界双验防误报：`message`/`version` 等载荷字段名是已知误报源）。

## 四、失败模式（本会话真实发生过的）

1. **子智能体配额窗口**：5 小时/周/月上限会打断派单——中断单常留**半成品在盘**。接管纪律：先 `git status`+diff 盘点，审读后续写（与契约一致的保留），再全链验证。本会话成功接管 4 次（G6 二批/htmltopdf/T4+T5/W6 首臂），零工作丢失。
2. **声明与机器账脱节**：「全绿/已验收」话术只对提交态成立——接管后每批必须亲跑五闸再提交（本会话实测抓到：覆盖率过期快照、G9 红被当常态、命中率门禁漏检）。
3. **表格解析陷阱**：问题工单.md 登记表的目录列带反引号、标题列含竖线——机器解析需按「状态列以关键词开头」+ 目录列按 `工单NNN-` 前缀容错匹配，且长括注内的「已收口」字样会误判（必须取状态列**开头**词）。
4. **台账 release 面过宽**：release 按 --repo 会放回该 owner 全部行（含废弃/归档）——修复脚本按 (disposition,target) 分组 dispose 回已裁决，教训=**release 必须带 --dir 或 --id-file 精确限定**。
5. **偶发假红两类**：负载下 perf 计时协议超时（已加 30s 鲁棒参数）；document-library teardown 定时器（上游缺陷已补丁，工单067）。全红先连跑 3 次定性再动手。
6. **误移教训**：归档批曾因状态列子串匹配误移 4 个未收口工单（已回移）——批量移动前必须逐条核验状态原文。
