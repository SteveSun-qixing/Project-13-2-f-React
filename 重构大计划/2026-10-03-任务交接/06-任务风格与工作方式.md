# 06 · 任务风格与工作方式（决定你能否接住节奏）

> 本节是本会话被用户认可的运行方式总结：团队长-子智能体编排、验收纪律、提交流程。**用户明确指示过：主智能体自己大量写代码是不正常的，必须任务拆块大量派发。**

## 一、角色定位：团队长，不是码农

- 主智能体只做四件事：**任务拆解 → 派单 → 契约/门禁裁决 → 集成验收**。
- 实现全部由子智能体完成；例外=「整个生态必须单一链路串行的任务」或子智能体配额窗口期的**接管**（接管纪律见 §五）。
- 单行修复也尽量派单；主智能体亲手只写：RFC、裁决记录、checkpoint、台账回写脚本、门禁白名单这类公共资产与治理件。

## 二、任务拆解原则（原子化）

1. **一个子智能体=一个原子任务**（一个插件包/一个能力域/一份文档批/一组测试），独占面互不重叠，owner 唯一。
2. 并发 4~6 路（用户指定的实际节奏；宪法上限更高，按配额现实调整）。
3. **互斥面约定**：packages/host 单路串行；根 pnpm-lock.yaml=目录锁 `/tmp/w4-lockguard`；tools/scaffold、tools/gates、文档库=单路独占或主智能体亲裁。
4. 每个派单提示词必须包含：①上下文与证据（失败清单/判例路径）；②必读清单（契约文档具体到文件）；③交付物；④硬性约束；⑤亲跑验证命令；⑥返回 ≤5 行。
5. 派单前先侦察：旧族矩阵行、母型判例、同族已交付包——把「正确做法的样例路径」直接喂给子智能体，效率倍增。

## 三、子智能体提示词模板（实测高效形制）

```
你是薯片生态重构团队的 X 工程师，原子任务：<一句话>。
工作区：<绝对路径>（git 分支「第五次重构」，禁止任何 git 写操作；命令一律 `npx -y pnpm@9 <cmd>`）。
必读：<契约/矩阵/母型/判例，精确到文件路径>
交付：<编号清单，具体到目录/文件/能力>
硬性约束：禁 TODO/占位/兼容层/假接线；禁改旧仓；FORBIDDEN_ANTD_EXPORTS 零命中；不自造 ID；
  不得放宽/删除既有测试断言；安装持目录锁 /tmp/w4-lockguard；不跑 gates:all（主智能体终验）。
过程材料：<开发日志路径（计划+日志+证据三段）>
交付与验证（亲跑、返回真实输出）：<具体命令与期望>；返回 ≤5 行。
```

约束要点：断言恰等可随动但强度不降；「如实登记缺位（工单+行内提示）不假接线」是处理未就绪依赖的统一手法（music/工单060 判例）。

## 四、批次节奏与提交纪律

1. **每完成一批（3~6 路全绿）→ 全仓五闸终验 → 立即提交**（用户指令：每完成一部分就提交一次）。绝不让多批积压。
2. 提交信息=中文长句，包含：批次定性 + 各路交付摘要（用例数）+ 门禁结果 + 在册登记项。参考 `git log --oneline -20`。
3. 每批随做：台账回写（release→dispose-batch 通道）、文档库目录行翻正（09-目录）、工单登记。
4. 阶段落 checkpoint（宪法 §九格式）+ 波次开发日志，落 `项目日志与笔记/`。

## 五、失败处理与接管纪律（本会话实战 4 次全成功）

1. 子智能体失败/取消/限额 → 先 `git status`+diff **盘点半成品**，再「审读→保留一致面→翻正不一致面→续完→全链验证」。零工作丢失、零半成品入库。
2. 子智能体返回的「全绿」不直接采信——集成验收必须主智能体亲跑五闸（曾抓到：新增包忘 install 导致解析假红、半成品 typecheck 错、load 偶发超时）。
3. 偶发失败定性流程：连跑 3 次全绿=环境偶发（登记工单）；稳定复现=真缺陷（定位根因修复）。
4. 公共资产改动（gates 配置/sdk 类型/契约常量）由主智能体串行化：RFC 记录→配置变更→门禁自测→集成验证。

## 六、验收纪律（证据闭环）

- 任何「完成」必须附：命令 + EXIT 码 + 文件路径。cpk 打包件跑五阶段 validate；宿主面改动跑 SMOKE 真机臂；Rust 面跑 clippy -D warnings。
- 「诚实登记缺位」文化：前置件未就绪就**如实降级+行内简体中文提示+工单登记**，禁假成功、禁假接线（music/工单060 判例已被 10+ 臂复用）。
- 台账回写按批做：`release --owner X --dir Y --keep-disposition` → `dispose-batch --owner w4-b1-lead --id-file ... --disposition ... --status ... --wave ... --allow-unclaimed`；⚠ release 必须精确限定（--dir/--id-file），否则会把废弃/归档行放回待评估。

## 七、上下文与信息纪律

- 派单提示词自包含：子智能体没有你的会话记忆——所有依据（矩阵行、判例路径、失败证据）写进提示词。
- 主智能体保持「侦察先于派单」：新领域先派只读勘查路（唯一产出=勘查报告），勘查报告成为后续所有臂的底册。
- 过程材料三段式（计划/日志/证据）落 `项目日志与笔记/`，命名 `W<N><批次>-<对象>-开发计划与日志-<日期>.md`。
