## 四、派单编排（承 W1/W2 触顶教训，全部硬约束写入派单书）

- 预算以**工具调用数**计：硬顶 130 次、110 次强制收口模式；每过一里程碑追加 `/tmp/wNNN_state.md`，交回即停不扩面。
- 大单**前置拆段**：双侧接线型、多职责聚合型一律按段派；前段验收即单独提交，不后拖。
- 并行度 ≤5 路；每路互斥「禁改清单」点名在途路所属文件面；**禁跑根聚合命令**（`pnpm lint`/`pnpm ci`/`gates:all`/`cargo test --workspace`），聚合闸由主智能体在代码面冻结期批量跑。
- 真进程/E2E 型单子串行承载纪律（单例锁 + 僵尸判据；`pgrep` 残留须过滤 `SiYuan`，那是用户自己的应用）。
- 验收只复跑派单指定定点闸；聚合面留阶段检查点批量跑一次。
- 新组件若被 workspace glob（`crates/*`）自动吸收，须在派单书要求邻居 crate `cargo check` 定点自证，且 agent 不改门禁/覆盖率配置。

## 五、裁决与风险登记

- **裁决A（性能口径，2026-09-21 主智能体）**：W2 准出五指标中的 `open_box_ms` 依赖箱子渲染 UI 段，而该段依工单035 裁定③（`DocumentView` 联合扩宽）随 W4 正式波原子交付。裁定：`open_box_ms` 在 W2/W3 以**在册可测段**交付——解析域基准（`parse-box-10k` 场景，权威预算取自 `@chips/perf` 注册表）+ 主进程视图构建段（headless）；UI 首屏段随 W4 补齐并回写本表。禁止为凑指标改门禁值或造数。
- **裁决B（新 crate 门禁归属）**：`chips-resource` 交付期内按其自身 `cargo test` 与逐错误码用例锁为定点闸；G6 覆盖率阈值的正式登记由主智能体在段二落位后按《工单027 收紧后的 scope 级豁免》口径处置，agent 不得自改配置。
- 风险1：`chips-resource` 段三与 `document:save` 落盘接线同触 `packages/host/src/capabilities/document/**`，须待 #121 与段一/段二验收后串行发，避免双路同文件面。
- 风险2：磁盘余量——cargo 新 crate 构建 + 真进程 E2E 同跑有写满风险，任一路报 IO 错误先 `df -h /` 定性（既有教训：先分清陈旧 target 与在途写入，用户级缓存不自主删）。
- 风险3：真凭据面（旧仓库 `.env`）本波不触碰、不搬运；W6 迁移时一律轮换。
